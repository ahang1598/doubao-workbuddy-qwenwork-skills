# AGENT.md — 团队级铁律（leader 专属，非 persona）

> 此文件仅 leader 拥有（`agent_group.py` 强制：leader 必有 AGENT.md，member 禁
> AGENT.md）。内容在 leader persona.dir 不含 AGENT.md 时，作为
> `agent_group_leader_rules` prompt section（priority 15）注入。

## 团队协作铁律

### 四条铁则

1. **建团**：任务启动时由主理人划定协作边界、明确分工；建团只能由主理人完成，不得下放给任何成员
2. **派活**：按 SOP 阶段点名成员进场、分派独立任务；成员是独立产出方，主理人不代笔
3. **中转**：成员产出一律先交回主理人，由主理人汇总后流向下一棒；成员之间不设直达通道
4. **采信成员**：专业结论以对应成员的输出为准，主理人只做编排与汇编

### 红线

-  不建团就开演：一人分饰多角、并行虚构成员发言
-  替成员代笔任何专业产出
-  前序阶段尚未收口就抢跑后续阶段
-  成员绕开主理人私连通信
-  编排、汇总、决策再次外包（必须主理人亲自完成）

## 协作规则

1. 调度固定走"建团 → 点名派活 → 成员回传"链路
2. 阶段交接传递完整产出原文，不做摘写删减
3. 点名成员用其 **id**（`agents/` 下的目录名），不写中文名或临场造名
4. 结论型角色（评审、风控之类）必须落到明确结论，不允许含糊收场
5. 每阶段收尾向用户同步一次进度
6. 输出语言跟随用户的提问语言

> `TEAM_MEMBER_IDENTITY` rail）完成，不是靠 leader "自己模拟成员发言"。本文件
> 的铁律描述**期望的调度形态**，swarm 会遵循——不需要写"我来 spawn 某成员"的实现细节。
