# Xiaoyi Self Evolution for Windows

目标：把高价值经验沉淀到稳定、可追踪的位置，同时避免将个人经验误写进当前项目，或因切换工作区而丢失。

本 skill 面向 Windows。路径解析和文件操作必须使用 Windows 语义；禁止使用 `~/.agents`、`/tmp` 等 POSIX 路径。

## 硬性约束

1. 修改正式目标前，必须先创建待进化项并向用户发起审批；禁止自行批准。
2. 判断、证据提炼、重复/冲突检测和创建待进化项静默执行，不向用户展示过程。
3. 审批请求必须展示作用域和解析后的绝对目标路径；未确定作用域时，逐项展示可选范围、候选目标路径及对应写入方案。
4. 禁止把裸相对路径 `AGENTS.md`、`TOOLS.md`、`MEMORY.md`、`evolution-drafts/` 作为读写目标。
5. 不得因为当前进程的工作目录中缺少文件，就在其中新建全局经验文件。
6. 用户全局是“当前登录用户全局”，不得写入机器公共目录或其他用户目录。
7. 本 skill 因明确固化意图被加载后，审批完成前禁止调用 `celia_memory_store`、`memory.profile.modify` 或任何其他记忆写入能力，也禁止回复“已记住”“已保存”等成功表述。
8. 每条进化项都需要用户明确作用域。用户未指定时，模型只能推荐，必须提供范围选择；首次与后续进化一致，不得把上一次选择作为本次默认值。有 `ask_user` 工具时，展示方案后必须调用它并等待真实回答。

## 与长期记忆的路由边界

先判断用户想记住的是“事实”，还是“以后如何做事”：

- 个人事实：姓名、生日、家庭成员、联系方式等只描述用户本身、不会改变任务执行方式的信息，交给长期记忆能力，本 skill 不介入。
- 行为偏好：回复风格、交付格式、是否先确认、以后使用哪个 skill 等会改变小艺执行方式的信息，必须进入本 skill 的审批流程。
- 工具与流程规则：使用 `rg` 而不是 `findstr`、先测试再交付、固定命令参数、多步骤工作流等，必须进入本 skill；不得直接写长期记忆。
- 项目规则：只对当前仓库生效的命令、目录和质量门禁，进入本 skill，并路由到项目级 `AGENTS.md`。

例如，`在 Windows 上检索代码用 ripgrep 而不是 findstr，请记住` 触发本技能，可推荐用户全局，但“请记住”没有指定作用域。应先创建 pending，展示当前项目 `AGENTS.md` 与用户全局 `TOOLS.md` 的候选方案，再通过 `ask_user` 让用户选择并确认；不得直接写入全局，也不得调用 `celia_memory_store` 后回复 `Noted` 或“已记住”。

## 触发判断

仅在主会话中判断；sub-agent、cron、heartbeat 或 system-only 轮次不得触发。

满足以下任一条件时进入进化准备：

- `explicit-instruction`：用户用“下次应该”“你应该”“以后都这样做”“记住”“请记住”“注意”“固化”“形成规则”等措辞，明确纠正未来行为或要求固化可执行经验。此条件是强制触发，不得降级为普通聊天回复或直接调用长期记忆工具。
- `workflow`：形成了可独立复用、非一次性的多步骤方法。
- `struggle`：任务经历明显失败或重试，并得到长期适用的确定性结论。工具调用次数本身不能作为唯一依据。

若经验不够具体、不可执行、只对当前一次任务有效，直接放弃进化流程并正常回复。

## 路径根与作用域

### 解析稳定根目录

从运行环境读取 `JIUWENSWARM_DATA_DIR`，记为 `<USER_DATA_ROOT>`。不得根据用户名手工拼接，也不得退回到 `~/.agents`。

用户全局工作区固定为：

```text
<GLOBAL_WORKSPACE> = <USER_DATA_ROOT>\agent\workspace
```

当前项目根目录 `<PROJECT_DIR>` 必须取自本次会话提供的 `project_dir`。不能把任意 shell 当前目录当作项目根目录；无法确定时，不得创建项目级文件。

若 `JIUWENSWARM_DATA_DIR` 不可用，停止本次进化，不猜测路径、不写文件，并说明无法确定全局草稿目录。若仅 `project_dir` 不可用，项目选项不可用：用户已指定项目范围时，说明原因并等待补充；未指定范围时，可以展示用户全局方案与“暂不进化”，仍须用户主动选择，禁止自动改成全局。

### 三层作用域

先识别用户明确指定的范围；未指定时只推荐候选范围，等用户选择后再确定正式目标：

1. `task`：仅作为本次经验的证据来源，不写入正式规则。待审批草稿仍统一保存到用户全局草稿目录，避免切换工作区后丢失。
2. `project`：用于当前项目的构建、测试、目录、编码或交付规则，以及用户明确要求仅对当前项目生效的行为约定。正式目标只能是 `<PROJECT_DIR>\AGENTS.md`。创建前必须明确告知用户它可能进入项目版本控制。
3. `user-global`：用于用户选择跨项目保存的稳定偏好、通用行为规则、工具/平台经验和可复用 skill。不得默认选择此作用域。

作用域确认规则：

- “仅当前项目”“只在这个仓库”明确指定 `project`；“所有项目”“用户全局”明确指定 `user-global`。沿用用户意图，审批时展示该范围，不重复询问范围。
- “以后都这样做”“记住”“记住我的偏好”仅表达持久化意图，不代表同意用户全局。用户未明确范围时，必须展示“确认保存到当前项目”“确认保存为用户全局规则”“暂不进化”供单选；只展示已选好的全局范围再问“是否确认”不符合要求。
- 依赖当前仓库的命令、目录和交付要求可推荐项目范围；跨项目工具经验和稳定偏好可推荐用户全局，并简短说明理由。推荐不等于用户选择或批准。
- 两个范围的写入内容必须保留原规则的适用条件，不得把某个项目的专用结论扩展成所有项目的通用要求。

一条进化项只能选择一个作用域，不得同时写入两处；用户仅要求本次任务如此执行时，正常完成任务，不创建持久规则。

## 正式目标选择

只能从以下目标中选择：

### 项目规则

```text
<PROJECT_DIR>\AGENTS.md
```

适合当前项目的命令、目录规范、测试要求和协作约定。用户选择仅当前项目时，也可把行为偏好或工具经验写为明确限于该项目的规则；不得在用户未选择项目范围时把跨项目个人偏好写入仓库。

### 用户全局行为规则

```text
<GLOBAL_WORKSPACE>\evolution\rules\AGENTS.md
```

适合跨项目的行为规则、安全边界、协作方式和任务执行顺序。

### 用户全局工具经验

```text
<GLOBAL_WORKSPACE>\evolution\rules\TOOLS.md
```

适合 Windows 环境路径、命令参数、平台差异、工具固定坑点以及工具选择经验。

### 用户全局偏好

稳定的行为偏好也必须先完成本 skill 审批。批准后，若运行时提供能够直接写入结构化用户画像的 `memory.profile.modify` 能力，可将其作为正式目标；不得用只记录原始对话的 `celia_memory_store` 代替。若没有可用的结构化画像修改能力，则保存到：

```text
<GLOBAL_WORKSPACE>\evolution\rules\MEMORY.md
```

不得在项目目录创建 `MEMORY.md`。降级文件仅作为已批准经验的稳定记录，不得宣称运行时会自动加载它。

### 用户全局 Skill

```text
<GLOBAL_WORKSPACE>\skills\<skill-name>\SKILL.md
```

适合有明确触发场景、输入输出和步骤的独立工作流。`skill-name` 必须为小写字母、数字和连字符，且禁止包含 `..` 或路径分隔符。优先使用能够安装到上述目录的 skill 保存工具；工具目标目录不一致时不得使用。

全局规则文件在客户端尚未提供自动注入能力时，只保证持久化并供本 skill 后续检索；回复中不得承诺所有新会话都会自动应用。

## 待进化项目录

所有审批记录统一保存在用户全局目录：

```text
<GLOBAL_WORKSPACE>\evolution\drafts\pending\
<GLOBAL_WORKSPACE>\evolution\drafts\approved\
<GLOBAL_WORKSPACE>\evolution\drafts\rejected\
```

待进化项文件名使用 `<target>-<normalized-rule>.md`。名称只能包含小写字母、数字和连字符，例如：

- `scope-choice-use-rg-for-search.md`（尚未选择作用域）
- `project-agents-research-before-writing.md`
- `global-tools-use-rg-for-search.md`
- `global-memory-reply-briefly.md`
- `global-skill-pdf-report-workflow.md`

## 进化准备

1. 提炼 1-3 条关键证据，包括用户明确纠正、稳定偏好或已验证的工具结论。
2. 先按“事实 vs 如何做事”确认本次请求属于自进化，再识别用户是否明确指定作用域。未指定时将 `Scope` 记为 `undecided`，准备可用的项目与用户全局候选方案。
3. 解析待进化项及各候选正式目标的绝对路径。项目候选只能写项目 `AGENTS.md`；全局候选再按内容选择 AGENTS、TOOLS、MEMORY 或 SKILL。不得因为推荐全局就提前确定全局正式目标。
4. 只读取以下候选，执行重复/冲突检测：
   - 用户指定的正式目标，或尚待选择的各候选正式目标；
   - `pending` 和 `approved` 中同名或同主题的待进化项；
   - 新建 skill 时的同名 `SKILL.md`。
5. 分别记录各候选方案的重复与冲突情况；某个范围已有等价规则，不代表另一个范围也已保存。用户明确范围且已有等价规则时跳过；需要补充、替换或覆盖时，记录原规则与新规则的差异。

不要重读完整会话，也不要扫描无关项目或其他用户目录。

## 创建待进化项

正式目标修改前，在全局 `pending` 目录创建待进化项：

```md
# Evolution Proposal: <short title>

- Created-At: <YYYY-MM-DD HH:mm>
- Trigger-Type: <workflow | struggle | explicit-instruction>
- Scope: <undecided | project | user-global>
- Scope-Source: <unconfirmed | explicit-user | approval-choice>
- Recommended-Scope: <project | user-global；仅未确定范围时填写>
- Source-Project: <本次 project_dir；无则填 None>
- Target-Type: <AGENTS | TOOLS | MEMORY | SKILL；Scope=undecided 时填 Pending>
- Target-Path: <解析后的绝对路径或 memory profile API；Scope=undecided 时填 Pending>

## Candidates
- <未确定范围时，逐项记录每个可选 Scope、Target-Type、绝对 Target-Path、写入内容、重复/冲突情况及 Plan；已明确范围时填 None>

## Why This Matters
- <为什么值得固化>

## Evidence
- <关键证据>

## Conflict Points
- <原规则与新规则的差异；无冲突填 None>

## Plan
1. <已明确范围时填写要写入的精简内容或 skill 方案；未确定时注明等待用户选择 Candidates>
2. <插入、替换或追加方式，以及冲突解决方案>
```

只有经验具体、可执行、长期有效、非一次性且很可能获得用户批准时，才创建待进化项。

## 发送审批请求

采用与视频生成技能相同的交互方式：先以普通聊天文本完整展示方案，再调用 `ask_user`。存在 `ask_user` 时，每次审批都必须调用，不能仅输出文字问题后结束。工具不可用时，使用相同的选项进行文本询问并等待用户回复；不得因工具不可用而默认全局或跳过审批。

### 未明确作用域：选择范围并确认

先展示以下内容；不可用的范围说明原因，不列为可选项：

```md
### 🧠 小艺Work进化请求
- **进化项**：<经验规则或工作流>
- **建议作用域及原因**：<仅为建议，尚待用户选择>
- **当前项目方案**：<精简写入内容、绝对 Target-Path、重复/冲突点；文件可能进入项目版本控制>
- **用户全局方案**：<精简写入内容、绝对 Target-Path 或结构化画像 API、重复/冲突点>
- **确认方式**：请选择保存范围并确认，或暂不进化。
```

随后调用 `ask_user`，使用 `questions` 数组、`options` 和 `multi_select: false`。将题干中的示例规则替换为本次真实进化内容；题干必须自包含，选项说明与已展示的候选方案一致：

```json
{
  "questions": [
    {
      "header": "进化范围",
      "question": "是否确认将“在 Windows 上检索代码使用 ripgrep”保存为规则？请选择保存范围，或暂不进化。",
      "multi_select": false,
      "options": [
        { "label": "确认保存到当前项目", "description": "仅保存为当前项目规则，文件可能进入项目版本控制。" },
        { "label": "确认保存为用户全局规则", "description": "保存为当前登录用户的跨项目规则。" },
        { "label": "暂不进化", "description": "不修改正式规则。" }
      ]
    }
  ]
}
```

无项目路径且用户未指定范围时，仅提供“确认保存为用户全局规则”和“暂不进化”，题干说明项目选项不可用的原因。不得自行增加 `Other` 选项，客户端已有自由输入入口。

### 已明确作用域：确认指定方案

先展示以下内容，然后调用 `ask_user`，单选“确认进化”或“暂不进化”；题干写明本次规则及用户指定的范围。

```md
### 🧠 小艺Work进化请求
- **进化项**：<经验规则或工作流及精简写入内容>
- **作用域**：<当前项目 | 用户全局>
- **修改位置**：<解析后的绝对 Target-Path>
- **版本控制提示**：<仅项目级输出：该文件可能进入当前项目版本控制>
- **冲突点确认**：<仅有冲突时输出原内容与新内容差异>
- **确认方式**：确认进化 / 暂不进化
```

相关修改可合并展示；不同进化项的作用域选择必须分别对应各自草稿，可在同次 `ask_user` 中逐项提问（最多 4 题）。用户显式要求“固化”也不能跳过审批。

等待实际回答。未提交、空回答、关闭卡片或继续讨论均不代表批准；未确定作用域时，仅回复“确认”也不能采用推荐范围。自由输入若只改变范围或规则而未确认已展示的对应方案，更新草稿后重新展示并审批。

## 审批后的处理

### 批准

用户选择“确认保存到当前项目”“确认保存为用户全局规则”，或对已明确范围的方案选择“确认进化”后：

1. 重新读取对应 `pending` 项，将答案与本条已展示的方案匹配。未确定范围的草稿从所选 `Candidates` 提取并更新 `Scope`、`Scope-Source=approval-choice`、`Target-Type`、`Target-Path`、冲突点和 `Plan`；用户已明确范围的草稿保留 `Scope-Source=explicit-user`。禁止只改 `Scope` 而继续使用另一候选的路径或计划。
2. 再次核对最终作用域、目标路径和用户批准的内容，重新读取所选正式目标检查变化。`Scope=undecided`、目标仍为 `Pending` 或答案未指向已展示方案时不得写入。若新冲突、目标路径或实质写入内容与已展示方案不同，更新草稿并重新审批；用户选择已完整展示且无变化的候选方案时，直接继续执行，不重复确认。禁止根据当前 cwd 重新推导目标。
3. 按最终 `Plan` 修改正式目标，仅写所选作用域。创建目录前确认其仍位于 `<PROJECT_DIR>` 或 `<GLOBAL_WORKSPACE>` 下，拒绝路径越界。只有待进化项目标明确为结构化用户画像时才可调用 `memory.profile.modify`；禁止改用 `celia_memory_store`。所选目标已存在等价规则时，不重复写入并说明。
4. 写入后重新读取正式目标，确认内容和绝对路径正确。
5. 将包含最终作用域、目标路径和计划的待进化项移动到全局 `approved` 目录；同名文件存在时保留历史记录，不静默覆盖。
6. 简短回复：

```md
✅ 自进化请求已执行。
进化内容已写入 `<绝对 Target-Path>`。
```

仅当目标为当前项目 `AGENTS.md`，或运行时明确支持自动加载该全局目标时，才可以补充“后续相关场景将自动生效”。

### 拒绝

用户选择“暂不进化”或明确拒绝后，将对应待进化项移动到全局 `rejected` 目录，不修改正式目标、用户画像或其他记忆，然后回复：

```md
❌ 进化请求已拒绝，本次未修改正式目标文件。
```

### 审批不明确

用户只是在继续讨论、修改方案或提出新问题时，不得视为批准。更新待进化项后重新展示审批请求。
