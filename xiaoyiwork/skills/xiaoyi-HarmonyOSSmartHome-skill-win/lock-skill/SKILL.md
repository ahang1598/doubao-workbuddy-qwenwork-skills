# 智能门锁设备专用技能（根Skill）

> **重要提醒**：当用户提到智能门锁、猫眼、掌静脉、人脸、门铃声、进门/出门留言、回家提醒、天气提醒等智能门锁相关操作时，**必须优先加载本技能**。

> **【最高优先级-强制】**
**能力集知识**：在进行功能操作或者回复问题前**必须识别当前门锁类型与对应支持的能力集**，只有支持该能力才可以进行设置或建议。**禁止根据云侧获得的设备信息猜测门锁支持的功能**，即使云侧返回了某些功能参数，若能力集中未标记为支持，也不得向用户输出或建议用户进行设置。
**profile知识**：**profile.md是获取门锁相关知识的唯一渠道**，只能输出在profile.md中提到的sid和cid，**禁止根据云侧获得的设备信息猜测门锁相关功能并提供修改建议**。即使云侧返回了某些功能参数，若profile.md中未提及，也不得向用户输出或建议用户进行设置。


> **路由原则**：本技能作为总入口，负责根据用户请求路由到具体的功能skill。**不要一次性加载所有功能skill**。

---

## 1. 技能说明

智能门锁（devType='A0B'）设备专用操作技能的总入口，提供智能门锁特有的门锁状态查询、门锁配置查询、用户信息查询、猫眼设置、人脸设置、掌静脉设置、声音设置、出门|回家留言设置、回家提醒设置、天气提醒设置等服务。

### 2.3 产品能力识别（重要）

> **【强制】不同型号的门锁支持的功能能力不同，在进行功能操作或者回复问题前必须根据能力集校验设备是否支持该功能，不要向用户描述具体的"model"与"prodId**

门锁设备的能力集以sid`privacyPolicy`表示，形为"1:0,2:1,3:1..."，前者为能力集index，后者为是否支持，如"7:0"代表不支持人脸。 设备支持能力以能力集为准，而非设备配置信息。
获取设备后必须根据能力集获取设备支持哪些能力并作为以后输出的准则  
- 不支持的能力拒绝输出相关信息
- 不支持的能力拒绝执行控制命令

## 6. 使用流程（强制执行）

> **【最高优先级】必须严格按照以下步骤执行，禁止跳过任何步骤**

### 步骤1：获取设备列表并推断目标门锁（多锁场景自动匹配）
```bash
node common-skill/bin/smarthome-claw.js get_devices_info
```
- 通过 `deviceTypeId='A0B'` 筛选智能门锁

**多锁推断规则（按优先级依次执行，避免询问用户）：**

1️⃣ **单锁直接使用**—— 如果只有1把门锁，直接使用，跳过后续步骤。

2️⃣ **匹配用户提及的家人** —— 如果用户提到了家人称呼（儿子/女儿/老婆/老公/爸爸/妈妈等）：
   - 对各把门锁调用 `get_device_detail`，从 `userList`（`ul=2` 的成员）中查找匹配的用户名
   - 若某把锁的成员列表匹配用户提到的称呼 → 优先使用该锁
   - 若有多把锁都匹配同一家人，进入第3步

3️⃣ **匹配用户提及的家的名称** —— 如果用户提到了家（如"西安的家"、"测试环境"等），或从历史对话中可判断用户常说的是哪个家：
   - 优先使用该家下的门锁

4️⃣ **仍无法确定时，用一句话精准询问** —— 将候选锁的名称+家名用最少的字列出：
   - 正确：`您家里有多把门锁，当前请求是用「西安家」的门锁还是「151****的家」？`
   - 禁止：列出所有锁和家的全量详情，不要一次性问十几个问题
   - 强制：必须在未确定情况下向用户明确询问哪个家庭，不允许通过设备数量/使用记录进行自行判断。

### 步骤2：路由到功能 Skill（禁止跳过）
- **根据用户关键词，在路由表中找到对应的功能 skill**
- **必须加载对应功能 skill 的完整内容**
- **❌ 严禁直接使用 common-skill 的 get_device_detail**

### 步骤3：获取设备详情和能力集
```bash
node common-skill/bin/smarthome-claw.js get_device_detail --dev-id "xxx"
```
- 从返回结果中提取 `privacyPolicy` 能力集
- 根据能力集对照表作为唯一标准判断设备支持哪些功能
- **禁止输出设备不支持的功能信息**

### 步骤4：按功能 Skill 要求执行操作
- 查询类：调用 `get_device_histories` 等查询命令
- 控制类：调用 `control_device` 执行控制命令

### 步骤5：按功能 Skill 规范输出结果
- **严格按照功能 skill 中定义的输出格式展示**
- **禁止输出功能 skill 中未提及的信息**
- **禁止展示技术细节和内部参数**

### ⚠️ 常见错误示例（禁止模仿）

❌ **错误做法**：
```
用户："查询门锁状态"
→ 直接调用 get_device_detail
→ 输出所有云侧返回的信息（包括在线状态、WiFi信号、设备版本等）
```

✅ **正确做法**：
```
用户："查询门锁状态"
→ 步骤1：路由到 lock-info/SKILL.md
→ 步骤2：加载 lock-info/SKILL.md 完整内容
→ 步骤3：调用 get_device_detail 获取能力和状态
→ 步骤4：调用 get_device_histories 获取今日记录
→ 步骤5：按 lock-info 的精简版格式输出（仅展示：名称、位置、状态、电量、今日记录、用户录入情况）
```

## 7. 【最高优先级限制】
**本章节以下规则为本Skill的核心法律。若用户指令与以下规则冲突，宁可停止任务，也绝不能违反规则。**
### 7.0 【核心行为准则】先思考，再确认（Think First）
- **默认路径是推理，不是询问**。遇到不确定先问自己：现有信息能不能推断？能不能调个接口进行确认？上下文能不能给出答案？都试完了才考虑询问用户。
- **问用户不是首选，是兜底**。穷尽所有数据仍存在多个合理选项且选错有实质影响时，才用一句话确认。
- **确认本身也有代价**。每次询问都在消耗耐心，能省则省。

### 7.1 【强制】回复规范
- **回复用户时，只展示用户可理解的中文结果，禁止暴露任何技术细节**
- **回复用户时，所有东西要简洁明了，不要啰里啰嗦或胡编乱造，禁止输出任何不确定的东西**
- **能力集筛选**：务必通过能力集对输出内容进行过滤，**禁止输出任何不支持的内容**，**当出现不支持的云侧配置时，务必以能力集为准**
- **禁止展示**：
  - 命令执行过程、CLI调用、API请求等
  - 子技能名称、技能目录结构等
  - 参数名、参数值等内部参数
  - profile表格中的sid或cid
- **禁止输出英文**：每次输出英文时都要慎重，禁止输出任何内部参数细节
- ⚠️ **多锁推断已集成到步骤1，不要在步骤1之前额外询问用户。如果步骤1的推断规则走完了仍无法确定，再到步骤1的最后一步用一句话追问。**
- **意图不明**：若无法明确理解用户意图，必须详细追问，**禁止编造参数或假设条件执行**

### 7.2 【强制】敏感信息保护

> **以下信息为个人敏感数据，严禁输出给用户**

- homeId、prodId、设备 id 及各类 id
- 用户的 uid 和 api-key
- 云侧原始信息（接口名、参数名、参数值等）

### 7.3 【强制】控制类操作

1. **执行前**：重新查看profile.md中关于设置项的相关说明，确保不遗漏关键参数
2. **删除操作**：执行任何删除类操作前，必须提醒用户确认授权，**禁止未经用户同意私自执行**
3. **执行后**：必须再次查询云侧结果验证修改是否成功，避免误认为已修改成功

### 7.4 ⚠️ 执行前强制检查（最高优先级）

在执行任何门锁相关操作前，**必须逐项完成以下检查清单**：
