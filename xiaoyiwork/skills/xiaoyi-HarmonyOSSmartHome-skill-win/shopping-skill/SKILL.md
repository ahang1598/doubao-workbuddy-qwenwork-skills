### 1.1 首先判断是单品需求还是套装/组合需求

**⚠️ 核心判别规则：**
- **单品推荐** → 用户明确提及具体产品名称（如"除湿机"、"空调"、"净化器"、"门锁"、"台灯"等带"机/器/灯/锁"等品类词），或明确表示要买单一产品
- **套装推荐** → 用户要求组合/套装/方案/一套/推荐一个方案，或描述生活痛点/场景（如潮湿、睡眠不好、老人独居、孩子安全、儿童健康起居等），或用"怎么配"、"搭配"、"组合"等表述

**单品推荐**：走步骤2的单品推荐流程（一句话结论→选购要点→对比表格→机型亮点→选购提醒）
**套装推荐**：走到 scene-bundle-skill/SKILL.md，按照套装格式（Markdown 表格）推荐组合方案

## 执行步骤 2：商品数据获取

### product_search（商品搜索）

- **功能**：智慧生活商城产品搜索 API
- **路由路径**：`shopping-skill/bin/product_search.js`
- **获取信息**：获取商品品类、具体型号、名称、价格、购买链接、图片

### 调用方式
```bash
# 基本格式
node shopping-skill/bin/product_search.js --keywords "<搜索关键词>"

# 示例：查询空调商品信息
node shopping-skill/bin/product_search.js --keywords "空调"

# 示例：查询空气净化器商品信息，按照价格升序排列
node shopping-skill/bin/product_search.js --keywords "空气净化器" --sort-by-price "asc" --verbose
```

### 参数说明
- `--keywords`：搜索关键词（必填）
- `--sort-by-price`：价格排序，可选 `asc`（升序）或 `desc`（降序），默认 `asc`
- `--verbose`：显示详细日志

### 全局输出规则
- 真实性原则：所有参数、价格、功能均来自接口返回数据，禁止虚构
- 严谨性原则：价格使用 "约 ¥XXX"、"参考价格 ¥XXX-XXX"、"主流平台到手价约 ¥XXX" 等表述
- 客观性原则：每款产品必须同时列出优势和不足，不允许出现 "完美产品"
- 简洁性原则：重点突出，避免冗长的参数堆砌，用生活化语言解释专业概念
- 格式锁定原则：步骤4中"输出结构要求"的每个子章节（1~5）必须按顺序完整输出，**不得跳过、合并或改变顺序**

## 边界情况处理
预算过低：如实告知用户该预算能买到的产品水平，同时给出 "加一点预算能买到更好的" 建议
没有符合条件的商品：坦诚告知用户，并给出替代方案或调整建议
用户询问非智能家居 / 家电产品：调用除智慧生活以外的数据，给出替代方案或调整建议
用户要求推荐特定品牌：先推荐该品牌下符合需求的产品，同时客观说明其他品牌的优势供用户参考
