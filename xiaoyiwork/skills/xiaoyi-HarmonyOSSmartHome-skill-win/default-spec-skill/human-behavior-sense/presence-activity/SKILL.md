# 家庭活动查询与家庭关爱

## 功能说明

查询家庭内最近的设备操作和人员活动情况，同时提供家庭关爱相关的信息，包括老人儿童的回家出门时间、作息规律、活动状态等。

## 数据来源

| 设备类型 | 监测活动 | 时间窗口 |
|---------|---------|---------|
| 智能门锁 | 开门、关门、用户识别、开门方向 | 24小时 |
| AI摄像头 | 人形检测、人脸识别、区域活动、姿态检测 | 30分钟 |
| 智慧屏 | 开关机、使用时段、观看内容分类 | 24小时 |
| 智能传感器 | 人体存在、移动感应 | **24小时（老人房/儿童房/卫生间等关键区域）** |
| 智能灯光 | 开关、调光、离家模式 | 24小时 |
| 智能家电 | 启动、停止、模式切换 | 30分钟 |
| 智能音箱 | 语音唤醒、指令执行、内容类型 | 20分钟 |

## 活动类型

### 人员活动
- 进门、出门（通过门锁识别）
- 在房间内移动（摄像头/传感器）
- 语音交互（智能音箱）
- 区域活动（AI摄像头识别区域）

### 设备活动
- 灯光开关、调节
- 家电启动、停止
- 音箱唤醒、播放
- 智慧屏开关、内容

## 家庭关爱功能

### 老人关爱

| 监测项 | 数据来源 | 说明 |
|--------|---------|------|
| 回家/出门 | 智能门锁 | 识别老人进出家门时间 |
| 起床/入睡 | 智能门锁+传感器+床垫 | 通过活动规律判断 |
| 活动异常 | AI摄像头 | 长时间无活动预警 |
| 异常停留 | AI摄像头 | 在卫生间等区域异常停留 |
| 紧急呼叫 | 智能手表/摄像头 | 跌倒检测、紧急按键 |

### 儿童关爱

| 监测项 | 数据来源 | 说明 |
|--------|---------|------|
| 回家/出门 | 智能门锁 | 识别孩子进出家门时间 |
| 到家确认 | 智慧屏+摄像头 | 到家自动提醒家长 |
| 作息规律 | 智能门锁+传感器 | 起床、睡觉时间分析 |
| 学习状态 | AI摄像头+智慧屏 | 检测是否在学习区域 |
| 娱乐时间 | 智慧屏+智能音箱 | 看电视/打游戏时长统计 |
| 久坐提醒 | AI摄像头 | 学习/娱乐时间过长提醒 |

### 家庭成员状态识别

| 状态 | 判断依据 | 适用场景 |
|------|---------|---------|
| 回家 | 门锁识别到家庭成员开门 | 老人/孩子到家提醒 |
| 出门 | 门锁从内开门 或 长时间无活动 | 离家确认 |
| 起床 | 门锁活动 或 传感器检测到活动 | 作息监测 |
| 睡眠 | 长时间无活动 + 传感器状态 | 睡眠监测 |
| 学习 | 摄像头检测在学习区域 + 智慧屏非娱乐 | 儿童学习监测 |
| 吃饭 | 餐厅区域活动 + 智能家电使用 | 用餐时间 |
| 看电视 | 智慧屏开启 + 内容识别 | 娱乐活动 |
| 打游戏 | 智慧屏/智能音箱检测游戏内容 | 儿童娱乐监测 |

## 使用流程

### 基础活动查询
1. 查询各设备最近的历史记录和状态变化
2. 按时间排序所有活动
3. 提取最近30分钟内的活动
4. 分类汇总人员活动和设备活动
5. 返回活动摘要

### 家庭关爱查询
1. 根据用户询问的家庭成员（老人/儿童），确定查询目标
2. 查询智能门锁历史记录，获取该成员的回家/出门时间
3. 查询AI摄像头区域活动，判断当前所在区域和状态
4. 查询智慧屏/智能音箱使用记录，判断活动类型
5. **【关键】查询老人房/儿童房/卫生间等关键区域的传感器24小时内的人体存在事件，构建活动轨迹**
6. 结合所有数据，生成完整的家庭关爱报告，**确保不遗漏任何活动时段**

### ⚠️ 活动轨迹完整性要求

**查询老人活动时，必须包含但不限于以下区域的传感器事件：**
- 老人房（睡眠/起床监测）
- 客厅/餐厅（日常活动监测）
- 卫生间（异常停留监测）
- 厨房（安全监测）

**时间窗口规则（必须遵守）：**
- 门锁记录：24小时内
- 关键区域传感器（老人房/儿童房/卫生间）：24小时内
- 其他区域传感器：30分钟
- 摄像头：30分钟
- 床垫/手环：24小时

**判定某人"在家活动"的充分条件（满足任一即可）：**
- 24小时内门锁有进门记录
- 24小时内关键区域传感器有人体存在事件
- 30分钟内有摄像头人形检测
- 30分钟内有面板/音箱交互

## 注意事项

1. **时间范围**：明确说明活动查询的时间范围
2. **活动类型**：区分人员活动和设备活动
3. **数据来源**：说明活动数据的来源设备
4. **隐私保护**：不暴露详细的操作细节和参数
5. **判断置信度**：对于推测性判断需说明"可能"、"推测"等词语
6. **关爱提醒**：涉及老人儿童安全的信息需突出显示
7. **异常处理**：检测到异常情况时需明确告知用户并建议关注
8. **敏感信息**：不暴露具体的门锁密码、人脸图像、详细位置轨迹、homeId、memberId、traceId 等内部标识符
9. **禁止输出内部信息**：绝对禁止输出以下内容：
   - ❌ 内部推理过程（如"我先查询了xxx"）
   - ❌ API 调用信息（如 trace-id、请求参数）
   - ❌ 原始数据结构（如 homeId、memberId、deviceId）
   - ❌ 调试日志（如 verbose 日志、warning 日志）
   - ❌ 仅面向开发人员的技术细节
10. **仅输出用户友好内容**：只输出用户直接关心的结论性信息，使用自然语言描述
11. **禁止思考语言**：绝对禁止出现以下词汇和句式：
    - "让我想想"、"我先查一下"、"首先"、"然后"、"接下来"
    - "根据..."、"通过..."、"因为..."、"所以..."
    - "我将..."、"我会..."、"我需要..."
    - 任何内心独白、推理过程、思考过程
    - 直接输出结论，不解释判断过程
