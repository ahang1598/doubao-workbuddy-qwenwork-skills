# GCMark 文本检测验收（1.1.1 历史记录）

本页记录 2026-10-21/22 的旧包实测，不是 1.2.0 的检测结论。1.2.0 的指南结构回归见 [text-guide.md](text-guide.md)，新增 POSM/POSF 与 UOF 2021 等变化尚未重新逐文件进行 GCMark 验收。

目标页面：https://gcmark.com/web/index.html#/mark/check/text

核对日期：2026-10-21 至 2026-10-22。平台公开页面资源 `index-RVk3DUr-.js` 明确区分“可上传格式”和“支持的检测项目”；二者不能混为一谈。

| 本技能格式 | 文本内容显式标识检测 | 元数据隐式标识检测 |
| --- | --- | --- |
| docx、pdf、md | 支持 | 支持 |
| html、htm | 支持 | 平台标为不支持 |
| dotx、xlsx、xltx、pptx、potx、uot、uott、uos、uost、uop、uopt、ofd、xmind | 平台标为不支持 | 支持 |

网站可能更新，验收时以实际页面为准。本技能不能使第三方尚未提供的检测项目变成“合规”。HTML 的 meta 扩展只保证本地写入、回读与保留业务内容。

## 标记与样例

1. 对已生成的每个文件运行 `scripts/main.py <绝对路径>`，同时写入显式与隐式标识。
2. 不使用 `--skip-visible`；该参数仅用于明确要求隐式标识的场景。
3. 使用 `tests/run_text_format_smoke.py <输出目录>` 可生成 18 种不含业务信息的样例，并保存 `text-format-results.json`；其中 `passed` 仅代表本地结构与回读验证，不代表 GCMark 检测通过。
4. GCMark 结果中的两个总览“是”仅表示检出；还需逐项核对提示内容形式、位置、显示文字，以及生成合成标签、提供者编码、内容编号等具体合规结果。
5. 保存被检测文件的 SHA-256、平台结果截图、检测日期及未支持的项目，防止上传错文件或将旧版本结果用于新包。

## 当前线上验收状态

2026-10-21 已由用户登录平台，实际上传并检测 18 种人工构造文件：

- DOCX、PDF、Markdown：显式三字段、隐式五字段全部合规，共 24 个必检字段通过。
- HTML、HTM：显式三字段全部合规；平台不支持元数据检测。
- XLSX、PPTX、DOTX、XLTX、POTX、XMind：隐式五字段全部合规；平台不支持显式检测。
- OFD：原样例未检出。为同一 CustomData 属性补充指南采用的小写 `name="AIGC"` 后，隐式五字段全部合规；同时保留原生 `Name`。技能已加入该兼容修复与回归检查，最终 CLI 产物已再次上传复测，隐式五字段全部合规。
- UOT、UOTT、UOS、UOST、UOP、UOPT：原样例未检出。比较用户下载的平台标识产物后，在原生 2009 元数据旁补充平台使用的 2021 命名空间兼容记录，保持同一来源 JSON；最终 CLI 产物全部重新上传，逐个核对五个必检字段，全部合规（30 项）。原生节点、正文和附件保留；合法来源冲突时停止并保留文件。

截至 2026-10-22，18 种样例在平台支持的检测项目上全部通过，共 95 个必检字段合规；不能表述为“18 格式双项通过”。两项均需在该站通过的交付使用已实测的 DOCX、PDF、Markdown。UOF 线上结果对应 UOF 2 ZIP 样例，旧版 UOF 1 单 XML 未进行网站验收。结果只对应受检文件的 SHA-256 和本次检测日期，不覆盖任意文件变体或未来平台版本。


## 标识数据与规范

- 生成合成服务提供者编码沿用技能既有值，本次未改变服务身份或核验其登记状态。
- 新生成的七个字段均为字符串。两个预留字段可为空；不为了凑齐“合规”而伪造签名、服务编码或检测结果。
- Markdown 按 TC260-PG-20258A 的 YAML 头部对象形式写入，并保留原有 frontmatter；OOXML/UOF/OFD/XMind/PDF 的元数据位置沿用格式规范。
- 标识格式与回读检测不能单独替代网站验收或业务合规评估。
