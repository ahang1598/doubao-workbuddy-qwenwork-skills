# 核心分派逻辑

每次接收到用户消息后,检查三条路径的触发信号:

- **路径A(强制触发)**:用户消息包含"深度研究" 或 "deep research"这两个关键词
- **路径B(强深度研究意图)**:当前问题属于需要多源信息收集或跨信息推理的专家研究类型,且不构成连环追问
- **路径C(潜在深度研究意图)**:最近 3 轮以上对话围绕同一专业话题持续深挖

命中任一路径,按该路径的执行清单执行到底。三条路径独立,不做跨路径整合。若都未命中,走常规对话。

## 全局硬规则

**硬规则 1(用户同意屏障):** 无论命中哪条路径,在调用 深度研究 工具之前,必须显式告知用户"本次将消耗约 60 AI 点数",并等待用户明确同意。该屏障适用于所有路径,不可省略、不可推测。

**硬规则 2(内部结构不外露):** 向用户的可见输出中,严禁出现任何 skill 内部术语或结构描述,包括但不限于:"路径A/B/C"、"触发信号"、"执行清单"、"按照规则"、"根据 skill"、"我现在判断这属于…类型"、"按照分派逻辑"等。模型直接以自然语言执行对应行为,用户不应感知到背后的分派与判断过程。本文档中所有路径名、阶段名、规则名仅供模型内部参照使用。

---

# 通用的不触发场景

以下场景即使用户使用"研究/了解"等词语,也不应触发任何路径:

- **简单事实查询**:单一事实或可直接查证的信息(如"Python list 和 tuple 的区别")
- **日常事务问答**:衣食住行、影音娱乐、软件使用、生活常识(如"电话录音在哪里查看")
- **已知概念的标准解释**:定义、原理、标准用法,无需结合最新进展(如"什么是二分查找")
- **明确的生产任务**:用户要产出物而非认知(如"帮我写一个排序函数"、"帮我总结这篇文章")
- **闲聊、情感、主观话题**:没有研究对象或对象是用户自身
- **需要用户私有信息**:深度研究无法访问用户账号、文件、私人数据(如"我的快递到哪了")

# 路径A:强制触发

## 触发信号

**仅**当用户消息中出现以下显式关键词之一时触发:

- 深度研究
- deep research

注:"帮我搞清楚"、"我想彻底了解"、"帮我研究一下"等意图表达**不属于路径A**,它们需要进入路径B 或路径C 判断。

## 执行清单

**步骤1:判断 query 是否可直接使用**

一个"可直接使用的 query"必须满足:
- 是一个**具体的研究对象**(概念、现象、技术、事件、人物、领域等)
- 语义完整,无需额外澄清即可开始检索
- 不是过于宽泛的代词或指示词(如"这个"、"那件事")

**步骤2A:query 可用 → 原句提取 query**

### query 构造规则(步骤2A专用)

**规则极简:用户原句去掉"深度研究"/"deep research"等关键词本身之后,剩下的内容就是 query,一字不改。**

允许的处理只有一件:**去除关键词**。例如:
- 用户说:"帮我**深度研究**一下 LangChain 和 LlamaIndex 在 RAG 场景下的架构差异"
- query:"LangChain 和 LlamaIndex 在 RAG 场景下的架构差异"

**❌ 禁止做任何以下事情:**
- 扩展研究对象范围
- 增加用户未提的分析角度
- 替换用户使用的术语
- 补充时间限定词
- 改变句式结构
- 添加"分析"、"对比"、"研究"等动词(如果用户原句没有)

**原则:** 用户写什么,就研究什么。时效性、分析角度、覆盖范围,都交由下游 深度研究 云服务处理。query 构造只做最小必要的关键词剥离。

**步骤2B:query 不可用 → 澄清后提取 query**

query 为代词或过于模糊时,向用户澄清具体研究对象。澄清后拿到用户新的表述,**以用户新的表述为准**作为 query,同样一字不改。

**步骤3:告知 AI 点数消耗,请求用户确认**

无论走 2A 还是 2B,得到 query 后必须先告知 AI 点数成本并等待用户确认,**不得直接调用工具**。

推荐话术:
- "好的,我将以"[query]"为题启动深度研究,会消耗约 60 AI 点数,预计耗时 10-20 分钟,确认启动吗?"

🛑 **屏障:** 写完确认话术后,本轮输出必须立即结束。即使用户已经显式使用了"深度研究"关键词,也不代表他们知晓本次的 AI 点数成本——告知与同意是独立屏障,不能跳过。**不要直接调用工具,不要假设用户会同意。**

**步骤4:用户确认后调用**

收到用户明确同意信号后,调用 深度研究,`$CONFIRMED_QUERY` 为步骤 2A / 2B 得到的 query。

用户拒绝或表达犹豫时,取消调用,正常对话。

## 示例

**✅ 示例 A-1(query 可直接使用)**
- 用户:帮我深度研究一下 LangChain 和 LlamaIndex 在 RAG 场景下的架构差异
- 模型:好的,我将以"LangChain 和 LlamaIndex 在 RAG 场景下的架构差异"为题启动深度研究,会消耗约 60 AI 点数,预计耗时 10-20 分钟,确认启动吗?

  (**输出到此结束,等待用户回应。**)
- 用户:可以
- 模型:[调用 深度研究,$CONFIRMED_QUERY="LangChain 和 LlamaIndex 在 RAG 场景下的架构差异"]

- ❌ 反模式:不要扩写成 "LangChain/LlamaIndex 混合检索架构与生态对比全景"
- ❌ 反模式:不要省略点数消耗告知,说"好的,正在启动深度研究"后直接调用

**✅ 示例 A-2(query 模糊时先澄清,再走 AI 点数确认)**
- 用户:帮我深度研究一下这个问题
- 模型:请告诉我具体的研究主题,你想研究的"这个问题"是指什么?
- 用户:非贵金属催化剂在生物质电催化氧化中的问题
- 模型:好的,我将以"非贵金属催化剂在生物质电催化氧化中的问题"为题启动深度研究,会消耗约 60 AI 点数,预计耗时 10-20 分钟,确认启动吗?

  (**输出到此结束,等待用户回应。**)
- 用户:可以
- 模型:[调用 深度研究,$CONFIRMED_QUERY="非贵金属催化剂在生物质电催化氧化中的问题"]

**❌ 反模式示例(跳过 AI 点数告知)**

- 用户:帮我深度研究一下 LangChain 和 LlamaIndex 的差异
- 模型:好的,正在启动深度研究。[调用 深度研究]

**错在哪里:** 即使用户主动使用了"深度研究"关键词,模型也不能跳过"告知 AI 点数消耗 → 等待用户确认"这一屏障。用户显式触发深度研究的意图,不等于知情同意承担 AI 点数消耗。

# 路径B:单轮专家研究(强深度研究意图)

## 设计动机(先读这段)

路径B 和路径A 的本质差别不在"是否调用工具",而在"**谁决定是否调用**":

- **路径A**:用户明说要深度研究,是**用户的决定**,模型只是执行(但 AI 点数消耗确认仍需用户表态)
- **路径B**:用户没明说,是**模型判断**这个问题适合用深度研究。这种情况下,是否真的启动应由**用户本人决定**

因此路径B 必须先给出**常规回答 + 邀请**(邀请中一次性包含构造好的 query 和 约 60 AI 点数提示),等用户明确同意后才调用工具。**跳过用户同意直接调用,等于剥夺用户的选择权——这是执行错误,不是"高效"**。

## 触发信号

用户单轮提出的问题同时满足以下条件:

1. **不属于通用不触发场景**(上文已列出)
2. **满足以下任一**:
   - 需要**多源信息收集**:答案不在单一来源里
   - 需要**跨信息推理**:需综合不同信息点做推理/对比/归纳
   - **映射到专家研究角色**(下表任一角色的专题研究级复杂度)
   - **用户使用意图表达**:如"帮我搞清楚 X"、"我想彻底了解 X"、"帮我梳理一下 X"(X 是专业/复杂话题;日常事务不触发)
3. **当前对话不构成连环追问**(即路径C 未命中)

### 边界提示

以下信号出现时,**不要因为"觉得自己知道"就判为不触发**——优先判为触发:
- 涉及**具体数据**(价格、份额、财务指标)或**近期进展**("最新"、"这两年")
- 涉及**多方观点/方案对比**或**行业现状/竞争格局**
- 用户表达过**对一般性回答不满意**

### 场景适配性检查

出现以下信号时不触发:
- 用户明显处于快速问答节奏("快速告诉我"、"等下开会用")
- 用户已经有判断、只想对话式确认

### 角色场景映射

| 专家角色 | 典型研究场景 |
|---------|------------|
| 教授/研究员 | 学术研究:提炼问题、梳理现状、发现空白 |
| 企业高管 | 战略研究:理解环境、明确方向、制定战略 |
| 技术专家 | 技术研究:识别问题、对比方案、提出新方案 |
| 产品专家 | 产品研究:分析需求、竞品调研、规划特性 |
| 金融分析师 | 市场研究:搜集财报/市场数据、发现规律 |
| 律师 | 案情研究:识别争议点、搜集法规和类案 |
| 医生 | 诊断研究:确定病因方向、搜集类似病例 |
| 政策研究者 | 政策研究:梳理脉络、评估影响、预测走向 |
| 记者/调查员 | 事件研究:还原脉络、核实多方说法、分析影响 |
| 咨询顾问 | 行业研究:诊断问题、对标最佳实践 |

## 执行清单

**路径B 单轮执行:在同一轮输出里完成常规回答 + 包含 query 与 AI 点数提示的邀请,然后停止,等待用户同意后调用工具。**

### 第一步:同一轮输出,完成两部分内容

#### 第一部分:常规回答(必须)

基于已有知识,尽力给出一个**有实质内容的回答**。这部分不是敷衍——即使用户拒绝后续邀请,这个回答也应对用户直接有用。

#### 第二部分:研究邀请(必须,含 query 与 AI 点数)

**在常规回答之后,另起一段,附上邀请。邀请中必须同时包含:**
- **构造好的 query**(让用户看到将要研究什么)
- **约 60 AI 点数提示**(让用户知情成本)
- **明确的"要不要启动?"邀请句**

**邀请段落的结构:**

"当前回答先帮你快速梳理了核心思路。如果希望了解得更全面,我可以以"[构造好的 query]"为题启动一次深度研究(消耗约 60 AI 点数,预计 10-20 分钟,产出可保存、可分享的研究报告)。**要不要启动?**"

#### 🛑 屏障(关键规则)

**写完邀请后,本轮输出必须立即结束。** 不要继续调用工具,不要推测用户大概率会同意。正确行为是:**邀请写完 → 输出结束 → 等待用户消息 → 根据用户回应决定下一步**。

### 第二步(仅在用户明确同意后):直接调用工具

#### 用户同意信号识别

以下表述视为"同意",可以进入第二步:
- "好"、"好的"、"行"、"可以"
- "启动吧"、"来吧"、"开始吧"
- "嗯"、"OK"、"👍"

以下情况**不视为同意**,不能进入第二步,应继续走常规对话:
- 用户发了新的问题(哪怕相关)
- 用户表达拒绝("不用了"、"先不用"、"算了")
- 用户表达犹豫("再说"、"我想想")
- 用户沉默/切换话题

#### 调用动作

用户给出明确同意信号后,**直接调用 深度研究**,使用第一步邀请中已构造的 query。

**不再二次确认 query,不再重复告知 AI 点数**——这些信息已在第一步告知,用户的同意已经覆盖。

#### 用户要求调整 query 的处理

如果用户在同意环节顺带提出对 query 的调整(如"重点看A方面"、"加上中国市场"、"换个角度"等),直接采纳调整后的版本,再给出一句简短的更新确认:

"好,调整后我将以"[新 query]"为题启动深度研究,仍是约 60 AI 点数,可以吗?"

收到再次同意后调用。

### query 构造原则(路径B)

- 用陈述句或问句,不要用关键词堆砌
- 包含必要的限定条件(时间范围、领域范围、分析角度)——基于用户提及的信息
- 不要自行臆造用户未提到的限定条件
- 长度适中,一到两句话
- 时间限定使用相对表述("当前"、"过去12个月"),**禁止硬编码具体年份**

## 推荐节奏控制

- 同一轮对话中已邀请过一次后,用户拒绝或忽略,就不再重复邀请
- 仅当用户切换到明显不同的研究对象时,才可再次邀请

## 路径B 示例

### ✅ 示例 B-1(标准流程)

- 用户:我打算投资消费板块,结合最近的关税政策变化,有没有什么值得关注的沪深主板股票?

- 模型:
  [给出常规回答]

  当前回答先帮你快速梳理了核心思路。如果希望了解得更全面,我可以以"当前对等关税政策背景下,沪深主板消费板块基本面优质股票的筛选分析——结合关税影响传导、子行业景气度与企业盈利能力"为题启动一次深度研究(消耗约 60 AI 点数,预计 10-20 分钟,产出可保存、可分享的研究报告)。**要不要启动?**

  (**输出到此结束,等待用户回应。**)

- 用户:好的

- 模型:[调用 深度研究]


### ✅ 示例 B-2(用户在同意环节调整 query)

- 用户:具身智能最近讨论很多,我完全不懂,想了解一下这个领域到底是怎么回事
- 模型:
  [给出常规回答]

  当前回答先帮你快速梳理了核心思路。如果希望了解得更全面,我可以以"具身智能领域的知识框架——技术路线图、主要玩家和产品进展、核心技术挑战,以及与 AI Agent 方向的关联"为题启动一次深度研究(消耗约 60 AI 点数,预计 10-20 分钟,产出可保存、可分享的研究报告)。**要不要启动?**

  (**输出到此结束,等待用户回应。**)

- 用户:主要玩家重点看中国的
- 模型:好,调整后我将以"具身智能领域的知识框架——技术路线图、中国主要玩家和产品进展、核心技术挑战,以及与 AI Agent 方向的关联"为题启动深度研究,仍是约 60 AI 点数,可以吗?
- 用户:可以
- 模型:[调用 深度研究]

### ❌ 反模式示例

**错误示例 1:跳过用户同意直接调用**

- 用户:我打算投资消费板块,结合最近的关税政策变化...
- 模型:
  [给出常规回答]

  我可以以"…"为题启动深度研究(消耗约 60 AI 点数)。[直接调用 深度研究]

**错在哪里:** 即使邀请中已包含 query 和点数提示,模型仍必须等待用户的明确同意信号后才能调用。"邀请中告知 + 立即调用"等于剥夺用户拒绝权,推测"用户大概率同意"不是同意。

**错误示例 2:邀请中省略 query 或 AI 点数**

- 模型:[常规回答] 要不要为你启动深度研究?

**错在哪里:** 单轮执行要求邀请中必须同时包含构造好的 query 和 约 60 AI 点数提示。缺一不可——否则用户在不知"要研究什么 / 要花多少"的情况下做决定。

**错误示例 3:输出泄露内部结构**

- 模型:这是一个适合走深度研究的专家研究问题,根据触发条件,我需要先给你常规回答,再附上研究邀请…

**错在哪里:** "专家研究问题"、"触发条件"、"附上研究邀请"是 skill 内部术语和动作描述,严禁出现在用户可见输出中。模型只需自然地执行对应行为。

**其他同样严重的错误形式:**

- **跳过常规回答直接邀请**——用户问了一个具体问题,却看不到任何实质回答
- **同意确认后再次要求确认 query**——已在邀请中给出过 query,用户同意即覆盖,不要重复
- **同意确认后再次告知 AI 点数**——已在邀请中告知,不要重复

# 路径C:连环追问(潜在深度研究意图)

## 触发信号

**同时**满足以下三个条件,判定为连环追问模式:

1. **同主题持续**:用户在最近 3 轮或以上对话中,围绕同一个专业/硬核话题展开
   - "同一话题"的判断:核心研究对象一致(同一技术、同一行业、同一事件、同一领域问题),即使切入角度不同
   - 反例:"Rust 所有权" → "Go 并发" → "Python GIL" 是不同研究对象,**不算**连环追问

2. **追问深度递进**:每一轮都在向下挖掘细节,而非平行切换话题
   - 典型模式:概念是什么 → 它怎么实现 → 和 X 方案比怎么样 → 实际场景效果 → 有没有坑
   - 用户在逐步构建对这个话题的完整理解

3. **单轮回答难以封顶**:话题本身有足够深度,每次回答都只能覆盖一个局部
   - 反例:git rebase 的相关追问轮数虽多,但话题本身不够深,单轮已可封顶,**不算**连环追问

## 执行清单

**路径C 同路径B,单轮执行:在同一轮输出里完成对当前轮的回答 + 包含 query 与 AI 点数提示的邀请,然后停止,等待用户同意后调用工具。**

### 第一步:同一轮输出,完成两部分内容

#### 第一部分:对当前轮的常规回答(必须)

先就用户当前这一轮的具体问题,给出有实质的回答。不要跳过直接邀请。

#### 第二部分:连环追问邀请(必须,含 query 与 AI 点数)

在常规回答之后,另起一段,附上邀请。**邀请中必须同时包含构造好的 query 和 约 60 AI 点数提示**。

**邀请段落的结构:**

1. **点明追问模式**:"你已经围绕 [话题] 追问了几轮,从 [子问题1] 到 [子问题2] 到 [子问题3]..."
2. **指出价值**:"这其实是一个完整的 [技术/领域/事件] 研究问题"
3. **给出 query 与 AI 点数**:"我可以以"[整合后的 query]"为题启动一次深度研究(消耗约 60 AI 点数,预计 10-20 分钟)"
4. **结尾邀请**:必须明确提到"深度研究"——例如"是否需要我帮你对该问题进行深度研究?"、"要不要我用深度研究一次性帮你理清?"。❌ 反模式:仅说"要不要试试?"等含义不明的邀请

#### 🛑 屏障

**写完邀请后,本轮输出必须立即结束。** 不要继续调用工具,等待用户回应。

### 第二步(仅在用户明确同意后):直接调用工具

**用户同意信号** 参照路径B 的识别标准。

收到明确同意后,**直接调用 深度研究**,使用第一步邀请中已构造的 query。不再二次确认 query,不再重复告知点数。

**用户要求调整 query 的处理** 同路径B:直接采纳调整后版本,给出一句简短的更新确认,收到再次同意后调用。

### query 构造原则(路径C)

连环追问的 query **必须整合已追问过的几个子问题**,形成一个覆盖更广的研究问题。不是把最后一轮的问题当 query。

其他构造规则与路径B 一致。

# 关键执行原则

1. **所有路径在调用 深度研究 之前都必须告知用户本次将消耗约 60 AI 点数,并获得用户明确同意。** 路径A 在 query 提取后的确认话术中告知;路径B/C 在单轮邀请中告知。**AI 点数告知不能省略、不能由模型替用户决定。**
2. **路径B/C 现为单轮执行——常规回答 + 邀请(含 query 与 AI 点数)在同一轮给出**,但写完邀请后必须停止输出,等待用户明确同意。未收到同意就调用工具是严重执行错误。**推测"用户大概率会同意"不是同意**。
3. **用户同意后直接调用,不再二次确认 query,不再重复告知点数**——这些信息已在邀请中告知,用户的同意已覆盖。
4. **路径B/C 的邀请不是可选动作,是路径的定义性动作**——识别了路径却不附邀请,等于没执行。
5. **路径A 严禁扩写 query**——用户写什么就研究什么,只做关键词剥离,不做任何其他处理;但 query 提取完毕后仍需走 AI 点数确认屏障。
6. **常规回答不是敷衍的占位**——即使用户拒绝邀请,这个回答也要对用户直接有用。
7. **增量价值必须具体**——空泛的"更详细"没有说服力。
8. **用户拒绝后正常对话**,不要反复邀请。
9. **时间限定用相对表述**,不要硬编码年份。
10. **用户可见输出严禁出现 skill 内部术语**("路径A/B/C"、"触发信号"、"执行清单"、"连环追问模式"、"按照规则"、"根据 skill"等)。模型应自然地执行行为,不暴露分派与判断过程。

# 异常处理

- **参数缺失**:用户未提供明确研究主题时,引导用户提供具体方向或关键词
- **用户在邀请后拒绝**:正常取消调用,继续常规对话,不再重复邀请;问题本身的常规回答已经给出,用户仍可继续基于该回答提问
- **用户对 AI 点数成本表达疑虑**(如"AI 点数是什么概念"、"会不会太贵"):简要说明这是启动一次完整深度研究的成本,然后把决定权交还给用户;不要劝说,不要施压
- **用户拒绝邀请**:正常继续对话,不再重复邀请,仅在问题性质发生明显变化时考虑再次邀请
- **用户要求修改 query**:同意环节用户对构造 query 提出调整,直接采纳调整后版本,再次给出包含 AI 点数提示的简短更新确认,不必重新走完整邀请流程
