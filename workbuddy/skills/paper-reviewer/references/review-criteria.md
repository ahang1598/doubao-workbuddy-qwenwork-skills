# Review Criteria — 评分锚点与评审细则

供 paper-reviewer skill 在 Step 2（识别领域后）与 Step 4（逐维度分析）加载使用。

---

## 一、Overall Score 评分锚点（NeurIPS/ICLR 风格，1-10）

| 分数 | 含义 | 判定标准 |
|---|---|---|
| 10 | Top 1% | 领域里程碑，开创全新方向，技术无懈可击 |
| 9 | Top 5% | 强烈接收（Strong Accept），重大创新 + 扎实证据 |
| 8 | Top 15% | 接收（Accept），明确创新，证据充分，瑕疵极少 |
| 7 | Good paper | 接收（Accept），扎实贡献，有少量可修复问题 |
| 6 | Marginally above threshold | 弱接收（Weak Accept），贡献真实但增量有限或证据有小缺口 |
| 5 | Marginally below threshold | 弱拒（Weak Reject），创新性或严谨性有明显短板，但非一无是处 |
| 4 | Reject | 拒稿（Reject），贡献不足或技术缺陷严重 |
| 3 | Clear reject | 明确拒稿，多处硬伤，或属增量式跟风 |
| 2 | Strong reject | 强烈拒稿，结论不成立或有学术诚信疑点 |
| 1 | Trivial / wrong | 毫无价值或根本性错误 |

评分校准原则：

- 6 分 = "这篇论文对领域有净贡献，值得被社区看到" 的分水岭。
- 分数必须与 Strengths/Weaknesses 的分量自洽：列了 3 条致命 weakness 却给 7 分，属于自相矛盾，禁止出现。
- 先在内心打出初分，写完 weaknesses 后回头校准一次。

## 二、Confidence 置信度（1-5）

| 分数 | 含义 |
|---|---|
| 5 | 审稿人是该子领域专家，熟悉所有相关工作，对判断完全有把握 |
| 4 | 熟悉该领域，仔细检查了主要 claim，有把握 |
| 3 | 基本了解该领域，主要判断可信，细节可能有遗漏 |
| 2 | 对领域了解有限，评审尽力但可能误判 |
| 1 | 非本领域，仅能提供表层意见 |

降档规则（满足任一即降至 ≤3）：

- 无法验证论文核心证明/推导的正确性；
- 不熟悉论文所对比的基线方法；
- 论文依赖高度专业的领域知识（湿实验、领域数据特性）而无法独立判断。

## 三、五维度评审细则

### 1. Novelty（新颖性）

考察点：

- 核心 idea 是新问题、新方法、新理论、新数据，还是已有工作的组合/微调？
- 与最接近的 3-5 篇相关工作的本质区别是什么？（作者的相关工作章节是否如实、完整地呈现了这种区别？）
- 创新是"概念性创新"（新视角）还是"技术性创新"（新机制）？组合式工作若带来质变也可算创新，但要说明质变在哪。

常见误判提醒：

- 不要把"我第一次见"当作"领域首创"——拿不准时用 WebSearch 核查近年相关工作。
- 增量工作的分数落在 4-6 区间，除非增量带来了出乎意料的洞察。

### 2. Soundness（技术严谨性）

考察点：

- **Claim-证据匹配**：论文的每个核心 claim 是否有对应的实验/证明支撑？是否存在实验只支撑弱结论、摘要却声称强结论的"overclaim"？
- **方法正确性**：推导、算法设计、系统架构有无逻辑漏洞或技术性错误？
- **实验设计**：基线是否公平且足够强？数据集是否标准？是否有数据泄漏（train/test 污染）？消融实验是否覆盖核心组件？统计显著性（多随机种子、方差报告、假设检验）是否具备？
- **理论论文**：证明是否完整？关键引理是否被引用而非证明？假设是否合理且被明确陈述？

### 3. Clarity（表达清晰度）

考察点：论文结构是否清晰；notation 是否一致且定义完备；图表是否自明（不看正文能否读懂）；方法描述是否足以让同领域研究者复现思路；是否存在关键歧义。

### 4. Significance（影响力）

考察点：问题本身重要吗？解法会被后续工作采用吗？对实践者有用吗？结论是否会改变社区对某个问题的认知？注意区分"问题重要"与"解法有影响力"——前者不构成接收理由。

### 5. Reproducibility（可复现性）

考察点：是否开源代码/数据（或承诺接收后开源）；超参数与训练细节是否完整；计算资源是否说明；是否有匿名仓库；依赖的数据/模型是否可获得。完全无法复现的工作在 ML 领域通常压分 1-2 档。

## 四、分学科检查清单

按 Step 2 识别的学科选用对应清单，作为五维度的补充检查项。

### 机器学习 / 深度学习（通用）

- [ ] 基线是否包含 SOTA 及经典方法，超参是否公平调优
- [ ] 是否报告多个随机种子的均值±方差
- [ ] 消融实验是否逐一验证每个新增组件的贡献
- [ ] 训练/测试划分是否标准，有无数据泄漏嫌疑
- [ ] 计算成本（FLOPs/显存/训练时长）是否报告并与基线可比
- [ ] 提升幅度是否超过随机波动范围（小提升 + 无方差报告 = 重大疑点）

### NLP / 大模型

- [ ] 评测 benchmark 是否多样且无污染（训练集混入评测数据是 LLM 时代头号嫌疑）
- [ ] Prompt/解码设置是否公开；人工评测是否有 inter-annotator agreement
- [ ] 与闭源模型对比时是否说明版本与调用方式
- [ ] 是否存在"用 GPT-4 评测 GPT-4 类输出"的循环评测偏差

### 计算机视觉

- [ ] 数据集划分是否遵循官方协议；预训练数据是否说明
- [ ] 数据增强/测试时增强是否对基线公平
- [ ] 定性结果是否有 cherry-picking 嫌疑（有无失败案例分析）

### 系统 / 网络 / 软件工程

- [ ] 性能评测的硬件/负载/基线系统是否真实且可复现
- [ ] 是否区分了"原型实现的开销"与"设计本身的开销"
- [ ] 可扩展性（scalability）claim 是否有大规模实验支撑
- [ ] SE 实证研究：样本量、代表性、效度威胁（threats to validity）是否讨论

### 理论（数学/算法/学习理论）

- [ ] 定理陈述是否精确（常数、假设、界的形式）
- [ ] 证明是否自包含；跳步处是否有依据
- [ ] 假设是否过强以至于结论平凡（trivial under assumptions）
- [ ] 与已知下界/上界的关系是否讨论

### HCI / 人机交互

- [ ] 用户研究的样本量、人口统计、招募方式是否报告
- [ ] 是否有伦理审批（IRB）与知情同意说明
- [ ] 定量结论的统计检验是否正确使用

### 生物信息 / 医学

- [ ] 样本量与功效分析；p 值校正（多重检验）
- [ ] 数据集的独立外部验证是否存在
- [ ] 临床 claim 是否有对应证据等级支撑；伦理审批是否齐全

### 社会科学 / 经管

- [ ] 内生性/因果识别策略是否可信（工具变量、DID、RCT 的适用条件）
- [ ] 稳健性检验是否充分；变量度量是否有效（信度/效度）
- [ ] 数据来源与样本选择偏差是否讨论

### 自然科学实验（物理/化学/材料等）

- [ ] 实验装置与测量方法是否足以支撑结论
- [ ] 误差分析与对照组设置是否完备
- [ ] 数据可获取性（原始数据是否公开）

## 五、常见致命缺陷（Fatal Flaws）清单

发现以下任一条，通常直接压到 4 分及以下，并在 review 开头点明：

1. 核心 claim 无证据支撑或证据与 claim 不匹配（overclaim）
2. 实验存在数据泄漏 / 基线明显不公平 / 评测方法错误
3. 理论证明存在关键错误，且无法小修
4. 与已发表工作实质重复而未引用（创新性失实，严重时涉及学术诚信）
5. 结果无法复现且作者拒绝提供任何细节
6. 统计结论存在根本性错误（如把相关性当因果，且无识别策略）

## 六、Major vs Minor 问题区分标准

- **Major（影响录用决定）**：涉及 claim 是否成立、创新是否真实、实验是否可信、证明是否正确——修复需要新的实验、证明或实质性改写。
- **Minor（不影响核心判断）**：排版、笔误、图表可读性、notation 不统一、缺少非关键的参考文献、附录组织混乱——修复不需要新的研究性工作。

写 review 时把两类分开：major weaknesses 进 "Weaknesses" 主体并影响分数；minor issues 可单列一节（Minor Comments / Typos），不显著影响分数。
