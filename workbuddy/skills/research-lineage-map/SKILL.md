# Research Lineage Map 研究谱系演进图

## Overview

为研究主题、模型家族或技术线索绘制"家谱式"演进图，核心是把**思想的演化路径**可视化：每个关键工作解决了什么问题、又被谁如何改进。最终交付一个嵌入 Mermaid 图表的独立 Markdown 文件。

## 核心设计原则

1. **"问题 → 解决"叙事是灵魂**：每条演进边必须回答"后来者解决了前人的什么问题"，而不是只画引用关系。
2. **年份是硬约束**：每个节点必须标注发表/发布年份，且关键节点的年份与血缘关系经联网核实。
3. **少而准优于多而错**：精选 8–20 个真正有承继关系的关键节点，拒绝堆砌。
4. **事实冲突以检索为准**：内部知识与联网结果冲突时，采用检索结果并在参考资料区留痕。

## 工作流程

### 第 1 步：明确范围与粒度

确认主题边界、时间跨度与节点粒度（论文级 / 模型版本级 / 范式级）。主题过大时（如"整个 NLP 史"），先收窄，或采用"总览图 + 分支子图"的分层画法。用户意图明确时直接判断，不必反复追问。

### 第 2 步：起草谱系节点清单

基于内部知识列出候选节点，每个节点记录：名称、年份、核心贡献、**解决了什么问题**、改进自谁、被谁改进。此清单是后续绘图与写表格的同一份数据源。

### 第 3 步：联网核实关键史实

用 WebSearch / WebFetch 核实每个节点的：发表或发布年份、名称拼写、承继关系（谁明确提出要解决谁的什么问题）。优先来源：arXiv 论文页、官方博客、机构公告、经典综述。核实失败的节点在明细表中标注"（年份待考）"，不得编造。

### 第 4 步：设计 Mermaid 谱系图

先阅读 `references/mermaid-patterns.md`（含语法模式与高频坑）。要点：

- 主图用 `flowchart`，按年代或范式划分 `subgraph` 泳道，用 `classDef` 着色区分开创性工作 / 增量改进 / 旁支。
- 演进边用带文字的箭头（`-->|解决了什么问题|`），旁支或弱化关系用虚线。
- 节点超过约 15 个或明显多分支时，拆为总览图 + 若干分支子图。
- 可选：文末附 `timeline` 简版时间线作为速览。

### 第 5 步：撰写 Markdown 文件

严格按 `references/output-template.md` 的结构产出：标题与一句话概览 → 主演进图 → 关键节点明细表（年份 / 贡献 / 解决的问题 / 来源）→ 阶段叙事（按年代分段，讲清"问题 → 解决"链条）→ 可选时间线 → 参考资料。文件语言跟随用户语言。

### 第 6 步：校验与交付

运行校验脚本检查全部 Mermaid 代码块，修复所有报错后再交付：

```bash
python scripts/validate_mermaid.py <输出文件.md>
```

校验通过后，用 `present_files` 交付 `.md` 文件，并提示用户：GitHub / GitLab / VS Code / Typora / Obsidian 及 mermaid.live 均可直接渲染。

## Resources
