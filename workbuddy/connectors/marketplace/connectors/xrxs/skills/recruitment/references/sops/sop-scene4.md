# 场景四：获取面试官日程

> **阅读提示：** 本文档为 [`../sop-summary.md`](../sop-summary.md) 场景四的详细步骤，通用约定见 [`common.md`](common.md)。命中本场景后严格按下列步骤执行，不得跳过、不得自行发明等价命令序列。

## 适用场景与触发话术

- 用户话术示例（含同义表达）：
  - 「查一下张经理的面试日程」
  - 「看看李总下周有没有空」
  - 「王面试官最近忙吗」
  - 「查询面试官日程」
- 关键词：面试官日程、面试日程、查日程、有没有空、最近忙吗。

> **原则：** 凡是用户希望「查询某位面试官的面试/日程安排」的需求，**统一走本场景**；本场景只输出分析后的日程总结，不展示原始空列表。

## 前置信息

| 信息 | 必填 | 说明 |
|------|------|------|
| 目标面试官 | 是 | 可直接提供 32 位 UUID 员工 ID，或提供姓名/手机号由 `searchEmployee` 定位 |
| 时间范围 | 否 | 用户未指定时默认查询未来 7 天；用户指定时按指定范围查询 |

## 执行步骤

### 步骤 1 — 识别目标面试官

先判断用户提供的是 32 位 UUID 还是自然标识（姓名/手机号等）。

**若提供的是 UUID（32 位字符串）：**

- 直接作为 `interviewerId` 使用。
- 用户明确说「员工 ID 是 xxx」时，也可直接作为对应 ID。

**若提供的是自然标识：**

调用：

```bash
xrxs-cli recruitment searchEmployee --request-body json
```

请求体示例：

```json
{
  "keyword": "张经理",
  "pageNo": 1,
  "pageSize": 20,
  "status": 0
}
```

- 若返回多条匹配记录，列出候选供用户确认，**禁止批量猜测**。
- 若返回为空，提示用户未找到该员工。
- 定位完成后，提取真实的 `employeeId` 作为 `interviewerId`。

### 步骤 2 — 查询面试官日程

```bash
xrxs-cli recruitment getInterviewerScheduleCalendar --request-body json
```

请求体示例：

```json
{
  "startDate": "2026-08-15",
  "endDate": "2026-08-21",
  "interviewers": [
    {
      "interviewerId": "EMP_123456",
      "companyId": "",
      "interviewDate": "2026-08-15"
    }
  ],
  "interviewTime": "2026-08-15 09:00",
  "duration": 60
}
```

- 用户未指定时间范围：默认查询未来 7 天。
- 用户指定了时间范围：按指定范围查询。
- `interviewTime` 和 `duration` 可按默认值填充（如当天 09:00、60 分钟），仅用于接口校验，不影响日程展示结果。

### 步骤 3 — 总结分析并输出

基于 `getInterviewerScheduleCalendar` 返回的 `days` 数据进行分析：

- 按日期分组，列出每天的日程概要（日程类型、时间段、事项说明）。
- 若某日没有日程，不单独展示该日期或仅简要说明「某日无安排」。
- 若整个时间范围内都没有日程，直接输出「该面试官在查询范围内无日程安排」。
- **禁止将原始的空列表 `[]` 直接返回给用户**。

输出示例：

```
张经理（EMP_123456）未来 7 天日程如下：
- 2026/08/16：14:00-15:00 面试 - 候选人张三（Java 工程师一面）
- 2026/08/18：09:00-12:00 请假
- 其余日期无安排
```

## 异常分支

| 异常情况 | 处理方式 |
|----------|----------|
| `searchEmployee` 返回多条记录 | 列出候选供用户确认 |
| `searchEmployee` 返回为空 | 提示未找到该员工 |
| `getInterviewerScheduleCalendar` 返回为空或全部无日程 | 输出「该面试官在查询范围内无日程安排」 |
| 关键字段缺失 | 以实际返回为准，缺失字段不展示、不编造 |
