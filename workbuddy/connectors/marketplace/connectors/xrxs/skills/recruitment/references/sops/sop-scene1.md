# 场景一：人岗推荐

> **阅读提示：** 本文档为 [`../sop-summary.md`](../sop-summary.md) 场景一的详细步骤，通用约定见 [`common.md`](common.md)。命中本场景后严格按下列步骤执行，不得跳过、不得自行发明等价命令序列。

## 适用场景与触发话术

- 用户话术示例（含同义表达）：
  - 「帮我推荐几个合适的候选人」
  - 「根据这个职位推荐几份简历」
  - 「给我推荐匹配度高的候选人」
  - 「看看这个职位有哪些合适的人选」
- 关键词：推荐、人岗匹配、合适候选人、匹配度、根据职位推荐简历。

> **原则：** 凡是用户希望「根据职位找候选人」或「推荐合适简历」的需求，**统一走本场景**；本场景只输出推荐清单，不实际执行 `recommendResume`。

## 前置信息

| 信息 | 必填 | 说明 |
|------|------|------|
| 目标职位 | 是 | 通过 `getMyJobList` 选择；必要时用 `getJobDetail` 查看职位描述与职责要求 |
| 推荐数量 / 匹配度阈值 | 否 | 用户未指定时，由 AI 自行决定合理的候选集规模，默认优先展示匹配度最高的若干候选人 |

## 执行步骤

### 步骤 1 — 确认目标职位

**若用户已直接提供 `jobId`（32 位 UUID 或明确为职位 ID）：**

直接使用该 `jobId` 进入后续步骤。

**若用户未提供具体 `jobId`，仅提供职位关键词：**

调用：

```bash
xrxs-cli recruitment getMyJobList --hire-status 0 --keyword <职位关键词>
```

- 使用用户提供的职位关键词搜索用户负责的进行中职位。
- 返回中的 `data.data.jobId` 与 `data.data.name` 等字段用于识别目标职位。

**搜索结果处理：**

- 若只返回 1 条职位记录，直接使用该职位的 `jobId`。
- 若返回多条职位记录，向用户列出候选职位（展示 `jobId`、`name`、`department` 等可用字段），请用户确认具体使用哪一个职位的 `jobId`。
- 若返回为空，提示用户当前没有匹配的进行中职位。

确认职位后，调用：

```bash
xrxs-cli recruitment getJobDetail --job-id <job-id>
```

- 读取职位详情中的职位描述（职责与要求），作为后续匹配评估的依据。
- 以实际返回字段名为准，若职位描述字段名不同，以返回为准。

### 步骤 2 — 获取简历筛选字段

```bash
xrxs-cli recruitment getResumeFilterFields
```

- 目的：确认 `applyJobIds` 等字段的完整结构与 `field` 值，用于构造 `getResumeList` 的 `filters`。
- **以返回为准，不猜字段名**。
- 该接口一次返回全部筛选字段定义，禁止用不同 `--keyword` 反复轮询。

### 步骤 3 — 按职位分页获取简历列表

```bash
xrxs-cli recruitment getResumeList --request-body json
```

请求体示例：

```json
{
  "source": 0,
  "pageNum": 1,
  "pageSize": 100,
  "filters": [
    {
      "type": 2,
      "field": "applyJobIds",
      "values": ["<目标职位ID>"]
    }
  ]
}
```

- `source` 固定为 `0`（全局搜索）。
- `pageSize` 固定为 `100`。
- `filters` 中的 `field` 必须引用步骤 2 返回的字段定义。
- 分页拉取：`pageNum` 从 `1` 开始递增，当某页返回条数 < `100` 或为空时停止。
- **本场景最多拉取 3 页**，即最多评估 `300` 条简历；达到 3 页后停止，不再继续拉取。

### 步骤 4 — 列表级粗略匹配评估

基于 `getResumeList` 返回的列表字段，结合步骤 1 获取的职位描述，由 AI 进行初步匹配评估：

| 字段 | 含义 |
|------|------|
| `school` | 毕业院校 |
| `major` | 专业 |
| `lastCompany` | 最近公司 |
| `lastJob` | 最近岗位 |
| `workAge` | 工作年限 |
| `degreeDesc` | 学历描述 |
| `workCity` | 工作城市 |

**评估目的：**

- 从大量简历中快速筛选出与职位要求相关性较高的候选集，**避免对海量简历逐一查询详情**。
- 评估方式由 AI 基于职位描述与候选人信息进行语义/关键词匹配，不强制固定算法。
- 输出一个精简的候选集（例如 10~20 条），进入步骤 5 的详情级精准匹配。

### 步骤 5 — 获取候选简历详情并精准匹配

对步骤 4 得到的候选集，逐个调用：

```bash
xrxs-cli recruitment getResumeDetail --resume-id <resume-id>
```

- 基于详情中的完整工作经历、教育经历、项目经历、自定义字段等信息，做更精准的匹配分析。
- 结合职位描述中的职责、技能、经验年限等要求，给出更准确的匹配结论。
- 若某个 `getResumeDetail` 返回关键字段缺失，以实际返回为准，不编造。

### 步骤 6 — 组织输出推荐清单

- 本场景**只展示推荐结果**，不调用 `recommendResume`。
- 输出内容基于 `getResumeList` 与 `getResumeDetail` 的实际返回，禁止编造字段。
- 建议输出结构：
  - 候选人姓名
  - 匹配度 / 匹配理由
  - 关键经历摘要（最近公司、最近岗位、工作年限、学历、专业等）
  - 简历 ID（`resumeId`），便于用户后续操作
- 若用户希望真正发起推荐，回退到 [场景二：推荐简历给用人部门](sop-scene2.md) 按步骤执行。

## 异常分支

| 异常情况 | 处理方式 |
|----------|----------|
| `getMyJobList` 返回为空 | 提示用户当前没有负责的进行中职位，无法推荐 |
| `getResumeList` 返回为空 | 确认 `applyJobIds` 与职位 ID 无误后，如实报告该职位下无匹配简历 |
| 某页返回条数 < `pageSize` 或为空 | 按分页停止条件停止，不再继续查询 |
| 关键字段缺失 | 以实际返回字段为准，缺失字段不展示、不推导、不编造 |
| 用户希望直接执行 `recommendResume` | 本场景只负责展示；回退到 `SKILL.md` 或 `recruitment-candidate.md` 的推荐流程 |
