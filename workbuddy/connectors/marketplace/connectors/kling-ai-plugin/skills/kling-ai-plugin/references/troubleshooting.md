# 故障排查

## 安装后缺少 MCP 工具

重新加载 WorkBuddy，并确认 `kling-ai-plugin` MCP 服务器已启用。如果工具仍未出现，重启宿主并查看其 MCP 诊断信息。不要把索取 API key 作为替代方案。

## 未授权或未连接

打开 WorkBuddy 的连接器连接入口，选择 `kling-ai-plugin`，并完成浏览器 OAuth 流程。WorkBuddy 可能会在连接器详情页或 MCP 设置中显示该连接。如果 OAuth 返回 `invalid_target`，不要臆造 `oauth_resource` 覆盖值；应报告宿主诊断信息，并验证当前 Kling 受保护资源元数据。

## 图像输入或图生视频失败

- 刷新实时模式定义，确认所选模型是否接受宿主当前提供的图片引用。
- 宿主无法提供模型接受的图片引用时，说明当前限制，不要用本地路径或任意外链绕过。
- 如果模式定义返回或要求 `taskTraceId`，应在素材准备和生成过程中保持相同的值。
- 只使用所选实时工具声明的输入名称、值类型和参考素材角色；不要把 `image`、`image_1` 和 `first_image` 当作同义字段。
- 若错误提到分辨率，分别核对参数名和值：图像通常使用 `img_resolution=1k/2k/4k`，视频通常使用 `resolution=720p/1080p/4k`，但最终只采用所选模型的实时 allowed values。
- 切换模型后废弃旧请求并重新构造；不要只替换 `model` 后复用旧 arguments 或 inputs。

## 任务仍在运行

在最初的生成轮次中，按 Kling 允许的间隔继续使用实时状态工具轮询，直到任务成功或失败。如果用户取消或当前轮次超时，返回任务编号；任务仍会在 Kling 侧运行。用户之后明确查询状态时，只查询一次。

## 生成失败

返回提供方的失败消息，并保留各项 ID 以供支持使用。不要自动创建替代任务，因为这可能再次消耗积分。

## 积分不足

对于 `PointNotEnough`，告知用户余额不足并停止。只有用户明确表示已充值或余额已变化，才把后续请求视为新的可提交意图；重复发送同一生成要求不构成余额变化。

## 限流

对于 `RateLimitExceeded`，返回提供方消息并停止。不要等待后自动重试、切换模型规避，或通过修改参数创建新任务。若此前已出现积分不足，仍须先满足余额变化条件。

## 提交超时且无法确定是否已创建任务

不要重试生成调用。当前 `query_tasks` 必须提供 `generationId`；只有已取得该编号时才能查询，并可附带同一 `taskTraceId`。`taskTraceId` 不能单独查找任务，当前工具面也没有任务列表筛选能力。没有 `generationId` 或查询无法证明任务状态时，告知用户提交状态未知并停止；只有用户明确授权承担可能重复扣费的风险后，才把后续生成视为新的收费步骤。

## 资源不存在或结果链接已过期

Kling 结果 URL 有效期为 24 小时。历史 Kling 结果本应在新提交前使用已保存的 `generationId` 调用一次 `query_tasks`，再按绑定的 `works[]` 序号和 `contentType` 选择本轮返回的当前 URL。若仍出现 `ResourceNotFound`，说明缺少任务编号、作品映射丢失、刷新失败、目标作品不可用或目标模型不接受该来源；此时请用户重新附图并停止。不要第二次查询同一任务，不要尝试同一作品的其他 URL 字段，也不要把请求降级为文生模式。URL 过期不代表作品一定丢失；用户也可以在 Kling 官网生成历史中找到作品后重新提供。不要记录签名 URL，也不要把它当作永久资产标识。
