# PROPDB 数据合同与输出

## 统一状态判断

所有当前工具使用相同 REST 包装：`statusCode`、`data`、`succeeded`、`errors`、`extras`、`timestamp`。

按以下顺序判断：

1. `succeeded=false`：失败。
2. 明确非成功状态，或存在非空业务错误：失败。
3. 成功且返回预期 `data`：按业务数据处理。
4. 成功但 `data=null` 或数组为空：调用完成但没有数据。

不要向普通业务用户输出包装字段、原始 `errors` 对象、`extras`、时间戳或原始 JSON。只给不会泄露内部实现的错误摘要。

## 组分身份

当前响应可能包含：

| 字段 | 业务含义 | 输出规则 |
| --- | --- | --- |
| `pCdataCompID` | 组分 ID | 消歧、复用查询或用户要求时展示 |
| `compName` / `compNameCN` | 英文/中文名称 | 默认展示实际存在的值 |
| `compNameAliasList` | 别名字符串 | 用户需要身份核对时展示；分隔格式未确认，不自行解析 |
| `iupacName` | IUPAC 名称 | 消歧或用户要求时展示 |
| `formula` / `casNo` | 分子式 / CAS | 默认用于身份核对 |
| `mw` | 分子量 | 只采用单个/批量详情响应；有值时保留接口口径，schema 未给单位时不自行补单位 |
| `smiles` / `inChiID` / `inChiKey` / `pubChemID` | 结构与外部标识 | 仅在用户需要且已授权返回时展示 |
| `canCalcPureProperty` | 是否可进行纯组分物性计算 | 只采用详情响应；不等于当前 MCP 已开放计算工具 |
| `image2D` / `image3D` / `has3D` | 媒体信息 | 用户明确需要且地址已鉴权时使用；明文 HTTP 或基础设施地址默认不外显，不转发到第三方 |
| `pCdataCompNo` / `openID` | 语义未确认的编号 | 默认隐藏 |

搜索接口是候选摘要。实测同一对象在搜索中 `mw=null`、`canCalcPureProperty=false`，在详情中却返回实际分子量和 `true`。搜索中的这两个字段按“未加载/非权威”处理。`mw=null` 不表示分子量为零；schema 没有声明分子量单位，不按领域常识补写 `g/mol`。

## 纯组分标量物性

| 字段 | 业务含义 | 输出规则 |
| --- | --- | --- |
| `property` / `property_Zh` / `propAbbreviation` | 物性名称 | 选择最适合用户语言的名称，必要时附简称 |
| `value` | 标量物性值 | 必须与实际单位一起展示；`null` 为暂无值 |
| `units` / `unitSymbol` | 单位文本/符号 | 优先使用明确、非空的返回单位；冲突时保留原值并说明待核对 |
| `source` | 数据来源 | 用户要求溯源或结论依赖时展示 |
| `error` | schema 描述为误差 | 原样作为“误差/不确定性”展示，不猜测格式、单位或置信水平 |
| `data_Type` | 数据类型 | 有业务意义且用户需要时展示；不自行映射未知枚举 |
| `noteContent` / `noteContentEN` | 注释正文 | 与结果解释相关时展示，跟随用户语言 |
| `hasDetails` | 是否有详情标记 | 只报告标记；没有详情工具时不承诺下钻 |
| `unitRow` / `unitCol` / `note` | 内部枚举/注释 ID | 默认隐藏 |

同一物性返回多条时保留每条记录的单位、来源和数据类型，不擅自平均、去重或挑选“最佳值”。若用户需要选择标准，要求其说明来源、数据类型或条件偏好。

### 数值哨兵

产品方确认部分无值物性可能返回 `1E+35`。对物性数值字段执行以下确定性规则：

1. 将解析后数值等于 `1e35` 的值标记为缺失；科学计数法大小写或表示形式不影响判定。
2. 用户侧显示“暂无数据”或省略该项，不显示 `1E+35`。
3. 不换算、不排序、不参与最小值、最大值、平均值或其他比较。
4. 只处理物性数值字段；不得对 ID、文献数、数据计数、时间戳或普通大数使用该规则。

未来新增实验点或模型输出字段时，只有接口契约明确沿用同一哨兵才扩展该规则。服务端应优先返回 `null` 和缺失原因。

## 混合物数据可用性

当前每条记录可能包含：

- `pCdataCompID`、`pCdataCompID1`：组分对 ID；
- `pCdataComp1`、`pCdataComp2`：组分名称；
- `property`、`property_Zh`：物性名称；
- `citationCnt`：文献数量；
- `dataSetsCnt`：schema 描述为数据点数量，但字段名像数据集数量。

在后端澄清前，把 `dataSetsCnt` 中性表述为“数据计数”，不要改写为实验点数或数据集数。计数为 `null` 时显示“暂无计数”，不能补零。

服务端可能规范化组分对顺序。通过 `pCdataCompID` 和 `pCdataCompID1` 关联对象，不把数组位置或输入顺序当身份依据。

此响应只能支持“是否列出某物性、返回了多少文献/数据计数”的结论。它不包含实验数值、温压范围、组成、关联式、参数或完整文献。

## 用户可见结构

### 单个组分

1. 命中身份；
2. 用户要求的物性值、单位、来源/误差；
3. 只列会影响理解的缺失或限制。

### 多个组分

使用紧凑表格，按用户输入顺序展示。结果数组顺序不同或缺项时，通过组分 ID 对齐；未返回对象单独列出，不猜测原因。

### 混合物可用性

先说明查询的组分对，再列物性、文献数和数据计数。结尾明确这是一份可用性摘要，而不是实验数据详情。

## 单位与换算

默认保留原单位。只有用户明确要求、维度和基准完全明确时才换算，并同时给出数据库原值和“Agent 换算值”。不得在以下情况换算：

- schema 未给单位，例如 `mw`；
- 摩尔/质量基准不明；
- 标准态、参考态、相态或温压条件不明；
- 单位字段互相冲突。

## 禁止外显

- 鉴权参数、连接 URL、token、服务器路径；
- REST 包装、工具追踪、原始请求/响应；
- `openID`、`unitRow`、`unitCol`、`note` 等默认隐藏字段；
- 错误堆栈、SQL、内部类型名和调试信息；
- 当前工具没有返回的实验点、模型参数、温压有效范围、计算值和来源。
