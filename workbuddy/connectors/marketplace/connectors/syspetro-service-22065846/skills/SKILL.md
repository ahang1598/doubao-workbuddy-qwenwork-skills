# 查询 PROPDB 物性数据库

## 开始前

只使用运行时实际挂载的 PROPDB MCP （syspetro-service-22065846）工具。以实时 tool schema 为工具名、参数、类型和返回结构的最终依据；当前接口仅支持查询，不要从旧 Skill、数据库总体建设范围或领域常识推断已经开放计算、拟合、导出或详情能力。

按任务读取：

- 首次规划调用时读取 [references/tool-routing.md](references/tool-routing.md)，核对 5 个规范工具名、对象解析和最小调用链。
- 解释字段、空值、错误、来源、计数或组织用户输出时读取 [references/data-contract-and-output.md](references/data-contract-and-output.md)。

运行时工具可能带 MCP 命名空间或生成哈希。4 个稳定工具按规范名称后缀识别；关键词检索工具在 `propdb` 命名空间内按“根据关键词查询混合物组分”的描述和唯一 `keyword` 输入识别，不能只硬编码某个哈希。零个或多个工具同时匹配时停止并报告配置冲突。保留 `propeties` 和 `keywork` 等源 schema 原始拼写，不擅自更名。

## 核心流程

1. 识别目标是能力介绍、组分检索、单个详情、批量详情、纯组分标量物性，还是二元物性数据可用性。
2. 优先使用用户明确提供的 `PCdataCompID`。否则按名称、别名、分子式或 CAS 检索每个不同组分词。
3. 只有搜索结果唯一，或存在一个可核对的唯一精确匹配时才自动选择。多个合理候选时展示用于消歧的名称、公式、CAS、IUPAC 和组分 ID，等待用户选择；不要默认取第一条。
4. 取得唯一 ID 后再调用目标查询。搜索响应只作为身份候选：不要使用其中的 `mw` 或 `canCalcPureProperty` 作最终结论；用户需要分子量、可计算标记或身份详情时调用单个/批量详情。只补充完成目标所需的数据，不为普通消歧默认调用详情，也不重复查询相同对象。
5. 检查响应状态和实际 `data`，按业务字段白名单构造结果。先给命中状态或结论，再给值、单位、来源和必要限制。

虽然当前输入 schema 的 `required` 为空，业务调用仍必须提供非空 `keyword`、有效 `Id` 或非空 `ids`。不得因此发送空参、猜测字段或猜测 ID。

## 选择路由

| 用户目标 | 行为 |
| --- | --- |
| 询问当前 MCP 能做什么 | 不调用业务数据工具；说明当前只读能力和未开放能力 |
| 按名称、别名、分子式或 CAS 找组分 | 检索候选并消歧 |
| 查看一个已知组分 | 单 ID 详情 |
| 对照多个已知组分的身份或分子量 | 一次批量详情；按 ID 关联结果，不假设返回顺序 |
| 查询某纯组分的沸点、分子量、临界性质、焓等基础物性 | 解析 ID 后查询标量物性列表，只整理实际命中的物性 |
| 查询两个组分之间有哪些混合物物性数据 | 解析明确组分对后查询物性名称与文献/数据计数 |
| 要求温压实验点、温压关联式、模型参数或物性详情 | 说明当前工具不能取得这些详情；不得从标量值、`hasDetails` 或常识补造 |
| 要求按性质范围筛选全库、计算、闪蒸、拟合、保存或导出 | 说明当前 MCP 未开放，不调用相近工具冒充 |

当前混合物输出模型是成对组分摘要。只为用户明确的组分对执行查询；对三个及以上组分，不假定接口具有多元混合物语义，先要求用户指定要查询的组分对。

## 控制查询范围

只查询用户明确指定的有限对象。拒绝空或宽泛关键词、顺序遍历 ID、猜测 ID、全库导出、拆批、变换查询或跨请求拼接数据库内容。当前没有已确认的数值型批量上限，不要自行编造；当范围明显不是为回答具体业务问题所需时，要求用户缩小到明确组分。

不要通过互联网、代码估算或其他数据源填补 PROPDB 空值。用户另行明确要求公开来源时，把外部数据与 PROPDB 结果分开标注，不得称为数据库返回。

## 解释物性结果

- 纯组分物性工具当前返回标量 `value` 和单位等元数据；它不能证明已经取得温度/压力序列或模型参数。
- 混合物工具当前返回物性名称、文献计数和数据计数；计数只表示数据可用性摘要，不是实验值、模型参数或完整文献列表。
- 保留接口单位和口径。用户要求换算时同时保留原值，并把换算结果明确标为 Agent 计算；维度、基准或条件不明确时不换算。
- `null`、缺失字段和空数组表示当前响应没有提供该数据，不填成 `0`，不凭常识估计。
- 物性数值字段等于 `1E+35` 或数值等价形式时同样按缺失处理：不展示为数值、不换算、不排序、不参与比较。不要把这条规则用于 ID、文献/数据计数、时间戳或任意其他大数。
- `hasDetails=true` 只说明返回记录带有详情标记；当前没有对应详情工具时，不承诺能够下钻。

## 保护数据与内部实现

默认不展示 REST 包装、工具追踪、鉴权信息、原始 JSON、错误堆栈、内部单位枚举、注释 ID、`openID` 或服务器实现字段。`PCdataCompID` 可在需要消歧或复用查询时作为“组分 ID”展示。

SMILES、InChI、PubChem ID、别名、媒体地址等身份字段只在用户目标需要且接口实际授权返回时展示。不要把数据库返回的结构标识或媒体发送给第三方搜索、绘图、转换或托管服务。

当前工具均为查询语义，没有保存或外部写入能力。不得声称创建了记录、保存了结果或生成了数据库原生报告。

## 处理失败和部分数据

- 明确失败：给出失败阶段和安全的业务错误摘要，不输出包装对象或堆栈，不伪造结果。
- 成功但 `data=null` 或列表为空：说明当前条件下未返回数据，不称为值为零。
- 批量结果缺少部分输入 ID：列出已返回对象和未返回 ID；在契约未明确前不猜测是不存在还是无权限。
- 搜索无匹配：建议用户改用更准确的名称、公式、CAS 或组分 ID，不自动改查外部数据源。
- 限流或超时：停止自动扩展和并行重试；说明实际状态并让用户稍后重试或缩小范围。
