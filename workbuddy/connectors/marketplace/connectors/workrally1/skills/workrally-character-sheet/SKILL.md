# WorkRally 角色设定表

把角色简介变成一条**槽位填满、内部自洽**的设定表提示词，需要时再生成。两种模式：

- **模式 A —— 只出提示词（默认）**：输出一条可直接复制的成品提示词。
- **模式 B —— 生成**：用户说「生成 / 出图 / 跑一下 / 画出来」时，先组装提示词，**再**调 `canvas_generate_image`。

核心价值是下面的**槽位架构**加上那套**杀掉 AI 磨皮感的写实引擎**。
永远不要即兴写设定表提示词——按顺序把槽位填满。

## 运行约定

先读 `references/workrally-mcp-mapping.md`，本文不重复工具与参数细节。要点：

- 只有模式 B 才调工具；模式 A 一个工具都不调
- 生成前必须调 `canvas_image_model_list` 取模型，**禁止硬编码 model_id**
- 每个变体一次 `canvas_generate_image`，`count: 1`；不要用 `count:N` 凑变体
- 提交后按 `task_ids` 逐个 `canvas_get_task` 轮询，间隔 3 秒
- 参考图放 `input_images`（URL 数组），提示词里用「第一张图片」按下标引用
- 本地图片先 `upload_file` 拿 URL；不要把本地路径塞进 `input_images`
- 提示词用中文；服装上的品牌字样等图内文字保留用户原文
- 不需要调展示工具，生图卡会自动渲染

追问最多一到两个，只问真正卡住组装的（通常是：风格预设、要不要直接生成）。

## 不可让步的四条原则

这四条压过任何简介，除非用户明确改掉，否则对每个预设都生效。

1. **写实 = 反修图，绝不是理想化。**「真实」永远不等于无瑕、磨皮、美颜。真实意味着看得见毛孔、
   自然的不对称、无反光的哑光皮肤、上得略不均匀的妆、以及零 AI 平滑痕迹。
   选了写实类预设，反 AI 写实模块就是**必填**，不是可选项。
2. **版权意识——只做原创角色。**绝不复刻可辨认的真人相貌或受版权保护的角色/IP。
   参考图只用于**风格与气质**启发，不是照搬。永远描述一个**原创**角色；
   用户点名了明星或现有 IP 时，只当作松散的调性参考，另建一张独立的原创脸。
   措辞里始终保留「所有视图是同一个**原创**角色」。
3. **成年角色要成年人的骨相。**角色设定为成年人时，主动避开娃娃脸和幼态圆润比例。
   明确写出成人结构：清晰（而非软圆）的下颌与颧骨、更长的面部三庭、成熟骨相、成人比例。
   这是反复出问题的点——**宁可偏成熟，不要偏可爱**。
4. **一致性会往下传递。**在已有角色上迭代时，**此前确立的每一个细节（脸、发、体型、服装、
   配饰、首饰）一律原样带下去**，除非用户明确要改。只改被点名的那一处，其余全部重述一遍，
   免得悄悄漂移。

## 流程

1. **读简介。**抽出角色身份、服装、想要的风格。只问那 1–2 个真正卡住组装的问题。
   用户贴了参考角色描述就逐字保留每个体貌细节。**在已有角色上迭代时按原则 4 全量带入。**
2. **选风格预设**（见「风格预设」）→ 决定写实/渲染模块与质量收尾。
3. **选构图预设**（见「构图预设」）→ 决定开头那一句。
4. **按顺序填槽位**（见「槽位架构」）。每个定义角色的细节都要**具体**（材质、颜色、剪裁、质感），
   绝不能是「好看的上衣」「漂亮的脸」这种。
5. **接上负向收尾**（见「负向收尾」）。
6. **输出**这一整条提示词。模式 B 则继续生成。

**铁律**

- **一致性就是产品本身。**始终声明所有视图是**同一个原创角色**。体貌描述**只写一次**，隐式作用于全部视图。
- **一整段、逗号分隔、有序。**图像模型对靠前的词权重更高——构图和身份放最前，质量收尾放最后。
- **具体压过形容词。**「奶白色阔腿九分裤，镂空花卉刺绣，抽绳腰头」远胜「好看的裤子」。
- **服装从头到脚。**上衣 → 外层 → 下装 → 腰带/腰封 → 鞋 → 首饰 → 包。不留空档。
- **统一布光 + 无缝背景**才让它读起来像一张**设定表**，而不是一张照片。

## 槽位架构

严格按此顺序填。方括号是变量槽，方括号外是可复用的骨架文本。

```
[构图开场句]，所有视图都是同一个原创[主体]，
纯白色无缝影棚背景，专业角色设定表呈现，
[身份：年龄 + 族裔/肤色]，
[脸：脸型、下颌线、颧骨、鼻、唇]，
[眼睛 + 抗眩光子句]，
[眉毛]，[头发：颜色、色调、长度、造型、质感、分缝]，[发饰（若有）]，
[写实模块 —— 取自所选预设]，
[身体：体型 + 比例]，
[服装：上衣 → 外层 → 下装 → 腰带/腰封 → 鞋 → 首饰 → 包]，
[布光模块 —— 取自所选预设]，
[质量收尾 —— 取自所选预设]，
[负向收尾]
```

### 槽位说明

- **身份**：年龄段（「二十出头的年轻女性」）、肤色、必要时的族裔背景。表述得体而具体。
  只做原创角色，绝不是某个真人的相貌（原则 2）。
- **脸**：鹅蛋/圆/心形/方；下颌（柔和/硬朗/纤细）；颧骨；鼻子；嘴唇（形状 + 质感，
  如「饱满双唇，自然玫瑰裸色，柔哑光到微缎面的质感」）。
  **成年角色必须写成熟骨相**（原则 3）：清晰的下颌线与颧骨、成熟的成人骨相与面部比例，
  明确写出**不是**幼态圆润的娃娃脸。
- **眼睛**：形状 + 眼型走势 + 颜色，然后写实类预设**必须**接上抗眩光子句：
  「眼神光自然收敛，虹膜里没有过大的高光斑，眼睛颜色是沉稳的实色而不是发光的」。
- **头发**：颜色 + 底调 + 长度 + 造型 + **质感**（「蓬松大波浪，大号圆梳吹出的收尾」）+ 分缝。
  质感是卖出真实感的关键。
- **服装**：每件都要写清材质、剪裁、颜色，外加一个细节。首饰要小而具体
  （「细金手链，几枚精致小金戒」）。没有包就明确写「不带包」。

## 风格预设

每套预设提供三个模块：**写实/渲染**、**布光**、**质量收尾**。默认是 `photoreal-unretouched`，这是招牌质感。

### 1. `photoreal-unretouched`（默认 / 招牌）

> **写实模块（反 AI 引擎——整套手艺就在这里）：**
> `可见的细腻皮肤纹理与自然毛孔，细纹、轻微不对称与质感上的不规则，能看出是真化的妆——粉底衔接略不均匀而不是无瑕覆盖，淡淡的自然腮红，是轻微的自然光泽而不是修图过的油光或水光，没有数码平滑，没有美颜滤镜，没有 AI 磨皮感，皮肤上完全没有人工眩光、油光或高光爆块，哑光到自然的肤质`
> ——可选的瑕疵锚点：`几颗淡淡的雀斑，锁骨附近一颗小痣`。
>
> **布光：**`柔和的漫射影棚光，没有硬反光`。
> **质量收尾：**`自然的解剖结构，高级但未经修图的商业摄影质感，电影感写实，干净白背景，4K 画质，对焦锐利落在皮肤纹理细节上`。

### 2. `editorial-polished`（时尚大片）

同样的写实底子，但允许精致的高级妆感：`无瑕但自然的皮肤，保留细腻纹理，颧骨上柔和的水光提亮，
时尚大片式的美妆布光，柔和主光配温和补光`。
质量收尾：`高级时装大片摄影，杂志封面级画质，电影感写实，4K`。

### 3. `anime-2d`（二次元）

> **渲染模块：**`干净的动画插画，锐利线稿，赛璐璐平涂配柔和渐变阴影，富有表现力的大眼睛与细致的虹膜高光，统一的角色设定表画风`。
> **布光：**`均匀平光，柔和环境阴影`。
> **质量收尾：**`高品质动画主视觉，干净的矢量感线条，锐利，4K`。（去掉皮肤纹理/毛孔那些子句，不适用。）

### 4. `3d-stylized`（三维风格化，皮克斯 / 梦工厂感）

> **渲染模块：**`风格化三维角色渲染，讨喜的夸张比例，带次表面散射的光滑皮肤，柔和圆润的五官，细致的发丝与布料解算`。
> **布光：**`柔和全局光照，三点影棚布光，温和轮廓光`。
> **质量收尾：**`顶级三维动画工作室水准，Octane/Unreal 级渲染，干净中性背景，4K`。

### 5. `game-concept`（游戏概念）

> **渲染模块：**`绘画感的游戏概念美术，半写实渲染，正交模型设定表，剪影清晰，材质信息通过细节暗示`。
> **布光：**`中性均匀的概念美术布光`。
> **质量收尾：**`专业角色概念设计，ArtStation 水准，锐利，4K`。

> 用户的风格对不上任何预设时，按同样的形状（渲染 + 布光 + 质量收尾）自建一套模块，
> 构图与一致性骨架保持不动。

## 构图预设

选一句开场。默认是 **split-screen**。

- **split-screen（默认）**：`分屏式角色设定表构图，左侧是角色的全身照——中性直立站姿，正面朝向镜头，
  双脚平踏地面，双臂自然垂放，从头到脚完整入镜，全身与双脚都可见；右侧是同一角色的胸部以上紧凑特写肖像，`
  - 右侧的变体：`面部特写肖像`、`胸部以上肖像`、`美妆特写`。
  - **硬性取景规则（每次逐字重复——这是最常崩的地方）：**
    - **永远站着。**左格角色是**站立**的——不能坐、不能蹲、不能倚靠、不能被裁切。写死：
      `站立全身，从头到脚，整个身体与双脚都在画面内，没有被裁切，不是坐姿`。
    - **右格永远是特写。**右格是紧凑裁切（面部或胸部以上），绝不是第二个全身。
    - **画面里只有这一个角色。**每次都往负向收尾里加：`画面中只有一个主体，恰好一个人，
      只有该角色在画面内，没有其他人，没有重复人影，没有人台模特，没有倒影，没有道具，
      没有家具，没有背景杂物，空旷的无缝影棚`。
- **turnaround / 转身表**：`角色转身设定表，一排四个一致的全身视图——正面视图、四分之三视图、侧面视图、背面视图，间距均匀，`
- **expression / 表情表**：`角色表情表，左侧一个全身参考，右侧一组头肩肖像网格，展示不同表情（中性、微笑、严肃、惊讶），`
- **outfit variations / 服装变体**：`角色服装设定表，同一角色以全身形式并排展示 [N] 套不同服装，`
- **triple panel / 三格**：`三格角色设定表——全身、胸部以上肖像、面部与配饰的细节特写，`

比例按构图匹配（见「生成」）。

## 负向收尾

始终以这一句结尾（按情况调整其中的可变项）：

```
没有文字，没有水印，没有 logo，没有画框边框
```

按需追加：`不带包，没有品牌标识，没有多余角色，没有背景道具，没有硬阴影，没有畸形的解剖结构，没有多余手指`。

**分屏设定表每次必加**（专治那个反复出现的崩法）：`画面中只有一个主体，恰好一个人，
只有该角色在画面内，没有其他人，没有重复人影，没有人台模特，没有倒影，没有道具，没有家具，
没有背景杂物，空旷的无缝影棚，左格是站立全身从头到脚未被裁切且不是坐姿，右格是紧凑特写而不是全身`。

成年角色追加：`没有娃娃脸，没有过分幼态的圆润比例`。
写实类追加：`没有美颜滤镜，没有数码平滑，没有磨皮，没有塑料皮肤，没有油光皮肤`。
版权安全每次都要（作为你自己的约束，不必写进提示词）：角色是原创的，不得像任何真实名人或现有版权角色。

## 生成（模式 B）

只有用户明确要求生成/出图时才做。提示词照模式 A 原样组装，然后调 `canvas_generate_image`。

首次提交前调一次 `canvas_image_model_list`。选型口径：

| 需求 | 挑选依据 |
|---|---|
| 写实类预设（1 / 2） | `resolution_options` 含 4K（枚举 6）或至少 2K（枚举 5）的主力档 |
| 二次元 / 三维 / 概念（3 / 4 / 5） | 从 `models[].name` / `desc` 里挑风格对得上的一档；对不上就用主力档，靠提示词压风格 |
| 在已有角色上迭代 | `kontext_config.max_input_images ≥ 1` |

**同一个角色的整组图不要中途换模型。**

**比例按构图取**：

| 构图 | 比例 |
|---|---|
| split-screen / turnaround / expression / triple panel | `16:9`（次选 `4:3`） |
| outfit variations（N ≥ 4） | `21:9` |
| 单张肖像 | `3:4` |

WorkRally **没有** `3:2` 和 `2:3`——横版编辑用 `4:3`，竖版肖像用 `3:4`。
需要精确原始比例时生成后本地 ffmpeg 裁切，并告知用户做过裁切。

提交形如：

```jsonc
canvas_generate_image({
  prompt: "<按槽位架构组装的整条中文提示词，含负向收尾>",
  model: "<canvas_image_model_list 返回的 model_id>",
  aspect_ratio: "16:9",
  resolution: 6,          // 4K；模型不支持时退到它 resolution_options 的最高档
  count: 1,
  input_images: ["<迭代已有角色时放上一版的结果 URL；从零开始则省略该字段>"],
  task_name: "<角色名_构图_变体N>"
})
```

- 负向收尾**写在提示词里**。WorkRally 的 `canvas_generate_image` 没有独立的负向提示词字段，
  不要臆造 `negative_prompt` 这类参数。
- 多个变体就多次调用，每次 `count: 1`，各自一条独立提示词。
- 用返回的 `task_ids` 轮询，间隔 3 秒；`state=4` 时读 `output_assets`。
  已完成的变体**冻结**，不要重复提交；轮询超时不等于生成失败。

生成后展示结果，并主动提供一轮定点修正（如「收紧服装描述」「加强皮肤纹理」「右格换成面部特写」）。

**没有明确要求就不要生成——默认是模式 A，只出文字。**

## 在已有角色上迭代（保一致性）

用户要在已出的角色上改东西时：

- 把**上一版通过的那张的结果 URL** 作为唯一 `input_images`，提示词里用「第一张图片」引用
- 整条提示词**重新完整写一遍**所有槽位（原则 4），只替换被点名要改的那一处
- 明确写出「改什么」和「必须保持不变的是什么」，例如：
  `第一张图片里的角色，保持完全相同的脸、骨相、发色发型、体型与配饰，只把上衣换成 <描述>。`
- 换成一个不相关的新角色时另起一组，不要借用上一个角色的参考图

每个角色最多两轮定点修正。用户笼统说不满意又说不清哪里不对时，问一句要改什么，
不要自己编一个缺陷出来。

## 交付

给出最终图，用一句话说明构图预设、风格预设、比例和做过的修正。
宿主看不到像素时，**如实说明未做视觉检查**，不要声称质量已通过。
提示用户「图片由 AI 生成」。不要暴露模型名、task_id 与内部流程机制。

> 分屏式角色设定表构图，左侧是角色的全身照——中性直立站姿，正面朝向镜头，双脚平踏地面，
> 双臂自然垂放，从头到脚完整入镜，全身与双脚都可见；右侧是同一角色的胸部以上紧凑特写肖像，
> 两侧是同一个原创女性角色，画面中只有一个主体、恰好一个人、只有该角色在画面内，
> 纯白色无缝影棚背景，专业角色设定表呈现，[年龄]，[肤色]，[脸型] 配 [下颌]，[颧骨]，[鼻子]，
> [唇形 + 质感]，[眼睛颜色/形状]，眼神光自然收敛，虹膜里没有过大的高光斑，[眉毛]，
