# 营销通 · 搞懂用户专家团 v1.1.2

> 上架申请版 · 2026-08-28 · 由「搞懂用户专家团」更名而来（id 不变：`find-users-team`，可与已装版本平滑升级）

## 定位

面向 vibe coding 出产品、想 go to market 的人群：**把真实用户的话变成洞察、人群、话题与内容 Brief**。是营销通工作流的中游段——上游思研（AI 调研），下游内容专家团（成稿）与金手指四件套（投放）。

**主理人通哥是营销通全流程主控入口**：用户从任意阶段进入（验证需求 / 搞懂用户 / 内容触达 / 投广告），由通哥分诊到对应能力，并以增长项目档案（growth-project.md）承载跨会话上下文。

## 成员（5 agents）

| 花名 | 职业 | 管什么 |
|---|---|---|
| **通哥**（lead） | 营销通·营销策略专家 | 阶段判断分诊 · 广告进入判断 · 结果判定六步 · 增长项目档案 |
| **郑识人** | 用户洞察专家 | 从真实语料看清用户：12 项洞察 + 用户原话 + 人群线索 |
| **拓野** | 人群扩展专家 | 从已验证人群向外扩：五维扩展 + 四档分类 + 低成本验证方式 |
| **寻声** | 话题发现专家 | 这群人正在愁什么、怎么搜：八类话题 + 真实搜索词 |
| **策远** | 内容策略专家 | 给谁讲、讲什么、怎么算有效：Brief 11 项（按内容团八维度交付） |

## 技能（7 skills）

| 技能 | 作用 |
|---|---|
| `growth-project` | 增长项目共享上下文（唯一事实来源，含验证目标/结果双字段、旧档案升级规则、原始材料可回溯） |
| `growth-output-standard` | 输出规范：来源标注、已验证/待验证区分、禁用内部术语 |

| `user-insight-toolkit` | 洞察方法：11 问 + 12 项输出 + 语料提交与充分性判断 |
| `audience-expansion-toolkit` | 人群扩展：五维 + 四档 + 验证方式 |
| `topic-discovery-toolkit` | 话题发现：八类话题 + 搜索词 + 不编造数据 |
| `content-brief-toolkit` | 内容 Brief：11 项 + 渠道判断 + 给内容团的八维度交付格式 |

## 安装要点（三处缺一不可）

1. 包目录 → `marketplaces/<市场>/plugins/find-users-team/`
2. 注册条目 → 该市场 `.codebuddy-plugin/marketplace.json` 的 `plugins` 数组
3. `settings.json` 指向 lead（包内已带）

安装后重启客户端。

## 上架后验证用例（两句）

| 说 | 期望 |
|---|---|
| 「我刚做了个 AI 工具，不知道有没有人需要」 | 先问有没有语料，没有则推荐思研（含入口说明），**不硬编用户画像**；首次接待**当场建档** |
| 「我发了几篇，效果一般，这是评论」 | **先读回上轮验证目标**再做三类拆分（原话/数字/主观判断），区分「验证为否」与「没验证到」 |
| 「我之前自己发过几篇验证了一下」 | 自行发布内容**不占 B 号**（不编 B1），记入已发布内容，结果回流并入当前 R |

## 依赖的外部能力（不在本包内）

思研（AI 调研平台，https://aimoderator.cn）· 社媒内容专家团（成稿）· 金手指四件套 苏策/齐亮/艾投/小助手（投放，含 MCP）。对接契约见 `skills/capability-handoff/`。

**均为软依赖——单包可用**：外部专家未安装时按 `capability-handoff` 的降级规则给自助出口（思研与金手指平台本就不依赖专家包；Brief 自写附自查三问），流程不停摆在"去装一下"。
