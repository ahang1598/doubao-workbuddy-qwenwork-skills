# 增长项目

搞懂用户专家团各专家共享的上下文容器。**每个专家开工前先读，收工后回写。**

## 存放位置

```
{workspace}/.workbuddy/memory/growth-project.md
```

⚠️ **绝不写进专家包目录**——那是只读技能包，分享给他人时会带上用户的业务数据。

## 读写规则

**读**：任务开始时先检查文件是否存在。
- 存在 → 读取后**只问缺失字段**，已有的不重复问。
- 不存在 → 首次接待、完成阶段判断后**当场创建**（至少写入产品段与已知情况），之后增量补齐——**不等到收工、不等第一份产物**。零语料的首次来访也要建，进度编号写「研究轮次：未开启（等第一批语料）」。

**写**：每个专家产出后**增量更新自己负责的段落**，其余段落原样保留。
- 不覆盖重写整个文件。
- 每次在 `## 变更记录` 追加一行：`日期 · 谁 · 改了什么`。

**旧档案升级**（读到旧格式文件时）：
- 文件缺当前版本的字段 → 在对应段落末尾**补上空字段**，已有内容一律不动。
- 在 `## 变更记录` 追加：`日期 · schema 升级 · 补齐字段 xxx`。
- **绝不因为缺字段重建整个文件**，也绝不把「字段是空的」当成「用户没做过」。

**原始材料可回溯**：
- 郑识人收到语料后，把原始材料的**位置**记进「语料来源与数量」（本机路径 / 思研链接 / 截图存放处）。不搬运内容、不建存储系统，只记「去哪能找到」。
- 通哥收到带回的评论截图、数据截图时同样处理，位置附在「内容表现」行内。
- 后续任何专家想回看原文，按位置去找；找不到时如实说「原始材料已不可考，以下基于当时的记录」，**不要假装记得原文**。

**告知用户**（首次存档后，用大白话说一次）：
> 你的产品和用户情况我记下来了，后面几步不用重复讲。

## 字段来源对照

| 段落 | 谁负责写 | 上游来源 |
|---|---|---|
| **进度编号** | **主理人统一发号**（专家只读不改） | 上一轮结果回流后推进 |
| 产品 | 主理人接待时采集 | 用户直接输入 |
| **风险记录** | **主理人开工前检查** | **强监管行业前置检查（见 `capability-handoff` 第零节）** |
| 用户 | 用户洞察专家 | 真实语料 / 思研调研结果 |
| 人群 | 人群扩展专家 | 用户洞察 |
| 话题 | 话题发现专家 | 用户洞察 + 人群 |
| 内容（策略 / Brief / **本轮验证目标**） | 内容策略专家 | 话题 + 产品 |
| 内容（**本轮验证结果**） | **主理人**（用户带回后，与下一步建议同次写入） | 三类拆分 + 与验证目标比对 |
| 内容（**本轮触达方式**） | **主理人**（用户选定后记录） | 用户选择 |
| 内容（已生成 / 已发布 / **内容表现** / **下一步打算**） | **主理人**（用户带回后记录） | 用户手动带回 |
| 内容（新增用户反馈） | **用户洞察专家** | 带回的评论与私信 |
| 获客 | 主理人判断 → 苏策 / 齐亮 | 已验证卖点 |
| 数据边界 | 每个专家各自补充 | 全流程 |

> ⚠️ **风险记录是全流程读取项**：寻声定话题方向、策远定内容方向、通哥交接给内容专家团和苏策时，都要先读这一段。

### 编号纪律：研究轮次 R 与内容批次 B

这是两个**不同的计数器**，绝不共用「轮」这一个词，否则同一条链路上会出现「前三份 R1、第四份 R2」这种对不上的编号。

| | 研究轮次 R | 内容批次 B |
|---|---|---|
| 数什么 | 一次完整的证据刷新（洞察 → 人群 → 话题） | 交给内容团的第几批内容 |
| 作用域 | 团内流转的三份产物 | 出团交付的内容 Brief |
| 谁看 | 产品负责人、上级 | 施工方（社媒内容专家团） |
| 为什么要 | 声明结论的**证据有效期**——R1 的 15 人样本和 R3 的 60 人样本，决策权重完全不同 | 让施工方知道这是第几批、跟上一批什么关系 |
| 用词 | 「第 1 轮」 | 「第 2 批」 |

**层级关系**：一个 R 内可以有多个 B（同一批证据下发了 B1、B2 两批内容）。**结果全部回流、主理人判定完，研究轮次才推进到 R+1。**

**发号规则**：
- R 与 B 都由**主理人统一发号**，写进「## 进度编号」段。
- 四位专家产出时**读取**该号写进产物版头，**不自行编号**。
- 出团交付物（内容 Brief）**只带 B 号，不带 R 号**——接收方看不懂内部研究编号，也用不上。
- **B 号只编「我们出的」内容批次**：通哥团产出 Brief、交内容团施工的那一批才占 B{n}。用户自行发布或自称已验证的内容**不占 B 号**——记入「已发布内容 / 内容表现」，结果回流并入当前 R。口诀：**Brief 是我们出的才占号，用户自己发的不占。**

⚠️ 与下文「本轮验证目标 / 本轮验证结果」的关系：那两个字段记的是**单次验证动作**（一次内容投放、一次访谈、一次付费投放），颗粒度比 R 细，通常对应一个 B。字段名里的「本轮」指当前这次验证动作，不是研究轮次 R。

### 「本轮验证目标」怎么写

用大白话写清**想知道什么** + **什么迹象算有反应**。例：

> 想知道「一人 SaaS 团队」是不是也有这个问题；评论里有人说「我也是」并说明自己身份，就算有反应。

⚠️ **不要写成实验设计**——一两句话就够。**这个字段没填，通哥后面只能做描述性分析，无法判断假设成不成立。**

### 「本轮验证结果」怎么写

用户带回结果后，通哥与下一步建议**同次写入**。一行摘要 + 四选一的判断：

> `08-25 · 3 人自我识别为独立开发者，无人来自一人 SaaS 团队 · 判断：支持独立开发者，一人 SaaS 团队无法判断`

四个判断的用法：
- **支持** —— 有明确正向信号
- **不支持** —— 有明确反证（注意：需要真的反证，不是「没动静」）
- **无法判断** —— 没验证到（信号不足、没触及目标人群）
- **出现新发现** —— 反馈里的痛点和原假设不一样（价值可能更高）

⚠️ **「不支持」和「无法判断」必须分开**。前者要换方向，后者该再试一次。

### 「下一步打算」怎么写

通哥每次给出建议后追加一行，注明日期与理由：

> `08-22 · 继续同人群加 2-3 条内容 · 有 3 人自我识别但样本太小`

作用是**下次进来能接着上次讲**，不用重新推演。

## 阶段判断（主理人用）

读完文件后，按**最后一个填好的段落**判断用户当前阶段，直接跳到下一步，不要每次从头跑：

| 已填到 | 当前阶段 | 下一步 |
|---|---|---|
| 无文件 / 只有产品 | 缺语料 | 先问有没有用户资料；没有则推荐思研 |
| 用户段已填 | 已有洞察 | 人群扩展 |
| 人群段已填 | 已有人群 | 话题发现 |
| 话题段已填 | 已有话题 | 内容策略 |
| 内容段有表现数据 | 已有反馈 | **先读回「本轮验证目标」做比对**，再回到用户洞察用新反馈迭代 |
| 获客段达标 | 可放大 | 判断是否进广告测试 |
