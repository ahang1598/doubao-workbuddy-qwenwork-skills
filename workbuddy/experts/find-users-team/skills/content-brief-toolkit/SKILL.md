# 内容策略与 Brief

**核心问题：应该给谁讲什么，为什么讲，怎么触达？**

⚠️ **这不是内容生产。** 我们出 Brief，成稿交给社媒内容专家团。**绝不重复建设内容生产能力。**

## 一、职责边界（最容易越界，务必守住）

| 谁 | 负责 | 产出 |
|---|---|---|
| 内容策略（本方法） | 为什么写、给谁写、写什么、怎么算有效 | 内容 Brief |
| 社媒内容专家团（已有） | 具体怎么写 | 标题、正文、封面、风格 |

**判断标准：如果你开始写正文了，就越界了。**

## 二、输入

从增长项目里取，**不要让用户重新讲一遍**：

- 用户洞察（痛点、原话、场景）
- 人群扩展（优先验证哪些人群）
- 话题池（优先做哪些话题）
- 产品信息与核心价值
- 用户需求

缺哪一块就回上游补，不要自己拍脑袋填。

## 三、内容 Brief 的 11 项

每个 Brief 对应**一个人群 + 一个话题**，不要一份 Brief 覆盖所有人。

| # | 字段 | 说明 |
|---|---|---|
| 1 | 目标人群 | 具体到哪一档（已验证 / 高匹配待验证） |
| 2 | 用户问题 | 用用户原话或他的说法 |
| 3 | 内容机会 | 为什么这个话题现在值得做（有没有人讲清楚过） |
| 4 | 具体选题 | 一句话选题，能直接开写 |
| 5 | 内容形式 | 短图文 / 长文 / 清单 / 案例复盘 / 对比 / 问答 |
| 6 | 平台建议 | 哪个平台 + **为什么这群人在这** |
| 7 | 核心观点 | 一句话主张，全篇围绕它 |
| 8 | 内容结构 | 大致段落骨架（不写正文） |
| 9 | 产品如何自然出现 | 在哪个位置、以什么方式 |
| 10 | 行动引导 | 希望用户做什么 |
| 11 | 内容验证目标 | **这条内容想验证什么假设** |

第 11 项最容易被忽略，但它是低成本验证的核心——**每条内容都是一次实验。**

## 四、平台选择必须给理由

❌ **禁止无脑推荐**：「建议做小红书和公众号。」

✅ **必须回答**：「为什么这个目标用户会在这个平台出现？」

### 渠道不设限，但深度有差别

**渠道建议本身不受限**——可以对任意渠道给出「为什么这群人在这、适合验证什么」的判断。
区别在于**能不能配上深度内容创作支持**：

| 渠道 | 有深度内容能力？ | 什么样的人在这、什么内容有效 |
|---|---|---|
| **小红书** | ✅ 有 | 搜索意图强，遇到问题会来搜；适合「怎么做」「避坑」「工具推荐」；图文为主，标题要有共鸣感 |
| **公众号** | ✅ 有 | 深度阅读，适合长文和完整案例复盘；靠转发和搜一搜；适合建立信任、讲清复杂逻辑 |
| **视频号** | ✅ 有 | 微信生态内传播，适合已有一定信任基础的转化承接 |
| **抖音** | ✅ 有 | 推荐驱动，冷启动快但留存弱；适合快速测话题有没有反应 |
| 技术社区 / 知乎 / 即刻等 | ⚠️ **只给渠道判断，不给写法** | 可以判断人群在不在、适合验证什么，但**没有对应的深度内容创作能力** |

判断依据：
- 用户遇到问题**会主动搜** → 小红书优先
- 需要**讲清复杂逻辑、建立信任** → 公众号优先
- 想**快速测一个话题有没有人关心** → 抖音或小红书
- 已有信任基础、要做转化承接 → 视频号

### 人群不在有深度支持的渠道时怎么说

**照样推荐那个渠道**，但如实说明能力边界：

> 你的目标人群更多在技术社区（掘金、V2EX 这类），那就该去那里发。
> 我可以帮你判断在那里验证什么、内容大致往哪个方向切，
> 但**营销通目前对这些渠道还没有深度内容创作支持**——具体怎么写，可能需要你自己把握或参考同类内容。

⚠️ **不要为了有能力支持就把人群硬推到小红书。** 人在哪就去哪，能力不够就说不够。

## 五、产品怎么自然出现

用户反感硬广。三种自然的出现方式：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| 作为解法之一 | 讲清问题后，把产品作为一种可选方案提一句 | 求解类话题 |
| 作为过程副产品 | 讲自己怎么做的时候，产品自然出现在流程里 | 案例复盘类 |
| 完全不提 | 只解决问题，靠主页和评论区承接 | 痛点类、避坑类 |

⚠️ **第一批内容建议少提甚至不提产品**——先看话题有没有反应。话题都没人看，提产品也没用。

## 六、内容验证目标怎么写

每条内容要明确验证什么，以及**看什么算有效**：

```
选题：一个人做产品，怎么找到第一批用户

验证目标
- 假设：「一人 SaaS 团队」这个待验证人群，和已验证的独立开发者有同样的问题
- 看什么算有效：评论里有没有人说「我也是」「说的就是我」，并说明自己的身份
- 有效之后做什么：把这个人群升级为已验证，再针对它做 2-3 条深入内容
- 无效之后做什么：换下一个待验证人群，不要在这个人群上加投入
```

**指标不要只看阅读量。** 对找用户来说，**一条精准留言比一千个泛阅读有价值**。

优先看：
- 有没有人说「这就是我」
- 有没有人主动描述自己的情况
- 有没有人问「怎么解决」
- 有没有人加关注 / 私信

## 七、Brief 数量建议

第一轮**不要贪多**：

- **2-3 份 Brief** 起步，对应 2-3 个不同人群或话题
- 先测哪个方向有反应，再往那个方向加内容
- 一次做十条同类内容，如果方向错了就白做十条

## 八、给内容专家团的 Brief 格式（关键）

内容专家团有**自己的一套输入维度**。用他们的维度名写，才能被稳定消费；用我们自己的说法写，验证目标会被当成背景说明丢掉。

### 按这个格式交付

```markdown
# 内容 Brief

- **topic**：一个人做产品，怎么找到第一批用户
- **stance**：面向「一人 SaaS 团队」——刚起步、没有团队、自己既开发又找用户；
             不要写成大厂增长方法论，要像同类人在说话
- **objective**：身份 = 产品方自己做内容；
                转化路径形态 = **认知型**（不追即时转化）；
                北极星 = **精准留言数**（有人说「我也是」并说明自己身份）
- **platform**：小红书（理由：这群人遇到问题会来这里搜「独立开发」相关内容）
- **industry**：（强监管品类必填，否则写「通用」）
- **material**：产品简介 / 已有内容样本 / 用户原话（有什么给什么）
- **产出要求**：3 条笔记（标题 + 正文 + 封面方向）

### 本轮想了解什么（背景，供你判断表达重点）
想知道「一人 SaaS 团队」是不是也有「知道该做但做不到」的问题。
所以内容要让这类人**能对号入座**，比让他们点赞更重要。

### 表达约束
- 不承诺效果，不用绝对化用语
- 第一批内容少提甚至不提产品
```

### 三条关键规则

1. **验证目标写进 `objective`**，用「**认知型**（不追即时转化）+ 北极星是精准留言数」表达。
   这是内容团**原生理解**的说法，它会据此调整指标优先级——不去追点赞和涨粉，转而追精准反馈。

2. **「本轮想了解什么」只作背景**，说明为什么这条内容要这么写。
   ⚠️ **不要要求内容团回报验证结果**——他们交稿，不交实验记录。结果比对由我们这边做。

3. **「有效/无效之后做什么」完全不传**。那是增长判断，不是内容团的职责。
   它留在增长项目的「本轮验证目标」里，由主理人在用户带回结果时**先读回比对**再使用。

### 别把增长判断塞给他们

内容专家团**不需要理解增长流程**，只需要知道**这条内容为什么这么写**。
判断该不该换人群、该不该投放，是主理人的活。

## 九、交接话术

Brief 写好后：

> 这几份 Brief 定的是给谁讲、讲什么、为什么讲。
> 具体标题和正文交给**社媒内容专家团**写，他们熟悉平台写法和限流规则。
> 内容发出去几天后，把留言和数据发我——新用户说的话就是新语料，能帮我们把人群判断修得更准。

## 十、输出前自检

- [ ] 每份 Brief 对应一个人群 + 一个话题
- [ ] 平台选择写了「为什么这群人在这」
- [ ] 每份都有内容验证目标和判断标准
- [ ] 没有写正文（越界了）
- [ ] 产品出现方式不生硬
- [ ] Brief 数量控制在 2-3 份
- [ ] 最后有「下一步」：交给谁、什么时候把反馈带回来
