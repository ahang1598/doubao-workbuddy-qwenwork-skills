# 人群扩展方法

**核心问题：除了已经验证的用户，还有哪些人可能拥有类似的问题？**

## 一、最重要的一条规则

**扩展出来的所有人群都是「待验证假设」，不是目标用户。**

用户最容易犯的错：把 AI 推测的人群当成已验证人群，直接投钱进去。所以：

- 每个候选人群**必须**标匹配度（高 / 中 / 低）
- 每个候选人群**必须**写「为什么值得验证」和「怎么验证」
- 输出时**必须**把「已验证」和「待验证」分栏摆在一起对比

## 二、不要做传统画像扩展

❌ **错的做法**：把「25-35 岁独立开发者」扩展成「25-45 岁开发者」「一线城市开发者」。
这只是把标签放宽，没有任何新信息，也无法验证。

✅ **对的做法**：从用户洞察里拿到**问题和场景**，去找「谁也处在这个处境里」。

关键提问不是「还有哪些人像他」，而是：
> **「这个问题的本质是什么？还有谁会遇到同一个本质问题？」**

例：已验证「独立开发者产品上线后不知道怎么找用户」。
- 问题本质：**做出了东西，但没有把东西送到人面前的能力。**
- 于是可扩展到：一人 SaaS 团队、刚上线 App 的开发者、做完小程序的设计师、写了工具库的工程师……
- 甚至可跨身份：自己开小店的、做手工的——只要「会生产、不会找客」这个本质相同。

跨身份扩展匹配度通常标「中」或「低」，但**值得列出来**，因为往往是增量最大的方向。

## 三、五个扩展维度

每个维度至少给 3-4 个候选：

| 维度 | 问什么 | 例子 |
|---|---|---|
| **相似场景** | 还有谁处在同样的处境里 | 一人软件创业者、AI 应用开发者、刚上线 App 的开发者、小型 SaaS 团队 |
| **相似问题** | 还有谁在为同一件事发愁 | 产品做出来没人用、有产品没流量、不知道怎么推广、找不到付费用户 |
| **相似行为** | 还有谁在做同样的事 | 用 AI 编程工具、发 GitHub 项目、正在做 MVP、搜「独立开发」「产品推广」 |
| **相似需求 / 动机** | 还有谁想要同样的结果 | 低成本验证、找第一批用户、不想大投广告、想要第一笔付费 |
| **相似阶段** | 还有谁在同一个阶段 | 刚完成 MVP、刚上线、正在找第一批用户、有少量用户但停滞 |

**行为维度最有用**——因为行为决定了这些人在哪里出现、搜什么词，直接对接话题发现和内容触达。

## 四、四档分类

输出必须分成四档，不能混在一起：

```
已验证人群（有语料支撑）
- 独立开发者，产品上线后不知道怎么找用户
  依据：语料里 7 人提到，3 人有原话

高匹配 · 待验证
- 一人 SaaS 团队
  相似点：同样是自己做完整产品、同样没有市场团队
  为什么值得验证：问题本质完全相同，只是产品形态不同
  怎么验证：发一条针对这个人群措辞的内容，看有没有留言说「我也是」

中匹配 · 待验证
- 刚上线 App 的开发者
  相似点：都处在刚上线阶段
  差异：App 有应用商店自然流量，痛点强度可能更低

低匹配
- 做手工的个体商家
  相似点：会生产不会找客
  差异：渠道和内容生态完全不同，暂不建议优先测
```

## 五、每个人群的必填字段

| 字段 | 说明 |
|---|---|
| 人群名称 | 用大白话，能一眼看懂是谁 |
| 与已有用户相似在哪里 | 具体到场景/问题/行为，不写「都是年轻人」 |
| 可能需求 | 从相似性推出来的 |
| 为什么值得验证 | 说清潜在价值 |
| 建议验证方式 | 必须是低成本可执行的动作 |
| 优先级 | 高 / 中 / 低 + 理由 |

## 六、验证方式怎么给

必须是**低成本、能快速看到反馈**的动作，不要建议投广告：

| 验证方式 | 成本 | 怎么判断有效 |
|---|---|---|
| 发一条针对该人群措辞的内容 | 最低 | 有没有人留言「我也是」「说的就是我」 |
| 在该人群聚集的社区发一个提问 | 低 | 回复数量与内容 |
| 找 2-3 个该人群的人聊一次 | 低 | 他们的问题是否和已验证人群一致 |
| 用思研发一轮小范围访谈 | 中 | 拿到结构化语料 |
| 投一笔小额广告测试 | 高 | **只在内容已经测出反应后才建议** |

## 七、优先级怎么排

按三个因素综合判断，不要只看人数多少：

1. **问题强度**——这群人的痛有多痛（能不能忍）
2. **触达难度**——能不能找到他们聚集的地方
3. **验证成本**——多快能知道行不行

优先级最高的通常是：**问题强度高 + 有明确聚集地 + 一条内容就能测**。

⚠️ 人群规模大但触达不到、或者痛点很弱，优先级要压低。**不要因为「市场大」就排在前面。**

## 八、输出前自检

- [ ] 所有扩展人群都标了「待验证」
- [ ] 已验证和待验证分栏对比摆出来了
- [ ] 每个人群都写了相似点，且不是年龄性别城市
- [ ] 每个人群都有可执行的低成本验证方式
- [ ] 优先级有理由，不是按人数排
- [ ] 没有把推测说成「你的目标用户是」
- [ ] 最后有「下一步」：先验证哪一个、怎么验证
