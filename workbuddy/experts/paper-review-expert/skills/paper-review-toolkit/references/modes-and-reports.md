# 工作模式、报告骨架与话术规范

## 一、四种工作模式

| 模式 | 触发信号 | 输入 | 输出 |
|------|----------|------|------|
| **M1 全篇评审**（默认） | "帮我评审""打个分""看看能不能过" | 论文全文或主要章节 | 完整评审报告（含红线、评分、PRI 清单、改写示例、行动计划） |
| **M2 单章精修** | "帮我改方法章""摘要怎么写""引言逻辑" | 指定章节 + 上下文 | 该章问题清单 + 段落级 After 改写 + 与全文的衔接建议 |
| **M3 投稿冲刺** | "准备投 XX""要投稿了""审稿意见回来了" | 稿件 + 目标期刊 / 审稿意见 | 就绪度检查 + 三档选刊 + Cover Letter + Rebuttal 草稿 |
| **M4 答辩预演** | "答辩会问什么""能不能过答辩" | 论文 + 答辩类型（预答辩/盲审/正式） | 三类评审人问题清单 + 应答要点 + 反例预案 + 软肋提示 |

模式识别失败时，默认走 M1，并在报告开头说明本次采用的模式。

---

## 二、M1 全篇评审 SOP

1. **补全信息**（一次性）：论文类型与目标场景（学位/中文期刊/英文期刊）、目标刊物或学校要求、当前阶段（初稿/返修）、字数与查重率、是否已有关键数据。
2. **红线筛查**：按 `redlines-and-format.md` 查 F1–F4，记录证据位置。
3. **七维度打分**：逐维度给分 + 扣分理由 + 证据位置；用脚本算总分与通过率区间。
4. **缺陷排查**：按 66 项清单逐条过，只记录确认命中的；为每条赋 S/O/E 算 PRI。
5. **隐性雷区标注**：筛出 S ≥ 4 且 E ≤ 2 的问题单独提示。
6. **合并与排序**：合并同根因缺陷，按 PRI 降序排列。
7. **写改写示例**：P0/P1 逐条给 Before → After。
8. **出行动计划**：三阶段计划，含完成标准与耗时估计。
9. **交付**：结论卡先行，明细在后；提示复评。

---

## 三、M4 答辩预演脚本

模拟三类评审人视角，每类问 3–5 个问题，**问题必须基于论文实际内容**（引用具体章节或数据），不得出通用套话。

### 角色 A：方法论专家（关心设计与可复现）

- 为什么选这个研究方法？换一种方法结论会不会变？
- 样本 / 工况怎么确定的？有没有做样本量或工况覆盖性论证？
- 实验条件写全了吗？我能不能照你的描述复现一遍？
- 数据里有没有异常值？怎么处理的？

### 角色 B：领域专家（关心创新性与贡献）

- 你这个工作和 XX（领域已有工作）的区别到底在哪？
- 你解决的这个问题，工程上真的重要吗？谁会用？
- 你的结论能推广到什么范围？换个场景还成立吗？
- 这个"首次"的依据是什么？

### 角色 C：统计 / 数据审稿人（关心方法正确性）

- 显著性是怎么算的？前提条件检验了吗？
- 只报 p 值的话，效应量多大？这个差异有实际意义吗？
- 多重比较校正了吗？
- 结论里说的因果关系，有实验设计支撑吗？

### 输出格式

| 角色 | 预测问题 | 为什么问这个 | 应答要点 | 需要的证据 | 风险等级 |
|------|----------|--------------|----------|------------|----------|

最后必须给出**三个最大软肋**（最可能被追问且当前材料最薄弱的地方），并建议答辩前必须补的材料清单。

## 四、Before → After 改写规范

### 4.1 硬性要求

1. **可直接替换**：After 给出的是能直接粘进论文的完整句子或段落，不是描述性的"建议增强逻辑性"。
2. **标注改动依据**：写明依据哪个关注点或规范（如"评审关注点：结论强于证据"、"GB/T 7714 期刊著录格式"）。
3. **标注副作用**：若改动会影响其他章节（如改了结论口径，摘要也要同步），必须提示。
4. **保留作者风格**：只改问题句，不整段重写；术语沿用作者原有用法（除非该用法不一致）。
5. **不新增事实**：改写中不得引入作者未提供的数据、文献或结论；必须补的数据用 `[需补充：xxx]` 占位。

### 4.2 输出格式

| 位置 | Before（原文） | 问题 | After（改写） | 依据 |
|------|----------------|------|---------------|------|

### 4.3 典型改写场景

- **摘要缺结果**：句尾补一句带具体数值的结论。
- **结论越界**：把"证明了……"降级为"结果表明……在……条件下"并补适用边界。
- **统计报告不全**：把"差异显著（p<0.05）"补全为"差异显著（t=3.21, df=48, p=0.002, Cohen's d=0.86, 95% CI [0.12, 0.47]）"。
- **引用格式错**：按目标格式重写该条著录。
- **局限套话**：把"研究尚存不足"改写为具体的三条局限与对应影响。

## 五、报告骨架

完整报告顺序固定，便于用户快速抓重点：

1. **结论卡**：总分 / 等级 / 通过率区间 / 红线结论 / 一句话判断
2. **红线筛查结果**：F1–F4 逐项结论（含"未命中"也要写明）
3. **七维度评分表**：得分 / 满分 / 扣分理由 / 证据位置
4. **Top 3 优势**（先肯定再批评，帮助用户判断哪些不能改坏）
5. **缺陷清单**：按 PRI 降序，含 S/O/E、分级、位置
6. **隐性雷区提示**
7. **Before → After 改写示例**
8. **三阶段行动计划**：改什么 / 完成标准 / 耗时 / 所需材料
9. **复评建议与免责说明**

---

## 六、复评机制

用户改完后重新评审时：

1. **使用完全相同的权重方案**，保证分数可比。
2. 输出**对比表**：各维度改前 / 改后 / 变化，并标注变化原因。
3. 输出**等级迁移**（如 D → B）与通过率区间变化。
4. 检查**红线是否清零**、P0 是否全部关闭。
5. 指出**新引入的问题**（修改常带来新风险，如删减导致论证断层）。
6. 给出下一轮最小行动集（通常只剩 P1/P2 与就绪度事项）。

## 七、会话 JSON（供脚本使用）

```json
{
  "scene": "journal-cn",
  "title": "论文标题",
  "target": "《汽车工程》",
  "stage": "初稿",
  "dimensions": { "D1": 13, "D2": 11, "D3": 12, "D4": 14, "D5": 11, "D6": 8, "D7": 7 },
  "fatal": [],
  "defects": [
    {
      "id": "C4-2",
      "name": "样本量严重不足且未说明依据",
      "where": "3.2 节",
      "s": 5, "o": 2, "e": 3,
      "fix": "补充功效分析，说明 α=0.05、power=0.8 下的最小样本量",
      "effort": "2h"
    }
  ],
  "notes": "可选的补充说明"
}
```

- `scene`：`thesis` / `journal-cn` / `journal-en`
- `dimensions`：键为 D1–D7，值为**该维度已得分数**（脚本按场景满分校验上限）
- `fatal`：命中的红线代码数组，如 `["F3"]`；为空表示未命中
- `defects[].s/o/e`：1–5 整数
- `effort`：预估耗时，自由文本（如 `2h`、`半天`）

> 维度满分随 `scene` 变化，脚本会自动按对应权重校验；超出满分会报错提醒重新核对。
