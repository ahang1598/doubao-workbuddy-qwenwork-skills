## C.5 创建脱敏策略

当没有合适的脱敏策略时，引导用户创建新策略。创建流程分为 3 步。

### 步骤一：收集策略基本信息

向用户收集以下信息（可交互式逐步收集）：

| 信息 | 必填 | 说明 |
|------|------|------|
| 策略名称 | 是 | 1~128 字符，同一项目下唯一 |
| 脱敏方法 | 是 | 从可用脱敏方法中选择 |
| 策略描述 | 否 | 最大 512 字符 |
| 用户组脱敏规则 | 是 | 为哪些用户组配置什么脱敏方法 |

**查询可用的脱敏方法**：

```bash
wedatacli ListDataMaskStrategyTypes '{}'
```

展示脱敏方法供用户选择（以 `ListDataMaskStrategyTypes` 实际返回为准）：

```markdown
可用的脱敏方法：

| # | 脱敏方法 | 说明 | 脱敏前 | 脱敏后 |
|---|---------|------|--------|--------|
| 1 | MASK_SHOW_FIRST_4 | 保留前四个字符 | 18888888888 | 1888xxxxxxx |
| 2 | MASK_SHOW_LAST_4 | 保留后四个字符 | 18888888888 | xxxxxxx8888 |
| 3 | MASK_HASH | 哈希脱敏 | 18888888888 | a1b2c3d4e5 |
| 4 | MASK_DATE_SHOW_YEAR | 日期脱敏保留年份 | 2026-04-27 | 2026-xx-xx |
| 5 | MASK_NULL | 置为 NULL | 18888888888 | NULL |
| 6 | MASK_DEFAULT | 默认值脱敏 | 18888888888 | *********** |

请选择脱敏方法（输入编号或名称）。
```

### 步骤二：收集用户组脱敏规则

**查询可用的用户组**：

```bash
wedatacli ListConsoleGroups '{"PageRequest":{"PageNumber":1,"PageSize":50}}'
```

展示用户组供用户选择：

```markdown
可用的用户组：

| # | 用户组名称 | 用户组 ID | 描述 | 用户数 |
|---|-----------|----------|------|--------|
| 1 | 数据分析组 | 17738042827013749 | 数据分析团队 | 15 |
| 2 | 开发组 | 17738042827013750 | 开发团队 | 30 |

请选择需要配置脱敏规则的用户组（可多选），并为每个用户组指定脱敏方法。
不同用户组可以使用不同的脱敏方法（如：数据分析组→保留后四位，开发组→哈希脱敏）。
```

> 💡 **提示**：脱敏策略的核心是「不同用户组看到不同的脱敏效果」。例如，数据分析组可以看到手机号后四位，而普通用户只能看到 NULL。

### 步骤三：确认并创建

展示创建计划并等待用户确认（用户组必须同时展示 `GroupId` 与 `GroupName`）：

```markdown
即将创建脱敏策略：

- **策略名称**：手机号脱敏
- **策略描述**：手机号保留4位显示
- **脱敏方法与生效用户组**：

  | # | 脱敏方法 | 用户组 ID | 用户组名称 |
  |---|----------|----------|-----------|
  | 1 | MASK_SHOW_LAST_4（保留后四位） | 17738042827013749 | 数据分析组 |
  | 2 | MASK_HASH（哈希脱敏） | 17738042827013750 | 开发组 |

确认请回复"确认"，需修改请告诉我。
```

确认后调用 `CreateDataMaskStrategy`：

```bash
wedatacli CreateDataMaskStrategy '{"WorkspaceId":"<workspace_id>","Strategy":{"StrategyName":"<策略名称>","StrategyType":"<脱敏方法>","StrategyDesc":"<策略描述>","Groups":[{"GroupId":"<用户组ID>","StrategyType":"<该组脱敏方法>","GroupName":"<用户组名称>"}]}}'
```

创建成功后输出：

```markdown
## ✅ 脱敏策略创建成功

- **策略 ID**：{StrategyId}
- **策略名称**：{StrategyName}

> 💡 策略已创建，是否需要将此策略绑定到脱敏标签？回复标签名称即可开始绑定。
```

## C.6 删除脱敏策略

> ⚠️ 删除前建议先检查策略是否已绑定脱敏标签，如已绑定需提醒用户先解绑。

1. 先调用 `ListDataMaskStrategies` 查询策略列表，确认要删除的策略
2. 展示删除计划并等待用户确认（必须带上影响范围：该策略下所有「脱敏方法+用户组 ID+用户组名称」）

```markdown
即将删除以下脱敏策略：

| # | 策略名称 | 策略 ID | 描述 |
|---|---------|---------|------|
| 1 | 手机号脱敏 | 71a88499-... | 手机号保留后4位 |

该策略当前生效的脱敏方法与用户组（删除后这些用户组将不再生效）：

| # | 脱敏方法 | 用户组 ID | 用户组名称 |
|---|----------|----------|-----------|
| 1 | MASK_SHOW_LAST_4 | 17738042827013749 | 数据分析组 |
| 2 | MASK_HASH | 17738042827013750 | 开发组 |

> ⚠️ 删除后不可恢复。如果该策略已绑定脱敏标签，建议先解绑再删除。
> 确认请回复"确认"，需修改请告诉我。
```

确认后调用 `DeleteDataMaskStrategy`：

```bash
wedatacli DeleteDataMaskStrategy '{"WorkspaceId":"<workspace_id>","StrategyIds":["<strategy_id>"]}'
```

## C.7 更新脱敏策略

支持更新策略名称、描述、脱敏方法、用户组规则。

1. 先调用 `ListDataMaskStrategies` 查询当前策略信息
2. 收集用户要修改的内容
3. 展示更新计划并等待用户确认（变更对照表必须同时展示 `GroupId` 与 `GroupName`）

> ⚠️ `Groups` 字段为**全量替换**模式，更新用户组规则时必须传入完整的规则列表（包括未修改的规则），否则未传入的规则会被删除。

```markdown
即将更新脱敏策略：

- **策略名称**：手机号脱敏 → 手机号脱敏-v2
- **用户组规则变更**（全量替换后的最终状态）：

  | # | 用户组 ID | 用户组名称 | 原脱敏方法 | 新脱敏方法 |
  |---|----------|-----------|-----------|----------|
  | 1 | 17738042827013749 | 数据分析组 | MASK_SHOW_LAST_4 | MASK_HASH |
  | 2 | 17738042827013750 | 开发组 | MASK_HASH | （不变） |

确认请回复"确认"，需修改请告诉我。
```

确认后调用 `UpdateDataMaskStrategy`：

```bash
wedatacli UpdateDataMaskStrategy '{"WorkspaceId":"<workspace_id>","Strategy":{"StrategyId":"<strategy_id>","StrategyName":"<新名称>","Groups":[{"GroupId":"<用户组ID>","StrategyType":"<新脱敏方法>","GroupName":"<用户组名称>"}]}}'
```
