# 工作流详细步骤 — tm-damage-calc

> **所属技能**：tm-damage-calc | **文件角色**：工作流定义 | **版本**：v1.3.0

---

## Phase 1：输入验证与证据充分性评估

### 1.1 必填字段检查（含降级分级）

| 降级等级 | 缺失字段 | 触发行为 |
|---------|---------|---------|
| L3 重度 | `infringement_duration` 或 `infringement_scope` | → SOFT_DEGRADED：仅输出赔偿要素清单+法定范围 |
| L2 中度 | 所有计算基础字段（损失/获利/许可费） | → SOFT_DEGRADED S2：输出举证妨碍提示+法定赔偿框架 |
| L1 轻度 | 惩罚性赔偿字段或合理开支字段 | → 完整测算+缺失处标注"[待补充]" |
| L0 完整 | 所有必填+计算基础参数齐全 | → 完整测算报告+撰写指引+证据清单 |

### 1.2 计算基础检查

```
has_path1 = plaintiff_loss > 0
has_path2 = defendant_profit > 0
has_path3 = license_fee > 0
has_path4 = true  # 法定赔偿始终可用（兜底）

if !has_path1 && !has_path2 && !has_path3:
    → 仅路径4可用，L2降级
```

### 1.3 证据充分性评估

- 对每项计算基础评估证据充分性（高/中/低）
- 证据不充分 → 标注"证据不足，计算结果仅供参考"
- 侵权人拒绝提供账簿 → 标注"可依据第63条第2款申请举证妨碍[已核实]"

### 1.4 选填字段提取

用户可能提供的案件背景信息属于**选填字段**，从输入中提取后存入报告，但**有则体现，无则省略**：

| 字段 | 提取来源示例 | 缺失处理 |
|------|------------|---------|
| 权利人名称 | "我方XX公司" | 省略，不标注占位 |
| 商标注册号 | "第123456号注册商标" | 省略，不标注占位 |
| 商标名称 | "云智""智云"等 | 省略，不标注占位 |
| 商标类别 | "第9类软件产品" | 省略，不标注占位 |
| 注册/续展日期 | "2018年注册，2028年续展" | 省略，不标注占位 |
| 商标知名度 | "驰名商标""知名品牌" | 省略，不标注占位 |
| 侵权人名称 | "XX公司侵权" | 省略，不标注占位 |

> **注意**：与 L1/L2 字段的区别：选填字段缺失时**不标注"[待补充]"**，直接省略对应输出块。L1/L2 字段缺失时须标注"[待补充]"。

### 1.5 Fast-Path 机制

| Fast-Path 触发条件 | 处理方式 |
|-------------------|---------|
| 仅有一项计算基础+信息完整 | 跳过其他路径，直接进入该路径测算+法定赔偿兜底 |
| 所有四路径数据齐全 | 跳过逐条评估，直接四路径递进测算 |
| 有惩罚性赔偿证据 | 惩罚性评估与主测算并行 |

## Phase 2：四路径递进测算+惩罚性评估+合理开支

### 2.0 时间对齐规则（强制，优先级最高）

用户提供的数据可能为**年度口径**（"年销售额500万"）或**月均口径**（"月均营收5万"），但侵权可能仅覆盖部分期间。必须按实际侵权期间计算，**禁止用全年月数（12）替代实际月数**。

**三种数据口径判定**：

```
if 输入为年度口径（"年销售额X万""年利润X万"，隐含12个月）:
    → 折算后金额 = 年度金额 × (实际侵权月数 / 12)
    → 标注"（X-X月）"
elif 输入为月均口径（"月均营收X万""月均利润X万"）:
    → 折算后金额 = 月均金额 × 实际侵权月数
    → 严禁 × 12！必须 × 实际月数
    → 标注"（X-X月，共X个月）"
else:  # 输入已明确为实际期间数据
    → 直接使用，标注"（已为实际期间数据）"
```

**折算示例**：

| 数据口径 | 输入数据 | 侵权期间 | 正确计算 | 错误做法 | 标注格式 |
|---------|---------|---------|---------|---------|---------|
| 年度 | 年销售额500万 | 1-8月（8个月） | 500×8/12=333.33万 | 直接用500万 | "销售额约333.33万元（1-8月）" |
| 年度 | 年利润100万 | 1-6月（6个月） | 100×6/12=50万 | 直接用100万 | "利润损失约50万元（1-6月）" |
| 年度 | 年许可费30万 | 3个月 | 30×3/12=7.5万 | 直接用30万 | "许可费基准约7.5万元（3个月）" |
| 年度 | 年销售额500万 | 14个月 | 500×14/12=583.33万 | 直接用500万 | "销售额约583.33万元（14个月）" |
| **月均** | **月均营收5万** | **2023年1-8月（8个月）** | **5×8=40万** | **5×12=60万** | **"总营收约40万元（1-8月，共8个月）"** |
| 月均 | 月均利润3万 | 1-5月（5个月） | 3×5=15万 | 3×12=36万 | "总利润约15万元（1-5月，共5个月）" |
| **多门店月均** | **年均门店数5×单店月均营收11.8万** | **2023年5-12月（8个月）** | **5×11.8×8=472万** | **5×11.8×12=708万** | **"年度总营收约472万元（2023年5-12月，年均5店，共8个月）"** |

**关键约束**：
- 折算后的金额必须标注实际计算期间，如"（1-8月）"或"（2024年1-8月）"
- **月均口径严禁×12**：月均数据乘以12是全年估算，侵权不足一年时必须乘以实际月数
- **多门店月均口径严禁×12**：年均门店数×单店月均营收×经营月数，非×12（5×11.8×8=472而非5×11.8×12=708）
- 跨年或不足月时，按实际天数折算
- 用户数据已明确为实际期间数据（非年度/月均口径），直接使用并标注"（已为实际期间数据）"

### 2.1 路径1：权利人实际损失（优先级1）

**六操作管线执行顺序**：
1. **转化**：损失金额 → 结构化计算要素
2. **细化**：实际损失=因侵权减少的销量×单位利润
3. **补充**：补充第63条第1款法律依据
4. **拆分**：损失计算与获利计算分开
5. **去重**：损失中不重复计算合理开支
6. **统一**：金额区间表述，标注证据充分性

- 如有损失数据 → 先执行 §2.0 时间对齐（年度→实际期间折算），再计算
- 无 → 跳过，标注"[待补充原告损失财务数据]"

**保守取值（路径1强制步骤）**：

在路径1细化完成后，须对"原始计算"金额进行保守取值扣除，分两步：

**步骤1：逐项扣除清单**

| 扣除因素 | 判定方法 | 扣除比例参考 |
|---------|---------|------------|
| 不可归因的销量减少 | 对比行业同期数据/权利人非侵权期间数据 | 10%-30% |
| 促销降价因素 | 区分主动降价促销 vs 被迫降价应对侵权 | 5%-15% |
| 行业整体下行 | 查询行业同比数据 | 行业下行幅度 |
| 产品质量/服务变化 | 权利人内部经营变化 | 100%（全扣） |
| 其他竞品影响 | 竞品同期市场动作 | 5%-10% |

**步骤2：生成"年度损失测算明细表"**

```
| 项目 | 原始计算 | 扣除因素 | 扣除金额 | 保守取值 |
|------|---------|---------|---------|---------|
| 销量减少损失 | A | [因素+比例] | A×比例 | A×(1-比例) |
| 价格侵蚀损失 | B | [因素+比例] | B×比例 | B×(1-比例) |
| 其他损失 | C | [因素+比例] | C×比例 | C×(1-比例) |
| 合计 | A+B+C | | 扣除合计 | 保守合计 |
```

**步骤3：校验保守取值合理性**
- 保守取值 < 原始计算（至少有一项扣除）
- 保守取值 > 0（不得因扣除而归零）
- 每项扣除因素有明确依据（不得凭空扣除）
- 扣除比例在合理范围内（总扣除通常不超过原始计算的40%）

### 2.2 路径2：侵权人获利（优先级2）

**六操作管线执行顺序**：
1. **转化**：获利金额 → 结构化计算要素
2. **细化**：侵权获利=侵权销量×单位利润
3. **补充**：补充第63条第1款+第63条第2款（举证妨碍）
4. **拆分**：获利计算与损失计算分开
5. **去重**：获利中不重复计算合理开支
6. **统一**：金额区间表述，标注证据充分性

- 如有获利数据 → 先执行 §2.0 时间对齐（年度→实际期间折算），再计算
- 无 → 跳过，标注"[待补充被告经营数据；可依据第六十三条第二款[已核实]申请举证妨碍]"

### 2.3 路径3：许可使用费倍数（优先级3）

**六操作管线执行顺序**：
1. **转化**：许可费 → 倍数计算要素
2. **细化**：许可费×合理倍数
3. **补充**：补充第63条第1款+司法解释第17条
4. **拆分**：许可费计算独立
5. **去重**：许可费中不重复计算合理开支
6. **统一**：倍数范围表述，标注许可合同类型

- 如有许可费 → 先执行 §2.0 时间对齐（年度许可费→实际期间折算），再按倍数计算（通常1-3倍）
- 无 → 跳过，标注"[待补充商标许可使用合同]"

### 2.4 路径4：法定赔偿（优先级4，兜底）

**六操作管线执行顺序**：
1. **转化**：侵权情节 → 法定赔偿评估要素
2. **细化**：持续时间+规模+主观恶性+商标知名度+后果
3. **补充**：补充第63条第3款（500万以下）
4. **拆分**：法定赔偿独立于其他路径
5. **去重**：不重复其他路径已计算的项目
6. **统一**：金额区间表述，标注"法院酌定"

- 兜底适用，始终可计算
- 根据侵权情节（含实际侵权期间）建议金额区间
- 标注"法定赔偿已考量侵权期间因素，如侵权仅8个月，不得以全年标准酌定"
- 标注：选择法定赔偿路径时，不叠加惩罚性赔偿（存在争议）

### 2.5 惩罚性赔偿评估

**双重条件检查（强制）**：

```
if is_malicious && is_serious:
    → 适用惩罚性赔偿
    base = 路径1/2/3的计算结果（不含合理开支）
    result = base × (1-5倍)
elif is_malicious && !is_serious:
    → 仅恶意但情节不严重，不适用惩罚性赔偿
elif !is_malicious && is_serious:
    → 情节严重但无恶意，不适用惩罚性赔偿
else:
    → 不适用惩罚性赔偿
```

**关键约束**：
- 基数**必须**取自路径1/2/3，不包含合理开支
- 倍数1-5倍，需与恶性程度匹配
- 标注"惩罚性赔偿基数取自路径X"

**基数选择理由（强制输出）**：

当多于一条路径可用时，须在惩罚性赔偿评估节输出基数选择理由：

```
1. 证据充分性对比：[路径1证据充分性] > [路径2证据充分性] > [路径3证据充分性]
   选择路径[Y]的[原始计算/保守取值]结果作为基数
2. 路径优先级考量：[解释所选路径的优先级优势]
3. 排除其他路径的原因：[路径A]因[理由]不选；[路径B]因[理由]不选
```

**选择规则**：
- 首选：证据充分性最高的路径结果（优先选"高"，其次"中"，最后"低"）
- 同等证据充分性：按路径1→2→3优先级
- 路径1如有保守取值：基数取保守取值（非原始计算），确保基数稳健
- 证据充分性均为"低"：建议律师补充证据后再确定基数

### 2.6 合理开支汇总

- 各项费用相加（律师费+公证费+调查费+购买侵权产品费+差旅费+其他）
- 标注凭证情况
- **独立于赔偿基数，不作为惩罚性赔偿基数**

## Phase 3：测算报告生成

### 3.1 案件背景（条件渲染——有则体现，无则省略）

- 提取用户输入中的案件背景信息（权利人名称、商标注册号/名称/类别、注册日期、续展截止日期、商标知名度、侵权人名称等）
- 有信息 → 输出"案件背景"小节，逐项列出
- 无信息 → **整节省略**，不输出占位符、不标注"[待补充]"

### 3.2 侵权概况
- 侵权持续时间+侵权范围

### 3.3 计算基础概况
- 可用计算基础+数据时间口径说明

### 3.4 四路径递进测算
- 按优先级1→2→3→4排列
- 每条路径：计算基础+计算依据+测算结果+证据充分性

### 3.5 惩罚性赔偿评估
- 恶意认定+情节严重认定+基数+倍数+结果

### 3.6 合理开支
- 各项费用明细+合计

### 3.7 推荐方案
- 推荐计算路径+推荐赔偿总额+理由
- 免责声明："参考性测算，须律师审核，最终以法院裁定为准"

## Phase 5：报告金额一致性校验（强制）

> **定位**：生成报告后，逐项交叉校验所有金额是否计算正确、前后是否一致。发现不一致时**必须修正后再输出**，不得输出存在内部矛盾的测算报告。
>
> **执行顺序**：Phase 4（格式/法条/红线）→ **Phase 5（金额交叉校验）** → 输出。Phase 5 未通过则回到对应 Phase 修正后重跑。

### 5.1 推荐方案金额一致性

**校验公式**：

```
推荐赔偿总额 = 推荐路径测算结果 + （如适用）惩罚性赔偿金额 + 合理开支合计
```

**校验流程**：

```
expected_total = recommended_path_result + punitive_amount + reasonable_expenses_total
if report.recommended_total != expected_total:
```

### 5.8 路径1保守取值合理性校验（新增）

**仅当路径1已计算时执行**：

```python
if report.has_path1() and report.path1.has_conservative_table():
    original = report.path1.loss_table.original_total
    conservative = report.path1.loss_table.conservative_total
    deductions = report.path1.loss_table.deduction_total
    
    # 校验1：保守取值 < 原始计算
    if conservative >= original:
        → 严重错误：保守取值应小于原始计算（至少有一项扣除）
        → 修正：逐项检查扣除因素，确保扣除后有实际减少
    
    # 校验2：保守取值 > 0
    if conservative <= 0:
        → 严重错误：保守取值不得归零
        → 修正：调整扣除比例，保留合理基数
    
    # 校验3：扣除合计 = 各分项扣除之和
    if deductions != sum_of_item_deductions:
        → 严重错误：年度损失测算明细表扣除合计与分项之和不一致
        → 修正：重新加总
    
    # 校验4：总扣除比例不超40%
    deduction_rate = deductions / original
    if deduction_rate > 0.4:
        → 警告：总扣除比例超过40%，建议检查扣除是否过度保守
    
    # 校验5：每项扣除有明确依据
    for item in report.path1.loss_table.items:
        if item.deduction_amount > 0 and not item.deduction_reason:
            → 严重错误：扣除项缺少扣除因素说明
            → 修正：补充扣除因素和比例依据
```

**校验指标总结**：

| # | 检查项 | 判定公式 | 不合格处理 |
|---|--------|---------|-----------|
| CV-01 | 保守取值 < 原始计算 | conservative < original | 阻断：逐项检查扣除因素 |
| CV-02 | 保守取值 > 0 | conservative > 0 | 阻断：调整扣除比例 |
| CV-03 | 扣除合计 = 分项之和 | deductions == sum | 阻断：重新加总 |
| CV-04 | 总扣除比例 ≤ 40% | deduction_rate ≤ 0.4 | 警告：标注供律师注意 |
