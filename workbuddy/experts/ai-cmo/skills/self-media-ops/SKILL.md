# 自媒体运营技能包

本技能包是AI CMO的共享方法论中枢，3 位专家（定位 / 选题脚本 / 涨粉变现）共用同一份领域知识。专家正文是面向各自角色的「操作速查版」，本包的 references 是「深度版」。

## 三段式主线
自媒体运营是顺序依赖的三段，并由增长段复盘反哺内容段，形成闭环：
1. **定位** — 我是谁、为谁做、和谁对标 → 详见 `@references/account-positioning-guide.md`
2. **内容** — 做什么内容、怎么写能爆 → 详见 `@references/topic-script-guide.md`
3. **增长** — 怎么发、怎么涨、怎么变现、怎么复盘 → 详见 `@references/growth-monetization-guide.md`

## 调用链路（极简）

主理人按「定位 → 内容 → 增长」接力调度成员，增长段复盘反哺内容段构成闭环：

```
用户需求
  └→ 主理人建团队(TeamCreate) + 拆解阶段
       ├→ [定位] ip-incubation-lead  → 人设资产/受众/对标/内容支柱
       │      ↓ 原文交接
       ├→ [内容] hot-topic-expert          → 选题池/钩子/脚本
       │      ↓ 原文交接
       ├→ [增长] multi-platform-content-lead   → 发布优化/分发/复盘/变现
       │      ↓ 复盘反哺选题
       └→ 主理人汇总 → 交还用户
```

> 链路细节（W1 起号全链路 / W2 内容生产 / W3 涨粉专项 / W4 变现设计）在主理人 MD；单点需求可跳过前置单专家直调（见主理人 MD「预设 Workflow」尾段）。本节只给极简骨架，不重复 Workflow 细节。

## 知识模块

### 模块一：账号定位与人设
要点：Persona 用户代表法（Cooper）合成主受众、价值主张三角 VPC（Osterwalder）求 Fit、Ira Glass 品味差距做对标校准、人设资产交集法（稀缺经验∩稳定产出∩受众情绪价值）、内容支柱作选题边界。
深度方法论：`@references/account-positioning-guide.md`

### 模块二：选题与脚本
要点：选题池多源沉淀、AIDA 漏斗、钩子模板库（Schwartz 认知层级：对接观众已有欲望而非介绍内容）、故事 4 拍弧线（Vogler）、完播率三段 + 流失风险线、各平台内容形态适配。
深度方法论：`@references/topic-script-guide.md`

### 模块三：涨粉与变现
要点：1000 True Fans（Kevin Kelly，深度变现+直接触达）、变现五象限按粉丝层级匹配主力线、AARRR（McClure，重 Retention/Referral 而非只追 Acquisition）、发布前优化 + 评论区养鱼、四率（完播/关注转化/互动/转粉）复盘反哺选题、多平台适配分发。
深度方法论：`@references/growth-monetization-guide.md`

## 输入物 → 产出物 → 归属专家

| 阶段 | 必填输入 | 选填输入（缺可标【假设-需验证】） | 产出物 | 归属专家 |
|---|---|---|---|---|
| 定位 | 赛道/品类、自身优势与资源、目标平台 | 对标账号偏好、表达风格样本 | 人设资产卡、核心受众画像、对标拆解表、内容支柱清单 | ip-incubation-lead |
| 内容（选题） | 人设资产 + 核心受众 + 内容支柱 | 目标平台倾向、内容形态偏好 | 选题池表（可排期，含钩子类型/形态/平台/优先级） | hot-topic-expert |
| 内容（脚本） | 选定选题 + 人设语气 | A/B 钩子变体数量 | 脚本（标题/钩子/分镜或口播/CTA/时长/平台） | hot-topic-expert |
| 增长（发布） | 脚本 + 目标平台 | 竞品分发策略 | 发布前优化清单、评论区互动预案 | multi-platform-content-lead |
| 增长（复盘） | 发布记录 + 单条数据 | 历史均值基线 | 四率复盘表 + 爆点共性 → 反哺选题池 | multi-platform-content-lead |
| 增长（分发/变现） | 粉丝量级与画像 + 可承接变现资源 | 历史变现流水、预算 | 多平台分发方案、变现路径优先级 | multi-platform-content-lead |

> 必填缺 → 专家停下追问、不产出完整方案（见下方「信息门槛」节）；选填缺 → 可标【假设-需验证】继续。上游产出 = 下游必填输入；跨段信息原文经主理人中转，不直连。

## 信息门槛（硬性必填门 · 三成员 + 主理人共享口径）

缺**必填**信息 → 停下追问、不产出完整方案；缺**选填**信息 → 可标「【假设-需验证】」继续。这是全专家团统一规则，主理人与三成员各自执行：

- **主理人门**：建团队前核验全局必填（运营目标 + 目标平台）；调度某成员前核验该阶段必填（见上表「必填输入」列）。缺则不建团队/不调度，向用户追问「缺什么 + 为什么必填 + 最小判断方向」，不产出完整方案。
- **成员门**：产出前二次核验自身必填（即上表该行「必填输入」）。Team 型场景缺则 SendMessage 回主理人请求补充；单专家直调缺则直接追问用户。补齐后才产出。
- **门衔接**：主理人调度前已核验阶段必填并原文交接给成员；成员若发现交接信息仍缺必填，回传主理人而非自行假设产出。SendMessage 回传格式：「【必填门未通过】我产出<XX>还需主理人补充：<缺失项>（为什么必填：…）。已接收信息：…。暂不产出完整方案。」

> 比爆品选品专家的「分层追问 + 区间预估 + 标假设」更严：本团必填缺 = 阻断不产出完整方案，不是标注即继续。各成员的逐项必填清单见各成员 MD 与各 reference §〇。

## 常见误用与边界

| 误用 | 后果 | 校正 / 详见 |
|---|---|---|
| 只调单专家跳过定位 | 选题漂移、人设无记忆点 | 全链路场景必须从定位起；单专家直调仅适用定位已清晰的单点需求（主理人 MD W2） |
| 把钩子/完播阈值当精确数 | 误判平台规则、硬套失效 | 阈值为平台经验值，随规则变化；`@references/topic-script-guide.md` §五 |
| 多平台直搬不重剪 | 全平台都起不来、被限流 | 一鱼多吃 = 适配改写非搬运；`@references/growth-monetization-guide.md` §七 |
| 变现过早过重 | 透支信任、掉粉 | 按粉丝量级排优先级；`@references/growth-monetization-guide.md` §八 |
| 只追单条爆款不建系列/合集 | 爆款涨来的人无「下一集」，留存差 | 复盘找可复制爆点反哺选题，建合集提权重；`@references/growth-monetization-guide.md` §九 |
| 对标只看数据不拆结构 | 抄了数据差距依旧 | 拆选题/节奏/人设层级，找差异化卡位；`@references/account-positioning-guide.md` §四 |
| 信息不足就产出万金油方案 | 针对性差、不可执行、人设漂移 | 必填缺则停下追问补齐再产出（见「信息门槛」节）；不允许"基于假设先给完整草案" |
| 产出文档暴露内部代号/英文Agent ID | 用户看不懂`multi-platform-content-lead`这类署名、W1/W2/Phase代号，像看后台日志 | 交付文档禁用 W1-W4/Phase/SOP 等内部代号，成员称谓用中文角色名禁英文ID；详见主理人 MD「面向用户文档呈现规范·脱敏铁律」 |
| 产出文风机械像 AI | 千篇一律填空表格、套话堆砌、口播稿像作文不像说话 | 禁 AI 套话、先讲业务判断再给清单、口播写成可念连续文本；详见主理人 MD「面向用户文档呈现规范·文风铁律」 |

> 本节是各 references 末「常见陷阱」的索引，深度原因与改法见对应 reference；本包不做重复展开。

## 输出格式
专家产出以文档/表格为主：人设卡、选题池表、脚本、发布计划、复盘表、变现路径图。主理人汇总为最终方案。

## 注意事项
- 人设一致性贯穿三段：选题落内容支柱、脚本符人设语气、变现不破调
- 平台合规：不教违规涨粉手段；不承诺具体涨粉/变现数字
- 分发是适配改写非搬运
