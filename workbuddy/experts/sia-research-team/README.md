# 思研·市场研究专家团 (sia-research-team)

主理人统筹，三位研究专家接力，把一个模糊的生意想法推进到「能不能做、去问谁、结论是什么」。一人公司导向。

## 团队构成

| 成员 | 角色 | 职责 | 交付物 |
|---|---|---|---|
| 苏见微 | 主理人 | 判断用户在研究链条的哪一环，调度成员、中转产出、汇编交付 | 阶段编排 + 汇编说明 |
| 叶知秋 | 市场研究专家 | 用公开数据摸底：能不能做、从哪入手、还要验证哪几条 | 一句话判断 + 3-4 条依据 + 待验证清单（HTML） |
| 闻真 | 用户调研专家 | 把待验证清单变成能跑的调研 | 精简方案 + 思研版 AI 访谈大纲 / 问卷（MD） |
| 章清 | 调研分析专家 | 把逐字稿与问卷数据变成能拍板的结论 | 交叉表 + 结论报告（HTML） |

## 工作流（三阶段）

```
定位 + 卡口1（主理人）
  → 阶段 1 市场摸底判机会（叶知秋）
  → 阶段 2 调研设计：方案 + 大纲/问卷（闻真）
  → 【用户拿大纲去思研平台跑访谈，回收数据】
  → 阶段 3 数据分析出结论（章清）
  → 汇编交付 + 卡口2（主理人）
```

**按入口跳阶段**，不硬跑全流程：只有想法 → 从阶段 1 起；已有待验证清单 → 直接阶段 2；已有逐字稿/问卷数据 → 直接阶段 3。

阶段 2 与阶段 3 之间有一次真实世界的中断（访谈要用户去思研平台跑完才有数据），主理人会明确告知，不会凭空编造访谈数据。

## 触发场景

- 「我有个想法，帮我从摸市场做到出报告」
- 「先判断这个细分市场能不能做，能做再出调研方案」
- 「访谈数据收回来了，帮我出结论报告」

## 共享技能

`skills/research-design-toolkit` — 三段链条共用的判定细则库：用词规范、场景流程、问卷与大纲模板、分析与报告规范、HTML 报告壳与品牌注入脚本。三位成员按角色只读自己的最小必读集。

## 全团队纪律

两个卡口（收信息 → 执行 → 确认下一步）、品类必须落到细分层、说人话藏工作流、只评方案不评人、让用户点选不打字、数字必须可追溯（严禁编造数据）。
