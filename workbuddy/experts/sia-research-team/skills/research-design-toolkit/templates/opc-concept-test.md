# [产品/想法一句话] 概念验证访谈大纲

**访谈对象**：[目标用户定义]
**单场时长**：45-60 分钟 ｜ **建议人数**：8-12 人（可行性判断够用）

---

## 一、开场（3 分钟）

> 我是 XX，在做一个关于 [品类场景] 的小调研。**没有对错答案，就想听你真实怎么想、怎么做的**，包括觉得没用的部分。过程需要录音，只用于整理，可以吗？

## 二、现状与不满（10 分钟）**——必须在展示概念之前**

1. 你平时遇到 [目标场景] 的时候，一般怎么处理？
   - 追问：能说个最近一次的具体例子吗？
2. 这个过程里最麻烦 / 最不爽的是哪一步？
   - 追问：当时怎么凑合过去的？
3. 为解决这个麻烦，你试过什么办法或工具？为什么后来继续用 / 放弃了？

*主持人注意：用户说的"现有办法"就是你的真对手，记下来。*

## 三、呈现概念（2 分钟）

> [给用户自己看：一段话描述 / 几张图 / demo 演示，不要自己解说]

## 四、复述理解（3 分钟）**——不能省**

4. 看完之后，你能用自己的话说说这是个什么东西吗？

*没听懂 ≠ 不喜欢。先分清"听不懂"还是"不想要"。*

## 五、第一反应（10 分钟）

5. 第一感觉怎么样？哪里最吸引你？
6. 有什么让你犹豫、不放心的？
7. 刚才提到你觉得麻烦的 [第2题的痛点]，这个能解决你的问题吗？哪里能 / 哪里不能？

## 六、对比与意愿（15 分钟）

8. 比起你现在用的办法，这个好在哪？差在哪？
9. 如果上线了，你会用吗？
   - 会：什么情况下会打开它？多久用一次？
   - 不会：卡在哪？改成什么样你就会用？
10. [若涉及付费] 现在为这类东西花多少钱？这个你觉得值多少？

## 七、收尾（5 分钟）

11. 如果只能加一个功能 / 只能砍一个功能，你选什么？
12. 还有什么我没问到但你觉得重要的？

---

## 访谈后快速判断表（访谈完 5 份后填）

| 判断项 | 看什么 | 现状 |
|---|---|---|
| 痛点真实吗 | 第 2 题用户能不能具体说出来 | |
| 听得懂吗 | 第 4 题复述的准确度 | |
| 比现状好吗 | 第 8 题说得出具体好处的人数 | |
| 会用吗 | 第 9 题给出具体使用场景的人数 | |
| 谁最先用 | 哪类受访者反应最积极，他们的共同点 | |

**判断标准（访谈 8 人后）**：
- 痛点真实 + 听得懂 + 过半说得出使用场景 → 值得往下做，进入小范围试用
- 痛点真实但方案没打动 → 回到概念修改，重点改第 5/8 题暴露的部分
- 痛点说不清 → 这个方向可能不成立，或找错了人群

## 主持人提示

- 第 2 题的时间必须给足——现状聊不透，后面的对比全是空中楼阁
- 概念呈现后忍住不解说、不辩护；用户质疑时追问"具体哪里让你这么觉得"
- "会用吗"的回答打对折听——意愿永远高于真实行为
- 每场记下受访者身份特征，第 5 场后开始找"反应最积极的人"的共同点
