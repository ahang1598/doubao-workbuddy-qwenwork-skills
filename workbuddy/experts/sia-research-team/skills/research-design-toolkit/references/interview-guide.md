# 访谈大纲撰写

**大纲不是问题清单，是一条有节奏的对话路径。** 提纲的每个模块都要能追溯到某个研究目标。

---

## 结构：五段式

| 段落 | 时长占比 | 干什么 | 注意 |
|---|---|---|---|
| **开场** | 5% | 自我介绍、说明用途、录音授权、打消顾虑 | 明确说"没有对错，就想听你真实想法" |
| **暖场** | 10% | 从简单的日常问题聊起，建立信任 | 不要一上来就问敏感或核心问题 |
| **主体** | 70% | 按研究目标逐块推进 | 每块之间要有过渡句，不要硬切 |
| **深挖** | 10% | 对前面出现的关键点回头追问 | 现场判断，提纲里预留位置 |
| **收尾** | 5% | 补充问题、感谢、后续说明 | 问一句"还有什么我没问到但你想说的" |

### 时长与内容量

| 单场时长 | 主体模块数 | 每模块问题数 |
|---|---|---|
| 45-60 分钟 | 3-4 块 | 3-5 个主问题 |
| 90 分钟 | 4-6 块 | 4-6 个主问题 |
| 120 分钟（座谈会） | 4-5 块 | 3-4 个主问题 + 互动环节 |

**主问题之外要写追问提示**，但不用写死——追问是现场判断。

**新手最常犯的错**：问题写太多。90 分钟塞 40 个问题，结果每个都只能浅浅带过。**宁可少问几个问得深，不要面面俱到全是皮毛。**

## 提问的基本功

### 漏斗式：从宽到窄

```
先开放 → 再聚焦 → 最后确认
```

- 开放："你平常怎么处理 XX 这件事？"
- 聚焦："刚说到用 A 工具，具体是哪些情况下会用？"
- 确认："所以主要是赶时间的时候会用 A，对吗？"

**顺序不能反。** 先问封闭问题会锚定用户，后面的开放问题就问不出真东西了。

### 问行为，不问观点

| 别问 | 改成 |
|---|---|
| 你觉得这个功能好用吗？ | 你最近一次用这个功能是什么时候？当时在做什么？ |
| 你会为这个付费吗？ | 你现在为类似的东西花过钱吗？花了多少？ |
| 你希望增加什么功能？ | 上次遇到搞不定的情况是什么？你最后怎么解决的？ |
| 你重视安全性吗？ | 你选它的时候，都比较了哪几个？为什么最后选了它？ |

**回忆具体经历比征求意见可靠得多。** 用户对未来行为的预测普遍不准，对过去做过什么的回忆相对可靠。

### 避免引导

| 引导性问法 | 中性问法 |
|---|---|
| 这个功能是不是让你觉得更方便了？ | 用了这个功能之后，和以前有什么不一样吗？ |
| 你是不是因为价格太高才没买？ | 当时没买是什么原因？ |
| 大部分用户都觉得 X 很好，你呢？ | 你对 X 的感觉是什么样的？ |

**三个要删的信号**：句子里有"是不是""会不会""对吧"；提到"别人都""大家都"；问题里已经含了答案。

### 追问的几种打法

| 打法 | 话术 | 用在哪 |
|---|---|---|
| **要具体** | "能说个具体的例子吗？" | 用户说得很笼统时 |
| **问过程** | "那之后呢？然后你做了什么？" | 想还原完整行为链 |
| **挖动机** | "当时为什么选这个而不是那个？" | 想知道决策依据 |
| **重复确认** | "你刚说的 XX，是指…？" | 用户用了模糊或多义的词 |
| **沉默** | 停 3-5 秒不说话 | 用户话说一半时，往往会自己补下去 |
| **反向问** | "有没有过用完觉得后悔的时候？" | 只听到好话时，主动找反面 |

## 从研究目标到提纲模块

**每个模块必须对应研究目标，写不出对应关系的模块删掉。**

| 研究目标类型 | 提纲模块怎么写 |
|---|---|
| 摸清用户是谁（画像） | 从日常生活/工作场景聊起，让用户自我描述，不要直接问人口属性（那些放甄别问卷） |
| 摸清怎么用（行为） | 还原最近一次完整使用经历，逐步骤走，问清每步的动作与感受 |
| 挖需求与痛点 | 从「上次遇到什么麻烦」入手，问当时怎么解决的、现在还有什么搞不定的 |
| 找选择原因（动机） | 回溯决策过程：怎么知道的 → 比较了什么 → 为什么选它 → 用了之后怎么想 |
| 测概念/方案 | 先问现状与预期，再呈现概念，再问理解、吸引点、疑虑、使用意愿 |
| 品牌感知 | 先无提示自由联想，再提示后评价，顺序不能反 |

### 概念测试模块的固定顺序

```
1. 先问现状与不满  ← 必须在看概念之前问，否则会被概念带跑
2. 呈现概念（描述/原型/视频）
3. 复述理解        ← 让用户说"你理解这是个什么东西"，检验传达准确性
4. 第一反应        ← 吸引点、疑虑，此时最真实
5. 逐要素评价      ← 哪部分有吸引力、哪部分多余
6. 使用意愿与原因
7. 改进建议
```

**第 1 步和第 3 步最容易被省，但都不能省。** 不先问现状，就没有对比基准；不让用户复述，会把"没听懂"误判成"不喜欢"。

## 座谈会 vs 一对一深访

| | 一对一深访 | 座谈会 |
|---|---|---|
| 适合 | 涉及隐私、需要深挖个人经历、话题敏感 | 需要群体激发、看观点碰撞、话题偏公共 |
| 人数 | 1 人 | 3-4 人（迷你组）或 6-8 人 |
| 提纲差异 | 可以顺着个人经历走，模块顺序灵活 | 必须有明确的轮次设计，避免个别人抢话 |
| 特有环节 | 无 | 投射技术、排序练习、分组讨论 |
| 时长 | 60-120 分钟 | 90-120 分钟 |

**座谈会提纲必须写清**：每个环节谁先说、怎么保证人人发言、遇到意见一致时怎么追问分歧。

**涉及钱、隐私、失败经历的话题不要用座谈会**——有人在场时用户会美化自己。

## 从三份真实大纲提炼的执行做法

### 1. 大纲是路线图，不是逐字稿

真实项目的大纲都会在开头写清：主持人可随受访者的表达调整顺序、增减追问，并用对方听得懂的说法沟通。

**写法要求**：
- 每个模块写清「目的 + 主问题 + 追问方向」，不要把所有追问写成必问题
- 用「重点关注」「若未主动提及再追问」「视时间交叉覆盖」标注弹性
- 不要要求主持人按题号逐题念完；**受访者的真实经历优先于提纲顺序**

### 2. 会前问卷要真正用起来

对已收集到的个人信息（当前使用情况、购买过的服务、出行经历等），访谈时应**逐一回访核实并深挖**，不要再从头泛问一遍。

> 示例写法："根据会前问卷中填写的内容，优先追问使用频率高/近期发生的服务；中低频服务视时间在不同小组交叉覆盖。"

这样既节省时间，也能让访谈更贴近真实经历。

### 3. 多业务线研究：先铺开，再分组深挖

面对多项服务/功能时，不要一项项从头讲到尾。先让用户列出自己日常会用的服务，主持人记录成卡片，再按使用频率和重要性排序，优先深挖高频项。

每项服务沿用同一条行为链：

```
怎么用 → 什么触发 → 去哪里找信息 → 怎么选产品 → 去哪办 → 哪不满意 / 还缺什么
```

好处是不同业务之间可横向比较，也不会因时间不够导致重点服务没有聊透。

### 4. 用户与非用户必须分开问

| 对象 | 该问什么 |
|---|---|
| 正在使用的人 | 最近一次经历、使用过程、续用/加购、实际满意与不满 |
| 听说过但没用的人 | 知道什么、为什么没试、顾虑在哪、什么条件会尝试 |
| 从没听过的人 | 先了解其原有做法和需求，再给概念，测能否听懂与是否感兴趣 |
| 曾用后停用的人 | 当初为什么试、哪里不满足、何时停、什么会让他回来 |

**不能把四类人混在同一串问题里。** 他们的答案对应完全不同的产品动作。

### 5. 还原经历后，必须加一次操作演示

涉及线上流程、入口、套餐选择、页面信息理解时，除了问回忆，还应邀请用户打开手机演示最近一次操作。

主持人观察点写进大纲：
- 第一反应打开哪个入口
- 是否反复寻找、犹豫或返回
- 选择时看什么信息（价格、期限、权益、自动续费等）
- 哪一步不清楚、下单是否顺畅
- 用户说的体验与实际操作是否一致

**操作演示是观察，不是让用户完成任务。** 不提示路径、不代替用户点击。

### 6. 概念/素材测试分三层，而不是直接问"喜不喜欢"

真实大纲中最有效的顺序：

```
先自由回答 → 再展示概念/页面 → 最后提示备选玩法或方案
```

可分为：
1. **用户自己先说**：现在怎么做、希望改什么、期望看到什么
2. **看概念后**：是否看懂、第一反应、吸引点、顾虑、会在何时使用
3. **看具体素材后**：入口找不找得到、页面信息懂不懂、多个版本选哪个、原因是什么

这样能区分「用户本来就有的需求」和「看了方案才被激发的兴趣」。

### 7. 涉及资金或资产的访谈：先聊钱的用途，再聊产品

不要一上来问"为什么买某产品"。先请用户把手头的钱按用途分一分（近期要花、求稳、长期增值等），再逐类问比例、期限、期待和购买渠道，最后才进入产品选择与购买经历。

这样能判断产品在用户心中的真实位置，而不是只听到产品评价。

## 提纲自检

- [ ] 每个模块能说出它对应哪个研究目标
- [ ] 问题总量与时长匹配（宁少勿多）
- [ ] 主体部分是从宽到窄的漏斗顺序
- [ ] 没有"是不是""会不会""对吧"这类引导句式
- [ ] 敏感问题放在中后段，不在开场
- [ ] 概念测试类：先问现状再给概念，且有复述环节
- [ ] 品牌类：无提示联想在提示评价之前
- [ ] 关键问题配了追问提示
- [ ] 收尾有开放式补充问题
- [ ] 时长分配已标注，且预留了 10% 弹性
- [ ] 已说明主持人可根据用户逻辑调整顺序，不把大纲当逐字稿
- [ ] 有会前问卷时，已标出哪些信息要逐一回访
- [ ] 多业务线研究已设计「先列举/排序，再按行为链深挖」的机制
- [ ] 用户 / 未使用者 / 停用者已分开问
- [ ] 涉及线上流程时已安排手机操作演示，并写清观察点
- [ ] 概念测试遵循「先自由回答 → 再展示 → 最后提示」顺序
