# 要回答的问题怎么写（内部步骤②的核心规范）

业务问题**不能直接跳到大纲或假设**，中间必须经过「要回答的问题 → 每个问题弄清什么」两层。这两层在内部跑，不外露。

```
业务上要做什么决定
    ↓
要回答的问题（3-5 条）    ← 界定这轮弄清什么
    ↓
每个问题弄清什么          ← 对象 + 哪些方面 + 跟谁比
    ↓
产出物（方向清单 / 要看的数字 / 初步判断 / 通过标准）
```

## 「要回答的问题」的写法

「了解…」「勾勒…」「深挖…」「验证…」「摸底…」都是**正确**的句式——**不要**因为句式是"了解 X"就判定有问题，或强行改写成假设句。这一层的职责是**界定边界**，不是给预判。

## 四项检验

| 检验 | 不合格的样子 |
|---|---|
| **边界清楚**（对象、范围可框定） | "了解用户"——哪些用户？了解什么？ |
| **能拆成内容** | "提升满意度"——这是业务目标，不是研究问题 |
| **服务决定**（说得清支撑哪个决定） | "全面了解市场"——了解完要决定什么？ |
| **范围可控**（单条不横跨太多内容） | "了解需求并验证方案并测算规模"——拆成三条 |

## 三种特殊结构的识别（识别后用白话告诉用户处理方式，不说术语）

| 结构 | 长什么样 | 处理 |
|---|---|---|
| **要分开看的人群** | "A 类用户 vs B 类用户在以上方面的差异" | 不是独立内容块——落到"找什么人"的配额里，在每块内容里分开看 |
| **两步走的问题** | "寻找并验证 X 方向" | 拆两步：先找出来，再验证；明确两步的衔接 |
| **要看数字的问题** | "了解认知度和使用率" | 重点是定每个数字怎么问、跟谁比；不硬编假设 |

## 「每个问题弄清什么」的拆法

每个问题拆成 **对象 × 哪些方面 × 跟谁比**，这层就是方案的骨架。常用拆法：

- **对象×方面矩阵**：品牌认知研究的标配（品牌 × 认知/使用/形象）
- **漏斗分级**：从宽到窄逐层（想到→知道→用过→常用→推荐）
- **旅程分段**：行为链研究（触发→找信息→选→用→复购）
- **人群分块**：画像研究（背景→行为→态度→需求）
- **原因拆层**：动机研究（表面原因→深层驱动→触发场景）
