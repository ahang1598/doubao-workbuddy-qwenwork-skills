# 问卷设计

**问卷一旦发出去就改不了。** 上线前的逻辑检查比题目本身更重要。

---

## 结构：四段式

| 段落 | 题量占比 | 干什么 |
|---|---|---|
| **甄别** | 5-8 题 | 筛出符合条件的人，不合格的直接终止 |
| **主体** | 70% | 按研究目标逐块问，从宽到窄 |
| **态度与评价** | 20% | 满意度、意愿、形象等主观题 |
| **背景信息** | 5-8 题 | 人口属性放最后（前置会引起反感和中途退出） |

### 题量与时长

| 目标时长 | 题量 | 说明 |
|---|---|---|
| 5 分钟 | 15-20 题 | 单一目标的快速测量 |
| 10 分钟 | 25-35 题 | 常规配置，多数项目够用 |
| 15 分钟 | 35-50 题 | 上限，再长完成率明显下滑 |
| 20 分钟+ | — | 不建议。拆成两波或改用其他方式 |

**换算参考**：简单单选约 10 秒/题，多选约 20 秒，矩阵量表按行数算（每行 8 秒），开放题 60 秒以上。

**开放题不超过 3 题**，且不要放在最前面。

## 题目写法

### 一题只问一件事

| ✗ | ✓ |
|---|---|
| 您认为产品的价格和质量如何？ | 拆两题分别问价格、质量 |
| 您是否因为方便快捷而选择它？ | 先问选择原因（多选），"方便""快"作为两个独立选项 |

### 选项必须不重不漏

**不重**：选项之间不能有交叉
- ✗ 年龄：18-25 / 25-35 / 35-45（25 和 35 归哪边？）
- ✓ 18-24 / 25-34 / 35-44

**不漏**：所有可能情况都有归处
- 单选题拿不准时加「以上都不是」或「其他（请注明）」
- 频率题要含「从未」这一档

### 中性表述

| 引导性 | 中性 |
|---|---|
| 您有多满意这项贴心的服务？ | 您对这项服务的满意度是？ |
| 大多数用户认为很方便，您觉得呢？ | 您觉得使用起来方便吗？ |
| 您是否同意应该增加 XX 功能？ | 以下功能对您的重要性分别是？ |

### 不用双重否定

- ✗ 您是否不认为这个功能没有必要？
- ✓ 您觉得这个功能有必要吗？

### 量表怎么选

| 量表 | 用在哪 | 注意 |
|---|---|---|
| 5 点 | 满意度、同意度，多数场景够用 | 中间点是"一般" |
| 7 点 | 需要更细的区分度 | 认知负担略高 |
| 10/11 点 | NPS、打分习惯强的场景 | 需说明两端含义 |
| 双向量表 | 态度有正负方向时 | 正负档数必须对称 |

**同一份问卷里量表点数要统一**，混用会让受访者混乱、也不好分析。

**矩阵题一屏不超过 8 行**，超了就拆。行数太多会出现"一路点同一列"的敷衍作答。

## 跳转逻辑（最容易出错的地方）

### 三条铁律

1. **每道题都要能说清"谁会看到它"**
2. **每个分支都要有出口**，不能出现问完就断掉的死路
3. **跳转条件必须互斥且穷尽**——不能有人同时符合两条路径，也不能有人无路可走

### 上线前必须画一遍完整路径图

**不要只看题目文字判断逻辑是否通顺。** 必须逐条走：

```
Q1 单选
 ├─ 选 A → Q2 → Q4
 ├─ 选 B → Q3 → Q4
 └─ 选 C → 终止（不符合条件）

Q4 多选  ← 检查：A 路径和 B 路径的人都能到这里吗？
 ├─ 含 X → Q5 系列
 └─ 不含 X → 跳过 Q5 系列 → Q6   ← 检查：这条路有出口吗？
```

### 逐条自检

- [ ] 每个分支终点都能走到问卷结束或明确的终止页
- [ ] 没有题目是"所有路径都到不了"的（写了但没人看得到）
- [ ] 多选题的跳转条件写清了是"含某项"还是"仅选某项"
- [ ] 甄别终止的条件互斥，不会误杀合格样本
- [ ] 后置题目引用的前置答案，在所有路径下都一定被问过
- [ ] 配额相关的题目在跳转路径上不会被跳过
- [ ] 「其他（请注明）」被选中时，后续逻辑有妥当处理

**常见事故**：Q10 问"您刚才提到的 A 品牌，使用频率是？"——但 A 品牌来自 Q5 多选，有些路径的人根本没看到 Q5。这类错误在纸面上很难看出，必须走路径图。

## 甄别问卷设计

**目的是筛人，不是收集数据。** 越短越好，5-8 题。

**顺序：先问最容易排除的**
```
1. 是否在目标城市
2. 年龄是否在范围内
3. 是否从事敏感职业（同业、市场研究、媒体等 → 终止）
4. 品类使用状况（是否符合本轮定义）
5. 配额相关变量（性别、人群类型等）
6. 近期是否参加过同类调研（3-6 个月内参加过 → 终止）
```

**敏感职业和近期参与必须问**，否则样本质量没保障。

**别在甄别题里暴露想找什么样的人**：
- ✗ 您是否每周使用 XX 产品 3 次以上？（等于告诉对方怎么答能入组）
- ✓ 过去一周，您使用以下各类产品的次数分别是？（把目标项混在多个选项里）

## 特殊题型注意事项

### 品牌认知（顺序不能反）

```
1. 无提示第一提及   —— 不给选项，让用户自己写第一个想到的
2. 无提示其他提及   —— 还想到哪些
3. 提示后认知       —— 出示品牌列表，问听说过哪些
4. 使用过的         —— 用过哪些
5. 当前在用的       —— 现在还在用哪些
6. 主要使用的       —— 最主要用哪个
```

**提示列表必须随机轮换顺序**，固定顺序会让排前面的品牌得分偏高。

### 满意度

- 总体满意度问一次，具体维度分开问
- **总体满意度放在具体维度之前**（先问细项会让用户在总体评分时做加权计算，失真）
- 配一道开放题问原因

### 价格测试

- 不要直接问"你愿意付多少钱"，这个数字不可靠
- 用价格敏感度测试（PSM）的四问法，或给具体价格档位测接受度
- **必须问现在为同类事物实际花了多少**，作为参照

### 排序题

- 待排项不超过 7 个，超过就先让用户选出 top 几再排
- 说明清楚是"从最重要到最不重要"还是反过来

## 从三份真实问卷提炼的执行做法

### 1. 先定义最终要看的漏斗，再倒推题目

品牌、平台、服务研究最稳定的主链路是：

```
无提示想到 → 提示后知道 → 主动了解 → 考虑使用 → 曾经使用 → 近期使用 → 最常用 → 推荐/满意 → 停用或未用原因
```

不是每轮都要全问，但要先确定最终需要哪几级指标，再倒推题目与跳转。**认知、实际使用、满意度不能混在同一题。**

### 2. 无提示回答要先统一编码，再进入统计漏斗

开放题（如"第一个想到什么品牌"）不能直接拿文字做统计。真实执行时应在后台设置**隐藏的统一编码题**：把用户填的别名、简称、错别字归到统一品牌/类别；遇到同名但版本不同的产品，要紧接着追问具体是哪一个版本。

```
无提示填答 → 统一编码（后台）→ 必要时澄清版本 → 最终认知变量
```

这样既保留自发认知，又能得到干净的数据口径。

### 3. 用前题答案决定后题展示内容

这是控制题量、避免无效评价的核心。

| 前题结果 | 后题怎么处理 |
|---|---|
| 没听说任何品牌/功能 | 自动填"以上皆无"并跳过相关评价 |
| 只剩一个近期使用对象 | 自动设为最常用，不让用户重复选 |
| 选过多个对象 | 后题只展示已选对象，让用户选最常用或逐个评价 |
| 没用过目标对象 | 问未用原因 |
| 曾用但近期没用 | 问停用原因 |
| 实际用过某功能 | 才展示该功能的满意度题 |

**规范要写清**：引用来源题号、可引用的选项代码、是否排除"其他/以上皆无"、仅有一项时是否自动圈选、无有效项时跳到哪里。

### 4. 产品/方案测试要控制变量

测试多个方案时，每个方案都要写清：价格、周期、权益内容、额度/规格、领取方式。**同一轮方案尽量一次只改变一个关键变量**，否则用户喜欢或不喜欢的到底是什么无法判断。

展示顺序应随机或轮换；"其他/都不想要"固定在末尾。

### 5. 满意度题要形成闭环

推荐用：总体满意度/推荐意愿 → 根据正负向分流追问原因 → 对实际用过的具体功能做细项评分。

- 推荐意愿可用 0-10 分；高分问推荐什么，低/中分问要改什么
- 细项满意度只面向实际使用者
- 不要只问"满意吗"，要能落到具体功能或服务环节

### 6. 问卷必须有一份独立的逻辑表

正式上线不要只靠 Excel 题面旁的备注。应维护唯一真源，至少包含：

| 字段 | 要写什么 |
|---|---|
| 题号 / 后台变量名 | 二者分开管理，题号可展示，变量名不变 |
| 适用人群（Base） | 谁会看到这题 |
| 题型与选项代码 | 单选/多选/矩阵、每个选项的唯一代码 |
| 随机与互斥 | 哪些随机；"其他/无"是否固定末尾且排他 |
| 引用 | 从哪题引用、引用哪些选项 |
| 跳转 | 条件表达式 + 去向 |
| 校验 | 是否必答、文本格式、回看提示 |
| 版本备注 | 草稿修改留这里，**不能留在正式题面** |

### 7. 样本控制不能只收画像题

性别、年龄、城市、使用频率等题可以用于分析，**但不等于已经有配额控制**。投放前还要单独写：总样本、每层最低样本、满额后怎么处理、是否加权。

产品测试类尤其要保证核心人群有足够样本，例如既有购买意愿、又确实遇到相关场景的人。

**样本量基线**：以选择题、评分题为主的问卷，总样本 **300 份起**——低于这个量，交叉格子和分层对比撑不住。开放题为主的 AI 访谈另按 30 份口径（见 `ai-interview-outline.md`）。

### 8. 有后续访谈招募时，联系方式单独收

抽奖、后续访谈、其他联络授权不要在不同题里重复收联系方式。更好的做法是问卷末尾统一设置联络授权页，让用户分别勾选"愿意参加访谈""愿意参加抽奖"，并说明用途、奖励和退出方式。

## 完整自检清单

**题目层面**
- [ ] 一题只问一件事
- [ ] 选项不重不漏，单选题有兜底选项
- [ ] 无引导性表述、无双重否定
- [ ] 量表点数全卷统一
- [ ] 矩阵题每屏不超过 8 行
- [ ] 开放题不超过 3 题且不在开头
- [ ] 专业术语已换成用户能懂的说法

**结构层面**
- [ ] 人口属性题在最后
- [ ] 敏感问题（收入、隐私）在中后段
- [ ] 品牌题：无提示在提示之前
- [ ] 满意度：总体在细项之前
- [ ] 品牌/选项列表已设随机轮换

**逻辑层面**
- [ ] 完整路径图已画并逐条走通
- [ ] 每个分支有出口，无死路
- [ ] 跳转条件互斥且穷尽
- [ ] 无孤岛题目（无人可达）
- [ ] 后置题引用的前置答案在所有路径下必定存在
- [ ] 配额题不会被跳过
- [ ] 已明确：前题仅一项时是否自动圈选；前题无有效项时跳到哪里
- [ ] 所有引用题写清来源题号、可引用选项代码，以及是否排除"其他/以上皆无"
- [ ] 已建立独立逻辑表（题号/变量/Base/代码/随机/互斥/引用/跳转/校验），不只依赖题面备注
- [ ] 正式版本无"新增/删除/待确认/顺序调整"等草稿残留

**甄别层面**
- [ ] 敏感职业已排除
- [ ] 近期参与同类调研已排除
- [ ] 未暴露目标人群条件
- [ ] 终止条件不会误杀合格样本

**样本与整体**
- [ ] 已有单独配额表：总样本、各层最低样本、满额后的处理与是否加权
- [ ] 画像变量与实际配额口径可一一映射
- [ ] 预估时长与目标一致（已按题型换算）
- [ ] 每道题能追溯到某个研究目标，无冗余题
- [ ] 已找 2-3 人试填并记录卡顿处
