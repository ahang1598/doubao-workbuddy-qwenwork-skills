# 工作流详细步骤

## Phase 0: 输入验证

**[SCRIPT CALL: validate_input]**

1. 检查round_agreements是否提供且至少含1轮协议
2. 检查company_registration是否提供注册资本/股东/持股比例
3. 检查各轮协议是否含必要字段（轮次/投资额/估值/新发股数/日期）
4. 数据完整性校验：实缴数据缺失→按认缴计算并标注；日期缺失→追问

**输入模式识别**：
- Mode A（文件上传）：用户提供历轮SPA文档+工商登记截图/PDF
- Mode B（结构化输入）：用户直接提供JSON/YAML格式的历轮数据+工商登记数据
- Mode C（自然语言描述）：用户口述历轮融资历程+工商登记概况→追问补全

## Phase 1: 历轮数据提取

**[SCRIPT CALL: round_data_extractor]**

### 步骤

1. 解析各轮SPA/增资协议/股权转让协议
2. 提取每轮关键数据：
   - 轮次名称（设立/A轮/B轮/...）
   - 融资类型（增资/转让/期权池设立/可转债转股/股改）
   - 日期（协议签署日/交割日）
   - 投资额/估值/新发股数/转让股数/每股价格
   - 投资人信息（姓名/机构/投资类型）
   - 特殊条款（反稀释/优先清算/参与权/转换权）
3. 按时间顺序排列各轮

### 关键词清单（提取检查点）

| 协议类型 | 须提取的关键信息 |
|----------|------------------|
| 增资协议 | 投资额/估值/新发股数/每股价格/交割日/优先权利条款 |
| 股权转让协议 | 转让方/受让方/转让股数/转让价格/转让日期 |
| 期权池设立决议 | 池比例/池总量/授权主体/行权安排 |
| 可转债协议 | 本金/利率/转换价/转换折扣/到期日/转换触发条件 |
| 股改决议 | 基准日/审计净资产/折股比例/折合股数 |
| 代持协议 | 显名股东/隐名股东/代持比例/代持原因/解除条件 |

### 数据流

→ 输出至Phase 2：历轮结构化数据表（含所有轮次的关键参数）

## Phase 2: 股权变动重建 [L2]

**[SCRIPT CALL: cap_table_calculator]**

### 步骤

1. 从公司设立开始（初始注册资本/创始股东持股）
2. 逐轮计算：
   - **增资轮**：新发股数→各股东持股比例稀释→注册资本增加
   - **转让轮**：转让股数→转让方与受让方持股变动→总股数不变
   - **期权池设立/扩大**：预留比例→各股东稀释→池内授予/未授予分别标注
   - **可转债转股**：转换股数=本息/转换价→各股东稀释→总股数增加
   - **股改**：折股比例换算→持股比例通常不变→每股价格变动
3. 特殊处理：
   - **代持还原**：识别代持关系→拆分名义与实际持股→重建还原后Cap Table
   - **持股平台穿透**：判断是否穿透→穿透至最终自然人或标注平台整体
4. 得到当前Cap Table

### 检查点

| 检查项 | 不达标信号 | 纠正动作 |
|--------|------------|----------|
| 股数守恒 | 各轮总股数不连续 | 追查差额来源 |
| 比例合计 | 各轮比例合计≠100% | 重新计算 |
| 优先股标注 | 未区分优先股/普通股 | 按协议标注持股类型 |
| 代持标注 | 存在代持但未还原 | 补充代持协议→还原 |

### 数据流

→ 输出至Phase 3：当前Cap Table（完整持股结构表）
→ 输出至Phase 4（如需模拟）：基准Cap Table

## Phase 3: 工商登记交叉验证 [L2]

**[SCRIPT CALL: variance_checker]**

### 步骤

1. 将Phase 2计算结果与工商登记数据逐项对比：
   - 注册资本是否一致
   - 股东名单是否一致
   - 各股东持股比例是否一致
   - 实缴出资是否一致
2. 标注差异（每项差异标注：计算值/工商值/差异值）
3. 分析差异原因：
   - **登记延迟**：增资/转让已完成但未及时工商变更
   - **代持未还原**：工商显示名义股东，实际为代持
   - **期权池未登记**：期权池在工商层面未反映
   - **计算口径不同**：计算含/不含期权池与工商口径差异
   - **计算错误**：重新核对计算
4. 输出差异报告+待核查项

### 检查点

| 检查项 | 不达标信号 | 纠正动作 |
|--------|------------|----------|
| 差异分析完整 | 差异未分析原因 | 逐项标注原因 |
| 待核查项标注 | 差异未列待核查 | 补充建议核查来源 |

### 数据流

→ 输出至Phase 5：工商差异报告

## Phase 4: 稀释模拟（如需） [L2]

**[SCRIPT CALL: dilution_simulator]**

### 步骤

1. 输入假设融资参数（投前估值/投资额/新发比例）
2. 检查是否需要期权池刷新（Top-up）：
   - 如需扩大期权池→先计算期权池扩大的稀释→再计算新发稀释
   - 如不需要→直接计算新发稀释
3. 计算各股东稀释后持股比例：
   - 无Top-up：稀释后 = 原比例 × (1 - 新发比例)
   - 有Top-up：稀释后 = 原比例 × (1 - 池扩大比例) × (1 - 新发比例)
4. 输出稀释前后对比表

### 检查点

| 检查项 | 不达标信号 | 纠正动作 |
|--------|------------|----------|
| Top-up处理 | 期权池扩大但未先稀释 | 先计算池扩大→再计算新发 |
| 新发比例 | 新发比例≠投资额/(投前估值+投资额) | 重新计算 |
| 比例合计 | 稀释后比例合计≠100% | 重新计算 |

### 数据流

→ 输出至Phase 5：稀释模拟结果表
→ 输出至Phase 4b（如降价融资）：基准稀释数据

## Phase 4b: 反稀释调整（如需） [L3]

**[SCRIPT CALL: anti_dilution_calculator]**

### 步骤

1. 判断是否触发反稀释：新轮估值 < 前轮估值→触发
2. 按反稀释方式计算调整价：
   - **加权平均法**：调整价 = (已发×原价 + 新发×新价) / (已发 + 新发)
   - **完全棘轮法**：调整价 = 新发价格
3. 计算调整后持股数 = 原投资额 / 调整价
4. 计算额外股数 = 调整后持股数 - 原持股数
5. 调整创始人持股（额外股数从反稀释补偿方调给投资人）
6. 输出调整后Cap Table

### 检查点

| 检查项 | 不达标信号 | 纠正动作 |
|--------|------------|----------|
| 反稀释方式标注 | 未标注加权平均/完全棘轮 | 按协议标注 |
| 调整价计算 | 加权平均公式有误 | 重新计算 |
| 额外股数来源 | 未标注从何方调整 | 标注补偿方（通常为创始人） |
| 总股数不变 | 调整后总股数变化 | 反稀释不增发新股，仅调整持股 |

### 数据流

→ 输出至Phase 5：反稀释调整方案表

## Phase 5: 报告组装

### 步骤

1. 组装五段式输出：
   - ①历轮股权变动表（来自Phase 1+2）
   - ②当前Cap Table（来自Phase 2）
   - ③工商差异报告（来自Phase 3）
   - ④稀释模拟结果（来自Phase 4，如需）
   - ⑤反稀释调整方案（来自Phase 4b，如需）
2. 附加免责声明
3. 附加待核查项清单（所有需律师进一步核实的事项）
4. 附加清算优先权瀑布分析（如协议中含优先清算权条款）

### 自检清单

| # | 检查项 | 不达标信号 | 纠正动作 |
|---|--------|------------|----------|
| 1 | 历轮完整 | 遗漏轮次 | 补充缺失轮次数据 |
| 2 | 计算准确 | 持股比例合计≠100% | 重新计算 |
| 3 | 差异分析 | 未分析工商差异 | 补充差异分析 |
| 4 | 稀释模拟 | 未计算稀释后比例 | 补充稀释计算 |
| 5 | 反稀释标注 | 未标注调整方式 | 按协议标注 |
| 6 | 来源文件标注 | 未标注各数据来源 | 补充来源标注 |
| 7 | 计算精度 | 未保留四位小数 | 统一保留四位小数 |
| 8 | 期权池处理 | 期权池未单列 | 拆分授予/未授予 |
| 9 | 穿透验证 | 持股平台未穿透判断 | 标注穿透/不穿透+理由 |
| 10 | 代持还原 | 代持未还原或未标注 | 还原或标注待核实 |
| 11 | 免责声明 | 缺失 | 补充标准免责声明 |
| 12 | 绝对化禁用词 | 使用保证/必然等 | 替换为限定表述 |
