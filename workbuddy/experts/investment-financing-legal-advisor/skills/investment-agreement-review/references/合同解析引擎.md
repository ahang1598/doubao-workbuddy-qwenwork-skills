# 合同解析引擎（底座）

> 合并自：contract-parse + verify-cite（基础设施层）

## 功能

将投资协议（PDF/Word，中/英）解析为结构化JSON，供所有下游子流程使用。

## 解析输出结构

```json
{
  "clauses": [{"id": "3.1", "number": "3.1", "level": 2, "title": "回购权", "text": "..."}],
  "definitions": [{"term": "合格IPO", "definition": "..."}],
  "cross_refs": [{"from": "3.1", "to": "8.2"}],
  "parties": [{"name": "...", "role": "投资方"}],
  "stats": {"total_clauses": 42, "max_depth": 4},
  "intake": {"filename": "...", "language": "zh", "pages": 18}
}
```

## 引用校验（verify-cite）

横切所有子流程：每个结论/修改必须有原文锚点。校验项：
- 编号序列（无重复编号/子级前缀一致）
- 交叉引用（无悬空引用）
- 定义（无重复定义/引用有定义）
- 金额（定义值与正文引用值匹配）

锚点状态：[已溯源] / [需人工确认]——后者不阻塞但标注不可省略。

## 脚本现状

当前 `scripts/` 目录仅含 `sync_engine.py`（功能：将共享内核引擎从 SSOT 物化至本技能包，支持 `--check` 模式校验一致性）。该脚本依赖工作区 `_shared/contract-review-core/scripts/` 路径，若该路径不存在则无法运行。

合同解析引擎（PDF/Word→结构化JSON）和引用校验引擎（verify-cite）部分当前为方法论设计，尚未落地为独立可运行脚本。依赖待补：待 `_shared/contract-review-core` 基础设施完善后，通过 `sync_engine.py` 物化 `ooxml_engine.py` 和 `pdf_intake.py` 至本技能包。

## 脚本纪律

所有HTTP/文件操作须通过 `scripts/` 下预置脚本，严禁自行编写替代脚本。脚本不存在时标注"脚本待补"，不虚构能力。
