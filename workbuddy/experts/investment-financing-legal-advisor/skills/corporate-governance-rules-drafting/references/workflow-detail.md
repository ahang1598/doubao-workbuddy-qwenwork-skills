
## 渐进式生成链

> 遵循 P2→P3→P4 "规划→草稿→精修"链式依赖，禁止三重独立生成。

| Phase | 产出物形态 | 增量内容 | 禁止 |
|:---|:---|:---|:---|
| **P2 结构规划** | 章节大纲（章节标题+每节关键要点≤20字/项+模板选择） | 不生成完整条文 | ❌ 禁止在P2即输出完整制度文本 |
| **P3 草稿填充** | 基于P2大纲的完整条文草稿 | 各章节完整条款、法条引用填充 | ❌ 禁止脱离P2大纲重新规划 |
| **P4 精修核验** | 基于P3草稿的精修文本 | 语言打磨、法条核验、红线校对 | ❌ 禁止从零重新生成条文 |

**链式依赖**：P2产物→P3输入 / P3产物→P4输入。后续Phase必须显式引用前一Phase的产出。

## Phase 0：交互前置与信息收集

**[前置步骤，编号为Phase 0但不计入主流程Phase序号]**

### 执行顺序（不可调换）

```
① 路由边界检查 → 不在本技能范围？→ 路由到目标技能（不展示配置卡）
  └→ 在范围内 ↓
② 参数提取与推断（推断规则表 + 置信度标注）
  └→ 同时判定 Mode A / Mode B ↓
③ 计算 gap_score
  ├→ gap=0 且全部 high + FAST_TRACK → 直通 Phase 1
  ├→ gap=0 且全部 high → 一行确认"已理解：{公司形式}·{企业规模}·{起草目标}。是否开始起草？"
  ├→ gap=0 但有 medium/low → 预填配置卡（⚠️标注低置信度项）
  └→ gap>0 → 展示配置卡（预填✅/⚠️/缺失❗）
```

### 步骤①：路由边界检查（🔴 必须在参数收集之前执行）

判定用户诉求是否在本技能范围内。判断依据参见 SKILL.md 模块5的"不适用（转对应技能）"表。

**禁止行为**：
- ❌ 禁止在路由边界判定前展示配置卡
- ❌ 禁止在路由边界判定前提取参数
- ❌ 禁止对"股权架构设计""章程起草"等不在本技能范围的诉求展开

**判定为不在本技能范围时的响应模板**：
```
您提到的{诉求要点}不在本技能范围内（本技能专注三会议事规则的起草与审查优化）。

建议转至：{推荐技能名称}
是否需要我帮您切换到该技能？
```

### 步骤②：参数提取与推断

基于以下推断规则表，从用户输入中提取/推断参数，标注置信度。

**Mode A 参数推断完整规则表**：

| 原始输入信号 | 推断参数 | 置信度 | 条件/注意事项 |
|:---|:---|:---:|:---|
| "初创/刚成立/天使轮/A轮/几个股东/几个人" | 规模=初创 | medium | 多人团队≠初创，注意交叉验证 |
| "AB轮/发展期/几十人/百来人/快速增长" | 规模=成长型 | medium | 与"初创"信号矛盾时取后出现的 |
| "拟IPO/上市/证监会辅导/几百人/千人" | 规模=成熟/拟上市 | medium | — |
| "有限公司/有限责任/某某有限公司" | 公司形式=有限公司 | high | 不含"股份"关键词 |
| "股份公司/股份有限公司/某某股份公司" | 公司形式=股份公司 | high | — |
| 未提及公司形式 | 公司形式=有限公司（默认推断） | low | 必须标注 low + 提醒用户确认 |
| "一人/独资/唯一股东/全资" | 公司形式=一人公司 | high | 如有"董事会"信号矛盾→标记冲突 |
| "股东会/股东大会/股东开会" | 起草目标=股东会 | high | — |
| "董事会/董事/董事开会/董事表决" | 起草目标=董事会 | high | — |
| "监事会/监事/监事开会" | 起草目标=监事会 | high | — |
| "三会都要/都需要/全套" | 起草目标=三会一起 | high | — |
| "智能制造/SaaS/跨境电商/食品加工"等 | 行业标签（非必填，辅助专业术语） | medium | 不影响路由 |
| 无规模信号 | 无法推断，留空 | — | gap_score+1 |
| 无起草目标信号 | 无法推断，留空 | — | gap_score+1 |

**Mode A/B 自动判定规则**：

| 输入特征 | 判定结果 | 置信度 |
|:---|:---|:---:|
| 用户粘贴了 >300字的制度文本 | Mode B | high |
| 用户上传了 .doc/.docx 文件（文件名含"议事规则/制度"） | Mode B | high |
| "审查/看一下/有没有问题/看看/校校/检查/过时"等关键词 + 原始文本 | Mode B | medium |
| "起草/写/生成/新建/帮做"等关键词 + 无文本 | Mode A | high |
| 仅有需求描述，无任何文本 | Mode A（默认） | high |

**Mode B 自动识别参数**：

| 自动识别项 | 识别方式 | 置信度 |
|:---|:---|:---:|
| 制度类型（股东会/董事会/监事会） | 从原始文本标题或内容关键词匹配 | medium（标题匹配→high） |
| 审查重点（更新/合规/表述/完整性） | 从用户指令关键词匹配："新公司法/2023/换法"=更新；"合不合规"=合规性；"语言/表述/术语"=表述质量；"缺/没有"=完整性补全 | medium |
| 公司形式 | 从原始文本或用户描述推断（同Mode A推断规则） | 同Mode A |

### 步骤③：gap_score 计算

**Mode A gap_score** = 3（公司形式 + 企业规模 + 起草目标）− 已提取的参数数量

**Mode B gap_score** = 更宽松（最低只需制度文本即可运行，参数缺失不阻断）

**三级处理详述**：

| gap | 置信度 | 具体动作 | 用户看到什么 |
|:---|:---|:---|:---|
| **0 / all high / FAST_TRACK** | 全部 high + 有限公司+初创+单份制度 | **直通**，不做任何交互 | 直接进入 Phase 1，用户不需要额外操作 |
| **0 / all high** | 全部 high | 一行确认（不展示完整配置卡） | "已理解：有限公司·成长型·董事会。是否开始起草？" |
| **0 / mixed confidence** | 存在 medium/low | 预填配置卡 | 字段已填推断值 + low置信度项标⚠️ + "以上推断是否正确？可直接修改" |
| **1–2** | 不限 | 配置卡 | 已填项✅ / 低置信预填⚠️ / 缺失标❗ + 用户一次补全修改 |
| **≥3** | — | 空白配置卡 or SOFT_DEGRADED | 全部标❗；用户选"先出草稿"→触发 SOFT_DEGRADED（C+D+G） |

### 配置卡展示规格

**一张卡，两套字段集**：

```
Mode A 配置卡：
┌────────────────────────────────────────┐
│ ① 公司形式： ○一人公司  ○有限公司  ○股份公司 │
│ ② 企业规模： ○初创≤20人  ○成长型  ○成熟/拟上市 │
│ ③ 起草目标： ○股东会  ○董事会  ○监事会  ○三会一起 │
│ 可选标记：   □上市公司  □外资/国企             │
│                                     │
│            [ 确认开始 ]                    │
└────────────────────────────────────────┘

Mode B 配置卡：
┌────────────────────────────────────────┐
│ 制度类型（已自动识别）：[董事会 ▼] ←可修正    │
│ ① 公司形式： ○有限公司  ○股份公司  ○一人公司  │
│ 审查重点（可多选）：                       │
│   ☑条文更新(2018→2023)  ☑合规性  ☑表述质量  ☑完整性补全 │
│ 可选标记：   □上市公司  □外资/国企             │
│                                     │

```

### Phase 0 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 0-0 | 🔴 路由边界已检查 | 未在参数提取前执行路由边界检查→暂停，回退执行 | L1 |

## Phase 2：结构规划（P2）

> **Mode B 跳过此Phase**（Mode B 直接进入 Mode B 专属步骤）

### 执行逻辑

1. 读取已加载的模板骨架文件，提取章节结构
2. 根据治理复杂度阶梯确定章节数量：
   - 精简版：5-6章（省略决议执行跟踪章、股东权利行使章等）
   - 标准版：7-9章
   - 完整版：10-11章
3. 基于模板骨架生成**章节大纲**（每章标题+3-5个关键要点，每要点≤20字）
4. 标注条件性条款（有限公司/股份公司差异、一人公司裁剪点）

### Phase 2 产出格式

```markdown
## 章节大纲（{制度类型}·{复杂度}版）

### 第一章 总则
- 要点1: 制定目的与依据（公司法第X条+章程）
- 要点2: 适用范围（全体股东/董事/监事）
- 要点3: 与章程关系（章程优先）

### 第二章 职权
- 要点1: 法定职权（引用法条编号，不复述全文）
- 要点2: 章程授予的其他职权
...
```

### Phase 2 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 2-1 | 章节数量与复杂度阶梯匹配 | 精简版>6章→裁剪；完整版<10章→补充 | L2 |
| 2-2 | 七段骨架全部覆盖 | 缺任一段→补充对应章节 | L1 |
| 2-3 | 有限公司/股份公司条件性条款已标注 | 未标注→补充标注 | L2 |
| 2-4 | 一人公司裁剪点已标记 | 未标记→补充 | L1 |

## Phase 3：草稿填充（P3）

> **Mode B 跳过此Phase**

### 执行逻辑

1. **基于 Phase 2 的章节大纲**，逐章填充完整条款
2. 每章按照模板骨架中的"必含条款"+"条件性条款"写入
3. 嵌入法律底线清单中的红线约束（不可突破的法定人数/比例等）
4. 企业未提供的参数用 `{参数名}` 占位，不可凭空编造

### Phase 3 关键规则

- **法条引用方式**：引用法条编号（"依据《公司法》第X条"），不复述法条全文
- **待确认参数显式标注**：`{董事会人数}`、`{授权金额上限}` 等
- **条件性条款按公司类型写入**：股份公司写通知≥20日，有限公司写≥15日
- **一人公司裁剪**：跳过不适用章节，在输出中说明裁剪理由

### Phase 3 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 3-1 | 每章条款与P2大纲一致 | P2有但P3缺→补充；P3有但P2无→删除 | L2 |
| 3-2 | 红线条款已嵌入 | 缺任一红线→补充 | L1 |
| 3-3 | 法条编号全部为2023版 | 出现2018旧编号→按source-trace映射表更新 | L1 |
| 3-4 | 无凭空编造的参数 | 出现未标注占位的具体数值→替换为占位 | L2 |
| 3-5 | 有限公司/股份公司差异已正确写入 | 差异未写入→补充 | L2 |

## Phase 4：法律核验与精修（P4）

> **Mode A 和 Mode B 共用**

### 执行逻辑

1. **基于 Phase 3 草稿**（Mode A）或 **Mode B 优化后文本**，执行法律核验
2. 逐条对照法律底线清单6类红线，标注违规项
3. 逐条对照 source-trace.md 编号映射表，标注过期条文
4. 语言精修：消除绝对化表述、统一条款编号体系、确保条款间无矛盾
5. 核验结果写入输出末尾的"核验链接"小节

### 定向查询与法条检索（强制执行，§17.15 契约）

**检索调用链**（按顺序执行，任一环节成功即停止）：
1. **优先**：`fadada-legal-info-search` 检索法条原文
2. **备选**：`fadada-legal-info-search` 无结果 → `fadada-web-search` 检索
3. **降级**：两次检索均失败 → 标记 `legal_retrieval_failed`，该法条降级为「待核查」，触发 SOFT_DEGRADED

**法条来源标注格式**（仅 O2 核验链接，不写入 O1 正文）：
```
[来源:检索 | 检索工具:xxx | 检索时间:YYYY-MM-DD]
```
示例（O2 核验链接中）：`第69条 [来源:检索 | 检索工具:fadada-legal-info-search | 检索时间:2026-06-03]`

> **关键规则**：O1 制度文件正文（DOCX/MD）中不出现任何 `[来源:检索|...]` 标注——O1 是直接可打印交付客户的制度文件。来源标注全部集中于 O2 风险提示的"核验链接"小节。

**定向查询补充**：
- 先读取 `references/trusted-data-sources.md`，按问题选择官方源
- 法条核实：国家法律法规数据库 https://flk.npc.gov.cn/
- 输出末尾须有"核验链接"小节：`[来源:检索 | 检索工具:xxx | 检索时间:YYYY-MM-DD]`

### Phase 4 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 4-1 | 法律底线6类红线逐条通过 | 任一红线违反→修正 | L1 |
| 4-2 | 法条编号全部为2023版 | 仍有旧编号→更新 | L1 |
| 4-3 | 无绝对化禁用词 | 出现"保证/必然/100%"→替换 | L2 |

## Mode B 专属步骤

> 在 Phase 1 之后、Phase 4 之前执行，替换 Phase 2-3。

### 步骤B1：解析原始制度

1. 用户提供原始议事规则文本（粘贴或DOCX）
2. 提取章节结构，标注原始制度的章节标题和条款内容
3. 判定原始制度是股东会/董事会/监事会议事规则

### 步骤B2：逐段比对

1. 按七段骨架（召集→通知→人数→表决→记录→回避→执行跟踪）将原始制度分解为对应段落
2. 逐段比对：标注"已有且合规"/"已有但过期"/"缺失"/"表述模糊"
3. 逐条对照 `source-trace.md` 的2018→2023编号映射表，标注过期条文
4. 逐条对照 `legal-baseline.md` 的6类红线 + 违规后果矩阵，标注违规项及严重度

### 步骤B3：生成变更清单

输出"变更对比清单"（MD格式）：

| # | 原条文 | 建议修改 | 修改理由 | 法条依据 | 严重度 |
|:---|:---|:---|:---|:---|:---|
| 1 | ... | ... | ... | 公司法§X | 🔴阻断 |

额外输出：
- 过期条文清单（2018→2023编号对照）
- 缺失章节清单（对照七段骨架标注）

### 步骤B4：生成优化后全文

基于变更清单，在原始制度上执行修改，输出优化后全文。

> 优化后全文进入 Phase 4（法律核验与精修）。

## 复杂度分层

| 复杂度 | 触发条件 | 流程简化 |
|:---|:---|:---|
| **SIMPLE** | 单份制度 + 初创企业 + 有限公司 + 信息齐全 | Phase 2-3合并（规划+草稿一步完成） |
| **STANDARD** | 单份制度 + 成长型/成熟企业 | 全流程 |
| **COMPLEX** | 三会一起 / 股份公司+拟上市 / Mode B含多项违规 | 全流程 + 三会间一致性交叉检查 |

### FAST_TRACK 快速通道（SIMPLE 子集）

当满足以下全部条件时，进入 FAST_TRACK：

| # | FAST_TRACK 触发条件 | 判定标准 |
|:---:|:---|:---|
| FT-1 | 3项必填参数全部明确 | 无任何占位参数 |
| FT-2 | 有限公司 + 初创型（≤20人） | 精简版颗粒度 |
| FT-3 | 单份制度（非三会一起） | 仅加载1份模板骨架 |
| FT-4 | 无特殊治理需求（如拟上市/外资/国企） | 标准法律基线即可 |

**FAST_TRACK 流程简化**：

| 原Phase | FAST_TRACK处理 | 跳过原因 |
|:---|:---|:---|
| Phase 0 | 正常执行 | 信息已齐全，仅确认 |
| Phase 1 | 正常执行 | 模式识别不可省略 |
| Phase 2-3 | **合并**为一步：直接基于模板骨架生成精简版草稿 | 初创+有限公司→精简版（5-6章），结构与骨架高度一致，无需先规划再填充 |
| Phase 4 | **简化**为红线速检：仅检查法律底线6类红线+法条编号 | 初创企业无复杂治理需求，无需逐条精修 |
| Phase 5 | 正常执行 | 终检不可省略 |

### 三会间一致性交叉检查（COMPLEX 专属）

当用户要求"三会一起"起草时，逐份生成完毕后，须执行以下交叉检查：

| # | 交叉检查项 | 说明 | 风险等级 |
|:---:|:---|:---|:---:|
| X1 | 授权链条一致性 | 股东会授权董事会→董事会授权总经理，金额不矛盾 | L1 |
| X2 | 职权分配无重叠 | 同一事项不可同时出现在两份制度的职权条款中 | L1 |
| X3 | 通知期限对齐 | 股东会≥15/20日→董事会章程自定→监事会章程自定，三份制度的通知章不矛盾 | L2 |
| X4 | 利害回避规则对齐 | 三份制度的回避范围/后果/后续机制表述一致 | L2 |
| X5 | 表决基数互不矛盾 | 如董事辞职补选的"原编制人数"在三份制度中定义一致 | L2 |
| X6 | 附则生效条件一致 | 三份制度的施行日期、审批机构不矛盾 | L2 |
| X7 | 一人公司裁剪一致性 | 若一人公司→三份制度的裁剪逻辑互不矛盾 | L1 |
| X8 | 术语定义统一 | "关联关系""近亲属""重大事项"等术语在三份制度中定义一致 | L2 |
