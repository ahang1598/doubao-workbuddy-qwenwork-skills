## §内容规格

### Mode A 起草输出结构

制度文件固定**7项输出块**结构（与"七段程序法骨架"不同——后者指制度正文的7个程序段：召集→通知→人数→表决→记录→回避→执行跟踪），每次生成都必须包含以下全部输出块：

```
1. 文件名称
   ├── 格式：{公司全称}{制度类型}议事规则
   ├── 示例：深圳某科技有限公司董事会议事规则
   └── 版本标注：版本V1.0 | {YYYY年MM月DD日}

2. 适用范围
   ├── 适用主体：{公司全称}全体股东/董事/监事
   ├── 适用事项：股东会/董事会/监事会的召集/召开/审议/表决/记录
   └── 排除：不适用于经营层日常办公会议

3. 法律依据
   ├── 上位法：2023年修订《中华人民共和国公司法》（2024.7.1施行）第X条至第Y条
   ├── 章程依据：{公司全称}公司章程（第X章第Y条）
   └── 行业依据（条件输出）：{《上市公司治理准则》等（如适用）}

4. 核心条款（按模板骨架展开，章节数取决于治理复杂度阶梯：精简版5-6章/标准版7-9章/完整版10-11章）
   ├── 第一章 总则
   ├── 第二章 职权
   ├── 第三章 股东权利行使/召集程序
   ├── 第四章 通知
   ├── 第五章 出席
   ├── 第六章 表决
   ├── 第七章 记录
   ├── 第八章 利害回避/履职保障
   ├── 第九章 决议执行与跟踪（精简版可省略）
   └── 第X章 附则

5. 生效与修订程序
   ├── 审议机构：经{股东会/董事会}审议通过后施行
   ├── 决议比例：{普通决议过半数 / 特别决议2/3}
   └── 修订程序：修订须经{审议机构}审议通过

6. 风险提示
   ├── 待确认的企业参数（如：董事会人数未提供→以{假设值}起草，待确认）
   ├── 需向客户核实的治理现状（如：是否有职工董事/是否有类别股）
   └── 制度施行后的监督要点

7. 待核事项
   ├── 待律师复核: {法条引用准确性/章程一致性/行业监管合规}
   └── 待客户确认: {企业规模颗粒度选择/具体企业参数}
```

### Mode B 审查优化输出结构

在Mode A 7段基础上，额外增加：

```
8. 变更说明（Mode B 独有，MD格式）
   ├── 变更对比清单（表格形式）
   │   ├── 原条文（逐条引用）
   │   ├── 建议修改（改写后条文）
   │   ├── 修改理由（法条依据 + 实务理由）
   │   └── 严重度（阻断/警告/建议）
   ├── 过期条文清单（2018公司法编号→2023新编号）
   └── 缺失章节清单（对照七段骨架标注）

9. 修订标注（嵌入DOCX正文）
   ├── DOCX全文开启"修订模式"或新增"修订说明"页
   └── 修订说明须包含：
       ├── 修订依据：2023新公司法（2024.7.1施行）
       ├── 修订要点摘要（3-5个核心修改）
       └── 修订日期 + 修订人（律师姓名）
```

### 写作约束

| 约束 | 说明 |
|:---|:---|
| 法条引用禁止模糊化 | 不可写"依据公司法相关规定"，必须标注具体条文编号 |
| 条文编号统一为2023版 | 不可混用2018版旧编号（对照source-trace.md映射表） |
| 待确认参数显式标注 | 企业未提供的参数用`{参数名}`占位，不可凭空编造 |
| 一人公司须裁剪 | 不设董事会/监事会→不生成对应制度，明确告知理由 |
| 不可写"保证合规" | 制度文件是内部管理文件，审核机构（股东会/董事会）审议通过前不具效力 |
| 禁止emoji | 所有输出格式（MD/DOCX）一律不使用emoji |
| 附件不作为编号条款 | 表决票样张/委托书格式/申报表等配套材料不编为"第X条"，不在正文中逐项列举；如需提示，在风险提示中说明"建议另行准备XX配套文件" |

### SOFT_DEGRADED 降级产物结构

当触发 SOFT_DEGRADED 降级时，输出以下最小骨架（不输出完整制度文件）：

```markdown
[SOFT_DEGRADED] 缺失信息：{列出缺失项}

## C块：待补充信息清单

| # | 缺失参数 | 影响的输出部分 | 补充后升级方式 |
|:---:|:---|:---|:---|
| 1 | 公司类型 | 决定治理结构（一人公司不设董事会/监事会） | 提供公司类型→重新执行Phase 1 |
| 2 | 企业规模 | 决定制度颗粒度（精简/标准/完整版） | 提供企业规模→重新执行Phase 2 |

## D块：法律底线摘要

- 2023年修订《公司法》（2024.7.1施行）为法律基线
- 股东会：§62-67 / 董事会：§68-75 / 监事会：§78-83
- {根据已知信息列出适用的法律底线}
- {根据已知信息列出不适用的声明，如"一人公司不设董事会"}

## G块：下一步行动

1. 提供{缺失参数1}→可重新生成完整制度文件
2. 提供{缺失参数2}→可确定制度颗粒度
3. 确认公司章程中的相关条款→确保制度与章程一致
4. 如有现有制度文本→可切换为Mode B审查优化
```

## §交付规格

### format_capabilities（§17.18 视觉输出标准契约）

| 能力 | 说明 |
|:---|:---|
| 输出格式 | Markdown（会话内预览）→ DOCX（主交付物）→ PDF（可选） |
| HTML转换 | 支持 HTML→DOCX/PDF 转换路线（预留） |
| 排版严肃度 | O1（制度文件）= C-Professional（正式公文级）/ O2（风险提示+变更说明）= I-Practical（实务参考级） |
| 打印适配 | A4纵向，页边距兼容主流打印机，三线表不跨页 |
| CSS模板 | 预留 `templates/docx-style.css`（当前不使用，声明能力预留） |

### default_output

| 输出块 | 格式 | 严肃度 | 说明 |
|:---|:---|:---|:---|
| **O1** 制度文件全文 | DOCX（主）/ MD（辅） | C-Professional | 封面+目录+正文+签署页+保密声明 |
| **O2** 风险提示+待核事项+变更说明 | MD | I-Practical | 实务参考，附于制度文件之后 |

### 产物复用关系（§17.25 产物复用契约）

| 输出产物 | 复用的中间产物 | 复用方式 |
|:---|:---|:---|
| O1 制度文件全文 | P3 草稿全文 | O1 = P4精修后的P3草稿（语言打磨+法条核验+红线校对），禁止从零重新生成 |
| O2 风险提示 | P0 输入解析（缺失参数清单） | 直接复用P0的gap_score和缺失参数清单，转为"待确认"提示 |
| O2 待核事项 | P4 法律核验结果 | 直接复用P4的核验未通过项，转为"待律师复核/待客户确认" |
| O2 变更说明（Mode B） | 步骤B3 变更清单 | 直接复用B3的变更对比清单，格式化输出 |

> **禁止**：O2 中不得重新分析已在 P0/P2/P3/P4 中完成的工作，避免重复消耗 token 和产出不一致。

### format_template 引用

本技能使用 **FS2（client-deliverable）** 模板，详见 wiki/技能输出格式架构方案.md §4.3。

### FS2 覆盖项

制度文件的特殊性决定了需对FS2模板做以下覆盖：

| 覆盖项 | FS2默认值 | 覆盖为 | 理由 |
|:---|:---|:---|:---|
| 封面布局 | 律所logo+标题居中+署名底部 | **公司全称顶部居中+制度名称中部居中+版本/日期底部居中（与标题保持≥8行间距）** | 制度文件是公司内部文件，封面信息全部居中排列，版本/日期与标题拉开间距避免拥挤 |
| 签署页 | 律所盖章位 | **公司盖章位 + 股东会/董事会审议通过决议编号** | 制度文件的"签署"是公司治理机构审议通过 |
| 保密声明 | "本文档为律所向客户交付的保密文件" | "本制度为公司内部管理文件，未经公司书面许可，不得对外提供" | 内部制度文件，非律所-客户关系 |
| 正文标题 | 黑体小三/四号 | **黑体三号加粗居中**（制度名称）+ 黑体三号加粗（章标题）+ 黑体四号（条标题"第X条"） | 制度文件标题须更正式，条级标题须加粗"第X条"部分 |

**不使用FS2的以下内容**：
- ❌ 律所简介/团队介绍页 — 制度文件不需要
- ❌ 计费说明 — 非报价文件

### delivery_formats

| 格式 | 用途 | 优先级 |
|:---|:---|:---|
| **DOCX** | 主交付物（打印/上会/归档/印用） | ⭐⭐⭐ 必出 |
| **MD** | 辅交付物（律师编辑复核副本/对话内预览） | ⭐⭐ 必出 |
| PDF | 归档版（可选，用户说"导出PDF"时生成） | ⭐ 可选 |

### 文件名规范

```
Mode A: {公司简称}_{制度类型}议事规则_V{版本号}_{YYYYMMDD}.docx
示例: 某科技_董事会议事规则_V1.0_20260603.docx

Mode B: {公司简称}_{制度类型}议事规则_修订版_V{版本号}_{YYYYMMDD}.docx
       {公司简称}_{制度类型}议事规则_变更说明_{YYYYMMDD}.md
示例: 某科技_董事会议事规则_修订版_V2.0_20260603.docx
       某科技_董事会议事规则_变更说明_20260603.md
```

### 排版基线（FS2内联版本，直接执行）

```
页面:
  size: A4 portrait
  margin: top 25mm / bottom 25mm / left 30mm / right 25mm
  装订说明: 左侧30mm留装订位，制度文件须归档装订

封面布局:
  顶部: {公司全称}（居中，黑体 二号 加粗）
  中部: {制度名称}议事规则（居中，黑体 一号 加粗，距顶部约1/3页高）
  底部: （居中，与标题保持≥8行空白间距，不得紧贴标题）
    版本：V{X.X}（居中，宋体 小四）
    起草日期：{YYYY年MM月DD日}（居中，宋体 小四）
    审批状态：待{股东会/董事会}审议（居中，宋体 小四）
  禁止: 版本信息紧贴标题（须≥8行间距）/ 出现"起草依据"（属律师内部工作记录）/ 封面页显示页码

DOCX结构（硬性约束，不得合并Section）:
  结构: 封面(Section1) + 分节符(下一页) + 正文(Section2)
  Section1（封面）:
    - 无页眉、无页码
    - 内容: 公司全称(顶部居中) + 制度名称(中部居中) + ≥8行空白 + 版本/日期/审批状态(底部居中)
  Section2（正文）:
    - 页眉: 公司全称 + 制度名称（从正文第1页起）
    - 页脚: "第X页 共Y页"（从正文第1页起计为"第1页"）
  禁止: 封面和正文在同一Section（会导致封面继承正文页码、版本信息被正文挤压溢出到第二页）

条款序号体系（五层层级，严格遵循，不得混用或跳级）:
  第一层-章: "第X章" + 空格 + 章名（如"第一章 总则"）
    - 格式：黑体 三号 加粗
    - 章名跨章不连续编号，每章独立命名
  第二层-条: "第X条"（全文连续编号，跨章不重置）
    - 格式：黑体 四号
    - 示例：第一章第一条、第二条 → 第二章第三条、第四条（中间不断号）
  第三层-款: 自然段缩进2字符，不加序号
    - 格式：宋体 小四 1.5倍行距
    - 一条中有多款时，每款独立成段，仅靠缩进区分
  第四层-项: （一）（二）（三）…（中文括号+中文数字）
    - 格式：宋体 小四，缩进2字符
    - 用于条下面的并列事项列举
    - **每项必须起一行**（独立成行），项目之间以句号结束，不使用分号连接
    - 示例：
      第八条 有下列情形之一的，应当召开临时股东会：
      （一）代表十分之一以上表决权的股东提议时；
      （二）三分之一以上的董事提议时；
      （三）监事会提议时。
  第五层-目: 1. 2. 3.…（阿拉伯数字+半角句点）
    - 格式：宋体 小四，缩进4字符
    - 仅用于项下面的进一步细分
    - **每目必须起一行**（独立成行），项目之间以句号结束，不使用分号连接
    - 示例：
      （一）会议通知应当载明以下内容：
      1. 会议时间；
      2. 会议地点；
      3. 会议方式（现场/通讯/线上）。
  禁止:
    - 禁止同一层级混用阿拉伯数字和中文序号
    - 禁止条级用阿拉伯数字（应为"第X条"）
    - 禁止项级用阿拉伯数字（应为"（一）（二）"）
    - 禁止项、目之间用分号连接在一行（每项/目必须独立成行）

字体:
  制度名称: 黑体 一号 加粗居中（封面）
  章标题: 黑体 三号 加粗
  条标题: 黑体 四号（"第X条"部分加粗，条后内容为正文宋体）
  正文: 宋体 小四 1.5倍行距
  首行缩进: 2字符

表格:
  样式: 三线表
  表头: 黑体 小四 加粗 居中
  表体: 宋体 小四

页眉页脚:
  封面页: 无页眉、无页码
  正文页:
    页眉: 公司全称 + 制度名称（居中 / 宋体 小五）
    页脚: 页码（居中 / "第X页 共Y页"，从正文第1页起计为"第1页"）
  保密声明: 正文页脚下方 "本制度为公司内部管理文件"
```

> **排版依据**：
> - 页边距参照 GB/T 9704-2012《党政机关公文格式》精神，左侧加宽至30mm以适应装订
> - 条款序号五层体系参照《中华人民共和国立法法》及全国人大议事规则的"章→条→款→项→目"层级
> - 上市公司巨潮资讯网披露的议事规则PDF均遵循此序号体系

## 内容-格式冲突仲裁条款

> 当本文件的约束与内容层（模板骨架）的约束在特定输入下产生不可调和的矛盾时，
> 仲裁优先级为 **法律文书有效性 > 阅读便利性 > 格式美学**。
>
> **裁决规则**：
> 1. 不得隐式裁决。必须在输出末尾的"格式冲突记录"小节显式标注冲突点、选择的裁决方向和理由。
> 2. 如果冲突涉及"法律文书有效性"（如缺失法定结构），法定结构优先，即使违反内容层约束。
> 3. 如果冲突仅涉及"阅读便利性"（如叙事过长），可在保持内容约束的前提下，通过格式层的局部调整（如分段/缩进/编号体系）改善可读性。
