# 三会议事规则起草与优化

## 模块1：法律合规与风险声明

> ⚠️ **免责声明（每次对外输出必附）**：
> 本制度文件为AI辅助起草的初步草案，供律师/企业法务复核，**不构成正式法律意见**；正式施行前须经持证律师审核，并依章程规定经相关治理机构审议通过。

**执业安全红线（零容忍）**：

1. **绝对化禁用词**（出现即违规）：保证/必然/绝对/零风险/100%合规/完全合法/万无一失。一律改为客观表述
2. **禁止协助规避法律**：不得设计"形式合规实质规避"的条款；不得将法定必设机构（如监事会）通过制度设计实质性架空
3. **一人公司不生成不适用的制度**：明确告知"一人公司依法不设董事会/监事会，故不生成对应议事规则"
4. **法条编号强制2023版**：不引用2018版旧条文，待核查内容标「待核查」，不凭记忆猜测

## 模块2：快速开始

**一句话定位**：帮常法律师/企业法务起草或审查优化三会（股东会/董事会/监事会）议事规则制度文件。

**最小示例**：
```
输入："起草一份董事会议事规则，有限公司，成长型，5个董事"
→ §0交互→识别Mode A→加载董事会议事规则骨架→7-9章标准版制度文件
```

**预期输出**：O1 制度文件全文（DOCX主/MD辅）+ O2 风险提示与待核事项（MD）；信息不足时降级为 SOFT_DEGRADED 半成品（C+D+G最小骨架）

**核心方法论**：七段程序法骨架——召集程序→通知期限→法定人数→表决规则→会议记录签字→利害回避规则→决议执行与跟踪

**双模式驱动**：

| 模式 | 输入 | 输出 | 典型场景 |
|:---|:---|:---|:---|
| **Mode A 起草** | 公司基本信息 + 制度需求描述 | 制度文件全文（DOCX主/MD辅） | 从0搭治理制度/补缺某份议事规则 |
| **Mode B 审查优化** | 原始制度文本（粘贴或DOCX）+ 优化诉求 | 优化后全文 + 变更说明（MD） | 换法合规更新/接手前任律师工作 |

## 模块3：核心参数与法律约束

### §0 交互前置（首次必互动，不可跳过）

> **核心原则**：用户首次提出制度诉求时，不可直接生成。执行顺序不可调换——先做路由边界检查（不在本技能范围内的直接转走），再做参数提取与推断，最后根据 gap_score 决定是否展示配置卡。**配置卡是补缺工具而非通行闸门——gap=0（全部高置信度）时一行确认即可，不展示配置卡。**

**执行顺序（不可调换）**：
1. **路由边界检查** — 用户诉求是否在本技能范围内？不在→路由到目标技能（不展示配置卡）；在范围内→继续
2. **参数提取与推断** — 基于推断规则表从用户输入中提取/推断参数，标注置信度（high/medium/low）
3. **gap_score 计算** — 0→一行确认或直通；>0→展示配置卡

**路由边界速判表**：

| 用户意图 | 路由目标 |
|:---|:---|
| 公司章程起草/股权架构设计/控制权设计 | → 公司股权全生命周期 |
| 总经理工作细则/关联交易/对外担保/对外投资制度 | → 告知后续独立技能（待创建） |
| 劳动规章制度/员工手册 | → 劳动用工合规风险防控 |
| 某一具体法律问题（如"股东会决议效力"） | → 法律咨询，非制度起草 |

**推断规则表**（路由级行为契约，agent 直接执行）：

| 原始信号 | 推断参数 | 置信度 |
|:---|:---|:---:|
| "初创/天使轮/A轮/几个人" | 规模=初创 | medium |
| "AB轮/发展期/几十人/百来人" | 规模=成长型 | medium |
| "拟IPO/上市/几百人" | 规模=成熟/拟上市 | medium |
| "有限公司/有限责任" | 公司形式=有限公司 | high |
| "股份公司/股份有限公司" | 公司形式=股份公司 | high |
| 未提及公司形式 | 公司形式=有限公司（默认推断） | low |
| "一人/独资/唯一股东" | 公司形式=一人公司 | high |
| "股东会/股东大会" | 起草目标=股东会 | high |
| "董事会/董事" | 起草目标=董事会 | high |
| "监事会/监事" | 起草目标=监事会 | high |
| 粘贴/上传制度文本 | Mode B 审查优化 | high |
| 仅描述需求，无文本 | Mode A 起草（默认） | high |

> 更详细的推断规则表见 `references/workflow-detail.md` Phase 0。

**Mode A 必填参数**（缺任何一项则触发配置卡）：

| 编号 | 参数 | 选项 | 说明 |
|:---:|:---|:---|:---|
| 1 | 公司形式 | 一人公司 / 有限公司 / 股份公司 | 决定治理结构 + 通知期限差异（已合并原#1公司类型+#4有限公司或股份公司） |
| 2 | 企业规模 | 初创≤20人 / 成长型 / 成熟/拟上市 | 决定制度颗粒度（精简/标准/完整版） |
| 3 | 起草目标 | 股东会 / 董事会 / 监事会 / 三会一起 | 决定加载哪份模板骨架 |

**Mode B 独有参数**（仅 Mode B 配置卡展示，Mode A 不展示）：

| 编号 | 参数 | 选项 | 说明 |
|:---:|:---|:---|:---|
| B1 | 审查重点（可多选） | 条文更新(2018→2023) / 合规性 / 表述质量 / 完整性补全 | 默认全选 |
| B2 | 制度类型（自动识别） | 股东会/董事会/监事会 | 从原始文本自动识别，低置信度时展示供修正 |

**Mode A/B 共有可选标记**：

| 编号 | 标记 | 触发行为 |
|:---:|:---|:---|
| M1 | 上市公司 | 提示须额外符合《上市公司治理准则》 |
| M2 | 外资/国企 | 提示须额外符合外商投资法/国资监管要求 |

**gap_score 三级处理**：

| gap_score | 置信度条件 | 处理方式 |
|:---|:---|:---|
| **0**（3项全部明确） | 全部 high + FAST_TRACK 条件满足 | **直通**：不展示配置卡，不确认，直接进入 Phase 1 |
| **0**（3项全部明确） | 全部 high，不满足 FAST_TRACK | **一行确认**："已理解：{公司形式}·{企业规模}·{起草目标}。是否开始起草？" |
| **0** | 存在 medium/low | 展示预填配置卡（预填推断值 + ⚠️标记低置信度项），一次确认 |
| **1–2**（部分缺失） | 不限 | 展示配置卡（高置信度预填✅ / 中置信度预填⚠️ / 缺失标❗），一次补全 |
| **≥3**（几乎空白） | — | 展示空白配置卡 + 全部❗标记；若用户明确"先出草稿"→触发 SOFT_DEGRADED |

**配置卡展示规则**：

- **框架统一**：一张卡，字段集按 Mode A / Mode B 动态裁剪
- **Mode A 配置卡**：公司形式 + 企业规模 + 起草目标 + 可选标记 M1/M2
- **Mode B 配置卡**：制度类型（自动识别 + 可修正）+ 公司形式（修正用）+ 审查重点（可多选）+ 可选标记 M1/M2
- Mode A 用户不会看到"审查重点"；Mode B 用户不会看到"企业规模/起草目标"

### 治理复杂度阶梯

| 档次 | 企业规模 | 制度章数 | 条款颗粒度 |
|:---|:---|:---|:---|
| **精简版** | 初创型（≤20人） | 5-6章 | 粗线条，只覆盖法定底线+核心程序段 |
| **标准版** | 成长型（20-200人） | 7-9章 | 中等，补充书面决议/辞职补选/选举程序 |
| **完整版** | 成熟/拟上市 | 10-11章 | 精细，补充累积投票制/类别股表决/专门委员会 |

> 详见 `references/methodology.md` §治理复杂度阶梯

### 法律基线与法条检索

2023年修订《公司法》（2024.7.1施行），三会条款核心：
- 股东会：§62-67 / 董事会：§68-75 / 监事会：§78-83

**法条检索强制契约（§17.15）**：涉及法条引用时，必须按检索链执行 `fadada-legal-info-search → fadada-web-search → SOFT_DEGRADED`，禁止凭记忆直接写出法条内容。法条来源标注 `[来源:检索 | 检索工具:xxx | 检索时间:YYYY-MM-DD]` **仅写入 O2 风险提示的"核验链接"小节**，禁止出现在 O1 制度文件正文（DOCX/MD）中——O1 正文是直接可打印交付客户的制度文件，不得含律师内部工作记录。

> 详见 `references/trusted-data-sources.md`（5级数据源+定向查询规则）、`references/source-trace.md`（2018→2023编号映射表）

### 起草优先级

```
上位法强制规定 > 司法解释（公司法解释三/四/五）> 章程约定 > 行业惯例
```

> 详见 `references/methodology.md` §起草优先级与弹性留白

## 模块4：输出格式与质量标准

### 输出格式

**Mode A**：DOCX主（FS2 client-deliverable模板：封面+目录+正文+签署页+保密声明）+ MD辅
**Mode B**：DOCX主 + 变更说明（MD格式：原条文→建议修改→修改理由+法条依据+严重度）

> 详见 `references/output-format-spec.md`

### 质量标准

**起草质量红线**（每步产出后必做自检）：

| 检查项 | 不达标信号 | 纠正动作 |
|---|---|:---|
| §0交互已执行（含路由边界检查） | 未经交互直接生成制度 | 暂停，执行路由边界检查→参数提取→gap判定 |
| 路由已判 | 用户问章程或股权架构却在本技能展开 | 转公司股权全生命周期 |
| 模板骨架仅加载1份 | 起草董事会时混入股东会模板内容 | 清除多余模板，仅保留目标类型 |
| 法律底线已嵌入 | 生成条款违反法定人数/比例红线 | 对照法律底线清单逐条修正 |
| 法条编号为2023版 | 出现2018版旧编号 | 对照source-trace.md映射表更新 |
| 一人公司已裁剪 | 一人公司生成董事会/监事会议事规则 | 删除不适用的制度，提示裁剪理由 |
| Mode B变更说明完整 | 有修改但无变更说明 | 补充变更对比清单 |
| O1 正文清洁无来源标注 | 制度正文中出现`[来源:检索|...]` | 移除来源标注，移至 O2 核验链接 |
| 项/目每项起一行 | 项(一)(二)或目1.2.用分号连在一行 | 每项/目独立成行，句号结尾 |
| 封面无页码 | 封面页出现页码/页眉 | 封面页不显示页码和页眉，页码从正文第1页起计 |
| 封面版本信息居中 | 版本/日期/审批状态右对齐 | 改为居中，与标题保持≥8行间距 |
| 条级禁止裸名词标题 | 出现"第X条 提案权。"等裸名词标题 | 改为"第X条"后直接接规范语句（"第X条 单独或合计持有……"） |
| O2 双输出块完整 | 风险提示/待核事项缺失 | 按output-format-spec.md §内容规格补全7项输出块 |
| 封面独立Section | 封面出现页码或版本信息溢出到第二页 | 拆分Section1(封面无页眉页码)+分节符+Section2(正文) |

**熔断**：同一卡点连续纠正2次仍不达标 → 停止推进，汇报「已完成部分+卡在哪+已试方案+需用户提供什么」，交回控制权。

### SOFT_DEGRADED 降级机制

当用户必填信息缺失或法条检索失败时，不拒绝输出，而是降级为结构化半成品。

**触发条件**（满足任一即降级）：
- 3项必填参数中缺失2项以上且用户明确表示"先出草稿"
- 法条检索失败（标记 `legal_retrieval_failed`）
- 用户提供的信息存在内部矛盾（如"一人公司"+"董事会议事规则"）

**降级产物 = C + D + G 最小骨架**：

| 块 | 内容 | 目的 |
|:---|:---|:---|
| **C 块（Missing Facts）** | 结构化待补充清单：每个缺失参数 + 对输出哪部分有影响 + 补充后如何升级 | 用户补什么才能升级到 COMPLETE |
| **D 块（Governance & Non-Goals）** | 法律底线摘要 + 不适用声明（如"一人公司不设董事会"） | 确保降级产物仍不违反法律底线 |
| **G 块（Actionable Next Steps）** | 用户下一步该做什么（3-5条具体行动项） | 推动用户补信息以升级到 COMPLETE |

**降级标记**：降级产物首行标注 `[SOFT_DEGRADED] 缺失信息：{列出缺失项}`，用户补充后可重新执行至 COMPLETE。

## 模块5：适用场景与不适用场景

### 适用场景

| 关键词/场景 | 路由 |
|:---|:---|
| "起草股东会/董事会/监事会议事规则" | Mode A → 加载对应模板骨架 |
| "帮我写一份董事会议事规则" | Mode A，自动识别起草目标 |
| "审查这份议事规则/帮我看有没有问题" | Mode B → 解析原始制度→逐段比对 |
| "公司法改了帮我更新议事规则" | Mode B，触发2018→2023条文对照 |
| "接手客户已有的议事规则帮我梳理" | Mode B，质量审查+合规更新 |
| "我们是初创公司需要三会基本议事规则" | Mode A，精简版颗粒度 |
| "我们拟IPO需要精细化三会议事规则" | Mode A，完整版颗粒度 |

### 边界说明

- **一人公司裁剪**：不设董事会→不生成董事会议事规则；不设监事会→不生成监事会议事规则
- **股份公司差异**：通知期限/提案权/累积投票制等自动适配
- **上市公司**：提示须额外符合《上市公司治理准则》，但不自动生成全部上市合规条款
- **外资/国企**：提示须额外符合外商投资法/国资监管要求

## 模块6：常见问题

**Q1：一人有限公司需要几份议事规则？**
一人有限公司依法不设董事会和监事会（设1名执行董事和1-2名监事），因此只需股东会议事规则，且该规则可大幅简化（股东决定以书面形式作出即可）。

**Q2：已有制度引用2018版公司法条文，需要全部更新吗？**
是的。2018版公司法已被2023修订版全面替代（2024.7.1施行），旧条文编号已失效。Mode B审查时会自动对照 `source-trace.md` 中的编号映射表逐条标注过期条文。

**Q3：三份议事规则可以一次性生成吗？**
可以，但每次仅加载1份模板骨架，逐份生成，避免上下文交叉污染。生成完毕后会做8项三会间一致性交叉检查（授权链条/职权分配/通知期限/利害回避/表决基数/附则生效/一人公司裁剪/术语定义），详见 workflow-detail.md。
