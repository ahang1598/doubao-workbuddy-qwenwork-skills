# 工作流详细步骤

## Phase 1: 场景识别与深度确认

1. 确认用户场景（投资并购/IPO/贷款融资/战略合作/单一查询）
2. 按场景确定尽调深度和十大部分覆盖率（见 `scenario-routing.md`）
3. 判停：目标公司名称无法确认或工商登记不存在→要求补充准确信息
4. 追问≤1次

## Phase 2: 信息采集

> 详见 `mcp-data-collection.md`

1. **2a**：检测天眼查MCP可用性，不可用则引导配置/降级
2. **2b**：search_companies搜索企业获取company_id（含子公司逐一搜索）
3. **2c**：并行调用各维度MCP工具（超时30秒→跳过+标注数据缺失）
4. **2d**：MCP无法覆盖的维度→汇总为一次性待补充信息清单

## Phase 3: 十大部分逐一核查

> 详见 `dd-framework.md` + `checklist-16d.md`

1. 将采集信息填入十大部分框架
2. 每部分标注：核查结果+风险评级（正常/需关注/[红旗]）+信息来源
3. [红旗]发现→调用专项技能做深度法律分析
4. 汇总[红旗]发现到第一部分
5. 法条引用验证：联网核实，不得依赖训练知识推测
6. 待核实标注：仅依赖单一数据源→标注【待核实】+信息来源+时间戳

## Phase 4: [红旗]发现深度分析

1. 识别红旗发现对应的专项技能：
   - 股权代持/资格问题 → 02-股东确权
   - 治理/关联交易问题 → 03-公司治理诊断
   - 投资协议条款问题 → 06-投资协议审查
   - 退出/争议问题 → 05-投融资退出
2. 调用对应技能做深度法律分析
3. 将分析结论整合到尽调报告对应部分

## Phase 5: 出具尽调报告+自检

### 自检清单

| 检查项 | 不达标信号 | 纠正动作 |
|--------|------------|----------|
| 十部分完整性 | 遗漏部分 | 补充缺失部分（至少标注"待补充"） |
| 风险评级 | 未标注风险等级 | 逐部分标注正常/需关注/[红旗] |
| 信息来源 | 未标注数据来源 | 补充信息来源标签 |
| 法条引用 | 未联网核实 | 联网核实法条编号和内容 |
| 待核实标注 | 单一数据源未标注 | 补充【待核实】标注 |
| 尽调结果转化 | 未提示转化为合同附件 | 补充"尽调结果须转化为投资协议附件"提示 |

### 熔断

同一步骤连续纠正2次不达标→交回控制权。
