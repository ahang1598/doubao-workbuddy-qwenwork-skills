# Rightly指引：网信办合规要求应对与自查要点

## 背景

网信部门持续升级个保合规要求，并分行业推进整改。已发布测评报告的行业包括：网上购物类、地图导航类、浏览器类、新闻资讯类、在线影音类、云盘类、拍摄美化类、电子图书类、短视频类、餐饮外卖类等。

**应对思路**：
1. **自查**：参照最新合规要求（部分高于现行法律法规）进行自查，重点关注最小必要性、分场景获取同意
2. **整改**：发现明确违规事项立即整改。高于现有合规要求的（如分场景授权），提前规划业务场景拆分

## 一、过度收集非必要个人信息

### 1. 后台静默监听用户安装卸载

**问题案例**：
- 部分APP后台静默持续监测用户安装和卸载其他APP的操作
- 后台静默时监听用户安装APP情况，将包名、时间信息上传至服务器

**分析建议**：
- 已知代码堆栈：APP切后台时取消监听，禁止后台监听注册
- 不知代码位置或无代码权限(SDK)：升级Rightly接入广播管控能力

**解决建议**：
- 非必要采集：删除监听代码
- SDK问题：联系SDK开发者删除并升级
- 兜底方案：Rightly广播管控（接入指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/installMonitor）
- 定向插桩：通过Rightly定向插桩移除SDK内特定代码（指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/stub）

### 2. 后台静默上传非必要个人信息

**问题案例**：
- 将用户新安装/卸载的APP信息上传到服务端
- 后台静默时将MAC地址、Android ID等设备识别码上传

**分析建议**：
- 已知敏感字段和域名：通过JADX-GUI反编译代码搜索域名分析
- 未知情况方式1：动态监控API调用，查询敏感API后台调用问题
- 未知情况方式2：接入网络传输监控能力（指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/networkCapture）

**解决建议**：
- 优先删除或整改代码
- 第三方SDK难以改动：配置全局兜底禁止相关API调用（指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/api）
- 注意：全局兜底会影响所有调用，需谨慎评估功能影响

### 3. 过度收集位置信息

**问题案例**：
- 天气功能获得位置权限后，却将经纬度、WiFi列表传给第三方广告SDK
- 在非必要页面调用位置权限，超出用户预期

**分析建议**：
- 手段1：静态扫描，根据定位API查看调用情况
- 手段2：动态监控，以定位API为筛选条件查看调用

**解决建议**：

**方案A - 简单处理（未明确要求分模块授权）**：
- 梳理定位API调用，删除非必要调用
- 前台必要但后台非必要：
  - 业务自建方案：APP切后台时取消监听
  - Rightly广播管控：直接接入并开启兜底禁止后台监听

**方案B - 分模块授权（复杂场景/被建议分模块授权）**：
- 升级Rightly接入分模块授权（指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/permForBusiness）
- 开发步骤：
  1. 基于定位API调用情况划分模块
  2. 在模块生效范围内进行进入/退出打点
  3. 提供模块管理界面或弹窗，授予/取消模块权限
  4. API执行时根据模块授权情况管控（方案已内置）

**解决案例**：
- XX业务通过接入分模块授权，避免了启动阶段调用定位权限
- XX业务在未被用户授权的早晚报功能场景，避免调用定位权限

### 4. 过度采集非必要信息

**问题案例**：
- 地图APP通过传感器收集用户所在楼层，未获授权
- APP在唤醒语音助手场景上传所有APP包名、版本号

**分析建议**：
- 以"手机传感器"为例，排查传感器API调用：
  - 手段1：静态扫描根据传感器API查看调用
  - 手段2：动态监控以传感器API为筛选条件

**解决建议**：
- 不必要的应用列表调用：升级Rightly接入分模块授权，在未进入允许访问的模块时禁用

### 5. 过度收集用户截图动作信息

**问题案例**：
- 通过存储权限持续监测用户相册截图文件夹，判断截图动作并上传

**解决建议**：
- 升级Rightly监控截图问题，启用兜底（指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/captureMonitor）

### 6-8. 过度收集人脸/个人资料/非影音文件

**人脸信息**：产品功能问题，建议修改产品流程（如取消强制人脸识别）
**个人资料**：产品功能问题，移除与功能无关的信息收集
**非影音文件过度访问**：
- 原文：App在用户未授予存储权限时尝试读取非媒体影音文件
- Rightly解决方案：本地检查工具协助定位SD卡访问（区分有/无权限，增删改查等情况）
- 发现案例：
  - 帮助某业务找到删除文件的代码
  - 帮助某业务找到启动时创建某目录的代码
  - 广告SDK的图灵库存在访问，升级解决
  - 业务在无权限时在SD创建目录，删除解决

## 二、未充分告知个人信息收集的目的、方式、范围

### 8. SDK披露字段不清晰

**问题案例**：
- 多处SDK收集设备标识、网络信息等，但未明确具体内容

**分析建议**：
- 手段1：静态扫描，分SDK查看敏感API调用
- 手段2：动态监控，根据SDK包名搜索堆栈

**解决建议**：
1. 如何梳理完整：
   - 汇总SDK自己的隐私协议披露信息
   - 参考已整改App的披露内容（QQ浏览器、腾讯地图）
   - 使用扫描数据查漏补缺
2. 如何减少字段披露：
   - 使用Rightly配置字段对应API的禁用兜底
   - 使用Rightly定向插桩移除SDK中的敏感字段

### 9. 隐私政策内容不规范或不完整

**问题案例**：
- 未说明App类型、基本功能、必要个人信息范围
- 首次弹窗未明确"同意隐私政策仅代表知悉和授权基本功能的必要个人信息"

**解决建议**：产品功能问题，修改隐私政策内容和弹窗文案

### 10. SDK披露非必要信息

**问题案例**：
- 广告SDK以广告监测为由收集设备硬件/网络/定位信息
- 推送SDK以推送消息为由收集标识/位置/运营商信息
- 隐私政策声明与实际收集不一致

**分析建议**：
- 手段1：静态扫描分SDK查看敏感API调用
- 手段2：动态监控根据SDK包名搜索堆栈

**解决案例**：
- 魅族SDK定位信息访问经分析确认实际无访问，与提供方沟通后移除
- MMA SDK动态监控发现堆栈均为已下架功能，直接下架解决

## 三、强迫用户同意收集非必要个人信息

### 11. 隐私政策一揽子同意敏感字段

**原文**：强迫用户一揽子同意收集OAID、用户操作记录等个人信息

**Rightly解决方案**：
- 接入分模块授权，将一条"隐私协议"当成一个模块，为模块绑定不同的API
- 实现字段的"分协议管理"
- 指引：docs.bugly.woa.com/rightly/dynamic/docs/Android/permForBusiness

### 强迫一揽子同意隐私政策中不合理条款
- 产品功能问题，建议修改

### 捆绑注销
- 不得与其他APP捆绑注销，需提供单独删除本APP个人信息的功能

### 未设置投诉举报/个人信息查询导出等功能
- 产品功能问题，建议修改

## 四、打开权限并非功能所必需

### 14. 超范围声明不必要权限

**问题案例**：声明不必要的日历、通讯录、健身、存储等权限

**分析建议**：
- 使用Rightly静态扫描梳理所有权限声明和对应API调用，甄别未使用的权限

**解决建议**：
1. 实际有使用的权限：使用录屏和功能路径说明解决
2. 日历权限：区分读/写必要性，仅需提醒功能则只保留写权限
3. 存储权限：
   - 无使用/可不使用：移除AndroidManifest声明和相关代码
   - 必须使用（如保存图片/下载文件）：
     - Android 9及以下：必须申请权限
     - Android 10+：通过MediaStore API或SAF绕过存储权限
     - 特殊声明：限制存储权限在Android 9及以下使用
   - 如必须保留：仅用户使用功能时上传文件内容，不上传拍摄地点/文件时间等非必要信息
4. 设备信息权限（READ_PHONE_STATE）：如无必要建议拔出

## 五、未充分保障用户权利

**问题案例**：
- 未明确是否存在跨平台广告推荐
- 如存在，应在设置页面提供单独关闭按钮

**解决建议**：产品功能问题，建议修改

## 六、隐私同意前的API管控

### 需要管控的API（来自最新网信检查要求）

| API | 管控说明 |
|-----|---------|
| ActivityManager#getRunningAppProcesses | 运行进程信息，隐私同意前禁用 |
| ActivityManager#getRunningTasks | 运行任务信息，隐私同意前禁用 |
| ConnectivityManager#getActiveNetworkInfo | 设备网络信息，隐私同意前禁用 |

### PMonitor配置示例

```java
// 运行任务信息
PMonitor.getConfig()
  .updateRuleForAPI(ConstantModel.InstalledAppList.NAME,
    ConstantModel.InstalledAppList.GET_RUNNING_TASKS)
  .rule(GeneralRule.BACK_NORMAL_AND_FRONT_NORMAL)
  .ruleBeforeStrategy(RuleConstant.STRATEGY_BAN)
  .submitRule();

// 设备网络信息
PMonitor.getConfig()
  .updateRuleForAPI(ConstantModel.Network.NAME,
    Network.GET_ACTIVE_NET_INFO)
  .rule(GeneralRule.BACK_NORMAL_AND_FRONT_NORMAL)
  .ruleBeforeStrategy(RuleConstant.STRATEGY_BAN)
  .submitRule();

// 运行进程信息
PMonitor.getConfig()
  .updateRuleForAPI(ConstantModel.InstalledAppList.NAME,
    ConstantModel.InstalledAppList.GET_RUNNING_APP_PROCESS)
  .rule(GeneralRule.BACK_NORMAL_AND_FRONT_NORMAL)
  .ruleBeforeStrategy(RuleConstant.STRATEGY_BAN)
  .submitRule();
```

## 附录：最新合规新规详情

### 隐私协议新规
1. 访问路径不超过4次点击（新要求）
2. 使用第三方SDK未完整披露（SDK嵌套，新检测能力）
3. 隐私政策应提供可跳转链接到个性化推荐开关

### 隐私调用新规
1. 未获授权访问外部存储（新检测能力）：无存储权限时不应读取非影音文件
2. 非必要性访问外部存储（新检测能力）：非必要场景下不访问存储权限
3. 未获同意访问运行状态信息（新检测API）：隐私同意前不访问进程信息和设备网络信息
4. 广告标识符权限管控（新检测能力）：提供区分功能的广告标识符开关
5. 未经同意访问SIM状态（新要求）：同意前不读取，同意后不高频读取
6. 启动时禁止扫描默认蓝牙（新要求）：过去仅管控获取蓝牙信息和主动连接

### 网信检查测试报告发布地址
- 网上购物类、地图导航类、浏览器类、新闻资讯类、在线影音类、云盘类、拍摄美化类、电子图书类、短视频类、餐饮外卖类
- 发布平台：中央网络安全和信息化委员会办公室（cac.gov.cn）

### 已通过网信检查的参考App
QQ浏览器、腾讯视频、微视、地图、天天P图均已通过网信检查，可参考其第三方SDK披露内容。
