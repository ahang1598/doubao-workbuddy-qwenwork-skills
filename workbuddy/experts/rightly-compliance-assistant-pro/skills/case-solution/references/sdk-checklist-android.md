# SDK隐私合规优化Checklist - Android

**适用对象**：SDK开发者、集成SDK的App开发者
**背景**：本checklist是SDK在合规优化中应对的主要合规点，不作为SDK的app合规标准。建议SDK将产品和SDK的合规优化配合同步推进。不包含特定政策未涉及的个性化场景。

## 1. 隐私政策与告知

### 1.1 隐私政策基本要求
- [ ] SDK需提供独立的隐私政策或个人信息处理规则
- [ ] 隐私政策需清晰说明收集的个人信息类型、收集目的、使用方式
- [ ] 隐私政策变更时需通知集成方App

### 1.2 信息披露
- [ ] 向集成方App提供SDK名称、版本号、主要功能说明
- [ ] 提供SDK收集的个人信息清单
- [ ] SDK独立采集、传输、存储个人信息的需单独说明

### 1.3 集成指引
- [ ] 提供合规使用指南，引导App开发者正确集成
- [ ] 功能变更或个人信息处理规则变更时及时告知

## 2. 数据收集

### 2.1 最小必要收集
- [ ] 仅收集实现功能所必需的最少信息
- [ ] 提供功能模块和个人信息收集的配置选项
- [ ] 不一揽子过度收集
- [ ] 区分必要和非必要收集项，提供开关

### 2.2 收集时机
- [ ] SDK初始化时不主动收集敏感信息
- [ ] 在功能实际使用时才收集对应信息
- [ ] App未调用SDK相关功能时不收集

### 2.3 权限使用
- [ ] 不主动申请系统权限，由App统一管理
- [ ] 使用权限前检查是否已获授权
- [ ] 提供权限使用的详细说明文档

### 2.4 设备标识
- [ ] 优先使用可重置的标识符（如OAID）
- [ ] 不收集不可变更设备标识（IMEI/MAC等）除非业务必需
- [ ] 对于READ_PHONE_STATE权限，如无必要不依赖
- [ ] 提供标识符收集的开关配置

## 3. 隐私同意前管控

### 3.1 同意前行为
- [ ] 用户同意隐私政策前，SDK不执行任何敏感API调用
- [ ] 提供"隐私同意状态"的配置接口
- [ ] 支持App通知SDK用户已同意/未同意
- [ ] 同意前不读取SIM状态
- [ ] 启动时不扫描默认蓝牙

### 3.2 Rightly管控示例
```java
// 配置隐私同意前禁用
PMonitor.getConfig()
  .updateRuleForAPI(模块名, API名)
  .rule(GeneralRule.BACK_NORMAL_AND_FRONT_NORMAL)
  .ruleBeforeStrategy(RuleConstant.STRATEGY_BAN)
  .submitRule();
```

## 4. 数据传输与存储

### 4.1 数据传输
- [ ] 数据传输使用加密通道（HTTPS）
- [ ] 不在后台静默上传非必要信息
- [ ] 传输的数据类型和频率遵循最小必要原则
- [ ] 不将设备标识、位置等信息传输给无关第三方

### 4.2 数据存储
- [ ] 数据存储在App私有目录
- [ ] 敏感数据加密存储
- [ ] 设置合理的数据保存期限，超期自动清理
- [ ] App卸载时随之清除SDK数据

## 5. 用户权利

### 5.1 数据删除
- [ ] 提供SDK数据清除接口
- [ ] 支持App调用以响应用户的删除请求
- [ ] 用户注销账号时确保SDK数据同步清除

### 5.2 功能控制
- [ ] 提供SDK功能开关，支持用户/App禁用特定功能
- [ ] 禁用后不再收集对应信息
- [ ] 提供个性化推荐/定向推送的关闭接口

## 6. 特殊场景

### 6.1 广告SDK
- [ ] 提供广告标识符的区分功能开关
- [ ] 非必要情况下不访问广告标识符
- [ ] 用户关闭个性化推荐后停止收集
- [ ] 提供删除用户个人特征标签功能

### 6.2 推送SDK
- [ ] 不以推送为由收集非必要信息（位置、运营商等）
- [ ] 提供消息推送开关
- [ ] 无推送任务时不活跃

### 6.3 分析/监控SDK
- [ ] 仅收集分析所需的最少数据
- [ ] 提供数据采集粒度的配置选项
- [ ] 提供完全禁用的开关
