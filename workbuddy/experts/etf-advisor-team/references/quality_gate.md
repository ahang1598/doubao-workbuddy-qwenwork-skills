# 质量门禁与自检清单（ETF 团队版）

> **本文件定位**：ETF 投资顾问专家团共享的质量自检清单与刚性拦截规则。报告模式下强制执行；对话模式下 Agent 自行确保分析深度。
>
> **设计理念**：GATE 0-3 串行门禁体系（ETF 团队适用版）——不引入个股专属的重型门禁（推导链十问/三表勾稽/M-Score/Beneish 等，均不适用 ETF），保留通用的结构完整性/三段式/数据溯源/信号融合/操作可执行性门禁。

---

## 一、输出自检清单

报告（ETF 交易建议书）撰写完成后，主理人必须逐项自检以下条目，**全部通过后方可交付**：

| # | 自检项 | 核验标准 |
|---|--------|---------|
| 1 | **三段式完整性** | 每个核心分析维度是否遵循「📊 关键数据 → 🔍 推导 → 📌 小结论」？是否存在跳过数据直接抛结论？ |
| 2 | **数据溯源标注** | 关键数据（净值/估值分位/份额资金流/规模/费率/宏观数据）是否标注来源与时间？ |
| 3 | **配置锚定** | 是否明确写出战略配置中枢 + 当前实际比例 + 偏离度 + 本次调仓后目标比例？每只标的标注核心/卫星定位？ |
| 4 | **信号融合表完整** | 信号融合表是否覆盖每只 ETF 的三方信号（结构/宏观/技术）+ 综合结论 + 冲突仲裁说明？禁止只凭单一维度下结论 |
| 5 | **操作可执行性** | 每只 ETF 的操作卡是否明确到「买入/卖出/持有/加减仓」？价位是否精确到小数点后两位？仓位是否给出具体百分比？分批计划是否给出具体价位与批次？ |
| 6 | **止盈止损明确** | 每只标的的止盈位/止损位/触发条件是否明确？纪律数值是否由风控官当场推导并写明理由（非照搬固定阈值）？ |
| 7 | **风险预案完整** | 是否覆盖系统性风险 + 各标的核心风险（引用风控官裁决）？ |
| 8 | **再平衡规则三全** | 定期触发/阈值触发/事件触发三类机制是否全部列明？频率与阈值是否由主理人推导并写明理由？ |
| 9 | **调仓执行顺序** | 是否给出先卖什么后买什么的执行顺序 + 资金衔接 + 交易成本估算？成本明显高于预期收益的调仓是否按风控官裁决取消/合并？「价位区间」列是否逐行为真实价位区间（新增标的须指定候选标的并给出价位，禁止填入板块名/类别/文字说明）？ |
| 10 | **合规声明** | 是否含四要素统一免责声明"⚠️ 以上内容由 AI 基于公开信息整理生成，仅供参考，不构成任何投资建议或个股推荐。投资有风险，决策需谨慎。"？措辞是否使用"候选操作/参考方案"（非"保证收益/必涨"）？ |
| 11 | **风格匹配** | 所有建议是否与用户投资风格（稳健/均衡/积极）/周期/回撤容忍匹配？ |
| 12 | **无模糊表述** | 是否避免了"逢低布局/长期持有/谨慎关注/有望上涨"等模糊表述？ |
| 13 | **口径与层面标注（v1.5.0）** | 所有仓位百分比是否标注分母（总资产/可用现金/某类额度）与层面（配置层/执行层）？是否存在裸百分数？ |

## 二、刚性拦截规则（GATE 0-4 串行）

> **报告模式下强制执行**。被拦截时的唯一合法动作是补写缺失内容，不允许降级为压缩版本。

### GATE 0：格式骨架检查
- 报告是否含「组合总览 / 配置中枢与偏离度 / 信号融合表 / 逐只操作卡 / 调仓执行顺序 / 风险提示 / 再平衡规则 / 合规声明」八大模块？
- 任一模块缺失 → ⛔ BLOCK → 补写该模块

### GATE 1：结构完整性检查
- 信号融合表是否覆盖持仓清单中**每一只** ETF？（缺一行即 FAIL）
- 每只 ETF 操作卡是否包含：操作结论 / 目标仓位 / 价位区间 / 分批计划 / 止盈位 / 止损位 / 触发条件 七要素？
- 调仓执行顺序表是否含：操作顺序 / 资金衔接 / 成本估算 三要素？
- 调仓执行顺序表「价位区间」列是否逐行为真实价位区间（`X.XX-X.XX` 数值格式，可附条件前缀）？新增标的是否已指定代表性候选标的并给出其价位区间？**发现该列填入板块名称/标的类别/"待估值回落"等非价位内容 → ⛔ BLOCK → 补写候选标的与真实价位**
- 新增标的是否已附成员分析（持仓诊断师工具体检 + 技术分析师估值/择时 + 行业主题加宏观景气确认 + 风控官裁决与止损位）并产出完整操作卡（七要素）？**仅有价格核实、无成员分析的新增标的 → ⛔ BLOCK → 回补成员分析**
- 任一结构缺失 → ⛔ BLOCK → 补写

### GATE 2：内容闭环检查
- 每个核心章节是否具备 📊 数据 + 🔍 推导 + 📌 结论 三段式？
- 信号融合表的"综合结论"是否由三方信号推导而来（而非凭空抛出）？
- 冲突仲裁说明是否写明取舍理由（仲裁顺序：风控红线 > 宏观方向 > 结构健康 > 技术择时）？
- 操作卡的价位是否与信号融合表结论一致？
- 止盈止损位是否由风控官推导并写明理由？
- 任一闭环断裂 → ⛔ BLOCK → 补写推导

### GATE 3：数据溯源与合规检查
- 关键数据是否标注来源与时间？
- 是否含 D 类伪信源（Wind/Bloomberg/iFinD 等付费终端作为信源名称）？→ 命中即 FAIL
- 是否含本地路径（C:\... 或 FinancialData/...）作为信源？→ 命中即 FAIL
- 是否含合规声明与免责声明？
- 是否含"保证收益/必涨/稳赚/无风险"等违规表述？→ 命中即 FAIL
- 任一不通过 → ⛔ BLOCK → 修正后重检

### GATE 4：交叉透明检查（v1.5.0 新增）
> **检查目标**：差异是否**透明**，而非**强制一致**——配置层与执行层结论、不同模式推导的数值差异是合法的，隐藏差异才是违规。

- 与工作区近期（≤30 天）交付物（组合建议书/单标的决策文件）是否存在结论或口径冲突？
- 若存在冲突：是否已通过**联动对照表**或差异说明显式摆明（而非静默并存、更非暗中调和为一套数字）？
- 本份交付的仓位百分比是否全部带**分母 + 层面**双标注（delivery_spec.md §九）？发现裸百分数 → ⛔ BLOCK → 补标注
- 单标的咨询（Workflow B）交付是否含**模式声明**（独立模式/继承模式）？
- 本次交付的宏观定调/风控框架若与近期交付物不一致，是否已注明原因（新证据 / 数据更新 / 独立推导无从属关系）？禁止静默漂移
- 任一不通过 → ⛔ BLOCK → 补联动对照表/差异说明/口径标注

## 三、信号融合表的冲突仲裁规则

当三方信号（结构/宏观/技术）方向不一致时，**必须**在"冲突仲裁说明"列写明取舍理由：

**仲裁优先级**（从高到低）：
1. **风控红线**（最高优先级）：命中清盘/流动性/行业逻辑红线 → 无论其他信号多乐观，方向定为"减仓/清仓"
2. **宏观方向定调**：宏观周期与行业景气方向 → 决定行业主题 ETF 的大方向
3. **结构健康度**：组合集中度/重复持仓/攻防配比 → 决定是否需要结构调整
4. **技术择时**：趋势/估值分位/资金信号 → 决定具体买卖点位与节奏

**冲突场景处理**：
- 宏观看多 vs 技术看空 → 倾向持有/观望，等技术信号转多再加仓（写明理由）
- 宏观看空 vs 技术看多 → 倾向减仓但不清仓，保留底仓等宏观明朗（写明理由）
- 结构警示 vs 技术看好 → 先做结构调整（合并/替换），再按技术信号操作新标的（写明理由）

> 仲裁结论必须落到具体操作，禁止"建议谨慎/均衡对待"等含糊表述。

## 四、对话模式 vs 报告模式

| 维度 | 对话模式（默认） | 报告模式（按需） |
|------|----------------|----------------|
| **触发** | 用户未要求"输出报告" | 用户明确说"出一份报告/生成建议书" |
| **载体** | 直接在对话中回答 | 落盘结构化文档（用户要求时可附 HTML） |
| **门禁** | Agent 自检内容质量 + 交叉透明两项（见下） | 必须 GATE 0-4 全部 PASS |
| **深度** | 与报告模式一致，不做降级 | 与对话模式一致，不做加码 |

**对话模式内容底线**：
1. 不模糊措辞——每个判断必须给具体数据+来源+时效
2. 不跳数据——即使对话也按「📊 数据 → 🔍 推导 → 📌 结论」三段式骨架
3. 必给明确方向——买卖类问题必须落到"买入/卖出/持有/加减仓/观望"之一
4. 必标信源——关键数据后标注来源+时效
5. **交叉透明两项（v1.5.0，对话模式也不豁免）**：①本次结论与近期交付物冲突时必须在对话中显式声明差异（或附联动对照表），禁止静默冲突；②仓位百分比必须带分母+层面标注，禁止裸百分数

## 五、铁律

1. **GATE 串行必须全过**：GATE 0→1→2→3→4 串行，任一 FAIL 则阻断，不允许跳过
2. **BLOCK 后必须补写**：被拦截时唯一合法动作是补写缺失内容，不允许删章节/删推导来压缩篇幅
3. **静默执行**：门禁在 Agent 内部执行，用户只看到通过后的最终版本
4. **数据缺失如实标注**：查不到的数据标注"[未获取]"并说明对结论的影响，严禁编造
5. **结论盒子独立于 GATE**：对话中的快速结论盒子（≤500字）不受 GATE 约束，可先行输出
