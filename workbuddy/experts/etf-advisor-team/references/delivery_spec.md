# 交付规范（ETF 团队版）

> **本文件定位**：ETF 投资顾问专家团共享的交付层规范，回答"怎么交付、交付什么、不能出现什么"。
>
> **职责分工**：本文件=交付层；`quality_gate.md`=门禁层；各 agent .md=角色方法论层；`output_template.md`=模板层。

---

## 一、两种交付模式

| 维度 | 对话模式（默认） | 报告模式（按需） |
|------|----------------|----------------|
| **触发** | 用户未要求"输出报告/生成建议书" | 用户明确说"出报告/生成建议书/写一份" |
| **载体** | 直接在对话中回答（纯文字） | 结构化文档（默认 Markdown；用户要求时可附 HTML） |
| **门禁** | Agent 自检内容质量（含口径与层面自检） | 必须 `quality_gate.md` GATE 0-4 全 PASS |
| **图表** | 不出现 | 仅在 HTML 中以内嵌 SVG 呈现，Markdown 保持纯文字 |
| **方法论深度** | **完全一致、不做降级** | **完全一致、不做降级** |

**核心一致性原则**："深度"是两种模式共同的底线；"形式"是两者的差异点。

## 二、对话模式规范

### 2.1 内容底线四条
1. **不模糊措辞**：禁止"基本面良好/趋势向好/政策友好"等空话。每个判断必须给具体数据+来源+时效
2. **不跳数据**：即使对话也按「📊 数据 → 🔍 推导 → 📌 结论」三段式骨架（可紧凑，不强制独立成段）
3. **必给明确方向**：买卖类问题必须落到"买入/卖出/持有/加减仓/观望"之一
4. **必标信源**：关键数据后标注来源+时效（行内"（东财，2026-08-16）"或脚标均可）

### 2.2 对话模式三段式紧凑写法示例

```
📊 数据：中证500ETF 现价 6.20，跟踪指数 PE 处近10年 25%分位（中证指数公司，2026-08-15）；
        近3月份额增长 8%（东财，2026-08-16）。

🔍 推导：估值处于低估区，份额持续增长说明被动资金在低位承接；
        均线系统多头排列，MACD 零轴上方。

📌 结论：倾向买入区。回踩 6.05-6.10 分批买入，止损 5.85 下方。
```

### 2.3 对话模式收尾
综合买卖决策对话结尾**必须**附正式报告引导：
> "如需完整的《ETF 交易建议书》（含信号融合表+逐只操作卡+调仓执行顺序），请告知，我可输出结构化报告。"

## 三、报告模式流程

### 3.1 报告模式标准流程

```
① 数据采集（各成员按职责采集：持仓诊断/技术/宏观）
 ↓
② 成员分析（Phase 1 三路并行 → Phase 2 风险终审）
 ↓
③ 主理人汇编《ETF 交易建议书》（结构见 output_template.md）
 ↓
④ 质量门禁自检（GATE 0-4 串行，见 quality_gate.md）
 FAIL → 补写缺失内容 → 重检
 PASS ↓
⑤ 对话轻量交付
 · ≤500 字快速结论盒子（覆盖四问：能不能做/什么价位/做多少/做错了怎么办）
 · Gate 摘要一行
 · 文件路径
 · 不重复贴全文
```

### 3.2 报告模式交付前三问自检

Gate PASS 后交付前，主理人内部回答以下三问，全部为"是"才算合格：
1. 📁 文档是否已写入并含八大模块（组合总览/配置中枢/信号融合表/操作卡/执行顺序/风险提示/再平衡/合规）？
2. 💬 对话中的结论盒子是否直接回答了用户核心问题（四问齐全）？
3. ✅ GATE 0-4 是否全部 PASS？

### 3.3 严禁的收尾方式
- 只给文件路径、**不给结论盒子**——用户没法从对话里直接获得核心判断
- Gate FAIL 却仍然交付
- 在对话中重复贴完整报告正文（文件已落盘，重复贴浪费 tokens）

### 3.4 标准收尾文案

> ✅ 《ETF 交易建议书》已汇编完成（GATE PASS · 覆盖 N 只标的）：
>
> [≤500 字快速结论盒子：组合总览 + 核心操作 + 关键风险]
>
> 完整建议书含信号融合表、逐只操作卡、调仓执行顺序，请查看交付文档。

## 四、三段式书写规范（所有交付强制）

每个分析章节必须遵循 **「📊 关键数据 → 🔍 分析推导 → 📌 小结论」** 三段式：

- **📊 关键数据**：原始数据+来源+时间（表格或行内）
- **🔍 分析推导**：基于数据的逻辑推导，写明"这个结论怎么来的"
- **📌 小结论**：明确的结论（评级/方向/操作倾向）

**三段式硬规则**：
1. 每个核心章节三段齐全，少一段视为不合格
2. 禁止跳过数据直接抛结论
3. 禁止只列数据不给推导
4. 禁止推导与数据脱节

## 五、数据信源标注规范

### 5.1 信源展示总规则
- 正式报告中引用来源时，**只写原始信源名称或原始 URL**（如"中证指数公司""东方财富""https://..."）
- **不要写本地中间文件名或工作路径**（如 `FinancialData/...`）
- 信源优先级：官方源头（政府/央行/交易所/指数公司）> 权威整合（东方财富/天天基金）> 媒体转引

### 5.2 信源标注方式
- 行内标注：`现价 6.20（东财，2026-08-16）`
- 脚标标注：`现价 6.20<sup>1</sup>` + 末尾信源汇总表

### 5.3 信源汇总表标准格式（报告模式附录必含）

| 编号 | 信源名称 | 信源类型 | URL / 获取方式 | 数据时效 |
|------|---------|---------|---------------|---------|
| 1 | 中证指数公司 | 指数官方 | https://www.csindex.com.cn/ | 2026-08-15 |
| 2 | 东方财富天天基金 | 金融数据平台 | https://fund.eastmoney.com/ | 2026-08-16 |

### 5.4 禁止的信源形态
- ❌ D 类伪信源：Wind/Bloomberg/iFinD/Choice 等付费终端作为信源名称
- ❌ 本地路径：`C:\Users\...` 或 `FinancialData/...` 作为信源 URL
- ❌ 工程文件名：`xxx.json`/`xxx.md` 作为信源名称
- ❌ 无 URL 的"AI 估算"——事实型数据禁 AI 估算

## 六、合规措辞规范

### 6.1 必须使用的审慎措辞
- "候选操作：买入（参考）" 代替 "建议买入"
- "业绩比较基准" 代替 "年化 X%"
- "波动相对可控" 代替 "稳健"
- "候选之一" 代替 "推荐"

### 6.2 禁止的违规表述
- ❌ "保证收益""稳赚""必涨""无风险"
- ❌ "强烈推荐买入""确定性机会"
- ❌ 任何形式的收益承诺

### 6.3 必含免责声明
所有交付（对话/报告）末尾必须含四要素统一模板（AI 生成 + 公开信息 + 不构成投资建议 + 不构成个股推荐）：
> "⚠️ 以上内容由 AI 基于公开信息整理生成，仅供参考，不构成任何投资建议或个股推荐。投资有风险，决策需谨慎。"

## 七、HTML 可视化（按需可选）

- **默认不产出 HTML**：报告模式默认产出 Markdown 纯文字
- **按需产出 HTML**：仅当用户明确要求"可视化版/HTML/网页版/带图表的"时，主理人可组织生成含内嵌 SVG 图表的 HTML
- **HTML 图表原则**：
  - 同量纲优先（口径一致才做图表）
  - 服务结论，不为装饰
  - A 股配色：红涨绿跌
  - 定性段落默认不画图
  - **图表精度硬约束**：任何图表（饼图/柱状/折线等）的几何参数必须与数据严格对应——饼图扇形角度 = 占比×360°、柱状高度 = 数值×比例尺，必须用程序化计算（Python/JS）生成 SVG，**禁止手估 path 弧度**；若无法精确计算则改用表格替代，宁缺毋滥（错误的图比没有图更糟）
- **图表类型建议**：K线+均线、估值分位仪表盘、资金流趋势、行业景气度热力图、组合配置饼图

## 九、口径与层面规范（v1.5.0，所有交付强制）

> **背景**：同日"组合建议书 35% vs 单标的决策 25%"事件——两个百分数分母不同（总资产 vs 可用现金）、层面不同（配置层 vs 执行层），未标注分母与层面即被误读为矛盾。本节杜绝此类歧义。

### 9.1 仓位百分比强制双标注

所有仓位/比例数字必须同时标注：

- **分母**：`占总资产 X%（≈Y 元）` / `占可用现金 X%（≈Y 元）` / `占某类资产额度 X%`——三选一，禁止裸百分数
- **层面**：**配置层**（组合资产配置决策，回答"组合里该给多少"）或 **执行层**（单笔交易纪律，回答"这一笔怎么投"）

标准写法示例：
- ✅ `目标仓位：占总资产 35%（≈21,200 元）｜配置层`
- ✅ `首笔投入：占可用现金 10%（≈4,500 元）｜执行层`
- ❌ `目标仓位 35%`（裸百分数，无分母无层面 → GATE 4 拦截）

### 9.2 两层结论的关系（防暗中融合）

- 配置层结论（组合建议书）与执行层结论（单标的咨询）是**不同层面问题的答案**，数值不同 ≠ 矛盾；
- 两层结论出现在同一工作区时，交付物必须通过**联动对照表**显式摆明差异（模板见 `output_template.md`），由用户取舍；
- **禁止主理人在任何交付物中暗中调和/融合两套数字为一套**；两套结论的最终取舍权在用户。

### 9.3 检查归属

- 对话模式：主理人自检（发现裸百分数当场补标注）
- 报告模式：GATE 4 逐项核验（见 `quality_gate.md`）
