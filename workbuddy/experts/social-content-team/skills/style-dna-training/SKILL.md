# 风格养成（Style DNA Training）

把 3-5 篇代表作品，提炼成一份**结构化、可复用、可跨会话调用**的写作风格档案（风格 DNA）。之后任何创作都能挂载这份 DNA，让产出稳定地"像本人写的"。

> **能力来源**：抽离自 caizhi「风格养成」已跑通实现（12 维度分析 + 结构蓝图 + 标题风格三轮提炼），已去除财经垂类耦合，适用于任意行业。

---

## 何时使用本 Skill

- 用户说"AI 写的没有我的味道 / 一股 AI 味 / 不像我写的"
- 用户要建立个人 IP、账号人格，需要文风稳定统一
- 用户想学习某个标杆账号的文风
- 用户在做内容矩阵，需要多个风格档案分别管理（如"我的风格""公司官号风格""对标大V风格"）

---

## 核心设计原则

1. **产出的是资产，不是文章**——本 Skill 的交付物是一份可存档、可命名、可被其他创作 Skill 读取的档案
2. **必须给证据**——每条风格特征都要附原文词汇/句式/片段作为证据，禁止空泛描述（"文笔优美"这类无效结论）
3. **第二人称输出**——用户看的是自己的画像，一律用"你"，禁止用"作者""他/她"
4. **行业无关**——只分析"怎么写"（表达特征），不预设"写什么"（行业内容）。行业相关信息由用户自述提供，AI 负责验证与细化
5. **主线是养成自己的风格，不是模仿别人**——学标杆只是养成过程中的参考手段，最终目的是长出用户自己的辨识度

## 三条路径：先判断用户处于哪种情况

| 用户状态 | 走哪条路径 | 产出 |
|---|---|---|
| **已有账号、有 3-5 篇作品** | 路径 A：样本提取（三轮提炼，见下文） | 风格 DNA 档案（confidence: high） |
| **没有账号 / 没有作品** | 路径 B：**风格共创**（访谈 + 对标参考 + 样例偏好） | 初始风格档案（confidence: low，假设态） |
| **品牌官号（多人协作）** | 路径 C：品牌调性档案（见"个人线 vs 品牌线"） | 品牌调性档案 + 品牌禁区 |

### 路径 B：风格共创（无作品时的初始风格生成）

**目标**：用户还没有内容产出时，先形成可用的初始风格假设，随后用真实作品持续校准。

**三种输入手段，可组合：**

**1. 五问访谈（固定 5 个问题，不得超过——问多了用户会烦且回答质量下降）**

| # | 问题 | 提取维度 |
|---|---|---|
| 1 | 你平时跟朋友聊这个话题，一般会怎么开口？（可以直接说一段） | 语气人称、开场习惯、口语特征 |
| 2 | 你最想让读者看完有什么感觉？（学到东西 / 被说中 / 被逗笑 / 觉得靠谱 / 被激励） | 情感基调、内容目的 |
| 3 | 你有什么别人不容易有的经历、身份或专业背景？ | 身份标签、可信度来源、差异化 |
| 4 | 你讲道理时习惯怎么讲？（讲自己的故事 / 摆数据 / 打比方 / 拆步骤 / 反问引导） | 论证方式、说服路径 |
| 5 | 有什么话你说不出口、或者特别不想变成的那种账号？ | 回避词汇、风格禁区、反向定位 |

可就回答追问细节，但主问题只有这 5 个。

**2. 对标账号参考（可选）**
让用户提供 1-3 个喜欢的账号，说明**具体喜欢哪一点**（结构 / 语气 / 选题角度 / 节奏）。**允许混合**——"想要 A 的结构 + B 的语气"是合理需求。
⚠️ 硬约束：对标只作**风格来源参考**，不得整体照搬。档案必须写清"哪些特征借自对标、哪些来自用户本人"，并主动指出两者冲突处（如用户自述温和但对标犀利）让用户选择。

**3. 样例偏好选择（可选，效果好）**
就用户的实际选题，写 2-3 段风格明显不同的短样例（如数据理性版 / 亲历故事版 / 犀利观点版），让用户选或指出更接近哪个、要改哪里。**从"选择"里提取偏好比从"描述"里提取更准**——用户常说不清想要什么，但一看就知道喜不喜欢。

**共创产出要求：**
- 档案标记 `confidence: low` + `status: hypothesis`
- 明确列出"待验证项"：哪些维度是推测的、需真实作品确认
- 给出下一步行动：建议先按此风格写 3-5 篇，之后回来校准（走路径 A 升级档案）

### 养成机制：假设 → 校准 → 稳定

风格养成不是一次提取，而是持续迭代：

| 阶段 | 触发 | 动作 | confidence |
|---|---|---|---|
| 初始 | 无作品 | 路径 B 共创 | low（假设态） |
| 校准 | 产出 3-5 篇真实内容后 | 用真实样本跑路径 A，对比假设与实际差异并修正 | medium |
| 稳定 | 累积 10 篇以上 | 增量更新，只改变化的维度 | high |
| 演进 | 用户主动要求调整（"想更活泼""换方向"） | 定向修改相关维度，保留变更记录 | 维持 |

**增量更新规则**：不重写整份档案，只改变化的维度，并在 `changelog` 追加一行"改了什么 + 为什么"——用户能看到自己风格的成长轨迹。

### 个人线 vs 品牌线（两条线逻辑不同，不可混用）

| | 个人 IP 风格 | 品牌官号调性 |
|---|---|---|
| 来源 | 真实经历、语言习惯、观点偏好 | 品牌手册、行业合规约束、多人协作需求 |
| 目标 | **辨识度**——越像你自己越好 | **一致性**——任何运营写出来都一个味 |
| 禁忌 | 写得像别人 | **越写越像某个具体的人** |
| 档案额外内容 | 个人经历素材库、观点立场 | **品牌禁区**（不能说什么、不能用什么语气）+ **多人协作校准说明**（新运营拿档案就能对齐） |
| 演进方式 | 随个人成长自然演进 | 须与品牌方确认后才可变更 |

品牌线注意：强监管行业（金融/医疗/教育等）的品牌禁区必须包含法规红线，不只是调性偏好。

## 执行流程（三轮提炼，顺序执行）

### 第 0 步：收集输入

**必需**：
- 历史作品：**建议 3-5 篇**（最少 1 篇可跑，但少于 3 篇需提示"样本偏少，画像可能不够稳定"）
- 支持形式：直接粘贴正文 / 上传文件（.txt / .md / .docx / .pdf）

**选填（有则显著提升准确度）**：
| 字段 | 说明 |
|---|---|
| 账号/笔名 | 用于命名档案 |
| 主要平台 | 公众号 / 视频号 / 小红书 / 头条 / 知乎 / X / LinkedIn / 其他 |
| 粉丝量级 | <1万 / 1-10万 / 10-50万 / 50万+ |
| 定位自述 | 一句话描述账号定位 |
| 目标受众 | 一句话描述目标读者 |

> **对自述信息的处理规则**：
> 1. 用户自述为参考，需在分析文章后**验证是否与实际文风匹配**（不匹配要指出）
> 2. "身份与受众"维度以用户自述为基础，结合文章内容细化补充
> 3. "代表主题"完全由你从文章中提取，**不受用户自述限制**

## 请从以下12个维度进行深度分析

请严格按以下格式输出，每个维度用二级标题（## ）标记。注意：输出请使用第二人称"你"来描述（因为用户看的是自己的风格画像）。

## 🎭 一、身份与受众
1. 结合用户自述和文章内容，精准描述你的**账号定位**（围绕什么领域输出什么类型的内容？）
2. 结合用户自述和行文深度/用词门槛，描述你的目标读者/粉丝画像
3. 从文章内容中提取你最擅长/最常写的**代表主题**（列举5-10个关键词标签）

## 📝 二、用词偏好
4. 语气标签：整体语气是什么风格？（如：数据驱动、直接犀利、温和亲民）
5. 高频动词有哪些？（列举5-8个）
6. 高频形容词有哪些？（列举5-8个）
7. 有没有你特别爱用的"口头禅"式表述？
8. 有没有你明显回避的词汇？

## 📐 三、句式与节奏
9. 平均句子长度偏长/中/短？
10. 常用句式类型（如：排比、反问、设问、短句群、长复句）
11. 段落节奏：是"快节奏多短段"还是"慢节奏长段深度"？
12. 有没有你标志性的"段落间过渡"方式？

## 🏗 四、论述结构
13. 常见的文章结构是什么？（如：总分总、并列式、递进式、对比式）
14. 开篇喜欢怎么切入？（数据冲击、故事引入、痛点共鸣、直接给结论）
15. 结尾的收束习惯？（金句总结、号召行动、反问留白、展望未来）

## 💡 五、论证方式
16. 你最依赖的论证方式是什么？（数据佐证、权威引用、案例推理、逻辑演绎）
17. 论证中是否常用对比/类比？
18. 有没有特殊的"说服力技巧"？（如：先立后破、自我反驳、预设读者质疑）

## 💫 六、情感基调
19. 整体情感基调是什么？（如：冷静理性、热血激情、温和亲切、戏谑讽刺）
20. 情感是否有起伏变化规律？
21. 在讨论不同主题时，情感表达有没有明显差异？

## 🔭 七、视角与立场
22. 你通常用什么视角写作？（第一人称亲历、第二人称对话、第三人称旁观）
23. 在争议话题上你的立场倾向？（旗帜鲜明/中立呈现/辩证平衡）
24. 你如何处理"不确定"的信息？（明确标注/模糊带过/回避不谈）

## 📰 八、话题选择与时效
25. 话题选择偏好？（追热点/常青知识/两者兼有）
26. 对时效性话题的响应速度和深度？
27. 有没有你特别回避的话题领域？

## 📊 九、数据与事实使用习惯
28. 你如何使用数据/事实依据？（大量数据+解读/少量数据点缀/几乎不用）
29. 呈现方式？（直接引用、图表辅助、类比换算、读者可感知的比喻）
30. 是否有固定的引用来源偏好？

## 📚 十、引用习惯
31. 你是否经常引用他人观点？（名人名言、书籍摘录、行业报告）
32. 引用的来源偏好？（学术权威、行业大佬、自身经验、读者反馈）
33. 引用后通常如何处理？（进一步论证、质疑反驳、延伸发散）

## 📏 十一、篇幅偏好
34. 你偏好的内容篇幅？（短平快<800字/中等800-2000字/长文>2000字）
35. 不同篇幅的内容分配逻辑？

## ✨ 十二、独特标识 & 核心标签
36. 有没有你**独有的**、一看就知道是你风格的表达方式？
37. 与同类型其他创作者相比，你最大的差异化特征是什么？
38. 用5-8个关键标签词概括你的风格特征，格式：【标签1】【标签2】【标签3】...

## 输出：风格 DNA 档案（标准数据结构）

三轮完成后，组装为如下档案。**这是跨 Skill 的接口标准，字段不可随意增删。**

```json
{
  "profile_id": "唯一标识",
  "name": "风格名称（用户自定义，默认「我的风格」）",
  "is_default": true,

  "account": {
    "account_name": "笔名/账号名",
    "platform": "wechat|video|xiaohongshu|toutiao|zhihu|x|linkedin|other",
    "platform_id": "账号ID或主页链接（选填）",
    "follower_scale": "<1万|1-10万|10-50万|50万+",
    "self_positioning": "用户自述定位",
    "self_audience": "用户自述目标受众"
  },

  "style_summary": "一句话风格概述（20-50字，第2人称）",
  "style_portrait": "风格画像总结（200字内）",
  "analysis_result": "12维度完整分析文本（Markdown，二级标题分维度）",
  "structure_blueprint": "结构蓝图（幕式结构纯文本）",
  "title_style": "惯用标题风格（纯文本）",

  "tags": ["标签1", "标签2", "..."],
  "keywords": ["专属关键词/手动偏好"],

  "source_materials": [
    { "title": "作品标题", "summary": "摘要（不存全文）" }
  ],
  "material_count": 5,
  "use_count": 0,
  "status": "active|archived",
  "created_at": "",
  "updated_at": ""
}
```

**字段说明要点：**
- `style_portrait` 是**创作时注入 Prompt 的主字段**（200 字内，控制 token 成本）
- `analysis_result` 是**完整版**，供用户查看/导出，创作时按需截取
- `structure_blueprint` / `title_style` 是独立字段，可被"结构骨架"和"标题创作"能力单独调用
- `source_materials` **只存标题+摘要，不存全文**（隐私与存储成本）

## 档案管理规则

| 能力 | 规则 |
|---|---|
| 多档案 | 支持同一用户存多份（我的风格 / 官号风格 / 对标账号风格） |
| 默认档案 | 有且仅有一个 `is_default=true`，创作时默认挂载 |
| 命名 | 用户可自定义，默认「我的风格」 |
| 使用计数 | 每次被创作调用时 `use_count +1`（用于识别最常用风格） |
| 归档 | `status=archived` 软删除，不物理删除 |
| 导出 | 支持导出为 Word / PDF / Markdown（含 12 维度 + 结构蓝图 + 标题风格） |

## 档案落地：存哪里、用户怎么看、怎么用（必须执行）

### 1. 存储：写入 workspace memory（主路径）

档案产出后，**由主理人写入** `{workspace}/.workbuddy/memory/style-profile.md`（品牌线写 `brand-tone-profile.md`）。这样新会话开始时档案会随 memory 注入上下文，AI 能"记住"用户的风格。

- 存储格式用 **Markdown**（AI 可直接读，是档案"真身"）
- 已存在同名档案时**增量更新**，不覆盖重写；在 `changelog` 追加变更行
- 多档案（我的风格 / 官号风格 / 对标参考）用不同文件名或在同一文件内分节，标明哪个是默认

### 2. 呈现：按需生成"风格身份证"HTML（给用户看）

用户想查看档案时，生成一页 HTML 卡片（可保存/分享），包含：一句话风格概述、12 维雷达或清单、代表句式示例、标志性表达、成长轨迹（changelog）。
⚠️ HTML 只是**呈现层**，不是存储格式——不要用 HTML 存档案。

### 3. 档案必须自带「怎么用」说明（关键，不可省略）

档案文件末尾必须包含这一节，用大白话写清四件事。用户不看说明就不知道这东西怎么用：

```markdown
## 怎么用这份风格档案

**什么时候用得上**
- 让 AI 帮你写内容时（会按你的风格写，不是通用 AI 腔）
- 自己写完想检查"像不像我平时的样子"
- 内容有 AI 味、读起来不像自己写的时候
- 团队里有人帮你代笔，给他这份档案就能对齐

**怎么让 AI 用**
直接说"按我的风格写XX"就行——档案已存在这个工作区，AI 会自动读取。
如果换了工作区或换了电脑，把这个文件发给 AI，说"这是我的风格档案，按它来写"。

**什么时候该更新**
- 又写了 3-5 篇新内容（可以让风格更准）
- 想调整风格方向（比如想更活泼、想更专业）
- 换了主要平台（小红书和公众号的表达方式不一样）
说一句"更新我的风格档案"即可，不用从头再来。

**怎么带走**
这份档案存在当前工作区，换电脑不会自动同步。需要跨设备用的话，把文件另存一份保管好。
```

### 4. 跨环境限制（要主动告知用户，不要让他以为是云端账号）

| 限制 | 说明 |
|---|---|
| 按 workspace 隔离 | 换工作目录读不到，需手动带文件 |
| 非云端同步 | 换电脑、重装不会自动同步 |
| 不写入专家包 | 档案属于用户数据，绝不能写进技能包目录（会污染包，且分享给他人时带上你的风格） |

## 行业泛化机制

本 Skill 内核（分析"怎么写"）**天然与行业无关**，可通过可选的行业包增强：

| 插件 | 作用 | 示例 |
|---|---|---|
| 行业术语表 | 识别该行业特有表达，避免误判为"生僻词" | 金融、医美、教培、SaaS、母婴… |
| 红线词库 | 提炼时标注需规避的表达 | 金融=承诺收益；医美=疗效宣称；教培=保过 |
| 平台范式库 | 结合平台特性校准分析（如小红书的 emoji 密度、标签习惯） | 公众号 / 小红书 / 视频号 / X / LinkedIn |

> **无行业包时完全可用**——行业包只提升精度，不是运行前提。

## 质量校验清单（输出前自查）

- [ ] 每个维度都有原文证据，没有空泛结论
- [ ] 全程第二人称"你"，无"作者""他/她"
- [ ] 结构蓝图的幕名有辨识度，不是"开头/中间/结尾"
- [ ] 未使用 markdown 加粗（`**`）——结构蓝图与标题风格为纯文本
- [ ] `style_summary` 是大白话、有辨识度、20-50 字
- [ ] 若样本 < 3 篇，已提示用户"样本偏少，画像可能不稳定"
- [ ] 用户自述与实际文风不符时，已明确指出差异

## 常见问题处理

| 情况 | 处理方式 |
|---|---|
| 只有 1-2 篇样本 | 可跑，但明确提示画像稳定性不足，建议补到 3-5 篇 |
| 样本风格差异很大 | 指出存在多种风格倾向，建议拆成多个档案分别养成 |
| 样本是他人作品（学标杆） | 正常提炼，但档案命名建议标注来源（如"对标-XX风格"） |
| 样本过长 | 12 维度轮单篇截取 3000 字，结构轮 2500 字，标题轮 500 字摘要 |
| 用户自述与文风明显不符 | 在「身份与受众」维度指出差异，以文章实证为准 |
