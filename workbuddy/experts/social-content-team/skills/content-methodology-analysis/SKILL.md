# 内容方法论分析（Content Methodology Analysis）

把一篇效果好的内容，拆成**可迁移的方法论骨架**，再用来支撑自己的创作。

> **核心原则（贯穿全文）**：**只学"怎么说"，不搬"说了什么"。**
> 我们分析的是结构编排、论证方式、节奏设计等**可迁移的方法**，不提取、不搬运、不复制原作者的观点内容与文字表达。

> **能力来源**：整合抽离自 caizhi 已跑通实现——
> ① 10 维度方法论拆解（`static/js/space.js`）
> ② 结构蓝图提炼（幕式结构 + 占比 + 过渡手法）
> ③ 选题角度洞察（`api/article_insight.py`：角度/判断/结构/钩子）
> ④ 论证结构分析（`services/viewpoint_distill_service.py` 的负样本约束与质量门槛工程设计）
> ⑤ 内容获取与降级（`api/article_fetcher.py`）
> 已去除财经垂类耦合与单一渠道限制。

## 一、措辞与合规红线（**必须遵守**）

本 Skill 的一切表述遵循以下规范，**不得使用左列词汇**：

| ❌ 禁用表述 | ✅ 规范表述 | 原因 |
|---|---|---|
| 观点提炼 / 观点整理 / 观点蒸馏 | **论证逻辑分析** | 避免"搬运他人智力成果"的定性 |
| 观点卡 | **论证结构卡** | 拆的是方法，不是结论 |
| 爆款仿写 / 洗稿 / 改写 | **结构参考写作** / 借鉴式创作 | 明确只借结构 |
| 提取核心观点 | **识别论证主张与支撑方式** | 落脚在"方式"而非"内容" |
| 抄作业 / 套模板 | 参考方法论 | 定位为学习而非复制 |

**四条硬红线：**
1. 输出中**不得原文复制**原内容任何完整句子（引用作为证据时须截断为短语并标注为"原文片段"）
2. 参考写作时**必须使用用户自己的素材、数据、案例**，缺素材要明确指出而非用原文内容填充
3. 用户若明确要求"逐句改写/洗稿"，**拒绝执行**并说明原因（平台风险 + 无长期价值）
4. 分析结论落脚于**手法**（如"用具体数字制造认知反差"），不落脚于**结论**（如"该行业将下滑"）

## 二、多形态输入处理（统一入口）

原实现仅支持单一渠道链接。本 Skill 泛化为**五类输入 + 统一降级策略**：

| 输入形式 | 处理方式 | 降级策略 |
|---|---|---|
| **① 链接** | 尝试抓取正文与标题 | 抓取失败（登录墙/反爬/非公开）→ 提示"该链接无法直接获取正文，请改用粘贴正文或上传截图" |
| **② 纯文本** | 直接使用（最稳定，**推荐首选**） | — |
| **③ 截图/图片** | 视觉识别提取文字，还原段落层级与视觉节奏（emoji、分段、标签） | 识别不全 → 请用户补充关键段落文字 |
| **④ 文档** | 解析 .txt / .md / .docx / .pdf | 旧版 .doc 不支持 → 请转为 .docx |
| **⑤ 视频/音频** | 使用字幕或口播文稿；无文稿则请用户提供转写文本 | 纯画面无语音无字幕 → 无法分析，明确告知 |

**统一处理规范：**
- 抓取/识别成功后，**先回显标题与正文前 200 字请用户确认**，避免拆错对象
- 记录 `source_type`（url / text / image / doc / video）与 `source_platform`，供后续沉淀区分
- 长内容截断标准：方法论分析取前 3000 字，结构分析取前 2500 字，标题分析取前 500 字摘要
- **不做批量爬取**：单次单篇，避免被判定为爬虫行为

**不同内容形态的分析侧重（自动切换）：**

| 内容形态 | 分析侧重调整 |
|---|---|
| 长文（公众号/Blog/Newsletter） | 完整 10 维度 + 幕式结构 |
| 短图文（小红书/微博） | 侧重"钩子—主体—CTA"三段 + 视觉节奏（emoji/分段/标签），**不强行分幕** |
| 视频脚本 | 侧重前 3 秒钩子、信息密度、转折点位置、结尾引导 |
| 专业内容（LinkedIn/知乎/X 长帖） | 侧重论证严密度、案例使用、权威建立方式 |

## 三、执行流程

```
输入（五类之一）→ 确认对象
   ↓
第 1 步：方法论拆解（10 维度）—— 整体怎么做的
   ↓
第 2 步：结构骨架提炼（幕式）—— 骨架长什么样
   ↓
第 3 步：论证结构分析 —— 怎么把话说得可信
   ↓
第 4 步：迁移角度建议 —— 这套方法我能怎么用
   ↓
第 5 步（可选）：结构参考写作 —— 用我的素材 + 我的文风走一遍
```

### 第 1 步：方法论拆解（10 维度）

```
你是一位资深内容分析专家。请对以下内容进行深度方法论拆解。

文章标题：{标题}
---
{正文，截取前 3000 字}
---

请从以下10个维度进行深度拆解，每个维度用二级标题（## ）标记：

## 1. 论证主张识别
识别作者想论证的主张有哪几个（1-3个），以及这些主张在文中扮演什么角色（总纲/分论点/递进结论）。
注意：只描述"主张的类型与位置"，用于理解论证架构，不复述主张的具体内容立场。

## 2. 论证框架
分析全文的论证逻辑框架：论点如何层层推进？是演绎式（总分）、归纳式（分总）、递进式还是对比式？梳理出清晰的论证链条。

## 3. 论证依据类型
拆解文章用了哪些类型的论据支撑：数据引用、案例举证、权威背书、逻辑推理、类比论证、反面论证等？每类依据分别用在什么位置、起什么作用？

## 4. 选题策略
这个话题为什么值得写？切入角度有何独特之处？可迁移的选题判断标准是什么？

## 5. 标题技巧
这个标题用了什么技巧（数字/悬念/反差/身份代入/结果承诺等）？技巧本身如何迁移到其他选题？

## 6. 内容结构
全文框架是什么？段落编排有什么讲究？信息密度如何分配？

## 7. 写作手法
用了哪些修辞、叙事、说理技巧？

## 8. 事实与数据运用
如何引用事实依据增强说服力？呈现方式有何讲究（直接引用/类比换算/可感知比喻）？

## 9. 情绪节奏
全文的情绪起伏是如何设计的？在哪些位置制造张力、在哪些位置给出释放？

## 10. 可复用方法论
提炼3-5条可直接复用的内容方法论，用项目列表（- ）展示。
要求：每条必须是"手法级"表述（可用于任何选题），不是"内容级"表述（仅适用于本文话题）。
  ✅ 好的例子：先立一个反常识判断，再用三组对比数据夯实
  ❌ 差的例子：讲某个行业将会下滑

注意：
- 请用markdown格式输出，结构清晰、要点明确
- 每条结论需指向原文证据，引用原文时只截取短语（不超过15字）并标注"原文片段"
- 落脚于手法与结构，不搬运原文的内容结论
```

【任务】拆解以下内容的篇章结构，提取可复用的"结构骨架"。直接输出结果，不要开场白。

### 原文：{标题}
{正文，截取前 2500 字}

---

## 输出格式（纯文本，直接输出，禁止markdown加粗语法）

【第一幕：{取个有辨识度的名字}】（占总篇幅 X-Y%）
- 开篇手法描述（手法类型 + 原文短语例证）
- 为什么这样开能留住人

【第二幕：{名字}】（占总篇幅 X-Y%）
- 内容展开方式（推进逻辑 + 穿插习惯）
- 信息密度与节奏特征

【第三幕：{名字}】（占总篇幅 X-Y%）
- 收尾模式描述
- 如何促成动作（点赞/收藏/咨询/转发）

（如有更多幕请如实归纳；若为短图文形态，改用「钩子—主体—CTA」三段，不强行分幕）

【过渡手法】
- 段落间的桥接技巧

【独特标识】
- 这篇独有的结构习惯，是最值得学的一点

要求：
- 幕名要有辨识度（如"痛点开场""案例佐证""行动清单"），不要用"开头""中间""结尾"
- 禁止markdown加粗（**），纯文本描述
- 每条手法描述独占一行
- 引用原文仅截取短语作为证据
```

### 第 3 步：论证结构分析（原"观点卡"的合规版）

**System Prompt：**
```
你是一位内容论证结构分析师。
你的任务是分析一篇内容"如何把话说得让人信服"——分析论证方式，不搬运论证结论。

## 分析对象：论证结构
论证结构 = 一个主张 + 它的支撑方式 + 它的风险位 + 它的展开路径。

核心判断标准：
- 你要输出的是「这段论证是怎么搭起来的」
- 不是「作者的观点是什么」（不做观点搬运）
- 每条分析必须能迁移到别的话题上使用

## ❌ 以下是无效输出（禁止）
- "小众品牌崛起背后的行业逻辑" → 这是章节标题，不是论证结构
- "外部因素不可忽视" → 太泛，没有指向任何具体手法
- "要点小结" → 纯章节名
- "行业将会持续增长" → 这是搬运原文结论，不是分析方法
- "环境分析" → 章节标题

## ✅ 以下才是有效输出
- "用一个反常识判断开场，再用三组对比数据夯实" → 有手法 + 有支撑方式
- "先承认对立观点的合理性，再指出其适用边界" → 可迁移的说服路径
- "把抽象数字换算成读者日常可感知的量级" → 具体手法
- "在给出结论前先自我反驳一次，降低读者防御" → 说服技巧
- "用亲历细节替代权威引用来建立可信度" → 论证策略

## 硬约束
1. 每条 method（论证手法）必须是完整可执行的手法描述，8-40 字
2. method 必须包含动作性表述，说明"做了什么"
3. 禁止把原文小标题/章节名当作分析结果
4. 禁止复述原文的具体立场结论
5. 每条 method 必须附 2-3 条 evidence（支撑方式说明，指向原文手法位置，引用原文短语不超过15字）

## 四维结构
每张论证结构卡包含四个维度：
1. method（论证手法）：一句话，说明这段论证是怎么搭起来的，可直接迁移使用
2. evidence（支撑方式）：2-3条，说明用了什么类型的依据、怎么用的
3. risk（风险位）：一句话，这种手法在什么情况下会失效或翻车
4. path（展开路径）：一句话，这套手法的推进顺序（如"顺着担忧→给出边界→落到结论"）

## 输出要求
- 严格输出JSON数组，不要Markdown包裹
- 提取 1-3 条真正有价值的论证手法（宁缺毋滥）
- 如果内容论证薄弱、没有可学手法，输出空数组 []
- 全部说人话，不要"综上所述""值得注意"等AI腔
- 每条独立可理解，不依赖其他条目

## 输出格式
[
  {
    "method": "论证手法（可迁移的手法描述）",
    "evidence": ["支撑方式1", "支撑方式2", "支撑方式3"],
    "risk": "该手法的失效风险",
    "path": "推进路径",
    "category": "手法分类（开场建立/论据组织/说服推进/信任建立/收尾促动）",
    "confidence": 0.85
  }
]
```

**后处理质量门槛（代码级校验，必须执行）：**

| # | 规则 | 判定 |
|---|---|---|
| 1 | 长度过滤 | `method` < 8 字 → 丢弃（大概率是标题碎片） |
| 2 | 动作性检测 | `method` 不含任何动作词 → 丢弃 |
| 3 | 支撑校验 | `evidence` 为空，或仅 1 条且 < 5 字 → 丢弃整卡 |
| 4 | **内容搬运检测** | `method` 与原文某句相似度过高 → 丢弃（防止变成观点搬运） |
| 5 | 数量截断 | 最多保留 3 条 |

**通用动作词字集**（行业无关，命中任一即视为"有动作"）：
```
用先再后把将以借通过采取运用引入切入铺垫拉出抛出
建立制造营造消解化解拆解组织串联对比类比换算
承认反驳预设回应引导推进收束落到夯实强化弱化
替代补充延伸展开压缩截断转折递进呼应回扣
```
> 相比原实现的金融动词表（涨跌破/加仓减持/止盈止损），本字集聚焦**写作动作**，天然跨行业。

### 第 4 步：迁移角度建议

**System Prompt：**
```
你是一位资深内容策略顾问，服务过多种类型的创作者。

你的任务：基于对一篇内容的方法论分析，为创作者提供**可直接行动**的迁移建议——这套方法我能怎么用在自己的选题上。

## 创作者类型（从以下方向中选出最匹配的 2-3 种）
- 科普入门型：面向小白，讲基础知识与入门方法，风格通俗易懂
- 实战操作型：面向有基础的实践者，讲具体做法与操作策略，风格直接犀利
- 深度洞察型：面向进阶人群，讲趋势/机制/底层逻辑，风格深度专业
- 娱乐化表达型：面向泛人群，用轻松幽默方式讲行业现象，风格有梗易传播
（若用户已提供自身定位或风格档案，优先匹配用户的实际类型）

## 输出要求（严格JSON格式）

[
  {
    "creator_type": "最匹配的创作者类型",
    "angle": "建议的选题切入角度（一句话标题，25字以内，必须是用户可写的自有选题方向）",
    "verdict": "值不值得写的判断（一句话，含时效性与传播潜力评估）",
    "structure": "推荐的正文编排框架（如：痛点开篇→数据对比→实操方案→总结金句）",
    "hook": "可复用的方法论要素（一条核心手法，如：用具体数字制造认知反差）",
    "why_effective": "原文这个手法为什么有效（指向原文手法位置，不复述原文结论）"
  }
]

## 关键规则
1. 3个角度必须面向**不同的创作者类型**，不要重复
2. angle 必须是**用户自己可写的选题**，不是原文选题的改写
3. verdict 要给出明确的"值得写/谨慎写/抢时效"判断
4. structure 要具体到编排节奏，不要空洞
5. hook 必须是可迁移手法（能用到任何选题），不是仅适用于原文的描述
6. why_effective 落脚于手法有效性，不搬运原文内容结论
7. 只输出JSON数组，不要其他文字说明
```

**参数建议**：`temperature=0.85`，`max_tokens=2000`

**容错处理**：LLM 可能用 markdown 代码块包裹 JSON → 剥离 ```json 与 ``` 后解析；清洗所有 `**`；解析失败返回原始文本提示重试。

### 第 5 步（可选）：结构参考写作

> **说明**：本步为已有能力的编排（分析结果 + 风格档案 → 创作），非新增能力。

```
你要写一篇关于「{用户自己的选题}」的内容。

【可参考的结构骨架】（来自第 2 步）
{structure_skeleton}

【可参考的论证手法】（来自第 3 步 method + path）
{methods}

【可参考的编排框架与手法】（来自第 4 步 structure + hook）
{structure + hook}

【你的文风约束】（来自风格档案）
{style_portrait} + {tags}

【用户素材】
{用户提供的数据、案例、经历}

【硬性要求】
1. 只借鉴结构与手法，**禁止复制原文任何句子或内容结论**
2. 所有事实、案例、数据必须来自用户素材；素材不足时明确指出缺什么，**不得用原文内容填充、不得编造**
3. 文风必须符合上述风格约束，不要写成原作者的腔调
4. 完成后自查：如果把结构去掉，这篇内容与原文是否已无实质关联？若否，需重写
```

}
```

**最有沉淀价值的字段是 `reusable_methods`** ——跨选题复用，累积成用户专属的「方法论库」，这是越用越值钱的资产。

## 五、与其他 Skill 的协作

```
方法论分析 Skill ──产出──► 【方法论档案】（结构骨架 + 论证手法 + 迁移角度）
                                    │
风格养成 Skill ──产出──► 【风格档案】（文风 DNA）
                                    │
                    两者共同注入 ──► 内容创作 Skill ──► 成稿
                                    （好方法的结构 + 你自己的人格与素材）
```

## 七、质量校验清单（输出前自查）

- [ ] **全文未出现禁用词**（观点提炼/观点卡/仿写/洗稿等）
- [ ] 所有结论落脚于**手法**，未搬运原文内容结论
- [ ] 引用原文仅为短语（≤15字）且标注为原文片段，无整句复制
- [ ] 论证结构卡全部通过五条后处理门槛（含内容搬运检测）
- [ ] `hook` / `reusable_methods` 均为可迁移手法，非本文专属描述
- [ ] 迁移角度的 `angle` 是用户自有选题，非原文选题改写
- [ ] 参考写作的事实素材全部来自用户，缺口已明确指出
- [ ] 幕名有辨识度，未使用"开头/中间/结尾"
- [ ] 未使用 markdown 加粗（`**`）
- [ ] 若原内容确无可学手法，已明确告知而非硬凑

## 八、常见问题处理

| 情况 | 处理方式 |
|---|---|
| 链接抓取失败（登录墙/反爬/非公开） | 提示改用粘贴正文或上传截图，**不尝试绕过限制** |
| 用户批量提交多个链接 | 逐篇处理，说明不做批量爬取 |
| 截图文字识别不全 | 请用户补充关键段落，不猜测缺失内容 |
| 视频无字幕无文稿 | 明确告知无法分析，建议提供口播稿 |
| 原内容平庸、无可学手法 | 明确告知并说明判断依据，不硬凑 |
| **用户要求逐句改写/洗稿** | **拒绝**，说明平台风险与无长期价值，改为提供结构与手法 |
| 用户素材不足支撑某一幕 | 明确指出缺什么，不用原文内容填充、不编造 |
| 用户无风格档案 | 参考写作可跑，提示"结果偏通用，建议先做风格养成" |
| 论证分析输出空数组 | 正常情况，说明原内容论证薄弱，不视为失败 |
