# 商单过审预检（Brand Deal Compliance Check）

对商单稿件做**卡审点扫描 → 三级判定 → 合规改写**，并识别品牌要求与平台规则的冲突。

> **架构**：本技能主干是**行业无关的通用合规框架**（广告法通用红线 + 平台通用审核逻辑 + 三级判定方法 + 改写原则）。
> 特定行业的词表与专项要求存放在 `platform-playbook/references/industries/`，**按用户所属行业动态加载**。
> **没有对应行业包时照样可用**——按通用框架给建议，并明确告知精度限制。绝不拿其他行业的规则硬套。

---

## 一、第 0 步：先问清行业与场景（不可跳过）

合规判定**高度依赖行业**——同一句话在不同行业判定可能相反（"零添加"在食品是高风险宣称，在收纳用品无关；"修复"在医美是红线，在家具是普通描述）。所以动手前必须确认：

| 要确认的 | 为什么必须问 |
|---|---|
| **所属行业/品类** | 决定加载哪个行业包、适用哪些专门法规 |
| **是否强监管行业** | 金融、医疗、医美、药品、保健食品、教育培训、房产、酒类、**宠物食品与医疗**等有专门法规，红线远严于普通消费品 |
| 发布平台与商单类型 | 平台审核口径不同；**报备类商单**（星图 / 腾讯互选 / 蒲公英）审核显著更严 |
| 创作者主体资质 | 强监管行业存在**主体资格**门槛，这比用词更根本 |
| 是否有品牌 Brief | 有则需做冲突识别 |

**问法示范**（说清为什么问，不要像查户口）：

> 先确认两件事，因为不同行业的审核标准差别很大：① 这个商单是什么品类的产品？② 在哪个平台发、是通过官方接单平台报备的吗？
> 问品类是因为有些行业（金融、医疗、保健食品、宠物食品、教育等）平台和法规管得特别严，用词标准完全不同，按错的标准检查等于白检。

⚠️ **用户不愿细说时**：按通用框架推进，但**明确声明假设**——"我先按普通消费品的标准检查；如果这个属于保健食品或医疗器械类，红线会严很多，告诉我我再重新过一遍。"

## 二、执行流程

```
接收稿件（+ 品牌 Brief，若有）
  ↓
第 0 步：确认行业与场景（见上）
  ↓
第 1 步：加载规则库
        ├─ 必载：ad-risk-words.md（广告法通用高危词，全行业适用）
        ├─ 必载：platform-playbook 对应平台文档（该平台审核红线与商单规范）
        └─ 按行业加载：references/industries/ 下对应行业包
           └─ 无对应行业包 → 明确告知，仅按通用框架执行，不套用其他行业规则
  ↓
第 2 步：逐句扫描 —— 标注命中位置、级别、原因
  ↓
第 3 步：三级判定 —— P0 必改 / P1 须改写 / P2 看语境
  ↓
第 4 步：合规改写 —— 整句改写（不做单字替换），保原意与用户风格
  ↓
第 5 步：Brief 冲突识别（若有）—— 给替代方案与沟通话术
  ↓
第 6 步：交付报告 + 剩余风险提示
```

## 三、三级判定标准（通用框架）

| 级别 | 定义 | 处理 |
|---|---|---|
| **P0 红线** | 命中即拒审或违法，不可协商 | 必须删改 |
| **P1 高风险** | 词本身中性，但在**商单场景**或**该行业**禁用 | 须改写并给替代表述 |
| **P2 需看语境** | 命中范围极大的常用字词 | **必须结合上下文判断**，禁止机械替换 |

### P0 通用红线（全行业适用，与行业包叠加）

| 类型 | 内容 | 依据 |
|---|---|---|
| 绝对化用语 | 最/第一/唯一/首个/顶级/国家级/最佳 | 广告法第九条 |
| 承诺保证类 | 保证有效 / 包过 / 零风险 / 无条件承诺结果 | 广告法 |
| 虚假与夸大 | 无依据的功效、结果、性能宣称 | 广告法 |
| **疗效与医疗暗示** | 非药品/非医疗器械宣称治疗、预防疾病 | 广告法第十七条 + 各行业专门规定 |
| 国家背书 | 暗示国家机关、领导人推荐或背书 | 广告法第九条 |
| 贬低同行 | 贬低其他生产经营者或其商品服务 | 广告法第十三条 |
| 诱导与导流 | 报备类商单中的加群 / 私信 / 扫码 / 私域引流 | 各平台商单规范 |
| 未标识商业内容 | 商业合作未按平台要求标注 | 广告法第十四条 + 平台规范 |

### P1 高风险（商单场景禁用，行业包会追加）

- **行为指令类**：直接指令交易动作（部分平台报备商单中受限）
- **比较宣称**：与竞品或基准比优劣（须有可验证依据，否则删）
- **数据无来源**：任何数字、排名、比例未标注来源
- **涉政涉敏**：政策文件引用、政府名义、时事敏感话题
- **群体贬称**：对用户群体的负面标签（引发反感并影响平台评估）
- **专业身份暗示**：非专业人士使用近似专业结论的表述（如"这个成分能改善XX"）

### P2 需看语境（禁止机械替换）

高频命中字词（如"稳""赚""涨""收益""最""第一""无限""修复""改善"等，具体清单随行业包扩展）：

| 语境 | 判定 | 处理 |
|---|---|---|
| 与承诺/保证连用 | **升级为 P0** | 必改 |
| 作为预测或功效宣称 | **P1** | 须改写 |
| 客观陈述 + 有来源 + 有免责 | **可保留** | 标注需补来源 |
| 出现在风险提示或免责声明中 | **保留** | 不动 |
| 属于固定词组、无宣称含义 | **保留** | 如"最近""第一次"这类日常用法 |

⚠️ **禁止单字替换**——把"稳健"改成"健"、把"最近"误判为绝对化用语，都会破坏文意且暴露机械处理。命中时给**整句改写建议**并说明判定依据。

---

## 四、改写原则（通用）

1. **保原意**：传达品牌想传达的价值，只换合规说法（品牌想说"效果好"→ 改讲使用感受与适用场景，不做功效宣称）
2. **保风格**：若用户有风格档案，改写后必须仍像用户写的，不要改成官方新闻稿腔
3. **讲体验与方法，不给承诺与指令**：把"用了一定有效"改成"我用下来的感受是…"
4. **数据必带来源**：涉及数字补"数据来源 + 个体差异说明"
5. **必带项按平台与行业核对**：风险提示、商业标识、免责声明、话题标签
6. **不为过审牺牲真实性**：不得编造数据、来源或使用体验来"补合规"

## 五、输出规范

> ⚠️ 交付前按 `output-readability` 自查。**P0/P1/P2 是内部分级代号，产物里不要只写代号**——每个级别第一次出现时必须带上意思：
> - P0 → **必须改，不改过不了**
> - P1 → **建议改，风险较高**
> - P2 → **要看前后怎么说的，不能一律替换**
>
> 另外：「语境」改说「上下文 / 前后怎么说的」；不要用「三级判定」这个词，直接按上面三档讲。
> **结论先行**：报告开头先给一句能直接行动的判断（可以提交 / 改完再提交 / 建议不接这单），再往下列细节。

### 1. 预检报告（主产出）

**结论摘要**：整体风险等级（高/中/低）+ P0/P1/P2 命中数量 + 一句话判断（能不能提交、要不要大改）+ **本次加载了哪些规则库**（让用户知道判定依据，也知道有没有行业包）

**卡审点清单**（表格）：

| # | 位置 | 命中 | 级别 | 原文片段 | 原因（含依据） | 改写建议 |
|---|---|---|---|---|---|---|

### 2. 合规改写版

改写后全文 + 侧标（每处改动对应清单编号）。

### 3. 平台专项检查项

按发布平台加载对应清单逐项核对（如视频号的画面与风险提示位置要求、小红书的商业内容标识要求等），详见 `platform-playbook` 对应平台文档。

### 4. Brief 冲突说明 + 沟通话术（若有 Brief）

| 品牌要求 | 平台/法规是否允许 | 依据 | 建议替代 |
|---|---|---|---|

附一段**可直接发给品牌方的说明**（口径专业、有依据、给方案，不是简单说"不行"）。

### 5. 剩余风险提示

明确列出：改写后仍存在的不确定项、需用户自行确认的事项（主体资质、数据来源真实性、素材授权）。

## 六、注意事项

1. **不承诺过审**：只说"已知卡审点已清除"，禁止"改完必过""包过"。平台审核有人工判断与政策动态调整
2. **平台规则优先于品牌诉求**：冲突时以平台规则为准，给替代方案 + 沟通话术，不为满足品牌方放行违规内容
3. **先查主体资质**：强监管行业中，主体是否有资格做该类营销，是**比用词更根本的问题**，须前置提示
4. **脚本阶段就要预检**：提醒用户在脚本/初稿阶段做检查，避免成片后返工
5. **行业包缺失时如实说明**：明确告知"这个行业我没有专门的规则库，以下建议基于通用广告法与平台规范，建议以官方最新规则核实"。**严禁拿相近行业的规则硬套**——那会给出错误的合规建议
6. **不做规避审核的建议**：不提供谐音、拆字、变体等规避检测手段，那本身违反平台规范
7. **标注规则可信度**：引用规则时标明来源层级——L0 法律法规原文 / L1 官方文档或权威汇总 / L2 行业共识。二手汇总须注明"具体条款以官方原文为准"
