# 6 专家产出 → 组件映射（section 级细化）

**说明**：本表**逐 section 指定组件**，模型生成时对号入座，不再主观挑组件。判定通则：

- 「分类：自由文本描述」→ `plain-list`（8b 标签式），**不要用 2 列表格**
- 结构化多字段可对比 → `data-table`（KV 型带 thead，或多列）
- 时间/阶段推进 → `timeline`
- 补充说明 → `callout`（2 色，见规则 3；仅**孤立单条**时使用）
- **≥ 2 条风险 / 红线并列 → 一律 `plain-list`，不用任何 callout 包裹**（规则 12 最新版）
- **决策分支 / 条件枚举（If-then）→ `plain-list` + `.tag-*` 字色**（规则 15），**禁止 3 条并列 callout**

未列出的产出，参考 `design-rules.md` 规则 11/12/13 自行组装。

## 通用约定（所有专家共用）

1. **文件名**：`{专家花名}-{产出类型}-{YYYYMMDD}.html`
2. **文件路径**：用户当前工作目录 `$(pwd)`
3. **Banner 4 行**：`brand-tag`（`营销通 · {专家职能名}`，纯白小字，**照抄 template 写死的整段、不许改字**）+ title（产出物名）+ subtitle（一句话说明）+ meta（日期/阶段/周期）。职能名查 `references/brand-tag-map.md`；**禁止用花名**（花名只出现在页脚 disclaimer）。详见规则 14 / 16
4. **底部 disclaimer**（可选）：涉及流量/收益预测时**必填**；建议格式 `—— 营销通 · {专家花名} 出品`
5. **`.lead` 是"这节最该先知道的一句话"**（规则 2）：**不加任何固定前缀**（禁「结论：」「小结：」）；按 section 性质写判断/共性/节奏/最该避开的一条；纯罗列/纯陈述/纯流程且无增量信息时**不加 lead**，直接上内容
6. **序号连续递增**，能合并的合并（如"下一步建议"含"关联专家"）
   - ⚠️ **指路必须写 `花名（职能名）`，逐字照抄不许自造**：启号（起号规划师）/ 梗王（首席内容策略官）/
     郝选题（选题助手）/ 赵写（内容风格教练）/ 包火（爆款分析师）/ 卞现（内容变现顾问）。
     禁止只写花名、禁止只写职能名、禁止自造称呼（"XX解析专家"这类不是正式名字）。
     **最严重的错误是把某人的花名配上别人的职能名**——写之前逐行核对花名与职能名是否同一行。
     完整对照与职责边界见 `references/referral-map.md`
7. **组件选用优先级**（规则 13 决策树的浓缩）：
   - 结构化多字段可对比 → `data-table`
   - 单一对象 K-V ≤ 6 项 → `data-table`（KV 型带 thead）
   - 「分类：描述」清单 → `plain-list`（8b 标签式）
   - 时间/阶段推进 → `timeline`
   - 补充说明 → `callout`（2 色，仅**孤立单条**用；≥ 2 条风险并列一律 `plain-list`，见规则 12）
