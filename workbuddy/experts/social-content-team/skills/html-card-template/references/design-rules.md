# HTML 卡片设计规则（16 条硬规则）

这套规则从多轮迭代沉淀而来，是**统一样式的地基**。违反任一条都会导致视觉不一致或返工。

---

## 规则 1｜所有小标题一律 `h2.section-title` + 序号

**做**：
```html
<section>
  <h2 class="section-title"><span class="idx">01</span>章节标题</h2>
  ...
</section>
```
- 序号连续递增（01 → 02 → 03 → ... → N）
- 无论主内容章节还是收尾板块（下一步建议、免责说明等）都用同一套
- 序号是**蓝色加粗 18px**，标题是**深色 600 weight 17px**

**不做**：
- ❌ 用 `<h3>`、`<h4>` 做"次级小标题"
- ❌ 底部特殊板块用不同样式（比如原来的 `.footer-section h3`）
- ❌ 跳序号（01 → 03）或用中文序号（一、二）

---

## 规则 2｜`.lead` 是"这节最该先知道的一句话"，不是每节标配

**核心原则**：`.lead` = **有话才说，且不加固定前缀**。

这一节要解决的是两个反向的坑：
- 坑 A（旧版"每节必须有结论句"造成的）：每个 section 硬塞一句凑格式，于是出现「结论：以下是 5 个对标账号」这种**假结论**——是陈述，不是判断
- 坑 B：固定写「**结论：**xxx」前缀，一份产物里"结论"重复七八次，**反而没有一处像重点**；而且"结论："本身是一种宣告式元话语，与 `output-readability` 规则四（不暴露写作规则）冲突

**做**：
```html
<h2 class="section-title"><span class="idx">01</span>xxx</h2>
<p class="lead">这节最该先知道的那句话，直接说，不加前缀。</p>
<!-- 然后才是表格/清单/时间轴 -->
```
- **不加任何固定前缀**——不写「结论：」「小结：」「总结：」「核心判断：」。直接写那句话本身
- 放在**表格/内容之前**——扫读的人第一眼看到重点
- **底色固定灰 `#FAFBFC`**，无左竖条——**永远不用品牌蓝底**，避免和 `.callout`（蓝）打架
- 一句话，**不超过 60 字**；可用 `<strong>` 强调句中关键词

### 按 section 性质自适应写什么

`.lead` 的内容不必是"结论"，但**必须有增量信息**——读者看完这一句就知道这节要给他什么。

| section 性质 | `.lead` 写什么 | 示例 |
|---|---|---|
| **判断型**（给建议/优先级/决策） | 给结论本身 | 本轮主打**中腰部达人**，头部预算占比不超过 30% |
| **罗列型**（清单/对标/案例） | 这批东西的**共性**或**怎么用** | 这 5 个都是万粉以内起量的，节奏比大号更值得你抄 |
| **流程型**（排期/路线图/日历） | 关键**节奏**或转折点 | 前两周只管把人设立住，第三周才开始推转化 |
| **陈述型**（数据/分布） | 数据里**最该注意的一点** | 三条里有两条靠同一个开头结构起量 |
| **风险型**（红线/雷点） | 最该**先避开**的那一条 | 只有一条会直接判违规：正文出现收益承诺 |

### 什么时候干脆不加 lead

**没有增量信息就省略，直接上内容。** 不许用废话占位。

- ❌「以下是 5 个对标账号」→ 标题已经说了，这句是零信息
- ❌「本次共选了 5 位达人」→ 陈述，不是重点
- ❌「本节介绍合规红线」→ 复述标题
- ✅ 上述情况**直接删掉 lead**，让 `plain-list` / `data-table` / `timeline` 紧跟标题

**自检口诀**：念一遍这句 lead——
- 如果它只是"这节我讲了 XX" → **删掉**
- 如果它是"所以你该 XX / 注意 XX / 这批的共性是 XX" → **保留**

**不做**：
- ❌ 加「结论：」「小结：」等固定前缀（**本轮明确废除**）
- ❌ 每个 section 硬塞一句 lead 凑格式
- ❌ 把陈述性开头包装成重点句
- ❌ 把 lead 放在内容后面（"根据以上分析..."）
- ❌ 结论句里塞很多分句——一句话，不超过 60 字
- ❌ **`.lead` 底色改成 `var(--brand-soft)` 或任何品牌色**——那是 `.callout` 的专属色

**关键色板责任分离**（改样式时必须遵守）：
| 组件 | 底色 | 用途 |
|---|---|---|
| `.lead` | `#FAFBFC`（灰） | 每节开头的重点句（**有增量信息才用**） |
| `.callout` | `var(--brand-soft)`（蓝） | 补充说明 / 建议 / 中性提示 |
| `.callout-warn` | `var(--warn-soft)`（黄） | 风险 / 红线 |

## 规则 3｜提示条统一 `.callout`，**只 2 色**（蓝 / 黄），无 icon

**色板**：
| 变体 | CSS 类 | 语义 | 适用场景 |
|---|---|---|---|
| **蓝**（默认） | `.callout`（不加修饰类） | 中性 / 正向 / 说明 | 建议、复用逻辑、口径说明、方案确认、补充备注 |
| **黄** | `.callout callout-warn` | 雷区 / 红线 / 风险 | 禁止、最忌、衰减、合规雷、"一票否决" |

**做**：
```html
<div class="callout"><strong class="title">建议：</strong>正向/中性说明。</div>
<div class="callout callout-warn"><strong class="title">风险提示：</strong>红线/雷区。</div>
```
- 左边框 3px 色条 + 淡底色 + 加粗标题词
- **无 icon**——靠颜色和标题词区分
- 标题词固定几个词：`建议：`/`说明：`/`口径：`/`补充：`（蓝）；`风险提示：`/`红线：`/`最忌：`/`注意：`（黄）

### 触发词 → 色块 硬映射表（选色查这张表，不主观判断）

| 关键词/语义 | 用 |
|---|---|
| 禁止 / 最忌 / 红线 / 一票否决 / 不可 / 严禁 | `callout-warn`（黄） |
| 风险 / 雷 / 踩雷 / 违规 / 合规红线 | `callout-warn`（黄） |
| 跨池衰减 / 换场子衰减 / 适用边界外 | `callout-warn`（黄） |
| 建议 / 推荐 / 可复用 / 优先 / 值得做 | `callout`（蓝） |
| 说明 / 口径 / 补充 / 备注 / 顺带说 | `callout`（蓝） |
| 已确认 / 通过 / 匹配 / 达标 | `callout`（蓝） |
| 方法论要点 / 复用模板 / 结构骨架说明 | `callout`（蓝） |

**同一 section 内规则**：
- **蓝色 callout**：允许同色多条并列（如说明 + 建议）
- **黄色 callout（warn）**：≥ 2 条一律走 `plain-list`（见规则 12），callout-warn 只留给孤立的单条警示
- **不允许蓝黄混排**——如果确实需要既讲建议又讲风险，拆成两个 section

**不做**：
- ❌ 用 `<blockquote>` 或 emoji（💡⚠️✅）
- ❌ 自造第三种颜色（如绿/红/紫）——绿色的 `callout-ok` 已废弃，不再使用
- ❌ 在 `callout` 内部再嵌套 `<h3>`/`<h4>` 之类的次级标题

## 规则 4｜表格一律 `.data-table`，KV 型必须带 thead

**做**（普通多列表）：
```html
<table class="data-table">
  <thead><tr><th>列1</th><th>列2</th><th>列3</th></tr></thead>
  <tbody>...</tbody>
</table>
```

**做**（KV 型两列表，如账号定位卡、Brief 六要素）：
```html
<table class="data-table">
  <thead>
    <tr><th style="width:130px;">重点维度</th><th>定位建议</th></tr>
  </thead>
  <tbody>
    <tr><td class="kv-key">人设一句话</td><td>xxx</td></tr>
    <tr><td class="kv-key">目标受众</td><td>xxx</td></tr>
  </tbody>
</table>
```
- **KV 型也必须带 thead**——避免和普通表格视觉不统一
- 表头搭配示例：「重点维度 / 定位建议」、「产能维度 / 说明」、「Brief 要素 / 内容」、「评估维度 / 现状」

**不做**：
- ❌ 用 `.info-list` 白卡竖排（已弃用）
- ❌ KV 型省略 thead
- ❌ 用 markdown 表格渲染 fallback

## 规则 5｜时间轴精简版，无 icon

**做**：
```html
<div class="timeline">
  <div class="tl-item">
    <div class="tl-head"><span class="week">Week 1</span>阶段主题</div>
    <div class="tl-goal"><strong>目标：</strong>xxx</div>
    <ul class="tl-list">
      <li>动作 1</li>
      <li>动作 2</li>
    </ul>
  </div>
</div>
```
- `<span class="week">` 里是徽章文字，`Week 1`/`Q1`/`阶段 1` 皆可
- 每块结构：**徽章 + 标题 → 一行目标 → bullet 列表**
- bullet 前**不加 icon**（原来的 bookmark/image/graph-up 已弃用）

**不做**：
- ❌ 在每行 bullet 前加 `<i class="bi bi-xxx">`
- ❌ 用"卡片式"布局代替连线时间轴

## 规则 6｜通用清单用 `.plain-list`

**做**：
```html
<ul class="plain-list">
  <li>动作 1</li>
  <li>动作 2 → 可找 <strong>xxx</strong></li>
</ul>
```
- 实心圆点 bullet（浏览器默认）
- 用于"下一步建议"、"关联专家"、任何非表格的清单场景

---

## 规则 7｜Icon 唯一允许场景：banner meta 行

**做**：
```html
<div class="meta">
  <span><i class="bi bi-calendar3"></i>2026-08-19</span>
  <span><i class="bi bi-flag"></i>起号阶段</span>
  <span><i class="bi bi-hourglass-split"></i>30 天路线</span>
</div>
```

**判定原则**：**Icon 的价值是"区分维度"，不是"装饰"**。
- ✅ banner meta 行：多个并列维度（日期/阶段/周期）纯文字分不清 → 加 icon
- ❌ 章节标题、结论卡、清单、bullet、表格单元格 → **不加 icon**

**Bootstrap Icons CDN**：
```
https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11.3/font/bootstrap-icons.min.css
```

**常用图标**：
- 日期/时间：`bi-calendar3`、`bi-clock`、`bi-hourglass-split`
- 场景/阶段：`bi-flag`、`bi-bookmark`、`bi-pin-map`
- 目标/数据：`bi-bullseye`、`bi-graph-up`

## 规则 8｜章节标题、结论卡、清单都不加左侧色条

**背景**：多处都用左竖条会互相干扰、显得杂乱。

**决定**：整个卡片体系里**没有任何组件使用 `border-left` 色条**，唯一例外是 `.callout`——因为它就是靠色条+底色分档的核心组件。

---

## 规则 9｜能合并的板块不拆多个标题

**判定**：如果两个板块内容本质是**"接下来该做什么"**的展开 → 合并为同一个 section。

**典型合并**：
- ❌ 06 下一步建议 + 07 关联专家（分开）
- ✅ 06 下一步建议（内含"找谁"）

**允许独立**：只有**结构上真正独立**的模块才能单独开标题，如：
- 风险预警（独立评估）
- 数据依据/参考来源
- 附录/补充说明

**Agent 自问**：这个板块跟已有板块能不能合并？语义相近就并入。

## 规则 10｜HTML 里禁止残留任何 Markdown 语法

**背景**：HTML 卡片是渲染后的成品，不是源码。任何 markdown 语法出现在正文里都是 bug——用户看到的是原始字符（如"但\*\*主线只能有一个\*\*"），而不是加粗效果。

**必须渲染成 HTML 标签的 Markdown**：

| Markdown 写法 | 必须替换为 |
|---|---|
| `**加粗文字**` | `<strong>加粗文字</strong>` |
| `*强调*` 或 `_强调_` | `<em>强调</em>` |
| `` `代码/术语` `` | `<code>代码/术语</code>` |
| `[链接文字](url)` | `<a href="url">链接文字</a>` |
| `# 标题` / `## 标题` | `<h2 class="section-title">...` |
| `- 列表项` / `* 列表项` | `<ul><li>列表项</li></ul>` |
| `1. 有序项` | `<ol><li>有序项</li></ol>` |
| `> 引用` | `<div class="callout">...</div>`（走 callout 规则） |

**自检 SOP（生成 HTML 前必跑）**：
1. 全文搜 `**` → 应为 0 处（除非在 `<code>` 里演示 markdown 本身）
2. 全文搜 `` ` `` （反引号）→ 应为 0 处
3. 全文搜行首 `#`/`- `/`* ` → 应为 0 处
4. 全文搜 `](` → 应为 0 处

**典型 bug 示例（不做）**：
```html
<!-- ❌ 错：markdown 残留 -->
<td>但**主线只能有一个**</td>
<td>推荐**每周 3-4 篇**</td>
<p>先问自己一个问题——`我最愿意花时间去挖的品类是什么？`</p>
```

**正确写法**：
```html
<!-- ✅ 对：转 HTML 标签 -->
<td>但<strong>主线只能有一个</strong></td>
<td>推荐<strong>每周 3-4 篇</strong></td>
<p>先问自己一个问题——<em>我最愿意花时间去挖的品类是什么？</em></p>
```

**例外**：只有在明确要"展示 markdown 源码"的场景（如教程里演示语法），才能用 `<code>` 或 `<pre>` 包起来保留原始字符。

## 规则 11｜`.callout` 是"一段话"，不是"一组要点"

**背景**：callout 定位是**补充说明/风险提示的短段落**，不是清单容器。塞进 ①②③ 或多个分号句会让内容挤在一行、失去层次。

**允许**：
- 1 句结论 + 至多 1 句短补充
- 或 1 句结论 + 少量 `<strong>` 关键词强调
- **同 callout 内可以嵌一个 `<ul class="plain-list">`** —— 仅限**蓝色 callout 的说明/建议**场景（如"参考做法：以下 3 点"）；**风险/红线并列一律走规则 12 用裸 plain-list**，不允许"黄色 callout + 内嵌 plain-list"

**禁止**：
- ❌ 一段话里手写 `①②③` / `1) 2) 3)` / 三个及以上并列分号句
- ❌ callout 里直接甩长清单不做包装（没有开头结论句）
- ❌ callout 里嵌 `<h3>`/`<h4>`/`<table>`

**超了怎么办**——按信息量 3 档处理：

| 信息量 | 处理 |
|---|---|
| 1 句话（≤ 60 字） | 保留 callout |
| 2-6 点要点（**非风险类**） | 蓝色 callout 顶部 1 句重点 + 内嵌 `<ul class="plain-list">` |
| 2-6 点要点（**风险/红线类**） | 直接 `<ul class="plain-list">`，走规则 12（不套 callout） |
| 6 点以上，或每点自身还有细分 | **抽出独立 section**：`h2.section-title` +（可选 `.lead`）+ `plain-list`/`data-table`，不留在 callout 里 |

**Agent 自问**：这段内容能不能一口气念完？念不完就抽出去。

## 规则 12｜任何风险并列一律 `plain-list`，不用 `callout` 包

**背景**：早期做法是"3 条以上红线合并到一个黄 callout + 内嵌 plain-list"，测试后发现整块黄底反而稀释重点、视觉压迫感重。经验：**并列 = 罗列陈述，不是单点警示**，不适合 callout 那种"高亮一段话"的定位。

**做法**（硬约束）：
- **任何 2 条及以上并列的风险 / 红线 / 雷点 / 踩雷清单** → 一律用 `plain-list`（走规则 6），**不加任何 callout 包裹**
- **只有孤立的单条警示** → 才用 `.callout callout-warn`（走规则 3 / 11）
- **绝对不用**"1 个大黄 callout 里嵌 plain-list"这种嵌套写法（那是旧做法，已废）

**示例（3 条红线的正确写法）**：
```html
<h2 class="section-title"><span class="idx">04</span>合规红线</h2>
<ul class="plain-list">
  <li><strong>标题：</strong>禁用"最"、"第一"、"顶级"等绝对化用语</li>
  <li><strong>商单：</strong>有合作必须走蒲公英报备</li>
  <li><strong>导流：</strong>正文和评论区不放联系方式</li>
</ul>
```
- 前缀词（"标题"/"商单"/"导流"）用 `<strong>` 加粗黑字，**不用红字/黄字标识**——靠章节标题（"合规红线"）+ 前缀词自身表达风险语义，视觉保持克制
- 章节标题就是"红线 / 风险 / 雷点"这类词，读者一眼知道整节属于警示范畴，不需要每条再刷一遍颜色

**孤立单条警示才用 callout-warn**：
```html
<div class="callout callout-warn"><strong class="title">红线：</strong>这一条务必单独强调，不与其他风险并列出现。</div>
```

**判定口诀**：
- **≥ 2 条并列** → `plain-list`（哪怕只有 2 条，也不用 callout 并列）
- **= 1 条孤立** → `callout-warn`
- **不允许**"合并成 1 个 callout + 内嵌 plain-list"的旧写法

**跨色规则**：蓝黄不能在同一 section 混排（沿用规则 3）——如果既有正向又有风险，拆成两个 section。

## 规则 13｜表格 vs plain-list 决策树（选组件不主观）

**背景**：表格滥用是最常见的呈现层问题——把"分类：自由文本"塞进 2 列表格，右列越写越宽、越写越散，反而不如列表清爽。

**决策树**（按顺序判断，命中即用）：

```
这段内容是什么？
├─ 1) 只是"分类/标签：自由文本描述"的清单
│     └→ plain-list（左标签加粗 + 冒号 + 描述）
├─ 2) 单一对象的多维度描述（≤ 6 项 K-V）
│     └→ data-table（KV 型，带 thead）
├─ 3) 多行 × 多列结构化字段（有评分/分级/数值等可对比字段）
│     └→ data-table（多列，带 thead）
├─ 4) 时间/阶段推进
│     └→ timeline
└─ 5) 单一段落的补充/提示
      └→ callout（走规则 3 色板）
```

**硬约束**：
- **2 列 + 右侧 ≥ 50% 是自由文本**（不是可对比字段） → **一律 plain-list，不用 table**
- **1 列表格** → 直接删掉表格外壳，用 `plain-list`
- **超过 6 列** → 拆成两张表或改成 `plain-list` 分组

**典型误用（不做）**：

| 场景 | 误用 | 正解 |
|---|---|---|
| 同行共性写法（清单） | 2 列表格：写法\|说明 | plain-list：`<strong>写法：</strong>说明` |
| 空白角度列表 | callout 里塞 ①②③ | 独立 section + plain-list |
| 单条建议 | 独立 KV 表 1 行 | 直接写 `.lead` 重点句 |
| 时间安排 | 4 列大表：周次\|主题\|目标\|动作 | timeline |

**plain-list 标准写法**（左标签加粗，全项目一致）：
```html
<ul class="plain-list">
  <li><strong>打工人「按点」午餐节奏：</strong>早 C 晚 A / 加班餐 / 凌晨局</li>
  <li><strong>冷门地铁站：</strong>14 号线沿线、龙岗、坪山方向</li>
</ul>
```
CSS 已保证左标签深黑加粗、冒号后微空隙，扫读锚点清晰。

## 规则 14｜Banner 4 行结构，brand-tag 必须"品牌+职能名"（禁止花名）

**做**：
```html
<div class="banner">
  <p class="brand-tag">营销通<span class="sep">·</span>{专家职能名}</p>
  <h1 class="title">{产出物名称}</h1>
  <p class="subtitle">{一句话说明：面向对象 · 关键参数}</p>
  <div class="meta">
    <span><i class="bi bi-calendar3"></i>{日期}</span>
    <span><i class="bi bi-flag"></i>{场景/阶段}</span>
    <span><i class="bi bi-hourglass-split"></i>{周期/范围}</span>
  </div>
</div>
```

Banner 4 行结构（从上到下）：
1. **brand-tag**（新增）：`营销通 · {专家职能名}` —— 纯白小字（13px / opacity 0.85），无胶囊底色
2. **title**：产出物名（"账号规划卡"、"爆款拆解报告"）—— 第一视觉焦点
3. **subtitle**：一句话说明（面向对象 / 关键参数）
4. **meta**：日期 / 阶段 / 周期（3 个 Bootstrap Icon 区分维度）

**brand-tag 硬约束**（违反必改）：
- ✅ 必须用**专家职能名**（`选题助手` / `内容变现顾问` / `爆款分析师` / `起号规划师` / `首席内容策略官` / `内容风格教练`...）
- ❌ **禁止用花名**（`郝选题` / `卞现` / `包火` / `启号` —— 花名是内部人格化标签，不出现在正式产物上）
- ❌ **禁止其他前缀/后缀**（`by 郝选题` / `作者：郝选题` / `【选题】` / `V1.0`）
- 7 个专家的固定职能名见 [brand-tag-map.md](./brand-tag-map.md)，agent 生成时直接照搬，不要自造措辞

**不做**（沿用）：
- ❌ 加版本号、水印、生成时间戳等杂物
- ❌ 加专家头像 / logo 图片
- ❌ 用花名作为 title —— title 是**产出物名**不是专家名

**品牌归属双通道**：
- **Banner brand-tag**：告诉读者"这是哪个能力域的产物"（品牌 + 职能，正式）
- **页脚 `.disclaimer`**：可保留花名 + 免责声明，例：
  ```html
  <p class="disclaimer">—— 营销通 · 郝选题 出品｜本报告仅供参考，实际执行请结合具体场景判断。</p>
  ```
- 花名允许出现在页脚（轻量、克制），banner 上一律职能名

**理由**：banner 是老板扫读第一屏，需要传达"这是什么能力的产物"（选题？商单？拆解？）。花名太内部、太人格化，正式产物上不适用；纯职能名既保住品牌辨识度、又符合正式文档习惯。

## 规则 15｜"条件枚举 / 决策分支"一律 `plain-list + tag`，禁止用 callout 并列

**背景**：决策分支（"若 A → 可接 / 若 B → 谨慎接 / 若 C → 不建议接"）本质是**同一维度下的 If-then 枚举**，不是风险提示。如果做成 3 条并列 callout：
- 看起来像"3 条并列风险"，实际只有 1 条是真风险
- 违反规则 12（并列风险一律走 plain-list、不用 callout 包）——但本质是**组件选错了**：这根本不是风险类
- 决策结果被底色喧宾夺主，读者不再看结果本身

**判定条件**（命中任一即为决策分支）：
- 多个块开头都是 `若…` / `如果…` / `当…` / `A 情况 / B 情况`
- 每块的核心是"结论词"（可接 / 谨慎接 / 不建议接、推荐 / 观望 / 淘汰、YES / 待定 / NO）
- 同一维度下的互斥枚举，读者需要**对比**而非**警示**

**做**——`plain-list` + `tag-*` 字色（三档）：
```html
<ul class="plain-list">
  <li><strong>若两点都谈成：</strong><span class="tag-ok">可接 ✓</span>品牌方产品与你账号定位高度匹配……</li>
  <li><strong>若只谈成内容框架：</strong><span class="tag-warn">谨慎接</span>可以接，但要在合同里……</li>
  <li><strong>若对赌坚持不改：</strong><span class="tag-bad">不建议接</span>点赞对赌不合理，宁可放弃……</li>
</ul>
```

**决策结果三档字色**（只染字色，不加底色）：
| 类 | 字色 | 用于 |
|---|---|---|
| `.tag-ok` | 绿 `var(--ok)` | 可接 / 推荐 / YES / 通过 / 达标 |
| `.tag-warn` | 橙 `var(--warn)` | 谨慎接 / 有条件 / 观望 / 待定 |
| `.tag-bad` | 红 `var(--danger)` | 不建议接 / 不推荐 / NO / 淘汰 |

**不做**：
- ❌ 3 条 callout 并列（1 蓝 + 2 黄 或 3 黄）承载 3 档决策——即便颜色搭对了，容器也选错
- ❌ 把决策结果做成表格（2 列 + 右侧长文本，命中规则 13 表格禁用条件）
- ❌ 给 `.tag-*` 加底色/胶囊/边框——底色噪音正是要避免的

**与其他规则的边界**：
- 规则 3（callout 2 色）：只针对"真正的风险 / 建议"这类**单向提示**
- 规则 11/12（callout 内嵌 list、同色合并）：只在真的是同类风险堆叠时才启用
- **决策分支不进 callout，走本规则**

**Agent 自问**：这几块是"警告读者"，还是"让读者对比选择"？后者就是决策分支，用 plain-list + tag。

## 规则 16｜brand-tag 完整性硬约束（禁止简写）

**背景**：agent 生成 HTML 时容易自作主张把"营销通"缩成"营销通"或"腾讯"，导致品牌信息缺失。本规则叠加规则 14。

**做**：banner 顶部 brand-tag 必须是完整的 `营销通 · <专家职能名>`，来源是**专家包 template.html 里预先写死的整段** `<p class="brand-tag">营销通<span class="sep">·</span>XXX</p>`——**直接整段复制、不许改任何一个字**。

**不做**：
- ❌ `起号规划师`（缺"营销通"前缀，本轮观察到的实际 bug）
- ❌ `起号规划师 · 营销通`（词序颠倒）
- ❌ `营销通·起号规划师`（把 `<span class="sep">` 换成裸 · 号，样式塌）
- ❌ `营销通 · 起号规划师 V1.0` / `by 起号规划师`（加版本号 / 前缀）
- ❌ 只写职能名 `起号规划师`（缺品牌前缀）
- ❌ 用"营销通 · 启号"（用花名而非职能名，命中规则 14）

**执行方式（关键机制）**：
1. **不由 agent 填空**——每个专家包的 `assets/template.html` 已把自己的 brand-tag 整段写死，agent 只负责选对模板、按模板结构 body，不改 banner。
2. **rsync 同步例外**：主副本改 template.html 时，需要重新用脚本按 `references/brand-tag-map.md` 里的映射为 7 个专家包分别写死，不能直接 rsync 覆盖（否则 6 个副本会全变成"社媒内容专家团"）。
3. Agent 自检：生成 HTML 后搜索：
   - `grep -c "营销通" output.html` 应 ≥ 1
   - `grep -c "营销通" output.html` 应等于 `grep -c "营销通" output.html`（如果前者更大，说明有裸"营销通"简写）

**理由**：品牌完整性是对外产物的底线。"营销通"是产物的能力域归属声明，agent 出于"简洁"省掉品牌前缀是最需要防的错误——所以从"提示 agent 别漏"升级为"agent 根本没机会漏"（模板里已经写死）。
