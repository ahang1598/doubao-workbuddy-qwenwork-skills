# AI-HIVE 错误与任务处理

错误展示以工具返回为准。用户可见失败结构为：

- `failure.code`：稳定错误码。
- `failure.summary`：面向用户的原因摘要。
- `failure.suggestion`：可执行建议；可能为空。

## 任务状态

| 状态 | 行为 |
|---|---|
| `PENDING` | 继续查询原 `taskId`。 |
| `SUBMITTED` | 已提交上游，继续查询原任务。 |
| `PROCESSING` | 正在生成，保留原任务并等待。 |
| `COMPLETED` | 校验结果 URL、数量和返回元数据。 |
| `FAILED` | 展示失败字段，停止当前任务。 |

## 处理原则

- 图片任务观察最多 3 分钟；视频任务观察最多 10 分钟。超出窗口时报告仍在处理和 `taskId`，后续继续查询同一任务。
- 余额不足时引导用户进入 AI-HIVE 钱包处理，不自动创建新任务。
- 参数无效时刷新模型目录，对照实时配置形成修正方案。
- 鉴权失败时引导用户重新连接 AI-HIVE Connector，不要求用户在对话中粘贴 Token。
- 内容策略拒绝时只建议修改相关内容，不承诺一定通过。
- 网络或上游错误不等于任务未创建；只要已有 `taskId`，就先查询原任务。
- 修改参数、Prompt、模型或路由后的再次生成属于新付费任务，必须向用户展示变化和价格并再次确认。

不得根据错误文案猜测内部分类、可重试性或供应商状态；没有返回的信息明确标记为未知。
