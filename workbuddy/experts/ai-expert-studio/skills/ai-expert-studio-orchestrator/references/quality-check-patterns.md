# 专家团质检模式

## Prompt QA

- 任务类型明确，Generate、Edit、Extend 不混用。
- 主体身份和数量与事实台账一致。
- 每份使用素材有唯一职责，未采用素材已列出。
- Prompt 不包含接口参数、内部分析或未解决占位符。
- Seedance 2.5 双版共享事实、素材和硬约束；增强版不是同义改写，也没有新增事实。

## 技术 QA

| 检查项 | 通过条件 |
|---|---|
| 任务状态 | `COMPLETED`；其他状态如实报告。 |
| 结果地址 | 工具返回非空 URL。 |
| 数量 | 返回数量与已确认的批量一致，或明确说明部分失败。 |
| 元数据 | 只报告工具实际返回的类型、尺寸、时长或缩略图信息。 |
| 失败 | 展示 `failure.code`、`failure.summary`、`failure.suggestion`。 |

## 视觉 QA 边界

收到 URL 不代表已经查看内容。运行时没有图片或视频预览能力时，QA 只能给技术结论，并标记“待用户视觉验收”。用户反馈具体缺陷后，QA 可以形成修复建议，但不能自行生成。

## 不通过后的处理

1. QA 描述问题和可选修正方向。
2. Lead 决定是否进入新任务评估。
3. Model Scout 刷新模型、路由和价格。
4. Lead 展示变化和新费用，取得用户确认。
5. Gen Executor 执行新的付费任务。

任何 QA 不通过都不会自动创建任务。
