# 建广告必填 ID / 凭证 · 前置校验清单

> **用途**：这是「代投（建广告）/ 盯盘（直接改账户）」动作的**前置闸门**。
> 只有当用户要艾投**真正连账户去建单或改账户**时，才逐项核对下面这张表——齐了才放行；只做**分析/复盘/给建议清单**时**不走**这套校验。
> 所有 Key 均来自腾讯广告投放 skill 的真实脚本参数，非杜撰。出处 = `tencentads-auth`（鉴权）、`tencentads-delivery-standard-create`（建单）、`tencentads-creatives`（创意）。

---

## 一、什么时候走校验 / 什么时候不走（先判断，再决定卡不卡）

| 用户在干的事 | 会不会连真账户 | 走不走前置校验 |
|---|---|---|
| **代投**：要艾投直接帮忙建广告（路径A授权直建 / 路径B金手指直灌） | ✅ 要连账户建单 | **✅ 走校验**（齐了才建） |
| **盯盘（托管改账户）**：要艾投直接改出价/预算/开关广告 | ✅ 要连账户改 | **✅ 走校验**（齐了才动手） |
| **只读分析**：读数据给调优/诊断清单（不直接改账户） | ❌ 只读或纯对话 | **❌ 不走校验** |
| **查问题（诊断）** | ❌ 只读或纯对话 | **❌ 不走校验** |
| **复盘 / 出报告** | ❌ 只读或纯对话 | **❌ 不走校验** |

> 一句话：**只有"要动用户账户"（建单 / 改账户）才校验**；只出主意、不亲自动手，就别用 ID 卡住用户。

---

## 二、必填 ID / 凭证表（校验时逐项对，齐了才放行）

| # | 字段名 | Key | 类型 | 来源 / 出处 | 谁来给 |
|---|---|---|---|---|---|
| -1 | 腾讯广告 apikey | `apikey` | string | `tencentads-auth` skill（鉴权凭证，所有 `tencentads-*` 脚本共享） | ✅ **用户一次性提供并保存**（授权钥匙，不保存则任何接口都调不通） |
| 0 | 账户 id | `account_id` | string | 建单+创意所有脚本顶层必填 | ✅ **用户给** / 从关联账户列表选 |
| 1 | 投放产品 id | `asset_id`（配合四元组 `marketing_target_type` / `marketing_carrier_type` / `marketing_goal` / `marketing_sub_goal`） | string + enum | `get-assets.mjs`（资产）→ 建单 | 🔧 系统查取（授权后） |
| 2 | 落地页 id | `carrier_id`（营销载体，落地页即一种 carrier） | string | `get-assets.mjs` 的 `carrier_hint.carrier_id` | 🔧 系统查取（授权后） |
| 3 | 转化归因 id | `conversion_id` | string | 建单顶层，`get-conversions.mjs` 返回（oCPM/oCPC 必填） | 🔧 系统查取（授权后） |
| 4 | 素材 id | `image_id` / `video_id` | string | `upload-image.mjs` 返回 / 商品模版生成返回 | 🔧 系统上传取（**图找素材经理·苏策，艾投不出图**） |
| 5 | 行动按钮组件 id | `component_id`（组件类型 `action_button`） | string / number | `get-component-list.mjs` 返回，用于 `creative_components` | 🔧 系统查取（授权后） |

## 三、校验怎么走（逐项列全再放行）

**触发校验后，艾投必须做这三步：**

1. **摊开来对**：把上面 7 行**逐项列给用户看**，每项标当前状态：`✅ 已就绪` / `❓ 待确认` / `❌ 缺`。别只报"缺了几个"，要让用户看到到底缺哪几项。
2. **两类分开要**：
   - `apikey` + `account_id` 这**两把钥匙**只能**用户给**——没给就停在这，用大白话说明"这是连你账户的钥匙和门牌号，你不给我进不去，也就没法帮你建/改"。
   - `asset_id` / `carrier_id` / `conversion_id` / `image_id` / `component_id` 这 5 个是**账户里的实体**，钥匙齐了由**系统连上去查/建**，不用用户逐个手填；查出来后**列给用户确认对不对**（尤其归因 id 要确认是不是"下单/留资"那个）。
3. **齐了才放行**：**7 项全部 `✅ 已就绪`**（用户给的 2 项 + 系统查到的 5 项都确认无误）才进入真正的建单/改账户动作。**有任何一项 `❌`／`❓`，就停下把缺口说清楚，不硬着头皮往下建**——这条与"不超出用户范围""只出清单不擅自动账户"两条铁律一致。

> **素材 id 特例**：艾投**不出图**。校验到 `image_id/video_id` 缺时，引导用户去专家中心找 **素材经理·苏策** 出成品图，再回到艾投上传拿 id。

---

## 四、两点严谨说明（延续既有口径）

1. **apikey 与其他 ID 性质不同**：`apikey` 是访问凭证，用户一次性给、`tencentads-auth` 保存后全脚本共享；`account_id` 起的 5 个是账户内实体，授权后系统查/建，不向用户逐个索取。
2. **"投放产品 id" 在 API 里不是单个 `product_id`**：靠四元组（`marketing_goal`/`marketing_sub_goal`/`marketing_target_type`/`marketing_carrier_type`）+ `get-assets.mjs` 查出的 `asset_id`；**"落地页 id" 归到营销载体 carrier**（`carrier_id`），没有独立的 `landing_page_id`。

---

## 五、与其他清单的关系

- **本表（实体 ID / 凭证）**：动账户时校验，系统查取为主，只两把钥匙向用户要。
- **`references/new_project_intake_checklist.md`（无 ID 版策略清单）**：新项目开建时向用户前置收齐**策略字段**（需求单/投放/素材/文案），**不问任何 ID**。
- 两者**互补**：用户负责"想清楚投什么"（策略字段 + 给两把钥匙），系统负责"把账户里的 ID 凑齐"。
