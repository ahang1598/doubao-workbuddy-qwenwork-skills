# 投放操作日志模板（投投 · 分项目存储）

> **用途**：投投做的**每一个操作**（尤其 API 直建/直改）都落成日志，全生命周期可追溯、可回滚参考。
> **存储规则（两处同步）**：
> 1. **本地**：一个项目一份独立文档，文件名 `投放操作日志_{offerName}_{YYYYMMDD}.md`，存于 `outputs/投放操作日志/`。
> 2. **同步金手指（✅ 已可用，2026-08-25 实测通过）**：调金手指 MCP `upsert_review_artifact({project, title, kind, payload})` 回灌。
>    - `project` 传项目名或项目 id（可先用 `list_projects()` 取准确名）；`kind` 用 `operation_log`；
>    - `payload` 为任意 object，约定放 `{source:"aitou", format:"markdown", content_md:"<日志全文>", ...}`；
>    - 回读校验走 `get_project_context({project})` → `review.artifacts[]`（每条含 `payload_json`）。
>    - 实测：中文 + Markdown 表格 + emoji 均无损；114KB HTML 体量写入成功；**同名 title 不覆盖而是新增一条**（append 语义，回灌历史留痕，天然契合追加式纪律）。
> **追加式**：所有记录**只追加不覆盖**，一个项目从"收策略单"到"每次巡检调优"全程记在同一份文档里。
> **多项目隔离**：不同 `offerName` 存不同文件，绝不混写。

---

## 使用说明（投投照做）

1. **首次建单时**：新建本文件（用真实 offerName / accountIds / date 替换占位），填「0. 项目档案」（策略单快照）。
2. **每做一个真实动作**（建营销单元/建创意/落自动化/调价/关停…）：往对应章节**追加一行**，记满 8 要素：`时间 / 阶段 / 操作对象(账户·广告ID) / 动作 / 变更前→后 / 依据 / 是否API直执行 / 结果`。
3. **每次交付**：把本文件本地保存 + 同步金手指一份，并在回复里给出文件路径。
4. **多项目**：每个 offerName 一份，文件名区分。
