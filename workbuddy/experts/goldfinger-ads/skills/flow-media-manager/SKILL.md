# 媒介策略·串联版（flow-media-manager）

全链路投放工作流的**第②环节【媒介经理】**。上游是 ad-demand-helper-pro 的《需求立项单》（对话栏文字）+《投放可行性评估清单》（HTML 文件），下游是 ai投手(flow-ai-shooter) 与 素材助手(flow-material)。

## 输入（读上游）

读 ad-demand-helper-pro 的 2 份产出：

### 输入 1：需求立项单（**从对话上下文读立项单完整文字，v1.27.0 起**）

> ⭐ **v1.27.0 数据源回切**：ad-demand-helper-pro v2.32.0 起**不再灌入金手指**（需求单阶段零 MCP 调用），因此**没有 session 可拉**——立项单**完整文字重新成为唯一权威源**，从对话上下文逐字段读取。
>
> ⚠️ **不要**再 `GET /api/mcp/session/{sid}` 取 `demand.groups`（v1.25.5～v1.26.x 的做法作废，那个 session 不存在了）；也不要 Read 立项单文件（不存在，它只是对话栏文字）。
>
> ⭐ **这些字段值有两个用途**：① 做策略；② **灌入时拼成 `demand.groups` 一并传给金手指**——v1.27.0 起**灌入合并为一次**，`demand` 需求单字段与 Part 2/3/4 策略字段在同一次 `open_config` 里全量灌入（原"提需先灌一次、策略再灌一次"作废）。所以取值时必须完整记住每个字段。

按立项单分区逐字段取值（对话栏文字里的字段名 → 内部字段语义）：
- **基础信息**：`offerId`（产品名称）/ `demand_offer_intro`（产品简介）/ `requestTitle`（标题行）
- **预算与测试目标**：`demand_test_goal`（测试目标）/ `demand_kpi`（考核指标，大白话）/ `demand_budget_limit`（总预算）/ `demand_budget_cycle`（投放周期）/ `demand_launch_date`（上线时间）
- **人群策略**：`demand_audience_logic`（客户类型/人群逻辑）/ `demand_core_ta`（核心人群）
- **素材与承接**：`demand_has_material`（现有素材）/ `demand_carrier`（转化载体，v2.22.0 起 og 载体槽位）/ `demand_product_channel`（商品渠道，v2.22.0 条件题）/ `demand_dev_resource`（开发资源）
- **其他**：`demand_compliance`（合规要求）/ `demand_history`（历史投放经验）/ `demand_selling_points`（核心卖点）

> ⚠️ 立项单里**没出现的字段就是没问到**（如预算来源、结束时间、落地页链接、渠道版位、人群数量）：按缺失处理，不阻塞，该由策略环节测算填充的就自己算。
> ⚠️ KPI 是大白话（如"品牌声量优先；单客获客成本不超过 100 元"）：AI 解析出策略方向（声量优先 → CPM/广覆盖）+ 成本上限（100 元 → oCPM 出价区间）。

### 输入 2：投放可行性评估清单 HTML 文件（3 段）

- **段 A 广告主类型**：推导画像（如"中小广告主·新手·To C·虚拟商品服务"）→ 影响策略激进程度
- **段 B 可行性评估**：6 维度（预算充分性/素材准备/合规风险/落地页承接/测试周期/KPI可达性）的 ✅/⚠️/❌ 状态
- **段 C 优化建议**：用户需要补什么

> ⭐ **策略针对性**（v1.2 起）：
> - ⚠️ 项 → **段 A 字段**里标注风险与建议（段C 已废，标注全部由段A 负责）
> - ❌ 项 → **段 A 字段**里标注"必须补齐才能投放"+ 具体补齐指引（**融入字段值，不要单独开 alert 块**）
> - 如"素材都没准备 ❌" → 段 B 标注"需先补产品图/视频素材"，具体指引融在段 B 的"成品规格"或"品牌资产透传"字段里

### 路径判定（参考可行性评估"历史经验"）

- 从没投过 / 无在投账户 → 走「基建路径」，参考 `ai-analysis-expert-newproject` 五维基建
- 投过没达预期 / 不错想扩量 / 正在投想优化 → 走「诊断路径」，参考 `ai-analysis-expert-diagnose`

### 投放方式判定（试跑发现的关键约束）⭐

- **用户指定了版位**（如"只投朋友圈+视频号""排除公众号"等强约束）→ 走**标准投放**（`tencentads-delivery-standard-create`），可手动指定版位
- **用户未指定版位 / 接受智能择优** → 走**智投 AIM+**（`tencentads-delivery-smart-create`），版位系统智能择优

> ⚠️ 原因：智投(AIM+)版位是系统智能择优，**不可手动指定"只投某版位/排除某版位"**。若立项单有版位强约束却走智投，建单后版位不可控。
> 此判定结果写入段A「投放方式」字段，ai投手据此选调哪个建单 skill。

**转化归因前置条件（试跑发现的关键约束）⭐**：
> 建单时 conversion_id 必须带链路信息，否则报 1801106。账户需先在腾讯广告后台配置转化归因链路。
> 若用户账户未配置，媒介经理应在段A末尾提醒，并给出以下指引（来源：WebSearch 联网查腾讯广告官方文档）：
> 1. 开通权限：联系行业运营，提供 UID/MDMID 申请开通「营销链路」权限
> 2. 新建转化：投放管理平台 →【资产】→【数据营销】→【转化归因】→ 新建转化
>    - 小程序：填 AppID(gh_开头) → 选优化目标 → 选营销链路 → 勾选上报节点
>    - H5网页：填落地页URL → 获取JS密钥嵌入 → 选优化目标 → 选营销链路 → 勾选上报节点
> 3. 联调激活：进入「转化联调」→ 上报行为数据 → 激活
> 4. 建广告时选新的带链路的 conversion_id

**品牌形象组件前置条件（试跑发现的关键约束）⭐**：
> 建创意时 brand 组件是模板必填项（缺则报"模板必填组件缺失: brand"），需在腾讯广告后台预先配置**新版品牌形象**（旧版报1800355"must use new version brand"，全场景强制新版）。
> 若用户账户未配置，媒介经理应在段A末尾提醒，并给出以下指引：
> 1. 入口：投放管理平台 →【资产】→【创意资产管理】→【品牌形象】
> 2. 新建**新版**品牌形象：
>    - 上传品牌 logo 图（**512×512像素**，新版统一标准）
>    - 填写 brand_name（**2~12个字**，如"某某优选"）
>    - 保存后在创意中用 component_id 引用（数字类型，如 `{"component_id": 1940737385209}`）
> 3. ⚠️ 旧版品牌形象（200×200/80×80/300×300等规格）已不可用，全场景报1800355，必须新建新版
> 4. 查账户已有品牌组件：`get-components.mjs '{"account_id":"<ID>","component_type":"BRAND"}'`，返回含 component_id + brand_type(common/wechat_channels等)

**落地页前置条件（试跑发现的关键约束）⭐**：
> 建创意时 main_jump_info 落地页组件是模板必填项，需账户侧预先在【资产→创意资产管理→落地页】中配置好落地页（不限于小程序，H5/小程序/应用宝等各类落地页均在此配置）：
> - 入口：投放管理平台 →【资产】→【创意资产管理】→【落地页】→ 新建落地页
> - 按落地页类型配置（小程序/H5等），配置并审核通过后建创意时引用
> - 若未配置：建创意时报 1800007 "Invalid ID of wechat mini program"（小程序）或落地页字段为空等错误
> 若账户未配置，媒介经理应在段A末尾提醒用户先到【资产→创意资产管理→落地页】配置落地页。

### 段 A：投放策略段（给 ai投手 建单用）⭐v1.20.0 补五维基建分档推导
五维基建给**具体数字区间**（默认基线，用户有经验则覆盖）。**v1.20.0 起：区间必须按预算分档推导给出**（不再给"裸区间"）：

- **投放方式**：按上方「投放方式判定」结论填写。**格式固定**（v1.20.0）：`智投 AIM+（tencentads-delivery-smart-create）` 或 `标准投放（tencentads-delivery-standard-create）`——skill 名括号附在后面，让 ai投手直接复制选用建单 skill。**v1.23.0 起**：是否智投不设独立字段，由本字段派生（`isSmartDelivery` = 智投 true / 标准 false，灌 open_config 时派生后照传）
- **优化目标 og（v1.24.0 判定逻辑重写，建单必填）**：双字段——`optimizationGoal`（og 英文枚举）+ `optimizationGoalName`（og 中文名）。**判定对照 `references/og-library.md`（层1 语义路由层：33 个浅层 og，不含深转、不含行业特化）**：官方四元组联动（营销目的→推广产品→营销载体→优化目标）+ 归因硬门槛（不接归因=不能用转化 og）——**营销目的输入 = C2 投放目标（v1.24.7 起 C1 已删，品牌宣传由 C3"品牌声量优先"单信号路由）**；小店=平台自动归因（**优先推荐**，前提=告知用户自行搭建官方小店落地页）；落地页=JS；App=SDK/API；无归因=**点击 og + CPC 出价（兜底）**。**出价联动二分**（v1.24.2）：选转化 og → bidding 只能 oCPX（与 `bidding` 交叉校验，矛盾即报）；选点击 og 兜底 → bidding 必须 CPC（按点击计费，不优化转化）。行业特化 og（金融开户/入金、教育低价课、短剧看剧等）不进库，涉及时调知识库查
- **账户**：账户数（**按日预算 4 档分档推导**，v1.20.0）+ 账户类型三选一（白户首选/老户重启/灰户避开）：
  > <1000 元/日 → 1 个 ｜ 1000-5000 → 1-2 个 ｜ 5000-20000 → 2-3 个 ｜ >20000 → 3-5 个
  - 字段值附一行小字推导："日预算 X 元 → 推 N 个账户"。**不再一律"默认 1 白户"**（高预算项目会被低估账户数，过审风险高、量级天花板低）
- **版位**：主投版位(依提需渠道偏好)、排除版位
- **广告结构**：**按日预算 3 档分档**（v1.20.0）：
  > <2000 元/日 → 3×3×5 ｜ 2000-10000 → 3-5×3-5×5-10 ｜ >10000 → 5×5×10
  - 字段值给分档结果（如"日预算 3000 → 4 广告 × 4 创意组 × 8 素材"），不给通用裸区间
- **出价**：出价方式(oCPM等)、出价金额区间、考核指标(AMS枚举，透传自需求单)。**考核指标分两个独立字段**（v1.24.1）：`kpi`（考核目标，单指标、只用成本口径，如 `成本≤90元` CPA 上限，透传需求单成本预期）+ `kpiRedline`（考核红线，**与 kpi 平级、独立指标**而非成对关系，按指标类型推导——**成本类**：常规 × 1.2-1.3 上浮；**ROI/量/率类**：常规 × 0.7 下浮；**触发动作暂不建设**，字段值先录入）。**v1.20.0 出价公式（核心推导依据）**：
  > **初始出价 = 考核成本 × 50%-70%**
  - 字段值附一行小字推导："考核成本 X 元 × 0.5-0.7 = 初始出价 Y-Z 元"——金额区间是**结果**，公式是**依据**（可施工内容，不属"待办型警告"，保留）
  - 调价节奏附在字段值里：单次调价 ≤10%、观察 4 小时再动、冷启动期别频繁调、累计 5-10 个转化后可回调
- **预算**：日预算/总预算/上线日期(透传)
- **定向/时段**：
  - **定向方式默认值**（v1.20.0）：`系统智能定向（首选），有老客种子叠加 lookalike`——oCPM 宽松定向利于探索，有种子再叠
  - **投放时段基线**（v1.20.0，用户经验可覆盖）：00-07 低/暂停 ｜ 09-11 放量 ｜ 14-17 观察 ｜ 20-23 高峰
  - 🚨 **日内时段渲染硬规则**（v1.25.6，实测 bug 修复）：时段基线在字段值里**就是一行文字**（`00-07 低/暂停 ｜ 09-11 放量 ｜ 14-17 观察 ｜ 20-23 高峰` 这种竖线分隔格式）——**禁止**做成"每小时一行"的表格（实测 bug：agent 自由发挥把时段拆成 0-0 / 1-0 / 2-0- 每小时一行，且把字符串当 iterable 逐字符遍历出乱码）；**禁止**对时段字符串做逐字符 enumerate——它是 4 个"区间+短语"块，不是字符序列
  - `deliveryHours` 传金手指时 key 是**时段区间**（如 `"00-07"`、`"09-11"`），值是**单个短语**（如 `"低/暂停"`、`"放量"`）——共 4 块左右，不按小时拆 key
- **素材池衔接**（v1.20.0 新增字段）：`素材池储备`——按段B 预算驱动测算结果填（如"20 张图片（总预算 6000 → 20 张档）"），让 ai投手建单时一目了然池子里有什么，避免段A/段B 信息断裂
- **上新节奏**（v1.20.0 新增字段）：`每 3-5 天补 1-2 条素材进池`——写"上新节奏"字段，让 ai投手/用户知道上线后怎么保持池子活性

**④ 基建驱动测算公式（v1.22.0 新增，精确数字以此为准）**

> 输入：**日预算**（段A）+ **CPA**（考核成本，需求单 KPI 解析）。公式把「预算 → 基建（广告数）→ 素材/文案数量」串成一条线。

| 输出项 | 公式 | 说明 |
|---|---|---|
| 广告数 | `日预算 ÷（CPA × 20）` | 每条广告日消耗达 CPA×20 才能积累足量转化跑出模型；算出日预算能支撑的并行广告条数。结果取整，不足 1 条按 1 条 |
| 素材数 | `广告数 × 3-5` | 每条广告配 3-5 素材，与段A 广告结构分档一致 |
| 外层文案数 | `= 广告数` | 每条广告 1 条外层文案（外层文案与按钮汇总表 ⑦ 按此动态算） |
| 首条评论数 | `= 广告数` | 每条广告 1 条首条评论（朋友圈版位） |

**硬约束：首次投放（基建路径）素材储备不低于 30**——在投素材（广告数×3-5）是当期消耗量，素材池储备（首投 ≥30）是轮换余量，两者别混；`materialPool.total` 按储备口径填。

**示例**：日预算 1500 元、CPA 90 元 → 广告数 = 1500÷(90×20) ≈ 0.83 → 1 条；素材 = 3-5 张/广告；外层文案 1 条、首条评论 1 条；首投素材池储备 ≥30。

## 全局原则
- 五维基建/诊断方法论参考 `ai-analysis-expert-newproject`/`-diagnose`，**不改原 skill**。
- **投放方式判定**：用户指定版位→标准投放；未指定/接受智能择优→智投AIM+。判定结果写入段A，ai投手据此选建单skill。
- 缺口C：品牌资产**引用**需求清单，不复制原始文件，素材助手以需求清单为准取原图。
- **两段一气呵成产出**（v1.18.0 起；v1.26.0 起无 HTML）：段A+B 一次做完，不做段间确认（段C 已删）——主路径直接落成 strategy 结构化字段灌入金手指，**不写本地 HTML**
- **主路径无 HTML；HTML 仅 fallback**（v1.26.0 起）：仅当金手指 MCP 不可用 / `degraded:true` 时，才写《投放执行确认单-[项目名].html》存档——**骨架走 `html-report-card`（与可行性评估同模板，v1.28.0 起统一）**，内容结构照 `references/html-memo-template.md`，theme.css 全文内联、文件自包含，跑 check_html.py 0 error 才交付；按既定轨道打开，话术改回"确认后我再灌入"
- **UI 必须与可行性评估一致**（v1.2.1 起，仅约束 fallback 产物）：系统字体 + `#f7f7f5` 纸底 + 单白卡 + `#378ADD` 主色 + 细线分隔 + **topbar 金手指 logo**（v1.14.0 起）；禁止玻璃拟态/渐变文字/深色代码块/入场动画。写文件前过一遍模板末尾「一致性自检」。
  - ✅ **v1.28.0 已统一**：fallback 确认单与可行性评估**共用 `html-report-card` 卡片规范**（用户决策 2026-08-26）——两份产物 UI 一致；`html-memo-template.md` 降级为纯内容结构指南。
- **策略完成必须灌入金手指**（v1.25.0 起取代 v1.5"写完必须打开"；v1.26.0 改述）：段A/段B 字段拼装完成后立即 `open_config` 灌入 + session 双重校验 + present_files 拉起配置页，不要只说做了什么而不做。**灌入成功 ≠ 交付完成**——校验失败要重灌并如实告知用户。
- ⭐ **立项单从对话上下文读**（v1.27.0 起）：不要 Read 立项单文件（不存在），也不要 curl session（提需阶段已不灌入，无 session）；直接从对话栏那份完整立项单文字逐字段取值。
- 🚨 **素材数量禁止照抄示例**（v1.26.0）：`materialPool` / `creativeDirections[].count` / 外层文案与首评条数，**必须由段B 预算驱动测算公式当次算出**——禁止照抄本 skill 任何示例值、反例数字或上一个项目的数量（实测发现 agent 把反例里的"8 条素材"抄进了真实产出）。
- 🚨 **og 枚举照抄产物原文**（v1.26.0）：`optimizationGoal` 英文枚举与 `optimizationGoalName` 中文名，**照抄段A og 判定结论的原文**（评估/确认逻辑里定的是什么就传什么），灌入时不临场改枚举、不凭印象编——枚举错位会导致金手指页面按钮/目标错配。
