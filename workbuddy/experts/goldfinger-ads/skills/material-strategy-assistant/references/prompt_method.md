# 生图提示词写作方法（可独立编辑）

> ✅ **当前状态：已启用。** 13 类「典型提示词模板」已补齐（见文末「各创意类型画面规范」），执行手册的"生成提示词"列**逐条真正输出提示词**、可据此出图。
> 每类同时配了一张**标准样式参考图**（平台案例库官方样例，运行时由 `scripts/fetch_case_samples.js` 落地到输出目录 `assets/case_samples/`，文件名以其 `[RESULT]` 为准；本地 `assets/case_samples/` 为兜底副本），供选型和向用户展示"这类素材长什么样"。
> 本文件的两段式流程、三级生图链路、各类型画面规范与提示词模板均为权威依据。

> 本文件是「生图提示词写作方法 + 生图执行链路」的唯一权威来源。要调整提示词写法或生图渠道策略，只改本文件即可，SKILL 主流程会引用它。

## 两段式流程：先打磨提示词，再执行生图

```
图片文案 ──▶ 【第1段】提示词优化打磨提示词 ──▶ 【第2段】三级生图链路执行 ──▶ 素材图
             (SOCAWT 六维补齐)                  (内置 → 已配key模型 → 索要key)
```

**两段必须都走，不可跳过第 1 段直接拼提示词。**

## 第 1 段：用「提示词优化」打磨提示词（强制）

写素材生图提示词时，**必须先走「提示词优化」方法（内置参考资料 `references/prompt-optimizer/prompt-optimizer.md`）的模式一（直接创作）**，用 SOCAWT 六维框架把 Brief 信息补齐成一条高质量提示词，而不是自己随手写一句。

### 调用方式

直接**读取本地参考资料** `references/prompt-optimizer/prompt-optimizer.md`（及其同目录 `references/soca-wt.md`、`references/prompt-craft.md`），按其**模式一：直接创作提示词**执行，无需通过 Skill 工具单独加载任何技能。

### 从 Brief 到 SOCAWT 的映射（提示词优化的输入）

打磨前先把本 skill 已有的 Brief 信息按下表整理好，作为提示词优化 9 要素的输入，**不要反过来向用户提问**（信息已经在 Brief 里了）：

| 提示词优化 9 要素        | 从素材 Brief 哪里取                 |
| ---------------- | ----------------------------- |
| 1 用途             | 版位 + 创意类型（如"微信朋友圈 常规海报"，类型须为 13 种之一）       |
| 2 主题（C Core）     | 模块A 关键洞察的核心信息                 |
| 3 主体（O Object）   | 产品主体 + 创意类型的表现要求（人物/产品/场景）    |
| 4 风格（A Artistry） | 模块B 设计风格                      |
| 5 构图（S Space）    | 模块B 主跑尺寸/比例（9:16 / 1:1 / 3:4） |
| 6 文字（T Type）     | 该条图片文案原文（**必须加引号**）           |
| 7 色彩（W Wash）     | 关键洞察的情绪基调（温柔治愈/热烈/高科技…）       |
| 8 限制             | 合规红线 + 留白要求（logo/风险语留位）       |
| 9 输出质量           | 分辨率档位（草图 1K / 终图 2K-4K）       |

### 模板选择

- 数字人海报 / 常规海报 / IP海报 / 户外海报（产品实拍/场景感强）→ **模板 A（导演口述式）**
- 榜单素材 / 小红书笔记 / 备忘录 / 公众号资讯 / 大字报 / 九图拼接 / 四图拼接（信息型/版式型）→ **模板 B（设计简报式）**

### 打磨后必须做的"降复杂度"收敛（本 skill 特有）

提示词优化产出的提示词偏长、偏完整；但**信息流素材实测：过长 prompt 反而不稳定**。所以拿到它的产出后，按下面三条收敛，再送去生图：

1. **保留**：主体 + 场景 + 光线 + 情绪色调 + 参考系（这几项是提示词优化带来的增量价值，务必留下）。
2. **删掉**：预防性负向词堆砌、`--ar` 之类参数语法、与画面无关的元数据说明。
3. **文案单独起段**：画面描述收敛到 1-3 句，然后另起一段用 `画面上的文案：` 承载文字，文字原文加引号。

> 收敛后长度参考：画面描述 1-3 句 + 文案段。既比"随手一句"信息量足，又不至于长到失控。

### 收敛后模板

```
{画面描述 1-3 句：主体 + 场景 + 光线 + 情绪色调 + 参考系}
画面上的文案：
"{文案第一行}"
"{文案第二行}"
```

需要主副标题或指定对齐时：

```
画面上的文案：
主标题："{主标题}"
副标题："{副标题}"
文案左对齐
```

> 三种引导语可互换："画面上的文案：" / "图片上文字是：" / "画面中的文案是："
>
> 🚨 **每条提示词最终都要叠加本文件「素材通用要求」段**（不出现多余数字文字、无 logo、不变形、文字落在 20%–80% 安全区、底图满幅出血、内容为中文、按风格维度随机组合）。类型专属规范 + 通用要求，两者都要，缺一不可。

### 参照范例（打磨前 vs 打磨后）

打磨前（自己随手写，信息稀薄、容易千人一面）：

```
暖光卧室床头，一支点燃的香薰蜡烛，柔和光晕，写实温馨治愈。
画面上的文案：
睡前一支慢下来
```

打磨后（走过提示词优化 + 收敛，补齐了光线方向、参考系、画幅、留白）：

```
请生成一张竖版 9:16 的照片。暖光卧室床头柜上，一支点燃的香薰蜡烛，火苗微微晃动，柔和光晕晕开在亚麻床品上，侧后方一盏暖黄小夜灯做逆光，整体色调偏暖琥珀色，参考日式生活方式杂志的克制、有呼吸感的调性。底部留出干净空白区。
画面上的文案：
"睡前一支 慢下来"
```

> 差异点：加了光线方向、参考系锚点、画幅比例、留白区，文案加了引号。这些正是提示词优化带来的增量。

## 第 2 段：三级生图链路（按顺序降级，不许跳级）

### L1 · WorkBuddy 内置生图（首选，默认走这条）

**默认第一选择**：直接调用 WorkBuddy 内置的生图工具能力（ImageGen），无需用户配置任何 API Key。

参数对齐：

| 参数         | 取值                                                             |
| ---------- | -------------------------------------------------------------- |
| prompt     | 第 1 段收敛后的提示词                                                   |
| size       | 按 Brief 尺寸换算：9:16→`1024x1536`、1:1→`1024x1024`、16:9→`1536x1024` |
| quality    | 草图 `medium`，终图 `high`                                          |
| n          | 同方向要多张备选时用 2-3，否则 1                                            |
| output_dir | 当前工作目录下的素材输出目录                                                 |

> 内置能力不支持任意比例（如 3:4、21:9）时，选最接近的档位，并在交付说明里注明"已按最接近比例出图，投放前可裁切"。

### L2 · 用户已配 key 的模型（内置失败时自动降级）

L1 失败（报错、超时、被拒、无返回图）时，**先探测再调用**，不要盲试：

```bash
node {baseDir}/scripts/detect_image_channels.js
```

- 退出码 `0`：有可用渠道 → 取 `[RESULT]` 里的首选渠道，用它的 `cmdTemplate` 生图。
- 退出码 `1`：无可用渠道 → 进入 L3。

当前内置探测的渠道（按优先级）：

|  优先 | 渠道                          | Key 变量           | 运行环境      | 备注                         |
| :-: | --------------------------- | ---------------- | --------- | -------------------------- |
|  1  | API易代理 · NanoBananaPro      | `APIYI_API_KEY`  | node（零依赖） | 国内直连，最省事                   |
|  2  | Gemini 官方 · Nano Banana Pro | `GEMINI_API_KEY` | `uv` + 外网 | 缺 uv 时提示 `brew install uv` |

降级时要**明确告知用户**："内置生图这次没成功，已自动切到你配好的 {渠道名} 继续出图。"不要静默切换。

### L3 · 用户有明确模型偏好 / 无可用渠道 → 提醒输入 API Key

触发条件（满足任一）：

- 用户明确点名了某个模型（"用即梦""用 nano banana""用 GPT-Image"等）；
- L1 失败且 L2 探测无可用渠道。

此时**停下来向用户索要 Key**，一次说清三件事（别只丢一句"缺 key"）：

1. 需要哪个环境变量名；
2. 去哪里申请（给链接）；
3. 怎么设置（给可复制命令）。

话术模板：

> 要用 {模型名} 出图，需要你的 API Key：
>
> 1. 申请地址：{keyUrl}
> 2. 设置命令：`export {KEY_NAME}="你的key"`（想长期生效就加到 `~/.zshrc`）
> 3. 设好后跟我说一声，我立刻接着出图。
>
> 也可以先用 WorkBuddy 内置生图看效果，等你方便了再切到 {模型名}。

**Key 处理红线**：Key 只在当次命令/环境变量里用，**绝不写进 SKILL、references、Brief、日志或任何交付文件**；不回显 Key 内容。

### 链路决策速查

| 情况                 | 走哪条                       |
| ------------------ | ------------------------- |
| 用户没提模型偏好           | L1 内置                     |
| L1 失败，探测到已配 key 渠道 | L2，并明确告知已降级               |
| L1 失败，无已配 key 渠道   | L3 索要 Key                 |
| 用户点名了某模型           | 直接 L3 校验该模型 Key；已配好则直接用   |
| 用户点名模型但没 Key       | L3 索要 Key，同时给"先用内置顶一下"的选项 |

## 出图工作流（草图 → 选 → 终图）

1. 每个创意方向先出 **1 张草图**（低分辨率/medium 质量），快速验证方向。
2. 多方向草图**一次性汇总呈现**给用户选，别一张一张问。
3. 用户选中的方向再出**终图**（高分辨率/high 质量）。
4. 出错就**小步微调一处**再试（改一个词/删一句），不要整条重写。

## 🚨 出图文件命名规范（用户确认策略后直接出图时强制遵守）

用户确认策略后、直接选择用某模型出素材时，**每张落地素材的文件名必须规范化**，统一格式（四段，用下划线 `_` 连接）：

```
{项目名称}_{素材类型}_{生成时间}_{生成序号}.{扩展名}
```

- **项目名称**：本项目产品名（如 `手工香薰蜡烛`）；含特殊符号的做安全化处理（`固收+` → `固收plus`，空格去掉或转下划线）。
- **素材类型**：只能用官方 13 类图片类型原名或 4 类视频类型名（常规海报/模拟朋友圈/…/IP海报；情景剧/单人口播/动图/混剪），**严禁自创类型名**——与执行手册「创意类型」列保持一致。
- **生成时间**：出图时刻，格式 `YYYYMMDDHHmm`（如 `202608221530`）。🚨 时间戳**必须用 `date` 命令实时取**（如 `date +%Y%m%d%H%M`），不要手算或写死。
- **生成序号**：同一「项目+类型+时间」批次内从 `01` 起两位递增（`01`、`02`…）；避免重名。

**示例**：`手工香薰蜡烛_榜单素材_202608221530_01.png`、`手工香薰蜡烛_常规海报_202608221530_02.png`、`手工香薰蜡烛_单人口播_202608221531_01.mp4`。

> 说明：这个命名让素材一眼可溯源（哪个项目、什么类型、什么时候出的、第几张），也便于后续按批次归档与投放端上传管理。草图阶段可不强制，**终图/交付给用户的素材必须按此命名**。

## 少数必要约束（仅出问题时加，不预防性堆）

- 出现二维码 → 加"不要出现二维码"
- 背景纯白 → 加"背景不要纯白"
- 多余乱字 → 加"除指定文案外不要其他文字"
- 文字排不下 → 缩短文案字数，而不是加约束词

## logo / 风险提示语 / 品牌资产

不写进 prompt（模型叠加不精准），也不做程序拼接。需要时让画面**留出干净区域**（"底部留出空白区"），后置用「妙思」精确叠加。

品牌资产只接收**干净原始素材**：透明底 PNG/SVG logo、高清产品图、可复制的 slogan/风险提示语、明确色值。不要把用户随手截的模糊图当最终资产使用；截图最多作为参考，否则容易导致清晰度不足、背景不干净、格式混乱、边缘毛糙或文字识别错误。

## 素材通用要求（🚨 底层提示词，对所有素材生效，每条生图提示词都必须叠加）

> 这是**所有创意类型共用的底层约束**。拼装任意一条生图提示词时，先套下方「各创意类型画面规范」的类型专属要求，**再叠加本通用要求**一起送去生图。本段优先级最高，与任何类型规范冲突时以更严格者为准。

**画面：**
- 生成的图片**不要出现除给定信息以外的任何数字和文字**。
- 底图要和文案有关联、不突兀；底图画面要**铺满尺寸**，不能出现奇怪的切割。
- 画面上**不允许出现任何 logo**。
- 图片内容比例要贴合尺寸，**画面比例正常、不要变形**。

**文案排版：**
- 文案布局合理，**行间距和字间距保持一致**，不过度紧密或宽松，**严禁文字挤在一起**，保障阅读体验。
- 文字与画面上下边缘保持**至少 20% 的安全距离**（即文字落在画面 **20%–80%** 范围内）；但**底图视觉元素应铺满整个画面**，不限于文字安全区内。**底图必须满幅出血。**

**语言：**
- 素材上的内容**均为中文**。

**风格随机组合（每次生成都要重新组合，避免千篇一律）：**
从以下维度各选一个或多个词，自由组合成本次画面风格；**同一维度内可组合 2–3 个词增强张力**；每次生成的组合必须**明显不同**：

| 维度 | 可选词 |
|---|---|
| 调性 | 高级 · 克制 · 权威 · 温暖 · 亲切 · 活泼 · 活力 · 理性 · 专业 · 年轻 · 治愈 · 稳重 · 大气 · 警示 · 醒目 |
| 质感 | 3D金属 · 3D玻璃 · 3D磨砂 · 3D软萌 · 扁平插画 · 拟真摄影 · 渐变流光 · 哑光 · 纸感 |
| 色彩语言 | 黑金（低调奢华）· 暖色系（亲切活力）· 冷色系（理性科技）· 马卡龙（治愈年轻）· 高饱和撞色（吸睛）· 低饱和莫兰迪（高级耐看）· 深底亮字（警示醒目） |
| 光影氛围 | 聚光 · 舞台光 · 柔光 · 冷光粒子 · 金色光晕 · 发光光带 · 素净无光效 |
| 意象隐喻 | 金条金币 · 科技芯片电路 · 城市建筑 · 文件放大镜 · 徽章奖牌 · 上升箭头 · 树苗成长 · 星空远山 |

> 用法：同一批多条素材要**跨维度错开组合**，让每条画面风格有明显差异，禁止全批用同一套风格。

## 各创意类型画面规范（13 种，权威范围，不许自行命名）

> 来源：《各类型素材输出规范》。下方 13 种是**唯一合法的图片创意类型**，策略选型的画面依据落在对应类型的规范内。
> 每种类型给出：**画面规范**（构图/风格硬约束）+ **标准样式参考图**（同上：`fetch_case_samples.js` 平台落地、本地兜底，展示"这类素材长什么样"）+ **典型提示词模板**（可直接改词复用）。
> 与文案规范配套：同名类型的文案规范见 `copywriting_method.md` 的「各创意类型文案规范」。
>
> 🚨 **提示词模板用法**：模板里 `{}` 为待替换占位——把本项目的产品主体/卖点/人群/图片文案原文代入即可；文案原文务必**加引号**、单独起段。代入后**再叠加上方「素材通用要求」**一起送去生图（类型专属 + 通用要求，缺一不可）。
> 🚨 **风格不要照抄样例**：参考图是金手指自家产品（蓝色科技调）的样例，仅示意**版式结构**；实际出图的色彩/质感/意象要按「素材通用要求」的风格维度，结合本项目行业调性重新组合，避免千篇一律。

### 1. 常规海报
- **画面规范**：素材样式=底图+文案。底图不杂乱、图文布局合理、底图与文案关联不突兀、底图铺满画面尺寸。风格简约、专业（金融类可偏严肃有金融感；其他品类按行业调性走，如宠物/家居可温暖治愈）。**文案在画面中占比不小于 50%**。
- **标准样式参考图**：`assets/case_samples/常规海报.webp`
- **典型提示词模板**：
```
请生成一张横版 16:9 的信息流广告海报。底图是{与产品/卖点强相关的干净场景或抽象意象，如：向上生长的柱状图与上扬箭头、柔和光晕铺开}，画面简约、留白充足、不杂乱，整体{按行业选调性：金融=严肃专业有金融感/家居香氛=温暖治愈}。左侧大面积留给文案区，右侧放主视觉元素，图文布局平衡，底图满幅出血、铺满整个尺寸。
画面上的文案（占画面 50% 以上、清晰醒目）：
主标题："{主标题，≤15字}"
副标题："{副标题，≤15字，可省}"
```

### 2. 模拟朋友圈
- **画面规范**：从**用户头像+昵称**开始模拟朋友圈信息流；**不要**绘制手机顶部系统状态栏和朋友圈导航标题栏。构成=白色底图+朋友圈正文+头像昵称+配图+评论。**只出现一条朋友圈内容**，配图要生活化或与文案关联。风格真实自然、有原生感。
- **标准样式参考图**：`assets/case_samples/模拟朋友圈.webp`
