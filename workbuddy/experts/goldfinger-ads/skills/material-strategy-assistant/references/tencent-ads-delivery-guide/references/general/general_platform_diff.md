# 第八部分　平台差异对照

> 底层逻辑相通，但**具体参数、产品名、口径各平台不同**。这部分是换平台时的速查表。

## 8.1 学习期门槛与稳定期对照

这是最容易混淆的地方——不同平台的门槛本来就不一样，不存在"唯一正确答案"。

| 平台           | 主流出价方式          | 学习期门槛                  | 稳定期   | 特点                                    |
| ------------ | --------------- | ---------------------- | ----- | ------------------------------------- |
| **巨量引擎/头条**  | oCPM            | **20 个转化**（口径：首投 4 天内） | 3-5 天 | 算法最成熟、流量最大、支持转化目标最多。适合日均 3000+ 的效果广告主 |
| **腾讯广告**     | oCPM / oCPC 都支持 | **30 个转化**             | 3-7 天 | 社交流量（微信/QQ），用户画像最精准。适合小程序/社交电商        |
| **百度**       | oCPC            | **30 个转化**             | 5-7 天 | 搜索流量 + 信息流，意图更明确、转化相对精准。适合教育/医疗/B2B   |
| **Meta（海外）** | ——              | **50 个转化**（口径：7 天内）    | ——    | 口径不同，逻辑一致                             |

**选择建议**：预算充足选头条，搜索流量选百度，社交裂变选腾讯。

⚠️ **深度转化目标要放宽**：以上是浅层转化（激活/注册/表单）的门槛。深度转化（付费/次留/ROI）数据稀疏，所需转化数与时间都要相应放宽。**执行时以你实际投放平台的官方口径为准。**

**复制计划也要重新过学习期**——复制走的是配置，模型积累的转化数据留在原计划身上。原计划的预估转化率是几百个真实转化喂出来的，这份"记忆"复制不走。

## 8.2 巨量引擎 / 千川

**产品矩阵**：巨量广告（竞价）、千川（电商直播）、本地推、星图（达人）、穿山甲（联盟）、巨量创意、巨量算数、巨量云图。

### 千川特有的判断

- 千川不能只调广告参数——**商品、价格、库存、直播间承接会实时改变投放结果**
- 千川素材的本质是**用钱买确定性流量**，而不是赌自然流量的运气
- **致命误区**：同一条视频既发主页挂车吃自然流、又投千川烧钱。结果视频内容偏内容向，两头都不讨好
- **正确做法**：两套素材体系、两套考核标准、两套优化逻辑。挂车爆款复制投千川，千川爆款优化后发主页挂车

### 千川素材测试 SOP

**测试前三件事**：

1. **账户权重确认**——新账户先跑 100 单建立模型；老账户检查近 7 日 ROI 是否 ≥ 目标值。权重低时强测 = 烧钱
2. **测试预算分配**——单素材测试预算 = 目标 CPA × 50（CPA 80 元 → 单素材 4000 元），同时测 3-5 条，总预算 1.2-2 万
3. **计划结构**——投放方式：专业推广（精准控量）；出价方式：控成本投放（目标成本 = 1.2 倍预期 CPA）；投放时段：全天或高峰（18:00-23:00）

**72 小时黄金测试周期**：24h 看趋势（CTR）→ 48h 看转化 → 72h 定去留。

**UBMax 自动化投放**：日预算建议 ≥ 目标成本 × 50，给机器足够探索空间；素材丰富度 = 机器优化的上限。

### CID 引流链路（电商投手必懂）

CID 是把广告点击与商品页打通的技术链路，用于站外引流到抖音电商，需配置商品 ID 与监测参数。

## 8.3 腾讯广告（AMS）

**产品矩阵**：ADQ（投放平台）、广点通、优量汇（联盟）。

### 版位与形态

| 版位类型         | 具体形态                                         |
| ------------ | -------------------------------------------- |
| 微信生态         | 朋友圈广告、公众号/小程序广告、视频号原生广告、搜一搜广告、互选广告、看一看广告     |
| PCAD（腾讯媒体矩阵） | 闪屏、信息流、贴片、蒙层、激励、搜索（覆盖 QQ、QQ 浏览器、腾讯视频、QQ 音乐等） |
| 优量汇          | 开屏、插屏、激励、信息流（域外流量聚合）                         |
| 互动形态         | OneShot、Phonemax、互动闪屏、信息流破框、TVmax            |

**朋友圈广告的用户数据参考**：日均渗透率接近 75%；超 8 成用户看完朋友圈广告后会有行动。

**朋友圈竞价广告特点**：CTR 高、转化高；支持首条评论、支持挂载图文组件、支持一键下载/应用直达、支持直接留企业微信名片。

### 关键操作差异

- ⚠️ **不要把朋友圈和视频号混为同一种流量**——版位合并会掩盖真实问题，必须**拆分版位**排查
- 腾讯 ADQ 视频号有三个入口：原生内容（主页内容拉取）、互动沉淀原视频、直播推广（短视频推直播）
- **ADQ 原生内容赛马**：目标不是买播放，是挑出值得追投的主页内容。做法是 5 条主页内容同题不同钩子（同产品、同利益点，只换前 3 秒和钩子），点击 × 停留 × 组件点击同时过线者胜出，5 选 1 进入原生放大
- 视频号小店智投配置：单账户预算建议 > 5000 元（预算太抠系统没探索空间）；小店管理员扫码确认绑定视频号，最多可批量绑定 20 个

### 企业微信获客链路

腾讯全流量（微信广告、腾讯平台与内容广告、优量汇）均支持企业微信获客：

- **直跳链路**：各流量版位直跳企业微信名片，高效获客
- **筛客链路**：通过落地页组件、公众号关注等二跳加微，高效筛客

## 8.4 小红书（聚光 / 薯条）

### 聚光 vs 薯条：流量基因完全不同

|      | **聚光（收割型）**                   | **薯条（种草型）**  |
| ---- | ----------------------------- | ------------ |
| 用户来源 | 搜索关键词、笔记评论区、商品详情页             | 发现页信息流、关注页推荐 |
| 心智状态 | 已被种草，正在比价决策                   | 闲逛状态，等待内容破防  |
| 核心特征 | 主动寻找                          | 被动触达，冲动决策    |
| 真相   | **聚光的流量不是"推"出来的，是用户自己"找"过来的** | 规模种草         |
|      |                               |              |
|      |                               |              |
|      |                               |              |

### 出价方式

| 方式          | 特点                                  | 适用                    |
| ----------- | ----------------------------------- | --------------------- |
| oCPC（推荐）    | 转化成本可控，±20% 波动范围。**成本超 20% 平台赔付差价** | 有明确转化目标、预算适中、追求稳定 ROI |
| Nobid（新手友好） | 只设预算不设出价，系统智能托管，预算内最大化转化数           | 预算明确、缺少成本概念           |

### 平台特性与限制

- ⚠️ **聚光不是纯竞价问题**——笔记内容价值、社区语境、搜索意图会直接影响分发
- 低质广告即使出价高也会被降权
- 原生品牌笔记 eCPM 权重更高
- 平台重视社区氛围保护
- **信息流与搜索需分别起量**，不能混在一起看
- KOS（企业号+员工号矩阵）：多账号消息聚合管理，客资来源清晰归类

## 8.5 快手（磁力引擎）

- **产品**：磁力引擎（投放平台）、磁力金牛（电商）、快分销
- ⚠️ **磁力流量对社区表达和素材标签敏感**，生硬搬运其他平台素材容易匹配错误人群
- **素材方向**：强人设口播、真实场景、直播切片、"老铁"信任表达
- **排查入口**：磁力引擎投放诊断与转化追踪
- **转化链路**：表单、私信、加粉、店铺、直播间

## 8.6 百度营销

- **产品**：百度推广、基木鱼（落地页）、观星盘（数据）、爱番番（CRM）
- **核心特性**：搜索 + 信息流双场景，意图更明确
- ⚠️ **关键词与搜索词不是一回事**——只看关键词汇总会隐藏低意图流量，必须看搜索词报告
- **搜索广告 vs 信息流的核心差异**：搜索广告调整后**立即生效**，没有"频繁调价重置学习期"的问题；信息流则必须给算法时间和数据
- 需按意图和匹配方式拆分单元
