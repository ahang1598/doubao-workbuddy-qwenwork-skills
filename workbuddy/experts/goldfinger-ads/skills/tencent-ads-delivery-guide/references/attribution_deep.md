# 腾讯广告转化归因（深入版）

> 来源：腾讯营销知识库（官方口径），整理日期：2026-08-20  
> 定位：转化归因完整细节手册。快速上手见《腾讯广告转化归因（基础版）》。



---

## 一、概念与两类上报体系

**转化归因**：在特定时间周期内，把用户的一条转化行为（购买、下载、安装、留资等）归属到一条具体广告上的过程。归因数据用于衡量转化量/成本，也是模型优化依据。

**两类上报体系**：

| 类型       | 说明                          | 举例                       |
| -------- | --------------------------- | ------------------------ |
| **自建上报** | 自己通过 SDK/API/JS 回传数据，需配转化规则 | Web 落地页、自有 App           |
| **平台上报** | 用平台官方链路自动回传，无需配规则           | 微信原生推广页、官方落地页、枫页、有赞、微信小店 |

**配置入口**：投放管理平台 →【资产】→【数据营销】→【转化归因】（部分界面为【工具箱】-【转化归因】）。数据接入底座是 **DataNexus（DN）**。

---

## 二、归因方式与归因窗口

| 归因方式     | 归因逻辑                       | 适用场景                                   |
| -------- | -------------------------- | -------------------------------------- |
| 点击归因（默认） | 关联**最后一次点击**               | 大多数场景                                  |
| 曝光归因     | 优先关联周期内点击，关联不到时回溯曝光时间窗内的曝光 | 增加转化量、摊薄成本、加速冷启动；**非标准选项，需联系行业运营内部申请** |

**归因窗口期**：具体天数官方公开资料未明确记载，与 DN 中数据源的归因设置有关，不同转化类型可能不同——登录 DN 查看对应数据源的归因配置确认。

---

## 三、自建上报方式与接入步骤

### 3.1 JS 归因（Web 落地页）

- **密钥获取**：转化归因 → 新建 JS 网页转化 → 填写表单时输入**有效的 Web 落地页链接** → 点右侧【获取密钥】，密钥自动复制到剪贴板
- **关键规则**：
  - **一个网页只能使用一个密钥**，必须嵌入 JS 才能正常上报
  - 只有创建和被授权该密钥的账户能看到全量数据
  - 后续可在「网页转化 - 详情 - 配置信息」中再次查看密钥

### 3.2 SDK 接入（App / 小游戏）

- **文档**：[APP 转化数据 SDK 接入文档](https://developers.e.qq.com/docs/guide/conversion/new_version/APP_sdk)
- **核心流程**：先在 DN 建 SDK 数据源 → 获取"数据源 ID + secret_key" → 初始化 SDK 接入开发
- **注意**：SDK 只需接入一次，同款 App 所有账户通用；安卓 SDK 自动使用 SDK 上报做归因，iOS 数据通过 API 上报即可

### 3.3 API 自归因（新版）

- **新版最大特点**：**无需反复授权拿 token**，开发者服务做好后优化师自己就能完成配置、联调，流程从 7 步缩短到 3 步，数据"不强依赖数据源 token"
- **接入流程**：投放平台 → 资产 → 数据营销 → 转化归因 → 新建转化 → 选"API（自归因上报）"→ 选转化类型（网页/小程序/App/小游戏等）→ 填转化信息 → 联调
- **各对象文档**：
  - [Web 转化 API 自归因](https://developers.e.qq.com/docs/guide/conversion/new_version/Web_api)
  - [APP 转化 API 自归因](https://developers.e.qq.com/docs/guide/conversion/new_version/APP_api)
  - [小游戏 API 自归因](https://developers.e.qq.com/docs/guide/conversion/new_version/Mini_Game_api)
- 旧版与新版只需选一种接入，新版更简单（旧版需开发者+优化师反复配合授权）

## 四、DataNexus（DN）数据源配置

- **入口**：DataNexus 数据源接入页（<https://datanexus.qq.com/web/datasource）→【新建数据源】>
- **流程**：弹框选数据源类型（Web / Android / iOS / 微信等）→ 输入名称等信息 → 确定（例：微信小游戏选"微信"类型 → 输 AppID + 名称）
- **关键配置**：
  - 创建后到**资产分发**（<https://datanexus.qq.com/web/asset/distribute）开启「\*\*转化归因\*\*」和「\*\*一方数据合作\*\*」开关，否则投放端选不到该数据源>
  - 查看密钥：数据源列表右侧【操作】→【查看密钥】，获取"数据源 ID + secret_key"
- ⚠️ **数据源创建后不支持删除**；监测链接组创建后也不支持删除

---

## 五、转化归因配置流程（5 步）

1. **选择新建方式**：首次数据接入（推荐）/ 已有数据源上报
2. **填写基本信息**：转化名称、转化类型（网页/应用/小程序/公众号/企业微信）、落地页链接或 APPID、优化目标、深度优化目标（选填）、营销链路（需权限）
3. **配置归因方式**（默认点击归因）与监测链接（选填）
4. **通过联调**：生成联调预览广告（有效时间 **1 小时**）→ 触发目标行为并上报 → 平台确认无误 → 完成激活转化
5. **激活并使用**：新建广告时选择该转化

## 六、第三方监测链接与宏参数

**作用**：自归因场景——你拿到点击/曝光明细（含 click_id、设备 id、IP 等），内部做数据匹配，再把匹配成功的转化回传给 AMS。

- **配置入口**：DataNexus → 数据监测 → 营销效果监测（<https://datanexus.qq.com/web/monitor/conversion），由开发提供监测链接地址（含各触点类型和宏字段）>
- **技术文档**：[点击监测](https://datanexus.qq.com/doc/develop/guider/interface/conversion/ad_track_click) ｜ [曝光监测](https://datanexus.qq.com/doc/develop/guider/interface/conversion/ad_track_impress)
- **绑定营销的两种方式**：
  1. 新建营销时，在「营销设置」模块直接选对应监测链接组
  2. 转化归因中新建转化规则时选监测链接组，营销再选该转化规则
- ⚠️ **两个坑**：
  - 监测链接组的"营销载体类型"要与实际投放一致（投 Android 应用就得选 Android 应用），否则选不到
  - **监测链接组和转化规则互斥**——选了转化规则就不能再选监测链接组
- **click_id 传递**：非微信流量为 URL 参数 `qz_gdt`，微信流量为参数 `gdt_vid`

### 6.1 宏参数列表（有据可依的部分）

| 类别   | 宏参数                                  | 含义                                     |
| ---- | ------------------------------------ | -------------------------------------- |
| 广告层级 | `__ACCOUNT_ID__`（按账户聚合）              | 广告账户 ID                                |
| 广告层级 | `__ADGROUP_ID__`（按广告聚合）              | 广告（订单）ID，互选订单对应 aid                    |
| 广告层级 | `__AD_ID__`                          | 广告 ID                                  |
| 广告层级 | `__CAMPAIGN_ID__`                    | 推广计划 ID                                |
| 广告层级 | `__DYNAMIC_CREATIVE_ID__`            | 动态创意 ID（取不到值时可改 `__DYNAMIC_CREATIVE_`） |
| 点击标识 | `__QZ_GDT__`                         | 非微信流量 click_id                         |
| 点击标识 | `__GDT_VID__`                        | 微信流量 click_id                          |
| 点击标识 | `__CLICK_ID__`                       | 通用 click_id 宏                          |
| 点击标识 | `__CLICK_TIME__`                     | 点击时间                                   |
| 回调   | `__CALLBACK__`                       | 转化上报回调地址                               |
| 追踪   | `__TRACE_ID__`                       | 追踪标识                                   |
| 设备   | `__MUID__`                           | 设备标识（MUID）                             |
| 微信   | `__WECHAT_OPEN_ID__`                 | 微信 openid                              |
| 其他   | `__ADVERTISER_ID__` / `__ACT_TIME__` | 广告主 ID / 行为时间                          |

**系统占用参数名**（自定义参数不能占用）：`muid、click_time、click_id、app_type、appid、广告主ID`。

### 6.2 设备号下发规则（重要：哈希形式，非明文）

- 因隐私合规要求，媒体侧实际下发的是**哈希后的设备标识**：`hash_idfa`、`hash_android_id`、`hash_oaid`、`caid`，以及微信侧 `wechat_appid + wechat_openid`、`wechat_appid + wechat_unionid`
- 配置要点：**同时配置安卓设备 ID（安卓ID/oaid）和 iOS 设备 ID（caid）的宏字段**，媒体侧根据实际设备类型自动下发
- 归因匹配：Android 系统**优先用 hash_android_id 归因**，失败后回退其他标识
- 明文宏 `__IMEI__`、`__OAID__`、`__IDFA__`、`__ANDROID_ID__` 及 `__IP__`、`__UA__`、`__TIME__`、`__TS__` **官方文档无逐字记载**，完整可选字段以下方文档为准

### 6.3 点击监测 vs 曝光监测

- **点击监测**：下发 `click_id`、`impression_id`、设备 id（muid 等）、ip 信息、广告层级 ID、`callback` 等
- **曝光监测**：接收 AMS 发出的曝光信息（用于曝光归因/自归因），**需联系行业运营申请开通**（非标准选项）
- 官方无"点击/曝光各自支持哪些宏"的逐字区分清单；实际下发字段 = 营销版本 × 你在 DN 配置监测链接组时勾选的可选字段的交集

**权威文档**：

- 点击监测字段列表（完整可选字段）：<https://datanexus.qq.com/doc/develop/guider/interface/conversion/ad_track_click#5-字段列表>
- 点击监测使用指南：<https://developers.e.qq.com/docs/guide/conversion/new_version/dianjijiance>
- 曝光监测说明：<https://developers.e.qq.com/docs/guide/conversion/new_version/baoguangjiance>
- 自归因上报流程（含哈希设备标识下发与匹配优先级）：<https://datanexus.qq.com/doc/develop/intro/inner_app_intro/attribution/attribution_common_self>

## 八、归因匹配机制与回传时效

### 8.1 匹配机制

| 机制                     | 说明                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **click_id 精确匹配**（主链路） | click_id 是每次点击的唯一标识，转化回传时作为 trace 必填字段，用于匹配腾讯点击数据与全网转化数据                                                                |
| **设备号哈希模糊匹配**          | 通过监测链接下发哈希设备标识（`hash_idfa`/`hash_android_id`/`hash_oaid`/`caid` 等），客户侧自归因时与转化数据匹配；Android 优先 `hash_android_id`，失败回退其他标识 |

**数据源匹配范围**（搜索营销场景）：

- **全网归因**：所有数据源回传的数据都可能匹配到你的营销
- **精准匹配归因**：只有通过绑定的数据源回传的数据才能匹配

> click_id 精确匹配 vs 设备号模糊匹配的优先级权重，官方知识库无逐字记载，以 DataNexus 自归因技术文档为准。

### 8.2 回传时效要求

- **联调阶段**：点"开始联调"后须在 **1 小时内**触发行为并完成上报
- **延迟上报的影响**：默认「转化回传口径」按**上报时间**统计——10 月 1 日发生的激活 10 月 2 日才上报，会记到 10 月 2 日，隔日成本随之变化
- **治理要求**：所有转化数据须**全量、准确、及时**回传；平台持续监测完整性/准确性/时效性，**少回传可能触发"转化数据回传状态"提醒及处罚**，需联系行业经理申请复检
- 知识库**无"超过 X 小时/天即失效"的明确数值**；归因是否有效取决于 DN 配置的归因窗口（转化须落在点击/曝光归因时间窗内才能被归属）

## 九、深度优化目标（二次转化）

**设置位置**：创建广告 → 「营销内容」→「优化目标」→ 先选浅层优化目标（必填）→ 下方出现「深度优化目标」（选填）。  
**前置条件**：需先在「工具 → 转化归因」完成转化配置并激活，广告端才能选到。

**支持的深度转化行为**（浅层目标基础上"再发生的一层行为"）：

| 浅层目标  | 可选深度目标                      |
| ----- | --------------------------- |
| 下单    | **下单 ROI**、付费、24 小时下单       |
| 表单预约  | 有效综合线索、下单                   |
| 关注    | 关注后发消息                      |
| 注册/激活 | 首日变现 ROI、七日变现 ROI、次日留存、营销变现 |

**两种模式**：

| 模式     | 是否出价    | 说明                              |
| ------ | ------- | ------------------------------- |
| 深度目标优化 | ✅ 需自己出价 | 分"转化行为 / ROI"两方向，填深度出价（如 ROI 值） |
| 深度辅助优化 | ❌ 不需出价  | 系统辅助出价；**白名单控制，非全量可见**          |

- **双目标出价**：浅层 + 深层分别出价，系统按效果智能优化，兼顾成本与量
- **ROI 深度优化实操**：优化目标选"下单" → 深度优化目标选"下单 ROI" → 填期望 ROI。建议：放宽定向给模型探索空间、搭配"一键起量"加速冷启动、下单出价按真实需求提 10%、ROI 值按历史 ROI 和营销周期设定；**ROI 未达标系统按 ROI 赔付**

## 十、归因差异：后台数据与自己统计不一致

**四类常见原因**：

1. **统计口径不同（最常见）**：
   - 营销播放口径：按广告点击/曝光时间统计，转化回溯到当天
   - 转化回传口径：按数据回传平台时间统计（**系统默认**）
   - 激活时间口径：按激活发生时间统计
2. **归因窗口/归因方式差异**：默认点击归因；窗口天数与 DN 配置有关，不同转化类型可能不同
3. **去重规则不同**：投放端命中"重复注册/重复线索"过滤的不进转化量、不计费（线索平台标"电话重复"：clickid 相同 → 过滤；clickid 不同 → 计费）；你的 CRM 可能展示全量线索
4. **数据延迟/回溯**：当天数据不全，建议以 **T+1 稳定数据**为准

**排查步骤**：确认报表口径 → 切"营销播放口径"再比对 → 以 T+1 数据核对 → 仍不符则检查上报质量（打点遗漏、归因窗口合理性、过滤逻辑、回传量与实际转化量是否匹配，要求全量准确回传）。

## 十一、微信小店 / 视频号小店归因

- **自动归因，无需手动接入**：属"平台上报"，微信原生落地页/小店自动将转化数据上报至腾讯营销，无需自建转化规则、无需 JS/SDK/API
- **推广路径**：先开通微信小店（原视频号小店）→ 通过「小店广告」推广到视频号
- 天猫等外部店铺商品需**先上架到微信小店**再推广，不能直接以天猫店铺投视频号
- **深度优化**：需要"下单 + 下单 ROI 深度优化/深辅"的微信小店商品，需通过【商品消费白名单提报】申请，提报后广告端才可选到

## 十二、常见问题排查表

| 问题                    | 排查方向                                                               |
| --------------------- | ------------------------------------------------------------------ |
| 联调上报数据一直为 0           | ①与开发确认 action_type 是否成功上报；②确认上报的 clickid/用户 ID 对应的是点击联调预览广告的用户     |
| 无法选择已有的监测链接组          | ①DN 中"营销载体类型"与投放实际不符（投 Android 应用，DN 也要选 Android 应用）；②监测链接组与转化规则互斥 |
| 新建转化二次校验失败            | 微信公众号 APPID 配置错误或未对上报账户授权                                          |
| 点【开始联调】报"不支持的营销四元组类型" | 投放账户没有对应营销内容（营销目的/载体）的投放权限，需联系行业运营开通                               |
| 点【开始联调】报"未通过身份验证"     | 账户未完成身份验证，需先完成                                                     |
