# 第九部分　问题诊断手册（18 类问题速查）

> 完整的分平台排查路径（108 条，覆盖巨量引擎/千川/腾讯广告/小红书聚光/磁力引擎/百度营销）见各渠道文件的「问题诊断与排查」章节。此处是**通用排查框架 + 18 类问题索引**。

## 9.1 所有问题的通用排查框架

### 第一步：校准判断基准

任何异常都对比两个基准：

1. **本账户同平台近 7 天中位数**
2. **异常发生前的基线**

⚠️ 不套用跨行业"标准值"。

### 第二步：确认生命周期阶段（决定该不该动手）

| 阶段            | 动作                    |
| ------------- | --------------------- |
| 冷启动期（前 72 小时） | **绝对静止**，20-30% 波动属正常 |
| 成熟稳定期         | 立即干预                  |

### 第三步：判断颗粒度

- 所有计划都出问题 → 外部环境（竞争、大盘、节点、审核政策）
- 单个/头部计划出问题 → 单点原因（素材衰退、承接失效、产品端改动）

### 第四步：漏斗定位断点

按顺序检查，找到**第一个崩掉的环节**：

```
展现量 → 点击率 → 到达率 → 转化率 → 线索质量/ROI
  ↓        ↓        ↓        ↓          ↓
竞争/预算  素材衰退  页面加载  落地页/     素材承诺过度/
/审核     /人群偏   速度      人群质量    人群不对
```

### 第五步：单变量修改 + 定观察窗口

- **一次只改一件事**，否则回落了也不知道是谁的功劳
- 观察周期：**至少 24 小时或一个完整转化窗口**；样本过少时不提前判断
- **回退条件**：若样本充足后核心成本连续恶化，恢复上一版稳定设置，并保留调整记录

## 9.2 18 类高频问题索引

| 序号 | 问题     | 分类    | 首查方向                              |
| -- | ------ | ----- | --------------------------------- |
| 01 | 计划不起量  | 起量与消耗 | 是 eCPM 竞争力不足，还是深度转化样本太少导致 pCVR 偏低 |
| 02 | 消耗不稳定  | 起量与消耗 | 拆分市场波动 / 模型扰动 / 素材衰退 / 频繁修改       |

| 04 | 点击率低   | 素材优化  | 素材开头、标题、人群匹配度                     |
| 05 | 有点击无转化 | 转化优化  | 落地页、承接链路、人群质量                     |
| 06 | 线索质量差  | 线索质量  | 先查话术，再查素材，最后查平台                   |
| 07 | 素材衰退   | 素材优化  | 四模型判断（新鲜感/eCPM 反馈/生命周期/同质化）       |

## 9.3 每条诊断的标准结构

分平台诊断手册里，每个问题都按这个结构组织，可直接照做：

1. **STEP01 平台化排查**——去哪个后台、看哪些层级、确认异常开始时间与最近一次操作
2. **STEP02 解决动作**——保持什么不变、只测哪一个变量
3. **DATA CHECK 数据判断口径**——与自己账户近 7 天中位数和异常前基线对比
4. **建议观察周期**——至少 24 小时或一个完整转化窗口
5. **回退条件**——什么情况下恢复上一版设置
6. **案例记录标准**——记录唯一变量与实际结果，便于复盘复用

# 附录　核心公式与阈值速查

## 公式

| 类别 | 公式                                           |
| -- | -------------------------------------------- |
| 竞价 | eCPM = 出价 × pCTR × pCVR × 1000（+ hiddencost） |
| 成本 | CPM = 消耗 ÷ 展示量 × 1000                        |
| 成本 | CPC = 消耗 ÷ 点击量 = CPM ÷ (CTR × 1000)          |
| 成本 | **CPA = 消耗 ÷ 转化数 = CPC ÷ CVR**               |
| 效率 | CTR = 点击 ÷ 展示 **× 100%**                     |
| 效率 | CVR = 转化 ÷ 点击 **× 100%**                     |
| 效率 | CTCVR = CTR × CVR                            |
| 结果 | ROAS = 广告收入 ÷ 广告消耗 × 100%                    |
| 结果 | ROI = (收入 − 成本) ÷ 成本 × 100%                  |
| 结果 | **盈亏平衡 ROAS = 1 ÷ 利润率**                      |
| 价值 | LTV = ARPU × 用户平均生命周期 = ARPU × (1 ÷ 月流失率)    |
| 价值 | Total LTV = Ad LTV + IAP LTV                 |
| 反推 | 盈亏平衡 CPM = 目标CPA × CTR × CVR × 1000          |

## 阈值

| 项目       | 标准                                          |
| -------- | ------------------------------------------- |
| 日预算下限    | ≥ 目标 CPA × 20（统一；巨量 UBMax 等自动化产品 × 50）      |
| 冷启动出价    | 目标成本 × 1.2 ~ 1.5                            |
| 学习期门槛    | 巨量 20 个转化，腾讯 30 个，百度 30 个，Meta 50 个（深度转化放宽） |
| 超成本定义    | 计费比 > 1.2（超目标 20%）                          |
| 超成本容忍    | 20-50% 观察 / 50-100% 警惕 / >100% 危险           |
| 关停绝对红线   | 老计划成本 > 出价 × 2                              |
| 前 5 转化判断 | ≤2× 继续 / 2-3× 拉长观察 / >3× 止损                 |
| 单次降价     | 5-10%，一天不超 2 次                              |
| 单次调价上限   | 15%                                         |
| 素材:创意    | 1 : 2~4（单素材配 2-3 个创意最优）                     |
| 单素材测试预算  | 常规渠道 × 15；千川 × 50                           |
| 新素材消耗占比  | 20-30%，不超过 40%                              |
| 素材差异度    | 新素材与核心素材 ≥ 30%；微调需画面差异 60%+                 |
| 首发标识     | 相似分镜占比 < 10%                                |
| 衰退分级     | 预警 CTR −10~15% / 处理 −20% / 淘汰 −30%          |
| 素材迭代响应   | 预警到新素材上线 ≤ 24 小时                            |
| 放量节奏     | +20% → +30% → +50%，每步观察 3 天                 |
| 落地页加载    | < 2 秒                                       |
| 定向覆盖     | ≥ 3000 万（最好 5000 万），预估日曝光 > 5000            |
| LTV 安全线  | LTV > CAC；LTV / CAC > 3                     |

## 十条核心结论

1. **eCPM 是唯一货币**——能否拿量看 eCPM，不看出价高低。把素材做好等于变相加价。
2. **出价是资格证，实付看第二名**（GSP）——这是你敢提价的底气，但竞争激烈时实付会被顶高。
3. **冷启动的门槛是转化数，不是天数**——喂不满就别开投。
4. **学习期任何修改都是推倒重学**，调三次就是三次重置。
5. **超成本先诊断再动手**——时间轴 → 颗粒度 → 漏斗，单变量修改。
6. **素材衰退是系统性现象**（用户疲劳 + eCPM 负反馈 + 生命周期 + 同质化），靠持续上新而非修补老素材。
7. **智能出价是放大器不是制造机**——回传不准、素材不行，模型救不了。
8. **放量不是加预算，是复制成功单元**；放量失败 80% 是承接端没跟上。
9. **算法学的是你教的东西，不是你想要的东西**——回传口径必须只对准唯一核心目标。
10. **所有异常都跟自己账户近 7 天中位数和异常前基线比**，不套用跨行业标准值。
