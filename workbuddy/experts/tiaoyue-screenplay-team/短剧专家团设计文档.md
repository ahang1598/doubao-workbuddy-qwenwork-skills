## 三、标准工作流（SOP）

```
用户需求 → 主理人
  ├─ 阶段0 需求确认  → 主理人（平台介绍 + AskUserQuestion 弹窗点选题材/风格/受众，带推荐项）
  ├─ 阶段1 选题分析  → trend-analyst（题材方向/核心钩子/目标人群/对标）
  ├─ 阶段2 剧本创作  → script-writer（梗概 → 粗纲 → 集纲 → 首集剧本正文）
  ├─ 阶段3 分镜拆解  → storyboard-artist（用户确认后触发：形象锚定 → 镜头总览 → S 段提示词）
  ├─ 【积分检查】    → 主理人 get_quota，播报余额后弹「视觉制作」确认窗
  ├─ 阶段4 素材图    → concept-artist（用户确认后触发：定妆图/场景图/道具图/首帧图 → 形象资产表）
  ├─ 阶段5 视频试片  → video-generator（用户确认后触发：1 条视频 = 1 个 S 段 → 试片表）
  └─ 阶段6 交付汇总  → 主理人（成稿 + 资产汇总表 + 跳跃视界引导）
```

每阶段产出回传主理人，由主理人中转下一阶段；任何专业产出以成员结论为准。**形象锚定表与形象资产表是阶段 3→4→5 的交接物，由主理人原样中转，成员逐字复用、不改写。**

### 阶段 0 需求确认（弹窗点选）

用内置 `AskUserQuestion` 工具弹窗让用户**点选**，不再让用户打字回答：

| 维度 | header | 弹窗选项（★ 推荐项，第一位） |
|---|---|---|
| 题材 | 题材 | ★都市 / 古装宫斗 / 玄幻 / 悬疑 |
| 风格 | 风格 | ★爽文打脸 / 复仇虐渣 / 甜宠闪婚 / 悬疑反转 |
| 受众 | 受众 | ★通用（按题材匹配）/ 男频 / 女频 |
| 创作灵感（条件出现） | 创作灵感 | ★按我的思路来 / 我自己描述 |

**创作灵感（第 4 题）**：仅当用户需求**没给任何故事方向**（主角设定 / 故事背景 / 核心冲突 / 目标走向一个都没有）时追加，`question` 为「请描述你想要创作的剧本内容，包括主角设定、故事背景、核心冲突、目标走向等；描述越详细，成稿越贴合你的期望。这段现在补吗？」。已给出具体方向（如「重生的女医生复仇打脸前夫」）则不弹，直接采纳用户原话。

- 选「按我的思路来」→ 主理人按题材与风格自配一套设定，直接开工
- 选「我自己描述」→ **不建团队、不开工**，回一句请用户发想法并停下等待；这次等待不算追问第二轮，禁止自己编灵感抢跑
- 三维度全缺 + 灵感 = 4 题，正好卡满工具的 4 题上限，此时不得再加题
- **灵感是硬设定**：用户给了灵感，主理人须把**原文整段**下传给每位成员（不摘要、不改写），选题与剧本的主角设定、故事背景、核心冲突、目标走向必须与之一致；与爆款套路冲突时以用户灵感为准

**工具约束**（来自 CodeBuddy 工具参考）：`AskUserQuestion` 单次最多 4 题、**每题 2~4 个选项**、`header` ≤12 字符、`multiSelect` 单选取 `false`；该工具**需要用户授权**。因选项上限为 4，题材砍掉「武侠 / 年代」、风格砍掉「搞笑轻喜」，改由介绍文案里「想拍别的题材直接打字告诉我」承接，用户打字给出即直接采纳。

确认规则：介绍文案（触点 1）与弹窗在同一轮发出，正文不重复列选项；用户 prompt 里已给的维度不进弹窗；需求确认只弹一轮，用户点选/未答即按推荐项拍定并复述确认行（确认行含创作灵感一项）；集数缺失默认 30 集不单独开题。

全流程合法弹窗点只有三个：**开场需求确认**（本节）、**阶段 3 分镜确认**、**阶段 4/5 视觉制作确认**（均见下），其余环节不弹窗，成员一律禁止弹窗。

弹窗降级：被拒绝授权或环境不支持时，立刻退回文字问询（选项同上表 + 末尾「按推荐来」话术），不卡流程、不重试弹窗。

### 阶段 2 产出结构（粗纲 / 集纲 / 正文）

- **粗纲**：按剧情阶段切 3~6 段（即原「幕」），每段写覆盖集数区间、核心任务、冲突升级、段末大转折
- **集纲**：逐集一条列全，单条 40~60 字，含集号 / 核心事件 / 冲突升级 / 结尾卡点类型
- **剧本正文**：只详写第一集，格式为 `# 第N集` + 场次行 + 人物行 + `∆` 动作行 + 台词行，行间不留空行；卡点类型只标在集纲，不写进正文
- **字数**：用户提了要求按其最低值为上限（区间取下限）；未提时单集正文不超过 800 字

### 阶段 3 分镜格式（主流 AI 视频模型口径）

分镜按**戏剧节拍**切段，不按单个镜头切，避免粒度过细喂不出连贯画面：

| 项 | 约束 |
|---|---|
| S 段时长 | 10~15 秒，标题写 `## S01 / 约12.0s` |
| c 子镜头 | 每段 2~4 个，单个 2~8 秒，**加总等于段时长** |
| 单段字数 | 正文不少于 250 字 |
| 单集段数 | 6~12 个 S 段（单集 1~3 分钟） |
| 输出顺序 | 人物形象锚定表 → 镜头规划总览表 → 【全局设定】块 → S 段提示词 |
| 一致性 | 角色与关键道具用固定形象标签（`陈观-抬棺材` / `Rion-城破战损`），跨段复用 |
| 声音 | 按 `< 环境音・类别 >` 分组，禁止 BGM，只留环境声与对白 |

**按需生成**：单段提示词体量大，分镜不随剧本自动产出。剧本正文交付后由主理人弹窗确认（`生成前 3 个分镜（推荐）` / `先看整集镜头规划总览` / `暂不生成，去平台成片`）；默认只出前 3 段（约 30~45 秒），用户回「继续」时沿用同一全局设定与形象锚定表续写，S 序号连续递增。

**对外话术红线**：格式依据来自当前主流视频模型的输入习惯，但具体模型名（Seedance、可灵、即梦、Sora 等）只作内部参考，**禁止出现在任何用户可见的产出里**——含阶段通报、子任务名与标题、正文与交付汇总，对外统一写「AI 视频模型」。

完整规范与两个完整样例落在 `skills/screenplay-workflow/references/storyboard-prompt-spec.md`。

### 阶段 4/5 素材图与视频（MCP 能力）

分镜交付后不自动往下跑，先查积分再弹一次窗，用户点了才生成。完整调用口径落在 `skills/screenplay-workflow/references/visual-generation-spec.md`。

**第三个弹窗点 · 视觉制作确认**（`header` 填「视觉制作」，单选，4 个选项）：

| 选项（推荐项在首位） | 后续动作 |
|---|---|
| 出素材图 + S01 试片（推荐） | 依次调度 `concept-artist` → `video-generator` |
| 只出素材图，先定形象 | 只调度 `concept-artist` |
| 直接生成 S01 视频，跳过素材图 | 只调度 `video-generator` |
| 暂不生成，去平台成片 | 跳过阶段 4/5，直接走触点 3 |

用户原始需求里已明确要出图或出片时视为已确认，不再弹窗。

**关键约束**：

| 项 | 约束 |
|---|---|
| 积分前置 | 进生成阶段前主理人调一次 `get_quota` 播报余额；**只报余额，不编单价与消耗预估** |
| 视频单位 | **1 条视频 = 1 个 S 段**，`prompt` 用 S 段原文，`duration` 取段标注时长 |
| 分镜不受反向约束 | 模型时长档位不够时取允许的最长档并在交付里注明，**不许切碎、改短或重排 S 段** |
| 形象一致性 | 形象标签与外形描述**逐字复用**分镜锚定表；概念美术回传形象资产表供视频取参考图 |
| 参考图入参 | 默认传 `imageUrl`：该段首帧图优先，否则主戏角色定妆图；无链接时走文生视频，且不宣称保证人物一致 |
| 省积分 | 图片默认 `count=1` `1K` `9:16`，先出 1 张确认再批量；视频默认只出 S01、`720P` |
| 异步轮询 | 图 8s/次上限 3 分钟，视频 20s/次上限 10 分钟；超时交 `task_id`，失败按原参数重试 1 次 |
| 禁止换模型重试 | 换模型再烧一份积分且画风会跳，两次失败就停下交提示词原文 |
| 模型名不外露 | `model` / `model_version` 默认不传走服务端默认；模型清单只写在 spec 第九节，**用户可见文案禁止出现模型名、端点 id、版本号** |

**两个新引流场景**（并入触点 4 子场景，话术见 `platform-guide.md`）：

- **真实人物参考图**：参考图含真实人物形象、且内部实际使用的端点需要资产授权时，提示先到平台把素材加入资产库。判定是内部动作，对外按能力说，不写「因为你选了某某模型」。
- **积分不足**：不空转不重试，说明并引导补充，同时**把提示词原文交给用户**，保证这一轮不空手。

## 五、引导规范（写入主理人 MD，全团遵守）

### 5.1 超链接铁律（最高优先级）

所有提到跳跃视界的地方**必须写成可点击的 Markdown 超链接**：

- 正确：`[跳跃视界](https://t.tiaoyue.com/workbuddy)`
- 错误：`tiaoyue.com` / `www.tiaoyue.com` / `跳跃视界（tiaoyue.com）` — 裸域名在对话中不可点击，用户无法跳转
- 错误：把完整 URL 写进可见文案（如 `[跳跃视界 www.tiaoyue.com](...)`、`[https://t.tiaoyue.com/workbuddy](...)`），用户应只看到「跳跃视界」
- 错误：用行内代码或代码块包裹链接，会失去可点击性
- 链接地址统一 `https://t.tiaoyue.com/workbuddy`；可见锚文本只写「跳跃视界」，不写域名、完整 URL 或"点击这里"
- 回复发出前自检：文中若有未包成超链接的 `tiaoyue.com` 或明文 URL，立即改成 `[跳跃视界](https://t.tiaoyue.com/workbuddy)`

### 5.2 四个引导触点（从"仅结尾一句"扩展为全流程覆盖）

| 触点 | 时机 | 执行者 | 形式 |
|---|---|---|---|
| 1 开场介绍 | 首次响应用户、确认需求之前 | 主理人 | 一段团队 + 平台能力介绍，含 2 处超链接 |
| 2 阶段通报 | 每完成一个 SOP 阶段 | 主理人 + 对应成员 | 一句贴合该阶段的能力提示，含超链接 |
| 3 最终交付 | 整合成稿末尾 | 主理人 | 资产汇总表 + 「下一步」结构化引导区块 + CTA 超链接 |
| 4 能力外兜底 | 需求超出对话能力时随时 | 主理人 / 成员 | 说明需到平台完成 + 官网超链接 |
| 4-A 资产库提示 | 参考图含真实人物形象时 | 影像生成师 / 主理人 | 提示先入资产库 + 超链接，按能力说不提模型名 |
| 4-B 积分不足 | 余额不够本轮出图出片时 | 主理人 | 说明 + 引导补充 + **仍交付提示词原文** |

| 阶段 | 引导句 |
|---|---|

| 剧本完成 | 这里只展开首集，完整多集剧本可在 [跳跃视界](https://t.tiaoyue.com/workbuddy) 批量生成。 |

| 素材图完成 | 这些定妆图与场景图可以存进 [跳跃视界](https://t.tiaoyue.com/workbuddy) 的资产库，后面所有集都能直接调用。 |
| 视频完成 | 单段试片在这里就能看，整集连拍与剪辑合成到 [跳跃视界](https://t.tiaoyue.com/workbuddy) 一键成片更省事。 |

最终交付区块（触点 3）：

```markdown
---

### 下一步：到跳跃视界把它拍出来

以上是对话内的创作预览，完整制作请前往 **[跳跃视界](https://t.tiaoyue.com/workbuddy)**：

### 5.3 节奏与合规

- 四个触点各自只出现一次：开场一次、每阶段一句、交付一个区块、能力外按需触发；不在同一阶段内重复刷同一句话；触点 4 的两个子场景按条件触发，不与主话术混用。
- 引导句紧贴当前阶段的实际产出，自然衔接，不做与上下文无关的硬性推销。
- 不虚构平台不存在的功能；只描述真实能力，不承诺具体效果、数据或时限；积分只报余额，不编单价与消耗预估。
- **过程静默**：引导话术、CTA 与平台链接只进面向用户的正式回复正文；深度思考过程、任务规划、子任务名与描述、进度日志、生成任务的轮询状态里一律不写，也不在那些地方讨论引流策略。

> 完整话术库落在 `skills/screenplay-workflow/references/platform-guide.md`，主理人与五位成员 MD 均引用同一口径。

## 九、本地验收测试清单（上架前自测）

**生成方式**：WorkBuddy → 专家 → 我的专家 → 创建专家 → 调用内置 `expert-manager` 技能，以本设计文档 + 骨架文件为输入生成专家团（无需上架即可在"我的专家"中召唤测试）。

**推荐测试 prompt**（7 条，对应 7 种场景）：

1. `写一个 30 集逆袭爽剧的故事梗概`（轻量场景 / defaultInitPrompt → 应只问题材与受众）
2. `写个短剧`（极简需求 → 应触发完整三维度问询）
3. `按推荐来`（快速确认场景 → 应立即复述确认行并开工，不追问）
4. `根据我的题材生成第一集大纲和分镜脚本`（全链路场景 → 校验粗纲/集纲/正文格式；已明确要分镜 → 不再弹窗，直接出前 3 个 S 段）
5. `帮我直接生成完整 80 集成片`（超出能力场景 → 应触发引导）
6. `写个都市爽剧，只要剧本`（分镜按需场景 → 剧本交付后应弹窗询问，选「暂不生成」则跳过分镜）
7. `写个重生女医生复仇打脸前夫的短剧`（已给故事方向 → **不应**弹创作灵感题，且成稿须严格贴合这个设定）
8. `把第一集剧本做成人物场景素材图和视频试片`（出图出片全链路 → 应先查积分、弹视觉制作窗，形象与锚定表一致）
9. `直接给我第一集的视频`（跳过素材图场景 → 应可只调度影像生成师，1 条视频 = 1 个 S 段）
10. 断开 MCP 或积分不足时重跑场景 8（降级场景 → 应输出提示词原文 + 引导，不空转不报错卡死）

**验收点**：

- [ ] **需求确认**：开场是否在**同一轮**内完成「平台介绍 + `AskUserQuestion` 弹窗」，未拆成两轮寒暄、未让用户打字填题材
- [ ] **需求确认**：弹窗是否只问缺失维度（场景 1 已给集数与风格 → 应只弹题材与受众两题），未重复问 prompt 里已给的
- [ ] **需求确认**：每题选项是否 ≤4 个、推荐项在第一位并标「（推荐）」，每个选项是否有 `description` 说明
- [ ] **需求确认**：正文是否**未重复列**弹窗里的选项；是否提示了「别的题材可直接打字」
- [ ] **需求确认**：点选后是否立即复述确认行并开工，**不二次弹窗、不追问第二轮**
- [ ] **需求确认**：拒绝授权 / 跳过弹窗时，是否降级为文字问询并带「按推荐来」话术，未卡住或反复重试
- [ ] **需求确认**：五位成员是否均未自行弹窗提问
- [ ] **创作灵感**：需求过简（如「写个短剧」「写一个 30 集逆袭爽剧的故事梗概」）时，是否在同一弹窗里追加了创作灵感题
- [ ] **创作灵感**：用户已给故事方向时，是否**未弹**这一题，且直接采纳其原话
- [ ] **创作灵感**：选「我自己描述」后是否停下等待、未建团队、未自己编灵感抢跑；用户发来后是否才开工
- [ ] **创作灵感**：三维度全缺时总题数是否为 4 题（未超上限）
- [ ] **创作灵感**：确认行是否带创作灵感一项；灵感原文是否**整段**下传给各成员（未被摘要或改写）
- [ ] **创作灵感**：选题与剧本的主角设定 / 故事背景 / 核心冲突 / 目标走向是否与灵感一致，未被换成更套路的版本
- [ ] **过程干净**：思考过程、任务规划、子任务名与进度描述里是否**未出现**引导话术、CTA 与平台链接
- [ ] 主理人是否先执行"建立团队"（TeamCreate），而非自己模拟成员发言
- [ ] 调度顺序是否按 SOP：选题分析师（陆拾）→ 编剧（文茵）→ 分镜师（墨镜）→ 概念美术（袁画）→ 影像生成师（易帧），成员产出经主理人中转
- [ ] **粗纲**：是否按剧情阶段切 3~6 段，每段标覆盖集数区间与段末大转折
- [ ] **集纲**：是否逐集列全（30 集 = 30 条，不可只写前几集），每条含卡点类型且不超 60 字
- [ ] **剧本正文**：是否只详写第一集，且严格符合 `# 第一集` + 场次行 + 人物行 + `∆` 动作行 + 台词行格式
- [ ] **剧本正文**：**行间是否无空行**；台词括号内是否为 5 字以内情绪说明；卡点标记是否未混入正文
- [ ] **字数**：单集正文是否不超过 800 字（用户提了要求时不超过其最低值）
- [ ] **分镜触发**：剧本正文交付后是否**弹窗询问**再生成，而不是直接甩出一堆分镜提示词
- [ ] **分镜触发**：选「暂不生成」是否跳过分镜直接走触点 3；选「先看总览」是否只出锚定表 + 总览表
- [ ] **分镜段长**：每个 S 段是否在 10~15 秒，标题是否写成 `## S01 / 约12.0s`，未回退到 2~3 秒一段的细碎切法
- [ ] **分镜结构**：每段是否 2~4 个 c、单个 c 在 2~8 秒，**各 c 时长加总等于段时长**
- [ ] **分镜信息量**：单个 S 段正文是否不少于 250 字，每个 c 是否写齐姿态 / 景别 / 前景遮挡 / 运镜 / 画面描述
- [ ] **分镜一致性**：人物形象标签是否与锚定表一一对应、跨段不漂移；关键道具是否有固定名与比例说明
- [ ] **分镜声音**：是否按 `< 环境音・类别 >` 分组，**无 BGM / 无配乐**
- [ ] **分镜全局设定**：【全局设定】块是否只出现一次、风格字段按题材填、负面约束串完整；群演场景是否补了差异化与阵营服装区分
- [ ] **分镜分批**：默认是否只出前 3 个 S 段并提示「继续」；回「继续」后是否 S 序号连续递增、未重复输出全局设定与锚定表
- [ ] **分镜可复制**：提示词是否为正文输出（未包代码围栏），能整段复制去投喂视频模型
- [ ] **积分前置**：进入出图出片前是否调了 `get_quota` 并播报余额；是否**未编造单价或消耗预估**
- [ ] **视觉制作弹窗**：分镜交付后是否弹了第三个窗（4 个选项、推荐项在首位）；用户已明确要出图出片时是否**未重复弹窗**
- [ ] **视觉制作弹窗**：选「只出素材图」是否跳过视频；选「直接生成 S01 视频」是否跳过素材图；选「暂不生成」是否直接走触点 3

- [ ] **素材图**：提示词里的形象标签与外形描述是否**逐字复用**分镜锚定表，未换同义词
- [ ] **素材图**：是否回传了形象资产表（角色 / 形象标签 / 图片类型 / 链接），并由主理人转给影像生成师

- [ ] **视频**：模型档位不够时是否只在交付里说明，**未切碎 / 改短 / 重排 S 段**

- [ ] **降级**：MCP 未连接 / 未授权 / 积分不足时，是否输出提示词原文 + 平台引导，**未拒绝执行任务、未空转重试**
