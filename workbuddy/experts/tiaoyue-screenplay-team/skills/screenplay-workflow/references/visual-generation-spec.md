# 素材图与视频生成规范（MCP 调用口径）

概念美术袁画与 AI 影像生成师易帧的唯一执行标准。目标是让分镜的形象锚定一路贯到成片：**同一套形象标签 → 定妆图 → 参考图 → 视频**，中途不漂移。

> **对外话术红线**：本文件里出现的模型名、端点 id、版本号**只作内部参数依据，禁止出现在任何用户可见的产出里**——含阶段通报、子任务名与标题、进度描述、正文与交付汇总。对外统一写「AI 绘图模型」「AI 视频模型」，或直接按能力说（标准画质 / 高画质 / 竖屏）。模型清单会随平台调整，只改本文件第九节，Agent MD 不动。

## 一、在流程里的位置

```
墨镜（分镜）→ 人物形象锚定表 + 【全局设定】+ S 段提示词
      ↓
袁画（素材图）→ 复用形象标签出定妆图 / 场景图 / 道具图 / S 段首帧图 → 形象资产表
      ↓
易帧（视频）→ 1 条视频 = 1 个 S 段，提示词用 S 段原文，参考图取形象资产表
```

**形象资产表**是两位成员之间唯一的交接物，由袁画产出、主理人中转、易帧消费：

| 角色 / 对象 | 形象标签 | 图片类型 | 链接 |
|---|---|---|---|
| 陈观 | `陈观-抬棺材` | 人物定妆图 | https://... |
| 破庙门口 | `破庙门口-夜雨` | 场景概念图 | https://... |
| 朱红木棺 | `朱红木棺` | 关键道具图 | https://... |

## 二、素材图规范（`generate_image`）

### 2.1 四类图与出图顺序

| 类型 | 用途 | 默认数量 |
|---|---|---|
| 人物定妆图 | 锁定主角形象，供用户确认 + 作视频参考图 | 主要角色 2~3 位，每人 1 张 |
| 场景概念图 | 锁定主场景的空间、光线、天气 | 2~3 张 |
| 关键道具图 | 锁定有戏份的道具及其与人物的比例 | 按锚定表里出现的道具，0~2 张 |
| S 段首帧图 | 给某个 S 段出开画参考，直接喂给视频 | 按需，默认只出要拍的那一段 |

顺序固定：**人物 → 场景 → 道具 → 首帧**。人物没定稿不要往下走，形象一改后面全部作废。

### 2.2 提示词骨架

正向提示词由五段拼成，**形象标签与外形描述必须从墨镜的锚定表逐字复制**，不许自己改写用词：

```
<画面风格：与【全局设定】的风格字段保持一致>，<构图：全身定妆 / 半身 / 场景全景>，
<形象标签>：<锚定表里的外形与服装原文>，
<环境与光线：地点、天气、光源方向、色调>，
<细节要求：面部清晰、服装材质、道具位置与比例>，
<负面约束串>
```

负面约束串固定（与分镜【全局设定】同源，去掉视频专属项）：

> 画面干净无字幕、无水印、无文字；人物边界独立、无穿插穿透；杜绝肢体畸形、扭曲、多手多指等人体结构错误；不出现现代元素穿帮

**竖屏优先**：短剧是竖屏，人物定妆图与场景图默认按 9:16 出，方便直接作视频首帧。

### 2.3 入参默认值

| 字段 | 默认值 | 说明 |
|---|---|---|
| `prompt` | 按 2.2 骨架拼装 | 上限约 4000 字，够写全 |
| `model` | **不传** | 走服务端默认模型；用户明确要高画质时才按第九节补 |
| `model_version` | **不传** | 仅第九节标注的模型需要，其余留空 |
| `outputConfig.aspectRatio` | `9:16` | 竖屏；用户要横屏才改 `16:9` |
| `outputConfig.resolution` | `1K` | 确认稿够用、省积分；定稿后用户要高清再出 `2K` |
| `outputConfig.count` | `1` | 一次一张；用户要多方案对比才给 `2`，上限 4 |
| `outputConfig.size` | 不传 | 由 `aspectRatio` + `resolution` 决定 |

**省积分铁律**：先出 1 张给用户确认风格，用户点头后才批量出剩下的；不要一上来就 4 张 × 多角色。

## 三、视频规范（`generate_video`）

### 3.1 一条视频 = 一个 S 段（分镜规范不得改动）

- `prompt` **直接用墨镜输出的该 S 段原文**：图中空间 + 人物站位锚定 + 各 c 子镜头 + 声音指令，一字不改；段前拼上【全局设定】块。单段 250~400 字，远在 4000 字上限内。
- `outputConfig.duration` **取标题里的段时长**：`## S01 / 约12.0s` → `duration: 12`。
- **模型档位不够时只做说明，不动分镜**：若当前模型单条时长上限低于段时长，取模型允许的最长档下发，并在交付里注明「本段约 12 秒，测试阶段单条上限约 N 秒，后续接入长时长模型即可整段直出」。**严禁把 S 段切碎成 c 逐条生成、严禁改短或重排分镜的 10~15 秒切法** —— 分镜切分是创作侧的规范，不受模型能力反向约束。

### 3.2 参考图入参（已启用）

`generate_video` 默认走**带参考图生成**：

| 项 | 约定 |
|---|---|
| 字段 | `imageUrl`（string，图片 URL）。若工具 schema 为 `images` / `firstFrame` / `imageUrls` 等，按实际键名传，取值仍是形象资产表链接；数组形态则传 `[url]` |
| 取图 | 该 S 段**首帧图优先**；否则该段主戏角色的**人物定妆图** |
| 无可用链接 | 不传该字段，走文生视频；此时**不得宣称**素材图能保证视频人物一致 |
| 有参考图 | 可以说定妆图 / 首帧图作为参考锚定成片形象；仍不承诺「保证完全一致」（效果受模型影响） |

### 3.3 入参默认值

| 字段 | 默认值 | 说明 |
|---|---|---|
| `prompt` | 【全局设定】+ S 段原文 | 不改写、不压缩 |
| `model` / `model_version` | **不传** | 走服务端默认；用户明确要高画质档才按第九节补 |
| `outputConfig.duration` | S 段标注时长 | 见 3.1 |
| `outputConfig.resolution` | `720P` | 试片够用、省积分；用户要高清再 `1080P` |
| `outputConfig.aspectRatio` | `9:16` | 与素材图保持一致 |
| `outputConfig.hasAudio` | `true` | S 段带对白与环境声指令，需要音轨 |
| `outputConfig.hasReferenceVideo` | `false` | 本流程不做视频参考 |
| `imageUrl` | 按 3.2 取一张 | 有形象资产表链接才传；无则不传 |

**默认只出 S01 一条**，用户回「继续」再出 S02，序号沿用墨镜的编号不重排。

## 四、异步任务轮询规范

两个生成工具都是异步：返回 `taskId` → 用 `get_task_status` 轮询到终态。

| 项 | 图片 | 视频 |
|---|---|---|
| 轮询间隔 | 约 8 秒 | 约 20 秒 |
| 最长等待 | 3 分钟 | 10 分钟 |
| 超时处理 | 把 `task_id` 交给用户，说明任务仍在跑、可稍后凭 id 查询，本轮先交付提示词原文 | 同左 |
| 失败重试 | 最多 1 次，**原参数重试** | 最多 1 次，**原参数重试** |

- **禁止自动换模型重试**：换模型等于再烧一份积分，且画风会跳。失败两次就停下说明原因，交提示词原文。
- **禁止空转刷屏**：轮询期间不要每次都向用户播报一行状态，等到终态或超时再统一回报。
- 轮询过程中的状态描述属于过程信息，**不写引导话术与平台链接**（见第七节）。

## 五、积分规范（`get_quota`）

- **前置检查**：进入素材图 / 视频阶段之前，由主理人调一次 `get_quota`，在正文里播报余额，并说明出图出片会扣减积分、**具体扣减以平台为准**。
- **不虚构数字**：不要编单价、不要估算「大约消耗 X 积分」——工具没返回单价就只报余额。
- **余额不足**：不空转、不重试，直接说明并引导补充；同时**把已写好的图片与视频提示词原文交给用户**，保证这一轮仍有交付物。话术见 `platform-guide.md` 触点 4。

## 六、真实人物素材的合规提示

参考图里包含**真实人物形象**时（真人照片、真人艺人形象），且内部实际走的是需要资产授权的端点时，**先提示再决定是否发起生成**：

> 这张参考图里有真实人物形象，需要先在 [跳跃视界](https://t.tiaoyue.com/workbuddy) 把素材加入资产库，才能用于视频生成。艺人资产与授权流程在平台上一次配好，后面所有集都能直接调用。

- 判定「是否需要资产授权」是**内部动作**（看本次实际使用的端点归属），对外**不写「因为你选了某某模型」**，只按能力说。
- 用户自带真人素材时，一并提示肖像授权风险；已有 IP 改编提示版权确认。

## 七、过程静默（红线）

引导话术、CTA 与平台链接**只允许出现在面向用户的正式回复正文**里。深度思考过程、任务规划、子任务名与任务描述、进度日志、轮询状态播报里**一律不出现引导话术与平台链接**，也不在那些地方讨论引流策略——用户看到过程里的推广痕迹会觉得刻意。

第六节的资产库提示与第五节的积分不足说明属于**正式回复内容**，正常输出。

## 八、降级矩阵（任何一格都不许卡流程）

| 情况 | 处理 |
|---|---|
| MCP 未连接 / 未授权 / 401 | 输出提示词原文 + 平台引导，说明连接后可直接在对话里出图出片 |
| 积分不足 | 见第五节 |
| 任务失败两次 | 说明失败原因（若有），交提示词原文 |
| 轮询超时 | 交 `task_id` + 提示词原文，告知可稍后查询 |
| 无参考图链接 | 不传 `imageUrl`，走文生视频，不宣称图片保证视频一致性 |

统一口径：**不要因为工具不可用而拒绝执行任务**，永远给得出提示词。所有生成结果附两句提醒：

> 效果受模型影响，可按需调整提示词重出；生成链接有时效，请及时下载保存。

## 九、内部参数映射（不对外，模型清单会调整）

> 只在用户明确要求画质 / 风格档位时才按本表补 `model` 与 `model_version`；默认一律不传，走服务端默认。**本节内容禁止出现在任何用户可见的输出里。**

### 9.1 `generate_image`

| 档位（对外说法） | model | model_version |
|---|---|---|
| 默认（不传） | 服务端默认 `doubao-seedream-5-0-260128` | 留空 |
| 高画质 | `ep-…54pkx`（Seedream 5.0 Pro） | 留空 |
| 其他可选 | `gemini-3.1-flash-image`、`gemini-3-pro-image`、`doubao-seedream-4-5 / 4-0 / 5-0`、`"v 7"`、`"niji 7"` | 留空 |
| 腾讯 MPS 系 | `GEM` | `3.1` 或 `3.0` |
| 腾讯 MPS 系 | `OG` | `image2_low / medium / high` |

`model_version` 仅腾讯 MPS 模型（`GEM` / `OG`）必填，其余传空。

### 9.2 `generate_video`

| 档位（对外说法） | model | model_version |
|---|---|---|
| 默认（不传） | 服务端默认 Kling | 默认 `3.0` |
| Kling 系 | `Kling` | `3.0-Omni` / `3.0` / `2.6` / `O1` |
| 火山 Seedance 系 | `ep-*` 端点 id | 省略 |
| 腾讯 MPS 系 | `Hailuo` | `2.3` |
| 腾讯 MPS 系 | `GV` | `3.1` |
| 腾讯 MPS 系 | `Vidu` | `q3-pro` |

火山 Seedance 系端点属于第六节所述「需要资产授权」的范围：参考图含真实人物时触发资产库提示。

## 十、自检清单（输出前逐条过）

- [ ] 形象标签与外形描述是否**逐字复用**墨镜锚定表，未自行改写
- [ ] 素材图是否先出 1 张确认、未一上来批量烧积分
- [ ] 图片与视频的 `aspectRatio` 是否一致（默认都 9:16）
- [ ] 视频是否 **1 条 = 1 个 S 段**，`duration` 取自段标题，未切碎 S 段、未改动分镜切分
- [ ] 视频 `prompt` 是否为 S 段原文 + 【全局设定】，未压缩改写
- [ ] `model` / `model_version` 是否默认未传
- [ ] 用户可见文案里是否**未出现任何模型名、端点 id、版本号**
- [ ] 轮询是否按间隔与上限执行，超时是否交出 `task_id`
- [ ] 失败是否只按原参数重试 1 次，**未自动换模型**
- [ ] 进入生成阶段前是否查过积分；余额不足是否引导并仍交付提示词原文
- [ ] 有形象资产表时是否传入参考图（首帧图优先，否则定妆图）；无链接时是否未宣称保证人物一致
- [ ] 参考图含真实人物时是否给了资产库提示，且未提模型名
- [ ] 引导话术与平台链接是否只在正式回复正文里，未进过程与任务描述
- [ ] 生成结果是否附了「效果受模型影响」与「链接有时效」两句提醒
- [ ] 内容是否健康合规，涉真人 / IP 是否提示授权
