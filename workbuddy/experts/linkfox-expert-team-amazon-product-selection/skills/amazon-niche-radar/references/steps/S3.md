# 步骤 S3：四源并行采集

- **输入**：S1 的 `精准词`、S2 的 `nodeIdPath`、用户输入的 `keyword`（原始入口词）
- **依赖**：S1, S2
- **用途**：为 S4 提供四个数据源的完整原始数据

## 操作

四个数据源互不依赖，同一轮一次性并行发起。

### S3.1 极目细分市场洞察（复用 S2-B 缓存，多 niche）

S2-B 已调用 `linkfox-jiimore-get-niche-info-by-keyword` 并完成与 SIF 标签词的交叉验证。直接复用其返回结果（24h 本地缓存），取**所有已验证 niche** 的完整指标（不只是第一个）。

每个已验证 niche 取字段：
- 市场容量：`searchVolumeWeekly`, `searchVolumeQuarterly`, `searchVolumeGrowthWeekly`, `searchVolumeGrowthQuarterly`, `unitsSoldWeekly`, `unitsSoldQuarterly`

- 竞争指标：`cpc{low/medium/high}`, `acos`, `breakEvenRatio`, `profitMarginGt50PctSkuRatio`, `returnRateAnnual`, `avgPrice`, `minimumPrice`, `maximumPrice`

报告中对每个已验证 niche 独立展示其极目指标，让用户看到品类下多个细分市场的对比（如 "mp3 player" vs "ipod classic" vs "mp3 player with bluetooth" 的垄断度/新品成功率/CPC 对比）。

#### S3.2-Fallback 兜底降级路径（sellersprite 空数据时自动触发）

**触发条件**（满足任一即触发）：
- API 返回 `errcode != 200`
- `data` 数组为空或缺失
- `data[0].products == 0`（样品商品数为 0）

**降级动作 — 关键词科学选择 + 动态翻页采集（翻到满 100 个唯一非广告商品为止）**：

**Step 0 — Fallback 关键词科学选择（必做，禁止跳过）**：

Fallback 翻页用什么关键词，不能盲目取种子词，必须对比以下两个候选词后科学选择：

| 候选词 | 来源 | 说明 |
|--------|------|------|
| 候选 A | 用户原始输入词 | 用户真正关心的品类入口词，搜索意图最精准 |
| 候选 B | S1 种子词（SIF 搜索量最大的精准词） | 搜索量更大，可能搜到更多商品但范围更宽泛 |

**对比维度**（从 S1.1 已有数据中直接取，不需要额外调用）：

1. **SIF 周搜索量**：哪个词搜索量更大（反映市场容量）
2. **S1.1 搜索结果数**：哪个词在默认相关性排序下返回的非广告商品更多（反映搜索结果丰富度）
3. **Top ASIN 重合度**：两个词的搜索结果中 Top 3 非广告 ASIN 是否一致（反映搜索意图是否同源）
4. **结果相关性**：快速扫描候选 B 的搜索结果标题，判断是否出现明显不相关品类（如"portable monitor"搜到车载显示器、工业触摸屏等）

**选择规则**：
- 若候选 A 和候选 B 的 Top 3 ASIN 完全重合 → 两词搜索意图同源，选搜索量更大的候选 B（能翻到更多商品）
- 若候选 B 搜索结果出现明显不相关品类 → 选候选 A（精准度优先于数量）
- 若候选 A 搜索结果数 ≥ 50 个非广告 → 选候选 A（数量足够且精准度更高）
- 以上规则不适用时，默认选候选 B（种子词），但在报告中注明选择依据

**选择结果记录**：在报告 data-source 中注明"Fallback 关键词选择：候选X（词名），选择依据：[规则]"

调用 `linkfox-amazon-search`，使用 `exact-aware-popularity-rank`（畅销商品）排序，逐页翻页采集：

```json
{"keyword": "<Fallback选定关键词>", "amazonDomain": "amazon.com", "language": "en_US", "sort": "exact-aware-popularity-rank", "page": <N>}
```

> **关键词锁定**：选定关键词后，翻页全程必须使用**同一个关键词**，**禁止中途换关键词重新尝试**。换词会导致前后页商品属于不同搜索意图，聚合统计失去意义。若某页返回商品不足，继续往后翻页即可，不可换词。

翻页规则（先探测再批量获取，避免逐页串行等待）：
1. **探测第一页**：先搜 page=1，检查返回的商品总数和广告比例
2. **计算总页数**：`总页数 = ceil(100 ÷ (每页非广告商品数))`，向上取整。例如第一页返回 16 个商品全部非广告 → 总页数 = ceil(100/16) = 7 页
3. **批量并行获取**：一次性并行发起 page=2 到 page=总页数 的搜索（不再逐页等待）
4. **合并去重**：所有页结果合并后，过滤 `sponsored: true`，按 ASIN 去重
5. **补页检查**：去重后若非广告商品不足 100 个，按差额计算需补几页（`补页数 = ceil((100-当前数) ÷ 每页非广告数)`），并行补搜
6. 取前 100 条按 `position` 升序作为样本
7. 若翻到 page=10 仍不足 100 条（极罕见），用实际拿到的数量作为样本，在报告中注明实际样本数

**数据处理与等价 JSON 输出**：
1. 合并所有页结果，过滤 `sponsored: true`，按 `position` 升序取前 100 条非广告商品
2. Python 脚本对 Top 100 做聚合统计，输出与 sellersprite 看板**等价 JSON 结构**（字段名与 sellersprite-market-statistics 一致），供 S4 无差别消费。**此脚本由 agent 现场编写**（与 S4 派生计算同策略，原因见 `S4.md` 脚本策略说明），须覆盖下方 17 个可算字段 + 5 个不可算字段标注 + `fallback_triggered` 标记 + `hl20*` 双版本字段，落盘后供 S4 消费
3. 降级 JSON 额外携带 `fallback_triggered: true` 标记 + `hl20*` 前缀的 Top 20 字段

**17 个可算字段派生公式**（详见设计文档 `fallback-plan-design`）：

| 分组 | 字段 | 公式 |
|------|------|------|
| 全样本 (Top 100) | `totalProducts` / `products` | count(非广告 ASIN) |
| | `brands` | count(distinct brand) |
| | `avgUnits` / `avgRevenue` | mean(monthlySalesUnits) / mean(monthlySalesRevenue) |
| | `avgPrice` / `avgRating` / `avgRatings` | mean(extractedPrice) / mean(rating) / mean(ratings) |
| | `avgBsr` | mean(position) **← position 替代 BSR** |
| | `avgWeight` / `baseAvgWeight` | mean(parse_weight(weight)) / avgWeight × 453.592 |
| | `avgVolume` / `baseAvgVolume` | mean(parse_volume(dimension)) / avgVolume × 16.387 |
| | `firstShelfDate` / `lastShelfDate` | min(availableDate) / max(availableDate) |
| 头部 Top N (N=10 和 20 双版本) | `hlProducts` / `hl20Products` | N |
| | `hlAvgUnits` / `hl20AvgUnits` | mean(monthlySalesUnits[:N]) |
| | `hlAvgRevenue` / `hl20AvgRevenue` | mean(monthlySalesRevenue[:N]) |
| | `hlAvgPrice` / `hl20AvgPrice` | mean(extractedPrice[:N]) |
| | `hlAvgRating` / `hl20AvgRating` | mean(rating[:N]) |
| | `hlAvgRatings` / `hl20AvgRatings` | mean(ratings[:N]) |
| | `hlAvgBsr` / `hl20AvgBsr` | mean(position[:N]) **← position 替代 BSR** |
| 新品 (availableDate ≤ 180 天) | `newProducts` / `newProductProportion` | count(new) / newProducts ÷ totalProducts × 100% |
| | `newAvgUnits` / `newAvgRevenue` / `newAvgPrice` | mean(字段 where new) |
| | `newAvgRating` / `newAvgRatings` | mean(rating/ratings where new) |
| | `minNewRatings` / `maxNewRatings` | min/max(ratings where new) |

**不可算字段（5 个）**：`sellers`, `avgSellers`, `avgRatingsCv`, `avgProfit`, `hlAvgRatingsCv` —— 报告中标注"数据未提供"。

### S3.5 Google Trends 5 关键词热度趋势

从 S1.2 的 SIF 精准关键词集合中取搜索量 Top 5 的词，分别调用 `linkfox-google-trend-get-trend-by-keys` 查询 5 年历史趋势（周维度）。5 次调用互相独立，同一轮并行发起。

参数（每个词一次调用）：

```json
{"keyword": "<关键词>", "region": "US", "dayRangeStart": "2021-07-24", "dayRangeEnd": "2026-07-24"}
```

取 `trendInfoForKeys[0].trendValues` 数组，字段：`timeRange`（周日期）、`value`（0-100 归一化热度）。

Google Trends 数据与 ABA 形成交叉验证：ABA 反映亚马逊站内搜索频率排名，Google Trends 反映 Google 搜索引擎上的搜索热度。两者趋势方向一致时增强判断可信度，分歧时揭示"Google 搜索意图与亚马逊购物意图的差异"（如 "ipod" 在 Google 上仍有高怀旧搜索量，但在亚马逊站内搜索排名持续下滑）。

### S3.6 社媒趋势验证（网络搜索）— 条件触发步骤

> **重要**：此步骤是**条件触发步骤**，不是"可选步骤"。当触发条件满足时**必须执行**，不得跳过。仅当触发条件不满足时才跳过。

**触发条件**（满足任一即触发）：
- Google Trends 某关键词年度均值较上年增长 ≥ 50%（如 32→70，翻倍以上）
- Google Trends 某关键词最近一年均值与前4年均值之比 ≥ 1.5（突增信号）
- ABA 某关键词排名在26周内改善 ≥ 30%（排名数值下降30%以上）
- ABA 某关键词排名在26周内恶化 ≥ 30%（排名数值上升30%以上）

取 `searchList` 数组，每条提取：`title`, `url`, `content`（页面摘要）, `score`（相关性）。

**使用场景**：

### S3.7 亚马逊商业洞察报告

使用 S1.2 中 SIF 反查出的带有 `isMainKw` **或** `isAccurateKw` 标签且搜索量最大的精准词，调用 `linkfox-amazon-opportunity-report-by-keyword` 查询亚马逊官方商业洞察报告，判断该关键词是否已形成成熟的细分市场赛道。

**脚本路径**：

```bash
python /root/.linkfox/.ce/skills/linkfox-amazon-opportunity-report-by-keyword/scripts/amazon_opportunity_report.py '<JSON参数>' --inline
```

> **注意**：必须加 `--inline` 标志，确保完整响应输出到 stdout。不加 `--inline` 时大响应只输出摘要，可能导致 `stdout` 字段（Markdown 报告正文）被截断。

**参数格式**：

```json
{"keyword": "<SIF isMainKw 或 isAccurateKw 搜索量最大的精准词>", "site": "US"}
```

**重试策略**（重要）：

首次查询可能返回 `errcode: 4004`（未找到该关键词的洞察数据）。此时**不要直接放弃**，按以下顺序依次重试 S1.2 精准关键词集合中的其他词：

1. 取 SIF `isMainKw` **或** `isAccurateKw` 标签词中搜索量 Top 5 的词（两种标签的词均可，合并后按搜索量降序取前 5）
2. 第一个词返回 4004 → 尝试第二个词
3. 第二个词返回 4004 → 尝试第三个词
4. 依此类推，最多尝试 5 个词
5. 5 个词全部返回 4004 → 确认该品类暂无商业洞察数据，在报告中注明"数据未获取"

**判断逻辑**：
- 如果报告返回 `code: "200"` 且 `stdout` 非空 → 该关键词已形成细分赛道，报告内容纳入 S5 报告的第 6 节
- 如果报告返回 `errcode: 4004` → 尝试下一个精准词
- 如果所有精准词均返回 4004 → 该品类尚未形成亚马逊官方认可的细分赛道，跳过此步骤

> **注意响应字段差异**：成功响应使用 `code`/`msg`/`stdout` 字段（API 文档定义），错误响应可能使用 `errcode`/`errmsg` 字段（网关层返回）。判断成功时以 `code == "200"` 或 `stdout` 字段非空为准。

返回 `stdout` 字段为 Markdown 格式的六维分析报告，涵盖：

1. **市场潜力**：年搜索量、YoY 增长率、近 90 日趋势、销售额、销量、均价、缺货率
2. **竞争结构**：在售产品数、品牌数（YoY 变化）、Top5 品牌 Click Share、新品上线数
3. **产品特征**：决胜属性（标配层）+ 溢价属性（差异化层）
4. **评价质量**：平均评分、差评痛点分布（设备失效/电池/说明书等）
5. **客户画像**：买家年龄段、收入区间、使用场景
6. **定价分析**：价格带分布、甜蜜区、空白价格段

**与其他数据源的交叉验证**：
- 商业洞察的"YoY 搜索量增长率" vs Google Trends 年度均值变化 → 验证趋势方向一致性
- 商业洞察的"差评痛点" vs 前台搜索的"低分高销量竞品" → 验证品质缺口是否已转化为搜索行为
- 商业洞察的"价格带甜蜜区" vs 前台搜索的"价格分布分桶" → 验证价格集中区是否一致
- 商业洞察的"客户画像" vs 前台搜索的"产品形态分类" → 验证人群与产品形态的匹配度
