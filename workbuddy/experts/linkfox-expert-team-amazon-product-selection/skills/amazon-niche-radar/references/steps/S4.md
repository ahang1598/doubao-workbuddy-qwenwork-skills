# 步骤 S4：派生计算

- **输入**：S3 的四个数据源原始数据
- **依赖**：S3（全部四个数据源返回后才能开始）
- **用途**：为 S5 报告提供所有派生统计指标，禁止 LLM 心算

## 操作

编写 Python 脚本，从 S3 落盘的 JSON 文件中读取数据，计算以下派生指标，输出为一份 JSON 文件。

### 来自卖家精灵数据（sellersprite-market-statistics）

#### 4.1 类目市场规模
- 年化销售额 = `avgRevenue × products × 12`
- 年化销量 = `avgUnits × products × 12`
- 市场时间跨度天数 = `lastShelfDate - firstShelfDate`（市场成熟度指标）
- 物流成本参考：`avgWeight`（磅）/ `baseAvgWeight`（克）→ 判断 FBA 重量段
- 仓储成本参考：`avgVolume`（in³）/ `baseAvgVolume`（cm³）→ 判断体积段

#### 4.2 头部集中度（头部 Top10 vs 类目均值对比）
- 销量倍数 = `hlAvgUnits ÷ avgUnits`
- 收入倍数 = `hlAvgRevenue ÷ avgRevenue`
- 价格策略对比 = `hlAvgPrice - avgPrice`（正值=头部高价，负值=头部低价走量）
- 评分优势 = `hlAvgRating - avgRating`
- 评论壁垒 = `hlAvgRatings - avgRatings`（头部比均值多多少条评论）
- 评论增长速度对比 = `hlAvgRatingsCv - avgRatingsCv`（头部月增评论 vs 均值月增评论）
- BSR 排名优势 = `avgBsr - hlAvgBsr`（正值=头部排名更靠前）

#### 4.2-Ext 头部 Top 20 扩展（仅 S3.2-Fallback 降级路径触发时计算）

当 sellersprite 数据为空、降级路径输出包含 Top 20 字段（`hl20AvgUnits` 等）时，额外计算以下 6 项指标，公式与 4.2 一致但 N=20。`hlAvgRatingsCv` 因降级路径不可算，跳过评论增长速度对比。

- 销量倍数 (Top20) = `hl20AvgUnits ÷ avgUnits`
- 收入倍数 (Top20) = `hl20AvgRevenue ÷ avgRevenue`
- 价格策略对比 (Top20) = `hl20AvgPrice - avgPrice`
- 评分优势 (Top20) = `hl20AvgRating - avgRating`
- 评论壁垒 (Top20) = `hl20AvgRatings - avgRatings`
- BSR 排名优势 (Top20) = `avgBsr - hl20AvgBsr`（position 替代 BSR）

**意义**：Top 10 反映绝对头部画像，Top 20 反映腰部进阶门槛。对比两者的销量倍数差距可判断头部集中度梯度——若 Top 10 倍数远高于 Top 20，说明销量高度集中在绝对头部；若两者接近，说明头部到腰部过渡平缓。

#### 4.3 新品表现（新品 vs 类目均值对比）
- 新品销量达标率 = `newAvgUnits ÷ avgUnits`（>1 表示新品销量超均值）
- 新品收入达标率 = `newAvgRevenue ÷ avgRevenue`
- 新品定价策略 = `newAvgPrice - avgPrice`（正值=新品定价更高，走差异化）
- 新品评分差距 = `avgRating - newAvgRating`（正值=新品评分低于均值）
- 新品评论门槛区间 = `minNewRatings → maxNewRatings`（最低多少条评论能进榜）
- 新品评论追赶难度 = `avgRatings ÷ newAvgRatings`（均值是新品评论数的多少倍）

#### 4.4 竞争门槛汇总表
直接取值汇总为表格，无需计算：`avgPrice`, `avgRating`, `avgRatings`, `avgRatingsCv`, `avgBsr`, `avgProfit`, `avgSellers`, `avgWeight`, `avgVolume`

### 来自前台搜索数据（amazon-search × 3 页）

对三页合并数据做以下 11 项派生统计，对应 S3.3 中定义的 11 个分析维度：

1. **流量聚集度**（降级路径下改名**「销量梯队分布」**，见 `S3.md` S3.2-Fallback 维度 1 适配）：`sum(monthlySalesRevenue)` 按 page 1/2/3 分别求和；降级路径下按 bestseller page 1-N 分别求和
2. **商品集中度**：按 `position` 排序的 `monthlySalesUnits` 序列 + 累计占比百分比
3. **品牌集中度**：按 `brand` 聚合 `monthlySalesUnits` 求和，降序取 Top 15 + 累计占比；CR3/CR5 = Top 3/5 品牌月销量之和 ÷ 全部商品总月销量
4. **价格分布**：按 `extractedPrice` 分桶（$0-15/15-30/30-60/60-100/100-200/200+），每桶商品数 + 销量合计 + 销量占比
5. **上架时间分布**：按 `availableDate` 计算距今时长，分桶（1月/3月/半年/1年/2年/3年/3年+），每桶商品数 + 销量占比
6. **上架趋势分布**：按 `availableDate` 提取年份分桶，每桶商品数 + 销量占比
7. **评分数分布**：按 `ratings` 分桶（无/1-50/50-100/100-200/200-500/500+），每桶商品数 + 销量占比
8. **评分值分布**：按 `rating` 分桶（<3.0/3.0-3.5/3.5-4.0/4.0-4.2/4.2-4.5/4.5+），每桶商品数 + 销量占比；额外识别 `rating < 4.2 且 monthlySalesUnits > 均值` 的竞品
9. **卖家类型分布**：按 `fulfillment` 统计 FBA / AMZ / 其他 的商品数 + 销量占比
10. **卖家所属地分布**：按 `sellerNation` 聚合，统计商品数 + 销量占比
11. **变体复杂度**：`options` 字段非空的商品比例

另外补充一个汇总项：
- **Top 20 商品清单**：先过滤 `sponsored: false` 排除广告商品，再按 `position` 升序取前 20 条自然排名商品。含 asin/brand/title/price/rating/ratings/units/revenue/fulfillment/nation/date 全部字段

### 来自 ABA 数据

#### Part A — 5 关键词搜索排名分析（来自 S3.4-B，字段：searchterm, reportstartdate, searchFrequencyRank）

1. **排名趋势序列**：每个关键词 26 周的 `searchFrequencyRank` 数组，用于折线图
2. **排名波动率**：变异系数 CV = `std(ranks) / mean(ranks) × 100`，判断关键词热度稳定性
3. **趋势方向**：前 13 周均值 vs 后 13 周均值，百分比变化 = `(后半段均值 - 前半段均值) / 前半段均值 × 100`（正值=恶化，负值=改善）
4. **周环比改善/恶化次数**：逐周比较 `searchFrequencyRank` 变化方向，统计改善次数（排名变小）和恶化次数（排名变大）
5. **最佳/最差排名**：`min(ranks)` 和 `max(ranks)`，展示排名区间
6. **热度梯队分层表**：按最新一周排名分梯队（第一梯队 < 5,000 / 第二梯队 5,000-20,000 / 第三梯队 > 20,000）

#### Part B — 种子词 Top ASIN 点击转化分析（来自 S3.4-A，字段：reportstartdate, clickedasin, clickShare, conversionShare, clicksharerank）

1. **Top3 点击集中度趋势**：每周 Top3 ASIN 的 `clickShare` 之和，按周排列
2. **Top3 转化集中度趋势**：每周 Top3 ASIN 的 `conversionShare` 之和，按周排列
3. **最新一周 Top3 ASIN 对比**：取最新 `reportstartdate` 的 Top3 ASIN，展示 `clickShare` vs `conversionShare` 对比柱状图
4. **点击-转化效率比**：`conversionShare ÷ clickShare × 100%`，效率 >100% 表示该 ASIN 转化能力超过其点击份额（高转化低点击的潜力品）
5. **头部 ASIN 更替频率**：统计 26 周内 `clicksharerank=1` 的不同 ASIN 数量，更替次数越多说明头部竞争越激烈

### 来自 Google Trends 数据（S3.5，字段：timeRange, value）

1. **5 年周维度趋势序列**：每个关键词 262 周的 `value` 数组，用于多折线对比图（支持 dataZoom 缩放）
2. **年度均值**：按 `timeRange` 的年份分组，计算每年 `value` 均值，用于年度对比表
3. **5 年趋势方向**：首年均值 vs 末年均值，百分比变化（正值=热度上升，负值=热度下降）
4. **Google Trends vs ABA 交叉验证**：对比每个关键词的 Google Trends 趋势方向与 ABA 排名趋势方向，判定一致性：
   - 一致：两源趋势方向相同（如 Google 上升 + ABA 改善），增强判断可信度
   - 分歧：两源趋势方向相反（如 Google 高位平稳 + ABA 持续下滑），揭示搜索意图差异
   - 无法对比：Google Trends 数据稀疏（大量 0 值）时不做判定

## 输出

一份 JSON 文件，包含报告所需的全部派生指标。后续 S5 写 HTML 时，统计数字只从这份 JSON 里取。

## 落盘

```python
import json
result = { ... }
output_path = resolve_data_path("market-insight-derived", timestamp, "json")
with open(output_path, "w") as f:
    json.dump(result, f, ensure_ascii=False, indent=2)
print(f"Saved full response: {output_path} ({os.path.getsize(output_path)} bytes)")
```

### 脚本策略说明

S4 的派生计算由 agent 现场编写 Python 脚本完成（不像 S6.4-C 利润核算有预置脚本 `step_4_calc_profit.py`）。原因：S4 的派生计算逻辑（分桶边界、聚合维度）因品类和数据源返回结构而异，需要 agent 根据实际数据调整；而 S6.4-C 的利润核算公式固定，可预置脚本。

脚本须使用 `scripts/linkfox_paths.py` 的 `resolve_data_path` 函数落盘，输入从 S3 落盘的 JSON 文件读取。

### 自检清单（agent 写完脚本后逐项确认）

- [ ] 前台搜索派生：11 项维度统计（流量聚集度 / 商品集中度 / 品牌集中度 CR3 CR5 / 价格分布 / 上架时间 / 上架趋势 / 评分数 / 评分值 / 卖家类型 / 卖家所属地 / 变体复杂度）+ Top 20 商品清单（过滤 sponsored）
- [ ] ABA 派生：Part A 6 项（排名趋势 / 波动率 CV / 趋势方向 / 周环比 / 最佳最差排名 / 热度梯队）+ Part B 5 项（Top3 集中度趋势 / 最新周对比 / 效率比 / 头部更替频率）
- [ ] Google Trends 派生：5 年趋势序列 / 年度均值 / 趋势方向 / 与 ABA 交叉验证
- [ ] 输出 JSON 包含报告所需的全部派生指标，后续 S5 写 HTML 时只从这份 JSON 取值
