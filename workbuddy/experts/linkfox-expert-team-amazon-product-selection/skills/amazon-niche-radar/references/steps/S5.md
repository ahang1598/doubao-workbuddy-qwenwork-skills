# 步骤 S5：报告生成

- **输入**：S4 的派生计算 JSON + S3 的四个原始数据源
- **依赖**：S4
- **用途**：交付最终 HTML 报告给用户

## 操作

### S5.1 读取组件规范

Read `linkfox-report-generator` 的 `references/analysis-layouts.md`，了解可用组件（KPI Cards / Content Section / Chart Container / Data Table / SWOT Grid / Progress Bar / Summary Box / Insight List 等）。

同时 Read 本 skill 的 `references/layout-extensions.md`，了解扩展组件（Three-Column Stats Panel 三列数据总览看板）。

### S5.2 设计报告结构

报告支持两种模式：

**模式 A — 综合分析报告（默认）**：按数据源分节，每个数据源独立做自己的多维度分析：

1. Report Header（标题 + 数据快照日期 + 数据来源说明）
2. Section: 极目细分市场洞察（数据源：jiimore，S2-B 最早获取）
3. Section: 亚马逊前台搜索分析（数据源：amazon-search，S1.1 获取，S3.3 复用）
4. Section: 卖家精灵类目统计（数据源：sellersprite，S3.2 获取）
5. Section: ABA 搜索词分析（数据源：aba）
6. Section: Google Trends 关键词热度分析（数据源：google-trend，S3.5 获取；若 S3.6 社媒验证触发则附在末尾）
7. Section: 头部卖家清单 Top 20（数据源：amazon-search）
8. Section: 亚马逊商业洞察报告（数据源：amazon-opportunity-report，S3.7 获取，条件触发：5 词全 4004 则跳过）
9. Section: Top ASIN 深度拆解 + 利润核算（数据源：keepa + sif + 1688，S6 获取）
10. Section: 综合研判（SWOT + Insight List）
11. Footer

**模式 A 降级路径适配（S3.2-Fallback 触发时自动应用）**：

当 S3.2 触发 Fallback 降级路径（sellersprite 返回空数据）时，模式 A 的第 4 节「卖家精灵类目统计」自动切换为降级看板，需做以下 3 处调整：

**调整 0 — S3.3 数据源不切换**：降级路径下，S3.3 的 11 维度分析**继续用 S1.1 的 3 页默认排序数据**，不切换到 bestseller Top 100。两批数据服务于不同章节：S1.1 的 3 页 → 第 3 节「亚马逊前台搜索分析」（反映默认排序下的竞争格局）；S3.2-Fallback 的 bestseller Top 100 → 第 4 节降级看板（反映销量梯队）。两批数据不混用、不替换。

**调整 1 — 第 4 节标题与 data-source 标注**：
- 章节标题改为「卖家精灵类目统计（兜底降级 · bestseller Top 100）」
- `data-source` 标注 `amazon-search (bestseller fallback)` 而非 `sellersprite`
- 追加 `.ds-computed` 子块注明：
  - `avgBsr` / `hlAvgBsr` 使用 bestseller 排序下的 `position` 替代 BSR，口径差异可忽略，数据为调用前几分钟内的真实前台数据
  - `sellers` / `avgSellers` / `avgRatingsCv` / `avgProfit` / `hlAvgRatingsCv` 5 个字段标注"数据未提供"
  - 如需真正类目 Top 100 BSR 榜单，可在自定义 agent 板块二创替换为 Sorftime / Junglescout 等数据源

**调整 2 — 第 4 节必须输出两个产物（三列看板 + 11 维度图表）**：

**产物 1 — 三列数据看板**：Read `references/templates/sellersprite-dashboard.md` 模板，数据从降级 JSON 取值（非 sellersprite API 直取）。关键差异：
- 左列「全部样本」：`sellers` / `avgSellers` / `avgRatingsCv` / `avgProfit` 4 个字段显示"数据未提供"，其余 9 个字段从降级 JSON 取值
- 中列「头部商品」：**上下排列两个 data-table**（Top 10 用 `hl*` 字段、Top 20 用 `hl20*` 字段），`hlAvgRatingsCv` 显示"数据未提供"
- 右列「新品 + 市场时间」：全部 11 个字段从降级 JSON 取值，无缺失
- 头部 vs 全样本均值对比柱状图（4 张 ECharts）：需双版本——Top 10 vs 均值 + Top 20 vs 均值

**产物 2 — 11 维度竞争格局图表**：Read `references/layout-extensions.md` 第 19 节「Amazon-Search Charts Panel」组件，数据源为 bestseller Top 100 非广告商品。9 张 ECharts 图表 + 2 项纯数据统计：
- 9 个有效维度照搬第 19 节图表配置：品牌集中度（帕累托图）/ 价格分布 / 上架时间分布 / 上架趋势分布 / 评分数分布 / 评分值分布 / 卖家类型分布（饼图）/ 卖家所属地分布 / 变体复杂度
- 维度 1「流量聚集度」→ 改名「销量梯队分布」：page 1-N 月销售额柱状图，反映头部 vs 腰部销量差距
- 维度 2「商品集中度」→ 保留 CR3/CR5 数据表，去掉帕累托拐点图（bestseller 排序下 position 已按销量降序，帕累托图天然单调递减）

**调整 3 — 输出检查清单（agent 自检，全部通过才能交付报告）**：
- [ ] 三列看板已用 `sellersprite-dashboard.md` 模板生成，非手拼 HTML
- [ ] 中列包含 Top 10 和 Top 20 两个 data-table
- [ ] 5 个不可算字段显示"数据未提供"
- [ ] 11 维度图表已用 `layout-extensions.md` 第 19 节组件生成，9 张图全部渲染
- [ ] 维度 1 标题为「销量梯队分布」而非「流量聚集度」
- [ ] 维度 2 为 CR3/CR5 数据表，无帕累托拐点图
- [ ] `data-source` 标注 `amazon-search (bestseller fallback)` + BSR 替代说明

**模式 B — 卖家精灵看板模式（Section 3 默认）**：sellersprite 数据正常时必须使用，无需用户额外要求。Read `references/templates/sellersprite-dashboard.md` 获取模板，将 `sellersprite-market-statistics` API 返回字段直接填入模板占位符，生成三列数据总览面板 + 4 张 ECharts 对比图。全部字段直接取自 API，无派生计算。

### S5.3 写 HTML 片段

按 `analysis-layouts.md` 的组件规范写完整 HTML 片段，从 `.report-header` 到 `.report-footer`。

关键规则：
- 不输出 `<!DOCTYPE>` / `<html>` / `<head>` / `<style>` / `<body>` / `<h1>`
- 每个含统计数字的 section 末尾必须有 `<div class="data-source">`
- 含派生计算的 section 末尾追加 `.ds-computed` 子块
- 数字千分位，百分比保留 1 位小数
- 图表用 ECharts（交互图）或 Canvas（静态图）
- 色板：`['#4f46e5','#06b6d4','#8b5cf6','#f59e0b','#10b981','#ef4444','#ec4899','#6366f1']`

### S5.4 落盘并注入模板

Write HTML 片段到文件，然后调用 inject_report.py：

```bash
python <linkfox-report-generator>/scripts/inject_report.py \
    --content-file <片段文件路径> \
    --language <zh|en> \
    --title <english-slug>
```

stdout 返回最终 HTML 报告路径。

### S5.5 告知用户

交付前确认：

- [ ] 三列看板已用 `sellersprite-dashboard.md` 模板生成（非手拼 HTML）

给用户最终 HTML 路径 + 一句话总结。不要把整份报告全文读回上下文。

### S5.6 报告生成优化策略

以下策略用于避免报告生成过程中的上下文溢出和阻塞：

**1. 分章节写入，不要一次性拼整个 HTML**
- 每个 content-section 独立写一段 HTML，追加到片段文件末尾（用 `>>` 或 Python `open(mode='a')`）
- 不要在一个 Write 调用中写超过 300 行的 HTML 片段——拆成多次追加
- 示例：先写 header + section1 → 追加 section2 → 追加 section3 → ... → 最后一次性调 inject_report.py

**2. 中间数据按需读取，不全部灌入上下文**
- S3/S4 的数据已落盘到 JSON 文件，写报告时用 Python `jq` 或 `json.load` 只提取当前章节需要的字段
- 不要把整个派生计算 JSON（可能 >10KB）读进上下文再手动取值
- 每个章节写完后，该章节的数据就可以从上下文中"遗忘"

**3. 大图表数据降采样**
- Google Trends 5 年 262 周数据点：ECharts dataZoom 支持交互缩放，但 HTML 体积会增大。如果片段 > 50KB，将周数据降采样为月数据（取每月均值，~60 个点）作为默认显示，dataZoom 仍可展开
- Amazon-search 前三页 ~150 个商品的价格分布图：直接用分桶后的聚合数据（6 个桶），不要把 150 个商品逐个画在图上

**4. 解读规范按需加载**
- `references/keepa-interpretation.md` 和 `references/sif-asin-interpretation.md` 只在写报告第 7 节（Top ASIN 深度拆解）时 Read，不在报告开始时一次性全部读取
- `references/layout-extensions.md` 只在需要三列看板或九图表组件时 Read

**5. 报告分段交付（超长报告兜底）**
- 如果报告预计 > 10 个 section 且每个 section 内容丰富，可将报告拆为两部分：
  - 主报告（section 1-8）：市场全景 + 数据源分节分析
  - 深度附录（section 9-10）：Top ASIN 深度拆解 + 综合研判
- 两部分分别调 inject_report.py 生成两个 HTML 文件，告知用户两个路径

**6. 避免重复读取大响应**
- SIF 关键词反查返回 ~80KB 数据：写入报告时只取 Top 10 关键词，用 `jq '.data[:10]'` 投影，不要把 80KB 读进上下文
- ABA 返回 ~50KB 数据：用 `jq` 只取需要的日期和排名字段，不要全量读取
- 亚马逊搜索三页 ~60KB 数据：用 Python 脚本直接从落盘文件计算派生指标，不要把原始商品列表读进上下文

## 输出

- 最终 HTML 报告文件路径（通过 `Saved full response:` 行交付）
