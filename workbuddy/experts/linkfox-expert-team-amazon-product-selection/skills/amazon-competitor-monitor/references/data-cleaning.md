# 竞品监控数据清洗规则

在异常检测与可视化之前强制执行。目标：降低误报、统一时间与口径。

## 1. 时间对齐
- 所有指标对齐到同一采集日（或同一小时窗口）
- 缺失当日数据：用最近有效值填充，并标记 `is_imputed = true`
- 「当前 vs 上期」必须同一工具、同一时间粒度

## 2. 评分数特殊处理
```
if reviews 下降 ≥ 30%（或绝对减少 ≥ 300）且 rating 变化 ≤ 0.1:
    标记为「疑似评论清理 / 变体合并 / 数据源差异」
    优先级降为「中」或「观察」，不要直接当差评爆发
```
激增同理：结合 Vine / 集中补评可能，观察转化率。

## 3. 价格与 Deal
- 优先使用 Buy Box 价格做变化率
- 同时记录 list_price、deal_price、是否 Limited time deal / Coupon
- Deal 状态从有→无 或 无→有：单独标记「促销状态变化」，不与纯价格变动混为一谈

## 4. 销量与 BSR 一致性
```
if sales_current == 0 and bsr 仍存在 and stock != OOS:
    flag = 「销量归零但非断货（疑似数据延迟或 Listing 异常）」
    不要直接判为断货高优先级
```
BSR 变差但销量上升：考虑类目整体变化或延迟，降低单一指标权重。

## 5. 多工具口径
- 趋势主序列固定用 **Keepa**
- SellerSprite 等仅作交叉验证
- 禁止用 A 工具的「上期」减 B 工具的「本期」算变化率

## 6. 关键词（SIF）
- null / `-` / `0` 统一为缺失，不参与变化率
- 自然排名与广告排名分开
- 变化：`current - prev`（正数 = 下滑）
- 可过滤搜索量过低词（如 < 100）减少噪音

## 7. 极值硬过滤
| 字段 | 合法区间 | 否则 |
|------|----------|------|
| price | [1, 9999] | 丢弃或 invalid |
| bsr | [1, 5_000_000] | 丢弃 |
| reviews | ≥ 0 | 置 0 |
| rating | [1.0, 5.0] | 丢弃 |

## 8. 变体 / 父体
- 全程固定监控父体或主推子体之一，不要混用
- 记录 parent_asin，便于排查评论数跳动

## 9. 缺失值策略
| 字段 | 处理 |
|------|------|
| 价格 | 近 3 日中位数填充 + imputed |
| BSR | 不填充，保留缺失（本身有信息） |
| 评分数 | 前值延续 |
| 销量 | 前值延续，降低异常权重 |
| 关键词排名 | 保持 null |

## 10. 出报告前检查清单
1. 时间窗口是否对齐？
2. 评分数大降是否伴随评分大降？
3. 销量归零是否已排除断货与延迟？
4. 价格变化是否同时有 Deal 状态变化？
5. 是否存在抓取失败极值？
6. 是否跨工具混用前后值？
