# 试跑提示词（针对本 meta-skill 自身）

> 目的：验证 `linkfox-ecommerce-skill-creator` 在用户说三种诉求（新建 / 复刻 / 微调）时能正确唤起，并把流程跑通。
> 三类必备：核心 + 边界 + 欠触发探针。

---

## 核心（happy path）

### C1：模式 1 新建（业务从零搭）
> 帮我做一个每周选品的 skill，每周一早上跑一次，能看 ABA 流量里冒出来的新词、对应类目的新品潜力，最后吐一份候选 ASIN 名单。

期望：进入模式 1 → 阶段 0 抽取已知 → 阶段 1 让用户自述 → 阶段 2 扫 `tier1-recipes.yaml` → 命中"周度选品"配方或回退到能力主表 → 阶段 4 把方案讲给用户确认 → 阶段 5 合成 trial prompts → 阶段 6 生成产物目录。

### C2：模式 2 复刻（换平台）
> 我有一个 amazon 的 listing 复刻 skill，现在要做一个 tiktok shop 版本，照着改一份。

期望：进入模式 2 → 读源 skill snapshot → 差异点访谈（平台变 → Tier 1 链路重选） → 渲染 diff → 生成产物目录 → 重跑 DAG 自检。

### C3：模式 3 微调（改一处）
> 把周度选品那个 skill 的 top N 从 50 改成 30，再加一列"评论数"。

期望：进入模式 3 → 变更面识别落到"字段增删 + 阈值"→ 直接 patch SKILL.md → 重跑 quick_validate + 1 条 trial prompt。

---

## 边界

### B1：只调一个 Tier 1（应被劝退到 Tier 1 直调）
> 帮我做一个 skill，给个 ASIN 就返回它的标题、价格、评分。

期望：识别到"只调一个 Tier 1 wrapper"信号 → 不进流程 → 建议直接调 `linkfox-amazon-product-detail`。

### B2：一次性分析（应被劝退）
> 帮我把这个 ASIN B0XXXXXX 的评论分析一下，看看主要差评原因。

期望：识别到"一次性分析"信号 → 不沉淀 skill → 建议直接执行。

### B3：浏览器抓取（应路由到 browser-act-skill-forge）
> 我想做一个 skill 自动登录某个站点把购物车导出来。

期望：识别到"浏览器自动化"信号 → 路由到 `browser-act-skill-forge`，不进本规范。

---

## 欠触发探针（最简短随意的口吻）

### U1：极简新建
> 帮我把这个流程变成可复用的。

期望：仍能触发（依赖 description 反向补漏一句 "即使用户只说'帮我把这个变成可复用的'…也应触发"）。

### U2：极简复刻
> 再来一个类似的，换 tiktok。

期望：触发模式 2，主动追问源 skill 是哪一个。

### U3：英文极简
> make this reusable.

期望：触发并主动追问场景与流程。
