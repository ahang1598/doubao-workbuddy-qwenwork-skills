# 试跑与迭代

> 借鉴 `skill-creator` 的 draft → trial → review → improve 循环。
> 不引入量化 benchmark；保持轻量但严肃。

---

## 试跑提示词的三类配比

每个 skill 至少 2–3 条试跑提示词，类型搭配：

| 类型 | 用意 | 例（A 周度选品 skill） |
|------|------|----------------------|
| **核心** | 最典型用法跑通 | "帮我做一次本周的母婴类目选品" |
| **边界** | 极端值 / 空结果 / 失败路径 | "看一下电动牙刷类目本周有没有突围款"（窄类目，可能没新品） |
| **欠触发探针** | 用户用最简短随意的口吻说 | "周一了，看看竞品" |

每条 prompt 用真实业务场景的语言，不要工具腔（"请调用 skill X 处理参数 Y"）。

---

## 试跑前要做

1. **念给用户确认**：
   > "我会用这两条提示词跑一下：……可以吗？"
   用户改写或加条目都接受。这是廉价的核对动作，比让用户从零写更轻。
2. **确认产物已就位**：自定义 skill 装在 `/root/.linkfox/workspaces/.claude/skills/<name>/` 或交付目录里，能被 agent 找到；系统级 `linkfox-*` skill 位于 `/root/.linkfox/.ce/skills/<name>/`，只读调用。
3. **决定执行环境**：本会话直接跑，还是新开 agent 触发？
   - 本会话：上下文已有，但容易"作弊"（agent 凭记忆而非 SKILL.md 走流程）。
   - 新会话：更接近真实使用，推荐。

---

## 单条试跑的循环

每条 prompt **独立走一遍 1–5**，不要批量跑完再统一处理：

### 1. 跑一条

执行当前 prompt，拿到日志、中间产物、报告产物。

### 2. agent 自检

把问题分两类：

**自行修复（明显错）**：
- 工具调用失败 / 参数错误。
- 数据缺失的降级逻辑不合理（例：API 返回空，不应该报告里写"暂无数据"，应该提示用户检查 key）。
- 字段中英混用 / 章节顺序错位 / 数字精度 / 缺货币符号。
- 排版瑕疵。

修完记下"自检发现 + 修复动作"。

**留给用户（影响业务理解）**：
- 评分权重 / 增删步骤 / 替换工具 / 阈值改动。
- 报告章节增减。
- 业务术语翻译选择。

**不要擅自改**——列出"建议 + 理由"等用户决策。

### 3. 呈现结果

把自检后的结果给用户：
- (a) 试跑产物链接（报告 / 中间数据落盘）。
- (b) 已修问题清单。
- (c) 待确认建议清单。

### 4. 接收反馈再迭代

用户提出整改 → 回到 1 重跑这条。

**沉默不算满意**：
- "还行" / "差不多" / "你看着办" → 再问一次具体哪里要改。
- 必须拿到"这条 OK，下一条"明确信号才进入下一条。

### 5. 进入下一条

上一条用户明确收工后，再开始下一条。重复 1–4。

---

## 反馈分类

每条用户反馈可以归到三类：

| 类别 | 处理 | 来源信号 |
|------|------|---------|
| 业务理解错误 | 回访谈剧本步骤 1 / 2 修 | "这一步根本不该有"、"权重不对" |
| 写法瑕疵 | 直接改产物 | "标题应该粗体"、"日期格式" |
| 触发问题 | 改 frontmatter description | "我说 X 它没反应" |

第三类容易被忽略——欠触发探针就是为它设计的。

---

## 跳过试跑的处理

用户当面说"不用试，先看看" → 把这一步标记为"未执行"，写进 `<产物目录>/.draft/dag.md`：

```markdown
## 试跑状态
- [ ] 核心 prompt: 未执行（用户跳过）
- [ ] 边界 prompt: 未执行
- [ ] 欠触发 prompt: 未执行

下次会话补做。
```

不要无声跳过——下次有人接手时不知道这一步漏了。

---

## 与 skill-creator 的差异

`skill-creator` 提供 `run_loop.py`、eval-viewer、blind comparison 等量化评测能力——本规范**不引入**。理由：

- 团队当前规模 + 电商业务节奏不需要量化打分。
- 量化评测要求维护 evals.json、grader prompt、history.json——重资产。
- 轻量自检 + 试跑 + 用户确认对当前阶段足够。

如果将来需要量化评测，升级路径：参考 `skill-creator/references/schemas.md` 的 schema 引入 evals.json 和 grader 流程。本目录不删除该升级路径。

## 类型 适配

| 类型 | 试跑重点 |
|-----------|---------|
| A 流程型 | 端到端跑通 + 报告产物外观符合预期 |
| B API 型 | 单 ASIN / 多 marketplace / 错误参数三类 |
| C 知识型 | 边界场景（输入超出领域）+ 欠触发探针（最简口吻） |
| D 抓取型 | 真实站点抓一次 + 反爬触发 + 选择器失效降级 |
