# 步骤 4：净利润核算

- **输入**：S1a 的 Keepa 商品详情 + S1b 的 buyboxPrice 历史曲线 + S2 的 1688 供应商数据 + S3 的市场指标映射表
- **依赖**：S1, S2, S3（全部数据就绪）
- **操作**：运行 `scripts/step_4_calc_profit.py`，脚本自动完成以下处理：

  **⚠️ 参数取值规则（除头程外禁止用默认值）**

  | 参数 | 数据来源 | 允许默认 |
  |------|---------|---------|
  | 售价 | S1b 的 buyboxPrice 曲线正常售卖价（非秒杀价） | ❌ 禁止 |
  | FBA配送费 | Keepa fbaFees | ❌ 禁止 |
  | 佣金比例 | Keepa referralFeePercentage | ❌ 禁止 |
  | 退货率 | S3 极目 niche returnRateAnnual | ❌ 禁止 |
  | ACoS | SIF sponsoredProductsKeywordCount==0 → 广告费$0；否则 S3 极目 niche acos × sponsoredProductsPercentageNow | ❌ 禁止 |
  | 弃置费 | Keepa 包装尺寸 → FBA 费率表自动查表 | ❌ 禁止 |
  | 仓储费率 | Keepa 包装尺寸 → FBA 费率表自动查表 + 当前月份 | ❌ 禁止 |
  | 入库配置费 | Keepa 包装尺寸 → FBA 费率表自动查表 | ❌ 禁止 |
  | 头程运费 | 用户输入（默认 $3.0） | ✅ 允许 |

  脚本 stderr 输出每个参数的来源和值，便于审计。未传入 --keepa-history-file 或 --market-metrics-file 时，脚本会用默认值并在 stderr 输出 `[⚠️ 警告]`。

  **FBA 费率自动查表**（`determine_fba_size_tier()`）

  脚本根据 Keepa 的 `packageWeight`（g）和 `packageLength/Width/Height`（mm）判断商品尺寸分段，自动匹配弃置费/仓储费率/入库配置费（费率表见 `references/fba-fee-table.md`）：

  | 尺寸分段 | 弃置费 | 仓储费率(1-9月) | 仓储费率(10-12月) | 入库配置费 |
  |---------|--------|----------------|-------------------|-----------|
  | 标准尺寸 | $0.50 | $0.87/cu ft | $2.40/cu ft | $0.30 |
  | 小号大件 | $1.00 | $0.56/cu ft | $1.40/cu ft | $0.40 |
  | 中号大件 | $2.00 | $0.56/cu ft | $1.40/cu ft | $0.40 |
  | 大号大件 | $3.00 | $0.56/cu ft | $1.40/cu ft | $0.50 |

  脚本根据 `datetime.now().month` 自动选择仓储费率（1-9月 vs 10-12月旺季）。

  **成本逐项计算（11 项全量成本）：**

  1. **1688采购成本(USD)** = 1688价格(¥) / 汇率
  2. **亚马逊佣金** = 售价 × referralFeePercentage / 100
  3. **广告费** = 售价 × nicheTACoS（来自 S3，无数据时回退 adTACoS）
     - **零广告策略判断**：先调用 `linkfox-sif-asin-summary` 获取 `sponsoredProductsKeywordCount`，若为 0 则广告费 = $0（该 ASIN 无人投广告），不使用 nicheTACoS
  4. **COGS（采购与头程成本）** = 1688采购成本(USD) + FBA头程
  5. **退款管理费** = 亚马逊佣金 × 20%
  6. **弃置费** = FBA 费率表自动查表（含在退货损失中，不单独计入总成本）
  7. **单笔退货亏损** = FBA配送费 + 退款管理费 + COGS + 弃置费
  8. **每件预期退货损失** = 退货率 × 单笔退货亏损（退货率来自 S3，无数据时用默认 15%）
  9. **月度仓储费** = (L×W×H mm³ / 28316846.6) × 仓储费率（自动查表 + 旺季判断）
  10. **入库配置费** = FBA 费率表自动查表
  11. **FBA头程** = fbaHeadCost（默认 $3.00/件）

  **净利润计算：**
  - 总成本 = 1688成本 + FBA配送费 + 佣金 + 广告费 + 预期退货损失 + 仓储费 + 入库配置费 + FBA头程
  - **净利润** = 售价 - 总成本
  - **净利润率** = 净利润 / 售价 × 100%

  每个 ASIN 取 1688 最低价货源计算"最优利润"。

  **脚本调用：**
  ```bash
  python scripts/step_4_calc_profit.py \
      --keepa-files <S1a输出.json> \
      --keepa-history-file <S1b输出.json> \
      --alibaba-files <S2输出.json> \
      --market-metrics-file <S3输出.json> \
      --niche-keyword "<S3匹配的niche关键词>" \
      --exchange-rate 7.2 \
      --fba-head-cost 3.0
  ```

- **输出**：合并后的 JSON 数组，每条含：
  - `asin` / `title` / `category` / `price` / `bsr` / `rating`
  - `price_source` — 售价来源（"keepa_buybox_normal" 或 "keepa_product_detail"）
  - `cost_1688` — 1688 采购成本(USD)
  - `fba_fees` — FBA 配送费
  - `referral_fee` — 佣金
  - `ad_cost` — 广告费
  - `cogs` — 采购与头程成本
  - `refund_admin_fee` — 退款管理费
  - `disposal_fee` — 弃置费（自动查表）
  - `single_return_loss` — 单笔退货亏损
  - `expected_return_loss` — 每件预期退货损失
  - `storage_fee` — 月度仓储费（自动查表 + 旺季判断）
  - `inbound_placement_fee` — 入库配置费（自动查表）
  - `fba_head_cost` — FBA 头程
  - `total_cost` — 总成本
  - `net_profit` — 净利润($)
  - `net_margin` — 净利润率(%)
  - `return_rate_pct` / `niche_tacos` — 使用的退货率和 TACoS
  - `return_rate_source` / `tacos_source` — 数据来源标注（"niche_matched" 或 "default"）
  - `products_1688` — 3 个供应商明细数组

- **用途**：为 S5 报告生成提供全部利润数据

- **落盘**：合并结果落盘到 `data/profit_analysis.json`

- **错误降级**：某个 ASIN 的数据缺失时，该 ASIN 的利润字段标为 null，在报告中标注"数据不完整"。未传入 --keepa-history-file 时，售价回退用 Keepa 商品详情的 price 字段并在 stderr 输出警告。

## 用户决策与重新核算（S4.5）

S4 初步核算完成后，**必须**进入用户决策环节——因为利润核算的准确性依赖于用户手动确认的货源价格和头程成本。

### 流程

1. **展示初步结果**：把 S4 的净利润结果展示给用户，标注"基于 AIGC 初步筛选货源，请确认后重新核算"
2. **用户确认/修改**：
   - **1688 货源确认**：从 B1+B2 候选中选择真正要采购的供应商，或手动输入不在候选列表里的货源价格(¥)
   - **FBA 头程确认**：用户输入准确的头程成本（默认 $3.0，用户可能知道更准确的物流报价）
   - **其他参数确认**（可选）：汇率、退货率、ACoS 等
3. **重新核算**：用户修改后，用确认的参数重新运行 `step_4_calc_profit.py`，通过 `--exchange-rate` / `--fba-head-cost` 等命令行参数传入用户确认值
4. **持久化长期固定参数**：用户确认的长期不变参数写入专家级 `MEMORY.md`，下次 agent 自动读取并传入脚本

### 长期固定参数存储

用户确认的参数分两类：
- **长期固定参数**（跨 ASIN 通用，如固定汇率 7.2、头程报价 $2.8）：写入专家级 `MEMORY.md`，agent 下次调用脚本时自动用记忆里的值传 `--exchange-rate` / `--fba-head-cost`
- **单次参数**（仅当前 ASIN，如本次确认的货源价格 ¥2.5）：不持久化，仅本次核算使用

### 重新核算脚本调用

```bash
python scripts/step_4_calc_profit.py \
    --keepa-files <S1a输出.json> \
    --keepa-history-file <S1b输出.json> \
    --alibaba-files <S2输出.json> \
    --market-metrics-file <S3输出.json> \
    --niche-keyword "<关键词>" \
    --exchange-rate 7.2 \
    --fba-head-cost 2.8
```

agent 读取 `MEMORY.md` 中的长期固定参数，替换默认值传入脚本。报告中标注哪些参数使用了用户确认值。
