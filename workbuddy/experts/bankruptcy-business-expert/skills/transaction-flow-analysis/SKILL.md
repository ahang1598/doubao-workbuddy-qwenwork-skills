# 交易流水分析（transaction-flow-analysis）

## M1 法律合规与风险声明

### 适用法域

本技能仅适用于**中华人民共和国大陆地区**（不含港澳台）的法律体系。涉及跨境交易或境外法律适用时，须明确声明并提示用户寻求专业意见。

### 风险等级：L2（中等风险）

交易流水分析涉及金额认定和法律定性判断，分类标注遗漏可能影响案件策略。所有输出均为**分析参考**，需律师复核后方可使用。涉及法律定性时（如"该备注'劳务费'可能不构成工资"），必须联网验证引用法条（§17.15强制契约）。

### SOFT_DEGRADED 降级机制

当输入信息不足时（如只有截图描述、交易记录不完整），保证最小骨架产出：

```
C (Core - 必须产出):
  ├── 已识别交易的分类标注（标注置信度）
  ├── 异常信号初步标记
  └── 下一步行动建议

D (Governance - 治理禁区):
  └── 免责声明（本报告由AI辅助生成，不构成审计意见或鉴定结论）

G (Guidance - 行动指引):
  └── 待补充交易清单 + 数据源完善建议 + 律师复核建议
```

降级强度：S1（仅C+D+G）→ S2（+数据概览与渠道分布）→ S3（接近完整但关键金额认定标注待核实）

## M2 快速开始

**最小输入示例**：

```
请分析以下银行流水，案件类型：民间借贷

2024-01-15 微信转账 张三 50000 支出 备注：借款
2024-03-20 银行转账 李四 30000 收入 备注：还款
2024-06-10 微信转账 张三 25000 支出 备注：借款
```

**预期输出**：HTML分析报告，含金字塔结论摘要、六要素核心发现、资金流向拓扑图、证据交叉引用。

**一句话定位**：多渠道流水进来，按案件类型自动分析，异常信号一目了然。

## M3 核心参数与法律约束

> **命名约定**：本章节使用中文编号指代 SKILL.md 顶层板块（M1 法律合规 / M2 快速开始 / M3 核心参数 / ... M7 工作流）。输入模式使用 `IM1`/`IM2`/`IM3` 前缀（Input Mode），与章节编号 M1-M7 区分。

### 三种输入模式（IM1-IM3）

| 模式 | 输入形态 | 置信度 | 适用场景 |
|------|----------|--------|----------|
| **IM1** 结构化 | 已导出CSV/Excel + 来源渠道标注 | high | 有银行/微信/支付宝导出文件 |
| **IM2** 半结构化 | 手动整理的交易列表 | medium | 从截图中手动整理的关键交易 |
| **IM3** 自然语言 | 口头描述交易记录 | low | 当事人只有口述信息 |

### 案件类型（CT1-CT6）

| # | 类型ID | 类型名称 | 族 | 能力层 | 核心分析维度 |
|---|--------|---------|-----|--------|-------------|
| CT1 | marriage-family | 婚姻家事 | 财产归属 | A | 归属分类/异常转移检测 |
| CT2 | labor-dispute | 劳动争议 | 劳动保护 | A | 工资标准确认/欠薪计算 |
| CT3 | private-lending | 民间借贷 | 债权债务 | B | 本息追踪/还款认定 |
| CT4 | contract-dispute | 合同纠纷 | 债权债务 | B | 履约验证/逾期计算 |
| CT5 | criminal-defense | 刑事辩护 | 刑事涉案 | C | 金额区间/流向拓扑 |
| CT6 | enforcement | 执行追索 | 执行财产 | B | 消费画像/财产线索 |

> 详细类型配置见 [templates/case-types/](templates/case-types/) 下 CaseTypeSpec 文件

### 案件类型族分类

| 族名 | 包含类型 | 共性特征 |
|------|---------|---------|
| **财产归属族** | CT1 | 共同/个人财产区分，转移行为识别 |
| **劳动保护族** | CT2 | 工资/加班费/报销分类，标准确认 |
| **债权债务族** | CT3, CT4 | 本金/利息/还款/逾期计算，合同履行验证 |
| **刑事涉案族** | CT5 | 涉案金额区间，资金流向拓扑，主观明知推定 |
| **执行财产族** | CT6 | 消费画像，财产线索发现 |

### 能力分层

| 层级 | 类型 | 成熟度评估 | 产品策略 |
|------|------|-----------|---------|
| **A类（高模板化）** | CT1, CT2 | 分类标准明确、法规依据清晰 | 标准输出 |
| **B类（中复杂）** | CT3, CT4, CT6 | 需多种计算逻辑、分类有争议空间 | 标准校验+置信度标注 |
| **C类（高风险）** | CT5 | 涉及刑事定性、金额区间直接影响量刑 | 强制律师复核 |

### 核心数据结构

所有输入归一化为 `NormalizedTransaction`：

```
NormalizedTransaction {
  transaction_date: datetime       // 交易时间
  direction: "收入" | "支出"        // 收/支
  amount: decimal                  // 金额（元）
  counterparty: string             // 对方名称/昵称
  counterparty_account: string     // 对方账号（如有）
  remark: string                   // 备注/摘要/商品说明
  channel: "bank" | "wechat" | "alipay"  // 来源渠道
  channel_raw_type: string         // 渠道原始交易类型
  balance_after: decimal | null    // 交易后余额（银行流水特有）
  source_position: string          // 来源位置标注（文件+行号）
  confidence: "high" | "medium" | "low"  // 数据置信度
}
```

> 完整输入规格见 [references/input-spec.md](references/input-spec.md)

## M4 输出格式与质量标准

### 输出：HTML可视化分析报告（v3.0 仅HTML）

**唯一输出格式**：HTML（C-Professional级），即开即用顶级律所级排版。

**报告结构（10区块）**：

```
第1页：执行概览
  S1 报告头（机密标记+标题+元数据）
  S2 结论摘要（金字塔模型：核心结论→3条关键发现→策略建议）
  S3 数据快照（4统计卡片+分析区间/渠道/风险等级）

第2页起：详细发现
  S4 核心发现（六要素卡片：事实叙事→数据锚点→法律分析→对方可能抗辩→策略影响评估→诉讼策略建议）
  S5 资金流向拓扑（Mermaid图+流向分析4条）
  S6 对手方分析（8列表格，高风险行高亮）
  S7 异常信号登记（7列表格，L1/L2/L3严重度分级）

末页：证据与治理
  S8 证据附件（3个可折叠区：分类明细/对手方排行/异常明细，含"关联发现"跳转链接）
  S9 分析限制与敏感度（数据完整性进度条+关键假设+敏感度分析+律师复核清单6项）
  S10 页脚（免责声明+报告元数据+自动页码）
```

**v3.0核心变更**：
- 移除Markdown输出通道，统一为HTML
- 核心发现从四要素升级为六要素（+对方可能抗辩+策略影响评分）
- 结论摘要升级为金字塔模型（一行核心结论+3条影响标注发现+策略建议）
- 新增 CRITICAL / SIGNIFICANT / NOTEWORTHY 影响分级
- 法条分析从"编号+要旨"升级为"编号+要旨+本案适用分析"
- 全面CSS重写（深海军蓝配色体系/4px间距网格/6级排版尺度/A4打印优化）

### 置信度标注标准

| 等级 | 标识 | 含义 | 触发场景 |
|------|------|------|----------|
| 高 | 🟢 | 分类明确，备注信息与交易模式一致 | 备注"工资"+每月固定金额+对公账户 |
| 中 | 🟡 | 分类合理但存在其他可能 | 备注"劳务费"但可能是工资或报销 |
| 低 | 🔴 | 分类基于推断，需律师核实 | 无备注+金额整数+对方为个人 |

### 写作红线

- ❌ 编造交易记录或推断不存在的交易
- ❌ 对交易性质作出确定性法律判断（如"此笔为转移财产行为"）
- ❌ 声称分析结果可替代审计意见或鉴定结论
- ❌ 基于备注推断的分类不标注置信度
- ❌ 遗漏异常信号的标注
- ❌ 在法律依据不确定时不标注需核实
- ❌ 将跨渠道的重复交易重复计入统计
- ❌ 金额汇总不列出计算过程
- ❌ **v2.0** 核心发现不含法条编号和条文要旨
- ❌ **v3.0** 核心发现只是一张分类表（必须为六要素完整法律叙事）
- ❌ **v3.0** 结论摘要金字塔不完整（缺核心结论/影响标签/策略建议任一项）
- ❌ **v3.0** 行动建议不达操作级（无具体法院/文书类型/调取对象/时间窗口）
- ❌ **v3.0** C类案件（CT5）给出确定性金额认定
- ❌ 将银行记账方向直接作为用户视角方向——银行"借"=用户支出，"贷"=用户收入，必须反转
- ❌ **v3.0** 核心发现遗漏对方可能抗辩及应对
- ❌ **v3.0** 核心发现遗漏策略影响评估表
- ❌ **v3.0** 核心发现无影响标签（CRITICAL/SIGNIFICANT/NOTEWORTHY）
- ❌ **v3.0** 证据锚点无具体行号引用

> 完整输出规格见 [references/output-spec.md](references/output-spec.md)

## M5 适用场景与不适用场景

### 适用场景

1. **"帮我分析离婚案中的银行流水"**：区分共同/个人财产，查找异常转账
2. **"帮我算拖欠了多少工资"**：从流水中提取工资发放记录，计算欠薪
3. **"帮我追踪这笔借款的本息"**：借贷案中逐笔匹配本金/利息/还款
4. **"看看合同履行期间有没有违约付款"**：合同纠纷中验证履约情况
5. **"涉案金额区间是什么"**：刑事案中梳理资金流向和金额区间
6. **"被执行人有没有隐匿财产"**：执行案中分析消费和财产线索

### 不适用场景

| 场景 | 原因 | 替代方案 |
|------|------|----------|
| 生成正式审计报告 | 本技能产出为内部工作文件 | 委托司法会计鉴定 |
| 银行流水PDF OCR解析 | 当前不支持（P2后续扩展） | 手动整理后输入 |
| 税务合规分析 | 超出技能范围 | 使用税务分析工具 |
| 跨境交易分析 | 法域限制 | 寻求当地专业意见 |
| 截图→结构化数据自动提取 | 当前不支持（P2后续扩展） | 手动整理关键交易后输入 |

## M6 核心原则

1. **法律含义优先**：所有交易分类标签必须附带法律要件说明，不能只是技术标签（如"大额转账"需标注为"疑似转移财产——离婚前1年内向特定关系人大额转出"）
2. **不确定性必标**：基于备注推断的性质分类必须标注置信度（高/中/低），禁止将推断性结论呈现为确定性事实
3. **降级不拒绝**：输入不完整时输出可识别部分+待补充清单（C+D+G），不拒绝处理
4. **案件类型驱动**：同一笔交易在不同案件类型下有不同法律含义（如"备注劳务费"在劳动案中是工资争议焦点，在借贷案中只是还款备注），必须按案件类型路由到正确分析框架
5. **法条强制验证**：涉及法律定性的分析结论必须联网验证引用法条（§17.15），禁止编造法条编号
6. **金额可复核**：所有汇总金额必须列出计算过程（逐笔累加），允许律师独立核实
7. **渠道不混同**：银行/微信/支付宝三种渠道的交易特征差异显著（银行有余额、微信有转账类型、支付宝有商品说明），归一化后保留渠道原始信息
8. **对手方可追溯**：每个对手方标注推断依据（备注信息/交易频率/金额模式），不编造关联关系
9. **异常有阈值**：异常检测规则必须量化（如"大额"=月收入3倍或5万元以上），禁止使用模糊描述
10. **禁止硬编码工具**：遵循§17.6，法条检索引用使用白名单工具，不绑定具体工具名
11. **叙事优先，表格为附件**：核心发现必须是法律叙事（六要素），数据表格退居证据附件。禁止将分类汇总表贴入核心发现
12. **结论先行，30秒可判断**：结论摘要金字塔位于报告最前方。律师可在30秒内判断本分析的价值
13. **探索式分析，非一次性出报告**：P3后输出第一轮概览（I1），律师选择深化方向后再执行P4/P5深度分析
14. **外部参考数据驱动精度**：case_context（合同付款节点/借款本金/约定工资等）加载后，P3/P4/P5的分析精度、异常敏感度、追踪深度自动提升
15. **对抗性思维内置**（v3.0新增）：每个核心发现必须分析"对方可能抗辩"及应对策略。顶级律师看流水不只是看事实，更是预判对方如何利用同一份流水反驳
16. **策略影响可见**（v3.0新增）：每个发现附带CRITICAL/SIGNIFICANT/NOTEWORTHY影响标签+策略影响评估表（对诉讼请求/举证责任/和解谈判的具体影响）
17. **法条分析达适用层**（v3.0新增）：法条引用须达三层——编号准确→条文要旨清晰→本案适用分析（条文如何适用于本案具体事实）
18. **行动建议达操作级**（v3.0新增）：诉讼策略建议必须含具体法院/文书类型/调取对象+账号/时间窗口，不可停留在"建议进一步调查"层

## M7 Phase工作流概览

### v3.0 两阶段探索式流程

```
输入 → P1验证 → P2归一化+路由+case_context → P3初步分类(L3)
                                                    ↓
                                          ┌── 交互点I1 ──┐
                                          │ 第一轮概览:     │
                                          │ 数据快照+TOP5  │
                                          │ 异常+建议方向   │
                                          │ 用户选择深度    │
                                          └────────────────┘
                                                    ↓
                              P4深度异常(L2) → P5深度流向(L2) → P6 10区块HTML组装 → 输出
```

| Phase | 名称 | 风险等级 | 输入 | 输出 | 关键动作 |
|-------|------|----------|------|------|----------|
| P1 | 输入验证与渠道识别 | L1 | 原始输入 | 验证结果+渠道清单 | 识别输入形态IM1/IM2/IM3，判定渠道类型 |
| P2 | 数据归一化+路由+**case_context** | L1 | 验证后输入+参考数据 | NormalizedTransaction+case_context+CaseType | v2.0新增：构建6案型结构化参考数据 |
| P3 | 按案件类型交易分类 | **L3** | NormalizedTransaction+CaseTypeSpec+case_context | 分类标注结果 | case_context提升分类精度（如知道工资标准→自动识别工资） |
| **I1** | **第一轮概览与方向确认** | L2 | P3分类结果 | 概览+用户选择 | v2.0新增：数据快照+TOP5异常+3个建议深入方向 |
| P4 | 异常模式检测 | L2 | 分类结果+case_context+I1选择 | 异常信号清单 | case_context提升敏感度（如知道约定付款日→精确计算逾期天数） |
| P5 | 对手方与资金流向分析 | L2 | 分类+异常+case_context+I1选择 | 对手方分析+流向拓扑 | case_context控制追踪深度（CT5追踪3层，CT1追踪1层） |
| P6 | 报告组装与质量检查 | L1 | 全部分析结果+I1选择 | HTML报告（v3.0：10区块完整结构） | v3.0：金字塔结论+六要素发现+证据交叉引用+影响分级 |

> 详细工作流见 [references/workflow-detail.md](references/workflow-detail.md)

### FAST_TRACK 条件

当同时满足以下条件时，跳过I1与P3-P5深度分析，直接输出简化报告：
- 交易笔数 ≤ 10笔
- 单一渠道
- 用户明确要求"快速概览"

### 输入输出概要

```
输入 → [P1 验证] → [P2 归一化+路由+case_context] → [P3 分类(L3)]
                                                          ↓
                                                   [I1 概览(L2)]
                                                          ↓
                                              [P4 异常(L2)] → [P5 流向(L2)] → [P6 10区块组装] → HTML报告
                                                                                      ↑
                                                                            SOFT_DEGRADED判定
```
