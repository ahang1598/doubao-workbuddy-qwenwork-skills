# 质量标准

> bankruptcy-case-portfolio-management 技能的质量检查清单

---

## 1. 阻断检查项（违反即阻断）

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| B1 | 案件目录结构完整 | 对比程序类型模板，检查必需目录是否全部创建 |
| B2 | case-meta.yaml 字段完整 | 检查 case_id/debtor_name/procedure_type/current_stage 必填字段 |
| B3 | 文件复制完整 | 对比 source_paths 文件数与目标目录文件数 |
| B4 | 索引台账包含所有案件 | 扫描 workspace_root，对比台账案件数与实际目录数 |
| B5 | 期限看板预警分级正确 | 抽查3个期限节点，验证预警级别计算正确 |
| B6 | 禁止虚构案件信息 | 抽查台账中案件信息，与 case-meta.yaml 对比 |
| B7 | 禁止替代管理人决定 | 检查输出中是否包含债权确认/分配方案提交等越权表述 |
| B8 | 期限预警分级未省略 | 检查期限看板是否包含红黄绿三级预警 |

---

## 2. 警告检查项（违反需提示）

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| W1 | 案号格式规范 | 检查是否符合法院案号格式（如"（2026）粤03破申123号"） |
| W2 | 日期格式统一 | 检查是否为 YYYY-MM-DD 格式 |
| W3 | 团队角色规范 | 检查是否在枚举范围内（负责人/成员/助理/外部顾问） |
| W4 | 程序类型路由正确 | 检查目录结构是否与程序类型匹配 |
| W5 | 阶段切换记录完整 | 检查 progress-tracker 是否记录所有阶段切换 |
| W6 | 更新日志完整 | 检查是否记录所有 INIT/UPDATE 操作 |
| W7 | 债务人简称提取正确 | 检查是否正确去除公司后缀 |
| W8 | 履职完成度计算正确 | 抽查1个案件，验证完成度计算 |

---

## 3. 输出质量检查

### 3.1 目录结构质量

| 检查项 | 标准 |
|--------|------|
| 目录层级 | 不超过3层 |
| 目录命名 | 使用中文，不含特殊字符 |
| 目录数量 | 通用7个+特有2-4个 |

### 3.2 元数据质量

| 检查项 | 标准 |
|--------|------|
| YAML 格式 | 通过 YAML 解析器验证 |
| 必填字段 | case_id/debtor_name/procedure_type/current_stage/status |
| 日期字段 | 符合 ISO 8601 格式 |

### 3.3 台账质量

| 检查项 | 标准 |
|--------|------|
| 案件数一致 | 台账案件数 = workspace_root 案件目录数 |
| 字段完整 | 包含ID/案号/债务人/类型/阶段/团队/日期/状态 |
| 排序合理 | 按状态+立案日期排序 |

### 3.4 期限看板质量

| 检查项 | 标准 |
|--------|------|
| 预警分级 | 包含🔴/🟠/🟡/🟢四级 |
| 剩余天数 | 计算准确 |
| 排序合理 | 按预警级别+剩余天数排序 |

---

## 4. 用户满意度检查

| 检查项 | 标准 |
|--------|------|
| 操作计划清晰 | 用户能明确理解将执行的操作 |
| 制品清单完整 | 用户能清楚看到所有生成制品 |
| 期限提示及时 | 临期期限能第一时间引起注意 |
| 多案件视图直观 | 用户能快速掌握多案件全貌 |

---

## 5. 与 agent 协同质量

| 检查项 | 标准 |
|--------|------|
| 输出格式兼容 | YAML/Markdown 可被 agent 正确解析 |
| 状态持久化 | 案件状态正确写入文件系统 |
| 边界清晰 | 不越权替代管理人决定 |
| 协同顺畅 | agent 调用后能正确读取制品 |
