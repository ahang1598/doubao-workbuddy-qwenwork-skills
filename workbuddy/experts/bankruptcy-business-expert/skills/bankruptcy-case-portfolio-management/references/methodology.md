# 方法论

> bankruptcy-case-portfolio-management 技能的核心方法论与隐性知识

---

## 1. 核心方法论

### 1.1 多案件工作空间标准化

**问题**：破产管理人同时承办多案件，材料分散、结构不一、难以统一管理和检索。

**方法**：建立标准化案件工作空间，按程序类型路由目录结构，统一元数据格式，实现多案件集中管理。

**关键设计**：
- **程序类型路由**：破产清算/重整/和解三套目录模板，反映不同程序的法定流程差异
- **通用+特有目录**：7个通用目录（接管/债权/财产/会议/履职/程序/底稿）+ 2-4个特有目录
- **元数据锚定**：`case-meta.yaml` 作为案件唯一事实源，所有制品从中读取或向其写入

### 1.2 多案件索引台账

**问题**：管理人难以快速回答"我手头有哪些案件/各到哪个阶段/谁来负责"。

**方法**：维护多案件索引台账，提供清单+看板+筛选三重能力。

**关键设计**：
- **清单**：完整案件列表，含ID/案号/债务人/类型/阶段/团队/日期/状态
- **看板**：按类型/阶段/团队三维度分布统计
- **筛选**：支持按债务人/案号/阶段/团队/程序类型组合筛选

### 1.3 跨案期限看板

**问题**：多案件期限节点分散，容易遗漏关键期限（如债权申报截止、债权人会议、重整计划提交）。

**方法**：跨案期限看板，集中展示所有案件期限节点，按预警级别分级。

**关键设计**：
- **节点类型**：债权申报截止/第一次债权人会议/重整计划提交截止/分配方案公告/履职报告提交
- **预警分级**：已逾期(🔴)/临期7日内(🟠)/即将到期30日内(🟡)/正常(🟢)
- **排序规则**：按预警级别+剩余天数排序，最紧急的在前

### 1.4 法定履职节点锚定

**问题**：管理人履职是否到位缺乏统一检查标准，容易出现程序瑕疵。

**方法**：以企业破产法第25条等法定职责为锚点，建立履职节点检查清单。

**关键设计**：
- **通用节点**：接管/财产调查/债权审查/会议筹备/报告提交
- **程序特有节点**：清算（变现方案/分配执行）、重整（经营方案/重整计划/投资人招募）、和解（和解协议/执行监督）
- **完成度计算**：已完成节点数/总节点数

## 2. 隐性知识

### 2.1 案件ID生成策略

**推荐格式**：`BANK-{年份}-{序号}`（如 `BANK-2026-001`）

**理由**：
- 人读友好，易于口头引用
- 年份区分便于年度统计
- 序号自动递增，避免冲突

**冲突处理**：检测到ID冲突时，提示用户确认覆盖或自动递增序号。

### 2.2 债务人简称提取

**规则**：
- 去除"有限公司"/"股份有限公司"/"有限责任公司"等后缀
- 保留核心字号（如"XX科技"/"XX房产"）
- 用于目录命名，避免过长

**示例**：
- `XX科技有限公司` → `XX科技`
- `XX房地产开发有限公司` → `XX房产`

### 2.3 期限预警阈值设定

**依据**：
- **临期7日**：债权申报截止前7日需重点跟进未申报债权人
- **即将到期30日**：重整计划提交截止前30日需启动草案编制
- **已逾期**：任何法定期限逾期即构成程序瑕疵，需立即补救

**调整空间**：用户可根据法院要求或案件复杂度调整阈值。

### 2.4 履职完成度计算

**权重设计**：
- 接管/债权审查/财产调查：核心节点，权重高
- 会议筹备/报告提交：程序节点，权重中
- 分配执行/重整执行：结果节点，权重高

**简化处理**：v1.0 采用等权重（完成数/总数），后续版本可引入加权。

### 2.5 团队任务分配矩阵

**目的**：解决多案件多成员的任务冲突和负载均衡。

**矩阵设计**：
- 行：团队成员
- 列：案件
- 单元格：任务列表
- 合计：成员任务总数

**风险提示**：同一成员任务数超过5件时提示负载过高。

### 2.6 多案件利益冲突审查规则

破产管理人同时承办多案件时须进行利益冲突审查：

**冲突类型**：
1. **同案对立方**：一家律所同时担任债务人的管理人和主要债权人的代理人（绝对禁止）
2. **跨案竞争方**：A案件债务人与B案件主要债权人为同一集团/关联方（须披露并获各方同意）
3. **债务人关联企业**：同时管理债务人及其子公司/母公司（可能发生财产混同，影响独立性）
4. **重整投资人冲突**：A案件重整投资人与B案件债务人存在竞争关系（须评估对两案的影响）

**审查机制**：
- 接案前：查询已承办案件的债务人/债权人/投资人清单
- 新增客户时：交叉比对利益冲突数据库
- 定期巡检：每月检查案件组合中的潜在冲突

**处理路径**：
- 绝对利益冲突→拒绝接案
- 可调和冲突→书面披露→获取各方知情同意→备案
- 存疑→提交法院审查

### 2.7 案件优先级动态排序

**排序维度（四维加权）**：
1. **法定期限压力（权重40%）**：最近期限剩余天数越少，优先级越高
2. **风险等级（权重30%）**：高（职工安置/在建工程处置/大额担保债权争议）> 中（常规债权审查/分配方案）> 低（一般性程序事务）
3. **成果产出关键度（权重20%）**：即将产出的成果对后续阶段的阻塞程度（如分配方案依赖债权审查完成）
4. **管理人资源占用（权重10%）**：已占用资源过多但进度落后的案件→优先级提升

**排序算法**：
```
priority_score = 0.4×(1-剩余天数/法定期限) + 0.3×risk_level + 0.2×output_blocking + 0.1×resource_strain
```
- 得分越高→优先级越高
- 同分按法定期限升序（越紧急排前面）

**颜色标注**：🔴 紧急（<7日）| 🟠 高优 | 🟡 中优 | 🟢 常规

## 3. 常见错误与防范

| 错误 | 后果 | 防范 |
|------|------|------|
| 案件ID重复 | 数据混乱 | 自动检测+用户确认 |
| 期限节点遗漏 | 程序瑕疵 | 模板预置+用户补充 |
| 程序类型误判 | 目录结构错误 | 用户确认+材料辅助识别 |
| 阶段更新滞后 | 进度跟踪失真 | 每次操作后自动更新 |
| 台账未同步 | 多案件视图失真 | 每次操作后自动重新生成 |

## 4. 与 bankruptcy-business-expert 的协同

```
用户：建案/查案/期限/进度/履职汇总
        ↓
bankruptcy-business-expert（主 Agent）
  识别意图 → 调用本技能执行文件系统操作
        ↓
bankruptcy-case-portfolio-management（本技能）
  INIT/UPDATE/PORTFOLIO/DEADLINE/PROGRESS/DUTY_SUMMARY
  读写案件工作空间（文件系统）
        ↓
返回结构化结果 → agent 编排报告/提示用户
```

**协同要点**：
- 主 Agent 负责门控、调度、报告编排
- 本技能负责案件工作空间的物理管理
- 主 Agent 不存储案件状态，状态持久化到文件系统由本技能完成
