# 法规检索场景选择

## 核心原则

法律法规检索先判断对象类型，再决定 scene。不要默认把用户问题改写成短关键词。

检索结果按“目标对象”和“相关依据”分层处理。精确对象不一致时不能写成精确命中，但可以展示与问题局部相关、主题相近或能辅助解释的依据，避免把有参考价值的结果直接丢弃。

必须原样保留：

- 法规、司法解释、规范性文件名称
- 条号、款项、项号
- 发文字号、发布机关
- 发布日期、实施日期、用户指定的参考日期
- “现行有效”“已废止”“当时有效”等时效要求

## scene 选择

skill 只根据法律检索任务选择 scene。

| scene | 适用条件 | 检索内容建议 |
| --- | --- | --- |
| `law_article_exact` | 同时出现法规名/司法解释名和条号 | 原始法规名 + 原始条号 |
| `law_statute_exact` | 用户要定位整部法规、司法解释、规范性文件 | 原始法规名或文件名；保留发布机关、发文字号 |
| `law_semantic` | 用户问法律依据、规则、适用边界、法律评价，或某部法中某个主题/概念的规定 | 法律专业改写后的完整自然语言表达 |

## 字段处理边界

skill 负责判断 scene，并在非语义 scene 下给出已确定的 `structuredFields`。检索服务负责字段校验、数据商字段映射和结果一致性校验。

字段规则：

- 字段抽不准就省略，不要为了字段完整编造法规全称、条号、发文字号或参考日期。
- 非语义 scene 缺少必填字段时，改用 `law_semantic`，保留改写后的 `searchContent`；不要硬填字段去满足工具入参。
- `law_article_exact` 至少需要 `lawTitle` 和 `articleNo`；缺任一字段时不要当成已完成精确法条定位。
- `law_article_exact` 可选 `referDate`；仅当用户明确给出完整年月日时传入，格式为 `YYYY-MM-DD`。不得根据“现行”“最新”、单独年份或当前日期自行生成；该场景不传 `effectiveness`。
- `law_statute_exact` 必须给出 `lawTitle`；可选 `effectiveness`、`effectLevel`、`region`。`documentNo` 和 `issuingAuthority` 原样保留在 `searchContent` 中，只用于结果核验，不传入 `structuredFields`。文件内主题、法律概念或具体规则问题改走 `law_semantic`。
- `effectiveness`仅在用户明确指定某一效力状态作为筛选条件时填写。用户要求查询、核验或说明效力状态时不得预设该字段。
- `law_semantic` 不传 `structuredFields`，改写后的完整自然语言表达是唯一检索内容。

## 字段格式和枚举

- `effectiveness` 支持：`现行有效`、`失效`、`已被修改`、`部分失效`、`尚未生效`。
- `effectLevel` 支持：`宪法`、`法律`、`司法解释`、`行政法规`、`监察法规`、`部门规章`、`党内法规`、`军事法规规章`、`立法机关工作文件`、`行政机关工作文件`、`行业/团体规范`、`地方性法规`、`自治条例和单行条例`、`地方司法文件`、`地方政府规章`、`地方规范性文件`、`地方律协规定`。
- `region` 使用 `中央` 或省级行政区简称；最高层级使用 `最高`，新疆生产建设兵团使用全称。
- 不传 `top_k`，由检索服务使用默认值。

容易误判的边界：

- 有法规名和条号，走 `law_article_exact`；不要只拿条号检索。
- 有法规名但问文件内主题、法律概念或具体规则，走 `law_semantic`；例如“公司法中刺破法人面纱的规定”，应改写为“公司法中关于股东滥用公司法人独立地位和股东有限责任、损害债权人利益并承担连带责任的法律规定”。
- 只有条号但没有法规对象，走 `law_semantic`，并提示需要确认法规名称。
- 问“依据是什么、怎么认定、能不能主张”，通常走 `law_semantic`，使用法律专业改写后的完整自然语言表达。

## 示例

| 用户问题 | scene | 说明 |
| --- | --- | --- |
| 检索现行有效的民诉法解释第二十七条 | `law_article_exact` | 有法规名简称和条号 |
| 人社部关于企业实施竞业限制合规指引的通知 | `law_statute_exact` | 定位整部规范性文件 |
| 公司法相关的刺破法人面纱的法规 | `law_semantic` | 已知法规名但问题指向法律概念和具体规则 |
| 竞业限制补偿金没约定还能主张吗？ | `law_semantic` | 开放式法律依据问题 |
| 民法典施行前，保证合同效力怎么认定？ | `law_semantic` | 需要历史版本和规则判断 |
| 第二十七条怎么规定？ | `law_semantic` | 缺少法规对象，不能直接当精确法条 |

## 结果处理

- `law_article_exact` 返回后，必须核对法规名、条号、时效要求。任一核心对象不一致，目标对象按未命中处理；若返回相邻条文、同一法规其他条文或主题相关规范，可以另列“相关依据”，说明差异。
- `law_statute_exact` 返回后，必须核对法规或文件名称；名称不完整或只命中近似文件时，可以说明“按名称检索得到相关规范”，但不能说已经精确命中。
- `law_semantic` 返回的是法律依据候选，不等于唯一答案；输出时要说明适用前提，并优先保留能直接回答问题的依据。
## 版本和时效复核

出现以下信息时，把版本复核作为必做步骤：

- 用户说“现行有效、最新、当前、尚未生效、已废止、当时有效”。
- 用户给出具体日期、施行日期、发布年份或历史版本。
- 检索结果同时出现现行版本、已被修改版本、修订决定、草案或解释性文件。

处理规则：

- 先确认目标法规当前是否存在现行版本，再确认目标条文在该版本中的条号和内容。
- 只命中修订决定时，不直接把修订决定当成完整现行条文；继续查被修改后的法规本体。
- 当前版本能定位法规但条文详情不可得时，写明“已定位现行版本，但当前检索未取到目标条文详情”，再列可取到的历史条文或相关依据。
- 用户问历史版本时，使用用户指定日期或版本，不用现行法覆盖历史问题；必要时并列说明现行法变化。

## 按需复查

默认一次检索；只有指定法条/法规未命中、版本时效无法核清、或结果明显不能支撑回答时，最多再检索一次。普通开放式问题不要为了增加材料而复查。
已定位目标法规，但返回结果缺少施行日期、失效日期或其他附加信息时，不为补齐单个字段继续检索；目标法规本身未确认或版本时效无法判断时，才进行一次复查。

| 现象 | 处理 |
| --- | --- |
| 精确法条未命中 | 保留未命中结论，再用完整问题走 `law_semantic` 查相关依据 |
| 精确法规未命中 | 保留原法规名或发文字号，再用文件核心名称走 `law_statute_exact` 或完整问题走 `law_semantic` |
| 只命中同一法规的其他条文 | 列为相关依据，说明目标条号未命中 |
| 开放式问题结果过宽 | 保留法律专业改写后的完整自然语言表达，加入核心法律关系、争议点、适用主体或事实条件进行二次收窄 |
| 结果集中出现不同层级依据 | 优先法律、行政法规、司法解释，再列部门规章、地方规则或规范性文件 |

补充检索不能改写或删除用户给出的法规名、条号、发文字号、日期和时效要求。

主题型问题首轮结果不足时，只做一次收窄：加入核心法律关系、争议点、适用主体或事实条件。复查结果与初次检索结果冲突时，按效力层级、时效状态、发布时间和适用地域说明差异。

## 弱结果诊断

- **结果为空**：检查法规简称是否可展开、条号是否缺法规对象、是否指定了过窄的参考日期或效力状态。
- **结果跑偏**：检查是否把开放式法律问题误走精确路径，或把文件名误压成少量关键词。
- **结果太宽**：补充主体、法律关系、争议焦点、适用地域、时间版本。
- **结果只有草案或旧法**：明确说明效力限制，不能当作现行有效依据。
- **多个依据冲突**：按层级、效力状态、发布时间和适用地域分列，不自行把冲突解释成确定结论。

## 相关依据展示规则

- 相关依据要说明“为什么相关”：同一法规、同一发布机关、同一法律关系、同一争议问题、相邻条文、同类制度。
- 相关依据要说明“哪里不一致”：法规名不同、条号不同、版本不明、地域不同、效力层级不同或只是主题相近。
- 精确查询未命中时，先写目标对象未命中，再展示相关依据；不要把相关依据放在结论里冒充目标对象。
- 如果返回结果只有很弱的主题关联，可以只列为“进一步检索线索”，不要据此给法律结论。

## 检索表达边界

`law_semantic` 始终使用完整自然语言 `searchContent`。二次收窄时补充核心法律关系、争议点、适用主体或事实条件，不把问题压缩成短关键词，也不删除法规名、条号、发文字号等定位信息。
