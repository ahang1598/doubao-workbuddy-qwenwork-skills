# 证件类型粗判 Prompt 模板（LLM 视觉）

> 本文件是 `alert-ocr` skill 的 reference，描述用 LLM 视觉能力**粗判证件类型**的 prompt 模板（Stage 1）。
> Stage 2 再按判定结果调对应的云 OCR pipeline（见 `../SKILL.md` 中“三步 pipeline”章节）。

## 执行前提（必须先满足）

- `cert_type_detection` 是识别策略标签，不是工具、脚本、函数或 MCP 名称。
- 禁止搜索 `cert_type_detection`、`LLM OCR` 或 `multimodal` 工具。
- 对当前证件的唯一 `image_local_path` 调用一次图片读取能力；返回可视图片即表示当前模型已获得像素输入。
- 图片载入后，当前模型直接执行下方 Prompt，不再寻找其他视觉能力；图片载入并不代表类型判断已经完成。
- 只有图片读取明确失败时才能提示用户重传，不得因工具列表中没有视觉工具而宣称无法识别。
- JSON 结构化失败时允许基于已载入图片重新组织结果一次，但不得重复读取同一路径。

## 目标

给一张证件图，让 LLM **只判定是 3 类中的哪一类**（不做完整 K-V 抽取，那由云 OCR 完成）：

| cert_type | 类型名 | 视觉特征 |
|-----------|-------|---------|
| `1` | 法人登记证书 |顶部标题含"社会组织法人登记证书"或"民办非企业单位登记证书"或类似；含"业务主管单位"、"业务范围"字段 |
| `2` | 慈善组织公开募捐资格证书 | 顶部含"慈善组织公开募捐资格证书"；发证机关是民政部门 |
| `3-front` | 身份证正面 | 左上"中华人民共和国"、含姓名 / 身份证号 / 头像 |
| `3-back` | 身份证反面 | 含"中华人民共和国国徽"、含有效期日期 |

**⚠️ 身份证正反面**：粗判层要能区分（后续Skill 层负责合并到同一 `idcard` 字段块）。

## Prompt模板

```
你是一个专业的证件类型识别助手。请判断我上传的这张图属于以下哪种类型：

1. cert_type=1  法人登记证书（视觉特征：顶部标题含"社会组织法人登记证书"或"民办非企业单位登记证书"，含"业务主管单位"、"业务范围"等字段）
2. cert_type=2  慈善组织公开募捐资格证书（视觉特征：顶部标题含"慈善组织公开募捐资格证书"，发证机关是民政部门）
3. cert_type=3-front  身份证正面（视觉特征：左上"中华人民共和国"，含姓名/身份证号/头像）
4. cert_type=3-back   身份证反面（视觉特征：含"中华人民共和国国徽"，含有效期日期）
5. unknown        非上述任何一类（如营业执照、其他证书、非证件图片等）

请以严格的 JSON 格式返回, 不要输出JSON 之外的任何自然语言解释：

{
  "cert_type": "1" | "2" | "3-front" | "3-back" | "unknown",
  "confidence": "high" | "medium" | "low",
  "reason": "简短理由（≤ 30 字）"
}

若图片模糊/多张证件重叠/非证件 → cert_type="unknown"，reason 说明。
不要编造。
```

## 输出解析

LLM 返回后，Skill 应做：

1. **cert_type 归一化**：`3-front` / `3-back` → 统一归为 `cert_type=3`，但**保留正反面标记**用于 Skill 层合并
2. **confidence 分支**：
   - `high` → 直接进入 Stage 2 云OCR
   - `medium` → 提示用户"识别为 X，请确认是否正确"，用户确认后再进 Stage 2
   - `low` → 提示用户手动选类型
3. **unknown 分支** → 提示"未识别为已知证件类型，请重新上传或联系客服"

## 与 Stage 2 云 OCR 的联动

粗判结果决定 Stage 2 的两个关键参数：

| cert_type | Stage 2 `private` | Stage 2 `ocr_type` |
|-----------|-------------------|--------------------|
| `1` | `0`（公有桶，CDN 域名）| `0`（非身份证）|
| `2` | `0`（公有桶，CDN 域名）| `0`（非身份证）|
| `3-front` / `3-back` | `1`（私有桶，COS 原始域名）| `1`（身份证）|
| `unknown` | 不进入 Stage 2 | 不进入 Stage 2 |

**⛔ 铁律**：`private` 和 `ocr_type` **必须与粗判结果一致**——不能出现 `private=0` 却 `ocr_type=1` 的混搭（见 `alert-ocr/SKILL.md` 相关铁律）。

## 边界处理

- 一张图里出现多个证件 → `cert_type="unknown"`，reason 说明"检测到多个证件"
- 图片非证件（如风景/文档/截图）→ `cert_type="unknown"`
- 图片过暗/模糊 → `confidence="low"`，让用户重传或手动选类型
