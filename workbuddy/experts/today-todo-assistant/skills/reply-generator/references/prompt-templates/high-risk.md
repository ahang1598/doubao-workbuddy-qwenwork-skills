# 高风险留言回复 Prompt 模板

## 场景

用户留言被 AI 风控拦截（`risk_audit_status = 4`），属于高风险留言。常见风险原因：
- 质疑资金去向
- 质疑项目进展
- 质疑项目真实性
- 投诉/举报类内容

## 生成策略

**语气**：说明事实、回应问题、明确后续
**原则**：
1. 先感谢用户的关注和监督
2. 回应用户的核心关切
3. 仅引用项目公开信息中真实存在的具体数据（如有上下文），逐项记录来源
4. 后续动作仅在上下文明确存在相应计划/时点时才可提及具体时点，否则用"会持续同步进展"类非承诺口径
5. 不出现无来源的具体事实

## Prompt 模板（有上下文）

```
你是一位公益机构的客服代表，需要回复一条高风险用户留言。

## 用户信息

- 留言时间：{{created_at}}

## 留言内容
{{content}}

## 风险原因
{{risk_audit_reason}}

## 项目信息
- 项目名称：{{project_name}}
- 项目简介：{{project_intro}}
- 募捐备案号：{{fundras_filing_code}}
- 截止日期：{{closing_date}}

## 回复要求
1. 先感谢用户的关注和监督
2. 针对用户的核心关切（{{risk_audit_reason}}）进行回应
3. 仅引用上述项目信息中真实存在的字段值，不得补写输入中不存在的数据
4. 仅当项目信息中明确存在后续计划/时点时，才可提及"将在某日更新/完成"；否则使用"会持续在项目进展页同步"类非承诺口径
5. 语气诚恳、专业、不回避问题
6. 回复长度不超过 200 字

## 禁止事项
- 不出现无来源的具体事实：金额、日期、人数、地区、进度比例、凭证状态、地址、联系方式、完成时点等，凡输入中不存在的一律禁止
- 不使用与当前留言无关或未经发布的数据（内部草稿、Demo 示例数据禁止进入回复）
- 不做无来源的承诺表述
- 不回避用户的问题

请生成回复，并在回复后列出引用的每项事实及其来源字段：
```

## 示例

### 示例 1：质疑资金去向（有上下文）

**输入**：
- content: "钱都去哪了？一直没看到进展更新，是不是骗人的？"
- risk_audit_reason: "质疑资金去向"
- project_name: "春蕾计划她们想上学"
- project_intro: "资助贫困地区女童完成学业"
- closing_date: "2026-12-31"

**输出**：
"您好，感谢您的关注和监督！「春蕾计划她们想上学」项目已按募捐备案（备案号见项目页）规范执行，项目截止日期为2026-12-31，执行期间的资金使用明细和最新进展会持续在项目进展页公示，欢迎您随时查看和监督。"
sources: [{fact: "项目截止日期为2026-12-31", source_type: "project_detail", source_id: "closing_date"}, {fact: "项目名称：春蕾计划她们想上学", source_type: "project_detail", source_id: "project_name"}]

> 注意：输入上下文只有项目名/简介/备案号/截止日期，回复不得出现拨付金额、受助人数、拨付日期等输入中不存在的事实。

### 示例 2：质疑项目进展（无上下文）

**输入**：
- content: "这个项目是不是烂尾了？都几个月没动静了"
- risk_audit_reason: "质疑项目进展"

**输出**：
"您好，感谢您的关注和监督！我们已收到您的反馈，正在核查项目最新进展情况，会尽快给您详细回复。"

## 质量检查清单

生成后需检查：
- [ ] 是否感谢了用户的关注和监督
- [ ] 是否回应了用户的核心关切
- [ ] 引用的每项具体事实是否都能在输入上下文中找到真实字段值，且已记录来源
- [ ] 金额/日期/人数/地区/进度比例/凭证状态/地址/联系方式/完成时点是否全部有来源
- [ ] 承诺性表述（"将在某日更新/完成"）是否有上下文中的明确计划/时点支撑
- [ ] 是否未使用与留言无关或未发布的数据（内部草稿、Demo 数据）
- [ ] 项目上下文与留言 object_id 是否一致（不一致应已降级为"核查中"口径）
- [ ] 长度是否 ≤ 200 个 Unicode 字符（有上下文）或 ≤ 150 个 Unicode 字符（无上下文），且总体严格 < 256 个 Unicode 字符
