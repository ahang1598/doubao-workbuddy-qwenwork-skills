# 负责人身份证 — 字段与提交

> 本文件是 `alert-cert-forms` skill 的 reference，描述**负责人身份证**（`cert_type=3`）的 K-V 字段清单、OCR ↔ proto 映射与提交前校验。
> 完整字段契约见同目录 [`tools/org_cert_update_review_input.md`](./tools/org_cert_update_review_input.md)。

## ⚠️ 归属判定（服务端行为）

`cert_type=3` 在服务端有两种归属，**由服务端按机构类型自动判定填谁**（Skill 层统一走 `idcard` 字段块，**不自行区分**）：

| 机构类型 | 服务端把 `idcard` 写到 |
|---------|----------------------|
| `institution_type ∈ {1, 2}`（公募/非公募机构）| 法人身份证槽位 |
| `institution_type == 3`（专项基金）| 专项基金负责人身份证槽位 |

Skill 只需按用户上传的身份证填 `idcard` 字段块，UI 展示时可根据机构类型决定标签是"法人身份证"还是"专项基金负责人身份证"。

> 📌 表中 `institution_type` 与脚本输出 `org.type_of_organization`（来自 `get_user_and_org_info`）**是同一个东西**（同值域、同语义），优先使用后者。

## OCR 云返回字段（K-V）

`alert-ocr` 走 `cloud_cert_pipeline` 引擎（`ocr_type=1`，**私有桶**），云 OCR 返回的 K-V 字段（示意）：

| K-V 键（云 OCR）| 说明 |
|-----------------|------|
| 身份证正面URL | alert-ocr Step 1 上传后拼接的 **COS 原始域名**（**不走 CDN**）|
| 身份证反面URL | 同上 |
| 姓名 | 中文 2-4 字 |
| 身份证号 | 18 位，末位可能是 `X`（大写）|
| 有效期起 | 从背面识别，`YYYY-MM-DD` |
| 有效期止 | 从背面识别，`YYYY-MM-DD` 或识别为"长期" |

## K-V → proto 字段映射

对应 proto `IdcardCert`（在 `update_org_cert.idcard` 字段块）：

| K-V 键 | proto 字段 | 类型转换 |
|-------|-----------|---------|
| 身份证正面URL | `idcard_front` | string 原样（COS 原始域名，不走 CDN）|
| 身份证反面URL | `idcard_back` | string 原样（同上）|
| 姓名 | `name` | string 原样 |
| 身份证号 | `id_card` | string 原样（18 位，末位可为 `X`）|
| 有效期起 + 有效期止 | `id_card_validity` | **Skill 层拼接**，见下方"有效期字段拼接规则"|

### 有效期字段拼接规则

`id_card_validity` 是**纯文本透传**字段，格式如下（**由 Skill 层拼接**）：

| 场景 | 格式 | 示例 |
|------|------|------|
| 有明确起止日期 | `YYYY-MM-DD~YYYY-MM-DD` | `2020-01-01~2030-12-31` |
| 长期有效 | `YYYY-MM-DD~长期` | `2020-01-01~长期` |

**⚠️ 分隔符**：使用 `~`（不是 `-`），前后不加空格。

**⚠️ 分隔符前后**：日期部分严格 `YYYY-MM-DD`，不能用旧格式 `YYYY.MM.DD`。

**Skill 层拼接伪代码**：
```
if有效期止 == '长期':
    id_card_validity = f"{有效期起}~长期"
else:
    id_card_validity = f"{有效期起}~{有效期止}"
```

## 正反面上传策略

用户可能一次上传两张（正 + 反），也可能分开上传：

| 上传情况 | Skill 处理 |
|---------|-----------|
| 只上传正面 | 提示"请补充身份证反面（含有效期）"，正面 K-V 暂存 |
| 只上传反面 | 提示"请补充身份证正面（含姓名和身份证号）"，反面 K-V 暂存 |
| 一次两张 | 独立走 alert-ocr，正反面 K-V 合并到同一 `idcard` 字段块 |
| 分两次两张 | 第一次 OCR 后暂存；第二次上传后合并，判定"正 + 反齐"后再进入 UI 二次确认 |

**⚠️ 判定"正/反面"**：可让 alert-ocr 类型粗判阶段返回，或根据字段完整性推断（有姓名+号= 正面；有有效期 = 反面）。

## 用户可见的表单字段（UI 展示）

| 界面标签 | proto 字段 | 是否可修改 |
|---------|-----------|-----------|
| 身份证正面预览 | `idcard_front` | ❌ 不可改（如需换图请回上传步骤）|
| 身份证反面预览 | `idcard_back` | ❌ 不可改（同上）|
| 姓名 | `name` | ✅（法人姓名 / 专项基金负责人姓名）|
| 身份证号 | `id_card` | ✅ |
| 身份证有效期 | `id_card_validity` | ✅（UI 可拆分为"起 + 止 + 长期开关"三个控件，提交前由 Skill 层重新拼接为纯文本）|

## 提交前校验清单

- ✅ `idcard_front` 非空（COS 原始域名格式）
- ✅ `idcard_back` 非空（COS 原始域名格式）
- ✅ `name` 非空
- ✅ `id_card` 长度 = 18；前 17 位是数字；第 18 位是数字或 `X`（大写）
- ✅ `id_card_validity`匹配正则 `^\d{4}-\d{2}-\d{2}~(\d{4}-\d{2}-\d{2}|长期)$`
- ✅ 若结束部分是日期 → **`end_date > 今天`**（不能提交已过期身份证）
- ✅ **覆盖语义**：`update_org_cert.cert_types` 中包含 `3` 时，本字段块 5 个字段全填

## 与备案的姓名一致性（不作为 Skill 校验）

用户上传的身份证姓名可能与后端已备案的法人姓名不一致（如法人变更）——这属于**业务变更场景**，**Skill 不做拦截**，由后端审核阶段处理。Skill 只保证格式合法。
