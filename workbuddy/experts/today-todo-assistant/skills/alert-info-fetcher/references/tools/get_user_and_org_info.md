# get_user_and_org_info — 机构信息（预警专家视图）

> **所属层级**: 第 0 层（由查询脚本经 `mcp_client` 内部调用，AI 不直接调用）
> **用途**: 首次查询脚本输出 `org` 字段的**语义字典 + 机构类型业务分支参考**
> **最后更新**: 2026-08-22（v3.0：调用方式改为脚本内部调用；`type_of_organization` 与 `get_org_detail.institution_type` 等价不变）

## 定位

本工具由 `query_todo_summary.py` / `query_todo_detail.py` 在首次查询时经 `_common/mcp_client.py` 内部调用，结果随脚本 stdout 的 `org` 字段返回给 AI。**AI 不直接调用本工具、也不构造任何参数**。

本文档的价值在于：说明 `org` 字段各成员的含义，以及 `type_of_organization` 如何决定证件/身份证的业务分支。

## org 字段（返回字段语义）

| 字段 | 类型 | 用途 | 说明 |
|------|------|------|------|
| `org_no` | string | ⭐ **准入判定 + 业务传参** | 机构编号。**为空则专家不可用**；部分接口调用需显式传入 |
| `org_name` | string | ✅ 话术 | 机构名称，用于对话中称呼机构 |
| `type_of_organization` | int32 | ⭐ **业务分支判定** | 机构类型：`1`公募 / `2` 非公募 / `3` 专项基金。|
| `affili_pub_org` | string | ✅ 上下文 | 所属公募编号（**仅 `type_of_organization=3` 时有值**）|
| `affili_pub_org_name` | string | ✅ 话术 | 所属公募名称（**仅 `type_of_organization=3` 时有值**），可用于标注专项基金挂靠关系 |
| `account_id` | int32 | ✅ 上下文 | 当前登录用户的账号 ID |
| `name` | string | ✅ 话术 | 当前登录用户的姓名，可用于开场称呼 |

**AI 从脚本 stdout 的 `org` 字段读取并存入会话上下文**供后续步骤复用；**MUST NOT** 在同一会话内重复运行查询脚本只为再拿机构信息。

## 由机构类型决定的业务分支

| 判定 | 结论 |
|-----|-----|
| `= 1`（公募）| 存在"慈善组织公开募捐资格证书"（`cert_type=2`）|
| `∈ {2, 3}` | 不会产生 `cert_type=2` 预警，**不应主动提示上传该类证件** |
| `∈ {1, 2}` | 身份证标签为 **"法人身份证"**；后端把 `idcard` 写入法人身份证槽位 |
| `= 3`（专项基金）| 身份证标签为 **"专项基金负责人身份证"**；后端写入专项基金负责人槽位；`affili_pub_org*` 有值 |

## 返回示例

**机构类（公募）**：

```json
{
  "org_no": "123456",
  "org_name": "XX 市慈善基金会",
  "type_of_organization": 1,
  "affili_pub_org": "",
  "affili_pub_org_name": "",
  "account_id": 88001,
  "name": "张三"
}
```

**专项基金类**：

```json
{
  "org_no": "998877",
  "org_name": "XX 助学专项基金",
  "type_of_organization": 3,
  "affili_pub_org": "123456",
  "affili_pub_org_name": "XX 市慈善基金会",
  "account_id": 88002,
  "name": "李四"
}
```

## 查不到机构信息时的处理

`org_no` 为空 = 当前账号没有绑定可用机构 → **本专家不可用**：

| 应返回 |
|-------|
| 自然语言说明：「我没能查到你所在的机构信息（`org_no` 为空），证件与备案号相关能力都需要机构上下文才能使用。请确认当前账号已绑定机构后再试。」 |

> ⛔ **MUST NOT** 在`org_no` 为空时用空字符串继续调用业务接口。

## 铁律

- ❌ **AI 直接调本工具**（本工具只由查询脚本经 `mcp_client` 内部调用）
- ❌ **`org_no` 为空却继续走业务流程**
- ❌ **同一会话内重复运行查询脚本只为再拿机构信息**（应存会话上下文复用）
- ❌ **把"工具不存在"与"RPC 调用失败"混为一谈**（前者是连接器缺失，后者是接口故障）
- ❌ **凭 `connector-status` 面板状态替代查询脚本返回做环境判断**（唯一证据是查询脚本的真实返回）
