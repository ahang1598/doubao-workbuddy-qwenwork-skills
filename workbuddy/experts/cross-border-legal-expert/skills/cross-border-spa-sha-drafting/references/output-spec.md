# 输出规格 — cross-border-spa-sha-drafting

> 本节遵循 base/governance/ssot-compiler.md §17（SSOT）：output-spec 定义

## 1. 输出格式

**主格式**：DOCX（C-Professional 格式严肃度，正式申报/签发用）
**辅格式**：Markdown（内部参考副本）
**受众**：律师团队起草参考，供后续正式协议起草使用
**条款编号体系**：采用国际交易文件标准编号（Article X / Section X.X / Clause X.X.X）

> 格式严肃度 C-Professional 继承自 `base/rule/format-docx/families/contract/spec.md` 合同与函件族。排版参数详见下方「DOCX 渲染规格」专章。

### 2.3 条款内容格式

每个核心条款条目包含：

| 字段 | 说明 | 格式 |
|------|------|------|
| Clause ID | 条款编号（Article X.Section X.X格式） | 国际标准编号 |
| 条款内容 | 条款草案正文 | 自然语言条款文本 |
| 谈判敏感性 | 谈判争议度标注 | 🔴高/🟡中/🟢低 |
| 谈判要点 | 关键谈判争议点说明 | 1-3条要点 |
| 替代方案 | 关键条款的替代方案（≥2个） | 方案A/B/C+适用场景 |
| 风险提示 | L3风险提示 | "须律师审核"+具体风险 |
| 法条依据 | 关联法律依据 | 法条全称+条号+标注 |

### 2.4 谈判敏感性定义

| 级别 | 定义 | 典型条款 |
|------|------|---------|
| 🔴 高敏感性 | 谈判中争议最大、最可能影响交易成败的条款 | 陈述保证范围与生存期/赔偿上限与下限/终止权/限制竞争/Earn-out |
| 🟡 中敏感性 | 需要协商但通常可达成折中的条款 | 交割条件清单/赔偿程序/保密范围/通知方式 |
| 🟢 低敏感性 | 通常模板化处理、谈判争议较少的条款 | 定义条款/费用承担/可分割性/完整协议 |

## 3. 写作红线

> 本技能遵守 `base/shared/writing-redlines.md` 全部 11 条通用红线。

偏离项：
- WR-03 强化：条款内容与谈判要点必须明确分离，条款正文不含主观评价，谈判要点单独标注
- WR-05 强化：每条法条引用须写全称+条号+款项+核实状态标注
- WR-10 强化：按谈判立场自动调整条款保护倾向，但禁止在买方保护版中出现不利买方的承认性表述，反之亦然
- WR-11 适用：选定"国际交易文件编号风格"贯彻到底——条款编号采用 Article X.Section X.X 格式，不混用中国法条枚举风格

## 4. C-Professional 格式规范

遵循 C-Professional 格式严肃度（客户级），适用于正式交易文件起草参考：

- 条款编号体系规范：Article X.Section X.X.Clause X.X.X 三级编号
- 标题层级规范：一二级标题用章（Article），三级用节（Section），四级用款（Clause）
- 术语一致性：同一术语全文统一使用定义条款中的定义形式
- 金额/日期格式规范：数字+币种+计算依据标注
- 禁止正文使用 Markdown 表格（条款正文纯文字叙述+编号段落）
- 表格仅用于附录（谈判要点/替代方案/风险提示汇总）

## 5. SOFT_DEGRADED 降级输出

当信息不足以完整交付时（遵循 `base/shared/risk-rules-common.md`）：

| 层 | 内容 | 说明 |
|---|------|------|
| **C 层** | 待补充交易信息清单 | 列出缺失的关键交易参数 |
| **D 层** | 治理声明：本条款框架仅覆盖已有信息范围内的条款骨架 | 申明输出限制+L3风险声明 |
| **G 层** | 建议下一步：补充交易参数后重新运行 | 告知用户可执行操作 |

降级时**禁止**生成确定性法律建议条款，仅输出条款骨架结构。

## 6. 禁止事项

遵循 base/governance/ssot-compiler.md §17.20 三层禁止清单：
- L3 致命禁止：不得输出确定性胜诉把握 / 不得伪装可发布 / 不得替代律师职责 / 不得虚构法条 / 不得跨法域越界
- L2 严重禁止：不得隐瞒风险 / 不得省略免责声明 / 不得隐藏复核需求 / 不得多方纠纷立场不明
- L1 注意禁止：不得省略时效标注 / 不得省略不确定性标注

额外技能特定禁止：
- 禁止输出未标注"须律师审核"的条款（L3-02 强化）
- 禁止对离岸法域条款做确定性法律建议（标注"[需离岸法域律师核实]"）
- 禁止在条款框架中包含可能被对方利用的承认性表述（L3-01 强化）
- 禁止遗漏程序要件审批条款（ODI(发改委第11号令+商务部第3号令)/反垄断(2024修订版门槛)/外商投资安全审查(2020年第37号令)/CFIUS(涉美并购标注"[需美国律师核实]")）（L3-04 强化）

### 突出加粗规则（🔴 本技能 DOCX 最核心约束）

> 以下规则直接解决"单个汉字被不恰当地加粗"的一线问题。

**1. 只对以下元素加粗：**
- 文书主标题
- 一级标题（Article X — 章标题）
- 风险提示标注文字（如「【高风险条款——谈判敏感度：高】」）
- 附录表格表头

**2. 禁止对以下元素加粗：**
- 正文条文内容
- 二级/三级标题（Section/Clause 标题，已通过字体区分层级）
- 法条引用
- 谈判要点说明
- 替代方案说明
- 关键词/核心术语（除非是该术语的第一次定义，且仅加粗该术语词本身而非整个句子）

**3. 中文加粗完整性铁律（阻断级）：**
对中文文本设置加粗时，必须对**完整中文词语或完整句子**加粗，绝对禁止对单个汉字或词语碎片加粗。

- ✅ 正确示例：**陈述与保证**（完整法律术语）
- ✅ 正确示例：**【高风险条款——谈判敏感度：高】**（完整标注句）
- ❌ 错误示例：**陈**述与**保**证（拆散词语，仅加粗单个汉字）
- ❌ 错误示例：卖方对知识产权的**陈述**（在正文条文中局部加粗，制造随意强调）
- ❌ 错误示例：**供** / **仅** / **错误** / **导** / **标注**（单个汉字加粗——严格禁止）

**4. 中英混排处理：**
中文正文中的英文单词（如 "BVI"、"SPA"、"CFIUS"、"MAC"）**不需要额外加粗**，使用宋体即可，英文和数字部分自动使用 Times New Roman。

### 风险标注方式（C-Professional，禁止 emoji）

> ⚠️ **严禁在 DOCX 输出中使用 emoji 符号**（🔴🟡🟢⚠️❌✅）。遵循 `base/rule/format-docx/base/prohibitions.md` §全局禁止事项——禁止 emoji/图标/装饰符号。所有风险标注必须使用纯文本。

| Markdown 阶段标记 | DOCX 标注方式 |
|------------------|--------------|
| 高敏感性 | 条款标题加粗 + 条款正文后另起一段「【高风险条款——谈判敏感度：高】」；宋体、小四号（12pt）、加粗 |
| 中敏感性 | 条款正文后另起一段「【中风险条款——谈判敏感度：中】」；宋体、小四号（12pt）、常规 |
| 低敏感性 | 不另做标注 |

> 谈判要点说明和替代方案均使用正文格式，不额外标注风险等级。

### python-docx 渲染指令

生成 DOCX 时使用 python-docx 库，必须遵守以下指令：

1. **字体设置**：中文字体 `run.font.name = '宋体'`（或 '黑体'/'楷体'），西文字体 `run.font.name = 'Times New Roman'`
2. **加粗**：仅通过 `run.bold = True` 实现，不得通过 HTML/CSS 伪实现
3. **禁止中文拆分加粗**：对一个完整中文词语设置 `run.bold = True` 时，必须将该词语的**全部汉字放在同一个 run 中**，不得将单个汉字拆分为独立 run 后分别设置 bold。这是解决"单个汉字加粗"问题的技术根因
4. **段落样式**：正文段落 `paragraph_format.first_line_indent = Cm(0.74)` 实现 2 字符缩进
5. **行距**：`paragraph_format.line_spacing = 1.5`
6. **禁止 emoji**：DOCX 文本中不得包含任何 emoji 字符。Markdown 阶段的 🔴🟡🟢 标记在 DOCX 转译时必须替换为纯文本标注
7. **表格**：附录中的谈判要点/替代方案/风险提示汇总可使用表格，但条款正文中禁止表格
8. **页脚页码**：`section.footer.paragraphs[0].text = "第 {page} 页 / 共 {total} 页"`
