# 输入规格 — supply-chain-compliance-review

> 版本：1.2.0 | 更新日期：2026-06-28

---

## 1. 输入模型

### 1.1 双模式输入

| 模式 | 触发条件 | 说明 |
|------|---------|------|
| **Mode A：结构化输入** | 用户提供结构化供应链数据 | 逐字段填写，精确审查 |
| **Mode B：自然语言输入** | 用户用自然语言描述供应链 | 技能自动提取信息，交互补全 |

### 1.2 核心字段定义

| 字段名 | 类型 | 必填 | 法律含义 | 示例 |
|--------|------|------|---------|------|
| company_profile | text | 是 | 企业概况——决定审查范围和深度 | "电子制造商, 年出口额2亿美元" |
| supply_chain_data | text | 是 | 供应链数据——供应商列表+层级+产品/材料+地区 | "Tier-1: 供应商A(中国), Tier-2: 供应商B(新疆地区)" |
| product_info | text | 是 | 产品信息——含原材料的来源国家 | "锂电池, 正极材料来自中国" |
| target_markets | enum | 否(默认US) | 目标市场——决定适用法规 | "US/EU/CN/multi" |
| screening_results | text | 否 | 制裁筛查结果（来自上游sanctions-list-batch-screening） | "供应商C: SDN匹配" |
| existing_commitments | text | 否 | 现有供应商合规承诺 | "供应商A已签署合规承诺书" |
| audit_scope | enum | 否(默认all) | 审查范围 | "UFLPA/sanctions/forced_labor/FDPR/all" |
| tier_depth | number | 否 | 供应链层级深度（默认3层） | 3 |

### 1.3 信息充分度判定

| 等级 | 充分度 | 依据 | 处理 |
|------|--------|------|------|
| S1 | 充分 | 供应链数据完整+产品信息+目标市场均明确 | 直接审查 |
| S2 | 基本充分 | 缺少部分供应商信息但不影响核心审查 | 审查+标注缺失影响 |
| S3 | 不足 | 缺少关键供应链信息影响风险判断 | SOFT_DEGRADED，交互补全 |
| S4 | 严重不足 | 无法进行有意义的供应链审查 | 降级为通用风险建议 |

### 1.4 交互补全规则

- 最多3轮交互
- 每轮最多追问3个关键信息
- 追问优先级：供应链层级 > 供应商地区 > 原材料来源 > 现有合规措施
- 用户明确表示"不知道"时，标注为缺失，不影响已确定部分的输出
