# 事实核验引擎（Fact Verification Engine）

> 本文件是技能的**强制核验规程**。所有输出路径（快速概览 / 全面报告 / 比较矩阵）的每条法律结论，
> 在输出前都必须通过本文件的流程。未通过核验的信息不得作为确定性结论呈现。
> SKILL.md 正文只保留"铁律摘要"，完整规则在此。

---

## 1. 零容忍规则（Zero-Tolerance）

| 行为 | 判定 | 处理 |
|------|------|------|
| 用 AI 预训练知识直接生成法律结论（"越南劳动法规定…"但无实时来源） | 绝对禁止 | 先检索来源再输出；无法检索则明示"无法验证" |
| 无实时来源佐证就陈述"某国法律规定 X" | 绝对禁止 | 同上 |
| 将 L4 来源（AI搜索/论坛）升级为 L1/L2/L3 确定性呈现 | 绝对禁止 | L4 保留 `[待验证]` 标签，仅作线索 |
| 对无法确认的法条内容推断或补全 | 绝对禁止 | 标 `[待线下验证]` 并给 URL 供用户自查 |
| 引用经 WebFetch/WebSearch 实时验证的外部来源 | 必须 | 唯一允许的法律结论产出方式 |

> **核心原则**：不查不说、无源不述、无法核实就明示无法核实。
> 技能价值在于**导航与结构化**，而非**记忆与复述**。即使训练数据含某国法律，也不得直接调用，
> 必须经下方三级核验重新获取、锚定后才能引用。

## 2. 三级核验流程（Three-Level Verification）

```
[外国法/跨境快捷通道] LDH 实时检索（可选，健康时优先）
  ├ scripts/ldh_client.py search / resolve / get —— 一步完成 Level A+B+C：
  │   search→候选(含官方 url) ; resolve→精确引用解析 ; get→官方源全文(锚点)
  ├ status=ok → 据 ldh-integration.md §5 打标签+回链官方源出脚注，可跳过下方三级的重复抓取
  └ status 非 ok（未配置/欠费/限流/不可达/空）→ 回退下方常规三级，绝不用训练数据补全
      ▼
Level A — 来源定位
  ├ 用联网检索工具（WebSearch 或 mcp__ddg-search__search）定位结论对应的精确外部来源 URL
  │   优先：L1 法规原文 > L2 权威指南 > L3 律所文章 > L4 AI辅助(见 §5)
  ├ 通过：找到一个或多个候选 URL（候选可来自 source-index.md / sources-*.md / resources.md）
  └ 失败：标 [无法定位权威来源] → 可降级 L4 但须标 [L4/待验证] → 仍失败则结论不可输出
      ▼
Level B — 可达性验证
  ├ 用抓取工具（WebFetch 或 mcp__fetch__fetch / mcp__ddg-search__fetch_content）确认 URL 非404、非登录墙、非空页；记录 HTTP码/最后修改时间/标题
  ├ 通过：200 且内容可读（或 [反爬] 但已知浏览器可访问）
  └ 失败：404→启降级(§4)试替代URL；登录/付费墙→标 [需注册]/[付费] 给URL；反爬→§4
      ▼
Level C — 内容锚定
  ├ 从已验证页面提取锚点：法条名+编号 / 章节标题 / ≤2句关键原文 / 发布日期或版本号
  ├ 通过：至少获得 法条名+编号 或 精确章节标题
  └ 输出：每条结论附脚注 [^N]，格式见 §3
```

> **LDH 不豁免核验**：LDH 命中仍须打正确确定性标签（按 namespace，见 `ldh-integration.md` §5）、
> 回链官方源 URL、带 source_id/案号/ECLI 锚点。LDH 是更快的取证通道，不是"免核验"通道。

## 3. 核验证据输出格式

**正文标签（带可跳转锚点）**：

- Markdown：标准脚注 `[^N]`（GFM 渲染器自动生成跳转）
- HTML：`<sup><a href="#fn-N" id="ref-N">[N]</a></sup>` 双向跳转
- Word：原生脚注（Insert → Footnote），自动书签+交叉引用

```markdown
[法规原文] 《越南劳动法》第36条规定试用期不得超过185天[^1]。
[权威指南] Chambers指南指出外籍员工工作证绑定具体雇主岗位[^2]。
[一般评论] 据Baker McKenzie分析，新就业法扩大失业保险覆盖范围[^3]。
[待验证] AI搜索显示可能需缴培训基金，请用户自行核实[^4]。   ← 仅限 L4
```

**脚注必填字段（顺序固定）**：

| 顺序 | 字段 | 必填 | 说明 |
|------|------|------|------|
| 1 | 确定性标签 | 必填 | [法规原文]/[权威指南]/[一般评论]/[待验证] 四选一 |
| 2 | 访问状态（前置） | 必填 | [已验证]/[需注册]/[付费]/[反爬]/[未验证] |
| 3 | 来源名称 | 必填 | 全称 + 版本/年份 |
| 4 | 完整 URL | 必填 | 用户可点击的精确地址 |
| 5 | 验证时间 | 必填 | YYYY-MM-DD |
| 6 | 锚点文本 | 必填 | 法条编号/章节标题/关键原文（证明该页确含此内容） |
| 7 | 发布日期 | 建议 | 尤其 3–12 月内需复核的敏感主题 |
| — | 目录定位 | 建议 | 如 `resources.md §12` 的 L1 官方源或 LDH Source ID |

> **禁止裸脚注**：仅有 URL 而无法条编号/章节标题的脚注不合格。

> **LDH 来源的脚注**：额外注明 `检索: LegalDataHunter (namespace=...)`，并在"来源名称/URL"位
> 填 LDH hit 的 `source`(Source ID) + `url`(官方源原址)，让用户能在权威原址复核；锚点用
> `source_id` / `ecli` / `case_number` / 关键原文。完整样例见 `ldh-integration.md` §5。

脚注样例：

```markdown
[^1]: [法规原文] [反爬] Vietnam Labour Code 2019 (Law No.45/2019/QH14), Art.36
     来源: ILO NATLEX — https://natlex.ilo.org/[记录URL]
     验证时间: 2026-04-06 | 锚点: 页面显示 "Article 36. Trial performance of the job..."
     目录定位: resources.md §7.4/ILO-NATLEX
[^4]: [待验证] [未验证] Perplexity AI Search — "Vietnam employer training fund"
     验证时间: 2026-04-06 | 来自AI辅助搜索(L4)，未经 L1-L3 交叉验证，仅供线索
```

HTML 双向跳转：

```html
<sup><a href="#fn-1" id="ref-1">[1]</a></sup>
<div id="fn-1"><strong>[法规原文]</strong> <span class="access-status">[反爬]</span>
  Vietnam Labour Code 2019, Art.36 —
  <a href="https://natlex.ilo.org/..." target="_blank">ILO NATLEX</a>
  <a href="#ref-1" class="back-ref" title="返回正文">↩</a></div>
```

### 3.1 参考文献区格式（输出层，所有路径强制）

上文 §3 脚注格式用于**正文核验证据记录**。输出报告中，参考文献区（`## 参考文献（N条）`）
采用独立于 Markdown 脚注机制的统一结构，每条包含以下字段：

```
[编号]. [确定性标签] [访问状态] 来源全称.
   Source: 出处数据库名称
   URL: 可点击URL（单独成行）
```

**与正文脚注的关系**：
- 正文 `[^N]` 脚注标注 → 参考文献区编号 `N.` 对应
- 参考文献区的 `Source` 和 `URL` 是对脚注中"目录定位"和"完整URL"字段的**格式强化呈现**，
  信息一致但更易于核验
- HTML 输出采用双向跳转（正文 `#ref-N` → 参考文献 `#fn-N`，参考文献 `↩` → 正文）

完整格式规范、Markdown/HTML/Word 三类样例、路径差异详见 `output-formats.md` §7。

---

| 失败原因 | 降级方案 | 输出形式 |
|---------|---------|---------|
| 反爬/403 但浏览器可访问 | 引用法条名+编号(若他源间接获知) + URL + `[反爬]` | "据ILO NATLEX记录，《越南劳动法》第36条规定试用期限[^1]，建议浏览器打开确认。" |
| 付费墙/登录墙 | 给登录页 URL + `[需注册]` + 说明该源涵盖此议题 | "据Practical Law越南劳动法指南（需订阅）[^2]有详细分析。" |
| 目标资源完全不存在 | `[未找到该法域]` + 切换备选 | "ICLG未覆盖该国劳动法，改用Mondaq比较指南[^3]。" |
| 所有自动化手段失败 | `[无法在线验证]` + 手动查找指引 | "无法自动获取权威来源，建议通过越南VCCI或当地律师确认。" |
| 多个来源矛盾 | **不自行仲裁** | 分别列各方说法+各自来源 + `[来源分歧，需律师裁决]` |

> **红线**：任何降级方案都**不允许**用预训练知识填充缺失的具体条款内容。

**LDH 检索失败的降级（外国法/跨境，详见 `ldh-integration.md` §4）**：

| LDH status | 含义 | 降级动作 |
|---|---|---|
| `not_configured` | 缺 RICHEEAI_TOKEN（非 RicheeAI 会话） | 静默走预置源（预期态） |
| `auth_failed` | 401/403 或代理鉴权失败 | 本会话停用 LDH，全回退预置源；输出注明"LDH 凭证不可用" |
| `quota_exhausted` | 429/402 限流/超额 | 回退预置源；retry_after 短且关键时可稍后重试一次 |
| `unavailable` | 5xx/超时（已自动重试1次） | 回退预置源；输出注明"LDH 暂不可达" |
| `empty` | 0 命中 | 该子问题回退 source-index → sources-*.md 目录导航（非错误） |

> 同一红线：LDH 降级也**绝不**用训练数据补全；查不到则进 §7 待查法规清单。

## 5. AI 辅助搜索使用规范（L4 Flexible Mode）

| 工具 | 用途 | 限制 |
|------|------|------|
| Perplexity | 快速锁定法规名称/编号/方向 | 必须点其来源链接做 Level B+C 二次验证 |
| WebSearch + 摘要 | 发现新 L2/L3 来源 | 搜索结果本身非结论，只引导到原始来源 |
| ChatGPT with Browsing | 同上 | 同上 |

规则：① AI 回答只作线索不作证据；② 有来源链接→对链接做 Level B+C；③ 无来源链接→只能 `[待验证]`
并说明未经交叉验证；④ 同一结论既有 L4 又有 L1-L3→以高等级为准，L4 仅作补充背景。

## 6. 法规援引出处精准定位流程

对报告中每条**法律法规名称**，执行：

```
Step A — 查 source-index.md 表 A 定位业务领域→数据类型，再按法域：
         中国 → 法大大检索；其他 → LDH 实时 discover 目录
Step B — 查 resources.md 专题库（IP→WIPO Lex；劳动→ILO NATLEX；数据→DLA Piper+EUR-Lex；
         Section 12 官方 L1 库）
Step C — 仍未定位 → 进入 §7 待查法规清单，标注建议查询方向
```

> 脚注援引法规时必须填该法规在目录中的精确定位节点（如 `resources.md §12` 的 L1 官方源或 LDH Source ID）。
> 无法定位的法规一律进待查清单，**不得**凭记忆补全条文。

## 8. 质量门禁（输出前逐项自检，任一"否"必须修正）

```
□ 1 来源定位：每条结论都用 WebSearch/WebFetch 找到外部来源？否→删或标 [L4/待验证]
□ 2 可达性：URL 可访问且已附访问状态标签？（顺序：确定性标签→访问状态→来源名）
□ 3 内容锚定：有法条编号/章节标题作证据？脚注 6 字段齐全？
□ 4 标签正确：L1→[法规原文] L2→[权威指南] L3→[一般评论] L4→[待验证]（禁止升级）
□ 5 无预训练填充：无法追溯到实时来源的结论→删除 或 标 [无法在线验证]
□ 6 跳转锚点：MD 用 [^N]；HTML 用 <sup><a>；Word 用原生脚注
□ 7 时效：3–12 月复核主题已加时效警告 / Legislative Alert？
□ 8 不自行仲裁：来源矛盾时分列各方，未替用户下结论？
□ 9 参考文献链接：每条参考文献含可点击URL且单独成行？Source出处已标注？
   参考文献区标题含来源统计（"N条"）和核验路径？格式遵循 output-formats.md §7？
□ 10 域展开验证：展开模式下，每个合规域是否都已独立过 Level A+B+C？
   任一域标记为 [无法在线验证] → 该域在报告中显式标注"待查"并提供核验指引；
   全量展开域 ≥30% 无法验证 → 降级为"待查法规清单"，不建议作确定性交付。
```

各路径最低核验要求：

| 路径 | 最低要求 |
|------|---------|
| A 快速概览 | 每条结论 ≥1 来源过 Level A+B；Level C 尽力而为 |
| B 全面报告 | 每子问题 ≥1 来源过 Level A+B+C，完整脚注 |
| C 比较矩阵 | 每个 法域×维度 独立核验，禁止跨法域推断 |
| D 业务合规操作指南 | 每个合规域 ≥1 来源过 Level A+B+C；≥30% 域无法验证则降级为"待查法规清单" |
