# 法律翻译整合工作流

本工作流覆盖四类任务: 翻译、审校、起草英文版、中英双语对照。

## 1. 输入识别

确认:

- 输入形式: `.docx`、粘贴文本、图片 OCR 后文本、片段术语。
- 任务类型: 翻译、审校、起草、双语对照、术语统一。
- 文书类型: 合同、诉讼/仲裁文书、公司文件、刑事材料、涉外合规文件、函件、备忘录。
- 目标输出: 英文译文、术语表、审校报告、双语 Word、修订建议。

如果是 `.docx`, 使用 `python3 scripts/extract_text.py` 提取文本; 如环境只提供 `python`, 可改用 `python`。

## 2. 术语抽取和路由

先抽取:

- 主体和角色: 甲乙方、原告/被告、申请人/被申请人、董事、股东、监管机关。
- 法律制度: 合同、侵权、公司治理、证据、管辖、犯罪构成、域外适用。
- 文书结构: 标题、定义、条款、附件、表格、签署页。
- 高风险数字: 金额、日期、期限、比例、编号。

再按 `domain-skill-router.md` 选择领域术语技能。

## 3. 术语表确认

生成术语表时, 每个术语至少给出:

- 中文术语
- 建议英文
- 来源或领域技能
- 适用语境
- 排除译法
- 是否需人工确认

若用户没有回复确认, 可以制作“待确认草稿”, 但交付报告必须列出待确认项。

## 4. 翻译或审校

翻译:

- 逐段保留原文结构。
- 使用确认后的术语表。
- 对无法确认的术语使用临时译法并标注待复核。
- 不随意删改原文法律效果。

审校:

- 对照原文和译文逐段检查。
- 重点检查术语、法域、程序身份、编号、数字。
- 输出问题表, 不直接覆盖用户译文, 除非用户要求直接修订。

起草英文版:

- 先确认是否基于中文原文起草, 还是根据要点直接写英文。
- 如果根据要点起草, 不虚构未提供事实、主体、期限、金额或法律依据。

双语对照:

- 翻译完成后将内容整理成脚本 schema。
- 使用 `python3 scripts/create_bilingual.py` 生成 Word; 如环境只提供 `python`, 可改用 `python`。

## 5. 一致性检查

必须检查:

- 术语一致性
- 法域一致性
- 程序身份一致性
- 编号对应性
- 数字准确性
- 高风险术语排除项
- 待确认项是否列明

## 6. 交付

交付内容按任务类型选择:

- 翻译: 英文译文 + 术语表 + 待复核项。
- 审校: 审校问题表 + 修订建议 + 风险等级。
- 起草: 英文草稿 + 假设 + 待补事实。
- 双语对照: Word 路径 + 一致性检查 + 高风险术语表。

固定提醒:

```text
本输出为翻译和术语审校工作底稿, 建议由律师、法务或专业译审复核后使用。
```
