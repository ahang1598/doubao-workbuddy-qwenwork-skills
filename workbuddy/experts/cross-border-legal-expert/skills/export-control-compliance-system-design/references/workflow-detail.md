## Phase 1：输入验证与企业画像构建

**风险等级**：L1

### 1.1 输入验证

1. 检查 `company_type` 非空且为合法枚举值（V1规则）
2. 检查 `product_lines` 非空（V2规则）
3. 检查 `export_destinations` 非空且≥1个目的地（V3规则）
4. 检查出口目的地国家代码是否可映射到Country Group（V4规则）
5. 检查已有ECCN结果与产品线一致性（V5规则）

### 1.2 企业画像构建

根据输入参数构建企业合规画像：

| 画像维度 | 推断规则 | 影响 |
|---------|---------|------|
| 企业规模 | company_size参数 / product_lines数量推断 | 组织架构复杂度 |
| 受控等级 | 产品线ECCN类别推断（0类→最高/3类→高/5类→中/其他→低） | SOP管控严格程度 |
| 管控重点 | company_type × industry_sector交叉推断 | 合规手册重点章节 |
| 目的地风险 | export_destinations × Country Group推断 | 许可证要求矩阵 |
| 上下游衔接 | 是否有#46/#47技能成果 | SOP引用vs独立生成策略 |

### 1.3 上下游衔接确认

1. 如用户提供 existing_eccn_results → 在SOP-01中采用"引用模式"（标注引用#46技能成果）
2. 如用户提供 sanctions_screening_setup → 在SOP-02中采用"引用模式"（标注引用#47技能成果）
3. 如未提供 → 在对应SOP中采用"独立生成模式"（标注"建议配合对应技能使用"）

### Phase 1 产出

- 验证通过/失败状态
- 企业合规画像（规模/受控等级/管控重点/目的地风险/上下游衔接）
- 生成策略确认（引用模式 vs 独立生成模式）

## Phase 2：合规手册框架生成

**风险等级**：L2

### 2.1 第一章：合规政策声明

1. 生成合规政策声明——明确企业对出口管制合规的承诺
2. 政策声明要素：
   - 适用法规范围（EAR+中国出口管制法）
   - 合规承诺（零容忍违规/主动披露/持续改进）
   - 适用人员范围（全体员工+第三方代理）
   - 修订机制（年度审查+法规变更触发修订）

### 2.2 第二章：风险评估（Risk Assessment）

1. 按产品线/出口目的地/最终用户三维评估出口管制风险等级
2. 风险评估要素：
   - 产品线维度：按ECCN类别评估受控等级（0类→最高/3类→高/5类→中/其他→低）
   - 出口目的地维度：按Country Group映射风险等级（E:1→低/D:5→高/禁运国→最高）
   - 最终用户维度：按制裁筛查结果+MEU风险+军工关联度评估
3. 风险等级输出：
   - 高风险（0类/E:1以外/MEU相关）→强化管控措施
   - 中风险（3类/D:1-D:4）→标准管控措施
   - 低风险（其他/E:1）→基础管控措施
4. 风险评估更新触发条件（法规变更/新产品线/目的地变化）
5. 风险评估结果对SOP管控严格程度的映射关系

### 2.3 第三章：合规组织架构与职责

1. 根据企业规模生成组织架构：
   - 大型企业：首席合规官→合规部门→各部门接口人→业务操作员
   - 中型企业：合规官→关键部门接口人→业务操作员
   - 小型企业：合规负责人（高管兼任）→业务操作员
2. 各层级职责定义
3. 合规委员会设置（大型企业适用）
4. 外部合规顾问角色

### 2.4 第四章：ECCN分类管理流程

1. 根据上下游衔接确认，选择引用模式或独立生成模式
2. 分类流程核心步骤：
   - 新产品分类触发机制
   - 分类请求提交→合规团队初审→技术参数对照CCL→ECCN编码确定→CCATS申请（不确定时）
   - 分类结果记录与更新机制
3. 与#46技能的衔接说明

### 2.5 第五章：出口许可证申请流程

1. 根据出口目的地×产品线×ECCN类别，生成许可证要求矩阵
2. 许可证申请流程：
   - 许可证需求判定（基于ECCN×Country Group×管控理由）
   - 许可证例外适用性判断
   - 许可证申请准备→提交→跟踪→续期→终止
3. 中国出口许可证申请流程（如涉及中国出口管制物项）

### 2.6 第六章：红色标志识别与交易筛选

1. 红色标志识别清单——覆盖15 CFR §732 Supplement No.3主要红旗场景：
   - 客户拒绝提供最终用途/最终用户信息
   - 客户愿意支付现金购买受控物项
   - 客户对产品功能不感兴趣但坚持购买
   - 客户要求绕过正常出口程序
   - 客户地址与已知制裁实体关联
   - 订单与客户业务不匹配
   - 客户要求不标注目的地
   - MEU相关红旗（§744.21管控：中国/俄罗斯/缅甸等军事最终用途/军事最终用户）
   - 🆕 采购高级别计算芯片但声称用于低端应用（2024年12月BIS新增，§732 Supplement No.3 AI相关红旗指标）
   - 🆕 无实际业务需求但大量采购受限物项（2024年12月BIS新增）
   - 🆕 最终用户地址为风险国家但声称用于盟国（2024年12月BIS新增）
   - 🆕 交易结构涉及多层中间商以掩盖最终用户（2024年12月BIS新增）
   - 🆕 无法清晰说明技术使用场景和最终目的地（2024年12月BIS新增）
   - 🆕 交易金额异常高于市场报价（2024年12月BIS新增）
   - 🆕 买方的技术能力和声称的产品应用场景不匹配（2024年12月BIS新增）
   - 🆕 买方急于完成交易不愿提供标准合规文件（2024年12月BIS新增）
2. 交易筛选流程——根据上下游衔接确认选择引用#47或独立设计

### 2.7 第七章：最终用途/最终用户核查

1. 最终用途核查流程
2. 最终用户核查清单
3. EUM声明收集与管理
4. 核查频率与触发条件
5. 异常发现升级流程

### 2.8 第八章：培训计划

1. 培训体系设计：
   - 入职培训（全体员工）
   - 定期培训（年度）
   - 专项培训（法规变更触发）
   - 高管培训（合规责任）
2. 培训内容矩阵（按岗位×培训类型）
3. 培训效果评估机制

### 2.9 第九章：合规审计计划

1. 内部审计制度设计：
   - 审计频率（年度全面审计+季度专项审计）
   - 审计范围（分类准确性/筛查覆盖率/许可证合规/记录完整性）
   - 审计流程
2. 外部审计安排
3. 审计发现处理机制

### 2.10 第十章：违规报告与纠正措施

1. 违规发现与上报渠道
2. 内部调查程序
3. 处置措施分类
4. BIS自愿披露流程（15 CFR §764.5）
   - ⚠️ 2024年9月BIS Final Rule更新：BIS引入"fast-track"60天快速处理通道——BIS对轻微/技术性违规的**处理时限**为60天，并非将narrative account提交期限缩短。正式narrative account提交期限仍为180天
   - BIS"fast-track"快速处理通道：轻微/技术性违规可在60天内获得BIS处理结果（no-action letter或警告信），但VSD narrative提交期限仍为180天
5. 中国出口管制违规报告
6. 纠正措施（Corrective Actions）——BIS EMCP核心要素：
   - 违规调查根本原因分析（系统性缺陷vs个人失误）
   - 流程变更（根据根本原因修订相关SOP/流程）
   - 全员再培训（涉及修改的流程对相关岗位重新培训）
   - 必要时提交自愿披露(VSD)（涉及EAR违规的按§764.5提交）

### 2.11 第十一章：记录保存与文档管理

1. 记录保存要求（5年，15 CFR §762）
2. 文档分类与归档
3. 记录检索与审计支持

### 2.12 第十二章：制度修订与更新机制

1. 法规变更监测机制
2. 制度修订触发条件
3. 修订流程与审批

### 2.13 第十三章：第三方合规与反腐败风险

> **新增章节**：出口管制合规制度必须覆盖第三方（代理商/中间人/经销商）的腐败风险，因为FCPA/UK Bribery Act违规可触发BIS拒绝令（Denial Order），直接导致出口特权丧失。

1. **第三方尽职调查流程**：
   - 代理商/中间人/经销商风险分级（高风险国家代理商→强制审查）
   - 尽职调查内容：关联实体/最终受益人/制裁清单关联/政治曝光人(PEP)身份/过往合规记录
   - 尽职调查触发条件（新签约/续约/高风险目的地代理变更）
   - 尽职调查结果分级处理（通过/附条件通过/拒绝合作）
2. **FCPA风险识别与管控**：
   - FCPA反腐败条款（18 U.S.C. §78dd-1/2/3）——禁止向外国官员行贿以获取业务优势
   - UK Bribery Act 2010 Section 1/6——禁止向外国公职人员行贿+禁止商业组织未能防止贿赂
   - 出口管制场景下的FCPA高危行为：向目的地国家官员/国有企业高管支付"咨询费"/"佣金"以获取出口许可证或规避管控
   - FCPA合规管控措施：礼品/招待费用上限+佣金合理性审查+第三方付款审批流程
3. **第三方合规审查流程**：
   - 第三方合规承诺书（Anti-Corruption Commitment Letter）——代理商签署反腐承诺
   - 第三方合规审计（年度合规审计+异常触发专项审计）
   - 第三方违规发现升级流程（发现第三方疑似腐败行为→内部调查→合规官决策→必要时外部律师介入→自愿披露评估）
4. **与出口管制的交叉风险**：
   - FCPA违规→BIS拒绝令风险路径说明
   - 第三方绕过出口管制+腐败行为的复合风险场景
   - 反腐败合规与出口管制合规的协同审查机制

### Phase 2 产出

- 完整合规手册框架（13章）
- 每章包含政策声明+操作流程+法律依据引用

3. 处置措施分类

## Phase 5：整体一致性检查与交付

**风险等级**：L2

### 5.1 一致性检查

| 检查项 | 方法 | 标准 |
|--------|------|------|
| QC-01 合规手册12大要素覆盖 | 逐章检查 | 12要素全部有对应章节（含第十三章第三方合规与反腐败） |
| QC-02 SOP与手册流程引用一致 | SOP引用点与手册章节对照 | 无脱节/冲突 |
| QC-03 表格字段与SOP步骤匹配 | 表格字段与对应SOP操作步骤对照 | 每个SOP步骤有对应表格字段 |
| QC-04 角色矩阵覆盖所有SOP岗位 | SOP岗位提取→矩阵对照 | 零遗漏 |
| QC-05 目的地管控要求与Country Group映射 | 目的地×ECCN×管控理由×许可证要求 | 映射正确 |
| QC-06 #46/#47引用标注 | 检查引用来源标注 | 有引用就有标注 |
| QC-07 "须结合企业实际情况调整"标注 | 全文件扫描 | 每套SOP有此标注 |
| QC-08 "内部底稿"标注 | 封面检查 | 合规手册+违规流程有此标注 |
| QC-09 红色标志覆盖度 | 对照15 CFR §732 Supp.3（含2024年12月AI相关新增指标） | ≥18条红旗场景 |
| QC-10 文件独立性 | 文件清单检查 | 每类文件独立输出，17个文件齐全 |
| QC-11 文件格式 | 格式检查 | 制度文件为DOCX，表格文件为XLSX |
| QC-12 格式合规验证 | 逐文件执行DF-01~09 + XF-01~06 | 全部通过或已标注"[格式存疑]"（见 §5.2a） |

### 5.2 多文件生成

按 output-spec.md §1.1 文件清单，逐一生成17个文件：

**DOCX文件生成（9个）**：

使用 python-docx（或调用docx skill）生成，遵循 output-spec.md §6.1 DOCX排版规格：

| # | 文件 | 内容来源 |
|---|------|---------|
| 1 | `{企业名称}-出口管制合规手册.docx` | Phase 2 产出的13章制度正文 |
| 2-8 | `SOP-01~SOP-07.docx` | Phase 3 产出的7套SOP |
| 9 | `{企业名称}-违规上报与调查流程.docx` | Phase 4.3 产出的违规流程 |

每个DOCX文件生成步骤：
1. 创建文档对象，设置页面（A4纵向+页边距）
2. 生成封面（企业名称+文件标题+版本号+发布日期+"内部底稿"水印）
3. 插入自动目录（TOC）
4. 按章节写入正文（标题层级+段落+表格）
5. 添加页眉（文件标题+版本号）+页脚（页码+"内部底稿"）
6. 保存为 .docx 文件

**XLSX文件生成（8个）**：

使用 openpyxl（或调用xlsx skill）生成，遵循 output-spec.md §6.2 XLSX排版规格：

| # | 文件 | 内容来源 |
|---|------|---------|
| 1-7 | `TM-01~TM-07.xlsx` | Phase 4.1 产出的7份表格模板 |
| 8 | `{企业名称}-角色职责矩阵.xlsx` | Phase 4.2 产出的角色矩阵 |

每个XLSX文件生成步骤：
1. 创建工作簿，添加Sheet 1（填写区）+Sheet 2（填写说明）
2. 写入表头（名称+编号+版本+日期），应用深蓝底色+白字样式
3. 写入字段行（字段名称+填写说明+示例值）
4. 冻结首行+首列
5. 设置列宽自适应+必填字段浅黄底色
6. 添加数据验证规则（下拉选项/日期格式/数字范围）
7. 添加签字区（底部合并单元格）
8. 保存为 .xlsx 文件

### 5.2a 格式合规验证（生成后必检）

**每个文件生成后立即验证**（不等到全部生成完），验证不通过则重新生成该文件：

**DOCX格式验证（9个文件逐一执行）**：

| # | 检查项 | 验证方法 | 不通过动作 |
|---|--------|---------|-----------|
| DF-01 | 页面尺寸为A4纵向 | 读取doc.sections[0].page_width/height | 重新设置页面后保存 |
| DF-02 | 页边距为上下2.54cm/左右3.18cm | 读取doc.sections[0].top_margin等 | 重新设置页边距 |
| DF-03 | 正文为宋体12pt | 读取第一个正文段落的runs[0].font | 重新设置字体 |
| DF-04 | 一级标题为黑体22pt加粗居中 | 读取Heading 1样式 | 重新设置标题样式 |
| DF-05 | 封面存在且含"内部底稿" | 搜索文档前5段落 | 重新生成封面 |
| DF-06 | 页眉含文件标题+版本号 | 读取doc.sections[0].header | 重新设置页眉 |
| DF-07 | 页脚含页码 | 读取doc.sections[0].footer | 重新设置页脚 |
| DF-08 | 合规手册须有TOC（目录） | 检查是否存在目录段落 | 插入TOC（合规手册专用） |
| DF-09 | SOP须有文件头表格 | 检查第一个表格为非空 | 重新生成文件头（SOP专用） |

**XLSX格式验证（8个文件逐一执行）**：

| # | 检查项 | 验证方法 | 不通过动作 |
|---|--------|---------|-----------|
| XF-01 | 含2个Sheet（填写区+填写说明） | 读取wb.sheetnames长度≥2 | 重新创建工作表 |
| XF-02 | Sheet 1 首行冻结 | 读取ws.freeze_panes不为None | 重新设置冻结窗格 |
| XF-03 | 表头行为深蓝底色+白字 | 读取A1.fill.start_color.rgb | 重新应用表头样式 |
| XF-04 | 必填字段有浅黄底色 | 扫描所有行检查标记字段的fill | 重新标记必填字段 |
| XF-05 | 签字区存在合并单元格 | 读取ws.merged_cells.ranges不为空 | 重新添加签字区 |
| XF-06 | 角色矩阵有颜色区分（绿色） | 扫描角色矩阵表检查权限分级行颜色 | 重新应用颜色 |

**重新生成规则**：
- 单项DF/XF检查不通过 → 修复该单项后重新保存（不重新生成整个文件）
- 2项以上不通过 → 重新生成整个文件
- 重新生成后再次验证，最多重试2次。2次后仍不通过 → 标注"[格式存疑]"+继续下一文件
