# 边界示例1 — 信息部分缺失的数据出境安全自评估报告

> 输入模式：Mode B（自然语言描述，信息不完整）
> 命中路径：安全评估（需确认）
> 信息完整度：低（境外法律环境+合同条款缺失+数量模糊）
> 降级状态：接近SOFT_DEGRADED阈值（2个必填参数需追问补全）

---

## 输入参数

```
data_processor_profile: "XX科技公司，做跨境业务"  # 模糊→追问补全
data_export_scenario: "需要把用户数据传到美国服务器"  # 模糊→追问补全
export_data_types_quantities: "大概几十万用户数据，有一些敏感的"  # 模糊→追问具体数字
overseas_recipient_info: "美国的一家云服务商"  # 模糊→追问补全
data_security_measures: "有加密和防火墙"  # 部分→追问补全
export_purpose_necessity: "业务需要"  # 模糊→追问补全
overseas_legal_env: ""  # 空→M6标注"待补充·需境外律师核实"
export_contract_terms: ""  # 空→M8标注"待补充·需提供合同文本"
```

---

## Phase 1 追问补全（3轮交互）

**追问第1轮**：
- 请提供XX科技公司的注册地+组织形式+主营业务
- 请提供出境数据的具体数量（个人信息XX万人+敏感信息XX万人）
- 请提供美国云服务商的名称+所在州

**追问第2轮**（假设部分回复）：
- 请提供数据安全措施的详细描述（管理措施+技术措施+应急处置）
- 请提供出境必要性理由的具体说明

**追问第3轮**（假设仍有缺失）→ 缺失2个必填参数，但仍可生成报告（缺口标注）

---

## 输出概览（含缺口标注的报告框架）

### M1 数据处理者基本情况

XX科技公司，[注册地待补充]，[主营业务待补充]...

### M2 数据出境业务场景描述

⚠️ **待补充·需追问补全**

需要补充的内容：
1. 出境场景业务背景与技术实现
2. 数据传输方式（API/文件/云端/邮件）
3. 传输频率和数据流向
4. 涉及的系统/平台/接口

### M3 数据出境目的和必要性分析

⚠️ **待补充·需追问补全**

需要补充的内容：
1. 合法性论证（PIPL第13条合法性基础）
2. 正当性论证（业务需要/公共利益）
3. 必要性论证（最小必要原则+境内替代可行性）

### M4 出境数据类型/数量/范围

个人信息：[数量待补充]万人
- 敏感个人信息：[类型和数量待补充]
- 重要数据：[是否涉及待确认]

### M5 境外接收方基本情况及安全能力评估

⚠️ **待补充·需追问补全**

需要补充的内容：
1. 接收方主体信息（名称/所在国/主营业务/组织形式）
2. 接收方安全管理制度评估
3. 接收方技术保护措施评估
4. 接收方数据保护认证/合规资质
5. 接收方历史数据安全事件

### M6 墄外接收方法律环境分析

⚠️ **本模块全部内容待补充·需境外律师核实**

需要补充的内容：
1. 美国数据保护法律框架（联邦+州法）
2. 美国政府调取数据权限（CLOUD Act+FISA+NSL）
3. 个人救济渠道
4. 与PIPL标准对等性评估

### M7 数据安全保护措施及能力

⚠️ **待补充·需追问补全**

需要补充的内容：
1. 管理措施（制度建设+人员管理+培训+审计）
2. 技术措施（加密+访问控制+脱敏+日志+监控）
3. 应急处置（事件响应+通报+恢复+复盘）
4. 全生命周期保护（收集→存储→使用→传输→销毁）

### M8 数据出境合同法律文件分析

⚠️ **待补充·需提供合同文本**

需要补充的内容：
1. 与美国云服务商签订的合同文本
2. 合同中的数据安全条款
3. 标准合同备案状态

### M9 自评估结论与风险缓解措施

**信息缺口汇总**：

| 模块 | 缺口项 | 法律含义 | 补全建议 |
|------|--------|---------|---------|
| M1 | 注册地/主营业务 | 主体适格性认定 | 提供工商登记信息 |
| M4 | 数据具体数量/敏感类型 | 安全评估阈值判断 | 提供数据分类分级报告 |
