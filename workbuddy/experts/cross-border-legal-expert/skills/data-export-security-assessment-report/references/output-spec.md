# 输出规格 — data-export-security-assessment-report

## 1. 输出格式

DOCX 格式报告（主格式，50-100页，正式申报/签发用）+ Markdown（辅格式，内部参考副本），严格遵循网信办标准模板九模块结构。纯文字叙述+结构化表格。

**格式严肃度**：F-Strict

**F-Strict 特定要求**：
- 禁止正文使用彩色标注、Richee组件等非黑白灰元素
- 允许在正文必要位置使用Markdown表格：M4出境数据范围表、M7安全措施清单表、M9残余风险矩阵表、附件数据清单表等结构化数据呈现场景。正文叙述性段落不使用表格。
- 禁止页脚（多页报告允许页码"— X —"居中，仿宋小四号，距底端1.5cm）
- 禁止混搭文书风格（选定"网信办模板填充风格"贯彻到底）
- 100%格式合规——网信办审查要求模板结构完整

## 2. 九模块输出结构

### M1 数据处理者基本情况

- 主体名称、组织形式、注册地、主营业务
- 数据处理能力和制度建设概述
- 数据分类分级管理现状
- 与M4的衔接：处理者情况决定数据范围认定

### M2 数据出境业务场景描述

- 出境场景概述（业务背景+技术实现+流程描述）
- 数据传输方式（API/文件/云端/邮件等）
- 传输频率和数据流向
- 涉及的系统/平台/接口

### M3 数据出境目的和必要性分析

- **合法性论证**：出境行为是否有法律依据
- **正当性论证**：出境是否符合公共利益/合同约定/业务需要
- **必要性论证**：是否为最小必要原则（是否可在境内实现同等目的）
- 必要性替代方案分析（境内替代可行性）

### M4 出境数据类型/数量/范围

- 数据分类（个人信息/敏感个人信息/重要数据/其他数据）
- 各类数据数量统计
- 具体字段清单（逐字段列出）
- **敏感信息专项标注**（数量+类型+敏感原因）
- 数据收集方式和来源

### M5 墄外接收方基本情况及安全能力评估

- 接收方主体信息（名称/所在国/主营业务/组织形式）
- 接收方安全管理制度评估
- 接收方技术保护措施评估
- 接收方数据保护认证/合规资质
- 接收方数据处理能力
- 接收方历史数据安全事件

### M6 墄外接收方法律环境分析

- **所在国数据保护法律框架**：有无立法+主要法律名称+核心制度
- **政府调取数据权限**：政府是否有权调取/监管/审查数据
- **个人救济渠道**：个人是否有数据保护申诉/诉讼权利
- **中国标准对等性评估**：该国数据保护标准是否与中国基本对等
- **法域叠加判断**（新增子模块）：
  - **(1) GDPR域外适用触发条件**（Art.3(2)）：如接收方位于EU/EEA或数据处理面向EU个人或涉及EU境内行为监控→触发GDPR域外适用→PIPL+GDPR双重合规义务
  - **(2) PIPL+GDPR双重合规路径冲突分析**：数据主体同意标准差异（PIPL单独同意 vs GDPR合法基础6类）、DPO/个人信息保护负责人设置义务差异、数据泄露通报时限差异（PIPL即时 vs GDPR72小时）、跨境传输机制差异（PIPL三类路径 vs GDPR adequacy/SCCs/BCRs）→标注冲突点并建议合规策略
  - **(3) CLOUD Act/FISA结构化分析**（如接收方位于美国或受美国管辖）：CLOUD Act强制披露义务范围（是否涵盖存储于境外数据）、FISA第702条外国情报监控对非美国人的数据调取、中美数据调取冲突下的合规路径（MLAT vs 申诉抗辩）、是否触发PIPL第41条"外国司法/执法机构调取境内数据审批"义务
  - ⚠️ 法域叠加分析全部标注**"需境外律师核实"**
- ⚠️ 本模块全部内容标注**"需境外律师核实"**

### M7 数据安全保护措施及能力

- **管理措施**：制度建设+人员管理+培训+审计
- **技术措施**：加密+访问控制+脱敏+日志+监控
- **应急处置**：事件响应+通报+恢复+复盘
- **全生命周期保护**：收集→存储→使用→传输→销毁各环节措施

### M8 数据出境合同法律文件分析

- 与境外接收方签订的合同概述
- 合同中的数据安全条款分析
- 标准合同备案状态（如适用）
- 合同约束力评估
- 合同违约救济条款
- **合同争议解决条款分析**（新增模块）：
  - **管辖约定**：合同约定的管辖法院/仲裁机构是否明确、是否对中方有利、是否存在管辖权冲突（如双方分别约定不同管辖）
  - **适用法选择**：合同选择适用法是否涵盖数据安全事项、是否与PIPL强制规定冲突（PIPL第38条等强制性规范不可协议排除）、适用法选择对中国数据主体权益的影响
  - **判决承认与执行**：境外判决/仲裁裁决在中国是否可依据《民事诉讼法》第284-289条承认与执行、是否存在互惠条约、执行障碍预判
  - ⚠️ 争议解决条款分析标注**"需境外律师核实"**
- 如未签合同 → 标注"待补充·需提供合同文本"

### M9 自评估结论与风险缓解措施

- **总体评估结论**：综合九模块分析结论
- **残余风险清单**：仍有风险的领域
- **缓解措施**：针对残余风险的具体缓解措施
- **持续监控建议**：出境后持续监控机制建议
- **有效期声明**：评估结论有效期（安全评估有效期3年）

## 3. 写作红线

### 3.1 通用红线（11条，引用 base）

本技能遵守 `base/shared/writing-redlines.md` 全部 11 条通用红线（WR-01~WR-11）。base 红线编号原样保留。

### 3.2 通用红线偏离项（3条）

| base 编号 | 偏离类型 | 偏离内容 |
|----------|---------|---------|
| **WR-07** | 补充 | 境外法条不确定时标注"[需境外律师核实]"（具体到base的"[需核实]"+境外律师），不只写"[需核实]" |
| **WR-10** | 补充（强化） | 本技能九模块必须全覆盖，任何模块不得以信息不足为由省略；缺失信息标注"待补充"占位而非删除模块 |
| **WR-11** | 强化 | 选定"网信办模板填充风格"贯彻到底——九模块严格按模板顺序填充，禁止混搭其他风格（如律师论证风格/学术论文风格等） |

### 3.3 技能专属红线（3条，本技能独有）

| # | 红线 | 说明 |
|---|------|------|
| WR-12 | 禁止保证评估通过 | 不保证安全评估申请必然通过审批；不写"必然通过""一定获批"等承诺性表述 |
| WR-13 | 禁止不利自认 | 不包含可能被监管利用的承认性表述（如"我方存在不足""明显违规"等可能被认定为不合规自认的内容） |

## DOCX 渲染规格（O1 主格式）

> 遵循 `base/rule/format-docx/` DOCX排版规范。

### 格式等级
- **格式严肃度**: F-Strict（法院文书级，仅黑白灰，无Richee组件）
- **主格式**: DOCX（正式申报/签发用）
- **辅格式**: Markdown（内部参考副本）

### DOCX排版要求
- 字体：宋体（正文）/黑体（标题），字号小四（正文）/四号（标题）
- 页边距：上3.7cm 下3.5cm 左2.8cm 右2.6cm
- 行距：1.5倍行距
- 页码：页脚居中
- 禁止：彩色标注、Richee组件、外部样式引用

### 风险标注方式（F-Strict无色标）
- 高风险：加粗+【高风险】前缀
- 中风险：斜体+【中风险】前缀
- 低风险：常规+【低风险】前缀
