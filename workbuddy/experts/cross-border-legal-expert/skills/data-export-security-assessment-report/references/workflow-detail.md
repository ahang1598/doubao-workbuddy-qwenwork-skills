# 工作流详情 — data-export-security-assessment-report

## Phase 1：输入验证与信息补全（L1）

**目标**：确保输入信息完整、准确，满足自评估报告生成所需全部参数。

### 步骤

1.1 识别输入模式（Mode A/B/C），按模式提取参数

1.2 必填参数完整性检查：
- 6个必填参数是否齐全（overseas_legal_env/export_contract_terms为可选，可为空，缺失时在M6/M8标注待补充）
- 数量参数是否为具体数字（不接受模糊表述）
- 敏感信息是否单独标注

1.3 上游技能衔接验证：
- 如有#24产出 → 验证路径判断结果是否为"安全评估"
- 如有#25产出 → 提取合规差距清单中的安全措施缺口
- 如有#26产出 → 引用PIA报告作为前置材料
- 如有#27产出 → 核查是否涉及出口管制物项

1.4 信息补全（最多3轮交互）：
- 缺失必填参数 → 追问
- 数量模糊 → 要求具体数字
- 超过3轮未补全 → 触发 SOFT_DEGRADED

### 输出

- 验证通过的完整参数集
- 或 SOFT_DEGRADED 降级输出

## Phase 2：数据出境场景定性与必要性分析（L2）

**目标**：完成M2和M3核心内容——出境场景描述和必要性论证。

### 步骤

2.1 数据出境场景定性：
- 确认出境行为是否构成法律意义上的"数据出境"
- 出境方式分类：传输/访问/委托处理
- 出境频率和数据流向描述

2.2 出境目的和必要性分析（M3核心）：
- **合法性论证**：
  - 出境行为是否有PIPL第13条合法性基础
  - 是否有合同约定或法定义务支持
- **正当性论证**：
  - 出境是否符合业务需要/公共利益
  - 是否有正当目的支撑
- **必要性论证**：
  - 是否为最小必要原则（境内替代可行性分析）
  - 出境数据是否为达成目的的最小范围
  - 是否存在冗余出境数据

2.3 CIIO专项分析（如 is_ciio=true）：
- CIIO认定依据说明
- CIIO出境必要性论证加强

2.4 自贸区专项分析（如属于自贸区）：
- 负面清单适用性分析

### 输出

- M2 出境场景描述段落
- M3 必要性分析段落

## Phase 3：出境数据范围与接收方评估（L3）

**目标**：完成M4和M5核心内容——数据范围梳理和接收方评估。

### 步骤

3.1 出境数据类型/数量/范围梳理（M4核心）：
- 数据分类：个人信息/敏感个人信息/重要数据/其他数据
- 各类数据数量统计（必须具体数字）
- 逐字段清单列出
- **敏感信息专项标注**（数量+类型+敏感原因+PIPL第28条对照）
- 数据收集方式和来源说明
- 多类型数据并行出境 → 每类数据单独列表

3.2 境外接收方基本情况及安全能力评估（M5核心）：
- 接收方主体信息（名称/所在国/主营业务/组织形式）
- 接收方安全管理制度评估（有无制度+制度完善度+执行情况）
- 接收方技术保护措施评估（加密/访问控制/日志/监控）
- 接收方数据保护认证/合规资质
- 接收方历史安全事件

### 输出

- M4 数据范围段落
- M5 接收方评估段落

## Phase 4：境外法律环境分析与安全措施评估（L3）

**目标**：完成M6和M7核心内容——境外法律环境分析和安全措施评估。

### 步骤

4.1 墄外接收方法律环境分析（M6核心）：
- **所在国数据保护法律框架**：
  - 是否有数据保护立法
  - 主要法律名称和核心制度概述
  - ⚠️ 全部标注**"需境外律师核实"**
- **政府调取数据权限**：
  - 政府是否有权调取/监管/审查数据
  - 调取程序和救济渠道概述
  - ⚠️ 标注**"需境外律师核实"**
- **个人救济渠道**：
  - 个人是否有数据保护申诉/诉讼权利
  - 救济程序概述
  - ⚠️ 标注**"需境外律师核实"**
- **中国标准对等性评估**：
  - 该国数据保护标准是否与中国PIPL基本对等
  - 对等性分析要点
  - ⚠️ 标注**"需境外律师核实"**
- **法域叠加判断**（新增子模块）：
  - (1) GDPR域外适用触发条件分析：接收方是否位于EU/EEA，或数据处理是否面向EU个人，或涉及EU境内行为监控→如触发，标注双重合规义务
  - (2) PIPL+GDPR双重合规路径冲突分析：同意标准差异/通报时限差异/跨境传输机制差异→标注冲突点并建议合规策略
  - (3) CLOUD Act/FISA结构化分析（接收方位于美国或受美国管辖时）：强制披露义务范围/FISA第702条/中美数据调取冲突/是否触发PIPL第41条审批义务
  - ⚠️ 法域叠加分析全部标注**"需境外律师核实"**
- 如 overseas_legal_env 为空 → 全模块标注"待补充·需境外律师核实"

4.2 数据安全保护措施及能力评估（M7核心）：
- **管理措施**：制度建设+人员管理+培训+审计+考核
- **技术措施**：加密+访问控制+脱敏+日志+监控+入侵检测
- **应急处置**：事件响应+通报+恢复+复盘+改进
- **全生命周期保护**：收集→存储→使用→传输→销毁各环节措施
- 如有#25产出 → 对照差距清单，标注缺口项

### 输出

- M6 境外法律环境分析段落
- M7 安全措施评估段落

## Phase 5：九模块报告组装与信息缺口标注（L3）

**目标**：组装完整九模块报告，标注所有信息缺口。

### 步骤

5.1 M8 数据出境合同法律文件分析：
- 如有 export_contract_terms → 分析合同安全条款
- 如无 → 标注"待补充·需提供合同文本"
- 标准合同备案状态（如适用）
- 合同约束力评估
- **合同争议解决条款分析**（新增模块）：
  - 管辖约定：合同约定管辖法院/仲裁机构是否明确、是否对中方有利、是否存在管辖权冲突
  - 适用法选择：合同适用法是否涵盖数据安全事项、是否与PIPL强制规定冲突
  - 判决承认与执行：境外判决/仲裁裁决在中国是否可承认与执行、是否存在互惠条约、执行障碍预判
  - ⚠️ 争议解决条款分析标注**"需境外律师核实"**

5.2 M9 自评估结论与风险缓解措施：
- 综合九模块分析结论
- 残余风险清单
- 缓解措施建议
- 持续监控建议
- 有效期声明（安全评估有效期3年）

5.3 九模块报告组装：
- 按网信办模板顺序组装（M1→M2→M3→M4→M5→M6→M7→M8→M9）
- **严格九模块顺序，不得增删重排**
- 每模块内信息缺口标注"待补充"

5.4 全报告信息缺口汇总表：
- 列出所有"待补充"项
- 按模块分组
- 标注缺失信息的法律含义

### 输出

- 完整九模块 Markdown 格式报告（50-100页）

## Phase 6：质量检查与降级处理（L3）

**目标**：确保输出质量，强制律师复核提醒。

### 步骤

6.1 九模块完整性检查：
- 模块数是否为9个
- 每模块是否非空
- 模块顺序是否正确

6.2 法条引用一致性检查：
- 报告中引用法条是否与 legal-references.md 一致
- 是否标注"以申报时生效版本为准"
- 境外法律是否标注"需境外律师核实"

6.3 信息缺口标注检查：
- 是否有未标注"待补充"的信息缺口
- 缺口汇总表是否完整

6.4 写作红线检查（11条通用+3条偏离+3条专属=17条）：
- 逐条检查 output-spec.md §3 红线（通用11+偏离3+专属3）
- 不合格项返回 Phase 5 修正

6.5 L3 强制律师复核提醒：
- 输出末尾必须包含"⚠️ 本报告须数据合规律师审核后方可作为正式申报材料"
- 标注关键不确定性项

6.6 降级检查：
- 判定口径：按"无法通过追问补全"的模块数（而非必填参数缺失数）触发降级
- 必填参数缺失≥3个 → 触发 SOFT_DEGRADED（与 input-spec.md §4 一致）
- 超过3轮交互仍未补全 → 触发 SOFT_DEGRADED
- 4个以上模块为"无法补全的待补充"（如境外法律环境空、合同文本缺失且企业确认无法提供）→ 触发 SOFT_DEGRADED
- 区别对待：标注"待补充·需追问"（可补全）的模块不计入降级统计；标注"待补充·需境外律师核实"或"待补充·需提供合同文本"（用户无法补全）才计入
- 降级输出 C+D+G 最小骨架

### 输出

- 质量检查通过的报告
- 或标注不确定性的降级报告
