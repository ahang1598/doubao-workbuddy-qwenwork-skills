# Software and Technology Development Review Cards

中文类型：软件与技术开发协议

These internal cards are general issue-spotting aids. Apply them as `[惯例]`
and verify current law for the governing law and each performance jurisdiction.

## DEV-R01 Scope and Agile Governance / 范围与敏捷治理
- Check: 需求基线、产品负责人、待办优先级、冲刺、完成定义和决策证据。
- Red flags: 以敏捷为由不设范围边界；口头优先级自动改变价格。
- Missing protection: 治理角色、记录工具、假设和排除项。
- Linked clauses: 变更、费用、验收
- Default risk: high.
- Mandatory-law check: 电子记录、行业资质及项目特定监管要求。

## DEV-R02 Milestones and Acceptance / 里程碑与验收
- Check: 阶段成果、环境、测试数据、客观标准、缺陷等级、修复重测。
- Red flags: 沉默或生产使用自动验收；未区分缺陷严重度。
- Missing protection: 重复失败、部分验收、回退和退款终止。
- Linked clauses: 付款、保证、退出
- Default risk: high.
- Mandatory-law check: 法定质量、网络安全和特定软件验收规则。

## DEV-R03 Background and Developed IP / 背景与开发成果权利
- Check: 背景工具、定制代码、通用组件、文档、模型、数据和改进。
- Red flags: 客户付款却仅获模糊许可；开发方背景资产未列明。
- Missing protection: 源代码权利、回授许可、人员权属和登记协作。
- Linked clauses: 交付、保密、退出
- Default risk: high.
- Mandatory-law check: 委托开发、职务成果、共同开发和技术合同规则。

## DEV-R04 Open Source and Third-Party Materials / 开源与第三方材料
- Check: 批准流程、许可证、清单、传递义务、安全和替代。
- Red flags: 可任意引入强传染许可；第三方费用和限制未披露。
- Missing protection: SBOM、预批准、许可证兼容和替换义务。
- Linked clauses: 知识产权保证、赔偿、维护
- Default risk: high.
- Mandatory-law check: 开源许可证、出口和第三方权利。

## DEV-R05 Security, Documentation and Continuity / 安全、文档与连续性
- Check: 安全开发、代码库、访问、文档、备份、托管和人员流失。
- Red flags: 关键代码仅存开发方环境；无构建说明或管理员凭证。
- Missing protection: 代码交付频率、托管触发、知识转移和灾备。
- Linked clauses: 验收、退出、保密
- Default risk: high.
- Mandatory-law check: 数据安全、关键系统和监管外包要求。

## DEV-R06 Delay, Warranty and Exit / 延误、保证与退出
- Check: 延误归责、依赖、修复保证、责任、在制品、移交和过渡。
- Red flags: 所有延误均归客户；项目终止后无可用成果或文档。
- Missing protection: 恢复计划、费用结算、在制成果许可和过渡支持。
- Linked clauses: 里程碑、责任、终止
- Default risk: high.
- Mandatory-law check: 违约金调整、不可排除责任和技术出口。

## Family Routing
- Aliases: software development agreement, technology development, custom development, agile development, 软件开发, 技术开发.
- Typical roles: developer, customer.
- Distinguish from: 仅提供现成软件使用权选许可；一般咨询且无技术成果选专业服务。
