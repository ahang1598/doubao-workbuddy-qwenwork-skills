# 合同审查方法论内核（共享内核 · SSOT）

> fadada / english 两技能共用的审查方法与执行控制规则单一真源（D1 方法 + D5-S7 纠错）。

## 1. 先结构硬校验，后条款审查

进入逐条审查前，先把交易当作系统建模并硬校验关键结构参数：
**领域 / 标的 / 排他性 / 当事方 / 权利方向 / 期限 / 对价经济 / 控制 / 退出**。
任一与交易意图不符即先标记，再进入条款审查。

## 1.5 法规依据检索核验（写 [法规] 前必做）

写任何 `[法规]` 依据前，先**经法规检索技能检索并核验条文原文与现行有效性**，不得凭记忆引法条：
中文法 → 「中国法律检索」技能（`skills_download/法律检索专家`，联网验证 + 北大法宝 MCP）；
英文/美国法 → Descrybe MCP `verify_quote` / `search_laws_and_rules`。命中→引核验后的条文原文（「」摘录）；
未命中 / 检索不可用 / 法域不覆盖 → 标 `待核查`，不写裸 `[法规]`、不出确定法律结论。详见 `evidence-labels.md` §3。

## 2. 双向审查（forward + reverse）

- **正向**：扫描已存在的有害条款（harmful terms）。
- **反向**：扫描应有而缺失的保护条款（missing protections）。
反向覆盖统计须纳入审查报告。

## 3. 四遍法

transaction（交易）→ clauses（条款）→ risk（风险）→ precision（精度一致性）。
精度遍核查：定义、交叉引用、日期、金额、救济、双语优先级是否存在不一致。

## 4. 双方权利对称比较

对比双方实质权利义务。当事方一律用「真实名称 + 角色」标注（如 `[公司名]（卖方）`），
禁止输出裸占位符 `客户`。无立场声明时，按合同类型与签署姿态推定主受险方，
在「事实与假设」段显式声明该推定，并注明「如立场相反请告知后重审」；此类审查不得标 `中立`。

## 5. 重大修订级联核查

任一重大修订后，级联核查受影响的定义、交叉引用、金额与救济，避免改一处崩一处。

## 6. 执行控制：自检 + 换策略 + 熔断（D5-S7）

- 每个交付物关口（deliverable gate）执行自检（自检）。
- 自检不通过时**换策略**（换参数 / 换数据源 / 降级路径），**不得原路重试**。
- **熔断**：同一步骤两种不同策略均失败 → 停止该路径，汇报卡点与已完成进度，转人工。
- 对任何外部 agent / 子技能调用：预设时间预算；超时即停止汇报，不无限等待。

## 7. Redline 编排纪律（避免过度批注）

修订稿（redline）的默认产物是**修订痕迹**，不是批注堆。编排操作时遵守：

- **高/中风险默认落为文本修订**（`replace` / `replace_text`，产生 OOXML `<w:ins>/<w:del>`）。
  凡能给出具体替换措辞的发现，必须写成修订操作，让审查方在痕迹上看到改法。
- **`comment`（comment-only）是例外，且必须带 `comment_only_reason`**，仅限三类：
  1. 事实确认 / 待签署填写项（如地址、签约方待定）；
  2. 信息缺口 / 不得臆断项（如准据法占位未填——不臆断准据法，标 `待核查`）；
  3. 需整条新增的独立条款（如增订 CISG 排除条款，宜由当事人在恰当位置插入）。
- **自检指标**：交付前核对 redline 中 `<w:ins>/<w:del>` 数应≥高+中风险里非上述三类例外的条数；
  若高/中风险几乎全是 comment、修订痕迹寥寥，即为「过度批注」反模式，须回头把可改写项落为修订。
- 报告中每条风险的处置标注（已修订 / 已批注待确认）必须与 redline 实际操作一致，不得报告称"已批注"而 redline 已改、或相反。

## 8. 一致性纪律（同一合同+同一规则多次运行偏差最小化）

偏差几乎全在 LLM 判断层；目标是**决策层一致**（命中风险集合、各自等级、处置方式），措辞可不同。

- **清单全覆盖、固定遍历序**：风险识别必须逐条遍历规则集（用户清单/iTerms/review-matrix 族卡/12通用规则），
  按规则号顺序产出每条规则的 `{命中?, 等级, 证据para, 建议}`；不靠开放式自由发挥。两次运行覆盖同一规则集、同一顺序。
- **等级查表，不临场判**：每条规则预设默认严重度（影响×概率矩阵→等级映射）；仅在有明确、可记录理由时偏离默认并注明。
- **稳定标识**：`issue_id` 由 `(rule_id, para_id)` 确定性派生，不随机编号；命中同一条款同一规则两次运行得同一 `issue_id`。
- **结构化 + 低温**：评级/分级步输出受 schema 约束、用低温度解码，削采样随机性。
- **处置纪律承 §7**：高/中风险默认落修订，例外才批注——处置方式由规则性质决定而非临场选择。
- **可证一致**：交付后用 `tests/review_consistency_check.py` 对多次运行的结构化产物算偏差度
  （集合 Jaccard / 等级一致率 / 处置一致率），超门限即视为不稳定，须回查规则覆盖与等级查表。
  判定默认按**小样本口径**（发现并集 ≤10）：以 **≤1档漂移率(≥0.95)+处置一致率(≥0.90)** 为主门限、
  集合 Jaccard 放宽至 0.80，等级完全一致率仅作参考；大样本或 `--strict` 时完全一致率(≥0.85)参与门限。
  理由：小发现集里 1 个借界项即拉低 ~1/n，完全一致率过度敏感，而真正要守的是"无重判(≤1档)+处置稳定"。
- **必须一致的场景**：对 `hash(规范化合同文本 + 规则集)` 命中的已核准历史审查，复用结论、只重评变化条款（幂等冻结）。
  检索取得并核验的 `[法规]` 条文原文随结论纳入冻结快照，复审直接复用，避免重复检索与原文漂移。
