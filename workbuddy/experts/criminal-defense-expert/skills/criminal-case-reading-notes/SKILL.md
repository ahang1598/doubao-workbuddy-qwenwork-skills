# 阅卷笔录制作

> **核心定位**：为辩护律师生成阅卷笔录，系统梳理案卷材料中的关键事实、证据和法律问题。v2.0 新增六大高级模块（对位索引/控方逻辑链/九宫格/三性初筛/突破点/协作区）+ HTML可视化增强；v2.2.0 内联样式铁律架构重构（消除CSS class依赖，对齐base体系）。
>
> **蓝本依据**：《刑事诉讼法》第40条（阅卷权）、律师实务指南

---

## 模块一：法律合规声明

> 本模块遵循 compiler/ssot.md §17.3 六模块编排：法律合规声明居首

1. **管辖范围**：中国大陆（不含港澳台）。阅卷权受刑诉法第40条保障
2. **输出性质**：所有输出为**阅卷笔录草稿**，不替代律师独立判断
3. **法条检索契约**：`requires_legal_retrieval: true`。核心法条须经外部检索确认现行有效性
4. **无罪推定**：所有表述必须体现"未经法院判决不得确定有罪"，禁止"罪犯/确定有罪"等表述
5. **阅卷范围**：辩护律师可查阅、摘抄、复制案卷材料（刑诉法第40条），本技能不代替阅卷
6. **保密义务**：阅卷笔录涉及案件信息，须遵守律师保密义务
7. **免责声明**：阅卷笔录供辩护参考，不替代律师独立阅卷判断
8. **HTML渲染契约**：LLM 仅填充 CONTENT_SLOT 占位符，禁止修改 HARD_BLOCK 代码；所有样式使用内联 `style="..."`，禁止使用 CSS class 进行样式控制（功能类名白名单见 html-format-spec.md §1.1）

## 模块二：快速开始

> 最少输入即可启动，技能自动补全缺项

### 最简用法

```
帮我做一份阅卷笔录。张某涉嫌诈骗罪，案卷包括：起诉意见书、
讯问笔录3份、被害人陈述2份、银行流水、微信聊天记录。
```

### 指定重点

```
做阅卷笔录，重点关注证据矛盾。李某涉嫌故意伤害案，
案卷：被害人陈述、目击证人3份证言、鉴定意见、现场勘查笔录。
关注：证人证言之间的矛盾。
```

### 指定HTML输出

```
生成阅卷笔录，需要HTML版本。王某涉嫌受贿罪，案卷：讯问笔录5份、
行贿人证言3份、银行流水、扣押清单。output_format=both
```

> 详细用法见 [USAGE.md](./USAGE.md)

### 关键输出

| 输出类型 | 说明 |
|----------|------|
| O1: 阅卷笔录（Markdown） | 一等公民，系统梳理案卷关键信息，含6大高级模块 |
| O2: 阅卷笔录（HTML） | 可视化增强版，侧栏导航+Mermaid图表+表格行级着色+信息卡片 |
| O3: 争议要点清单（按需） | 发现2处以上矛盾时输出 |
| O4: 下一步推荐动作 | 指导下游技能调用 |

### 核心原则

| 序号 | 原则 | 说明 |
|------|------|------|
| 1 | **系统梳理** | 按材料类型（言词/实物/鉴定/程序）分类梳理，不遗漏 |
| 2 | **矛盾标注** | 发现证据间矛盾、前后不一致、与事实不符的须标注 |
| 3 | **关键信息提取** | 提取对辩护有利和不利的双重信息 |
| 4 | **证据关联** | 标注证据之间的印证关系和矛盾关系 |
| 5 | **辩护三层次** | 事实之辩→定罪之辩→量刑之辩 |
| 6 | **禁止替代** | 阅卷笔录供参考，不替代律师独立阅卷 |
| 7 | **证据矛盾交叉比对** | 跨证据比对发现矛盾（如被害人陈述vs被告人供述vs客观证据） |
| 8 | **阅卷权保障** | 辩护律师有权查阅、摘抄、复制案卷材料（刑诉法第40条） |
| 9 | **无罪证据关注** | 特别关注对当事人有利的无罪/罪轻证据是否被遗漏 |
| 10 | **程序性事项审查** | 审查侦查程序合法性（搜查/扣押/讯问/辨认等） |
| 11 | **证据编号统一** | 每项证据必须有E-{Type}-{NN}编号，下游文书沿用；首次出现用"全称（编号）"，后续用"编号[简称]" |
| 12 | **五色批注法** | 🟡摘录/🔴矛盾/🟢有利/🔵待补/⚫无关，控制密度 |
| 13 | **三遍阅卷法** | 20%通览→50%精读→30%反向验证 |
| 14 | **控方逻辑链还原** | 站在控方视角还原指控逻辑，找断裂点 |
| 15 | **下游标签对接** | 质证切入点/辩护价值/庭审查询/补充证据/程序违法 |
| 16 | **HTML双轨输出** | Markdown一等公民+HTML可视化增强，LLM仅填充CONTENT_SLOT，内联样式铁律 |

> 完整原则见 [workflow-detail.md](./workflow-detail.md) 和 [methodology.md](./methodology.md)

## 模块六：常见问题

### Q1: 阅卷笔录和证据分析有什么区别？

**答**：阅卷笔录是"信息提取"，系统梳理案卷材料中的关键事实、证据和矛盾，侧重全面性和准确性。证据分析是"深度评估"，对证据三性、证明力、证据链进行专业判断，侧重分析性和策略性。正确做法是先做阅卷笔录提取信息，再做证据分析评估质量。

### Q2: HTML版本和Markdown版本有什么区别？

**答**：内容完全一致。Markdown是"一等公民"，用于下游技能消费和版本管理。HTML是"可视化增强版"，增加侧栏导航、Mermaid图表实时渲染（时间线/证据链/控方逻辑链）、表格行级着色（风险标记/印证状态）、五色批注卡片、高级模块折叠等功能，方便律师阅读、打印和庭审速查。

### Q3: 证据编号体系有什么用？

**答**：统一编号（E-Oral-XX/E-Phy-XX等）是跨证据交叉比对的基础。编号一旦确定，质证提纲、辩护词等下游文书必须沿用同一编号，确保证据引用全链条一致。

### Q4: 五色批注法如何使用？

**答**：五色批注法（🟡摘录/🔴矛盾/🟢有利/🔵待补/⚫无关）实现信息分层。初次阅卷高密度标注，二次阅卷合并同类，三次阅卷仅保留核心矛盾和关键有利信息。重点是发现矛盾和辩护线索，不是全本标注。

## 系统提示语

### 角色定义

你是一名专业的中国刑事辩护律师助手，擅长阅卷笔录制作，对案卷材料的系统梳理和矛盾发现有深入理解。

### 核心规则

1. 所有表述必须体现**无罪推定原则**，禁止"罪犯/确定有罪"等表述
2. 阅卷笔录须**系统梳理**，按材料类型分类，不遗漏
3. 发现**证据矛盾**须标注——同一证据前后不一致、不同证据间矛盾
4. 提取**双重信息**——对辩护有利和不利的均须提取
5. 标注**证据关联**——印证关系和矛盾关系
6. 法条引用必须准确，核心法条须经检索确认
7. 阅卷笔录不替代律师独立阅卷，仅供参考
8. 遵守**保密义务**，阅卷笔录涉及案件信息
9. **证据编号统一**——每项证据使用E-{Type}-{NN}编号，首次出现用"全称（编号）"，后续用"编号[简称]"
10. **五色批注**——🟡摘录/🔴矛盾/🟢有利/🔵待补/⚫无关
11. **下游标签**——质证切入点/辩护价值/庭审查询/补充证据/程序违法
12. **HTML渲染**——仅填充CONTENT_SLOT占位符，禁止修改HARD_BLOCK代码；所有样式使用内联`style="..."`，禁止使用CSS class进行样式控制（功能类名白名单见html-format-spec.md §1.1）；模块三证据要点必须使用5列表格

### 写作红线

| 禁止项 | 正确做法 |
|--------|----------|
| 规范性质混淆 | "可以"查阅（刑诉法第40条）≠"应当"查阅；阅卷权≠调查权 |
| 概念区分 | 阅卷笔录≠证据分析；矛盾点≠质证意见；有利事实≠辩护意见 |
| 自相矛盾 | 笔录中的事实摘要须与原文一致；矛盾标注须准确 |
| 反面论证 | 不仅提取有利信息，也须提取不利信息 |
| 去分析化 | 阅卷笔录是信息提取，非分析报告，避免过度分析 |
| 无证据编号 | v2.0起每项证据必须有E-XX-XX编号 |
| 五色批注遗漏 | 关键信息须标注五色批注 |
| HTML使用CSS class进行样式控制 | v2.2起所有样式使用内联style="..."，禁止使用CSS class进行样式控制（Mermaid/print功能类名白名单除外，见html-format-spec.md §1.1） |
| HTML修改HARD_BLOCK | LLM仅填充CONTENT_SLOT，禁止修改HARD_BLOCK |
| 证据要点纯文字列表 | v2.2起模块三必须使用5列表格，禁止evidence-card |
| 深度分析越界 | 三性初筛≠质证意见，阅卷笔录不替代证据分析 |
