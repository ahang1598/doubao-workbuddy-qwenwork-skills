# 输入规格

> 本文件定义 criminal-case-reading-notes v2.0.0 技能的完整输入参数规格
> 遵循 compiler/ssot.md §17（SSOT）：输入宽容度契约

## 1. 必需输入

| 字段 | 类型 | 枚举值 | 说明 | 验证规则 |
|------|------|--------|------|----------|
| `case_name` | string | - | 案件名称（被告人+罪名） | 非空 |
| `case_materials` | string | - | 案卷材料描述 | 非空 |
| `reading_perspective` | enum | defense/prosecution/third_party | 阅卷视角 | 必须为枚举值 |

## 2. 可选输入

### 2.1 案件基本信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `alleged_crime` | string | [待补充] | 涉嫌罪名 |
| `case_stage` | enum | 审查起诉 | 侦查/审查起诉/一审/二审 |
| `suspect_name` | string | [待补充] | 犯罪嫌疑人/被告人姓名 |
| `case_number` | string | [待补充] | 案号 |

### 2.2 阅卷范围

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `volumes_count` | number | [待补充] | 卷宗册数 |
| `focus_areas` | array[string] | [] | 重点关注领域 |
| `time_period` | string | [待补充] | 案件时间跨度 |
| `key_dates` | array[string] | [] | 关键时间节点 |

### 2.3 阅卷参数

| 字段 | 类型 | 枚举值 | 默认值 | 说明 |
|------|------|--------|--------|------|
| `organization_method` | enum | chronological/thematic/dispute | thematic | 笔录组织方式 |
| `detail_level` | enum | quick/standard/deep | standard | 详细程度（影响高级模块折叠策略） |
| `focus_crimes` | array[string] | [] | [] | 重点罪名（多罪名时） |

### 2.4 输出格式参数（v2.0新增）

| 字段 | 类型 | 枚举值 | 默认值 | 说明 |
|------|------|--------|--------|------|
| `output_format` | enum | markdown/html/both | both | 输出格式（markdown一等公民+html可视化增强） |

## 3. 输入宽容度契约

### 3.1 最小输入识别

| 最小输入 | 处理方式 |
|----------|----------|
| 仅案件名称+卷宗描述 | 生成阅卷笔录框架 |
| 仅"阅卷"/"笔录" | 询问案件信息 |
| 自然语言描述 | 提取结构化字段 |

交互补全最多3轮。

### 3.2 输出格式自动推断

| 用户表述 | 推断结果 |
|----------|----------|
| "帮我做阅卷笔录" | output_format=both（默认） |
| "需要HTML版本" | output_format=html |
| "只需要Markdown" | output_format=markdown |
| "要打印的版本" | output_format=html（提示可打印） |
| "给团队共享" | output_format=both |

## 4. 场景适配规则

### 4.1 组织方式适配

| organization_method | 说明 | 适用场景 |
|---------------------|------|----------|
| chronological（时间线） | 按事件发生时间组织 | 事实脉络复杂、时间线长 |
| thematic（主题） | 按主题/模块组织 | 通用方式，最常用 |
| dispute（争点） | 按争点组织→正反证据 | 准备质证/辩论时 |

### 4.2 阅卷视角适配

| 视角 | 关注重点 | 典型用户 |
|------|----------|----------|
| defense | 证据弱点+程序问题+有利事实+突破点 | 辩护律师 |
| prosecution | 证据链完整性+证明力+补强+逻辑链完整性 | 公诉人 |
| third_party | 客观记录+全面梳理 | 法官/学者 |

### 4.3 阶段适配

| 阶段 | 可阅卷范围 | 笔录重点 |
|------|-----------|----------|
| 侦查 | 有限（律师会见受限） | 事实确认+权利保障 |
| 审查起诉 | 全部卷宗 | 事实核查+证据分析+辩护方向+控方逻辑链还原 |
| 一审 | 全部卷宗+补充 | 质证准备+辩论准备+九宫格对比 |
| 二审 | 一审卷宗+二审材料 | 一审判决批判+新证据评估 |

### 4.4 详细程度适配（v2.0新增）

| detail_level | 输出范围 | 高级模块 | 适用场景 |
|--------------|----------|----------|----------|
| quick | 基础六模块 | 不渲染 | 快速浏览/初次阅卷 |
| standard | 全部十二模块 | 默认折叠 | 通用（默认） |
| deep | 全部十二模块 | 全部展开 | 深度阅卷/复杂案件 |
