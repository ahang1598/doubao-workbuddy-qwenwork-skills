# 标准示例001：电信诈骗案微信证据分析

> criminal-electronic-evidence-analysis | 标准示例 | v1.1.0

## 输入

```
分析这个案件的电子证据。张某涉嫌电信诈骗罪，案件信息：
- 案件名称：张某涉嫌电信诈骗案
- 涉嫌罪名：电信诈骗罪
- 罪名类型：T1

证据清单：
1. 扣押手机1部（华为Mate40，SN:HW2024001），扣押清单列明，封存状态完好
2. 微信聊天记录截图12张（无哈希值，从手机截图提取）
3. 支付宝交易流水PDF（SHA-256: 3a7bd...e8f2c，由支付宝公司调取）
4. 手机取证报告（未附完整性校验值）

哈希值：
- E01: SHA-256 d4f5e6...a1b2c3（提取时）
- E03: SHA-256 3a7bd...e8f2c（调取时）

扣押清单：华为Mate40手机1部、身份证1张

辩护视角：罪轻辩护（金额有争议，部分系正常交易）
```

## 预期输出特征

- **O1 解构清单**：4项证据逐条解构，E02（微信截图）无哈希值标注"原始性可质疑"
- **O2 12维度报告**：
  - A2完整性核验：E01哈希值三段一致→完整；E02无哈希值→存疑；E04未附校验值→缺失
  - A3取证程序：E01扣押规范→合规；E02截图提取无笔录→瑕疵（第27条）
  - B5主体同一性：微信ID→手机号→实名认证映射链评估
  - C10关联性切断：微信使用≠本人操作（共享手机可能性）
  - C11合法性排除：E02无哈希值+截图非原始数据→第28条排除可能性
- **O3 三维映射**：人物关系图（张某-受害人-第三方账户）+资金流时间线
- **O4 下游动作**：P0-对E02申请排除（2016规定第28条）；P1-调取微信原始数据；P2-核实E01哈希值三段一致性

## 关键验证点

| 验证项 | 预期 |
|--------|------|
| T1罪名路由 | 激活电信诈骗专攻审查点（A2聊天记录原始性+A4 VoIP审批+B5微信映射链） |
| 哈希值审查 | E02无哈希值显性标注，风险等级提升 |
| 瑕疵vs非法 | E02截图提取无笔录→第27条瑕疵（可补正）；若E02经审查发现篡改→第28条非法 |
| 设备≠人 | 微信账号使用需论证主体同一性，不能直接等同 |
| 12维度完整 | A1-A4/B5-B8/C9-C12共12维度全部有评估结论 |
