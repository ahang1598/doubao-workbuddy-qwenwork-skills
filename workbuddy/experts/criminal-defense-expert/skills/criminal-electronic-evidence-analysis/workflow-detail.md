# 刑事电子证据分析 — 工作流详述

> 本节遵循 compiler/ssot.md §17（SSOT）：可维护度约束

## Phase 拆解

```
Phase 1: 信息采集与罪名路由  [风险等级: L1]
  输入: case_name + alleged_crime + evidence_list + 可选输入
  核心动作:
    1. 校验必需输入
    2. 识别罪名类型 → 路由到T1-T5或通用
    3. 识别证据形式 → 分类标记
    4. 标注缺失项 → 启动降级路径
  输出: 结构化输入数据 + 罪名路由结果 + 缺失项清单
  门控: evidence_list非空
  降级触发: hash_values/forensic_report/media_inventory缺失
  降级动作: 标注缺失 + 继续分析

Phase 2: A组基础维度分析（能不能用）  [风险等级: L2]
  输入: Phase 1输出
  核心动作:
    A1 载体识别：逐一标注证据来源设备/介质/云端位置，已扣押vs未扣押；微信截图vs原始数据库区分
    A2 完整性核验：哈希值比对、原始存储介质封存状态、原始性可质疑空间；哈希值不一致时的降级策略（系统性变化vs针对性篡改→第27条瑕疵vs第28条非法）
    A2.5 保管链连续性审查：扣押→提取→检查→移送→展示，每个环节的交接记录+签名+校验值（2016规定第18-21条）
    A3 取证程序合法性：扣押清单vs实物、见证人在场、笔录签名（2016规定第7/8/14/15/24条）；写保护设备审查（第24条第(四)项）；镜像vs逻辑提取区分
    A4 收集方式合法性：远程勘验/技侦/在线提取的授权与权限（2019规则第23-35条）；云存储数据跨境取证审查（《数据安全法》第36条）
  输出: A1-A4+ A2.5五维度评估结论
  门控: A1-A4+ A2.5全部有评估结论
  降级触发: 哈希值缺失（A2受限）、扣押清单缺失（A3受限）、保管链记录缺失（A2.5受限）
  降级动作: 标注"基于不完整信息" + 风险等级提升

Phase 3: B组内容解构分析（说了什么）  [风险等级: L2]
  输入: Phase 2输出 + evidence_list内容
  核心动作:
    B5 主体同一性：微信号/QQ/支付宝UID/手机号/银行账号 ↔ 真实身份映射（2016规定第25条）
    B6 时间线重建：按时间戳还原行为链（资金流/信息流/物流交叉）
    B7 多源印证：电子数据 vs 言词证据 vs 传统实物证据的印证关系
    B8 删除/篡改痕迹：已删除数据恢复、修改痕迹、文件元数据分析
  输出: B5-B8四维度评估结论 + 时间线 + 映射关系
  门控: B5-B8全部有评估结论
  降级触发: 内容摘要缺失（B5/B6受限）
  降级动作: 标注"内容不足，分析受限" + 列出待补充信息

Phase 4: C组辩护点发现分析（对辩方有什么用）  [风险等级: L2]
  输入: Phase 2-3输出
  核心动作:
    C9 客观性挑战点：数据来源/传输/存储中可能污染的环节
    C10 关联性切断点：把"被告在场"切断为"设备在场"
    C11 合法性排除点：取证主体不适格、程序倒置、技侦越界（2016规定第27/28条）
    C12 量刑有利点：电子数据反映的自首/立功/退赃/悔罪
  输出: C9-C12四维度评估结论 + 辩护点清单
  门控: C9-C12全部有评估结论
  降级触发: 无（基于A/B组结论推演）
  降级动作: 无

Phase 5: 产物组装与输出  [风险等级: L1]
  输入: Phase 2-4全部输出
  核心动作:
    1. 组装电子证据解构清单（O1）
    2. 组装12维度评估报告（O2）
    3. 生成主体-行为-资金三维映射（O3）
    4. 生成可执行下游动作清单（O4）
    5. （可选）生成HTML可视化报告（O5）
  输出: 5件套完整产物
  门控: O1-O4完整
  降级触发: O3三维映射数据不足
  降级动作: 生成简化版映射 + 标注"数据不足，映射为示意性"
```

## 快速路径 vs 完整路径

| 路径 | 触发条件 | 执行 Phase | 跳过内容 |
|------|---------|-----------|---------|
| 快速路径 | 单项电子证据 + 无鉴定意见 + 无哈希值 | Phase 1→2→4→5 | Phase 3中B6/B7简化 |
| 完整路径 | 多项电子证据 + 有鉴定意见 + 有哈希值 | Phase 1→2→3→4→5 | — |

### 快速路径底线：不可简化维度

即使走快速路径，以下维度**不可简化**，必须逐项审查：

| 不可简化维度 | 理由 |
|------------|------|
| A2 完整性核验 | 哈希值状态是电子数据审查的核心，简化将导致分析基础崩塌 |
| A3 取证程序合法性 | 取证程序是最高频辩护点，简化将遗漏关键排除点 |
| A2.5 保管链连续性 | 保管链断裂直接影响证明力，不可省略 |
| C11 合法性排除点 | 排除点是辩护的核心产出，简化将使分析失去价值 |

> **风险提示**：单项证据但案件重大（可能判5年以上），即使符合快速路径条件也应走完整路径。快速模式的风险不在于"快"，而在于"律师以为够快了但实际不够快"——即律师以为单项证据简单，结果庭审中发现这个证据是定罪关键。

## 罪名路由差异

### T1：电信诈骗 — 专攻审查点

| 维度 | 专攻重点 | 法条依据 |
|------|---------|---------|
| A2 | 聊天记录截图的原始性（截图vs原始数据库，是否从扣押手机提取） | 2016规定第8条 |
| A4 | VoIP通话记录的提取方式（是否经远程勘验审批） | 2019规则第27条 |
| A4 | 跨境数据管辖权（电诈案常涉境外服务器，调取是否符合《数据安全法》第36条） | 《数据安全法》第36条 |
| B5 | 微信/QQ号→手机号→实名认证的映射链完整性 | 2016规定第25条 |
| B6 | 诈骗话术时间线与资金流时间线的交叉验证 | — |
| B6 | ⚠️时区校验（境外服务器日志可能使用UTC） | — |
| B7 | 被害人陈述中的转账时间与银行流水的印证 | — |
| A3 | 远程勘验是否全程录像（电诈案嫌疑人多涉五年以上刑期） | 2019规则第34条 |
| C10 | IP地址与嫌疑人位置的关联（动态IP/VPN/代理问题） | — |

### T2：网络赌博 — 专攻审查点

| 维度 | 专攻重点 | 法条依据 |
|------|---------|---------|
| A1 | 服务器镜像的来源（是否为原始镜像，物理镜像vs逻辑提取） | 2016规定第9条 |
| A2 | 投注记录数据库的完整性校验 | 2016规定第5条 |
| A3 | 跨境服务器的取证程序合规性 | 2019规则第23-35条 |
| A4 | ⚠️跨境数据管辖权（网赌案服务器常在境外，远程勘验是否替代了MLAT程序） | 《数据安全法》第36条 |
| B6 | 投注时间线与资金流的交叉验证 | — |
| B6 | ⚠️NTP同步校验+时区校验（跨服务器日志比对前必做） | — |
| B8 | 服务器日志的修改痕迹 | 2016规定第28条 |
| C11 | 远程勘验是否经审批（跨境取证需严格批准） | 2019规则第27/34条 |
| A3 | 网赌案涉五年以上刑期，远程勘验是否全程录像 | 2019规则第34条 |
