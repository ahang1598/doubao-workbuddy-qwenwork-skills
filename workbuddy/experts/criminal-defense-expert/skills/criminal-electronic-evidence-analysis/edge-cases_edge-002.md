# 边缘示例002：哈希值不一致场景

> criminal-electronic-evidence-analysis | 边缘示例 | v1.1.0

## 输入

```
分析这个案件的电子证据。王某涉嫌非法吸收公众存款罪，案件信息：
- 案件名称：王某涉嫌非法吸收公众存款案
- 涉嫌罪名：非法吸收公众存款罪
- 罪名类型：T4

证据清单：
1. 扣押电脑1台（联想ThinkPad，SN:LN2024001），扣押清单列明，封存状态完好
2. 投资者数据库备份文件（SQL格式，提取时SHA-256: a1b2c3d4...e5f6g7，移送时SHA-256: x9y8z7w6...p0q1r2）
3. 微信聊天记录截图8张（无哈希值，从电脑中截图提取）
4. 手机取证报告1份（附提取时SHA-256: h4i5j6k7...l8m9n0）

扣押清单：联想ThinkPad电脑1台、华为手机1部

补充信息：
- 电脑提取时间：2024年5月10日
- 电脑移送时间：2024年6月15日
- 中间有1次检查记录（2024年5月25日），但未重新计算完整性校验值
```

## 边界问题

1. **哈希值不一致**：E02（投资者数据库）提取时与移送时的SHA-256不一致，这是最常见的实务场景
2. **不一致原因待分析**：是系统日志自动写入导致？还是针对性篡改？需要降级策略
3. **保管链断裂**：5月25日检查未重新计算校验值，无法定位哈希值变化发生的时间点
4. **截图vs原始数据**：E03微信截图无哈希值，需追问是否有原始数据库

## 预期输出特征

- **O1 解构清单**：E02哈希值列标"提取时与移送时不一致"（红色），完整性列标"存疑"（红色），风险等级"高"
- **O2 12维度报告**：
  - A2完整性核验：
    - E01：三段一致→完整
    - E02：**哈希值不一致→触发降级策略**：
      - 不一致范围：需控方逐文件比对说明是全部文件不一致还是部分文件不一致
      - 不一致原因分析：5月25日检查时未重新计算校验值，无法排除检查过程中对数据的修改
      - 降级判断：系统性变化（系统日志自动写入）→第27条瑕疵可补正；针对性篡改（投资者数据被修改）→第28条非法不得作为定案根据；原因不明→第114条第(二)项"真实性完整性存疑且不能合理解释"
      - 应对建议：要求控方说明不一致原因、提供5月25日检查过程录像、逐文件比对哈希值
    - E03：无哈希值→存疑
    - E04：有哈希值→待验证（需确认比对结果）
  - A2.5保管链连续性：
    - 5月25日检查环节未重新计算校验值→保管链断裂
    - 5月10日至6月15日期间存在无校验值的空白期
    - 结论：保管链**断裂**，风险等级**高**
  - A3取证程序合法性：
    - 5月25日检查是否通过写保护设备接入→需核实
    - 检查过程是否有录像→需核实
  - C11合法性排除点：
    - E02哈希值不一致+保管链断裂+5月25日检查无校验值→第114条第(二)项排除可能性
    - E03微信截图无哈希值+截图非原始数据→第28条排除可能性
- **O4 下游动作**：
  - P0-要求控方说明E02哈希值不一致原因并提供逐文件比对
  - P0-要求提供5月25日检查过程录像和写保护设备使用记录
  - P1-对E03申请调取微信原始数据库
  - P1-对E02申请排除（如控方无法合理解释哈希值不一致）

## 关键验证点

| 验证项 | 预期 |
|--------|------|
| 哈希值不一致降级策略 | 触发"系统性变化vs针对性篡改"分析框架，区分第27条/第28条/第114条 |
| 保管链断裂识别 | 5月25日检查未重算校验值→断裂，不是简单的"存疑"而是"断裂" |
| 截图vs原始数据区分 | E03微信截图是传来证据，需追问原始数据库 |
| 写保护设备审查 | 5月25日检查环节是否使用写保护设备 |
| T4罪名路由 | 激活非法集资专攻审查点（A1宣传材料固定+A3投资者数据库取证程序） |
