# 输入规格

> 本文件定义 criminal-case-management v2.3.0 的完整输入参数规格
> 遵循 compiler/ssot.md §17（SSOT）：输入宽容度契约

## 1. 必需输入

| 字段 | 类型 | 说明 | 验证规则 |
|------|------|------|----------|
| `suspect_name` | string | 犯罪嫌疑人/被告人姓名 | 非空，长度 ≥ 2 |
| `alleged_crime` | string | 涉嫌罪名（优先使用刑法规范罪名） | 非空 |
| `source_paths` | string[] | 案卷文件来源路径列表（文件或文件夹的绝对路径） | 非空，至少1条路径 |

## 2. 可选输入

### 2.1 案件基本信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `case_stage` | enum | [待确认] | 案件阶段（侦查/审查起诉/一审/二审/死刑复核/执行/申诉再审） |
| `case_number` | string | [待补充] | 案号 |
| `suspect_id_number` | string | [待补充] | 身份证号（部分脱敏） |
| `co_defendants` | string[] | null | 其他同案嫌疑人姓名列表（多嫌疑人案件） |
| `urgency` | enum | normal | 案件紧急度（urgent/medium/normal），影响案情表生成优先级和期限监控排序 |

### 2.2 强制措施与羁押信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `coercive_measure_info` | structured | null | 强制措施信息（类型/决定机关/时间/期限） |
| `custody_status` | enum | [待确认] | 羁押状态（在押/取保候审/监视居住） |
| `detention_deadline_info` | structured | null | 办案期限/羁押期限信息 |
| `custody_location` | string | [待补充] | 羁押地点 |

### 2.3 人员信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `victim_info` | string | [待补充] | 被害人信息 |
| `witness_info` | string | [待补充] | 关键证人信息 |
| `investigator_info` | string | [待补充] | 办案人员信息 |

### 2.4 案件路径与上下文

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `workspace_path` | path | 当前IDE workspace | 当前工作区根路径，用于项目检测 |
| `existing_folder_path` | path | 自动检测 | 已有案件目录路径（用于增量更新时跳过检测直接指定） |
| `project_dir_override` | path | null | 手动指定案件目录路径（跳过项目检测，强制使用此路径） |

### 2.5 文件命名方案（INIT模式）

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `naming_scheme` | enum | A | INIT模式交互选择：A标准/B简化/C律师习惯；UPDATE模式从 `00-项目配置.md` 读取 |
| `naming_date_field` | enum | file_modified_date | 日期来源：file_modified_date / material_date / none |
| `naming_include_subject` | boolean | true | 是否包含主体标识 |
| `naming_separator` | enum | "-" | 分隔符："-" / "_" |

### 2.6 增量更新模式

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `update_mode` | boolean | 自动检测 | 手动指定是否为增量更新模式（一般不填，由项目检测自动决定） |

## 3. 输入宽容度契约

### 3.1 最小输入识别

| 最小输入 | 处理方式 |
|----------|----------|
| 仅姓名+罪名+文件路径 | 自动检测项目→确定INIT/UPDATE→执行文件操作 |
| 仅"初始化刑事案件"+案件名称 | 从名称中提取姓名和罪名，追问文件路径 |
| 自然语言描述 | 提取结构化字段，不足部分追问 |

交互补全最多3轮。

### 3.2 自然语言识别模式

| 用户表述 | 提取字段 |
|---------|---------|
| "张某涉嫌盗窃罪" | suspect_name=张某, alleged_crime=盗窃罪 |
| "审查起诉阶段" / "已经到检察院了" | case_stage=审查起诉 |
| "文件在 D:\案卷\" / "材料在桌面" | source_paths=[路径] |
| "被拘留了" / "取保了" / "还在看守所" | custody_status=在押/取保候审/在押 |
| "3月15号被抓的" | coercive_measure_info.拘留日期=03-15 |
| "补充XX案的新材料" | update_mode=true，自动检测已有项目 |

### 3.3 source_paths 输入形态

| 形态 | 示例 | 处理方式 |
|------|------|----------|
| 单个文件夹 | `D:\案卷\张某盗窃\` | 扫描文件夹内所有文件 |
| 文件列表 | `D:\案卷\a.pdf`, `D:\案卷\b.docx` | 逐文件处理 |
| 混合 | "D:\案卷\ 目录和 D:\新到\审计报告.pdf" | 合并处理 |
| 用户打开案件目录 | IDE workspace即案件目录 | 当前workspace作为source_paths |

## 4. 场景适配规则

### 4.1 案件阶段适配

| 阶段 | 目录生成范围 | 案情表重点 | 索引关注 |
|------|------------|----------|---------|
| 侦查 | 00-案件管理 + 10-侦查 + 98-待分类 | 犯罪嫌疑+强制措施+共犯地位 | 侦查卷材料 |
| 审查起诉 | 00 + 10 + 20-审查起诉 | 构成要件+量刑情节+退补 | 全部卷宗 |
| 一审 | 00 + 10 + 20 + 30-一审 | 全部6板块+争议焦点 | 全部+庭审材料 |
| 二审 | 全部（侧重40-二审） | 一审认定事实+新事实 | 一审卷+二审新证据 |
| 死刑复核 | 全部（侧重50-死刑复核） | 死刑适用条件+程序合规 | 全部卷宗 |
| 执行 | 全部（侧重60-执行） | 判决执行情况 | 执行相关文书 |
| 申诉再审 | 全部（侧重70-申诉再审） | 原审事实+新证据 | 原审卷+新证据 |

### 4.2 材料数量适配

| 材料规模 | 索引策略 | 案情表策略 |
|---------|---------|----------|
| ≤5份 | 逐份详细索引 | 逐份提取事实 |
| 6-20份 | 逐份索引+重点材料详细摘要 | 按类别提取+重点材料详述 |
| >20份 | 分类索引+每类摘要 | 按板块提取+大量事实归并 |

### 4.3 文件大小限制

| 阈值 | 处理方式 |
|------|----------|
| ≤10MB | 正常处理，生成MD副本 |
| 10-50MB | 警告用户后处理，MD副本标注文件较大 |
| >50MB | 跳过MD副本生成，仅复制文件，索引表标注"MD副本未生成（文件过大）" |
