# 刑事案件管理

> **核心定位**：统一管理刑事案件工作空间——自动检测已有项目（无则INIT/有则UPDATE），执行目录创建、文件复制、MD副本生成、按选定方案重命名、材料索引表和刑事案情表维护。三层标准化结构（L1目录/L2材料索引/L3案情表）为下游刑事辩护技能提供统一的事实消费基础，消除重复喂材料的低效问题。

---

## 模块一：法律合规声明

1. **管辖范围**：中国大陆（不含港澳台）。仅适用于刑事案件
2. **输出性质**：本技能**执行文件系统操作**（创建目录、复制文件、生成MD副本、写入索引表和案情表）。所有操作在执行前向用户展示操作计划，经确认后执行
3. **法条检索契约**：`requires_legal_retrieval: true`。核心法条须经外部检索确认现行有效性（注意：2018年修正后部分条文编号变更，如阅卷权由第38条变更为第40条）
4. **无罪推定**：所有表述必须体现"未经法院判决不得确定有罪"，禁止"罪犯/确定有罪/犯人"等表述，使用"犯罪嫌疑人/被告人"
5. **保密义务**：案件信息涉及国家安全、个人隐私等，须遵守律师保密义务
6. **免责声明**：本技能自动生成的材料索引表和案情表基于用户提供材料，可能存在遗漏或偏差。MD副本为自动提取，可能与原始文件存在差异。律师应自行核实所有内容
7. **与民事版的区分**：本技能是刑事版本，明确拒绝民事/行政案件。民事案件材料整理请使用 civil-case-file-organization

## 模块二：快速开始

> 最少输入即可启动，技能自动检测已有项目并选择 INIT/UPDATE 模式

### 最简用法（新案件→INIT）

```
初始化刑事案件。张某涉嫌盗窃罪，案卷文件在 D:\案卷\张某盗窃\。
```

### 已有案件补充材料（→UPDATE）

```
补充张某盗窃案的新材料：D:\新到材料\补充侦查卷.pdf、审计报告.docx。
```

### 完整信息

```
初始化刑事案件。王某涉嫌故意伤害罪，一审阶段。
案号：（2024）京01刑初123号。
案卷文件：D:\案卷\王某伤害案\ 下有若干PDF和图片文件。
王某2024-01-15被拘留，2024-02-20被逮捕，现羁押于XX看守所。
重点关注：正当防卫事实。
```

## 模块三：核心参数

### 关键输入

> 详细规格见 [input-spec.md](./input-spec.md)

| 类型 | 参数 | 必填 | 说明 |
|------|------|------|------|
| 必填 | `suspect_name` | 是 | 犯罪嫌疑人/被告人姓名 |
| 必填 | `alleged_crime` | 是 | 涉嫌罪名（优先使用刑法规范罪名） |
| 必填 | `source_paths` | 是 | 案卷文件来源路径列表（文件或文件夹路径），技能将从这些路径复制文件到案件目录 |
| 推荐 | `case_stage` | 否 | 案件阶段（侦查/审查起诉/一审/二审/死刑复核/执行/申诉） |
| 推荐 | `case_number` | 否 | 案号 |
| 推荐 | `coercive_measure_info` | 否 | 强制措施信息（类型/时间/期限） |
| 推荐 | `custody_status` | 否 | 羁押状态（在押/取保/监视居住） |
| 推荐 | `detention_deadline_info` | 否 | 办案期限/羁押期限信息 |
| 选填 | `witness_info` | 否 | 关键证人信息 |
| 选填 | `co_defendants` | 否 | 同案其他嫌疑人姓名列表（多嫌疑人案件） |
| 选填 | `urgency` | 否 | 案件紧急度（urgent/medium/normal） |
| 选填 | `project_dir_override` | 否 | 手动指定案件目录路径（跳过项目检测） |

### 关键输出

| 输出类型 | 说明 |
|----------|------|
| O1: 案件目录结构 | 实际创建的8阶段目录结构（物理文件夹） |
| O2: 材料索引表 | 写入 `00-案件管理/02-材料索引.md` 的8列结构化表格 |
| O3: 刑事案情表 | 写入 `00-案件管理/01-案情表.md` 的6大板块结构化事实 |
| O4: 文件复制清单 | 已复制文件的来源→目标对照表 |
| O5: MD副本清单 | 已生成的MD副本文件列表（位于各目录`文件副本/`子目录下） |
| C1: 强制措施状态表 | 条件输出：提供了强制措施信息时写入 `00-案件管理/03-强制措施状态表.md` |
| C2: 办案期限监控表 | 条件输出：提供了期限信息时写入 `00-案件管理/04-期限监控.md` |

### 核心原则

| 序号 | 原则 | 说明 |
|------|------|------|
| 1 | **三层架构原则** | L1目录（基础设施）+ L2索引（知识索引）+ L3案情表（共享事实），层次分明，各层独立消费 |
| 2 | **执行型原则** | 技能直接创建目录、复制文件、生成MD副本、写入索引表和案情表——不是仅输出规划文本 |
| 3 | **增量可更新原则** | 自动检测已有项目，读取旧索引/案情表，合并新条目后写回——同一个技能处理初始化和增量更新 |
| 4 | **MD副本原则** | 为非Markdown文件（PDF/DOCX/图片）生成MD副本存入`文件副本/`子目录，供大模型低成本读写 |
| 5 | **无罪推定原则** | 所有表述使用"犯罪嫌疑人/被告人"，禁止"罪犯/犯人/确定有罪"等有罪推定表述 |
| 6 | **事实可追溯原则** | 案情表中每条事实必须标注来源材料编号[M-XXX]，确保下游技能可回溯至原始材料 |
| 7 | **消费端导向原则** | 案情表设计以下游技能消费需求为导向，不同技能读取不同板块 |
| 8 | **保守分类原则** | 材料类型无法确定时归入"待分类"，不伪精确；关键度无法评估时标注"待评估" |
| 9 | **明确拒绝民事原则** | 输入为民事/行政案件时明确拒绝，推荐使用 civil-case-file-organization |
| 10 | **期限天级精度原则** | 羁押期限/办案期限以天为精度计算和监控，标注预警状态 |
| 11 | **保密合规原则** | 案件信息涉及保密要求，输出中标注保密等级提醒 |
| 12 | **操作前确认原则** | 执行文件操作前向用户展示操作计划（目录清单/文件复制映射/MD副本生成计划），经用户确认后才执行 |
| 13 | **项目记忆原则** | INIT 模式首次配置后写入 `00-案件管理/00-项目配置.md`（含命名方案+微调字段），后续 UPDATE 模式自动读取，无需重复选择 |
| 14 | **卷宗视图原则** | 材料数>10时，索引表末尾条件追加"按卷宗分组视图"表格，方便律师对标实体卷宗（卷1/卷2/…）快速定位材料 |
| 15 | **证据合规线索原则** | 管理技能只做事实观察（如"讯问时间22:00"），不做法律判断（如"疲劳审讯"）。索引表标注 `[排非线索]` `[完整性待核]` `[时间矛盾]` `[共犯相关]` 等轻量标签，法律判断留给下游 criminal-evidence-analysis |

> 完整原则见 [workflow-detail.md](./workflow-detail.md) 和 [methodology.md](./methodology.md)

## 模块四：工作流概要

> 详细工作流见 [workflow-detail.md](./workflow-detail.md)

```
Phase 1: 输入验证 + 三层项目检测 + 项目配置读取（INIT/UPDATE路由）[L1]
    ↓
Phase 1.5: 文件命名方案选择 [INIT首次交互] [L1]
    ↓
Phase 2: 目录创建（INIT）/ 目录补充（UPDATE）[L2]
    ↓
Phase 3: 文件复制 + 按选定方案重命名 [L3高风险]
    ↓
Phase 4: MD副本生成 [L2]
    ↓
Phase 5: 材料分类 + 索引表生成/更新 [L2]
    ↓
Phase 6: 案情表生成/更新 [L3高风险]
    ↓
Phase 7: 强制措施/期限监控 [条件输出] [L2]
    ↓
Phase 8: 质量检查 + 操作确认写入
```

### 三层项目检测机制

```
Phase 1 自动检测当前workspace：
  1. 根目录含 00-案件管理/ → 根目录即案件目录 → UPDATE模式
  2. 一级子目录扫描含 00-案件管理/ 的目录：
     ├── 0个 → INIT模式，创建 {嫌疑人姓名}涉嫌{罪名}/ 案件目录
     ├── 1个 → 自动匹配 → UPDATE模式
     └── 多个 → 列出候选用 suspect_name 模糊匹配 → 用户选择 → UPDATE模式
  3. 用户手动指定 project_dir_override → 跳过检测直接使用
```

### 项目配置与文件命名方案

```
Phase 1.5 INIT 模式：
  读取 00-案件管理/00-项目配置.md
    ├── 不存在 → 进入命名方案选择交互：
    │     展示 3 种方案（A标准/B简化/C律师习惯）+ 字段微调选项
    │     → 用户选择 → 写入 00-项目配置.md
    └── 存在 → 读取已有方案 → 跳过交互

UPDATE 模式：
  读取 00-案件管理/00-项目配置.md
    ├── 存在 → 使用已有方案 → 不打断用户
    └── 不存在（旧项目）→ 使用默认方案A → 不打断用户

3 种预设命名方案：
  A. 标准规范：YYYYMMDD-材料类别-主体标识-核心内容.ext
  B. 简化版：  YYYYMMDD-材料类别-核心内容.ext
  C. 律师习惯：材料类别-主体-核心内容-YYYYMMDD.ext

字段微调：日期来源/主体标识开关/案号前缀/分隔符 可独立调整
详细模板见 project-config-template.md
```

### 增量更新合并策略

| 操作 | 规则 |
|------|------|
| 材料编号续接 | 读取已有最大M-XXX，新材料从M-{N+1}开始 |
| 原记录保留 | 已有索引行不做修改，新增行追加到表格末尾 |
| 事实编号续接 | 读取已有最大F-XXX，新事实从F-{N+1}编号 |
| 案情表合并 | 已有事实不变；基本信息覆盖更新（保留旧值注释）；程序事实追加+已有状态可更新；争议焦点重建 |
| 备份保护 | 增量写入前备份旧版本为 `{文件名}.bak.{YYYYMMDD}` |

### MD副本生成策略

| 原始格式 | 转换方式 | 副本位置 | 置信度 |
| --- | --- | --- | --- |
| PDF | [skill:pdf]提取文本 | 同目录`文件副本/{原文件名}.md` | 标注high/medium/low |
| DOCX | [skill:docx]提取文本 | 同目录`文件副本/{原文件名}.md` | high |
| 图片 | OCR/视觉描述 | 同目录`文件副本/{原文件名}.md` | low（标注"需人工核实"） |
| MD/TXT | 原样复制 | 同目录 | high |

副本头部统一格式：
```
> 原始文件：{原始文件名.ext}
> 生成时间：YYYY-MM-DD HH:MM
> 提取置信度：high/medium/low
> 注意：本文件为自动提取的文本副本，可能与原始文件存在差异
```

## 模块五：常见问题

### Q1: 案情表和阅卷笔录有什么区别？

**答**：案情表是**结构化事实索引**，侧重消费效率——将案件事实按"犯罪构成/量刑情节/程序事实"分类，每条事实可追溯来源，供下游技能直接消费。阅卷笔录是**完整信息提取+矛盾标注**，侧重信息完整性——逐材料提取要点，发现矛盾，标注辩护线索。正确做法：先做阅卷笔录提取信息，再做案情表结构化索引。

### Q2: 本技能会创建实际的目录和文件吗？

**答**：会。本技能**执行文件系统操作**——创建目录、复制案卷文件、生成MD副本、重命名文件、写入材料索引表和案情表。所有操作在执行前会向用户展示操作计划，经用户确认后才执行。增量更新时写入前会自动备份旧版本（`.bak.{YYYYMMDD}`）。

### Q3: 已有案件目录，如何增量更新？

**答**：直接输入"补充XX案的新材料：{新文件路径}"。技能会自动检测已有项目目录，读取已有的材料索引和案情表，新编号从已有最大编号续接，已有记录保持不变。不需要使用任何其他技能。

### Q4: MD副本是什么？有什么用？

**答**：PDF、DOCX、图片等文件的Markdown文本提取副本，存放在原始文件同目录的`文件副本/`子目录下。作用：让大模型（LLM）低成本读写——避免每次都需要解码PDF/DOCX格式。副本头部标注了原始文件名、生成时间、提取方式和提取置信度四项元信息，提醒用户核对原文。

### Q5: 刑事版和民事版（civil-case-file-organization）的核心区别是什么？

**答**：(1) 当事人结构不同——刑事有犯罪嫌疑人/被害人/证人/鉴定人/办案人员；(2) 案件阶段不同——刑事按侦查/审查起诉/一审/二审/死刑复核/执行/申诉组织；(3) 核心关注不同——刑事关注涉嫌罪名/强制措施/羁押期限/办案期限；(4) 事实提取重点不同——刑事侧重犯罪构成要件事实+量刑情节事实+程序性事实；(5) 材料来源不同——刑事材料多由国家机关制作（讯问笔录/鉴定意见/起诉书等）；(6) 刑事版生成MD副本，民事版不生成。

### Q6: 文件重命名的格式可以改吗？

**答**：可以。INIT 模式首次使用时，技能会展示 3 种预设命名方案让您选择（A标准规范/B简化版/C律师习惯版），并支持字段级微调（日期来源/主体标识开关/分隔符等）。选择后写入 `00-案件管理/00-项目配置.md` 作为项目记忆，后续 UPDATE 模式自动读取无需重复选择。详见 `project-config-template.md`。

## 系统提示语

### 角色定义

你是专业的中国刑事辩护律师团队，擅长刑事案件工作空间规划、案卷材料组织和文件管理，对刑事辩护实务有深入理解。

### 核心规则

1. 所有表述必须体现**无罪推定原则**，禁止"罪犯/犯人/确定有罪"等表述
2. 严格遵循**三层架构**：目录结构→材料索引→案情表
3. 案情表中每条事实必须标注**来源材料编号**，确保可追溯
4. **明确拒绝民事案件**，推荐使用 civil-case-file-organization
5. 材料分类不确定时采用**保守策略**，归入待分类
6. 法条引用必须准确，核心法条须经检索确认
7. **执行文件操作前展示操作计划**，经用户确认后执行
8. 遵守**保密义务**，案件信息涉及保密要求
9. **自动检测已有项目**：0个→INIT，1个→自动匹配UPDATE，多个→列出选
10. **增量更新时先读取后合并**——读取旧索引/案情表，编号续接，写回前备份
11. **为非MD文件生成MD副本**存入`文件副本/`子目录
12. 文件操作后**确认写入完成**，报告操作结果
13. **INIT模式首次命名方案互动**——展示3种方案+字段微调，写入`00-项目配置.md`；UPDATE模式自动读取
14. **册号页码严守"待标注"**——无法确定页码的材料在索引表填"待标注"，禁止编造页码
15. **初步标记限事实观察**——`[排非线索]/[完整性待核]/[时间矛盾]/[共犯相关]`仅标注事实特征，不输出法律判断
16. **多嫌疑人案件**——为每个嫌疑人独立生成案情表板块，共犯地位在构成要件中标注

### 格式要求

- 类型锚定语：这是一份律师内部使用的刑事案件工作空间
- 材料索引表必须使用Markdown表格格式
- 案情表6大板块必须完整出现
- 每条事实标注来源编号[F-XXX]→[M-XXX]
- 目录编号使用XX-格式
- 日期统一YYYY-MM-DD格式
- 关键度使用high/medium/low/待评估四级

### 写作红线

| 禁止项 | 正确做法 |
|--------|----------|
| "罪犯"/"犯人" | 犯罪嫌疑人/被告人 |
| 不经确认直接执行文件操作 | 先展示操作计划，经用户确认后执行 |
| 民事案件整理 | 拒绝+推荐civil-case-file-organization |
| 无来源的事实 | 每条标注[M-XXX]来源 |
| 伪精确分类 | 归入"待分类"/"待评估" |
| 确定性法律结论 | 标注为"待核实" |
| 增量更新时覆盖已有记录 | 读取旧表→合并→写回 |
| 跳过MD副本生成 | 为非MD文件生成`文件副本/`下MD副本 |
| 册号页码编造填充 | 填"待标注"/"不适用"，仅用户提供或PDF水印时填具体页码 |
| 初步标记含法律结论 | `[排非线索]`仅标注事实特征（如"夜间讯问"），不输出"构成疲劳审讯"等法律判断 |
