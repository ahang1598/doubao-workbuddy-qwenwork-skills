# 工作流详述

> 本文件定义 criminal-case-management v2.3.0 的各Phase子步骤与检查点

## 1. 工作流概览

```
Phase 1: 输入验证 + 三层项目检测 + 项目配置读取（INIT/UPDATE路由）[L1]
    ↓
Phase 1.5: 文件命名方案选择 [INIT首次交互] [L1]
    ↓
Phase 2: 目录创建（INIT）/ 目录补充（UPDATE）[L2]
    ↓
Phase 3: 文件复制 + 按选定方案重命名 [L3高风险]
    ↓
Phase 4: MD副本生成 [L2]
    ↓
Phase 5: 材料分类 + 索引表生成/更新 [L2]
    ↓
Phase 6: 案情表生成/更新 [L3高风险]
    ↓
Phase 7: 强制措施/期限监控 [条件输出] [L2]
    ↓
Phase 8: 质量检查 + 操作确认写入
```

## 2. Phase 1: 输入验证与三层项目检测 [L1]

### 2.1 输入验证

| 步骤 | 操作 | 产出 |
|------|------|------|
| 1.1 | 解析输入 | 提取 suspect_name, alleged_crime, source_paths |
| 1.2 | 识别案件类型 | 判断是否刑事案件 |
| 1.3 | 确定案件阶段 | case_stage（默认"待确认"） |
| 1.4 | 验证文件路径 | 检查 source_paths 指向的文件/文件夹是否存在 |
| 1.5 | 评估输入完整度 | completeness_level（full/partial/minimal） |

**检查点**：
- [ ] 姓名和罪名已提取
- [ ] 案件类型已确认（刑事/非刑事）
- [ ] 文件路径有效
- [ ] 输入完整度已评估

**追问模板**：
- 缺姓名："请提供犯罪嫌疑人/被告人的姓名"
- 缺罪名："请明确涉嫌罪名（如盗窃罪/诈骗罪/故意伤害罪等）"
- 缺文件路径："请提供案卷文件所在的路径（文件夹或文件路径）"
- 非刑事："本技能仅适用刑事案件。民事案件请使用 civil-case-file-organization"

### 2.2 三层项目检测

```
Layer 1: 根目录检测
  workspace 根目录下有无 00-案件管理/ 目录？
  ├── 有 → 根目录即案件目录 → 进入 UPDATE 模式

Layer 2: 一级子目录扫描
  扫描 workspace 下所有一级子目录，列出含 00-案件管理/ 的目录
  ├── 0个 → 进入 INIT 模式
  │         案件目录名：{嫌疑人姓名}涉嫌{罪名}/
  ├── 1个 → 自动匹配 → 进入 UPDATE 模式
  └── 多个 → 列出候选列表
              + suspect_name 模糊匹配目录名
              + 用户选择或确认匹配结果
              → 进入 UPDATE 模式

Layer 3: 手动指定
  project_dir_override 非空？
  └── 跳过 L1/L2，直接使用指定路径 → UPDATE 模式
```

**交互模板（多个候选时）**：

```
检测到以下已有案件目录：
1. 张某涉嫌盗窃/
2. 李某涉嫌诈骗/
3. 王某涉嫌伤害/

请输入序号选择，或输入"新案件"创建新项目。
```

**Phase 1 产出**：
- `mode`: "INIT" 或 "UPDATE"
- `case_dir`: 案件目录的绝对路径
- `case_dir_name`: 案件目录名（INIT时生成，格式：`{嫌疑人姓名}涉嫌{罪名}/`）
- `existing_m_max`: UPDATE模式下的最大M-XXX编号（从旧索引表读取）
- `existing_f_max`: UPDATE模式下的最大F-XXX编号（从旧案情表读取）
- `missing_dirs`: UPDATE模式下的缺失目录列表

**UPDATE模式初始化**：
- 读取已有 `{case_dir}/00-案件管理/02-材料索引.md` → 确定最大 M-XXX 编号
- 读取已有 `{case_dir}/00-案件管理/01-案情表.md` → 确定最大 F-XXX 编号
- 读取已有目录结构 → 确定缺失目录
- 读取已有 `{case_dir}/00-案件管理/00-项目配置.md` → 确定命名方案（不存在则使用默认方案A）

### 2.3 项目配置读取

```
Phase 1 确定模式后读取 00-案件管理/00-项目配置.md：
  INIT 模式 → 文件不存在（跳过，Phase 1.5 中采集）
  UPDATE 模式：
    ├── 文件存在 → 提取 naming_scheme + field_overrides → 传给 Phase 3
    └── 文件不存在（旧项目）→ 使用默认方案A
```

**项目配置字段**：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `naming_scheme` | A | 命名方案：A标准/B简化/C律师习惯 |
| `date_field` | file_modified_date | 日期来源：file_modified_date / material_date / none |
| `include_subject` | true | 是否包含主体标识 |
| `include_case_number` | false | 是否包含案号 |
| `separator` | "-" | 分隔符："-" / "_" |

### 2.4 Phase 1.5: 文件命名方案选择 [INIT首次交互] [L1]

**触发条件**：INIT 模式且 `00-案件管理/00-项目配置.md` 不存在

### 写入项目配置

```yaml
# 用户确认后写入 00-案件管理/00-项目配置.md
# 00-项目配置.md
naming_scheme: {A/B/C}
field_overrides:
  date_field: {file_modified_date/material_date/none}
  include_subject: {true/false}
  include_case_number: false
  separator: "{'-'/'_'}"
```

**降级规则**：
- 用户输入"跳过"或超时不回复 → 默认方案A
- 微调交互用户回车跳过 → 使用选定方案的默认字段值
- 配置文件写入失败 → 使用默认方案A + 操作报告中警告

### 方案-字段组合规则

选定方案后，字段微调仅在方案默认值基础上提供反向选项：

| 方案 | 默认字段 | 微调选项 |
|------|---------|---------|
| A | 日期=修改日期, 主体=true, 分隔符=- | 可关闭主体/关闭日期/改分隔符 |
| B | 日期=修改日期, 主体=false, 分隔符=- | 可开启主体/关闭日期/改分隔符 |
| C | 日期=修改日期, 主体=true, 分隔符=- | 可关闭主体/关闭日期/改分隔符 |

### 3.4 文件复制

| 步骤 | 操作 | 🔴高风险注意 |
|------|------|-------------|
| 3.4.1 | 向用户展示"来源→目标"复制映射表 | **必须经用户确认后才执行复制** |
| 3.4.2 | 逐文件执行复制操作 | 使用文件复制工具，保持原始文件不变 |
| 3.4.3 | 验证复制完整性 | 逐文件对比源文件与目标文件大小 |

**复制规则**：
- 目标文件不覆盖已有同名文件。如目标已存在，自动在文件名后加"（1）"/"（2）"等序号
- 复制失败的文件记录到错误清单，Phase 8中提示用户

### 3.5 文件重命名（按选定方案）

| 步骤 | 操作 | 🔴交互注意 |
|------|------|-----------|
| 3.5.1 | 读取命名方案（项目配置或默认方案A） | Phase 1/1.5 已确定 |
| 3.5.2 | 按选定方案生成新文件名 | 见下方3种方案格式 |
| 3.5.3 | 日期提取：优先使用材料内日期，降级为文件修改日期 | 取决于 `date_field` 配置 |
| 3.5.4 | 生成"旧文件名→新文件名"映射表 | — |

**三种命名方案格式**：

| 方案 | 格式 | 示例 |
|------|------|------|
| A（标准） | `YYYYMMDD-材料类别-主体标识-核心内容.ext` | `20240115-讯问笔录-张某-第1次供述.pdf` |
| B（简化） | `YYYYMMDD-材料类别-核心内容.ext` | `20240115-讯问笔录-第1次供述.pdf` |
| C（律师习惯） | `材料类别-主体-核心内容-YYYYMMDD.ext` | `讯问笔录-张某-第1次供述-20240115.pdf` |

**字段微调影响**：
- `date_field: none` → 方案A/C去掉日期字段，方案B退化为 `材料类别-核心内容.ext`
- `include_subject: false` → 方案A退化为方案B格式，方案C去掉主体字段
- `separator: "_"` → 所有 `-` 替换为 `_`
- `include_case_number: true` → 在主体标识后追加案号简写

**Phase 3 检查点**：
- [ ] 文件复制映射表已展示并获用户确认
- [ ] 所有文件已复制到目标目录
- [ ] 复制完整性已验证（大小对比）
- [ ] 文件已按选定命名方案重命名
- [ ] "旧文件名→新文件名"映射表已生成
- [ ] 错误清单已记录

## 5. Phase 4: MD副本生成 [L2]

### 5.1 生成规则

| 原始格式 | 转换方式 | 目标路径 | 标注 |
|---------|---------|---------|------|
| `.md` / `.txt` | 直接复制 | 同目录`{文件名}.md` | — |
| `.pdf` | [skill:pdf]提取文本 | 同目录`文件副本/{文件名}.md` | 置信度 |
| `.docx` | [skill:docx]提取文本 | 同目录`文件副本/{文件名}.md` | 置信度 |
| `.jpg/.png/.jpeg/.webp` | OCR或视觉描述 | 同目录`文件副本/{文件名}.md` | 置信度low |
| 其他格式 | 跳过 | — | 索引表标注"MD副本不可生成" |

### 5.2 大小限制

| 阈值 | 处理方式 |
|------|----------|
| ≤10MB | 正常处理 |
| 10-50MB | ⚠️ 警告后尝试生成，副本标注"文件较大，可能不完整" |
| >50MB | ⛔ 跳过生成，索引表标注"MD副本未生成（文件>50MB）" |

### 5.3 副本头部模板

```markdown
> 原始文件：{原始文件名.ext}
> 生成时间：YYYY-MM-DD HH:MM
> 提取方式：{pdf→md / docx→md / OCR / 直接复制}
> 提取置信度：high / medium / low
> 注意：本文件为自动提取的文本副本，可能与原始文件存在差异。关键内容请核对原始文件。
```

**Phase 4 检查点**：
- [ ] 非MD文件已生成MD副本
- [ ] MD副本存放于 `文件副本/` 子目录
- [ ] 副本头部信息完整
- [ ] 超大文件已按规则跳过并标注

## 6. Phase 5: 材料分类与索引表生成/更新 [L2]

### 6.1 分类流程

```
已复制文件 → 识别材料类型 → 确定所属阶段 → 评估关键度 → 生成索引行
```

### 6.2 INIT模式：生成新索引表

| 步骤 | 操作 |
|------|------|
| 6.2.1 | 从M-001开始编号 |
| 6.2.2 | 逐文件生成索引行（8列） |
| 6.2.3 | 按编号排序 |

### 6.3 UPDATE模式：增量更新索引表

| 步骤 | 操作 | 规则 |
|------|------|------|
| 6.3.1 | 读取已有 `02-材料索引.md` | 提取全部已有M-XXX行和最大编号 |
| 6.3.2 | 新文件从M-{已有最大编号+1}开始编号 | M-013→M-014→M-015... |
| 6.3.3 | 新索引行追加到表格末尾 | 已有行不做任何修改 |
| 6.3.4 | 备份旧文件 | 复制为 `02-材料索引.bak.{YYYYMMDD}.md` |
| 6.3.5 | 合并后写回 | 保留已有行+追加新行 |

### 6.4 材料类型枚举

| 类型 | 典型材料 |
|------|---------|
| 言词证据 | 讯问笔录、被害人陈述、证人证言 |
| 实物证据 | 扣押物品、银行流水、合同 |
| 鉴定意见 | 法医鉴定、价格鉴定、DNA鉴定 |
| 程序文书 | 拘留证、逮捕证、搜查证 |
| 诉讼文书 | 起诉意见书、起诉书、抗诉书 |
| 法律文书 | 判决书、裁定书、决定书 |
| 技术材料 | 电子数据检验报告、现场勘查笔录 |
| 律师工作成果 | 会见笔录、辩护意见、取证申请 |
| 同步录音录像 | 讯问同步录音录像文件 |

### 6.5 关键度评估标准

| 级别 | 标准 |
|------|------|
| high | 直接影响定罪量刑 |
| medium | 间接影响或有佐证作用 |
| low | 辅助参考 |
| 待评估 | 信息不足无法判断 |

### 6.6 初步标记生成规则（v2.3.0新增）

> **核心约束**：初步标记仅做事实观察，不做法律判断。违反此规则即为阻断级错误。

| 步骤 | 操作 | 产出 |
|------|------|------|
| 6.6.1 | 逐材料扫描事实特征 | 识别排非线索/完整性/时间矛盾/共犯标记 |
| 6.6.2 | 标注对应标签 | `[排非线索]` `[完整性待核]` `[时间矛盾]` `[共犯相关]` 或无标记(—) |

## 10. 复杂度分层

### SIMPLE 触发条件与简化规则

- **触发条件**：单罪名 + 材料≤5份 + 无强制措施信息
- **管线简化**：Phase 1-2 合并 + Phase 7 跳过 + Phase 8 合并到Phase 6
- **MD副本**：仍然生成，不跳过

### STANDARD 触发条件（默认）

- **触发条件**：2-20份材料 或 含强制措施信息
- **全流程**：Phase 1→2→3→4→5→6→7→8

### COMPLEX 触发条件与增强规则

- **触发条件**：多罪名 或 材料>20份 或 含退补/延期等复杂程序
- **增强项**：+ Phase 5 分批处理（每批10份） + Phase 6 多罪名分别提取构成要件 + Phase 7 退补期限重算 + Phase 8 增加交叉引用完整性验证
