# 方法论

> 本文件定义 criminal-case-management v2.3.0 的核心方法论

## 1. 三层架构设计原理

### 1.1 问题：重复喂材料的效率黑洞

当前24个刑事技能各自独立，每个都需要通过 `case_materials`（纯文本）输入案卷内容。同一案件的材料被反复喂给不同技能，效率极低且不现实。

### 1.2 解决方案：三层消费架构

```
L1 基础设施层：目录结构
  → 标准化工作空间，按阶段组织材料 + 物理文件管理
  → 消费者：律师（人工管理）、本技能（增量更新）
  → 本技能执行层：创建物理目录、复制案卷文件、按用户选定方案重命名（3种方案可选）

L2 知识索引层：材料索引表
  → 每份材料一行记录，8列结构化信息
  → 消费者：下游技能（决定是否需要读取原始材料或MD副本）
  → 本技能执行层：生成/更新索引表，写入 00-案件管理/02-材料索引.md

L3 共享事实层：刑事案情表
  → 从材料中提取的结构化案件事实，6大板块
  → 消费者：下游技能（替代 case_materials 作为输入）
  → 本技能执行层：生成/更新案情表，写入 00-案件管理/01-案情表.md
```

### 1.3 三层消费模式

```
                    ┌──────────────────────┐
                    │  L1 目录结构          │ ← 律师/本技能（物理文件管理）
                    └──────────────────────┘
                              │
                    ┌──────────────────────┐
                    │  L2 材料索引表        │ ← 下游技能（定位原始材料）
                    └──────────────────────┘
                              │
                    ┌──────────────────────┐
                    │  L3 刑事案情表        │ ← 下游技能（直接消费事实）
                    └──────────────────────┘
                              │
                    ┌──────────────────────┐
                    │  文件副本/ MD副本     │ ← LLM（低成本文本读写）
                    └──────────────────────┘
```

## 2. 双模式路由方法论

### 2.1 项目检测机制

三层检测策略确保准确判断INIT/UPDATE模式：

```
Layer 1 — 根目录检测：workspace根下 00-案件管理/
Layer 2 — 子目录扫描：一级子目录中含 00-案件管理/ 的候选
Layer 3 — 手动指定：project_dir_override 强制路由
```

### 2.2 INIT模式策略

- 案件目录名：`{嫌疑人姓名}涉嫌{罪名}/`
- Phase 2 创建完整目录结构
- Phase 5/6 从M-001/F-001开始编号

### 2.3 UPDATE模式策略

| 操作 | 策略 | 理由 |
|------|------|------|
| 目录补充 | 对比已有与阶段映射表，仅创建缺失目录 | 避免覆盖已有目录 |
| 编号续接 | 读取已有最大M-XXX/F-XXX，从N+1开始 | 保持编号连续和可追溯 |
| 备份保护 | 写入前备份为 `.bak.{YYYYMMDD}.md` | 支持回滚 |
| 旧记录保护 | 已有索引行/事实行不做任何修改 | 避免破坏已有工作成果 |
| 命名方案读取 | 读取 `00-项目配置.md` 获取命名方案；不存在则使用默认方案A（不打断用户） | 保持命名一致性 |

## 3. MD副本生成方法论

### 3.1 设计目的

律师案卷材料多为PDF/DOCX/图片格式。大模型（LLM）每次读取这些格式需要解码，效率低且消耗上下文。MD副本让LLM可以低成本读写文本内容，只在需要核对原文时才读取原始文件。

### 3.2 转换策略

| 格式 | 策略 | 置信度 | 注意事项 |
|------|------|--------|---------|
| PDF | 使用[skill:pdf]提取文本 | 取决于PDF质量 | 扫描件PDF可能无法提取文字，标注low |
| DOCX | 使用[skill:docx]提取文本 | high | 格式信息可能丢失（表格/页眉页脚） |
| 图片 | OCR后提取文字；若无OCR能力则视觉描述 | low | 必须标注"需人工核实" |
| MD/TXT | 直接复制原文 | high | — |

### 3.3 存放位置与命名

- 存放：原始文件同目录下的 `文件副本/` 子目录
- 命名：`{原始文件名（不含扩展名）}.md`
- 示例：`起诉意见书.pdf` → `文件副本/起诉意见书.md`

### 3.4 大小控制

| 阈值 | 处理 | 原因 |
|------|------|------|
| ≤10MB | 正常生成 | — |
| 10-50MB | 警告后生成 | 大文件转换耗时较长 |
| >50MB | 跳过生成 | 避免上下文爆炸和处理超时 |

## 4. 增量更新合并方法论

### 4.1 材料索引表合并

```
已有索引表（M-001 ~ M-012）
    ↓ 保留所有已有行
新增材料（3份）
    ↓ M-013 ~ M-015
合并后索引表（M-001 ~ M-015）
    ↓ 已有行不变，新增行追加到末尾
写入 02-材料索引.md
```

### 4.2 案情表合并

| 板块 | 策略 | 原因 |
|------|------|------|
| 基本信息 | 覆盖更新（保留旧值注释） | 案件基本信息可能变化（阶段推进） |
| 构成要件 | 追加 | 新材料可能补充新事实 |
| 量刑情节 | 追加 | 同上 |
| 程序事实 | 追加+状态覆盖 | 程序推进，时间线扩展 |
| 争议焦点 | 重建 | 新材料可能改变争议焦点分布 |
| 来源追溯 | 追加 | 新事实来源追加 |

### 4.3 回滚策略

UPDATE模式写入前自动备份：
- `02-材料索引.bak.20260608.md`
- `01-案情表.bak.20260608.md`
- 备份文件保留最近3个版本，超过自动清理

## 5. 材料分类方法论

### 5.1 刑事案件材料9大类

| 类别 | 核心特征 | 典型材料 |
|------|---------|---------|
| 言词证据 | 人的陈述 | 讯问笔录、被害人陈述、证人证言 |
| 实物证据 | 物品/书面载体 | 扣押物品、银行流水、合同 |
| 鉴定意见 | 专家判断 | 法医鉴定、价格鉴定、DNA鉴定 |
| 程序文书 | 诉讼程序性文件 | 拘留证、逮捕证、搜查证 |
| 诉讼文书 | 指控/答辩文书 | 起诉意见书、起诉书、抗诉书 |
| 法律文书 | 裁判性文书 | 判决书、裁定书、决定书 |
| 技术材料 | 技术性报告 | 电子数据检验报告、现场勘查笔录 |
| 律师工作成果 | 辩护方产出 | 会见笔录、辩护意见、取证申请 |
| 同步录音录像 | 讯问录音录像 | 讯问同步录音录像文件 |

### 5.2 分类决策树

```
材料内容
├── 人的口头/书面陈述？ → 言词证据
├── 专家的分析判断？ → 鉴定意见
├── 国家机关的指控/答辩？ → 诉讼文书
├── 法院的裁判？ → 法律文书
├── 诉讼程序性文件？ → 程序文书
├── 技术检验/勘查？ → 技术材料
├── 律师制作？ → 律师工作成果
├── 讯问同步录音录像？ → 同步录音录像
├── 其他实物/书证？ → 实物证据
└── 无法判断？ → 98-待分类
```

## 6. 案情表提取方法论

### 6.1 六板块提取优先级

| 板块 | 优先级 | 数据来源 |
|------|--------|---------|
| 案件基本信息 | P0（必须） | 起诉意见书/起诉书/拘留证 |
| 犯罪构成要件事实 | P0（必须） | 讯问笔录/被害人陈述/鉴定意见 |
| 量刑情节事实 | P1（重要） | 讯问笔录/自首材料/退赃材料 |
| 程序性事实 | P1（重要） | 程序文书/起诉书/退补函 |
| 争议焦点 | P2（推荐） | 对比控辩材料差异 |
| 事实来源追溯 | P0（必须） | 全部材料 |

### 6.2 事实提取原则

1. **忠实原意**：事实描述必须与原始材料一致，不增不减
2. **来源标注**：每条事实必须标注来源材料编号[M-XXX]
3. **无罪推定**：使用"涉嫌""据指控""据供述"等中性表述
4. **不伪精确**：无法确定的事实标注"待核实"
5. **双向提取**：有利和不利事实均须提取

## 7. 刑事 vs 民事关键差异

| 维度 | 刑事案件 | 民事案件 |
|------|---------|---------|
| 当事人结构 | 犯罪嫌疑人/被害人/证人/鉴定人/办案人员 | 原告/被告/第三人 |
| 案件阶段 | 立案→侦查→审查起诉→一审→二审→死刑复核→执行→申诉 | 一审→二审→再审→执行 |
| 核心关注 | 涉嫌罪名/强制措施/羁押期限/办案期限 | 诉讼请求/证据/法律关系 |
| 材料来源 | 国家机关制作为主 | 当事人提供为主 |
| 保密要求 | 更高（涉及国家秘密/个人隐私） | 一般 |
| 时间敏感 | 天级（羁押期限/办案期限） | 月级（诉讼时效） |
| 事实提取重点 | 犯罪构成要件+量刑情节+程序事实 | 法律关系+争议事实+损失 |
| 索引关注 | 证据合法性+证明力+程序合规 | 证据真实性+关联性+证明力 |
| 文件操作 | 创建目录+复制文件+MD副本 | 创建目录+复制文件（无MD副本） |

## 8. 关键度评估方法论

### 8.1 评估维度

| 维度 | high | medium | low |
|------|------|--------|-----|
| 对定罪的影响 | 直接影响 | 间接影响 | 无直接影响 |
| 对量刑的影响 | 显著影响 | 一定影响 | 影响不大 |
| 争议性 | 控辩争议核心 | 可能争议 | 无争议 |
| 替代性 | 不可替代 | 有替代来源 | 可替代 |

### 8.2 特殊标注

- **high（辩护关键）**：对辩方有利的核心证据
- **high（控方核心）**：控方定罪量刑的核心证据
- **待评估**：信息不足，需阅卷后确定

## 9. 册号页码策略（v2.3.0新增）

### 9.1 问题

LLM 在没有页码数据时倾向于编造页码（如"卷1第1-5页"），导致索引表数据可信度下降。页码数据只有3种可靠来源。

### 9.2 四态页码模型

| 状态 | 填写内容 | 触发条件 | 下游使用 |
|------|---------|---------|---------|
| 用户提供 | `卷X第Y-Z页` | 用户在输入中提供了具体页码 | 直接引用 |
| PDF水印 | `卷X第Y-Z页[PDF水印]` | PDF文件内置页码水印可提取 | 引用时标注"PDF水印刷" |
| 待标注 | `待标注` | 无法从上述两种来源确定页码 | 引用时标注"页码待核实" |
| 不适用 | `不适用` | 非卷宗材料（律师自制/电子数据/外部获取） | 无需页码 |

### 9.3 禁止编造原则

- 绝对禁止：用户未提供页码 + PDF无水印 → 仍填"卷1第1-5页"
- 允许推算：扫描件按扫描顺序标注页码范围（标注"[扫描件推算]"）
- 写作红线：页码字段填"待标注"时，下游技能引用须标注"页码待核实"

## 10. 多嫌疑人案件支持（v2.3.0新增）

### 10.1 策略

多嫌疑人案件在案卷材料层面通常是物理共享的（同一本卷），但在事实层面需要区分：

| 维度 | 处理方式 |
|------|---------|
| 材料索引表 | 共享，标注"共犯相关"标记关联到对应嫌疑人 |
| 案情表（一）基本信息 | 主嫌疑人基本信息填写，co_defendants字段列出其他同案人 |
| 案情表（二）构成要件 | 为每个嫌疑人独立组织构成要件事实（主体要件下分列） |
| 案情表（五）争议焦点 | 按嫌疑人分列争议 |

### 10.2 共犯地位标注

在构成要件"主体要件"下标注：
```
#### 3. 主体要件
- 主嫌疑人张某：[F-003] 实施盗窃行为 [来源：M-002]
- 同案人李某（共犯）：[F-004] 望风接应 [来源：M-002]
```

## 11. 证据合规线索方法论（v2.3.0新增）

### 11.1 核心界限：管理 vs 分析

| 维度 | 管理技能（本技能） | 分析技能（criminal-evidence-analysis） |
|------|------------------|---------------------------------------|
| 性质 | 事实观察 | 法律判断 |
| 产出 | `[排非线索]` 标签 + EC-XXX事实描述 | 三性评估 + 非法证据排除判断 + 质证策略 |
| 深度 | "讯问时间22:00-次日02:00" | "构成疲劳审讯，供述可申请排除（刑诉法第56条）" |
| 后续动作 | 标注下游技能消费路径 | 输出完整证据分析报告 |

### 11.2 为什么要这样分？

1. **避免职责越界**：管理技能在索引/案情表阶段未深度阅读材料，不能做出可靠的法律判断
2. **避免污染下游**：管理技能的轻量标签不会预设结论，下游技能可以基于完整阅读做出独立判断
3. **消费效率**：EC-XXX编号让下游技能可以精准定位需要分析的线索，而非通读全部材料

### 11.3 下游消费路径

```
criminal-case-management
    ↓ 输出 EC-001 "夜间讯问" + 标注消费路径 criminal-evidence-analysis
criminal-evidence-analysis
    ↓ 读取 EC-001 → 阅读 M-002全文 → 判断是否构成非法证据
criminal-case-strategy / criminal-defense-speech-trial
    ↓ 消费三性评估结果 → 纳入辩护策略
```
