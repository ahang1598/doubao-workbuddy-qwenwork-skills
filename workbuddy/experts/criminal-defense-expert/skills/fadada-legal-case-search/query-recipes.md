# 案例检索场景选择

## 核心原则

案例检索先判断用户要找的是目标案例、指定官方案例来源、严格限定条件结果，还是普通类案趋势。`case_semantic` 是默认类案入口；不要默认把用户问题改写成短关键词。

检索结果按“目标案例”和“相关案例”分层处理。案号或指定来源不一致时不能写成精确命中，但可以展示事实、争议焦点、案由、法院层级或裁判观点相近的案例，避免把有研究价值的线索直接丢弃。

必须原样保留：

- 案号
- 案件名称或标题
- 法院名、地域、审级、审判程序
- 案由、案件类别、文书类型
- 裁判日期、结案日期、时间范围
- 指导性案例、参考案例、公报案例、典型案例、人民法院案例库、入库编号

## scene 选择

skill 只根据案例检索任务选择 scene。

> **临时调整**：`case_authority_search` 当前暂停使用。指导性案例、参考案例、案例库编号等问题暂时走 `case_semantic`，完整保留来源和编号；没有核验来源时，不得声称已找到指定来源案例。

| scene | 适用条件 | 检索内容建议 |
| --- | --- | --- |
| `case_docket_exact` | 用户给出案号，要求找该案例 | 原始案号；必要时附原问题 |
| `case_structured_search` | 用户明确使用“只要、仅限于、必须、排除其他”等表达限定案由、法院、地域、日期、文书类型等条件 | 原始条件完整保留 |
| `case_semantic` | 默认类案入口；用户描述争议事实，问法院一般怎么判，或给出普通地域/时间/案由条件但未明确限定 | 法律专业改写后的完整自然语言表达，条件用于排序和结果说明 |

## 字段处理边界

skill 负责判断 scene，并在非语义 scene 下给出已确定的 `structuredFields`。后端负责字段校验、数据商字段映射和结果一致性校验。

字段规则：

- 字段抽不准就省略，不要为了字段完整编造案由、法院、日期、案例编号或入库编号。
- 非语义 scene 缺少必填字段时，改用 `case_semantic`，保留改写后的 `searchContent`；不要硬填字段去满足接口入参。
- `case_docket_exact` 必须给 `docketNo`。
- `case_structured_search` 必须给 `hardFilters: true`，并至少提供 `causeOfAction`、`courtName`、`province`、`dateStart`、`dateEnd`、`documentType`、`caseCategory`、`keyword`、`reasoningKeyword`、`citedLaw` 中一个硬条件；普通地域、时间、案由条件不放入 `hardFilters`。
- 审级不传入 `structuredFields`，也不放入 `keyword`；原样保留在 `searchContent` 中，并在返回结果中核对。只有审级一个限定条件时，使用 `case_semantic`。
- `case_semantic` 不传 `structuredFields`，改写后的完整事实和争议焦点是唯一检索内容。

## 字段格式和枚举

- `dateStart`、`dateEnd` 使用 `YYYY-MM-DD`，开始日期不得晚于结束日期。
- `caseType` 仅支持 `ptal`（普通案例）或 `qwal`（权威案例）。
- `documentType` 支持：`判决书`、`裁定书`、`调解书`、`决定书`。
- `caseCategory` 支持：`刑事案件`、`民事案件`、`行政案件`、`执行案件`、`管辖案件`、`国家赔偿与司法救助案件`、`强制清算与破产案件`、`国际司法协助案件`、`非诉保全审查案件`、`其他案件`。
- 当用户表述同时包含多个结构化维度时，分别填写对应字段；每个字段仅使用其定义的枚举值，不得将复合表述直接作为单一字段值。无法可靠拆分时，不填写不确定字段；该信息属于必要限制时，改用 `case_semantic` 并在 `searchContent` 中保留原始表述。
- `reasoningKeyword` 使用简短法律短语，例如“违约金过高”，不得传入完整问句。
- `citedLaw` 使用法规全称及条号，例如“中华人民共和国劳动合同法第二十三条”。
- `province` 使用省级行政区简称；最高人民法院使用 `最高`，新疆生产建设兵团使用全称。
- 不传 `top_k`，由检索服务使用默认值。

容易误判的边界：

- 有案号，走 `case_docket_exact`；案号未找到时，不能用相似案号替代目标案例。
- 用户说“最高法院判过、法院层级高、有代表性”，通常仍走 `case_semantic`，再按法院层级和相关性排序。
- 用户指定最高法发布、人民法院案例库、指导性案例、参考案例、公报案例、典型案例等官方来源：当前使用 `case_semantic`，并在 `searchContent` 中原样保留来源、案例编号和入库编号。
- 只有普通地域、时间、案由、审级条件，仍走 `case_semantic`；只有明确“只要、仅限于、必须、排除其他”时，才走 `case_structured_search`。

## 示例

| 用户问题 | scene | 说明 |
| --- | --- | --- |
| 找这个案例：（2021）粤0104民初44725号 | `case_docket_exact` | 已知案号 |
| 找最高法发布或人民法院案例库里相邻关系油烟损害的参考案例 | `case_semantic` | 指定官方案例来源 |
| 找广东近三年相邻关系纠纷二审判决书 | `case_semantic` | 带普通条件的类案问题，条件用于排序和说明 |
| 只要广东 2021-2025 相邻关系纠纷判决书 | `case_structured_search` | 明确限定地域、时间、案由和文书类型 |
| 竞业限制违约金过高，法院一般会不会调低？ | `case_semantic` | 开放式类案趋势 |
| 看（2021）粤0104民初44725号，并找几个类似的油烟相邻关系案例 | 先 `case_docket_exact`，再 `case_semantic` | 目标案例和同类案例分开检索、分开输出 |

## 结果处理

- `case_docket_exact` 返回后，必须核对案号完全一致。案号不一致时，目标案例按未命中处理；若返回同案由、同法院、同事实类型或同争议焦点案例，可以另列“相关案例”，说明差异。
- 指定官方来源时，只有返回结果明确标注相应案例类型或来源，才能确认来源符合；否则只能列为相关案例线索。
- `case_structured_search` 返回后，必须核对关键筛选条件；条件不全满足时，在相关性中说明差异。该路径仅用于严格限定条件，不作为普通类案默认入口。
- `case_semantic` 返回的是类案候选，用于总结裁判倾向，不构成普遍约束性规则；普通结构化条件可在该路径下作为排序、筛选和差异说明。
## 硬条件与优先条件

结构化条件不要一律作为硬过滤。先判断用户语气：

| 用户表达 | 条件性质 | 处理 |
| --- | --- | --- |
| 只要、限于、必须、限定、排除其他 | 硬条件 | 不满足时按未命中或弱结果说明 |
| 优先、重点、最好、尽量、近似、类似 | 优先条件 | 先检索同类案例，再按该条件排序 |
| 有没有相关案例、法院一般怎么判 | 语义条件 | 保留事实和争议焦点，地域/时间/案由可作为二次筛选 |

非硬条件结果为空或过少时，可以按下列顺序放宽，并记录差异：

1. 放宽文书类型或审级。
2. 放宽法院到同地区或同层级法院。
3. 放宽地域到省内、相邻地区或全国。
4. 放宽时间范围。
5. 放宽案由，保留核心事实和争议焦点。

用户明确限定的硬条件不得自行放宽；确需展示类似案例时，必须写明“不满足用户限定条件，仅作检索线索”。

## 裁判结果方向校验

当用户要求特定结果方向时，检索结果必须校验：

- 支持 / 不支持 / 驳回 / 发回重审 / 改判 / 宣告无罪 / 罪名成立。
- 调减成功 / 未调减 / 承担连带责任 / 不承担连带责任。
- 房主承担责任 / 房主不承担责任 / 责任比例。

事实相近但结果方向不同的案例，不算已检索到目标案例。可以作为相反案例或例外案例展示，用于说明裁判分歧。

## 按需复查

默认一次检索；只有指定案号、指定官方来源、硬条件或裁判结果方向无法支撑回答时，最多再检索一次。普通类案问题不要为了增加样本而复查。
类案检索返回多个案例后，不得为了补齐日期、裁判结果等字段逐案查询详情。使用列表已有字段回答。
只有用户明确指定其中一个案号继续查询时，才调用案号详情检索。

| 现象 | 处理 |
| --- | --- |
| 案号未命中 | 保留未命中结论，再用案由、事实争点或法院地域走 `case_semantic` 查相关案例 |
| 权威案例未命中 | 说明未命中指定来源，再用相同争议焦点查普通裁判文书或典型案例线索 |
| 严格限定条件过窄 | 保留原条件；如展示类似案例，必须标注不满足哪些限定条件 |
| 语义类案结果太宽 | 加入案由、核心事实、争议焦点、请求类型、裁判结果方向进行二次收窄 |
| 只找到少量案例 | 可以展示少量结果，但标注样本不足，不归纳成稳定趋势 |

补充检索不能改写或删除用户给出的案号、法院、案由、地域、日期、文书类型、案例来源和入库编号。

复查时保留用户事实和裁判结果方向；结果方向不一致的案例移到“相反或例外案例”。输出时按相关程度排序，不把仅主题相近的案例放在主结论里。

## 弱结果诊断

- **结果为空**：检查案号格式、案由是否过窄、地域/时间/审级限制是否过强。
- **结果跑偏**：检查是否把目标案号问题误走类案语义路径，或把权威案例需求当普通案例检索。
- **结果只有普通裁判文书**：如果用户指定权威来源，必须说明未命中指定来源；普通裁判文书只能作为研究线索。
- **结果倾向单一**：对趋势问题补充查相反裁判方向、例外事实或不同地区/审级案例。
- **结果时间较早**：提示时效性和后续裁判变化风险，优先展示更新案例。

## 相关案例展示规则

- 相关案例要说明“为什么相关”：争议焦点相同、事实结构相近、案由相同、法院层级较高、裁判观点可比、涉及同一法律关系。
- 相关案例要说明“哪里不一致”：案号不同、来源不符合、地域不同、审级不同、时间较早、文书类型不同或关键事实不同。
- 相关程度使用：高度相关、部分相关、仅供类比、进一步检索线索。
- 精确案号未命中时，先写目标案号未命中，再展示相关案例；不要把相关案例放在结论里冒充目标案例。
- 如果样本少或相关性弱，只作为检索线索，不归纳成稳定裁判趋势。

## 关键词字段使用边界

`keyword` 和 `reasoningKeyword` 只用于 `case_structured_search` 中用户明确指定的硬条件。`case_semantic` 始终使用完整自然语言 `searchContent`，不把问题压缩成短关键词，也不删除案号、法院、案由、时间范围等定位信息。
