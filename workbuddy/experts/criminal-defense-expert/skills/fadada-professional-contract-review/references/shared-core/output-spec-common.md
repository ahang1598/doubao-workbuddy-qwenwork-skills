# 输出物格式共享规范（共享内核 · SSOT）

> fadada / english 两技能共用的 D3 输出物格式硬约束单一真源。GATE-critical 四项同时在各 SKILL.md 正文保留可见。

## 1. OOXML 真修订（D3-S1，critical）

修订版 / 带批注修订版必须使用 OOXML 修订标记：
- 新增 / 替换 → `<w:ins>`；删除 → `<w:del>` + `<w:delText>`。
- 禁止用 `【已修订】【保留原文】【修改前】【修改后】〔删除〕〔新增〕（修改：` 等内联文字替代。
- 批注版批注气泡含 `<w:comment>`（作者建议填技能标识，如「法大大iTerms」）。

## 2. 无 emoji（D3-S2，critical）

所有本地生成的 docx / xlsx 全文禁 emoji 字符（WPS 兼容）。风险与状态必须有**文字标签**，不得只靠颜色表达。

## 3. 表格宽度（D3-S3，critical）

Word 表格总宽度不得超过页面内容区：A4 + 上下左右 25.4mm 边距时约 **9026 DXA**；
按 `word/settings.xml` 实际 `<w:pgMar>` 重算并留 2–3mm 余量。签名行不得跨页拆分。

## 4. 依据标签（D3-S4，critical）

仅 `[用规][要点][法规][惯例]` 四种，禁 emoji 与自创标签。每条 `[法规]/[用规]/[要点]` 依据
**必须带 「」 原文摘录**（裸标签/纯转述无效），缺原文须补全或降级 `待核查`。完整规则见 `evidence-labels.md` §3。

## 5. 报告文本卫生

- 正式法律交付物（评审报告 / 意见书 / 风险清单）必须含免责声明；修订版正文不插入。
- 报告 JSON 字段值为**纯文本**，禁 Markdown 标记（`##` / `**` / 反引号 / 列表符号）——
  docx 不渲染 Markdown，标记会原样泄漏进文档；分组用 items 数组。校验器对含裸标记的报告判 fail。
- 对话内只输出 Markdown 预览，不得声称已生成实际不存在的下载文件。

## 6. 交付清单（manifest）

每次交付消息结尾附交付清单：每个生成文件一行——文件名、`outputs/` 路径、用途、状态（已交付 / 待确认后生成）。
生成了但未列给用户的文件 = 交付不完整。

## 7. 推荐固定章节（非 critical，建议对齐）

评审报告建议七段式：执行摘要 / 法务视角 / 财务视角 / 业务·商务视角 / 风险管理视角 /
优先级+风险等级对照表 / 综合决策矩阵。修订版末尾建议含「修订说明汇总表」（# / 条款 / 修改原因 / 风险等级 / 依据来源）。
