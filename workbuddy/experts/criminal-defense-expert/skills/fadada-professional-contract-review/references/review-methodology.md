# 审查方法论（双向审查与结构硬校验）

进入正式审查（`review_intake.py` 返回上下文包之后）与本地输出生成前读取本文件。
方法论用于组织审查执行，不改变 SKILL.md 的安全规则、依据标签与输出格式约束。

> **输入前置（不可绕过）**：本方法论的审查对象必须是 `review_intake.py` 上下文包里的
> `contractPath` 与 `extractedPath`。**未跑 `review_intake.py` 就不得开始执行本方法论**——
> 用 `Read`／附件读到的正文做扫描，拿不到段落 ID、产不出 redline、审查范围也无法与
> `sourceSha256` 对账。详见 `references/runtime-playbook.md` §0 执行铁律。

> `review_build.py` 构建 docx；不是对话里的长篇分析文本。

## 1. 双向审查

只做正向审查会系统性遗漏「合同里没有的东西」。两个方向都必须执行：

- **正向扫描**：合同里有 → 逐条检查是否有害、歧义、冲突或不可执行。
- **反向扫描**：清单要求 → 逐项检查合同是否有、是否被稀释、方向是否反转。

反向清单来源（按优先级）：

1. iTerms 组织清单命中时：以 `normalized_rules[]` 全量为反向清单，逐项核对。
2. 用户上传规则/审查要点：逐条转为「合同应有什么」核对。
3. 均无时：按合同类型构建「应有结构」影子清单（当事人与权限、范围、价款与支付、期限与续约、违约与救济、保密/数据/IP、终止与存续、争议解决、通知与变更），结论标注为一般实践（`[惯例]`），不得冒充用户规则。

每项反向核对记录四态状态码：**符合 / 偏离 / 缺失 / 反转**（反转 = 权利义务方向与应有立场相反，最高风险，优先处置）。

输出要求：评审报告中给出反向覆盖统计（应核对项数、符合数、偏离数、缺失数、反转数）。统计是描述性计数，**不得**折算为「合同安全分」或类似评分。

## 2. 结构参数硬校验

条款级审查之前，先对交易骨架做硬校验（防止把关键参数当事实记录而不校验）：

| # | 参数 | 核对点 |
|---|---|---|
| 1 | 地域/范围 | 许可、销售、服务的地域与领域边界 |
| 2 | 排他性 | 受益方、受限方、期限、例外、维持条件 |
| 3 | 当事人与角色 | 主体正确性、关联方延伸、担保方、签约权限 |
| 4 | 权利流向 | 谁授予、谁取得、谁控制、谁同意；方向是否与我方立场一致 |
| 5 | 期限与退出 | 起始、续约、终止事件、过渡、存续条款 |
| 6 | 经济条款 | 价款、税费、币种、调价、抵销、审计 |
| 7 | 控制权 | 批准权、变更控制、和解控制 |
| 8 | 责任结构 | 赔偿方向、责任上限与例外 |

iTerms 清单含 `transaction_profile` 时，以其为基准比对；任一参数出现「反转」立即列为高风险，先于普通条款偏好处理。

## 3. 权利对称性检查

对每项重大权利（许可范围、终止权、赔偿、审计权、维权权、改进归属），对比双方：受益方/受限方、触发条件、限定语与例外、救济、期限与存续。单向权利本身可以成立，但必须是**有意安排**且与交易结构一致；「对方有明示保留而我方没有」「对方可任意终止而我方受限」是典型红旗。

## 4. 级联扫描

每处重大修订（含 operations.json 中的 replace 操作）确定后，全文核查连锁影响：

- 同一定义术语及其同义表述；
- 关联的陈述保证、义务、条件与救济条款；
- 交叉引用与附件引用；
- 日期、期限、公式、阈值、币种；
- 终止、存续、赔偿、保险、责任上限的 carve-out。

发现不一致即补充 operations 或在报告中列为待确认项。

## 5. 歧义扫描

- **语义歧义**：一词多义（如「验收」未定义标准）。
- **句法歧义**：修饰语、否定、连词、标点的归属不唯一。
- **上下文歧义**：定义、优先顺位条款、例外、附件或外部文件相互冲突。

区分「故意的弹性」与歧义：弹性标准仅当决策者、考量因素、证据与后果足够明确时可接受，否则按歧义处理。

## 6. IP 三层检查（IP 密集合同适用）

对既有 IP、交付成果、改进、共同开发，分别核查三层，只查归属是隧道视野：

1. **L1 归属**：谁拥有、许可范围、保留权利。
2. **L2 申请/控制**：谁控制申请与维持、费用承担、配合义务。
3. **L3 维权**：谁有权起诉、和解控制、所得分配、配合义务。

红旗：我方平台改进归属未明示；一方有申请控制条款另一方缺失；约定了申请费用但未约定维权费用。

## 7. 常见失败模式自检

| 失败模式 | 防范 |
|---|---|
| 记录参数但不校验 | §2 结构硬校验 |
| 以「行业标准」为由降级用户规则偏离项 | 用户规则优先于行业惯例（依据优先级不变） |
| 80% 篇幅花在存在的条款上 | §1 反向扫描强制执行 |
| 按合同目录审查、继承其盲点 | §1 以清单/影子结构为大纲 |
| 只分析对方权利 | §3 对称性检查 |
| 只查 IP 归属 | §6 三层全查 |
