# 输入规格

> 本文件定义 criminal-interrogation-analysis 技能的完整输入参数规格

## 1. 必需输入

### 1.1 案件基本信息

| 字段 | 类型 | 说明 | 验证规则 |
|------|------|------|----------|
| `case_name` | string | 案件名称（嫌疑人+罪名） | 非空 |
| `interrogation_text` | string | 讯问笔录文本（≥1份） | 非空，文本长度≥50字符 |

### 1.2 笔录内容

| 字段 | 类型 | 说明 | 验证规则 |
|------|------|------|----------|
| `interrogation_records` | array[object] | 讯问笔录结构化数组 | 至少1份笔录 |

每份笔录对象结构：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `record_id` | string | 是 | 笔录编号（如I-001） |
| `date` | string | 是 | 讯问日期（YYYY-MM-DD） |
| `time_start` | string | 否 | 开始时间 |
| `time_end` | string | 否 | 结束时间 |
| `location` | string | 否 | 讯问地点 |
| `interrogators` | array[string] | 否 | 讯问人员姓名 |
| `content` | string | 是 | 笔录正文内容 |

## 2. 可选输入

### 2.1 分析参数

| 字段 | 类型 | 枚举值 | 默认值 | 说明 |
|------|------|--------|--------|------|
| `analysis_depth` | enum | quick/standard/deep | standard | 分析深度 |
| `focus_layers` | array[int] | 1-10 | 全部 | 指定分析层 |
| `focus_issues` | array[string] | - | [] | 重点关注问题 |

### 2.2 辅助材料

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `objective_evidence` | array[object] | [] | 客观证据清单（书证/物证/电子数据/鉴定意见） |
| `audio_transcript` | string | [待补充] | 同步录音录像文字转写稿 |
| `co_defendant_statements` | array[object] | [] | 同案犯供述 |
| `client_statement` | string | [待补充] | 当事人在律师会见时的陈述 |

### 2.3 程序上下文

| 字段 | 类型 | 枚举值 | 默认值 | 说明 |
|------|------|--------|--------|------|
| `case_stage` | enum | 侦查/审查起诉/一审/二审/再审 | 审查起诉 | 诉讼阶段 |
| `suspect_role` | enum | 犯罪嫌疑人/被告人 | 犯罪嫌疑人 | 当事人角色 |
| `suspect_name` | string | [待补充] | 嫌疑人/被告人姓名 |

### 2.4 客观证据对象结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `evidence_id` | string | 证据编号 |
| `evidence_type` | string | 证据类型（书证/物证/电子数据/鉴定意见） |
| `evidence_name` | string | 证据名称 |
| `key_facts` | array[string] | 该证据可证明的关键事实要素 |

## 3. 输入宽容度契约

### 3.1 最小输入识别

| 最小输入 | 触发条件 | 处理方式 |
|----------|----------|----------|
| 仅案件名称+笔录文本 | 基础二要素 | 自动提取笔录要素，启动标准分析 |
| 仅1份笔录 | 单份笔录 | 跳过演变/翻供/多人交叉分析，标注[待补充] |
| 上游技能产物 | criminal-case-reading-notes | 直接消费结构化笔录数据 |
| 自然语言描述 | 非结构化输入 | 提取结构化字段 |

### 3.2 信息补全策略

1. **从笔录文本中提取**：自动识别讯问时间/地点/人员/内容
2. **推理补全**：根据罪名推理常见客观证据类型
3. **上游消费**：优先使用 criminal-case-reading-notes 产物
4. **占位符标注**：无法提取的信息用 `[待补充]` 标注

### 3.3 交互补全限制

交互补全最多3轮，超过后强制进入 SOFT_DEGRADED 模式。

## 4. 深度模式与覆盖层

| 深度模式 | analysis_depth | 覆盖分析层 | 典型场景 |
|----------|---------------|-----------|---------|
| 快速扫描 | quick | 第1-2层 | 初步筛查、时间紧迫 |
| 标准分析 | standard | 第1-6层 | 常规案件、阅卷阶段 |
| 深度分析 | deep | 第1-10层 | 重大案件、翻供/非法证据排除 |
