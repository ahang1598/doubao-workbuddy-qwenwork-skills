# 输入规格

> 本文件定义 criminal-cross-examination 技能的完整输入参数规格
> 遵循 compiler/ssot.md §17（SSOT）：输入宽容度契约
> 版本：v2.2.0

## 1. 必需输入

### 1.1 案件基本信息

| 字段 | 类型 | 说明 | 验证规则 |
|------|------|------|----------|
| `defendant_name` | string | 被告人姓名 | 非空 |
| `alleged_crime` | string | 涉嫌罪名 | 非空 |
| `evidence_list` | array[object] | 控方证据清单 | 至少1项 |

### 1.2 证据清单格式

每项证据应包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `evidence_name` | string | 是 | 证据名称（如"被害人赵某陈述"） |
| `evidence_type` | enum | 是 | 证据类型 |
| `evidence_summary` | string | 推荐 | 证据内容摘要 |
| `cross_exam_focus` | string | 否 | 针对该证据的质证重点 |

**evidence_type 枚举值**：

| 类型值 | 分类 | 说明 | 编号前缀 |
|------|------|------|----------|
| witness_testimony | 言词证据 | 证人证言 | E-Oral |
| victim_statement | 言词证据 | 被害人陈述 | E-Oral |
| suspect_statement | 言词证据 | 犯罪嫌疑人/被告人供述和辩解 | E-Oral |
| expert_opinion | 鉴定意见 | 鉴定意见/检验报告 | E-Exp |
| documentary | 实物证据 | 书证 | E-Obj |
| physical | 实物证据 | 物证 | E-Obj |
| audio_visual | 实物证据 | 视听资料 | E-Obj |
| electronic_data | 实物证据 | 电子数据（独立类型，需七要素审查） | E-Obj |
| investigation_record | 程序性证据 | 勘验/检查笔录 | E-Pro |
| identification_record | 程序性证据 | 辨认笔录（独立类型，需四要素审查） | E-Pro |
| inspection_record | 程序性证据 | 侦查实验笔录（独立类型，需条件相似性审查） | E-Pro |

> **v2.1.0 变更**：`audio_visual` 类型新增 `electronic_data` 子类型（电子数据需独立审查七要素），`investigation_record` 拆分为 `identification_record`（辨认笔录）和 `inspection_record`（侦查实验笔录），三者分属不同程序性证据，审查要点完全不同。

## 2. 可选输入

### 2.1 质证策略

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `cross_exam_focus` | string | 全部证据三性 | 质证重点 |
| `defense_type` | enum | 事实之辩 | 辩护方向 |
| `trial_stage` | enum | 一审 | 审理阶段 |

**defense_type 枚举值**：
- 事实之辩：否认指控事实（无罪辩护）
- 定罪之辩：行为不构成犯罪/构成他罪（重罪→轻罪）
- 量刑之辩：承认事实但争取从轻（罪轻）

### 2.2 案件补充信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `prior_convictions` | boolean | false | 是否有前科 |
| `has_confession` | boolean | false | 是否有供述 |
| `has_repentance` | boolean | false | 是否认罪认罚 |
| `victim_reconciliation` | boolean | false | 是否取得被害人谅解 |
| `detention_date` | string | [待补充] | 羁押日期 |
| `court_name` | string | [待补充] | 审理法院全称 |

### 2.3 证据矛盾提示

| 字段 | 类型 | 说明 |
|------|------|------|
| `evidence_contradictions` | array[string] | 已知的证据间矛盾 |
| `procedural_issues` | array[string] | 已知的程序性问题 |

## 3. 输入宽容度契约

### 3.1 最小输入识别

| 最小输入 | 触发条件 | 行为 |
|----------|----------|------|
| 仅被告人+罪名 | 无证据清单 | 交互询问证据清单（最多3轮） |
| 仅"质证"关键词 | 无任何信息 | 询问案件基本信息+证据清单 |
| 自然语言描述 | 非结构化输入 | 提取关键信息生成质证提纲 |

### 3.2 信息补全策略

1. **从描述中提取**：自然语言处理提取证据清单和质证重点
2. **推理补全**：根据罪名推断常见证据类型
3. **占位符标注**：无法提取的信息用 `[待补充]` 标注

### 3.3 交互补全限制

交互补全最多3轮，超过后强制进入 SOFT_DEGRADED 模式。

## 4. 场景适配规则

### 4.1 辩护方向适配

| 辩护方向 | 质证策略侧重点 | 结构顺序 |
|----------|----------------|---------|
| 事实之辩 | 合法性为首要（先打掉），真实性为次要（找矛盾），攻击证据链断裂 | 合法性 → 真实性 → 关联性 |
| 定罪之辩 | 关联性为首要（行为与该罪名构成要件不对应），合法性/真实性为辅助 | 关联性 → 合法性 → 真实性 |
| 量刑之辩 | 不利证据合法性攻击+有利证据真实性防守（攻防二元策略） | 不利证据：合法性→真实性→关联性；有利证据：真实性→关联性→确保采信 |

### 4.2 证据类型适配

| 证据类型 | 质证侧重 | 专项审查 |
|----------|----------|----------|
| 言词证据 | 真实性（有无矛盾/诱导/主观偏颇）+ 一致性 + 交叉询问 | 利害关系/感知能力/记忆/表达 |
| 实物证据 | 同一性（是否原始证据）+ 完整性（链条是否断裂） | 提取程序/保管链 |
| 鉴定意见 | 鉴定资质 + 鉴定方法 + 检材来源 + 交叉询问 | 六要素全覆盖 |
| 电子数据 | 完整性校验 + 取证程序 + 时间戳真实性 | 七要素全覆盖 |
| 辨认笔录 | 混同规则 + 单独辨认 + 辨认前无接触/无暗示 + 见证人 | 四要素全覆盖 |
| 侦查实验笔录 | 条件相似性 + 多次实验一致性 + 见证人 | 条件对比 |
| 现场勘验笔录 | 见证人 + 当场签字 + 物品清单 | 程序完整性 |
