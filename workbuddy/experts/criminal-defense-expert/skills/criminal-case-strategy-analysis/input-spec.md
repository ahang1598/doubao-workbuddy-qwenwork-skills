# 输入规格

> 本文件定义 criminal-case-strategy 技能的完整输入参数规格
> 遵循 compiler/ssot.md §17（SSOT）：输入宽容度契约

## 1. 必需输入

### 1.1 案件基本信息

| 字段 | 类型 | 枚举值 | 说明 | 验证规则 |
|------|------|--------|------|----------|
| `suspect_name` | string | - | 被告人/犯罪嫌疑人姓名 | 非空 |
| `alleged_crime` | string | - | 涉嫌罪名 | 非空 |
| `case_stage` | enum | 侦查/审查起诉/一审/二审 | 案件阶段 | 必须为枚举值 |

### 1.2 案件事实

| 字段 | 类型 | 说明 | 验证规则 |
|------|------|------|----------|
| `case_facts` | string | 案件基本事实描述 | 非空，自由文本 |

## 2. 可选输入

### 2.1 被告人信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `suspect_gender` | string | [待补充] | 性别 |
| `suspect_age` | string | [待补充] | 年龄/出生日期 |
| `suspect_prior` | boolean | false | 是否有前科 |
| `suspect_custody` | boolean | true | 是否在押 |
| `custody_duration` | string | [待补充] | 羁押时长 |

### 2.2 控方证据

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `prosecution_evidence` | array[string] | [] | 控方主要证据清单 |
| `evidence_weaknesses` | array[string] | [] | 已发现的证据弱点 |

### 2.3 辩方证据/线索

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `defense_evidence` | array[string] | [] | 辩方已有证据 |
| `mitigating_factors` | array[string] | [] | 从轻/减轻情节线索 |
| `witness_leads` | array[string] | [] | 辩方证人线索 |

### 2.4 程序信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `detention_date` | string | [待补充] | 拘留/逮捕日期 |
| `procedural_issues` | array[string] | [] | 已发现的程序问题 |
| `investigation_stage` | enum | 初查/立案/侦查终结 | 侦查阶段细分 |

### 2.5 辩护目标

| 字段 | 类型 | 枚举值 | 默认值 | 说明 |
|------|------|--------|--------|------|
| `defense_objective` | enum | 无罪/罪轻/减轻/缓刑/最轻 | 最轻 | 辩护总体目标 |
| `defense_type` | enum | 事实之辩/定罪之辩/量刑之辩/综合 | 综合 | 辩护层次 |

## 3. 输入宽容度契约

### 3.1 最小输入识别

| 最小输入 | 触发条件 | 处理方式 |
|----------|----------|----------|
| 仅被告人姓名+罪名 | 基础二要素 | 生成通用策略框架，待补充 |
| 仅"策略"/"怎么办" | 最小触发 | 询问案件基本信息 |
| 仅案件事实描述 | 非结构化输入 | 提取结构化字段 |
| 已有阅卷笔录/证据分析 | 上游技能产物 | 直接消费结构化数据 |

### 3.2 信息补全策略

1. **从案件描述中提取**：自然语言处理提取罪名、阶段、关键事实
2. **推理补全**：根据罪名推理法定刑幅度、常见辩护要点
3. **上游技能消费**：如有criminal-case-reading-notes/criminal-evidence-analysis产物，优先采用
4. **占位符标注**：无法提取的信息用 `[待补充]` 标注

### 3.3 交互补全限制

交互补全最多3轮，超过后强制进入 SOFT_DEGRADED 模式。

## 4. 场景适配规则

### 4.1 阶段适配

| 阶段 | 策略侧重点 | 可用信息量 | 策略灵活性 |
|------|-----------|-----------|-----------|
| 侦查 | 证据保全+权利保障+初步方向 | 极少（律师会见受限） | 高（后续可调整） |
| 审查起诉 | 事实核查+证据分析+辩护方向 | 较多（可阅卷） | 中高 |
| 一审 | 质证策略+辩论准备+量刑辩护 | 充分（全部卷宗） | 中 |
| 二审 | 一审判决批判+新证据+改判理由 | 有限（加一审材料） | 低（受上诉理由约束） |

### 4.2 辩护三层次路由

| defense_type | 策略核心 | 典型场景 |
|-------------|----------|----------|
| 事实之辩 | 否认指控事实+证据不足 | 当事人不认罪+证据薄弱 |
| 定罪之辩 | 行为定性+罪名认定+此罪彼罪 | 事实无争议但定性有分歧 |
| 量刑之辩 | 从轻/减轻/缓刑/免刑 | 事实和罪名无争议，争量刑 |
| 综合 | 以上多种策略组合 | 案情复杂，多角度论证 |

### 4.3 辩护目标适配

| defense_objective | 策略强度 | 风险等级 |
|-------------------|----------|----------|
| 无罪 | 最强（全面挑战事实/证据/程序） | 高（败诉后果严重） |
| 罪轻 | 较强（承认部分事实，争定性） | 中高 |
| 减轻 | 中等（承认犯罪，争减轻情节） | 中 |
| 缓刑 | 较弱（承认犯罪+社会危险性低） | 低 |
| 最轻 | 最弱（全面认罪，争最小处罚） | 最低 |
