# 输入规格

> 本文件定义 criminal-meeting-guide 技能的完整输入参数规格
> 遵循 compiler/ssot.md §17（SSOT）：输入宽容度契约

## 1. 必需输入

| 字段 | 类型 | 枚举值 | 说明 | 验证规则 |
|------|------|--------|------|----------|
| `suspect_name` | string | - | 犯罪嫌疑人/被告人姓名 | 非空 |
| `alleged_crime` | string | - | 涉嫌罪名 | 非空 |
| `meeting_purpose` | enum | 初次会见/案件核实/策略沟通/庭前准备/宣判后 | 会见目的 | 必须为枚举值 |

## 2. 可选输入

### 2.1 被会见人信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `suspect_gender` | string | [待补充] | 性别 |
| `suspect_age` | string | [待补充] | 年龄 |
| `suspect_custody` | boolean | true | 是否在押 |
| `custody_location` | string | [待补充] | 羁押地点 |
| `custody_duration` | string | [待补充] | 羁押时长 |
| `prior_record` | string | [待补充] | 前科/累犯情况（影响量刑档次和取保可行性） |
| `mental_health` | string | [待补充] | 精神疾病史（影响刑事责任能力认定） |
| `minor_status` | boolean | false | 是否未成年人（影响程序权利和强制措施适用） |

### 2.2 到案方式信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `arrival_method` | enum | [待补充] | 到案方式：抓捕/电话传唤后主动到案/主动投案/通缉到案 |
| `arrival_details` | string | [待补充] | 到案经过详情（时间/地点/在场人员） |
| `co_defendants_arrival` | string | [待补充] | 同案犯到案情况（关联立功认定） |

> **到案三关联**：到案方式直接决定自首认定（主动投案/传唤后到案→可能构成自首）、立功认定（同案犯到案→可能构成立功）、取保可行性（同案犯未到案→取保难度增大）。

### 2.3 同案犯信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `co_defendants_info` | string | [待补充] | 同案犯信息：姓名/是否到案/强制措施/认罪认罚情况 |
| `co_defendants_sentencing` | string | [待补充] | 同案犯量刑建议（地位比对法：预判自身刑期区间） |
| `role_in_crime` | string | [待补充] | 当事人在共同犯罪中的地位和作用（主犯/从犯/胁从犯） |

### 2.4 案件信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `case_stage` | enum | 侦查 | 侦查/审查起诉/一审/二审 |
| `case_facts` | string | [待补充] | 已知案件事实 |
| `prosecution_evidence` | array[string] | [] | 已知控方证据 |
| `property_seizure` | string | [待补充] | 财产处置情况：查封/扣押/冻结详情（手机扣押是关键证据来源） |

### 2.5 会见参数

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `focus_questions` | array[string] | [] | 重点关注问题 |
| `defense_direction` | string | [待补充] | 已确定的辩护方向 |
| `special_concerns` | array[string] | [] | 特殊关注事项（健康/家庭等） |

### 2.6 律师信息

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `lawyer_name` | string | [待补充] | 律师姓名 |
| `lawyer_firm` | string | [待补充] | 律师事务所 |

## 3. 输入宽容度契约

| 最小输入 | 处理方式 |
|----------|----------|
| 仅嫌疑人+罪名+目的 | 生成会见提纲 |
| 仅"会见"/"提纲" | 询问案件信息 |

交互补全最多3轮。

## 4. 场景适配规则

### 4.1 会见目的适配

> 问题类型权重和典型问题数量详见 [workflow-detail.md Phase 2](./workflow-detail.md#phase-2-会见目的路由)

| meeting_purpose | 会见重点 | 典型问题 |
|-----------------|----------|----------|
| 初次会见 | 了解当事人+案情+权利告知+到案方式+同案犯 | 是否被刑讯/到案经过/同案犯是否到案/是否有自首立功 |
| 案件核实 | 核实事实+证据+笔录一致性+矛盾点 | 对XX笔录内容有无异议/案发时的情况 |
| 策略沟通 | 确定辩护方向+风险评估+预期管理 | 是否认罪/是否申请取保/同案犯量刑比对 |
| 庭前准备 | 庭审流程+质证预演+最后陈述 | 庭审注意事项+如何回答发问 |
| 宣判后 | 判决解读+是否上诉+刑期预期 | 对判决有无异议/是否上诉 |

### 4.2 阶段适配

| 阶段 | 会见权限制 | 会见重点 |
|------|-----------|----------|
| 侦查 | 危害国家安全/恐怖活动/特别重大贿赂需批准 | 权利告知+基本事实+到案方式+程序合法性 |
| 审查起诉 | 无限制 | 事实核实+笔录聚焦+辩护方向+同案犯地位比对 |
| 一审 | 无限制 | 质证准备+庭审预演+量刑沟通 |
| 二审 | 无限制 | 一审批判+上诉理由+新证据 |

### 4.3 首次会见 vs 后续会见差异

| 维度 | 首次会见 | 后续会见 |
|------|----------|----------|
| 核心任务 | 三确认框架（委托→权利→程序合法性）+ 事实初步了解 | 针对性核实+辩护策略推进 |
| 权利告知 | 完整告知 | 确认已知+变化更新 |
| 问题设计 | 宽覆盖（到案/同案犯/前科/财产/程序） | 聚焦上次遗留+新发现 |
| 策略讨论 | 不宜过早深入辩护策略，先夯实事实基础 | 可深入辩护方向选择+量刑预期 |
| 时长预期 | 较长（需完成三确认+全面了解） | 较短（聚焦特定问题） |
