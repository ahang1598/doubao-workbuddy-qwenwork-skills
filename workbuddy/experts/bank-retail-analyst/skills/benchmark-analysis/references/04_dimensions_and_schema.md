## 2. 同业排名与变化追踪

对上述所有指标计算**7家银行**中的基准行排名，**重点关注**：

## 3. Step 7 完整性校验（2026-04-29 强制）

> **来源**：2026-04-29 故障复盘——当次运行因只跑了维度一、`rankings` 只覆盖 6 个指标，后续 PDF 生成时只能把维度二/三/四做成"数据暂缺"占位块，严重影响交付质量。

生成 `benchmark_analysis_result.json` 后，**必须**在输出前做一次结构化自检：

```python
# 必查项（不通过则 raise，不允许继续生成 PDF）
assert len(meta["dimensions"]) >= 4, "维度未覆盖完整（至少 4 个）"
assert all(y in rankings for y in ["2024年度", "2025年度"]), "缺少本期/上期 rankings"

# 每个维度的核心指标至少要有 2025 横截面排名
REQUIRED_METRICS_2025 = [
    "零售分部营业净收入",            # 维度一
    "零售信用减值损失",              # 维度二（兴业浦发允许 N/A）
    "全行业务费用",                  # 维度三
    "个人存款成本率",                # 维度四
]
for metric in REQUIRED_METRICS_2025:
    block = rankings["2025年度"].get(metric, {})
    assert len(block) >= 3, f"{metric} 2025 年参排银行 <3 家，无法构成同业比较"

# 每个维度的参排家数不得少于 3（7 家口径）
for metric, block in rankings["2025年度"].items():
    if len(block) < 3:
        log.warning(f"{metric} 仅 {len(block)} 家参排，结论可信度低")
```

### 降级策略（当 Skill 1 / 2 抽不到零售分部级别指标时）

| 维度 | 理想口径 | 降级口径 | 触发条件 |
|---|---|---|---|
| 维度三·营业支出 | 零售分部营业支出 / 零售分部业务费用 | 全行业务费用 / 全行成本收入比 | 零售分部字段 < 3 家有数据 |
| 维度四·存贷利差 | 零售贷款收益率 - 个人存款成本率 | 仅呈现已披露家的个人存款成本率 | 零售贷款收益率 < 3 家有数据 |

降级时**必须在报告中明确标注**"⚠️ 关键口径风险：XX 指标行业普遍不披露，本维度降级为……"，不得静默回退。

## 4. `benchmark_analysis_result.json` Schema（2026-04-29 固化）

```jsonc
{
  "meta": {
    "generated_at": "ISO 8601",
    "banks": ["中信","招商","平安","兴业","浦发","光大","民生"],
    "periods": ["...", "2024年度", "2025年度"],
    "dimensions": [                                // 必须 4 项（即使某维度降级也要列出）
      "维度一：零售业务分部营收分析",
      "维度二：零售信用减值损失分析",
      "维度三：零售营业支出分析（降级·全行口径）",
      "维度四：零售存贷利差分析"
    ]
  },
  "results": {
    "<bank>": {
      "<period>": {
        "<原始字段>": 数值,
        // 本 Skill 计算的派生字段（单位：% 或 pp 或 百万元）：
        "零售营收在全行营收占比": 派生,
        "零售分部利息净收入": 营收-非息(派生),
        "零售非息在全行非息占比": 派生,
        "零售非息在零售营收占比": 派生,
        "零售减值负担率": 派生,
        "零售减值占全行减值占比": 派生,
        "零售减值成本率": 派生,
        "全行成本收入比": 派生,
        "零售存贷利差(派生)": 派生,
        "零售贷款占比": 派生
      }
    }
  },
  "rankings": {
    "<period>": {
      "<metric>": {
        "<bank>": {"rank": int, "value": num}
      }
    }
  }
}
```

### 固化规则

1. `meta.dimensions` 长度恒为 4（降级维度也出现在列表中，命名后缀注明"（降级·XX口径）"）
2. `rankings[<period>][<metric>]` 的 bank 键仅包含**本期有数据的银行**；缺数据的银行不在 rankings 内，但应在 PDF/MD 的"未参与排名（数据缺失）"行中列出
3. `results[<bank>][<period>]` 可扁平携带原始字段与派生字段；同名字段以派生覆盖原始（标注 `@notes: ["派生来源…"]` 留痕）

## 5. PDF 生成失败模式（2026-04-29 复盘）

| 故障 | 现象 | 根因 | 护栏 |
|---|---|---|---|
| 模板未渲染 | PDF 正文出现 `{{ ctx.xxx }}` / `{% for ... %}` | 脚本没走 `env.get_template().render()`，用字符串拼接 | shared runtime 的 `_detect_jinja_residuals` 渲染后扫描，发现即 raise |
| 维度不全 | PDF 维度二~四全是"数据暂缺"占位块 | 只跑了维度一的分析；result.json 的 `meta.dimensions` 只有 1 项 | Step 7 自检 + 本节前置条件硬门槛 |
| 排名家数少 | "零售营收占比"排名只显示 3 家 | 上一轮 rankings 没覆盖全所有有数据的银行 | Step 7 的 `len(block) >= 3` 与"从 DB 全量重算"约束 |
| ctx 字段名错 | 模板里 `ctx.kpi_cards` 但 ctx 直接 `kpi_cards` | 业务脚本把顶层 ctx 与 `ctx.*` 混淆 | 业务模板统一走 `ctx.*`；守卫会捕捉 |
