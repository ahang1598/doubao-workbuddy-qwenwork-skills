# 引用匹配器

## 一、适用场景

- 交底书背景技术部分需要补充引用支撑
- 技术观点、实验数据、对比结论需要文献依据
- 审查意见中需要引用现有技术作为论证依据
- 需要生成规范的参考文献清单（GB/T 7714-2015）
- 需要导出RIS/ENW/BibTeX供文献管理软件使用

## 二、观点识别策略

### 2.1 需要引用的观点类型

| 类型 | 示例 |
|------|------|
| 技术问题陈述 | "CSI对相对运动极其敏感，设备自身晃动导致CSI矩阵剧变" |
| 现有技术描述 | "PIR传感器只能检测移动热源，人静止则失效" |
| 实验数据引用 | "误报率从15.3%降至2.0%" |
| 技术效果对比 | "相比传统方法，本发明在XX方面提升了30%" |
| 技术标准引用 | "符合IEEE 802.11n标准" |

### 2.2 观点提取规则

- 每段至少提取1个核心观点（如有）
- 涉及数据、百分比、对比结论的必须提取
- 涉及技术问题陈述的必须提取
- 常识性知识（如"WiFi基于无线电波"）不需要引用

## 三、匹配与核验

### 3.1 检索匹配流程

1. 提取观点关键词
2. 构建检索式（核心词 + 同义词 + 上位词）
3. 专利库（CNIPA/Google Patents）+ 学术库（CrossRef/Semantic Scholar）并行检索
4. 筛选最相关的 3-5 篇候选文献
5. 核验 DOI/专利号/URL 的真实性
6. 选择最匹配的 1-2 篇作为引用

### 3.2 引用核验标准

| 核验项 | 通过标准 |
|--------|---------|
| DOI | 可通过 CrossRef 或 doi.org 访问 |
| 专利号 | 可通过 Google Patents 或国知局官网访问 |
| URL | 可直接访问，内容与引用描述一致 |
| 作者/标题 | 与数据库记录完全匹配 |

**核验状态标记**：
- ✅ 已核验：DOI/专利号/URL 全部可访问
- ⚠️ 待核验：部分信息可访问但不完整
- ❌ 无法访问：所有链接均无法打开

## 四、输出格式

### 4.1 引用匹配报告

| 字段 | 说明 |
|------|------|
| 引用序号 | [1], [2], [3]... |
| 引用位置 | 说明书段落编号或章节 |
| 观点原文 | 需要支撑的技术观点 |
| 引用文献 | 完整著录信息 |
| 核验状态 | ✅/⚠️/❌ |
| 匹配度 | 高/中/低 |

### 4.2 参考文献清单（GB/T 7714-2015）

**专利**：[序号] 申请人. 专利名称: 专利号[P]. 授权公告日.
**期刊**：[序号] 作者. 文章标题[J]. 期刊名, 年份, 卷(期): 起止页码.
**会议**：[序号] 作者. 文章标题[C]//会议名. 会议地点, 年份: 起止页码.

### 4.3 导出文件

- `references.ris`：RIS 格式（EndNote/NoteExpress）
- `references.enw`：ENW 格式（EndNote）
- `references.bib`：BibTeX 格式（LaTeX/Zotero）

## 五、红线规则

- **绝对禁止编造引用**：找不到真实文献就标记为"待补充"，绝不编造
- 每条引用必须可核验（至少有 DOI 或专利号）
- 无法访问的引用必须明确标注，不得隐藏
- 引用位置必须精确到段落，不可模糊
- 完成后通过 SendMessage 将引用报告与引用文件包回传主理人
