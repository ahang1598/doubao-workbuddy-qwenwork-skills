# CNIPA 发明专利申报全流程 SOP（团队行动手册）

> 本手册由原独立技能 `patent-cnipa-filing` 合并入本专家团（v2.0.3），作为主理人调度全流程的作业基准。
> 覆盖：Step 1.0 体检 → 1.7 质量闸门（Gate B）→ 2.1 附图 → 2.2 格式终检 → 2.3 打包（Gate C）。

## 0. 触发前置（专利性质确认）

进入 SOP 第一步必须先确认**专利性质**：发明专利 / 实用新型 / 外观设计。
对**理论研究型发明专利（无实测数据）**：按「组合非显而易见协同 + 公开基数可推算 + 不编造」口径推进——专利法 26.3 款不要求自有实验数据，22 条看组合创造性。

## 1. 全流程 SOP 概览（对应团队成员分工）

```
Step 1.0 体检        → 材料成熟度、附图占位、主体信息、引用溯源（主理人）
Step 1.1 检索        → 对比专利/论文真实性核验（查新师 patent-prior-art-searcher / 文献师 patent-literature-search）
Step 1.2 引证据      → 删虚构、更正硬伤、重建 GB/T7714 引用清单（引证师 patent-citation-matcher）
Step 1.3 验真明      → 五步幻觉核验：作者/状态/DOI 等（幻觉哨兵 hallucination-guard）
Step 1.4 焦窗明      → Johari 四象限 + 溯源表 + 隐藏区排查（盲区审计师 johari-window-auditor）
★ 来源影响判定门禁（人工主导，见 §2）
Step 1.5 范方圆      → 权项优化：独权+从属，结构核验（权项师 patent-claim-optimizer）
Step 1.6 文述理      → 整合修订三件套：纠错+统一符号+理论标注（架构师 patent-disclosure-architect）
Step 1.7 法正清 Gate B → 质量闸门：7维评分+四级闸门（合规官 patent-compliance-checker）
Step 2.1 图致准      → 附图生成（绘图师 patent-figure-drawer，Graphviz 工具链见 §3）

Step 2.3 包综汇 Gate C → 跨文档一致性闸门 + 打包清单（打包师 patent-packager）
```

## 2. ★ 来源影响判定门禁（出正式说明书前必过）

顺序不可颠倒：
1. **人工溯源**所有来源（由用户核验真实性，AI 不代验）
2. **人工确认**信息准确
3. 对每条来源判「是否影响专利成果」+ **过程 + 原因** → 三结果：
   - **加固**：利好、引用有效（最佳）
   - **无价值**：没用 → **删除该来源**
   - **颠覆**：推翻成果（须说明原因）→ **重判可行性**
4. 确认专利**加固**后 → 出正式成果 → 形成**说明书**
5. **说明书 = 所有上报资料唯一基础**（权项/摘要/附图/请求书全部派生）

铁规：
- 溯源内容**只服务加固/颠覆**；不相干不要、AI 候选「无价值」一律删。
- 溯源交付物须含两项：**(a) 可打开链接**（AI 先实测可打开再交付）；**(b) 打开后核对清单**（名称/申请人/法律状态/申请日/权项是否含某特征）。
- 可用链接实测：专利检索用 `pss-system.cponline.cnipa.gov.cn`（官方、免费注册、权威法律状态）；国标 `openstd.samr.gov.cn`（免登录）；论文用 DOI 直链。
- 门禁未关闭前，说明书一律视为**草稿**；AI 仅作智囊团候选（标盲区 + 过程 + 原因），**不得代断**。

## 3. 附图工具链（图致准 · 实战坑）

> 出图由团队绘图师 `patent-figure-drawer` 执行，Graphviz 主力脚本见其 `tools/patent_figures_graphviz_v4.py`。

- 专利架构/流程图**主力工具 = Graphviz**（matplotlib 仅作 Graphviz 不擅长布局的兜底）。
- Graphviz 关键坑：**`splines="ortho"` 不渲染边标签**（"是/否/回环"等会丢）→ 必须用 `splines="spline"`。
- 依赖安装：默认 PyPI 国内易超时 → 用清华镜像 `python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple graphviz`；系统 `dot` 常见于 `C:/Program Files/Graphviz/bin/dot.exe`（加 PATH）。
- 样式铁规：白底黑线、`color/fontcolor="black"`、`penwidth="1.2"`、`fontname="SimHei"`、JPEG/TIFF、300 DPI、≤165×245mm、阿拉伯数字标号、图号留外部文字。
- **图数由说明书「附图说明」决定**，非工具——附图说明引几张就画几张。

### 3.1 说明书官方格式铁规（实战固化）

**章节与段号**
- 章节标题：**不加「一、二、三」编号** → 直接 `技术领域` / `背景技术` / `发明内容` / `附图说明` / `具体实施方式` / `参考文献`（6 个，顺序固定）。
- 标题行：说明书首行直接写**发明名称**（无「说明书」前缀）。
- 段号：`0001.` **4 位补零 + 句点 + 空格**，从「技术领域」首个内容段起**全局连续编号**；章节标题本身不加段号。
- ⚠️ 段号后**必须加空格**：正文含 `1.1`/`4.3.1` 等十进制子编号，无空格会撞成 `0002.1.1` 歧义。

**背景 ↔ 发明内容分工铁规（防循环重复）**
- 背景技术：**只写现有技术 + 其缺点**，禁止越界写本发明。
- 发明内容：写本发明（技术方案 / 有益效果）；对背景痛点用**引用式**表述，禁止原话重述。
- **技术问题段**：只概括要解决的技术问题，不剧透解决方案、不重列背景已写缺点。
- **有益效果段**：只陈述效果，禁止重述技术方案实现细节（避免三重重复）。
- 发明内容内**严禁出现「背景」子标题**。
- 与现有技术的创造性对比论证，留到答复审查意见阶段再写，不放背景技术。

### 3.2 主流专利表达结构（照已授权专利模板固化）

**发明内容主流三段式**
- 目的段：「鉴于上述现有技术的缺陷，本发明提供一种…，克服…，实现…」
- 技术方案：「实现本发明的技术方案如下：」→ **复述独立权利要求**（方法权项用 S1/S2…步骤，系统权项按模块列）→ 从属权项用「进一步地，…」逐条引出（说明书**不写**「其特征在于」，那是权项句式）。
- 有益效果：「本发明与现有技术相比，具有以下有益效果：」+ 编号优点（只讲效果）。

**具体实施方式主流框架**
- 引言：「为使本发明的目的、技术方案及优点更加清楚明白，以下结合附图及实施例，对本发明作进一步详细说明。应当理解，此处所描述的具体实施例仅用以解释本发明，并不用于限定本发明。」
- 展开：「如图X所示」结合附图逐模块/步骤写，细节（模块参数/算法/公式）全放这里。
- 收尾：「以上所述仅为本发明的优选实施例，并不用于限定本发明；凡在本发明的精神和原则之内所作的任何修改、等同替换和改进等，均应包含在本发明的保护范围之内。」

**表达层红线（过程性元词汇零容忍）**
- 禁入说明书的元词汇：溯源 / 背书 / 锁死 / 反面对比 / 加固 / 颠覆 / 智囊团 / 门禁 / datasheet / 【注 / （注 / 「---」分隔段 / 实验口吻（理论研究型须写「理论分析项，非实验测试」）。
- 「依模块 datasheet 选型，非限定」→「具体型号不作限定」；内联「（注：…）」一律改正文或删。
- 说明书内**不嵌「说明书摘要」块**（摘要独立成文）。

**页面与配套文档**
- 页面：A4(21.0×29.7cm) + 页边距(上2.5/下2.0/左2.5/右1.5cm) + 宋体小四(12pt)，四件套统一。
- 权项：阿拉伯数字顺序编号、独权顶格、从属权项「根据权利要求X所述」引用。
- 摘要：首行直接以**发明名称**起头，≤300 字（含标点），含摘要附图图号。
- 请求书：电子申请下进系统填，docx 仅作填写参考（主体信息留空标【待用户填写】）。

## 4. 数据声明措辞（实战坑）

- **数据声明非法律强制**。专利法无「必须声明未经实验验证」要求；充分公开（26.3）只要求技术人员能实现。
- **内联标注优于横幅**：具体参数后跟「（理论推测值/预期效果，非实验测试数据）」小标注自然且保护性强；**顶部独立「【数据声明】」横幅突兀、易诱发审查员额外质疑，应删**。
- 替代做法：把诚实立场化成一自然句放「具体实施方式」开头。
- ⚠️ **摘要 300 字硬限**：任何末句修改后**必须复算字数**。

## 5. 主体信息（请求书）

- 请求书/格式文档中主体信息（发明人身份证号、申请人名称/统一社会信用代码/地址/电话/邮箱、联系人）**全部留空标【待用户填写】**，AI 不碰敏感信息、不编造。
- 请求书要素：发明名称（与权项/摘要一致）、摘要附图指定、申请文件清单、费用减缴、实质审查请求。

## 6. 闸门检查清单

完整 11 项格式终检 + Gate C 跨文档一致性清单见 **packager 技能的 `references/patent_filing_checklist.md`**。核心闸门：

- **Gate A（真实性）**：每篇引用 URL/DOI 由用户逐项打开终核（AI 可先抽验，但不代用户确认）。
- **Gate B（质量·法正清）**：7 维评分 + 四级闸门（数据合规→非智力活动→技术方案三要素→创造性贡献）。
- **Gate C（打包·包综汇）**：四文档发明名称一致；权项独权覆盖「方法+系统」；摘要≤300；说明书嵌图数 = 附图说明引图号数；附图 TIFF 数 = 图数；摘要附图一致；请求书主体信息留空。

## 7. 红线

- 不编造数据 / 作者 / 专利状态。
- 门禁未关闭不出正式说明书（说明书 = 唯一基础）。
- 权项/摘要/附图/请求书全部由说明书派生，禁止各自为政。
- 重大改动前备份（如 `*_备份A前.docx`）。

## 8. 反向训练纪律（来自实战失误固化）

1. **自研校验脚本不可盲信（最高优先级）**：python-docx 核验脚本自身会有 bug（曾误报章节缺失、误取标题段当正文段）。纪律：① 校验告警与文档原文矛盾时，**先 inspect 原文再复查检测逻辑**；② 校验目标段落显式指定；③ 关键校验脚本沉淀进 references 复用复审，不每次临时现写。
2. **受限字段改动后立即重跑对应闸门**：凡改动受闸门约束的字段（字数/权项数/图数/名称一致性/引用连续性），改后**立即重跑该闸门项**，不依赖"之前通过过"。
3. **出图/出件前先确认真实工具链**：用户提及「之前靠某工具做的」，先定位真实工具与参数，确认后再产出，禁止臆测替代。
4. **声明类内容去横幅化、融入正文**：诚实立场以正文内联小标注 + 开头自然句表达，避免 banner 式防御语气。
5. **编辑前备份、编辑后立即全量复验**：实质编辑前先备份；编辑后跑完整 Gate C 确认无回归。
