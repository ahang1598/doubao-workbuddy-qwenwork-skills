# 审查意见答复器

## 一、适用场景

- 收到国知局《审查意见通知书》后需要答复
- 审查员指出新颖性/创造性/充分公开等问题需要申辩
- 需要对权利要求进行合规修改（不超出原公开范围）
- 答复期限内需要提交《意见陈述书》

## 二、审查意见类型与应对策略

### 2.1 常见审查意见类型

| 类型 | 审查员典型表述 | 应对方向 |
|------|---------------|----------|
| 新颖性不足 | "权利要求1相对于对比文件D1不具备新颖性" | 区别技术特征论述 |
| 创造性不足 | "权利要求1相对于D1+D2的结合不具备创造性" | 技术启示非显而易见性论述 |
| 公开不充分 | "说明书未充分公开如何实现XX" | 补充技术细节/参数 |
| 权利要求不支持 | "权利要求X概括过宽，得不到说明书支持" | 限定保护范围/分案 |
| 修改超范围 | "修改后的内容超出原说明书记载范围" | 回退修改/引用原文件依据 |

### 2.2 答复策略矩阵

#### 新颖性答辩

```
步骤1：逐特征对比
  将权利要求的技术特征与对比文件逐一对比
  ↓
步骤2：识别区别技术特征
  找出权利要求有但对比文件没有的特征
  ↓
步骤3：论述区别的技术效果
  说明区别特征带来什么意料不到的效果
  ↓
步骤4：结论
  权利要求相对于对比文件具备新颖性
```

#### 创造性答辩

```
步骤1：确定最接近现有技术
  审查员选择的对比文件D1
  ↓
步骤2：确定区别技术特征
  权利要求 vs D1的区别
  ↓
步骤3：确定实际解决的技术问题
  区别特征解决了什么技术问题
  ↓
步骤4：判断技术启示
  D2（或其他对比文件）是否给出了结合的技术启示
  ↓
步骤5：论述非显而易见性
  本领域技术人员不会有动机将D1+D2结合
  或结合后无法预期技术效果
  ↓
步骤6：辅助论据
  商业成功/意料不到的效果/解决了长期技术难题/克服技术偏见
```

## 三、权利要求修改规则

### 3.1 修改红线

**绝对不可**：
- 增加原说明书未记载的技术特征
- 扩大原权利要求的保护范围
- 改变发明主题

### 3.2 允许的修改方式

| 修改类型 | 说明 | 示例 |
|----------|------|------|
| 删除权利要求 | 删除某项权利要求 | 删除从属权利要求15 |
| 合并权利要求 | 将从属特征并入独立权利要求 | 将从属3的特征并入权利要求1 |
| 限定保护范围 | 增加技术特征限定 | 将"射频信道感知"限定为"WiFi CSI" |
| 修正明显错误 | 修正笔误/引用错误 | 修正附图标记错误 |

### 3.3 修改依据标注

每次修改必须标注依据：
```
修改后的权利要求1：
一种基于射频信道感知中枢的自适应多模态协同调度方法，其特征在于：
[原权利要求1的内容]
[并入原权利要求3的特征：本体位姿补偿]  ← 修改依据：原权利要求3
```

## 四、意见陈述书结构

```
## 意见陈述书

### 一、修改概述
本次修改共涉及X项权利要求，具体修改如下：
1. 权利要求1：并入原权利要求3的特征（本体位姿补偿）
2. 删除原权利要求3、15
3. 权利要求编号重新编排
（修改未超出原说明书和权利要求书记载的范围）

### 二、针对审查意见的答复

#### 2.1 关于新颖性
审查员认为权利要求1相对于D1（CNXXXXXX）不具备新颖性。
申请人不同意上述意见，理由如下：
[逐特征对比表]
[区别技术特征论述]
[技术效果论述]
结论：权利要求1相对于D1具备新颖性。

#### 2.2 关于创造性
审查员认为权利要求1相对于D1+D2的结合不具备创造性。
申请人不同意上述意见，理由如下：
[最接近现有技术分析]
[区别技术特征]
[实际解决的技术问题]
[技术启示分析：D2未给出结合启示]
[意料不到的技术效果]

### 三、修改后的权利要求书
[完整的修改后权利要求书]

### 四、结语
综上所述，修改后的权利要求书符合专利法第26条第4款的规定，
权利要求1-X具备新颖性、创造性和实用性，恳请审查员予以授权。
```

## 五、答复质量检查清单

```
□ 逐条回应了审查员的所有意见
□ 每条答复都有法律依据和技术逻辑
□ 修改未超出原说明书和权利要求书记载的范围
□ 修改后的权利要求仍得到说明书支持
□ 修改后的权利要求编号连续无跳跃
□ 意见陈述书语气客观理性，不情绪化
□ 答复期限在审查意见通知书发出日起4个月内
□ 附上了修改前后的对照表
```

## 七、本项目实战经验（预判）

### 7.1 可能收到的审查意见预判

基于本项目交底书的特点，预判审查员可能提出以下意见：

| 预判意见 | 应对准备 |
|----------|----------|
| "射频信道感知中枢"概括过宽 | 从属权利要求2已限定为WiFi CSI，可进一步限定 |
| 权利要求19的公式得不到支持 | 实施例7有完整的权重扫描实验数据支撑 |
| 失败实验数据自测不可信 | 交底书已标注"尚未经第三方认证"，可在答复中承诺提供原始日志 |
| 实施例6（Wi-Fi 8）是假设性的 | 交底书已明确标注"假设未来标准发布"，基于标准演进趋势的合理假设 |

### 7.2 答复弹药准备

| 弹药类型 | 内容 | 使用场景 |
|----------|------|----------|
| 区别技术特征表 | 3篇对比专利的区别点逐一列举 | 新颖性/创造性答辩 |
| 失败实验 | 2组失败实验数据 | 证明技术难度，支撑创造性 |
| 技术效果对比表 | 7项有益效果vs现有技术 | 创造性辅助论据 |
| 上位概念依据 | 说明书同时记载了WiFi CSI和未来射频感知 | 防止概括过宽质疑 |

## 十一、工具局限性与Workaround

| 局限性 | 影响 | Workaround | 实战经验 |
|--------|------|------------|----------|
| 答复策略基于预判而非实际审查意见 | 预判可能与实际审查意见不同 | 收到实际审查意见后重新评估策略 | 本项目预判4类审查意见 |
| 修改超范围判断需要专业经验 | AI可能无法准确判断修改是否超范围 | 每次修改必须标注原文依据；修改后人工逐条确认 | "不超出原公开范围"是红线 |
| 对比文件理解可能有偏差 | AI对技术文献的理解可能不准确 | 逐特征对比时引用对比文件原文段落 | 本项目3篇对比专利逐特征对比 |

**核心原则**：审查意见答复是高风险环节，所有法律判断和技术对比必须人工复核，AI仅作辅助起草。
