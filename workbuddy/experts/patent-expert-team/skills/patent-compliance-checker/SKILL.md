# 合规审查器

## 一、适用场景

- 交底书撰写完成后的合规性自检
- 正式申报前的缺项排查
- 格式规范验证（摘要字数、附图编号、术语一致性等）

## 二、CNIPA发明专利申报必需文件清单

### 2.1 必提交文件

| 文件 | 法律依据 | 要求 |
|------|----------|------|
| 发明专利请求书 | 专利法第26条 | 名称、发明人、申请人、地址 |
| 说明书 | 专利法第26条 | 清楚、完整说明，本领域技术人员能实现 |
| 权利要求书 | 专利法第26条 | 以说明书为依据，清楚、简要限定保护范围 |
| 说明书摘要 | 专利法第26条 | 简要说明技术要点，**≤300字** |
| 说明书附图 | 实施细则第18条 | 必要时提交 |

### 2.2 2026年新要求

- **发明人身份证号**：依据《专利法实施细则》第14条，发明人需填写身份证号
- **电子申请**：推荐通过国知局电子申请系统提交

## 三、说明书五大部分检查

依据《专利法实施细则》第18条，说明书必须包含：

| 序号 | 部分 | 检查要点 | 常见问题 |
|------|------|----------|----------|
| 1 | 技术领域 | 一句话说明所属领域 | 写太宽（"涉及电子领域"）或太窄 |
| 2 | 背景技术 | 现有技术+缺陷+对比文件 | 贬低现有技术、无对比文件 |
| 3 | 发明内容-技术问题 | 对照背景技术缺陷 | 与背景技术脱节 |
| 4 | 发明内容-技术方案 | 全部必要技术特征 | 笼统说"通过AI"无具体步骤 |
| 5 | 发明内容-有益效果 | 对照现有技术优点 | 无数据支撑、纯宣传语 |
| 6 | 附图说明 | 每幅图简略说明 | 附图编号与正文不一致 |
| 7 | 具体实施方式 | 优选方式+举例 | 太简略、无完整流程 |

**撰写顺序**：必须按上述顺序，每部分前写明标题。

## 四、权利要求书结构检查

### 4.1 独立权利要求

```
1. 一种XXX方法/系统/设备，其特征在于，包括以下步骤/包括：
[全部必要技术特征]
```

**检查点**：
- 包含解决技术问题的全部必要技术特征
- 不包含非必要技术特征（过窄保护范围）
- 用"其特征在于"引导技术特征

### 4.2 从属权利要求

```
N. 根据权利要求M所述的XXX，其特征在于，[进一步限定]
```

**检查点**：
- 引用编号正确（M < N）
- 引用关系无断裂
- 科技术语与说明书一致

### 4.3 多项独立权利要求

同一申请可包含多项独立权利要求（方法/系统/设备），需满足单一性要求。

## 五、格式规范检查清单

```
□ 案件名称≤25字
□ 案件名称无商业宣传用语
□ 说明书名称与请求书一致
□ 摘要≤300字
□ 摘要有指定附图
□ 权利要求用阿拉伯数字顺序编号
□ 权利要求无插图（可有化学式/数学式）
□ 附图标记放在技术特征后括号内
□ 说明书无"如权利要求…所述"引用语
□ 说明书无商业性宣传用语
□ 用词规范、语句清楚
□ 术语全文统一
□ XML电子申报格式正确（2026年新增，见第九章）
□ 发明人身份证号已填写
□ 伦理合规声明（涉及人体/基因等技术时）
```

## 六、自动化检查脚本模板

```python
# 合规检查脚本核心逻辑
import re

def check_compliance(filepath):
    with open(filepath, 'r', encoding='utf-8') as f:
        text = f.read()

    results = {}

    # 1. 摘要字数检查
    abstract_start = text.find('本发明公开')
    abstract_end = text.find('摘要附图')
    if abstract_start > 0 and abstract_end > 0:
        abstract = text[abstract_start:abstract_end].strip()
        cn_chars = len([c for c in abstract if '\u4e00' <= c <= '\u9fff'])
        results['摘要中文字数'] = f"{cn_chars} ({'OK' if cn_chars <= 300 else 'OVER LIMIT'})"

    # 2. 说明书五大部分（专利法实施细则第18条）
    parts = ['一、技术领域', '二、背景技术', '三、发明内容',
             '四、附图说明', '五、具体实施方式']
    for p in parts:
        results[p] = 'OK' if p in text else 'MISSING'

    # 3. 权利要求结构
    rq_section = text[text.find('权利要求书'):]
    rq_count = len(re.findall(r'\*\*\d+\.\*\*', rq_section))
    results['权利要求项数'] = rq_count
    deps = re.findall(r'根据权利要求(\d+)所述', rq_section)
    results['从属引用关系'] = deps

    # 4. 术语一致性
    results['信道状态信息出现次数'] = text.count('信道状态信息')
    results['射频信道出现次数'] = text.count('射频信道')

    # 5. 实施例
    examples = re.findall(r'实施例\d+', text)
    results['实施例'] = sorted(set(examples))

    return results
```

## 十、费用减缴备案检查（2026年实战经验融入）

### 10.1 费减资格判断

| 备案人类型 | 费减条件 | 减缴比例 |
|-----------|---------|---------|
| 个人 | 上年度年收入≤6万元 | 85% |
| 企业（小型微利） | 上年度应纳税所得额≤100万元 | 85% |
| 企业（小型微利） | 上年度应纳税所得额≤300万元 | 70% |

**小型微利企业认定标准（2026年现行）**：
- 年度应纳税所得额≤300万元
- 从业人数≤300人
- 资产总额≤5000万元

### 10.2 费减备案材料清单（企业）

| 序号 | 必传文件 | 说明 |
|------|---------|------|
| 1 | 企业所得税年度纳税申报表封面（A类2017版） | 盖公章+统一社会信用代码 |
| 2 | 企业所得税年度纳税申报主表 A100000 | 核心数据：应纳税所得额 |
| 3 | 企业所得税年度纳税申报基础信息表 A000000 | 小型微利企业认定证据 |

**不传文件**（避免暴露财务细节）：
- A105050职工薪酬、A105060广告费、A105080资产折旧、A106000弥补亏损等子表

### 10.3 费减备案与专利申请的先后顺序（核心红线）

```
正确顺序：
1. 先完成费减备案 → 拿到费减备案号
2. 再提交专利申请 → 在请求书中勾选"请求费用减缴且已完成费减资格备案"
3. 填入费减备案号

错误顺序（会导致驳回）：
- 专利申请先勾选"已完成费减备案"但实际未备案 → 承诺作伪，被驳回
```

### 10.4 费减备案表单填写要点

| 字段 | 填写要求 | 常见错误 |
|------|---------|---------|
| 上年度应纳税所得额 | 亏损企业填 `0`（系统不支持负数） | 填负数导致提交失败 |
| 详细地址 | 必须含省/市/区/街道/门牌号 | 只填到区级被退回 |
| 备案人名称 | 与营业执照完全一致 | 简写或漏字 |

## 十一、实质审查请求书检查

### 11.1 检查清单

| 检查项 | 要求 | 常见问题 |
|--------|------|---------|
| 实质审查请求 | 发明专利申请需在自申请日（优先权日）起3年内提出 | 逾期未请求视为撤回 |
| PCT备注字段 | 非PCT申请应留空或删除 | 系统模板可能预填PCT备注，需人工删除 |
| 延迟审查请求 | 可选，国内发明专利一般不勾选 | 误勾选会延迟审查 |
| 费减备案号 | 与费减备案通过号一致 | 填错或漏填 |

### 11.2 系统模板陷阱

> **实战经验**：国知局系统生成的实质审查请求书模板可能包含"PCT国际申请"备注字段，非PCT申请需确认该字段是否影响审查。2026年实测：该字段为系统固定模板，部分版本无法删除，但不影响非PCT申请的实质审查流程。

## 十四、工具局限性与Workaround

| 局限性 | 影响 | Workaround | 实战经验 |
|--------|------|------------|----------|
| 合规检查依赖AI对法规的理解 | AI可能对专利法条文理解有偏差 | 法律条款引用需链接到官方法规原文 | 本项目引用专利法实施细则第14/18条均有URL |

| 2026年新要求可能更新 | CNIPA规则可能随时变化 | 每次使用前检查国知局官网最新通知 | 局令第84号是2026年新要求 |
| XML电子申报格式检查缺失 | 当前skill未覆盖XML格式 | 需人工确认电子申报系统格式要求 | 待补充（B4修复项） |
