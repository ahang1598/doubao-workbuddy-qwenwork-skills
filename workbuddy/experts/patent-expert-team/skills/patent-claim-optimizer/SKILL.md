# 权利要求优化器

## 一、适用场景

- 交底书撰写中设计权利要求层级
- 分析现有权利要求的保护范围是否合理
- 优化权利要求布局策略（独宽从窄/层层递进）
- 识别权利要求可能被规避的风险点

## 二、权利要求布局策略

### 2.1 三维布局模型

```
维度1：保护对象
├── 方法权利要求（做什么）
├── 系统权利要求（包括什么）
└── 设备权利要求（硬件是什么）

维度2：保护层级
├── 独立权利要求（最宽保护范围）
├── 从属权利要求（逐步限定）
└── 从属权利要求（具体实施例）

维度3：保护深度
├── 上位概念（射频信道感知中枢）
├── 中位概念（WiFi CSI采集单元）
└── 下位概念（OFDM子载波振幅与相位矩阵）
```

### 2.2 独立权利要求设计原则

| 原则 | 说明 | 违反后果 |
|------|------|----------|
| 包含全部必要技术特征 | 解决技术问题必不可少的特征 | 缺少必要技术特征，保护范围过窄 |
| 不包含非必要技术特征 | 优选实施例的特征不应放入独立权项 | 保护范围过窄，容易被规避 |
| 用上位概念 | 用"射频信道感知"而非"WiFi CSI" | 保护范围过窄，竞争对手可绕开 |
| 清楚简要 | 不含模糊用语 | 保护范围不确定 |

### 2.3 从属权利要求设计策略

```
独立权利要求1（方法，最宽）
├── 从属2：限定感知模块具体实现（WiFi CSI）
├── 从属3：限定异常事件类型（微动/射频/静止异物）
├── 从属4：限定交叉验证策略（IMU补偿）
├── 从属5：限定能力等级（L1/L2/L3）
├── 从属6：限定硬件触发同步
├── 从属7：限定分级唤醒采样率
├── 从属8：限定非视觉隐私守护
├── 从属9：限定趋势预警
└── 从属10：限定加权投票公式

独立权利要求11（系统）
```

### 2.4 上位概念化策略

| 层级 | 本项目案例 | 保护范围 |
|------|-----------|----------|
| 上位 | 射频信道感知中枢 | 最宽（覆盖未来WiFi/5G/6G等所有射频感知） |
| 中位 | WiFi信道状态信息采集 | 中等（覆盖所有WiFi协议） |
| 下位 | OFDM子载波振幅与相位矩阵 | 最窄（仅覆盖OFDM制式） |

**原则**：独立权利要求用上位概念，说明书同时记载下位实现，确保支持。

## 三、权利要求质量检查

### 3.1 结构检查

```
□ 独立权利要求包含"其特征在于"引导语
□ 从属权利要求用"根据权利要求N所述…，其特征在于"
□ 从属引用编号正确（M < N）
□ 引用关系无断裂
□ 科技术语与说明书一致
□ 权利要求无插图（可有化学式/数学式）
□ 附图标记放在技术特征后括号内
```

### 3.2 保护范围检查

```
□ 独立权利要求无非必要技术特征
□ 独立权利要求用上位概念
□ 从属权利要求逐步缩小保护范围
□ 每项权利要求都能在说明书中找到支持
□ 权利要求之间无冲突
```

### 3.3 规避风险检查

```
□ 竞争对手能否通过替换模块绕开独立权利要求？
□ 竞争对手能否通过删除步骤绕开方法权利要求？
□ 从属权利要求是否覆盖了主要规避路径？
□ 是否有"防规避"权利要求（如上位概念+具体实施例双保险）
```

## 五、本项目实战经验

### 5.1 关键数据

| 指标 | 数值 |
|------|------|
| 权利要求总项数 | 11项 |
| 独立权利要求 | 2项（方法/系统） |
| 从属权利要求 | 9项 |
| 上位概念使用 | "射频信道感知中枢" |
| 保护对象维度 | 方法+系统 |

### 5.2 经验教训

1. **多维布局**：同时覆盖方法与系统两个维度，防止竞争对手只规避其中一个
2. **上位概念化**：从"WiFi CSI"上位到"射频信道感知中枢"，保护范围覆盖未来6G等射频感知技术
3. **从属权利要求覆盖规避路径**：每个辅助感知模块单独成项，防止竞争对手通过替换模块规避
4. **能力等级权利要求**：L1/L2/L3分级设计，覆盖未来技术演进
5. **公式权利要求**：加权投票公式写入权利要求，保护算法核心
6. **非视觉隐私守护写入权利要求**：将"全程不采集光学图像"作为技术特征，形成独特保护点

## 九、工具局限性与Workaround

| 局限性 | 影响 | Workaround | 实战经验 |
|--------|------|------------|----------|
| 上位概念化判断依赖专业经验 | AI可能过度上位或上位不足 | 每个上位概念必须在说明书中找到下位实现支撑 | "射频信道感知中枢"有WiFi CSI+6G感知双支撑 |
| 规避路径预判有限 | 竞争对手的规避方式难以穷举 | 重点覆盖已知竞品的技术路线；发明人补充行业洞察 | 本项目发明人提供3条竞品信息 |
| 权利要求编号易出错 | 从属权利要求引用关系复杂 | 逐项检查引用编号；修改后重新编号全量验证 | 本项目11项权利要求逐项验证 |

**核心原则**：权利要求布局策略必须经发明人确认，AI不可独立决定保护范围。
