# 工作流程详述 | 劳动争议仲裁申请书

> 版本: 3.3.0 | 风险等级: L2

## 总览

> 本节遵循 compiler/ssot.md §17（SSOT）：§17.15 法条检索强制契约

法条检索调用链：
- Step 1（首选）：fadada-legal-info-search —— 专业法律信息检索
- Step 2（备选）：fadada-web-search —— 通用网络检索
- Step 3（降级）：SOFT_DEGRADED + legal_retrieval_failed 标注
- 法条来源标注格式：`[来源:检索 | 检索工具:XXX | 检索时间:XXX]`
- 强制检索触发条件：(1)法条引用时须确认现行有效；(2)用户争议法条适用性时；(3)知识截止日后新发布/修订的法律
- 降级路径：检索源不可用时，标注"法条截至2026-03-01未经实时核实，提交前须人工确认"

```
标准管线：P0 诉前评估[L2] —hard gate→ P1 输入验证[L1] → P2 事实建构[L2] → P3 请求论证[L3] → P4 文书生成[L2] → P5a Phase内嵌检查 → P5b 终检[L2]
FAST_TRACK：P0 诉前评估[L2] —hard gate→ P1 输入验证[L1] → P2+P3合并 → P4 文书生成[L2] → P5a 关键阻断 → P5b 终检[L2]
```

> v3.1.0 管线变更：(1) P0→P1 增加 hard gate（四维全COMPLETE才放行）；(2) P5 拆分为 P5a（Phase内嵌检查）+ P5b（终检仅格式+跨Phase一致性）；(3) 新增 FAST_TRACK 快速通道（单请求+证据充分+无时效争议时自动判定）。

## Phase 0: 诉前评估 [L2]

**输入**：原始用户输入（初步信息）
**输出**：pre_assessment（诉前评估结果 + 策略建议 + 复杂度判定 + FAST_TRACK资格）

> 顶级团队"不评估不动笔"。P0在P1之前执行，决定是否继续及如何继续。
> **完整评估指南详见 [references/p0-assessment-guide.md](p0-assessment-guide.md)**
> **P0→P1 hard gate 详见 [references/p0-assessment-guide.md](p0-assessment-guide.md) §6**

四维评估概要（含1个必做步骤）：
1. **管辖策略**：履行地vs所在地，裁判口径比较，**确定管辖地后必查仲裁委全称**（见p0-assessment-guide §1）
2. **时效评估**：1年+拖欠工资例外+二倍工资逐月+中断/中止事由（见p0-assessment-guide §2）
3. **请求权基础**：法律依据/构成要件/抗辩预判/金额可证（见p0-assessment-guide §3）
4. **举证能力**：申请人举证/用人单位举证倒置/证据强弱点（见p0-assessment-guide §4）
5. **请求可行性预判**：对每项请求分级（high/medium/low），给出取舍建议（见p0-assessment-guide §5）

### 0.1 P0→P1 Hard Gate

> v3.1.0 新增：P0→P1硬门控，防止AI跳过P0直接进入P1。

**门控规则**：P1启动条件 = P0四维评估全部 COMPLETE。任一维度 INCOMPLETE 则阻断，须补充后重新评估。

**时效紧急例外**（v3.1.1 新增）：当P0检测到任一请求时效critical（距届满≤7日），门控降级为"时效+管辖完成即放行"，其余维度在P2/P3中补充评估，并在O2中标注"⚠️ 诉前评估未完成项"清单。仲裁时效为硬期限，不可因评估不完整而延误提交窗口。

详见 [p0-assessment-guide.md](p0-assessment-guide.md) §6.1 门控条件 + §6.2 P0最小必须输出 + §6.4 FAST_TRACK门控。

### 0.2 案件复杂度分级

> v3.1.0 新增：P0完成后自动判定案件复杂度，决定是否适用FAST_TRACK。

| 级别 | 判定条件 | 执行模式 |
|------|---------|---------|
| **simple** | 单请求 + 证据充分(≥high) + 无时效争议 + 请求类型为常见给付型 | FAST_TRACK 快速通道 |
| **moderate** | 2-3项请求 / 证据部分充分 / 有时效争议但不严重 | 标准管线 |
| **complex** | ≥4项请求 / 多重争议类型 / 证据薄弱 / 时效严重 / 含确认类请求 | 标准管线 + P0全量评估 |

**FAST_TRACK 触发条件**（全部满足）：
- 仲裁请求 ≤1 项
- 请求类型为拖欠工资/经济补偿金/赔偿金等常见给付型
- 证据支撑 ≥ moderate
- 无时效争议（所有请求 status=safe）
- 无管辖争议

**FAST_TRACK 简化流程**：
- P0：时效+管辖快速检查 + 请求权基础简化评估（跳过完整四维，但须输出fast_track_eligible=true作为门控等价信号）
- P2+P3合并：事实建构与请求论证合为一个Phase（跳过蓝图工序，直接生成叙事）
- P4：生成O1 + O2简化版（仅保留"对方抗辩预判"和"时效风险分析"两大核心板块，其余板块跳过）
- P3.1：交叉校验改为内嵌自检，不输出校验清单（简化token消耗）
- P5a：仅关键阻断检查（金额精确/法条编号/O1无内部标注）
- P5b：仅O1格式终检

> v3.1.1 变更：FAST_TRACK保留O2简化版（抗辩预判+时效风险），确保律师不盲飞。预估提速从60-80%调整为40-50%。

## Phase 1: 输入验证 [L1]

**输入**：原始用户输入（6种形态之一）+ pre_assessment
**输出**：validated_input

### 1.1 字段完整性检查

- 必需字段：applicant / respondent / arbitration_claims / facts_and_reasons / evidence_list
- 可选字段：labor_relation_start / labor_relation_end / monthly_salary / work_years / jurisdiction_preference / limitation_defense / burden_of_proof_assessment

### 1.2 交互补全（≤3轮）

> 完整补全表详见 [references/input-spec.md](input-spec.md) §4

核心补全项：申请人身份信息(P0) → 申请人送达地址(P0) → 被申请人信息(P0，名称全称/住所地/联系方式，法定代表人) → 被申请人实际经营地址(P1) → 仲裁请求(P0) → 事实与理由(P1) → 证据材料(P1) → 工资标准(P2) → 管辖选择(P2)

### 1.3 输入验证规则

- 仲裁请求金额须精确到元（阻断级）
- 被申请人须为用人单位（阻断级）
- 须属劳动争议范围（阻断级）
- 仲裁时效检查（警告级）
- 送达地址是否已提供（警告级）

## Phase 2: 事实建构 [L2]

**输入**：validated_input
**输出**：fact_blueprint（段落蓝图）→ fact_timeline（事实时间线）

### 2.0 一段一事蓝图（v3.1.0 新增）

> 生成前先规划，蓝图审查通过后再逐段撰写，避免段落交叉混述导致事后回退。

**P2.1 蓝图规划**：先列出 N 个段落计划，每段仅含结构化要点，不含完整文本：

```
段1（劳动关系基础）：
  → 事实要点：入职时间/岗位/合同签订/工资标准
  → 法律评价：无（纯事实段）
  → 结论句：建立劳动关系基础框架

段2（请求1映射，如拖欠工资）：
  → 对应请求：仲裁请求一
  → 事实要点：拖欠起止月/金额/催要交涉
  → 法条依据：劳动法第50条
  → 结论句：被申请人应当支付拖欠工资XXX元

段3（请求2映射，如违法解除）：
  → 对应请求：仲裁请求二
  → 事实要点：解除经过/解除理由/交涉过程
  → 法条依据：劳动合同法第48条/第87条
  → 结论句：被申请人应当支付赔偿金XXX元
  ...

段N+1（结论收束）：
  → 立场宣示：对被申请人行为的定性总结
  → 法条归总：呼应前N段引用的法条
  → 标准收束语："为维护申请人的合法权益，特向贵委提出仲裁申请，恳请依法予以支持。"
```

**蓝图审查规则**：
- 每段结论句必须指向**唯一请求项**（或"劳动关系基础"/"结论收束"）
- 段2~段N 中不得有两段指向同一请求项——**同一请求项多角度论证例外**：若同一请求需从多个角度论证（如违法解除须论证程序违法+实体违法；拖欠工资须论证合同约定+法定标准），允许拆为多段，但须在蓝图阶段标注"请求X-角度A"和"请求X-角度B"，每段仍须有独立结论句
- 涉及跨争议背景事实仅在服务于当前请求项的必要范围内简述
- 段落之间须有因果递进逻辑衔接标注（因果→/递进↑/转折↗）

**蓝图审查不通过** → 调整段落划分，重新审查，通过后才进入2.1。

### 2.1 时间线梳理

- 提取关键时间节点：入职日/合同签订日/工资变动日/争议发生日/协商日/解除日
- 构建chronological事实链条
- 标注缺失时间节点

### 2.2 核心事实+法条支撑结构

> v3.0.0 从"四步法独立段落"重构，v3.0.1 调整为"1+N+1"结构，v3.2.0 进一步简化为"核心事实+法条支撑"——写明能支持仲裁请求的基本事实就够了，不过度展开法律论证。

事实与理由按核心事实+法条支撑结构组织，无独立分标题，同一叙事流依次覆盖：

| 段落 | 内容 | 技法 | 约占篇幅 |
|------|------|------|---------|
| 1段：劳动关系基础 | 入职具体日期、岗位、合同签订、工资标准 | 简明扼要，建立基本事实框架 | 15% |
| N段：分请求核心事实 | 每个请求1段核心事实+法条引用，一段一事。关键要素：时间、金额、行为、交涉过程 | **核心事实+法条支撑** | 70% |
| 1段：结论收束 | 以"申请人认为"起头，对被申请人行为做定性总结+法条归总+标准收束语 | 立场宣示+请求呼应，不归纳争议焦点 | 15% |

**禁止项**：
- ❌ "关于拖欠工资""关于违法解除"等独立小标题段落
- ❌ 法条论证独立成段（"大前提""小前提""结论"显式标签）
- ❌ O1正文出现法条性质标注（授权性/命令性等）
- ❌ O1正文出现内部方法论标签（[策略][评估][风险]等）

### 2.3 策略性叙事技法

**选择性叙事**：
- 有利事实：详细展开，含时间、地点、人物、经过
- 不利事实：简略提及或不提及（法律不要求自认不利事实）
- 中性事实：适度交代，保持叙事完整

**因果链构建**：
```
用人单位行为 → 法律后果 → 申请人权利受损 → 仲裁请求正当
```
例："被申请人自2024年11月起未支付劳动报酬（行为）→ 构成拖欠劳动报酬（法律后果）→ 申请人合法权益受损（权利受损）→ 应支付拖欠工资27000元（请求正当）"

**关键节点锚定**：
- 入职日期 → 劳动关系起点
- 未签合同满1月 → 二倍工资起算点
- 拖欠起始月 → 欠薪期间起算点
- 解除日期 → 时效起算点/N计算终点
- 仲裁申请日 → 时效截止校验

**避免不利自认**：
- ❌ "我虽然迟到但..."（自认迟到）
- ❌ "公司说我绩效不达标..."（自认绩效问题）
- ✅ "被申请人单方主张绩效不达标，但未提供经考核的客观证据"
- ✅ "被申请人以'业务调整'为由解除，但未证明符合法定解除条件"

### 2.4 法律事实映射

| 事实类型 | 法律概念 | 关联法条 |
|---------|---------|---------|
| 入职未签合同 | 事实劳动关系 | 劳动合同法第7条、第10条 |
| 欠发工资 | 拖欠劳动报酬 | 劳动法第50条 |
| 单方解除 | 劳动合同解除 | 劳动合同法第39-48条 |
| 未缴社保 | 社会保险争议 | 社会保险法第58条 |
| 工伤未认定 | 工伤保险待遇 | 工伤保险条例第14-16条 |
| 未安排年休假 | 年休假工资 | 职工带薪年休假条例第5条 |
| 加班未付加班费 | 加班工资 | 劳动法第44条 |

### 2.5 缺失证据提示

- 对比仲裁请求与证据清单，识别证据缺口
- 每项请求至少需要1项证据支撑
- 提示可补证方向
- 标注举证责任倒置领域（用人单位须举证的事项）

## Phase 3: 请求论证 [L3]

**输入**：fact_timeline
**输出**：claims_with_basis

### 3.1 金额交叉校验（v3.1.0 新增）

> v3.1.0 新增：P3生成金额请求后，将公式参数与P1 validated_input 逐一比对，防止"输入7,000但公式用12,000"的矛盾。

**校验规则**：

| 校验项 | 方法 | 异常处理 |
|--------|------|---------|
| 月工资基数一致 | 公式中`X元/月`须与P1中`monthly_salary`一致 | 不一致→标红警告，须确认来源（如有涨薪须注明） |

**基数构成校验**（v3.1.1 新增）：当monthly_salary>5000元时，提示用户确认该金额是否已包含季度奖/年终奖分摊/加班费分摊，并标注[需核实当地口径]。经济补偿金基数争议口径：
- 季度奖/年终奖是否分摊计入月基数：各地做法不一
- 加班费是否计入：北京计入，上海部分计入，深圳不计入
- 交通/通讯/餐补是否计入：各地口径差异
| 工作年限一致 | 公式中`Y年`须与P1中`work_years`一致 | 不一致→标红警告，须确认计算依据 |
| 合计金额校验 | 各项金额之和 = 合计行金额 | 不一致→自动修正合计行 |
| N/2N互斥检测 | 检查是否同时存在经济补偿金(N)和赔偿金(2N)作为独立请求 | 同时存在→阻断，须改为2N主位+N备位 |
| 计算公式参数溯源 | 每项公式须标注参数来源（如"月工资12,000元[来源:P1输入]"） | 无来源标注→警告 |

**交叉校验清单**（P3.1 执行后输出）：
```
□ 月工资基数：公式值 vs P1输入 → 一致/不一致(说明)
□ 工作年限：公式值 vs P1输入 → 一致/不一致(说明)
□ 合计金额：各项之和 vs 合计行 → 一致/不一致(已修正)
□ N/2N互斥：无同时独立请求 / 检测到互斥(已修正)
□ 参数溯源：全部已标注 / 部分未标注(补充)
```

**结构化输出格式**（v3.1.1 新增，可选）：AI自检时可使用以下JSON格式替代□打勾表，P5可直接引用cross_check字段：
```json
{
  "cross_check": {
    "salary_base": {"formula_value": "12000", "p1_value": "12000", "status": "pass"},
    "work_years": {"formula_value": "3.5", "p1_value": "3.5", "status": "pass"},
    "total_amount": {"sum": "165000", "total_line": "165000", "status": "pass"},
    "n_2n_mutex": {"detected": false, "status": "pass"},
    "param_trace": {"all_traced": true, "status": "pass"}
  }
}
```

> FAST_TRACK模式下，交叉校验简化为内嵌自检，不输出清单。

### 3.2 请求排列策略

| 排列规则 | 说明 | 示例 |
|---------|------|------|
| 确认类优先 | 先确认法律关系，再主张给付 | 先"确认劳动关系"，再"支付工资" |
| 主位→备位 | 主要请求在前，备位请求在后 | 主位"2N赔偿金"，备位"N经济补偿金" |
| 金额大→小 | 金额大的请求排在前面 | 赔偿金→拖欠工资→二倍工资差额 |
| 时间先→后 | 同类请求按时间顺序 | 2024年欠薪→2025年欠薪 |

**主位/备位请求机制**：

```
主位请求：违法解除赔偿金2N（劳动合同法第48条+第87条）
  └ 备位请求：如被认定为合法解除但未提前30日通知，支付代通知金+1（劳动合同法第40条）
  └ 备位请求：如认定为协商解除，支付经济补偿金N（劳动合同法第46条）
```

通过 `arbitration_claims[].priority` 字段标记：
- `primary`：主位请求
- `secondary`：备位请求（仅在主位不被支持时适用）

### 3.3 金额精确计算与公式嵌入

**计算公式嵌入规则**：每项金钱请求必须嵌入计算公式，格式为：

```
请求金额XXX,XXX元（参数A × 参数B × 系数C）
```

> **计算公式速查详见 [references/claim-templates.md](claim-templates.md)**，覆盖经济补偿金(N)/赔偿金(2N)/二倍工资差额/拖欠工资/加班费(三档)/年休假工资/代通知金/加付赔偿金等全部10类。

> **计算基数注意**：经济补偿金/赔偿金基数为**应发工资**（税前），包括计时/计件工资、奖金、津贴、补贴等货币性收入。加班费是否计入基数各地口径不一，须核实当地规定。

### 3.4 法条依据匹配

> v3.0.0 从"三段论显式标注"改为"叙事融合论证"，v3.2.0 进一步简化为"基本事实+法条依据"——不再展开"事实→法律评价→法律后果"三步论述，只陈述核心事实+引用法条。法条性质标注仅在O2和内部方法论中使用。

**匹配模板**：

```
[核心事实]……依照《XX法》第X条之规定，被申请人应当支付[金额]（[计算公式]）。
```

**O1正文示例**：

> 被申请人于2024年12月31日以"业务调整"为由口头通知解除劳动合同，未出具书面解除通知，未支付经济补偿。依照《中华人民共和国劳动合同法》第四十八条、第八十七条之规定，被申请人应当向申请人支付赔偿金84,000元（12,000元/月×3.5年×2倍）。

文书末尾法条引用：
> 1. 《中华人民共和国劳动合同法》第三十九条：劳动者有下列情形之一的，用人单位可以解除劳动合同：（一）在试用期间被证明不符合录用条件的；（二）严重违反用人单位的规章制度的；（三）严重失职，营私舞弊，给用人单位造成重大损害的；（四）劳动者同时与其他用人单位建立劳动关系，对完成本单位的工作任务造成严重影响，或者经用人单位提出，拒不改正的；（五）因本法第二十六条第一款第一项规定的情形致使劳动合同无效的；（六）被依法追究刑事责任的。
> 2. 《中华人民共和国劳动合同法》第四十条：有下列情形之一的，用人单位提前三十日以书面形式通知劳动者本人或者额外支付劳动者一个月工资后，可以解除劳动合同：（一）劳动者患病或者非因工负伤，在规定的医疗期满后不能从事原工作，也不能从事由用人单位另行安排的工作的；（二）劳动者不能胜任工作，经过培训或者调整工作岗位，仍不能胜任工作的；（三）劳动合同订立时所依据的客观情况发生重大变化，致使劳动合同无法履行，经用人单位与劳动者协商，未能就变更劳动合同内容达成协议的。
> 3. 《中华人民共和国劳动合同法》第四十八条：用人单位违反本法规定解除或者终止劳动合同，劳动者要求继续履行劳动合同的，用人单位应当继续履行；劳动者不要求继续履行劳动合同或者劳动合同已经不能继续履行的，用人单位应当依照本法第八十七条规定支付赔偿金。
> 4. 《中华人民共和国劳动合同法》第八十七条：用人单位违反本法规定解除或者终止劳动合同的，应当依照本法第四十七条规定的经济补偿标准的二倍向劳动者支付赔偿金。

**O2使用指引中补充性质标注**：
> 第四十八条（授权性）：劳动者可选择继续履行或主张赔偿金
> 第八十七条（命令性）：用人单位违法解除须支付二倍经济补偿金

### 3.5 时效审查

- 一般时效：1年（调解仲裁法第27条）
- 拖欠工资例外：劳动关系存续期间不受1年限制
- 二倍工资：逐月起算1年时效（部分地区从离职起算，须核实当地规定）
- 中断事由：主张权利/对方同意/申请仲裁
- 时效审查结果须在P5质量检查中校验

**O1时效论证写法模板**（嵌入事实与理由段）：

```
申请人于[争议发生日]知悉权益受损，于[申请日]申请仲裁，未超过一年仲裁时效。就拖欠工资部分，依调解仲裁法第二十七条第四款，劳动关系存续期间不受一年时效限制。
```

文书末尾法条引用：
> 1. 《中华人民共和国劳动争议调解仲裁法》第二十七条：劳动争议申请仲裁的时效期间为一年。仲裁时效期间从当事人知道或者应当知道其权利被侵害之日起计算。前款规定的仲裁时效，因当事人一方向对方当事人主张权利，或者向有关部门请求权利救济，或者对方当事人同意履行义务而中断。从中断时起，仲裁时效期间重新计算。因不可抗力或者有其他正当理由，当事人不能在本条第一款规定的仲裁时效期间申请仲裁的，仲裁时效中止。从中止时效的原因消除之日起，仲裁时效期间继续计算。劳动关系存续期间因拖欠劳动报酬发生争议的，劳动者申请仲裁不受本条第一款规定的仲裁时效期间的限制；但是，劳动关系终止的，应当自劳动关系终止之日起一年内提出。

**O2时效风险分析**（独立段）：
- 逐项时效状态 + 风险标记（⚠️/✅）
- 中断事由详情
- 拖欠工资例外说明
- 二倍工资逐月审查结果

### 3.6 终局裁决策略

当符合以下条件时可考虑终局裁决策略（调解仲裁法第47条，授权性）：

| 策略 | 操作 | 效果 |
|------|------|------|
| 控制总额 | 将请求金额控制在最低工资×12个月以内 | 用人单位不可起诉 |
| 拆分请求 | 将部分请求另行主张 | 核心请求获终局保护 |
| 自然适用 | 金额本就在终局范围内 | 自动适用终局裁决 |

> **注意**：终局裁决下劳动者仍可在15日内向法院起诉（调解仲裁法第48条），仅限制用人单位的起诉权。

### 5.4 O1 DOCX渲染

按 [format-spec.md](format-spec.md) §9 DOCX排版规范渲染为DOCX格式：
- 页面设置：A4 / 3.14cm上下边距 / 2.98cm左右边距
- 字体字号：方正小标宋_GBK 22pt(标题) + 方正黑体简体 16pt(段落标题) + 宋体+TNR 16pt(正文)
- 行间距：30pt最小值
- 页眉：空白（无内容、无线条）
- 页脚：居中"第 X 页 / 共 N 页"
- 签名区：右对齐+中文大写日期
- 文书末尾法条引用：按出现先后顺序列出条编号+条文全文（见format-spec.md §9.6）
- 强调方式：加粗（4项必须加粗+4项禁止加粗，详见format-spec.md §9.7）
- 孤行控制：开启
- **无证据清单段**

### 5.5 O2 HTML渲染

按 output-spec.md §9 I-Practical 风格渲染为HTML格式：
- 页眉：技能名+案件类型+角色+日期
- 正文：微软雅黑11pt，line-height:1.6
- 证据清单：含三分类标签卡片+持有人标注+映射矩阵表格
- 时效分析：含风险标注（Emoji+文字）
- 补证方向：行动项卡片
- 提交检查清单：☐待办任务清单
- 免责声明：仅供参考，不构成法律意见
- 配色：青灰主色(#005F73)+暖橙强调(#EE9B00)

### 5.6 输出交付

- 通过所有检查 → 输出双产物：O1(DOCX) + O2(HTML)
- 阻断级检查失败 → 修复后重新生成
- 警告级检查失败 → 标注警告但可输出

### 5.7 回退与增量修复

- 阻断级检查失败 → 定位到对应Phase，仅重做受影响范围（保留其他Phase产物）
- 同一Phase内多次阻断 → 累积修复后一次性重做
- 超过3次回退 → 降级为C+D+G模式，输出问题清单
