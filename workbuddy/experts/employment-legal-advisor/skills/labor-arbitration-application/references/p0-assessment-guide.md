# 诉前评估指南 | 劳动争议仲裁申请书

> 版本: 3.3.0 | 仅在P0诉前评估阶段加载

## 1. 管辖策略评估

| 评估项 | 内容 | 决策依据 |
|--------|------|---------|
| 履行地管辖 | 劳动合同实际履行地 | 调解仲裁法第21条（程序性） |
| 所在地管辖 | 用人单位注册地 | 调解仲裁法第21条（程序性） |
| 两地比较 | 裁判口径差异 | 同类案件两地裁判倾向 |
| 选择建议 | 推荐管辖地 | 综合裁判口径+举证便利+交通成本 |

**管辖决策矩阵**：

| 因素 | 偏好履行地 | 偏好所在地 |
|------|-----------|-----------|
| 裁判口径 | 履行地更有利 | 所在地更有利 |
| 举证便利 | 证据在履行地 | 证据在所在地 |
| 交通成本 | 申请人居住在履行地 | 申请人居住在所在地 |
| 执行便利 | 财产在履行地 | 财产在所在地 |

**仲裁委全称查证**（选管辖地后必做）：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 确定管辖城市/区县 | 根据推荐管辖地定位到区县级行政区域 |
| 2 | 查询仲裁委全称 | 在人社部官网或当地人社局官网查询"劳动人事争议仲裁委员会"全称，不可自行编造或缩写 |
| 3 | 确认办公地址 | 核实仲裁委实际办公地址和立案窗口地址（二者可能不同） |
| 4 | 提示 | 输出时标注"仲裁委全称须核实，本技能生成的名称仅供参考" |

> ⚠️ 实务坑：仲裁委名称"劳动人事争议仲裁委员会" vs "劳动仲裁委员会"——多数地级市使用前者，个别历史遗留使用后者。写错=被驳回。

## 2. 时效评估

| 评估项 | 规则 | 例外 |
|--------|------|------|
| 一般时效 | 1年（知道或应当知道权利被侵害之日起） | — |
| 拖欠工资 | 劳动关系存续期间不受1年限制 | 终止后1年内须申请 |
| 二倍工资 | 逐月起算，每月差额独立计算1年时效 | 部分地区从离职起算 |
| 中断事由 | 主张权利/对方同意/申请仲裁 | 中断后重新起算 |
| 中止事由 | 不可抗力/其他正当理由 | 中止期间不计入 |

### 2.1 二倍工资逐月时效审查模板（v3.1.0 新增）

> v3.1.0 新增：将分散在多个文件中的二倍工资逐月时效规则收敛为可执行模板。

**适用场景**：请求未签书面劳动合同二倍工资差额时，P0必须按此模板逐月审查。

**审查模板**：

| 月份 | 二倍工资差额 | 应付日期 | 时效届满日 | 申请日是否在时效内 | 可否主张 |
|------|------------|---------|-----------|-------------------|---------|
| 入职第2月(YYYY-MM) | XXX元 | YYYY-MM-DD | YYYY-MM-DD | ✅是/❌否 | ✅/❌ |
| 入职第3月(YYYY-MM) | XXX元 | YYYY-MM-DD | YYYY-MM-DD | ✅是/❌否 | ✅/❌ |
| ... | ... | ... | ... | ... | ... |
| 入职第12月(YYYY-MM) | XXX元 | YYYY-MM-DD | YYYY-MM-DD | ✅是/❌否 | ✅/❌ |

**填写规则**：
- 应付日期 = 每月工资支付日（通常为次月15日或月底）
- 时效届满日 = 应付日期 + 1年
- 申请日 = 仲裁申请日期
- ❌不可主张的月份 → P3生成请求时自动排除

**起算规则选择**（v3.1.1 新增）：二倍工资差额的"应付日期"认定在实务中有两种观点：
- **观点A**（北京高院）：应付日期 = 当月工资支付日（如2月15日发1月工资，则1月二倍工资差额的应付日 = 2月15日）
- **观点B**（广东高院倾向）：应付日期 = 应当签订书面合同满1月之日（如7月1日入职，8月1日满1月，应付日 = 8月1日）
- **默认规则**：根据管辖地自动选择观点A/B，如无法确定则按观点A（对劳动者更有利）计算并在O2中标注[需确认当地起算规则]
- 观点A与观点B可能导致时效起算日差1-2周，直接影响部分月份是否超时效

**地区差异**：
- 北京：从主张权利之日起往前推1年
- 广东：从离职之日起算
- 其他地区：须核实当地规定，标注[需核实当地规定]

**审查产出**：`二倍工资可主张月份 = [列表] / 已超时效月份 = [列表] / 可主张总额 = XXX元`

## 3. 请求权基础评估

对每一项拟提出的仲裁请求，评估：

| 评估项 | 内容 | 判断标准 |
|--------|------|---------|
| 法律依据 | 对应哪条法律 | 条文是否明确授权/命令 |
| 构成要件 | 法律规定的要件是否齐备 | 逐一检视要件事实 |
| 抗辩预判 | 对方可能抗辩 | 是否有应对依据 |
| 金额可证 | 金额是否有证据支撑 | 工资流水/合同/考勤 |

## 4. 举证能力评估

| 争议类型 | 举证方 | 申请人需准备 | 法律依据 |
|---------|--------|------------|---------|
| 拖欠工资 | 申请人举证基础事实 | 工资流水/合同约定 | 调解仲裁法第6条 |
| 解除合法性 | 用人单位举证 | 解除通知/沟通记录 | 解释(一)第44条 |
| 减少报酬 | 用人单位举证 | 原报酬标准证据 | 解释(一)第44条 |
| 工作年限 | 用人单位举证 | 入职证据/社保记录 | 解释(一)第44条 |
| 加班事实(2年内) | 用人单位提供考勤 | 加班初步证据 | 解释(一)第42条 |
| 二倍工资 | 申请人举证未签合同 | 事实劳动关系证据 | 劳动合同法第82条 |

## 5. 请求可行性预判与取舍建议

在完成请求权基础评估和举证能力评估后，对每项拟提出的仲裁请求做可行性分级，并给出取舍建议：

| 可行性 | 条件 | 建议 |
|--------|------|------|
| **high**（可直接主张） | 法律依据充分 + 构成要件齐备 + 证据可支撑 | 列为主位请求，优先排列 |
| **medium**（可主张但需补证） | 法律依据充分但证据偏弱 | 列为请求但提示补证方向，可做备位 |
| **low**（不建议主张） | 证据严重不足或法律依据存疑 | 建议放弃或降为备位请求，避免弱请求拖累整体说服力 |

**evidence_support 分级定义**（v3.1.1 新增）：
| 级别 | 定义 | FAST_TRACK适用 |
|------|------|---------------|
| **strong** | ≥2项直接证据（如合同+工资流水，或解除通知+交涉记录） | 适用 |
| **moderate** | 至少1项直接证据+1项间接证据（如银行流水+同事证言） | 适用 |
| **weak** | 仅有间接证据或证据链不完整 | 不适用FAST_TRACK |

**取舍原则**：
- 弱请求可能引发对方强抗辩，甚至暴露我方薄弱环节
- 仲裁员对"漫天要价"的申请书信任度降低
- 仅保留有充分证据和法律依据的请求

## 6. P0→P1 硬门控

> v3.1.0 新增：P0→P1 增加 hard gate，P0 四维评估全部 COMPLETE 才允许进入 P1。

### 6.1 门控条件

| 维度 | COMPLETE 条件 | INCOMPLETE 表现 |
|------|--------------|----------------|
| 管辖策略 | 已确定管辖地+已查证仲裁委全称 | 管辖地未确定/仲裁委名称为占位符 |
| 时效评估 | 逐项请求时效状态已判定(safe/warning/critical) | 未逐项检查/二倍工资未逐月审查 |
| 请求权基础 | 每项请求法律依据+构成要件已评估 | 请求无法律依据/要件齐备度未评估 |
| 举证能力 | 申请人举证+用人单位举证倒置已识别 | 未识别举证方/缺失证据方向未提示 |
| 请求可行性预判 | 每项请求可行性已分级(high/medium/low) | 请求未分级/low请求未标注取舍建议 |

**门控规则**：四维全部 COMPLETE → 放行至 P1；任一维度 INCOMPLETE → 阻断，补充后重新评估。

### 6.2 P0 最小必须输出

P0 输出 `pre_assessment` 须包含以下全部字段，不完整不允许进入 P1：

```python
pre_assessment = {
  # 维度1：管辖（必须）
  jurisdiction: {
    recommended: "XX仲裁委",          # 必填
    full_name: "XX市XX区劳动人事争议仲裁委员会",  # 必填，不可为占位符
    reason: "...",                     # 必填
    verified: true|false               # 必填，false时P1须交互确认
  },
  # 维度2：时效（必须）
  limitation: {
    status: "safe|warning|critical",   # 必填
    details: "...",                    # 必填
    monthly_review: [...]              # 二倍工资时必填，逐月审查结果
  },
  # 维度3+4+5：请求评估（必须）
  claim_viability: [                   # 必填，每项请求必须有
    { 
      claim: "...", 
      viability: "high|medium|low", 
      recommendation: "primary|secondary|drop",
      evidence_support: "strong|moderate|weak",
      legal_basis: "...",              # 必填，法律依据
      gaps: [...],
      limitation_status: "safe|warning|critical"  # 必填
    } 
  ],
  evidence_assessment: { strong: [...], weak: [...], missing: [...] },  # 必填
  strategy_suggestion: "...",          # 必填
  
  # v3.1.0 新增：复杂度判定
  complexity: "simple|moderate|complex",  # 必填
  fast_track_eligible: true|false         # 必填
}
```

### 6.3 用户拒绝P0的降级

如用户明确拒绝P0诉前评估，自动降级为 SOFT_DEGRADED C+D+G 最小骨架模式（详见 risk-framework.md §4），输出 Missing Facts Checklist + Governance & Non-Goals + Actionable Next Steps，不生成正式仲裁申请书。

### 6.4 FAST_TRACK 门控路径（v3.1.1 新增）

> v3.1.1 新增：FAST_TRACK跳过完整四维评估时，hard gate如何判定。

当 `complexity=simple` 且 `fast_track_eligible=true` 时，P0输出 `fast_track_eligible: true` 即等价于hard gate通过，无需四维全COMPLETE。FAST_TRACK模式下：
- P0仅做时效+管辖快速检查 + 请求权基础简化评估（确认请求类型为常见给付型+证据支撑≥moderate）
- P0仍须输出 `pre_assessment` 完整字段，但请求权基础和举证能力维度可简化为"FAST_TRACK简化评估，已确认请求类型和证据基本充分"
- P2跳过蓝图工序，直接生成叙事；P3.1交叉校验改为内嵌自检

### 6.5 时效紧急例外门控（v3.1.1 新增）

> v3.1.1 新增：时效紧急案件不可因四维评估未完成而阻断。

**触发条件**：P0检测到任一请求 `limitation_status=critical`（距时效届满≤7日）

**降级门控**：时效+管辖两维COMPLETE即放行，其余维度（请求权基础/举证能力/请求可行性）标记为INCOMPLETE但允许通过，在O2中输出"⚠️ 诉前评估未完成项"清单提醒律师补全。

**输出字段**：
```python
pre_assessment = {
  # ... 正常字段 ...
  urgency_override: true,           # 时效紧急覆盖
  incomplete_dimensions: ["请求权基础", "举证能力"],  # 待补全维度
  urgency_note: "距时效届满≤7日，已降级门控放行"
}
```
