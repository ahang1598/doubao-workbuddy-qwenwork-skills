# 劳动争议仲裁申请书

## 1. 法律合规声明

本技能生成的仲裁申请书仅供参考，不构成法律意见。用户须在提交前由执业律师审核。法条引用基于知识截止日前的现行文本，使用前须检索确认。本技能不保证仲裁结果。


## 2. 快速开始

**最少输入**：申请人姓名 + 被申请人单位名称 + 至少1项仲裁请求 + 事实简述

```
申请人：张××，男，汉族，××××年×月×日生，住××省××市，公民身份号码×××，联系电话×××
被申请人：××××××公司，统一社会信用代码×××，住所地：××市××路××号，联系电话×××
法定代表人：×××，职务
仲裁请求：1. 支付拖欠工资30000元；2. 支付经济补偿金15000元
事实：2023年3月入职，2025年1月被违法解除...
```

技能将交互补全缺失信息（最多3轮），生成完整仲裁申请书。

## 3. 核心参数

### 3.1 输入参数

> 完整规格见 [references/input-spec.md](references/input-spec.md)

**必需参数**：
- `applicant`：申请人信息（姓名/性别/民族/出生年月日/公民身份号码/住址/联系电话）
- `respondent`：被申请人信息（单位全称/住所地/联系电话/法定代表人/法定代表人职务/统一社会信用代码）
- `arbitration_claims`：仲裁请求数组（每项含 type/amount/description/priority/formula）
- `facts_and_reasons`：事实与理由
- `evidence_list`：证据清单

**可选参数**：
- `labor_relation_start`：劳动关系起始时间
- `labor_relation_end`：劳动关系终止时间
- `monthly_salary`：月工资标准
- `work_years`：工作年限
- `jurisdiction_preference`：管辖偏好（履行地/所在地）
- `limitation_defense`：时效抗辩预估
- `burden_of_proof_assessment`：举证能力评估

### 3.2 输出

> 完整规格见 [references/output-spec.md](references/output-spec.md) | 格式规范见 [references/format-spec.md](references/format-spec.md)

**双产物架构**：

**O1 仲裁申请书（DOCX，F-Strict）**——提交仲裁委的正式文书：

> ⚠️ 关键格式：当事人信息标签与内容同行不换行；请求编号不加粗、首行缩进0.93cm；段落标签与内容之间不空行

1. 首部（劳动人事争议仲裁委员会全称 + 文书名称）
2. 申请人信息（"申请人：姓名，性别，…"——标签与内容同行，不换行。如为用人单位方则另起一段法定代表人信息但标签仍同行）
3. 委托代理人（如有："委托代理人：姓名，律所"——同行不换行。两人则各一段）
4. 被申请人信息（"被申请人：单位名称，信用代码，…"——标签与内容同行，不换行）
5. 被申请人法定代表人信息（"法定代表人：姓名，职务"——另起一段但标签与内容同行）
6. 仲裁请求（"仲裁请求"标签加粗、缩进0.93cm；请求编号"一、""二、"不加粗、首行缩进0.93cm；金额+计算公式嵌入加粗，千分位格式）
7. 事实与理由（核心事实+法条支撑结构：1段劳动关系基础 + N段分请求核心事实+法条依据 + 1段结论收束，文书末尾集中列出引用法条全文）
8. 尾部（此致 + 仲裁委员会 + 申请人签名/委托代理人签名 + 日期 + 附件包）

**O2 使用指引（HTML，I-Practical）**——律师内部使用指引：

> 格式遵照 I-Practical 风格（详见 format-spec.md §9 + output-spec.md §9）
- 对方抗辩预判与应对策略（实体+程序抗辩逐项预判）
- 证据分析（三分类+持有人+证据充足度+映射矩阵）
- 法条性质标注（覆盖O1引用的全部法条）+ 时效风险分析 + 管辖策略摘要
- 补证方向（含工资标准举证阶梯路径）+ 提交检查清单（含仲裁请求增加/变更时限提醒）

### 3.3 核心原则

1. **诉前评估先行**：动笔前须完成管辖/时效/请求权基础/举证能力四维评估，不评估不动笔
2. **仲裁请求具体确定**：每项请求须明确类型和金额，禁止"大约""约"等模糊表述
3. **请求排列策略**：确认类→给付类，主位→备位，金额大→金额小，仲裁员一目了然
4. **计算公式嵌入请求项**：每项金钱请求须嵌入计算公式（如"赔偿金56,000元（8,000元/月×3.5年×2倍）"），仲裁员一眼看清
5. **一段一事、事与法对应**：事实与理由部分每个自然段只讲一件事，每件事对应一项仲裁请求并援引对应法条，一段一事一法，杜绝段落交叉混述
6. **法条引用提交标准**：O1正文引用法条编号+关键内容概括，性质标注（授权性/命令性/程序性/证据性）仅用于O2和内部方法论，绝不出现在O1正文中。引用到的全部法条在文书末尾集中列出编号+条文全文
7. **基本事实原则**：事实与理由部分写明能支持仲裁请求的核心事实即可——时间、金额、行为、交涉过程。每个请求1段，一段一事，引用对应法条。不过度展开法律论证（仲裁申请书不是代理词），禁止"关于XX"独立小标题段落，禁止法条论证独立成段。末段以"申请人认为"起头做结论收束（立场宣示+法条归总+标准收束语），不归纳争议焦点
8. **仲裁前置原则**：劳动争议必须先经仲裁，不得直接向法院起诉（调解仲裁法第5条，命令性）
9. **举证责任倒置意识**：解除合法性、减少报酬、计算工作年限由用人单位举证（解释(一)第44条，命令性），在事实叙事中刻意引导
10. **时效审查**：1年仲裁时效（调解仲裁法第27条，命令性），拖欠工资不受此限，二倍工资逐月起算
11. **终局裁决标注**：追索劳动报酬不超过当地月最低工资标准12个月金额的争议为终局裁决（调解仲裁法第47条，授权性），可作为策略选项
12. **策略性事实叙事**：选择性叙事（有利事实详述/不利事实简述或省略）、因果链构建、关键节点锚定、避免不利自认
13. **金额精确到元**：所有金钱请求须精确计算到人民币元，禁止模糊区间
14. **O1/O2双格式严格隔离**：O1（DOCX）严格干净——无内部标签、无性质标注、无证据清单、无映射矩阵；O2（HTML）承载所有内部方法论标注（三分类/持有人/映射矩阵/性质标注/策略分析）。O1中仅出现纯文书内容
15. **不保证胜诉**：绝不使用"必将胜诉""无疑应予支持"等绝对化表述
16. **当事人双视角**：支持劳动者方和用人单位方律师使用，注意用语适配
17. **减少裁判者认知负担**：格式统一（宋体三号/30pt最小值行距）、段落因果递进（非并列罗列）、请求排列有序、法条按需层级递进。仲裁申请书篇幅简洁，只写核心事实+法条依据，让仲裁员拿到手就能用

### 3.4 写作红线

> 完整21条红线详见 [references/output-spec.md](references/output-spec.md) §3

核心红线：❌ 禁止保证胜诉 | ❌ 禁止金额模糊 | ❌ 禁止法条引用错误 | ❌ 禁止不利自认 | ❌ 禁止遗漏交涉记录 | ❌ 禁止计算基数错误 | ❌ 禁止请求项缺计算公式 | ❌ 禁止段落交叉混述 | ❌ 禁止N和2N并诉 | ❌ 禁止管辖外请求 | ❌ 禁止法条性质标注出现在O1 | ❌ 禁止证据清单嵌入O1 | ❌ 禁止映射矩阵出现在O1 | ❌ 禁止"关于XX"独立段落 | ❌ 禁止O1替仲裁员下结论 | ❌ 禁止将仲裁时效称为"诉讼时效" | ❌ 禁止使用"开除""辞退"等非法律术语 | ❌ 禁止遗漏仲裁前置说明 | ❌ 禁止遗漏送达地址 | ❌ 禁止遗漏信用代码 | ❌ 禁止在正文中插入分析框架标签 | ❌ 禁止"综上所述本案核心争议在于"等O2式争议焦点归纳

### 4.1 风险分级

| Phase | 风险 | 说明 |
|-------|------|------|
| Phase 0 诉前评估 | L2 | 管辖/时效/请求权基础/举证能力四维评估 |
| Phase 1 输入验证 | L1 | 基础字段校验 |
| Phase 2 事实建构 | L2 | 事实梳理与法律映射，策略叙事 |
| Phase 3 请求论证 | L3 | 金额计算与法条引用，主位备位设计，高风险 |
| Phase 4 文书生成 | L2 | 格式规范与去分析化 |
| Phase 5 质量检查 | L2 | 合规自检 |

### 4.3 FAST_TRACK 快速通道（v3.1.0 新增）

> 对简单案件启用快速通道，跳过完整四维评估，合并P2/P3，仅输出O1。

**触发条件**（P0自动判定，全部满足时启用）：
- 仲裁请求 ≤1 项 + 常见给付型（拖欠工资/经济补偿金/赔偿金）
- 证据支撑 ≥ moderate
- 无时效争议（所有请求 status=safe）
- 无管辖争议

**简化流程**：P0快速检查+简化评估 → P1输入验证 → P2+P3合并生成(跳过蓝图) → P4生成O1+O2简化版(抗辩预判+时效风险) → P5a关键阻断 → P5b格式终检

**预估提速**：40-50%

### 4.4 SOFT_DEGRADED C+D+G

当输入不足时，输出最小骨架 C+D+G。详见 [rules/risk-framework.md](rules/risk-framework.md) §4。

触发条件（v3.1.0 调整）：事实简述<50字 / 证据清单缺失 / 仲裁请求金额未明确 / 管辖仲裁委未确定 / 用户明确拒绝P0评估

## 5. 适用边界

### 5.1 适用范围

- 中国境内劳动争议仲裁申请（含确认劳动关系、追索劳动报酬、经济补偿/赔偿金、未签合同二倍工资、社保损失、加班费、年休假工资、高温津贴、代通知金等）
- 劳动者方或用人单位方提起的仲裁申请

### 5.2 不适用

- 非劳动争议（民事合同纠纷、侵权纠纷等）
- 已进入诉讼阶段的案件（应使用起诉状）
- 行政投诉/劳动监察举报
- 集体劳动争议（10人以上，应使用 labor-collective-dispute）
- 工伤认定申请（应使用 labor-injury-identification）

### 5.3 hard_reject_conditions

- 明确要求保证胜诉
- 要求伪造证据或虚构事实
- 非劳动争议法律关系
- 已超过仲裁时效且无中断事由（仅提示，不拒绝）

## 6. 常见问题

**Q: 仲裁请求可以写"约3万元"吗？**
A: 不可以。仲裁请求金额必须精确到元，如"30000元"。模糊金额将被仲裁委要求补正。

**Q: 拖欠多年的工资是否受1年时效限制？**
A: 劳动关系存续期间的拖欠工资争议不受1年仲裁时效限制（调解仲裁法第27条第4款）。劳动关系终止后，自终止之日起1年内须申请仲裁。

**Q: 用人单位方如何提起仲裁申请？**
A: 用人单位可就违约金（仅限竞业限制和服务期两种情形）提起仲裁申请。注意用语从"劳动者"视角转为"用人单位"视角。

**Q: 终局裁决对劳动者有什么影响？**
A: 终局裁决下，用人单位不可向法院起诉，但劳动者可在15日内起诉。适用条件见调解仲裁法第47条。

**Q: 仲裁请求是否需要写计算过程？**
A: 是。顶级律师做法是将计算公式嵌入请求项，如"赔偿金56,000元（8,000元/月×3.5年×2倍）"，让仲裁员一眼看清计算依据。

**Q: 经济补偿金基数用应发工资还是实发工资？**
A: 应发工资（税前）。包括计时/计件工资、奖金、津贴、补贴等货币性收入。加班费是否计入基数各地口径不一，需核实当地规定。

**Q: 二倍工资时效如何计算？**
A: 二倍工资逐月起算，每月的二倍工资差额自应付之日起算1年时效，非从劳动关系终止之日起统一计算。

## 7. 快速执行摘要（v3.1.0 新增）

> 仅列出每个Phase的最小必须动作，常规执行仅看此摘要。边界情况时查阅详细reference。

| Phase | 最小必须动作 | 产出 |
|-------|-------------|------|
| P0 | 判定复杂度(simple/moderate/complex) → 四维评估(管辖/时效/请求权/举证) → 硬门控检查 | pre_assessment + complexity + fast_track_eligible |
| P1 | 必需字段检查 → 交互补全(≤3轮) | validated_input |
| P2 | 一段一事蓝图(段→请求映射) → 蓝图审查 → 时间线+核心事实+策略叙事 | fact_blueprint + fact_timeline |
| P3 | 金额交叉校验(公式参数vs输入+基数构成) → 排列策略+公式嵌入 → 法条依据匹配 → N/2N互斥检测 | claims_with_basis |
| P4 | O1净化扫描(8项Strip) → O1七段式组装 → O2复用P0/P3产物 | O1(DOCX) + O2(HTML) |
| P5a | P2/P3/P4末尾各自执行内嵌检查(关键阻断) | 通过/阻断 |
| P5b | 终检(17阻断+18警告+格式检查) → 阻断时按回退映射表增量修复 | final_output |

> **P5质检失败恢复机制**：P5b发现阻断项时，按以下回退映射表增量修复，不重新执行完整流程：
> - 事实/金额错误 → 回退至P2/P3对应段，仅修正受影响请求项
> - 法条引用错误 → 回退至P3法条匹配步骤，替换错误引用
> - 格式/净化问题 → 在P4内原地修复，不回退
> - 连续2次修复仍不达标 → 停止，输出当前版本+阻断项清单+需用户补充信息
