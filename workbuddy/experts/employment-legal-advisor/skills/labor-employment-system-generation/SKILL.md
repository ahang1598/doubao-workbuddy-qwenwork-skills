# 企业劳动用工制度生成

## 模块1：法律合规与风险声明

> ⚠️ **免责声明（每次对外输出必附）**：
> 本制度文件为AI辅助生成的专业工作底稿，供执业律师复核，**不构成正式法律意见**；正式颁布前须经律师逐条审阅、经民主程序（职代会讨论/工会协商）和公示程序（签收确认）。

**执业安全红线（零容忍）**：

1. **绝对化禁用词**（出现即违规）：保证/必然/绝对/零风险/100%合规/完全合法。一律改为客观表述
2. **禁止写入违法条款**：不得写入"迟到一次罚款XX元"（企业无罚款权）/ "入职不满一年不享年假"（侵害法定权利）/ "工伤期工资按病假发"（停工留薪期待遇不变）/ "超过XX年龄不录用"（就业歧视）
3. **禁止混同保密与竞业限制**：保密为法定义务（不需补偿），竞业限制为约定义务（必须补偿），须明确区分
4. **法条编号须核实**：涉及法条引用时按 `references/trusted-data-sources.md` 检索链执行，待核查内容标「待核查」，不凭记忆猜测

## 模块2：快速开始

**一句话定位**：帮劳动法律师为企业客户生成整套劳动用工制度文件包（员工手册+专项制度+配套表单+民主程序模板）。

**最小示例**：
```
输入："帮我为深圳一家200人物业公司生成劳动用工制度"
→ Phase 0 交互 → 识别 Mode A → 加载 7 模块骨架 → 标准版制度文件包（7个独立DOCX + 2个附录DOCX）
```

**预期输出**：
- Mode A（起草）：O1 制度文件包（DOCX，7制度+2附录）+ O2 风险提示清单（MD）+ O3 风险矩阵（MD）
- Mode B（审查）：O1 审查意见（MD，逐条比对+修改建议+法条依据）+ O2 优化后制度文件（DOCX）
- 信息不足时降级为 SOFT_DEGRADED 半成品（C+D+G最小骨架）

**核心方法论**：三大生效要件（内容合法 → 民主程序 → 签收闭环）+ 制度起草五步法 + 三层次违纪体系

**双模式驱动**：

| 模式 | 输入 | 输出 | 典型场景 |
|:---|:---|:---|:---|
| **Mode A 起草** | 企业基本参数 + 制度需求描述 | 制度文件包（DOCX主/MD辅） | 从0搭建劳动用工制度/补缺某模块 |
| **Mode B 审查** | 原始制度文本（粘贴或DOCX）+ 审查诉求 | 审查意见（MD）+ 优化后制度（DOCX） | 合规体检/法条更新/接手上任律师工作 |

## 模块3：核心参数与法律约束

### Phase 0：交互前置（首次必互动，不可跳过）

> **核心原则**：用户首次提出制度诉求时，不可直接生成。执行顺序不可调换。

**执行顺序（不可调换）**：
1. **路由边界检查** — 用户诉求是否在本技能范围内？不在→路由到目标技能；在范围内→继续
2. **参数提取与推断** — 从用户输入中提取/推断企业参数，标注置信度（high/medium/low）
3. **gap_score 计算** — 0→一行确认或直通；>0→展示配置卡

**路由边界速判表**：

| 用户意图 | 路由目标 |
|:---|:---|
| 审查已有制度合规性 | Mode B（本技能内） |
| 劳动争议案件分析/仲裁诉讼 | → 劳动法律师系列技能 |
| 单一合同审查（如竞业限制协议） | → 合同审查技能 |
| 工伤赔偿计算 | → 工伤赔偿计算器 |

**Mode A 必填参数**（缺任何一项则触发配置卡）：

| 编号 | 参数 | 选项 | 说明 |
|:---:|:---|:---|:---|
| 1 | 企业注册地 | 广东省/北京/上海/江苏/浙江/其他 | 决定地方性标准数据匹配 |
| 2 | 企业规模 | 初创≤20人 / 20-200人 / 200-500人 / 500人+ | 决定制度复杂度阶梯 |
| 3 | 主营业务/行业 | 物业/制造业/餐饮服务/科技互联网/建筑施工/医疗/其他 | 决定行业专项注入 |
| 4 | 用工模式 | 自聘为主/派遣混用/外包为主 | 决定特殊用工管理模块深度 |

**推断规则表**（路由级行为契约，agent 直接执行）：

| 原始信号 | 推断参数 | 置信度 |
|:---|:---|:---:|
| "物业/保安/保洁/小区" | 行业=物业管理 | high |
| "工厂/生产线/车间" | 行业=制造业 | high |
| "餐厅/外卖/连锁" | 行业=餐饮服务 | high |
| "科技/互联网/SaaS" | 行业=科技互联网 | medium |
| "建筑/工程/项目制" | 行业=建筑施工 | medium |
| "医院/诊所/药房" | 行业=医疗 | high |
| "几个人/十来个人/刚起步" | 规模=初创≤20人 | medium |
| "小区物业管理" | 规模=20-200人（默认） | low |
| "外包/派遣" | 用工模式=派遣混用 | high |
| 未提及用工模式 | 用工模式=自聘为主（默认推断） | low |

> 详细推断规则表见 `references/workflow-detail.md` Phase 0。

**gap_score 三级处理**：

| gap_score | 置信度条件 | 处理方式 |
|:---|:---|:---|
| **0**（4项全部明确） | 全部 high + FAST_TRACK | **直通**：不展示配置卡，不确认，直接进入 Phase 1 |
| **0**（4项全部明确） | 全部 high，不满足 FAST_TRACK | **一行确认**："已理解：{行业}·{规模}·{地域}·{用工模式}。是否开始生成？" |
| **0** | 存在 medium/low | 展示预填配置卡（预填推断值 + ⚠️标记低置信度项），一次确认 |
| **1-2**（部分缺失） | 不限 | 展示配置卡（高置信度预填✅ / 中置信度预填⚠️ / 缺失标❗），一次补全 |
| **≥3**（几乎空白） | — | 展示空白配置卡 + 全部❗标记；若用户明确"先出草稿"→触发 SOFT_DEGRADED |

**FAST_TRACK 条件**：用户描述一次性满足（1）明确的行业信号 +（2）明确的规模信号 +（3）明确的地域信号 +（4）明确的用工模式信号。

### 制度复杂度阶梯

| 档次 | 企业规模 | 制度模块数 | 条款颗粒度 |
|:---|:---|:---|:---|
| **精简版** | 初创型（≤20人） | 3模块（员工手册+考勤休假+薪酬绩效） | 粗线条，覆盖法定底线+核心条款 |
| **标准版** | 中型（20-200人） | 7模块（全模块） | 中等，补充行业专项+风险提示 |
| **完整版** | 大型（200人+） | 7模块深化 | 精细，补充分支机构/多岗位/多用工模式适配 |

> 详见 `references/methodology.md` §制度复杂度阶梯

## 模块4：输出格式与质量标准

### 输出格式

**Mode A**：DOCX主（FS2 client-deliverable排版规范：封面+目录+制度正文+配套表单+民主程序模板）+ MD辅（O2风险提示清单+O3风险矩阵）
**Mode B**：MD主（审查意见：原条文→修改建议→理由+法条依据+严重度）+ DOCX辅（优化后制度文件）

> 详见 `references/output-format-spec.md`

### 质量标准

**起草质量红线**（每步产出后必做自检）：

| 检查项 | 不达标信号 | 纠正动作 |
|---|---|:---|
| Phase 0 交互已执行（含路由边界检查） | 未经交互直接生成制度文件 | 暂停，执行路由边界→参数提取→gap判定 |
| 路由已判 | 用户问劳动仲裁却在本技能展开 | 转劳动法律师系列技能 |
| 行业专项已注入 | 生成制造业制度但无倒班制/职业病防护条款 | 重新加载行业注入表 |
| 地方标准数据已匹配 | 深圳企业用了广州的低工资标准 | 对照regional-rules.md修正 |
| 负面清单已过筛 | 出现"迟到罚款XX元"等违法条款 | 对照negative-list.md逐条修正 |
| 保密与竞业已区分 | 混在同一章未区分法定义务与约定义务 | 保密融入员工手册行为规范章，竞业独立为附件 |
| 惩罚程序正义完整 | 缺少申辩期/工会意见/处分时效 | 补充程序正义三环节 |
| 模块间交叉一致 | 员工手册引用条款与专项制度不一致 | 逐条交叉校验修正 |
| 表单字段与制度正文一致 | 处分通知书缺少制度规定的申辩期字段 | 修正表单模板 |
| O1 正文清洁无工作标注 | 制度正文中出现 `[来源:检索\|...]` | 移除来源标注，移至 O2 |

**熔断**：同一卡点连续纠正 2 次仍不达标 → 停止推进，汇报「已完成部分+卡在哪+已试方案+需用户提供什么」，交回控制权。

### SOFT_DEGRADED 降级机制

当用户必填信息缺失或法条检索失败时，不拒绝输出，而是降级为结构化半成品。

**触发条件**（满足任一即降级）：
- 4 项必填参数中缺失 2 项以上且用户明确表示"先出草稿"
- 法条检索失败（标记 `legal_retrieval_failed`）
- 用户提供的信息存在内部矛盾

**降级产物 = C + D + G 最小骨架**：

| 块 | 内容 | 目的 |
|:---|:---|:---|
| **C 块（Missing Facts）** | 结构化待补充清单：每个缺失参数 + 对输出哪部分有影响 + 补充后如何升级 | 用户补什么才能升级到 COMPLETE |
| **D 块（Governance & Non-Goals）** | 法律底线摘要 + 制度不能写什么（负面清单关键项） | 确保降级产物仍不违反法律底线 |
| **G 块（Actionable Next Steps）** | 用户下一步该做什么（3-5条具体行动项） | 推动用户补信息以升级到 COMPLETE |

**降级标记**：降级产物首行标注 `[SOFT_DEGRADED] 缺失信息：{列出缺失项}`，用户补充后可重新执行至 COMPLETE。

### 适用场景

| 关键词/场景 | 路由 |
|:---|:---|
| "生成员工手册/劳动用工制度/公司规章制度" | Mode A → 采集参数→加载模块骨架 |
| "帮物业/工厂/餐厅/科技公司做一套用工制度" | Mode A，行业信号明确→自动加载行业注入表 |
| "审查这份员工手册有没有问题" | Mode B → 逐条合规审查 |
| "新版劳动法出来了帮我更新制度" | Mode B，触发法规更新对照 |
| "接手客户已有的制度帮我梳理合规性" | Mode B，质量审查+合规更新 |
| "初创公司20人需要基本制度" | Mode A，精简版（3模块） |
| "集团公司500人+多分支机构" | Mode A，完整版（7模块深化） |

### 边界说明

- **不替代律师独立判断**：所有输出为专业底稿，须经执业律师审阅
- **不覆盖地方性法规全部细节**：支持6个地区的主要标准，地方特殊规定需律师确认
- **不含境外适用**：仅适配中国大陆法律体系，不含港澳台及境外
- **不替代民主程序**：输出含民主程序模板，但程序的实际执行由企业自行完成
- **审查版（Mode B）不替代专项尽职调查**：仅作规范性审查，不判断企业经营实际合规状态

## 模块6：常见问题

**Q1：初创公司10个人需要全部7个模块吗？**
不需要。精简版仅需3个模块（员工手册+考勤休假+薪酬绩效），其余模块可后续按需补充。详见 `references/module-selection-guide.md`。

**Q2：保密和竞业限制放同一份文件可以吗？**
不建议。保密为法定义务不需补偿，竞业限制为约定义务必须补偿，混同签收会产生法律混淆。建议：保密条款融入员工手册行为规范章，竞业限制协议作为劳动合同独立附件。

**Q3：外地的物业公司能用这套制度吗？**
可以，但需要指定地区后加载对应的地方性规则数据。当前支持广东/北京/上海/江苏/浙江6个主要地区。

**Q4：员工手册里的条款和专项制度冲突了怎么办？**
员工手册为"权利性条款"（员工可直接引用的权利），专项制度为"管理性条款"（HR操作细则）。如出现不一致，以专项制度为准（专项制度为实施细则），但专项制度不得缩减员工手册已载明的法定权利。制度位阶规则见 `references/methodology.md` §制度位阶与冲突解决。
