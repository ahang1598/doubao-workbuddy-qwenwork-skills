## Phase 总览

```
Phase 0 [前置·不计入主Phase序号] 交互前置与信息收集
Phase 1         模式识别与制度范围确认
Phase 2 [P2]   结构规划 — 基于复杂度阶梯生成制度框架大纲
Phase 3 [P3]   逐模块填充 — 按确认的模块清单逐一生成完整条款 [L3]
Phase 4 [P4]   法律核验与一致性校验 — 交叉校验+法条核验+红线校对 [L3]
Phase 5         终检与交付
```

**Mode A 走全部 Phase**。**Mode B 走 Phase 0-1 + Mode B 专属步骤 + Phase 4-5**。

## 加载决策树

> 基于 Phase 0 收集的 4 项必填参数，决定加载哪些参考文件。

| 参数 | 加载文件 | 加载条件 |
|:---|:---|:---|
| 行业 | `references/industry-specs.md` | 6行业匹配→加载对应行业注入表 |
| 地域 | `references/regional-rules.md`（相关地区节） | 匹配6地区→加载对应地方标准数据 |
| 规模 | 复杂度阶梯（精简/标准/完整版） | 决定制度模块数量和条款颗粒度 |
| 用工模式 | `references/module-skeletons.md §special-employment` 深度 | 派遣/外包为主→完整深度；自聘为主→简化 |

**始终加载**（不管参数如何）：
- `references/methodology.md` — 三大生效要件+五步法+程序正义框架
- `references/legal-baseline.md` — 8类红线约束
- `references/negative-list.md` — 8条不可写入条款
- `references/module-skeletons.md`（原module-guide.md已删除） — 7模块章节结构（[LEGACY]参考基准，主要参考以 `references/module-skeletons.md` 骨架为准）

**禁用规则**：
- ❌ 禁止在生成制造业制度时加载物业管理行业注入表
- ❌ 禁止在企业注册地为深圳时加载北京的地方标准
- ❌ 禁止并行生成多个模块（须串行逐模块生成，确保一致性）

## 渐进式生成链

> 遵循 P2→P3→P4 "规划→填充→精修"链式依赖。

| Phase | 产出物形态 | 增量内容 | 禁止 |
|:---|:---|:---|:---|
| **P2 结构规划** | 制度框架大纲（每模块章节标题+关键条款要点≤20字/项） | 不生成完整条文 | ❌ 禁止在P2即输出完整制度文本 |
| **P3 逐模块填充** | 基于P2大纲的完整制度条款草稿 | 各模块完整条款、法条引用、行业专项注入、风险标注 | ❌ 禁止脱离P2大纲重新规划模块 |
| **P4 精修核验** | 基于P3草稿的精修文本 | 交叉一致性校验、法条核验、红线校对、语言打磨、负面清单过筛 | ❌ 禁止从零重新生成条文 |

**链式依赖**：P2产物→P3输入 / P3产物→P4输入。后续Phase必须显式引用前一Phase的产出。

## Phase 0：交互前置与信息收集

**[前置步骤，编号为Phase 0但不计入主流程Phase序号]**

### 执行顺序（不可调换）

```
① 路由边界检查 → 不在本技能范围？→ 路由到目标技能
  └→ 在范围内 ↓
② 参数提取与推断（推断规则表 + 置信度标注）
  └→ 同时判定 Mode A / Mode B ↓
③ 计算 gap_score
  ├→ gap=0 且全部 high + FAST_TRACK → 直通 Phase 1
  ├→ gap=0 且全部 high → 一行确认
  ├→ gap=0 但有 medium/low → 预填配置卡（⚠️标注低置信度项）
  └→ gap>0 → 展示配置卡（预填✅/⚠️/缺失❗）
```

### 步骤①：路由边界检查（[L1] 必须在参数收集之前执行）

判定用户诉求是否在本技能范围内。判断依据参见 SKILL.md 模块5的边界说明。

**禁止行为**：
- ❌ 禁止在路由边界判定前展示配置卡
- ❌ 禁止在路由边界判定前提取参数
- ❌ 禁止对"劳动争议诉讼""工伤赔偿计算"等不在本技能范围的诉求展开

**判定为不在本技能范围时的响应模板**：
```
您提到的{诉求要点}不在本技能范围内（本技能专注企业劳动用工制度的起草与审查优化）。

建议转至：{推荐技能名称}
是否需要我帮您切换到该技能？
```

### 步骤②：参数提取与推断

基于以下推断规则表，从用户输入中提取/推断参数，标注置信度。

**Mode A 参数推断完整规则表**：

| 原始输入信号 | 推断参数 | 置信度 | 条件/注意事项 |
|:---|:---|:---:|:---|
| "物业/保安/保洁/小区/写字楼" | 行业=物业管理 | high | — |
| "工厂/生产线/车间/制造" | 行业=制造业 | high | — |
| "餐厅/外卖/连锁/餐饮" | 行业=餐饮服务 | high | — |
| "科技/互联网/SaaS/软件" | 行业=科技互联网 | medium | 需确认是否有生产线 |
| "建筑/工程/施工/项目制" | 行业=建筑施工 | medium | — |
| "医院/诊所/药房/医疗" | 行业=医疗 | high | — |
| "深圳/广州/东莞" | 地域=广东省 | high | — |
| "北京" | 地域=北京市 | high | — |
| "上海" | 地域=上海市 | high | — |
| "南京/苏州" | 地域=江苏省 | high | — |
| "杭州/宁波" | 地域=浙江省 | high | — |

| 无规模信号 | 无法推断，留空 | — | gap_score+1 |
| 无地域信号 | 无法推断，留空 | — | gap_score+1 |

**Mode A/B 自动判定规则**：

| 输入特征 | 判定结果 | 置信度 |
|:---|:---|:---:|:---|
| 用户粘贴了 >300字的制度文本 | Mode B | high |
| 用户上传了 .doc/.docx 文件（文件名含"员工手册/制度/规章制度"） | Mode B | high |
| "审查/看一下/有没有问题/看看/校校/检查/过时/不合规"等关键词 + 原始文本 | Mode B | medium |
| "起草/写/生成/新建/帮做/做一套"等关键词 + 无文本 | Mode A | high |
| 仅有需求描述，无任何文本 | Mode A（默认） | high |

### 步骤③：gap_score 计算

**Mode A gap_score** = 4（注册地 + 企业规模 + 行业 + 用工模式）− 已提取的参数数量

**Mode B gap_score** = 更宽松（最低只需制度文本即可运行，参数缺失不阻断）

**三级处理详述**：

| gap | 置信度 | 具体动作 | 用户看到什么 |
|:---|:---|:---|:---|
| **0 / all high / FAST_TRACK** | 全部 high + 深圳+物业+200人+正式工 | **直通** | 直接进入 Phase 1 |
| **0 / all high** | 全部 high | 一行确认 | "已理解：{行业}·{规模}·{地域}·{用工模式}。是否开始生成？" |
| **0 / mixed confidence** | 存在 medium/low | 预填配置卡 | 字段已填推断值 + low置信度项标⚠️ |
| **1–2** | 不限 | 配置卡 | 已填项✅ / 低置信预填⚠️ / 缺失标❗ |
| **≥3** | — | 空白配置卡 or SOFT_DEGRADED | 全部标❗；用户选"先出草稿"→触发 SOFT_DEGRADED |

### Phase 0 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 0-0 | [L1] 路由边界已检查 | 未在参数提取前执行路由边界检查→暂停 | L1 |

| 0-5 | 行业已匹配注入表 | 6大行业中无匹配但用户已指定→标记待补充 | L2 |

## Phase 1：模式识别与制度范围确认

### 执行逻辑

1. **确认 Phase 0 推断结果**：4项必填参数已在 Phase 0 判定和确认
2. **确定复杂度阶梯**：根据企业规模确定精简版/标准版/完整版
3. **执行模块选择决策树**：按规模+行业推荐模块组合
4. **展示制度范围骨架**：列出推荐模块清单供律师确认或调整

### Mode A 模块组合推荐

| 企业规模 | 推荐模块 | 说明 |
|:---|:---|:---|
| 精简版（≤20人） | 员工手册 + 考勤休假 + 薪酬绩效 | 3模块，覆盖法定底线 |
| 标准版（20-200人） | 7模块全量 | 员工手册+合同管理+考勤休假+薪酬绩效+奖惩+特殊用工+保密竞业 |
| 完整版（200人+） | 7模块深化 + 可选扩展 | 增加反性骚扰/个人信息保护/远程办公/数据安全/外籍管理等扩展模块 |

> 详细决策树见 `references/module-selection-guide.md`

### Phase 1 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 1-1 | Phase 0 推断结果已确认 | 参数仍不明确→回退 Phase 0 | L2 |
| 1-2 | 复杂度阶梯已确定 | 未按规模确定→确定 | L2 |
| 1-3 | 模块清单已展示并获确认 | 未展示骨架确认→展示 | L2 |

## Phase 2：结构规划（P2）

> **Mode B 跳过此Phase**

### 执行逻辑

1. 读取确认的模块清单，按 `references/module-skeletons.md` 加载对应骨架文件
2. 根据复杂度阶梯确定每个模块的条款颗粒度
3. 加载对应行业注入表（`references/industry-specs.md`）
4. 加载对应地区标准数据（`references/regional-rules.md` 相关地区节）
5. 生成**制度框架大纲**（每模块章节标题+3-5个关键要点，每要点≤20字）
6. 标注行业专项注入点 + 风险标注点

### Phase 2 产出格式

```markdown
## 制度框架大纲（{行业}·{复杂度}版）

### 模块01：员工手册
- 第一章 总则（目的/范围/术语定义）
- 第二章 招聘与录用（就业歧视禁止/录用条件/禁止童工）
- ...（共12章，精简版5章）

### 模块03：考勤与休假制度
- [行业注入] 制造业—倒班制排班方案
- [行业注入] 制造业—夜班津贴标准
- [风险标注:L2] 综合计算工时制审批要求
...
```

### Phase 2 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 2-1 | 模块数量与复杂度阶梯匹配 | 精简版>3模块→裁剪；完整版<7模块→补充 | L2 |
| 2-2 | 行业注入表已加载 | 未加载→加载匹配的行业注入表 | L1 |
| 2-3 | 地区标准数据已匹配 | 深圳企业用了广州标准→修正 | L1 |
| 2-4 | 模块骨架仅加载1份/模块 | 混入其他行业骨架→清除 | L2 |

## Phase 3：逐模块填充（P3）

> **Mode B 跳过此Phase**

### 执行逻辑

1. **基于 Phase 2 的制度框架大纲**，逐模块生成完整条款
2. 每个模块按 `references/module-skeletons.md` 对应骨架的章节结构执行（module-guide.md 已删除，以 `module-skeletons.md` 为准）
3. 嵌入行业专项注入（从 `industry-specs.md` 读取）
4. 注入地区标准数据（从 `regional-rules.md` 读取）
5. 负面清单过筛（对照 `negative-list.md` 逐条检查）
6. 风险标注（L1/L2/L3 体系）

### Phase 3 关键规则

- **法条引用方式**：引用法条编号（"依据《劳动合同法》第4条"），标注核实状态
- **地方标准显式标注**："深圳最低工资2520元/月（粤府函〔2025〕23号）"
- **行业专项显式标注**：`[制造业专项]` 标记行业特有条款
- **员工手册与专项制度职责边界**：员工手册=权利性条款（可引用），专项制度=管理性条款（HR操作）
- **保密融入行为规范章**：保密条款在员工手册"行为规范"章呈现；竞业限制独立为合同附件
- **程序正义三环节**：通知与申辩→工会意见→决定送达（奖惩制度必含）
- **制度位阶条款**：附则中写入"本制度与员工手册不一致的，以本制度（专项制度）为准，但不得缩减员工手册已载明的法定权利"

### Phase 3 出声思考（会话中输出）

生成每个模块时必须在会话中输出：
```
正在生成[模块名称]：
- 核心条款：[N]条
- L1风险点：[N]处（[简述]）
- 行业专项注入：[N]处（[简述]）
- 地方标准注入：[N]处
- 制度位阶引用：详见《XX文件》
```

### Phase 3 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 3-1 | 每模块条款与P2大纲一致 | P2有但P3缺→补充 | L2 |
| 3-2 | 行业专项已注入 | 制造业无倒班制条款→补充 | L1 |
| 3-3 | 地区标准数据已注入 | 未按注册地匹配→修正 | L1 |
| 3-4 | 负面清单已过筛 | 出现"迟到罚款"条款→修正 | L1 |
| 3-5 | 保密与竞业已区分 | 混合同章→拆分 | L1 |
| 3-6 | 程序正义完整 | 缺申辩期/工会意见→补充 | L2 |
| 3-7 | 员工手册权利性条款完整 | 全部是"详见XX文件"→补充可直接引用的权利条款 | L2 |
| 3-8 | 制度位阶条款已写入 | 附则无冲突解决规则→补充 | L2 |

## Phase 4：法律核验与一致性校验（P4）

> **Mode A 和 Mode B 共用**

### 执行逻辑

1. **基于 Phase 3 全部模块草稿**（Mode A）或 **Mode B 优化后文本**，执行法律核验
2. 逐条对照 `legal-baseline.md` 8类红线，标注违规项
3. 逐条对照 `negative-list.md` 8条负面清单，确认无违法条款
4. 执行多模块交叉一致性检查（详见下方）
5. 语言精修：消除绝对化表述、统一术语定义、确保条款间无矛盾
6. 地方裁判口径差异化提示（对照 `regional-rules.md` 地方差异矩阵）

### 法条检索强制契约（§17.15）

**检索调用链**（按顺序执行，任一环节成功即停止）：
1. **优先**：联网检索法条原文（国家法律法规数据库 https://flk.npc.gov.cn/）
2. **备选**：地方人社局官网检索地方性标准
3. **降级**：两次检索均失败 → 标记 `legal_retrieval_failed`，该法条降级为「待核查」，触发 SOFT_DEGRADED

**法条来源标注格式**（仅 O2 风险提示清单，不写入 O1 制度文件正文）：
```
[来源:检索 | 检索工具:xxx | 检索时间:YYYY-MM-DD]
```

> **关键规则**：O1 制度文件正文（DOCX/MD）中不出现任何 `[来源:检索|...]` 标注。

### Phase 4 检查项

| # | 检查项 | 阻断条件 | 风险等级 |
|:---:|:---|:---|:---:|
| 4-1 | 法律底线8类红线逐条通过 | 任一红线违反→修正 | L1 |
| 4-2 | 负面清单8条全部通过 | 任一违规→修正 | L1 |

## Mode B 专属步骤

> 在 Phase 1 之后、Phase 4 之前执行，替换 Phase 2-3。

### 步骤B1：解析原始制度

1. 用户提供原始制度文本（粘贴或DOCX）
2. 提取章节结构，识别制度模块类型（员工手册/考勤/薪酬/奖惩等）
3. 标注原始制度的结构完整性

### 步骤B2：逐条比对

1. 按模块拆分原始制度
2. 逐条比对：标注"已有且合规"/"已有但过期"/"缺失"/"表述模糊"/"违反法律底线"
3. 逐条对照 `legal-baseline.md` 的8类红线 + `negative-list.md` 的8条负面清单
4. 行业专项适配度评估（如制造业制度是否含倒班制/职业病防护条款）

### 步骤B3：生成变更清单

输出"变更对比清单"（MD格式）：

| # | 原条文 | 建议修改 | 修改理由 | 法条依据 | 严重度 |
|:---|:---|:---|:---|:---|:---|
| 1 | 迟到一次罚款50元 | 删除罚款条款，改为"扣除当日绩效分X分" | 企业无罚款权 | 工资支付暂行规定第16条 | L1阻断 |

额外输出：
- 过期法规清单（标注失效法规及替代法规）
- 缺失模块清单（按行业标准对照）
- 程序正义缺陷清单

### 步骤B4：生成优化后全文

基于变更清单，在原始制度上执行修改，输出优化后全文。

> 优化后全文进入 Phase 4（法律核验与精修）。

## 复杂度分层

| 复杂度 | 触发条件 | 流程简化 |
|:---|:---|:---|
| **SIMPLE** | 精简版（≤20人/3模块）+ 信息齐全 | Phase 2-3合并（规划+填充一步完成） |
| **STANDARD** | 标准版（20-200人/7模块） | 全流程 |
| **COMPLEX** | 完整版（200人+/7模块深化+扩展模块）/ Mode B含多项违规 | 全流程 + 多模块交叉一致性检查 |

### FAST_TRACK 快速通道（SIMPLE 子集）

当满足以下全部条件时，进入 FAST_TRACK：

| # | FAST_TRACK 触发条件 | 判定标准 |
|:---:|:---|:---|
| FT-1 | 4项必填参数全部明确 | 无任何占位参数 |
| FT-2 | 初创型（≤20人）+ 自聘为主 | 精简版颗粒度 |
| FT-3 | 单行业 + 单地域 | 单一行业注入表+单一地区数据 |
| FT-4 | 无特殊用工需求（无派遣/外包/退休返聘/实习） | 标准法律基线即可 |

**FAST_TRACK 流程简化**：

| 原Phase | FAST_TRACK处理 | 跳过原因 |
|:---|:---|:---|
| Phase 0 | 正常执行 | 信息已齐全，仅确认 |
| Phase 1 | 正常执行 | 模式识别不可省略 |
| Phase 2-3 | **合并**为一步：直接基于3模块骨架生成精简版草稿 | 初创+自聘→精简版（3模块），结构与骨架高度一致 |
| Phase 4 | **简化**为红线速检：仅检查8类红线+负面清单 | 初创企业无复杂用工需求 |
| Phase 5 | 正常执行 | 终检不可省略 |
