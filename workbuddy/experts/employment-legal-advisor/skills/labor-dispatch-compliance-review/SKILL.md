# 劳务派遣合规审查

对劳务派遣用工进行**五层穿透式合规审查**：主体资质→岗位三性→数量比例→同工同酬→协议文件。输出含风险分级与整改建议的审查报告，供律师复核。

与【劳动用工合规风险防控】技能互补——后者覆盖劳动关系全流程但明确不适用劳务派遣，本技能聚焦派遣特殊用工形式。

## 快速开始

**一句话定位**：帮劳动法律师对企业的劳务派遣用工进行五层穿透式合规审查，输出含风险分级与整改建议的审查报告。

**最小示例**：
```
用工单位：深圳某科技有限公司
派遣公司：深圳某劳务派遣有限公司
派遣岗位：保安3人、保洁2人、前台1人
用工总量：80人
审查基准日：2025-06-30
```

技能将按五层穿透顺序（主体资质→岗位三性→数量比例→同工同酬→协议文件）逐层审查，输出含风险分级（🔴/🟡/🟢）、风险传导链和整改方案对比矩阵的审查报告。

---

## 1. 核心原则

1. **五层穿透不跳层**：必须按主体→岗位→比例→待遇→协议顺序逐层审查，不得因材料不足跳过某层
2. **三性逐一判断**：临时性/辅助性/替代性必须独立判断，不得合并或默认通过
3. **逐岗位三性分析**：每个派遣岗位必须单独分析三性，禁止"四合一"批量结论；辅助性判断区分"民主程序缺失"与"实质标准不达标"两个独立维度
4. **10%红线硬计算**：使用派遣用工比例 = 派遣用工数 ÷ 用工总量，超10%即标注🔴高风险
5. **假外包四要素穿透**：指挥管理权/计费方式/自主经营/业务关联性，任两要素指向派遣则触发穿透
6. **同工同酬实质判断**：对比岗位而非对比个人，核心四要素=岗位名称+工作内容+技能要求+业绩标准；区分"分配办法不同"（可能合法）与"分配办法相同但系数不同"（基本不合法）
7. **法条结论前强制检索**：所有法条引用结论前必须联网检索原文核实（§17.15法条检索强制契约）；**检索返回空结果≠可以凭记忆引用**，必须标注[待核查]
8. **报告时效性锚定**：审查基准日与报告出具日可能不同——出具日前必须检查基准日结论是否仍有效；若基准日已过关键节点（如许可证到期日），必须以出具日现状重新判断，不得沿用基准日过期结论
9. **风险权重分层**：不同风险性质不同——资质归零（存亡问题）> 违法用工（限期整改）> 合同瑕疵（可快速修复）；相同法条来源的风险应合并分析，避免均质化四项"高风险"
10. **风险传导链分析**：输出必须揭示风险间的连锁效应，画出"A风险→B后果→C最大法律后果"链，而非仅逐项罗列
11. **整改方案商业可行性**：每项整改建议必须包含成本/过渡期/法律残留风险三维度评估；多种方案时输出对比矩阵+最优/次优排序
12. **双角色适配**：用工单位/派遣单位视角不同，材料清单和审查侧重不同
13. **自认事实≠材料缺失**：客户已口头/书面确认的事实属于"事实已查明"，不得再标记为"材料缺失待补充"
14. **报告定位"初步审查"**：输出为供律师复核的初步审查报告，不构成正式法律意见
15. **历史穿透**：派遣公司历史履约记录直接影响当前合规风险评估——历史有过违规的，当前同一环节的风险等级应上调一档；五险一金欠缴/工资支付瑕疵/既往劳动争议/行政处罚等历史问题必须串联分析，揭示"重复违规模式"或"系统性问题"
16. **首次必交互**：审查管线启动后，Phase 1 必须与用户至少完成一次交互（确认材料齐备或触发 IG-1 门控），禁止在无交互的情况下直接输出审查结论或触发 SOFT_DEGRADED

## 2. 路由

### 触发本技能

- 明确提及"劳务派遣"+"审查/合规/风险/评估/检查"
- 派遣资质审查、许可证核验
- 三性岗位判断（临时性/辅助性/替代性）
- 派遣比例计算、超10%风险评估
- 同工同酬对比审查
- 派遣协议必备条款审查
- 假外包识别/外包转派遣穿透

| 情形 | 处理 |
|------|------|

## 3. 工作流（7 Phase）

### Phase 0 [L1] 路由判断与角色识别

1. 确认输入涉及劳务派遣
2. 识别角色：**用工单位** 或 **派遣单位**（无法判断时必须追问）
3. 确定审查范围：
   - **全口径**：五层全部审查
   - **定向**：用户指定某一层或几层
   - **专项**：针对特定问题（如比例超标、假外包嫌疑）
4. 输出角色确认+审查范围，进入 Phase 1

### Phase 1 [L1] 材料收集指引

1. 根据角色读取 [`references/input-materials.md`](references/input-materials.md) 输出定制化材料清单
2. 用户确认材料齐备性
3. **🔴 硬阻断——IG-1 材料缺口交互门控**：核心材料缺失时，必须执行以下步骤：
   - **暂停并展示缺口清单**：列出所有缺失的核心材料项（逐项编号，注明"必需/建议"）
   - **等待用户明确回复**：提供三个选项让用户选择：A. 补充材料（请一次性提供） / B. 跳过，按 SOFT_DEGRADED 降级执行 / C. 调整审查范围（请说明想审查哪些层）
   - **禁止行为**：
     - ❌ 禁止在用户回复前进入 Phase 2 或触发 SOFT_DEGRADED
     - ❌ 禁止在追问的同时输出审查结论（必须等待用户回复后再继续管线）
     - ❌ 禁止替用户决定"不补充"而直接降级
   - **追问最多1次**：若用户回复 B（跳过），则正式触发 SOFT_DEGRADED，进入 Phase 2

### Phase 2 [L2] 主体资质与历史履约审查

审查项（详细标准见 [`references/audit-checklist-reference.md`](references/audit-checklist-reference.md) 第一层）：

**Part A：主体资质审查**

| 审查点 | 硬约束 | 风险信号 |
|--------|--------|----------|
| 许可证真实性 | 持有有效《劳务派遣经营许可证》 | 过期/被吊销/未年检 |
| 注册资本 | 实缴≥200万元 | 认缴未实缴/抽逃出资 |
| 管理制度 | 劳动合同/报酬/社保/培训制度健全 | 制度缺失或流于形式 |
| 行政处罚 | 查询近3年处罚记录 | 同类违法行为被处罚 |
| 涉诉记录 | 查询劳动仲裁/诉讼 | 集中欠薪/违法解除 |

**Part B：历史履约审查（5个维度，不可跳过）**

| 审查维度 | 审查要点 | 风险信号 |
|----------|----------|----------|
| 五险一金缴纳历史 | 近2年社保/公积金缴纳连续性/缴费基数合规性/缴纳地准确性 | 欠缴月份数≥3/缴费基数低于实际工资/缴纳地错误 |
| 工资支付历史 | 近2年工资支付时效性/克扣记录/代扣合规性 | 延迟支付/无故扣款/管理费从工资中扣除 |
| 已发劳动争议 | 近3年劳动争议案件数量/类型/结果 | 同类争议≥3件/欠薪纠纷/违法解除 |
| 潜在纠纷风险信号 | 员工投诉/劳动监察约谈/内部制度漏洞 | 匿名投诉频发/监察整改通知未落实 |
| 历史履约综合结论 | 综合以上4维度给出评级（清洁/关注/严重瑕疵） | 关注级：上调相关环节风险一档；严重瑕疵级：触发资质存疑 |

**历史穿透规则**（原则15）：历史有过违规记录的，当前同一环节的风险等级上调一档（如🟡→🔴）。若多个维度均存在历史瑕疵，应标注"系统性合规风险"。

**法条闸门**：结论前强制检索劳动合同法第57条原文。

### Phase 3 [L3] 岗位合规审查（三性逐一判断）

**🔴 必须逐岗位分别分析，禁止"四个岗位均非主营业务岗位"式批量结论。**

对每个派遣岗位按以下顺序独立判断：

**临时性**：存续时间≤6个月，超6个月即违规
**辅助性**（分两步，不得混同）：
  1. **民主程序判断**：是否经职工代表大会/全体职工讨论+公示？——客户已自认"没走过民主程序"的，直接认定辅助性不成立，不得标记为"材料缺失待补充"
  2. **实质标准判断**：是否为主营业务外岗位？——主营业务=工商登记经营范围核心项；边缘岗位（如仓库管理员为生产配套服务）应标注"裁审口径存在弹性，需关注本地倾向"
**替代性**：原员工脱产学习/休假/医疗期，须有证据支撑

每岗位三性独立判断，逐一给出合规/不合规/待核结论。详细判断标准和正误示例见 [`references/audit-checklist-reference.md`](references/audit-checklist-reference.md) 第二层。

**法条闸门**：结论前强制检索劳动合同法第66条、暂行规定第4条原文。

### Phase 4 [L3] 比例计算与假外包穿透

**比例计算**：
- 公式：派遣用工比例 = 派遣用工数 ÷ 用工总量 × 100%
- 10%红线：超10%标注🔴高风险，给出整改期限
- 计算须列出：派遣人数/用工总量/计算过程/结果

**🔴 重要——超标罚款争议标注**：
第92条罚款的"每人"基数存在两种实务计算口径：
- 口径A：按全部派遣工人数（更不利于用工单位）
- 口径B：按超标部分人数（派遣工总数 − 用工总量×10%）
报告必须同时展示两种口径的计算结果，标注"实务中存在争议，需关注本地执法倾向"，不得仅取最不利于客户的算法。

**假外包四要素穿透**（任两要素指向派遣则触发）：

| 要素 | 指向外包 | 指向派遣 |
|------|----------|----------|
| 指挥管理权 | 承包方自主管理 | 发包方直接指挥 |
| 计费方式 | 按成果/项目计费 | 按人头/工时计费 |
| 自主经营 | 独立生产工具/场地 | 使用发包方场地设备 |
| 业务关联性 | 非发包方主营业务 | 发包方主营业务环节 |

详细穿透方法见 [`references/audit-checklist-reference.md`](references/audit-checklist-reference.md) 第三层。

**法条闸门**：结论前强制检索劳动合同法第66条、暂行规定第4条。

**🔴 风险合并提示**：Phase 4的"比例超标"与Phase 3的"三性不成立"如均违规，本质上是同一法条（第66条）的两个侧面，合并为一个结构化风险分析，不得拆为两个独立🔴高风险项。

### Phase 5 [L2] 同工同酬与待遇审查

- 薪酬对比：派遣工与同类岗位正式工对比（基本工资+绩效+奖金+津贴）
- 社保缴纳地合规：是否在用工单位所在地缴纳
- 工资支付规范性：是否由派遣单位按月支付
- 福利待遇：是否享受同类岗位福利

**🔴 同工同酬分析不得仅止于"差异X%，需进一步核查"**。发现薪酬差异后必须：
1. 逐项判断四要素（岗位名称/工作内容/技能要求/业绩标准）是否构成"同工"
2. 区分"分配办法不同"（如派遣工适用派遣公司薪酬体系，可能合法）与"分配办法相同但系数不同"（基本不合法）
3. 给出倾向性判断（更可能构成/不构成违反同工同酬）+ 两种方向各自的法律后果

详细审查标准见 [`references/audit-checklist-reference.md`](references/audit-checklist-reference.md) 第四层。

**法条闸门**：结论前强制检索劳动合同法第63条、暂行规定第9条。

### Phase 6 [L2] 协议文件审查

- 派遣协议必备条款对照（暂行规定第7条12项）
- 退回条件合法性审查
- 派遣劳动合同审查（2年以上固定期限/载明派遣信息）
- 协议有效期与许可证有效期对齐

详细审查标准见 [`references/audit-checklist-reference.md`](references/audit-checklist-reference.md) 第五层。

**法条闸门**：结论前强制检索劳动合同法第58-60条、暂行规定第7条。

### Phase 7 [L1] 报告组装与交付

1. **🔴 时效性检查（出具前强制）**：检查审查基准日与报告出具日的时间差——若基准日已过关键节点（许可证到期日、比例整改截止日等），必须以出具日现状重新判断该层结论，不得沿用基准日过期结论。在报告引言中明确标注"审查基准日"与"出具日"两个日期。

2. **🔴 硬阻断——格式确认交互**：展示三个选项暂停等待用户选择
   - A. 生成 DOCX 正式报告（按 `references/output-spec.md` §§A）
   - B. 生成 Markdown 即时预览（按 `references/output-spec.md` §§B）
   - C. 同时生成 DOCX + Markdown

3. 用户选择后按对应规范生成报告

4. 报告九部分结构（强制顺序，采用三段式框架：引言→正文→结尾→附件）：

   **引言**
   1. 引言（含审查基准日/出具日 + 综合风险等级 + 角色识别 + **用工总人数|正式:派遣:外包比例|核心风险一句话总结**）

   **正文**
   2. 主体资格与资质审查（含历史履约审查结果）
   3. 派遣岗位合规性审查（逐岗位三性分析表，禁止批量结论）
   4. 派遣用工比例审查（含两种罚款计算口径）
   5. 劳动报酬与福利待遇审查（含四要素分析+倾向性判断）
   6. 派遣协议及劳动合同审查（含管辖条款利益分析）
   7. 外包用工穿透审查（条件性输出）

   **结尾**
   8. 综合风险评估与建议（含以下四项子内容）：
      - **审查结论汇总表**（9列表格：审查事项/结论/风险等级/核心问题/法条依据/紧迫度/整改方向/计算过程/备注，作为读者30秒速览风险全景的入口，置于第8部分最前面）
      - **风险权重分层排序**：按存亡问题→限期整改→可快速修复三层排序，每层不超过4项
      - **风险传导链分析**：画出"许可证到期→派遣协议失去合法基础→N名派遣工劳动关系归属争议→事实劳动关系认定→追溯性社保补缴+经济补偿金+第92条连带赔偿"等连锁效应链
      - **最坏情况法律后果量化**：叠加所有高风险项的最大法律后果估算
      - **整改方案对比矩阵**：每方案含成本估算/过渡期/法律残留风险三维度 + 最优/次优排序 + "不整改会怎样"对照

   **附件**
   9. 附件（含材料清单 + 审查方法说明）

5. **地方裁审口径检索**（生成报告前强制）：以"用工单位所在省/市 + 劳务派遣 + 三性认定 + 裁审口径"为关键词联网检索，在报告综合评估部分标注受案法院/仲裁委所在地的裁审倾向

6. DOCX 生成方式：按 `references/output-spec.md` §§A 编写 python-docx 代码，调用 [skill:docx] 执行

## 4. SOFT_DEGRADED 降级

**🔴 触发前置条件**：SOFT_DEGRADED 仅在 IG-1 材料缺口追问已完成（即用户已明确回复"跳过"或超时未回复）后触发。未经 IG-1 追问，禁止直接进入 SOFT_DEGRADED 模式。

触发条件与详细定义见 [`references/output-spec.md`](references/output-spec.md) §§C：

| 触发条件 | 降级行为 |
|----------|----------|
| IG-1追问后用户跳过/不补充 | 局部审查 + 缺口清单（标记"待补充"层） |
| 法条无法核验 | 结论标注"待核查"+建议律师复核 |
| [skill:docx] 不可用 | 回退 Markdown 输出 + 提示后续可补生成 DOCX |

降级报告首部必须标注降级级别（C-材料不足/D-核验受限/G-工具不可用）。

## 5. 执业安全红线

1. **不构成法律意见**：报告首部必须声明"本报告为AI辅助初步审查结果，不构成正式法律意见，仅供参考"
2. **禁止绝对化表述**：不得使用"一定违法""必然违规""确保合规"等措辞，使用"存在风险""建议关注""需律师确认"
3. **法条必须核实**：引用法条前必须联网检索原文，不得凭记忆引用
4. **检索空结果≠可以凭记忆引用**：检索返回空结果时，该法条结论必须标注[待核查]，不得照引不误——即使你知道条文内容
5. **比例计算透明**：必须列出计算公式、数据来源、计算过程，不得直接给结论
6. **第92条罚款必须展示两种计算口径**："按全部派遣工人数"和"按超标部分人数"，标注"实务中争议，需关注本地执法倾向"，不得仅取最不利于客户的算法
7. **假外包穿透审慎**：四要素穿透为法律风险提示，非最终定性，建议律师综合判断
8. **整改建议留边界**：整改建议为参考方案，提示"具体整改方案需结合企业实际情况由律师出具"
9. **管辖条款利益分析**：管辖约定不在客户所在地的，不得直接标🟢低风险——必须从客户应诉成本/证据提交/群体性争议风险三个维度分析，至少🟡中风险
10. **风险不得均质化**：禁止将所有问题标为同一风险等级；资质类（许可证到期=存亡问题）> 违法用工类（三性/比例=限期整改）> 合同瑕疵类（协议条款缺失=可快速修复）
11. **自认事实不得标"材料缺失"**：客户已口头/书面确认的事实（如"没走过民主程序"），不得标记为"材料缺失待补充"，应直接依据自认认定
12. **免责声明强制**：报告末尾必须附免责声明
