# 场景四：开启员工自评环节并发放给全员

> **阅读提示：** 本文档为场景四的详细步骤，通用约定见 [`common.md`](common.md)。命中本场景后严格按下列步骤执行，不得跳过、不得自行发明等价命令序列。

## 适用场景与触发话术

- 用户话术示例（含同义表达）：
  - 「帮我开启员工自评环节并发放给全员」
  - 「开启XX方案的员工自评，让全员开始自评」
  - 「把自评环节开起来，全员进入自评」
- 关键词：开启、自评、发放、全员、推进环节、openPlanFlow。

> **「发放给全员」的含义：** `openPlanFlow` 开启环节后，方案下**所有被考核人自动推进到该环节并收到自评任务**，一步到位，无需额外命令。

## 前置信息

| 信息 | 必填 | 说明 |
|------|------|------|
| 方案名称（或方案 ID） | 是 | 用于定位方案（必须为**进行中**） |

> **安全规则提醒：** 开启环节影响方案下全员，执行前必须向用户展示影响面并取得明确确认。

## 执行步骤

**步骤 1 — 定位方案（仅进行中）**

```bash
xrxs-cli appraisal batchQueryPlanInfos --request-body '{"planType":1,"planStatus":1,"planName":"<方案名关键词>"}'
```

- 复用[场景二](sop-scene2.md)步骤 1/2 的定位与候选确认逻辑（最多重试 1 次，搜不到/多个 → 列候选让用户选）。

**步骤 2 — 获取当前可开启的环节列表**

```bash
xrxs-cli appraisal queryCanOpenFlowList --request-body '{"planId":"<planId>"}'
```

- 从返回的**当前可开启**环节列表中定位「员工自评」环节，取对应 `flowId`。
- 该列表只包含当前可开启的环节；若「员工自评」不在其中，**不猜**，按异常分支处理。
- 同一请求体只拉一次。

**步骤 3 — 展示影响面**

```bash
xrxs-cli appraisal getPlanFlowPeopleCount --request-body '{"planId":"<planId>"}'
```

- 展示方案被考核人总数及各环节人数，让用户确认「全员推进到自评环节」的影响面。

**步骤 4 — 执行开启并反馈**

**权限检查（permission check）**：调用正式开启命令 `openPlanFlow` 前，先执行权限检查判断用户是否已授权永久允许执行该命令：

```bash
xrxs-cli permission check appraisal-openPlanFlow
```

- 若返回 `true`，说明用户已授权，可直接调用 `openPlanFlow`。
- 若返回 `false`，说明用户未授权，必须先调用 `openPlanFlowPreview` 展示操作摘要，等用户确认后再调用 `openPlanFlow`。

```bash
xrxs-cli appraisal openPlanFlow --request-body '{"planId":"<planId>","flowId":"<flowId>"}'
```

- 用户确认后执行；命令返回成功即向用户报成功，不复查、不轮询。
- 若报错，如实反馈报错信息，不掩盖。

## 异常分支

| 异常情况 | 处理方式 |
|----------|----------|
| 方案搜不到（进行中） | 最多重试 1 次，仍搜不到列出候选让用户确认；无进行中方案则如实告知 |
| 「员工自评」不在可开启列表 | 如实展示 `queryCanOpenFlowList` 返回的可开启环节，请用户确认（可能环节已开启、或方案状态不允许），不猜 |
| 可开启列表为空 | 如实反馈：当前无可开启环节（方案可能未开始/已终止/环节均已开启），请用户确认方案状态 |
| 执行报错 | 如实反馈报错信息（如方案状态、权限等），不掩盖 |

## 输出模板

```markdown
## 开启员工自评环节 — <方案名称>（<方案ID>）

✅ 已开启：<方案名称> 的「员工自评」环节已开启，方案下全部 N 名被考核人已自动推进到自评环节并收到自评任务。

**影响面**：被考核人共 N 人（开启前各环节人数：<环节名> X 人 / <环节名> Y 人）
```
