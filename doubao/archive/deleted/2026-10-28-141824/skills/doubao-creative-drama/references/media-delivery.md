# 媒体直接交付与产后目录整理

## 适用范围与边界

本门禁适用于 `image_gen`、`image_edit` 的所有成功输出，包括核心资产、KV、候选、草稿、改稿、中间素材和最终图。视频适用于 `text_to_video`、`image_to_video`、`media_to_video`、`video_edit` 及等价视频生成／编辑工具中按主 `SKILL.md` 既有模式、字幕和阶段路由需要向用户展示的成功输出。完整模式资产、状态图、剧情高光关键帧和视频片段阶段继续逐项交付候选、草稿、未采用版本和修订结果；轻量模式与成片阶段仍只交付字幕策略对应的唯一最终视频。内部视频烧录源、裁剪片、拼接中间件和字幕测试样片不因本规则成为额外交付物，不用于排除 `image_gen`／`image_edit` 的成功图片结果。

主 `SKILL.md` 的完整／轻量模式、逐集闭环、字幕擦除／烧录、唯一最终版本、视频确认、工具路由、单轮数量上限、串行批次和受控 subagent 分工保持不变。主 Agent 负责交付与全部画布 CLI；视频生成／编辑和成片媒体变更工具仍按 `delegation.md` 强制委派，图片可由主 Agent 执行或按原边界委派。subagent 只执行锁定任务并回传真实结果，不调用 `present_files`、不自行执行画布 CLI 或整理画布。

音频、剧本、文档、字幕、分镜与按需展示的 Prompt 文件保持原来的直接文件交付规则，不创建画布对象。用户上传、本地剪辑／拼接／字幕擦除／烧录／封装／渲染／导出等非上述工具直接关联的资产，不假称已被工具自动写入；非 Mobile 对既有路由要求上画布的唯一实际交付版本，仍按 [CLI 协议](cli/README.md) 取得有效短链、手工创建和回读，归入产后归档。此边界不能用于把上述工具的原始结果另存一份后重复创建；内部源和中间件不额外展示、创建或归档为最终交付版本。

## 调用前：透传 Workspace ID

每次独立调用、重试、编辑、变体、分集、分段及串行批次中的每项调用，都先核对当前对话中唯一、有效且指向当前目标的原始 Workspace ID，按实际工具契约显式传入；不得只写进 Prompt、参考素材字段或文件名。

非 Mobile 在现有有效规划确认后立即复用当前有效 ID；无 ID 时按主 `SKILL.md` 的原模式和目标范围初始化 Workspace，不提前创建，由 mainagent 将原始 Workspace ID 单独传入 `present_files` 交付新画布卡片，成功后再调用媒体工具。主 Agent 在图片／视频派发包中独立传递 ID 与环境，subagent 逐次核对，回传实际传入值。

Mobile 继续使用原标记 `Device platfrom:Mobile`：已有唯一有效 ID 只作为媒体工具上下文透传；没有 ID 不为补参数创建 Workspace。禁止全部 Canvas CLI、Workspace 操作、画布卡片和目录整理，不以画布能力缺失阻塞生成。

ID 冲突、工具字段不支持、参数名无法确认或校验失败时，停止受影响调用并回报真实错误，不省略已有 ID 降级重试，也不猜测字段或对象 ID。

## 工具成功后：先逐项直接交付

默认非 Mobile 的工具结果通过调用时透传的 Workspace ID 关联画布，不再执行显式媒体 Item 创建。Workspace 关联不等于用户交付、`outputs` 准出或最终版本确认。内部视频源即使由工具自动关联，也不额外展示、创建或归档为最终交付版本。画布 Loading 等状态由媒体工具／平台按实际工具契约维护，不通过主 Agent 重复创建 Item 或回填 `asset.url`／`size` 来结束。图片工具成功返回后，主 Agent 立即按下列输入单项调用 `present_files`，再保存、登记、检查、选图或进入依赖步骤。视频按原模式、字幕和阶段路由确定当前应交付版本，完成原有基础可播放／可渲染检查及必要的非视频生成类字幕擦除／烧录后，主 Agent 立即按下列输入单项调用 `present_files`：

| 产物 | `present_files` 输入 | 交付主体 |
|---|---|---|
| 未发生媒体后处理的视频生成／编辑工具可见输出 | 工具返回的原始视频短链；subagent 原样回传，不改成结果对象或 Item 卡片链接 | 主 Agent |
| `image_gen`／`image_edit` 所有成功图片输出 | 工具返回的原始图片结果对象／句柄，不换成本地副本或短链文本 | 主 Agent |
| 按已确认策略完成擦除／烧录／拼接等媒体处理后的唯一实际交付版本 | 真实处理工具返回的当前视频资源短链；只有本地文件时先上传取得该版本的有效短链，不冒用处理前原始视频短链 | 主 Agent |

一次 `present_files` 只交付一个结果；按原 `current_episode` 和集内稳定顺序逐项交付，不等待同类可见结果全部生成后再集中交付。轻量模式和成片阶段继续只展示一个最终版本；字幕开启时原始无字幕源不额外交付。图片保存、登记和检查在直接交付后继续按原清单规则完成，不得为交付原始图片结果先下载、复制或重传。一次工具调用返回多张图片时，按稳定返回顺序逐项调用 `present_files`，全部直接交付后再检查、选图或进入依赖步骤。视频原有保存、基础媒体检查和必要字幕处理所需的读取继续适用，不作为额外媒体副本交付。

对已通过 Workspace ID 关联画布的视频／图像生成或编辑工具原始结果，不得执行 `+create`／`+create-batch` 创建重复 VIDEO／IMAGE Item，不得为补 `source_ids` 创建副本；不得在直接交付前插入媒体 `+get`；图片不得为直接交付先 `FileBatchUpload`、下载、复制或重新上传，视频不得为重复登记而下载、复制或重新上传。视频基础可交付检查及必要字幕处理所需的读取、保存不属于重复登记。非直接关联的实际媒体后处理版本按上表取得本版本短链，不冒用处理前短链。聊天短链、工具预览、缩略图、Markdown、本地路径或画布可能存在的对象均不能代替 `present_files`。

工具成功返回的图片结果即使审美不佳、错字、身份漂移或预计需要返工，也先直接 `present_files`，不得静默丢弃或先做修正版。视频按原交付路由完成字幕清理及基础可交付检查后，立即交付当前实际版本，不因审美、口型、连续性或接缝等主观问题延迟展示；内部视频源和唯一最终版本规则继续适用。后续质量处理与是否允许新版本仍遵守原短剧规则，不因本流程添加生成后的自主重生、主观返修或额外用户确认。

按原路由应交付的当前实际视频版本缺少有效短链、图片结果句柄不可用或 `present_files` 失败时，保留真实结果与错误，停止依赖该结果的步骤；不猜测 URL、不把工具预览标为已交付，也不为补交付而重复生成或另建媒体 Item。工具本身失败时不伪造成功产物。

## 完成判据与批次

单项 `present_files` 成功即记录 `delivery_status=delivered`，不等待画布写入或回读。在已有工具结果或操作记录中保存实际 Workspace ID（或明确无 ID）、工具调用／任务 ID、原始视频短链或图片句柄、用途、版本、所属分集／片段／批次及单项交付结果；发生媒体处理时另记来源与当前实际交付版本，不改变既有 manifest schema。工具没有返回真实 Item ID 时，记录句柄等待产后定位，不补造 ID。

所有图片和视频执行继续按 `current_episode` 与集内稳定顺序串行；同一批连续 `1-2` 个 SEG 也必须串行，前一 SEG 完成原有保存、登记、直接交付及下一段必要的真实 FRM 承接后才能派发下一 SEG，不改成视频版的独立任务并行。交付前不执行媒体 `+get`，本轮归档读取不作为串行媒体交付前置条件。当前集、阶段用户确认、下一批生成确认和进入成片拼接确认保持不变，不用目录整理扩张原授权。

媒体交付和目录整理分别记录状态。默认非 Mobile 仍必须完成本轮产后目录整理，二者均完成后才能记为该轮处理全部完成；目录失败只记录归档未完成，不把已经交付的媒体、delivery manifest 或用户确认状态倒退为未交付／blocked，不重复交付、生成或创建。单项媒体已交付不等于阶段 `approved`、`accepted`、`confirmed`；原有阶段、当前集和最终用户确认仍须完成。Mobile 不存在目录整理门槛。

## 产后目录整理

本节仅在非 Mobile 执行，由主 Agent 在本轮应展示的成功媒体全部直接交付后处理；不得抢在任一可见结果直接交付之前。资产／关键帧按当前已规划串行生成轮次汇合，视频按当前已确认的连续 `1-2` 个 SEG 批次汇合，成片只整理当前集字幕策略对应的唯一实际交付版本。后续轮次、批次和分集分别执行同样流程，不能等整部短剧结束后集中补整理。

1. **等待直接交付汇合**：确认本批每项成功结果均已单项 `present_files`，保留失败项的真实状态。目录读取与更新不能替代或延迟交付。
2. **定位真实对象**：用 `+tree --path /` 查看骨架，必要时 `+ls` 展开候选分支。根据真实工具返回的 Item ID、原始结果句柄、资产短链、Workspace 和任务记录缩小范围；不得仅凭标题或时间猜测。无法唯一映射时记录目录未完成并排查，不补建 VIDEO／IMAGE Item。
3. **读取实际内容**：分批调用 `design-cli design-workspace +get`，每批最多 10 个 ID。核对 ID、type、title、brief、asset URL、现有 path 及可用来源关系；不以 `+get-workspace` 代替对象读取。这里的 `+get` 是产后归档，不是交付准出或二次交付。
4. **形成最小目录计划**：只整理本批产物及与其关系明确的锚点，保留既有项目沙箱、`episodes/ep_N/` 与 `episode_segment_index`／`SEGxxx` 映射。画布顶层路径使用绝对 path，可按项目语义组织为：
   - 用户输入参考：`/user-anchors/<project>/source`
   - 人物／场景／道具／状态等身份母版：`/core-assets/<project>/<identity>/master`
   - 当前集生成资产与剧情高光关键帧：`/generated-assets/<project>/<ep_N>/<assets-or-keyframes>/<version>`
   - 当前集工具生成视频片段：`/generated-assets/<project>/<ep_N>/segments/<SEGxxx>/<version>`
   - 当前集字幕策略对应的唯一最终成片：`/deliverables/<project>/<ep_N>/<version>`
5. **仅更新 path**：使用 `+update`／`+update-batch` 修改真实顶层对象的绝对 `path`；目录由 path 自动形成，没有独立 `mkdir`。不修改准确 brief，不改内容、标题、资产 URL、尺寸、位置、来源或类型；Frame 成员不单独填 path。禁止空 Item 充当目录，禁止为生成结果重复创建或重传，禁止用 `source_ids` 补写／覆盖血缘。
6. **回读核验**：用 `+tree`／`+ls` 检查目录，再按需 `+get` 核对已移动对象，确认 ID、内容、资产 URL、来源、transform、z-index 和类型未改变。失败即停止继续移动，保留已知状态与未完成归档记录，只恢复未完成的目录操作，不重新生成、交付或创建对象。

非直接关联工具产出的唯一实际交付视频，确需手工上画布时，由主 Agent 在直接交付后按 CLI 协议登记一次并回读，再进入上述目录整理；必须使用当前处理后版本，禁止借登记创建内部母版或其他最终版本。完成后把真实 Item ID、最终 path 与目录核验结果回填已有项目／资产记录，不另建重复索引，不把归档状态写入 `delivery_manifest.status` 取代其原有可交付状态枚举。产后读取或目录能力缺失不反向推翻单项交付成功，也不授权跳过后续仍需的阶段确认或下一批生成确认。
