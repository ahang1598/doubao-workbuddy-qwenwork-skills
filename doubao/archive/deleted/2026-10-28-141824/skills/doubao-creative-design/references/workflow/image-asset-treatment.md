# 图片处理与采用版本

本规范消费已确定的 AI + Coding 路线，不改变品类路由、用户授权或媒体交付门禁。图片用途来自同一 Brief；生产参数和结果沿用 [素材清单](../../example/asset-manifest.md) 的当前字段，CSS、DOM 几何留在最终 HTML，不另建并行清单。

## 先判断用途，再决定处理

实际查看新生成、编辑、用户提供和复用的图片。按每个使用位置区分：完整场景／照片窗、有意保留纸底的图窗、独立透明主体。同图不同用途分别判断，记录背景承担的作用及采用结果；不能只写“按需处理”，也不能为迁就意外白底把已确定的独立主体改成卡片。

| 方法 | 解决的问题 | 边界 |
| --- | --- | --- |
| 裁切 | 调整构图、画幅比例和取景范围 | 不会去掉主体周围背景；不得非等比拉伸主体来适配画幅 |
| 蒙版 | 控制可见区域，形成照片窗、局部遮挡或已规划的渐隐 | 矩形、圆形等规则蒙版不等于沿主体轮廓抠图；边缘羽化不能冒充去底或掩盖残底 |
| 混合模式 | 让纹理、光效、色彩与底图融合 | 不等于真实透明，可能改变品牌色和商品颜色；须在实际背景上检查结果 |
| 真实抠图 | 沿主体轮廓生成透明区域，供独立叠放 | 需检查有效透明、边缘、孔洞、半透明部分及残留底色；已有合格透明结果不重复处理 |

按使用位置先确定设计职责，再选择必要操作，处理步骤可以组合，不做四选一。例如照片窗可以保留背景后裁切并加圆形蒙版；独立商品可抠图后等比缩放或安全裁切；纸纹可裁切后混合；人物与文字穿插可使用透明主体配合局部蒙版。这些是使用示例，不是强制配方。跨色块或独立定位的完整图窗不因此必须抠图；主体需要脱离原背景穿插或在多个背景复用时，使用已有合格透明结果，或实际去底后使用。

- 场景、照片、平稿、背景和一体化 Hero 的背景具有叙事或构图职责时保留，不强制拆层。
- 意外矩形底与页面冲突时，返回既定用途修正素材；不临时补白框、描边或纸片来解释处理失败。
- 通用混合模式用于画面融合，不能证明图片具有透明区域。人物、商品、Logo 和多色插画不得靠混合模式冒充透明素材；需要保护的品牌色、商品色不得发生未经授权的变化。独立艺术标题采用纯白底 `multiply` 或纯黑底 `screen` 时，另遵循现有艺术标题准入及已知稳定背景条件；该专项条件不扩展为对纹理、光效等用途的限制。
- 抠图失败先修正分割或采用真实透明源，不自动重画人物、商品、Logo、包装或 IP。扩图、修补、换场景仍按既有身份保护及编辑授权执行。

## 按实际用途检查结果

仅检查实际采用的操作与目标，不要求所有图片都做 Alpha 检测：

- 裁切：核对主体、文字与保护区域是否误裁，以及最终比例和取景。
- 蒙版：核对显隐范围、遮挡顺序、边界及渐隐是否符合设计。
- 混合模式：在最终背景与阅读尺度下核对颜色、对比和融合效果；用于保真呈现的品牌、商品尤其检查是否偏色。
- 透明主体：位图检查真实透明数据，SVG 检查背景填充、引用图像及实际渲染，二者均需视觉验边。

声明为透明主体的位图，不能凭纯色底、棋盘格、PNG 扩展名或 alpha 声明通过验收；需检查实际文件是否存在有效透明像素，RGBA 但全为不透明也不合格。无底 SVG 不要求具备 PNG 的 Alpha 通道。

透明主体的自动检测与视觉验边分别记录：像素检测只能证明透明数据存在，不能证明抠图准确。查看浅底、深底和最终背景上的残底、白边／色边、孔洞、毛发、半透明细节、阴影残留与误删；检查证据对应具体文件版本，换图后重查。尚未运行检测或未查看预览时如实记为未验证，不把手填通过当成脚本检测。

## 采用结果与最终使用位置

当前清单每项只支持一个 `output`，按 [素材清单的采用版本记录](../../example/asset-manifest.md#采用版本与来源记录) 执行：同一结果供多个位置使用时共享一项；同一源图产生不同采用结果时分项，各自有独立 `asset_id`、`output` 和 `consumers`。处理来源通过 `reference_inputs` 回指可核验的源记录或真实源地址，源图、未采用候选、处理步骤和检查证据记入 `postprocess`，不覆盖历史结果，不虚构使用位置来容纳未采用版本。每个实际使用位置明确采用哪一结果，并分别检查裁切、背景、大小与遮挡。

生成前只记录用途、处理计划与准出条件，不预填不存在的输出或检查通过。源图返回后立即保存真实地址与待检查状态，再完成必要处理、采用记录与素材检查；完整 HTML 出现后才核验实际引用及最终背景。已有合格图片复用不触发重复生成或抠图。

素材阶段核验文件和就绪条件；完整 HTML 形成后再对照实际图片地址与采用记录，不能用清单声明代替 HTML 引用检查，也不能在 HTML 尚未产生时声称完成此项验收。换源或更换处理版本时，重新检查受影响位置及其边缘、蒙版、光影和接缝；不无差别替换同 URL 的全部用途。

## 衔接效果按设计职责采用

自然落底可以不加效果。描边、承托、阴影和穿插用于已确定的识别、空间或图文关系，不为透明素材统一加白边、发光或重阴影，也不固定要求每类效果的数量。

- `box-shadow` 跟随矩形盒子，适用于有意图的图窗或纸片；主体轮廓投影使用 Alpha 感知的 `drop-shadow` 或已验证的轮廓层。
- 矩形虚线边框不是主体虚线轮廓；后者需要真实轮廓路径或预处理轮廓层。
- 效果不能掩盖残边、误删或改变受保护身份。核对最终尺度、光向和对比；复杂效果无法可靠实现时返回设计选择简化，不虚称已实现。

实际处理、生成与 HTML 实现的操作边界见 [后处理与组装操作矩阵](../style/coding/ai-coding/asset-prompt-guide.md#22-后处理与组装操作矩阵)。
