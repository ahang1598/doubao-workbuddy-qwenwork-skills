# 媒体直接交付与产后目录整理

## 适用范围与边界

适用于 `text_to_video`、`image_to_video`、`media_to_video`、`video_edit` 及等价视频生成／编辑工具，以及 `image_gen`／`image_edit` 的所有成功输出。覆盖候选、草稿、改稿、中间素材、四宫格视觉关键帧、视频片段、变体和最终工具成品；画面质量不改变直接交付要求。

主 `SKILL.md` 的视频确认、工具路由、单轮数量上限、固定批次和异步 subagent 分工保持不变。mainagent 负责交付与全部画布 CLI，subagent 只执行已授权的视频生成／编辑并回传原始结果信息，不调用 `present_files`、不写入或整理画布。

音频、文档、字幕、分镜与按需展示的 Prompt 文件保持原来的直接文件交付规则。用户上传、本地剪辑／拼接／封装／渲染／导出等非上述工具直接关联的资产，不假称已被工具自动写入；确需手工入画布时仍按 [CLI 协议](cli/README.md) 取得有效短链、创建和回读。此边界不能用于把上述工具的原始结果另存一份后重复创建。

## 调用前：透传 Workspace ID

每次独立调用、重试、编辑、变体、长视频片段及并行批次中的每项调用，都先核对当前对话中唯一、有效且指向当前目标的原始 Workspace ID，按实际工具契约显式传入；不得只写进 Prompt、参考素材字段或文件名。

非 Mobile 在现有执行确认完成后复用当前有效 ID；无 ID 时先按主 `SKILL.md` 创建 Workspace，由 mainagent 将原始 Workspace ID 单独传入 `present_files` 交付新画布卡片，成功后再调用媒体工具。mainagent 在视频派发包中独立传递 ID 与环境，subagent 逐次核对，回传实际传入值。

Mobile 继续使用原标记 `Device platfrom:Mobile`：已有唯一有效 ID 只作为媒体工具上下文透传；没有 ID 不为补参数创建 Workspace。禁止全部 Canvas CLI、Workspace 操作、画布卡片和目录整理，不以画布能力缺失阻塞生成。

ID 冲突、工具字段不支持、参数名无法确认或校验失败时，停止受影响调用并回报真实错误，不省略已有 ID 降级重试，也不猜测字段或对象 ID。

## 工具成功后：先逐项直接交付

默认非 Mobile 的工具结果通过调用时透传的 Workspace ID 关联画布，不再执行显式媒体 Item 创建。每个成功结果就绪后，mainagent 立即按下列输入单项调用 `present_files`：

| 产物 | `present_files` 输入 | 交付主体 |
|---|---|---|
| 视频生成／编辑工具输出 | 工具返回的原始视频短链；subagent 原样回传，不改成结果对象或 Item 卡片链接 | mainagent |
| `image_gen`／`image_edit` 图片输出 | 工具返回的原始图片结果对象／句柄，不换成本地副本或短链文本 | mainagent |

一次 `present_files` 只交付一个结果；一次调用返回多个成功结果时，按稳定返回顺序逐项交付，不等待同类结果全部生成后再集中交付。

不得为同一结果执行 `+create`／`+create-batch` 创建 VIDEO／IMAGE Item，不得为补 `source_ids` 创建副本；不得在直接交付前插入媒体 `+get`、`FileBatchUpload`、下载、复制或重新上传。聊天短链、工具预览、缩略图、Markdown、本地路径或画布可能存在的对象均不能代替 `present_files`。

成功结果即使效果不佳、身份漂移或预计需修改，也先直接交付，不静默过滤或先生成修正版。后续质量处理与是否允许新版本仍遵守原视频规则，不因本流程添加生成后的自主重生、主观返修或额外用户确认。

视频成功响应缺少可交付的原始短链、图片结果句柄不可用或 `present_files` 失败时，保留真实结果与错误，停止依赖该结果的步骤；不猜测 URL、不把工具预览标为已交付，也不为补交付而重复生成或另建媒体 Item。工具本身失败时不伪造成功产物。

## 完成判据与批次

单项 `present_files` 成功即记录 `delivery_status=delivered`，不等待画布写入或回读。记录实际 Workspace ID（或明确无 ID）、工具调用／任务 ID、原始视频短链或图片句柄、用途、版本、所属视频／片段／批次及单项交付结果。工具没有返回真实 Item ID 时，记录句柄等待产后定位，不补造 ID。

串行依赖只在当前结果直接交付成功后继续；并行只执行原规则已确认且互不依赖的固定批次，每项先直接交付，整批交付状态汇合后再继续。原有每批视频最多 2 个、阶段确认和下一批生成确认保持不变，不用目录整理扩张原授权。

媒体交付和目录整理分别记录状态。默认非 Mobile 仍必须完成本轮已确认批次的产后目录整理，二者均完成后才能记为该批处理全部完成；目录失败不撤销已成功的媒体交付，不重复交付、生成或创建。Mobile 不存在目录整理门槛。

## 产后目录整理

本节仅在非 Mobile 执行，由 mainagent 在本轮已确认固定批次的所有成功工具结果完成直接交付后处理；不得抢在任一结果直接交付之前。后续新批次独立执行同样流程，不能等整个长视频项目结束后集中补整理。

1. **等待直接交付汇合**：确认本批每项成功结果均已单项 `present_files`，保留失败项的真实状态。目录读取与更新不能替代或延迟交付。
2. **定位真实对象**：用 `+tree --path /` 查看骨架，必要时 `+ls` 展开候选分支。根据真实工具返回的 Item ID、原始结果句柄、资产短链、Workspace 和任务记录缩小范围；不得仅凭标题或时间猜测。无法唯一映射时记录目录未完成并排查，不补建 VIDEO／IMAGE Item。
3. **读取实际内容**：分批调用 `design-cli design-workspace +get`，每批最多 10 个 ID。核对 ID、type、title、brief、asset URL、现有 path 及可用来源关系；不以 `+get-workspace` 代替对象读取。这里的 `+get` 是产后归档，不是交付准出或二次交付。
4. **形成最小目录计划**：只整理本批产物及与其关系明确的锚点，保留既有项目沙箱与 `video_N`／`SEGxx` 映射。画布顶层路径使用绝对 path，可按项目语义组织为：
   - 用户输入参考：`/user-anchors/<project>/source`
   - 人物／产品／Logo 等身份母版：`/core-assets/<identity>/master`
   - 生成图片与四宫格关键帧：`/generated-assets/<project>/<video_N>/keyframes/<version>`
   - 工具生成视频片段：`/generated-assets/<project>/<video_N>/segments/<SEGxx>/<version>`
   - 工具生成最终成片：`/deliverables/<project>/<video_N>/<version>`
5. **仅更新 path**：使用 `+update`／`+update-batch` 修改真实顶层对象的绝对 `path`；目录由 path 自动形成，没有独立 `mkdir`。不修改准确 brief，不改内容、标题、资产 URL、尺寸、位置、来源或类型；Frame 成员不单独填 path。禁止空 Item 充当目录，禁止为生成结果重复创建或重传，禁止用 `source_ids` 补写／覆盖血缘。
6. **回读核验**：用 `+tree`／`+ls` 检查目录，再按需 `+get` 核对已移动对象，确认 ID、内容、资产 URL、来源、transform、z-index 和类型未改变。失败即停止继续移动，保留已知状态与未完成归档记录，只恢复未完成的目录操作，不重新生成、交付或创建对象。

完成后把真实 Item ID、最终 path 与目录核验结果回填已有项目／资产记录，不另建重复索引。产后读取或目录能力缺失不反向推翻单项交付成功，也不授权跳过后续仍需的阶段确认或下一批生成确认。
