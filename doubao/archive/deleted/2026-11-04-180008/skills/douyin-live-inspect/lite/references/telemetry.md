# Lite 遥测运行约束

遵守 [公共遥测约束](../../references/telemetry.md)。命令、后台任务和报告交付的遥测由运行时自动处理，不手工发送漏斗快照或生命周期事件。

- 创建、重试、恢复和续办沿用原任务目录，批量视频沿用原批次目录。保留入口返回的执行环境，不修改任务标识或本地遥测标记。
- 命令成功、阶段结束和报告已交付是不同状态。报告未就绪时按业务回执等待或恢复，不以遥测事件判断工作流完成。
- 按报告流程实际交付后执行原有交付确认。恢复任务或报告内容变化后，旧回执不能证明当前报告已交付；重新获取当前报告并确认交付，不沿用旧版本回执。恢复完成后即使报告内容未变化，也须重新交付；旧安装生成的无轮次回执同样需要重新导出。
- 直播按业务指引完成质检和复盘结果交付；批次需要核对全部预期视频，不能用一个子视频的成功代替整个批次完成。终态失败需交付失败原因并按业务回执确认，不能标为报告成功。
- 用户主动要求停止时执行普通停止流程；来源停播或断流不能当作用户主动停止。按业务回执完成收尾，不为产生结束事件强行结束任务。
- 旧任务缺遥测记录或线上缺事件时不补报、不重跑。遥测失败不影响质检、报告和交付流程。


新版完整流程沿用父入口 execution_env 和同一个任务/批次目录。现有质检、复盘宿主交付回执自动汇入 `workflow.snapshot`，无需额外执行正式版交付脚本。直播复盘 `insufficient` 是内容不足，不能因说明已经展示而记为工作流成功；明确采集/判定/复盘/交付失败记录已观察原因，缺回执及未结束状态保持未知。批次取全部预期子项，子项不另计使用 Skill 的流程分母。旧任务没有新版入口则不补建流程。

报告生成与交付独立续办；自动恢复和有限重试沿用原流程、任务及证据版本，不新建统计分母。暂时无法交付保留待交付/未知，不伪造回执；重试耗尽保留原阶段与原因，内容不足仍不计成功。用户明确取消整个流程后不继续自动重试。

非必要导出/线上保存受阻时保留已生成正文，按交付参考降级继续。跳过 HTML 或改用本地报告不等于线上保存成功；沿用原流程和任务，保留原错误及缺失回执，禁止为了统计成功跳过实际交付确认。

`OUT_OF_MEMORY` 表示已观察到明确内存不足证据。说明失败阶段与原任务仍保存的结果，释放资源后沿原任务恢复，不盲目反复重启或把未知上传重复提交。不能仅凭 SIGKILL/137 推断内存不足；没有可核验证据时保持未知。遥测由运行时自动发送，不手工补造事件或上传原始错误、转储及业务正文。

## 兼容与内容不足归因补充

Python 3.10 缺少 SQLite 错误常量时仍保留普通存储异常诊断；只有明确内存错误证据才归 OUT_OF_MEMORY。复盘 blocked 且任务快照明确为 recap / insufficient 时，交付内容不足说明前后均保持内容不足和原原因，failed 说明回执不表示技术故障，也不算有效复盘交付。后续真实失败或有效报告恢复仍按当前任务证据更新。

质检与复盘的生成状态由现有任务快照自动记录；实际交付继续使用原回执，内容不足说明不确认有效报告交付。
