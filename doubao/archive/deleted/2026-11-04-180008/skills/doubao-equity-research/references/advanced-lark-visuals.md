## 共同原则

先写清图形要回答的决策问题，再选择表达。实质性单股股价分析优先取得 OHLC 并使用 K 线；仅有可靠收盘价或分时价时使用股价图。其他图形按信息关系选择。图表不扩大研究范围，也不替代事实校验。

- 每张图只回答一个主要问题，并在图前用一句话说明“为什么看这张图”；
- 图后用一至三句写出观察结果、反证和限制，关键结论不能只存在于图内；
- 标明证券、期间、信息截止日、币种、单位、复权/会计口径和来源；
- 颜色承载稳定语义，不作为唯一编码；涨跌配色应与市场惯例一致并显示图例；
- 图形精度不得高于数据精度。作者打分、标准化值和模型输出必须明示方法；
- 表格或段落更清楚时不生成 HTML；不要为了“高级”重复同一信息；
- 只使用本技能已有脚本生成 HTML，不手写图表或临时兜底页面；
- 生成的 `.html` 只作为飞书 HTML block 的中间载荷，必须实际写入目标飞书文档并拉取复核，不得直接交付文件、源码、本地路径或下载链接；
- 生成器未覆盖所需关系时，改用表格、段落或省略，不另造视觉格式。

每个章节通常只有一个主视觉。新增第二张图前必须写出它回答的不同问题；若问题相同，保留信息密度最高的一张。图表数量没有配额，零张也可以。

首次使用或修改后运行：

```bash
python3 "$EQUITY_RESEARCH_SKILL_DIR/scripts/lark_visuals.py" --self-test
python3 "$EQUITY_RESEARCH_SKILL_DIR/scripts/lark_charts.py" --self-test
```

## 股价与分时

### 何时使用

使用股价图回答价格水平、分时路径、收盘价趋势、均价偏离或成交量变化，但现有输入没有完整可靠 OHLC，或 K 线会降低可读性。典型场景包括：

- 分时价格、均价线和成交量；
- 只有可靠收盘价的多日价格路径；
- 用户明确需要直观价格折线而非蜡烛图；
- K 线数据门禁不满足，但价格趋势仍会改变判断。

不要用股价折线替代本应展示盘中振幅、跳空、影线或开收关系的 K 线。只有一个价格点时直接写数字。

复制 `assets/chart-templates/price-chart.template.json`，替换全部示例数据、证券信息、口径和来源，再运行：

```bash
python3 "$EQUITY_RESEARCH_SKILL_DIR/scripts/lark_visuals.py" \
  price price-chart.json --output price-chart.html
```

输入支持 `time`/`date`、`close`、可选 `average`、`volume`、事件、昨收/基准价、涨跌配色以及 `terminal-light`/`terminal-dark` 两套专业交易终端风格。若只有收盘价，`adjustment` 仍必须明确不复权/前复权/后复权/总回报。

## K 线

只要任务对单只股票进行价格路径、涨跌归因、量价或事件窗口分析，默认使用 K 线。以下场景尤其需要：

- 跳空、盘中振幅、长上下影、波动聚集等仅靠收盘价看不出的信息；
- 成交量与价格形态的关系；
- 财报、公告或监管事件前后的交易路径；
- 用户明确要求 K 线或技术路径复盘。

只有以下理由可判定 K 线不适用：

- 用户明确要求纯文本、Markdown 或不要图；
- 只问单一价格、单一收益数字、日期或计算口径；
- 缺少可核验的完整同口径 OHLC；
- 多证券筛选、组合或横向比较中，逐只 K 线会稀释重点；
- 公司行动、停牌、制度或数据断点无法可靠处理；
- 价格路径与用户的实际判断无关。

每根 K 线必须具备同一证券、交易时区、频率和复权口径下的 `date/open/high/low/close`。交易日严格升序且不重复。只有收盘价时不得猜测开高低，改用 `price`。

按 `script-usage.md` 运行 `lark_visuals.py kline`。生成器产出自包含 HTML，包含响应式 K 线、成交量、悬停明细、区间摘要、可选均线和显式涨跌图例。

文档按以下顺序装配：

1. 图前结论句：说明观察窗口和读图目的；
2. HTML block：按线上最新版 `lark-doc` 流程写入生成的 `.html`；
3. 图后解释：指出价格事实、相对基准、事件一致性与不能确认的归因；
4. 必要的事件窗口表：提供可复算数值，不让读者只能目测图形。

## 趋势

用于 1–5 组可比时间序列，如收入/利润、KPI、盈利预期、估值倍数或 A/H 折溢价历史。序列必须使用相同期间、单位和口径；量纲不同不得强行共用单轴。若只有一两个数字或读者需要精确查数，用小表。

按 `script-usage.md` 运行 `lark_charts.py trend`，输出响应式 HTML 趋势图。正文只解释拐点、差异和与判断相关的变化，不逐点复述。

## 瀑布

用于从明确起点桥接到终点，如收入到利润、上期到本期利润、旧指引到新指引、企业价值到股权价值。每个桥接项必须可复算，正负方向一致，终点必须等于起点加全部变化。

按 `script-usage.md` 运行 `lark_charts.py waterfall`，输出响应式 HTML 瀑布图。若桥接项含大量小项，先聚合到会改变判断的驱动。

## 热力图

用于两个独立变量形成的敏感性矩阵，如 WACC × 永续增长、价格 × 盈利、汇率 × 毛利率。横纵轴、基准格、单位和不可行区域必须清楚；颜色不能代替数值。

按 `script-usage.md` 运行 `lark_charts.py heatmap`。HTML 提供每格数值、悬停明细和基准格强调。若矩阵很小且无需交互，用飞书表格。

## 时间线

用于事件、催化剂、监管里程碑或信息可得时序。区分事件发生日、首次公开日和可交易日；同日多个事件应聚合或明确层级。

按 `script-usage.md` 运行 `lark_charts.py timeline`，输出响应式 HTML 时间线。只保留会改变预期或验证结论的节点，日历流水账不进入图中。

## 多象限

象限图适合展示对象在两个决策维度上的位置关系，例如同业定位、候选筛选、风险重要性、组合流动性压力或业务竞争位置。不适合展示强时间序列、超过两个核心维度的综合结论，或把不可比指标压成一个神秘分数。

必须满足：

- 定义横轴、纵轴、方向、单位、范围和分割阈值；
- 轴使用原始指标、透明标准化值或有方法说明的评分；
- 分割阈值来自业务门槛、样本中位数、历史分位数或明确假设；
- 点大小只承载一个已说明的第三变量；
- 颜色只区分组别，不同时承担好坏含义；
- 距离接近时不声称显著排名差异，边界附近的点视为敏感项。

按 `script-usage.md` 运行 `lark_visuals.py quadrant`，输出自包含 HTML 象限图。文档同时保留原始数据表或方法附注；图负责位置关系，表格负责精确数值。

## 传导链

仅当结构图明显比段落更快回答问题时使用 `lark_charts.py flow`，适合：

- `行业变量 → 业务量价 → 利润率/现金流 → 预期修正 → 估值`；
- 盈利驱动、价值链、证据树或证伪路径；
- 风险传播、组合暴露或监管影响链。

节点按阅读顺序排列，每个节点只保留一个短标题和必要说明；边只表达输入 JSON 中明确声明的关系。禁止把相关性包装成因果，也不要把整篇报告压缩成一张“总览图”。超过 10 个节点、分支复杂或需要大量精确数值时，改用分节段落和表格。

## 选型速查

| 问题关系 | 首选表达 |
|---|---|
| 单股价格路径、量价和事件窗口 | `price` 或 `kline` HTML |
| 同口径时间序列 | `trend` HTML |
| 起点到终点的可复算桥接 | `waterfall` HTML |
| 两变量敏感性 | `heatmap` HTML |
| 重要事件时序 | `timeline` HTML |
| 两个清晰维度上的对象定位 | `quadrant` HTML |
| 少量节点的传导、价值链或风险路径 | `flow` HTML |
| 少量精确数字或短结构 | 表格或段落 |

## 文档装配与校验

写入前按 `lark-doc-delivery.md` 的线上校验门禁重新读取最新版 `lark-doc`。写入后完成：

1. **数据**：证券、日期、频率、复权、币种、单位、来源和截止日完整；
2. **语义**：标题、轴、节点和编码能独立解释；
3. **渲染**：HTML 无外部依赖、无横向溢出，悬停和响应式尺寸正常；
4. **一致性**：图中数字与正文、表格、事实表一致；
5. **可访问性**：不依赖颜色区分唯一信息，图前后文本足以表达结论；
6. **克制**：删除不改变判断的装饰、重复指标和无解释图形；
7. **独立问题**：每个视觉都有唯一、非空的 `visual_purposes`；
8. **HTML 闭环**：拉取后确认 block 位于目标章节且渲染可用，并设置 `html_block_checks.embedded_in_lark_document=true`、`source_file_not_delivered=true`；
9. **强制飞书交付**：只要生成过本文件涉及的 HTML，就必须实际写入飞书文档并拉取复核；写入受阻时保持未完成，不得降级为直接发送文件或源码。
