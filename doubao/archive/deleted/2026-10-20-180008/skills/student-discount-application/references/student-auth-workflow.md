# 学生认证交互

仅在 `content` 命中 `STUDENT_AUTH_REQUIRED` 稳定锚点且 `errorMsg` 为空时执行。该路由标签由 Skill 内部生成，不从 `structuredContent` 读取。

## 校验

- `content` 包含"抖音账号已绑定，但尚未完成学生认证"或路由表中的兼容锚点；
- 在需要向用户展示二维码时，`content` 文本中包含形如 `` `https://aka.doubaocdn.com/s/xxxx` `` 的二维码图片链接（CDN URL，通常以反引号包裹）。

模型看不到二维码状态或失效时间、quickReplies、deep link，因此不校验这些隐藏字段。需要展示时若文本中缺少二维码链接，以 `{}` 重查一次；仍缺失则停止，不猜测或编造 URL。

## 用户交互

1. 检查当前任务的可见对话与执行历史，判断本次办理是否已经启动过[学信网当前有效学籍核验](chsi-enrollment-verification.md)。
2. 若没有执行记录：
   - 使用[阶段提醒文案](stage-reminders.md)中 `STUDENT_AUTH_REQUIRED` 的学信网过渡文案；
   - 不展示、不缓存当前响应中的二维码链接；
   - 在启动前将本次办理标记为已经执行过学信网流程；
   - 完整执行一次[学信网当前有效学籍核验](chsi-enrollment-verification.md)，将结果归一为"没有查到结果""查到有效结果""查到无效结果"之一；
   - 无论结果如何都在 `finally` 中以 `{}` 调用统一工具；
   - 只按新响应的 `content` 和 `errorMsg` 重新路由，并在任何新阶段或错误文案之前先展示一次学信网结果；
   - 若仍命中 `STUDENT_AUTH_REQUIRED`，严格按"学信网结果 → 本阶段文案 → 从新响应文本提取二维码URL并以markdown图片展示"的顺序输出。
3. 若已有执行记录：
   - 使用阶段提醒文案中的二维码阶段文案；
   - 从 `content` 文本中提取二维码 CDN 链接，在阶段文案后以 markdown 图片格式 `![学生认证二维码](<URL>)` 展示；
   - 提醒用户使用手机亲自完成页面流程；
   - 若页面要求实名认证，先按页面完成实名认证，再继续学生认证；
   - 提醒用户完成后回到豆包明确表示"已完成认证"；
   - 等待用户回复后，再以 `{}` 调用工具查询最新状态。
4. 已有执行记录且本轮没有待展示学信网结果时，不重复展示旧结果。

## 隐私与安全

- 不读取、输入、收集或复述账号、密码、短信验证码、身份证号、人脸信息。
- 不让用户在对话中发送认证材料。
- 不代替用户操作登录、实名、人脸或学信网认证页面。
- 不缓存或重复展示旧二维码链接；不读取 quickReplies 中的 deep link 或 action schema。
- 用户反馈二维码过期或链接不可用时重新调用工具，只展示最新响应中的二维码。

## 后续路由

- `STUDENT_NOT_ELIGIBLE`：按固定阶段文案告知未满足活动资格并结束。
- `BENEFIT_GRANTED` / `BENEFIT_ALREADY_GRANTED`：使用 `content` 可见的权益称谓；有效期不可见时省略。
- `errorMsg` 非空或命中错误锚点：按错误路由处理；工具错误不等于用户认证失败。学信网流程刚执行过的前提下，即使本次路由进入错误分支，仍须**先展示本节学信网结果文案，再输出错误固定文案**（详见 stage-reminders.md 学信网流程结果章节的强制输出顺序要求），学信网结果不允许因后续工具错误被省略。
