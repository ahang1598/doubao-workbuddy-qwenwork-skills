# 视频结果交付与防重复生成门禁

本文件由主 `SKILL.md` 对所有实际视频生成与编辑任务强制读取，只规定视频结果的逐项交付、质量检查顺序、重试边界和下游阻断规则。与主 Skill 或其他业务/工具 ref 中“先筛选后交付”“失败后自动重跑”“攒到最后统一展示”或“调用生成工具后直接结束”等规则冲突时，以本文件为准。

## 核心原则

- 视频工具每返回一个可访问链接、本地路径或可渲染视频资源，即视为一个成功结果。
- 候选视频、草稿视频、改稿视频、中间片段、分段视频、未采用版本和最终视频都属于交付对象；每个成功结果都必须如实、逐项、立即交付，不能因效果差、错字、身份漂移、产品不一致或后续未采用而静默丢弃。
- 主 Agent 必须针对每个成功视频结果单独调用 `present_files`；多个结果不得合并成一次交付，也不得只用文字或裸链接代替。
- 必须先完成当前视频的 `present_files` 交付，再质检、筛选、修复、拼接或进入任何依赖该视频的下游步骤；禁止攒到任务末尾补交。
- “交付重试”只允许复用同一个已生成视频资源重新调用 `present_files`，不得再次调用视频生成工具，不得改变 prompt、模型、参数、seed 或输入素材。
- 一个已成功返回资源的视频生成调用不得因主 Agent 主观判断质量不佳而自动重生。需要重新生成、改稿或换方案时，先说明已交付结果及具体问题，等待用户明确决定。

## 视频画面文字问题

- 生成视频画面出现错字、缺字、伪文字、乱码或字形问题时：先完成该视频交付，再记录具体问题，并明确标记为“有文字问题”。
- 完成标记后停止自主处理：不得连续分析、改写 prompt、调用编辑工具或重新生成。
- 若问题文字是后续拼接或成品必须准确依赖的艺术标题、品牌文字或关键信息，必须暂停依赖该视频的下游组装，不能把错误文字带入成品。
- 等待用户明确决定保留、修改、重生或更换方案后，才能继续。

## 非文字问题

- 身份漂移、产品不一致、结构错误、比例错误、分辨率不足、协议不符或其他非文字问题，不取消质量检查。
- 仍须先交付当前成功视频并记录问题，再按已确认工作流决定是否修复。
- 不得形成自动修复循环：如果现有流程没有用户对修复动作的明确授权，先等待用户决定；即使已有授权，同一结果完成一次修复尝试后仍不合格，也必须再次停下并交付该次结果，不能连续重生。

## 长视频分段

- 单条视频、批量候选、独立版本和长视频的每个 segment 都按独立成功结果逐项交付。
- segment 交付并通过下游可用性检查后，才能用于拼接；不合格 segment 必须阻断拼接，不能自动重跑或用未交付版本替换。
- 视频工具没有返回任何可用资源时，报告该次生成失败并等待用户明确要求重试；不得自动再次调用生成工具。
- 用户明确要求重试时，该重试视为新的生成结果，成功后仍须重新执行完整交付门禁。

## 执行顺序

`视频工具返回结果 -> 对每个成功视频单独调用 present_files -> 记录质量问题 -> 判断是否阻断下游 -> 等待用户决定或继续已获授权的非生成步骤`

一句话原则：视频生成成功就先如实交付；展示失败只重试同一视频资源，不能重新生成；视频画面文字错误不擅自修复，不合格视频不得静默进入下游。
