# 布局、碰撞与层级

方向签只计入整体不可见的点或集合卡：任意实际图标、落点、名称或卡片正文仍有部分露出，就不计数；装饰引线不算可见内容。完全移出视野或被面板完全遮挡才计数，列表、数量和取景使用同一去重 ID 集合。点击后的验收比计数更严格：按列表栏实测位置取景，目标需可读、可点击；有限修正后仍不可见应提示收起面板，不能因为还有方向签就判定定位成功。面板参与取景避让，不参与业务 marker 碰撞。

模型只表达意图，Compiler 生成确定策略，Runtime 执行组件库算法。

## 默认碰撞策略

当前 View 的元素参与布局。页面标题、侧栏、底部面板属于 UI 层，不进入地图元素碰撞。路线实际绘制路径可参与固定障碍，区域填充和边界不参与；锚点允许压盖，名称标签仍避让自己的图标和固定路线。

连续热力图和蜂窝热力图是分析底层，不进入标签碰撞，也不能遮挡普通 Marker、路线和文字。地图控件与图例属于最高 UI 覆盖层；视野适配通过运行时测量为它们保留安全边距，而不是移动业务几何。

地图内容容器建立独立堆叠上下文；不能靠不断增大浮层 z-index 与 SDK 内部竞争。默认全览在控件布局后执行，切换 View 会取消待执行 fit；稳定性等待包含待执行 fit。底部图例按高度保留 bottom，不能把横跨地图的图例宽度算作 left。Runtime 统一测量地图内 UI，但按用途分别消费：内容面板 blocksLabels:false，只参与取景、指针遮挡和 UI 摆放；控件、图例与版权按各自保留区参与标签避让。方向签只做 UI 局部避让，不进入 marker 碰撞或取景保留区；地图外侧栏与页头不重复占位。视野留白保护不能替代真实包络的后置验证，安全空间不足时明确降级或失败。

路线箭头与居中锚点共用业务终点时不属于碰撞位移：Compiler 保留相同经纬度，只按终点组件外径为箭头设置 `endInset`；Renderer 沿路线末段向内收缩箭头尖端。编号点使用 13.5px，通用途经点使用 6px，均包含描边和 1px 视觉间隙；非居中 pin 不自动内缩。

默认流程是在同一次候选搜索中先尝试原位置，再尝试偏移；失败后才按组件能力降级。完整实体默认不能隐藏。标签等辅助部分只有组件声明 hideable 且策略允许时才可隐藏。

默认碰撞优先级从高到低为：起终点、路线节点、普通 POI、集合卡片、路线标签、路线本体和区域。选中态不参与基础偏移求解：Runtime 保留选中前的整体 offset 和部件 offset，再用固定偏移检查选中形态。如果选中形态变大并与邻居冲突，只允许非选中邻居按现有策略降级（如收起标签），不尝试新的偏移候选。取消选中后恢复基础布局。Z-index 仍使用相同语义顺序，选中只能在几何类别内部提层，路线不能越过点或 UI。

布局预算与偏移上限以配对 Catalog 的 `layoutDefaults.budget` 为准，不从示例复制另一套默认值。当前锁定 Catalog 的累计计算预算为 500ms，不包括调度等待，也不是单帧或整个生成任务耗时保证。优先尝试上一轮的稳定候选；点组件的 `labelOffset` 表示相对地理锚点的最终目标位置，不能在重排时再次当作增量累加。

多路线选中使用系列聚焦，不改变路线坐标或基础碰撞偏移：选中系列保持完整不透明并提高绘制层级，未选中系列降低到 0.18～0.3；其它系列的路线标签可隐藏，共享节点保持中性显示。只有一条可见路线时仍可查看详情，但不启用路线间比较聚焦。取消选择必须恢复路线、标签、侧栏和图例。路线、路线标签、图例和侧栏只能引用同一个 `seriesId`，不能分别保存颜色、线宽和虚线。

## Presentation Plan 示例

```json
{
  "layoutIntent": {
    "preset": "offset-only",
    "selectedBy": "user",
    "reason": "用户明确要求保留全部标签，只进行偏移"
  },
  "stackingOverrides": [
    {
      "selector": { "semanticRole": "route-node" },
      "collisionPriority": {
        "relativeTo": "endpoint",
        "placement": "below",
        "delta": 50
      },
      "selectedBy": "user"
    }
  ]
}
```

允许隐藏完整实体时必须同时满足：用户明确要求、selectedBy 为 user、entityHideSelectors 非空。Compiler 对不满足条件的请求报错。

Compiler 会把 selector 解析为当前 View 内具体的 `entityHideIds`，Runtime 只接收 ID 白名单。没有进入该白名单的组件即使发生无法解决的碰撞，也只能保留必要重叠或报错，不能整体消失。

未找到无冲突位置时按 onUnresolved 处理，默认保留必要重叠并报告，不静默丢失实体。预算未完成的 `budget-pending` 与无空间不同；累计计算超预算的 `budget-exceeded` 必须失败，不能按保留重叠伪装为布局完成。验收须等待当前布局 revision 完成。

Runtime 对每个 View 先设置该 View 的 `layoutPolicy`，再提交带 `collisionPriority` 与 `zIndex` 的元素。切换 View、`zoomend` 和 `resize` 会重新求解基础布局；选中元素只在固定基础偏移上运行降级检查。连续缩放过程只重投影现有结果，不触发 fit 或引入其他 View。
