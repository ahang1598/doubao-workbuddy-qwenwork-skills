# 商务与项目合同、协议：需求判断与生成规则

- **工作主线**：1. 确认本指南是否适用并明确分析问题 → 2. 完整读取材料并确认事实边界 → 3. 进行内容规划 → 4. 按要求选择具体排版格式 → 5. 完成交付前逐项检查。

- **路由条件**:主任务是建立、表达、填写或修改交易关系、权责交换、合同条款或履约责任。仍在比较商业方向、申请资源、进行市场研究或规划项目交付而未形成权利义务条款时不命中。不命中时返回 [`Word 写作分类指导`](writing-taxonomy.md) 重新判断。
只有 [`Word 写作分类指导`](writing-taxonomy.md) 已经选择“商务协议与合同”时，才读取本文件。


## 一般流程分支

严格按顺序执行，每一步完成后再进入下一步。

```text
步骤 1：完整阅读用户提供的信息
              │
              ▼
步骤 2：区分文书类型
              │
      ┌───────┴───────┐
      ▼               ▼
   合同              协议/普通约定
      │               │
      ▼               ├── 有用户模板 → 按模板填写 → 进入检查项
步骤 3：确定模板来源   └── 无模板 ──────────┐
      │                                    │
  ┌───┼───┐                                │
  ▼       ▼                                │
  A       B                                │
用户    无模板                              │
模板      │                                 │
  │       │                                 │
  ▼       ▼                                 ▼
按模板填写                  步骤 4：无模板起草
      │                       │
      └───────────┬───────────┘
                  ▼
          文书专项信息 → 共同检查项
```

### 步骤 1：完整阅读用户提供的信息

信息来源的优先级从高到低为：**用户附件 > 联网搜索 > 先验知识**。不得跳过或颠倒。

#### 1.1 用户附件（优先级与权威性最高）

**用户材料是具体事实的基础。**
- 用户上传或提供的一切材料是本次任务的第一手事实来源，优先级高于联网搜索和先验知识。附件中的关键信息常藏在图、表、公式里，仅靠文本提取会丢失；如果之前读取附件时只获得了文本信息或没有读取附件，必须再次解析。
- 用户附件不能只在任务开始时被概括或摘要。开始写作前，必须回到原始附件核对将要采用的细节，避免因早期压缩理解而遗漏限定条件、数据口径、图表信息、例外情况或原文措辞。
- **附件信息处理**：
  - **完整读取**：DOCX、PDF、图片和表格均须读取其文字与视觉信息；图、表、公式、扫描页、批注和嵌入对象中的相关内容不得因初步提取而遗漏。
  - **附件角色**：多附件时，先明确每份材料的用途。模板只决定结构和格式；上下文材料用于理解任务背景；素材和事实材料用于支持具体内容；示例只用于学习结构、粒度或表达。
  - **按问题整合**：不要按附件顺序分别摘要或写作。应围绕同一对象、时间、事项或结论，将分散在不同附件中的相关信息匹配、补全和整合。
  - **冲突处理**：附件信息不一致时，先区分其对象、时间、地区、口径和角色；不能确认时明确保留差异或待确认，不得自行拼接、混算或选择性采用。

#### 1.2 联网搜索

补齐主题相关的真实数据、事实、案例和现行法律法规。不得编造；缺失信息标注为占位、假设或待补，并标注来源。

用户提供的是完整文档或逐页大纲、且未说明能否扩写时，默认联网搜索扩充素材与案例，除非用户明确要求不扩写。

### 步骤 2：区分文书类型

根据步骤 1 获取的信息，判断本次任务的文书类型。这一步决定后续走哪条路径。

- **合同**：以交易、服务、采购、建设、租赁、买卖、合作交付等权利义务交换为核心，通常需要主体、标的、价款或费用、履行、验收、违约、争议解决和生效签署。
- **协议**：范围更宽，可用于框架合作、补充约定、会议达成的一致意见、项目协作安排或对既有合同的补充。协议不等于低规格，但如果没有对应示范模板，通常按新文件起草。
- **普通约定**：简单欠条、收据、熟人借款、低复杂度合作备忘等，只写清真实约定，不机械套长合同。

在内容规划中明确具体类型，例如"采购合同""城镇房屋租赁合同"或"框架合作协议"；不要把"用户模板""正式模板"当成题材。

#### 如果是协议或普通约定

不进入步骤 3，按以下方式处理：

**用户提供了模板**：按用户模板的结构和格式，结合一般规范与步骤 1 获取的完整信息填写。复制模板后原位填写，不得只提取字段后重建相似文件。在内容规划中记录用户模板及其使用原因。必须核验模板中引用的法律名称、条文编号、机构名称、条例、规章、标准和政策文件是否仍为现行有效版本。发现疑似废止、修订、更名或替换时，不得自行替换具有法律效力的表述；应在内容规划或核验清单中记录原文、核验来源、查询日期、疑似替代版本及其影响。只有用户明确授权且已完成必要的专业复核后，才可在不改变模板格式的前提下替换。

**用户未提供模板**：搜索权威网站获取规范指导和范文参考，注意准确性和时效性，不得编造。然后进入步骤 4「无模板起草」完成正文。

处理完成后，直接进入「文书专项信息」和「共同检查项」。

#### 如果是合同

继续进入步骤 3。

### 步骤 3：确定合同模板与内容来源

仅限合同类型。按以下优先级判断，命中即停，不再进入更低优先级的分支。

#### 分支 A：用户提供了模板（优先级最高）

用户明确指定了 Word 模板文件。模板必须存在可填写区域、占位符、表格字段、固定栏目，或用户明确要求"按此模板填写/保持此模板格式"。只有格式参考或内容样例时，不进入此分支，进入分支 B。

处理方式：
1. 严格按照用户模板的结构和格式，结合一般合同规范与步骤 1 获取的完整信息填写；
2. 复制模板后原位填写，不得只提取字段后重建相似文件；
3. 在内容规划中记录用户模板及其使用原因；
4. 必须核验模板中引用的法律名称、条文编号、机构名称、条例、规章、标准和政策文件是否仍为现行有效版本。发现疑似废止、修订、更名或替换时，不得自行替换具有法律效力的表述；应在内容规划或核验清单中记录原文、核验来源、查询日期、疑似替代版本及其影响。只有用户明确授权且已完成必要的专业复核后，才可在不改变模板格式的前提下替换。

#### 分支 B：无可用模板

用户未提供模板。

处理方式：
1. 可检索国家市场监督管理总局合同示范文本库：`https://htsfwb.samr.gov.cn/`。使用合同标的、真实法律关系和交易对象检索，不只搜用户口语名称；比较适用范围、发布机关、版本年份、全国/地方属性和排除条件。存在全国通用版本时默认使用；地方版本仅在用户明确要求地区化且地区一致时才可选；
2. 只从官网详情页下载 Word 版本，并记录标题、发布机关、版本、适用地区、详情页 URL 和下载时间。搜索结果摘要或第三方转载不能作为模板文件。如果官网没有完全匹配的模板，可以选择一份法律关系和交易结构最接近、且已经核验的模板作为参考材料，但不得把它当成填写模板，也不得把其示范身份、地方依据或发布机关带入新合同；
3. 若仍未找到合适模板，进入步骤 4「无模板起草」；
4. 使用一般格式；
5. 在内容规划中说明条款编号、签署区和默认无目录等例外。

### 步骤 4：无模板起草

适用于协议、普通约定或无模板合同的起草。根据真实法律关系保留必要模块：合同/协议主体与资格、背景或鉴于条款（必要时）、标的/合作事项、价税与支付、履行期限地点方式、交付与验收、双方权利义务、变更与解除、违约责任、不可抗力（确有持续履行风险时）、保密/知识产权/数据处理（被交易触发时）、通知送达、争议解决、生效与签署、附件及其效力。

- 条款按"适用条件—主体—动作或标准—期限—不履行后果"写清，避免只有原则没有操作边界。
- 权利义务、交付验收、价款支付和违约责任相互对应；不得把有利于一方的表述伪装成中性默认。
- 法律名称、强制性要求或管辖选择需要核验；无法核验时不编造条文编号，以待确认项提示专业复核。
- 未被交易触发的通用条款不机械加入；附件只有在正文真实引用且用户有相应材料时才建立。
- 输出是待当事人确认的草案，不暗示已经审核、批准、生效或具有官方示范文本身份。

协议没有模板时，正文通常采用"标题 → 当事人 → 鉴于/背景（必要时）→ 条款 → 签署区"。条款较长时使用"第一条、第二条、第三条……"作为主层级；条内再按需要使用"（一）""1."，不得混用"四、"和"4.1"。

Word 格式：标题居中，当事人信息、正文条款、附件和签署区清楚分区；条款编号全文唯一且连续。合同/协议正文较长时优先使用"第一条、第二条……"主层级；默认不设置装饰性封面、目录、彩色标题、标题线或通用页眉；签署区只提供文字与留白，不生成印章、签名或已签署状态。

#### 一般格式要求

- **格式优先级**：本指南关于条款编号、签署区、目录、封面、标题颜色和页眉的明确规定，优先于 [`writing-taxonomy.md`](writing-taxonomy.md) 中“## 一般Word排版格式要求”；未明确规定的格式项目，按该部分执行。用户明确要求、有效模板、组织规范或法定文种要求与本文件或一般格式要求冲突时，按 [`Word 写作分类指导`](writing-taxonomy.md) 中的“格式规则优先级”处理。

- 一般格式要求：除上述明确规定的项目外，必须完整读取[`writing-taxonomy.md`](writing-taxonomy.md) 中“## 一般Word排版格式要求”及“## 交付前回读与校验”；除本指南明确覆盖的项目外，按其中规则执行。


## 文书专项信息

在内容规划中关注：

| 内容 | 关注事项 |
|-|-|
| 文书类型 | 合同、协议或普通约定，以及更具体的交易类型 |
| 法律关系 | 当事人之间实际形成的权利义务关系 |
| 适用范围 | 适用国家/地区及地方模板适用范围；未确定时写入待确认项 |
| 当事人 | 各方身份、角色和签约资格，不在这里复制完整个人信息 |
| 标的 | 标的、服务、项目或合作事项及其范围 |
| 关键条款 | 本任务必须检查的价款/费用、履行、验收、违约、期限、解除和争议处理等条款 |
| 签署要求 | 签署区、附件、生效条件和需要保留的待填字段 |

## 共同检查项

- 不得编造主体身份、授权、标的、金额、税率、账户、日期、许可证、验收结果、违约事实、管辖或签署状态。未知字段使用明确待确认占位，不把推测写成条款事实。
- 所有金额、比例、日期、主体、项目、标的、履行状态和违约事实必须标明来源状态：用户确认、附件可定位、可计算推导、建议条款或待确认。待确认信息不得写成既成事实。
- 控制条款和说明的篇幅时，看每段是否增加了权利义务、交易事实、风险分配、责任、期限、验收或争议处理信息。没有增加这些信息的段落不要扩写，也不得用长篇通用条款掩盖交易事实缺失。
- 使用用户模板时，保留原有编号和样式。其他合同/协议在起草前只选一套层级；不得用字号、加粗或缩进伪装层级。
- 从头到尾检查封面、说明页、正文、表格、附件、签署页、页眉页脚、文本框和内容控件。原位替换主体、地区、项目、标的、金额、日期等所有实例信息，保持全文一致。
- 成稿必须删除仅用于示范发布的"示范文本"等标识、制定/发布机关说明、模板使用说明页和示例填写内容。清理和填充都不得重建 DOCX。
- 使用模板时，必须核验模板中引用的法律名称、条文编号、机构名称、条例、规章、标准和政策文件是否仍为现行有效版本。发现疑似废止、修订、更名或替换时，不得自行替换具有法律效力的表述；应在内容规划或核验清单中记录原文、核验来源、查询日期、疑似替代版本及其影响。只有用户明确授权且已完成必要的专业复核后，才可在不改变模板格式的前提下替换。
- 在内容规划中关注关键事实、附件用途、待确认事项和模板信息。只保留生成和验收必需信息，不写成长篇草稿。
- 交付前先核验本指南规定的合同条款、编号、签署区、附件和模板保真要求；再按 [`writing-taxonomy.md`](writing-taxonomy.md) 中“## 交付前回读与校验”完成通用检查。任何影响条款完整性、签署区、附件、页码、表格或模板保真的问题未解决前，不得交付可签署终稿。
