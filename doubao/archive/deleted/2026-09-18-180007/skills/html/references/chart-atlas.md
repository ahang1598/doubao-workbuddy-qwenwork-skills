# 图表图谱

主 SKILL.md 的 15 类图表清单之外的**扩展、红线、库选型和叙事模式**。做数据可视化任务时按序读。

## 扩展图表类型

对照 SKILL.md 里已有清单不重复，只补高价值遗漏项：

- **弦图 Chord**：闭环多对多流转（贸易流、迁徙、供应链）。比 Sankey 更适合表达"没有起点终点、只有量级和流向"的关系。ECharts / D3 皆可。
- **力导向图 Force-directed**：可交互动态关系网。用户能拖动节点、观察聚簇。适合社交网络、依赖图、生态位——静态关系用 SKILL.md 已有的「关系网络图」即可，需要交互探索时才上力导向。
- **旭日图 Sunburst**：层级 + 占比的组合表达，比 Treemap 更能读出「几层深」。适合分类学、目录结构、预算科目。
- **Treemap 矩形树图**：纯占比 + 层级，读者更关注面积对比而非层数时用它。
- **雷达图 Radar**：**维度 ≤ 6 且共享量纲**（0-100 或相同单位）时用。**>6 维必成蛛网 slop**，改成小倍数条形图。
- **日历热力图 Calendar heatmap**：时间 × 强度，GitHub 贡献格式。习惯追踪、事件密度、季节性。
- **Bump chart**：排名随时间变化。比折线更清晰"名次交换"的瞬间，体育、榜单、市场份额排位常用。
- **Waffle chart 10×10**：百分比人化表达。「100 人里有 23 人」比一个孤零零的 23% 更有力，适合社会议题、健康数据。
- **Slope chart / Dumbbell**：两时间点/两组别的前后对比。三列以上就退化成 bump 或折线。
- **Small multiples 小倍数**：同一图表在不同类别上重复。**堆叠面积、多线折线超过 5 条时的默认答案**——分成 5 张小图胜过一张挤爆的图。Tufte 反复强调过。
- **Ridgeline / Joyplot**：多类别分布对比，类似"山脊"堆叠。人口金字塔的现代版。
- **Beeswarm**：一维散点，避免重叠。分布 + 个体标注共存时比 boxplot 更亲切。
- **Marimekko / Mosaic**：宽度和高度都编码变量的堆叠——市场份额 × 品类销售额矩阵。信息密度极高但学习成本也高，慎用。
- **Parallel coordinates 平行坐标**：多维数据（>4 维）里找异常和聚簇。可交互 brush 时价值最大，静态图基本读不出东西。
- **Stream graph**：随时间变化的多类别占比，居中对称。适合"演进感"强的话题（音乐流派、话题热度），但读精确值不如堆叠面积。

## 图表红线

以下几乎总是错，出现即降低产物可信度：

- **饼图分片 > 5**：读者无法比较角度。>5 类改横向条形（bar chart）按值降序。
- **甜甜圈饼图中间放大数字**：本质是"一个大数字 + 装饰环"，中间数字直接放条形图旁边更诚实。
- **双 Y 轴 dual-axis**：几乎总是误导——两个量纲用视觉重合暗示相关性。改成上下两张对齐时间轴的图。
- **3D 饼图 / 3D 柱状图 / 3D 折线**：3D 扭曲比例，全是 slop。二维数据就用二维图。
- **词云 word cloud**：字号 ≠ 值，长词天然占更大面积。改条形图。
- **雷达图 > 6 维**：变成蛛网，任何两个方案叠上去都难以阅读。
- **面积图从非零基线开始**：面积图的语义就是「面积代表值」，切基线等于骗人。
- **堆叠折线**：折线的斜率语义在堆叠后失效，改堆叠面积或小倍数。
- **超过 7 种类别用颜色区分**：色盲/记忆容量都撑不住。合并成"其他"或改小倍数。
- **无 x 轴标签的时间序列**：从没有过合理理由。
- **柱状图坐标轴不从 0 开始**：视觉上放大微小差异，欺骗性极强（除非明确标注 axis break）。折线可以从非零起，柱状不行。
- **rainbow / jet 色板**：色觉不均匀，感知失真。用 viridis、cividis、magma（perceptually uniform）替换。

## 库选型

- **ECharts**（`echarts`）：默认首选，覆盖 90% 场景，图表配置对象化易维护。SKILL.md 已锁定。**弱项**：force-directed 布局粗糙、chord 不够灵活、深度定制困难。
- **D3.js**（`d3`）：ECharts 做不了或做得难看的场景走 D3——force、chord、custom shape、scrollytelling scrub 里跟随的图表。上手成本高但天花板高。
- **Observable Plot**（`@observablehq/plot`）：D3 的高层封装，声明式 API 类似 ggplot。**快速原型 / 探索性图表 / small multiples** 首选，20 行出图。
- **Chart.js**：只做基础统计图（bar/line/pie），比 ECharts 轻。极简需求时用。**不要用它做定制**——扩展性远不如 D3。
- **Recharts / Nivo / Victory**：React 生态，本 skill 单文件自包含场景基本用不上。
- **Highcharts**：商业授权，除非用户明确要求否则不用。
- **Rough.js**：手绘风格图表。做「工作坊」「策略图」「教学」调性时是唯一选择，比后期加 filter 自然得多。

**判断顺序**：能 ECharts 就 ECharts → ECharts 做不好但属于统计图就 Observable Plot → 需要定制布局或交互就 D3。地图叠大量数据点用 Deck.gl（选型细节见 `visual-techniques.md` 地图段）。

## 数据叙事模式

单张图表只是砖，叙事才是建筑。以下模式把图表编排成故事：

- **Scrollytelling**：滚动驱动图表变化，每一屏聚焦一个论点。长文数据报道的标配。工具选型和编排原则（一屏一论点、主图 pin、数据切换 tween、末态可读）见 `visual-techniques.md` 滚动叙事段。
- **Annotated chart**：在图上直接标"这里是转折点""这段数据缺失原因是 X"，而不是把注解丢到图下 caption。The Economist、FT 是范式。annotation 用一根短线 + 4–8 字标签。
- **Reference band / event marker**：在时间序列上叠一层灰色 band 标"衰退期""疫情期""政策变化点"。历史/经济图表标配。
- **Linked views（brush + zoom）**：多图共享 selection——一张图 brush 出时间段，其他图同步 filter。**数据探索型看板**必备，静态报告用不上。
- **Chart-in-chart / detail-on-demand**：主图俯瞰，hover / click 出小图看局部细节。避免主图信息过载。
- **Sparkline inline**：文字段落里塞小图。"营收从 100 → 150 ↗ [小折线]"，Tufte 原创。信息密度极高。
- **Comparison overlay**：多方案叠一张图 vs 分开小倍数——**默认走小倍数**，只有明确要读者比"交叉/交汇"时才叠。

## 图表 × 排版

图表不是孤立矩形，它属于版面：

- **坐标轴标签**：`tnum`（等宽数字）+ 数字右对齐。ECharts 默认没开。
- **图例位置**：能省则省——直接把系列名写在线的末端（label at end of line），读者眼睛不用来回跳。
- **色板与全站呼应**：图表颜色从 SKILL.md 的整站 palette 派生（oklch 派生），不用 ECharts 默认 10 色轮盘（那套一眼 slop）。
- **网格线**：主网格 `#eeeeee` 或更淡，次网格不要。零轴用主文字色，其他坐标线 30–40% opacity。
- **数据密度优先**：Tufte data-ink ratio——能删掉的边框、背景、装饰性网格全删。
