# 多股票比较的飞书文档交付规范

本文件只规定多股票比较的交付路由、信息结构和组件选择。命令、XML 标签和参数以执行时线上环境中的最新版 `lark-doc` skill 为准。

需要任何图表或图解时，同时读取 `advanced-lark-visuals.md`，逐图选择富表格、HTML block、SVG/Mermaid whiteboard 或段落；不要先决定“做几张图”再寻找内容填充。

## 1. 先设置 delivery_mode

在任何检索、分析、起草或图表生成前，先选择且只选择一个状态：`TEXT` 或 `LARK_DOC`。无法确定时选择 `LARK_DOC`。把选择与理由写入交付清单，并用 `scripts/delivery_gate.py --phase plan` 校验；不要等正文写完后才判断载体。

### `delivery_mode=TEXT`

只有以下四项**全部为真**时才能选择 `TEXT`：

1. 只比较一个明确事实、同口径指标或单一决策问题；
2. 一至三段短文本足以准确回答，省略文档不会损失关键信息；
3. 不需要真实行列数据、结构化比较、情景、时间线、多章节导航、复杂证据链或图示；
4. 不需要且尚未生成任何非 Markdown 高级组件。

例如：A 与 B 谁的同口径毛利率更高、两家公司财年口径有何区别、某一估值倍数如何定义。不要为了形式感创建空洞文档。

`TEXT` 模式禁止生成 HTML block、whiteboard、SVG/Mermaid/PlantUML、分栏、高亮块和富样式表格。若研究中发现任一条件不再成立，或实际生成高级组件，立即单向升级到 `LARK_DOC`。

### `delivery_mode=LARK_DOC`

出现任一情况时必须选择 `LARK_DOC`，并把主要分析写入飞书文档：

- 比较三家以上公司，或两家公司涉及两个以上分析维度；
- 需要两个以上分析章节，或需要在选择结论、证据、不可比项、反证和风险之间导航；
- 存在 KPI 趋势、横向矩阵、情景估值、事件窗口或催化剂日历等真实行列数据；
- 涉及股价路径、涨跌归因、相对强弱、事件反应或其他价格行为分析；此时默认需要 K 线 HTML；
- 对比分栏、表格、HTML block 或 whiteboard 能明显降低理解成本；
- 用户要求一页纸、完整报告、深度研究、可复核引用或可分享交付物；
- 正文很长，直接聊天会淹没核心结论。

全面股票对比、竞品分析、投资二选一、三家以上比较、财报比较、估值比较、组合适配、配对交易、相对投资论点复核、完整报告、可复核引用和可分享交付物默认属于 `LARK_DOC`。用户的 query 很短、没有显式说“写文档”或聊天界面默认渲染 Markdown，均不能推翻这些规则。

用户明确要求纯文本/Markdown 且不允许外部文档时，只有承诺不生成高级组件且文本不会损失问题所需信息，才能使用 `TEXT`；否则先说明载体冲突并请求用户取舍。模式一经选择，不得因为写入耗时、命令复杂、认证或权限问题从 `LARK_DOC` 降级。若失败，保持未完成并报告最小阻塞信息。

### 状态生命周期

`LARK_DOC` 不只是最终输出格式，而是贯穿任务的交付状态：

1. **Plan**：建立交付清单和质量清单，锁定 `delivery_mode` 与文档档位；所有候选图表进入 `visual_plan`，完成格式选择、预算和去重后运行两个计划门禁；
2. **Preflight**：读取线上最新版 `lark-doc`，检查认证/权限和本次所需语法；
3. **Skeleton**：只为通过内容准入门禁的章节创建骨架，先放标题、比较元信息和选择结论；
4. **Build**：只写入质量清单中 `include=true` 的正文和组件；
5. **Verify**：拉取文档，复核结构、证据、重复内容和组件渲染，并完成压缩编辑；
6. **Final**：先通过质量最终门禁，再通过交付最终门禁，之后才返回核心结论与文档链接。

## 2. 写入前的线上校验门禁

每次最终执行 `docs +create`、`docs +update` 或其他文档写入前，必须：

1. 读取当前线上运行环境中可用的最新版 `lark-doc` skill 的 `SKILL.md`，不得用记忆、本文件或打包时的本地版本替代；
2. 按最新版 `lark-doc` 的前置条件，继续完整读取本次创建或编辑所要求的共享规则、XML、样式、创建/更新工作流等引用文件；
3. 计划使用 HTML block 或 whiteboard 时，再读取最新版 skill 指定的扩展块或画板说明；
4. 以线上文档为唯一命令和语法依据。若与本文件示意冲突，线上 `lark-doc` 优先；
5. 先完成事实校验和文档大纲，再写入，避免把未经核验的草稿发布到在线文档。

未完成上述读取时，不得尝试写入。这个门禁每次写文档都执行，不能因为同一会话中曾经用过旧命令就跳过。

### 内容写入门禁

正式起草前读取 `writing-quality.md`，建立质量清单并运行 `editorial_gate.py --phase plan`。不要先写一份长稿再尝试压缩；只有通过准入的章节才能进入文档骨架。低质量内容不得因“已经检索到”“可能有用”或“文档看起来更完整”而写入附录。

## 3. 专业研究文档的信息顺序

默认按读者决策顺序组织，不套固定的“公司简介—行业—财务”模板。核心财务金融快照是股票比较的默认底座；其他部分按相关性保留：

1. **标题与比较元信息**：全部证券名称/代码、市场、信息截止日、比较期间、币种、会计、业务层级和价格口径；
2. **选择结论**：先回答本质差异、什么情景下谁更优，以及不能排名的边界；
3. **核心财务金融快照**：一张紧凑横向表，默认覆盖市场数据、估值和至少两个经营财务类别；不相关时必须有质量清单记录；
4. **胜负驱动**：通常 3–5 条，按改变选择的重要性排序，并指出分别偏向哪家公司；
5. **增量横向矩阵**：只放核心快照未覆盖、但当前问题需要的 KPI、情景或事件数据；不可比项显式标注；
6. **差异机制**：只展开用户问题需要的大盘/板块/外围、供应链与新闻监管、市场位置、商业模式、经营财务、成长、预期、估值或价格行为；
7. **最强反例与翻转条件**：说明什么证据会改变相对排序；
8. **验证点/催化剂**：写清公司、指标、阈值、时间窗和数据来源；
9. **数据来源与方法**：读者可复核即可，证据账本和冗长细节放附录；
10. **免责声明**：完整研究最后保留规定文本。

核心结论必须出现在正文最前部。默认 `standard` 最多 8 个分析章节，但上限不是配额；证据链较少时主动缩短。若使用高亮块，全文通常只把这一处作为唯一重强调；若核心判断不确定，明确写出会限制结论的数据缺口或条件，不用颜色制造虚假的确定感。

## 4. 组件选择矩阵

由信息关系选择组件，不按“每篇都要有”的配额选择。

每个组件还必须通过内容准入测试：若删除后不影响判断或理解，若内容已由其他表格/段落表达，或证据质量不足，就删除该组件。高级样式不是内容质量的替代品。

| 研究内容 | 首选表达 | 适用边界 |
|---|---|---|
| 选择结论、重大不可比提醒、关键数据缺口 | 高亮块 | 仅强提醒；通常 0–1 个，避免每节一个 |
| 公司 A vs B、胜出理由 vs 翻转条件、做多端 vs 对冲端 | 对比分栏 | 仅限两侧信息量接近的短对照；多家公司或多指标改用表格 |
| 默认核心财务金融快照 | 紧凑富表格 | 5–12 个行业适用指标；全部公司同列，日期、期间、币种、单位和口径完整 |
| 横向矩阵、KPI、财务、估值、情景、事件窗口 | 富表格 | 真正行列数据；公司为列或行为一致规则，统一期间、币种、单位和口径 |
| 大盘/板块/外围市场与公司表现 | 富表格或 `timeseries` HTML | 统一时区、交易窗口、币种和基准；只保留有传导关系的市场 |
| 差异因果链、供应链位置、盈利传导、配对交易逻辑 | whiteboard | 图示明显比段落更清楚；精确数字回表格，图旁保留比较结论 |
| 公司/供应链/监管新闻 | 时间线表或 `timeline` SVG whiteboard | 两项以上且时序/阶段关系重要；区分发生、发布、生效与可交易时间 |
| 同业定位、候选优先级、风险或组合暴露 | `quadrant` SVG whiteboard | 两个维度、刻度和分割阈值必须可解释；不代替原始数据表 |
| 完整 OHLC、成交量、事件标记和价格路径 | K 线 HTML block | 股价分析的默认主视觉；必须有同口径 OHLC，跨公司统一窗口、频率与复权定义 |
| 相对收益、预期修正、A/H 历史路径 | `timeseries` HTML block | 路径比端点重要；基期、对齐方法和缺失交易日必须说明 |
| 估值敏感性、板块强弱或暴露矩阵 | `heatmap` HTML block | 网格足够密且同口径；保留精确数值、色阶中心和不可行区域 |
| 利润率、现金流、量价或指引桥接 | `waterfall` SVG whiteboard | 桥接项可复算、起终点一致；不要与相同信息的表图重复 |
| A/H 折溢价、历史区间与事件 | 同步表 + `timeseries` HTML | 同步价格/汇率/股份权利；执行障碍必须与价差同屏呈现 |
| 公式与关键假设 | 公式或简洁段落 | 展示可复算的关键公式，不把整篇写成方法论文 |
| 叙述、机制、判断与解释 | 连贯段落 | 默认表达；不要机械拆成 bullet 或卡片 |
| 来源、公告、监管文件 | 可点击引用/来源列表 | 来源紧随事实，并保留发布日期和截止日 |

### 高亮块

适合放“结论 + 关键条件 + 最大风险”的短摘要，不要把完整正文塞入。颜色保持语义一致：信息用中性/蓝色，风险用红色，待确认用黄色；不要用绿色或红色暗示无条件买卖建议。

### 对比分栏

适合以下短对照：

- 公司 A 的优势 vs 公司 B 的优势；
- 当前胜出理由 vs 会翻转排序的条件；
- 配对交易做多端逻辑 vs 做空/对冲端逻辑。

若每侧超过少量要点、需要跨行比较或含多期数值，改用表格。分栏不能替代三情景估值表。

### 表格

一张表只回答一个问题。表头写明期间，标题或注释写明币种、单位、是否复权、FY/CY/TTM、法定/调整后。重要变化优先展示绝对值与同比/环比，避免只用颜色表达涨跌。典型表格包括：

- 默认核心财务金融快照：市场数据、估值及至少两个经营财务类别；
- 用户问题需要、但核心快照尚未覆盖的增量 KPI；
- 市场位置、经营、财务质量、增长和估值比较；
- 各公司 Bull/Base/Bear 情景、关键假设、估值结果与相对排序；
- 催化剂/风险的公司归属、时间、影响路径与验证指标；
- 同窗口股价事件反应、相对表现和缺失交易日说明。
- 大盘、板块、外围市场及公司相对收益的传导证据；
- A/H 同步价格、汇率、折溢价、成本假设、执行门禁与历史位置。

### Whiteboard

优先用于结构关系，而不是精确数字表。多股票比较中的高价值场景包括：

- 同一行业变量如何通过不同商业模式传导到各公司的量价、利润率、现金流、预期与估值；
- 各公司在供应链、价值链、客户、产品和利润池中的不同位置；
- 相对投资论点的证据树、排序翻转条件和证伪路径；
- 配对交易的共同因子、差异因子和风险传播链；
- 国际或监管事件如何沿地区、供应链节点和公司暴露传导；
- 同业、候选或风险项目在两个清晰维度上的象限定位；点大小只能承载已说明口径的第三变量。

图中只放理解结构所需的信息，精确数字回到正文表格。插入后按最新版 `lark-doc`/`lark-whiteboard` 流程检查渲染；空白画板不算完成。

格式选择遵从线上最新版 `lark-doc` 的责任边界：象限、瀑布、金融事件时间线、供应链/传导/风险网络等自定义金融图优先 SVG；天然属于思维导图、时序、类图、饼图或甘特图时才考虑 Mermaid。SVG 使用完整 `viewBox` 与 `<text>`，不得引用外部资源；不要用一张巨大画板同时承载多个独立问题。

### HTML block

股价分析默认使用带悬停明细和事件标记的 K 线；其他 HTML block 仅当时间路径、密集矩阵、悬停明细或多序列联动确有实质价值时使用，例如 `timeseries` 相对表现/预期/AH 历史路径或 `heatmap` 估值敏感性/板块矩阵。遵守最新版 `lark-doc` 对单文件、尺寸、资源和运行时的限制，并满足：

- HTML block 前后各有一段文本，说明它回答的问题和读者应看到的结论；
- 关键结论不能只存在于交互组件内；
- 不内联大体积数据或图片，不把同一张表再做一遍 HTML；
- K 线只使用完整、严格升序、同一复权口径的 OHLC；只有收盘价时改用折线图；跨公司比较必须统一窗口、频率、复权与时区说明；
- 归一化相对收益必须写明共同基期、基准值、汇率和非共同交易日处理，不能把起点选择当作稳健结论；
- A/H 图必须同时显示价差定义、价格/汇率时间戳和执行限制，不能把历史均值线包装成必然回归；
- 除股价分析默认 K 线外，若静态表格足够，优先表格。
- 禁止把多个低相关图塞进单个 HTML Dashboard 规避图表预算；一个 HTML block 只承担一个主要信息任务。

## 5. 按任务组合，而非固定模板

- **比较一页纸/会前准备**：选择结论 + 紧凑核心财务金融快照 + 估值/风险短段；除涉及股价分析时默认使用 K 线外，通常不需要 HTML block。
- **全面股票对比**：选择结论 + 核心财务金融快照 + 胜负驱动 + 必要机制章节 + 情景/风险；按领域扫描加入真正影响结论的大盘/板块、供应链、新闻监管、外围和 A/H 信息。默认最多三个视觉家族，不以载体增加图表配额。
- **财报比较**：选择结论 + 核心财务金融快照 + 各公司实际值/预期值/差异表 + 指引和盈利变化机制；仅在多期趋势复杂时加图。
- **投资二选一**：高亮选择结论 + 核心财务金融快照 + A/B 短分栏 + 翻转条件；不能排名时明确分情景结论。
- **估值比较**：相对估值与反向 DCF 表为主；二维可复算敏感性用 `heatmap` HTML，透明双维定位用 `quadrant` SVG，二者不因“完整”自动同时出现。
- **股价与事件比较**：默认使用同窗口 K 线 HTML + 相对表现/事件反应表；只有质量清单记录了允许的不适用原因时省略 K 线。
- **大盘/板块/外围复盘**：市场状态短表 + `外围变量 → 板块/供应链 → 公司` 传导结论；跨市场曲线只在交易时区、币种和基期可对齐时使用。
- **供应链/国际/监管事件**：存在多节点分叉时用供应链 SVG，存在两项以上关键阶段时用 `timeline` SVG，否则使用段落/表格；新闻摘要不能替代传导分析。
- **同业定位**：统一口径比较表是主证据；只有双轴确实回答决策问题时，再加多象限 SVG。
- **组合适配/配对交易**：共同因子、差异因子、相关性、流动性和压力测试表 + 暴露/风险传播图；缺少组合输入时明确限制。
- **A/H 或 H 股相对价值**：同步价差表 + 历史折溢价 HTML 图 + 执行条件/成本/风险表；未验证可转换、借券和交收时，标题与结论均不得使用“可执行套利”。

## 6. 写入与校验

1. `LARK_DOC` 完成 preflight 后，按 `core-financial-snapshot.md` 建立核心财务金融快照，再按 `writing-quality.md` 建立质量清单并通过 `editorial_gate.py --phase plan`；三家公司以上、混合口径或量化排名按 `script-usage.md` 运行 `audit_ledger.py`；
2. 只为准入章节创建骨架并分节写入；不要把研究笔记、被排除章节或方法过程复制进正文；
3. 拉取已写文档，确认核心财务金融快照位于结论之后且覆盖全部对象，再复核整体顺序、引用、表格口径、图表渲染和免责声明；把 `visual_plan` 中保留图的 ID 同步到交付清单 `visual_family_ids`；
4. 逐段删除不改变判断的句子，合并同义主张，删除普通背景、新闻流水账、重复表图和无关数据缺口；
5. 将文档中的每个图与 `visual_plan` 一一核对：信息任务是否独立、为何优于表格/文字、是否超过档位预算、是否与其他图/表重复；不能说明价值就移除；
6. 逐图检查实际渲染、来源、单位、坐标/色阶、文字结论和移动端可读性；若 `price_analysis=true`，再确认 K 线覆盖或允许例外以及窗口、频率、时区和复权口径；
7. 完成 `visual_plan` 的逐图最终验证字段，更新质量清单并通过 `editorial_gate.py --phase final`；
8. 只有质量门禁实际通过后，才在交付清单记录 `editorial_gate_passed=true`；存在图表时逐图拉取复核后记录 `visuals_fetch_verified=true`，再通过 `delivery_gate.py --phase final`；
9. 两个门禁均通过后，在聊天中返回一至三句核心结论和文档链接，不把文档全文再复制一遍。

## 7. 最终交付门禁（必须执行）

在发送最终回复前，先拉取文档完成压缩编辑并运行 `scripts/editorial_gate.py --phase final <quality-manifest.json>`；质量门禁未通过时不得进入交付完成态。随后盘点正文和中间产物，更新交付清单，并运行 `scripts/delivery_gate.py --phase final <delivery-manifest.json>`。以下任一项存在，即判定为“已生成非 Markdown 高级样式”：

- HTML block 或其单文件 HTML；
- whiteboard、SVG、Mermaid、PlantUML 或其他画板源文件；
- `<grid>` 分栏、`<callout>` 高亮块、交互组件；
- 使用单元格底色、合并单元格、复杂列宽等 Markdown 无法保真的富表格；
- 其他若转成 Markdown 会丢失关键信息关系、交互或视觉编码的组件。

若盘点结果为“是”，交付清单中的 `delivery_mode` 必须是 `LARK_DOC`，并完成以下闭环：

1. 按第 2 节重新读取线上最新版 `lark-doc` 及本次写入所需引用文件；
2. 创建或更新飞书文档，把主要分析和所有保留的高级组件实际写入；
3. 拉取文档复核，确认组件存在、顺序正确、渲染可用且核心结论位于最前；
4. 最终聊天回复只给一至三句核心结论和可访问的飞书文档链接。

以下均不算完成：直接发送 `.html`、`.svg`、`.xml`、PNG 预览或其他本地文件；粘贴 HTML/SVG/XML/画板源码；只描述“可写入飞书”；只给本地路径；生成高级组件后又用 Markdown 摘要代替文档。

若认证、权限、组件写入或文档创建失败，任务仍处于未完成状态，最终门禁也不得通过。只向用户说明完成飞书写入所需的最小阻塞信息并按 `lark-doc` 流程处理；不得把分析正文或高级素材作为替代性交付。只有文档成功写入、取得可访问链接并拉取复核后，才能把任务表述为已完成。

交付前最终自检：结论是否最先出现；核心财务金融快照是否包含或有可审计的不相关理由、是否覆盖全部对象且保持紧凑；每节是否改变判断并带来新信息；低质量证据、通用背景、重复主张和新闻堆砌是否删除；事实/公司表述/一致预期/作者推断是否区分；日期、币种、单位和口径是否完整；最强反证是否公平；每个图是否进入 `visual_plan`、未超预算或有充分理由、与其他图表不重复、实际渲染且有文字结论；篇幅和图表数是否由问题而不是载体决定；`price_analysis=true` 时 K 线是否已写入并复核，或是否有可审计的不适用记录；若存在非 Markdown 高级样式，飞书文档是否已实际创建、复核并取得可访问链接。
