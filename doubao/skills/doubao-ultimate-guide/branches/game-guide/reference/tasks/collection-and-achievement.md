# 收集与成就攻略规则
本文件适用于 `primary_task=collection-and-achievement` 的请求，负责收集品、奖杯、成就、图鉴、隐藏要素、全收集目标和易遗漏内容。目标是帮助用户从当前进度完成明确的收集或成就目标，并避免因路线混乱、前置遗漏、不可逆条件或版本差异造成重复劳动。
## 一、适用条件
当用户核心需求属于以下情况时使用本文件：
- 想收集某类全部物品、图鉴、日志、宝箱或隐藏要素；
- 不知道还缺哪些收集品；
- 想完成某个奖杯、成就或挑战条件；
- 想规划全收集路线；
- 找不到某个具体收集品或成就触发条件；
- 担心遗漏、错过或不可逆内容；
- 需要确认收集进度和最终完成状态。

若核心问题只是寻找一个具体位置，使用 `navigation.md`；某个收集品依赖任务推进，使用 `quest.md`；需要完整区域流程，使用 `walkthrough.md`。只有这些内容对当前收集目标构成独立复杂需求时才作为辅助任务加载。
## 二、处理目标
收集与成就攻略必须建立：

```text
目标范围
→ 当前进度
→ 必要前置与遗漏风险
→ 合理分组
→ 推荐执行顺序
→ 单项获取/触发方式
→ 缺失项排查
→ 最终完成确认
```
不得无序罗列全部点位，也不得默认用户从零开始。
## 三、生成前必须确认
至少确认：
- `final_goal`；
- 收集或成就的准确对象；
- 用户当前已完成、已获得或已知缺失内容；
- 目标范围：单个、某一区域、某一类别还是全收集；
- 是否存在任务、章节、难度、周目、角色或世界状态前置；
- 是否存在永久错过、阶段限定、分支锁定或多人要求；
- 当前版本、平台、DLC和奖杯/成就体系差异。

用户已提供进度截图、清单或缺失数量时，必须优先利用，不从零重复完整列表。
## 四、先确定收集范围
明确当前请求属于：
- 单个目标；
- 指定区域；
- 指定类别；
- 指定奖杯/成就；
- 多项组合目标；
- 全收集。

范围越大，越需要先按区域、前置或执行路线分组；范围越小，越应直接解决当前缺失项。

不得把“全收集攻略”机械输出给只缺一个目标的用户。
## 五、收集项分类
根据实际游戏机制按需区分：
- 固定地图点位；
- 任务奖励；
- BOSS或敌人掉落；
- 商店或兑换；
- 隐藏区域；
- 解谜奖励；
- 随机掉落；
- 条件触发；
- 多周目或分支限定；
- 联机或多人限定；
- 活动、赛季或限时内容。

不同获取机制必须分别处理，不能把所有项目都当作地图点位。
## 六、进度对齐
先判断用户当前进度：
- 已完成哪些区域；
- 已获得哪些目标；
- 已解锁哪些地图和传送点；
- 当前是否仍能返回遗漏区域；
- 是否已经触发影响收集的分支或不可逆状态。

若用户只缺少少量内容，优先定位缺失项，不重复已完成内容。

无法直接识别缺失项时，可根据游戏内编号、区域计数、图鉴顺序、成就进度或用户截图进行排查。
## 七、执行顺序
大型收集任务优先按照降低重复移动和遗漏风险的方式组织，可采用：
- 区域顺序；
- 主流程推进顺序；
- 前置依赖顺序；
- 最短或较高效率路线；
- 不可逆内容优先；
- 同类目标批量处理。

默认顺序：

```text
易错过/不可逆
→ 有前置限制
→ 当前区域可顺路完成
→ 可随时返回
→ 随机或重复刷取
```
实际游戏有更合理路线时，以真实机制为准。
## 八、单项获取说明
每个关键收集项按需包含：
- 名称或编号；
- 所在区域；
- 最近可识别起点；
- 获取前置；
- 具体位置或触发条件；
- 获取动作；
- 获得后的确认方式。

简单点位可以合并；复杂路线调用 `navigation.md`，复杂任务调用 `quest.md`，复杂谜题调用 `puzzle.md`。
## 九、易遗漏与不可逆内容
以下内容必须优先标记：
- 章节结束后无法返回；
- NPC死亡、移动或任务失败后无法获取；
- 分支选择锁定；
- 仅特定时间、天气、难度或周目出现；
- 只能一次获得；
- 需要先完成隐藏前置；
- 会因剧情推进改变地图或世界状态；
- 赛季、活动或版本限定。

必须说明“什么时候会错过”和“如何避免”，不得只写“注意可能错过”。
## 十、成就与奖杯条件
成就攻略必须确认：
- 官方或实际触发条件；
- 条件是否需要一次完成；
- 是否允许分多次累计；
- 是否限定难度、角色、武器、模式或周目；
- 是否有隐藏条件；
- 是否需要完成后额外触发结算或保存；
- 不同平台的成就名称或条件是否存在差异。

不得只照抄成就描述；若描述模糊，应解释实际判定方式。
## 十一、随机掉落与重复刷取
涉及随机掉落时按需说明：
- 掉落来源；
- 必要条件；
- 是否受难度或版本影响；
- 最有效率的重复路线；
- 一次循环的关键步骤；
- 是否存在保底、上限或其他确认机制。

无法可靠确认掉率时不得编造具体概率。用户目标是效率时，可调用 `resource-and-efficiency.md`。
## 十二、缺失项排查
用户“只差一个/几个但不知道缺什么”时，按以下顺序排查：
1. 游戏内区域计数、图鉴编号或分类；
2. 最容易永久错过的项目；
3. 隐藏区域和任务奖励；
4. 需要特殊世界状态的项目；
5. 随机掉落或商店兑换；
6. DLC、版本或平台独有内容。

优先给最快缩小范围的方法，不直接把全部收集项重新列一遍。
## 十三、全收集路线
全收集请求应按阶段或区域组织，并处理：
- 主流程顺路收集；
- 必须回头处理的项目；
- 不可逆内容；
- 后期解锁能力才能取得的项目；
- 多周目要求；
- 最终扫尾顺序。

目标是减少重复跑图，但不得为了追求最短路线而给出高风险、难执行或依赖用户未解锁能力的路线。
## 十四、收集中的辅助任务
- 单个点位难找 → 调用 `navigation.md`；
- 获取依赖任务链 → 调用 `quest.md`；
- 依赖复杂谜题 → 调用 `puzzle.md`；
- 需要连续区域推进 → 调用 `walkthrough.md`；
- 需要高难战斗 → 调用 `combat-and-boss.md`；
- 重点是刷取效率 → 调用 `resource-and-efficiency.md`。

辅助规则必须嵌入当前收集顺序，不把答案拆成互不关联的多个攻略。
## 十五、完成确认
必须说明如何确认目标已完成，例如：
- 收集计数达到上限；
- 图鉴全部点亮；
- 奖杯/成就弹出；
- 游戏内挑战状态完成；
- 获得最终奖励；
- 某区域剩余数量归零；
- 系统显示100%或对应完成标志。

若游戏内完成率不等于真正全收集，必须明确区别。
## 十六、视觉辅助
按 `reference/media.md` 执行。收集与成就攻略优先使用：
- 区域地图；
- 点位标记；
- 推荐路线；
- 隐藏入口；
- 易遗漏位置；
- 现场识别截图。

多点收集应按区域或执行顺序组织视觉素材，不无序堆图。地图标记必须与正文编号或顺序对应。
## 十七、推荐输出结构
根据目标范围选择必要部分，不机械输出全部栏目：

```text
你当前还需要完成什么
→ 先处理的易错过/前置
→ 按区域或路线执行
→ 单项获取方式
→ 缺失项排查
→ 最终完成确认
```
单个目标直接给获取方式；大型全收集再按阶段和区域展开。
## 十八、完成条件
收集与成就攻略输出前确认：
- 收集范围和用户当前进度已对齐；
- 没有重复要求用户完成已获得项目；
- 必要前置、不可逆和易遗漏条件已正确标记；
- 执行顺序合理且不会造成明显重复劳动；
- 单项获取方式具体可执行；
- 随机内容没有编造概率；
- 成就实际触发条件已核验；
- 缺失项有可操作的排查方法；
- 完成状态有明确确认方式；
- 视觉素材与点位、路线和版本一致，或已合理降级；
- 用户可以从当前状态完成 `final_goal`；
- 关键事实、版本和视觉素材已通过 `retrieval.md`、`media.md` 与 `quality-check.md` 校验。
