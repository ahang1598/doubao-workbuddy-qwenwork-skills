# 资源规划与效率攻略规则
本文件适用于 `primary_task=resource-and-efficiency` 的请求，负责货币、材料、体力、行动点、时间、抽卡资源、升级资源、制作资源及其他有限资源的投入、优先级与效率规划。目标是根据用户当前资源、账号阶段、目标和时间范围，明确“先做什么、先投什么、哪些暂缓、资源是否足够”，而不是只给泛化的省资源建议或理论最优结论。
## 一、适用条件
当用户核心需求属于以下情况时使用本文件：
- 不知道有限资源应该优先投入哪里；
- 想规划角色、装备、建筑、科技或其他养成顺序；
- 想判断某个角色、武器、卡池或项目是否值得投入；
- 想规划体力、行动点、金币、材料或时间；
- 想提高刷取、养成、升级或日常玩法效率；
- 想计算当前资源能否完成某个目标；
- 需要短期、中期或长期账号发展规划；
- 面临多个互斥目标，需要做资源取舍。

若核心问题是具体Build，使用 `build.md`；角色和队伍培养，使用 `character-and-team.md`；新手整体发展路线，使用 `beginner.md`。只有这些内容是当前资源决策不可缺少的独立需求时，才作为辅助任务加载。
## 二、处理目标
资源规划必须建立：

```text
最终目标
→ 当前资源与限制
→ 必要成本
→ 优先级
→ 投入顺序
→ 可暂缓内容
→ 缺口与获取方式
→ 风险/机会成本
→ 目标完成判断
```
不得只告诉用户“优先主C”“攒资源”“效率最高”，必须明确资源应该如何分配以及这样取舍的原因。
## 三、生成前必须确认
至少确认：
- `final_goal`；
- 用户当前资源数量或可可靠判断的资源状态；
- 当前账号、进度或发展阶段；
- 计划投入的候选目标；
- 用户的时间范围：立即、近期、当前版本、赛季或长期；
- 用户的硬限制和偏好，如无氪、低氪、每天可玩时间、保留某类资源等；
- 当前版本、活动、卡池、商店、掉落和资源系统是否影响规划；
- 是否存在限时、重置、溢出、保底、上限或不可逆投入。

用户没有提供精确资源数量时，可以给优先级和条件化方案，但不得编造精确预算结果。
## 四、先确定规划目标
资源规划必须先明确资源服务于什么目标，例如：
- 尽快通过当前内容；
- 培养一支可用主队；
- 准备下一个角色或卡池；
- 完成某个Build；
- 提高长期账号价值；
- 追求当前版本效率；
- 在限定时间内完成活动；
- 平衡多个发展目标。

存在多个目标时，按优先级区分：
- `must_do`：不完成会阻塞最终目标；
- `high_value`：投入收益明显且适合当前阶段；
- `optional`：有剩余资源再处理；
- `delay`：当前投入机会成本过高，应暂缓。

不得把所有目标同时列为最高优先级。
## 五、资源分类
先区分资源性质，再决定投入策略。
### 稀缺不可逆资源
获取有限、投入后难以回收或长期影响账号，例如抽卡货币、限定兑换材料、重置困难的强化资源。

处理：提高决策门槛，明确机会成本和替代目标。
### 周期恢复资源
随时间恢复或定期重置，例如体力、行动点、门票。

处理：优先避免长期溢出，并投入当前阶段收益最高的目标。
### 可重复刷取资源
可持续获得，但需要时间或体力。

处理：比较获取效率和实际需求，不为了囤积无限刷取。
### 通用货币
用途多、消耗面广。

处理：预留近期刚性需求，再分配剩余资源。
### 限时资源
活动、赛季或版本结束后失效或价值下降。

处理：优先确认截止时间和最佳兑换顺序。

不同资源不得因为都叫“材料”就使用同一规划逻辑。
## 六、优先级判断
资源投入按以下顺序判断：
1. 是否是完成 `final_goal` 的必要条件；
2. 是否会解除当前核心瓶颈；
3. 单位资源带来的实际提升；
4. 是否适合用户当前阶段；
5. 是否存在更低成本替代；
6. 是否具有长期保值性；
7. 是否会挤占更重要目标的资源。

优先解决“最限制当前进度的瓶颈”，而不是平均强化所有项目。
## 七、投入顺序
规划应尽量给出明确顺序，例如：

```text
先满足核心功能门槛
→ 解决当前瓶颈
→ 完成高收益升级
→ 补稳定性与泛用性
→ 再处理高成本边际提升
```
涉及多个角色、建筑、科技或装备时，应说明：
- 谁先投入；
- 投到什么程度先停；
- 什么时候切换下一个目标；
- 哪些项目暂时不值得继续投入。

不得只给最终毕业状态而缺少实际成长路径。
## 八、成本与资源缺口
能够可靠获取数据时，应计算或整理：
- 当前拥有量；
- 目标总成本；
- 已投入量；
- 剩余缺口；
- 预计可获取资源；
- 是否存在安全余量。

无法可靠确认精确数据时，应使用条件化判断，不编造数值。

资源不足时优先回答：
1. 哪些目标必须保留；
2. 哪些可以降低标准；
3. 哪些可以推迟；
4. 哪些资源有更高效来源。
## 九、收益与机会成本
每项重大投入按需说明：
- 能解决什么问题；
- 提升主要体现在哪里；
- 是否只是小幅边际提升；
- 投入后会失去什么其他机会；
- 是否存在即将到来的版本、卡池或系统变化。

尤其涉及不可逆资源时，不得只说“值得/不值得”，必须结合用户目标说明取舍。
## 十、抽卡与限定资源决策
涉及抽卡、招募、限定兑换或类似系统时必须按 `reference/retrieval.md` 深度核验当前有效信息。

重点考虑：
- 用户当前资源；
- 保底、继承或兑换机制；
- 当前已拥有角色和队伍缺口；
- 目标对象对账号的实际提升；
- 后续已确认或官方公布的资源需求；
- 用户偏好和风险承受能力。

不得把未经官方确认的爆料当作确定未来信息。可以参考可靠信息做条件分析，但必须明确不确定性。

推荐结论应尽量明确，例如：
- 当前建议投入；
- 建议保留资源；
- 达到某个资源安全线后再投入；
- 只在满足特定队伍条件时值得；
- 强度收益有限，但偏好优先时可以投入。
## 十一、体力与行动点规划
周期恢复资源应优先避免长期溢出，但不需要制造必须全天候清空的压力。

按当前阶段判断：
- 哪类材料最缺；
- 哪个副本或来源当前收益最高；
- 是否有活动加成；
- 是否应该提前刷未来资源；
- 是否存在等级提升后效率更高的阶段；
- 是否应保留恢复道具。

计划应给出“当前优先刷什么”和“什么时候改变目标”，不只列所有可刷内容。
## 十二、日常、周常与时间效率
用户关注时间效率时，应区分：
- 高价值且耗时短；
- 高价值但耗时长；
- 可选；
- 当前阶段可以跳过。

根据用户可用时间给优先级，不默认所有日常、周常和活动必须全部完成。

效率规划应优化“单位时间获得用户真正需要的收益”，而不是机械追求奖励总量最大化。
## 十三、刷取效率
涉及刷材料、装备、掉落或经验时按需比较：
- 单次收益；
- 时间成本；
- 体力/行动点成本；
- 成功率；
- 路线复杂度；
- 是否可顺带获得其他需要资源；
- 是否存在活动或难度加成。

若掉率无法可靠确认，不得编造精确效率。可基于已确认机制给相对优先级。
## 十四、短期与长期规划
根据用户需求区分：
### 短期
解决当前卡点、完成活动、形成第一套可用配置。
### 中期
补齐核心队伍、Build或稳定资源循环。
### 长期
处理高成本强化、收藏、广度培养或未来储备。

不得为了长期理论价值牺牲用户当前必须解决的核心进度；也不得为了短期微小提升耗尽会影响明确长期目标的稀缺资源。
## 十五、资源安全线
涉及高价值或不可逆资源时，可按需设置安全线，例如：
- 保留完成已确定目标所需的最低资源；
- 预留必要强化成本；
- 防止活动结束前资源不足；
- 防止抽卡后无法完成核心培养。

安全线必须基于可靠机制和用户目标，不得随意给出固定数字。
## 十六、动态调整
资源计划不是固定清单。出现以下情况时应调整：
- 获得关键角色、装备或掉落；
- 当前核心瓶颈解决；
- 游戏版本或平衡变化；
- 新活动提供更高效资源来源；
- 用户目标改变；
- 实际资源收入与预期差异明显。

按需告诉用户“什么信号出现后应该改变投入方向”。
## 十七、与其他任务文件的关系
- 资源投入服务于具体Build → 调用 `build.md`；
- 多角色培养和配队优先级 → 调用 `character-and-team.md`；
- 新手整体发展阶段 → 调用 `beginner.md`；
- 刷取路线或材料位置 → 调用 `navigation.md`；
- 收集或掉落目标 → 调用 `collection-and-achievement.md`；
- 当前资源不足是因为某战斗卡关 → 按需调用 `combat-and-boss.md`。

辅助规则必须服务当前资源决策，不把答案扩展成无关完整攻略。
## 十八、视觉辅助
按 `reference/media.md` 执行。资源与效率规划优先使用：
- 优先级表格；
- 投入顺序；
- 资源流向结构；
- 简洁决策树；
- 必要的活动、商店或资源界面截图。

仅在角色、道具、兑换入口或资源系统需要识别时使用游戏截图。不得为了配图加入无关角色宣传图。
## 十九、推荐输出结构
根据实际问题选择必要部分，不机械输出全部栏目：

```text
直接结论
→ 当前资源最优先投哪里
→ 哪些先停/先保留
→ 具体投入顺序
→ 资源缺口与获取方式
→ 关键机会成本或风险
→ 什么情况下调整计划
```
用户只问一次简单取舍时，直接给明确建议和关键理由；用户要求完整规划时，再展开短中长期路线。
## 二十、完成条件
资源规划与效率攻略输出前确认：
- 最终目标和时间范围明确；
- 当前资源和用户限制已纳入判断；
- 资源类型没有混用错误逻辑；
- 投入优先级和停止点清楚；
- 没有要求用户平均投入所有目标；
- 重要机会成本和不可逆风险已按需说明；
- 精确数值均有可靠依据，未编造成本、掉率或收益；
- 强时效的卡池、活动、版本和资源机制已完成最新核验；
- 用户知道先做什么、哪些暂缓以及资源不足时如何取舍；
- 视觉素材或结构化表达真正帮助决策，或已合理降级；
- 用户可以据此把现有资源投入到 `final_goal`；
- 关键事实、版本和视觉素材已通过 `retrieval.md`、`media.md` 与 `quality-check.md` 校验。
