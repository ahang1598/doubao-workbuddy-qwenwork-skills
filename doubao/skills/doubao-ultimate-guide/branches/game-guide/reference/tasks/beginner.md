# 新手攻略规则
本文件适用于 `primary_task=beginner` 的请求，负责新手入门、开局发展、基础系统理解、阶段目标、常见误区和前期成长路线。目标是帮助用户快速建立正确的游玩框架，知道“现在先做什么、哪些不用急、什么容易浪费资源”，而不是一次性灌输整套游戏百科。
## 一、适用条件
当用户核心需求属于以下情况时使用本文件：
- 刚开始玩，不知道先做什么；
- 想要开局或前期发展建议；
- 不理解游戏核心系统和基础循环；
- 不知道哪些角色、装备、技能或资源值得优先投入；
- 想避免新手阶段常见错误；
- 回坑后需要重新理解当前基础环境；
- 想知道达到某个阶段前应该完成哪些关键目标。

若核心问题已经明确为具体任务、Build、配队、战斗或资源规划，应使用对应任务文件；只有用户真正需要建立整体入门框架时，才以本文件作为主任务。
## 二、处理目标
新手攻略必须建立：

```text
当前阶段
→ 先理解什么
→ 现在优先做什么
→ 哪些资源先保留
→ 哪些系统暂时不用管
→ 阶段性目标
→ 常见高成本错误
→ 进入下一阶段的判断
```
不得把所有系统、角色、装备和玩法一次性全部介绍。只覆盖用户当前阶段真正需要知道的内容。
## 三、生成前必须确认
至少确认：
- `final_goal`；
- 用户是完全新手、刚过教程、前期玩家还是回坑玩家；
- 当前已解锁的主要系统和游戏进度；
- 用户偏好的玩法目标，如休闲、剧情、PVP、长期养成、速通或低氪；
- 是否存在平台、版本、赛季、服务器或新手活动差异；
- 当前版本中会显著影响新手路线的重要机制。

用户没有提供精确进度时，可以按最常见的新手阶段提供分段建议，但不得假设用户已经解锁后期系统。
## 四、先建立核心循环
优先解释玩家最需要理解的1–3个核心循环，例如：
- 探索 → 战斗 → 获取资源 → 强化；
- 做任务 → 解锁系统 → 提升角色；
- 收集资源 → 建造/生产 → 扩张；
- 对局 → 获取奖励 → 解锁内容；
- 抽取/养成 → 配队 → 挑战更高内容。

只说明直接影响当前决策的核心逻辑，不展开完整系统百科。

用户理解“为什么现在做这些”比记住大量规则更重要。
## 五、开局优先级
按真实依赖关系给出前期优先事项。通常优先判断：
- 必须完成的教程或主线解锁；
- 关键功能和系统；
- 稳定获取资源的入口；
- 主力角色/职业/武器的基础成型；
- 重要地图、传送点或生产设施；
- 会随时间恢复或刷新的资源；
- 容易永久浪费的稀缺资源。

优先级必须有明确顺序，不使用“都很重要”式建议。
## 六、阶段目标
将新手期拆成少量真正有意义的阶段，例如：
- 教程/刚开局；
- 核心系统解锁期；
- 第一套可用配置成型；
- 开始稳定获取资源；
- 进入中期或常规玩法。

每个阶段按需说明：
- 当前最重要目标；
- 完成哪些内容；
- 资源主要投在哪里；
- 哪些内容可以暂时跳过；
- 达到什么状态可以进入下一阶段。

不得使用只适用于某款游戏的固定等级分段，除非已通过 `retrieval.md` 确认。
## 七、资源保护
新手攻略必须识别游戏中的稀缺或高价值资源，并按需提醒：
- 哪些可以放心使用；
- 哪些应先保留；
- 哪些只能投入核心目标；
- 哪些早期看似丰富但后期会紧缺；
- 哪些资源有时间上限或溢出损失。

只提醒真正可能造成明显长期损失的资源，不制造“什么都不敢花”的焦虑。

涉及复杂长期资源分配时调用 `resource-and-efficiency.md`。
## 八、角色、装备与队伍的前期原则
根据游戏类型按需说明：
- 是否应该集中培养少数核心单位；
- 是否需要先建立一套最低可用Build；
- 是否应该平均培养；
- 前期装备是否值得深度强化；
- 哪些低成本配置可以长期使用；
- 什么时候需要开始关注完整配队或高阶Build。

详细角色培养和队伍问题调用 `character-and-team.md`；详细装备构筑调用 `build.md`。本文件只保留新手阶段的方向和优先级。
## 九、系统解锁与信息减负
对于复杂游戏，按以下方式处理：
- 当前阶段必须理解的系统：解释用途和基本操作；
- 即将使用的系统：简要说明为什么重要；
- 后期系统：明确“现在不用管”，不提前灌输细节。

不得因为游戏系统多就全部介绍。新手攻略的目标是降低决策负担，而不是增加信息量。
## 十、常见新手错误
只列会造成明显损失、卡进度或长期返工的错误，例如：
- 把稀缺资源平均分散；
- 过早高投入低价值装备或角色；
- 忽略必须完成的关键解锁；
- 资源达到上限后长期溢出；
- 错过明显不可逆内容；
- 不理解核心机制导致反复失败；
- 盲目照搬后期Meta配置。

每个错误应说明“为什么有问题”和“正确做法”，不要只列警告。
## 十一、学习顺序
新手需要掌握多个系统时，按实际使用顺序安排：

```text
先学当前必须操作的
→ 再学直接影响成长的
→ 再学资源与配置优化
→ 最后处理高阶和长期系统
```
不要把机制解释顺序等同于游戏菜单顺序。
## 十二、日常、周常与长期运营内容
持续运营游戏按需说明：
- 新手当前必须完成的固定周期内容；
- 哪些奖励价值高；
- 哪些内容暂时打不过可以放弃；
- 哪些资源存在过期或上限；
- 哪些活动值得优先参加。

不得默认所有日常和周常都必须完成，也不得用高压“清单打卡”替代正常游玩建议。
## 十三、开荒与效率取舍
新手默认优先：
1. 可执行；
2. 稳定；
3. 低资源浪费；
4. 建立正确理解；
5. 最后才是理论最高效率。

只有用户明确追求速通、冲榜或极限效率时，才提高对最优路线和高操作方案的权重。
## 十四、回坑玩家
用户属于回坑玩家时，重点处理：
- 当前版本相对其离开时的主要变化；
- 旧资源和旧角色是否仍可使用；
- 新系统中哪些必须先处理；
- 回归活动或追赶机制；
- 当前阶段最有效的恢复路线。

不得把回坑玩家当成完全新手重新讲所有基础知识。
## 十五、辅助任务调用
- 不知道具体主线怎么推进 → 调用 `walkthrough.md`；
- 某个系统卡在任务解锁 → 调用 `quest.md`；
- 需要第一套可用Build → 调用 `build.md`；
- 需要确定主力和队伍 → 调用 `character-and-team.md`；
- 需要详细资源投入规划 → 调用 `resource-and-efficiency.md`；
- 卡在具体战斗 → 调用 `combat-and-boss.md`。

辅助规则只补充用户当前阶段需要的部分，不把新手攻略扩展成全游戏百科。
## 十六、视觉辅助
按 `reference/media.md` 执行。新手攻略优先使用：
- 关键系统入口；
- 地图或功能界面；
- 重要菜单位置；
- 容易找不到的核心设施；
- 需要识别的关键资源或图标。

基础概念用文字即可说明时不强制展示图片。视觉素材应帮助用户完成当前操作，而不是展示游戏宣传内容。
## 十七、推荐输出结构
根据用户当前阶段选择必要部分，不机械输出全部栏目：

```text
你现在最先做什么
→ 当前阶段的3–5个优先事项
→ 资源先怎么用
→ 哪些系统暂时不用管
→ 最容易踩的坑
→ 达到什么状态后进入下一阶段
```
用户只问一个新手问题时，直接回答该问题；用户明确要求完整新手路线时，再按阶段展开。
## 十八、完成条件
新手攻略输出前确认：
- 已识别用户真实的新手或回坑阶段；
- 没有默认用户已解锁后期系统；
- 当前阶段优先级清楚；
- 没有一次性灌输全部游戏系统；
- 关键稀缺资源和高成本错误已按需提醒；
- 角色、装备和资源建议符合用户当前条件；
- 复杂问题已按需调用对应任务规则；
- 用户知道现在先做什么、暂时不做什么，以及何时进入下一阶段；
- 视觉素材能帮助完成当前操作，或已合理降级；
- 关键事实、版本和视觉素材已通过 `retrieval.md`、`media.md` 与 `quality-check.md` 校验。
