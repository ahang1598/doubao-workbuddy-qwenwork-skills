# 流程推进攻略规则
本文件适用于 `primary_task=walkthrough` 的请求，负责章节、区域、关卡、主流程或连续阶段推进。目标是帮助用户从当前进度稳定推进到明确目标，不遗漏关键前置、必要节点和完成标志。
## 一、适用条件
当用户核心需求属于以下情况时使用本文件：
- 不知道下一步做什么；
- 想从当前进度推进到某个章节、区域或目标；
- 想获得一段连续流程的完整攻略；
- 卡在主流程、关卡流程或区域推进中；
- 需要从当前状态到最终目标的连续行动路径。

若核心问题只是单个任务、单次战斗、单个地点或单个谜题，应分别路由到对应任务文件；只有这些内容属于完成连续流程不可缺少的节点时，才作为辅助任务加入。
## 二、处理目标
流程攻略必须建立：

```text
当前状态
→ 必要前置
→ 连续推进节点
→ 关键卡点处理
→ 阶段完成判断
→ 下一阶段或最终目标
```
不得从默认开局或攻略作者视角开始，必须从用户真实 `stage` 出发。
## 三、生成前必须确认
至少确认：
- `final_goal`；
- 用户当前 `stage`；
- 当前流程所需的关键前置；
- 目标流程的起点与终点；
- 会阻塞推进的关键节点；
- 是否存在版本、DLC、平台、模式差异；
- 是否存在不可逆选择、易错过内容或重要分支。

无法确认但不影响主流程的信息不得阻塞输出；会直接导致路线错误的信息按 `routing.md` 处理。
## 四、流程拆分
将流程拆成真正影响推进的阶段节点，不按每个小动作机械拆分。

每个关键节点按需包含：
- 当前地点或状态；
- 本节点目标；
- 需要执行的动作；
- 必要路线或交互；
- 关键战斗、任务或解谜；
- 完成判断；
- 下一节点入口。

一个节点只有在以下情况之一成立时才单独拆出：
- 地图区域发生明显变化；
- 需要完成新的前置；
- 出现重要任务或关键交互；
- 存在高失败风险战斗；
- 有重要分支或不可逆选择；
- 玩家容易迷路或卡住；
- 完成后游戏状态发生明显变化。
## 五、前置条件
所有影响流程可执行性的前置必须在对应步骤前说明，包括：
- 必须完成的任务；
- 必须解锁的区域、能力或道具；
- 等级、装备或资源门槛；
- 必须触发的事件；
- DLC、资料片或模式要求。

不得把前置集中堆在开头却不说明它具体影响哪一步。

用户已满足的前置可简写；未满足的前置必须给出补齐方式，必要时调用对应辅助任务文件。
## 六、路线与推进节点
涉及移动和区域切换时：
- 给出明确起点；
- 按真实移动顺序描述；
- 使用可识别地标、传送点、门、楼层、区域名或场景特征；
- 复杂路线提供中间确认点；
- 每次区域切换说明如何判断已进入正确区域。

路线复杂时调用 `reference/tasks/navigation.md` 作为辅助规则，并按 `reference/media.md` 配置地图或路线视觉辅助。
## 七、流程中的战斗、任务和解谜
流程攻略只解释推进所必需的内容，不自动展开完整子攻略。

处理规则：
- 简单节点：直接给必要操作。
- 会明显阻塞流程：加载对应辅助任务文件。
- BOSS/高难战斗：需要独立打法时读取 `combat-and-boss.md`。
- 复杂任务：读取 `quest.md`。
- 复杂寻路：读取 `navigation.md`。
- 复杂解谜：读取 `puzzle.md`。

主结构始终由流程顺序控制，辅助规则嵌入对应节点，不拆成互相独立的多篇攻略。
## 八、分支与不可逆内容
若流程存在重要分支：
- 只说明与当前目标直接相关的选择；
- 标明会影响后续流程、奖励或结局的不可逆选择；
- 默认遵守 `spoiler_level=minimal`；
- 不为展示完整度提前泄露后续重大剧情。

多个路线都可完成目标时，优先选择最符合 `player_context` 的路线，并按需补充替代路线。
## 九、完成判断
每个重要阶段应给出可验证的完成标志，例如：
- 出现新区域或传送点；
- 任务日志更新；
- 获得关键道具；
- NPC位置或状态变化；
- 新Boss/章节解锁；
- UI、地图或世界状态发生明确变化。

不得只写“完成后继续下一步”。
## 十、易错点与卡点
只补充会实际导致流程中断或重复返工的内容，包括：
- 容易错过的前置；
- 走错路线的分岔；
- 必须先交互的机关；
- NPC或任务状态变化；
- 不可逆选择；
- 关键资源不足；
- 版本变化导致的旧攻略失效。

普通低风险细节不需要堆叠成“注意事项大全”。
## 十一、视觉辅助
按 `reference/media.md` 执行。流程攻略优先使用：
- 区域地图；
- 关键入口；
- 中间确认点；
- 重要场景；
- 易走错节点。

视觉素材按流程顺序放置，只覆盖真正需要确认的位置，不为每个普通步骤强行配图。
## 十二、推荐输出结构
根据实际复杂度从以下结构中取需要的部分，不机械输出全部栏目：

```text
目标与当前进度
→ 必要前置
→ 阶段1：目标 + 操作 + 完成判断
→ 阶段2：目标 + 操作 + 完成判断
→ 关键卡点/分支
→ 最终阶段
→ 目标完成确认
```
复杂长流程可按章节或区域分段；简单流程可压缩为连续步骤。
## 十三、完成条件
流程攻略输出前确认：
- 从用户真实 `stage` 开始；
- 所有必要前置已覆盖；
- 流程节点顺序正确；
- 关键卡点没有断层；
- 复杂子问题已按需调用辅助任务规则；
- 每个重要阶段都有完成判断；
- 没有无必要剧透；
- 用户可以从当前状态连续执行到 `final_goal`；
- 关键事实、版本和视觉素材已通过 `retrieval.md`、`media.md` 与 `quality-check.md` 校验。
