# 策略 / 模拟经营 / 4X 处理规则
本文件适用于 `primary_game_type=strategy-simulation` 的请求，负责根据策略、模拟经营与4X游戏的核心机制修正具体任务攻略。它不决定攻略主体结构；主体结构始终由 `primary_task` 文件决定。本文件只补充该类游戏中特别影响正确性和可执行性的局面判断、资源约束、发展顺序、长期规划、动态反馈和多方案权衡。
## 一、适用条件
当当前问题主要依赖以下机制时使用本文件：
- 资源生产、分配和长期积累；
- 城市、基地、产业、人口或设施经营；
- 科技、政策、建筑、兵种或发展路线选择；
- 地图扩张、外交、战争和区域控制；
- 回合制或实时战略决策；
- 经济、物流、供应链和生产效率；
- 多变量系统之间的连锁影响；
- 当前局面不同会导致完全不同的最优决策。

不要因为一款游戏带有资源、建造或战斗元素就自动使用本文件。只有当前问题的核心答案依赖经营、战略决策或系统性资源配置时，才将 `strategy-simulation` 作为主类型或辅助类型。
## 二、`mechanic_focus`
根据当前问题确定最主要的机制焦点：

- `strategy`：局面判断、军事行动、阵容部署、战术或战略决策是核心；
- `simulation`：经营、生产、人口、设施、物流或系统平衡是核心；
- `4x`：探索、扩张、开发、征服与长期文明发展是核心；
- `management`：资源分配、优先级、建设顺序和效率优化是核心。

只选择最贴近当前问题的焦点。若多个机制同时存在，以最能改变当前决策逻辑的机制为准。
## 三、核心处理原则
### 1. 先判断局面，再给方案
策略类游戏通常不存在脱离局面的唯一答案。必须优先考虑：
- 当前回合、时间或发展阶段；
- 已有资源和收入；
- 当前人口、城市、基地或领地；
- 敌我力量；
- 科技、政策或系统解锁；
- 地图位置和外部压力；
- 用户当前目标。

不得把固定Build Order或通用发展路线直接当作所有局面的最优解。
### 2. 区分硬约束、瓶颈和优化项
先判断：
- 什么是当前无法绕过的硬约束；
- 什么是最限制发展的核心瓶颈；
- 什么只是可以优化但不影响目标的次要问题。

优先解决瓶颈，不平均优化所有系统。
### 3. 给决策规则，不只给单点答案
动态局面会持续变化时，应按需提供：

```text
如果出现A → 采取方案A
如果出现B → 转向方案B
达到条件C → 进入下一阶段
```
让用户能够根据后续局面继续判断，而不是只得到一条很快失效的固定指令。
## 四、阶段判断
策略与经营攻略必须先识别当前发展阶段，例如：
- 开局建立基础循环；
- 扩张和规模增长；
- 中期转型；
- 稳定运营；
- 后期优化或胜利冲刺；
- 危机处理或战时状态。

不同游戏阶段的资源价值和最优决策可能完全不同。不得把后期高收益策略直接推荐给尚未建立基础经济的用户。
## 五、资源与瓶颈
分析资源时重点区分：
- 当前库存；
- 稳定收入；
- 消耗速度；
- 生产能力；
- 储存或上限；
- 转换效率；
- 机会成本。

优先识别真正的限制因素，例如：
- 缺钱；
- 缺人口；
- 缺产能；
- 缺物流；
- 缺科研；
- 缺土地；
- 缺军事保护；
- 缺某个前置资源。

不得因为某种资源数值最低就默认它是核心瓶颈。
## 六、建设与发展顺序
涉及建筑、科技、政策、单位或设施顺序时，应说明：
- 为什么先做这一项；
- 它解决什么当前问题；
- 达到什么条件后转向下一项；
- 哪些项目可以暂缓；
- 哪些属于陷阱投资或过早投资。

推荐顺序应围绕当前 `final_goal`，而不是机械复制固定开局模板。

存在成熟固定开局时，可以作为基准，但必须根据用户局面调整。
## 七、经济与生产循环
经营和模拟类问题重点检查：
- 输入资源是否稳定；
- 生产链是否断裂；
- 中间产品是否堆积；
- 下游是否缺料；
- 运输和物流是否成为瓶颈；
- 劳动力、空间、电力或维护成本是否限制扩张；
- 生产规模是否超过实际需求。

优化时优先解决最上游的真实瓶颈，不对所有设施等比例扩建。
## 八、扩张与发展节奏
涉及扩张时必须平衡：
- 新区域收益；
- 建设成本；
- 防守压力；
- 维护成本；
- 资源供给；
- 管理能力；
- 外交或敌对风险。

不得把“能扩张”直接等同于“应该立即扩张”。

按需说明：
- 什么条件满足后适合扩张；
- 扩张前需要准备什么；
- 扩张后优先稳定哪些系统；
- 什么情况下应暂停扩张。
## 九、战争与战略决策
涉及战争、对抗或军事扩张时重点判断：
- 当前战略目标；
- 敌我实际战力；
- 兵种/单位克制；
- 补给和生产能力；
- 地形和地图位置；
- 战争持续成本；
- 是否存在外交或经济替代方案。

不要只比较面板数值。策略游戏中的战斗建议必须考虑持续补充、资源消耗和战后收益。

具体即时操作或单场高复杂度战斗可按需结合 `combat-and-boss.md`，但整体战略仍由当前任务结构控制。
## 十、风险与安全余量
策略类长期规划应避免把资源全部投入单一路线。按需保留：
- 紧急资金；
- 防御能力；
- 关键资源库存；
- 备用产能；
- 外交余地；
- 转型空间。

但不得机械要求所有游戏都“留20%资源”等固定比例，除非有可靠机制依据。
## 十一、动态反馈与调整信号
应告诉用户哪些信号意味着当前策略需要调整，例如：
- 资源持续负增长；
- 库存长期堆积；
- 某生产线频繁停摆；
- 人口/劳动力不足；
- 敌人开始明显压制；
- 维护成本超过扩张收益；
- 科技或新系统解锁；
- 当前瓶颈已经转移。

攻略不仅要告诉用户“现在怎么做”，还应按需说明“什么时候换策略”。
## 十二、随机性与地图差异
存在随机地图、随机事件、AI行为或程序生成内容时：
- 不得把单一存档路线写成通用固定解；
- 应区分固定机制与随机局面；
- 给出判断标准和分支决策；
- 用户提供截图或局面数据时，优先针对当前局面分析。

无法确认具体随机结果时，不编造事件或地图信息。
## 十三、数值与效率计算
涉及产量、收益、成本、回本周期或效率比较时：
- 优先使用当前版本真实数值；
- 明确计算条件；
- 区分理论最大值和实际可持续值；
- 将维护、运输、失败风险等必要成本纳入判断；
- 不使用旧版本数值直接比较当前方案。

精确数值无法可靠确认时，用相对关系和条件化建议，不编造数据。
## 十四、信息密度控制
策略游戏容易产生大量变量，但攻略只保留当前决策真正相关的信息。

处理原则：
- 先给当前核心问题；
- 再给关键理由；
- 再给执行顺序；
- 最后给必要的分支条件。

不要为了“深度”把整套系统全部解释一遍，也不要让大量背景数据淹没用户下一步动作。
## 十五、与任务文件的结合
本文件只修正处理方式，不替代任务文件。
### `walkthrough`
强调阶段目标、发展顺序、转型节点和动态条件。
### `quest`
仅在策略/模拟游戏存在任务系统时，补充任务对经营状态的影响。
### `navigation`
强调战略地图、区域连接、资源点和扩张路径。
### `combat-and-boss`
强调战斗前的兵力、资源、地形和持续作战能力。
### `build`
强调兵种、卡组、单位组合或系统构筑中的资源与战略适配。
### `character-and-team`
强调英雄、指挥官或单位分工与整体战略目标。
### `puzzle`
仅在存在独立逻辑或机关问题时使用。
### `collection-and-achievement`
强调成就条件、长期路线和不可逆发展选择。
### `beginner`
强调先建立基础循环，再逐步学习复杂系统。
### `resource-and-efficiency`
强调机会成本、瓶颈、投入顺序和长期资源规划。
## 十六、视觉辅助侧重
按 `reference/media.md` 执行，优先考虑：
- 城市/基地布局；
- 生产链关系；
- 科技或发展路径；
- 战略地图；
- 资源分布；
- 兵力和区域关系；
- 简洁流程图、表格或决策树。

视觉素材必须帮助理解结构和决策，不为每个建筑或单位机械配图。
## 十七、常见错误
生成策略/模拟经营/4X攻略时禁止：
- 脱离当前局面直接给固定最优解；
- 平均优化所有系统而忽略核心瓶颈；
- 只看库存，不看收入和消耗；
- 只比较理论收益，不考虑维护、物流和机会成本；
- 把随机地图或事件的单一结果当成通用规律；
- 把后期策略直接套给前期玩家；
- 给扩张建议却忽略防守和持续成本；
- 只给一次性答案，不说明关键转向条件；
- 使用过时版本数值进行效率比较。
## 十八、完成条件
使用本文件修正攻略后确认：
- 已基于用户当前局面而不是默认局面给建议；
- 当前发展阶段判断合理；
- 核心瓶颈已经识别；
- 资源、建设和发展顺序有明确优先级；
- 方案包含必要的机会成本和风险判断；
- 动态局面有可执行的调整信号或条件分支；
- 随机因素没有被写成固定事实；
- 数值和效率判断与当前版本一致；
- 本文件只修正了主任务攻略，没有覆盖或重复主任务结构；
- 关键事实、版本和视觉素材已通过 `retrieval.md`、`media.md` 与 `quality-check.md` 校验。
