# 游戏攻略最终质量检查规则
本文件用于正式攻略生成前的放行检查。目标不是润色，而是阻止目标对象漂移、事实错误、当前环境错位、历史规则冒充现行规则、毒攻略、不可执行步骤、玩家条件不匹配、虚假图片和错误产物格式进入最终交付。

## 目录
- 检查顺序
- 内部记录
- 放行矩阵
- 六类核心痛点
- 硬失败总表
- 软质量问题
- 最终放行条件

## 一、检查顺序
按固定顺序检查；前一层存在硬失败时，返回对应阶段修正，不用后续优化掩盖核心错误。

```text
1. 目标对象与需求完整性
2. 攻略证据与验真
3. 当前环境、可用性、当前规则与历史边界
4. 毒攻略与负面反证
5. 进度与前置
6. 可执行性
7. 玩家适配
8. 剧透控制
9. 信息闭环
10. 视觉真实性与实用性
11. 输出前产物本体质检
12. 最终产物格式与内容完整性
13. 表达与可读性
```

## 二、内部记录
建议维护：

```text
hard_failures:
soft_issues:
missing_atomic_needs:
target_identity_status:
evidence_status:
current_context_status:
availability_status:
current_rule_status:
historical_compatibility_status:
progress_status:
execution_status:
player_fit_status:
spoiler_status:
visual_status:
output_status:
artifact_image_status:
final_status: pass | revise
```

存在任一硬失败时，`final_status=revise`。

## 三、放行矩阵

| 证据与验真 | 已按 `retrieval.md` 建立候选、拆解 claims、验证来源环境/独立性/目标特异性/玩家复现和 `evidence_scope` | 单一未经验证来源；高赞当证据；同源内容算多源；证据越界；相关对象/系统证据被用于目标核心结论；核心结论无目标特异性；`rejected` 进入正文 | `retrieval.md` |

| 视觉主题 | HTML和飞书使用浅色、可读、与游戏主题/目标对象/真实素材相关的主题色；记录 `theme_color_basis` 或中性降级原因 | HTML大面积深色/深渐变；配色与游戏或目标对象无关；从CG/立绘/AI图取色；为了视觉补写未验证外观或设定；无取色依据且未降级为中性浅色 | `media.md`、`output.md` |
| 产物内容 | 正文完整，事实只来自 `accepted_claims` 和条件化 `conditional_claims` | 输出层新增未验证事实；快速结论、Hero、图片说明编造；过程性自我背书 | `output.md` |
| 表达可读性 | 简洁、可扫描、标题服务执行，不堆无关百科 | 章节泛化、标题过深、步骤含糊、口号化可靠性表述、无关扩展压过答案 | `output.md` |

## 四、任务可执行性重点
| 任务 | 必须能检查 |
|---|---|
| `walkthrough` | 从当前阶段连续推进到目标阶段 |
| `quest` | 当前任务状态、前置、下一动作明确 |
| `navigation` | 从可识别起点到真实入口/目标，不能只给坐标 |
| `combat-and-boss` | 触发、前摇、站位、时机、输出窗口和失败原因明确 |
| `build` | 当前环境、用户资源、核心组件、替代方案和适用边界明确 |
| `character-and-team` | 角色定位、队伍协同、培养成本和用户已有条件明确 |
| `puzzle` | 机关状态、观察角度、交互顺序、重置/失败处理明确 |
| `collection-and-achievement` | 目标唯一性、前置、路线、遗漏点和完成确认明确 |
| `beginner` | 当前阶段优先级、资源误用风险和短期目标明确 |
| `resource-and-efficiency` | 成本、收益、机会成本、限时性和不可逆风险明确 |

## 五、六类核心痛点
- 进度错位：检查起点、任务阶段、前置和世界状态。
- 不可执行：检查每步是否有动作、对象、位置、判断标志和下一状态。
- 时效过时：检查当前环境、可用性、当前规则证据和历史边界。
- 玩家差异：检查角色、职业、装备、资源、平台、操作水平和限制。
- 剧透失控：只给完成当前目标所需信息。
- 信息碎片化：正文必须能脱离聊天独立使用。

## 六、硬失败总表
出现任一项必须返工：
- `target_identity_lock` 未锁定或全篇对象漂移。
- `verified_aliases` 未证明同一对象，或 `related_but_distinct` 被并入当前默认攻略。
- 未覆盖用户完整 `final_goal`、核心卡点或关键 `atomic_needs`。
- 时效敏感问题未确认当前有效环境和本次 `verified_at`。
- 只展示核验时间，但未用它判断当前版本、赛季、活动、池子、轮换或限时内容是否有效。
- 正式产物正文第一信息块未先展示本次核验时间/当前时间（含日期、具体时间、时区）和当前有效环境，或在时间块前先给当前状态、获取途径、推荐结论、步骤。
- 需要当前可用性判断但未建立 `availability_gate`。
- 问当前具体方法但未建立 `current_rule_snapshot`。
- 当前默认步骤的 `current_rule_evidence.status` 不是 `confirmed`。
- `supported` 方法未写条件，或 `insufficient/speculative` 方法进入步骤。
- 具体方法组件未验证 `method_environment` 和 `current_status` 就进入当前步骤。
- 旧环境活动、入口、道具、商店、掉落池、刷新池、保底机制、NPC、任务阶段或地图状态被写成当前可执行方法。
- 历史环境的常驻、池内、可刷、盒子/卡池/掉落名单、保底或刷新规则被写成当前事实。
- 当前环境只有机制存在证据，没有目标当前在池或当前可用证据，却写成当前可获得。
- 方法组件 `current_status=removed/expired/changed/uncertain`，却进入当前操作流程。
- 当前不可用却输出历史方法为当前步骤。
- 当前没有可执行途径或当前方法未确认时，仍生成 Step 01/02/03 式确定流程。
- 历史方法使用步骤卡、编号流程、操作流程、推荐路线、效率技巧、FAQ操作建议或祈使句呈现。
- 当前不可用时，标题、副标题、Hero或模块标题仍写成“抓捕攻略、刷取指南、定向获取、当前刷法”等当前执行口吻。
- `insufficient`、疑似过期或未确认当前仍有效的攻略被写成当前确定步骤、默认路线、推荐刷法或现行获取攻略。
- 只找到历史攻略或过往视频，却未标“历史攻略，当前不可执行”“疑似过期，未确认当前仍有效”或“未找到可靠当前攻略”。
- 未达到候选攻略池最低要求时，没有说明搜索范围、已确认内容和证据缺口。
- 正文第一信息块后没有先给总述模块，或总述晚于详细步骤、路线、机制、Build、表格、排查。
- 总述模块只是“下面详细说明”“本文将介绍”等空泛导语，没有概括核心结论、适用条件、执行主线、第一动作、关键风险或完成标志中的关键项。
- 总述包含后文没有展开或证据不支持的判断。
- 历史规则未达到 `temporal_compatibility=verified_current` 却用于当前规则。
- 只有通用机制证据，没有目标特异性证据。
- 只有相关对象、相关形态、进化阶段、外观/皮肤、资质/词条、强化状态、技能槽、同家族对象、活动变体或地图状态证据，却写成当前目标的获取、触发、解锁、保底、掉落、入口、Build 或当前可用性事实。
- 核心攻略来自单一未经验证来源，或同源转载被当成多源。
- 未查明显争议方案的负面反馈。
- 多个独立玩家当前无法复现且无法解释，仍推荐该方案。
- `rejected_claims`、未验证事实或输出层新增事实进入正文。
- 前置、进度、资源、角色、平台或难度与用户条件不匹配。
- 步骤不可执行、缺起点/入口/阶段/成功标志。
- 使用虚假、生成、CG、立绘、同人、MOD/私服或错误版本图片。
- HTML或飞书主题色来自宣传CG、立绘、同人图、AI图，或没有任何真实游戏视觉依据且未使用中性浅色降级。
- HTML使用大面积深色背景、深色渐变、强压暗背景，导致阅读性差或与游戏目标无关。
- 飞书文档未实际插入任何经过验证且对执行有帮助的真实游戏图片。
- 飞书文档只有图片链接、占位符、搜索结果页、文件名或“未找到图片”说明，没有真实图片块。
- 图片集中堆在文末，未放在对应关键信息、路线节点、机制说明或对象识别旁边。
- 飞书文档在 `visual_need=required/recommended` 时用文字降级替代配图交付。
- 地图/路线/去哪找/入口/NPC/隐藏点/收集品类攻略缺少地图定位图或入口/地标实机图，且图片缺口会影响执行。
- 精灵/怪物/宠物/道具/装备/技能类攻略缺少目标识别图或真实 UI 图，导致用户无法确认对象。
- Boss/机制/解谜/站位类攻略缺少关键帧、场地图、机关图或 UI 图，且文字无法可靠替代视觉判断。
- 最终未实际生成飞书文档或HTML完整产物。
- 输出前产物本体质检未确认至少 1 个真实图片块，或只检查了素材计划而未检查最终产物。
- 用户未指定HTML时，未实际尝试飞书创建/更新命令就直接生成HTML。
- 飞书可创建但因排版、图片、耗时、缺少父文件夹token或未读取lark文档而直接HTML备用。
- HTML备用未记录严格飞书失败证据，或未说明已尝试的飞书命令类型和失败原因。
- 飞书文档只有普通段落、Markdown残留或链接堆砌，没有使用高亮块、分栏、步骤卡、表格等可扫描排版承载关键信息。
- 飞书分栏未使用 lark-cli Docx XML 的 `<grid>` + `<column width-ratio="...">`，或 `width-ratio` 总和明显不为 `1`。
- 飞书关键步骤有图片却没有就近放置，也没有使用“左图右字/左字右图”的 `<grid>` 图文分栏承载步骤。
- 飞书高亮块未使用有效 `<callout emoji="..." background-color="..." border-color="..." text-color="...">`，或全文只重复同一种 emoji/颜色样式。
- 飞书高亮块只是装饰，未承载“当前状态、先做什么、风险/前置/旧方法、完成标志”等真实攻略状态。
- 使用 emoji、颜色或 XML 风格代码块包装未验证结论，造成读者误以为内容已确认。
- 飞书文档使用 XML 风格代码块时写入未验证的掉率、保底、活动ID、NPC编号、道具ID或其他伪系统事实。

## 七、软质量问题
以下不一定阻止交付，但应尽量修正：
- 结构过度模板化；
- 标题泛化或层级过深；
- 图片数量偏多但帮助有限；
- 失败排查不够靠前；
- 条件方案表达不够醒目；
- 术语未面向用户水平解释；
- 结尾缺完成确认或下一步。

## 八、最终放行条件
只有同时满足以下条件才能交付：
- `final_status=pass`；
- 无 `hard_failures`；
- 关键 `soft_issues` 已修正或不影响执行；
- 正文只使用 `accepted_claims` 和写清条件的 `conditional_claims`；
- 当前环境、当前可用性、当前规则和历史边界表达一致；
- 正文按“第一信息块 → 总述模块 → 详细展开”的顺序组织；
- 输出前产物本体质检已确认至少 1 张经过验证且对执行有帮助的真实游戏图片实际存在；
- 图片真实、适用、位置正确，且靠近对应步骤或关键信息；
- 飞书文档或HTML可独立阅读并完成用户目标。
