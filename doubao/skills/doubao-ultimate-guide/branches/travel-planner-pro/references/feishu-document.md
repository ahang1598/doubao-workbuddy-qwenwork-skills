# 飞书旅行文档补充规范

本四合一版本中，飞书旅行文档的唯一交付契约是 `references/feishu-workflow.md`。如果本文件与 `feishu-workflow.md` 有冲突，一律以后者为准。

## 核心原则

- 正文第一屏不重复飞书标题区的标题，不写“默认假设”，直接进入路线结论、住宿取舍、最大风险或场景化入口。
- 旅游攻略主线是：怎么走、住哪里、每天怎么玩、怎么吃、怎么订、预算多少、出发前复查什么。
- 雨天、疲劳、堵车、排队、预约失败等是辅助兜底，只在真正影响主线时就近写 1-2 条，不做固定大模块。
- 本四合一版本不搜图、不生图、不插图；不要写图片说明、图片来源、图片锚点、`image-plan.tsv` 或 `media-insert`。
- 文末不做“来源/信息来源/参考资料”章节。来源、官方入口、票务入口、地图入口和复查动作放在对应事实附近。
- 不暴露 skill、工具命令、认证、权限、fallback、XML 注释或内部字段。

## 组件使用

只使用 `feishu-workflow.md` 白名单组件：`title/h1/h2/h3/p/b/i/br/callout/grid/column/table/thead/tbody/tr/th/td/checkbox/bookmark/blockquote/hr`。

- `callout`：路线结论、天气/预约提醒、关键风险。
- `grid`：住宿区域对比、路线取舍、预算档位、美食点单卡、场景 Q&A。
- `table`：路线总览、Day 时段、预算、交通、预订时间线。
- `checkbox`：出发前复查、预订清单、证件和打包。
- `bookmark`：只放真实可打开 URL。
- `blockquote`：动态价格、适用边界、官方复查提醒。

不要自造 `<card>`、`<timeline>`、`<badge>`、`<section>` 等标签；所谓路线卡、美食卡、预算卡，都用 `callout + grid + table` 组合表达。

## 链接规则

- 只有确认真实可打开的 URL 才写 `<bookmark>`。
- 禁止空链接、占位链接、example.com、猜测官网、猜测店铺链接。
- 官方小程序、公众号、App 或地图入口无法确认网页 URL 时，不写 bookmark，改写执行路径：例如“打开微信搜索官方小程序：___”“打开大众点评/美团搜索：城市 + 店名/菜品/商圈”“打开地图搜索：___”。
- 美食模块可以使用美团、大众点评、地图或餐厅官方入口；具体餐厅页面 URL 未确认时，只写平台搜索路径。

## 质量自检

- 用户 30 秒内能看懂最顺路线、住哪里、最大风险吗？
- Day 1 能直接照着走吗：时段、交通、用餐、预约、可删减项是否清楚？
- 住宿、交通、美食、预算和预订是否闭环？
- 天气和现场变化是否服务主路线，而不是抢占主体篇幅？
- 文档是否有 callout/grid/table/checkbox/bookmark/blockquote 的层次，而不是全篇列表或表格？
- 链接是否真实可打开；不能确认的是否改成平台搜索路径？
