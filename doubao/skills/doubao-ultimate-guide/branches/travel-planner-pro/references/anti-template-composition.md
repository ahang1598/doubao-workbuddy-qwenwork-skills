## 目的

让每份旅行攻略像“为这次旅行专门做的路书”，而不是把同一套“结论 -> 路线总览 -> 分日安排 -> 住宿 -> 美食 -> 预算 -> 风险”换个目的地。稳定的是可执行、可核验、可复查；变化的是首屏、标题、章节顺序、视觉重点和取舍逻辑。

生成前必须先在内部完成“旅行场景指纹”，再写文档。

## 旅行场景指纹

内部判断 6 件事，不要原样写进正文：

1. 用户真正要解决的问题：初访省心、周末活动、美食、亲子老人、自驾、出境、户外、预算省钱、短暂停留、行程审查、目的地选择。
2. 用户原话里的专属词：目的地、天数、日期、同行人、预算、节假日、兴趣、交通方式、限制条件。
3. 第一屏必须先回答什么：是不是值得去、住哪里最顺、哪条路线最合适、最大风险是什么、哪件事必须提前订。
4. 本文像哪种材料：初访路书、美食地图、周末活动雷达、自驾驾驶日历、亲子舒适手册、出境准备清单、中转时间账、预算决策表。
5. 哪些模块是主角：路线、活动、美食、住宿、交通、预算、证件、安全、图片地图、预订路径。主角展开，配角合并。
6. 视觉承担什么功能：认路、识别景点、点单、预算判断、避坑、路线记忆，还是只需要链接卡。

如果第一屏不能直接回答用户最关心的问题，说明还在套模板，必须重排。

## 标题去同质化

`<title>` 不要默认写成 `XX旅游攻略`、`XX几日游攻略`、`XX旅行计划`。除非用户明确要求“攻略”二字，优先使用更贴合场景的标题形态：

- 初访路线：`第一次去南京的 3 天 2 夜省心路线`
- 美食主题：`顺着老城街区吃的潮州美食地图`
- 周末短途：`杭州周末展览与 city walk 雷达`
- 亲子老人：`带老人慢游苏州的低步行路书`
- 自驾：`北疆自驾环线驾驶日历`
- 出境：`东京 5 日自由行证件交通与街区路线`
- 中转：`上海虹桥 6 小时短停时间账`
- 预算：`5000 元内去成都的机酒和玩法决策表`

标题必须包含至少 1 个用户专属词或明确同义词。不要连续多个文档都用同一后缀；可轮换“路线、路书、地图、雷达、日历、清单、时间账、决策表、手册、玩法”等。

正文开头不要复制标题，不要以“默认假设/当前假设”开场。`<title>` 后优先进入结论 callout、路线一句话、取舍说明、风险提醒，或在图片确有价值时进入代表图。

## 首屏决定顺序

| 场景 | 第一屏优先回答 | 不要第一屏变成 |
|---|---|---|
| 城市初访 | 玩几天、住哪里、最顺路线、最大坑 | 城市百科 |
| 周末/近期 | 这个周末最值得做什么、活动日期、票务风险 | 经典景点大全 |
| 美食主题 | 住哪里方便吃、按什么街区/时段吃 | 景点路线先行 |
| 亲子/老人 | 步行强度、午休、厕所电梯、室内备选 | 高密度打卡 |
| 自驾 | 每天驾驶强度、补给停车、撤退方案 | 景点堆叠 |
| 出境 | 签证入境、支付通信、城市交通 | 只列景点 |
| 中转短停 | 是否建议进城、保守/进取路线、最晚撤退时间 | 普通半日游 |
| 预算省钱 | 总成本、现金/优惠/积分取舍、预订路径 | 空泛省钱技巧 |
| 行程审查 | 哪些保留、哪些删改、为什么不可行 | 重写一份泛攻略 |

## 章节标题规则

H2 标题必须具体到本次旅行。至少 60% 的 H2 要包含目的地、天数/日期、街区/交通/人群/预算/活动等场景词，或明确的动作动词。

避免直接使用这些泛标题：

- 先给结论
- 路线总览
- 分日安排
- 住哪里
- 吃什么
- 交通
- 预算
- 风险与备选
- 出发前准备
- 信息来源
- 常见问题
- 写在最后

如果需要表达这些信息，改成场景标题：

- `路线总览` -> `3 天都围着秦淮和玄武湖走，少跨区`
- `住哪里` -> `第一次去南京优先住新街口或夫子庙北侧`
- `吃什么` -> `老城早餐和夜宵不要跨区找`
- `预算` -> `5000 元预算先保住宿和交通舒适度`
- `风险与备选` -> `下雨或排队时，把城墙换成博物馆`
- `常见问题` -> `周末排队和闭馆最容易卡住的 5 件事`

泛标题不是绝对禁止，但全篇不能成套出现。H2 泛标题超过 2 个时必须重写。

## 模块组合规则

- 主角模块要有取舍理由、执行表、备选和复查动作。
- 配角模块合并为 grid、callout、表格一列、checkbox 或来源引用。
- 不要每篇都固定“住宿/交通/美食/预算”独立成章；如果用户问美食，住宿和交通为美食路线服务；如果用户问自驾，美食只作为补给和落脚点。
- 每个 Day 不能只有上午/下午/晚上景点名；至少有今日主线、交通/步行、用餐落点、预约/排队提醒、可删减项和雨天/疲劳备选。
- 视觉卡要和主线绑定。城市初访优先路线图/住宿区域图；美食主题优先点单图鉴；自驾优先驾驶日历和补给卡；亲子老人优先低步行和室内备选卡。

## 反模板自检

创建飞书文档前做内部自检：

- 标题是否只是 `XX旅游攻略/XX旅行计划`？如果是，重写。
- 第一屏是否直接回答用户最关心的问题？如果先讲百科或默认假设，重排。
- H2 泛标题是否超过 2 个？如果超过，改成场景化标题。
- 章节顺序是否和通用模板高度一致？如果是，把用户核心痛点前置。
- 用户原话里的目的地、天数、日期、同行人、预算或兴趣是否出现在标题和多个 H2 中？如果没有，文档不够专属。
- 是否所有 Day 的结构完全一样且内容只有短列表？如果是，为每天补不同主线、取舍、用餐和备选。
- 是否为了图片压缩了正文？如果是，补回路线细节和预订风险。

| 呼和浩特端午 | 端午去呼和浩特的草原与老城路线 |

| 潮州美食 | 顺着牌坊街吃的潮州美食地图 |
| 亲子上海 | 带娃玩上海的低排队亲子手册 |

| 东京出境 | 东京 5 日街区自由行与出发清单 |
