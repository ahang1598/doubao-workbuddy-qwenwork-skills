# 目的地选择

当用户不知道去哪、只给出大区域、季节、天数或同行人画像时，读取本文件。

## 流程

1. 只澄清真正影响决策的约束：出发城市、日期/月度、天数、同行人和硬预算。
2. 当区域很宽或季节影响很大时，必须基于当前搜索建立候选目的地，而不是只凭记忆预设。
3. 按季节匹配、交通可行性、人群适配和风险过滤候选地。
4. 对 3-5 个最终候选地做横向对比，并给出明确推荐、淘汰理由和下一步。
5. 除非某个选择明显胜出，否则先让用户选定目的地，再写完整行程。

## 候选目的地发现

搜索模式：

```text
[区域] [月份] 旅游目的地 [天数]
[出发地] 出发 [区域] [天数] 天游
[区域] 亲子游 / 老人友好 / 自驾 / 徒步
[区域] 雨季 / 台风季 / 雪季 / 花期 / 枯水期
```

国内目的地可优先使用这些关键词：

```text
[区域] [月份] 旅游推荐
[出发地] 出发 [区域] [天数] 天游
[区域] 亲子游 老人友好 自驾 攻略
[目的地] [月份] 花期 枯水期 雨季 台风
```

## 筛选维度

| 维度 | 需要判断的问题 |
|---|---|
| 交通 | 用户到达是否方便？会不会把太多时间浪费在路上？ |
| 天气 | 出行日期是最佳季、平季还是风险季？ |
| 人流 | 是否遇到公众假期、大型活动或明显旺季？ |
| 人群适配 | 是否适合亲子、老人、独旅、夜生活、户外或无障碍需求？ |
| 成本 | 住宿和交通是否符合预算？ |
| 丰富度 | 目的地内容是否撑得起用户的旅行天数？ |
| 预订风险 | 是否存在许可证、火车票、酒店或热门项目紧张的问题？ |
| 攻略丰富度 | 是否值得专门做图文路书，还是只适合短途轻攻略？ |
| 替代弹性 | 下雨、人多、交通失败时是否有室内或近距离备选？ |

## 不要做

- 不要只按“热门程度”推荐目的地。
- 不要忽略出发地交通成本。
- 不要在雨季、高温、台风、雪季、海拔、节假日等风险明显时只写优点。
- 不要给 10 个候选地让用户自己筛。先过滤到 3-5 个。
