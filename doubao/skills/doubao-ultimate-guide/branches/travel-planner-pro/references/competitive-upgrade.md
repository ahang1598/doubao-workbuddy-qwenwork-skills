当用户请求周末城市短途、近期活动调研、机票酒店预算、积分里程、低价玩法、地图点位、城市调查或多来源比价时，读取本文件。目标是吸收开源旅行技能中可复用的强能力，同时保持本 skill 的默认飞书路书优势。

不要在用户文档中写竞品名、开源项目名、内部工具名或安装命令。只体现更强的调研、比价、预订和韧性。

## 一、周末城市短途调研

适用场景：

- “本周末/下周末去 X 怎么玩”
- “X 城市周末去哪”
- “X 最近有什么活动/展览/演出/集市”
- “调研一下 X 城市”
- “X city walk / 美食街 / 地铁路线 / 优惠门票”

### 时间锁定

必须把相对时间转成绝对日期：

| 用户表达 | 处理 |
|---|---|
| 本周末 | 当前日期之后最近的周六周日 |
| 下周末 | 下一个完整周六周日 |
| 未来一个月 | 从当前日期起 30 天 |
| 节假日 | 查询当前年份放假日期，写明绝对日期 |

活动推荐看“活动举办日期”，不是文章发布时间。过期活动必须删除；长期活动要写覆盖时段。

### 调研方向

根据城市规模和用户偏好选择，不要机械全放。短途城市攻略优先覆盖：

- 演出/演唱会/音乐节/脱口秀/剧场。
- 集市/市集/夜市/文化节。
- 球赛/体育赛事。
- 博物馆/美术馆/当前展览。
- 5A/4A 景区、城市公园、免费打卡点。
- 优惠门票、学生/亲子/夜游/联票规则。
- 美食街、老字号、夜宵区。
- city walk 路线：节点、长度、时长、拍照点和撤退点。
- 地铁路线、关键站点出口、商圈直达性。
- 新开业/主题店/购物中心，只在用户偏好或路线需要时加入。

### 信息密度门槛

周末城市调研要避免“只有三四个泛泛推荐”。最低要求：

| 模块 | 最低要求 | 优秀标准 |
|---|---|---|
| 近期活动/演出 | 2-3 个 | 5 个以上，含时间、场馆、票务 |
| 博物馆/展览 | 2 个 | 4 个以上，含当前展览和预约 |
| 美食街/街区 | 2 条 | 4 条以上，含代表店和交通 |
| city walk | 1 条具体路线 | 2 条以上，含节点、长度、时长 |
| 优惠门票 | 2 个 | 4 个以上，含规则和有效期 |
| 地铁/交通 | 关键站点 | 站点出口、末班车或换乘提醒 |

如果某模块低于最低要求，要补查；如果仍找不到，明确写“未找到可靠近期信息”，不要硬编。

### 周末短途文档结构

不要套普通多日游目录。建议结构：

```markdown
## 这个周末最值得做的 3 件事
| 排名 | 活动/路线 | 时间 | 区域 | 适合谁 | 风险 |

## 周末一图速览
活动、展览、美食街、city walk、地铁和预算摘要。

## 两条可执行路线
轻松版 / 紧凑版，或 文艺展览线 / 美食 city walk 线。

## 近期活动清单
含时间、地点、票务/预约、交通、是否适合放进主线。

## 吃逛和交通
按街区组织，不跨区找饭。

## 预订与出发前复查
票务、天气、地铁末班、活动变更。
```

## 二、机酒预算与预订路径

适用场景：

- “怎么订更便宜”
- “机票酒店怎么选”
- “预算 X 能不能去”
- “现金还是积分/里程”
- “穷游/省钱/低价/错峰”

### 成本矩阵

预算型攻略必须展示排序后的 3-5 个方案，不要列十几个选项。每个方案要有：

| 字段 | 说明 |
|---|---|
| 总成本 | 大交通 + 住宿 + 当地交通 + 门票体验 + 餐饮 |
| 现金支出 | 用户需要真实支付的金额 |
| 积分/里程/优惠 | 如涉及，写有效成本和限制 |
| 便利度 | 直达、转机、位置、行李、退改 |
| 风险 | 库存、取消政策、夜航、转机、隐藏费用 |
| 推荐理由 | 为什么排这个位置 |

推荐排序优先：总体验与风险平衡，而不是单纯最低价。最低价如果有凌晨到达、自行转机、不可退、无托运行李、离核心区远，必须写清。

### 现金 vs 积分/里程

如果用户提到积分/里程/信用卡点数：

- 不推荐用户先转点再找票。先确认库存、可出票和规则，再考虑转点。
- 写清税费、燃油附加费、转点不可逆、库存变化和退改成本。
- 如果没有可靠实时库存，只能写“思路”和“复查动作”，不能声称有票。
- 对小额差异不要过度优化；若两个方案接近，优先推荐更少折腾、更稳的方案。

### 预订路径

每个核心推荐都要有下一步：

- 从哪里订：官方、OTA、票务平台、酒店官网、航空公司、景区官方。
- 何时订：现在订、7 天前、48 小时前复查、当天确认。
- 先确认什么：库存、退改、行李、儿童票、证件、入场时段、支付方式。
- 失败怎么办：无票、涨价、天气取消、酒店无房的替代方案。

## 三、酒店与住宿比较

住宿建议不要只写“住市中心”。当用户需要酒店、预算或住宿区域时，做区域 + 具体选择两层判断。

### 区域矩阵

| 区域 | 适合谁 | 通勤逻辑 | 优点 | 缺点 | 风险 |
|---|---|---|---|---|---|

### 住宿选项矩阵

| 方案 | 位置 | 价格可靠度 | 适合谁 | 主要收益 | 主要风险 |
|---|---|---|---|---|---|

比较酒店、公寓和民宿时要考虑：

- 1-2 晚短住：位置、交通、早餐和退房便利通常比房间面积更重要。
- 5 晚以上或家庭出行：厨房、洗衣、房间数和取消政策可能更重要。
- 演唱会/展会/节假日：离场馆或交通枢纽近，且提前锁价更重要。
- 深夜到达：前台、打车、周边安全和自助入住风险。

## 四、地图点位与路线可视化

当用户要地图、路线、city walk、自驾、周末城市调查或图文路书时，内部维护地点清单。

地点清单字段：

```text
name / address_or_area / type / belongs_to_day / why_in_route / time_window / risk / source
```

地点类型建议：

| 类型 | 例子 | 用途 |
|---|---|---|
| 景点 | 博物馆、古城、景区 | 主线点位 |
| 活动 | 演唱会、集市、展览 | 时效点位 |
| 餐饮 | 美食街、餐厅、夜市 | 用餐落点 |
| 交通 | 机场、高铁站、地铁站 | 转场和住宿判断 |
| 住宿 | 推荐区域、酒店片区 | 通勤判断 |
| 购物/休息 | 商场、咖啡、亲子空间 | 雨天和疲劳备选 |

抽取地点时排除：菜名、活动主题、抽象描述、纯路线名。地图或路线图只放真实地点。

飞书文档中至少体现一种可视化入口：

- 生成/插入路线图或手绘地图。
- 插入地图链接卡。
- 用路线总览表 + 地点清单 + city walk 节点表替代。

## 五、隐藏亮点与非模板化体验

当普通攻略容易同质化时，加入 1 个“额外惊喜层”，但不能影响主线可执行性：

- 小众博物馆/街区/市场/观景点。
- 老建筑、非遗、独立书店、艺术空间。
- 适合雨天/夜间/独处的低风险点。
- 本地人常去但游客不一定知道的街区。

规则：

- 小众点必须说明为什么值得去、放在哪天顺路、如果时间不够是否删掉。
- 不用“冷门宝藏”这类空话；给具体体验价值。
- 不把偏远小众点硬塞进短行程主线。

## 六、搜索失败与 fallback

不要因为一个来源失败就降级为泛泛攻略。每类事实至少准备一个 fallback。

| 事实类型 | 首选 | fallback |
|---|---|---|
| 活动/演出 | 官方场馆、票务、文旅 | 本地媒体、演出聚合平台 |
| 门票/预约 | 景区/博物馆官方 | 官方小程序、票务平台，标注需复查 |
| 交通 | 运营方/官方交通 | 地图/LBS、票务平台 |
| 酒店价格 | 酒店官网/OTA 当前价 | 多平台区间，标注参考 |
| 航班/火车 | 运营方/官方票务 | OTA/聚合搜索，标注动态 |
| 餐饮口碑 | 点评/地图/近期社区交叉 | 只推荐区域和菜品，不硬推单店 |
| 小众点 | 官方/旅游局/可靠媒体 | 多源交叉，无法确认则放备选 |

最终文档要保留来源状态：

- 成功核验：写具体结论和来源。
- 部分核验：写可靠度和复查动作。
- 未核验：不要写成事实；放入“仍需确认”。

## 七、优于竞品的交付要求

为了明显优于只做周末调研或只做机酒比价的 skill，最终攻略必须同时满足：

- 有旅游攻略的完整体验：路线、住宿、交通、美食、预算、风险、备选。
- 有周末调研的时效层：近期活动、展览、优惠、city walk 或地铁可达性。
- 有预订策略：成本矩阵、预订路径、退改/库存/失败 fallback。
- 有飞书文档体验：富文本、表格、callout、checkbox、grid、bookmark；图片/视觉卡或地图链接卡按用户价值加入。
- 有质量检查：不静默忽略失败来源，不把过期或单源信息写成确定事实。
