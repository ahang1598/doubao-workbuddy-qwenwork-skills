# 开源旅游 Skill 能力参考

用于吸收开源旅行技能的能力启发。不要在最终攻略里堆项目名或安装命令；这些内容只帮助内部判断“该补什么能力”。

## 能力地图

| 开源方向 | 可借鉴能力 | 攻略中应体现 |
|---|---|---|
| Spring AI Alibaba / LangChain Travel Agent | ReAct/FunctionCall、多工具编排、RAG 资料检索 | 先核验事实，再做路线决策；不要凭空写票价和开放时间 |
| AMap LBS / 地图技能 | POI 搜索、周边检索、路线规划、交通耗时、地图可视化 | 按地理聚类排 Day，不跨区乱跳；给路线图或交通卡 |
| FlyAI / 机票酒店景点全链路 | 航班、酒店、景点、价格、库存、预订链路 | 动态价格和库存必须标注可靠度和复查动作 |
| travel-companion / 多人协同 | 共同偏好、候选投票、共享行程、待办和分账 | 多人旅行要处理偏好冲突、预算分摊、预订责任人 |
| TRAE/Dify Prompt Skill | 零代码提示词结构化 | 给弱模型明确步骤、模板和禁止项 |
| 小程序/网站攻略系统 | 地图视图、收藏、路线、预算、图文展示 | 飞书文档要像产品化路书，不只是长文 |
| travel-hacking / 里程穷游 | 机票里程、低价日历、住宿积分、现金 vs 积分、预订路径、fallback | 穷游/机票预算问题要给成本矩阵、省钱路径、退改/库存风险和下一步预订动作 |
| weekend-city-trip / 城市短途调研 | 周末活动、演出展览、优惠门票、city walk、地铁出口、地图点位、补查询 | 近期城市攻略要锁定绝对日期，覆盖活动和可达性，质量不足时补查 |

## 何时触发这些能力

- 用户提到“路线怎么走、附近、顺路、地图、自驾、公共交通”：强调 LBS 思维，必要时联网查 POI、地图、交通时间。
- 用户提到“机票、酒店、价格、门票、预约、什么时候订”：强调动态库存和价格核验。
- 用户提到“周末、近期、下周末、一个月内、演出、展览、集市、city walk”：强调近期城市调研，核验活动举办日期和地点。
- 用户提到“多人、同事、朋友、投票、预算分摊”：加入协同清单、待确认事项、责任人表。
- 用户提到“穷游、里程、便宜、机票怎么省”：加入低价窗口、错峰、机场选择、行李限制、里程/积分思路。
- 用户提到“做成文档/路书/图文攻略/分享给朋友”：强化飞书文档、预订清单和可分享排版；路线图、时间轴卡只在能帮助认路、扫读或决策时加入。

## 工具优先级

联网和工具可用时，按事实类型选择来源：

- POI/路线：地图服务、官方交通、城市交通官网、景区官方交通说明。
- 航班/酒店：航司/机场/OTA 价格只作动态参考，最终提醒锁价和取消政策。
- 门票/预约：景区、博物馆、剧院、国家公园或官方票务。
- 当地体验：旅游局、近期可靠媒体、多个社区平台交叉判断。
- 美食口碑：点评/地图/小红书只用于近期体验、排队、菜品形态和差评点，不作为官方事实。
- 搜索失败：至少尝试一个替代来源；无法核验时明确写来源缺口和复查动作，不静默省略。

## 不能做

- 不把开源项目名写进用户攻略，除非用户在问技术实现。
- 不声称已调用某个地图、机票或酒店 API，除非真的调用了。
- 不用单个社区帖子决定路线、价格、开放时间或安全规则。
- 不把“推荐景点列表”当成行程规划；路线必须通过时间、交通和体力检查。
- 不把动态价格写死为确定价格；使用 `实查`、`参考`、`估算` 标签。

## 输出增强清单

从这些开源能力抽象后，完整攻略尽量加入：

- 地理聚类路线表。
- POI/景点取舍理由。
- 当日交通段耗时和费用。
- 住宿区域选择矩阵。
- 预订时间线。
- 预算可靠度标签。
- 现金/积分/优惠/便利度/风险成本矩阵。
- 具体预订路径和失败 fallback。
- 周末近期活动和 city walk 节点表。
- 雨天/拥挤/疲劳/预约失败备选。
- 共享待办和多人偏好确认表。
- 路线图、时间轴卡、美食图鉴或预算卡。
