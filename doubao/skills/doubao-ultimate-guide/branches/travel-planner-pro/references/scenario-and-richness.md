本文件合并了反模板构图规则和内容丰富度要求。**用途**：让每份旅行攻略像“为这次旅行专门做的路书”，而不是把同一套“结论→路线→分日→住宿→美食→预算→风险”换个目的地；同时让攻略像能带出门的路书而非景点清单。格式契约（XML/富 block/图片底线）见 `feishu-workflow.md`；本文件管的是**标题、首屏、章节顺序、取舍逻辑、内容厚度**。

## 1. 旅行场景指纹（生成前先做，不写进正文）

内部判断 6 件事：

1. 用户真正要解决的问题：初访省心 / 周末活动 / 美食 / 亲子老人 / 自驾 / 出境 / 户外 / 预算省钱 / 短暂停留 / 行程审查 / 目的地选择。
2. 用户原话专属词：目的地、天数、日期、同行人、预算、节假日、兴趣、交通方式、限制条件。
3. 第一屏必须先回答什么：值不值得去、住哪里最顺、哪条路线最合适、最大风险、哪件事必须提前订。
4. 本文像哪种材料：初访路书 / 美食地图 / 周末活动雷达 / 自驾驾驶日历 / 亲子舒适手册 / 出境准备清单 / 中转时间账 / 预算决策表。
5. 哪些模块是主角（展开），哪些是配角（合并为 grid/callout/checkbox/来源引用）。
6. 视觉承担什么功能：认路 / 识别景点 / 点单 / 预算判断 / 避坑 / 路线记忆，还是只需链接卡。

**如果第一屏不能直接回答用户最关心的问题，说明还在套模板，必须重排。**

## 2. 标题生成公式

`<title>` 不要默认 `XX旅游攻略/XX几日游攻略/XX旅行计划`。除非用户明确要“攻略”二字，从下面公式选一个，替换占位符即可用：

| 公式 | 示例 |
|---|---|
| `第一次去{目的地}的{N}天{N}夜省心路线` | 第一次去南京的 3 天 2 夜省心路线 |
| `顺着{街区}吃的{目的地}美食地图` | 顺着牌坊街吃的潮州美食地图 |
| `{城市}周末展览与 city walk 雷达` | 杭州周末展览与西湖 city walk 雷达 |
| `带{人群}慢游{目的地}的低步行路书` | 带老人慢游苏州的低步行路书 |
| `{区域}自驾环线驾驶日历` | 北疆自驾环线驾驶日历 |
| `{城市}{N}日自由行证件交通与街区路线` | 东京 5 日自由行证件交通与街区路线 |
| `{机场/车站}{N}小时短停时间账` | 上海虹桥 6 小时短停时间账 |
| `{预算}元内去{目的地}的机酒和玩法决策表` | 5000 元内去成都的机酒和玩法决策表 |
| `{目的地}{N}日小众慢游路书` | 定州古城 2 日小众慢游路书 |

标题必须含至少 1 个用户专属词或明确同义词。不要连续多个文档用同一后缀；轮换“路线、路书、地图、雷达、日历、清单、时间账、决策表、手册、玩法”。正文开头不复制标题、不写“默认假设”，`<title>` 后优先进结论 callout / 路线一句话 / 取舍说明 / 风险提醒。

## 3. 首屏决定顺序

| 场景 | 第一屏优先回答 | 不要第一屏变成 |
|---|---|---|
| 城市初访 | 玩几天、住哪里、最顺路线、最大坑 | 城市百科 |
| 周末/近期 | 这个周末最值得做什么、活动日期、票务风险 | 经典景点大全 |
| 美食主题 | 住哪里方便吃、按什么街区/时段吃 | 景点路线先行 |
| 亲子/老人 | 步行强度、午休、厕所电梯、室内备选 | 高密度打卡 |
| 自驾 | 每天驾驶强度、补给停车、撤退方案 | 景点堆叠 |
| 出境 | 签证入境、支付通信、城市交通 | 只列景点 |
| 中转短停 | 是否建议进城、保守/进取路线、最晚撤退时间 | 普通半日游 |
| 预算省钱 | 总成本、现金/优惠/积分取舍、预订路径 | 空泛省钱技巧 |
| 行程审查 | 哪些保留、哪些删改、为什么不可行 | 重写一份泛攻略 |

## 4. H2 规则与模块组合

- H2 标题具体到本次旅行。**至少 60% 的 H2 含目的地/天数/街区/交通/人群/预算/活动等场景词或明确动词。**
- **H2 泛标题不超过 2 个。** 避免直接用：先给结论、路线总览、分日安排、住哪里、吃什么、交通、预算、风险与备选、出发前准备、信息来源、常见问题、写在最后。
- 必须用泛信息时改成场景标题：`路线总览`→`3 天都围着秦淮和玄武湖走，少跨区`；`住哪里`→`第一次去南京优先住新街口或夫子庙北侧`；`吃什么`→`老城早餐和夜宵不要跨区找`；`预算`→`5000 元预算先保住宿和交通舒适度`；`风险与备选`→`下雨或排队时，把城墙换成博物馆`。
- 主角模块要有取舍理由、执行表、备选和复查动作。配角模块合并为 grid/callout/表格一列/checkbox/来源引用。
- 不要每篇固定“住宿/交通/美食/预算”独立成章：用户问美食，住宿和交通为美食路线服务；用户问自驾，美食只作补给和落脚点。
- 每个 Day 不能只有上午/下午/晚上景点名；至少有今日主线、交通/步行、用餐落点、预约/排队提醒、可删减项、雨天/疲劳备选。

## 5. 反模板自检（创建前过一遍）

- [ ] 标题不是 `XX旅游攻略/XX旅行计划`？含专属词？
- [ ] 第一屏直接答用户最关心的，没先讲百科或默认假设？
- [ ] H2 泛标题 ≤2 个？
- [ ] 章节顺序不和通用模板高度一致？用户核心痛点前置？
- [ ] 用户原话的目的地/天数/日期/同行人/预算/兴趣出现在标题和多个 H2？
- [ ] 所有 Day 结构不全相同且不只有短列表？每天有不同主线/取舍/用餐/备选？
- [ ] 没为了图片压缩正文？

## 6. 8 类内容丰富度（按场景选，不全堆）

### ① 取舍说明

每条路线说明为什么这样排：为什么住这个区域而非更便宜/更热闹的；为什么某热门点不放主线；为什么上午/下午这样安排；为什么美食放这天这区不跨区找；为什么亲子/老人要删点、午休或打车。

> Day 2 不把博物馆和远郊景区放一起，因为两者方向相反，排队和转场会吃掉午后时间。

### ② 每日主线和撤退点

每个 Day 有：今日主线（最想完成的体验）/ 今日高光（最值得保留的 1–2 个点）/ 可删减项（太累/排队/下雨先删哪个）/ 撤退方案（改去哪、怎么回酒店、晚餐是否换区）。

### ③ 交通和步行体感

不只写“乘地铁前往”。给：转场耗时 / 步行强度（低中高或“全天约 1.5–2 万步”）/ 打车地铁步行取舍 / 高峰、末班、停车、行李寄存、换乘风险。

### ④ 美食点单和排队替代

美食攻略让用户知道怎么吃，不只知店名：招牌/点单组合 / 适合几人、口味、忌口、是否油腻辛辣甜 / 排队时的替代店或街区 / 和当天路线关系 / 预算和付款/营业风险。

### ⑤ 预订和复查

完整攻略给可执行预订动作：现在就订（大交通、酒店、热门门票、演出、餐厅）/ 出发前 7 天复查（天气、开放时间、活动票务、酒店退改）/ 出发前 48 小时复查（交通班次、预约二维码、餐厅营业、极端天气）/ 当天复查（排队、临时闭馆、导航、末班车）。

### ⑥ 晴雨/疲劳/排队备选

| 变化 | 处理 |
|---|---|
| 下雨 | 室内博物馆/商场/咖啡馆替代，减少户外步行 |
| 排队 >45 分钟 | 保留核心点，删掉重复体验点 |
| 老人/孩子累了 | 回酒店午休，晚上只保留近距离用餐 |
| 预约失败 | 换同区域替代，不跨区追点 |
| 太热/太冷 | 上午户外，下午室内，晚间轻活动 |
| 交通延误 | 取消远点，保留住宿附近体验 |

### ⑦ 场景化 Q&A

问答贴合当前旅行，不固定复制。城市初访（住哪里、经典点怎么删、一天走多少、晚上去哪安全）；周末活动（活动过期/没票/下雨改哪条线）；美食（排队太久/一个人怎么点/忌口/夜宵早餐怎么排）；亲子老人（午休在哪、厕所电梯、推车轮椅、孩子睡着）；自驾（停车难/夜路/加油充电/封路撤退）；出境（支付失败/手机没网/语言/证件丢失）；中转（寄存失败/边检排队/进城太晚/最晚撤退时间）。回答用“判断条件 + 处理动作”。

### ⑧ 具体而克制的氛围提示

可以写氛围，但落到行为：“如果只想轻松拍照，把 Day 1 晚上留给河边散步，不再加第三个景点。”“亲子路线成功标准不是打卡数量，而是午睡、吃饭和排队都不崩。”不要空泛宣传：“感受城市魅力”“沉浸式体验人文风情”“一场说走就走的旅行”“祝你旅途愉快”。

## 7. 视觉层次增强

视觉效果 ≠ 多塞图片。优先“有信息量的视觉组件”：

- 首屏：结论 callout；目的地代表图/封面只在第一印象、识别或分享有价值时出现。
- 路线：简化地图、路线图、街区方向卡或地图链接卡。
- Day：时间轴卡、当天核心图或“今日主线 + 撤退点”卡。
- 美食：点单图鉴、多菜品拼图、美食街区地图，不用单菜图代表全部。
- 预算：预算卡、预订清单、现金/舒适度/风险对照表。
- 风险：晴雨两案卡、避坑卡、排队替代表。

颜色分工：蓝=路线结论，绿=推荐保留，黄=风险/预约，灰=来源/前提。卡片分工：路线卡解决“怎么走”，Day 卡解决“保什么删什么”，餐饮卡解决“怎么点”，预算卡解决“钱怎么花”，补救卡解决“现场怎么改”。标签：`需预约`/`高排队`/`雨天可替`/`亲子友好`/`可删减`/`低步行` 贴近具体点位。emoji 只做导航（🧭路线/🍜美食/🚇交通/💰预算/⚠️风险/✅复查），不当内容。图片很少时仍用 callout/grid/checkbox/bookmark/blockquote/hr 形成“彩色路书”观感，**不能退化成纯表格或纯列表**。

## 8. 内容厚度补强

每个核心模块至少回答两个：为什么重要或为什么这样安排 / 用户到现场具体怎么做 / 失败、排队、下雨、太累、没票、超预算怎么改。某 H2 下只有一行总结或一张表时，优先补一段取舍解释、一个执行例子或一个现场补救卡；补不了就合并到相邻模块，不保留薄章节。

## 9. 飞书组件建议

- 取舍说明：callout 或短段落。
- 分日执行：时间段表 + Day 卡 + 备选 callout。
- 住宿/路线对照：grid 或表格。
- 美食：图鉴 grid + 点单表。
- 预算预订：表格 + checkbox。
- Q&A：短表格或 grid，不用长编号列表。
- 复查：checkbox。
- 来源：blockquote 或就近放对应事实旁。
- 视觉节奏：hr、短标签、彩色 callout、两列 grid。

## 10. 使用自检

- [ ] 用户打开 Day 1 知道先去哪、怎么去、吃什么、删什么？
- [ ] 知道住哪个区域以及为什么？
- [ ] 知道哪些热门点不值得放主线？
- [ ] 知道下雨、排队、疲劳、预约失败时怎么改？
- [ ] 美食有点单、排队替代、适合时段、路线绑定？
- [ ] 预算有分类、可靠度、预订动作？
- [ ] Q&A 贴合当前场景，不是泛泛旅行问答？
- [ ] 视觉帮认路/点单/避坑/预算判断，不是装饰？
- [ ] 有语义色彩和卡片节奏，不是只有表格/列表？
- [ ] 每个主要模块足够厚，至少有解释+执行+调整中两类？
