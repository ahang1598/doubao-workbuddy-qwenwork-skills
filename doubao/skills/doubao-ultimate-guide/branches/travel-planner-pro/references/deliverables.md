# 交付物规范

## 目录

- 选择交付物
- 文件组织
- 默认：飞书/Lark 旅行文档
- Markdown 行程
- Word 文档
- HTML 攻略
- PDF 导出
- tripData JSON


当用户要求 Word、Markdown、HTML 页面、路书、打印手册、PDF，或飞书工具不可用需要降级交付时，读取本文件。

## 选择交付物

| 用户需求 | 推荐交付物 |
|---|---|
| 未指定格式 | 飞书/Lark 旅行文档 |
| 云端协作或主要交付 | 飞书/Lark 旅行文档 |
| 飞书工具不可用 | 同结构 Markdown + 复查清单；不提供图片文件夹 |
| 可编辑本地稿 | Markdown 或 Word |
| 精美可分享页面 | 单文件 HTML |
| 打印或发送最终手册 | 先确认 HTML，再导出 PDF |
| 豆包/社交视觉图 | 本四合一版本不生成图片卡片、长图或手绘地图 |
| 后续可重新生成 | `tripData.json` + HTML |

## 文件组织

在用户指定位置创建交付物。若用户未指定，在项目无关线程中默认使用当前线程的 `outputs/` 目录。

推荐结构：

```text
outputs/
└── [目的地]-[yyyy-mm]/
    ├── tripData.json
    ├── [目的地]-[天数]天旅行攻略.html
    ├── [目的地]-[天数]天旅行攻略.pdf
    └── sources/
        └── source-notes.md
```

## 默认：飞书/Lark 旅行文档

当用户未指定格式，或要求在线协作、组织内分享、云文档交付时，创建飞书/Lark 旅行文档。详细规则读取 `references/feishu-workflow.md`。本四合一版本不搜图、不生图、不插图，文档质量由路线、天气、预算、预订、风险、bookmark、callout、grid、table 和 checkbox 承担。

建议覆盖内容：

- 飞书标题区承载标题；正文第一屏直接给路线摘要、核心取舍和最大风险，不再重复同名标题。
- 目的地速览；用路线摘要、住宿区域、地图/官方入口 bookmark 和风险提示帮助识别。
- 路线总览表；路线图/手绘地图按路线复杂度和认路价值决定。
- 分日行程；每个 Day 必须有主线、交通步行、用餐落点、预约排队和可删减项。撤退点、雨天/疲劳/堵车/预约失败只在确实影响主线时轻量出现。
- 景点、美食、住宿、交通、预算、预订清单。
- 官方入口或动态事实来源写在对应事实附近；不要集中到文末来源章节。
- 文档第一屏直接给旅行结论、路线摘要、适合人群和最大风险，不把“默认假设”作为开头章节。
- 场景化排版：城市初访、美食、自驾、出境、亲子老人、中转短停应各有重心，不要统一套同一套目录。

如果飞书工具不可用，创建同结构 Markdown，不要把降级稿当作最终飞书文档冒充完成。保存 Markdown/HTML 后，检查是否存在图片空承诺、`<img>`、图片说明、图片来源、`image-plan.tsv`、`media-insert` 等旧流程痕迹；发现即删除或改成行动型“出发前复查/预订清单/仍需确认”。

## Markdown 行程

Markdown 适合飞书降级稿、备份稿或用户明确要求的可编辑旅行计划：

- 概览、路线摘要和仍需确认。
- 分日行程。
- 预订清单。
- 带可靠度标注的预算表。
- 时效信息就近备注。

长行程建议拆分为总览、Day 01-07、Day 08-14、实用附录。保存后用 `wc -l`、`wc -c` 和 `tail` 检查文件是否完整。

## Word 文档

Word 仅在用户明确要求 `.docx` 或“Word 文档”时生成。内容结构沿用飞书旅行文档，不插图。生成后必须检查文件存在、可打开。

## HTML 攻略

单文件 HTML 应满足：

- 离线友好：CSS 和 JS 内联，避免脆弱的外部图片依赖。
- 响应式：适配 375px 手机、平板和桌面宽度。
- 可打印：包含 `@media print`、分页控制，文字不被裁切。
- 目的地定制：版式、色彩和信息层级要贴合目的地和旅行类型。
- 实用优先：行程、路线逻辑、预订提醒和预算必须易扫读。

常见内容覆盖：

- 首屏：目的地、日期、同行人、主题；不做封面图。
- 路线总览。
- 天气和打包建议。
- 分日行程。
- 住宿、美食、交通。
- 预算。
- 预订时间线和风险提醒。
- 出发前复查和更新时间说明；必要来源放在对应事实附近，不做文末来源章节。

即使用户说图文攻略，本四合一版本也不搜图、生图或插图；用富文本结构和链接卡替代。

设计要求：

- 不要做营销落地页；第一屏就是攻略本身。
- 使用和目的地相关的克制装饰元素。
- 精美 HTML 中不要把 emoji 当作主要图标系统。优先用 CSS、内联 SVG 或可用图标库。
- 避免卡片套卡片，不要在紧凑面板里使用过大的标题。
- 确保移动端和打印版都没有文字重叠或裁切。

## PDF 导出

导出 PDF 前：

1. 打开或渲染 HTML。
2. 检查桌面端和移动端布局。
3. 检查打印预览或 PDF 渲染分页。
4. 修复文字裁切、元素重叠、标题孤行等问题。

只有用户明确要求一步到位的最终 PDF 时，才跳过用户确认直接导出。

## 交付后验证

写入文件后：

- 确认文件存在且非空。
- HTML 需要做基础语法检查，并在可能时打开或渲染预览。
- PDF 需要在工具可用时渲染页面或检查页数。
- 最终回复中给出准确输出路径，并列出用户出行前仍需复查的事实。
