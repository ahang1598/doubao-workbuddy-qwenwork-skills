本文件合并了交付合同、反模板构图、专业输出标准、飞书 XML 排版和视觉设计五部分。它是健身攻略的**唯一**格式契约：标题怎么写、XML 怎么搭、富 block 用哪些、图片怎么放、质量怎么自检，都在这里。SKILL.md 给的是 8 步流程和必填清单；这里给的是每一步的细则。

## 1. 交付契约（唯一出处）

- 最终交付优先是一份**真实创建的飞书在线文档（Docx）**，并在最终聊天回复给出真实 URL。
- 默认用 XML 富文本创建；用户明确要求导入 Markdown 时才用 `--doc-format markdown`。
- 即使用户只问“要怎么做/怎么练”，也不能只给普通建议或可复制 Markdown。
- 信息不全时也先创建文档，不要只反问。缺失信息只做内部判断：能合理推断的直接写成“适用边界/调整开关”（如强度、替代动作、疼痛停止线），不能把问题清单塞进文档正文或文末。
- 只有在飞书创建工具不可用、认证失败、权限不足或命令失败时，才退回聊天兜底；兜底必须说明“本次未能创建飞书在线文档”的原因，并给可重试的 XML/Markdown 片段。**不要假装已创建。**
- 正文只写健身攻略内容。工具版本、CLI 子命令、认证、权限、登录、scope、token、fallback、替代方案、图片搜索失败、未找到可下载图片、`image-plan.tsv`、`no_reliable_image` 等执行状态**只能留在内部记录**；成功交付时绝不写进飞书文档正文，也不要写进最终聊天回复。禁止在正文写内部工具状态、环境限制或执行过程。
- 正文禁止出现 HTML 表单标签或代码块式控件。复选任务在 XML 中只能写 `<checkbox done="false">事项</checkbox>`；Markdown 降级稿才写 `- [ ] 事项`。不要写 `<input type="checkbox" />`、`<button>`、`<select>`、`<textarea>`、`<label>`、`<form>`，也不要把它们转义成 `&lt;input...&gt;` 放进正文。
- XML 只用白名单组件：`title/h1/h2/h3/p/b/i/br/callout/grid/column/table/thead/tbody/tr/th/td/checkbox/bookmark/blockquote/hr/img`。不要自造 `<card>`、`<workout-card>`、`<section>`、`<timeline>`、`<badge>`、`<tag>`、`<panel>`、`<tabs>`；动作卡/饮食卡/复盘卡用 `callout + grid + table` 实现。
- 禁止最终交付只是一段可复制 Markdown、普通聊天建议、无文档链接、只有一张表，或声称“已创建”但没有真实 URL。
- 最终回复只给：文档标题、飞书文档链接、1–3 条内容亮点。**不要粘贴完整正文，不解释媒体检索结果，不把缺失信息写成待办或追问，不承诺后续细化。**

成功交付最终回复禁止出现：

- 媒体检索失败、图片不可用、下载不稳定、改用其他资料承接等过程说明。
- 文档完整性辩解、执行不受影响、后续可再细化等交付解释。
- 把缺失信息包装成文末问题、待补充清单或需要用户继续补资料的句子。
- `image-plan.tsv`、`no_reliable_image`、`media-insert`、`lark-cli` 等内部文件、状态或命令名。

缺失信息处理规则：
- **文档正文**：只写完整攻略、适用边界、自我调整开关和停止条件；不要把缺失变量写成面向用户的追问块。
- **最终聊天回复**：成功交付时默认只给标题、URL 和亮点。若确有非阻塞变量值得收集，只能放在聊天外层用一句“可选微调方向”轻提示，不写成编号问题清单，不进入文档正文。
- **确实高风险或无法安全生成时**：先不创建普通攻略，在聊天中说明必须先确认的安全信息；确认后再建文档。

### 合格 vs 不合格

用户问“我不想减重，只想塑形，想练马甲线以及肩背，要怎么做”：

- ❌ “可以，你应该每周练 3 次力量训练……”（聊天建议）
- ❌ 只输出 `# 塑形马甲线与肩背训练攻略` 这类 Markdown
- ✅ 创建题为“马甲线与肩背线条训练手册”的飞书 Docx，回复给真实 URL

用户问“我想减脂，但主要吃食堂和外卖，不太会算热量”：

- ❌ 大篇幅写健身房动作，把食堂外卖放成几条附录
- ✅ 创建题为“食堂外卖也能执行的减脂吃法”的飞书 Docx，第一屏直接给“不用精确算热量”的执行结论

## 2. 场景指纹与标题（生成前先做）

生成前必须先完成“场景指纹”，**不要原样写进正文**，只用于内部决策：

1. 用户真正要解决的问题：开始健身 / 外食减脂 / 线条塑形 / 跑不动 / 增肌 / 力量 / 体态 / 疼痛边界 / 打卡坚持。
2. 用户输入里的专属词：食堂、外卖、不会算热量、马甲线、肩背、偏瘦、25 分钟、TFCC、跑步、无器械、健身房、8 周。
3. 第一屏必须先回答什么：外食用户先答怎么点餐；跑步用户先答怎么跑不崩；塑形用户先答练哪些肌群；新手用户先答今天从哪一练开始。
4. 哪些模块是主角（展开成 H2），哪些是配角（合并到 callout / 表格 / 动作卡 / 复盘里）。
5. 本文像哪种文档：点餐手册 / 训练路线 / 动作学习卡 / 周期系统 / 疼痛避雷清单 / 打卡面板 / 计划审查报告。

### 标题生成公式

`<title>` 必须包含至少 1 个用户专属词或明确同义词。**禁止默认写成 `XX攻略` / `XX计划` / `XX方案`**（除非用户明确要求“攻略”二字）。从下面公式选一个，替换占位符即可使用：

| 公式 | 示例 |
|---|---|
| `{场景}也能执行的{目标}吃法` | 食堂外卖也能执行的减脂吃法 |
| `从第一练开始的{人群}健身路线` | 从第一练开始的零基础健身路线 |
| `每周 {N} 练的{目标}训练系统` | 每周 5 练的增肌训练系统 |
| `{症状}友好{部位}训练与避痛方案` | TFCC 友好的小臂训练与避痛方案 |
| `{时长}下班后训练卡` | 25 分钟下班后训练卡 |
| `{周期}训练打卡与复盘面板` | 8 周训练打卡与复盘面板 |
| `{人群}{目标}训练手册` | 马甲线与肩背线条训练手册 |
| `{痛点}时的{解法}方案` | 跑几分钟就喘时的跑走递增方案 |

正文开头**不要再复制标题**。`<title>` 后优先直接进入 `<callout>` 或一个更具体的阅读入口。如果使用 `<h1>`，必须比标题更具体，不能复制标题原文。

### 首屏决定顺序

| 用户核心场景 | 第一屏优先回答 | 禁止第一屏变成 |
|---|---|---|
| 食堂/外卖/不会算热量 | 今天怎么点、怎么不用称重也减脂 | 通用训练原则 |
| 马甲线/肩背/塑形 | 练哪些肌群、体重不是唯一指标 | 减重科普 |
| 新手小白 | 今天第一练和一周节奏 | 长篇心理建设 |
| 偏瘦增肌 | 怎么吃出盈余、怎么练出渐进 | 减脂饮食 |
| 跑步喘 | 跑走比例、强度和膝踝保护 | 标准跑姿百科 |
| 25 分钟上班族 | 单次时间盒和最低有效训练 | 大而全周期表 |
| TFCC/疼痛 | 避痛边界、可练/暂缓动作 | 普通手臂训练 |
| 8 周打卡 | 记录什么、记录如何改变计划 | 只列 8 周动作 |

### H2 标题规则

- H2 标题必须像这道题专属标题。**至少 60% 的 H2 要包含用户专属词、动作/场景/限制词或明确动词。**
- **H2 泛标题不超过 2 个。** 超过会被质量脚本判 FAIL。避免直接使用这些泛标题：核心训练原则、安全注意事项、训练安排、动作要点、饮食建议、恢复与睡眠、学习资源、打卡复盘、常见问题、写在最后、装备清单、健身基础知识。
- 必须用泛信息时改成场景标题：`安全注意事项` → `这些疼痛和头晕信号先停练`；`训练安排` → `25 分钟里只保留 5 个高收益动作`；`饮食建议` → `食堂午餐照着 211 盘子取`。
- 标题层级不跳级：`H1 → H2 → H3`。全篇最多 1 个 H1。

## 3. 文档架构（按场景选主线）

先在内部用一句话确定本文主线，再围绕主线安排章节。**禁止所有文档都套同一套目录**（如“导览 → 安全 → 训练 → 动作 → 饮食 → 复盘”）。下面是主线方向，不是目录模板：

| 主线 | 第一屏切入 | 重点 |
|---|---|---|
| 新手起步型 | 今天先怎么开始 | 第一练、动作降阶、习惯建立、风险红线、2–4 周递进 |
| 减脂执行型 | 减脂抓手 | 力量训练、有氧/步数、饮食缺口、外食策略、平台期复盘 |
| 饮食执行型/食堂外卖型 | 不用精确算热量也能执行 | 餐盘法、食堂和外卖点餐、饮料零食夜宵、样例餐、加班应急、轻运动配套、每周复盘 |
| 塑形线条型 | 视觉目标与肌群策略 | 肩背/核心/臀腿肌群、训练频率、动作质感、体态、围度/照片复盘 |
| 增肌进阶型 | 肌群训练量和渐进超负荷 | 分化、周训练量、主动作进阶、热量盈余、恢复 |
| 力量主项型 | 主项表现和技术风险 | 强度周期、主项技术、辅助动作、降载、训练日志 |
| 体态/疼痛边界型 | 风险分流和动作重建 | 疼痛边界、活动度、稳定性、低风险力量、动作自检 |
| 动作教学型 | 这个动作是否适合你 | setup、执行路径、常见错误、降阶/进阶、视频/图解、停止条件 |
| 计划审查型 | 原计划诊断 | 保留项、风险项、修改版安排、复盘方式 |

### 必须做好的 5 个维度

每个完整攻略都要满足：

1. **安全性**：红旗情况（胸痛、晕厥、急性损伤、关节肿胀、术后/孕产期/慢病/医生限制）+ 训练中止标准（关节锐痛、麻木、头晕、疼痛 >3/10、次日明显恶化）+ 通用计划不替代医生/康复师。
2. **合理性**：显式说明为什么这样安排——先匹配目标人群再决定周期结构；新手先全身不五分化；强度保留余力用 RPE/RIR；训练量从低到高。
3. **丰富度**：不只给动作清单。按需覆盖周期路线、周结构、今天第一练、居家/健身房版、动作自检、媒体资源、可记录训练模板、中途调整、执行陪伴、进步判断、饮食行动、恢复。
4. **动作教学密度**：核心动作必须写 6 项——起始姿势、执行路径、发力感觉、常见错误（≥2 个+修正）、降阶/进阶、停止条件。辅助动作只给 1 句自检。
5. **格式**：高度结构化但不固定表单。混合短段落、清单、callout、训练日卡、分栏、少量表格。**完整飞书文档至少 5 类富 block**，主要 H2 附近至少 1 个非纯文本组件。

### 清晰充盈骨架

完整攻略不是“动作表 + 饮食几条 + 打卡清单”。生成前确认正文能回答这些问题：

- **我今天先做什么**：第一屏给最低可执行起点、本周频率和最重要停止条件。
- **为什么这样安排**：每个主角模块至少有 1–3 句取舍解释，说明这个安排如何服务用户目标。
- **具体怎么做**：训练写动作名、组数、次数/时长、强度大白话、休息、热身/收操、替代动作；饮食写点餐口令、样例餐、饮料零食夜宵处理；动作教学写完整动作卡。
- **怎么判断有效**：写 2–4 周可观察指标，如完成率、重量/次数、围度/照片、7 日均重、疼痛评分、主观疲劳、睡眠。
- **卡住怎么办**：漏练、吃超、器械被占、时间不够、没动力、酸痛/疼痛、平台期至少覆盖其中 2 类，并给恢复计划的方法。
- **怎么读得清楚**：主要模块按“解释 → 执行 → 调整/复盘”组织；表格前后有自然语言，不连续堆同类组件；主要 H2 下不能只有一句话或一张薄表。

这些是能力要求，不是固定目录。不同场景可以换开头和模块顺序，但不能丢掉执行颗粒度。

### 模块组合规则

- 主角模块：给 2–4 段解释、表格/卡片/清单和调整规则。
- 配角模块：合并为 callout、grid、表格一列、blockquote 或 checkbox，不单独凑 H2。
- 安全边界可前置，也可嵌入动作卡；疼痛/特殊人群必须前置。
- 资源链接：贴着对应动作或饮食场景放，**不要永远放文末**。
- 复盘：必须告诉用户记录什么会影响下一步，而不是只写“坚持打卡”。
- 主要 H2 下不能只有一句话或一张薄表。每个主要模块至少包含“解释 / 执行 / 判断调整”中的两类信息；否则合并到相邻模块。
- 完整攻略至少有一个“低动力/漏练/吃超/器械被占/时间不够/疼痛不适/平台期”处理模块或分散在对应章节的处理卡；不要把坚持支持写成鸡汤。

## 4. 飞书 XML 组件与骨架

创建飞书 Docx 优先用 XML。命令形态：

```bash
lark-cli docs +create --api-version v2 --doc-format xml --content @file.xml
```

> 用 `@file.xml` 文件方式传内容，**不要**把 XML 内联进 `--content '<...>'`——引号/反引号/`$` 会被 shell 吃掉。

### 必填富 block 清单（完整攻略）

完整攻略至少满足以下组合（会被 `check_fitness_quality.py` 检查）：

- 1 个开头 `<callout>`：训练判断或最重要结论。
- 1–3 个 `<table>`：训练安排、动作处方、复盘表。
- 1 个 `<grid>`：居家/健身房对照、动作要点/常见错误、训练/饮食对照。
- ≥3 个 `<bookmark>`（真实 http(s) URL，非 example.com）：核心动作视频/图解链接；饮食执行型放餐盘法、饮食指南、成人活动量资源。
- ≥3 个 `<checkbox done="false">...</checkbox>`：本周任务或打卡项。不要用 HTML `<input type="checkbox" />`。
- 1–3 个 `<hr/>`：分隔训练、动作、饮食/复盘等大主题。
- 1 个系统感组件：训练路线卡 / 低动力卡 / 替代矩阵 / 动作质感卡 / 饮食交通灯 / 进步仪表盘。
- 至少 2 个执行阻力处理点：漏练、吃超、器械被占、时间不够、没动力、酸痛/疼痛、平台期、外卖应酬等，根据用户场景选择。
- 可选真实图片：中文用户先找国内教学图/权威图解/开放图片，国内不可下载或质量不稳时再用 Wikimedia/权威图库。**搜不到可靠图就不插图，严禁生图。** 有可靠图片时下载到本地 → `+media-insert --file` 插入（见 SKILL.md “图片协议”）。没有可靠图片时，用真实视频/图解 `<bookmark>`、动作卡和自检表补足。

### XML 骨架（替换 {{占位符}} 即可使用）

```xml
<title>{{场景词 + 形态词}}</title>
<callout emoji="📌" background-color="light-blue" border-color="blue">
  <p><b>核心结论：</b>{{1 句最该先做的事}}</p>
</callout>
<h1>{{比标题更具体的阅读入口}}</h1>
<h2>{{场景化标题，含专属词}}</h2>
<table>
  <thead><tr><th background-color="light-gray">列名</th></tr></thead>
  <tbody><tr><td>...</td></tr></tbody>
</table>
<h2>{{场景化标题}}</h2>
<grid>
  <column><h3>居家版</h3><p>...</p></column>
  <column><h3>健身房版</h3><p>...</p></column>
</grid>
<h2>{{动作/饮食模块}}</h2>
<p>{{写一句唯一锚点句，例如“膝盖朝脚尖方向，重心落在全脚掌”。图片计划写到旁路 image-plan.tsv，不写进 XML 正文。}}</p>
<bookmark name="{{真实资源名}}" href="{{真实URL}}"></bookmark>
<checkbox done="false">{{本周任务}}</checkbox>
<hr/>
<callout emoji="⚠️" background-color="light-yellow" border-color="yellow">
  <p><b>停止条件：</b>{{疼痛/头晕/麻木信号}}</p>
</callout>
```

### 图片插入方式（重要：下载本地 + media-insert，避免 403 和堆文末）

**不要在 XML 里内联 `<img href="URL"/>`**——飞书会服务端抓取外部 URL，很多图库/CDN 返回 403 防盗链。**也不要在 XML 正文里写 `<!-- 插图位置 -->`、`<!-- media: -->`、`anchor=`、`caption=` 这类内部字段**——飞书可能把 XML 注释当正文显示。**搜真实图优先，搜不到可靠图就放弃，严禁生图。** 正确流程是下载本地 + 旁路图片计划 + `+media-insert`：

1. 搜图：先找国内可打开教学图/权威图解/开放图片；需要可下载直链时，再用 Wikimedia/权威图库直链（如 `upload.wikimedia.org/...jpg`）兜底。
2. `curl -sL -A "Mozilla/5.0..." "<URL>" -o outputs/.../visuals/NN.png`，`file` 验证是 "PNG/JPEG image data"（HTML/空 → 换源）。
3. XML 草稿只写正常正文和唯一锚点句；图片文件、锚点、图注、用途和来源写到 `outputs/{场景}/image-plan.tsv`：
   ```tsv
   file	anchor	caption	purpose	source_type	source	status	reason
   visuals/01-squat.png	膝盖朝脚尖方向，重心落在全脚掌	图：深蹲下蹲路径	纠正膝盖内扣	doubao-search	深蹲 标准动作 图解	ready	
   ```
   没有可靠图片的对象只在旁路计划记录跳过原因；不要把跳过原因写入正文或最终回复。
4. `lark-cli docs +create --content @file.xml` 建文档（正文不带图、不带内部标记）。
5. 只对 `image-plan.tsv` 中 `status=ready` 且有 file 的行跑 `lark-cli docs +media-insert --file <本地> --selection-with-ellipsis "<锚点>" --caption "..."`，图插到锚点附近、不堆文末、不 403。
6. `+fetch` 验证 media block 在锚点附近。

**`--selection-with-ellipsis` 必填**——否则 `+media-insert` 默认追加文末（图全堆后面）。搜不到合适图的位置就不插图，改用权威视频/图解 bookmark + 文字动作卡，不生成图片。

`<bookmark>` 用于链接到真实资源页面（动作视频、权威饮食资料）。没有可靠图片时，bookmark + 动作卡就是正确降级，不需要硬塞图片。

### 组件用法与语义色彩

- `<callout>`：安全红旗、训练中止、关键原则、适用边界。完整文档 4–6 个，不要连续堆。**蓝**=结论/主线；**绿**=推荐/完成标准/低动力；**黄**=风险/疼痛/停止/补救；**灰**=备注/适用前提/资料说明。色彩最多 4 类，同义同色。
- `<table>`：高密度结构化信息（周期路线、周结构、动作处方、视频资源、打卡复盘）。表头 ≤8 字，每格一个核心信息，动作要点放 1 句不塞长段。
- `<grid>`：对照（居家/健身房、动作要点/常见错误、训练/饮食）。
- `<checkbox>`：本周执行动作和复盘事项。
- 禁止 HTML 控件：飞书 XML 里不要写 `<input type="checkbox" />`。若看到模型生成了这种写法，改成 `<checkbox done="false">事项文本</checkbox>` 后再创建文档。
- `<bookmark>`：贴在对应动作/饮食场景旁的真实链接，不堆文末。
- `<blockquote>`：适用前提、资料说明、医学边界、访问日期。
- `<hr/>`：章节节奏，每 2–3 个大模块用一次，不连续用、不替代标题。
- 图片：只有可靠真实图片才下载本地 → `+media-insert --file --selection-with-ellipsis` 插入（见 SKILL.md "图片生产协议"）；服务动作/餐盘/风险/复盘，必须配 1 句图注。搜不到可靠图就不插图。

不要自造组件标签。以下会露出到正文：

```xml
<card title="训练日动作卡">深蹲、划船、平板支撑</card>
```

应改成真实飞书组件：

```xml
<callout emoji="🏋️" background-color="light-green" border-color="green">
  <p><b>训练日动作卡：</b>深蹲、划船、平板支撑，强度保持还能再做 2-3 次。</p>
</callout>
```

### 有序列表限制

- 有序列表只用于步骤、阶段或优先级。
- 不要连续用多个 `<ol>` 组织整篇。超过 5 项优先改成表格、grid、checkbox 或动作卡。
- 富 block 中非纯文本占比建议 ≥45%。

### 迷你文档兜底

极短或窄问题也创建简短飞书文档：

```xml
<title>{{场景目标}}训练卡</title>
<callout emoji="📌" background-color="light-blue" border-color="blue">
  <p>先给最小可执行方案，再给需要停止训练的信号和可调整选项。</p>
</callout>
<h2>今天先做什么</h2>
<table>...</table>
<h2>注意事项与下一步</h2>
<checkbox done="false">完成一次低风险训练</checkbox>
```

## 5. 视觉设计

视觉元素服务理解：动作看得懂、计划找得到、风险能被注意到、打卡容易执行。**不花哨、不堆高亮。**

### 图片双轨规则

- **动作与动作提醒优先搜图**：具体动作、起始/结束姿势、动作路径、常见错误、发力位置、安全注意、降阶/进阶，优先搜 B 站/小红书图文、权威动作库、官方图解。用户要学“怎么做”和“哪里容易错”时，不要用抽象训练卡替代动作图。
- **抽象执行系统**：211 餐盘可搜权威餐盘图嵌入；点餐交通灯、训练卡、替代矩阵、低动力卡、复盘仪表盘这类抽象结构，用表格/callout/grid/checkbox 等富 block 承载，不生图。
- **搜不到就放弃插图**：动作图找不到可靠来源时，不生成线条示意图或错误对照图，改用真实视频/图解链接和动作卡。
- **禁止**：身材焦虑、前后对比夸张、局部减脂暗示、健身写真、明星图、挑战图、版权不明图片。

### 图片来源优先级

1. 用户提供的图片。
2. 开放许可或官方机构图片/图解。
3. 权威动作库页面中的图解链接（ACE/NASM/ExRx/NHS/Mayo）。
4. 普通网页图片仅作参考链接，不直接嵌入。

每张图片配 1 句说明，例如“看膝盖方向和髋部后坐，不要模仿过深幅度”“用于理解肩胛后收，不代表你的动作已合格”。

### 视觉组合（按场景选 2–4 个，不全部堆上）

| 场景 | 推荐视觉组合 |
|---|---|
| 泛入门 | 导览卡 + 安全红线 callout + 阶段路线表 + 第一练训练日卡 + 1 个核心动作路径图/错误对照图 + 打卡复盘表 |
| 减脂 | 目标路径卡 + 力量/有氧/步数三分栏 + 饮食行动清单 + 周训练表 + 体重围度复盘表 + 进步仪表盘 + 211 餐盘/饮食交通灯图 |
| 食堂外卖 | 开头结论 callout + 3 栏 grid（餐盘/口令/复盘）+ 交通灯表 + 场景点餐表 + 样例餐表 + 饮料零食夜宵卡 + 加班补救 callout + 本周 checkbox + 211 餐盘/点餐交通灯图 |
| 增肌 | 肌群周训练量表 + 主动作进阶卡 + 动作图解链接 + 蛋白和训练日饮食清单 + 睡眠恢复提醒块 |
| 体态/久坐 | 疼痛分流 callout + 每天 5 分钟清单 + 动作前后感受表 + 办公室/居家分栏 + 动作图解链接 |
| 动作教学 | 动作图/视频链接 + 标准动作卡 + 常见错误与修正分栏 + 降阶/进阶路径 + 停止条件 callout |
| 塑形/马甲线/肩背 | 线条目标 callout + 肩背/核心/臀腿策略分栏 + 周训练表 + 动作质感卡 + 资源链接卡 + 照片/围度复盘表 |
| 长期计划/复盘 | 周训练卡 + 训练日志样例 + 进步仪表盘 |

### 图片放置

- 动作图、错误对照图放对应动作卡/媒体表附近，**不堆文末**。
- 餐盘图/点餐交通灯放点餐规则、样例餐或外食补救模块旁。
- 风险/停止条件图放黄色安全 callout 或降阶动作模块旁。
- 训练卡/复盘仪表盘放训练日志、打卡表或进阶规则附近。
- 只有一张图时，优先放最能降低执行成本的位置，而非默认封面。

### 系统感组件内容要求（不能是空壳）

- 训练路线卡：周期、频率、主动作、复盘点。
- 动作质感卡：起始姿势、路径、发力、错误、降阶/进阶、停止条件。
- 饮食交通灯：每类都给真实食堂/外卖例子。
- 低动力卡：最低完成标准和恢复原计划的方法。
- 进步仪表盘：记录字段和根据结果怎么调整。
