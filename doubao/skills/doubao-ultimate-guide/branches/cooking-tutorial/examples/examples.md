# Examples

## 文件定位

本文件是 `cooking-tutorial` Skill 的参考案例文件，用于帮助模型理解不同美食制作与烹饪教学任务下，什么样的输出是合格的、清晰的、可执行的、图文策略正确的。

本文件负责提供典型案例和反例，包括：

1. 单道菜文档案例（每步必配图）。
2. 需要真实步骤图的图文教程案例。
3. 四菜一汤 + 甜品 + 饮品 + 技能的复杂文档案例。
4. 烘焙失败诊断案例。
5. 配方替代案例。
6. HTML 图文步骤页案例。
7. 备菜保存案例。
8. 错误示例与问题说明。

本文件不负责完整规则说明。主任务分类与教程细度见 `reference/task-and-detail-guide.md`；图片与视觉规则见 `image-and-visual-guide.md`；安全与质量底线见 `reference/safety-and-quality-guide.md`；输出结构见 `templates/output-templates.md`。

> 与主控规则的一致性：根据 `SKILL.md` 的全局硬性规则，本 Skill 的输出形式**强制只在文档与 HTML 之间二选一，不存在精简文字回答等任何其他形式**，并且**所有输出必须图文并茂、每个操作步骤必须配图**。图片只有“真实检索图（优先）”和“统一风格生成图（兜底）”两档，**不允许图片占位、不允许假链接**，落到正文的图片都必须是可渲染真实链接；关键状态生成图须标“示意图，仅供参考”。即使用户要求“直接说/简单说/只要文字/不要文档”，也不退回纯文字：仍用文档承载、内容写精简，用户明确“不要文档”则改用 HTML；仅当用户明确要求“不要图片/不要信息图/极简文字版”时，才可省略图片。本文件中所有案例均按此口径设计；案例片段中出现的 `https://可渲染的真实图片URL.jpg` 等仅为占位示意，**实际输出必须替换为真实可渲染链接**，绝不能把字面占位写进正文。

## 一、案例使用原则

使用 examples 时，应注意：

- 示例不是固定模板，不能机械套用。
- 示例用于理解“输出质量标准”，不是要求每次都写同样内容。
- 用户有明确要求时，优先满足用户要求。
- 用户没有明确要求时，根据 `SKILL.md` 的默认策略选择**文档或 HTML**（强制二选一）；即使用户要求“直接说/简单说/只要文字/不要文档”，也不退回纯文字，而是仍用文档承载、内容写精简，或在用户明确“不要文档”时改用 HTML。
- 短任务可以参考单道菜、技巧、失败诊断等案例（仍以文档承载、每步配图）。
- 长任务、复杂任务、图文任务应参考文档、HTML 和复杂复合任务案例。
- 涉及图片时，必须遵守“关键状态真实图优先、无果统一风格生成图兜底、全程不留占位”的规则。
- 涉及安全、保存、特殊人群、健康目标时，必须遵守安全与质量边界。

## 二、优秀案例 1：单道菜文档（每步必配图）

### 用户需求

```markdown
教我做番茄炒蛋，写详细一点，我是新手。
```

### 任务判断

```markdown

内容模块：菜谱制作
约束标签：新手友好、家常菜、短内容
输出形式：文档形式（默认，每步必配图）
应调用：
- reference/task-and-detail-guide.md
- image-and-visual-guide.md
- reference/safety-and-quality-guide.md
- templates/output-templates.md
```

### 合格输出示例

```markdown
# 新手版番茄炒蛋

## 适合情况

- 难度：新手友好
- 预计耗时：15 分钟
- 份量：2 人份
- 口味特点：酸甜咸鲜，鸡蛋嫩，番茄有汤汁
- 主要工具：炒锅、碗、锅铲


## 食材与调料

| 类别 | 内容 | 用量 | 备注 |
|---|---|---:|---|
| 主料 | 番茄 | 2 个，约 300 克 | 熟一点更容易出汁 |
| 主料 | 鸡蛋 | 3 个 | 常温蛋更容易打散 |
| 调料 | 盐 | 约 2 克 | 分两次放 |
| 调料 | 白糖 | 约 3 克 | 中和酸味，可不放 |
| 调料 | 食用油 | 约 15 毫升 | 分两次用 |
| 可选 | 葱花 | 少量 | 出锅前放 |

## 前期准备

1. 番茄洗净，去蒂，切成 2-3 厘米小块；如果想口感更细，可以先去皮。
2. 鸡蛋打入碗中，加一小撮盐，用筷子打到蛋清和蛋黄完全融合，表面有细小泡沫。
3. 葱切成葱花备用。

## 制作步骤

### 步骤 1：先炒鸡蛋

![步骤1配图](https://可渲染的真实图片URL.jpg)
*图示：蛋液边缘凝固、中间略湿时推成大块（真实图 / 示意图，仅供参考）*

- 操作：锅烧热后倒入约 10 毫升油，油热后倒入蛋液。
- 时间：中火加热约 20-30 秒。
- 火候/温度：中火，不要小火慢煎。
- 状态判断：蛋液边缘开始凝固，中间还有一点湿润时，用锅铲轻轻推成大块。
- 注意事项：不要一直翻碎，鸡蛋会变老。
- 图片来源：真实检索图（优先）/ 统一风格生成图（兜底）
- 推荐检索词：番茄炒蛋 鸡蛋 半凝固 推成大块

### 步骤 2：炒番茄出汁

![步骤2配图](https://可渲染的真实图片URL.jpg)
*图示：番茄边缘变软、锅底出现红色汤汁（真实图 / 示意图，仅供参考）*

- 操作：盛出鸡蛋，锅中补少量油，倒入番茄块。
- 时间：中火炒 2-3 分钟。
- 火候/温度：中火。
- 状态判断：番茄边缘变软，锅底出现红色汤汁。
- 注意事项：如果番茄偏硬，可以加 1-2 汤匙热水帮助出汁。
- 图片来源：真实检索图（优先）/ 统一风格生成图（兜底）
- 推荐检索词：番茄炒蛋 番茄 炒出汁

### 步骤 3：合炒调味

![步骤3配图](https://可渲染的真实图片URL.jpg)
*图示：鸡蛋裹上番茄汁、仍保持大块嫩感（真实图 / 示意图，仅供参考）*

- 操作：把鸡蛋倒回锅里，加入盐和少量糖，翻炒 30 秒。
- 时间：约 30-60 秒。
- 火候/温度：中小火。
- 状态判断：鸡蛋表面裹上番茄汁，但还保持大块和嫩感。
- 注意事项：不要炒太久，否则鸡蛋会变老、番茄汤汁会变干。
- 图片来源：真实检索图（优先）/ 统一风格生成图（兜底）
- 推荐检索词：番茄炒蛋 鸡蛋 裹番茄汁 出锅前

## 关键技巧

- 鸡蛋先炒到半凝固就盛出，最后再回锅，这样更嫩。
- 番茄要炒到出汁再放鸡蛋，否则味道会分离。
- 盐分两次少量加，比一次放很多更稳。

## 常见问题与补救

| 问题 | 可能原因 | 补救方法 | 下次避免 |
|---|---|---|---|
| 鸡蛋太老 | 炒太久或火太小 | 加一点番茄汁拌匀，口感会稍微软一些 | 鸡蛋半凝固就盛出 |
| 番茄不出汁 | 番茄偏硬或炒得不够 | 加 1-2 汤匙热水再炒 1 分钟 | 选熟番茄，切小块 |
| 太酸 | 番茄酸度高 | 加少量糖调整 | 先尝味再加糖 |

## 保存与复热

- 建议现做现吃。
- 如需保存，冷却后密封冷藏，建议当天或次日吃完。
- 复热时用微波炉或小锅加热到热透，鸡蛋口感会比刚出锅略老。
```

### 关键图文策略

```markdown
水波蛋教程的关键难点是“真实水面状态、鸡蛋入水动作、蛋白凝固程度”，这些都是关键状态判断节点，必须优先真实步骤图或真实参考图；多轮检索确实无果时，才用统一风格生成图兜底，并在图注标“示意图，仅供参考，实际以文字描述为准”。无论真实图还是生成图，落到正文的都必须是可渲染真链，不留占位。

```

### 合格输出示例片段

```markdown
# 水波蛋图文教程

## 适合情况

- 难度：新手进阶
- 预计耗时：8-10 分钟
- 份量：1 个水波蛋
- 关键成功点：水不能大滚，鸡蛋要贴近水面滑入，捞出前蛋白应完整凝固


## 食材与工具

| 内容 | 用量 | 备注 |
|---|---:|---|
| 新鲜鸡蛋 | 1 个 | 越新鲜越容易成形 |
| 清水 | 约 800 毫升 | 水深至少 6-8 厘米 |
| 白醋 | 1 小勺，约 5 毫升 | 帮助蛋白凝固，可少量使用 |
| 漏勺 | 1 把 | 捞出水波蛋 |
| 小碗 | 1 个 | 先把蛋打入碗中 |

## 制作步骤

### 步骤 1：把水加热到微沸

![步骤1配图](https://可渲染的真实图片URL.jpg)
*图示：水面只需微微冒小泡，不要大滚（真实图优先 / 无果生成图标示意，仅供参考）*

- 操作：锅中加水，加入白醋，中火加热。
- 时间：约 4-5 分钟。
- 火候/温度：水面出现小气泡即可，不要大滚。
- 状态判断：锅底和锅边有小泡上升，水面轻微晃动，但没有剧烈翻滚。
- 注意事项：水太滚会把蛋白冲散。
- 图片来源：真实检索图（优先）
- 推荐检索词：水波蛋 微沸水面 / poached egg simmering water small bubbles

### 步骤 2：鸡蛋贴近水面滑入锅中

![步骤2配图](https://可渲染的真实图片URL.jpg)
*图示：碗口贴近水面、鸡蛋轻轻滑入（真实图优先 / 无果生成图标示意，仅供参考）*

- 操作：鸡蛋先打入小碗，把碗口贴近水面，轻轻把鸡蛋滑入水中。
- 时间：10 秒内完成。
- 火候/温度：保持小火或中小火。
- 状态判断：鸡蛋入水后蛋白轻微散开，但仍围绕蛋黄。
- 注意事项：不要从高处倒入，否则蛋白会散得很厉害。
- 图片来源：真实检索图（优先）
- 推荐检索词：水波蛋 鸡蛋贴近水面 入锅 微沸 / poached egg sliding egg into simmering water

### 步骤 3：小火煮到蛋白凝固

![步骤3配图](https://可渲染的真实图片URL.jpg)
*图示：蛋白变白并包住蛋黄、漏勺轻推可整体移动（真实图优先 / 无果生成图标示意，仅供参考）*

- 操作：保持水面微动，小火煮 3-4 分钟。
- 时间：3 分钟是流心，4 分钟蛋黄会更凝固。
- 火候/温度：小火，不要让水翻滚。
- 状态判断：蛋白变白并包住蛋黄，用漏勺轻推时整体能移动。
- 注意事项：不要频繁搅动。
- 图片来源：真实检索图（优先）
- 推荐检索词：水波蛋 蛋白凝固 包裹蛋黄 捞出前 / poached egg white set before removing

### 步骤 4：捞出并吸掉多余水分

![步骤4配图](https://可渲染的真实图片URL.jpg)
*图示：漏勺捞出后放厨房纸吸水（真实图优先 / 无果生成图标示意，仅供参考）*

- 操作：用漏勺轻轻捞出，放到厨房纸上吸 10-20 秒。
- 状态判断：表面没有明显水滴，蛋白完整。
- 注意事项：不要用力按压，否则蛋黄可能破。
- 图片来源：真实检索图（优先）
- 推荐检索词：水波蛋 漏勺捞出 厨房纸吸水 / poached egg slotted spoon paper towel

## 食品安全提醒

- 水波蛋通常是半熟蛋，建议使用新鲜、来源可靠的鸡蛋，并尽快食用。
- 儿童、老人、孕期或免疫力较弱人群不建议吃半熟蛋。
```

# 戚风蛋糕塌陷诊断与补救

## 1. 问题判断

戚风出炉后塌陷，通常不是单一原因，最常见的是：没有烤透、蛋白状态不稳定、出炉后没有及时倒扣、翻拌消泡，或烤箱温度不合适。

如果蛋糕只是轻微回缩，仍然可以吃；如果中心明显湿黏、像没熟的面糊，就不建议直接食用，可以切片回烤后再判断。

## 2. 可能原因排序

| 可能性 | 原因 | 对应现象 | 判断方法 |
|---|---|---|---|
| 高 | 没烤透 | 出炉后中心塌、内部湿黏 | 竹签插入中心有湿面糊 |
| 高 | 出炉后没有倒扣 | 表面快速回缩 | 出炉后直接正放冷却 |
| 中 | 蛋白打发不足或消泡 | 膨胀不高、组织粗糙 | 面糊入模时很稀、气泡大 |
| 中 | 烤箱温度偏低 | 表面颜色浅但内部湿 | 烤很久仍不上色 |
| 中 | 烤箱温度偏高 | 表面裂得厉害但内部没熟 | 外熟内生 |

## 3. 当前补救方法

| 情况 | 补救方式 | 能改善到什么程度 |
|---|---|---|
| 只是轻微塌陷，内部熟了 | 切块食用或做蛋糕杯 | 外形不能恢复，但口感可接受 |
| 中心湿黏没熟 | 切片后 150℃ 回烤 8-12 分钟 | 可改善熟度，但不会恢复蓬松 |
| 已经有异味或放置很久 | 不建议继续食用 | 安全优先 |

## 4. 下次避免方式

- 蛋白打到提起打蛋头有小弯钩，泡沫细腻稳定，不要打得太软。
- 翻拌时用切拌和翻拌，不要画圈搅拌。
- 面糊入模后轻震 1-2 次，震出大气泡即可，不要反复震。
- 烤箱要提前预热，按配方温度烤足时间。
- 出炉后立刻从 20-30 厘米高度轻震一下，再倒扣冷却。
- 完全冷却后再脱模。

## 5. 正确/错误状态对比与配图

| 对比项 | 正确状态 | 失败状态 | 配图建议 |
|---|---|---|---|
| 蛋白打发 | 小弯钩、细腻稳定 | 软塌或粗糙结块 | 真实对比图优先，无果生成示意（标免责） |
| 出炉处理 | 倒扣冷却 | 正放快速回缩 | 真实图优先 |
| 熟度 | 竹签拔出无湿面糊 | 中心湿黏 | 真实图优先 |

| 图片用途 | 来源建议 | 推荐检索词 |
|---|---|---|
| 蛋白打发小弯钩状态 | 真实图优先 | 戚风蛋糕 蛋白打发 小弯钩 |
| 戚风塌陷对比 | 真实图优先 | 戚风蛋糕 塌陷 原因 对比 |
| 戚风倒扣冷却 | 真实图优先 | 戚风蛋糕 出炉 倒扣 冷却 |

```markdown
# 饼干没有黄油，能不能用玉米油代替？

## 1. 结论

可以代替，但不建议按 1:1 完全替代，而且成品口感会明显变化。

黄油能提供奶香、酥松感和一定支撑；玉米油是液态油，能让饼干更湿润，但香气弱，成品可能更脆或更散，不会有明显黄油香。

## 2. 替代比例

| 原材料 | 替代方案 | 推荐比例 | 影响 |
|---|---|---:|---|
| 黄油 100 克 | 玉米油 | 70-80 克 | 奶香下降，面团更软 |
| 黄油 100 克 | 玉米油 + 少量奶粉 | 玉米油 75 克 + 奶粉 10 克 | 增加奶香，但不完全等同黄油 |
| 黄油 100 克 | 椰子油 | 80 克左右 | 有椰香，冷却后支撑略好 |

## 3. 做法调整（涉及制作的步骤仍每步配图）

### 步骤 1：油糖蛋乳化
![步骤1配图](https://可渲染的真实图片URL.jpg)
*图示：鸡蛋、糖、玉米油搅到颜色略浅、液体均匀（真实图 / 示意图，仅供参考）*
- 不要把玉米油直接当软化黄油打发；它不能像黄油一样打入空气。
- 先把鸡蛋、糖、玉米油搅拌到乳化状态。

### 步骤 2：拌入面粉成团
![步骤2配图](https://可渲染的真实图片URL.jpg)
*图示：加入低筋面粉压拌到无干粉（真实图 / 示意图，仅供参考）*
- 用刮刀压拌到没有干粉即可。
- 如果面团太软，先冷藏 20-30 分钟再整形。

### 步骤 3：烘烤观察上色
![步骤3配图](https://可渲染的真实图片URL.jpg)
*图示：边缘上色即可出炉（真实图 / 示意图，仅供参考）*
- 烘烤时间可以先按原配方，最后 3-5 分钟观察上色情况。

## 4. 成品变化

- 香气：黄油香会明显变弱。
- 口感：可能更脆，但酥松感下降。
- 形状：面团更容易摊开，造型饼干可能不够立体。
- 成败率：普通小圆饼可以尝试；曲奇裱花类不太建议完全替代。

## 5. 不建议替代的情况

- 需要打发黄油的曲奇。
- 需要清晰花纹的裱花曲奇。
- 强调黄油香的原味饼干。
- 已经是低油低糖配方的饼干，因为再替代更容易影响结构。
```

### 为什么这是好例子

```markdown

- 说明可以替代但有影响。
- 给比例，不只说“可以用”。
- 解释口感、香气、形状和成败率变化。
- 涉及制作步骤时每步配图，不留占位。
- 明确不建议替代的场景。

# 一周便当备菜方案

## 1. 总体建议

不建议周日把 5 天的便当全部做成熟菜冷藏到周五。更稳妥的方式是：周日完成“主食分装 + 肉类腌制/熟制 + 蔬菜预处理 + 酱汁准备”，其中前 2-3 天吃冷藏熟菜，后 2 天使用冷冻主菜或半成品现做。

## 2. 适合提前做的内容

| 内容 | 处理方式 | 保存方式 | 建议时间 |
|---|---|---|---|
| 米饭 | 分装冷冻 | 冷冻 | 1 周内 |
| 鸡腿肉 | 腌制或煎熟 | 冷藏 2-3 天 / 冷冻更久 | 视保存方式 |
| 牛肉片 | 腌制分装 | 冷冻 | 1 周内 |
| 西兰花 | 焯水后沥干 | 冷藏 | 2-3 天 |
| 胡萝卜、玉米 | 蒸熟分装 | 冷藏 | 3 天左右 |
| 酱汁 | 单独装小盒 | 冷藏 | 3-5 天 |

## 3. 不建议提前完全做好的内容

- 绿叶菜：容易出水、发黄，建议前一晚或当天早上快炒。
- 炸物：冷藏后会回软，口感下降。
- 半熟蛋：不适合长时间带饭保存。
- 凉拌菜：不建议长时间室温携带。
- 海鲜：复热口感变化大，也更需要注意保存。

## 4. 复热口感保持

| 食物 | 复热方法 | 口感提醒 |
|---|---|---|
| 米饭 | 微波炉加热，可喷少量水 | 更接近现蒸口感 |
| 鸡腿肉 | 微波炉中火或平底锅回热 | 避免过热变柴 |
| 炖肉 | 连汤汁一起加热 | 不容易干 |
| 西兰花 | 微波短时间加热 | 过热会发黄变软 |
| 煎牛肉 | 建议半成品冷冻，吃前快炒 | 完全熟制后复热容易老 |

## 5. 食品安全提醒

- 熟食冷却后应尽快密封冷藏，不建议长时间室温放置。
- 冷藏便当建议优先吃前 2-3 天的熟菜。
- 米饭如果有异味、发黏或长时间室温放置，不建议继续食用。
- 便当复热要热透，尤其是肉类和米饭。

> 若用户进一步要求某道备菜的详细做法，则按指定制作处理，每个操作步骤都配可渲染真链图。
```

### 为什么这是好例子

```markdown
- 没有简单建议“一次做 5 天熟菜”。
- 区分适合提前做和不适合提前做。
- 有保存方式、时间、复热方法和口感变化。
- 对米饭、半熟蛋、海鲜等高风险点有提醒。
- 涉及具体做法时仍要求每步配图。
```

## 九、反例 1：只给菜名，不给执行路径

### 用户需求

```markdown
帮我设计一套四菜一汤，朋友周末来家里吃。
```

### 不合格输出

```markdown
可以做：
1. 红烧肉
2. 清炒时蔬
3. 可乐鸡翅
4. 凉拌黄瓜
5. 番茄蛋汤

这些菜都很好吃，适合朋友聚会。
```

### 问题说明

```markdown
不合格原因：

- 只给菜名，没有菜单搭配逻辑。
- 没有份量、人数、采购清单。
- 没有备菜安排和出餐顺序。
- 没有说明哪些可以提前做。
- 没有任何关键步骤和注意事项。
- 没有图文规划，更没有每步配图和现代食谱信息图。
```

### 应改为

```markdown
应使用“菜单/套餐设计类输出结构”，至少包含：
- 场景与目标
- 菜单总览
- 搭配逻辑
- 采购清单
- 备菜安排
- 出餐时间线
- 分菜品步骤（每道菜每步配图）
- 关键技巧
- 保存与剩菜处理
- 现代食谱信息图 + 图文规划（真实步骤图优先、生成图风格统一、不留占位）
```

## 十、反例 2：图文教程只放成品图

### 用户需求

```markdown
做一个水波蛋图文教程。
```

### 不合格输出

```markdown
# 水波蛋教程

配图：水波蛋成品图

步骤：
1. 烧水。
2. 放鸡蛋。
3. 煮熟。
4. 捞出。
```

### 问题说明

```markdown
不合格原因：

- 只放成品图，没有关键步骤图，违反“每个操作步骤都配图”。
- “烧水”“放鸡蛋”“煮熟”都过于笼统。
- 没有说明水面应微沸，不是大滚。
- 没有说明鸡蛋如何入水。
- 没有说明蛋白凝固状态。
- 没有真实步骤图检索词。
- 没有半熟蛋食品安全提醒。
```

### 应改为

```markdown
应为每个操作步骤配一张可渲染真链图（真实图优先），并拆成真实图片需求：
- 水波蛋 微沸水面
- 水波蛋 鸡蛋贴近水面滑入锅中
- 水波蛋 蛋白凝固包裹蛋黄
- 水波蛋 漏勺捞出
- 水波蛋 厨房纸吸水
- 水波蛋 成品 半流心

并为每一步写清：
- 操作
- 时间
- 火候/温度
- 状态判断
- 注意事项
- 图片（可渲染真链）+ 图片来源 + 推荐检索词
```

## 十一、反例 3：把生成图当作精准状态判断且不标免责

### 用户需求

```markdown
帮我做一个蛋白打发教学，要配图。
```

### 不合格输出

```markdown
我直接生成三张蛋白打发图当作判断标准：
1. 湿性发泡
2. 中性发泡
3. 硬性发泡
（不标注来源，也不说明是否为示意图）
```

### 问题说明

```markdown
不合格原因：

- 蛋白打发程度是关键状态判断节点，应优先检索真实参考图，而不是直接拿生成图当精准判断标准。
- 即使确实无法检索到真实图、改用统一风格生成图兜底，也必须标“示意图，仅供参考，实际以文字描述为准”，此处缺少免责。
- 没有说明每个状态的可观察标准。
- 没有说明过度打发的风险。
```

### 应改为

```markdown
应优先检索真实图（落到正文为可渲染真链，每个状态一张）：
- 蛋白打发 湿性发泡 弯钩
- 蛋白打发 中性发泡 小弯钩
- 蛋白打发 硬性发泡 直立尖角
- 蛋白打发 过度打发 粗糙结块

若多轮检索确实无果，可用统一风格生成图兜底，并在图注标“示意图，仅供参考，实际以文字描述的状态判断为准”。

并说明：
- 湿性发泡：提起打蛋头有大弯钩，适合部分蛋糕卷。
- 中性发泡：小弯钩，泡沫细腻稳定，常用于戚风。
- 硬性发泡：尖角直立，适合部分蛋白霜。
- 过度打发：泡沫粗糙、结块，容易消泡。
```

## 十二、反例 4：安全表达过度承诺

### 用户需求

```markdown
帮我做一个控糖早餐，适合糖尿病人吃。
```

### 不合格输出

```markdown
这个早餐糖尿病人可以放心吃，不升糖，非常健康，还能减脂。
```

### 问题说明

```markdown
不合格原因：

- “放心吃”“不升糖”“非常健康”“还能减脂”都是过度承诺。
- 没有说明份量、碳水来源和个体差异。
- 糖尿病属于健康管理场景，不能替代医生或营养师建议。
```

### 应改为

```markdown
更合适的表达：

“下面给一个相对控糖友好的早餐思路，重点是控制精制糖和总碳水量，增加蛋白质和蔬菜。具体是否适合你的血糖管理，需要结合个人情况、用药和医生/营养师建议。”

输出中应包含：
- 食材和份量
- 碳水来源
- 蛋白质来源
- 烹饪方式（涉及制作步骤时每步配图）
- 可替代材料
- 估算热量或营养时标注“约”
- 不作医疗承诺
```

## 十三、反例 5：步骤空泛，无法照做

### 用户需求

```markdown
红烧肉怎么做？
```

### 不合格输出

```markdown
五花肉切块，炒糖色，加入调料，炖熟，收汁即可。
```

### 问题说明

```markdown
不合格原因：

- 没有食材用量。
- 没有说明五花肉是否焯水。
- 没有说明糖色炒到什么颜色。
- 没有说明加什么调料、加多少。
- 没有说明加热水还是冷水。
- 没有说明炖多久、什么火候。
- 没有说明什么时候收汁。
- 没有失败补救和安全提醒。
- 没有任何步骤配图，违反每步必配图。
```

### 应改为

```markdown
至少应写清，并为每个操作步骤配一张可渲染真链图（关键状态如炒糖色、收汁优先真实图）：
- 五花肉用量和切块大小。
- 是否焯水、焯多久。
- 糖色炒到琥珀色小泡，不要发黑。
- 何时加肉、何时加生抽老抽料酒。
- 加热水没过肉面。
- 大火烧开后转小火炖 45-60 分钟。
- 筷子能轻松插入后开盖中火收汁。
- 糖色发黑发苦时不建议继续用。
```

## 十四、好输出共性总结

优秀输出通常同时满足：

```markdown
1. 先判断任务类型，而不是直接套菜谱。
2. 输出形式强制在文档或 HTML 之间二选一，绝不退回纯文字（用户要“只要文字/不要文档”时也仍用文档/HTML 承载，只是内容写精简）。
3. 覆盖用户显式要求，不遗漏甜品、饮品、图文、HTML、文档等。
4. 食材、调料、份量尽量具体。
5. 步骤按真实制作顺序拆开，关键状态单独成步、细碎动作合并。
6. 每个关键步骤有时间、火候、状态判断和注意事项。
7. 每个操作步骤都配一张可渲染真实图片链接，全程不留图片占位、不写假链接。
8. 关键状态判断图优先真实检索图；无果用统一风格生成图兜底，并标“示意图，仅供参考”。
9. 生成图用于封面、信息图、示意图、摆盘参考，可作关键状态兜底但须标示意+免责，不冒充精准判断标准。
10. 文档/HTML 默认加入现代食谱信息图模块；多张生成图风格统一、全文协调。
11. 复杂任务有总览、采购清单、时间线和分模块步骤（每道菜每步配图）。
12. 失败诊断区分当前补救和下次避免。
13. 配方替代说明比例、影响和风险。
14. 备菜保存说明保存方式、保存时间、复热方法和口感变化。
15. 涉及食品安全、操作安全、特殊人群时有提醒。
16. 不说“保证成功”“最健康”“一定减脂”等过度承诺。
17. 结构清晰，不重复章节，不把多道菜步骤混在一起。
```

## 十五、快速判断：当前输出是否像好案例

输出前可以用以下问题快速检查：

```markdown
- 是否默认用了文档或 HTML（仅例外时精简文字）？
- 用户看完能不能直接开始做？
- 新手会不会卡在“适量”“炒熟”“煮一会儿”这种模糊词上？
- 有没有写清什么时候加什么、什么时候转火、什么时候出锅？
- 有没有写清什么状态算对？
- 是否为每个操作步骤都配了可渲染真实图片，全程无占位、无假链接？
- 关键状态图是否优先真实检索图？无果生成图是否标“示意图，仅供参考”？
- 文档/HTML 是否默认加入现代食谱信息图模块？多张生成图是否风格统一？
- 如果是长内容，有没有总览、清单和时间线？
- 如果是失败诊断，有没有当前补救和下次避免？
- 如果是替代，有没有比例和影响？
- 如果是保存复热，有没有食品安全提醒？
- 有没有不该说的健康承诺或绝对化表达？
- 图中文字质量自检：图上所有文字必须真实、可读、与正文一致—— 无乱码、无伪文字、无错别字、无错误或乱拼英文、无缺字漏字重复字；字体统一、字号层级合理、清晰不被遮挡；标题、食材、用量、步骤、数据均与正文完全对应。只要任一项无法保证，必须改用 “无文字视觉底图 + HTML/CSS、SVG 或文档文本层渲染文字”，而不是输出带错字的整图。
```
