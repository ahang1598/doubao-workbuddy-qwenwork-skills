# Output Templates

## 文件定位

本文件是 `cooking-tutorial` Skill 的输出模板文件，用于规定美食制作、菜谱教学、烘焙甜品、饮品制作、烹饪技能、菜单/套餐设计、食材利用、失败诊断、配方调整、备菜保存、图文教程、文档教程和 HTML 教程的输出骨架。

本文件负责回答五个问题：

1. 不同任务应该用什么结构输出？
2. 文档形式、HTML 形式分别怎么组织？（输出形式强制只在文档与 HTML 二选一）
3. 图文教程中的图片、图片说明和图片检索词应该放在哪里？
4. 复杂任务如何拆成总览、模块、步骤、时间线和图文说明？
5. 最终内容如何保证清晰、可执行、可阅读、可复用？

本文件不负责主任务判断、教程细度、图片规则和安全底线。主任务与步骤细度见 `reference/task-and-detail-guide.md`；图片检索、生图边界和信息图规则见 `image-and-visual-guide.md`；食品安全、操作安全、健康表达和质量自检见 `reference/safety-and-quality-guide.md`。

> 与主控规则的一致性：根据 `SKILL.md` 的全局硬性规则，本 Skill 的输出形式**强制只在文档与 HTML 之间二选一，不存在精简文字回答等任何其他形式**，并且**所有输出必须图文并茂、每个操作步骤必须配图**。图片只有“真实检索图（优先）”和“统一风格生成图（兜底）”两档，**不允许图片占位、不允许假链接**；落到正文的图片都必须是可渲染的真实链接。即使用户要求“直接说/简单说/只要文字/不要文档”，也不退回纯文字，而是仍用文档承载、内容写精简；用户明确“不要文档”则改用 HTML。仅当用户明确要求“不要图片/不要信息图/极简文字版”时，才可省略图片（但输出形式仍是文档或 HTML）。本文件中的所有模板默认按文档/HTML、图文并茂、每步必配图设计。

## 一、模板使用总原则

使用模板时，必须先完成以下判断：

1. **判断主任务**：指定制作 / 食材利用 / 菜单套餐 / 烹饪技能 / 失败诊断 / 配方调整 / 备菜保存。
2. **判断内容模块**：菜谱制作 / 烘焙甜品 / 饮品制作 / 烹饪技能，可多选。
3. **抽取约束标签**：场景、人群、目标、食材、设备、时间、难度、份量、口味等。
4. **选择输出形式**：强制只在文档与 HTML 之间二选一。默认**文档形式**；当用户要求 HTML/网页/页面/卡片/可视化时用 **HTML 形式**；即使用户要求“直接说/简单说/只要文字”也仍用文档承载（内容写精简），用户明确“不要文档”则改用 **HTML**，**不存在精简文字回答这种纯文字形式**。
5. **调用对应模板**：单道菜/单技巧/单问题用对应任务模板（仍以文档承载）；多道菜、复杂任务用文档或复杂复合任务模板；网页/卡片/可视化用 HTML 模板。
6. **加入图文模块（默认必做）**：所有输出都图文并茂、每个操作步骤都配图；文档和 HTML 默认加入「一图概览」模块（即下文标注的内部信息图模块，标题对用户显示为「一图概览」）。仅当用户明确要求极简文字版、不要图片或不要信息图时才省略。

模板不是固定填空表，允许根据用户需求增删模块，但不能省略用户显式要求和关键执行信息，也不能省略任何操作步骤的配图。

## 一·补、排版丰富度规则（全局硬性）

输出**禁止通篇 bullet**。同一篇文档/HTML 至少混用 **3 种以上**组织形式（表格、有序列表、高亮块、分栏/看板、折叠块、分割线、标签条等），让排版丰富、有层级、便于扫读。但组件要**用得合理**——服务内容，不为花哨而堆叠。

### 1. 内容性质 → 组件选用对照

| 内容性质 | 推荐组件 | 要避免 |
|---|---|---|
| 概览/元信息（难度·耗时·份量·口味·工具） | 高亮块(Callout) 或 横向标签条；信息多时用紧凑表格 | 一长串 bullet |
| 食材·调料·采购清单 | 表格（带用量列右对齐） | 纯 bullet 罗列 |
| 制作步骤 | 有序列表 + 每步配图，关键状态用 📌 高亮块单独拎出 | 通篇 bullet 平铺 |
| 关键技巧 / 注意事项 | 高亮块分色：💡 技巧、⚠️ 注意/安全 | 平铺 bullet |
| 失败诊断 / 正确·错误对比 | 表格，或左右分栏画板 | 大段文字 |
| 时间线 / 出餐顺序 / 备菜安排 | 表格，或时间轴样式 | bullet |
| 保存·食用建议 | 表格 + 🧊 冷藏/❄️ 冷冻/🔥 复热 标签 | 散落文字 |
| 真正并列的短项（≤5 项、彼此平行、无先后） | 此时才用 bullet | — |

### 2. 高亮块（Callout）使用规范

- 飞书 Callout 可带 emoji 图标，建议固定语义：💡 技巧、⚠️ 注意/食品安全、📌 关键状态判断、🧊 冷藏、❄️ 冷冻、🔥 复热、🌶️ 辣度、⏱️ 时间。
- 高亮块只用于**关键状态、安全提醒、核心技巧、估算说明**等需要"跳出来"的信息，不要把普通正文也塞进高亮块。
- 同一篇里高亮块不宜过密，避免整页都是色块。
- **高亮块看板（2×2 / 2×N 网格，推荐用于"关键技巧与注意事项"）**：当技巧/注意点有 3 条以上时，优先把它们分类塞进**网格看板**（如左上「💡 核心技巧」、右上「⚠️ 易错点」、左下「📌 状态判断」、右下「🧊/🔥 进阶建议」），比竖排单列 callout 更丰富、更便于扫读。
  - HTML 用 `.callout-grid`（CSS Grid 两列），响应式窄屏自动转单列；文字全部走文本层。
  - 飞书文档不支持网格 CSS 时，退回**分组的高亮块序列**（按类别分组、每组一个 callout），仍比一长串平铺 bullet 丰富。
  - 看板内每格保持同级语义（都是"技巧类"或都是"注意类"），不要把不相关信息硬凑成网格。

### 3. 表格使用规范

- 用量、热量、时间等数值列右对齐；表头简洁。
- 表格只用于"多项 × 多属性"的对比/清单；单条信息不要硬做成表。
- 不要把一个完整步骤的长说明塞进单元格，步骤正文走有序列表，表格只承载结构化要点。
- **宽度统一、适中、撑满容器（重要）**：表格宽度优先**占满内容容器**（HTML 用 `width:100%`），不要让两列内容挤在左半边、右边大片留白显得"小气"。同一篇里各表格宽度基线尽量统一。
  - HTML 表格统一加 `width:100%; table-layout:fixed`；标签/项目列设 `width:25%~30%`，内容/详情列占其余 `70%+`，并给内容列 `min-width` 防止被压扁。
  - 内容长可以让行高/换行自然延展（"太长可以长"），但**禁止整表收窄成窄条**。
  - 飞书文档表格不支持自定义 CSS 宽度，则通过**让每列都有实际内容、必要时合并稀疏的两列表为更宽的多列表或改用高亮块**来避免窄条；不要输出只有两列且每列都很短的"小气表"。

### 4. emoji 使用规范

- 可在标题前缀和高亮块图标处**适当**使用 emoji 提升可读性（如「🍳 制作步骤」「🛒 采购清单」），保持同一篇内图标语义一致。
- 不滥用、不在正文句中乱插 emoji；纯文字/极简版按用户要求可不加。

> 落地要求：下文各模板给出的是"可混排骨架"，模型应按本节对照表把内容映射到合适组件，而不是把所有模块都退化成 bullet 或都套同一张表。

## 二、输出形式选择表

| 用户需求/任务特征 | 推荐输出形式 | 模板 |
|---|---|---|
| 单道菜、单个甜品、单杯饮品、单个技巧、单个失败问题 | 文档形式（默认） | 对应任务模板 |
| 多道菜、一桌菜、四菜一汤、一周餐食、聚会餐、年夜饭 | 文档形式 | `菜单/套餐设计文档模板` |
| 明确要求飞书、Word、PDF、正式教程、可打印、可分享 | 文档形式 | `文档模板` |
| 明确要求 HTML、网页、页面、卡片、可视化菜谱页、图文步骤页 | HTML 形式 | `HTML 教程模板` |
| 明确要求信息图、一张图看懂、步骤图、菜谱信息图 | 文档或 HTML 承载 + 「一图概览」模块 | `一图概览模块模板` |
| 需要真实步骤图、状态图、图片检索词 | 任意形式均加入（默认） | `图文步骤模块模板` |
| 失败诊断、配方替代、备菜保存 | 文档形式 | 对应任务模板 |
| 复杂复合任务 | 文档形式优先 | `复杂复合任务模板` |

> 输出形式强制只在文档与 HTML 之间二选一。即使用户说“直接说/简单说/只要文字/不要文档”，也不退回纯文字：仍用文档承载、内容写精简；用户明确“不要文档”则改用 HTML。

## 三、通用内容模块

无论使用哪种输出形式，核心内容可从以下模块中按需选择。

### 1. 基础信息模块

> 元信息优先用**高亮块/标签条**呈现，更轻快；项目较多时再退回紧凑表格。不要写成一长串 bullet。

高亮块写法（推荐）：

```markdown
> 🍳 **{菜品名称}**　|　难度：新手友好　|　⏱️ 准备 10 分 + 制作 15 分　|　份量：2 人份
> 口味：咸鲜　|　适合场景：快手晚餐　|　主要工具：炒锅
```

项目较多时的紧凑表格写法：

```markdown
## 教程概览

| 项目 | 内容 |
|---|---|
| 类型 | 菜谱制作 / 烘焙甜品 / 饮品制作 / 烹饪技能 |
| 难度 | 新手友好 / 家庭版 / 进阶版 |
| 预计耗时 | 准备时间 + 制作时间 |
| 份量 | 例如 2 人份 / 4 人份 / 1 杯 |
| 口味特点 | 例如 咸鲜、清淡、奶香、酸甜 |
| 适合场景 | 例如 早餐、晚餐、便当、聚会 |
| 主要工具 | 例如 炒锅、烤箱、空气炸锅、奶锅 |
```

- **排版要丰富：禁止通篇 bullet，至少混用表格、有序列表、高亮块等 3 种以上形式。**
- 保存模块标题按是否需复热动态选择（含热菜「保存、复热…」/ 全冷食「保存…」，不带"复热"）。

## 十七、输出前模板自检

输出前检查：

- 是否选择了正确模板？输出形式是否在文档/HTML 之间二选一（绝不退回纯文字）？
- 是否覆盖用户显式要求？
- 是否判断主任务和内容模块？是否抽取约束标签？
- 是否写清食材、调料、用量、工具？是否写清前期准备？
- 是否按真实顺序拆分步骤？关键状态是否单独成步、细碎动作是否合并？
- 是否写清时间、火候、温度、状态判断？
- 是否有关键技巧、注意事项、失败补救？
- 是否按需加入保存、复热（仅热菜）和食品安全提醒？
- **是否为每个操作步骤都配了可渲染的真实图片链接，全程无图片占位、无假链接？**
- 关键状态图是否优先真实图？无果生成图是否标“示意图，仅供参考”？
- 文档或 HTML 是否默认加入「一图概览」模块？
- **可见正文/标题是否没有出现"现代食谱信息图"字样（统一用「一图概览」），也没有泄漏内部视觉 brief 分区名？**
- **排版是否丰富（禁止通篇 bullet，混用表格/有序列表/高亮块等≥3 种），技巧与安全提醒是否用 💡/⚠️ 高亮块？**
- **保存模块标题是否按是否需复热动态处理（冷餐/凉菜/饮品/甜品不出现"复热"二字）？**
- 多张生成图是否风格统一、全文协调？
- HTML 是否使用语义结构、`figure`、`figcaption`、准确 `alt`，且每个步骤卡片都有图？
- 复杂任务是否先总览，再分模块展开？
- 是否避免重复章节、信息堆叠和多菜步骤混写？
