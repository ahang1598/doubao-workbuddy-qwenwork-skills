# Image and Visual Guide

## 文件定位

本文件是 `cooking-tutorial` Skill 的图片与视觉参考文件，用于指导模型在美食制作、菜谱教学、烘焙甜品、饮品制作、烹饪技能、文档教程和 HTML 教程中，如何合理使用图片、图片说明、图片检索建议、图片生成提示和信息图视觉模块。

本文件负责回答八个问题：

1. 什么时候需要图文并茂？
2. 图片应该来自网上检索，还是直接生成？
3. 每个步骤应该如何拆成图片需求？
4. 真实步骤图、状态图和生成图的边界是什么？
5. 文档/HTML 中的信息图应该如何组织？
6. 图片如何服务教程，而不是变成装饰？
7. 不同类型的食谱图应该如何选择和生成？
8. 图中文字如何避免乱码、错字、伪文字、字体失控和内部说明泄漏？

本文件不负责主任务分类、教程步骤细度、食品安全、输出模板和示例案例。主任务与步骤细度见 `reference/task-and-detail-guide.md`；安全与质量底线见 `reference/safety-and-quality-guide.md`；输出骨架见 `templates/output-templates.md`；参考案例见 `examples/examples.md`。

> 与主控规则的一致性：根据 `SKILL.md` 的全局硬性规则，本 Skill 的输出形式**强制只在文档与 HTML 之间二选一，不存在精简文字回答等任何其他形式**，并且**所有输出必须图文并茂**。即使用户要求“直接说/简单说/只要文字/不要文档”，也不退回纯文字：仍用文档承载、内容写精简，用户明确“不要文档”则改用 HTML。仅当用户明确要求“不要图片/不要信息图/极简文字版”时，才可省略图片（但输出形式仍是文档或 HTML）。

> 关于占位示意：本文件正文、提示词模板和示例中出现的 `{菜品名称}`、`{口味描述}`、`{步骤画面列表}`、`https://可渲染的真实图片URL.jpg` 等花括号字段与示意 URL，均为**面向模型的占位说明**，用于指示该处应填入的内容。实际输出时必须替换为真实菜品信息和**可渲染的真实图片链接**，绝不能把这类字面占位原样写进给用户的正文。

## 总则：图片交付六大铁律（最高优先级）

以下六条为本文件最高优先级规则，覆盖下文其余所有关于图片密度、图片来源、生成图、信息图和文字渲染的描述。

### 铁律一：每步必配图

在文档与 HTML 输出中，教程的**每一个操作步骤都必须配一张图片**，不得出现“有文字步骤但无图”的步骤。成品、食材、关键状态、摆盘、信息图等也应按需配图。仅当用户明确要求“不要图片/极简文字版”时例外。

### 铁律二：图片只有真实图/生成图两档，不留占位

每张图片的来源只在以下两档之间选择，**默认必须有图，不允许用空白图片占位作为最终交付**：

1. **第一优先：真实检索图。** 优先从网上检索与该步骤的操作动作、关键状态高度匹配的真实图片。涉及火候、油温、水温、糖色、打发、发酵、凝固、熟度、乳化、收汁等关键状态判断节点，应尽最大努力使用真实图或真实参考图。
2. **兜底：统一风格生成图。** 当某步骤经充分检索仍找不到高匹配真实图时，用生成图兜底，不留空位、不漏图。生成时须沿用全文统一风格。

处理顺序：

- 有能力生成图：必须生成图片并插入。
- 没有生图能力但有图片检索能力：必须检索真实图片并插入。
- 有真实图：优先用真实图。
- 没有合适真实图：用生成图兜底。
- 不允许最终完全没有图片。
- 用户明确要求“不要图片/纯文字版/不要信息图”时，才可以省略图片。

### 铁律三：生成图全文风格必须统一

一篇教程中若使用了多张生成图（兜底图、封面、信息图、摆盘图、步骤图等），必须保持统一视觉风格，包括：

- 色调一致
- 光影一致
- 构图语言一致
- 图标风格一致
- 卡片风格一致
- 质感一致
- 背景风格一致

不得出现一张像写实摄影、一张像卡通插画、一张像电商海报、一张像杂志大片的风格割裂。

### 铁律四：关键状态生成图必须标注示意与免责

当关键状态节点不得不使用生成图兜底时，图注必须明确写出：

> 示意图，仅供参考，实际请以文字描述的状态判断为准。

适用节点包括：

- 水温、油温、微沸、大滚
- 炒糖色颜色
- 蛋白打发状态
- 面糊浓稠度
- 面团发酵状态
- 肉类熟度
- 蛋类凝固程度
- 海鲜熟度
- 酱汁挂勺
- 收汁状态
- 油水分离
- 正确/错误对比
- 失败状态诊断

### 铁律五：图片必须是可渲染的真实链接，不写假占位

无论真实图还是生成图，落到文档/HTML 正文时都必须是**可访问、可渲染的真实图片链接**：

- 真实图用检索到的真实图片 URL。
- 生成图用生成工具返回的图片 URL。
- HTML 的 `src`、文档的图片块都用真链。
- 不得写“图片地址”“图片占位”“待补图”“稍后插入”等假占位文本。
- 若当前环境无法联网检索，则走生成图兜底。
- 若当前环境不能完成插图，应在执行层面重新选择支持图片交付的方式，而不是输出无图文档。

### 铁律六：图上文字必须可读、准确、无乱码

所有食谱图、信息图、步骤图中出现的文字必须满足：

- 无乱码
- 无伪文字
- 无错误英文
- 无错别字
- 无缺字漏字
- 无无法辨认的假中文
- 字体风格统一
- 字号层级合理
- 文字不遮挡食物主体
- 文字不挤压图片内容
- 食材、步骤、数据与正文一致

**默认文字渲染方式（硬性）：凡需在图上呈现中文标题、食材名称、用量、步骤说明、调料配比、关键数据的，一律生成「无文字视觉底图」，文字全部由 HTML/CSS、SVG 或文档文本层叠加，禁止生图模型直接生成这些中文文字与数字。** 生图模型只负责成品主体、食材小图、调味品小图、背景、装饰元素、卡片底色等无文字视觉素材。仅当文字为极短英文/数字标签、且本节自检全部通过时，才允许带字生成。

> **现代食谱信息图（即「一图概览」）专项更严约束**：这张概览图**一律生成纯无文字视觉底图**，不适用上句"极短英文/数字标签可带字"的例外——即**任何文字、数字、标签都不画进图**，生图时也**不为文字预留版位**，只把成品、食材、装饰元素合理排布成干净画面；原本要呈现的标题、食材、用量、关键数据等全部交给文本层承载（HTML 端走分栏，文档端走图下文字块，见「推荐排版范式」一节）。

如果生成图中文字出现乱码、错字、伪文字、错误英文、字体不统一或不可读，必须重新生成，或改为“无文字视觉底图 + HTML/CSS、SVG 或文档文本层渲染文字”。

### 配图质量补充硬约束（隶属铁律一、铁律二，与六大铁律同等强制）

以下两条是对“铁律一：每步必配图”和“铁律二：真实图优先”的细化——**“配图”不只是“有图”，而是要有“对的、不重复、不带水印的图”**。它们不新增铁律编号，但与六大铁律同等强制，下文其余条文遇到“成品图替代”“水印”相关描述均以本处为权威定义。

**补充一：步骤图必须是“对应该步动作/状态的过程图”，禁止成品图凑数、禁止无意义雷同。**

- 每个步骤要配能看出“这一步在做什么、做到什么状态”的过程图（如切配、煸炒、裹油、加汤、焖煮、收汁等），不同步骤应是**内容不同**的过程图。
- **禁止用成品图填充过程步骤位**：成品图只能出现在成品、封面、概览处，不得放进切配、下锅、翻炒、加水、焖煮、收汁等过程步骤旁。
- **禁止无意义雷同**：不得多个不同动作的步骤共用同一张图，也不得堆几张看不出区别的图充数；若几张图看起来差不多，说明检索词没拆开，必须按“动作+状态”重新拆词重搜。
- **合理例外**：确属“同一持续状态、仅时间推移”的相邻步骤（如同一锅持续焖煮），可按配图密度规则**合并成一步配一张过程图**，这属于合理合并，不算凑数；但合并后的图仍须是该步的过程图，不能用成品图替代。
- 检索时每一步用各自不同的检索词（动作不同、状态不同），不得所有步骤都套菜名成品图。

> 例（海南鸡饭·鸡油饭）：正确是“煸炒姜蒜出香 / 米粒裹鸡油变透亮 / 倒入鸡汤焖煮”等不同过程图；错误是每个步骤都放同一张白盘鸡饭成品图。

**补充二：落入正文的真实检索图严禁带任何可见水印或平台/用户角标。**

- **禁止任何可见水印**：包括平台 logo、网站域名、博主/用户名角标、App 水印、任何图库样片水印、相机时间戳、二维码、促销文字贴片等，**无论深浅、无论位置，一律不用**（不存在“水印不重就放行”）。
- 命中带水印的候选图时：**先换图**——更换检索词或来源重新找干净图；**仍找不到干净真实图**时，按铁律二改用**统一风格、无水印的生成图**兜底（关键状态兜底图仍按铁律四标“示意图，仅供参考”）。
- **不得**以去除他人水印为目的对图片进行裁切、涂抹、打码后当作干净图使用（既不可靠也涉及版权）；正常构图裁剪不在此限。
- 生成图同样不得出现伪水印、伪平台标识（与铁律六一致）。

### 推荐排版范式：图文一体 / 图文分栏（隶属铁律六，为“图上文字走文本层”的推荐实现形态）

本节是对“铁律六：图上中文文字默认走文本层”的版式细化，目的是让排版既丰富好看、又始终不让生图模型直接画中文字。它不新增铁律编号，但下文涉及“图文一体”“分栏”“速览图版式”均以本处为权威定义。

**前提（先消歧，最重要）：**

- 这里的「**图文一体**」= **无文字视觉底图 + 文本层（HTML/CSS、SVG 或文档文本层）贴合排版**，看起来图文融合、紧凑好看；它**不是**“让生图模型把中文标题/食材/用量/数据画进图里”。
- 这里的「**图文分栏**」= 同样是**无文字视觉底图 + 文本层**，只是版式上左右或上下分开排（如左图右文）。
- **两种版式的文字都走文本层**，区别只是版面松紧，**都不允许让生图模型直接画中文文字与数字**（与铁律六完全一致）。

**一、现代速览图（顶部信息图 / 一图概览）：固定为「无文字底图 + 文本层」，图上不画任何字。**

- **底图（硬性）**：一律生成**纯无文字视觉底图**——只画成品/食材/装饰元素，**不画任何文字、数字、标签，也不为文字预留版位**（不再保留"标题留白区/数据气泡位"等待填字的空位），把画面合理排满即可（与铁律六「现代食谱信息图专项更严约束」一致）。
- **文字承载（硬性）**：菜品名、食材清单、用量、总时长、份数、难度、关键参数等全部走文本层，分场景实现：
  - **HTML 端**：默认采用「左图右文卡片分栏」（无字底图在一侧、文本信息在另一侧），即把分栏作为这张概览的**默认呈现版式**，而非"带字生成失败后才退回"的备选。
  - **文档 / 飞书文档 / 纯 Markdown 端**：默认采用「图 → 紧跟其下文字块」的上下式（这些环境无法稳定渲染左右分栏，见下文「四、分场景实现」）。
- 因此这张概览图**不存在"带字生成"路径**，也就不存在"文字乱码退回"问题——它从一开始就是无字底图 + 文本层。

**二、步骤图：推荐「左图右文步骤条」，好看时也可用大图。**

- **推荐**：每步一行「左过程图 + 右步骤说明 / 状态判断 / 火候时间」的分栏步骤条，与“配图质量补充硬约束·补充一（每步不同过程图）”天然配合，强制一步一图一描述、更难用成品图凑数。
- **例外（图为主角处）**：成品展示、封面、概览等图本身即主角的位置，或排版上整图大图更好看时，可用整图大图，不强制分栏。
- 无论分栏与否，都不得削弱既有硬约束。

**三、最低底线（兜住下限，防止软推荐被忽略后退化）：**

- 推荐图文一体 / 分栏的丰富排版；但即使不分栏、不做花式排版，也**必须**满足“每步必配图、每步不同过程图（补充一）、关键状态标示意与免责（铁律四）、检索图无水印（补充二）、文字走文本层（铁律六）”等全部既有硬约束。
- **分栏与否只是版式选择，不得成为减少配图、堆成品图或让模型画字的借口。**

**四、分场景实现（防止 HTML 分栏在文档/Markdown 里渲染崩）：**

- **HTML 产物**：用 flex / grid 实现真正的左右分栏，并做响应式（窄屏自动转上下堆叠），具体骨架见 `templates/output-templates.md`。
- **文档 / 飞书文档 / 纯 Markdown 产物**：这些环境无法稳定渲染左右分栏，应改用「图 → 紧跟其下的文字块」的**上下式图文对应**（视觉上仍是一步一图一描述），**不要**在文档里硬塞 flex/grid 分栏代码，否则会渲染成乱码或塌成上下堆叠。

## 一、总原则

美食制作与烹饪教学类内容**必须**图文并茂，且**每个操作步骤都必须配图**。图像不是附属装饰，而是帮助用户理解操作过程、状态判断、火候变化、食材质地和最终效果的重要组成部分。

核心原则：

1. **步骤先行**：先拆解真实制作步骤，再决定每一步需要什么图片。
2. **真实状态优先**：涉及真实火候、质地、颜色、凝固程度、发酵程度、打发状态、油温水温等判断时，优先用真实图片；实在检索不到时方可用生成图兜底，并按铁律四标注示意与免责。
3. **图片服务教学**：每张图片都必须对应具体步骤、状态判断、注意事项或成品呈现，不能只做装饰图。
4. **生成图有边界**：生成图主要用于封面、信息图、风格化插图、图标流程、摆盘参考，以及检索无果时的兜底；能用真实图的关键状态，不主动用生成图替代。
5. **文档/HTML 默认图文并茂**：默认输出形式为文档或 HTML，二者均默认加入图文模块和现代食谱信息图模块，除非用户明确要求极简文字版、不要图片或不要信息图。
6. **检索要拆细**：不能只检索菜名成品图，应将每个关键步骤拆成“菜品名称 + 操作动作 + 关键状态 + 视觉目标”后分别检索。
7. **版权与来源清楚**：使用网络图片时，应注意图片来源、版权和引用说明，不应把不确定来源的图片当作自有图片。
8. **视觉清晰优先**：图片必须清晰、直观、能说明问题，优先选择步骤明确、状态可辨、无过度修图的图片。
9. **生成图全文风格统一**：当一篇教程中使用了多张生成图，必须保持统一的视觉风格，使全文美观协调，不出现风格割裂。
10. **图上文字默认走文本层（硬性）**：中文标题、食材名称、用量、步骤说明、调料配比、关键数据一律用 HTML/CSS、SVG 或文档文本层渲染，禁止生图模型直接生成这些中文文字与数字；生图模型只负责无文字视觉素材。仅极短英文/数字标签且自检全部通过时才允许带字生成。

## 二、什么时候必须使用图文策略

由于所有输出强制图文并茂且每步必配图，**本文件的图文规则默认必用**。以下情况尤其关键：

- 用户要求图文并茂、图文教程、步骤图、菜谱信息图、一张图看懂、可视化教程。
- 用户要求生成飞书文档、Word、PDF、HTML、网页教程、图文步骤页、可视化菜谱页。
- 教程涉及复杂步骤、关键状态判断、火候判断、质地判断、正确/错误对比。
- 教程涉及烘焙、甜品、饮品等对颜色、质地、分层、打发、发酵、凝固状态要求较高的内容。
- 用户是新手，或者需求中出现“不翻车”“新手友好”“详细步骤”等表达。
- 输出内容较长，包含多道菜、套餐、四菜一汤、一周餐食、甜品、饮品和技能模块。
- 用户要求信息图、封面图、配图建议、图片生成提示或图片检索关键词。
- 用户要求小红书风格、适合保存、适合分享、食谱长图、完整食谱卡片等视觉化内容。

如果用户明确要求“不要图片”“只要文字”“极简文字版”，可以不配置图片，但仍要保证步骤、火候、时间、状态判断清楚。

## 三、图片来源选择规则

图片来源只在两档之间选择：**网上检索真实图片**与**直接生成图片**。不使用图片占位。选择时应根据图片用途判断。

### 1. 优先用真实检索图的情况

当图片用于说明真实烹饪状态、关键火候、食材变化、失败对比、操作动作时，应优先从网上检索真实图片。

适合且应当优先检索真实图的内容包括：

- 真实菜品成品图。
- 食材真实状态图。
- 切配、腌制、焯水、下锅、翻炒、加水、焖煮、收汁、出锅等真实过程图。
- 水温、油温、锅气、微沸、沸腾、糖色、焦化、乳化、挂勺等状态图。
- 蛋白打发、面糊浓稠度、面团发酵、烘烤上色、蛋糕回缩等烘焙状态图。
- 饮品分层、奶泡状态、冰块比例、茶汤颜色、咖啡萃取状态等饮品状态图。
- 正确与错误做法对比图。
- 失败状态图，例如蛋糕塌陷、面包未发起、炸物回软、汤汁油水分离。

应当尽最大努力用真实图的关键状态判断节点包括：

- 水波蛋入水状态、微沸水面、蛋白凝固包裹蛋黄、漏勺捞出、厨房纸吸水。
- 炒糖色从浅黄到琥珀色的颜色变化。
- 蛋白湿性发泡、中性发泡、硬性发泡。
- 面团发至 2 倍大、按压缓慢回弹。
- 面糊提起呈飘带状、无干粉状态。
- 油温状态，例如筷子周围冒细泡、食材下锅起泡程度。
- 肉类变色、收缩、煎至焦边、炖至可戳透。
- 汤汁浓稠、酱汁挂勺、开盖收汁状态。
- 绿叶菜断生但保持翠绿。
- 饮品分层、奶泡细腻、冰块未明显融化。

> 对上述关键状态节点：先多轮检索真实图；确实无果时方可用生成图兜底，并按铁律四标注“示意图，仅供参考，实际以文字描述的状态判断为准”。

### 2. 用生成图兜底的情况

当某步骤检索不到高匹配真实图时，用生成图兜底，不留占位。

适合用生成图兜底或表达的内容包括：

- 难以检索到真实图的通用动作步骤，例如“加盐翻匀”“倒入调好的料汁”“撒葱花”“装碗”等。
- 多轮检索仍无真实图的关键状态节点。
- 统一风格的图文教程封面。
- 菜谱信息图、现代食谱信息图、视觉摘要图。
- 步骤示意图、教学插图、图标流程图。
- 食材处理示意图。
- 摆盘参考图、成品氛围图。
- 社交平台或文档中使用的现代美食视觉图。
- 拼贴式步骤海报、双栏食谱长图、单页完整食谱信息图等视觉图。

生成图片时必须满足：

- 明确标注其用途，例如“示意图”“信息图”“风格化参考图”“摆盘参考图”。
- 不把生成图当作真实步骤照片。
- 沿用全文统一视觉风格。
- 若为关键状态兜底图，额外加“仅供参考，实际以文字描述的状态判断为准”。
- 图中如包含文字，必须自检无乱码、无错字、无伪文字、无错误英文。

## 四、步骤图片拆解方法

图文教程不能先生成一张泛化插图，而应先把教程步骤拆解成图片需求，再为每一步配置图片。每个步骤都要明确：该图优先真实检索图，无果时用统一风格生成图。

### 1. 拆解公式

每个关键步骤的图片需求应按以下公式拆解：

```markdown
菜品/教程名称 + 操作动作 + 关键状态 + 视觉目标
```

例如：

```markdown
水波蛋 + 鸡蛋贴近水面滑入锅中 + 水面微沸 + 展示蛋白不被冲散
水波蛋 + 蛋白凝固包裹蛋黄 + 中心仍柔软 + 展示捞出前状态
红烧肉 + 炒糖色 + 琥珀色小泡 + 展示糖色不能发黑
戚风蛋糕 + 蛋白打发 + 提起弯钩 + 展示湿性偏中性发泡
牛肉滑炒 + 肉片变色边缘微卷 + 大火快速翻炒 + 展示出锅时机
奶茶 + 茶汤和牛奶混合 + 颜色均匀 + 展示饮品基底状态
```

### 2. 每个步骤的图片字段

输出图文内容时，每个步骤建议包含以下字段，按需取用，避免与正文重复啰嗦：

```markdown
- 步骤名称：
- 操作说明：
- 状态判断：
- 注意事项：
- 图片需求：
- 推荐检索词：
- 图片来源：真实检索图（优先）/ 统一风格生成图（兜底）
- 图片说明：
```

> 注意：`图片来源`只在“真实检索图”和“统一风格生成图”二选一，不写“图片占位”。关键状态判断节点优先填“真实检索图”，仅在检索无果时改为“统一风格生成图（示意，附免责）”。

### 3. 检索词写法

检索词应具体，不要只写菜名。可以同时给中文和英文检索词，提高召回质量。

推荐写法：

```markdown
- 中文检索词：水波蛋 微沸水面 鸡蛋入锅
- 英文检索词：poached egg simmering water egg sliding into pot
```

检索词应包含：

- 菜品名称。
- 具体动作。
- 关键状态。
- 需要看到的视觉细节。

不推荐：

```markdown
水波蛋
红烧肉
蛋糕
奶茶
```

推荐：

```markdown
水波蛋 蛋白凝固 包裹蛋黄 漏勺捞出
红烧肉 炒糖色 琥珀色 小泡
戚风蛋糕 蛋白打发 弯钩状态
奶茶 茶汤 牛奶 混合 分层
```

> 当某步骤多轮检索仍无高匹配真实图：通用动作直接转生成图兜底；关键状态节点先继续放宽/更换检索词、扩展中英文关键词，仍无果再用生成图兜底并标注示意与免责。

### 4. 烘焙与饮品的完整字段示例

烘焙示例：

```markdown
- 步骤名称：蛋白打发至中性发泡
- 操作说明：蛋白分三次加糖，中高速打发至提起打蛋头出现略弯的尖角。
- 状态判断：尖角小弯钩、纹路清晰、盆倒扣不流动。
- 注意事项：打发不足易塌，打过头易消泡分离。
- 图片需求：展示打蛋头提起时蛋白呈中性发泡弯钩。
- 推荐检索词：蛋白打发 中性发泡 弯钩 / egg white soft-to-medium peak
- 图片来源：真实检索图（优先；无果时生成图须标“示意图，仅供参考”）
- 图片说明：图示中性发泡的弯钩状态。（真实图）
```

饮品示例：

```markdown
- 步骤名称：茶汤与牛奶混合
- 操作说明：将晾至温热的红茶汤与牛奶按 1:1 倒入杯中拌匀。
- 状态判断：颜色均匀呈奶茶色，无明显分层。
- 注意事项：茶汤过烫易使奶味发腥。
- 图片需求：展示茶汤与牛奶混合均匀的奶茶基底。
- 推荐检索词：奶茶 茶汤 牛奶 混合 / milk tea mixing
- 图片来源：真实检索图优先，无则统一风格生成示意图
- 图片说明：图示混合均匀的奶茶基底。
```

## 五、图片配置方式

图文教程应按步骤安排图片，每个步骤都要配图，并优先为关键步骤匹配真实图片。

### 1. 成品图

用途：展示最终效果。

要求：

- 优先检索真实成品图。
- 成品图应清晰、自然、能体现菜品标准状态。
- 如用于封面或统一视觉，可生成风格化成品图，但须与全文风格一致。
- 成品图不能替代关键过程图。

示例图片需求：

```markdown
图片需求：展示最终水波蛋，蛋白完整包裹蛋黄，切开后蛋黄半流心。
推荐检索词：水波蛋 成品 半流心 / poached egg runny yolk finished
图片来源：真实检索图（优先）
```

### 2. 食材图

用途：展示主要食材和处理前状态。

要求：

- 优先检索或使用真实食材图。
- 食材图应展示分量、形态、切法或处理前后对比。
- 如果食材状态影响成败，应单独配图，优先真实图。

示例图片需求：

```markdown
图片需求：展示新鲜鸡蛋、白醋、清水和漏勺等水波蛋基础材料与工具。
推荐检索词：水波蛋 食材 鸡蛋 白醋 漏勺
图片来源：真实检索图（优先）
```

### 3. 关键步骤图

用途：展示切配、腌制、下锅、翻炒、加水、焖煮、收汁、出锅等关键节点。

要求：

- 优先检索真实烹饪过程图。
- 图片必须对应具体步骤，不要用成品图代替过程图。
- 需要体现手部动作、锅内状态、食材变化或工具使用方式。
- 复杂动作应使用近景或特写。

### 4. 状态判断图

用途：展示容易出错、文字难以描述的状态。

要求：

- 优先使用真实图片或真实参考图。
- 状态图要清楚体现“到什么程度才算可以进入下一步”。
- 对烘焙、甜品、饮品、火候、油温、水温等尤其重要。
- 多轮检索确实无真实图时，方可用统一风格生成图兜底，并标注“示意图，仅供参考，实际以文字描述的状态判断为准”。

### 5. 通用动作步骤图

用途：展示“加盐翻匀”“倒入料汁”“撒葱花”“装碗”等难以检索真实图的通用动作。

要求：

- 先尝试真实检索。
- 若无高匹配真实图，用统一风格生成示意图兜底。
- 生成图须与全文风格一致，并标注“示意图”。

### 6. 摆盘图

用途：展示出锅装盘、装饰和搭配方式。

要求：

- 可使用真实摆盘图，也可根据需要生成统一风格的摆盘参考图。
- 摆盘图应服务于最终呈现，不必承担步骤判断功能。
- 文档或 HTML 中可用作成品展示、封面或结尾图。

## 六、配图密度与优先节点

**每个操作步骤都必须配图**。下列节点不仅要配图，还应优先使用真实状态图、特写或正确/错误对比图：

- 用户可能不理解的操作。
- 容易失败的节点。
- 状态判断比文字更直观的节点。
- 成品呈现要求较高的节点。
- 烘焙、甜品、饮品中对质地、颜色、分层要求较高的节点。
- 需要区分正确/错误做法的节点。
- 关键火候、油温、水温、糖色、收汁状态。
- 刀工、切配、包裹、整形、打发、发酵、翻拌等动作。
- 新手常出错的步骤。
- 文档或 HTML 中承担视觉导航作用的步骤。

配图密度要求：

- 默认的文档/HTML 教程：每个操作步骤逐一配图。
- 关键状态节点优先真实图。
- 通用动作步骤可用统一风格生成图兜底。
- 复杂套餐：每道菜的每个操作步骤都要配图；关键难点步骤优先真实图。
- 步骤极多时可合并连续细碎动作，例如“加生抽—加老抽—加糖—翻匀”合并为“加入调味料并翻匀”，再配一张图。合并的是步骤粒度，不是漏配。
- 仅当用户明确要求极简文字版、不要图片或不要信息图时，可减少配图、退而为 2-4 个关键节点提供配图建议或检索词（输出形式仍是文档或 HTML）。

## 七、网上搜索图片规则

### 1. 搜索前先拆步骤

不能只检索菜名成品图，应先根据教程拆出每个步骤，再逐步检索对应内容。

错误做法：

```markdown
只检索：水波蛋 图片
然后把成品图放在所有步骤旁边。
```

正确做法：

```markdown
1. 水波蛋 微沸水面
2. 水波蛋 鸡蛋贴水面滑入锅中
3. 水波蛋 蛋白凝固包裹蛋黄
4. 水波蛋 漏勺捞出
5. 水波蛋 厨房纸吸水
6. 水波蛋 成品 半流心
```

> 硬性：每个步骤用各自不同的检索词，配各自不同的过程图；**严禁所有步骤共用一张图、严禁用成品图凑过程步骤位**（见“配图质量补充硬约束·补充一”）。若检索结果与上一步几乎相同，必须换词重搜，直到拿到能看出本步动作/状态的图，实在无果再用统一风格、无水印的生成图兜底；候选图带任何可见水印的，先换图，换不到再用无水印生成图（见补充二）。

### 2. 搜索结果筛选标准

优先选择：

- 画面清晰。
- 步骤状态明确。
- 和当前步骤高度匹配。
- 无明显摆拍误导。
- 无过度滤镜。
- 食材和做法与教程一致。
- 角度能看清关键动作或状态。
- 来源相对可靠，便于引用和说明。

避免选择：

- 只有成品、看不出步骤。
- 过度美化或不真实。
- 与步骤不一致。
- 画面杂乱、重点不清。
- **带任何可见水印、平台 logo、网站域名、博主/用户名角标或图库样片水印（不分深浅，一律排除；权威定义见“配图质量补充硬约束·补充二”）。**
- 不能反映状态判断的泛化图片。
- 与菜系、做法或食材不符的图片。
- **多个不同动作的步骤复用同一张图，或几张步骤图无意义雷同、看不出动作差异（见“配图质量补充硬约束·补充一”）。**
- **用成品图冒充过程步骤图（见“配图质量补充硬约束·补充一”）。**

### 3. 检索失败后的处理

当某步骤经多轮检索仍无高匹配真实图：

- **通用动作步骤**：直接转入统一风格生成图兜底，并标注“示意图”。
- **关键状态判断节点**：先继续放宽或更换检索词、扩展中英文关键词、尝试更通用的同类状态参考图；确实无果再用统一风格生成图兜底，并标注“示意图，仅供参考，实际以文字描述的状态判断为准”。
- **当前环境无法联网检索/插入时**：走生成图兜底，仍不漏图。

任何情况下都不允许最终完全没有图片。

### 4. 图片来源说明

使用网络图片时，应保留或说明来源信息。不要把网络图片说成自制、自有或模型生成。

建议在文档或 HTML 中为图片保留以下信息：

```markdown
- 图片用途：
- 图片来源：
- 对应步骤：
- 图片说明：
- alt 文本：
```

如果无法确认版权或来源，应另寻可用真实图或改用统一风格生成图，不直接声称可商用。

## 八、直接生成图片规则

### 1. 生成图片适用场景

可以直接生成图片的场景包括：

- 步骤检索不到高匹配真实图时的兜底。
- 用户明确要求“生成图片”“画一张图”“做一张信息图”。
- 需要统一视觉风格的文档封面或教程插图。
- 需要现代食谱信息图。
- 需要步骤图标、流程图、版式示意。
- 需要摆盘参考或成品氛围图。
- 需要拼贴式步骤海报、双栏食谱长图、单页完整食谱信息图等视觉图。

### 2. 生成图片提示应包含的信息

生成图片时，应给出清晰画面描述，并确保与全文风格统一：

```markdown
- 菜品名称：
- 画面主体：
- 食材状态：
- 操作动作：
- 构图方式：
- 视角：俯拍 / 侧拍 / 45 度斜角 / 近景 / 特写
- 背景与环境：
- 光线氛围：
- 文字标注：
- 是否需要图标：
- 是否需要信息图布局：
- 成品呈现方式：
- 画面规格：
- 统一风格说明：与本篇其余生成图保持一致的色调/光影/构图/图标风格
- 是否为关键状态兜底图：是→图注须含“示意图，仅供参考”
```

### 3. 生成关键状态兜底图的特别要求

当关键状态节点不得不用生成图兜底时：

- 必须先尽力真实图检索。
- 图注必须含“示意图，仅供参考，实际请以文字描述的状态判断为准”。
- 文字状态判断必须写得足够具体，作为用户判断的主依据。
- 图片仅作辅助。
- 不得让生成的近似颜色/质地被当作精准成败标准。

### 4. 生成图风格一致性

当一篇教程使用多张生成图时，必须保持统一风格：

- 统一色调与饱和度。
- 统一光影方向与强度。
- 统一构图语言与视角偏好。
- 统一图标风格。
- 统一背景质感。
- 统一文字层级与字体风格。
- 兜底图、封面、信息图、摆盘图之间不得出现明显风格割裂。
- 建议在生成第一张图时确立“风格基准”，后续所有生成图沿用同一基准描述。

## 九、信息图文字渲染与防泄漏规则

### 1. 内部视觉 brief 不得外露

现代食谱信息图、分步骤菜谱信息图、拼贴式步骤图、双栏食谱长图、单页完整食谱信息图中的以下内容属于内部视觉 brief，只用于指导生成、排版或设计，不得作为用户可见正文原样输出：

- “信息图包含：……”
- “视觉风格：……”
- “优先级：……”
- “构图说明：……”
- “图片生成提示：……”
- “本模块用于文档开头的视觉总览……”
- “成品菜品视觉主体 + 食材清单 + 核心步骤……”

**特别注意：「食材区 / 步骤区 / 信息区 / 信息区·内容 / 附加信息区」等分区名属于内部排版分组用的 brief，不得作为可见标题画进图或写进正文。** 图上和正文只能出现真实标题（如“食材”“做法步骤”“小贴士”）与真实内容，绝不能把 brief 的分区名当作标题渲染出来。

最终用户可见内容只能包括：

- 信息图标题
- 信息图本体
- 简短图注
- 必要的图片来源说明
- 必要的步骤说明
- 必要的食材与调料信息
- 必要的小贴士

### 2. 图中文字默认走文本层（硬性）

标题、食材名称、用量、调味品、酱汁比例、步骤编号、步骤说明、关键数据、小贴士等中文文字信息，**默认必须**使用以下方式渲染，不得交给生图模型直接生成：

- HTML/CSS 文本层
- SVG 文本层
- 文档文本层
- 可编辑文本框
- 后期排版层

图片生成模型**只**负责无文字或少文字的视觉素材：

- 成品菜品视觉主体
- 食材小图
- 调味品小图
- 步骤过程图
- 背景
- 装饰元素
- 卡片底色

**禁止**让图片生成模型直接生成中文标题、食材清单、用量、步骤段落、调料配比、关键数据等文字。仅当文字为极短英文/数字标签、且第 4 小节自检全部通过时，才允许带字生成。

### 3. 必须带字生成时的限制

如果必须生成整张带字图片，应遵守：

- 文字尽量少。
- 只保留短标题、短标签、短步骤名。
- 不生成长段中文。
- 不生成复杂表格文字。
- 不生成大量中英文混排。
- 不生成细小不可读文字。
- 不生成不确定英文标题。
- 生成后必须自检文字准确性。

### 4. 图中文字自检要求

所有带字图片输出前必须逐项自检：

- 是否有乱码？
- 是否有伪文字？
- 是否有错别字？
- 是否有错误英文或乱拼英文？
- 是否有缺字、漏字、重复字？
- 是否有无法辨认的假中文？
- 字体是否统一？
- 标题、正文、标签是否有层级？
- 字号是否过小？
- 文字是否遮挡食物主体？
- 文字是否和正文菜谱一致？
- 食材数量是否和正文一致？
- 步骤顺序是否和正文一致？
- 调料名称是否和正文一致？
- 图上单位与数值是否真实有效？（不得出现 Wal、Val 等伪单位，不得出现 42:00ng、05:271-21-78.30 等乱码数据；热量、时间、份数、用量必须与正文一致）
- 图中是否出现无意义字符、无关水印、平台伪标识或人名串？

若任一项不合格，必须采取以下处理之一：

1. 重新生成图片。
2. 改为无文字视觉底图。
3. 使用 HTML/CSS、SVG 或文档文本层补字。
4. 删除错误文字，只保留视觉图。
5. 将图注和正文作为准确信息来源。

## 十、分步骤菜谱信息图生成要求

当用户要求为某个菜品生成“分步骤菜谱信息图”“菜谱信息图”“步骤图”“一张图看懂做法”等视觉产物时，应自动匹配该菜品的传统做法，并生成适合信息图呈现的内容结构和画面要求。

### 1. 基础要求

- 可采用俯视图。
- 整体为极简风格。
- 使用白色或浅色背景。
- 顶部居中显示菜品中文名。
- 标注主要食材的中文名称、用量和关键数据。
- 用虚线、箭头、线条和图标展示烹饪步骤。
- 底部展示成品摆盘效果图。

### 2. 内容必须包含

1. **食材清单**：包含精确用量和热量，尽量避免只写“适量”；如确实需按口味调整，应给出参考范围。
2. **烹饪步骤图标**：根据菜品传统做法自动匹配合适图标，例如切菜、腌制、焯水、炒制、煎制、炖煮、调味、收汁、摆盘等。
3. **成品呈现方式**：成品图建议使用 2:3 的摆盘视觉比例，突出最终菜品效果。

### 3. 画面构图建议

- 顶部为菜品中文名。
- 中部以食材区和步骤区为主体。
- 食材、步骤和小贴士应围绕菜品或制作流程有序排布。
- 底部展示成品摆盘效果。
- 整体应留白充足，信息层级清楚，避免文字和元素过密。
- 视觉顺序应让用户一眼看懂：食材 → 步骤 → 成品。

### 4. 信息图中的步骤表达

步骤应短而明确，适合视觉呈现：

```markdown
1. 食材准备
2. 腌制入味
3. 热锅下料
4. 翻炒/炖煮/烘烤
5. 调味收汁
6. 装盘完成
```

如果菜品有关键状态，应在步骤旁加短提示：

```markdown
- 水保持微沸
- 糖色到琥珀色
- 蛋白打至弯钩
- 汤汁收到挂勺
- 表面烤至金黄
```

## 十一、现代食谱信息图视觉要求

当输出形式为**文档形式**或 **HTML 形式**时，应默认加入“超简洁现代食谱信息图”模块，用于展示菜品、食材、步骤、关键数据和成品效果。该模块是文档/HTML 教程中的默认视觉组成部分；如果用户明确要求极简文字版、不要图片或不要信息图，则可以省略。

> **本模块总约束（硬性，优先于本节其余描述）：现代食谱信息图（即「一图概览」）的生成图一律是「纯无文字视觉底图」——图上不画任何中文/英文/数字/标签，生图时也不为文字预留版位。** 下文「食材区/步骤区/附加信息区」等描述的是**最终模块（底图 + 文本层）整体**应呈现的信息，而非要把这些文字画进图里：菜品名、食材名称与用量、步骤说明、热量/时间/份数等关键数据**全部由文本层承载**（HTML 端走「左图右文卡片分栏」默认版式，文档端走「图下文字块」上下式，见第十节「推荐排版范式」）。生图模型只负责成品主体、食材小图、调味品小图、背景、装饰元素与卡片底色等无文字视觉素材。

### 1. 视觉方向

该风格不局限于俯视视角，可以使用透视、斜角视角或轻微悬浮构图，以美观成品形式展示菜品。

整体可采用：

- 杂志风信息图。
- 生活美食摄影结合信息图。
- 极简现代食谱卡片。
- 柔和渐变背景。
- 轻量卡片式步骤面板。
- 玻璃拟物或干净矢量图标。

### 2. 内容组织方式

以菜品成品为视觉主体，例如切片、装盘或分份效果；将食材、步骤和小贴士以动态排版环绕在菜品周围。

食材区要求：

- 为每种食材配置图标或小插画（底图只画图标/小图，不画名称文字）。
- 用量等文字由文本层标注，不画进图。
- 可用群组、列表或环形流动形式排列。
- 与菜品视觉主体产生联系，不要孤立堆放。

步骤区要求：

- 用带编号的面板、箭头或线条展示制作步骤的视觉流向（编号与步骤说明文字走文本层，不画进图）。
- 可搭配小刀、平底锅、烤箱、计时器等小烹饪图标。
- 在主菜周围形成清晰逻辑流程。
- 步骤说明文本由文本层承载，应短而具体，不要长段说明。

附加信息区要求：

- 用简洁气泡或标签的**视觉容器**呈现在菜品附近（容器内的文字由文本层填充，底图不画字）。
- 可包括总热量、准备时间、烹饪时间、份数、辣度等。
- 热量和准备时间等关键数据应在文本层突出展示。
- 如数据为估算，应在文本层标明“约”。

### 3. 视觉风格要求

- 食物色彩应鲜艳自然。
- 光影柔和，不要过曝或过度滤镜。
- 图标简洁偏矢量。
- 字体现代清晰。
- 步骤面板可使用柔和渐变、玻璃拟物或轻量卡片风格。
- 构图层级应清晰，优先级为：菜品 > 步骤 > 食材 > 附加数据。
- 画面应保留足够留白，使信息透气易读。
- 光线与背景建议使用柔和自然的棚拍光线。
- 背景可采用极简纹理或渐变背景，营造高级杂志质感。
- 该信息图风格应与全文其余生成图保持统一。

### 4. 输出规格建议

- 建议规格：1080×1080。
- 超清晰。
- 适配社交平台、文档和网页嵌入。
- 不出现水印。
- 底图为纯无文字视觉素材，不画任何文字（拥挤小字/可读性问题因此天然不存在；所有文字交由文本层渲染并保证清晰可读）。
- 如果需要打印或放入 PDF，可使用更高分辨率或竖版布局。

## 十二、真实摄影拼贴式分步骤食谱图规则

### 1. 视觉类型定义

当用户要求生成“图文菜谱”“步骤图”“一张图看懂做法”“小红书风格食谱图”“分步骤美食海报”等内容时，可以使用 **真实摄影拼贴式分步骤食谱图**。

这种视觉类型不是单张成品照，而是：

- 上方成品主视觉
- 下方 5-6 个步骤过程图
- 菜品标题
- 食材小卡片
- 手写风箭头或短标注
- 底部简短总结文案

核心特点是：**成品吸引人，步骤像拼图一样清楚，适合快速保存和照做。**

### 2. 适用场景

适合：

- 家常菜
- 快手菜
- 小炒类
- 下饭菜
- 简单甜品
- 简单饮品
- 4-6 步能讲清的教程
- 用户要求“小红书风格”“图文步骤图”“一张图看懂”

不适合：

- 复杂烘焙全流程
- 需要大量文字解释的失败诊断
- 需要精确状态判断的大量对比图

### 3. 版式结构

推荐比例：竖版 3:4 或 4:5。

版式：

```markdown
顶部：
- 菜品大标题
- 简短口味描述
- 大幅成品图

中部或侧边：
- 食材准备小卡片

下半部分：
- 2 行 × 3 列步骤图卡片
- 每个步骤有编号
- 每个步骤展示一个真实操作节点

底部：
- 简短总结文案
```

### 4. 通用提示词结构

```markdown

画面下半部分是 2 行 × 3 列的六个步骤图卡片，每个卡片左上角有圆形编号 1-6，分别展示：{步骤 1 画面}、{步骤 2 画面}、{步骤 3 画面}、{步骤 4 画面}、{步骤 5 画面}、{步骤 6 画面}。整体为小红书美食教程海报风格，拼贴式排版，米白色背景，暖色调，步骤卡片边框清晰，少量手写风箭头和短标注，画面干净、清晰、真实、有食欲，竖版 4:5，高清，无水印。
```

### 5. 更稳定的无文字底图提示词

```markdown
生成一张竖版真实摄影拼贴式分步骤食谱海报底图，主题是「{菜品名称}」。不要在图片中生成任何文字、标题、数字、步骤说明、食材名称、伪文字或水印。画面上半部分是一张成品主视觉，展示{成品视觉描述}，真实家常菜摄影风格，食物色泽自然、油润、有食欲，背景温暖干净。画面下半部分是 2 行 × 3 列的六个步骤图卡片，分别展示{步骤画面列表}。保留清晰留白区域用于后期添加中文标题、步骤编号、食材清单和说明文字。整体为小红书美食教程海报风格，拼贴式排版，米白色背景，暖色调，卡片边框清晰，高清，竖版 4:5，无水印。
```

## 十三、竖版双栏食谱信息长图规则

### 1. 视觉类型定义

当用户要求生成“图文菜谱”“食谱长图”“一张图看懂做法”“小红书风格菜谱图”“图文教程海报”“适合保存的菜谱卡片”等内容时，可以使用 **竖版双栏食谱信息长图**。

这种视觉类型不是单纯成品图，也不是简单步骤拼图，而是把完整食谱压缩到一张竖版长图中，兼具：

- 成品吸引力
- 食材说明
- 调料说明
- 步骤教学
- 小贴士

核心结构：

- 左侧：菜品标题 + 口味卖点 + 大幅成品主视觉 + 小贴士
- 右侧：准备食材 + 准备调味品 + 做法步骤 + 步骤小图
- 底部：一句口感总结或场景文案

### 2. 适用场景

适合：

- 图文菜谱
- 食谱长图
- 步骤图
- 菜谱卡片
- 适合保存、分享、打印或发布的内容
- 家常菜、快手菜、下饭菜、甜品、饮品、早餐、便当等

不适合：

- 步骤特别复杂、需要大量文字说明的菜
- 需要精确状态判断的烘焙教学主图
- 需要大量真实步骤图的失败诊断
- 用户明确要求纯文字、不要图片或不要信息图

### 3. 版式结构

推荐比例：

- 竖版 9:16、3:4 或 4:5
- 适合手机阅读和社交平台保存
- 背景以米白、浅奶油色、浅棕色为主

推荐布局：

```markdown
画面左侧：
- 顶部：短口味描述
- 中部：大标题
- 标题下：一句卖点副标题
- 中下部：大幅成品图
- 成品图上或旁边：圆形/贴纸式亮点标签
- 底部：小贴士 Tips 区

画面右侧：
- 顶部：准备食材区
- 中上：准备调味品区
- 中下：做法步骤区
- 每个步骤左侧放编号
- 每个步骤右侧放真实步骤小图或生成步骤图
- 步骤之间用细线分隔

画面底部：
- 一句口感总结或食用场景文案
```

### 4. 通用提示词结构

```markdown
生成一张竖版双栏食谱信息长图，主题是「{菜品名称}」。整体为真实美食摄影 + 小红书食谱卡片风格，米白色背景，暖色调，圆角卡片，棕色系标题和装饰线条，画面清晰、有食欲、适合手机竖屏保存。

画面左侧是主要视觉区：顶部有简短口味描述「{口味描述}」，中间是醒目的中文大标题「{菜品名称}」，标题下方有一句卖点副标题「{卖点文案}」。左侧中下部放一张大幅成品图，展示{成品视觉描述}，食物色泽自然、油润、有热气感，放在浅色陶瓷餐具中，背景为温暖木质桌面。成品图旁边可加入圆形贴纸标签，突出「{亮点标签}」。

左下角加入“小贴士 Tips”卡片，展示 2-3 条关键技巧；底部加入一句简短总结文案「{底部总结文案}」。整体真实摄影质感，食物高光自然，卡片排版干净，信息密度高但不拥挤，竖版 9:16 或 4:5，高清，无水印。
```

## 十四、单页完整食谱信息图（含食材细节版）规则

### 1. 视觉类型定义

当用户要求生成“图文菜谱”“完整食谱长图”“一张图看懂做法”“适合保存的做菜卡片”“带食材和酱汁细节的教程图”时，可以使用 **单页完整食谱信息图（含食材细节版）**。

它和普通“步骤拼图”不同，重点不是只展示流程，而是把以下信息整合在一张图里：

- 成品主视觉
- 菜名标题
- 简要做法步骤
- 食材和调料细节
- 酱汁配比
- 可选配菜或替代食材
- 小贴士
- 步骤配图

它适合做成一张 **高信息密度但结构清晰的竖版菜谱卡**。

### 2. 适用场景

适合：

- 用户想要“一张图看懂完整做法”
- 用户要求图文并茂、适合保存、分享、打印
- 用户希望同时展示成品、食材、调料、酱汁、步骤、小贴士
- 用户希望信息更细，不只是“步骤图”
- 菜品属于家常菜、快手菜、下饭菜、糖醋类、焖烧类、炒菜类、便当菜、简单宴客菜
- 步骤通常在 4-6 步内可以讲清

不太适合：

- 烘焙中需要大量状态判断的复杂教程
- 需要逐秒火候演示的高难度烹饪教学
- 特别复杂、步骤特别长的专业菜谱
- 用户明确要求极简版或纯文字版

推荐比例：

- 竖版 3:4、4:5 或 9:16

## 十六、不同输出形式中的图文处理

### 1. 文档形式（默认）

文档形式应默认图文并茂，每个步骤逐一配图，并加入现代食谱信息图模块。

推荐做法：

- 封面或开头放成品图/现代食谱信息图。
- 食材表后放食材图或食材区插图。
- 每个操作步骤附近放对应步骤图。
- 状态判断处优先放真实参考图。
- 结尾放摆盘图或保存复热提示图。
- 图片说明要写清“这张图展示什么”，并注明真实图/示意图。
- 所有图片均使用可渲染的真实链接，不写假占位。

### 2. HTML 形式

HTML 形式应默认支持图文并茂，每个步骤逐一配图，并加入现代食谱信息图模块。

推荐做法：

- 使用 `<figure>` 和 `<figcaption>` 承载图片和说明。
- 每个步骤卡片内都要有对应图片，不得有无图步骤卡片。
- `src` 使用真实可访问的图片 URL，不写“图片地址”等假占位。
- 使用 `alt` 描述图片内容。
- 现代食谱信息图可作为页面顶部或教程概览模块。
- 不要把所有图片集中堆在页面底部。

示例结构：

```html
<article class="step-card">
  <h3>步骤 2：鸡蛋入锅</h3>
  <p><strong>操作：</strong>将鸡蛋先打入小碗，贴近水面轻轻滑入微沸的水中。</p>
  <p><strong>状态判断：</strong>水面只有小气泡，不要大滚。</p>
  <p><strong>注意事项：</strong>不要从高处倒入，否则蛋白容易散。</p>
  <figure>
    <img src="https://可渲染的真实图片URL.jpg" alt="水波蛋鸡蛋贴近微沸水面滑入锅中的真实步骤图">
    <figcaption>图示：鸡蛋应贴近微沸水面滑入锅中，避免蛋白被水流冲散。（真实图）</figcaption>
  </figure>
</article>
```

## 十七、图片说明与 alt 文本规则

每张图片都应有清晰说明，尤其是文档和 HTML，并应注明是真实图还是生成示意图。

图片说明应包含：

- 对应步骤。
- 展示内容。
- 用户应观察的状态。
- 与操作注意事项的关系。
- 图片性质：真实图 / 示意图。
- 关键状态示意图须附“仅供参考”。

推荐写法：

```markdown
图示：水面只微微冒小泡时，将鸡蛋贴近水面滑入锅中，蛋白不容易被冲散。（真实图）
图示：蛋白打至中性发泡弯钩状态。（示意图，仅供参考，实际以文字描述为准）
```

不推荐写法：

```markdown
图 1：水波蛋。
图片：步骤图。
这里是图片。
```

HTML 中的 `alt` 文本应准确描述图片内容，不要堆关键词。

推荐 alt：

```html
alt="水波蛋鸡蛋贴近微沸水面滑入锅中的真实步骤图"
```

不推荐 alt：

```html
alt="美食 图片 菜谱 水波蛋 好看"
```

## 十八、正确与错误对比图

当用户问失败原因、技巧教学或新手易错问题时，可以使用正确/错误对比图。

适用场景：

- 蛋白打发过度 vs 打发不足。
- 面团发酵不足 vs 发酵过度。
- 水波蛋水太滚 vs 微沸状态。
- 炒糖色过浅 vs 琥珀色 vs 发黑。
- 牛肉炒老 vs 刚熟滑嫩。
- 炸物油温太低 vs 合适油温。
- 酱汁太稀 vs 挂勺状态。
- 奶茶正常混合 vs 油水分离/过腻。

要求：

- 优先检索真实对比图。
- 对比说明要明确写出差异。
- 多轮检索确实无真实图时，方可生成对比示意图，并标注“示意图，仅供参考，实际以文字描述为准”。
- 错误状态生成图尤其容易失真，须谨慎并以文字差异说明为主依据。
- 对比图中文字必须可读、准确、无乱码。

## 十九、图片交付硬性规则

凡是生成菜谱、甜品、饮品、烹饪技能教程、文档或 HTML，最终输出必须包含图片相关交付，且满足六条铁律：

- 每步必配图。
- 默认必须有图片，只有真实图和生成图两档。
- 生成图全文风格统一。
- 关键状态生成图须标示意与免责。
- 图片为可渲染真实链接。
- 图上文字必须无乱码、无错字、无伪文字。

最低要求：

- 每个操作步骤均有对应图片，无遗漏。
- 关键状态判断节点优先用真实图；确实无果时方可用生成图兜底，并标“示意图，仅供参考”。
- 单道菜/单个甜品/单杯饮品：每步配图 + 至少 1 张成品图 + 食材图。
- 烘焙甜品：必须包含关键状态图，例如蛋白打发、面糊状态、发酵状态、烘烤上色等。
- 饮品制作：必须包含原料图、混合/分层状态图、成品图。
- 烹饪技能：必须包含正确/错误状态图或关键动作图。
- 文档/HTML：必须包含现代食谱信息图模块。
- 复杂菜单：每道菜每个操作步骤都有图，关键难点步骤优先真实图。
- 全文多张生成图须风格统一、美观协调。
- 食谱长图和信息图中文字必须自检，不能出现乱码、伪文字、错字、错误英文或字体失控。

如果最终输出中存在无图步骤、关键状态生成图未标注示意与免责、图中文字乱码或错字，或多张生成图风格割裂，视为不合格输出（用户明确要求不要图片时除外）。

## 二十、图片与信息准确性要求

图片必须和教程内容一致。

检查项：

- 图片中的食材是否和教程一致？
- 图片展示的步骤是否对应当前步骤？
- 图片状态是否符合文字描述？
- 图片是否可能误导用户？
- 图片是否只是成品图但被放在过程步骤里？
- 图片是否过度美化，导致用户误判真实状态？
- 如果是生成图，是否明确标注为示意/风格化参考？
- 关键状态兜底图是否加了“仅供参考”？
- 如果是网络图，是否保留来源说明或版权提示？
- 如果是文档/HTML，图片是否放在对应步骤附近、每步都有、链接可渲染？
- 关键状态是否已尽力用真实图，仅在无果时才用生成图？
- 多张生成图风格是否统一协调？
- 图中文字是否无乱码、无伪文字、无错字、无错误英文？
- 图中文字是否和正文食材、步骤、调料、数据一致？
- 信息图是否没有泄漏内部视觉 brief？

## 二十一、输出前图文自检清单

输出前检查：

### 1. 配图完整性

- 是否为每一个操作步骤都配了图片？
- 是否没有无图步骤？
- **每个步骤图是否都是对应该步动作/状态的过程图，没有用成品图凑过程步骤位、没有多个不同动作的步骤共用同一张图、没有无意义雷同图？（配图质量补充硬约束·补充一）**
- 是否有成品图？
- 是否有食材图？
- 是否有关键状态图？
- 文档/HTML 是否加入现代食谱信息图模块？
- 复杂菜谱或菜单是否每道菜都有足够图片？

### 2. 图片来源与用途

- 关键状态判断节点是否已优先尽力检索真实图？
- 无真实图时是否用了统一风格生成图兜底？
- 关键状态生成图是否标注“示意图，仅供参考”？
- 是否避免只检索菜名成品图？
- 是否把步骤拆成“菜品名称 + 操作动作 + 关键状态 + 视觉目标”？
- **所有检索图是否都干净无水印——无平台 logo、网站域名、博主/用户名角标、图库样片水印（不分深浅）？带水印的是否已换图或改用无水印生成图？（配图质量补充硬约束·补充二）**
- 是否为每张图片说明“展示什么”并注明真实图/示意图？
- 是否把图片放在对应步骤附近？

### 3. 生成图风格

- 多张生成图是否风格统一？
- 色调、光影、构图、图标、背景是否一致？
- 是否避免一篇教程里出现多种不协调风格？
- 信息图、步骤图、封面图是否属于同一视觉体系？

### 4. 图中文字质量

- 图中是否有乱码？
- 是否有伪文字？
- 是否有错别字？
- 是否有错误英文或乱拼英文？
- 是否有缺字、漏字、重复字？
- 字体是否统一？
- 字号是否合理？
- 文字是否清晰可读？
- 文字是否遮挡食物？
- 标题、食材、步骤、数据是否和正文一致？
- 图上单位与数值是否真实有效（不得出现 Wal/Val 等伪单位、42:00ng 等乱码数据，热量/时间/份数须与正文一致）？
- 图上是否没有无关水印、平台伪标识或人名串？
- 是否没有把「食材区/步骤区/信息区」等内部 brief 分区名当作可见标题画进图？
- 如果文字无法保证准确，是否改用无文字底图 + 可控文本层？
⚠️ 只要任一项无法保证，必须改用 “无文字视觉底图 + HTML/CSS、SVG 或文档文本层渲染文字”，而不是输出带错字的整图。

### 5. 信息图与食谱长图

- 选择的视觉类型是否合适？
- 拼贴式步骤图是否突出步骤过程？
- 双栏食谱长图是否左侧成品、右侧食材/调味/步骤清晰？
- 单页完整食谱信息图是否包含主食材、基础调料、酱汁区、可选配菜和小贴士？
- 是否避免把内部视觉 brief 直接输出到正文？
- 是否避免信息过密、文字过小、元素拥挤？

### 6. HTML 与文档可用性

- HTML 图片是否有准确 `alt` 文本？
- 图片是否放在对应 `<figure>` 与 `<figcaption>` 中？
- 文档图片是否放在对应步骤附近？
- 图片说明是否帮助用户理解操作状态？
- 图片、文字、步骤、状态判断是否一致？

### 7. 例外情况

- 用户明确要求不要图片时，是否才省略图片？
- 用户要求极简文字版时，是否仍保证步骤清楚可执行？
- 用户要求精简回答时，是否至少保留关键图建议或检索词？
