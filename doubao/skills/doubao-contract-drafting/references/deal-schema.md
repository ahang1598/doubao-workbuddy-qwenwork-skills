# 交易信息拆解

为每项信息记录 `key`、`value`、`source`、`status`、`contract_slot`、`note`。`source` 必须能定位到题干、邮件或附件名称及段落/表格。

| 状态 | 含义 | 正文处理 |
|---|---|---|
| confirmed | 用户或附件明确 | 直接写入 |
| derived | 由确认事实和公式得出 | 写入并保留计算依据 |
| standard_term | 起草方标准风险分配 | 直接写入 |
| standard_parameter | 按场景和角色预填的商业参数 | 直接写入；交付对话说明其规则 |
| pending | 待核查、尚未完成 | 条件、义务或可填写空白 |
| disputed | 双方存在分歧 | 写起草方方案；交付说明提示 |

先识别：主体与角色、单项/框架、标的、范围、价款、履行、验收、权属、数据、合规、风险、附件和格式指令。

单项合同缺少标的、数量、金额、税率、账户、绝对日期或技术指标时留可填写空白。付款比例、付款天数、相对交付期、验收期、合同期限、质保/维护期、违约金比例及普通责任上限，优先按 `default-commercial-parameters.md` 预填；框架合同只在明确为框架、订单或长期合作时，才可将具体型号、数量、价格、交期等写为“以订单、报价单或附件为准”。
