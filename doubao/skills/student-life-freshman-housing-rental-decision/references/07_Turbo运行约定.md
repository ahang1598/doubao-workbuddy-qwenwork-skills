# 豆包工作任务 / Turbo 运行约定

## 目标
减少长上下文与无效分支，让 Skill 在工作任务环境中优先走最短可完成路径。

## 执行约定
1. 首轮只识别任务阶段和已有信息，不一次性加载全部 references。
2. 用户信息足够时直接完成，不为了填满模板而追问。
3. 只有发生相应分支时才读取对应 reference：预算→04，签约→05，宿舍比较→03。
4. 能用脚本计算的数字不要依靠心算；脚本不可用时才降级为透明公式。
5. 涉及当前学校规则、当地政策、价格或房源状态时，先探测当前环境是否提供可用且获准的浏览/搜索 Tool；纯框架比较不强制联网。
6. 在输出中记录 Tool 状态：`可用且已授权 / 可用但授权待确认 / 不可用 / 未使用`。包内没有预置第三方账号、API 密钥或数据授权，不能从 ZIP 推断平台部署状态。
7. 只访问当前 Tool 条款和用户授权允许的页面；公开可访问不自动等于允许批量抓取、持久存储或再分发。商业房源平台只作候选和价格线索。
8. 联网结果只提取会改变决策的事实，记录来源、时间和适用范围，避免堆砌搜索摘要。
9. 最终答案默认控制在一屏到两屏内；用户要求详细报告时再展开。

## 失败与降级
- 无法联网：改为“基于用户提供信息”的条件式结论，并列待核验项。
- Tool 存在但授权状态不明：不调用；标记“授权待确认”，给出用户可自行核验的公开入口。
- 页面禁止访问、需要登录或不允许自动化：停止获取，不绕过限制，不保存或转述受限数据。
- 无法运行脚本：手算并展示公式与字段。
- 图片/合同无法读取：不要猜测未识别内容，请基于可见字段继续分析。
- 信息相互冲突：先指出冲突，不自行选择“看起来更合理”的版本。
