# 房源比较与预算

## 预算口径

- `月度总成本 = 月租 + 物业 + 水电等 + 网络 + 月均通勤 + 其他月度固定费用`
- `首次现金 = 押金 + 首期预付租金 + 中介/服务费 + 搬家 + 必要添置 + 其他一次性费用`
- `有效月成本 = 月度总成本 + 一次性不可退费用 / 计划居住月数`

可退押金不计入有效成本，但计入首次现金占用。字段缺失或不确定时写 `null`；只在用户明确说明无该费用时写 `0`。脚本对不完整数据只输出 `known_*` 已知小计，完整总额为 `null`。

“押金”这个名称本身不足以证明必然可退；预付租金、服务费等也不能仅凭名称断言不可退。仅按用户提供或已核验的书面条件标记可退、不可退、抵扣或预计损失，否则写“退还/抵扣条件待核验”。“押一付三”可用于计算明确到期的押金和三期租金现金占用，但水电、物业等是否当场预缴不明时，只输出“已知小计 + 待确认到期金额”，不输出最低/建议准备数。

若连月租金额都未提供，不得声称首次现金下限等于首期租金，也不得自行引入市场平均或“常见”水电/物业/通勤区间。未获用户确认的假设不进入正式结论。

列缺失字段时只标注其计算归属：水电/物业/网络/通勤进入月度总成本，押金/首期预付/到期的一次性费用进入首次现金占用，已确认不可退的一次性费用才可按计划月数进入有效月成本。不得描述未经来源支持的典型金额、影响幅度、是否通常包含或通常另收。

### 费用不完整

- 只把用户提供的数字相加为“已知小计”；月度总成本、首次现金或有效月成本字段不完整时保持 `null`。
- 两个方案都不完整时不排名或断言谁更便宜，只列可能改变结论的缺失字段。
- 用户提供押付规则时，只计算明确到期的已知现金占用；退款、抵扣和损失性质未有书面条件或核验依据时保持待核验。

### 异常金额

- 负数、非有限数、布尔值、超出脚本范围的月数或其他非法格式必须保留原值并指出字段。
- 用户更正前不运行脚本、不换算、不排名。负数若代表补贴或返现，拆成原始应付额与补贴字段并确认周期和条件。
- 只追问修正异常所需的最少信息，不借异常输入补充价格或政策事实。

## `calc_budget.py` 输入

```json
{
  "currency": "CNY",
  "monthly_rent": 1800,
  "monthly_property": 100,
  "monthly_utilities": 180,
  "monthly_internet": 50,
  "monthly_commute": 120,
  "monthly_other": 0,
  "deposit": 1800,
  "prepaid_rent": 5400,
  "agency_fee": 900,
  "moving_cost": 300,
  "setup_cost": 500,
  "other_one_time_nonrefundable": 0,
  "planned_months": 10,
  "monthly_budget_limit": 2500
}
```

`monthly_rent` 与 `planned_months` 必填。月数必须是 1–120 的整数；金额必须是有限非负数，布尔值不视为数字。脚本不执行汇率换算，所有金额必须已统一币种和计费周期。

## 多方案比较

- 使用同一币种、时间周期、门到门通勤口径与同一组维度。
- 将未知分数写为 `unknown`/`null`，不用默认好评补齐。
- 六个权重维度必须齐全且总和为 100；仅调整权重，不在同一轮中替换维度。
- 方案名称必须唯一。缺失任一维度的方案不进入正式排名；STOP 不进入排名；CHECK 只能作为条件式候选。
