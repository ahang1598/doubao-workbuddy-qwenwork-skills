# 商品图片生图参考：Prompt 与多图生成流程

## Prompt 写法

为每张图写独立完整 prompt，不要只写“参考上图”“保持一致”。

每张图先写设计矩阵行和简报，再写 prompt。简报至少包含：平台/载体、资产类型、商业任务/买家问题、商品露出策略、品类证据层/其他要素、物理结构骨架、场景语义、实例填充、视觉方向、镜头距离/视角、参考资产、图上文字、必须展示的产品元素、商品主体保留项、合规/避免事项。详情页按已确定屏数逐屏独立简报，避免一条 prompt 试图生成整套详情页。

写 prompt 前先确定：

- 商业任务：这张图负责点击识别、解释购买理由，还是解除具体顾虑。
- 画面任务：用什么主体、场景、动作、局部、结构、参数表、卡片或无商品信息画面证明这件事。
- 物理结构骨架：上下分区、左右分栏、Bento 卡片、局部放大圆窗、步骤卡、尺寸线、参数表、平铺清单、中心主视觉或纯文字色块。
- 场景语义：这个骨架里的环境、动作、道具、光影和情绪为什么服务本屏任务。
- 实例填充：每个卡片、图标、文字、局部放大窗、手部动作、尺寸线、参数字段和道具的具体内容。
- 可见文字：所有需要渲染到画面里的字逐字确定；未确认的信息不进图。
- 保留与禁止：商品主体要保留什么，哪些 claim、配件、标志、价格或平台元素不能出现。
- 商品露出策略：强商品、局部商品、内在机制、弱商品还是无商品；无商品屏要说明用什么场景、人物状态、图标、色块或文字结构承担画面任务。
- 品类证据层：本图证明哪个商品要素，例如刀刃锋利、纸张纤维、衣服面料、洗衣液去污流程、接口兼容、食品质地、护肤品质地等；看不见的机理必须写成“示意”，不得写成实拍或检测结论。

### 文生图

按“总览句 + 分区扫描主段落 + 条件收束 + 画幅比例”写：

- 总览句：第一句说明画面类型、平台/载体、构图方向、设计风格和核心任务；第二句可说明背景材质、主体或证据层的一句话概括。
- 分区扫描主段落：占 prompt 主体，按从上到下、从左到右、从前景到背景的物理空间顺序描述。每个空间分区以明确方位词开头，例如“画面顶部”“画面左侧”“中央区域”“右下角”。同一分区内用“从左到右依次为”或“上方/下方”展开。
- 条件收束：说明全局配色、字体气质、光影方向、商品主体清晰度、平台合规、禁止项。
- 画幅比例：单独写比例，如 1:1、3:4、4:5、16:9、1:6；不要把像素尺寸、模型名、seed、文件路径写进 prompt，除非用户明确给定固定画布。

每个可见文字必须用中文引号写出，例如：“轻盈不闷，通勤一整天”。使用强文字模型时，prompt 应要求模型直接生成好看的文字版式，并逐字写准文案；使用弱文字模型时，prompt 应要求生成无字底图并预留排版区域。

生图 prompt 避免直接写“主图”“详情页”“产品详情页”“电商详情页”“详情页首屏”“详情页材质说明”“Banner”“A+页”“车图”等载体词，容易让模型生成网页界面、边框、错误模板或把这些词当成可见标题。内部简报可以保留这些名称；真正传给生图工具时，改写为“正方形商业产品展示图”“竖版产品信息图”“横向品牌产品视觉”“材质细节信息图”等可视化描述。

可见文字清单和 prompt 文案必须分开：

- `屏次名称/模块名` 可以写“首屏、材质说明、详情页 D1”，但不能原样进入图上文案。
- `图上文案` 只写买家能看到的最终文字，例如“轻薄贴合”“材质轻盈说明”“一眼看清核心配置”。
- 如果 prompt 中需要说明图片用途，用“画面任务是解释材质/配置/使用场景”，不要写“画面文字写产品详情页”。
- 每个图上文案字段都要有完整值；缺信息时用“待确认”或移出画面，不能让模型自由补字。

空间分区至少写清：

- 绝对位置：顶部、中央、左侧、右侧、底部、前景、背景、左上角、右下角，禁止只写“旁边”“附近”。
- 元素类型：商品、文字、卡片、图标、尺寸线、步骤编号、局部放大窗、背景道具、分割线、标签。
- 形态细节：元素由什么视觉部件组成，例如半透明信息卡、细线箭头、圆形放大窗、磨砂底座、尺寸标尺。
- 内容描述：图片类写主体、场景和色调；文字类必须用中文引号逐字给出所有可见文案。
- 文字视觉样式：颜色、字体粗细、大小层级、背景色、边框、阴影、圆角、透明度或 3D/描边效果。
- 关联关系：和相邻元素的对齐方式、间距、前后层级、引导线关系。
- 风格特征：材质、配色、处理手法，例如高对比硬光、柔和无影光、金属拉丝、奶油白柔光。
- 光影工艺：主光方向、投影、反光、轮廓光、材质质感。
- 禁止项：不出现哪些未证实 claim、徽章、价格、道具或配件。

量化密度要求：

- 每个独立元素都要描述，不能用“等”“若干”“相关元素”跳过。
- 所有可见文字 100% 用中文引号框定。
- 每个独立元素至少包含一个明确颜色词。
- 每屏至少写清 3 个空间方位关系；复杂图按分区逐段描述。

文字层级要求：

- 主标题必须最大最清晰，支撑说明次之，参数/注释最小。
- 图上文案要下钻为具体证据，不写空泛词，例如把“高品质”改成“细密纤维”“加宽刀背”“三档风速”“低泡易漂洗”等可视化证据。
- 证据必须视觉化：尺寸用尺寸线，流程用步骤卡，材质用微距，包装用清单，兼容性用矩阵或列表。

空间分区描述要具体到实例：

- 每个可见元素都写出位置、形态、颜色、内容、层级和相邻关系。
- 同类卡片也要逐个写差异，例如三张卖点卡分别展示什么图标、文字和细节。
- 不用“等”“若干”“相关说明”省略信息。
- 颜色、材质、字体粗细、阴影、边框、透明度只写有助于生成的关键项，不堆砌无关形容词。

文生图 prompt 示例：

```text
生成一张竖版产品信息图，画面任务是解释商品的轻量结构，风格为干净专业的浅灰白影棚质感。画面顶部居中放置黑色加粗标题“轻量结构，日常携带不累手”，标题下方用浅灰小字写“适合通勤、出差、户外随身使用”。画面中央偏左展示与首张产品展示图一致的商品完整主体，主体边缘带柔和右侧轮廓光，底部有自然浅灰投影。画面右侧从上到下排列三张白色圆角信息卡，分别写“握持更稳”“收纳不占位”“随身携带”，每张卡片左侧配一个不同的细线图标。画面底部用细灰线连接商品局部放大圆窗，圆窗展示材质纹理细节。整体低饱和、留白充足、文字清晰，不出现销量、认证、价格、排名、功效百分比和虚构评价。画幅：3:4。
```

### 图生图

按“编辑目标 + 保留项 + 编辑项 + 空间描述”写成一段：

- 编辑目标：说明基于哪张商品图生成哪类商品主图或详情图。
- 保留项：商品颜色、结构、包装、Logo、文字、比例、透视不变。
- 编辑项：背景、光影、排版、图上文案、局部放大、尺寸线、步骤卡。用户实拍图必须明确“不保留原拍摄背景和周边杂物”，只保留商品主体。
- 空间描述：按画面区域逐步写清目标结果。

如果同时使用灵感参考图和商品图，必须区分角色：灵感图只参考版式、配色和视觉节奏；商品主体严格来自用户商品图。prompt 中要明确“不保留灵感图原有商品、文字、价格、品牌和认证”。

图生图更适合：保留真实商品身份、换背景、提升光影、生成主图、增加详情图版式、做局部放大、做尺寸/步骤/清单说明。不要用图生图去“发明”新 SKU、新包装、新认证或新功能，也不要把用户实拍图里的房间/桌面/杂物当成商品真实使用场景。图生图不是只能换背景；如果设计矩阵指定中景交互、近景微距、平铺清单、接口特写、刀刃微距、纤维纹理、面料走线、泡沫/污渍处理、内部结构或斜角破框，应在 prompt 中明确允许这些镜头和构图变化。若工具持续保留同一输入视角和完整主体占比，应停止继续用同一底图 image_edit，不要靠重复提示词硬拗；改用多角度参考、局部/微观/内在/无商品屏、结构控制或抠图重合成。

如果要生成多张同商品图片，强商品/局部商品图生图 prompt 必须明确“本图是同一商品的不同场景/局部/信息图，不重新设计商品身份，但允许按本图设计矩阵改变镜头距离、视角、裁切、摆放、场景和版式”。弱商品图可以引用商品图但要求商品只作为道具点缀；内在机制屏优先使用结构/剖面/流程参考，不传完整商品参考；无商品图不要引用商品图，prompt 明确“不出现任何具体商品、竞品、包装或 Logo”。后续图优先引用用户原图、已确认主图或参考资产池，而不是引用前一张失败图。

示例结构：

```text
基于用户提供的商品图生成一张竖版核心卖点信息图，保留商品瓶身颜色、包装文字、Logo、瓶盖结构和正面透视不变；不保留原拍摄背景、桌面、墙面和周边杂物，将背景替换为浅米白影棚场景，画面正中央放置商品完整主体，右侧加入局部放大圆形特写展示质地，顶部居中放置黑色加粗标题“清爽质地 日常护理不厚重”，下方用三条浅灰卡片说明“轻薄易推开”“适合早晚护理”“搭配洁面后使用”；整体柔光、低饱和、留白充足，禁止出现认证徽章、销量、功效百分比和虚构评价，禁止出现“产品详情页”“电商详情页”等模板文字。
```

图生图 prompt 必须写清保留项：

- 商品外形、颜色、材质、包装文字、品牌标识、图案、瓶盖/接口/配件结构。
- 商品朝向、透视、主要比例和关键边缘。
- 用户上传图中真实存在的数量和包装内容。
- 如果是用户实拍图：明确保留商品，不保留拍摄背景、环境道具、杂物、桌面纹理和非售卖配件。

图生图禁止：

- 改掉商品真实颜色或包装文字。
- 把一个 SKU 画成多个 SKU。
- 把背景道具画成随箱配件。
- 给商品加不存在的认证章、平台标识或品牌授权标。
- 把用户实拍照片的杂乱背景、房间、桌面、线缆或其他非商品物体延续到商业成品图。
- 把内部模块名生成成图上标题，例如“产品详情页”“电商详情页首屏”“详情页材质说明”。

## 多图生成流程

工具调用口径：

- 在 ActionHub 或目标 App 场景中，图片生成和图片编辑必须按当前暴露的 `image_gen` / `image_edit` 工具 schema 调用；只填写 schema 中真实存在的字段，例如 prompt、参考图/输入图、蒙版、尺寸、数量、输出格式等。
- 文生图任务走 `image_gen`；基于用户商品图换背景、保留主体、局部重绘、修字或延展画面走 `image_edit`。不要把普通图片生成写成 Connector 任务，也不要输出任务 ID、轮询步骤或臆造异步任务字段。
- 工具 schema 与本参考中的 prompt 结构冲突时，以当前工具 schema 为准；把本文的设计矩阵、可见文字清单、主体保留项和禁止项压缩进 schema 允许的 prompt / instruction 字段。
- 若当前环境没有 `image_gen` / `image_edit`，或 schema 不支持必要参考图、蒙版、文字修复、尺寸或批量输出，明确降级为 brief / prompt / 拍摄建议，不把未执行的图片生成说成已完成。

生成商品主图和多张详情图时，按以下顺序处理：

1. 先确定主参考图：用户真实商品图优先；没有真实商品图时，先生成或选定一张概念主参考图，并标为待用户确认。
2. 再定商品主体保留项：颜色、结构、包装、Logo、文字、比例、透视、真实配件、SKU 数量和关键识别细节。
3. 再定整套视觉锚点：主色、字体风格、光影方向、背景材质、商品摆放规则。
4. 先生成商品主图底图，再按已确定屏数生成详情图底图；后续强商品/局部商品图必须继承主图中的商品身份，微观材质/内在机制/弱商品/无商品图只继承视觉语言、商品事实和文案口径。所有 D 屏开始生成前必须确认完整商品强露出上限、局部/微观/内在/弱商品/无商品屏位置，并按屏数选择足够的品类证据层和其他要素图。只有没有生图工具或被安全策略/工具错误阻断时，才改为规划 brief。
5. 为每张图单独写 brief 和 prompt，一次只承担一个画面任务；每张 brief 必须写清商品露出策略、镜头距离/视角、版式骨架、场景动作、文字策略和参考资产选择，避免一组图全部正视平拍、全部强露商品或全部同一种信息卡。如果用户要求单张长图，把已确定屏数合并为一个纵向长画布 brief。
6. 强商品/局部商品图引用同一主参考图、多角度参考或局部参考，并继承同一商品主体保留项；微观材质屏可用材质、纤维、走线、刃口、泡沫、质地等局部参考或示意；内在机制屏可用结构示意、剖面、流程图、材质层次或图标，不强制露出完整商品；弱商品图可引用主参考图但要求商品只作点缀；无商品图不引用主参考图，避免模型强行生成商品。用户实拍图只用于商品身份，不继承原拍摄环境。
7. 前一张图生成后，记录已成立的商品识别、主色、字体、光影和背景材质，后一张图继承这些锚点，但必须更换至少两个视觉维度：镜头距离、视角、参考资产/生成路线、交互动作、场景、信息结构、商品露出策略或版式骨架。若上一张是完整商品强露出，后一张优先转为局部、内在机制、弱商品或无商品。
8. 每张底图生成后，先检查设计矩阵和商品露出策略是否执行，再检查主体一致性；通过后再用真实字体合成最终图上文案，导出带文字成品图。
9. 国内详情页逐屏生成并叠字后，可以按用户要求拼成长图预览；Amazon 副图和 A+ 模块应按独立素材交付，不把长图预览当成后台上传稿。
10. 如果某一张图失败，只修该图 prompt，不推翻整套方向；已成功的图片仍要完成主体检查、叠字并交付。

单屏失败时按问题类型修 prompt：

- 设计矩阵未执行：如果生成图没有体现该屏商业任务、品类证据层、物理结构骨架或场景语义，视为废稿，静默丢弃，不写入成品展示区。
- 主体变形或多图主体不一致：加强同一商品主体保留项，优先引用用户原图或主图，减少风格改造，强调颜色、结构、包装文字、透视不变。
- 主体连续不一致：停止继续批量生成，回到主参考图；改用图生图/参考图适配/局部重绘/商品抠图合成路线，或要求用户补充真实商品多角度图。
- 完整主体重复：如果连续多屏都是同一个完整商品主体，只换文字、背景、色块、标签或光影，停止继续生成；回到资产类型规划，把其中部分屏改为局部商品、内在机制、弱商品或无商品，并更换参考资产、镜头距离、视角、场景动作和版式骨架后重生。
- 品类要素缺失：如果整套详情图缺少该品类能证明卖点的其他要素图，不能标为完整详情图；先按本次屏数补足关键证据层，再生成或交付。例如主机缺接口/散热/内部结构，菜刀缺刃口/切割/握柄，纸巾缺纤维/层数/吸水，衣服缺面料/走线/版型，洗衣液缺用量/泡沫/污渍处理/机理示意。
- 图文不强绑定：如果文案说材质但画面没有材质微距，说步骤但没有动作，说参数但没有尺寸线/参数卡，说包装但没有清单，视为废稿，重写骨架和实例填充后重生。
- 文字乱码：优先擦除或覆盖乱码区域，用真实字体文字层重排；下一轮生图改为无文字底图并预留文字区。只有短字样场景才尝试缩短文案、减少文字层级、增大字号和对比度后重生。
- 文字漏项或空值：回到可见文字清单，删除缺值标签或标“待确认”，不要让模型自由补全；如果规格/推荐范围缺失，把该信息移到待补资料。
- 载体词入画：把 prompt 中的“详情页、产品详情页、主图、Banner、A+页”等用途词改成可视化描述，并重生或局部修字。
- 参数小字乱码：减少字段、拆成多屏或转真实字体兜底；完整参数写入飞书正文表格。
- 文字正确但排版丑：不要继续用脚本整体重排；优先让强文字模型重新生成带字版式，或用上一版好看版式做参考只替换错字。
- 信息拥挤：删掉次级卖点，拆成下一屏，保留一个主标题和一组证据。
- 图文不符：重写画面任务，让动作、局部、参数或场景直接对应文案；未修复前不得交付为成品图。
- 平台不符：优先按平台规则改背景、文字密度、促销表达和画幅。
