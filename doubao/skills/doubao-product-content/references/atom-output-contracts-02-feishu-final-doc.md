# 原子输出契约：飞书文档成稿模式

## 飞书文档成稿模式

用于标题、详情页文案、商品图片三类同时交付，或用户未限定能力时的飞书交付容器。最终交付优先是真实飞书文档；只有无法创建/更新飞书文档时，才输出可复制到飞书的正文。飞书触发不等于自动补齐所有原子能力，正文内容按用户明确需求、商品复杂度和语义强相关模块组织。

飞书文档工具流程：

1. 只要命中飞书文档成稿模式，就先检查真实飞书文档工具，而不是先判断用户是否点名飞书：
   - 用户提供飞书/Lark 文档 URL 或 token：写入现有文档。
   - 用户明确要求“写到飞书/创建飞书文档/生成飞书文档”：创建或写入飞书文档。
   - 用户未明确限定能力但命中飞书文档成稿模式：若目标 App 暴露 `lark-doc/lark_cli_exec`，默认创建新飞书文档。
   - 用户同时要求标题、详情页文案、商品图片三类但未提飞书：若目标 App 暴露 `lark-doc/lark_cli_exec`，默认创建新飞书文档。
2. 在 ActionHub 或目标 App 场景中，所有飞书命令都通过 `lark-doc/lark_cli_exec` 统一入口执行；不要在技能正文里要求直接调用本地 `lark-cli` 子命令。
   - 先通过 `lark-doc/lark_cli_exec` 读取 lark-doc 工具说明、创建/更新文档说明、XML/样式说明和当前可用参数。
   - 若该入口返回不支持某个帮助读取命令，改用同一入口查询 `docs --help`、`docs +create --help`、`docs +update --help`，不要拼接不存在的子命令。
3. 创建新文档时，通过 `lark-doc/lark_cli_exec` 执行等价的 `docs +create --as user --title "{商品名/类目}商品内容交付稿" --content @payload.xml`。
4. 更新已有文档时，通过 `lark-doc/lark_cli_exec` 执行等价的 `docs +update --as user --doc "{URL或token}" --command append --content @payload.xml`。
   - 若用户要求替换全文，可用 `--command overwrite`，但应先确认或明确这是覆盖操作。
5. 只有以下情况可以降级为聊天正文：
   - 目标 App 没有暴露 `lark-doc/lark_cli_exec` 或飞书文档工具。
   - 未登录、无权限、命令失败且无法自行修复。
   - 用户明确要求“不要创建飞书文档，只给正文”。
   - 当前宿主不允许调用外部工具。
   - 不能因为“任务简单”“用户未明确要求飞书文档”“聊天回复足够承载”“当前在 MainAgent 环境”“发现了飞书相关技能但还没调工具”而降级。
6. 降级时必须在最终回复开头用一句话说明原因，例如“当前无法调用飞书文档工具，因此先提供可复制到飞书的正文。”
7. 成功创建或更新文档后，最终回复必须包含“核心内容速览”、图片预览、使用提示和文档链接；图片预览必须直接嵌入聊天回复，不要只给图片路径、文件名或“见飞书文档”；不要把完整飞书正文重复粘贴到聊天里。
8. 飞书嵌图必须做显示安全处理。文档内任何图片显示都禁止直接使用网络图片 URL，包括表格单元格、表格外图片块、XML 和 Markdown 图片语法；禁止写法包括 `<img href="图片URL">`、`<img src="https://...">`、`![图片](https://...)`。网络图必须先下载成本地文件，导出裁掉多余白边/透明边、扁平化 RGB、保持正确比例的显示安全图，再上传/转换为飞书图片 token 或可用的本地上传资源后插入。正文图片块、图文区域、分栏图片区建议使用 480-720px 宽的正文图，表格核对清单才使用 140-220px 宽的缩略图。网络原图 URL 只能作为普通文本链接写在“来源/原图链接”列，不能作为图片源。不要把带巨大透明画布、长白边、未压缩原图或异常长宽比的图片直接塞进表格单元格。可用 `scripts/prepare_feishu_image.py --preset body --output-dir {body_dir} --trim-white {images...}` 导出正文图，或用 `--preset table` 导出表格缩略图。

执行顺序：

- 先完成用户明确要求或语义强相关的标题、详情页文案、商品图片和合规待补资料；拍摄脚本只在包含图片/拍图需求或用户要求拍摄建议时加入。
- 有真实生图能力时，先生成带最终文字的主图和详情图成品，并完成主体一致性和文字校验；只有成品图合格后再写入飞书。
- 写入飞书前先为主体参考图、主图、详情图各导出显示安全版本；如果图片来源是网络 URL，先下载为本地文件，再导出本地显示安全图并上传/转换成图片 token 或本地上传资源；禁止在飞书正文任何位置直接用网络 URL 作为图片源。如果本地成品图本身正常但飞书显示出很长白底，必须重新裁切、扁平化、导出正文图或表格缩略图，或改为本地上传后的正文图片块。
- 写入飞书前建立“图片交付清单”，列出主体参考图、全部主图、全部详情图的编号、资产类型、本地显示安全图路径、飞书图片 token/本地上传资源、原图来源链接、是否已上传/转换、正文位置；飞书正文必须按清单全量插入，不能只挑代表性图片。清单中的 `原图来源链接` 只能作为文本来源，不得用于 `<img>` 或 Markdown 图片语法。
- 再把正文组织成飞书文档 payload。
- 然后调用飞书文档工具创建或更新文档。
- 创建或更新后做飞书显示检查：正文图片块、图文卡片或表格单元格不应显示大面积长白底，不应出现异常行高；异常时必须替换图片显示版本后再交付。同步核对商品图片章节中的主图和详情图数量是否等于图片交付清单中的已生成主图和详情图数量；缺图时必须补插图文卡片、正文图片块、分栏图片或必要表格单元格，不能用“已插入代表图”解释为完成。
- 交付前扫描飞书 payload：不得出现 `<img href="http`、`<img href="https`、`<img src="http`、`<img src="https` 或 Markdown 图片网络源 `](http`、`](https`。命中任一项时必须改为本地下载、显示安全处理、上传/转换后再嵌入；不能继续创建或交付该文档。
- 最后按“外部回复核心内容速览”向用户报告结果，并直接嵌入主图和详情图预览。不要在调用飞书工具前先把完整正文发到聊天里。

排版原则：

- 飞书正文优先做成阅读舒服、层次清楚的成稿，而不是全表格堆叠，也不是强制图文卡片一种形态。表格、分栏/多列、高亮块、引用块、Markdown 无序列表、Markdown 有序列表、短段落、图片块和图文块都可以用；按信息类型选择最清晰的组件。
- 适合用表格：基础信息、标题备选、参数、包装清单、价格/规格待确认、执行矩阵、图片交付核对、合规待补资料等需要对齐比较或核对的内容。
- 适合用高亮块/引用块：主推结论、核心购买理由、关键风险、公开信息待确认、交付降级说明、用户最需要先看到的提醒。
- 适合用分栏/卡片：核心卖点、主图方案对比、详情图分组、不同人群/场景版本、可选素材组合。
- 适合用 Markdown 有序列表：执行步骤、拍摄步骤、使用步骤、详情图叙事顺序、后续修改清单。
- 适合用 Markdown 无序列表：注意事项、禁用表达、素材需求、可替换词、风险点、补充建议。
- 不要为了“结构化”把所有正文都塞进表格；也不要为了“美观”把需要对齐核对的数据写成松散段落。
- 若本次包含商品图片，主体参考图必须在商品图片章节靠前单独展示。用户提供商品图、已确认主图、概念主参考图或公开信息参考图，都要插入正文图片块或图文卡片，并写清 `参考图编号、主体保留项、可变化项、使用范围`；不能只在文字里写“同 M1 主参考图”。
- 若本次包含商品图片，商品图片成品必须逐张展示且图片和解释文字相邻。每张主图/详情图至少包含：成品图、编号/名称、资产类型、图上文案、本图解决的买家问题、使用建议或修改提示。具体形态可用图文块、分栏、图片块 + Markdown 列表、短段落 + 高亮块、或必要表格；不能把所有图片堆到文档末尾让用户自己对照。
- 详情图推荐按 `D1-D5`、`D6-D10`、`D11-D15` 分组，每组先放一句叙事目的，再逐图展示。工具支持分栏时可左图右文；不支持时，用图片块后接短段落、无序列表或高亮块替代。
- 可另附 `图片交付核对表`，只记录编号、资产类型、正文位置、图上文案、主体一致性和是否已插入，用于核对完整性；不能用核对表替代正文图文展示。
- 每个表格控制在 4-8 列；字段太多时拆成多个表格，不做一张超宽表。长文案、长 prompt、风险说明不要硬塞进表格单元格；表格里写编号或摘要，下方用独立段落/代码块承接。
- 正文图片块、图文区域、分栏图片区使用显示安全正文图，不放过小缩略图；表格核对清单只放缩略图或不放图。正文图建议宽 480-720px，表格缩略图建议宽 140-220px，均保持比例。
- 飞书文档内禁止使用网络 URL 直插图片，禁止 `<img href="https://...">`、`<img src="https://...">` 和 `![图片](https://...)`；只有工具不支持单元格/正文嵌图、图片无法上传/转换，或当前降级为聊天正文时，才用本地文件路径或普通文本图片链接兜底；兜底链接不能标为“已嵌图”。
- 如果飞书图片块或单元格出现“图片上方/下方很长白底、行高被撑大、图片内容只占一小段”，该文档未通过交付检查。优先重新导出显示安全图；仍异常时，调整为正文图片块并降低宽度，保留旁边文字说明。
- 若本次包含详情图，必须先做资产类型分配、商品露出策略和品类证据层/其他要素规划，再生成并写入文档。整套详情图根据商品属性自由组合 `整体图/全貌图`、`细节图/材质特写`、`微观纹理图`、`内在结构图/功能机制图/剖面/爆炸图`、`场景图/使用场景`、`交互图/步骤图`、`规格参数图`、`包装清单图`、`对比/选择图`、`信任说明图`、`无商品信息图` 等类型；不要连续多屏同角度、同构图、同完整主体露出、同信息密度。任何品类的整套详情图都不能只放同一个完整商品主体；必须穿插该品类能证明卖点的要素图，例如主机的接口/散热/内部结构，菜刀的刃口/钢材纹理/切割动作，纸巾的层数/纤维/吸水，衣服的面料/走线/版型，洗衣液的用量/泡沫/污渍处理/机理示意。


规则：

- 标题、详情页文案和详情图必须使用一致的核心 claim。
- 商品图片必须先锁定主参考图；主图和详情图不得各自独立文生图重新生成不同商品。
- 若本次包含商品图片，主体参考图必须插入飞书文档。即使详情图执行信息里写了“同 REF-1”，文档里也必须有可视化的 REF-1 图片，便于用户检查后续成品是否同一商品。
- 若本次包含商品图片，商品图片文字必须好看且正确；强文字模型优先用模型原生排版，不默认脚本重排。不能只把标题、卖点、价格用普通文字散放到图上。
- 图上文案列必须写最终可见文字，逐字对应图片，不写内部模块名、文件名或生成说明。禁止把“电商详情页”“产品详情页”“详情页首屏”“详情页材质说明”“Banner”“A+页”“主图”“车图”等载体词渲染到图片中，除非这些词是商品名或用户明确提供的真实文字。
- 任何图上文案都不能有空值标签：`推荐腰围`、`臀围`、`尺寸`、`容量`、`配置`、`材质`、`价格`、`适配型号` 等字段没有值时，必须从图片里删除该项，或用“待确认”显示并列入待补资料；不得出现标签后面空白。
- 若本次包含商品图片，飞书里的商品图片必须先展示“成品图”，再写执行信息和 prompt。用户看文档时应先看到图片结果和本图作用，而不是先看到设计 brief。
- 若本次包含商品图片，`主体参考图/主体锁定`、`商品主图成品展示` 和 `详情图成品展示` 按可读性选择图文块、分栏、短段落、Markdown 列表、高亮块或必要表格。每张图至少写清编号、名称、资产类型/用途、图上文案、本图作用和使用/修改提示。可附图片交付核对表，但不强制把成品图放进表格。
- 若本次包含详情图，`详情图设计矩阵与叙事顺序`、`三层推演与实例填充`、`详情图执行信息` 是生成前必须完成的三张表。不要只写资产类型；每屏必须写清商业任务/买家问题、品类证据层、商品露出策略、物理结构骨架、场景语义和实例填充。
- 详情图成品的 `资产类型`、`商品露出策略` 和 `品类证据层/其他要素` 不得全部相同。10-11 屏至少覆盖 5 种资产类型，并至少安排 3 屏局部商品、内在机制、弱商品或无商品屏；12-15 屏至少覆盖 6 种资产类型，并至少安排 4 屏局部商品、内在机制、弱商品或无商品屏。可选类型包括整体图、细节图、微观纹理图、场景图、交互图、步骤图、规格参数图、包装清单图、对比选择图、信任说明图、痛点氛围图、品牌理念图、纯文字过渡图、内在结构图、功能机制图、剖面/爆炸图、无商品信息图。
- 资产类型必须匹配画面：写“细节图/微观纹理图”就要有局部放大、微距、材质/接口/纹理/纤维/走线/刀刃/泡沫等可见细节；写“内在结构图/功能机制图”就要有剖面、爆炸结构、流程箭头、结构层级、机制图标、参数关系或示意图，不要求完整商品主体；写“场景图”就要有真实使用环境和动作；写“规格参数图”就要有参数表、尺寸线或配置卡；写“包装清单图”就要平铺实际包含物和数量；写“无商品信息图”要用场景、图标、色块、文字结构或痛点状态承接商品叙事，不能出现其他商品或竞品。
- 所有品类必须有其他要素图：10-11 屏至少覆盖 4 类非完整主体重复要素，12-15 屏至少覆盖 5 类。示例：主机/3C 是接口、散热、内部结构、配置卡、连接场景；菜刀是刃口、钢材纹理、握柄、切割动作、清洗收纳；纸巾是层数、纤维、压花、抽取、吸水/湿韧；衣服是面料微观、走线、领口袖口、版型、上身动作、洗护；洗衣液是用量、泡沫、污渍处理、衣物纤维清洁过程、机理示意。若 D 屏连续出现同一个完整商品主体，只换文案、背景、色块、标签或光影，不能标为完整交付。
- 每屏只做一件事：一屏只能回答一个买家问题或推进一个转化动作。不得把参数、品牌故事、售后、场景、多个卖点揉在同一屏；信息太多时拆屏。
- 飞书正文默认承载本次命中的商品内容模块；用户明确要求完整商品页或同时覆盖标题、详情页文案、商品图片时，包含标题、详情页文案、商品主图和商品详情图。拍摄脚本只在用户包含图片/拍图需求或明确要求拍摄建议时加入。
- 商品详情图数量按商品复杂度、平台位置和用户预算确定：轻量/短版 3-5 屏，标准商品页 6-9 屏，高复杂度、多 SKU、强参数/强信任类目或用户明确要求完整长详情时 10-15 屏。用户明确要求单张长图时，按已确定的 N 个纵向板块组织，只交付单张长图方案。少于已承诺屏数时必须标为短版、降级或未完成，并说明原因。
- 淘宝、京东、拼多多图片交付中，主图/卖点图/转化规格屏需要价格标签或促销贴片时，只能使用用户提供、授权商品页、品牌/店铺后台截图，或用户明确确认后的价格。未获用户确认前，图上价格贴片改为非数字表达；公开网页检索到的价格只能放入正文“待确认价格参考”，不得进入可直接上架的图上文字。
- 不要把“需求判断”“执行计划”“方法论说明”写进飞书正文。
- 缺失信息只放在“缺失信息/需补证据”和“合规与待补资料”，不要打断正文。
- 用户给了可检索商品线索但信息不全时，先联网搜索公开商品信息补全规格、尺码、材质、容量、包装清单等，并在“公开信息补全（需确认）”和“需用户确认的公开信息”中标明。
- 如果商品信息没有给全但仍能生成，先给可用版本，并在“合规与待补资料”里列出建议补充的信息。
- 如果生成了真实图片，必须在“商品图片”部分展示已经完成文字合成的主体参考图、主图和详情图成品并标注用途；只生成无字底图或只写“后期叠字”不算生成成功。如果无法生成真实图片，交付商品主图和详情图的详细 brief，并明确降级原因。
- 如果创建飞书文档，主体参考图、全部主图和全部详情图成品必须插入文档正文中的图文卡片、分栏区域、正文图片块或必要表格单元格；只在聊天里展示图片但飞书里没有图片，或飞书里只插入部分代表图，不算完整飞书交付。
- 如果飞书 payload 或正文中把网络 URL 写进图片标签或 Markdown 图片源，视为未通过交付检查；必须改成本地下载、缩略图处理、上传/转换后嵌入。网络 URL 只能作为普通文本来源链接。
- 如果最终回复写“共 X 张：M 张主图 + N 屏详情图”，飞书文档中商品主图成品展示至少有 M 张主图、详情图成品展示至少有 N 屏详情图，且图片交付核对表数量一致；任何少于该数量的情况都必须先补齐或明确标注哪些图片生成失败/未交付，不能说“只挑代表图预览”。
- 最终回复和飞书文档里的详情图数量必须与本次承诺一致；不要把所有完整商品页固定成 10-15 屏。如果实际 N 少于已承诺数量，必须明确写成“降级交付/短版/未完成”，说明用户要求或失败原因，并列出剩余屏次计划。
- 如果飞书文档里的图片显示异常，即使本地图片文件正常，也不能视为完整交付；必须替换为显示安全正文图、显示安全缩略图或改用正文图片块。
- 如果多张图片主体不一致，不能把它们标为成品；必须基于同一主参考图重生、局部修复或降级说明具体原因。
- 如果多张图片构图重复，不能标为完整详情图方案；必须重排资产类型、商品露出策略、品类证据层和视角，补足全貌、局部、微观材质、内在结构、功能机制、场景、交互、规格、包装、痛点氛围或无商品信息屏等差异。任何品类都不能只让同一个主体角度反复出现。
- 如果文字没有形成电商版式层级、对齐、容器或价格/标签组，不能把图片标为成品；优先让强文字模型重生好看带字版式，或保留好看版式只局部修错字。
- 如果文字很小、参数很多或 OCR 无法稳定读出，不能把模型原生小字当成成品。把图片改为大字信息卡/分屏详情图，或生成无字底图后用真实字体渲染；完整参数清单放在飞书正文表格，不强塞到图里。
- 飞书正文要完整、清晰、可复制，不要用“你可以”“建议你再”等聊天口吻。
- 飞书正文要有阅读层次：正文信息可以用表格、分栏、高亮块、引用块、Markdown 无序列表、Markdown 有序列表、短段落、代码块和图片块混排，选择标准是美观、可读、易扫读、便于核对。
- 通过 `lark-doc/lark_cli_exec` 生成真实飞书文档时，payload 应优先生成符合阅读顺序的飞书正文块：标题、段落、高亮/引用块、分栏/多列块、图片块、Markdown 列表和必要表格混排。若当前 XML 能力不支持分栏或高亮块，降级为“标题/段落 + Markdown 列表 + 图片块 + 必要表格”的组合，不要退回全表格堆叠。
