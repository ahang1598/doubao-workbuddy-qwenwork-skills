# 商品图片生图参考：版式与图中文字

## 版式与视觉

- 单屏只讲一件事，标题、画面和支撑说明围绕同一个信息点。
- 多屏之间形成节奏变化：首屏主视觉、卖点拆解、细节特写、步骤图、参数表、信任说明不要全部用同一版式。
- 套装商品先总后分：首屏可展示全套，后续拆重点单品、数量、使用顺序和搭配关系。
- 多图视角要变化：全貌、中景交互、近景特写、场景使用、平铺清单、参数表交替使用。只换背景、不换角度和信息结构，不算多样化。
- 多图商品露出也要变化：完整商品、局部商品、微观材质、内在结构、弱商品、无商品信息屏要按任务穿插。主体一致性只锁定身份，不等于每屏都要出现完整商品；无商品信息屏只要服务商品叙事、文字正确、没有竞品或虚构商品，也可以算成品图。
- 不同品类都不能连续使用“居中完整主体 + 大标题/标签”。主机要穿插接口/散热/内部；菜刀要穿插刃口/钢材纹理/切割；纸巾要穿插纤维/层数/吸水；衣服要穿插面料/走线/版型；洗衣液要穿插泡沫/污渍处理/机理示意。只换背景、不换证据层，不算多样化。
- 风格参考图只作版式、配色、视觉组织锚点，不替代商品主体，不复刻参考图里的商品、文案、品牌、价格、认证或 UI。
- 版式不要只写“高级排版”。要明确骨架：上下分区、左右分栏、中心主视觉、Bento 信息卡、局部放大圆窗、步骤卡、参数表、尺寸线、包装清单平铺等。
- 文字层级要拉开：主标题最大，支撑说明次之，参数/注释最小；避免所有文字同等大小。
- 证据要视觉化：尺寸用尺寸线，流程用步骤卡，材质用微距，包装用清单，兼容性用矩阵或列表。
- 商品要融入光影：背景、投影、反光和轮廓光要与商品方向一致，避免生硬抠图感。
- 抽象风格词必须转成具体视觉语言：
  - 高级：克制配色、留白、柔和轮廓光、极简无衬线字体。
  - 生活方式：自然光、真实场景、手持/使用动作、低促销感。
  - 科技感：冷色、硬光、局部发光、金属/玻璃材质、清晰参数卡。
  - 母婴：柔光、低饱和、圆润形态、干净安全感。
  - 强转化：高对比主标题、明确利益标签、商品占比更高，但不使用虚构价格和夸大承诺。
  - 清爽种草：自然环境、低饱和配色、真实使用动作、少量手写/杂志感元素，但仍要保留商品识别。

图像内容要从“骨架 -> 场景 -> 实例”推演：

1. 先定骨架：这一屏是首屏、卖点拆解、材质细节、步骤、参数、包装清单还是信任说明；选择上下分区、左右分栏、中心主视觉、Bento 卡片、局部放大、尺寸线、表格等骨架。
2. 再定场景：背景是否是影棚、生活场景、工作台、浴室、厨房、户外、书桌、衣柜；场景物件必须和商品使用逻辑相关。
3. 最后填实例：每个卡片、图标、文字、局部放大窗、手部动作、尺寸线和道具都要写清具体内容，不能用“相关元素”“若干说明”概括。

人物或手部入镜时，写清动作和商品关系：拿起、按压、打开、穿戴、涂抹、连接、清洁、收纳、对比、测量。服饰鞋品可写模特姿态、上身/上脚角度和搭配色系；美妆个护优先手部、质地、取用动作，谨慎使用人脸前后对比。

平台差异：

- 淘宝/天猫详情页：可以中高信息密度，但每屏仍只讲一个核心信息。适合首屏理由、卖点拆解、痛点场景、细节材质、使用步骤、参数规格、信任售后。
- 抖音电商详情图：像短促静态说明，每屏一个短利益点，配动作、场景或结果；少小字，少说明书式参数堆叠。
- 小红书详情/种草图：真实体验、选择理由、质地细节和搭配建议优先；弱促销，保留生活感和使用痕迹。
- 拼多多详情图：规格、数量、尺寸、材质、用法、实拍和对比要清楚直接；主图/卖点图/转化规格屏配置价格标签或促销贴片时，价格只能来自用户提供、授权商品页、品牌/店铺后台截图或用户明确确认后的数值，避免误导价格和数量。
- 京东详情图：参数、型号、安装步骤、质检/认证、包装清单、售后说明更重要；主图/卖点图/转化规格屏配置克制的价格标签或促销贴片时，价格只能来自用户提供、授权商品页、品牌/店铺后台截图或用户明确确认后的数值，视觉上专业可靠。
- 得物详情图：标签、走线、材质、鞋底、五金、成色、搭配和真实质感优先；营销文字要少。
- TikTok Shop / Shopee / Lazada：小屏可读，本地化短句，清楚展示变体、套装、尺寸、包装和使用动作；图片数量和变体图按后台提示执行。
- Amazon 信息型副图：偏客观说明，适合尺寸、包装清单、使用场景、功能机制和适配范围。不要写价格、折扣、购买按钮或夸张促销语。
- Amazon A+ / PDP 模块：偏品牌化和克制排版，文字可作为模块文案，不一定全部烘焙进图里，避免小字不可读。
- 独立站 PDP：可以兼顾品牌感和转化，首屏更重调性，中段用图解和 FAQ 解除疑虑。

信息密度：

- 首屏：1 个主标题 + 1 个支撑句或短标签。
- 卖点/细节屏：1 个主标题 + 2-4 个短支撑点。
- 参数/规格屏：表格或卡片可以信息更密，但必须分组。
- A+ 模块：图片克制，长文案可放在模块文字区域，不强制全部进图。
- 小屏跨境副图：短句、本地语言、强分组，避免低对比小字。
- 白底主图：按平台规则需要无文字时，不为了表达卖点加字。

文字排版：

- 标题要下钻到具体购买理由，不只写“高端好物”“品质之选”。
- 支撑信息要和画面证据对应，例如尺寸配尺寸线，材质配微距，步骤配动作，包装配清单平铺。
- 字号层级要明显：主标题最大，卖点标签中等，参数/注释最小；避免所有字一样大。
- 每条图上文案尽量短句化。需要较长解释时，把长文案放到详情页正文或 A+ 模块文字区，不强制烘焙进图片。
- 图标要描述视觉形态，例如“细线盾牌配对勾图标”，不要只写“保障图标”。

## 文字版式层设计

用于把最终文案做成商品图的一部分。目标不是“把文字放上去”，而是让文字像电商设计稿的一部分：有层级、有对齐、有留白、有安全区、有与商品主体的关系。优先让强文字生图模型完成这部分设计；脚本只负责兜底修复或确定性替换。

## 图中文字生成路线选择

先判断当前可用生图工具的文字能力：

- 强文字模型：例如用户明确使用豆包/Seedream、Qwen-Image、Ideogram，或当前工具在中文/英文海报字上表现稳定。默认走“原生文字排版生成 -> OCR/人工校验 -> 局部修字”。
- 普通/弱文字模型：例如 Stable Diffusion 常规模型、文字容易乱码的文生图模型。默认走“无字底图 -> 参考原生版式或设计 brief -> 真实字体后期合成”。
- 混合流程：先让强文字模型生成一版好看的带字稿作为版式参考；若文字有错，优先局部修错字。只有局部修字会破坏效果时，才基于原稿版式重建少量文字层。

强文字模型流程：

1. 把图上文字控制在短句：主标题、副标题、2-4 个标签、价格组；不要让模型生成长段落。
2. prompt 中明确要求“电商主图排版、字体层级清晰、价格组/标签组/信息卡完整、文字正确无错字”，并逐字给出每一段文案。
3. 让模型同时生成画面和文字版式，保留它的字体、字重、装饰、位置和整体审美。
4. 生成后逐字校验；如果只有个别错字，优先用局部重绘/编辑替换错字，并要求保持原字体、字号、颜色、位置、装饰和排版不变。
5. 局部修复后再次 OCR/人工校验；仍不对时，才转入真实字体兜底。

真实字体兜底流程：

1. 使用模型成稿或参考图提取版式：文字位置、字号比例、颜色、卡片、标签、价格组、阴影、装饰线和留白。
2. 擦除错误文字或生成无字底图，但尽量保留背景、商品、卡片、标签和装饰元素。
3. 用真实字体按原版式重建文字，不要凭空设计一套低质脚本排版。
4. 导出后检查：新文字是否融入原图，是否像设计元素，是否没有错字。

需要后期叠字时，必须先做文字版式层规格：

1. 先划分文字安全区：标题区、卖点区、价格区、标签区、注释区；避开商品主体、Logo、包装关键文字、口红膏体、瓶身、尺寸线和局部放大窗。
2. 再确定视觉层级：主标题最大且最醒目；副标题比主标题小 35%-55%；卖点标签中等；价格可以独立放大；注释最小且低对比。
3. 再确定排版骨架：居中标题、左上标题组、左下价格组、右侧卖点卡、底部横条、半透明信息卡、胶囊标签、细线分隔、局部标注线等。
4. 最后合成文字和图形层：必要时加入半透明白底卡片、浅色遮罩、圆角胶囊、细线、价格组合、图标占位或局部标注线，保证文字读得清且像设计元素。

常用文字组件：

- 主标题组：1 行主标题 + 1 行副标题；主标题字重更高，副标题灰度降低，间距紧凑。
- 价格组：币种符号小、数字大、后缀小；价格区域必须独立成组，不要和卖点散在画面各处。
- 卖点胶囊：2-4 个短标签，放在同一行或同一列，使用圆角浅底或细描边。
- 信息卡片：适合参数、成分、包装清单；用白色/浅色半透明底，文字左对齐。
- 局部标注：细线连接商品细节和短文案；线条不能穿过主体关键区域。
- 底部条：适合促销、规格、到手价待确认等信息；高度克制，不遮挡商品。

版式约束：

- 文字不能压住商品主体的关键识别区域。美妆口红图中，文字不得盖在膏体、瓶身 Logo、瓶盖高光或包装主视觉上。
- 不要把价格、卖点、注释分别随意贴在画面底部；它们必须组成价格组、标签组或信息卡。
- 不要所有文案都居中堆在商品上方；如果商品占中轴，文字可放左上、右上、底部卡片或环绕但不压主体。
- 浅色背景上用深色文字；复杂背景上必须加半透明卡片、遮罩、描边或阴影。
- 文字和商品至少保留 24-48px 视觉间距；主标题和画布边缘至少保留 5%-8% 安全边距。
- 价格不能使用普通正文大小；价格要有商业识别，数字明显大于币种和后缀。
- 单张主图只保留 1 个主标题、1 个副标题、1 个价格/促销组和最多 2-4 个短标签；多余信息拆到详情图。

失败标准：

- 文字像文档正文一样直接打在图上，没有卡片、标签、对齐、层级或视觉组合。
- 文字覆盖商品主体或与商品边缘相撞。
- 底部散落多个小字，彼此没有对齐关系或视觉容器。
- 主标题、副标题、价格、卖点字号差异不明显。
- 价格、卖点、注释颜色太浅不可读，或与背景融合。
- 文案没有和画面证据对应，只是漂浮在空白处。

`scripts/render_text_overlay.py` 支持 `text`、`price`、`rect`/`card`/`pill`、`line` 图层。使用脚本时优先用这些图层组合出设计结构，而不是只用 `text` 层。

## 图上文字防乱码流程

用于中文、英文、中英混排、品牌口号、参数表、价格贴片和详情页短句。除非用户明确只要纯 prompt 草案或当前环境没有生图能力，否则商品图片交付必须包含文字正确且排版好看的最终图片文件。

默认流程：

1. 先把所有图上文字逐字定稿，区分主标题、支撑句、标签、参数和脚注；未确认价格、认证、功效百分比不进入画面。定稿清单必须剔除内部载体词和模板词，例如“电商详情页”“产品详情页”“详情页首屏”“详情页材质说明”“Banner”“A+页”“主图”“车图”。
2. 强文字模型优先生成带字成品图，让模型完成字体、字重、标签、价格组、卡片、装饰和留白；弱文字模型才优先生成无字底图。
3. 生成前做缺值校验：任一标签后缺少值，必须删除该项、改为“待确认”或移到待补资料；不得生成“推荐腰围/臀围”后面空白、参数卡空行或只有标题没有内容的卡片。
4. 生成后先保留原生版式做校验：逐字核对错字、乱码、漏字、重复、断行、裁切、标点、大小写、价格数字和单位；同时检查文字是否美观、是否融入画面、是否遮挡商品。校验要覆盖错词替换、语义跑偏和信息缺失，例如把商品名误生成“产品详情页”、把正常词误成无意义词、把型号/推荐范围漏掉。
5. 校验失败但版式好看时，优先局部重绘或局部编辑错字，要求保持原字体、字号、颜色、位置、背景卡片和整体排版不变。
6. 局部修字失败、模型文字能力不足、文字过小或参数过密时，再用真实字体、价格组、标签、卡片或线条兜底合成文字层并导出新的最终图片文件；中文优先使用 Noto Sans CJK、Noto Serif CJK、Source Han Sans、Source Han Serif、PingFang SC 或系统可用中文字体；英文优先使用 Inter、Roboto、Open Sans、Helvetica/Arial 等稳定字体。
7. 兜底合成后再次 OCR/人工校验和版式校验。

小字和参数图策略：

- 机箱、电脑配置、家电参数、服饰尺码推荐、兼容型号、材料成分等超过 4-6 个信息点时，不让模型直接生成完整参数表小字。
- 图上只保留买家最需要先看到的关键参数，用分组信息卡、Bento 卡、尺寸线或大字号标签展示；完整参数、尺码、适配范围放到飞书正文表格。
- 最小字号必须保证在目标平台预览尺寸下可读。OCR 读不出来、人工缩略图看不清或数字/单位混乱时，判定失败。
- 失败后不要继续要求模型“把小字写准”；改为拆屏、放大、减少字段，或无字底图 + 真实字体渲染。

成品图硬性要求：

- 有可用生图工具时，每张成功生成的商品图都必须经历“底图生成 -> 文字层合成 -> 成品图检查 -> 展示成品图”。
- 最终回复不能把“后期真实字体叠字”“设计师套用”“待生成”当成最终交付状态；这些只能作为内部步骤或降级说明。
- 如果某些图因为安全策略、工具失败或素材不足无法生成，必须明确标注失败原因；已生成的图仍要完成文字合成后交付，不能因为部分失败而把全部图片降级为 brief。
- 若用户要求 10-15 屏详情图，但工具限制导致无法一次完成全部图片，先交付已完成的带字成品图，并列出剩余图片的继续生成计划；不要把未生成图片伪装成已完成。
- 已完成详情图少于本次承诺屏数时，不能在飞书或聊天里写成“完整详情图”；必须标注为“降级交付/未完成”，写清缺失屏次、失败原因和后续生成计划。
- 飞书文档交付时，所有已生成的带字成品图都必须进入飞书文档的主图/详情图图文展示区，图片和本图作用说明要相邻；聊天核心速览可以只放代表图，但飞书文档不能只插入代表图。交付前按编号核对 `已生成图片数 = 飞书正文成品展示图片数 + 明确失败/未生成数`。

可用脚本：

- `scripts/render_text_overlay.py` 只作为兜底或局部替换工具，不作为默认美术排版引擎。
- 使用脚本时，把模型生成的优秀版式作为参考，把文字、价格、卡片、标签和线条合成到已生成底图，输入为底图、输出文件和 JSON 图层。
- JSON 图层必须逐层写出 `type` 和 `box`；`box` 为 `[left, top, right, bottom]` 像素坐标，脚本会自动换行并缩小字号以适配文本框。

示例：

```bash
python scripts/render_text_overlay.py \
  --input base.png \
  --output final.png \
  --layers layers.json
```

确需模型直接生成文字时，只允许短字样：

- 中文尽量 2-8 个字，英文尽量 1-4 个词。
- 放大字号、提高对比度，减少字体花样和文字层级。
- prompt 逐字写出文案，并要求“文字清晰、无乱码、无错字、无重复、无变形”。
- 生成后必须 OCR/人工校验；失败就切回无字底图加真实字体文字层。

文字层设计要求：

- 字体文件必须支持目标字符集，避免中文显示成方块、问号或空白。
- 导出前确认编码为 UTF-8；不要把中文 prompt、文案表或 SVG/HTML/CSS 保存成错误编码。
- 价格、尺寸、容量、型号和单位要使用可读数字和标准符号；避免全角半角混乱。
- 小屏电商图的最小文字要足够大，参数/脚注宁可少写，不用不可读小字。
- 参数表、尺码表、推荐范围不能出现空白值、错位值或只剩标签没有内容；信息不全时写“待确认”或从画面移除。
- 文字不能压住商品关键识别区域、Logo、包装主视觉、尺寸线或局部放大窗。
- 文字必须有版式组织：标题组、价格组、标签组、信息卡或标注线至少选择一种，不能只放散落文字。
- 如果模型原生版式明显更好，优先局部修字而不是用脚本整体重排。

交付时的文字状态标注：

- `模型原生排版，已校验`：强文字模型生成且文字逐字正确，推荐优先状态。
- `模型原生排版，局部修字后已校验`：版式保留，错字已局部修复。
- `后期真实字体兜底，已校验`：模型文字能力不足或局部修字失败时使用。
- `无文字底图`：适合交给设计师二次排版，或平台位置禁止图上文字。
- `需局部修字`：已有图片中存在乱码、错字或裁切时使用。
