# 原子输出契约：商品图片生成规则

## 商品图片生成规则

- 用户提供商品图时，必须优先用用户图片作为主体参考，保持商品主体一致；多张商品图片共用同一套主体保留项。
- 用户提供的是自己拍摄的商品图时，只继承商品主体、包装、Logo、真实配件和比例；原拍摄背景默认不可迁移。应使用抠图、分割、局部重绘、换背景或商品主体合成，把桌面、房间、线缆、手边杂物、墙面和非商品道具从商业成品图中清除，除非用户明确要求保留该场景。
- 用户没有提供商品图但提供了商品名时，先联网搜索商品名称或品类常见外观，基于常见外观生成概念主参考图或 brief；后续所有图片必须继承这张概念主参考图，并在末尾明确提醒用户上传真实商品图以保证主体一致。
- 用户没有商品图且商品名/品类也不清楚时，先问商品是什么。
- 商品图片默认包含商品主图和商品详情图；用户只说“图片/商品图/生图/上架图”时不要只给详情图。
- 商品主体保留项必须写清：颜色、结构、包装、Logo、文字、比例、透视、可见配件。
- 多图主体一致必须有主参考图、主体保留清单和逐图一致性检查；不能每张图单独文生图重新想象商品。
- 主体不一致时，优先改用图生图、参考图适配、结构控制、局部重绘或商品抠图合成；已明显变成另一款商品的图片不能交付为成品。
- 商品详情图数量按商品复杂度、平台位置和用户预算确定；轻量/短版 3-5 屏，标准商品页 6-9 屏，高复杂度、多 SKU、强参数/强信任类目或用户明确要求完整长详情时 10-15 屏。用户明确要单张长图时，按已确定的 N 个纵向板块合并为一张长画布。少于已承诺屏数时必须说明原因。
- 商品主图价格、促销贴片只能使用用户提供或已授权/已确认价格。未获用户确认前，图上价格贴片改为非数字表达，公开网页检索到的价格只能放入正文“待确认价格参考”，不得进入可直接上架的图上文字。
- 中文、英文和中英混排图上文字默认优先用强文字模型生成好看的原生文字版式，再 OCR/人工逐字校验并局部修字；弱文字模型、局部修字失败、文字过小或参数必须强确定时，才改用“无字底图 + 后期真实字体叠字 + OCR/人工校验”。有生图能力时必须把文字真实合成进最终图片文件，不能把“后期叠字”作为交给用户或设计师的待办。
- 成功生成的商品图片必须展示或链接带文字成品图；无字底图、待生成占位、待设计师叠字都不能标为已完成。
- 强文字模型优先生成带字成品图；生成后逐字校验，错字优先局部修复，尽量保留原生字体、装饰、位置和版式。
- 后期真实字体叠字只是兜底，不是默认美术排版流程。文字合成必须先参考模型原生版式或设计稿规格：安全区、标题组、价格组、标签组、卡片/遮罩/线条、对齐和留白。纯文字坐标叠加不能标为完成。
- 可见文字生成前必须执行文本清单校验：删除内部载体词，确认每个标签都有值，确认数值/单位/型号无遗漏，确认没有“产品详情页”“电商详情页”等泛化模板词被当成商品名。
- 参数型图片必须控制文字密度。机箱、电脑配置、尺码推荐、兼容型号、材料参数等信息超过 4-6 项时，优先拆为多张详情图或用分组卡片展示核心项；完整表格放进飞书正文或聊天正文。小于最小可读字号的参数不得进入图上文字。
- 价格、卖点、注释不能散落在画面底部或压住商品；必须组成价格组、标签组、信息卡或底部条。
- 每张主图/详情图单独写 prompt 或 brief，包含资产类型、业务目标、关键信息、视觉方向、图上文案、主体保留项和禁止项，不要让一个 prompt 同时承担整页所有信息。
- 图上文案必须逐字写出，不使用“XX”“待补充”“若干文字”等占位。
- 主图负责一眼识别商品和点击理由，详情图负责解释卖点、规格、步骤、证据和选择理由。
- 详情图模块按买家决策路径组织：先理解商品，再相信卖点，再确认规格/使用/售后。
- 多张商品图片要主体一致、视角和版式变化：主图、全貌、局部特写、步骤、参数表、包装清单、场景使用交替安排。
- 抽象风格词要转成具体视觉语言，例如“高级”写成克制配色、留白、柔和轮廓光和极简字体。
- 生成真实图片后要检查商品主体一致性、文字可读性、图文一致性、平台适配和未证实 claim；偏离时只修关键问题。
