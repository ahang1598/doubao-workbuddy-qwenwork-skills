# 豆包电商商品内容

## 版本规则

当前版本：3.5。后续每次优化本技能时，把版本号增加 0.1，并在交付压缩包文件名中同步版本号，例如 `doubao-product-content-3.6.zip`。

## 概览

使用本技能把商品事实转成四类可执行交付：商品标题、详情页文案、商品图片、图片拍摄建议脚本；商品图片默认包含商品主图和商品详情图，其中拍摄脚本是图片需求后的补充建议，不作为飞书文档模式的必要判定项。不声称获取实时平台数据，不虚构商品证据。公开网页检索到的价格、促销、同款区间只能作为“待确认参考”，不得直接写入商品主图、卖点图或详情图可见文字；图片价格必须来自用户提供、授权商品页、品牌/店铺后台截图，或用户明确确认后的数值。

核心原则是“证据先行”：先说明已知信息和缺失信息，只写用户已提供证据或明确标注为假设的信息。

本技能先判断需求，再计划执行。重点判断内容质量：标题要准确覆盖搜索意图并让买家一眼看懂商品价值；详情页文案要把商品事实转成可信的购买理由；商品主图要让买家一眼识别商品和点击理由；详情图要把文案转成可生成、可设计的画面；拍摄脚本要让用户知道怎么拍到可用于商品图片的素材。需求判断必须先区分三类：`纯边界外需求`、`复合需求`、`本技能可覆盖需求`。

商品图片采用电商设计链路，而不是普通商品图提示词链路。执行顺序必须是：平台/载体分流 -> 购买阻力和转化任务判断 -> 推荐资产组合 -> 单屏商业任务 -> 物理结构骨架 -> 场景语义推演 -> 实例填充 -> 单张生成 -> 废稿审查。每张图都必须回答“这张图帮买家解决什么问题、用什么画面证据证明、采用什么版式骨架呈现”。详情图一屏只做一件事，禁止把多个卖点、参数、品牌故事、售后和场景揉进同一屏；也禁止多屏都只是完整商品主体旁边换一段解释文字。平台/载体优先于通用美学：国内主图负责点击，国内详情页负责逐屏建立理解和信任，Amazon 主图负责合规白底，Amazon 信息型副图负责客观卖点/尺寸/包装/场景，Amazon A+ 负责模块化品牌内容，独立站 PDP 负责品牌调性和转化说明。

商品图片必须先锁定商品身份，再扩展场景和详情图。多张图不得每张独立文生图重新想象商品；默认先确定一张主参考图和主体保留清单，并把主体参考图插入飞书文档，再为每张图分配商品露出策略、资产类型、镜头距离、视角、画面任务和参考资产。主体一致性只锁定商品身份，例如颜色、结构、Logo/包装主视觉、SKU 数量、关键配件和标志性比例；不得把原图视角、摆位、裁切、背景、商品占比或完整主体出现方式也误当成必须复制的主体一致性。主体一致性不等于每张图都必须出现完整商品：主图、首屏、包装清单、尺寸/参数、局部细节和使用步骤等证据屏应直接展示商品；痛点氛围、品牌理念、纯文字过渡、参数摘要、结构/机理示意、材质层次、剖面/爆炸图、微观纹理、使用前后状态、流程步骤等屏可以弱露出商品、只用环境/人物/材质/图标/结构示意表达，甚至完全不出现商品。所有品类都必须先做“商品证据层拆解”：从商品本体之外找能证明卖点的要素层，包括材质/纹理、结构/层次、功能机理、使用动作、场景关系、规格比例、包装清单、原料/成分、清洁/护理/安装流程、售后边界和风险限制。菜刀不能只拍整把刀，要有刀刃/刃口/钢材纹理/握柄/切割动作/清洗收纳；纸巾不能只拍整包纸，要有层数/纤维纹理/压花/抽取动作/吸水或湿韧场景；衣服不能只拍平铺或模特全身，要有面料微观纹理/走线/领口袖口/版型剪裁/上身动作/洗护说明；洗衣液不能只拍瓶身，要有用量、泡沫、污渍处理、衣物纤维清洁过程、香型或低泡漂洗场景，涉及分子/机理图时必须标注为示意且不能虚构功效证据。后续图片用图生图、参考图条件、局部重绘或同一商品模型/工作流生成时，必须主动改变商品露出方式、镜头距离、视角、构图、交互动作、场景关系或版式骨架；如果工具持续保留同一输入角度和完整主体占比，必须停止沿用同一底图，把后续屏改为局部、内在机制、无商品、参数、场景、材质微观、步骤流程或包装清单路线。任何品类的整套详情图都不能只放同一个完整商品主体；必须穿插该品类的细节、材质、结构、机理、动作、场景、参数、包装和边界说明等其他要素图。用户上传自己拍摄的商品图时，该图只用于提取和锁定商品主体；除非用户明确要求保留原场景，否则必须隔离、抠除或重绘原拍摄背景，不能把用户家中、桌面、线缆、杂物、墙面等实拍环境融入商业成品图。

商品图片中的中文和英文文字默认优先交给具备强文字能力的生图模型做原生排版生成，让模型完成字体、字重、位置、装饰、留白和整体设计感；生成后用 OCR/人工校验逐字核对，只对错误文字做局部重绘、文字替换或真实字体兜底修复。不要默认用脚本从零排完整张图的文字，否则容易变成“字对但不好看”。可见图上文案不得出现内部载体词或模板词，例如“电商详情页”“产品详情页”“详情页首屏”“详情页材质说明”“Banner”“A+页”“主图”“车图”，除非这些词本身就是商品名或用户明确要求展示的真实文字。所有图上文案必须在生成前定稿并完成缺值检查；如“推荐腰围/臀围”等标签后没有值，必须删除该行/卡片或明确写“待确认”，不能留下空白。参数多、小字多的商品图必须拆分为多屏大字信息卡或改用真实字体后期渲染；机箱、3C 配置、尺码表等密集参数不得交给模型生成微缩文字。有生图能力时，最终交付必须是已经生成完成且文字好看、正确、可读的成品图。

飞书文档成稿采用“两层交付”：飞书文档承载本次命中的资产和执行细节，聊天最终回复只输出“核心内容速览”、图片预览、使用提示和文档链接，不重复粘贴全文。飞书触发沿用当前设置；未明确限定输出项时仍优先尝试创建或更新真实飞书文档，但文档内容范围按用户明确需求、语义强相关模块、商品复杂度和用户预算决定，不自动扩成标题、详情页文案、商品图片、拍摄脚本全套。飞书文档如包含商品图片，必须把主体参考图、全部主图和全部详情图成品逐张插入正文，但不绑定单一排版形态；应按信息类型选择最清晰的组件组合：结构化正文可用表格，重点结论/风险/待确认可用高亮块或引用块，卖点和方案对比可用分栏/卡片，步骤和拍摄脚本可用 Markdown 有序列表，注意事项和补充信息可用 Markdown 无序列表，图片说明可用图文块、分栏、短段落或必要表格。目标是美观、可读、好扫读，而不是固定使用某一种组件。不得因为任务看起来简单、用户没有点名飞书、当前是 MainAgent 环境、聊天里也能排版、或已经找到飞书相关技能，就跳过飞书工具流程。只有飞书工具不存在、未登录、无权限、命令失败且无法自行修复、宿主禁止外部工具，或用户明确要求不要创建文档时，才降级为聊天正文并说明原因。飞书中的图片必须先处理成显示安全版本：裁掉多余透明/白边画布、扁平化为 RGB、保持正确长宽比；正文图片用中等宽度，表格核对清单才使用缩略图，避免图片文件正常但飞书显示出很长白底；可用 `scripts/prepare_feishu_image.py` 批量导出正文图或表格缩略图。飞书文档内任何图片显示都禁止直接使用网络图片 URL：不得在表格单元格、表格外图片块、XML 或 Markdown 中使用 `<img href="https://...">`、`<img src="https://...">` 或 `![...](https://...)`。远程图片必须先下载为本地文件，导出显示安全版本，再通过飞书工具上传/转换为图片 token 或可用的本地上传资源后插入；网络原图只能作为普通文本链接放在“来源/原图链接”列，不能当作图片源。外部“核心内容速览”可以只展示代表性图片，但飞书文档中的商品图片章节必须全量展示已生成资产；不得把“只挑代表图预览”当作飞书正文少插图的理由。外部速览如本次生成了商品图片，必须直接展示图片，至少包含 1 张主图预览；详情图不足 3 张时展示全部，详情图达到 3 张及以上时至少展示 3 张不同资产类型代表图。只有文字、文件名或路径不能算完整图片速览。整套商品图必须有资产类型和视角变化，按商品属性自由选择整体图、细节图、场景图、交互/步骤图、规格参数图、包装清单图等组合，不能把多屏详情图做成同一角度的重复展示。

## 参考文件加载

按需读取参考文件，不要一次性加载无关内容：

- 用户指定平台、市场、跨境渠道、独立站或多平台分发时，读取 `references/platforms.md`。
- 用户指定品类、赛道、人群顾虑、虚拟商品、合规敏感类目，或命中商品图片生成/详情图规划时，读取 `references/categories.md` 的“品类证据层映射”，先选出该品类的 4-5 类证据层，再规划详情图。
- 产出标题、详情页文案、商品图片或拍摄脚本前，先读取 `references/atom-output-contracts.md` 目录索引，再按交付场景读取其中列出的一级子文件。
- 命中商品图片能力，且需要生成真实图片或输出生图/设计 brief 时，先读取 `references/detail-image-generation.md` 目录索引，再按图片任务读取其中列出的一级子文件。
- 涉及健康、美妆功效、食品、母婴、虚拟商品、品牌/IP、认证、排名、销量、极限词或绝对化承诺时，读取 `references/compliance-checklist.md`。
- 交付模式判定为飞书文档成稿模式时，必须按 `references/atom-output-contracts.md` 的飞书文档工具流程处理；不能把“飞书文档”只理解成聊天里的文档结构。

如果用户一次要求多个原子能力，只加载覆盖这些能力所需的最小参考集合。

## 信息收集

只从当前对话中收集或推断信息：

- 商品：类目、商品名、SKU/规格、外观属性、材质、参数、包装清单、价格带、变体关系。
- 人群：购买者类型、使用场景、购买动机、顾虑、语言或地区。
- 平台：目标平台、内容位置、国内或跨境场景。
- 证据：认证、检测报告、成分表、实测数据、真实评价、品牌授权、销量数据、质保、物流承诺。
- 当前素材：已有标题、详情页文案、商品照片、主图/详情图参考、设计参考、拍摄限制、用户提供的竞品文本。
- 目标：搜索曝光、点击、转化、上架完整性、合规清理、本地化、商品图片生成、拍摄执行。
- 公开信息补全：当用户给了商品名、品牌、型号、链接、图片或足够可检索线索，但缺少尺码、规格、材质、容量、成分、包装清单等上架关键信息时，先联网搜索公开商品信息进行补全；补全内容必须标注为公开信息/待确认，不当成用户已确认事实。
- 价格补全：淘宝、京东、拼多多的商品主图、卖点图或转化规格屏需要价格标签/促销贴片时，价格必须来自用户提供、授权商品页、品牌/店铺后台截图，或用户明确确认后的数值；缺价格时可检索公开页面作为正文待确认参考，但不得直接进入图上文字。未获用户确认前，图上价格贴片改为非数字表达，如“限时优惠待确认”“到手价待确认”，不写成已确认成交价、历史低价或活动价。

向用户收集信息时遵循“缺什么问什么”：

1. 商品不清楚时，先问品类、商品名、核心规格或外观。
2. 平台不清楚且会影响标题、文案或图片时，问目标平台或市场。
3. 做标题时，优先确认当前标题、目标关键词、核心卖点、目标人群和禁用词。
4. 做详情页文案时，优先确认核心卖点、参数证据、购买顾虑、现有文案和页面目标。
5. 做商品图片时，优先确认商品照片、主图/详情图用途、详情页文案/卖点、风格参考、图/屏数量和是否需要真实生图；如果没有商品照片但有商品名，可先联网搜索常见外观做概念生成，并在结果末尾提醒上传真实商品图以保证主体一致。
6. 附加拍摄脚本时，优先基于已知商品、平台和详情图用途直接给建议；只有可拍摄环境、设备、模特/手部、道具、商品可拆解程度会显著影响执行时才追问。

缺少信息时，优先用“已知事实 / 公开信息补全 / 基于假设的草案 / 缺失信息”继续推进。只要能合理生成，就先产出可用版本，并在回答末尾提示建议补充的信息。只有平台、类目、目标语言、内容位置、图片数量、敏感 claim 是否有证据等关键点会实质改变结果时，才向用户追问。

## 需求判断与计划

先判断用户请求属于哪一个或哪几个能力，再给后续计划并执行：

- `title`：优化或撰写商品标题、SEO 标题、关键词方向、标题违规表达清理。
- `detail-copy`：优化或撰写商品详情页文案、详情页模块文案、商品描述、卖点转利益、强 claim 弱化。
- `product-image`：生成商品图片，默认包含商品主图和商品详情图；如果宿主环境有可用生图工具，必须先生成图片，再把最终图上文字合成到图片上并交付成品图；只有宿主环境没有可用生图工具或生成被安全策略/工具错误阻断时，才降级输出商品主图和详情图结构、每张/每屏画面 brief、图上文案、设计/生图提示词方向。
- `shooting-script`：图片相关需求后的附加建议；用户只要求自己拍商品图时也可单独输出，包括镜头、角度、道具、光线、构图和后期用途。

判断后按命中能力决定交付模式。飞书文档触发沿用当前设置：用户同时覆盖标题、详情页文案和商品图片，或没有明确限定只要其中某一项/某两项时，仍按飞书文档成稿处理，并优先创建或更新真实飞书文档；先查飞书工具可用性，能用就创建/更新，不能用再降级聊天正文。飞书触发只决定交付容器，不等于自动扩写全部原子能力；文档内优先完成用户明确提出或语义强相关的内容。只有用户明确限定只要标题、详情页文案、商品图片中的某一项或某两项时，才使用对话直接交付；“用户未提飞书”“任务简单”“信息不多”“可以先给核心内容”都不是对话直出的理由。只有需求中包含图片、主图、详情图、生图、拍图、场景图，或用户要求拍摄建议时，才在结果末尾附加“自行拍摄建议脚本”。

### near-miss / should-not-trigger

以下请求即使含有电商词，也不要直接触发本技能；如果同一句里同时有可覆盖的商品内容需求，先按“复合需求”给 A/B 选项：

- 选品、竞品调研、广告投放、店铺诊断、客服售后、直播或短视频脚本、活动广告套图、后台上传、Connector 图片任务。
- 要求虚构授权、销量、排名、认证、医疗/食品/母婴/虚拟商品强 claim，或要求绕过平台/法律风险。
- 只问平台运营策略、价格策略、利润测算、活动节奏、热搜趋势、竞品贬低或投放 ROI。

### 边界外与复合需求处理

先做边界判别，再决定是否进入本技能执行。不要把边界外任务包装成本技能能力，也不要因为一句话里含有边界外任务就丢掉可覆盖的商品内容任务。

纯边界外需求只说明不属于本技能，并给出可转入本技能的最小改写方向；不得输出该边界外任务的实质结果。当前只按以下边界外类型处理：

- 选品决策：不判断哪个品最值得卖，不做利润机会排序、市场机会结论。
- 竞品调研：不主动找竞品、分析竞品点击率或编造竞品、热搜、销量；可让用户提供本品后转为本品主图策略。
- 广告投放：不写千川/站内广告预算、人群包、ROI 预估、投放节奏。
- 店铺诊断：不分析店铺转化低、流量、经营归因或竞店表现；只可承接单品图文优化。
- 客服售后：不处理投诉、赔付、退换货个案或售后安抚；通用顾虑可转为详情页 FAQ。
- 直播/短视频：不写整场直播话术、逼单节奏、短视频脚本、分镜、达人口播。
- 活动广告套图：不做大促主会场 KV、多尺寸投放图或活动广告套图；只可做商品页静态主图/详情图。
- 后台操作：不上传商品、不管理平台后台、不声称已填写类目或参数。
- Connector：不创建、轮询或寻找 Connector 图片任务，不输出任务 ID。
- 虚构或高风险 claim：不写无证据官方授权、平台验真、正品授权、销量/排名、用户背书、医疗治疗、食品减重保证、母婴绝对安全、虚拟商品永久安全/包找回/官方授权。

复合需求是同一请求里同时包含本技能可覆盖部分和上述边界外部分。命中复合需求时，先暂停执行，并给用户两个选项，等待用户选择后再继续：

- `A`：抛弃本技能之外的需求，只让 `doubao-product-content` 专心完成可覆盖的商品标题、详情页文案、商品图片、拍摄建议或飞书交付。
- `B`：按用户原需求继续，但本技能之外的部分不动用 `doubao-product-content` 能力；本技能只承接其中可覆盖的商品内容部分。

复合需求的回复要明确点名“这是复合需求”，并分别列出“本技能可覆盖部分”和“本技能之外部分”。在用户没有选择 A/B 前，不要直接生成完整商品页，也不要直接产出选品、竞品、投放、店铺诊断、客服售后、直播短视频、后台操作、Connector、运营节奏、价格策略、授权证明、医疗功效判断等边界外结果。若用户选择 B，边界外部分也必须由普通对话能力或其它合适能力处理，不能在 `doubao-product-content` 的产出里假装完成。

表格中保留的复合类型必须按 A/B 分流处理：选品+商品页、竞品+商品图、投放+主图、直播+静态图、短视频+商品页、客服+FAQ、店铺诊断+单品优化、后台上传+上架内容、活动广告+详情页、虚构授权/认证+正常商品页、实时热词+标题、竞品贬低+对比图、视频分镜+静态素材、价格策略+价格标签、授权缺失+得物上架、医疗功效+美妆图文、平台运营+Listing、实拍背景保留+包装清单。

明确排除：

- 不写直播话术、短视频脚本、达人口播、分镜脚本或视频拍摄脚本。用户要求视频时只提供静态图片素材如何支持视频封面/商品页的建议，或说明不属于本技能。
- 不创建或轮询 Connector 任务，不上传商品或管理店铺后台；真实图片生成只限宿主环境已提供的普通生图能力。
- 商品图片能力必须覆盖商品主图；用户要求图片、商品图、上架图或整套商品页时，不要漏掉商品主图。不要扩展到活动广告图套图、直播背景或短视频素材，除非用户明确要求且仍属于静态商品页素材。
- 不做选品机会、竞品调研、广告投放、活动节奏、平台运营节奏、客服售后、利润定价、价格策略或店铺诊断。

整套上架内容按以下顺序处理：

1. 归一化商品事实，标出未经证实的 claim。
2. 选择平台规则和赛道规则。
3. 定义核心购买阻力、首要点击理由和核心转化承诺。
4. 按命中能力和飞书交付规则输出：明确要求完整商品页、上架内容或标题/详情文案/商品图片三类同时覆盖时，按依赖顺序输出标题、详情页文案、商品图片；模糊请求先完成语义最相关模块，并在文档中列出可补模块。只有包含图片/拍图需求或用户要求拍摄建议时，再附加拍摄脚本建议。
5. 运行质量检查，并指出未解决风险。

## 生成流程

每个原子能力都按以下步骤执行：

1. 建立 claim 台账，把信息分成 `已确认`、`公开信息补全待确认`、`需证据`、`应避免`。
2. 把商品特征转成买家利益，但保留可追溯的原始特征，避免空泛营销。
3. 根据平台和赛道调整语气、文字密度、图片信息密度和证据位置，不套用单一模板。
4. 只有当选项服务于不同意图时才输出多版，例如搜索覆盖、点击清晰、高端感、价格敏感、送礼场景、证据型转化、生活方式种草、本地化表达。
5. 除非用户明确提供依据，否则不写促销紧迫感、排名、医疗、安全、授权、销量、认证等强 claim。
6. 商品图片交付要同时写清商业任务和视觉任务：主图负责什么点击理由，详情图让买家看懂什么、相信什么、行动什么，以及应该拍/设计/生成什么画面。
7. 商品图片生成前必须先做平台/载体分流和资产组合推荐：判断是国内主图、国内详情页、Amazon 主图、Amazon 信息型副图、Amazon A+、独立站 PDP 还是内容种草图；再从首屏钩子、痛点解决、核心优势、材质/细节、步骤说明、规格参数、包装清单、对比选择、信任/售后、品牌收束中选择最有商业价值的组合。不要机械生成固定几屏。
8. 商品图片有用户商品照片时必须先建立“主体身份锁定”：选定主参考图，提取商品身份硬锁项和镜头/版式可变项，并让后续需要直接展示商品的主图/详情图基于该参考图或已确认主图继续生成；局部商品、内在机制、弱商品或无商品屏只继承商品事实、视觉语言和身份边界，不强制露出完整商品。
9. 没有用户商品照片但有商品名时，先联网搜索商品名称或品类常见外观，基于常见外观生成概念主参考图；后续需要直接展示商品的图片继承这张概念主参考图，局部/内在/无商品屏继承事实口径和视觉语言，并在结尾提醒用户上传真实商品图片替换主体。
10. 用户没有上传足够商品信息但给了可检索线索时，先联网搜索公开商品信息补齐尺码、规格、材质、容量、成分、包装清单、适配范围等；无法确认的字段不要写成事实，放入待补资料。
11. 商品详情图屏数按商品复杂度、平台位置、用户预算和交付模式决定，不固定为 10-15 屏。轻量或预算有限任务可做 3-5 屏，标准商品页常用 6-9 屏，高复杂度、多 SKU、强参数/强信任类目或用户明确要求完整长详情时再做 10-15 屏。用户明确要求单张详情长图或不要拆分时，按已确定的 N 个纵向板块组织为一个长画布。少于计划屏数时必须标注为短版、降级或未完成，并说明原因。
12. 商品详情图生成前必须建立逐屏设计矩阵。每一屏都要填写：平台/载体、资产类型、商业任务、买家问题、品类证据层、商品露出策略、物理结构骨架、场景语义、实例填充、图上文案、文字层级和合规边界。缺任一项，不得进入生图。
13. 每屏必须采用“三层推演”：第一层定物理结构骨架，例如上下分区、左右分栏、Bento 信息卡、中心主视觉、局部放大圆窗、步骤卡、尺寸线、参数表、包装清单平铺、纯文字色块；第二层定场景语义，例如厨房切割、浴室清洁、桌面办公、衣柜搭配、户外使用、抽取纸巾、倒取洗衣液；第三层做实例填充，把每个卡片、图标、文案、局部放大窗、手部动作、尺寸线和道具写清，不能用“相关元素”“若干说明”概括。
14. 淘宝、京东、拼多多图片需要价格标签或促销贴片时，只能使用用户提供、授权商品页、品牌/店铺后台截图，或用户明确确认后的价格；缺价格时可检索公开页面作为正文“待确认参考”，不得进入图上文字。未获用户确认前，图上价格贴片改为非数字表达，如“限时优惠待确认”“到手价待确认”，并列入待补资料。
15. 标题、详情页文案和商品图片必须协同：标题承诺的核心卖点，详情页文案要展开解释，主图要抓住点击理由，详情图要用画面证明或帮助理解。
16. 商品图片生成成功后，必须按商品露出策略检查：直接展示商品的图片要检查主体身份一致性，颜色、结构、Logo/包装文字、关键配件、比例、SKU 数量和标志性细节必须与主参考图一致；局部商品、内在机制、弱商品或无商品屏不因没有完整商品而扣分，但不得生成另一款商品、虚构内部结构、虚构配件或把场景道具画成售卖内容。
17. 商品图片生成成功后，必须先检查模型原生文字排版是否可用：如果排版漂亮且文字正确，保留模型原生文字；如果排版漂亮但文字有错，只局部修错字，尽量保留原字体风格和版式。
18. 只有模型无法可靠生成文字、局部修字失败、平台禁止模型直接造字或需要强确定性价格/规格时，才使用 `scripts/render_text_overlay.py` 将文字、价格、卡片、标签和分隔线渲染到无字底图上；脚本兜底必须服从已有画面设计语言，不能从零做低质贴字。
19. 生成图上文字前必须做“可见文字清单”检查：逐字列出实际要上图的文字，禁止内部载体词入画，禁止空值标签，缺失规格/尺码/推荐范围要移出画面或标为“待确认”。
20. 参数多或小字多时，优先拆屏、分组卡片、大字标题 + 少量关键参数；完整参数表放入飞书正文表格，不强行塞进图片。若小字 OCR/人工检查失败，必须重生成无字或低字底图，并用真实字体兜底渲染。
21. 商品详情图生成前必须先分配资产类型、商品露出策略和视角：至少覆盖整体/全貌、局部细节、内在结构/功能机制、使用或场景、规格/参数/包装/步骤中的多种类型；连续图片不得使用同一角度、同一构图、同一完整主体露出方式和同一信息密度。
22. 所有品类都必须有“其他要素图”，不能只靠完整商品主体换背景和文字凑屏。10-11 屏至少包含 4 类非完整主体重复屏，12-15 屏至少包含 5 类，优先从该品类的材质纹理、局部结构、功能机理、微观细节、使用动作、规格比例、场景状态、流程步骤、包装清单、成分/原料、售后/使用边界中选择。主机/3C 选接口、散热、内部结构、配置卡和连接场景；菜刀选刃口、钢材纹理、握柄、切割动作和收纳清洁；纸巾选层数、纤维、压花、抽取、吸水/湿韧；衣服选面料微观、走线、版型、上身动作和洗护；洗衣液选用量、泡沫、污渍处理、衣物纤维清洁过程和机理示意。涉及看不见的内部机理、分子、纤维或剖面时，只能作为“示意图/机理示意”，不得伪造检测、功效百分比或真实微观照片。
23. 对照 `references/categories.md` 的品类证据层映射做检查：若详情图没有覆盖该品类至少 4-5 类证据层，或只是完整商品主体加解释文字，不能进入生成；必须先重排屏次，再生成图片。
24. 如果输出依赖公开信息补全、未证实信息或信息未给全，结尾必须列出风险或待补资料，并提示用户补充/确认。

## 质量检查

最终输出前检查：

- 事实安全：不虚构认证、销量、临床效果、前后对比、品牌授权、物流承诺、价格历史。
- 合规安全：不写绝对化优势、保证结果、医疗治疗、不安全母婴/食品/美妆 claim、未经授权的品牌/IP。
- 平台适配：标题密度、文案语气、图片文字量、视觉顺序和行动引导符合目标平台的常见内容习惯。
- 赛道适配：核心卖点回应对应品类的真实购买决策。
- 原子契约：输出遵循 `references/atom-output-contracts.md` 中对应能力的结构。
- 主体一致：直接展示商品的图片必须继承同一主参考图和主体保留清单；不能出现同一商品在不同图里颜色、造型、包装、Logo、配件数量或 SKU 变成另一个商品。局部商品、内在机制、弱商品或无商品屏可以不出现完整商品，但不得生成另一个商品、虚构配件或把道具伪装成售卖内容。
- 实拍背景隔离：用户商品图的原始拍摄场景不得默认进入成品图；只有商品主体、包装和真实配件可继承，背景、杂物、桌面、墙面、线缆等必须替换或清理。
- 视角多样：主图和详情图必须形成全貌、细节、材质微观、内在结构、功能机理、场景、交互、规格、包装、痛点氛围或纯文字过渡等有差异的资产组合；不能多张图只是同一商品同一角度、同一商品占比、同一完整主体换背景或换文字。任何品类缺少能证明卖点的其他要素图，不能标为完整详情图；例如主机缺接口/散热/内部结构，菜刀缺刃口/切割/握柄，纸巾缺纤维/层数/吸水，衣服缺面料/走线/版型，洗衣液缺用量/泡沫/污渍处理/机理示意，都要重排补图。
- 文字版式：优先保留模型原生设计感；图上文字必须像电商设计稿，而不是普通文档文字贴图。检查标题、卖点、价格、标签、注释是否有层级、对齐、留白、安全区和视觉承接。
- 文字准确：图上可见文字不得含“电商详情页”“产品详情页”等内部载体词，不得出现错字、乱码、漏字、重复标签、空值标签或未确认数字；小字和参数必须可读，无法可读就拆屏或转真实字体兜底。
- 飞书显示：插入飞书前检查图片显示安全版本，避免透明长画布、未裁切白边或超大原图导致图片块或表格单元格出现长白底；出现长白底时必须换显示安全图、调整为正文图片块或重新导出正文宽图。飞书文档内禁止用网络 URL 直接插图；网络 URL 只能作为普通文本来源链接，不能作为 `<img>` 或 Markdown 图片源。
- 飞书图片完整性：若本次包含商品图片，飞书文档里的商品图片章节必须逐张覆盖本次已生成的全部主图和详情图；最终声明“共 X 张/屏”时，正文图文卡片、图片块、分栏区或表格核对清单的数量要与 X 对齐。只插入代表性预览图、把剩余图只写进 brief/计划/聊天说明、或因为正文太长而省略，都不算完整交付。
- 详情图数量完整性：详情图数量必须与商品复杂度、用户预算和本次承诺一致；不要把所有完整商品页都固定成 10-15 屏。轻量/短版可少于 6 屏，标准商品页通常 6-9 屏，高复杂度或用户明确要求完整长详情时可 10-15 屏。若实际交付少于已承诺数量，必须标注短版、降级或未完成，并说明缺失屏次和原因。
- 可执行性：有生图能力时，商品图片不是只给设计师或生图执行者的待办 brief，而是要交付可直接查看和使用的成品图；无图或无字图不能算生成完成。
- 内容质量：标题、详情页文案、商品图片 brief 和拍摄脚本都要具体、可信、可执行，并能对应商品事实和买家顾虑。

如果用户要求“合规检查”“审核”“风险评估”或“能不能用”，先列风险和修改建议，再给改写方案。

## 输出规则

- 默认使用用户语言；中文场景优先中文输出。跨境平台可按用户要求输出英文或目标语种。
- 最终交付必须按 `references/atom-output-contracts.md` 中的交付模式组织：标题、详情页文案、商品图片三类同时覆盖时输出飞书文档成稿；未明确限定能力时仍默认尝试真实飞书文档，但文档内容按用户明确需求和语义强相关模块组织，不默认补齐拍摄脚本或固定数量详情图；只有明确限定的单项或两项能力才在对话中直接输出可复制结果。
- 飞书文档成稿模式不是普通聊天排版：在 ActionHub 或目标 App 环境中，必须把 `lark-doc/lark_cli_exec` 作为飞书命令统一入口；先通过该入口读取 lark-doc 帮助和 `docs +create/+update` 参数，再通过该入口执行创建或更新文档。不能在技能正文里要求直接调用本地 `lark-cli` 子命令，也不能把“任务简单”“用户没说要飞书”“MainAgent 环境”“已经发现飞书技能”当作跳过创建文档的理由。只有目标 App 未暴露 `lark-doc/lark_cli_exec`、该入口不可用、未登录、无权限、命令失败且无法自行修复、宿主禁止外部工具，或用户明确不要创建文档时，才在聊天中输出可复制正文并说明原因。
- 若本次包含商品图片，飞书文档成稿模式必须包含主体参考图和全量图片成品展示区：主体参考图展示 `参考图编号、主体保留项、可变化项、使用范围`；主图和详情图逐张写清编号、名称、资产类型、图上文案、用途/备注和本图解决的问题。图片与说明必须相邻，但具体可用图文块、分栏、短段落、Markdown 列表或必要表格。可另附一张简短图片交付核对表，但不能用核对表替代正文展示；有真实图片时必须把全部主图和全部详情图逐张嵌入正文，不能只写文件名或路径，也不能只挑代表图。
- 飞书嵌图必须使用显示安全图：正文图片块、图文区域、分栏图片区建议插入裁切白边、扁平化 RGB、宽度约 480-720px 且保持比例的正文图；表格核对清单才使用宽度约 140-220px 的缩略图。飞书文档内禁止任何网络 URL 直插图片，包括表格单元格和表格外图片块。禁止写法包括 `<img href="图片URL">`、`<img src="https://...">`、`![图片](https://...)`。必须先下载远程图到本地，生成显示安全图，再上传/转换为飞书图片 token 或本地上传资源后嵌入；若工具不支持上传/转换，则该图不能标为已嵌入，只能把网络 URL 作为普通文本来源链接并说明降级。若飞书显示出现长白底，必须重新导出显示安全图或改为本地上传后的正文图片块，不能交付异常显示。

- 公开搜索补全的信息不能和用户已确认事实混在一起；在正文基础信息或结尾标注为“公开信息补全，需用户确认”。
- 优先写具体买家语言，不写空泛夸张词。
- 标题、详情页文案和商品图片要使用一致的核心 claim 词汇，保证整套商品页口径统一。
