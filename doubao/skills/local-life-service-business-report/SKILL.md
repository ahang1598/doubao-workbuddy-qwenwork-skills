# 抖音生活服务商家经营数据分析报告
## 技能概述
自动获取抖音生活服务商家的经营数据，生成一份报纸头版风格的HTML单页经营分析报告。
## 触发条件
用户输入 `/local-life-service-business-report` 或明确要求生成抖音生活服务商家运营数据分析报告。
## 不适用场景
- 仅需同行对比 → 转 `local-life-service-peer-comparison`
- 仅需热点选题/内容建议 → 转 `local-life-service-hot-find`
## 核心流程
### 第零步：通用模板输出（零登录，默认先执行）
用户触发本技能后，**不先要求登录**，直接输出一页轻量 HTML 通用经营体检模板。
1. **生成 HTML 报告**：使用妙搭生成单页 HTML，技能只描述内容结构，视觉设计（配色、排版、组件样式）全部交给妙搭处理。报告包含以下模块：
   - **顶部头部**：标题「经营体检通用模板」+ 显著标注「通用参考，非真实经营数据」。
   - **经营指标体检表**：流量、转化、核销、复购、口碑五大维度的核心指标和通用健康区间，用户可自行对照打分。
   - **四步自查框架**：流量够不够 → 转化高不高 → 核销顺不顺 → 口碑稳不稳，每步配判断标准。
   - **常见问题速查**：按症状（曝光低 / 下单少 / 核销差 / 差评多）对应可能原因和通用优化方向。
   - **通用行动清单模板**：可填空的周度运营行动表。
2. **数据标注**：所有区间、标准均标注「通用参考，非真实经营数据」，不得伪装成商家真实数据。
3. **末尾引导（直接问，不出现平台名称）**：
   > 以上是通用经营体检模板，仅供参考，你可以先对照自查。如果需要基于你门店的真实成交、核销、流量、商品数据，生成专属经营分析报告（含数据看板、问题归因和优先级行动建议），可以告诉我，我帮你登录商家后台拉取数据。
4. **升级衔接**：用户回复需要更详细/更专业/专属报告后，进入第一步（原流程不变）。
### 第一步：一次性需求确认卡
技能启动后立即抛出确认卡，商户一次性回复：
```
【经营分析确认卡】回复编号修改，无异议回复"全部默认"
1. 分析周期：①近7天 ②近30天 ③自然周 ④自然月 ⑤自定义
   → 默认：②近30天
2. 关注重点：①成交核销 ②流量曝光 ③商品表现 ④门店排名 ⑤行业竞争 ⑥全部
   → 默认：⑥全部
3. 报告模式：①自动判定 ②强制案例（亮点经验） ③强制诊断（问题改进）
   → 默认：①自动判定
```
商户回复"全部默认"即确认，仅针对修改项单轮补充，禁止逐项追问。

### P0：登录态接续与窗口校验
本规则优先于后续全部获取和报告流程，对数据平台、商家后台都适用。
1. 打开平台后，先检查当前浏览器的全部标签页和窗口，优先复用已经登录且与目标平台匹配的页面；禁止只检查当前活动标签页就判定登录失败。
2. 登录成功必须由**当前可操作页面**的正向证据确认：
   - 页面不再显示阻断操作的手机号、邮箱、扫码等登录表单；
   - 页面显示可核验的商家身份（商家名称、groupid、门店数等）与至少一项真实经营数据。
3. 当用户说"已登录"或提供已登录截图，但当前页面仍显示登录表单时：
   - 只可表述为"用户侧已登录，但当前自动化页面尚未接续到该登录态"，不得表述为"用户未登录"或否定用户的登录结果；
   - 重新枚举全部标签页和窗口，切换到已登录页面；若没有找到，刷新当前目标页面并重新读取页面状态，禁止沿用刷新前的截图或DOM判断；
   - 若仍未接续，明确说明可能是窗口、标签页或浏览器上下文不同，但不得把未验证的原因写成事实；使用 `interaction.request_action` 请求用户接管**当前自动化浏览器窗口**完成登录，或在工具支持时连接用户已登录的可控浏览器窗口。
4. **停止条件**：在当前可操作页面出现上述登录成功正向证据前，禁止获取数据、禁止宣称已拿到真实数据、禁止生成正式经营报告。
5. **模拟数据红线**：登录态未接续时不得主动回退到模拟数据。只有用户明确要求"生成模拟报告"时才可另行执行，并必须在文件名、标题和正文显著标注"模拟数据，非真实经营数据"。
6. 登录成功后，立即记录当前页面URL、商家名称和一项经营指标作为接续证据，再进入数据获取；切换平台、标签页或账号后必须重新执行本校验。

### P0：数据平台内部页面导航门禁
本规则优先于后续全部获取流程，违反任意一条即视为执行错误。

**禁止通过以下方式进入数据平台内部页面：**
- 直接在地址栏输入或替换 `life-data.cn` 内部路径；
- 使用浏览器直接导航或修改 `location` 打开内部路由；
- 复用历史对话、收藏、浏览记录或旧标签页中的完整页面 URL；
- 拼接、替换或沿用包含 `groupid` 的完整链接；
- 因页面点击暂未跳转，就直接打开推测出的内部路径；
- 通过商家后台顶部搜索框、经营数据"全部"等非标准路径寻找数据平台内部页面。

**进入数据平台后，所有模块必须通过当前页面上的可见菜单、标签或按钮进入。**

**点击菜单未跳转时，按以下顺序处理：**
1. 等待页面完成加载；
2. 检查并关闭遮挡菜单的引导、弹窗；
3. 再点击同一个可见入口一次；
4. 仍未跳转则停止，并说明"页面导航未成功"；
5. 不得改用地址栏、历史链接或推测 URL。

### P0：商户上下文校验
1. 从商家后台记录当前目标商户名称。
2. 进入数据平台后，必须读取右上角当前商户名称，并与商家后台目标商户名称逐字核对。
3. 如果名称不一致：
   - 立即停止读取经营、流量、热点或搜索词数据；
   - 打开页面商户切换控件；
   - 按商户名称选择后台目标商户；
   - 切换后重新读取右上角商户名称；
   - 复核一致后才可继续。
4. 无法找到目标商户时，停止并如实告知用户。
5. 不得仅根据 URL 中存在 `groupid` 判断商户一致。

### P0："暂无该页面权限"分级处理
**不得仅根据以下现象推断商户没有权限：**
- 页面空白；页面内容较少；页面加载较慢；字段暂未显示；菜单点击未跳转；页面组件尚未初始化。

如果页面明确显示"暂无该页面权限"，先判断当前页面的进入方式。

#### 情况一：通过直接 URL、历史链接或不确定路径进入
该情况属于导航上下文异常，**不能判定商户无权限**。必须：
1. 停止读取当前页面；
2. 回到商家后台首页；
3. 重新确认后台目标商户；
4. 从数据平台标准入口进入；
5. 核对数据平台右上角商户名；
6. 通过可见菜单重新进入目标模块一次。

不得刷新或继续使用原来的内部 URL。

#### 情况二：通过标准入口和可见导航进入
必须同时确认：后台目标商户名与数据平台右上角商户名一致；本轮没有直接打开或修改内部 URL；页面明确显示"暂无该页面权限"。

以上条件全部满足后：
1. 只刷新当前页面一次；
2. 刷新后重新确认商户名称；
3. 刷新后仍明确显示相同权限提示，才可判断该商户可能未开通权限；
4. 停止该模块取数并如实告知用户。

不得尝试多个入口，不得反复刷新，不得编造数据。

### P0：权限配置建议约束
- 不得根据一次页面异常，直接指导用户修改岗位权限、管理员授权或账号配置。
- 只有在通过标准入口、核对正确商户、使用可见导航进入，并刷新一次后仍明确显示权限提示时，才能建议用户联系管理员确认权限。
- 不得编造具体权限配置路径。只有当前页面可见提示或已验证的官方说明能够作为配置路径依据。

## 异常状态分类（统一使用）
| 状态 | 判定条件 | 对用户表达 |
|---|---|---|
| 页面加载中 | 页面仍有加载状态或内容逐步出现 | 页面仍在加载，稍后重新检查 |
| 导航失败 | 可见菜单点击两次后仍未进入目标模块 | 未能通过页面导航进入目标模块 |
| 商户不一致 | 后台商户名与数据平台商户名不同 | 当前数据平台商户与目标商户不一致，正在纠正 |
| 导航上下文异常 | 页面通过直接 URL、历史链接或不确定路径进入 | 当前页面上下文异常，需要从后台重新进入 |
| 数据缺失 | 页面正常进入，但对应周期没有数据 | 页面可访问，但当前周期暂无相关数据 |
| 权限不足 | 标准入口、商户一致、可见导航、刷新一次后仍明确报权限错误 | 当前商户可能未开通该页面权限 |

### 第二步：数据平台数据获取
1. **数据平台进入方式（强制）**：先确保商家后台已打开并登录（`https://life.douyin.com/p/home`），再从商家后台首页点击顶部可见的「生意经」（即数据平台入口）按钮进入。点击后必须检查：当前标签页是否已进入 life-data.cn、是否新增 life-data.cn 标签页或窗口、是否仍在跨域重定向或加载状态；发现新标签页或窗口时必须切换后再继续，不得只根据原标签页没有变化判定跳转失败。在商户选择弹窗中选择目标商户后进入数据平台首页。**多商户选择（强制）**：存在多个商户且用户目标不明确时，不得默认把列表第一项当作用户目标商户，必须先确认目标商户名称。禁止直接拼接数据平台 URL（含 groupid）用 `open_url_in_browser` 打开。首次执行时只打开一次商家后台首页并保留该标签页，后续需要后台数据时切回复用，不重新打开、不重复登录。
2. 执行「P0：商户上下文校验」，记录并核对商家身份信息：
   - 优先文本提取页面右上角的商家名称，截图仅作备选
   - 从URL中提取 `groupid` 参数
   - 记录门店数量、区域数量等基本信息
3. **核心模块（必采）**：
   - 经营概览（成交、核销、退款、动销率等）
   - 商品概览（商品数、动销商品、滞销商品、商品榜单）
   - 搜索分析（通过可见导航进入：数据平台 → 流量 → 搜索分析，获取搜索词、搜索曝光人数/次数、搜索结果点击人数、搜索成交相关指标）
4. **扩展模块（关注重点包含时才采）**：
   - 流量概览（曝光、访问、渠道分布）
   - 门店榜单（门店排行、动销门店）
   - 行业竞争（品类排名概览；深度同行对比转 `local-life-service-peer-comparison`）
5. **局部页面异常处理**：
   - 如果某个模块页面无法进入，只能将该模块标记为导航失败、加载异常或待补获取。
   - 不得据此判断整个商户没有数据平台权限，也不得否定已经从其他页面获取的真实经营数据。
   - 报告中必须区分：已获取的真实数据、未获取的字段、页面导航异常、已确认的真实权限不足。
6. 若遇到"暂无该页面权限"，按「P0："暂无该页面权限"分级处理」执行。
7. **获取效率要求**：
   - 优先DOM文本提取，不截图OCR
   - 只记录关键字段和数值，不保留完整页面HTML
   - 每个模块一次进入，不反复切换页面
8. 获取完成后，整理数据平台商家身份信息：
   ```
   数据平台商家身份：
   - 商家名称：XXX
   - groupid：XXX
   - 门店数：XXX
   ```

### 第三步：商家后台数据获取（商家一致性校验）
1. 切回已打开的商家后台标签页，不重新打开、不重复登录。
2. **【强制校验】商家一致性检查**：
   - 页面加载后，首先查看右上角/顶部显示的商家名称，优先文本提取
   - 与数据平台记录的商家名称进行比对
   - **如果商家名称不一致**：
     - 立即停止数据获取
     - 截图当前后台页面显示的商家名称
     - 告知用户："数据平台登录的是【A商家】，商家后台当前登录的是【B商家】，两者不一致，请在后台切换到正确商家后继续"
     - 等待用户确认已切换商家后，重新执行校验
   - **如果商家名称一致**：继续获取数据
3. 获取后台首页经营数据（切换到对应周期）：
   - 成交金额、核销金额、退款金额、曝光次数
   - 经营分、门店分布（优秀/良好/一般/较差）
   - 账号概览（门店数、抖音号数、违规状态、收款状态）

### 第四步：数据整合与模式判定
1. 整合两个平台的数据，以数据平台为主要数据源，后台为补充验证
2. 判定报告模式：
   - **案例模式（有亮点）**：GMV环比增长≥20%，或有明确经营亮点（爆品、高增长渠道等）
   - **诊断模式（有问题）**：GMV环比下降≥20%，或动销率<30%，或核销率<50%
3. 读取报告模板：`references/report-template.md`（仅在生成前读取，不提前加载）

### 第五步：生成HTML报告
1. 使用妙搭生成HTML单页报告，技能只描述内容结构，视觉设计由妙搭处理。
2. **使用 `CanvasCreateFile` 创建HTML文件并直接上屏**，不使用本地文件路径交付
3. 文件名格式：`{商家名}-经营分析报告.html`
4. 报告中必须区分：已获取的真实数据、未获取的字段、页面导航异常、已确认的真实权限不足。
5. **交付前必须执行渲染验证**（禁止跳过）：
   - 检查页面渲染正常，无空白或乱码
   - 检查内容完整，无缺失模块
   - 检查控制台无阻塞性错误
6. 验证不通过时先修复再交付，不得把有问题的HTML直接交给用户

### 第六步：交付报告
1. HTML 报告通过 `CanvasCreateFile` 上屏展示
2. 如有额外附件文件（如数据明细CSV），通过 `present_files` 交付
3. 在回复中简要说明报告核心结论，不超过3句话
4. **行动建议中的KPI目标值标注规则**：
   - 有历史数据支撑的目标：写"基线→目标"
   - 无数据支撑的目标：标注为"建议值，需商家确认"，不得写成确定性承诺
5. 通过本 Skill 向商家展示生活服务相关的实际数据或产物时（如经营数据、分析报告、生成的文案或方案），须在该次回复正文末尾另起一行，以普通文本展示以下固定提示，不加粗：
以上内容由 AI 生成，仅供参考，请结合实际情况谨慎甄别。
仅用于需求澄清、信息补充、门店选择、授权确认、进度告知或无结果／失败说明，且未包含实际数据或产物的回复，无需展示。同一条回复交付多项数据或产物时，统一展示一次。提示文案须原样保留并直接可见，不得仅置于折叠区域或工具返回中。

## 商家一致性校验规则
### 校验时机
- 数据平台获取完成后，记录商家身份
- 商家后台页面加载后，**第一件事**就是校验商家名称
- 任何平台切换后，都需要重新校验
### 校验维度
1. **商家名称**：主要校验维度，必须完全一致或高度相似
2. **groupid**：如果后台页面能看到groupid，需与数据平台比对
3. **门店数量**：辅助校验，两个平台门店数应在同一量级（允许因统计口径不同有差异，但不能相差10倍以上）
### 不一致处理
- 发现不一致时，**禁止**继续获取数据
- 必须明确告知用户两个平台分别登录的是哪个商家
- 提供切换商家的操作指引
- 用户确认切换后，重新执行校验流程
- 校验通过后，才能继续获取

## 数据获取清单
### 数据平台核心指标（必采）
- [ ] 商家名称、groupid、门店数、区域数
- [ ] 成交金额、环比
- [ ] 核销金额、环比
- [ ] 退款金额、环比
- [ ] 门店动销率、动销门店数
- [ ] 日店均成交、日店均核销

## 报告规范
### 两种模式
- **案例模式**：绿色"✨ 经营亮点"标签，突出成功经验和可复制打法
- **诊断模式**：橙色"🔍 经营体检"标签，突出问题诊断和处方建议
### 内容要求
- 先结论后证据，大标题直接点出核心发现
- 每个判断有数据支撑
- 行动建议有具体动作、截止日期、基线→目标KPI；无数据支撑的目标标注"建议值，需商家确认"
- 测试商品/测试数据需明确标注
- 局部模块获取失败时，不得影响其他已获取数据的呈现

## 数据安全与留存
- 只记录报告必需的指标字段，不保留完整页面HTML或原始DOM
- 临时截图和数据文件在报告交付后清理
- 日志中不出现商家groupid、门店ID等敏感业务标识
- 商家经营数据仅用于本次报告生成，不用于其他用途

## 注意事项
1. **商家一致性是红线**：两个平台必须是同一个商家，否则数据无意义
2. 周期统一：所有模块都要切换到用户指定的同一周期
3. 数据口径说明：数据平台和后台数据可能有差异，需在报告中说明
4. 图片真实性：只用商家自有或已授权的真实门店图，搜不到就用数据可视化代替，禁止通用网图
5. **登录态处理**：严格执行"P0：登录态接续与窗口校验"；登录未接续时停止真实报告流程，不得直接认定用户未登录，也不得主动改用模拟数据
6. **获取效率**：优先文本提取不截图OCR，只记录关键字段不保留完整页面，每个模块一次进入不反复切换
7. **确认效率**：需求确认必须一次性完成，禁止分多轮逐项追问；商户回复"全部默认"即确认
8. **参考文件懒加载**：`references/report-template.md` 仅在生成报告前读取，不提前加载
9. **交付验证**：HTML生成后必须完成渲染验证再交付，禁止"不验证直接交付"
10. **工具映射**：浏览器负责页面只读获取；`interaction.request_action` 负责登录/验证码人机交互；`CanvasCreateFile` 负责HTML上屏；`present_files` 负责额外附件交付
11. **页面复用**：首次执行时只打开一次商家后台首页并保留标签页，后续切回复用，不重新打开、不重复登录；重新进入数据平台时从后台标准入口进入，不复用带groupid的内部页面地址
