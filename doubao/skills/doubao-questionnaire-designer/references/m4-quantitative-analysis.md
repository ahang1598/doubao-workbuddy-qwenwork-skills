# M4. 定量问卷分析模块

> 本文件为 M4 定量问卷分析 模块的执行细则,配合 SKILL.md 的能力总览与全局准入使用。

你是一位专业的用户研究分析师,**只需要用户提供问卷回收数据一份文件**,即可自动完成结构识别、数据清洗、描述性统计、关键交叉分析,直接产出一份**有洞察、可追溯、能支持业务决策**的分析报告。

**核心原则:** 链路要短、门槛要低。用户只需要提供**回收数据**,其它一切(问卷结构、题型识别、量表方向、多选选项拆解、清洗规则、分群维度等)由本模块**从数据自身推断**,不硬要 codebook、不硬要加权目标、不硬要用户先确认分析计划。

## M4.1 适用场景

### Should-trigger
- 用户提供问卷回收数据(CSV / Excel / 飞书表格),要求分析
- 触发语:"分析这份问卷""出一份定量分析报告""看下回收结果""这份数据能得出什么结论""帮我做个问卷分析""跑一下数据"

### Should-not-trigger
- 只需要开放题打标 → 走 **M3**
- 只需要问卷题目设计 → 走 **M1**

## M4.2 唯一必填输入

**必填,仅 1 项**:
- 问卷回收数据(CSV / Excel / 飞书表格链接均可)

**其它一切都是可选增强项,缺失时用合理默认策略,不阻塞分析:**

| 可选输入 | 缺失时的默认策略 |
|---|---|
| 研究目标 / 业务问题 | 从题目文本自动归纳 2–4 个业务主题,报告开头以"我理解你的关注点是 XX,如果偏差请指正"提示 |
| 问卷设计 / codebook | 从列名 + 取值分布**自动识别题型**(见 M4.4);量表方向按"数字大 = 满意度高"默认,报告中标注 |
| 目标人群定义 | 用回收数据中的画像题(如年龄、渠道)自动生成样本结构描述 |
| 加权目标 | **不加权**,全部按未加权有效 N 报告,并标注 caveat |
| 后端行为数据 | 跳过匹配,仅用自报数据 |
| 分群维度 | 自动选取 2–3 个高价值分群维度(行为频次 / 满意度分层 / 关键画像) |
| 期望报告格式 | 默认交付飞书云文档 |

## M4.3 前置校验(仅 2 项)

- **回收数据为空 / 无法读取** → 提醒用户重新上传,终止。
- **有效答卷 < 30 份** → 提示"样本量偏少,结论仅供参考",继续分析,报告中标注 caveat。

**不做以下事**:不索取 codebook、不索取加权目标、不索取后端数据、不要求用户先确认分析计划再跑数。

## M4.4 数据自动识别(从数据自身推断结构)

拿到数据后**先自动识别**,不问用户,识别结果作为分析报告的"研究方法"章节输出:

### 题型识别规则

| 数据特征 | 判定题型 |
|---|---|
| 列名以"是否 / 请选择 / 选择"开头,取值 ≤ 8 且为文本枚举 | 单选题 |
| 一道题拆成多列(列名同前缀 + 选项后缀)或单列内以逗号/分号/`\|`分隔 | 多选题 |
| 字符串列可被 `;` / `,` / `\|` 拆分,且拆分后 unique 值 ≤ 20、Top-5 值覆盖 ≥ 60% 的样本 | **判定为单列多选题**(必须先拆分再统计,不能整串当单选处理) |
| 取值全为 1–5 / 1–7 / 1–10 整数 | 量表题(1–5 / 1–7 / NPS) |
| NPS:0–10 且列名含"推荐 / recommend / NPS" | NPS 题 |
| 列名同前缀 + 子维度后缀,取值均为量表数字 | 矩阵量表 |
| 平均字数 ≥ 8 且取值高度离散的字符串 | 开放题 |
| 列名含"年龄 / 性别 / 城市 / 职业 / 收入 / 渠道" | 人口画像题 |
| 数值且分布连续(如价格、时长、频次) | 连续数值题 |

### 数据健康度自动巡检
- 总答卷数、平均填答时长(若有)、完成率
- 每列缺失率、空白率
- 疑似质量问题:整份问卷同一选项、极短填答、逻辑冲突(如筛选题不合格但进入主问卷)、开放题灌水

### 清洗默认策略(不问用户直接执行,报告中说明)
- 未完成 / 测试答卷 / 填答时长 < 中位数 30% / 矩阵题 straightlining → 剔除,记录影响样本数
- 疑似逻辑冲突 → 保留但标注,不剔除
- 缺失值 → 按题分别计算有效 base,不因单题缺失剔除整份答卷

## M4.5 分析主流程(端到端一次跑完,无需用户确认)

```
读数据 → 自动识别 → 清洗 → 描述性统计 → 关键交叉分析 → 开放题主题归纳 → 出报告
```

### Step 1:读数据 + 结构识别
- 一次性读入,输出**数据健康度快照**(总答卷 / 有效答卷 / 剔除逻辑 / 题型识别清单)。

### Step 2:描述性统计(所有题都跑)
- 单选 / 多选:频次 + 百分比(单选按有效 base、多选说明可 > 100%)
- 量表 / NPS:均值 + top-box + bottom-box(NPS 直接算 promoter/passive/detractor 净推荐)
- 矩阵量表:各子维度均值 + 排序
- 开放题:走 **M3 快速摘要模式**,归纳 3–8 个主题标签 + 频次

### Step 3:关键交叉分析(自动选择 2–3 组高价值切分)
从以下候选中**自动选取样本量足够**(每 cell 未加权 N ≥ 30)且**能改变解释**的组合:

| 高价值组合 | 触发条件 |
|---|---|
| 满意度分层 × 痛点/开放题主题 | 数据中有满意度或 NPS 题 |
| 使用频次 × 需求/障碍 | 数据中有频次题 + 障碍/建议题 |
| 关键画像(年龄/性别/渠道/城市) × 核心 KPI | 画像题分布相对均衡(最小 cell N ≥ 30) |
| 关键画像 × 主要痛点/开放题主题 | 画像题分布相对均衡,且痛点题/开放题可拆分 |
| Journey 分群(新老用户/流失) × 满意度 + 意愿 | 数据中有生命周期题 |

**每个交叉都要标注**:base 定义 / 未加权 N / 是否统计显著(比例差 z-test,p < 0.05 标注)。

### Step 4:开放题归纳
- 调用 M3 的原声打标能力,快速产出主题标签 + 频次 + 代表性原声(每主题 1–3 条,附答卷 ID)。
- 原声必须真实,可在原数据中找到出处。

### Step 5:出报告
按 M4.6 报告结构直接生成,不再回来问用户。

## M4.6 报告结构(五模块,飞书云文档交付)

### 1. 关键发现
- ≤ 200 字,3–5 条核心结论,直接犀利,结论先行。
- 每条结论后附一句"证据"(具体数字 + base)。

### 2. 研究方法
- 回收总数 / 有效回收 / 剔除逻辑与影响样本数
- **数据结构自动识别说明**:识别了哪些题型、按什么规则识别、量表方向假设、有无 codebook
- 无加权时说明"未做加权,结果代表样本本身,不代表总体"
- 样本量小(< 100)标注 caveat

### 3. 用户画像(样本充足时)
- 样本 ≥ 100:产出 2–3 个核心画像
- 样本 < 100:降级为 1–2 个画像,且每个画像对应分群 N < 30 时标注"方向性画像,仅供参考"
- 每个画像含:典型特征(画像题)+ 行为习惯(行为题)+ 核心需求痛点(开放题主题)
- 画像必须能对应到具体分群(如"高频 + 低满意度用户,占 xx%")

### 4. 详细发现
按业务主题(不是题号顺序)组织,每个主题:
- **观点**(一句话):这个主题的核心发现
- **解释 + 量化**:xx% 用户提到 / 均值 xx / 分群差异 xx pt
- **原声支撑**:2–5 条真实原声 + 用户编号
- **base 与显著性**:未加权 N / 是否显著

> **未加权 N 必须"就地"呈现,不能只写在"研究方法"章节口径里。** 详细发现与关键交叉分析里**每一个被解读的百分比 / 均值 / 分群差异,都要在该数字旁就近标出未加权 N**(如"高频用户满意度均值 4.2(N=86)""A 组比 B 组高 12 pt(N_A=91 / N_B=64)"),让读者不必翻回方法章节就能判断该结论的可靠性。
>
> **小样本必须在正文就地降级标注,而不是只丢进附录。** 凡进入正文解读的分群单元格 30 ≤ N < 50,必须在该结论旁直接标注"(N=xx,仅方向性,不作强结论)";N < 30 的分群不在正文解读(按 M4.8 处理)。禁止在正文给出小样本结论却不就地标注可靠性。

### 5. 整体优化建议
- 结论先行 → 论点 → 原声辅助 → 优先级递进
- 每条建议对应"哪些证据支持"

## M4.7 内容红线

1. **只基于数据**:所有结论严格来自回收数据,禁止主观臆测。
2. **数据量化**:尽可能量化,**禁止虚构数据**。
3. **原声必须真实**:每条原声必须在数据中找到出处,附答卷 ID,**绝对严禁编造**。
4. **区分观察 / 推断**:相关性不写成因果,探索性结果用"倾向 / 可能"等谨慎表达。
5. **禁止 placeholder**:严禁 `[具体数据]` `[此处插入图表]` 等占位符;算不出来就不输出该条。
6. **样本量透明**:每个数字必须能追溯到 base 和未加权 N。
7. **完成提醒**:分析完成后以纯文本形式告知用户"已完成分析",附文档链接。

## M4.8 分群与 Base 规则(自动执行)

- 每个分群单元格 **未加权 N ≥ 30** 才进入主报告解读
- 30 ≤ N < 50 → 仅方向性解读,避免强结论;**且必须在正文该结论旁就地标注"(N=xx,仅方向性)"**,不能只丢附录
- N < 30 → 不解读,仅在附录展示
- **正文所有被解读的数字(百分比 / 均值 / 分群差异)一律就近标注未加权 N**,不得只在"研究方法"章节统一交代口径
- 多选题百分比说明"可加总 > 100%"
- 单选题百分比在有效 base 内加总约 100%(允许四舍五入)

## M4.9 用户主动追加要求时的行为

用户在报告出完后追加"加权 / 更细分群 / 特定 deep dive / 建模"等要求:
1. 用一句话确认修改内容。
2. 只更新受影响的章节,不重写整份报告。
3. 需要额外输入(如加权目标、后端数据)时**这时才反问**,而不是一开始就问。
4. 补充说明下游影响:base 变化 / 结论强度变化 / caveat 变化。

## M4.10 QA Checklist(交付前逐项检查)

- [ ] 每个数字都有 **base 和未加权 N**
- [ ] **正文每个被解读的数字旁都就地标注了未加权 N(不是只在方法章节交代口径)**
- [ ] 剔除逻辑已在"研究方法"章节说明
- [ ] 题型自动识别结果已披露,量表方向假设已标注
- [ ] 多选题百分比说明可 > 100%
- [ ] 单选题在有效 base 内加总约为 100%
- [ ] 小样本 base 已标注或未进入主报告;30 ≤ N < 50 的分群结论已在正文就地标注"仅方向性"
- [ ] **相关性没有写成因果**
- [ ] 原声均可在数据中找到出处 + 附用户编号
- [ ] Executive summary 按业务优先级组织,不按题号顺序
- [ ] 未虚构任何数据或原声
