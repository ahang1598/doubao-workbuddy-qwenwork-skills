# M3. 开放题原声打标模块

> 本文件为 M3 开放题原声打标 模块的执行细则,配合 SKILL.md 的能力总览与全局准入使用。

帮助用户基于问卷开放题原声(verbatim),通过严谨的五步流程从零构建标签体系并完成全量批量标注。

**核心价值**:不拍脑袋、不一次定稿、不只给标签名——从原声中"长出"标签,通过两轮原声 + 质检迭代收敛,给出完整的定义、边界、示例。

## M3.1 适用场景

### Should-trigger
- 用户有一批问卷开放题原声需归类/编码/打标
- 从零构建文本标签体系
- 对已有标签体系做质检或优化
- VOC 分析、用户研究、产品反馈、客服工单分类
- 触发语:"帮我分析这些开放题""对这些反馈打标""帮我做编码"

### Should-not-trigger
- 结构化数据(数字评分、选择题)—— 不需要文本分类
- 只需情感分析(正/负/中)—— 无需主题标签体系
- 已有完整标签体系且只需执行标注 —— 可直接跳到 Step 5
- 需 NLP 模型训练 / 深度学习分类器
- 原声语言非中文且用户未说明 —— 先确认语言

## M3.2 输入(分阶段收集)

| 阶段 | 需要的输入 | 格式 |
|---|---|---|
| Step 1 | 题目问法 + 研究目的 + **首批约 100 条**原声 | 文本列表 / Excel / CSV / 飞书表格链接 |
| Step 4 | 第二批约 100 条**新**原声 | 同上 |
| Step 5 | 全部原声(含前两批) | 同上 |

**数据量守门**:
- 首批 < 30 条 → 提示样本量偏少,建议补到 80–100 条。
- 首批 < 15 条 → **拒绝建标签**,要求补充数据。

## M3.3 五步工作流

### Step 1:收集题目与首批原声
1. 索取:题目问法 + 研究目的 + 首批 ~100 条原声。
2. 数据概览:总条数 / 平均长度 / 空白无效占比 / 高频关键词 TOP 10。
3. 展示概览,确认数据无误后进入 Step 2。

### Step 2:基于首批原声建立标签体系
1. 逐条阅读,提取核心语义。
2. 按语义聚类形成一级标签;判断是否需要二级/三级。
3. 为每个标签写完整定义卡片:**标签名 / 定义 / 适用条件 / 不适用边界 / 2–3 条示例原声**。
4. 对所有原声做初步归类,生成分布统计。
5. **必设"无意义表达"标签**,下设两个二级:
   - 无信息量表达:无、没有、不知道、随便、哈哈哈、111、???、空白、纯表情、乱码等
   - 答非所问:与题目问法明显不相关的表达

### Step 3:抽检标签质量
1. 每个标签抽取最多 10 条(不足则全量)。
2. 逐条判定是否确实属于该标签,记录正确/错误。
3. 计算准确率,分析误标模式。
4. 输出抽检报告:

| 抽检准确率 | 判定 | 行动 |
|---|---|---|
| ≥ 90% | 良好 | 保持,微调定义即可 |
| 70%–89% | 需优化 | 补充边界说明或拆分/合并 |
| < 70% | 严重问题 | 必须重新定义或重组 |

抽检报告必须**可解释**:哪条被误标、为什么、建议怎么改。

### Step 4:第二批原声试标与优化
索取第二批约 100 条新原声,用当前体系试标,检查五个维度:
- **覆盖度**:是否大量原声无法归入现有标签?
- **新主题**:是否出现全新主题需要新增标签?
- **混淆度**:是否有多个标签定义模糊导致标注犹豫?
- **颗粒度**:是否过粗需拆分或过细需合并?
- **分布**:新原声分布是否与首批差异很大(样本可能有偏)?

输出**变更说明**(保持不变 / 新增 / 合并 / 拆分 / 重命名补定义 / 删除,每项附理由)。

### Step 5:全量标注
1. 索取全部原声。
2. 逐条标注:每条**一个主标签**,可加 1–2 个次标签;无意义表达直接标为对应二级。
3. 标注理由用一句话说明,不写长文。
4. **大批量策略**:>200 条分批(每批 100–150)、>500 条先输出前 200 条抽检后再继续。
5. 输出优先飞书电子表格;否则 Markdown 表格 / JSON。

## M3.4 关键原则

### 颗粒度判断
- 跟着原声走,不跟着假设走。
- 大量原声聚集同一细分话题(如 50/15 都在说加载速度慢)→ 值得单独设标签。
- 只有 1–2 条提到 → 不单独设,归入上级。
- **例外**:低频高严重性(安全、资金损失)保留独立标签。

### 层级硬性约束
- 总样本 < 100 时,**禁止**三级标签。
- 某二级下原声 < 10 条时,**禁止**在其下拆三级。
- 一级标签建议 5–12 个,超 15 需收敛。

### 多主题原声
选**最核心诉求**为主标签(篇幅最多 / 语气最强 / 最靠前的);次要主题作次标签,最多 2 个。

### 模糊表达
1. 优先结合题目问法推断意图。
2. 推断后仍无法确定 → 标注为最接近的标签 + 备注"模糊,需人工复核"。
3. **绝不随机分配**。

### 无意义表达边界
- "没有什么建议" → 无信息量表达
- "没有遇到过这个问题" → **不是**无意义(应归入实质标签或"未遇到")
- "还好吧" → 无信息量表达
- "还好,就是有时候有点卡" → **不是**无意义("有时候有点卡"是有效信息)
- 全量标注若无意义占比 > 30%,提醒用户题目设计可能需优化。

## M3.5 输出模板

### 标签体系(每个标签)
```
### 一级标签:[标签名]
**定义**:[一句话]
**适用条件**:[什么原声应打这个标签]
**排除边界**:[什么原声不该打]
**示例原声**:
- "..."
- "..."
```

### 全量标注表格(优先)

| id | 原声文本 | 主标签(一级) | 主标签(二级) | 次标签1 | 次标签2 | 是否无意义 | 判定理由 | 备注 |
|---|---|---|---|---|---|---|---|---|

### 标注统计
- 总标注 / 有效原声 / 无意义占比
- **一级标签分布表**:各一级标签的频次 + 占比(按频次降序)
- **二级标签分布统计**(有二级标签时必出):在每个一级标签下,列出其各二级标签的频次 + 占比(占比可选用"占该一级"或"占总有效"两种口径,标明用哪种),让用户看清一级内部是如何分布的,不能只给一级汇总数
- 多标签统计(仅主 / 主+1 / 主+2)

> 二级分布是分层解读的关键:若某一级下二级高度集中在一两个子标签,应在统计下用一句话点出(如"'加载慢'一级中 78% 集中在'首屏加载'子标签")。仅有一级、无二级拆分时,注明"本体系未设二级标签,故无二级分布"即可。

## M3.6 护栏
- 一级标签 > 15 → 主动收敛。
- 二级标签总数 > 40 → 建议提升一级合并。
- 出现三级但总样本 < 100 → 收回至二级。
- 标签定义交叉 → 列出重叠原声 → 提两个方案(合并 / 重新划界)由用户决定。
- 研究目的不清晰 → 反问:关注"用户有哪些不满"(问题归因)还是"用户想要什么"(需求方向)?
