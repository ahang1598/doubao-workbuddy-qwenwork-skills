# 综合与图表规范

本文件用于决定“如何把文献变成证据逻辑、研究脉络和专业可视化”。证据节点必须来自已纳入证据或已说明的综合主题，不得凭空生成。图表方法参考 `standard-feishu-diagram` 的图型选择与可编辑飞书白板实践：https://github.com/Hanny-YANG/standard-feishu-diagram 。思维导图采用标准 Mermaid `mindmap`、`root((...))` 与缩进分支语法；为提高飞书解析稳定性，不在生产模板中使用 HTML 换行、图标或复杂自定义样式。

`audience_mode=patient` 时，图表以“证据类型、代表文献、主要结论和证据边界”为主；除非用户明确询问，不生成研究方向、课题机会或证据空白分支。

## 触发规则

图表服务于用户问题，不是少量文献报告的必填装饰。相关文献不足 5 篇，且用户已指定输出结构、问题范围很窄或更需要少数核心文献深入解读时，可不生成白板图。除医学资讯跟踪在图表不能增加信息时可省略外，纳入正文或参考文献的相关文献达到 5 篇及以上时，除非用户明确要求不要图表，必须同时生成证据脉络思维导图和关键研究里程碑时间线图；用户有指定核心交付物时，应把两张图放在该内容之后的标准证据章节中。

文献不足 5 篇时，满足以下条件之一通常提供图表：

- 核心纳入证据达到 3-4 条，且证据类型、结论或发展阶段具有清晰层级。
- 用户要求研究热点、前沿进展、课题设计、论文写作、教学材料或汇报。
- 存在多条指南、多个治疗/诊断/研究方向或多个研究类型。
- 文献结论不一致、指南更新与旧实践存在张力、证据不足或研究空白明显。
- 用户需要展示研究脉络、证据分层或里程碑演进的正式材料。

采用默认完整骨架且图表有助于表达时，可在“证据脉络与研究关系”附近放置以下精简可视化组：

1. `证据脉络思维导图`：用 Mermaid `mindmap` 以研究主题或核心科学问题为根，按指南/共识、系统综述、关键原始研究、最新进展和争议/空白组织证据层级。
2. `关键研究里程碑时间线图`：按年份或研究阶段横向排列里程碑，并在时间节点下方纵向列出研究/指南/综述/监管节点；年份多时必须合并为时间段，避免一堆年份各只挂一篇文献。

证据脉络思维导图和时间线图是默认完整骨架的主图，并非所有任务的完成条件。决定绘图后，直接从 CSV 读取按行顺序生成的 `citation_number`，整理本图节点清单：`citation_number | short_name | evidence_role`。两张主图使用这份清单生成文献节点，标签先拼接再写入 Mermaid：`[citation_number] short_name`。mindmap 使用稳定节点 ID 包裹可见标签，例如 `ref1["[1] DAPA-CKD"]`。同一文献在图、图例、正文和参考文献中复用同一编号；不得显示内部 `evidence_id`，也不得使用 `G1`、`R1`、`SR1` 等类型前缀号。

不要为了满足默认图组而给少量、同质证据强行绘图。文献达到 5 篇但自然年份序列不明显时，时间线可按研究阶段、指南迭代或证据发展阶段组织；相关文献不足 5 篇、用户明确拒绝图表，或医学资讯跟踪中图表不能增加信息而省略时，应通过清晰的表格、短列表或按日期/主题整理呈现证据关系。

## 飞书标准图型取舍

默认只把以下内容做成图：

| 需求 | 首选表达 | 说明 |
|---|---|---|
| 领域如何演进 | 关键研究里程碑时间线图 | 标准时间线；年份多时合并阶段 |
| 文献/机制如何构成证据脉络 | 证据脉络思维导图 | Mermaid `mindmap` 白板；以主题为根，用层级分支组织证据类型与核心观点 |

其它内容默认不画复杂图，改为正文段落或必要的标准表格：

| 需求 | 首选表达 |
|---|---|
| 核心研究怎么解读 | 每篇核心文献一个小节 |
| 指南推荐有何差异 | 逐份指南/共识段落解读，必要时补指南对比表 |
| 热点方向有哪些 | 逐主题段落，必要时补热点主题表 |
| 证据为何冲突 | 争议矩阵表 |
| 还缺哪些研究 | 研究空白表 |
| 论文哪句话引用哪篇文献 | 引用逻辑解读，必要时补对照表 |
| 学习材料怎么组织 | 学习路径段落或知识框架，必要时补简表 |

只有在用户明确要求“画图”、或内容天然属于飞书标准图型（流程图、决策树、时间线、矩阵、思维导图等）且能稳定显示时，才额外生成图。额外图必须说明图型选择理由，并保持节点少、标签短、图例完整。

默认组合：

- 主题循证综述：`证据脉络思维导图 + 关键研究里程碑时间线图 + 系统综述/关键研究逐篇解读`。
- 指南查新：`证据脉络思维导图 + 关键研究里程碑时间线图 + 指南/共识逐份解读`；只有多份指南需要横向比较时再补指南对比表。
- 热点/前沿：`证据脉络思维导图 + 关键研究里程碑时间线图 + 逐主题进展/争议/空白解读`；只有用户要求图形化热点时再补主题簇图。
- 课题论证：`证据脉络思维导图 + 研究空白解读 + 可行研究问题建议`；必要时补简表。
- 论文写作：`引用逻辑解读 + 参考文献用途建议`；必要时补引用对照表，不默认做额外白板图。
- 学习资料：`知识框架 + 学习路径建议`；必要时补简表，不默认画复杂知识图谱。

## 图表选择

| 表达 | 回答的问题 | 适用任务 | 默认形式 |
|---|---|---|
| 关键研究里程碑时间线图 | 领域证据如何演进，哪些研究是里程碑，最新研究改变了什么 | 所有文档类产物、热点分析、指南查新 | 飞书标准图 |
| 证据脉络思维导图 | 关键指南、综述、原始研究和最新进展如何围绕主题形成层级脉络 | 所有文档类产物、课题论证、学习资料 | Mermaid `mindmap` 白板 |
| 关键研究逐篇解读 | 哪些研究最值得读，它们各自贡献、局限和引用用途是什么 | 所有文档类产物、论文写作、课题论证 | 正文小节 |
| 指南差异解读/可选对比表 | 不同指南推荐是否一致，推荐强度和适用人群如何不同 | 指南查新、临床实践学习 | 正文小节，必要时表格 |
| 热点主题解读 | 文献集中在哪些方向，近年有哪些新主题 | 研究热点、课题论证 | 正文段落，必要时表格 |
| 争议矩阵 | 证据为何不一致，争议来自人群、干预、终点还是研究质量 | 课题设计、讨论章节 | 表格 |
| 研究空白表 | 哪些人群、终点、场景、方法或随访证据不足 | 课题论证、基金/论文选题 | 表格 |
| 引用逻辑解读/可选对照表 | 每组文献支撑论文哪个论点或段落 | 论文写作支持 | 正文建议，必要时表格 |
| 学习路径解读/可选简表 | 先学什么指南、再读哪些经典研究、最后看哪些前沿 | 进阶学习资料 | 正文小节，必要时表格 |

不要把所有内容塞进一张图。根节点以下固定使用三级：一级为证据分类，二级为带编号的具体文献，三级为该文献产生的核心结论、增量信息、限制或研究启示。通常使用 4-6 个一级分类，每类放 1-3 条代表文献；文献过多时只保留代表证据，其余放正文和参考文献。

## 可选证据地图

证据地图回答：“本次结论由哪些证据构成，各证据的强弱和作用是什么？”

证据地图不作为默认额外白板图。若证据脉络思维导图已经覆盖证据来源与结论，优先用逐篇解读或简要证据表承载证据地图信息；只有用户明确要求证据地图，或需要展示多类证据共同支持/限制多个结论时，才额外生成标准关系图。

必须包含：

- 中心节点：用户问题或主题。
- 证据节点：已纳入的文献，使用 CSV `citation_number` 和可读指南/研究简称，如 `[1] DAPA-CKD`。
- 结论节点：`相对确定`、`倾向支持`、`存在争议`、`证据不足`、`不支持` 或任务化结论。
- 连线标签：`指南推荐`、`系统综述支持`、`RCT 支持`、`观察性补充`、`安全限制`、`证据冲突`、`研究空白`。
- 图例表：列出 CSV `citation_number` 渲染的引用序号、标题、链接、来源/期刊、年份和来源级别。
- 证据节点按质量、权威性、匹配度和时效性区分核心或辅助角色，不在图中展示阅读状态。

证据地图不能只画“文献 A -> 文献 B -> 结论”的链条；必须表达证据角色。

## 证据脉络思维导图

证据脉络思维导图回答：“围绕当前主题，指南、综述、关键研究和最新进展分别提供了什么证据，争议与空白在哪里？”

必须包含：

- 根节点：中心主题或核心科学问题。
- 4-6 个一级分支：按任务从指南/共识、系统综述、关键原始研究、最新进展、安全/监管、机制证据和争议/空白中选择。
- 二级文献节点：用 `ref1["[1] 文献简称"]` 这类稳定语法呈现可见编号与简称。
- 三级结论节点：每条二级文献至少有一个下级短节点，概括该文献产生的核心结论、增量信息、限制或研究启示；分类和结论节点不编号。
- 图例表：引用序号、标题、链接、来源/期刊、年份、类型、用途；编号与图中节点一致。

优先使用 Mermaid `mindmap` 的中心主题与放射状层级，根节点以下严格保持“分类 -> 文献 -> 结论”三级。每篇文献只放在最相关的一个分类；若一篇文献横跨多个主题，在正文说明交叉作用，不复制图中节点。mindmap 使用 Mermaid 自动布局和分支配色，不添加 `classDef`、手工连线、HTML、图标或复杂样式。

节点标签格式：

- 文献节点：必须写为 `[1] DAPA-CKD`、`[2] KDIGO 2024`、`[3] Cochrane 2023`。
- 概念节点：`Wnt/beta-catenin 通路`、`免疫微环境`、`诊断性能`。
- 结果节点：`复发风险下降`、`骨破坏加重`、`研究空白`。

禁止只按年份堆文献；年份演进由 2.2 时间线负责。思维导图按证据角色和研究主题组织。

Mermaid 白板模板：

```xml
<whiteboard type="mermaid">
mindmap
  root(({{研究主题或核心科学问题}}))
    指南与共识
      ref1["[{{citation_number_1}}] {{short_name_1}}"]
        {{推荐方向或标准}}
    系统综述
      ref2["[{{citation_number_2}}] {{short_name_2}}"]
        {{汇总结论}}
    关键原始研究
      ref3["[{{citation_number_3}}] {{short_name_3}}"]
        {{核心发现}}
      ref4["[{{citation_number_4}}] {{short_name_4}}"]
        {{补充或限制}}
    最新进展
      ref5["[{{citation_number_5}}] {{short_name_5}}"]
        {{增量信息}}
    争议与空白
      {{主要争议}}
      {{待研究问题}}
</whiteboard>
```

## 关键研究里程碑时间线图

关键研究里程碑时间线图用于里程碑和最新进展，优先做成类似“上方年份/阶段色块 + 中间横向时间轴 + 下方按时间节点纵向排列研究卡片”的标准时间线，而不是阶段演进流程图或只有表格：

- 按年份或研究阶段排列关键指南、经典研究、重要综述、监管事件和最新研究。
- 若总年份节点超过 7 个、年份跨度超过 8-10 年，或多个年份各只有 1 篇文献，优先把相邻年份合并为时间段/阶段节点；若 5-7 个年份节点每个都能挂 2 条以上代表证据，可以保留单年节点以形成清晰横向年份轴。常用分组如 `早期基础研究`、`机制验证阶段`、`关键临床研究阶段`、`指南更新阶段`、`近 5 年最新进展`。
- 每个时间段下方尽量纵向列出 2-5 个代表节点；只有真正改变指南、监管、安全警示或研究范式的事件，才保留为单一年份节点。
- 文献节点文本必须包含连续编号和可读研究简称，写为 `[1] DAPA-CKD`、`[2] ESC 2025`；年份或研究阶段节点不编号。
- 标记每个节点的意义：`奠定标准`、`改变指南`、`扩展人群`、`提出争议`、`安全警示`、`最新进展`。
- 经典里程碑不受年份限制；最新进展默认近 1-5 年。
- 不要把普通低质量研究放成里程碑。
- 反模式：`2020 -> 2021 -> 2022 -> 2023 -> 2024 -> 2025` 且每个年份只挂 1 篇文献。应改为 `2020-2022 机制与观察性证据`、`2023-2024 系统综述与关键研究`、`2025 最新指南/进展` 等阶段节点。
- 反模式：用 `flowchart LR` 画成“2021 基础证据 -> 2022 核心综述 -> 2023 负担数据 -> 2024-2025 指南更新”并把文献节点散在右侧或斜向连线。这会变成流程/关系图，不是里程碑时间线。`flowchart LR` 只作为 Mermaid `timeline` 不可用时的兜底，而且必须保持横向年份/阶段轴和每个时间节点下方的纵向文献卡片列。

时间线节点必须能在正文或参考文献表中反查到来源，或明确标注为教材/背景节点。

推荐视觉结构：

- 上方是标题，如 `{{主题}}关键研究里程碑（{{起止年份}}）`。
- 中间是横向时间轴，年份或时间段节点横向排列；若使用原生形状或 PPT，年份/阶段节点做成彩色短条，横轴贯穿所有节点。
- 每个年份/阶段下方是纵向研究卡片列；每张文献卡片第一行必须写 `[1] 研究简称`，第二行写核心贡献。年份多时同一时间段下要放多张代表研究卡片，而不是拆成很多单文献年份。
- 图下必须有图例表，列出与节点一致的引用序号、研究简称、完整标题、链接、年份/时间段、来源/期刊和意义。

Mermaid 白板模板：

```xml
<whiteboard type="mermaid">
timeline
    title {{主题}}关键研究里程碑（{{起止年份}}）
    {{stage_1}} : [{{citation_number_1}}] {{short_name_1}}：{{contribution_1}}
                : [{{citation_number_2}}] {{short_name_2}}：{{contribution_2}}
    {{stage_2}} : [{{citation_number_3}}] {{short_name_3}}：{{contribution_3}}
                : [{{citation_number_4}}] {{short_name_4}}：{{contribution_4}}
    {{stage_3}} : [{{citation_number_5}}] {{short_name_5}}：{{contribution_5}}
                : [{{citation_number_6}}] {{short_name_6}}：{{contribution_6}}
    {{stage_4}} : [{{citation_number_7}}] {{short_name_7}}：{{contribution_7}}
                : [{{citation_number_8}}] {{short_name_8}}：{{contribution_8}}
</whiteboard>
```

## 关键研究逐篇解读

关键研究逐篇解读回答：“哪些研究最值得读，它们各自贡献了什么，应该如何引用？”默认用正文小节，不再把所有研究压成一张大表，也不额外做白板图。

推荐小节结构；每篇系统综述和关键研究都必须明确写出期刊名称和发表年份，不能只写研究简称、数据库或类型：

- 小节标题：使用 CSV `citation_number` 渲染的 `[n]` 加可点击研究简称或完整题名。
- 类型与来源：写清系统综述、Meta、RCT、队列、诊断研究或机制研究，并明确标注期刊名称和发表年份。
- 研究设计与对象：用 1-2 句说明人群、样本、干预/暴露、对照和主要结局。
- 主要结论：解释这篇文献对用户问题的实际贡献。
- 局限与适用边界：说明人群、方法、随访、终点或证据等级限制。
- 引用用途：说明适合放在背景、指南依据、机制解释、结果比较、争议或研究空白哪个位置。

若用户明确要求横向比较，或论文写作需要快速比较多个研究，可在逐篇解读后补一个简短比较表；表中的研究标题仍必须有链接。

## 其他相关研究

本节用于快速筛选已经进入文末参考文献、但未在“系统综述与关键研究”中详细解读的其余相关研究。不要重复第四章已经逐篇展开的文献，也不要使用表格。

- 每篇使用一个无序列表项，固定以 `[n] [可点击标题](URL)（期刊，年份；类型）` 开头；`n` 来自同一行 CSV `citation_number`，随后用 4-6 句话总结研究核心内容和主要结论。
- 标题必须可点击；期刊名称、年份和研究类型不得省略。
- 总结应帮助用户快速理解研究做了什么、主要对象或方法是什么、得出了哪些与主题相关的核心结论，以及必要的适用边界；保持为一个连贯段落，并明显短于第四章的核心研究逐篇解读。
- 本节列出的研究必须能在文末“完整参考文献（含链接）”中找到同一标题和链接；文末属于研究论文、且没有在其他正文证据章节得到实质解读的条目，都必须在这里列出，方便快速筛选。

## 热点主题表

热点分析默认用逐主题段落解读，而不是复杂白板图或大表。只有用户明确要求图形化热点，且主题数量少、可稳定显示时，才补充主题簇图；只有需要横向比较主题时才补充热点主题表。

若没有完整文献计量数据库，只能写：

`本热点归纳基于本次检索纳入文献的标题、摘要和关键词归纳，不等同于完整 bibliometric 共现分析。`

主题簇建议维度：

- 机制/病理生理。
- 诊断/预测模型/生物标志物。
- 药物/干预/手术或管理策略。
- 特殊人群。
- 真实世界与长期结局。
- 安全性与不良事件。
- 指南实施与实践差距。
- 数字医疗、AI 或新技术。

必要时使用以下字段做简表：

| 主题簇 | 代表证据 | 近年变化 | 证据强度 | 研究空白 |
|---|---|---|---|---|

每个主题簇至少给出 1-3 条代表文献或说明“证据不足”。

## 指南差异解读或可选对比表

指南查新或学习材料默认先逐份解读指南/共识；只有确实需要横向比较多份指南差异时，才补充以下对比表：

| 维度 | 填写内容 |
|---|---|
| 指南/机构/年份 | 必须带链接 |
| 适用人群 | 年龄、疾病阶段、特殊人群 |
| 核心推荐 | 推荐条文的准确概括 |
| 推荐强度/证据等级 | 原文报告则填写；没有写 `未报告` |
| 与其他指南差异 | 推荐方向、阈值、药物/检查顺序、证据解释差异 |
| 更新点 | 与旧版或旧实践相比的新变化 |
| 实践影响 | 对学习、课题、论文或临床实践的意义 |

不要把不同年份或不同疾病范围的指南混为同一推荐；不要把这张表作为“指南与专家共识”章节的默认结构。

## 争议矩阵

当证据不一致时，用争议矩阵替代单一结论：

| 争议点 | 支持证据 | 反对/限制证据 | 争议原因 | 当前判断 | 后续研究方向 |
|---|---|---|---|---|---|

争议原因通常来自：人群不同、干预剂量/时机不同、结局不同、随访时间不同、研究质量不同、指南更新时间不同、真实世界可及性不同。

## 研究空白表

课题和论文写作支持必须识别空白，但不要夸大。

常见空白：

- 人群：儿童、老年、妊娠、合并症、不同种族/地区、本土数据不足。
- 干预：剂量、疗程、联合策略、序贯策略、真实世界实施。
- 结局：长期结局、生活质量、成本效果、安全性、患者报告结局。
- 方法：缺少 RCT、样本小、回顾性多、混杂控制不足、诊断标准不一致。
- 场景：基层、急诊、围手术期、ICU、慢病管理、科室协作。

输出研究空白时优先用段落或短列表解释，同时给出可行研究问题；若空白类型较多或需要横向比较，再补充简表。不要只写“需要更多研究”。

可选简表字段：

| 空白类型 | 当前证据不足之处 | 代表证据 | 可行研究问题 | 方法建议 |
|---|---|---|---|---|

## 论文引用逻辑解读或可选对照表

为论文添加文献时，优先用正文说明“哪个论点应引用哪类文献、各自引用角色和风险”；只有用户需要写作引用安排、段落级对应或多文献横向比较时，才补充以下对照表。不默认做额外白板图：

| 论文段落 | 需要支撑的论点 | 推荐引用 | 引用角色 | 风险 |
|---|---|---|---|---|
| 引言背景 | 疾病负担/临床重要性 | [1]/[2]/[3] | 背景 | 数据年份可能较旧 |
| 研究空白 | 现有研究不足 | [4]/[5] | 空白 | 需避免夸大 |
| 讨论比较 | 与既往研究一致/不一致 | [6]/[7]/[8] | 比较 | 人群或终点不同 |

草拟段落时每一句重要事实后都要能定位到引用。不要把一个引用放在段落末尾覆盖多个无关事实。

## 学习资料组织

学习资料应体现“从框架到实践”的层次，默认用小标题、短段落或短列表组织；只有信息密度较高或用户需要课件/讲义结构时，才补充简表：

- 知识框架：疾病定义、分型、诊断、治疗、随访、安全。
- 指南路径：推荐流程、检查/治疗顺序、特殊人群。
- 经典研究阅读路径：先指南，再综述，再里程碑研究，再最新前沿。
- 临床实践提示：常见问题、证据依据、实践提示、风险提醒。

学习资料可以使用教材/专著，但结论仍应与最新指南和研究校对。

## Mermaid 和飞书白板规则

飞书白板图只用于默认固定图组或用户明确要求的标准图。生成前先确认图型、目的、节点和边；不要把任意概要表强行转成 Mermaid。

若使用 `<whiteboard type="mermaid">`：

- 白板块内只能放纯 Mermaid 文本。
- 不要放 Markdown 代码围栏、HTML/XML 标签、`<br/>`、`<span>`、`<b>`。
- 不要放 HTML 上标标签；引用编号必须改成普通文本 `[1]`、`[2]` 等连续编号或可点击文献名。
- 不要使用 `light-yellow`、`light-green` 等飞书 callout 色名；要么省略样式，要么使用合法十六进制颜色。
- 节点标签保持短句；复杂信息放图例表。
- mindmap 必须形成“一级分类 -> 二级带编号文献 -> 三级证据结论”；每个一级分类有明确证据角色，例如指南、系统综述、关键研究、最新进展或研究空白。
- 每条二级文献下一层至少有一个短结论节点，如 `推荐背景`、`汇总证据`、`直接支持`、`提出冲突` 或 `提示空白`；不要只堆题名。
- 每篇文献只放在最相关的一个分支，不绘制跨分支连线。
- 不承诺飞书白板连线一定具备对象绑定；若需要严格可编辑关系图，应按当前环境支持的标准飞书 diagram 能力验证后再说明。

安全示例：

```xml
<whiteboard type="mermaid">
mindmap
  root((主题问题))
    指南与共识
      ref1["[1] 指南简称"]
        推荐方向
    系统综述
      ref2["[2] 系统综述简称"]
        总体证据
    关键研究
      ref3["[3] 关键研究简称"]
        关键结局
    争议与空白
      仍需研究的问题
</whiteboard>
```

生成最终报告 XML 后，无论是否包含 Mermaid 白板，都必须先运行 `node scripts/sanitize-feishu-report.js <report.xml>`，再运行 `node scripts/validate-report-whiteboards.js <report.xml>`。若白板检查失败，先修复 Mermaid，或改为表格/形状图；不得因为没有白板而跳过上标、链接和参考文献校验。

## PPT 图表规则

通过 `lark-ppt` Skill 创建 PPT/幻灯片时，关键图表优先用原生 `shape`、`line`、`table` 或原生图表组合绘制。默认只做时间线页和逻辑关系页；系统综述、关键研究、最新进展、热点、争议和空白优先做逐篇/逐主题解读页，只有横向比较确有必要时才做表格页。Mermaid whiteboard 只能作为增强，不能作为唯一主图，因为回读 XML 不一定能证明 whiteboard 内容实际显示。

每页只讲一个主信息。逻辑图、时间线、逐篇解读页和必要表格必须显示可读文献简称；可见编号从 CSV `citation_number` 渲染为 `[1]`、`[2]`，并在同页脚注或末页参考文献提供链接。

## 交付前检查

- 图表是否回答明确问题，而不是装饰。
- 除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上且用户未明确拒绝图表时，是否同时提供证据脉络思维导图和关键研究里程碑时间线图；文献不足 5 篇或资讯跟踪按专用结构省略图表时，用户指定的表格、清单、核心文献解读或资讯时间线是否已经清楚表达证据关系。
- 图中证据节点是否来自已纳入证据或参考文献表。
- 图例是否提供链接、来源/期刊、年份和来源级别。
- mindmap 是否严格形成“一级分类 -> 二级文献 -> 三级结论”，每个文献节点下一层是否至少有一个简短贡献、结论或限制说明。
- 是否区分高质量证据、辅助证据、争议证据和研究空白。
- 热点主题解读是否说明数据来源和局限；若使用热点主题表，是否避免伪装成完整文献计量分析。
- 论文引用逻辑是否把论点和引用一一对应；若使用对照表，表格是否只作为补充。
- 是否避免把概要表、热点、争议、空白、学习路径强行画成非标准复杂图。
- 图表是否过载；过载则拆成两张或改为表格。
