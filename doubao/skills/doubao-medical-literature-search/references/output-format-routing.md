# 输出格式路由

本文件只管“用户要哪种产物时，选择什么模板、怎么创建、怎么校验”。默认飞书文档 QA 见 `output-and-qa.md`。

## 选择规则

| 用户意图 | 默认产物 | 模板 | 适用场景 |
|---|---|---|---|
| `full_report`，且未指定格式、格式含糊或只提出分析/检索/整理需求 | 飞书文档 | `assets/feishu-doc-template.xml` | 文献综述、指南查新、热点分析、课题论证、学习资料 |
| `full_report`，且说“PPT、汇报、组会、教学、幻灯片” | PPT/幻灯片（使用 `lark-ppt` Skill） | `assets/ppt-deck-template.xml` | 科室汇报、研究生组会、教学课件、项目汇报 |
| `full_report`，且明确要求“Word、docx、正式报告、投稿附件、归档” | 可打开的 Word/docx（通过 `lark-doc` Skill 的 `office-word` 子模块） | `assets/word-report-template.md` | 正式文献综述、课题附件、论文写作支持、可打印归档 |
| `full_report`，且要求创建表格、对照表、清单或矩阵，但未指定 Excel/xlsx | 飞书文档 | `assets/feishu-doc-template.xml`，在正文中插入表格 | 表格是核心交付物，同时补充结论、解读、证据边界和来源链接 |
| `full_report`，且明确指定 Excel/xlsx 表格 | Excel/xlsx 工作簿 | 按用户指定字段和工作表结构 | 需要独立电子表格文件 |
| `full_report`，且明确要求 Markdown | 按用户要求 | 回答中提到的每个外部证据都给出各自可点击 URL，不限制篇数；期刊论文按需并列展示 Oxford CEBM 2009 证据级别和已命中的期刊级别 | 用户指定的完整检索或调研格式 |
| `quick_answer`：`audience_mode=patient` 且未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；或明确要求快速回答、简短、精简、概括、小结、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；或检索仅限单篇具名论文、单份具名指南、单一明确年份，且未要求完整报告或正式文档 | 普通聊天回答 | 不加载文档模板 | 仅做 1-2 个高价值批次；提到的每个外部证据均给出各自可点击 URL，不限制篇数，使核心结论可追溯；不创建产物 |

先判定 `response_mode`，再选择格式。`audience_mode=patient` 且未明确提出文献查阅/梳理、循证分析、完整报告或正式文档要求时，进入 `quick_answer`；用户明确提出轻量要求或命中单篇具名论文、单份具名指南、单一明确年份的窄范围例外时，也进入 `quick_answer`。若明确要求查阅/梳理文献、循证分析、完整报告或正式文档，则使用 `full_report`。除 `patient` 例外外，“用户没有主动要求文档”仍属于未指定格式，一般任务必须按 `full_report` 创建飞书文档。普通的问题聚焦、需求明确、文献较少或已找到足够信息都不能改变模式。不确定时按 `full_report` 执行。

“表格”本身不等于 Markdown 或聊天输出。只要用户要求创建表格且没有明确写 `Excel/xlsx`，就通过 `lark-doc` 创建飞书文档，并在表格前后保留必要的常规文档内容；不要只交付孤立表格。

默认飞书文档不是可选增强，而是 `full_report` 未指定格式时的主交付物。只输出 PMID/题名列表或聊天摘要时，必须视为未完成并返回飞书创建步骤。`full_report` 创建失败也不得改用 `quick_answer` 完成任务。

## 渐进式披露

`full_report` 先完成任务分类、检索边界、关键词扩展、内部证据记录、预算内检索、按需原文阅读、证据评价和综合；图表只在有助于回答时设计。每轮检索后及时记录高相关候选，再进入筛选和阅读。`quick_answer` 只做 1-2 个高价值批次；回答中提到的每个外部证据都给出各自可点击 URL，不限制篇数、不得漏链，并使核心结论可追溯；缺少协议的完整域名与路径先补 `https://`，最终链接目标只允许以 `https://` 或 `http://` 开头，不输出无协议短链，也不为此逐条打开短链；不加载文档模板。只有 `full_report` 准备交付时才加载对应模板：

- 飞书文档：加载 `assets/feishu-doc-template.xml`。
- PPT/幻灯片：加载 `assets/ppt-deck-template.xml`，并按 `lark-ppt` Skill 要求先做页面规划。
- Word/docx：加载 `assets/word-report-template.md`，然后使用 `lark-doc` Skill，并按其顶层路由进入 `office-word/office-word-skill.md` 子模块生成真正 `.docx`。

所有格式均保留 `audience_mode`：`professional` 可呈现研究空白、课题与引用建议；`patient` 解释术语并聚焦用户问题，除非用户明确要求，否则删除研究方向、课题建议、证据空白和无关风险内容。

飞书完整骨架依次包含不编号“总结”高亮块、根据用户 Query 命名的第一章直接回答、证据脉络、指南/共识、系统综述与关键研究、其他研究、最新进展/资讯与证据状态、按需建议、检索策略与证据范围、参考文献和免责声明。用户指定比较表、清单、字段或章节顺序时，在第一章按该形式完整放置核心交付物，再以后续骨架检查覆盖情况；第一章已明确回答且证据、链接和边界完整的重复内容可合并、缩减或删除，后续只补齐尚未覆盖的重要内容。检索策略与证据范围放在参考文献前并可精简；相关文献不足 5 篇时可省略白板图，达到 5 篇及以上时除非用户明确要求不要图表，仍需补充证据脉络思维导图和关键研究里程碑时间线图。医学资讯跟踪可按专用主线灵活组章，图表不能增加信息时可省略。文末参考文献默认使用 `标题｜来源｜类型｜年份｜期刊分区｜链接` 六列表格，期刊分区未明确命中时留空，且每条有可点击来源入口，链接文字为 `PDF` 或 `原链接`。

## 飞书文档

飞书文档适合完整、可追溯、图文并茂的文献分析。

创建规则：

- 直接调用平台已配置的 `lark-doc` Skill，由其路由到 `online-doc` 创建或更新文档；不要通过 CLI 查找 Skill。
- 默认 XML；用户明确要 Markdown 时才用 Markdown。
- 长报告默认用通过校验的完整 XML 一次创建并统一回读；只有一次创建明确因载荷或长度限制失败时，才按 `lark-doc-delivery-reliability.md` 从实际目录选择 3 个锚点和 3 个连续大块兜底。禁止默认逐章更新或用 `append` 填充中间章节。
- 标题后先使用不编号“总结” callout；第一章按用户 Query 提炼标题，先写“问题小结”，再深入回答，并把用户指定的核心表格、清单或重点文献解读放在本章；第二章起再使用证据脉络图、里程碑时间线、逐篇文献解读和参考文献分组。
- 飞书文档 XML 禁止使用原始、转义、双重转义或样式化 HTML 上标标签，也不得使用 `<ref>` 标签或其转义形式；引用编号和脚注改用正文括号、可点击文献名、允许的 citation 引用组件或参考文献表。生成最终 XML 后必须依次运行 `node scripts/sanitize-feishu-report.js <report.xml>` 和 `node scripts/validate-report-whiteboards.js <report.xml>`，两者退出码均为 0 后再调用 `lark-doc`。
- 正文、证据表、图例和建议段落提到具体文献/指南/试验时必须就地给出可点击标题或简称，例如 `<a href="{{url}}">{{文献名或研究简称}}</a>`；不得显示内部 `evidence_id`，文末参考文献链接不能替代正文链接。
- 正式产物直接使用文献写入内部 CSV 时按行顺序生成的 `citation_number`，在正文、图表和参考文献中渲染为 `[1]`、`[2]` 等编号；编号与可点击文献名共同出现，不再另行规划或重排。不得使用 `G1`、`R1`、`SR1` 等类型前缀号。
- 除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上时，除非用户明确要求不要图表，同时插入 Mermaid 证据脉络思维导图和关键研究里程碑时间线图；文献不足 5 篇时，只有图表能改善表达才插入。
- 图中每个文献节点必须从 CSV `citation_number` 渲染为 `[1] 研究/指南简称`，并通过图例表或同页注释提供链接；不得显示内部 `evidence_id`。
- 指南与专家共识、系统综述、关键研究和最新进展章节优先用逐篇/逐主题段落解读。复杂任务可补充争议矩阵表、研究空白表、指南对比表或引用逻辑表；只有用户明确要求或能稳定映射为飞书标准图型时，才额外画图。
- 飞书完整骨架在参考文献前设置“检索策略与证据范围”，精简介绍必要的来源、关键词、纳入排除和覆盖边界；任务十分明确时只保留影响结果解释的信息。第一章核心交付物已完整覆盖的后续重复内容可合并、缩减或删除，只补齐尚未回答的重要证据、局限和来源链接。任何结构都不展示内部工具名称。
- 若 `lark-doc` 不可用或创建失败，最终回复必须写 `飞书文档创建失败`，给出原因和可重试飞书 XML 草稿入口；不得降级为只给题名列表。

## PPT/幻灯片

PPT/幻灯片必须通过 `lark-ppt` Skill 创建。它是汇报材料，不是把报告压缩成标题和项目符号。创建前按 `lark-ppt` Skill 要求写页面规划，每页明确 `layout_type`、`visual_focus`、`text_density`、核心信息和引用来源。

推荐 10-14 页结构：

1. 封面：主题、用途、日期。
2. 总结：3 条以内主结论、实践启示和证据边界。
3. 用户问题直接回答：标题根据 Query 提炼，先给问题小结，再呈现用户指定对照表、清单或核心文献解读。
4. 证据脉络思维导图：指南、综述、关键研究、最新进展和争议空白如何围绕研究主题形成层级脉络。
5. 指南/共识要点：逐条解读推荐方向、等级、更新点和差异。
6. 关键研究里程碑时间线图：优先做横向年份/阶段轴，时间节点下方纵向排列研究节点；年份很多时合并为时间段，节点写可读研究简称，避免一堆年份各只挂 1 篇文献。
7. 系统综述与关键研究：逐篇解释研究设计、主要结论、局限和引用用途；每篇标注期刊、年份、Oxford CEBM 2009 证据级别和已命中的期刊级别。
8. 其他相关研究：用带链接的无序列表列出标题、期刊、年份、类型、Oxford CEBM 2009 证据级别和已命中的期刊级别；每篇用 4-6 句话总结研究核心内容和主要结论，不使用表格。
9. 最新进展、研究热点、争议与空白：逐主题解释方向、代表文献、变化和证据边界。
10. 学习/课题/论文写作启示：优先用分点无序列表，突出学习路径、课题机会、引用用途和引用风险。
11. 检索策略与证据范围：精简展示问题框架、来源、关键词、纳入排除和覆盖局限。
12. 参考文献：核心证据与辅助参考；每条正式参考文献必须有原文/摘要页/DOI/PubMed/期刊页/官方入口之一的可点击链接。

设计约束：

- 画布按 960 x 540 规划。
- 每页一个主信息；正文不超过 5 条要点。
- 4 页以上至少使用 4 种版式，如封面、结论页、逻辑关系页、时间线、矩阵表、参考文献页。
- 关键图表优先使用原生 `shape`、`line`、`table` 或原生图表组合绘制。
- Mermaid whiteboard 只作增强，不能作为唯一主图。
- 每页直接引用可读文献简称；正文页提到具体文献时，文献标题/简称优先做成可点击链接。若采用编号，只使用全篇连续的 `[1]`、`[2]`，并与可点击文献名或同页链接共同出现，不能只给编号。
- 时间线页和证据脉络思维导图页必须在文献节点中显示 `[n] 研究简称`，而不是内部 `evidence_id` 或只有概念词。
- 生成后回读/校验页数、主体元素、空白页、重叠、溢出和引用入口。

## Word/docx

Word 适合正式、可打印、可归档的文献综述或论文支持材料。用户要求 Word/docx 时，必须使用 `lark-doc` Skill，并按 `lark-doc` 顶层路由进入其 `office-word/office-word-skill.md` 子模块，默认交付真正可打开的 `.docx` 文件；不要改用独立的 office-word 工具名、泛泛的 Word 工具或把 Markdown 改名成 docx。Markdown 只作为 `lark-doc` / `office-word` 不可用时的可重试草稿。

推荐结构：

1. 标题页与文档信息。
2. 不编号“总结”高亮块。
3. 第一章：根据用户 Query 命名并直接、深入回答问题。
4. 第二章：证据脉络思维导图与关键研究里程碑时间线图。
5. 第三章：指南与专家共识。
6. 第四章：系统综述与关键研究。
7. 第五章：其他相关研究。
8. 第六章：最新进展、热点、争议和空白。
9. 第七章：论文写作/课题/学习建议。
10. 第八章：检索策略与证据范围。
11. 第九章：参考文献。
12. 免责声明。

版式要求：

- A4，页边距约 2.5 cm。
- 正文宋体或等效中文正文字体，小四或 11-12 pt，1.5 倍行距。
- 标题层级清晰，自动编号或稳定编号。
- 表格列宽稳定，不横向溢出。
- 图表有编号、题注和图例表；打印后仍能通过文献简称与链接追溯到正文或参考文献表。
- 参考文献格式按用户要求；未指定时默认使用 `标题｜来源｜类型｜年份｜期刊分区｜链接` 六列表格。期刊分区仅填写明确匹配的期刊论文，其他资料留空。无论 Vancouver、AMA、APA、GB/T 7714 或其他格式，文末每条正式参考文献都必须带原文/摘要页/DOI/PubMed/期刊页/官方入口之一的可点击链接。正文中被引用的文献标题或简称也必须就地带超链接，不只在文末给链接；没有任何可点击入口的资料不能进入最终参考文献表。
- 生成后检查 `.docx` 文件可打开、标题层级正常、表格不溢出、链接可见、图表有图例；最终回复给出 Word 文件入口和关键说明。

## Markdown

仅在 `full_report` 用户明确要求 Markdown 时使用，保留：

- 结论和证据确定性。
- 核心文献表，含链接、类型、来源、年份、Oxford CEBM 2009 证据级别和已命中的期刊级别。
- 检索范围和局限。
- 检索方法和主要关键词。
- 参考文献默认按 `标题｜来源｜类型｜年份｜期刊分区｜链接` 呈现，且每条都有链接；期刊分区未明确命中时留空。

不要把指定格式变成无来源的观点回答。表格请求按前述飞书/Excel 规则处理。`audience_mode=patient` 且未明确要求查阅文献、循证分析、完整报告或正式文档，或用户明确要求快速回答、简短、精简、概括、小结、限定字数、一段话、不要创建文档或直接聊天回答，或命中窄范围检索例外且未要求正式产物时，不进入本节，而使用 `quick_answer` 的 1-2 批检索路径。

## 失败兜底

如果目标格式工具不可用：

- 明确说明失败原因。
- 不要以“稍后生成”结束。
- 提供对应模板的完整可重试草稿：飞书 XML、PPT XML，或供 `lark-doc` Skill 的 `office-word` 子模块重试的 Word/docx Markdown 草稿。
- 最终回复仍保持简短，给出草稿路径和关键说明。
