# 输出格式路由

本文件只管“用户要哪种产物时，选择什么模板、怎么创建、怎么交付”。默认飞书文档交付见 `output-and-qa.md`。

## 选择规则

先识别稿件用途：用户要求“写一篇综述”、生成综述稿件或完整综述论文，包括可投稿综述时，按 `review-manuscript-and-citations.md` 确定 `writing_mode=review_manuscript`、`response_mode=full_report`，默认直接路由 `word`，按正式医学论文格式生成 `.docx`。其余调研任务按下表选择产物；用户明确另选格式时按其要求。

| 用户意图 | 默认产物 | 模板 | 适用场景 |
|---|---|---|---|
| 用户要求“写一篇综述”、生成综述稿件、完整综述论文或可投稿综述 | 论文 Word/docx（直接使用 `word` Skill） | 论文内容要求见 `references/review-manuscript-and-citations.md`，正式论文格式由 `word` 按目标期刊要求落实 | 正式综述论文稿件 |
| `full_report`，且未指定格式、格式含糊或只提出分析/检索/整理需求 | 飞书文档 | `assets/feishu-doc-template.xml` | 文献综述、指南查新、热点分析、课题论证、学习资料 |
| `full_report`，且说“PPT、汇报、组会、教学、幻灯片” | PPT/幻灯片（使用 `ppt` Skill） | 平台 `ppt` Skill 当前流程 | 科室汇报、研究生组会、教学课件、项目汇报 |
| `full_report`，且明确要求“Word、docx、正式报告、投稿附件、归档” | 可打开的 Word/docx（直接使用平台 `word` Skill） | 向 `word` 交接完整内容、文种用途和引用要求，由其采用对应专业文档格式 | 正式文献综述、课题附件、论文写作支持、可打印归档 |
| `full_report`，且要求创建表格、对照表、清单或矩阵，但未指定 Excel/xlsx | 飞书文档 | `assets/feishu-doc-template.xml`，在正文中插入表格 | 表格是核心交付物，同时补充结论、解读、证据边界和来源链接 |
| `full_report`，且明确指定 Excel/xlsx 表格 | Excel/xlsx 工作簿 | 按用户指定字段和工作表结构 | 需要独立电子表格文件 |
| `full_report`，且明确要求 Markdown | 按用户要求 | 回答中提到的每个外部证据都给出各自可点击 URL，不限制篇数；期刊论文按需并列展示 Oxford CEBM 2009 证据级别和已命中的期刊级别 | 用户指定的完整检索或调研格式 |
| `quick_answer`：`audience_mode=patient` 且未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；或明确要求快速回答、简短、精简、概括、小结、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；或检索仅限单篇具名论文、单份具名指南、单一明确年份，且未要求完整报告或正式文档 | 普通聊天回答 | 不加载文档模板 | 默认做 1 个高价值批次；提到的每个外部证据均给出各自可点击 URL，不限制篇数，使核心结论可追溯；不创建产物 |

先判定 `response_mode`，再选择格式。`audience_mode=patient` 且未明确提出文献查阅/梳理、循证分析、完整报告或正式文档要求时，进入 `quick_answer`；用户明确提出轻量要求或命中单篇具名论文、单份具名指南、单一明确年份的窄范围例外时，也进入 `quick_answer`。若明确要求查阅/梳理文献、循证分析、完整报告或正式文档，则使用 `full_report`。除 `patient` 例外外，“用户没有主动要求文档”仍属于未指定格式，一般任务必须按 `full_report` 创建飞书文档。普通的问题聚焦、需求明确、文献较少或已找到足够信息都不能改变模式。不确定时按 `full_report` 执行。

“表格”本身不等于 Markdown 或聊天输出。只要用户要求创建表格且没有明确写 `Excel/xlsx`，就通过 `lark-doc` 创建飞书文档，并在表格前后保留必要的常规文档内容；不要只交付孤立表格。

默认飞书文档不是可选增强，而是 `full_report` 未指定格式时的主交付物。只输出 PMID/题名列表或聊天摘要时，必须视为未完成并返回飞书创建步骤。`full_report` 创建失败也不得改用 `quick_answer` 完成任务。

正式输出的表格使用 `-` 显示缺失、未核验、未匹配、空值及不适用的证据等级；已有医学分析、风险、争议和官方等级保持原义。

## 渐进式披露

`full_report` 先完成任务分类、检索边界、关键词扩展、内部证据记录、预算内检索、按需原文阅读、证据评价和综合；图表只在有助于回答时设计。每轮检索后及时记录高相关候选，再进入筛选和阅读。`quick_answer` 默认做 1 个高价值批次；回答中提到的每个外部证据都给出各自可点击 URL，不限制篇数、不得漏链，并使核心结论可追溯；保留搜索工具返回的原始 URL，按内容可靠性判断 PDF 和索引入口；不加载文档模板。只有 `full_report` 准备交付时才加载对应模板：

- 飞书文档：加载 `assets/feishu-doc-template.xml`。
- PPT/幻灯片：读取并调用平台 `ppt` Skill，按其当前流程规划页面并生成产物。
- Word/docx：直接读取并调用平台 `word` Skill，交接本轮完整内容、文种用途、图表和引用要求。完整综述论文先读 `review-manuscript-and-citations.md` 明确论文内容与学术表达，再由 `word` 采用正式论文格式生成 `.docx`。

所有格式均保留 `audience_mode`：`professional` 可呈现研究空白、课题与引用建议；`patient` 解释术语并聚焦用户问题，除非用户明确要求，否则删除研究方向、课题建议、证据空白和无关风险内容。

飞书完整骨架依次包含不编号“总结”高亮块、根据用户 Query 命名的第一章直接回答、证据脉络、指南/共识、系统综述与关键研究、其他研究、最新进展/资讯与证据状态、按需建议、检索策略与证据范围、参考文献和免责声明。用户指定比较表、清单、字段或章节顺序时，在第一章按该形式完整放置核心交付物，再以后续骨架检查覆盖情况；第一章已明确回答且证据、链接和边界完整的重复内容可合并、缩减或删除，后续只补齐尚未覆盖的重要内容。检索策略与证据范围放在参考文献前并可精简；相关文献不足 5 篇时可省略白板图，达到 5 篇及以上时除非用户明确要求不要图表，仍需补充证据脉络思维导图和关键研究里程碑时间线图。医学资讯跟踪可按专用主线灵活组章，图表不能增加信息时可省略。文末参考文献默认使用 `标题｜来源｜类型｜年份｜期刊分区｜链接` 六列表格，期刊分区未明确命中时填 `-`，且每条有可点击来源入口，链接文字为 `PDF` 或 `原链接`。

## 飞书文档

飞书文档适合完整、可追溯、图文并茂的文献分析。

创建规则：

- 直接调用平台已配置的 `lark-doc` Skill，由其路由到 `online-doc` 创建或更新文档；不要通过 CLI 查找 Skill。
- 默认 XML；用户明确要 Markdown 时才用 Markdown。
- 飞书在线报告可用完整 XML 一次创建；长度受限时按实际需要分块。
- 标题后先使用不编号“总结” callout；第一章按用户 Query 提炼标题，先写“问题小结”，再深入回答，并把用户指定的核心表格、清单或重点文献解读放在本章；第二章起再使用证据脉络图、里程碑时间线、逐篇文献解读和参考文献分组。
- 飞书文档 XML 禁止使用原始、转义、双重转义或样式化 HTML 上标标签，也不得使用 `<ref>` 标签或其转义形式；引用编号和脚注改用正文括号、可点击文献名、含来源超链接的 citation 样式容器或参考文献表。
- 正文、证据表、图例和建议段落提到具体文献/指南/试验时必须就地给出可点击标题或简称，例如 `<a href="{{url}}">{{文献名或研究简称}}</a>`，文末参考文献链接不能替代正文链接。
- 正式产物直接使用文献写入内部 CSV 时按行顺序生成的 `citation_number`，在正文、图表和参考文献中渲染为 `[1]`、`[2]` 等编号；编号与可点击文献名共同出现，不再另行规划或重排。不得使用 `G1`、`R1`、`SR1` 等类型前缀号。
- 除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上时，除非用户明确要求不要图表，同时插入 Mermaid 证据脉络思维导图和关键研究里程碑时间线图；文献不足 5 篇时，只有图表能改善表达才插入。
- 图中每个文献节点必须从 CSV `citation_number` 渲染为 `[1] 研究/指南简称`，并通过图例表或同页注释提供链接。
- 指南与专家共识、系统综述、关键研究和最新进展章节优先用逐篇/逐主题段落解读。复杂任务可补充争议矩阵表、研究空白表、指南对比表或引用逻辑表；只有用户明确要求或能稳定映射为飞书标准图型时，才额外画图。
- 飞书完整骨架在参考文献前设置“检索策略与证据范围”，精简介绍必要的来源、关键词、纳入排除和覆盖边界；任务十分明确时只保留影响结果解释的信息。第一章核心交付物已完整覆盖的后续重复内容可合并、缩减或删除，只补齐尚未回答的重要证据、局限和来源链接。任何结构都不展示内部工具名称。
- 若飞书文档创建失败，聊天说明原因并回答已核实的结论、相关风险与关键依据；原始草稿内部保留。

## PPT/幻灯片

调用平台 `ppt` Skill，遵循其当前页面规划、制作与交付流程。制作前先检索该医学题材常见的汇报结构与视觉风格，结合受众和用途确定叙事；可主动搜集适合的医学示意图或公开图像，核实其来源和含义。

内容按“问题与结论 → 证据展开 → 分析讨论 → 实践启示与总结”递进，按题目和证据量安排页数，保证章节完整、内容充实，并在结尾收束到用户最关心的问题。文献调研通常覆盖：

1. 主题、用途与检索截止日期。
2. 总结与用户问题直接回答，呈现指定对照表、清单或核心文献解读。
3. 证据脉络和关键研究里程碑。
4. 最新指南/共识、系统综述与关键研究：解释推荐、研究设计、主要结果、局限与适用性。
5. 其他相关研究、最新进展及相关争议，按关联度分配篇幅。
6. 学习、课题或临床实践启示，检索范围与完整参考文献；按受众保留需要的内容。

每页围绕明确主信息展开，可组合段落、分点、数据、图表和病例片段，用分栏、图解或续页承载充分内容。图表与文献编号沿用 CSV 的统一 `[n]`。各页页脚保留支持该页内容的来源超链接，正文文献名或简称也尽量就地可点击。

涉及教学查房时，以真实病例或明确的教学具体病例组织“病例汇报 → 床旁要点 → 病例特点与问题 → 分析讨论 → 总结”；重心放在病例分析与诊疗讨论。真实病例只使用已提供的事实，教学病例身份应清楚。生成后使用 `present_files` 交付 PPT 文档或文件链接，参数按当前环境工具合同。

## Word/docx

用户要求 Word/docx、正式报告、投稿附件或可打印归档材料时，直接读取并调用平台 `word` Skill，将完整内容、文种用途、受众、图表与题注、正文编号—URL 映射、参考文献及用户模板一次交接，由 `word` 按对应专业文书格式组织版式并生成 `.docx`。

用户要求“写一篇综述”、生成综述稿件或完整综述论文时，包括未明确写“投稿”的正式综述，先按 `review-manuscript-and-citations.md` 完成证据综合与学术写作，再交 `word` 使用正式医学论文格式；按综述类型和目标期刊要求组织题名、摘要与关键词、引言、主题证据综合、讨论与结论、参考文献等内容。普通文献调研和学习型综述仍按既有默认飞书流程交付。

创建 Word 时明确以下引用要求：默认按现行 GB/T 7714 顺序编码制著录，用户或目标期刊明确指定其他格式时按其要求。正文完整 `[n]` 使用 Word 原生 run 上标，方括号与数字一并上标，不附超链接；按首次引用顺序编号，同一来源复用编号。每条文末参考文献末尾追加“（查看来源）”，其中“查看来源”为指向该条真实来源 URL 的 Word 原生超链接，已有 DOI 也保留此末尾入口。允许的来源入口沿用本 Skill 既有规则。

标题层级、分页、字体、表格、图表和文件生成使用 `word` 的正式文档流程；引用要求在生成交接时一并传递。最终使用 `present_files` 交付 Word 文件或实际文件链接。XML、CSV 和过程草稿内部保留。

## Markdown

仅在 `full_report` 用户明确要求 Markdown 时使用，保留：

- 结论和证据确定性。
- 核心文献表，含链接、类型、来源、年份、Oxford CEBM 2009 证据级别和已命中的期刊级别。
- 检索范围和局限。
- 检索方法和主要关键词。
- 参考文献默认按 `标题｜来源｜类型｜年份｜期刊分区｜链接` 呈现，且每条都有链接；期刊分区未明确命中时填 `-`。

不要把指定格式变成无来源的观点回答。表格请求按前述飞书/Excel 规则处理。`audience_mode=patient` 且未明确要求查阅文献、循证分析、完整报告或正式文档，或用户明确要求快速回答、简短、精简、概括、小结、限定字数、一段话、不要创建文档或直接聊天回答，或命中窄范围检索例外且未要求正式产物时，不进入本节，而使用 `quick_answer` 的默认 1 批检索路径。

## 交付与创建失败

`full_report` 默认交付聊天回答和飞书文档链接。用户要求 PPT、Word 或其他最终格式时，按上述路由生成；`present_files` 仅选择最终产物或其链接，参数按环境工具合同。XML、CSV 和原始草稿留作内部过程文件。

目标格式创建失败时，说明创建情况与原因，聊天中给出已核实的结论、相关风险和关键依据；内部草稿保留供后续继续使用。
