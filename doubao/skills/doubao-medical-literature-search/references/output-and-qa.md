# 输出与复核

本文件只管“怎么交付、交付前检查什么”。非默认格式路由见 `output-format-routing.md`。

## 默认输出

先按 `audience_mode` 调整表达。`professional` 保留专业术语和与任务相关的研究空白、课题或引用建议；`patient` 解释必要术语，优先回答用户关心的问题，保持严谨但不过度制造焦虑，不主动罗列研究方向、课题建议、证据空白或无关风险。两种模式使用相同的来源质量、链接和核验标准。

`response_mode=full_report` 且用户没有明确表达预期格式时，必须创建飞书文档；不要用聊天正文、Markdown、独立表格、Word 或 PPT 代替默认交付。用户明确要求 Markdown、Excel/xlsx、PPT 或 Word/docx 时，保持 `full_report` 并按用户指定格式输出；其中 Word/docx 必须通过 `lark-doc` Skill 的 `office-word` 子模块生成真正 `.docx`。

用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel/xlsx`，按飞书文档交付：在文档中插入所需表格，并保留结论、解读、证据边界和来源链接等常规正文。不得把普通表格请求降级为聊天表格或纯 Markdown 表格。

`response_mode=quick_answer` 由以下任一条件触发：`audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；用户明确要求快速回答、简短、精简、概括、小结、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；检索范围仅限单篇具名论文、单份具名指南、单一明确年份且未要求完整报告或正式文档。仅做 1-2 个高价值批次，以普通聊天直接回答；回答中提到的每个外部证据都必须各自带可点击 URL，不限制来源篇数、不得漏链，并使每项核心检索结论均可追溯。不创建飞书文档、PPT 或 Word。

除合法进入 `quick_answer` 外，聊天窗口只用于短状态和最终入口，不承载完整报告、证据表草稿、检索流水、大量文献列举、候选文献清单或完整参考文献展开。这些内容必须放入飞书文档或目标产物正文与附录。

## 先满足用户需求，再完成标准文档

飞书文档标题后先放不编号的“总结”高亮块；第一章标题根据用户 Query 提炼为回答型专业小标题，并对照需求清单完整回答用户最关心的问题和每个明确提出的字段。涉及多个可比较对象且主要维度可对齐时，优先在第一章用对比表集中呈现，再用正文解释差异、证据边界和不可直接比较之处；用户指定的表格/清单结构、呈现顺序或核心文献解读应原样优先满足。第二章起用飞书标准骨架检查内容覆盖：前文已经明确回答且证据、链接和边界完整的重复内容可以合并、缩减或删除；尚未覆盖的重要证据、局限、建议、带链接参考文献和免责声明仍须补齐。相关文献不足 5 篇时图表可按需省略，达到 5 篇及以上时除非用户明确拒绝，仍需在第一章之后插入两张主图；医学资讯跟踪在图表不能增加信息时可省略。

`full_report` 默认飞书文档的创建顺序：

1. 确认用户没有明确要求非飞书格式，将 `target_format` 设为 `feishu_doc` 并立即锁定到交付完成。
2. 生成任何 XML 前先读取 `assets/feishu-doc-template.xml`；默认飞书任务不得读取或仿照 `assets/ppt-deck-template.xml`。飞书 XML 去除前置注释后的首个元素必须是 `<title>`。
3. 生成文档前确认内部 CSV 中保留的文献已按写入行顺序生成 `citation_number`，不再规划正文首次出现顺序或重排编号。以已读取的飞书模板作为覆盖检查骨架；先生成不编号的“总结”高亮块，再生成以用户 Query 命名的第一章并深入回答问题。若用户指定表格、清单或深度解读，在第一章插入并突出该核心交付物；第二章起删除、合并或缩减重复内容，并补齐尚未覆盖的必要证据。若生成图表，再整理 `citation_number | short_name | evidence_role` 节点清单。正文、图表、图例和参考文献均复用同一 CSV 编号与链接；不显示 `evidence_id`。
4. 对本次将要写入飞书的同一份最终 XML，依次运行 `node scripts/sanitize-feishu-report.js <report.xml>` 和 `node scripts/validate-report-whiteboards.js <report.xml>`；两条命令都必须以退出码 0 完成，不得以目测、口头确认或“等价处理”跳过。校验检查原始及多重转义上标、样式化上标、可见模板指令和 Mermaid 格式；不检查内部工具名、正文标题或文献题名超链接，也不校验参考文献表。允许 citation 引用组件，仅在文档实际包含白板时检查 Mermaid 格式。
5. 直接调用平台已配置的 `lark-doc` Skill，由其路由到 `online-doc`，并读取 `lark-doc-delivery-reliability.md`。默认使用完整 XML 一次创建；create/fetch/update 固定使用 v2。创建响应必须通过返回值硬闸门，并统一回读实际生成的全部章节、正文链接、参考文献及已使用的白板。
6. 只有创建和正文回读全部完成后，默认任务才能进入最终回复。任一步失败都不能伪装成完整交付。

不要执行 `which lark-cli`、`lark-cli skills read`、`lark-cli docs skills` 或帮助探测来寻找 Skill。若第 4 步失败或当前环境没有加载 `lark-doc`，最终回复必须写 `飞书文档创建失败`，说明原因，并给出可重试飞书 XML 草稿文件路径或完整 XML 草稿入口。不能只交付 PMID 列表或聊天正文。

完整检索可持续使用内部 literature-log CSV 记录纳入证据，但 CSV 不属于用户可见产物。

默认飞书文档结构：

0. 不编号“总结”高亮块：概括核心结论、实践启示和证据边界；`professional` 模式可按任务补充研究局限和空白
1. 根据用户 Query 提炼的回答型专业小标题：先写“问题小结”，再深入回答用户问题；用户指定核心交付物也放在本章
2. 证据脉络与研究关系：论文关系梳理、关键里程碑
3. 指南与专家共识
4. 系统综述与关键研究
5. 其他相关研究
6. 最新进展、热点、争议与空白；医学资讯跟踪任务改为“最新医学资讯与证据状态”
7. 学习、课题或论文写作建议；`patient` 模式除非用户明确要求，否则删除
8. 检索策略与证据范围（含精简检索方法与关键词）
9. 完整参考文献（含链接）
10. 免责声明

默认使用通过校验的完整 XML 一次创建并统一回读。以下是标准骨架的 3 个 section 兜底示例；不编号“总结”高亮块保留在骨架中，用户指定核心交付物纳入 `section-1`，其余保留章节仍按连续内容块写入：

| section | 包含章节 | 写入方式 |
|---|---|---|
| `section-1` | 第 1 章正文、用户指定核心交付物（如有），以及第 2、3 章的标题和正文 | 兜底时插在本次动态生成的第一章标题后；块内不得重复锚点标题 |
| `section-2` | 第 4 章正文，以及第 5、6、7 章的标题和正文 | 兜底时插在骨架的“四、系统综述与关键研究”后；块内不得重复锚点标题 |
| `section-3` | 第 8 章正文，以及第 9、10 章的标题和正文 | 兜底时插在骨架的“八、检索策略与证据范围”后；块内不得重复锚点标题 |

执行时先在本地生成完整 XML 草稿并运行校验，然后直接整篇创建。只有完整创建明确受载荷或长度限制阻断，且未留下可用文档时，才按标准骨架选取 3 个锚点并最多写入 3 个连续大块；使用本次动态第一章标题、第四章和第八章为锚点，用户指定核心交付物随第一章写入。三个锚点一次 fetch 获取；只有 `degrade_code=1002`、需要新插入 block ID 或结构发生替换/删除时才重新 fetch。不得继续拆成逐章更新。

上述目录是飞书完整报告的覆盖检查骨架，而非必须逐章复述的固定目录。用户指定格式时，在第一章按要求呈现核心交付物，并自由调整各章篇幅与章内呈现方式；第一章已完整覆盖的对应章节或重复内容可以合并、缩减或删除，但不得遗漏尚未回答的重要证据、局限、建议和带链接参考文献。用户明确只查指南、共识或其他证据类型时，删除范围外章节并顺延编号，不保留空标题，也不为填满骨架补充范围外文献。检索策略与证据范围可精简，图表按限定范围和触发规则保留或省略。

医学资讯跟踪可进一步按资讯任务重组目录，以“时间窗与截止日期、最新动态、对应证据、证据状态、增量意义、完整参考文献”为主线。指南、系统综述、关键研究、其他相关研究、学习/课题建议和两张白板图仅在能提供独立信息时保留，可合并、改名、调整顺序或省略；不得为了对齐默认章数重复内容或保留空标题。少量纳入的预印本应在正文和参考文献类型中标明“预印本/未同行评议”。

## 任务化结构

| 任务 | 应突出章节 |
|---|---|
| 主题循证综述 | 总结、第一章直接回答、指南、系统综述、关键研究、临床/学习意义 |
| 指南查新 | 最新推荐、指南差异、更新点、实践影响 |
| 研究热点 | 主题簇、时间线、最新进展、争议、研究空白 |
| 医学资讯跟踪 | 截止日期、近期权威动态、对应论文/指南/注册信息、少量相关预印本、证据状态与实际意义；按内容灵活组章 |
| 课题论证 | 研究现状、证据不足、可行研究问题、方法建议 |
| 论文写作支持 | 引用逻辑、可用文献表、段落草稿、引用风险 |
| 学习资料 | 知识框架、指南要点、经典研究、学习路径、实践问答 |

## 强制样式

飞书完整报告应图文并茂但不牺牲准确性。用户指定的核心交付物优先采用其要求的格式；后续内容只补充尚未覆盖的主要证据，已在前文完整回答的对应章节或重复内容可合并、缩减或删除，不机械堆叠重复表格、图表或结论。标准骨架通常包含：

- 总结与第一章：标题后先用不编号的“总结”高亮块概括结论、实践启示和证据边界；除栏目标签外，可适度加粗关键结论、重要数字和限制条件。第一章标题根据用户 Query 提炼，以普通正文中的加粗“问题小结”开篇，再按需求使用二三级标题、自然段、列表或对比表深入回答；非比较任务不强制表格。
- 检索策略与证据范围：固定放在参考文献前；任务明确时可缩为短段或小表，只保留会影响结果理解的来源、关键词、检索边界、纳入排除和覆盖局限。
- 可视化组：除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上时，除非用户明确要求不要图表，同时插入证据脉络思维导图和关键研究里程碑时间线图；不足 5 篇时，仅在证据类型多、研究演进重要或结论关系复杂时按需插图。
- 指南与专家共识、系统综述、关键研究和最新进展章节优先用“每篇/每份文献一个小节”的段落解读；与用户问题和核心结论关系最大的指南或研究可适度展开关键条文、研究设计、结果、适用边界及实际意义，外围或重复证据简写，不按文献数量平均分配篇幅。第四章每篇研究仍须标注期刊名称和年份。
- “其他相关研究”使用无序列表，不使用表格。每篇写可点击标题、期刊、年份和类型，并用 4-6 句话总结研究核心内容和主要结论，用于筛选文末参考文献中未在第四章详细解读的研究。
- 学习、课题或论文写作建议按用户用途自由组织，优先用无序列表分点呈现学习路径、课题机会、论文引用用途和引用风险；可用加粗、浅黄提示或语义色突出重点，不要默认约束为表格。
- 医学资讯跟踪按时间或主题呈现“动态、日期、发布主体、对应原始证据、证据状态和增量意义”；正式指南/论文、在线优先、预印本/未同行评议、会议摘要/发布、试验注册更新和机构新闻稿必须区分，不把资讯标题或预印本发现直接写成成熟医学结论。资讯主线完整时可省略无独立价值的标准章节和白板图。
- `patient` 模式保留直接回答、关键文献和必要证据边界；除非用户明确要求，不生成研究方向、课题建议、证据空白清单或无关风险扩展。
- 任务相关补充内容优先用正文段落或短列表；争议、研究空白、引用逻辑、学习路径或指南差异确实需要横向比较时，才补充标准表格。只有用户明确要求，或确实能稳定映射为飞书标准图型时，才额外生成图。
- “检索策略与证据范围”固定为第八章、紧邻参考文献，只保留外部来源、核心关键词、检索批次/效率、纳入排除和证据覆盖局限。不要铺开完整检索流水或大量关键词组合。

语义色建议：

| 用途 | 颜色 |
|---|---|
| 核心结论/证据方向一致 | `light-green` |
| 检索范围/背景说明 | `light-blue` |
| 证据有限/待核验/需谨慎 | `light-yellow` |
| 证据冲突/争议 | `light-orange` |
| 安全警示/不支持 | `light-red` |

不要生成伪医学影像、伪数据可视化或难以在飞书稳定显示的复杂 diagram。热点主题表若基于本次检索归纳，必须说明不等同于完整文献计量分析。

## 飞书写法

优先使用：`<title>`、`<h1>`、`<h2>`、`<callout>`、`<table>`、`<ul>`、`<ol>`、`<a href="https://...">来源标题</a>`、`<whiteboard type="mermaid">`。

禁止在飞书文档 XML 中使用 HTML 上标标签，也不得使用 `<ref>` 标签或其转义形式。不要用这些标签做引用编号、脚注或证据编号；直接改用可点击文献名、允许的 citation 组件或文末参考文献表。

正文所有被引用的文献名本身必须带超链接；首次出现时标注来源/期刊和年份。正式文档中的期刊论文按需标注 Oxford CEBM 2009 证据级别，并并列展示索引明确命中的 2025 中科院分区/北大核心；指南/共识的 Oxford 证据级别写 `不适用`，其原文分级体系和推荐等级另行保留。研究推荐写法：`<a href="{{url}}">{{文献名或研究简称}}</a>（{{来源/期刊}}，{{年份}}；Oxford CEBM 2009：{{1a-5；研究设计信息不足时填“暂未分级”}}；期刊级别：{{命中的中科院分区/北大核心}}）`。`journal_rank_2025` 为空、匹配不唯一或来源不是期刊论文时，省略整个“期刊级别”字段，不显示占位词。参考文献表不能替代正文链接，不能只写编号、PMID、DOI 或纯文本题名。文献题名清单、候选文献列表和编号参考文献列表也必须逐条链接题名；`1. 文献题名。期刊，年份。` 这种无链接列表视为交付失败。

正文不能出现无链接来源小标题。以下写法不合格：

`《某某疾病诊疗指南（2025）》`

`DAPA-CKD 研究显示...`

正确写法是把来源名本身做成链接：

`<a href="{{url}}">某某疾病诊疗指南（2025）</a>（{{来源/期刊}}，2025；原指南分级按原文保留）`

`<a href="{{url}}">DAPA-CKD</a>（NEJM，2020，RCT；Oxford CEBM 2009：1b；期刊级别：中科院 1 区）显示...`

Oxford CEBM 2009 等级、期刊级别及其说明只写入正式飞书、Word 或 PPT 产物。聊天 Quick Answer 和最终入口回复保持简洁，不逐条展示这些分级，也不重复文末说明。

表格建议：

- 检索问题表：主题、框架、范围、结局、时间、语言、纳入/排除。
- 指南对比表：仅在需要横向比较多份指南差异时使用，包含指南、机构/年份、推荐、强度/证据等级、适用范围、更新点；单纯“指南与专家共识”章节默认用逐条解读。
- 关键研究解读：每篇文献一个小节，题名或研究简称可点击，明确标注期刊、年份、Oxford CEBM 2009 证据级别和已命中的期刊级别，并解释主要结论、局限和引用用途。
- 其他相关研究：用带链接的无序列表逐篇呈现 `标题（期刊，年份；类型；Oxford CEBM 2009；命中的期刊级别）`，每篇随后用 4-6 句话总结研究核心内容和主要结论，不使用表格；期刊级别未命中时直接省略。
- 热点表：主题簇、代表文献、近年变化、证据强度、研究空白。
- 论文引用对照表：仅在用户明确需要论文写作引用安排时补充；学习、课题或论文写作建议章节默认不用表格。

Mermaid 白板必须遵守 `synthesis-and-visualization.md` 中的安全规则。

## 参考文献

文末参考文献分组：

1. 核心证据：质量高、来源权威、与当前主题高度匹配且能支撑关键结论；不按全文可及性机械分组。
2. 辅助参考：低级别、不权威、方法学薄弱、与主题匹配度较低，或仅用于背景、教材/实践说明和研究线索的资料；不得单独支撑关键疗效或安全性结论。
3. 排除/待核验：只在需要透明展示筛选时列代表性记录。

默认飞书文档的完整参考文献必须用表格承载，不用纯编号列表承载。除非用户明确要求特定参考文献格式，文末参考文献表固定为六列：`标题｜来源｜类型｜年份｜期刊分区｜链接`。
表内不新增编号列；“标题”单元格使用 CSV `citation_number` 写成 `[n] 可点击完整题名`。

- `标题`：完整题名、指南名、试验名、教材/监管来源名。
- `来源`：期刊、机构、数据库、监管机构或教材来源。
- `类型`：指南、共识、系统综述、Meta、RCT、队列、诊断研究、真实世界研究、安全监管、教材/实践资料或辅助参考等；仅对确实阅读全文的重要论文，可在类型后追加 `已阅读全文`。
- `年份`：发表、发布或更新年份；不清楚写 `未返回`。
- `期刊分区`：期刊论文填写 `journal_rank_2025` 明确命中的中科院分区或北大核心；未命中、匹配不唯一或非期刊资料留空，不显示“未匹配”。
- `链接`：必须是可点击锚文本，如 `<a href="{{url}}">{{link_label}}</a>` 或 `[{{link_label}}]({{url}})`；当前 URL 直接指向 PDF，或已有结果明确标识为 PDF 资源时，`link_label` 写 `PDF`，其他来源入口写 `原链接`。不要写裸 URL、DOI、PMID 或“链接未返回”，也不为判定标签额外逐条打开网页。

无论采用 Vancouver、AMA、APA、GB/T 7714、Markdown、Word、PPT 或飞书格式，文末参考文献表的每一条正式参考文献都必须包含可点击的原文、摘要页、DOI、PubMed、期刊页、指南官网或官方入口链接之一；没有任何可点击入口的条目不得进入正式参考文献。交付前只确认每条参考文献行存在可点击来源入口，不检查标题单元格或文献题名本身是否带超链接。

## 检索策略与证据范围中的检索披露

默认完整骨架将检索披露放在参考文献前的“检索策略与证据范围”。用户任务十分明确时可进一步压缩，但只保留：

- 检索来源/数据库：PubMed/PMC、Cochrane、指南官网、学会官网、监管机构、期刊官网、ClinicalTrials.gov、CNKI/万方/中文期刊官网等实际使用来源；不要展示内部工具名。
- 核心关键词：3-8 个关键中英文词、缩写或 MeSH/Emtree 近似词；不要铺开全部检索式。
- 检索效率/上下文预算：本次用了多少检索批次、Fetch/原文阅读只读取哪些关键部分、为什么没有继续扩大检索。
- 纳入排除与覆盖局限：文献类型、人群/主题、时间范围、语言/地域、未能访问或证据不足的部分。

## 中间消息纪律

允许的中间消息：

- `正在检索和阅读核心文献，完成后会生成专业文档。`
- `完整文档一次写入受限，正在改用三块兜底。`
- `目标格式创建遇到阻断，正在准备可重试模板。`

禁止：

- 不输出完整检索流水、证据表草稿或长篇 todo。
- 不在聊天窗口输出大量文献列举、候选文献清单、筛选记录、证据矩阵或完整参考文献表；这些内容放入文档附录。
- 不在创建目标产物前把完整报告先贴到聊天窗口。
- 不把工具返回内容直接整理成用户可见正文。
- 不逐条播报“我计划”“我将继续写入”、章节、section、block ID、命令、参数纠错和重试。正常完整报告只发送一次开始状态和最终结果；只有切换三块兜底或最终阻断时才允许增加一句状态。

## 最终回复格式

最终回复保持简短，并按 `response_mode` 分流：

**`quick_answer`（patient 无明确文献/循证要求、明确轻量要求或命中窄范围检索例外；不创建产物）**

1. 核心要点回答：用 2-4 句话或 1-3 条要点直接回答检索问题。
2. 来源链接：回答中实际提到的每个外部证据都分别使用 `[来源标题或稳定简称](URL)`，不限制篇数、不得遗漏；每项核心检索结论均须可追溯，不显示纯文本题名或裸 URL。链接只采用正式发布主体、期刊/出版社官网、PubMed/PMC、DOI、监管机构、专业学会、正式说明书或可信研究注册/预印本平台等权威可追溯入口；不引用或展示自媒体、营销软文、健康博客、问答社区、内容聚合/转载、搜索结果页和来源不明页面。URL 只取检索结果结构化返回的 `url/link`；缺少协议的完整域名与路径先补 `https://`。发送前确认所有 Markdown 链接目标均以 `https://` 或 `http://` 开头，不得出现 `[标题](shturl.cc/...)`、括号中的 `shturl.cc/...` 或其他无协议裸短链；无需逐条打开或解析短链。无法取得合格 URL 的候选不得作为具名依据写入回答；没有可核验链接时明确检索限制并降低确定性。
3. 关键说明与继续调研：简要说明证据边界；`professional` 模式可给 1-3 个相关方向，`patient` 模式不主动推荐研究方向或证据空白，可询问是否需要解释某项证据。
4. 免责声明：写明“本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”
5. 深度报告引导：把“是否需要我进一步生成完整的文献检索调研报告？”作为最后一句。

**`full_report`（创建目标产物）**

1. 核心要点回答：先根据用户提问、调研主题和实际用途直接回答问题，不用“详见文档”代替回答。
2. 产物入口：`[{{飞书文档/lark-ppt 幻灯片/Word 文件标题}}]({{https_url_or_absolute_local_file_path}})`；不能只写标题。
3. 关键说明与继续调研：概括最重要的证据边界；`professional` 模式可给相关主题延伸，`patient` 模式只给与当前问题直接相关的后续说明选项。
4. 若失败：明确写 `{{产物类型}}创建失败`，说明原因，并提供可重试草稿或完整 fallback 内容。

`full_report` 未指定格式时，最终回复必须先有核心要点回答，再给飞书文档入口；飞书文档入口只要有 URL 或本地文件路径就必须写成 Markdown 可点击链接。若只有文献列表、PMID 清单、Markdown 草稿、纯标题或“已检索到若干篇”，最终回复无效。

发送最终回复前，按顺序做硬检查：

1. 最终回复开头是否根据用户提问、调研主题和实际用途，直接给出 2-4 句话或 1-3 条核心要点回答。
2. `quick_answer` 是否由 `audience_mode=patient` 且无明确文献/循证/正式产物要求、用户明确轻量要求，或单篇具名论文、单份具名指南、单一明确年份的窄范围检索触发；是否没有覆盖用户对查阅文献、循证分析、完整报告或正式文档的明确要求；每个被提及的外部证据是否都有各自的权威可追溯 URL，且链接目标以 `https://` 或 `http://` 开头、没有无协议短链；是否未引用或展示自媒体等非权威页面，并在最后追问前展示免责声明。
3. 如有目标产物，其文末参考文献表是否每行都有可点击来源入口；不逐条检查正文标题或文献题名本身是否带超链接。
4. 最终回复是否按 `audience_mode` 给出合适引导：`professional` 可推荐 1-3 个相关方向，`patient` 不主动展开研究方向或证据空白；未创建飞书文档时，是否询问“是否需要我进一步生成完整的文献检索调研报告？”

任一项为否，不发送最终回复，回到修复步骤。

## 最小 QA

交付前检查：

- `response_mode` 已按用户要求与受众模式判定；`audience_mode=patient` 且无明确文献查阅、循证分析、完整报告或正式文档要求时已使用 `quick_answer`。除此例外，普通的“未主动要求文档”、问题聚焦、文献较少或已有足够信息未被误判为 `quick_answer`，单篇具名论文、单份具名指南或单一明确年份的窄范围例外已正确识别。
- `full_report` 已生成目标产物，或已明确失败原因和可重试草稿；`quick_answer` 已按聊天短答交付。
- 最终回复和文档第一章已覆盖用户明确提出的对象、问题、字段、时间/来源范围和交付形式；证据不足项已明确披露，没有静默缺项，也没有用文档链接、过程说明、文献罗列或“详见文档”代替回答。
- `full_report` 且用户未明确格式时，目标产物是通过平台已配置的 `lark-doc` 创建或更新并完成回读验证的飞书文档；最终回复包含飞书文档链接或可打开入口。URL、文档标识或 `revision_id` 未被单独当作成功证据。
- create/fetch/update 均使用 v2；每个飞书响应满足顶层 `ok=true`、存在时 `data.result=success`、warnings 为空，预期更新数大于 0。`failed`、`partial_success`、warning、权限未完成或回读缺失均未被当作成功。
- 默认使用完整 XML 一次创建。只有明确的载荷或长度失败才启用三块兜底；锚点来自本次实际目录，大块内不重复锚点标题，也未继续展开成逐章更新。
- 已直接调用平台配置的 `lark-doc` Skill，没有执行 `which lark-cli`、`lark-cli skills read`、`lark-cli docs skills` 或帮助探测来寻找 Skill。
- 聊天正文-only、文献清单-only 或 PMID 列表-only 不算 `full_report` 交付完成。
- 聊天窗口没有铺开大量文献列举、候选清单、筛选记录、证据矩阵或完整参考文献表；这些内容已放入文档或附录。
- 飞书完整报告以不编号“总结”高亮块开头，第一章标题根据用户 Query 提炼，并先写“问题小结”后深入回答；若用户指定输出形式，核心结果已在第一章按该形式呈现。前文已完整覆盖的重复章节可合并、缩减或删除，后续已补齐尚未回答的重要证据、局限和来源链接；第八章“检索策略与证据范围”紧邻参考文献并只精简写明必要边界，全文不出现内部工具名称或 `xx_search`。
- 检索轮次符合上下文预算：`quick_answer` 一般 1-2 个批次，默认 `full_report` 2-4 个批次，复杂课题一般不超过 5 个批次；超过时已在“检索策略与证据范围”中精简说明理由。
- 用户明确限定只查指南、只查共识或其他指定证据类型时，正文和参考文献没有擅自扩展研究论文或范围外证据。
- 医学资讯跟踪任务已覆盖近期权威动态和对应原始证据，明确日期、来源类型与证据状态；预印本已标明“预印本/未同行评议”，新闻稿、资讯页面或预印本未被单独写成已确立的疗效、安全性结论。
- `patient` 模式已使用严谨易懂的表达，未主动罗列研究方向、课题建议、证据空白或无关风险；必要证据边界仍有说明。
- Fetch/原文阅读没有把整页网页、整份 PDF 或低相关内容大量塞入上下文；只读取与核心结论、图表节点或正式参考文献相关的摘要、推荐条文、主要结果、关键表格和局限。
- 核心结论可追溯到证据表、正文链接和参考文献。
- `full_report` 已运行本地期刊级别匹配；正式文档中的期刊论文并列展示 Oxford CEBM 2009 证据级别和已命中的期刊级别，未命中、匹配不唯一或非期刊资料没有占位提示。
- 文末参考文献表每条正式参考文献都有可点击的原文、摘要页、DOI、PubMed、期刊页、指南官网或官方入口链接之一，不因引用格式不同而省略链接；默认飞书文档参考文献表固定为 `标题｜来源｜类型｜年份｜期刊分区｜链接` 六列；无任何可点击入口的资料不得出现在最终参考文献表；文末链接不能替代正文提及处的就地链接。
- 内部 CSV 已按保留文献的写入行顺序生成 `citation_number`，没有为正文顺序反复回填或重排；正文、参考文献以及实际生成的图表/图例均复用该列的 `[n]`，不得出现章节独立编号或 `G1`、`R1`、`SR1` 等类型前缀号。
- 输出正文、“检索策略与证据范围”和最终回复没有出现 `medical_search`、`scholar_search`、`general_search` 或任何 `xx_search` 内部工具名。
- 可见报告、PPT、Word 和最终回复没有展示模板/QA 指令，例如“正文引用链接要求”“本节图表要求”“写法要求”“参考文献链接要求”“要求：正文页提及”等；这些约束只能存在于模板注释、reference 或脚本校验中，不能成为用户可见正文。
- 输出没有使用高程度或绝对化结论措辞；正式文档如需描述指南分级，写明原指南体系和原文等级，不与 Oxford 等级混写。
- 公式上标使用 Unicode 字符（如 ²、³、⁻¹），不使用 sup 标签；飞书文档 XML 不包含原始、转义、双重转义、数字实体或样式化 HTML 上标，也不包含 `<ref>` 标签或其转义形式。已对最终写入文件实际运行清理脚本和校验脚本，且两者退出码均为 0；citation 引用组件不受此限制。
- 文档结构服务于用户检索目标：多个对象且维度可横向对齐时已优先用对比表集中呈现；用户指定的表格、清单或对照内容已靠前完成。重点指南和核心研究的讨论深度与问题关联度匹配，外围内容保持简洁，没有平均分配篇幅。
- 除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上且用户未明确拒绝图表时，文档已同时包含证据脉络思维导图和关键研究里程碑时间线图。
- 若生成了时间线图或证据脉络思维导图，文献节点均使用统一 `[n]` 编号，且图例提供链接；相关文献不足 5 篇、用户明确拒绝图表，或医学资讯跟踪中图表不能增加信息时，未生成白板图不影响合格判定。
- 用户可见产物中没有出现内部 `evidence_id`；正文、图表、图例和章节标题均使用可点击来源名称或可读文献简称。如采用引用编号，只出现与全文一致的 `[1]`、`[2]` 连续序号。
- 已运行飞书 XML 校验；若文档包含 Mermaid 白板，其语法和内容已通过检查。
- 实际生成的图表节点能回到参考文献表，且图例提供链接。
- 参考文献分为核心证据和辅助参考。
- 热点或主题簇分析说明数据来源和局限。
- 论文写作支持中，每个引用和论点对应清楚。
- 药物、安全性、器械或监管问题已查权威来源。
- `quick_answer` 已展示免责声明；自媒体、营销资料、健康博客、问答社区、内容聚合/转载、搜索结果页或来源不明页面既未作为依据，也未出现在可见来源中。
- 未伪造 GRADE、PRISMA、Meta 分析、影响因子、分区、DOI、PMID 或研究数据。
- 输出没有变成具体患者诊疗指令。
