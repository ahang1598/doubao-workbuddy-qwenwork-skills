# 输出与交付

镜像链接可以作为引用链接，保留原始镜像 URL，无需替换为主站链接；聊天引用和正式文档超链接均可使用。

本文件只管“怎么交付”。非默认格式路由见 `output-format-routing.md`。

本文件的固定章节、双图、逐篇解读、分区/等级展示和参考文献表用于普通调研报告。`writing_mode=review_manuscript` 时，按 `review-manuscript-and-citations.md` 及目标期刊要求组织论文并交 `word` 生成；用户要求国标时，参考文献采用该专用文件的著录规则。稿件仍保持来源链接、引用对应和最终文件交付。

## 聊天引用

- `seed_medical_search` 已在当前可用工具列表中，直接调用即可；不得使用 `tool_search` 搜索、发现或确认该工具。
- 聊天引用按 `SKILL.md` 执行：`seed_medical_search`、`general_search` 结果积极使用 `<RichMediaReference>["真实URL"]</RichMediaReference>`，组件位于对应句子的标点之后；其他来源使用可点击标题超链接。`aka.doubaocdn.com` 域名的内容可以引用，也可以展示。搜索工具返回的第三方存储/索引 PDF 资料可以引用和展示；PubMed、PMC、DOI 解析、期刊官网和 Semantic Scholar 均可。保留工具返回的原始 URL，不因第三方域名改换到主站；按内容真实性、研究质量与问题相关性判断来源。飞书 XML、PPT、Word 等文档统一使用超链接。
- 使用 Markdown 超链接时，锚文本采用工具返回的完整来源标题或稳定简称；链接取实际返回的 `url/link`。

## 默认输出

先按 `audience_mode` 调整表达。`professional` 保留专业术语和与任务相关的研究空白、课题或引用建议；`patient` 解释必要术语，优先回答用户关心的问题，保持严谨但不过度制造焦虑，不主动罗列研究方向、课题建议、证据空白或无关风险。两种模式使用相同的来源质量、链接和核验标准。

`response_mode=full_report` 且用户没有明确表达预期格式、也未命中投稿综述时，必须创建飞书文档；不要用聊天正文、Markdown、独立表格、Word 或 PPT 代替默认交付。投稿综述默认交付 `word` 生成的论文 `.docx`。用户明确要求 Markdown、Excel/xlsx、PPT 或 Word/docx 时，保持 `full_report` 并按用户指定格式输出；其中 Word/docx 必须通过 平台 `word` Skill生成真正 `.docx`。

用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel/xlsx`，按飞书文档交付：在文档中插入所需表格，并保留结论、解读、证据边界和来源链接等常规正文。不得把普通表格请求降级为聊天表格或纯 Markdown 表格。

`response_mode=quick_answer` 由以下任一条件触发：`audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；用户明确要求快速回答、简短、精简、概括、小结、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；检索范围仅限单篇具名论文、单份具名指南、单一明确年份且未要求完整报告或正式文档。默认做 1 个高价值批次，以普通聊天直接回答；回答中提到的每个外部证据都必须各自带可点击 URL，不限制来源篇数、不得漏链，并使每项核心检索结论均可追溯。不创建飞书文档、PPT 或 Word。

聊天回答围绕结论、相关风险和关键证据展开，按问题需要充分解释。完整报告及文献表放入飞书文档；XML、CSV 和执行过程仅内部保留。

## 先满足用户需求，再完成标准文档

飞书文档标题后先放不编号的“总结”高亮块；第一章标题根据用户 Query 提炼为回答型专业小标题，并对照需求清单完整回答用户最关心的问题和每个明确提出的字段。涉及多个可比较对象且主要维度可对齐时，优先在第一章用对比表集中呈现，再用正文解释差异、证据边界和不可直接比较之处；用户指定的表格/清单结构、呈现顺序或核心文献解读应原样优先满足。第二章起用飞书标准骨架检查内容覆盖：前文已经明确回答且证据、链接和边界完整的重复内容可以合并、缩减或删除；尚未覆盖的重要证据、局限、建议、带链接参考文献和免责声明仍须补齐。相关文献不足 5 篇时图表可按需省略，达到 5 篇及以上时除非用户明确拒绝，仍需在第一章之后插入两张主图；医学资讯跟踪在图表不能增加信息时可省略。

`full_report` 使用六列 CSV 保留题录、原始链接和 `journal_rank_2025`，正文、图表和参考文献复用稳定的 `citation_number`。类型、证据级别与结果解读直接依据实际核实原文。

飞书报告按 `assets/feishu-doc-template.xml` 生成内容，调用平台 `lark-doc/online-doc` 创建；长度受限时按实际需要分块。`full_report` 默认交付聊天回答和飞书文档链接。XML、CSV 和原始草稿仅作内部过程文件保留，`present_files` 不选择这些文件；用户明确要求 PPT、Word 等最终格式时继续按相应路由交付最终产物。 `present_files` 的具体参数按环境工具合同。

默认飞书文档结构：

0. 不编号“总结”高亮块：概括核心结论、实践启示和证据边界；`professional` 模式可按任务补充研究局限和空白
1. 根据用户 Query 提炼的回答型专业小标题：先写“问题小结”，再深入回答用户问题；用户指定核心交付物也放在本章
2. 证据脉络与研究关系：论文关系梳理、关键里程碑
3. 指南与专家共识
4. 系统综述与关键研究
5. 其他相关研究
6. 最新进展、热点、争议与空白；医学资讯跟踪任务改为“最新医学资讯与证据状态”
7. 学习、课题或论文写作建议；`patient` 模式除非用户明确要求，否则删除
8. 检索策略与证据范围（含精简检索方法与关键词）
9. 完整参考文献（含链接）
10. 免责声明

上述目录是飞书完整报告的覆盖检查骨架，而非必须逐章复述的固定目录。用户指定格式时，在第一章按要求呈现核心交付物，并自由调整各章篇幅与章内呈现方式；第一章已完整覆盖的对应章节或重复内容可以合并、缩减或删除，但不得遗漏尚未回答的重要证据、局限、建议和带链接参考文献。用户明确只查指南、共识或其他证据类型时，删除范围外章节并顺延编号，不保留空标题，也不为填满骨架补充范围外文献。检索策略与证据范围可精简，图表按限定范围和触发规则保留或省略。

医学资讯跟踪可进一步按资讯任务重组目录，以“时间窗与截止日期、最新动态、对应证据、证据状态、增量意义、完整参考文献”为主线。指南、系统综述、关键研究、其他相关研究、学习/课题建议和两张白板图仅在能提供独立信息时保留，可合并、改名、调整顺序或省略；不得为了对齐默认章数重复内容或保留空标题。少量纳入的预印本应在正文和参考文献类型中标明“预印本/未同行评议”。

## 强制样式

飞书完整报告应图文并茂但不牺牲准确性。用户指定的核心交付物优先采用其要求的格式；后续内容只补充尚未覆盖的主要证据，已在前文完整回答的对应章节或重复内容可合并、缩减或删除，不机械堆叠重复表格、图表或结论。标准骨架通常包含：

- 总结与第一章：标题后先用不编号的“总结”高亮块概括结论、实践启示和证据边界；除栏目标签外，可适度加粗关键结论、重要数字和限制条件。第一章标题根据用户 Query 提炼，以普通正文中的加粗“问题小结”开篇，再按需求使用二三级标题、自然段、列表或对比表深入回答；非比较任务不强制表格。
- 检索策略与证据范围：固定放在参考文献前；任务明确时可缩为短段或小表，只保留会影响结果理解的来源、关键词、检索边界、纳入排除和覆盖局限。
- 可视化组：除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上时，除非用户明确要求不要图表，同时插入证据脉络思维导图和关键研究里程碑时间线图；不足 5 篇时，仅在证据类型多、研究演进重要或结论关系复杂时按需插图。
- 指南与专家共识、系统综述、关键研究和最新进展章节优先用“每篇/每份文献一个小节”的段落解读；与用户问题和核心结论关系较大的指南或研究可适度展开关键条文、研究设计、结果、适用边界及实际意义，外围或重复证据简写，不按文献数量平均分配篇幅。第四章开头使用一个浅蓝 callout，简要说明本章按问题匹配度、研究设计适切性、信息量与精确性、偏倚风险、endpoint 质量以及一致性/可重复性筛选，并直接概括各类关键证据分别贡献了什么、主要限制是什么、当前证据能支持到什么程度；不为六个维度建立评分或表格。第四章每篇研究仍须标注期刊名称和年份，并在末尾用一句自然语言给出“研究价值短评”，依次说明可支持的具体判断、关键依据和主要边界，不机械罗列六项，也不据此给研究排座次。样本量、事件数、随访或覆盖范围应在设计与结果中写明实际数据，短评只说明这些事实如何影响精确性或适用性，并使用非排序表述。
- “其他相关研究”使用无序列表，不使用表格。每篇写可点击标题、期刊、年份和类型，并用 4-6 句话总结研究核心内容和主要结论，用于筛选文末参考文献中未在第四章详细解读的研究。
- 学习、课题或论文写作建议按用户用途自由组织，优先用无序列表分点呈现学习路径、课题机会、论文引用用途和引用风险；可用加粗、浅黄提示或语义色突出重点，不要默认约束为表格。
- 医学资讯跟踪按时间或主题呈现“动态、日期、发布主体、对应原始证据、证据状态和增量意义”；正式指南/论文、在线优先、预印本/未同行评议、会议摘要/发布、试验注册更新和机构新闻稿必须区分，不把资讯标题或预印本发现直接写成成熟医学结论。资讯主线完整时可省略无独立价值的标准章节和白板图。
- `patient` 模式保留直接回答、关键文献和必要证据边界；除非用户明确要求，不生成研究方向、课题建议、证据空白清单或无关风险扩展。
- 任务相关补充内容优先用正文段落或短列表；争议、研究空白、引用逻辑、学习路径或指南差异确实需要横向比较时，才补充标准表格。只有用户明确要求，或确实能稳定映射为飞书标准图型时，才额外生成图。
- “检索策略与证据范围”固定为第八章、紧邻参考文献，只保留外部来源、核心关键词、检索批次/效率、纳入排除和证据覆盖局限。不要铺开完整检索流水或大量关键词组合。

语义色建议：

| 用途 | 颜色 |
|---|---|
| 核心结论/证据方向一致 | `light-green` |
| 检索范围/背景说明 | `light-blue` |
| 证据有限/待核验/需谨慎 | `light-yellow` |
| 证据冲突/争议 | `light-orange` |
| 安全警示/不支持 | `light-red` |

不要生成伪医学影像、伪数据可视化或难以在飞书稳定显示的复杂 diagram。热点主题表若基于本次检索归纳，必须说明不等同于完整文献计量分析。

## 飞书写法

优先使用：`<title>`、`<h1>`、`<h2>`、`<callout>`、`<table>`、`<ul>`、`<ol>`、`<a href="https://...">来源标题</a>`、`<whiteboard type="mermaid">`。

禁止在飞书文档 XML 中使用 HTML 上标标签，也不得使用 `<ref>` 标签或其转义形式。不要用这些标签做引用编号、脚注或证据编号；直接改用可点击文献名、含来源超链接的 citation 样式容器或文末参考文献表。

正文所有被引用的文献名本身必须带超链接；首次出现时标注来源/期刊和年份。正式文档中的期刊论文按需标注 Oxford CEBM 2009 证据级别，并并列展示索引明确命中的 2025 中科院分区/北大核心；指南/共识的 Oxford 证据级别写 `不适用`，其原文分级体系和推荐等级另行保留。研究推荐写法：`<a href="{{url}}">{{文献名或研究简称}}</a>（{{来源/期刊}}，{{年份}}；Oxford CEBM 2009：{{1a-5；研究设计信息不足时填“暂未分级”}}；期刊级别：{{命中的中科院分区/北大核心}}）`。期刊级别未明确命中、匹配不唯一或来源不是期刊论文时，省略整个“期刊级别”字段，不显示占位词。参考文献表不能替代正文链接，不能只写编号、PMID、DOI 或纯文本题名。文献题名清单、候选文献列表和编号参考文献列表也必须逐条链接题名；`1. 文献题名。期刊，年份。` 这种无链接列表视为交付失败。

正文不能出现无链接来源小标题。以下写法不合格：

`《某某疾病诊疗指南（2025）》`

`DAPA-CKD 研究显示...`

正确写法是把来源名本身做成链接：

`<a href="{{url}}">某某疾病诊疗指南（2025）</a>（{{来源/期刊}}，2025；原指南分级按原文保留）`

`<a href="{{url}}">DAPA-CKD</a>（NEJM，2020，RCT；Oxford CEBM 2009：1b；期刊级别：中科院 1 区）显示...`

Oxford CEBM 2009 等级、期刊级别及其说明只写入正式飞书、Word 或 PPT 产物。聊天 Quick Answer 和最终入口回复保持简洁，不逐条展示这些分级，也不重复文末说明。

表格建议：

- 检索问题表：主题、框架、范围、结局、时间、语言、纳入/排除。
- 指南对比表：仅在需要横向比较多份指南差异时使用，包含指南、机构/年份、推荐、强度/证据等级、适用范围、更新点；单纯“指南与专家共识”章节默认用逐条解读。
- 关键研究解读：每篇文献一个小节，题名或研究简称可点击，明确标注期刊、年份、Oxford CEBM 2009 证据级别和已命中的期刊级别，并解释主要结论、局限和引用用途。
- 其他相关研究：用带链接的无序列表逐篇呈现 `标题（期刊，年份；类型；Oxford CEBM 2009；命中的期刊级别）`，每篇随后用 4-6 句话总结研究核心内容和主要结论，不使用表格；期刊级别未命中时直接省略。
- 热点表：主题簇、代表文献、近年变化、证据强度、研究空白。
- 论文引用对照表：仅在用户明确需要论文写作引用安排时补充；学习、课题或论文写作建议章节默认不用表格。

Mermaid 白板必须遵守 `synthesis-and-visualization.md` 中的安全规则。

## 参考文献

文末参考文献分组：

1. 核心证据：质量高、来源权威、与当前主题高度匹配且能支撑关键结论；不按全文可及性机械分组。
2. 辅助参考：低级别、不权威、方法学薄弱、与主题匹配度较低，或仅用于背景、教材/实践说明和研究线索的资料；不得单独支撑关键疗效或安全性结论。
3. 排除/待核验：只在需要透明展示筛选时列代表性记录。

默认飞书文档的完整参考文献必须用表格承载，不用纯编号列表承载。除非用户明确要求特定参考文献格式，文末参考文献表固定为六列：`标题｜来源｜类型｜年份｜期刊分区｜链接`。用户要求国标时按 `review-manuscript-and-citations.md` 生成规范参考文献条目，正文和文末统一使用相应引文编号与来源链接。
表内不新增编号列；“标题”单元格使用 CSV `citation_number` 写成 `[n] 可点击完整题名`。

- `标题`：完整题名、指南名、试验名、教材/监管来源名。
- `来源`：期刊、机构、数据库、监管机构或教材来源。
- `类型`：指南、共识、系统综述、Meta、RCT、队列、诊断研究、真实世界研究、安全监管、教材/实践资料或辅助参考等；仅对确实阅读全文的重要论文，可在类型后追加 `已阅读全文`。
- `年份`：发表、发布或更新年份；不清楚写 `未返回`。
- `期刊分区`：期刊论文填写 已明确核实的中科院分区或北大核心；未命中、匹配不唯一或非期刊资料填 `-`。
- `链接`：必须是可点击锚文本，如 `<a href="{{url}}">{{link_label}}</a>` 或 `[{{link_label}}]({{url}})`；当前 URL 直接指向 PDF，或已有结果明确标识为 PDF 资源时，`link_label` 写 `PDF`，其他来源入口写 `原链接`。不要写裸 URL、DOI、PMID 或“链接未返回”，也不为判定标签额外逐条打开网页。

无论采用 Vancouver、AMA、APA、GB/T 7714、Markdown、Word、PPT 或飞书格式，文末参考文献表的每一条正式参考文献都必须包含可点击的原文、摘要页、DOI、PubMed/PMC、Semantic Scholar、期刊页、工具返回的 PDF 或索引入口链接之一；没有任何可点击入口的条目不得进入正式参考文献。

## 检索策略与证据范围中的检索披露

默认完整骨架将检索披露放在参考文献前的“检索策略与证据范围”。用户任务十分明确时可进一步压缩，但只保留：

- 检索来源/数据库：PubMed/PMC、Cochrane、指南官网、学会官网、监管机构、期刊官网、ClinicalTrials.gov、CNKI/万方/中文期刊官网等实际使用来源；不要展示内部工具名。
- 核心关键词：3-8 个关键中英文词、缩写或 MeSH/Emtree 近似词；不要铺开全部检索式。
- 检索效率/上下文预算：本次用了多少检索批次、Fetch/原文阅读只读取哪些关键部分、为什么没有继续扩大检索。
- 纳入排除与覆盖局限：文献类型、人群/主题、时间范围、语言/地域、未能访问或证据不足的部分。

## 中间消息纪律

允许的中间消息：

- `正在检索和阅读核心文献，完成后会生成专业文档。`
- `完整文档一次写入受限，正在分块完成。`
- `目标格式创建遇到阻断，正在准备可重试模板。`

禁止：

- 不输出完整检索流水、证据表草稿或长篇 todo。
- 不在聊天窗口输出大量文献列举、候选文献清单、筛选记录、证据矩阵或完整参考文献表；这些内容放入文档附录。
- 不在创建目标产物前把完整报告先贴到聊天窗口。
- 不把工具返回内容直接整理成用户可见正文。
- 不逐条播报“我计划”“我将继续写入”、章节、section、block ID、命令、参数纠错和重试。正常完整报告只发送一次开始状态和最终结果；需要说明实际变化时补充一句状态。

## 最终回复格式

聊天回答直接给出结论、相关风险和依据，篇幅按问题需要展开，不设 Skill 预定字数、句数或要点数量上限；用户明确限制篇幅时按用户要求。优先在相关句子的标点之后，用角标引用最重要的依据。 按 `response_mode` 分流：

**`quick_answer`（patient 无明确文献/循证要求、明确轻量要求或命中窄范围检索例外；不创建产物）**

`quick_answer` 下，内容适合图表展示时，可根据情况读取并使用 `doubao-visualization` Skill，在聊天回答中补充图表。 如果选择 `quick_answer` 模式，且问题需要检索相关图片、加入图片有助于提升回答效果，可先通过 `tool_search` 发现 `visual_search` 工具，再使用该工具搜索图片，并按工具返回的图片和来源信息在回答中引用展示。

1. 核心回答：直接回答检索问题，说明相关风险与重要依据，按问题需要展开。
2. 来源链接：聊天回答（包括 `quick_answer` 和 `full_report` 的最终摘要）直接引用 `seed_medical_search`、`general_search` 的结果时，积极使用 `<RichMediaReference>["真实URL"]</RichMediaReference>`，组件紧跟对应句子的标点之后；同处多个来源使用纯 URL JSON 数组。URL 取工具实际返回的 `url/link`，与来源标题成对保留；其他检索来源可用可点击标题超链接。采用内容可靠且可追溯的资料入口，保留工具返回的原始 URL。`aka.doubaocdn.com` 域名的内容可以引用，也可以展示。搜索工具返回的第三方存储/索引 PDF 资料可以引用和展示；PubMed、PMC、DOI 解析、期刊官网和 Semantic Scholar 均可。保留工具返回的原始 URL，不因第三方域名改换到主站；按内容真实性、研究质量与问题相关性判断来源。飞书 XML、PPT、Word 等文档产物统一使用可点击超链接。
3. 关键说明与继续调研：简要说明证据边界；`professional` 模式可给相关方向，`patient` 模式不主动推荐研究方向或证据空白，可询问是否需要解释某项证据。
4. 免责声明：写明“本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”
5. 深度报告引导：把“是否需要我进一步生成完整的文献检索调研报告？”作为最后一句。

**`full_report`（创建目标产物）**

1. 核心要点回答：先根据用户提问、调研主题和实际用途直接回答问题，不用“详见文档”代替回答；若聊天摘要直接引用外部证据，仍按上述来源工具分流规则呈现链接。
2. 产物交付：默认给出飞书文档链接；用户明确要求其他最终格式时，`present_files` 仅选择最终产物或其链接，参数按环境工具合同。XML、CSV 和原始草稿仅内部保留。
3. 关键说明与继续调研：概括最重要的证据边界；`professional` 模式可给相关主题延伸，`patient` 模式只给与当前问题直接相关的后续说明选项。
4. 若失败：说明创建情况与原因，聊天中给出已核实的结论、相关风险和关键来源；原始草稿保留在内部供继续处理。

`full_report` 未指定格式时，最终回复必须先有核心要点回答，再给飞书文档入口；飞书文档入口只要有 URL 或本地文件路径就必须写成 Markdown 可点击链接。若只有文献列表、PMID 清单、Markdown 草稿、纯标题或“已检索到若干篇”，最终回复无效。

## 内容与交付

- 正式表格单元格中，不详、缺失、未提供、未核验、不明确、无法明确、未知、暂未分级、未匹配、空值和不适用的证据等级统一显示 ASCII `-`。只替换缺失字段值，保留单元格中已知信息、实际风险或争议说明及官方等级。正文据实表达，期刊级别无匹配时在正文省略；表格占位符转换不回写 CSV。

- 回答覆盖用户指定问题、字段、范围和格式，研究解释与实际核实的来源相符。
- 正文、表格使用一致的文献编号与可点击来源链接；重要阈值、官方用词、适用人群与统计口径核对原文。
- 飞书、PPT、Word 各按对应平台 Skill 生成。
- 本次拟纳入文献整理后一次运行 CSV 批量匹配；直接使用 stdout JSON 的 `results` 写正文与参考文献表，无需额外 Read CSV 获取期刊级别。后续新增需要匹配的期刊时再按需执行。
- 按任务需要保留证据脉络、里程碑和文献解读，患者模式聚焦当前问题。
- 默认交付聊天回答和飞书文档链接；`present_files` 仅选择用户要求的最终产物，XML、CSV 和原始草稿内部保留。
