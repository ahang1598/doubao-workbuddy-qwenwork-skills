# 核心流程

本文件只管“如何理解用户意图、如何拆解检索任务、如何组织综合”。证据来源和质量评价见 `evidence-sources-and-appraisal.md`，图表见 `synthesis-and-visualization.md`，交付见 `output-and-qa.md`。

## 1. 判断任务类型

先用一句话复述用户真正要解决的问题，例如：

`我理解本次要回答的是：围绕 {{主题/疾病/药物/问题}}，系统检索并综合 {{指南/关键研究/最新进展/热点/论文引用}}，用于 {{学习/课题/论文/汇报/临床实践参考}}。`

将任务归入一个主场景，可有 1-2 个辅场景：

| 场景 | 用户常见说法 | 核心产出 |
|---|---|---|
| 主题循证综述 | 查某疾病、症状、检查、治疗、科室问题的文献 | 结论、指南、关键研究、证据等级、临床意义 |
| 指南/共识查新 | 查最新指南、专家共识、推荐变化 | 指南要点解读、推荐差异、更新点、适用边界 |
| 研究热点/前沿 | 分析某领域研究热点、趋势、最新进展 | 主题簇、时间线、里程碑研究、前沿问题 |
| 医学资讯跟踪 | 查最近发布、近期动态、领域新消息或持续跟踪某主题 | 按时间整理权威资讯、对应原始证据、证据状态和实际意义 |
| 课题论证 | 分析某课题有没有价值、研究基础和空白 | 研究现状、争议、空白、可行研究方向 |
| 论文写作支持 | 为论文引言、讨论、综述补文献或引用 | 引用逻辑、可用文献表、段落草稿、参考文献 |
| 学习资料 | 整理某病种/药物/指南用于进阶学习 | 知识框架、指南要点、关键研究、学习路径 |
| 文献支持型研究/论文问题 | 用文献支撑研究设想、论文段落、综述观点或课题论证 | 文献证据链、引用来源、引用用途和局限 |

用户想直接查找或获取指南、共识、研究本身，或梳理相关文献清单、证据脉络、最新医学资讯时，继续本 Skill。普通患者/用户主动选择本 Skill，或明确希望查阅、梳理更多医学文献进行循证以理解医疗问题时也继续本 Skill，并设为 `audience_mode=patient`。若用户要某个具体患者/临床问题的诊断、检查、用药或治疗答案，转向 `doubao-clinical-decision-support`；若患者主要询问报告异常含义、复查或就医沟通且未要求文献调研，转向 `doubao-medical-report`。若用户只是借病例限定文献检索人群，最终要的是综述、研究进展、资讯跟踪、课题或引用清单，继续本 Skill。

### 1.1 判定 audience_mode

| audience_mode | 判定 | 表达与内容取舍 |
|---|---|---|
| `professional` | 医疗从业者、研究者、医学生或医学内容团队 | 保留专业术语和与任务相关的研究空白、课题或引用建议 |
| `patient` | 普通患者/用户主动选择本 Skill，或希望查阅更多医学文献循证理解医疗问题 | 解释必要术语，优先回答其关心的问题；不主动列研究方向、课题建议、证据空白或无关风险 |

`audience_mode` 不改变来源准入、链接和核验标准。`audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档时，参与路由并固定使用 `quick_answer`。

### 1.2 判定 response_mode

| response_mode | 唯一触发条件 | 工作深度与交付 |
|---|---|---|
| `quick_answer` | `audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；或用户明确要求快速回答、简短、精简、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；或检索范围仅限单篇具名论文、单份具名指南、单一明确年份，且未要求完整报告或正式文档 | 仅做 1-2 个高价值批次，以聊天回答；每个被提及的外部证据各自带可点击 URL，不创建产物 |
| `full_report` | 除上述明确要求外的所有本 Skill 任务 | 完成检索、筛选、证据综合和目标产物；未指定格式时创建飞书文档 |

先检查上述 `patient` 例外，再检查用户明确提出的轻量要求或窄范围检索边界。除 `patient` 例外外，一般性问题聚焦、需求明确、文献较少、已有足够信息、用户没有主动要求文档或 Agent 认为可以直接回答，均不构成 `quick_answer` 条件；单篇具名论文、单份具名指南或单一明确年份是例外。用户明确要求查阅/梳理文献、循证分析、完整报告或正式文档时使用 `full_report`。无法确定时使用 `full_report`，不要反复讨论模式；`full_report` 一经判定即保持到交付完成。

`quick_answer` 仍需完成必要的高价值检索。回答中提到的每篇指南、共识、论文、试验、说明书或监管来源，都必须在对应正文位置使用可点击标题或简称；不得只在文末统一列链接，也不得把无链接候选写成具名依据。

来源标题与检索结果结构化返回的 `url/link` 必须成对保留，不从摘要或展示文本手抄链接。生成 `quick_answer` 前，将缺少协议的完整域名与路径统一补为 `https://...`，再渲染成 `[来源标题或稳定简称](URL)`；所有链接目标必须以 `https://` 或 `http://` 开头。发现 `[标题](shturl.cc/...)`、普通括号中的 `shturl.cc/...` 或其他无协议裸短链时，先补协议并重新渲染。这里只做格式规范化，不逐条打开、解析或核验短链。

用户明确要求 PPT、Word、Markdown 或 Excel/xlsx，但没有要求简短或不要文档时，仍为 `full_report`，只改变目标格式。用户要求创建表格、对照表、清单或矩阵但未指定 `Excel/xlsx` 时，目标产物固定为飞书文档，表格嵌入正文并配套结论、解读、证据边界和来源链接。文本润色、翻译、总结、仿写或缩写不属于本 Skill，不进入任一响应模式。

用户对证据类型的限定独立于 `response_mode`，必须原样遵循。明确要求“只查指南”“只查共识”或只查某种研究设计时，即使采用 `full_report`，也只规划对应检索批次、正文和参考文献，不自动补充其他证据类型。只限定证据类型不等于指定单份具名文献，不单独触发 `quick_answer`。

### 1.3 先确定前置核心交付物

以满足用户的实际检索需求为第一目标。用户给出明确的比较对象、字段、表格/清单结构、关注顺序，或要求围绕少数核心文献深入解读时，先规划用户指定的核心交付物。

生成飞书文档时，标题后先用不编号的“总结”高亮块概括结论、启示与主要边界；第一章标题根据用户 Query 提炼，专门深入回答用户最关心的问题。第一章以普通正文中的加粗“问题小结”开篇，再按实际问题自由组织二三级标题、段落和列表；用户指定的统一对照表、筛选清单或核心文献深度解读也放在本章。第二章起以飞书模板检查证据覆盖：第一章已经明确回答且证据、链接和边界完整时，后续重复内容可合并、缩减或删除；尚未覆盖的证据脉络、指南/共识、关键研究、其他研究、最新进展与空白、建议和带链接参考文献再按需补齐。“检索策略与证据范围”固定放在完整参考文献之前，可压缩为短段或小表；相关文献不足 5 篇时图表不是必选项，达到 5 篇及以上时除非用户明确拒绝，仍需生成两张主图。医学资讯跟踪按专用主线组章，图表不能增加信息时不受该数量触发规则约束。

用户没有指定特殊格式时，直接使用默认骨架；用户指定了格式时，在骨架中前置并突出核心交付物，再把骨架当作覆盖检查清单。不要机械保留与前文重复的章节，但不得遗漏尚未回答的重要证据、局限和来源链接。

## 2. 界定检索边界

优先从用户原话中抽取边界；信息不足时使用透明默认值，不要反复追问。

| 边界 | 默认做法 |
|---|---|
| 人群/疾病 | 使用用户给出的疾病、症状、科室、药物或研究对象；缺失时按通用成人/常见临床场景处理并说明 |
| 干预/暴露 | 药物、手术、检查、危险因素、护理措施、管理策略、机制或研究变量 |
| 对照/参照 | 标准治疗、安慰剂、无暴露、其他方案、健康对照或历史研究 |
| 结局 | 疗效、安全性、死亡、复发、住院、诊断性能、生活质量、指南推荐、研究趋势 |
| 时间范围 | 最新进展默认近 5 年；指南查新默认近 5-10 年并优先最新版；里程碑研究不受年份限制 |
| 资讯时效 | 医学资讯跟踪按用户指定窗口；未指定时优先最近 3-12 个月，并明确检索截止日期 |
| 语言/地域 | 中英文优先；涉及中国实践时加入中文指南、专家共识和本土研究 |
| 文献类型 | 按任务选择指南、共识、系统综述、RCT、队列、真实世界研究、诊断研究、机制研究、教材/专著、安全来源 |
| 输出深度 | 用户明确要求短答、限字、不要文档，或检索仅限单篇具名论文、单份具名指南、单一明确年份且未要求正式产物时使用 `quick_answer`；其余使用 `full_report` |

复杂问题拆成 2-5 个可检索子问题，避免一个检索式包打天下。

## 2.1 上下文预算与效率

先估算任务深度和可用上下文，再决定检索轮次与 Fetch 深度。目标是覆盖关键证据，而不是穷尽所有搜索结果。

| 任务深度 | 检索预算 | Fetch/精读预算 |
|---|---|---|
| `quick_answer` | 1-2 个高价值批次；每批 3-6 条候选 | 通常只打开摘要页/官方入口，确认题名、年份、来源和链接；不创建文档 |
| `full_report` | 2-4 个高价值批次；初筛候选总量约 12-36 条 | 定向精读 1-3 份核心指南/综述/关键研究；其他资料按需阅读摘要、推荐条文、主要结果、关键表格和局限 |
| 复杂课题/查新 | 一般不超过 5 个批次；需要更多时说明原因 | 只对会进入核心结论、图表或正式参考文献的文献做深读 |

除非用户明确要求系统综述级别穷尽检索、文献计量或专项查新，不要反复扩展同义词、连续搜索很多轮，或把低相关网页内容读进上下文。若检索结果已经足以回答问题，停止扩大检索，进入筛选、阅读和综合。

## 3. 选择问题框架

- 治疗、管理、预防问题：用 PICO/PICOTS。
- 病因、危险因素、暴露问题：用 PECO。
- 诊断问题：写清目标疾病、待评价检查、参考标准和诊断性能指标。
- 领域/热点/范围综述：用 PCC（Population, Concept, Context）。
- 论文写作：用“研究问题 + 论文段落用途 + 需要支撑的论点”。
- 学习资料：用“学习对象 + 临床场景 + 知识层级 + 必须覆盖的指南/教材/实践问题”。

输出检索问题时尽量写成 1 句话或一张小表，便于后续综合。飞书完整报告将其精简放入参考文献前的“检索策略与证据范围”；用户任务边界十分明确时可缩短为必要的检索边界和覆盖局限，但不铺开检索流水。

## 4. 关键词扩展

每个子问题都做中英文扩展：

- 疾病：中文名、英文名、缩写、旧称、分型、严重程度、MeSH/Emtree 近似词。
- 症状/体征：同义词、常见描述、鉴别诊断方向。
- 药物：通用名、商品名、靶点、药物类别、中英文名、适应证。
- 干预/检查：技术名、别名、设备/方法名、路径或策略名。
- 结局：临床终点、替代终点、安全事件、患者报告结局、诊断指标。
- 研究类型：guideline, consensus, systematic review, meta-analysis, randomized trial, cohort, real-world, registry, diagnostic accuracy, safety。

关键词扩展应提高召回，不要把检索边界扩到无关领域。执行过程保留每个检索批次的实际 query；最终文档只在参考文献前的“检索策略与证据范围”章节精简展示 3-8 个核心中英文关键词、缩写或 MeSH/Emtree 近似词，不铺开完整检索流水。

## 5. 检索批次

按任务需要组合批次；工具调用和优先来源边界遵循 `evidence-sources-and-appraisal.md` 的“检索顺序”。`full_report` 默认 2-4 个高价值批次，`quick_answer` 只做 1-2 个批次，复杂课题一般不超过 5 个批次：

1. 指南/共识批次：国际/国内学会、政府、权威机构、最新指南和共识。
2. 综述证据批次：Cochrane、系统综述、Meta 分析、证据总结。
3. 关键研究批次：RCT、大型队列、真实世界研究、诊断研究、里程碑研究。
4. 最新进展批次：近 1-5 年高相关研究、新药/新技术、指南更新。
5. 医学资讯批次：近期权威机构、学会、监管部门、期刊在线优先、会议官网和临床试验注册动态；仅在用户要求最新资讯或领域跟踪时启用。正式来源尚未覆盖非常新的主题时，可少量补充与问题高度相关的 `arXiv`、`medRxiv` 或 `bioRxiv` 预印本，并明确其尚未同行评议。
6. 安全/监管批次：药品说明书、FDA/EMA/NMPA、禁忌、警示、特殊人群。
7. 本土/专科实践批次：中文指南、专家共识、本土队列、专科规范。
8. 论文写作批次：围绕引言背景、研究空白、方法依据、讨论比较分别检索。
9. 学习资料批次：教材/权威综述、指南要点、实践流程和经典研究。

`full_report` 中，每轮检索结果先筛掉明显无关、重复、低质量来源；默认每批次初筛 4-10 条候选，候选总量通常控制在 12-36 条。高相关证据去重并确定保留后立即写入内部 CSV，按 CSV 行顺序在 `citation_number` 填入下一个连续数字，并保留 `evidence_id`、原标题、类型、期刊/机构、年份、级别、纳入理由和链接。摘要或原文片段仅在实际取得时填写；不要把低相关搜索结果全部写入上下文。`quick_answer` 不创建 CSV。

## 6. 初筛与精读

初筛顺序：

1. 题名和来源是否相关。
2. 文献类型是否符合任务目的。
3. 年份、机构、期刊和研究设计是否有价值。
4. 摘要或简介是否回答子问题。
5. 是否有可点击原文、官方入口、DOI/PMID 或可追溯页面。

初筛后，通过同一行 CSV 的 `evidence_id -> original_title -> url -> journal_or_institution/year/evidence_level -> inclusion_reason` 保持证据追踪，但不向用户渲染 `evidence_id`；可读简称从 `original_title` 稳定生成。`citation_number` 只按去重后记录写入 CSV 的先后顺序递增，不按正文首次出现顺序规划，也不因章节排序变化而重排。正文、关系图、时间线图、图例和参考文献可直接复用该编号形成 `[n]`，不另建临时映射，不使用 `G1`、`R1`、`SR1` 等类型前缀。没有可点击 `url` 或没有可用原标题的文献，不能作为正文核心证据。完整报告在 1-3 篇最能支撑结论的资料上完成定向精读；默认不向用户展示阅读状态，仅对确实阅读全文的重要论文可标注 `已阅读全文`。关键细节未能核验时，直接说明具体限制，不创建“仅摘要”分类。

Fetch/精读核心证据时按需记录，不把整页或整篇 PDF 原样塞入上下文。优先读取与问题直接相关的摘要、推荐条文、主要结果、关键表格、局限和链接入口；对背景性证据，只记录题名、来源、要点和链接。核心或辅助角色按质量、权威性、匹配度和时效性判定。

精读核心证据时记录：

- 指南：推荐条文、推荐强度、证据等级、适用人群、更新时间和差异点。
- 系统综述/Meta：PICO、纳入研究、效应量、异质性、偏倚、结论边界。
- RCT/队列：入排标准、样本量、干预/暴露、对照、主要终点、效应量、安全性、亚组和局限。
- 诊断研究：参考标准、敏感度、特异度、AUC、LR、PPV/NPV、误判后果。
- 机制/基础研究：只用于机制解释或研究假设，不直接支撑临床推荐。
- 教材/临床实践资料：用于学习框架和背景，不替代最新指南与原始研究。

## 7. 综合方式

第一章先直接回答用户问题，再根据任务类型选择后续综合结构：

- 主题循证综述：`第一章直接回答 -> 指南与专家共识 -> 综述证据 -> 关键研究 -> 最新进展 -> 临床意义 -> 局限 -> 检索策略与证据范围 -> 参考文献`。
- 指南查新：`最新版推荐 -> 与既往/不同指南差异 -> 证据依据 -> 实践影响`。
- 热点分析：`主题簇 -> 时间线 -> 里程碑 -> 最新前沿 -> 争议 -> 研究空白`。
- 医学资讯跟踪：`截至日期与时间范围 -> 最新动态 -> 对应论文/指南/注册信息/少量相关预印本 -> 证据状态 -> 对当前领域的实际意义`。该结构可直接作为报告主线；标准骨架中不能增加独立信息价值的证据图、指南、系统综述、其他研究或课题建议章节可合并或删除，不保留空标题。
- 课题论证：`研究背景 -> 现有证据 -> 未解决问题 -> 可行研究问题 -> 方法建议`。
- 论文写作：`可支撑论点 -> 引用文献 -> 可写段落 -> 参考文献 -> 引用风险`。
- 学习资料：`知识框架 -> 指南要点 -> 经典研究 -> 实践路径 -> 推荐阅读`。

综合时必须把“研究发现”或“资讯事件”翻译成用户能理解和使用的临床、科研或学习意义；不要停留在文献摘要或新闻标题搬运。资讯跟踪需明确区分正式指南、同行评议论文、在线优先、预印本/未同行评议、会议摘要/发布、试验注册更新和机构新闻稿。

`audience_mode=patient` 时，保留直接回答、文献依据和必要证据边界；除非用户明确询问，不生成研究方向、课题建议或研究空白清单，也不主动扩展与其问题无关的风险信息。

综合完成后统计将进入正文或参考文献的相关文献数。除医学资讯跟踪在图表不能增加信息时可省略外，达到 5 篇及以上时，除非用户明确要求不要图表，读取 `synthesis-and-visualization.md` 并生成证据脉络思维导图和关键研究里程碑时间线图；不足 5 篇时，再根据证据类型、研究发展脉络、冲突程度和用户指定格式判断是否绘图。凡使用图表，直接读取 CSV 中按行顺序生成的 `citation_number`，图表节点使用同一 `[citation_number] + 可读简称`。

默认飞书长文档先生成一份完整 XML 草稿并通过校验，再按 `lark-doc-delivery-reliability.md` 用完整 XML 一次创建并统一回读。只有一次创建明确因载荷或长度限制失败时，才按标准骨架切成 3 个连续大块兜底；骨架保留开头“总结”高亮块，并可选动态生成的第 1 章、第 4 章和第 7 章为锚点，用户指定核心交付物随第 1 章写入，不得继续拆成逐章更新。

## 8. 完成条件

`quick_answer` 或其他未创建飞书文档的回答，除完成直接回答和来源链接外，末尾必须询问：“是否需要我进一步生成完整的文献检索调研报告？”

`full_report` 只有在以下条件满足时才算完成：

- 已生成目标产物：未明确格式时必须是通过 `lark-doc` Skill 创建或更新且完成回读验证的飞书文档；URL、文档标识或 `revision_id` 不能单独证明写入成功。用户明确要求时才可改为通过 `lark-ppt` Skill 创建的 PPT/幻灯片、通过 `lark-doc` Skill 的 `office-word` 子模块创建的 Word/docx，或用户指定的 Markdown/Excel/xlsx 格式。普通表格、对照表、清单和矩阵仍在飞书文档中交付。
- 默认飞书文档正文已通过完整返回值检查及回读。
- 只给 PMID/题名清单或只在聊天窗口输出文献列表，不满足默认完整报告的完成条件。
- 若默认飞书文档创建失败，必须明确标注 `飞书文档创建失败`，说明 `lark-doc` 不可用或具体错误，并提供可重试飞书 XML 草稿文件路径或完整 XML 草稿；不能静默降级为聊天正文。
- 不得因检索完成、文献数量较少、问题已能直接回答或产物创建失败而把 `full_report` 改为 `quick_answer`。
- 关键结论和图表节点能追溯到正文链接和参考文献表。
- 除医学资讯跟踪在图表不能增加信息时可省略外，相关文献达到 5 篇及以上且用户未明确拒绝图表时，完整产物包含证据脉络思维导图和关键研究里程碑时间线图；不足 5 篇且未生成白板图不影响完成。若使用图表，文献节点必须使用 CSV 的连续 `[n]` 编号并能追溯到正文和参考文献。
- 飞书完整报告在参考文献前的“检索策略与证据范围”中精简说明必要的检索边界；任务明确时可缩短该章。第一章核心交付物已完整覆盖的重复章节可合并、缩减或删除，后续只补充尚未回答的重要证据、局限和来源链接。无论采用哪种结构，都不展示内部工具名称。
- 正文、图例、证据表中提及的具体文献标题或简称均就地带超链接；不能只靠文末参考文献表提供链接。
- 文末参考文献表每条正式参考文献都有可点击的原文、摘要页、DOI、PubMed、期刊页、指南官网或官方入口链接之一，无论采用哪种参考文献格式；无任何可点击入口的资料不能进入最终参考文献表。
- 证据不足、无法访问原文或存在争议时已明确标注。
