# 医学文献循证检索分析

## 核心定位

医学领域相关的文献检索与调研需求优先使用 `doubao-medical-literature-search`。本 Skill 覆盖指南查新、研究调研、限定范围的一次性资讯查新、综述和课题方向调研，将医学主题或课题转化为可检索问题，综合指南/共识、系统综述、关键研究、最新进展、权威医学资讯和必要监管来源，输出可追溯的文献梳理与证据脉络。

## 与循证医学问答的边界

分流只看用户最终想获得什么，不看问题中是否出现“指南”“文献”或病例信息：

- 用户预期获得具体医学问题的答案、判断或决策支持，包括根据指南、研究或说明书回答具体条目、标准、数字、疗程或适用条件时，改用 `doubao-clinical-decision-support`；由该 Skill 根据背景量、复杂度、分析深度和用户要求另行选择响应模式。
- 用户想直接查找或获取指南、共识、研究本身，或获得相关文献清单、资料分类比较、证据脉络、研究进展、热点、里程碑、课题方向、研究思路、综述或引用清单时，使用本 Skill。
- 普通患者/用户主动选择本 Skill，或明确希望查阅、梳理更多医学文献进行循证，以理解某医学主题、疾病、治疗或最新进展时，可以使用本 Skill，并设为 `audience_mode=patient`；若核心诉求转为个体化诊疗决策，仍按下一条分流。
- 具体患者的诊断、检查、用药或治疗决策改用 `doubao-clinical-decision-support`；患者主要询问报告异常含义、复查或就医沟通且未要求文献调研时改用 `doubao-medical-report`。病例仅用于限定检索人群，最终目标仍是多文献综合、指南更新、研究进展、医学资讯跟踪、课题或学习材料时，继续使用本 Skill。
- 查询 PubMed 等文献数据库中的一组论文、指南或证据脉络，继续本 Skill；只查基因/变异、临床试验、药械注册等公开数据库的具体记录、标识或字段，改用 `doubao-biomedical-data-query`。数据库记录仅作为文献调研材料时，不改变本 Skill 归属。
- 主要查询医保目录、限定支付、药品品规编码或地方待遇政策，改用 `doubao-medical-insurance-assistant`；只把医保条件作为文献比较维度时，继续本 Skill。
- 开放式查询领域最新进展或持续跟踪、订阅更新，改用 `doubao-medical-literature-monitoring`；限定主题、时间或来源的一次性文献查新继续本 Skill。
- 用户给定文献并要求来源内解读或翻译，分别改用 `doubao-medical-literature-interpretation`、`doubao-medical-literature-translation`；需要主动检索、比较或扩展多篇证据时，继续本 Skill。
- 推荐课题方向、梳理研究基础与证据空白，继续本 Skill；需要形成可执行的研究方案、终点或方法设计时，改用 `doubao-medical-protocol-design`。病历文书、临床汇报或患者科普写作也不属于本 Skill。

## 受众模式

- `professional`：医疗从业者、研究者、医学生或医学内容团队，按专业文献调研方式呈现。
- `patient`：普通患者/用户主动选择本 Skill，或希望通过查阅更多医学文献循证理解医疗问题；解释必要术语，保持严谨易懂，不主动展开研究方向或证据空白，也不堆叠与问题无关的风险信息。

`audience_mode` 不降低来源质量、引用链接或证据核验要求。它通常只改变表达和章节取舍，但 `audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档时，固定使用 `quick_answer`。

## 响应模式

选择本 Skill 后，再判定 `response_mode`。它只决定检索深度和交付方式，不改变任务归属：

| response_mode | 唯一触发条件 | 交付 |
|---|---|---|
| `quick_answer` | `audience_mode=patient` 且用户未明确要求查阅、检索或梳理指南/共识/论文/研究，也未要求循证分析、完整报告或正式文档；或用户明确要求快速回答、简短、精简、一段话、只给要点、限定字数、不要创建文档或直接聊天回答；或检索范围仅限单篇具名论文、单份具名指南、单一明确年份，且未要求完整报告或正式文档 | 默认 1 个高价值检索批次；聊天中直接给结论和每个被提及来源的可点击链接，不创建产物 |
| `full_report` | 除上述明确要求外的所有文献检索与调研任务 | 完成检索、筛选、证据综合和正式产物；用户未指定格式时默认创建飞书文档 |

除上述 `patient` 例外外，一般性问题聚焦、需求明确、文献数量较少、已经找到足够信息、用户没有主动要求文档，或 Agent 认为可以直接回答，都不能触发 `quick_answer`；“单篇具名论文、单份具名指南、单一明确年份”仍是窄范围检索例外。用户明确要求查阅/梳理文献、循证分析、完整报告、飞书文档、PPT、Word、Excel/xlsx 等正式产物时使用 `full_report`。其他未说明响应深度或格式的任务默认 `full_report`。

`quick_answer` 完成必要的高价值检索后，引用的指南、共识、论文、试验、说明书或监管来源均可追溯；聊天引用与文档引用分别按下文规则呈现。

`quick_answer` 下，内容适合图表展示时，可根据情况读取并使用 `doubao-visualization` Skill，在聊天回答中补充图表。

如果选择 `quick_answer` 模式，且问题需要检索相关图片、加入图片有助于提升回答效果，可先通过 `tool_search` 发现 `visual_search` 工具，再使用该工具搜索图片，并按工具返回的图片和来源信息在回答中引用展示。

## 国标参考文献与投稿综述

- 用户要求“国标”“国家标准参考文献”或“GB/T 7714”时，读取 `references/review-manuscript-and-citations.md`，按用户指定版本或现行 GB/T 7714 著录。该引用格式优先于默认六列参考文献表；正文引文与文末条目对应，每条保留可点击来源入口。
- 用户要求“写一篇综述”、生成综述稿件或完整综述论文，包括可投稿综述、期刊稿件或按稿约成稿时，仍由本 Skill 检索、评价和综合证据，设置 `response_mode=full_report`、`writing_mode=review_manuscript`，在锁定默认飞书格式前确定 `target_format=word_docx`；读取上述文件明确论文内容与学术表达后，直接路由 `word` Skill，按正式医学论文格式生成 `.docx`。正文使用不附超链接的原生上标编号，文末默认按现行 GB/T 7714 著录，每条末尾提供可点击的“（查看来源）”；用户或目标期刊明确指定其他格式时按其要求。内部检索、六列 CSV 和期刊匹配继续沿用本 Skill。普通文献调研与学习型综述仍按以下默认流程交付。

## 默认交付

- 判定 `target_format=feishu_doc` 后立即锁定到交付完成。默认飞书任务先读取 `assets/feishu-doc-template.xml`，再生成 XML。飞书 XML 去除前置注释后的首个元素必须是 `<title>`。
- `response_mode=full_report` 且用户未指定格式、也未命中综述论文分支时，调用平台 `lark-doc` 的 `online-doc` 创建飞书文档。综述论文按上一节默认路由 `word`；PPT/幻灯片调用平台 `ppt` Skill，Word/docx 调用平台 `word` Skill；用户明确要求 Markdown 或 Excel/xlsx 时按指定格式交付。参数遵循当前工具合同。
- 用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel` 或 `xlsx`，一律通过 `lark-doc` 创建飞书文档，在文档中插入所需表格，并用常规正文补充结论、解读、证据边界和来源链接；不要只在聊天中贴表格。
- `full_report` 使用 UTF-8 BOM 的六列 literature-log CSV：`citation_number,original_title,journal_or_institution,year,url,journal_rank_2025`。如果需要写 CSV 文件，先 Read 再 Write；新建时先 Read 模板，已有文件每次批量写入前先 Read 当前内容，再 Write。按六列结构批量追加，新行的 `journal_rank_2025` 先留空，由匹配脚本写入。台账保留题录、原始链接和期刊匹配结果。脚本自行读入 CSV 再写入，已满足先 Read 再 Write 的要求，不必在调用脚本前额外 Read。`quick_answer` 不创建 CSV。
- 飞书在线文档按模板生成完整 XML 后创建；载荷受限时按实际需要分块。
- 聊天回答直接给出结论、相关风险和依据，篇幅按问题需要展开，不设 Skill 预定字数、句数或要点数量上限；用户明确限制篇幅时按用户要求。优先在相关句子的标点之后，用角标引用最重要的依据。 `full_report` 默认交付聊天回答和飞书文档链接。XML、CSV 和原始草稿仅作内部过程文件保留，`present_files` 不选择这些文件；用户明确要求 PPT、Word 等最终格式时继续按相应路由交付最终产物。 `professional` 模式可按任务给相关延伸；`patient` 模式聚焦当前问题。`quick_answer` 保留免责声明，并把“是否需要我进一步生成完整的文献检索调研报告？”作为最后一句。

## 执行要求

以下普通调研报告的固定结构、图表、编号和证据展示要求，遇投稿综述或指定国标时，以“国标参考文献与投稿综述”一节及对应专用文件为准；检索、证据核实和内部记录要求继续适用。

- 正式表格单元格中，不详、缺失、未提供、未核验、不明确、无法明确、未知、暂未分级、未匹配、空值和不适用的证据等级统一显示 ASCII `-`。只替换缺失字段值，保留单元格中已知信息、实际风险或争议说明及官方等级。正文据实表达，期刊级别无匹配时在正文省略；表格占位符转换不回写 CSV。

- `seed_medical_search` 已直接存在于当前可用工具列表中；需要检索指南、共识或药品说明书时直接调用，不得先用 `tool_search` 搜索、发现、确认或转接该工具。
- `seed_medical_search` 返回的指南、共识内容 URL 不能 fetch。需要更细致的信息时，细化 Query，多次调用 `seed_medical_search` 获取推荐条文和上下文；也可使用 `general_search` 检索对应内容，再 fetch `general_search` 返回的可读取页面或 PDF URL。根据实际取得的内容进行分析和引用。
- 聊天回答（包括 `quick_answer` 和 `full_report` 的最终摘要）直接引用 `seed_medical_search`、`general_search` 的结果时，积极使用 `<RichMediaReference>["真实URL"]</RichMediaReference>`，组件紧跟对应句子的标点之后；同处多个来源使用纯 URL JSON 数组。URL 取工具实际返回的 `url/link`，与来源标题成对保留；其他检索来源可用可点击标题超链接。采用内容可靠且可追溯的资料入口，保留工具返回的原始 URL。`aka.doubaocdn.com` 域名的内容可以引用，也可以展示。搜索工具返回的第三方存储/索引 PDF 资料可以引用和展示；PubMed、PMC、DOI 解析、期刊官网和 Semantic Scholar 均可。保留工具返回的原始 URL，不因第三方域名改换到主站；按内容真实性、研究质量与问题相关性判断来源。RichMediaReference 用于聊天；飞书 XML、PPT、Word 等文档产物统一使用可点击超链接，含来源超链接的 citation 样式容器可继续使用。
- 镜像链接可以作为引用链接，保留原始镜像 URL，无需替换为主站链接；聊天引用和正式文档超链接均可使用。
- 检索与交付由 Main Agent 完成，不派生子 Agent。相互独立的搜索调用尽量并行、批量发出，再统一等待和整理结果。
- 快速判断任务边界与 `response_mode`，不要反复纠结模式。`audience_mode=patient` 且用户未明确要求查阅/梳理指南、共识、论文或研究，也未要求循证分析、完整报告或正式文档时，直接使用 `quick_answer`；用户明确要求快速回答、简短、精简、限定字数、不要创建文档或直接聊天回答，或检索范围仅限单篇具名论文、单份具名指南、单一明确年份且未要求正式产物时，也使用 `quick_answer`；否则使用 `full_report` 并高效行动。
- 引用准入按内容可靠性和可追溯性判断；工具返回的原始 PDF 与索引入口适用上述 URL 规则。营销软文、无法核实的二手解读或来源不明材料不作为医学依据。低级别研究可使用其可核验来源，并解释与当前结论有关的证据局限。
- `quick_answer` 在完整报告追问之前必须展示：“免责声明：本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”完整报告追问仍为整条回复的最后一句。
- `full_report` 一经判定即锁定到交付完成。不得因问题聚焦、文献较少、已经得到初步答案、执行耗时、上下文压力或产物创建失败而自行降级为 `quick_answer`。
- `audience_mode=patient` 时先检查用户是否明确要求查阅文献或循证分析：未要求时按 `quick_answer` 直接回答；明确要求时再按其深度与格式完成检索或详细分析。两种情况下都优先回答用户关心的问题并解释证据含义；研究方向、课题建议、研究空白和大量风险条目仅在用户明确询问时提供。
- 文本润色、翻译、总结、仿写或缩写不属于本 Skill，不得把这类任务当成 `quick_answer`。
- 回答前把用户明确提出的对象、人群、问题、字段、时间/来源范围和交付形式整理为需求清单；总结、第一章和最终回复必须逐项闭环，不能用“已完成检索”、文献罗列或“详见文档”代替答案。先直接回答用户最关心的问题，再给证据和边界；飞书文档开头的“总结”高亮块可适度加粗关键结论、重要数字和限制条件。
- 严格遵循用户限定的证据范围。`full_report` 不等于必须扩展全部证据类型：用户只限定“查指南”“查共识”或某种研究设计时，仅检索、阅读和交付该范围，不主动补充其他类型；这种证据类型限定不等于单份具名文献，也不单独触发 `quick_answer`。
- 用户的检索目标和指定交付形式优先。完整文档在标题后先放不编号的“总结”高亮块，再设置根据 Query 提炼的回答型第一章，逐项回答需求清单。涉及两个及以上药物、方案、人群、指南或研究且核心维度可横向对齐时，第一章优先用对比表集中呈现用户关心的字段，再用正文解释关键差异、证据边界和不能直接比较之处；非比较任务不强制表格。用户指定的清单、字段或重点文献解读也放入第一章。第二章起继续使用 `assets/feishu-doc-template.xml` 的标准骨架；前文已完整覆盖的内容可合并、缩减或删除，尚未回答的重要证据、局限、建议、带链接参考文献和免责声明仍须补齐。“检索策略与证据范围”固定放在完整参考文献之前。
- 检索要以完成用户的文献检索与研究调研目标为准：`quick_answer` 默认 1 个高价值批次，常规 `full_report` 默认 1-2 个批次，复杂课题/查新通常在 3 个批次内。结果足够时可首批结束；只有缺口可能改变核心结论或存在明确关键事实缺口时，才围绕该缺口定向补查或读取原文。同批并行发出相互独立查询，不同资料方向可放在同一批。优先阅读与核心结论、图表或正式参考文献相关的摘要、推荐条文、主要结果、关键表格和局限。
- `full_report` 每批检索后筛选高相关来源并批量追加六列 CSV。临床指南/共识和药品说明书使用 `seed_medical_search`：指南 Query 包含 `filetype:guideline`，说明书 Query 包含 `filetype:drug`；同时需要时分别查询。`general_search` 可补充官方发布页、监管页和正式原文入口。
- 文献去重并保留后，`citation_number` 按记录顺序递增并保持稳定；正文、图表、图例和参考文献复用同一 `[n]`，章节调整时沿用已有编号。
- 证据角色按研究质量、来源权威性、主题匹配度和时效性判断，不按是否取得全文机械分组。利用关键研究时，将“问题匹配度 × 研究设计适切性 × 信息量与精确性 × 偏倚风险 × endpoint 质量 × 结果一致性与可重复性”作为方法层判断：不计算分数，不要求逐项展示；用“可支持的具体判断 + 关键依据 + 主要边界”说明研究对当前检索问题的贡献。默认不展示阅读状态；仅对确实阅读过全文的重要论文，可简要标注 `已阅读全文`。
- 正文提及的外部证据应尽量都通过文档超链接就地呈现；正文、证据表、图例和建议段落中的具体指南、论文、试验、药品说明书、教材或监管来源，首次出现时必须就地给出可点击标题或简称，不得只写纯文本名称或只在文末补链接。文末参考文献表每条正式参考文献也必须包含可点击来源入口。
- 正文不得把指南、共识、研究名、试验名或教材/监管来源写成无链接小标题或纯文本加粗标题；首次出现必须由内部记录的 `original_title + url` 渲染成可点击原标题或稳定简称，并标注期刊/机构、年份和级别；正式文档中的期刊论文还要展示本地索引命中的 2025 期刊级别。
- 文末“完整参考文献（含链接）”默认固定为六列表格：`标题｜来源｜类型｜年份｜期刊分区｜链接`。如正文采用连续编号，在既有“标题”单元格内写成 `[1] 可点击标题`，不得新增编号列。期刊分区仅填写已明确核实期刊级别的论文，其他资料填 `-`。除非用户明确要求 Vancouver、AMA、APA、GB/T 7714 等特定格式，不要改成编号列表、纯 bibliography 或其他宽表；即使使用特定格式，每条仍必须有可点击来源入口。参考文献和图表来源表的链接文字按 URL 显示 `PDF` 或 `原链接`，不显示“原文/摘要”。
- 执行过程中只输出必要的简短状态，不展开长篇思考过程、初步梳理、候选文献枚举、证据表草稿或中间推理；正文、检索披露和最终回复不得展示内部检索工具名或内部来源列名。引用编号用普通文本、可点击文献名、含来源超链接的 citation 样式容器或参考文献表。
- 所有输出格式中的公式上标统一使用 Unicode 上标字符（如 ²、³、⁻¹），不得使用 sup 标签、转义/双重转义上标标签或样式化 HTML 上标；文档中不得使用 `<ref>` 标签或其转义形式，引用改用可点击来源名称、含来源超链接的 citation 样式容器或参考文献表。
- 不编造文献、DOI、PMID、指南版本、研究数据、影响因子、期刊分区或引用页码；正文无法核验时据实说明未核验、原文可及性或证据不足；表格对应缺失字段显示 `-`。
- 内部来源准入不使用 A/B/C/D 标签；核心或辅助用途按权威性、方法学质量、主题匹配度、时效性和可核验程度判断。正式文档展示研究证据级别时统一采用 Oxford CEBM 2009；指南/共识的 Oxford 证据级别写 `不适用`，其原文分级体系和推荐等级在对应条文中保留，不做换算。该分级及说明只写入正式文档，不在 `quick_answer` 或产物入口回复中展开。
- 正式文档中提及期刊论文时，同时展示 Oxford 证据级别和本地索引命中的 `2025 中科院分区/北大核心`。期刊级别仅表示发表载体，不代替方法学评价；未命中、匹配不唯一或非期刊资料时整段省略，不显示“未匹配”类提示。聊天 `quick_answer` 和产物入口回复不展开证据或期刊分级。
- 模型自拟结论的强度与证据匹配；引用官方推荐强度和分级时，保留原体系、原词及等级，英语等级保留原文。研究价值短评只使用非排序表述，不做最高级或名次式评价；样本量、随访、期刊和发表时间只用于解释精确性、适用性或时效性。确需横向排序时，另在有明确范围和数据依据的比较段中说明。
- 除医学资讯跟踪按专用结构可在图表不能增加信息时省略外，纳入正文或参考文献的相关文献达到 5 篇及以上时，除非用户明确要求不要图表，正式产物必须同时呈现证据脉络思维导图和关键研究里程碑时间线图；飞书在线文档使用 Mermaid 白板，PPT、Word 分别按 `ppt`、`word` Skill 的当前流程呈现这两类图表。相关文献不足 5 篇时，若问题范围很窄或图表不能增加信息，可省略其中一张或全部图表。思维导图按“证据分类 -> 具体文献 -> 核心结论”组织；时间线按年份或研究阶段呈现；图表与正文、参考文献统一使用 CSV 编号。系统综述和关键研究默认逐篇解读并写明期刊名称和年份；与用户问题、核心结论或关键边界直接相关的指南和研究应适度展开其关键条文、设计、结果及实际意义，外围或重复证据保持简洁，不平均分配篇幅。
- 输出定位为循证文献检索与学术、临床学习支持，不替代临床医嘱、伦理审查、正式系统综述注册、统计分析或人工专家审稿。

## 循证阅读与判断

已返回的题录可直接使用；卷号仅在用户要求时额外核对，不为补卷号增加搜索。

优先核对最新国家诊疗规范、权威指南与支撑关键结论的核心论文，核实版本和发布日期。

- 关键阈值、分级、诊断标准和官方用词回到原始规范或论文核实；官方等级为英语时保留原文，并保留原文所述适用人群、分母、时间窗与统计口径。
- 检索片段不足时调整 Query；工具实际支持 `snippet`、`max_length` 等参数时按其合同扩大可用片段。对影响结论的重要指南和论文，Fetch 原文及相邻段落、表格、脚注，获得足以理解结论的完整上下文。
- 分清原始证据、综合推断和实践建议；结论强度与证据质量、研究设计和一致性匹配，说明会影响当前判断的相关风险。涉及临床应用时核对指南框架、禁忌和用药安全。
- 病例资料只使用用户提供的事实；检索默认人群作为研究边界说明，与实际患者事实区分。

## 能力路由

- `seed_medical_search` 检索临床指南/共识和药品说明书；每次指南 Query 必须包含 `filetype:guideline`，每次说明书 Query 必须包含 `filetype:drug`。可按主题或资料类型多次查询，同时需要两类资料时分别查询。
- 研究论文优先使用 `general_search`、`scholar_search`；`scholar_search` 先通过 `tool_search` 发现并读取实际工具合同，再检索论文、系统综述、Meta 分析、RCT、队列、诊断研究、里程碑研究和最新高影响力研究。用户已安装且可用的 PubMed MCP 仅在需要补充较新论文题录时适度调用，参数以当前 MCP 合同为准；核对发表/更新日期、人群、统计口径和预印本状态。
- `general_search` 用于研究论文检索，以及定位学会官网、政府/监管机构、期刊原文页、数据库页面、临床试验注册和其他权威正式入口。
- 用户明确强调“最新”“近期”“刚发布”或“最新进展”时，指南/共识仍先用带 `filetype:guideline` 的 `seed_medical_search`，随后适度前移 `general_search`，补充可能尚未被医学或学术检索及时收录的最新正式发布信息；同时核验来源权威性，并继续用 `scholar_search` 覆盖相关研究证据。
- 用户明确要求本 Skill 完成限定范围的一次性医学资讯查新时，优先用 `general_search` 检索近期权威机构、学会、监管部门、期刊在线优先、会议官网和试验注册动态，再用 `scholar_search` 补充或定位对应论文、指南及既有证据；可少量补充与主题高度相关的 `arXiv`、`medRxiv` 或 `bioRxiv` 预印本，必须标明“预印本/未同行评议”。按日期、来源类型和证据状态去重整合，不把新闻稿或预印本单独写成已确立的疗效或安全性结论。
- 医学资讯跟踪报告以“时间窗与截止日期、最新动态、对应证据、证据状态、增量意义和可点击来源”为主线；标准章节只作为覆盖清单，无独立信息价值的证据关系图、指南、系统综述、其他研究或课题建议章节可合并或省略，不保留空标题。
- 用户明确指定期刊、学会、机构或数据库时，以完整满足该指定范围为主要检索边界和交付重点；仅在补充必要背景、关键证据缺口或核验结论时少量扩展其他来源，不得让扩展内容偏离或挤占用户要求。
- 论文类核心证据通过原文、PDF、期刊页或摘要入口核验，论文搜索摘要用于初筛；`seed_medical_search` 返回的指南、共识内容 URL 不能 fetch，按上述定向搜索或读取 `general_search` 返回内容的方式，获取可定位的条文及足够上下文。
- 统计换算、诊断指标、风险差、NNT/NNH、样本量或趋势计算可使用计算能力辅助。

## 执行流程

1. 读取 `references/core-workflow.md`，判断任务类型、`audience_mode` 和 `response_mode`，形成 1-5 个可检索问题和默认边界；若为医学资讯跟踪，启用其专用检索与整合路径。综述论文在此时确定 `writing_mode=review_manuscript` 和 Word 交付；要求国标或投稿综述时读取 `references/review-manuscript-and-citations.md`。
2. 读取 `references/evidence-sources-and-appraisal.md`，初始化内部文献记录，按其中的检索工具顺序和优先边界调用工具；每轮初筛后及时写入拟纳入或保留为辅助参考的记录。
3. 按预算覆盖指南/共识、系统综述、关键研究、最新进展、本土证据、安全/监管信息和必要教材/实践资料。
4. 根据问题精读核心证据，类型、证据级别、结果与局限直接依据实际核实原文用于正文。本次拟纳入文献整理后，默认运行 `node scripts/match-journal-rank.js --csv <literature-log.csv> --in-place` 一次批量匹配；后续新增需要匹配的期刊时再按需执行。脚本 stdout 返回 JSON，其中 `results` 与 CSV 逐行对应，包含 `citation_number`、`journal_or_institution`、`url`、`journal_rank_2025`、`status`、`matchedJournal`；可直接按编号和 URL 用于正文与参考文献表，无需额外 Read CSV 获取期刊级别。
5. 普通调研报告使用文献写入 CSV 时已按行顺序生成的 `citation_number`，直接综合结论并规划“总结高亮块 -> 第一章深度回答用户问题 -> 第二章起补充证据骨架”；不再为正文顺序单独规划或回填编号。投稿综述按主题论证组织论文；国标顺序编码制按首次引用顺序编排展示编号，并保留内部编号映射。仅在需要图表时读取 `references/synthesis-and-visualization.md`；正文锚文本由原标题生成。
6. 投稿综述按 `references/review-manuscript-and-citations.md` 整理稿件并交 `word` 生成。普通调研报告读取 `references/output-and-qa.md`；默认飞书文档必须在生成任何 XML 前读取 `references/lark-doc-delivery-reliability.md` 和 `assets/feishu-doc-template.xml`。第一章固定用于直接、深入回答用户问题，用户指定的表格、清单或深度解读也放在第一章；第二章起与其重复的内容可合并、缩减或删除，第八章再精简披露检索策略与证据范围，随后给出完整参考文献。非默认格式再读取 `references/output-format-routing.md`。
7. 按目标格式创建文档。
8. 默认在聊天中回答问题并给出飞书文档链接；用户要求其他最终格式时，`present_files` 只选择最终文档或文件链接，参数按环境工具合同。XML、CSV 和原始草稿内部保留，无需结束清理。
