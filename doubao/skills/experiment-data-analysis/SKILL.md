# 实验数据分析

## 能力与触发边界

先按下表判断能否执行，避免把指导模板误报为已完成分析。

| 能力层级 | 场景 | 本 Skill 能做什么 | 触发规则 |
|---|---|---|---|
| **脚本主流程** | 独立被试的基础组间实验 | 配置校验、量表信度、操纵检验、组间 ANOVA 决策、简单效应、交互图，以及配置支持的简单或被调节中介 | 有实验数据并明确要求这些推断分析时触发 |
| **有限 CLI** | 单一嵌套因子的 ICC；单个被试内因素的基础重复测量；一个组间因素加一个被试内因素的标准混合 ANOVA | 脚本提供对应 CLI，但 ICC 只用于诊断，后两类主要输出终端结果；本次返修未独立运行验证 | 有明确实验设计、完整 ID 列与长格式数据时可触发；先声明限制，不能承诺复杂模型或完整报告 |
| **仅指导或模板** | 多层模型、随机斜率、刺激物抽样、交叉随机效应、复杂重复测量、复杂混合设计、实验研究中的 CFA 或 SEM | 设计诊断、假设清单、代码模板与报告检查点 | 仅当请求明确属于实验研究且接受方法指导或模板时触发；不得声称主脚本会执行或结果已验证 |
| **不支持** | 广义线性混合模型、增长曲线、交叉滞后、多结局复杂 SEM、缺失数据插补模型、稳健或贝叶斯模型 | 说明能力缺口并建议交给匹配的方法或工具流程 | 不以“可直接分析”触发；若已因实验设计诊断进入本 Skill，须在执行前停止并降级说明 |

### 应触发

- 已提供实验数据，希望分析独立组间设计、操纵检验、ANOVA、简单效应或效应量。
- 已提供实验数据和理论模型，希望分析脚本明确支持的 Model 4、Model 8 或 Model 12。
- 已明确被试 ID、组间与被试内因素，希望分析基础重复测量或标准混合设计，并接受有限 CLI 输出。
- 实验数据存在班级、刺激物或情境聚类，希望先诊断设计并获得多层或交叉随机效应模板。
- 实验研究需要潜变量测量模型与结构模型规划，且用户明确接受“仅指导或模板”。

### 不应触发

- 纯问卷量表开发、EFA、通用 CFA、通用 SEM 或 AMOS 建模，未给出实验设计语境。
- 仅做文件转换、数据清洗、变量重编码、描述统计、频次、相关矩阵或可视化。
- 一般回归、逻辑回归、预测、分类、聚类、增长曲线或交叉滞后模型。
- 质性分析、访谈编码、文本分析或元分析。
- 用户要求复杂模型“直接跑完”，但不接受本 Skill 仅提供方法选择与模板的边界。

边界题与待验证用例见 [测试题集](references/test_cases.md)。

## 核心流程

### 0. 隐私与授权门禁

在读取数据前完成以下检查；无法确认时暂停并向数据责任人补问：

1. 确认用户有权处理数据，记录数据来源、研究用途、授权范围和保留期限。
2. 只保留分析所需字段；移除姓名、手机号、邮箱、精确地址、证件号、设备标识及可反推身份的自由文本。
3. 被试 ID 使用不可逆或受控映射；报告只给汇总统计，不粘贴原始个体行。
4. 不把原始数据、日志、配置中的本地绝对路径或敏感值放入 Skill 发布目录。
5. 若存在未脱敏敏感数据、授权不明或输出目录可公开访问，停止分析并要求先整改。

完整检查表见 [数据质量、隐私与统计假设](references/data-quality-privacy-assumptions.md)。

### 1. 诊断实验设计

依次确认：

1. 分析单位是什么，每个被试参与一个还是多个条件？
2. 是否有被试 ID、时间或条件列，数据是宽格式还是长格式？
3. 被试是否嵌套于班级、公司、家庭或医院？
4. 是否从刺激物或 Topic 总体抽样，且同一被试评价多个刺激？
5. 主要因变量、操纵变量、中介与调节变量分别是什么？
6. 是否涉及潜变量；若是，用户要直接执行还是只要模型规划？

按 [实验设计决策矩阵](references/design_decision_matrix.md) 选择路径。设计不明时先补问，不能默认使用普通 ANOVA。

### 2. 确认输入与变量映射

至少取得：

- 数据文件：CSV 或 SAV。
- 每列的含义、类型、编码和合法范围。
- 自变量、因变量、操纵检验题、量表题项及理论方向。
- 被试 ID、组别、时间、聚类、刺激物或 Topic ID。
- 主要假设、主要结局、计划对比和多重比较策略。

生成类型 1 配置时读取 [配置字段说明](references/config_guide.md)，以 [配置示例](scripts/config_example.json) 为起点。不要把示例列名当作真实映射。

### 3. 缺失数据与质量审计

在任何推断统计前：

1. 按变量、条件、被试和分析单元报告总量、缺失数与缺失比例。
2. 检查重复被试、非法编码、空单元格、零方差、极端不平衡和每格有效样本量。
3. 明确每项分析的有效样本及排除规则。脚本中的 `dropna()` 不等于经论证的缺失处理。
4. 不静默做整行删除、均值填补或删异常值。若缺失机制与处理方案不能合理确定，停止自动推断，只输出质量审计与待确认项。
5. 插补、加权、混合模型最大似然或敏感性分析超出脚本自动范围时，降级为方法建议并标记未执行。

### 4. 检查统计假设

按模型记录并审查：

- 独立性来自设计，而不是仅靠检验；存在聚类或重复测量时不得使用独立样本模型代替。
- 连续结局检查残差分布、异常点影响和方差结构，不只检查原始变量正态性。
- 组间模型检查方差齐性；不齐时改用 Welch、稳健标准误或匹配方法，不能只警告后继续给确定结论。
- 重复测量检查球形性；不满足时报告 Greenhouse–Geisser 校正或使用合适的混合模型。
- 回归与中介检查线性、同方差、共线性、模型设定和 Bootstrap 有效抽样数。
- 多层模型检查组数、组大小、随机效应结构、奇异拟合与收敛；ICC 不是是否建模的唯一判据。
- CFA 或 SEM 先检验测量模型、识别与拟合，再解释结构路径；常用阈值只是启发式标准。

### 5. 选择执行方式

#### 类型 1：基础组间脚本主流程

```bash
python3 <skill_dir>/scripts/exp_analysis.py <config.json>
python3 <skill_dir>/scripts/exp_analysis.py <config.json> --check-only
```

脚本会读取配置并生成报告与交互图。执行前必须完成前述隐私、缺失和假设检查；`--check-only` 只校验配置与列，不构成功能或统计正确性验证。

#### 有限 CLI

```bash
python3 <skill_dir>/scripts/exp_analysis.py --icc <data.sav> --group <聚类列> --dv <因变量列>
python3 <skill_dir>/scripts/exp_analysis.py --rm-anova <data.csv> --subject <被试ID> --within <被试内因素> --dv <因变量>
python3 <skill_dir>/scripts/exp_analysis.py --mixed-anova <data.csv> --subject <被试ID> --within <被试内因素> --between <组间因素> --dv <因变量>
```

仅在数据结构与该窄模型完全一致时使用。ICC 命令不拟合最终多层模型；复杂重复测量或混合设计不得硬套以上命令。

#### 仅指导或模板

多层、交叉随机效应、复杂重复测量及实验型 CFA 或 SEM 只读取 [实验设计决策矩阵](references/design_decision_matrix.md) 提供规划和模板。输出必须包含：

> 当前能力仅提供方法指导或代码模板；未由本 Skill 主脚本执行，也未产生可验证的统计结果。

### 6. 结果审查与报告

- 操纵检验按 [操纵检验路径](references/manipulation_checks.md) 处理；失败时如实报告，不删除检验题来掩盖失败。
- ANOVA 按 [ANOVA 决策树](references/anova_decision_tree.md) 解释高阶交互、低阶交互与计划对比。
- 中介按 [PROCESS 模型指南](references/process_models.md) 核对脚本支持范围；间接效应使用 Bootstrap 区间。
- 报告按 [APA 结果规范](references/reporting_standards.md) 编写，同时给出有效样本、缺失处理、假设诊断、软件和版本、随机种子及未执行项。
- 区分“脚本输出”“人工解释”“仅模板建议”；没有原始数据、命令、日志和产物时不得宣称结果可复现或已通过验证。

## 失败与降级

| 情况 | 处理 |
|---|---|
| 授权不明或数据含直接标识符 | 停止读取与执行；要求先完成授权、脱敏和最小化 |
| 文件损坏、格式不支持或列映射错误 | 停止；列出缺失信息和可接受格式，不猜测映射 |
| 关键缺失比例未知或删失会改变样本结构 | 只输出质量审计；补齐缺失处理方案后再推断 |
| 空单元格、零方差、每格样本过少 | 跳过受影响检验并列明范围；不得把缺失结果写成“不显著” |
| 方差齐性、球形性或模型设定不满足 | 切换到有依据的稳健方法；当前能力不支持时只给方法建议 |
| 模型不收敛、奇异拟合或 Bootstrap 有效次数不足 | 不解释系数或区间；记录错误与有效次数，简化模型或移交专门流程 |
| 复杂嵌套、交叉随机效应或实验型 SEM | 仅提供模板与检查点；不生成伪结果 |
| 依赖缺失 | 告知缺失包和环境信息；未经用户同意不修改全局环境 |
| 输出目录不可写 | 改用用户确认的安全目录；不得把参与者数据写入发布目录 |

## 输出与证据边界

类型 1 主流程通常在 `output_dir` 生成：

- `analysis_report.md`
- `interaction_plot.png`

有限 CLI 主要输出到终端。为实现复核，Owner 后续应在发布包外保存脱敏数据、配置、完整命令、环境版本、日志、报告、预期与实际判定、no-skill 基线及隐私复核。缺少这些材料时，状态只能标为“待验证”，不能写“通过”。
