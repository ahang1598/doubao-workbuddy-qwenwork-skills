## 1. 数据授权与最小化

在读取文件前记录以下信息；任一关键项无法确认时暂停：

| 检查项 | 最低要求 | 不满足时 |
|---|---|---|
| 数据来源 | 能说明由谁收集、为何可用于当前分析 | 请求数据责任人确认 |
| 使用目的 | 当前分析与授权目的相符 | 停止目的外使用 |
| 分析范围 | 只读取必要文件、工作表与字段 | 缩小输入范围 |
| 保留期限 | 有明确删除或归档时间 | 不创建额外副本 |
| 输出范围 | 报告接收者和存储位置已确认 | 不生成公开链接或共享副本 |

参与者数据默认视为受限数据。统计便利不能替代授权，也不能因为脚本“本地运行”就省略治理记录。

## 2. 数据脱敏检查

### 直接标识符

删除或单独隔离姓名、手机号、邮箱、证件号、账户名、设备 ID、精确地址及原始联系方式。

### 间接标识符

检查小群体中的年龄、单位、职位、地理位置、罕见疾病或事件、精确时间戳及自由文本组合。即使单列不识别个人，组合也可能重识别。

### ID 与自由文本

- 被试 ID 使用研究专用替代标识，不在分析目录保存映射表。
- 自由文本仅在统计模型确有必要时保留，并先人工去标识。
- 报告避免输出小样本单元的逐人值或可反推身份的极值描述。

### 路径与日志

配置、日志和报告可能泄露用户名、项目名或数据位置。对外证据中使用相对路径或脱敏占位符，原始绝对路径只保存在受控环境。

## 3. 缺失数据审计

先建立缺失概况，再决定处理方法：

1. 报告每列缺失数和缺失比例。
2. 按实验条件、时间点、聚类和主要结局比较缺失分布。
3. 识别结构性缺失、跳题、失访、无效值转缺失和技术性缺失。
4. 记录每项模型实际使用的样本量及被排除原因。
5. 比较完整与不完整个案在已观测关键变量上的差异。

不要把脚本内部 `dropna()` 当成缺失数据方案。整行删除、单变量均值填补和事后删异常值都需要明确依据，并在报告中说明对估计对象的影响。

以下情况停止自动推断：

- 主要结局或分组变量的缺失来源不明。
- 缺失与条件、时间或结果明显相关，但没有处理计划。
- 删除缺失后出现空单元格、严重不平衡或样本结构改变。
- 需要多重插补、逆概率加权或联合模型，而当前流程没有受验证实现。

降级输出应包含缺失概况、受影响分析、需要补充的信息和可选方法，不生成填补后的伪数据。

## 4. 通用质量检查

- 检查重复被试 ID、重复记录和一人多条件是否符合设计。
- 检查分类编码是否落在预期水平，连续变量是否在合法范围。
- 检查量表反向题是否已正确编码。
- 检查每个设计单元的有效样本数、均值、标准差和零方差。
- 检查极端值是否来自录入错误；不因结果不显著而删除异常点。
- 检查长宽格式、被试与时间组合的唯一性，以及是否缺少整次测量。
- 检查刺激物或 Topic 是否真正来自可推广总体，避免把固定材料误称随机样本。

## 5. 统计假设清单

### 组间 t 检验与 ANOVA

- 观测独立性由随机化与抽样结构支持。
- 模型残差近似满足所选检验要求。
- 检查方差齐性与极端影响点。
- 方差不齐时采用 Welch 或有依据的稳健方法；当前脚本仅提示而未自动保证稳健替代时，不能直接给确定结论。
- 多重比较需说明计划对比或校正方法。

### 重复测量与混合 ANOVA

- 被试 ID 与重复观测映射正确。
- 被试内因素超过两个水平时检查球形性。
- 球形性不满足时报告 Greenhouse–Geisser 校正或改用合适混合模型。
- 缺失与不平衡超出传统 ANOVA 能力时，不强制完整个案分析。
- 组间乘时间交互通常是干预差异变化的主要证据，但其解释仍依赖随机化、基线与测量质量。

### 中介与调节

- 模型次序与因果解释来自研究设计和理论，不由显著性自动证明。
- 检查连续预测变量的中心化需求、线性、同方差和共线性。
- 报告 Bootstrap 次数、随机种子、成功拟合次数和区间算法。
- Index 区间包含零时，不宣称被调节中介成立。

### 多层与交叉随机效应

- 聚类结构由设计决定；ICC 只描述聚类程度，不是唯一选模阈值。
- 检查组数、组大小和随机效应是否可识别。
- 记录优化器、收敛警告、奇异拟合和随机效应结构比较。
- 需要 Satterthwaite 或 Kenward–Roger 自由度时，使用明确支持该功能的实现。
- 模型不收敛时从理论允许的简化开始，不通过反复试模挑显著结果。

### CFA 与 SEM

- 仅限实验研究中的方法规划或模板，不由本 Skill 主脚本执行。
- 先确认样本量、模型识别、估计量与变量尺度。
- 先报告测量模型，再报告结构模型。
- CR、AVE、CFI、TLI、RMSEA 和 SRMR 的常用界值只作启发式判断，需结合模型复杂度、估计方法与领域规范。
- 不因单一拟合指标达标就宣称模型正确，不基于修改指数无理论地加路径。

## 6. 失败降级规则

| 失败 | 最低安全输出 | 禁止行为 |
|---|---|---|
| 隐私或授权失败 | 风险项和整改清单 | 继续读取、复制或共享原始数据 |
| 缺失机制不明 | 缺失概况和待决策问题 | 静默删行或单均值填补 |
| 假设不满足 | 诊断结果与备选方法 | 继续使用原检验并下确定结论 |
| 样本或单元不足 | 可计算的描述统计与限制 | 把不可估计写成不显著 |
| 不收敛或奇异拟合 | 模型规格、警告和简化建议 | 解释不稳定系数 |
| 超出自动化范围 | 标注“仅指导或模板” | 编造输出、p 值、拟合指标或验证状态 |

## 7. 独立证据记录

发布包不保存自测证据。Owner 在独立证据目录中至少记录：

- 用例 ID、测试日期、执行人和 Skill 版本。
- 脱敏数据或可公开生成数据及其校验值。
- 完整配置、命令、依赖版本和随机种子。
- 标准输出、错误输出、退出码和产物路径。
- 人工预期、实际结果、判定与 badcase。
- 至少五组 no-skill 基线对比。
- 数据授权、最小化、脱敏与删除记录。

没有以上链路时，只能写“待 Owner 验证”或“未独立验证”。
