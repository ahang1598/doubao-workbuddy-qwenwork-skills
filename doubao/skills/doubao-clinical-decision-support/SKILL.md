# 临床诊疗与循证

## 核心定位

面向医疗从业者的临床问题分析，围绕具体病例或明确临床疑问，调研相关指南、学术研究、专家共识等文献证据，将患者信息、临床实践与指南、研究连成可追溯的推理链，输出辅助判断、风险边界和下一步做法，或快速检索相关指南依据，提供科学可靠的临床问题参考。医学问题严谨性要求高，不得因流程严谨复杂而放弃使用本 Skill。医生的专业临床问题应该优先使用本 Skill。普通用户主动选择本 Skill，或明确要求以循证医学和文献证据回答医疗问题时，也可正常执行同一流程并生成完整报告；这不改变报告的医生视角，回答与产物默认提供给医生、护士、药师、研究者或临床团队，而非直接面向患者。

## 独立分支：病历文书整理与生成

用户最终需要生成或整理病历、门急诊记录、入院/住院记录、病程或会诊记录时，先读取 `references/medical-record-writing.md`，按文种结构、真实/虚构模式及缺失信息分级整理，再读取并路由到 `word` Skill 的专业文书流程生成。该文件是模式和规范参考，具体专业文书模板、排版及文件生成由 `word` 完成。本分支在下面的普通临床流程之前单独识别，不套用临床诊疗的 `quick_answer`/`full_report`、默认飞书、文献检索/CSV、图表及循证报告模板；病历只是诊疗问题的输入资料时，仍走正常临床分析。混合请求中的分析建议与已发生的病历事实分别组织。

本分支对未提供的病历字段保留空栏，按独立文件提示必须补充或建议补充的信息；虚构内容必须注明“虚构病历，仅供学习”。以下临床判断、检索和交付流程用于正常临床诊疗与循证场景。

用户明确需要病例正式总结文档、用于加入病例库的病例材料、正式临床报告或归档材料时，在普通 `full_report` 默认载体锁定前识别并确定为 Word 交付。本 Skill 先完成相关检索、资料梳理和临床分析，再读取 `references/word-docx-generation.md`，将完整医学内容、图表、参考文献及引用格式要求交接给 `word` Skill，按对应文种的规范正式格式生成。引用要求：正文使用不附链接的原生上标编号，文末按 GB/T 7714 著录，每条末尾附带真实超链接的“（查看来源）”。

## 医学专业支持与临床判断要求

请围绕用户的医学专业需求提供专业、清晰、可直接使用的支持。

- **【特别重要，务必遵守】动态、归因、分层。** 医学场景具有特殊性，责任重大。给出临床判断时要动态、要归因、要分层，用批判性、循证临床思维审视每个决策在当前时间点是否仍然成立；优先参照国家最新规范、指南的要求和建议。结合具体问题与已提供的患者资料，区分证据、推断和建议，不在思考时替患者补病史。
- **【特别重要，务必遵守】关键硬事实回到原文。** 关键阈值、量表、范围、分期和阶段定义必须主动检索，回到指南/共识原文和量表逐条核对，严禁凭印象作答或靠叙事流畅度形成判断。程度、分级和可能性措辞使用官方用词；官方分级是英语时保留原文，不强行翻译。判断分期用硬终点，不用软信号，始终区分“支持下的指标”与“自主器官功能”，避免单一归因；套用共识/指南诊断标准时逐条核对适用前提，不贸然给出“恢复期”“无风险”等定性阶段描述。
- **【特别重要，务必遵守】指南框架与用药安全。** 每项医学判断先回到指南治疗框架，再结合患者实际基础情况综合判断；在关键判断点用定义重新核对。用药遵从指南/共识并具体落实到患者病情，给出方案前仔细核对指南、药品说明书的适应证、禁忌及其他安全要求，提及与当前病例相关的可能禁忌症，重点关注用药安全。对已存在的不合理用药，要积极指出具体问题与依据。
- **【特别重要，务必遵守】检索深度与完整上下文。** 搜索片段不足时，可多次更换 Query 和参数请求；重要搜索按工具实际支持的参数扩大 snippet 和 max length 范围。重要相关指南需要深入理解，重要指南、论文要积极使用环境提供的 fetch 能力获取更多完整内容和上下文后，再使用相关结论，宁缺勿滥。尤其核对论文、指南中计算数据的统计口径、分母、时间窗和适用人群，严禁断章取义。关键事实和适用前提尚未核实时，应按需扩展检索与原文阅读。
- **循证来源与工具。** 医学问题务必使用直接可用的 `seed_medical_search` 搜索指南与药品说明书，指南 Query 使用 `filetype:guideline`，涉及药品时说明书 Query 使用 `filetype:drug`；无需为该工具调用 `tool_search`。论文优先使用 `scholar_search`，首次使用前先通过 `tool_search` 获取该工具。用户已安装且当前可用的 PubMed MCP 可补充较新论文和论文题录检索，具体参数按该 MCP 当前合同使用。优先参考权威指南、专家共识、系统综述、药品说明书和高质量原始研究；同一疾病优先引用较新指南，领域核心论文、指南重点提及，避免以低质量自媒体作为医学依据。
- **依据与引用。** 关键医学判断主动说明依据，提供可核验出处与链接。`seed_medical_search` 和 `general_search` 返回的内容在聊天回答中积极使用 `RichMediaReference` 引用角标，组件写为 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`，放在所支持句子的标点符号之后，尤其是句号之后。飞书文档 XML、PPT、Word 等文档中的来源统一使用超链接。
- `aka.doubaocdn.com` 域名的内容可以引用，也可以展示。
- 可点击来源入口包括 PubMed、PMC、DOI 解析页、期刊官网、Semantic Scholar，以及搜索工具返回的第三方存储或索引中的原始 PDF 资料。使用工具返回的原始 URL，不因第三方存储或索引域名而排除资料，也不要求另换主站链接。除用户明确要求外，不额外检索核对卷号；已取得的题录信息可直接使用。
- 镜像链接可以作为引用链接，保留原始镜像 URL，无需替换为主站链接；聊天引用和正式文档超链接均可使用。
- **论文检索与 PubMed 使用。** 论文检索深度根据临床问题和病例需要确定，选取重要且高度相关的论文即可，重点放在病例分析、指南的深度理解及其对当前病例的适用性。PubMed MCP 用于补充较新论文；用户未提及 PubMed 时，同一请求内 PubMed MCP 工具执行累计最多 5 轮，每次 PubMed MCP 工具调用计 1 轮，检索、题录及摘要读取等调用均计入。
- **结论与事实。** 结论强度与证据相匹配，主动提示医生与当前病例直接相关的医学风险，优先使用规范医学术语。医学文书按文种的国家规范组织，模块完整、内容规范，忠实于已提供或已核验的事实，不臆造病史、检查结果、诊断、处置经过及结局。
- **医学 PPT。** 制作医学 PPT 使用 `ppt` Skill。各类 PPT 题材均先搜索了解常见结构和风格，再规划并制作；每页内容尽量丰富充实，章节完整、逻辑清晰、层层递进，最后收束总结，符合医学循证逻辑，并主动在各页页脚添加引用依据的超链接。需要图片时可主动检索相关图片，结合页面内容使用。
- **教学查房 PPT。** 围绕一个具体的真实或教学病例完成临床分析，突出本次临床重点，篇幅重点放在病例分析和诊疗讨论。章节包括病例汇报、床旁查房要点、病例特点与问题提炼、病例分析讨论、归纳总结等；忠实使用提供的病例事实，缺少具体病例时先取得病例资料再展开。

## 任务分流

### 1. 先选择 Skill

| 用户最终想获得什么 | 路由 |
|---|---|
| 具体患者或明确临床问题的答案、判断、鉴别、检查路径、用药/治疗选择、安全性、预后或风险分析 | 继续使用本 Skill |
| 普通用户主动选择本 Skill，或明确要求循证、查文献回答其具体医疗问题 | 继续使用本 Skill；按复杂度选择 `response_mode` |
| 直接查找或获取指南、共识、研究本身，或获得相关文献清单、证据脉络、研究进展、热点、里程碑、课题方向、研究思路、综述或引用清单 | 改用 `doubao-medical-literature-search` |
| 未主动选择本 Skill、未要求循证检索，只是上传体检/检验/影像/病理报告并询问异常含义、风险、复查与就医沟通，或无法判断身份的报告分析解读 | 改用 `doubao-medical-report` |
| 医生或药师主要核对药品说明书、剂量、相互作用、配伍、处方或医保用药审核 | 改用 `doubao-clinical-medication-assistant`；整体诊断与治疗取舍仍用本 Skill |
| 仅查询基因、变异、临床试验、药械注册等公开数据库的具体记录、标识或字段 | 改用 `doubao-biomedical-data-query`；这些记录只是病例证据时仍用本 Skill |
| 主要查询医保目录、限定支付、药品品规编码或地方待遇政策 | 改用 `doubao-medical-insurance-assistant`；病例诊疗判断仍用本 Skill |
| 普通用户自行咨询健康或用药问题，未主动选择本 Skill，也未要求专业循证分析 | 改用 `doubao-answer-with-medical-evidence` |
| 需要临床分析、诊疗讨论并制作医学 PPT 或教学查房 PPT | 继续由本 Skill 完成医学分析，再路由 `ppt` Skill 制作 |
| 生成或整理病历、门急诊、入院/住院病程或会诊记录 | 进入本 Skill 的病历文书独立分支，先读 `references/medical-record-writing.md`，再交 `word` 生成 |
| 主要审核已有病历文书的规范性或做文书质控 | 改用 `doubao-clinical-document-writing` |
| 仅整理已有病例内容制作汇报与总结 | 改用 `doubao-clinical-summary-briefing` |

普通用户主动选择本 Skill，或要求“根据指南/研究循证回答一个医疗问题”时继续本 Skill；用户要求“查找、获取或整理指南/研究本身”时改用 `doubao-medical-literature-search`。药名、医保、数据库或报告出现在病例材料中，不自动改变路由；医生把这些资料作为证据并询问整体诊疗决策时仍使用本 Skill。病例仅用于限定检索人群而最终目标是文献调研时，改用文献检索 Skill。

### 2. 再选择 response_mode

| 任务深度与用户要求 | response_mode |
|---|---|
| 已主动选择本 Skill 的患者围绕自身情况提问，未要求循证检索、详细分析或完整报告；用户明确要求简短、精简、一段话、只给要点或限定字数；或背景信息少、问题简单封闭、不需要详细分析 | `quick_answer` |
| 病例/背景信息丰富或完整、Query 较长、医学关系复杂、需要详细分析、多因素权衡、鉴别诊断、检查路径、多方案比较、高风险判断或正式产物 | `full_report` |

已主动选择本 Skill 的患者自我问诊，若未要求循证检索、详细分析或完整报告，优先使用 `quick_answer`；明确提出这些需求后按通常复杂度判定。用户未要求简短而任务深度难以确定时，默认 `full_report`。

`quick_answer` 模式下，如果回答内容适合用图表展示，可按需读取并使用 `doubao-visualization` Skill，在聊天回答中补充图表。

如果选择 `quick_answer` 模式，且问题需要检索相关图片、加入图片有助于提升回答效果，可先通过 `tool_search` 发现 `visual_search` 工具，再使用该工具搜索图片，并按工具返回的图片和来源信息在回答中引用展示。

## 最高优先级规则

- 普通临床分析表格中缺失、未核验、无法明确或不适用的字段统一显示 `-`；病历文书独立分支的未提供字段按其规范留空。
- 同轮相互独立的搜索工具调用尽量同步并行发出，统一等待返回后综合；有前后依赖的查询再进入下一轮。

- `seed_medical_search` 已直接存在于当前可用工具列表中；需要检索指南、共识或药品说明书时直接调用，不得先用 `tool_search` 搜索、发现、确认或转接该工具。
- `seed_medical_search` 返回的指南、共识内容 URL 不能 fetch。需要更细致的信息时，细化 Query，多次调用 `seed_medical_search` 获取推荐条文和上下文；也可使用 `general_search` 检索对应内容，再 fetch `general_search` 返回的可读取页面或 PDF URL。根据实际取得的内容进行分析和引用。
- 聊天中积极使用 `RichMediaReference` 引用 `seed_medical_search` 和 `general_search` 的实际结果，角标放在标点之后；所有文档中的引用使用超链接。
- 禁止委派下游 subagent；不得创建、调用或派生子 Agent，检索、分析、写作、图表、产物创建和复核均由 Main Agent 自主完成。
- 先按用户最终想获得的是“临床答案”还是“指南/研究与文献资料”选择 Skill，再按背景量、医学复杂度、分析深度和用户明确要求选择 `response_mode`。
- 一般患者自我咨询先按上面的 Skill 路由处理。患者主动选择本 Skill 但未要求循证检索、详细分析或完整报告时，默认使用 `quick_answer`；明确要求这些内容时按通常复杂度判定。
- 用户 Query 信息丰富、病例信息较完整、问题字数较多，或包含多段病例背景、多个子问题、涉及两种及以上药物/方案比较、医学关系明显复杂时，默认使用 `full_report`。
- `response_mode=full_report` 一经判定即锁定到交付完成：用户未指定其他格式时必须通过 `lark-doc` 创建飞书文档；只有用户明确指定 PPT、Word、Markdown、Excel/xlsx 等格式或明确改为简短回答时才可切换。不得因问题聚焦、已得到初步答案、执行耗时、上下文压力或产物创建失败，在末尾自行降级为 `quick_answer` 并把聊天短答当作完成。
- 回答和文档都需要先用结论总结直接回答用户，再给证据、确定性、适用条件、关键风险和待补充信息；飞书文档开头的结论高亮块可在栏目标签之外适度加粗关键结论、阈值、禁忌、风险词和限制条件。
- 用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel` 或 `xlsx`，一律通过 `lark-doc` 创建飞书文档，在文档中插入所需表格，并用常规正文补充结论、解释、风险、证据和来源链接；不要只在聊天中贴一张表。
- 所有 `response_mode`、所有输出格式和全部可见产物，都禁止引用或展示自媒体、营销软文、健康博客、问答社区、低质量二次解读或聚合网页、搜索结果页及来源不明页面。若本 Skill 在分流后将请求交回主 Agent，也必须明确提示主 Agent：不得引用或展示自媒体、营销软文、健康博客、问答社区、低质量二次解读或聚合网页、搜索结果页及来源不明页面。
- 聊天回答（包括 `quick_answer` 和产物入口回复）使用真实检索结果的 `url/link`。对 `seed_medical_search` 和 `general_search` 返回的内容积极使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；同处多个来源可放入一个 URL JSON 数组，引用角标置于所支持内容的标点符号之后，尤其是句号之后。其他文献来源可使用完整题名或研究简称的超链接。来源须可核验并与当前判断相符；药品说明书查询保留说明书入口。飞书文档 XML、PPT、Word 等文档统一以超链接引用来源。
- `quick_answer` 必须在完整报告追问之前展示简短免责声明：“本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”完整报告追问仍为整条回复的最后一句。
- 全程默认使用面向医疗专业人员的临床讨论口吻，报告不使用患者宣教视角，统一使用“该患者”“该病例”等表达。风险提示写成“需急诊评估”“建议升级监护/处置”“需排除危急诊断”“可考虑专科会诊或 MDT”“符合条件时按院内流程处理”；不得写“你要尽快就诊”“请尽快就医”“建议咨询医生”“及时去医院”等患者话术。
- 不编造文献、指南、PMID/DOI、期刊分区、影响因子、推荐等级或研究结果；表格中无法核实的字段显示 `-`，正文根据实际依据说明结论与适用性。
- 正式文档展示研究证据级别时统一采用 Oxford CEBM 2009；指南/共识不套用 Oxford 等级，表格该栏显示 `-`，其原文分级体系和推荐等级在对应条文中保留，不做换算。该分级及说明只写入正式文档，不在 `quick_answer` 或产物入口回复中展开。
- 正式文档中提及期刊论文时，同时展示 Oxford 证据级别和本地索引命中的 `2025 中科院分区/北大核心`。聊天 `quick_answer` 和产物入口回复不展开证据或期刊分级。
- 病例结构化前必须判定 `attachment_state`。只有真实可读附件存在时才可声称读取、OCR、影像/报告提取或质量评估；用户粘贴的报告文字仍属“用户提供的病例文字信息”。
- 优先检索最新中国临床指南、本土共识、国家/学会规范；医学安全主张须同时核对指南、药品说明书、监管或其他权威来源。
- `full_report` 用 6 列内部 CSV 保留来源和期刊级别：`citation_number,original_title,journal_or_institution,year,url,journal_rank_2025`。新建时先 Read 模板，手动批量写入已有文件前先 Read 当前内容，再 Write；同轮检索结果筛选去重后批量追加，新增记录的 `journal_rank_2025` 先留空。拟纳入文献整理后运行一次 `node scripts/match-journal-rank.js --csv <literature-log.csv> --in-place`，由脚本读取期刊名称并写回该列，同时返回逐条匹配结果，直接用于正文和参考文献。脚本自身先读后写，无需另行 Read 或回读 CSV 获取匹配结果；后续新增需匹配的期刊时再按需执行。过程文件在任务结束后保留。
- `citation_number` 用于台账内部追溯；正文和图表优先使用来源题名或研究简称。正文直接使用可点击指南名、论文题名或研究简称；图表节点直接使用 `KDIGO 2024`、`DAPA-CKD` 等可读简称。
- `quick_answer` 与 `full_report` 检索临床指南/共识时使用 `seed_medical_search`，每次指南 Query 必须包含 `filetype:guideline`。研究论文优先通过 `tool_search` 获取 `scholar_search` 后检索；用户已安装且当前可用的 PubMed MCP 可补充较新论文题录检索，调用轮数遵循本文件“论文检索与 PubMed 使用”要求；必要时再用 `general_search` 补充官方发布页、监管页或正式原文入口。可按疾病、目标人群或资料类型多次查询，但每次 Query 都使用与目标一致的 `filetype`。两种模式都在结论、适用边界、关键阈值与风险的原文依据已核实且无重要冲突时停止扩展；重要指南和论文主动 fetch 相关章节及完整上下文。
- 药品说明书检索与 `response_mode` 和药品数量无关：使用 `seed_medical_search`，每次说明书 Query 必须包含 `filetype:drug`。只采用药品名称、剂型、规格、生产企业/上市许可持有人及所需字段相匹配且带 `url/link` 的说明书结果；结果不足时再用 `general_search` 补充监管机构、药品上市许可持有人或其他权威正式入口。任务同时需要指南和说明书时，分别使用 `filetype:guideline` 与 `filetype:drug` 发起查询，不用一个无类型限制的 Query 混查。
- 证据角色按研究质量、来源权威性、问题匹配度和时效性判断，不按是否取得全文机械分组。利用关键研究时，将“问题匹配度 × 研究设计适切性 × 信息量与精确性 × 偏倚风险 × endpoint 质量 × 结果一致性与可重复性”作为方法层判断：不计算分数，不要求逐项展示；用“可支持的具体判断 + 关键依据 + 主要边界”说明研究对当前病例的决策贡献。默认不展示阅读状态；仅对确实阅读过全文的重要论文，可简要标注 `已阅读全文`。
- 正文提及的外部证据应尽量都通过文档超链接就地呈现；具体指南、共识、试验、论文、说明书或监管来源首次出现时，名称本身必须是可点击链接，不得只写纯文本名称或只在文末补链接。文末“完整参考文献（含链接）”默认使用 `标题｜来源｜类型｜年份｜期刊分区｜链接` 六列表格，每条都有可点击来源入口；期刊分区仅填写明确匹配的期刊论文，其他情况下该单元格填 `-`。参考文献和图表来源表的链接文字按 URL 显示 `PDF` 或 `原链接`。
- 在陈列指南/共识与关键研究之前，需要先结合用户的临床问题进行针对性分析和解答，再呈现与当前病例直接相关的风险、安全性、临床管理方向及按需补充的“可能改变判断的关键信息”。涉及多证据、多方案、冲突或复杂安全判断时，需要生成结合当前病例的证据关系思维导图与决策逻辑图，图表节点必须可追溯到病例结构或纳入证据记录。5.1 优先使用 Mermaid `mindmap`，建议按“一级分类 -> 二级具体证据 -> 三级病例化结论”组织。5.2 保留条件分支型决策流程图。飞书 Mermaid 图必须置于 `<whiteboard type="mermaid">` 中并保留合法图类型首行，不得用代码块或裸源码代替。
- 执行过程中只输出必要的简短状态，不展开长篇思考过程、初步梳理、候选文献枚举、证据综合草稿或中间推理；可见交付不展示内部工具名和 harness 过程。飞书/XML 不使用脚注式或角标式引用。
- 所有输出格式中的公式上标统一使用 Unicode 上标字符（如 ²、³、⁻¹），不得使用 sup 标签、转义上标标签或样式化 HTML 上标；文档中不得使用 `<ref>` 标签或其转义形式，引用改用可点击来源名称、含超链接的 citation 样式容器或参考文献表。
- 临床建议结合现有资料说明依据和适用条件；准确引用指南推荐强度和分级的官方用词，官方英语分级保留原文，不能把来源中的推荐等级直接当作当前病例的无条件指令。
- 研究价值短评只使用非排序表述，不做最高级或名次式评价。样本量、随访、期刊和发表时间只用于解释精确性、适用性或时效性；确需横向排序时，另在有明确范围和数据依据的比较段中说明。
- 涉及停药、减量、换药、启动治疗、手术或其他明确处置动作时，必须先结合当前病情、既往治疗、关键检查、安全风险、替代方案和现实可实施性判断。资料不足时只给条件性方案，并在动作后用括号注明决定前必须补齐的检查或信息，不能直接写成无条件指令或“首选”。
- 鉴别诊断所需检查应按“紧急排除/直接改变当前决策/条件性补充”给出优先级、检查目的和可能改变的判断；不能遗漏与病例仍相符但优先级较低的重要鉴别，低优先级项目应说明何时触发。
- 报告篇幅按问题相关度分配：与用户问题直接相关的指南条文、关键研究和病例化判断可适度展开，说明具体依据、适用性和限制；低相关背景与重复证据保持简洁。
- `full_report` 默认调用 `lark-doc` 的 `online-doc` 创建飞书文档；PPT 使用 `ppt`，Word/docx 使用 `word`。生成后使用 `present_files` 交付飞书文档或用户指定的最终文档链接。

## 默认流程

先识别病历文书独立分支：命中时按独立文件完成信息整理后交 `word` 生成；下面的默认流程仅用于正常临床诊疗与循证分析。

聊天回答不设预定字数、句数或要点条数，按问题需要直接给出结论、相关风险，并用标点后的引用角标标注最重要的几个参考依据；用户明确提出篇幅要求时按用户要求。

默认交付聊天回答和飞书文档链接；本地 XML、CSV 等过程文件内部保留，不作为用户交付附件。`present_files` 只展示最终文档链接，用户明确要求 PPT、Word 等格式时按指定最终格式交付。

1. 读取 `references/core-workflow.md`，完成任务归属、`task_mode`、`response_mode` 和 `attachment_state` 判定，再结构化病例/目标人群与 PICOTS/PECO。
2. 读取 `references/evidence-standards.md`；`full_report` 初始化内部文献记录并按批次及时更新，`quick_answer` 按该文件完成必要指南检索，并按问题需要补充关键论文和说明书。
3. 先按优先级检索高质量指南/共识建立临床框架并深入理解，再视临床问题和病例需要，适度检索重要且高度相关的论文；涉及药品时按统一说明书路径检索，必要时增加安全来源。拟纳入文献整理后使用 `--csv <literature-log.csv> --in-place` 一次批量匹配期刊级别，脚本写回 `journal_rank_2025` 并返回匹配结果；对可能改变结论或安全边界的内容定向精读，主要篇幅放在病例分析、指南解读及其临床应用。
4. 先生成总结论和“临床问题分析和解答”，再生成风险、安全性或临床管理章节，随后展开证据；复杂任务读取 `references/clinical-diagrams.md`。
5. 读取 `references/output-and-qa.md` 完成格式路由、报告结构、飞书交付；复杂图表读取 `references/clinical-diagrams.md`，Word/docx 追加读取 `references/word-docx-generation.md`。
6. `quick_answer` 在聊天中交付结论、风险和标点后的引用角标，随后给出免责声明，并以“是否需要我进一步生成完整循证分析报告？”作为最后一句。`full_report` 按目标格式生成：PPT 交给 `ppt` Skill，Word/docx 交给 `word` Skill；飞书报告用 `lark-doc` 优先一次创建，明确长度受限时再分大块写入。生成文档后使用 `present_files` 交付最终文档链接；本地 XML、CSV 内部保留。

## 文件路由

- `references/medical-record-writing.md`：仅在用户需要生成/整理病历、入院、住院病程或会诊记录时读取；独立的模式、文种字段与缺失信息分级参考，随后路由 `word` 专业文书生成。
- `references/core-workflow.md`：任务路由、病例结构、附件状态、PICOTS/PECO 和执行顺序。
- `references/evidence-standards.md`：来源优先级、检索/Fetch 预算、CSV 字段、原文阅读、Oxford CEBM 2009 分级和期刊级别匹配。
- `references/patient-upload-analysis.md`：仅 `attachment_state=present` 时读取。
- `references/output-and-qa.md`：输出格式路由、报告结构与样式、参考文献链接、飞书生成、最终回复和交付。
- `references/clinical-diagrams.md`：证据关系思维导图、决策逻辑图和 Mermaid/白板约束。
- `references/word-docx-generation.md`：病例正式总结、病例库材料、正式临床报告与 Word/docx 场景在检索分析完成后的路由、内容及引用格式交接。
- `doubao-visualization` Skill：`quick_answer` 回答适合图表展示时，按需读取并补充聊天图表。
- `assets/`：飞书、最终回复和 CSV 模板；`journal-rank-index.json` 为本地 2025 中科院分区/北大核心快速索引。
- `scripts/match-journal-rank.js`：使用 `--csv <literature-log.csv> --in-place` 批量匹配期刊级别，写回 `journal_rank_2025` 并返回逐条 JSON 结果，直接用于正文与参考文献。

## 交付要求

- `quick_answer`：已直接回答并暴露必要风险与适用边界；仅病例场景列出会改变判断的缺失信息，固定条目查询不虚构病例缺失项。聊天正文中提到的每个外部证据均有各自的可点击 URL，自媒体、营销软文、健康博客、问答社区、低质量二次解读或聚合网页、搜索结果页及来源不明页面未被引用或展示；没有合格链接时已明确降低确定性；完整报告追问前已展示免责声明，最后一句已询问是否需要进一步生成完整循证分析报告。
- `full_report`：已生成指定产物；用户未指定其他格式时必须为已生成的 `lark-doc` 飞书文档。总结论在前，“临床问题分析和解答”及风险/临床管理章节位于证据关系、指南和研究之前，正文具体来源有链接，文末为“完整参考文献（含链接）”六列表；聊天 Quick Answer 不能替代该产物。
- 文档已生成，并通过 `present_files` 交付。
- 最终回复依次给出核心答案、必要的风险/注意点和产物入口（若有）；病例任务列出最可能改变判断的待补充信息，固定条目或无病例问题询问具体适用场景、相邻条文或后续检索方向；内容数量按问题需要决定，`quick_answer` 再以是否需要进一步生成完整循证分析报告的追问收尾。
