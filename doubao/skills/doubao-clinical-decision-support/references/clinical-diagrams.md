# 循证图表规范

本文件只负责“何时画图、选择什么图、图中放什么，以及怎样避免 Mermaid/白板解析失败”。报告章节、链接、格式路由、在线交付和内容 QA 统一见 `output-and-qa.md`。

图表方法参考 `standard-feishu-diagram` 的图表选择、语义颜色、节点/连线建模和可编辑飞书白板实践：https://github.com/Hanny-YANG/standard-feishu-diagram

## 触发与选图

默认飞书完整报告至少使用 1 个真正有助于回答问题的图表。存在 3 篇以上核心证据、多个候选方案、指南冲突或复杂安全判断时，优先使用 2 个互补图表；只有内容确有需要时再增加风险矩阵或泳道图，不为凑数量作图。

| 临床场景 | 首选图 | 主要回答 |
|---|---|---|
| 多篇指南/研究共同支持或限制结论 | 证据关系思维导图 | 病例线索和不同证据怎样共同形成判断 |
| 多方案、检查顺序、药物边界或禁忌筛查 | 决策树/流程图 | 当前病例在不同条件下怎样分支 |
| 指南冲突或新旧证据存在张力 | 证据冲突图/矩阵 | 不同来源在哪里一致、冲突及各自适用边界 |
| 获益、风险、确定性和可及性需要权衡 | 风险-获益矩阵 | 各方案的取舍和优先讨论顺序 |
| MDT、药师、检验/影像和院内流程分工 | 泳道图 | 谁在什么条件下完成哪一步 |

复杂病例的优先组合是“证据关系 Mermaid 思维导图 + 决策逻辑 Mermaid 流程图”。不要把证据层级、严格决策顺序和多角色执行全部塞进同一张图。

## 证据关系思维导图

思维导图回答：“当前病例由哪些线索和证据共同构成判断，哪些因素支持、限制或改变结论？”

- 根节点写当前临床问题或病例判断，不写泛泛疾病名。
- 根节点以下使用“一级分类 -> 二级证据 -> 三级结论”的结构。一级分类可从病例线索、指南与共识、关键研究、安全边界、现实约束、缺失信息和综合判断中按需选择，不机械凑齐。
- 二级证据写具体病例数据、可读指南/研究简称、安全阈值或关键缺失项，如 `eGFR 42`、`KDIGO 2024`、`DAPA-CKD`；不显示内部 `evidence_id`。
- 每条二级证据至少对应一个病例化结论，说明其对诊断概率、方案排序、安全边界或监测复评的意义。
- 每条证据只放在最相关的一个分类。交叉作用放正文或图例说明，不复制节点或绘制交叉线。
- 使用 Mermaid `mindmap` 的层级缩进和自动分支配色；不添加 `classDef`、手工连线、HTML、图标或复杂样式。

若节点不能嵌入链接，不为链接破坏 Mermaid 纯文本结构；按 `output-and-qa.md` 在图下邻接表或正文中提供可点击来源。

## 决策逻辑图

流程图回答：“在这个病例条件下，临床上如何分支判断？”

- 起点是病例当前状态或待回答问题。
- 只使用用户实际提供的症状、检查文字、诊断分层、合并症、当前用药、关键缺失信息和安全条件；无真实附件时不得生成附件提取信息。
- 决策节点写成可回答的问题，如 `是否存在活动性出血？`、`是否达到药物使用阈值？`。
- 每条边标注医学条件、阈值或分支含义，不能只有无解释的“是/否”。
- 终点使用条件性临床表达，如 `倾向纳入方案讨论`、`需 MDT 讨论`、`先补充检查再判断`。
- 高风险、禁忌、急症和必须补充资料的分支使用风险色，并在正文相应临床管理章节展开。

## 其他图表

- **证据冲突图/矩阵**：并列来源、推荐方向、适用人群、证据强弱与冲突点，不能用简单投票代替证据评价。
- **风险-获益矩阵**：只比较当前问题真正相关的方案，明确获益、主要风险、监测条件和证据确定性。
- **泳道图**：每条泳道代表真实责任方，每个步骤只属于一个责任方，跨泳道连线标注触发条件或交付物；不要把“治疗前/治疗中”当成责任方。

## 视觉与文字

颜色用于表达医学语义，不作装饰：

| 语义 | 建议颜色 |
|---|---|
| 病例、临床问题、主路径 | `#DBEAFE` / `#2563EB` |
| 指南、共识、学会来源 | `#EDE9FE` / `#7C3AED` |
| 系统综述、RCT、队列等研究 | `#DCFCE7` / `#16A34A` |
| 条件判断、证据有限、需补资料 | `#FEF3C7` / `#D97706` |
| 高风险、禁忌或当前不支持 | `#FEE2E2` / `#DC2626` |
| 现实约束、人工确认 | `#F1F5F9` / `#64748B` |

- 节点标签保持简短；复杂数据和解释放正文或表格。
- 决策节点用问题句，结论节点用条件性医学表达。
- 同类节点尽量同层、同色、相邻；一条边只表达一个关系。
- 主路径应能快速读懂，风险和例外路径放右侧或下方，避免双向线、回折线和跨组长连线。
- 不生成伪医学影像；位图只用于非诊断性机制示意或沟通材料。

## Mermaid 白板安全

飞书文档使用 `<whiteboard type="mermaid">`，块内只放纯 Mermaid 文本：

- 第一条有效内容必须是 `mindmap`、`flowchart TD` 或其他合法图类型声明。
- 不放 HTML/XML 标签、Markdown 代码围栏或字面量 `\n`。
- 避免原始 `<`、`&` 等 XML 敏感字符，改写成“低于”“大于等于”等文字。
- mindmap 不使用 `classDef`；流程图如需样式，只使用合法十六进制颜色，不使用 `light-yellow` 等飞书 callout 色名。
- 不在白板外展示 Mermaid 源码。解析失败时降级为表格、分点逻辑或可编辑图元，并保留相同的医学信息和来源说明。

以下仅示范稳定语法，实际节点必须根据当前病例和纳入证据现场生成：

```xml
<whiteboard type="mermaid">
mindmap
  root((当前临床问题))
    病例线索
      eGFR 42
        影响药物适用边界
    指南与共识
      KDIGO 2024
        支持讨论心肾获益路径
    关键研究
      DAPA-CKD
        提供肾脏结局依据
</whiteboard>
```

```xml
<whiteboard type="mermaid">
flowchart TD
    Start[当前病例状态]:::case
    Q1{是否达到适用条件}:::decision
    A[倾向纳入方案讨论]:::action
    B[先补充信息再判断]:::risk
    Start --> Q1
    Q1 -->|达到且无禁忌| A
    Q1 -->|未达到或信息不足| B
    classDef case fill:#DBEAFE,stroke:#2563EB,color:#1E3A8A;
    classDef decision fill:#FEF3C7,stroke:#D97706,color:#78350F;
    classDef action fill:#DCFCE7,stroke:#16A34A,color:#14532D;
    classDef risk fill:#FEE2E2,stroke:#DC2626,color:#7F1D1D;
</whiteboard>
```

## 不同产物的呈现

- **飞书文档**：优先 Mermaid 白板；来源链接放在邻接图例表、正文核心证据解读或正文引用中。
- **PPT/飞书幻灯片**：关键图默认使用原生 `shape`、`line`、`table` 或 `<chart>`；结构化图表同时包含 `chartPlotArea` 与 `chartData`，并核对数据维度数量。Mermaid whiteboard 仅作可选增强，并提供同页或相邻页的原生图形/表格兜底；实际视觉验收不能只依赖 XML 回读。
- **Word/docx**：优先稳定的表格、流程图图片或原生形状，具体生成规则见 `word-docx-generation.md`。

## 图表自检

- 图表回答了明确临床问题，且所有证据节点来自已纳入证据。
- 思维导图没有混入严格决策顺序，流程图的分支条件清楚。
- 风险、禁忌和证据不足醒目但克制；来源按 `output-and-qa.md` 可追溯。
- 已生成报告 XML 时运行 `scripts/validate-report-whiteboards.js <report.xml>`；未通过则修复白板或使用等信息量的降级图，不保留裸源码。
