# 核心流程

本文件只定义端到端执行顺序。证据来源、检索工具顺序、预算和评价标准见 `evidence-standards.md`；附件读取见 `patient-upload-analysis.md`；图表规则见 `clinical-diagrams.md`；文档结构、链接和交付规则见 `output-and-qa.md`。

先按主文档识别病历文书独立分支。用户最终要生成/整理病历、入院/住院病程或会诊记录时，读取 `medical-record-writing.md` 后交 `word` 专业文书流程生成，不进入本文件的临床模式、检索和循证报告流程。仅把病历作为分析依据的请求，继续下面的普通临床流程。

执行原则：快速完成分流，不反复讨论任务模式；除非用户明确要求简短、精简或限定字数，边界不清时直接使用 `full_report` 并开始工作。

## 1. 判定任务归属

先判断用户最终要获得什么：

| 用户目标 | 路由 |
|---|---|
| 围绕具体患者或明确临床问题，获得诊断鉴别、检查路径、用药/治疗比较、安全性、预后或风险分析 | 继续本 Skill |
| 普通用户主动选择本 Skill，或明确要求循证、查文献回答其具体医疗问题 | 继续本 Skill；按任务复杂度完成快速回答或完整报告 |
| 直接查找或获取指南、共识、研究本身，或调研相关文献清单、证据脉络、研究进展、热点、里程碑、课题方向、研究思路、综述或引用清单 | 改用 `doubao-medical-literature-search` |
| 未主动选择本 Skill、未要求循证检索，主要询问上传体检、检验、影像或病理报告的异常含义、复查和就医沟通 | 改用 `doubao-medical-report` |
| 医生或药师主要核对药品说明书、剂量、相互作用、配伍、处方或医保用药审核 | 改用 `doubao-clinical-medication-assistant` |
| 仅查询公开生物医学数据库的具体记录、标识或字段，如变异、试验、药械注册 | 改用 `doubao-biomedical-data-query` |
| 主要查询医保目录、限定支付、药品品规编码或地方待遇政策 | 改用 `doubao-medical-insurance-assistant` |
| 普通用户自行咨询健康或用药问题，未主动选择本 Skill，也未要求专业循证分析 | 改用 `doubao-answer-with-medical-evidence` |
| 需要临床分析、诊疗讨论并制作医学 PPT 或教学查房 PPT | 本 Skill 完成医学分析，再交给 `ppt` Skill 制作 |
| 生成或整理病历、门急诊、入院/住院病程或会诊记录 | 进入病历文书独立分支，先读 `medical-record-writing.md`，再交 `word` 生成 |
| 主要审核已有病历文书的规范性或做文书质控 | 改用 `doubao-clinical-document-writing` |
| 仅整理已有病例内容制作汇报与总结 | 改用 `doubao-clinical-summary-briefing` |
| 医生把报告作为复杂病例证据，并询问诊疗决策 | 继续本 Skill |

分流只看最终目标。“需要具体临床问题答案”只决定继续本 Skill，不决定后续 `response_mode`。普通用户主动选择本 Skill，或明确要求根据指南、研究或其他文献证据回答一个医疗问题时继续本 Skill；用户想直接查找、获取或整理指南/研究本身时改用文献检索 Skill。药品、医保或数据库记录只是病例证据时，不转为单项查询 Skill。普通用户入口只放宽触发条件，不改变报告受众：完整报告仍从临床团队视角讨论“该患者”或“该病例”。

继续本 Skill 后，用一句话锁定决策问题：

`在 {{病例条件或目标人群}} 下，{{方案/检查/用药/随访/诊疗原则}} 是否适合；与 {{对照方案或常规做法}} 相比，其获益、风险和证据边界是什么。`

## 2. 确定输入模式和交付深度

`task_mode` 只决定如何整理输入：

| task_mode | 判定 | 结构化方式 |
|---|---|---|
| `patient_case` | 有具体患者、病例资料、检查结果、用药、附件，或明确询问“这个患者/病例” | 提取病例要素、附件状态和会改变判断的缺失信息 |
| `clinical_question` | 无具体患者，但属于诊疗原则、鉴别诊断、检查路径、药物安全、治疗比较或指南冲突问题 | 明确目标人群、适用/排除条件、关键风险和问题边界 |

`response_mode` 只决定工作深度与交付方式：

| response_mode | 使用条件 | 交付 |
|---|---|---|
| `quick_answer` | 已主动选择本 Skill 的患者自我问诊且未要求循证检索、详细分析或完整报告；用户明确要求简短、精简、一段话、只给要点或限定字数；或背景信息少、问题简单封闭且不需要详细分析 | 完成必要指南检索，按需补充重要论文和说明书；聊天中给结论、风险和可点击来源 |
| `full_report` | 病例或背景信息丰富/完整；Query 较长；需要详细分析、多因素个体化判断、鉴别诊断、检查路径、多方案比较；医学关系复杂、高风险、指南冲突、需要多篇证据或正式产物 | 完成检索、筛选、原文阅读、证据综合、图表和目标文档 |

判定规则：

- 先完成 Skill 路由；一般患者自我咨询改用患者循证咨询 Skill。患者主动选择本 Skill 但未要求循证检索、详细分析或完整报告时，优先 `quick_answer`；明确提出这些需求后按通常复杂度判定。
- 用户明确要求简短、精简或限定字数时，优先使用 `quick_answer`。
- 背景信息少、问题简单封闭且不需要详细分析时，可使用 `quick_answer`；药品数量和是否查询说明书不参与模式判定。
- 用户希望得到具体临床答案，只决定使用本 Skill，不参与 `response_mode` 判定。
- 问题聚焦、只提出一个核心问题或 Query 表述较短，本身不构成选择 `quick_answer` 的依据；病例信息丰富、问题复杂或需要详细分析时，仍使用 `full_report`。
- 若患者年龄、合并症、器官功能、既往治疗、检查结果或风险偏好会实质改变答案，使用 `full_report`。
- 除上述情况外，出现任一复杂条件就使用 `full_report`。
- 一时无法确定时直接使用 `full_report`，不要在模式判断上消耗检索和交付时间。
- `full_report` 一经判定即保持到目标产物完成；用户未指定其他格式时，目标产物固定为 `lark-doc` 飞书文档。除非用户明确改变格式或要求改为简短回答，不得在检索、写作或创建失败后切回 `quick_answer`。
- `task_mode` 与 `response_mode` 相互独立：无具体病例也可以做完整报告，具体病例在用户明确要求简短时也可以快速回答。
- 表格请求按交付格式单独处理：用户要求创建表格、对照表、清单或矩阵但未明确指定 `Excel/xlsx` 时，目标产物固定为飞书文档，表格嵌入正文并配套结论、解释、风险和来源链接；明确指定 `Excel/xlsx` 时才交付电子表格。

## 3. 执行附件状态闸门

病例或问题结构化前，必须先设置 `attachment_state`：

| 状态 | 判定标准 | 动作 |
|---|---|---|
| `present` | 当前环境实际存在可读取的图片、PDF、Word、截图、影像文件、报告文件、本地路径或连接器附件 | 读取 `patient-upload-analysis.md`，评估质量并提取可用信息 |
| `none` | 没有真实附件；用户只粘贴报告文字、化验值、超声结论、病历摘要或自然语言描述 | 只按“用户提供的病例文字信息”处理，跳过附件分析 |
| `ambiguous` | 用户说“见附件/已上传”，但当前环境没有可读取文件 | 提示“未检测到可读取附件”，基于现有文字给条件性分析或请补传 |

硬性边界：

- 报告样文字、检查描述、化验数值和病历摘要不等于上传附件。
- `attachment_state=none` 或 `ambiguous` 时，不得声称读取附件、OCR、提取影像/报告或评估附件质量，也不添加对应空章节。
- 仅 `attachment_state=present` 时，报告才可加入“上传资料质量与病例提取”，并说明资料类型、日期、质量、关键发现、决策影响和局限。

## 4. 结构化临床问题

### patient_case

只提取影响当前决策的内容，不把病例原文重写成长摘要：

| 维度 | 内容 |
|---|---|
| 基本信息 | 年龄、性别、体重/BSA、妊娠/哺乳、就诊场景 |
| 疾病状态 | 诊断、分期/分型、严重程度、病程、当前关键矛盾 |
| 病例证据 | 症状体征、实验室、影像/病理文字、基因或评分 |
| 治疗与用药 | 既往治疗、疗效/不良反应、当前用药、过敏史 |
| 安全因素 | 肝肾功能、感染、出血、血栓、心血管风险和合并症 |
| 现实约束 | 可及性、费用、院内路径和患者偏好 |
| 缺失信息 | 会改变方案排序、安全边界或下一步检查的资料 |

缺失信息只分为 `必须补充`、`建议补充`、`可后续补充`。存在必须补充项时，可以给条件性暂定结论，但不能给确定性治疗指令。

### clinical_question

不硬填病例表，只明确：

- 目标人群和临床场景。
- 需要回答的诊疗、检查、用药、安全、预后或指南冲突问题。
- 证据适用条件与排除条件。
- 最可能改变答案的风险因素和 3-6 个待限定信息。

随后形成 1-3 个可检索子问题：

- 治疗、管理、预后问题使用 PICOTS。
- 病因或危险因素问题使用 PECO。
- 诊断问题写清目标疾病、待评价检查、参考标准、诊断性能和误诊/漏诊后果。

## 5. 临床动作与鉴别检查闸门

### 明确处置动作

凡结论涉及停药、减量、换药、重新加药、启动治疗、抗感染降阶梯、手术/介入或其他会立即改变管理的动作，先核对：当前病情与紧迫性、既往治疗及反应、支持该动作的关键检查、执行与不执行各自的风险、替代/过渡方案、监测复评条件，以及必要的术者经验、设备和院内可实施性。

信息充分时也使用条件性临床表达；信息不足时不得直接写“停用”“首选”或确定排序，应把缺口紧邻写在动作后，例如：`可讨论暂停/调整某方案（决定前需补齐：会改变该动作的检查或病史）`。同时说明补齐后可能改变的是动作时机、方案排序、安全边界还是替代路径。

### 鉴别检查优先级

根据病例先建立“候选诊断—支持/反对线索—验证检查”对应关系，再按以下顺序给出检查。每项说明检查目的及阳性/阴性结果可能改变的判断：

1. **紧急排除**：用于排除危及生命、器官功能或需要立即升级处置的诊断，注明时间窗口。
2. **直接改变当前决策**：用于确认主要诊断、决定能否启动/停止治疗、手术或降阶梯的核心检查。
3. **条件性补充**：用于仍与病例相符的低概率、少见或第二线鉴别，不因优先级较低而静默遗漏；说明在首轮阴性、特定症状/实验室线索出现或病程不符合预期时启动。

避免无差别罗列检查；同一检查能覆盖多个鉴别时合并说明，已完成且结果可靠的项目不重复建议。

## 6. 初始化检索与证据记录

读取 `evidence-standards.md`，按问题复杂度设置 `search_budget`、`fetch_budget` 和停止条件；预算作为工作量参考，关键硬事实和重要来源上下文尚未核实时继续扩展。`seed_medical_search` 直接调用，`scholar_search` 首次使用前先 `tool_search`；已安装且可用的 PubMed MCP 可补充较新论文题录。用户未提及 PubMed 时，同一请求内 PubMed MCP 工具调用累计最多 5 轮，每次检索、题录或摘要读取等调用均计 1 轮。

`full_report`：

1. 初始化内部 literature-log CSV。
2. 用 `seed_medical_search` 查找高质量中国指南、本土共识、国家/学会规范和必要国际指南；每次 Query 必须包含 `filetype:guideline`，并核对发布机构、年份/版本、适用人群和原文链接。
3. 在深入理解指南/共识、分析病例后，按当前临床问题需要，通过 `tool_search` 获取 `scholar_search`，适度检索重要且高度相关的关键论文，重点核对可能支持或改变当前判断的结果。
4. 涉及药品时，按 `evidence-standards.md` 的全模式说明书规则补充说明书。
5. 指南/共识及按需纳入的关键论文已覆盖当前问题、风险和适用前提后停止扩展；主要精力放在病例分析、指南深度理解及病例适用性。
6. 同轮独立搜索尽量同步并行，统一等待结果后筛选、去重并批量追加 6 列来源台账；保留原标题与原始链接，`journal_rank_2025` 交给匹配脚本填写，分析内容直接用于正文。

`quick_answer`：

- 用 `seed_medical_search` 查高质量指南/共识，每次 Query 必须包含 `filetype:guideline`；按问题需要用 `scholar_search` 补充重要且高度相关的论文。涉及药品时，按 `evidence-standards.md` 的统一说明书规则以 `filetype:drug` 补充说明书；可按资料类型多次查询。
- 选用足以回答问题的高质量来源，不预设可见来源篇数；回答中提到哪个来源，就必须给出该来源的可点击 URL。
- `aka.doubaocdn.com` 域名的内容可以引用，也可以展示。
- 聊天回答（包括 `quick_answer` 和产物入口回复）使用真实检索结果的 `url/link`。对 `seed_medical_search` 和 `general_search` 返回的内容积极使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；同处多个来源可放入一个 URL JSON 数组，引用角标置于所支持内容的标点符号之后，尤其是句号之后。其他文献来源可使用完整题名或研究简称的超链接。来源须可核验并与当前判断相符；药品说明书查询保留说明书入口。飞书文档 XML、PPT、Word 等文档统一以超链接引用来源。
- 不为了凑轮次扩展检索。

执行过程中只报告一句必要状态；候选列表、初步梳理、todo、证据综合草稿、工具名称和中间推理均作为内部工作内容。

## 7. 筛选、精读和引用映射

围绕当前病例筛选重要且高度相关的来源，按需要 fetch 指南条文、阈值、量表、研究结果和完整上下文；医学判断中的硬事实仍回到正式来源核实。相互独立的查询尽量同步并行，依赖前轮结果的任务再顺序执行。

完整报告将去重后的题录、原始 URL 和期刊级别保存在 6 列台账，保持 `citation_number` 稳定。拟纳入文献整理后运行一次 `node scripts/match-journal-rank.js --csv <literature-log.csv> --in-place`，脚本读取来源列、写回 `journal_rank_2025` 并返回逐条匹配结果；直接用该工具结果组织正文与参考文献，后续新增需匹配的期刊时再按需执行。研究类型、证据级别和病例分析从实际读取的内容提炼，直接用于正文。快速回答可直接使用搜索来源，无需台账。

聊天引用与文档超链接按 `output-and-qa.md`；`aka.doubaocdn.com` 域名的内容可以引用，也可以展示。

## 8. 综合证据并直接回答临床问题

先回到指南诊疗框架，再结合患者实际基础情况形成判断并组织文档，区分证据、推断和建议。临床判断动态、归因、分层，按当前时间点重新核实每个决策；程度、分期和分级使用原文官方用词，官方英语分级保留原文，结论强度与证据相匹配。分期核对硬终点和适用前提，区分支持下的指标与自主器官功能，不以单一信号或单一归因定义恢复阶段。给出用药方案前核对指南/共识和说明书禁忌，说明病例相关风险，积极指出现有不合理用药的具体问题与依据。

“临床问题分析和解答”必须位于指南/共识和关键研究之前：
1. 直接进入分析，结合病例或目标人群及调研到的证据，详细、清晰、有条理地回答用户提出的问题；可按需要拆分临床子问题，不限制数量。
2. 对主要方案分别说明临床获益、风险、证据依据和适用限制。
3. 在合适的位置引用后文可点击的指南名、论文题名或研究简称。
4. 仅 `attachment_state=present` 时引用真实附件发现。

篇幅按与用户问题的关联度分配。对直接决定诊断、检查路径、方案排序或安全边界的指南条文和关键研究，适度展开原文推荐/等级、研究设计、关键结果、病例适用性与局限；低相关背景、重复结论和仅作旁证的来源简要带过，不平均分配篇幅。

随后生成置于证据关系与决策逻辑之前的风险、安全性或临床管理章节，标题按用户问题和病例重点确定。可结合实际需要讨论重要风险、禁忌或安全条件，监测复评、协作或升级处置，以及可能改变判断或管理方向的缺失信息；不预设固定小模块标题、顺序或数量。

涉及多篇证据、多方案、证据冲突或复杂安全判断时，读取 `clinical-diagrams.md`：

- 证据关系思维导图以当前临床问题为根，分层表达病例线索、指南、研究、安全来源和临床判断。
- 决策逻辑图结合当前病例条件、关键缺失项和安全门槛绘制。
- 图表节点只能来自病例结构或已纳入证据；无附件时不得出现上传报告或 OCR 节点。

## 9. 生成与交付

`quick_answer`：

1. 直接回答核心问题，字数、句数和条目数按问题需要决定，角标引用最重要的几个依据。
2. 给出必要风险和适用边界；仅 `patient_case` 列出会改变判断的缺失信息，固定条目查询不得虚构病例缺失项。回答适合图表展示时，可按需读取并使用 `doubao-visualization` Skill，在聊天回答中补充图表。 如果选择 `quick_answer` 模式，且问题需要检索相关图片、加入图片有助于提升回答效果，可先通过 `tool_search` 发现 `visual_search` 工具，再使用该工具搜索图片，并按工具返回的图片和来源信息在回答中引用展示。
3. 聊天回答（包括 `quick_answer` 和产物入口回复）使用真实检索结果的 `url/link`。对 `seed_medical_search` 和 `general_search` 返回的内容积极使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；同处多个来源可放入一个 URL JSON 数组，引用角标置于所支持内容的标点符号之后，尤其是句号之后。其他文献来源可使用完整题名或研究简称的超链接。来源须可核验并与当前判断相符；药品说明书查询保留说明书入口。飞书文档 XML、PPT、Word 等文档统一以超链接引用来源。
4. 在收尾追问前写明：“免责声明：本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”
5. 无论任务类型，最后一句固定追问：“是否需要我进一步生成完整循证分析报告？”

`full_report`：

1. 按 `output-and-qa.md` 选择目标格式：默认飞书文档使用 `lark-doc`，PPT 使用 `ppt`，Word/docx 使用 `word`。
2. 组织完整内容后优先一次生成；只有服务明确提示长度限制时，再分成少量大块写入同一文档。
3. 生成后简要确认正文、表格及来源链接；聊天按需要展开结论、风险和关键引用，最后使用 `present_files` 仅交付飞书文档或用户指定的最终文档链接。报告 XML、CSV 和素材等过程文件内部保留。
