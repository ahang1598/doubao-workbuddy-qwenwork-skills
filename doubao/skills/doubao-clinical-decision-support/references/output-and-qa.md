# 输出与交付

本文件用于普通临床诊疗与循证分析的输出。病历文书整理生成属于独立分支，先按 `medical-record-writing.md` 处理字段、留空和缺失分级，再交 `word` 专业文书流程生成；文书分支的结构与待填空栏按该文件保留。

镜像链接可以作为引用链接，保留原始镜像 URL，无需替换为主站链接；聊天引用和正式文档超链接均可使用。

本文件统一负责输出格式路由、报告结构、可见样式、来源链接、飞书在线交付、最终回复和 QA。图表的选择、节点与 Mermaid 安全仍单独见 `clinical-diagrams.md`；Word/docx 的细节见 `word-docx-generation.md`。

## 聊天引用硬规则

`aka.doubaocdn.com` 域名的内容可以引用，也可以展示。

- `seed_medical_search` 已在当前可用工具列表中，直接调用即可；不得使用 `tool_search` 搜索、发现或确认该工具。
- 聊天回答（包括 `quick_answer` 和产物入口回复）使用真实检索结果的 `url/link`。对 `seed_medical_search` 和 `general_search` 返回的内容积极使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；同处多个来源可放入一个 URL JSON 数组，引用角标置于所支持内容的标点符号之后，尤其是句号之后。其他文献来源可使用完整题名或研究简称的超链接。来源须可核验并与当前判断相符；药品说明书查询保留说明书入口。飞书文档 XML、PPT、Word 等文档统一以超链接引用来源。
- 使用 Markdown 超链接时，锚文本采用完整题名或可读研究简称；多个链接用中文顿号或分行分隔。聊天 `RichMediaReference` 使用实际来源 URL，放在所支持内容的标点之后；文档以超链接承载引用。

## 读者与交付边界

聊天回答不设预定字数、句数或要点条数，按问题需要直接给出结论、相关风险，并用标点后的引用角标标注最重要的几个参考依据；用户明确提出篇幅要求时按用户要求。

默认交付聊天回答和飞书文档链接；本地 XML、CSV 等过程文件内部保留，不作为用户交付附件。`present_files` 只展示最终文档链接，用户明确要求 PPT、Word 等格式时按指定最终格式交付。

默认读者是医生、护士、药师、研究者、MDT 或其他医疗工作者。即使请求来自普通用户，完整报告也保持临床团队视角，用“该患者”“该病例”指代分析对象，说明需评估的危急诊断、处置优先级、监测、会诊或院内管理条件；不要改写成“你要尽快就医”“建议咨询医生”等患者宣教口吻。

`response_mode` 由 `SKILL.md` 判定：

- `quick_answer`：聊天中直接给出核心答案、必要风险和可点击来源，不输出检索过程、候选清单、todo 或长篇推理。
- `full_report`：按用户指定格式创建完整产物；未指定格式时使用飞书文档。聊天按内容需要给出结论、相关风险和关键引用，完整报告放入飞书文档；保持已确定的响应模式。

用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel/xlsx`，在飞书文档中插入表格，并补充必要的结论、解释、风险、证据和链接；不要只交付孤立聊天表格。内部 literature-log CSV 可用于稳定记录证据，但不作为用户可见产物。

## 输出格式路由

| 用户要求 | 目标产物 | 创建入口 |
|---|---|---|
| `full_report` 且未指定格式，或明确要求完整循证临床报告 | 飞书文档 | `lark-doc` 的 `online-doc`，模板 `assets/feishu-doc-template.xml` |
| 患者自我问诊且未要求循证/查文献/完整报告，明确要求简短或限定字数，或简单封闭问题采用 `quick_answer` | 聊天快速循证回答 | `assets/final-response-template.md` |
| PPT、汇报、MDT 展示或幻灯片 | PPT/飞书幻灯片 | `ppt` Skill；先搜索题材结构与风格，再做页面规划 |
| Word、docx、病例正式总结文档、加入病例库、正式临床报告或归档材料 | 可打开的 `.docx` | 完成检索、资料梳理和临床分析后，再路由 `word` Skill，按 `word-docx-generation.md` 交接内容和引用要求 |
| 创建表格但未指定 Excel/xlsx | 含表格的飞书文档 | 飞书模板中插入表格和必要正文 |
| 明确指定 Excel/xlsx | Excel/xlsx 工作簿 | 按用户字段和工作表结构创建 |
| 明确要求 Markdown 或不要创建文档 | 用户指定格式 | 每个被提及的外部证据都保留可点击 URL |

不确定且用户没有要求简短时，按 `full_report` 飞书文档执行。确定目标格式后，读取对应 Skill 和当前任务需要的内容参考：飞书文档使用飞书模板，PPT 使用 `ppt` Skill 的制作流程，Word 使用 `word` Skill。

格式要求：

- **飞书文档**：内容按本文件后续章节生成，图表按 `clinical-diagrams.md`，在线创建按本文件“飞书在线交付”执行。
- **PPT/幻灯片**：调用 `ppt` Skill，按其当前流程生成。先搜索该题材的常见结构和风格，再规划章节、逐页信息和视觉重点；临床汇报可参考 10-12 页，页数按病例复杂度和展示需求调整。每页内容丰富充实，配合证据、图表与解释展开，章节完整、层层递进，末尾收束总结。覆盖病例/问题、临床分析、诊疗讨论、风险管理、证据关系、指南/研究和病例化落地；各页页脚主动添加引用依据超链接，末页汇总参考文献。需要图片时主动检索合适的图片。教学查房必须围绕具体真实或教学病例，按“病例汇报 → 床旁查房要点 → 病例特点与问题提炼 → 病例分析讨论 → 归纳总结”组织，篇幅重点放在病例分析和诊疗讨论。图形、版式与导出按 `ppt` Skill 当前合同执行，医学图表内容参照 `clinical-diagrams.md`。
- **Word/docx**：病例正式总结文档、用于加入病例库的病例材料、正式临床报告与归档材料，由本 Skill 完成相关检索、资料梳理和临床分析后，再将完整医学内容、图表及引用要求交接给 `word` Skill，按对应文种的规范正式格式生成 `.docx`；正文原生上标不附链接，文末采用 GB/T 7714 并为每条添加“（查看来源）”超链接，具体见 `word-docx-generation.md`。
- **失败兜底**：说明失败步骤和原因，在内部保留对应的报告 XML、页面规划与素材或 Word 草稿，不以“稍后生成”结束，也不把 `full_report` 改成聊天短答。

## 完整报告结构

论文的检索深度、展示数量和篇幅按当前病例需要安排，选取重要且高度相关的论文即可；报告重点放在病例分析、指南深度理解与实际诊疗讨论，关键研究章节按实际纳入内容组织。

默认飞书报告使用以下覆盖骨架，可按临床问题调整小节和第 4 章标题：

1. 总结论
2. 病例信息梳理与临床问题
3. 临床问题分析和解答
4. 根据问题生成的风险、安全性或临床管理章节
5. 证据关系与决策逻辑
6. 指南/共识证据
7. 关键研究证据
8. 检索策略与证据覆盖
9. 完整参考文献（含链接）
10. 免责声明

关键章节作用：

- **总结论**：直接回答用户问题；按需呈现“总结”“关键依据”“注意事项”，不机械凑齐栏目。“注意事项”可合并说明重要风险、不确定性、适用条件、需补充信息和证据限制。
- **病例信息梳理与临床问题**：围绕当前决策梳理真正影响判断的病例信息、治疗经过、安全因素、现实约束、临床问题和必要的 PICOTS/PECO，并说明这些信息对判断的影响。正文按病例自由使用自然段、短列表、callout 或必要表格，不预置固定字段或固定表格；仅 `attachment_state=present` 时纳入真实附件的质量、关键发现和局限。
- **临床问题分析和解答**：位于外部证据章节之前，直接进入针对当前临床问题的分析，自由组织病例线索、临床子问题、证据支持与限制；不要预设“问题总结”，也不要写成泛泛证据摘要或“证据与病例匹配程度”。
- **风险、安全性或临床管理章节**：位于证据关系图之前，标题和内容贴合当前问题。明确处置动作使用条件性表达；资料不足时在动作后括号标注决定前必须补齐的检查或病史。需要补做的鉴别检查按“紧急排除、直接改变当前决策、条件性补充”呈现，并说明检查目的和结果会改变哪项判断；不预设固定小模块标题、顺序或数量。
- **证据关系与决策逻辑**：图表数量、节点、颜色、来源邻接表和 Mermaid 安全统一按 `clinical-diagrams.md`，本文件不重复规定。
- **指南与关键研究证据**：篇幅服从当前临床问题。对关联度较高、可能改变结论或安全边界的指南条文与研究，适度展开推荐原文/等级、研究设计、关键结果、病例适配性和局限；低相关或重复来源简要呈现。核心研究使用可点击题名或研究简称，并标注期刊、年份、研究类型和 Oxford CEBM 2009 证据级别；本地索引命中时再追加 `2025 中科院分区/北大核心`，未命中时整段省略。每篇核心研究末尾按需要给出“研究价值短评”，依次说明可支持的具体判断、关键依据和主要边界；六个维度只用于形成判断，不机械罗列，也不据此给研究排座次。样本量、事件数、随访或覆盖范围应在设计与结果中写明实际数据，短评只说明这些事实如何影响精确性或适用性，并使用非排序表述。内容较多时可按需使用无序列表，不拆成固定小模块；研究结论不得外推为无条件临床指令。
- **完整参考文献（含链接）**：使用本文件“引用与参考文献”规定的六列表格。

## 可见样式

- 表格中缺失、未核验、无法明确或不适用的字段统一显示 `-`；适用于病例表、证据表、图例表和参考文献表。
样式用于突出医学重点，不替代论证：

- 结论可用浅绿或浅蓝 callout；证据有限或待补资料用浅黄/浅橙；高风险、禁忌或当前不支持用浅红。适度加粗关键阈值、风险词和限制条件。
- 风险内容可使用 `🚨`、`⚠️`、`🛡️` 等有明确语义的 emoji，结合短段落或无序列表；只保留与当前问题有关的块。
- 病例结构、指南矩阵、方案比较和决策条件适合表格；解释性分析优先使用自然段和短列表，不要把所有内容表格化。
- 复杂报告可组合结论 callout、病例结构表、证据关系图、决策逻辑图、证据矩阵和方案对比表，但不为凑数量加入无用组件。
- 模板注释、生成约束、占位符、示例说明和工具提示仅用于内部生成，不能出现在可见文档中。写入前必须替换或删除全部 `{{...}}` 占位符，并清除 XML 注释及其文字。

飞书 XML 的 callout 只使用以下起始标签格式：

`<callout emoji="x" background-color="light-yellow">`

其中 `x` 替换为实际 emoji；可按 `lark-doc` 规则增加 `border-color` 或 `text-color`，**不得使用 `type` 属性**。例如：

```xml
<callout emoji="⚠️" background-color="light-yellow">
<p><b>注意事项：</b>正文内容</p>
</callout>
```

公式上标使用 Unicode 字符，如 `²`、`³`、`⁻¹`，不使用 `<sup>`、转义后的 sup 标签、脚注或角标式引用。文档中不得使用 `<ref>` 标签或其转义形式；citation 组件可作为含超链接的样式容器；文档来源均通过超链接呈现。`RichMediaReference` 用于聊天回答。

## 附件状态与病例资料

生成报告前必须判定 `attachment_state`：

| 状态 | 可见内容 |
|---|---|
| `present` | 可加入“上传资料质量与病例提取”，说明真实附件类型、日期、质量、关键提取和局限 |
| `none` | 只写“用户提供病例信息/证据资料”；不得声称读取附件、OCR、质量分级或影像/报告提取 |
| `ambiguous` | 说明未检测到可读取附件；若继续分析，只能基于用户文字和检索证据 |

用户在聊天中粘贴的超声、化验、病历或报告文字属于“用户提供的病例文字信息”，不是上传附件。无附件时默认不单列“未上传附件”章节。

## 引用与参考文献

### 正文链接

正文、表格和图例第一次提到具体指南、共识、试验、论文、说明书或监管来源时，名称本身必须是可点击链接，并在邻近位置标注期刊/来源和年份；正式文档中的研究标注 Oxford CEBM 2009 证据级别，本地索引命中时并列标注 2025 期刊级别，指南/共识保留原文分级。不能把来源名写成无链接小标题、纯加粗文字、书名号或裸 URL。

推荐格式：

`<a href="{{url}}">DAPA-CKD</a>（NEJM，2020，RCT；Oxford CEBM 2009：1b；期刊级别：中科院 1 区）`

`<a href="{{url}}">KDIGO 2024 CKD Guideline</a>（KDIGO，2024；原指南分级按原文保留）`

Oxford CEBM 2009 和期刊级别及其说明只写入正式飞书、Word 或 PPT 产物。指南/共识不套用 Oxford 等级，表格该栏显示 `-`，原指南推荐等级另行保留。聊天 Quick Answer 和最终入口回复按问题需要展开，不逐条展示证据或期刊等级，也不重复文末分级说明。

若某段、表格行或图例引用具体来源，该位置或紧邻位置必须包含相应链接。图中节点不能嵌入链接时，在图下使用邻接表或在正文首次提及时补足；不要只在文末给链接。不得显示内部 `citation_number`；只有用户明确要求特定引用格式时才使用普通引用序号。

### 完整参考文献（含链接）

可点击来源入口包括 PubMed、PMC、DOI 解析页、期刊官网、Semantic Scholar，以及搜索工具返回的第三方存储或索引中的原始 PDF 资料。使用工具返回的原始 URL，不因第三方存储或索引域名而排除资料，也不要求另换主站链接。除用户明确要求外，不额外检索核对卷号；已取得的题录信息可直接使用。

第 9 章标题必须包含“链接”，默认按 `核心证据`、`辅助参考` 分组，必要时另列 `排除/待核验`。每组均使用六列表格：

`标题｜来源｜类型｜年份｜期刊分区｜链接`

- `标题`：完整题名、指南名、共识名、说明书名或监管来源名。
- `来源`：期刊、机构、数据库或监管来源。
- `类型`：指南、共识、系统综述、Meta、RCT、队列、诊断研究、安全监管、说明书或辅助参考等；仅对确实阅读全文的重要论文追加 `已阅读全文`。
- `年份`：发表、发布或更新年份。
- `期刊分区`：期刊论文使用匹配脚本已写入 CSV 的 `journal_rank_2025` 或工具结果中同一行的返回值，填写明确命中的中科院分区或北大核心；未命中、匹配不唯一或非期刊资料统一填 `-`。
- `链接`：必须是 http(s) 可点击锚文本。URL 直接指向 PDF 或现有结果明确标识为 PDF 时显示 `PDF`，其他入口显示 `原链接`；不为判断标签额外逐条访问网页。

核心/辅助角色由质量、权威性、问题匹配度和时效性决定，不按全文可及性机械分组。低级别、不权威、方法学薄弱或相关性不足的资料不得单独支撑关键疗效或安全性结论。

除非用户明确要求 GB/T 7714、Vancouver、AMA 等格式，不得改成编号列表、纯 bibliography 或其他宽表；即使用户要求特定格式，每条仍须保留可点击链接。没有 http(s) 来源入口的展示记录应补链或移除，不写裸 DOI、PMID 或“链接未返回”。

## 飞书在线交付

使用平台 `lark-doc` 的 `online-doc` 创建文档，格式与参数按其当前合同。生成完整报告后优先一次写入：

`lark-cli docs +create --content @report.xml`

XML 使用一个 `<title>` 作为标题来源；`--content @file` 使用当前工作目录下的相对路径。表格参考 `lark-doc` 示例：

```xml
<table>
  <colgroup><col span="2" width="120"/></colgroup>
  <thead><tr><th>表头一</th><th>表头二</th></tr></thead>
  <tbody><tr><td>内容一</td><td>内容二</td></tr></tbody>
</table>
```

服务明确提示长度受限时，再按内容拆成 2-3 个大块写入同一文档。只有插入位置需要定位时才读取一次目录。

文档生成后使用 `present_files` 仅交付飞书文档或用户指定的最终文档链接，参数按当前工具合同填写。报告 XML、CSV、素材等过程文件在任务结束后保留。

## 最终回复

最终回复按 `assets/final-response-template.md` 和 `response_mode` 生成，不展示内部工具名、harness、模板/QA 指令、证据草稿或长篇过程。

`quick_answer`：

1. 直接回答临床疑问，说明确定性和适用条件。
2. 提示真正重要的风险、证据边界或需医生确认的条件。回答内容适合用图表展示时，可按需读取并使用 `doubao-visualization` Skill，在聊天中补充图表。 如果选择 `quick_answer` 模式，且问题需要检索相关图片、加入图片有助于提升回答效果，可先通过 `tool_search` 发现 `visual_search` 工具，再使用该工具搜索图片，并按工具返回的图片和来源信息在回答中引用展示。
3. 聊天回答（包括 `quick_answer` 和产物入口回复）使用真实检索结果的 `url/link`。对 `seed_medical_search` 和 `general_search` 返回的内容积极使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；同处多个来源可放入一个 URL JSON 数组，引用角标置于所支持内容的标点符号之后，尤其是句号之后。其他文献来源可使用完整题名或研究简称的超链接。来源须可核验并与当前判断相符；药品说明书查询保留说明书入口。飞书文档 XML、PPT、Word 等文档统一以超链接引用来源。
4. 病例任务可追问会改变判断的缺失信息；固定条目或无病例问题询问目标人群、使用场景或后续问题，不虚构病例资料。
5. 展示免责声明：“本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”
6. 最后一句固定询问：“是否需要我进一步生成完整循证分析报告？”

`full_report`：

1. 最终回复先直接回答用户问题，再提示与当前问题相关的风险或注意点，不能只写“详见文档”；聊天摘要中 `seed_medical_search` 和 `general_search` 的引用积极使用标点后的 `RichMediaReference`。
2. 已生成文档时，使用 `present_files` 仅交付飞书文档或用户指定最终文档的链接，XML、CSV 内部保留。
3. 按任务追问会改变判断的病例信息、适用人群或待明确问题。
4. 创建受阻时说明当前状态，原稿在内部保留以便重试；聊天仍回答临床问题并给出风险和关键引用。

最终使用 `present_files` 交付链接。
