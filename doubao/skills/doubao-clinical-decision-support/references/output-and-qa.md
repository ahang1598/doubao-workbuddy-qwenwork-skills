# 输出与复核

本文件统一负责输出格式路由、报告结构、可见样式、来源链接、飞书在线交付、最终回复和 QA。图表的选择、节点与 Mermaid 安全仍单独见 `clinical-diagrams.md`；Word/docx 的细节见 `word-docx-generation.md`。

## 读者与交付边界

默认读者是医生、护士、药师、研究者、MDT 或其他医疗工作者。即使请求来自普通用户，完整报告也保持临床团队视角，用“该患者”“该病例”指代分析对象，说明需评估的危急诊断、处置优先级、监测、会诊或院内管理条件；不要改写成“你要尽快就医”“建议咨询医生”等患者宣教口吻。

`response_mode` 由 `SKILL.md` 判定：

- `quick_answer`：聊天中直接给出核心答案、必要风险和可点击来源，不输出检索过程、候选清单、todo 或长篇推理。
- `full_report`：按用户指定格式创建完整产物；未指定格式时使用飞书文档。聊天只保留短状态、核心回答和最终入口，不承载完整报告，也不得在末尾自行降级为 `quick_answer`。

用户要求创建表格、对照表、清单或矩阵时，除非明确指定 `Excel/xlsx`，在飞书文档中插入表格，并补充必要的结论、解释、风险、证据和链接；不要只交付孤立聊天表格。内部 literature-log CSV 可用于稳定记录证据，但不作为用户可见产物。

## 输出格式路由

| 用户要求 | 目标产物 | 创建入口 |
|---|---|---|
| `full_report` 且未指定格式，或明确要求完整循证临床报告 | 飞书文档 | `lark-doc` 的 `online-doc`，模板 `assets/feishu-doc-template.xml` |
| 患者自我问诊且未要求循证/查文献/完整报告，明确要求简短或限定字数，或简单封闭问题采用 `quick_answer` | 聊天快速循证回答 | `assets/final-response-template.md` |
| PPT、汇报、MDT 展示或幻灯片 | PPT/飞书幻灯片 | `lark-ppt`，模板 `assets/ppt-deck-template.xml` |
| Word、docx、正式归档材料 | 可打开的 `.docx` | `lark-doc` 的 `office-word`，并读取 `word-docx-generation.md` |
| 创建表格但未指定 Excel/xlsx | 含表格的飞书文档 | 飞书模板中插入表格和必要正文 |
| 明确指定 Excel/xlsx | Excel/xlsx 工作簿 | 按用户字段和工作表结构创建 |
| 明确要求 Markdown 或不要创建文档 | 用户指定格式 | 每个被提及的外部证据都保留可点击 URL |

不确定且用户没有要求简短时，按 `full_report` 飞书文档执行。确定目标格式后只读取相应模板：飞书任务不得读取 PPT 模板，PPT 任务不得套用飞书 XML。

格式要求：

- **飞书文档**：内容按本文件后续章节生成，图表按 `clinical-diagrams.md`，在线创建与回读按本文件“飞书在线交付”执行。
- **PPT/飞书幻灯片**：使用 `lark-ppt`，默认 10-12 页并先做 slide plan。覆盖结论、病例/问题、临床分析、风险管理、证据关系、指南/研究、病例化落地和带链接参考文献；每页只讲一个主信息，使用多种版式。关键关系图优先使用原生形状/连线/表格，详细规则见 `clinical-diagrams.md`。
- **Word/docx**：使用 `lark-doc` 的 `office-word` 生成真正可打开的 `.docx`；版式、图表和可打开性检查只按 `word-docx-generation.md`，不在本文件展开。
- **失败兜底**：说明失败步骤和原因，保留对应的完整飞书 XML、PPT XML 或 Word 草稿，不以“稍后生成”结束，也不把 `full_report` 改成聊天短答。

## 完整报告结构

默认飞书报告使用以下覆盖骨架，可按临床问题调整小节和第 4 章标题：

1. 总结论
2. 病例信息梳理与临床问题
3. 临床问题分析和解答
4. 根据问题生成的风险、安全性或临床管理章节
5. 证据关系与决策逻辑
6. 指南/共识证据
7. 关键研究证据
8. 检索策略与证据覆盖
9. 完整参考文献（含链接）
10. 免责声明

关键章节作用：

- **总结论**：直接回答用户问题；按需呈现“总结”“关键依据”“注意事项”，不机械凑齐栏目。“注意事项”可合并说明重要风险、不确定性、适用条件、需补充信息和证据限制。
- **病例信息梳理与临床问题**：围绕当前决策梳理真正影响判断的病例信息、治疗经过、安全因素、现实约束、临床问题和必要的 PICOTS/PECO，并说明这些信息对判断的影响。正文按病例自由使用自然段、短列表、callout 或必要表格，不预置固定字段或固定表格；仅 `attachment_state=present` 时纳入真实附件的质量、关键发现和局限。
- **临床问题分析和解答**：位于外部证据章节之前，直接进入针对当前临床问题的分析，自由组织病例线索、临床子问题、证据支持与限制；不要预设“问题总结”，也不要写成泛泛证据摘要或“证据与病例匹配程度”。
- **风险、安全性或临床管理章节**：位于证据关系图之前，标题和内容贴合当前问题。明确处置动作使用条件性表达；资料不足时在动作后括号标注决定前必须补齐的检查或病史。需要补做的鉴别检查按“紧急排除、直接改变当前决策、条件性补充”呈现，并说明检查目的和结果会改变哪项判断；不预设固定小模块标题、顺序或数量。
- **证据关系与决策逻辑**：图表数量、节点、颜色、来源邻接表和 Mermaid 安全统一按 `clinical-diagrams.md`，本文件不重复规定。
- **指南与关键研究证据**：篇幅服从当前临床问题。对关联度最高、真正改变结论或安全边界的指南条文与研究，适度展开推荐原文/等级、研究设计、关键结果、病例适配性和局限；低相关或重复来源简要呈现。核心研究使用可点击题名或研究简称，并标注期刊、年份、研究类型和 Oxford CEBM 2009 证据级别；本地索引命中时再追加 `2025 中科院分区/北大核心`，未命中时整段省略。内容较多时可按需使用无序列表，不拆成固定小模块；研究结论不得外推为无条件临床指令。
- **完整参考文献（含链接）**：使用本文件“引用与参考文献”规定的六列表格。

## 可见样式

样式用于突出医学重点，不替代论证：

- 结论可用浅绿或浅蓝 callout；证据有限或待补资料用浅黄/浅橙；高风险、禁忌或当前不支持用浅红。适度加粗关键阈值、风险词和限制条件。
- 风险内容可使用 `🚨`、`⚠️`、`🛡️` 等有明确语义的 emoji，结合短段落或无序列表；只保留与当前问题有关的块。
- 病例结构、指南矩阵、方案比较和决策条件适合表格；解释性分析优先使用自然段和短列表，不要把所有内容表格化。
- 复杂报告可组合结论 callout、病例结构表、证据关系图、决策逻辑图、证据矩阵和方案对比表，但不为凑数量加入无用组件。
- 模板注释、生成约束、占位符、示例说明和工具提示仅用于内部生成，不能出现在可见文档中。写入前必须替换或删除全部 `{{...}}` 占位符，并清除 XML 注释及其文字。

飞书 XML 的 callout 只使用以下起始标签格式：

`<callout emoji="x" background-color="light-yellow">`

其中 `x` 替换为实际 emoji；可按 `lark-doc` 规则增加 `border-color` 或 `text-color`，**不得使用 `type` 属性**。例如：

```xml
<callout emoji="⚠️" background-color="light-yellow">
<p><b>注意事项：</b>正文内容</p>
</callout>
```

公式上标使用 Unicode 字符，如 `²`、`³`、`⁻¹`，不使用 `<sup>`、转义后的 sup 标签、脚注或角标式引用。文档中不得使用 `<ref>` 标签或其转义形式；citation 组件可以作为样式容器，但具体来源名称仍须带可点击链接。

## 附件状态与病例资料

生成报告前必须判定 `attachment_state`：

| 状态 | 可见内容 |
|---|---|
| `present` | 可加入“上传资料质量与病例提取”，说明真实附件类型、日期、质量、关键提取和局限 |
| `none` | 只写“用户提供病例信息/证据资料”；不得声称读取附件、OCR、质量分级或影像/报告提取 |
| `ambiguous` | 说明未检测到可读取附件；若继续分析，只能基于用户文字和检索证据 |

用户在聊天中粘贴的超声、化验、病历或报告文字属于“用户提供的病例文字信息”，不是上传附件。无附件时默认不单列“未上传附件”章节。

## 引用与参考文献

### 正文链接

正文、表格和图例第一次提到具体指南、共识、试验、论文、说明书或监管来源时，名称本身必须是可点击链接，并在邻近位置标注期刊/来源和年份；正式文档中的研究标注 Oxford CEBM 2009 证据级别，本地索引命中时并列标注 2025 期刊级别，指南/共识保留原文分级。不能把来源名写成无链接小标题、纯加粗文字、书名号或裸 URL。

推荐格式：

`<a href="{{url}}">DAPA-CKD</a>（NEJM，2020，RCT；Oxford CEBM 2009：1b；期刊级别：中科院 1 区）`

`<a href="{{url}}">KDIGO 2024 CKD Guideline</a>（KDIGO，2024；原指南分级按原文保留）`

Oxford CEBM 2009 和期刊级别及其说明只写入正式飞书、Word 或 PPT 产物。指南/共识的 Oxford 证据级别写 `不适用`，原指南推荐等级另行保留。聊天 Quick Answer 和最终入口回复保持简洁，不逐条展示证据或期刊等级，也不重复文末分级说明。

若某段、表格行或图例引用具体来源，该位置或紧邻位置必须包含相应链接。图中节点不能嵌入链接时，在图下使用邻接表或在正文首次提及时补足；不要只在文末给链接。不得显示内部 `evidence_id`；只有用户明确要求特定引用格式时才使用普通引用序号。

### 完整参考文献（含链接）

第 9 章标题必须包含“链接”，默认按 `核心证据`、`辅助参考` 分组，必要时另列 `排除/待核验`。每组均使用六列表格：

`标题｜来源｜类型｜年份｜期刊分区｜链接`

- `标题`：完整题名、指南名、共识名、说明书名或监管来源名。
- `来源`：期刊、机构、数据库或监管来源。
- `类型`：指南、共识、系统综述、Meta、RCT、队列、诊断研究、安全监管、说明书或辅助参考等；仅对确实阅读全文的重要论文追加 `已阅读全文`。
- `年份`：发表、发布或更新年份。
- `期刊分区`：期刊论文填写 `journal_rank_2025` 明确命中的中科院分区或北大核心；未命中、匹配不唯一或非期刊资料留空，不显示“未匹配”。
- `链接`：必须是 http(s) 可点击锚文本。URL 直接指向 PDF 或现有结果明确标识为 PDF 时显示 `PDF`，其他入口显示 `原链接`；不为判断标签额外逐条访问网页。

核心/辅助角色由质量、权威性、问题匹配度和时效性决定，不按全文可及性机械分组。低级别、不权威、方法学薄弱或相关性不足的资料不得单独支撑关键疗效或安全性结论。

除非用户明确要求 GB/T 7714、Vancouver、AMA 等格式，不得改成编号列表、纯 bibliography 或其他宽表；即使用户要求特定格式，每条仍须保留可点击链接。没有 http(s) 来源入口的展示记录应补链或移除，不写裸 DOI、PMID 或“链接未返回”。

## 飞书在线交付

### 路由与本地预检

判定 `target_format=feishu_doc` 后立即锁定，并先读取 `assets/feishu-doc-template.xml`，再开始生成 XML。直接使用平台已配置的 `lark-doc`，由其路由到 `online-doc`；不要用 `which lark-cli`、`lark-cli skills read`、帮助探测或猜测参数来寻找能力。若平台未加载 `lark-doc`，说明在线文档能力不可用并保留本地 XML 草稿，不自行发明替代命令。

当前平台在线文档命令使用 v2，`docs +create`、`docs +fetch`、`docs +update` 显式传 `--api-version v2`。`docs +fetch --scope` 必须逐字从 `full`、`outline`、`range`、`keyword`、`section` 中选择，不得凭记忆生成别名：完整交付回读固定使用 `full`，只取目录和 block ID 固定使用 `outline`，已知目标时才使用 `range`、`keyword` 或 `section`。命令失败时读取结果中的 `validation`、`allowed` 等结构化错误字段，按任务目标改用 `full` 或 `outline` 后重试一次。具体 XML schema 或命令与本文件冲突时，以平台 `lark-doc` 为准；医学内容、callout、链接和章节要求以本文件为准。

完整回读示例：`lark-cli docs +fetch --api-version v2 --doc "<doc-url-or-token>" --scope full`。目录或 block ID 的简要读取示例：`lark-cli docs +fetch --api-version v2 --doc "<doc-url-or-token>" --scope outline 2>&1 | head -80`，这是合法命令。若返回内容实际出现 `validation: invalid value ... allowed: ...`，表示本次 fetch 未执行；必须按 `allowed` 列表修正参数后再调用，不能继续内容验收或声称回读成功。

写入前完成以下预检：

1. 先生成一份完整本地报告 XML，并运行 `scripts/validate-report-whiteboards.js <report.xml>`。
2. XML 的首个元素必须是 `<title>`，且只有一个标题来源。模板已有 `<title>` 时不得再传 `--title`。
3. 最终待写入 XML 不得残留 XML 注释、`{{...}}` 占位符、模板说明或生成约束；callout、链接和白板符合本文件与 `clinical-diagrams.md`。修复后重新渲染并复跑校验。
4. `--content @file` 使用当前工作目录下的相对路径，不传 `@/absolute/path`，也不使用 `--content "$(cat file)"`。
5. `outline` 简要读取可使用 `2>&1 | head -80` 控制展示长度，不得仅凭管道或 `head` 判定失败；但必须检查已返回内容，出现 `validation`、`allowed`、`error` 等真实错误语义时按失败处理。完整交付验收仍使用 `scope=full`，并保留足以核对正文、结构和写入状态的结果。

### 写入策略

优先用通过校验的完整 XML 一次创建：

`lark-cli docs +create --api-version v2 --content @report.xml`

创建返回通过硬闸门后做一次完整 fetch；内容完整即结束，不再创建骨架或逐章更新。只有一次创建明确因载荷、长度或服务限制失败，且没有留下可用文档时，才启用三块兜底：

1. 创建只含唯一标题和 3 个可见锚点的骨架：`一、总结论`、第 4 章实际标题、`八、检索策略与证据覆盖`。
2. 一次 fetch outline 取得三个锚点 block ID。
3. 最多写入三个大块：
   - `section-1`：第一章正文，以及第二、三章标题和正文，插在“一、总结论”后。
   - `section-2`：第四章正文，以及第五至七章标题和正文，插在第 4 章实际标题后。
   - `section-3`：第八章正文，以及第九、十章标题和正文，插在“八、检索策略与证据覆盖”后。
4. 三个锚点来自同一次 outline fetch；只有 `degrade_code=1002`、需要引用新插入 block 或结构被替换/删除时重新 fetch。
5. 三块写完后统一完整回读，不在每一章后重复 fetch。

不得默认拆成十章十次更新。只有某个大块本身再次触发长度限制时，才只拆该失败大块；`append` 只用于文末追加，不用于填充中间 section。若创建返回 document ID 但同时失败、warning 或回读不完整，先 fetch 同一文档确认实际状态，不立即创建第二份。

### 返回值与停止条件

每次 create、update、fetch 都检查完整 JSON，并可运行：

`node scripts/validate-lark-doc-result.js --operation create|update|fetch lark-result.json`

- create：`ok=true`，document_id/url 存在，warnings 为空。
- update：`ok=true`，`data.result=success`，warnings 为空，`updated_blocks_count > 0`。
- fetch：`ok=true`，且回读到本次报告预期章节、正文链接和参考文献。
- `permission_grant` 存在时必须为 `status=granted`。

`failed`、`partial_success`、warning、更新数为 0、权限失败或回读缺失均阻断下一次写操作。常见问题：

- `degrade_code=1017`：同时使用 `--title` 与 XML `<title>`，保留一种标题来源。
- `degrade_code=5002` 且指向 callout：按本文件“可见样式”删除不支持的属性并重新校验。
- `degrade_code=1002`：回读最新结构，确认内容未落盘后，用新的显式 block ID 重试一次。

只读 fetch 出现 `network.timeout` 时，对同一 fetch 最多重试 2 次，期间不执行新写操作。连续超时则标记“已发起创建但未验证”并停止更新。正常创建过程只保留一次开始状态和最终结果；只有切换三块兜底或最终阻断时，才额外发送一句有价值的状态。

只有实际使用的 create/update 和最终 fetch 均通过，且无 warning、partial success、权限失败或未验证步骤，才可以说“飞书文档交付完成”。

## 最终回复

最终回复按 `assets/final-response-template.md` 和 `response_mode` 生成，不展示内部工具名、harness、模板/QA 指令、证据草稿或长篇过程。

`quick_answer`：

1. 直接回答临床疑问，说明确定性和适用条件。
2. 提示真正重要的风险、证据边界或需医生确认的条件。
3. 回答中每个被提及的外部证据都给各自可点击 URL，不限制篇数；禁止引用或展示自媒体、营销软文、健康博客、问答社区、聚合转载、搜索结果页及来源不明页面。Markdown 链接目标必须以 `https://` 或 `http://` 开头；不输出无协议短链、裸地址或 `[标题](shturl.cc/...)`。简单药品查询也必须提供说明书链接。
4. 病例任务可追问会改变判断的缺失信息；固定条目或无病例问题询问目标人群、使用场景或后续问题，不虚构病例资料。
5. 展示免责声明：“本回答仅提供循证医学信息参考，具体诊疗应结合患者实际情况、检查结果及院内规范，由负责医生综合判断，本回答不可代替医生诊断。”
6. 最后一句固定询问：“是否需要我进一步生成完整循证分析报告？”

`full_report`：

1. 最终回复先直接回答用户问题，再简短提示关键风险或注意点，不能只写“详见文档”。
2. 提供可点击产物入口，如 `[{{标题}}]({{url_or_local_file}})`。
3. 按任务追问会改变判断的病例信息、适用人群或待明确问题。
4. 创建失败时明确产物类型、失败步骤和原因，并提供可重试的完整草稿；不能把聊天短答当作完整报告交付。

飞书文档创建后，按“飞书在线交付”回读，再做一次内容抽查：预期章节、总结论、临床分析、指南/研究证据和参考文献区应存在，正文及文末链接应保留。若回读缺正文或链接，修复源文件并更新后再交付。

## 最小 QA

交付前检查以下 6 类：

1. **任务与格式**：回答了用户实际问题；`response_mode` 和目标产物符合本文件“输出格式路由”，`full_report` 未降级。
2. **病例真实性**：附件状态正确；未虚构患者资料、附件提取、OCR 或影像质量。
3. **证据与表达**：关键结论结合病例和高质量证据，优先考虑中国指南/本土共识，必要说明书或监管来源已覆盖；完整报告已运行期刊级别匹配，论文并列展示 Oxford 证据级别和命中的期刊级别，未命中和非期刊资料无占位提示；`quick_answer` 未引用或展示自媒体、营销软文、健康博客、问答社区、聚合转载、搜索结果页及来源不明页面，并已在最后追问前展示免责声明；不编造，不下直接医嘱，不使用“强推荐”“强烈支持”等高程度措辞。
4. **链接与样式**：正文提及的外部证据均有就地 http(s) 链接，参考文献六列表每条有链接，期刊分区未明确命中时留空；callout 使用 `emoji + background-color` 且无 `type`，公式无 sup 标签，文档无 `<ref>` 标签及其转义形式，内部 `evidence_id` 不可见；可见正文不含模板注释、生成约束或未替换占位符。
5. **结构与图表**：总结论和临床分析在证据展开前；风险/管理章节在证据关系前；所需图表符合 `clinical-diagrams.md` 并通过白板校验。
6. **交付可靠性**：飞书操作、返回值、权限和回读符合本文件“飞书在线交付”；失败或未验证时如实说明，不把 URL、`revision_id`、warning 或 partial success 当作完成。

涉及明确处置动作时，确认其有病例依据、条件和必要补充信息；涉及鉴别诊断时，确认高危排除、核心检查与条件性补充均有覆盖；正文篇幅应明显向最相关的指南、研究和病例化判断倾斜。
