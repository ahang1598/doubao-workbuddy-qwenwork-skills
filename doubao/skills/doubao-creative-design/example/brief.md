# 任务 Brief：公共字段、品类字段与素材清单 转译

本文件是自然语言 Brief 的字段参考，不是新的 JSON Schema，也不是要求逐栏填满的参数表。任务只维护一份 `brief.md`：Spec 填内容，Visual 在原条目追加视觉决策；素材生产的 Prompt、真实输入、短链、版本和准出状态只写入 `asset-manifest.json`。公共字段与命中品类字段合并使用；同义内容只写一次，不再创建视觉 Brief 或资产 Brief。

读取时机：确定产物与生产路线后、完善任务 Brief 前。主 Skill 与品类 Spec／Visual 是决策规则，本文件汇总输出；纯 Coding 由冻结 Brief 直接进入 HTML，AI + Coding 先建立 [轻量素材清单](asset-manifest.md)。字段不适用时省略或简注原因；不能删掉品类必填项。这里的“字段”是中文标题／自然语言条目，不要求增加技术键。

## 公共字段

### 任务与事实

- 主题与主体：做什么，为谁做；商品、品牌、人物或组织，不涉及时明确不适用。
- 目标与受众：传播任务、读者、阅读环境及希望形成的认知／行动。
- 产物与路线：命中品类及理由；数量、尺寸／比例与单位、交付格式、可编辑范围；纯生图、纯 Coding 或 AI + Coding。
- 输入与来源：用户原文、参考图片真实短链、已有资产／母版、来源用途、确认状态、继承与排除项。
- 事实边界：用户提供、已核实、自拟非事实文案、待替换占位分别说明；不得将未知事实写成已确认。必要占位声明也纳入准确文案。
- 保留与修改：用户要求、禁止项、编辑范围、身份保护、不可裁切内容及待澄清缺口。
- 决策优先级：按“用户锁定／品牌或事实规范／确认参考／品类规则／Agent 可裁量”说明本任务真实优先级；同级冲突写明采用项与放弃项。
- 任务状态：当前内容／视觉是否确定、是否需要 KV、确认结论、版本及受影响范围。冻结设计不代表素材已经就绪。

### 整体方案与逐单元内容

- 总方案：主要命题、信息链／说服链、叙事节奏、设计理由与交付边界；说明内容与感受如何从开场推进到收束，不以章节标题列表代替叙事。
- 视觉命题与注意力路径：希望形成的第一印象；第一焦点、第二阅读层、行动／收束点及其与内容目标的关系。
- 数量与顺序：先展开内容与体验，再合并重复任务、确定阅读顺序及单元数量；长页区分叙事段落与实际滚动长度，固定纸幅遵守用户尺寸，不预设跨品类统一页数。
- 每个设计单元：在原条目中写清叙事任务（新增什么理解或感受）、具体内容（观点、解释或比较关系，以及完整准确文案与来源）、画面支撑（主体、视角、场景或细节如何支持表达）、前后推进（承接什么、引出什么；单页不强造跨页关系）。同时保留名称、类型、唯一结论、主次与分组、尺寸策略、配图计划及特殊约束，不另建叙事表。允许扩展有依据的场景、搭配建议和视觉视角，明确创意表达与商品事实的边界；不为增量编造性能、数据或承诺，也不把事实有限等同于只能重复口号。重复且无增量的单元合并，不按字数或屏数扩写。
- 内容结构生产规范：说明本品类的事实、文案、单元职责、顺序、尺寸、素材来源和缺口如何写入同一 Brief，以及哪些内容必须保持可核验。
- 内容结构验收规范：检查完整性、准确性与顺序，并确认每段的关键内容、画面支撑及前后推进已明确；仅有标题、态度口号或“大图＋文字”不能视为叙事完成。不要求每段同时承担解释、比较和情绪任务，按本段职责验收。
- 尺寸策略：用户要求或规划目标的宽高、单位、必要比例、内容增高／分页原因、安全区和切片／折线保护；坐标、实测框与 CSS 参数留给 HTML。
- 文字承载：明确哪些是独立可编辑文字、哪些按路线随图片一体生成；不能在图内与 DOM 重复覆字。
- 适配与状态：目标载体、断点／尺寸变化时保留、重排、降级或移除什么；交互任务列默认、选中、禁用、错误、空白、加载等实际需要状态，静态任务不虚构交互。

### Visual 追加的公共字段

- 风格与依据、艺术表现手法：主体、背景、辅助元素如何表达本次内容。
- 决策边界：本轮锁定项、参考继承项、禁止项、允许 Agent 在 HTML 阶段自行决定的细节及冲突优先级。
- 视觉命题与注意力路径：第一焦点、第二阅读层、收束位置、阅读方向和每屏／页需要形成的视觉结论。
- 配色与文字系统：来源、主辅色和强调色职责、文字角色、字级与阅读关系；不输出技术色值表或模板参数。
- 图片系统：摄影／插画／材质的统一视角、光线、轮廓、裁切和后处理意图。
- 背景系统：按内容组记录全局底面、组级背景与局部覆盖的职责、连续／硬切关系及 CSS／图片／组合方式；同一职责不重复生产，完全遮挡且无其他职责的底图不生成。
- 每屏／页的相对构图：视觉作用与焦点、主体所在区域、图文上下／左右／环绕／叠压关系、相对面积、密度、留白、对齐轴、允许遮挡和不可裁切对象；不写坐标或 CSS 参数。
- 每屏／页的图文占比与图片层级：图片主导／图文平衡／文字主导，主图、辅图、缩略图的尺度差，以及背景、前景、主体和文字的层次关系。
- 每屏／页的容器与开放排版视觉决策：先说明是否需要边界及原因；无需容器时写对齐、分隔、留白和组织方式。需要时写容器家族、承载内容、主次与相对尺度、轮廓、背页／页签／袋口／卷边／折痕／缺口／夹具等结构部件、材质、边缘工艺、厚度／阴影、内部安全区、图文关系和同页变体规则；普通白色圆角矩形不得作为整页默认。
- 跨单元连续性与变化：固定识别锚点、允许变化项、入口／出口及翻页／跨屏接力，避免逐页复制或每页换风格。每条实际接缝只在后一单元用自然语言记录一次：属于连续场景、同章推进还是章节切换，上屏交出什么、下屏如何接住，需要保护的文字／商品／人物，以及采用同一母图延展、结构化分隔或切屏。连续场景必须有同一母图、连续裁切或可验证的共享背景生产单元依据；两张独立完整主图不直接融合。只有背景层确需连续时，才记录两端背景职责、保色／材质要求、保护区与失败后的职责边界，具体渐变、mask、blend、长度和曲线留给 [HTML 组装](../references/workflow/html-assembly.md#屏间过渡路由基础方案优先)。
- 载体适配、极端内容与降级：长标题、多语种、图片缺失、窄版、打印、远读和交互状态下如何保持核心目标；不得靠删事实或整体缩小解决。
- 布局能力名称与可见关系：采用品类 Visual 内的自然语言名称，例如“连续流动（串页）”或“规整对齐（方格／网格）”，并说明作用对象与边界。先形成视觉草案，再查询能力；Brief 通过短采用记录保存选中 ID、源路径与版本、范围和内容映射，不保存类名、参数副本或查询日志。
- 参考图短链与借鉴内容、素材生产意图、视觉验收条件及必要降级。验收条件写成可观察结果，覆盖焦点、文案、图文比例、主体保护、背景关系、一致性与禁用效果；查库不替代设计，也不强制用卡片。
- 视觉效果生产规范：说明本任务怎样落实已选风格、构图、字体、配色、背景、容器、素材和跨单元关系。
- 视觉效果验收规范：说明最终画面必须观察哪些焦点、可读性、图文关系、主体保护、连续性、载体适配和禁用效果；不能用模板命中或字段齐全代替。

### 每张图片的设计意图

- 画面职责：先为叙事任务选择能支撑表达的观看方式，如整体情境、主体轮廓、局部观察或同条件对照，再确定图片名称、所属单元、用途、数量及前后关系。不同观看方式按内容选用，不要求逐类生成；不先限定“人物图＋单品图”数量再安排章节。同一资产能兑现多个任务时复用并注明使用处，不复制记录或重复生图。
- 目标配图：以自然语言说明主体、情境、风格、光影与承托、目标画幅、主体范围和位置、文字净空、图文及背景关系、允许裁切区与透明需求；设计画面，不只写“使用原图、去底、放右侧”。
- 参考贡献：实际查看后说明每张参考提供的身份、事实、姿态、构图、光影或调性，以及必须保留、允许变化和不能继承的部分。仅用于身份或风格的参考不默认锁定整张照片；用户明确锁定的原图与继承要求优先。
- 素材生产意图／使用说明：对照目标配图和参考贡献选择参考编辑、生成、抠图、修整、组合或复用，说明各自解决的画面差距及保护项；不固定处理顺序。原图同时满足表达、构图与显示质量时可直接使用，否则按方案处理，不以原图现成或去底完成代替配图设计。按最终版面检查焦点、身份、清晰度、图文关系及整组一致性；未实现前只记录目标，不宣称通过。正式生产方式、真实输入短链、完整 Prompt、比例、目标尺寸、安全区、消费者和准出标准在建立 `asset-manifest.json` 时编译，不在 Brief 重复维护。
- 生产结果、处理版本、真实 URI、尺寸、Alpha、准出状态、未通过原因和最终采用版本只写回对应素材记录；Brief 不随生产过程复制这些事实。Canvas Item ID 不代替图片短链。

## 未匹配品类的通用字段

仅在真正没有可匹配的主产物 Ref 时使用[通用兜底](../references/style/coding/generic-visual-fallback.md)，不因局部交付绕过所属品类。

- 路由与原因：通用兜底、未匹配原因；HTML 使用 `category_ref_key: generic-fallback`，不伪造某品类键。
- 产物与任务：名称、数量、尺寸／比例／单位、格式、可编辑性、受众与阅读环境、传播任务、唯一主命题、按需主行动。
- 内容与事实：准确必需文案／数据／标识／入口、来源与事实状态、整理／补写权限、禁止伪造项和缺口。
- 素材：原始来源、身份母版、可生成范围、使用位置、目标画幅、保护区及逐图生产意图／使用说明；正式 Prompt 进入素材清单，生成与处理短链按公共图片条目回写。
- 组织：真实阅读顺序、逐单元职责、入口出口、内容分组、主次、配图和尺寸策略。
- 视觉：视觉主张、构图、文字系统、配色系统、图片系统、表面与容器、留白节奏、边界处理、按需唯一母题及重复规则；逐单元补背景和容器效果。
- 生产与验收：各元素用图片还是可编辑文字／原生图形、参考与身份保护、交互范围、实际交付与验收条件。
- 使用与品类相同的自然语言 Brief → 公共 HTML，不新增通用参数合同。查询 CSS 时不传不存在的 `--ref-key generic-fallback`；按真实效果查询并判断候选边界，不修改品类映射冒充命中。

## Brief 到生产文件的对齐

Brief 是内容与视觉决策的唯一规划事实源，不自动转换成另一份全量参数文件。素材与排版必须兑现已确定的叙事任务、关键内容和画面支撑；压缩措辞时先更新同一 Brief 的准确文案，调整呈现方式不得丢失内容含义。不能用空泛口号替换具体内容，或无说明地删去解释、比较和支撑画面；实质调整返回同一 Brief 更新受影响项。

- 纯生图：从 Brief 组织最终成品 Prompt，并记录真实输出。
- 纯 Coding：冻结 Brief 后直接编写完整 HTML；DOM、坐标、层级、字体、颜色和 CSS/SVG 实现只在 HTML 中维护。
- AI + Coding：冻结 Brief 后，根据每张图片的生产意图，把正式图片调用所需的用途、生产方式、来源、完整 Prompt、尺寸、安全区、消费者和准出标准编译到 `asset-manifest.json`；素材就绪后直接编写 HTML。Prompt 只在 manifest 维护。
- 最终可见文案逐字来自 Brief。规划说明、理由和 QA 元数据不得进入 DOM。
- 长图不维护手填几何投影；给连续顶层区段设置唯一 `data-section-id`，由浏览器检查器读取最终 HTML 的实际 DOM 几何。

### 版本与完整性门禁

1. Spec 内容、Visual 可见决策、准确文案和逐图职责齐全，经适用 KV 确认后冻结 Brief。
2. AI + Coding 在首次正式图片调用前通过素材清单校验；生图／后处理后立即回填素材记录的真实 URI、尺寸、Alpha、版本和采用状态，Brief 只在设计意图变化时更新。
3. 编写 HTML 前所有实际消费者需要的素材均已就绪；纯 Coding 不为证明就绪创建空素材清单。
4. 图内文字范围由 Brief 明确；其余标题、正文、数字、标签和来源保持真实可编辑 DOM。
5. CSS/SVG 选择、字体、元素关系和几何直接落实到 HTML，并通过实际 DOM、截图与平台回读验收；任何清单通过都不能替代视觉正确。


## CSS 采用记录（HTML 路线必填，保持简短）

正文先回答“哪些真实内容、为什么这样排、如何验收”；采用记录回答“哪个来源用于哪里”。每个实际采用的组合或原子写一条，不记录全量候选、类名或 CSS 参数副本。

- Brief 版本与状态；尺寸模式：固定或自然增高；目标宽高。固定画幅不得靠加高解决溢出，自然增高在实测后回填最终高度并递增版本。
- 来源：真实 catalog ID、源文件及 anchor、读取时源文件 SHA-256。Visual 家族编号（如 RV5.3）不等于 CSS ID。
- 范围：整页／章节／局部／原子。采用依据与未采用原因用一句话说明；“约七成匹配”只能是有具体关系证据的估计。
- 内容映射：Brief 内容标题 → HTML 稳定区域标识；保留的主次、阅读顺序和跨区关系；调整与原因。
- 验收：可观察的构图、文字完整性、尺寸和安全区要求。冻结前排除“左侧/上方”等未决选项；真实参数只在最终 HTML 维护。
