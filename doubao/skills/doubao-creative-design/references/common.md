# 共用内容、创意与身份策略

## 1. 概述

统一需求记录、事实边界、创意构图与身份保护。路线和批准触发见 `SKILL.md`；参考继承见 `reference.md`；编辑范围见 `edit.md`；能力、状态及交付见 `SKILL.md`，具体检查见 `quality.md`。

## 2. 使用场景

- **新建与延展**：先组织内容，再确定视觉策略和素材职责。
- **复刻与局部修改**：保留已锁定的构图、密度、材质、光线和字体关系，只处理授权变化，不重新发散。
- **身份相关制作**：商品、人物、品牌、Logo及角色使用真实来源或已确认母版。
- **建议与审查**：按相关条款分析，不建立生产Brief，不启动生成流程。

## 3. 核心流程

1. **按任务组织需求。** 简单纯图直接依据用户要求与参考编写提示词，不要求建立、保存或冻结 Brief。混合生产、纯代码及详情页、长图、VI、三折页、套图等需统筹内容或跨页关系的复杂任务，维护同一份自然语言 `brief.md`，记录内容、尺寸、准确文案、来源、视觉方案、参考用途及交付与编辑范围；已有 Brief 直接更新，不另建生产 Brief。
2. **集中澄清阻断项。** 只问影响当前产物、事实、范围或执行的缺失信息。数量、版本差异及高成本规格无依据时不擅定；非事实偏好可依上下文默认，不违背用户要求或显著增费。产物未定不先制作，已知答案不重复询问。
3. **先核实内容。** 现实主张使用用户资料或可核验来源；缺失集中记录，仅暂停依赖部分。先形成内容结构与逐字文案，再确定视觉；明确每处文字由图片还是原生层承载。
4. **形成创意推导链。** 新建或整体重做按“受众认知、情绪或行为目标 → 主题张力 → 具体对象、动作与关系 → 构图与视觉处理 → 最终可见画面”推导，说明各步如何支撑主题。必要时比较机制不同的方案，不设固定候选数或评分权重；最终保留一个主机制，辅助处理只服务主张。局部编辑不重新发散。创意新建或整体重做时，围绕本次品牌、商品或活动的具体特点设计，避免只替换名称、沿用通用画面；指定模板、复刻及局部修改沿用已确定的方案。
5. **落实图文关系。** 写清主体、动作、构图、阅读路径、字体与色彩职责、素材用途及保护范围。方案须能用具体对象和可见关系复述，不以“高级”等风格词代替设计。
6. **同步有效版本。** 自拟分组、顺序和文案可在确认前调整；确认后改变内容、主构图或视觉关系，记录原因、版本和影响范围，按入口处理确认。续做或状态不明时回读真实源及母版，保护原件和历史版本。

### 按需检索

- **按缺口检索。** 用户明确要求，或任务依赖尚未提供、无法确认的外部事实或特定视觉资料时检索；另遵守当前环境必须检索的要求。普通创作和已有充分参考的编辑不默认搜索。视觉创作提到豆包时，按[主入口的图像工具使用指南](../SKILL.md#图像工具使用指南)先确认对应品牌参考，再决定是否搜索。用户指出指定 IP、身份或事实错误，且现有参考不足时先核实关键依据；参考充分时直接据此修正，不凭未经核实的记忆反复生成。
- **按目标选资料。** 围绕具体缺口组织关键词，必要时限定型号、版本、时间或地域。事实查文字资料，外观查图片资料，优先官方与原始来源；用户已有参考图时直接读图，不搜相似图替代。
- **使用前核对。** 检查对象与版本是否匹配，实际查看检索图片并记录参考用途；不以搜索摘要代替完整依据，不替换用户指定身份。将核实信息用于内容与方案，保留来源链接，不编造图片地址。
- **同一目标最多两轮。** 每轮可含围绕同一缺口的多个查询；首轮不足时调整关键词、来源或限定条件，资料充分即停止。不重复相同查询，不通过改名或拆分目标重置轮次；检索轮次与生成后反思、修复分别计数。
- **缺口按必要性处理。** 两轮后仍不足，省略非必要信息，必要缺口进入下述澄清。工具不可用时说明限制，不声称已检索或核实；用户才能提供的私有事实、素材与偏好不靠检索猜测。

### 澄清工具使用

- **提问必须帮助创作。** 问题须与当前产物、使用场景和阶段直接相关，回答应能帮助产物更可用、更符合规范或改善表达效果。提问前明确“答案会改变哪项内容、规格或设计决定”；无法说明实际影响的问题不问，不为填满题数收集泛泛偏好。
- **问题应当有效、可回答。** 围绕具体缺口，用用户能理解的语言说明选择及影响，不堆设计术语，不诱导未经证实的结论。已有材料能回答、规范已明确或可合理自主判断的事项直接处理；确需用户决定且无安全默认值时，才纳入本次澄清。
- **只问阻塞问题。** 缺少不可替代的真实输入、产物无法确定、要求冲突或关键规格无安全默认值时才提问。已知答案不重复问，非阻塞偏好按上下文处理；不以文字问卷代替视觉方案。
- **一次集中 1–3 题。** 按“核心事实与必需素材 → 产物及范围 → 互斥要求 → 数量与规格”排序，仅纳入阻塞项。每题解决一个决策，说明缺什么及其影响，不把多个独立问题塞进一题。
- **选项具体可执行。** 有明确选择时提供 2–4 个选项，写清产物、范围或规格差异；题数与选项数不得超过工具上限。互斥决策用单选，确可组合且工具支持时才用多选。准确名称、原文、日期等用自由输入，不编造候选；不手加工具已提供的“其他”选项。
- **调用当前澄清工具。** 环境提供 `interaction.ask` 时按其实际协议调用；其他环境使用当前模式可用的结构化输入工具，如 `request_user_input` 或 `request_user_input_async`。不调用未暴露、被模式禁用或不支持该用途的工具，不用普通文本、Markdown 选项或结尾问句模拟调用，也不在调用前后重复问题。

| 提问内容 | 字段与填写要求 |
|---|---|
| 问题标识 | 工具要求 `question_id`／`id` 时使用同次调用唯一的 snake_case 标识，长度服从实际协议 |
| 短标题 | 工具支持 `header` 时填写简短主题，遵守长度限制；它不能替代完整问题 |
| 问题与原因 | 按实际 `question`／`title` 等字段写完整问题；有 `display_message` 时可单独说明阻塞原因，没有则合入问题，不另造字段 |
| 选项与自由输入 | 按工具支持的选项结构、说明字段及输入方式填写；不把单选工具当多选，不把文本输入当素材上传 |

例如，必须保留商品外观但缺少原图时，询问“需要保留哪一款商品的外观？请提供对应原图或可访问链接，用于核对身份。”仅在工具支持附件时收集原图；仅支持文本时收集可访问链接，不要求通过文本工具上传文件。

- **前期集中澄清一次。** 回答后据此更新内容、数量、规格与输入；已有 Brief 时同步更新，再执行，不重复问卷或要求再次确认答案。后续仍缺必要信息时说明并暂停依赖部分，不追加问卷；创作目标或交付对象实质改变时按新任务判断。
- **等待真实回答。** 异步工具调用完成不等于用户已回答。收到必要答案前暂停依赖步骤，无依赖工作可继续；默认选项、未回复和等待时长均不构成回答或批准。
- **工具失败只暂停依赖。** 工具不可用、调用失败或无法收集必要素材时，说明限制并暂停受影响步骤，不假造答案或降级为文本问卷；不受影响的已授权工作继续。
- **制作确认单独处理。** 前期信息澄清不代替 KV、封面或身份母版确认，也不因“一次澄清”取消这些入口要求。各阶段按主入口处理，不新增确认环节。

仅实际平台或工具要求消耗确认时，展示已确定的内容、数量、规格、方向和输入，再按平台机制确认；这些参数变化后重新处理。“暂不生成”或未回复不构成许可，暂停依赖步骤，不擅自采用低成本替代。普通澄清不附带生成确认，不因主观风格或成本高另增确认。

## 4. 不同产物/策略展开

### 事实与创作分开处理

- **现实主张有依据。** 价格、参数、日期、数据、功能、功效、承诺、认证、身份、联系方式及权利状态不可补造，也不以免责声明放行。履历、营业信息、权益及通知结果同样适用。
- **表达可主动完善。** 主动完善标题、副标、叙事、栏目和过渡，依据已有事实写出实际展示的介绍、特点解释、使用情境、说明与图注。说明性内容应让读者理解对象、具体特点及其意义，不能只换写标题或重复口号；按内容需要展开，不设最低字数，不强求各模块同样长。缺少某项事实时，继续完善其余有依据的内容，不补造主张或附无必要的占位声明。保留锁定原文、专名、数量与单位，不为排版删事实。
- **虚构明确用途。** 获准的故事、概念及演示不冒充真实证据、有效凭证或机构承诺；招聘业务补写作为待确认提案，健康建议和定量内容须有依据。新创Logo不声称已注册、无侵权或取得授权。
- **行动入口真实可用。** 正式扫码、拨打、联系或跳转须有真实目标。草稿未要求入口有效时，可明确标“二维码待补”，不制作假码、号码或链接；改变报名、投递方式须确认。
- **来源如实区分。** 用户资料、核验资料、生成内容、脚本产物和混合结果分别记录；资料推断不冒称原文结论，内部旧平台基准不冒称现行官方标准。

### 构图服务内容

- **按内容分配空间。** 写清必要内容，合并重复表达，再安排主体与文字。偏空时先补足有依据的必要解释；内容充分后调整模块位置、主图尺度、栏宽和间距。双栏主栏提前结束、侧栏拖长时，压缩辅助模块或改为通栏，不机械拉齐栏底；长图可缩短未锁定的段高。保留锁定尺寸、原文、极简要求与有意留白，不靠虚构事实、重复文案或装饰填满。
- **先分内容组，再定屏。** 按阅读任务组织入口、解释与收束。详情页和长图中，服务同一问题的相邻内容优先合并组织；需要独立比较、取景或换章时再分开，不因同类型而强并。制作分屏不等于视觉换章，不把每屏都做成独立海报；页数、面序和尺寸锁定时在既定范围内重排。海报突出首眼识别，电商对应购买证据，套图兼顾系列与单页可读，数据图保护口径和比例。
- **建立可见关系。** 主体、背景、标题及信息通过对齐、遮挡、穿插、承托或共享留白形成联系。容器承担聚组职责，装饰连接对象或动线。移除任一主层后，其他层应能体现原有配合，而非仅配色相近。
- **保留构图依据。** 海报和简单视觉默认避免无目的居中；标识、对称对象、仪式表达及明确对称要求可采用。网格可服务比较和检索，不把海报构图强加给仪表盘。
- **继承关键机制。** 记录参考中需保留、允许适配及不采用的关系；改变核心尺度、裁切或图文关系时明确自定义。专属Logo、水印、角色和事实不随风格复制。具体观察与重建按 `reference.md`。
- **明确方案差异。** 有多个方向时，差异应来自符号、动作、空间、视角或信息揭示方式；仅换颜色、字体或位置不算新机制。淘汰事实错误、冲突参考或与主题无关的方案，不据此撤销入口允许的纯图路线。

### 文字净空与连续空间

- **拼贴、手绘风不影响正文。** 风格可用于背景、装饰、标题和容器外观；正文及正文容器保持水平，不倾斜或变形，正文清晰可读。
- **按最终画面预留净空。** 结合字色、明暗、纹理与裁切安排文字，避开人脸关键五官、产品识别特征及必要证据。装饰性穿插须保持文字可读、主体可辨；冲突先移字、调整取景或重排，不靠压暗主体和加厚字效遮掩。正文不普遍套描边投影；短摄影标题、漫画大字可按风格使用。
- **保留遮黑带限制。** 禁止随文字框临时新增灰黑底板、雾带或压暗横带；调光、羽化或烘焙进图不改变该限制。有独立职责的既定纸签、铭牌、票据可承载信息。
- **区分放射图形与光效。** 通知、公告、喜报、捷报、成果战报、邀请函和节庆贺图默认不用放射；用户明确要求才使用平面放射，光效须另有明确要求。红金、丝绸、金属或庆典语义不构成光效授权。
- **按边界职责融合。** 图窗和换章可保留清楚边界；连续照片须有一致透视、尺度、光向和接触关系，仅安全空场用于Alpha衔接，不以黑幕、白雾或短色带遮缝。
- **保护接缝两侧。** 最终缩放和换行后，文字边界向外默认扩半个当前行高，并计入描边、字影及完整羽化尾部；图内文字实际看图定位。标题、正文、Logo、二维码均不得受侵。空间不足先移字、移边或重排，不覆字或压暗硬叠。

### 身份与生产分工

- **每个身份保持母版。** 实际查看上传图，区分身份、风格、版式和证据；记录可读来源、版本、不变量与允许变化，多款无法对应时不猜型号，不预填未来句柄。
- **先确认再衍生。** 从零创建先完成母版生成、展示与身份批准；混合路线另做身份核验；已有身份缺源仅阻断相关制作。错误首图或上一衍生图不升格为母版。
- **传入真实参考。** 身份敏感调用实际输入母版图；已有成品修改同时以当前成品为目标。工具不能接收必要输入时暂停，不以文字近似重绘。
- **独立变体不串源。** 同源N个独立变体预先锁定后分别执行N次编辑，使用同一已确认母版；连续扩图按实际依赖执行。直接摆放可复用真实资产。
- **先分工再组装。** 混合制作区分真实主体、生成影像、准确原生文字、确定性图形、独立遮罩资产及临时参考，拆分完成后才生产正式素材。纯图不强制拆层，纯代码不调用生图。
- **保护比例与范围。** 摄影、插画及生成素材等比缩放；局部授权只解除指定项。固定画布与容量见 `produce-code.md`，字体见 `fonts.md`，模板依赖与采用见 `templates.md`。

## 5. 输出形式

- **按任务保留设计依据。** 简单纯图将准确文案、视觉方案与保留项落实到提示词，尺寸及参考按工具协议传入。需要 Brief 的任务保存内容、来源、方案、图文关系、锁定项及待补项；整体决定写一次，各页只补差异，纯图执行不重复建档或增加冻结步骤。
- **实现参数留在源文件。** 坐标、字号、色值、CSS/SVG及消费位置不另建几何副本。素材句柄、生产历史与处理记录留在既有素材记录，不复制为第二份Brief。
- **按入口进入生产。** 本文件输出内容与视觉依据，不以规划完成替代图像生成、真实展示、批准或交付。
