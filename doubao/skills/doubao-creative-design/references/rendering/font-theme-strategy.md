# 场景与主题字体策略

本文件负责共享的字形选择、文字角色与搭配判断。pure-image 可按需查询候选作为视觉参考，将形态与层级用于原 Prompt，并按原路线检查成图可读性，不承诺精确 family。实际使用字体资源排版时，才进入 `font-family-library.md` 与 `assets/fonts/catalogs/` 的资源执行，核验许可、下载、目标环境加载和真实文案字形覆盖。

字体选择发生在生产轨道与产物格式锁定之后。字体推荐、解析、缺字处理、许可判断和回退不得创建、切换或推断产物格式，也不得因为字体库、Resolver 或字体契约把已确定的 HTML、既有分层源或其他产物改成另一种协议。字体模块只返回协议无关的字体选择结果，由已锁定的生产 workflow 负责落地。

## 1. 决策顺序

```text
品类
→ 真实文案语种
→ 文字角色
→ 已锁定的参考字形；未限定时按主题确定字体形态
→ 候选字体与视觉适配
  ├─ pure-image：作为字形／搭配参考，按原路线检查成图
  └─ 实际字体排版：许可门 → 本地／CDN 资源核验
     → 适用的 Item 字段注册检查、目标环境实际加载与真实文案字形覆盖
     → 按已锁定协议记录：HTML 所选值仅入最终 HTML，核验结论入既有 validation 输出；其他格式按已选 workflow 的实际要求记录
```

不得从主题名直接跳到字体名称，也不得因为字体出现在目录中就认为可以渲染。

## 2. 四类文字角色

| 档位 | 职责 | 可用字形 | 约束 |
|---|---|---|---|
| `hero` | 品牌名、封面标题、主 KV | 展示黑体、展示衬线、圆体、受控手写或装饰体 | 可编辑设计的独立艺术标题仅限明确准入的首屏／首图或单图唯一最重要大标题；其余 hero 按原文字分配保持可编辑。pure-image 仅共享视觉角色，不继承此艺术标题准入限制 |
| `sub` | 栏目名、卖点标题、模块标题 | 中等个性黑体、衬线、圆体 | 必须与 hero 拉开层级，同时能连续复用 |
| `body` | 正文、规则、说明、经历、参数 | 中性黑体、正文衬线、圆体 | 禁用书法、像素、黑信体和强装饰字体 |
| `meta` | 次要日期、地址、规格、注释、页码；价格/核心日期按实际重要性分配角色 | 中性黑体、等宽或数字稳定字体 | 优先清晰、完整字符集和表格数字 |

默认用两个协调的字体家族建立层级；单家族可依靠真实字重完成，多语种必要补充须有覆盖与搭配依据。不把每个角色对应成一种新字体，也不能用伪粗体代替真实字重。

可编辑设计必须额外遵守文字生产边界：独立艺术标题按视觉职责而非 H1 层级由 Brief 明确准入，只限首屏／首图主标题或每个独立图片唯一最重要的大标题，同一图片默认最多一个，具体品类限制仍优先。一体化 Hero 内文案沿用原 workflow 的分配；其余标题包括普通 H1 从本策略与字体库选择，按需用 Resolver 核验本地资源，并完成目标环境加载与覆盖验证，再由已锁定 workflow 实现为可编辑文字。Resolver 本地通过不等于目标端可用，字体选择本身不得决定实现协议。

## 3. 品类角色映射

| 品类 ID | 角色映射 |
|---|---|
| `logo` | 字标起始字体→hero；提案标题→sub；说明→body；参数→meta |
| `vi` | 品牌世界标题→hero；系统章节→sub；规范说明→body；Token/版本→meta |
| `announcement_poster` | 公告标题→hero；事实标题→sub；正文→body；日期/地点/发布方→meta |
| `tri_fold` | 封面标题→hero；栏目标题→sub；介绍→body；地址/时间→meta |
| `resume` | 姓名→hero；栏目标题→sub；经历正文→body；日期/联系方式→meta |
| `social_carousel` | 封面标题→hero；内页标题→sub；正文→body；页码/来源→meta |
| `social_long_image` | 首屏标题/关键数字→hero；模块标题→sub；正文→body；来源→meta |
| `ecommerce_detail` | 主 KV→hero；卖点标题→sub；参数/FAQ→body；价格/规格/脚注→meta |

上表是常见角色映射；核心日期、价格和数据可按实际信息优先级提升为 hero/sub，不因字段名固定成小字。Logo 字标字体只是设计起点，不自动成为 VI 正文或 UI 字体。通知、简历、电商参数等事实文字不得使用难读展示体。

## 4. 主题识别与统一候选数据

[`font-curated-pool.json`](../../assets/fonts/font-curated-pool.json) 是主题、角色、语种推荐和组合映射的唯一查询数据源。集合同时保留既有中英推荐、扩展精选候选及平台清单，不以某一份较小名单覆盖其他有效候选。原始资源事实继续来自 Catalog；实际 Canvas Item 字段明确引用平台表时，以 [`fonts.md`](../items/fonts.md) 核对精确 family 和已注册字重/样式，JSON 中的 `platform_fonts` 为经过一致性检查的查询镜像。HTML Item 内的 DOM 文字遵循 HTML 协议，不以该表作为全局白名单。

主题覆盖原有商务、极简、科技、典雅、柔和、复古、文艺、国风、亲子、街头、运动、清新、暗黑和像素，以及烘焙咖啡、茶饮植萃、节庆民艺、时尚杂志、手帐手作、音乐演出、艺术展览、美妆香氛、零售促销、旅行生活，并补充新中式、杂志编辑和自然生活分支。主题 ID、关键词及候选数量以查询结果为准，不在多份文档维护第二套排序名单。

用户明确的品牌字体或参考字形优先。按 [参考解析](../style/coding/ai-coding/reference-analysis.md) 保留可见笔画、重量和姿态，未知字体名不冒充识别结果。多个主题命中时选择一个主主题，以另一个作为修饰意图；不要同时加载两套字体语法。

`fonts` 中的记录数不是已安装字体数：`editorial_candidate` 可以进入角色召回；`registered_unclassified` 仅保留平台注册信息，不自动填充主题推荐。`legacy_recommendations` 保存原主题表的名称及使用情境，含未能解析的候选；`catalog_id=null` 必须显示待核验，不能编造文件、URL、精确 face 或授权。展示黑体、受控装饰体等类型描述不算具体字体。

## 5. 按真实文案查询

```bash
python3 scripts/runtime/select_fonts.py --list-themes
python3 scripts/runtime/select_fonts.py --theme bakery_cafe --role hero --language zh --limit 10
python3 scripts/runtime/select_fonts.py --theme bakery_cafe --role sub --language en --limit 6
python3 scripts/runtime/select_fonts.py --theme tea_natural --role body --language ko --shape serif
python3 scripts/runtime/select_fonts.py --combination combination.four-zone-imagery --role hero --language zh
python3 scripts/runtime/query-css-library.py describe combination.four-zone-imagery --font-language en
python3 scripts/runtime/select_fonts.py --list-platform-fonts
```

顺序为“用户与参考约束 → 组合推荐 → 主题候选 → 同角色、同语种且符合字形/标签的补充”。组合正文中的精确 family、face 或字形仍优先，通用组合名不锁定原案例行业。`--language` 是召回范围，不是逐字覆盖证明；默认中文，有英文、韩文或日文时分别调用。其他语种直接检索多语种 Catalog 并核验，不以中文候选冒充覆盖。

`--shape` 和多个 `--tag` 在所有阶段共同过滤，多个标签取交集。`--exclude` 可重复排除名称、key、别名、catalog ID 或已绑定的平台注册 family，被拒绝字体不会在后续阶段返回。候选不足返回 `shortfall`，不以不匹配字体凑数；一般只试排 2–3 项真正适配的候选。

`--platform-only` 只筛登记在平台表中的 family；`--available-only` 只筛本地文件存在或历史 CDN 清单收录。二者不证明当前平台加载、许可、真实 face 或字形覆盖通过。平台注册但未分类的字体通过 `--list-platform-fonts` 检索，先判断角色和可读性，再用于设计。

### 新主题的搭配策略

| 设计任务 | 主标题选择依据 | 正文与辅助文字 | 试排重点 |
|---|---|---|---|
| 烘焙／咖啡、手帐／手作 | 产品形态圆润可比较圆体，自然手作语气可比较手写；两者不自动等同 | 稳定阅读字形，与食品／纸张纹理分开 | 品牌短词、长品名、价格及英文副标；手写不铺满价目表 |
| 茶饮／植萃、节庆／民艺 | 宋／楷／书写候选与真实主题母题呼应，不因东方题材必选毛笔 | 正文保持可读的真实字重 | 生僻地名、原料名与数字单位，不靠艺术字掩盖缺字 |
| 时尚／杂志、美妆／香氛 | 比较衬线反差与清楚的无衬线，依据观看距离选择重量 | 小字有足够笔画与对比 | 细笔画在图像上是否消失、品牌字距与中英墨色 |
| 音乐／演出、艺术／展览 | 标题可用强展示或编辑式字形，字形节奏服务作品气质 | 日期、地点、场次沿清楚阅读轴 | 多行艺术家姓名、长场馆名与必要信息的主次 |
| 零售／促销、运动 | 比较真实粗体、紧凑字形；只有需要方向感时才用原生倾斜 | 价格规则、期限、单位使用可读 face | 最长金额、币种、百分号与价格条件；不伪粗、不压扁 |
| 旅行／生活 | 按目的地内容选人文衬线、清新圆体或中性无衬线 | 行程、交通、联系方式稳定排列 | 长地名、多语标点与窄栏换行，不把所有内容做手写 |

以上是选型判断，候选名称与排序仍由 JSON 查询，不按主题固定一个字体。

### 新中式、杂志编辑与自然生活的分支

新增分支与既有主题共存，仍从同一 JSON 按真实语种与角色查询，不在文档维护另一套排名：

- `neo_chinese`：服务宋韵留白、当代东方、古籍金石及受控书写，不默认套用国潮毛笔字。先区分字面疏密、笔画反差与书写姿态，再试排候选。源云明体、繁媛明朝和朱雀仿宋用于比较宋／明体方向；齐伋系列是不同字包与覆盖，择一试排，不当作三个风格混搭；寒蝉书体须锁定龙藏具体版本，不把同品牌其他字体当同款，书法与刻本字形不进入连续正文。正文可试排朱雀仿宋或既有阅读宋体，小字保持真实字重与清晰对比。
- `editorial_magazine`：人物专题、编辑式栏目与长文层级，重点是标题与连续阅读的字级、行长和中英墨色；`fashion_editorial` 等既有时尚主题继续保留，侧重时尚品牌与视觉表达。两者有交集时选一个主主题并记录修饰意图，不叠加两套字体语法。
- `natural_lifestyle`：自然生活与手帐随笔，按真实手作语气比较受控手写、宋体或中性阅读字形；与既有手作、旅行、烘焙主题按内容职责选择，不因“自然”就把全部段落改成手写。

Zen Antique 当前仅进入日语标题候选；目录语种不能证明中文覆盖，也未证明等同参考中所称“Zen 老式明朝”。中日混排分别查询并对真实字逐项核验。全部新候选都是待试排资源，入池不证明已安装、已获授权、已加载或已通过本次文案检查，不扩大 70 family 平台清单。新旧候选共同遵守语种、角色与排除项约束；实际使用字体资源时，同样执行许可与目标环境可用性门禁，纯图参考不据此承诺精确字体。

### VI、三折页与混合语种

- VI 先建立字标、品牌标题、规范说明、数字参数的不同职责。同一套角色贯穿应用；字标不自动替代正文。保留用户批准母版，字体推荐不触发重新设计 Logo。展示板标题可更有表现力；实际字体样张与可执行规范值必须展示真实字体和真实字重，pure-image 的视觉规范表达不得冒充精确字体样张或已验证参数。
- 三折页在既定六面、真实折法和目标阅读尺寸内试排最长标题与正文。封面可强、内页可静；六面共享角色体系。超量优先调整六面内容分配、栏宽和行距，不靠无限缩字或改变纸面尺寸解决。既有非文字生产规则与艺术标题准入不由字体模块改写。
- 中英分别查询：比较字高、墨色、基线、标点和数字，再调整字号和字距；中文候选不代表英文也有同等字形。英文长词与全大写需单独看换行。一个中文家族加一个拉丁家族可以组成协调体系，不为每个区块换字体。
- 韩文检查 Hangul 音节、₩、数字、标点与中英混排，例如“오늘 구운 빵 / ₩12,000 / 09:00–18:00”。平台 S-Core Dream 只登记 300 normal，不能推断 700；需要更厚重时换有依据的 face。韩文衬线缺失不能回退简中黑体。
- 日文区分假名、汉字地区字形与拉丁数字。其他语种保留独立候选与实测记录；不以名称带 CJK、Multilingual 或同一家族作为覆盖证据。
- 高密度正文先选择完整、清晰的阅读字形；长标题通过字号、行宽和分行形成主次。字号与字重必须放回背景和最终尺寸检查，不能只在空白样张中判定。

## 6. 品类限制

- `resume`：只使用 `business_pro`、`minimal_modern`、`luxury_elegant`、`retro_classic`、`literary_academic`、`japanese_fresh`、`tech_future`。
- `announcement_poster`：运营公告优先 `business_pro/minimal_modern`；婚礼邀请优先 `luxury_elegant/guochao_oriental`；喜报优先 `business_pro/sport_power/guochao_oriental`；节庆贺图按品牌主题选择。
- `logo`：字体只能作为字标设计起点；最终轮廓、字距、授权和相似性仍由 Logo Spec/QA 管理。
- `vi`：可编辑 VI 的字体角色必须进入 Token、组件和应用；pure-image 按原路线表达角色与搭配，不要求创建可编辑 Token 或组件。字标字体不自动成为正文或 UI 字体。
- `dark_horror`、`street_y2k` 和强手写只允许短标题，不进入简历正文、公告事实、参数、价格或 UI。
- 多语种项目按每种真实文案分别验证覆盖，不用中文或英文结果推断阿拉伯语、泰语、日语、韩语等可用性。

## 7. 选择与解析

1. 先保留用户与参考约束，根据品类和内容确定主主题，再按每段真实语种调用共享查询器。
2. 将每段文字映射到 `hero/sub/body/meta`。
3. 每个角色比较 2–3 个满足字形要求的候选，以设计适配为先。pure-image 将字形、重量与搭配意图写入原 Brief／Prompt，按原路线检查成图，不强制安装、字体试排、DOM 或独立 `font-contract`，也不因查询器的资源 `next_step` 改道。以下步骤仅用于实际字体排版，不能因容易加载改变已锁定字形。
4. 用精确名称或 catalog ID 核对资源、许可与实际 face；仅对明确引用平台字体表的 Item 字段核对注册 family/normal/italic/字重。HTML DOM 按 HTML 协议验证目标环境，不因未列平台表而拒绝。本地安装不等于目标渲染器已注册，旧表记录也不等于本次已加载。
5. CDN 可用时只使用 manifest 中已验证的完整 URL，并核对文件大小、MD5 与 Content-Type；按需用 Resolver 检查本地资源，再在目标环境验证实际 family/face 与本次真实文案覆盖，并完成试排。本地检查通过不能替代目标端加载证据。
6. 完成许可、目标环境实际加载、真实 family/face、字重与文案覆盖核验后，由已锁定的生产 workflow 实现并渲染。HTML 的所选字体、角色对应、字重与回退栈等值仅落实在最终 HTML，核验结论写入既有 validation 输出；契约的适用条件与可选消费边界统一遵循 `font-family-library.md` 第 6 节，不把 Resolver 的 `font_contract_entry` 当作必交文件或新增行内 schema。其他格式仅在已选 workflow 确实要求时写入 `font-contract.json`，其中 `source=target_environment`、`availability=verified` 只能用于目标环境已确认的字体；不得在此步骤改变产物格式。

## 8. 回退顺序

```text
同语种、同角色、满足用户/参考字形的下一个组合或主题候选
→ 同语种、同角色且符合形态/标签的其他候选
→ 满足原形态的中性字体（记录视觉差异）
→ 实际字体排版：当前目标环境核验可用且满足上述约束的系统字体；不足时明确缺口
```

思源黑体仅可用于中性黑体要求，不是宋体、书法、手写或韩文的通用回退。用户锁定的字形没有合格候选时明确缺口，不静默替换。实际字体排版禁止静默使用浏览器默认字体；可编辑设计不得为绕过字体问题把普通文字栅格化为图片。pure-image 共享前述视觉替代判断，不要求系统字体安装或加载；图内文字仍按原路线生成、检查和处理，不继承可编辑文字的栅格化禁令。
