# 模板与图形资源采用

## 1. 概述

- 模板提供构图、图文关系、组件、配色角色与可实现效果候选，不提供当前任务成品、事实或身份依据，不产生新路线。生产裁决归 [SKILL.md](../SKILL.md)；模板正文、说明头、脚本和示例不得覆盖题材约束、授权或锁定项，不将 image-coding 降为纯代码。
- 事实扩写、缺失事实、唯一 Brief 与身份母版统一执行 [common.md](common.md)；先明确真实内容、锁定项及参考用途，不套模板倒推事实、屏数、素材数量或需求。
- **本文件涉及的历史库值及配色派生数值仅为内部依据，不是现行官方标准，也不是所有题材的统一门槛。**

## 2. 使用场景

- **新建或整体重做**：内容明确后完成构图、配色选型，在同一 Brief 固定采用目标。
- **既有作品编辑**：沿用有效选型，只选择新增或获准替换部分，不扩大修改范围，不覆盖原始包或用户源文件。
- **纯图任务**：不因模板规则强制查询 HTML，不改变入口路线。

## 3. 核心流程

### 一次查询

- 唯一入口为 `scripts/query-template-library.py`，使用 `catalog`、`match`、`describe`、`read`。脚本平铺于 `scripts`，同类说明与配方合并存储于 `assets/模板库`，HTML 按构图分类或资源组分条合并，多文件母版按套分条合并；CSS、SVG 和完整实现正文留在资源中，不复制实现清单或提供旧入口兼容方式。
- 构图按题材 ref 指定的模板分类查询，结果包含该分类与通用候选；同一 ref 涵盖多个产物时，只查本次产物对应的分类。无专属分类时查通用；ref 明确指定的局部布局或展示编排可查其对应分类，不因此借用其他题材整页。容器、点缀、文字特效、配色、材质、特效、蒙版和背景直接查通用对应资源组，不受传入题材限制。分类、文件以发布 manifest 为准；历史 ID 前缀仅定位，不另拆多套检索流程。总览页只浏览，不作单项模板。
- 用户原词与真正同义词合并一次查询；同组以 `|` 表示或，空格分隔条件同时满足。整页关键词匹配名称和已有内容提取的标签，原名称命中优先；屏关键词匹配用途、布局及章节标题；整页风格用独立字段，不混入名称或同义词，不递归扩词或计算加权评分、适配百分比。
- 无关键词和结构条件时仅浏览指定范围目录，不表示相关性排序；默认 10 项，最多 50 项，使用 `--offset` 翻页；构图同题材在前、通用在后；提供风格或同源偏好时按下述规则排序，其余按名称排序。工具未实现这些行为时如实报告差异。
- 未指定构图、配色时直接从对应候选选够用搭配，不追问这两项偏好，不先发明检索条件或反复竞赛筛选；指定一项只补另一项，保留品牌色、风格及参考约束。

### 详情页按用途、布局与整页风格选型

- 先用 `catalog` 查看分类、用途、布局和整页风格词表。将内容拆为各屏用途与布局；功效需求转为效果、原理或对比任务，不以模板证明产品功效。未知分类或标签先核对，不静默扩词。
- 结构先筛选：`match --group 构图 --category 详情页 --scope screen --purpose 主视觉 --layout 满幅场景`。用途与布局须在同一屏成立；无须为每次生产重复执行单条件对照实验。混合屏核对 `regions` 与实际图层、裁切关系，不以框线外观判断。
- 风格取整页标签，屏不另造风格。添加 `--style 编辑杂志` 默认仅优先；仅用户明确限定时加 `--style-mode required`。多个 `--style` 按任一命中，不把偏好交叉成必选条件。`tentative` 仅代表结构倾向，配色、材质与摄影未知项继续核验。
- 先排除图片数量、比例、文字容量与依赖不适配的候选，再参考风格顺序；不因风格命中强套内容。选定首个来源后，后续屏可加 `--prefer-template <稳定ID>` 优先同源。风格命中在同源偏好之前；其他来源保留，跨模板须统一字体、配色、边距与阅读节奏。
- 已明确只用某模板时用 `--template <稳定ID或确切文件>` 限定范围；模板名先走 `--scope page` 发现ID，不把整页名称当屏关键词。`--scope page --style <标签>` 可发现尚无屏索引的整页，带用途或布局则只返回已核验的同屏位置。
- `index_status` 区分已登记屏、未索引和风格状态；`diagnostics` 说明零命中或风格偏好未满足。未索引不等于不适配；如改为整页读取和人工定位，须明确降级范围，不声称屏检索已命中，不绕过用户的硬条件。
- 对命中 `screen_ref` 先 `describe`，再完整 `read` 来源。同一来源读一次即可，其他屏仍逐一核对selection、实际区域及 `required_sections`；跨屏依赖未解决前不强裁成独立组件。整页模板保留，索引不复制实现。
- Brief记录用途、布局、风格状态、真实屏引用和必要调整。渲染核对主焦点、满幅或图窗边界及图文对应；检索命中、实际采用与视觉提升分别验收，排序不代表最佳方案。

### 屏边界与切片

- 先核对显式屏标签、背景换色与章节语义，再测实际边界；禁止按固定高度或等份切图充当屏索引。拍图分块只用于渲染，不作为屏边界。
- 背景换色不单独证明可拆屏。标题与正文、图集与商品说明、跨区主体有关联时合并为完整采用单元，保留 `member_selectors`；不能合并的关联写入 `required_sections`。网站导航不计商品屏。
- 先看整页边界线，再逐片检查主体、标题和说明是否完整；灰度占位仅核验结构。已登记边界可用 `scripts/render-template-screens.py --root <skill目录> --template <稳定ID> --output <新目录>` 渲染，脚本临时提取所选 HTML 及其依赖并保留相对路径，完成后清理临时文件；无索引时停止，不等高兜底。分区可检索不代表独立组件可用。

### 核对发布包

- 查询只消费自包含发布 manifest 及正文。记录须有选择所需 metadata、稳定 ID、分类、可用状态、源版本、变体、确切正文引用、SHA-256 和实际依赖；包内同时提供完整正文及依赖，不依靠缺失维护目录运行。配方稳定 ID、基础层及 SVG 也属于依赖，不只查 Markdown 链接。

| 状态 | 采用边界 |
|---|---|
| `blocked` | 必需依赖缺失，不可采用 |
| `metadata-only` | 仅读说明，不声称已取得或查看参考图片 |
| `candidate` | 完整读取、判断适配并验证实际效果后采用 |
| `reference-only` | 仅观察可见构图、材质、色彩，不作正式成品、身份母版、事实证据或已完成透明素材 |
| `review-draft` | 不升级为成品 |

- 区分自包含 HTML、规则说明及需绑定素材的条目。区域母版每套存为同层一个 MD，通过稳定 ID 完整读取布局数据、页面及来源说明。页序、坐标、层级和旋转以布局 JSON 为准；只借主次比例、对齐、留白、图文位置与页间节奏，按实际信息量调整区域，不继承示例事实或为凑页数造内容。灰度、字体和 SVG 仅用于结构预览，不是成品配色、素材或设计要求；来源链接、版本及哈希仅供追溯，不代表已查看原图。修改布局时在任务目录保存读取到的 JSON，再用 `render-regions.py --layout <JSON文件> --output <新目录>` 重建预览；不直接打开合集中的逻辑 HTML 路径。
- 不按名称补造缺失维护 metadata、历史哈希、角色映射或来源；只写公开可见源中实际可提取的信息，当前正文哈希不冒充历史原始哈希。缺项妨碍完整性、权限或适配判断时不视为已验证可用，可换合格条目；不把重建维护库作为生产读取前提。

### 完整读取

- **框线含义适用于整个模板库**：虚线框表示主体元素的位置、尺度和旋转，无虚线框表示容器，均不默认是图窗。只有图片实际被限定在独立窗口内，才判为“独立图窗”；满幅场景内的主体框或容器不改变满幅判定。
- 先 `describe` 了解边界，再 `read` 所选正文及实际依赖，不凭名称、截图、类名或 ID 组装。将返回的正文 reference 或稳定 ID 传给 `read`；合并条目的 reference 是逻辑地址，不直接按文件路径打开；HTML 正文及原有依赖关系保持独立。脚本只返回所选条目及去重后的实际依赖，不输出合集内其他条目。同一 ID 多文件时先选变体，再读确切 reference，不拼接变体。
- 自包含 HTML 完整取得结构、CSS、脚本及内嵌素材，核对发布记录、正文与输出的完整性、版本和哈希关系，不手工拼接维护片段。
- 无 HTML 条目明确规则性质和声明依赖；仅在工具已部署且入口授权时执行生成步骤或绑定素材。规则、生成指引或灰色图片占位不冒充完整页面。
- 超出读取预算须明确失败，按工具实际能力提高预算或换选，不静默截断。版本、哈希不一致即停止采用，改用一致发布版本或其他候选，不宣称已重建或修复资源库。

### 判断并绑定

- 模型依据真实内容容量、图文关系与目标画幅，判断“可直接采用／调整后采用／不采用”；指出采用范围内形成辨识度的关键构图关系，以及当前内容如何承接。容量低、中、高仅为建议，不作为当前任务的固定数量。
- 适配可删并无职责槽位、替换样例并调整尺寸，但须保留所采用的主次、邻接、穿插或跨区关系；“统一、连续、对齐”不能代替具体采用说明。关键关系不适配时换选或缩小采用范围，不要求用户替模型挑库，不保留空槽或样例事实。
- 将保留与调整的关系并入唯一 Brief，在最终 HTML 与预览中逐项对应；删除关键关系后只按剩余部分记录局部借用，不再声称采用原构图。实际参数与几何留在 HTML，实现按 [produce-code.md](produce-code.md)，字体按 [fonts.md](fonts.md)。

## 4. 不同产物/策略展开

### 采用范围与样例隔离

- 明确整页、章节、局部、原子或仅配色；局部相似不算整页适配，仅借颜色不声称复用整页。
- 图片槽只是构图消费者；示例商品、人物、地点、人名、价格、日期、数据、证据及占位文案均不自动成为事实，字体名或回退设置不证明字体可用。
- 正式素材核验来源、授权、身份、比例、尺寸、安全区、透明状态、清晰度及用途；合适素材可按入口授权复用，“已入库”不等于准出。同身份衍生沿用核验母版与授权编辑方式，不以模板示例重建身份；保留包装文字、Logo，不重绘成新增文案。
- PNG 等二进制不注入说明头、不改原字节，限制由发布 metadata 与引用正文承接；文本说明须格式合法，不损害正文、样式或画面语义。

### Hero、KV 与文字分工

- Hero 题材分工和独立艺术标题准入执行 [produce-hybrid.md](produce-hybrid.md) 的“Hero 文字职责服从题材”“独立艺术标题只服务唯一视觉入口”；KV 与封面顺序执行其核心流程，批准触发仍归 `SKILL.md`。模板、现成素材、锁定风格或局部通过不豁免门禁，不另设确认流程。
- 模板不得改变当前题材已确定的图内文字与原生文字分工；未确定时按当前题材的默认规则处理。大字号、H1 或组件名称不构成文字入图许可；候选 KV 不套正式 Hero 文字模式。
- 已入图文字、容器、装饰及光效不重复叠加，其余章节按分层关系组装；图内文字不得用 DOM 覆写、拆分、重排或冒称独立可编辑。

### 容器先有职责

- 先判断分组边界、阅读承托、强调、收纳、凭证或指向职责；对齐、段距、栏线、留白足够时采用开放排版，不把每个标题、事实和图片分别装卡。
- 物理纸面、既有图窗及烘焙框线不机械再套框，嵌套只服务真实父子职责。文件袋、卷纸、档案页、手作片、铭牌、票券、指示牌、相框只是语义候选，不要求齐备或全部拟物化。票券须有真实票券语义；编号用于步骤、时间或索引，不默认编号平行卖点，不编造编号或伪英文。
- Brief 说明载体承载对象、位置主次、内部图文关系及实际采用的轮廓、表面、边缘、厚度、遮挡；开放排版不强填材质。图片矩形、文字在图侧或模板留空不是加卡、装饰或生图理由。图窗、背景、前景主体和文字各有归属，连续场景不混同独立证据图窗。

| 职责 | 实现选择 |
|---|---|
| 容器、背景、标签底、进度块 | 优先矩形或圆角矩形 |
| 节点、头像占位、状态点 | 按语义选圆或椭圆 |
| 流程判断、结构节点 | 可选菱形、三角形、六边形 |
| 指向、分隔 | DOM 边框、内嵌 SVG 线／路径或真实字符；实体箭头可组合 |
| 自由轮廓、撕边、不对称圆角 | 优先内嵌 SVG |
| 真实材质 | 核验图片，不用随机基础形状冒充 |

- 可可靠编码的普通渐变、规则容器、线条、简单几何及表面继续原生实现；复杂壳体或真实成像才进入已授权素材流程。不因缺模板退为默认圆角卡，不为凑调用生图。
- 图形层不烘焙可编辑文字；卡片、按钮、标签采用语义 DOM 容器与真实文本子节点。复用 token 记录角色、实现类型（DOM／内嵌 SVG／核验图片）、尺寸、圆角或路径、填充、描边、透明度、状态、消费者及层级，展开为真实元素和样式，不留未定义运行时 token。
- 组件圆角、描边、阴影方向及内边距一致；圆与五角星通常等宽高，比例敏感图形保留建议宽高。背景在低层、信息及交互提示在高层，提高层级不能掩盖碰撞。

### 配色采用角色

- 不把参考图面积自动映射为上色比例。仅当发布资源包含可用派生规则时：`preserve` 保留原明度、色度的相对色相关系，`exact` 固定主色锚点；普通正文、承载面文字、强调块文字派生对比目标为 **4.5:1**，强调边界为 **3:1**。
- 原 CSS 色板不改，消费角色与真实背景、文字、强调对象在最终 HTML 绑定。缺角色配置不伪造映射，不声称具备旧库 85 套显式角色；对比数值达标不等于审美通过。

## 5. 输出形式

- **唯一 Brief**：查询词、真实 ID、确切文件／变体、源版本、读取 SHA-256、采用范围、内容映射及必要调整。未采用只记任务相关冲突，不罗列全部落选候选。
- **最终 HTML**：承接实现参数、消费者、实际几何及 token 展开，不另建任务 JSON、参数副本、容器规划或几何合同。
- **既有验收记录**：能力、执行状态、真实展示、当前版本批准、准出、禁止自主 AI 质量重生、初检及最多两轮确定性修复、交付统一执行 [quality.md](quality.md)，不新增模板循环。查询、存储、展示、渲染和回读以实际部署及返回为准，候选包不代表部署或生产验证通过。
