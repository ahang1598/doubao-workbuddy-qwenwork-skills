# AI + Coding 步骤

> 先按主 SKILL 判断交付环境。system 明示 `Device platfrom: Mobile` 时遵循 [Mobile 直接交付](../mobile-app-direct-delivery.md)：Brief／素材记录留在本地，跳过本文全部 Workspace、Canvas CLI、Item 与卡片步骤，媒体逐项直接交付、HTML 预览走 CDN＋Markdown。其他环境执行本文默认 Canvas 分支。生产与编辑顺序不变。

共同创意和构图之后，按需落实 `references/style/coding/concept-production.md` 与 `references/style/coding/composition-layout.md`；凡有文字／容器布局或间距变化，后者必读。公共视觉原则不能代替本路线的生产映射和几何验收。

本工作流只适用于图像工具作为中间素材生产器、最终由完整 HTML/CSS 文档形成准确分层版式的任务。HTML 是唯一可编辑作品源；复杂自由路径可以内嵌 SVG，禁止 JSX 和自定义 Canvas HTML 协议。完整 HTML 按固定画布协议预览、上传并创建为顶层 HTML Item，原始 `.html` 不通过 `present_files` 直接交付。调用图像工具或写入 HTML Item 前，先按 `references/cli/README.md` 完成对话级 Workspace 路由：对话已有唯一有效 ID 时直接绑定；没有时直接调用 `+workspace-create`，绑定响应中的原始 ID，并由主 Agent 调用 `present_files(<workspace_id>)` 交付新建画布卡片；不先调用 `+get-workspace`，也不创建 ID 中间文件。画布卡片交付成功前不得生成资产或创建任何 Item；`+create` 只创建平台对象，不承担创建 Canvas Workspace 的语义。纯生图最终图读取 `references/workflow/creation/pure-image.md`，不得混用。

通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图已有合适底图且无需新图时，核验真实来源、质量与最终可见消费者后直接复用，不强制新生成／编辑记录；其余新建 AI Coding 仍核对必要的图像生产。公告类及其他图像工具结果即使文字错误或效果不佳，也须先完成媒体交付，记录问题并等待用户明确提出修改要求，不得自主重生或连续改 Prompt；未准出素材暂停进入 HTML，原生 DOM 文字仍正常修正。

## 纯生图误路由提示

先核对主 `SKILL.md` 已确定的父路线并保持至任务完成。已选 pure-image 的单一 Logo、独立角色／表情／动作图片、普通海报、单张社媒封面及主表明确准入的纯图系统进入 `references/workflow/creation/pure-image.md`，不读取本文及 Coding Spec／Visual；不能因母版由图像工具生成就把系统改判为纯图。“生成一张”、导出 PNG 或要求调用生图工具不改变路线。通知／邀请函、详情页、连续长图和 IP 系统默认 ai-coding，其纯图例外由主表决定；三折页、菜单、简历、Logo 系统与 VI 保持原路线。VI／IP 系统按实际范围使用 Logo、角色或两者的母版，不要求独立 IP 补 Logo。既有 HTML 源编辑继续保留完整 HTML。

社媒套图默认 pure-image，读取现有纯图平台 Ref 与 pure-image-sequence；用户要求可编辑设计或文字时才进入本路线，封面与内页均以图片素材＋HTML 原生文字组装。仅指定局部可编辑时，该区域必须原生排字，封面不例外；非目标区域沿既有艺术标题准入规则，真实照片内的标签不必重画。

## 参考输入分流

已经进入本轨后，先区分图片是身份／事实输入，还是需要继承的设计参考。有“参考排版／结构和风格”“做同款换产品文案”“严格复刻”，或明确指定字体、配色、肌理、卡片、渐变、弥散或蒙版等继承维度时，必须在视觉选型、字体选择和 KV 生成前读取 [参考图解析与继承](../../style/coding/ai-coding/reference-analysis.md)。实际查看原图，过滤水印、截图 UI、平台按钮、黑边、账号名和 AI 角标，再把 11 维视觉底稿、适用时的逐块图文绑定、七类同源机制和六步目标重建写入当前同一份自然语言 Brief。Brief 不新建 `reference_analysis` JSON、参数表或平行机器合同。仅用于产品外观、人物身份或内容证据的图片，执行原身份／事实流程，不触发设计参考解析。

- “参考结构和风格／做同款，只换产品和文案”默认保留布局、构图、图文关系、文字层数和成像机制，再按新主题重建；明确要求严格复刻或位置不动时，只锁定用户授权的对应几何。
- 仅借鉴某项调性时只分析指定维度；不把配色、纸感参考自动升级成全版式复刻。
- 图 1 提供产品、图 2 提供长图结构时分别绑定职责；多图按维度确定来源，截图内多张缩略图须先辨认目标，不能把预览拼图当完整原稿或猜测不可读细节。
- 明确沿用模板、替换模板内容时，同时读取 [模板编辑](../template-rewrite.md)，由 `template_contract` 决定修改权限与源文件保护；参考解析只把获准继承维度转成视觉目标。仅借鉴另一张设计制作新图仍属于创建，其授权来源是当前创建请求，不因上传参考而改判编辑。

解析方法、证据精度、继承边界和原图对照标准只在该 Ref 维护。此处是执行入口，不新增确认轮次、生产协议或参考专属参数文件；未限定的视觉维度继续按品类规划。

## 流程总览

严格沿主 `SKILL.md` 的“HTML 路线唯一生产顺序”执行：获取需求与按需文字澄清 → 创建唯一 Brief → 依次读取品类 Spec、参考解析（命中时）与 Visual System 来完成候选 Brief → 适用品类执行 KV 视觉澄清并冻结最终 Brief → 建立轻量素材清单 → 按清单生产正式图片并回填 → 完整 HTML → 预览、上传、顶层 HTML Item 回读与最终验证。除 KV 视觉澄清外，不得先生成图片再补 Brief／槽位，也不得边写 HTML 边继续决定内容结构或视觉方向。

本路径中，电商详情页、社媒长图的新建与整体重做由品类和操作类型强制触发 **KV 视觉澄清**，执行 [`visual-kv-clarification.md`](../visual-kv-clarification.md)，不以 Agent 判断方向是否存在分歧为条件。KV 位于完整候选 Brief 之后、最终 Brief 冻结与正式素材清单之前，用于把已经建立的视觉方向具象化并取得用户确认，不能用于倒推品类 Visual System 或补造内容。方向已锁定时生成 1 个 KV，仍须展示并等待用户明确批准当前版本；“直接开始”“其他你决定”、普通参考图和已有素材只能减少前置文字询问，不能批准尚未展示的 KV。续做时先核验确认依据与当前版本、范围相匹配；依据有效后继续，否则回展或更新 KV 并等待确认。生产每个候选时读取 [素材 Prompt 指南的 KV 章节](../../style/coding/ai-coding/asset-prompt-guide.md#kv-visual-generation)，确定主体、图文关系、场景和准确 Prompt。可编辑套图不另生候选 KV，但必须执行自己的真实封面确认门禁：先规划整套内容，只完成并展示分层封面；当前版本获得用户明确确认后，才提取系列机制并生产内页。默认纯图套图执行 pure-image workflow 与 pure-image-sequence。纯生图、纯 Coding、其他 AI + Coding 品类和局部小改不进入 KV。

KV Prompt 中所有待渲染文字必须逐条用中文双引号 `“”` 包裹，排版说明放在引号外；具体源文案、界定符与提交前检查遵循 [KV 文字引用规则](../../style/coding/ai-coding/asset-prompt-guide.md#待渲染文字的中文双引号)。

上述 KV 记录对社媒长图只保留真实参考、版本、确认与素材复用信息，不生成平行机器路线。用户选择、修改或混合意见必须写回同一自然语言 Brief，删除未采用的候选歧义并冻结最终版本；随后才建立正式素材清单。套图不执行本 KV 段落，但“不执行 KV”不等于可以跳过 `social-carousel-spec.md` 的封面展示确认。

阶段 4–8 必须回读同版本、与当前获准生产范围匹配的 Brief；素材生产阶段同时回读同阶段素材清单。套图一期的“当前范围”只有封面，二期才包括内页；不得因全套内容已规划而提前把内页资产加入清单或生产批次。摘要查询只用于候选判断；采用组合结构时，须在冻结后、编写 HTML 前实际读取 `follow_ups` 指定变体的 HTML 模板、布局、皮肤及必要依赖，不能只读组合 dependencies；组合验证以选定的主次尺度、图文组织、节奏与背景关系是否成立为准；参考商品、素材对象与章节名称不是必填内容。替换内容或按内容删改槽位后重新校准关系，不因缺少示例章节降为局部复用；仅保留零散原子能力时不声称采用完整组合。Brief 用自然语言描述关系，短采用记录保存真实 ID、源版本、范围和内容映射；实现不必照搬类名，但须兑现选定结构。参考任务继承已锁定的原图依据，KV 和推荐配方不能擅自覆盖。冻结后保留当前阶段已确认的图文与关系；因素材等原因必须改变时，先在同一 Brief 明确原关系、变更及原因，遵守原确认要求，不默默弱化。原图观察、目标适配和实际结果分别记录；改画幅或换文案只调整必要区域。资产复用关系与消费者写入素材清单；`--require-ready` 仅是技术校验，资产准出与视觉验证仍须由 Agent 对照实际素材、DOM 与渲染检查。

社媒长图按[一体化 Hero 与第 2 屏衔接](../../style/coding/scenarios/social-long-image-spec.md#一体化-hero-与第-2-屏衔接)生成含主标题的完整首屏图片，小字按实际阅读与可编辑需求分配；其余章节继续分层。这是素材生产单元的差异，不改变整张长图的 AI + Coding 路线。

可编辑社媒套图执行“同一中文 Brief 规划完整页链、文案、编辑范围与容量 → 只锁定封面制作依据并准备封面资产 → HTML 分层组装、真实渲染并向用户展示封面 → 停止等待当前版本的明确确认 → 从确认封面提取自然语言 `series_contract` → 增补内页素材清单 → 分别组装多个独立内页 → 逐页与全套检查”。本分支读取 Coding 套图 Spec、Social Visual 与本路线素材规范，不读取 pure-image workflow 或其平台／模型 Ref。`series_contract` 只记录真实可见的构图力场、字体角色、色彩职责、边缘、材质与图像处理机制，不建立系列机器合同、角色矩阵、品类 JSON 或 CSS 参数副本；内页不得复制封面坐标和对象数量。明确要求可编辑的区域必须使用原生文字，封面不得以整图绕过；非目标区域沿既有艺术标题准入规则，真实照片内标签可保留。已有 HTML 源编辑保持完整 HTML，不按新建默认路线压平。

AI + Coding 按以下阶段执行。每个阶段都有明确准出条件；未通过时返回对应阶段修正，不得直接跳到下一阶段：

本工作流必须显式标注产物来源：`Agent生成` 指由 Agent 根据 Ref、用户输入和已确认参数编写或推导；`脚本生成` 指由仓库内脚本输出；`用户提供/真实资产` 指原始输入或已核验资产；`混合生成` 指 Agent/Coding 与脚本或真实资产共同形成。未标来源的产物不得进入交付清单。

| 阶段 | 主要动作 | 阶段产物 | 准出条件 |
|---|---|---|---|
| 1. 需求、按需澄清与 Brief 建档 | 判断唯一品类和轨道，只澄清阻塞项；立即定位或创建唯一 Brief，先写主题、商品／核心对象、受众、事实来源、参考用途、画幅和交付边界 | **Agent 生成**的 Brief 初稿、路由结论、真实资产锚点 | 主题与商品／核心对象明确；阻塞事实未被猜测；尚未调用图像工具、检索模板或编写 HTML |
| 2. 品类 Ref → 完整候选 Brief | 先由 Spec 补内容结构、页面／章节职责、准确文案与硬约束；命中参考时补 11 维底稿、逐块图文绑定、七类机制和六步重建；再由 Visual 补风格、构图、逐图职责与 Prompt 意图、图文组合、字体角色和效果要求 | **Agent 生成**的完整候选 Brief；无需 KV 时即为最终 Brief | 完整表达用户目标、全部可见文案、每张图片及其文字绑定、可编辑文字范围与人类可读验收；需要 KV 时仅保留 1–2 个明确定义的候选方向，除短采用记录的来源 ID、版本、范围和映射外，不含坐标、色值表、CSS 参数副本 |
| 3. 适用品类的 KV 展示确认与最终 Brief 冻结 | 电商详情页、社媒长图的新建与整体重做根据候选 Brief 生成并展示 1–2 个真实 KV；方向已锁定时生成 1 个，仍须展示并等待用户明确批准当前版本。用户确认、修改或混合后，把唯一采用方向写回同一 Brief；KV 发生变化时重新展示并等待当前版本获批。其他品类直接冻结阶段 2 的 Brief | KV、确认记录、**Agent 生成**的最终自然语言 Brief | KV 已完成媒体门禁；当前 KV 版本已取得可核验的用户明确批准，或已按 KV 专项规范登记等价的既有确认设计，且确认依据与当前版本、范围相匹配，否则不得进入阶段 4；最终 Brief 不再含方向歧义，完整表达全部文字、图片职责、图文关系、字体角色、视觉效果与验收；除 KV 外尚未生成正式图片 |
| 4. 轻量素材清单 | 只登记当前获准生产范围内正式图片的用途、方法、参考输入、身份来源、Prompt、比例、尺寸、安全区、消费者、后处理和准出标准；执行 `validate_asset_manifest.py` | **Agent 生成**的 `asset-manifest.json` | 当前阶段全部正式图像调用参数可执行；不包含 DOM 坐标、字号、颜色、CSS 参数或页面几何 |
| 5. 正式图片生产、准出与清单回填 | 只按素材清单生产摄影、插画、复杂材质、背景、透明主体和准入艺术标题；普通可编辑文字、规则卡片和简单图形不调用生图模型 | **用户提供／真实资产**与**Agent 生成**的准入素材、更新后的素材清单 | 每项媒体结果完成双通道闭环；真实 URI、尺寸、Alpha 和版本已回填；`--require-ready` 通过 |
| 6. Brief＋就绪素材 → 完整 HTML | 读取 [HTML 组装](../html-assembly.md)，把准确文案、真实资产、字体、CSS/SVG 和图文关系直接落实为一个完整 HTML5 文档 | **Agent/Coding 生成**的版本化完整 `.html` | Coding 文字均为真实 DOM；模板效果已展开为行内样式／内嵌 SVG；固定画布锁定；不存在占位资产、HTML Frame、片段、外部 CSS 或整页压平 |
| 7. 预览与交付 | 按 HTML 检查调用 shot.py；同尺寸完整预览图上传 CDN、核验公网链接并以 Markdown 图片展示（截图不调用 present_files、不创建 IMAGE Item）。默认 Canvas 再上传 HTML、create／get 并将同一 Workspace ID 与刚回读的 HTML Item ID 拼成 `<workspace_id>?item_id=<item_id>` 单值交给 `present_files` 输出对应画布卡片；Mobile 到预览展示即止 | 真实预览及交付结果；默认 Canvas 另保存上传短链和回读 | 截图完整、像素一致；当前环境所有必要交付均成功，未验证项如实记录 |
| 8. 视觉验证与媒体出口 | 对照自然语言 Brief、素材清单、参考底稿和真实渲染检查内容、设计目标、模板效果、字体、逐块图文组合与参考继承；连续长页检查实际 DOM 区段 | 验证记录、最终说明；按需产生图片／视频成品 | 技术与视觉结论分开；不能用清单齐全或模板命中代替画面成立；原始 `.html` 不通过 `present_files` 直接交付 |

阶段 1–3 完成并冻结唯一 Brief；可编辑套图的“冻结”按阶段解释：一期只冻结完整内容计划和封面制作依据，内页视觉及最终系列机制保持待定，封面确认后才原位补齐。阶段 4 只建立 [轻量素材清单](../../../example/asset-manifest.md)，不复制文字、字体、模板或几何；套图一期只登记封面实际需要的图片，二期再增补内页。阶段 5 回填真实素材；阶段 6 才把实现参数直接写入 HTML。素材清单由 Agent 维护，不要求用户提供文件。

正式图片调用前执行 `python3 scripts/runtime/validate_asset_manifest.py <asset-manifest.json>`，编写 HTML 前再加 `--require-ready`。连续长图正式验收使用 shot／shot.py；需要定位时读取同次 shot.py 的 measurement 和 issues；这些脚本不参数化自然语言 Brief。

电商详情页按以下依赖链执行：阶段 1 接收需求并锁定真实商品事实；阶段 2 由品类 Spec 选择责任链并按事实删除、合并或拆分，形成段落与屏幕责任，复核连续信息负荷后确认是否需要独立透气段，再由 Visual System 规划图片职责、背景组和屏间关系；阶段 3 用 KV 澄清视觉方向并冻结最终 Brief；阶段 4 建立正式素材清单，阶段 5 才按最终比例和用途生成并准出完整背景、同宽覆盖图、独立主体和其余配图；阶段 6 由 HTML 试排并确定最终几何。

阶段 7–8 对完整 HTML 文档仅运行 `python3 <SKILL_DIR>/scripts/runtime/shot.py <html_path>`，按 [HTML 预览](../html-preview.md) 读取同次报告与完整截图，不拆成局部 HTML 或平台 Item，不另行调用浏览器测高或截图。自然高度测量已集成在脚本内，细则见 [DOM 测高](../html-dom-measurement.md)。未锁高时按 `measurement.natural.height` 与实际内容核对，仅在必要时回填声明高度及 html／body／作品根三处高度，再运行同一脚本；锁高越界时保持尺寸并重排，不以截图高度反推自然高度。连续长图结合源码、报告和完整截图核对 `data-section-id` 内容区段：内容连续覆盖至独立页尾安全区起点，安全区延续至画布底部，不用空区段凑高，也不要求内容吞并安全区。退出码与交付遵循现有预览规则；失败只返回 Brief、素材清单、资产或 HTML 的最小责任步骤。

### 核心资产先行

阶段 1 区分“沿用已有身份”和“获准新建 Logo／IP”，在同一 Brief 记录来源、修改范围与依赖关系；各身份分别维护母版，不把多个角色合成一个身份。

- **已有身份**：阶段 2 前按 [画布资产语义目录工作流](../canvas-asset-organization.md) 回读并确认商品、Logo 或角色母版，登记 `core_asset_id` 与身份不变量。缺少来源只阻断依赖它的生产，不以文字重生相似对象。
- **从零新建**：先完成 Brief 的设计意图与系统范围；阶段 4 只登记输入已齐全的母版及独立素材，阶段 5 生成正式母版并完成交付、身份检查与确认，再登记锚点、回填原 Brief，并补齐原素材清单中的衍生任务。尚未取得真实参考的任务留在 Brief 的依赖计划中，不伪填 `planned` 输入。母版确认不是额外候选 KV。
- **同源延展**：确认后的母版写入 `/core-assets/<语义名>/master`，有效确认记录直接复用；衍生图以该母版调用 `image_edit`，直接摆放沿用已核验素材。每批只生产依赖已就绪的任务，最终展示 HTML 等全部所需素材就绪后组装。

阶段 3 的 KV 与阶段 5 的每次正式图片生成／编辑都必须执行 [交付门禁](../image-generation-delivery-gate.md)。每个结果同步启动持久化／回读与工具产物直接独立 `present_files` 两个分支；串行任务在当前结果汇合前不得调用下一次生成／编辑，并行任务可同时执行预先锁定的独立批次并在 join barrier 等待整批。KV 结果完成闭环后才能让用户选择；正式结果完成闭环并回填素材清单后，才能比较、修复或继续 HTML 组装。

### 主视觉确认后的正式生产门禁

主视觉确认后，正式生产返回的每个媒体结果——包括背景、主体、抠图源、艺术标题、候选和中间素材——都必须立即完成写入／回读与直接交付双通道闭环。串行结果闭环前不得生产下一项，并行批次全部闭环前不得开始下一批；全部正式媒体均闭环且素材清单回填后，才可进入阶段 6 的 HTML 组装。禁止先积攒素材再集中补写、补交付，或先组装 HTML 再补媒体记录。

可编辑套图的封面用户确认与媒体技术准出是两道独立门禁：一期封面资产完成双通道闭环后即可组装、渲染并展示封面，不等待整套素材；展示后必须停止。只有确认记录与当前封面版本匹配，才允许把内页专属资产加入下一批。工具成功、媒体交付、预览或 QA 都不能代替用户确认；封面版本变化或确认依据不可核验时，重新展示并取得确认。

Brief 必须明确区分最终可见文案、规划说明和 QA 元数据。只有最终可见文案可进入真实文本 DOM 或明确准入的图片文案；“主体居于画面右侧”“标题区位于左上”等规划句不能出现在成品可见层。阶段 6 生成 HTML 前逐字比对 Brief 的可见文案，发现规划文字进入 DOM 时直接修正 HTML。

每个品类 Ref 要求的内容写入同一 Brief，不能只写“已阅读”。Spec 确定内容，Visual 原位追加视觉。社媒长图与套图使用中文叙事、信息链、逐屏／页职责、文案、配图及自然语言视觉效果；不输出机器 Brief、独立套图合同或矩阵，不调用旧社媒 JSON 计划验证器，也不将取消字段移入 HTML。可编辑套图在封面确认后必须把可观察系列机制写入同一 Brief 的 `series_contract` 段落；这不恢复机器字段。实际色值、几何与资产绑定在实现时记录。

用户明确提出白描、波普、新艺术、印象派、3D 等风格词时，在品类 Ref 之后读取 `references/style/shared/explicit-style-terms.md`，且只使用当前品类“显性风格词适配”已列出的词。Brief 用自然语言记录标准风格名称、用户原词及品类化可见特征，不要求 `style_fingerprint` 机器字段；未列出的词不加入候选，也不输出“不建议”清单。用户没有显性风格诉求时，不为凑字段强制选择 ST。

三折页、简历、Logo、VI、菜单、关系图、个人卡片的 Visual 使用开放式风格候选，上述封闭编号适配不用于这些品类；保留用户明确风格，落实到可见特征与用途。三折页、简历、VI、菜单、关系图和个人卡片的普通素材 Prompt 只描述画面，文案与艺术标题由 Coding 完成，既有母版自身的字标不受影响。Logo 主标和组合标按 Logo Visual 由生图／图片编辑工具生成，Prompt 逐字写明品牌名与字形；单色、反白等状态以确认主标为参考编辑。其余品类继续按各自约定。

用户明确要求全部文字独立可编辑时，主标题也使用真实文本 DOM，不生成艺术标题位图；只指定部分字段可编辑时保护这些字段，其余标题沿原准入规则。

## 读取路由

先执行主 `SKILL.md` 的设计 Brief 前置门禁，按需读取澄清策略并把结果回写同一 Brief，再选择唯一品类 Ref，确定内容责任与物理边界；若进入品类 Ref 时 Brief 缺失，立即按当前上下文创建并填写后再继续。命中参考输入分流时先完成原图解析，再确定创意、构图和具体视觉选型。下表是品类基础依赖顺序，参考解析是其视觉决策前的条件步骤，不得因表中未重复列出而跳过。

表中的“字体闭环”不是新产物，而是所有正式 HTML 共用的连续步骤：从 [字体推荐入口](../../rendering/font-recommendation-list.md) 按语种、角色、形态和气质形成候选，结合目标文案试排完成视觉判断；精选清单不是封闭白名单，`scripts/runtime/select_fonts.py` 只提供候选、缺口和诊断。视觉候选确定后进入 [字体资源与执行契约](../../rendering/font-family-library.md)，由 Resolver 核验实际 family、face、weight／style、许可、目标文案字形覆盖和 Web 加载；通过后才把字体、字重和回退栈写入最终 HTML 的真实文本 DOM，最后用 `shot.py` 验收字体实际加载后的字形、换行、基线、伪粗体和裁切。用户锁定精确字体时，任一资源门禁失败都必须停止定稿并请求确认，不得静默替换或把普通文字栅格化绕过。

## 全流程交付契约（阶段 8 输出定义）

本节先定义最终交付边界，便于规划阶段建立交付约束；它不是执行顺序。实际执行仍按流程总览中的阶段 1–8 进行，阶段 5 的正式资产生产细则见下方。

| 思维导图／概念关联图 | Workspace 内以完整 HTML Item 保存可编辑节点、关系和视图；按需导出总览与局部图 | 内容来源、关系依据、连线、层级、拥挤度和阅读检查 |
| 流程图 | Workspace 内以完整 HTML Item 保存可编辑节点、条件、泳道和路径；按需导出总览与子流程图 | 起止点、分支覆盖、合流、循环出口、异常路径、责任归属和可读性检查 |
| 知识图谱 | Workspace 内以完整 HTML Item 保存可编辑实体、类型、关系和视图；按需导出总览与局部图 | 实体消歧、关系方向、来源、时间、冲突状态、筛选范围和密度检查 |
| 个人名片／会员及权益卡 | 正反面或状态按独立作品边界建立 HTML Item；按需交付印刷与数字预览 | 身份／权益事实、正反面职责、系列变量、二维码／入口和实际尺寸检查 |
| 未命中具体场景 | 用户要求的可编辑源和实际渲染图 | 通用交付验证记录、Brief、素材清单和完整 HTML |

过程文件默认保存在 `.creative-design/<task-id>/`，包括 Brief、素材清单、Prompt、版本化 HTML 和验证记录；最终交付清单只包含用户要求的渲染／导出成品与必要验收证据，可编辑源位于已写入并回读核对的 Workspace。图片工具生成的失败草稿仍按最高优先级门禁逐张同步执行 CLI 写入／回读与工具产物直接 `present_files`，但必须标记为未通过且不得混入最终可选清单；HTML 和无关调试文件不得交付。

交付来源必须在交付说明中再次写明：Brief、最终 HTML、资产计划、Prompt 和内部 HTML 载荷属于 **Agent/Coding 生成**；用户原图、产品图、人物图和其他核验素材属于 **用户提供/真实资产**；字体精选候选属于 **脚本生成**，正式字体可用性属于 **平台验证**；最终交付包属于 **混合生成**。不得把 Agent 推导的内容或示意资产描述成用户原始事实。

## 全流程公共出口（阶段 6–8 执行规则）

本节定义协议、渲染和验证阶段的公共出口；它不是对阶段 5 的替代，阶段 5 必须先完成正式资产准出。

生产前先按当前品类 Spec 确定生产单元和文字编辑边界，再选择图片或 Coding；默认 AI + Coding 不表示任何区域都应拆层。正式电商详情页首屏默认采用无字主图＋独立 HTML 原生标题与文案（商品与环境共同构图，保留原包装文字与 Logo），主图不新增上屏文字并保留原包装文字与 Logo；按 Brief 明确选择一体生成且符合文字编辑边界时，才将商品、环境、主标题及必要短辅助文字共同成图，价格、日期、条件、参数和正文仍使用原生文字。社媒长图 Hero 默认生成包含背景、主体、主标题及适合入图小字的完整图片，各自具体范围与用户明确编辑要求均按对应 Spec 执行。用户明确要求独立编辑的文字必须保留原生实现，不得烘焙后冒称可编辑。只有品类允许分层的区域，AI 才通常负责环境、复杂视觉资产或无文字壳体，准确文字、数字、日期、价格和 CTA 保持独立文本 DOM；商品、人物、证书、评论、数据和平台界面不伪造。Logo 品类：AI 可生成含已确认品牌文字的位图母版，但必须逐字核验，并在 Brief 中保留准确源文字。

生成 HTML 作品时，完成 Brief 和素材准备后读取 `references/workflow/html-assembly.md`、`references/html/coding-rendering.md` 与 `references/cli/README.md`，严格执行“生成完整固定画布 HTML → `shot.py` → 同尺寸完整预览图上传 CDN、核验公网链接并以 Markdown 图片展示（截图不调用 present_files、不创建 IMAGE Item） → `FileBatchUpload` → 创建一个顶层 HTML Item → 保存返回 ID → `+get` 回读核对 → 将同一 Workspace ID 与刚回读的 HTML Item ID 拼成 `<workspace_id>?item_id=<item_id>` 单值交给 `present_files` 输出对应画布卡片”。禁止 HTML Frame、Frame 成员 HTML、代码片段或直接 `present_files` 交付原始 `.html`。若用户另需图片／视频，再从同源 HTML 渲染／导出，并对每个媒体成品执行既有双通道门禁。创建、大幅改写或整页重写后读取 `references/workflow/html-validation.md` 与 `references/workflow/validation.md`；失败时按 `references/workflow/troubleshooting.md` 回到最小失败单元修正。

生产前先建立信息结构、页面／模块责任、阅读顺序和视觉焦点，不得用线框、情绪板或无关装饰替代真实构图。创作型任务至少 70% 画面遵循同一视觉家族，最多使用一种次级母题；只有本文件开头列明的电商详情页与社媒长图执行 KV 门禁。可编辑套图不执行 KV，但按套图 Spec 先只生产、组装和展示封面，确认后才进入内页；其他任务不得仅因成本高触发 KV。

根据可编辑性和视觉职责选择载体：位图用于生成式 Logo 母版、摄影、插画、纹理、复杂拼贴和强视觉壳体；普通文字、图标、按钮、表格、标签和规则图形优先使用 HTML DOM、行内 CSS 或内嵌 SVG。需要叠压的独立 AI 素材按“高反差纯色底生成 → 真实抠图 → Alpha 检查 → 透明 PNG 排版”执行；文字按生产单元分配：正式电商首屏默认完整商品／环境主图与 HTML 原生标题、文案分离，仅 Brief 或用户明确选择且不与文字独立可编辑要求冲突的一体化 DIT 可将主标题及必要短辅助文字入图，价格、日期、条件、参数和正文仍使用 DOM；社媒一体化 Hero 依当前品类 Spec 决定入图文字，优先于本段普通文字使用 DOM 的通用建议；用户明确要求独立编辑的文字按对应 Spec 排除出图并原生实现。独立艺术标题只含其准确源文字；普通背景／壳体不新增需准确排版的文字、字母、数字、标识或伪界面。用户产品原有包装文字、标签和 Logo 属于身份内容，必须保留，不能被“无字素材”限制擦除；水印和无关界面不得新增。所有 AI 资产保存用途、提示词、源参考、资产槽位和替换位置。电商详情页的最终背景不得以无依据纯色 DOM 静默兜底；若规划的纹理、材质、光场或背景图未能落成实际 HTML 层，必须停止并返回资产阶段或 正式素材清单阶段。

连续长图在冻结背景图片的目标比例和安全区前，先用真实文案、选定字体和主素材比例完成整页比例草图与段高试排，并按公共构图规则在 HTML 完成后读取实际 DOM 几何。段高包含实际图文、必要内外间距及有职责的构图空间；呼吸段不按留白百分比扩高。制作顺序与具体回写要求见对应长图 Spec。最终按整图缩略图、连续相邻段和手机阅读尺度复核，素材清单通过不等于实际图文与留白通过。

## 阶段 5：AI/真实资产生产与资产准出

电商底图与视觉表达按当前 Spec／Visual 的自然语言关系执行。有内容依据的稳定网格允许保留；纯色只用于已有设计依据的区域，不因资产失败或省事退回纯色底加小图卡片。首次渲染的连续代表段落同时检查图像、字级、容器与段间节奏，不能只检查首屏 KV。

本阶段在整体规划完成后执行。正式素材前允许做非交付的文字容量、比例与占位测量，用来确定可执行目标尺寸；测量不加载未就绪素材、不提前组装正式成品、不作为交付物。目标写入原素材清单，不另建几何规划文件。可编辑套图确认前的测量只用于整套内容容量与封面，不得据此生产内页资产或组装内页。最终 HTML 测高只同步画布高度，不自动改写 Brief、素材比例或重生图片；只有实际消费区域、取景保护或有效像素不再满足准出标准时，才返回受影响素材记录与生产步骤。先按 [轻量素材清单](../../../example/asset-manifest.md) 落实当前获准生产范围内的实际素材、目标尺寸、安全区和消费区域。背景可由 CSS、图片或二者组合实现：连续长图先按连续内容组确定全局底面、组级背景与局部覆盖的职责，套图确认前只确定封面基底，确认后才逐页确定内页基底及背景是否需要独立生产；屏或页不自动成为背景边界。同一职责不得重复生产，完全被遮挡且无其他职责的底图不生成。执行 [素材指南](../../style/coding/ai-coding/asset-prompt-guide.md) 的比例、裁切、分辨率、身份和可组装性检查，未准出资产不得进入 HTML；不先做好页面再反补素材规划。

### 分图层 Coding 的 AI 视觉素材

本路径适用于已锁定的 ai-coding 任务。此处的 `image_gen/edit` 是素材生产器，生成结果按职责进入后续 HTML；可编辑社媒套图的封面与内页均执行素材准出、HTML 组装、检查和整套交付，不设置完整封面终图例外，但必须分两期：封面确认前只生产和组装封面，确认后才生产内页。品类 Ref 不得新增最终图分支、将可编辑页面压平或改变父路线；所有 AI 视觉素材均不得绕过本阶段的准出。

简历是强制例外：当简历 Ref 判定 `portrait_mode=professional-id` 且存在用户上传可识别人像时，阶段 5 必须先执行 `deterministic-id-crop` 或 `image-edit-id-photo`，生成并真实载入独立的 `portrait-id-3x4`，再允许阶段 6 引用 `used_asset_ref`。不得把 `original_asset_ref` 直接当作 `used_asset_ref`，不得把生活照直接放入标准简历，也不得以“原图可用”跳过人像准备；人像资产未通过比例、背景、身份和加载核验时，流程必须停在阶段 5。

### 提示词结构

本节提供 AI + Coding 的品类化 Prompt 补充；通用的槽位比例、主体框、安全裁切区、有效分辨率、质量描述和重生门禁以 `references/style/coding/ai-coding/asset-prompt-guide.md` 为准。两者冲突时先满足已冻结的槽位与质量门禁，再保留本节的风格和组装关系要求。

任何背景图、主体图、插画、装饰或获准艺术标题都必须先从同一自然语言 Brief 中落实当前品类的具体风格及可见特征，再写对象。社媒与电商均读取当前 Spec／Visual 写入该 Brief 的内容职责、完整风格名称、字体角色、配色职责、构图、影像和具体可见关系，不要求 V/T/C/L/I/A 或其他旧机器字段，也不恢复独立系列合同、布局枚举或资产矩阵；可编辑套图封面确认后的自然语言 `series_contract` 是同一 Brief 内的可观察机制记录，不属于机器合同。实际色值、尺寸、层级与消费绑定只在最终 HTML 中实现，图像调用参数进入轻量素材清单。

普通配图均采用对应 Visual 的风格优先写法，不写上屏文案、文字排版或“无文字／no text”等否定词，比例和尺寸只放工具参数。社媒一体化 Hero、Brief 或用户明确选择且不与独立编辑要求冲突的正式电商一体化 DIT Hero、Logo 主标／组合标和准入艺术标题是文字例外，逐项写准确文案与字形；电商该例外仅限主标题及必要短辅助文字，价格、日期、条件、参数和正文仍原生排字，默认电商主图不新增上屏文字。可编辑套图封面没有整图文字例外；明确要求可编辑的文字必须原生实现，局部编辑的非目标区域可沿既有艺术标题准入规则。已有字标及真实照片内标签可作为身份或实物内容保留，不要求重画；物理、质量与交付约束仍保留。

风格指纹至少包含：`主风格母题`、`时代或文化语汇`、`媒介类型`、`形态与轮廓语言`、`背景色/主色/辅色/强调色及比例`、`光线与对比`、`材质工艺`、`边缘与颗粒处理`、`情绪强度`、`系列连续性锚点`。每个 Prompt 只选择一种主风格，最多叠加一种次级母题；各素材继承 Brief 与素材清单指定的共享锚点，并按作用对象写入各自的媒介与表面处理；例如背景采用丝印而菜品保留摄影时，共享配色／光线关系，不把网点和漏墨扩散到菜品。

```text
风格指纹：<主风格母题；时代/文化语汇；媒介；形态语言；配色关系；光影；材质工艺；边缘/颗粒；情绪；连续性锚点>
主体：<具体主体、动作与不可改变特征>
环境：<地点、背景、道具>
媒介：<摄影 / 拼贴 / 插画 / 3D / 线稿>
构图：<从 references/style/shared/composition-principles.md 选择 1 种主构图与最多 1 种辅助构图，并写明视角、景别、主体位置、占比、裁切与阅读动线>
构图职责：<图像对象如何共轴、遮挡、穿插、破框、承托、避让或共享负空间>
装饰职责：<无则写无；有则说明装饰如何沿动线、贴边、重复锚点或连接主体与信息，而不是填空>
过渡职责：<单页可写无；长图/套图说明如何通过跨区主体、路径、材质、裁切、尺度或光场完成接力>
与相邻区域的连接：<对象、方向和可见关系>
光线：<方向、软硬、时间>
色板：<设计变量中的 2–4 种颜色>
质感：<纸张、颗粒、网点、材质>
留白：<具体位置、范围和低纹理特征>
连续性：<与系列素材统一的规则>
保护：<实际主体身份、关键轮廓、裁切保护和允许变化范围>
```

Prompt 按“具体风格 → 参考分工与主体 → 物理空间扫描 → 画面关系 → 处理与保护”合成一段自然语言；Coding 排版说明不传给图片模型。每个重要对象写清方位、占比、轮廓、颜色、材质、光线、前后关系与裁切，比例与尺寸单独传工具参数。

#### 合成关系先行

调用图片工具前，先从 [composition-principles.md](../../style/shared/composition-principles.md) 、冻结 Brief 和素材清单确定资产的构图职责、装饰职责、过渡职责及与相邻章节的连接，再决定生成完整背景还是独立素材。不能先生成一张自足的“好看背景”，再把标题、卡片和 CTA 覆盖上去。

- 背景必须为准确文字或独立主体提供可观察的轴线、负空间、框架、路径、遮挡入口或空间基准；只预留一块空地不算构图关系。
- 独立主体必须与至少一个准确元素形成共轴、遮挡、穿插、承托、避让或路径关系；装饰必须连接阅读动线、边缘或重复锚点，不作为随机填充。
- 长图和套图的关键资产必须说明与相邻章节的连接：谁跨区、哪条路径延续、何处裁切接力，或光场、尺度和材质如何换挡。
- 合成预览中若背景、主体、标题和信息场可以分别替换而不影响其他元素的几何依据，说明它们仍是机械叠放；返回 Brief、素材清单或 HTML 重建关系。

### 后处理职责与选择

后处理不是生图失败后的补救，而是阶段 4 必须规划、阶段 5 必须执行并回填的资产职责：

| 动作 | 适用情况 | 必须记录 | 不得用于 |
|---|---|---|---|
| `cutout` 抠图 | 主体需要跨区、破框、叠压、复用或独立替换 | 源图、纯色底、Alpha 成品、边缘检查和替换入口 | 把带环境底的矩形图伪装成透明素材 |
| `crop` 剪切/裁切 | 改变镜头、景别、目标画幅、焦点或跨页/跨段回声 | 裁切框、焦点、保留的身份/事实区域和版本 | 裁掉产品关键结构、人物关键部位、Logo、二维码或证据条件 |
| `mask` 蒙板 | 前后景、局部显隐、穿插、破框、异形容器、文字避让或材质显露 | 素材阶段记录蒙板对象、范围、形状和可编辑／降级方式；具体层级在 HTML 中确定 | 覆盖错字、伪造事实、隐藏溢出或替代真实抠图 |
| `transition` 过渡 | 长图段落、套图页面、三折页面板或信息状态之间需要接力 | 起点、终点、承接对象、变化方式并由 HTML 落实实际关系 | 只写“自然过渡”，或只用相近颜色制造假连续 |
| `gradient` 渐变 | 光场、材质、透明度、密度、空间深度或对比控制 | 渐变承担的对象、方向、颜色/透明度范围和载体 | 随机背景装饰、遮盖低对比、填补空洞或替代构图关系 |

简单渐变、蒙版、裁切和规则路径优先由标准 CSS／内嵌 SVG 实现；复杂材质渐变、手绘蒙版、真实光场或不可稳定表达的壳体才由图片资产／预处理承担。图片生产信息进入素材清单；DOM、层级和组装关系在完整 HTML 中实现并由真实渲染验证。

### HTML 组装与表面决策

进入阶段 6 后，在编写完整 HTML 时对每个“容器 + 文字组”和“图像 + 卡片／背景”组合执行 [Coding 布局](../../style/coding/composition-layout.md) 的内容框与融合规则。布局参数直接写入 HTML，不先建立参数计划：

- 在真实 DOM 容器上设置宽高、padding、gap、对齐和溢出策略；使用真实文字和字体渲染后测量文字组，再调整容器高度。
- 按 `references/style/coding/composition-layout.md` 的“AI + Coding：多层间距与防贴边”确定正文基准 B、页面安全区、父子容器留白、卡间距、完整标题组到卡片及章节间距，并直接落实为 DOM 结构与行内样式。固定尺寸下通过重排解决空间不足，不擅自改用户比例、删文案或缩小文字硬塞。
- 新生成的矩形摄影、背景、纹理面、场景窗和壳体分两段检查：源图到就绪文件核对裁切、等比缩放、保护区与有效像素，禁止非等比拉伸；就绪文件到每个显示实例核对实际缩放与取景。仅要求完整同框显示的实例，DOM 框与就绪素材的比例误差不得超过 1%。合法 `cover`／`contain` 不因框与素材比例不同判为拉伸，而按等比缩放、实际裁切或留边、主体与事实保护区及裁切后有效像素验收；插值放大不增加有效像素。
- 为每个图像边界回答“边界应明确还是应融合”。明确边界时按层级选择细描边、内高光或低层阴影；融合边界时选择局部渐变覆盖、共享底色或预处理边缘。不得同时默认开启全部效果。
- 蒙版只服务穿插、破框、局部显隐或异形裁切；规则裁切／渐隐可按 CSS 库用行内 `clip-path`、`mask-image` 和 `-webkit-mask-image` 实现，复杂主体分割或浏览器无法稳定复现的蒙版必须在组装前形成透明图片资产。
- 简单背景需要增加质感时，从 `references/style/coding/composition-layout.md` 的 Coding 纹理清单选择一种主纹理；元素数量、透明度、密度区和文字禁入区直接落实到 HTML。真实纸纹、纤维、噪点、织物和折射仍使用图片。

完整 HTML 首次渲染后，读取真实 DOM 测量并检查文字墨迹与容器四边的距离、标题／正文组间距、共享轴线、图片非透明边界、接缝和效果强度。出现顶边拥挤、文字被压缩、图像拉伸或矩形贴片感时，直接修正 HTML；只有内容决策或图片职责错误才返回 Brief／素材阶段。

在实际渲染图中逐层执行上述防贴边验收，特别检查首尾子卡片到父容器的左右距离、末行单位／注释到卡片底边、最下方卡片到父容器底边，以及完整标题组与下方卡片的净距。对照计划中的实际间距，未通过则更新受影响布局并重新渲染；不以 HTML 无溢出或文本框未越界替代视觉验收。几何修正沿用现有素材及既定视觉路线，工具写入和交付时序仍按原门禁执行。

### 社媒套图专属分支

主 Ref 为可编辑社媒套图时，封面与内页均按正常图片素材＋HTML 原生文字分工，沿同一中文 Brief 制作。先规划完整页链与容量，但一期只把封面实际需要的图片放入共享清单，分层组装、渲染并向用户展示真实封面后停止。只有当前封面获得明确确认，才从真实结果提取可观察的 `series_contract`、增补内页素材并继续多个独立页面。确认前禁止内页专属图片调用、编辑、后处理、HTML 组装、渲染和交付；技术 QA 与媒体闭环不构成确认。不建立系列机器字段，也不机械复制封面坐标、对象数量和容器。用户要求可编辑的区域必须为原生文字，封面不例外；非目标区域可沿既有艺术标题准入规则。默认纯图套图不进入本分支。

### 背景图改写策略

先按最终用途选择生产单元，并在同一自然语言 Brief 中说明职责；轻量素材清单只记录实际需要生成、编辑或复用的图片，不增加生产分类字段：

- **完整单图**：共同依赖光影、透视、材质或图形构图的主体与环境联合生产，不因实现方便拆成纯底加孤立贴图。是否包含文字由品类路由决定：正式电商详情页首屏默认完整商品／环境主图不新增上屏文字，标题与文案独立 HTML 原生实现，原包装文字与 Logo 保留；按 Brief 明确选择一体生成且符合文字编辑边界时，主标题及必要短辅助文字才共同入图，价格、日期、条件、参数和正文仍原生排字。社媒长图 Hero 默认一体图；明确文字独立编辑时按各自 Spec 预留原生文字区域，不扩大或缩减用户编辑范围。
- **独立素材＋布局**：产品外观、质地、结构或其他证据需要独立取景、比较、移动或叠压时，分别准备素材并与原生信息布局组合。照片和证据图窗可保留合理矩形边界；只有确需透明叠压的素材才执行去底，不将近似底色当透明。背景与语义壳体仍分别承担底面、空间或内容媒介职责。
- **纯 Coding 信息区**：规格、参数、服务、FAQ、表格或规则图形不依赖生成式视觉证据时，可以原生文字、线条、图标与有设计依据的纯色信息底完成；不为凑素材生成背景或孤立装饰，也不因此改变整页已选路线及其他区域的生产要求。

不能把以上单元都套入“无字背景”模板，不能把独立素材示例当作默认 Hero 配方，也不能以有依据的纯色信息区为由省略已经确认的场景、纹理或视觉资产。

先从当前品类 Spec 读取背景数量、完整画布范围、章节绑定、烘焙内容和覆盖关系，再按 [素材 Prompt 指南的背景定义](../../style/coding/ai-coding/asset-prompt-guide.md#5-背景图-prompt)编译具体类型、组织方式、风格与照明。Prompt 明确视觉职责、具体媒介与色彩、分区面积与密度、文字可用区域、相邻章节衔接，以及该类型实际需要的材质／光影。平面色块不写虚构空间光；均匀纸纹不强制地平线、主光和轮廓光；实景／3D 才描述透视、光源和接触阴影。

无字背景不新增可读文案与伪标识，真实产品既有标签和 Logo 仍按身份源保留。一体化社媒 Hero 的图内文案由其 Spec 分配，不套用无字背景和独立艺术标题的拆分规则。正式电商 Hero 默认完整连贯的商品／环境主图不生成新增上屏文案，全部标题与文案由 HTML 原生文字承担；按 Brief 明确选择一体生成且符合文字编辑边界时，主标题及必要短辅助文字可按电商 Spec 随完整画面生产，不另拆独立字图。价格、日期、条件、参数和正文始终原生排字；仅指定部分文字独立可编辑不构成选择一体化模式，所选一体化模式也不得将指定可编辑文字入图。背景矩形边界应成为有意的全幅、画框或场景窗口；需要超出边界移动的主体继续沿原独立素材与抠图流程，不以近似底色伪装透明。

文字局部对比不足时按[共同构图策略](../../style/shared/composition-principles.md#文字与背景的对比处理)选择字色、位置、字重、描边、投影或局部调光；不预设黑灰色面。首屏与后续章节的色阶、材质尺度、路径或边界在生成前确定，不用事后压暗带掩盖接缝。

### 独立素材图改写策略

素材图包括需要进入排版的产品主体、人物、角色、插画、贴纸、复杂图标和装饰。Prompt 不能只描述“生成一个人物/物件”，必须说明其在整张设计中的语义角色和风格化造型：

1. **语义与构图角色**：写清素材承担主视觉、视线引导、情绪表达、信息佐证或边缘装饰中的哪一种职责，以及最终放置区域、朝向、占比、裁切和与标题、背景、前景、卡片或相邻章节的叠压关系。主视觉若与标题分区，还要说明通过哪条路径、光场、遮挡或尺度关系形成共同视觉重心。
2. **主体实例化**：描述主体身份、数量、姿态、动作、表情、视角、景别、轮廓、关键结构和禁止改变的身份特征；不得使用“相关素材”“若干装饰”等泛称。
3. **风格化造型**：沿用背景图的风格指纹，具体写明比例夸张、几何化程度、线条粗细、轮廓硬软、色块切分、笔触、表面材质、颗粒、印刷或渲染方式。素材允许比背景更集中、更高对比，但不能另起一套画风。
4. **色彩与光影匹配**：重复背景的主色、辅色和光源方向，说明素材自身强调色的使用部位；边缘光、阴影软硬、透视和色温必须能与最终背景融合。相同底色不算融合，最终合成还要依靠共享光向、透视、接触阴影、遮挡、路径或材质中的至少两项建立空间关系。
5. **可合成边界**：主体轮廓完整，四周保留安全边距，细小结构可识别。凡是用于跨区、破框、压边、穿插或覆盖文字的素材，都按 isolated element 生产：高反差均匀纯色底、无环境、无地面、无边框、无渐变、无投影，随后真实抠图并检查 Alpha；不得生成浅色渐变底后直接放入相近色页面背景。
6. **身份与系列一致性**：用户上传产品或人物作为 edit target 时逐项锁定不可变特征；系列素材统一视角体系、轮廓语言、光向、材质和颗粒，但每个素材的动作与构图职责必须不同。

独立素材模板：

```text
<具体风格及可见特征>的独立<主体类型>素材，采用<线条、色块、笔触、材质或渲染工艺>。主体朝向<方向>、约占画面<比例>，与<图像对象>形成<避让或轮廓关系>；保持<身份、数量、姿态、动作、表情、视角和关键结构>。以<主辅色及部位>组织主次，<符合材质的明暗>表现体积；单一<高反差纯色>背景，主体完整且不贴边，保留<裁切安全范围>，画面仅包含<指定对象>。
```

### 艺术标题改写策略

本节只规定分图层 Coding 中的独立艺术标题素材。一体化社媒 Hero 的标题随背景与主体生成，按社媒长图 Spec 执行，不进入本节的单独字图、纯色底与抠图步骤。正式电商 Hero 默认标题与文案使用 HTML 原生文字，不因本节艺术标题准入改生成独立字图；按 Brief 明确选择一体生成且符合文字编辑边界时，主标题及必要短辅助文字按电商 Spec 随商品／环境生成，也不进入本节。独立艺术字是进入 HTML/CSS 排版的中间图片素材；AI 原生视觉最终图中若自然包含少量标题，它仍随整张最终图一次性交付，不单独抽取、抠图或套用本节流程。

主视觉与风格明确后，先建立完整文字层级清单，再单独判断视觉优先级。标题层级不等于艺术字资格：只有**首屏／首图主标题**，或每个可独立交付图片中被明确选为唯一最高视觉优先级的**最重要大标题**进入艺术标题流程并读取 `references/style/coding/ai-coding/art-title-prompt-library.md`。同一独立图片默认最多一个艺术标题；长图、详情页等单一完整图片通常只选择首屏主标题，后续章节 H1 不再逐项生图。没有明确唯一第一标题时不生成艺术字，所有标题进入字体库流程。若存在已确认 KV，命中的艺术主标题读取 `kv_title_style_reference`；标题文字仍以当前项准确 `source_text` 为唯一事实源。生成模型必须产生真正的艺术字形，不能只是基本字体截图。

艺术标题准入必须记录 `art_title_eligible=true` 与唯一原因 `first_screen_primary | image_primary`；仅仅是 `title_level=h1` 不构成准入。艺术标题视觉重量只允许中粗、粗或特粗。未命中准入的一级标题、二级及以下标题、正文、参数、标签、图注、来源、日期、价格、型号、单位、免责声明和 CTA 必须从字体库选择真实字体，并继续使用可编辑文本 DOM。每个准入标题在调用 image 工具前完成以下生成记录：

```text
source_text: 逐字源标题
art_title_eligible: true
eligibility_reason: first_screen_primary | image_primary
deliverable_id: 所属独立图片产物；用于校验每张图默认最多一个
kv_title_style_reference: 已确认 KV 标题的版本／裁切参考图／字形参数；未触发 KV 时为 none
role: brand-memory / section-marker / emotional-call / hero-shape
art_title_reason: 艺术字承担的具体视觉责任
exact_line_breaks: 唯一断行与字序
skeleton: 具体字形骨架
weight: medium-bold | bold | extra-bold
width_height_ratio: 字面宽高关系
stroke_logic: 笔画粗细与变化
corner_terminal: 转角与末端处理
specified_glyph_edits: 指定到字符和部位的切角／延伸／连笔／断笔
baseline_tilt: 基线与倾斜
palette_by_part: 主色／辅色／强调色对应部位
material_effect: 纹理、描边、阴影或印刷工艺
dimensional_mode: flat | low-relief | extruded-3d | inflated | sculpted
view_angle: 正视或受控轻微偏转
extrusion: 厚度、方向、侧面可见程度；平面字为 none
face_material: 字面材质、颜色、粗糙度与纹理尺度
side_material: 侧面材质与颜色；平面字为 none
surface_finish: 唯一表面处理
lighting: 主光方向、软硬与高光关系
shadow_policy: 仅字形自阴影／侧面阴影，不生成地面或环境投影
edge_treatment: 倒角、圆角、毛边、飞白或墨晕
target_box: 最终画面位置与宽高
final_display_px: 最终显示像素
generation_px: 生成与最终采用文件的最低有效像素
integration_mode: blend | alpha-cutout；按最终消费者与背景条件选择
background_color: blend 路线仅纯白或纯黑；alpha-cutout 路线使用与全部边缘高反差的均匀纯色
safe_padding: 四周安全边距
fallback_action: 完成媒体交付后标记未准出、停止并报告；只有用户明确要求修改后才可重新生成、拆成更短标题或改用文本 DOM
```

同一系列中实际准入的艺术主标题必须保持笔画逻辑、字面比例、空间形态、挤压方向、材质、光向、边缘处理和色板一致，并统一使用中粗、粗或特粗视觉重量。禁止细宋体骨架、发丝笔画、极细狂草、无职责长横线或编辑批注线。艺术主标题成为可移动、可替换的独立图片 DOM；其余标题以真实文本 DOM 建立层级关系。

```text
Prompt 使用 `references/style/coding/ai-coding/art-title-prompt-library.md` 的“通用完整 Prompt 骨架”：先选唯一字形路线，再选至多一种主材质和一种辅助工艺，并明确空间形态、正面／侧面材质、粗糙度、纹理尺度、挤压厚度、光向、自阴影和边缘。未触发 KV 时省略参考图，使用已冻结的主视觉字形参数；不得把多个模板、材质和特效拼成风格词清单。
```

该 Prompt 库中的“纯色抠图背景”只在 `alpha-cutout` 路线解释为抠图底；`blend` 路线的背景与混合模式以本文件的白底／黑底成对规则为准，不修改 Style 文件本身。

每张艺术字在调用前按最终消费者选择接入方式，不按新建／编辑区分。只用于已知、稳定的 HTML 背景时可选 `blend`：深色字体使用纯白背景生成并在目标图片节点设置行内 `mix-blend-mode: multiply`，浅色字体使用纯黑背景生成并设置行内 `mix-blend-mode: screen`；保留纯色底，不调用抠图，混合模式不得设置在父容器或整页。需要透明导出、跨多个背景复用、背景未知或严格保持原字色时选 `alpha-cutout`：使用与全部边缘高反差的均匀纯色底生成，再调用抠图工具输出透明 PNG。两条路径都把最终采用文件与 `source_text` 人工逐字比对，OCR 只作辅助；共同检查文字、断行、内部镂空、笔画粘连、裁边和最终显示尺寸，`blend` 另检查纯色底均匀性、背景融合与对比度，`alpha-cutout` 另检查 Alpha、白边／色边及深浅底边缘。发现生成文字不准确或效果不佳时，仍先按交付门禁完成写入与交付，再标记 `delivered_with_text_issue` 并暂停该标题的 HTML 组装；禁止过度反思、自动拆词、连续改 Prompt 或自主重生。只有用户明确提出修改要求后，才可按其要求拆成更短标题、重新生成或改用文本 DOM；不得把错字、缺字或遮盖修补资产带入 HTML。

调用前按轻量素材清单统一记录该艺术标题的用途、生产方式、参考／身份来源、Prompt、目标比例与尺寸、安全区、消费者、接入方式、后处理和准出标准，验收通过后在 `output` 回填混合模式源图或透明 PNG 的最终短链；准确源文字和准入理由保留在 Brief。本节仅用于已准入的独立艺术标题；简历／三折页全部标题保持原生文字，正式电商 Hero 默认标题与文案也保持原生文字；社媒一体化 Hero 和 Brief 或用户明确选择且不与文字独立可编辑要求冲突的正式电商一体化 DIT Hero 则按各自品类范围整体生产，不进入本节。电商一体化仅允许主标题及必要短辅助文字入图，价格、日期、条件、参数和正文仍原生排字。其他分层区域不得把独立艺术标题合并进背景、商品或卡片表面。

用户要求“全部替换”艺术字时，只处理当前已经通过准入的艺术主标题槽位；先重新核对每张独立图片的唯一最高优先级标题，再分别重生、按消费者选择混合或抠图、逐字校验和替换。不得借“全部替换”把其他 H1 扩张为艺术字。未准入标题继续使用文本 DOM。

### 艺术标题分辨率门槛

- 生成前先记录艺术标题在最终画布中的显示宽高；最终采用文件中的有效字面像素宽度和高度均应达到最终显示尺寸的至少 `2 倍`，放大插值后的像素不计入有效分辨率。
- 可用时优先使用 `seedream_5.0_pro` 的 `2048×2048` 方图；不可用时选择当前 image 工具可提供的最高分辨率方形或近方形画布。不得使用文字只占小区域的低有效像素横图。
- 标题主体建议占源图宽高包围盒的 `65%–80%`，四周保留 `8%–12%` 安全边距；超宽标题可分行或拆成短语分别生成，不把整句压缩成远景小字。
- 记录最终采用文件的实际像素尺寸，并在最终显示尺寸和 200% 放大视图检查笔画边缘、内部镂空、颗粒与细线；混合路线还须在真实背景复查融合和对比度，抠图路线须在深浅背景复查透明边缘。任一方向不足 2 倍、出现锯齿或缩放发糊时，先完成媒体交付门禁并标记素材未准出；后续编辑／重生须遵守用户修改授权，不以锐化或强行放大通过验收。

### 产品身份锁定

用户产品素材的识别、锚点、实际工具图片输入与逐张核对统一执行 [画布资产语义目录工作流](../canvas-asset-organization.md#4-用户上传的初始视觉锚点)。先实际查看产品，记录轮廓、比例、材质、颜色、部件、标签和 Logo；仅摆放时复用已准出原素材，需要改场景／构图时使用宿主图像编辑能力，并传入对应身份图，不能仅凭文字描述重绘。

KV、Hero、环境、细节等包含产品的新资产都保留同一身份来源；改变用途不等于可以替换产品。编辑已有合成图时以当前图为编辑对象、原产品为身份参考，不用母版替掉整张当前图。逐张对照原图核验，失败沿用既定路线和停止条件，不把失败衍生图升级为母版。

### 素材拆分

本节落实需要独立编辑／叠压的分层区域；一体化社媒 Hero 的内部内容随整体图生成，不按卡片或独立标题再拆一次。

- 不生成可由真实文本 DOM、HTML 元素、行内 CSS 或内嵌 SVG 清晰实现的正文、按钮、表格、图标或简单图形。
- 背景、主体、纹理和装饰按需要拆成独立资产，便于替换和生成其他固定尺寸版本。
- 同一页面优先少量强视觉，不用大量普通图片填满空间。
- 为每个素材保存用途、提示词、源参考与替换位置。
- `asset-manifest.json` 严格使用 [轻量素材清单](../../../example/asset-manifest.md) 的字段：`asset_id`、用途、生产方式、参考输入、Prompt、目标比例／尺寸／安全区、页面或区域消费者、后处理、准出标准、状态与就绪输出。相同素材重复摆放共享一条资产记录并列出多个消费者；DOM ID、坐标、层级、字体、CSS 参数和实现绑定只存在于 HTML。
- 社媒套图素材对应原 Brief 的页次、用途、参考短链、文字安全区和本页变化；一期只登记封面资产，确认后再增补内页，并注明继承的 `series_contract` 可观察机制。没有明确用途、槽位和具体机制的“同风格素材”不得进入排版，不另加系列机器字段。

### 卡片布局变体准出

Brief 先用自然语言说明卡片形态、内容与视觉系统的关系；编写 HTML 时再确定实际尺寸、角度、层级和间距。规则网格／同轴模块可服务技术卖点、平行比较和编辑秩序；错位、倾斜、叠压、路径等用于确有需要的表达。不能因为调用 Coding 就默认统一圆角卡片，也不能为摆脱模板而强制倾斜或重叠。

套图同时执行 Social Visual 的卡片数量、主辅面积、主动布局变化与跨页配额；以下通用试排建议不豁免套图硬门禁。等尺度证据可在一个主组内排列，页面其他部分承担所需差异，不改造事实来凑配额。

- 当视觉系统需要重叠或穿插时，Brief 说明对象、方向、允许遮挡和被保护的文字／事实区域，具体比例与层级由 HTML 实现并在渲染后核验；其他情况由对齐、留白、图片尺度和字级建立关系。
- 多卡片组按内容决定保持或变化哪些尺寸、位置、轮廓与密度；稳定壳体内部也应有清楚的主体、结论与从属说明。仅换底色而保留无差别小图和文字堆叠仍需返修。
- 倾斜与叠压的具体角度、旋转中心和比例在 HTML 试排时确定；普通正文不旋转，叠压通常控制在 `10%–30%`，并以实际可读性为准。
- 手绘、撕边、液态、票券、拟物和不规则容器按所需效果及选中 CSS／SVG 的可靠表达能力选择载体，不按名称优先裁定为图片。可稳定表达的轮廓、规则表面与结构由 Coding 实现；无法可靠表达的复杂材质、插画或拟物成像才走 `image-shell`/`hybrid-card`。排列服从本节的视觉系统与内容关系，不强制错位、倾斜或不等权。
- 参数表、ATS 事实区、证据比较、技术卖点和编辑式系列可以采用规则网格；Brief 写明主动选择依据与内部图文层级，不视为设计降级。

### 生图卡片素材

卡片按视觉职责与可靠实现能力选择载体。中性底板、功能标签、按钮、规则面板，以及选中 CSS／SVG 能可靠表达的贴纸、异形卡片、便利贴、票券、撕纸、手绘气泡、像素窗口或拟物结构，使用 DOM／CSS／SVG，不因名称、媒介隐喻或章节识别职责强制生图。只有所需复杂材质、插画或拟物成像无法由选中 CSS／SVG 可靠兑现时，才作为独立图片壳体生成并抠图；准确文字仍由 Coding 承担。

生成卡片可以包含外壳、材质、插画、非事实图形、摄影或场景，准确文案与规则仍由 Coding 承担。Prompt 只写具体风格、外轮廓、视角、主体、低纹理空间、材质、光向、边缘工艺及系列连续性，不提文字或文字否定词；比例单独传工具参数。

代表真实帖子、视频、商品、创作者或平台案例的卡片只能使用有来源的真实素材。没有真实案例时，可以生成明确作为示意的内容场景或非品牌化封面视觉，但不得伪造账号、播放量、评论、平台 UI 或可被误认成真实发布内容的截图。

多个已确定采用图片壳体的卡片属于同一系列时，先锁定共同的透视、光向、材质、圆角或边缘工艺，再分别生成承担不同章节结论的内容对象和构图。这些独立图片壳体无论外接框是否接近矩形，均按 isolated element 生成并抠图；原生 CSS／SVG 容器不进入该流程。只有作为整块背景使用的环境图、纹理面或场景插画可以保留矩形边界。不要一次生成包含全部准确文案和全部卡片的整段排版。

卡片 Prompt 可追加：

```text
风格：<具体风格及视觉特征>
卡片结构：<外轮廓、视角、材质、主体区>
低纹理区域：位于<具体位置>，占卡片<比例>，明度稳定、表面平缓
系列连续性：与其它卡片共享<透视、光向、材质、边缘工艺>，本卡通过<内容对象和构图>区分
保护：<轮廓、主体与边缘完整性>
```

### 独立图片元素透明化门槛

当 AI 生成内容是要以透明形式叠加到背景、文字、面板或其他图片上的独立元素，或艺术标题已选择 `alpha-cutout` 时，严格按以下顺序执行；图片壳体不得因外接框接近矩形而跳过透明化。已选择 `blend` 的艺术标题和由 CSS／SVG 可靠实现的容器不属于本流程：

1. 将素材类型标记为 `isolated element`，例如选择 `alpha-cutout` 的艺术字、产品主体、角色、插画、贴纸、复杂图标或装饰；
2. 选择与主体所有边缘高反差的均匀纯色底：深色主体优先白底，浅色或白色主体优先纯绿/纯蓝/深色底，避免背景色与半透明边缘、头发、玻璃或文字内部镂空同色；
3. 在生图提示词中明确写入“单一纯色背景、无环境、无地面、无边框、无渐变、无投影、主体完整且不贴边”；不要要求模型直接输出透明背景；
4. 生成后调用 `remove-image-background`、抠图工具或宿主等价能力，输出带 Alpha 通道的 PNG；
5. 在深色和浅色测试底上检查白边、绿边、孔洞误删、半透明丢失、阴影残留和裁边。失败时记录素材未准出并暂停组装，完成既有媒体交付；涉及艺术标题的重生等待用户修改授权，获准后再修正源图与抠图，普通非文字素材按原修复门禁处理；
6. 只把通过检查的透明 PNG 回填素材清单并绑定到最终图片 DOM。同时保留纯色底源图，供重新抠图，但不得把源图作为最终排版素材。

完整矩形使用的环境摄影、全幅场景图和纹理不执行此流程。若场景主体需要跨出图片边界或与文字堆叠，另行制作该主体的 `isolated element` 版本并抠图。

独立素材提示词追加段：

```text
Asset mode: isolated element for compositing
Background: one uniform <white / chroma green / other high-contrast solid color>
Isolation: subject complete, centered with safe padding, clean silhouette
Avoid: environment, floor, frame, gradient, cast shadow, extra objects, cropped edges, transparency claim
Post-process: run background-removal tool and export transparent PNG before layout
```

### 素材准出检查

本阶段只验素材本身、准确来源、身份、比例、Alpha、分辨率、可组装性和素材记录。涉及最终图文关系的条目此时只核对计划与预留区域；实际 DOM、相邻接缝及文字覆盖须在完整 HTML 生成后按 HTML 验收流程检查，不得把尚未生成的 HTML 当作素材准出前提。
- 语义是否匹配内容；
- 系列的镜头、光线、色板和颗粒是否统一；
- 社媒套图一期封面资产只检查当前封面 Brief、封面清单、用途、身份、比例、文字安全区和素材本身的技术／视觉准出；不得以前置的封面渲染或用户确认作为封面资产准出条件；
- 社媒套图内页资产必须核验当前封面版本、真实呈现证据、用户明确确认原文与时间均匹配；仅在确认后进入共享清单，并对应同一中文 Brief 的页次、用途、文字安全区、`series_contract` 机制与逐页变化；
- 是否出现错误文字、品牌或界面；
- 每项重要图片资产是否已写明构图职责、装饰职责、过渡职责以及与相邻章节的连接；不适用项是否明确写无；
- 背景、主体、标题、信息场和装饰是否形成至少一种可观察关系，而不是一张自足背景上覆盖独立卡片；
- 背景主机制、材质尺度和文字负空间是否服务所选视觉系统；不把固定材质占比当作所有画面的审美标准；
- 背景、容器和标题是否至少共享色板、轮廓、材质或网格中的三项；
- 是否优先直接排字并把主容器控制为一个，且没有通用 SaaS 圆角卡、等权卡片墙、多层投影或无意义玻璃拟态；
- 多卡片组的规则排列或错位／穿插是否符合已选系统，实际图片、文字与容器是否有清楚的主次；
- 多卡片的保持与变化是否由内容和调性决定，是否避免同权小图／文字卡堆叠与只换颜色；
- 先锋酸性数字招聘是否只选择模糊能量场、液态膜材或线框异空间中的一个分支；
- 艺术标题最终采用文件的有效字面像素宽高是否均达到最终显示尺寸至少 2 倍；
- 混合路线是否使用纯白底＋`multiply` 或纯黑底＋`screen` 的成对实现，并在真实背景保持融合与可读；
- 抠图路线的边缘是否在深浅背景上干净，且具有真实可用透明通道；
- 产品身份是否与参考一致。
- 卡片是否确实承担章节识别、媒介或材质语义，而不是本可由 Coding 完成的普通底板；
- 生图卡片是否留出真实可用的文字安全区，且准确文字仍由真实文本 DOM 承担；
- 同系列卡片是否共享透视、光向、材质和边缘语言，同时通过内容对象与构图区别章节；
- 案例卡是否使用真实来源，或明确保持为不冒充真实平台内容的示意视觉。
