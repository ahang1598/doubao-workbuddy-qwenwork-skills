# HTML 检查执行流程

页面自检例外统一遵循 [预览策略](html-preview.md)：只有 `shot.py` 返回退出码 `3`、脚本无法完成执行时，才可跳过自检并记录“预览未验证”，继续默认 Canvas 中未被独立规则阻断的可完成部分。退出码 `1` 表示检查完成并发现问题，必须按 hint 与实际截图修正并重跑，不得改记为“预览未验证”；退出码 `1` 本身不阻断默认 Canvas 的 HTML 上传、Item 创建与回读，是否阻断由源码硬门禁、媒体门禁或其他独立规则决定。只有当前版本合格的同尺寸完整预览才进入 CDN＋Markdown 展示；不合格截图不得展示，缺失预览不得伪造，所需预览与卡片未闭环时不得宣称完整完成。Mobile 无合格预览时只说明可视交付未完成，不启用 Canvas。


新建、整体重排、页尾变化或其他影响高度的修改，固定画布高度验收执行 [DOM 测高](html-dom-measurement.md) → 未锁高时仅回填四处高度并复测正式固定高度 → `scripts/runtime/shot.py` 严格预览；锁高越界返回排版，不自动改高。不影响高度的局部修改复查受影响区域，不强制整体测高。图片按 [比例与取景规则](../style/coding/ai-coding/asset-prompt-guide.md#图片比例取景与有效像素) 分别核查源图到就绪文件、就绪文件到每个显示实例；合法 cover／contain 不因框比例不同被判拉伸。

> 先按主 SKILL 确定环境。`Device platfrom: Mobile` 时遵循 [Mobile 直接交付](mobile-app-direct-delivery.md)，仅在本地生产、验收并展示上传 CDN 的预览；跳过下面所有 Workspace、HTML 上传、CLI、Item 和画布卡片要求。默认 Canvas 才执行这些步骤。VI 在任何环境都禁止向用户直接交付 `.html` 源文件；默认 Canvas 的 `FileBatchUpload` 只用于创建唯一顶层 HTML Item。

在 [HTML 组装](html-assembly.md) 或 HTML 编辑完成后使用。[固定画布与交付协议](../html/coding-rendering.md) 管理源码，[shot.py 预览策略](html-preview.md) 是默认优先的截图策略；交付环境沿 [交付验证](validation.md) 确定。

通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图已有合适底图且无需新图时，按主 SKILL 的复用例外核验真实来源、质量与最终可见消费者，不强制新生成／编辑记录；其余新建 AI Coding 仍核对必要的图像生产。

## 1. 源码与同源输入

- 使用当前完整 `.html`、同版本素材、准确文案和唯一自然语言 Brief；AI Coding 同时读取原素材清单。保留本地相对资源的路径上下文，最终资产引用遵守交付协议。
- ai-coding 新建／整体重做须核对实际图像生成／编辑结果、生产来源和最终可见消费者；没有图像产物、只展示 KV 后弃用，或以隐藏图片／无关装饰凑调用均不通过。返回素材生产，不能把纯 Coding 成品记为符合本路线。用户明确限制图像工具时记录原话与实际限制；局部改字／间距沿用已核验素材，不要求重新生图。pure-coding 和 pure-image 不套用此项。
- 核对文档完整、画布正整数宽高、三个根容器的固定行内尺寸、真实资产 URL、文字和元素唯一映射；不允许根画布通过裁切掩盖正文或页尾。逐项检查 `<img src>`、`srcset`、行内 `background-image`／`mask-image` 和内嵌 SVG `<image href>`：生成／编辑图片必须逐字匹配素材清单已准出的最终 HTTP(S) 短链；本地／相对路径、`file://`、`data:`、Base64、Blob、临时预览地址、占位 URL、擅自重传换链或未登记版本均不通过。作品容器最后必须有唯一 `data-canvas-bottom-safe-area` 正常流收尾区，数值和行内高度符合预览策略基线；缺失、过小、隐藏、脱离文档流、位于其他可见元素之前或只用纯 padding 代替均不通过。
- 按 [布局几何规则](../style/coding/composition-layout.md#长图段高图文比例与实际兑现) 将 Brief 的视觉目标、就绪素材与 HTML 声明对照。源码中的坐标和字体仅是声明，不能充当实际 DOM、字体加载或视觉完成的证据。

## 2. 预览与检查记录

流程图、思维导图和知识图谱须核验已展示当前版本的实际渲染结果；仅有 HTML／SVG／Mermaid 代码块不算完成，渲染失败时明确说明可视交付未完成。

交付前只运行 `python3 <SKILL_DIR>/scripts/runtime/shot.py <html_path>`。按 [预览策略](html-preview.md) 读取 consoleErrors、resourceErrors、issues/hint、measurement 和 screenshot。脚本内部执行自然测高、恢复后复核与分段截图；Agent 不使用其他浏览器检查器或预览 Skill。修正源码后重跑同一入口。退出码 `1` 的问题必须按 hint 与截图修正并重跑；只有退出码 `3` 的执行失败可跳过自检并交付已有成果，同时记录预览未验证。

## 3. 视觉与平台复核

素材阶段之后，在当前完整 HTML 中检查：

- HTML 是否按 Brief 的关系落实角度、重叠对象／比例、错位、轮廓、层级和文字安全区；若使用规则网格，是否能从内容职责说明技术卖点、平行比较、编辑秩序或可读性的主动选择依据；
- 最终 DOM 中标题、正文、卡片壳体、商品／人物、证据和背景是否具有清楚层级，卡片文字是否位于真实内容区，所有有意相交是否保留被保护内容；
- 卡片、装饰、光场和从属图片是否完全避开商品识别面、人物面部、Logo、接触点、尺寸端点与证据字段等 `protected_regions`；不得以降低透明度或把标题临时提到最高层代替关系修正；
- 主体是否挤压代码内容；
- 一体化社媒 Hero 是否绑定准确图内文案并完成与第 2 屏的衔接检查；独立艺术标题是否只覆盖准入的大标题并保存源文字、消费者、接入方式、最终文件与验收结果；混合路线核验纯白底＋`multiply` 或纯黑底＋`screen` 的成对实现和真实背景效果，抠图路线核验真实 Alpha 与深浅底边缘；其余分层文字是否使用经实际 HTML 预览验证的真实文本 DOM；
- VI 是否先核对 Brief 中的宽窄依据：默认宽幅长板使用 1600px 宽画布并以约 16:9 横向视域组织主要章节，明确分页时逐页固定尺寸，只有明确窄幅依据才接受窄长画布。宽幅 VI 同时查看整张缩略图、每个完整章节和代表性细节；内容集中在中间窄栏、两侧无职责空白、重复单列堆叠、等权缩略图墙、微小文字或异常增高均返回布局重组，不能仅凭声明宽度判为通过；
- 品类 Visual 已声明明确字号门槛时，验收必须读取该品类规则并核对最终 DOM 的实际渲染字号，不以 CSS 声明值、变量或相对单位本身代替结果。VI／品牌 HTML 另按 [品牌 HTML 字号底线](../style/coding/systems/vi-visual-system.md#品牌-html-字号底线) 逐项检查；所有低于 `20px` 的文字同时在 100% 视图和最终完整预览中确认可读，达到数值但因字重、对比、背景或缩放难辨仍判失败；



本节统一验收素材职责、就绪状态、布局与文字。先对照用户目标和同一 Brief 查看完整作品、首屏与正文接力、主要正文组织及每条接缝两侧；接缝居中只指验收取景，不规定构图居中。逐图对照原 purpose 或使用说明中的去底结论、理由及采用版本，核对最终消费者：透明主体不得残留实底、棋盘格、白边／色边或误删细节；完整平稿、照片图窗和场景的有职责背景不算残底，不能为验收强制抠图。

逐段检查正文、表格、FAQ、卡片和 CTA 前后的空白是否承担真实职责，内容高度不得机械继承 Hero、背景图或交付切片高度。代表性正文取景只用于构图检查，不能代替文字全检：必须用当前实际截图在真实阅读尺度逐条、逐行人工核对标题、说明、正文、图注、菜名规格价格及每条末行，检查孤立汉字、标点、数字单位和语义断裂；有意竖排、单字主视觉或诗句断行按原依据判断。覆盖不足的条目记未验证，不能只看缩略图或抽查首屏。

仅电商详情页（含其连续长图）按[阅读尺寸与字号门槛](../style/coding/scenarios/ecommerce-detail-page-spec.md#阅读尺寸与字号门槛)验收：在最终阅读宽度检查 DOM 有效字号及图内文字；任何内容文字低于 13px，或模板 12px 内容字原样交付，均退回重排。仅有位图且无法确认时记未验证；对比不足另记。

对 Brief 已选的每处衔接，在同一验收记录对应写明 Brief 条目／版本、实际 section 或图像节点、采用机制、当前 HTML 版本、接缝局部截图及结论。纯 Alpha 方案逐项核对实际起点、100%→0% 的有效区间、末端全透明缓冲，以及透明后显露的是否为共享底图；参数存在或节点备注不算通过。先看整图阅读节奏，再以原尺寸查看包含完整作用范围及两侧保护对象的局部；可从 shot.py 当前完整截图裁取并注明源图与裁取位置，不冒称脚本已自动输出或判断接缝。截图缺失、版本不一致或未查看局部时记录未验证。扩展背景另核对主体、投影、字标和图内文字未被改写；技术通过与视觉通过分开判定。

技术报告与人工视觉结论分别写入既有验收记录。shot.py 未自动检测或未返回的项目，尤其孤字、残底和段内空白，不得宣称自动通过；用实际截图补足视觉检查，无法检查的项目明确记为未验证。下表按实际内容适用，未涉及项记不适用，不为通过检查凑效果数量。

| 高频问题 | 检查实际画面 | 失败后的处理 |
|---|---|---|
| 无依据光柱／亮带 | 普通纸面或桌面是否被斜向白带、放射光抢占；照明是否符合已选场景，是否压低文字对比 | 改正素材 lighting 或移除多余 CSS 光层；主题明确需要的舞台／科幻光束保留 |
| 意外断裂或错误衔接 | 按已选关系检查：空间连续看透视、尺度、纹理与对象；媒介转换看载体边界与进入方向；视觉呼应看轴线、色彩职责和母题；独立图窗看边界职责；明确换章看真实内容转折。首屏进入正文不能自动算换章。两张满幅图片直接衔接时，接缝不得露出底层背景形成空隙或色带；有意设计的过渡或分隔除外。以接缝为取景中心同时检查首屏底部接力文字、正文首标题及边界／过渡的完整作用范围，确认保护区未被纸边、色块、蒙版、高光或低对比背景侵入 | 关系判断错误先回到规划；空间错误返回素材；文字净空不足时调整构图、素材或边界，不用 Coding 覆盖一体化 Hero。局部色阶差异才做融合；有依据的纸边、图窗、撞色与章节带保留，不一律抹平 |
| 白雾／黑幕遮缝 | 接缝联合画面是否出现横向亮／暗带、透明度台阶，或使桌面、产品轮廓、接触点消失；同时检查原图、最终裁切与附加蒙版 | 原图问题返回素材；多余覆盖直接移除；仅安全空场可调整 Alpha，无连续关系时换图或明确换章，不继续加雾 |
| Hero 主次与开场失效 | 社媒Hero按所选关系检查：图主的主体尺度与场景识别、文主的标题表现与辅助图从属、图文组合的共同主组与阅读顺序；三类均检查完整开场、正文接力及实际文字承载，不用统一图文占比验收。详情页仍检查完整主图与少量标题的关系，是否被拆回商品贴图、通用光效和三卡卖点 | 对照 Brief 的开场比例、内容职责与高度依据核对实际开场边界；社媒长图 Hero 无用户指定或完整命名配方例外时，核对 H/W 为 1.5–1.8；需要过渡到下屏时默认 1.8，并检查底部过渡安全区避开标题、主体及关键信息、计入首屏高度且未额外加高；其他社媒 Hero 仍按原起排范围检查，无用户／参考依据而低于范围时返回构图，不因无溢出放行，有明确紧凑参考时不按统一比例判失败；排查CSS显式高度、比例方向与横图auto高度，不横图拉伸、空白补高或重复覆字，也不强迫小点缀变主图 |
| 米色默认与背景未兑现 | 配色是否来自已选品牌／参考／主题；指定色场、纹理或影像是否实际可见 | 纠正默认色覆盖或缺失的背景层；有依据的米色、稳定色面不判失败 |
| 实物被代码替代 | VI／信息图中的设备、场景、真实截图和证据是否绑定正确素材，而非临时几何占位；数据与文字仍准确可编辑 | 返回素材分工／绑定；纯数据、图标与明确可编辑原型不强制生图 |
| 构图单一或图文关系丢失 | 不同职责的段落是否都退化为同轴标题加下方图片；已选环绕、对照、穿插、主体尺度与阅读接力是否可见 | 对照原目标修复局部构图；内容需要的规则重复保留，不为变化随机左右翻转 |
| 内容容量、间距与断行失衡 | 按 [内容容量与留白](../style/coding/composition-layout.md#容器内容框间距与顶边) 分别核对整页、各栏／折面及模块内部：主体是否集中靠上，是否存在无职责的连续空区，壳体增高后内部是否仍挤在顶部；简历比较栏间节奏，三折页兼看单面与整侧，不要求各面等密度。用最终字体检查完整标题组、数字单位、图注、末行及相邻净距；背景覆盖、页尾任务栏或单个最末节点落底均不能代替这些检查。有意场景留白、竖排和叠压按原构图核对 | 固定纸幅内联动栏目、模块、图窗、间距和内部排版，兼顾原字级层次与完整事实；不能只拉高空壳、裁掉单位、放大装饰或改画布尺寸。未锁高长页则收拢无职责空段再测高；改变采用结构或锁定内容沿品类授权流程处理 |
| 渐变侵入文字安全区 | 按[渐变安全区](../style/shared/composition-principles.md#渐变与文字安全区)联合检查接缝两侧实际文字、图内文字与完整羽化尾部；核对共同祖先的 mask／opacity／filter 和真实层叠上下文。背景渐变另验逐行局部对比 | 移动或收回前景过渡、拆分受影响层，空间不足回到构图／素材；不以提高 z-index、降低遮罩透明度或单屏无溢出代替修复。改字、换图、调整裁切或范围后重新核验 |
| 文字融入背景或表现未兑现 | 在最终阅读尺度逐组检查标题、正文、数字和小字，包括图内文字；跨明暗交界时看每行及局部笔画，不以整图平均对比、放大后可读或无溢出代替。已选字形与强调关系是否成立 | 按[共同对比策略](../style/shared/composition-principles.md#文字与背景的对比处理)修正字色、位置、构图或素材，并复查当前合成结果；检查祖先透明度、滤镜与覆盖层。关键文字仍混淆不得标记视觉通过；图内修改沿原授权流程，不默认加阴影、灰雾或底板 |
| 配图有主题、无实际作用 | 对照相邻文案指出图中可见的细节、动作、差异或场景关系；最终阅读尺寸是否看得清？氛围图按品牌／情绪作用判断，不作为功效证据。去图或换商品仍无影响时复查用途 | 缺事实返回内容；图没表达目标返回素材；目标被缩小、遮挡或裁掉返回布局；结构特写被压成无可辨关系的窄条同样失败，扩大槽位或重新取景。按原目标复查，不补写“增加高级感”追认，也不以 IMAGE 存在即通过 |
| 容器与装饰过量或缺位 | 连续段落是否因内容有多项就被拆成相同列数的卡片；去底板后图文关系是否仍清楚；核对实际 box-shadow／drop-shadow、伪元素及图内烘焙阴影，不只看实现声明。必要图窗、实体载体与已确认 KV 按原职责判断 | 回到内容关系重排开放图文，再保留确有职责的边界；移除普通卡／标签及纸纹自动带出的投影，真实接触或悬浮阴影按光向保留，不靠换圆角或错位通过 |
| 文案、身份与资产错误 | 逐字读标题与关键数字，检查重字、错字、截字、遮挡、产品／Logo 身份、失效资源、残底和页尾完整性 | 原生文字与布局回到源修正；图内文字按原交付门禁记录并等待授权修改；身份／资源错误返回资产步骤 |

在既有验收记录中分开写明尺寸／溢出／安全区、主体及各栏／各面／模块内部的空间分配、大块留白的职责；视觉结论须指出具体区域，不能仅列自动检查通过数量。`shot.py` 的内容底边只是几何测量，不是语义内容占用或版面均衡判断；任务栏、页码等即使落在页底，也要单独复查主体至页尾的空区。截图或测量证据不足时记录未验证，不编造填充率。为发现的问题注明源／资产版本、章节及可定位的 DOM id／data-layer-id、可见证据、已确认或待核实的原因、修复动作与复查结果；没有元素映射时用章节与画面位置定位，不编造测量值。工具报告只是线索，须核对截图与设计意图：有意出血、叠压、光学对齐或竖排可能是合理例外，写明依据，不能见告警就改。布局问题按表中内容容量与间距标准定位所属组及共同定位祖先，修正尺寸依赖；`overflow:visible`、没有裁切或工具未报错，都不证明局部边界和相邻关系成立。已发现的缺陷先按相应流程处理，不能标记通过；改动后用当前版本重新预览，复查受影响区域及相邻接缝，改变全局样式或整体几何时重看全图。素材修改遵守既有授权与停止条件，不为视觉审查无限重生；无法修复或未取得预览时明确记录未解决／未验证。

按 [背景、卡片、文字关系与三类安全区](../style/coding/ai-coding/reference-analysis.md#背景卡片文字关系与三类安全区) 逐一检查当前设计涉及的页面边缘、卡片真实内容区和素材语义保护区，并将结果归入现有验收记录。核对连续场景是否被误加卡片、字组是否对应正确产品、表面纹理是否落在指定层且实际可见；作品展示外底不应无依据进入成品。无纹理／无卡片可以是正确目标，不能为凑验收项增加效果。

将“配方有实现”“当前节点已绑定”和“实际渲染符合目标”分开记录。素材依赖尚未完成、只看过占位框或未核验局部时记未验证；完整缩略图和无溢出报告不能证明安全区、语义断行、纸感或柔焦正确。每次替换素材、字体、文案或调整裁切／旋转／遮罩后，复查对应保护区、内容框、相邻对象与共享背景，不沿用旧版本通过状态。

参考任务另按 [原图对照验收](../style/coding/ai-coding/reference-analysis.md#5-html-重建与验证) 核对用户锁定的目标；不能只拿自定 HTML 声明证明还原成功。字体、图片或源码改变后，旧预览不代表新版本。

源码和实际发现的内容问题按 [交付验证](validation.md) 修正。退出码 `1` 或截图确认的真实页面问题必须按 hint 与实际截图修正并重跑，不得标记通过或改记为“预览未验证”；这些问题本身不统一阻断默认 Canvas 的 HTML `FileBatchUpload`、Item 创建与回读，是否阻断须依据源码硬门禁、媒体门禁或其他独立规则，已完成写入也不免除修正与复查义务。只有退出码 `3` 的执行失败可跳过自检并记录“预览未验证”，继续未被独立规则阻断的可完成部分。证据覆盖不足只改变相应检查项的验证状态，不得把已发现的问题改记为未验证以绕过修正。平台预览与本地预览分别记录证据；没有真实上传短链、Item 回读或平台预览时保留 `PLATFORM_UNVERIFIED`，不把截图当作平台成功证据。

当前版本合格、与 HTML 声明画布严格同尺寸且内容完整的预览截图是必展结果：合格截图就绪后，必须先用 `FileBatchUpload` 上传 CDN 并核验返回的公网可访问 HTTP(S) 链接，再以标准 Markdown 图片语法 `![可编辑设计预览](https://cdn.example.com/preview.png)` 展示；URL 必须逐字使用预览图上传结果。不合格或缺失预览不得展示。该截图不得调用 `present_files`、不得创建 IMAGE Item、不得写入 Workspace 或资产目录；CDN 上传不算画布持久化。默认 Canvas 的 HTML 源 `FileBatchUpload`、顶层 HTML Item 创建与回读按独立门禁执行，不以预览展示完成作为统一前置条件；回读后将同一 Workspace ID 与刚回读的 HTML Item ID 拼成 `<workspace_id>?item_id=<item_id>` 单值交给 `present_files` 输出对应画布卡片。完整 VI 的分页或章节不得拆成多个 HTML Item，HTML 源上传只用于画布持久化，禁止通过聊天、Markdown、附件、压缩包或 `present_files` 直接交付；完整 VI 的 CDN、上传、CLI、回读与卡片交付必须由 Main Agent 执行。退出码 `1` 的问题仍须修正并重跑，但该预览问题本身不阻断 HTML 上传、Item 创建与回读；是否阻断仍由源码硬门禁、媒体门禁或其他独立规则决定。退出码 `3` 的执行失败可跳过自检并记录“预览未验证”，继续未被独立规则阻断的可完成部分。没有合格预览、未完成其 CDN＋Markdown 展示或当前环境所需卡片未交付时，不得宣称完整完成。Mobile 无合格预览时只报告可视交付未完成，不启用 Canvas；其他图片导出仍按用户授权和媒体交付门禁处理。

### 屏间过渡路由验收

先对照 Brief 与对应 Visual 核对相邻屏叙事关系，再按 [屏间过渡路由](html-assembly.md#屏间过渡路由基础方案优先) 检查背景层的基础路线与增强层；不得因成品“看起来有渐变”跳过关系、载体和端点验证：

- 两端为独立完整主图时，出现跨图渐变、mask、opacity 或 blend 直接融合即失败；连续场景必须验证同一母图／连续裁切或同一背景生产单元依据，同章推进必须有承担内容／节奏职责的结构化分隔，章节切换必须保留清楚边界。

- 首尾必须符合相邻 Section 的目标原色、原纹理或图片退场关系；纯色端无纹理残留，图片接缝终色准确。
- `normal`／CSS／mask 基础版本必须先有独立可见结果。Blend 只能作为中段独立装饰层，容器必须设置 `isolation:isolate`，且在首尾完全退出；产品、文案、按钮、Logo 与证据不得继承其 mask、opacity、filter 或混合模式。
- 同色系纹理增强须同时满足色相、亮度、纹理尺度兼容和“基础融合仍不足”；跨色系严格保色、背景可变或需要跨背景复用时，不得保留 blend 增强。
- 在实际背景、最终裁切和目标视口中与基础版本对照。出现偏色、端点污染、横向暗／亮带、脏灰、纹理混杂、细节损失或文字对比下降即判增强失败：先撤销增强并恢复 `normal`／mask，再调整遮罩范围；仍不自然时缩短交叠区或保留有职责边界，不继续堆叠覆盖层。
- 默认 `auto` 接缝只需记录基础路线和 QA 结论；非默认、增强或发生回退的接缝再记录 `base / endpointLock / mask / enhancement / forbidden / fallback / qa`，不虚构像素、opacity 或取色证据。


### 接缝与文字碰撞的必查局部

逐一查看每条接缝及其两侧实际成品局部，不以整张长图缩略图代替：对照 [双侧取色与合成](html-assembly.md#素材就绪后的合成与几何复核) 的 A／B 来源，检查过渡起点、接缝与终点，确认叠加后没有新增亮暗横带、残留矩形边或被擦除的主体／文字。既有雾带不能成为下一次取色依据；无数值采样证据时只记录视觉判断，不虚报精确取色。

逐组查看全部竖排／旋转／绝对定位文字、数字标题组及其相邻正文，在正常阅读尺度和足够清晰的局部预览中核对每一行。先验证标题占位和正文可用区互不侵入，再看实际字形是否相交、末行是否挤入下一组；图内文字同样纳入。出现「竖题盖时间线」「数字挤进标题」即失败，即使全部节点仍在画布内。修复所属布局与占位，不用 z-index、遮罩或减淡文字掩盖；字体、字号或断行改变后联动复查邻组。

当前 `shot.py` 不检测文字间碰撞，也不判断渐变质量；其无 issues 不能作为这两项通过依据。现有截图不足以逐字判断时，保留该区域未验证状态，不凭缩略图标记通过。将检查过的区域与发现记录在原验收文件，不新增检查合同。

## 4. 自检入口与能力边界

仅使用上述 shot.py 报告和实际截图做页面自检，不另行运行 verify-html.cjs、Browser Use 或其他预览 Skill。自动检查不证明审美或事实正确；缺失检查项如实记录。输出在 _shots/，无需删除。
