# Brief → HTML 组装

新建、整体重排或页尾变化时，固定画布高度验收执行 [DOM 测高](html-dom-measurement.md) → 未锁高仅四处高度回填／锁高越界返回排版 → 正式固定高度复测 → `scripts/runtime/shot.py` 严格截图预览；局部修改未影响整页高度与页尾时，只复查受影响范围后严格预览，不强制整页测高。图片按 [比例与取景规则](../style/coding/ai-coding/asset-prompt-guide.md#图片比例取景与有效像素) 分别核查源图到就绪文件、就绪文件到每个显示实例；合法 cover／contain 不因框比例不同被判拉伸。

> 先按主 SKILL 判断交付环境。system 明示 `Device platfrom: Mobile` 时遵循 [Mobile 直接交付](mobile-app-direct-delivery.md)：Brief／素材记录留在本地，跳过本文全部 Workspace、Canvas CLI、Item 与卡片步骤，媒体逐项直接交付、HTML 预览走 CDN＋Markdown。其他环境执行本文默认 Canvas 分支。生产与编辑顺序不变。

用于已锁定 最终 HTML的创建或编辑任务。把冻结 Brief、已选 Visual System 与就绪素材直接落实为完整 HTML；生产路由、素材生成与交付顺序仍由调用本文件的 workflow 管理。

完整 VI 的 HTML 生成、修改、返修及 `shot.py` 自检只能由 Subagent 执行；Subagent 完成后向 Main Agent 回传本地完整 HTML、声明尺寸、同尺寸预览、校验状态、建议 `path`、完整 `brief` 与创建意图并停止。CDN、`FileBatchUpload`、Workspace、CLI、回读、`present_files` 及用户交付全部由 Main Agent 完成，具体读取 [VI HTML 交付规范路由入口](vi-html-delivery-route.md)。本条不适用于其他品类，也不授权 Subagent 生产 VI 素材。

## 1. 组装入口

创建任务满足以下条件后开始组装：

- 唯一自然语言 Brief 已完成并冻结；
- pure-coding 所需真实资产、字体和实现依赖已可用；
- ai-coding 的 `asset-manifest.json` 已通过 `validate_asset_manifest.py --require-ready`；
- 本轮正式生产返回的全部图片／视频结果（含候选、未采用版本、抠图源与中间素材）均已完成写入、`+get` 回读和逐项 `present_files` 交付；串行与并行门禁已汇合，不存在待补写或待交付分支；
- 所有 Coding 文字已在 Brief 中逐字确定并注明可编辑职责；
- Visual 草案阶段选择的 CSS／SVG 候选仍适合最终内容与素材。

HTML 组装时不得继续决定内容结构、视觉方向或正式图片职责；这些变化返回 Brief 或素材阶段。坐标、字号、颜色、层级、DOM ID、CSS/SVG 参数和消费者直接写入 HTML，不建立全量中间参数文件。

## 2. CSS／SVG 实现绑定

<a id="css-recipe-binding"></a>

执行三个时点：

1. Spec 内容与 Visual 草案形成后、Brief 冻结前，按 [组合参考筛选](../../assets/templates/css/README.md#brief-combination-match) 用 `search`／`describe` 优先比较组合，必要时用 `get --prose` 补读设计说明，适配真实内容后再用原子补足局部；草案中的模型自选布局可调整，用户锁定项保持不变。
2. 最终 Brief 冻结后，读取采用的组合及补充／替换原子，执行 `query-css-library.py get <ID> --dependencies`；需要结构时再用 `template` 精确提取。
3. 素材就绪并组装 HTML 时，校核所选实现与最终素材、实际消费者的绑定，落实对应行内声明或内嵌 SVG 及完整依赖；HTML 完成后用渲染确认效果可见。后续修改只回查受影响的实现、依赖与绑定。

CSS catalog、class 名和模板 ID不会在最终页面自动加载样式。所有采用内容必须展开到真实节点；只写名称、注释或 class 不算实现。只有组合经适配仍不适用或确无候选时才转原子组装／自行实现，在验证记录保留具体原因；不能仅凭局部原子绑定声称已复用组合。

## 3. 元素与关系映射

| Brief 内容 | 最终 HTML职责 |
|---|---|
| 章节、页面与重复组 | 按内容关系组织容器；连续长页顶层区段使用唯一 `data-section-id` |
| 准确标题、正文、数字、单位、条件 | Brief 标为 Coding 的内容全部保持真实 DOM 文字，并使用稳定 `id`／`data-layer-id` |
| 图片与背景 | 绑定素材清单中的最终 HTTP(S) 短链或经核验的现有资产短链，按实际主体、安全区和裁切等比显示；具体载体遵循 [图片素材短链契约](../html/coding-rendering.md#图片素材短链契约) |
| 字体 | 在目标文字节点直接写入已验证 family、字重、字号、行高、字距与显式回退栈 |
| 卡片与表面 | 内容层与表面层可分别控制；透明度、模糊和滤镜不得连带降低正文可读性 |
| 图表、标注与路径 | 使用 DOM 或内嵌 SVG；准确文字与数值保持可编辑 |
| 对齐、遮挡、穿插和过渡 | 直接通过 DOM 结构、定位、层级和裁切表达，并在真实预览中核验 |

HTML 必须消费 Brief 的内容、视觉目标、素材职责和图文关系，不能只复制文案后重新发明一套设计。稳定 DOM 标识只用于源内定位，不传作平台 Item ID。

需要角色跨框、物件与文字穿插、材质附着容器时，先建立可独立定位的真实承载层。能由整体图片兑现的关系留在图内；需要在 HTML 中跨层或复用的对象落实为独立素材或原生节点。

## 4. 素材合成与实际测量

- 组装前逐项读取素材清单的最终 `output.uri`。生成／编辑图片在 `<img src>`、`srcset`、行内 `background-image`／`mask-image` 和内嵌 SVG `<image href>` 中只能使用该项已准出的 HTTP(S) 短链；不得把本地文件、相对路径、Base64、Blob、临时预览地址或未经登记的替代链接写入 HTML。
- 图像工具输出可直接使用时保留原始短链；抠图、裁切等处理产生新文件时，以清单回填的最终处理短链替换所有消费者。禁止为了插入 HTML 下载重传或换链；同一资产的重复消费者复用同一短链。
- 新建与编辑中的独立艺术字统一按最终消费者接入：只用于已知、稳定的 HTML 背景时可保留纯色底，深色字体节点使用纯白底＋行内 `mix-blend-mode: multiply`，浅色字体节点使用纯黑底＋行内 `mix-blend-mode: screen`；需要透明导出、跨背景复用、背景未知或严格保色时使用准出的透明 PNG 且不附加混合模式。混合模式仅作用于目标图片节点；其他透明叠加素材继续按自身用途执行原抠图规则。
- 每张图片绑定前读取原素材 purpose 或使用说明中的去底结论与理由，按 [素材使用规范](../style/coding/ai-coding/asset-prompt-guide.md#6-独立素材与图片编辑) 核对实际就绪图；新生成、已生成与复用图均适用。需要去底的必须已有真实处理结果及边缘核验，已有有效透明的无需重复处理，保留完整背景的按场景／图窗职责使用。结论缺失或与文件不符时先补查，不能仅凭清单校验成功进入组装。只绑定清晰度、透明边缘及用途检查通过的最终版本，按实际裁切等比显示；不沿用旧低清或带底版本，不把透明留边当作主体可见范围。
- 背景、主体与信息层按 Brief 中的光向、空间、接触、避让和前后关系组装；图片已经烘焙的光影不重复添加。
- 相邻长图片段作为连接区域处理；同一场景优先共享底图或跨段图层，明确换章则保留有依据的边界。
- 按 [容器内容框、间距与顶边](../style/coding/composition-layout.md#容器内容框间距与顶边) 依次落实可用宽度下的内容排版、所属容器尺寸和相邻组位置，再核对整页范围；根画布固定不要求内部容器统一锁高。
- 调整坐标、字号、层级和裁切时直接修改完整 HTML，并重新检查相关元素及邻近区段；改变主构图、视觉系统或素材职责时返回 Brief。

连续长页的顶层连续区段按视觉阅读顺序设置：

```html
<section data-section-id="hero" style="...">...</section>
<section data-section-id="proof" style="...">...</section>
```

连续长页的上述顶层区段须从画布顶部连续覆盖到独立页尾安全区起点、宽度与画布一致、ID 唯一；收尾安全区单独计量。这里约束区段外框连续性，不要求简历每栏或折页每面填实，也不能证明区段内部没有空洞。按当前脚本实际返回的测量和截图核对，未提供的区段诊断不宣称自动通过；不另填坐标投影来证明连续性。

### 素材就绪后的合成与几何复核

#### 屏间过渡路由（基础方案优先）

先读取 Brief 与对应 Visual 已确定的相邻屏叙事关系。若两端是两张独立完整主图，不进入下表的渐变、mask 或 blend 路线：连续场景必须消费同一母图的延展／连续裁切结果，或让两屏共同消费同一可验证的背景生产单元且主体保持独立；否则退回 Visual 重组。同章推进落实为独立的结构化分隔；章节切换保留明确边界。下表只处理纯色、纹理和图片背景层之间的实际露底接缝，以及图片背景层向纯色／纹理退场；不得用背景算法融合两张完整主图。

Brief 只保存全局默认与例外意图；普通背景接缝的 `from / to` 从相邻 Section 已落实的纯色、纹理或图片背景层推导，不要求逐条填写完整过渡参数。组装时先选择唯一基础路线并锁定首尾，再判断是否需要增强：

| 相邻背景 | 默认基础路线 | 可选增强 | 禁止与回退 |
|---|---|---|---|
| 纯色 → 纯色 | 原生 CSS `linear-gradient` 明确首尾色 | 调整色标、曲线和有效范围 | 不用 blend 代替准确首尾色；失败时简化为双端色渐变 |
| 纯色 → 纹理 | `normal` 纹理层＋局部 mask 渐入，纯色端保持无纹理 | 基础融合不足且允许染色时，仅在中段增加独立 blend 氛围层 | 纹理侵入纯色端或出现色带时撤销增强，收缩纹理显露区 |
| 同色系纹理 → 纹理 | `normal` mask crossfade，两端分别只显示原纹理 | 色相、亮度与纹理尺度兼容且基础融合不足时，使用“端点隔离＋中段局部 blend” | 禁止全段 blend；发闷、压暗或纹理混杂时回退 `normal`／mask |
| 跨色系纹理 → 纹理 | `normal` mask crossfade，优先保留两端原色原材质 | 仅调整遮罩范围与节奏 | 严格保色时禁止 blend；脏灰或偏色时缩短交叠区或保留有职责边界 |
| 图片 → 纯色／纹理 | `normal` CSS／mask 令图片退场并锁定目标端颜色或纹理 | 安全空场内可增加独立中段氛围层 | blend 不得决定终色或影响图片主体；失败时关闭氛围层 |
| 暗场／浅场光效 | 先按以上类型完成基础路线 | 暗场黑底素材可用 `screen`；浅场白底素材可用 `multiply`，均只作装饰增强 | `screen` 黑端不能承担黑色收口，`multiply` 白端不能承担纯白收口；换背景后必须重验 |

执行顺序固定为：识别两端类型与方向 → 建立 `normal`／CSS／mask 基础层并锁定端点 → 调整范围和曲线并先验收基础版本 → 仅在融合不足、素材兼容且允许艺术化染色时加入中段增强 → 与基础版本对照 → 任一门禁失败先撤增强，再修基础路线。产品、文案、按钮、Logo 与证据始终位于独立 `normal` 内容层；不得把 mask、opacity、filter 或 blend 设到它们的共同祖先。所有 blend 增强必须放在独立容器中并设置 `isolation:isolate`，只影响该接缝的装饰层。

仅对非默认、增强或发生回退的接缝，在既有采用／验收记录中紧凑记录 `base / endpointLock / mask / enhancement / forbidden / fallback / qa`；普通 `auto` 接缝记录采用的基础路线和结论即可，不另建过渡参数文件。反向过渡按同一规则镜像处理，不复制一套反向表。


- 新建、整体重排或页尾变化时先按载体处理高度：简历、三折页及其他锁定尺寸作品在原画布内预留品类安全区与 [预览流程](html-preview.md#先测高再锁定画布)规定的唯一 `data-canvas-bottom-safe-area` 正常流收尾区，主体在剩余区域内分配；自然高度仅用于容量诊断，不向纸面外追加安全区或改高。只有允许自然定高的长页才由正文、页尾语义内容与该收尾区的正常流总高确定画布高度。
- Grid／Flex 可以实现已规划的固定纸幅分区，但内容、容器与邻组必须共同适配；不得用空的 `flex:1`、巨大间距或只拉高外壳制造“撑满”。底栏、签名、来源和 CTA 必须有真实占位，不用 `position:absolute; bottom:0` 代替语义页尾的布局。风格装饰可局部定位，但不得与语义内容重叠，且其落在底部不证明主体容量、空区或页尾安全区通过。
- 图片以最终就绪版本和实际裁切为准，等比显示；有意裁切必须保留槽位指定的主体与保护区。不能把透明留边当成主体可见范围。
- 背景、主体与信息层按 HTML 与 Brief 的光向、空间、接触、避让和前后关系组装。复杂折射或已经烘焙的光影使用对应素材，不重复添加；电商／社媒的背景职责与叙事关系由当前品类 Spec／Visual 写入同一自然语言 Brief，具体尺寸、色值、层级与素材消费位置直接落实到最终 HTML，不恢复旧背景生产合同或品类机器字段。
- 背景按 HTML 与 Brief 的实际承载方式落地：色场展开为具体渐变声明，纹理绑定尺度与区域，图片绑定最终资产。颜色令牌只提供配色，不自动生成背景；局部纸面也不自动扩展成整页米色。
- 先按[融合处理](../style/coding/composition-layout.md#图像卡片与背景的融合处理)记录上下段的主关系：空间连续、媒介转换、视觉呼应、独立图窗或明确换章。首屏进入正文本身不等于换章；内容仍在接力时，必须说明读者怎样从 Hero 进入下一段。配色相近不能替代空间或阅读关系，结构错位返回素材步骤，不继续加蒙版遮缝。
- 将首屏底部、正文开头与两者边界作为一个连接区域试排。文字保护区始终保留；只有空间连续且需要边缘融合时才另设无主体、无文字的低细节融合区，媒介转换、视觉呼应、独立图窗和明确换章不为“无缝”强加渐变。首屏图内已有接力文字时，素材生成前就要为其和正文首标题共同预留净空；就绪素材无法满足时返回素材或构图，不用 Coding 覆盖、压暗或加卡片补救。产品识别面、Logo和二维码同样保护。
- 先区分图片退场与颜色变化。图片需要融入共享底图时，优先在安全空场中使用局部 Alpha 从 100% 到 0% 的渐隐，让真实底图与纹理显露；不默认另建 A→B 实色色场，不把“下屏实色→上屏实色→透明”覆盖层当作同等替代。纯色覆盖只能改变表面颜色，不能保证纹理连续；不透明图片下面的渐变也不能令图片退场。独立图窗、媒介转换和明确换章仍保留有职责的边界。
- 渐隐范围由最终素材、实际裁切和上下保护区共同确定，不设固定像素、固定比例或按画布宽度等比换算的默认长度。先把上侧主体／投影／文字的保护边界、下侧内容的保护边界、图像与底图的实际覆盖范围和父层裁切边界投到同一连接区域坐标系；图内文字及投影需结合原图与最终截图确认，不能只用 img 外框代替。只有退场图层与接管底图同时覆盖、无保护对象且未被裁切的连续空场才可用于融合，上下两段各自的空白高度不能直接相加。
- 在上述连续空场内选起点 S、完全透明终点 E 和缓冲长度 B：S 位于上侧保护区之后，E+B 不越过下侧保护区、实际覆盖或裁切边界，且 E>S、B>0。有效渐隐长度为 E−S，Alpha 在该区间由 100% 连续降到 0%，随后 B 范围保持全透明并显露真实底图；可用空场给出长度上限，不要求耗尽。起止、缓冲和曲线在最终 HTML 中按节点本地坐标落实为真实行内样式，不能把页面坐标直接填入局部 mask，也不能只在备注里声称已计算。
- 空场不足时先调整布局或扩展同色同材质的无主体背景，再重新计算；不把起点移入主体、不拉伸原图，也不只增加下段 padding 制造等待区。扩图核对原主体、字标、图内文字和投影保持不变；身份变化不能因过渡更柔和而放行。只调整技术范围时更新 HTML 与验证记录；若改变背景职责、上下段关系或素材设计意图，则回到同一 Brief 更新后再组装。改图、改文案、字体、裁切或层级后，旧边界与截图不再作为当前验收依据。
- 蒙版仅作用于需退场的图像或无文字背景层，主体与准确文字仍处在完全不透明的保护区。共享底图放在共同父层、保持跨段同一坐标和纹理尺度；HTML 记录实际消费者、起止、全透明缓冲、层级及裁切。不得对含文字的共同祖先设置 mask／opacity，也不以整张图片 opacity 代替局部退场；完全透明段之后不能再有覆盖层把底图染暗。
- 只有设计确实要求颜色变化时才单独选用色场，并从关闭待修复覆盖层后的实际上下边缘取色：按左／中／右低细节背景取代表色，避开主体、文字和高光；透明素材先与真实底色合成。来源版本、采样区域与色值留在原实现／验证记录。端点色接近不证明叠加后的颜色或纹理连续；默认不把 blend 叠加到 Alpha 方案，也不加入无依据的黑白中间色、multiply 或实色色带遮缝。只有命中上表增强资格且基础版本对照证明确有净改善时，才保留隔离在中段的 blend 层。
- 在同一版本的最终截图上复查上下端、中段灰雾、纹理显露、主体投影和阅读距离。更长不等于更好；未形成净改善时保留用户已选方案，不持续叠加色层或无限加长。换图、裁切、底色、纹理尺度或范围后重新核验；颜色方案还需重取色。实际画面已有连续光场时不重复添加。
- 过渡仍显硬边时，先检查CSS是否限制有效范围：渐变元素的高度与定位、父层固定高度、overflow:hidden/clip、clip-path和mask边界、background-size/position、伪元素及层叠覆盖。将背景过渡移至共同父层或扩大其覆盖与重叠范围，仅解除截断背景的限制；仍保留整张画布出界裁切及主体、文字保护。不得靠全局取消裁切让内容溢出。接缝需有可连接的背景，两个结构不相接的矩形不能只加同色渐变。
- 背景已包含的光影或过渡不重复添加 CSS。局部融合依据最终裁切边缘，避开设备、产品、桌面结构和文字保护区；不把整张图片降低透明度，不以大面积黑灰／白雾涂层让实物消失。物体轮廓、接触点或材质尺度不连续时，调整素材或构图后重查，不能以边界变模糊判定修好。已就绪的一体化社媒 Hero 作为一个完整图片层落地；先核对图内已包含的标题、小字、主体、容器、装饰和光效，禁止再次生成或叠加对应的DOM文字、CSS面板、图片或效果。只有生成前已明确拆出、且图内已留空的内容才按已冻结 Brief 另行组装；外层定位容器不附加可见底板或装饰。不得用 Coding 覆字或加卡片修补图内错误。图内文字错误须在完成该产物的交付闭环后记录并等待用户提出修改要求，不得自主重生；用户授权修改后，按原编辑权限修正 Hero 并替换整体资产。
- 阴影由实际材质与悬浮关系决定：普通卡片／胶囊默认无外投影，优先用色差、细边或内高光分层；纸张默认也无外投影，真实叠纸接触才用短接触阴影；玻璃靠透底和边缘表现，明确悬浮的实体才加环境投影。先检查图片是否已烘焙阴影，再决定 CSS；不同时叠加图片暗边、渐变黑底、box-shadow 与 drop-shadow。配方的形状不自动启用投影，实际值遵循 [材质参数](../../assets/templates/css/surfaces/materials.md#surfaces.parameters)。
- 字体、文案、宽度或断行变化后，按上述布局定义重算受影响整行／整组及下游位置，原测量值不再作为通过依据。断行与数字单位处理分别引用 [语义完整性](../style/coding/composition-layout.md#断行孤字与语义完整性) 和 [数据组尺度](../style/coding/composition-layout.md#数据组与图注的共同尺度)。局部容纳与相邻净距成立后，若影响整页高度或页尾，再按 [DOM 测高](html-dom-measurement.md) 确定或核对根画布高度；未影响时仅复查受影响范围。用户锁定尺寸内重排，不擅自删减事实。
- 测量后先比较原设计目标与实际结果，再回写断行、几何、裁切、层级与接缝实测值。在既有验收记录保留目标、实际值和未解决差异，不另建几何参数文件；禁止用实际 DOM 全量覆盖原目标后，仅凭“声明与 HTML 一致”判通过。
- 位置或参数调整仍兑现原关系时，更新 HTML 并重查相邻元素；原定环绕变成上下堆放、材质效果不可见、图窗或字形强调消失等属于设计差异，先修复实现。确需更换主构图、视觉系统或素材职责时，按已有授权回到 Brief 或资产步骤说明取舍并同步更新，用户锁定项不得静默降级。

## 5. 输出与检查

输出一个完整固定画布 HTML5 文档。所有准确文字、素材引用、字体、CSS/SVG 和元素关系以该 HTML 为实现事实源。

按 [HTML 检查执行流程](html-validation.md) 和 [预览策略](html-preview.md) 检查：

- 源码完整、样式行内化、SVG 已内嵌；
- 素材可加载，内容满足 [布局验收](html-validation.md#3-视觉与平台复核) 的画布范围、所属内容区与相邻净距要求；
- 连续长页读取 shot.py 的测量与完整截图，未提供的区段诊断不假称已验证；
- 声明尺寸下固定画布和关键元素没有意外偏移；
- 最终截图中的主焦点、图文主次、阅读路径、材质和内容容量符合 Brief。

自动报告只能证明结构和浏览器实测，不证明审美、身份或事实正确。没有实际预览时记录未验证，不以代码完整代替视觉通过。

## 设计效果复核

同时查看完整作品、正常阅读尺度和接缝上下两侧，核对原 Brief 的图文关系、保护区和材质效果。CSS 名称、索引记录或参数存在不能证明效果可见：检查真正的消费者、行内声明、变量、SVG 内嵌、覆盖和后景条件。玻璃必须有可供透底模糊的后景，透明度不连带影响正文；一体化 Hero 已包含的文字、容器、阴影和光效不重复生成或叠加。改变原构图或素材职责时返回同一 Brief，不能降低目标迁就现有 HTML。
