# `interaction.ask` 图片与视频创作文本澄清策略

> 先按主 SKILL 判断交付环境。system 明示 `Device platfrom: Mobile` 时遵循 [Mobile 直接交付](mobile-app-direct-delivery.md)：Brief／素材记录留在本地，跳过本文全部 Workspace、Canvas CLI、Item 与卡片步骤，媒体逐项直接交付、HTML 预览走 CDN＋Markdown。其他环境执行本文默认 Canvas 分支。生产与编辑顺序不变。

> 宿主兼容约定：本文的 `interaction.ask` 表示宿主提供的结构化用户输入能力，而不是要求所有宿主暴露同名工具。若宿主提供 `interaction.ask`，使用该工具；若 Codex 当前模式提供 `request_user_input`，使用该工具并映射等价字段。宿主没有结构化输入能力时，只停止依赖阻塞答案的生成步骤并报告能力缺失，不用自然语言选项模拟工具调用。

## 阶段边界

前置文字澄清只解决产物、真实输入、冲突要求和交付范围，不用文字选项代替视觉方案。所有 HTML 路线先完成前置澄清并创建 Brief，再由品类 Ref 完善自然语言候选 Brief。仅 AI + Coding 路径中新建或整体重做的电商详情页、社媒长图在候选 Brief 完整后进入 [视觉 KV 澄清](visual-kv-clarification.md)；用户选择写回同一 Brief，冻结最终版本后才执行 Brief → HTML。套图默认走 pure-image，以同一轻量 Brief 规划共享系列并逐页生成完整图片；要求可编辑设计或文字时才走 ai-coding，封面与内页均按正常素材生产和 HTML 原生文字组装。两种套图分支均不另生候选 KV。纯生图、纯 Coding 和其他 AI + Coding 品类不进入 KV。

KV 是独立于前置文字澄清的视觉澄清阶段。进入 KV 前必须已经完成品类 Spec、参考解析（命中时）、Visual System 与包含 1–2 个完整候选方向的 Brief，但此时不得先执行 正式素材清单。实际 KV 通过普通对话确认；确认结果先回写 Brief 并消除方向歧义，随后冻结最终 Brief，再执行结构化转译。反馈改变设计方案时先更新候选 Brief，必要时重做 KV。

## 目的与原则

本策略用于图片创作、图片编辑、视频创作和视频编辑。在提出视觉方案、调用生成工具或开始高成本实现前，先判断是否存在会导致错误产物、事实编造、无效生成或明显返工的阻塞信息。

核心原则：

1. 只澄清阻塞当前执行的决策，不做完整需求问卷。
2. 已经明确的信息不重复确认；可安全默认的非事实信息由 Agent 决定。
3. 先确定生成什么产物，再讨论视觉方向；产物未定时不生成、不排版。
4. 硬性阻塞的前置文字澄清、完整候选 Brief 后的 KV 视觉澄清和最终消耗确认是不同阶段，不能混在同一个问题里；高成本本身不构成前置澄清理由。
5. 区分“用户必须提供的真实输入”与“允许 Agent 创作补齐的传播文案”。人物或产品身份素材、真实 Logo、真实二维码、可实际访问的链接和真实联系方式不得伪造；营销标题、栏目词和非事实传播文案可按授权创作；真实日期、价格、功效、数据、资格和业务承诺须来自用户或可核验资料。可另拟待确认业务文案草稿，不能把“继续执行”或未回复视为允许虚构事实；明确虚构／演示内容须与真实证据区分，遵循 [内容事实边界](../style/shared/content-truth.md)。
   - **简历专用覆盖**：主场景命中简历／履历／CV 后，候选人的公司、职位、日期、职责、结果、数据、学历、奖项、资格、证书、技能、客户、项目、联系方式和链接全部属于真实履历事实，即使用户说“帮我补齐”或“继续做”也不得生成。Agent 只可生成栏目名、页码、索引和其他 `layout_label`；事实缺失且会影响成品时必须澄清。
   - **Logo／VI 专用覆盖**：品牌准确名称、大小写、语言、行业、既有 Logo、权利状态、允许修改范围和真实品牌资产不可推测；从零创建的新 Logo／VI 可标记为 `agent_generated`，但不得声称已注册、无侵权或已取得授权。
   - **通知／喜报专用覆盖**：主体姓名、事项、结果、奖项、排名、日期、时间、地点、发布方、联系方式和真实入口属于事实字段，不因用户授权代写而允许虚构；缺失且影响成品时必须澄清或从画面删除。
   - **菜单专用覆盖**：真实营业菜单的菜名、分类、价格、规格、食材、份量、产地、过敏原、饮食标签、热量、优惠和营业规则属于事实字段，不得根据菜名或图片推测；缺失价格可以保留明确草稿位置，但阻断真实营业成品交付。
   - **个人名片／会员及权益卡专用覆盖**：姓名、头衔、联系方式、会员等级、卡号、权益、金额、期限、兑换／使用条件和真实入口属于身份或交易事实，不得推测；演示值必须明确标记，不能冒充有效凭证。
   - **思维导图专用覆盖**：用户材料中的节点、观点归属和关系依据必须忠实保留；Agent 可在获准创意发散时生成并标记 `agent_generated` 内容，但不得把推导关系冒充原文结论。
6. 一旦判断需要澄清，必须调用 `interaction.ask`；不得用普通文本、Markdown 列表、自然语言选项或结尾问句代替工具调用。
7. 澄清只进行一次分流，不形成反复追问链。用户出现“文案你来设计”“帮我补齐”“你来安排”“按主题发挥”等相关意图，或在收到澄清后未提供非功能性文案而明确要求继续，即视为授权 Agent 进入执行并默认补齐。

## 生成前的澄清检查

在任何图片／视频生成、编辑或 KV 前，内部检查 `clarification_gate_passed`：当前产物路线已确定；影响事实、素材、内容结构、数量规格与交付范围的必要问题已经明确；需要提问时已用当前宿主可用的结构化澄清能力取得答案并回写同一 Brief。未通过时只停止依赖答案的步骤。

需要澄清时，一次盘点并尽可能收齐当前阶段已知的必要事实与约束，不重复询问已有答案或安全可默认的偏好。进入 KV 后通过实际图片和普通对话确认视觉方向，不再用文字选项替代视觉方案。保持原 KV 适用品类，套图不新增候选 KV；简历继续按真实资料是否充分判断，不新增必须上传附件或必须选择 CSS 风格的门禁。

## 总决策流程

实际创作产物进入本流程前，先服从主 `SKILL.md` 的“设计 Brief 前置门禁”：新任务创建 Brief，连续轮次定位并更新原 Brief，将当前上下文先写入。澄清可以暂时把未知项标为待补，但读取品类 Ref 前必须已经在同一 Brief 中明确主题与商品；没有实体商品时记录“不适用”及实际核心对象。

按顺序执行：

1. 用户是否只要方案、提示词、脚本、分镜或建议？
   - 是：交付文本方案，不调用生成工具，也不做消耗确认。
   - 否：继续。
2. 主要产物是否已确定？
   - 否：用 `interaction.ask` 在可执行的产物类型之间澄清。
   - 是：记录产物类型、执行路径和品类，继续。
3. 是否缺少不可替代的真实输入或功能性资产？
   - 是：只询问缺失的身份素材、编辑目标、真实品牌资产或可实际使用的入口；这些内容不可由 Agent 伪造。
   - 否：继续。
4. 是否缺少传播文案？
   - 简历场景缺少候选人事实：只生成 `layout_label`，其余缺失事实一次性澄清；简历候选人事实永不进入该补齐分支。
   - 是，且用户已授权代写、要求继续，或澄清后未提供：Agent 按主题、L3 场景和排版角色补齐，标记 `source=agent_generated`，继续执行。
   - 是，且文案内容会实质改变用户业务承诺、法律责任或交易结果：一次性澄清；用户要求继续时可给待确认草稿并推进独立设计，真实业务事实仍须按共同事实边界核验，不能用假设冒充已确认内容。
   - 否：继续。
5. 是否存在硬性阻塞？
   - 是：无论成本高低，只澄清不可替代的真实输入、互相冲突的要求、无法判断的主要产物或无法执行的交付范围。
   - 否：继续。
6. 是否属于高成本生成？
   - 否：低成本任务除硬性阻塞外不澄清；采用安全默认值并直接执行。
   - 是：继续检查高成本澄清条件。
7. 是否同时满足 AI + Coding、新建或整体重做，以及电商详情页或社媒长图之一？
   - 是：只记录“品类 Ref 完成候选 Brief 后执行 KV 视觉澄清”；当前前置文字澄清阶段不生成 KV，也不先执行 HTML 结构化转译。
   - 否：不进入 KV 流程。社媒套图不生成候选 KV。
8. 其他高成本任务是否仍有无法执行的数量、长度、规格或内容结构缺口？
   - 是：只澄清缺失的执行参数，不附带视觉方案选择。
   - 否：沿用户参考和合理默认值直接执行。

所有路线的文案扩写均受 [共同内容与事实边界](../style/shared/content-truth.md) 约束；下文补齐规则不授权伪造真实业务承诺或健康数据。

## 先确定三类主要产物

先按主 `SKILL.md` 确定路线。普通海报和未要求可编辑的单张社媒封面进入 pure-image；单张封面明确要求文字或设计可编辑时按通用可编辑单页策略进入 ai-coding，读取 `generic-visual-fallback.md`，不套用套图页链。通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图不属于普通海报，默认进入 AI + Coding。社媒套图默认 pure-image，读取现有纯图平台 Ref 与 pure-image-sequence，在同一轻量 Brief 中先规划完整系列再逐页生成含封面在内的完整图片，不读取 Coding Spec／Visual。用户要求可编辑设计或文字时，套图进入 AI + Coding，才读取 Coding 套图 Spec／Social Visual，封面与内页共用同一完整 Brief 与素材清单，按正常素材生产、HTML 原生文字组装与 DOM 检查执行。仅指定局部可编辑时，该区域必须原生排字，封面不例外；非目标区域可沿既有艺术标题准入规则，真实照片内标签不必重画。不主动增加制作方式澄清，只有真实冲突才澄清。连续长图与详情页默认生图＋Coding，不因泛称“生图”整体改道；用户明确要求全部由图像模型生成且不要 HTML 排版时，可锁定 pure-image，目标高度／宽度 > 16／9 时分段生成后拼接。路线锁定后，下游 Ref 不重新分流。连续任务沿已确认路线与授权范围编辑，已有 HTML 源始终保持完整 HTML；真实既有资产缺失仍阻断身份衍生。

“明确指定生图”按主 `SKILL.md` 的“产物要求与制作方式”判定。“生成一张”、单张成品或最终图片交付要求本身不构成路线覆盖，也不因此追加制作方式澄清；沿用品类默认值，连续任务则沿用已确认路线。仅当用户明确指定制作方式时应用覆盖，不能在澄清阶段把普通产物表述重新解释为纯生图要求。

### A. 纯 Coding 生成

- 特征：文字、数字、图表和规则化排版为主，强调信息准确、动态更新和批量生成。
- 常见：数据看板、分析型财报／销售数据战报、趋势图、排行榜、参数对比、套餐价目、时间轴、路线图、甘特图、组织架构、课程表、日历、自动化周报、比赛数据、社交媒体数据卡。这里的“战报”以筛选、比较、趋势或多图表分析为主体；单张传播型成果战报属于公告海报，走 AI + Coding。
- 主要交付：服从主 `SKILL.md` 已锁定的生产路线，可编辑作品默认以完整固定画布 HTML/CSS 为源；已有完整 HTML 编辑保持原完整源，不因输出格式或交互要求重新路由。获准的 Logo／VI 自由路径、复杂布尔、自定义曲线或轮廓字形需求按品类 Spec 使用 HTML 内嵌 SVG，不另立生产路线。预览、画布交付及用户另需的媒体导出沿当前环境的交付协议执行。
- 澄清重点：数据源、字段、状态、交互、更新方式、响应式范围和导出要求。

### B. 分图层 Coding + AI 生图

- 特征：信息密度高并要求较强设计感；文字必须准确且可修改；需要多尺寸、印刷或画布分层编辑。
- 常见：折页、宣传册、商品详情页、招聘/活动/公众号/小红书长图、菜单、个人名片、会员／权益卡、思维导图、产品/品牌手册、楼书、旅游攻略、课程介绍、操作指南、学术海报、展会背板、易拉宝、包装版面。
- 品类默认与用户覆盖只服从主 `SKILL.md`：详情长图、信息长图、社媒长图、明确要求文字或设计可编辑的单张社媒封面、明确要求可编辑设计或文字的社媒套图、通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图、三折页、菜单、简历和 VI 系统化页面进入本类；从零 Logo 母版、上述公告海报家族之外的普通海报、未要求可编辑的单张社媒封面及未要求可编辑的社媒套图走纯生图。单张可编辑封面读取通用视觉兜底，不套用套图 Spec；可编辑区域的文字必须原生实现。已有 HTML 编辑沿原路线，不用本段重新路由。
- 实现与交付：内部实现使用 [完整固定画布 HTML/CSS](../html/coding-rendering.md)。同尺寸完整预览图上传 CDN、核验公网链接并以 Markdown 图片展示；预览截图不创建 IMAGE Item、不调用 `present_files`。默认 Canvas 环境再上传完整 HTML、创建顶层 HTML Item 并 `+get` 回读，将 `<workspace_id>?item_id=<item_id>` 作为单值传给 `present_files` 输出对应画布卡片；Mobile 环境到预览展示即止，不上传 HTML、不执行 CLI 或 Item／卡片步骤。不得创建 HTML Frame、粘贴 HTML 或直接 `present_files` 交付 `.html`。复杂自由路径可内嵌 SVG，不接受自定义 Canvas 协议或 JSX。浏览器无法稳定表达的效果须预处理为已核验图片资产。
- 澄清重点：画布尺寸、页面/画板数量、可编辑字段、信息层级、AI 素材清单、印刷或导出规格。
- 执行：把生图工具当作素材生产器。依次完成需求与按需文字澄清 → 唯一 Brief 建档 → 品类 Ref 逐步补全候选 Brief → 适用品类执行 KV 视觉澄清 → 冻结最终 Brief → 建立轻量素材清单 → 按清单生图并回填 → 直接编写完整 HTML → 从真实 DOM 提取结构、文字、字体、几何与资产绑定 → 预览 → 上传 → 顶层 HTML Item → 回读。只为 Brief 明确准入的首屏／首图主标题或每个独立图片唯一最重要大标题生成艺术字；其他标题包括普通 H1 使用真实文本 DOM。

### C. AI 原生视觉生成

- 特征：图像工具直接输出最终成品，不再进行 Coding 排版。视觉氛围、摄影和艺术表达是默认常见场景；用户明确要求“全部由图像模型生成、不要 HTML 排版”时，可覆盖通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图、长图和详情页的默认路线。单一 Logo 母版本来属于 pure-image，不是覆盖对象；Logo 系统与 VI 系统整体保持 AI + Coding，其中 Logo 母版可生成或复用。超出上述覆盖范围的制作方式要求若与交付要求冲突，交由主流程澄清具体冲突，不在本文件新增纯图授权。社媒套图默认 pure-image，先按共享系列计划逐页生成完整成品；要求可编辑设计或文字时由主路由选择 AI + Coding，封面与内页均按图片素材＋HTML 原生文字制作。文字密度和图数本身不取消已获准的纯图选择，但不能把生成式文字与图形声明为已保证准确。
- 常见：品牌海报主视觉、产品宣传图、产品棚拍/场景图、食品/时尚/人物/美妆/珠宝摄影、建筑/室内效果图、绘本、电影/专辑/书籍封面、角色、游戏场景、插画、3D 和超现实艺术。
- 主要交付：PNG、JPG。
- 执行：确定产物与必要参数后，跳过视觉提案，按产物数量、真实依赖和原交付门禁调用图像工具生成用户可下载交付的最终图片。默认纯图套图读取现有 pure-image 平台 Ref 与 [页序、分段与拼接](pure-image-sequence.md)，先在同一轻量 Brief 中规划共享视觉、完整页链与逐页文案，再生成封面及内页完整成品，不读取 Coding Spec／Visual。不要先做 Coding 版，不要把结果定义为素材或提案，也不要在生成后自动抠图、拆层、添加 Coding 排版或任意二次处理；已获准的纯图长页按该流程分段生成并拼接，不限于电商，也不改变 pure-image 路线。

### 分类规则

- 分图层产物固定使用完整 HTML 作为唯一可编辑作品源。同尺寸完整预览图上传 CDN、核验公网链接并以 Markdown 图片展示；预览截图不创建 IMAGE Item、不调用 `present_files`。默认 Canvas 环境再上传完整 HTML、创建顶层 HTML Item 并 `+get` 回读，将 `<workspace_id>?item_id=<item_id>` 作为单值传给 `present_files` 输出对应画布卡片；Mobile 环境到预览展示即止，不上传 HTML、不执行 CLI 或 Item／卡片步骤。用户明确要求浏览器交互时仍使用本 HTML 协议，但交互不得改变固定画布尺寸，且静态打开时核心内容必须完整可见。
- 先用品类确定默认路线，再按用户明确要求覆盖；准确文字和可编辑性要分开判断。用户指定生图并提供准确源文字时不自动改道；同时要求纯位图无法保证的功能或独立图层时，只澄清该冲突。
- 混合需求选择一个主要交付；生图输出需拆为素材、与独立文字／图形进行 Coding 排版时属于 B。C 可以直接交付完整生成图；已获准的纯图长页按纯图长页流程连接完整分段位图仍属于 C，不因拼接改道。
- 用户描述已明确对应某类时直接分类，不让用户重复选择。
- 只有不同分类会实质改变交付时才提问；选项必须说明交付形式和差异。

## 必须澄清的情况

以下属于硬性阻塞，出现任一情况时使用 `interaction.ask`：

- 缺少不可替代的真实输入：必须保持的人物或产品身份、指定编辑目标、版权图片、真实 Logo、真实二维码、真实联系方式或必须可访问的链接。
- 任务要求围绕同一商品、品牌或 Logo 生产衍生物料，但核心母版缺失、存在多个冲突版本、无法确认哪一个是权威版本，或必须保持的身份特征不清楚。
- 缺失内容会构成真实业务承诺、法律条款或可执行交易条件，且用户没有授权 Agent 假设或代写。
- 横版/竖版、写实/插画、静态/视频、单图/分层等要求互相冲突。
- 必需的上传图片、产品原图、首尾帧、人物参考、品牌资产或数据文件缺失。
- 主要产物无法判断，且不同选择会改变交付格式或实现路径。
- 没有安全默认值，任一选择都会明显改变核心结果。

以下不是硬性阻塞：

- 主观风格词本身不是硬性阻塞。Agent 先结合用户参考与品类 Ref 在候选 Brief 中形成 1–2 个可执行方向；适用品类需要 KV 时，用真实 KV 完成视觉澄清，再把唯一采用方向写回最终 Brief。
- “一套、几张、多个版本、批量、系列”等表述仅在无法确定可执行数量或版本差异时构成高成本信息缺口，不因关键词本身自动澄清。
- 进入视频或其他高成本任务不自动触发澄清；先检查信息完整度和视觉方向分歧。

## 不应澄清的情况

以下情况直接执行：

- 单张普通图片的主题、用途和视觉要求已经充分明确。
- 高成本任务的信息明确、详尽且可执行；指定品类仍按视觉 KV 门禁执行。
- 缺失项可用稳定行业默认值解决，且不是事实、身份或数量。
- 用户已在上下文中回答过相关问题。
- Agent 可以自主决定的非核心细节，如轻微光线、装饰、常规留白或安全裁切。
- 已有唯一、可读取且经用户提供／事实验证／用户确认的核心母版，并已明确其身份不变量与允许变化；此时直接建立核心资产锚点并进入 `image_edit`，不重复询问。
- 用户当前只要方案、提示词、脚本、分镜或建议。
- 缺失信息不影响当前阶段，例如此刻只做信息架构，不需要最终摄影素材。
- “有更好，没有也能做”的偏好项。
- 用户已表达“文案你来设计”“帮我补齐”“你来安排”“按主题发挥”等代写意图；Agent 可以补非事实营销标题、栏目词、过渡句、解释文案和不依赖虚构入口的 CTA。真实日期、价格、奖项、功效、数据、资格、交易规则和业务承诺仍须来自用户或可核验来源。
- 已进行一次澄清，用户未提供非功能性文案但明确要求继续；采用可见、具体且与主题一致的设计假设，标记 `source=agent_generated`，不再次追问。

## 三类澄清方法

### 1. 风格信息处理

记录用户风格词、参考图用途、必须继承特征和可探索范围，不把抽象风格词转成文字视觉选项。只有要求彼此冲突且无法执行时才澄清冲突；适用品类在完整候选 Brief 后、最终 Brief 与素材清单 前进入真实 KV 视觉澄清。

### 2. 缺少核心信息

先判断缺失项属于“真实输入”还是“可创作文案”。只有缺少真实输入会阻塞；可创作文案优先询问一次，用户授权代写、要求继续或未补充时直接由 Agent 补齐。例如：

- 活动海报：真实活动名、主办方、日期、地点、票价和实际报名入口属于真实输入；可在授权后补非事实传播标题、栏目词与行动文案。
- 产品宣传：必须保持的产品原图、真实 Logo、产品名、价格、功效与促销条件属于真实输入；可在授权后补不改变真实承诺的卖点表达与 CTA。
- 人像/人物：身份特征、是否需要保持本人、服装或场景限制。
- 信息图/教程：准确文案、数据来源、步骤与顺序。
- 图生图/产品图：哪张是 edit target，必须保持哪些身份特征，允许改变什么。
- 视频：时长、比例、镜头数量、首尾帧、角色和字幕/配音要求。

### 3. 数量与规格不明确

选项应同时写明数量、内容结构和成本影响。例如：

- 1 张纯图封面：生成包含文案与主视觉的完整成品，成本最低。
- 4 张基础纯图套图：共享系列规划下的 1 张完整封面与 3 张完整内页，场景／细节按页面职责分配。
- 6 张完整纯图系列：先规划完整页链，再以主视觉、场景、细节和不同构图形成 6 张完整页面，生成成本更高；不因此增加 KV。

“做几个版本”必须澄清版本数量以及每个版本改变什么；不要只问“要几张”。

## 高成本生成与消耗确认

以下默认属于高成本：

- 所有视频生成、视频编辑和图生视频。
- 多镜头、长时长或多段视频。
- 系列图、批量图、多版本视觉方向或大量变体。
- 单个社媒长图。
- 单个电商详情页。
- 高分辨率复杂处理、批量抠图/修复/产品图编辑。

### 1. 指定品类的视觉 KV 澄清

仅已锁定 AI + Coding 的电商详情页、社媒长图新建或整体重做，在品类 Spec、参考解析（命中时）、Visual System 和完整候选 Brief 均完成后，才读取 [视觉 KV 澄清](visual-kv-clarification.md)，生成 1–2 个真实完整 KV；已获准的 pure-image 长页不进入此阶段。不得用文字 A/B/C、Moodboard 或色板代替，也不得先执行正式素材清单。候选实际图片上屏后停止后续生产，通过普通对话取得确认；确认结果写回同一自然语言 Brief，保留版本记录并收束为唯一采用方向，冻结后建立轻量素材清单、完成素材生产，再直接编写最终 HTML，不恢复品类机器计划或旧合同。用户反馈改变设计方案时先更新候选 Brief，再按 KV 流程处理；不得因图内文字错误自主重生。

### 2. 其他高成本任务的范围确认

高成本本身不触发视觉方案选择。仅在数量、长度、规格或内容结构缺失且阻塞执行时确认相应参数；信息明确时直接执行。

### 3. 最终生成确认

当任务实际调用的平台或高成本生成工具要求消耗确认时，先用普通文本展示内部计划中已经锁定的最终参数：

- 最终产物类型和交付格式。
- 数量与逐项内容。
- 尺寸、比例、分辨率或视频时长。
- 同一自然语言 Brief 中已确认的视觉方向和必须保持的元素；不要求填写或展示 `selected_visual_route` 等旧品类机器字段。
- 将使用的新建或编辑输入素材。

尚未进入 KV 视觉澄清时使用单独的一题确认；KV 候选已上屏后遵循平台原生授权机制或普通对话：

- 问题只表达“是否按以上参数开始生成”。
- 选项只有两个：`按要求生成`、`暂不生成`。
- `multi_select: false`。
- 不在这一题中提供修改方向、其他选项或自由组合。

确认只对展示过的最终参数有效。数量、内容、规格或方向发生变化后，旧确认失效，必须重新展示并确认。若平台或工具没有独立的消耗确认要求，且需求已经明确完整，不额外制造确认步骤。

## `interaction.ask` 编写规范

每次普通澄清控制在 1–4 个问题，并按以下优先级排序：

1. 核心事实与必需素材。
2. 产物类型和内容结构。
3. 会改变视觉结果的互斥方向。
4. 数量、比例、分辨率和导出规格。

每个问题遵守：

- 一个问题只解决一个决策。
- `question_id` 使用 snake_case，最多 64 字符，且在同次调用中唯一。
- `header` 简短，最多 12 个字符。
- `display_message` 说明为什么当前信息会阻塞执行。
- 提供 2–4 个互斥、可执行、结果导向的选项；不要自行添加“其他”。
- 只有选项可以兼容组合时才使用多选；方向、比例、媒介、是否生成通常是单选。
- 仅当选项无法覆盖且自由输入不会导致失控时允许自由输入。

## 澄清输出规则

### 需要澄清时

- 当前轮必须调用 `interaction.ask`，并把所有阻塞问题放进该工具调用。
- 不得在工具调用前后重复输出同一问题，也不得先用普通文本询问，再补一个工具调用。
- 除指定品类的实际 KV 展示与最终参数展示外，不额外输出长篇需求复述、方案解释、免责声明或“请确认”等提示；阻塞原因写入工具的 `display_message`。
- 一次调用集中处理 1–4 个当前已知的阻塞问题。不要明知还有阻塞项却逐轮单题追问；也不要把非阻塞偏好塞入同一次调用。
- 如果宿主的结构化用户输入能力不可用或调用失败，不得用普通文本选项模拟工具调用。停止依赖该答案的生成步骤，并明确报告能力不可用或调用失败。

### 高成本生成确认时

- 指定品类按视觉 KV 规范展示实际图片并在普通对话中等待确认；进入该阶段后禁止再次调用澄清工具。
- 尚未进入视觉阶段时，先展示已锁定的最终参数，再按平台要求单独确认消耗。

### 用户回答后

- 将工具返回值并入已有上下文，并立即增量回写当前任务的同一份设计 Brief，再继续下一步；不要重复询问、再次复述全部答案、另建设计 Brief 或要求用户用普通文本确认。
- 如果答案改变了数量、规格、方向或素材范围，重新计算执行参数；仅在尚未进入视觉阶段且仍存在新的阻塞问题时再次调用 `interaction.ask`。
- 用户选择“暂不生成”时停止生成，不把停止解释为同意，也不擅自执行低成本替代方案。
- 用户没有补充非功能性文案但表达继续执行时，将缺失项转为 `agent_generated`，记录主题、L3、版式角色或用户意图作为生成依据，直接进入 Brief；不得再次追问同一项。

### 不需要澄清时

- 不调用 `interaction.ask`，不输出形式化确认问题，直接执行用户请求。
- 可以简短说明采用的安全默认值，但不得把说明写成需要用户回答的问题。

## 默认值边界

视觉与交付默认值只有同时满足以下条件才能采用：

- 不是事实信息或身份特征。
- 默认后仍可交付可用结果。
- 有稳定行业惯例或上下文依据。
- 不违背用户已表达的偏好。
- 不显著增加生成成本。

不得默认或伪造：

- 必须保持的人物或产品身份、指定编辑目标、真实 Logo、真实二维码、真实联系方式和必须可访问的链接。
- “一套”“批量”“多个版本”的数量。
- 高成本生成参数。
- 人物或产品必须保持的身份特征。
- 没有上下文依据的互斥视觉方向。

进入执行后默认可以补齐：

- 用户明确要求 Agent 设计、扩写、补齐或自由发挥的非事实营销标题、栏目词、过渡句、解释文案、情绪文案和不依赖虚构入口的 CTA；不得把此授权扩展到真实日期、地点、价格、规则、功效、数据、奖项、资格、福利或交易承诺。
- 已澄清但用户未提供、同时又明确要求继续的非功能性文案。补齐内容必须具体、能承担信息层级或排版角色，并标记 `source=agent_generated` 与生成依据。
- 缺失真实入口时，改用“私信咨询”“到店了解”等不依赖虚构联系方式、二维码或链接的 CTA；不得生成看似可用但实际无效的入口。

## 禁止事项

- 为了形式完整而询问与执行无关的信息。
- 把完整需求表一次性丢给用户。
- 重复询问已经回答的内容。
- 用抽象形容词作为选项。
- 把 Agent 补齐内容伪装成用户输入、已核验事实或外部来源；或不记录 `source=agent_generated` 与生成依据。
- 伪造人物/产品身份素材、真实 Logo、二维码、联系方式或可访问链接。
- 在普通澄清问题里夹带“是否开始生成”。
- 在前置文字澄清中提供视觉多方案，或在品类 Ref 尚未完成候选 Brief 时提前生成 KV。
- 向用户暴露视觉系统编号、Scene ID、图层参数、生产轨道或其它内部实现字段。
- 未展示最终参数就进行高成本确认。
- 确认后静默改变数量、规格或视觉方向。
- 产物类型未确定就先做视觉提案、排版或生成。
- 判断需要澄清后，改用普通文本、Markdown 选项或其他问答方式绕过 `interaction.ask`。
- 在 `interaction.ask` 前后重复问题，或在等待工具回答时继续生成。

## 最短执行口令

> 前置文字阶段只处理阻塞执行的输入、产物、冲突与范围，不提供视觉多方案。先创建唯一 Brief，并用对应品类 Spec、参考解析和 Visual System 完成候选版本。仅 AI + Coding 下新建或整体重做的详情页、社媒长图进入真实 KV 视觉澄清；上屏后停止后续生产，确认结果写回 Brief。随后冻结最终 Brief；AI + Coding 建立轻量素材清单并完成素材生产，pure-coding 则直接进入完整 HTML。其他任务不因高成本自动进入。
