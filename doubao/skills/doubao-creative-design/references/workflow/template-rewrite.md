# 模板／既有设计编辑规范

> 先按主 SKILL 判断交付环境。system 明示 `Device platfrom: Mobile` 时遵循 [Mobile 直接交付](mobile-app-direct-delivery.md)：Brief／素材记录留在本地，跳过本文全部 Workspace、Canvas CLI、Item 与卡片步骤，媒体逐项直接交付、HTML 预览走 CDN＋Markdown。其他环境执行本文默认 Canvas 分支。生产与编辑顺序不变。

本文件只负责模板编辑的**授权边界、源文件保护和流程分流**：判断什么能改、什么必须保留，以及采用局部编辑还是重建。最终图片或完整 HTML 源都是编辑底稿，不是普通风格参考。

可见布局、字形、色彩、材质和成像的观察与继承目标统一由 [参考图解析与继承](../style/coding/ai-coding/reference-analysis.md) 承担。本文件不重复视觉分析；参考解析也不得扩大本文件确定的修改权限。

## 1. 建立模板编辑合同

先读取 `references/workflow/clarification-strategy.md`，再实际读取模板源、已有渲染、用户要求和可用资产。在同一份自然语言 Design Brief 的“模板授权边界”中写清：源文件与渲染依据、哪些内容必须保留、哪些文字／图片／数据获准替换、哪些容器可为新内容有限适配、哪些对象禁止修改，以及不受影响、必须回归核对的区域。

这段自然语言授权说明是编辑权限的唯一事实源。用户没有授权的项目默认锁定；只有整体版式、背景或多数元素明确变化时才做整屏或整页重建，否则只做局部修改。重建表示更换实现方式，不表示放宽修改范围，也不要求另建 YAML 合同或参数清单。

## 2. 读取与分流

1. 有完整 HTML 源时，优先读取 DOM 结构与实际渲染。局部修改只建立受影响区域及相邻关系的视觉基线；不得为“分析完整”而重建全页。
2. 只有最终图片且需要重建为可编辑 HTML，或任何任务需要从可见设计恢复布局／风格时，强制读取 [参考图解析与继承](../style/coding/ai-coding/reference-analysis.md)：先过滤水印、截图 UI、平台按钮、黑边、账号名和 AI 角标，再把 11 维底稿、逐块图文绑定、七类同源机制与六步重建方案写入同一份自然语言 Design Brief。模板授权边界作为其唯一权限来源。
3. 只有出现以下任一触发条件时才重新处理受影响字体：新文案包含原字体无法提供的字形，新文案造成异常换行或版式失败，原字体资源在目标环境不可用，或用户明确要求换字体；未受影响的字体与文字区域保持原样。触发后先从 [字体推荐入口](../rendering/font-recommendation-list.md) 保留模板字形与角色约束，以真实新文案试排候选；`scripts/runtime/select_fonts.py` 只提供候选、缺口和诊断，不证明资源可用。目标仍为正式 HTML 时，再按 [字体资源与执行契约](../rendering/font-family-library.md) 核验实际 family、face、weight／style、许可、目标字形覆盖和 Web 加载，通过后写回完整 HTML 并用 `shot.py` 检查实际字形、换行、基线与溢出；用户锁定精确字体或关键字形而门禁失败时必须请求确认，不得静默替换。目标仍为 pure-image 时只借用视觉建议，不进入 HTML 字体资源门禁。
4. 有完整 HTML 源时按原生产类型转入 `editing/pure-coding.md` 或 `editing/ai-coding.md`，保留未授权区域；只有图片且要求重建可编辑 HTML 时，按主路由进入 `creation/pure-coding.md` 或 `creation/ai-coding.md`，把图片作为继承参考和授权边界，不假定存在可编辑源。只编辑位图时进入 `editing/pure-image.md`。HTML 读取 `references/html/coding-rendering.md` 与 `references/cli/README.md`；涉及品类职责或物理结构时读取对应 Spec。

## 3. 执行边界

1. 反复承载商品、人物、品牌或 Logo 身份的资产，先确认权威版本并登记到 `/core-assets/<语义名>/master`；模板截图或低清预览不得充当母版。衍生物通过 `image_edit` 生产并记录 `derived_from_core_asset_id`。
2. 电商局部改字默认只修改用户明确点名的文字，以及为容纳新文字所必需的最小排版范围；优先调整目标文本的换行、文本框尺寸与局部间距，不能借改字重做商品、背景、其他卖点或全局风格。若最小范围仍无法容纳，先说明会影响哪些相邻对象并取得确认，再扩大编辑范围。
3. 已有 HTML 或可编辑源中的价格、SKU、规格、日期、单位、促销／服务条件保持为原生可编辑文字；Logo、二维码和 CTA 保持为独立可替换对象。未获明确授权时不得改变这些对象的内容、含义或功能，也不得将它们随商品、背景或壳体烘焙进图片。Logo 与二维码不为满足“可编辑”而重绘。只有扁平图片时如实说明无法保留原生可编辑性：用户要改最终图则沿纯图片局部编辑边界处理，用户要恢复独立编辑能力则先确认重建范围，不静默切换路线。
4. 其他获准内容优先进入已有文本框、数据位置与图片位置。空间不足时，只能在 `adaptable` 范围内凝练文字、调整容器或复用同类组件；无法容纳时返回具体冲突。
5. 参考解析可把必须保留项和可适配项转成可观察、可验收的目标，但不能自行放宽授权，也不能新增可替换项。
6. 修改后回读源与实际渲染，检查溢出、遮挡、错层、字体、资产及 `untouched_regions` 回归，最终执行 `references/workflow/validation.md`。

不得把模板当背景图后另起一套设计系统；不得用截图覆盖可编辑内容；不得覆盖用户源文件。
