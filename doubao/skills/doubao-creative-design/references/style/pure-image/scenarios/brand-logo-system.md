# Logo 系统

> 内容补写统一遵循 [共同内容与事实边界](../../shared/content-truth.md)：创意表达可补写，真实业务／健康／身份事实不能因版式需求伪造；下文扩写示例仅在此边界内适用。

> 适用范围：仅供已选 `pure-image` 的任务读取。品类／平台规则在前，模型改写在后，见 [纯生图读取路由](../../../workflow/creation/pure-image.md#品类-ref-路由) 与 [指令合同及模型接力](../prompt-guide.md#14-产物知识与模型改写接力)。本 ref 不决定生产轨道、工具字段、Workspace、串并行或交付；这些全部服从宿主原 workflow 与 [交付门禁](../../../workflow/image-generation-delivery-gate.md)。用户指定数量、原文、参考身份和编辑范围优先于默认建议。


## 主 Skill 路由适配

本文的设计推演与示例仅提供画面知识；Prompt 的详细程度和最终表达服从已选择的模型改写 ref，局部编辑始终服从宿主保留／改动合同。事实来源、澄清工具和停止条件服从宿主原澄清策略。

本 ref 只提供 Logo 系统的产物规则。被 `doubao-creative-design` 路由调用时，工具协议、澄清轮次、核心资产记录和 prompt 总规则以主 `SKILL.md` 为准；本文件只补充 Logo 主版本、变体、规范页和文字门禁。

## 概述

Logo 系统是纯生图产物 reference，只解决品牌识别标志本身的建立、优化、变体延展和规范化，不生成无关 IP、包装、海报或完整 VI 手册。

涉及角色／物件 Logo、角色与品牌名锁定、字标描边、贴纸边、身份容器或背景处理时，必须完整读取 [Logo IP 角色、字标描边与背景处理参考](../../shared/logo-ip-wordmark-background-reference.md)。本文件把共享机制编译进每张 Logo 的 `design_brief`，不复制参考样本的具体品牌资产。

每张角色／字标 Logo 的 `design_brief` 必须把线条风格写成可观察结构：线重、端点、转角／曲率、闭合与开口、黑白节奏和表面完整度至少各有明确选择。可用“粗圆等线卡通＋受控稚拙”“胶管式连续曲线”“粗轮廓＋大留白”“黑白块面卡通”或“干净骨架＋轻微丝网油墨颗粒”等组合，不得只写“可爱手绘风”。

**最高优先级名称门禁**：只要品牌名称已经明确，每个首轮候选与最终标准 Logo 主版本都必须包含准确品牌名，并形成字标或图文组合标。禁止只输出独立图形、角色头像、物件符号、抽象符号、首字母图标或无名称徽记；也禁止把品牌名缩成角落小字、图片说明或无关副标题。独立图形标／角色标／缩写标只能在含品牌名的标准主版本被确认后，作为同一响应式家族的附属变体生成。品牌名未知时必须先澄清准确文字，不得使用占位名称、随机英文或纯图形绕过。

Logo 必须先建立或确认一个核心图，即标准 Logo 主版本。理论上所有 Logo 变体都应基于该主版本调用 `image_edit` 延展，保持品牌识别一致。若用户只要求一个 Logo 主图，第一张必须是干净的标志主图；若用户要求 Logo 规范，再拆出组合、单色、小尺寸、网格或应用预览。

Logo 不只是单张标志图，后续视觉语言、包装和应用都应能追溯到它的图形基因。设计或提取 Logo 时，必须明确：

- 图形概念：品牌理念被转译成什么符号、几何或字形动作。
- 制图逻辑：圆切、直线、折角、负形、比例、对称或解构关系。
- 字标气质：衬线、无衬线、手写、宽体、窄体、拉伸、断笔或定制字形。
- 单色识别：纯黑、反白、小尺寸状态下仍能识别。
- 延展母题：可放大、重复、裁切、做纹样或做辅助图形的局部。

如果用户已提供 Logo 或强参考图，不要重新设计另一套无关 Logo；应从参考图中提取可延展的图形、色彩、字体和比例关系。

## 使用场景

当用户明确要求以下产物时触发：

- 品牌 Logo、标志、图形标、字标、标准组合。
- 横版 / 竖版组合、单色版、小尺寸头像、favicon。
- Logo 升级、Logo 规范页。
- 在已有 Logo 历史资产上要求延展、改字、换色、保持一致。

不应触发的情况：

- 用户要求纯生图 VI 全案、多章节品牌手册或多触点品牌方案时，回到宿主纯生图品类路由组织 Logo、应用及必要 IP／包装 ref；本文件只负责其中的 Logo。
- 用户只要求 IP、吉祥物、包装、海报、主 KV、门店、贴纸、书签或周边时，不使用本 skill。
- Logo 主图不生成无关吉祥物场景、复杂 mockup 环境、随机英文、假注册标、条码式细节或密集小字。

## 核心流程

本产物 ref 由宿主纯生图 workflow 调用。先明确当前产物、参考图角色、数量与依赖，再在同一任务 Brief 中为每张正式图片建立独立条目。生成、资产登记和交付时序服从宿主纯生图 workflow；图片引用表仅是内部追溯记录，不能代替 Workspace ID 透传与 `RichMediaCard` 单项交付。

### 张数策略

除非用户明确要求完整 Logo 规范，通常生成 2-4 张。

- 轻量：1-2 张，适合单个 Logo 方向、字标优化、图形标优化或小尺寸头像。
- 标准：2-4 张，适合标准组合 + 图形标 / 字标 + 单色或小尺寸验证。
- 完整 Logo 规范：4-6 张，适合标准组合、横版/竖版、单色、小尺寸、制图规范和必要应用预览。

Logo 主图与 Logo 规范页必须拆开：主图只展示标志，规范页才展示网格、比例、色值和说明。

### Logo 画幅决策

Logo 画幅优先级固定为：用户明确尺寸 / 比例 / 用途 > 平台或载体要求 > 默认推荐。用户已指定画幅时直接沿用；用户未指定时，再根据 Logo 类型推荐比例。画幅只服务生成构图，不改变 Logo 本身的几何关系和品牌识别。

| Logo 场景 | 默认推荐比例 | 使用说明 |
|---|---|---|
| 标准 Logo 主版本 / 图形标 / App 图标 / 头像 | 1:1 | 最常见默认比例，适合确认核心识别、图形标、小尺寸头像和 icon 适配。 |
| 横版 Logo / 图形 + 字标横向组合 | 3:1 或 16:9 | 横向锁定版优先 3:1；需要更完整展示留白、规范说明或品牌头图预览时用 16:9。 |
| 竖版 Logo / 上下组合 / 徽章式 Logo | 4:5 或 3:4 | 适合图形在上、字标在下的组合，或需要保留竖向呼吸感的徽章式标志。 |
| Logo 规范页 / 网格页 / 安全区说明 | 16:9 或 4:3 | 适合展示网格、比例、色值、留白和多版本对照；不要把规范信息塞进 Logo 主图。 |
| 单色版 / 反白版 / 小尺寸验证 | 1:1 或 16:9 | 单个版本用 1:1；多版本并列验证用 16:9。 |
| 应用预览 | 按目标物料比例 | 名片、包装、门头、Banner、社媒头像等应用场景必须跟随目标载体尺寸，不使用 Logo 默认比例硬套。 |

### 核心主版本

- 没有可用 Logo 锚点时，第一张先生成干净明确的标准 Logo 主版本，作为核心图；品牌名已知时，该主版本必须包含准确品牌名，不能只有图形。
- 有用户 Logo、历史生成 Logo 或强参考图时，先用 `image_edit` 建立或修正标准 Logo 主版本，不重新设计无关 Logo。
- 标准组合、图形标、字标、横版、竖版、单色、小尺寸、favicon、规范页和必要应用预览，原则上都以核心主版本作为参考图调用 `image_edit` 生成。
- 同一轮多图必须复用已确认身份锚点及锁定变量，每张图按真实参考角色记录顺序；若某张衍生图无法传入其必需身份参考，停止该依赖步骤，不能用文字复写代替真实母版。

### 多风格候选与确认门禁

- 用户已提供并确认 Logo 时，直接将其登记为唯一核心图，不额外生成竞争候选。
- 用户未提供 Logo 时，先生成多个在核心概念、造型路线和视觉气质上真正不同的候选，逐一完成宿主交付门禁并说明差异，等待用户明确选择。品牌名已知时，每个候选都必须包含同一准确品牌名并形成字标或图文组合标，禁止将纯图形作为候选主输出。用户确认前禁止把任一候选当作正式母版继续生成组合标、材质版或应用预览。
- 换色、换字体、轻微变形、改变排版或更换 Mockup 不算不同方向。候选至少在“身份来源”和“形态结构”两个维度同时不同。
- 每个候选都要说明核心概念、造型操作、黑白识别方式、适合的品牌气质、目标场景、小尺寸风险与主要禁用项。

用户确认后，只保留一个唯一核心图。单色、反白、横／竖组合、紧凑标、小尺寸和材质状态均以该图调用 `image_edit`；透明底按下方去底步骤处理，不通过重新生图或 `image_edit` 模拟透明底。不得把其他候选、风格参考或上一张衍生结果加入正式家族。

### Logo 风格母题与结构质量

候选从适合 Brief 的母题中选择，每个方向使用一个主母题，最多加入一个有明确职责的辅助母题：

| 风格母题 | 可见特征与构造方法 | 适合气质 | 必须避免 |
|---|---|---|---|
| 几何负形符号 | 用有限基础形、切口、嵌合、共享边和单一主负形建立稳定黑白剪影 | 理性、创新、科技、空间、专业 | 通用圆圈加首字母、隐喻过多、小尺寸细缝消失 |
| 模块构成字标 | 统一笔画和模块尺度，通过压缩、堆叠、共享笔画和切角形成紧凑共同轮廓 | 文化、潮流、音乐、数字、创意机构 | 破坏拼写、机械拉伸字体、每个字符使用不同规则 |
| 有机膨胀粗字 | 粗重圆润、受控膨胀、局部压缩、连笔和基线跳动，字腔小但清晰 | 餐饮、生活方式、年轻消费、亲和社交 | 软塌无骨架、字腔堵塞、套用通用泡泡字体 |
| 复古角色徽记 | 低色数角色头像／物件与粗字标共享笔画、圆角、色块和时代语汇 | 餐饮、零售、社区、亲和消费 | 角色细节过多、卡通与字标割裂、无依据年份／城市 |
| 物件／角色融合标 | 将强业务相关对象嵌入字母、字腔、基线、外框或负形，使图文互相生成 | 咖啡、宠物、娱乐、体验型服务 | 图标只摆在文字旁、通用杯子／笑脸／动物剪影 |
| 动势轨道与开放环 | 用单一弧线、开放环、箭头或连续路径控制方向、开口和视觉重心 | 运动、音乐、出行、连接型产品 | 随意加箭头、方向混乱、动势与业务无关、线条过细 |
| 极简物件字标组合 | 少量大轮廓和一个关键动作配合紧凑粗字标，以基线、重心或轮廓咬合形成整体 | 门店、餐饮、个人品牌 | 插画细节多于标志、符号与名称等权分离、缩小时表情消失 |
| 角色主标＋定制字标锁定 | 角色／物件与完整品牌名通过共同描边、粗细、圆角、色块、基线或遮挡形成一个主标；可左图右字、上图下字或嵌合 | 音乐、餐饮、潮流、娱乐、宠物、社群 | 只画角色不写品牌名、角色与字标割裂、遮挡关键字符、依赖复杂场景才成立 |
| 复古人物肖像＋脚本字标 | 将人物压缩为稳定单色／低色数肖像，配合粗脚本或衬线字标与弱层级描述语 | 餐饮、甜品、手作、地方零售、个人品牌 | 肖像过度写实、脚本字不可读、虚构年份／产地／人物故事 |
| 双语／双层名称锁定 | 主品牌名承担最大识别，第二语言或确认描述以共同轴线、固定断行和弱层级跟随 | 跨语言品牌、本地门店、文化消费 | 随机翻译、两种语言等权竞争、副语言过小、擅自新增口号 |
| 响应式排布家族 | 确认母版后只改变排布、比例和从属信息，核心字形、负形与颜色职责保持不变 | 包装、招牌、头像、社媒、多尺寸载体 | 将不同候选混称家族、每种格式重画核心字形 |

候选阶段评估剪影、负形、字腔、笔画连续性、品牌名逐字准确与单色辨识度；确认主标后，用实际黑色单色版和白色反白版复核结构与远距离识别，通过后再进入应用预览。未通过时反馈具体问题，取得用户确认后调整母版，不擅自重设计。优先使用少量粗壮形体，不用碎细节、发丝线、微孔、随机装饰或多个隐喻制造“设计感”。图形标或角色标与字标必须在笔画、圆角、负形、基线、色块或比例中共享至少两项可观察特征。

角色／图形与品牌名组合时，只选择一种主结构：横向并列、上下堆叠、嵌合／咬合，或字标主导＋图形陪衬。横向关系共享中线或基线；上下关系由品牌名承托角色；嵌合不能遮挡关键字符；图形陪衬不能成为随机贴纸。粗描边、贴纸白边、投影边和高饱和底色只在品牌气质需要时使用，不能掩盖图文割裂。场景照片只做应用验证，不得当作标准母版。

角色设计按“主剪影 → 一个身份部位／道具 → 一个表情或动作 → 最少内部细节 → 与字标同步”的顺序压缩。可采用头像／半身速记、产品拟人、单线角色或粗线块面角色，但标准主标不得成为多动作插画；产品拟人必须先保留产品原型，人物头像必须避免写实肖像细节。角色与字标至少共享两项线重、端点、圆角、黑量、倾斜、基线或负形语言。

字标先建立无描边可读母版，再按真实职责选择单层对比描边、贴纸式白边、双层轮廓、偏移投影边或手绘粗糙边。描边后逐字检查字腔、粘连、形近误读、反白和小尺寸；贴纸白边与承托底属于应用版时必须单独标记，不得取代标准母版。背景同时区分纯色测试底、身份容器、应用承托底和场景材质；身份容器只有在参与名称轮廓／负形／品牌语义并能单色继承时才保留为 Logo 本体。

存在中英文、主名＋品类描述或双层名称时，只能使用用户提供或确认的准确文字；主品牌名优先识别，第二层通过更弱字重、字号和间距形成从属，共享同一对齐轴。禁止模型自由添加翻译、域名、口号、品类词、年份、注册符号或社媒账号。角色＋名称组合必须同时验证单色正版和反白版，确认角色表情、关键轮廓、名称字腔和图文锁定关系不依赖彩色填充、白边或场景背景。

### 底色、响应式家族与测试

需要为新品牌建立配色方向时，读取 [品牌规划配色参考](../../shared/brand-color-planning-reference.md)，每个候选只选择一组色系作为规划起点，并定义主色、承载色、墨色和强调色职责。配色与候选结构同时规划；确认后的黑白版本仍须通过结构复核，参考色系不能补救轮廓、拼写或图文关系问题，也不能覆盖用户已有标准色。

标准主标默认限制为 `1–3` 个印刷色角色，常规最多 `4` 个；黑、白、奶油色、灰、正式描边、影边与身份容器填色均计入。第四个颜色只能用于一个可命名的小面积身份部位，禁止每个字符、五官、服装或道具随机换色。渐变默认不进入标准母版；确有既有资产或不可替代颜色语义时，必须同时生成不超过 `3` 色的简化平面版及单色／反白版。超过四个颜色的理由、固定色序、对象和降级方式写入 `design_brief`，“活泼、年轻、丰富”不能作为理由。

- 纯白底 Logo 保持均匀纯白背景；进入 HTML 时只对 Logo 图片节点使用 `mix-blend-mode: multiply`。
- 纯黑底 Logo 保持均匀纯黑背景；进入 HTML 时只对 Logo 图片节点使用 `mix-blend-mode: screen`。
- 透明 PNG／SVG 已有可靠透明通道时直接使用，不补造底色，也不机械套混合模式。

确认母版后，按真实用途派生主标、横／竖组合、独立字标、独立图形标／角色标、紧凑副标、单色／反白和小尺寸简化；没有使用价值的形式省略。至少在大尺寸标准稿、中等组合应用和小尺寸图标／标签三个尺度检查深浅背景、品牌色、低对比风险、屏幕、普通印刷及任务实际载体。Mockup 只能证明场景适配，不能代替标准母版。

禁止复刻参考 Logo 的具体字形、角色、轮廓、负形或组合；禁止无依据添加 `TM`、`®`、`©`、年份、城市、口号或虚构外文；禁止用通用图库图标、默认字体加外框、随机首字母拼贴冒充原创；禁止把位图预览声称为可编辑矢量母版。

### 默认交付依赖顺序

用户只说“做一个 Logo”且未限制交付时，至少完成平面彩色主标、黑色单色版和白色反白版；需要完整 Logo 版时，再交付透明底、图形标、横版／竖版组合、小尺寸状态和 Logo 展示版。执行顺序固定为：

1. 用 `image_gen` 生成平面彩色主标，或以用户已有 Logo 为参考用 `image_edit` 建立主标；品牌名已知时，主标必须清晰包含准确品牌名并形成字标或图文组合标。确认后登记为唯一核心图。
2. 把核心图作为参考图生成黑色单色版。Prompt 核心句：`把参考图的背景换成纯白色，把完整 Logo 图标和字标统一换成纯黑色；严格保持轮廓、内部负形、字形、比例、间距和组合位置。`
3. 继续以同一核心图生成白色反白版。Prompt 核心句：`把参考图的背景换成纯黑色，把完整 Logo 图标和字标统一换成纯白色；严格保持轮廓、内部负形、字形、比例、间距和组合位置。`
4. 需要透明底时，对确认主标执行专门去底，核验透明通道和边缘，保留字腔、负形及 Logo 本体；已有合格透明资产直接复用，不将白底或棋盘格当作透明通道。
5. 再以同一核心图为参考，分别编辑横版、竖版及小尺寸状态。组合标 Prompt 逐字写明品牌名、字体特征、字色、字重、字形风格、图形与字标的层级、位置和间距。
6. 最后使用所有已确认状态制作 Logo 展示版或应用预览；展示标签与说明不得混入主标图片。

拟物、金属、玻璃、黏土、织物、陶瓷或浮雕 Logo 属于主标确认后的材质状态，必须从同一核心图编辑，不能替代平面、单色和反白交付。

### 一致性与多样性

在纯生图路线中也必须先锁定上游核心锚点，再做差异化延展。不要为了多样性破坏品牌识别，也不要为了一致性让多张图只像同一画面的轻微改版。

一致性锁定：

- 锁定用户明确提供或历史生成确认的品牌名、Logo 图形、字标拼写、主色、字体气质、材质、图形母题、画面文字和关键语气。
- 所有可见文字必须逐字保留用户提供内容，不自行更换品牌名、活动名、产品名、口号或数值信息。
- 锁定品牌名拼写、图形几何、线条粗细、转角逻辑、字标气质、配色和间距。变体只能调整布局、比例、间距和色彩模式。

多样性释放：

- 多图之间至少在组合方式、色彩模式、版式比例、应用场景、规范信息层级或小尺寸验证方式中选择 2-3 项形成真实差异。
- 差异必须服务用户意图和 Logo 用途；不要只换背景、只换角度或只换装饰。
- Logo 系统的多样性只能来自标准组合、图形标 / 字标、横版 / 竖版、单色、小尺寸和必要应用预览；Logo 主图不得用复杂场景、长文或随机符号制造丰富感。

### Logo 主图边界

Logo 主图不是 Logo 规范页。标准组合 Logo、图形标、字标、横版/竖版组合的主图画面只展示标志本身。

Logo 主图只允许出现：

- 图形标；
- 字标 / 品牌名；
- 必要的中英文品牌名组合；
- 极少量用于标志组合本身的短副标，如果用户明确提供。

上述清单是允许元素范围，不表示可以省略品牌名。只要名称已知，标准 Logo 主图必须至少包含“字标／品牌名”；图形标可以与其组合，也可以在后续单独派生，但不能独自构成标准主图。

设计理念、方案编号、版本序号、制图网格、比例说明、色值、应用规范、使用规则、设计思路和说明段落都不属于 Logo 主图内容。用户要求展示这些信息时，拆成独立的 Logo 规范页或品牌手册页，不要塞进 Logo 主图。

Logo 主图 prompt 应写成正向纯展示结构，例如：`白色或浅灰纯净背景，中央展示标准组合 Logo，左侧为简洁图形标，右侧为品牌名“{品牌名}”，整体水平居中，周围留出充足安全区。`

Logo 规范页才可以包含网格、比例、单色版、小尺寸测试和说明标签。

### Logo 规范页文字门禁

Logo 规范页默认属于文字高风险场景。生成前必须先在内部建立 `visible_text_inventory`，最终 prompt 只能渲染清单内文字，没有进入清单的说明、注释、色值、规则和标签都不能写进画面。

默认可见文字优先控制在 5-8 处，复杂规范页最多 12 处。用户没有提供具体说明文案时，只允许使用版本标签，不生成解释句、自然段或泛化说明。

Logo 规范页常用标签应逐字明确，例如：

- “标准组合”
- “横版组合”
- “竖版组合”
- “图形标”
- “字标”
- “单色版”
- “小尺寸”
- “安全区”

每一处文字必须和对应容器绑定描述，同时写清字号层级和字体风格。例如：`下方四个等宽模块分别展示横版、竖版、图形标和字标，每个模块底部显示中号冷灰色几何无衬线标签“横版组合”“竖版组合”“图形标”“字标”。`

禁止在 Logo 规范页 prompt 中使用会诱导模型自由补字或生成模糊小字的表述，包括 `简短说明文字`、`小字说明`、`下方标注说明`、`说明文字`、`规范说明`、`应用场景说明`、`相关说明`、`若干说明`、`辅助信息`、`密集小字`、`极小文字`、`示意文字`、`色值示意文字`。

错误示例：`每个版本下方标注简短说明文字。`

正确示例：`每个版本下方只显示一行中号几何无衬线标签，文字依次为“标准组合”“横版组合”“竖版组合”“图形标”“字标”，不添加解释句。`

### Prompt 策略

每张 `design_brief` 都要先写生成目标，再写从参考图提取的 Logo 锚点，最后按目标画面结构描述新图。不要只写“参考原图风格”。

`image_gen` 时，先建立一个干净明确的 Logo 方向。

`image_edit` 时，只提取可复用的 Logo 锚点：

- 品牌名准确拼写；
- 图形概念；
- 线条和转角逻辑；
- 配色/材质；
- 间距气质；
- 字体方向。

不要过度保留参考图的页面背景、裁切、场景道具、阴影或偶然版式，除非它们本身就是 Logo 系统的一部分。

每张 Logo prompt 都要有明确差异：标准组合、图形简化、字标版、横版、竖版、单色转换、小尺寸验证。

中文画面文字必须加中文双引号，英文画面文字必须加英文双引号。如果只出现 Logo 文字，就只列品牌名。

## 输入

- 用户提供的品牌名、产品名、人名、活动名必须逐字保留。
- 用户提供的 Logo、历史生成 Logo、IP、包装、主 KV、视觉语言锚点或强参考图，应作为 `image_edit` 参考图传入。
- 多参考图必须在 prompt 中按 `[img0]`、`[img1]`、`[img2]` 逐张说明作用，编号与实际参考图输入顺序一致，编号形式按工具真实约定适配。
- 价格、销量、折扣、功效百分比、排名、评分、认证编号、监管声明等数值或权威信息只能来自用户提供内容或已确认资产。
- Logo 规范页、高密度信息物料和带说明标签的页面必须先建立 `visible_text_inventory`；最终 prompt 只能渲染清单内文字。没有正文时，用版本标签、短标题、短标签、数字、步骤名和图标卡片表达。

## 输出形式

可选产物：

- 标准组合 Logo：图形 + 品牌名。
- 横版/竖版组合。
- 单独图形标或单独字标。
- 黑白单色版本。
- 小尺寸头像 / favicon 验证。
- Logo 规范页。
- 必要时增加一张 Logo 应用预览。

所有 `image_gen`／`image_edit` 正式产物按宿主门禁按宿主当前环境规则透传 Workspace ID，并在返回后使用 `RichMediaCard` 直接逐项交付，随后更新内部图片引用记录；不得重复创建媒体 Item 或在直交前回读；直交后的目录归档仍按公共门禁执行。Logo 主图和 Logo 规范页分别交付。

验收时，品牌名已知却只输出图形、名称拼写不准确、名称只是角落注释、或独立图形先于组合主标被当作正式母版，均视为 `LOGO_BRAND_NAME_MISSING`，不得进入后续家族派生。

## 工具与脚本

- `image_gen`：只在没有用户参考图、历史生成图、核心锚点，且必须建立第一张核心 Logo 主版本时使用；输入需要完整提示词与目标画幅，具体字段完全按宿主实际工具协议。
- `image_edit`：用于已有用户图、历史图、Logo / IP / 包装 / 主 KV / 视觉语言锚点的延展；也用于基于核心 Logo 主版本生成所有 Logo 变体。输入需要完整提示词、目标画幅与有序参考图，具体字段完全按宿主实际工具协议。

工具调用规则：

- `prompt` 只放完整 `design_brief`，不写工具参数、文件路径、URL、模型名、seed、输出文件名或内部 skill 名称；画幅按宿主指令指南表达。
- `design_brief` 必须完成三层推演：载体骨架、场景语义、实例填充。复杂画面按物理空间分区扫描，每个可见元素写清位置、类型、形态、内容、文字样式、状态、关系、风格和工艺。
- 全新应用延展的 `image_edit` Brief 先写目标，再列参考图继承项并展开新画面。局部编辑则以宿主 `must_keep`／`must_change` 合同为准，明确保留原文字、背景和未授权区域，不强制重写 70% 画面。
- 所有画面文字必须逐字明确；中文用中文双引号包裹，英文用英文双引号包裹；每处文字必须写清字体大小和字体风格。
- 不使用 `xx`、`某某`、`品牌名`、`对应色值`、`应用场景说明`、`相关说明`、`规范说明`、`说明文字`、`标签文字`、`若干文字`、`辅助信息`、`短说明`、`简短说明文字`、`小字说明`、`下方标注说明`、`自然段正文`、`介绍文案`、`补充信息`、`文字占位` 等会让模型自由补字的表述。
- 每张衍生产物在同一任务 Brief 中有独立条目和明确参考身份；批量字段与并发条件由宿主原工具和调度规则决定。
- 传入工具前自检：prompt 不包含工具字段、路径、模型名或内部参数；必要的身份保护与禁止项按宿主合同保留；所有中文双引号内容都是最终画面文字；重复结构没有用“等”“若干”“同上”省略；Logo 规范页已建立 `visible_text_inventory`，且没有 `极小文字`、`密集小字`、`示意文字`、`简短说明文字` 等不可读文字描述。
