# Coding 构图、间距与表面规则

供 ai-coding 与 pure-coding 按需使用。共同的主构图、参考机制和阅读关系见 [公共构图](../shared/composition-principles.md)。本文件不为 pure-image 增加几何编译、抠图或分层要求；标明 AI + Coding 的素材生产条款不适用于禁用生图的 pure-coding。

对于 AI + Coding，构图绑定先按品类确定生产单元：社媒长图 Hero 整体生成；其余分层区域拆分资产与代码元素，独立艺术标题只用于首屏／首图或该独立图片唯一最重要的大标题，同一图片默认最多一个，其余文字由可编辑 DOM 承担。每张正式图片在轻量素材清单中登记用途和消费页面／区域，所有 DOM 文字的字体从字体库解析后再进入 HTML 组装。

AI + Coding 构图需要 `image_generate`／`image_edit` 时，建立对应素材记录并读取 [asset-prompt-guide.md](ai-coding/asset-prompt-guide.md)。工具支持的画幅比例与像素尺寸通过调用参数传入并记录于素材清单，最低有效像素用于素材验收；显示 fit 模式、定位与取景直接写最终 HTML。Prompt 将主体相对位置、焦点、负空间和安全裁切要求转为画面描述，不混入上述参数。摄影、插画和生成素材只允许等比缩放；比例差本身不证明裁切失败，按素材指南核验实际取景，无法保全主体和保护区时再于授权范围内重构图或扩图，不拉伸适配。

整体丰富度由商品尺度、图像细节、材质／光线、字级与疏密共同承担。底图要求以当前品类 Spec／Visual 为准；需要作品级纹理、肌理或渐变时，局部文字承托、Logo 测试块等纯色功能区不替代整页底图。用户明确锁定的视觉要求优先，不能因素材未就绪或实现方便擅自更换背景；不从这里扩展新的生产路由。

### 容器视觉语法：开放排版优先，语义容器按需

本策略统一处理 Coding 产物中的信息容器、图窗及开放信息组，按“是否使用 → 如何使用 → 准出标准”执行。Visual 在既有 Brief 说明可见关系，组装将决定落实到真实素材、DOM 和行内样式，验收检查最终渲染；不另建容器规划文件。品类只补充自身的页数、画幅、折线、交互或其他已确认边界。

#### 一、是否使用

先判断内容是否需要分组边界、阅读承托、重点强调，或收纳、凭证、翻阅、指向等明确语义。对齐、段距、栏线和留白已经足够时，采用开放排版并说明组织方式；不能为了丰富画面把每个标题、事实和图片分别装进卡片。物理纸面、已有图窗或底图中已烘焙的框线不机械再套一层。

需要容器时，先确定承载内容、归属、主次及与相邻组的关系，再选择家族和外观。规则排列适合平行事实、比较和编辑秩序；叠压、错位或旋转须有阅读与空间依据，不以几何整齐或没有容器判定设计退化。嵌套只有在父子内容确有不同职责时采用；背页、袋口、衬纸、夹子等属于组合结构部件，不各自变成内容卡。

以下家族供按语义选择，不要求每项出现，也不要求所有容器拟物化：

| 容器家族 | 平面几何构造 | 可见拟物效果 | 适用关系 |
|---|---|---|---|
| 文件夹／资料袋／口袋 | 背页、页签、斜坡肩角、前袋和露出的内容片分层 | 内外层色差、袋口遮挡、纸片探出、定向接触阴影 | 分类、档案、作品集、岗位、资料包 |
| 卷轴／公告纸／垂挂纸 | 主纸面、顶部卷边或横杆、底部折页／坠边分层 | 卷边高光、内侧暗面、纸张厚度、局部翘角 | 公告、规则、活动说明、长段正文 |
| 报纸／档案页／旧书页 | 不规则切角或轻微波浪纸边、分栏线、折痕和页眉结构 | 纸纤维、套印、磨损边、折叠明暗，但正文保持清晰 | 报告、故事、回顾、文化内容 |
| 撕纸／涂刷边／手作片 | 不规则闭合轮廓、内层平整内容面、局部胶带／夹子 | 毛边、油墨、纸层厚度、错位衬底和轻旋转 | 短观点、数字、照片说明、手作主题 |
| 阶梯框／切角牌／铭牌 | 肩角、缺口、双层轮廓、内外嵌套几何 | 金属边、压印、内高光、薄浮雕和低层投影 | 重点指标、荣誉、套餐、标题与短事实 |
| 票券／邮票／凭证 | 齿孔、侧缺口、票根、分隔虚线与编号区 | 纸张厚度、压印、套色、撕取关系 | 场次、权益、优惠、凭证；必须具有真实票券语义 |
| 标签牌／对话牌／指示牌 | 尾部、挂孔、连接短线、支架或指向结构 | 连接点、悬挂感、局部厚度和方向明确的阴影 | 注释、人物引语、短标签、真实指向 |
| 分层窗口／相框／胶片 | 外框、内窗、衬纸、压片、胶带和前后页 | 图片嵌入、局部遮挡、边缘反光、照片纸厚度 | 摄影、案例、作品、人物或产品证据 |

#### 二、如何使用

在 Brief 中说明容器承载什么、位置与主次、内部图文关系，以及实际采用的轮廓、表面、边缘、厚度和遮挡方式。未采用的效果不添加；采用开放排版时不强填材质与结构部件。选择与整体视觉一致的主材质与必要辅助效果，阴影解释接触和层级，纹理落在相应表面，不为统一风格给所有区域同时叠加玻璃、模糊和发光。

能可靠编码的结构使用 DOM、CSS 或 SVG：轮廓、表面、装饰与内容按需要分层，准确文字保持独立。裁切只作用于指定图窗或形状，不能裁掉正文；表面纹理、mask、滤镜和透明度不得无意影响内容层。复杂壳体按现有素材流程准备，不因某个容器名称强制生图，也不因缺少现成模板退化为默认圆角卡。

逐槽核对图片所表达的内容与对应文案。完整场景、透明主体和局部特写分别确定取景与主体尺度；不透明图片背后的渐变不能消除图片自带底色。需要融合时先核对边缘颜色、光线、投影和裁切，明确的照片边界可以保留；不默认以整图白雾掩盖接缝。跨区域连续场景保持统一取景与坐标，局部图窗保留自己的归属。

### 容器内容框、间距与顶边

根画布按 [固定画布协议](../../html/coding-rendering.md#html-fixed-canvas-delivery) 锁定，内部容器按实际内容和构图分配空间。无底板信息组同样需要明确归属，不为测量增加可见边框；几何直接落实到 HTML，不另建合同或通用占用率表。

先区分载体：固定纸幅先扣除品类页边距、折线避让和页尾安全区，再按真实内容分配主体、栏目／折面及模块的可用宽高；未锁高长页先定可用宽度，再由内容确定所需高度。两者均用最终字体、字重、完整文案及就绪素材试排，容纳标题、副题、数字与单位、正文、图注、组距和四向留白。容量按完整排版盒核算；视觉净距按字形墨迹、容器内轮廓和图片可见主体检查，不以空文本框或透明留边代替。

背景覆盖、内容分布与留白分别判断：背景负责表面完整；内容分布看承担信息或叙事职责的文字、头像／作品、事实图表等如何使用可用空间；留白说明分组、焦点、场景或跨面接力。背景、空壳、纯装饰和孤立页尾不能证明主体已充分使用纸面；不把各组联合包围盒或最末节点底边当成填充率，也不设置通用占用率门槛。

固定纸幅同时试排整页、每栏／每面和模块内部。简历检查主窗口／主体尺度、左右栏节奏及内容结束位置；三折页保持纸幅、面宽、折法与面序，逐面分配空间并核对整侧关系，允许封面疏、信息面密。有意的桌面空区、非最大化窗口和不等高栏尾可以保留，但须与已选构图和阅读焦点一致，不能因风格名称而忽略意外空区。

内容偏少时先在所选结构内联合调整栏目、模块、图窗的尺寸与比例、组距及可读字级，并同步重排内部内容，不只拉高外壳或把余量集中留在页底。仍不适配时重新评估布局的采用范围，改变用户锁定构图按原授权流程处理。事实不足可沿品类规则展开已有信息或保留合理简洁，不编造／重复内容、不用装饰填洞、不为凑面积夸大文字和头像，不拉伸照片或字形。内容偏多时按下文容量顺序重排；两种情况都保持固定载体和品类安全边界。

竖排标题、侧边眉标、编号栏和绝对定位文字必须先占位，再排正文：从所属内容区扣除其完整可见范围与净距，采用独立网格列／行或等效真实占位，不能在全宽正文上事后叠一条竖标题。旋转、缩放或 writing-mode 改变后的范围同样计入；标题再长也不能靠提高 z-index 遮住正文。折页按每个折面分别核算，不能借邻面空间。

数字与标题组成同一标题组时，例如「80°C」与「恒温慢熬」，使用共同排版流和明确组内间距，按最终字体及实际宽度一起试排；不以两个独立绝对坐标碰凑。放不下时重分宽度或将完整语义组换行，并从完整组底部安排后文。正文、竖题、图内文字和准确数字都属于保护内容，有意图文穿插不等于允许文字互盖。

#### AI + Coding：多层间距与防贴边

从页面安全区、父容器可用区、子容器到图文组逐层检查，不能用卡片内部 padding 代替父容器留白。以该区域正常阅读字号与视觉密度确定间距，同组采用一致尺度；标签的紧凑留白不能直接用于正文。固定数值仅作为试排选择，不作为所有品类的统一合格线。

- 子项在扣除父容器内边距后的可用区排布；并列项总宽与间距不能超过可用宽度。圆角、粗边、切角和不规则壳体按实际内轮廓留出内容区。
- 完整标题组包含副题、英文与说明行；从该组实际底部计算下一组起点。分隔线两侧、首行顶部和末行底部各自保留可见净距。
- 图像与装饰需要破框或叠压时，明确允许重叠的对象、区域及层级，并同时保护正文、单位、图注和关键主体。旋转后还须检查邻组与页面边界。
- 文案、字体、图片取景或容器尺寸变化后，联动重排所属组及受影响的相邻元素，重新检查剩余画布空间。不能只增大文本框或挪动某一行。
- 内容超量时优先重分宽度、列数、组距与区域；固定页内重新分配内容，只有在获准时改变锁定尺寸、页数或文案。不用隐藏、裁切、渐隐、拉伸或持续缩字掩盖超量。自然流模块能增高，不代表固定纸面能容纳它。

### 容器准出标准

用最终字体、完整文案和就绪素材渲染目标尺寸，先看整体层级，再看标题、末行、四角、图窗接边和叠压处。以下三方面均满足才算本次容器效果通过：

| 检查对象 | 通过条件 |
|---|---|
| 使用与归属 | 容器有明确职责，或开放排版组织清楚；图片内容与文案对应，图注、单位和标签不串组，无多余套框。 |
| 空间与容量 | 内容完整，无非预期重叠或裁切；父子四向净距、完整标题组、末行和相邻组有合理留白；关键主体与文字受保护；满足本次固定画布及品类安全区。 |
| 视觉兑现 | 轮廓、材质、层级和边界符合选定关系；文字在真实底色和纹理上可读，指定连续背景没有意外接缝；有意图窗边界保留；无靠模糊、遮挡或缩字掩盖的问题。 |

仅写了策略、引用了 CSS、素材成功加载或“无横向溢出”不算视觉通过。未就绪素材、未测字体或尺寸明确记录范围；局部模块通过不推导为整页或任意内容通过。发现问题回到对应容器与相邻关系调整后重渲染；纯间距问题不触发无关素材重生或新一轮风格确认。既有交付时序和品类印制检查仍按原协议执行。

## 长图段高、图文比例与实际兑现

详情页与社媒长图使用同一套测量口径，内容责任与视觉风格仍由各自 Spec 决定。

### 先规划整页，再确定局部

先用整图缩略图读取参考的章节边界、相对段高、焦点大小、文字层级、图片窗口与重复节奏，再检查关键段的局部。参考展示板、设备状态栏、样机外框和水印不参与比例测量。参考像素不足以准确读取时记录估计范围，不虚报精确百分比，不复制其事实文案。

用当前真实文案和主素材共同试排：为每段明确内容责任、最终宽高、主焦点、正文组及段尾出口，形成纵向比例草图；不是每条卖点都分配一个屏高。同类内容可以等高、同轴、同图文比例；不同职责按实际内容和视觉重量变化，不机械交替高低段。用户未指定总高时由段高求和；指定总比例时先整体分配再迭代，不能在末尾补空白或缩小文字凑高。

### 比例必须带测量对象与分母

- **段高比**为段高／成品宽度，用于比较长短段；**段落份额**为段高／整图总高。两者不能混写。
- **图片框宽／高／面积占比**分别以本段宽／高／面积为分母，只描述图片槽位。
- **主体可见包围盒占比**先在最终就绪图片中定位实际产品／人物／食物轮廓，再映射到本段。透明留边、生成环境和原图空白不计入主体包围盒；完整场景的主视觉范围与产品本体范围分别记录。包围盒面积不是逐像素轮廓面积，也不代表遮挡后的实际可见面积。
- **文字组**按完整标题、副标、正文或标签的实际 DOM 节点分组测量；不同字号分为多个节点时逐项核对并在视觉检查中看完整组，不把空文本框当字形墨迹。图内标题用已检查的图内区域记录，不假造独立 DOM 文字。
- 图文可能重叠，共享同一空间；图占比与文占比不要求相加为 100%。“图七文三”仅用于明确无重叠的版面分区，不能代替字级、主次与主体尺度。

每段给主焦点和关键文字／图片组指定有依据的目标范围；依据来自用户参考、主题、内容量和手机阅读，不把某个固定百分比推广到所有段。素材按这些槽位反推主体位置、镜头与负空间；不可先生成带大量留白的完整海报再缩进小框。实际素材与比例草图冲突时，在进入 HTML 前调整素材构图或重新试排，保留用户尺寸与完整事实。

### 最终 DOM 测量与核对

两类长图都以最终 HTML 为几何事实源。给顶层连续区段设置唯一 `data-section-id`，给需要定位和编辑的关键图片、标题及正文设置稳定 `id` 或 `data-layer-id`；素材清单只用自然语言消费者说明图片使用在哪一页、哪个区域，不保存 DOM ID、坐标、层级或字号。

HTML 完成后仅运行 `python3 scripts/runtime/shot.py <最终作品.html>`，读取当前源的 measurement、issues 和截图。自然高度、正式内容底边和安全区分别核对；脚本没有返回的字体、区段或元素诊断不得宣称已检查，不另行运行浏览器检查器。完整流程见 [HTML 预览](../../workflow/html-preview.md)。

脚本不能自动理解商品可见轮廓、字形墨迹、遮挡意图和美感。最终还需查看整图缩略图、相邻段和手机尺度：第一眼是否看见计划的主焦点；是否产品小而容器大；同类内容是否稳定、不同职责是否有变化；留白是否承担构图而非填高。换素材或修改 HTML 后重新运行检查器；失败时修正受影响 HTML 或返回素材阶段，不改 Brief 目标迁就错误结果。

### 图像、卡片与背景的融合处理

先依据内容与已确认规划决定图片如何使用：独立图窗保留取景与归属边界；共享场景联合安排环境、主体和文字净空；透明主体使用核验就绪的无底素材独立叠放。再用下表说明上下段的阅读关系，最后选择必要效果。CSS／SVG 库中的图窗、卡片、边框和渐变只是候选，不反向决定构图；融合不等于所有图片都要淡出。

色场、图片 Alpha 与表面透明度独立绑定：色场记录颜色、方向和覆盖范围；额外的图片渐隐仅在确有衔接需求且最终裁切后存在安全空场时配置，素材已有的轮廓 Alpha 正常保留；表面透明度只作用于独立表面层。图片元素与普通文字默认 opacity=1，不用共同父层的 opacity、filter 或 mask 连带削弱主体、文字和纹理。摄影本身的明暗不自动转换为 CSS 渐变，明确的深浅分区可以保留硬边。

采用效果时，在原使用说明及最终 HTML 中落实对象、区域、方向、颜色／透明度、层级和取消条件，不另建记录。用实际底色及相邻区域核验主体轮廓、接触点、材质细节与叠字对比；出现亮暗带、灰雾、透明度台阶或裁切露底时修正来源，不能靠继续加强渐变遮盖。换图、换底色或改范围后重验。普通信息卡与标签默认无投影，只有真实接触或悬浮才补对应阴影。

| 关系 | 触发依据 | 处理与验收 |
|---|---|---|
| 空间连续 | 主体、动作、环境、台面、光向或路径需要跨段延续 | 共享或扩展同一可感知场域，联合规划主体、环境与文字净空；检查透视、接触关系、尺度、材质和光向真的连续，不以颜色接近冒充同一场景 |
| 媒介转换 | 场景进入纸页、票据、信息板、相册或其他有内容职责的载体 | 保留可理解的载体边界和进入方向，使读者知道主图怎样交给正文；边界清楚即可，不强行抹平 |
| 视觉呼应 | 物理场景不同，但内容仍连续推进 | 用栏目轴、标题色、线条、轮廓、主题角色或色场职责延续阅读；不为连续感强行扩图或加蒙版 |
| 独立图窗／比较组 | 图片需要独立证明细节／结果，参与同条件比较，拥有专属图注，或因真实来源、媒介与空间不同而不能合理连续 | 保留有职责的取景边界，统一同组景别、比例、裁切和后期，使图片与图注／说明共轴；边界不能说明证据、比较、归属或媒介身份时，不使用图窗 |
| 明确换章／换场 | 主题、购买问题、叙事阶段或内容任务发生真实转折，而不是仅从 Hero 进入正文 | 允许清楚硬切，并以适合项目的字级、色彩职责、品牌母题或阅读轴维持全局识别；换章理由与下一焦点必须明确，不能只靠交替纯色、照片和空白说明条制造章节感 |

关系不止一种时选择主关系，必要时只补一个辅助手段；均不成立时沿用当前视觉关系。融合不等于消除边界，也不要求所有方式出现；验收看阅读是否接得住、切换是否有意图、视觉语言是否一致，不以接缝隐形为准。

| 观察到的关系 | 应增加的处理 | 不应增加的情况 |
|---|---|---|
| 文字与背景局部混淆 | 按[文字与背景的对比处理](../shared/composition-principles.md#文字与背景的对比处理)选择字色、字重、移位、轻投影、描边或局部调光 | 对比已经足够时不添加承托；不得默认黑灰蒙版或统一压暗整图 |
| 照片需要与相邻区域连续 | 先评估透视、尺度、纹理与接触关系是否连续；在授权范围内优先复用共享场景或扩图，仅最终裁切后的安全空场可用图片 Alpha 衔接，遵守[渐变与文字安全区](../shared/composition-principles.md#渐变与文字安全区)及[合成复核](../../workflow/html-assembly.md#素材就绪后的合成与几何复核) | 结构不相容或无安全空场时返回素材／获准重排；明确图窗保留边界，不默认用短同色色带、黑幕或白雾遮缝 |
| 图片被定义为画框、窗口或证据卡 | 保留有意的图窗边界；确需分界时才用细描边，只有真实深度或接触关系才用与光向一致的阴影 | 边界已清楚时不自动加边或投影；全幅背景、无边界照片不统一套框 |
| 卡片表面与背景明度接近 | 使用 `1` 条克制描边、内高光或微小色差建立边缘 | 已有明显色差、叠压或厚度关系 |
| 透明/玻璃/凝胶壳体需要厚度 | 使用图片壳体自身的材质边缘；Coding 只补准确内容和必要高光线 | 用普通半透明矩形声称实现复杂折射 |
| 主体需要破框、穿插或局部显隐 | 使用透明图片、合法 DOM 层级遮挡，或入库前烘焙复杂蒙版 | 用蒙版隐藏错误裁切、溢出文字或错误结构 |
| 区块需要光向、空间深度或密度换挡 | 使用有明确方向和停靠点的线性/径向渐变 | 无构图职责的随机彩色渐变 |

同一区域通常只保留一个主融合手段和一个辅助边缘手段。例如“对比字色 + 细描边定义图片窗口”可以同时存在；“渐变 + 厚描边 + 重阴影 + 玻璃 + 发光”属于效果堆叠，必须删减。

### Coding 简单背景纹理清单

简单背景纹理由低透明 HTML 元素、CSS 渐变或内嵌 SVG 构成，作为独立低层 DOM，不能压过标题、正文、产品识别面或照片焦点。每张画面选择一种主纹理，必要时增加一种局部辅助纹理：

| 纹理 | Coding 实现 | 适用 |
|---|---|---|
| 细线网格、坐标纸 | 多层 `linear-gradient` 或内嵌 SVG，低透明、局部缺省 | 科技、教育、信息图、理性编辑风格 |
| 横向扫描线、印刷走纸线 | 少量等距 CSS 线性渐变，方向与阅读轴一致 | 数字界面、复古印刷、屏幕语义 |
| 稀疏圆点、半调点阵 | 少量小 circle，密度随区域变化 | 活动、年轻社媒、印刷风格 |
| 棋盘格、像素块 | 少量规则 rect，控制两级尺度和局部密度 | 游戏、潮流、数字文化 |
| 放射线、速度线 | 从焦点发出的内嵌 SVG 路径或受控 CSS 线条，避开文字安全区 | 运动、发布、强调主视觉 |
| 等高线、流线 | 少量内嵌 SVG Bézier 路径，保持统一方向和间距 | 户外、自然、流动主题 |
| 纸张分栏线、裁切标记 | 细边框、伪元素等价的真实 DOM 或内嵌 SVG 角标／刻度 | 杂志、档案、研究、复古编辑 |
| 半透明几何叠片 | 低透明 HTML 容器，使用同色系尺度差 | 极简、品牌、抽象信息背景 |
| 稀疏颗粒点 | `12–40` 个低透明小圆或短线，集中于非文字区 | 轻微粗粝、印刷或模拟噪点 |
| 边缘色带、窄幅渐变 | 页面边缘的窄 DOM 或行内 CSS 渐变 | 章节换挡、视线入口与出口 |

需要随机纤维、真实纸纹、砂砾、织物、噪点、折射或连续手绘肌理时改用图片，不用数百个 DOM 节点模拟。Coding 纹理的元素数量、间距、透明度和留空区域必须在 最终 HTML 中确定，禁止运行时随机生成。

### 背景、图片与文字的关系归属

图文关系是布局决策，不新增独立 CSS 类别。先辨认页面／章节的共享背景、独立图窗、前景主体和文字归属，再决定图层、容器与可复用实现。满版场景上直接叠字，属于背景承载文字；局部照片配图注属于独立图窗；只有明确载体才增加卡片。图片文件为矩形、面板为矩形或文字在图片一侧，都不能作为卡片依据。

- **通用布局关系**：满版叠字、邻接图注、环绕、跨栏图片与共享场域等，在本文件记录背景范围、图像角色、文字锚点、主次比例和保护区；CSS 优先复用主场、网格及叠层原子。只有现有实现不能表达且可独立复用的新机制，才新增布局原子。
- **品类物理约束**：折面、折线、开合顺序和面板职责由对应 Spec 规定，不在通用布局重复维护。
- **具体组合**：某套背景、图窗、文字、配色和材质的完整关系存入组合正文，以对象引用和局部参数落实；组合引用布局实现，不复制通用规则。分析记录可写“图文关系”，入库类型须明确为布局原子或组合方案。

### 编号、眉标与结构标记

编号用于步骤、时间顺序或明确索引；普通并列卖点不默认加 01／02／03。眉标用于章节分类、品牌身份或确有价值的辅助信息，不在每个标题上方自动补全大写英文。分隔线、箭头、标签和边框分别说明分组、方向或归属，不能只因版式显得空就添加。明确的票券、档案或编辑风格可保留有依据的索引语法，但不新增虚构编号、伪英文或事实。用户指定的视觉特征优先，任何配色、字体或几何形态本身都不作为通用禁用项。

#### 断行、孤字与语义完整性

使用已解析字体和最终容器宽度试排，检查每行实际文字；字形覆盖通过不代表断行合理。标题、短说明和卡片正文避免末行只剩一个汉字、标点或脱离前文的单位；姓名、短术语、日期、数字与单位按语义整体安排，不在括号内部或数量单位之间随意断开。长段落末行过短时先看阅读节奏，不以固定字数一律判错；有意竖排、单字主视觉和明确诗句断行不属于孤字问题。

修正顺序：先去掉无意的硬换行，调整列宽／容器宽度与布局，再按语义分行；必要时采用当前字体可用的字宽或在原字级范围内微调字号，文案仅在获准时精简。不得为消灭孤字缩小全页文字、压扁字形、堆空格、给整段加 nowrap 或把内容裁掉。需要保持连续的短语可局部不换行，但要核对其整体宽度不超出容器。

标题可在实际渲染支持时使用行内 text-wrap:balance，正文可尝试 text-wrap:pretty；它们只是排版辅助，不能保证中文语义与单位不断开，也不替代截图检查。品牌标题或固定构图允许有意换行，记录在原 Brief 目标与 HTML；多尺寸分别试排，不沿用仅在单一宽度成立的硬换行。

断行变化后按 [容器内容框、间距与顶边](#容器内容框间距与顶边) 重算所属组及相邻布局。组内间距应小于组间间距，同职责项目共享间距基准；有意留白按构图保留，不将所有间距强制等大。

#### 数据组与图注的共同尺度

数字、千分位、小数点、百分号、数量级、单位及限定词共同组成可读的数据组，即使分成不同字号的 TEXT，也要一起测量和保护。数值本身不拆行；“万人次”“元／盒”等单位保持横向完整。同排采用基线对齐并计入数值与单位间距；宽度不足时，可将完整单位另起一行并与对应数值紧邻，不能挤成逐字竖排或落到容器外。日期范围和带条件的短数据同样按语义安排。

同排指标先用实际字体测量最宽数据组，而非仅按数字位数估算，再确定列宽、共同数字字级及单位字级；同时核对各列标题、说明和来源占用的高度。同权指标保持一致字级，不为最长一项单独骤降字号。空间不足先调整列宽、列数或整组排布，必要时在原层级范围内共同微调字级；不删除分隔符、舍入数值、改换计量口径或以裁切迁就等宽模板。

图片与其图注作为对应单元安排：图注的可用宽度随所属图窗或明确分配的说明区确定，正常换行仍留在本单元；与下一图注之间保留栏间净距。同排图注按共同起始线对齐，并以最高图注组确定后续内容起点；不为凑同高截掉文字，也不让较长图注跨入邻图。

### 正式 Hero 的纵向空间

正式 Hero 从开场到下一章节入口测量，包含标题、主体、环境与段尾出口；不能只测其中的产品图框。这里的“首屏”是开场章节，不要求塞进一个手机视口。先定成品宽度 W，再定 Hero 高度 H，不用浏览器 vh、整页高度的固定百分比或统一 640px 推导。

正式 Hero 按“用户明确指定的 Hero 尺寸／比例 ＞ 已明确选用的完整命名配方原有 Hero 高度规则 ＞ 通用默认 `H/W = 1.8`（宽 1080px 时高 1944px）”确定高度，并在 Brief 的 `height_reason` 中记录所用依据与整段测量边界。只有以名称或稳定标识明确采用完整组合方案时，配方高度才生效；仅借配色、字体、布局原子、局部模块或参考构图不构成配方例外，配方未规定 Hero 高度时回到默认值；其中社媒长图按构图在 `H/W = 1.5–1.8` 内选择，需要过渡到下屏时默认 `1.8`，底部预留避开标题、主体及关键信息的过渡安全区，计入首屏高度，不额外加高。

Hero 的主体、标题、环境与段尾出口共同兑现所选高度。社媒长图可在上述默认区间内按构图选高；选定后，文字多少、参考图比例、素材形状、场景纵深和整页总高限制均不自行改变该高度；内容与尺寸冲突时说明冲突，不靠缩字、空白或重复内容凑高。正文段不继承 Hero 比例。

社媒 Hero 仍按[图主、文主、图文组合](scenarios/social-long-image-spec.md#一体化-hero-与第-2-屏衔接)确定主导关系：图主检查主体尺度与必要环境，文主检查字级、断行和负空间，图文组合检查共同主组与阅读顺序，均保留段尾出口；关系类型不产生另一套默认高度。不能保持小图与小标题只拉高容器，也不按固定三等分堆叠。

KV 的 1920×1080 只用于确认视觉方向，不能成为正式 Hero 的默认比例。正式资产按锁定的正式槽位重新构图；用户或完整命名配方确定为横版时保留该槽位。复用比例不同的素材时先验证裁切，无法保全商品、人物、图内标题及环境关系则通过图片编辑或素材重组适配，不拉伸、不靠空白补高。

Brief 用自然语言说明相对构图、参考与开场职责；素材清单只记录图片目标比例、尺寸与安全区。正式区段宽高直接落实到 HTML，实测写入 HTML 验证记录，不新增几何规划文件。生成前检查目标比例，组装后同时核对实际段高、主主体尺度及标题—环境关系；只检查容器高度不算通过。

CSS 只落实已选段高，不反向决定首屏比例：`aspect-ratio` 与 `--vl-stage-ratio` 是宽／高，通用 `H/W = 1.8` 须写 `5 / 9`，不能写 `1.8`；用户或配方高度按同一换算落实。显式 height、max-height、父级固定网格行或内边距可能改变实际尺寸，须以最终成品内容宽度核对。`layout.chapter-flow` 的满幅图片使用 height:auto，会沿用源图宽高比；横版 KV 须先按锁定正式槽位重新生产／适配，不能直接入流，也不能仅靠 cover 强制改成另一比例。组合中的小图窗高度、道路重复步长与局部章节比例不作 Hero 段高；一体化 Hero 只借外层几何，不重复套用配方内的标题、图窗或面板。

## Coding 映射

先遵守当前 workflow 的 最终 HTML协议。AI + Coding 与 pure-coding 都通过真实文本／容器／图片 DOM、CSS Grid／Flex／定位、`object-fit`／`object-position`、标准 `clip-path`／mask、transform、层级和内嵌 SVG 落实构图；所有样式展开为元素行内 `style`。复杂主体分割、真实透视或浏览器无法稳定表达的光学效果才在资产阶段预处理，不得因模板库存在某种效果就无职责叠加。

- 引导线、分区、非对称网格：明确轴线、区域比例、基线和目标坐标。
- 框架、异形、前后景：使用合法图形、透明资产及层级；协议不支持的复杂效果按原素材规则处理。
- 满版与负空间：按焦点及安全裁切区准备源图，禁止拉伸；保留标题和事实信息的可读区域。
