# 未匹配垂类 Ref 时的通用兜底策略

## 启用门禁

本文件只在用户的主要产物无法匹配任何 `references/style/coding/scenarios/` 垂类 Ref 时读取，用于建立最小完整、可执行、可验收的通用设计 Brief。

按以下顺序判断：

1. 先锁定用户真正要交付的产物，不按题材词、风格词、画布比例或局部内容猜测。
2. 查找 `references/style/coding/scenarios/` 中是否存在与该产物相匹配的垂类 Ref。
3. 有匹配项时停止读取本文件，以垂类 Ref 为主规则；不得使用本文件重新选择场景、业务任务、模块链或生产路径。
4. 无匹配项时，在 Brief 用自然语言记录“通用兜底”和未匹配原因，然后完整执行本文件；最终 HTML 的实现记录使用 `category_ref_key: generic-fallback`。

局部交付继承其所属主产物的垂类 Ref，不因只制作封面、首屏、单个面板或局部模块而启用通用兜底。

## 权威层级

固定遵循：

`user_confirmed > scene_ref_and_brief > composition_refinement > generic_fallback`

- 用户已确认的内容、品牌、尺寸、素材、交付和禁止项优先。
- [composition-principles.md](../shared/composition-principles.md) 只在主构图已选定后细化布局或生图描述，不代替本文件的兜底 Brief。
- 兜底路线包含 `image_generate` 或 `image_edit` 时，必须读取 [asset-prompt-guide.md](ai-coding/asset-prompt-guide.md)。Brief 写图片职责与图文关系；HTML 路线在素材清单中落实用途、生产方式、参考／身份来源、Prompt、比例、目标尺寸、安全区、消费者和准出标准，再调用工具。
- 若执行中发现实际已匹配某个垂类 Ref，停止使用通用兜底，转读该垂类 Ref 补充内容与视觉要求；保留主入口已锁定的父路线，不由垂类 Ref 重新裁定生产路径。

## 通用 Brief

使用 [Brief 公共字段与通用字段](../../../example/brief.md#未匹配品类的通用字段)，在同一任务文档记录路由原因、产物、受众、传播任务、主命题、准确内容、事实来源、素材、阅读顺序、视觉主张、生产路线和验收条件。逐单元追加内容与视觉，不另建机器参数 Brief。

路线在 Brief 中写“纯生图／纯 Coding／AI + Coding”。只有 HTML 范围进入公共 HTML，`route` 分别使用 `pure_coding` 或 `ai_coding`；纯生图不强制建立 HTML。通用兜底没有品类绑定键，查询 CSS 不传 `--ref-key generic-fallback`，按自然语言效果限量查询并检查候选适用边界。

通用 Brief 也必须写清：用户锁定／参考继承／禁用／可裁量的决策优先级；视觉命题、第一焦点、第二阅读层和收束点；每个单元的相对构图、图文占比、密度、留白、对齐轴、遮挡和主体保护；图片层级、裁切／遮罩、背景与前后景关系；跨单元固定与变化；载体适配、极端内容、状态与降级；以及焦点、文案、图文比例、主体保护、背景关系和禁止效果的可观察验收。坐标、色值、字号、DOM ID、CSS 属性和实现层级仍只在最终 HTML 中确定。

只有会实质改变产物、用户责任、真实身份或无法代替的素材缺口才停止澄清。非事实性文案可在用户授权或要求继续时补齐，并标记 `agent_generated`；不得伪造真实品牌证据、交易信息、检测结果、奖项、联系方式或可扫码入口。

## AI + Coding 生产拆分门禁

当路线为 AI + Coding 时，先完成自然语言 Brief 的主视觉、文字层级、准确源文案、配图与关系；Visual 草案形成后，新建／整体重做先比较同品类、同作用范围的 CSS 组合摘要，摘要不足时补读设计说明，再查询未覆盖或需替换的局部原子。用户锁定项不变，模型自选的布局关系可随组合比较调整；确无适用组合时才转原子组装或自主实现。最终 Brief 冻结后建立轻量素材清单，生产并准出图片，再读取选中实现与依赖并编写完整 HTML；局部修改只复查受影响部分。不在 Brief 或素材清单中创建 `render_text`、`asset_slots`、`font_bindings`、`template_bindings`、`elements`、`relations` 与 `validation_bindings` 等平行实现字段：

- 逐项标记用户／真实资产、AI 生成／编辑、抠图、文本 DOM、容器／CSS／内嵌 SVG 或混合生产方式；
- Brief 为每张图片记录用途、画面目标、目标区域、来源、参考职责、主体／背景关系、保护和禁用项；素材清单再记录生产方式、完整 Prompt、尺寸、安全区、后处理、消费者和准出标准；
- 只为首屏／首图主标题或每个独立图片中唯一最重要的大标题建立艺术字图片记录，同一图片默认最多一个；其他标题包括普通 H1 均在 Brief 标记为可编辑文字，并在 HTML 中使用真实 DOM；
- 素材清单只记录需要图片工具或预处理的 `cutout`、`crop`、复杂 `mask` 等资产动作；CSS 渐变、规则蒙版、层级和组装关系在 HTML 中确定；
- 需要图像工具的资产先完成生成、身份/来源、抠图、Alpha 和尺寸准出；生成／编辑结果即使存在质量或文字问题，也须先完成当前交付环境要求的闭环。艺术字等图内文字不准确时，记录问题并等待用户提出修改要求，不得自主重生；原生 DOM 文字仍须正常修正。
- Coding 只能组装已规划、已准出的资产与准确内容，不得先写整页再倒推生图区域。
- 工具返回后立即把生成短链、处理后短链和最终采用版本回写原素材记录及所有消费者；Brief 只在设计意图变化时更新。版本规则见 [Brief → HTML 门禁](../../../example/brief.md#版本与完整性门禁)。

## 内容与阅读结构

1. 先将内容按用户理解和行动所需的顺序排列，再进入视觉构图。
2. 只保留一个主命题和一个主行动；次要信息必须在尺度、位置和对比上从属。
3. 每个内容组只承担一个主责任：建立、解释、证明、对比、操作或收束。
4. 内容很少时不用装饰、随机英文和重复口号伪造密度；内容很多时先删重复、合并同义和建立结论，不盲目缩小字号。
5. 多页、多屏或多面产物需逐个设计单元记录责任、入口、出口和与前后单元的关系；不默认复制同一版式。

## 通用视觉执行映射

为每个产物建立一组有名的视觉规则，不只写“高级、简约、酸性、杂志感”等形容词：

- 视觉主张与构图：主体、文字、空间与媒介如何表达主命题；主轴、焦点、阅读顺序、负空间和边界。
- 文字与配色系统：展示、正文、数据／标签层级；背景、表面、正文与强调色职责。
- 图片与表面系统：视角、光线、轮廓、材质与后期；逐单元背景必须有纹理、肌理或渐变之一，保护局部文字静区。
- 容器与留白：逐单元说明卡片承载内容、轮廓、材质、配色、描边、阴影、透明度、内部留白与图文关系；无需容器时写开放排版。
- 边界处理与母题：融合还是分离、所需渐变／蒙版／纹理的用途，最多一个可识别母题及重复规则。

上述均为自然语言结果。内容框、padding、坐标、字距、色值与不透明度等执行值由 HTML 计算和绑定，不在 Brief 建参数表。

执行以下底线：

- 三秒内可识别主命题或第一任务；第一焦点不与多个同等重量节点竞争。
- 先建立尺度差、图文关系和负空间，再增加材质、贴纸、卡片或装饰。
- 只在内容确实需要边界、比较、局部承托或操作时建立容器；不将所有信息包装成同款圆角卡。
- 一个产物使用一组主字体关系、一个主色彩逻辑和一个主影像逻辑；变化来自责任与尺度，不来自逐区换风格。
- 文字压图时只处理文字附近的对比度，不给整张影像套无差别深色蒙版。
- 矩形生成图按最终槽位的取景需求规划比例和尺寸；图与框的比例差只用于评估取景，不直接证明拉伸。按素材指南检查实际横纵缩放差，容差不超过 1%；合法 cover／contain 不因图框比例不同而失败，须验收最终可见取景、主体与保护区及有效像素。无 fit 保护的直接填充和后续 transform 仍须检查真实横纵缩放。容器先测量文字并建立 content_box，再确定外框尺寸，不把文字挤贴顶边。
- 图像边界应明确时才添加细描边、内高光或低层阴影；应融合时才添加局部渐变覆盖、共享底色或预处理边缘。简单背景纹理从 `composition-principles.md` 的 Coding 清单选择，真实自然材质继续使用 IMAGE。
- 不为了“完整”同时启用大渐变、玻璃、霓虹、网格、拼贴和重投影。

含可编辑文字时，另行执行 [font-family-library.md](../../rendering/font-family-library.md)。需要细化已选构图时，再按需读取 [composition-principles.md](../shared/composition-principles.md)。电商详情页不使用本兜底文件，其容器门禁与卡片系统已内置于对应场景 Ref。

## 元素与生产路由

每个可见元素在 Brief 中记录责任、内容来源、生产方式和编辑形态：

| 元素 | 默认生产方式 | 底线 |
|---|---|---|
| 普通标题、正文、数据、日期、价格、CTA | HTML DOM 文字 | 保持准确、可编辑，不烘焙进图片 |
| 简单几何、线、色块、可控图标 | HTML DOM／行内 CSS／内嵌 SVG | 使用标准浏览器实现，不生成位图代替 |
| 复杂摄影、插画、环境、自然纹理 | 用户素材或 image 工具 | 不包含需逐字准确的文字、Logo、数据和二维码 |
| 人物、商品、真实证据 | 用户素材或已验证来源 | 不伪造身份、品牌、交易、评论或证明 |
| 需独立叠压的复杂主体／异形壳体 | CSS／SVG 可可靠表达的规则轮廓与结构用原生实现；复杂影像或材质用 image 工具 + 真实抠图 | 不按“异形壳体”等名称强制生图；图片透明边缘干净，不保留伪透明矩形底 |

本表只拆分主入口已锁定父路线内的元素职责，不重新选择路线。完整位图、PNG/JPG 或无分层要求本身不授权改走纯生图；通知／公告及长图／详情页等默认 AI + Coding 的产物，只有用户明确要求全部由图像模型生成且不要 HTML 排版时，才由主入口选择 pure-image，纯图长页在目标高度／宽度 > 16／9 时分段生成后拼接。社媒套图默认 pure-image，用户要求可编辑时进入 ai-coding；已进入本文件的可编辑套图按原生文字与图片素材分工实现，包括封面，不由本文件改道；未匹配品类也沿用主入口已确定的路线。

## 实现与交付

- Coding 产物必须使用自然语言 Brief 和完整 HTML；稳定元素 ID 只在最终 DOM 中管理，素材清单使用独立 `asset_id` 和人类可读消费者说明。
- 需要 HTML/CSS 时，以 `references/html/coding-rendering.md` 与 `references/cli/README.md` 为唯一协议事实源。
- 分图层 Coding 只生成 HTML/CSS；允许效果质量受协议限制而降级，不允许信息、位置、层级、主次和风格类别改变。
- 交付只包含用户要求的产物、真实素材、必要中间协议和验收证据，不附加无关样例、演示页或平行设计系统。

## 通用验收

交付前逐项核对：

- [ ] Brief 已记录通用兜底及无垂类 Ref 可匹配的具体原因，最终 HTML 的实现记录使用 `category_ref_key: generic-fallback`。
- [ ] 产物、数量、尺寸、比例、格式、可编辑性和交付范围与用户要求一致。
- [ ] 主命题、第一焦点、阅读顺序和主行动清楚，不存在多个同权重焦点。
- [ ] 用户文案、数据、标识、人物和商品身份未被擅自改写；补写内容的事实状态可追踪。
- [ ] 字体、配色、影像、材质、容器和装饰服务于同一视觉主张，不是风格词的随机拼装。
- [ ] 准确文字和简单图形保持可编辑；位图资产无乱码、伪 Logo、伪数据、伪二维码或未处理透明边缘。
- [ ] 缩略图、100% 视图和最终设备／打印尺度均已检查，无缺字、静默字体回退、意外换行、遮挡、越界或裁切。
- [ ] 所有交互、下载、编辑和导出能力都真实可用，不使用装饰按钮冒充功能。

## 禁止作为兜底的方式

- 不用统一白色圆角卡片、等高模块和胶囊标签填满未知场景。
- 不因没有垂类 Ref 就默认深色科技、蓝紫渐变、玻璃拟态、酸性拼贴或“大字 + 小卡”。
- 不把通用兜底写成新的隐式垂类模板，不为未知产物强制规定页数、模块数或固定 CTA。
- 不让本文件覆盖用户已确认的 Brief，也不在已匹配垂类 Ref 时与其并行执行。
