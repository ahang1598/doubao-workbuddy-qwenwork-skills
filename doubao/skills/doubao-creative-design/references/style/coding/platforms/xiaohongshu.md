# 小红书单页与套图首页 Reference

> 主 `SKILL.md` 已确定产物路线后，本文只补充小红书单页与套图封面的平台要求。普通新建套图沿 pure-image；明确要求可编辑的新建套图沿 AI + Coding，封面同样使用 DiT 主视觉资产＋Coding 准确文字与布局。本文不得重新路由；已有设计编辑沿原格式与授权范围进行。

本文档只负责小红书平台的内容钩子、移动端可读性、封面视觉语法和平台红线。它不决定套图页数、页面责任链、内页布局或连续性；这些由 [social-carousel-spec.md](../scenarios/social-carousel-spec.md) 负责。交付协议与实现也不在本文定义。

## 1. 使用边界

主 `SKILL.md` 先决策路线。小红书封面／独立单页及默认套图纯生图，全部文案随逐页完整图片生成；长图与可编辑套图按各自 Coding 规则执行，不能因“生图”措辞将其压平。

- **已选 pure-image**：转到 [纯生图小红书 ref](../../pure-image/media/media-xiaohongshu.md)，按纯生图 workflow 执行；本文不重复约束其生产顺序或结构。
- **可编辑套图**：由 `social-carousel-spec.md` 和 Social Visual 在同一 Brief 规划整体；本文只补充封面平台要求。封面完成真实分层渲染后返回套图 Spec，实际呈现当前版本并等待用户确认；确认前不得制作内页。仅指定局部可编辑时，该区域必须原生排字，封面不例外。
- **长图／已有 HTML 编辑**：由对应 Spec 决定内容与结构，本文只补充平台要求；既有完整 HTML 源不压平。
- **其他平台**：不得因为内容“像小红书”自动读取本文。

## 2. 单页执行链

意图与品类 → 主路由锁定产物方式 → pure-image 返回对应平台 Ref／AI + Coding 读取本文补充 → 返回对应场景 Spec 执行。套图封面完成后的呈现、暂停、确认和内页生产严格由 `social-carousel-spec.md` 决定；本文不定义工具调用、重试或交付时序。

## 3. 轻量 Brief

在已有 Brief 的首页条目补齐以下内容，不另建平台表单：

- 平台与画幅：小红书，默认 3:4，可按需求采用 4:5 或明确尺寸。
- 发布目的与钩子：向谁传达什么，为什么继续看。
- 准确文案：全部主标题、副标、必要事实及声明。
- 主视觉与图文关系：主体、构图、文字落点、阅读顺序和安全区。
- 视觉效果：具体风格、字体气质、颜色职责、图片处理及系列延续，用自然语言说明。
- 参考图：真实 URL 短链、具体借鉴内容与排除项。

有参考图时同时学习**视觉风格、布局关系、内容组织、叙事逻辑**，不只借颜色或贴纸。单页无需虚构多页叙事；套图首页只补“如何制造翻页理由”，完整页链、超量内容归属与拆页留给套图 Spec。

## 4. 内容钩子与可见文案

小红书可视化文案优先由三类组件组成：

1. **情绪钩子／主标题**：明确利益、场景、反差、问题或态度，不做空洞标题党。
2. **细节特征／副标**：用短语说明具体对象、适用场景、时间或证据。
3. **逻辑结构／序号**：仅在教程、清单、测评等需要结构感时使用，不为填满画面强加编号。

照片主导型封面可只保留主标题、日期／地点和少量注释；教程、测评、活动和信息型封面可加入副标或结构词。所有需要准确呈现的可见文字必须逐条写入同一 Brief，并由 HTML 原生文字落实，不得写“这里放标题”“若干卖点”等占位符。只有符合既有准入且不属于指定可编辑范围的艺术标题，才将准确文案与字形写入素材 Prompt。

## 5. 视觉策略

先根据内容选择真实媒介，再选择装饰。优先让人物、产品、物件、场景或具体插画承担主视觉，不把“纯色底 + 黑体字 + 同款圆角卡”当默认答案。

### 5.1 影像型内容

- **美妆／测评**：真实妆面、肤质、产品和质地是证据；可采用妆面主图 + 质地微距、产品色样板、对比联图或镜前日记。
- **穿搭／OOTD**：完整造型为主镜头，辅以动作、面料、鞋包和真实场景；可采用主图卫星、编辑式非对称网格、胶片接触印样或物件标本板。
- **Plog／旅行／探店**：用主镜头、环境、动作、细节和空镜形成照片日记；统一调色，以少量日期、地点和手写注释收束。
- **产品／食物**：以真实产品或食物细节建立可信度，避免用无关卡通图标代替主体。

### 5.2 图形与信息型内容

- **活动／运动／潮流**：可使用高饱和撞色、错位剪影、手工边缘、波普几何和强展示字，但信息仍须有主次。
- **教程／经验整理**：根据主题选择编辑杂志、日系手账、专业图解或实体文具拟物；容器需要有材质、尺寸和层级差异，不能铺满同款便签。
- **知识／严肃议题**：优先极简线框、专业编辑、数据图形或克制摄影；不得用幼态贴纸削弱可信度。
- **节日／节气**：以应季生活场景和主题符号为底，避免只换节日色和装饰贴纸。

### 5.3 字体气质

可编辑套图封面在 Brief 中描述字体性格、字重与效果；实际字体解析、资源验证、原生实现和后续内页字体继承统一返回宿主 `ai-coding.md` 执行。本文只给出封面的平台气质提示：

- 日常、旅行、手账：自然手写、圆润马克笔、轻松编辑体；
- 潮流、运动、活动：超粗展示体、倾斜压缩体、波普描边或膨胀字；
- 专业、克制、高级：现代无衬线、宋黑对比或窄体编辑标题；
- 同一张图控制展示字体数量，正文保持稳定可读，禁止所有层级都退化为同一种默认黑体。

## 6. 可编辑首页平台规则

- 小红书 3:4 封面以“杂志”级的版式秩序作为质量锚点，不要求所有成品都像传统纸媒封面，也不要求图像模型生成完整封面。
- 在同一 Brief 写清主视觉、标题位置、图文关系、材质、色彩职责和安全区；Prompt 编译、工具参数和素材记录返回宿主 `ai-coding.md`。
- 全部准确文案、字体特征、字色、字重、特效与信息层级由 Brief 驱动 HTML 原生文字；来源及占位声明不得遗漏。封面聚焦传播钩子，复杂规则与长正文是否拆页由套图 Spec 的容量规则决定。指定可编辑区域不得转为艺术标题位图。
- 有参考图时，把视觉风格、布局关系、内容组织与叙事逻辑的借鉴内容写成具体可见效果；参考输入、素材生产与 HTML 组装返回宿主 workflow，不在本文重复。
- 封面结果不得是无职责四宫格，也不得以完整位图冒充指定可编辑的原生文字；具体生成、组装与交付时序服从宿主 workflow。
- 可编辑套图封面完成正式分层渲染后，必须返回 `social-carousel-spec.md`：实际呈现当前封面并等待用户明确确认。平台检查、预览成功或 Agent 自检均不替代用户确认。

## 7. 平台红线

- 3:4 画布顶部 8%、底部 12% 不放关键信息；4:5 同样规避上下边缘 8%。
- 不仿造小红书原生 UI，不生成假点赞、假关注、假评论或站外导流信息。
- 不使用未授权 Logo、人物肖像或品牌资产；用户提供的品牌素材按原貌使用。
- 不把所有文字机械塞入同质圆角卡、半透明卡或便签；容器必须服务信息关系。
- 不做悬浮棚拍感的“假生活”；人物和场景应有真实动作、空间与光线依据。
- 不用机械纯色描边包住所有人物或物体；需要描边时应符合手工、印刷或主题材质逻辑。
- 医疗、金融、未成年人和功效宣称遵守相应合规边界，不虚构数据、奖项、入口或权威背书。

## 8. 最终验收

封面完成真实渲染后检查以下平台可见结果：

- 三秒内能否读出主题、对象和行动／价值；
- 主视觉是否真正支撑内容，而非角落装饰；
- 标题、副标、日期、金额和专名是否逐字正确；
- 字体气质是否落实，是否出现默认黑体统治全部层级；
- 卡片和容器是否有明确语义，是否出现同款卡片墙；
- 参考图的四轴是否都有可见对应；
- 缩到手机预览尺寸后，P0/P1 是否仍清楚；
- 顶部、底部和边缘安全区是否通过；
- 是否出现假 UI、站外导流、虚构事实或不合规表达。

素材错误处理、修改授权、媒体交付和 Coding 修正统一服从宿主素材与交付门禁，本文不另定时序。可编辑套图同时返回套图 Spec 检查当前封面用户确认门禁。
