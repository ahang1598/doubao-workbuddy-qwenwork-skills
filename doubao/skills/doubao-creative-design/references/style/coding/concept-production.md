# Coding 创意生产映射

仅供已选 coding 路线使用；pure-coding 不调用生图工具，复用其中的真实资产、原生文字与图形映射。AI + Coding 执行生图素材拆分。公共创意发散和选择仍读取 [公共创意](../shared/creative-concept-system.md)。

## 第六步：将选中概念交给生产

本节只在主创意选定后执行，用于衔接 AI 生图、Coding 与 HTML 生产，不属于候选创意“落地性”的定义。候选阶段只要求把意义说成具体事物、可见动作／关系、构图和明确后期手法，不要求提前填写坐标、资产清单、风险等级或降级方案。

### 1. 先拆资产，不生成整屏替代设计

把概念拆为：

- 用户必须提供或必须继承的真实主体；
- AI 生图生成的背景、环境、人物、复杂物件、材质、独立主体或经准入的艺术标题；
- HTML DOM／CSS／内嵌 SVG 生成的准确文字、色块、简单几何、线条、路径、图表、价格、参数、日期、标签和 CTA；
- 需要抠图、遮罩或前后景穿插的独立资产；
- 只用于预览、不得进入最终交付的临时参考。

AI + Coding 项目必须在此处完成“生图资产 vs Coding 元素”的第一轮生产规划。每个概念元素都要先指定 `carrier` 和 `production`，并说明它最终进入哪个 `asset_slot` 或可编辑层；没有完成拆分时，不得开始整页 Coding、HTML 坐标或 HTML 组装。Coding 不是用来先搭一张页面再寻找生图位置，生图也不是用来替代已经规划好的准确文字、数据和规则结构。

AI 生图必须服务已选概念，Prompt 写出主体、动作、空间、镜头、光影、材质、负空间、画幅和排除项；不得只写风格形容词。除通过准入的独立艺术标题外，图片 Prompt 不包含传播文字。

### 2. 概念到 最终 HTML

每个核心机制必须有明确载体：

```text
concept_element:
  semantic_role:
  visual_behavior:
  carrier: text-dom / container-dom / inline-svg / image-dom
  production: coding / user_asset / image_generate / image_edit / cutout
  geometry:
  z_order:
  continuity:
  fallback:
```

如果概念只能存在于自然语言描述，无法映射为图层、坐标、资产或可验证关系，则概念尚未完成。

### 3. 生图与 Coding 的共同构图

- 生图资产必须预留真实文字净空和叠压边界；不得生成后才在角落寻找放字位置。
- 背景元素应能进入主体前后，建立景深与空间关系；不能把所有素材并排摆在同一平面。
- 独立主体按最终遮挡和破框需求生成／抠图；完整场景保留有意矩形边界。
- Coding 不是后贴字幕。标题、数字、线条和图形必须参与主轴、尺度与节奏。
