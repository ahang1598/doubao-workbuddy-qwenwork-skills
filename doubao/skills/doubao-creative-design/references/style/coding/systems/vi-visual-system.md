# VI 视觉表现规划

## 读取入口

读取 [VI Spec](../scenarios/vi-spec.md) 保存的同一 Brief 中“VI 内容与系统结构”。缺少必要母版、系统范围或准确文案时返回 Spec，不创建副本，不新增未经授权的 Logo、角色或应用。

进入本 Visual 前，应已由 VI Spec 在初始 `required_refs` 阶段读取 [VI HTML 交付规范路由入口](../../../workflow/vi-html-delivery-route.md) 及其公共 HTML Ref 和当前环境分支。Visual 的章节、分页、画板和长板决策只能改变同一个完整 HTML 内部的呈现，不得改变“禁止直接交付 HTML、唯一完整 HTML、默认 Canvas 唯一顶层 HTML Item、Mobile 仅 CDN＋Markdown 预览”的交付结构。除 Logo 测试、色板、规范示意及具有明确品牌色／信息职责的功能纯色区外，普通展示背景必须用纹理、肌理或渐变等可观察机制建立变化，不得以无变化纯色铺满；具体背景 Prompt 继续读取 [背景图 Prompt](../ai-coding/asset-prompt-guide.md#5-背景图-prompt)。

Spec 负责事实、内容、范围、母版与授权、来源和交付边界；Visual 负责在这些内容上形成视觉命题、身份规则、字体与颜色关系、构图、图像、材质、应用变化和可观察验收。保留 Spec 的全部有效内容，在原章节、文案、配图与应用条目后丰富视觉，不另建内容来源、视觉 Brief 或机器计划。

## 最高优先级门禁：确认后的 Logo 唯一视觉锚点

已确认 Logo 是 VI 后续衍生创作的唯一视觉参考。任何背景、角色、插画、产品氛围图、应用场景或 Mockup 只要需要调用图像工具，就必须使用 `image_edit`，并且只传入该 Logo 母版这一张图。不得调用 `image_gen` 从零生成，不得追加风格、材质、角色、产品、场景、平稿、候选或其他衍生图作为第二参考，也不得把文字 Prompt、URL 字符串或对 Logo 的口头描述当作已经传入 Logo。

该规则优先于下文的风格候选、摄影母版、角色媒介翻译、背景 Prompt 和应用场景示例。其他真实资产可以直接复用或由 HTML 确定性放置，但不能加入 `image_edit` 的参考输入。Logo 母版不可取得、未确认或存在冲突版本时，停止图像衍生，只允许继续原生 HTML、CSS、SVG 和内容规划；需要第二张图片才能完成的编辑也必须停止并报告冲突。

本 VI 禁止建立独立辅助图形、Pattern、装饰性 Icon 或纹样系统。视觉变化必须来自确认 Logo／字标的真实使用状态、品牌色面积、字体层级、IP／产品／摄影内容、材料、裁切和版面关系，不能为了填满页面另造一套图形语言。

## 最高优先级门禁：首屏必须直接由 Logo `image_edit` 生成

确认 Logo 并向用户告知完整设计规划后，Main Agent 开始正式 VI 图像生产时，第一项资产必须是首屏效果。实际调用固定为 `image_edit`，参考输入固定为一张已确认 Logo 母版；不得用 `image_gen`、HTML-only 首屏、纯色底加原 Logo、无 Logo 氛围图、预制模板或第二张参考图替代。目标尺寸与比例直接使用最终首屏需要的画幅；未指定宽幅 VI 时按 `1600 × 900 px` 的 16:9 首屏视域规划。

这张首屏效果必须按照本文件“开场视觉与章节节奏”的既有定义，在沉浸裁切、标志／角色整合、封套陈列或身份系统预告中只采用一种主结构，并在单张输出中建立唯一最大主体、品牌主色场、同源光色／材质／空间关系、必要文字净空和通向第二章的连续线索。它不是单独的 Logo 图、随机背景图、应用 Mockup 缩略图或候选墙，而是整套 VI 的完整封面主视觉基础。

`image_edit` 结果必须核对 Logo 拼写、字形、轮廓、比例、负形与颜色职责。为保证身份精度，HTML 组装时允许在首屏效果上用由同一原始 Logo 母版经 MediaKit 去底并验边通过的透明排版版本进行准确覆盖，并使用 HTML/CSS 原生文字完成标题、短命题与 `Brand Identity System` 类职责说明；但不得以覆盖层为理由省略首屏效果生成，也不得让错误 Logo 留在底图中与正确母版重叠。

## 最高优先级门禁：排版 Logo 透明化与大尺度占版

已确认 Logo 母版继续作为 `image_edit` 的唯一视觉输入；但 Logo／字标一旦作为独立图片层进入 HTML 首屏覆盖、规范区、应用平稿、Identity Kit 或展示板，就必须是无图片背景的真实透明资产。带白底、黑底或其他矩形背景的位图，必须在排版前调用 MediaKit CLI：`MEDIAKIT_SURFACE=skill MEDIAKIT_RUNTIME=codex mediakit-cli --cloud image remove-image-background --image-url "<logo_url>" --scene general --output-format png`。命令同步返回后记录原始 `image_url`、输出 `image_url`、尺寸、格式与版本关系；已有可靠 Alpha PNG 或无底 SVG 只核验，不重复抠图。

禁止在 VI 排版里保留 Logo 图片背景，禁止使用 `mix-blend-mode: multiply`、`screen`、CSS 滤镜、同色底块或裁切矩形伪装透明。MediaKit 结果必须在浅色、深色和最终品牌底色上检查外轮廓、字腔、内部孔洞、负形、细笔画、白边／色边、误删与残底；失败时停止消费并报告，不重绘 Logo，也不回退到带底版本。该透明版本仅是同一母版的排版就绪衍生物，不取代身份母版，也不改变 `image_edit` 唯一参考规则。

整套 VI 采用“大图、大字、低空白”的默认尺度策略：Logo、主视觉、摄影、场景、应用物料、章节标题、关键数字和首屏命题都从可读性、净空、安全区、裁切保护与真实载体边界允许的最大尺度开始排版，再按冲突最小幅回退。优先让主体出血、跨栏、贴近安全边界或形成清楚的大中小尺度差；禁止小 Logo、小图片、小字号和窄栏内容漂浮在大面积无职责空场中。留白只服务阅读分组、品牌净空、节奏和制作安全，不作为“高级感”的默认装饰。

## 最高优先级门禁：先确认 Logo，再设计 VI

用户已经提供并确认可用 Logo 时，不再生成多风格 Logo 候选，直接把该 Logo 登记为唯一母版并进入 VI 规划；这只跳过候选选择阶段，不跳过 Logo 唯一视觉锚点门禁。用户没有提供 Logo 时，必须先依据 Spec 生成多个核心概念、造型路线和视觉气质明显不同的 Logo 方向，逐一交付并说明差异，让用户选择。禁止用换色、换字、轻微变形或不同 Mockup 冒充多个风格；用户未明确确认其中一个方向前，不得开始任何 VI 系统的视觉生产。

正式进入 VI 设计前，必须向用户输出完整设计规划。规划应覆盖品牌理解、Logo 母版或候选状态、推荐视觉方向与理由、VI 范围、颜色／字体／影像／IP 系统、应用触点、展示结构、资产生产顺序、确认节点、交付物和验收边界。没有 Logo 时先输出含候选阶段和选择门禁的规划；Logo 选定并确认后，以确认母版更新规划，告知用户后才进入正式 VI 设计。内部 Brief 不能替代这次用户可见的规划输出。

## 最高优先级门禁：Subagent 仅用于 HTML 生成

VI 设计中，除完整 HTML 生成／修改和 `shot.py` 自检外，不得调用 Subagent。Main Agent 必须亲自完成 Ref 读取、Brief、规划、Logo 候选、首屏与全部素材生成、`image_edit`、MediaKit、检查、选稿、返修、Workspace、CLI 写入／回读、CDN、`FileBatchUpload` 与用户交付。任何图像／视频／处理结果都由 Main Agent 直接取得原始短链并完成 [交付门禁](../../../workflow/image-generation-delivery-gate.md) 的双通道闭环；不得让 Subagent 生产素材、操作工具、上传文件或代做复核。

### 完整 VI 手册 HTML 的 Subagent 组装门禁

所有 Logo 候选、确认母版及正式 VI 素材由 Main Agent 完成各自交付闭环后，开始组装或修改完整 VI 手册 HTML 页面时，Main Agent 必须调用 Subagent 执行。Subagent 只能使用已经确认且已闭环的素材，按照 [HTML 组装](../../../workflow/html-assembly.md) 生成完整页面，并按 [HTML 检查执行流程](../../../workflow/html-validation.md) 使用 `scripts/runtime/shot.py` 完成自检；HTML 返修仍由 Subagent 在这一阶段完成。随后 Subagent 向 Main Agent 回传完整 HTML 文件、`data-canvas-width`、`data-canvas-height`、同尺寸本地预览结果、预览／校验状态、建议画布 `path`、完整 `brief` 和创建意图，并立即停止。Subagent 不得上传 CDN、调用 `FileBatchUpload`、操作 Workspace／CLI、调用 `present_files` 或直接向用户交付 HTML、预览及画布卡片。

VI 手册完全复用公共 HTML 交付策略，并严格按以下编号顺序执行：

1. **CDN＋Markdown 同尺寸预览**：Main Agent 接收 Subagent 使用 `shot.py` 自检后的完整预览图，核对截图像素与 HTML 声明宽高一致，由 Main Agent 将预览图上传 CDN，亲自核验公网 HTTP(S) 链接可访问，再用标准 Markdown 图片语法展示。该预览必须输出，但不调用 `present_files`、不创建 IMAGE Item、不写入 Workspace。
2. **上传完整 HTML（仅默认 Canvas）**：Main Agent 使用 `FileBatchUpload` 上传完整 `.html` 文件并取得原始短链；Subagent 禁止执行上传。禁止直接向用户交付 `.html` 文件。
3. **创建唯一顶层 HTML Item（仅默认 Canvas）**：Main Agent 使用该短链执行 `design-cli ... +create`，协议中只允许一个顶层 `<item type="HTML">`。`+HTML` 不是 CLI 命令；禁止创建 `<frame type="HTML">`，禁止按章节拆成多个 Item。
4. **回读（仅默认 Canvas）**：取得 Item ID 后执行 `design-cli ... +get`，核对 HTML 短链、类型、`path`、`brief` 与对象 ID。
5. **交付画布卡片（仅默认 Canvas）**：回读成功后调用 `present_files("<workspace_id>?item_id=<item_id>")`。

`Device platfrom: Mobile` 环境只执行第 1 步，完成 CDN＋Markdown 预览展示后停止；禁止执行第 2–5 步，包括 HTML 上传、Workspace、CLI、Item 和画布卡片。预览自检失败时保留视觉未验证状态并遵循公共预览例外；默认 Canvas 可以继续执行第 2–5 步，但不得把截图失败改写为成功。缺少第 1 步，或默认 Canvas 缺少第 2–5 步任一闭环时，不得宣称 VI 手册完成。

整体规则写一次，逐章、逐应用只补差异。全篇以自然语言描述可见关系；品牌规范所需的准确色值和真实尺寸可记录，CSS 参数、模板 ID、文件依赖、槽位契约、工具字段和评分清单不进入 Brief。方向草案须可调整：新建／整体重做先比较适用组合并适配真实内容，再补局部原子，最终冻结 Brief 后才读取选中实现。

## 背景系统与 Prompt 规则

整套 VI 必须建立可持续的品牌背景机制，但不强制每页都使用纹理、肌理或渐变。背景机制可以来自连续品牌色域、摄影场景、Logo／字标裁切、材料表面、纹理、肌理、渐变或空间光影；准确规范区、Logo 测试、色板和说明区可以使用干净纯色。纯色若承担明确品牌色、留白或信息职责，就是有效设计，不得为满足字段机械增加渐变、噪点或无关装饰。

每次写出具体系统底图、材质背景或应用场景背景 Prompt 前，必须先读取并遵循 [背景图 Prompt](../ai-coding/asset-prompt-guide.md#5-背景图-prompt)，按其中的背景职责、纹理选择模型和完整 Prompt 编译语法描述材质、色场、变化方向、尺度、低纹理区与连续关系。凡实际调用图像工具生产此类素材，必须调用 `image_edit` 且只传入已确认 Logo 母版；背景规则只负责 Prompt 编译，不能改变唯一参考输入。直接复用真实背景时不强造 Prompt，但必须记录使用方式并检查本节结果门禁。

结果门禁不等于全板叠噪点。真实场景已有的色域、材质、渐变与光影可承担背景职责；准确规范区保持清楚，不要求每章都加装饰，不在已有场景照片上重复覆盖全板纸纹。整套作品只需让背景选择与品牌语言一致，并在沉浸区、规范区和应用区之间形成有依据的强弱变化。

## 风格选择与主机制

从品牌价值提炼一个语义锚点，说明它如何转成形态、色彩、材质、空间或行为。视觉命题应是可持续运用的关系，不只列“年轻、高级、科技”等形容词。

风格从品牌认知、受众、母版、参考和业务场景推导，不以行业名称套色或套材质，内容密度也不自动决定风格。方向未定时比较机制真正不同的方案；已有明确参考时，不为凑方案数量另换风格。最终选一个主方向，辅助手法服务主机制；品牌可跨多个媒介，但必须有共同的识别规则。

决策优先级写入原 Brief：用户锁定项与参考约束、获准 Logo／身份母版及品牌规范优先，随后明确应用事实、可调整项和 Agent 可裁量项；公共组合或实现默认值不能覆盖用户锁定项。

| 风格候选 | 选择线索 | 如何形成系统 |
| --- | --- | --- |
| 瑞士模块、几何现代主义 | 精确、秩序、清楚组织 | 比例、转角、字级、编号、留白与网格跨载体复用，不仅展示辅助线 |
| 人文编辑、出版档案 | 叙述、内容、文化感 | 图片裁切、标题节奏、边注与栏目关系成为共用语言 |
| 手作纸本、印刷工艺 | 手工、材料、触感有品牌依据 | 真实制作动作、印记、纤维与套色转成识别机制，保持一致尺度，不伪造历史 |
| 数字动态、透明层叠 | 状态、连接、流动是表达重点 | 聚合、伸展、循环、路径、弹性与叠色可解释，不只是蓝紫渐变 |
| 角色插画、趣味拟物 | IP 有明确品牌职责 | 角色轮廓、动作、行为与场景承担沟通，不等于每页贴吉祥物 |
| 纪实摄影、生活方式摄影 | 产品、人物或真实空间是认知来源 | 统一镜头、景别、光线、材质响应与构图，不仅使用同一滤镜 |
| 空间导视、工程图形 | 方向、尺度与实际环境重要 | 远近层级、标识、路径和环境材料在平面与空间中对应 |
| 实验拼贴、受控极繁 | 用户希望强表达且允许视觉实验 | 主次密度、裁切、强母题与材料碰撞形成规律，不混装无关风格 |

风格名称不能代替品牌独有特征。例如“圆角开口来自母版，重复成可调密度的图案；在袋体上疏朗，在数字页角收紧”，比“保持品牌感”更可执行。

### 风格组合配方

风格不能只从上表选择名称。最终方向必须同时冻结颜色结构、字形性格、身份来源、图像处理、材料强度和版面密度，使各系统像出自同一品牌，而不是独立套用字体、装饰图形和 Mockup。

| 组合配方 | 色彩与字形 | 图形与图像 | 版面与材质 | 适用边界 |
| --- | --- | --- | --- | --- |
| 高饱和角色识别 | 单一强主色占绝对主导，奶油白／浅中性色建立反差，少量暖色只作节奏；展示字粗重、圆润或受控稚拙 | 直接使用获准角色的动作、表情与身份部位组织画面；图片以角色、产品和少量真实场景为主，不派生辅助图形 | 大色块、紧凑模块、受控复古印刷颗粒；不能退化成儿童绘本或每页贴同一角色 | IP、餐饮、新消费与社交型品牌；没有确认角色母版时不得启用 |
| 手作编辑式品牌 | 双色或低色数为主，材料色只作辅助；字标、展示字和线描共享手写力度、圆角与不规则程度 | 从产品、食材、工具或制作动作提取线描母题；摄影保持自然、克制和真实材料感 | 编辑式留白、不对称拼贴、纸面颗粒或轻套印；避免卡片堆叠、蓝紫科技渐变和全板统一噪点 | 手作、文化、咖啡、烘焙与工作室品牌；手作感不得损害正文可读性 |
| 温暖产品生活方式 | 暖中性色承载大面积背景，品牌主色建立识别，产品／食材色形成支撑；字体圆润友好且商业可读 | 产品英雄摄影决定光色；原料、叶片、器具或产品直接作为真实内容，不抽象成辅助图形 | 大 Hero、清楚规范区和应用矩阵；使用自然侧光、真实台面与适量环境对象 | 食品、饮品、美妆与生活方式品牌；不得滑向促销电商页或无品牌依据的奢华棚拍 |

三种配方是可执行关系，不是模板编号。品牌可以采用其他方向，但必须以同等颗粒度写清六类关系。不得从多个配方各拿一个显眼效果拼装，也不得为了“高级感”自动加入玻璃、金属、辉光或多色渐变。

### 色彩面积、同源语言与密度

- **色彩面积关系**：写清绝对主导、次要支撑和少量强调的颜色角色，以及它们在首屏、规范区和应用中的面积变化。低色数优先验证；`2–4` 个主要颜色角色足以建立系统时，不增加无职责新色。颜色职责不能在不同应用中任意交换。
- **身份元素同源**：Logo 字形、展示标题、获准 IP、产品图像与摄影处理至少共享两项可观察特征，例如笔画粗细、圆角／切角、开口、倾斜、轮廓节奏、色彩面积或材料响应。不得另建辅助图形、Pattern 或装饰性 Icon 来补足所谓品牌感。
- **版面密度模式**：整套先选择高密度系统板、低密度编辑板、商业平衡板或实验拼贴板中的一种主要密度逻辑，再按章节职责局部变化。高密度依靠对齐和分组，不靠缩小文字；低密度依靠主次和留白，不靠空洞；商业平衡以大 Hero、清楚规范和应用证据形成节奏；实验拼贴仍须由统一母题、裁切与色彩控制。
- **亲和型消费品牌**：需要亲和、轻松或年轻时，明确控制为友好而非幼稚、手作而非粗糙失控、商业清楚而非企业模板化、产品诱人而非促销堆字。不得仅靠圆角卡片、卡通人物或暖色宣称亲和。

### 补充方向与局部小效果

局部纸纤维、编号、网点与轻套印可增加档案印刷感；扫描线、偏移和高对比可服务酸性数字表达；裁片、胶带、手工边与轻叠压可表达素材关系；透明、金属、软体或光场可围绕主体轮廓形成触感。克制表达可以减少装饰、增加留白和规则线，但仍须保留品牌特征。

每种小效果说明承载对象与用途，只在适用章节使用，不能让每章同样热闹，也不能用单一材质代替完整品牌语言。

## 固定、变化与派生规则

用中文写出“输入 → 操作 → 输出 → 保留项”：

- 固定项：获准 Logo 的轮廓、负形、字形与组合，主要形体和笔画语法，颜色角色，字体节奏，图像语言与 IP 身份。
- 可变量：版面方向、尺度、裁切、排列、图像景别、场景，以及已许可的表情姿态、服装道具和材料；不笼统允许任意变化。
- 变换方法：通过 Logo 家族状态、字标尺度、品牌色面积、图片裁切、主体景别、IP 动作和材料响应形成变化；不得把 Logo 拆解成新的装饰图案。
- 禁区：拉伸 Logo、换字、交换关键颜色职责、另造脸型、删除关键身份部位，或发展辅助图形、Pattern、装饰性 Icon、纹样与第二套身份体系。

Logo 家族、IP、产品与图像系统分别保留稳定身份，并通过颜色角色、字体节奏、动作、材料、裁切和版面关系形成同一品牌；不要求也不允许额外建立辅助图形系统来连接它们。

系列必须在共同规则中改变真实内容、主体、裁切、局部色彩或用途，不只是同图换字、角色换背景；多状态和跨媒介序列突出继承与差异，不能把三套独立设计并排称为系统。

## Logo 设计与家族规范

本节只消费 Spec 已冻结的准确品牌名、核心概念、形式职责、语气和使用环境，不从参考图复制具体标志、品牌名、角色或构图。新 Logo 的任务是把一个有依据的品牌记忆点压缩成清楚、独特、可复用的识别结构；不是把行业常见图标、首字母、笑脸和装饰字体随意拼接。

涉及 IP 角色 Logo、角色与名称组合、字标描边、身份容器或 Logo 背景时，完整读取 [Logo IP 角色、字标描边与背景处理参考](../../shared/logo-ip-wordmark-background-reference.md)。共享参考用于建立角色压缩、描边职责和背景分层；VI 中独立 Logo 图片层仍以本文件的 MediaKit 去底规则为最终覆盖项。

VI 延展必须继承 Logo 已确认的线条语言，并以六个维度记录：线重、端点、转角／曲率、闭合与开口、黑白节奏和表面完整度。角色插画、展示字、灯牌、工牌、T 恤和周边可以改变尺度与材料，但不能把“粗圆等线卡通＋受控稚拙”擅自换成精细描线、写实明暗或另一套卡通笔触；材质颗粒只改变表面，不改变干净骨架。

### 最高优先级：已知品牌名必须与标记共同输出

只要品牌名称已经明确，每个候选和确认后的标准主标都必须包含准确品牌名，并设计为字标或图文组合标。不得只输出独立图形、角色头像、物件符号、抽象标记、首字母图标或无名称徽记；不得把名称缩成角落注释或与 Logo 无关的普通排字。独立图形标／角色标／缩写标只能在含品牌名的组合母版确认后，作为同一响应式家族的附属状态派生。名称未知时必须返回 Spec 澄清，禁止用占位名称、随机英文或纯图形先行。

### 1. 黑白优先与核心轮廓

Logo 先在纯黑／纯白条件下成立，再进入品牌色、材质和应用。第一轮正式比较至少同时查看黑标白底与白标黑底，检查整体剪影、视觉重心、主负形、字腔、笔画连续性和远距离识别；颜色、渐变、阴影、纹理与 Mockup 不能掩盖结构问题。

- 单色状态必须保留核心概念和主要识别关系，不能去色后只剩普通文字或无法辨认的图形。
- 轮廓应能在缩略图中形成独特外形；内部细节只服务概念和识别，不用大量微孔、发丝线、碎片或小装饰制造复杂度。
- 负形必须有明确语义或结构职责，并在正负反转、小尺寸和不同输出方式中保持；不能为了“巧思”强行塞入第二、第三个隐喻。
- 圆形、方形、字母和几何基础形可以使用，但必须经过比例、切口、连接、负形或节奏上的品牌化处理，不能停留在通用模板符号。

### 2. 核心概念与造型路线

每个候选方向只保留一个核心概念和一套主要造型操作。用户没有提供 Logo 时，必须从适合 Brief 的不同路线中形成多个可比较方向；候选之间应在语义压缩、结构机制和视觉气质上真正不同，而不是只换字体、颜色、旋转角度或外框。品牌名已知时，每个方向都必须把同一准确名称纳入 Logo 本体。用户已提供并确认 Logo 时跳过候选生成。可选路线按实际 Brief 选择，不要求机械覆盖全部类型：

| 造型路线 | 核心要求 | 常见失败 |
| --- | --- | --- |
| 定制字标 | 从准确品牌名的字符、音节、重复字形或发音节奏建立独有轮廓；统一笔画、字腔、圆角／切角和基线 | 直接套现成粗体、随意挤压、为了造型破坏拼写 |
| 几何图形标／字母标 | 用有限形体、切口、连接和负形形成稳定剪影；字母含义必须可追溯 | 通用圆圈加首字母、随机几何堆叠、依赖说明才看懂 |
| 图文一体标 | 图形与字标在笔画、基线、负形或轮廓上互相生成，拆分后仍有明确职责 | 图标放左文字放右却声称融合、图形遮挡关键字符 |
| 角色／物件标 | 用最少轮廓和表情保留角色或产品记忆点，并与字标共享线条性格 | 细节过多、小尺寸糊成一团、角色与品牌名像两套设计 |
| 有机粗体／实验字形 | 通过受控膨胀、压缩、连笔、错位或不规则建立个性，同时保持准确字符识别 | 所有字同样扭曲、字腔堵塞、只剩潮流字体效果 |

### 参考样本提炼的 Logo 风格母题库

以下母题来自对参考样本共同造型规律的抽象，只用于建立候选差异和质量标准，不复制任何具体品牌名、角色、字形、轮廓、负形或组合方式。选择母题时以品牌事实和使用环境为先；每个候选以一个主母题为核心，最多加入一个有明确职责的辅助母题，禁止把多个显眼特征拼成风格杂烩。

| 风格母题 | 可见特征 | 构造方法 | 适合的品牌气质 | 必须避免 |
| --- | --- | --- | --- | --- |
| 几何负形符号 | 黑白高对比、稳定外轮廓、圆／方／切口中藏有字母、对象或方向关系 | 从一个基础形出发，通过切除、嵌合、镜像、旋转和共享边形成单一主负形；细节服从整体剪影 | 理性、创新、设计、科技、空间、专业服务 | 通用圆圈加首字母、隐喻过多、只有解释后才能辨认、细缝在小尺寸消失 |
| 模块构成字标 | 字母被压缩、堆叠、拆分或重组成紧凑色块，字与字之间形成共同轮廓 | 统一笔画重量与模块尺度，用重复形、共享竖画、切角和负形建立节奏；先保证准确拼写，再控制实验程度 | 文化、潮流、创意机构、音乐、数字品牌 | 为造型牺牲读音和字序、机械拉伸现成字体、每个字符使用不同规则 |
| 有机膨胀粗字 | 粗重、圆润、柔软、略带手工不规则，字腔小但仍清晰，整体像连续形体 | 对字干做受控膨胀、局部压缩、连笔和基线跳动；保持一致圆角、黑量和内部留白 | 餐饮、生活方式、年轻消费、亲和社交品牌 | 软塌无骨架、字腔堵死、所有字同样扭曲、直接套用复古泡泡字体 |
| 复古角色徽记 | 简化角色头像或物件与粗体字标组成强记忆组合，常以低色数和线面关系建立亲和力 | 角色只保留能识别身份的轮廓、表情和标志部位；字标与角色共享笔画、圆角、色块或时代语汇 | 餐饮、零售、社区、儿童友好但面向大众的消费品牌 | 角色细节过多、卡通与字标像两套系统、用怀旧滤镜代替原创结构、未经依据添加年份或城市 |
| 物件／角色融合标 | 产品、动物或人物动作直接参与字母、容器或负形，图形和名称互相生成 | 选择一个与业务强相关的物件或行为，将其轮廓嵌入首字母、字腔、基线或外框；融合后仍能拆出清楚主标 | 咖啡、餐饮、宠物、娱乐、体验型服务 | 图标仅摆在文字旁却声称融合、物件喧宾夺主、使用通用杯子／笑脸／动物剪影 |
| 动势轨道与开放环 | 弧线、箭头、开放圆环、倾斜或连续路径带来速度、循环、连接和方向感 | 以单一运动路径控制字标或符号，让开口、终点和重心与品牌行为一致；静止状态仍保持平衡 | 运动、音乐、出行、连接型产品、实验文化 | 随意加箭头、旋转后失去阅读方向、动势与品牌行为无关、线条过细 |
| 极简物件字标组合 | 一个高度简化的物件／角色符号配合紧凑粗字标，低色数、留白明确、远距离识别强 | 将物件压缩为少量大轮廓和一个关键动作，字标使用同等视觉重量；通过基线、重心或轮廓咬合建立整体 | 门店、餐饮、个人品牌、轻松但需要商业清晰度的品牌 | 插画细节多于标志、符号与名称等权分离、只在大尺寸成立、缩小时表情消失 |
| 角色主标＋定制字标锁定 | 角色／物件与完整品牌名构成一个共同主标，常见为左图右字、上图下字或角色与字标咬合 | 先稳定角色轮廓和准确字形，再用共同描边、粗细、圆角、色块、基线或遮挡建立锁定关系 | 音乐、餐饮、潮流、娱乐、宠物、社群和人物型品牌 | 只画角色不写品牌名、角色像插画而字标像后贴、遮挡关键字符、依赖场景才成立 |
| 复古人物肖像＋脚本字标 | 单色／低色数人物头像配合粗脚本或衬线字标，主次明确、有招牌与手作感 | 将肖像压缩为稳定面部剪影和少量身份特征；字标保持宽笔画、清楚字腔和受控连笔 | 餐饮、甜品、手作、理发、地方零售、个人品牌 | 肖像过度写实、脚本字不可读、虚构年份／产地／人物故事、品类词抢主名 |
| 双语／双层名称锁定 | 主品牌名最大，第二语言或合法短描述形成稳定次层；可横向或上下堆叠 | 固定主次比例、共同对齐轴和唯一断行；第二层只使用已确认信息 | 跨语言品牌、本地门店、文化消费、国际化产品 | 随机翻译、双语等权竞争、副语言不可读、擅自新增口号或品类词 |
| 响应式排布家族 | 同一字形和图形在拱形、横向、纵向、图文组合、纯字标等格式中保持身份连续 | 先确认唯一主母版，再只改变排布、比例和从属信息；核心字形、角色、负形和颜色职责保持不变 | 需要包装、招牌、头像、社媒和多尺寸载体的品牌 | 把不同候选混称家族、每种格式重画核心字形、用应用变化掩盖主标不成立 |

这组参考的共同质量特征必须吸收：优先用黑白检验结构；采用少量粗壮形体而不是碎细节；让字形、图形与负形共同承担识别；允许亲和、幽默和复古，但仍保持商业可读性；从一开始考虑横向、纵向、紧凑标和小尺寸状态。色彩和 Mockup 只能验证风格延展，不能替代标志本体成立。

### 角色／图形与品牌名的组合补充

角色／图形必须与准确品牌名形成一种清晰主关系：横向并列、上下堆叠、嵌合／咬合，或字标主导＋图形陪衬。横向组合共享中线或基线；上下组合由品牌名承托角色；嵌合组合不得遮挡关键字符；字标主导时图形只能强化名称记忆，不能变成随机贴纸。一个标准主标只选择一种主关系，不同时堆叠多种构造。

角色与字标至少统一两项可观察语言：笔画／描边重量、圆角、主色角色、负形、基线节奏或外轮廓倾向。粗描边、贴纸白边、投影边和高饱和色底只在品牌气质需要时采用，不得用来掩盖两者割裂。场景照片只属于应用验证；标准母版仍须在干净深浅底上独立成立。

双语、主名＋品类描述或双层名称只使用用户确认文字，主品牌名必须先读；第二层通过更弱字重、字号与间距形成从属，并与主名共享对齐轴。禁止自由添加翻译、域名、口号、品类词、年份、注册符号或社媒账号。所有角色＋名称组合至少检查单色正版和反白版，保证表情、轮廓、名称字腔与锁定关系不依赖彩色、白边或场景背景。

### 多风格候选的组织方法

用户未提供 Logo 时，先根据 Brief 从母题库选择若干真正适配且彼此差异明显的主母题。候选至少在“身份来源”和“形态结构”两个维度同时不同，例如一个以几何负形符号为主、一个以有机定制字标为主、一个以角色／物件融合为主；不能只在同一有机粗字路线内改变圆角、颜色或排版。每个方向需同时给出：一句核心概念、主母题、造型操作、黑白识别方式、适用场景、小尺寸风险和不采用其他母题的理由，供用户做真实选择。

### 3. 字标与 Logo 标记同源

字标不是普通字体加图标。定制字标应明确哪些字符被重绘、连接、切开、旋转、嵌合或形成负形，并统一笔画重量、字腔尺度、圆角／切角、端点、倾斜和视觉节奏。图形标或角色标与字标至少共享两项可观察特征；若刻意形成对比，也必须说明由共同基线、负形、色块或比例维持整体。不得在 Logo 家族之外新增辅助图形。

逐字检查品牌名，不得出现错字、缺字、多字、形近字替换、不可辨认连字或未经确认的大小写变化。中文、拉丁字母、数字和描述语分别进行字距、基线和视觉重量修正；不能用软件机械居中、数学等距或默认 kerning 代替光学校正。

需要描边时先保留无描边、可读、可降级的字形骨架，再根据用途选择单层对比描边、贴纸白边、双层轮廓、偏移投影边或手绘粗糙边。描边是被确认的字标变体，不是 HTML 临时特效；其内外转角、线重和角色轮廓必须同源，且不得封闭字腔、粘连字符或在反白／小尺寸时破坏拼写。贴纸切边、灯牌发光边和周边保护边登记为应用状态，不能反向成为唯一母版。

### 4. 光学校正与结构质量

- 调整字符间距、图文间距、内外留白、视觉中心和上下重量，使标志在真实观看中平衡；几何中心不等于视觉中心。
- 检查同权笔画的视觉粗细、圆弧外扩、尖角越界、横竖补偿、交接处黑量和封闭字腔，避免某处突重或塌陷。
- 检查外轮廓是否出现无意凹口、切线、粘连、悬浮小点或难以稳定输出的极细间隙；有意不规则必须重复成语言，而不是单点事故。
- 描述语和品类词是从属层，不得抢过品牌名；只有真实需要时进入组合标，并保持与主标可分离。

### 5. 响应式 Logo 家族

确认主方向后，从同一母版建立实际需要的家族，而不是生成多套无关 Logo：

- **主标**：信息最完整、品牌识别最强的默认形式。
- **横向／纵向组合**：只重排图文关系和从属信息，不重画核心图形或换字。
- **独立字标**：在无需图形或横向空间有限时使用，保持母版字形。
- **独立图形标／角色标**：只在核心轮廓已经具备独立识别且场景确实需要时提供。
- **紧凑副标／缩写标**：服务头像、小标签、封签或狭窄空间；必须从母版提取，不另造第二概念。
- **单色／反白状态**：保持相同结构；不能依靠描边、投影或换形补救。
- **小尺寸简化**：只删除次要纹理、从属文字或内部细节，保持核心剪影、主要负形和识别笔画。

每个家族成员记录用途、最小空间、保留项、删除项和禁止替代关系。没有独立使用价值的形式必须省略；不能为了展示丰富生成一整页无用途变体。

### Logo 背景移除与 HTML 消费规则

Logo 标准稿可以保留其真实源背景作为来源证据，但排版消费版本必须透明。带底位图统一使用 MediaKit `remove-image-background` 的 `general` 场景输出 PNG，不添加描边，不以重绘替代背景移除；处理后仍须保持完整画布内容、字序、轮廓、比例、颜色职责和内部负形。HTML 只能引用验边通过的透明短链，不得设置 `multiply`／`screen`，也不得引用原始带底位图作为视觉层。

抠图结果若损伤细笔画、字腔或内部孔洞，先修正分割、换用更清晰的同一母版或真实透明源；在合格透明资产出现前停止排版。白底／黑底版本仍可作为 Logo 黑白测试证据，但不能直接进入最终 VI 版面。

去底前必须先区分图片背景与 Logo 身份容器。番茄、椭圆、徽章、旗帜、爆炸形或其他底板只有真实参与字形、负形或品牌语义并已被确认为母版结构时才保留；MediaKit 只移除其外部图片背景。普通应用承托底、纸纹、Mockup、墙面、投影和摄影环境全部排除。抠图后除浅深底验边外，还需检查贴纸白边、反白字、浅色角色区域和内部孔洞没有被误删。

### 6. 尺寸、背景与应用测试

Logo 至少在大尺寸标准稿、中等组合应用和小尺寸图标／标签三个观察尺度测试。最小尺寸不是统一固定值，而由实际字腔、负形、线条、输出介质和阅读距离测试后确定；在最小状态下不能依赖描述语、微小表情或细线维持识别。测试时同时查看：

- 黑标白底、白标黑底、品牌主色与低对比风险背景；
- 正常尺寸、缩略尺寸、远距离和低清预览；
- 屏幕、普通印刷及本任务真实需要的招牌、包装或头像；
- 无保护背景与实际安全区；
- 主标、紧凑标和小尺寸简化之间的身份连续性。

应用验证必须从标准母版或对应平稿出发。Logo 在纸袋、杯身、招牌、菜单或社媒头像中的照片和 Mockup 只能证明场景适配，不能反向成为标准稿，也不能在场景中改变字形、比例、负形和图文关系。先完成标准母版与家族，再制作应用场景。

### 7. Logo 禁止项

- 禁止直接复刻参考 Logo 的具体字形、角色、构图、负形或组合关系；参考只用于判断造型机制和质量标准。
- 禁止无依据增加 `TM`、`®`、`©`、成立年份、城市、口号、品类词或虚构外文。
- 禁止使用通用图库图标、默认字体加外框、随机首字母组合或无语义几何拼贴冒充原创 Logo。
- 禁止把多个候选方向混成正式家族；家族成员必须从一个已确认母版派生。
- 禁止用颜色、渐变、阴影、立体材质或 Mockup 掩盖黑白结构、拼写和间距问题。
- 禁止把位图预览声称为可编辑矢量母版，或把模型生成的近似重复声称为精确几何变体。

## 字体、配色与图像

### 字体角色与标题小效果

文字与准确规范由 HTML/CSS 原生实现；展示标题也不进入普通生图 Prompt。既有 Logo 中的字标按母版继承，字标字体只是身份资产的一部分，不自动替代正文、界面或展示说明字体。

区分品牌展示字、正文、界面小字、数字、章节标签、图注和必要语言补充。按主题与真实文案选择字形组合，用大小、粗细、宽窄和段距建立层级，标签、图注和数字形成稳定节奏，不用大量字体制造丰富感。

展示短标题可按主题采用厚衬线、粗黑、手绘、套印或材料字形效果，集中服务第一视觉焦点；其余标题、长文与准确说明保持清楚。效果字仍须保留真实可编辑文字本体，不能用矩形材质底冒充字形效果，也不能以艺术处理遮蔽字腔或正文。

品牌字体的真实来源、许可、可用字重、混合语种和字符覆盖必须核实；名称、字体候选、历史资源记录或平台名单不证明当前渲染可用。缺失时选择适配替代并说明，不凭名称保证可用。先用最长标题、正文、数字与必要外文安排文字区域，实际渲染检查字形、字重、缺字与回退，不靠极小字制造精致感。

#### VI 展示板基础字号系统

以下区间用于固定画布的 VI 展示板、宽幅模块化长板、紧凑 Brand Board 和分页提案中的 HTML 原生文字。以正文 `25–30px` 为基准，默认优先采用各区间上半段或上限，让文字在画布中形成清楚体量；只有最长文案、真实载体或层级冲突要求时才下调。字号在最终 HTML 中写成明确固定 `px` 值，不使用 `vw`、`vh` 或运行时缩放。用户已有规范或不可变源设计可以覆盖区间，但必须在最终实际尺寸下证明可读；不能仅因内容放不下而降到区间以下。

| 文字角色 | 默认字号区间 | 建议行高 | 使用边界 |
| --- | ---: | ---: | --- |
| 品牌展示字／首屏主命题 | `84–144px` | `0.9–1.1` | 只承担第一视觉焦点；短文字可接近上限，长标题先调整行宽与断行，不连续缩字 |
| 章节标题 | `48–72px` | `1.05–1.2` | 每章结论与导航入口；与正文形成清楚级差，不把普通标签放大冒充章节标题 |
| 正文／规范说明 | `25–30px` | `1.45–1.7` | 默认阅读基准；连续段落优先使用中间值并控制行长，不得使用 `13px` 等微小字号 |
| 界面小字／辅助说明 | `16–20px` | `1.3–1.5` | 仅用于短辅助信息、组件状态和次级说明；必须在所属组件和最终预览中可读，长内容升级为正文角色 |
| 关键数字／核心参数 | `56–96px` | `0.95–1.15` | 用于需要形成视觉焦点的数据；普通色值、尺寸和参数随正文或标签角色，不一律放大 |
| 标签／章节眉标／状态文字 | `20–24px` | `1.15–1.4` | 使用字重、大小写、字距、底色或边界建立角色，不靠继续缩小制造层级 |
| 图注／应用名称／来源说明 | `16–20px` | `1.3–1.5` | 与对应图像近邻；可以低于 `20px`，但必须在最终预览中可读，信息较长时改用正文，不压缩成密集小字 |

VI 展示板中的正文、章节信息和主要说明默认不得低于 `20px`；界面小字、短辅助说明、图注、应用名称和来源说明允许使用 `16–20px`。确实只用于生产标记、版权或法律脚注且用户要求保留时，可以使用 `16–18px`。所有低于 `20px` 的文字都必须在 100% 视图和最终完整预览中可读，并与主要阅读内容分离；低于 `16px` 不得作为展示板有效信息。Mockup、照片或应用效果图内因透视缩小而不可读的原生小字，只能作为场景效果，不能承担展示板的信息说明或被宣称已完成可读性验证。

相邻层级不只靠字号区分：品牌展示字、章节标题、正文和辅助文字还需通过字重、行距、段距、颜色职责、对齐与位置建立稳定角色。正文与章节标题通常至少形成约 `1.6×` 的字级差；品牌展示字通常至少为正文的约 `3×`。关键数字只有承担主结论时才使用大字级，普通参数必须服从所在文本角色。

内容超量时依次调整信息分组、栏目宽度、横向并列、段落长度、章节数量或分页；不得把正文、图注和标签连续压缩到下限以下。内容偏少时先把主标题、章节标题、关键数字、Logo、主图和应用对象放大到可读性与安全边界允许的最大尺度，再调整组距；只保留有职责的留白，不让整页文字机械同比放大。最终同时检查 100% 视图、整板缩略图和实际交付预览；源代码中的字号落在区间内，不代表缩放后的成品必然可读。

### 色彩职责与编辑式色板

颜色记录准确值及用途，不只有色块。区分主色、辅色、强调色、明暗中性色、表面色、文字色与背景色；存在界面时说明状态色，存在角色时说明身体、面部、服装和配件的颜色职责。品牌多色有职责即可，不机械限定色数。

上句适用于完整 VI 色板，不代表 Logo 母版可以无限用色。Logo 标准主标仍按共享 Logo 规则默认使用 `1–3` 个印刷色角色、常规最多 `4` 个；完整 VI 可以拥有更宽的应用色板，但只有获准的 Logo 色组进入 Logo 本体。IP、包装、门店和数字界面可按系统职责使用其他品牌色，不得反向把全部 VI 色板塞进 Logo。

需要建立新品牌配色或向用户推荐色彩方向时，必须读取 [品牌规划配色参考](../../shared/brand-color-planning-reference.md)。该参考中的色系是候选起点，不是默认同时采用的全集；一次方向只选择一组并写清主色、表面／纸色、墨色和强调色职责。用户已有标准色时以用户资产为准，不用参考库覆盖。

内外应用共享颜色职责，可按载体改变面积，不任意互换主辅关系。按适用场景检查深浅背景、灰阶、单色与对比；渐变说明色标、方向和使用范围。屏幕色、真实印刷色、专色与材料色分开，不虚构 Pantone、CMYK、专色对应或材料打样结果。

色板采用编辑式组织时，主色可用大块，与较小的辅色、强调色和中性色共享对齐轴；可在旁边嵌入产品微距、材质切片或获准反白标志应用窗口，建立主题联系。色名、准确值与用途清楚呈现，标准色独立、干净表达，材料照片不能充当标准色样。

色板展示面积不代表品牌实际使用比例；实际比例若需要规范，应另以有依据的使用规则说明。不为每个色块重复套卡片，也不为装饰改变标准呈现。

### 摄影、插画与材质语言

- 使用摄影作为品牌主视觉或主要应用证据时，先建立一份整套共享的摄影语言：主光方向与软硬、色温、背景／台面材料、镜头距离和景别范围、阴影语言、产品或人物的可见尺度、允许的环境辅助对象、后期对比与颗粒，以及禁止出现的摄影风格。它是文字化的艺术指导规则，不是可追加到图像工具中的第二张参考图。各应用可以改变对象和取景，但不得另起光色与空间世界。
- 摄影写清主体、景别、视角、光向、背景、颜色与后期处理；产品组统一光向、台面和视觉尺度，全貌与细节各有内容职责。
- 插画写清轮廓、笔触、负形、透视、对象关系与质感，图标和图解沿用同一语言。
- 3D 写清形体、材料、边缘、光照与空间，不能为同一角色另造比例，也不能以质感改变产品身份。
- 纹理说明属于主体、背景还是局部表面，明确尺度、范围与强弱，不全板覆盖同一层噪点。
- 每张配图说明用途、真实来源、主体可见尺度、构图、光色、与文字的净空和邻图关系；摄影、插画和材质分别描述，不用一组泛化形容词代替全部媒介。需要图像工具衍生时，参考栏只能记录同一份已确认 Logo 母版。
- 准确产品、场所、人物与证据依原资产直接复用或由 HTML 确定性放置，不能作为 `image_edit` 的第二输入；真实照片与生成概念图分别标明，生成图不冒称实拍，概念图不冒充已落地案例。
- 动态或声音表达仅在任务需要时从同一品牌行为延展；静态提案只描述相应意图，不宣称已实现。

## IP 与媒介翻译

- 只使用 Spec 已确认的角色职责、用途和来源；基准记录轮廓、头身比例、面部关系、标志部位、颜色分区和可观察的性格行为。
- 只有角色已经构成确认 Logo 的一部分时，才允许调用 `image_edit` 从该 Logo 唯一输入中衍生角色状态；每个变体说明从 Logo 保留的身份特征、改动项和用途，不能纯靠文本重生相似角色。
- 独立角色母版和其他角色图片只能直接复用或由 HTML 确定性放置，不得作为第二参考图。若角色编辑必须依赖 Logo 之外的角色母版，停止该图像调用并报告与最高优先级规则冲突。
- 不同角色可以各有内容定义及家族关系，但本轨道不以多张角色母版调用图像工具；表情变化不更改五官数量、位置逻辑或主色职责。
- 纸艺、毛绒、像素或 3D 可改变材料与边缘，但不删除身份特征；小尺寸可简化次要细节，不能删除决定身份的面部或标志部位。
- 用对应视图对照，不宣称仅凭正面图验证所有角度。实体媒介需专业制作或打样验证。
- 场景行为必须呼应品牌，不把工作角色突然换成无关人格。服装、道具与节庆变化以授权和真实用途为边界。
- 不用角色时，由摄影序列、产品或应用变化承担相同叙事职责，不新增吉祥物或辅助图形填页。

## 应用、组件与展示

### Identity Kit 总览

VI Lite、紧凑 Brand Board 及需要快速理解系统的展示，在应用场景之前建立一个 Identity Kit 总览区。它只呈现本次真实存在且已确认的资产：主标、必要组合标、图形标／字标／副标、正色与反白状态、颜色职责、字体角色、获准 IP 及核心产品／图像资产。禁止加入辅助图形、Pattern、装饰性 Icon 或无用途变体填满矩阵。

总览区先建立主标与其他资产的视觉主次，再用近邻、对齐和一致命名说明关系。它必须让读者一眼识别“品牌是谁、由哪些已确认资产组成、哪些是主身份、哪些是应用内容”，但不能替代安全区、最小尺寸、颜色状态和应用细节。Logo 家族若含多个版本，必须标明职责与使用场景，不能把多个候选方案并排冒充正式家族。

Identity Kit 的完整度来自 Logo 家族、颜色、字体、IP／产品和真实应用之间的职责关系，不来自辅助图形数量。不得展示“母版拆解 → Pattern／Icon”的派生链，也不得用装饰性纹样占据系统章节。

### 母版 → 应用平稿 → 场景 → 展示板

先沿用确认的统一品牌母版，建立准确应用平稿，再将同一平稿放入场景，最后组织展示板。各层必须有来源对应关系；若交付仅覆盖其中一层，如实说明，不把效果示意当作缺失源稿。

Visual 在原应用条目分别补充三种位置：

1. **物料在板上的位置**：说明平稿、独立物件或场景在展示板中的主辅位置、大小、相邻文字、对齐与阅读顺序。
2. **图文在平稿内的位置**：说明品牌名、标题、正文、Logo／字标和图像在实际应用平面中的区域、层级、留白、安全范围与变化。
3. **设计在场景表面的落位**：说明同一平稿在杯身、袋面、灯箱等表面的透视、曲面、接缝、折痕、材料响应与遮挡关系。

不能用一个“居中”混写三层，也不能在样机里重新设计字标。母版、平稿或场景发生变化时，只更新相关应用与展示，不重新发明无关部分。

### 系列应用与场景表现

数字应用定义品牌轮廓、字体、间距、边界、颜色、层级与状态的共用关系，组件示例覆盖实际需要的长文本、空态、禁用、错误等状态。小尺寸和长内容有适配方式，情绪性品牌图形不替代准确操作含义；可点击效果图不等于功能实现。

实物与环境应用继承至少两类适用的品牌语言，例如 Logo 与字体、颜色与影像，不仅机械贴标。固定规则不等于所有物件同样布局；按阅读距离、尺寸、形状、材料和使用动作调整，系列在同一规则中改变主体、裁切、局部色彩和内容职责。

应用稿、包装平面、实际刀模与效果示意分别记录。场景落位考虑真实透视、杯身曲面、纸袋折痕、手指遮挡及材质；物件与台面有合理接触关系，不靠旋转平面矩形冒充所有场景贴图。标志、袋柄、杯沿等关键部位不被无意裁掉或遮住。

场景已有袋杯组合时，不额外叠入同一物件形成重复；一张主要应用场景配少量相关细节，每张图都应补充不同证据。

### 门店、灯牌、穿戴与周边的表现规则

具有线下门店、员工服务或消费周边的品牌，应用展示不能停留在包装和名片。按 Spec 的应用物料交付矩阵选择真实项目，并让各类物料分别验证不同距离、材料、动作和触点：

- **店铺场景**：至少展示一个能够判断门头、入口、主色场、标识尺度和顾客动线关系的关键场景；需要时补充收银台、吧台、菜单区、货架、墙面或桌面近景。远景负责发现品牌，中景负责进入和选择，近景负责材料与细节，不能用一张模糊室内图替代全部空间证据。
- **灯牌与导视**：灯箱、发光字、侧招、吊牌、门牌和方向牌分别按实际阅读距离、安装高度、正面／侧面观看与昼夜状态设计。发光效果不得吞掉字腔、轮廓或负形；夜景辉光不能改变 Logo 颜色职责，未获得供应商参数时只标概念效果，不承诺亮度、材料或安装方式。
- **T 恤及员工穿戴**：明确正面、背面、胸口、袖口或围裙／帽子的真实落位，控制 Logo、字标、品牌色与获准 IP 的尺度和净空，并检查织物折痕、人体动作、头发、挂绳和手臂遮挡。不得新增辅助图形填充衣身，也不得只把完整 Logo 大面积居中贴在每件衣服上；系列变化应来自岗位、功能或真实穿着场景。
- **工牌与证件**：区分品牌区、姓名、岗位、编号、照片、二维码或访问权限等真实信息层级；工牌、胸牌、挂绳和员工证分别考虑近距离阅读、佩戴方向、边缘安全区与固定方式。没有真实数据时使用明确占位，不虚构员工身份或权限。
- **品牌周边**：帆布袋、贴纸、徽章／Pin、钥匙扣、杯具、笔记本、卡套、手机壳、伞、玩偶或礼盒按品牌语义和受众选择。先建立一项主周边，再用少量相关物形成系列；每件保留共同 Logo／字标、颜色、字体、IP 或产品关系，同时因载体尺度和使用动作产生真实差异，禁止靠 Pattern 或辅助图形铺满表面。
- **交易与服务物料**：包装袋、杯套、外带盒、餐垫、价签、收据、会员卡、感谢卡与配送包装沿购买—使用—携带—复购链组织，明确哪些信息需要准确可读、哪些图形可以变化。不能把展示 Mockup 当成刀模、生产文件或已经落地的店铺照片。

若这些场景需要图像工具生成，仍只允许以已确认 Logo 为唯一视觉参考调用 `image_edit`；每个生成结果先完成媒体双通道交付，再进入 VI 手册组装。真实店铺、人物、制服或产品照片只能直接复用或由 HTML 确定性放置，不得作为第二参考图。

完整系统可暂时遮去 Logo，检查字体、色彩、影像、IP 行为和材料是否仍有一致性，但不得靠新造辅助图形或藏在图片中的品牌名作弊；这是视觉自查，不冒充真实用户识别测试。

### 开场视觉与章节节奏

先读取 Spec 已确定的载体与宽窄结论。窄幅只沿用户明确的手机长图、竖向长卷、紧凑 Brand Board、沿用主参考竖向总览结构、窄幅源设计或真实窄载体执行；其余 VI 展示默认按宽幅模块化长板规划。宽幅长板以约 16:9 的横向视域组织每个主要章节，再把章节纵向组合；这是一套宽屏章节，不是手机单列长图，也不要求每章机械等高。Brand Board 则以紧凑纵向阅读链压缩系统总览和核心应用，不因此缩小到不可读或取消母版关系。

VI 首屏必须像品牌封面，而不是规范目录。它必须先以确认 Logo 为唯一输入直接调用 `image_edit` 生成完整首屏效果，再作为 HTML 首屏的主视觉基础；不得只靠 CSS 色块、原 Logo 贴图或模板容器拼出首屏。它在整板缩略图中应先呈现一个不可忽略的品牌形象，再让文字解释；首屏只选择下列一种主结构，最多加入一个低权重辅助机制，并在 Brief 中写明依据：

- **沉浸裁切型**：适合 IP、产品或 3D／摄影主体承担第一认知。主体占据首屏绝对面积并允许越出画布边缘，以局部特写、遮挡、前后层次和明确光色制造进入品牌世界的感觉；裁切必须保留决定身份的脸部、轮廓、产品结构或标志部位。Logo 可作为次级签名，但主体本身必须已经承载品牌识别，不能只是无关漂亮大图。
- **标志／角色整合型**：适合 Logo 与角色、物件或字标本身就是品牌核心。把主标或品牌名放到首屏中心关系中，让角色从字腔、字肩、基线、轮廓或留白处参与构图；字和角色必须像同一身份系统，不是图标贴在文字旁。可使用放大的轮廓水印或单一辅助色块增强结构，但不得生成第二套标志。
- **封套陈列型**：适合品牌提案封面、作品集式 VI 或需要先展示一张核心应用证据的任务。以大面积品牌色场包围一张居中的封套、品牌板或应用画面，中心对象必须达到足以看清 Logo 与核心应用的尺度；外围只保留短标题、少量索引或低对比图案。不得把中心对象缩成孤立小缩略图，也不得用大量空白掩盖信息不足。
- **身份系统预告型**：适合 VI Lite、Brand Board 或 Logo 家族本身就是核心内容的任务。以主标为绝对第一视觉，同时用一条获准 IP 动作序列、组合标、核心色、产品图像或少量应用切片预告后续系统；首屏仍是一个整体构图，禁止加入辅助图形，禁止做成等权候选墙、资产清单或办公文档目录。

### 首屏尺度、色场与信息密度

- **主体尺度**：主 Logo、IP、产品或中心封套必须形成唯一最大尺度，并在安全区和身份保护允许范围内尽可能填满首屏。沉浸裁切型通常让主体占据大部分首屏高度或宽度；标志整合型让品牌名／主标成为最先读到的形；封套陈列型让中心对象与外围色场形成清楚的内外层级。禁止小 Logo、小角色和若干等权卡片漂浮在巨大背景中。
- **色场**：优先使用一个占绝对面积的品牌主色，配一个高反差中性色和最多一个辅助色；允许纯色承担完整首屏背景，不为“高级”机械加入渐变、玻璃或噪点。大色块之间通过清楚边界、弧形／波形收口、主体遮挡或 Logo／字标轮廓连接，不使用无职责装饰色。
- **文字密度**：首屏原则上只保留准确品牌名／Logo、一个短命题或 `Brand Identity System` 类职责说明，以及必要的极少量索引信息。长品牌介绍、字体说明、色值和应用清单进入后续章节；不能用微小文字把首屏填成提案说明页。
- **装饰密度**：点阵、编号、轮廓水印、线条和小标签只能作为低权重节奏，数量少、位置明确，不与 Logo、角色或产品竞争。参考图中的具体装饰不得照搬。

Logo 与 IP 只在已有母版和授权范围内使用，可以与场景、光色、材质和构图协同，但不能被生成模型重绘、换字、改造身份或降成无职责角标。首屏主视觉是强制图像生产项，必须继续遵循 Logo 唯一视觉锚点门禁，只使用已确认 Logo 调用 `image_edit`；没有 IP 或 IP 不承担本次品牌职责时，不为凑首屏强行增加角色。

首屏文字由 HTML/CSS 原生完成，图片素材负责场景、角色、产品、光色与材质；除既有身份资产中的真实字标外，不把标题、口号和说明交给生图模型。首屏底部必须预埋进入第二章的连续线索，例如同一色带、角色动作延续、Logo／字标轮廓、主体裁切、应用切片或明确的波形／弧形收口；第二章再展开角色动作、Logo 家族、Identity Kit 或应用证据。禁止首屏结束后无关联硬切成白底规范表。

### 首屏快速验收

先检查资产记录中是否存在以确认 Logo 为唯一输入直接调用 `image_edit` 生成的首屏效果、对应原始短链和媒体双通道闭环；缺失时首屏直接不通过。在整板缩略图与首屏单独视图中同时检查：三秒内能否识别品牌名或核心身份；是否只有一个最大视觉主体；主色是否形成明确记忆；主体裁切是否保留身份；原生标题是否清楚；首屏与第二章是否存在可观察的颜色、轮廓、动作、主体或应用接续。若首屏更像小海报贴在背景上、普通目录页、等权素材墙、纯色底贴 Logo 或与品牌无关的漂亮插画，则判为不合格并禁止进入 HTML；先保留公共媒体交付记录，用户要求修改后再以同一 Logo 母版重新执行 `image_edit` 并重做首屏结构。

每章只建立一个结论、一个主焦点、清楚的阅读顺序与结束点；大图、规则、系列陈列和场景形成强弱节奏。章节高度由真实关系决定，但先利用横向空间消化内容：说明与场景左右并列，系列与状态横向排布，主图和证据形成尺度差。不能先造超长空板补装饰，也不能把各项逐一排成“标题—图片—文字”的单列重复段。

### 宽幅章节的组织方式

先从下列关系选择最符合内容职责的一种作为主结构，必要时增加一种辅助结构；不按固定模板凑页。

| 组织方式 | 适用内容关系 | 实施边界 |
| --- | --- | --- |
| 主视觉＋说明侧栏 | 开场、品牌命题、核心场景 | 主视觉占主要宽度，说明与规范集中于一侧；避免小主体配巨大空场 |
| 规则区＋应用证据 | Logo、字体、颜色、图像规则与其实际应用 | 规则和应用左右并列、近邻对应；不能把样机当规则来源 |
| 上部主对象＋下部横向系列 | 包装、海报、数字界面或 IP 的系列变化 | 主对象先建立尺度，下方 3–5 个同类状态共享基线；避免等权缩略图墙 |
| 非对称矩阵 | 平稿、独立物件、场景与细节共同说明一个结论 | 一个大模块带动 2–4 个辅助模块，保持真实主次与阅读入口 |
| 左窄右宽／右窄左宽 | 较短规范、色板或细节与大场景并置 | 窄区不塞长文，宽区承担主要视觉证据；两侧共享轴线或边界 |

现有“主视觉加物料总览、品牌语法加系列平稿、物料陈列加场景证据”继续作为内容组织策略：先确认它们表达的内容链，再落入上述宽幅关系。母版与局部注释保持近邻；规则矩阵只组织可比较的字体、颜色或状态；生成路径展示真实基础、操作、变化与保留关系，不只是装饰箭头。

### 版面关系与物料尺度

- 标题、正文与图注共享稳定内容轴，主视觉与主题色域可有意出血；不能拿装饰外沿代替文字对齐。
- 宽幅章节必须使用主要横向空间，不能把内容压在中间窄栏后用两侧空白冒充宽版。主视觉或主场景通常承担最大面积并尽可能接近安全边界，规则、平稿、辅助物料与细节按职责形成中、小尺度；若仍存在大片无职责空白，先放大主图、Logo、标题、关键数字或真实物料，再考虑增加内容。
- 按实际可见物件判断主体大小，透明边与照片空背景不计作主体；同类系列保持基线、视角和视觉大小，主袋、主海报与徽章保留层级差异。
- 平稿和独立物件尽量完整呈现；场景可以按构图裁切，但保留必要身份、轮廓和用途证据。平稿、场景和细节通过近邻、对齐或连贯阅读关系对应，不重复堆同一物件。
- 叠压时指定哪两个对象、谁在前、遮挡目的和保护区，不能全板任意相交。
- 最长文案优先留容量。内容过量时依次合并重复说明、左右并列相关内容、将同系列组成横向阵列、增加宽幅章节；仍过长时拆成多张宽幅长板或独立分页，不持续增高，也不默认缩字。
- 展示页比例不能替代真实物料尺寸；屏幕、印刷、实物和空间分别按实际阅读距离、制作条件与可见尺度适配。

### 规范与物料的小效果

等高招贴统一高度与说明基线，突出内容与构图变化；贴纸群组由一个主贴纸带动辅助形体，只在专用组内受控拼贴，文字与标志部位保持净空。反白应用使用已确认反白标志，延续原有形态；局部放大与整体对象保持对应，可展示真实字标笔画、产品细节或材料切片。

开放色域以相接的主辅色块、面积和留白建立层级；品牌轮廓可从章节边缘出现，接续下一组内容，不随机散放符号。标志结构说明必须依据真实母版，不凭空添加辅助线制造专业感；规范样本保持规整，不因小效果失去准确性。

## 创意底图与图片融合

根据品牌和内容职责选择背景机制，并满足“背景系统与 Prompt 规则”。先按章节职责做简单匹配：

- 首屏／品牌故事 → 主题主视觉场或品牌母题放大，优先情绪与第一记忆点。
- Logo／字体／色板／网格 → 纯净规范场加图像窗，优先准确与可读。
- 产品／IP／应用展示 → 真实场景、物料陈列场或有依据的材质，优先主体证据。
- 规则与案例同屏 → 强视觉区＋干净信息区，避免全屏背景干扰说明。
- 缺少可靠图像资产 → 品牌色场＋原生排版；有明确品牌职责的干净纯色同样允许，不用辅助图形、低质量背景图、无关渐变或机械噪点硬撑。

整套只确定一个主背景机制和一个辅助机制；信息越准确，背景越克制，情绪越重要，背景越沉浸。候选机制包括：

- 产品或材料微距：用切面、纤维、叶脉等有依据的质感连接品牌与颜色。
- 品牌母题放大：局部裁切、重复带或轮廓延伸形成方向和尺度变化。
- 主题主视觉场：产品、角色、制作动作与环境共同表达品牌命题。
- 物料陈列场：统一承托面、光线、接触与阴影关系，让不同对象处于同一空间。
- 纯净规范场加图像窗：标准色样与说明保持安静，主题质感集中在对应图像窗口；若品牌本身依赖低色数与大色域，完整纯色区可以承担识别，不需要额外纹理证明设计成立。

配图先确定共享场景、透明主体或独立图窗，再按公共 [素材使用规范](../ai-coding/asset-prompt-guide.md#6-独立素材与图片编辑) 在使用前确认去底结论、理由及就绪版本。可复用的 Logo、字标和 IP 身份素材使用真实透明源；已有有效 Alpha 或无底 SVG 可直接核验使用，带底源需要独立叠放时实际去底并验边，不以重绘替代。完整应用平稿、照片图窗和场景保留其有职责的背景，不一律抠成透明。

标准母版与展示效果图分别保留来源、用途和版本；带台面、纸纹、光影或样机透视的效果图不能替代可复用身份母版，也不自动升级为标准稿。统一光色、边缘和空间关系，避免残底；已有材质和阴影不重复叠加，准确标志、标准色样与正文保持清晰。

## 容器与开放排版视觉决策

Visual 必须在原 Brief 每个系统展示页与应用页的对应条目中输出“容器与开放排版视觉决策”。先判断是否需要承托，再按 [容器视觉语法](../composition-layout.md#容器视觉语法开放排版优先语义容器按需) 选择可系统化的容器家族；不能只写全局组件风格或留到 HTML 阶段决定。新建／整体重做时，这些先作为可调整草案，在组合比较后确定，不先锁死模型自选容器与布局。

- 逐个说明容器名称、承载规范／应用内容、位置与主次；同屏多个容器分别描述，共用效果可引用整体规则，但须写本页差异。
- 写清轮廓与圆角／切角、表面材质、填充配色及纹理／渐变、边框与边缘、阴影与厚度、透明度／模糊，以及内部留白、图文排列、与底图和品牌资产的关系。未使用的效果明确写“无”，不默认全部叠加。
- 只写可见效果的自然语言，不输出 CSS 参数、技术色值表或槽位契约；来源 ID 仅写入短采用记录；品牌标准色另在色彩系统记录。规则容器交给 HTML/CSS，复杂壳体按 [素材使用规范](../ai-coding/asset-prompt-guide.md) 准备；色板与标志测试区不因装饰改变标准呈现。
- 无需容器时明确写“开放排版、无容器”，说明用对齐、段距或分隔线组织信息；不能为填字段强加卡片或卡片嵌套。
- 普通白色圆角矩形只用于中性规范区，不能成为品牌组件的默认答案。文件夹、档案页、卷纸、票券、切角铭牌、材料样本、照片衬纸等结构，须经过品牌形态、材质和边缘语言适配后才可跨应用复用。
- 将本页效果写入视觉验收重点，检查实际边缘、材质、对比、文字容量与跨应用一致性；不得仅凭“品牌卡片”“高级容器”等名称判为完成。

## 写回内容结构 Brief

在原有品牌、系统、章节、配图和应用条目中补充以下内容；整体规则写一次，各项只追加差异，保留 Spec 全部有效内容。

- **品牌定位下**：语义锚点、视觉命题、主机制、具体风格、选择依据与决策优先级。
- **风格系统下**：采用的组合配方或同等颗粒度自定义关系、色彩面积层级、字标与 Logo 标记同源特征、版面密度模式，以及亲和／专业／实验程度的可观察边界。
- **Logo 条目下**：核心概念、造型路线、黑白结构、字标与 Logo 标记同源特征、光学校正重点、主标与响应式家族、单色／反白、小尺寸简化、安全区、适用场景和禁止项。
- **系统章节下**：固定特征、允许变量、派生方法、禁区与适用范围；说明标志、字体、颜色、图像和角色怎样同源，并明确不建立辅助图形系统。
- **字体与颜色条目下**：展示字、正文、数字、标签、多语种与层级；准确品牌色、用途、深浅适配、编辑式色板与标准色的分工。
- **图像与 IP 条目下**：主体、组合、密度、裁切、摄影与插画语法；按需补角色动作、表情、媒介翻译和身份检查。
- **摄影条目下**：整套共享的光向、色温、背景／台面、景别范围、阴影语言、主体尺度、环境对象、后期方式与禁用风格。
- **每章准确文案后**：结论、第一焦点、注意力路径、文字层级、相对构图、图文占比、对齐轴、密度、留白、允许遮挡及邻章入口。
- **每张配图后**：用途与画面目标、真实参考及其职责、主体尺度、材质、光线、配色、融合方式、文字净空、处理方式、身份保护与禁用项；完整 Prompt 留在素材清单。
- **每项应用后**：所属消费者触点、补充的品牌证据、共用规则如何落实，平稿内图文关系、场景表面落位、物料在展示板中的主辅位置；数字、实物与环境各自改变什么。
- **Identity Kit 条目下**：Logo 家族职责、颜色与字体角色、获准 IP／产品／图像资产范围，以及总览与详细规范之间的对应关系；明确本 VI 不包含辅助图形系统。
- **每页容器与底图条目下**：开放／分组方式、轮廓、配色、材质、边缘与层次、背景变化和保护区；无容器明确说明。
- **跨载体与降级条目下**：Logo、字体、颜色、影像与 IP 在数字、印刷、实物、空间中的保留、简化、重排和禁用；长文本、小尺寸、深浅背景、复杂材质、图片缺失及实现受限时怎样处理。
- **生产与验收条目下**：第一焦点、图文比例、系列一致性、身份稳定、应用可用性、真实编辑能力、字体与制作条件的实际测试。

组合适配后的最终可见结果写回上述原条目再冻结 Brief，不另附候选评分清单、机器计划或平行视觉规范。

## 形成每项素材生产意图并编译 Prompt

每张待生成或编辑素材先在 Brief 记录用途、目标应用、画面目标、处理方式、唯一 Logo 母版短链、身份保护和禁用项。生产方式固定为 `image_edit`，参考输入固定为一张已确认 Logo 母版。冻结 Brief 后，在素材清单中补比例、尺寸、安全区、消费者与准出标准并编译完整 Prompt；这些生产字段不反向变成 Brief 的代码参数。

风格是 Prompt 首要信息，先写具体风格与可见特征，再写主体、动作、数量、环境、手法、配色、材料、构图、视角、明暗、留白及保护范围。底图、材质或场景背景 Prompt 必须先读取本文件指定的背景图规则，以下示例不替代该读取与完整编译。

普通 Prompt 只描述画面，不写品牌口号、说明文案、文字排版，也不写“无文字／无字／no text”等否定词。VI 开场或封面不是电商 Hero 例外；文字由 Coding 完成。现有 Logo、产品包装与品牌标记作为真实身份保护，不因此移除或重写。

图像工具的实际输入只能是已确认 Logo 母版这一张图。风格图、材质图、角色图、产品图、场景图、应用平稿、候选稿和已有衍生结果可以供内容理解、人工对照、直接复用或 HTML 确定性放置，但不得传入图像工具。Prompt 不写 URL、路径或工具参数；Logo 母版短链缺失、不可访问或版本冲突时标待补并停止图像衍生，禁止改用无参考生成。

### Logo 锚点材质衍生示例

调用 `image_edit`，只传入已确认 Logo 母版：

> 从输入 Logo 的轮廓、负形、笔画重量和颜色职责提取同源形态，衍生宽高比 4:3 的手作丝网印刷纸面构成。主要色版沿右下角形成受控叠映，边缘有轻微缺墨，纸纤维细密，左上部连续开阔。柔和漫射明暗，颗粒尺度一致；不复制额外标志，不引入另一套形态、颜色或材质语言。

### Logo 锚点角色衍生示例

仅当确认 Logo 本身包含角色，且 Spec 已启用该角色与动作时使用。调用 `image_edit`，只传入该 Logo 母版：

> 以输入 Logo 中的角色为唯一身份依据，延续其圆润平面轮廓、头身关系、五官、标志部位、笔画重量和颜色分区，衍生向右侧伸手欢迎的自然动作。画面宽高比 4:3，角色位于左侧，右侧开阔；不改变身份比例，不新增角色、服装或配件，不引入另一种插画语言。

### Logo 锚点应用场景示例

调用 `image_edit`，只传入已确认 Logo 母版。应用场景只使用完整 Logo／字标、品牌色和真实载体关系，不生成辅助图案，也不能把应用平稿或其他图片作为第二参考：

> 采用现代产品静物摄影风格，制作宽高比 4:3 的帆布袋应用示意。输入 Logo 的完整字形、轮廓、比例、负形和颜色保持不变，清楚落在袋体平整正面；袋体其余区域以品牌底色和材料本身为主，不增加辅助图案。袋体完整位于中部，浅灰台面，柔和侧光呈现织物，标志区域不受折痕遮挡，不新增其他品牌符号。

已有场景可直接使用时只写来源、放置和裁切说明，不再调用图像工具改造。对模型输出的身份漂移记录缺陷，是否再编辑遵循主流程；再次编辑仍只能传入已确认 Logo 母版，不能把错误衍生图作为参考输入。不把坏图登记为合格母版；场景图内的文字也不因此成为原生可编辑文字。

## 视觉验收

先验证载体选择，再验证宽幅组织和品牌内容；宽窄判断错误时返回 Spec，不通过继续增高或局部补装饰修正。

1. **载体与尺寸**：核对用户要求、Brief 的宽窄依据、HTML 声明尺寸和实际预览尺寸。默认宽幅 VI 的画布宽度为 1600px，主要章节以约 16:9 横向视域组织；只有 Brief 有明确窄幅依据时才接受手机式窄长画布或紧凑 Brand Board。分页模式逐页核对固定比例，不把多页拼成长页。
2. **横向空间使用**：逐章检查主视觉、规则、平稿、场景和细节是否形成左右并列、上下主次或非对称矩阵中的真实关系。若内容仍集中在中间窄栏、两侧只是无职责空白，或各项重复单列向下堆叠，视为宽版未成立。
3. **三个观察尺度**：查看整张缩略图，确认宽幅章节节奏和总长不过度；查看每个章节完整画面，确认一个结论、一个主焦点和明确结束点；查看代表性细节，核对文字、Logo、色板、平稿与场景对应关系。三种观察均通过才算完成。
4. **容量处理**：出现微小文字、等权缩略图墙、重复 Mockup、单章异常增高或连续多个同构段时，先横向重组、合并重复内容或增加／拆分宽幅章节；不靠继续增高、整体缩小或无职责装饰通过。

- 固定特征、变量和变换规则在实际应用中可观察，不是形容词；系列有真实变化而非同图换字或换背景。
- 用户未提供 Logo 时，必须存在多个已逐一交付且概念、造型和风格真正不同的候选，以及用户明确选择记录；用户提供 Logo 时不得额外生成候选。无论入口如何，正式 VI 生产前必须存在已经告知用户的完整设计规划。任一条件缺失都不得进入 VI 系统设计。
- 除完整 HTML 生成／修改与 `shot.py` 自检外，VI 全流程不得出现 Subagent 执行记录；Logo、首屏、全部素材、MediaKit、检查、Workspace、CLI、上传和交付必须有 Main Agent 亲自执行记录。任一越权委派都不得把对应阶段标记为完成。
- 完整 VI 手册 HTML 必须由 Subagent 组装／返修并用 `shot.py` 自检，Subagent 回传本地 HTML 与预览后停止；随后由 Main Agent 严格执行编号交付链：第 1 步上传同尺寸预览至 CDN、核验公网链接并用 Markdown 展示；默认 Canvas 再依次完成第 2 步 `FileBatchUpload` 完整 HTML、第 3 步 `design-cli ... +create` 唯一顶层 `<item type="HTML">`、第 4 步 `design-cli ... +get` 回读、第 5 步 `present_files("<workspace_id>?item_id=<item_id>")` 画布卡片。Mobile 必须停在第 1 步。不得直接交付 HTML 文件、创建 HTML Frame、拆分章节 Item 或由 Subagent 越权上传、写入、操作 CLI 或完成用户交付。
- 凡调用图像工具生产 VI 衍生资产，实际调用必须为 `image_edit`，并且恰好只传入一张已确认 Logo 母版。使用 `image_gen`、未传 Logo、传入多个参考、改用其他资产或把上一张衍生结果继续作为参考，均不得准出；Logo 不可用时只能停止图像衍生。
- 风格不是名称标签：颜色面积、字标与 Logo 标记关系、摄影语言、材质强度和版面密度必须在整套实际画面中可观察。低色数能够建立系统时不得用辅助图形、无职责新色、渐变、玻璃或辉光制造丰富。
- Logo 与各 IP 的母版来源唯一明确，所有变体身份一致；Logo 在黑白状态具有独特剪影和稳定负形，品牌名逐字准确，字腔、笔画、字距、视觉中心和图文关系经过光学校正。主标、字标、图形标／角色标、紧凑副标、单色、反白与小尺寸简化均从同一确认母版派生，颜色角色、字体与图像语言同源；不得新增辅助图形、Pattern、装饰性 Icon 或纹样系统。
- 品牌名已知时，每个首轮候选和最终标准主标均以准确品牌名形成字标或图文组合标；独立图形、角色或缩写只作为确认后的附属状态，不得替代标准主标或把名称降为角落说明。
- VI Lite／Brand Board 的 Identity Kit 必须在应用前快速说明真实 Logo 家族、颜色、字体、获准 IP、产品与图像资产；完整度来自职责关系，不来自填满矩阵或制造辅助图形。
- 母版、应用平稿、场景与展示板来源对应；三种位置分别落实，场景不另造设计，不重复堆叠同一物件。
- 首屏必须有“确认 Logo 唯一输入 → `image_edit` 完整首屏效果 → 原始短链与媒体双通道闭环 → HTML 主视觉消费”的真实生产链；HTML-only、纯色底贴 Logo、无 Logo 背景或使用第二参考均不得准出。首屏按 Brief 在沉浸裁切、标志／角色整合、封套陈列或身份系统预告中只采用一种主结构，并形成唯一最大视觉主体和明确品牌色场。三秒内必须识别品牌名或核心身份；不得退化成小海报贴背景、小 Logo／角落 IP、等权候选墙或普通规范目录。首屏到第二章必须有可观察的色彩、Logo／字标轮廓、动作、主体或应用切片接续，同时不挤掉后续规范与应用。章节有强弱和阅读接续，真实可见主体尺度合理，同类系列基线、视角与大小稳定，长文不靠缩小到难读来容纳。
- 背景机制与品牌语言一致；可以使用品牌色域、摄影、Logo／字标裁切、材质、纹理、渐变或光影，准确色样、标志测试和说明区允许保持干净纯色。不得加入辅助图形，不得机械增加噪点或渐变，照片已有材质与阴影不重复叠加。容器的边缘、表面、对比与文字容量按逐页决定验收。
- 字体使用真实文案核对可用资源、许可状态、字重、字形、字符覆盖、缺字和回退；原生文字与布局可实际编辑，标题效果不靠普通生图代替。
- 单色、小尺寸、灰阶、长文本、深浅背景与目标制作条件按适用范围检查。编辑式色板不冒充实际用色比例，屏幕色不冒充已验证印刷色。
- Logo 分别检查黑标白底、白标黑底、品牌色、缩略尺寸和真实应用；颜色或 Mockup 通过不能替代黑白结构通过。通用图标、默认字体套壳、无语义首字母拼贴、微小细节、错误拼写、未经确认附文或互不相关的家族变体均不得准出。
- 所有作为独立层进入 VI 排版的 Logo 必须是经核验的真实透明 PNG／SVG；带底位图必须有 MediaKit `remove-image-background` 的 `general` 场景处理记录、输出短链和浅色／深色／最终底色验边。保留图片背景、使用 `multiply`／`screen` 或透明边缘存在残底、白边、误删时不得准出。
- 全板必须体现“大图、大字、低空白”：主图、Logo、标题、关键数字和应用物料在安全边界内尽可能放大并充分使用横向与纵向空间；大片无职责空白、小主体漂浮、小字号堆叠或窄栏缩在画布中央均不得准出。
- 应用集合按实际消费者触点提供互补证据，不能用同一场景换 Logo 位置或同一种 Mockup 换载体名称冒充完整应用系统。
- 数字状态及操作含义清楚，不以可点击效果图宣称功能完成；实物与环境按真实尺寸、阅读距离、材料、供应商参数和必要打样验证，未验证事项列为待确认。
- 应用源稿、可编辑文字、可替换素材和展示图分别真实存在；不以 Mockup 代替 VI 系统，不以位图冒充矢量／3D 母版，不以展示包装冒充可生产文件。
- 规范说明、色值、版本、来源与示意声明准确；没有验证的印刷、交互或法律结论如实列出。公共组合匹配和实现读取不代替最终绑定、素材检查与实际渲染验证。

将本任务的身份规则、唯一 Logo 锚点、字体／配色／图像系统、逐页构图、三种位置、系列与跨载体变化、母版消费、素材职责、容器与背景、载体适配、降级及“无辅助图形系统”写入 **视觉效果生产规范**；将 `image_edit` 调用方式、唯一 Logo 输入及实际母版版本，与上述身份同源、真实字体、颜色职责、应用对应、跨应用一致、小尺寸／灰阶／深浅背景、制作条件和真实交付能力检查写入 **视觉效果验收规范**。两者写在同一 Brief 的对应位置，不另建平行规范。
