# 关系图统一视觉系统

## 底图与 Prompt 强制规则

每个视图的作品级底图必须包含与主题和已选视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。节点与关系密集区域可以降低纹理频率、对比和密度，或使用局部纯色承托，但仍须与整体底图连续且同源。

每次写出具体底图或概念环境背景 Prompt 前，必须先读取并遵循 [背景图 Prompt](../ai-coding/asset-prompt-guide.md#5-背景图-prompt)，按其中的背景职责、纹理选择模型和完整 Prompt 编译语法描述材质、色场、变化方向、尺度、低纹理区与连续关系。该路由适用于新生成和编辑既有底图；直接复用真实背景时不强造 Prompt，但必须记录使用方式并检查本节结果门禁。

## 读取入口与图种边界

按任务读取同一 Brief 中对应内容结构，不创建副本，也不为构图改写语义：

- 思维导图／概念关联图：[思维导图 Spec](../scenarios/mind-map-spec.md)
- 流程图：[流程图 Spec](../scenarios/flowchart-spec.md)
- 知识图谱：[知识图谱 Spec](../scenarios/knowledge-graph-spec.md)

一张图只设一个主图种。层级分类优先思维导图，步骤与条件流转优先流程图，类型化实体关系与可追溯事实优先知识图谱；混合内容拆成相邻视图并保留明确跳转，不把三套线语义叠在一屏。

## 容器与开放排版视觉决策

Visual 阶段必须在原 Brief 每个总览或局部视图的对应条目中输出“容器与开放排版视觉决策”，先判断节点是否需要边界，再按 [容器视觉语法](../composition-layout.md#容器视觉语法开放排版优先语义容器按需) 选择容器家族；不能只写全局风格或留到 HTML 阶段决定。

- 逐个说明容器名称、承载节点／知识组、位置与主次；同屏多个容器分别描述，共用效果可明确引用，但须写本屏差异。
- 写清轮廓与圆角／切角、表面材质、填充配色及纹理／渐变、边框与边缘、阴影与厚度、透明度／模糊，以及内部留白、节点文字排列、连线出入口与底图关系。未使用的效果明确写“无”，不默认全部叠加。
- 只写可见效果的自然语言，不输出 CSS 参数、色值表或槽位契约；来源 ID 仅写入短采用记录；规则容器交给 HTML/CSS，复杂壳体按 [素材使用规范](../ai-coding/asset-prompt-guide.md) 准备，不改变真实节点和关系语义。
- 无需容器时明确写“开放排版、无容器”，并说明如何用对齐、间距或关系线组织信息；不能为填字段强加卡片或卡片嵌套。
- 普通白色圆角矩形只用于稳定节点或交互状态，不能把全部知识节点做成同款卡。主题簇可使用文件夹／资料袋、档案页、标签牌、切角节点、票券或分层窗口建立语义差异，但轮廓变化不得改变真实层级、端点和连线方向。
- 将本屏效果写入视觉验收重点，检查实际边缘、材质、对比、最长节点容量与连线遮挡；不得仅凭“高级容器”等名称判为完成。

### 品类常用容器表

下表列出本品类节点和分组的常用容器候选；节点尺寸仍由真实文字和关系决定，容器类型不能替代图种、层级与连线语义。

| 常用容器类型 | 常见用途 | 视觉选择与边界 |
|---|---|---|
| 中性圆角容器（非默认） | 普通节点、定义、证据与解释 | 只在稳定节点语义成立时使用；按层级改变边框或表面，不强制等大节点 |
| 文件夹轮廓 | 主题分组、资料集与分类簇 | 页签必须对应真实分类，不用于单个普通概念 |
| 侧尾对话框 | 注释、提问、观点与待确认项 | 尾部必须指向明确对象，不代替实际关系线 |
| 阶梯面板 | 中心主题、结论与阶段边界 | 只用于关键层级，不能让所有节点都成为重框 |
| 胶囊与徽章 | 状态、关系类型、编号与图例 | 只承载短标签，长概念仍使用正文节点 |
| 圆角磨砂玻璃 | 科技网络或抽象空间中的少量主节点 | 保证连线和文字对比，不能让透明层遮乱端点 |

### 已有布局 CSS 能力表

下表完整覆盖当前模板库已有的布局能力。Visual 根据内容职责选择，不按顺序轮用，也不要求每屏使用一种；写回 Brief 时使用表内能力名称和实际图文关系，便于后续自然语言匹配。名称用于能力对应，不输出 ID、路径、类名或参数。

| 布局能力 | 适用关系 | 写入 Brief 的边界 |
|---|---|---|
| 紧凑内容 | 同组事实、短字段、密集但可扫描的信息 | 写明压缩的是留白与组距，不缩小到不可读，也不把无关内容塞进同框 |
| 宽松内容 | 单一主张、少量重点、需要呼吸感的组件 | 写明留白服务的焦点与阅读停顿，不用空白凑画布高度 |
| 规整对齐（方格／网格排版） | 参数、证据、规格、并列比较和稳定栏目 | 写明列组、共同基线与主次；方格只组织可比较内容，不自动生成卡片墙 |
| 疏朗留白 | 长文、说明、编辑阅读栏与安静叙事 | 写明行宽、文字轴、图片归属与段间节奏，不等于所有内容缩成窄列 |
| 错落平衡 | 短标题接力、偏轴构图、左右不等权信息 | 写明错位对象、方向和共同对齐依据，不随机散放正文 |
| 聚焦主场 | 商品、人物、作品或场景作为第一视觉焦点 | 写明主体尺度、取景、文字静区和图文前后关系，不把主图缩成卡片配图 |
| 连续流动（串页／长页排版） | 长图章节、连续叙事、上下屏衔接和系列阅读 | 写明上一段出口、下一段入口、共享背景或接力对象，不只写“向下阅读” |
| 叠层拼贴 | 多张照片、纸片、证据或装饰需要错位叠压 | 写明主片、副片、角度、遮挡与保护区，不用随机旋转制造丰富 |
| S 形导览线 | 流程、路线、时间或概念节点需要曲线推进 | 写明真实节点、起止点和绕行保护区；没有关系节点时不用装饰曲线 |
| 横向卡片列 | 同类短条目、阶段、步骤或可横向扫描的内容组 | 写明条目共同尺度与差异；长正文、价格条件或复杂证据不挤入窄卡 |
| 章节眉线 | 章节编号、标题、短导语与换章提示 | 写明眉线承担的层级与接续对象，不把分隔线当主视觉 |
| 带引导线的图像标注 | 产品部件、成分、结构、地图或证据图解释 | 写明标注对象、端点和文字归属；引导线必须指向真实细节且不交叉遮挡 |

同一屏可组合兼容能力，例如“聚焦主场＋带引导线的图像标注”或“连续流动＋章节眉线”；组合后仍须形成一个明确主关系。没有适用能力时保留自定义关系并描述可见结果，不为命中模板改写内容。

### CSS 原子能力校验

完成视觉方向草案后、最终 Brief 冻结前，将本品类已选效果拆成下列自然语言能力词并执行公共限量查询。这里选中 ID、源路径与版本进入 Brief 短采用记录，不复制代码或参数；查询只验证能力与边界，不能反向新增视觉决定。

| 决策维度 | 交给查询的自然语言能力词 | Brief 保留内容 |
|---|---|---|
| 布局 | 阅读轴、主图关系、网格、错位、叠层、连续流动等实际关系 | 本屏图文主次、阅读路径与开放／分组方式 |
| 字形 | 填字、描边、发光、浮雕、路径排字等可见效果及文字角色 | 哪组文字采用何种效果、作用和可读边界 |
| 形状 | 当前选定的容器、图窗、票券、纸边、徽章或其他轮廓 | 轮廓服务的真实内容与本屏差异 |
| 表面 | 纸张、玻璃、塑料、织物、金属、柔焦等材质及承载对象 | 材质落在背景、卡片、图片还是文字，正文如何保持清晰 |
| 配色与背景 | 色彩职责、渐变／弥散方向、纹理类型及覆盖范围 | 可见色彩关系、背景变化、静区和保护范围 |
| 作用对象与边界 | 字体、卡片、背景、局部装饰；需要素材承担的复杂部分 | HTML 与图片的分工、必要降级及验收重点 |

候选摘要证明确实可实现后，把最终可见结果写回原 Brief；没有适用候选时保留已选方向，说明由素材或原生实现承担。真实引用、依赖、参数和消费者只进入后续 最终 HTML。

## 写回对应内容 Brief

整体字段写一次，各视图只追加布局差异，不重抄节点清单。

- 风格与依据：具体视觉语言、读者与主题的选择理由
- 决策优先级：用户锁定、原文关系、来源证据、交互范围、参考继承／排除与 Agent 可裁量项
- 视觉命题与阅读路径：入口、主干顺序、跨支或跨实体关系、局部探索与返回路径
- 艺术表现手法：节点、关系、主题图与背景如何共同表达内容
- 字体与层级：主题、分支、节点、说明、关系标签、状态与来源
- 配色与编码：分类、状态、强调的颜色、线型与形状含义
- 逐视图相对拓扑与密度：层级方向、集群面积、节点疏密、关系路径、图片／文字占比、留白、局部入口与低干扰区
- 图片层级与背景：沿用配图计划，来源、主辅尺度、裁切／遮罩、前后景、节点归属和背景关系
- 跨视图连续与状态：同源节点、折叠／展开、搜索／定位、局部视图与总览的固定和变化
- 素材生产意图：逐图用途、画面目标、处理方式、参考职责、保护与禁用项；正式 Prompt 在素材清单中编译
- 载体适配、降级与验收：窄版、打印、复杂关系、图片缺失时的重排，以及端点、方向、可读性、图文比例和交互范围的可观察检查

## 风格选择

根据读者、内容气质、参考与表达意图选择，不把知识图都做成蓝色节点框。风格不改变关系语义，图种和领域不是固定风格标签。

| 风格候选 | 何时考虑 | 具体表现 |
| --- | --- | --- |
| 瑞士网格、清晰知识编辑 | 希望高效总览与检索 | 清楚主干、稳定字级、有限分类色和低干扰来源区 |
| 手绘笔记、白描线绘 | 希望亲近、记忆、复习感 | 圈注、手绘轮廓与少量主题图，装饰线不混同真实关系线 |
| 编辑档案、文献索引 | 希望追溯资料与观点 | 非对称分组、注释、来源索引，编号不能伪造出处 |
| 有机枝条、自然插画 | 内容适合生长或分类的视觉比喻 | 分枝节奏与柔性轮廓，不强迫画树或暗示生物因果 |
| 地图式主题探索 | 多区域需要定位与回溯 | 分类区域和地标式主题，空间路径不暗示执行顺序 |
| 包豪斯、孟菲斯、积木图形 | 希望轻快、教学或形态辨认 | 少量形体对应明确角色，不用随机装饰干扰连线 |
| 像素模块、数字系统 | 参考或主题适合数字语汇 | 统一颗粒尺度和端点关系，准确正文不全用像素字 |
| 纸艺、等距微缩、艺术拼贴 | 主题需要材料或空间表达 | 辅助对象与低密度主题场，节点和关系仍独立且准确 |

一个主方向贯穿总览与局部；辅助手法只处理局部，不每个分支换一种画风。不能只换底色，就宣称完成手绘或空间风格。

## 通用布局与连线

先试排最长节点、最深路径与连接最多的局部，节点尺寸由文字决定。内容过密时回 Spec 拆视图或限定范围，不靠缩字、隐藏关系或自动聚类制造“整洁”。实际端点、方向、标签和图例必须准确；交叉不代表相连，汇合必须有明确节点。结构由 HTML/CSS/SVG 确定性构建，不让图片模型生成整张关系图。

### 思维导图／概念关联图

| 布局 | 选择依据 | 主要风险 |
| --- | --- | --- |
| 中心放射、左右分枝 | 单根、短分支、较宽画幅 | 为对称补节点、旋转长文本或左侧倒读 |
| 单向树、上下层级 | 层级深或标题长 | 最深层变得过小，空间方向被误认作时间 |
| 分区集群 | 多主题、会议或检索 | 只有分区没有实际关系，邻近误导归类 |
| 对照双区 | 确有相同维度的比较 | 强行凑对应、隐藏差异和缺项 |
| 概念网络 | 多中心与交叉联系 | 线团、错误端点和遗漏关系标签 |
| 总览＋局部展开 | 内容多、关联密集 | 版本不一致、没有返回定位 |

主层级和跨主题关系以线型、位置、粗细与标签区分；实际端点、箭头和关系名称必须准确。交叉不代表相连，汇合必须有明确节点。准确节点、连线、箭头和图例由 Coding 依据内容确定性构建，不生成整张知识网络。

### 流程图

- 默认建立单一主轴；开始、活动、判断、子流程、数据／文档、结束使用稳定且可区分的形状，图例只解释本图实际使用项。
- 判断节点的每条出线必须有条件；优先写明确默认路径，分支汇合使用独立合流点，循环必须标出回路条件与退出条件。
- 跨角色流程按需使用泳道，节点归属只表示责任主体，不借位置暗示未定义的先后或审批权。
- 正常、异常、超时、取消等路径以标签和线型共同编码；异常支线降低视觉权重但不能隐藏。
- 避免反向长线和多次交叉；确需跨区时使用带名称的连接点。长流程拆成总览与子流程，并保留入口、出口和返回定位。

### 知识图谱

- 先由查询目标选择总览、实体邻域、关系路径、时间切片或冲突视图，不默认把全部实体铺成力导向网络。
- 实体类型以形状、边框或分区稳定编码；关系必须显示方向与名称。节点距离、面积和线宽不得暗示未定义的相似度、重要度或置信度。
- 来源、时间、已证实／推断／提案／矛盾状态使用标签、线型或侧栏共同表达，不只靠颜色；同一编码在所有视图保持一致。
- 高连接实体先做密度压力测试；超阈值时按类型、来源、时间或查询范围过滤，并展示筛选状态与被省略数量。
- 总览与局部复用同一实体标识、名称和关系方向；同名异义实体不得因视觉靠近而合并。

## 字体、颜色与导航

- 主题、主分支、普通节点、解释、关系标签与来源有明确层级，不每深一层都机械缩小。
- 所有文字与字形效果由 HTML/CSS 实现。专业术语、混合语种、公式符号检查实际字体覆盖。
- 同一颜色或形状保持稳定含义；分类色不能突然代表置信度。节点面积、线宽与距离不暗示未经定义的权重。
- 推断、提案、争议与待确认用可见标签、线型或说明，不只靠颜色。
- 背景、插画与关系线有主次；去掉装饰仍看得清节点，灰阶下仍能辨别必要关系。
- 静态折叠用明确范围与局部页索引，不画伪按钮；交互模式收起节点时同步隐藏附属线，展开后保留来源。

字体候选先从 [字体推荐入口](../../../rendering/font-recommendation-list.md) 按语种及主题、节点、步骤、条件、关系、泳道、图例、来源等文字角色，再结合形态和图表气质形成；精选清单不是封闭白名单，查询脚本只提供候选、缺口和诊断。必须用真实节点、连线标签、分支条件、泳道、图例、来源、专业术语、公式符号和多语种文案试排；装饰字体只用于短标题，不承载节点、步骤、条件、关系、来源或密集图例。视觉候选确定后，正式 HTML 再按 [字体资源与执行契约](../../../rendering/font-family-library.md) 核验实际 family、face、weight／style、许可、目标字形覆盖和 Web 加载，并把文字写入真实 DOM。等待目标字体加载并确认实际命中或回退后，必须重新测量节点尺寸与文字换行，重新计算连线避让、端点、箭头和标签位置，再检查遮挡、溢出和可读性；不得用字体加载前的几何数据冒充验收。用户锁定精确字体时，任一门禁失败都必须说明具体失败项并请求确认，不得静默替换或把浏览器回退视为通过。

## 配图生产意图与 Prompt 编译

图像只辅助主题识别、记忆或展示真实证据，不要求每节点一张。原资料截图直接使用并记录节点归属，装饰不模拟准确证据；没有必要图像时可以不生图。

每项待生成或编辑图先在 Brief 记录用途、目标视图、画面目标、来源、参考职责、节点／背景关系、保护和禁用项。冻结 Brief 后，在素材清单中补生产方式、比例、尺寸、安全区、消费者与准出标准并编译完整 Prompt；先写具体风格与视觉特征，再写对象、数量、手法、颜色、材质、视角、构图、明暗、留白与保护范围。

Prompt 只描述画面，不写节点文案、关系标签或文字排版，也不写“无文字／无字／no text”等否定词；不要把节点清单与箭头关系交给图像模型。图中的低纹理空间只描述位置。

有参考图时区分主体、风格与待编辑原图；图1、图2对应真实短链，同序传工具。Prompt 不写 URL、路径或工具参数，短链待补时不调用依赖该图的生成。不得自动继承参考中的科学关系、人物、品牌或事实。

### 无参考主题图示例

仅适用于 Spec 已规划植物主题装饰的情况：

> 采用细墨线白描风格，制作宽高比 1:1 的植物枝叶小插画。一条枝干从左下向右上自然伸展，三片形态不同的叶片疏朗排列，深绿色线条粗细稳定，纸白底面，中央与左上保持开阔，柔和均匀明暗。

### 带参考的同源素材示例

图1为已确认的植物主题图，真实短链记录在该图条目：

> 延续图1的细墨线白描风格、深绿色与纸白关系，编辑为宽高比 4:3 的横向素材。保留原叶片形态和线条粗细，将枝叶集中到右下方，只延展左上纸面，保持低纹理和疏朗空间，不新增其他物件。

来源截图直接使用时写：“关联到指定节点，保留出处和证明结论所需上下文，等比缩放；注释在独立文字层中呈现。”

## 视觉验收

- 对照源内容核对节点、实际连线端点、方向、标签与依据标识；流程图另核对分支覆盖、合流、循环出口和异常路径，知识图谱另核对实体类型、关系谓词、来源与时间状态。
- 最长节点、最密局部和全部视图在目标尺寸可读，无遮挡、缺字或关系歧义。
- 总览与局部同源，折叠范围准确，重要外部关系可定位，全量任务没有用折叠数量代替内容。
- 颜色、形状和线型的含义稳定，装饰不制造新的分类、因果或权重。
- 交互任务实际测试展开、收起、搜索、定位与返回；静态图不声称这些功能已实现。
- 结构校验不等于知识核实，未核验的来源和专业判断如实记录。

将本任务的拓扑、文字层级、关系编码、节点容器、背景、辅助图像、跨视图同源、交互范围和降级写入 **视觉效果生产规范**；将上述节点、连线、方向、依据、密度、可读性和交互检查写入 **视觉效果验收规范**，不能用结构文件通过代替真实画面与知识边界核对。
