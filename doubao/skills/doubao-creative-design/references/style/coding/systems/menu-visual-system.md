# 菜单视觉表现规划

## 底图与 Prompt 强制规则

每页菜单的作品级底图必须包含与菜品、品牌和已选视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。菜名、价格和点单条件区域可以降低纹理频率、对比和密度，或使用局部纯色承托，但仍须与整体底图连续且同源。

每次写出具体底图、台面或环境背景 Prompt 前，必须先读取并遵循 [背景图 Prompt](../ai-coding/asset-prompt-guide.md#5-背景图-prompt)，按其中的背景职责、纹理选择模型和完整 Prompt 编译语法描述材质、色场、变化方向、尺度、低纹理区与连续关系。该路由适用于新生成和编辑既有底图；直接复用真实背景时不强造 Prompt，但必须记录使用方式并检查本节结果门禁。

## 读取入口

读取 [菜单 Spec](../scenarios/menu-spec.md) 保存的同一 Brief 中“菜单内容结构”。缺少 Brief、菜品价格关系或页面职责时返回 Spec，不自行创建、补价、删菜或重排点单逻辑。

## 容器与开放排版视觉决策

Visual 阶段必须在原 Brief 每页菜单或每屏点单内容的对应条目中输出“容器与开放排版视觉决策”，先判断是否需要边界，再决定容器家族；不能只写全局风格或留到 HTML 阶段决定。具体构造统一遵循 [容器视觉语法](../composition-layout.md#容器视觉语法开放排版优先语义容器按需)。

- 使用容器时逐个说明容器名称、承载菜组／套餐、位置与主次；同屏多个容器分别描述，共用家族可明确引用，但须写本屏的尺度、开合、页签、边缘或附件差异。
- 写清轮廓与圆角／切角、表面材质、填充配色及纹理／渐变、边框与边缘、阴影与厚度、透明度／模糊，以及内部留白、菜图与菜名价格排列、与底图的关系。未使用的效果明确写“无”，不默认全部叠加。
- 只写可见效果的自然语言，不输出 CSS 参数、色值表或槽位契约；来源 ID 仅写入短采用记录；规则容器交给 HTML/CSS，复杂壳体按 [素材使用规范](../ai-coding/asset-prompt-guide.md) 准备，菜名、价格与条件保持准确可编辑。
- 无需容器时明确写“开放排版、无容器”，并说明如何用对齐、段距或分隔线组织信息；普通菜品列表不为填字段强加卡片或卡片嵌套。
- 普通白色圆角矩形只用于中性功能区、稳定比较或触控选项，不能成为整页默认。需要视觉承托时优先使用文件夹／口袋、卷轴／公告纸、报纸／档案页、撕纸／涂刷边、阶梯框／切角牌、票券、衬纸／相框等有语义的结构，以平面几何、分层节点、材质、边缘工艺和接触阴影形成拟物感。
- 将本屏效果写入视觉验收重点，检查实际轮廓、结构部件、材质、边缘、厚度、阴影、对比、长菜名容量与规格价格对应；不得仅凭“高级容器”或只改圆角和底色判为完成。

### 品类常用容器表

下表列出本品类常用容器候选；普通菜品列表仍优先开放排版，只有菜组、套餐、推荐或真实载体语义成立时才选择容器。

| 常用容器类型 | 常见用途 | 视觉选择与边界 |
|---|---|---|
| 文件夹／口袋／资料袋 | 分类菜单、套餐集合、品牌故事与图片索引 | 用背页、页签、前袋和露出内容片形成结构；菜图可从袋口探出，不把文件夹简化成带圆角的色块 |
| 卷轴／公告纸／垂挂纸 | 套餐规则、活动说明、宴席菜单和较长文字 | 顶部卷边／横杆、主纸面与底部折页分层，文字保持可编辑，不用一张烘焙文字的卷轴图 |
| 报纸／档案页／旧书页 | 咖啡、酒馆、地方菜、故事型与复古菜单 | 使用不规则切角、分栏、折痕、纸纤维和套印建立媒介感；正文区保持平整清楚 |
| 撕纸／涂刷边／手作片 | 推荐菜、分类标题、短说明与季节限定 | 外层毛边配内层平整内容面，可有胶带、夹子或错位衬底；不让长列表全部变成碎纸 |
| 阶梯框／切角牌／铭牌 | 招牌菜、主厨推荐、价格重点与套餐主组 | 用肩角、缺口、双层边和薄浮雕建立重点，只突出少数主信息 |
| 票券与缺口 | 酒单、餐券、节庆限定或点单联 | 需要真实票券语义，不生成无意义条码和编号 |
| 照片衬纸／相框／胶片窗 | 菜品摄影、门店、厨师或原料证据 | 图片、衬纸、胶带／夹具和说明分层，允许轻微错位，不用统一圆角图卡 |
| 拱形图片窗 | 菜品特写、门店与原料照片 | 保持器皿和食物完整，不因装饰裁掉识别部分 |
| 胶囊与徽章 | 辣度、冷热、推荐、售罄与短规格 | 只放短标签，状态不能只靠颜色表达 |
| 中性圆角容器（非默认） | 触控选项、规格比较和确需稳定边界的功能区 | 只在功能关系成立时使用；同页不复制成等大白卡阵列，不将圆角作为视觉风格本身 |

### 已有布局 CSS 能力表

下表完整覆盖当前模板库已有的布局能力。Visual 根据内容职责选择，不按顺序轮用，也不要求每屏使用一种；写回 Brief 时使用表内能力名称和实际图文关系，便于后续自然语言匹配。名称用于能力对应，不输出 ID、路径、类名或参数。

| 布局能力 | 适用关系 | 写入 Brief 的边界 |
|---|---|---|
| 紧凑内容 | 同组事实、短字段、密集但可扫描的信息 | 写明压缩的是留白与组距，不缩小到不可读，也不把无关内容塞进同框 |
| 宽松内容 | 单一主张、少量重点、需要呼吸感的组件 | 写明留白服务的焦点与阅读停顿，不用空白凑画布高度 |
| 规整对齐（方格／网格排版） | 参数、证据、规格、并列比较和稳定栏目 | 写明列组、共同基线与主次；方格只组织可比较内容，不自动生成卡片墙 |
| 疏朗留白 | 长文、说明、编辑阅读栏与安静叙事 | 写明行宽、文字轴、图片归属与段间节奏，不等于所有内容缩成窄列 |
| 错落平衡 | 短标题接力、偏轴构图、左右不等权信息 | 写明错位对象、方向和共同对齐依据，不随机散放正文 |
| 聚焦主场 | 商品、人物、作品或场景作为第一视觉焦点 | 写明主体尺度、取景、文字静区和图文前后关系，不把主图缩成卡片配图 |
| 连续流动（串页／长页排版） | 长图章节、连续叙事、上下屏衔接和系列阅读 | 写明上一段出口、下一段入口、共享背景或接力对象，不只写“向下阅读” |
| 叠层拼贴 | 多张照片、纸片、证据或装饰需要错位叠压 | 写明主片、副片、角度、遮挡与保护区，不用随机旋转制造丰富 |
| S 形导览线 | 流程、路线、时间或概念节点需要曲线推进 | 写明真实节点、起止点和绕行保护区；没有关系节点时不用装饰曲线 |
| 横向卡片列 | 同类短条目、阶段、步骤或可横向扫描的内容组 | 写明条目共同尺度与差异；长正文、价格条件或复杂证据不挤入窄卡 |
| 章节眉线 | 章节编号、标题、短导语与换章提示 | 写明眉线承担的层级与接续对象，不把分隔线当主视觉 |
| 带引导线的图像标注 | 产品部件、成分、结构、地图或证据图解释 | 写明标注对象、端点和文字归属；引导线必须指向真实细节且不交叉遮挡 |

同一屏可组合兼容能力，例如“聚焦主场＋带引导线的图像标注”或“连续流动＋章节眉线”；组合后仍须形成一个明确主关系。没有适用能力时保留自定义关系并描述可见结果，不为命中模板改写内容。

### CSS 原子能力校验

完成视觉方向草案后、最终 Brief 冻结前，将本品类已选效果拆成下列自然语言能力词并执行公共限量查询。这里选中 ID、源路径与版本进入 Brief 短采用记录，不复制代码或参数；查询只验证能力与边界，不能反向新增视觉决定。

| 决策维度 | 交给查询的自然语言能力词 | Brief 保留内容 |
|---|---|---|
| 布局 | 阅读轴、主图关系、网格、错位、叠层、连续流动等实际关系 | 本屏图文主次、阅读路径与开放／分组方式 |
| 字形 | 填字、描边、发光、浮雕、路径排字等可见效果及文字角色 | 哪组文字采用何种效果、作用和可读边界 |
| 形状 | 当前选定的容器、图窗、票券、纸边、徽章或其他轮廓 | 轮廓服务的真实内容与本屏差异 |
| 表面 | 纸张、玻璃、塑料、织物、金属、柔焦等材质及承载对象 | 材质落在背景、卡片、图片还是文字，正文如何保持清晰 |
| 配色与背景 | 色彩职责、渐变／弥散方向、纹理类型及覆盖范围 | 可见色彩关系、背景变化、静区和保护范围 |
| 作用对象与边界 | 字体、卡片、背景、局部装饰；需要素材承担的复杂部分 | HTML 与图片的分工、必要降级及验收重点 |

候选摘要证明确实可实现后，把最终可见结果写回原 Brief；没有适用候选时保留已选方向，说明由素材或原生实现承担。真实引用、依赖、参数和消费者只进入后续 最终 HTML。

## 写回内容结构 Brief

整体字段只写一次，各页差异补在原页面条目内，不另建视觉 Brief。

- 风格与依据：具体风格、品牌／受众／参考依据及可见特征
- 决策优先级：用户锁定、菜品价格事实、品牌规范、参考继承／排除、载体要求与 Agent 可裁量项
- 视觉命题与注意力路径：品牌／食欲入口、分类检索、菜品比较、价格与点单条件的阅读顺序
- 艺术表现手法：食物、器皿、背景与辅助元素的共同处理
- 配色：品牌、食物或参考的取色来源，信息色与强调色职责
- 文字系统：菜单名、分类、菜名、译名、规格、价格和注释的字体、层级
- 图文关系：招牌食欲型／图鉴比较型／价目检索型的主关系，图片职责、有效主体尺度及文字容量的共同试排结果
- 逐页排版：主图与辅图相对面积、跨栏／出血／出画关系、列宽、价格轴、菜图位置、文字净空和低干扰区
- 配图展示方式：先按单品识别、场景或特写用途决定完整展示或裁切，再选择图框／蒙版，写清主体保护范围与窄版适配
- 背景与素材：统一视角、台面、器皿和材料；沿用配图计划的对应关系
- 菜品与背景联动：共享台面、色块承托、摄影窗衔接、分类色场、食材呼应、场景统领或平面拼贴中的主关系，以及接触点、光向、色彩、材质和跨区接力
- 素材生产意图：逐图用途、画面目标、处理方式、来源、参考职责、保护与禁用项；正式 Prompt 在素材清单中编译
- 载体适配、极端内容与降级：桌面／墙面／手机、长菜名、多语种、多规格、图片缺失时保留、重排或降级什么
- 视觉效果生产与验收：第一焦点、图文占比、背景联动、实际阅读距离、最长菜名、多规格、照片身份与示意声明

## 风格选择与艺术手法

结合店铺个性、顾客、食物真实形态、阅读环境与参考选择一个主方向，不按餐饮类别固定绑定。“精致”不意味着少图小字，“热闹”不意味着全部放大。先确定具体风格及图文关系，再共同细化手法。

| 风格候选 | 选择依据 | 艺术手法与图文机会 |
| --- | --- | --- |
| 手绘食欲拼贴 | 希望亲切、丰富、有手作感 | 完整器皿去底图大小穿插，同源餐具笔触和共享纸面；不能成为贴纸墙 |
| 现代食物编辑 | 希望精致但食欲明确 | 一处代表菜放大、精细质地、非对称留白，稳定菜名价格轴 |
| 自然餐桌摄影 | 食物与真实环境共同表达品牌 | 原木、石材或布面与菜盘统一光向，食物比布景更清楚 |
| 复古商业印刷 | 参考或品牌有年代气质 | 色版叠印、手绘器皿、展示字与规则线，准确信息不做错版 |
| 品牌插画图鉴 | 希望轻松、可比较，已知产品外观 | 统一绘制语言保留杯型、切面与口味区别，不用图形取代真实份量 |
| 季节餐桌编辑 | 有真实时令、宴席或组合内容 | 多盘错落、斜向桌面、冷暖色层连接主图与清单 |
| 暗调食材微距 | 质地与制作细节是表达重点 | 局部侧光、自然暗部、油润或酥皮近景，深底不能吞掉信息 |
| 像素、波普或涂鸦 | 品牌希望俏皮、大胆、有节奏 | 图形对照与轻快字级，菜品识别和价格仍保持稳定 |
| 品鉴出版排版 | 用户或品牌明确以名称、年份、菜序精读 | 字体对照、细线与留白，可少图或无附加图，不由“高端”自动推断 |

烹饪动作、浇汁或蒸汽只能来自真实菜品或获准示意，不能新增工艺；生成材质和氛围也不能伪装成产地、手作或有机认证。

## 各类型菜单的图文组合与配图手段

先按点单任务选主关系，再组织整页；局部菜名与价格对齐，不等于整页等大、等距、等权。

- **招牌食欲型**：已确认的招牌／推荐菜承担第一焦点，放大有效食物主体，配合跨栏、出血或非对称布局；其余品项按分类稳定检索。
- **图鉴比较型**：同权菜品采用可比较的取景和尺度，让份量、配料、杯型等差异看得清；分类之间可有节奏，不强行造主角。
- **价目检索型**：名称、规格与价格优先，保留清楚的列组与行距；图片有点单或品牌职责才加入，不强加主图。

### 图文尺度与容量

先用真实内容确定可读字级和可辨认的食物主体，再决定列数、分区与页数；不先锁死网格再把图字缩进去。招牌须有明确尺度优势，比较图须能看清差异；主图、分类图与条目图按实际职责选用，不设统一面积比例或数量配额。

图片按有效主体而非图框判断大小：透明留边、空台面和装饰纹理不计作食物主体。先清理无功能留边、改善取景或图框；保留用于识别、份量判断的食物、器皿与配料，不靠裁掉它们放大。只能辨认色块时扩大主体或重排，不以放大预览代替实际阅读距离检查。

图文冲突时调整列宽、分区、取景或页数，不缩小正文、不取消用户锁定配图。原 Brief 记录选择依据与试排结果；需测量占比时注明页面、分区或条目的分母，图文叠压面积不必相加为 100%。留白服务焦点、分类与阅读停顿，不填高。

### 位置、裁切、遮罩与叠压

- **整盘／整杯去底图**：使用带透明背景的主体图跨越栏线、压住色块边缘或伸入标题留白，适合快餐、手绘拼贴、饮品和招牌菜。保护盘沿、杯口、杯底、把手、吸管及外伸配料；允许装饰压住空白边缘，不允许文字或色块遮住食物识别部分。
- **矩形摄影窗**：使用 4:3、3:2、1:1 或按真实照片决定的稳定取景，适合现代编辑、自然餐桌、分类横幅和高端菜单。单品识别图先清理无功能留边，再用 contain 保留完整食物与盘／杯；场景或特写按焦点裁切，图框不适配先调整图框或素材。可贴页边出血、跨一至两栏或成为侧边纵向图片区，不默认套圆角卡片。
- **圆形／椭圆蒙版**：仅在统一图鉴、杯型对比、小份甜品或品牌图形语言明确需要时使用。圆盘本身是圆形不等于必须裁圆；圆形蒙版不得切掉盘沿、杯身、装饰叶和关键配料，也不得成为所有条目的默认头像。
- **拱形、撕纸、邮票、手绘轮廓和色块蒙版**：只在已选风格确有对应语义时使用。蒙版轮廓服务于照片角色，不能为了装饰把菜品压成相同形状；食品主体与蒙版边缘保留呼吸区。
- **透明渐隐／羽化**：只用于场景图、台面或氛围图与底色衔接，渐隐从没有食品主体和图中文字的安全空场开始。整盘菜、单杯、包装标签和价格证据不得被羽化；主体图优先硬边去底、自然阴影或清楚摄影边界。
- **遮光层／色彩蒙版**：只有文字确需叠在照片上且对比不足时才局部添加，范围只覆盖文字背后空场；不能给全部菜图统一罩灰、罩黄或降低食物饱和度。文字可以进入照片真实负空间，不能盖在菜品、脸、标签或套餐数量证据上。
- **叠层与出画**：主图可超出网格、压住背景色块或局部越过页面边界来建立活力；副图只遮挡主图的空白、器皿外阴影或背景，不遮挡食物核心。叠压后仍保留菜名、价格和图片的一对一归属。

### 菜品与背景的联动

背景不能只是与菜品无关的浅色纸面、渐变或通用纹理。每页先从以下关系中选择一种主联动，最多叠加一种辅助联动，并写清菜品怎样进入背景空间：

| 联动方式 | 菜品与背景怎样连接 | 适用场景与边界 |
|---|---|---|
| 共享台面／场景 | 菜盘、杯子或食材落在同一木、石、布、纸或餐桌表面，统一视角、尺度、接触阴影和明暗方向 | 自然餐桌、轻食、西餐、咖啡；不得把不同透视和光向的菜图硬贴到同一台面 |
| 色块承托／跨栏出画 | 从品牌色或菜品真实颜色提取少量色块作为分类区域，去底菜品跨越色块边界、栏线或页面边缘 | 快餐、波普、手绘、饮品；色块承担分组和节奏，不得覆盖食物造成变色 |
| 摄影窗与页面底色衔接 | 照片保留清楚边界，或只在无主体的安全空场渐隐到页面底色；文字贴近照片负空间或相邻信息栏 | 现代编辑、餐厅特选、酒单；不得羽化食物、盘沿、杯身和包装标签 |
| 分类色场接力 | 各分类使用同一材质系统下的轻微色场变化，代表菜压住或靠近分类入口，下一分类从上一图的方向、色彩或边缘接续 | 多品项中餐、甜品图鉴、长页菜单；分类可区分但不能像几张无关模板拼接 |
| 食材／器皿呼应 | 背景中的线描、纹样、局部器皿轮廓或真实食材碎片与主菜有事实关系，作为阅读路径或分类提示 | 手绘、复古、地方菜、季节菜单；不添加菜品不存在的配料、产地和制作工艺 |
| 场景主图统领 | 一张餐桌、门店、厨台或宴席摄影成为大面积背景，文字只落在真实空场或独立承托区，其他菜图减少或不再重复 | 品牌餐厅、宴席、餐厅特选；场景不能比食物更抢眼，不能用遮罩制造不存在的空场 |
| 平面拼贴接力 | 菜品去底图、手绘箭头、色块、标签和短线共同形成一条明确动线，主图最大，辅图沿阅读路径出现 | 快餐、复古商业、年轻品牌；旋转、遮挡和贴纸必须有共同轴线，不随机撒图 |

背景联动必须同时满足：

- **空间一致**：摄影或 3D 菜图落在背景中时有可信接触点、阴影、视角和尺度；平面插画／拼贴可以刻意悬浮，但必须由描边、衬纸或色块说明其平面语法。
- **颜色互相支持**：背景色从品牌、食物或参考中取得职责，不把整页蒙成同一色。暖色食物保留层次，浅色餐盘与背景有边界，深色菜品不落入无细节暗区。
- **图文共同避让**：背景在文字区降低纹理和对比，主图则保留完整轮廓；文字利用图片真实负空间或相邻区域，不以大面积半透明白膜盖住菜品。
- **材质尺度一致**：纸纹、木纹、织物和颗粒按成品阅读尺度使用；背景纹理不穿透到每张照片表面，也不让菜图像贴在另一种无关材料上。
- **跨页／跨栏有接力**：上一图片的朝向、桌边、色块或装饰线应引向下一信息区。联动不等于复制同一菜图，也不靠无意义渐变填补接缝。

### 按菜单类型选择图文关系

| 内容与载体 | 可选图文关系 | 识别与阅读边界 |
|---|---|---|
| 招牌、快餐与餐厅特选 | 有重点菜时用代表图连接标题和分类列表；辅图只补不同信息 | 去底主体或照片图窗均可，保留食物、器皿和菜名价格对应 |
| 多品项餐厅 | 分类列表为检索主轴，代表菜图按外观判断价值加入，不要求每类配图 | 不把正文挤小，不用无职责的小头像或装饰填空 |
| 饮品、甜品与外观图鉴 | 需比较杯型、分层或口味时用同尺度条目图；否则采用分类图或列表 | 保留杯口、杯底、把手和关键配料，同权图片可同级 |
| 自然餐桌与轻食 | 代表餐盘、共享场景或独立摄影窗与列表共同构图 | 辅图数量由内容增量决定，保持真实食材、份量及接触关系 |
| 套餐与分享餐 | 组合图邻近固定包含、任选和加价说明 | 不暗示未包含的赠品，不裁掉盘数或改变数量判断 |
| 品鉴、宴席与酒单 | 菜序或酒款文字轴为主，主题图按需，可无附加图 | 不用图片打断菜序、年份、容量和价格比较 |
| 墙面与灯箱 | 分类、产品图与价格在同一视野组织 | 按观看距离与亮度决定尺度，不按面积百分比代替远读核验 |
| 手机菜单 | 窄屏分类与条目重排，重点图与所属菜名规格价格近邻 | 不把桌面多栏整版缩小，不要求每类都有入口图 |
| 插画、手绘与复古商业 | 有依据的插画、色块和列表共同组织阅读 | 不虚构外观或份量，保留价格轴，不随机撒贴纸 |

### 每页必须写入 Brief 的配图编排

每页或每个显示区至少写清以下内容，使用自然语言，不写 CSS 参数：

- 图片策略：图片主导／图文平衡／列表主导，以及选择理由；
- 整页关系：图片职责、文字容量及实际阅读尺寸下的试排结果；量化占比时注明分母，不为满足面积而新增配图；
- 一级主图：具体内容、对应菜品、相对面积、所在区域、是否出血／跨栏／出画、焦点与文字净空；
- 二级图片：数量、对应分类或套餐、与主图的尺度差、排列方向及归属；
- 裁切与蒙版：按图片用途选择完整展示或有依据的裁切，再选择图框与蒙版；保护主要食材、份量和器皿边界，核验裁后有效清晰度；
- 背景联动：共享台面、色块承托、摄影窗衔接、分类色场、食材呼应、场景统领或平面拼贴中的主关系，接触点、光向、色彩、材质和跨区接力；
- 图文关系：文字位于图片真实负空间、相邻分区、环绕区域还是独立列表，菜名价格如何与图片一一对应；
- 响应式或多载体变化：窄版保留哪张主图、哪些辅图降级或移除，不能只把桌面布局整体缩小。

禁止把“三个等宽分类顶图＋下方纯文字三栏＋大量微小圆形菜图”作为通用菜单模板。它只有在恰好三类、三张图同等重要、每栏内容相近且圆形裁切确有统一图鉴语义时才成立。若页面存在明显空白而所有菜图仍很小，应优先放大主图、让代表菜跨栏／出画、改变图片位置或减少无职责图片，而不是继续增加装饰线和小缩略图。

## 图文关系与文字排版

| 关系 | 何时选择 | 要保住什么 |
| --- | --- | --- |
| 主图＋分类列表 | 招牌或场景建立食欲，品项仍较多 | 主图明显强于普通条目，分类与价格不被挤小 |
| 单列／双列检索 | 长菜名或多项常规点单 | 每栏独立读，菜名与价格近邻，描述另行展开 |
| 规格矩阵 | 杯型、容量、杯瓶需要比较 | 列头、行对齐与缺项表达一致，不用空白冒充免费 |
| 图鉴式成组 | 少至中等品项，各外观有辨认价值 | 图、菜名、规格、价格逐项对应，不默认圆形蒙版 |
| 套餐组合＋选择区 | 固定项与任选项并存 | 包含、任选、加价分别分组，图片不承担数量说明 |
| 菜序编排 | 品鉴、宴席的顺序重要 | 序列清楚，图像不打断真实菜序 |

菜单 HTML 字号统一用 `px`。近读菜单按目标显示宽度、计入整版缩放后的有效字号判断：菜名与价格从 `16–20px` 起测，下限 `16px`；描述、译名、规格、单位、点单条件与过敏原从 `14–16px` 起测，下限 `14px`；仅来源、版权等非点单辅助信息可用 `12–14px`，全部有效文字下限 `12px`。下限用于验收，不是默认字级；按主次与阅读距离选择实际字号，菜单名与分类标题相应放大，关键点单信息不能借脚注降级。

先沿用 [菜单 Spec](../scenarios/menu-spec.md#尺寸与内容补写) 的尺寸与页数约束，再用最长菜名、多语种、多规格及复杂套餐连同图片试排。难读时先调整字号、对比、列宽、分区和非必要辅图，超量按分类分页，不持续增高静态菜单、不缩小整版或擅自删菜、删条件、取消锁定主图；锁定单页时先说明容量冲突。

文字全部由 HTML/CSS 实现：标题可有性格，普通菜名、价格与条件不图像化。金额、货币、单位相邻，双语主次或等权关系明确。卡片仅用于套餐、独立菜组或实际触控选择；普通列表用对齐和间距，避免同尺寸卡片压掉条件。

字体候选从 [字体推荐入口](../../../rendering/font-recommendation-list.md) 按语种、角色、形态和气质形成，并用真实菜单名、分类、菜名、译名、说明、价格、规格、单位、过敏原与点单条件试排；精选清单不是封闭白名单，查询脚本只提供候选、缺口和诊断。必须逐项检查菜名—说明—价格—规格—单位—过敏原的配对，换行、对齐或字体差异不得制造归属误判；数字、小数点、货币符号和单位须清楚辨识。装饰或手写字体只用于短标题，不承载价格、规格、过敏原或密集说明。视觉候选确定后，正式 HTML 再按 [字体资源与执行契约](../../../rendering/font-family-library.md) 核验实际 family、face、weight／style、许可、目标字形覆盖和 Web 加载，写入真实 DOM，并在目标载体与阅读距离检查条目配对、混排基线、换行、伪粗体、裁切和非预期回退；用户锁定精确字体时，门禁失败必须请求确认，不得静默替换。

## 食物影像与背景

- 实拍优先表达真实份量与摆盘；保留配料、数量、器皿、杯型、分层和产品身份。
- 菜品图、套餐组合图、氛围图与装饰图分别标职责。一图对应多菜时写全归属，装饰不能紧邻价格制造错误对应。
- 同组图统一视角、光线、背景和缩放依据，但不把不同盘型拉伸成相同轮廓。
- 裁切不作为低清修复，也不为躲参考图文字切掉菜品。正式菜单中主体模糊或最终有效像素不足的菜品、饮品、包装与场景素材，必须以实际源图为编辑目标执行 `image_edit` 高清化后再进入 HTML；仅背景有意景深虚化而主体清晰时不触发。编辑须保留菜品外观、份量、食材、器皿、包装、Logo 与准确文字，不猜补不可辨认细节；输出按目标显示尺寸复核真实细节和有效像素，尺寸放大、插值或锐化本身不算通过，未解决不得准出。清理旧字同样须保留菜品、主要食材及合理器皿边界，不能补造缺失细节或夸大份量。生成菜品示意须有外观依据和授权，必要声明由 Coding 就近呈现。
- 材质、纸面、共享台面可以连接全页，不默认给每盘套相框；盘子是圆的也不等于要裁圆。
- 色彩从品牌、食物或参考提取；文字与食物有足够对比，不使高饱和色或发光灯箱淹没细节。辣度、售罄等状态也有文字或图形线索。

## 形成每张配图生产意图并编译 Prompt

每项待生成或编辑图先在 Brief 单独写用途、目标页、画面目标、处理方式、参考职责与来源、主体和背景关系、保护与禁用项。冻结 Brief 后，在素材清单中补生产方式、比例、尺寸、安全区、消费者与准出标准并编译完整 Prompt；开头写具体风格与可见特征，再写已确认菜品、数量、器皿、视角、主体位置、配色、材料、光线、留白与裁切保护。多图分别描述，不能共用“高级菜品图”。

普通 Prompt 不写菜名价格等上屏文案、文字排版，也不写“无文字／无字／no text”等否定词；只说低纹理空间的位置。菜单没有电商 Hero 的一体生字例外。包装本身的真实标识属于资产身份，不借此删除。

参考图按图1、图2记录真实短链与借鉴内容；Prompt 只用图序号，工具参考参数同序传入，不放 URL 或本地路径。缺短链标待补，不调用依赖它的参考生成。原图编辑明确只改背景、裁切或后期等获准范围，不从风格参考复制另一道菜。

## 载体适配与验收

- 单页、册页核对 Spec 的选定页框与实际尺寸；仅采用默认设计范围的普通静态菜单检查短边范围及长短边比，不能用增高绕过分页。用户尺寸、真实载体和明确滚动／交互需求优先，不以默认范围否决。手机按目标显示宽度与完整预览逐条试读，导出计入缩放与压缩。按上述角色下限检查可读性；细字重、弱对比或纹理干扰仍判失败。分页、装订与折线不分开菜名价格。
- 墙面／灯箱按安装尺寸、最远预期阅读距离与实际亮度放大字级，近读字号下限不能代替远读验证；未完成实物远读检查时标记未验证，不以放大预览代替。
- 核对全部条目、多语种、规格列头、套餐加价、图片归属及示意标记，完成一次点单走查。
- 按所选主关系验收：招牌主体有第一焦点，图鉴能辨认菜品差异，价目表能快速对应名称、规格与价格；已选主图不能退为小缩略图。
- 交互范围存在时验证规格切换、单多选、加价和售罄；静态稿不声称交易已实现。

将本任务的字体、价格轴、图文层级、菜图与背景联动、容器／开放排版、载体适配、素材职责和降级写入 **视觉效果生产规范**；将上述点单、远读／近读、条目对应、图片尺度和交互边界检查写入 **视觉效果验收规范**，不能只写“按菜单 Visual 执行”。
