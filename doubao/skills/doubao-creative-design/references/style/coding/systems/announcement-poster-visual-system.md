# 公告海报视觉表现规划

本文件把 [`announcement-poster-spec.md`](../scenarios/announcement-poster-spec.md) 保存的内容结构补充为可执行的视觉方案，决定决策优先级、视觉命题、注意力路径、风格、艺术表现手法、配色、相对构图、图文占比、背景、图片层级、文字排版、载体适配、素材生产意图和可观察验收。完整 Prompt 在冻结 Brief 后编译到素材清单。

主体、受众、内容、日期、时间、地点、行动要求、叙事节奏、信息链、配图计划与画幅由 Spec 提供。Visual 保留这些内容，细化配图表现、风格和排版，不改变文案节奏、阅读顺序或图片用途。

## 底图与 Prompt 强制规则

每张作品级底图必须包含与主题和已选视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。文字安全区可以降低纹理频率、对比和密度，或使用局部纯色承托，但仍须与整体底图连续且同源。

每次写出具体底图 Prompt 前，必须先读取并遵循 [背景图 Prompt](../ai-coding/asset-prompt-guide.md#5-背景图-prompt)，按其中的背景职责、纹理选择模型和完整 Prompt 编译语法描述材质、色场、变化方向、尺度、低纹理区与连续关系。该路由适用于新生成和编辑既有底图；直接复用真实底图时不强造 Prompt，但必须记录使用方式并检查本节结果门禁。

## 读取入口

按主 `SKILL.md` 的画布资产读取规则，查找当前任务的设计 Brief，读取“公告海报内容结构”，不只依赖对话记忆。

找不到 Brief 或内容结构不完整时，返回 [`announcement-poster-spec.md`](../scenarios/announcement-poster-spec.md) 创建或补齐；Visual 不创建第二份 Brief，不自行补写事实、占位文案或新增海报。

读取可直接排版的标题与正文、简短的叙事节奏与信息链、配图计划及其来源后，开始视觉规划；只有文案大意时返回 Spec 补齐，不适用的时间、地点或行动要求无需补齐。占位草稿同样可以规划视觉，但须完整继承占位声明和正式使用前的替换要求。

## 容器与开放排版视觉决策

Visual 阶段必须在原 Brief 每张海报及各尺寸版本的对应条目中输出“容器与开放排版视觉决策”，多屏作品逐屏填写；先判断是否需要实体载体或信息边界，再按 [容器视觉语法](../composition-layout.md#容器视觉语法开放排版优先语义容器按需) 选择容器家族，不能只写全局风格或留到 HTML 阶段决定。

- 逐个说明容器名称、承载内容、位置与主次；同屏多个容器分别描述，共用效果可明确引用，但须写本屏差异。
- 写清轮廓与圆角／切角、表面材质、填充配色及纹理／渐变、边框与边缘、阴影与厚度、透明度／模糊，以及内部留白、图文排列、与底图和主体的遮挡关系。未使用的效果明确写“无”，不默认全部叠加。
- 只写可见效果的自然语言，不输出 CSS 参数、色值表或槽位契约；来源 ID 仅写入短采用记录；CSS／SVG 能可靠表达的规则容器、卷边、折片、缺口与结构关系由 HTML 原生实现，不因“实体载体”或“复杂壳体”等名称强制生图。只有无法可靠表达且确有视觉职责的复杂材质或非规则形体，才按 [素材使用规范](../ai-coding/asset-prompt-guide.md) 准备图片，文字承载沿既定路线。
- 无需容器时明确写“开放排版、无容器”，并说明如何用对齐、段距或分隔线组织信息；不能为填字段强加卡片或卡片嵌套。
- 普通白色圆角矩形只用于中性事实分组，不能覆盖全部公告内容。需要载体感时优先用卷轴／公告纸、报纸／档案页、文件夹／资料袋、撕纸／涂刷边、切角铭牌、票券或照片衬纸，以平面几何、卷边、折痕、背页、胶带、夹具、纸纹和接触阴影形成拟物结构。
- 将本屏效果写入视觉验收重点，检查实际边缘、材质、对比、文字容量与遮挡；不得仅凭“纸感卡片”“高级容器”等名称判为完成。

### 品类常用容器表

下表列出本品类常用容器候选，不是默认套用清单；先由公告类型、内容关系与已选风格判断是否需要容器，再输出本屏的可见效果。

| 常用容器类型 | 常见用途 | 视觉选择与边界 |
|---|---|---|
| 中性圆角容器（非默认） | 日期地点、报名方式、变更前后信息 | 仅在稳定事实分组成立时用薄边或实色面；普通事项不堆成等权卡片墙 |
| 阶梯面板 | 喜报结果、重点名单、关键结论 | 适合正式或仪式化边框；边框不侵入长文案 |
| 票券与缺口 | 邀请函、活动凭证、场次信息 | 只有票券／凭证语义成立时使用，不伪造条码、编号或兑换能力 |
| 不规则撕纸边 | 拼贴公告、活动重点、短行动语 | 只包短信息，长条须按最终比例验证，不作为通用正文框 |
| 文件夹轮廓 | 档案公告、招募岗位、分组事项 | 页签承担真实分类；无分类语义时不用文件夹装饰 |
| 照片衬纸与胶带 | 获奖照片、嘉宾照、活动图 | 承托真实图片与图注，不给纯文字信息假装照片框 |

### 已有布局 CSS 能力表

下表完整覆盖当前模板库已有的布局能力。Visual 根据内容职责选择，不按顺序轮用，也不要求每屏使用一种；写回 Brief 时使用表内能力名称和实际图文关系，便于后续自然语言匹配。名称用于能力对应，不输出 ID、路径、类名或参数。

| 布局能力 | 适用关系 | 写入 Brief 的边界 |
|---|---|---|
| 紧凑内容 | 同组事实、短字段、密集但可扫描的信息 | 写明压缩的是留白与组距，不缩小到不可读，也不把无关内容塞进同框 |
| 宽松内容 | 单一主张、少量重点、需要呼吸感的组件 | 写明留白服务的焦点与阅读停顿，不用空白凑画布高度 |
| 规整对齐（方格／网格排版） | 参数、证据、规格、并列比较和稳定栏目 | 写明列组、共同基线与主次；方格只组织可比较内容，不自动生成卡片墙 |
| 疏朗留白 | 长文、说明、编辑阅读栏与安静叙事 | 写明行宽、文字轴、图片归属与段间节奏，不等于所有内容缩成窄列 |
| 错落平衡 | 短标题接力、偏轴构图、左右不等权信息 | 写明错位对象、方向和共同对齐依据，不随机散放正文 |
| 聚焦主场 | 商品、人物、作品或场景作为第一视觉焦点 | 写明主体尺度、取景、文字静区和图文前后关系，不把主图缩成卡片配图 |
| 连续流动（串页／长页排版） | 长图章节、连续叙事、上下屏衔接和系列阅读 | 写明上一段出口、下一段入口、共享背景或接力对象，不只写“向下阅读” |
| 叠层拼贴 | 多张照片、纸片、证据或装饰需要错位叠压 | 写明主片、副片、角度、遮挡与保护区，不用随机旋转制造丰富 |
| S 形导览线 | 流程、路线、时间或概念节点需要曲线推进 | 写明真实节点、起止点和绕行保护区；没有关系节点时不用装饰曲线 |
| 横向卡片列 | 同类短条目、阶段、步骤或可横向扫描的内容组 | 写明条目共同尺度与差异；长正文、价格条件或复杂证据不挤入窄卡 |
| 章节眉线 | 章节编号、标题、短导语与换章提示 | 写明眉线承担的层级与接续对象，不把分隔线当主视觉 |
| 带引导线的图像标注 | 产品部件、成分、结构、地图或证据图解释 | 写明标注对象、端点和文字归属；引导线必须指向真实细节且不交叉遮挡 |

同一屏可组合兼容能力，例如“聚焦主场＋带引导线的图像标注”或“连续流动＋章节眉线”；组合后仍须形成一个明确主关系。没有适用能力时保留自定义关系并描述可见结果，不为命中模板改写内容。

### CSS 原子能力校验

完成视觉方向草案后、最终 Brief 冻结前，先比较同品类、同作用范围的 CSS 组合，判断整体信息层级、图文关系与视觉语言能否适配真实内容；再将组合未覆盖或需要替换的局部拆成下列自然语言能力词并执行公共限量查询。用户锁定项与事实不变，Agent 自选的栏数、容器形状和图片位置可随比较调整；确无适用组合时才转原子组装或自主实现。这里选中 ID、源路径与版本进入 Brief 短采用记录，不复制代码或参数，不因库中存在某种效果新增无职责装饰。

| 决策维度 | 交给查询的自然语言能力词 | Brief 保留内容 |
|---|---|---|
| 布局 | 阅读轴、主图关系、网格、错位、叠层、连续流动等实际关系 | 本屏图文主次、阅读路径与开放／分组方式 |
| 字形 | 填字、描边、发光、浮雕、路径排字等可见效果及文字角色 | 哪组文字采用何种效果、作用和可读边界 |
| 形状 | 当前选定的容器、图窗、票券、纸边、徽章或其他轮廓 | 轮廓服务的真实内容与本屏差异 |
| 表面 | 纸张、玻璃、塑料、织物、金属、柔焦等材质及承载对象 | 材质落在背景、卡片、图片还是文字，正文如何保持清晰 |
| 配色与背景 | 色彩职责、渐变／弥散方向、纹理类型及覆盖范围 | 可见色彩关系、背景变化、静区和保护范围 |
| 作用对象与边界 | 字体、卡片、背景、局部装饰；需要素材承担的复杂部分 | HTML 与图片的分工、必要降级及验收重点 |

候选摘要证明确实可实现后，把最终可见结果写回原 Brief；没有适用候选时保留已选方向，说明由素材或原生实现承担。真实引用、依赖、参数和消费者只进入后续 最终 HTML。

## 写回内容结构 Brief

保留 Spec 已写的全部字段，在“公告海报内容结构”中接着追加以下一套视觉字段，不另建“视觉 Brief”章节，不重抄内容：

- 风格：结合发布主体的行业／店铺／品牌特征、受众、公告事项与文案情绪确定具体风格，说明选择依据
- 决策优先级：用户锁定项、品牌规范、参考继承／排除、品类禁用项与 Agent 可裁量项
- 视觉命题与注意力路径：第一焦点、关键事实、说明与行动／落款的阅读顺序和最终视觉结论
- 艺术表现手法：与风格一起确定，写清背景、主体、辅助元素如何处理，怎样呼应本次公告的情绪与信息重点
- 配色：主色来源、辅助色与强调色、各自用途
- 相对构图与图文占比：谁形成第一视觉焦点，主体所在区域、图文上下／左右／叠压关系、图片与文字相对面积、密度、留白、对齐轴和允许遮挡区
- 文字排版：标题、关键事实、说明、日期数字与落款的字体、层级、断行和位置
- 图片系统与层次：沿用配图计划，写明主辅图尺度、位置、裁切／遮罩、前后景、背景联动和身份保护
- 背景与容器：具体画面、材质、文字承托和主体关系；默认无明显光源与定向光束，采用均匀漫射明暗
- 文字净空与安全边距：文字保留区与不可裁切区域
- 素材生产意图：逐图写用途、画面目标、参考职责、主体与背景关系、保护项和禁用项；直接使用的素材写使用方式，完整 Prompt 在素材清单中编译
- 参考图短链与借鉴内容：沿用已有来源，仅补充视觉参考与借鉴关系
- 尺寸适配、极端内容与降级：多尺寸的保留／重排／裁切、长标题和图片缺失处理，不靠删事实或整体缩小解决
- 视觉效果生产与验收：素材制作要求，以及焦点、文案、图文比例、主体保护、背景关系、禁止效果和真实尺寸的可观察验收

单张海报只填写一次。多尺寸版本共用这套视觉规划，在“尺寸适配说明”中按版本补充排版、裁切和安全区的差异，不重复填写全部字段。

只追加适用字段的具体内容，不能用“高级感”“参考案例”代替决策。实际试排发现内容或已确认画幅无法容纳时，返回 Spec 更新同一 Brief；不能为了造型删掉时间、地点、来源说明或占位声明。

## 结合发布主体与公告事项确定视觉表达

公告类型说明“要传达什么”，不预设“应该是什么情绪或风格”。通知可以活泼、温暖、实验或庄重，婚礼可以浪漫、纪实或幽默，喜报也可以克制；清晰、准确是信息要求，不等于冷静、商务或极简的视觉。

从 Spec 的主体、受众、具体事项与文案节奏出发，结合用户想传达的感受、品牌个性、参考图与已有素材，一起确定风格和表现手法。行业和公告类型都只是线索，不是风格标签；同一行业可以有不同品牌个性，同一品牌也可因场合调整表达。涉及风险、损失或紧急行动时，视觉不能淡化事项的重要性或产生误导，但不必因此抹去品牌特征。

类型只用于检查信息重点，不用于筛选风格：

| 公告类型 | 信息重点 |
| --- | --- |
| 日常通知 | 事项、对象与安排 |
| 变更公告 | 变化、新旧安排与行动，不暗示未知原因 |
| 停业／恢复公告 | 状态、原因与生效时间 |
| 公示公告 | 结果、依据与期限可查读 |
| 喜报／荣誉 | 成果与主体明确，庆典符号不冒充真实证据 |
| 成果战报 | 数字、单位、范围与口径，数据图形按实际数值绘制 |
| 婚礼请柬 | 人物关系与出席安排 |
| 活动邀请 | 活动主题与参与安排 |
| 开业／乔迁邀请 | 主体、新空间与到场安排，不虚构促销权益 |
| 聚会／宴请邀请 | 相聚理由与出席安排 |
| 节庆／周年贺图 | 祝福、纪念及节日与品牌的关系 |

用户参考与品牌已有要求优先，同时保证视觉情绪与事项的重要性相符。用一句话说明“谁向谁发布什么事项，因此采用什么风格和手法”，分别写入已有的“风格”和“艺术表现手法”字段；不新增行业分析字段，也不进行第二轮独立选风格。

需要展开创意或构图时，按需读取[创意概念](../../shared/creative-concept-system.md)和[构图原则](../../shared/composition-principles.md)。具体描述须写清背景、主体和辅助元素的处理，让素材 Prompt 与文字排版能直接落实，而不止留下风格名称。

### 风格候选与选择依据

风格表是跨品类的视觉词汇，不是公告类型的对应表，也不是必须先于手法完成的独立步骤。任何方向都可用于不同公告，前提是符合当前表达意图且不妨碍信息传达。

- 用户有明确风格、参考或品牌规范时，先识别其中的字体、图像、色彩与材质特征，不能只照搬风格名称。
- 未指定时，结合品牌个性、受众偏好和本次希望传达的感受，从表中选一个主方向；再用已有照片、主题物件、文案长度与画幅检验是否可落实，不按行业或公告类型自动匹配。
- 同时确定具体手法：风格说明整张作品的视觉语言，手法说明如何做出来。必要时用一个相容的辅助方向处理局部，明确主次，避免堆砌风格名。
- 在已有字段中写明选择理由，例如“希望亲切且有手作趣味，采用像素插画，以颗粒图形呼应主体，日期用清晰正文”；没有足够线索时选择能支撑现有内容的方向，不虚构品牌偏好。表外风格同样可用。

| 风格方向 | 具体风格举例 | 选择线索 | 对画面的直接影响 |
| --- | --- | --- | --- |
| 理性商务风 | 国际主义网格、瑞士平面风、现代极简主义 | 希望传达秩序、准确或专业感 | 明确轴线、字号级差、简洁图形与稳定事实区，不因是通知就默认使用 |
| 杂志编辑风 | 现代主义编辑、人文纪实编辑、高端时尚编辑 | 希望以人物、场景或文字的编排建立叙述与质感 | 照片裁切、标题尺度与网格留白共同组织阅读 |
| 自然质朴风 | 北欧自然主义、原生有机风、侘寂美学 | 希望亲近、松弛，或强调材料本身的触感 | 自然材质、柔和光线与有机形态，文字仍有清晰对比 |
| 新中式风 | 当代东方极简、宋式美学、新水墨风、金石书卷风 | 用户或主题希望采用东方审美语言 | 留白、纸面、笔触与字形呼应，不仅靠加入传统符号 |
| 国潮装饰风 | 新年画风、工笔重彩风、新国潮插画风 | 希望饱满、有装饰张力，且有适合转译的文化意象 | 主题纹样、叙事插画和色面共同构图 |
| 诗性浪漫风 | 法式浪漫主义、电影感柔焦、唯美超现实主义 | 希望柔情、梦幻或富于想象，不限于婚礼 | 光影、人物关系或花艺形成情绪，事实文字保持清晰 |
| 复古商业风 | 海派装饰艺术、昭和复古风、美式中世纪广告风 | 品牌或参考具有明确年代气质，希望怀旧而有识别度 | 时代字形、边饰、印刷色彩与纸感保持一致 |
| 手账拼贴风 | 档案拼贴、撕纸拼贴、混合媒介拼贴 | 希望私人、手作或有记忆感，且有可组合素材 | 照片、纸片与笔迹按主次叠放，不伪造事件记录 |
| 波普撞色风 | 波普艺术、漫画网点风、孟菲斯设计 | 希望明快、大胆、有节奏，受众接受强烈色形对照 | 强色面、网点、几何图形与大字建立视觉节奏 |
| 趣味创意风 | 像素插画、涂鸦艺术、黏土拟物、清新扁平插画 | 希望俏皮、童趣或有游戏感，符合主体个性而非仅凭行业判断 | 颗粒图形、手绘笔触或拟物主体与标题互动，正文不必像素化 |
| 都市潮流风 | 实验字体、街头涂鸦、地下音乐海报风 | 希望有个性、动势或街头文化表达 | 字体混排、斜向动势与影像裁切形成张力 |
| 未来科技风 | 未来极简主义、复古未来主义、赛博朋克 | 希望精密、前卫或有未来想象，且符合品牌与参考 | 金属、透明材料与空间层次；不默认添加方向性光束，不虚构数据界面 |
| 抽象色场风 | 全息虹彩、颗粒渐变、液态光谱 | 希望流动、通透或感官化，适合用非具象画面承载情绪 | 连续色场、透明叠色、折射材质与柔和失焦，不生成可辨认光源、放射光束或孤立光球 |
| 奢雅精致风 | 装饰艺术、新古典主义、时装高级定制风 | 希望仪式感与精细工艺感，且素材和品牌气质支持 | 比例、压印、织物与局部高光体现细节，不只套黑金 |
| 先锋实验风 | 解构主义、粗野主义、超现实主义拼贴 | 希望突破常规，用户或受众接受陌生化表达 | 打破轴线、尺度或媒介关系，但不破坏关键事实的阅读 |
| 材质肌理风 | 木刻版画、丝网印刷、纤维艺术、金属浮雕、透明层叠 | 希望材料或制作痕迹成为主视觉语言 | 通过颗粒、线描、反光、纤维与层叠表现主题，而非仅铺纹理 |

### 六类可选处理方法

以下用于细化已结合发布主体、受众与事项确定的表现，不是独立必选步骤。按需选一至三种写入已有“艺术表现手法”字段，并落实到文字、图片排版或素材 Prompt；不要求六类齐用，也不绑定参考图的配色与物件。

- **透明、反射与运动**：可通过失焦、方向性运动模糊、透明介质折射或镜面倒影组织空间。例如让柔化色带沿斜向流动，与清晰标题形成动静对照；或用半透明色面叠加表现层次。这些处理不等于添加照明光束；“放射构图”也只表示平面对象围绕焦点排列，不表示放射性光线。逆光轮廓、聚光等明显光效仅在用户明确要求，或明确要求保留参考中的该项光效时使用。按需写明模糊方向、清晰区域和反射平面，不强行为背景指定光向，不模糊准确文字、人物身份或证据，不用孤立光球代替空间。
- **图形与纹样**：用负形切割、密集曲线、重复圆弧、疏密变化或同一纹样的局部呼应建立动线。例如以水波状负形切开月轮，让底部浪纹回应它；或让连续线束弯曲、收拢、展开，为标题让出空白。写明母题、线条走向、密度变化和留白位置，缩略图下避免细线粘连、摩尔纹或干扰正文。
- **文字图像化**：用衬线、无衬线、手写花体或像素字的对照，结合连笔穿插、局部叠压、巨字裁切和低对比文字暗纹，让文字本身成为图形。写明哪组字主导、哪组字辅助、穿插与裁切发生在哪里；只使用 Brief 中已有文案，关键事实不裁切、不藏进暗纹，文字效果由 Coding 实现，不进入生图 Prompt。
- **实体与结构**：用信封展开、纸片透视叠放、封口、扣合、穿绳、悬浮与接触阴影建立邀请的仪式感。例如让圆扣与细绳连接上下纸面，或用展开的信封承托请柬；写明结构连接、前后层次、透视和受光。区分平面成品与请柬展示效果图，不能默认把可读的正面公告换成倾斜 Mockup，也不把结构细节变成装饰卡片堆。
- **印刷与材料**：用颗粒叠色、色层渐隐、箔金般反光、蚀刻线描、压印、纤维纸纹或仿旧破损边缘形成触感。例如让冷暖色层在纸纹中叠映，或用细密线描物件呼应旧纸边缘；写明材料、颗粒尺度、边缘处理和高光范围。做旧不侵入正文，箔金感不吞字；这些是视觉效果，不据此声称采用了真实烫金、蚀刻或印刷工艺。
- **尺度与虚实**：用巨大局部与微小主体对照、剪影留白、远近层叠、清晰与模糊交替形成纵深。例如只露出大型月轮的弧面，以小型主题物件和倒影建立尺度；或以前景剪影、中景插画与淡化远景组织层次。写明各层尺度、遮挡和清晰度，不为制造宏大感缩小事实文字，不用剪影或裁切替代必须辨认的真实人物。

## 决定配色

- 先保护 Logo、人物肤色、服装、产品和证据的真实颜色，再从品牌识别色、用户参考、主照片、活动主题物或材料中选择主色，并写明来源。
- 追求平稳或柔和时用同类色、邻近色作为辅助；需要强调状态变化、关键日期或成果时，用有明确对比的强调色，不让全部文字都发光或高饱和。
- 默认组织为主色与辅助色，必要时增加一个少量强调色；中性色承担正文和留白。已有品牌或参考要求多色时，说明各色职责，不为凑色数改动真实素材。
- 喜报不必红金，机构通知不必雾蓝，婚礼也不必粉色。颜色应与受众、主题和风格共同成立，而不是由品类名称直接套色。
- 多尺寸沿用同一颜色关系，可调整面积与明度，但不每张另换色板。
- 占位说明使用 Spec 的统一“**注：**”声明，放在对应内容旁，清晰可读但不抢正文；不因视觉简洁而隐藏、缩小到难读或删除。

## 决定整张图文关系

先用 Brief 中的标题、正文、日期与行动要求，结合本阶段选择的图片比例试排，再确定主关系。留白来自实际文字和主体需求，不预设文字区必须占画面多少。

| 主导关系 | 何时选择 | 图文如何配合 |
| --- | --- | --- |
| 事实主导 | 通知、改期、停业、安排公示 | 状态与日期形成第一信息组，解释与行动沿稳定轴线排列，主题素材退到不干扰的位置 |
| 字体主导 | 活动名称、品牌邀约或短标题本身有表现力 | 用字形、尺度与横竖排形成主体，日期地点成为清楚的次级信息，不能把每行都当展示字 |
| 人物或场景主导 | 人物关系、场地或活动现场是主要吸引点 | 先保护脸部、动作与环境识别，再为标题和事实寻找净空；图片不替代姓名和安排 |
| 主题图形主导 | 节庆、文化活动、无人物邀请 | 一个母题组织负空间与动线，标题与图形发生呼应，事实区保持顺畅阅读 |
| 实体载体主导 | 信笺、请柬、透明片或票券语义有助于邀请 | 载体自身成为构图主体，文字沿纸面或材料关系落位，不给每项日期地址再套小卡 |
| 成果数字主导 | 业绩、赛事或里程碑的结果是主要信息 | 数字、单位、统计主体与周期一起成立，主照片和辅助指标从属，不能只留下孤立大数字 |

选择一种主关系，局部关系为它服务。中轴、偏轴、上下分区、左右并置或编辑式穿插都是实现选项，不以通知类型或字数自动决定布局。

## 决定文字排版

### 标题与关键事实

- 用能表达选定风格的实际字形确定标题气质，再安排尺度、位置与断行。标题一般控制在一至两行；正式长名称保留完整，不为行数上限改写。
- 标题、关键事实、说明、日期数字、行动和落款形成明显层级。大标题不一定最粗，细衬线与粗字对照、偏轴和竖排都可按主题使用。
- 变更通知的新旧安排采用明确标签、对照或删除线；不只靠颜色区分。日期与时间、数字与单位、姓名与结果保持相邻。
- 真实英文标题可承担视觉焦点；装饰英文不得超过核心事项的语义权重，也不能临时编造英文填空。
- 采用文字图像化时，在“文字排版”中落实字形混排、连笔穿插、巨字裁切或暗纹的对象与层次，不写进背景 Prompt；艺术处理限于展示文字，关键事实与正文保持完整、清晰且可编辑。

### 正文与多组信息

- 单条说明贴近对应标题；时间、地点和出席方式按同一阅读轴分组，多项安排可并列，但不默认全部居中或等距铺满。
- 战报说明紧邻对应数字，单位、周期、范围和比较基准不缩成难读小字；不同口径不能因排版相似而被暗示为可比。
- 正文用高可读字体、自然断行和稳定间距，不压扁字形、不用大幅缩字解决容量问题。内容超量先回到 Spec 处理重复与分组。
- 占位声明与其描述的事实成组保留，预留真实阅读空间；规划文字、参考链接和检查结论不进入成品。

### 可编辑文字与艺术标题

本文件只细化主入口已锁定的父路线，不重新裁定制作方式。公告家族默认 ai-coding；明确纯代码或符合简洁文字公告条件的任务保持 pure-coding；用户明确要求全部由图像模型生成且不要 HTML 排版时保持 pure-image，不执行本文件的 HTML 组装要求。明确纯图长页在目标高度／宽度 > 16／9 时分段生成后拼接，不转回 HTML。

在 HTML 路线中，标题、姓名、日期、时间、地点、结果、单位、发布方、行动及正文默认由 HTML/CSS 排版并保持可编辑。仅 ai-coding 中明确需要艺术字、且通过首屏／首图主标题或每个独立图片唯一最重要大标题准入的文字，可按 [艺术标题 Prompt 与材质库](../ai-coding/art-title-prompt-library.md) 生成、抠图并逐字核验；同一图片默认最多一个。用户要求该文字或全部文字可编辑时不使用字图。其余标题使用真实字体、层叠与样式处理，不交图像模型生成。

在 HTML 路线中，字体先从 [字体推荐入口](../../../rendering/font-recommendation-list.md) 按语种、角色、形态和气质形成候选，并用准确的主标题、姓名、日期、时间、地点、结果、单位、发布方、行动和正文试排；精选清单不是封闭白名单，查询脚本只提供候选、缺口和诊断。主标题与日期地点须层级清楚，事实文字和小字优先保证可读；艺术标题获得准入不表示其他文字可以栅格化。视觉候选确定后，正式 HTML 再按 [字体资源与执行契约](../../../rendering/font-family-library.md) 核验实际 family、face、weight／style、许可、目标字形覆盖和 Web 加载，写入真实 DOM，并检查信息层级、混排、换行、基线、伪粗体和裁切；用户锁定精确字体时，门禁失败必须请求确认，不得静默替换或猜测字体可用性。

## 决定图片排版

沿用 Spec 配图计划中的背景图及其他配图、来源和用法，不另起一套图片计划。分别细化主图、辅助图、证据与装饰的大小关系、位置、裁切和前后关系；只计划背景图时，不为丰富画面擅自增加人物或场地照片。

配图数量指内容性图片，不等于实现素材数量。为实现既定视觉，可拆出背景中的非事实装饰或抠图主体；在原配图计划下补充它们对应的图片、拆分用途和来源，不改变原有内容及图片用途。需要新增人物、场地或证据等内容性配图时，返回 Spec 更新计划。

| 图片组合 | 适合的内容 | 排版重点 |
| --- | --- | --- |
| 单张主照片配文字 | 人物喜报、婚礼、场地邀请 | 主体清楚，文字进入低干扰区域或独立分区；不固定照片面积比例 |
| 一张主图加少量辅助图 | 事件与证据、人物与活动环境 | 主图建立识别，辅助图各补一类信息，图注与对应照片相邻 |
| 并列人物或事件图 | 签约双方、团队、同等参与者 | 视角与尺度相容，姓名归属明确；真实关系平等时允许等权并列 |
| 主题插画与文字 | 节庆、创意活动、无照片邀请 | 插画轮廓、动作或负空间呼应标题，说明区不被纹样填满 |
| 编辑式拼贴 | 活动回顾式邀请、青年文化、纪实主题 | 大小与叠压有主次，照片内容真实，不能拼出不存在的事件 |
| 品牌／人物与数字组 | 成果与战报 | 图像明确指向统计主体，数字不压脸、不吞单位，证据不被装饰覆盖 |

- 真实人物照片、Logo 和证据保持独立可替换；婚礼人物只能使用用户照片，不生成相似新人。无照片时采用不依赖照片的视觉方案，不保留空照片框，不改写公告内容。
- 图窗可保留清晰边界；沉浸式关系需要光向、透视与环境连贯；独立主体才按需抠图，不强制所有照片做渐隐。
- 裁切保护脸部、手部、动作接触点、Logo、证书标题和正在说明的场景特征；禁止非等比拉伸或用裁切制造虚假关系。
- 参考图中的人物、品牌、水印、文字与具体事件不会自动继承；只继承 Brief 明确授权的内容与视觉关系。

## 决定背景、承托面与安全区

背景从整张图文关系推导，可以是完整影像环境、纸张与织物、商业印刷底面、主题插画、透明材料或连续色场，不是固定颜色模板。

- **底图默认无明显光线效果**：采用均匀、柔和的漫射明暗，不出现可辨认的光源、定向光束、顶部聚光、从上向下的放射光、太阳芒／耶稣光、舞台追光、体积光、闪电／雷霆光纹或镜头光晕。喜报、战报的热烈与隆重通过色彩、字体、平面纹样、材质和构图表达，不能自动转译为顶部打光。只有用户明确要求某项光效，或明确要求保留参考中的该项光效时，才在 Brief 中逐项写明例外；选择抽象色场、未来科技、奢雅精致、庆典、隆重、红金、金色、丝绸／绸缎或一般性参考图片都不构成光效授权。
- 无明显光效不等于无层次：可保留柔和材质明暗、局部反光、接触阴影和非放射性色彩过渡，不额外制造亮光源或照射轨迹。直接使用的真实照片不因此强制去除原有自然照明，但不得为底图另加戏剧性打光。
- **放射构图不等于放射性光线**：用户明确要求放射构图时，只能用平面实色线条、色块、纹样、飘带轮廓或对象阵列围绕焦点组织视线，不得把线条转成发光射线、顶部光源、明亮锥形光束或舞台灯。丝绸／绸缎使用均匀材质明暗和褶皱起伏，褶皱不得全部汇聚到顶部亮点，也不得形成舞台帷幕式照射。
- 先说明颜色、材质、空间深度与主体的关系，继承默认光线规则，再安排标题、事实、日期、行动和落款所需的低干扰区域。净空位置和大小由实际文字、照片与画幅决定。
- 背景可承担完整无字主视觉，不必拆碎成大量装饰层；只有需要遮挡、替换或保持身份时才拆出独立素材。
- 背景成品不承载文案、真实人物、Logo、二维码、机构印章或证据，这些内容由 Coding 或独立真实素材承担。这是组装与验收要求，不将文字相关的排除项复制进生图 Prompt。
- 清晰纯色可用于事实区或字体主导设计；已有摄影、纸艺、花艺或复杂材质目标时，不能因制作方便全部替换成普通渐变。
- 通常先用字级、对齐和段距分组。只有纸面、请柬、票券等载体语义或对比需求成立时，才加承托面，不把每个信息组做成悬浮卡片。
- 阴影对应真实接触、叠压和统一光向；连续环境优先扩图或共用背景，需要渐隐时让图像透明度自然露出下层，不用短距离黑白渐变掩盖接缝。
- 只有已规划的背景、装饰与展示大字可以出血。关键事实、人物面部、落款和二维码避开裁切边缘；检查实际字形边界，而不只看文字框。
- 行动信息使用静态海报可执行的形式，如扫码、地址或联系方式；不把普通文字做成无交互的网页按钮。占位入口只作明确说明，不画伪二维码。

## 形成每张配图的生产意图并编译 Prompt

图片排版确定后，在该张海报的原图片条目中，为每项待生成或编辑素材分别写出人类可读的生产意图。每项素材须能对应原配图计划中的图片或其补充的拆分记录；内容性配图的数量、用途和来源仍沿用 Spec。多项素材不能共用一句模糊描述。冻结 Brief 后，建立素材清单时再按本节要求为每项记录编译完整自然语言 Prompt；直接使用或确定性裁切的素材只写使用方式，不为凑 Prompt 重新生成。

**普通配图 Prompt 只描述画面**：背景、材质及装饰等普通配图不写实际文案、标题、日期或文字排版，也不写“无文字”“无字”“不要文字”“no text”等否定要求，不列“字母、数字、伪文字”等文字相关排除词。普通可编辑文案与文字效果由 Coding 实现；需要留白时，只写“左侧保持连续低纹理区域”“下方留出开阔空间”等画面关系，不说明供哪段文字使用。本节逐图写法与示例均针对普通配图；准入的独立艺术主标题另按艺术标题库逐字描述准确源文字，已锁定的 pure-image 完整成品则在其路线内编译包含准确文案的 Prompt。

### 逐图写回方式

沿用 Spec 中的图片名称，在已有“素材生产意图”字段内逐项记录，不另建图片计划：

```markdown
### 素材生产意图

- 图片：对应配图计划中的哪张图
  - 用途与处理方式：背景／主照片／辅助图等；无参考生成、参考生成、原图编辑或直接使用
  - 参考与来源：逐项记录图1、图2对应的真实短链及借鉴内容；无参考时写“无”，直接使用时记录原素材来源
  - 图片排版：目标画幅、大小位置、裁切与文字净空，沿用已确定的排版
  - 生产意图／使用说明：待生成或编辑图片写画面目标、主体、参考职责、构图、背景关系、保护和禁用项；直接使用写具体使用方式

正式调用前，将上述条目与最终 Brief 的风格、配色、图文关系和安全区编译为 `asset-manifest.json` 中的完整 Prompt、生产方式、目标尺寸和准出标准；Brief 不再复制最终 Prompt。
```

仅一张背景图也要写清主题、构图、材料与留白，不只写“生成一张喜报背景”。多图分别说明职责，并保持已选配色、材质与主体身份一致；图片序号在每次调用内与实际传入顺序一一对应。

### Prompt 的内容顺序

风格是画面描述的首要信息：每条 Prompt 开头写明 Brief 已确定的具体风格及其视觉特征，再围绕它描述主体、动作、数量、背景、辅助元素、艺术手法、配色、材质、构图、视角、比例、明暗及裁切保护。不能只列物件或用“高级感”代替具体风格；这里是落实已有视觉决定，不重新独立选风格。

每条 Prompt 依次写清：

- 具体风格及可见特征，后续的图形处理、色彩、材质与空间关系如何共同服务这一风格。
- 图片的主题与视觉职责，是背景、主题图形、场景还是装饰；所属海报记录在图条目中，不把海报文案带入 Prompt。
- 基于哪些参考图，继承其中的主体、场景、构图、材质或风格中的哪些内容；原图编辑时明确哪些保持不变、哪些允许修改。参考的具体对应规则见下文。
- 主体的内容、动作、数量、尺度与身份保护要求；背景、主体和辅助元素采用什么艺术表现手法。
- 构图、视角、前后景、主焦点、目标画幅和低干扰区域的位置；在调用前确定目标显示尺寸与所需有效像素。
- 主辅色、材料处理与明暗层次，以及它们怎样形成整张风格。底图 Prompt 默认明确写“均匀漫射明暗，无明显光源，无定向光束；任何放射关系均为不发光的平面图形组织”；不强制填写光线方向、软硬或色温，仅在已明确的光效例外中细化。红金、金色、丝绸／绸缎、庆典和隆重不能作为补写光源的理由。
- 允许裁切与必须保护的区域，是否需要透明背景、独立主体或后续抠图。
- 按需限定身份变化、虚假证据和无依据元素等画面问题，不加入文字相关负面词。无光效例外时，底图负面要求包含“无顶部聚光、无放射光、无太阳芒／耶稣光、无舞台追光、无体积光、无闪电／雷霆光纹、无镜头光晕”；若采用放射构图，另写“仅使用不发光的平面实色图形围绕焦点排列”。

### 有参考图时

- 区分**主体来源图**、**风格／构图参考图**和**待编辑原图**。例如图1只提供花枝形态，图2只提供纸纹与配色；不能笼统写“参考图1、图2做同款”。
- Prompt 内只用“图1、图2”等序号，不写 URL、本地路径或工具参数。真实短链按同一顺序传入图像工具的参考图参数，并在该图条目及海报参考字段中记录一致的对应关系。
- 缺少真实短链时标记“短链待补”，补齐前不得调用依赖该图的参考生成或编辑，也不假称工具已读取图片；无参考生成不得引用不存在的图序号。
- 在参考记录中写清继承与排除项：不自动继承参考中的人物、Logo、文字、水印、奖项与事件；进入 Prompt 时只描述所借鉴的图形、色彩、材质或布局，不追加文字排除句。参考中的明显光效默认排除，除非用户明确要求保留该项光效。
- 用户照片、Logo 与证据能直接使用时，优先保留原素材，通过排版、裁切或抠图组合，不要求模型重画身份或事实。背景与真实主体分别制作，不把新人、证书或机构标识烘焙进生成底图。

### 示例：无参考生成背景

配图计划为“一张纸页与枝叶主题背景”，无参考图，目标为 1080 × 1440 px；Prompt 可写：

> 制作一张宽高比 3:4 的纸艺背景，采用细纤维纸张与木刻版画结合的表现；右上方以展开的纸页和植物枝条形成主要轮廓，均匀漫射明暗下以轻微接触阴影表现纸层厚度，背景使用纸白与植物绿。左侧与下方保持连续低纹理区域，枝叶不伸入这些区域，边缘留出适配裁切空间。无明显光源、无定向光束、无顶部聚光、无放射光、无舞台追光、无体积光、无镜头光晕。

### 示例：两张参考图生成背景

配图计划为“一张月轮与枝叶主题背景”。图1是月轮与枝叶构图参考，图2是纸张质感与配色参考；在实际 Brief 中填入各自真实短链，调用时按图1、图2顺序传入。Prompt 可写：

> 制作一张宽高比 3:4 的月轮与枝叶主题背景。借鉴图1中月轮局部出画、枝叶沿边缘展开的图形关系，只使用月轮与枝叶意象；借鉴图2的细纤维纸纹与淡黄、青绿色关系，不继承其光效。月轮位于右上角，枝叶少量分布于右侧与底部，中部偏左保留连续低纹理区域，下方留出开阔空间。以纸层叠压和轻微接触阴影建立层次，均匀漫射明暗，无明显光源，无定向光束。无顶部聚光、放射光、舞台追光、体积光或镜头光晕。

### 示例：编辑已有背景

原配图计划已经采用用户提供的花枝背景，需要适配竖版；图1对应待编辑原图的真实短链。Prompt 可写：

> 编辑图1，将原有花枝背景扩展为宽高比 3:4 的竖版画面。保留现有花枝的形态、颜色和纸纹，只向左侧与下方延展同样的纸面，新增区域保持低纹理与开阔留白。不要复制出第二组花枝，不改变原有主题，不添加人物或新道具。延展区域采用均匀漫射明暗，与原纸面自然衔接，无明显光源、无定向光束、无顶部聚光、无放射光、无舞台追光、无体积光、无镜头光晕。

### 示例：背景与真实照片组合

配图计划为“一张待生成背景＋一张用户提供的新人合照”。背景单独写无人物 Prompt，照片在同一字段中写使用说明，不把两人的身份交给背景生成：

> 直接使用用户合照，来源记录为该素材的实际标识或真实短链。放入已规划的右侧照片区域，等比缩放，保留两人完整面部、手部与接触关系；不修改五官、服装或人物数量。左侧为标题与邀请文案，下方为时间地点，照片不遮挡这些区域。需要去背景时按原图抠图处理，保留独立可替换素材，不生成相似新人。

以上只示范普通配图写法，不是固定配图、配色或布局。实际 Prompt 必须使用当前 Brief 的主题、配色、画幅、留白位置和参考来源；纯背景、材质与装饰图也须逐项描述。普通可编辑文案及文字效果留在 Coding 规划中，不传给普通配图的图像模型；准入艺术主标题与已锁定的 pure-image 完整成品分别按各自 Prompt 规则处理。

生成前读取[素材 Prompt 规范](../ai-coding/asset-prompt-guide.md)，落实参考、比例、像素和处理方式。素材的交付与问题处理遵循[图像交付门禁](../../../workflow/image-generation-delivery-gate.md)；记录实际缺陷，不因文件已生成或已交付就宣称视觉检查通过。

## 多尺寸适配

所有版本共享同一文案、事实来源、占位状态、主风格、主色关系、人物与品牌身份；每张单独试排并检查。

- 竖版转方图或横版时，可改变分区方向、断行、图片裁切、装饰密度和留白位置，但不能改变读者首先看到的核心信息。
- 先保留标题、主体、时间地点、行动与落款，再调整非必要装饰。数字与单位、姓名与结果、占位内容与声明始终成组。
- 场景图优先移动裁切窗口或扩展背景；重要主体无法保留时，调整构图，不拉伸或直接裁掉。
- 每张版本都有完整阅读闭环，不安排“上一张入口／下一张出口”，也不拼接成连续长页。
- 超出已确认尺寸或内容范围时回到 Spec 更新原 Brief，不能另建一份适配计划。

## 视觉效果生产与验收

将本任务适用的要求写入“视觉效果生产规范”和“视觉效果验收规范”；完成制作后记录实际检查结果，不以选定风格或写完 Prompt 代替成品验收。

- 缩略图下能识别公告类型与核心事项；目标显示尺寸下能读清时间、地点、单位、行动和落款。
- 主视觉、标题与辅助信息围绕同一传播目标，通知不被做成促销广告，邀请与喜报不只剩氛围。
- 用户要求的热烈、隆重、克制、浪漫或实验风格，在字形、色彩、材质和构图中有具体体现，而不只出现在描述中。
- 未明确要求光效时，底图无顶部聚光、放射光、定向光束、太阳芒／耶稣光、舞台追光、体积光、闪电／雷霆光纹或镜头光晕；出现时判为未通过，不能因属于喜报／战报，或采用红金、金色、丝绸、隆重、庆典、抽象色场与放射构图而视为默认装饰。若缺陷来自已成功生成的图片，先完成当前环境的媒体交付闭环，记录问题并暂停受影响依赖，取得用户明确修改要求后才编辑或重生成；原生 Coding 效果仍正常修正。
- 人物、品牌、证据与来源一致；参考借鉴没有替换真实身份或改变事件含义。
- 图片清晰、透明边缘干净；源图与显示容器的比例差不等于实际拉伸，须单独检查是否发生非等比缩放。采用 cover／contain 时保持等比，以实际取景、主体与文字保护、裁切后有效像素及最终显示清晰度验收，不仅凭比例差判失败；无溢出、裁字、压脸、单位截断、低对比或意外遮挡。
- 占位草稿的每处补写都有就近可读声明，不能以“无占位内容”否决已明确允许的草稿；正式发布版本需先完成 Spec 要求的事实替换与复核。
- HTML 路线的普通文案和未准入艺术标题由 Coding 实现并保持可编辑；普通配图的正式 Prompt 不含文案或文字相关否定词，准入独立艺术主标题按艺术标题库编译准确源文字并核验。生成素材若意外出现字符，判为未通过；成功结果先完成当前环境的媒体交付闭环，记录具体问题，影响下游时暂停相关依赖，取得用户明确修改要求后才编辑或重生成，禁止自主追加调用。Coding 原生文字仍须正常修正；不能用压平整图冒充可编辑成品。
- 每个尺寸都有同源实际渲染，素材、文案与检查结果相符；未完成的验证如实注明。

## 邀请函图文与 CSS 策略

以下能力补充本文件的 Brief 规划；事实、公告家族路线及放射性光线授权边界继续遵循主 SKILL 与本品类规则，不因配方默认效果扩大授权。

### 1.4 图文联合构图、素材先于组装

通知／邀请函采用“组合优先比较，必要时整页布局＋原子重新组合”的选型顺序，具体入口与适配边界统一见[4.2.1](#invitation-visual-css-routing)。通知／邀请函先决定整张画面的图文关系，再生产素材；“先做底图”只指生产顺序，不代表先选背景、再往上堆文字。先用真实文案联合试排标题、事实、主视觉和留白，文字区的位置、容量与承托方式由所选图文关系共同确定。

底图不是一张“已经设计完的空海报”。它必须为标题、核心事实和行动信息提供明确空间依据，并通过色域、光场、边缘密度、纸张或材质关系承担渲染作用。



### 4.2 构图选择规则

通知／邀请函先按参考与传播重点选择画面关系，再用 D1–D3 校验容量；密度不决定居中、纸卡或照片轨道。现有构图代码是描述入口，不是只能照抄的模板。

| 主导关系 | 何时选择 | 图文安排 |
|---|---|---|
| 字体主导 | 开业、时尚活动、品牌邀约，标题本身有表现力 | 用真实字体的尺度、粗细、横竖排或疏密建立焦点；正文独立清晰，可偏轴，不把所有文字等距居中 |
| 主题图形主导 | 节庆邀请、文化活动，有月轮、植物、曲线等明确母题 | 一个主要图形组织留白与动线，文字沿其侧面、弧线外侧或负空间落位；不把主题符号堆在四角 |
| 实体载体主导 | 请柬、信笺、信封、透明邀请片的物性有助表达 | 载体成为整张构图主体，可有叠纸、扣绳与接触阴影；不把每个事实字段再做成小卡 |
| 影像主导 | 人物、空间、活动场景承担邀请理由 | 先定主体景别与文字净空；照片身份有来源，生成环境不冒充真实现场 |
| 事实主导 | 放假、延期、停业等需要快速理解 | 主标题与关键日期形成级差，说明和行动用对齐、段距、细线组织；原／新时间可并列，不默认做按钮 |

邀请函与通知不套用同一留白量：邀请可让标题与主视觉占据较大篇幅，通知须优先容纳影响范围、时间和行动。信息过密先压缩重复说明、调整列宽和分组，确需多页时沿主路由处理，不靠卡片叠加解决。其他喜报／荣誉沿既有构图策略。

#### 4.2.1 通知／邀请函的 CSS 选型与执行

第 4.2 节的主导关系用于比较候选，不预先锁定布局。Spec 策略编号与底图模板不是 CSS ID；CSS 参数和素材契约以库内正文为准。

1. **优先比较组合。** 从本节及 4.2.2 的相关候选中，用 `describe ID...` 比较主题表达、风格、画幅、真实文案容量和素材条件；缺少关键关系时用 `get ID --prose` 补读。候选不足才按 [CSS 检索入口](../../../../assets/templates/css/README.md#按风格读取) 限量补查组合，不展开未选方案的代码和依赖。同题材或同配色不足以采用；示例行业、文案或颜色不同也不是排除理由。
2. **判断整体采用或适配采用。** 可替换文案、配色和主体素材，调整字号、区域比例与间距，同时保留所选组合的核心图文关系、文字层级和材质语言。适配采用对应公共记录的“结构适配”；将保留的可见关系与调整项用自然语言写入原 Brief，实际组装关系由 HTML 实现。用真实内容试排，若必须破坏核心关系才能满足需求，转下一路径；不为命中配方改变用户意图，也不因“机构通知宜克制”跳过比较。
3. **无合适组合时，整页布局＋原子重新组合。** 简记不适配原因，先从带产物与范围标签的整页布局中选骨架：开放主视觉可用 [单侧信息轴](../../../../assets/templates/css/layouts/asymmetric-balance.md#layout.cross-column-axis)，信纸、装订、票据方向可用 [通知与邀请函布局](../../../../assets/templates/css/layouts/notice-and-invitation.md)。再按需组合字体、配色、材质、形状和局部图文原子，统一主轴、字级与光向。库内骨架仍不适用时自主设计整页关系。阅读栏、图片主场、信封叠层和日期标签只承担各自范围，不能单独代表整页设计；局部借用如实记录，不标记整组采用。
4. **两条路径汇合。** 选定后用 `get <ID> --dependencies` 读取采用范围的实现及必要 `follow_ups`，按[公共 CSS 绑定](../../../workflow/html-assembly.md#css-recipe-binding)记录目标元素、覆盖参数和素材职责。先试排真实文案，再按 5.3 确定承托方式、按 5.4 生产底图；素材就绪后复核。长尺寸重算区域比例与文字容量，不拉高容器填空，也不沿用样例固定高度。入库方案可直接选用，当前素材、字体和渲染仍须检查。

### 5.1 字体规范

字体按角色选择，不按“喜庆／高级”猜名称：

- `display_title`：通知类型、喜报、邀请函、节日标题；允许宋体、展示黑体、真实书法字或定制艺术字；
- `fact_title`：核心事项、结果、姓名和新时间；优先清晰黑体或高可读宋体；
- `body_text`：原因、说明、邀请语和影响范围；不得使用难读书法；
- `date_number`：日期、时间、成绩、编号；使用高辨识数字字体；
- `signature`：发布方、邀请方和品牌落款；保持真实 Logo／字体规范；
- `fallback_stack`：HTML 中可稳定加载的回退链。

要求：

1. 正式 Canvas 记录 `package_status=canvas_platform`、`coverage_status=verified_by_platform` 和字体契约；并用真实文案完成字体资源可用性检查 并记录本地路径；
2. 主标题通常不超过两行，核心标题建议 4–14 个中文字符；
3. 正文保持稳定字距和行距，不能为了塞入而压扁；
4. “囍”、书法标题或艺术字必须来自用户资产、真实字体或逐字核验的独立资产；
5. 日期、地点、姓名、成绩和行动要求始终使用可编辑 TEXT；
6. 英文语义通常为 P2，但用户提供的准确英文标题可承担视觉主导；中文事项与关键事实仍须易读，不编造英文填版。

通知／邀请函主标题默认采用较正文更有分量的字形，按实际渲染判断主次；采用纤细字形时，仍须通过尺度、对比和构图保持标题主导，不仅比较字号或名义字重。强调日期优先用数字尺度、位置和字重，不自动加胶囊。正文保持稳定阅读，不把每一行都做成展示字。



### 5.3 信息承托、材质与边界

通知／邀请函的承托方式由所选组合或整页布局决定，不先固定有框或无框：

- **背景直接承字**：在底图规划的低干扰区域排字，适合开放主视觉关系；按目标字色检查局部明暗与纹理。
- **背景＋独立信纸／信息面承字**：载体承担正文时，由 Coding 根据真实内容建立内容框与内距；复杂纸感可用素材承载，文字独立。背景围绕信息面构图，不重复生成同一纸框。

文字区容量决定两种方式是否可用，不以文案长短机械指定。日期、地址和提醒优先用字级、对齐、段距与细线组织，不逐项套卡；主承托面和从属区的数量上限不是配额。

**容器与投影**：实体请柬、单一公告纸面、照片图窗或透明邀请片可成为构图主体；文字仍独立可编辑。普通时间、地点、提醒不默认做胶囊、圆角按钮、图标底座或层层嵌套的信息框。胶囊只在所选视觉确有票签／标签语义时使用，不能让所有重点都像按钮。平面分组默认无投影；纸张／透明片的阴影须对应叠压、悬空距离和统一光向，局部、轻薄且有接触依据，不用大面积黑色模糊、上下暗晕或中心亮斑制造“高级感”。

**渐变与衔接**：在既有 `HTML 中的层级与相邻区域关系` 和 `素材清单中的必要后处理说明` 中先说明是连续场景、色场过渡还是有意分区，再决定实现。连续背景优先共享同一底层或扩图；需要蒙版时对图像自身 Alpha 做渐隐，露出实际下层颜色，明确起止位置与足够的重叠范围。不得在素材矩形底部铺短距离黑／白渐变遮盖接缝。深浅跨度大时先调整素材边缘与过渡范围；确需中间色，选择与两侧同色系的色阶，不引入脏灰带。场景、纸面、纯色区有意转换时可清晰分界，不强制所有边界柔化。

**切边与安全区**：区分画布裁切、素材图窗和容器裁切。仅已规划的背景、装饰或展示大字可出血；标题正文、日期地点、联系方式、二维码与完整信息卡须保留安全距离。检查实际文字墨迹、圆角轮廓和纸边，不仅检查盒尺寸；必要时扩大容器、调整内边距或素材裁切，禁止靠 `overflow:hidden` 截掉内容来消除溢出。跨区叠压先在 HTML 说明所属层和遮挡顺序，不让相邻色块盖掉卡片一侧。遇到折页按主路由读取对应规范，折线可形成分区，但关键文字／二维码避开折线；跨折装饰须有意设计，不把正常折线抹成渐变。

这些规则用于通知／邀请函的平面表达；其他喜报沿原策略，仍不得遮挡事实或形成无职责卡片墙。
