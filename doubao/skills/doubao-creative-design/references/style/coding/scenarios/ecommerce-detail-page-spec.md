# 电商详情页内容与叙事 Brief
本文件用于电商详情页、电商长图、商品副图组合和 Amazon A+ 内容。它决定下述七类问题：
- 整页叙事节奏
- 说服链
- 每屏作用、解决的购买问题
- 各内容段的配图职责与来源
- 每屏文案
- 总屏数
- 每屏尺寸与段高

本文的“屏”在连续长图中指内容段，不等于独立背景或一张生成图；商品副图、A+ 等独立版位仍按实际载体分别交付。内容阶段确定配图要说明什么，共享场景与独立图窗的生产范围由 Visual 决定后写回同一 Brief。

**注意**：本文件明确上述七类内容职责并写入设计 Brief 的“内容结构 Brief”板块，再与 [`ecommerce-visual-system.md`](../systems/ecommerce-visual-system.md) 按其首段边界联合完善图文方案；最终风格、美学、配色和跨段背景仍由 Visual 决定，完整方案沿原 KV／冻结流程确认。

## 底图结果约束

凡本品类进入 HTML/CSS 设计，作品级底图必须包含与主题和视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。事实与正文区域可以局部降为纯色或低纹理以保证阅读，但仍须属于同一底图系统。Spec 只记录这项结果门禁和底图职责；具体材质、色场、变化方向、生成方式与 Prompt 由对应 Visual 决定。

商品资料、概念补充和统一说明遵循 [内容创作与事实边界](../../shared/content-truth.md)；已有资料与补充设定在同一 Brief 中区分。

### 详情页视觉证据节奏合同

在锁定逐屏责任前，内容结构 Brief 还必须写一段“视觉证据节奏”，把购买信息转成不同的观看方式，而不是把每项卖点都做成“标题＋说明＋矩形商品图”：

- **Hero 视觉主场**：从“完整商品雕塑化陈列／人物上身或真实使用场景／材质或工艺极端微距／结构拆解或环绕标注／动作或性能瞬间／编辑式大小图叙事／连续场景跨屏”中选择主导关系，由其核心影像承担第一视觉焦点。商品身份须清楚可辨，但完整商品不必总是最大对象；微距主导时，用可识别的全貌或定位上下文说明细节归属。按对应 Visual 写清主体、承托、文字位置、辅助证据和下一屏接力，不得用缺乏主场的小商品图、空白、渐变或卖点卡补高。
- **图片层级依据**：视觉高点由商品与购买信息决定，不规定主场数量；有主次关系时明确主图与辅助证据，同条件比较可同尺度同权。普通信息屏可无图片或只用一张局部图，不能为“图多”复制小矩形商品图。
- **证据形态轮换**：按内容段选择“整体轮廓／穿着或使用场景／材质微距／结构标注／动作或性能／规格决策／信任或服务／收束”等主要形态，以信息职责决定尺度和排布变化。连续说明或真实对照可以保持相同关系；改变证据形态不要求更换背景，不机械逐屏换景。
- **构图与辅图依据**：由新增信息决定是否跨栏、放大、环绕、叠压、跨段连续或追加辅图，不设置动作数量配额。每张辅图须补充可指出的细节、定位、过程或比较；无内容增量则不添加。同条件比较可保持同尺寸图窗，不能为反模板强制造型变化。
- **内容段、背景与交付切片**：内容段按购买问题及真实图文容量定高，交付切片按平台尺寸和安全边界划分，二者均不自动触发换背景。Spec 记录各段需要呈现的主体、证据及上下段接力意图；Visual 再判断哪些段共享背景、哪些内容使用独立图窗，并将实际配图数量与覆盖范围写回原 Brief。共享背景不要求内容段等高；表格、FAQ、参数和规格仍按真实容量组织，不以空白补齐背景范围。独立版位按实际载体交付，不强求跨版位连续。
- **信息与阅读节奏**：参数、尺码、服务和认证按可读容量组织；需要换挡时用商品、场景或有职责的停顿接续，不要求每个信息段前后增加情绪屏。透气段须有实际叙事作用，不能用空白填满屏高。
- **参数／规格的决策职责**：每个表格、FAQ、尺码或对照模块要写清帮助用户作出的具体选择，以及要保留的行列；它是最后的决策工具，不得把整页正文退化成密集表格，也不得为视觉整齐把关键条件缩小。

这份合同只写可观察关系和职责，不写坐标、CSS、DOM ID 或库模板；Visual 再把它转成具体构图和 HTML 实现。

### 生产状态与增量维护

Brief 是持续补全的唯一任务记录，不另建平行版本。先明确输入与说服轴，再形成完整候选视觉系统和逐屏方案；适用 KV 的任务在候选完整后出图确认，最后冻结同一 Brief，再生产素材和 HTML。阶段状态只用于既有执行记录：`INPUT_LOCKED` → `PERSUASION_LOCKED` → `CANDIDATE_COMPLETE`（视觉、准确文案、逐屏职责与图文关系均有可执行候选）→ `KV_APPROVED`（适用时）→ `BRIEF_FROZEN`（视觉系统与逐屏方案一并冻结）→ `ASSETS_READY` → `CODED`。这些状态不是 Brief 的必填机器字段。

- Spec 和 Visual 分别补齐自己的内容与视觉职责，KV 前允许迭代完整候选；确认后更新原 Brief。上游变化时复查受影响的素材与实现，不等待 KV 后才规划逐屏。
- 未达到前一状态不得假装进入后一状态；不需要 KV 的任务可以跳过 `KV_APPROVED`，但须在 Brief 中注明。
   
## 整页叙事节奏及叙事方式
**统一策略**：先展开用户从产生兴趣到选择商品需要理解的内容与体验，再以真实事实和证据校准表达，联动推演文案、画面及前后关系，最后决定段落与素材数量。资料有限时，可围绕可见外观、佩戴或使用关系、配色与搭配建议展开；创意情境不冒充实际使用证据，未知性能、数据与承诺不补造。不按现有图片张数或款式数量直接划分章节。

- 同时判断主要购买动机、用户首先追问的问题、决定性证据、决策成本／风险和购买时机，据此确定叙事快慢及证据前后，不换算透气屏数量。
- 品类责任链用于查漏，不直接变成章节。先判断缺少的是事实依据还是尚未设计的表达：前者删除无依据断言或记录必要缺口，后者完善内容与配图；再合并重复任务，拆开无法在一段讲清的复合任务。
- 每段写清新增理解或体验、具体内容、画面支撑及承接。删除该段若没有实质损失则合并；关键理解仍缺失则补内容与配图。情绪可承担独立体验任务，但须由具体场景或视觉变化兑现，不能只换口号或重复照片。
- 陌生新品先解释是什么；成熟品类突出真实差异；高客单或高风险商品前置信任与风险条件；食品、护肤和材质商品可先建立感官吸引，再回到真实商品事实。
- 主体责任链完成后再复核连续信息负荷。优先在相邻内容屏内部改变留白、景别、密度、媒介或构图；只有确有承上启下职责且不能由相邻屏承担时，才建立独立透气屏。

**品类对应的叙事节奏及说服链**
* **功能标品**：展示产品→展示痛点→展示解决(拆解→参数/PK→认证→质保)→结尾
* **颜值感官**：展示产品／调性／生活方式→场景搭配→材质与工艺→感官体验／完整系列→选择与售后→结尾
* **高信任门槛**：展示产品→展示痛点→展示解决(专利/专家→机理/对比→检测/临床) →试用→售后)→结尾
* **高频快消**：展示产品→展示爽点/痛点→展示解决(量贩/性价比→多场景→极速发货→售后)→结尾
* **B端采购**：展示产品→展示(国标资质→使用场景→暴力测试/细节→详细参数标注→工厂/品牌实力→售后寄样/定制)→结尾
* **轻奢高客单**：展示产品与身份价值→材质／工艺／来源→佩戴或空间关系→证书与服务→结尾
* **虚拟服务类**：说明服务解决的问题→展示真实内容／界面／流程→权益与适用条件→交付与售后→结尾

## 总屏数
这里的“屏”指完成一个内容或体验任务的叙事段落，不等同于手机视口；实际滚动长度由图文容量与阅读节奏确定。潮流服饰、配饰等视觉驱动详情页以5–7个完整段落作为起始容量参考，充分展开后按任务合并或扩展，不设最低屏数。一行标题或价格组不自动算独立一屏，也不靠拉长留白补足数量。下表用于估计规划容量，不能代替逐段内容判断。

*品类惯例屏数对照表*：
| 品类 | 屏数 |
| :--- | :--- |
| **功能标品**（数码3C / 智能家电 / 硬件设备） | 6 ~ 9 屏 |
| **颜值感官**（潮流服饰 / 时尚鞋包 / 家居饰品） | 5 ~ 7 屏起步，按有效内容调整 |
| **高信任门槛**（保健品 / 功效护肤 / 孕婴童用品） | 7 ~ 10 屏 |
| **高频快消**（休闲零食 / 日用百货 / 快消纸品） | 4 ~ 6 屏 |
| **B端采购**（车间工作服 / 工业设备 / 办公耗材） | 5 ~ 8 屏 |
| **轻奢高客单**（珠宝首饰 / 高端手表 / 艺术家居） | 5 ~ 7 屏 |
| **虚拟服务类**（知识课程 / 软件服务 / 权益卡券） | 4 ~ 6 屏 |

### 运动商品完整长页候选

性能证据、局部特写、参数逐层展开时，可选「性能递进长页」；多组穿搭摄影、非对称图窗与单品交替时，可选「摄影分章长页」。按真实内容取舍章节，不锁定参考商品、演示数据、屏数或原总高。具体布局与皮肤由 [Visual 候选](../systems/ecommerce-visual-system.md#运动商品长页候选) 分开匹配；Brief 记录自然语言关系，不要求填写 CSS ID。

### 候选 KV 与正式首屏的边界

候选 Visual KV 只确认视觉方向，按 [KV 生成规则](../ai-coding/asset-prompt-guide.md#kv-visual-generation) 使用横版 `1920×1080`，以商品、准确主标题与连续场景建立焦点；不要求后续卡片／素材样本，不提前制作竖向首屏。候选生成完成后按 [KV 确认工作流](../../../workflow/visual-kv-clarification.md) 等待确认，再生产正式素材。下述逐屏尺寸与正式 Hero 方式均不覆盖候选 KV；具体生成约束只在素材指南维护。

## 每屏尺寸策略

先完成逐屏责任与真实内容试排，再确定背景图片的生产比例、安全区和完整长页尺寸策略。屏是内容与构图单位，不等于手机视口，也不默认等高；同类内容可以等高，不同责任必须按实际信息量、主体尺度和视觉重量变化。不得先给所有屏套固定高度，再靠缩小字号、拉大空白、增加无职责装饰或重复卖点填满。

### 1. 统一测量口径

- 先确定成品宽度 `W`，再为每屏确定高度 `H`，以 `H/W` 表示段高比；不要把段高比与该屏占整图总高的份额混写。
- 每屏从上一屏出口到下一屏入口整体测量，包含标题组、正文、商品／人物、环境、卡片、必要留白和段尾出口；不得只按图片框或外层容器高度计算。
- 每屏 Brief 必须用自然语言记录尺寸策略、段高依据、主焦点、关键文字／图片组、上下屏入口与出口，以及安全切片边界，不记录最终坐标。HTML 实现时以正常文档流保持各区段纵向连续，不维护独立坐标表。

### 阅读尺寸与字号门槛

本节仅适用于电商详情页（含作为详情页交付的连续长图）。

- 按实际展示宽度验收；手机端未指定时按 390px，多个目标宽度逐一检查。
- 所有内容文字在最终阅读宽度下不得小于 13px；13px 是下限，不是默认字号。模板中的 12px 内容字须调整，难以辨认时增大字号或重排。
- 未缩放 DOM 查目标视口计算字号，缩放 DOM 查有效显示字号；整图及嵌入图片按实际显示宽度检查。已知源 HTML 时，等效字号 = 源 CSS 字号 × 实际显示宽度 ÷ 源 CSS 画布宽度（均为 CSS px）；仅有位图则直接看最终尺寸，无法确认记未验证。放不下先重排，不缩字。

### 2. 正式 Hero／开场屏

- 正式 Hero 按“用户明确指定的 Hero 尺寸／比例 ＞ 已明确选用的完整命名配方原有 Hero 高度规则 ＞ 通用默认 `H/W = 1.8`（宽 1080px 时高 1944px）”确定高度，并在 `height_reason` 中记录所用依据。只借用配方的配色、字体、布局原子或局部模块不触发配方高度；配方未规定 Hero 高度时仍使用通用默认值。
- 横版 KV 只确认视觉方向，不能直接决定正式 Hero 比例。正式 Hero 必须按上述优先级确定的正式槽位重新构图；用户或配方确定为横版时保留该槽位。标题、商品、环境和下一段入口共同兑现高度，不能以小商品、纯渐变、大 padding、空容器或卖点卡补高。

### 3. 后续各屏

- 普通卖点、全貌、场景、步骤、参数、证据、规格、换气和收束屏均不继承 Hero 比例，也不使用统一默认屏高。
- 透气屏的 H/W 仅作分场景试排参考，不继承或按百分比绑定 Hero 高度；实际段高按内容、主体保护与接力需要确定，超出参考范围时记录 `height_reason`，并同步复核背景消费范围、接缝与切片，不以空白或重复素材补高。
- 按真实文案、实际字体与断行、主素材比例和主体可见尺度、卡片内容、屏内边距、组间距及段尾出口试排高度。主体周围有构图职责的空间可以保留；卡片／步骤末尾、CTA 前及段尾没有职责的余量必须收拢。
- 首屏、全貌、场景、换气和收束通常采用低到中密度；参数、步骤、证据、选择和规格可采用中到高密度。密度决定内容组织和节奏，不直接换算为固定高度或固定留白率。

### 4. 总高、改尺与切片

- 用户未指定总高或比例时，先用文字容量与比例测量确定素材所需目标尺寸，写入原素材清单；素材就绪后在正式 HTML 逐屏试排，按自然内容与独立安全区实测总高。尺寸变化时回到受影响素材步骤；由正常文档流或同步更新后的定位自动形成后续屏位置，不维护独立坐标表。
- 用户严格指定整页总高或长宽比但未指定 Hero 高度时，保持已按优先级确定的 Hero 高度，在后续屏之间重分配比例、图文尺度和有职责空间；无法兼容时说明冲突。用户同时明确指定 Hero 尺寸时按其要求执行。不得在末尾集中补空、拉伸图片、压小正文、重复装饰或虚构卖点填高。
- 尺寸调整必须同步更新最终 HTML、完整背景的使用方式、图片消费区域、接缝和切片边界。切片不得截断标题、商品、人物面部、数字单位、步骤节点、证书或连续背景关键节点。

### 各屏功能
- 一屏只承担一个主要功能，保留一个核心主张，回答一类问题。
- 每一屏都明确写出该屏功能，例如：理解杯盖如何密封；比较两个规格的差异；知道完整套装包含什么；在推进决策中缓解氛围进行换气。

### 屏内文案
- 先按该屏功能确定要传达的信息，再决定表达方式；不能只写“高级感文案”“年轻化文案”等空泛风格。
- 开场屏写清产品是什么、适合谁和核心利益；共情屏描述真实场景或痛点；解决屏先给利益结论，再用功能、参数、步骤或证据解释；结尾屏汇总选择条件、售后和行动。
- Brief 中写明主标题、正文、必要数据与限制条件，并区分信息来源和概念补充；不将内部核验记录逐项展示在成品中。
- 文案长度由屏内信息和版面共同决定：一屏保留一个核心主张，正文补原因和必要条件；仅影响理解的局部说明就近呈现。

**开场屏：**
- 正式电商开场屏默认使用无字主图＋独立 HTML 原生标题与文案（商品与环境共同构图，保留原包装文字与 Logo）；主图不新增上屏文字，保留商品原有包装文字与 Logo。按 Brief 明确选择一体生成且符合文字编辑边界时，才将商品、环境、主标题及必要短辅助文字共同生成或编辑；价格、日期、条件、参数和正文始终使用 HTML 原生文字。所选一体化模式的 DIT Prompt 只逐项编译获准入图文字的准确文案、文字层级、字体特征、字色、特效与位置关系，不以 HTML 覆盖或重排图内文字。
- 图片：按已选 Hero 主导关系建立品牌调性与商品身份，核心影像主导，定位图与辅助信息从属；保留用于识别或证明的真实轮廓、Logo 与关键结构。
- 文字：用可读的主副层级说明使用时机、品牌、产品名称和核心利益；文字与主体之间留出真实静区，不能把一组卖点卡放在商品周围代替 Hero 构图。
- 商品溢价越高，文字越少，但主标题、身份和必要条件仍需清楚；价值感由主体尺度、取景、材质、场景和留白承担，不由缩小商品或堆加空白承担。

**共情屏：**
 - 溢价类：展示理想生活方式
  - 图片：
  - 文字：
 - 实用类：展示实际生活痛点
  - 图片：
  - 文字：
 
**解决屏：**
按当前购买问题与可用真实证据组织。价值、信任、体验和售后仅作职责分类，可按需选用、合并或省略，不要求逐类建屏；屏数由内容自然统计，配图由信息增量与共享范围决定。

奖项、认证、检测、专利、专家背书和客户案例须有真实来源；信息缺失时按事实边界调整内容，不以经验编造证据。

**透气屏：**

- **职责与准入**：透气屏是可选屏型，用于情绪延续、章节过渡、材质感知或生活方式想象，不按品类、分数或总屏数预设数量和位置。先尝试由相邻内容屏的出口、入口、留白、景别或密度变化承担；只有无法由相邻内容屏承担，且能写清上一组完成的论证、下一组进入的任务及其接力关系时才独立创建。它须与商品、品牌、证据或后续内容保持可观察关系，不以无关氛围图、空白、重复照片或口号填高。

- **Hero 后紧邻透气屏**：确需独立设置时，默认采用较短、较轻的过渡，`H/W = 0.38～0.68` 仅作试排参考，不绑定 Hero 高度百分比。验收看是否收束首屏注意力、降低阅读负荷并引向后文，而非复制完整商品／人物场景加大标题的第二张海报。可用材质局部、环境细节、低干扰色场、抽象关系或短句；允许延续 Hero 的背景、媒介与构图语法，不规定变化维度或锚点数量。
- **页中透气屏**：`H/W = 0.45～0.90` 仅作试排参考，按材质、场景、文字及前后接力确定实际段高。可使用材质微距、生活方式局部、品牌色场、章节短句、环境细节或抽象图形；较大场景须承担可指出的情绪或叙事推进。多个透气段可复用同一摄影或材质语言，但不得重复同一无增量职责。
- **内容与分类**：可无字，或使用通常 0～20 字的短句，字数不作硬门槛；可重新锚定商品、总结已有感受、引出章节或强化已核实价值，不承载复杂参数、优惠条件、规格比较及长篇说明。按主要职责分类：完整主体仅作身份锚定不自动改类；主要承担独立体验、价值解释、证据或新购买结论时，归入相应内容屏，不以“透气”名义弱化必要说明与事实条件。
- **段高与连续性**：段高以真实图文容量、主体保护、阅读停顿和转场需要决定；参考范围不是最低高度或硬上限，超出时在 `height_reason` 写清依据及不能由相邻段承接的原因，不因素材大或共享场景自动撑高。Brief 写清前后内容如何交接；具体表现、背景组与接缝由 Visual 决定。语义或色彩呼应不等于共享空间，透气段不自动新建背景组、重复生成背景或增加过渡屏；局部纯色仍须服从既有底图系统。

## 屏内配图
- 明确这屏要证明什么，再思考配什么样的图，配几张图。
- 每张图要承担明确责任：建立品牌调性、展示商品、解释结构、证明质感、说明尺寸、演示步骤、建立使用情境、换气等。
- 商品外观、包装、接口、规格关系和使用动作优先参考用户提供的资产，可直接使用、按需裁切使用及调用生图工具进行参考生图。
- 同一核心商品在所有屏中保持颜色、比例、Logo、包装文字和结构一致。不同图片的视角与场景可以变化，多材质/色彩的商品可以对应变化，但不能让商品像不同型号。
**图片裁切规范**：
  - 按图片在本屏承担的作用确定裁切重点，并在 Brief 中写清主体、视觉焦点、目标画幅、允许裁切区域与必须保护区域；商品主图须保留可识别轮廓和 Logo、型号、包装文字、接口等身份或功能结构，细节图须聚焦单一卖点且保留定位上下文，人物、食品和服饰不得在关节、接触点、器皿边缘或正在说明的版型与工艺位置生硬截断。
  - 场景图必须保留商品、使用动作及人与商品的接触关系，步骤图、对比图和规格图须保持一致的取景尺度、角度与主体大小；适配横竖版或多尺寸时优先移动裁切窗口或扩展背景，预留文字和安全边距，禁止非等比拉伸或用裁切制造虚假的尺寸、效果与性能差异。
  - 抠图商品须保留完整透明边缘、自然阴影和内部孔洞，不得残留色边或紧贴轮廓；参考图的裁切若损伤商品身份、事实证据或目标尺寸可读性则不沿用，并在 Brief 中记录参考图短链、借鉴的取景关系和调整原因。
**图片编辑prompt规范**：明确写出参考图对应的序号（如图1/2/n）和要参考的内容，补充环境、光影（方向、程度、色调、软硬、类型），可酌情添加非事实装饰、使用者。
- 未经用户提供或核实的功能按事实边界作为概念设定处理，作为真实商品信息发布前确认或替换。
- 有参考图时，在对应屏的“屏内配图”中写入真实 URL 短链，并说明借鉴内容。短链必须来自实际工具或平台返回值；没有短链时写“短链待补”，不得编造 URL 或用本地路径代替。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：按本 Spec 把商品事实、说服链、总屏数、逐屏职责、准确文案、尺寸策略、配图及证据来源、占位和事实缺口写入同一 Brief；每屏只保留能推进购买判断的内容责任。
- **内容结构验收规范**：逐屏核对商品身份、参数价格、证据、条件、文案、素材归属、上下屏接力和结尾行动，确认没有编造功效、漏掉限制、重复屏或靠缩字容纳过量内容。


## 7. 下一步路由

完成并保存内容结构 Brief 后，读取 [`ecommerce-visual-system.md`](../systems/ecommerce-visual-system.md)，在同一 Brief 补齐决策优先级、视觉命题、注意力路径、逐屏相对构图、图文占比、图片层级、背景关系、屏间连续、载体适配、降级、素材生产意图和设计约束；完整 Prompt 在素材清单中编译。

### 食品饮料组合候选

食品／饮品的卖点在于酥脆层次、组织切面、果肉颗粒或液体质地时，可用微距突出食欲与品质感。Spec 写清要呈现的细节及其卖点，取景、光影与主辅关系交给 Visual；微距不是必选项，感官画面不能替代产地、营养或等级证明。

包装烘焙需要原料、制作、场景、包装和资料逐章说明时，选“暖烘焙食品长页”主版；主要依赖多口味切面、手掰与连续摄影时，选同组合的“烘焙沉浸摄影”变体。参考中的产地、温度、营养或适用人群不是默认事实，按用户资料替换，缺失信息不为凑章编造。

果茶新品只需原料、风味与口感感官表达时，可用“清透微距感官长图”变体（单画布连续叙事，非左右两图）；若任务是完整销售详情，另补必要商品资料。选型见 [食品感官候选](../systems/ecommerce-visual-system.md#食品感官候选)。Brief写人类可读的章节与图片职责，不要求填写CSS ID。
