# 社媒长图内容与叙事 Brief

本文件用于连续滚动阅读的社媒长图，负责整页叙事节奏、信息链、每屏功能、配图、文案、总屏数和尺寸策略。这里的“屏”是内容段落，不是固定手机视口；逐页独立发布的作品使用套图 Spec，围绕购买决策组织的内容使用电商详情页 Spec。

不决定最终风格、配色、字体、背景成像与具体排版；内容结构保存后，由 [Social Visual](../systems/social-visual-system.md) 在同一 Brief 中接续。内容补写遵循 [共同内容与事实边界](../../shared/content-truth.md)，不把电商购买链或未经核实的参数套入社媒叙事。

## 背景结果约束

作品级背景系统应以与主题和视觉系统相关的色场、纹理、肌理或渐变建立连续基底，并在内容或视觉阶段转换处有意换挡；不得以无变化纯色铺满整张长图，也不用无职责空白或近似背景重做代替节奏。背景生产单元只对应实际可见职责，具体材质、范围、接缝、实现方式与 Prompt 由 Social Visual 决定。

## Brief结构

按主 `SKILL.md` 的资产读取规则查找当前主题的设计 Brief，已有则更新，没有则创建并先填写主题、受众、平台、用户原文与已知素材。不另建第二份品类 Brief。先围绕用户目标展开并取舍内容，再组织阅读顺序、划分段落和确定长度；下列结构用于记录结果，不是预先分配屏数的模板。用户已锁定结构或长度时，在该约束内组织内容。

```markdown
## 内容结构 Brief

- 叙事节奏：哪些内容直接说，哪里解释、举例或停顿
- 信息链：读者从什么问题进入，依次理解什么，最终获得什么
- 屏数：写完各屏职责后统计数量
- 连续内容组：记录相邻屏的内容范围、合组／拆组依据与接力关系；Visual 在同一条目补充背景生产单元和实现方式

### 第一屏：开场／Hero
- 功能：主题、核心主张与继续阅读的理由
- 尺寸策略：目标宽高、高宽比 H/W、段高依据、主焦点、段尾出口、切片保护
- 制作方式：按本文一体化 Hero 规则记录图内文案与独立可编辑文字的分工
- 配图职责：画面需说明的内容、主体与环境关系、参考图真实 URL 短链与借鉴内容；由 Visual 决定满幅场景、独立主体或局部图窗及实际素材数量，不预设背景与内容图必须分开生产
- 文案类型：表达方式、标题与正文、必要事实及来源

### 第二屏至第 N 屏：各屏类型
- 功能：本屏结论与需要回答的问题
- 尺寸策略：目标宽高、高宽比 H/W、段高依据、主焦点、段尾出口、切片保护
- 配图职责：画面需说明的内容、主体与环境关系、参考图真实 URL 短链与借鉴内容；由 Visual 决定满幅场景、独立主体或局部图窗及实际素材数量，不预设背景与内容图必须分开生产
- 文案类型：标题、解释、例子、图注或行动文案及来源
```

每屏实际展开一个条目，不以“后续同上”省略。文案先组织完整再试排，保留用户锁定原文；规划说明与上屏文案分开。可按需补“布局适配提示”和“遮挡关系提示”，写清不可删减的内容、允许改排的方式及人物／证据保护区域，不在此阶段虚构坐标或测量结果。

## 整页叙事节奏及叙事方式

### 按阅读目标组织信息链

用“读者看完后最需要获得什么”选择主目标，并保留用户明确要求的其他目标。下表用于组织已展开的内容，可以删并重排，不因选中一条内容链而省略其他必要内容，也不预设屏数或风格。

| 阅读目标 | 阅读结果 | 内容链起点 |
| --- | --- | --- |
| 活动传播／参与转化 | 理解活动并参与 | 活动价值 → 玩法／作品样貌 → 流程与条件 → 权益 → 参与入口 |
| 知识科普／方法教程 | 理解问题并掌握方法 | 问题 → 结论 → 解释／例子 → 步骤 → 误区 → 总结 |
| 经验清单／实用攻略 | 获得可复用的经验 | 场景 → 重点建议 → 分类清单／实例 → 注意事项 → 行动 |
| 品牌故事／人物叙事 | 建立理解与认同 | 命题 → 人物／背景 → 事件与转折 → 真实细节 → 价值与余韵 |
| 产品种草／解决方案 | 理解特定场景中的价值 | 使用处境 → 解决方式 → 功能／证据 → 使用方法 → 推荐理由 |
| 公益倡议／议题传播 | 理解议题并采取行动 | 现象／事实 → 影响 → 解释与误区 → 可执行行动 → 来源与入口 |
| 人才招聘 | 理解团队与岗位并投递 | 招募主张 → 团队／工作样貌 → 岗位与要求 → 成长待遇 → 投递 |
| 内容叙事／专题策划 | 完成一次有推进的阅读 | 开场命题 → 分章展开 → 关键节点 → 回看与收束 |

“招聘”“科技”“公益”不能直接决定蓝色企业风、玻璃卡或插画。相同内容链可以使用不同视觉方向。

### 章节职责与取舍

全图通常经历吸引、建立理解、展开、收束，但不必各占一屏。每段围绕一个主要结论组织支撑；短规则、过渡、总结不强行扩写成大段。

| 责任模块 | 需要交代的内容 |
| --- | --- |
| 首屏 | 主题、吸引点、读下去的价值 |
| 问题 | 具体处境、困扰及其影响 |
| 价值 | 用户能获得什么，以及成立的条件 |
| 知识 | 结论、解释、必要例子或来源 |
| 步骤 | 目标、动作顺序、关键提醒和完成结果 |
| 证据 | 证据内容、它支持的主张与适用范围 |
| 集合 | 分类依据、项目关系与重点 |
| 规则 | 对象、条件、限制和必要例外 |
| 权益 | 权益内容、获得条件和实际收益 |
| 行动 | 做什么、到哪里做、何时需要完成 |

这些是可选的内容职责，不是必须逐项填写的模块。取舍时判断每段为读者增加了什么理解、感受或行动理由；图像和情绪表达可以承担这一作用，不以字数衡量。删除后不影响目标、理解或阅读节奏的段落优先合并或省略，必要的定义、因果和操作顺序须保留。

### 跨段叙事方法

| 方法 | 使用条件 | 组织策略 |
| --- | --- | --- |
| 章节杂志流 | 专题包含多个相对独立视角 | 用章节题和导语建立主线，同类栏目保持稳定阅读习惯 |
| 问题—答案推进 | 读者存在连续疑问 | 先给当前答案，再引出必要的下一个问题，避免悬念拖延 |
| 时间线／流程推进 | 顺序影响理解或执行 | 每个节点对应事件、动作或阶段结果，路径有实际先后 |
| 清单逐级展开 | 分类或建议可独立扫描 | 先给分类或重点，相关项目成组，不平均放大所有条目 |
| 场景—证据交替 | 需要兼顾感受与可信解释 | 场景说明处境，邻近证据回应主张；不用气氛图冒充证明 |
| 情绪曲线叙事 | 人物、品牌或议题有转折 | 由具体事件、细节和镜头推进情绪，避免只靠换色和口号 |

选择能解释当前内容顺序的方法即可，不要求凑齐多种叙事模式。

### 上下段内容交接

先决定上段完成什么、下段为何继续，再在相邻屏条目中用自然语言记录交接对象、方向、接收位置和保护区；末段记录收束，不虚构下一屏。全貌进入细节、场景进入行动／证据、对象或路径延续、同一空间改变焦点、同一比较维度换挡均可形成接力；只有内容确实换章时才明确停顿。交接关系是规划依据，不自动转写成可见提示语；能由内容顺序和图文关系表达时，不另加引导文案。Spec 不提前指定色域、材质、蒙版、CSS 或其他视觉实现。

## 总屏数

按已取舍内容的独立职责和阅读顺序划分段落，再统计屏数；开场、解释、证据与收束可以合组，不设默认屏数区间。内容尚未回应用户目标时先补足内容，重复时先合并，不用预设屏数限制展开或反向凑段。总高度在真实文案与配图试排后确定，用户已指定的尺寸约束仍须遵守。

视觉方向确认只锁定用户实际确认的范围，不自动等于确认全部文案、段落或信息量。未确认内容可在原目标与已选方向内继续完善，并更新同一 Brief；不得改动用户已确认的具体内容，也不以此绕过既有 KV 确认流程。

## 每屏尺寸策略

- 先锁定用户或平台要求的成品宽度；正式 Hero 高度按 [正式 Hero 的纵向空间](../composition-layout.md#正式-hero-的纵向空间) 的统一优先级确定。后续段按真实文案、主图比例与段落职责试排，并以高宽比 `H/W` 记录；发布载体不明时先确认载体。
- 后续段不继承 Hero 高度。重点图解展开，短规则收紧，同类比较可以等高。
- 每屏宽高包括标题、说明、图片、必要留白和交接区；不能只测图片框。段高依据说明是哪组内容或主体尺度需要这些空间。
- 未指定总高时由各屏高度求和；指定总高但未指定 Hero 高度时，在不改变已选 Hero 高度规则的前提下调整后续段，无法兼容则说明冲突。不能拉伸图片、压小正文或靠装饰补高；修改段高同步后续纵坐标、背景接缝和切片边界。
- 切片不截断标题、数字单位、人物面部、操作接触点和关键证据；连续路径或主体跨段时写明保护范围。具体几何由同一 最终 HTML 落实。

## 各屏功能与文案

开场说清主题与阅读价值；问题段给出具体处境；解释段先给结论再补原因、例子与边界；证据段明确支持哪项主张；步骤段写动作、顺序和判断结果；收束段回扣主题并给出适合本次目的的行动或余韵。每屏一个主结论，不把同一段口号换词复制。

先明确主题、受众、阅读目的、已有文字与素材、载体和编辑要求。用户只提供主题或零散要点，并要求策划／创作长图时，应主动组织并扩写成有实际信息的文案，不把“已有信息直接使用”理解为只能照抄。用户要求原文不变、仅排版或限定改写范围时，遵守该边界。

### 围绕主题补足信息

先找读者读完仍会留下的问题；用户授权补充信息时，围绕这些缺口补充必要的解释、具体情境、可执行动作、示例或比较，并按事实边界区分资料与概念设定。关键段写透，辅助段写短；同一意思不换几种口号重复。内容充分是读者能够理解和行动，不是达到固定字数、屏数或每段统一句式。

- **从结论到解释**：说明这件事是什么、为什么与当前读者有关；原因有依据时再写因果，不将联想写成确定结论。
- **从抽象到具体**：将“提升效率”“有设计感”等泛词展开成具体问题、使用场景、可观察变化或评价维度。
- **从建议到行动**：方法类内容补动作、顺序、输入和判断结果；建议用法不改写为品牌已承诺的服务流程。
- **从概念到例子**：补一则贴近主题的说明性例子，明确其示意性质；不虚构真实客户、作品成绩或亲历故事。
- **从并列到推进**：同类内容归组，重复内容合并；解释和例子服务段落主张，前文提出的问题在后文得到回应。

例如只有“设计师线上接单：海报、精修”时，可以扩写为：“海报设计先梳理需要突出的主题和关键信息，让标题、主体与行动入口形成清楚的阅读顺序。图片精修围绕用途判断处理重点，例如商品展示关注边缘、色彩与细节的一致性。”这些是服务类型的解释，不能擅自加上“24 小时交付、无限修改、转化率翻倍”。若例子需展示真实效果，应使用用户提供的作品。

### 事实与文案边界

事实资料、概念补充和披露方式统一遵循 [共同内容与事实边界](../../shared/content-truth.md)，不另设逐屏声明。用户锁定原文保持原样；参考图只支持可见内容与关系，模糊、裁掉或未展示的信息不能作为事实证据。允许的创作补充在 Brief 中区分来源与设定，不冒充已知事实。

形成文案后连贯通读：主张是否具体、解释是否支撑主张、例子是否贴题、结论是否超出依据；删掉重复形容词、空洞英文和只为填版的句子，再按信息量确定章节与长度。文案与构图可以迭代，不能因当前框太小就擅自删必要事实。

同一 Brief 的准确文案是唯一成品文字来源，包含标题、正文、标签、图注、行动和必要声明。构图指令、来源与状态和上屏文字分开，不把“右侧放人物”“此处过渡”等输出到画面，也不维护另一份可独立修改的机器 Brief。

## 屏内配图

有可用参考图时，在对应图片条目写入真实 URL 短链，并说明直接使用、裁切、编辑或仅借鉴及具体用途。已有短链不得省略；没有时写“短链待补”，不得编造或以本地路径替代。身份图、事实证据与风格参考分别标明。

### 背景系统与生产单元

连续内容组是阅读顺序相邻、承担同一叙事阶段或明确接力关系的一组屏。Spec 按内容责任确定组别：

- **合组条件**：相邻屏共同回答同一阶段问题、支撑同一阶段结论，或存在明确的全貌—细节、问题—解释、场景—行动／证据等接力关系。符合时默认延续当前组；仅同色、同主题或标题相近不足以合组。
- **拆组条件**：读者要解决的问题、叙事阶段或内容任务真正改变，且下一段可以形成独立入口。标题、屏边界、段高或配图变化不自动拆组；局部补充和短说明优先留在当前组。

连续内容组不等于背景生产单元。Spec 确定内容关系；Visual 先依据内容、参考和主体尺度选择满幅场景承载图文、独立主体与开放排字或有边界图窗，再规划背景范围与素材生产单元。完整场景可同时包含主体、环境和文字净空，后置原生文字不要求把场景缩进图窗；文字归属仍遵循本品类及用户的可编辑要求。三种关系可按叙事组合，不以任一种作为全页默认。具体按以下原则规划：

- **条件连续**：从场景关系、光向与透视、主体尺度、文字安全区和色场／纹理判断相邻屏是否相容；相容时优先共享当前背景或延续同一基底，通过景别、主次、图文比例和信息密度推进。
- **合理换挡**：按内容判断继续共享场景、另起完整场景或采用局部图窗。环境和主体共同承担新的叙事阶段时可换景；局部证据、并列比较或明确取景边界需要独立观看时采用图窗。用色彩、材质、路径或章节边界完成接力，不为维持连续底面缩小主场景，也不为避免图窗强行融合不兼容场景。
- **生产关系**：不同内容组可以共用背景，同一内容组可包含多个背景生产单元。Visual 决定使用 CSS、图片或组合；不设固定组数、变化次数或图片数量，只为实际可见、露底或跨段连续职责生产背景。
- **验收**：背景的共享范围和换挡理由可追溯；没有近似背景重复生产、无职责空白隔段、纹理或光场意外重启，也没有缺乏依据的切换或强行融合。

### 什么时候配图

先判断本段是否需要让读者看见具体对象、动作、结构、差异或证据，或需要主题主视觉与情绪停顿。满足其一且图像能提供实际贡献时配图；纯规则、短总结、联系方式可以直接排字，抽象关系可用原生图解。装饰素材可建立调性、平衡构图或连接段落，但须指定从属位置，不冒充说明图或证据。

图片资源优先给关键主视觉、解释、真实样貌与证据；不全花在首屏，也不规定每段配图。文字为主、素材仅在左下角点缀可以成立；已选沉浸场景则不能以小图替代主视觉。图文权重服从本段职责。

### 配图功能与构建策略

| 功能 | 何时需要 | 画面构建与图文关系 |
|---|---|---|
| 主视觉／主题识别 | 需要快速识别主题并建立阅读动机 | 选代表主体或有依据的隐喻；标题与主体形成一个主组，决定谁主导、谁从属 |
| 场景代入 | 需要理解使用处境、人物状态或环境 | 明确谁在何处做什么，保留关键环境线索；文字指出价值或问题 |
| 对象展示／细节 | 外观、质地或部件本身影响理解 | 全貌与局部按需要组合，明确可见细节及裁切保护；图注邻接对应对象 |
| 动作／步骤示范 | 文字难以说明动作位置或顺序 | 展示手、工具、操作位置和结果；一步一关键变化，避免重复无变化镜头 |
| 机制／结构解释 | 需要解释内部结构、因果或作用位置 | 采用剖面、分解、过程图或准确图解；标注连接实际部件，不用光球替代机制 |
| 对比／选择 | 差异影响判断 | 统一视角、尺度或比较维度，成对呈现；文字补充条件与适用范围 |
| 事实／作品证据 | 需要支持主张或展示真实能力 | 使用可追溯作品、截图、实拍或数据，保留关键细节与来源；不以生成示意冒充记录 |
| 分类／图鉴集合 | 类别差异需要被看见 | 选择代表对象，统一必要视角与边缘语言；按分类轴组织、图注一一对应 |
| 路线／空间定位 | 地点、位置或移动顺序影响理解 | 地图、场景节点与有意义路径对应；真实地点用有来源信息，概念地图注明示意 |
| 隐喻／概念表达 | 抽象主题需要形成可感知形象 | 用与主题可解释的物件关系、尺度变化或场景构建隐喻；后文兑现其含义 |
| 情绪／转场／点缀 | 需要停顿、调性或视觉平衡 | 使用有关联的场景、形态或小物，限定范围和权重；不占据证据位置或挤压正文 |

画面对象可为人物、产品／器物、动植物、空间／建筑、过程、结构、地图、界面／文档、材质细节或抽象形态，按本段功能选取，不设题材白名单。摄影、线描、绘本、拼贴、版画、3D、等距或代码图解是成像选择，由 Visual 决定；不能把功能、对象和媒介混为一类。

### 从图片功能决定景别与构图

先确定读者必须看见什么，再选择看多近、从哪里看、主体放哪里；特写、全景、右侧构图都是表达选择，不是轮流套用的模板。

| 需要看清的内容 | 景别与画面组织 |
|---|---|
| 质地、工艺、操作接触点 | 特写／微距突出真实细节，保留足够整体线索；必要时辅以全貌图和局部标注 |
| 人物动作、使用过程 | 中景呈现人与工具／物件的完整关系，手、接触位置和动作结果不被裁切 |
| 环境、空间、多人关系 | 全景或远景建立位置与规模，主体仍可辨；大段文字不盖住关键环境线索 |
| 对象全貌、造型或类别 | 完整展示或有依据的局部裁切，主辅对象拉开尺度；比较对象保持必要的一致性 |
| 结构、路径、步骤 | 选能解释关系的剖面、俯视、分解或连续镜头；不是所有内容都适合摄影视角 |
| 文字主导的段落 | 主体可偏右，为左侧标题留出净空；也可左下点缀、环绕或局部出血，取决于阅读轴和前后段关系 |

“右侧构图”应说明主体朝向与文字关系，例如“人物位于右侧，面向左侧标题，动作和视线将读者带向说明”；不能只留一个空白半边。特写不损坏识别面，全景不让主体缩成难辨小点。镜头变化由解释需要驱动，同类比较可保持一致景别，无需每段强行换镜头。

这些是 Spec 的选图和构建方法。Brief 只写选定结果，例如“右侧手部操作特写，左侧短说明，操作接触点是第一视觉焦点”；HTML 再细化槽位、裁切与保护范围。

### 把“配一张图”写成可生产的内容

以下作为 Spec 的构建检查方法：在对应屏的配图条目写清选定内容、来源短链与使用方式，同一系列共用项引用一次；正式图片的目标比例、尺寸、安全区、消费者与准出标准在素材清单细化：

- **用途与对象**：属于哪段、帮助理解哪条结论，使用什么主体。具体到物种／物件类型、身份或产品版本，不只写“配产品图”。
- **画面内容**：主体在做什么、位于什么环境、必须看见哪些细节。例如教程图需要可辨的操作位置，不是只拍一个工具。
- **图文分工**：图已经展示什么，哪些解释仍由标题、图注、标注或正文承担。必须保留的事实文字不靠模型猜写。
- **构图适配**：景别、主体位置、朝向、关键细节的裁切保护和文字负空间。先根据内容选择横／竖或透明主体，再在素材清单 确定尺寸；不把任意图硬塞固定卡框。
- **来源与限制**：用户资产／已核验来源／生成示意／编辑衍生／代码图解；标记身份、真实细节或证据中不能改变的部分。缺少真实素材时明确缺口，不编造“已获得”。

媒介、色温、光向、笔触、颗粒与后期引用 Visual 的统一设定，避免每张图重新选择风格。复杂内容可拆成多项素材，简单内容无需把上述要点扩成多层表单。

### 图文互动的设计决策

在各屏配图条目写清内容对应关系，不把“图文结合”作为完成描述；以下空间表现由 Visual 结合实际素材细化：

| 关系 | 需要确定的对象与阅读方式 |
|---|---|
| 邻接解释 | 哪段文字解释哪幅图／哪个细节，读者是否无需跨远距离寻找对应 |
| 标注与引导 | 线连接哪个可见位置，表达归属、步骤或因果；图中目标不存在时不能补假标注 |
| 主辅对照 | 哪幅建立全貌、哪幅补细节；比较时保持指标、视角或尺度一致 |
| 环绕／嵌入 | 主体轮廓与文字净空共同构图；长正文保持可连续阅读的行宽 |
| 穿插／破框 | 主体、短标题或路径谁前谁后，形成什么主次；完整字义、脸、产品识别面和证据不被遮挡 |
| 图中文字与原生文字分工 | 哪些内容属于图内整体表达，哪些必须独立修改；同一文案只有一个可见承载者 |

关系由内容决定；具体字体描边、文字下沿高亮、引导线外观和容器材质由 Visual 选择，HTML 再记录对象、位置与层级。不是每段都需要叠压，也不把普通邻接强行改成穿插。

### 素材组合与复用

- 身份可复用：同一个产品或角色保持外观一致；动作、情境或证据变了，应生成／编辑相应画面。重复裁切同一张图不等于新增故事。
- 同类对象用可比较的视角与尺度；有主次的作品选一张主图、若干支持图，数量服从内容。人物故事可用环境、行动、细节形成镜头组。
- 图片紧邻其解释。复杂图用局部放大、编号或连线建立对应；图片本身已说明的动作不再写长段复述。
- 跨段主体、路径或连续场景只有在确实连接上下文时才复用；纯装饰不算解释素材。
- 主体破框、图文叠压、全幅照片、开放排字或带边界图窗都可以成立。采用哪种关系取决于内容和素材，不能为“灵动”强制遮挡文字。

### 配图写法对比

示例需求：做一张摄影征集长图，含人像、街头、静物三类方向；以下为规划示意，不代表活动已提供这些作品。

| 原先笼统写法 | 改后的有效规划 |
| --- | --- |
| 人像赛道配人物图 | 展示人物在窗边接受侧光的半身摄影示意，脸与手势清楚；图展示光线和情绪，文字解释该方向关注人物表达。若作为真实获奖作品，须替换为已授权原作 |
| 街头赛道配城市图 | 展示街角行人与环境发生关系的瞬间，保留人物、路口与层次；图展示“人与城市”的关系，图注说明观察点，不用空中楼宇全景代替 |
| 静物赛道配产品图 | 桌面日常物件通过光影、材质或几何形成明确构图；图展示观察方法，文字解释创作方向，不虚构品牌商品广告 |
| 三张图均匀贴进卡片 | 三类同等重要时保持可比较图窗，标题与例图就近；某一方向是重点时再增加篇幅。参与规则另用紧凑步骤，避免规则也变成空场景图 |

### 一体化 Hero 与第 2 屏衔接

Hero 是从开场到下一章节入口的完整构图单元。先按本节默认生产方式确定文字归属：主标题及适合入图的小字随完整画面生成，只有用户明确要求对应文字独立可编辑时才拆为原生文字；再在该生产边界内选择文字主导、摄影、拼贴、图窗或其他主视觉关系。先看主题最有辨识度的内容，再选择第一视觉焦点：

| 内容条件 | 优先尝试的主视觉关系 |
|---|---|
| 主张短而有力、字形能表达情绪 | 文字主导：大字、断行和强调色建立识别，小插画或图形从属；不强加大照片 |
| 人物、产品或可信结果就是吸引点 | 主体与标题／关键数字共构：通过尺度、邻接或穿插形成主组；真实身份与数字须有来源 |
| 地点、生活情境或活动现场影响理解 | 场景主导：用全景或中景建立环境和动作，文字进入真实净空 |
| 多个对象共同代表主题 | 拼贴主视觉：建筑、人物、器物或照片用共同基底、尺度与遮挡形成一个主组；数量按内容确定 |
| 图片重要但需要稳定编辑秩序 | 图窗与标题共构：椭圆、拱窗、纸框等轮廓组织主图，标题、导语和图注形成阅读入口；图窗不必满幅 |
| 动作、店铺、招牌或主题物件能直接表达内容 | 动作／语义场景：标题进入招牌、展板等有意义载体，人物与物件动作组织视线 |
| 差异或问题能够建立阅读动机 | 问题／对比开场：保留可解释的比较维度，正文及时兑现答案和证据 |

明确参考与用户锁定优先。多种方式都可成立时，选最能表达核心内容且现有素材支持的一种主要关系，辅助机制只服务它；不按题材固定模板，也不要求先生成全部候选。

开场范围按内容成立：标题、导语、主图与必要引入可共同构成 Hero，不必恰好是一个手机视口。Brief 写焦点、图文权重、位置和阅读出口；图像主导时不能缩成小图，文字主导时也不为“有氛围”强塞大场景。素材生产前先按统一优先级锁定 Hero 高度；没有用户或完整命名配方例外时，按构图在 `H/W = 1.5–1.8` 内选择；需要过渡到下屏时默认取 `1.8`，在首屏底部预留避开标题、主体及关键信息的过渡安全区，供渐隐或背景延续使用。安全区计入首屏高度，不额外加高，Brief 写明其范围与衔接方式。再用真实内容和主次检验该槽位能否成立并确定图片目标比例；无法容纳时说明冲突，不由内容量静默生成另一比例。HTML 兑现并复测该构图，不沿用候选横版素材高度，也不用空白满足比例。

**怎样接正文**：先判断上下段的关系，再选择连接方式：

- **空间连续**：同一场景、对象或路径延伸；检查透视、边缘和尺度真的接得上。
- **媒介转换**：场景进入相册、纸页、票据或信息板；边界可以明显，但应看得出如何从主图进入内容。
- **视觉呼应**：不共享物理场景时，用栏目轴、标题色、线条、轮廓或主题角色延续阅读；无需强行扩图。
- **明确换章**：内容转折时用撞色、撕纸边、章节带或留白清楚切换；不要求所有边缘渐变融合。

好衔接看阅读是否接得住、切换是否有意图、视觉语言是否一致；同色不自动连续，有边界也不自动失败。密集信息段继续继承必要字级、色彩与媒介语言，有职责的图窗／容器可以重复，不以“不许卡片”替代主次设计。

社媒长图默认生成包含背景、主体、主标题及适合入图小字的完整 Hero 图片，并作为一个正式图片生产单元写入原素材清单、绑定首屏消费者；完整底图、首屏背景或分离主体不能替代该单元，也不能以无字底图＋DOM 主标题代替。用户明确要求文字独立可编辑时，仅拆出对应 DOM 文字，图片预留位置且不重复含字；风格与文字位置描述不构成独立编辑要求。真实 Logo、二维码和证据沿原资产约束处理；正文继续按分层规则实现。

正式纵向区域沿 [长图段高与图文比例规则](../composition-layout.md#长图段高图文比例与实际兑现) 试排，HTML 落实实际宽高与主体范围；不以横版 KV、视口高度或空白补高替代。素材 Prompt 负责联合场景与生产分工，[HTML 组装](../../../workflow/html-assembly.md#4-素材合成与实际测量) 负责实际承接，[视觉复核](../../../workflow/html-validation.md#3-视觉与平台复核) 检查首两屏合成结果。图内文字错误沿既有交付门禁，不擅自用 DOM 覆字掩盖；交付区分 Hero 整体可替换与文字独立可编辑范围。

### Brief → 素材清单 → HTML

先将完整设计决策记录到 Brief，再由 HTML 细化执行；CSS 匹配只做能力校验并保留在当前实现上下文，不进入素材清单。素材就绪后将实际尺寸、裁切、色值和依赖直接写入同一 HTML。仅测量或参数修正留在 HTML；主构图、风格或内容职责变化回到 Brief。

| 已确定的决策 | 放入哪里 | 实现时核对什么 |
| --- | --- | --- |
| 章节职责、文案、分组与图文分工 | Brief；HTML 使用同源文字和真实章节 DOM | 顺序、信息完整性与一一对应 |
| 字体、配色、图像处理与表面语言 | Brief 记录自然语言目标；HTML 确定实际参数 | 所选风格在主体、文字和信息表面共同成立 |
| 图片内容、来源、身份、目标尺寸与安全区 | 轻量 `asset-manifest.json` | 就绪素材是否真正展示计划的动作、细节或证据 |
| 段高、盒子、层级、阅读区和叠压 | 最终 HTML 的真实 DOM 与行内样式 | 可读、无误裁、无不当遮挡，图片比例正确 |
| 需要抠图、复杂蒙版或其他图片后处理 | 素材清单；CSS 渐变、规则蒙版与跨段层级直接写 HTML | 每个效果有实际承载者；无须效果的不增字段 |

一张连续长图在 HTML 路径保持一个完整 HTML 文档和一个顶层 HTML Item。生成、字体解析、行内样式、上传、回读及技术验收统一执行工作流与 HTML 组装规则，不在 Spec 复写。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：按本 Spec 把主题、原文、信息链、章节与逐屏职责、准确文案、Hero 承载边界、段高策略、配图来源、切片保护和内容缺口写入同一 Brief。
- **内容结构验收规范**：核对全部章节、逐屏结论、文案、图片职责、上下屏出口、Hero 与独立文字分工、长页连续和切片安全，确认没有漏段、重复屏、整页压平或用缩字掩盖内容超载。

## 下一步路由

核对信息链、屏数、逐屏功能、尺寸、配图、文案、连续内容组及上下段内容交接已写入同一 Brief，再读取 [Social Visual](../systems/social-visual-system.md)。Visual 在原条目补充视觉决策、背景生产单元、跨屏连续、素材意图和验收；内容缺口回到原条目修正。视觉草案形成后按主 `SKILL.md` 校验 CSS 候选，将选中的 CSS ID、源路径与版本、作用范围及内容映射写入 Brief 短采用记录；Brief 冻结后再编译素材 Prompt 并进入实现。
