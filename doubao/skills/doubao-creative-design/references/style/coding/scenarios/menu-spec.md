# 菜单内容 Brief

在当前任务已有设计 Brief 中填写“菜单内容结构”；没有时根据当前对话创建，同任务不另建副本。先让读者能找菜、比较规格、辨认价格和理解点单条件，再由 Visual 决定风格与图文排布。

## 底图结果约束

凡本品类进入 HTML/CSS 设计，作品级底图必须包含与主题和视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。事实与正文区域可以局部降为纯色或低纹理以保证阅读，但仍须属于同一底图系统。Spec 只记录这项结果门禁和底图职责；具体材质、色场、变化方向、生成方式与 Prompt 由对应 Visual 决定。

## Brief 结构

```markdown
## 菜单内容结构

- 品牌与受众：餐厅／店铺、主要顾客、使用情境
- 用途与载体：日常点单、套餐、品鉴或展示；单页、册页、折页、墙面、手机或交互
- 阅读环境：近读／远读、明暗环境、语种、更新频率
- 尺寸与页数：宽 × 高及单位；按内容分配后统计页数
- 分类与顺序：类别名称及所含菜品
- 菜品清单：准确菜名、译名、描述、规格、单位、币种、价格及来源
- 套餐与规则：固定包含项、可选组、选择数量、加价、适用范围与时段
- 重点内容：已确认招牌、推荐或需要比较的菜品；事实性标签标来源
- 信息链：找分类 → 选菜／比规格 → 看价格与条件
- 配图计划：主图、分类图、条目图或套餐组合图的数量、菜品对应、真实 URL 短链、来源清晰度与目标用途；逐图记录高清白底图抠图／合格场景图保留背景／低清参考 image_edit 修复等处理方式，按菜单 Visual 的素材准出标准验收后使用，不能将参考菜单的直接裁切块视为合格菜品素材；背景主题按需
- 缺失与待核实：缺价、外观、过敏原、翻译或制作参数等

### 第 1 页／显示区
- 职责与分类：
- 菜品与文案：准确内容及与总清单的对应
- 配图与来源：
- 特殊约束：装订、折线、远读或交互状态
```

后续页面沿用同样条目，只填实际需要的页面；同一道菜多处出现时共用内容来源，不能重新编价。既有菜单改价只改授权范围，不借机重写菜品或换图。

## 类型与常用配图

| 类型 | 内容与阅读重点 | 常用配图与用法 |
| --- | --- | --- |
| 日常多品项菜单 | 分类检索、菜名价格近邻、规则易找 | 代表菜主图或分类图配条目，非每菜必配图；密集内容仍保留已确定的图像入口 |
| 饮品／甜品图鉴 | 比杯型、规格、口味与价格 | 单杯或单件实拍／授权插画，保留杯型、分层和真实外观，不统一裁成圆头像 |
| 套餐／分享餐 | 固定项、任选组、人数与加价 | 一张真实组合图或分别对应的菜图，图片不能暗示未包含的赠品和数量 |
| 品鉴／宴席菜单 | 菜序、配饮与价格范围 | 可用一道主题菜、食材或餐桌氛围，也可按明确需求文字主导 |
| 酒单 | 酒名、年份、产区、杯／瓶与容量价格 | 真实酒瓶或标签细节按需，文字比较优先，不虚构产地年份 |
| 墙面／灯箱菜单 | 同一视野内完成找菜与读价 | 少量明确产品图辅助远读，不能让顾客跨面板找一个价格 |
| 手机菜单 | 窄屏分类与短段阅读 | 分类主图或条目图与菜名绑定，不直接缩小桌面多栏 |

图片由用途与素材决定，不把“高端”等同于无图。已选图文方向缺图时记录补齐方式，不静默改成无图终稿。实拍、授权生成示意、装饰图分别标明，素材标识或真实 URL 短链对应到具体菜品。已有短链不得省略；未取得时写“短链待补”，不得编造 URL 或用本地路径代替。

## 菜品、价格与套餐关系

| 价格方式 | 必须说清 |
| --- | --- |
| 固定价 | 一个金额及对应单位、币种 |
| 多规格 | 每个规格与各自价格，一行一组或清楚列头 |
| 起价 | 明确“起”及适用条件，不显示成完整固定价 |
| 时价 | 使用已确认的时价表述，不伪造金额 |
| 已包含 | 所属套餐，不把空金额当免费 |
| 暂不可售 | 真实状态与展示方式 |
| 待补价 | 只作标记明确的草稿，营业使用前补齐 |

- 称重计价写清每多少重量，按杯／瓶计价保留容量与单位；税费、服务费、最低消费、适用时段只采用已确认规则。
- “主食任选一＋饮品任选一”是两组选择，分别列候选、最少／最多数量和加价归属。
- 译名与菜名一一对应；不能根据图片猜过敏原、热量、配料、产地或素食属性。
- 同菜跨页共用价格来源，渠道价不同时明确版本与适用范围。
- 菜品与价格尽量不跨页拆开；跨页分类重复必要列头。折页菜单同时采用 [三折页物理规则](tri-fold-spec.md#折法与尺寸)，不套第二套内容流程。

## 尺寸与内容补写

用户尺寸、真实载体和明确滚动／交互需求优先。其余未指定尺寸的普通静态菜单，默认 A4 比例竖版 `1200 × 1697 px`；已选横版用 `1697 × 1200 px`，在原 Brief 标明设计假设。可选短边为 `900–1600 px`，长短边比为 `1.25–1.6`：竖版宽为短边、高为宽乘该比例，横版互换；宽高不能脱离比例任意组合。这是默认设计范围，不是行业或印刷标准。

选定后锁定本次页框，不随菜量持续增高。超量先调整列数与分类编排，再增加同规格页面；大类可续页并重复列头，菜名—规格—价格不拆散，不删菜、不缩字硬塞。用户锁定单页且无法容纳时说明容量冲突，不擅自加页或改尺寸。

印刷采用成对规格：A5 `148 × 210 mm`、A4 `210 × 297 mm`、A3 `297 × 420 mm`，横版整对互换；CSS 像素不等于物理尺寸，印刷输出另按分辨率换算，出血、色彩模式和装订要求待供应商核实。墙面按安装尺寸与阅读距离，手机滚动菜单按目标显示宽度重排，不套静态页比例，也不把桌面多栏整版缩小；仅载体歧义会改变制作与交付时澄清。

可润色已知菜品描述与译文，不新增配料、份量、价格和优惠。缺价、分类歧义及素材缺口写入 Brief 和交付说明；设计预览在页脚统一标明草稿状态及影响使用的缺口，不逐行堆放“待定”或把“图1内容待确认”等制作说明排成菜单栏目。无法确认的内容不猜补，也不伪装成已核实信息；用户明确要内容核对表时按该用途展示。过敏原等安全信息不编造结论，真实营业前必须补齐核实。

## 内容核对

保存前按一次实际点单检查：找到分类、选定菜品、辨认规格价格、理解套餐选择和附加费用。核对全部菜品覆盖、语种对应、配图归属与缺口；静态菜单不声称可下单、支付或更新库存。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：按本 Spec 把菜单载体、分类顺序、菜品与译名、规格价格、套餐规则、准确文案、图片来源、尺寸和待核实项写入同一 Brief，保持菜名—规格—价格关系不可拆散。
- **内容结构验收规范**：完成一次真实点单走查，核对全部条目、币种单位、起价／时价／加价条件、多语言对应、图片归属和安全信息缺口，确认没有生成价格、配料或可交易能力。
