# 社媒套图内容与叙事 Brief

本文件仅负责已由主路由选为 AI + Coding 的可编辑社媒套图：内容页链、单页容量、封面确认、系列机制与独立内页。每页独立成立，通过翻页共同推进一个传播任务，不是把连续长图机械切片。默认纯图套图不读取本文件或 Social Visual，而使用现有 pure-image 平台 Ref 与 pure-image-sequence；本文不得重新路由。

**封面与内页均为图片素材＋HTML 原生文字**：DiT 生产摄影、插画、复杂材质、人物、奖品和其他可替换视觉资产，准确文字、容器、规则图形和布局由 Coding／HTML 承担。明确指定可编辑的区域必须使用原生文字，封面不例外；仅局部可编辑时，非目标区域可沿既有艺术标题准入规则，真实照片内标签无需重画。最终风格、艺术手法、配色、背景、图文组合与逐页排版由 [Social Visual](../systems/social-visual-system.md) 接续。已有 HTML 编辑保留原格式。

## 底图结果约束

可编辑套图封面与每张内页的作品级底图都必须包含与主题和系列视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整页。信息区域可以局部降为纯色或低纹理以保证阅读，但仍须属于同一系列底图系统。Spec 只记录这项结果门禁和逐页底图职责；具体材质、色场、变化方向、复用方式、生成方式与 Prompt 由 Social Visual 决定。

## Brief结构

先按主 `SKILL.md` 查找当前主题的设计 Brief，已有则继续更新，没有则创建并填写主题、受众、平台、原文与已有素材。在同一份“内容结构 Brief”中填写：

```markdown
## 内容结构 Brief

- 叙事节奏：首页如何吸引，内页如何解释与推进，尾页如何收束
- 信息链：按阅读顺序写清各页共同完成的传播任务
- 页数：写完逐页职责后统计数量
- 当前生产阶段：content-plan / cover / awaiting-cover-approval / inner-pages / final
- 背景计划：一期只写封面可执行方案；内页在封面确认前只写内容职责和预计素材需要，不锁定具体视觉骨架
- 可编辑范围：整套设计／文字或用户指定的页面与区域；指定文字均须原生实现，封面不例外
- 封面确认记录：封面版本、真实呈现证据、用户确认原文与确认时间；确认前保持为空

### 第一页：首页／封面
- 功能：主题、主张与继续翻页的理由
- 尺寸策略：目标宽高、宽高比、平台安全区和完整保留的信息
- 制作方式：按正常素材流程准备背景、主体与装饰，以 HTML 原生文字组装封面；指定可编辑区域不得烘焙进图片
- 配图类型：画什么、几张、用途、参考图真实 URL 短链与借鉴内容
- 文案类型：主标题、必要短说明、表达方式与事实来源

### 第二页至第 N 页：各页类型
- 功能：本页唯一结论，以及与前后页的内容关系
- 尺寸策略：与首页相同的画布尺寸、内容密度和安全区
- 制作方式：生图素材＋Coding，准确文字独立可编辑
- 配图类型：本页背景、主体、动作、场景或证据；数量、来源短链及用法
- 文案类型：标题、正文、图注、必要条件与来源
- 翻页衔接：接住什么、下一页回答什么；尾页写收束
```

逐页展开，不把所有内页合成一个条目。Brief 使用中文字段与自然语言，写清内容和可见效果；不输出套图专属 JSON、机器视觉合同、参数提取表或资产矩阵，也不把它们转移到 HTML。普通实现所需的色值、尺寸、素材引用和图层关系由公共实现流程落实。

新建可编辑套图固定按下列顺序执行：

```text
整套内容规划 → 封面 Brief → 仅生产封面资产并分层组装真实封面
→ 真实渲染并向用户呈现当前封面 → 停止并等待该版本的明确确认
→ 从确认封面提取 series_contract → 逐页内页构图与资产计划
→ 生成并实现多个独立内页 → 全套并排与逐页验收
```

内容一起规划，视觉先封面后内页。封面确认前只确定内页“讲什么”、每页容量和事实缺口，不生成内页专属视觉资产，不冻结内页卡片外形、具体构图或最终系列机制。

## 整套叙事节奏及叙事方式

先判断读者需要快速获得答案、按步骤学习，还是随人物与事件逐渐建立理解。教程先明确收益再拆解动作，故事让转折由事实与细节推进，活动从吸引点进入参与条件；不能每页都用强口号，也不为制造悬念推迟必要答案。

一套图选择一个主要传播任务。内容类型与视觉风格是正交轴，不能从“胶带、便签、绿色、酸性”等风格词反推内容类别。

| 传播任务 | 用户完成阅读后的结果 | 推荐页链 |
| --- | --- | --- |
| 活动传播／参与转化 | 理解活动并参与、投稿、报名或到场 | 封面钩子 → 活动价值 → 参与方式 → 内容／赛道方向 → 奖励权益 → 行动收束 |
| 知识科普／方法教程 | 理解问题并掌握方法 | 封面命题 → 问题建立 → 核心结论 → 方法拆解 → 示例／误区 → 总结收藏 |
| 经验清单／实用攻略 | 获得可保存、可复用的经验 | 封面场景 → 困扰 → 清单分类 → 关键方法 → 示例 → 注意事项／收藏 |
| 品牌故事／人物叙事 | 建立情绪与价值认同 | 封面命题 → 背景 → 人物／事件 → 转折 → 价值证据 → 余韵收束 |
| 产品种草／解决方案 | 理解产品如何解决特定场景问题 | 封面痛点 → 使用场景 → 功能介入 → 卖点证据 → 使用方法 → 推荐／行动 |
| 公益倡议／议题传播 | 理解议题并采取行动 | 封面现象 → 事实影响 → 误区 → 正确方法 → 行动清单 → 组织／行动收束 |
| 人才招聘 | 理解雇主与岗位并完成投递 | 招募主张 → 团队／业务 → 岗位 → 职责要求 → 福利成长 → 投递流程 |
| 内容叙事／专题策划 | 完成一次有节奏的主题阅读 | 封面命题 → 背景 → 分页展开 → 关键节点 → 高潮 → 回看／开放结尾 |

页链表示传播责任，不表示固定页数。相邻责任可以合并，但不能删除支撑后直接跳到奖励或 CTA。

### 页面责任与取舍

| 页面责任 | 需要交代的内容 |
| --- | --- |
| 首页 | 封面钩子、主题与视觉承诺 |
| 问题 | 冲突或读者处境 |
| 价值 | 价值和继续翻页的理由 |
| 知识 | 概念、分类、结论或原理 |
| 步骤 | 方法、参与方式或执行顺序 |
| 证据 | 有来源的数据、照片、案例或结果 |
| 画廊 | 人物、作品、场景或内容集合 |
| 规则 | 资格、边界和提醒 |
| 收益 | 奖励、福利、成果或收益及成立条件 |
| 行动 | 投递、参与、收藏或其他收束 |

每页可以有一个主要责任和一个辅助责任，但只有一个主结论；不要求将所有责任各做一页。

## 总页数

- 3–4 页：单一活动、简短说明、轻量征集或一个观点的快速传播。
- 5–7 页：大多数活动、教程、攻略、种草、品牌故事和招聘套图。
- 8–10 页：复杂教程、多个案例、完整规则或专题叙事；只有真实内容需要时使用。

相邻两页如果结论、素材和动作都高度重复，应合并而不是换背景继续排。

## 每页尺寸与内容容量

- 用户或发布平台尺寸优先，整套保持相同宽高；小红书首页比例和安全区沿 [平台 Ref](../platforms/xiaohongshu.md)。
- 页是完整发布单位，不使用电商长页按内容增加段高的策略，也不记录纵向切片边界。每页保留可独立识别的主题、结论或上下文；不能把一个标题、步骤或证据切在两页之间。
- 以同页面职责、同画布、同字体职责的已验证模板为基准计算 `content_load_ratio = 实际排版占用量 / 模板标准占用量`。没有真实模板时只记录预估档位，不虚报精确比率；最终以真实字体渲染、手机阅读和底部净距为准。

| 档位 | 负载率 | 处理 |
| --- | ---: | --- |
| short | `<0.85` | 保持层级，用留白或有语义的图像承接；低于 0.65 也不强行填充 |
| standard | `0.85 ≤ r ≤ 1.15` | 使用标准布局 |
| long | `1.15 < r ≤ 1.45` | 扩容器、压缩非语义留白、调整图文比例 |
| dense | `1.45 < r ≤ 1.80` | 使用该页面职责已验证的高密度变体 |
| split | `>1.80` | 拆成下一张独立完整单页，并补写入口与承接 |

推荐容量只用于预估：理念／介绍约 90–170 中文字；步骤 2–3 个、每步 20–55 字；话题／灵感 3 组、每组 20–70 字；权益／规则 2–3 组、每组 40–80 字；陈列 3–6 件；地图导语 60–120 字、标注 5–8 个。

以 `516×696` 为验证基准：主标题最多两行且不低于 34px，模块标题不低于 18px，正文不低于 `13px/1.4`，辅助文字不低于 10px；左右安全区不少于 31px，上下关键净距不少于 28px，模块间距不少于 14px，正文内边距不少于 18px。其他画布按短边换算，并以平台安全区和移动端结果收紧。

适配顺序固定为：扩展容器 → 减少非语义留白（最多 20%）与非关键装饰（最多 25%）→ 调整图文比例、图片区最多缩小 20% → 正文最多缩小 8%、标题最多缩小 10% 且不破下限 → 已验证 dense 变体 → 拆页。任何档位真实渲染仍不可读，也直接拆页；不得截断、隐藏溢出、整体缩小、拉高固定画布或拼成长图。用户锁定页数且无法容纳时，停止并请求内容取舍。

## 各页功能与文案

- 首页说清“是什么、为什么值得继续看”，不塞入全部规则。
- 建立页明确问题、场景或背景；展开页每次增加一个答案、步骤或事件；证据页说明支持什么；规则页保留条件与例外。
- 尾页由前文自然导出参与、保存、投递或价值余韵，不突然增加未解释的承诺。
- 写出可直接排版的标题、说明、图注与行动文案，不能只写“放一段介绍”。关键事实与来源就近对应；规划文字不进入成品。
- 过少时围绕读者仍有的问题补解释、动作和明确示例；过多时先合并同义表述与重复页，再收紧辅助信息。

### 文案补全

沿用详情页的补写动作：优先使用用户资料或可核实来源；资料缺失时可以根据品类经验先生成明确标记的占位内容，在同一 Brief 标记待替换项，并在对应内容旁显示：

> 注：以下内容由模型根据经验生成，非真实事实，正式使用前请替换为已核实内容

声明用与背景形成明确对比、但可略低于正文对比度的小字号，清晰可读，不放大抢占主信息，也不缩小或隐藏。每个含占位事实的页面就近声明，不能只在尾页或交付说明统一披露；首页有占位事实时，声明同样由 HTML 原生文字就近呈现。

占位不等于真实来源或用户确认，不伪造证书、报告、投稿、真实人物记录或有效联系方式。真实二维码、邮箱和报名链接不得猜造；无法安全标记的内容删除或记录缺口。保留用户锁定原文。

## 页内配图

### 背景生产单元

封面与内页逐页确定背景职责，可由 CSS、图片或二者组合实现。同一视觉场可跨页复用底面或同源变体，明确换章时再改变；套图不先拼成长图再切页。

先划分每页的全局底面、组级背景与局部覆盖；页边界不自动要求新背景，同一职责不得重复生产。完全被遮挡且无其他职责的底图不生成；首页同样按正常素材流程与 HTML 原生文字组装，不设置完整终图例外。

### 配图类型与用法

先确定图片解释哪项内容，再决定数量和来源；纯规则、联系方式或短总结页不强制新增内容图。

| 配图类型 | 常见用途 | 数量与用法起点 |
| --- | --- | --- |
| 主题主视觉 | 首页识别主题，内页关键节点强化主张 | 一张主图或一组有主次的对象；不把封面构图复制到内页 |
| 真实场景与人物 | 人物叙事、活动回顾、团队或地点介绍 | 一张主镜头，必要时补行动或环境细节；真实记录不能由生成图冒充 |
| 对象与细节 | 展示物件、商品、作品及局部 | 一张全貌配必要细节；说明邻接对应部位 |
| 步骤示范 | 教程、玩法、参与流程 | 每个关键变化配对应动作，不重复凑图 |
| 对比与证据 | 测评、知识解释、成果 | 同维度对照或有来源的截图／数据；尺度、条件和来源完整 |
| 分类与图鉴 | 攻略清单、路线、内容方向 | 按真实类别配代表对象；数量服从分类，不先做无主次九宫格 |
| 转场与从属素材 | 页间接力、主题呼应、语义纸壳 | 只为实际需要的对象或关系生产；可复用素材不重复生成 |

对应图片条目写清用途、主体与动作、数量、来源、直接使用／裁切／编辑／生成及保护范围。有参考图时必须附真实 URL 短链和借鉴内容；未取得写“短链待补”，不得编造或用本地路径替代。参考图中的人物、商品、文字与品牌不得因为参考版式而自动沿用。

动作图保留手和接触点，全景保留空间关系，细节图保留定位上下文，对比保持取景尺度。需要压边、穿插或独立替换的主体单独准备，Visual 再决定排列，不在 Spec 冻结绝对坐标。

## 可编辑封面职责

封面与内页共用同一 Brief、内容事实源与素材清单，但按阶段增量冻结：一期只锁定整套内容计划与封面制作依据，只把封面实际需要的图片登记进素材清单。先写清唯一传播目标、第一视觉、第二阅读信息、继续翻页的理由，以及标题、副标、日期、数字、专名、品牌、声明和 CTA 的准确文案与来源；缺失内容先回 Brief 补齐。

封面准确文字由 HTML 原生文本承载。用户仅指定某个区域可编辑时，该区域必须原生排字，不能借封面身份绕过；非目标区域可沿既有艺术标题准入规则，真实照片内的包装字标或标签无需重画。素材 Prompt 按正常素材规范编译，不把全部封面文案交给图像模型。

在同一 Brief 中确定目标宽高、平台安全区、主体保护区、允许裁切区、最低有效像素，以及背景、主体、装饰与文字的视觉关系。选择图片主导、图文平衡或文字主导关系；除明确的大字报或纯文字命题外，保留可识别的人物、商品、物件、场景、插画或图形主体。多图须有主图、动作、环境、细节或证据等不同职责；拼贴、手账、印刷、3D、玻璃等机制以参考、主题语义或已选视觉方向为依据，不作默认装饰。

参考图分别记录编辑目标、身份母版、构图、风格或事实证据职责及真实来源。身份衍生使用图像编辑并实际传入已确认母版；风格参考不授权继承其中的人物、商品、文字或 Logo。既有设计按授权范围保留主体、文字、比例、透视与光向，HTML 源不压平。

素材按公共准出检查身份、结构、比例、清晰度与安全裁切；封面组装后检查真实 DOM 中的文字、字体、信息层级、对齐、断行、遮挡和移动端可读性。技术准出完成后必须实际呈现当前真实封面，然后停止生产并等待用户确认；不得等待内页素材，也不得直接继续整套。

### 封面确认门禁

有效确认必须发生在用户看到当前真实封面后，并明确表达“确认、可以、按这版继续”等放行意思。保存封面版本标识、呈现证据、用户确认原文和确认时间；封面发生修改后，旧确认失效，必须重新渲染、呈现并确认当前版本。

以下情况都不算确认：image／HTML 工具成功、预览成功、内部 QA 通过或 Agent 自认为可用；用户在封面生成前说“直接做完”“不用问我”或一次性授权整套；只确认文案、页数、参考图或抽象风格；没有看到当前封面版本时的“继续”；带有未完成修改条件的表态。

封面未确认时，禁止：

- 把内部验收、媒体交付或工具状态写成用户确认；
- 冻结或声称已完成最终 `series_contract`；
- 生成、编辑、后处理或复用为本套定制的内页视觉资产；
- 锁定内页具体卡片、坐标、图文比例与资产槽位；
- 组装、渲染、写入或交付任何内页；
- 以赶时间、节省调用或用户已授权整套为理由越过门禁。

### 确认后提取系列机制

风格来源是用户确认后的真实封面主视觉，不是 Prompt、参考图或风格标签。确认后实际查看该封面的渲染与分层实现，在同一自然语言 Brief 写入唯一 `series_contract` 段落；它不是独立 JSON、参数表或 CSS 副本。

通用提取六轴：构图力场、字体骨架与层级、色彩职责、形状与边缘、材质工艺、图像处理。每项机制必须回答“看见什么 → 为什么形成该效果 → 内页如何重新实例化 → 不能退化为什么”。固定的是产生风格的规则，不是标题坐标、背景色面积、主体数量或所有页面的同一种容器。

三个案例只作为机制示例，不是模板分类：

- 实验拼贴：固定粗粝石质与软萌角色的触感对照、切角纸面和不规则标题；理念、参与、奖励分别映射为引文面、操作纸片和展陈场。
- 春日摄影：固定柔光颗粒、半透明纸面、照片边缘和手账标记；内页迁移光感与图像处理，不重复封面树木或同一照片。
- 运动波普：固定运动方向、厚白描边、网点印刷和功能色；地图优先空间、话题优先分类，不为“变化”牺牲功能。

确认 `series_contract` 后，才为每个内页建立正式构图和资产槽位。页面主任务决定主轴、图文关系、容器和密度；内页继承系列机制，但不得机械复制封面坐标、对象数量和构图骨架。

|---|---|---|
| 小红书 | 默认 3:4；顶部 8%、底部 12% 不放关键信息，4:5 时上下各避让 8% | 手机缩略图中快速呈现真实内容价值；照片、商品、场景或具体插画承担主视觉，可使用克制的杂志编辑、生活记录或信息封面语法，不仿平台 UI |
| 抖音 | 默认 9:16；顶部 8%、底部 20%、右侧 12%–15% 不放关键信息 | 一个强焦点、明确动势与高对比标题关系；不虚构价格、承诺、平台互动或站外引流 |
| 快手 | 默认 9:16；顶部 8%、底部 20%、右侧 12%–15% 不放关键信息 | 真实场景、人物动作、手部或实物细节优先，表达直接但不强制红黄大字报，不伪造信任背书 |

## 首页与内页生产

1. 在同一 Brief 完成整套页链、逐页准确文案、事实来源、编辑范围和容量预估；内页此时只记录内容职责与预计素材，不锁具体视觉。
2. 形成封面 Brief，只把封面需要的资产登记进共享 `asset-manifest.json`，按正常流程生成、编辑或复用并完成准出；不另建首页 manifest，不生产整页文字烘焙的封面终图。
3. 用 HTML 原生文字和分层素材组装封面，完成真实 DOM、渲染、移动端与平台检查；所有 `image_gen`／`image_edit` 成功产物仍按 [交付门禁](../../../workflow/image-generation-delivery-gate.md) 满足当前环境的 Workspace ID 规则并使用 `RichMediaCard` 直接逐项交付；其他工具结果按各自协议交付。
4. 实际向用户呈现当前封面，记录版本并停止；技术准出、工具成功、预览或媒体交付都不能替代用户确认。
5. 当前封面获明确确认后，查看真实结果并把 `series_contract` 以自然语言写回同一 Brief；不建立系列机器合同、角色矩阵或参数表。
6. 先按每页职责、内容容量与画幅执行 [内页 CSS 布局选型](../systems/social-visual-system.md#carousel-layout-selection)，比较布局后再适配确认封面的风格；在原 Brief 留下逐页采用记录，确定图文比例、容器与资产槽位，再增补内页素材。确认前预估的内页需求不能提前进入生成批次。
7. 各内页分别生产素材、组装独立完整 HTML 并渲染；准确标题、正文、规则、页码与图注由 HTML 原生文字实现。明确要求可编辑的区域不得使用艺术字位图替代。
8. 逐页检查布局来源与真实 DOM 的对应、主要阅读关系、成图与移动端阅读，再用并排缩略图检查系列识别和节奏；自主布局保留具体适配原因。封面与内页均按原 HTML 与媒体交付门禁处理；一期封面展示不是整套完成，二期内页未齐也不得宣称完成。

AI 图内文字有误时先完成交付，记录具体问题并等待用户明确要求，不自动重生、编辑或 Coding 覆字；错误文字影响准确内容时暂停依赖它的下游步骤。Coding 原生文字仍正常修正。

已有设计编辑先读取完整 HTML 源并按授权范围修改，不因新建默认路线压平现有 DOM 内容。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：把整套主题、页链、逐页职责与准确文案、容量档位、编辑范围、平台尺寸、翻页关系、来源和缺口写入同一 Brief；一期另写封面制作依据，确认后再写 `series_contract` 与内页视觉计划。
- **内容结构验收规范**：核对当前阶段只生产获准范围；确认记录对应当前已展示封面版本；内页发生在确认后；超量页面按安全顺序适配后拆页；封面及内页指定可编辑文字均原生实现。

## 准出与下一步

- 各页功能、尺寸、准确文案、容量档位、配图来源与翻页关系写齐，必要占位声明就近可读。
- 封面与内页均明确图片素材＋HTML 原生文字分工；用户指定可编辑区域包括封面必须原生排字，不以整图替代，也不压平已有 HTML。
- 一期只准出真实封面并完成呈现；没有当前版本的有效确认记录时，内页资产、最终系列机制与内页 HTML 均不得出现。
- 确认后 `series_contract` 能指出封面中真实可见的六轴机制，内页按职责重新组织而不是复制封面几何。
- 全局底面、组级背景与局部覆盖分别写清职责和范围，不重复生产，也不为填满画布生成无职责底图。
- 视觉和配额读取 [Social Visual](../systems/social-visual-system.md#套图一致性与差异性硬门禁)，规划按内容试排，结果须同时满足一致性、差异性和可读性。
- 保存同一中文 Brief 后进入 Visual；不生成品类机器计划，不调用旧 JSON 计划验证器，也不将旧系列字段复制进 HTML。
