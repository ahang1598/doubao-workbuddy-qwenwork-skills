# 流程图内容 Brief

在当前设计 Brief 中填写“流程图内容结构”。先确定步骤、条件、责任主体和异常路径，再交给统一 Visual 决定布局；不得为了排版改写业务逻辑。

产物为实际渲染的可视流程图，HTML／SVG／Mermaid 代码仅作为实现，不作为成品交付。

## 适用边界

流程图用于表达有方向的步骤、条件分支、循环、交接或状态流转。单根分类用思维导图，类型化实体事实网络用知识图谱，数值比较用统计图；混合内容拆成相邻视图。

## 底图结果约束

进入 HTML/CSS 设计时，作品级底图必须包含与主题和视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。密集节点区可降低纹理以保证阅读；具体材质、变化方向与 Prompt 交由统一 Visual 决定。

## Brief 结构

```markdown
## 流程图内容结构

- 目标、受众与使用场景：
- 来源与范围：原始资料、版本、明确排除项
- 起点与终点：
- 参与者／泳道：责任主体及边界
- 节点清单：名称、类型、责任主体、前置／输出、来源
- 连线清单：起点、终点、方向、条件、正常／异常、来源
- 分支与合流：条件、默认路径、汇合位置
- 循环：进入条件、回路与退出条件
- 异常：失败、超时、取消、回退与人工介入
- 子流程与跨图连接：入口、出口和返回定位
- 视图计划：总览、局部流程与筛选范围
- 载体与尺寸：静态／交互、宽 × 高及单位
```

无需用户填写内部 ID 或机器 Schema；实现阶段再建立稳定标识。

## 语义规则

- 只使用开始／结束、活动、判断、子流程、数据／文档、注释等必要类型；用户未要求时不强行套完整 BPMN。
- 判断节点的每条出线写明条件；有默认路径时显式标注。不能从资料中证明的条件标为待确认，不自行补齐。
- 分支后需要继续共同流程时设置合流；循环必须可退出；每个开始应能到达明确结束或已说明的外部出口。
- 节点归属与泳道一致，跨泳道连线表示真实交接；位置邻近不代表先后、审批或因果。
- 正常、异常、超时、取消路径分开记录。孤立节点、悬空端点和无标签判断线在冻结前处理。

## 内容结构生产与验收

- **内容结构生产规范**：在同一 Brief 中写入目标与来源、起止点、节点、泳道、分支条件、合流、回路出口、异常路径、跨图连接、视图范围和待确认项；每条连线保留方向、条件与端点。
- **内容结构验收规范**：确认必要路径无遗漏，起止点、方向、条件和责任主体可追溯；无悬空端点、无标签判断线或责任错位。分支条件在来源允许范围内互斥且覆盖，无法确认时如实标记缺口；合法回路、异常和跨图连接须有可继续阅读的出口。

语义参考：[Mermaid Flowchart](https://mermaid.js.org/syntax/flowchart.html)；需正式业务流程符号时再参考 [OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/)。
