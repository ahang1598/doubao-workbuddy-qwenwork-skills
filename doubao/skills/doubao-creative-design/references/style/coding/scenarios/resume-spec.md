# 简历内容 Brief

在当前任务已有设计 Brief 中填写“简历内容结构”；没有时根据当前对话创建，同任务不另建副本。简历的第一优先级是文案：先把真实经历整理成与目标岗位相关、可直接排版的完整内容，再交给 Visual 排版；版式必须适配文案，不能反过来删事实、缩字或把简历做成招聘广告和个人宣传海报。

## 底图结果约束

凡本品类进入 HTML/CSS 设计，作品级底图必须包含与职业定位和视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。正文阅读区域可以使用极弱纸纹、低对比肌理或克制渐变，并允许局部纯色承托，但不能牺牲打印、ATS 辅助阅读或文字对比。Spec 只记录这项结果门禁和底图职责；具体材质、色场、变化方向、生成方式与 Prompt 由对应 Visual 决定。

## Brief 结构

```markdown
## 简历内容结构

- 候选人与目标：姓名、目标岗位、受众；未给岗位时说明暂定方向
- 阅读模式：ATS 机器解析优先、招聘者阅读优先或作品结合型
- 联系方式：准确电话、邮箱、城市、作品／个人主页等所需字段
- 职业摘要：来源支持的定位、经验与优势，不堆空泛形容词
- 经历与项目：组织、角色、起止时间、本人动作、方法、产物与实际结果
- 教育、技能与资质：学校、专业、学位、时间、技能证据、证书与来源
- 信息链：身份与方向 → 最相关证据 → 经历细节 → 补充信息
- 页面与尺寸：默认 1 页；用户明确要求多页时记录页数，另写宽 × 高及单位、语种、提交格式与渠道要求
- 配图计划：从用户提供资料中找到与本简历候选人对应的人像，记录真实 URL 短链，作为图1裁切／编辑成 3:4 证件照；可选作品或项目截图另写数量、真实短链、归属与用途
- 内容取舍与扩缩：重点经历、删减内容、需要展开的事实及改写依据
- 缺失与待核实：事实冲突、未提供结果、缺照、失效链接等

### 第 1 页
- 职责与模块顺序：
- 上屏文案：实际可用的完整内容
- 配图与来源：

### 后续页（按需）
- 职责、模块顺序、实际文案与配图来源
```

默认交付 1 页简历，只有用户明确要求 1 页以上时才规划多页。经历数量与一页容量不匹配时，先在本阶段调整文案详略，不先加页，也不能缩字藏事实；调整后仍无法形成可信、可读的一页时，列出原因和取舍方案，请用户决定删减内容或改为多页。

## 阅读模式与内容重点

| 模式 | 内容安排 | 常用配图 |
| --- | --- | --- |
| ATS 机器解析优先 | 姓名、联系、经历、组织、时间和技能有连续文本顺序；不用图形独立表达事实 | 按本品类约定准备本人证件照，用户明确无照时省略；其他配图通常无需 |
| 招聘者阅读优先 | 首先看到方向与最强证据，再展开本人贡献 | 本人证件照；少量与具体经历对应的真实证据图按需 |
| 作品结合型 | 履历与精选作品互相说明，不变成只有作品的画册 | 本人证件照、真实作品／项目截图；艺术人像仅作附加，不代替身份照片 |

未知投递渠道时采用保守、可复制的结构，不自行升级创意简历。岗位影响证据取舍，不固定绑定视觉风格。

| 内容方向 | 应优先表达 |
| --- | --- |
| 技术、数据、工程 | 本人负责范围、方法、复杂度、产物与验证结果 |
| 研究与学术 | 研究问题、方法、发表、作者角色与准确引用 |
| 金融、法律、医疗、机构 | 资质、责任、合规与可验证实践 |
| 教育、公益、服务 | 服务对象、本人方法、范围与有依据的影响 |
| 市场、增长、运营 | 指标口径、周期、渠道、本人动作与实际结果 |
| 咨询、产品、管理 | 决策、协作、推进过程与交付，不把团队成果全归个人 |
| 设计、艺术、内容 | 作品、本人角色、设计判断、成果与真实链接 |

## 经历整理与事实边界

- 可压缩、统一时态或改为“动作—对象—结果”，不能编造学历、公司、职位、项目、客户、技能、奖项和数字。
- 无量化结果时，用真实产物、采用情况、协作范围或任务复杂度表达，不补百分比。
- 应届生可优先相关项目、实习与教育；有经验者优先相关工作与成果。不要求每段等长。
- 职责说明持续贡献，项目展开关键问题和本人动作；同一事实不重复两段。
- 日期冲突、重叠、空窗期和指标不明保留待核实，不能自行修正历史或推断原因。
- 岗位描述可帮助排序，不能用招聘要求补写候选人尚未证明的能力。搜索不能用来制造个人履历。

### 一页内容过多时

按以下顺序精简，保留姓名、联系方式、目标、组织、职位和日期等身份事实：

1. 删除空泛自评、重复职责、与目标岗位无关的课程和重复技能；合并同一经历中表达相同成果的句子。
2. 近期且相关经历保留 3–5 条强证据；较早或相关性低的经历压缩为 1–2 条，写清职责范围和最重要产物。
3. 每条优先保留“本人动作 + 对象／方法 + 真实产物或结果”，删除背景铺垫、套话和未形成证据的形容词。
4. 多个同类短项目可以合并成一组，但项目名称、本人角色和不同结果不能混写。
5. 仍超量时明确列出拟删除项及理由，不能通过低于可读字号、极窄行距或隐藏内容强塞一页。

### 一页内容过少时

只展开已有事实，不发明新经历或结果：

1. 把笼统职责追问或拆成“面对什么任务 → 本人采取什么动作 → 使用什么方法／工具 → 交付什么产物 → 有什么已知结果”。
2. 对项目补充已知的对象、范围、协作角色、关键难点、决策依据和交付物；未知数字、客户、规模和结果保持待补。
3. 技能后补其真实使用场景，教育经历可补与目标岗位相关且来源明确的课程、课题、作品或活动。
4. 没有量化结果时描述实际采用情况、交付范围、审核通过、上线状态或协作复杂度；没有这些事实就不虚构。
5. 扩写仍不足时保持简洁留白，并列出最值得向用户追问的事实，不用无关爱好、长篇自我评价或装饰填满页面。

改写结果必须是可直接排版的完整文案，不只写“突出成果”“精简经历”等编辑建议。

## 人像、作品与页面

从用户提供的简历、附件或图片中定位与本简历候选人对应的真实人像，以该图作为身份参考图，记录真实 URL 短链并标为图1。优先直接裁切；需要统一背景、曝光或构图时，以图1调用图片编辑工具生成 3:4 证件照，保持同一人的面部、年龄、肤色、发型、体型和服装身份。没有对应人像时继续内容草稿并列“证件照待补”，不得根据姓名或经历生成替身；用户明确不放照片，或投递渠道明确要求无照时省略并记录依据。

作品和项目截图逐项记录对应经历、本人角色、真实 URL 短链与允许处理范围；生成背景或插画只能作为非事实视觉，不冒充候选人作品。已有短链不得省略；没有可用短链时写“短链待补”，不得编造 URL 或用本地路径代替。

默认按 A4 210 × 297 mm、1 页起排，用户与投递渠道尺寸优先。只有用户明确要求多页时才增加后续页；学术 CV 等天然多页产物也应先获得明确页数要求。多页时第 1 页独立说明身份、方向与最强证据，后续页保留身份和页码，经历尽量不截断，避免最后一页只剩零散几行。

## 固定页面、安全区与长文本验收

简历的页面尺寸在排版前锁定，默认 A4 210×297mm、1页。局部记录可以因换行变高，但所有记录的总高必须仍容纳在这一页中。**不得用正文 scrollHeight、自然高度或新增空白重新定义整页高度**，也不能在失败后把产物改称长图。浏览器窄窗口只改变预览缩放或滚动，不重新定义纸张尺寸或页数。

本库新增三套简历的试排基准为800×1132px（A4比例近似），正文四边48px，约12.6mm；其他分辨率按物理距离等比例换算。姓名、联系方式、正文、日期和页脚文字都在安全区内；纯装饰可出血，照片脸部另设安全区。页脚放在安全底线之上，不能与最后一条经历争用同一空间。不要仅检查main边界，必须检查真实文本行框与安全边界。

长文本按以下顺序处理，每一步后重新测量固定页面：

1. **字段换行**：姓名正常换行并推开下方内容；邮箱/链接在自身容器内断行，完整保留文本和链接；机构胶囊按内容增高。短年份区间保持同行，整组日期空间不足时移动到下一行；不截断日期。
2. **局部布局**：统一调整同组列比、沟槽与标签换行，保持职位—组织/日期—职责的对应；不能逐条任意调列。标题与照片重叠时优先调整照片槽位和标题区域，不能覆盖脸部。
3. **有限紧凑档**：减少模块/记录间空隙，缩减装饰及照片占比，拓宽正文列；保留原文字号、事实、日期和全部条目。不能减安全区、压缩字形或行距到不可读，也不能使用line-clamp、省略号、滚动框、透明文字或overflow:hidden藏正文。
4. **超容量处理**：仍放不下时停止成品导出，给出超出安全底线的像素值、发生溢出的字段、保持字号的重排结果，以及逐项可精简文案方案。内容精简沿用本Spec的事实核对规则；需要删除非重复事实或增加A4页时请用户决定，不自动删项、加页或加长画布。

验收记录应包括：预先锁定宽高与页数、四边安全距离、姓名/邮箱/机构的实际换行、正文和辅助字号、最末文字位置、正文碰撞/裁切、人脸遮挡、导出前后尺寸和文字是否一致。导出前与行内HTML导出后都测一次；页面尺寸匹配但文字越过安全区仍为失败。达到最小字号不等于可读，浅色小字、粉底白字等必须另验前景/背景对比与实际阅读效果。

容量测试要同时有正例与负例：正例增加姓名、邮箱、机构或职责后仍保持固定A4；负例保留全部超量内容，必须报告拒绝导出。截取A4范围的截图会隐藏溢出，不能单凭截图声称通过；负例完整溢出图只作为诊断，不作为简历成品。之前将4157字符撑成长画布的测试不属于简历适配通过证据。

## 缺口与内容核对

简历不适用经验补造履历：草稿直接标明待补事实，正式投递前移除占位与写作指导并完成核实。可以准备另列的提问或句式建议，不把建议混入简历正文。

保存前对照原材料核对姓名、联系、组织、日期、资质、本人贡献、数字口径、作品归属与每页顺序。只做文本抽取检查不能宣称所有 ATS 均兼容；实际渠道测试状态留给后续记录。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：按本 Spec 把候选人事实、目标岗位、阅读模式、完整履历文案、证据与作品来源、人像状态、页面职责、尺寸和待补事实写入同一 Brief，不把写作建议混入可见简历。
- **内容结构验收规范**：对照原材料核对姓名、联系、组织、职位、日期、本人贡献、数字、资质、作品归属、页序和人像身份；未做真实渠道测试时不得宣称 ATS 全面兼容。
