# 公告海报内容 Brief

在当前任务已有的设计 Brief 中填写“公告海报内容结构”；没有时根据当前对话创建，不另建同任务副本。

<a id="announcement-hybrid"></a>

## 底图与准确文字分工

通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图默认按 AI + Coding 制作：复用合适的真实底图或生成无字主视觉，标题、正文、姓名、日期、地点、结果数字、单位、统计范围和行动信息默认全部由 HTML 原生文字准确排版。只有明确需要艺术字的唯一主标题才按艺术标题准入另行处理；用户明确要求纯代码或“全部由图像模型生成、不要 HTML 排版”时再按主路由覆盖，不能由“海报”“做一张”“导出图片”等产物表述自行改道。

## 底图结果约束

凡本品类进入 HTML/CSS 设计，作品级底图必须包含与主题和视觉系统相关的纹理、肌理或渐变中的至少一项，不得以无变化纯色铺满整张画布。事实与正文区域可以局部降为纯色或低纹理以保证阅读，但仍须属于同一底图系统。Spec 只记录这项结果门禁和底图职责；具体材质、色场、变化方向、生成方式与 Prompt 由对应 Visual 决定。

“放射构图”与“放射性光线”必须分开：前者仅指平面对象、实色线条、纹样或信息单元围绕焦点排列；后者包括顶部聚光、放射光束、太阳芒／耶稣光、舞台追光、体积光、闪电／雷霆光纹和镜头光晕。公告海报家族默认不使用二者；只有用户明确要求放射图形时才可采用不发光的平面放射构图，只有用户另行明确点名某项光效或要求保留参考中的该项光效时才可使用放射性光线。喜报、捷报、成果战报、庆典、隆重、红金、金色和丝绸／绸缎都不构成光效授权。

## Brief 结构

```markdown
## 公告海报内容结构

- 主体：谁发布
- 受众：向谁说明
- 内容：通知什么、邀请什么或公布什么结果，写出可直接排版的标题与正文，不只写文案大意
- 日期：事项发生或生效的日期；需要时注明发布日期
- 时间：具体时刻或时间段
- 地点：
- 行动要求：读者需要做什么，按需附联系方式或参与方式
- 叙事节奏：文案是直接告知，还是先抒情再邀请，简短说明语气与节奏
- 信息链：用一句顺序说明先读什么、再读什么
- 配图计划：背景图的主题内容与用途；其他配图按需写明内容、数量、真实 URL 短链、直接使用／编辑／借鉴方式，以及如何使用
- 画幅：宽 × 高及单位，比例按宽:高记录
```

不适用的时间、地点、行动要求等字段可省略。改期写清原安排与新安排；喜报写清主体与结果；涉及数据时保留单位、周期和范围，不另拆一套内容规划。

配图计划写清画什么、用来做什么，例如“一张以花枝为主题的待生成背景图承托请柬文案；用户提供的一张合照（附真实来源或短链）作为主照片，保留两人完整面部”。没有其他配图就只写背景图，不虚构素材或链接；具体风格、位置、裁切、光线和 Prompt 交给 Visual。

画幅优先使用用户指定尺寸；未指定时默认 **1080 × 1440 px（3:4）**。明确要求手机全屏、方图或横屏时分别用 9:16、1:1、16:9；印刷按实际纸张尺寸。默认只做一张，多尺寸版本共用同一内容。

## 适用类型

| 类型 | 常见场景 | 情绪与文案节奏 | 常用配图与用法 |
| --- | --- | --- | --- |
| 日常通知 | 放假安排、营业时间、服务调整、维护通知 | 清晰、平稳，直入事项 → 时间与影响范围 → 行动要求 → 落款，不做抒情铺垫 | 常用一张承托信息的背景，可包含品牌相关物件或事项主题图形；已有店铺、服务空间照片可用于识别发布主体，不必另配照片 |
| 变更公告 | 活动延期、改期、取消、地点变更 | 郑重、体谅，先说变更结论 → 新旧安排 → 必要原因与处理方式 → 简短致歉或感谢 | 常用简洁背景或沿用原活动主题图；地点变更时可附有来源的新场地照片帮助识别，不用无依据的灾害或天气图暗示原因 |
| 停业／恢复公告 | 临时闭店、暂停服务、恢复营业 | 停业克制体谅，恢复营业积极亲切；均先说状态 → 生效时间与范围 → 后续安排 → 致谢或欢迎 | 常用品牌相关背景、门店物件或真实店面照片；恢复营业可用已提供的新空间照片展示变化，不生成虚假的装修现场 |
| 公示公告 | 名单公示、入选结果、评选结果、安排公示 | 客观、正式，直入公示事项与结果 → 范围或依据 → 适用的公示期限与反馈方式 → 发布方 | 通常只需承托名单与结果的背景；必要时附真实入选作品或成果照片，按对应对象标清来源，不为填满画面增加无关配图 |
| 喜报／荣誉 | 录取、晋升、签约、获奖、里程碑达成 | 热烈、自豪，先亮成果与主体 → 具体结果及依据 → 祝贺或感谢，避免空泛口号抢在结果前 | 可用绸带、桂冠等庆祝主题背景，按需配本人／团队照片、签约现场或真实奖状奖杯照片，分别用于主体识别或成果佐证；装饰奖杯不能冒充真实奖项 |
| 成果战报 | 销售业绩、赛事结果、项目阶段成果 | 有力、真实，直入核心结果 → 周期、范围与单位 → 关键表现 → 收束；未达目标或失利时不强作庆祝 | 常用承托结果数字的背景；可配相关产品、团队、项目或赛事现场照片说明成果归属。图表按核实数据制作，数字不作为底图的一部分生成 |
| 婚礼请柬 | 婚礼仪式、婚宴邀请 | 温柔、真挚，可用一两句抒情开场 → 新人姓名与邀请 → 时间地点 → 期待出席，抒情不挤掉安排 | 常用花枝、植物、信笺或与新人有关的主题背景；可配用户提供的新人合照作为主体，真实场地照片按需辅助识别；无合照时采用无人物方案，不生成替身新人 |
| 活动邀请 | 展览、演出、沙龙、讲座、会议、发布会 | 期待、诚挚，活动主题或一句吸引点开场 → 邀请与内容亮点 → 时间地点 → 参与方式；正式会议直接入题 | 常用活动主题物件或图形背景，如书籍、乐器、展览主题；有来源时配作品、嘉宾、产品或场地照片说明亮点，不把往届现场当成本届实况 |
| 开业／乔迁邀请 | 门店开业、品牌入驻、新址启用、乔迁庆典 | 喜悦、热情，先宣布开业或新址启用 → 简短邀约 → 时间地点 → 欢迎到场，不虚构促销权益 | 常用品牌物件或开业主题背景；可配真实门头、新空间或代表性产品照片帮助认店和了解业务，Logo 使用已提供素材 |
| 聚会／宴请邀请 | 生日、周年纪念、同学聚会、年会、答谢宴 | 亲切、温暖，一句回忆、感谢或相聚理由 → 邀请主题 → 时间地点 → 出席回复，避免长篇煽情 | 常用与相聚理由有关的背景，如蛋糕、餐桌物件或共同记忆中的物品；用户提供的旧照、合照用于表达关系，不能虚构共同经历 |
| 节庆／周年贺图 | 新年、中秋、节日祝福、品牌或组织周年庆 | 温暖、喜悦或纪念感，节日／周年主题 → 一句祝福或感谢 → 落款；如含放假安排，将时间与行动单独写清 | 常用一个节日或周年主题背景，如月轮、灯笼、花卉或品牌代表物；周年可按需配真实历史照片或产品图建立纪念关系，不必把所有节日符号堆在一起 |

按场合与受众调整情绪和铺垫长度，紧急事项优先直入重点；公示公告指传播海报，不替代有法律效力的正式文书。

配图列是内容候选，不是必选清单或固定风格。结合主体、受众与实际素材取舍，将选中的内容写回“配图计划”，不照抄整列；背景中的主题元素不必各拆成一张图。待生成背景或非事实装饰标明“待生成”，直接使用的照片、Logo、作品与证据逐项记录用户素材标识或可核实来源。有可用参考图时必须附真实 URL 短链；未取得时写“短链待补”，不得编造 URL 或用本地路径代替。

## 内容补写

内容优先来自用户资料或可核实来源。资料缺失时可按场景经验补写占位内容，并在对应内容旁显示“**注：**以下内容由模型根据经验生成，非真实事实，正式使用前请替换为已核实内容”。声明以清晰可读的小字号呈现，与背景有明确对比但不抢正文；不得隐藏、冒充已确认事实，正式使用前须替换核实。

## 写回 Brief 的内容结构规范

- **内容结构生产规范**：按本 Spec 把公告类型、发布主体、受众、准确文案、事实状态、信息顺序、尺寸、配图来源和缺口写入同一 Brief；占位声明必须与对应内容就近绑定。
- **内容结构验收规范**：逐项核对核心事项、主体、时间地点、影响范围、行动、落款、来源与占位披露，确认信息顺序适合当前场合且全部面向读者可直接使用。

## 通知与邀请函的视觉候选入口

先按本 Spec 完成真实文案和信息顺序，再由 [公告海报视觉规划](../systems/announcement-poster-visual-system.md#邀请函图文与-css-策略) 联合试排整页关系并比较组合。命中相关组合时按约 70% 适配原则判断；不适合整体复用时用整页布局与局部原子组织自己的方案。简历、长图或折页示例不能仅因同色就当作邀请函整版。候选不新增 KV 或风格选择门禁。
