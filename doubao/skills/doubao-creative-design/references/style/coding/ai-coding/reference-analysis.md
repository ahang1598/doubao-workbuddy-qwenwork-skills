# AI + Coding 参考图解析与继承

用于已经路由到 AI + Coding 的参考新建、图片模板重建和参考驱动修改。目标不是复述参考图，而是先把它转成可执行的内部视觉底稿，再把底稿写入同一份自然语言 Design Brief，最后由 最终 HTML 和 HTML 落实。

本文件不授予编辑权限，也不重新决定生产轨道。模板任务能改什么只由 [模板编辑](../../../workflow/template-rewrite.md) 的授权边界决定；参考新建能继承什么只由当前用户请求决定。原图中的 Logo、商品、人物、文案、数据和独特插画不会因为被分析就自动获准复用。

## 1. 调用与输入分工

出现“参考排版／结构／风格”“做同款换产品文案”“严格复刻”，或用户明确指定参考图中的字体、配色、肌理、卡片、渐变、蒙版等维度时，必须在视觉选型、字体选择、KV 和正式素材生产之前读取本文件。

每张输入先区分用途：身份来源、内容证据、整体设计参考或局部效果参考。多张图按维度指定主次来源，不平均混合；身份图只保护商品、人物或品牌身份，不自动提供版式；局部效果图也不能反向覆盖主参考的整体阅读关系。

按用户语义判断继承强度：

- “一模一样／位置不动／严格复刻”只在已授权维度内尽量保持具体关系。
- “参考结构和风格／做同款，只换内容”默认做结构迁移，保留机制并为新主题适配。
- “只参考配色／字体／某个效果”只分析指定维度，其余视觉由当前品类 Ref 补足。

只有原图缺失、关键继承要求互相冲突，或完整文案无法在锁定结构中容纳时才澄清；不为填写分析增加确认轮次。

## 2. 先形成内部视觉底稿

### 2.1 清理非设计内容

实际查看可访问的原尺寸参考。分析前先从设计画幅中排除水印、截图 UI、软件或浏览器工具栏、平台按钮、黑边、账号名、AI 角标、演示外框及其他非作品内容。被排除内容只记录为“已过滤”，不得进入构图、文案、色彩、字体、素材或 HTML 计划。

拼图、长图并排预览和多页截图要先识别真实页面及顺序；无法恢复的隐藏部分保持未知，不猜测。低清、裁切、模糊或透视拍摄只允许得出相应精度的观察，不宣称完成精确取色、字体识别或像素测量。

### 2.2 十一维逐项推演

以下 11 维必须逐项写入 Design Brief 的“参考图视觉底稿”。只分析用户要求继承的参考；确实不存在的维度写“未出现”，不能省略，也不为凑项添加效果。

1. **版式**：说明栅格、分栏、模块、留白和对齐方式，以及它们怎样组织内容。
2. **构图**：说明构图类型、主体位置／尺度／朝向、视觉重心、纵深与阅读路径。
3. **关系**：说明主体与陪体、文字、背景之间的遮挡、接触、穿插和孤立度。
4. **文案**：逐字记录可辨文字，并说明语种、语气、修辞和商业作用。不可辨文字明确标记，不补猜为事实。
5. **色彩**：说明主色、辅色、点缀色的职责，以及明度、饱和度、冷暖和高对比／互补／邻近／单色加点缀等配色机制。参考观察色不自动成为目标色。
6. **光影材质**：说明光源方向、强弱描述词、颜色倾向、自然光／棚拍光／环境光等属性、高光和阴影落位及纹理。此维禁止使用 K、RGB、HEX 或光比数字。
7. **字体**：说明字族、字阶、字重、粗细、横竖排、倾斜或错落，以及颜色、描边、阴影、发光、纹理、立体与破损处理。字形观察不等于已识别具体字体名。
8. **信息**：说明信息层级、标注、图例、卡片、栏目、编号和数据关系。
9. **风格**：说明画种、流派、媒介、笔触、颗粒与网点。摄影必须补充焦段感、机位、景深、对比度、影调，以及具体胶片型号或明确调色语言。
10. **人像**：有人像时说明姿态、表情、发型、服装廓形与材质，并说明底妆、腮红、眼妆、唇妆、修容、高光和妆感流派；无人像时写“未出现”。
11. **商业与可迁移规律**：说明卖点、痛点、CTA、品牌语气，以及这张图为什么成立；不得把“高级感”“氛围感”当作原因。

### 2.3 多块结构必须逐块绑定图文

参考包含分栏、四宫格、时间轴、步骤图、对比卡或卡片流时，必须按真实阅读顺序逐块记录“配图—文字”绑定。每一块都要写清：

- 该块主体，以及构图、姿态或朝向；
- 材质或成像手法；
- 色彩职责和与相邻块的差异；
- 逐字可辨文案、文案层级及其承载语义；
- 图片与文字为何绑定、读完后如何进入下一块。

不得写“其余同理”，不得把多块结构压成“一张主图＋多段文字”，也不得只记录容器数量而遗漏每块的主题差异。用户提供 A／B／C 三项内容不等于画面必须机械切成三栏；仍按参考的阅读路径和语义权重分配。

### 2.4 抽取七类同源机制

完成 11 维与逐块记录后，另用自然语言总结七类可迁移机制：

1. 构图公式；
2. 配色思路；
3. 文字层数与字号相对比例；
4. 文案语气与修辞；
5. 图文的层叠、穿插、咬合、并置、环绕或遮挡方式；
6. 主体与其他元素的关联强弱；
7. 美术成像手法。

“同款”学习的是这些机制，不照搬坐标、具体色相和具体物象。独特插画、品牌符号或旧主题道具必须换成服务新主题的对象。

### 2.5 证据与不确定性

对关键判断说明来自哪张图、哪个区域，以及是直接观察、可复核测量、合理推断还是尚未解决。OCR 只辅助转写；所有文字仍需逐字看图。参考观察、目标适配和最终成品三个阶段不得互相覆盖：不能把实现偏差改写成新的参考目标，也不能用 最终 HTML 自洽证明参考还原成功。

## 3. 直接写入自然语言 Design Brief

参考分析只写入当前任务的同一份 `brief.md`，不新建参考分析 JSON、参数表、机器合同或平行 Brief。Brief 使用自然标题、连贯段落和必要的逐块表格，禁止要求用户或 Agent输出字段枚举、模板编号、坐标、色值表或参数校验结果。

有参考图时，Design Brief 至少包含以下自然语言小节：

1. **参考来源与清理说明**：哪张图负责身份、整体结构或局部效果；过滤了哪些非设计内容。
2. **参考图视觉底稿**：按第 2.2 节逐项写完 11 维观察。
3. **逐块图文绑定**：仅多块结构适用，但一旦适用必须逐块完整写，不得合并省略。
4. **七类同源机制**：说明真正要学习的构图、配色、文字、图文关系、关联和成像机制。
5. **目标重建方案**：把新主题、真实资产和完整文案放回参考机制中，说明保留、替换、重建和降级内容。
6. **不确定、冲突与验收重点**：只写会影响结果的未知项、最小解决方案，以及最终应在画面上看到什么。

Brief 中逐字列出最终可见文案，并在叙述中明确哪些句子是画面文字、哪些是设计说明；最终 HTML 再分别整理为可见文字和规划信息。Brief 只说明配色机制与颜色职责，实际 HEX、透明度、像素尺寸、坐标、z-index、CSS 属性、SVG 文件名和模板 ID 统一在 最终 HTML／HTML 阶段确定。

### 3.1 按优先级重建

目标重建方案严格按以下顺序形成：

1. 用户明确要求优先。
2. 默认换掉所有具体色相，只保留高对比、互补、邻近、单色加点缀等配色思路；用户明示保留原色、真实资产固有色及证件照规范背景除外。
3. 换掉旧主题的主视觉、配图、道具、装饰和图形族。新配图必须为新主题点题，不做“圆换圆、方换方”的换皮。
4. 完整对齐参考图的文字模块数、层级和字号相对比；缺文案由 Agent 在事实边界内补齐，用户明示精简时才降低密度。
5. 从视觉焦点、主体尺度／姿态／朝向、标题与主视觉关系、模块分组、阅读路径、装饰分布六项中至少重建三项，并在 Brief 中点明是哪三项及如何改变。
6. 保留一个主亮点和一至两个辅助亮点，其余降级。简约图不靠增加装饰区分，必须改变主视觉轮廓、位置关系或阅读路径中的至少一项。

### 3.2 内容容量

把用户最终文案按语义和商业作用映射到参考图的文字模块。默认保持模块数、层级和相对字级，不因文案不足主动降密；缺少不涉及真实事实的过渡句、解释或 CTA 时可按 [内容事实边界](../../shared/content-truth.md) 补齐。

完整文案超过参考容量时，先在不损失事实的前提下凝练重复表达；仍超载时沿参考的叙事语法增加屏、页或章节，并保持同源构图家族、图文比例和密度节奏。禁止通过全面缩小字号、压行距、删除必要配图或连续堆满高密度模块来维持原屏数。

## 4. Brief → HTML → 模板库

Design Brief 冻结后才建立或更新 最终 HTML。HTML 的职责是把自然语言方案结构化转译为可执行事实，不反向要求 Brief 补齐机器字段，也不存在自动解析 Brief 的编译器。只有 素材清单、HTML 源、资源引用和真实渲染接受结构／参数校验；Brief 只检查是否忠实表达用户要求、11 维底稿、逐块绑定、同源机制和重建方案。

HTML 至少要为每项关键决定找到实际承载对象：

| Brief 决策 | 最终 HTML 落点 |
| --- | --- |
| 版式、构图和阅读路径 | 章节／组件结构、稳定元素 ID、Grid／Flex／定位关系、具体几何与层级 |
| 主体、陪体与遮挡关系 | 实际图片 DOM、裁切、transform、z-index、保护区与接触关系 |
| 最终可见文案 | 可见文字集合、真实 DOM 文本或品类准入的图内文案；规划说明不得进入 DOM |
| 配色机制 | 目标色值、渐变色标、透明度、作用对象和对比检查；不复制参考具体色相，除非属于例外 |
| 光影、材质、字体和成像 | CSS／SVG 模板引用、字体契约、图像素材或后处理；每个效果绑定真实消费者 |
| 信息与逐块图文绑定 | 卡片／步骤／对比／时间轴的逐块 DOM 结构，图片、文字和语义一一对应 |
| 商业主次与亮点 | 主焦点、辅助焦点、CTA 位置和其余元素的降级方式 |

确定品类后，先在 [`assets/templates/ref-bindings.json`](../../../../assets/templates/ref-bindings.json) 取得稳定 `ref_key`，再用该键筛选 CSS 与 SVG 候选。CSS 模板从 [`assets/templates/css/catalog.json`](../../../../assets/templates/css/catalog.json) 取得稳定 ID 和正文位置；SVG 从 [`assets/svg/catalog.json`](../../../../assets/svg/catalog.json) 取得稳定资源 ID、文件名和适用品类。Brief 只描述想达到的视觉效果，模板 ID、依赖、覆盖值和消费者写入 HTML。

命中库内的卡片容器、渐变、弥散、蒙版、纸纹、玻璃、文字效果等机制时，必须读取对应正文和依赖，按真实代码写入 HTML；目录命中、名称相似或只写 ID 不算实现。没有精确候选时才按当前视觉系统自行实现，并在 HTML 验证记录中说明未采用原因。

## 5. HTML 重建与验证

HTML 只按 [HTML/CSS 编码与渲染契约](../../../html/coding-rendering.md) 生成完整固定画布文档。准确文案使用真实 DOM；复杂自由路径使用内嵌 SVG；图片承担摄影、插画、复杂材质或已准入的一体化内容。不得把参考截图作为整页背景后覆盖新文字来冒充分层重建。

验证分为两层：

1. **实现一致性**：检查 HTML 的元素、文字、素材、CSS/SVG 引用、几何和层级是否真正进入同版本 HTML，并检查预览、上传、顶层 HTML Item 写入和回读。
2. **参考继承度**：直接对照 Design Brief 的 11 维底稿、逐块绑定、七类机制和重建六步检查最终渲染。不能用字段齐全、模板 ID 命中或 HTML 与源码一致代替画面成立。

先看完整画面的焦点、主体尺度、模块分组、阅读路径、文字密度和亮点控制，再逐块检查图片—文字语义、字体表现、色彩机制、光影材质、人像与商业作用。参考任务若只锁定局部维度，只验收该维度及其受影响邻居；未授权区域必须保持不变。

每项结论写明可见证据、差异和处理结果。没有实际预览时标记未验证；低清参考导致无法确认的字体、妆容或材质细节也保持未知，不把推断写成通过。

### 背景、卡片、文字关系与三类安全区

在参考分析时确定下列关系，并将被继承的部分带入现有 Brief 的 `invariants`、`adaptations` 和 `acceptance`；HTML 细化与素材就绪时按同一记录落实。没有参考的新建任务按已选构图建立目标，不编造原图证据。本节是关系检查依据，不另建 Schema，不要求所有设计具有卡片或纹理。

| 检查项 | 必须形成的执行依据 |
| --- | --- |
| 背景归属 | 区分成品整页／章节背景、卡片表面、照片内部场景和作品展示外底。外侧衬底不自动提取为成品背景；共同色场和连续场景明确共享范围，不按文字段落强拆 |
| 图文与容器关系 | 标明文字属于哪张卡、哪件产品或哪段场景，记录父子／并列、对齐轴、净空、前后层级、允许穿插和阅读顺序；无卡片写 none。产品在连续长图内左右错落，须分别记录产品、标题与卖点的位置，不能简化为等宽左右图文卡或机械镜像 |
| 纹理与成像归属 | 字形、卡面、背景和主体成像分别绑定承担者及范围；记录颗粒尺度、密度／强度、渐变方向与淡出边界。区分细纸纹、大片斑驳、暗纹插画与摄影柔焦，不能用一种噪点代替所有材质；已有图片承载的效果不重复覆盖 |
| 页面安全区 | 明确成品画幅内文字和关键内容距边缘的区域、章节留白及接缝保护范围；装饰出血单独记录。安全距离依据目标画幅、阅读尺度和参考证据确定，不套统一百分比 |
| 容器安全区 | 依据真实可见内表面扣除边框、折角、夹子、缺口、遮挡和旋转后不可用区域；内容框不能直接等于外接矩形。卡片与内容一起变换时核验最终可见位置 |
| 素材语义保护区 | 明确人脸、Logo、产品轮廓、标签、关键证据等不得误裁／遮挡的部位，以及可承载文字的低干扰净空；背景淡出、纹理和前景装饰都要避让。区分素材源坐标与目标显示坐标 |

在同一 Brief 用自然语言说明承托、遮挡与安全关系；图片裁切与安全区记入原素材清单，实际节点、几何、层级与蒙版直接在 HTML 实现，不恢复机器规划字段。每个判断绑定来源区域和目标消费者；范围、比例或数值标明坐标基准，并区分实测、观察、推断及待定。允许叠压要说明哪一层可遮哪一层、哪些内容必须完整，不能仅写一个 z-index。

材质状态分别记录为“已有实现及依赖”“已绑定当前素材／节点”“当前渲染已核验”；仅在配方中提到纸纹、柔焦或斑驳，不等于已经兑现。复杂材质仍沿既有素材生产和 HTML 能力边界执行，不将库示例中的滤镜直接当成正式交付能力，也不对含正文的共同根节点施加模糊或整体透明度。

规划安全区不能直接当成实际验收结果。最终素材经过缩放、裁切、旋转、遮罩或替换后，将保护区映射到实际显示坐标，核验文字墨迹、卡片可用内面与真实主体；占位框和素材原始尺寸不能证明这一关系成立。文字还须按真实字体、目标文案和每个交付尺寸检查语义断行、数字单位与标签行数：例如需横排的 Top 10 意外拆行，即使没有溢出也属于失败；有依据的竖排不套此例。先调整行宽、分组及容器高度，再复查邻居，不能通过缩小全页文字或隐藏溢出来消除告警。
