# 艺术标题 Prompt 与材质库

用户要求某段文字独立可编辑时，该文字使用真实文本 DOM；要求全部文字可编辑时主标题也不进入生成式艺术字流程。未要求该文字可编辑时才按下文准入规则执行。

本文件的独立字图流程只服务于已通过准入的艺术主标题图片层。一体化社媒 Hero 仅可引用本库的字形、材质与边缘语言，标题在整体场景中生成，按社媒长图 Spec 验收，不执行独立字图的纯色底、抠图、独立投影限制；本文以下流程均指独立字图。其准入为：首屏／首图主标题，或每个独立图片产物中唯一最重要的大标题。同一图片默认最多一个；普通 H1、章节标题、模块标题不得调用本库。生成模型应产出具有明显字形改造、笔画语言或材质空间表达的艺术字体；如果目标只是基本黑体、宋体、圆体或常规展示字体，必须从字体库选择并使用可编辑文本 DOM。

## 选择顺序

1. 读取准确 `source_text`、标题层级、语义、目标尺寸及已确认的 `kv_title_style_reference`。
2. 先定字形骨架：黑体融合、稚拙手绘、厚笔书法、风动行草、粗笔签名、复古诗意或粗笔狂草；所有路线统一使用中粗、粗或特粗视觉重量。
3. 再定空间形态：平面、浅浮雕、挤压立体、充气软体或雕塑体。立体不是默认选项；只有主视觉需要体积、产品感、潮流感或材质表现时使用。
4. 再定材质、光线、边缘与阴影。材质必须服务主题，并与 KV 的产品、环境或视觉系统同源。
5. 最后按 [艺术标题接入规则](../../../workflow/creation/ai-coding.md#艺术标题改写策略) 选择生成背景与接入方式。DIT 黑底字图＋HTML Web 合成沿用 `blend`：浅色字用纯黑底，图片节点行内设置 `mix-blend-mode: screen`；深色字用纯白底＋`multiply`，两者均不抠图，只适用于已知稳定背景。透明导出、跨背景复用、背景未知或严格保色走 `alpha-cutout`。字图可移动、替换，不等于文字可逐字编辑；不改变各品类准入边界。

系列中多个独立图片各自有准入艺术主标题时，共用字形骨架、空间形态、主材质、光向、边缘逻辑与色板，并按语义和长度做受控变化。所有未准入标题改从字体库选择协调字体。

## 必填效果参数

艺术标题 Prompt 不能只写“高级、立体、有质感”。至少明确以下参数：

```yaml
glyph_style: 字形骨架、字重、宽高比、笔画节奏
glyph_edits: 指定到字符和部位的切角、连笔、延伸或断笔
dimensional_mode: flat | low-relief | extruded-3d | inflated | sculpted
view_angle: 正视，或不超过约 12° 的轻微俯仰／水平偏转
extrusion: 无，或厚度、方向、侧面可见程度
face_material: 字面主材质、颜色、粗糙度、纹理尺度
side_material: 侧面材质与颜色；平面字为 none
surface_finish: 哑光、半哑光、镜面、拉丝、磨砂、釉面等唯一处理
lighting: 主光方向、软硬、面积、亮暗关系
shadow_policy: 只允许字形自阴影／侧面阴影；禁止环境地面与外部投影
edge_treatment: 倒角、圆角、毛边、飞白或墨晕
palette_by_part: 字面、侧面、局部强调的明确色彩职责
microtexture: 颗粒、纤维、裂纹、刮痕等的尺度与密度
integration_mode: blend | alpha-cutout
background_color: blend 按黑底／白底成对规则；alpha-cutout 使用与全部字形边缘高反差的均匀纯色
```

立体字默认使用接近正视的镜头，保证字面不因透视而缩窄；厚度通常不超过字面主笔画宽度的 `0.3–0.8 倍`。自阴影只用于解释体积，不得形成漂浮在地面上的场景投影。高光必须服从单一光源，不能每个字各自发光。

## 字形路线模板

以下模板中的“XX”替换为准确源文字，并补入材质模块；背景按已选接入方式调整，不由模板决定必须抠图。不要照抄情绪叙事覆盖当前任务语义。

### 1. 创意融合黑体

```text
在单一纯白生成背景上生成准确中文标题“XX”，只包含这组文字。采用创意融合黑体：以清晰、稳定、年轻的粗黑体骨架为基础，字面比例紧凑有力，重心一致；在指定笔画的转角、末端或负形中融入少量流畅曲线，使规整结构与灵动节奏并存。起收笔利落，局部切角和曲线变化有明确位置，不随机扭曲，不损害逐字识别。字形居中、完整、四周留足安全边距，高对比专业字体设计展示。<加入唯一材质模块与光线参数>。无额外文字、字母、数字、Logo、边框、水印或场景物体。
```

适合年轻品牌、潮流活动、运动、社媒主标题。可搭配半哑光喷漆、丝网油墨、拉丝金属或轻量挤压立体；不默认使用彩虹渐变、霓虹外发光和多重描边。

### 2. 稚拙童趣手绘体

```text
在单一纯黑生成背景上生成准确中文标题“XX”，只包含这组白色文字。使用中粗至特粗的稚拙手绘骨架，字形模拟儿童手写的夸张比例：各字大小和倾斜有受控差异，局部歪扭、圆钝、笨拙可爱，但每个字仍清晰可认，字序与断行准确。笔画厚实，保留蜡笔或粗铅笔反复涂画的颗粒、叠痕和不均匀边缘，纹理尺度在最终缩放后仍可见，不让噪点切断关键笔画。整体跳脱常规排版但保持视觉平衡。无额外涂鸦文字、人物、边框、地面、投影、Logo 或水印。
```

适合亲子、教育、手账和轻松社媒。材质优先蜡笔、粉笔、油画棒、纸浆或软陶；如果做立体，只使用低浮雕纸浆／软陶，避免金属与玻璃破坏童趣。

### 3. 白色书法手写体

```text
在单一纯黑生成背景上生成准确中文标题“XX”，只包含这组白色书法文字。使用中粗至特粗、有力量的毛笔手写骨架，运笔方向清楚，提按、转折、顿挫、飞白与墨韵变化自然；主笔厚实有力，连接笔画不得细成发丝或断裂，内部镂空保持清楚。字形整体简洁大气，居中偏上并保留安全边距，黑白高对比，具有东方书法的力量与温度。材质为真实宣纸吸墨形成的细微毛边和受控飞白，不使用均匀电脑描边、发光或塑料高光。无印章、落款、额外文字、场景、边框或水印。
```

适合文化、生活方式、节气和人文主题。默认保持平面墨迹；如需体积，只做克制的纸面压凹、漆字浅浮雕或金属压印，不把书法笔触变成肥厚气泡。

### 4. 飘逸风动手写体

```text
在与墨色高反差的单一浅米色生成背景上生成准确中文标题“XX”，只包含这组文字。采用中粗至粗重的飘逸行草骨架，字形舒展，主笔厚实，最细连接笔画仍稳定可见，运笔连贯；只在指定撇、捺或收笔处上扬并拉长，形成被风带动的方向感。飞白、枯笔和墨色浓淡沿真实运笔变化，拖尾保持完整且不触边，不用无意义长横线。整体洒脱自由、线条流畅，文字仍逐字可读。无额外文字、印章、风景、边框、地面、投影或水印。
```

适合旅行、户外、东方时尚和情绪主题。可搭配矿物颜料、金粉墨、丝绸墨迹或轻微烫金；不适合厚重挤压立体。

### 5. 潇洒个性签名体

```text
在单一纯白生成背景上生成准确中文标题“XX”，只包含这组黑色文字。采用中粗至粗重的现代签名式手写骨架，提按转折自然，主笔厚实，最细连笔仍保持稳定可见；连笔与牵丝只连接可解释的相邻笔画。书写节奏快速而完整，局部墨迹浓淡、干湿和飞白自然。字形自由不羁但不潦草到无法识别，不加入伪英文、随机缩写或额外符号。构图紧凑有张力，四周留足拖尾安全区。无印章、边框、地面、投影、Logo 或水印。
```

适合音乐、人物态度、生活方式和时尚内容。优先墨水、马克笔、油漆笔或金属签字笔材质；若用立体效果，仅做薄金属线材、漆面浅浮雕或霓虹管实体，不叠加外发光污染字形。

### 6. 复古诗意手写体

```text
在单一均匀暖米色生成背景上生成准确中文标题“XX”，只包含这组文字。采用中粗至特粗、疏密错落的手写书法骨架，字面大小、间距和基线有受控变化，不机械居中；主笔厚实流畅，连笔牵丝克制且不得细成发丝，墨色呈褪色旧印刷般的暖褐变化。以细颗粒、轻微油墨缺失和纸纤维感表现年代感，但背景保持纯色均匀，复古纹理只存在于字形内部。整体浪漫、安静、有时间感，仍能逐字清晰辨认。无老照片场景、建筑、人物、落款、额外文字、边框或水印。
```

适合城市文化、展览、书影和叙事长图。可搭配旧铅字油墨、铜版氧化、木刻、烫旧金箔或褪色丝网印刷；避免同时加入胶片、火漆、邮戳等无关道具。

### 7. 粗笔狂草张力体

```text
在单一纯黑生成背景上生成准确中文标题“XX”，只包含这组白色文字。采用粗笔狂草骨架，整体为中粗至特粗视觉重量，线条奔放、节奏跳跃；指定撇捺和收笔可夸张拉长，粗重主笔与略细但仍厚实的连接笔形成对比，枯笔和断连必须符合真实运笔。所有关键字根、交叉点和内部镂空保持可辨，最细笔画在目标显示尺寸下仍清楚，拖尾完整且不触边。整体极简、高张力，不添加编辑批注线或与字形无关的长线。无额外文字、印章、边框、场景或水印。
```

此路线只在情绪张力确有需要时使用，不作为通用主标题公式。首次生成前须在 Prompt 中保证连接笔画在默认缩放下可见；生成后若连接笔画丢失，判为未通过，先完成产物交付、记录问题并暂停该标题的下游使用。用户明确要求修改后，才加粗骨架或改用其他字形路线生成新版本，不以锐化补救。适合粗墨迹、漆笔、金属漆或厚线浮雕，不使用银丝、细金属线材和发丝效果。

## 立体字与材质模块

从下列模块中选一个替换字形模板里的材质占位。模块必须随当前色板、光向和标题语义改写，不直接堆叠。

### A. 挤压立体字

```text
空间形态为接近正视的挤压立体字，镜头水平偏转不超过 8°，保证全部字面完整可读。字面使用<主色与主材质>，侧面向<左下／右下>挤压，深度约为主笔画宽度的<0.3–0.8>倍，侧面使用<较暗同色／指定辅色>。边缘做<小圆角／窄倒角>，单一<左上／右上>面积光形成连续高光、侧面明暗和字形自阴影；无地面、无环境投影、无漂浮底座。各字透视、厚度和光向一致，缩小后不让侧面吞没字面。
```

### B. 充气软体字

```text
空间形态为充气软体字，保留原字骨架与关键负形；笔画圆润鼓起但不过度膨胀，接缝处自然，字面为<哑光橡胶／半透明软胶／织物充气>，表面只有宽而柔的受控高光和轻微褶皱。体积厚度一致，内部镂空不闭合，单一上方软光解释鼓包，自阴影柔和，无地面和环境投影。禁止糖果融化、液体滴落、过强塑料反光或把不同字做成不同材质。
```

### C. 金属／镀铬／拉丝

```text
字面材质为<拉丝铝／镀铬银／香槟金／氧化铜>，明确<细密单向拉丝／克制镜面／细颗粒氧化>，反射只呈现抽象明暗条带，不映出环境、人物或摄影棚。使用窄倒角捕捉单一侧上方主光，亮部不过曝，暗部仍有材质层次；侧面颜色更深且与字面分离。禁止彩虹镀膜、脏灰噪点、多重轮廓光和廉价塑料感。
```

### D. 玻璃／凝胶／亚克力

```text
字形为<透明玻璃／半透明凝胶／磨砂亚克力>，边缘有可读的厚度和受控折射，内部透射色为<颜色>，高光来自单一面积光。透明区域仍保持足够密度与边缘对比，关键笔画和内部镂空不得因折射消失；只允许少量内部气泡或细微磨砂，不生成背景景物的复杂反射。禁止水滴融化、液体拉丝、炫彩色散、强外发光和不可抠取的半透明雾边。
```

### E. 石材／陶土／软雕塑

```text
字形表面使用<细砂岩／哑光陶土／纸浆／软雕塑>材质，体积为浅浮雕或克制雕塑体；表面起伏尺度小于主笔画宽度的 10%，只保留少量颗粒、手工压痕或细裂纹，不切断笔画。边缘<磨圆／手工不规则但闭合>，单一斜上方软光形成浅阴影和真实厚度。禁止巨大裂缝、苔藓、碎块、背景地面和考古道具。
```

### F. 印刷／织物／手工工艺

```text
字形保持平面或低浮雕，使用<丝网油墨／凸版油墨／刺绣线／毛毡／烫金箔／漆面>。明确油墨堆积、网点、纱线方向、锁边、金箔细皱或漆面刷痕的唯一主纹理；纹理密度在缩小后仍形成整体质感，不变成随机噪点。边缘与工艺一致，光线只用于表现微小厚度。禁止同时混用多种手工材质、附加针线工具、纸张背景或无关装饰。
```


## 效果质量门禁

- **先字形、后特效**：关闭材质和阴影后，字形轮廓仍应成立；若只能靠描边、辉光或贴纸边识别，判为未通过。先完成产物交付、记录问题并暂停该标题的下游使用；用户明确要求修改后，才调整骨架生成新版本。
- **材质可解释**：必须看得出材质由什么表面、粗糙度、反射或手工痕迹构成；“高级质感、3D、电影感”不能单独作为材质描述。
- **体积一致**：同组每个字的挤压方向、厚度、透视消失方向、倒角和光源一致；禁止单字随机旋转或各自打光。
- **粗度达标**：所有艺术字只使用中粗、粗或特粗骨架；书法和签名体的连接笔画也不能细成发丝。首次生成前在 Prompt 中明确目标显示尺寸下的笔画可读要求；生成后若缩小导致任何关键笔画消失，判为未通过，先完成产物交付、记录问题并暂停该标题的下游使用。用户明确要求修改后，才加粗骨架生成新版本。
- **主次明确**：准入的唯一艺术主标题允许一种主材质和一种局部工艺；其他标题不进入生成模型，改用真实文本 DOM。
- **接入可用**：`blend` 保留纯色底，在实际 HTML 背景检查边缘、颜色变化与对比，不把混合模式设在父容器或整页；`alpha-cutout` 选择与全部边缘高反差的底色，真实抠图后检查 Alpha、镂空、色边及半透明细节。无法可靠接入时先完成产物交付、记录问题并暂停使用；用户要求修改后才生成新版本。
- **缩小可读**：在最终显示尺寸下逐字可辨，材质形成整体层次而非脏点；关键笔画、金属高光和透明边缘不能消失。
- **不伪造场景**：不得出现地面、墙面、底座、摄影棚、漂浮投影、展示台或背景装饰；最终空间关系由 Coding 排版建立。
- **不随机装饰**：星星、闪电、皇冠、火焰、液滴、贴纸边和英文小字只有在 Brief 明确规划且属于标题本体时才能出现。

出现错字、缺字、形近字错误、额外文字、透视导致字面不可读、材质吞没笔画、不同字厚度／光向不一致、抠图后出现大面积色边或半透明破损时，判为未通过。`image_gen`／`image_edit` 产物在两种环境中都按公共门禁使用 `RichMediaCard` 逐项交付；默认 Canvas 的产后归档不作为交付前置条件，Mobile 不执行 Canvas 操作。交付后标记具体问题，暂停该标题的下游使用并等待用户提出修改要求。禁止自动重生、后期覆盖错误文字，或把多个错误字拼成一张不可维护的标题图；用户明确要求修改后才按单一失败维度生成新版本。
