# 生图 Prompt 与素材使用规范

## 1. 读取时机与用途

- Visual 已在 Brief 明确图片内容、职责、关系与视觉方向后读取。正式素材在建立素材清单、编译 Prompt 前读取；候选 KV 在完整候选 Brief 后读取 [KV 视觉素材生成](#kv-visual-generation)，不等待最终 Brief 冻结或正式素材清单。底图直接进入 [背景图 Prompt](#5-背景图-prompt)。
- 生成／编辑前用本文件核对参考输入、构图、身份与资产用途；结果返回后按本文件完成短链回写、画布登记和 HTML 使用检查。
- 仅复用或替换已有图片时，读取资产使用与 HTML 接入规则，不为凑流程重新生图。
- 本文件把同一份自然语言 Brief 中的配图计划转成可执行 Prompt，不重新决定品类、事实、风格、图片数量或编辑权限。
- 完整纯生图终图使用 [纯生图 Prompt 指南](../../pure-image/prompt-guide.md)；本文件不把它改成分层素材。Visual 引用本文件时仅继承适用的背景写法。
- 本文件不要求槽位合同或全量实现参数。Brief 写图片名称、用途、画面目标、参考职责、图文／背景关系、保护项、禁用项和直接使用说明；`asset-manifest.json` 保存生产方式、真实参考、完整 Prompt、比例、目标尺寸、安全区、消费者、准出标准及实际结果。DOM 几何留在最终 HTML。
- 主 workflow 的 最终 HTML 与阶段要求仍由主流程管理，本文件不扩充其字段，也不要求 Brief 复制技术参数。

正式素材执行顺序（不套用于候选 KV）：读取冻结 Brief 对应图片条目 → 建立对应素材记录并核实参考与用途 → 在素材清单编译 Prompt → 生成／编辑（按主 SKILL 的环境规则透传 Workspace ID）→ 使用 `RichMediaCard` 直接逐项交付→ 回写结果句柄、交付状态与版本 → 检查 → 必要后处理 → 回写最终采用版本 → HTML 组装。`image_gen`／`image_edit` 结果不重复创建媒体 Item，也不在直交前插入媒体回读；直交后的目录归档按公共门禁执行；Mobile 同样逐项直接交付且不调用 Canvas。

## KV 视觉素材生成

本节承接 [KV 确认工作流](../../../workflow/visual-kv-clarification.md) 已确定的候选范围、数量与用途，只负责生成构图、参考输入和 Prompt。候选 KV 是直接生成的完整视觉样张，不是 HTML 分层素材；不因本文件还包含普通配图规则而去掉 KV 标题、拆成散图或提前抠图。确认后正式资产是否抠图按其实际消费者重新判断。

候选阶段使用完整候选 Brief，将真实参考、Prompt、实际结果与版本写入原 `kv-contract.json` 及工作流已有记录；不要求冻结 Brief、不建立正式 `asset-manifest.json`。下文普通素材的建清单、后处理和 HTML 接入顺序仅用于确认后的正式生产。KV 的尺寸、准确标题来源、直接生图、交付与用户确认规则仍由 KV 工作流管理。

从完整候选 Brief 仅提取本张 KV 所需的传播目标、主体身份、准确主标题、候选视觉方向、参考锁定项和确有依据的辅助内容。完整逐屏方案保留在原 Brief，但正式 Hero 的竖向尺寸、全套首屏文案、后续章节配图、卡片清单和 HTML 组合示例不自动进入 KV Prompt；不把“候选 Brief 完整”解释为“整页内容都要在 KV 展示”。必要输入缺失时补齐同一 Brief，不让生图猜测。

**本次调用对象与尺寸**：电商详情页、社媒长图候选 Visual KV 均为 `1920×1080（16:9）` 横版完整关键画面，仅用于确认视觉方向，不是正式 Hero 段高；不得将正式 Hero 的用户尺寸、配方高度或通用默认值带入候选 KV 请求。提交前核对工具比例与尺寸参数，返回后核验实际像素；无法精确输出时如实记录并沿既有流程处理，不静默改为竖版、不拉伸补齐，未达要求不登记为合格 KV。

**辅助内容按本张需求选择**：默认不加入卡片或样本；仅在本张 KV 有明确的比较、归属或必要阅读隔离时采用工作流允许的单卡片，先在原记录说明实际承载内容及其与主主题的关系。场景装饰参与同一空间，不套卡片壳。不因后续页面会用某种卡片、Visual／CSS 示例出现该物件、或画面有空位而补素材；候选 KV 不另生成卡片壳、背景或独立标题配件。用户确认后的正式素材另按对应用途生产。

使用原有 `kv-contract.json` 记录实际输入、候选固定项、差异、完整 Prompt、请求参数及输出实际尺寸，不增加中间创意文件或必填术语链。

- **先让主题成立**：一句话说明画面要传达什么，选定第一焦点及必须看清的主体特征。商品身份、参考锁定项和准确文案优先；创意隐喻仅在能帮助表达时采用，常规摄影、居中构图和纯粹的产品展示均可成立，不为新奇扭曲主体或强加道具。
- **让图文共同构图**：确定主体尺度、视角、位置、标题所在净空及阅读先后；背景、光线、接触阴影和材质形成同一场景。用必要的主题元素组织画面，不堆砌“高级感”形容词、漂浮装饰或样本卡片。艺术表现由构图与材质关系兑现，不靠固定构图清单。
- **把参考转成可执行描述**：说明保留的色彩职责、媒介、字体气质、光向与边缘处理，以及允许变化的部分。双候选只需一个有价值的突出差异，身份、事实与用户锁定项相同；单候选不强求差异轴。
- **直接写生成 Prompt**：清楚描述用途、主体身份、构图与图文位置、场景光材、色彩字体、准确文字和禁止改动项；文字按本节中文双引号规则。内容具体即可，不强求十段固定顺序、关键词数量或抽象隐喻。允许模型丰富符合方向的摄影／绘制细节，不允许改主体身份、事实、文案或核心关系。比例、像素及真实参考图放调用参数，身份图必须实际传入。
- **以实际成图判定**：按 [KV 工作流的交付后验收](../../../workflow/visual-kv-clarification.md#交付后验收)查看主体是否有吸引力且可识别、标题是否准确且有空间、场景是否自然、候选差异是否可见；Prompt 完整不算效果达标。横版 KV 用于确认视觉方向，正式竖向 Hero 按目标槽位重新构图，不能只把横图裁窄、缩小主体或补空白。


### 待渲染文字的中文双引号

最终发给图像工具的 KV Prompt 中，所有明确要求生成或修改的可见文字必须逐条用中文双引号 `“”` 包裹，包括主标题、副标题、英文、数字和标签；Prompt 本身使用何种语言不影响此要求。不得用英文单双引号、反引号或未加引号的散文替代。字体、颜色、位置、断行等排版说明写在引号外，不能混入待渲染文案。

- 以每条准确 `source_text` 为内容边界；只在外侧添加界定引号，不改动原文的字词、数字、标点或原有引号，不把界定引号写回 `source_text`。
- 界定引号用于说明文字范围，不是需要画进图片的字符；源文案本身含引号时，明确注明这些原文引号需要保留。保留参考图上的既有包装文字无需重新转写；若 Prompt 显式指定其文字内容，同样使用 `“”` 包裹。
- 中文双引号约束作用于实际 Prompt 文本，不替换 JSON／HTML 的语法引号。提交前检查全部待渲染文案是否成对包裹、与源文案一致，且没有在其他位置出现冲突的文字版本；该格式不能替代出图后的逐字验收。

示例：主标题渲染为“把一座森林，赠予你”，使用暖白色粗宋体，在逗号后换行；副标题渲染为“四种木质气息 · 一份森林心意”；英文小字渲染为“A FOREST, FOR YOU”。仅渲染各对界定引号内的原文，不渲染界定引号和排版说明。

## 2. Brief、参考与资产使用

### Brief 定设计，素材清单管生产

1. 以原 Brief 的“页面／章节 + 图片名称”定位设计意图，在 `asset-manifest.json` 建立唯一对应素材记录；底图、局部背景和独立配图都不在 Brief 复制生产状态。
2. 按 Brief 的画面职责、目标配图与参考贡献编译处理方案：用参考编辑改变获准的环境、光影、承托或构图，用生成补足有职责的新场景／配景／复杂材质，用抠图和组合建立需要的图文层次；可以组合使用，不固定先裁切再抠图。保护身份不等于照搬原照片，去底也不替代画面设计。缺少事实或视觉决定时返回原 Spec／Visual 补齐，不让 Prompt 临时发明新内容；身份衍生仍按下文母版与 `image_edit` 规则执行。
3. 每张待生成／编辑图片在素材清单单独写完整 Prompt；多图分别写职责、数量、主次和差异，不共用一句“生成同风格图片”。
4. 已有素材同时满足目标表达、构图与实际显示质量时，记录来源、适配依据与使用方式后直接复用；不能仅因素材存在或能够裁切就采用，也不为凑调用重生合格素材。具体任务的图像生产要求继续服从主路线，不伪造生成记录。
5. 生成后短链、处理后短链、尺寸、Alpha、版本和采用状态必须写回同一素材记录，不只存于聊天、调用日志或最终 HTML；Brief 不复制这些生产事实。
6. 回填结果不能反向改变已确认设计。若用户反馈改变内容、主构图或风格，先更新原 Brief 的设计决定，再继续生产。

### 参考输入与版本绑定

- 按 [资产组织与视觉锚点](../../../workflow/canvas-asset-organization.md#4-用户上传的初始视觉锚点) 保存真实来源；实际查看并按目标配图区分待编辑原图、身份母版、风格参考与构图参考，明确各自提供的依据。参考图不是默认成品素材；只锁定已指定的身份、事实及继承范围，不自行把未锁定的背景、光影和整幅构图也固定下来。
- Brief 逐图记录参考对象及借鉴／排除范围；素材清单保存实际参考短链与顺序。Prompt 只用“图1、图2”等序号，工具参考输入按相同顺序传入实际图片。URL、文件路径、内部 ID 和工具参数不写进 Prompt。
- 只有分析过但未实际传入的图片，不能声称已作为工具参考。Item ID 也不能冒充图片输入；按工具实际支持的地址或附件形式传图。
- 商品、人物、品牌与 Logo 的身份衍生必须实际传入已确认母版并使用 `image_edit`，不得仅凭文字重绘相似身份。母版缺失、冲突或未确认时停止依赖它的生成。
- 编辑已合成图片时，当前成品是编辑目标，母版是身份参考；不能用母版替掉当前成品而丢失原构图。工具无法同时接受必要输入时说明限制。
- 裁片保留父图来源与裁切范围；抠图、扩图或编辑结果保留输入短链与新版本关系，不覆盖原图、不将衍生图擅自升级为母版。
- 同一张就绪图可以复用；HTML 中每处使用仍需独立定位。替换前检查受影响页面，不能因同 URL 出现多次就未经授权全部替换。
- 不得编造资产 URL、来源、授权、生成记录或身份核验结果；缺短链就记录待补，不能用占位地址进入画布或正式 HTML。

## 3. 图片分工与尺寸适配

| 图片角色 | 图片负责 | HTML 负责 |
|---|---|---|
| 全局底面／背景组 | 实际露出的连续材质、复杂光场、场景或跨组背景空间 | 按职责范围置于对应内容下方，承接前景和可编辑文字 |
| 局部背景 | 本区域的环境、影像、纸层和局部表面 | 覆盖范围、与相邻区域及底面的衔接 |
| 独立主体 | 人物、商品、插画、物件的完整外观 | 使用就绪透明图片，等比摆放与叠压 |
| 复杂壳体 | 撕纸、织物、凝胶、异形轮廓等复杂外观 | 内部准确文字、定位与必要裁切 |
| 一体化 Hero | 按品类规则共同生成背景、主体与获准图内文字 | 作为整体图片层使用，不假称内部文字可编辑 |
| 独立艺术标题 | 仅生成品类允许且已准入的标题字形 | 抠图后独立摆放，其余文字保留真实 DOM |

规则矩形、简单线条、常规渐变、普通阴影和可编辑文字由 HTML/CSS 实现；需要真实摄影、复杂纤维、光学折射或自由形变时使用图像。背景服从已确定的视觉职责，不用普通色块替换影像或材质。按最终用途明确图片与 HTML 各自承担的内容和关系，组装前核对实际素材，避免重复表达或遗漏。

### 图片比例、取景与有效像素

- 先确认图片承担完整主体、结构证据、场景或纹理职责，再确定显示区域；不能把动作或结构关系压成无法辨认的窄条。
- Brief记录用途、焦点、图文关系及保护项；asset-manifest.json记录真实来源、处理、尺寸、版本与检查；显示框、定位和层级留在最终HTML。
- 生成前按已定构图选择工具支持的最接近比例和尺寸；参数不写入Prompt正文。工具返回后读取真实宽高，不用请求值代替结果。
- 每次处理后统一EXIF正常显示方向，再读取尺寸；裁切框、焦点和保护区使用同一坐标系。像素已转正时规范化方向标记，避免重复旋转。
- 验收分两段：源图→就绪文件，及就绪文件→每个HTML显示实例。源图与就绪图可以是同一文件，不为过流程强制后处理。
- 第一段的缩放必须使用同一比例因子；裁切只改变取景，扩图或留边只改变画布。禁止用指定宽高的非等比resize预先压扁主体。
- 比对处理前后的脸部、肢体、商品轮廓、Logo、包装、圆形和字形；就绪图与显示框同比分辨率不能证明此前没有烘焙变形。
- 第二段以最终引用文件的正常方向宽高W、H及未旋转内容框宽高B_w、B_h计算，不把旋转后的外接框当成图片比例。
- ratio_gap=max((W/H)/(B_w/B_h),(B_w/B_h)/(W/H))只表示图与框的比例差，不直接证明拉伸。
- contain使用s=min(B_w/W,B_h/H)，实际图像尺寸为sW×sH；cover使用s=max(B_w/W,B_h/H)，再由框裁掉超出部分。
- HTML必须以行内object-fit:cover或contain及明确框尺寸、object-position实现取景；背景图对应使用background-size和background-position，并核对实际定位区与裁切区。
- 常规百分比位置p_x、p_y下，图像偏移为((B_w-sW)×p_x,(B_h-sH)×p_y)；其他位置语法、变换和裁切按实际渲染解析，不能默认居中。
- 将可见框反向映射到就绪图，再结合源→就绪处理记录，检查最终保留的源图区域；同时检查父级overflow、clip-path、mask及前景遮挡。
- 合法cover/contain不得因框与图不同比例被误判拉伸；无fit保护的直接填充及后续变换须检查真实横纵缩放是否相同。
- 实际横纵缩放比超过1.01可报IMAGE_ASPECT_MISMATCH诊断；1.01仅为计算容差，不许可主动非等比变形。可见身份或几何变形无论阈值均失败。
- ratio_gap≤1.15优先检查轻量裁切；1.15–1.5加强构图与保护区复核；>1.5优先评估完整显示、扩图或获准重排。各档均不保证安全，也不自动要求重生。
- 焦点、面部、肢体、产品识别面、Logo、包装文字、动作、证据及必要上下文必须在最终取景中成立；安全区冲突时改取景、完整显示、扩图或获准重排。
- 正常图片可直接使用经验证的HTML等比显示或安全cover；不强制所有图片预裁，也不强制透明主体补成框比例。
- 只有固定取景、复用一致性或实际处理需要时生成裁片；保留父图、方向、裁切坐标、输入输出尺寸和新版本，不覆盖原图。
- 有效像素按最终可见取景与对应输出区域核算；contain按实际图像内容尺寸而非含留边的整个框核算，透明留边不计作主体大小。
- 1倍输出的有效像素不得低于对应显示像素；额外导出倍率按目标输出另验，主视觉可争取1.5–2倍余量。插值放大不算新增细节，不足记录IMAGE_LOW_RESOLUTION。
- 同图每个消费者分别检查；换URL、裁切、框尺寸、object-position、旋转、蒙版或输出倍率后，重查受影响的保护区、清晰度和相邻接缝。
- 参数通过仍须打开实际素材和完整预览，在正常阅读尺度核对焦点、身份、语义与清晰度；不能改尺寸记录或勾选通过标记掩盖问题。

## 4. Prompt 写作维度与规范

### 连续自然语言结构

按“总览句 → 分区扫描 → 关键关系 → 条件收束”写成可视化描述，不堆标签。
首句明确具体风格、可见特征和画面类型；主体篇幅按上到下、左到右或后景到前景逐区描述，最后收束统一材质、光线和保护要求。

| 维度 | 必须说清的内容 |
|---|---|
| 位置与构图 | 明确方位、相对占比、焦点、留白和裁切边界，不写“放在合适位置” |
| 元素类型 | 背景、主体、道具、壳体或装饰分别是什么 |
| 形态细节 | 轮廓、组成、姿态、朝向、材质与关键结构 |
| 内容 | 具体人物、商品、环境、动作和数量，不以功能名代替画面 |
| 状态 | 表情、动势、物体状态及需要表现的变化 |
| 关联关系 | 主次、尺度、接触、遮挡、穿插、指向与前后层次 |
| 风格 | 具体媒介、笔触、摄影或渲染语言，不只写“高级、电影感、8K” |
| 视觉工艺 | 主辅色职责、纹理、印刷、纸边、反射、明暗及统一处理 |
| 镜头与景深 | 摄影／写实／3D 的视角观感、机位、俯仰方位、焦点和清晰范围；平面图形用正投影、平面明暗，不强加景深 |

维度按图片实际需要自然展开，不另填九列表格；少量元素不为凑维度添加无关道具。镜头和景深服务识别，不虚化商品正面、关键动作或事实证据。

### 文字与参数边界

- 普通配图 Prompt 只描述画面，不写上屏标题、正文、价格、日期或 HTML 排版。
- 不写“无文字／无字／no text”等文字否定词，也不堆字母、数字、伪文字等排除词；需要留白时只描述空间位置与低纹理状态。
- 已有包装文字与 Logo 是身份内容，必须保留，不能因普通配图规则删除。
- 一体化 Hero、Logo 主标／组合标和独立艺术标题，仅在主路线及品类明确允许时包含文字。逐项写准确文案、字形、字重、颜色、特效、层级、位置与断行；不得自行扩大准入范围。
- 独立艺术标题读取 [艺术标题 Prompt 与材质库](art-title-prompt-library.md)，不能按 H1 层级批量生字。完整终图仍沿纯生图流程。
- HTML 坐标、DOM ID、层级值、CSS 属性与模板名不进入 Prompt；把必要组装意图转成画面要求，例如主体朝向、轮廓完整性、负空间和安全边距。

### 风格与质量

- 以当前 Visual 为依据，选择一种主媒介、按需配一种辅助工艺，不把玻璃、金属、纸张、黏土和水彩堆在同一素材上。
- 素材继承 Brief 中与其用途相关的视觉关系和参考主次；系列的一致与变化按原设计目标处理，不因通用质量描述或实现便利改变已确定的风格。
- 平铺纸面、织物与图形使用稳定明暗；摄影／3D 使用可信主光和接触关系。不同时要求互相冲突的光向，不默认追光、光晕、暗角或轮廓光。
- “放射构图”只表示平面对象、实色线条、纹样或信息单元围绕焦点排列，不表示放射性光线。除非当前品类 Visual 和用户明确要求同时授权光效，不得把放射、爆发、能量、庆典、隆重、红金、金色、丝绸／绸缎改写成顶部光源、光束、太阳芒、耶稣光、舞台追光、体积光、闪电／雷霆光纹或镜头光晕。
- 低饱和、灰调、深色均是可选表现，不覆盖品牌色或已确认参考。暗部保留细节，纹理不得污染文字安全区。
- 质量描述落到清晰轮廓、准确结构、完整肢体、真实材料、自然边缘和干净渐变，避免空泛赞美词。

## 5. 背景图 Prompt

### 5.1 背景职责与生产顺序

- 作品级背景门禁优先：整页和连续背景组不得以无变化纯色规避主题所需的纹理、肌理、渐变或空间关系；CSS 渐变与原生材质可直接兑现职责，不强制生图。稳定纯色仅用于有明确信息职责的局部信息区，且须说明增加纹理会削弱主体或版式；不得把一个连续背景组拆成多屏或多容器后逐段套用纯色例外。
- 通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图默认执行无明显光效底图：正向描述先写平面色面、非放射性渐变、纹理／材质、均匀漫射明暗、接触阴影和低干扰区域，再明确无可辨认光源。若 Brief 没有逐项记录用户授权的光效例外，Prompt 不得出现顶部聚光、放射光、太阳芒／耶稣光、舞台追光、体积光、闪电／雷霆光纹、镜头光晕、辉光背景或“从顶部照射”等描述。
- 先读取 Brief 已选图文关系，按连续内容组或独立页面确定生产单元，再分配全局底面、组级背景与局部覆盖；屏或页不自动成为生产边界。长图和详情页采用满幅场景时，将商品／人物、环境与供 Coding 排字的空间作为同一画面生产，不把“背景”自动解释为空纹理，也不另生主体图窗。自然场景已有的光影、材质和空间变化可承担底图职责，无须额外叠纹理或渐变。
- 同一背景职责只由一个层级承担，不得重复生产或烘焙到全局底面、背景组与局部覆盖；完全被遮挡且无其他职责的底图不生成。
- 只有实际露出、跨组连续、承接留白或统一材质时才生产相应图片底面；CSS 足以兑现职责时不生成图片。工具不能一次输出所需连续范围时，按真实消费区域扩图或拼接，不能拉伸补齐。
- 背景 Prompt 写画面、材料和低干扰区域，不要求生成后续 Coding 文案。满幅场景按真实文案试排需求说明主体尺度与位置、文字区方位与容量、可接受的明暗和细节密度、最终取景及延展边界；文字区是场景内可排字的空间，不生成空白卡片或占位文字。获准一体化终图的背景描述合入整图 Prompt，不删掉该终图必须生成的准确文案。

### 5.2 纹理、肌理与渐变选择

先匹配主题与媒介，选一个主材质或色场，按需加入一种辅助工艺。现成背景先检查适配性，不强制重新生成。

| 表现 | 可选素材语言 | 需要描述 |
|---|---|---|
| 纸张与印刷 | 纤维纸、网点、墨迹、套印 | 纤维／点径、疏密、渗染、套色与正文区低干扰；作为展开底图时保持平整连续 |
| 织物与纤维 | 亚麻、牛仔、帆布、绒面 | 经纬方向、纱线尺度、起伏、绒毛与哑光 |
| 自然表面 | 水波、木纹、石纹、沙脊 | 起点、走向、尺度、有机变化与真实反射 |
| 半透明材料 | 磨砂、蜡纸、薄膜、亚克力 | 透色区域、羽化、颗粒、厚度与克制折射 |
| 工业材料 | 拉丝、压纹、氧化、液态金属 | 主结构、粗糙度、反射范围与暗部细节 |
| 渐变与雾化 | 连续色场、柔雾、点阵 | 颜色起止、方向、范围、过渡、疏密；避免色带和高亮干扰 |

纹理尺度按最终阅读大小选择，不能全页同强度撒噪点；光感服从材质，平铺面不强加棚拍追光。简历、菜单、信息图优先低对比表现；公告底图继续遵守对应 Visual 的无明显光效规则。红金、金色与丝绸只定义颜色和材料，不能推导为舞台帷幕、顶部亮点或汇聚式光束；需要褶皱时使用均匀材质明暗，避免所有褶皱朝顶部亮点收束。

### 5.3 完整背景 Prompt 编译语法

具体风格与背景职责 → 主材质／色场与颜色 → 起点和延展方向 → 尺度与疏密变化 → 分区状态 → 边缘与微观表现 → 合理明暗 → 低干扰区与连续线索。
此语法用于材质／色场底图。场景型按主体与环境关系 → 镜头与主体尺度 → 光向与空间 → Coding 文字区与保护对象 → 最终取景及连续边界编译，不为套材质语法删掉主体。渐变型写颜色过渡与范围，不为套语法虚构纤维；材质型写真实表面，不用“高级纹理”代替观察量。比例、像素尺寸仍只放工具参数。长图与详情页的满幅资产在采用前，用实际文字和目标裁切预合成，核对主体可见尺度、可读性与覆盖范围；不合格按既有后处理、编辑权限或变更流程处理，不在 HTML 阶段自行改成图窗。

> 编辑式纸本背景，浅灰纤维纸贯穿整页，青绿色墨迹从右下沿边缘向上展开，细小网点由密到疏融入纸面。上部与中左区域平整、低对比，底部保留轻微纸纤维和柔和色阶过渡；材质在各区域连续，不出现重复拼接边。均匀漫射明暗，仅纸层交接处有轻微接触阴影，整体清晰、克制。

编辑背景时补充：图1是哪张原图、保留哪些材质与构图、只向哪里扩展或改变什么；不借背景编辑重画人物、商品、品牌或事实。

## 6. 独立素材与图片编辑

### 独立素材 Prompt

明确主体、数量、姿态、轮廓方向、完整范围与安全边距；横长／竖长构图靠姿态、镜头或排列适配，不靠拉宽压扁。

> 手作纸本与剪纸风格的独立植物枝条，深绿叶片沿右下向左上舒展，疏密有序，纸边细纤维清晰。完整保留叶尖与枝端，四周留出余量，均匀柔和明暗。单一高反差纯蓝背景，主体与背景边缘清楚分离，只保留一组枝条。

图片进入 HTML 前，执行 [图片处理与采用版本](../../../workflow/image-asset-treatment.md)：按每个使用位置判断背景职责、必要处理与采用结果；已有有效透明不重复抠图，完整场景不强制透明化。具体操作的执行阶段与记录位置见本文后处理矩阵。

### `image_edit` Prompt

- 按“保留项 → 获准改动 → 区域 → 融合关系 → 完整性”描述，不把局部修改写成整图重建。
- 当前成品与身份母版分别传入并注明职责；五官、商品结构、包装文字、Logo、颜色和关键部件按授权保持。
- 扩图写原图保留区域、新增方向与新增内容，新增区继承透视、纹理、光线和景深；不能用拉伸代替扩图。
- 结果与原图逐张对照。身份漂移版本不得继续作为母版衍生；保留原结果及问题记录，按交付门禁处理后再决定修正。

## 7. 生图后直接交付与回写素材记录

### 直接交付后回写素材记录

1. `image_gen`／`image_edit` 返回每张图片后，先按公共门禁直接交付，再将真实返回的原始图片短链写回 `asset-manifest.json` 的对应素材记录，保留用途、Prompt 和参考输入；不得等整页完成才统一补写。
2. 在同一条目下记录版本与实际状态：已生成、待检查、已采用或未采用及原因。坏图也保留原始短链，不能隐藏或覆盖历史结果。
3. 抠图、裁切、扩图等产生新结果时，将处理后短链追加到同一条目，说明来源和处理内容；检查通过后明确“HTML 采用此版本”。不能把原始带底图误作透明成品。
4. 记录实际传入的 Workspace ID（Mobile 无 ID 时如实记录）、工具结果句柄和`RichMediaCard` 单项交付成功或失败状态；不以媒体 Item ID 或 `+get` 回读作为图片直交准出条件。先有短链或工具预览不等于已交付或已通过视觉检查。
5. 同一底图跨页复用时，各消费者引用同一已采用短链并说明复用关系；并行结果按 `asset_id` 逐项回填，不能按返回时间猜对应页。
6. 保存同一份素材清单。Brief 只在图片职责、画面目标、关系、保护或禁用项等设计意图改变时更新，不复制生产状态、结果短链和版本历史。

自然语言记录示意（实际记录必须使用真实返回值）：

```text
第二屏背景：浅灰纤维纸，右侧青绿墨迹；左侧低干扰。
参考与 Prompt：素材记录中的真实输入和已编译 Prompt。
原始结果：工具返回的真实图片短链；已生成。
处理后结果：扩图工具返回的真实短链；承接第一屏纸纹。

```

### 单项交付与画布登记边界

- `image_gen`／`image_edit` 调用与结果严格执行 [交付门禁](../../../workflow/image-generation-delivery-gate.md)：按当前环境处理 Workspace ID，主 Agent 使用 `RichMediaCard` 直接逐项交付，串行依赖与固定并行批次按该门禁汇合；失败停止依赖步骤，有缺陷的成功结果也不隐藏。素材记录回写不得推迟直接交付。
- 图像工具结果不重复上传或创建 IMAGE Item，不在直接交付前插入媒体回读；默认 Canvas 在本轮结果全部直交后按 [资产目录工作流](../../../workflow/canvas-asset-organization.md#3-产物完成后的强制目录整理) 读取真实对象并更新 path。Mobile 不执行 Canvas 操作。
- 用户上传、本地处理／导出及其他工具产物按各自协议处理。只有确需显式登记的资产才执行 [IMAGE 协议](../../../items/image.md) 与 [CLI create](../../../cli/create.md)，提供真实尺寸、稳定绝对 path、标题、摘要和有效资产 URL；内容变更创建新版本，update 不替换图片内容。
- 已有工具短链不得为交付下载、复制、重传或换链；只有确需上传且没有可用短链的独立本地文件才按上传协议取链。用于 HTML 的采用版本必须有真实可用短链；缺失时停止该素材的组装，不伪造 URL，也不因此隐藏可直接交付的原始工具结果。

## 8. 质量检查与进入 HTML

### 逐图检查

实际打开最终图片，不能只看 Prompt、工具成功状态或缩略图：

- 身份、商品关键结构、事实及用户锁定的数量、动作和继承项与已确认依据一致；获准变化的场景、动作、构图和组合关系符合原 Brief，不新增虚假品牌、证据或无关主体。新配景按已确认画面目标验收，不据此推断或补造商品事实。
- 在最终版面核对构图、主体大小、负空间、裁切、图文关系与原 Brief 一致；最终阅读尺寸下焦点、文字和材质可辨，组内光影与视觉语言协调。单张清晰、抠图干净或工具成功不等于配图已兑现方案；组装前先核对素材条件，最终效果在实际版面复核，不提前宣称通过。
- 实际比例与有效分辨率满足显示要求，无非等比拉伸、糊脸、压缩块或过度锐化。
- 底图有纹理／肌理／渐变，接缝连续，阅读区低干扰；系列材质、色彩与边缘语言一致。
- 独立透明素材在浅色和深色底上检查 Alpha、白边、色边、毛发、内部孔洞与误删细节。
- 获准图内文案逐字检查；普通配图意外生成文字也按图内文字问题记录。

AI 图内错字、缺字、伪文字或可读性问题：直接交付后在素材记录标记 `delivered_with_text_issue` 并等待用户明确要求，不自动重生或用 DOM 覆字掩盖。承担准确内容的错误文字资产暂停下游使用；原生 DOM 文字仍须正常修正。
非文字的身份、结构、比例、低清或风格失败：保留已交付版本与问题，按原 workflow 修正最小失败项；修正版继续透传 Workspace ID 并直接交付，不无限重试。不能以“已交付”冒充“可组装”。

### HTML 资产使用

1. 只采用来源与版本可追溯、生成结果与记录一致、内容及质量检查通过，并已在当前环境实际交付的版本。图像工具结果须通过 `RichMediaCard` 逐项交付，默认 Canvas 的产后目录回读不作为媒体准出前置条件；Mobile 环境不调用 Canvas，同样逐项完成 `RichMediaCard` 交付，并记录 `delivery_environment=mobile_direct`、源版本、生成结果和交付状态。从素材记录读取已采用短链并与实际资产核对，不从记忆、旧 Prompt、Brief 或预览地址取图。
2. 使用真实 `<img src="…">` 或背景引用；源地址指向最终就绪资产，不能使用 Item ID、图片名称、占位地址或本地临时路径冒充 URL。
3. 按 [HTML 组装](../../../workflow/html-assembly.md) 与 [最终 HTML协议](../../../html/coding-rendering.md) 在完整固定画布文档中摆放，CSS 展开到元素行内；具体几何与依赖回填既有 最终 HTML，不要求用户 Brief 填坐标表。
4. 用独立 DOM 标记定位各图片实例；实际存在的全局底面或背景组置于其职责范围下方，局部背景、主体和文字按已确定关系叠放。同图复用不重复生成，但每处都验证尺寸、裁切与遮挡。
5. 普通定位、旋转、等比缩放、`object-fit`、`object-position`、规则蒙版、渐变与已验证滤镜留在 HTML；真实抠图、扩图、复杂主体形变与光学烘焙在使用前完成，并回写新资产短链。
6. 准确标题、正文、数据与标签保留真实可编辑 DOM；只有品类明确准入的图内文案随图片整体使用，不假称可独立编辑，也不重复覆盖一份文字。
7. 更换图片、裁切或画幅后重新检查邻近文字、主体边界、透明边缘和接缝；不得改记录或缩放整张成品掩盖错误。
8. 按 [HTML 检查](../../../workflow/html-validation.md) 检查源码和实际预览，确认资源加载、比例、层级、文字安全区与长图完整性；不可预览时明确未验证范围。
9. 默认 Canvas 环境中，图片 Item 登记不等于 HTML 已完成；完整 `.html` 经 `FileBatchUpload` 上传后，按 [HTML Item 协议](../../../items/HTML.md) 创建单个顶层 HTML Item 并 `get` 回读，原始 HTML 不通过 `present_files` 直接交付。Mobile 环境不执行 CLI 或 Item 步骤，按 Mobile 规则使用 `RichMediaCard` 交付实际媒体，HTML 预览仍走 CDN＋Markdown。

最终核对：Brief 的图片用途、Prompt、原始与采用短链、画布 ID、实际 HTML 引用和检查结果可以相互追溯；没有误用旧版、缺链、重复生成或未授权替换。

### 参考输入与版本绑定

在现有槽位／资产记录中保留所用源图锚点及版本、相关区域、使用方式和目标对象；多图逐项记录职责，不把身份图与风格图压成单一来源。真实锚点与工具传图规则沿用 [用户视觉锚点](../../../workflow/canvas-asset-organization.md#4-用户上传的初始视觉锚点)，具体交接如下：

正式素材按最终显示尺寸与裁切检查清晰度；有意景深／背景虚化不等于主体低清，仅作风格参考的图不直接充当正式素材。低清先区分身份依据是否可辨与成品像素是否够用：可辨的身份可作为参考编辑依据，按目标画面处理获准区域；不可辨的文字、结构与材质不能猜造为事实。按目标选择保真增强、授权重制、调整画面或补充来源，不默认整套等待高清图，也不以插值放大冒充细节恢复；画面调整须回写原 Brief 并遵守既有确认要求。未解决的素材不得准出或进入正式组装。增强以实际源图为 image_edit 目标，尺寸写工具参数；保留身份、构图、准确文案与接缝，不猜补不可辨认的文字或结构，不重绘用户锁定素材。修后对照原图检查目标尺寸及局部细节，通过后绑定新版本；尺寸增大或锐化不代表恢复真实细节。

1. 调用前，从本槽位绑定解析实际图片；区分编辑目标、身份参考与风格参考。画布 Item ID 不是通用传图参数，须按当前工具声明转换为可接受的图片输入，并核对输入内容、版本和来源。裁片保留父图与裁切坐标，不能只声明“参考了图 2”。
2. 在既有调用记录保留实际图片输入与锚点对应、输出版本及目标槽位；仅分析的参考保留证据引用，不虚记为工具输入。`source_uri` 保持原义，多来源及多步处理通过所引用的输入记录追溯，不只留最后一张参考。
3. 并行生成 N 个同源编辑版本时，每个版本分别编译 Prompt 并独立调用一次 `image_edit`。单参考变体每次仅传入同一张已确认参考图；需身份母版的复合编辑每次固定传入同一当前成品作为编辑目标、同一独立母版作为身份参考，输入版本、顺序与授权职责保持一致。按 [交付门禁](../../../workflow/image-generation-delivery-gate.md) 执行同一预先锁定批次，不混入无关参考，不以一次多结果调用替代，也不把并行结果串作输入；工具无法同时接受必要输入时说明限制并停止依赖步骤。
4. 后处理结果以新 `asset_key` 绑定最终元素，回指输入资产与操作；同图多次摆放共享就绪资产，每个实例保留独立元素 ID 与几何，平台返回 ID 在写入后映射。HTML 使用最终就绪资产的真实地址，不使用参考 ID、槽位名或旧版本地址。
5. 共享复用以同一已准出版本为单位，不限制必要的返修或变体；换源、重生、裁切、去底或替换版本时，使依赖的采样、主体边界、文字安全区与接缝证据失效，按新结果重查。原参考证据不被衍生结果覆盖。

### 2.2 后处理与组装操作矩阵

| 操作 | 应在何时完成 | 在哪里记录 | 最终 HTML 表达 |
|---|---|---|---|
| 抠图 `cutout` | 使用前先按去底结论判断；仅“需要去底”执行真实抠图，已有有效透明或保留完整背景的不重复处理 | 原 asset-manifest.json 的 purpose 或使用说明保留结论与理由，沿原记录回写输入、输出、Alpha、版本及边缘检查结果 | 仅引用核验通过的就绪版本；透明位图或无底 SVG 按原图片契约使用，不新增 cutout 属性 |
| 等比裁切 `crop` | 固定取景或复用一致性需要时生成新裁片；否则允许经验证的 HTML 安全裁切 | asset-manifest.json 记录父图、方向、裁切坐标、输入输出尺寸与版本 | 行内 cover／contain 及 object-position，按最终实例验保护区；不得非等比拉伸 |
| 扩图 `outpaint` | 源图与槽位比例不兼容但主体可保留时，入库前生成新区域 | 原 asset-manifest.json 记录扩展方向、保留区、新生成区、结果尺寸与版本 | 使用扩图后的新 IMAGE 资产 |
| 旋转 `rotation` | 普通整体旋转在组装阶段；旋转会改变内部透视/运动模糊时在生成或预处理阶段 | 普通旋转直接写最终 HTML；烘焙旋转的输入、处理事实、输出与版本写原 asset-manifest.json | 普通旋转写入行内 `transform:rotate(...)`，并按旋转后外接框避让 |
| 普通渐变 | 组装阶段，且只限 浏览器支持的线性／径向渐变 | 方向／中心、半径、色标和作用范围直接写最终 HTML 的实际声明 | 元素行内 `background:linear-gradient(...)`／`radial-gradient(...)`，或内嵌 SVG 的渐变定义；不生成渐变位图 |
| 复杂渐变/光场 | 先核对当前模板与目标渲染能力；已验证的 CSS／SVG 渐变、纹理、玻璃和混合留在 HTML，只有无法稳定实现的成像效果进入生成／预处理 | 图片生产写原素材清单，代码效果直接绑定 HTML | 不因效果名称重复生图；准确文字和规则图形保持独立层 |
| 鱼眼 `fisheye` | 若鱼眼影响真实场景透视、主体轮廓或镜头空间，在生成 Prompt 中直接要求；已有图后加鱼眼则入库前烘焙 | 原 asset-manifest.json 记录中心点、强度、作用范围、保护区、输出尺寸与版本 | 当前 HTML 无鱼眼字段，只能使用烘焙后的 IMAGE；不得伪造属性 |
| 自由形变/透视形变 `warp` | 生成阶段直接形成目标视角，或入库前烘焙；不能留到 HTML | 原 asset-manifest.json 记录烘焙的四角／网格、透视方向、强度、保护区、输出尺寸与版本 | 普通 `rotate`／`skew`／`perspective` 可用行内 CSS；会改变主体真实透视或像素内容的 warp 仍须在生成或预处理阶段烘焙 |
| 蒙板 `mask` | 复杂显隐、异形裁切或穿插在入库前烘焙；简单矩形裁切通过正确源图和槽位处理 | 烘焙蒙版的轮廓、作用对象、保留／删除区、羽化、输出 Alpha 与版本写原 asset-manifest.json；代码蒙版直接写最终 HTML | 简单裁切可使用行内 `clip-path`／`mask`；复杂羽化或高风险主体边缘优先使用处理后的透明图片或明确的图层遮挡 |
| 位置与层级 | 最终组装阶段 | 最终 HTML 的真实 DOM 结构、定位与层叠声明 | 行内 `left/top/width/height/transform/z-index` |

所有预处理输出都视为新资产版本，在原 asset-manifest.json 记录输入、输出、实际处理参数、尺寸、Alpha、版本与回退；QA 证据归既有检查输出并关联对应版本。实际旋转、渐变、位置与层级直接落实到最终 HTML，不另建组装 schema，也不将全量实现值复制到 Brief。浏览器已有的 `transform`、`filter`、`mask`、`clip-path` 等能力必须使用合法 CSS 语法并写在对应元素的行内 `style` 中；`fisheye`、像素级 `warp` 等非标准效果不得伪装成 HTML 属性，须在生成或预处理阶段烘焙。

### 光照与相邻场景的编译

在既有 lighting 中区分受光效果与可见光束：普通桌面、纸面、工作室摄影描述光源面积、受光面的明暗变化、阴影软硬与反射位置；“柔光、窗光、氛围”不自动展开为光柱、斜向亮带或放射光。可见光束只在已选舞台、烟雾、科幻或参考确有该机制时生成，并限定位置与强度；平面色场不解释成摄影打光。例如工作台可写“大面积窗外散射光照亮桌面，明暗缓慢变化，纸张保留细微纹理，空气清透”，而非只写“暖色氛围光场”。

生成前按最终使用方式区分连续场景、独立图窗与有意换章，并回写既有槽位和交接记录。同一空间把标题净空、主体、桌面／墙面和跨区对象联合构图，优先同一场景图或基于实际母版连续扩展；独立图窗保留完整取景边界，同组比较统一主体尺度、机位口径与后期；换章允许清楚硬切，不强求物体跨界。透明主体按使用前结论处理：需要去底的实际抠图后验边，已有有效透明的不重复抠图；不将带实景背景的矩形照片声明为透明主体。

需要分开生产连续素材时，将实际前图／母版作为编辑依据，在 continuity_cues 写明来源版本、交接区域、透视、主体与纹理尺度、光向和景深；同色提示词不能代替同源连续，连续扩图不按独立变体并行生成。先用最终素材、实际裁切和文字预合成一组相邻区域，再批量组装：结构或透视不相接回到扩图／构图，局部色阶差异才交给 HTML 融合。蒙版只作用于存在可融合后景的边缘，文字、主体与接触面独立保护；背景连续且已预留低细节融合区时，可按最终边缘采样色扩大渐变或扩图范围；禁止的是用黑幕、白雾或渐变掩盖主体、透视和接触面的结构断口，不是限制背景渐变只能很窄。生成时保护文字、Logo及主体识别区，向衔接方向提供足够可重叠背景，实际范围由两屏联合试排确定。具体组装与最终读图沿 [HTML 组装](../../../workflow/html-assembly.md#素材就绪后的合成与几何复核) 和 [视觉复核](../../../workflow/html-validation.md#3-视觉与平台复核)，原准出记录注明本次验证的素材版本和两侧区域。
