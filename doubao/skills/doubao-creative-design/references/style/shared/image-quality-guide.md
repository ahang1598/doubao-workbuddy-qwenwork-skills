# 共同图像质量与身份原则

供 pure-image 与 ai-coding 的图像生成／编辑使用，不决定路线、不新增工具参数或交付步骤。`image_gen`／`image_edit` 的所有成功结果先按 [交付门禁](../../workflow/image-generation-delivery-gate.md) 满足当前环境的 Workspace ID 规则并使用 `RichMediaCard` 直接逐项交付，再验收；问题版本也不能静默丢弃。

## 调用前

- 确定角色：完整终图、背景、独立主体或其他素材。pure-image 的 final_image 使用最终画幅、可见文字和参考角色，不要求 asset_slot、assembly_spec、HTML 或抠图。ai-coding 素材继续读取本路线的素材 Prompt 指南。
- 冻结目标比例、像素需求、主体、焦点、允许裁切区和必须保留内容。不能把写入 Prompt 当作工具已支持该尺寸的证据；只有工具真实参数和输出可证明能力。
- 先实际查看并区分用户图片的身份、风格、版式和证据职责。既有真实人物／产品／Logo 由用户原始资产或已确认母版保持身份。从零创建的新 Logo／IP 首张核心图没有旧母版，按原创建规则执行；衍生前再确认身份。
- 需要保持身份的生成／编辑调用，必须把身份原图传入工具真实图片输入，并核对输入与记录的母版一致；只在 Prompt 提及、只记录路径或只传风格参考均不成立。原有包装文字、Logo 与标签属于身份内容，保持原貌；“不生成文字／Logo”指不新增未经授权内容，不能用它擦除真实产品标识。
- 编辑已有成品时，当前成品是 edit target，核心母版是 identity reference。除非在编辑母版本身，不用母版替换当前成品；工具无法接收必要输入时说明能力限制。
- 可见文字先按 [内容与事实边界](content-truth.md) 整理，再冻结进 Prompt。纯图可以包含完整传播文字；普通分层素材才按其职责留出无字区域。

## 输出验收

- 比例：核对输出真实宽高与最终需求，不能非等比拉伸。扩图须生成新区域，裁切不得损失必保内容。
- 有效像素：核对原始／裁切后的有效分辨率，不将插值放大计作新增细节；无法满足时如实说明，不虚报高清或目标尺寸。
- 视觉：检查主体结构、光向、透视、材质、焦点、清晰度与系列一致性；没有查看真实图片不能宣称检查通过。
- 身份：对照母版检查轮廓、包装、Logo、颜色及本次未授权变化。
- 文字：核对冻结的可见文字。AI 生成文字错误、字形异常或不可读时，沿原门禁记录 delivered_with_text_issue 并等待用户明确修改，不自动重生或 Coding 覆字；原生 DOM 文字仍正常修正。
- 素材专属：只有需要抠图或组装的资产才检查 Alpha、槽位与可组装性。完整终图不因没有独立文字层或透明底判为失败。

## 失败处理与路线保持

身份、比例或结构等非文字问题按原 workflow 的修正与停止条件处理。连续失败沿用已选路线：pure-image 仍通过图像生成／编辑修正，ai-coding 沿本路线修正素材或布局；不得因失败自动在 pure-image、ai-coding、pure-coding 之间切换。保留原有停止条件，不无限重试，不把失败资产标为合格。工具能力不足或达到停止条件时保留失败状态并说明具体限制，用户明确切换方式后才重新路由。

## 电商完整位图拼接例外

pure-image 电商沿原 ref 的逐屏／模块生成和完整位图拼接规则，拼接不等于分层文字排版。其他品类不自动获得此例外；每张输入及拼接产物按原交付门禁处理。此文件不改变拼接、上传或 CLI 的实现与时序。
