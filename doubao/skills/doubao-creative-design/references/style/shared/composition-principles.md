# 构图规范与视觉重建描述

用于海报、商业视觉、品牌 KV、封面、简单图形、网页首屏、信息图关键屏和长图关键画面。目标是从整体到局部确定空间关系，并将构图准确转换成可编码的布局或可直接使用的图像生成描述。

## 选择顺序

1. 判断图像用途、画幅、媒介与信息密度。
2. 选择一种主构图；只有确实强化动线或层级时再加一种辅助构图。
3. 估算主体、背景、文字区和留白的比例。
4. 写出视线入口、视觉焦点和视线出口。
5. 再确定主体视角、次视觉、光影、文字、色彩和材质。

海报和简单视觉默认避免安全但平庸的正中构图。仅当品牌标识、仪式感、对称物体、图标、空状态或用户明确要求对称时使用居中，并通过尺度、留白或前后景避免呆板。

## 背景与信息层的正向关系

“避免在背景上覆盖一组卡片”只是退化边界，不是设计方法。背景、主体、标题、信息场和装饰必须通过至少一种可观察的主关系组成同一画面；长图或多章节作品还应建立跨区关系。关系必须在 Brief 中以人类可理解的对象和效果说明，并在最终 HTML 的真实 DOM 结构、层级和样式中兑现，不能只存在于风格描述里。

| 关系类型 | 设计职责 | 可执行方式 |
| --- | --- | --- |
| 构图关系 | 建立主次、空间和共同焦点 | 共轴、遮挡、穿插、破框、承托、避让、共享负空间、标题沿主体轮廓排布 |
| 装饰关系 | 强化阅读动线和视觉家族，而不是填空 | 装饰沿路径延伸、贴合边缘、连接标题与主体、重复同一锚点、参与框架或裁切 |
| 过渡关系 | 让相邻章节发生叙事换挡和视觉接力 | 主体跨区、材质连续、路径延伸、裁切接力、尺度变化、光场或色彩换挡 |
| 空间关系 | 让独立资产真正进入同一场景 | 统一透视、统一光向、接触阴影、前中后景、共享地平线或空间基准 |

优先从内容责任中寻找关系：产品轮廓可以为标题提供遮挡，人物视线可以指向行动入口，液体、道路、线缆或纸边可以成为章节路径，摄影负空间可以直接承载事实。不要先生成一张自足背景，再寻找可以盖上去的卡片位置。

关系验收回答两个问题：

1. **去掉背景后**，信息层是否失去明确的轴线、空间、承托或动线依据；
2. 去掉信息层后，背景是否仍能看出为标题、主体、事实或下一章节预留的负空间和进入方向。

若两者互不影响，或唯一联系只是颜色接近，应视为机械叠放，返回 Brief、构图或素材阶段重新建立关系。容器确有信息聚组职责时仍可使用，但它必须参与上述关系，不能作为与背景无关的默认覆盖层。

## 从参考或策略形成 Brief

构图词不能直接成为 Brief。分析参考图或已选场景策略时，先提取能决定成品第一印象的 `3–5` 个机制，再把每个机制绑定到区域、元素和资产；未完成绑定，不得声称“已参考”或进入实现。

长图的段高与图文比例需说明测量对象和分母：图片框不等于主体可见轮廓，字框不等于字形墨迹；重叠图文的占比不要求相加为 100%。同类内容允许有依据的重复，用焦点、疏密和章节职责建立节奏，不以换版数量代替设计。Coding 的数值投影与回读核对见[长图比例规则](../coding/composition-layout.md#长图段高图文比例与实际兑现)。

对于 AI + Coding，构图绑定先按品类确定生产单元：社媒长图 Hero 整体生成；其余分层区域拆分资产与代码元素，独立艺术标题只用于首屏／首图或该独立图片唯一最重要的大标题，同一图片默认最多一个，其余文字由可编辑 DOM 承担。每张图片在轻量素材清单中记录用途和消费区域，所有 DOM 文字的字体从字体库解析后再进入 HTML 组装。

AI + Coding 构图需要 `image_generate`/`image_edit` 时，建立对应素材记录并按 [素材 Prompt 规范](../coding/ai-coding/asset-prompt-guide.md) 编译：工具支持的画幅比例与像素尺寸通过调用参数传入并记录于素材清单；最低有效像素作为素材验收要求，显示 fit 模式与取景落实在最终 HTML，不伪造工具参数。Prompt 只描述主体相对位置、焦点、负空间、裁切边界及保护要求。纯生图沿自身完整终图 Prompt 规则，不要求 Coding 素材清单。摄影、插画和生成素材只允许等比缩放；取景无法保全主体和保护区时，在授权范围内重构图或扩图，不以拉伸适配。

卡片／信息容器的关系由视觉系统与内容决定：技术卖点、平行比较、参数和编辑秩序可以采用规则网格或同轴序列；需要动作、破框或不等权关系时再选择错位、倾斜、叠压、路径等手法。不能以几何整齐本身判定退化；应检查商品／图像的视觉分量、文字层级、容器职责和整体节奏，避免无差别小图卡片堆叠。采用 Coding 时在 Brief 中说明可见关系与保护要求，实际位置、角度、层级和文字安全区在编写 HTML 时确定；纯生图只把这些关系转为视觉描述。

### 容器内容框、间距与顶边

不要把文字框直接贴到容器边界。每个含文字容器在 HTML 中建立真实外层容器和内容区，通过宽高、padding、gap、对齐与溢出策略控制关系；这些值直接属于最终 DOM 与行内样式，不另建几何契约。

- 按 [Coding 容量规则](../coding/composition-layout.md#容器内容框间距与顶边)，先在可用宽度下用准确完整文案、实际字体与字号试排并测量完整文字组。未锁高时由内容确定高度；用户要求固定等高卡片或已锁定尺寸时保留该约束，先在可用区域内重排，不靠持续缩字或挤掉必要留白迁就高度。
- 左右内边距通常不小于正文 `1em`，上下内边距通常不小于正文 `0.8em`；小标签可降到 `0.6em`。这是起始尺度，最终仍按视觉重量、描边厚度和材质边缘加大。
- 标题与正文之间通常保留标题字号的 `0.35–0.65` 倍；正文与来源、标签之间通常保留正文字号的 `0.55–0.9` 倍。不得依赖换行空格制造间距。
- 对齐使用可见边界：文字按字形墨迹顶边、图片按非透明像素边界、壳体按实际外轮廓对齐，不以带透明留边的位图画布边界冒充视觉顶边。
- 同轴元素先做几何对齐，再在实际渲染中按需要用 `transform:translateY(...)` 做约 `0.03–0.15em` 的光学校正；实际位置与字框尺寸使用 CSS 布局和 width／height，框内对齐使用 Flex／Grid。双轴居中可用 `display:flex;align-items:center;justify-content:center`，多行文字另用 `text-align:center`。字框先容纳完整文字，不用位移或对齐掩盖裁切。
- 完整文字组四向墨迹必须位于 `content_box` 内。溢出先调整断行与组内排布；未锁定的容器仅可在允许的父容器和画布余量内增高，并联动检查邻组净距。改变锁定尺寸或缩短文案必须取得用户明确授权，准确文案不得擅改；不允许裁切、遮盖或持续缩小字号。

### 图像、卡片与背景的融合处理

先确定边界是否应该被看见，再选择效果；每项效果必须记录作用对象、区域、方向、颜色/透明度、层级和取消条件。

| 观察到的关系 | 应增加的处理 | 不应增加的情况 |
|---|---|---|
| 文字与背景局部混淆 | 按[文字与背景的对比处理](#文字与背景的对比处理)选择字色、字重、移位、轻投影、描边或局部调光 | 对比已经足够时不添加承托；不得默认黑灰蒙版或统一压暗整图 |
| 照片需要与相邻区域连续 | 先评估透视、尺度、纹理与接触关系是否连续；在授权范围内优先复用共享场景或扩图，仅最终裁切后的安全空场可用图片 Alpha 衔接，遵守[渐变与文字安全区](#渐变与文字安全区)及[合成复核](../../workflow/html-assembly.md#素材就绪后的合成与几何复核) | 结构不相容或无安全空场时返回素材／获准重排；明确图窗保留边界，不默认用短同色色带、黑幕或白雾遮缝 |
| 图片被定义为画框、窗口或证据卡 | 保留有意的图窗边界；确需分界时才用细描边，只有真实深度或接触关系才用与光向一致的阴影 | 边界已清楚时不自动加边或投影；全幅背景、无边界照片不统一套框 |
| 卡片表面与背景明度接近 | 使用 `1` 条克制描边、内高光或微小色差建立边缘 | 已有明显色差、叠压或厚度关系 |
| 透明/玻璃/凝胶壳体需要厚度 | 使用 IMAGE 壳体自身的材质边缘；Coding 只补准确内容和必要高光线 | 用普通半透明矩形声称实现复杂折射 |
| 主体需要破框、穿插或局部显隐 | 使用透明 IMAGE、合法图层遮挡，或入库前烘焙复杂蒙板 | 用蒙板隐藏错误裁切、溢出文字或错误结构 |
| 区块需要光向、空间深度或密度换挡 | 使用有明确方向和停靠点的线性/径向渐变 | 无构图职责的随机彩色渐变 |

同一区域通常只保留一个主融合手段和一个辅助边缘手段。例如“对比字色 + 细描边定义图片窗口”可以同时存在；“渐变 + 厚描边 + 重阴影 + 玻璃 + 发光”属于效果堆叠，必须删减。

### 文字与背景的对比处理

规划和素材生成前，将文字位置、预期字色与局部背景的明暗、纹理共同确定；文字净空须能稳定承载对应字色，不只是没有物体。生成图内文字与后叠文字均遵循此要求。素材就绪后按最终裁切和阅读尺度检查每组文字覆盖的实际背景，尤其是高光与明暗交界，不用整图平均色或品牌色代替判断；再选择最小且符合风格的处理。文字可读性通过字色、字重、位置或贴合字形的效果解决，不新增灰黑底板、灰雾或压暗色带；不把可选手段依次叠满。

| 问题与风格 | 优先选择 | 使用边界 |
|---|---|---|
| 稳定底色上字色偏近、正文偏细 | 从既定色板选择有明度差的字色，调整字重、字号或行长 | 对比色要与文字所在背景有实际明度差，不能只换同亮度颜色；同一色板可分配深浅两套文字色，不机械沿用白字或金字，不改变锁定色与产品／证据色 |
| 文字恰好压住高频细节、线或高光 | 移动文字、调整构图／等比裁切，或移开无信息装饰 | 保留主体和完整文案；不把修饰线提到正文上层 |
| 摄影上的短标题需要轻分离 | 小范围、单方向的克制投影 | 阴影贴近字形，不形成脏灰雾带；正文和小注释不靠大模糊投影补救 |
| 插画、运动、漫画、贴纸风的大标题 | 与字面和背景有对比的外轮廓描边 | 宽度按字重和显示尺度确定，不吞笔画／字腔，不给全部正文套描边 |
| 现有构图仍无法提供稳定阅读区 | 重排文字与主体，或重构背景的低频留白 | 场景光影与渐变按主体、光源或整体色场组织，不跟随文字框制造承托面 |
| 信息本来属于纸签、铭牌、文件夹等媒介 | 用该语义容器的表面承载文字 | 是内容与风格选择，不是因对比不足临时加大底板 |

按实际用途与边界识别底板：跟随文字框形成规则色块、横带或雾状承托的效果，不因命名为“局部调光”、降低透明度、羽化边缘或烘焙进图片而放行。既定纸签、票据、铭牌、品牌色卡片可以承载其所属信息，须有独立的内容职责和构图依据；不能把临时补救改称语义容器。正常场景渐变与光影保留在背景计划中，不作为文字承托选项。

同一区域选一个主处理，只有单项不足且风格允许时配一个辅助效果。高级编辑可优先字色、字重、构图；漫画运动可用描边；实景可用轻投影；拼贴使用纸面与局部接触阴影。生成图把所选手段写进对应文字的 Prompt；Coding 按实际协议支持实现，不凭效果名称自造字段。验收同时检查生成图片内与 Coding 叠加的效果：检查文字周围是否存在跟随文字框的补救底板（可编辑层可隐藏文字核对，图片内效果直接读图判断）；若有且不属于既定语义容器，退回构图或素材修改。按最终阅读尺度检查字腔、细笔画、阴影灰边与背景线穿字，不只检查文字框是否越界。

### Coding 简单背景纹理清单

简单背景纹理由低透明 DOM／CSS 或内嵌 SVG 构成，作为独立低层元素，不能压过标题、正文、产品识别面或照片焦点。每张画面选择一种主纹理，必要时增加一种局部辅助纹理：

| 纹理 | Coding 实现 | 适用 |
|---|---|---|
| 细线网格、坐标纸 | CSS 重复渐变或 SVG 网格，低透明、局部缺省 | 科技、教育、信息图、理性编辑风格 |
| 横向扫描线、印刷走纸线 | 少量 CSS／SVG 等距细线，方向与阅读轴一致 | 数字界面、复古印刷、屏幕语义 |
| 稀疏圆点、半调点阵 | 少量小 circle，密度随区域变化 | 活动、年轻社媒、印刷风格 |
| 棋盘格、像素块 | 少量规则 rect，控制两级尺度和局部密度 | 游戏、潮流、数字文化 |
| 平面放射线、速度线 | 从焦点向外排列的 SVG 图形路径，使用实色线条或色块并避开文字安全区；这是二维构图元素，不是光束、光芒、聚光、辉光或体积光 | 运动、速度、爆发关系；通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图默认不用，除非用户明确要求该平面图形 |
| 等高线、流线 | 少量 SVG 贝塞尔路径，保持统一方向和间距 | 户外、自然、流动主题 |
| 纸张分栏线、裁切标记 | CSS 边线／SVG 短线、角标和刻度 | 杂志、档案、研究、复古编辑 |
| 半透明几何叠片 | 低透明 DOM／SVG 形状，使用同色系尺度差 | 极简、品牌、抽象信息背景 |
| 稀疏颗粒点 | `12–40` 个低透明小圆或短线，集中于非文字区 | 轻微粗粝、印刷或模拟噪点 |
| 边缘色带、窄幅渐变 | 页面边缘的 DOM 色带或 CSS 渐变 | 章节换挡、视线入口与出口 |

需要随机纤维、真实纸纹、砂砾、织物、噪点、折射或连续手绘肌理时改用 IMAGE，不用数百个 HTML Item 模拟。Coding 纹理的元素数量、间距、透明度和留空区域必须在 最终 HTML 中确定，禁止运行时随机生成。

### 参考机制映射表

| 机制编号 | 机制类型 | 来源观察 | 可执行视觉关系 | 人类可读目标 | 约束级别 | Brief 落点 | 成品证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `M1` | `<尺度/裁切/叠压/密度/材质/节奏/容器>` | `<参考中真正决定效果的关系>` | `<谁相对谁如何组织>` | `<主导、从属、局部遮挡、留出标题区等>` | `<不可弱化/允许适配/不采用>` | `<页面或章节及对象名称>` | `<渲染中可以直接观察的结果>` |

机制必须写成关系，不写成孤立形容词。例如：

- 不写“主体大”，写“主体占画布 `58%–72%`，顶部和右侧出血，产品识别面保持完整”；
- 不写“标题有冲击”，写“标题字面宽度占画布 `70%–92%`，位于主体后方并被遮挡 `10%–25%`”；
- 不写“有留白”，写“右上保留 `24%–32%` 的低纹理信息区，与左下主体形成对角张力”；
- 不写“有高级感”，写“单侧柔光、一个暖中性色底、一个强调色、一个主物件和一组细线家具”；
- 不写“信息丰富”，写“只设置一个占画布 `20%–35%` 的高密度信息簇，其余区域保持明显密度落差”。

### 机制类型与提取重点

| 类型 | 必须回答的问题 | 常用量化方式 |
| --- | --- | --- |
| 尺度与裁切 | 第一锚点是谁，完整展示还是主动出血 | 主体占比、出血边、关键识别面、景别 |
| 图文关系 | 标题与主体是分离、承托、穿插还是遮挡 | 标题宽高、交叠比例、前后层级、可识别词组 |
| 空间与密度 | 高密度区和呼吸区在哪里，是否产生张力 | 区域比例、信息簇数量、低纹理区比例、主轴 |
| 节奏与边缘 | 哪些重复母题让画面形成系统 | 重复元素种类、数量、间距、页缘方向 |
| 影像与材质 | 光线、镜头、媒介和表面如何统一 | 光向、软硬、色温、景别、核心材质数量 |
| 容器与信息场 | 信息如何聚组，容器是否属于构图本身 | 主容器数量、轮廓、占比、与背景共用的轴线 |

### 关系图

只要参考中存在穿插、遮挡、破框或跨区关系，Brief 必须用自然语言关系表说明对象、效果和保护边界；关系表用于指导分层，不是实现参数表或新增视觉元素。

| 前景对象 | 后景对象 | 关系 | 可见约束 | 编辑要求 |
| --- | --- | --- | --- | --- |
| `<对象名称>` | `<对象名称>` | `<遮挡/穿插/承托/避让/共轴>` | `<局部遮挡、保持识别面、共享阅读轴等>` | `<是否独立可编辑、必须保护的内容>` |

图文交叠按生产单元落实：一体化社媒 Hero 在整体图内建立前后关系；需要独立编辑／重排的分层区域将主体与标题拆为可独立排序的 DOM 元素，复杂主体在资产计划中安排独立图片。不得为了减少图层把“穿插”静默降级为上下分离。

### 约束级别与取舍

- `不可弱化`：决定参考辨识度的机制，通常包括第一锚点尺度、主裁切、核心图文关系和密度反差。改变后应重新选择策略或记为 custom。
- `允许适配`：可随画幅、文案长度、品牌色和真实资产调整，但必须保留机制的方向与主次关系。
- `不采用`：品牌专属文字、Logo、水印、独特角色、无关装饰或与当前事实冲突的做法；明确排除，避免生成阶段误抄。

每张画面至少确定 `2` 个不可弱化机制，最多保留 `5` 个决定性机制。不是把参考的所有细节都复制进 Brief，而是保住对第一印象影响最大的关系。

### 策略退化判定

出现以下任一情况，视为构图机制未被利用，必须回到 Brief 修正，而不是继续转 HTML：

- 只保留色值、风格名或字体类别，主体尺度与图文关系没有进入区域和元素清单；
- 参考中的强裁切、穿插或破框被改成“完整主体居中 + 标题上下分离”；
- 把关系复杂的画面压成一张满版背景 IMAGE，再叠普通文字；
- 用平均留白、平均分区或等权卡片代替参考中的密度反差和主次尺度；
- 删除信息容器后没有建立替代的信息场，或为了“完整”给每组内容都套通用圆角卡；
- 生成资产只满足题材与色彩，未满足主体位置、占比、景别、光向和预留关系；
- 验收只检查协议、可读性和关键词命中，没有逐项对照机制 ID 的成品证据。

## 主构图体系

### 1. 引导线构图

- 对角线或斜角：主体、色块或文字沿 20–60° 方向形成张力。
- Z 型：适合标题、主体、说明的三段阅读。
- S 型：适合柔和路径、人物动作、植物、织物或流体。
- C 型、U 型：用景物、文字或装饰包围主体，同时保留开口作为视线出口。
- 放射型构图：多个平面对象、实色线条、纹样或信息单元围绕主体向外排列，用于组织视线和强调中心。**放射构图不等于放射性光线**：不得据此生成光源、顶部聚光、从上向下的光束、太阳芒、耶稣光、舞台追光、体积光、镜头光晕或发光背景。通知／公告／喜报／捷报／成果战报／邀请函／节庆贺图默认不使用放射型；只有用户明确要求放射图形时才采用，并仍以平面实色图形实现，用户另行明确要求光效时才可加入照明效果。
- 透视消失线：利用建筑、道路、桌面、阴影或重复物引向焦点。

### 2. 分区构图

- 左右 3:7、7:3：适合强主体与窄文字列。
- 左右 4:6、6:4：适合网页首屏、产品介绍和图文并置。
- 左右 2:8、8:2：适合边注、超大主体或强裁切。
- 上下 3:7、7:3：适合标题带与满幅主视觉。
- 上下 4:6、6:4：适合封面、信息图和内容较均衡的单页。
- 三段式或上中下：只在三段承担不同信息任务时使用，避免等高切成三张卡片。

### 3. 框架包围构图

- 使用矩形、三角、菱形、圆弧、门窗、植物、肢体或物体轮廓形成边界。
- 框架可以被主体或标题突破，避免所有元素被关在完整边框内。
- 适合强调核心产品、人物、展览主题或负空间主体。

### 4. 散点构图

- 用多个尺度不同但风格一致的元素形成群落，设置 1 个主点、2–4 个次点和足够空区。
- 使用方向、密度、颜色或尺度形成隐形动线，不做均匀撒满。
- 适合材料清单、收藏、食物、商品集合、教育展示和轻量信息图。

### 5. 满版构图

- 主视觉占画面 75–100%，通过裁切、景深、光影或局部负空间容纳文字。
- 适合摄影、电影海报、品牌 KV、电商主视觉和强情绪封面。
- 文字只压在可控负空间或局部对比处理上，不给整张图套沉重蒙版。

### 6. 几何异形构图

- 使用多块几何堆叠、大色块切割、圆/椭圆/波形或不规则轮廓组织区域。
- 几何形承担裁切、节奏、引导或层级中的至少一种功能，不作为无意义装饰。
- 同一画面控制 1 种主形态和 1 种辅助形态。

### 7. 锚点与负空间构图

- 将主体放在三分点、边缘、角部或偏轴位置，以 25–45% 有意留白容纳标题、行动或情绪。
- 用标题、编号或短线建立第二锚点，使主体与文字形成张力。
- 适合极简海报、产品静物、网页首屏、社交封面和艺术插画。

### 8. 非对称编辑网格

- 使用窄文字列、跨栏图片、超大编号、边注或错位基线组织信息。
- 先建立清晰网格，再让 1–2 个关键元素越界；不要把所有对象随意错位。
- 适合杂志、品牌故事、展览、文化内容和高级图文版式。

### 9. 前中后景叠压构图

- 用前景裁切元素、中景主体和背景材质建立深度，让标题或标签与主体边缘有意重叠。
- 主体占画面 55–85%，辅助卡片明显更小并浮在主视觉内部或边缘。
- 适合产品 KV、拼贴、长图关键屏、网页主视觉和需要弱化模块拼接的设计。

## 产物选择矩阵

| 产物 | 优先主构图 | 常用辅助构图 | 关键限制 |
|---|---|---|---|
| 海报、封面、社交视觉 | 满版、锚点留白、对角线 | 框架、异形、叠压 | 默认不居中；缩略图仍有单一焦点 |
| 品牌 KV、电商主视觉 | 满版、3:7 分区、叠压 | 平面放射图形、框架、几何切割 | 产品身份与文字负空间优先；平面放射图形不解释为照明射线 |
| 网页首屏、落地页 | 4:6 分区、非对称网格、锚点留白 | 对角线、叠压 | 保留导航、CTA 及用户明确批准的目标画幅适配空间 |
| 信息图、教育展示 | Z 型、分区、散点 | 几何异形、框架 | 顺序和数据准确性高于形式 |
| 长图关键屏 | 满版、叠压、非对称网格 | S/Z 型、跨区异形 | 画面之间通过轴线、材质或越界连续 |
| 产品界面、仪表盘 | 任务网格与信息层级 | 局部锚点、分区 | 不把海报构图强加给高频操作区 |

## 转写为视觉重建 Prompt

按以下顺序组织一段 180–350 字的连续中文，不使用分析口吻或标签列表：

1. 图像类型、整体风格与主要材质；
2. 主构图与辅助构图；
3. 结构分布：区域比例、主体占比、文字区与留白；
4. 阅读动线：入口、焦点、出口；
5. 主视觉：主体、数量、位置、视角、景别；
6. 次视觉：背景、前景、陪体、装饰及其作用；
7. 光影：只描述真实影响画面的光；放射构图、视觉动势、庆典、隆重、红金、丝绸和金属不自动产生光源或光束；
8. 文字版式：保留可辨识的主标题、品牌、日期与重要文字，无法辨认的小字只描述位置和功能；
9. 色彩、材质、纹理与画幅尺寸。

描述必须忠实于参考，不补充不存在的故事、元素或文字；估算比例只用于表达真实视觉关系。用于 AI + Coding 时，按 [素材 Prompt 规范](../coding/ai-coding/asset-prompt-guide.md) 将参考分析转为素材指令：普通配图的后叠文字区用方位、连续表面和低纹理空区正向描述，不附加通用文字排除列表；图内准确文案只按品类明确准入，已有包装文字与身份 Logo 保持。画幅参数与像素指标不混入 Prompt。纯生图沿自身完整终图规则描述整张成品及其文字，不套用 Coding 素材要求。

## Coding 映射

- 引导线：用网格轴线、斜切容器、`transform`、`clip-path` 或 SVG 路径建立方向。
- 分区：优先使用相对固定画布的 CSS Grid 比例列／行；只有用户明确批准目标比例或尺寸适配时，才为该目标画幅独立试排。浏览器窗口变窄不授权重排，同一作品的布局与字号不得随视口改变。
- 框架：使用伪元素、SVG、边框或场景物体，不把框架烘焙进文字层。
- 散点：使用受控绝对定位或网格密度变化，保留稳定锚点和已批准目标画幅的安全边界，不做视口驱动的运行时重排。
- 满版：使用 `object-fit: cover`、焦点位置和局部渐变，确保重要主体不被裁掉。
- 几何异形：使用 CSS 形状、SVG 或遮罩；简单图形不生成位图。
- 锚点留白：用明确网格空区承载标题与 CTA，不用大量空白掩盖信息不足。
- 非对称网格：先定义列、基线和安全边距，再允许关键元素跨栏。
- 前中后景：使用明确 z-index 层级、局部遮挡和可独立替换的图层，避免整屏压平。

## 检查

- 是否已经完成参考机制映射表，并将每个机制 ID 绑定到区域、元素或资产；
- 是否至少保留两个不可弱化机制，且没有被安全居中、上下分离或单张背景图静默简化；
- 存在叠压、穿插或破框时是否建立了关系图和独立图层；
- 是否只有一个清晰主焦点；
- 主构图是否可以用一句话说清；
- 主体、文字、留白与背景是否有明确比例；
- 阅读动线是否在三步内完成；
- 辅助构图是否强化而非干扰主构图；
- 默认缩略视图下标题与主体是否仍清晰；
- 用户明确批准的目标比例／尺寸适配是否分别保留焦点、顺序与负空间，同一固定作品在不同视口下是否保持排版不变；
- 生成描述是否遗漏构图、视角、景别、光影、文字区或尺寸；
- 是否通过策略退化判定，而不只满足题材、配色和协议合法性；
- 是否脑补了参考中不存在的元素或小字。

### 渐变与文字安全区

先区分连接关系和作用对象：背景色场可以位于文字下方，按上节检查每行文字的局部对比；前景淡出／接缝遮罩只适用于空间连续且确有安全空场的影像区域。媒介转换、视觉呼应、独立图窗和明确换章不为消除边界自动加渐变。无论硬切或融合，过渡都不得覆盖可编辑文字或图内文字；渐变不默认生成，也不默认限定为窄条。

将接缝上下两侧作为一个保护场检查。在最终缩放、裁切与换行后，用每组文字的实际字形边界建立保护区，默认向外扩半个当前行高，并计入描边／字影外缘；图内文字通过读图标出边界。保护范围同时包含首屏底部接力文字、正文首标题、正文、小字、Logo和二维码。边界、纸边、色块、蒙版及其完整羽化／模糊尾部均不得侵入保护区；不能只检查渐变中心或不透明端。距离不足时先移动文字或边界、扩大净空、调整构图；一体化 Hero 无法满足时返回素材，不靠降低透明度、覆字或压暗硬叠。

Coding 将背景及其过渡与文字拆为独立层，核对实际层叠上下文；不得对包含文字的共同祖先设置淡出 mask、opacity 或 filter。提高子文字 z-index 不能解除祖先蒙版，也不能保护已经烘焙在图内的文字。记录连接关系、边界／过渡起止、作用层与保护区到已有组装记录；文案、字体、素材裁切或过渡范围变化后重新测量，并以接缝为取景中心联合复核上下两侧。
