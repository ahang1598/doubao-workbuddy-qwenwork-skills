# pure-coding 与 image-coding 共享 HTML 实现规范

## 1. 概述

- **统一实现，不裁决路线。** 本文件负责 pure-coding 与 image-coding 的全部 HTML 实现、固定画布、原生层、资产消费、测量及完整源。路线、例外、批准与生产顺序仅由 [SKILL.md](../SKILL.md) 裁定；素材现成或代码方便不构成改道理由。
- **共用规则归唯一责任方。** 事实、扩写、唯一 Brief、创意与身份母版见 [common.md](common.md)；执行状态、真实展示、准出、修复权限及交付见 [SKILL.md](../SKILL.md)，素材要求见 [quality.md](quality.md)。本文件只保留实现提醒，不新增批准。

## 2. 使用场景

- **纯代码直接实现。** 使用核验的真实现有资产、准确文字、HTML/CSS 与内嵌 SVG；不调用生图，不强制新增素材清单、字体计划或几何副本。
- **混合素材就绪后组装。** 按 [produce-hybrid.md](produce-hybrid.md) 完成适用前置，图像生产按 [produce-image.md](produce-image.md)。入口规定的 KV、封面及身份批准不得由素材准出替代，也不得扩展至其他产物。
- **编辑保护完整基线。** 已有源按 [edit.md](edit.md) 获取完整文档，只检查、修改授权范围及必要联动区域；新建与整体重做执行下述完整实现规范，局改不为迁移旧结构改动未受影响内容。实际渲染或宿主接入受阻时按编辑规范处理具体冲突，不跳过失败或宣称通过。
- **选型交由专项文件。** 含文字 HTML 试排前读取 [fonts.md](fonts.md)；新建、整体重做及局改受影响项按 [templates.md](templates.md) 比较、完整读取和采用发布资源。细选规则不在此重复。

## 3. 核心流程

### 设计方案与 HTML 实现

- 沿用唯一 Brief 的真实内容、锁定尺寸、阅读顺序、原生文字职责及身份依据。结构、主构图、视觉系统或素材职责变化时，先更新同一 Brief，按入口处理适用确认，不静默降级。
- Brief 冻结后将坐标、字号、色值、层级、裁切和 CSS/SVG 参数直接写入完整源，不另填几何投影。
- 按主入口约定的一页／一面／一屏分别保存完整 HTML5 文档，包含 `<!DOCTYPE html>`、`html`、`head`、UTF-8 声明及 `body`；片段、补丁、截图均不能替代。分页 VI 同样逐页保存，不合并为一个长画布。
- 章节、重复组按语义组织；可定位编辑节点使用稳定 `id`／`data-layer-id`，真实区域可用 `data-region`，不得冒充宿主对象 ID。
- 沿用采用记录，保留 Brief 版本、确切资源 ID、发布资源提供的源 SHA-256、采用范围、内容映射和调整理由。整页、章节、局部、原子分别表述；借色板、保留 class 或注释不等于采用整页。

### 固定画布尺寸设置

- `html` 必须含 `data-canvas-width`、`data-canvas-height`，值为不带单位、小数或百分号的十进制正整数字符串。
- **作品总容器必须明确。** 每个独立 HTML 在 `body` 内用唯一 `data-canvas-root` 标记该页／面／屏的外层容器；尺寸仅对应该文件，不包裹整套页面。缺失、重复或标在 `html`／`body` 上均报错，不自动猜测容器。
- `html`、`body`、唯一作品容器的行内 `width`、`height` 均须为与属性完全一致的固定 px 值。清除默认外边距，采用 `box-sizing:border-box`，核对实际边框盒。
- **仅宽高强制行内。** 其他样式可用样式块、class、id 或可加载外部样式表；普通样式不得覆盖固定尺寸。
- 根节点不得以 `max-width`、`min-height`、`height:auto` 替代固定宽高，不用 `overflow:hidden` 藏正文、模块或页尾。局部装饰可按职责裁切；内容须容纳在所属区域，不全局解除裁切使其侵入下一章。
- 禁止 JavaScript、视口单位或媒体查询计算、改变作品尺寸；禁止根文档或整件作品随窗口 `scale`／`zoom`。内部百分比相对固定画布计算，排版不随视口改变。
- `data-canvas-protocol`、`data-canvas-version`、`id="canvas-root"` 非必填；已有则保留，仅接入规范明确要求时新增，不能替代尺寸属性与 CSS。

以下为 750×1500 的尺寸骨架示例，实际宽高按任务确定；本例为独立页面，包含正常流底部安全区；连续非末屏按下文接缝规则处理。

```html
<!DOCTYPE html>
<html lang="zh-CN" data-canvas-width="750" data-canvas-height="1500"
      style="width:750px;height:1500px;">
<head>
  <meta charset="UTF-8">
  <style>
    * { box-sizing: border-box; }
    html, body { margin: 0; padding: 0; }
  </style>
</head>
<body style="width:750px;height:1500px;">
  <main data-canvas-root style="width:750px;height:1500px;">
    <!-- 正式内容、页码及收尾信息放在安全区之前 -->
    <div data-canvas-bottom-safe-area="24" style="height:24px;"></div>
  </main>
</body>
</html>
```

- **按内容排版，按当前尺寸导出。** 用完整文案、可用字体和计划图像比例预排字号、栏宽与图文面积；混合生产在素材准出后组装正式 HTML。锁定尺寸在原画布内重排；未锁定屏高随实际内容调整，不保留模板多余高度。每次定高或改高，同步两项画布属性与三个根节点的行内尺寸，按同一尺寸渲染；测量方法见“页面测高与固定高度”。


| 报错 | 修复方法 |
|---|---|
| `OUTPUT_PATH_INVALID` | 将截图命令的 `--output` 改为 `.png` 文件路径；属于调用参数，不修改 HTML |
| `CANVAS_SPEC_INVALID` | 按 `canvasSpecErrors` 补齐或统一画布属性、三个根节点的行内尺寸及唯一作品根节点 |
| `ROOT_SIZE_MISMATCH` | 声明正确但实际边框盒不符；检查 CSS 覆盖、默认边距、padding、border 与定位 |
| `CONTENT_OVERFLOW`／`BOTTOM_SAFE_AREA_INVALID` | 按下文“页面测高与固定高度”定位具体内容或装饰，再处理排版、安全区或测量误判 |
| 字体错误／图片 503 等资源失败 | 按资源诊断修复或有限重试；不为资源错误改变画布尺寸 |

### 分页、分面与分屏

- 按主入口的拆分单位生产；每个文件包含独立可渲染的完整 HTML、固定尺寸和稳定编号，各自运行检查并导出同尺寸预览。
- 画册、套图及分页 VI 按页序交付；三折页交内侧、外侧两个完整展开面，不把三个折区分别交付。
- 详情页先按 ecommerce-detail 规划整页再分文件；各屏等宽，高度区分锁定值与起排参考，不继承同一模板高度。背景跨屏时按整页坐标连续裁切或沿用共享背景参数，再换算为各屏局部坐标，不能在每个文件顶部重新开始同一渐变或场景。
- 用户需要完整详情长图时，使用同版本、等宽且与各自声明尺寸一致的完整导出图；第 n 屏起点为前面各屏实际导出高度之和，总高等于各屏高度之和。不按估算高度定位，不用负间距、重叠贴图或裁掉内容掩盖接缝；宽度不一致时回源统一，不拉伸成图。保留各屏 HTML，拼接预览不替代独立文件。

### 物理尺寸与采样分开计算

- 优先采用用户明确值、已确认印厂或版位规格；编辑继承原尺寸。冲突先解决，无尺寸才按题材推荐，并在 Brief 记录用途、单位及假设来源，示例不作默认规格。
- 数字作品用 px，默认 1 倍导出与画布同像素。物理成品用 mm 记录裁切、出血、折线及安全区；折叠品同时记录展开与闭合尺寸。
- HTML 按 `1 in = 96 CSS px`、`px = mm × 96 / 25.4`、`1 pt = 4/3 px` 换算。根宽高向上取整；元素、折线先保留精度，整数边界按累计转换后求差，避免逐段舍入漂移。屏幕 CSS 毫米不保证实物尺测毫米。
- 印刷位图另算 `export_px = ceil(mm / 25.4 × PPI)`。PPI 未确认时，300 仅可作为明示的设计测试假设，不冒充印厂要求；96 CSS px/in 不是印刷分辨率。
- 每边已确认出血为 b mm 时，出血版为 `(裁切宽 + 2b) × (裁切高 + 2b)`；内容、折线相对裁切区定位后整体偏移。未知出血不猜填，先做裁切区并记待补。
- 净稿不显示辅助线；生产校样可显示折线、裁切线及说明，须明确区分。尺寸齐全不等于具备印刷交付能力。
- 高分辨率输出从同一源按目标分辨率重新渲染，不放大小截图或仅改 PPI 元数据。导出像素按未取整物理尺寸计算，CSS 取整余量在边缘处理，不非等比拉伸，也不因采样倍率重写版式。

## 4. 不同产物/策略展开

### 原生文字与数据保持可编辑

- Brief 指定 Coding 的主副标题、正文、数字、单位、条件、标签、CTA、图注及来源须逐字成为真实 DOM 文本，并可稳定定位。图表、标注和复杂路径可用 DOM／内嵌 SVG；准确文字及数值保持可编辑，不栅格化或烘焙入背景。
- 数据仅消费有依据的输入与可复算转换。比例、合计、排序、坐标映射及单位换算可追溯口径和方法；零值、未知、不适用不得混用。模板姓名、学历、年月、章节及数值不是任务事实；无依据的非锁定示例槽位移除或暂停并记待补，不擅删确认事实。
- 仅 Brief 明确准入的一体 Hero 图内文案或唯一独立艺术标题可用图片，并与 Coding 清单互斥。不重复 DOM 覆字，不声称图内文字可编辑，不用图片替代全部文字。
- 字体选择理由留在 Brief；真实 `@font-face`、family、weight、style、size、line-height、letter-spacing 及显式回退栈落实到最终节点，在目标环境验证。本地可见或下载过不证明交付可用。
- 文字效果优先使用适合节点的发布 CSS：描边用 `-webkit-text-stroke` 且保留可读字色；阴影、发光用受控 `text-shadow`；渐变同时落实背景、标准及 WebKit `background-clip:text` 和透明字色；逐字差异用真实嵌套 `span`、变换及阴影。
- 装饰可用伪元素，独立装饰节点设 `aria-hidden="true"`。复杂纹理无法稳定用于真文本时先简化效果，不擅自转图片。

### 素材链接与使用位置

- 生成或编辑图片逐字使用素材记录中准出的最终 HTTP(S) 短链。原结果可用则保留原链；真实处理产生新文件才使用回填结果链，不为插入 HTML 下载重传、复制换链。
- 素材项、采用版本及消费者记录按 [quality.md](quality.md) 维护；仅使用真实记录中的就绪版本，不凭记忆、旧 Prompt 或预览地址猜测。
- 最终图片引用须为核验有效的 HTTP(S) 地址，覆盖 `img src`、`srcset` 每项、实际生效的 CSS 背景／蒙版（含外部样式、伪元素）、SVG `image href`／`xlink:href`。禁止本地、相对路径、`file://`、位图 `data:`、Base64、Blob、临时预览或占位 URL；用户资产缺有效链接时先取得并核验，不假装上传。
- 自包含静态 SVG 是唯一数据地址例外：由 [inline-svg-assets.py](../scripts/inline-svg-assets.py) 生成百分号编码的 `data:image/svg+xml,`，可用于 `src`、`href` 或 CSS 背景／蒙版，不用于 `srcset`。SVG 不含外部图像、字体、样式、脚本或动态引用；来源与消费者仍须核对，需要节点可编辑时使用内嵌 SVG DOM。检查器的结构验证不替代来源核验与实际渲染。
- 同资产消费者复用同链；替换时按真实资产与授权范围同步记录、全部相关引用并重预览，不因同 URL 就无差别替换。可访问仍须核身份、用途、版本、尺寸、清晰度与 Alpha。

### 透明素材与混合模式

- 背景处理执行 [produce-image.md](produce-image.md)，真实Alpha与边缘按 [quality.md](quality.md) 核验；在最终背景复查，透明留边不计作主体可见范围。
- 独立艺术字仅在已知稳定背景下，允许深字纯白底配节点级 `multiply`、浅字纯黑底配节点级 `screen`。透明导出、跨背景、背景未知或严格保色须用准出透明 PNG，不附混合模式。
- 普通 Logo HTML 展示可在均匀白底图的图片节点使用 `multiply`，均匀黑底图的图片节点使用 `screen`，核对实际背景与品牌色，不声称具有 Alpha；VI 的独立 Logo 层仍须真实透明。去底保留品牌本体底板，不重画身份；例外不扩至人物、商品及其他多色素材。
- 图文关系由真实承载层、定位、层级与裁切实现；跨层或复用对象使用独立资产或原生节点。已烘焙文字、面板、装饰及光影不重复叠加，不以 DOM 覆字或卡片修补 Hero 图内错误。
- 效果须实际可见，令牌、配方名或 CSS 属性存在不算兑现。祖先透明度、蒙版、模糊与混合不得损伤信息和身份；子节点 `z-index` 不能抵消祖先蒙版。

### 图片缩放、裁切与清晰度检查

- 比例分为“源图 → 就绪文件 → 每个显示实例”核验。先统一 EXIF 正常方向，记录父图、裁切坐标及处理版本；缩放等比，裁切只改取景，扩图只加画布，不以最终同框比例掩盖已烘焙变形。
- 正常方向素材为 W×H、未旋转内容框为 Bw×Bh：`contain = min(Bw/W, Bh/H)`，`cover = max(Bw/W, Bh/H)`。合法 contain／cover 不因框比例不同被判拉伸。
- `ratio_gap = max((W/H)/(Bw/Bh), (Bw/Bh)/(W/H))`：≤1.15 优先轻裁切；1.15–1.5 加强构图复核；>1.5 优先评估完整显示、获准扩图或重排。这些仅为复核触发，不保证安全，也不授权重生或新增批准。
- 仅要求完整同框显示的实例，框与素材比例误差须 ≤1%。真实横纵缩放比超过 1.01 可报 `IMAGE_ASPECT_MISMATCH`；容差不许可主动变形，任何可见身份或几何失真均失败。
- 按实际定位、旋转、裁切、mask、父层 overflow 及前景遮挡反推可见源区域，不默认居中。逐消费者检查焦点、脸、肢体、产品识别面、Logo、包装文字、动作、证据及必要上下文；这些操作改变源可见面积，不能只查文件尺寸。
- 1 倍输出的裁切后有效像素不得低于对应显示像素；主视觉建议保留 1.5–2 倍余量，其他导出倍率另验。contain 按实际图像内容算，插值不增加细节，不足报 `IMAGE_LOW_RESOLUTION`。艺术标题宽、高两向均须达到真实有效 2 倍像素。
- 组装前可按已知素材、拟用框、定位及处理参数检查，不要求已有最终 HTML；组装后必须补验每个真实消费者和实际遮挡，不把计划值当最终证据。

## 5. 输出形式

### 完整源与预览对应同一版本

- 每页／面／屏保留完整固定画布 HTML 及当前源同尺寸完整预览；正式预览为 1 CSS px 对应 1 PNG 像素，不以其他视口、拉伸、补白、裁内容代替该文件的完整预览。高 DPI 输出另按同源目标采样渲染。
- 源变化保存完整新版本并重新核验，旧预览、旧回读不为新版本背书；Brief、源、素材记录与实际输出保持对应。附件与缓存范围按 [quality.md](quality.md) 控制，不另建生产合同。
- **交付使用实际出口。** 按[主入口](../SKILL.md#交付规范)保留完整 HTML 源并交付同尺寸预览。

- 预览失败时可继续独立可完成的源保存，但素材、源码与入口门禁仍有效；诊断图不作正式成品，不宣称可视交付完成。状态、修复预算及未解决／未验证结论按主入口执行。
