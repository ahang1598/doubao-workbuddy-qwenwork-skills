# 微信公众号官方接口发布流程

本文件用于通过微信公众号官方服务端接口完成文章上传、保存草稿、草稿链接预览、正式发布和结果核验。后续上传到豆包时，本流程必须面向普通用户协作完成，不要求用户理解代码、命令或接口细节。

## 1. 总原则

1. **只走官方接口。** 正文、图片、封面、草稿、预览和发布都通过微信官方服务端接口完成。
2. **不做 HTML 预览模拟。** 微信接口的 `content` 字段必须是 HTML，这是接口格式要求；但不得生成本地 HTML 页面冒充公众号预览。预览结果必须来自微信接口返回的草稿临时链接，或发布后的正式文章链接。
3. **不让用户看代码。** 面向用户只展示“需要提供什么”“已完成什么”“下一步确认什么”。脚本、payload、环境变量由 Agent 在运行环境内处理。
4. **不自动发表。** 保存草稿可以自动执行；正式发布必须在用户看过草稿链接预览并明确授权后，才可调用发布接口。
5. **不虚报结果。** 草稿创建、发布提交、发布成功是不同状态。必须以接口返回或查询结果为准。
6. **微信接口只能在用户本地电脑执行。** 豆包必须先切换到用户的“本地电脑模式”，再调用微信接口；不得在云端、远程 Agent、共享容器或不明执行节点执行，否则出口 IP 不稳定，白名单会失效。
7. **本地直连模式需要用户完成公众号开发配置。** 用户只需要按提示在微信开发者平台找到 AppID、AppSecret，并把微信回显出口 IP 所在的 `/24` 网段加入公众号 API IP 白名单。
7. **不记录密钥。** AppSecret、access_token 不写入文章、飞书文档、公开日志或最终回复。报错时只输出脱敏后的原因和用户可执行动作。
8. **草稿交付必须同时返回两个链接，缺一不可。** 每次草稿创建成功后，最终回复中必须同时给出：①草稿临时预览链接（`tempkey` 只读链接，用于手机/外部预览排版）；②后台编辑器直达链接（含 `appmsg_edit&action=edit` 和 `appmsgid`，用户点击后可直接在编辑器中点「发表」）。两个链接必须在同一条回复中成对出现，明确标注各自用途，不得只给其中一个，不得以"已在浏览器中打开"为由省略编辑器链接，不得让用户自行去草稿箱翻找。若临时链接接口未返回，仍必须给出编辑器直达链接，并说明临时预览可在编辑器中点「预览」获取。

## 2. 接口能力边界

| 阶段 | 接口 | 能否纯接口完成 | 用户感知 |
|------|------|----------------|----------|
| 获取凭证 | `/cgi-bin/stable_token` | 能 | 必须在用户本地电脑执行；用户需提供 AppID/AppSecret，并把微信回显出口 IP 所在 `/24` 网段加入白名单 |
| 正文图片上传 | `/cgi-bin/media/uploadimg` | 能 | 用户无需处理，失败时提示压缩或换图 |
| 封面上传 | `/cgi-bin/material/add_material` | 能 | 用户只需确认封面图 |
| 创建草稿 | `/cgi-bin/draft/add` | 能 | 返回草稿 `media_id` 和草稿临时预览链接（`tempkey`）；最终交付必须同时返回临时预览链接和后台编辑器直达链接 |
| 草稿核验 | `/cgi-bin/draft/batchget` | 能 | 返回草稿标题、正文、临时链接等 |
| 草稿预览 | `/cgi-bin/draft/add` 返回的临时链接 | 能 | 直接把 `tempkey` 只读链接发给用户预览 |
| 正式发布 | `/cgi-bin/freepublish/submit` | 依账号权限 | 需用户明确确认 |
| 发布状态 | `/cgi-bin/freepublish/get` | 依账号权限 | 返回成功、发布中、审核失败等状态 |

注意：

- 草稿接口通常可用于公众号和服务号。
- 发布和发布状态接口通常要求企业主体已认证账号。个人主体、未认证企业主体或不支持认证的账号可能返回 `48001 api unauthorized`。
- 本 Skill 不使用 `message/mass/preview` 手机预览接口：它对个人/未认证号返回 `48001`，且需要索取用户微信号，体验差且易误导。预览统一用草稿临时链接。
- 从 2025 年 7 月起，个人主体账号、企业主体未认证账号及不支持认证账号的发布能力会被回收。遇到无权限时，应提示用户只能创建草稿后在公众号后台人工发表。
- 直连 `stable_token` 的 AppID/AppSecret 模式只允许在用户本地电脑模式执行。豆包云端执行节点、远程 Agent、共享容器和不明执行节点不得调用这些接口。

## 3. 用户协作流程

### 3.0 启用 AppSecret 前的账号资格检查

在微信开发者平台点击“启用 AppSecret”前，先检查账号类型和实名状态。不要把“个人管理员实名”和“微信认证”混为一谈：

1. **个人主体账号，提示“该账号尚未完成实名”**：
   - 打开微信公众平台：https://mp.weixin.qq.com/
   - 使用当前公众号管理员微信扫码登录；
   - 路径：`设置与开发 → 人员设置 → 管理员信息`；
   - 按页面提示修改并完成管理员实名信息；
   - 在 `账号详情 → 主体信息` 看到管理员姓名后，说明实名已完成。
2. **非个人主体账号，提示“该账号尚未完成主体认证”**：
   - 在微信公众平台的 `账号详情 → 认证情况` 点击“申请微信认证”；
   - 完成主体认证后再启用 AppSecret。
3. 完成后回到微信开发者平台：`前往控制台 → 我的业务与服务 → 公众号 → 基础信息 → 开发密钥`，重新点击“启用 AppSecret”。

官方说明：https://developers.weixin.qq.com/doc/oplatform/developers/product/subscription_service/appid.html

### 3.1 首次直连配置

首次发布时，Agent 必须主动完成以下编排，不能把命令交给用户：

1. 先确认豆包已进入用户本地电脑模式；未进入时必须要求切换，不能继续调用微信接口。
2. 调用 `check-config`，检测当前公网出口 IP 并检查本地配置状态。
3. 先检查是否需要完成第 3.0 节的管理员实名或主体认证；遇到“未完成实名/主体认证”提示时，必须先给出对应的公众平台入口和路径。
4. **先给用户可点击入口和准确路径：**
   - 微信开发者平台：https://developers.weixin.qq.com/platform/
   - 路径：`微信开发者平台 → 前往控制台 → 我的业务与服务 → 公众号 → 基础信息`
   - AppID：在“基础信息”查看
   - AppSecret、API IP 白名单：在“开发密钥”查看和配置
5. 展示脚本检测到的公网出口 IP 仅用于预提示。若微信接口返回 IP 白名单错误，以错误响应中 `invalid ip` 后的 IP 为准，并把它所在的 `/24` 网段整段加入白名单（因为出口 IP 会在同网段内轮换）。
6. 让用户二选一：
   - **直接提供**：把 AppID/AppSecret 发给 Agent，仅用于当前任务，不写本地配置；
   - **保存本地**：把 AppID/AppSecret 提供给 Agent，由 Agent 调用 `setup-local` 写入权限为 `0600` 的本地配置文件，后续自动复用。
7. 用户完成 IP 白名单后，Agent 在用户本地电脑模式调用 `verify-config`。验证成功后自动继续创建草稿。

对用户只需这样说：

> 请先打开微信开发者平台：https://developers.weixin.qq.com/platform/  
> 路径：微信开发者平台 → 前往控制台 → 我的业务与服务 → 公众号 → 基础信息。  
> AppID 在“基础信息”，AppSecret 和 API IP 白名单在“开发密钥”。  
> 获取后你可以直接发给我用于本次发布，也可以让我保存到本地供以后使用。

IP 白名单是否必要：

1. **本地直连模式下是必要的。** 微信公众号服务端接口会校验调用来源 IP。未加白时，获取或使用接口凭据通常会返回 `40164` 或类似 IP 不合法错误。
2. **加的是公网出口 IP，不是局域网 IP。** 不要填写 `192.168.x.x`、`10.x.x.x`、`172.16.x.x` 这类内网地址。
3. **按微信回显 IP 所在的 `/24` 网段加白。** 当前执行环境出口 IP 会在同一 `/24` 网段内轮换，逐个加单 IP 会反复触发 `40164`。发生 `40164` 或 `61004` 时，取错误消息中 `invalid ip` 后的 IP，把它所在的 `/24` 网段整段加入白名单。例如 `117.133.49.99` 应添加 `117.133.49.0/24`。
4. **“检测 IP”和“微信实际看到的 IP”可能不同。** 预检测 IP 仅供参考；白名单以微信错误回显的 IP 所在网段为准。微信支持 `/24` CIDR，不支持 `*` 通配或 `IP:端口`。
5. **不得回退到云端执行。** 若当前不是用户本地电脑模式，停止接口调用并要求豆包切换本地电脑模式；不再尝试配置云端出口 IP。

用户必须完成的动作只有：

1. 点击微信开发者平台链接并扫码登录；
2. 找到 AppID/AppSecret，选择直接提供或保存本地；
3. 若验证报 IP 白名单错误，把微信错误消息中 `invalid ip` 后的 IP 所在 `/24` 网段加入白名单；
4. 用草稿临时链接预览排版；
5. 在 Agent 自动打开的后台草稿编辑器中点「发表」（个人/未认证号），或确认后由 Agent 通过接口发布（已认证企业号）。

直连调试入口链接：

- 微信开发者平台（查看公众号/服务号基础信息与开发密钥）：https://developers.weixin.qq.com/platform/
- AppID / AppSecret 官方说明：https://developers.weixin.qq.com/doc/oplatform/developers/dev/appid.html
- 公众号开发接口管理迁移说明：https://developers.weixin.qq.com/doc/subscription/guide/dev/migration.html
- API IP 白名单官方说明：https://developers.weixin.qq.com/doc/oplatform/developers/basic_func/ip_whitelist.html
- 稳定版 access_token 接口说明：https://developers.weixin.qq.com/doc/subscription/api/base/api_getstableaccesstoken.html
- 微信接口调试/诊断工具：https://developers.weixin.qq.com/console/devtools/debug

微信页面操作路径：

1. 打开微信开发者平台，使用公众号管理员或开发者微信扫码登录。
2. 进入“前往控制台 - 我的业务与服务 - 公众号 - 基础信息”，复制公众号 AppID。
3. 进入“基础信息 - 开发密钥”，启用或重置 AppSecret；AppSecret 只展示一次，需立即保存到安全配置中。
4. 运行验证；若出现 `40164` 或 `61004`，从错误消息取得微信实际看到的 IP。
5. 在同一页面配置 API IP 白名单，添加该 IP 所在的 `/24` 网段，例如 `117.133.49.99` → `117.133.49.0/24`。
6. 回到对话，告诉 Agent “已完成”。Agent 会自动验证并继续。

本地安全存储：

- 默认配置文件：`~/.config/doubao-wechat-writing/wechat-mp.json`，权限为 `0600`。
- 用户选择“保存本地”时，AppID/AppSecret 写入该文件；用户选择“直接提供”时不写入本地配置。
- access token 缓存在同一配置目录，权限为 `0600`，无需用户维护。
- 换网络后无需重新输入 AppID/AppSecret；若微信回显出口整体切换到新网段，只需把新的 `/24` 网段加入白名单并重新验证。

### 3.2 上传并保存草稿

用户说“上传到公众号”“保存草稿”“传到后台”时：

1. 确认正式飞书文档已创建并通过 `scripts/require_feishu_output.py` 校验。
2. 仅在用户明确要求上传、预览或发布时，从用户确认的飞书“正文”区块生成临时 `publish_package.json`；禁止把整个飞书文档导出后直接当正文上传。
3. 将发布包中的 `body_markdown` 转换为微信接口支持的 HTML。这里的 HTML 只作为接口入参，不作为预览页面交付。
4. 调用 `scripts/wechat_mp_api_publish.py create-draft --publish-package <绝对路径>` 或 `workflow` 创建草稿。
5. 将脚本返回的 `next_user_message` 转成自然语言反馈给用户。
6. 草稿临时预览链接（`tempkey`）必须随草稿创建结果一并获取并交付给用户供只读预览。**临时预览链接和第 8 步的编辑器直达链接必须在同一条最终回复中成对交付，缺一不可。** 若接口确实未返回临时链接，仍必须给出编辑器直达链接，并在回复中注明"临时预览可在编辑器中点「预览」获取"。
7. **紧接着按第 3.5 节自动打开公众号后台草稿编辑器**：用浏览器打开 mp.weixin.qq.com，登录后进入草稿箱，按标题定位并点开该文章，让用户直接在编辑器中点「发表」。不要停在"请去草稿箱自行查找"。

8. 编辑器页面加载完成后，**从浏览器地址栏复制完整编辑器 URL**（含 `appmsg_edit&action=edit` 和 `appmsgid`），在最终交付话术中标注为"可直接点击发表的链接"返回给用户。**这是草稿上传的必备交付项，不得省略，不得以"浏览器已打开"为由跳过。最终回复必须同时包含：①草稿临时预览链接；②后台编辑器直达链接。**

默认到“草稿已创建、后台编辑器已打开、编辑器直达链接已返回”即停止，不自动发布。

### 3.3 草稿预览

本 Skill 不提供"手机预览"（`message/mass/preview` 群发预览接口只对已认证企业号开放，个人/未认证号会直接返回 `48001`，容易误导用户）。预览优先走草稿临时链接；接口未返回临时链接时，通过后台编辑器的「预览」按钮获取，但无论哪种情况，编辑器直达链接都必须返回：

1. 草稿创建成功后，`draft/add` 通常会返回一个 `tempkey` 草稿临时链接，直接发给用户在浏览器/微信中打开预览真实排版；
2. 若接口未返回临时链接，**不得让用户自行去草稿箱翻找**；仍必须按第 3.5 节打开后台编辑器并返回编辑器直达链接，告知用户"可在编辑器中点「预览」按钮获取手机预览"。
3. 不索取用户微信号，不调用群发预览接口，不伪造二维码或本地 HTML 预览。

对用户话术（两个链接必须同时出现）：

> 草稿已创建。
>
> 只读预览（手机端看排版）：{草稿临时链接}
>
> **点击发表（后台编辑器直达）：{编辑器URL}**
>
> 我同时帮你在公众号后台打开了这篇草稿，确认无误后直接点「发表」即可。

临时链接仅用于只读预览；**无论是否返回临时链接，都应按第 3.5 节自动打开后台草稿编辑器，并将编辑器 URL 作为"可直接点击发表的链接"返回给用户**，让用户可直接发表。

### 3.4 账号资质分流：能否接口发布

在尝试接口正式发布前，必须先判断账号资质，避免让用户误以为“任何号都能一键接口发布”：

- **仅企业主体且已完成微信认证的账号**，才拥有 `freepublish/submit`（正式发布）接口权限。
- **个人主体、未认证企业主体、不支持认证的账号**：只有草稿接口权限。接口正式发布会返回 `48001 api unauthorized`。这类账号只能创建草稿后，由用户在公众号后台人工发表。
- 微信没有“免登录一键发布链接”。草稿临时链接（`tempkey`）是只读预览页，没有发表按钮；正式发布必须由管理员在后台扫码登录后手动操作，或由已认证企业号通过接口完成。

因此正式发布分两种情况：

**情况 A：个人/未认证账号 —— 引导后台人工发布（默认兜底）**

草稿创建成功后，如果接口发布返回 `48001`，或已知账号为个人/未认证主体，不要反复重试接口。**按第 3.5 节自动打开公众号后台草稿编辑器**，让用户直接在编辑器中点「发表」，并告知：

> 你的公众号是个人（或未认证）主体，微信不开放接口正式发布。我已经帮你在后台打开了这篇草稿，排版和图片都已就绪，你只需在编辑器右下角点「发表」即可。
>
> 如果希望以后全自动接口发布，需要把公众号升级为企业主体并完成微信认证。

**情况 B：已认证企业账号 —— 接口正式发布**

用户明确要求“发布”“发表”“正式发出去”时，仍必须先完成草稿（并让用户用草稿链接预览确认）。

发布前必须向用户二次确认：

> 请确认是否正式发布：公众号「{账号}」，标题「{标题}」。发布后将进入微信发布审核/公开流程，可能不可逆。请回复“确认发布”后我再继续。

只有用户在本轮明确回复确认，才允许：

1. 设置 `confirm_publish=true`；
2. 调用 `freepublish/submit`；
3. 调用 `freepublish/get` 轮询或查询状态；
4. 成功后反馈正式文章链接；失败时反馈平台状态和下一步处理。
5. 若此时仍返回 `48001`，说明账号其实无发布权限，转情况 A 的后台人工发布指引。

### 3.5 自动打开后台草稿编辑器（草稿创建后必做）

草稿通过接口创建成功后，**不要只把草稿箱链接和标题发给用户让其自行翻找**。Agent 应紧接着用浏览器自动化打开公众号后台，直接定位并点开刚创建的草稿，让用户落在编辑器页面，可直接点「发表」。

接口返回的 `media_id` 是 API 侧 ID，公众号后台网页使用另一套 `appmsgid`，无法仅凭 `media_id` 拼出后台编辑链接。因此必须通过浏览器登录后台后，在草稿箱中按标题定位。

**操作步骤（Agent 用浏览器工具执行，不让用户手动操作）：**

1. 调用 `open_url_in_browser` 打开 `https://mp.weixin.qq.com/`。
2. 截图判断登录状态：
   - 若显示扫码登录页，调用 `interaction.request_action`（type=browserControl）提示用户用公众号管理员微信扫码登录；用户完成后继续。
   - 若已登录（看到后台首页），直接继续。
3. 点击左侧菜单「内容管理」展开子菜单，再点击「草稿箱」。
4. 在草稿箱页面定位目标文章：
   - 草稿箱右上角有搜索框（placeholder 为「输入标题/关键词」），优先在搜索框中输入文章标题进行搜索，确保准确定位。
   - 若刚创建的草稿明确排在第一位且标题可见，也可直接点击该卡片。
5. 鼠标悬停在目标文章卡片上，会浮现操作按钮；点击编辑图标（铅笔图标）打开文章编辑器。注意不要误点删除图标或「发表」按钮。
6. 等待编辑器页面加载完成（URL 包含 `appmsg_edit&action=edit`），截图确认标题、封面和正文已就位。
7. **从浏览器地址栏复制完整编辑器 URL**（必须包含 `appmsg_edit&action=edit` 和 `appmsgid` 参数），记录下来用于最终交付。这是用户可以直接点击打开、然后点「发表」的链接，与只读的草稿临时预览链接（`tempkey`）不同。
8. 告知用户：草稿已在后台编辑器中打开，确认排版无误后可直接点右下角「发表」；同时将第 7 步复制的编辑器 URL 作为"可直接点击发表的链接"在最终回复中明确交付。

**注意事项：**

- 浏览器会话会保持登录态，后续再次上传时若未过期可跳过扫码。
- 草稿箱中可能有多篇同名或相似标题的文章，务必以本次创建返回的标题为准；用搜索框定位最可靠。
- 打开编辑器即可，不要替用户点击「发表」——正式发表必须由用户本人确认后操作。
- 若浏览器自动化失败（页面结构变化、网络异常等），回退为原有话术：给出 `https://mp.weixin.qq.com/` → 草稿箱 → 按标题查找 → 点「发表」。

## 4. 运行脚本

脚本路径：

```bash
scripts/wechat_mp_api_publish.py
```

支持动作：

| action | 用途 |
|--------|------|
| `setup-local` | 把用户已提供的 AppID/AppSecret 保存到权限为 `0600` 的本地配置 |
| `check-config` | 检测本地配置和当前公网出口 IP，不调用微信发布接口 |
| `verify-config` | 调用微信接口验证 AppID、AppSecret 和 IP 白名单 |
| `preflight` | 不调用微信接口，检查标题字节数、正文、封面和图片是否可用 |
| `create-draft` | 创建草稿（返回草稿临时预览链接；Agent 须随后按 3.5 节获取并返回后台编辑器直达链接，两个链接成对交付） |
| `publish` | 发布已有草稿，必须显式确认 |
| `status` | 查询发布任务状态 |
| `workflow` | 创建草稿，并按 payload 决定是否发布 |

常用环境变量：

```bash
WECHAT_MP_APPID=公众号AppID
WECHAT_MP_APPSECRET=公众号AppSecret
TASK_ARTIFACT_DIR=当前任务产物目录
```

可选环境变量：

```bash
WECHAT_MP_ACCESS_TOKEN=临时直连token
```

优先使用 AppID/AppSecret 由脚本自动获取稳定版接口凭据。`WECHAT_MP_ACCESS_TOKEN` 仅用于已有安全 token 的临时场景。

环境变量只用于自动化测试和用户本地电脑上的自动化执行。面向普通用户时，Agent 应先给官方链接和路径，再根据用户选择按当次使用或保存本地处理。

## 5. Payload 格式

Agent 生成 payload，用户不需要手写。仅在用户明确要求上传、预览或发布时，Agent 才创建临时发布包；旧的 `markdown_path` 仅用于迁移已有稿件。

### 5.1 发布包（生产默认）

飞书交付文档负责阅读、审核、备选标题、验真和运营建议；发布包只包含会进入微信正文的字段。它在用户发起上传、预览或发布操作后生成，位于当前任务产物目录，不是文章写作阶段的必备文件。

```json
{
  "schema_version": 1,
  "title": "文章最终标题",
  "author": "公众号名称",
  "digest": "120字以内摘要",
  "body_markdown": "只包含最终标题以下的正文、正文图片和图片注释",
  "cover_url": "https://example.com/cover.jpg",
  "layout_profile": "clean",
  "need_open_comment": 0,
  "only_fans_can_comment": 0
}
```

硬规则：

1. `body_markdown` 只能包含正文、正文小标题、引用、列表、正文图片和图片注释。
2. 正文过长时可使用 `body_markdown_path` 代替 `body_markdown`，路径相对发布包所在目录解析；两者必须且只能存在一个。
3. 封面图、备选标题、内容验真、运营策略、编辑备注、提示词都不得进入正文。
4. 脚本发现上述区块标题时会拒绝创建草稿，而不是猜测删除。
5. 发布命令使用 `--publish-package /absolute/path/publish_package.json`；包内标题、正文、封面和排版预设会覆盖旧 Markdown 输入。

### 5.2 兼容 Payload（迁移已有稿件）

```json
{
  "appid": "公众号AppID，建议由本地安全配置注入",
  "appsecret": "公众号AppSecret，建议由本地安全配置注入",
  "title": "文章最终标题",
  "author": "公众号名称或用户确认的作者",
  "digest": "120字以内摘要",
  "markdown_path": "/absolute/path/文章最终标题.md",
  "cover_path": "/absolute/path/cover.jpg",
  "layout_profile": "clean",
  "content_source_url": "",
  "need_open_comment": 0,
  "only_fans_can_comment": 0,
  "publish": false,
  "artifact_dir": "/absolute/path/current-task-output"
}
```

可替代字段：

- `content_html`：已有微信正文 HTML 时使用；
- `markdown`：直接传 Markdown 字符串；
- `cover_url`：封面是公网 URL 时使用；
- `cover_media_id`：封面已作为永久素材上传时使用；
- `media_id`：发布、查草稿时复用已有草稿；
- `publish_id`：查询发布状态时使用。

## 6. 内容转换规则

1. 正文来源优先级：`content_html` > `markdown` > `markdown_path`。
2. **生产发布来源优先级：** `publish_package` > `content_html` > `markdown` > `markdown_path`。没有发布包时脚本会给出兼容输入警告；不得将整篇飞书交付文档直接导出后作为 `markdown_path`。
3. 创建草稿前先运行 `preflight`；标题必须不超过 64 UTF-8 字节，中文标题通常约 21 个汉字，不能仅按字符数判断。
4. **没有独立的微信“自动排版 API”。** `draft/add` 接收 HTML 内容，Skill 必须在调用前将 Markdown 转为微信可接受的内联 HTML。微信可能过滤少数 CSS 属性，最终效果以微信草稿预览为准。
5. `layout_profile` 支持两种排版预设：
   - `clean`（默认）：适合深度文章，正文两端对齐、加大行距、带左侧强调线的小标题、浅灰引用块、图片间距和分隔线。
   - `minimal`：只使用更保守的基础字号、行距、标题和引用样式，适合账号对复杂样式兼容性要求更高的场景。
6. Markdown 一级标题若与最终标题一致，创建草稿时从正文移除，避免重复标题；`---`、`***` 和 `___` 会转换为分隔线。
7. 正文图片会先通过 `/media/uploadimg` 上传，正文中替换为微信图片 URL；超过 1MB 时，Skill 在本地模式会自动压缩后重试。macOS 使用系统图片工具；其它系统使用已安装的 Pillow。
8. 封面图会通过 `/material/add_material?type=image` 上传为永久素材，作为 `thumb_media_id`。
9. 若用户强调“不要 HTML 模拟”，仍允许生成接口所需 HTML，但不得把该 HTML 当作预览交付给用户。

## 7. 账号权限与异常处理

常见错误处理：

| 错误 | 用户可理解说明 |
|------|----------------|
| `40164` | 当前调用 IP 未加入公众号 API IP 白名单。请把微信错误回显的 `invalid ip` 所在 `/24` 网段加入白名单 |
| `40013` | AppID 不正确 |
| `40125` | AppSecret 不正确 |
| `40243` | AppSecret 已被冻结，需要后台解冻 |
| `48001` | 账号无接口发布权限，通常是个人或未认证主体，改走后台人工发表 |
| `53503` | 草稿未通过发布检查，需要检查标题、封面、正文图片或声明 |
| `53504/53505` | 需前往公众平台官网处理草稿后才能发表 |
| `89503` | 本次调用需要管理员确认 |

遇到 `48001`：

- 如果发生在 `draft/add`，说明草稿接口也无权限，停止并提示账号不支持接口创建草稿。
- 如果发生在 `publish`，保留“已创建草稿”的结果，按 3.4 情况 A 和 3.5 节自动打开后台草稿编辑器，让用户直接点「发表」。
- 这是账号资质限制（个人/未认证主体），不是配置或脚本错误，不要重复重试接口，也不要要求用户再改配置或加白。
- 只在用户明确表示账号已升级为已认证企业主体后，才重新尝试接口发布。

遇到“未完成直连配置”：

- Agent 先运行 `check-config` 并展示当前公网出口 IP。
- Agent 先提供微信开发者平台链接和准确菜单路径。
- 用户可直接提供 AppID/AppSecret 用于本次任务，也可要求 Agent 运行 `setup-local` 保存本地。
- 用户只在微信开发者平台完成 IP 白名单配置。
- Agent 运行 `verify-config`；成功后自动继续，失败则根据错误码给出一个明确修正动作。
- 不要把 AppSecret 写入公开文档、日志或聊天记录。

## 8. 交付给用户的话术

### 草稿完成

**强制要求：以下两个链接必须同时出现在最终回复中，缺一不可，不得合并、不得省略。**

必须包含：

- 公众号名称；
- 标题；
- 草稿是否创建成功；
- **【必填】草稿临时预览链接**（接口返回的 `tempkey` 只读链接，标注为"只读预览（手机端看排版）"；若接口未返回，注明"可在编辑器中点「预览」获取"，但仍须给出编辑器链接）；
- **【必填】后台编辑器直达链接**（从浏览器地址栏复制，含 `appmsg_edit&action=edit` 和 `appmsgid`，标注为"点击发表（后台编辑器直达）"，用户点击后可直接在编辑器中点「发表」）；
- 已自动在后台编辑器中打开该草稿；
- 下一步：确认排版后如何发表。

**禁止行为：**
- 禁止只给临时预览链接而不给编辑器直达链接；
- 禁止只给编辑器链接而不给临时预览链接（除非接口确实未返回且已说明）；
- 禁止以"浏览器已打开"为由不返回编辑器链接；
- 禁止让用户自行去草稿箱翻找文章；
- 两个链接必须在同一条回复中相邻出现，各自标注清楚用途。

示例：

> 草稿已创建：{标题}。
>
> 只读预览（手机端看排版）：{草稿临时链接}
>
> **点击发表（后台编辑器直达）：{编辑器URL}**
>
> 我已在公众号后台打开了这篇草稿，确认排版无误后：
> - 个人号或未认证号：直接在编辑器右下角点「发表」。
> - 已认证企业号：回复 "确认发布"，我通过接口正式发布。

### 发布完成

必须包含：

- 发布任务是否提交；
- 发布状态；
- 正式文章链接（如已成功）；
- 若仍在发布中，说明稍后继续查询。

示例：

> 发布任务已提交，目前状态：发布中。我会用发布状态接口继续查询；成功后反馈正式文章链接。
