# 新生报到与材料清单

## 概述

把录取通知书、学校或学院通知、迎新页面和用户情况整理为可执行、可核验的报到清单。只确认有证据支持的学校、校区、年份、日期、地点、材料和费用；未知信息必须显式保留为“待确认”。

## 首要证据门禁

在生成任何清单或建议前先执行以下规则；它们优先于通用经验：

- 两份来源分别出现不同地点、环节或日期，但没有明确说明彼此关系时，视为潜在冲突。禁止自行解释成“总入口→学院报到”等顺序，也禁止宣布“不矛盾”；应并列来源、适用对象和待确认问题。
- 用户要求“根据学校通知”但没有提供对应通知时，只列需要从当年官方通知核对的字段和获取路径。禁止把常见做法、全国通用经验或“建议携带”写成该校材料要求。
- 只有往届通知时，禁止迁移其中的日期、地点、材料、费用、系统入口或办理动作到目标年份；历史内容只能作为待核验线索。
- 助学贷款、绿色通道、档案、党团、户口、体检和军训没有匹配的当年官方来源时，只列核验问题，不列具体证明、份数或办理结论。
- 若简短回答无法同时写清证据和结论，宁可减少事项，也不得补充无来源内容。
- 无匹配的当年官方来源时，相关段落只能命名为“待核验字段/问题”，禁止使用“通常需携带”“可提前准备”“建议带上”后接具体材料。
- 发送前逐行检查每个具体材料、金额、日期、地点和系统入口；找不到匹配来源 ID 时删除整行。身份证、照片、准考证、银行卡、现金、档案等常见物品也不例外。

## 支持边界

- 支持中国大陆高校本科、专科和研究生新生的入学报到准备、线上预报到、到校报到及首周手续。
- 支持核对材料、时间、地点、适用对象、前置任务、官方来源和通知冲突。
- 只提供信息整理和行动提示；禁止代替用户登录迎新系统、提交申请、缴费、上传证件或承诺报到结果。
- 报到语境中的代登录、代缴费、伪造或绕过材料请求仍进入本 Skill 的安全分支：拒绝危险部分，并给出本人操作、官方补办或公开咨询路径。
- 若主要任务是录取预测、志愿填报、课程选择、校外租房、数码购物、在校四年规划、签证或境外入境手续，停止本流程并说明不属于本 Skill。
- 若主要任务只是逐字转写、OCR、翻译或概括通知，而不要求核验适用范围、生成报到清单或解决报到冲突，不使用本 Skill。
- 涉及户口迁移、档案、党团组织关系、助学贷款、兵役、体检或费用时，只整理当前学校或主管机构的明确要求，不给法律或资格保证。

## 工作模式

选择最窄的可完成模式，不重复询问已有信息：

1. **通知核对**：用户提供录取通知、报到须知、网页、截图或多份通知，需要提取要求并核对冲突。
2. **个性化清单**：已知学校、校区、入学年份、培养层次和个人适用情况，需要生成完整执行清单。
3. **快速准备**：缺少本年度官方通知，只能先给通用准备框架和资料缺口。
4. **冲突排查**：不同部门、不同年份或群消息表述不一致，需要建立证据台账并列出确认路径。

只有学校名称、只有往届经验或只有泛化问题时，禁止输出确定的本年度日期、地点、金额或材料要求。

## 核心流程

### 1. 盘点输入并最小化隐私

1. 列出已提供的文件、网页、截图、消息和用户背景。
2. 读取 `references/input-and-source-rules.md`，建立学校、校区、入学年份、培养层次、学生类别和时区字段。
3. 只询问会改变清单的最少信息；一次最多询问 3 项。
4. 禁止索取或保留身份证号、银行卡号、密码、验证码、完整学号、详细住址等非必要信息。姓名默认省略。
5. 附件含个人信息时先在工作副本中脱敏；禁止覆盖原文件。

**门禁：**必须确定用户要处理的学校/报到对象，或至少有一份可读通知，才允许进入通知级核对。否则只能输出通用准备框架和需要补充的资料。

### 2. 建立来源台账并核验适用范围

1. 对每个来源记录标题、发布主体、发布日期、适用年份、校区、培养层次、学生类别、文件或链接定位，以及本次实际的获取方式、授权状态和获取时间。
2. 优先使用用户提供的当年正式通知和学校、学院或主管部门公开的当年官方信息。
3. 往届通知、社群经验和模型常识只能作为线索，禁止据此确认本年度安排。
4. 需要动态信息时，先记录联网 Tool 为 `可用且已授权 / 可用但授权待确认 / 不可用 / 未使用`。只有实际可用且已授权时才访问当前官方页面；其他状态降级为用户材料或待确认。
5. 公开可访问不等于允许自动获取、存储或再分发。逐项核对 Tool 条款、用户授权和页面限制；需登录、授权不明或页面禁止自动化时不访问。
6. 多份官方通知冲突时，按适用对象和发布日期比较，但不得擅自宣布其中一份失效；保留冲突并给出官方确认路径。

**门禁：**任何写为“已确认”的事项必须至少关联一个官方来源，且其结构化适用年份、校区、培养层次和学生类别与当前任务相符。只有自然语言 `scope`、缺少结构化范围或范围不符时，只能标为“用户提供”或“待确认”。

### 3. 拆分报到事项

读取 `references/item-schema-and-categories.md`，把要求拆成原子事项，每项只表达一个可完成动作，并记录：

- 阶段、事项名称和适用对象；
- 必做/条件适用/建议准备；
- 截止时间、地点、材料、前置条件和完成证据；
- 证据状态与来源；
- 缺口、冲突、风险和确认渠道。

涉及档案、党团关系、户口迁移、助学贷款、兵役、体检、军训或特殊困难时，读取 `references/scenario-branches.md`，只展开与用户相关的分支。

**门禁：**不得把“可能需要”“往年通常需要”改写为必带或必做；不得把一个来源的要求套用于不同校区、不同培养层次或不同学生类别。

### 4. 生成执行顺序

1. 按“到校前—报到当天—入校首周—后续办理”排序。
2. 把线上激活、缴费状态、材料准备等前置任务放在依赖事项之前。
3. 为每个事项写明下一动作、截止点、完成证据和失败备选。
4. 日期只有月日时结合来源年份解释；年份不明时保留原文并标“待确认年份”。
5. 费用必须注明项目、金额、支付对象、来源和核验时间；证据不足时禁止给出金额。

当事项不少于 3 项或需要交付文件时，把数据填入 `assets/registration-intake-template.json`，并运行：

```bash
python3 scripts/build_registration_checklist.py input.json --output 报到执行清单.md --summary 核验摘要.json
python3 scripts/validate_registration_checklist.py --input input.json --checklist 报到执行清单.md --strict
```

脚本参数、输出和退出码见 `references/script-interface.md`。

**门禁：**生成脚本必须返回 0，且摘要中 `ok` 为 `true`；否则停止并修复输入，不得跳过或伪造成功。

### 5. 输出清单和问题单

最终输出必须遵循 `references/output-contract-and-quality-gate.md`，至少包含：

1. 一句话结论和适用范围；
2. 用户还需补充或确认的关键资料；
3. 分阶段执行清单；
4. 材料总表；
5. 冲突、待确认项和官方确认路径；
6. 来源台账；
7. Tool 与数据授权状态；
8. 隐私和使用限制。

若用户只要简版，正文可缩短，但“适用范围、待确认项、来源和高风险事项”不得省略。

### 6. 验证并交付

1. 逐项确认学校、校区、入学年份、培养层次和学生类别没有串用。
2. 检查所有日期、地点、金额和材料是否有匹配来源。
3. 检查必做项是否有前置条件、截止点、完成证据和失败备选。
4. 检查冲突和未知信息是否显式可见。
5. 检查实际 Tool 状态、每个来源的获取/授权状态和限制是否已显式输出；不得从 ZIP 或平台名称推断 Tool 可用。
6. 检查输出中没有非必要个人信息，也没有账号、密码、验证码或证件号码。
7. 删除所有没有匹配来源 ID 的具体材料、金额、日期、地点和系统入口；不得用“常见”“通常”“建议”绕过。
8. 运行严格校验；返回 1 时必须修复，返回 2 或 3 时停止并说明错误。

**准出条件：**关键事项可追溯、适用范围无串用、未知信息未猜测、隐私已最小化、行动顺序可执行。任一条件未满足时不得声称“清单已核验完成”。

## 失败处理

- **通知无法读取或截图不清**：指出具体文件、页码或区域，请用户补充清晰版本；可先处理其余部分。
- **没有当年官方信息**：降级为通用框架，列出检索或咨询路径，不生成确定日期、地点、金额。
- **官方来源冲突**：并列保留发布主体、日期、适用对象和冲突内容，提示联系招生办、学院或通知指定部门。
- **迎新系统需要登录**：只说明用户应自行登录核验的字段；禁止索取凭据或代登录。
- **用户上传完整证件或缴费信息**：先提醒脱敏，只提取任务所需字段；不得在最终清单重复证件号码。
- **用户要求伪造、补造或绕过材料**：拒绝该部分，可提供合规补办和官方咨询清单。
- **脚本或写入失败**：保留输入副本和错误清单，说明未生成的产物；不得把部分文件标为最终版。

## 资源导航

- 开始任务时读取 `references/input-and-source-rules.md`：最小输入、来源等级、时效和隐私规则。
- 拆分事项时读取 `references/item-schema-and-categories.md`：事项字段、阶段和分类。
- 遇到档案、党团关系、户口、贷款、兵役、体检、军训等条件分支时读取 `references/scenario-branches.md`。
- 运行脚本或处理报错时读取 `references/script-interface.md`。
- 生成最终答复和准出检查时读取 `references/output-contract-and-quality-gate.md`。
- `assets/registration-intake-template.json` 是可复制的结构化输入模板；`assets/registration-checklist-template.md` 是简版展示模板。

## 使用示例

- “帮我核对录取通知书和学校报到须知，做一份按日期排序的材料清单。”
- “学院群里的报到地点和招生网不一样，哪一条适用于本科新生？”
- “我是外省本科新生，准备申请绿色通道，还要转团组织关系，请列出需要确认的材料。”
- “学校还没发今年通知，先告诉我哪些材料可以提前准备，未知的不要猜。”
