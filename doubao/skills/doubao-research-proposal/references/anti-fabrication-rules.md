# 防虚构规则

## 匿名化与字数约束（针对匿名评审材料）

匿名评审材料只保留模板允许的非身份化信息，不得出现姓名、单位、导师、职务、获奖、刊物/出版社/发表时间等可识别身份的信息。字数按任务书执行；如国社科活页，选题说明控制在 300 字以内、论证总字数控制在 7000 字以内，预期成果与参考文献从简。占位符也需匿名化，例如 `【待补充：请填写符合匿名要求的代表性成果名称及排序】`。

## 谨防幻觉捏造的信息

申请人姓名、单位、职称、学历、经历、团队成员、合作单位、已发表论文、专利、获奖、已承担项目、个人简历、预实验数据、实验结果、统计数据、预算金额、经费分配、具体指标、参数、性能数据、研究对象细节、未公开方案、未发表成果等，如果用户没有明确提供，都必须留空。

未经论文、用户材料或可靠文献明确支持，不得在正文中使用“首次”“首个”“填补空白”“国际领先”等强声明表达。未完成检索时，应改成：“拟探索”；“有望形成”；“尝试建立”等。

## 占位符格式

统一使用 `【待补充：请填写XXX内容】`。XXX 需要说明字段、范围、格式或建议来源。例如 `【待补充：请填写本项目拟使用的数据来源、样本规模、获取方式及伦理审批状态】`。

错误格式包括 `【待补充】`、`【请补充】`、`TBD`、空括号和没有补充指引的注释。

## 可生成内容

可以生成学术写作结构、通用背景、公开常识、逻辑过渡、可行性分析维度、风险类型、时间规划框架和基于用户材料的改写。所有带有具体数值、具体机构、具体论文、具体成果或具体实验结果的内容都必须有用户材料或可核验来源支撑。

## 事实、基本信息与 AI 建议分层

执行时必须维护三类边界：基本信息只记录任务书和模板约束；事实必须有用户材料、模板原文或可核验来源；AI 建议只能作为待确认的写作策略、候选创新点、逻辑优化或风险补强方案。AI 建议在用户确认前不得写入正式正文为确定性结论。

统计数据属于高风险事实。任何百分比、样本量、时间范围、显著性、置信区间、模型性能、调查结论、预算金额或阶段指标都必须有明确来源和口径；缺来源时使用占位符。不得把相关性写成因果，不得混用均值/中位数/比例，不得让分项合计与总量矛盾。

## 文献来源分层



处理文献时按以下优先级执行：



1. **用户已提供或用户论文中已引用的文献**：最优先使用。只要 Agent 已经调研过该文献、了解其内容，即视为已确认文献，直接用于正文引用和参考文献清单，不需要加"待核验"标签。与当前项目高度相关的引用应系统整理进综述，不应轻易标为待补充。

2. **主动检索且可核验的真实文献**：必须主动调用已有文献调研/检索类 Skill 补充检索，尤其关注近5年工作和近2-3年前沿进展。只要 Agent 已经读过该文献并了解其内容，即可正常引用，不需要加"待核验"标签。

3. **无法确认的具体引用或事实**：只有在 Agent 尚未真正调研过该文献、无法说明其内容，或作者、题名、年份、来源存在明显矛盾时，才使用占位符。



## 引用处理

用户提供的文献按用户指定格式整理为正文引用和 BibTeX；用户未指定时默认采用 GB/T 7714。检索到并可核验的文献可以列入参考文献，但 URL、检索页或系统来源标签只作为核验线索，不得以 Markdown 链接或裸链接形式进入正式正文。没有具体文献时，只写引用占位符或“建议补充的文献方向”，不要生成看似真实的作者、题名、期刊和年份。防虚构禁止编造文献，但不禁止主动检索真实文献。

## 参考文献完整性要求

参考文献不应只给示例或框架。只要用户材料、用户论文参考文献或主动检索结果中已经存在真实可核验文献，Agent 必须尽量完整整理并写入 `references.bib` 或参考文献清单。

执行时必须区分三类状态：

1. **已采用文献**：正文已经引用或用于支撑论证的文献，必须进入参考文献清单。只要 Agent 已经调研过该文献、了解其内容，就是已确认文献，无需添加"待核验"标注。
2. **已识别但未采用文献**：用户材料中出现、但与当前论证关系弱或尚未使用的文献，应在 TODO 或文献备选清单中说明，不要遗忘。
3. **待核验文献**：仅当 Agent 尚未真正读过该文献、无法说明其内容，或作者、题名、年份、来源存在明显矛盾时，才使用占位符并说明需要核验什么。对于已经调研过、了解内容的文献，不应因为"未逐字确认某个技术细节"就标注待核验。

如果用户已提供一批参考文献，Agent 不得仅挑 2-3 条示例后把其余全部标为待补充；应先系统整理，再基于相关性筛选。
