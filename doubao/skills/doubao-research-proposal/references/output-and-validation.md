# 输出结构与验证规范

## Markdown 默认输出

默认创建 `research-proposal/` 目录，结构如下：

```text
research-proposal/
├── PROPOSAL.md
├── STRATEGIC_LOGIC.md
├── FACTS_AND_SUGGESTIONS.md
├── TODO_LIST.md
├── REVIEW_FIX_LOG.md
├── figures/
└── references.bib
```

`PROPOSAL.md` 每个章节使用 Markdown 标题层级，正文中保留所有 `【待补充：...】` 占位符。

`STRATEGIC_LOGIC.md` 记录“科学问题 -> 研究目标 -> 研究内容 -> 技术路线 -> 证据/待补充项”的映射。每一项都应标注支撑类型：用户事实、可核验文献、模板要求、AI 建议或待补充事实。

`FACTS_AND_SUGGESTIONS.md` 用于严格区分三类信息：基本信息、事实、AI 建议。建议使用以下栏目：信息类别、内容、来源、确认状态、进入正文的位置。AI 建议在用户确认前不得写成事实性结论。

`TODO_LIST.md` 包含提案基本信息、待补充项总数、按章节排序的待补充项、补充建议和填写说明。每个待补充项包含所在章节、位置说明、需要补充内容、补充建议。

`REVIEW_FIX_LOG.md` 记录模拟评审和终稿审查发现的问题，以及已经主动完成的正文修订。每条记录包含问题类型、严重程度、原位置、处理方式、是否仍需用户确认。若发现问题但因缺少用户事实无法修订，应说明需要补充的事实，而不是虚构内容。

`references.bib` 只保存用户提供或检索可核验的文献。没有具体文献时，文件可为空或写注释提示，不要生成虚假 BibTeX。

## 参考文献与来源格式统一

正式正文统一使用用户确认的学术引用格式；若用户未指定，默认采用 GB/T 7714（顺序编码制），正文使用 `[1]`、`[2]` 等编号引用，文末“参考文献”按 GB/T 7714 条目列出。所有正文文内引用都必须同时满足两项要求：一是在正文文末“参考文献”部分提供完整条目；二是在 `references.bib` 中同步保存对应 BibTeX 条目。通过检索工具获得的 URL、系统来源链接或平台追溯标签，只用于核验来源和整理参考文献，严禁以 Markdown 链接（如 `[题名](URL)`）或裸链接形式保留在正式申请书正文中；交付前应将其转换为 GB/T 7714 或用户指定的标准学术引用，并同步到文末参考文献与 `references.bib`，或移入 `FACTS_AND_SUGGESTIONS.md` / `TODO_LIST.md` 作为来源线索。

## 输出说明附加提示

最终交付说明中应额外提示用户：当前 Skill 主要适用于基于已有研究成果、研究基础和明确选题来撰写或优化立项书；文献调研能力用于补充真实可核验材料，但可能无法全面覆盖相关领域。若用户需要更完整的领域调研，可提供已有文献库、核心论文清单、检索关键词或综述材料，也可调用豆包已有的文献调研类 Skill 进一步补充内容。

## 终稿检查清单

交付前检查以下事项：

- **任务书一致性**：章节名称、顺序、数量、字数、匿名化、模板字段、输出格式是否与用户确认版本和模板要求一致。
- **信息分层**：基本信息、事实和 AI 建议是否清晰分开；正文是否只包含已确认事实与已确认建议。
- **事实边界**：正文是否存在用户未提供的具体个人信息、成果、预算、实验数据、统计结果、模型参数或研究对象细节。
- **参考文献完整性**：核对正文文内引用、文末“参考文献”部分和 `references.bib` 是否一一对应；正文引用必须能在文末参考文献和 `references.bib` 中同时找到完整条目，`references.bib` 也不应包含未在正文或备选清单中说明的孤立条目。
- **占位符准确性**：是否存在“误用占位符”，即原本已有真实来源却被标为待补充；所有占位符是否使用 `【待补充：具体说明】` 格式；TODO 清单是否覆盖所有占位符。
- **重复内容**：是否存在相邻章节重复叙述同一背景、同一创新点或同一技术路线；若有，应合并、删减或改为交叉引用。
- **统计学错误**：百分比、分项合计、样本量、时间范围和统计口径是否一致；是否把相关性写成因果；是否混用均值、中位数、比例、显著性或置信区间；是否存在无来源的统计结论。
- **逻辑链自洽**：每个研究内容是否服务于目标，每个目标是否回应核心问题，创新点是否由文献缺口自然推出。
- **图表一致性**：图表标题、图注、数据口径和正文结论是否一致，图表不得替代缺失事实。
- **语言要求**：语言、语气、术语和格式是否符合用户要求。

## 评审后主动修订规则

模拟评审或终稿审查发现问题后，优先修订 `PROPOSAL.md`、`STRATEGIC_LOGIC.md`、`FACTS_AND_SUGGESTIONS.md` 或 `TODO_LIST.md`。修订完成后再更新 `REVIEW_FIX_LOG.md`。只有在缺少用户事实、缺少模板原文或涉及用户决策时，才把问题保留为待确认项。
