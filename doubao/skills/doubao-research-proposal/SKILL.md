# Doubao Research Proposal: 学术立项书助手

## 概述

本 Skill 协助用户撰写、审查和优化学术提案或研究计划。它重点解决三类问题：事实边界不清、论证链条不完整、正文与任务书或模板要求不一致。

## 使用场景

适用于基金申请（如国自然、国社科）、博士后或人才计划、学位论文开题报告、保研/考研/申博/访学/联合培养研究计划、科研立项书等场景。用户可能会说“帮我写基金申请”“优化开题报告”“审查研究计划”“根据已有成果写立项书”“检查申请书是否符合模板”。

不适用于全面系统综述、纯文献计量分析、从零到一的科研选题/idea 生成、单纯论文润色、法律/医疗/财务等高风险结论判断。

- 立项/基金/开题报告交付→本 Skill
- 需要完整领域调研，应配合doubao-academic-researcher Skill
- 需要语言润色、论文正文撰写，使用doubao-academic-polish
- 想法价值/投稿评审→doubao-academic-evaluator

本 Skill 需要用户已具备一定研究基础（对应课题的论文、研究计划、实验数据或初步成果等），提供的研究计划/内容需有一定雏形，作为扩写和优化的基础。从零到一的科研选题与 idea 生成不在本 Skill 范围内。

## 信息分层规则

执行任何写作或审查前，先建立三类信息边界：

1. **基本信息**：项目类型、任务书/模板要求、申报类别、语言、章节、字数、截止时间、匿名化要求、输出格式等任务参数。基本信息只用于约束结构与格式，不得被包装成学术事实。
2. **事实**：用户材料、可核验文献、公开模板要求、真实数据、已发表成果、实验结果、统计口径等有来源支撑的内容。事实写入正文时必须能回溯来源；缺来源时使用 `【待补充：...】`。
3. **AI 建议**：选题定位、章节组织、创新点候选、技术路线优化、表达策略、风险补强建议等推断性内容。AI 建议在用户确认前只能出现在策略说明、待确认清单或草稿标注中，不得伪装成既定事实。

## 核心流程（分阶段确认）

1. **确认任务书与基本信息**。识别提案类型、资助机构或目标受众，读取用户模板或预置模板，形成基本信息表并同步到 `FACTS_AND_SUGGESTIONS.md`；这样可以让模板要求先于正文发挥约束作用，避免后续返工。
2. **整理事实台账与材料边界**。优先读取用户提供的论文、参考文献、BibTeX、文献笔记、实验数据、已有草稿、评审意见、CV/成果清单等材料，整理为“已确认事实 / 待核验事实 / 缺失事实”并更新 `FACTS_AND_SUGGESTIONS.md`；这样可以避免把 AI 建议误写成事实。
3. **补充文献检索与定位**。在用户材料之外，调用已有文献调研/检索类 Skill 如`doubao-academic-researcher`补充真实可核验文献，重点覆盖近5年工作和近2-3年前沿进展，同步更新 `FACTS_AND_SUGGESTIONS.md` 的文献证据状态和 `references.bib`；这样可以降低论证只依赖用户已有材料或旧文献的风险。
4. **确认论证逻辑**。设计从“科学问题 -> 研究目标 -> 研究内容 -> 技术路线 -> 证据/待补充项”的闭环逻辑，并把候选科学问题、创新点和技术路线标注为 AI 建议，更新 `RESEARCH_LOGIC.md`；这样可以让用户先确认方向，再进入正文写作。
5. **生成正文草稿**。基于已确认的基本信息、事实和论证逻辑生成 `PROPOSAL.md` 正文，每个章节使用 Markdown 标题层级，客观表述现状，逻辑推导未来，对缺失事实使用 `【待补充：...】` 占位，并同步更新 `TODO_LIST.md`；这样可以在保证可读性的同时守住事实边界。
6. **审查并主动修订**。检查结构、任务书一致性、重复内容、统计学错误、参考文献完整性和逻辑一致性；如不满足交付门槛，需首先积极查证、补充或修改相关内容。发现问题后先修改 `PROPOSAL.md`、`RESEARCH_LOGIC.md` 或相关文件，再将修订记录写入 `REVIEW_FIX_LOG.md`，这样可以避免只提出评审意见而没有改进正文。
7. **终稿确认**。展示最终文件结构、使用模板、事实缺口、AI 建议采纳情况、修订记录和检查结果，提醒用户补齐所有占位符并人工核对关键事实；这样可以让正式提交前的风险集中暴露。

## 输入与输出

**输入要求**：
- 基本信息：研究主题、研究方向、任务书/模板要求、申报类别、字数/格式限制、匿名化要求、输出格式。
- 关键材料（应主动引导用户尽量提供）：初步研究想法、已发表成果摘要、关键实验数据、核心参考文献、已有草稿或文献笔记。仅有研究主题、研究方向和目标机构、但无任何成果或雏形时，应明确告知用户本 Skill 不适用于从零到一的 idea 生成，仅能生成框架性草稿，并主动引导补充论文、研究计划或已有成果。
- 模板：可使用 Skill 预置模板；若用户提供自定义模板、学校/单位模板或最新版模板，优先使用用户模板。

**默认输出目录**：`research-proposal/`。

**默认输出文件**：
- `PROPOSAL.md`：核心提案/计划书正文，只写入用户确认事实和已确认的写作方案。
- `RESEARCH_LOGIC.md`：逻辑映射表（目标-路线-证据对应关系），区分事实支撑与 AI 建议。
- `FACTS_AND_SUGGESTIONS.md`：基本信息、已确认事实、待核验事实、AI 建议及用户确认状态。
- `TODO_LIST.md`：待补齐的事实清单、模板字段、逻辑增强建议。
- `REVIEW_FIX_LOG.md`：模拟评审发现的问题、已执行的正文修订、仍需用户决策的问题。
- `references.bib`：经过核验的参考文献。

**输出前检查**：交付前必须查阅 [output-and-validation.md](references/output-and-validation.md) 查缺补漏，重点核对输出结构、参考文献同步、系统来源链接清理、任务书一致性、重复内容、统计学错误和终稿说明。

**输出说明附加提示**：
输出说明附加提示：最终交付说明中必须提醒用户：

本 Skill 不是用于从零到一生成科研 idea，主要适用于用户已有研究成果、研究基础或明确雏形的场景；若用户只有主题没有基础，仅能产出框架性草稿，需用户补充对应论文、研究计划或初步成果。
文献调研不是本 Skill 的重点，内置的文献检索能力仅用于补充真实可核验材料，可能无法全面覆盖相关领域。若用户需要更完整的领域调研，可提供已有文献库、核心论文清单、检索关键词或综述材料，也可调用豆包已有的文献调研类 Skill 进一步补充并提供。
所有用户未提供内容均以占位符格式填写，待用户手动填充，坚守诚信底线不虚构内容。

如用户有输出格式要求时优先遵守用户要求。否则检查并输出结束后，先检测lark-cli 是否可用，如可用则默认使用飞书文档相关工具将核心提案/计划书上传至飞书文档交付用户。注意需要用`docs +create --doc-format markdown`等命令，而不是单纯用`markdown +create`上传，因为后者没有创建飞书文档只是上传markdown文件所以没法渲染mermaid图。如不可用则转化为docx文档交付用户。

## 使用原则

- **任务书优先**：章节、字数、匿名化、模板字段和评审要求必须与任务书/模板要求或用户确认要求一致。
- **事实分层**：基本信息、事实和 AI 建议分开记录；只有已确认事实和已确认建议才能进入正式正文。
- **论证优先**：不仅是填充章节，而是说明“为什么这个项目值得做”或“为什么用户具备开展基础”。
- **逻辑闭环**：研究内容必须直接服务于研究目标，研究目标必须直接回应科学问题。
- **审查后修订**：模拟评审发现问题后主动改正文与配套文件，再汇报修改结果。
- **诚信底线**：所有具体数据、简历、引用、团队能力、研究计划、进度安排等必须有据可查；若用户未提供，严禁虚构内容，必须直接使用 `【待补充：具体说明】` 占位留空。
- **用户主导**：Agent 提供逻辑辅助与草稿撰写，核心学术观点、关键事实和重要 AI 建议由用户把关。
