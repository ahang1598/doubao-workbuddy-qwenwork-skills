# 研究思路聚焦助手（Research Idea Refiner）

## 基本信息

## 能力与边界

将模糊研究想法通过系统诊断、分轮提问、方向发散和初步文献验证，聚焦为清晰、可行、有理论贡献潜力的研究问题。核心目标是在投入完整综述或研究设计前，先确认问题是否具体、值得研究且可操作。

本技能保留六阶段核心能力：

1. Idea 解析与初步诊断
2. 聚焦提问与澄清
3. 方向发散与选择
4. 初步文献验证
5. 研究问题定稿
6. 最终验证

### 应触发

- 只有宽泛领域、大主题或初步想法，不知道如何聚焦。
- 希望识别候选研究方向、潜在研究 Gap 或理论贡献空间。
- 需要打磨博士论文、学位论文、课题申报的前期选题与研究问题。
- 想法包含部分变量或关系，但对象、场景、机制、边界条件仍不明确。
- 询问“这个方向能做什么研究”“帮我细化研究问题”“这个 idea 是否值得研究”等。

### 不应触发

- 已有清晰研究问题，目标是直接设计实验、问卷、访谈或统计分析。
- 需要完整系统综述、元分析、理论综述或大规模文献计量。
- 只要求检索、翻译、总结或格式化文献，不需要聚焦研究问题。
- 需要纯质性研究方案、访谈提纲或民族志设计，且不涉及问题聚焦。
- 已有审稿意见，需要逐条回复或修改论文。
- 需要生成论文正文、伪造数据、伪造引文或代替伦理审查。

### 边界输入判定

| 输入情况 | 处理方式 |
|---|---|
| 仅一个词或领域名 | 视为层级1；先给出 3-5 个代表性主题供选择，再开始阶段1-2 |
| 已有主题但无变量关系 | 视为层级2；重点补齐对象、场景、IV/DV 或核心机制 |
| 已有关系但边界不清 | 视为层级3；完成诊断后可加速进入阶段3 |
| 已有对象、场景和明确关系 | 视为层级4；确认用户确需“问题打磨”而非“研究设计”，再精简执行阶段1-3 |
| 输入跨多个学科或包含多个议题 | 先拆分候选主线，要求选定一条主线；不得把所有议题强行塞入同一问题 |
| 用户要求跳过互动 | 基于现有信息生成暂定方向，所有缺口标记 `[INPUT NEEDED]`，不得假定用户偏好 |
| 用户只接受纯质性路径 | 说明本技能不覆盖完整纯质性设计；可仅协助聚焦问题，后续设计转交适合的流程 |

## 核心流程

按“参考文件加载 → 阶段1 → 阶段2 → 阶段3 → 阶段4 → 阶段5 → 阶段6”推进。每阶段满足门禁后再进入下一阶段；用户尚未提供选择或文献证据不足时，停在当前阶段并明确下一步所需输入。

### 阶段1：Idea 解析与初步诊断

**目标**：理解初始想法，识别模糊点和缺失信息，判断聚焦层级。

1. 提取研究领域、研究对象、场景、可能的核心关系、动机与目标。
2. 判定模糊度：
   - **层级1（领域级）**：仅给出学科或领域。
   - **层级2（主题级）**：有具体主题但无核心关系。
   - **层级3（关系级）**：有核心关系但对象、场景或机制不完整。
   - **层级4（问题级）**：对象、场景、核心关系基本明确。
3. 识别缺失维度：对象、场景、IV/DV 或核心关系、理论视角、结果变量、实践动机和资源约束。
4. 输出 Idea 解析表、层级诊断及缺失维度清单。

### 阶段2：聚焦提问与澄清

**目标**：通过低负担提问，把想法推进到关系级以上。

1. 每轮只问最关键的 2-4 个问题，一次不得超过 4 个。
2. 优先覆盖研究对象、场景、核心关系、理论视角、实践动机和方法偏好。
3. 每轮回答后简要复述已确认信息，再决定是否继续提问。
4. 连续追问最多 3 轮；仍不明确时，用 2-3 个候选方向替代开放式追问。
5. 对“不确定”“都可以”，主动提供 2-3 个常见选项及简短取舍。
6. 用户明确不继续细化时，基于已知信息进入阶段3，并标记缺失项。

**输出**：澄清记录与达到关系级以上的研究想法描述；不能达到时输出带 `[INPUT NEEDED]` 的暂定描述。

### 阶段3：方向发散与选择

**目标**：提供 2-3 个有实质差异的方向供选择。

每个方向包含：

- 一句话核心研究问题；
- 1-2 个候选理论框架及对应关系；
- 潜在创新点；
- **待验证**的初步 Gap 假设；
- 新颖性、可行性、发表潜力和兴趣匹配度的优劣。

方向必须在理论、核心关系、场景、机制或结果变量上存在实质差异，不得仅替换人群。阶段3的 Gap 只能表述为“待文献验证的假设”，不能写成已证实的文献结论。

要求用户选择、组合或调整方向；未获确认，不进入阶段4。确认后复述核心研究问题。

### 阶段4：初步文献验证

**目标**：通过实际检索快速验证选定方向的新颖性、可行性和研究价值。

1. 加载[文献检索与 Gap 验证指南](references/literature-gap-guide.md)。
2. 生成中英文检索词，覆盖核心构念、同义词、理论/关系词和情境/方法词。
3. 使用当前环境实际可用的学术搜索或通用搜索工具，检索 5-8 篇高质量相关论文；记录真实引用信息及可访问链接。
4. 优先纳入综述或元分析、核心实证研究与近年研究，并核验标题、作者、年份、来源及 DOI/链接之间的一致性。
5. 基于检得文献评估：
   - 新颖性：核心关系、机制、情境或理论是否已被充分检验；
   - 可行性：构念是否可测量或操纵，样本与数据是否可获得；
   - 研究价值：是否回应理论争议、实践问题或重要边界条件。
6. 可行且有潜在新颖性时进入阶段5；已充分研究或可行性低时，给出有依据的调整建议并回到阶段3或重新检索。

**文献真实性门禁**：

- 禁止凭记忆补写、猜测或拼接作者、题名、期刊、年份、卷期页码、DOI、链接和研究结论。
- 只有实际检索并核验过的文献才能作为证据；无法核验的条目标记 `[CITATION NEEDED]`，不得放入“已验证文献”列表。
- 检索不足 5 篇时，调整关键词和范围后重试；仍不足则如实报告数量与限制，不得用虚构条目补足。
- 无检索工具、访问失败或来源不可核验时，阶段4降级为“检索方案 + 待核验清单”，不得声称 Gap、新颖性或阶段4已经验证。

**输出**：实际检得的文献列表、检索策略、三维评估与方向确认/调整建议。

### 阶段5：研究问题定稿

**目标**：形成 1-2 个清晰、可操作的最终研究问题。

1. 整合对象、场景、核心关系、机制/边界和理论框架。
2. 附关键要素摘要：对象、场景、IV→DV、中介/调节、理论框架和已核验的初步文献。
3. 不完整字段标记 `[INPUT NEEDED]`；未核实引文标记 `[CITATION NEEDED]`，不把其作为结论依据。
4. 用户需要时，简述下一步研究设计路径，但不展开为完整研究设计。

### 阶段6：最终验证

交付最终研究问题前逐项检查。未通过项应修正，或明确标注未通过原因和 `[INPUT NEEDED]`。

- [ ] 已给出模糊度层级与关键缺失维度。
- [ ] 每轮提问不超过 4 个，连续追问不超过 3 轮。
- [ ] 想法达到关系级以上，或已清楚标记缺失输入。
- [ ] 已提供 2-3 个实质差异方向及四要素与优劣比较。
- [ ] 用户已确认选择的方向。
- [ ] 阶段4使用实际检索；引文信息和链接可核验。
- [ ] 新颖性、可行性和研究价值判断均有明确证据或被标为未验证。
- [ ] 最终问题包含对象、场景和核心关系。
- [ ] 不含虚构文献、数据、检索过程或测试结果。

只有当前任务中实际完成的项目才能勾选。不得把本 Skill 的编写、静态校验或测试设计当作阶段3-6已经验证的证据。

## 输入要求

- **初始研究想法**（必填）：一个词、一句话或一段描述均可。
- **研究领域/学科**（可选）。
- **理论偏好**（可选）。
- **目标成果或期刊层级**（可选）。
- **资源约束**（可选）：时间、预算、样本、数据权限等。
- **方法偏好**（可选）。

缺少必填想法时，仅索取该信息，不自行生成用户意图。缺少可选信息时可继续，但需说明默认假设或标记 `[INPUT NEEDED]`。

## 输出形式

完整执行时输出：

1. 最终研究问题 1-2 个；
2. 研究问题关键要素摘要；
3. 方向方案、优劣比较及用户选择记录；
4. 实际检索并核验的初步文献；
5. 有证据的可行性、新颖性与研究价值评估；
6. 阶段6检查结果与未决项。

默认使用中文。缺失信息用 `[INPUT NEEDED]`，待核引文用 `[CITATION NEEDED]`。

## 失败降级

- **想法极度模糊**：先给 3-5 个领域主题，再让用户选择；不直接生成最终研究问题。
- **连续三轮仍无法聚焦**：停止开放式追问，提供 2-3 个候选方向及推荐理由。
- **用户不选择方向或中断**：输出当前进度、候选方向和恢复任务所需的最小输入，不进入阶段4。
- **参考文件不可读**：说明缺失文件及受影响阶段，只执行本文件可支持的部分。
- **搜索工具不可用或访问受限**：输出可复用检索式、建议数据库和待核验清单；停止文献结论与最终新颖性判断。
- **高质量相关文献少于 5 篇**：如实给出实际数量、检索范围和局限；可提出暂定 Gap 假设，但必须标为未验证。
- **检索结果相互矛盾**：并列呈现证据差异，缩小结论范围，提出需要继续检索的关键词或研究边界。
- **方向已被充分研究**：引用核验过的文献说明现状，并调整机制、边界、情境或理论视角。
- **研究资源明显不足**：提出可操作的替代样本、公开数据、代理变量或缩小范围方案。
- **用户要求虚构文献、数据或验证结果**：拒绝虚构，仅提供检索、数据收集或验证方案。
