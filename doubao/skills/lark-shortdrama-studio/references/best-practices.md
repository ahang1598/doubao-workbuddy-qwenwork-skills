# 最佳实践与注意事项

## 多维表格

### 1. 附件上传必须用相对路径

附件上传必须用当前目录下的文件（相对路径），不能用绝对路径如 `/tmp/xxx.png`。

**正确**：
```bash
lark-cli base +record-upload-attachment ... --file ./family_chengwei.png
```

**错误**：
```bash
lark-cli base +record-upload-attachment ... --file /tmp/family_chengwei.png
```

### 2. 关联字段参数名是 link_table

创建关联字段时，参数名是 `link_table`，不是 `link_table_id`。

```json
{"type":"link","name":"关联剧本","link_table":"<table_id>"}
```

### 3. 关联字段默认是单向的

飞书多维表格的 link 字段默认是单向的（bidirectional: false），不会自动生成反向关联。

需要两边都手动创建关联字段，并手动填充数据。

### 4. 单选字段的选项必须先存在

写入单选字段值之前，必须确保该选项已经在字段定义中存在，否则会报 `not_found` 错误。

创建单选字段时要把所有可能的选项都定义好。

### 5. 新建 Base 会自动创建默认表

新建 Base 时会自动创建一张默认表，需要手动删除。

### 6. hue 有效值

Red, Orange, Yellow, Lime, Green, Turquoise, Wathet, Blue, Carmine, Purple, Gray

**注意**：Cyan 不是有效值。

### 7. field-update 是 high-risk-write

修改字段时可能需要加 `--yes` 参数确认。

## 视频生成

### 1. 一定要用参考图

纯文字生成的视频角色一致性很差，一定要用参考图（image_to_video）。

参考图能显著提升角色和场景的一致性。

### 2. 参考图 2-3 张最佳

太多参考图会互相干扰，2-3 张效果最好。

- 角色正面图（必传）
- 场景全景图（必传）
- 其他角度/道具（可选）

最多不超过 5 张。

### 3. 提示词不写外貌

角色外貌交给参考图，提示词里只写动作和情绪。

**正确**：
```
一位年轻女子走进厨房，打开冰箱门，眉头微皱，眼神疑惑。
```

**错误**：
```
一位穿白色衬衫、黑色长发、大眼睛的年轻女子走进厨房...
```

### 4. 15 秒是黄金时长

- 太短（<10秒）：内容太碎，效率低
- 太长（>20秒）：质量不稳定，容易崩坏
- 15秒：质量和效率的平衡点

### 5. 一次最多生成 2 个

视频生成比较耗时，一次最多生成 2 个，避免超时或限流。

### 6. 生成后及时下载

视频链接可能会过期，生成后要及时下载到本地并入库。

### 7. 不满意就重生成

不要将就用质量不好的视频，调整提示词或参考图重新生成。

常见调整方向：
- 角色不一致 → 加/换参考图
- 动作不自然 → 简化动作描述
- 画面崩坏 → 缩短时长
- 场景不对 → 加场景参考图

## 角色一致性

### 1. 角色设定图要有明显差异化

避免"标准帅哥脸"/"标准美女脸"，每个角色要有独特的识别特征：

- 发型（长度、颜色、样式）
- 服装（颜色、款式、风格）
- 体型（高矮胖瘦）
- 气质（眼神、表情、姿态）
- 年龄感

### 2. 三视图分别生成

正面、侧面、背面分别生成，保持提示词一致，只改视图描述。

这样能保证三视图的一致性。

### 3. 视频生成务必传参考图

这是保证角色一致性的最有效手段。

不传参考图的话，角色形象每段视频都可能不一样。

## 项目管理

### 1. 每个项目一个独立 Base

不要把多个项目放在同一个 Base 里，每个项目一个独立 Base：
- 数据完全隔离
- 权限独立控制
- 不会互相干扰
- 方便归档和迁移

### 2. 状态字段要及时更新

每个环节的状态要及时更新，保证进度追踪准确：

- 资产：待生成 → 已生成 → 已确认
- 分镜：待拆分 → 拆分中 → 已拆分
- 视频：待生成 → 生成中 → 已生成 → 已审核

### 3. 关联字段要双向填充

虽然不是真正的双向联动，但两边都填充数据的话，查询时两边都能看到关联。

### 4. 项目看板用于总览

项目看板只放统计数据和总览信息，不放具体业务数据。

具体数据在各自的表里（剧本库、分镜库、资产库）。

## 工作流

### 1. 资产优先原则

先确认资产，再做分镜和视频。

如果资产没确认就开始拆分镜，后期改资产会导致大量返工。

### 2. 渐进式确认

每一步都确认后再往下走：
- 资产确认 → 分镜拆分
- 分镜确认 → 视频生成
- 视频确认 → 下一段

不要一口气做完所有步骤，中间发现问题就晚了。

### 3. 先做核心场次

不要从第一场按顺序做到最后一场，先做核心场次验证效果：
- 验证角色一致性
- 验证场景还原度
- 验证视频质量
- 确认没问题再批量做

### 4. 及时备份重要文件

- 生成的图片和视频要及时下载
- 重要的 Base token 和 table_id 要记录下来
- 可以导出到本地备份

## 常见问题

### Q: 附件上传失败怎么办？

A: 检查文件路径是否是相对路径（当前目录下），不要用 /tmp/ 或其他绝对路径。

### Q: 单选字段写入报错 not_found？

A: 检查该选项是否已经在字段定义中存在，不存在的话先添加选项。

### Q: 关联字段怎么双向联动？

A: 飞书的 link 字段默认是单向的，需要两边都手动创建关联字段并填充数据。

### Q: 视频生成的角色和设定图不像？

A: 确保传入了角色参考图，提示词里不要描述角色外貌。可以多传几张不同角度的图。

### Q: 视频后半段画面崩坏？

A: 缩短时长（从15秒降到10秒），减少画面元素，简化动作。

### Q: 一次能生成几个视频？

A: 最多 2 个，太多会超时或限流。

### Q: 生成的视频链接会过期吗？

A: 可能会，生成后及时下载到本地并入库。

### Q: 怎么提高角色一致性？

A: 1) 一定要用参考图 2) 参考图用正面图 3) 提示词不写外貌 4) 可以多传几张角色图

## 效率提升技巧

1. **批量生成图片**：一次生成多张角色/场景图
2. **并行上传附件**：可以连续调用上传命令
3. **复用资产**：同系列短剧可以复用角色和场景资产
4. **模板化**：常用的提示词做成模板，直接填空
5. **先验证再批量**：先做1-2个片段验证效果，没问题再批量生成
