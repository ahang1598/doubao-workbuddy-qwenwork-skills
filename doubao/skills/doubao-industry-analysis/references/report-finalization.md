# 报告定稿规则与写作大纲（Report Finalization）

本文件是写作阶段的唯一蓝本：固定章节、给出每个板块的方法论与展开重点、说明写作风格。**篇幅以论证完整、信息充分、与主线一致为准**，靠把每个小节写透、多做量化测算与对比来撑起专业深度，而不是堆空话注水。

最高优先级仍是 SKILL.md 的质量标准：数据真实可溯源、判断贯穿一条主线、信息详实、克制专业。任何本地格式或章节规则若与该标准冲突，保留质量标准、把格式简化掉。

> **⚠ 写法（配合 SKILL.md 第4步）**：正文按下表依次分六批写入 `parts/` 下的固定 Markdown 分片，再合并为 `output/report.md`。分片和阶段校验仅在定位问题时按需执行，整篇完成后统一做一次校验。
>
> **⚠ 写作前必读判断主线底稿（第 3 步产出）**：本大纲解决"写什么板块、每板块该展开到什么程度"，而判断主线解决"这篇报告到底要证明什么判断"。两者配合——写每个板块时，**开头用一句"亮明判断"的主题句**，**结尾用 `回扣主线` 小节把结论收回到全文主线**，正文数字与主线核心数据保持一致。**不要在正文里出现"本板块要证明的子命题："这类标签式说明**——子命题是内部抓手，读者应通过论证"看出"你在证明它（正反例见 `insight-spine.md`）。

## 总则

1. **结论先行**：每个板块开头先给判断，再用证据展开；禁止"本报告将探讨…"式绕弯开场。
2. **不编造**：查不到的数字宁可写"公开信息有限，据……推算"，或给出测算假设；不硬凑。
3. **成段论述为主**：用有逻辑递进的段落写分析，列表只用于真正并列的要点（风险条目、参考文献、对比清单）。不要把连贯论证拆成一堆短 bullet。每个小节在表格或列表前都要有一句小结或判断句引出，不允许某小节只有列表/表格、没有论述。
4. **时效**：市场规模/政策/技术以联网检索的最新结果为准；正文标注数据基期与年份，年份用解算出的真实数字（如 2026），不留占位符。
5. **专业深度（写出扎实论证的关键）**：篇幅靠"论点—数据—含义"的密度自然展开，不靠注水。**每个分析观点都要用检索到的具体数据（带数字与来源）支撑，并做一步量化测算或拆解（量×价、CAGR、CR_n、ROE 杜邦、敏感性区间等）或同业/情景对比，再点"这对决策意味着什么"；论点与数据一一对应，无据的论断不写——内容显得单薄时通常是论证不够，应补数据与测算、不补形容词**（把事实转成判断的镜头见 `analysis-framework.md`）。多用对比表承载并列信息，避免泛泛而谈与重复前文。
6. **主线绑定——用论证体现，不要标签式表述**：
   - 每个板块**开头第一段**用一句**"亮明判断"的主题句**承接该板块的子命题——写成一个有态度、可被证明的论断，正文随后用数据与逻辑去证明它。**严禁出现"本板块要证明的子命题：……"这类标签**。
   - 每个板块**结尾必须放一个 `回扣主线` 小节**（标题就叫"回扣主线"），用 2–3 句：先一句话**总结本章**，再**自然说清本章结论"印证 / 强化 / 限定（部分修正）"了核心判断、与哪个 T 信号联动**。这个小节兼具本章小结与回到主线的双重作用。用行文表达，不要写成"本板块支持主线"的生硬套话。**发现反证要如实写、不藏。**
   - 正文出现的核心数字与主线底稿"核心数据"对得上、不自相矛盾。

## 写作批次

以**论证完整、信息充分、与主线一致**为准，依次写入以下六个分片。每批写完当前分片再进入下一批。六批完成后用 `scripts/assemble_report.py` 合并。

| 批次 | 文件 | 内容 | 写作重点 |
|---|---|---|---|
| 批1 | `parts/01-executive-summary.md` | 主标题（含「——」副标题）+ 核心观点（执行摘要：共识 vs 非共识 + 核心数据 + 主线论证链） | 先把核心判断、关键数字与主线论证链交代清楚。 |
| 批2 | `parts/02-industry-definition-scale.md` | 一、行业定义、规模测算与历史坐标（1.1–1.4）+ `回扣主线` | 重点写清行业边界、规模口径、自建测算与历史定位。 |
| 批3 | `parts/03-structure-competition.md` | 二、行业结构、竞争格局与格局演变（2.1–2.7，产业链全景表等）+ `回扣主线` | 重点展开产业链、利润池、头部玩家、格局演变与可比估值。 |
| 批4 | `parts/04-drivers-constraints.md` | 三、核心驱动力与制约因素（3.1–3.3，含重点政策梳理）+ `回扣主线` | 重点写透需求、技术、政策、成本、竞争的传导机制。 |
| 批5 | `parts/05-trends-opportunities.md` | 四、趋势研判与结构性机会（4.1–4.7，含 T 信号清单表、三情景给结果）+ `回扣主线` | 重点交代趋势判断、验证信号、预期差与三情景结果。 |
| 批6 | `parts/06-commercialization-risk-refs.md` | 五、商业化路径、盈利质量与落地建议（5.1–5.4）+ `回扣主线`，接风险提示（关联相应的 T 信号）+ 结语 + 参考文献 + 免责声明 | 重点收束盈利与落地逻辑，补齐风险、结语、参考文献并回看主线一致性。 |

板块一至五每章都以 `### 回扣主线` 收尾。主标题写在批1，风险、结语、参考文献与免责声明写在批6。整篇只保留一个 Markdown H1（`#`）主标题、一处参考文献标题和一份免责声明。执行摘要交代共识与非共识、核心数据与主线论证链（各论据注明展开板块），定稿时核对主线一致性。风险提示与相应的 T 信号联动。

## 各板块方法论

### 核心观点（执行摘要）

- 开篇 2–3 句给核心判断 + 关键数字（规模、增速、所处周期位置）——这几个数字应与判断主线的"核心数据"一致。
- **必写"市场共识 vs 非共识判断"**：用一两句说清"市场已经知道、已被定价的是什么（共识）"，再点出"本报告比共识多看到了什么、预期差在哪（非共识判断）"。这是让报告有 insight、而非资料汇编的关键。
- 用一段写出"主线论证链"：列出核心论据，每条注明在哪个板块展开（如"装机量价齐升，见板块一"）。
- 给出面向决策意图的一句话结论（投资 / 入局 / 战略落地）。
- Markdown 写作时，核心判断用引用块突出，含核心判断 / 关键风险 / 验证信号三个要点。

### 板块一：行业定义、规模测算与历史坐标

- **1.1 行业定义与边界**：定义本行业、产业链范围、与相邻行业的边界。
- **1.2 市场规模（多源交叉 + 自建测算）**：
  - 至少 2 个来源对照当年/上年规模，差异 >30% 时并列展示并解释口径差异（出厂/零售、含税、销量/销售额）。
  - 给一条**自建测算**：写清量×价（或渗透率×空间）的拆解公式与假设。
- **1.3 增速、宏观敏感性与生命周期**：CAGR 预测（窗口到 当前年+5）；说明本行业最相关的宏观变量（如地产、出口、补贴、利率）及历史弹性；判断处于导入/成长/成熟/衰退哪个阶段。
- **1.4 历史复盘与周期律（如适用）**：用因果链行文复盘关键转折并给出可溯源的依据。

### 板块二：行业结构、竞争格局与格局演变（核心板块）

- 开篇一句话点明行业属哪类结构（产业链型/网络型/资产负债型/单店模型型，见 `industry-structure-playbooks.md`），仅作行文取向。
- **2.1 产业链 / 结构全景**。说明各环节的构成、价值和关键节点。
- **2.2 价值分布与利润池**：价值集中在哪个环节、被谁拿走。对照各环节的毛利率和价值占比。
- **2.3 头部玩家**：CR3/CR5 集中度、第一/二阵营划分与定位。
- **2.4 格局演变与终局推演**：关键成功要素（KSF）排序 + 3–5 年终局形态判断 + "反转信号"（什么发生会推翻本判断），反转信号汇总到板块四 4.4。
- **2.5 估值与融资并购**：A 股可比公司 PE/PB 区间与当前分位（高/中/低位）；近年代表性融资/并购倒序列举。
- **2.6 供需、产能与价格周期（如适用）**：产能利用率、价格走势、库存位置。
- **2.7 重点公司简析（仅用上市公司公开披露）**：主业、份额、最近财务概况。

### 板块三：核心驱动力与制约因素

- **3.1 五维驱动—制约矩阵**：从需求、技术、政策、成本、竞争五个维度，各写驱动力与制约因素。
- **3.2 技术路线对比（如适用）**：主流技术路线优劣、卡脖子环节、国产化进度。
- **3.3 政策梳理（中国行研标配）**：
  - 梳理会影响结论的政策。写明发布时间、发文机关、文件名称及文号、政策层级、核心内容和影响方向。
  - 一段写政策周期定位（扶持初期/加码/退坡/规范）与边际变化；前瞻信号汇总到 4.4。

### 板块四：趋势研判与结构性机会｜窗口 当前年–次年（必要时延 1 年）

板块四不应该是泛泛的行业趋势描述，而应该试图完成行业调研报告中的结构性机会研判。为了完成这种结构性机会研判，你应该试图围绕当年或1-2年内行业内部结构性变化，理解当前和未来的产业阶段及变化，试图识别外部关键变量，以及产业中最具确定性与最具弹性的细分方向，思考产业链受益环节、兑现时间表、关键验证信号和潜在风险。

- **4.1–4.3 关键趋势（按分析需要展开）**：每个独立的趋势小节应由一个清晰的中心判断统领，后续讲清做出这样趋势判断的原因，完成一条连贯的分析。具体而言，需要说清楚 该趋势判断与当前产业阶段之间的关系，为什么这个趋势可能发生或正在发生，是否有证据可以支持这样的趋势判断，它会如何影响产业链的价值分配，哪些环节因此受益或承压，以及后续应通过什么信号验证判断是否成立。**上述每小节的主题内容应该以自然段承载，每个自然段之间要有良好的逻辑衔接，在引用证据、数据的时候需要有来源**。
- **4.4 信号验证清单**。汇总反转信号、历史复盘启示和政策前瞻信号。将触发条件写成可观测的指标或可判定的事件，注明数据来源、观察窗口、判定标准，以及触发后如何调整结论。
- **4.5 一致预期与预期差**：市场主流预期是什么、本报告的预期差在哪、有实质依据的反方观点及回应。对可能改变核心结论的反例，追查其实际结果，并说明它会限定结论的适用范围，还是足以推翻结论。（投资意图额外写一句"当前估值大致定价了哪一档情景"。）
- **4.6 出海/全球化（如适用）**：海外空间、竞争对手、本土玩家出海进展。
- **4.7 三情景推演（必做，板块四收尾）**：乐观/中性/悲观三档。可直接搬用判断主线的"三情景速览"。每档必须给**结果**，不能只列假设：①假设（前两行直接用 1.2 的量价参数）；②对应**规模/增速结果**；③**利润/毛利率方向**；④**对结论的含义**（估值/投资/入局判断如何变）；⑤触发条件（挂某个 T 信号）。**"只有定性描述、没有结果"是常见硬伤，务必避免。**

### 板块五：商业化路径、盈利质量与落地建议

- **5.1 盈利模型（二选一）**：A=单位经济（单位售价−单位成本=单位利润）；B=成本结构（拆成本大项+盈亏平衡）。资产负债型用 B 的变体（息差/承保利润率、成本收入比、信用成本）；单店模型型补单店模型拆解。
- **5.2 回报率与现金流画像（必做）**：ROE/ROIC 的水平与趋势 + 杜邦拆解（净利率×周转×杠杆）+ 现金流三指标（经营现金流、资本开支、自由现金流）。可比样本 ≥3 家时给中枢与区间。用可比期间的实际回报率、净利润和现金流检验盈利质量。关键指标缺失时标明缺口，将结论限定在已有证据能支持的范围。
- **5.3 落地路径**：只写已锁定的决策意图（投资就写投资视角；入局就写进入路径），不要四类角色都铺一遍。
- **5.4 进入壁垒**：技术/资金/牌照/渠道/规模等壁垒，与 2.4 的 KSF 排序呼应。
- **5.5 失败案例（可选）**：有代表性且可溯源的案例可单列，也可并入 2.3 或风险提示。
- **5.6 90 天行动建议（仅入局/战略落地意图写）**：给出与决策直接相关的可执行动作。

### 风险提示

- 每条写清"风险事件 + 触发逻辑 + 影响"，并与 4.4 的某个观察指标呼应（哪个指标超阈值即兑现）。
- 合规标配，不可省。

### 结语

- 收束主线，重申核心判断与最关键的观察指标；不引入新论点。

## 数字与口径小抄

- ≥5 位整数加千位逗号（12,345）；年份、文号不加逗号。
- 统一用"万/亿"中文数量级；标注汇率时点与统计口径；区分同比/环比、百分比(%)与百分点(pct)。
- **数字与中文之间不加空格**："2026年"而非"2026 年"；正文双引号用中文""。
- 估值 PE/PB/PS 标 TTM/静态/动态(LYR) 与时点；行情类数字写"数据截至 YYYY-MM-DD"。

## 交付前自检清单（逐条确认）

- [ ] **判断主线已贯穿、无标签痕迹**：执行摘要点明共识 vs 非共识；五大板块开头是亮明判断的主题句、每章结尾有 `回扣主线` 小节；4.4 有 T 信号清单表、4.7 三情景给了结果；正文不出现"本板块要证明的子命题"这类标签。
- [ ] **各板块内容完整**：覆盖应有内容，论证扎实、信息充分；不在末尾集中补篇幅。
- [ ] **核心证据核验**。定稿的数据复核聚焦执行摘要、核心判断、估值、规模测算和情景结果所依赖的数字，以及存在来源冲突、口径疑点、异常值或写作后新增/改动的数据。对照取证时保留的原文摘录或查询结果，核对数值、前后一致性及估算/推断的限定措辞；记录不足以支撑该主张或存在疑点时，回源核验受影响项。判断现状时，核对截至研究日可取得的最新同口径数据；跨公司或跨期对比时，核对期间、产品、业务范围和单位，无法统一则分开呈现并限定结论。复算关键测算的公式、单位换算和结果。其余已完成取证的数据沿用来源台账与写作阶段记录。
- [ ] **结构完整**：9 个板块齐备；关键风险与相应的 T 信号联动；免责声明齐备未删改。
- [ ] **本地校验与飞书交付**。按 `lark-doc-report-standard.md` 完成定稿与交付，返回文档链接。

## 免责声明（附在报告末尾，除非用户明确要内部稿不带声明）
