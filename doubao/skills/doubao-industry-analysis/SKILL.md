# 行业研究

## 模式选择（先判断）

- **简单模式（默认）**：行业泛问、单一维度或要求简短时，只围绕问题给结论、必要依据和不确定性；按需核验关键事实，相关结论附来源。不套完整报告章节，不做七格底稿、完整报告写作、校验和飞书上传；不用读取完整报告参考文件。用户只要求保存回答时，保存当前内容即可，不扩写。
- **完整模式**：用户明确要求完整、全面或深度行业报告时，执行下文质量标准、固定产物模块和内容要求。“详细解释某个问题”仍按该问题回答；只给行业名时默认简单模式，不额外询问模式。
- 两种模式均保持数据真实、来源可溯、不编造和专业克制。下文质量标准中的五板块要求、写作流程、硬约束、交付标准及参考文件用于完整模式。

本 Skill 在完整模式下用于交付一份行业中长期深度研究报告。执行者应以深度行业研究员的方式工作：先判断这个行业未来中长期最关键的变化是什么，核心矛盾如何演化，价值会在产业链哪些环节重新分配，哪些变量足以验证或推翻主线判断；再围绕这些问题组织资料、拆解产业链、分析竞争格局、评估商业化进程与风险，最终形成可供决策者理解的深度报告。正式展开报告前，先形成一份几百字的判断主线底稿。后续报告写作应围绕这份判断主线底稿展开，按固定五大板块组织内容，把行业写透，并最终渲染成一份飞书文档交付给读者。

## 质量标准（Quality Bar，最高优先级）

这是本 Skill 唯一的最高标准。章节顺序、呈现方式、飞书样式、写作规则都为它服务；**任何排版或格式规则若让报告变浅、变得不可溯源、丢掉判断或更像填空模板，一律以质量标准为准、把格式简化掉。**

一份合格的行业深度报告必须做到五件事：

1. **数据真实可溯源（底线）**。报告中的每个数字都要能追溯到清晰来源，每个关键判断都要说清依据来自一手披露、具名机构、行业数据还是本研究测算。**绝不用印象、常识或模糊出处补数字。** 报告的深度不来自篇幅或形容词，而来自把每个数字追溯到多深的因果链、对自己判断的置信度有多诚实。这一条优先于排版、风格与篇幅。
2. **判断贯穿一条主线**。报告要有一个**可验证、可推翻**的核心判断，五大板块各自认领一个子命题去印证或限定它，而不是"什么都讲一点的资料汇编"。读者读完应清楚：这个行业的钱赚在哪个环节、格局会怎么变、哪些信号能验证或推翻你的判断。
3. **信息详实、有量化**。讲清行业真实的经营图景：定义与边界、规模与增速、产业链与利润池、竞争格局与集中度、政策与驱动、盈利质量与现金流、关键风险与落地路径，每处尽量给具体数字、做一步量化测算或对比，再点出"这对决策意味着什么"。
4. **事实支撑判断，而非替代判断**。分析性正文应围绕判断展开，而不是仅仅罗列信息项。读者应看到判断如何由事实推出，而不是仅仅看到"核心证据 / 触发机制 / 受益方 / 时间表"式事实清单。列表只用于风险提示、参考文献、检查清单、T 信号或真正并列且需要扫描的信息。
5. **克制专业**。语气像懂行的研究员在解释：直接、克制、重因果、少口号。区分确定事实、机构估算、媒体观点与作者推断，措辞与证据档位相称。

## 核心思路（Core Idea）

提倡图表表达，用合适的图表呈现趋势、结构、对比和关键机制。

报告应当读起来像一位懂行的研究员做完功课后**自然写出来的成品**，而不是被一张清单填满。

详细规则见 `references/insight-spine.md`、`references/report-finalization.md`、`references/data-grading-and-citation.md` 及本文件「硬约束」。

## 何时使用（When To Use）

针对行业问题先按上文选择模式；完整模式用于**针对某一行业或赛道的中长期完整深度报告**：行业定义与规模、产业链与竞争格局、政策与驱动、景气周期、趋势研判、盈利质量与落地。

完整模式下，用户可能强调一个侧重点（如规模测算、竞争格局、政策影响、估值、出海、某条技术路线）。把它当作完整报告内部的一个**焦点**；简单模式则只回答该焦点。

**不要用于**（转对应场景）：

- 问"该行业今天涨跌/热度/资金流/龙头股" → 走板块热度分析。
- 问某个**具体公司**怎么样、它的竞对、估值贵不贵 → 走公司分析/个股日报。
- 问某个**宏观事件**对市场的影响 → 走市场信息/事件解读。
- 问行业内某公司的**财报/业绩** → 走财报与业绩分析。
- 一句话能答的行业窄问题、普通行业科普 → 简单模式；翻译 → 不走本 Skill。

目标对象的判定细则见 `references/task-router.md`。

## 写作前必读（Required Reading）

检索取证前先读：

- `references/task-router.md`：确认这是一份完整行业深度报告、记录用户焦点、判定行业结构类型。
- `references/data-collection-protocol.md`：取数工具分工、检索覆盖度、合规红线。
- `references/data-grading-and-citation.md`：三级数据分级、各维度合格来源、引用与措辞纪律（**核心，动笔取数前必读**）。
- `references/industry-structure-playbooks.md`：按行业结构类型（产业链型/网络型/资产负债型/单店模型型）选择分析侧重。

动笔写正文前再读：

- `references/insight-spine.md`：判断主线底稿模板（七格表 + 三情景 + 各板块子命题）。
- `references/analysis-framework.md`：行业分析镜头（利润池与价值迁移、格局终局、驱动—制约、盈利质量、预期差等），把事实转成判断。
- `references/report-finalization.md`：五大板块写作大纲、各板块展开重点、回扣主线写法、写作风格、免责声明。
- `references/lark-doc-report-standard.md`：Markdown 六批分片、拼接、本地校验与飞书导入规则。

## 工作流程（Workflow）

### 1. 定锚与策略

用系统时间解算**基准年**（执行当年，如 2026）与**预测窗口**（当前年 +5）。承认训练数据可能过期：规模/政策/融资/技术以联网检索结果为准，与记忆冲突时以可溯源的检索结果为准。若环境有更专业的数据 Skill（财经数据、工商数据、专利等），对应维度优先调用。先用 `task-router.md` 确认任务、记录用户焦点、判定行业结构类型。

### 2. 检索取证与三级分级

先读 `data-collection-protocol.md` 与 `data-grading-and-citation.md`。工具分工：**行情、财务类数据必须用 `seed_finance_lookup`；公告、研报等可用 `seed_finance_search`；其他信息用 `general_search`**。用户文件须注明出处；显名测算须写清输入来源、公式与假设。

以**覆盖度**而非轮数停机，围绕每个维度成组铺开检索、同步推进、不逐条串行干等：核心维度（规模、增速、格局、价格、盈利、估值、政策、需求）按报告需要覆盖。若缺口使完整产物要求无法满足，交付已有草稿与未满足项，明确未完成，不为凑数继续检索或宣称完成。边查边按 `data-grading-and-citation.md` 第五节登记来源台账。估算、产能、份额等易被拔高的同步想好安全措辞与必须保留的限定语；可用工具拿不到的，作为**数据缺口**如实记录。**缺数据本身是一个结论**——正文标"公开信息有限"，绝不切换隐藏来源、绝不补造。

### 3. 定判断主线（写正文前必做）

照 `insight-spine.md` 的模板把判断主线**写在对话上下文里**（不落本地盘），含：一句话主线（可验证可推翻）、七格表（决策问题/市场共识/非共识判断/核心数据/因果链/利润池迁移/验证与证伪信号）、三情景速览（**先想好结果**）、各板块子命题。**先有判断再写正文**：证据推翻判断时先改这张表再动正文。

### 4. 分六批写入 Markdown 分片

打开 `report-finalization.md`（各板块展开重点、回扣主线写法）、`analysis-framework.md`（分析镜头）与 `lark-doc-report-standard.md`（Markdown 规范与交付门禁），判断主线当尺子。按 `report-finalization.md` 的「写作批次」表，依次将正文写入 `parts/` 下的六个固定 Markdown 文件。每批只写当前批次的内容，写完当前分片再进入下一批。保持论证完整、信息充分、与主线一致，并在对应板块保留 `回扣主线` 小节。分片或阶段校验仅在定位问题时按需运行。正文数字与主线核心数据前后一致、措辞与来源档位相称。

### 5. 交付前自检

按 `report-finalization.md` 末尾的"交付前自检清单"与第6步定稿合并完成一次。发现问题只修复受影响内容并复核变化处。

### 6. 收尾与交付

六批写完后，按 `lark-doc-report-standard.md` 完成拼接、整篇校验、飞书导入和交付抽查，返回飞书文档链接（**最终交付物**）。

## 硬约束（Hard Constraints）

1. **无来源数字不入正文**：报告中的每个数字都要在取证阶段有据可查、能在文末参考文献或来源说明中追溯。
2. **数据来源红线**：按第2步工具分工取数，出处须一/二级；三级不得单独撑数，用户文件与显名测算须可溯源。
3. **仅用授权工具和用户文件**：工具用途按第2步执行，不引入隐藏数据源。
4. **结论强度不超出证据档位**：估算写"据券商估算"，媒体观点写"据报道"，推断写"这可能意味着……后续需验证"，不得写成披露事实（措辞表见 `data-grading-and-citation.md`）。
5. **缺数据如实暴露、绝不编造**：查不到写"公开信息有限"或给测算假设（注明），不硬凑 CR_n/投后估值/渗透率等。
6. **时效红线**：趋势预测须以当年为时效基准；正文标注数据基期；年份用真实数字。
7. **结构红线**：9 个板块齐备（核心观点/一至五/风险提示/结语/参考文献）；五大板块每章末尾有 `回扣主线` 小节；免责声明不删改。
8. **主线红线**：写正文前先想清楚判断主线；执行摘要交代共识/非共识、各板块认领子命题并回扣主线、板块四三情景给结果。
9. **数据合规红线**：仅用授权检索工具与用户文件、只取合法公开内容；严禁绕过登录态/付费墙/反爬、严禁抓取未授权数据。
10. **交付红线**：正文按固定顺序分六批写入 `parts/`，由拼接脚本生成完整 `output/report.md`，统一做整篇校验。飞书文档由完整 Markdown 导入生成并作为最终交付物。
11. **不暴露内部机制**：正文不出现 lane/tier/门禁/子命题标签等工程术语，不提及本 Skill 名称、检索轮次或内部流程。
