# 时间范围遍历处理

本文件规范消息、日程、文档等记录在时间范围内的批量获取与处理，以降低信息遗漏和长上下文处理中的信息丢失风险。

核心顺序：

1. **先全文读取**：按时间切片获取，在当前上下文中全文读取每片匹配记录及任务所需内容，不得先将原始返回内容存入文件再回读。
2. **再整理保存**：读完后整理分片结果；具备文件能力时，必须将分片总结及必要依据保存到文件。
3. **总结保留引用**：总结也须遵循主 Skill 的内容使用与引用格式要求，保留事实与来源的对应关系，再用于合并。

## 1. 场景与路由边界

典型场景：

- 汇总某个月反馈群里的反馈，需要获取该月范围内的相关消息。
- 提取某段时间内本人发送的消息中的工作事项，需要遍历匹配消息。
- 获取某天本人参加的所有会议，再逐个提取待办，需要先确定会议集合。
- 列出某段时间内本人创建的文档，提取用户要求的字段并整理。

仅带有时间条件、但目标是定位某条信息或回答一个具体问题的请求，如“上个月是谁提过某件事”，不自动进入本流程。跨来源的项目背景、风险或进展综合，也不能仅因包含时间范围就改成记录遍历。

先按主 Skill 第 1 章判断路由，再应用本流程：

- 单一数据域的记录遍历使用对应的 `lark-xxx` Skill，通常通过 `lark-cli` 获取记录，不使用 `enterprise_agentic_search` 代替完整枚举或精确统计。
- 复合请求中，本流程只处理需要遍历记录的子任务；后续是否需要企业搜索，仍按主 Skill 判断。
- 工作总结的候选事项发现阶段可复用本文件的切片、分页、分片处理和进度记录方法；查询范围、覆盖要求及停止条件以[工作总结处理](work-summary.md)规则为准，不因复用本流程而要求穷尽全部来源和时间片。未取完的范围仍须如实记录，不得标记为已完整获取。

## 2. 确定范围与划分时间片

1. **确定共同范围**：从用户请求和上下文确定时间范围、数据域、对象或容器范围、人员及其他筛选条件，以及最终需要提取或统计的内容。只补全可由上下文确定的信息；缺少会实质影响查询的必要条件时，按对应 Skill 处理。
2. **选择切片粒度**：根据时间跨度、已有信息量和工具返回限制，将原范围划分为可获取和处理的时间片，不固定按天或按周。范围较小且信息量可控时可以作为一个时间片处理，不为切片而增加调用。
3. **保证范围覆盖**：所有时间片共同覆盖原时间范围，保留相同的对象和筛选条件。按工具实际采用的时区和时间边界语义构造参数，避免交界处漏记录；工具边界导致重叠时，在合并阶段去重。
4. **按需细分**：
   - 每片都必须取完匹配记录，并读完任务所需的内容，不能只读一部分或摘要就算完成。
   - 若一片内容太多，无法读完或处理完，就缩短这一片的时间范围，继续拆分，直到能完整处理。
   - 若只是单条记录太长，则按工具支持的方式分段读取，不要继续缩短时间片。
   - 遇到返回截断，先区分是查询结果不全还是显示被裁剪，再按原因处理。

## 3. 获取与处理各时间片

### 执行方式

- **串行或并发**：相互独立的时间片允许并发，由模型根据任务规模、返回内容大小及工具约束选择串行或并发，不要求全部串行，也不要求全部并发。
- **分批控制**：并发应分批进行，并结合各片预计返回量控制单批规模；完成一批结果的处理和保存后，再获取下一批，避免多个时间片的原文同时累积导致上下文过长。
- **直接调用工具**：本遍历流程应直接调用工具，不将分片获取或处理委派给子 Agent，以避免子 Agent 回传结果时丢失来源引用。
- **依赖顺序**：依赖前序结果的查询、同一时间片中依赖上一页游标的分页必须顺序执行。
- **工具限制**：并发不得覆盖对应工具的调用限制；`enterprise_agentic_search` 仍遵守主 Skill 第 2 章的独立、串行调用要求。

### 空片与错误处理

- **空片不重试**：查询及必要处理正常完成但结果为空时，如实记录为空并继续处理其他时间片，不因结果为空再次发起请求。
- **只重试失败范围**：只有请求出错时才按对应工具的重试规则重试；遇到限流或超时时，必要时降低并发。正常分页和读取必要内容不属于失败重试。
- **失败不等于无记录**：失败片保留为未完成，不重复已完成范围；无法恢复时明确说明缺口，不得计为无记录。

### 每片处理要求

- **获取匹配记录**：按对应 Skill 的能力和参数规则查询，完成必要分页。不能把第一页、默认返回数量或相关性排序后的部分结果当作该片全部记录。命令带有 `--format` 参数时使用 `--format json`。
- **全文读取后整理**：
  - 每片获取后，必须在当前上下文中全文读取匹配记录及任务所需内容，保留原文与来源的对应关系，再进行整理。
  - 不得将原始返回内容重定向或保存到文件后再回读，也不得用已落盘代替已读取。
  - 若列表字段不足以完成任务，应继续全文读取各对象的必要正文；分别记录枚举和内容处理进度，独立对象可分批并发读取。
  - 内容过多时缩小时间片或按工具支持的方式分批读取，不将全部原文一次性载入上下文。
- **区分获取与展示**：返回内容过长时应分批获取和处理；不得将 `head` 等裁剪后的输出当作完整查询结果。分页未结束、返回截断或存在权限及工具能力限制时，保留未完成状态及原因。
- **按目标整理**：提取用户任务所需的记录或事实，保留关键原文、发言或记录主体、时间和实际返回的来源链接。统计任务保留可核对、可去重的记录依据，不只保存一段概括性摘要或一个局部总数。
- **分片总结引用**：
  - 每个时间片全文读取并整理后，必须先按主 Skill 第 3.2、3.3 节的内容使用和引用格式要求为总结添加引用，再保存。
  - 不能只在最终合并结果中补充引用。
  - 保存、回读和合并分片总结时，必须保留各项内容与来源引用的对应关系及完整来源链接。
- **保留分片结果与进度**：
  - **进度记录**：记录该片时间范围、已处理内容、完成状态及尚未获取或处理的范围。
  - **有文件能力**：
    - 每片全文读取并整理后，必须将带引用的总结、任务所需关键原文或记录依据及来源映射保存到可回读文件。
    - 不得只保存概括性摘要而丢失核对、去重或统计所需依据。
    - 处理当前批次时保留原文和来源；保存后上下文保留结果索引、必要的精简结果和处理进度。
    - 合并或核对时按需分批回读已整理结果，不重新加载全部原文。
  - **无文件能力**：
    - 控制后续获取规模，保留任务所需依据和处理进度。
    - 无法在上下文中可靠保留时，应说明处理限制，不得仅依赖对话压缩后的笼统摘要声称已完成。

时间切片不能替代分页，也不能突破权限或工具能力边界。只有实际查询和处理范围能够支持时，才能认定该片已完成；“有结果”不等于“已取完”，“查询失败”也不等于“没有记录”。

## 4. 合并与输出

资料获取后，基于各时间片结果统一处理：

- **依据进度补齐范围**：根据原范围内各片已记录的处理状态，对仍未完成的范围按对应工具规则补充处理。无法完成时明确保留缺口，不用其他已完成时间片代替。
- **去重与统计**：优先使用实际返回的稳定记录标识识别跨页、跨片重复；没有稳定标识且无法确认是否重复时，不得随意合并。统计基于去重后的记录，不能直接相加可能重叠的分片总数。
- **关联跨片内容**：同一讨论、事项或会议可能跨越时间片。依据记录中明确的关联信息组织连续内容，不把切片边界当作事项边界，也不因主题相似而强行合并。
- **按用户目标输出**：依据完整记录或已保留的分片依据进行提取、统计或汇总，不仅拼接各片摘要。内容使用和来源引用遵守主 Skill 第 3.2、3.3 节。
- **如实说明限制**：未取完、未处理完或无法确认覆盖的范围，应明确说明；不得声称结果完整或给出无保留的精确总数，也不得将未返回的记录解释为不存在。

## 5. 示例

用户请求：“汇总 7 月反馈群里的反馈。”

先按主 Skill 判断获取消息所需的路径，使用 `lark-im` Skill 及其支持的 `lark-cli` 能力确定群和查询范围。根据消息量选择时间片，例如先按周划分；每片保持相同的群、时间语义和用户限定，不额外添加用户未指定的关键词以缩小结果。

独立时间片可串行或并发获取，每片完成分页并整理反馈及来源。某片内容过多时再细分；没有取完的片保留为未完成。最后去重并关联跨片的连续反馈，按用户要求汇总，说明实际存在的覆盖缺口。是否还需补充背景或其他来源，另按主 Skill 路由判断，不因需要汇总就将消息枚举交给企业搜索。
