# 多轮上下文处理

本轮存在追问、省略、指代或来源切换时，必须先按本文件补全意图，再进入 `SKILL.md` 第 1 章进行路由判断；单轮独立问题无需读取。

多轮上下文处理既影响本轮路由，也影响调用时的 query 补全。执行顺序为：按本文件检查主题继承和来源切换 → 进入主 Skill 第 1 章判断路由 → 确定调用 `enterprise_agentic_search` 后，按主 Skill 第 2 章应用通用 query 规则，并按本文件补全历史上下文。

## 主题可继承，入口类型不继承

本轮如果是上一轮唯一主题的追问、补充、细化、筛选、范围收窄或来源切换，应继承上一轮核心问题、主体、对象、时间范围和限定条件继续判断，不得因为本轮表达短就直接追问。

显式入口的强制调用规则只在当轮生效。后续轮次如果不再包含 `[企业知识]` 或 `doubao-enterprise-search` 的 Skill 调用标记，则按语义召回边界判断；主题、来源方向和已确认约束可以继承。

只有本轮指代无法唯一解析时才请求澄清。上一轮存在多个主题、主体或时间范围，但本轮表达显然同时指向它们或不需要在其中选择时，应继续继承，不因候选数量多而澄清。

## 基于上下文补全 query

多轮继承后调用 `enterprise_agentic_search` 时，query 不应只传本轮短句，而应补全为可独立理解的问题；补全只限上一轮唯一主题和已确认约束，不得新增未确认来源或结论。例如上轮是“查 A 项目风险”，本轮是“B 团队呢”，query 应补全为“B 团队关于 A 项目的风险”。

本轮完整意图 = 上一轮仍有效的信息 + 本轮新增信息 − 本轮撤销或替换的信息。本轮明确表达覆盖历史信息，其他未冲突字段继续继承。

只在存在指代、省略时间、省略主体等必要信息时补全上下文，且补全必须保持原意；不得添加、替换或泛化用户未表达的信息来源、渠道、对象类型、工具范围、检索范围、核心主体、指代关系或限定条件。用户限定或排除来源、时间、对象、判断目标或输出口径时，query 和后续回答必须保留这些约束；涉及“我 / 当前用户 / 我们”时不得替换成其他对象，也不得根据问题主题、候选答案或检索结果反推用户身份、角色、组织或范围。用户未限定范围时保持开放检索，不要改写成特定来源、特定对象类型或特定渠道下的查询，也不得擅自扩大为更宽泛的主题分析、维度拆解或跨来源研究。

## 停止继承

本轮明确表达始终优先于历史上下文。出现以下任一情况时，不继承已被替换的旧信息，并根据本轮意图重新判断来源和路由：

- 用户开启了与上一轮无关的新主题；
- 用户明确切换了主体、对象、时间范围或信息来源；
- 本轮要求与历史约束冲突，或用户明确撤销、修改了旧要求。

只停止继承被替换或冲突的部分；仍被本轮指代、且不冲突的主题和约束可以继续继承。不得为了维持上一轮路由而忽略本轮的新意图。
