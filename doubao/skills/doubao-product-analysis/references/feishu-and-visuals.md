# 飞书报告与 HTML5 可视化

## 目录

- 主报告原则
- HTML5 block 选择
- 产品定位图证据规则
- 能力 Roadmap 图
- HTML 文件规范
- 写入与验证

## 1. 主报告原则

飞书云文档是唯一可独立阅读的报告。正文保留结论、事实 ID、证据口径、取舍和来源；HTML5 block 只压缩复杂关系，不承载正文缺失的关键事实。

推荐阅读路径：

1. 标题和 `as of`；
2. 一屏执行摘要；
3. 用户问题与市场机会；
4. 竞品机制和定位图；
5. 产品选择、核心能力与 Roadmap；
6. 来源、局限和待验证项。

每节先写结论，再给证据和产品含义。细节矩阵放在对应章节或折叠附录，不让读者先穿过方法论。

## 2. HTML5 block 选择

| 要回答的问题 | 首选形式 |
|---|---|
| 精确功能、价格、来源对比 | 飞书原生表格 |
| 玩家战略位置与目标选择空间 | `assets/product-positioning-map.html` |
| 用户问题如何进入能力与阶段 | `assets/capability-roadmap.html` |
| 单个关键流程如何工作 | 正文步骤 + 少量截图 |
| 连续市场趋势 | 仅在有同口径真实序列时用原生图或轻量 HTML |

同一信息不同时做正文表格、画板和 HTML。默认最多两个核心 HTML5 block；普通表格足够时可以只有定位图。任何被正文称为“见图”或列入交付物的视觉都必须真实生成并插入，不能只描述一个未交付的象限图或路线图。

## 3. 产品定位图证据规则

定位图不是装饰。生成前建立轴与点位底稿：

| 对象 | X 轴等级与事实 ID | Y 轴等级与事实 ID | 状态 | 备注 |
|---|---|---|---|---|

### 轴选择

好轴应满足：

- 两端代表真实的战略或用户价值取舍；
- 两轴相对独立，能区分代表性方案；
- 可以从产品行为、目标用户、商业模式或公开战略证据判断；
- 能帮助决定目标产品应该去哪里，而不是只描述谁更好。

避免：体验好/差、智能高/低、功能少/多、价格高/低与价值高/低这类价值判断或同义轴。可以使用如“通用工作流 ↔ 垂直深度”“用户主动编排 ↔ 系统自动执行”，但仍需结合具体产品重新定义。

### 点位与机会空间

- 有连续可比数据时才使用数值坐标，并在图下注明指标和来源；
- 没有时使用 3×3 低/中/高格位，点放在格子中间，不展示百分比刻度；
- 同一格存在多个产品时错开仅为可读性，不代表精确差距；
- 目标产品当前点位必须来自事实；建议点位用虚线/空心样式并标为“产品建议”；
- 建议空间旁列出成立条件和最大风险；无人区域先标“待验证”，不得写成已确认蓝海。

图前写一句最重要的战略差异，图后写目标产品的选择和代价。

## 4. 能力 Roadmap 图

能力 Roadmap 只展示主线：用户问题 → 选择的机制/价值 → 核心能力 → 三阶段结果与证据门。

每阶段最多呈现：

- 一个阶段结果；
- 1–3 项核心能力；
- 一个关键验证/停止条件；
- 一个明确非目标。

详细功能、负责人、精确指标和来源留在正文表格。没有资源和技术评估时不在图中写日期。

## 5. HTML 文件规范

- 单文件 HTML，不能依赖外部脚本、样式、字体或网络图片；
- 必须包含：

```html
<meta name="use-iframe" content="true">
<meta name="html-box-height-mode" content="auto">
<meta name="description" content="该图回答的问题与核心结论">
```

- `width: 100%`、`max-width: 100%`，按约 820px 飞书正文宽度设计；
- 浅色背景、高对比正文、字号不小于 12px，移动端可顺序阅读；
- 颜色不是唯一编码，状态同时使用标签、线型或图例；
- 无交互也能理解；不做导航、长滚动 Dashboard 或 hover 才显示的核心信息；
- 替换模板中的全部 `{{PLACEHOLDER}}`，不把说明文字、虚构数字或示例品牌带入成品。
- 图中涉及竞品能力、平台、价格、性能或认证时标注事实 ID，并在图后正文提供完整来源映射。

## 6. 写入与验证

使用飞书写入工具前读取其当前说明，特别是文档 XML 和 extended blocks。HTML 路径必须相对于执行文档写入命令的当前工作目录：

```xml
<html5-block path="@product-positioning-map.html"></html5-block>
```

交付前完成：

1. 本地打开或渲染 HTML，确认无溢出、遮挡和占位符；
2. 写入/更新飞书文档；
3. 回读文档，确认块位于正确章节；
4. 核对正文承诺的视觉数量与实际 HTML5 block 数量一致；
5. 预览执行摘要首屏、HTML 高度、表格、事实 ID 和来源链接；
6. 对存量文档确认无关内容、评论锚点和其他附件未被破坏。

权限或账号失败时，记录失败的具体工具、文档和错误；保留已完成的正文与 HTML 文件供重试，不声称云端已完成。
