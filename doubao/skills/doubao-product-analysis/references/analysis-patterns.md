# 产品分析路径

按用户要做的决定选择路径。可以组合，但只保留会影响当前决策的模块。

## 目录

- 进入、发布或继续投入
- 竞品或品类研究
- 存量产品调整
- 定位与差异化
- 核心能力与路线图
- 总结结论

## 1. 进入、发布或继续投入

### 核心问题

- 哪个细分用户的什么问题最值得解决？
- 用户是否已经用时间、预算、流程或风险为问题付出成本？
- 为什么现在可能成立？若不做，代价是什么？
- 市场价值、可触达性和可进入性是否同时成立？
- 目标产品凭什么进入，最大的不确定性是什么？

### 建议结构

1. 一句话判断：进入、先验证、继续观察或不进入；
2. 最强目标细分与问题证据；
3. 市场成立门与时机；
4. 主要替代方案和进入壁垒；
5. 进入方式、明确不做与差异化依据；
6. 最小验证计划和停止条件。

市场规模只是输入之一。即使 TAM 较大，问题不急、用户不可触达、壁垒不匹配或战略不一致，也可以建议不进入。

## 2. 竞品或品类研究

### 核心问题

- 比较对象是否解决同一用户任务，还是只在品牌上相邻？
- 各方案如何触发、完成、纠错和交付结果？
- 价值来自什么机制，代价和边界是什么？
- 哪些差异是版本、套餐、地区或用户细分造成的？
- 哪些启示能迁移，哪些只在特定前提下成立？

### 建议结构

1. 对比目的、对象、场景、版本与时间；
2. 用户指定维度的对比，每个维度写结论、差异、证据 ID 和边界；
3. 关键流程或机制差异；
4. 1–3 个跨维度的结构性分野；
5. 价值、成本、风险和适用边界；
6. 对当前决策的启示和待验证项；
7. 若用户要求产品规划，补目标用户、P0、Non-goals 与验证方法。

根据问题选择矩阵、分维度小节或流程图。不要机械要求每个维度一张表，也不要把所有差异压进单一功能清单。对比矩阵用于承载事实，结构性分野用于解释“为什么不同”，产品启示用于回答“因此怎么选”，三层不要混写。

先建立直接竞品、相邻方案、人工替代和“不处理”的候选池，检查最大、最可比及目标地区代表性对象是否遗漏；再选择少量关键对象深入分析，并说明纳入与排除理由。候选池用于防漏，不进入报告凑数量；发现遗漏对象可能改变结论时再补查。

可使用机制对比表：

| 用户任务 | 产品或替代 | 入口与流程 | 核心机制 | 自动与人工边界 | 用户结果 | 代价与风险 | 适用边界 | 事实 ID 与状态 |
|---|---|---|---|---|---|---|---|---|

事实表内的数字、平台、语言、权限、价格、认证、模型和政策必须带事实 ID。不能逐条回源的内容移入待验证项，不参与“谁更强”的判断。

好的结构性分野应同时满足：

- 两端代表真实的产品选择或用户代价，而非“好/差”；
- 能解释多个功能差异，而不是重新命名某项功能；
- 有至少两条已核验事实支持；
- 能导出明确的目标用户、借鉴、差异化或放弃。

## 3. 存量产品调整

### 核心问题

- 当前产品真实表现、使用路径和主要反馈是什么？
- 哪些能力已创造价值，哪些只是存在但未被采用？
- 问题来自价值、可发现性、可用性、质量、信任、定价还是渠道？
- 调整会破坏哪些已有体验、数据、承诺或工作流？
- 保留、调整、停止和新增的优先级是什么？

### 建议结构

1. 当前状态与证据边界；
2. 关键问题和根因假设；
3. 现有能力的保留、调整、停止、新增；
4. 方案选项与影响范围；
5. 迁移、兼容、运营和合规风险；
6. 分阶段验证与回滚或停止条件。

不要把存量产品当作 0→1 重写。区分已确认现状、用户反馈、分析推断和新的产品选择。

## 4. 定位与差异化

### 核心问题

- 对谁而言，目标产品需要成为哪类选择？
- 价值主张是否来自真实问题和可信机制？
- 哪些能力是品类门槛，哪些可能形成差异，哪些不值得投入？
- 差异化能否被用户感知、被产品兑现并被渠道解释？
- 选择该位置需要放弃什么？

### 建议结构

1. 目标细分和竞争参照；
2. 当前事实位置；
3. 可选定位及各自代价；
4. 推荐价值主张与可信理由；
5. 基础门槛、差异能力和明确放弃；
6. 验证信号与重审条件。

只有轴代表真实战略取舍且点位有证据时才使用定位图。无人占据的位置只是待验证空间，不是已确认机会。

## 5. 核心能力与路线图

### 能力卡

| 字段 | 要回答的问题 |
|---|---|
| 用户结果 | 这项能力持续改善什么结果？ |
| 独特机制 | 为什么比现有替代更有效？ |
| 系统组成 | 体验、数据或模型、工作流、质量、运营、生态包含什么？ |
| 依赖与边界 | 技术、数据、资源、合规、渠道和人工服务要求是什么？ |
| 质量门槛 | 未达到什么条件就不能发布或规模化？ |
| 竞争作用 | 品类门槛、差异化能力还是护城河候选？ |
| 证据状态 | 已验证、部分验证还是待验证？ |

只在交付方式影响决策时比较自建、采购或合作，并评估速度、控制力、数据、切换成本和长期投入。

### 路线图

先给 P0 验证闭环：一个目标用户、一个关键任务、最少必要能力、一个主要 Non-goal、一套验证方法和一个停止条件。

只有目标产品现状、资源、技术依赖和阶段证据足够时，再按最大不确定性扩展后续顺序：

- **验证**：闭合最小价值环，验证问题、价值或可交付性中的最大风险；
- **深化**：在证据成立后补齐质量、反馈闭环、复用和运营能力；
- **规模化**：在留存、价值、质量或商业门槛通过后扩展细分、渠道或生态。

每阶段写明目标结果、能力范围、非目标、依赖、证据与验收、继续或停止条件。功能清单可以作为实现明细，但不能替代路线图。

没有资源和技术评估时不写季度、月份或多年规划；没有指标定义、基线、样本和测量窗口时不写精确阈值。把长期方向写成条件式选择，不写成既定承诺。

## 6. 总结结论

尝试将总判断压缩为一句话：

> 面向【目标细分】的【关键问题】，建议【做/验证/调整/观察/不做】；现在优先【产品选择或能力】，借鉴【机制】、差异化【价值】、明确不做【范围】，因为【关键证据与时机】；若【重审信号】出现则调整。

若无法写出这句话，检查报告是否仍停留在信息汇总、是否缺少真实选项，或是否把假设写成了结论。
