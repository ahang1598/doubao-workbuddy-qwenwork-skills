# 多平台改写分发 Skill

目标：把用户提供的一篇母稿或一组素材，先整理成稳定的"母稿资产"，再按平台语法改写成可发布的多平台分发文档。重点不是文字缩短或换标题，而是为每个平台重新选择切口、结构、语气、互动方式和视觉呈现，同时保持事实一致。

## 1. 使用边界

### 1.0 判断流程（按优先级依次检查，命中即停止）

```
Step 1: 有没有用户提供的已有素材？
  → 完全无素材 + 自由发挥 → 不归本 Skill（见 1.2.1）
  → 有素材 / 有主题+信息点 → 继续 Step 2

Step 2: 是不是多平台分发（≥2个平台）？
  → 明确 ≥2 个平台 → 归本 Skill（见 1.1.1）
  → 只提单平台 → 继续 Step 3

Step 3: 单平台 + 有素材，意图是"把素材改成某平台版"？
  → 是 → 有条件归本 Skill（见 1.1.2）
  → 不是（纯创作/纯润色/纯翻译等）→ 不归本 Skill（见 1.2.2）

Step 4: 是不是论文/学术写作？
  → 是 + 要写论文正文 → 不归本 Skill（见 1.2.3）
  → 是 + 把论文改成平台内容 → 有条件归本 Skill（见 1.1.2）
```

**两条铁律**：
1. **平台名本身不是触发条件**：提到"小红书 / 公众号 / 短视频 / 微博"不自动进入本 Skill。
2. **"用本 Skill"不能覆盖边界**：用户调用本skill，或说"使用我上传的 skill / 按这个 skill 来"时，仍必须走以上判断流程。

### 1.1 应使用

#### 1.1.1 标准场景（直接进入完整工作流）

同时满足：**有素材 + ≥2个平台**

- 用户提供已有素材（母稿 / 文章 / 新闻稿 / 活动稿 / 产品稿 / 报告摘要 / 访谈素材 / 口播稿 / 散乱素材），要求做 ≥2 个平台版本。
- 用户明确说"一稿多发 / 多平台分发 / 内容矩阵 / 分发包 / 执行包 / 跨平台改写 / 同一内容发多个平台"。
- 用户提供母稿/素材，说"适合不同平台 / 不同平台都能发 / 几个平台都能发 / 平台化处理 / 适合平台传播 / 平台发布稿"。

> **「散乱素材」定义**：≥3 条具体信息点（事实、数据、观点、场景描述等），不是单纯的主题或方向。
> **「≥2个平台」定义**：明确提到小红书、公众号、短视频、微博中的任意 2 个及以上，或用"多平台/全平台/各平台"等泛指词。

#### 1.1.2 有条件使用（受限场景，仍用分发包结构）

满足素材条件，但平台数量或素材完整度不足：

| 场景 | 处理方式 | 限制条件 |
| --- | --- | --- |
| 单平台 + 有素材 + 意图是"把素材改成某平台版" | 只输出该平台版本，仍保留母稿资产、平台策略、平台成品、统一发布检查的完整分发包结构 | 不得新增母稿以外的事实 |
| 素材不完整但有主题 + ≥3 个具体信息点 | 先生成"分发母稿草案"，标注待确认事实，再做平台改写 | 不得编造案例、数据、体验、证言 |
| 母稿很短或只有一句话 | 可做结构化、场景化、口语化和平台语气改写 | 不得新增事实、数据、外部案例、用户反馈、权威背书 |
| 论文 / 研究材料 + 多平台分发意图 | 把论文/研究材料当母稿资产，改写成平台传播内容 | 不得生成学术论文正文 |
| 多平台 + 某单平台重点优化 | 输出多平台分发包，将该平台标为主平台并增强，其余为适配版本 | 不得跳过其他平台 |
| 内容天然偏某一平台 | 默认输出四平台版本，在分发策略中标注主发 / 次发 / 不建议强投 | 不得直接砍掉不建议的平台 |

### 1.2 不应使用

#### 1.2.1 无素材类

- **无素材 + 单平台从零创作 / 自由发挥**
  例："帮我写一篇小红书笔记，主题是早睡的好处。没有素材，你自由发挥就行。"
- **无素材 + 多平台创作**
  例："帮我做一个关于健身的多平台内容矩阵，从零开始，你自由发挥。"

#### 1.2.2 单任务类（有素材但不是平台改写）

- **纯润色 / 纯翻译 / 纯摘要 / 纯扩写**（没有"改成某平台版本"的意图）
  例："帮我把这篇文章润色一下""帮我把这篇文章翻译成英文""帮我写个摘要"
- **标题库 / 选题库 / slogan / 朋友圈文案 / 金句**（只产出碎片化内容，不成文）
  例："帮我想 10 个小红书标题""帮我写一句 slogan"
- **单平台独立创作**（即使有素材，但意图是"写一篇新的"而非"把素材改成"）
  例："帮我从零写一篇公众号文章""帮我写一个单独短视频脚本"

#### 1.2.3 内容品类不匹配

- **论文 / 学术论文 / 毕业论文 / 开题报告 / 文献综述 / 研究计划 / 研究报告**等学术写作或代写请求
  例："使用我上传的 skill，帮我写一篇论文，关于抖音的达人生态研究。"
- **短剧 / 小说 / 诗歌 / 散文**等文学创作
- **文案策划案 / 品牌策略案 / 营销方案**等方案类写作（非平台成品）

#### 1.2.4 执行动作类

- 要求**实际发布 / 排期 / 发群 / 私信 / 评论互动 / 日程提醒**等执行动作
- 要求**直播话术 / 带货脚本 / 客服话术 / 销售话术**等运营话术

#### 1.2.5 事实风险类

- 要求编造**体验、测评、用户证言、销量、疗效、收益、权威背书**或无法证实的外部事实
- 要求伪造**截图、热搜、榜单、新闻报道、数据报告**等

### 1.3 边界回复策略

#### 1.3.1 拒绝类（直接回复，不创建文档）

**场景：无素材 + 要创作**

> 这更像从零创作，不属于"多平台改写分发"。如果要使用本 Skill，请补充一段母稿/素材，或确认要把该主题做成小红书、公众号、短视频、微博等多平台分发包。

**场景：论文/学术写作 + 要写正文**

> 这个请求是论文/学术写作，不属于"多平台改写分发"。本 Skill 只能把已有论文、研究材料或文章改写成小红书、公众号、短视频、微博等平台分发内容；如果要使用本 Skill，请提供母稿或研究材料，并说明要分发到哪些平台。

**场景：纯润色/翻译/摘要/slogan 等**

> 这是纯润色/翻译/摘要类任务，不属于"多平台改写分发"。如果要使用本 Skill，请明确要改成哪些平台的版本。

**场景：要求执行动作（发布/排期/私信等）**

> 本 Skill 只负责生成多平台分发内容文档，不负责实际发布、排期、私信等执行动作。

#### 1.3.2 信息不足类（先补信息或降级处理）

| 场景 | 处理方式 | 回复/说明 |
| --- | --- | --- |
| 多平台意图明确但未指定平台 | 不追问，默认小红书、公众号、短视频、微博 | 在分发策略中标注"未指定平台，按默认四平台处理" |
| 用户说"全平台 / 所有平台 / 各平台" | 按本 Skill 支持范围处理为小红书、公众号、短视频、微博 | 不扩展 B 站、抖音、快手、视频号、知乎等，除非用户明确指定 |
| 用户只问"适合哪些平台 / 发哪里 / 哪个平台更适合"，无生产动词 | 不创建完整分发包，只输出平台适配建议 | 用聊天回复即可，不创建飞书文档 |
| 用户说"简单处理 / 不用太复杂"但有多平台意图 | 仍保留标准分发包和飞书文档交付，只压缩各平台模块 | 不改成交谈式短答，不取消飞书文档交付 |
| 缺素材但有多平台分发意图 | 只生成"分发母稿草案"，列出待确认事实 | 在统一发布检查中标注，不得编造 |

### 1.4 复合场景交叉策略

按以下优先级判断，高优先级覆盖低优先级：

1. **多平台改写优先**：只要有多平台分发意图 + 有素材，优先归本 Skill，即使其中包含单平台写法。
2. **单平台从零创作不归**：即使平台名命中本 Skill 支持的平台，只要是从零创作，就不归。
3. **有素材 + 单平台改写 = 有条件归**：单平台但有素材且意图是改写，归本 Skill（见 1.1.2）。
4. **事实核查 / 联网是辅助**：需要核查事实或联网时，核查是辅助动作，最终仍交付多平台分发包。
5. **生图是标配，不可用时降级标注**：需要生图但工具不可用时，标注"待生成 + 提示词"，不得声称已生成图片。
6. **复合需求拆分处理**：本 Skill 只负责分发包生产；发布排期、实际发文、私信引流、直播话术、评论区运营等需求，告知用户需拆出为后续任务，不在本 Skill 内执行。

## 2. 执行优先级

1. **唯一交付格式**：只允许输出 **标准可交付分发包**（母稿拆解 + 分发策略总览 + 平台成品 + 统一发布检查）。"短版 / 纯 Markdown"等要求不改变格式与飞书文档交付。
2. **飞书文档为最终交付**：必须创建并返回飞书文档链接；聊天内 Markdown 仅在飞书创建失败时作为兜底草稿并标注"任务尚未完成"。
3. **默认实际出图**：除非用户明确"不要图"，每个平台必须实际生成并插入 **2 张** 图片；提示词或"稍后再生成"不能替代成图。
4. **用户显式要求优先**：用户指定平台 / 长度 / 是否要图 / 语气优先遵守，但不得取消分发包结构与飞书文档交付。
5. **事实一致**：不新增母稿没有的事实、数据、功效、价格、排名、背书、评价、截图或报告。
6. **平台差异**：每个平台必须承担不同分发角色，不允许同文长短版；图片也必须体现平台差异。
7. **内容密度克制**：3 个及以上平台时每个平台只保留核心模块（小红书 / 短视频 3 个 / 微博 2 个 / 公众号直接输出完整文章）；1-2 个平台时可加 1-2 个扩展模块。
8. **结构唯一**：七大部分在文档中只允许出现一次；任何章节、模块或平台内容不得重复。

## 3. 飞书文档 Block 与排版约束

> **通用排版 / Block / 缩进 / 编号 / 空行 / 图片规则唯一以 `references/common/output-standard.md` 为准（SSOT）**。本节只保留最关键的红线摘要，冲突时以 output-standard.md 为准。

- **所有 Block 缩进层级 = 0**（禁止使用飞书 `indent` 属性；视觉层级只靠字号/字重区分）——详见 `output-standard.md §2`。
- **大章节独立顶级 Block**：写入新 `##` 大章节或紧跟表格/分栏/引用块之后的任何内容前，必须完整执行"空段落 Block → 验证根级 → `---` → 新章节"四步——详见 `output-standard.md §3`。
- **标题层级与编号**：分发包外层用 `## 一、`（中文数字+顿号）/ `### 1.`（阿拉伯+小数点）/ `#### （1）`（括号数字）；公众号文章内部独立三级（`标题：` H2 / `1.` H3 / `(1)` 加粗段落），禁止再次使用"一、二、三、"；同一编号格式全篇只代表同一层级——详见 `output-standard.md §4`。
- **空行与段落间距**：段间恰好一个空段落 Block；小节标题前后各恰好一个空行；表格/分栏/引用块/分割线与前后恰好一个空行；大章节首尾禁止空段落 Block；单段软换行 ≤2——详见 `output-standard.md §5`（小红书视觉锚点补充在 `platforms/xhs.md`）。
- **图片配文**：图片规格/尺寸/用途标注（`16:9` `横版` `封面头图` 等）绝不写入正文任何 Block；公众号图片下方一律无配文，其他平台允许 1 行短说明——详见 `output-standard.md §6`。
- **备选标题 / 附录**：使用引用块（Quote Block），不使用 `1.`/`(1)` 序号，不使用缩进——详见 `output-standard.md §7`。

**排版反模式（禁止）**：微博/小红书/公众号正文塞进短视频分镜表单元格；图片说明/标签/发布检查写进 table 单元格；同一大章节出现两次；大章节标题写进 grid column 或 callout；表格/分栏/引用块结束后没有 `---` 分隔就贴下一大章节；单图强行分栏；图片集中堆到文末；emoji/装饰符号作大章节标题前缀。

## 4. 唯一交付格式与工作流

### 4.1 唯一交付格式

始终使用 **标准可交付分发包**：母稿拆解 + 分发策略总览 + 平台成品（含图片）+ 统一发布检查。文档骨架、模块清单、图片放置详见 `references/common/distribution-package-format.md`。用户要"更完整、可执行、分镜、视觉 prompt"时只在对应章节增强，不切换档位。

### 4.2 多平台核心分工

| 平台 | 区分问题 | 内容重点 | 强化 | 弱化 | 成品形态 |
| --- | --- | --- | --- | --- | --- |
| 小红书 | 这和我有什么关系？ | 场景、利好、清单、避坑 | 用户收益、场景、收藏、封面点击、搜索标签 | 宏大背景、官方通稿、长论证 | 图文笔记、清单、避坑贴 |
| 公众号 | 这件事为什么重要？ | 背景、逻辑、解释、证据、叙事 | 结构递进、信息增量、论证链、手机阅读节奏 | 网感、碎片清单、只有情绪没有解释 | 长文、深度解读、方法文章 |
| 短视频 | 为什么我要继续看？ | 钩子、画面、动作、反差、节奏 | 前 3 秒、可拍动作、视觉证明、口语台词、镜头变化 | 抽象解释、复杂背景、长段口播 | 口播脚本、分镜脚本 |
| 微博 | 这件事值得怎么讨论？ | 观点、态度、话题、短句 | 判断密度、公共讨论、观点拆条、转评收束 | 长解释、弱观点、伪热搜感 | 单条观点、多条连发 |

### 4.3 标准工作流

1. **识别输入 + 拆母稿**：读 `references/common/source-analysis.md`，形成母稿资产与事实边界。若涉及热点 / 政策 / 真实品牌 / 近期事实或素材不足，同时读 `references/common/internet-search.md` 完成必要联网。若涉及新闻 / 医疗 / 法律 / 金融 / 教育 / 产品功效等，同时读 `references/common/fact-check-and-compliance.md`。以上三份可**并行读取**。
2. **确定平台**：用户指定则只输出指定平台；说"多平台 / 全平台 / 一稿多发 / 适合不同平台 / 平台化处理 / 适合平台传播"但未指定具体平台，则默认小红书、公众号、短视频、微博；只问平台建议时不创建完整分发包。
3. **读交付规格 + 平台规则**（可并行）：`references/common/distribution-package-format.md`、`references/common/output-standard.md`、以及所选平台的 `references/platforms/{xhs,wechat,short-video,weibo}.md`。
4. **出图**：除非用户明确"不要图"，读 `references/common/image-generation.md`；若需要更精细的封面设计再读 `references/common/cover-design-methodology.md`。为每个平台实际生成 **2 张** 图，按 `distribution-package-format.md §4-5` 放置。
5. **创建并交付飞书文档**；失败时给可复制 Markdown 兜底草稿并标注"任务尚未完成"。
6. 按 §5 完成前统一自检。

## 5. 完成前统一自检

覆盖交付、结构、Block、平台、图片、事实六个维度，此清单为唯一自检来源（其他文件不再重复）。

### 5.1 交付与结构

- 只输出标准可交付分发包，已创建并返回飞书文档链接。
- 先做母稿资产拆解再做平台改写；只输出用户指定或默认的平台。
- 平台数量与模块对应：≥3 个平台每个只保留核心模块；1-2 个平台最多加 1-2 个扩展模块。
- 无重复：无相同章节编号 / 标题 / 平台内容 / 图片模块 / 发布检查表。发现重复时删除副本，只保留第一份完整版本。

### 5.2 Block 与标题层级

- 每个大章节独立顶级 Block；表格 / 分栏 / 引用块结束后输出 `---` 分隔再开始下一大章节。
- **所有 Block `indent_level = 0`**（禁止飞书 `indent`），视觉层级只靠字号 / 字重区分（详见 `output-standard.md §2`）。
- 分发包外层 `## 一、` / `### 1.` / `#### （1）`；公众号文章内部 H2 `标题：` / H3 `1.` / 加粗段落 `(1)`。同一编号格式全篇代表同一层级，禁止跨层级混用（详见 `output-standard.md §4`）。
- 备选标题 / 附录使用引用块 Quote Block，不用编号，不用缩进（详见 `output-standard.md §7`）。
- 分镜表内无微博 / 小红书 / 公众号正文串入。

### 5.3 平台与图片

- 每个平台承担 §4.2 的区分问题；平台间视觉差异明显。
- 每个平台实际生成并插入 2 张图片（用户明确不要图除外），紧跟平台内容而非集中末尾。
- 单图不分栏，多图用二栏 / 紧凑表格；公众号图片下方**禁止**任何配文；其他平台图片说明作为独立段落 Block 紧跟图片。
- **图片规格 / 尺寸 / 用途关键词绝不写入正文**（`16:9` `横版` `封面头图` `800×` 等，详见 `output-standard.md §6`）。
- 短视频用 7 列分镜表；微博提供讨论入口而非公众号摘要。

### 5.4 事实与合规

- 保留母稿事实边界；未编造新事实、评论、销量、报告、榜单。
- 列明可直接发布内容 vs 需用户确认内容。
- 无绝对化词、无伪造真实截图 / 热搜 / 权威背书。

## 6. 文件职责边界

- `SKILL.md`：触发、边界、优先级、总工作流、统一自检；通用排版细则以 `output-standard.md` 为 SSOT，本文件只保留红线摘要。
- `common/output-standard.md`：**唯一通用排版 SSOT** — Block 层级与缩进 / 大章节独立性 / 编号规范 / 空行与段落间距底线 / 图片配文与图片规格标注禁令 / 备选标题写法 / 最低交付标准 / 统一发布检查表 / 禁止退化。
- `common/source-analysis.md`：母稿拆解、素材补全、事实边界。
- `common/distribution-package-format.md`：文档骨架、模块顺序、图片放置与排版、Block 实施细节。
- `common/internet-search.md`：联网判断、query 拆分、结果沉淀。
- `common/image-generation.md`：生图策略、素材优先级、提示词、生图质检、替代方案。
- `common/cover-design-methodology.md`：封面与图片设计方法、爆款封面方法论、画面风格技法、Prompt 模板。
- `common/fact-check-and-compliance.md`：事实核查与合规边界。
- `platforms/*.md`：该平台如何从母稿资产改写成平台成品；只保留平台专属内容，通用规则引用 `output-standard.md`，不重复。
