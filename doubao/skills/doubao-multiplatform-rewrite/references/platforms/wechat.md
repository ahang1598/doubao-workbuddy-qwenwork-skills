# 公众号平台改写规则

> 通用 Block / 缩进 / 编号 / 空行 / 图片规格标注禁令 / 备选标题写法 → 以 `references/common/output-standard.md` 为准。本文件只保留公众号平台专属规则。

## 平台角色

公众号回答：**这件事为什么重要？**

把母稿事实、观点、案例或活动整理成有背景、有解释、有递进、有信息增量的文章，读完真正理解一件事。

## 改写重点

强化：背景交代、问题意识、解释链和论证链、信息增量、结构递进、事实边界、手机阅读节奏。

弱化：过度网感、碎片清单、只有情绪没有解释、纯营销口号、小红书式夸张标题。

## 公众号文章内部三级层级（平台专属，覆盖通用编号规则）

**冲突背景**：分发包外层大纲已使用"四、五、"中文数字 + 顿号；公众号文章内部**严禁再次使用"一、二、三、"中文序号**，否则视觉层级完全重叠混乱。

公众号文章内部使用三级层级（每级样式互不重叠、字号严格递减）：

| 层级 | 内容 | 格式 | 编号 | 飞书样式 | 示例 |
| --- | --- | --- | --- | --- | --- |
| 文章主标题 | 全篇唯一 | `**标题：xxx**` | 无 | **H2 加粗** | `**标题：3 分钟一杯好咖啡**` |
| 章节标题 | 一级章节 | `**1. xxx**` | 阿拉伯 + 小数点 | **H3 加粗** | `**1. 为什么需要入门机**` |
| 小标题 | 章节内子小节 | `**(1) xxx**` | 括号数字 | **加粗独立段落** | `**(1) 家用场景：早晨 3 分钟出杯**` |

**强制规则**：

1. **主标题必须带 "标题：" 前缀**，H2，字号严格小于外层 `四、公众号版本`（H1）；全篇唯一。
2. **章节标题禁止中文序号**，只能用 `1. 2. 3.`，H3 加粗；严禁"一、二、三、"。
3. **小标题使用括号数字** `(1) (2) (3)` 作为加粗独立段落 Block，字重明显区别于正文。
4. **五级视觉层级严格区分**：外层 H1（`四、公众号版本`）> H2（`标题：xxx`）> H3（`1. xxx`）> 加粗段落（`(1) xxx`）> 正文；只靠字号 / 字重区分，**全部 `indent_level = 0` 不靠缩进区分**（详见 `output-standard.md §2 & §4`）。
5. **主标题唯一**；文末备选标题使用引用块（详见 `output-standard.md §7`），不使用 H2/H3/加粗/编号。

## 结构骨架

```markdown
四、公众号版本   <!-- 外层容器：H1 -->

## **标题：3 分钟一杯好咖啡，我用这台入门机做到了**   <!-- H2 + "标题：" 前缀 -->

【封面头图】

【正文开头段落】100-150 字，建立阅读必要性，承接标题承诺。

### **1. 为什么我们需要一台入门咖啡机**   <!-- H3，阿拉伯数字 -->

**(1) 家用场景：早晨 3 分钟出杯**   <!-- 加粗独立段落 -->
正文内容，短段落。

**(2) 预算与门槛：500-2000 元的取舍**
正文内容。

【文中结构图】

### **2. 挑选入门机的 3 个核心变量**

**(1) 萃取压力与稳定性**
正文内容。

**(2) 清洁与日常维护成本**
正文内容。

【结尾段落】收束全文。

---

> **备选标题**
> - 备选 A：xxx
> - 备选 B：xxx
> - 备选 C：xxx
```

**禁止规则**：

- ❌ 公众号文章内部使用"一、二、三、"等中文数字 + 顿号；
- ❌ 主标题写成纯 H1 或普通段落；
- ❌ 小标题与正文字重相同；
- ❌ 同一篇文章混用"一、"与"1."作为章节序号；
- ❌ 备选标题写成普通段落 + `1. 2. 3.` 编号（必须用引用块）；
- ❌ 任何 Block 使用飞书 `indent` 缩进属性（详见 `output-standard.md §2`）。

不再单独输出"文章定位 / 导语摘要 / 内容验真 / 图片"等目录大节；封面头图紧跟主标题后，文中图插入正文对应位置，事实边界统一收敛到文末发布检查。

### 扩展模块（仅 1-2 个平台时可选）

- **摘要 / 导语**：1-2 条推文摘要或开篇引导语。
- **文末互动引导**：1-2 条留言/在看/转发话术。

## 文章类型

按读者需求选：热点解读（时间线、背景、影响、争议边界）；专业解释（概念定义、变量拆解、案例验证）；方法文章（步骤、边界、误区）；品牌故事（场景、细节、转折、价值主线）；观点评论（中心判断、论证、反方处理）。

## 正文写法

先明确读者困惑：概念看不懂 / 机制看不懂 / 趋势看不懂 / 方法不会用 / 不知怎么判断。围绕**一个核心问题**展开，不平铺扩写。

- 开头建立阅读必要性，不寒暄；从困惑、误区、反常识、场景或关键数据切入。
- 正文开头 100-150 字承载原导语功能，不另设目录大节。
- 选题不写"大概念"，聚焦到一个具体问题。
- 小标题要有信息量，避免只写"01/02/写在最后"。
- 每节回答一个具体问题，推动文章向前。
- 短段落适配手机阅读。
- 深度不等于堆术语，解释要清楚。
- 素材不足时不假装完整证据链，在统一发布检查标注边界。

## 解释增强

三层解释法（一句讲清 → 拆机制 → 落场景）；变量拆解（2-4 个关键变量）；对比解释（"不是 A 而是 B"，纠正误区）；框架输出（结尾给可复用判断标准）；边界提醒（说明什么情况不适用）。

## 图片放置（平台专属）

公众号不设独立"图片"模块，2 张图分别放置：

1. **封面头图**：标题后正文前，正文舒适宽度。
2. **文中结构图**：插入正文对应小节内（讲完背景放时间线，讲完方法放流程图）。

- 默认 2 张：封面头图 + 文中结构图。
- 封面头图建立主题氛围，不塞太多字，横版或宽幅。
- 文中图优先做结构图/时间线/对比图/流程图。
- 风格克制、留白充足；不用高饱和廉价渐变。
- **图片下方一律不加配文**；图片规格 / 用途标注（`16:9` `横版` `封面头图` 等）**绝不写入正文**（详见 `output-standard.md §6`）。

## 排版风格

按内容自动选一种并保持统一：现代杂志风（人物/品牌故事/生活方式）；极简留白风（成长/职场/情绪）；知识卡片风（科普/教程/方法论）；高端商务风（企业/产业/报告）；文艺清新风（读书/心理/艺术/校园）。排版服务阅读，不为样式增加目录层级。

## 质检（平台专属，通用项见 output-standard.md）

- 是否回答"这件事为什么重要"，有核心问题和中心主线。
- 是否输出为完整可直接发布的文章。
- **五级层级严格区分**：外层 H1 > H2 主标题（`标题：`）> H3 章节（`1.`）> 加粗段落小标题（`(1)`）> 正文；**全部 Block `indent_level = 0`**；无"H3 章节缩进大于其下小标题"层级倒置。
- **同一编号格式全篇代表同一层级**：`1. 2. 3.` 只用于 H3 章节标题；`(1) (2) (3)` 只用于加粗段落小标题；备选标题用引用块不用编号。
- 有信息增量，标题不欺骗不夸大。
- 封面头图与文中结构图分别放在主标题后和正文对应位置；**图片下方无任何配文**；**正文无 `16:9` / `横版` / `封面头图` / `文中结构图` / `800×` 等图片规格关键词残留**。
