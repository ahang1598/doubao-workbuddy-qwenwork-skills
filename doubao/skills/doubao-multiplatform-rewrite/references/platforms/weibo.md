# 微博平台改写规则

只负责微博版本如何从母稿资产改写成传播内容。

## 平台角色

微博回答：**这件事值得怎么讨论？**

把母稿事实、观点、情绪或争议，提炼成可转发、可评论、可参与的话题入口。不是公众号摘要，也不是小红书短版。

## 改写重点

强化：观点密度、话题参与、公共讨论、短句传播、观点拆条、转评引导。

弱化：长解释、弱观点、生活碎碎念、伪热搜感、过度营销口号。

## 输出结构

> 层级示例展示"平台大章节内部结构"。写入飞书时由 `## 六、微博版本`（按顺序对应中文序号）承接。
>
> **⚠️ 强制约束（`SKILL.md §3.1` STEP 1-4）**：微博紧跟短视频分镜表后，是"微博正文被写进分镜表最后一列"的**最高发生位置**。写 `## 六、微博版本` 前**必须**：① 先调用一次写入 API 在分镜表后插入根级空段落 Block，强制脱离 table；② 验证该 Block 父级为文档根级（非 table）；③ 追加独立段落 `---`；④ 再插入 `## 六、微博版本`。跳过 ① = 执行错误，必须回滚重写。

```markdown
## 六、微博版本

### 1. 微博配图
<grid>
<column>图片 1</column>
<column>图片 2</column>
</grid>

### 2. 微博正文
- 单条微博备选 2-3 条；或复杂内容给 3-4 条连发版。
```

不再单独输出传播切口、单条版本、多条连发版本、正文末尾标签、转评动作、观点短句等目录大节；话题、互动和短句融入微博正文。

### 扩展模块（仅 1-2 个平台时可选）

- **评论区引导话术**：2-3 条互动引导，含具体讨论问题、投票选项或站队方向。

## 微博正文写法

先把母稿压成一个可讨论判断：支持什么 / 反对什么 / 提醒什么 / 重新定义什么，或把个体经验公共化。

- 开头直接给判断/问题/反差/讨论点。
- 一条微博一个核心观点，不塞完整背景。
- 事实作为观点支撑，不堆资料。
- 保留转发理由：有判断 / 有情绪 / 有信息 / 有立场 / 有提问。
- 标签 2-4 个直接放正文末尾。
- 转评引导用一个具体问题收束，不泛泛"你怎么看"。
- 不伪造热搜、网友评论或平台趋势。

## 观点增强

判断先行（先"我怎么看"再给事实支撑）；冲突外显（提炼选择/分歧/误区/代价/反差）；公共化表达（个体经验 → 更广泛的问题）；观点短句拆条；讨论闭环（结尾给具体问题）。

## 连发写法

3-4 条，同一模块内：① 抓讨论（判断/问题/冲突/公共情绪）；② 补事实（关键事实支撑）；③ 讲影响（为什么和更多人相关）；④ 引互动（补充案例/站队/转发/提问）。每条递进，不把公众号段落切碎。

## 视觉衔接

模块名 **微博配图**，放在微博版本最前。默认 2 张：场景图 + 内容图（二栏或紧凑表格）。建议 1:1 或 16:9，每张图上只放一句核心判断或一个讨论问题。每张图下方 1 行短说明（用途 · 风险时加素材边界）。风格有传播感、观点感、留白充足；信息密度不过高；不制作伪热搜/伪评论/伪媒体报道。

## 质检（平台专属，通用项见 SKILL.md §5）

- 是否回答"这件事值得怎么讨论"，有明确观点而非平铺说明。
- 是否只保留两个核心模块，不像公众号摘要。
- 是否有具体转评问题；无伪造热搜、网友观点或平台背书。
- **写入前是否严格执行 STEP 1-4**：分镜表后先插入根级空段落 Block 强制脱离 table，验证父级为文档根级，追加 `---`，再插入 `## 六、微博版本`。分镜表最后一列不得出现微博正文残留。
