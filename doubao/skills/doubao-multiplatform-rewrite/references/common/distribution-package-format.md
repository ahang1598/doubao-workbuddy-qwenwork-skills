# 多平台分发包格式

负责最终文档结构、模块顺序、图片放置与排版，以及飞书 Block 实施细节。不写平台文案方法（在 platforms/*.md），不重复事实核查与 SKILL.md 顶层规则。

## 1. 文档交付原则

- 唯一交付格式：**标准可交付分发包**（`SKILL.md §2`）。
- 最终必须创建为飞书文档并交付链接；聊天内 Markdown 只在飞书创建失败时兜底。
- 多平台全量输出时克制，避免拆成 7-8 个小节。
- 用户要"只要正文 / 越短越好 / 先给初稿"仍创建文档，只保留核心模块。
- **平台数量与模块丰富度对应**：≥3 个平台只留核心模块；1-2 个平台可加 1-2 个扩展模块。

> 结构唯一性、Block 独立性、标题层级由 `SKILL.md §3` 统一定义，本文件不重复。

## 2. 标准分发包骨架

```markdown
# 多平台改写分发方案｜主题

## 一、母稿拆解
- 原文主题 / 核心主线 / 目标受众 / 关键信息（≤3）/ 分发切口（≤3）/ 风险与待确认（≤3）

## 二、分发策略总览
| 平台 | 平台角色 | 核心切口 | 成品模块 |
| --- | --- | --- | --- |

## 三、小红书版本
### 1. 笔记配图
### 2. 标题
### 3. 正文

## 四、公众号版本
（直接输出完整文章，不拆分标题/正文编号模块；封面头图放在标题后、正文前；文中结构图插入正文对应位置）

## 五、短视频版本
### 1. 封面图
### 2. 创意策略
### 3. 分镜表

## 六、微博版本
### 1. 微博配图
### 2. 微博正文

## 七、统一发布检查
```

只输出用户指定或合理默认的平台；编号按实际顺延（例如仅小红书 + 公众号时，小红书 = 三、公众号 = 四、统一发布检查 = 五）。不新增视觉参考、图上文字、正文末尾标签、互动收束、观点短句等独立大节；需要时并入正文、分镜表或统一发布检查。

## 3. 平台核心模块与扩展模块

### 3.1 核心模块（所有平台数量下均保留）

- **小红书 3 个**：笔记配图、标题、正文。标题给 3-5 个备选；标签和互动收在正文末尾。
- **公众号**：直接输出一篇完整文章，**不拆分编号模块**。标题后紧跟封面头图；文中结构图插入正文对应小节；短段落 + 加粗小标题。
- **短视频 3 个**：封面图、创意策略、分镜表。开场吸引点、情绪弧线、视觉风格写进创意策略；口播、镜头、剪辑合并进分镜表。
- **微博 2 个**：微博配图、微博正文。正文可给 2-3 条单条备选或一组连发，都放在同一模块内。

### 3.2 扩展模块（仅 1-2 个平台时可选，最多加 1-2 个）

- **小红书**：`话题标签备选`（5-8 个，核心 / 流量 / 长尾）/ `评论区互动引导`（2-3 条）。
- **短视频**：`标题文案`（3-5 个视频/封面备选）/ `道具清单`（必选 / 可选）。
- **微博**：`评论区引导话术`（2-3 条讨论问题 / 投票 / 站队）。
- **公众号**：`摘要 / 导语`（1-2 条）/ `文末互动引导`（1-2 条）。

## 4. 图片模块命名与放置

| 平台 | 模块名 | 数量 | 位置 | 排版 |
| --- | --- | --- | --- | --- |
| 小红书 | `笔记配图` | 2 | 小红书版本最前（标题前） | 二栏或紧凑表格 |
| 公众号 | 无独立模块 | 2 | 封面头图放标题后、正文前；文中结构图插入对应小节 | 单图正文宽度，不分栏 |
| 短视频 | `封面图` | 2 | 短视频版本最前（创意策略前） | 二栏或紧凑表格 |
| 微博 | `微博配图` | 2 | 微博版本最前（正文前） | 二栏或紧凑表格 |

图片下方保留 1 行简短说明（独立段落 Block），格式：`用途 · 素材边界（仅风险时标注）`。

- 默认只写用途，如 `封面图`、`场景图`、`文中结构图`。
- 涉及真实感风险（可能被误认为真实截图 / 产品 / 数据）时才加素材边界，如 `封面图 · 概念场景，非真实`。
- `状态: success` 不写；只有 `blocked` 时单独标注原因。
- 不写"图上文字"。
- **公众号例外**：所有图片下方一律不加任何配文（`SKILL.md §3.4`）。

## 5. 图文排版方式

### 5.1 单张图

不强行分栏：

```markdown
### 1. 微博配图
<image url="..." />

场景图 · 概念视觉，非真实
```

### 5.2 两张及以上

用二栏或紧凑表格：

```markdown
### 1. 笔记配图
<grid>
<column>图片 1 + 短说明</column>
<column>图片 2 + 短说明</column>
</grid>
```

规则：默认每平台 2 张图（公众号除外）；小红书 / 短视频 / 微博用二栏或紧凑表格；公众号封面头图放标题后正文前，文中结构图插入对应小节；只有 1 张时不分栏；图片宽度控制在栏宽或正文舒适宽度；不使用 emoji 做标题前缀。

### 5.3 视觉差异

- 图片精美、清晰、有留白；同文档图片风格统一（字体气质、圆角、阴影、色彩）。
- 平台差异：小红书生活化 / 公众号克制 / 短视频动态钩子 / 微博观点传播。
- 建议比例：小红书 3:4；公众号横版或宽幅；短视频 9:16；微博 1:1 或 16:9。
- 不用低质渐变、密集小字、廉价素材、无关插画、平台标识、水印、二维码。

## 6. 飞书 Block 层级实施细则

**总规则见 `SKILL.md §3.1`（含四步强制执行步骤：先插入根级空段落 Block 脱离表格 → 验证脱离成功 → 输出 `---` → 再插入 `##` 章节标题）**。

### 6.1 五处最易踩坑的写入路径

以下每一步的"→ 跳出"都对应 SKILL §3.1 的 STEP 1-4，**不能省略先插入空段落 Block 的动作**：

1. `## 二、分发策略总览` 表格写完 → cursor 停在 table 内 → **必须先插入根级空段落 Block 脱离 table，再输出 `---`，再插入 `## 三、小红书版本`**。
2. `### 1. 笔记配图` 的 `<grid>` 写完 → **必须先插入根级空段落 Block 闭合 grid**，再插入 `### 2. 标题`。
3. **短视频 `### 3. 分镜表` 写完 → cursor 停在 table 最后一个单元格 → 若直接下一动作是插入 `## 六、微博版本`，会导致微博正文被写进分镜表最后一列（历史高发 bug）**。必须严格执行 STEP 1-4：先插入根级空段落 Block → 验证 Block 父级为文档根级 → 输出 `---` → 再插入 `## 六、微博版本`。
4. 短视频 `### 2. 创意策略` 若用 `>` 引用块承载 → 写完后 **必须先插入根级空段落 Block 闭合引用块**，再插入 `### 3. 分镜表`。
5. 公众号"文中结构图"作为独立段落 Block 插入正文小节之间，不嵌进段落 Block 内。

### 6.2 一次性排版自检信号

- **目录树信号**：目录树里"六、微博版本"应与"五、短视频版本"处于同一父级（都是文档根级）；若"六、微博"缩进到分镜表下面 = 被写进了 table，必须回滚重写。
- **单元格信号**：短视频分镜表最后一列（"音效/花字"）中若出现"微博 / 观点 / 讨论 / 转评"等词，几乎可判定微博正文被误写入分镜表，立即回滚。
- **Block 父级检查**：写完每个 `##` 大章节后立即检查 Block 父级 ID 是否等于文档根 ID；不等则脱离父容器后重写。

## 7. 文档排版原则

- 一级标题控制总结构，二级承载平台内模块，三级保留核心细分；扩展模块也用 `###`。
- 表格只用于分发策略、短视频分镜、发布检查等真正需要横向比较的内容。
- 正文区可复制，不夹杂内部说明、过程解释和提示词。
- 事实边界、来源、待补充素材统一收敛到"统一发布检查"。
- 各版本之间用独立段落 Block `---` 分隔。
