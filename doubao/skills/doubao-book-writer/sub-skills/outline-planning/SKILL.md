# Outline Planning（大纲规划与冻结）

本阶段把需求翻译成可执行的章节结构，经用户确认后冻结。大纲结构是"准备"的一部分：长稿的 `make prepare` 会调用大纲结构门禁强制校验章节表、依赖、预算与台账一致性。

## 职责边界

- 从需求清单推导章节列表、核心问题和收获点。
- 写入 `outline.md`（用户可读真源）和 `chapter-ledger.md`（章节台账）。
- 冻结大纲：`outline.md` 与 `chapter-ledger.md` 通过 `make prepare` 的结构门禁即视为冻结，不再单独维护版本号或时间戳（三阶段模型以产物文件为状态，不写 `state.json`）。
- 管理变更：冻结后调整结构须先与用户确认，再改 `outline.md` 与 `chapter-ledger.md` 并重跑 `make prepare`。

## 大纲结构要求

大纲结构门禁校验以下内容（长稿 `make prepare` 强制），写作时按此组织 `outline.md`：

- 必需 `##` 章节：核心主张、语气/作者声音、目标读者、章节规划、章节依赖关系、总字数目标；
- 章节规划表列：`章节 | 标题 | 核心问题 | 用户收获 | 目标字数`；章节 ID 从 `ch01` 起连续唯一，标题唯一，核心问题与用户收获非空，目标字数为正整数；
- 各章目标字数之和必须完整分配全书目标，且全书目标落在需求清单字数契约区间内；
- 章节依赖表列：`章节 | 前置章节`；依赖章节存在、位于当前章之前，无自依赖和循环；
- `chapter-ledger.md` 的章节 ID、标题、目标字数与大纲逐行一致。

## 大纲完成标准

- `outline.md` 已写入，含核心主张、作者声音标签、目标读者、章节规划表、章节依赖表和总字数目标，各章目标合计等于全书目标且落在清单字数契约内；
- `chapter-ledger.md` 已写入，每章一行（编号、标题、状态、计划字数、已写字数），与大纲逐行一致；
- 长稿 `make prepare` 返回 `status: pass`（通过即视为大纲冻结）。

短稿跳过本阶段，需要段落规划时直接在 `manuscript.md` 内组织，不创建伪长篇台账。大纲结构只能由脚本判定，不手写自称通过。

## 与其他阶段的衔接

- 上游 `project-intake`：提供需求清单和布局判定。
- 下游 `manuscript-writing`：需要冻结的大纲作为写作锚点。
- 长稿改写：重新确认结构后先走变更单再重新冻结；短稿不进入本阶段。
