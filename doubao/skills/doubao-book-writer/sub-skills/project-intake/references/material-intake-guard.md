# 项目素材收束规则

本规则服务于新建书稿的素材阶段。已有书稿切换任务时从磁盘恢复现状，不重建布局并覆盖现有产物。

## 阶段目的

素材阶段要回答的是“现有材料能否支持需求冻结”，不是“是否已穷尽所有资料”。满足写作所需的事实、观点和案例覆盖后，应进入下一阶段；继续搜索必须对应一个明确缺口。

## 收束判断

出现以下任一情况时，执行器应向用户说明材料已可用于需求确认，并给出不超过三个后续动作：

- 已达到用户或项目配置约定的最低材料量，并覆盖主要主题；
- 两轮连续补充没有产生新的关键证据，只是在同一方向增加近似材料；
- 用户连续要求“继续”，而本轮素材任务已经结束；
- 一轮实际搜索填补了原有核心缺口。

用户明确要求继续收集时，应记录新的缺口、用途和停止条件。不得把“再丰富一些”当作无限检索授权。

## 搜索证据要求

新建或整体改写在正文前至少覆盖三个不同检索方向。随后检查缺口；仍缺数据、案例、反方观点或时效信息时再定向补搜。

有效证据应写入 `sources.md` 或 `sources/`，至少包含来源、日期、可用结论和目标章节。搜索计划、工具成功提示、无链接摘要都不算来源。搜索不可用时要明确降级，并只使用用户材料与已验证内容。

## 预算和重复控制

达到充分线后，每次新增材料都应绑定缺口编号或目标章节。追加前检查相同 URL、标题与事实是否已经存在；重复材料应合并引用，而不是换一个分类再次入库。

`project-config.materialGatherNotesMaxChars` 是素材笔记的软上限。超过上限时运行写作契约门禁会给出警告；扩展预算需要用户确认。

```bash
node scripts/gates/style-contract-gate.mjs --workspace <workspace>
```

## 用户新增质量要求

“案例不重复”“每类至少若干条”等约束若不影响当前需求冻结，应记入需求清单的 `qualityConstraints` 备注，留给大纲或写作阶段落实。只有当该约束决定可否开写时，才继续停留在素材阶段。

## “继续”的解释

| 当前事实 | 处理方式 |
|---|---|
| 素材已足够，用户说“继续” | 转入需求确认或长稿大纲规划 |
| 缺少已点名的关键材料 | 说明缺口和预计补充范围后继续检索 |
| 已进入正文阶段，用户说“继续写” | 从磁盘恢复状态并继续写章 |
| 上一轮中断 | 从磁盘正文与已生成的检查报告恢复，不重新开始素材收集 |

## 工作区与状态边界

只读写当前 `WORKDIR`。未经用户明确授权，不读取兄弟目录中的其他书稿。素材阶段是否收束由现有材料能否支持需求冻结决定；准备阶段是否通过由 `make prepare` 的现场检查决定，执行器不能手改报告文件来制造通过。

长篇项目只有完成大纲冻结后才维护 `chapter-ledger.md`，素材阶段不得提前伪造章节完成记录。
