# 书稿质量审计契约

本文件定义如何解释质量报告。脚本负责产生证据，`make write` 的形态与清洁检查是硬门禁，`make quality` 提供深度质检评分；人工或模型不能在缺少有效脚本结果时自行宣布通过。

## 一、先确定审计边界

先从磁盘确认正文布局和本轮授权范围。短稿检查 `manuscript.md`；长稿检查 `manuscript/chNN-*.md`。局部编辑只扩展到判断一致性所需的相邻内容，不借质检改写未授权章节。

若目标是尚未纳入项目的存量 Markdown，可使用审计脚本的 standalone 能力输出诊断，但这不等于建立了完整书稿项目，也不能直接进入交付。

## 二、结果由三部分组成

### （一）四层评分

机器审计把可观察信号分成四层，每层按通过规则占比换算为十分制：

| 层级 | 观察对象 | 规则 |
|---|---|---|
| S | 句子表达 | S1–S6 |
| P | 段落推进 | P1–P4 |
| C | 章节组织 | C1–C4 |
| B | 全篇结构与节奏 | B0、B1、B2、B4、B5、B3 |

综合分按四层等权平均，保留一位小数：

```text
overall = (S + P + C + B) / 4
```

B0 既参加 B 层评分，也是结构风险项。编号冲突不能用其他高分抵消。

### （二）硬门禁

门禁只有 `pass` 或 `fail`，不参与平均分。任一必需门禁失败，即使综合分很高也不得交付。

终稿的写作形态门禁由 `make write` 强制执行（内部调用 `check-writing-shape.mjs`），报告写入 `.doubao-book-writer/reports/`。以下确定性问题会被检查：可见标题使用阿拉伯数字层级、连续编号冒号项替代正文、短引导语后堆叠列表、体裁不适用的论文式标题，以及超过脚本阈值的模板化表达。

事实可靠性、版权、用户定制要求和专业判断属于人工复核门禁。人工结论要列明证据和未决风险，不能只写“已检查”。

### （三）附加观察

图表与视觉材料密度可以作为 V1 记录，但默认不进入四层总分。只有用户明确要求图文书或展示型成品时，才把视觉支持度纳入项目专属门禁。

## 三、判定口径

| 状态 | 条件 | 后续动作 |
|---|---|---|
| 通过 | 综合分不低于 7.5，且所有必需门禁通过 | 可进入交付准备 |
| 待润色 | 综合分为 7.0–7.4，且门禁通过 | 修订主要问题后复测 |
| 不通过 | 综合分低于 7.0，或任一门禁失败 | 修订并重新生成证据 |

机器扫描定位风险，不替代事实核查。自动修复只能生成候选变更；应用后仍要重跑同一检查，并复核修改是否改变原意。

## 四、审计方式

### （一）小规模与局部任务

十个以内的正文文件直接执行完整深度质检。`make quality` 一次性给出 S/P/C/B 四层评分与机器可检项（破折号、长句、绝对化命令词、无来源数字、命令词密度）：

```bash
make quality WORKDIR=<书稿目录>
```

报告写入 `.doubao-book-writer/reports/quality_check.json`。深度质检默认门槛综合分 7.5，可用 `--min-score` 调整（通过 `check_quality.mjs` 直接运行时）。

### （二）大规模书稿

正文超过十个文件时，先做全量机器扫描，再按风险选择章节精检。超过五十章时应按卷或目录分组，避免随机抽样掩盖局部异常。概览阶段只负责定位，不能代替终稿所需的完整门禁。

节奏变异、结构雷同等依赖上下文的指标应在精检阶段计算。报告标记“待精检”意味着尚未形成最终结论。

### （三）全书一致性

长稿还需执行跨章检查和全书总账：

- [`cross-chapter-consistency.md`](./cross-chapter-consistency.md) 检查主张、数据、对象与承诺在章节之间是否冲突；
- [`whole-book-audit.md`](./whole-book-audit.md) 汇总术语、来源、表达和发布风险；
- 修改正文后重新运行 `make write` 与相关质量脚本。

## 五、句段章篇速查

| 编号 | 核心问题 |
|---|---|
| S1 | 开头是否直接进入具体问题、事实或场景 |
| S2 | 程度修饰与强命令表达是否有必要 |
| S3 | 长句是否妨碍理解，节奏是否单一 |
| S4 | 段落是否依赖模板连接词推进 |
| S5 | 行业套话是否替代了具体含义 |
| S6 | 破折号等标点是否形成机械模式 |
| P1 | 段落是否围绕问题或判断推进 |
| P2 | 引语、案例或证据是否真正支撑论点 |
| P3 | 是否反复使用对称排比制造完整感 |
| P4 | 删去某段后信息是否没有损失 |
| C1 | 章节是否说明结论的条件和局限 |
| C2 | 结尾是否完成本章任务并推动后文或行动 |
| C3 | 各部分长度和结构差异是否符合内容需要 |
| C4 | 数据是否具体且口径可核验 |
| B0 | 标题编号和层级是否唯一、连续、合法 |
| B1 | 标题是否摆脱固定句式批量生成的痕迹 |
| B2 | 段落长度、标点与章节结构是否有自然变化 |
| B3 | 全书节奏是否既有变化又保持可读性 |

详细句级阈值见 [`sentence-discipline.md`](./sentence-discipline.md)。

## 六、报告最低信息

章级报告至少记录文件、四层分数、综合分、门禁结论、命中位置和修订状态。全书报告增加检查范围、规模策略、跨章问题和未决风险；正文较多时把逐章证据拆到独立报告，主报告只保留汇总与高优先级问题。

```markdown
## 质量结论

- 范围：manuscript/ch01-*.md 至 manuscript/ch08-*.md
- 模式：全量扫描 + 风险章节精检
- 综合分：7.8/10
- 写作形态门禁：pass

| 优先级 | 规则 | 位置 | 证据 | 处理状态 |
|---|---|---|---|---|
| P0 | B0 | 第三章 | 标题编号重复 | 已修复并复测 |
| P1 | S5 | 第六章 | 套话掩盖具体动作 | 待作者确认 |
```

最终交付仍以本地 Markdown 为内容真源。质量报告只记录检查过程，不得反向覆盖正文。
