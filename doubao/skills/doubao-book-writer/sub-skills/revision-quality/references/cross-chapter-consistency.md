# 全书跨章一致性审查

跨章审查解决单文件评分看不到的问题。长稿、多作者并行稿、对称章节和“一章一个对象”的分类型书稿都应在终稿清洁前执行；短稿可按实际结构缩减范围。

## 审查输入

执行前读取大纲、章节台账、全部当前正文、来源记录、项目简报和术语约定。正文与磁盘状态不一致时，以 Markdown 真源为准，先修正台账再继续。

## 七个检查面

| 编号 | 要查什么 | 合格条件 |
|---|---|---|
| CX-1 | 同一主题的结论、推测和事实状态 | 不互相矛盾；不确定内容明确标注边界 |
| CX-2 | 重复出现的数据、日期、单位和统计口径 | 数值一致，或解释差异来自何种口径 |
| CX-3 | 对称章节的篇幅、问题深度与证据量 | 差异来自内容需要，而非遗漏 |
| CX-4 | 跨章复述、对象重复和近似案例 | 后章提供新信息，重复内容压缩为引用 |
| CX-5 | 前文提出的框架、问题与承诺 | 后文有回应，未兑现项有处置说明 |
| CX-6 | 同一来源的引用方式和可用结论 | 不断章取义，不在不同章节给出相反解释 |
| CX-7 | 叙事人称、语气、术语和案例偏好 | 与项目风格约定一致，变化有明确设计理由 |

## 分类型章节的写前查重

若每章围绕人物、地区、公司、品牌、产品或其他独立对象展开，Chapter Brief 确认后、写正文前执行以下检查：

1. 从已完成章节和术语表提取已写对象及别名。
2. 提取本章核心对象、时间范围和预定角度。
3. 判断对象是否相同，以及内容范围是否高度重合。
4. 发现重合时，在写作前选择处理方式并记录。

默认处理不是再次完整介绍，而是保留本章的新角度，并用一句话指向首次完整出现的章节。若概要有助于理解，可用短段概括后跳转。只有用户明确接受重复时才完整重述，并把决定写入项目配置或变更记录。

## 段落级重复判断

不要只按关键词判重。先比较段落的核心结论、证据和推理顺序；三者大体相同且只是换词时，视为重复。保留信息最完整或最早承担定义职责的一处，其他章节改为引用、补充证据或承担不同论证任务。

## 修订顺序

先处理事实矛盾和对象重复，再统一术语与风格，最后检查承诺回收。CX 与全书总账可以并行检查，但发现问题后都必须回到 Markdown 修订；修改正文后重跑 `make write`（形态、字数、台账）与相关质量脚本。

## 报告格式

报告按 CX-1 至 CX-7 排列。每项记录结论、涉及章节、原文证据、优先级和处理结果。分类型重叠另加一张表：对象、首次章节、重叠章节、差异角度、最终处置。

没有问题时也应记录检查范围和“未发现冲突”，不能只写笼统的“已检查”。报告不是通过凭证，交付前的硬形态与清洁仍由 `make write` 判定。
