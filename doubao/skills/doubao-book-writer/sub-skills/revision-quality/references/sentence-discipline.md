# 句级表达检查

S 层用于发现句子层面的机械表达。它提供可重复的检查方法，不要求把所有句子压成同一种短句，也不把词表命中直接当作错误。修改应以信息准确、语义自然为先。

## 一、检查流程

1. 先运行机器扫描，获得词项、句长和标点位置。
2. 回到上下文判断命中是否承担真实信息。
3. 重写句意和结构，不做机械同义词替换。
4. 对修改后的正文复跑同一脚本。
5. 在报告中保留位置、处理方式和仍需人工确认的例外。

机器词典真源为 `directive-lexicon.json`。其受保护短语应先从扫描文本中排除；规范、法律和安全红线中的命令语气也要结合体裁判断。

## 二、六项评分规则

### （一）S1：具体开场

章节和重要段落应尽快交代人物、场景、事实、数据、冲突或待解决的问题。纯趋势判断、空泛定义和“众所周知”式开头会推迟信息进入。

不合适：`行业持续变化，企业都在寻找新的效率答案。`

更具体：`周一早上，客服队列里还有 137 条消息没人处理。`

并非每段都要使用戏剧场景；准确的问题句或事实句同样合格。

### （二）S2：修饰和命令语气

程度词只有在提供可辨认的强度差异时才保留。删除后含义不变的修饰应删去；可以核验时，用数量、条件或比较对象替代模糊强度。

`效率显著提升` 不如 `平均处理时间从 18 分钟降到 11 分钟` 具体，但缺少可靠数据时也不能编造数字。

机器扫描的程度词包括“非常、显著、大幅、高度、深入、极其、充分、彻底”等。诸如“深度学习”“高度不确定”属于完整术语或有实际含义的搭配，可由词典保护。

命令表达包含“无论如何”“绝不能”这类强制语气，也包括在命令语境下出现的“务必”“必须”“一定”。写作稿全书合计建议不超过 3 次；超过时检查是否能改成条件、风险或理由。`不一定`、`一定规模` 等非命令语境不计入命中。

推荐复验：

```bash
node scripts/quality/machine-quality-engine.mjs --profile manuscript --workspace <书稿根> --bundle-root <本包根> --directive-budget
```

通过条件是进程退出码为零，且报告中的 `directiveBookTotal` 不大于 3。方法类文档使用 `reference-doc` profile，不应用书稿命令词阈值。

### （三）S3：可读句长

四十个汉字以上的句子进入复核列表。长句并非天然错误；当多个因果、条件或转折挤在一起，读者需要回读时再拆分。建议把超长句占比控制在 10% 以下，超过 8% 可作为预警。

拆句后要保留逻辑关系。把一个完整论证切成连续碎片并不会提升可读性。

### （四）S4：逻辑衔接

“此外、同时、值得注意的是、综上所述”等词反复出现，往往说明段落之间缺少真实关系。优先让后一段承接前一段的对象、结论或未解问题，而不是更换另一个连接词。

同一连接词全文建议不超过 3 次，过渡词总密度建议低于每千字 2 次。口语中的正常“同时进行”要结合语义排除。

### （五）S5：具体用语

对“赋能、抓手、底座、链路、闭环、颗粒度、打通、对齐、势能、组合拳”等行业套话逐条复核。若词语承担准确的专业含义，可以保留并确保上下文已解释；若只是装饰，应写出谁做什么、对象如何变化。

机器目录 `cliche-catalog.json` 只负责定位可能的套话。`machine-quality-engine.mjs --fail-on-s5-buzz` 可用于严格扫描，但最终修订要依据上下文。

### （六）S6：标点服务节奏

标点应表达句法关系，而不是制造表面变化。重点复核连续两个 U+2014 构成的破折号、连续分号、密集感叹号和“标签：解释”句式。

| 信号 | 建议上限 | 处理原则 |
|---|---:|---|
| 破折号 | 每千字 1 次 | 后半句可独立时通常改为句号；重复解释时合并内容 |
| 分号 | 每千字 2 次 | 先判断并列关系，过长时分句 |
| 感叹号 | 全文 2 个 | 只保留确有情绪强度的位置 |
| 模板冒号句 | 0 | 直接陈述关系，不保留空引导语 |

破折号密度超过每千字 1 次视为 S6 未收口，应重写后复扫；超过每千字 3 次属于机器阻断范围。恰等于阻断阈值时以脚本当前报告为准。不要把所有破折号批量替换成逗号，这会掩盖原句结构问题。

## 三、独立写作形态门禁

列表拼凑和标题层级不参加 S1–S6 平均分，由 `check-writing-shape.mjs` 单独阻断。可见 Markdown 标题使用中文层级，例如 `第一章`、`一、`、`（一）`；不得使用 `第1章`、`1.1` 或 `2、`。文件名中的 `ch01-` 是机器标识，不受此限制。

连续三项以上的编号冒号句，或短导语后直接排列三项以上无序列表，不能替代正文论述。修订时应说明各项之间的因果、条件、比较或取舍关系，而不是删掉序号后用分号串接。

操作步骤、核对清单、参数、安全红线和资源目录可以使用列表，但列表前要说明用途，项目本身应可执行或可核对，且不能承载章节的主要论证。完整边界见 `../../manuscript-writing/references/writing-style-constraints.md`。

门禁报告位于 `.doubao-book-writer/reports/writing-shape-check.json`；缺失、无法解析或 `status: fail` 都不允许进入交付。

## 四、报告方式

句级报告不要只列统计总数。每类问题至少提供代表性位置、上下文判断和修订状态；命中为合理术语时记录豁免理由。

```markdown
| 规则 | 文件与位置 | 观察 | 处理 |
|---|---|---|---|
| S2 | 第三章，第六段 | “显著”没有比较依据 | 改写为具体变化 |
| S5 | 第五章，第二段 | “链路”指技术追踪链，语义准确 | 保留并补充定义 |
| S6 | 全书 | 破折号 1.4 次/千字 | 重写后复扫 |
```

全书合稿后要重新计算词项和标点密度。单章分别通过，不保证合并后的总量仍符合阈值。
