# 长文写作形态与反 AI 拼凑规范

本文件是正文写作、续写、扩写、改写和精修共同遵守的权威形态规范。目标不是把清单换成更长的句子，而是让正文形成自然、连续、可追踪的论证链。写完后必须运行 `scripts/quality/check-writing-shape.mjs`；脚本失败时不得进入终稿交付。

## 一、标题编号

正文可见标题中的层级编号一律使用汉字，不使用阿拉伯数字。章节文件名可继续使用 `ch01-标题.md` 这类稳定机器标识，但文件内标题必须符合中文出版习惯。

允许：

```markdown
# 第一章 行业背景
## 一、智能制造的边界
### （一）概念演进
```

禁止：

```markdown
# 第1章 行业背景
## 1.1 智能制造的边界
### 1.1.1 早期定义
## 2、实施路径
## 第一节 智能制造的边界
```

年份、百分比、金额、样本量、产品版本和操作步骤中的阿拉伯数字不受此规则限制。规则只约束 Markdown 标题行中的结构编号。

章级标题使用 `第一章`、`第二章`；章内一级主题使用 `一、`、`二、`；下一层使用 `（一）`、`（二）`。这三层是正文唯一允许的可见编号层级，不使用 `第一节`、`第二节`，也不再增加 `1.`、`1.1`、`（1）` 或另一轮 `（一）` 作为第四层。

每个编号后必须有能够概括内容的语义标题，不能只写编号，也不能用“相关内容”“其他事项”“具体分析”一类空标题。若 `### （二）关机与重启` 下还要区分正常关机、重启与应急处理，不要继续写一轮 `（一）（二）（三）`。改用少量无编号加粗小标题：

```markdown
### （二）关机与重启

**正常关机**

关机前需保存工作文件并关闭程序，避免尚未写入磁盘的数据丢失。Windows 与 macOS 的入口不同，但都应优先使用系统菜单完成关机。

**重启与睡眠**

系统卡顿或完成更新后可以重启；短时间离开时使用睡眠，以保留当前工作状态。
```

无编号加粗小标题只用于第三层标题下确有必要的局部导航，不计入正式目录。能用自然段顺畅承接时，优先不用小标题。

## 二、正文不得用分点代替论述

长文正文的默认形态是自然段。连续三项及以上的编号条目、冒号标签和短句说明，通常只是把提纲直接贴进正文，必须改写。

禁止把正文写成：

```text
1. 数据质量问题：故障样本稀缺，数据标注困难。
2. 工况复杂多变：正常波动与故障难以区分。
3. 模型泛化不足：不同设备之间难以迁移。
4. 投资回报周期长：需要等待真实故障才能验证。
```

应改写为：

```text
预测性维护首先受制于故障数据的生成机制。设备在大多数时间里保持正常运行，真正可用于训练和验证的故障样本很少；即使积累了传感器数据，噪声、缺失值和标注误差也会削弱其可用性。这个问题进入真实产线后还会被工况差异进一步放大：负载、环境和设备老化都可能制造看似异常的波动，使模型难以判断变化究竟来自故障还是正常运行条件。

数据稀缺并不是唯一障碍。即便模型在一台设备上取得稳定结果，同型号设备之间的安装方式、维护历史和磨损程度也会改变数据分布，原有判断因而难以直接迁移。企业要验证投资回报，还必须等待足够长的运行周期和真实故障事件。项目见效慢，运维流程又需要同步调整，最终使预测性维护从一个模型问题转化为数据、设备和组织共同参与的长期工程。
```

改写时不能只删除序号并用分号连接。合格段落必须说明各问题之间的因果、递进、条件或转折关系。

## 三、禁止“导语加子列表”拼装

以下形态同样不合格：

```text
发展方向：
- 小样本学习，降低故障数据依赖
- 数字孪生与 AI 结合
- 边缘端实时推理
- 从定制化走向标准化
```

应改写为有主线的段落：

```text
后续技术演进将围绕“减少数据依赖”和“降低部署成本”两条相互关联的路径展开。小样本与零样本方法试图缓解真实故障数据不足的问题，数字孪生则通过物理模型补足纯数据方法缺少的先验约束。模型能够稳定工作后，推理任务还需要进一步下沉到边缘端，以减少传输延迟和持续上传数据的成本。只有这些能力逐渐形成可复用接口和评价标准，预测性维护才可能从逐厂定制转向规模化产品。
```

## 四、段落必须形成推进关系

一个承担实质论述的自然段，通常完成以下过程，但不得把该过程原样打印成清单：

```text
对象或问题定位 → 事实、案例或机制依据 → 条件差异或反例 → 本段判断与下一层问题
```

写作时遵守以下要求：

- 段首直接进入具体对象、场景、冲突或待解决的问题，不用宏大趋势套话。
- 提出判断后解释依据。涉及事实时给出材料、数据、案例或可追踪来源；纯推理时把前提与推导过程写清。
- 相邻句之间必须有语义关系，不把若干正确但互不相干的句子并排放置。
- 相邻段落通过问题推进、因果变化、条件收窄、共识与分歧或方法与局限衔接。
- 复杂机制可用较长句说明，关键判断可用短句收束；避免每段句数、句长和结构完全相同。

### 章节、段落和句子的节奏

- 章节篇幅不必整齐一致。重要问题可以写得更充分，承担过渡或说明作用的章节可以更短，以内容需要为准。
- 段落长短可以变化。解释机制、条件和因果时可以展开，明确判断和转折可以用短段落收住。
- 句子可以长短交替。不要为了整齐把每句话写成相同长度，也不要让每段使用同一套句式。
- 可以加入作者自己的分析、判断和过渡，让内容形成观点，而不是把搜索资料拼在一起。自己的判断要说明依据和推理过程。
- 事实、数据、案例和引语必须来自用户材料或可追踪来源。没有依据时可以标注为观察或推测，不能编造成已经证实的事实。

## 五、常见 AI 痕迹

### 空泛开头

禁止用下列句式承担章节或段落开头：

- "随着技术的不断发展……"
- "近年来，某领域受到广泛关注……"
- "在当今数字化时代……"
- "某问题具有十分重要的意义……"

应直接说明具体对象、现实矛盾或变化依据。

### 机械连接词

"首先、其次、最后、此外、另外、同时、综上"以及提示注意类套话不是绝对禁词，但不能成为正文的主要结构支架。**连续两个段落**依靠这些词才能成立，说明内容仍是并列提纲，应重排语义关系。

同样禁止的枚举式开头：

- "第一，……第二，……第三，……"（序数词分段）
- "一是……二是……三是……"（枚举式分段）

应改为有因果、递进或转折关系的连续段落。

### 段落内多连接词

单段落内出现 2 个及以上机械连接词（如"首先……其次……最后……"堆在一段里），仍是提纲形态，必须改写为有主线的连续散文。

### 汇报口吻

禁止用下列句式承担段落开头：

- "下面从三个方面展开……"
- "本节主要介绍……"
- "本节将……"
- "综上所述……"
- "总的来说……"

这些是汇报材料的口吻，不是长文正文。应直接进入具体对象、机制或冲突。

### 标签冒号句

避免连续使用“问题：……”“原因：……”“方向：……”这类标签冒号句。冒号适合解释一个明确对象，不适合把整节正文压成 PPT 提纲。

### 伪论证

以下做法不算论证：

- 罗列多个问题，却不说明它们如何相互作用。
- 罗列多个方案，却不说明选择条件、代价和适用边界。
- 每段最后都写“具有重要意义”或“提供参考价值”。
- 把同义句换词重复，当作层层递进。
- 删除序号后用分号把原清单拼成一个超长句。

## 六、列表的允许边界

本规范不禁止真正需要扫描和执行的列表。下列场景可以使用列表：

- 用户明确要求的操作步骤、核对清单、参数表或资源目录。
- 安全红线、法律条款、接口字段等必须逐项识别的内容。
- 章节末尾不超过五项的行动核对表，且正文已经完成解释。
- 对比表中的并列字段。

允许列表必须同时满足：

1. 列表承担查阅或执行功能，而不是替代正文论证。
2. 前文已经说明为什么需要这些项目以及它们之间的关系。
3. 列表项目能够被独立执行、核对或比较。
4. 列表结束后有必要的解释、风险或适用边界，不突然跳到下一主题。

章节标题含“步骤、清单、操作、规范、流程、参数、资源”时，检查器可对列表放宽，但不会豁免阿拉伯数字标题和正文中的连续标签拼凑。

## 七、表格与加粗的允许边界

表格和加粗不是禁用项，但必须承担信息功能，不能用来制造“看起来很丰富”的版式。

表格适合呈现口径一致、需要横向比较的信息，例如参数差异、职责分工、时间线、风险等级或操作系统路径。表格前先说明比较目的，表格后解释主要差异、适用边界或结论。不要把连续论述拆成一格一句，不使用只有一列的伪表格，也不要连续堆放多个表格。一般每两千字以内不超过一个表格；确因数据密集需要增加时，应以内容可比性为依据。

加粗适合标记关键术语、风险边界、结论句中的核心对象，以及第三层标题下少量无编号小标题。不要整段加粗，不在 Markdown 标题中重复加粗，不连续用多个加粗短句代替段落。一般每五百字以内不超过一处加粗；单篇短稿至少允许四处，具体仍以是否有实际提示价值为准。

## 八、禁止装饰性高亮块

正文不得使用 `> [!NOTE]`、`> [!TIP]`、`> [!WARNING]` 等 callout，也不得使用 `<details>` 折叠块。普通引用、用户要求保留的原始引语和带来源的引文仍可使用 Markdown 引用格式。重点内容应通过自然段推进、适量加粗或必要表格表达，不能依靠装饰性组件制造层次。

## 九、写作后自检

交付前逐项确认：

- [ ] 可见标题遵循 `第一章 → 一、 → （一）`，未出现 `第一节`、`1.1`、`第1章` 等形式。
- [ ] 正式编号只到三层；`（一）` 标题下没有再次出现 `（一）（二）（三）` 伪四级标题。
- [ ] 每个二、三级编号后都有具体语义标题；更细导航只使用少量无编号加粗小标题。
- [ ] 表格用于横向比较或查阅，前后有解释，没有把正文拆进单元格或连续堆表。
- [ ] 加粗只标记关键内容或少量无编号小标题，没有整段加粗、标题内重复加粗或加粗短句拼装。
- [ ] 正文没有装饰性 callout 或折叠块；普通引语仍保留来源和引用语义。
- [ ] 正文没有连续三项及以上的编号冒号条目。
- [ ] 正文没有"短导语 + 三项及以上无序列表"替代论述。
- [ ] 正文没有"第一/第二/第三"或"一是/二是/三是"枚举式段落开头。
- [ ] 正文没有连续两个段落依靠"首先/其次/最后"等机械连接词推进。
- [ ] 单段落内不出现 2 个及以上机械连接词（"首先……其次……最后"堆在一段）。
- [ ] 正文没有"下面从...展开""本节主要介绍""综上所述"等汇报口吻开头。
- [ ] 删除标题和列表后，正文仍能形成完整的论证链。
- [ ] 每个主要判断都有事实、案例、机制或推理支撑。
- [ ] 相邻段落之间存在递进、转折、因果或条件关系。
- [ ] 章节、段落和句子长短随内容自然变化，没有机械同构。
- [ ] 已加入基于材料的分析判断，并区分了事实、推理和待核实内容。
- [ ] 没有空泛开头、模板连接词主导、标签冒号句堆叠和同义反复。
- [ ] 必要列表符合本文件的功能性豁免边界。
- [ ] `scripts/quality/check-writing-shape.mjs` 返回 `status: pass`，报告已写入 `.doubao-book-writer/reports/writing-shape-check.json`。

任一项失败时重写目标段落并重新检查，不得用自然语言声明豁免。
