# 通用长文写作包

## 启用条件

当项目属于非虚构书稿、手册、说明性长文，或无法归入其他专门体裁时，加载本地 `general` 规则。它是远端场景配置不可用时的基础写作约束，不替代项目简报、用户材料和阶段门禁。小说、剧本、网文和纯文学创作不使用本规则。

## 立项信息

开始写作前应确定书名方向、核心主张、目标读者及其问题。还要记录预计篇幅、章节规模、现有素材、写作深度和发布方式。书名、受众、体裁与篇幅属于主要求；缺少其中任一项时，先补齐需求，不直接生成正文。

## 结构选择

短稿以根目录 `manuscript.md` 为真源。长稿使用分章文件，并由 `outline.md` 与 `chapter-ledger.md` 维护结构和进度。

长篇通常包含前言、正文、结语和按需设置的附录。前言交代写作缘起与阅读方法；正文每章围绕一个问题推进；结语回收全书主张并给出可执行的后续方向。附录只承载术语、来源、模板等辅助内容，不能用来填补正文论证缺口。

可见标题统一使用汉字序号：

```markdown
# 第一章 章节名
## 一、主题名
### （一）子主题名
```

不得在可见标题中改用 `第1章`、`1.1` 或 `2、`，也不得在 `### （一）` 下重新用一轮 `（一）（二）` 充当第四级。确需更细导航时，使用少量无编号加粗小标题。章节开头直接呈现问题、场景或矛盾，不写“本章将介绍”式目录复述。各节用连续自然段完成主张、依据、分析与过渡；可比信息可以用适量表格，关键内容可以少量加粗，但二者不能代替论述。章末可以简短回收要点，不能用长清单代替结论。

## 质量基线

### 句与段

核心判断需要用户材料或可追溯来源支持。清理病句、空洞修饰和机械连接词，避免“随着时代发展”“众所周知”等无信息开场。段落应承担单一推进任务，长度服从论证需要，不强制整齐划一。

### 章与篇

章节必须回应大纲中的问题，编号连续，承诺的篇幅和内容得到兑现。全书需要统一术语、数字口径和核心观点；概念首次出现时给出清楚定义。前言提出的阅读收益应在正文中实际实现，标题不得夸大内容。

## 调研与来源

写正文前按主题、读者和同类作品至少检索三个方向，检查证据缺口后再做针对性补搜。事实、数据、案例和引语记录来源、链接、日期、有用结论及目标章节。优先顺序通常是原始数据与官方材料、学术或专业机构、可信媒体，再到其他可核验资料。无法联网时明确说明限制，只使用用户材料，不编造出处。

## 图表使用

图表必须帮助理解而不是装饰。流程或决策适合流程图，概念关系适合关系图，历史变化适合时间线，方案差异适合对比表，连续数据适合折线或柱状图。每个图表都应在正文中被解释，并标明数据来源和统计口径。

## 完成判定

本体裁指南只提供体裁约束。最终完成仍以写作形态检查、质量审计、全书终审和工作流最终验证的实际通过结果为准。
