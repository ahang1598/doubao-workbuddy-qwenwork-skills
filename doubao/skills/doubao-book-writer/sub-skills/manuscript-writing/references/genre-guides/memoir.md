# 专家个人著作写作包

## 定位

`memoir` 用于行业专家、管理者和实践者将长期经验整理成专业著作、方法论或实践指南。作者经历是证据来源之一，但成稿不能成为履历陈列；读者应获得可理解、可检验、可使用的知识。

## 立项问题

项目简报需要冻结核心主张、目标读者、作者独特经验、预期改变、体裁、篇幅和出版方式。还应区分哪些内容来自个人实践，哪些借鉴现有理论，哪些仍是假设。

若书名或宣传承诺某种结果，正文必须说明适用条件和限制。不能把个别成功经历包装成普遍规律。

## 知识结构

著作通常沿“问题—解释—方法—案例—实践”推进：

| 部分 | 核心任务 |
|---|---|
| 导言 | 说明读者问题、作者观察位置和阅读方法 |
| 概念基础 | 定义核心术语，交代与既有研究或方法的关系 |
| 原创框架 | 展示组成部分、因果假设、适用边界和判断方式 |
| 操作方法 | 给出步骤、输入、决策点、工具和完成标准 |
| 案例验证 | 用成功、失败和边界案例检验框架 |
| 实践迁移 | 帮助读者选择场景、执行、复盘和调整 |
| 附录 | 汇总模板、术语、来源和进一步阅读 |

章节数量和篇幅服从论证需要。理论与案例交替出现，避免连续多章只讲抽象概念，也避免用大量故事掩盖方法缺失。

## 原创性与证据

原创性不是换名已有概念。作者需要说明新框架解决了什么旧问题、与已有方法有何差异、依据来自哪些实践，以及在哪些情况下不适用。借鉴理论要准确引用，不把公共知识宣称为个人发明。

数据写明来源、年份和口径；时间较早但仍有价值的资料说明使用理由。案例记录行业、规模、约束、过程和结果，必要时取得授权并脱敏。不能把多个客户经历拼成一个“真实案例”而不说明。

## 可复现方法

每个方法至少交代使用前提、所需输入、操作步骤、关键判断、常见失败和验收结果。仅写“重视”“提升”“加强”不构成方法。模板和清单需要提供填写示例，并在正文解释为什么这样使用。

读者行动应由低风险练习逐步进入真实应用。章末可设置简短复盘或行动提示，但不要求每章采用相同清单结构。

## 全书一致性

核心术语首次定义后保持稳定。摘要、图表、案例和正文采用同一套框架名称与数字口径。前言承诺的读者收益逐项在正文实现；作者观点因新证据变化时明确说明，而不是前后矛盾。

## 调研与图表

优先查找原始研究、专业机构资料、经典著作、行业披露和可靠深度报道。检索既用于支持观点，也用于寻找反例和边界。框架图说明概念关系，流程图展示方法步骤，对比表呈现案例差异；所有数据图注明来源和口径。

## 放行条件

核心主张有清楚依据，原创部分与既有知识边界明确，方法可以复现，案例真实且使用合规，读者承诺得到兑现后，书稿才可进入全书终审。
