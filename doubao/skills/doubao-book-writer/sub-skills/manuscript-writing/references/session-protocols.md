# 写作决策记录协议

复杂写作不是靠模拟一场“多人会议”得出结论，而是把问题拆成可验证的判断，再记录选择依据。本协议用于大纲分歧、核心主张、读者风险和终稿异议；普通章节写作不必启动额外流程。

## 一、何时建立决策记录

以下情况需要记录：

- 两种结构会明显改变读者理解顺序；
- 一个核心主张缺少边界或存在强反例；
- 修改会影响多个章节、来源口径或用户已确认的大纲；
- 终稿检查发现用户需要决定是否接受的残余风险。

拼写修正、局部顺句和已有规则能够直接判断的问题不进入决策记录。

## 二、记录单元

每个问题使用独立编号，内容保持短而可追溯：

```markdown
## DEC-007 先讲案例还是先讲框架

- 触发位置：outline.md / 第三章
- 当前目标：让第一次接触该主题的读者理解决策过程
- 已知事实：用户要求保留两个真实案例；第二章已经定义核心术语
- 约束：不得增加未经核实的数据；总章数不变
- 候选 A：案例开场，再提炼框架
- 候选 B：框架开场，案例用于验证
- 关键差异：A 降低进入门槛；B 便于查阅
- 建议：A
- 用户决定：待确认
- 影响范围：outline.md、第三章、第五章交叉引用
```

事实、推断和偏好分开写。若判断依赖来源，记录来源位置；若只是作者选择，不能伪装成读者研究结论。

## 三、形成候选方案

先从当前目标推出评价标准，再提出候选项。常用标准包括：信息进入速度、论证完整性、读者前置知识、来源强度、修改成本和对已确认内容的影响。

通常保留两个差异清楚的方案；确有第三条独立路径时再增加。不同措辞但执行结果相同的方案应合并。每个方案至少说明收益、失败方式和受影响文件。

建议必须给出理由，但不能替用户决定。若一个方案违反硬约束，直接标为不可行，不为了形式平衡继续推荐。

## 四、四种检查镜头

决策可以按需要选择一个或多个镜头，不要求固定角色或固定顺序。

**证据镜头**检查事实、来源和推理跳步：哪些句子可以核验，哪些是分析，反例会否推翻结论。

**理解镜头**检查读者在当前位置掌握了什么：术语是否提前使用，问题是否被看见，行动是否清楚。

**结构镜头**检查本次选择对其他章节的影响：是否重复、是否破坏承诺回收、是否改变大纲冻结范围。

**表达镜头**检查语气、节奏和体裁：是否依赖模板句、列表或夸张修饰制造完整感。

各镜头独立提交证据即可，不需要虚构人物身份。出现分歧时回到评价标准，而不是投票取多数。

## 五、用户确认与执行

会显著改变范围、结构或已确认结论的决定，应向用户展示：当前问题、最多三个候选项、推荐项及主要代价。用户未确认前，允许准备草稿或差异说明，但不覆盖正式正文。

用户确认后，将状态改为“采用”，注明确认依据和时间，并列出需要同步的文件。执行完成后补记实际结果；若结果与预期不同，新增一条后续决定，不覆盖原记录。

## 六、保存位置

决策记录写入 `.doubao-book-writer/decisions/DEC-*.md`。目录不存在时可在当前阶段首次需要时创建。索引可写入 `.doubao-book-writer/decisions/index.md`，只记录编号、标题、状态和影响范围。

正文、需求清单和大纲仍是内容真源。决策记录解释为什么改变，不能代替正文修改、来源登记或 `make` 检查。

## 七、终稿异议处理

终稿阶段按阻断、重要、可后置三个等级登记问题。阻断项涉及事实可信度、用户硬约束或交付完整性，必须解决；重要项可以修改，也可以在得到用户接受后保留；可后置项不应阻塞交付。

每项异议包含文件位置、原文证据、影响和动作。修改后运行正式质量门禁。决策记录中的“已接受”不等于脚本门禁通过，也不能把失败状态改写成通过。

## 八、停止条件

当评价标准稳定、候选差异已说明、用户需要作出的决定明确时，停止继续发散。无法形成新证据的重复讨论不应延长流程。剩余不确定性作为风险记录，交给用户决定是否接受或推迟。
