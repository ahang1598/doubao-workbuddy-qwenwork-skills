# 精修写回协议

## 适用范围

用户要求精修、润色、去重复、统一术语或收口事实时，进入 edit 路由的修订流程。精修针对已经存在的正文，不重建未授权章节，也不把扩写目标偷偷并入润色任务。

开始前明确目标文件、段落边界、保留内容、允许改变的事实和期望风格。范围不清且不同解释会造成显著工作量差异时，先请用户确认。

## 写回保护

任何精修写回前，先把原文件复制到 `.doubao-book-writer/backups/<timestamp>/`。一轮最多修改两个正文文件。用户未指定的文件保持不变；文件内未指定范围应保持字节一致，不能顺手调整标题、标点、换行或其他章节。

备份完成后记录目标文件哈希和编辑范围。若任务中断，比较原稿、备份和当前稿后再决定继续或回滚，不根据对话猜测磁盘状态。

## 编辑目标

精修可以处理：

- 句意不清、语法问题和机械连接；
- 重复观点、段落顺序和过渡；
- 术语、数字、人物称谓和时间口径；
- 来源缺口、待确认标记和事实边界；
- 标题编号、列表替代论述和模板化表达。

精修不能改变用户核心主张、删除必要证据、编造案例或制造不存在的引语。涉及事实增删时，先核对来源台账并同步受影响的结论。

## 执行方法

先读取 [`writing-style-constraints.md`](./writing-style-constraints.md)、项目简报、术语记录和目标段落上下文。根据问题类型修改最小必要范围，再读回写入后的文件，确认指定内容已改变、范围外内容未变化。

文字调整应解决表达根因。禁止只删除序号、把项目符号连接成一长句，或批量替换词汇而不检查语境。段落和句子允许自然长短变化，不为追求整齐而统一节奏。

精修造成篇幅明显变化时，用磁盘实测字符数更新台账。若任务本身包含目标字数，按 [`amplification-guide.md`](./amplification-guide.md) 执行扩写计划与字数门禁，而不是在精修中口头宣称达标。

## 检查闭环

每次写回后运行目标范围的写作形态检查：

```bash
node scripts/quality/check-writing-shape.mjs --workspace <workspace> --input <relativeMarkdownPath> --json
```

根据改动同时运行必要质量检查：语言和段落调整检查 S/P；事实变更增加 C；跨章术语或重复变更增加 B。报告失败时按具体行修复并重跑，不能手写 `status: pass`。

## 进度与结束

精修完成后更新 `chapter-ledger.md` 和 `progress.md`，记录真实修改文件、最后动作和下一步。`status` 继续保持 `in_progress`；只有最终工作流验证可以改为 `completed`。

范围外内容保持一致、备份可用、目标问题关闭、写作形态和相应质量检查通过后，本轮精修才算完成。
