# 扩写路由操作卡

扩写的交付物不是“更长的文字”，而是在原稿边界内增加可验证的信息。正文之外的状态文件和回执不计入扩写量。

## 一、不可破坏的基线

开始前固定三项事实：原文件哈希、用户允许修改的范围、范围外必须保持不变的字节。所有目标文件先进入 `.doubao-book-writer/backups/<timestamp>/`，再进行写回。

若用户只指定某章或某段，其他正文不是可自由调整的上下文。补充背景时不得顺手改写相邻章节；确需跨章调整，应先扩大授权范围并更新 checklist。

## 二、为每个增量指定用途

计划中的新增内容应属于以下至少一种任务：补足推理步骤、增加可追溯证据、解释反例或适用边界、展开案例过程、补充可执行方法。单纯复述结论、增加程度词、堆叠列表或制造虚构案例不算有效扩写。

新增事实、数据、案例和引语若不在用户材料中，应先查找可追溯来源并登记用途。无法验证的判断要说明是作者分析，不能伪装成资料事实。

## 三、计划的机器接口

扩写计划固定写入 `.doubao-book-writer/amplification-plan.md`。门禁只依赖下面四个标题及目标表前三列；其余说明可按项目需要组织。

### 全书目标

记录扩写前实测字符、用户目标、允许范围、预计增量和停止条件。字符统计以保存后的 UTF-8 Markdown `text.length` 为准。

### 章节扩写目标表

```markdown
| 章节 | 正文路径 | 扩写后字符数 | 当前字符 | 增量任务 | 证据准备 | 保留边界 |
|---|---|---:|---:|---|---|---|
| ch03 | manuscript/ch03-example.md | 9000 | 6200 | 展开失败案例的决策过程 | 已登记两项来源 | 不复述第二章定义 |
```

正文路径只能指向工作目录内的真实正文 Markdown。台账、计划和上下文摘要不会被计量。扩写后字符数必须为正数。

### 执行策略

这里写明批次顺序、每个文件的增量任务、内容禁区和复核方式。一个写回批次最多包含两个正文文件；较大的目标拆成多批，每批独立备份、写入和验证。

### 授权记录

```markdown
- [ ] 用户已同意本轮扩写计划
- 确认依据：
- 确认时间：
```

只有获得明确同意后才能勾选。不能以沉默、超时或此前对其他范围的同意代替本次确认。

## 四、写回循环

每个批次按以下闭环推进：

1. 运行计划结构门禁，确认表格和授权有效。
2. 备份本批原文件并记录备份位置。
3. 按“增量任务”写作，不超出保留边界。
4. 重新读取落盘正文，计算实际字符。
5. 检查范围外字节、来源、跨章重复和写作形态。
6. 通过后同步章节台账；失败则只修复本批目标。

并行草稿只能作为临时材料，不能由多个进程同时覆盖同一正式章节。合并前按章节边界去重，并再次核对术语与前后文。

## 五、计量和状态

计划批量计量：

```bash
node scripts/gates/chapter-length-verify.mjs --workspace <workspace> --from-plan .doubao-book-writer/amplification-plan.md
```

单文件计量使用 `--file` 与 `--target-chars`。默认最低完成线为扩写后字符数的 90%；未达到时该批保持未完成，不能用模型估算值更新台账。

计量通过不代表内容通过。新增段落还要经过写作形态检查；涉及事实时检查来源；长稿检查相邻章是否重复。所有修订完成后再运行：

```bash
node scripts/core/refresh-chapter-ledger.mjs --workspace <workspace>
```

## 六、中断与收口

中断时保留正式稿、最近备份和当前计划，并记录哪些文件已经写回、哪些仍停留在临时稿。恢复后从磁盘正文与已生成的检查报告判断，不依赖聊天摘要猜测进度。

只有计划内各批次均达到计量线、正文检查通过、台账与磁盘一致，扩写路由才可收口。随后可按 [`refinement-guide.md`](./refinement-guide.md) 进行精修；会话结束规则见 [`progress-closure.md`](./progress-closure.md)。
