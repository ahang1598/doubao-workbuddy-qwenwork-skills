# 进度恢复与会话收束

## 真源顺序

用户要求继续写作时，先读取磁盘状态，不凭对话记忆猜测断点。依次核对当前正文、长篇项目的 `chapter-ledger.md` 与 `outline.md`，以及 `.doubao-book-writer/reports/` 下已生成的检查报告。可读 Markdown 与任何辅助记录冲突时，以实际正文和用户最新明确要求为准。

根目录存在非空 `manuscript.md` 时按短稿恢复；否则长稿从 `manuscript/chNN-*.md` 中定位当前章。既无正文也无有效布局时，不自行续写，先回到准备阶段完成需求清单与布局。

## 可选的进度记录

`progress.md` 不是门禁产物，`make` 不消费它——恢复真源是磁盘正文、`chapter-ledger.md` 与检查报告。若维护 `progress.md` 作为人类可读的恢复辅助，只记录已经发生的事实（本轮完成了什么、在写哪章、下一步建议），不得把自然语言计划写成已完成动作，也不能用它替代 Markdown 正文真源。

## 阶段推进由 make 强制

推进顺序由 `make` 依赖链决定，不按章节数量或主观判断跳转：

| 变化 | 必要条件 |
|---|---|
| 进入写作 | 需求清单有效、素材调研到位；长稿大纲已冻结并通过结构检查（`make prepare` 通过） |
| 进入交付 | 计划正文已落盘，形态、字数、占位符清洁通过（`make write` 通过） |
| 判定完成 | 终稿已生成，飞书读回校验通过或用户显式 `SKIP_LARK=1`（`make status` 为 PASS） |

短稿可跳过大纲，但不能跳过需求、正文、交付。是否可推进以对应 `make` 目标的实际结果为准，不以手写声明为准。

## 单轮写作收束

每轮结束前明确本轮真实修改了哪些文件、在写哪章、下一步做什么（不超过三条）。只记录本轮真实修改的文件；未完成事项写入下一步，不伪装成完成。

若用户中途停止，先保存已确认内容，再说明可以从哪个章节或检查点恢复。不要为了制造完整结尾而在未确认范围继续写作。

## 执行额度中断

宿主提示 finish-tier、工具调用或执行步数接近上限时，把它视为可恢复中断，不视为阶段完成。停止开启新批次和可选优化，先确保当前已写内容完整落盘。当前阶段的 `make` 检查尚未通过时，不声称完成，更不能跳到后续阶段。

下一轮先读取磁盘正文与 `.doubao-book-writer/reports/` 恢复现状，从最近未完成的章节或检查继续，不重建项目。收尾提醒不能降低任何 `make` 检查或交付要求。

如果已无法保存进度，回复只能说明本轮中断且任务未完成。

## 完成状态

正文非空或生成交付文件都不等于项目完成。完成度由 `make status` 给出三态：

- **PASS**：写作检查通过且飞书读回校验通过（或 `SKIP_LARK=1` 且终稿已生成）。
- **BLOCKED**：卡在某阶段，说明卡点与下一步。
- **DRAFT_ONLY**：正文存在但检查未过或未交付，标注未验收草稿，禁止说"已完成"。

只有 `make status` 为 PASS 才能向用户报告完成；未达 PASS 时如实转述卡点，不把未完成状态说成完成。
