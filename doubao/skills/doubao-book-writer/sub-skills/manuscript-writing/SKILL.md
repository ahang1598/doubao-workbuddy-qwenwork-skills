# Manuscript Writing

本文件只管非虚构长文档正文怎么写、怎么落盘、怎么复查。阶段推进不由本文件判断，统一交给`make write`和`make status`。如果任务目标是虚构叙事、剧情创作或文学表达，不进入本写作循环。

## 写作循环

1. 先读磁盘：需求清单、`outline.md`、`chapter-ledger.md`、已有正文和最近检查报告。
2. 确认本轮范围：新写哪几章、改哪几段、是否需要扩写或精修。
3. 写入Markdown：短稿写`manuscript.md`，长稿写`manuscript/chNN-*.md`。
4. 读回刚写的文件，确认内容确实落盘。
5. 运行`make write WORKDIR=<书稿目录>`。
6. 失败就按脚本提示修正文，不开新批次。

一次只推进可检查的小块。长稿默认一到两章一批；用户要求局部编辑时，只处理授权范围。

## 续写

续写不靠对话记忆。当前章节、下一章和已完成内容以磁盘为准：

- `outline.md`给出章节任务和依赖。
- `chapter-ledger.md`给出实际进度和字数。
- `manuscript/`里的正文文件高于任何自然语言记录。

台账和正文冲突时，先读正文，再运行`make write`刷新台账。不要手工把未写章节标成完成。

## 扩写

扩写前先写`.doubao-book-writer/amplification-plan.md`。计划至少说明：

- 哪些章节要加厚；
- 新增的是论点、证据、案例、解释、反例还是结构衔接；
- 目标字符数和保留边界；
- 用户是否同意本轮扩写。

扩写不是把原话换一遍。新增内容必须让读者多获得信息。完成后用`chapter-length-verify.mjs`或`make write`实测字数，不用模型估算。

## 精修

精修先备份，再改稿。优先处理：

- 事实口径不稳；
- 段落顺序不顺；
- 套话、空泛判断、机械连接；
- 作者声音被削平；
- 章节之间重复或跳跃。

精修不应擅自改核心观点、关键事实、体裁定位和用户指定语气。篇幅变化明显时，重新跑写作检查。

## 体裁参考

体裁参考放在`references/genre-guides/`。默认读`general.md`；白皮书、培训、调查报告、人物口述、家谱、顾问类项目按文件名选择对应参考。这里的“人物口述”和“品牌故事”只指事实可核验的非虚构稿件，不承接小说化、剧情化加工。

体裁参考只约束写法，不替代用户材料。用户材料、需求清单和事实来源优先。

## 写作形态

标题使用三层中文层级：`第一章`、`一、`、`（一）`。更细的导航用少量无编号加粗小标题。

正文靠自然段推进。连续编号项、标签冒号句、短导语后堆列表、装饰性高亮块，都不能替代论述。表格只放可比较的信息，并在表格前后解释结论。

`make write`会检查标题、列表、字数、占位符、台账和空壳章节。没通过前，不说写作完成。
