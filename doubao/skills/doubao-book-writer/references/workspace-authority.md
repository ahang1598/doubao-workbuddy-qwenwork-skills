# 工作区权威数据约定

## 判定规则

书稿项目的可恢复事实来自用户项目目录，而不是聊天记录。正文、进度、结构和来源都必须能由磁盘文件重新构造；对话只负责解释本轮意图。

## 恢复项目时先看什么

按以下问题读取，不把固定顺序当成形式任务：

- 正文实际是什么：短篇读取 `manuscript.md`，长篇读取 `manuscript/*.md`。
- 长篇接下来写什么：读取 `outline.md` 和 `chapter-ledger.md`。
- 事实依据在哪里：读取 `sources.md`、`sources/` 与 research evidence。
- 检查进行到哪一步：读取 `.doubao-book-writer/reports/` 下的检查报告。

Markdown 与辅助记录冲突时，以用户可读的正文为准；不得静默覆盖正文。

## 写入闭环

一次正文修改只有同时满足以下条件才算落地：

1. 文件写入成功；
2. 重新读取后内容完整；
3. 未指定区域保持不变；
4. 长稿对应台账已同步（`make write` 自动刷新 `chapter-ledger.md`）；
5. 对应 `make` 检查使用写入后的文件重新执行。

仅生成回复、仅生成云端文档，都不能替代本地 Markdown 写入。

## 隐藏目录的边界

`.doubao-book-writer/` 可以保存需求清单、检查报告、备份和交付中间产物，但不能成为正文来源。隐藏目录必须能由公开项目文件解释，不允许保存一份用户看不到的“另一版正文”。

## 完成信号

最终完成由 `make status` 给出：只有写作检查通过且飞书读回校验通过（或用户显式 `SKIP_LARK=1` 且终稿已生成）才是 PASS。任一检查未过时不称完成，如实转述 BLOCKED 或 DRAFT_ONLY。
