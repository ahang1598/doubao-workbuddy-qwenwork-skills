# 回答中的语义图标与符号

执行时遵守 [SVG 执行与确认边界](../../svg-visualization.md#执行与确认边界)：静态图直接构造 SVG，不以修改绘图脚本为前置；已有工具权限内的临时计算与检查不另发对话授权确认，平台强制审批及浏览器许可仍须遵守。


本包使用 [SVG 共用规范](../../svg-visualization.md)：优先静态 SVG，必要交互通过 HTML 控件更新 SVG。程序化矢量示意替代生成式配图，不调用图片生成或编辑工具、不用 Canvas 或位图回退。宿主无法展示时保留文字和表格。


## 正式交付边界

本轮正式交付只保留一种格式、默认一份成品。内容、图表及说明的位置按原任务和宿主能力处理，不要求将说明、记录或图表合并进文档。配置、底稿、预览及运行依赖继续内部生成和核验，不默认另附下载文件；宿主必需的资源上传/写入照常执行。额外格式、源文件或独立文档仅按用户明确要求提供。保留实际显示/插入及内容核验，不以少交文件代替检查。

为概念、步骤或状态选用语义准确且风格统一的轻量图标。

## 输入与输出

输入：概念/状态清单、已有图标库或品牌规范、目标宿主。

交付：图标与含义映射、可访问标签、嵌入后的轻量图示。

边界：这是基于 HTML/SVG 和配图规则新增归纳的能力；原包没有独立图标分支或现成图标库，不据此声称附带专用工具。

## 执行

1. 确认图标能帮助识别概念，而不是无关装饰；先给出概念—图标—标签的映射，符号含义以用户和领域语境为准。
2. 优先复用宿主已提供或项目现有的图标库，逐个确认真实名称与导出；不臆造 icon 名称，小图标使用现有矢量组件或简单 SVG，不调用图片生成工具。
3. 使用同一线宽、尺寸和视觉语言；状态用文字/形状共同表达，不只靠颜色。装饰图标隐藏于读屏，动作图标放在有名称的真实控件中。
4. 宿主明确允许时才可为缺少的简单符号编写 SVG；宿主要求现有 Lucide 等组件时遵循其限制，不手绘路径绕过。图标不能冒充品牌标志、官方标识或安全认证。
5. 复杂机制、精确数值、真实部位或解释性插画分别使用相应能力，不用若干图标替代必须解释的关系。

## 工具、宿主与授权
