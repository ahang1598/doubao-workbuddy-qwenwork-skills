# 可视化是否值得生成

先决定是否需要图，再选图形和宿主。可视化可以使用同一份事实和数据；收益来自更清楚的视觉编码，不要求补充新数据，更不能为作图编造指标。

## 生成前判断

在内部回答三个问题，不把检查过程加进最终答复：

1. 用户需要看清什么：差异、趋势、分布、关系、步骤依赖、时间间隔，还是参数变化对结果的影响？
2. 准备用什么表达它：共同尺度上的长度/位置、节点与连线、按真实间隔排布的时间轴，或可改变结果的控件？
3. 相比现有文字/Markdown表格，读者能更快完成哪项比较、定位或判断？

若只能回答“更好看、更多颜色、换成卡片、再列一遍”，就保留原本清楚的文字或表格，不追加可视化，也不为省略图而增加一段解释。

- 仅出现日期、数字、流程或多个对象，不自动触发绘图；用户要查记录也不等于要看时间线。
- 已有逐条表格时，不把相同字段、编号和说明逐项搬进卡片、横向列表或等距时间节点，再当作另一份图形答案。
- 若图有明确收益，图表达关系或比较，表保留必要的精确查值/追溯；正文只解释关键结论，不让三种形式逐项重复。用户明确要求保留表格时仍保留。
- 用户明确要求图示时完成有用图形，并压缩重复正文；不能借“没有新数据”拒绝，也不能用文字卡片敷衍。事实不足则说明具体缺口。

## 时间线与交互的边界

- 时间轴用于看清先后、持续时间、间隔、并行或阶段衔接。需要比较时长时，位置/长度按真实时间编码；若仅展示事件顺序，明确语义，不用等距布局暗示等长间隔。
- 将同一批记录按日期分组后列出编号，通常仍是列表。只有用户问题确实需要观察事件密度/阶段等关系时才画相应图；受理件数不能当作获批数或研发阶段。
- 折叠、hover、装饰动画或给短表加筛选不自动产生收益。交互应让参数变化、步骤推演、有效筛选或多视图比较回答实际问题；否则用更简单的静态表达或表格。

## 对照案例

| 请求与材料 | 合适处理 | 理由 |
| --- | --- | --- |
| 查询某药CDE受理记录；完整表格已列9条记录及3个日期 | 结论、记录表和官方来源；省略逐条编号卡片时间线 | 查询和追溯已完成，重排同一清单没有帮助回答另一问题 |
| 用户明确要求比较这些受理事件的时间间隔或集中程度 | 按实际日期定位事件/数量，并保留必要编号查值 | 时间距离或密度经视觉编码后更容易比较；不暗示获批或研发进度 |
| 少量产品的两列参数已一眼可比较 | 保留表格 | 不为数字存在而画图 |
| 多厂家在同一口径下的份额与多年变化 | 共同尺度的比较/趋势图，保留关键精确值 | 降低跨对象、跨期间比较的成本 |
| 入排或决策规则存在实际分支与依赖 | 有条件标签的流程图 | 连线和分支表达表格不易直接呈现的路径 |
| 用户需要知道价格/渗透率变化何时改变容量或适应症排序 | 可调参数与即时结果/排序，并显示公式与假设 | 交互揭示敏感性或决策边界；不只是静态文字展开 |

## 交付前删减

移除图后，用户是否会明显更难比较、理解关系或探索状态？若不会且未明确要求图，删除图。反向检查：图若已清楚表达主关系，删除重复的长段文字与卡片；必要的来源、口径及查值表仍保留。
