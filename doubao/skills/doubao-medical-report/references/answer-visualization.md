# 回答正文可视化与子 skill 路由

## 适用与展示位置

用户仅提供报告图片、照片、截图或粘贴的文字内容且未指定载体时，默认 `inline_visual_report`，在当前回答正文先给可视化解读。明确要求飞书文档或更新已有飞书文档时进入文档分支。PDF 等其他报告文件的默认方式由主入口决定。

正文建议按“关键结论 → 有解释收益的图形 → 异常逐项解读 → 下一步建议 → 必要来源与免责声明”组织；紧急情况提示置于最前。根据资料规模取舍，不把完整文档目录搬到聊天里，也不把核心解读藏在附件或链接后。

## 共用规范

生成前读取 [可视化取舍](atomic-skills/answer-data-chart/references/visual-value.md)，使用实际载体前读取 [依赖与交付协议](atomic-skills/answer-data-chart/references/delivery-contract.md)。子 skill 保留已有的信息价值、数据准确性、交互收益和移动端规范；绘图载体统一按 [SVG 可视化规范](svg-visualization.md) 优先使用 SVG，不走生成式图片分支。

优先寻找能更清楚表达实际差异、参考区间位置、变化、关系或步骤依赖的图形。短表或文字已足够清楚时保留它们；仅用 emoji、换成等大卡片或重排清单不算额外的可视化收益。图形与精确查值表可互补，避免逐项重复。

## 按任务读取子 skill

主 Agent 在当前任务顺序读取并执行相应子 skill；“子 skill”是包内指令和资源，不是创建子 Agent，也不依赖另行安装同名技能。

| 信息关系 | 子 skill | 报告解读中的用途 |
|---|---|---|
| 数值比较、分布、跨期变化 | [answer-data-chart](atomic-skills/answer-data-chart/SKILL.md) | 有共同单位/合理尺度时比较结果与参考范围；同一指标有两个及以上可比较时间点时展示变化 |
| 指标之间的关系、复查步骤、就医沟通路径 | [answer-structure-diagram](atomic-skills/answer-structure-diagram/SKILL.md) | 区分观察证据、可能解释和下一步；用有依据的连线或分支表达关系 |
| 多次报告、多个系统的有效视图切换或步骤演示 | [answer-interactive-visualization](atomic-skills/answer-interactive-visualization/SKILL.md) | 仅在交互确实帮助比较或理解过程时使用；不让用户自行调节数据来得到诊断或治疗建议 |
| 家庭监测、餐盘、管理步骤的非诊断性示意 | [answer-structure-diagram](atomic-skills/answer-structure-diagram/SKILL.md) | 用可核对的 SVG 图形、文字和步骤说明表达；无法可靠绘制的动作改用文字 |
| 轻量语义符号、章节或状态识别 | [answer-icon-visualization](atomic-skills/answer-icon-visualization/SKILL.md) | 用一致符号配文字标签辅助阅读，不能替代数据或关系图 |

## 医学资料适配

- 单次报告重点呈现本次异常和参考范围，不伪造历史趋势；文字性影像、内镜、病理发现用原报告描述与关系说明，不强行改成数值图。
- 不把不同单位或不同临床意义的原始数值放在同一尺度下排序；任何标准化或偏离比例标明算法和局限，不将偏离幅度等同临床风险。
- 数值、单位、参考范围、日期和图中标注与用户资料对应；缺失信息注明不确定性，不补造数值或参考区间。保留现有不确定性处理方式，不恢复强制用户确认或暂停整份报告的流程。
- 关系图不能把相关性画成已证实的病因；风险等级须配文字依据。图标、颜色和图形均不能表示确诊或替代医生判断。
- 正文保持清新蓝绿色的健康管理语义、克制的 emoji 和明确标签；精确图表遵守其子 skill 的颜色约束，不强加调色。飞书表格的 XML 色值不直接用于聊天渲染。
- 数据图、知识解释和动作示意均采用程序化 SVG；不调用生图或图片编辑工具，不嵌入生成式图片，不把 SVG 转成栅格图。非诊断性示意说明用途与局限，不表现治疗承诺、处置演示或伪造医学影像。

## 宿主适配与交付

按实际宿主协议展示 SVG。宿主支持内联 SVG 时直接展示；明确支持 `renderer` 时可在最小 HTML 容器中嵌入 SVG，交互仅用于有实际收益的视图或步骤切换。不使用只返回配置的 ECharts 分支，也不回退到 Canvas、截图或图片生成。内部 SVG 资源可以支持正文展示，不把 XML、本地路径或未渲染代码块当作已展示结果。

无相应展示工具时，继续给出准确的正文解释和必要表格，说明实际展示限制；不因此自动改为创建飞书文档。浏览器 UI、无头浏览器或截图自动化前，说明必要性并获得用户对当前任务的明确许可。

飞书文档继续使用原生表格、callout、分层底色和文字趋势说明，不恢复已移除的飞书图表助手依赖。默认按本次要求交付一种载体，额外云文档、独立 HTML 或 SVG 源文件仅在用户明确要求时提供。
