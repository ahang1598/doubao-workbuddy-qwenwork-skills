# 医学检验检查报告解读

## 适用场景

当用户上传、提供或提到体检报告、检验报告、检查单、化验单、影像报告、内镜报告、病理结果、专科报告或历年健康数据，并希望理解报告内容、异常含义和下一步该怎么观察或就医沟通时使用本 skill。只要识别到用户表达的是“医学检验检查报告解读”或“体检报告解读”需求，或上传了疑似医疗报告的图片、照片、截图、PDF、文档、表格、压缩包/文件，即使没有明确说“解读”，甚至只发附件没有正文，也应调用本 skill。典型需求包括：

- 解读体检、检验、影像、胃肠镜、病理和专科报告。
- 处理用户上传的报告图片、照片、截图、PDF、文档或文件，并判断其中是否包含体检、检验、检查、影像、内镜、病理或医院报告内容。
- 处理用户只发图片/附件、只说“帮我看看”“正常吗”“有什么问题”“怎么解读”的报告解读场景。
- 解读单张检查单或单次检验报告；即使没有历年趋势，也必须生成异常总览、分组表、逐项详细解读和单次指标汇总表。
- 将健康问题分为：建议限期就医、建议复查随访、建议长期管理。
- 识别内部紧急风险或急症风险时，单独生成“情况紧急”提示，并用视觉上更强的警示呈现。不要向用户展示“危急值”这个内部术语。
- 健康问题分类必须先用普通用户能看懂的一句话表达，再列医学指标和证据；不要把专业术语直接作为主要问题标题。
- 分模块详细解读异常指标，并说明当前结果、参考范围、临床意义、相关风险和行动建议。
- 分析历年指标趋势和异常变化，作为异常解读和长期管理的辅助证据。
- 评估疾病风险和相关风险因素。
- 生成医疗复查、营养饮食、运动健身、睡眠压力和生活方式管理建议。
- 生成适合飞书阅读、分享、协作和后续编辑的个人健康管理文档。

不要用本 skill 做急诊判断、疾病诊断、疾病确诊、具体治疗方案、处方建议、用药调整、检查替代决策或替代医生治疗决策。若用户要求“诊断是什么”“怎么治疗”“吃什么药/剂量/疗程”“是否需要手术”等，应改为建议携带报告咨询医生，并仅提供报告证据整理、风险提示、复查沟通要点和生活方式管理建议。若用户描述急性胸痛、严重呼吸困难、意识障碍、肢体无力、消化道出血等急症风险，应先建议立即就医。

## 输出方式与优先级

- 用户只发报告图片、照片、截图，或粘贴文字报告内容（包括只有附件没有正文、只说“帮我看看/正常吗/解读一下”），且未指定交付载体时，优先在当前回答正文直接完成可视化解读，使用 `inline_visual_report`，不默认创建飞书文档。
- 用户明确要求飞书文档、完整云文档、分享协作或提供飞书文档链接要求更新时，使用飞书文档分支。用户明确指定其他载体时按其要求。
- 其他报告文件输入未指定交付方式时，沿用飞书文档输出；用户要求只在对话解释或不要创建文档时使用正文解读。
- 正文解读需要先读 [回答正文可视化路由](references/answer-visualization.md)，按内容调用随包子 skill。可视化沿用已有子 skill 的取舍、数据、渲染、移动端和实际展示规范，不能只用 emoji 或重新排成卡片替代有用图形。

## 可视化载体

可视化优先用程序化 SVG，数据比较、关系图、动作与管理步骤示意都遵守 [SVG 可视化规范](references/svg-visualization.md)。静态 SVG 为默认；交互有理解收益时才使用 SVG 配合最少的 HTML/脚本。不调用图片生成或图片编辑工具，不输出 PNG/JPEG/WebP 等新栅格图，也不将 SVG 截图或转成位图。用户上传的报告图片仍可作为输入阅读。

当前宿主不能展示 SVG 时，保留准确的正文解释、表格或步骤，不自动改成生图。飞书文档仍不调用图表助手；无法原生显示 SVG 时使用表格和文字。

## SVG 的执行方式

静态图默认直接构造 SVG 内容，并用宿主支持的方式在回答正文展示，不以创建、修改 `build_svg.py` 等脚本或单独生成图表预览项目作为前置步骤。临时计算和检查按 [SVG 规范中的执行与确认边界](references/svg-visualization.md#执行与确认边界) 处理，区分模型主动追问与平台强制审批。

## 工具使用规则

- **趋势模块硬门槛**：只有证据表中存在同一数值指标 2 个及以上可靠时间点，才允许生成“重点指标趋势”模块。若所有内容都只有一个时间点，必须省略“重点指标趋势”，改为用表格和文字呈现单次异常、偏离程度和风险分层。
- 单次报告或单张检查单仍须按系统/指标类别做详细解读，并以表格汇总异常指标。
- 创建飞书文档时，必须按 `lark-doc` skill 的创建文档流程执行；创建前读取其要求的共享认证和文档 XML 规则。
- 飞书文档分支默认使用文档 XML 创建文档；只有用户明确要求 Markdown 时才改用 Markdown。
- 输出内容只能定位为“健康信息整理与管理建议”。不得输出诊断结论、疾病确诊、具体治疗方案、药物剂量/疗程、手术/侵入性处置建议，或替代医生判断的治疗路径。
- 内部紧急风险识别必须谨慎但不能只依赖报告是否标注。若报告标注内部紧急风险、用户/报告提供的检验机构紧急阈值被命中，或结果呈极端异常且经 `general_search`/`MedicalSearch` 核验符合权威立即处理标准，应触发用户可见的“情况紧急/请立即联系医生”。报告正文不得出现“危急值”“critical value”“panic value”等内部术语；无触发时不要写任何“未发现紧急风险”的默认说明。
- 只要回复中涉及药品、医生、医院，或需要给出相关建议，必须调用 `MedicalSearch`；多个实体分多次调用，每次只查一个 query。
- 需要查当前指南、权威标准、疾病科普或医学来源验证时，使用 `general_search`。
- 需要计算日期窗口、BMI、eGFR、百分比变化、均值、标准差、趋势统计或风险评分时，使用 `calculator`。
- 动作讲解、家庭监测、饮食搭配和复查流程需要图解时，按 SVG 规范由 [结构图子 skill](references/atomic-skills/answer-structure-diagram/SKILL.md) 用矢量图形、文字和连线表达；结构不能可靠表达时用步骤文字，不生成伪造医学影像或处置演示。
- `operate_saved_memory` 只在用户明确要求“记住/更新/删除”个人信息时使用。不要主动记忆健康信息。

## 核心工作流

1. 识别资料来源：报告日期、医院/科室、检查类型、患者基本信息、是否有历年数据，以及数值是否清晰可读。
2. 建立健康问题清单：本次异常、持续异常、恶化趋势、改善项目和无法确认项目。
3. 将问题分为四类：
   - `suggest_emergency_or_urgent_review`：情况紧急或需要立即急诊处理。
   - `suggest_timely_medical_review`：建议限期就医。
   - `suggest_follow_up_testing`：建议复查随访。
   - `suggest_long_term_management`：建议长期管理。
4. 对每条任务给出明确时间窗口：
   - 情况紧急：现在，立即联系报告出具机构/主管医生，必要时急诊或拨打 120。
   - 建议限期就医：非急诊但需尽快，通常 24-72 小时内或 1 周内，必须写清楚具体窗口。
   - 建议复查随访：通常 1-4 周、1-3 个月或按原报告建议。
   - 建议长期管理：通常 1-3 个月建立计划，3-6 个月复盘。
5. 生成健康问题分类表：`优先级 | 主要问题（一句话） | 这意味着什么 | 对应指标/证据 | 建议动作`。主要问题必须通俗，医学术语只放证据列。不要在报告正文或标题中输出“普通用户版”。
6. 医学解释必须基于已抽取证据和已验证来源。不得编造诊断、病因、风险结论或具体治疗方案。
7. 对所有优先级异常生成“异常指标详细解读”模块：当前结果与参考范围、异常程度、医学解释、相关风险、与其他指标的关系、复查/就医/管理建议。单张检查单必须逐项解读每个异常指标，不得只输出总览。
8. 对重复指标做趋势分析：新发异常、持续异常、恶化、改善、波动、稳定或数据不足。仅当存在同一指标 2 个及以上时间点时生成“重点指标趋势”；若全是单时间点，不生成该模块。
9. 生成长期管理建议：就医沟通、复查安排、营养、运动、睡眠、生活方式和家庭监测。不得生成个体化治疗方案、药物方案或处置方案。
10. 按已选输出方式组织解读。正文分支按 [references/answer-visualization.md](references/answer-visualization.md) 调用子 skill，将图形和关键解读放在回答正文；保持逐项异常解读、风险与建议的必要信息，不要求照搬完整云文档目录。
11. 飞书文档分支才按 [references/report-structure.md](references/report-structure.md) 生成 XML 草稿并创建文档；保留任务卡、异常解读表、趋势对比表、风险分层和管理清单。推荐命令：`lark-cli docs +create --api-version v2 --content '<title>...</title>...'`。
12. 正文分支直接交付可视化解读和必要说明；飞书文档分支交付实际生成的文档 URL，格式为：`飞书文档：[个人健康管理报告](https://.../docx/...)`。

## 默认输出

按“输出方式与优先级”选择载体。图片或文字报告的正文分支，先给关键结论，再展示有解释收益的图形并逐项说明异常、参考范围、含义和建议；不以创建文档为先决步骤，不要求用户点击链接才能看到核心解读。无需同时附送飞书文档、HTML、图表配置或重复的下载文件。

飞书文档分支的最终回复须含真实文档链接，不能只说“已生成报告”。该分支不生成本地 HTML；创建失败时说明原因，并保留可重试的文档草稿或草稿位置。正文可视化按当前宿主协议实现，内部渲染资源不默认作为独立下载文件交付。

## 医疗安全要求

每份报告必须包含：

- 明确免责声明：报告用于健康信息整理和管理建议，不构成诊断、治疗方案、处方、用药建议或替代医生面诊。
- 对异常或高风险发现，建议咨询合格医生或对应专科。
- 涉及指南阈值、药品、医生、医院或重要医学解释时，要保留来源。
- 原始报告不完整、文字不清、时间过旧或互相矛盾时，要写明不确定性。

禁止写“你确诊了某病”“诊断为...”“治疗方案是...”“完全没问题”“必须服药”“停掉某药”“建议手术/不用手术”“无需就医”等确定性或治疗指令。应使用“提示”“可能与...相关”“建议与医生讨论”“需要结合症状和医生判断”等表达。
