# Generate Premium Promo Kit

把企业中的商品事实和活动讨论直接变成可评审、可修改、可归档的高质量促销物料。默认一站式执行；除非缺少产品参考图或存在无法安全决策的关键冲突，不要停下来反复提问。

## 读取必需参考

- 开始策划与生成前，阅读 [visual-quality.md](references/visual-quality.md)。
- 识别活动类型并策划宣传语前，阅读 [campaign-archetypes.md](references/campaign-archetypes.md)。
- 确定每张海报的字体、层级和版式前，阅读 [typography-system.md](references/typography-system.md)。
- 制定物料清单与平台尺寸时，阅读 [deliverables.md](references/deliverables.md)。
- 生成后质检与改版时，阅读 [qa-checklist.md](references/qa-checklist.md)。

## 输入契约

用户通常只提供三部分：

1. 商品资料：商品文档、品牌规范、商品图、文件夹或附件；
2. 活动上下文：节庆、周年庆、购物节、上新等促销脑暴文档、群聊、会议纪要或价格表；
3. 触发语：如“豆包帮我生成促销活动的全套物料”。

自动发现并读取用户明确放入范围内的飞书文档、群聊、附件和本地文件。不要要求用户手工复制已有内容。

如果缺少产品参考图，先从商品文档、附件和指定文件夹中查找。仍找不到时，只询问一次产品图；没有可靠产品图不得伪造正式商品外观。

如果缺少品牌Logo，先从品牌规范、商品包装、附件和指定文件夹中查找。正式物料必须使用真实Logo素材；不得让模型凭文字生成近似Logo。仍找不到时，使用明确的Logo占位区并将其标为阻塞项，不把占位版交付为Final。

## 事实优先级

按以下顺序处理信息：

1. 商品名称、规格、材质、功能、成分、使用方法：最新版官方商品资料；
2. 产品外观、颜色、包装、Logo位置和结构：用户提供的真实产品图；
3. 品牌色、字体、Logo安全区和禁用项：品牌规范；
4. 本次价格、优惠、活动时间、渠道与受众：群聊或脑暴文档中最新的明确决定；
5. 历史活动和旧版本：仅作参考，不得覆盖本次确认信息。

为价格、核心卖点和促销机制保留来源。遇到冲突时：

- 使用能确定的最新明确决定；
- 在Brief中标出冲突及采用值；
- 无法判断且会造成价格、合规或产品事实错误时才请求确认；
- 非关键缺口使用醒目的占位符继续首版，不因小缺口中断。

## 一站式工作流

### 1. 建立事实底座

提取并结构化：

- 商品名称、SKU、规格、颜色、材质、核心卖点、适用人群；
- 日常价、活动价、组合优惠、赠品、叠加规则、限购与库存；
- 活动目标、主题、时间、渠道、目标受众、行动号召；
- 品牌规范、禁用表述、视觉方向和渠道尺寸；
- 产品图片及其他可复用资产。

不要扩写资料未支持的功能、功效、成分、检测结论、保冷时长或适用范围。

### 2. 识别活动意图并输出可执行Brief

先判断活动属于节庆、周年庆、购物节、上新、开业、会员或其他类型，再依据 [campaign-archetypes.md](references/campaign-archetypes.md) 选择传播逻辑。不要套用固定的“高级生活方式”空话。

简洁输出并同时用于后续生成：

- 活动背景与目标；
- 活动主题、主广告词、辅助文案；
- 每类物料对应的标题、卖点短句、价格/优惠、活动时间与CTA；
- 目标人群与核心场景；
- 产品事实和卖点；
- 价格及促销机制；
- 高级视觉概念、配色、光影、字体与版式；
- 平台策略；
- 物料矩阵；
- 待确认项与风险。

先明确呈现Brief，再基于Brief生成宣传物料。若用户要求“一键生成”或“全套物料”，输出Brief后立即继续首批生成，不额外等待确认；只在关键事实缺失会导致错误宣传时暂停。

### 3. 规划默认首批物料

没有用户自定义清单时，默认生成：

- 活动主KV：16:9横版1张、3:4竖版1张；
- 电商方图：1:1三张，分别承担主视觉、价格利益、场景卖点；
- 小红书生活方式海报：3:4一张；
- 朋友圈运动促销海报：3:4一张；
- Brief、物料清单、生成提示词、质检记录和版本说明。

平台尺寸与内容任务使用 [deliverables.md](references/deliverables.md)。

### 4. 构建系列化创意系统

先确定一套母视觉，再派生各平台版本：

- 一个活动主题与一句核心广告语；
- 一套“主标题＋辅助卖点＋促销机制/活动信息＋CTA”的传播文案体系；
- 一套主色、辅助色和光影语言；
- 一套字体组合、字号比例、网格、价格卡、Logo安全区和装饰元素；
- 2—4个与商品关联的真实场景；
- 一个固定产品英雄角度和比例范围。

高端不等于空泛奢华。通过克制留白、真实材质、准确产品、现代排版和场景可信度建立高级感。遵守 [visual-quality.md](references/visual-quality.md)。

### 5. 路由生成模型

固定使用：

- 商品图、KV、电商图、社交海报、邀请函等全部静态视觉调用 **Seedream 5.0 Pro**；
- 在模型请求参数中明确选择 Seedream 5.0 Pro；
- Seedream 5.0 Pro不可用时，立即说明阻塞或请求用户允许替代，不得静默降级到其他模型；
- 不生成短视频、动态海报、口播视频或镜头脚本，除非用户在后续请求中明确扩展范围。

不要只输出提示词来代替用户要求的生成。调用可用媒体生成工具实际产出素材。

### 6. 使用两阶段流程生成成品宣传物料

无字商品场景图只是中间底图，不是最终宣传物料。为了保证商品、Logo和文字质量，默认采用：

1. 先生成/编辑无文字或少文字的产品场景底图，锁定商品外观、构图与光影；
2. 再使用真实Logo素材和可控文字排版层，加入Brief确认的主标题、辅助卖点、价格/优惠或活动信息、活动时间与CTA；
3. 无法可靠生成中文时，保留干净排版区，不生成近似文字；必须随后用可控文本层补齐，不能只交付无字底图；
4. 同一系列复用统一字体、字重、阴影、对齐、价格卡和留白规则。

排版必须遵守 [typography-system.md](references/typography-system.md)。文字需要与产品、场景和构图形成一个整体，禁止把几行默认字体简单贴在图片上。

每张Final宣传物料至少必须具备：

- 真实品牌Logo；
- 与活动类型对应的主宣传语；
- 一条产品卖点或场景利益短句；
- 已确认的价格、折扣、赠品、活动时间等促销信息；若活动没有价格机制，则使用已确认的活动权益或参与方式；
- 清晰CTA，如“立即选购”“限时参与”“到店体验”；
- 完整且可直接发布的排版设计。

每个生成提示词必须包含“全局一致性块”及该物料的场景、文案、尺寸和禁止项。不要把多张不同构图塞进一次模糊请求。

### 7. 自动质检并重试

逐张对照产品参考图检查。使用 [qa-checklist.md](references/qa-checklist.md) 的硬门槛。

- 产品外观或结构错误：必须重做；
- 缺少Logo、宣传语、促销信息或CTA：不得作为成品交付；
- Logo、价格、活动主题、中文文字错误：必须修正；
- 字体廉价、层级混乱、系列不一致：重新排版；
- 文字只是简单叠加、未形成品牌版式：不得作为Final；
- 每个物料最多自动重试2轮；仍失败时只能将底图标记为中间产物，并明确列出需人工排版的内容，不把无字图或Logo占位图冒充定稿。

### 8. 归档与回传

物料生成与质检完成后，必须新建或更新一个活动飞书云文档，按以下结构归档：

1. 活动Brief；
2. 产品事实与参考图；
3. 视觉系统；
4. 主KV；
5. 电商图；
6. 社交海报；
7. 每张物料的尺寸、渠道、文案、版本和提示词；
8. 质检记录；
9. 待确认项和变更记录；
10. 完整交付清单。

将全部图片以可预览形式插入文档对应章节，不只粘贴本地路径。将文档链接和交付清单回传原群聊。定稿前保留旧版本，不覆盖用户已确认素材。

若飞书工具不可用，创建等价的本地交付包，明确说明飞书归档尚未完成，不得声称任务已经完整交付。

## 最小化沟通规则

- 自动读取已有资料，不让用户重复搬运；
- 一次性列出真正阻塞的缺口，最多问1—3项；
- 能以占位符继续的就继续；
- 清楚区分“已确认事实”“创意建议”“待确认信息”；
- 用户要求修改时，继承全部上下文，只改点名内容，锁定其他产品事实、价格和品牌规范。
