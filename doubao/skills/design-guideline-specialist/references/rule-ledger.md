# 规则账本与确认协议

使用本参考将用户的 Logo 和设计规范转换为可执行、可追溯的审计规则。

## 规则类别

只建立与用户资料相关的类别：

- Logo 版本、组成、图形与字标；
- 比例、间距、安全区和最小尺寸；
- 标准色、单色、反白和背景适用性；
- 对比度、位置、裁切、遮挡、拉伸、倾斜、镜像和视觉效果；
- 品牌名、拼写、大小写、字体和字标；
- 标题、正文、字重、字号和排版；
- 联名、主从关系、分隔方式和排列顺序；
- 必备文案、法务声明、版权和口号；
- 渠道、媒介、国家/地区、活动或产品场景例外。

## 规则 ID

使用稳定、可读的 ID：

- `LOGO-01`：Logo 组成或版式；
- `SPACE-01`：安全距离或间距；
- `SIZE-01`：尺寸；
- `COLOR-01`：色彩；
- `TYPE-01`：字体；
- `NAME-01`：品牌名与拼写；
- `LAYOUT-01`：位置与排版；
- `COBRAND-01`：联名；
- `LEGAL-01`：必备文案或法务信息。

同类规则按顺序递增。已向用户确认的 ID 不要因排序调整而更改。

## 账本字段

| 字段 | 说明 |
|---|---|
| 规则 ID | 稳定编号 |
| 类别 | Logo、色彩、字体、排版等 |
| 要求 | 可直接执行的判定条件 |
| 适用场景 | 媒介、背景、渠道或上下文 |
| 例外 | 规范明确允许的例外 |
| 来源定位 | 文件、页码、章节、幻灯片、区块或图片 |
| 状态 | 明确规则／推断待确认／未知 |
| 确认记录 | 用户是否已确认及相关补充 |

## 状态标准

### 明确规则

满足以下任一条件：

- 规范使用“必须”、“需要”、“不得”、“禁止”、“仅限”等强制性措辞；
- 规范给出可直接测量的数值或条件；
- 规范将示例明确列为 Do 或 Don't；
- 用户在确认环节明确指定为规则。

### 推断待确认

包括：

- 只有视觉示例，没有文字解释；
- 从 Logo 样图中估计的比例、颜色、字体或间距；
- 用词为“建议”、“通常”、“优先”、“尽量”，但审计是否需要将其视为强制不明确；
- 两个来源表达不一致，但可能属于版本或场景差异。

推断待确认项必须向用户追问，不得直接用于违规判定。

### 未知

包括：

- 来源无法读取或缺失关键页面/图片；
- 规范没有涉及该问题；
- 上下文不足以确定适用场景；
- 冲突在确认后仍未解决。

未知规则不参与通过/违规评分。

## 确认门槛

确认结果必须包含：

1. 成功读取的来源和版本；
2. 部分读取或无法读取的来源；
3. Logo 版本与区分特征；
4. 明确规则表；
5. 推断待确认项；
6. 冲突与缺口；
7. 会改变审计结论的必要问题。

将“确认”、“没问题”、“按这个执行”等明确表达视为确认。

用户只回答了部分问题、修改了规则、新增了资料或回复含糊时，不得视为确认。更新账本后重新请用户确认。

确认后冻结当次规则版本。审计中规则变更时，暂停审计并重新确认。
