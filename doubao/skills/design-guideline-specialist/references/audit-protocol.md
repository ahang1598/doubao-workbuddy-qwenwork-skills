# 视觉资产审计协议

仅在用户确认规则与审计范围后使用本参考。

## 1. 冻结审计依据

记录：

- 规范名称、版本和日期（如有）；
- 用户已确认的规则 ID；
- 已确认的适用场景和例外；
- 审计来源与范围；
- 因属于推断或未知而不参与判定的规则。

规则变更时停止审计，更新规则账本并重新获得确认。

## 2. 建立完整资产清单

为每个审计单元分配稳定资产 ID，并保留来源定位：

- 本地文件：相对路径、文件类型、尺寸/页数；
- 文档：文档标题、页码、幻灯片或区块；
- 多维表格：记录 ID、主字段、字段名和附件名；
- 网页：URL 和页面内可识别的资产位置。

将每项标记为：

- `已读取`；
- `无法读取`；
- `格式不支持`；
- `重复`；
- `按已确认范围跳过`。

不得因为文件相似而自动跳过。除非用户明确要求抽样，否则检查所有范围内资产。

## 3. 逐资产检查

使用原始分辨率或足够清晰的渲染结果。必要时使用 OCR、图像对比、页面渲染和可靠测量。

对每个适用规则记录：

- 结果；
- 检测到的品牌元素；
- 观察证据和大致位置；
- 已确认规则 ID 及要求；
- 置信度；
- 具体修改建议。

### 结果分类

- `通过`：所有适用的已确认规则均有充分证据表明符合。
- `确认违规`：至少一条适用的已确认规则有充分证据表明不符合。
- `需要人工复核`：证据、场景或规则不足以安全判定。
- `不适用`：没有已确认规则适用于该资产。

### 置信度

- `高`：画面清晰，规则和证据可直接对应。
- `中`：基本可判断，但受尺寸、压缩、背景或上下文影响。
- `低`：证据不足，只能推测。低置信度项目必须进入人工复核。

## 4. 避免误判

- 如果规则未要求必须出现 Logo，Logo 缺失不是违规。
- 区分普通正文中的品牌名与承担 Logo/字标功能的独立文字。
- 规范未限制的 Logo 变体不得仅因为与示例不同而判定违规。
- 严格应用浅色/深色背景、PPT 封面/内页、单品/联名等场景例外。
- 不得将预览、压缩或渲染引入的缺陷当作原资产缺陷，除非已检查原件。
- 没有可靠测量方法时，不得声称得到精确颜色、字体、间距或尺寸。使用“视觉估算”标记。
- 规则未知、图像模糊或场景不明时，进入人工复核。

## 5. 报告结构

### 摘要

报告：

- 发现资产数和成功审计数；
- 无法读取、不支持、重复和跳过数；
- 通过、确认违规、需要人工复核和不适用的资产数；
- 按规则类别和规则 ID 统计的违规数；
- 清单总数与各类结果数的对账。

### 明细表

| 资产 ID | 来源定位 | 文件/页面/记录 | 检测到的品牌元素 | 结果 | 规则 ID | 已确认要求 | 实际证据 | 位置 | 置信度 | 修改建议 |
|---|---|---|---|---|---|---|---|---|---|---|

包含无违规资产的覆盖表，不得只输出问题项。

### 人工复核

对每项说明：

- 什么内容不确定；
- 为什么无法安全判定；
- 人工需要检查或测量什么；
- 确认后会应用哪条规则。

### 局限

列出无法访问的来源、缺失的视觉示例、预览限制、OCR 限制、不支持格式和范围排除。

## 6. 交付前自检

- 清单数与所有结果数一致。
- 每个确认违规都引用了已确认规则 ID。
- 引用规则确实适用于对应资产场景。
- 推断和未知规则没有被用于违规判定。
- 跳过项和访问失败已披露。
- 修改建议具体可执行，且不要求直接覆盖原始资产。
- 不存在伪造的像素值、色值、字体、比例或测量数据。
