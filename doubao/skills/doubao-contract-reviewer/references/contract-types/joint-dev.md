# 合作开发合同专项审查规则

> 本文件仅包含通用规则（risk-library 40 条 + trap-detection 16 条独有规则）**未覆盖**的合作开发合同特有风险。
> 识别为合作开发合同时由 SKILL.md Step 0 条件加载，非合作开发合同不加载本文件。
>
> **编号规则**：JD = Joint Development，编号 JD-01 ~ JD-07。
> **方向化**：所有规则均标注触发前提，严格区分"约束我方"还是"约束对方"。

## 规则详情

### JD-01 各方投入（资金/技术/人员）未量化

| 字段 | 内容 |
|------|------|
| **优先级**| 🟡 P1 |
| **触发前提**| **始终触发**。合作开发的核心基础是各方投入的明确量化，投入不清将导致后续权属和收益分配全部失去依据 |
| **风险描述**| 合同未具体约定各方的投入内容和规模（资金金额、技术贡献范围、人员数量及工时、设备/场地提供等），导致各方贡献不可衡量 |
| **检测方法**| 检查合同是否明确约定：①各方资金投入金额及到账时间；②各方技术投入内容（技术方案/专利/Know-how）；③各方人员投入（人数/资质/工时）；④设备/场地等其他投入 |
| **修改建议**| 增加"各方投入"条款，建议采用表格形式列明各方的投入明细："甲方投入：资金 X 万元（于 X 日前到账），技术人员 X 名（全职）；乙方投入：核心技术方案、专利许可、测试设备" |

### JD-02 分工安排和里程碑节点未明确

| 字段 | 内容 |
|------|------|
| **优先级**| 🟡 P1 |
| **触发前提**| **始终触发**。《民法典》第 851 条规定合作开发合同应当约定"各自承担的工作" |
| **风险描述**| 合同未明确各方的分工范围和阶段性里程碑节点，导致开发过程中推诿扯皮，项目延期或成果质量不达标 |
| **检测方法**| 检查合同是否约定：①各方的分工范围（谁负责哪些模块/环节）；②开发阶段划分和里程碑节点；③各阶段的交付物和验收标准；④延期的处理机制 |
| **修改建议**| 增加"项目计划"附件，以甘特图或表格形式列明各阶段分工："阶段一（X月-X月）：甲方完成{任务}，乙方完成{任务}，交付物为{成果}，验收标准为{标准}" |

### JD-03 背景 IP 与合作产出 IP 未分离界定

| 字段 | 内容 |
|------|------|
| **优先级**| 🟡 P1 |
| **触发前提**| **始终触发**。知识产权归属是合作开发合同的核心条款。risk-library 规则 38/39 覆盖通用 IP 归属检查，但"背景 IP vs 合作产出 IP"的分离界定是合作开发特有问题 |
| **风险描述**| 合同未区分背景 IP（各方合作前已有的知识产权）和合作产出 IP（合作过程中新产生的知识产权），导致一方的既有 IP 被错误归入合作成果，或合作成果被一方独占 |
| **检测方法**| 检查合同是否：①定义"背景 IP"并列明各方的背景 IP 清单；②定义"合作产出 IP"；③明确背景 IP 归原属方所有，仅许可合作使用；④明确合作产出 IP 的归属（共有/按贡献分配/归一方所有+另一方许可使用） |
| **修改建议**| 增加 IP 条款："各方合作前已有的知识产权（见附件《背景 IP 清单》）归原属方所有，仅在本合同目的范围内许可对方使用。合作过程中新产生的知识产权归{双方共有/按贡献比例分配}" |

### JD-04 收益分配方式和比例未约定

| 字段 | 内容 |
|------|------|
| **优先级**| 🟡 P1 |
| **触发前提**| **始终触发**。《民法典》第 860 条规定合作开发的成果归属和利益分享由合同约定，未约定则由各方合理协商 |
| **风险描述**| 合同未约定合作成果的商业化收益分配方式和比例，合作成功后双方因利益分配产生重大争议 |
| **检测方法**| 检查合同是否明确约定：①收益分配比例；②收益的计算方式（净利润/营收/许可费）；③分配周期和结算方式；④各方独立使用合作成果时的收益处理 |
| **修改建议**| 增加收益分配条款："合作成果的商业化收益按甲方 X%、乙方 Y% 的比例分配，以净利润为计算基准，按{季度/年度}结算。各方独立使用合作成果进行商业化的，应按上述比例向对方支付许可费" |

### JD-05 亏损/风险分担方式未约定

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| **始终触发**。有收益分配必须有对应的风险分担，否则"共享收益、不担风险"的条款对一方显失公平 |
| **风险描述**| 合同约定了收益分配但未约定开发失败或亏损时的风险分担机制，导致一方承担全部损失 |
| **检测方法**| 检查合同是否约定：①开发失败时各方已投入成本的处理；②开发过程中产生亏损的分担比例；③一方过错导致项目失败时的赔偿责任 |
| **修改建议**| 增加条款："合作开发未达预期目标的，各方按投入比例分担已发生的成本和损失。因一方过错导致项目失败的，过错方应赔偿对方的合理损失" |

### JD-06 合作终止后的成果处理未约定

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| **始终触发**。合作终止/解除后的成果处理直接影响各方利益 |
| **风险描述**| 合同未约定提前终止或期满后已完成和进行中成果的处理方式（归属、使用权、保密义务延续等），导致成果闲置或争议 |
| **检测方法**| 检查合同是否约定：①终止时已完成成果的归属和使用安排；②进行中成果的处理（继续完成/停止/由一方接管）；③终止后各方对合作成果的使用限制；④保密义务的存续期 |
| **修改建议**| 增加条款："合同终止后，已完成的合作成果按本合同 IP 条款处理。进行中的成果，双方协商由一方继续完成并向对方支付合理对价，或停止开发并各自保留已有成果的使用权" |

### JD-07 合作管理机构和决策机制缺失

| 字段 | 内容 |
|------|------|
| **优先级**| 🔵 P2 |
| **触发前提**| **始终触发**。中大型合作开发项目需要明确的治理机制 |
| **风险描述**| 合同未约定合作的管理架构（联合管理委员会/项目经理制）和决策机制（一致同意/多数决/一票否决），导致日常管理和重大决策时无章可循 |
| **检测方法**| 检查合同是否约定：①管理架构（如联合管委会的组成、职责）；②日常决策机制；③重大事项决策机制（如方向变更、追加投入）；④争议内部升级机制 |
| **修改建议**| 增加条款："双方成立项目管理委员会，各方派 X 名代表组成。日常事务由项目经理负责，重大事项（包括但不限于方向变更、追加投入超过 X 万元）须经管委会一致同意" |

## 执行说明

1. **加载条件**：当 §2.1 交易本质解构识别出"共同研发、成果共享"模块时加载本文件（可与其他类型文件并行加载）
2. **执行顺序**：本文件的 7 条规则与通用规则（risk-library + trap-detection）合并为统一规则集，按 P0→P1→P2 统一排序后一起执行（不再单独置于通用规则之后），重要风险自然前置
3. **去重保障**：本文件所有规则均已与 risk-library（40 条）和 trap-detection（16 条独有）完成去重，不存在重叠。JD-03 与 RL-38/39 的区别在于：RL-38/39 检查通用 IP 归属，JD-03 专门检查"背景 IP vs 合作产出 IP"的分离界定
4. **融入清单**：JD 规则命中项与通用规则命中项合并排序（P0 > P1 > P2），共同受 15 条上限约束
