## 加载机制

- **多模块并行加载**：Step 0 按 Playbook §2.1 四问解构交易本质，一份合同可能由多个并存模块叠加（如"定制开发+代运营"=copyright+service），按解构出的**每个模块加载对应类型文件**（可同时多个，建议 ≤3，抓主要模块）
- **去重保障**：每个文件的规则均已与 risk-library（40 条）和 trap-detection（16 条独有）完成去重；多类型文件之间同一风险只批注一次
- **统一排序融合**：所有加载的类型规则与通用规则**合并为统一规则集，按 P0→P1→P2 统一排序**后一起执行，共同受批注上限约束（详见 Playbook §4.9）
