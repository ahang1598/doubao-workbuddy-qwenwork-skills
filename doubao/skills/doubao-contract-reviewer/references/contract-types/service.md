# 服务合同专项审查规则

> 本文件仅包含通用规则（risk-library 40 条 + trap-detection 16 条独有规则）**未覆盖**的服务合同特有风险。
> 识别为服务合同时由 SKILL.md Step 0 条件加载，非服务合同不加载本文件。
>
> **编号规则**：SV = Service，编号 SV-01 ~ SV-07。
> **方向化**：所有规则均标注触发前提，严格区分"约束我方"还是"约束对方"。

## 规则详情

### SV-01 服务范围/SOW 不清晰

| 字段 | 内容 |
|------|------|
| **优先级**| 🟡 P1 |
| **触发前提**| **始终触发**。服务范围不清是服务合同纠纷最常见原因 |
| **风险描述**| 合同未附 SOW（Statement of Work）或服务内容描述笼统模糊（如"提供咨询服务"），导致双方对服务边界理解不一致，引发范围蔓延（scope creep）或服务不足争议 |
| **检测方法**| 检查合同是否有独立的 SOW 附件或详细的服务内容描述，是否明确：①服务项目清单；②各项服务的具体内容和交付物；③服务排除项（不包含哪些） |
| **修改建议**| 增加 SOW 附件或在合同中明确服务项目清单，建议采用表格形式列明"服务项目、具体内容、交付物、完成时间"，并明确"SOW 未列明的服务不属于本合同范围" |

### SV-02 服务标准/SLA 未量化

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| 我方为**委托方（甲方/采购方）**时触发。我方为服务方→不触发（SLA 不量化对服务方更灵活） |
| **风险描述**| 合同约定的服务标准为主观描述（如"提供优质服务""尽合理努力"），缺乏可衡量的 SLA 指标，导致无法客观评判服务质量 |
| **检测方法**| 检查合同是否约定可量化的服务标准，如：响应时间、解决时间、可用率、错误率、满意度评分等 |
| **修改建议**| 增加 SLA 条款，约定量化指标，例如："服务方应确保系统可用率不低于 99.5%，故障响应时间不超过 X 小时，未达标的按{标准}扣减服务费" |

### SV-03 服务验收标准和流程未明确

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| 我方为**委托方**时触发。我方为服务方→不触发（验收标准不明确时，委托方难以拒绝付款，对服务方有利） |
| **风险描述**| 合同未约定服务成果的验收标准和流程，导致服务方交付后委托方无客观依据拒绝验收，或服务方以"已交付"为由要求付款 |
| **检测方法**| 检查合同是否约定：①验收标准（对照 SOW 逐项验收）；②验收流程（提交→审核→反馈→确认）；③验收期限；④验收未通过的处理方式 |
| **修改建议**| 增加验收条款："服务方完成服务后提交验收申请，委托方应在 X 个工作日内完成验收。验收未通过的，委托方应书面说明理由，服务方应在 X 日内整改并重新提交" |

### SV-04 服务人员要求未约定

| 字段 | 内容 |
|------|------|
| **优先级**| 🔵 P2 |
| **触发前提**| 我方为**委托方**时触发。我方为服务方→不触发（人员要求不约定时服务方有更大灵活度） |
| **风险描述**| 合同未约定服务人员的资质要求、人数、关键人员锁定和替换机制，服务方可能随意调换人员影响服务质量 |
| **检测方法**| 检查合同是否约定：①人员资质要求；②关键人员名单及锁定期；③人员替换需事先通知并经委托方同意；④替换人员的资质不低于原人员 |
| **修改建议**| 增加条款："服务方应指派符合{资质要求}的人员提供服务。关键人员名单见附件，未经委托方书面同意不得替换。确需替换的，替换人员资质不得低于原人员" |

### SV-05 不可转包/分包条款缺失

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| 我方为**委托方**时触发。我方为服务方→不触发（无分包限制对服务方有利） |
| **风险描述**| 合同未禁止或限制服务方将服务转包/分包给第三方，导致实际提供服务的主体不可控，服务质量和数据安全难以保障 |
| **检测方法**| 检查合同是否约定：①禁止转包或限制分包条件；②如允许分包，是否需委托方事先书面同意；③分包方的资质要求；④服务方对分包方行为的连带责任 |
| **修改建议**| 增加条款："未经委托方书面同意，服务方不得将本合同项下的服务全部或部分转包/分包给第三方。经同意分包的，服务方对分包方的行为承担连带责任" |

### SV-06 服务终止后交接安排未约定

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| **始终触发**。服务终止后的交接直接影响业务连续性 |
| **风险描述**| 合同未约定服务终止/到期后的交接安排（含数据迁移、文档移交、过渡期支持），导致服务中断时委托方业务受损或被锁定（vendor lock-in） |
| **检测方法**| 检查合同是否约定：①终止后的交接义务和交接期限；②数据/文档/账号的移交方式；③过渡期的服务支持安排；④交接完成的确认标准 |
| **修改建议**| 增加条款："合同终止或到期后，服务方应在 X 日内完成全部交接工作，包括但不限于：移交全部数据和文档、配合委托方或新服务方完成过渡、删除委托方数据并出具删除证明" |

### SV-07 服务中断/延迟违约责任不对等

| 字段 | 内容 |
|------|------|
| **优先级**| 🟠 P1 |
| **触发前提**| **始终触发**。检查服务方延迟/中断的违约责任与委托方延迟付款的违约责任是否对等 |
| **风险描述**| 合同约定服务方延迟/中断的违约责任轻微（如仅"延长服务期"），而委托方延迟付款的违约责任严重（如高额滞纳金+暂停服务），双方违约责任不对等 |
| **检测方法**| 对比服务方违约责任条款和委托方违约责任条款，检查违约金比例、赔偿范围、解除权触发条件是否大体对等 |
| **修改建议**| 调整违约责任使双方大体对等，例如服务中断超过 X 天委托方有权按日扣减服务费，严重中断（超过 Y 天）有权解除合同并要求赔偿 |

## 执行说明

1. **加载条件**：当 §2.1 交易本质解构识别出"行为/服务给付"模块时加载本文件（可与其他类型文件并行加载）
2. **执行顺序**：本文件的 7 条规则与通用规则（risk-library + trap-detection）合并为统一规则集，按 P0→P1→P2 统一排序后一起执行（不再单独置于通用规则之后），重要风险自然前置
3. **去重保障**：本文件所有规则均已与 risk-library（40 条）和 trap-detection（16 条独有）完成去重，不存在重叠
4. **融入清单**：SV 规则命中项与通用规则命中项合并排序（P0 > P1 > P2），共同受 15 条上限约束
