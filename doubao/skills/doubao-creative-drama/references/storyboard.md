# 分镜阶段 Ref

完整模式在项目级故事包、`current_episode` 详细剧本和当前集资产分别取得用户确认后读取本文件。本文件是镜头规划、运镜阈值和 planned SEAM 的唯一权威。本阶段只处理当前集；不得在当前集达到目标前提前制作后续集分镜。轻量模式在规划页取得视频生成授权后读取本文件，只把已确认的最多 `8` 行简洁预览扩充为与完整模式同列定义、同填写标准的内部十五列详细分镜，用于逐镜编译视频 Prompt。

## 本 Ref 关键要求

- 分镜只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成关键帧、视频或最终 Prompt。
- 正式分镜必须覆盖当前确认范围内全部剧情，不能只给样例、摘要或局部镜头。
- 用户可见分镜阅读稿按“本集提要 -> 章节 -> 视频片段 -> 片段内镜头秒数”的顺序写。每个 SEG 先选择 `density_profile`：高密度平台短片 `high_density_short`、对白/情感 `dialogue_emotional`、悬疑蓄力 `suspense_build`、微电影/生活流 `micro_film` 或 `custom`。只有 `high_density_short` 的常规剪辑型 `15` 秒视频至少 `8` 个有效镜头；其他类型按完整动作、表演反应、信息事件、阅读时间和自然切点推导，不设统一最低镜数。真正一镜到底是唯一单镜例外。
- 关键帧按集规划总量：完整模式每集必须 `3-4` 张高光 KF，从整集开局钩子、重大揭示/反转、关系断裂/选择、高潮或结尾钩子中择强选点。不是每个 SEG 都需要关键帧；未承载集级高光或连续性风险的 SEG 不规划 KF。关键帧不规划首帧或尾帧。
- 每个 SEG 必须存在 `reference_input_plan` 数组：有真实图片输入时逐张规划本段已选高光关键帧（若有）、连续接缝所需的上一段真实尾帧、主体、角色状态、场景、道具、风格和连续性抽帧的职责、来源、采用/剥离边界；没有任何真实图片输入时可写空数组，并在片段路由理由中说明 `text_to_video` 的成立条件。非首段只有 planned `SEAM=elliptical` 且不需要媒体锚点时才可为空；不得伪造图片项。视频阶段不得无理由重排或漏传，真实上传顺序变化时必须同步更新图片标记和记录。
- planned SEAM 是生成前目标；真实 FRM、observed seam 和剪切点只能在视频阶段记录。

## 目标

把 `current_episode` 已确认的完整剧本和当前集采用资产逐场转换为可直接指导视频生成和生成后抽帧的分镜交付包。正式交付必须覆盖当前集全部剧情，不得只提供样例、部分镜头、简略提纲或夹带后续集镜头。

本阶段只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成角色图、场景图、道具图、音色、关键帧或视频。必须引用 approved 人物/状态、场景、道具、音色和 `STYLE001` 全局 moodboard；完整模式每集必须规划 `3-4` 张高光 KF，同时说明为什么这些时刻值得成为关键帧，规划视频必需图片职责和生成后 FRM 抽取职责。

每集唯一导演总控卡锁表达策略并解释“为什么这样看、如何剪、如何连续”，分镜主表写“观众看到什么”；最终视频 Prompt 只在 `video.md` 编译。分镜阶段不得写伪最终 Prompt。

分镜阶段只能继承已确认视觉锚点；`style_contract` 缺少可执行风格机制时必须停止并返回 `planning.md` 补齐、递增 revision 和重新确认，不得在分镜阶段自行补选风格。已确认风格存在但需要诊断漂移时，才读取 `电影大师风格库.md`，且只用于解释和校准原有光线、色彩、构图、材质和节奏机制。镜头职责、动态数量、主运镜和切点合同以本文件为准。

写具体分镜时，先执行本文件、`scriptwriter.md`、`assets.md`、`manifests.md` 和 `control-contracts.md`。四个创作参考库只读取与当前分镜问题直接相关的部分：用 `剧作方法与类型库.md` 校准场景功能、攻防关系、信息释放和必要场面；用 `题材亮点与传播库.md` 校准开场钩子、反转、爽点/泪点、传播句和片段节拍；用 `题材受众库.md` 校准观看焦点、情绪回报、平台观看场景和表达禁区；用 `电影大师风格库.md` 校准光线、色彩、构图、材质、声音和节奏机制。不得因分镜阶段读取候选库而改写已确认剧情、结局、人物身份、受众定位、风格合同或资产版本。

## 输入条件

必须具备：

- 已确认并存入 `01_剧本/` 的 `剧本_全局设定与分集总纲.md` 和全剧完整剧本；合并文件必须同时包含“全局故事圣经”和“分集推进总纲”两章。另需已确认并存入 `episodes/ep_N/01_剧本/` 的分集创作说明、完整剧本和 `script_contract_ep_N.json`。
- 已确认的 `00_制作控制/project_data_card.json`；本集所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具及声音主体均能解析到稳定 ID 与 approved 当前版本。一次性物件只进入分镜和 Prompt，不要求建立 PROP 资产。
- 已确认且已向用户展示或明确标注复用的当前集人物、场景、道具、音色和风格资产；资产必须来自当前集新增项、共享 approved 库或已完成分集的 approved 复用项，不得引用尚未生成的未来集资产。
- 已确认的项目固定画幅。
- 已确定且已经按 `planning.md` 完成参数确认表的视频模型、片段时长上限和会员模型提示；本阶段只继承，不自主切换。
- 用户原始指令、后续修改、原台词、必须出现项和禁用项。

剧本存在未写出的剧情、场次或台词时，返回剧本阶段补齐，不得由分镜阶段猜测剧情。

上列输入条件只适用于完整模式。轻量模式只读取已确认规划、五列预览、用户原始指令与真实可用素材，然后创建 `episodes/ep_1/02_分镜/分镜_完整分镜表_ep_1.md`。十五列逐镜要求与完整模式完全一致，不能删列、空列或用五列预览代替；扩充只能补足镜头、动作过程、表演、声音、连续性和素材职责，不得改变已确认的故事方向、动作结果、台词、模型、时长、画幅或素材边界。轻量模式不创建项目数据卡、分镜 JSON、导演总控卡、视频片段执行表、连续性账本、参考输入计划或关键帧需求清单，也不新增用户确认门。

## 分镜产物分层

完整模式内部生成唯一导演总控卡、十五列分镜表、视频片段执行表、连续性账本、关键帧需求清单和结构化索引；面向用户只展示可审查的分镜阅读稿与简要镜头方案摘要，不点名内部制作支撑物、哈希、路径或检查过程。轻量模式只生成十五列分镜表，且不向用户展示。两种模式都不得用参数确认表中的五列分镜预览表/剧情节奏预览表替代详细分镜。

各文档职责：

- **导演总控卡**：拆镜前唯一的导演决策中心，统一锁定本集视觉叙事、核心意象、场面调度、节奏波形、表演、声音与风格系统；不得另建导演阐述卡或强风格系统卡。
- **完整分镜表**：一行一镜，固定十五列，包含镜头职责、画面、声音、运镜、连续性和抽帧承接。
- **视频片段执行表**：一行一 `SEGxxx`，记录模型调用容器、片段内时间轴、切镜触发、首尾状态、承接方式和生成风险。
- **连续性账本**：追踪角色、道具、空间、轴线、光线、动作和声音的跨镜头、跨片段连续性。
- **关键帧需求清单**：把已确认基础资产映射到镜头和视频片段，并定义每张待生成关键帧的职责、构图、状态和连续性。

## 完整模式工作顺序

1. **拆剧情节拍**：逐场标出钩子、欲望、阻力、策略变化、权力转折、代价、信息差和兑现或悬念。
2. **写导演总控卡**：按本文件“导演总控卡字段合同”锁定本集视觉、意象、调度、节奏波形、表演、声音、色彩、材质、字体/版式和剥离项；后续所有镜头只落实这一个决策中心。
3. **定章节与片段**：先按剧本章节/场次职责排出本集阅读稿顺序，再按确认模型把默认片段切成每 `15` 秒一个 `SEGxxx`；尾段、自然切点或用户指定模型例外时记录原因。
4. **推导节奏与覆盖方案**：先选择 `density_profile`，再列不可移动内容节点，判断信息密度、动作强度和阅读时间，确定唯一主重拍，决定节点之间切镜还是镜内连续，先分配动作和核心证明时长，再分配剩余时长，最后用 `1-5` 强度序列检查。只有 `high_density_short` 的常规剪辑型 `15` 秒叙事视频至少 `8` 镜；其他类型不设统一最低镜数。任何类型都必须保持完整动作单元，不得为了数量拆断。
5. **写完整分镜表**：一行只承担一个不间断观看位置；显著换机位、景别、视角、时间或信息焦点时拆成新镜；同一 SEG 内各镜头首尾相接，总和等于该片段时长。
6. **切视频片段**：按模型时长上限把镜头分组为 `SEGxxx`，片段边界必须落在镜头切换点。
7. **补连续性和导演控制**：在唯一导演总控卡内明确轴线、视线、动作方向、道具状态、光位、声音桥、动作桥和每个切点的动机。
8. **规划关键帧、输入图和抽帧需求**：把已确认人物、角色状态、场景、道具、音色和风格资产绑定到镜头，定义待生成高光关键帧职责；先从整集选择 `3-4` 个剧情高潮、信息揭露、动作不可逆点或关系断裂瞬间，再映射到对应 `SEGxxx`，写清它为什么是信息峰值或冲突峰值；列出视频阶段必须传入的图片职责、实际传入顺序建议、采用/剥离边界，并列出生成后需要抽取的首帧、场景锚点帧、必要角色状态帧、必要道具状态帧和尾帧。

轻量模式只执行其中与十五列分镜直接相关的步骤：拆剧情节拍、推导镜头与时长、逐镜填写十五列、检查时间连续与每列非空，然后交给 `video.md` 编译 Prompt。不得因此创建上述完整模式配套文件。

除“完整分镜表”及其十五列填写规则外，本文件后续关于导演总控卡、结构化分镜索引、片段执行表、参考输入计划、关键帧需求、表演谱、色彩脚本、连续性账本、SEAM 和阶段确认的文件要求均只适用于完整模式。

## 节奏类型与镜头数量推导算法

对每个 SEG 在拆镜前执行一次，并把结论写入片段执行表和 `storyboard_ep_N.json.segments[]`。不得先决定镜头数再往里填内容。

1. **读取依据**：读取本段剧本目标、完整台词、`viewer_takeaway`、`hook_landing`、不可移动内容节点、用户指定的平台/风格/镜头方式、总时长和相邻 SEAM。先把用户明确要求的一镜到底或剪辑方式锁定，不能由密度规则覆盖。
2. **选择主导负载**：判断本段最不能被压缩的内容是什么。短时间内需要连续给出异常、行动、反馈、证据和结果，且删除任一事件都会削弱观看动力，选 `high_density_short`；意义主要来自说话策略、倾听反应和关系距离，选 `dialogue_emotional`；意义主要来自线索可见性、延迟揭示和等待压力，选 `suspense_build`；意义主要来自连续行为、环境观察、生活质感或余韵，选 `micro_film`；用户定义的规则无法被前四类准确描述时选 `custom` 并写清自定义判断标准。题材名称、平台名称和时长本身不能单独决定类型。
3. **冲突时取舍**：同一段同时命中多类时，选择“若被压缩最先损坏核心证明”的一类作为 `density_profile`，其余只作为执行倾向。例如对白中藏证据时，若观众必须听清攻防才成立，主类仍是 `dialogue_emotional`；若台词只是为连续揭示服务，才选 `high_density_short`。记录采用理由和未采用类型的排除理由。
4. **拆不可移动事件**：把本段写成按因果排序的事件节点，每个节点必须至少改变信息、行动、关系、危险、空间或道具状态之一。再把每个节点拆成不可再分的动作单元：起点、动作过程、接触或反馈、可见结果。一个动作单元只有在改变观察位置、信息焦点或关系时才允许跨镜；为了多一镜把“伸手 -> 接触”无理由切断不成立。
5. **从单元生成镜头**：先为每个需要独立观察位置的动作单元分配一个镜头；说话权改变、听者反应改变策略、证据从不可读变为可读、空间关系或时间跳跃时新增镜头。相邻单元若观察位置、信息职责和动作连续性相同则合并；删除后不损失剧情、关系、信息或连续性的镜头删除。
6. **处理高密度 15 秒下限**：仅当 `density_profile=high_density_short`、`shot_mode=edited` 且时长恰为 `15` 秒时，检查是否至少得到 `8` 个有效镜头。少于 `8` 镜时，优先补足剧本已经包含但尚未独立呈现的证据、对手反馈、听者反应、空间关系、策略变化或结果余震；不得复制反应、数字裁切或拆断完整动作凑数。仍不足 `8` 个真实职责时，说明本段并不具备高密度内容：返回剧本补足因果事件，或在不违背用户要求时改选真实 `density_profile`，不能伪报八镜。
7. **检查其他类型**：`dialogue_emotional|suspense_build|micro_film|custom` 不追求数量。逐镜执行删除测试和动作完整性测试；若删除镜头会丢失策略、反应、线索、等待压力、空间关系或余韵则保留，否则合并。长镜只有在连续时间本身承担压力、选择或观察价值时成立。
8. **输出与回退**：记录 `density_rationale`、`indivisible_action_units[]`、每个单元对应的 SHOT、删除测试结论和最终镜头数。若时长容不下完整台词、动作和反应，先拆 SEG 或返回剧本缩减非锁定内容；不得提高语速、截断动作或压掉反馈。

### 黄金三秒事件设计

只对 `high_density_short + edited + 15秒` 执行。三个事件不是三个任意剪辑点，而是一条最短因果链：

1. **事件一，给出异常或承诺**：让观众在首镜看见或听见一个具体事实，知道“哪里不对、谁有风险或这次会看到什么”。不得只用标题、滤镜、空镜或音效假装钩子。
2. **事件二，让主体采取行动或暴露目标**：主体必须因事件一做出可见动作、语言策略、视线选择或位置变化，使观众知道谁被卷入以及他想做什么。
3. **事件三，给出反馈并改写观看关系**：对手、环境、证据或道具回应主体，使信息差、权力、危险、焦点或空间关系至少一项变化；这一步同时构成前 `3` 秒内的有意义切镜或镜内观看关系变化。

把三项写入 `opening_event_chain`，逐项绑定真实时间范围、SHOT、前态、事件和后态。三个事件可以落在三个镜头，也可以在连续镜头运动中完成，但登记为 `edited` 时仍须存在真实切点；同一个物体的三个无变化特写、同一反应的重复角度、文字卡加音效或纯景别变化不算三个事件。若第三项在 3 秒内无法读懂，先简化信息或提前可见证据，不得靠加速台词解决。

## 每集导演总控卡

详细拆镜前只生成一份 `episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。它同时承担原导演阐述、导演控制与风格系统职责，不得再创建平行决策卡。至少包含：

- 视觉叙事策略：本集观察者立场、空间压力、构图与镜头节奏如何随局势变化。
- 核心意象：一个可重复、可变义的视觉或声音母题，以及每次出现的意义变化。
- 场面调度总纲：从分集创作说明的人物关系张力表继承权力差、信息差、情感差，并转成高低、远近、遮挡、靠近和回避。
- 节奏设计：六步推导结果、所选波形、唯一主重拍和 `1-5` 强度序列；快切、连续表演、停顿和静默分别落在哪个剧情节点及原因。
- 表演指导：逐镜填写情绪层次、微表情目标、肢体语言和呼吸节奏；微表情不能单独承担关键信息。
- 声音设计：基础环境声、叙事性环境声、情绪性环境声、BGM 曲线、静默和声音桥。
- 色彩叙事合同：主辅色、人物/关系映射、变化触发节点和光影象征。
- 视觉风格系统：媒介形态、构图骨架、光线方向、色彩关系、材质、镜头质感、字体/版式和明确剥离项。

导演总控卡不能只列形容词。每项必须绑定场次、镜号范围或剧情触发点，并在完整分镜表和 `storyboard_ep_N.json.director_control_card` 中可追溯。

### 亮点绑定检查

分镜前读取本集 `script_contract.highlight_ledger`，按 `manifests.md` 的 schema 在 `storyboard_ep_N.json.highlight_bindings` 中逐项绑定。每个 `role=primary` 的亮点至少包含一个兑现镜头、一个结果/反应镜头和一个高潮后余震镜头；同一长镜可承担多个职责，但对应可观察阶段必须写清。绑定必须填写视觉、表演、声音和视频编译说明，某一维度不适用时写清理由，不能统一填写“加强氛围”。任何剧本主要亮点找不到镜头，先返回剧本调整或重拆分镜，不得直接删除。

每个主要亮点按“触发 -> 变化 -> 反馈 -> 结果”推导，不从“需要一个高光画面”倒推装饰性镜头：

1. **触发**：读取 `setup_evidence` 和当前场次前态，选择真正迫使人物或局势改变的台词、证据、动作或规则事件，并绑定观众可见/可听的镜头。
2. **变化**：写清触发后谁采取了什么不可忽略的策略，人物位置、道具控制权、信息归属、关系或危险如何发生可见变化；只写情绪形容词不成立。
3. **反馈**：给出对手、听者、环境或规则的即时回应，让观众确认变化被世界接住。反馈必须改变下一拍策略或认知，不能只补一个无后果惊讶特写。
4. **结果**：写清本场或后续场次留下的代价、权力重排、选择后果或余震。结果可延迟到后续集，但必须通过 `deferred_aftereffect_ref` 指向明确回收点。

四步按顺序写入该亮点的 `causal_chain` 并绑定 SHOT；再把变化/兑现镜头映射到 `payoff_shot_ids`，反馈镜头映射到 `reaction_shot_ids`，结果或余震映射到 `aftereffect_shot_ids` 或跨集引用。同一 SHOT 可以承担相邻两步，但必须分别写出可观察状态；若缺触发、反馈或结果，返回剧本补因果，不得用慢动作、强音乐、发光或群众惊叹替代。

### 受众执行检查

分镜只能继承已确认 `drama_plan.json.audience_plan`，不得重新选择受众、平台或地域。在 `storyboard_ep_N.json.audience_execution` 中按 `manifests.md` 分别登记观看焦点、情绪回报、平台观看场景和表达禁区的执行合同，并把每项绑定到真实场次或镜头。四项都必须可追溯；仅写“符合受众”“适合平台”或重新引用受众库标签不算落地。

## 导演总控卡字段合同

> 本节规定每集正式拆分镜前必须完成的唯一导演判断，以及这些判断如何进入逐镜表和视频 Prompt。不得另建第二份导演控制包或强风格系统卡，也不把整张总控卡塞进每个 Prompt。

### 职责边界

- `导演总控卡_ep_N.md`：每集唯一整体创作判断，先于逐镜表完成，并在同一文件内把判断落实为每个 SEG 和 SHOT 的调度、布光、表演、声音、动作与剪辑合同。
- `storyboard_ep_N.json`：保存总控卡文件指针和可执行字段，不复制长篇说明。
- `video.md`：只编译已确认导演总控卡和分镜，不重新发明导演方案。

### 每集导演总控卡

固定文件：`episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。至少包含：

- **视觉叙事策略**：回答观众如何被安排去看，包括主要观察距离、主客观视角、空间压力、运动与静止分工、何时拒绝特写、何时让环境压过人物。禁止只写“电影感、压迫感、高级感”。
- **开场承诺与情绪曲线**：继承 `script_contract.opening_contract`，写清首个叙事节拍如何被看见、谁先反应、什么动作或信息使其升级、在哪个场次兑现或延续；再把项目级 `emotion_design` 细化为关键角色的入场状态、压力来源、转折触发、可见证据、关系后果和尾态。
- **核心意象**：选择 1-2 个道具、动作、空间、色彩或声音母题，记录“首次含义 -> 变奏 -> 高潮重释 -> 结尾余韵”。每次出现必须增加信息或改变意义；无变化的装饰不算核心意象。
- **场面调度总纲**：继承人物关系张力表，说明权力差、信息差和情感差如何通过距离、屏幕位置、纵深、遮挡、出入口和道具控制权变化。允许反讽调度，不能机械套“强者站高、弱者站低”。
- **节奏设计**：标记需要快切、连续表演、停顿、长镜或突然中断的段落及戏剧原因。快切用于信息压缩或失控，长镜用于让选择和反应无法逃避；不得用速度掩盖场景没有转折。
- **节奏波形推导**：依次记录不可移动内容节点、每个节点的信息密度/动作强度/阅读时间、唯一主重拍、切镜或镜内连续选择、动作与核心证明优先后的时长分配，以及 `1-5` 强度序列。可选“快起 -> 稳证 -> 快收”“逐级加速 -> 高光 -> 短停”“快慢交替 -> 汇聚”“连续推进 -> 节点变速”“结果前置 -> 倒推线索 -> 原因揭示”“稳态建立 -> 突然打断 -> 连续应对 -> 新稳定”“单点触发 -> 层层扩散 -> 整体响应 -> 回收”“两线交替 -> 节奏对齐 -> 汇合”“问题脉冲 -> 回答脉冲 -> 证据停留”“克制积累 -> 局部释放 -> 完整爆发 -> 余韵”“建立规则 -> 两次变奏 -> 打破规则 -> 新规则收束”“起点 -> 偏离 -> 回归 -> 无缝 Loop”或自定义波形；不得固定切成 `0-3 / 3-7 / 7-11.5 / 11.5-14 / 14-15`。
- **视觉风格系统**：媒介形态、构图骨架、光线方向、色彩关系、材质、镜头质感、字体/版式、明确剥离项。它是总控卡的一部分，不单独维护风格系统卡。
- **亮点转译**：逐项读取本集 `script_contract.highlight_ledger`，写清观众先看到什么、哪个动作兑现、表演如何泄露真实意图、声音何时进出、哪个镜头保留余震。信息重释重证据和反应，关系攻防重距离/遮挡/道具控制权，专业能力重流程和策略修正，母题重重复变奏，表演瞬间重表面策略与泄露动作，情绪余震重高潮后的结果镜头。

### 总控卡逐字段推导方法

按下列顺序从上游事实推导，不允许先写形容词再找镜头佐证：

1. **建立输入表**：读取 `creative_proposition`、`opening_contract`、`highlight_ledger`、人物关系张力矩阵、场次 entry/exit state、`emotion_design`、`rhythm_design`、`style_contract`、数据卡空间/状态和用户镜头禁令。每条输入标记来源场次；互相冲突时回到最早权威阶段，不在总控卡中私自折中。
2. **推导观察者立场**：先问观众应比谁知道得多、与谁同处压力、何时需要看清证据。由答案决定主客观视角、主要观察距离、环境与人物的画面占比，再绑定场次范围；这形成“视觉叙事策略”。
3. **推导核心意象**：从会重复出现且意义会改变的动作、道具、空间、色彩或声音中选 `1-2` 个，分别写首次含义、变奏触发、高潮重释和结尾余韵。删掉后不影响理解或意义不变化的对象不选。
4. **推导场面调度**：把每个关系节点的权力差、信息差、情感差翻译成世界坐标中的距离、纵深、遮挡、出入口、视线和道具控制权；先写 T0，再只记录触发后的 T1/T2 变化。机位随后服务调度，不允许为了构图暗中移动人物或房间。
5. **推导节奏与表演**：从不可移动节点和主重拍分配快切、连续表演、停顿和静默；再对承担转折的角色写“表面策略 -> 内在压力 -> 泄露动作 -> 对方反馈 -> 尾态”。没有因果触发的表情、呼吸或停顿删除。
6. **推导声音**：先锁基础环境声，再为会改变信息的动作配置叙事声，只在主观感知触发时加入情绪性声音；最后决定 BGM 入退、静默和声音桥。若声音与对白争夺同一信息，把非主信息后移或降低，不同时强调。
7. **推导色彩和风格**：逐项继承 `style_contract`，先写基础光源、主辅色、材质和构图骨架，再只在有世界内原因或剧情触发时写变化。无法指出光源、时间、天气、实景灯、服装或空间原因的自动变色删除。
8. **绑定执行范围**：每项决策必须落到场次、SEG、SHOT 范围或明确触发点，并在逐段执行区写首态、尾态、删除损失和专项合同。若一项无法绑定任何镜头，它不是本集执行决策，应删除或返回上游补依据。
9. **一致性检查**：逐项问“它服务哪个剧情问题、在哪一镜可见、变化由什么触发、视频 Prompt 需要继承哪部分”。四问任一无答案时重写；不同字段要求互斥动作、光线、声音或观看立场时，以核心证明和用户锁定项为先，不能同时保留。

### 表演指导合同

AI 表演使用可观察层次，不依赖抽象形容词或只有微表情。每个关键镜头至少写清：镜号、角色、表面策略、内在压力、可见情绪层次、主要脸部/目光/肢体/呼吸变化、触发点、尾态和禁止表演。

- 表面策略决定人物在做什么；内在压力解释动作为什么泄露。
- 微表情只作增强，关键信息同时由动作、距离、道具、声音或结果承担。
- 一镜最多突出一个主要表演转变，复杂变化拆成可观察节拍。
- 有听者时单独写听者反应及尾态，不能只细化说话者。
- 禁止“夸张震惊、持续流泪、机械点头、全员同一表情”等默认失控表演。
- 关键表演镜头可绑定 `performance_scores` 和 `performance_coverage`；AU 只作辅助强度标尺，不替代自然语言动作因果。

### 声音设计方案

每集先写整体声音命题，再逐段落实三层声音：

- **基础环境声**：房间底噪、空调、电流、远处车流等，用于空间和连续性，不抢对白。
- **叙事性环境声**：钟声、雨声、脚步、门锁、机器停转等，每次出现必须改变信息或预期。
- **情绪性主观声**：心跳、耳鸣、闷化、呼吸放大等，只在人物感知被触发时短暂进入，并写退出点。

BGM 不得持续填满，也不得只写“低频 BGM”“紧张音乐”“悬疑感音乐”。每条 BGM 写清入点、退点、乐器/音色、速度或节奏、音量、质地、情绪职责和对白避让；跨 SEG 延续时，下一段复用上一段已确认 BGM 描述或 `bgm_descriptor`。

- 静默写明移除哪些声音、保留哪些身体或空间声、持续范围、人物感知和结束触发。
- 完全静默只在世界逻辑或主观听觉成立时使用；通常保留呼吸、布料、空间反射更可信。
- 声音桥登记来源镜头、目标镜头、声音主体、跨越时长、叙事作用和淡入淡出。优先使用环境声、拟音、动作声或非语义人声尾音；音乐桥只在剧情确实需要时使用。台词尾音只写声尾、气口或混响状态，不复制完整台词，不得写“自然衔接”。

### 色彩叙事合同

色彩首先是项目已确认风格的子系统，其次才承担本集变化。禁止把冷蓝、暖橙、红色等机械等同于固定情绪。

色彩脚本写清基础主色、辅色、禁用色/冲突色、人物色彩归属、变化触发、光影路径和高潮状态。色彩变化必须能在光源、时间、天气、实景灯、服装、人物移动或空间转换中解释；认知改变不等于画面自动变色。关键段记录基准主辅色、色温/对比、肤色与主体分离、可见触发、跨镜继承或允许偏移，不要求固定色值。

### Prompt 编译

- 视频 Prompt 不照抄十五列分镜表；以分镜阅读稿的逐镜语言为骨架，抽取景别、机位、运镜、时长、声音、动作桥、连续性和抽帧承接等硬信息，结合 `reference_input_plan` 的真实图片职责，改写为 `video.md` 的项目语言五段式。每个镜头恰好编译一次。
- 每个 SEG 只采用与该段直接相关的导演总控卡内容：视觉策略、节奏原则、色彩基线、人物色彩归属、场景光源、核心意象、道具状态、表演节拍、三层声音、BGM 入退点、静默、声音桥、禁止表演、禁止色彩跳变和尾态。
- 阅读稿、十五列表和 JSON 不一致时，先回分镜修订；视频阶段不得自行取舍。

## 场次、片段与镜头

“场次、视频片段、镜头”不得混为一层：

- **场次**：连续戏剧空间或连续戏剧行动，使用 `E{集号}S{场号}`，例如 `E01S01`。
- **视频片段**：一次视频模型调用容器，使用 `SEG001`、`SEG002`；它可以包含一个或多个完整镜头。
- **镜头**：一次不间断观看位置，使用 `E01S01-SHOT001`；单个镜头不得跨两个视频片段。

模型时长只决定提交方式，不反向决定剧情节奏。不得为了填满模型上限把无关镜头塞进同一片段，也不得把重复裁切、数字推拉或无信息变化的构图算作新镜头。

## 片段与时长

- 交付规模按用户意图伸缩：单条剧情短片通常为 15-60 秒；常规多集短剧单集通常为 1-3 分钟，极短集支持 15-60 秒；微电影通常为 5-10 分钟。具体时长结合用户指令、剧本事件量、对白预算和自然切点确定，并在规划阶段以准确秒数确认。
- 用户未指定模型时固定使用 `seedance 2.0 fast`，每个 SEG 默认规划为 `10-15 秒`且不得超过 `15` 秒。
- 用户明确指定 `seedance 2.0 mini` 或 `seedance 2.0` 时，每个 SEG 仍不得超过 `15` 秒。
- 只有用户明确指定并完成会员额度提示确认后才能使用 `seedance 2.5`；该模型每段优先规划为 `25-30 秒`，不得超过 `30` 秒。
- 所有镜头使用绝对时间戳，首尾相接，总和等于本集确认时长。
- 默认尽量利用已确认模型容量，但不为凑时长填充慢动作或无效镜头。总时长尾数、自然切点、动作复杂度、生成稳定性或用户明确时长要求导致片段低于目标区间时，记录 `duration_exception_reason`；这些理由不得用于自主切换模型或突破对应时长上限。
- 片段边界优先落在可剪切拍点且必须同时是镜头切换点：连续动作优先在动作进程 `30%-70%`、遮挡最充分或甩镜运动模糊最强处切出，让下一段从同相位或略微推进的位置接入；只有动作单元真正结束、策略变化、信息揭示、角色反应、场景切换或声音过门时才落在完成态。
- 不得在一句台词、一个连续动作或关键反应中间强行截断。
- 每个片段至少安排两个可观察的剧情状态变化，例如“发现线索 -> 误判”“施压 -> 反击”“动作接触 -> 结果反应”。
- `high_density_short` 的 `15` 秒视频执行黄金三秒：前 `3` 秒至少包含 `3` 个可见信息事件，并至少发生一次有意义切镜或观看关系变化；第一镜通常不超过 `1.2` 秒。其他类型不套三事件和首镜时长指标，但首个完整叙事节拍必须持续推进问题、目标、关系或悬念。任何较长首镜都必须持续升级构图、焦点、动作、关系或信息。
- 中间 SEG 默认使用 `continuous_motion` 或 `cuttable_completion` 尾态，让下一段从动作相位、视线、声音或状态继续，不强制停住。只有剧情确需停顿时才使用 `stable_hold` 并写理由。最终 SEG 默认使用 `stable_hold` 保留 `0.6-1.0` 秒稳定结果帧；无缝 Loop 或未完成动作结尾按真实切点处理。
- 每个片段必须有独立可理解的 `viewer_takeaway` 和钩子落点：观众看完本 SEG 要知道发生了什么、谁采取了什么策略、压力来自哪里、证据/关系/危险/道具状态改变了什么，以及最后一拍为什么让人继续看。不能把 10-15 秒片段写成单一慢镜、无信息凝视、纯氛围空镜或只有“情绪很难过”的镜头集合；抒情段也必须让观众看见具体选择、证据、回避、失去或关系变化。
- 短剧节奏必须紧凑：剧情人声优先承载目标、阻力、施压、反击和钩子，但不按句数堆叠。默认每个 SEG 至少有一条可原生生成的人声；普通段把人声总朗读时长控制在片段时长约 `55%` 以内，高密度对话或独白段也不得超过约 `70%`。不得把 15 秒写成无声凝视或纯氛围空镜，也不得把 15 秒塞成长篇解释让模型加速朗读。纯动作、无声、音乐蒙太奇或强抒情段必须来自用户明确要求或题材硬约束，并用动作信息变化补足观看密度。
- `seedance 2.5` 的 `25-30 秒`片段必须在同一场景/动作链/对话轮次能够稳定持续时使用；跨场景过多、复杂动作过载或尾态无法承接时，改用更短片段并说明原因。
- 真正一镜到底是唯一允许单镜覆盖整段或整片的例外：从头到尾必须是同一次连续拍摄，禁止硬切、隐藏切、遮挡伪切、匹配剪辑和时间跳跃。可以连续跟拍、平移、推拉、升降、环绕或穿越空间，但必须通过连续摄影机路线、主体行动和空间变化安排至少三个可观察节点。只有缓慢推镜、发光、凝视、轻微动作、走路或抬手不构成合格长镜头。

### 尾态选择算法

在定稿每个 SEG 的末镜前执行：

1. 先判断是否为最终 SEG、无缝 Loop，或后续仍需承接同一动作/视线/声音/状态。
2. 后段必须接同一动作且完成态会失去动势时，选 `continuous_motion`，把尾点放在动作进程 `30%-70%` 的清晰相位，并写方向、速度、接触状态和下一段从何相位继续。
3. 当前动作已经完整，但下一段可从结果、反应、视线、物件位置或声音尾音接入时，选 `cuttable_completion`；结果必须可读，但不额外停住等待。
4. 只有最终落点、剧情明确要求停顿，或中间段的停顿本身会改变判断/关系时选 `stable_hold`。最终 SEG 默认留 `0.6-1.0` 秒；中间 SEG 必须在 `tail_hold_reason` 写清停顿制造的具体信息或压力。
5. 只有首尾画面与动作能形成真实无缝循环时选 `loop_continuation`，同时写明末态如何回到首态；“画面相似”但动作、道具、光线或声音状态不闭合时不得使用。
6. 将所选模式写入末镜动作、声音、SEAM 出段 cue 和下一段入段 pickup。若下一段无法从该尾态自然开始，先改尾点或转场；不得在 Prompt 中同时要求“稳定停住”和“持续高速运动”。

### 真正一镜到底的场面调度算法

仅在用户明确要求或连续时间本身承担叙事价值时使用 `shot_mode: true_one_take`：

1. **画路线而非列镜头**：先在 `blocking_map` 标出摄影机起点、终点、可通行路径、角色 T0/T1/T2 位置、出入口、遮挡物、光源和必须看清的证据；全段只登记一个 SHOT。
2. **安排至少三个连续节点**：节点必须依次改变空间、关系、信息或动作结果，例如“跟随进入 -> 绕到对峙双方之间 -> 后退揭示门外证人”。每个节点写触发、摄影机路径、主体行动、新信息和进入下一节点的自然动力。
3. **让主体动作驱动摄影机**：角色靠近、回避、抢夺、开门、转身或视线发现决定摄影机何时跟、停、绕、升降或转焦；不得让摄影机无原因游走，也不得只靠持续慢推撑满时长。
4. **维持连续世界**：逐节点核对轴线、屏幕方向、角色速度、道具接触、光位、声音距离和背景锚点。遮挡可以作为真实空间经过，但不得借遮挡伪造切换、换时空、换演员或重置动作。
5. **分配时间与可生成性**：为每个节点保留完整动作和反应时间；复杂多人同步、跨楼层、不可连续通过的空间或需要时间跳跃时判为不可执行。用户未锁定一镜到底时改为 `edited`；用户已锁定时停止并说明具体冲突，返回调整动作或空间，不能偷偷使用隐藏切。
6. **编译与检查**：Prompt 只写一条连续摄影机路线，节点之间使用“摄影机继续/转向/绕行/停下后再跟随”等连续语言，不写“切到、转场、匹配剪辑、蒙太奇”。检查任一时间点是否都能从前一位置物理到达；无法回答时重做路线。

## 高密度剧情与运镜

分镜阶段要把镜头机制写成叙事功能，不把紧凑误解为机械碎切。连续微动作可以合并为本项目的剧情动作组：每个 `2-5` 秒动作组可承载多个微动作，但必须在同一行写完整“切入触发、主体动作、对手/环境/道具反馈、结果变化和切出落点”，不能只写“快速打斗”“连续躲避”“镜头跟随”。

动作、追逐、对峙、技能、商业攻防或家庭冲突的高密度段，优先按轮次组织：

- **起势/亮招**：用近景、特写、低机位、推镜或固定等待建立威胁和行动意图，画面必须让观众知道谁先掌握主动权。
- **接触/碰撞**：用动作切、POV、过肩、横移、甩镜或快推表现第一次交锋，并让道具、身体、空间或声音出现可见反馈。
- **躲避/格挡/误判**：用俯拍、侧跟、后拉、慢动作或短暂停顿展示角色处境，让观众看清危险差一点发生在哪里。
- **反制/策略变化**：用环绕、升镜、低机位或焦点转移表现主动权翻转，不能只让角色“突然变强”，必须有证据、技能、道具或选择作为原因。
- **结果/留白/钩子**：用闪白、遮挡、声音断点、结果特写或远景关系重置制造期待，但留白后必须给出结果、代价或新危机，不能只停在空悬念。

机位要讲权力关系：占优者可用仰拍、低机位、前景压迫、居中或高占比；劣势者可用俯拍、远景、遮挡、边缘构图或被迫后退；局势翻转时，机位、景别、焦点或画面占比也要随之变化。观众信息差是短剧高效抓人的手段：可以让观众先看见角色未看见的威胁、证据或伏笔，但分镜必须安排角色随后发现、误判或利用它，不能让信息差悬空。

## 动态镜头数量

镜头密度从内容节点和完整动作推导；每镜通常服务一个可观察的信息、动作、反应或关系变化，具体秒数由对白朗读、动作起势、动作完成、反应停顿和切点决定。`high_density_short` 的常规剪辑型 `15` 秒视频至少 `8` 个有效镜头，可继续增加但不设上限。`dialogue_emotional|suspense_build|micro_film|custom` 不设统一最低镜数，必须用删除测试、动作完整性和观看关系证明每镜必要。任何类型都不得为达到数量拆断完整动作，也不得把慢推、发光、凝视、轻微呼吸、重复反应或无信息变化的数字裁切算作镜头变化。

- 镜头必须足以清楚表达当前片段实际承担的钩子、目标、阻力、策略变化、高潮或反转、反应和收束。
- 两个以上关键职责只能靠一句台词或静止画面带过时，应增加镜头或镜内变化。
- 删除后不影响剧情、关系、信息或连续性的镜头应合并。
- 不为镜头数量碎切，不用慢动作、重复反应或无意义空镜填时长。
- 一镜到底只能登记一个镜头，且必须满足真实连续拍摄定义；镜内仍须包含连续变化的摄影机路线、主体行动、关系、空间或信息节点。
- 每个镜头只指定一个主运镜；片段内允许并鼓励切镜，但每个切点必须由动作、视线、遮挡、声音、反应、空间或信息变化触发。
- 剧情片段默认包含可听人声：出镜对白、旁白、画外音或内心独白按剧情选择，句句推动剧情、关系、信息或反应。每句可跨相邻镜头连续，但不能靠拖长停顿填时长，也不能靠加速语速塞进过短镜头。字幕生成、样式和烧录只继承 `delivery.md`；视频模型阶段仍禁止画面字幕和自动转写。
- 只有 `high_density_short + edited + 15秒` 强制至少 `8` 个有效镜头。真实一镜到底不把镜内节点伪报为多个镜头；其他配置按剧情节点与动作完整性决定。任何时长都不得用一个状态、一个动作、统一慢推、发光或轻微动作填满。

## 动作桥与观看关系

每个跨镜动作和每个切点都按以下链条设计：

```text
前镜状态
-> 动作发起
-> 运动路径
-> 合理切点或镜内调度
-> 后镜续接
-> 接触/反馈
-> 结果
```

每次切镜必须明确回答“为什么现在切”“用什么承接前一镜”“切后增加了什么新信息”。承接锚点只能来自动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中的实际可见/可听事实。动作桥示例包括“拿取 -> 移向入口 -> 接触 -> 收纳结果”“刷头靠近 -> 接触表面 -> 连续涂抹 -> 结果展示”“取料 -> 上脸 -> 使用反馈 -> 放回”“铺垫 -> 触发特效 -> 环境响应 -> 结果停留”。不得从动作发起直接跳到结果，也不得让手、人物、产品或道具在切后无路径换位。

## 单镜因果检查

每镜检查：

```text
谁想达成什么 -> 遇到什么阻力 -> 使用什么动作或语言策略 -> 收到什么反馈 -> 局势发生什么变化
```

无法回答且删除后不影响剧情的镜头必须删除或重写。对话镜头不能只做机械正反打；情感场景依靠视线、距离、动作和停顿；悬疑场景分别呈现线索、错误理解和揭示；动作场景保持空间、受力和结果连续。

## 运镜与镜头差异化

每个镜头先回答“观众为什么必须看这一镜”，再决定景别、机位和运动；删除后不影响目标、阻力、关系、信息、代价或情绪变化的镜头必须合并、改写或删除。运镜列不得只写运动名，必须写成“起点 -> 路径 -> 终点 -> 信息收益”，说明摄影机从哪里出发、跟随或离开谁、如何移动、停在哪里，以及观众因此获得什么新信息。人物移动也要写清靠近、远离、绕开、挡住、抢占、退让、追随或切断等关系变化。

每镜“运镜”列必须写明主运镜、方向、速度、焦点变化、进入状态和结束状态；只写“电影感”“镜头运动”“缓慢推进”视为未填写。建立空间可用远景/全景配横移、升降或克制摇镜；进入压力可用推近、手持贴跟或狭窄过肩；揭示线索可用焦点转移、视线匹配切或俯拍落到道具；权力翻转可用低机位、环绕或画面占比变化；追逐和失控可用手持、冲刺跟拍、甩镜或快切，但必须保持屏幕运动方向；情感选择可以克制固定或轻移，但停顿本身必须改变关系。

常用运镜必须按剧情职责选择，不是凑变化：

| 运镜 | 适合用途 | 执行写法要点 |
|---|---|---|
| 固定 | 对话、压迫停顿、喜剧反应、情绪积累 | 写清谁被困在画内，稳定被什么动作、台词或沉默打破 |
| 推近 | 逼近压力、强调线索、进入人物情绪 | 从哪个景别推到哪里，最终压到脸、手、道具还是威胁物 |
| 拉远 | 揭示环境、关系疏离、结尾余韵 | 从谁或什么物件拉开，新增什么空间、孤立或危险信息 |
| 横摇/竖摇 | 跟随视线、揭示新主体、展示高度 | 从什么主体摇到什么主体，新出现的信息是什么；无信息增量不得空扫 |
| 横移/侧移 | 展示人物与物体关系、制造遮挡切、延展空间 | 平行于谁移动，前景/背景依次揭示什么关系或障碍 |
| 跟拍 | 行走、追逐、行动目标推进、陪伴视角 | 从前跟、后跟还是侧跟，保持什么距离，人物奔向或逃离什么 |
| 手持 | 紧张、失控、冲突临场感 | 跟随哪个动作产生可控晃动，晃动如何服务危险或混乱 |
| 环绕 | 关系变化、权力翻转、主体亮相 | 绕谁、绕多少角度，画面占比如何改变，谁从被动变主动 |
| 升降 | 空间揭示、地位变化、规模感 | 从什么高度到什么高度，揭示什么空间层级或危险位置 |
| 焦点转移 | 线索揭示、信息差、视线关系 | 焦点从前景转向后景或反向，前后景对象和距离必须明确 |
| 变焦/希区柯克变焦 | 惊觉、眩晕、认知翻转 | 只用于单一明确高潮，说明主体尺寸和背景压缩/拉伸关系 |
| 甩镜/匹配剪辑 | 突发反应、场景跳转、动作接力 | 前后运动方向、形状或声音必须能匹配，不用模糊掩盖断裂 |
| 快切蒙太奇 | 时间压缩、准备过程、连续打击 | 每个短镜头提供不同结果，不用重复构图冒充节奏 |

短剧常用组合也要服务剧情：

| 剧情职责 | 可用组合 | 注意 |
|---|---|---|
| 快速钩子 | 异常细节特写 -> 主角反应 -> 危险或关系揭示 | 依次回答发生什么、谁受影响、矛盾在哪 |
| 对话交锋 | 双人中景建轴 -> 过肩或轻推 -> 反应特写 -> 权力方低机位近景 | 每次切镜对应策略变化，不做机械正反打 |
| 身份揭示/掉马 | 证据特写或焦点转移 -> 围观反应 -> 主角推近或半环绕 | 先展示证据，再展示认知和权力变化 |
| 悬疑发现 | 遮挡侧移 -> POV 看线索 -> 快推或变焦到反应 | 公平线索先出现，惊觉运镜只用一次 |
| 追逐/逃离 | 侧跟 -> 遮挡切 -> 低位冲刺跟拍 -> 拉升交代位置 | 保持屏幕方向，动作每段改变位置或优势 |
| 打斗/抢夺 | 全景建位 -> 手持起势 -> 接触特写 -> 反应中景 -> 结果全景 | 起势、接触、受力、结果分开，复杂连招拆镜 |
| 情感选择 | 固定双人中景 -> 视线或手部特写 -> 呼吸感轻推 -> 拉远 | 运镜克制，但每镜必须改变关系信息 |
| 信息压缩 | 道具/动作结果/时间变化快切 -> 匹配剪辑收束 | 每个短镜头必须给新信息，不用慢动作填充 |

先把每镜主运镜归入以下互斥家族：`static`、`axial`、`pan_tilt`、`lateral`、`tracking`、`orbit`、`vertical`、`handheld`、`optical_focus`、`montage`。`4-5` 镜片段默认至少使用 `2` 个家族，`6` 镜及以上默认至少使用 `3` 个家族；同一家族默认不得超过当前片段镜头数的 `50%`，`axial` 中推近与拉远合计也不得超过 `50%`。超过时填写 `camera_variety_exception_reason`，说明连续跟拍、一镜到底、克制对话或其他叙事原因。

即使比例合格，也禁止“所有镜头都从远到近或从近到远，只更换速度”的伪差异；至少一镜应改变摄影机路径或观察关系，如跟拍、横移、环绕、升降、手持、POV、焦点转移、遮挡切或匹配剪辑。每镜只选择一个主运镜；简单辅助运动必须与主运动先后发生、方向明确且不争夺控制权。复杂组合优先拆成相邻镜头序列，如“侧跟 -> 遮挡切 -> 半环绕正面”，避免短镜同时堆叠推、拉、摇、移、环绕。

采用 POV 第一人称时，写明所属角色、眼睛高度、视线方向，以及可见的手部、衣袖、伤痕或手持道具；POV 内不得出现该角色完整正脸，也不得混写为自拍、监控或过肩镜头。运镜词库只是决策候选，不是必选清单；生成后若实际运镜未发生、方向错误或退化成统一慢推，按镜头执行失败处理。

## 对白时长预算

每句台词在进入分镜前必须朗读估时，不能只按字数猜测。尚无最终音色时，可用目标语速试读或临时语音样本估算；音色资产完成后再复核一次。

```text
镜头时间预算 = 台词实际朗读时长 + 句前起势 + 句中自然停连 + 句后反应 + 必要动作时间
```

- 默认每个 SEG 至少安排一条可原生生成的人声，类型可以是出镜对白、旁白、画外音或内心独白；只有用户明确要求默剧、无声、纯音乐或无台词时，才允许整段没有 `speech_lines`，并记录用户原文。没有角色开口的画面仍应通过旁白、画外音、内心独白、呼吸、反应声、环境声或拟音承担声音叙事，不要做成无声空镜。
- 台词密度按朗读时长上限控制，不按句数下限堆叠。普通 SEG 的计划人声总朗读时长建议不超过片段时长的 `55%`；对话交锋、审问、告白、独白高潮等确需高密度人声的 SEG 也不得超过约 `70%`，其余时间必须留给表演、动作、反应、换气和剪辑。
- 语速按短剧场景动态调整，但必须有硬上限。中文台词只统计 `spoken_text` 中实际发声的汉字，标点、镜头描述、动作描述和画外音类型标注不计入字数：普通剧情、情感、悬疑、古风、品牌剧情化、旁白和抒情段建议 `2-4` 汉字/秒，硬上限 `4` 汉字/秒；追问、争吵、逃跑、喜剧反差、强压迫交锋等快节奏段建议 `3-5` 汉字/秒，硬上限 `5` 汉字/秒；告白、压抑威胁、病弱、哭腔、老年/儿童角色、重要揭示后的停顿段应主动低于普通上限。任何镜头或台词行都不得超过对应 profile 的硬上限，不得写“较快语速”“快速说完”“加速念完”等方式规避字数限制。
- 语速上限不是放慢剧情：当台词减少或拆短时，必须用角色行动、听者反应、证据特写、道具状态变化、空间调度、切镜、环境声、拟音或声音桥补足信息密度；不能把省出的时间变成无信息凝视、空镜或纯氛围拖延。快节奏段可以快，但必须听得清、看得懂、让关系或局势真实变化。
- 单句优先短而有钩子：中文出镜对白通常控制在 `6-18` 个汉字，旁白或内心独白通常控制在 `8-24` 个汉字；更长的句子优先拆成多镜、跨 SEG 或改成画外音覆盖动作空镜。不得为了塞完整台词要求模型加速朗读。
- 台词窗口必须容纳完整发声，并为开口前动作、换气、重音、对方反应和切镜留下时间。
- 避免机械匀速念稿：速度可以随策略变化，但不能靠全句加速挤进过短镜头。
- 人声必须始终清楚高于 BGM 和非关键环境声；重音词附近不得安排抢占听觉的强拟音。
- 台词超时优先拆分到相邻镜头或相邻 SEG、缩短非必要动作、改为画外音覆盖动作空镜，或回到规划/分镜延长片段；用户原台词不得擅自删字、改字或用同音字替换。
- 出镜对白、动作和反应的时间区间必须首尾相接；旁白、画外音和内心独白可以跨镜连续，但必须标明起止镜头，且画面人物不做对应口型。

### 叙事过渡、画外音与内心独白

- 旁白、画外音和内心独白由视频模型原生生成，文本放入 `{}`，明确声音主体、类型、情绪、起止时间及“画面人物不开口”。
- 可按剧情使用黑屏、短暂暗场、环境空镜、物件特写、声音先行或声音延续表现时间跳跃、记忆、章节转换和内心状态，但不是每段必用。
- 黑屏或暗场必须有明确职责和短时长，不能替代应拍摄的剧情。需要显示时间、地点、章节时使用画面文字 `“三年前”`、`“翌日清晨”`，不使用 `【】` 字幕通道。
- 同一句内容默认只走一个声音或剧情内文字通道：听见的人声用 `{}`；时间/章节文字用 `“”`；默认不生成逐句字幕，也不写入视频模型 Prompt。只有用户明确要求字幕时，才从已确认人声文本派生无标点 SRT 供成片阶段处理。

## 用户可见分镜阅读稿

`分镜_阅读稿_ep_N.md` 必须使用适合用户审查的顺序，不展示内部 JSON、哈希、字段名或校验结果。格式至少等价于：

```markdown
## 第X集：[可读标题]

### 本集故事提要
[用一段话说明本集主线、冲突、高潮和结尾钩子/落点]

### 第一章：[章节名]（本章时长：约90秒 / 00:00 - 01:30）
> 本章叙事功能：[世界观铺陈 / 冲突升级 / 反转兑现 / 高潮落点等]

#### 片段一：00:00 - 00:15（常规剪辑型，本段包含 8 个分镜）
- **镜头1 (00:00-00:01.0)**：[景别｜视角｜主运镜｜机位/角度] 给出第一个可见信息事件和动作发起。
- **镜头2 (00:01.0-00:02.0)**：[景别｜视角｜主运镜｜机位/角度] 用动作、视线或位置承接并给出第二个信息事件。
- **镜头3 (00:02.0-00:03.0)**：[景别｜视角｜主运镜｜机位/角度] 完成前 3 秒的第三个信息事件和观看关系变化。
- **镜头4 (00:03.0-00:05.0)**：[景别｜视角｜主运镜｜机位/角度] 写清动作过程、环境或对手反馈。
- **镜头5 (00:05.0-00:07.5)**：[景别｜视角｜主运镜｜机位/角度] 写清新的证据、反应或策略变化。
- **镜头6 (00:07.5-00:10.5)**：[景别｜视角｜主运镜｜机位/角度] 写清主重拍的触发、变化与反馈。

- **镜头8 (00:14.0-00:15.0)**：[景别｜视角｜主运镜｜机位/角度] 以稳定尾态留下下一片段可承接的动作、视线、物件、声音或情绪。
```

- 章节按照剧本的章节与场次映射排列，不能只写“第一章、第二章”的空标题。
- 默认每个片段写成 `00:00 - 00:15`、`00:15 - 00:30` 这类连续 15 秒段；尾段不足 15 秒或用户确认了其他模型上限时，写真实起止时间和原因。
- 每个片段必须按“动态镜头数量”列出足量分镜，镜头时间首尾相接并覆盖完整片段。
- 每个镜头行必须包含：镜头编号、绝对时间、景别、视角、主运镜、机位/角度、画面动作、声音、人声文本或“无”、切入/切出方式。
- 听得见的人声一律写成 `说话人：{原文}`，例如 `旁白：{门已经开了}`；音效用 `<具体声音>`；BGM 用 `()` 或 `（）`；标题、品牌字、时间地点等画面文字用中文引号 `“”`。字幕源使用 `【】`，只在用户明确要求字幕时登记，并明确不由视频模型渲染。
- 分镜阅读稿可以保留自然语言章名、片段名和故事提要，但不得省略完整镜头列表，不得用参数确认表的剧情预览替代正式分镜。

### 各列要求

- **场次**：稳定 ID 使用 `E{集号}S{场号}`，并保留剧本中的人读编号。
- **视频片段**：稳定 ID 使用 `SEG001`、`SEG002`；同一片段内镜头总时长不得超过所选模型上限。
- **镜号**：稳定 ID 使用 `E01S01-SHOT001`，末尾序号在当前场内连续、不重复、不跳号。
- **镜头职责**：写可验证的剪辑职责，不得写“推进剧情”“增强氛围”等空泛词。
- **时长**：写绝对起止时间和本镜持续秒数，与台词、动作、停顿和切点匹配。
- **画面描述**：写清主体、空间位置、朝向、视线、动作起点、轨迹、反馈、结果和剧情变化。
- **景别**：明确大特写、特写、近景、中景、全景、远景、大远景、过肩或 POV。
- **机位/角度**：明确摄影机高度、观察方向、主客观视角和镜头感。
- **光影氛围**：明确日夜、内外景、主辅光方向、色温、明暗层次、材质反射、天气和情绪效果。
- **对白·旁白**：写明说话人、声音类型和完整文本；用户文本逐字按原顺序保留。
- **音效**：环境声和拟音使用 `<具体声音>`，BGM 使用 `(具体音乐)`，写清进入、持续、淡出或承接时机。
- **运镜**：明确主运镜、方向、速度、焦点起落、切入原因和结束状态。
- **切入/切出动机**：由动作、视线、遮挡、物件、声音、反应、空间或信息变化驱动。
- **连续性要点**：记录屏幕位置、视线、轴线、动作方向、道具状态、光位、环境声和台词尾音。
- **抽帧/承接要求**：说明生成前关键帧目标和生成后实际抽帧时刻；两者不得互相覆盖。

|---|---|---:|---|---:|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 00:00-00:15 | 15s | E01S01-SHOT001 至 E01S01-SHOT008 | 8；`edited` | `high_density_short` / `cuttable_completion` | 完成钩子、误判和第一轮压力 | 逐条列出 SHOT001-SHOT008 的绝对时间、景别、机位、动作桥、切入触发、主运镜家族、运动路径、方向、速度、焦点起落、新增信息和切出落点 | 主角低头看手机，房间冷光 | 主角抬头看向门口，手机仍在手中 | 起始片段；生成后抽取场景锚点与尾帧 | 按真实输入路由：高光 KF + 出场 CHR + 当前 SCN/PROP/STYLE 必需图片；接口支持音频输入时再加已批准 VOICE；后续片段按 seam_mode 决定是否加入上一段视频和 tail FRM | 近景口型、手机文字、冷光稳定 |

每个非首段在“与上一片段衔接方法”中写入入段承接；每个非尾段在该片段尾状态和片段内镜头执行表的末镜切出落点中写入出段转场。二者必须来自同一个 `SEAMxxx`，不能各自发明转场。

### 视频参考输入计划

每个 `SEGxxx` 必须在 `storyboard_ep_N.json.segments[].reference_input_plan` 中写入视频阶段的图片输入计划数组。它不是最终 Prompt，也不是已传图证据；它用于提前规定“要传哪些图、按什么职责传、开头如何定位、哪些内容必须剥离”。数组可以为空，但只表示当前片段没有任何真实图片输入：首段可据此走 `text_to_video`；非首段仅当 planned `SEAM=elliptical`，且当前新起点不需要任何媒体锚点时才可为空。`continuous` 非首段必须规划上一段真实 tail FRM。视频阶段真实调用时仍以 `video_manifest_ep_N.json.reference_inputs` 和工具 schema 为准，但不得无理由删除分镜已列为必需的输入职责。

每条计划至少写：

```json
{
  "order": 1,
  "role": "previous_tail_as_start_frame|previous_scene_anchor_reference|previous_character_state_reference|previous_prop_state_reference|segment_highlight_reference|identity_reference|character_state_reference|scene_layout|prop_structure|prop_state_reference|style_reference",
  "planned_source": "KF001|FRM003|CHR001_v01|SCN001_v01|PROP001_v01|STYLE001_v01|用户素材 SRC001",
  "opening_binding": "[project-language binding for localized marker <图片1>/<IMG1> and its reference duty]",
  "adopt": "[project-language adopted subject, state, space, material, light, or style facts]",
  "exclude": "[project-language excluded subtitles, QR codes, watermarks, UI text, unrelated background, or unrelated people]",
  "required": true
}
```

- `order` 是计划顺序；视频阶段若工具实际上传顺序调整，必须同步改写最终 Prompt 的图片编号标记和 `reference_inputs[].order`，不能照搬旧编号。
- 第一段不规划生成式首帧关键帧；视频从已批准资产、已规划高光关键帧（若有）和文字动作合同启动，生成后再抽取真实 `start FRM` 作为事实记录。
- 非首段先读取对应 `SEAMxxx.seam_mode`。`continuous` 时必须把上一段已抽取、保存并登记的真实 `tail FRM` 作为 `previous_tail_as_start_frame` 并优先放在首位；tail FRM 缺失时停止下一段编译并先补齐，不得用上一段视频、其他帧或高光 KF 冒充。`elliptical` 时根据转场锚点和新起点选择当前场景、角色状态、道具或其他真实参考，不要求把上一段 tail FRM 当作 0 秒画面。
- 当前镜头或片段使用的角色状态、以及已升级为 PROP 且会复现的道具状态，必须提前解析到 `project_data_card.json` 的 `state_id` 和 approved 状态资产；查找范围包含共享资产库、本集 `episode_assets` 和其他分集已 approved 且在当前集登记为 `reused_episode_assets` 的资产。`reference_input_plan` 里用 `character_state_reference` 或 `prop_state_reference` 指向对应状态图，不能只写角色基准图、道具基准图再靠文字描述需复现状态。一次性道具状态只写入镜头动作和视频 Prompt 意图，不升级为 PROP 输入。
- 场景参考只锁空间、灯光、陈设和布局；风格参考只锁色彩、材质、光线、构图、景深和颗粒/线条语言，不承载剧情人物或道具；道具参考只锁结构、尺寸、材质、当前状态和可见面；不得把不同职责的图片混写成同一个主体。
- 任何用户或外部图片都必须写 `adopt/exclude`。图片中的字幕、二维码、水印、平台界面、无关人物、镜面文字和背景杂物默认剥离，除非用户明确要求保留且权限、剧情和平台风险均已确认。
### 关键帧需求决策

关键帧需求清单在分镜阶段完成，由主 Agent 根据已确认剧本、导演总控卡、十五列分镜、片段执行表和连续性账本决定。用户只确认可读分镜稿和镜头方案；确认后关键帧阶段按清单生成，不再临时挑普通画面代替。若关键帧阶段发现分镜选点缺少剧情峰值、缺状态资产或画面任务混杂，返回分镜或资产阶段修正。

关键帧按集规划而不是按 SEG 配额：每集固定总共 `3-4` 张，只落在观众必须看懂的高潮画面，例如证据露出、动作落点、关系反转、危险逼近或不可逆选择，不落在普通首帧、普通尾帧、角色展示或纯气氛镜头。未选中的 SEG 不补关键帧；多 SEG 项目中单个 SEG 通常 `0-1` 张，只有同段承载两个独立集级峰值时才允许 `2` 张；整集只有一个 SEG 时，该段承载本集全部 `3-4` 个互不重复的高光职责。第一段仍不额外生成首帧；`continuous` 非首段由上一段真实 tail FRM 承接，`elliptical` 非首段按已规划新起点开始。

优先生成关键帧的场景：

- 信息揭露、身份暴露、证据露出、文字证据可读、误会被推翻或观众认知改变。
- 角色做出不可逆选择、抢夺/推开/跪下/拔刀/按下发送等动作落点，或动作前一拍已经无法回头。
- 两人关系发生空间性变化：堵门、逼近、退到墙边、遮挡出口、夺走道具、站位高低翻转。
- 角色状态或已升级为 PROP 的道具状态会延续到后续片段：换装、受伤、血迹、开合、破损、易主、内容物露出、屏幕/信件/牌匾出现文字。一次性道具状态变化不触发资产补图。
- 多人同框、复杂遮挡、POV、过肩、镜面、门窗前后景、低光或强色温变化，视频容易漂移。
- 片段中后部承担悬念、危险逼近、声音桥或状态变化时，优先选择能让观众读懂结果和代价的高光瞬间；下一段承接仍以真实 tail FRM 为准。

通常不单独生成关键帧的场景：

- 删除后不影响剧情理解的纯氛围、纯运镜、纯场景展示或装饰性空镜。
- 只有“看向远方、低头沉思、站在原地”等弱动作，且没有新信息、道具状态或关系变化。
- 已由人物、场景、道具资产稳定覆盖的外观展示镜头。
- 可由视频 Prompt 稳定完成的简单动作过程，例如普通走路、坐下、转头、拿起杯子。
- 同一片段内重复的反应特写；除非第二次反应带来新的认知、选择或关系后果。

每张待生成关键帧在需求清单中写清：所属 `SEG` 和镜头、高光序号、准确时间点、单一戏剧任务、选择理由、画面焦点、主要人物屏幕位置和关系、必须传入的角色/状态/场景/道具/风格参考、画面内文字要求、从上一镜继承什么、给下一镜留下什么。画面任务不能同时塞入身份介绍、情绪展示、证据特写和动作高潮；冲突过多时增加第二张高光关键帧，或回到分镜拆镜。

### 片段内镜头执行表要求

逐片段另列“片段内时间 / 镜号 / 景别 / 机位 / 前镜状态 / 动作发起 / 运动路径 / 合理切点或镜内调度 / 后镜续接 / 接触或反馈 / 结果 / 新增信息 / 主运镜家族 / 焦点起落 / 切出落点”。它必须与完整分镜表一一对应，确保同一片段里的多个镜头不会在视频阶段被合并成一个长画面。

- 每个时间段首尾相接，总和严格等于该片段实际时长。
- 每个镜头都有切入触发和切出落点。
- 每个镜头的主运镜、景别、角度或焦点职责至少有一项与相邻镜头形成叙事差异。
- 每个片段至少有两个可观察的剧情状态变化；单镜片段按长镜头例外处理。
- 片段边界必须落在镜头结束处，下一片段从新镜头开始，不重复上一片段已完成动作。
- 主运镜不能只填“推近、拉远、镜头移动”。必须写清运动家族、摄影机路径、方向、速度、焦点起落和停止点，例如“侧向跟拍；摄影机在角色右侧平行向门口移动；中速；焦点由手中钥匙转到门锁；角色触锁时停在近景”。

## 导演总控卡的逐段执行区

在唯一 `导演总控卡_ep_N.md` 内逐片段填写以下执行区，不另建 `分镜_导演控制包.md`：

| 片段 | 戏剧目标 | 首态 | 尾态 | 镜头职责与删除损失 | 世界坐标/轴线 | 光源锁 | 声音交接 | 专项合同 |
|---|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 可观察的戏剧目标 | 片段开始的角色、道具、空间和声音状态 | 片段结束的角色、道具、空间和声音状态 | E01S01-SHOT001：删除后观众将不知道具体信息 | 轴线、人物屏幕侧、视线方向和摄影机活动区 | 光源来源、方向、色温和变化 | 台词尾音、环境声或 BGM 如何交接 | 无 / blocking_map / lighting_plan / action_ledger |

- **叙事节拍**：按下节记录钩子、欲望、阻力、策略变化、权力转折、代价、信息差和兑现/悬念，并绑定证据镜头。
- **片段可理解性**：每个 SEG 写 `viewer_takeaway` 和 `hook_landing`，前者说明观众看完本段知道的剧情事实，后者说明最后一拍形成的结果、危险、问题或继续观看理由；两者必须来自已确认剧本，不能在分镜阶段临时发明新剧情。
- **台词证据链**：把关键身份、指控、承诺、能力、秘密和判断绑定到前置来源、可见证据镜头及其剧情后果；角色撒谎或误判时明确标记。
- **场面调度**：双人以上交互、走位、遮挡、道具传递、追逐或打斗必须建立 `blocking_map`，用 T0/T1/T2 记录人物、道具、摄影机和 180 度轴。
- **布光**：复杂光线、昼夜切换、情绪转折或跨片段同场景必须建立 `lighting_plan`，每个光源写清来源、方向、色温、照亮区域和首尾连续性。
- **表演指导**：从导演总控卡继承本集表演总纲，再逐镜落实；同一镜有多角色时每个角色单独一行。

| 镜号 | 角色 | 表面策略 | 内在压力 | 情绪层次 | 微表情目标 | 肢体语言 | 呼吸节奏 | 禁止表演 |
|---|---|---|---|---|---|---|---|---|
| E01S01-SHOT003 | 林远 | 假装平静结束谈话 | 害怕承认自己仍在等待 | 克制的崩溃 | 眼眶红但不落泪，下颌短暂收紧 | 手指无意识攥住衣角，肩线不塌 | 呼吸变浅，回答前停一拍 | 嚎哭、持续瞪眼、夸张颤抖 |

逐镜声音必须能回指导演总控卡的三层环境声和 BGM 曲线；静默写清移除哪些声音、持续多久、结束触发是什么。逐镜色彩与光线必须回指色彩叙事合同的基准色或触发节点，不得只写“冷色高级感”。
- **动作账本**：打斗、追逐、抢夺、跌落、复杂接触或多人同步动作必须建立 `action_ledger`，按“起势 -> 位移 -> 接触/落空 -> 反应 -> 结果”拆拍；超出生成稳定性时拆镜或改用反应、遮挡、声音暗示。
- **剪辑动机**：每个切点必须由动作、视线、遮挡、物件、声音、反应、空间或信息变化驱动；“为了丰富镜头”不是动机。
- **片段内镜头执行表**：逐片段另列“片段内时间 / 镜号 / 动作桥 / 切入触发 / 主运镜 / 剧情变化 / 新增信息 / 切出落点”，确保分镜表中的每个镜头恰好一次编译进视频 Prompt，不遗漏、不重复，也不合并成无节点长镜头。

### 风格一致性检查

风格检查写入唯一 `导演总控卡_ep_N.md` 的逐段执行区，不增加第 16 列。逐场记录色彩、光影、构图/景别、镜头运动、标志机制和跨镜一致性，并绑定镜号及可见证据。只采用服务剧情的风格机制，不规定每集固定出现多少大师元素，也不能用统一慢推或死黑代替风格。

| 检查项 | 达标标准 |
|---|---|
| 色彩 | 场景主辅色与变化原因符合已确认风格 |
| 光影 | 光源有来源，方向、软硬和明暗层次明确 |
| 构图与景别 | 服务镜头职责，不机械重复同类特写 |
| 镜头运动 | 方向、速度和停止点符合风格与剧情 |
| 标志机制 | 有叙事作用才采用，不按固定数量凑元素 |
| 跨镜一致 | 可由文字合同和生成后场景锚点帧复核 |

## 开场、转场与角色表演控制

### 开场镜头合同

每集第一个可观看节拍必须把 `script_contract.opening_contract` 转译为镜头，而非只在台词或旁白中声明。第 1 集必须直接兑现规划 `OPEN001`；后续集可采用剧本中已解释的变体，但仍要在首镜建立与项目承诺的关系。开场类型只确定观众首先被什么抓住，仍必须服务人物目标、阻力和后续兑现：

| 主开场机制 | 首个可观察承诺 | 镜头设计重点 | 禁止替代 |
|---|---|---|---|
| 悬疑问题 | 可被看见的异常、缺口或未解问题 | 线索可读、视点克制、人物对异常作出行动或错误判断 | 用模糊滤镜、惊吓音效代替线索 |
| 世界观震撼 | 规则、尺度或秩序与人物处境的碰撞 | 奇观必须落到人物目标、代价或行动 | 只有空镜和设定说明 |
| 人物塑造 | 人物独有策略、习惯或失控裂缝 | 先让人物做选择，再解释背景 | 靠旁白贴标签 |
| 视觉奇观 | 一个无法被普通画面替代的视觉事件 | 构图、尺度、反应和后果连续出现 | 只展示漂亮场景 |
| 冲突驱动 | 双方目标立刻相撞 | 明确谁要什么、谁阻止、第一轮反馈是什么 | 无来源的争吵或突发事件 |

每个开场至少登记：首个时间范围、第一可见承诺、人物或世界的即时反应、升级触发，以及本集兑现或悬念延续的场次。把这些内容同步写入导演总控卡的 `opening_proof`：`opening_scene_id` 必须等于剧本合同的场次，`first_shot_id` 必须是该场次第一个承担开场职责的镜头，其余三项写明实际画面证据。短片不套固定秒数；按实际时长把开场作为首个完整叙事节拍。

`high_density_short` 的 `15` 秒视频必须执行黄金三秒规则。其他类型由首个完整叙事节拍建立问题、人物、奇观或冲突，不硬套三个事件。最终结尾必须完成结果、反应和落点；除已规划无缝 Loop 外，不得只是回到与开头相似的画面。

### 转场设计合同

转场是两个镜头或两个 SEG 之间的叙事动作，不是后期遮掩错误。每个 `SEAMxxx` 选一个主转场，必要时可附声音桥，但不能把多种无关技巧堆在同一切点。跨 SEG 转场必须采用“双锚单主导”：上一段尾部负责把画面送到可剪切状态，下一段开头负责从该状态迅速接入。由于相邻 SEG 实际上是分开独立生成，双侧 cue 都必须自洽写清画面、方向、速度、遮挡、动作相位和落点，不得写“同上”“相同”“保持上一段”“自然接上”等需要读取另一段 Prompt 才能理解的省略词。

分镜阶段必须先做一次 seam-first 设计，再定稿视频片段执行表：逐个边界判断它是 `continuous` 还是 `elliptical`，选择唯一主锚点，并写清出点动作相位与入点动作相位。连续边界优先使用上一段实际尾态可继承的动作、视线、道具接触、屏幕方向或遮挡物；省略边界优先使用相似构图、物件、声音或明确叙事动机。不要把“自然衔接”“后期看情况”写成转场策略。

| 转场类型 | 出点与入点必须匹配的锚点 | 适用场景 |
|---|---|---|
| 动作匹配 `action_match` | 同一动作相位、方向、速度或受力结果 | 连续行动、交接、反击 |
| 遮挡切 `occlusion_cut` | 前景遮挡物的方向、面积和解除时机 | 过门、掠物、人物交错 |
| 相似构图 `graphic_match` | 画面形状、主体位置、视觉重心或色块关系 | 时空跳跃、意义对照 |
| 甩镜同向 `whip_pan_match` | 同向运动、模糊强度和入画落点 | 失控、追逐、能量转移 |
| 视线/物件匹配 `eyeline_match|object_match` | 视线目标或道具形态、位置、接触关系 | 对话、线索、联想 |
| 声音桥 `sound_bridge` | 声音来源、进入/退出点和画面关系；台词尾音只写声尾性质，不复制完整台词；BGM 必须写可复用的乐器/节奏/音量/情绪职责 | 时间/空间转换、余韵；默认只辅助视觉转场 |
| 有动机硬切/叠化 `motivated_hard_cut|dissolve` | 明确的策略、信息或时间关系 | 不应伪装连续性的转场 |

衔接卡必须先选 `seam_mode`：`continuous` 用于同一行动、空间或无跳跃的时间推进，`elliptical` 用于明确的时间/空间/认知跳跃。再填写 `transition_anchor`、`outgoing_prompt_cue`、`incoming_prompt_pickup`、`required_invariants`、`permitted_deltas`、`proof_requirement`：分别说明匹配什么、上一段末镜如何把动作/运镜/声音送出、下一段 0 秒如何接住同一锚点、无论切法如何都不能变化的事实、计划允许变化的维度、要在首尾窗口中怎样核验。`continuous` 的 `permitted_deltas` 必须为空；`elliptical` 至少登记一项允许变化，且只验收不变量与计划变化的正确性。连续动作优先动作匹配、遮挡切或甩镜同向；跨时空优先相似构图、物件/声音匹配或有动机硬切。无法满足锚点时回到分镜；若视频已生成，则只记录返修建议，等待用户明确确认后再重生或编辑，不能让声音桥掩盖未允许的身份、动作相位或光位错误。

`outgoing_prompt_cue` 与 `incoming_prompt_pickup` 必须成对但不重复：前者写“上一段最后 0.5-2 秒发生什么出画、遮挡、甩动、视线、物件接触或声音延续”；后者写“下一段 0 秒从哪个屏幕边缘、哪种运动模糊、哪个遮挡物、哪个物件位置、哪个动作相位或哪个声音桥快速进入，并在 0.3-0.8 秒内落到本段新主体或新信息”。下一段开头不得再写一个新的转场名或完整重复上一段运镜，只能用可独立理解的具体画面接住该 `SEAMxxx` 的主锚点并继续剧情。衔接卡必须把摄影机运动方向转译成屏幕入画方向：例如上一段“向右甩镜至运动模糊，把门框遮满画面”，下一段应写“迅速从画面左边运动模糊和门框遮挡中接入，遮挡解除后停到新主体”，而不是只写“同向甩镜接上”。

方向必须拆开写清：摄影机运动方向、画面中模糊或遮挡物的流动方向、主体从哪一侧入画或出画、停在哪个景别和位置。不得只写“同向运动”。具体左右、上下、前后按该接缝实际画面设计填写，不套固定方向；若方向无法稳定判断，改用遮挡切、物件匹配、视线匹配或有动机硬切。

常见双锚写法：

| 主转场 | `outgoing_prompt_cue` 写什么 | `incoming_prompt_pickup` 写什么 |
|---|---|---|
| 动作匹配 | 动作切到未完成相位、方向、速度、受力点 | 从略微推进的相位开始，完成结果，不重做起势 |
| 遮挡切 | 哪个前景从哪侧进入、遮挡面积、遮满时机 | 从哪侧遮挡中开场，遮挡如何迅速解除并露出新主体 |
| 甩镜同向 | 摄影机甩动方向、模糊强度、切出前画面被什么吞没 | 从对应方向的运动模糊进入，短时间内停到新景别和新信息 |
| 相似构图 | 形状、主体位置、色块或视觉重心如何占满尾帧 | 以对应形状/色块/重心开场，并立刻揭示新时空或新意义 |
| 视线/物件匹配 | 视线目标或物件接触点在尾帧的位置 | 从目标物/接触点开场，说明看见者或持有者如何变化 |
| 声音桥 | 台词尾音、环境声、拟音或 BGM 的出点；台词尾音只写尾音性质和结束时机；BGM 只在剧情需要时写可复用的具体描述 | 声音从 0 秒继续，但只写非语义尾音、呼吸、环境声或拟音；BGM 逐字复用上一段描述，不把上一段完整台词再写一遍；画面动作仍要有具体入点 |
| 有动机硬切 | 上一段以明确结果、反应或信息落点收住 | 下一段快速建立新时空和变化原因，不伪装为连续动作 |

高风险边界必须预先设计桥接方案：当角色太多、同一动作难以由下一段 0 秒稳定承接、场景/光位跨度大、上一段尾帧无法作为真实图片输入，或预定为 `dissolve` 但当前成片工具只支持普通拼接时，增加 `1-2` 秒桥接镜头或独立 `bridge SEG`。真正重叠两侧画面的视觉转场会消耗两侧有效帧，叠加类光效或声音桥不改变主时间轴；分镜必须在 `duration_s` 和接缝卡中提前写清，不能到成片阶段用效果遮掩未设计的跳变。桥接镜头优先使用手部接触、门/墙/衣料/前景遮挡、关键道具特写、同向甩镜、视线目标或声音尾音；它必须承担剧情信息或情绪余波，不能只是空转场。

### 角色表演谱与情绪曲线

关键表演镜头在导演总控卡逐段执行区和 `performance_scores` 中使用时间段表演谱。先在 `performance_coverage` 声明哪些镜头必须有表演谱；确实没有关键表演时使用 `not_applicable` 并说明为什么。每拍使用相对镜头的 `start_ms/end_ms`，首尾连续、不重叠、不得超过该镜时长；内容按“发生原因 -> 基准状态 -> 人物策略 -> 可见脸部动作 -> 目光与身体 -> 声音/呼吸/停顿 -> 听者反应 -> 结束状态”编写；台词只在其触发或改变表演时出现。

| 时间段 | 发生原因/策略 | 基准状态 | 情绪状态与变化 | 可见脸部动作 | 目光与身体 | 声音/呼吸/停顿 | 台词触发 | 听者反应 | 结束状态 |
|---|---|---|---|---|---|---|---|---|---|
| 0-2 秒 | 听见意外称呼，先假装没听见 | 视线落在桌面，双唇自然闭合，肩线稳定 | 防御开始松动 | 嘴唇轻抿后松开，眉心短暂收紧 | 低头，视线避开对方，手指停在衣角 | 呼吸变轻，开口前停半拍 | 无 | 对方停住追问并观察她的手 | 视线准备回到对方 |
| 2-4 秒 | 对方继续逼问 | 视线准备回到对方 | 试探转为亲近或反击 | 眼神变软，嘴角只起极轻微弧度 | 偷看对方后微偏头，肩线轻收 | 声音略拖，句尾保留气息 | 说出关键台词 | 对方听到后收回逼近动作，视线转向她攥住衣角的手 | 维持可被下一镜继承的关系状态 |

- `cause` 必须来自台词、动作、道具、信息或对方反应，不能只写“情绪来了”。
- 每拍 `baseline_state` 写动作发生前观众能够看到或听到的状态；第一拍继承镜头入态，第二拍起必须逐字承接上一拍 `end_state`。变化太复杂时拆拍，不允许用“继续上一状态”绕过。
- 有明确听者、对手或共同在场角色时，`listener_response.mode` 使用 `covered`，逐人写 `character_id`、反应发生时机、可见反应和尾态；独白、无人回应或本拍确实不适用时使用 `not_applicable` 并写具体原因。听者不能只作为静止背景，反应应改变距离、视线、动作、认知或下一轮策略中的至少一项。
- 先写任何观众都看得见的脸部、目光、手势、姿势和呼吸，再按需要以 `AUxx + 1-5 强度 + 时机` 作为辅助校准。AU 不单独传意，不替代自然语言。使用 AU 时必须标为 `human|stylized_human` 且 `face_visibility: clear`；非人、遮脸、远景或无法辨认面部的镜头只写可见行为，不得伪造 AU 精度。
- 一拍只突出一个主要变化；复杂情绪拆成连续拍点。先用 `emotion_curve_coverage` 列出承担转折的角色，或写不适用原因；每条曲线写清 `character_id`、入场状态、压力来源、场次级触发、前后状态、可见证据、关系后果和尾态，分别与项目级曲线、场景攻防和 BGM 曲线对应，但不得让 BGM 或色调替代人物变化。
- 说话前的口唇、下颌、眉眼和身体预备应与语气一致；台词结束后的闭口、视线、呼吸或姿势也必须成为下一拍可继承的状态。

## 连续性账本与片段衔接卡

逐视频片段记录：

| 片段 | 时间范围 | 实际时长 | 首状态 | 尾状态 | 角色与造型 | 道具 | 场景/光线 | 动作趋势 | 声音承接 | 上一段抽帧与承接方法 |
|---|---|---:|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 00:00-00:12 | 12s | 完整写明 | 完整写明 | 脸部、发型、服装、伤痕、位置、朝向、视线 | 持有者、可见面、开合或破损状态 | 场景时间、天气、主光方向、色温、固定背景锚点 | 动作向量、速度、下一拍 | 台词尾音、环境声或 BGM 入点/出点 | 起始片段；生成后抽取 start/scene/tail，命中换装或复现道具时加 character_state/prop_state |
| SEG002（分镜02） | 00:12-00:24 | 12s | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | SEG001 连续性抽帧组中的 tail FRM 作为本段 0 秒首帧视觉基准；同场景/角色状态/道具延续时补 scene、character_state、prop_state FRM，并写动作匹配/遮挡切/甩镜/物件或视线匹配/明确省略剪辑 |

追踪角色身份/状态、服装伤痕、位置朝向、轴线、手持物、道具状态、场景光线、环境声和音乐。**“上一段抽帧与承接方法”列必填**：首段写抽帧计划；`continuous` 非首段写上一段连续性抽帧组如何作为真实图片输入，其中 tail FRM 是 0 秒首帧视觉基准，同场景/角色状态/道具延续时加 scene、character_state、prop_state FRM；`elliptical` 非首段写清时间/空间/认知跳跃、允许变化、新起点及转场锚点，不强制 tail FRM。若连续承接所选工具无法接收 tail FRM，必须改分段方案或返回用户重新选择可接收图片的工具方案，不得静默降级。

每个跨片段接缝必须建立唯一 `SEAMxxx` 片段衔接卡，显式写出“上一片段结尾状态 → 本片段 0 秒开场状态”，并记录：

1. 上一段计划尾态、本段 0 秒开场状态和相关高光 KF；实际 `tail/start/scene/character_state/prop_state FRM` ID 在视频生成后写入 `continuity_ep_N.json`，不得在分镜阶段伪造。
2. 上一段结尾与本段 0 秒开场的角色屏幕位置、姿势、身体朝向、视线方向及当前 `state_id`。
3. 道具持有者、可见面、开合/破损状态及手部接触点。
4. 主光方向、色温、曝光、SCN 场景版本和固定背景锚点。
5. 摄影机轴线侧、机位高度、景别、观察方向、镜头角度和运动家族。
6. 动作向量、速度、接触状态和动作相位；连续动作优先在动作进行到 `30%-70%` 时切出，下一段从同一相位或略微推进的位置切入，禁止动作重做或回弹。
7. 预定切法：动作匹配、视线匹配、物件匹配、遮挡切、相似构图、甩镜同向接入、叠化、声音桥或有动机硬切；不得写“自然衔接”或“后期看情况”。同时写转场锚点、允许变化和首尾帧窗口中的核验方式。
8. 上一段尾部检查窗口与下一段头部检查窗口，默认各 `12` 帧；视频阶段在两段生成后从窗口内选择并记录实际剪切点，成片阶段优先消费 verified cut，缺失时使用 best available cut，不直接按文件末帧和首帧拼接。
9. 原生人声尾音、环境声或 BGM 在切点前后如何延续，以及声音桥的入点/出点；BGM 只有剧情需要同一情绪或同一声源跨段时才使用，并写成可逐字复用的具体描述。
10. `outgoing_prompt_cue` 和 `incoming_prompt_pickup`：上一段最终 Prompt 结尾使用前者，下一段最终 Prompt 开头使用后者；两者必须共享同一 `transition_anchor`，禁止双转场、反向运镜或动作重复。

连续性账本为每个接缝追加：

```text
SEAM ID / 上一片段 / 下一片段 / 上一段计划尾态 / 本段 0 秒开场状态 / 相关高光 KF / 预定切法 / 转场锚点 / 出段 Prompt cue / 入段 Prompt pickup / 允许变化 / 核验要求 / 尾部窗口帧数 / 头部窗口帧数 / 动作相位 / 屏幕位置与方向 / 摄影机角度与运动 / 道具接触 / SCN 与轴线光位 / 声音桥 / fallback
```

若文字继承无法稳定保持同一画面，不追求伪像素连续；应把边界设计成遮挡切、甩镜、动作匹配、视线匹配、物件匹配、桥接镜头或明确换机位，让差异成为有动机的剪辑。分镜定稿前逐个接缝做“硬切预演”：如果按普通拼接直接相接会显得跳变，就必须修改出入点、增加桥接段或改为明确省略剪辑，不能把问题留给成片阶段。

## 参考资料与参考视频

分镜阶段接收用户图片、视频、脚本或风格参考时，先按 `manifests.md` 的 `source_manifest.json` 分类并写明采用什么、不采用什么；跨阶段冲突优先级仍按 `control-contracts.md`。

针对 Seedance 运镜模板类资料：

- 采用：逐镜“景别 + 机位 + 运镜 + 动作”的结构、跟拍/环绕/升降/手持/焦点转移/甩镜/匹配剪辑等候选，以及动作匹配切镜和接缝重复帧排查思路。
- 不采用：默认 `4K/60fps`、固定三秒定格、所有动作都缓慢、每句最多两种运镜等与当前工具 schema 或剧情职责冲突的模板；最终参数以实际工具能力和项目节奏为准。
- 组合名称不能直接复制成模糊 Prompt。必须拆为相邻镜头，或在模型已验证、路径简单时拆成同镜先后两段运动。

参考视频必须拆成六项可迁移导演信息：

```text
reference_structure：段落结构、信息顺序、切点逻辑
reference_pov：机位、景别、视角和观察者身份
reference_motion：主体动作、摄影机轨迹、速度和节奏
reference_emotion_arc：情绪起点、升级、翻转和回报
reference_audio_logic：台词、环境声、拟音、音乐和声音桥关系
reference_risk：需剥离的品牌、人物身份、字幕、口号、水印、平台 UI 和未授权内容
```

只迁移已声明的结构、视角、运动、情绪或声音机制，不复刻原人物、场景、品牌和文字。

## 与关键帧和视频阶段的边界

分镜阶段不生成关键帧、不写最终视频 Prompt，只提供关键帧可执行、视频可编译的事实：

- 稳定场次、镜头和片段 ID。
- 每镜画面、职责、时长、景别、机位、光影、对白、音效、运镜、切点动机、连续性和抽帧/承接要求。
- 每个 `SEGxxx` 的片段内镜头执行表、首尾状态、衔接方法、必需图片职责和预计输入素材类型。
- 人物、角色状态、主要场景、音色、道具状态、风格、关键帧需求清单，以及生成后的 FRM 抽帧计划；状态变化必须绑定已生成或待补生成的 approved 状态资产，不能只留文字状态。

关键帧阶段按已确认职责生成并验收图片；视频阶段再把分镜、资产和已规划 KF 编译成项目语言时间轴 Prompt。每个 SEG 必须具备可传入的当前角色/状态、场景、必要风格依据，以及已升级为 PROP 且本段需要复现的关键道具依据（若有）；只有被选为集级高光的 SEG 才必须具备可传入的高光 KF。这些依据可来自共享资产、本集资产或项目内其他分集已 approved 的复用资产。角色服装、妆发、伤痕、伪装、装具等状态与基准不同，或已升级为 PROP 的道具开合、破损、内容物、归属、可见面等状态与基准不同且会复现，必须在该 SEG 的参考计划中列出对应 approved 状态资产。一次性道具状态只进入镜头动作和 Prompt。非首段还要消费上一段已验收连续性抽帧组。人声必须写明主体、音色锚点、类型、逐字文本和发声窗口；出镜对白要求口型，其余人声要求画面人物不开口。

### 分镜内容人工复核

交付前由创作者逐项查看，不要求代码判断或填写固定报告模板：

| 评估维度 | 达标标准 |
|---|---|
| 镜头职责 | 删除后会损失明确剧情信息，否则合并或删除 |
| 开场承诺 | 第一个叙事节拍实际呈现开场问题、人物、奇观或冲突，并已绑定后续兑现 |
| 运镜差异 | 多镜片段通过运镜家族分布检查；推/拉不支配大多数镜头；重复时有连续性理由 |
| 运镜家族统计 | 逐 SEG 记录各家族计划镜头数和占比，生成后再记录实际值与偏差 |
| 切点动机 | 每个切点都有动作、视线、遮挡、声音、反应、空间或信息触发 |
| 连续性 | 轴线、视线、动作、道具、光位和场景拓扑无冲突 |
| 信息密度 | 持续产生行动、反馈、关系、线索或情绪变化，不按固定秒数打点 |
| 风格落地 | 能指出色彩、光影、构图、材质和运镜的证据镜号；STYLE001 只作为视觉语言参考，不引入剧情人物或道具 |
| 表演层次 | 核心角色逐镜具有基准态、表面策略、内在压力、微表情、肢体、呼吸和尾态；有听者时反应可见，且不依赖夸张表演传意 |
| 情绪曲线 | 关键角色的触发、可见表演变化、关系后果和尾态与场景攻防一致 |
| 转场策略 | 每个 SEG 接缝的主转场、锚点、允许变化和帧窗口核验要求明确 |
| 声音叙事 | 三层环境声、BGM 曲线、静默和声音桥均有入点、出点及剧情职责 |
| 色彩叙事 | 主辅色、色温/对比、主体分离和色调偏移有触发节点，并与人物认知或关系变化一致 |
| 可生成性 | 复杂动作、多人同框和长镜有拆镜或降级方案 |
| 抽帧承接 | 每个 SEG 有 start/scene/tail 计划；命中换装、妆发/伤痕/伪装变化或复现道具状态变化时加 character_state/prop_state 计划；每个相邻 SEG 有 SEAM 接缝合同、双侧帧窗口和明确切法 |

每项填写“通过/不通过/存疑、证据镜号、修改建议”。镜头职责、时间轴、连续性或可生成性失败时阻断进入关键帧阶段。

## 存储与阶段确认

本阶段产物统一进入当前 `ep_N` 的分镜目录；路径、命名和 `storyboard_ep_N.json` schema 只读取 `manifests.md`。

完整模式落盘前检查：

- 当前确认范围内全部剧本场次和剧情均已进入分镜表。
- 导演总控卡可追溯到关系矩阵、镜号或剧情触发点。
- 十五列分镜表完整，时间戳连续，总时长正确，片段时长不超过模型上限。
- 每镜有职责、切入/切出动机、连续性、抽帧/承接要求、主运镜和可见状态变化；相邻镜头有叙事性差异。
- 核心表演镜头有原因、基准态、可见动作、目光/身体、声音/停顿、听者反应和尾态；声音与色彩符合本集总合同。
- 出镜对白、旁白、画外音和内心独白均绑定镜头、声音主体、类型与发声窗口；用户原台词逐字、按原顺序进入对应镜头。
- 片段执行表与分镜表一一对应；镜头密度、运镜分布、长镜例外和复杂调度均已按本文件检查。
- `storyboard_ep_N.json` 顶层必须写入 `schema_version`、`episode_id`、`revision`、`project_data_card_revision`、`source_markdown`、`duration_s`、`shots`、`segments` 和 `seams`；`source_sha256` 可保留为恢复辅助，不作为轻量检查硬门。`shots` 和 `segments` 必须是非空数组，`shots` 不得用镜头总数数字代替。
- 每个相邻片段都有 planned SEAM，包含主转场、转场锚点、允许变化、核验窗口和必需抽帧承接。
- 关键帧需求清单只引用已确认人物、角色状态、主要场景、音色、道具状态和全局风格资产，且与数据卡稳定 ID、状态和 revision 一致；需要状态版而尚无 approved 状态资产时，返回资产阶段补齐。

将分镜阶段及目标分集状态写为 `awaiting_confirmation`，运行内部结构检查；存在问题时先修复，不单独输出阶段报告。通过后向用户提供全部可审查的分镜类用户可见 Markdown 文件，每个文件配一句简短说明，并在聊天中简要输出镜头方案摘要；文件链接使用真实可访问路径，链接范围仅限用户可见分镜稿。不得在聊天说明中展开或点名内部执行技术、代码逻辑、机器字段、自动检查原文、连续性账本、片段衔接卡、导演总控卡内部执行区、关键帧需求清单、结构化索引、哈希或任何内部文件，并按 `language_contract.output_language` 使用不固定但语义完整的确认句：请用户确认分镜是否需要修改；需要修改则直接指出；确认无误则用明确肯定回复；收到确认后才开始生成关键帧。确认句要礼貌清晰，避免每阶段重复同一句模板。

轻量模式只检查内部完整分镜表存在十五列、每镜各列非空、时间连续且总时长等于规划值；通过后直接进入 Prompt 编译，不展示分镜、不写 `awaiting_confirmation`、不等待分镜确认。

收到修改意见时只修订分镜。改变镜头职责、时间轴、轴线、接缝或大范围执行合同的重大修改重新提供完整受影响文件；局部文字或单镜微调只提供修改文件、修改前后和影响范围。只有用户明确确认后才进入 `keyframes.md`。
