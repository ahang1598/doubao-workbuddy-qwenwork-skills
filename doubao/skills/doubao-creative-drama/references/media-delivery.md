# 媒体交付

mainagent 根据工具真实返回的结果类型，按[制作入口的交付规则](../SKILL.md#richmediacard-交付规则)逐项交付，不按短链外观判断媒体类型。需要展示的图片和视频，包括图片/视频候选、各集片段和最终成片，结果就绪后立即各发一张 RichMediaCard；一张卡片的 `refs` 只放该项一个真实图片或视频引用，不把多张图片、多个视频或音频合进同一张卡片，不等整组、同批其他结果或后期完成。短链、URL或句柄必须来自该项真实结果且能供卡片消费，不编造引用，也不拿音频短链当作图片或视频引用。标签、JSON及排版严格使用入口的完整格式，不自行改名或添加前缀。

音频（含角色音色样音）单独使用宿主实际支持的音频/文件交付入口，例如工具已返回的可播放音频附件或正式文件交付能力生成的真实文件入口，供用户播放或下载。按该能力的实际 schema 使用真实音频资源或文件，不猜工具名、字段或文件地址，不把音频写入 RichMediaCard 的 `refs`，也不把“音色已就绪”“可试听”等文字或仅有内部路径当作音频交付。展示供用户试听不要求 Agent 自行播放或检查音频。文档和用户明确要求的 Prompt 沿用原文件入口规则。

subagent 只逐项回传，mainagent 逐项交付；取消结果、失败和阻塞均由 mainagent 说明。视频取消成功或用户明确不再接收该任务结果时，按 `delegation.md` 停止对应交付，其他任务不受影响。轻量模式和完整模式一致。成片目标先交片段，完成已定拼接、字幕或混音后再交最终成片。同一结果兼作最终版时只展示一次，每项可附简短自然说明。

交付状态采用宿主已有的真实展示反馈：已输出标签或发起文件交付，不等于已成功展示。没有展示反馈时，仅记录已发出、展示结果未确认，不声称已成功渲染，不重复发送，也不为此新增用户确认、播放、试听或媒体质检。已成功展示的同一结果不重复交付，用户明确要求回看时按原规则处理。

结果缺失、标签以普通文本显示或宿主明确报告卡片/文件入口展示失败时，说明受影响的交付项并保留真实状态。恢复交付时复用原真实结果，只修复该项格式、资源引用或原交付操作，遵守原有适用修复次数，不重新生成、不修改媒体内容、不新增生成确认。缺少对应展示能力或可用音频/文件入口时说明具体阻塞并保留结果，不伪造卡片或文件入口，不把未渲染标签、裸链接或内部路径当作交付成功。
