# 剧本创作 Ref

本文件是剧本因果、证据链、格式和内容验收的唯一权威。开始前读取 `planning.md` 的已确认方案、`control-contracts.md` 的状态规则、`manifests.md` 的剧本/Data Card 字段和 `剧作方法与类型库.md` 的故事引擎、类型合同与改稿流程；共享资产检查点在正文对应位置读取 `assets.md`，镜头工作交给 `storyboard.md`，创作候选库按需读取。

## 权威引用

- 已确认规划及参数：`planning.md`。
- 目录、命名、剧本 manifest 和数据卡 schema：`manifests.md`。
- 共享标准资产检查点：`assets.md`；后续镜头化：`storyboard.md`。
- 故事引擎、关系矩阵、信息账本、场景攻防、类型规律和分轮改稿：`剧作方法与类型库.md`。
- 短剧化变体、题材亮点与传播弹药读取 `题材亮点与传播库.md`；受众和视觉机制候选按需读取对应参考库；跨阶段状态与失效读取 `control-contracts.md`。

## 输入门禁

必须存在已经通过 `drama_lint.py --stage planning` 且经用户确认的：

- `00_制作控制/drama_plan.json` 内容完整，且 `制作状态.json.phases.planning == confirmed`。
- `00_制作控制/project_manifest.json`、`source_manifest.json` 及当前 `episodes/ep_N/episode_manifest_ep_N.json` 已按 `manifests.md` 建立。
- `用户确认记录.jsonl` 存在当前 `drama_plan.json.revision` 的规划确认记录。参数确认正文已按 `planning.md` 在当前对话中直接展示，不依赖 Markdown 文件。

剧本必须继承规划中的目标、事实锁、唯一主机制与辅助机制、核心卖点、类型策略、亮点策略、风格合同、情绪设计、节奏波形、规模和风险，不得自行更换受众、平台、画幅、模型、故事发动机或创意主路径。规划存在 `pending` 且会改变剧情意义、权限、成本或交付规模时返回规划阶段，不得直接补写。

没有完整参数确认、用户只选择了方向但未确认其余参数，或已确认计划仍缺生图/视频模型、集数、时长及适用的会员模型提示时，禁止开始写剧情梗概、人物小传、场景清单或完整剧本。

## 边界

承接短篇短剧、微电影、剧情短片、动画短片、单条剧情短视频，以及具备完整"目标→阻力→策略→反馈→变化"因果链的剧情宣传片、剧情预告片和广告剧情；纯商品转化广告、品牌价值观 TVC、企业宣传或真人对镜口播不属于本 Skill。也可承接多单元、几十集和跨集主线的长篇完整剧本。常规多集短剧单集通常为 1-3 分钟，极短集支持 15-60 秒；微电影通常为 5-10 分钟。最终时长必须结合用户指令与剧本容量确定；超过 10 集时须声明长篇漂移风险，先锁全局故事、全部分集推进和结局，再逐集写详细剧本并复核。

## AI 生成可拍性合同

> 本 Skill 服务真人质感 AI 短剧、动画、漫剧、微电影和其他剧情视频。AI 生成有技术边界，剧本阶段必须主动降低风险，但不得用“模型不擅长”为理由把所有动作改成慢动作、静止画面或纯对白。

### AI 生成的七大限制与剧本应对

| AI 的限制                    | 剧本阶段的应对策略                                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **微表情有限**         | 关键意义不能只依赖细微表情；用动作、距离、视线、道具状态和结果反馈补足。微表情可加强情绪，但不能单独承担反转                          |
| **复杂动作易失真**     | 把动作拆成"起势→接触→受力→结果→反应"的短动作链；只有中间过程无法稳定生成时才用声音或剪辑省略，禁止默认改成慢动作填时长            |
| **多人互动易错位**     | 明确当前主行动者、关系轴线和每个主体的反馈；按镜头复杂度拆成单人策略、对手反应与群体后果，不机械规定固定人数                          |
| **口型同步有误差**     | 台词不要太密集（避免机关枪式快嘴）；关键金句单独成句，给口型足够时间；少用生僻字、绕口令、外语；长台词拆成短句，中间插入动作/反应镜头 |
| **场景/道具一致性差**  | 核心道具和场景在项目数据卡中精确锁定；分集只引用稳定 ID 和当前状态，并补本场动作与位置增量                                            |
| **留白可能退化为静止** | 留白仍要有呼吸、视线、手部、道具、环境光或环境声变化，并在结束时改变认知、关系或情绪距离                                              |
| **渲染可能缺少质感**   | 从已确认风格出发设计主光方向、明暗层次、材质和色彩关系；不得为了“掩盖塑料感”把所有项目统一改成暗调                                  |

### 风格处理

本文件不维护导演、作品或动画流派清单。用户指定风格，或项目需要建立视觉锚点时，按需读取 `电影大师风格库.md`，把风格拆成可观察的光线、色彩、构图、材质和节奏机制；不得默认用暗调、慢推或特写掩盖生成问题。

### AI 短剧的可拍性红线（动笔前检查）

写完每一场戏后，快速检查是否触碰以下红线，触碰则改写：

- □ 多主体都在同时执行关键动作？→ 明确主行动者并拆分策略与反应
- □ 有复杂动作（打斗/舞蹈/跑酷）？→ 拆成短动作链，逐段明确空间与结果
- □ 留白没有任何可观察变化？→ 加入呼吸、道具、光线或环境声变化
- □ 台词密集到没有呼吸？→ 拆成短句，插入动作/反应
- □ 核心道具/场景描述模糊？→ 精确描述颜色、材质、布局
- □ 依赖微妙表情传递关键信息？→ 改用动作、台词、旁白或特写

## 双层剧本结构

完整模式项目必须同时存在两层剧本，不能用其中一层替代另一层。轻量模式不建立独立剧本文件，其剧情因果、动作和台词直接进入已确认预览后的内部完整分镜，不适用本节文件硬门：

1. **项目级完整全面剧本**：保存于根目录 `01_剧本/剧本_全剧完整剧本.md`。它不需要复写每句对白和每个细动作，但必须从开端写到最终结局，完整覆盖主线、人物弧、分集/段落因果、主要场景序列、关键行动、核心台词意图、伏笔埋设与回收、高潮兑现和最终状态。禁止只写题材介绍、世界观、人物设定或一句话分集大纲。
2. **分集详细完整剧本**：保存于 `episodes/ep_N/01_剧本/`。每集必须把总览中的本集内容细化为可直接进入分镜的全部场次、动作节点、对白、旁白、声音职责、状态变化和集间承接，不得擅自改变全剧总览的核心因果与结局。

单条短片、微电影和单部长视频同样创建项目级完整剧本；其 `ep_1` 详细剧本负责补齐逐场动作、全部对白和声音执行。项目级剧本负责完整理解，`ep_1` 负责直接制作，职责不同。

全局故事圣经与分集推进总纲合并保存为 `01_剧本/剧本_全局设定与分集总纲.md`，不得再分别生成 `剧本_全局故事圣经.md` 或 `剧本_分集推进总纲.md`。合并文件固定包含两个一级章节：

1. **全局故事圣经**：世界观、故事规则、人物与关系、主线问题、人物弧、关键伏笔、揭示顺序、结局和不可破坏的因果链。
2. **分集推进总纲**：按全部集数依次写每集目标、阻力、策略变化、核心事件、转折、阶段兑现、结尾状态和下一集钩子；单集项目保留 `ep_1` 一行。

两章可以在同一次修改中一起更新，但必须保持标题和边界清楚。全局设定变化时复核全部分集行；局部分集调整时复核其前后承接，不把两个章节压成一段混合摘要。

项目级剧本包必须先完成并确认，内容包括全局故事圣经、全部分集推进总纲、完整主线、人物弧、伏笔账本、最终结局和 `00_制作控制/project_data_card.json` 的跨集基线。它必须覆盖全部集数，但不提前写各集逐场动作与完整台词。项目级确认后才进入 `ep_1` 详细剧本；每集详细剧本只在该集开始制作时生成并单独确认，确认后完成本集资产、分镜、关键帧、视频和成片，再进入下一集详细剧本。关键帧必须等待当前集资产与详细分镜分别确认后生成。

## 目标

先把用户创意转化为稳定的全剧故事、项目数据卡和逐集推进合同；随后在当前集开始制作时，把该集细化为可直接进入分镜的完整剧本。

正式交付必须结合用户本轮指令、已提供素材、后续修改和已确认设定生成完整、具体内容。不得只给方法、模板、提纲或示例；不得在正式剧本中出现"略、此处略、后续依此展开、待补充、TBD、XXX、1-N、占位符"等未完成内容。项目级故事包必须完整覆盖当前确认的全部集数与最终结局；进入某集详细创作后，该集每一场、每个动作节点和全部应发声台词都必须实际写出，使下游可以不补写剧情就直接制作完整分镜表。不得把“覆盖全部分集推进”误解为在项目级阶段提前批量写完所有分集详细剧本。

动笔前先按 `control-contracts.md` 建立项目级 `01_剧本/项目_事实与假设.md`，逐字保存用户核心要求和限制，并将已验证事实、未知项、推进假设、项目惯例分栏。仅某一集成立的假设写入对应 `script_contract_ep_N.json` 的来源字段，不重复建立多份事实锁。

剧本阶段必须继承规划阶段已经向用户展示并确认的 `selected_direction_id`，不得重新暗中替换方向。若写作时发现所选方向存在无法闭合的因果、授权或可生成性问题，返回规划阶段更新候选与选择理由，不在剧本阶段另起一套未确认方案。

每场戏必须形成"角色目标 -> 现实阻力 -> 采取策略 -> 对方反应或环境反馈 -> 局势变化"。场景结束时至少改变权力关系、人物认知、情感距离、危险程度、目标难度、关键线索或道具归属中的一项；开场与结尾状态相同且没有新增有效信息的场景必须删除或重写。

每场正文定稿后，从 Markdown 与项目数据卡编译 `script_contract_ep_N.json.scenes[]` 的 `entry_goal`、`tactic`、`countermove`、`turn` 和 `exit_value`。Markdown 是创作正文权威，JSON 是派生执行合同；修改正文后必须重新编译来源哈希和受影响场次，禁止人工维护两套互相独立的剧情。对白、动作和场面调度只能是这场攻防的外在执行，不得先写“漂亮对白”再反推剧情用途。

剧本中的关键事实必须建立"台词证据链"。凡是会改变人物判断或剧情走向的身份、指控、承诺、能力、秘密、规则和结论，都要登记：

```text
台词声明 -> 事实来源或前置铺垫 -> 可见画面/动作/道具/结果 -> 揭示场次 -> 对局势的后果
```

- 不能只让角色说"他背叛了我""我有证据""我是负责人"就视为剧情成立；后续必须让观众看见证据或看见该判断造成的可观察后果。
- 角色可以撒谎、误判或隐瞒，但剧本要区分"角色所信"和"故事事实"，并规划公平线索或后续验证。
- 同一事实重复解释而没有新证据、新策略或新后果时，删除重复台词。
- 涉及真实品牌、人物、IP、地点或时效事实时，证据链来源必须是用户资料或可靠检索结果；未核实内容只能写成虚构设定、角色观点或待确认项。

本阶段不写逐镜头分镜，逐镜头规划由 `storyboard.md` 处理；但剧本必须完整到足以逐场转换，不得把剧情创作责任留给分镜阶段。

**完整模式必须先产出并确认 1 套项目级完整故事包和 1 份内部项目数据卡；每集进入制作时，再产出该集 1 份机器合同和 5 份分集创作产物。最终全部分集仍缺一不可，但禁止在项目级确认前批量提前写完。轻量模式不创建项目数据卡或独立剧本产物，只在规划确认后内部扩充十五列完整分镜。**

项目级固定文件为：内部 `项目_事实与假设.md`、用户可读的 `项目设定卡.md`、`剧本_全局设定与分集总纲.md`、`剧本_全剧完整剧本.md` 和内部 `project_script_manifest.json`。原“剧情梗概、人物小传、主要故事场景”不再分别生成独立项目文件，统一作为 `剧本_全局设定与分集总纲.md` 中“全局故事圣经”章节的固定子章节。

### 项目数据卡

完成项目级完整剧本后，立即按 `manifests.md` 创建 `00_制作控制/project_data_card.json`。它不是人物小传的摘要，而是所有下游阶段共同读取的结构化事实源：

- `global_settings`：项目名称、风格资产 ID、比例、总集数、逐集时长和字幕样式。
- `characters[].identity_locked`：角色类型、年龄阶段、脸型/五官/肤色或物种表面、痣/疤痕等身份标志、身高体型和固定 `voice_id`。
- `characters[].state_timeline`：服装、发型、妆容、伤痕和表面状态的初始值及每次变更；每条写生效场次、结束范围、剧情原因和新状态。
- `scenes[]`：主要场景稳定布局、门窗朝向、固定家具、基础光源、`3-5` 个可见且可核对的一致性锚点，以及由真实剧情触发的布置/灯光状态变化；不预制剧本没有使用的昼夜版本。
- `props[]`：核心道具不可变外观、尺度类别与参照、逐场剧情功能，以及位置、归属、开合、内容物、破损和完整性状态变化。
- `voices[]`：每个出镜角色、画外角色和叙述者的固定音色描述及资产 ID。

角色面部身份、身高体型和音色默认全剧不可变。服装、发型、妆容和表情可以变化，但必须由剧情、时间跳跃或明确造型动作触发；同一 SEG 内没有对应镜头时不得突然变化。分集剧本只引用稳定 ID 和当前 `state_id`，不得重新发明角色、场景、道具或音色基础设定。

`01_剧本/项目设定卡.md` 必须从当前 `project_data_card.json` 和已确认全局剧本生成，只展示用户需要审查的世界观、人物关系、主要场景、关键道具、声音主体、视觉方向和禁用项。数据卡是机器事实源，设定卡是用户可读投影；修改设定卡中的事实时必须先更新数据卡及受影响剧本，禁止两份内容各自维护。

每集固定文件为：

1. **分集梗概**：本集目标、阻力、策略变化、高潮、结果和下一钩子。
2. **分集人物状态**：本集开场/结尾的关系、认知、服装、伤痕、道具归属和待延续状态。
3. **人物关系张力矩阵**：每对核心关系的权力差、信息差、情感差，以及本集变化节点和场面调度含义。
4. **分集主要场景**：本集实际使用的场景、功能、人物进入/离开与状态变化。
5. **详细完整剧本**：包含全部场次、时间/内外景、人物、动作提示、对白、旁白、画外音、内心独白、情绪节拍和结果。

对应文件为 `剧本_分集梗概_ep_N.md`、`剧本_分集人物状态_ep_N.md`、`剧本_人物关系张力矩阵_ep_N.md`、`剧本_分集主要场景_ep_N.md`、`剧本_完整剧本_ep_N.md` 和 `script_contract_ep_N.json`。关系矩阵格式与更新规则读取 `剧作方法与类型库.md`；每一个关系变化必须能回指具体场次。分集创作只引用已确认项目级故事包和数据卡中的稳定 ID、人物弧、伏笔与本集目标，不得改写最终结局，也不得假定尚未生成的资产文件或 approved 版本。

| ----------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| `剧作方法与类型库.md` | 建立故事引擎、关系矩阵、信息账本、场景攻防、执行改稿，或确定主/子类型与混合职责 | 写作与七轮改稿方法、类型规律、冲突发动机、必要场面和结局义务 | 用户事实、已确认方向、完整因果和已确认结局                       |
| `题材亮点与传播库.md` | 需要创意发散、短剧化变体、题材发动机、亮点、钩子、反转、传播句或节拍候选        | 呈现类别写法、故事发动机、亮点组合、可替换骨架和情绪曲线     | 用户事实、完整因果、人物口吻、类型结局义务与自然时长             |
| `题材受众库.md`       | 用户未明确受众、平台或市场方向，或明确要求平台适配                              | 受众心理假设、题材与情绪方向、待核实的平台差异               | 实时事实、用户画像、法律结论、改变默认字幕烧录策略或自动开启 BGM |
| `电影大师风格库.md`   | 用户指定风格，或项目需要建立视觉锚点、诊断风格漂移                              | 光线、色彩、构图、材质、声音和节奏机制                       | 剧情、镜头职责、人物身份、资产版本、最终 Prompt 语法             |

优先级统一服从 `control-contracts.md`：系统、安全、合规、授权、真实性、工具硬限制 > 用户最新确认 > 已确认素材与事实 > 默认创意规则。主体、动作、场景、风格、时长、比例、镜头方式、台词和禁止项一旦被用户锁定，剧本不得改写；新增台词、细节和情节只能填补未锁定空间并服务整部作品。候选库互相冲突时不混用，返回唯一主机制选择最小充分策略。

实际采用的受众假设、类型路径、风格机制和全剧信息差账本追加到 `01_剧本/项目_事实与假设.md` 的“策略选择”附录；每集独有的信息差和状态变化写入 `剧本_分集梗概_ep_N.md`。不把未采用的候选整包写入正式交付。

## 单集创作卡

写每集前填写一张创作卡。字段用于内部设计和复核，不要求正式剧本机械显示这些标题：

| 字段                 | 必须回答                                                                                                                                                                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心戏剧问题         | 主角这一集必须解决或推进什么                                                                                                                                                                                                                        |
| 故事引擎             | 欲望、阻力、失败代价、不可逆选择和本集兑现如何持续制造行动                                                                                                                                                                                          |
| 开场状态与钩子       | 绑定`opening_strategy.opening_id`。第 1 集直接继承主/辅机制、首节拍、可见承诺、升级和兑现；后续集可写强化、反转或更新型变体，但必须说明变体理由以及如何延续项目承诺。写初始局势、第一可见承诺、具体异常或冲突、升级触发，以及兑现或悬念延续的位置 |
| 主角目标、时限与代价 | 主角主动争取什么，失败会失去什么                                                                                                                                                                                                                    |
| 对立目标与资源       | 谁或什么形成阻力，为什么阻止主角                                                                                                                                                                                                                    |
| 信息差与证据         | 观众、主角、对手各知道什么，公平线索在哪里                                                                                                                                                                                                          |
| 策略与权力变化       | 旧策略如何失效，新策略如何改变局势                                                                                                                                                                                                                  |
| 情绪推进与回报       | 压力、关系或认知如何变化，最终兑现什么情绪                                                                                                                                                                                                          |
| 人物外壳、内核与执念 | 公开形象保护什么恐惧或渴望，什么信念驱动重复选择                                                                                                                                                                                                    |
| 母题与视听意图       | 关键道具、动作、色彩和声音如何改变意义                                                                                                                                                                                                              |
| 高潮、结果与下一问题 | 当前问题如何回答，角色如何反应；连续剧再建立下一问题                                                                                                                                                                                                |
| 可传播台词或等价母题 | 放在高潮或反转位置；写清由哪个情境、选择和代价支撑，非语言作品写视觉/声音母题                                                                                                                                                                       |
| 可拍性风险           | 复杂动作、多人同框、微表情、长台词、场景和道具风险及处理方式                                                                                                                                                                                        |

钩子必须服务主线并登记兑现；关键信息遵循“埋设 → 发酵 → 揭示 → 后果”；人物弧遵循“旧策略失效 → 承担代价 → 新选择 → 局势改变”。商业对话型短剧每集至少一句可传播台词，优先放在高潮或反转位置；沉默戏、幼儿内容或自然主义作品可用视觉/声音母题等价承担。高潮和结局必须由前文规则与人物选择造成，不靠巧合、临时设定或强制模板。

填不出目标、阻力、策略、反馈、变化或证据链时，不得用氛围、金句、镜头效果或新增设定代替剧情。完成后把对应字段写入 `script_contract_ep_N.json` 和分集梗概，字段结构读取 `manifests.md`。

## 视觉叙事、母题与声音意图

剧本可登记道具、环境、服装、色彩、动作、台词和声音母题，要求每次出现都改变状态或意义。需要具体风格时读取 `电影大师风格库.md`，但剧本只写叙事意图。

## 画幅与竖屏写作意图

只有确认竖屏时才考虑单一视觉焦点、纵向高低关系和边缘安全；横屏继续使用横向空间、群像和环境关系。字幕、机位、运镜、布光和转场不在本阶段定稿。

## 类型变体与差异化生成

只从已确认 `drama_plan.json.type_strategy` 与 `highlight_strategy` 继承主类型、题材路由、故事发动机、项目签名、亮点支柱、采用机制和排除机制。四个创作参考库只用于把这些已确认策略细化成人物选择、冲突、信息差、场面和台词，不得重新选择或自定义另一套故事发动机、项目签名、亮点支柱、受众或风格。若现有策略无法闭合，返回 `planning.md` 更新 revision 并重新确认后再写剧本。

### 逐集亮点执行

每集根据已确认 `highlight_strategy` 建立 `highlight_ledger`。短集至少守住一个主要亮点；较长单集可增加辅助亮点，但不得挤压主故事因果。每项必须能定位：前置铺垫、兑现动作、状态变化、题材职责、呈现类别表达和高潮后的余震。连续两集重复同一亮点机制时，必须说明它如何升级、反转或完成回扣。

钩子负责让人继续看，亮点负责让人记住，高潮负责完成不可逆选择，三者可以在同一场发生但职责不得混写。金句只能是亮点的表达之一，不能替代人物行为、关系变化或题材机制。

## 规划继承与澄清

剧本阶段不重新询问规划参数。直接继承已确认 `drama_plan.json` 中的故事方向、开场策略、题材、受众、类型策略、亮点策略、情绪曲线、时长、比例、模型、字幕和禁用边界。

若关键字段缺失、互相冲突或用户在本阶段提出会改变规划的要求，返回 `planning.md` 更新完整参数确认；不得在剧本文件中维护第二套默认值或只局部口头确认。

### 长篇漂移风险继承（>10 集）

集数超过 `10` 时，`planning.md` 已要求把漂移风险和逐集机制写入同一份规划参数确认。剧本阶段只核对该确认记录并执行已确认安排，不新增第二次风险确认门：

- 项目级故事包一次覆盖全部集数、人物弧、伏笔账本和最终结局。
- 每次只细化并确认当前集，完成该集目标后才细化下一集。
- 剧情、人设、伏笔、道具、场景或资产漂移通过项目数据卡和相邻分集承接复核纠正。
- 不在剧本正文重复面向用户的风险提示，也不因后续集尚未细化而改变已确认的全局结局。

## 输出要求

下面前三类项目级创作内容作为 `剧本_全局设定与分集总纲.md` 中“全局故事圣经”章节的固定子章节，不再分别落盘；第四类完整剧本继续单独保存。`项目_事实与假设.md`、项目设定卡、项目数据卡、关系张力矩阵和机器合同仍按上文规定生成。多集项目无论长短都必须让合并文件的“分集推进总纲”章节覆盖全部集数；单集项目保留一行 `ep_1` 总纲以保持结构一致。

### 字数与完整性门禁

- 不设置字数上限；长度服务完整主线、清晰因果和可拍细节，禁止用重复描述、空泛氛围或无功能对白凑字数。
- 项目级总剧本包建议 `2000-3000` 字，包含故事大纲、人物小传、主要场景、核心道具、音色数据卡、全局风格锚点和分集梗概。
- 每集 `剧本_完整剧本_ep_N.md` 的最低有效中文/字母/数字字符数按确认时长计算：`max(120, min(800, 时长秒数 × 4.5))`，结果四舍五入为整数。极短集不再被固定 800 字误阻断，常规长集仍以 800 字为上限门槛；低于动态下限不得交给分镜阶段。
- 字数达标不等于内容合格。剧本仍须具备明确主线、人物目标、阻力、行动、反馈、局势变化、高潮和结果，保证观众看完知道故事在讲什么。
- 分集剧本只写本集剧情增量；角色外貌、场景布局、道具基础外观和音色不重复铺陈，统一引用 `project_data_card.json`。

### 产物一：剧情梗概

- 单一连贯叙事文本，不用小标题堆砌，也不用过多分点。允许用 3-5 个自然段落对应"起承转合"。
- 覆盖：故事起点与主角初始处境、核心冲突登场、事件升级与转折、高潮反转、落点/情感闭环。
- 必须包含：主角核心动机、反派/对立面的具体阻挠手段、主角的关键抉择、结局形态（爽感释放 / 情感和解 / 反转揭示 / 行动号召）。
- 常规短剧单集 1-3 分钟：按实际语速、动作和反应预算动态估算字数；微电影 5-10 分钟相应扩展。极短集 15-60 秒只保留单一核心变化，不以删掉结果和反应压缩时长。
- 多集项目：剧情梗概覆盖全剧主线（不逐集展开），并在 `剧本_全局设定与分集总纲.md` 的“分集推进总纲”章节写覆盖全部集数的表格，供完整剧本阶段落地；单集项目保留一行 `ep_1` 总纲。

### 产物二：人物小传

常规短剧通常覆盖主角、配角、反派三类角色，每类至少一位；用户指令或实际剧情不需要某类角色时不得机械添加。微电影可将"对立力量"作为独立小传，不要求人格化反派。每位主要角色或对立力量使用以下颗粒度：

```markdown
#### [角色名]（[主角 / 配角 / 反派]）

- **一句话定位**：[年龄 + 身份 + 关键人设标签]。
- **外壳**：[角色公开呈现的身份标签、说话方式和惯常行为]。
- **内核**：[外壳保护的恐惧、脆弱、渴望或价值判断]。
- **执念**：[持续驱动选择的创伤、遗憾、承诺或错误信念]。
- **性格**：[3-5 个具体性格特质，避免抽象形容词，用行为倾向描述]。
- **动机**：[核心动机 + 底层驱动力（欲望/恐惧/执念）]。
- **策略与越界选择**：[惯用策略 + 哪个节点采用过去不会使用的新策略]。
- **成长弧线**：[开场状态 → 中段动摇/受挫 → 结局蜕变，写清转折触发事件]。
- **视觉方向**：[大方向的形象、气质与识别符号，细节由资产阶段落地]。
- **固定音色锚点**：[年龄/性别表达 + 音高与质感 + 语言/口音 + 语速 + 停顿节奏 + 基准情绪 + 句尾习惯]，同步写入 `project_data_card.json.voices[].voice_anchor`。
- **关键道具/记忆点**：[标志性物件或行为习惯]。
```

人格化反派小传特别要求：

- 必须写清"合理性动机"（反派为什么这样做，避免脸谱化）。
- 爽剧、逆袭和明确善恶对抗题材写清实质失败、代价或惩罚落点。
- 微电影、关系戏和社会议题不强制惩罚；应写清对立力量如何被理解、承受、改变、绕过或留下余韵。

### 产物三：主要故事场景

在动笔完整剧本之前，先把全剧反复出现的核心场景一次性锁定，作为产物四完整剧本场次表头 `场景名 [日/夜] [内/外景]` 的取用来源。

**规模推导：**

1. 先逐场读取已确认故事中的地点变化、时间跳跃、人物出入、行动阻力和证据位置，合并空间功能相同且不影响因果的地点。
2. 单场短片、密室戏、独白或同一空间内成立的完整冲突链可以只登记 `1` 个核心场景，不为满足数量机械加场。
3. 短篇通常使用 `1-4` 个核心场景；长篇可按跨集剧情需要使用 `1-8` 个或更多场景。这里是复杂度预警范围，不是最低值或封顶值。
4. 超出常用范围时，逐个说明新增场景承担的独立剧情功能，以及为什么不能由既有场景完成；能够合并而不损害因果、节奏或视觉辨识的场景应合并。

**输出格式：**

```markdown
| 场景编号 | 场景名称 | 场景类型/功能 | 空间概念方向 | 情绪氛围基调 | 叙事性关键陈设 | 常见时间/内外景 |
|---|---|---|---|---|---|---|
| SCN001 |  | [主场景/次场景/回忆场景/梦境] |  |  |  | [日 内 / 夜 外 / …] |
| SCN002 |  |  |  |  |  |  |
```

**字段颗粒度：**

- **场景名称**：2-6 字为宜，需与后续剧本正文场次表头一字不差（如 `茶室`、`旧公寓客厅`、`天台`）。
- **场景类型/功能**：主场景（反复出现的日常/工作/家庭空间）/ 次场景（推动关键剧情的少量出现空间）/ 回忆或梦境（视觉上与现实形成区隔的特殊空间）。
- **空间概念方向**：剧本只写大方向（材质、体量、光源、时代感）；细节由分镜阶段的场景文字合同、唯一导演总控卡和连续性账本落地，主要场景布局参考图由共享标准资产检查点按 `assets.md` 生成。
- **情绪氛围基调**：本场景默认承载的情绪（压抑/温暖/悬疑/冷冽/怀旧等）；同一场景可承载不同情绪，但需列出主基调。
- **叙事性关键陈设**：与关键道具、伏笔、剧情反转有直接关系的物件（如"书架下层的深棕色铁盒"、"茶室长桌上的落款签"）。
- **常见时间/内外景**：给出该场景在剧中最常出现的 `日/夜 + 内/外景` 组合，便于剧本正文表头对齐。

**产物四完整剧本的场景取用约束（强制）：**

- 完整剧本每一场戏的表头 `场次编号 场景名 [日/夜] [内/外景]` 中的 `场景名`，**必须严格从本清单的 `场景名称` 中选择**，禁止在剧本正文里凭空新增未登记的场景。
- 如果剧情确需新增场景，必须先暂停剧本创作，按 `SCNxxx` 稳定 ID 回填本清单，并向用户简要说明新增场景的必要性；用户确认后再继续剧本创作。
- 只有剧情已经需要某个地点、时间或空间功能，但清单中尚未登记对应场景时，才暂停并回填；单场故事因果完整时允许只登记 `1` 个场景，不得为凑数新增无功能场景。

### 产物四：完整剧本（分集分场专业格式）

按下节"专业剧本格式规范"输出。长篇（>10 集）必须在剧本正文最前面加一次"长篇幻觉声明"（模板见上文"长篇幻觉风险声明"章节）。

**场景取用硬约束**：完整剧本每一场戏的场次表头 `场景名`，必须严格从产物三"主要故事场景"清单中选取；如剧情确需新增场景，先回填产物三再继续。

#### 长篇逐集制作规则（>10 集时强制，短篇同样遵守逐集原则）

一次性写完全部详细剧本容易在中后段漂移，因此先锁项目级故事，再逐集细化：

- **项目级先锁定**：一次覆盖全部集数的故事圣经、分集推进总纲、人物弧、伏笔账本和最终结局，经用户确认后不得由后续分集自行改写。
- **每次只细化当前集**：先复述上一集已发生事实、本集目标、待兑现伏笔和结尾状态，再完整写出本集场次、动作与台词；当前集没有确认前不得开始下一集详细剧本。
- **每集完成后复核**：对照项目级故事包、数据卡、关系张力和伏笔账本检查人设、因果、节奏、伏笔与结局方向；发现漂移时只修当前集或回到真正受影响的项目级合同。
- **伏笔记录**：当前集未回收的关键伏笔继续写入内部机器合同并绑定预计回收集数；不得因后续集尚未细化而临时改变已锁定的回收方向。

## 专业剧本格式规范

完整剧本必须严格采用**分集分场专业剧本格式**，让下游分镜阶段能一场戏对一段镜头列表。**不建议再使用"章节 + 100 字梗概"这类概要式写法作为完整剧本的最终形态**——概要式内容归在"剧情梗概"产物里。

### 剧本头（每部剧本开头一次）

```markdown
《[剧本标题]》

类型：[短篇短剧 / 微电影 / 剧情短片 / 动画短片 / 广告剧情 / 长篇短剧]（如为长篇，注明总集数）

风格：[王家卫风格的电影 / 是枝裕和风格的电影 / 3d玄幻 / 2d水墨 等]

标签：[题材关键词 + 情感关键词，例如"豪门联姻 + 先婚后爱 + 救赎"]

人设：[一句话高浓缩人设对撞，例如"年轻洒脱活泼女×年成熟稳重古板男"]

单集时长：[X 分钟]  |  剧作基调：[微电影三幕式 / 短视频钩子驱动]
```

长篇短剧在剧本头之后立即输出一次"长篇幻觉声明"。

### 风格字段填写指引（索引）

`风格` 字段必须写成可执行机制，不得只写“电影感”“高级感”。用户已经指定创作者、作品或动画流派时保留其意图，并从 `电影大师风格库.md` 选取少量光线、色彩、构图、材质和节奏特征；用户未指定时可以直接使用不绑定具体人物的机制组合，不强制选大师。后续资产、分镜和 Prompt 沿用同一份已确认视觉合同。

### 分集与分场格式

- **分集标题**：`第X集`，独占一行，不带集名（可在剧情梗概里给集名，剧本正文用集号即可）。
- **场次编号**：格式为 `X-Y`，X 为集号、Y 为该集内场次序号（从 1 起）。
- **场景表头**：`场次编号 场景名 [日/夜] [内/外景]`，例如 `1-1 茶室 日 内`、`1-2 茶室门口 日 外/内`。**`场景名` 必须严格从产物三"主要故事场景"清单的 `场景名称` 中选取，与其一字不差**；剧情如需新增未登记场景，先回填产物三再继续。
- **人物**：单独一行，列出该场出现的人物；如有画外音使用"角色名+VO"形式，如 `白父VO`。
- **动作提示**：以三角形符号 `△` 起首，只描述人物可见动作、空间关系、道具状态和结果。**动作提示必须客观、可拍摄，不写心理活动，不预设景别、机位、焦段或运镜**；镜头设计属于 `storyboard.md`。
- **对白**：`角色名：带规范标点的可读台词`，例如 `白清枞：盲婚哑嫁，你也能接受？`。问句、感叹、停顿和强调首先由标点帮助阅读，再在机器合同中用 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words` 精确执行。
- 每条人声在 `script_contract_ep_N.json` 中绑定 `voice_id` 和数据卡 `voice_anchor`；分集只写本场表演增量，不得改写固定音色描述。旁白也必须使用独立、全剧稳定的 VOICE。
- **旁白/画外音**：`角色名VO: 内容`。
- **内心独白**：`角色名OS: 内容`，只在无法由动作、关系或可见证据表达且确有叙事价值时使用。
- `VO/OS` 都属于后续视频模型必须原生生成的画外人声；画面人物不得做对应口型。剧本必须写清声音主体、起止场次、情绪、文本和对应画面职责。
- 时间跳跃、章节转换、记忆或内心状态可以按需使用短黑屏、暗场、环境空镜、物件特写或声音先行；不是强制模板。若需要显示时间、地点或章节，剧本写明上屏文字内容，分镜阶段编译为 `“画面文字”`。
- **情绪节拍记录**：用户可见剧本只用自然语言动作与表演描述情绪变化，不写任何内部元数据。供后续分镜使用的节拍标签只保存在内部机器合同中，不得进入展示给用户的剧本 Markdown。`【】` 只作为成片字幕源文本标识，不进入视频模型 Prompt。
- **场次结束**：空一行进入下一场次。

### 用户台词与台词闭环

- 用户提供的每一句原台词先作为 `source_text` 逐字、按原顺序保存。`display_text` 仅规范标点、引号和空格，用于剧本正文和人工审阅；`spoken_text` 再按 `delivery.md` 去除标点与不可发音符号，用作语音、Prompt 和字幕匹配键。三层文本除标点规范外不得删改、拆句、合句、调序或替换字词。
- 剧本正文统一使用 `display_text`；每条 `speech_lines` 同时保存 `source_text/display_text/spoken_text`。问句、感叹和语义停顿由 `display_text` 保留可读性，模型表演再由 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words` 控制。
- 用户只给少量台词且未禁止补充时，原始 `source_text` 保持不动；新增台词使用自身相同的三层文本合同，不得插入或改写用户原句内部。
- 每句台词先明确说话人的表面目的、隐藏顾虑和当前策略；相邻台词形成试探、阻挡、逼迫、反击、让步、揭示或关系变化。
- 画面已经能够直接看到的信息不再由台词复述。潜台词通过停顿、动作、视线、距离或答非所问呈现。
- 每句承担事实、指控、身份揭示或能力证明的台词，必须能在"台词证据链"中找到前置来源、可见证据或结果反馈；找不到时改写为角色主观判断，或补足证据。
- 完整短篇最后一句回扣开场冲突、角色选择、核心道具或主题命题；连续剧先完成当前局势变化，再建立下一问题。

### 分集分场格式样例（微电影向）

微电影通常单集独立、以情感沉淀取胜，样例展示"留白 + VO 克制 + 象征化对立面"的典型写法。

```markdown
《最后一封信》

类型：微电影（1 集）

风格：都市真人

标签：都市治愈 + 父子和解 + 遗物开启

人设：情绪克制的都市白领儿子×一辈子沉默的老式父亲

单集时长：3 分钟  |  剧作基调：微电影三幕式

第一集

1-1 旧公寓门口 日 外

人物：林远

△林远背对门内，右手推开吱呀作响的木门。尘埃在门缝斜光中缓缓浮动。

△林远停在门框中央三秒，没有立即迈步进去。

林远VO：父亲走后的第七天，我第一次踏进这里。

1-2 旧公寓客厅 日 内

人物：林远

△林远缓缓走进客厅，视线扫过书架上父亲的旧照片，眉头轻蹙。

△林远走到书架前，右手抬起，指尖轻抚玻璃相框，停在父亲肩膀上。

△指尖在玻璃相框上停留三秒后缓慢滑落，指腹沾了一层薄灰。

1-3 旧公寓客厅 日 内

人物：林远

△林远蹲下，左手扶住书架。一个深棕色、四角磨损的铁盒静置在下层中央。

△铁盒表面缓缓浮出微小光斑，盒内传出规律的滴答声。

1-4 旧公寓客厅 日 内

人物：林远

△林远从书架抽出那本《平凡的世界》，翻开书页——一枚小铜钥匙从书脊夹层滑落到桌面。

△林远盯着桌面的钥匙看了很久，没有说话。

△钥匙在斜光下闪过细微反光，桌面浮尘缓缓沉落。

1-5 旧公寓天台 傍晚 外

人物：林远、姑姑

△林远手里握着修好的旧怀表，站在天台边缘。夕阳把两人剪影拉长。

△姑姑站在他身后三步远的位置，没有说话，从旧布袋里掏出那本翻旧的《平凡的世界》。

△姑姑压低声音
姑姑：你爸让我把这个交给你。

△林远缓缓打开怀表，按下侧面按钮。

△怀表里传出沙哑的声音
怀表VO：对不起。

△林远蹲下身，肩膀开始颤抖。姑姑没有走过去，只是站在原地。

林远VO：三年了，我第一次听见他这么小声地说话。
```

> 微电影样例说明：动作提示允许"停三秒""指尖缓慢滑落""浮尘缓缓沉落"这类留白性描述；VO 只出现在开场与结尾，中段用画面 + 环境音承担；对立面（父亲的沉默）以"怀表 VO + 未寄出的书本"作为象征化道具登场，不需要人格化反派登台。

### 单集内部结构与章节层继承

单集完整剧本按下文“单集章节结构”动态组织。章节层不写在剧本正文里，而由场次排列自然承担叙事功能；需要辅助理解时可在剧情梗概或分集大纲标注章节与场次映射。

### 长篇分集大纲附表

长篇短剧在剧情梗概之后、完整剧本之前，必须附一份分集大纲表：

```markdown
| 集号 | 集名 | 核心事件 | 情绪节拍 | 关键伏笔/回收 |
|---|---|---|---|---|
| 第1集 |  |  | 开场钩子 |  |
| 第2集 |  |  | 冲突展开 |  |
| ... |  |  |  |  |
```

分集大纲的作用是给完整剧本的每一集提供锚点，降低超过 10 集之后的漂移风险；用户发现漂移时，可用大纲表定位应回填的伏笔。

## 单集章节结构

章节数量由总时长、策略变化、场景跨度、关系转折和信息揭示动态决定，不设固定数量。每章必须承担独立职责并改变剧情状态；删除后不影响主线的章节合并或重写。章节只用于剧作组织，不等同于视频片段，也不得按模型时长机械切分。

**章节功能分配**：

- **微电影三幕式**：建立情感缺口与钩子 → 事件和冲突迫使主角改变 → 高潮选择、反应与落点。
- **短视频钩子驱动**：快速建立问题 → 压力升级与策略变化 → 身份、能力或事实兑现 → 当前冲突收束。

## 写作原则与策略路由

本文件只保留跨类型都必须满足的剧作硬门：角色主动选择、冲突因果、策略反馈、信息或关系变化、证据链、完整落点和可拍性。

短剧、微电影、爽感、钩子、留白及呈现类别变体的候选策略按需读取 `题材亮点与传播库.md`，受众假设读取 `题材受众库.md`；视觉风格机制读取 `电影大师风格库.md`。策略库不能覆盖本文件的因果、证据和完整性门禁。

### 类别 × 题材双层路由

正式写剧本前必须从已确认 `drama_plan.json.type_strategy` 逐字继承：

1. `format`：动画/卡通短剧、漫剧、AI 真人/数字人短剧、口播解说短剧、微电影/短片或用户自定义形态，决定叙述载体、场景颗粒和表演方式。
2. `subject_route` 与必要的 `subject_subroute`：决定冲突发动机、信息释放和高潮义务。合并题材词不能不分主次地同时套用。
3. `format_strategy`：四项分别说明叙述载体、场景颗粒、台词/旁白和表演/动作策略，不得只写“发挥动画优势”“电影感”等空话。
4. `intersection_strategy`：四项分别说明钩子呈现、冲突推进、高潮兑现、制作限制补偿。任一项在正文中找不到场次证据，先重写策略或正文，不得进入分镜。

执行顺序固定为：先按 `剧作方法与类型库.md` 第二部分建立类型与题材路由及结局义务，再按 `题材亮点与传播库.md` 第一部分改写为对应载体语法。更换呈现类别视为剧作层变更，至少重审场景拆分、台词/旁白比例、信息证据、动作复杂度和高潮表达，不能只在分镜阶段换画风。

## 题材与受众策略

需要受众、平台、地域或题材选择时读取 `题材受众库.md`。其中内容只作为待验证假设：

- 用户明确受众和平台时以用户信息为准。
- 涉及最新趋势、平台政策、审核、人口画像或市场偏好时必须检索并记录日期与来源。
- 不根据年龄、性别、地域机械决定题材、人物、节奏和结局。
- 不因平台名称自动开启字幕、热门 BGM、固定画幅或固定钩子秒数。
- 风险内容遵守当前法律、平台政策和宿主安全规范，不用改名或影射规避核验。

## 剧本内容质量人工评估

`drama_lint.py` 只检查结构和显式合同，不能判断故事是否成立。交付前统一使用下表阅读全文，不再执行第二套单集检查或独立可拍性评分：

阅读全文前必须按 `剧作方法与类型库.md` 第一部分顺序执行七轮改稿：前提轮、结构轮、人物轮、关系轮、场景轮、台词轮、导演与可拍轮。信息与反转在结构轮复核，节奏删减在场景轮和导演与可拍轮复核。每轮只解决一种问题并记录修改依据；不得一遍同时润色所有维度，也不得把格式校验当作改稿。

| 维度           | 达标标准                                                                                                          | 失败处理                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 因果           | 每场有目标、阻力、策略、反馈和状态变化                                                                            | 删除、合并或重写最早失效场次                                   |
| 钩子与兑现     | 钩子服务主线，有明确兑现位置和后果                                                                                | 补兑现或删除无关刺激                                           |
| 人物           | 主角主动选择并承担代价，对立力量有独立目标和资源                                                                  | 重写动机、策略或关系变化                                       |
| 信息与证据     | 关键事实、身份、能力和反转均有来源、公平线索与可见后果                                                            | 补证据或改为角色主观判断                                       |
| 台词与声音     | 每句符合身份和策略，原文可追溯，时长可读完，人声类型明确                                                          | 保留原文并调整分句、动作或时长                                 |
| 关系张力       | 每对核心关系的权力差、信息差、情感差有场次证据并发生有效变化                                                      | 回写关系矩阵，重写无攻防或无变化场次                           |
| 亮点与可传播点 | 每集主要亮点具备铺垫、兑现、状态变化、形态表达和余震；商业对话型台词由高潮/反转及代价支撑，例外类型有等价视听母题 | 删除伪亮点和口号式金句，回到题材发动机、人物选择与亮点账本重写 |
| 节奏与情绪     | 持续产生行动、反馈、关系、认知或情绪变化，留白也有职责                                                            | 压缩空转段落或补有效变化                                       |
| 完整性         | 当前范围有开端、推进、高潮、结果和角色反应                                                                        | 不交付提纲、占位符或停在高潮的半成品                           |
| AI 可拍性      | 主行动者清晰；复杂动作可拆；关键信息不只依赖微表情；场景道具可锁定                                                | 简化动作、拆分人物、补可见证据或登记下游风险                   |
| 跨集一致性     | 人物弧、伏笔、状态和集间承接与项目级剧本及数据卡一致                                                              | 修订权威上游并使受影响下游失效                                 |
| 交付完整性     | 项目级总览、分集正文、合同、数据卡、路径和哈希一致                                                                | 补齐产物并重新校验                                             |

以上项目由创作者在交付前人工复核，不要求填写固定报告模板；发现问题时直接修改剧本并重新展示受影响内容。

| 改道具               | 证据链、动作接触、状态变化和连续性                                 | 剧本、分镜、资产、相关视频                   | PROP 状态版本及相关 SEG                                          |
| 改视觉风格           | 全局风格合同、角色/道具表现、全部视频和调色                        | 规划及全部受影响下游                         | CHR/PROP 按影响重做，相关或全部 SEG 重生                         |

只使真正受影响的阶段和稳定 ID 失效，不机械推倒全项目；但风格、角色身份或核心因果改变时不得假装是局部修改。旧版本标记 `superseded` 并保留，允许回滚但必须记录原因。

## 正式输出约束

正式产物直接遵循本文件前述"剧情梗概 -> 人物小传 -> 主要故事场景 -> 完整剧本"结构和专业剧本格式。不得复制缩略示例，不得为了控制篇幅省略任何已确认范围内的剧情。

- 短篇必须完整写出全部场次、动作、对白、旁白、情绪节拍和结局。
- 长篇先完成覆盖全部集数与最终结局的项目级完整故事包，再只完整写出当前集；不得以项目级总览或分集大纲代替当前集详细完整剧本。
- 示例、模板和格式说明只用于约束结构，正式产物中不得出现"略、此处略、后续依此展开、1-N、XXX、TBD、待补充"等占位表达。
- 如果输出长度不足以完成当前确认范围，应在生成前缩小并重新确认批次范围，不得交付半成品。

## 交接

路径、命名、`project_script_manifest.json`、`project_data_card.json` 和 `script_contract_ep_N.json` schema 只读取 `manifests.md`。项目级阶段产出完整故事包与数据卡；逐集阶段只产出当前集详细剧本和机器合同。JSON 只保存执行字段、正文路径与哈希，不复制完整正文。

项目级落盘前核对全部集数、人物弧、伏笔和最终结局，将 `phases.script` 写为 `awaiting_confirmation`，只展示项目级用户可读文件并等待确认。通过后把 `phases.script` 写为 `confirmed`，设置 `current_episode: ep_1`、`current_stage: script` 和 `episodes.ep_1.stage_status.script: in_progress`。当前集详细剧本完成后，只将该集 `script` 写为 `awaiting_confirmation` 并检查、展示、确认；不得要求后续集详细剧本同时存在。聊天中不重复粘贴完整正文，也不展示机器合同、JSON、内部字段、路径、校验命令或检查统计。

```text
项目级：请确认全局故事圣经、全部分集推进总纲和最终结局是否需要修改。确认后我会开始第 1 集详细剧本。
分集级：请确认当前集详细剧本是否需要修改。确认后我会开始当前集资产阶段。
```

收到修改意见时只修订真实受影响范围。改变全局因果、人物弧、伏笔回收、结局或分集边界时回到项目级故事包；只影响当前集执行细节时修订当前集。必须先确认项目级故事包，再确认当前集详细剧本，才进入该集 `assets.md`；当前集达到目标后才开始下一集详细剧本。
