# 关键帧阶段 Ref

当 `current_episode` 的资产和十五列详细分镜分别取得用户确认后读取本文件。本文件是剧情关键帧生成、登记、目视验收和阶段确认的唯一权威。关键帧阶段位于当前集分镜之后、当前集视频片段之前；不得跨集批量生成关键帧。

## 本 Ref 关键要求

- 关键帧只能从已确认分镜的高光关键帧需求清单和 approved 资产生成；任一选点、构图或状态未定时返回上游。
- 关键帧生成必须使用 `image_edit` I2I；不得使用 `image_gen`、text-to-image 或纯文字 Prompt 临时生成关键帧。若没有足够有效参考图，先返回资产阶段补齐可用角色、状态、场景、道具或风格图。发生在已登记剧情场景内的关键帧，必须传入对应 approved `SCNxxx` 场景四宫格作为场景参考；不能只靠关键帧文字描述或角色图背景替代场景图。
- 完整模式下关键帧阶段必须执行并取得用户确认后才能进入视频阶段；不得把完整模式关键帧合并到分镜或视频阶段，也不得用角色、场景、风格图或视频 FRM 代替。只有轻量模式可按 `control-contracts.md` 的轻量边界将关键帧阶段记为 `merged`。
- 关键帧按集控制总量：完整模式每集必须 `3-4` 张剧情高光 KF，只落在整集最强的开局钩子、重大揭示/反转、关系断裂/选择、高潮或结尾钩子上。不是每个 SEG 都需要 KF；未被选中的 SEG 不生成关键帧。第一段也不生成首帧 KF；任何 SEG 都不生成尾帧 KF。
- KF 是生成前目标，FRM 是生成后事实；二者不得互相冒充或覆盖。
- 关键帧 Prompt 必须使用自然语言或字段化完整 PE；第一句先写项目统一画风、`project_visual_mode` 和可观察风格词，必须与资产阶段人物、场景、道具和 STYLE001 保持一致；人物是真人写实/照片级时，关键帧、场景和道具都保持可信真实媒介；人物是 2D 漫画、动漫、水墨动漫、插画或动态漫时，关键帧、场景和道具都保持同一非真人媒介。随后逐张说明真实传入图片的职责：主体、角色状态、场景、道具、风格或高光参考，并写清采用/剥离边界，再用完整字段写生成目标、主体继承、场景继承、变化要求、构图与镜头、动作与情绪、光影与色彩、风格与质感、画面文字和负面约束。用户上传、指定或认可的有效参考图优先级最高；已生成 approved 图负责项目连续性，两者各自有用时必须同时传入。道具参考来自多状态图时，必须用 `<图x-第x个>（状态）` 指明采用的具体分区，不能笼统引用整张图。
- 关键帧内容必须承接分镜阶段已定的剧情峰值：信息揭露、身份暴露、背叛证据出现、动作反转、情绪失控、关系断裂、危险逼近或选择不可逆的瞬间。不得把关键帧写成普通站姿、空泛氛围图、服装展示图、普通开场图、普通收尾图、“人物在房间里难过”或“准备发生但还没有戏”的过渡图；画面必须让观众一眼看懂正在发生的事件、造成压力的证据或动作、局势变化和下一拍的危险/选择/钩子。
- 抽象情绪必须转化为可见表演：眼神方向、眼睑张力、瞳孔聚焦、眉峰高低、嘴唇开合、下颌紧绷、手指力度、肩颈姿态、身体重心、道具接触和与他人的距离都要具体写出；不得只写“震惊、克制、崩溃、愤怒、动容”等模型无法直接执行的心理词。
- 画面文字必须明确：短文字需要精确出现时用中文引号包住，例如信纸露出“杀你父亲的人是顾承安”；完整信件、档案、书页等长文本可不逐字写，但要说明画面有文字、文字大意和可读关键词，避免生成空白纸或无意义字符。
- 每张关键帧实际传给模型的完整 Prompt 原文必须保存到 `episodes/ep_N/03_资产/提示词/`，不能保存简洁版、摘要版、压缩版或说明版，并在 `keyframe_manifest_ep_N.json.keyframes[].prompt_path` 登记；Prompt 文件默认内部追溯，只有用户明确要求查看 Prompt、排查或交接时才随对应关键帧展示入口。
- 关键帧完成后按集数、片段和时间顺序展示给用户确认，不展示内部 ID、字段或检查统计。

## 输入条件

必须同时具备：

- 项目级故事包、当前集详细剧本，以及当前集资产和分镜阶段均已取得用户明确确认。
- 当前集十五列详细分镜、视频片段执行表、连续性账本和 `storyboard_ep_N.json` 完整。
- 分镜已按集完成高光关键帧需求清单：完整模式每集必须 `3-4` 张，映射到少数承载集级高光或连续性风险的 SEG；未选中的 SEG 可以没有 `required_keyframe_roles` 或 `keyframe_requests`。所有 SEG 仍必须有 `reference_input_plan`，只在本段确有已规划 KF 时列入 `segment_highlight_reference`。不规划生成式首帧或尾帧。
- 所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具和风格均引用已批准资产版本；服装、发型、妆容、伤痕、伪装或随身装具与基准不同时，必须已有对应角色状态资产。当前高光发生在某个 `SCNxxx` 场景内时，该场景必须已有 approved 四宫格布局参考图，并作为 `K1` 真实传入。一次性物件只写入关键帧 Prompt，不要求补 PROP 资产。
- 生图模型继承已确认规划，不得在本阶段自主切换；使用 `seedream 5.0 pro` 时必须已经完成会员与额度提示确认。

任一分镜动作相位、机位、构图、角色当前状态或道具状态版本仍未确定时，返回分镜或资产阶段修复，不得先生成“通用关键帧”再让下游迁就。

## 生成时机

- 关键帧只在资产与分镜都确认后生成，位于视频生成之前；完整模式必须执行本阶段并等待用户确认。它是视频段的画面锚点，不替代分镜，也不替代视频 Prompt。
- 按剧集执行：先读本集 `storyboard_ep_N.json` 和视频段执行表，再按本集关键帧需求清单生成 `3-4` 张需要的关键帧；不要跨集混用待确认关键帧。
- 只为分镜清单中被选中的 `SEG` 生成高光关键帧，按剧情重要性和片段时间顺序推进；未选中的 `SEG` 不补普通高光图，首段不额外生成 0 秒首帧。
- 如果某段复用前段已批准的同状态关键帧，可以不重画，但必须在 manifest 里登记真实复用关系。

## 数量与职责

- 每集总共只使用 `3-4` 张高光关键帧。多 SEG 项目中，单个 `SEGxxx` 通常为 `0-1` 张，只有同一片段同时承载两个独立集级峰值且无法拆分时才允许 `2` 张；整集只有一个 SEG 时，该 SEG 必须承载本集全部 `3-4` 个互不重复的高光职责，不受多 SEG 项目的单段 `2` 张上限限制。
- 当前集第一个 `SEGxxx` 不生成首帧 KF；视频的真实首帧在视频生成后抽取为 FRM。非首段先读取 planned `SEAM`：`continuous` 承接必须使用上一段已保存视频抽取并登记的真实 tail FRM，缺失时停止下一段编译并先补齐；`elliptical` 明确发生时间、空间或认知跳跃时不要求 tail FRM 作为 0 秒基准。任何模式都不得用其他帧或高光 KF 冒充真实 tail FRM。
- 分镜阶段根据整集剧情峰值和漂移风险决定数量：优先选择开局钩子、重大揭示/反转、关系断裂/选择、高潮或结尾钩子；同段存在两个独立高光、证据与反应都必须可读时可以在同一 SEG 放两张。关键帧阶段不重新按感觉增删数量，只在选点明显错误时退回分镜。
- 信息量触发包括空间锚点建立、视角切换、决定性动作、情节或身份揭示、结尾悬念、光影转折和道具状态突变。
- 不按每个 SHOT 机械生成图片；没有独立叙事或连续性职责的镜头不增加关键帧。
- 相邻连续片段可以复用已批准的同状态关键帧，但两个片段的内部登记必须记录真实引用关系。
- 高光关键帧应选择动作即将不可逆或结果刚刚暴露的可推进姿态，不默认使用人物正立、直视镜头或完全静止的设定图姿态。
- 关键帧锁定单帧状态和动作相位，不承担完整运动过程。不得把多张静态图当作完整运动指令；主体如何从起点运动到结果必须由分镜和实际视频 Prompt 明确描述。
- 多张关键帧不得无差别作为同权重输入。视频阶段按工具能力传入高光关键帧，若工具不支持有序多关键帧控制，就把高光图作为参考图，并在 Prompt 中写清对应时间点的状态目标。

| 类型 | 必须表达 | 禁止 |
|---|---|---|
| 高光关键帧 | 信息揭露、证据出现、动作接触、关系变化、危险逼近或不可逆选择的单帧状态 | 普通首帧、普通尾帧、无剧情变化的漂亮画面、角色展示图 |

选择规则：先把人物身份与伤妆/服装、场景拓扑、已升级为 PROP 的关键道具状态、站位变化、结果、证据露出和关系反转纳入“剧情重要性 × 生成漂移风险”评分，再从整集中只选择最强的 `3-4` 个高光时刻生成 KF。人物身份与空间拓扑的全程稳定由 approved 资产和分镜合同持续锁定，片段首尾事实由生成后 FRM 锁定；不得为了逐项覆盖这些因素而突破关键帧总量或补首尾 KF。纯运镜、纯表情过渡、可由视频 Prompt 稳定表达的动作过程通常不单独画。

## 视频可用性标准

关键帧不是概念图、剧照海报或参考拼贴，而是后续视频可以直接消费的剧情高光参考图。生成和验收时先过以下标准：

- **高光参考与首尾事实分离**：关键帧只锁剧情高光，不登记为目标视频 `first frame` / `last frame`。真实首帧和尾帧只在视频生成后作为 FRM 抽取；角色图、场景图、风格图只作为参考图，不得冒充关键帧。
- **静帧可拍性**：Prompt 描述的一切必须能被摄影师在同一瞬间拍到；“先、再、随后、转身过程中、表情从 A 到 B”属于视频动作，不能写进单张关键帧。
- **高光事实不串线**：每张高光关键帧只呈现选定时间点已经成立的事实。写完后要把手位、持物、视线、站位和可见状态反查一遍，不能把尚未发生的结果提前塞进画面。
- **人物站位可接戏**：每个在场人物都要有屏幕位置、彼此距离、身体朝向、头部朝向、视线目标、手部状态和持物关系。只写“他很愤怒”不够，必须落成可见姿态，例如握紧杯沿、身体前压、视线钉在对方手里的证据上。
- **空间和镜头轴线稳定**：写清前景/中景/背景、角色在轴线哪一侧、机位高度、观察方向、焦段意图和主光方向。否则视频容易越轴、换场、人物左右跳变或光位重置。
- **景别承载正确表演**：远景不要要求眼睫、泪光这类不可读细节；近景不要承担完整走位、追逐、递物全过程。关键帧只锁当前景别能读到的表演通道。
- **画幅适配**：关键帧构图必须按目标视频画幅生成或裁切预想完成，避免把横图、方图直接当竖屏首帧导致人物被拉伸、裁头或主体偏出安全区。
- **数量服务剧情峰值**：每集通常只保留最强 `3-4` 个高光；不要为了每个 SEG 都有图而补普通画面。若需要靠首尾两张图解释动作过程，优先回到分镜拆镜或在视频 Prompt 中写清运动路径。

## 画面创作法

生成关键帧前先写出“这张图的戏”，再写视觉。好关键帧不靠漂亮形容词，而靠观众一眼能读到的冲突、关系和下一秒会发生的动作。

1. **先定观众要看懂的一件事**：每张关键帧只服务一个主任务，例如“她第一次看见证据”“他伸手要抢手机”“父亲把钱藏回枕下”。不要同时承担身份介绍、场景展示、反转、悲伤和动作高潮。
2. **把主任务变成画面焦点**：明确视觉重点落在脸、手、道具、门口、手机屏还是两人距离。焦点之外的信息只保留能解释剧情的部分；无关装饰越多，视频越容易误读。
3. **选择有势能的动作相位**：优先画“动作即将发生”或“动作刚刚完成”的一瞬间。不要画普通站立、正脸定妆照、海报式凝视，也不要画复杂动作中段；复杂动作交给视频 Prompt。
4. **用身体表演替代情绪词**：少写“愤怒、崩溃、震惊”，改写为可见事实：肩膀前压、手指扣紧杯沿、嘴唇停在半张、视线避开对方、把证据攥皱。表演必须匹配景别，远景写身体和走位，近景写眼神、手和细小反应。
5. **让人物关系有空间压力**：写清两人距离、谁压迫谁、谁堵门、谁退到墙边、谁在画面高位或低位。短剧关键帧尤其需要“冲突关系”而不是单人美图。
6. **前中后景要有承接功能**：前景可放遮挡、道具或证据；中景承载人物关系；背景交代出口、床、桌、门、车窗等行动路径。不要让人物贴在空背景上。
7. **竖屏优先保脸、手、道具和安全区**：竖屏短剧中，脸、手、已升级为 PROP 的关键道具（若入画）必须进入中上部可读区域；一次性道具按剧情可读性处理，不要求补资产。字幕区和裁切边缘不要压住关键证据。多人同框时优先半身 / 中近景，避免全身小人看不清表演。
8. **参考图少而准**：只传会改变结果的参考图。身份/状态、场景、关键道具、风格彼此冲突时，先保身份和道具因果，再保场景拓扑，最后保风格；不要为了“更丰富”塞入无关参考。
9. **避免海报感和 AI 美图感**：不要中心站姿、过度磨皮、无目的逆光、大片空旷背景、符号堆叠、夸张特效或宣传照姿势。关键帧要像剧情现场的某一帧，而不是角色展示页。
10. **写负面约束只针对本图风险**：不要堆通用禁词；针对当前图最可能坏的点写，例如“不要第二个相同人物”“不要把手机变成纸条”“不要改变左手持物”“不要让门出现在画面右侧”。

### 可见描述密度

关键帧 Prompt 的画面主体描述建议控制在 `300-500` 字；参考图定位另算。内容过多时优先保留主体、剧情证据、动作相位、人物关系、光线和关键材质，删除不影响视频首尾承接的装饰。

每句都给模型一个可见限定：位置、数量、遮挡、接触点、材质、光照、朝向或可读文字。所有元素先绑定空间关系，再写形态和状态；有前后重叠时写清谁遮住谁、遮住哪个部位；可清晰计数的人物、信件、杯子、门、屏幕、烛台等都写具体数量，不用“多个、若干、一些”带过。

人物只写同一瞬间能看见的姿态和表演。身体动作写清身体朝向、头部朝向、视线目标、上肢/手指、肩颈、重心、脚步或被裁切部位；近景可以写眼睑、瞳孔、眉峰、嘴唇、下颌和手指力度，远景优先写站位、距离、遮挡和动作方向。避免“略微、稍微、有点、似乎”等模糊词；需要轻微变化时改成具体可见结果，例如嘴唇停在半张、右肩高于左肩、食指压住纸角。

材质、颜色和光影只写画面会呈现的结果。颜色稳定时写具体色名；颜色不稳定时写明暗、冷暖或部位差异；材质要绑定纹理、反光、褶皱、磨损、潮湿、透明叠加或边缘状态。光照写光源方向、照亮区域、阴影软硬和投影方向，不用“高级、超写实、电影感很强”这类评价替代视觉结果。

画面文字必须按画面可读性处理：需要准确出现的短文字用中文引号写出，并说明在信纸、牌匾、手机屏幕、档案页或墙面上的位置、字号相对关系和可见程度；长信件、档案、书页不逐字展开时，说明上面有密集中文手写或印刷文字、大致内容和少量可读关键词。没有剧情需要的文字不写进画面。

常见返修方向：

- 角色不像：减少非身份参考，强化当前角色状态图；把脸部角度、发型、服装、伤痕和年龄写成可见事实。
- 画面没戏：把抽象情绪改成手、视线、距离、压迫关系和道具接触；让主体处在动作前一拍或后一拍。
- 视频接不上：优先检查真实 tail FRM、下一段 start FRM、站位、手位、持物、屏幕方向和光位；需要改生成前目标时只重画相关高光关键帧，不生成首帧或尾帧替代真实抽帧。
- 构图像海报：降低装饰性光效，加入前景/中景/背景和行动路径；让人物处在剧情关系里，而不是对镜头摆姿势。
- 道具漂移：单独传道具状态图，写清归属、朝向、接触点、可见面和是否有文字；文字内容不稳定时留白，后期叠字。

## 生成合同

每张关键帧必须基于已批准角色/状态、场景、已升级为 PROP 的道具和风格资产生成，工具固定使用 `image_edit`；只要项目内存在与当前画面直接相关的角色、状态、场景、已升级为 PROP 的道具、风格、KF 或 FRM 的 approved 图，就必须真实传入对应图片，不得用 text-to-image/纯文生图重新生成。当前剧情发生在已登记场景内时，必须传入对应 approved 场景四宫格，采用其空间拓扑、固定陈设、画面外补全结构、光位、材质和场景锚点；不得因为关键帧构图是近景、人物图带背景或分镜已有文字描述而省略场景图。一次性道具只写进关键帧 Prompt，不要求补道具资产。没有足够有效视觉参考图时，返回 `assets.md` 补齐并确认，不得在关键帧阶段降级为 `image_gen`，也不得用文字临时替代。缺换装后角色状态、场景四宫格或需复现的 PROP 道具状态资产时，先返回 `assets.md` 补齐并确认。

关键帧生成前按职责收集真实可用图片：

```text
K0 当前角色状态资产：锁服装、妆发、伤痕、伪装和随身装具；无状态变化时使用身份基准图或头部身份锚点。
K1 当前场景布局或状态资产：使用 approved `SCNxxx` 四宫格，锁空间拓扑、固定陈设、画面外补全结构、门窗朝向、行动路径、光位和材质；如需指定格位，用 `<图片N - 第M格>` / `<IMGN - Cell M>` 标明近景、远景、平视全景或远景俯拍。
K2 当前已升级为 PROP 且需要复现的道具资产：锁结构、尺寸、归属、可见面和当前状态；若来自道具多状态图，用 `<图x-第x个>（状态）` 指明具体分区。一次性道具只在关键帧 Prompt 中描述，不列为资产输入职责。
K3 STYLE001 全局 moodboard：锁主色调、色彩关系、线条、光线、材质、构图、景深、颗粒和空间氛围；不得生成剧情人物、角色脸、具体服装或剧情道具。若由 SCN/KF 明确承载，也必须记录承载关系。
K4 必要的用户/外部有效视觉参考：只采用已保存并登记的视觉信息，剥离文字、水印、品牌和无关主体。
K5 用户认可的视觉画风锚点：当任一人物、场景、道具、构图或风格图被指定为 `style_anchor_reference` 时，作为风格参考传入，只继承从该图抽取出的媒介、线条、上色、纸感/颗粒、色阶、材质、光影和设定稿质感等画风词，不继承锚点图里的无关人物、场景、道具、服装、布局、姿态和剧情状态。
```

关键帧调用的 Prompt 必须使用自然语言，第一句先写项目统一画风与可观察风格词，例如“全项目统一保持[媒介、线条、上色、纸感/颗粒、色阶、材质、光影、构图和空间氛围]”；之后按真实传入顺序用 `language_contract.video_language` 逐张写清每张图的职责、可采用内容和剥离内容。视频输入图片标记跟随 Prompt 语言，中文使用 `<图片1>`、`<图片2>`，英文使用 `<IMG1>`、`<IMG2>`；如果输入是宫格图，用 `<图片N - 第M格>` / `<IMGN - Cell M>` 指定具体格子，并与真实传图顺序一致；如果输入是道具多状态图，用 `<图x-第x个>（状态）` 指定当前采用的状态分区。场景、风格、道具、高光参考和主体职责必须分开写，不能把风格图误写成角色，不能把场景图继承为人物身份。每张参考图都要写明采用内容与剥离内容，默认剥离字幕、二维码、水印、平台界面、镜面文字、无关人物和无关背景。

关键帧必须真实生成、保存为可打开的常见图片格式，目视验收，同时保存实际提交 Prompt 文件，并在 `keyframe_manifest_ep_N.json` 登记为 `approved` 后，视频阶段才允许作为 `segment_highlight_reference` 传入。分镜阶段只规划职责，不得把“待生成 KF”当作可传入图片。

关键帧阶段若用户追加或替换含人物、场景、道具、构图或风格等有效视觉参考维度的图片，不得只修当前关键帧；先返回资产阶段为对应稳定资产或视觉类型建立新版本，再按 `control-contracts.md` 和 `assets.md` 重做所有依赖旧版本或旧 `project_visual_mode` 的状态图、细节图、关键帧和后续视频输入图。

Prompt 使用 `drama_plan.json.language_contract.video_language`。第一句先写项目统一画风，且必须与资产阶段已批准画风词一致；不要把画风藏到末尾负面约束或笼统写“保持风格一致”。随后写清：

1. 本图的单一戏剧任务：观众此刻必须看懂什么，以及为什么这是当前片段的信息峰值或冲突峰值；必须写成具体事件，例如“她发现证据并意识到门外有人偷听”，不能只写“她悲伤、紧张、孤独”。
2. 所属分集、片段、镜头、高光序号和准确剧情时刻。
3. 角色版本、外观状态、服装/妆发/伤痕/伪装状态资产、位置、数量、遮挡、朝向、视线、眼睑/瞳孔/眉峰/嘴角/下颌等表情细节和动作相位。
4. 道具版本、状态资产、归属、朝向、接触关系、可见面和当前状态。
5. 场景空间拓扑、固定陈设、前中后景、遮挡关系、行动路径、时间天气、材质、主光方向、照亮区域、阴影软硬和色温。
6. 景别、机位高度、观察方向、镜头轴线、构图重心、主体屏幕位置和竖屏安全区。
7. 当前可见的因果状态及观众此刻必须读到的信息：前一拍造成了什么压力，画面中哪个证据/动作/关系变化正在改变局势，下一拍会引向什么危险、选择或钩子；画面中有文字时，说明载体、位置、可见程度和内容。
8. 与上一镜或入站状态的连续性，以及下一镜或后续片段必须继承的状态。
9. 单帧约束：只呈现一个确定瞬间，不做多宫格，不复制角色，不生成字幕、随机文字、水印或界面元素。
10. 高光边界声明：直说本图是剧情高光关键帧，不是目标视频首帧或尾帧；视频首尾事实以生成后 FRM 为准。

画幅只进入内部生成参数，不写入 Prompt。只有真实传入的图片才能登记为参考依据；参考图可以来自用户上传、确有必要的检索下载、截图、已批准资产、KF/FRM 或外部素材，但必须已保存并登记，不得把仅存在于网页或文字描述中的图片说成已传入。

## 登记与验收

全部结果写入 `episodes/ep_N/03_资产/keyframe_manifest_ep_N.json`，并直接引用已确认的 `storyboard_ep_N.json`。每项必须包含关键帧、片段、镜头、高光序号、数据卡版本、资产与状态引用、信息量触发项、剧情状态、角色/道具/场景/机位合同、来源文件、模型、版本、状态和使用范围。

实际看图后逐张检查以下内容，不要求填写固定报告模板：

- 角色身份、数量、造型、服装/妆发/伤痕/伪装和当前状态正确；不同角色的脸型、五官比例、眉眼、年龄感、发型轮廓、体态剪影和身份标志必须保持可见区分度，除已登记双胞胎/克隆/同一角色状态外不得共脸。
- 道具结构、方向、归属、接触点、可见面和状态正确；已升级为 PROP 的复现道具不得缺图或换形，一次性道具只按 Prompt 检查可见表现。
- 场景空间、时间、天气、光位、色温和构图符合已确认分镜。
- 高光职责清晰，动作相位和连续性合同一致。
- 关键帧没有把人物锁成无动作价值的正立展示姿态；静态构图仍保留可继续发生的动作张力。
- 关键帧没有提前出现尚未发生的终点事实，也没有被当作工具不支持的硬锚点。
- 每个在场人物的屏幕位置、距离、身体朝向、视线、手位和持物关系可见且可接到下一镜。
- 画幅、裁切、安全区和主体重心适合目标视频比例；没有把参考图拉伸成首帧的风险。
- 无字幕、水印、多宫格、复制人物、结构崩坏或无关物体。

任一核心项失败时建立新版本定向重生；只有 `approved` 关键帧可以进入视频阶段。

## 用户展示与确认

每张关键帧生成、保存并通过基础可打开检查后，必须立即按 `SKILL.md` 的交付前置路由完成当前环境交付并图文交叉直显给用户；非 Mobile 必须由主 Agent 同步写入 Canvas 并 CLI 回读成功，当前关键帧未交付上画布前不得继续生成下一张。不得只返回 URL 文本、附件链接、纯文件路径、工具自带预览、HTML `<img>` 或旧人工通知/展示工具，不得等全部关键帧完成后才第一次展示。全部关键帧完成内部验收后，按集数、视频片段和时间顺序确认展示结果；说明只写“第几集哪个片段的第几个高光”，例如“第 1 集 SEG003 高光1”“第 1 集 SEG003 高光2”；Prompt 文件入口仅在用户明确要求查看 Prompt、排查或交接时就近展示。必要时补一句极短状态，不展开用途解释，不面向用户写具体镜头号。同一类型从 `1` 开始编号，面向用户不显示内部 ID、工具名、字段、任务号或检查统计。

确认句必须按 `language_contract.output_language` 改写，语义完整但措辞不固定：请用户确认这些关键帧是否需要修改；需要修改则指出具体画面；确认无误则用明确肯定回复；收到确认后才开始生成视频片段。确认句要礼貌清晰，避免每阶段重复同一句模板。

收到修改意见时只返修受影响关键帧并再次展示。用户明确确认后，将关键帧阶段写为 `confirmed`，再进入 `video.md`；不得在确认前生成视频片段。
