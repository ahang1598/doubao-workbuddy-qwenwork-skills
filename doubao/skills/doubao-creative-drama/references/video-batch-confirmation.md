# 视频批次参数与五列分镜确认

本文件只定义完整模式视频生成前以及轻量模式返修/重生时的批次展示格式。所有视频生成确认的调用结构、选项和授权边界只以 `interaction-ask-video-clarification-ref.md` 为准；轻量模式首次生成不重复展示本文件两张表。

## 强制顺序

除轻量模式首次生成外，每次视频生成、重生、返修或继续下一批前，主 Agent 必须在同一条普通文本消息中按以下顺序展示：

1. 一张且仅一张本批次合并参数确认表。
2. 一张且仅一张本批次五列分镜表。
3. 立即按 `interaction-ask-video-clarification-ref.md` 调用一次标准视频生成确认。

两张表缺一不可。禁止使用散文、逐片参数块、旧规划表、内部 Prompt 文件或上一个批次的表格代替。确认前不得调用任何视频生成或编辑工具。

## 批次边界

- 每批只覆盖当前集接下来连续的 `1-2` 个 SEG，禁止超过 `2`。
- 两个连续视频共用一张合并参数确认表和一次 `interaction.ask`，不得分别制作两套参数确认。
- 两个视频允许时长不同，必须逐个 SEG 分别展示时长。
- 两张表只能包含当前批次，禁止混入已完成片段或尚未进入本批次的后续片段。
- 任一参数、分镜、台词、素材或时长变化后，旧确认失效；重新生成两张完整表并再次确认。

## 合并参数确认表

固定为两列 Markdown 表格 `参数｜本批次确认值`，至少逐行包含：

| 参数 | 本批次确认值 |
|---|---|
| 任务类型 | 完整模式统一写“长视频生成任务”；轻量返修或重生写“短视频生成任务”或“视频编辑任务” |
| 交付格式 | 本批片段的文件格式和交付方式 |
| 数量 | 当前批次真实视频数量，只能为 `1` 或 `2` |
| 分段时长 | 按批次顺序逐条写 `SEGxxx：N秒`；即使两段时长相同也分别列出 |
| 总时长 | 等于本批次各 SEG 时长之和 |
| 画幅与分辨率 | 当前批次真实参数 |
| 视频模型 | 当前批次模型及必要会员高消耗提示 |
| 视觉与连续性 | 当前批次共同视觉方向、角色或产品锁定特征及前后段连续关系 |
| 声音与字幕 | 当前批次配音、完整台词或旁白范围、音乐、音效和字幕策略 |
| 参考素材 | 当前批次实际使用的首尾帧、关键帧、角色、场景、道具、音频或待编辑视频 |
| 工具限制与消耗 | 当前模型或工具限制及视频高消耗提示 |

“数量”必须等于本批次五列分镜表行数、`planned_video_count`、`segment_durations` 项数及本次确认覆盖的 SEG 数。“分段时长”不得写成统一时长、范围、平均值或只写总时长。模型、画幅、分辨率、素材、台词、字幕和声音必须来自当前批次锁定执行包。

## 本批次五列分镜表

固定列顺序如下，每个 SEG 恰好一行：

| 片段与时长 | 画面内容 | 主体动作 | 声音与完整台词 | 运镜与素材 |
|---|---|---|---|---|
| `SEGxxx｜N秒` | 本段起始局势、关键推进和可见结果 | 主体策略、对手或环境反馈、动作落点与尾态 | 本段全部对白、旁白、画外音、内心独白及必要声响；没有则明确“无” | 主要镜头推进与切换、前后承接方式及本段真实输入素材 |

逐行要求：

- SEG ID 和时长必须匹配 `storyboard_ep_N.json`、本批 `segment_durations` 和实际请求。
- 每行是一个视频片段的简洁完整分镜，不是只有主题词的摘要。画面内容至少交代起点、推进和结果；主体动作至少交代行动、反馈和段尾状态。只能压缩当前 SEG 已确认的详细分镜，不得另写、借用其他批次剧情或漏掉本段结果。
- 声音与完整台词必须列全该 SEG 的 `speech_lines[].spoken_text` 并标明声音类型；禁止只写“有对白”“同剧本”或摘要。
- 运镜与素材必须说明主要观察方式、镜头切换或连续运动、片段承接方式，以及当前 SEG 实际使用的图片、视频、音频职责；禁止把待生成、未批准或其他批次素材写成已使用输入。
- 两个连续 SEG 的时长、剧情、动作、声音、运镜和素材必须保留在各自独立行中，禁止合并成一行。

## 记录与校验

本次实际展示原文完整保存到 `generation_confirmations[].final_parameters_text`。结构化同步保存：

- `confirmation_id`
- `attempt`
- `supersedes_confirmation_ids`
- `planned_video_count`
- `segment_durations`
- `displayed_parameter_table`
- `displayed_storyboard_rows`

字段结构读取 `manifests.md`。首次确认写 `attempt: 1` 和空的 `supersedes_confirmation_ids`；重生或返修同一 SEG 时保留历史记录，递增 attempt，并显式列出被替代的重叠确认 ID。替代只作用于新旧范围交集，不影响旧批次中未返修 SEG 的原确认。调用视频工具前运行视频阶段检查；数量超过 `2`、两张表数量不等于一、逐段时长与 SEG 不一致、总时长错误、五列表行数错误、台词缺失、表格混入其他批次或返修确认未建立替代链时必须阻断。
