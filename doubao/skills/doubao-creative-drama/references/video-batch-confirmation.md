# 视频批次参数与五列分镜确认

本文件只定义完整模式视频生成前以及轻量模式后续批次/返修/重生时的批次展示格式。所有视频生成确认的调用结构、选项和授权边界只以 `interaction-ask-video-clarification-ref.md` 为准；轻量模式首次生成沿用规划列表与全片预览，不追加一套批次展示。

## 强制顺序

除轻量模式首次生成外，每次视频生成、重生、返修或继续下一批前，主 Agent 必须在同一条普通文本消息中按以下顺序展示：

1. 一句简短开场白，说明本批准备制作或调整什么；编辑与重新生成按实际路径表述，不重复全剧介绍、规格清单或完整剧情，不声称已经开始或完成生成。
2. 一份本批次合并参数确认列表，使用 Markdown 无序列表；前四项固定为模型、时长、比例、数量，之后才是视频内容与其他必要信息。
3. 一张且仅一张本批次五列分镜表。
4. 立即按 `interaction-ask-video-clarification-ref.md` 调用一次标准视频生成确认。

开场白、当前参数列表与分镜表缺一不可；参数及其他说明使用 Markdown 列表或自然段，只有分镜表使用 Markdown 表格。禁止使用参数表格、逐片重复参数块、内部 Prompt 文件、上一个批次的展示或只有散文的说明代替当前列表与分镜。开场白与展示格式不增加确认问题；确认前不得调用任何视频生成或编辑工具。

## 批次边界

- 批次任务上限与授权范围只读 `interaction-ask-video-clarification-ref.md`；每次模型编辑调用同样计入任务数。当前集的 SEG 在本地 manifest 中按接下来的连续范围登记，不能漏计其他项目或编辑任务。
- 两个连续视频共用一份合并参数确认列表和一次 `interaction.ask`，不得分别制作两套参数确认。
- 两个视频允许时长不同，必须逐个 SEG 分别展示时长。
- 参数列表与分镜中的生成/编辑内容、逐段时长只能包含当前批次，禁止混入已完成片段或尚未进入本批次的后续片段。所属成片的目标时长和条数仅用于说明本批归属，不把整部作品、拼接或未来批次列为本次生成调用，不扩大授权范围。
- 实质变更导致确认不再适用时，按确认 Ref 展示变化并重做必要选择和生成确认；已确认范围内的执行细化不反复确认。生成确认前的分段时长细化须明确展示。

## 合并参数确认列表

固定使用 Markdown 无序列表，前四项顺序为模型、时长、比例、数量，随后展示内容和其他必要信息；字段显示名随项目输出语言本地化。以下是填写语义，正式展示须填入本批真实值，不能照抄方括号占位内容：

```text
- **模型**：[当前批次视频模型及必要会员/高消耗提示；不同片段采用不同已确认模型时逐段对应，不自行更换]
- **时长**：[先标本批所属成片的目标时长（适用且已知时），再逐条列出本批片段时长及本批合计；只交片段时不虚填成片时长]
- **比例**：[当前批次真实比例；不同时逐段明确对应]
- **数量**：[分别标明本批所属成片条数/集数和本批生成或编辑片段数；本批只能为1或2段；只交片段时明确不制作拼接成片]
- **视频内容**：[取自已采用分镜的本批核心内容，不临时扩写；编辑与重新生成按实际路径说明]
- **声音与字幕**：[本批采用的音色、音乐、音效和字幕设置；全部发声原文在下方分镜中列全，不用此项摘要代替]
- **参考素材**：[本批实际使用的图片、音频、视频及用途；如依赖同批前段结果，明确待其完成后取得真实素材]
- **限制与消耗**：[必要的模型或工具限制及视频高消耗提示]
```

任务类型、交付格式、分辨率、视觉与连续性不单列为固定用户参数项；执行需要的值及约束仍按既有规划、主表、真实 schema 和请求记录保留。具体动作连续性与转场放在分镜对应内容中，不另加一项重复说明。用户明确要求查看这些信息时按实际值说明，不另建参数表或增加确认。

“成片条数/集数”只计算本批片段所属的实际交付目标；同一条成片分成两段，本批写“成片1条；本批片段2段”，不能把片段当成新增成片。数量未知且与本批执行无关时，不猜全剧总数，只标明本批实际所属集号/范围；执行必需范围不明时仍按原交互 Ref 必要澄清，不新增数量批准步骤。

“本批片段数”必须等于本批次五列分镜表行数、`planned_video_count`、`segment_durations` 项数及本次确认覆盖的 SEG 数；机器记录的 `quantity` 始终只保存这个 `1|2` 整数，不保存成片条数或混合说明。所属成片数量与时长取自已有采用规划，并随本次实际展示原文保存，不新增计数状态或授权字段。

“时长”中的各 SEG 时长不得写成统一时长、范围、平均值或只写成片总时长，本批合计必须等于本批各 SEG 之和；目标成片时长另作明确标注，不用它代替本批合计。模型、比例、分辨率、素材职责、台词、字幕和声音来自当前批次已锁定的分镜与参数；真实资源已就绪的调用同步核对执行包，待同批前段结果的承接输入按下文明确依赖，不能要求后段执行包提前含有尚不存在的真实资源。

## 本批次五列分镜表

固定列顺序如下，每个 SEG 恰好一行：

| 片段与时长 | 画面内容 | 主体动作 | 声音与完整台词 | 运镜与素材 |
|---|---|---|---|---|
| `SEGxxx｜N秒` | 本段起始局势、关键推进和可见结果 | 主体策略、对手或环境反馈、动作落点与尾态 | 本段全部对白、旁白、画外音、内心独白及必要声响；没有则明确“无” | 主要镜头推进与切换、前后承接方式及本段真实输入素材 |

逐行要求：

- SEG ID 和时长必须匹配 `storyboard_ep_N.json`、本批 `segment_durations` 和实际请求。
- 每行是一个视频片段的简洁完整分镜，不是只有主题词的摘要。画面内容至少交代起点、推进和结果；主体动作至少交代行动、反馈和段尾状态。只能压缩当前 SEG 已确认的详细分镜，不得另写、借用其他批次剧情或漏掉本段结果。
- 声音与完整台词必须列全该 SEG 的 `speech_lines[].spoken_text` 并标明声音类型；禁止只写“有对白”“同剧本”或摘要。
- 运镜与素材必须说明主要观察方式、镜头切换或连续运动、片段承接方式，以及当前 SEG 将使用的图片、视频、音频职责；已有素材引用真实批准来源。同批前段尚未生成时，明确写“待 SEGxxx 完成后提取真实尾帧用于连续承接”等依赖，不伪造 FRM ID 或声称已经传入。该依赖声明只用于本批明确前段的生成后证据，不能替代缺失用户素材或未批准资产；批次确认与逐次就绪按 `video.md` 执行。
- 两个连续 SEG 的时长、剧情、动作、声音、运镜和素材必须保留在各自独立行中，禁止合并成一行。

## 批次确认记录

本次实际展示原文完整保存到 `generation_confirmations[].final_parameters_text`。结构化同步保存：

- `confirmation_id`
- `attempt`
- `supersedes_confirmation_ids`
- `planned_video_count`
- `segment_durations`
- `displayed_parameter_table`
- `displayed_storyboard_rows`

字段结构读取 `manifests.md`。首次确认写 `attempt: 1` 和空的 `supersedes_confirmation_ids`；重生或返修同一 SEG 时保留历史记录，递增 attempt，并显式列出被替代的重叠确认 ID。替代只作用于新旧范围交集，不影响旧批次中未返修 SEG 的原确认。
