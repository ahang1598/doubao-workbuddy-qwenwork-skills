# 视频阶段 Ref：生成与必要承接

完整模式按已确认的当前集剧本、资产与分镜执行；轻量模式先由规划和内部完整分镜准备本次 Prompt，再取得视频生成授权。本文件负责实际输入、五层 Prompt、受控委派和结果登记；两种模式都可分段生成，仅按后续实际需要提取尾帧，不安排生成后检查。成片拼接、混音、字幕和交付读 `delivery.md`。

## 当前工具链

### 视频起点与连续性

首段起点由分镜初始状态和 approved 资产定义；非首段先读取 planned `SEAM`，`continuous` 必须由上一段真实 `tail FRM` 承接，`elliptical` 则按明确的新时空或新认知起点开始。

连续接缝继承前段真实尾帧。只有图片输入时使用 image_to_video；有音频或视频参考时使用 media_to_video。只把本段所需素材作为实际输入。

当前可执行能力：

| 能力 | 当前用途 | 禁止误用 |
|---|---|---|
| `image_gen` | 无参考图时从项目语言描述生成新资产 | 不登记虚假参考图 |
| `image_edit` | 有参考图时生成或修订资产、承接候选图 | 不把编辑图冒充原始 FRM |
| `text_to_video` | 当前片段没有任何媒体输入时根据 Prompt 生成视频 | 有必须继承的图片、视频或音频时不得使用；非首段仅限 `elliptical` 且无必要媒体锚点 |
| `image_to_video` | 只有图片输入时生成视频 | 不得携带视频或音频输入 |
| `media_to_video` | 按真实接口接收图片、音频或必要视频参考；可搭配图片 | 不要求为选工具额外上传视频或音频；提交前核对实际 schema 支持当前输入组合 |
| `video_edit` | 仅按下文编辑合同修改指定单视频的具体画面内容 | 不改音频、风格、运镜等禁用目标；次数、时长例外和比例以编辑合同为准 |
| `Seed Audio 1.0` | 生成角色与旁白稳定音色 | 新生成人声时必须传入对应已批准 VOICE 并用 `media_to_video`；音色参考能力不可用时暂停受影响调用，不用文字兜底 |
| mediakit | mediakit 负责抽帧、拼接、ASR、字幕擦除和固定预设字幕烧录 | 不使用 FFmpeg、本地脚本或手工转码冒充正式媒体链路；不改变剧情和镜头职责，不默认替换合格原生人声 |

工具路由按实际输入与用途选择：续段仅图片输入时使用 image_to_video，有视频或音频参考时使用 media_to_video，只有尾帧和参考图时也不人为补视频或音频；仅图片生成使用 `image_to_video`，存在音频或必要视频参考时用 `media_to_video`；零媒体用 `text_to_video`；修改已有视频须先按下文编辑合同判断，符合全部条件才用 `video_edit`，其他创作修改重新生成。`continuous` 非首段因必须传入上一段真实 tail FRM，不属于零媒体路由；`elliptical` 非首段若确实没有任何必要媒体输入，可以使用 `text_to_video`。调用前读取所选工具实际 schema，核对输入组合并记录真实字段；若不支持所需组合，停止受影响调用并回报能力差异，不拿上一段视频、无关音频或虚假素材凑条件，也不擅自换模型。

## 执行顺序

1. 从唯一十五列逐镜主表提取本次 SEG 的镜头和全部人声。完整模式补读本段真正用到的导演总控卡与输入计划；轻量模式从既有规划继承本段相关的共用创作决定，再结合主表的局部变化和真实素材展开，保留人物信息、动作接触/结果及声画时序，不从用户概览反推或压缩成摘要，也不要求其他完整模式文件。分段在同一视频 manifest 组织，不另建一份逐镜时间轴；实际请求自足地写出必要基准，不能只提交内部文件引用。
2. mainagent 在本批生成确认前确定每段在整场戏中的职责、人物策略、观众应知与暂不揭示的信息及视听办法，按下文写定完整五层与逐镜 Prompt，不另建文件。真实媒体已就绪的调用准备最终 Prompt 和请求快照；依赖前段结果的后段提前写好完整 Prompt 模板及接续要求，只保留真实媒体引用和必要编号待绑定，不把剧情、台词、镜头或导演要求留到确认后补写，不伪造 FRM、路径或资源。
3. mainagent 展示当前批次的生成参数、片段和人声，按交互合同取得授权。完整模式的项目执行确认不能替代视频授权；全片规划也不授权后续批次。
4. 实际生成确认返回明确同意后，mainagent 按 `delegation.md` 在当前处理轮次通过真实委派工具派发本批已就绪任务，禁止直接调用视频制作/处理工具或仅文字承诺后结束。依赖前段真实结果的后段，待输入就绪后仅绑定到预先写定的 Prompt 模板和请求，再在处理该就绪结果的当前轮次实际委派；同批授权与方案不变不重复确认。委派不可用、失败或结果未明时按该 Ref 说明阻塞，不由 mainagent 代执行。
5. mainagent 收到每个成功结果立即交付。后续批次另取授权，成片目标按已确认的方案完成后期并交付最终版本。

## 批次授权与逐次就绪

- **批次确认前**：mainagent 写定本批每个 SEG 的剧情、全部人声、分镜、完整 Prompt 或仅待真实输入绑定的完整 Prompt 模板、模型、时长、规格、必要素材职责及先后依赖。依赖同批尚未生成结果时，展示“待 SEGxxx 完成后提取真实尾帧用于连续承接”，不能声称输入已存在，不填写虚构 FRM ID、路径或哈希。轻量首批还可列明需要新制的参考图或音色及其用途、模型、数量与消耗，依实际图片/音频授权准备；不能把视频授权扩展成未列明的其他付费任务。依赖声明不能跳过缺失的用户素材或冒用未批准资产，必要新增参考也不能记成已存在。
- **每次实际调用前**：该调用所需真实媒体必须存在。“已取得整批确认”不表示后段可以带缺失输入执行。缺尾帧时只等待或修复依赖该尾帧的调用，不阻止已就绪前段执行。
- **依赖就绪后**：mainagent 把此前已声明的依赖绑定到确认前写定的完整 Prompt 模板和请求，只补真实媒体引用及必要编号，核对它与已确认剧情、首态、不变量和工具能力相容，随后按 `delegation.md` 实际委派。该绑定不新增剧情、台词、镜头或效果，不增加任务数、不重复询问。真实结果使剧情、模型、制作路径或关键参数必须实质改变时，停止受影响调用，按视频交互 Ref 展示变化并完成必要选择与生成确认，不擅自迁就错误尾态。
- 批次展示、原始确认及实际执行记录分别保存：确认原文不事后覆盖，执行快照只记录真正提交的资源。不得把等待依赖写成已执行或已验证；执行代理不能自行编译后段或补造资源。

## 批次合同

每个片段在实际调用前必须具备以下条件；同批依赖未就绪的片段按上节等待，不要求其在前段执行前就拥有真实尾帧：

- 完整模式必须具备当前 `episode_id`、`project_data_card.json` revision、项目索引的当前单集条目、`storyboard_ep_N.json`、`source_manifest.json` 中与本集相关的输入记录、`asset_usage_ep_N.json`。轻量模式只要求内部十五列详细分镜、当前确认记录和实际使用的真实素材；分段与依赖直接记入视频 manifest。
- 完整模式当前片段命中的 `highlight_bindings`：绑定记录保留上游原文与对应镜号，Prompt 忠实转写本段实际承担的视觉、表演、声音兑现和结果回应；不把跨段亮点的全部环节塞进每个 SEG，不为余震另添停留镜头。不得用通用“震撼、电影感、情绪拉满”替代具体设计。轻量模式直接从十五列分镜对应镜头提取可见触发、变化、反馈和结果。
- `ep_2` 及以后各集的首个 SEG 必须读取 `00_制作控制/episode_seams.json` 中对应 `EPSEAMxxx`。`continuous` 跨集依赖必须绑定上一集真实尾帧及 SHA-256 并处于 `bound`；`elliptical` 跨集接缝不强制把尾帧作为视觉输入，但必须记录上一集结果、保留的不变量、允许变化、新起点和切换策略。集内起点与跨集承接分开登记，字段语义见下文 `incoming_episode_seam` 说明。
- 稳定片段 ID `SEGxxx`、绝对时间范围和完整镜头 ID。
- 已确认的十五列详细分镜，其中包含镜头职责、连续性和抽帧承接要求。
- 完整模式必须具备已确认的 `导演总控卡_ep_N.md`、分镜 JSON 的 segments/seams 及其中必要的连续性记录，并使当前镜头可追溯到对应表演、声音、色彩、切镜与连续性合同；轻量模式不创建这些文件，直接使用十五列分镜中的对应列。
- 完整模式必须使用已确认的角色、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具和风格；所有出场角色必须解析到数据卡身份与当前状态，主要场景和复现道具必须解析到 approved SCN/PROP 版本。一次性物件只写入 Prompt，不要求建立 PROP。轻量模式按需采用真实用户素材、可复用资产或必要新增参考，不补造数据卡与独立资产阶段。
- 已确认的视频模型、片段时长和画幅参数。
- 根据本次 `input_image_ids/input_video_ids/input_audio_ids` 选择的 `tool_mode`，且输入组合满足对应工具合同。

- 所有计划人声已完成朗读估时并标注类型。出镜对白要求对应角色真实开口；旁白、画外音和内心独白不驱动画面人物对该句做口型，不禁止同窗内另有已确认对白，具体按“人声与文字合同”分配主次。字幕默认关闭，只有用户明确要求字幕时才在成片阶段处理；视频模型阶段始终禁止直接生成字幕；需要新生成人声时必须实际传入对应已批准 VOICE 并走 `media_to_video`；缺少音色或参考能力时暂停受影响调用，不用文字或静音替代。

批次任务上限、生成授权及下一批确认统一读取 `interaction-ask-video-clarification-ref.md`，当前集 SEG 的展示和本地范围记录读取 `video-batch-confirmation.md`。调度按 `delegation.md` 区分独立任务与真实结果依赖，不能仅凭编号连续便假定可以并行，也不要求所有任务一律串行。

任一项缺失、版本未确认或能力与工具 schema 不符时停止生成，返回对应阶段修复。

## 模型、时长与画幅

模型、片段时长、画幅、批次上限和例外理由必须直接继承已确认规划与 `storyboard.md`，并在调用前用所选视频工具的实际 schema 复核。本阶段不得重选模型、重算镜头数量或为适配调用擅自改时长；模型继承包括用户直接指定或在前置方案选择中选定的有效结果，不能仅因用户最初未指定就覆盖其后续选择。

片段边界必须落在已确认镜头切换点；画幅只进入工具参数，不写进 Prompt。模型默认值、用户指定或前置选定模型的条件、时长能力及会员提醒只读 `interaction-ask-video-clarification-ref.md`；方案选择不能代替实际生成确认。模型能力与已确认计划不兼容时停止调用并返回规划或分镜，不静默换模型、压缩剧情或突破时长上限。

## 入站连续性

场景与画面一致性由四层控制：

1. **项目数据卡**：SCN 锁定空间拓扑、固定陈设和基础光位，状态时间线记录合理变化。
2. **共享场景参考**：每个主要 SCN 使用同一批准布局图，不在各集重新生成。
3. **必要尾帧**：只有下一次调用需要连续承接时才提取实际尾帧；其来源与可见状态用于输入准备，不作前段质量判断。
4. **下一段承接**：从实际 `tail FRM` 继承角色在场景中的位置、姿势、朝向、动作相位、道具状态和光位；首镜按已确认切点延续或改变观察位置，不把构图、景别和机位一律锁死。世界中的人物与物件不能借切镜移动，画面投影随合法机位切换可变，空间与视线关系仍须读得懂。

尾帧输入的具体用法按当前转场与真实接口确定：

- **状态参考**：下一段从同一剧情时刻切到特写、反打或其他已规划机位时，真实尾帧用于锁身份、空间和动作状态；在现有 `opening_binding/adopt/exclude` 写清新首镜取景、视线/动作匹配及不继承的旧构图。输入职责名 `previous_tail_as_start_frame` 保留用于登记尾帧来源，不能单凭名称把参考图声明成接口的固定首帧。
- **固定首帧**：确需同构图续接且工具有相应能力时，才将尾帧绑定为实际首帧，动作立即继续；不重演上一段末拍，不添加稳定停留。
- 调用前核实图片在真实接口中承担参考图还是固定首帧。仅支持固定首帧而计划要求直接换机位时，返回分镜调整切点与分段，不插入无意义推拉或转向来迁就输入；通用参考图也不等于保证像素级首帧复刻。保持已确认剧情、时长、生成授权及模型边界。

### 长视频逐段连续继承算法

适用于两种模式的连续续段；完整模式跨集首段还读取 `EPSEAM` 的既定承接要求。轻量模式同样遵循方法，结论直接记入当前视频 manifest，不建完整模式账本。

1. 读取采用故事、逐镜主表、必要素材和当前边界的 `seam_mode|required_invariants|permitted_deltas|transition_anchor`。连续续段等待上一段真实尾帧，省略转场按明确新起点准备；不能因为输入未生成把连续段改成纯文本生成。
2. 只为下一段输入读取尾帧可见的身份、服装、位置/朝向、动作相位、道具归属/开合/接触、空间与光位；不把看不到的中间事件或台词记成已验证事实。结合已定剧情与首镜决定继承项，正常反打/景别改变不要求先复刻旧构图。
3. 连续接缝真实传入 tail FRM，职责登记为 `previous_tail_as_start_frame`；按工具实际能力区分状态参考和固定首帧。省略转场只传新起点必要图片/音频。需要的输入与当前素材冲突时，只处理该调用的输入问题，不启动对前段的审片或自动重生。
4. Prompt 第一层写真实素材职责与起点，第二层写本段行动/反馈/结果，第三层依原镜序立即推进、不重演上一段末拍，第四层写动作/声音桥与尾态，第五层写身份、空间、光色、声音不变量和禁区。信息各有职责，不重复堆入每层。
5. 在当前视频 manifest 和实际请求中保存来源段、版本、帧路径/时间、真实输入顺序与继承说明。实际图片标记随上传顺序同步。

缺真实必需尾帧、必要素材、有效授权或接口能力时只暂停受影响调用，复用成功结果。原始尾帧不经美化后冒充真实状态；用户要求制作派生参考图时另存版本并保留原图，遵守对应生成权限。不以文字引用代替真实图片输入，也不因续段自动上传上一段视频。

## 图片输入合同

| 场景或问题 | 当前路径 | 处理 |
|---|---|---|
| 无任何媒体输入 | `text_to_video` | 只传 Prompt 和生成参数；不得登记图片、视频或音频 ID；非首段仅限 `elliptical` 且无必要媒体锚点 |
| 续段仅有真实尾帧或其他参考图 | `image_to_video` | 按连续性计划传入真实图片 |
| 普通仅图片生成 | `image_to_video` | 用户提供视觉锚点时，须将内容不变的原始图片作为实际输入，禁止裁剪、重绘、拼贴或仅用文字替代 |
| 存在音频或明确采用的动态视频参考 | `media_to_video` | 只传本段必要资源；视频参考不是续段默认项 |
| 符合全部编辑合同的具体画面修改 | `video_edit` | 只传指定单视频，遵守最终成片累计次数、原比例及原时长例外；禁用目标不走此路由 |

## 生成质量目标

每个 `SEGxxx` 的目标来自整场戏的当前进度。中段可直接承接试探、操作或追逐，不必重做开场钩子；一项证明或回报可以跨 SEG 完成。沿用现有记录，不新增创作表：

```json
{
  "quality_target": {
    "hook": "",
    "evidence_or_clue": "",
    "credible_action": "",
    "visual_payoff": "",
    "closing_beat": ""
  }
}
```

- `hook`：本段接入的具体未决行动或问题；全片开头才承担首次吸引任务，中段直接写承接点。
- `evidence_or_clue`：本段已有的证明、线索或关系证据及镜号；不承担此项时写清“不适用：本段承担……”，不新造线索。
- `credible_action`：人物当前办法、对象与反馈，符合动机、空间和已建立的世界规则；动画形变或奇幻能力依本片规则，不强套真人物理，也不允许无规则穿模。
- `visual_payoff`：本段实际完成的揭示、反差、动作或关系回应；主要兑现位于后段时说明本段的具体推进和既有后段镜号，不提前揭底或强加一次反转。
- `closing_beat`：真实落点与待续行动；中段可以未完，不要求封闭式收尾或尾部停留。

适用内容须对应可观察镜头；不适用说明不能代替本段应有的进展。具体进展按下文动态执行要求判断，不能用“制造悬念、情绪升级”等标签交差。调用数量、总生成时长、重试上限及可核实的费用/额度信息进入批次确认；没有可靠价格时明确写“无法准确估价”，不得猜测。

视频模型的会员提示及生成确认按 `interaction-ask-video-clarification-ref.md`。图片会员模型在参数确认时紧跟模型名告知用户：`seedream 5.0 pro（会员模型并且消耗最多的额度）`；缺少该提示或用户未确认时不得调用对应图片模型。

### 场景四维怎样改变观察与衔接

沿用剧作库的四维判断，不新增场景分类文件：

- **开放度**：封闭空间保住出入口、距离、遮挡与控制关系；开放空间保住本次路线、目标方位及跨地点行动因果。换场时只补辨认当前行动所需的定位，不每次先来一段风景慢推。
- **熟悉度**：熟悉处境省略无用介绍，但本片特殊布局或规则仍须可知；陌生处境先拍影响眼前选择的一次规则使用/反馈，不用设定旁白阻断正在发生的事。
- **压力值**：高压让危险、可用办法与行动反馈可读，关键信息不能被碎切/声效淹没；低压让小愿望与回应、失误或趣味持续发生，不能把“低压”解释成低信息和慢动作。
- **时间感**：线性接真实动作进度；循环区分重置项与保留项，重复部分按已定省略压缩，只强调本轮变化；碎片化依已定时空/视点标识和证据顺序呈现，不能为“神秘”隐去基本辨认条件。闪回或主观想象只继承该层事实，不能把其中状态直接当成现实尾态。

### 人物互动、注意顺序与视听落点

1. **从关系意图写表演**：提取已确认的“谁想让谁做什么、用什么办法、对方怎样回应”。例如同是微笑说“没事”，接受帮助、礼貌退让或掩饰试探需要不同视线、手部和距离；只采用本片已定的一种，不同时堆笑、皱眉、低头和流泪。倾听者的阻挡、接物、避让或反问可以与发声并行，不能说完一句才全员依次做表情。
2. **让重点在需要的时刻可读**：物证、交接、动作接触或表情转折是当前判断依据时，构图/景别/遮挡/焦点先保证它可辨。分别落实观众何时能辨认、人物何时有依据地反应；两者依已定知情顺序，可以观众先知，也可以角色先知后向观众揭示，不强排成一条固定顺序。需要转移重点时，用既定接物、视线或位移把注意从一个对象交给另一个；非重点人物可以继续幅度较小的任务或自然静止，不要求全员同时抢戏。关键手势、接触面与身体轮廓从最终观察机位须可辨，不能只在文字里发生、实际被身体或道具遮住。在应当读懂的时刻，不能被闪光、别的动作或切镜抢走注意，也不擅自延时或抢先揭示。主观画面、误导与延迟揭示按已定叙事层级处理，人物不能使用自己尚未得到的信息。
3. **把辨识度落在既有设计上**：优先保住项目签名中的独特操作、空间用法、视点、声画反差或视听回扣，写出在哪个动作/声音接点显效。普通镜头为重点建立对照，不能每镜同时大运镜、强逆光、粒子特效和音乐重击；宏大场景需要的尺度、层次与人物处境也须来自已定分镜，不随意添加大场面。
4. **声音参与动作和判断**：需要听清台词时音乐/环境不抢字；接触声须与实际接触对应，已定声画反差须保住含义。声源在画外时写清来自谁/哪里，距离和阻隔沿用既定听觉位置，不能一切近景就让远处声音突然贴耳；主观听觉按已定进入/退出处理。下一场声音先进入当前画面（J cut），与同场人物在画外说话不是一回事；前一句延续到听者/结果画面（L cut），原句只说一次。写清声音归属、覆盖镜号及人物是否实际听见，不让人物对另一时空的声音无依据地反应；跨独立 SEG 的声音桥还须有可用真实音轨及授权处理能力，不能用文字承诺自动拼好。音乐的进入、变化、退出跟既定选择或结果，不默认全段铺满、每切一镜重启；无配乐、对白密集或行动无台词均依实际方案。不能用持续旁白解释镜头本该拍清的因果，也不强迫每个已定环境声都引发人物反应。
5. **先核实能否执行**：确认当前工具能否完成采用的参考职责、口型/音频、关键文字、运动与时长组合；未知能力不当作保证，决定理解的动作不靠含混词躲开。真实限制与分镜冲突时，只返回受影响项提出具体取舍，保持有效上游与已成功结果；不得暗删情节、加时、换模型或突破生成确认。

## 片段内镜头与运镜执行

把分镜按 `SEGxxx` 分组后逐镜编译，禁止摘要式合并。每个时间段按以下顺序写：

```text
镜号与顺序/片内时间 -> 本镜承担的行动/证据/反应 -> 必要景别、机位与摄影动作 -> 本镜状态或信息增量 -> 需要时补声音、人声与相邻镜头承接；全局身份、光色与禁区集中写一次
```

- 分镜中每个镜头独占一个首尾相接的计划时间区间，总和等于片段时长；模型适配的表达按下文“时间预算与模型适配”。
- 切点依据保留在分镜；编写相邻镜头时落实采用的前后关联，例如“她收回正在递出的钥匙，目光落到门边”之后，下一镜直接让门边对象和正在发生的反馈可读，不只写“切换角度”。只有需要额外说明的动作或声音承接写在第四层衔接说明中，不在每镜重复全链条；承接锚点从动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中选择。切镜不重置动作、重说台词或自动制造反转。
- 跨镜动作按 `storyboard.md` 的连续或明确省略方式编译：决定成败的接触、反馈和结果须可读；观众已知的准备与移动可消费已确认省略，不擅自补回全流程拖长。连续切镜接同一动作进度，禁止手、人物或道具无依据瞬移。
- 相邻镜头的主运镜、景别、角度或焦点职责至少一项发生叙事性变化。
- 真正一镜到底只能有一个镜头，必须从头到尾同一次连续拍摄，禁止硬切、隐藏切、遮挡伪切、匹配剪辑和时间跳跃；按已确认连续摄影机路线、主体行动与观察重点迁移写明进展和落点，节点数量只服从分镜与 `pacing.md`，不另设配额。
- 场景和角色描述使用稳定名称，不使用“同上”“还是那里”“那个人”等模糊指代。
- 每镜把主表中的具体事件完整转成可见、可听的导演描述：当前是谁在对谁或什么做哪件事，对方或环境怎样回应，观众在何处看清本镜的新进展；再写服务事件的景别、机位与必要摄影要求。不能把“试探、反制、关系升温、紧张升级”等标签当作动作正文，也不能把多个已定应对压缩成“双方争执后和解”。移动镜头写路径、方向、显露的内容与落点；固定镜头写观察位置和清晰对象，不强迫每镜运动。只写“推近人物，气氛紧张，电影感”没有落实事件，须按原分镜展开，而不是临时添加新剧情。
- 运镜家族只用于描述计划与实际执行，观察和运动取舍按 `storyboard.md`，不为增加家族种类补运动。最终 Prompt 的导演描述默认使用 `drama_plan.json.language_contract.video_language` 确定的项目视频语言；用户明确指定 Prompt 语言时遵循该要求，并在已有 `language_contract.explicit_overrides` 中记录，不因此改变视频人声或字幕语言。已锁定的台词、歌词和画面文字按原文及其指定语言保留，不因导演描述语言变化而翻译或改写。内部运镜术语须转为对应语言的具体自然导演描述；例如，导演描述使用中文时，将 `tracking` 写为“摄影机在角色右侧保持一米距离，与角色平行向门口中速侧跟”；使用其他语言时，用相应语言表达相同摄影要求。固定镜按实际观察位置编译。镜内连续移动、重构图或移焦不擅自增拆镜号，已确认真实切镜也不合并；同一句跨镜人声只按其连续发声窗口写一次，不因换镜重说。

## 镜头密度与片段内切镜

节奏与密度基线只以 `pacing.md` 为准；摄影与切镜执行见 `storyboard.md`。Prompt 阶段不得重新规划镜头数量或修改阈值，只执行已确认 `shot_plan`：

- 保持镜头顺序、已确认时间预算、可见事件与必要摄影要求，时间表达按下文模型适配；分镜中影响理解的动作桥、切镜原因和承接锚点不得丢失，通用不变量集中写一次。每个已确认镜头在最终 Prompt 中恰好出现一次。
- 不因生成方便合并计划镜头、截断台词或把多个镜头退化成统一慢推。开头从已定事件入点开始，片内切换接真实动作/声音进度，结尾在已定有效落点结束；不自行添加空镜铺垫、切后等待、动作重演或稳定尾帧来填满时间。若计划本身仍有空耗或衔接缺口，返回分镜修相关项，不在编译时暗改镜头或剧情。

### 时间预算与模型适配

分镜秒数用于判断容量、安排人声和追溯镜头，不是模型已按这些秒数生成的证明。保持一份最终 Prompt，不另存一份删镜的“简化执行稿”：

- **先区分集内与片内时间**：分镜与 manifest 保留本集绝对时间；单次生成 Prompt 使用时间码时，镜头窗口、人声覆盖和声音事件统一换成当前 SEG 从 0 开始的时间，镜号不变。例如本集 30–45 秒的 SEG，镜头 32–34 秒应写为片内计划 2–4 秒，不能让一个 15 秒请求在第 32 秒才开始。换算只减去该 SEG 起点，不改变事件相对顺序或预算；2.0 优先再按下一条转为镜头顺序，不新增第二份创作源。
- **Seedance 2.0 / 2.0 fast**：计划窗口保留在既有分镜/批次记录，最终 Prompt 优先写“镜头 SHOT_ID｜第 N 镜”，用实际切出事件和必要的快慢关系组织顺序，不逐镜强制小数秒窗口。第三层开头说明“按以下镜头顺序推进，在指定动作/信息到达时切换，不为凑时长等待”；人声按所属镜号与跨镜覆盖表达，不再叠加“必须到第几秒开口/结束”的硬承诺。不删镜、不改变总生成时长或原计划容量，也不把“自然节奏”解释成任意拖长；省去模型侧硬时间码不等于省去上游预算。
- **Seedance 2.5**：可按时间轴组织，同样围绕可读动作、完整发声和计划切点编写，不能承诺毫秒级兑现。实际参数及输入组合仍以宿主 schema 为准，不把公开指南的输入上限、首尾帧参数或建议时长直接移植为本工具能力。
- 若批准设计依赖不可错开的精确同步、超过当前能力的并行操作，或必要内容在预算内无法读懂，生成前返回受影响分镜说明取舍；不自行放慢、删内容、增加调用或切换模型。

## Prompt 五层写法

主 Agent 在本批生成确认前直接从已确认十五列分镜撰写完整自然语言 Prompt；依赖前段结果的后段也先写定完整模板与接续要求，真实输入绑定按本文件“执行顺序”处理。请求就绪后，主 Agent 将唯一最终 Prompt 原文保存在实际请求快照的 request 参数字段中并交给 subagent，由 subagent 原样调用指定工具提交，主 Agent 不直接提交视频生成或编辑请求。以下五层对应输入与起点、本段目标、逐镜内容、衔接尾态、一致性禁区五项职责，按此顺序写自然导演描述；第三层每镜单独成块，不为凑五个自然段挤成一大段。模型、工具、生成模式、比例和调用参数留在实际请求参数中，不把 Prompt 写成 YAML、参数表或内部执行说明。不增加另一份 JSON 镜头稿、不要求编译脚本，也不让执行 subagent 重写。

### 先写什么，写到哪里

| 层 | 只承担的职责 | 避免混入 |
|---|---|---|
| 1·输入参考与起点 | 按真实顺序说明本段输入、采用/剥离维度；音频点名所属主体及仅参考声线的用途；写清0秒人物位置、朝向、姿态、道具与空间状态；无媒体如实说明 | 全段镜头、后续剧情、虚构素材编号 |
| 2·本段目标 | 必须发生的行动、反馈和结果；让观众理解什么 | 所有外貌、光色细节与长篇背景 |
| 3·逐镜时间轴 | 按分镜顺序，每镜写镜号、模型适配后的顺序/时间表达、可见行动/证据/反应、必要摄影和实际人声 | 将多镜摘要成一句“随后发生一连串事情” |
| 4·衔接与尾态 | 必要的跨镜动作/声音衔接，以及最后实际落在哪个状态 | 重演第三层、重新引入故事或全段复述 |
| 5·一致性与禁区 | 需要持续保持的身份、空间、媒介和禁止项，集中写一次 | 给每镜添加统一慢推、凝视、呼吸或停顿 |

第三层逐镜以“镜头 SHOT_ID｜”开头：2.0/2.0 fast 后接“第 N 镜”，2.5 可后接片内起止秒数，具体按“时间预算与模型适配”。每镜先写可见事件，再写服务该事件的机位/运镜；不要求每镜都有完整起势、接触、反馈和结果。台词贴在实际发声镜头中，明确说话人；跨镜完整台词只写一次，注明声音覆盖到哪一镜，原句不拆改。出镜对白写明主体、对应真实<音频N>声线、口型职责和{完整原文}；旁白/画外音/内心独白也绑定各自真实音频并写“该句不驱动画面人物口型”，具体句式按下文人声合同。音色音频只参考声线，不额外播放样音原句、不把样音语速、停顿或情绪固定到正片；正片表演按本句变化。

### 完整写法示例：15 秒《门内的声音》

下例用 2.5 的片内时间轴表达示范五层职责；用于 2.0/2.0 fast 时，按上文改成逐镜顺序与切出事件，保留全部镜号、内容和上游预算，不照搬逐镜硬时间码。此例不规定默认镜数或节奏。

以下示例假设对应事件、八镜分镜及林晓音色均已确认；林晓的同一适用已批准音色在本片其他片段继续复用。当前真实传入<音频1>，不因参考音色额外加入其样音原句；门内声音按已确认剧情故意使用相同声线，两名发声主体均显式绑定该参考。此例不是当前已有素材或授权，实际任务须替换为真实输入。它仅演示转写方式，不能临时套进别的故事。它用问话引出矛盾、用假离开诱发行动、用对应物证确认危险，最后让主角采取反制；切镜服务这些变化。

```text
## 1·输入参考与起点
<音频1>是已批准的林晓音色，只参考年轻女性的清亮中音、普通话和稳定咬字，不额外播放或复述样音台词，不固定其语速、停顿与情绪；门内声音按本片设定也使用该声线，不继承样音背景或其他声音。没有图片或视频输入，不编造对应编号。真人悬疑。林晓站在自家门外，钥匙还握在手中；门内已有脚步声。门的开合方向与人物位置从头到尾一致。

## 2·本段目标
林晓发现门内的人使用与自己相同的声音；她假装离开，诱使对方伸手开门，看见相同的红绳后关门反锁，把威胁暂时困在里面。

## 3·逐镜时间轴
镜头 E01S01-SHOT001｜0–1.5 秒
钥匙尚未插入，门内锁舌先响。钥匙与门锁同框近景，让观众立刻看清异常；没有空镜铺垫。

镜头 E01S01-SHOT002｜1.5–3 秒
切林晓贴近门侧的半身，她把钥匙停在锁前。林晓按照<音频1>的声线警觉地真实开口说出{谁在里面}，驱动她可见的口型。

镜头 E01S01-SHOT003｜3–4.5 秒
切门缝，门内脚步停住。门内声音以画外音按照<音频1>的声线回答{我是你}；该句不驱动画面中林晓的口型。

镜头 E01S01-SHOT004｜4.5–6.5 秒
林晓退一步又侧身贴墙，保持手能碰到门把的距离。林晓装作离开，按照<音频1>的声线真实开口说出{那我走了}，驱动她可见的口型；脚步声与动作并行，不留站定等待。

镜头 E01S01-SHOT005｜6.5–8 秒
切门把特写，它立刻从里面转动；林晓的手从画面侧边接住外侧门把。假离开得到对方行动反馈。

镜头 E01S01-SHOT006｜8–10 秒
门开一条窄缝，一只戴红绳的手探出；林晓握住门把不再让门扩大。近景看清红绳，保持手与门把的接触关系。

镜头 E01S01-SHOT007｜10–12 秒
沿林晓握门把的手切到她腕上相同的红绳，再抬到她收紧的手指；她不长时间凝视，立即决定关门。

镜头 E01S01-SHOT008｜12–15 秒
回到门侧中景，门内的手缩回时林晓立即推门合上，把手中钥匙插入外锁并转动。林晓按照<音频1>的声线真实开口说出{那你先别出来}，驱动她可见的口型，说话与反锁并行；锁舌落下作为本段结果。

## 4·衔接与尾态
门把转动、接住门把、开缝、关门与反锁按同一门的方向连续承接，不重复开门。最后林晓仍在门外，钥匙留在外锁上，门已反锁，门内声音安静下来。

## 5·一致性与禁区
声音身份：林晓与门内声音按已定剧情分别作为两名主体发声，均以实际输入<音频1>为声线依据；文字音色描述只补充说明，不替代该音频。逐句情绪依剧情变化，不额外播放或复述样音。林晓的身份、服装、红绳与门外空间保持一致；门内手属于未露面的对方，不复制成林晓多长一只手。禁止拼版、字幕、水印、随机文字和无事件慢推；不加停顿填满时长。
```

`video_edit` 仅使用下文编辑合同及原样执行原文，不套新片五层；mainagent 核对修改范围、累计次数和实际提交原文。

上例用于 2.0/2.0 fast 时，第三层保留全部八镜，开头统一声明按顺序在动作/信息到达时切换，不为凑时长等待。以下仅示范第四、五镜的转写，不能把这两镜单独当成完整请求；预算仍留在原分镜中，其他层不变：

```text
镜头 E01S01-SHOT004｜第4镜
林晓退一步又侧身贴墙，保持手能碰到门把的距离。林晓装作离开，按照<音频1>的声线真实开口说出{那我走了}，驱动她可见的口型；脚步声与动作并行，假离开的动作成立后立即切门把，不先站定等待。

镜头 E01S01-SHOT005｜第5镜
门把立刻从里面转动；林晓的手从画面侧边接住外侧门把。特写让这次转动与接住的接触可辨，接住后切到已定开门缝动作，不重复转动或额外停留。
```

## 人声与文字合同

- 人声覆盖继承 `SKILL.md` 与已确认剧本：短剧优先以有效对白和适合场景的人声参与推进，微电影/短片依叙事主轴选择；先核对具体语言交锋与行动安排，再分配 SEG，不用句数或全程发声比例代替判断。已确认的无台词行动段使用 `speech_lines: []`，不设置要求新生成人声的 `native_required`，在现有声音说明中落实行动声、环境声或其他已采用声音；不新造 `speech_mode` 枚举，也不为填字段增写台词。呼吸、反应声作为表演/声音处理，不伪装成四类语言台词。
- 完整模式每个需新生成人声的主体在 `project_data_card.json.voices[]` 中只有一个当前 `VOICE ID` 和 `voice_anchor`，每条新生成 `speech_lines.voice_anchor` 必须逐字复制数据卡中的该值。已授权原片解说中保留的演员台词/原声按来源媒体及时间码引用，不改列为待生成人声，不要求新建演员 VOICE 或重说原台词；新增解说者仍按新生成人声准备。轻量模式不创建项目数据卡，声音身份、已批准音色版本及采用依据从已有规划、十五列分镜与真实音色来源记录继承，具体准备按 `assets.md`；不因轻量模式省略必要音色。稳定身份仅包含年龄感、音高与音色、语言/口音和稳定发声特征；语速、停顿与情绪按台词变化，详见 `pacing.md`。
- 需要新生成人声的片段必须核实实际接口支持把音频作为对应主体的声线参考，并支持与本段必需图片等共同输入；仅能作配乐或替换整轨不算满足。确认具备所需能力后记录 `audio_input_supported: true`，每次实际传入对应已批准 VOICE 并使用 `media_to_video`。缺少资源、批准依据或接口能力时暂停受影响调用，说明缺口并按现有规则补齐或由用户选择可执行方案；不得只写文字音色、借用上一段声音、静默换模型、改无声或后配。`audio_input_supported: false` 不能作为继续新生成人声的降级许可；无台词片段也不因此变成静音。
- 同一主体从首个有人声的片段起，跨段、跨集复用同一适用的已批准 VOICE；对白、该人物的OS及VO默认使用同一声音身份，独立叙述者单独绑定。每次调用的 `audio_inputs` 保存实际传入资源与文件，`voice_inputs` 逐人映射 `voice_id/resource_id`；Prompt 中<音频N>对应本次真实音频输入顺序。多人不得串用参考，无该主体人声时不上传其 VOICE。VOICE ID、文字描述、前段尾帧或历史调用都不能替代本次音频输入。第五层按主体声明一次固定 `voice_anchor` 仅作补充，逐句仍绑定真实<音频N>，不重复整套年龄、音高与音色。
- 需要新生成人声的生成片段必须先确认 `native_audio_supported: true`；不支持时停止并返回参数确认，由用户决定是否改模型或接受无声/后配方案，禁止自主换模型。仅保留授权原片声音的证据片段不触发此生成能力要求。
- 对待新生成的人声设置 `speech_mode: native_required`，相应 `speech_lines` 的 `type` 只能是 `on_screen_dialogue`、`narration`、`voiceover`、`inner_monologue`；每句同时保存 `voice_id`、`voice_anchor`、原始 `source_text`、带标点 `display_text` 和无标点 `spoken_text`，用 `delivery_intent`、`pause_plan`、`emotion`、`emphasis_words` 表达表演增量；保留原片声音不改登记为待生成 `speech_lines`。
- 四类需要新生成的人声均由视频模型原生生成并使用 `{完整文本}`；出镜对白驱动指定角色口型，其余三类写“该句不驱动画面人物口型”。画外角色可在场景外实际说话，内心独白属于指定人物主观声音，旁白按既定叙事视角；不要将三者都演成全体人物闭嘴凝视。保留的授权原片人声不交给视频模型重生成。
- 待生成 `speech_lines` 中每条 `spoken_text` 必须逐字以 `{spoken_text}` 出现在实际请求快照取出的 Prompt 原文中。只有结构化字段中存在、但实际 Prompt 没有对应花括号台词，按“台词未提交给模型”阻断；不得为满足此项把保留原片台词重新提交生成。
- 每句在实际发声位置绑定声音形式、主体、真实音频和口型职责。例如“人物对白（林晓，按照<音频1>的声线，驱动林晓可见的口型）：{完整文本}”“旁白（叙述者，按照<音频2>的声线，该句不驱动画面人物口型）：{完整文本}”；画外音、内心独白也按各自主体与真实音频写明。编号仅示范句式，实际只引用本次已传入且对应正确的音频。跨镜整句只写一次，注明声音延续到哪镜，切到听者或物件不重说、不强求画面出现说话嘴部。`【】` 是字幕源标识，禁止代替 `{}` 进入实际视频 Prompt。
- 口型只要求对应人物嘴部实际可见的发声时段。手部、物件或听者镜头可以覆盖既定对白，不能为证明每句都开口擅添正脸镜头或修改原分镜；声音主体、音色和台词类型仍按既定合同，不因换观察对象而更换。
- 抢话、叠话、OS 转对白及一句跨镜，只执行已确认文本、发声窗口与主次：写清谁先开始、哪里被打断或接话、哪句必须听清；同一人物从心声转开口时口型只从对白起点出现，不默认先停半拍。实际叠话会遮掉关键内容或接口不能承担时返回分镜调整，不在此强加叠话，不自行截断已确认原句。内心独白表达判断/误判时，其主观内容不能替代客观事件已发生的证据。
- 字幕与人声独立：默认最终 `subtitle_enabled: false`，同时视频调用固定 `video_generation_subtitles: false`；只有用户明确要求字幕时，才在成片阶段按 `subtitle_render_stage: final_mediakit_burn` 处理。必须保留全部计划人声，视频画面中禁止模型直接生成逐句字幕。
- 生成前直接对照采用剧本、逐镜主表及 Prompt 落实每句，返回后不安排逐句试听、口型核验或自动返修。
- 两种模式的音色均先查已批准版本复用，缺失时按 `assets.md` 准备并取得原有规则要求的授权和采用依据；轻量不补独立资产阶段。音色仅用于声线参考，完整正片台词由视频模型按已确认文本原生生成；不播放样音原句替代台词，不将样音节奏固定到正片，也不把传入音色当作跨段效果已经验证。生成后直接交付，不追加试听核验。

## 动态执行与有效进展

静态参考图不会自动产生动作；身体运动、变焦和画面变化也不自动等于剧情推进。逐镜先判断本镜承担的行动、证据、反应或必要空间观察，再忠实转写：

- 沿用 `observable_state_changes` 记录本段按实际职责承担的可观察进展，不设逐段配额，写具体事实而非“情绪升级”。例如“对手收走通行证堵住出口”与“主角用已露出的备用钥匙改走侧门”；不能把无关走动、眨眼、移焦各算一次推进。同一事件的两个不同后果可分别记录，不要求新增两件事。已确认的单一证据/反应或过渡短段只记录真实内容并说明职责，不复制同义句凑数，不因此降低常规剧情段的密度。记录中的有效进展逐项进入实际 Prompt。
- 上述单一职责不构成节奏豁免：时长与镜头仍执行 `pacing.md` 和已确认分镜。不能把常规15/30秒剧情段自行改名为“反应段”来只留一次凝视；内容不足先返回分镜安排有效覆盖，不延长证据停留或凑抽象状态词。用户明确的形式例外依原确认处理。
- 本镜的 `subject_action/state_change` 直接落实到时间轴，不另建逐镜 JSON。行动镜写主体、对象、正在完成的步骤及本镜切出状态；决定成败的接触、反馈和结果由同镜或相邻镜头共同拍清，不要求每镜重演完整“起点 → 过程 → 反馈 → 结果”。世界位置和动作相位依旧须连续或有已确认省略。
- 快动作仍须有足够辨认的发力依据、运动方向及受力/落空反馈；可借前镜已开始的动作或与台词并行承载，不每次另停下来蓄力。摄影机同速跟随不等于主体没移动，背景位移、距离变化和接触结果应支持判断；不能用整段运动模糊或闪光遮掉决定成败的接触。若当前机位无法拍清，返回分镜修覆盖，不以生成稳定为由统一改成慢走、轻抬手。
- 证据镜可以保持物件和机位稳定，写清本镜新露出什么、观众为何能判断及怎样接回反应；不为“动起来”让文字抖动、人物乱动或反复移焦。反应镜说明人物因何改变判断或办法，并有可辨的行为/语言证据，不只写“震惊”。空间观察镜交代随后行动需要的入口、距离、危险或路线，不以漂亮空景充数。
- 普通固定机位仍按实际事件发展；设计中的短暂持格、定格或静默按已确认呈现方式和时长执行，须有阅读、对照或叙事职责。常规剧情段不得用轻微呼吸、空等、慢推拉填满；同一对象的新信息已读完就按计划推进。用户明确要求的静态形式按其锁定项执行，不假装其中发生了动作。
- 台词与行动、倾听与反应可以同时发生。开头立即进入本段既定行动，中段持续有因果反馈，结尾落在已定结果/待续动作；不额外添加让角色“准备好”的停顿，不为尾帧好抽而让人物停住。

## 表演、声音与色彩的按需编译

每镜只编译与事件、人物策略和可见变化有关的表演、声音及光色增量；不重复所有脸部动作、呼吸、BGM 声层和色彩基准。共用基准放全局约束，逐镜写例外或变化。关键镜头可以更详细，普通证据/反应镜头保持清楚简短。声音身份与语速、停顿和情绪分离，详见 `pacing.md`。

### 文字符号

| 通道 | 强制符号 | 示例 |
|---|---|---|
| 出镜对白、旁白、画外音、内心独白 | `说话人：{原文}` | `旁白：{门已经开了}`，该句不驱动画面人物口型 |
| BGM | `()` | (低频弦乐缓慢进入) |
| 环境声、拟音 | `<>` | 门锁转动<金属咔哒声> |
| 逐句字幕源文本 | `【】` | 仅用户明确要求字幕时，从已确认 `speech_lines` 派生为【门已经开了】供成片 SRT；可在第五层声明其为后期字幕源，但必须明确视频模型不渲染 |
| 标题、章节、时间地点等画面文字 | 中文双引号 `“”` | 黑屏中央出现“十年前” |

同一内容默认只进入一个声音或画面文字通道。默认无字幕；只有用户明确要求字幕时，才在成片阶段生成无标点 SRT，且它不属于视频模型画面文字；`{}` 中的人声照常生成。只有用户明确要求气泡对话等剧情内文字时，才允许同一句同时作为人声和画面文字。

## 可选叙事过渡

可按剧情选择短黑屏、暗场、环境空镜、物件特写、声音先行或声音延续，承载时间跳跃、章节转换、记忆和内心活动；不是每段必用。黑屏/暗场必须写时长、叙事职责和进入/离开方式，不能替代应拍剧情。时间、地点或章节提示使用 `“画面文字”`，旁白或内心独白使用 `{人声文本}`；默认不生成逐句字幕，只有用户明确要求字幕时才留到成片阶段生成无标点 SRT。

## 不同场景类型的五层侧重点

所有类型仍使用同一五层，只调整时间轴层逐镜时间轴的重点：

| 场景类型 | Prompt 重点 | 注意事项 |
|---|---|---|
| 对话戏 | 建立轴线、视线匹配、说话动作、倾听反应和策略变化 | 不执行“每句台词一镜”；切镜可以转给听者、正在发生的操作、证据或空间关系，不必等说话人说完整句或先改变策略 |
| 动作戏 | 起势、位移、接触/落空、受力反应和结果，保持屏幕方向 | 复杂动作拆成可验证拍点，不能让一个镜头承担过多并行动作 |
| 情感戏 | 当前关系意图、具体回应，眼神/手部/距离随交锋变化 | 微表情与呼吸可和对白、动作并行；停顿仅在已定判断或回应需要时使用，不预装慢语速或抒情光变 |
| 悬疑戏 | 遮挡、POV、失焦/对焦、线索可见性和信息克制 | 公平线索先出现，不用镜头效果直接替代谜底铺垫 |
| 爽点/反转戏 | 本段承担的压力、证据、反应或权力/局势变化；让结果可辨 | 完整兑现可跨镜/跨段，不重复铺压与揭晓；慢动作、特写或定格只执行已定用途，不追加结果停留 |
| 空镜/转场 | 观众此刻需要的方位、时间/规则变化或声音来源 | 按真实输入路由；无角色不等于无叙事职责，不为转场重做无信息建立镜头 |

## video_edit 编辑合同

### 先判断编辑还是重新生成

mainagent 结合完整意图识别目标，不仅凭“改”“再来一版”决定工具。仅字幕和水印按原后期规则，截取、裁剪、规格探测及既定拼接按原技术处理规则；不通过 video_edit 完成这些操作。

整体调色、风格、转场、运镜、动作、表演节奏、镜头顺序或音频内容变化均走重新生成；另创故事、增加或删除镜头、修正剧情因果也不走 video_edit。不能忽略部分要求来迁就编辑条件；不能以技术处理名义完成上述创作修改。原来已授权的拼接、混音、声音桥等成片制作保持原合同。

只有以下条件全部满足才使用 `video_edit`：

- 用户明确指定一个真实可访问的已有视频，仅替换、删除或修改其中主体、人物、物体或场景等具体画面内容，并保留其余内容；不属于上段禁用目标。
- 本次必需媒体只有这个视频，不需要图片、音频或其他视频；不能丢弃必要输入来满足条件。历史用过但本次不需引用的图片或音频不计入本次输入，先图片生视频再仅删物体仍可判断首次编辑。
- 同一最终成片任务尚未成功调用过 video_edit，原时长和比例真实已知且符合下述条件，实际工具支持所需操作和已定模型。输入不可访问、规格未知或能力未核实则先解决，不能猜测或静默换模型。

### 次数按最终成片任务累计

同一视频任务最多成功调用 1 次 video_edit。单位是用户要求的一条最终成片；同一条视频的各生成片段、修改版本、输出 ID、重新确认和更换 subagent 均不重置次数。用户分别要求的独立视频分别计数，同一连续剧中不同最终成片分别计数。

mainagent 在已有视频记录与操作日志中关联原始输入、有效指令、同一最终成片及实际成功编辑调用；委派时传入已有累计次数，subagent 回传实际结果。成功以工具实际完成编辑为准，提交受理、运行中或卡片交付成功不作为计数依据；运行中或结果未明不重复提交。同一最终成片任务已有编辑在运行或结果未明时，不再提交其任何片段或版本的编辑；不能在一次授权中安排该成片的多次编辑。真实失败不计入成功次数，但失败重试必须重新取得生成授权。工具已完成编辑后，即使用户不满意或交付失败，也不再使用第二次 video_edit。

已成功编辑一次后的修改，按下节回溯原始素材重新生成或选择原规则允许的非生成处理；无可执行路径则说明并停止受影响步骤。不能先编辑各片段一次来绕过最终成片任务的累计上限。

### 输入、时长、比例与执行原文

- `video_inputs` 只包含一个真实源视频，不传图片、音频或音色；未要求改变的原声音、音色及口型关系保持不变。首次编辑可使用用户指定的刚生成视频，前面的生成不计为编辑成功。
- 先从真实元数据取得原时长和比例；不足时委派必要的正式探测，只回传数据，不启动生成确认或额外质检。真实规格和可行方案确定后再展示参数并取得生成授权。
- 输入超过 15 秒不使用此编辑路径，不静默截短。输出保持原时长；唯一例外是输入不足 4 秒时，工具输出按 4 秒安排，确认前须说明并核实必要截取能否恢复用户要求的成片时长，未解决不提交。该例外不是延长用户成片的许可。
- 输出保持原比例，且须为 `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` 之一，并核实工具真实支持。用户要改模型、时长或比例时不走本编辑路径，不静默裁切、拉伸或换参数；需要其他可执行方案时按交互 Ref 澄清。
- Prompt 原样传递当前有效的用户编辑执行原文，不删减、润色或追加镜头、台词、声音或字幕。用户明确选中已展示的方案时，传所选方案对应的编辑内容，不只传“第二个”；指代不清先按交互 Ref 澄清。输入顺序、保留要求、实际参数和授权范围在执行记录中明确，不把内部说明或资源 ID 混入 Prompt。
- 输出建立新 `_vNN`，不覆盖源视频；返回后由 subagent 逐项回传、mainagent 逐项交付，不安排生成后规格或内容核验。仅后续输入确需尾帧时按本文件第二部分处理。

### 重新生成时回溯原始输入

同一视频任务重新生成时，mainagent 必须以第一轮真实原始素材与生成指令为基础，合并此前已确认且仍有效的修改、本轮要求及素材，再按当前采用剧本和分镜准备完整请求。不能只传“调暖”“换动作”等本轮短句，也不能用刚生成或已编辑的视频替代原始素材。第一轮本来就是用户原视频参考时，该原视频仍按实际职责采用。

明确被替换的旧要求或素材不再沿用；冲突按交互 Ref 澄清，必需原始素材不可访问先补齐，不猜造。保留原始来源不等于强制上传所有历史素材：每次仍按当前镜头真实职责传入必要且有效的输入，需新生成人声时实际传入对应已批准音色，连续接缝仍传所需真实尾帧。生成 Prompt 继续按本文件五层规则编写，不把 video_edit 的原文传递规则扩展到新生成。

无新要求的“重来”“再来一版”沿用此前编辑/重新生成判断，再核对当前输入、规格及累计次数；已有一次成功编辑则必须改用上述重新生成路径。单纯不满意不自动执行。新增批次、修改版本、重新生成或失败重试，均按原交互合同展示本批参数并实际调用 `interaction.ask` 取得本次授权，不能沿用历史确认。同批已明确列入本次授权范围的片段和任务不重复确认，后续仅补入已约定的真实依赖素材，不改变已确认方案。

## 视频生成失败处理

失败类型、`V/A/F/S/N` 编号、重试预算和返回层级统一读取 `troubleshooting.md`。本阶段只负责保存旧 Prompt、修改变量、预期改善和实际结果；每轮只改变与证据直接相关的变量。

## 生成后交付记录

本阶段执行入口是上文“执行顺序”。结果返回后按模式保存、登记，主 Agent 按 `media-delivery.md` 直交真实结果；需要后续输入时才补充实际尾帧与来源，不创建结果验收或接缝审查记录。

## 存储与无歧义命名

路径、命名、视频清单字段和 manifest schema 只读取 `manifests.md`。mainagent 把唯一完整 Prompt 保存在实际请求快照的 request 参数中；subagent 按 prompt_field 取出原文调用指定工具提交，mainagent 保存真实执行记录及对应哈希。独立 Prompt Markdown 只按需派生展示，不作为第二份必备产物。实际模型、时长、输入资源、输出文件、版本和任务结果写入视频记录，不维护第二套命名规则。

## 输入模态复核

调用前依据 `reference_inputs/video_inputs/audio_inputs` 中的真实文件选择工具路由；输入变化后重新选择工具。

全部目标片段完成后按上文执行顺序直接进入交付或必要合成。视频 manifest 记录真实工具完成状态和输出，不把片段改为“已验收”，不在此运行阶段 lint 或要求用户确认结果。

## 第二部分：必要尾帧与输入准备

两种模式均仅在下一次调用实际需要尾帧时执行；单段视频、末段且无跨集连续依赖、明确省略转场且无尾帧职责时直接跳过。不得为完整模式自动抽取 start/scene/tail 全套，不创建接缝窗口、观察对比或质检报告。

1. mainagent 委派 subagent 使用实际宿主 mediakit `extract-frames` 的尾帧能力（如 `SpecifiedFrames` 的 `-1`），遵循真实 schema。由 subagent 保存任务 ID，用同一任务查询至 `completed`，及时下载真实返回图片并内部回传；mainagent 不直接调用抽帧工具，任务未完成不能伪称尾帧存在。
2. 仅在准备下一段输入时查看这张图，识别其可用参考内容，记录来源视频版本、时间位置、文件与必要可见状态。它不是前段合格证据，不据此验证中间剧情、台词或剪辑效果。工具返回的时间位置未知就如实记录未知，不伪造毫秒。
3. 必需参考不能使用时，只处理输入获取问题；不得悄悄选择更早帧并当成当前尾态，或启动前段回放、双侧帧比较和反复寻找“最佳切点”。输入仍无法取得则暂停依赖它的续段，如实说明；已完成结果照常交付，不自动重生。
4. 两种模式均将实际帧及源 SEG/版本、时间码、路径、哈希和使用关系写入 `video_manifest.frames[]`；本次实际输入仍在对应 `reference_inputs` 绑定，不另建连续性文件或重复 Markdown 清单。跨集连续依赖把真实来源绑定到 `episode_seams.json`，使用 `bound` 表示输入已绑定，不表示视频已审看通过。
5. 真正传入视频请求后才记录“已传入”；只存图片或写 Prompt 不算。按已定边界将该尾帧用于状态参考或固定首帧，不能从职责名推断接口保证像素级复刻。

抽帧只准备输入；成片按 `delivery.md` 使用既定顺序、计划边界和真实工具能力合成，不再寻找或复核 observed seam / verified cut。用户主动要求修改时再按其具体问题定位，不把排障变成正常生成后的固定步骤。

## 资料依据与适用边界

以下资料只提供创作和能力判断依据，不授权安装外部 Skill、扩大工具输入或修改当前确认流程：

- [Seedance 2.5 官方提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)：参考其按职责绑定素材、顺序/时间轴表达与多视图取舍；不把公开 API 能力等同于当前宿主工具。
- [Animation Mentor：角色调度与观看重点](https://www.animationmentor.com/blog/tutorial-use-character-staging-to-guide-viewer-focus/)：迁移重点交接与最终机位下关键姿态可读的方法；不要求所有人物同时运动，也不把局部静止扩大为全段慢节奏。

- [Johnnie Burn 的声音设计访谈](https://www.motionpictures.org/2024/01/the-zone-of-interest-sound-designer-johnnie-burn-on-creating-the-soundscape-from-hell/)：参考画外声音建立另一层叙事、人物可有意不回应的做法；不迁移特定影片的时长、题材或慢速观察方式。
