# 视频制作方案选择与 interaction.ask 生成确认

本文件是视频默认模型、前置制作方案选择、用户台词取舍、生成确认、批次授权与制作模式判断的唯一权威。批次展示格式见 `video-batch-confirmation.md`；执行主体、依赖调度与交付收口见 `delegation.md`；完整模式项目执行及实际重大方案变更确认见 `control-contracts.md`。这些确认不能互相替代。

## 适用范围与内容补全

前置制作方案选择只决定模型、分段和台词取舍，不是多个创意候选。除第 10 节影响故事规划的集数/组织方式澄清，以及本文件明确允许的制作方案选择、内容取舍、素材询问及用户主动要求的审阅外，直接依据需求和可用材料拟定一套完整内容，不因简短 brief、未给脚本、未定风格或规格不全而发创意问卷。未指定的内容与规格合理拟定后展示；事实、必需素材、对象 ID 和工具能力不得编造。

普通评价、偏好交流、创作建议和状态说明可以自然对话，不因收到反馈就发起询问。对象指代不明、锁定要求冲突、必需素材或事实缺口，以及其他必须取得用户答复才能继续的必要澄清，均由 mainagent 实际调用 `interaction.ask`；制作方案选择、素材询问和生成确认同样如此。已有答案直接继承，不重复询问，不将可由模型在未锁定空间创作的细节变成必要澄清。subagent 只执行已确认任务并内部回传，不向用户发问。必要交互能力不可用时停止依赖该答复的步骤，不能改用其他交互工具、聊天同意或展示 JSON 代替实际调用。普通创作阶段的采用确认仍按原控制合同，不能代替第 8 节的生成确认。

## 1. 默认模型

用户未明确指定其他模型，也未在制作方案选择中选定其他模型时，必须使用 **seedance 2.0 fast**，工具参数值为 `seedance_2.0_fast`。

不得因为成片时长、片段时长、素材类型、输入视频或音频、任务复杂度而自行更换模型。参考创作、单视频编辑等工具路径同样遵循这一默认规则。

用户明确指定或选定其他模型时，核实实际工具支持后遵循其选择。

当前制作方案按以下能力规划，执行时以实际工具的可用模型、参数和时长限制为准：

| 模型 | 单次生成时长 | 使用规则 |
|---|---:|---|
| seedance 2.0 fast | 4–15 秒 | 默认模型 |
| seedance 2.5 | 4–30 秒 | 用户明确指定或在方案选择中选定；必须说明“会员模型并消耗更多的额度” |
| seedance 2.0 mini | 4–15 秒 | 仅在用户明确指定时使用，不作为默认、降级或替代推荐 |

不能提供实际不可执行的模型或方案。某模型不可用时，不得擅自切换为其他模型。

## 2. 整体顺序

通常按以下顺序执行：

**读取已有要求并按第 10 节补齐影响规划的集数/组织方式 → 判断是否需要前置制作方案选择，必要时实际询问 → 完成内容规划 → 展示内容和制作参数 → 实际询问生成确认 → 执行当前批次。**

前置方案选择解决的是：

- 使用哪个模型。
- 是否分段生成并拼接。
- 是否保留全文、允许精简或允许延长成片。

**选择制作方案只授权相应规划和明确同意的文案调整，不授权调用视频模型。**

不满足前置选择条件时，直接使用默认模型或用户指定模型进行规划，不额外增加一道方案选择。

## 3. 什么时候必须前置选择

任务涉及新生成，且命中以下任一情况时，必须先实际调用 `interaction.ask`，以单选题选择制作方案。

### 情况一：用户明确要求单条成片超过 15 秒，且未指定模型

按**一条完整成片的总时长**判断：

- 用户要求一条 22 秒视频：触发。
- 用户要求三条互不相关、各 10 秒的视频：不因合计 30 秒触发。
- 用户要求完整保留一段已核实为 22 秒的音频，并据此制作对应时长的视频：触发。
- 用户已明确指定模型：不因超过 15 秒再次询问模型方案，直接核实该模型是否支持并规划。

不能通过先拆成多个不超过 15 秒的片段，绕过此选择。

### 情况二：用户提供的口播词或台词明显过长

符合以下任一情况时触发：

- 用户指定了成片时长，提供的台词明显无法在该时长内自然说完。
- 用户未指定时长，但提供的台词明显不适合放进默认 fast 的一次短片。

这里判断的是**明显放不下**，例如要求在很短的视频中完整念完多段长口播或多轮长对白。

不得为了判断是否询问而逐字计数、套用字数阈值、精确计算朗读时间，或额外调用计时、TTS 工具。没有真实音轨依据时，不得声称“这些台词需要 22 秒”等精确结果。

只是略显紧凑或拿不准时，不因“可能超时”增加询问；也不能擅自删改用户原文或用不自然的加速朗读解决。

### 不触发的情况

以下情况不增加此类方案选择：

- 仅写剧本、分镜或提示词，尚不执行视频制作。
- 保留原画面的纯后期剪辑、拼接、混音等操作。
- 模型自己写出的文案太长：应自行改好。
- 用户已经允许改写，且在授权范围内精简即可解决台词过长问题。
- 用户已经明确选择了当前仍有效的制作方案及相应台词取舍。

其中，**用户明确要求单条超过 15 秒且未指定模型**的条件，仍独立生效，不能因允许改写而跳过。

两种触发条件同时出现时，合并为一次选择，不先问模型、再另问台词取舍。

## 4. 已明确成片时长时，怎么提供方案

只展示已经核实可执行的选项：

- **seedance 2.0 fast（默认推荐）**：每段不超过 15 秒，需要多段时生成后拼接为一条成片。
- **seedance 2.5（会员模型并消耗更多的额度）**：每段不超过 30 秒；30 秒以内可一次生成，超过 30 秒则分段生成后拼接。
- **暂不制作**：不继续执行制作，不授权任何生成。

每个制作选项必须简短写清：

**预计生成段数、各段秒数、是否拼接、最终成片总时长。**

例如，用户明确要求 22 秒成片：

- fast：预计生成 2 段，11＋11 秒，拼接为一条 22 秒成片。
- 2.5（会员模型并消耗更多的额度）：预计生成 1 段 22 秒视频，无需拼接，最终一条 22 秒成片。

这些只是拆分示例，不是固定模板。实际分段应遵循：

- 按内容、动作和声音衔接安排时长，不要求用满模型上限。
- 每段满足实际工具的时长上下限和其他限制。
- 拼接取用后的总时长符合用户要求。
- 剩余尾段太短时重新分配各段时长，不擅自延长成片。
- 用户要求真实一镜到底时，不能把分段拼接列为满足该要求的方案。
- 此步骤不展开完整剧本或正式分镜。

**默认模型不能用来跳过已触发的选择；成片超过 15 秒也不能成为自动升级模型的理由。**

## 5. 用户台词明显过长时，怎么提供方案

### 用户没有锁定成片时长，也没有指定模型

根据实际可执行能力，在同一次选择中提供：

1. 保留全文，使用 fast，必要时分段生成后拼接。
2. 保留全文，使用 2.5；选项包含完整会员提醒，并说明是否可能需要分段。
3. 允许精简台词，使用 fast 制作短片。
4. 暂不制作。

此时如果尚未确定适合全文的成片时长，只说明：

**是否保留全文、使用哪个模型、是否可能分段。**

不要为了把选项写完整而编造精确朗读用时，也不要保证 2.5 一次就能容纳全文。用户选定后，再在规划中确定实际时长和分段，并在生成确认前展示。

### 用户已经锁定成片时长

必须说明真实取舍：

- **保留指定时长，允许精简台词。**
- **保留全部台词，允许延长成片。** 如适用，再区分 fast 分段与 2.5 方案。
- 暂不制作。

换模型或增加生成段数，不能让同一段长台词在固定的短时长内自然说完。不得把延长成片藏在模型选项里。

### 用户已经指定模型

保持该模型，只询问必要的内容取舍，不默认加入换模型选项。

### 用户要求逐字保留

如提供精简选项，必须明确写成：

**“允许改写并精简台词”。**

用户同意前不得改写。用户选定精简后，应保留核心意思、事实和必要条件，完整展示修改后的台词，再进行生成确认。

用户选定保留全文后，规划中不得继续擅自删改。

## 6. 前置方案选择的交互要求

必须由主代理**实际调用 `interaction.ask`**。普通文字提问、展示 JSON、用户在聊天中说“可以”，都不能替代规定的实际交互调用。

使用一道单选题，字段结构如下。以下示例仅适用于**用户明确要求 22 秒成片，且相关模型及拼接能力均已核实可用**的情况：

```json
{
  "questions": [
    {
      "question_id": "video_plan_select",
      "header": "制作方案",
      "display_message": "请选择这条22秒视频的制作方案。此次选择仅确定制作方式，不会开始生成。",
      "display_option": [
        {
          "option_id": "fast",
          "label": "seedance 2.0 fast（默认推荐）",
          "description": "预计生成2段，11+11秒，生成后拼接为1条22秒成片。"
        },
        {
          "option_id": "seedance25",
          "label": "seedance 2.5（会员模型并消耗更多的额度）",
          "description": "预计生成1段22秒视频，无需拼接，最终为1条22秒成片。"
        },
        {
          "option_id": "cancel",
          "label": "暂不制作",
          "description": "不继续执行制作，不调用视频生成工具。"
        }
      ],
      "multi_select": false
    }
  ]
}
```

台词过长时，按前述规则改写选项，明确保留、精简和延长之间的取舍，不机械套用这个示例。

交互字段要求：

- `questions`、`display_option` 必须是数组。
- 使用 `question_id`、`header`、`display_message`、`display_option`、`multi_select`。
- 每个选项使用 `option_id`、`label`、`description`。
- 不使用 `question`、`options` 等替代字段。
- 不把数组序列化成字符串，不添加工具未提供的字段。
- 不使用其他交互工具代替 `interaction.ask`。
- 选项写“选择某方案”，不要写成“按某方案生成”，以免混淆授权。

## 7. 选择方案后，怎么规划和确认

用户选择方案后，完成对应链路所需的内容规划，再展示：

- 视频完整内容，说明开头、推进和结尾。
- 实际使用的全部口播或台词，明确说话者。
- 已选模型；涉及 2.5 时在模型字段写明会员及更多额度提醒。
- 最终成片总时长、预计生成段数、各段时长及是否拼接。
- 比例，以及工具实际支持并将使用的其他规格。
- 输入素材及用途、必要的声音和画面文字安排。
- 当前准备执行的批次范围。

这些内容和参数应在正常对话中展示，不能只藏在确认题里。

方案细化后，各段时长发生变化的，必须在生成确认前明确展示。用户需要先审剧本或分镜时，先完成其要求的审阅，再进行生成确认。

不因这道前置选择而增加创意问卷、额外的逐阶段审阅，或强制把一条短视频升级为完整链路。

## 8. 生成必须另行确认

所有视频模型生成和模型编辑，在执行前都必须由主代理实际调用 `interaction.ask` 进行生成确认。

方案选择、剧本认可、分镜认可，都不能代替生成确认。

确认题只保留以下两个选项：

```json
{
  "questions": [
    {
      "question_id": "video_confirm",
      "header": "生成确认",
      "display_message": "是否按以上参数开始生成视频？",
      "display_option": [
        {
          "option_id": "generate",
          "label": "按要求生成",
          "description": "视频生成为高消耗生成，确认后按已展示方案开始后台生成。"
        },
        {
          "option_id": "cancel",
          "label": "暂不生成",
          "description": "暂停执行，不调用视频生成工具。"
        }
      ],
      "multi_select": false
    }
  ]
}
```

用户必须通过实际确认交互明确同意，才能执行当前批次。沉默、含糊回复、普通聊天中的认可或历史确认，不能代替当前批次的确认。

## 9. 分批执行及确认失效

每批最多安排 **2 个视频模型生成或编辑任务**，长视频的每个生成片段也计入任务数。

- 可以展示整条视频的完整制作方案，但一次生成确认只授权当前列出的批次。
- 下一批执行前，直接展示该批参数并调用生成确认，不再增加一道“是否继续”的问题。
- 相互独立的任务可并行。
- 依赖上一段实际尾帧或结果的任务，取得真实结果后再顺序执行。

模型、制作路径、用户锁定内容或其他关键参数发生实质变化时，不能沿用不再适用的方案选择或生成确认。应展示变化，完成对应的必要选择及确认。

已确认范围内的执行细化，不应反复增加确认。

## 10. 制作模式：两类默认完整，其他默认轻量

这是本 Skill 的制作约定。先读取用户明确的作品定位与已有项目，按下文落实影响本次规划的组织方式及集数，再路由；不能用“其他默认轻量”绕过尚未回答的规模问题。用户显式指定模式时遵循其要求，未指定时仅以下两类默认 `full`，其他任务默认 `lightweight`：

1. **微电影、电影作品**：用户明确以一部微电影或电影为创作与交付目标，按整部作品组织故事、详细剧本、人物与视听表达。即使人物少、场景少或时长短，也默认完整。
2. **连续叙事的多集短剧**：各集共同推进同一故事，前集的事件、人物选择、关系或伏笔持续影响后集；默认完整，先贯通全剧再逐集制作。

“电影感”“大片效果”“电影级运镜”只表达审美要求，不代表制作电影作品；泛称“短片”、讲完整故事或片长较长，也不自动归入第一类。依据已有明确定位判断；信息确有歧义且影响当前制作安排时，只澄清这一缺口，不增加模式问卷。

同一视频分成多个 SEG 生成再拼接仍是一部视频，不算多集。多个互不承接的小故事，即使共用角色、场景或音色，也不自动算连续叙事；逐个按其实际作品定位登记，共用素材直接复用。连续剧的某一集或某个片段属于原项目，不能因本次只做一集/一段而重新判为独立轻量项目。

### 没说集数，或只给剧情大纲时

先读本次要求、可恢复历史、已有大纲和项目记录，分别判断“是否连续多集”与“具体多少集”。集数决定故事容量、分集推进和结局安排；影响本次规划且没有明确依据时，先由主 Agent 实际询问，得到答复后再按范围组织正式故事，不擅自用 `episode_count=1` 消除歧义。准备这一问题只需理解大纲主线与现有约束，不提前写分集总纲或详细剧本：

- **已有依据就继承**：明确分集且剧情相承的大纲、已定连载项目，或“做一季”“先做第一集，后面继续”“每集留悬念”等要求，足以确定连续多集，未给总集数也默认完整。只修改现有某集或某段时，沿用项目及当前范围，不为局部交付追问全剧集数。
- **只说短剧、集数不明时先问**：只有“做个短剧”，或只给大纲且单条、连载都成立时，合并询问“准备做一集完整故事，还是连续多集？多集的话计划几集；还没定也可以让我根据大纲建议。”这一题补齐组织方式与数量，不先默认轻量或完整，不生成两套创意候选。大纲长短、章回标题、开放结尾或可续写潜力不能替用户作答；明确微电影/电影定位或“一条/单集独立故事”已有答案，不因此再问。
- **连载已定、数量未定时只问缺项**：需要规划全剧但总集数未定时，只询问计划几集，允许用户交由模型建议，不再询问是否多集。用户已明确“集数你定/按大纲建议”等时，直接根据实际故事容量提出一份集数及逐集/总时长建议，标明建议并放进已有规划确认，不追加“是否让我建议”的问题。局部任务不依赖全剧数量时不追问；用户未答复不能视为同意模型代定。
- **已答就继承，不逐阶段重问**：沿用真实答复、已确认规模及其作用域，只有用户改变组织方式、集数，或锁定时长/交付范围与必须保留的剧情发生真实冲突时，才澄清受影响缺口。必要集数澄清同样适用于纯剧本或全剧方案目标，不因尚不生成视频而跳过。集数答复只解决创作范围，不授权生图、音色或视频调用，也不替代原有模型选择与生成确认。

集数澄清使用当前 `interaction.ask` 实际支持的输入形式，允许用户给出具体数量或交由模型建议，不硬套第 6 节的视频模型选择选项。原始答复保存到现有来源/规划记录；它不是 `video_plan_select` 或 `generate`，不新增授权枚举、独立确认文件或阶段检查。

确认单条或连续多集后，再按本节确定对应模式；用户授权模型建议规模时，在建议采用范围内规划，正式推进及授权仍按原有模式规则。单条不默认 15/30 秒，也不把大纲当成只能取一小段的素材。按完整主线、关键事件、人物关系、因果与结局推导合适片长；需要时在同一视频内分 SEG。不得擅自截成“第一集”、用未完待续替换已给结局、删掉锁定内容或靠旁白摘要挤进短时长。

**轻量与完整采用相同创作策略和质量要求。** 剧情丰富度、因果、人物、叙事、台词、节奏、表演、视觉、音乐与转场均须充分设计。多角色、多场景、多线叙事、复杂动作、跨段状态依赖、参考素材、研究难度、镜数、时长或调用次数，都用于安排必要设计和真实执行，不新增自动进入完整模式的条件。高质量要求、先看剧本/分镜或先做必要资产，也不自动升级。

轻量合并配套文件与常规展示/确认，必要信息按 `planning.md` 保存到已有规划、正文或唯一十五列主表；逐镜内容充分展开，用户概览不替代故事、人声或执行依据。复杂任务在原载体内保留实际需要的调度、状态、信息顺序和声画设计，不靠减少剧情、压缩台词、简化镜头或增加阶段门应付难度，不补完整模式文件包。

| 请求 | 默认模式及处理 |
|---|---|
| 两人一个场景的微电影 | 完整，少人物/场景不改变作品定位 |
| “电影感”的剧情短视频，有多线、复杂接触、跨段状态和配乐 | 轻量，调用相应创作方法并充分记录必要信息 |
| 一条长剧情视频拆为多个 SEG | 轻量，分段及片长不触发完整；明确电影定位时按第一类 |
| 多个故事共用角色，但剧情互不承接 | 分别判断作品定位，默认轻量并复用素材 |
| 前集的选择改变后集关系与剧情的多集短剧 | 完整，维护全剧推进与集间承接 |

已有合法项目沿用采用模式、有效上游和真实授权，不因新默认要求重建或重走。完整项目只做局部时，从实际缺口继续；新任务或用户改变作品定位后，才按本节确定对应模式，不因难度增大自行升级。模式不授权新增付费调用，两种模式的视频确认、每批任务上限和委派边界相同，仍执行本文件前述条款。

模式不改变交付终点：两种模式都支持只要规划、剧本、资产、分镜或视频片段，按 `control-contracts.md` 到目标即停止。已有剧本、分镜或批准资产先继承，只补当前目标所需缺口；微电影或连续多集的定位不要求补无用途文件、未来集详细内容或新增媒体。没有实际视频调用不触发视频生成确认，不得把作品定位当成制作视频或成片的授权。

## 商业素材询问

仅当用户要求制作企业宣传片、广告 TVC、卖货/带货/产品销售类视频，且未上传任何相关品牌、Logo、产品或企业资料资产时，在出方案前实际调用 `interaction.ask` 询问“上传相关素材，或按无素材概念方案制作”。先检查本次及可恢复历史上传；已有相关资产就利用，不因缺某一类而索要整套资料。普通口播、个人 UGC、创意剧情视频和仅需文本的任务不因此增加素材询问；普通商业视频仍按主入口的 Skill 适用范围分流。

只问素材选择，不借机追加卖点、内容、审美或规格问卷。用户选择上传则等待素材；已明确允许无素材概念方案则不重复问，规划中说明视觉一致性的具体限制，不虚构品牌/产品事实。此项与前置制作方案选择分别按真实触发条件处理，均不授权生成。
