# 成片、字幕与交付 Ref

本文件负责已授权的拼接、音轨、字幕制作与直接交付，不安排生成后检查。工具名、参数、异步状态与结果字段以宿主实际 schema 为准。

## 第一部分：成片与交付

### 输入与授权

- 使用真实已生成并保存的片段、既定顺序、计划边界、声音和字幕方案；不需要 accepted SEG、observed seam、verified cut、双侧帧窗口或质检报告。
- 两种模式都可拼接。轻量模式将段序、边界与依赖记在视频 manifest；完整模式复用分镜的分组与 planned seam，不另要求结果验收。
- 项目/分镜/本批展示已经明确的普通拼接、裁剪、混音和字幕制作直接执行，不再常规询问“是否拼接”。重大方案变更才按 `control-contracts.md` 确认；任何新增视频模型调用仍需独立生成授权。
- 参数、BGM、片头片尾、字幕、`audio_policy` 和交付范围沿用已定方案。只有已明确目标响度才按该值处理，不临时发明 LUFS 指标。能力缺失只暂停实际受影响的操作，不重做有效上游。

### 拼接与音轨

1. 按已定段序与计划切出/切入边界组织素材；未另定裁剪时直接使用生成片段完整区间硬切拼接。不能以未做接缝检查为由阻断，也不声称切点已验证无缝。
2. 按需要通过实际媒体工具统一画幅、帧率和编码；仅当工具执行需要且返回数据不足时取得必要元数据，用已有任务结果即可，不建立例行 probe 或重复探测。
3. 原生人声默认保留。只有真实独立音轨才按已定方案分轨混音；混合原声保留整轨，不声称可以单独降低其中 BGM。确需分离时先取得实际能力和相应授权，不假定分离无损，不另生成一遍人声冒充分轨。
4. 声音桥按既定计划与实际工具能力执行，不自动重配人声、补句、改台词或新增音乐。不以混音掩盖剧情或身份问题。
5. 完成用户要求的声音操作后将该音轨作为字幕时间依据；后续确需修改音轨才重做受影响的字幕，不重做未受影响片段。

精确跨段同曲/相位衔接以真实音频与工具能力为限，不能因 Prompt 写了同一 BGM 就保证连续。必要的制作取舍应在生成前说明，不在生成后安排试听验收。

### 执行与直接交付

1. 主 Agent 锁定采用片段、顺序、计划边界、声音/字幕设置和唯一最终输出，把实际媒体变更委派给受控执行者。
2. 真实任务提交后保存 `task_id`，用同一任务查询至 `completed`；`running|queued` 继续查询，不重复提交。下载真实结果并保存制作记录：轻量写入 `video_manifest_ep_N.json.delivery`，完整写入 `delivery_manifest_ep_N.json`；真实段序、制作参数、音轨、字幕来源、任务结果和输出均保留，不另写重复清单。明确失败或缺输出就修失败的下载/合成操作，不能虚报完成或自动重生视频。
3. 无合成需求时原生成视频即最终版本；有拼接、混音或字幕要求时完成对应操作后直接交付。不额外 probe 验片、播放/试听、抽帧复核、运行阶段 lint 或生成质量报告。
4. 每集/每条作品只交付一个最终视频：默认无字幕，用户明确要求字幕时只交字幕版。原始片段在完整模式按原路由逐项展示；轻量成片目标同样逐项交付源片，再完成合成；只要视频片段的任务由视频阶段逐项交付，不进入本成片流程。后期工具返回短链时同样立即交付；仅有本地文件的中间产物按项目需要留档。
5. 按 `media-delivery.md` 用 RichMediaCard 直交当前唯一最终视频。记录实际结果与交付状态，将 `video|final` 的实际目标写为 `completed`，不等待成片确认；多集完成当前目标后继续下一集。

`deliverable` 表示工具已完成且有真实资源可交付，不表示经过内容审看或质量验收。任务失败、资源缺失或交付失败时记录 `blocked`，只报告实际缺口。旧记录的 candidate 可保留历史语义，新流程不因“未审片”生成候选状态。已明确得知的问题如实说明，不隐藏已消耗结果，不自动返修。

### 平台适配与追溯

用户要求平台专用版本且规格不确定时，在生成前核实当前官方要求并记录来源、日期、比例、时长、安全区和字幕安排。导出只执行已定设置，不另做交付后平台验收。来源片段、实际任务结果、采用参数和最终路径写入既有 manifest/操作日志，不重复建立成片清单、媒体探测报告或质量报告；用户明确需要清单时才导出。

## 第二部分：字幕生成与烧录

字幕是用户要求的制作内容，不是视频检查。默认关闭；开启时才执行 ASR 和烧录。视频生成 Prompt 固定禁止自动字幕及无关文字；不在生成后主动寻找/擦除字幕、水印或随机文字。用户明确要求文字清理时才执行相应非视频生成媒体操作，不自动调用视频编辑或重生。

### 工具与记录

只使用宿主实际 mediakit 或等价能力，媒体变更仍委派执行，不以 FFmpeg/本地脚本冒充正式工具。提交保存真实任务 ID，用同一任务查询终态、及时下载结果。ASR 保存未经改写的真实返回及其输入；不为证明质量另建调用信封、ASR 对齐报告或媒体检查报告。SRT 与烧录参数由该实际返回和采用文本派生。

### 台词与字幕文本合同

从剧本第一次写出台词时就保存三层文本：`source_text` 保存本次采用的台词来源文本；带规范标点的 `display_text` 用于剧本正文和人工阅读；`spoken_text` 用于视频 Prompt、语音校验和字幕正文。用户原始文本始终在现有 `source_lock`、来源登记和原文件中逐字保留，不覆盖。未授权改写时，`source_text` 即用户原句；用户按 `interaction-ask-video-clarification-ref.md` 明确同意改写后，先完整展示修改稿，再把该采用版本作为执行文本来源并关联实际许可，原文继续保留。三层之间仅做格式转换，不能借规范化再次改写：`display_text` 与 `spoken_text` 只能调整标点、引号和空格，字词与顺序不得改写。`spoken_text` 按以下规则规范化：

| 原符号 | 处理 |
|---|---|
| `。？！…….!?` | 删除 |
| `，、；：,;:` | 替换为一个半角空格 |
| `——` | 替换为一个半角空格 |
| 中文/英文引号、书名号、圆括号 | 删除 |
| 句首、句尾空格 | 删除 |
| 连续多个空格 | 合并为一个半角空格 |

问句、感叹和语义停顿在 `display_text` 中保留正常标点；模型执行另写入 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words`，避免只依赖标点控制表演。

```json
{
  "speaker": "林远",
  "type": "on_screen_dialogue",
  "source_text": "顾长渊，本宫今日来，不是跟你拜堂的。",
  "display_text": "顾长渊，本宫今日来，不是跟你拜堂的。",
  "spoken_text": "顾长渊 本宫今日来 不是跟你拜堂的",
  "delivery_intent": "冷静拒绝",
  "pause_plan": ["顾长渊 后短停", "今日来 后短停"],
  "emphasis_words": ["不是", "拜堂"],
  "subtitle_text": "顾长渊 本宫今日来 不是跟你拜堂的"
}
```

### 字幕制作顺序

1. **使用最终音轨**：单段原视频或已完成必要合成的视频直接作为内部烧录源，不再次拼接或另做母版检查。
2. **获取真实时间**：调用实际 `asr-subtitles` 并保存 `start_time/end_time/subtitle_text` 及接口提供的说话人信息，仅用于字幕时轴，不用于判断漏句、口型或剧情是否达标。任务未完成不能消费结果。
3. **组织字幕文本**：用说话人、句序和语义将已有时间映射到采用 `speech_lines.spoken_text`；一句被拆开或相邻短句合并时保留实际时间依据。可辨的识别错字改回采用文本；不把根本没有时间依据的整句硬塞入，也不为 ASR 与剧本的差异启动视频检查或自动返修。必要时间仍无法取得时说明字幕制作的实际缺口，保留成功媒体，不偷偷改交无字幕版本冒充完成字幕任务。
4. **排版**：相邻同说话人短句间隔小于 0.5 秒可合并，取首句开始和末句结束；超过 18–20 个汉字优先按语义换两行，保持同一区间。只有可靠词级时间才拆成不同事件；字幕随实际快节奏短句结束，不为凑 1.5–5 秒强制延长或拖慢视频。不猜测整体偏移量，不用不存在的朗读时间替代 ASR。
5. **生成内部 SRT 并烧录**：直接从上述真实时间和文本构造合法 SRT/字幕对象，使用下列预设执行一次所需烧录，不先做字体样片或代表帧试验。

默认使用 mediakit `add-subtitle-to-video`。参数字段名以调用时实际 schema 为准，视觉结果固定为：

| 成片比例 | 位置预设 | 位置参数 | 字号 | 字体 | 颜色 |
|---|---|---:|---:|---|---|
| `9:16` | `lower_third` | `pos_y=70%` | `36px` | 思源黑体（`sy_black`） | 白色 |
| `16:9` | `bottom_center` | 底部居中 | `36px` | 思源黑体（`sy_black`） | 白色 |

其他比例默认使用 `bottom_center / 36px / sy_black / 白色`，在生成前依据已定构图与平台安全区安排。用户明确要求其他样式时必须重新确认；未确认不得动态改变字体、字号、颜色或位置。

本地 SRT 不能直接传给 `--subtitle-url`，该字段只接受公网 HTTP/HTTPS URL。默认把当前 SRT 转成等价的字幕对象数组，并通过 `--subtitles` 传入；对象字段固定为 `start_time/end_time/subtitle_text`，时间单位为秒。SRT 作为内部字幕文本事实源，用户另要求时才单独交付。

```bash
mediakit-cli editing add-subtitle-to-video \
  --video-url "拼接后_原音轨.mp4" \
  --subtitles '[{"start_time":0.24,"end_time":3.16,"subtitle_text":"顾长渊 本宫今日来 不是跟你拜堂的"}]' \
  --subtitle-font-size 36 \
  --subtitle-font-type sy_black \
  --subtitle-font-color '#FFFFFFFF' \
  --subtitle-pos-preset lower_third

mediakit-cli shared query-task \
  --task-id <subtitle_task_id> \
  --poll-complete
```

横屏把 `--subtitle-pos-preset` 改为 `bottom_center`。终态必须为 `completed`，再从 `result.video_url` 下载字幕版；不得使用不存在的本地输出参数。

### 完成与保存

烧录任务完成后下载真实结果并直接交付，不播放、抽取字幕首中尾帧、做遮脸/OCR/安全区复检或另设字幕验收门。保留实际 ASR 返回、SRT、必要烧录参数与真实任务结果即可；不重复建立字幕最终版 JSON、对齐报告、无字幕母版/字幕版基础报告或探测信封。

字幕默认思源黑体、36px、白色；用户已指定的样式优先，在生成前落实构图与已知安全区。不能保证未实际审看的字幕完美对齐、无遮挡或字形已验证。字幕烧录沿用原音轨；工具明确失败只修本次制作操作，不扩大为视频重生或自动换交付版本。
