# 资产阶段 Ref

本文件是资产设计、生成与用户采用确认的唯一权威。完整模式在项目级与当前集剧本取得相应确认后（单集同一正文共用一次），逐集准备当前集实际需要的人物、主要场景、道具、音色和必要状态资产。只对新增造型、用途、版本或文字视觉方案等采用决定展示确认；原适用范围内已批准复用按 `control-contracts.md` 直接承接，不重复确认。新生成图片按 `media-delivery.md` 立即逐项直交，再保存登记；下一张只等待直交及必要依赖。当前集资产已有有效采用依据后才进入分镜；当前集达到目标后，下一集从详细剧本开始。轻量资产目标按实际设计、复用与生图要求完成并交付；其他轻量任务仅在需要已有素材、音色边界或必要新增参考时补读对应章节，共用表达按已有规划继承，不补造完整模式数据卡与资产包。只要资产的任务交付即停止，不因本文件后续流程要求继续分镜或视频；实际新增媒体的生成授权仍须取得。

先读本节关键要求、“从剧本确定设计与制作范围”、“状态记录与出图判断”和工具路由，再读本次实际生产的角色、场景、道具或音色章节；相应 Prompt 骨架在提交前查阅。登记时读取 `manifests.md` 的资产相关章节，展示与生成时补读入口指定的实际工具/交付规则，不全量加载其他阶段。

两种模式共用本文件适用的身份辨识、空间/尺度、动作可行性、状态与声音设计方法。轻量的共用设计和状态约束按 `planning.md` 写入已有规划，真实媒体及完整生成 Prompt 沿来源和操作记录引用；下文数据卡、资产注册表及分集使用表的写入位置用于完整模式，不能据此要求轻量补文件或降低设计覆盖。

## 本 Ref 关键要求

- 资产阶段只处理当前集实际需要的 CHR/SCN/PROP/VOICE 和必要状态版本；开始生成前先查共享库与所有已完成分集资产，已有 approved 可用版本时直接复用。先依剧本确定设计，再补缺失媒体；连续性状态不等于新图片，出图按“状态记录与出图判断”执行。不为后续集提前生成资产，不生成剧情视频。
- 非轻量模式需新生成或复现的画面中，长时间出现、多次出现、跨片段承接、影响走位调度或承担剧情识别功能的场景必须准备 `SCNxxx` 场景资产，和人物、道具一起进入资产阶段确认。场景图不是可选氛围图，而是视频的空间布局输入；缺失时不得进入依赖该场景的生成。
- 人物图按实际出场范围选择身份主视图、三视图或必要细节；状态版只补现有图无法说明的外观变化。用户上传、指定或认可的人物维度优先，已批准人物图负责项目连续性；两者各有必要职责时同时参考。人物图可兼任风格参考，但不继承无关身份、服装或背景。
- 所有图片资产共享同一套 `project_visual_mode` 和可观察风格词；生图/修图 Prompt 第一句必须先写统一画风，再写主体、参考图、结构和细节，不得在真人写实、漫画/动漫/插画/水彩/照片级等互不兼容模式之间漂移。
- 图片 Prompt 完整写清当前资产的生成目标、适用版式、必要结构与尺度、可见身份/状态、材质光色、文字和限制；有参考时逐张说明采用与剥离内容。不把其他类别字段或剧情表演机械套入，不用重复形容词充当完整度；正文不写“生成类型：T2I/I2I/文生图/图生图”。
- 同一角色的基准图、必要状态图、头部锚点和修订图按角色安排生成顺序，每张成功返回即交付，不等整组完成；后续采用清单按角色归组引用，不为重新归组重复展示媒体。每张图旁边用自然语言说明它依次是什么状态、从什么时候生效、用于哪些集/场次；资产阶段不要求面向用户写到具体镜头或 SEG。
- 同一道具有多种确需补图的外观状态时，优先在一张多状态图上清楚分区，逐区说明状态、结构、内容物和使用时机；不为单纯易主、移位或转向复制相同图片。多状态图只表现同一个道具。
- 不生成独立风格板。使用已确认文字视觉合同；用户已有风格图片时仅按相关维度选用，不自动成为每段必传输入。
- 有当前目标需要的有效视觉参考维度就用 `image_edit`，没有才用 `image_gen`。人物、场景、道具、构图、姿态、色彩、光影、质感、媒介类型和画风锚点都可能构成视觉参考维度；纯文字指令、剧本/文档/表格截图和 OCR 图在逐张查看后若只提供文字内容，则只作文字来源，若同时提供当前目标相关视觉维度则仍按该维度处理。用户认可图优先，其次是 approved 资产、状态图、FRM 和有效用户风格图；只传当前目标必要参考，逐张登记采用维度和剥离维度。基于既有角色、状态、场景、道具、风格或 FRM 继续生成时禁止纯文生图。当前目标命中有效视觉参考维度时，该参考图必须被实际打开查看并作为真实图片输入传给 `image_edit`；只把参考图写进 Prompt 文本、source_manifest 或 available_visual_reference_ids，但工具请求没有传入对应图片，按路由错误阻断。
- 每次生图或修图实际传给模型的完整 Prompt 原文必须保存到对应资产目录的 `提示词/` 下，不能保存简洁版、摘要版、压缩版或说明版；完整模式在资产登记的 `generation.prompt_path` 引用，轻量沿已有来源与实际操作记录引用，不为登记补建完整模式资产文件。Prompt 文件默认内部追溯，只有用户明确要求查看 Prompt、排查或交接时才紧邻对应图片或音频条目展示入口。
- 音色资产使用 `text_to_audio_plus` 生成；样音固定按 5 秒、1-2 句短台词设计，`voice_anchor` 在完整模式写入数据卡，轻量沿已有规划与真实音色来源记录继承，两种模式逐句复用，不检查或修复底层音频格式细节。
- 完整模式进入分镜前须有有效采用依据，新增采用决定取得确认，同范围 approved 复用沿用原依据；轻量按目标和实际生成授权承接，不补独立资产确认门。旧版保留不覆盖。

## 目标与输入条件

资产阶段只生产当前集下游实际会消费的基础媒体：人物身份/状态、主要场景、核心道具/状态、角色音色；不补造风格板。SCN 锁空间基准，文字风格合同锁定必要的媒介、光色和材质，FRM 由 `video.md` 记录。非轻量模式需新生成或复现的画面中，当前集长时间、多次、跨片段、多人走位、影响轴线或承担剧情识别的场景必须建 `SCNxxx`；一次性、极短、纯抽象或已被用户首帧锁定的轻量场景可不单独生成，但不得冒充 approved SCN。后续集即使已在剧本中规划，也只能保留数据卡中的稳定 ID、状态时间线和需求预测，不得在当前集提前生成对应媒体资产。

仅剪用授权原片画面时，以已实际查看的真实来源、时间码、采用范围和其中可见的身份、造型、道具及空间证据履行复用职责，不为填满 CHR/SCN/PROP 类别重画原作或猜造不可见布局。沿现有来源与资产登记记录实际文件、范围及审阅状态；来源登记不等于已经审阅或 approved。原片证据只覆盖所采用的原片范围，不能自动支持新机位、新动作或新画面的空间复现；确需新生成的部分仍须补足本文件要求的对应资产。没有实际原片时保留待核验缺口，不伪造复用验收。

初次收到、新增或替换用户图片时，先逐张实际打开并登记；已登记且未变化的来源复用分析，后续操作只查看本次相关、变化或存疑图片，不重复全库打开。补全 `source_manifest.json` 的多维拆解。逐张盘点的单位是每个 URL、附件 ID 或输入实例，而不是文件名：多张图即使系统提示给出相同 `local path`、相同 `image.png` 或相同 basename，只要 URL、附件 ID、消息位置或输入顺序不同，都必须分别读取、转存为独立 `SRCxxx`、计算哈希并登记；不得只下载后几张、只看第一张、用同名文件覆盖前一张，或按展示名去重。逐张盘点只判断图片真实内容和可能职责，不等于全部传给生成工具；生成时仍按当前目标只选择足够且必要的相关图和相关维度。不得因为用户图片像文档截图、只含场景、只含风格、只含道具、只含构图、与当前类别不同，或用户没有说“参考”，就跳过查看和登记；同一张图可以同时登记为 `text_source` 与人物、状态、场景、道具、构图、媒介风格、色彩光影或质感参考。

参考图的使用遵循“三段式”：先拆维度，再定权重，最后写边界。拆维度时分别记录身份/状态、空间/道具、构图/姿态、媒介类型、画风、色彩、光影、材质/颗粒/纸感和文字信息；定权重时区分 `lock`、`weak`、`exclude`，只有清晰、稳定、与用户意图一致的维度可锁定；写边界时明确“采用什么、不采用什么、用到哪里”。参考图质量差、主体遮挡、压缩严重、有水印/界面、风格混杂或与 approved 资产冲突时，不得整体照搬：能可靠识别的维度可弱参考，身份、主风格或剧情关键结构冲突时先向用户确认取舍。

资产必须继承已确认剧本、数据卡和视觉风格合同。缺风格候选或视觉机制时才读取 `电影大师风格库.md`；该库只补光线、色彩、构图、材质和节奏机制，不覆盖角色身份、道具结构、状态或镜头职责。

全项目使用同一套渲染语言。剧情可改变时间、天气、磨损、情绪和场景状态，但不得拼贴互不兼容的风格。实际图片 Prompt 首句写适用的统一画风词，随后按该类资产职责写完整内容；不要求每次列全纸感、颗粒、线条等不适用项。有参考图时逐张写采用/剥离边界；用户明确要求混合风格时，规划阶段先写清主风格、例外元素和可观察边界。若用户参考图之间风格不同，默认只选一个主视觉类型锁定项目，其他图只能按指定维度弱参考。

## 从剧本确定设计与制作范围

资产要让已确认的戏能够发生。沿用已选呈现类别、题材与人物设定，不在本阶段重写故事或另起视觉方向竞选。在生成前连着关键行动做以下判断，结论进入既有数据卡、资产登记或图片旁说明，不另建资产设计卡、评分表或报告：

1. **找当前需要**：谁在什么环境做什么，观众必须认出什么、看清什么变化；区分用户锁定项、剧本已定项与仍可设计的部分。先列当前集需求并查复用，再决定生成，不能按目录穷举人物状态和场景物件。
2. **让设计有来由**：人物从职业、生活条件、当前任务和个人选择确定剪影、妆发、服装层次与使用痕迹；场景从生活/工作用途确定空间、陈设和使用痕迹；道具从实际功能确定尺度、机构和识别差异。身份不靠统一制服或刻板标签代替，财富与地位也不必都靠夸张装饰。用户已锁造型时，只深化未锁细节。
3. **让选择适合本片**：短剧中需要迅速辨认的人物关系、控制权与关键差别应易读；微电影/短片可用磨损、收纳、修补或不合时宜的选择表达经历与关系。两者都按当前剧情取舍，不强制前者艳丽夸张、后者灰暗朴素。真人按可信穿戴与材质工作，动画/动物按既定形体、肢体和画法工作，不另改呈现类别。
4. **把人物、空间和物件放在一起想**：顺着关键行动推演站位、距离、遮挡、接触与进出；衣物能否完成藏取和活动，物件能否握持、传递或打开，家具和通道是否容得下既定动作。先统一相对尺度与必要可见面，再各自出图，避免三张单图都漂亮却不能合用。涉及堆叠、遮挡、容纳或穿过时，把数量、摆放方向、组合后的宽高、接触高度和路径放在同一尺度下简单核算；不能各自填了尺寸，就宣称组合条件成立。纸面已不成立时先调整未锁定设计；已确认事实互相冲突则说明缺口，不擅改剧情，也不以“留待视频实测”放行。此时只判断场次可行性，不编号镜头、不预制 SEG 或正式分镜。
5. **选择最少而充分的表达**：按下文决定主视图、多视图、状态图和细节图。优先用一份清晰资产覆盖兼容的职责，不能为少图省略关键结构，也不因想象中的未来镜头预制全部角度。已有合格用户素材可以直接登记复用，不因没有指定版式就重画。

主要人物反复出镜、跨集复用或承担侧背与全身行动时，优先使用完整三视图；长期使用、多人调度或空间关系复杂的主要场景，优先完整布局与必要多视角。只在当前使用范围明确、现有依据确实覆盖需求时简化，不能只凭“本次暂时想到正面”省去必要信息。当前需求不清时沿用对应完整标准；这是当前资产的覆盖判断，不授权预制未来集造型或场景状态。用户指定的三视图、四宫格或其他版式不得自行缩减。

设计时把人物辨识、人物与物件尺度、场景布局和关键差别可读性落实到生成要求；返回后保存登记并展示，不安排资产阶段质检。实际资源在被后续调用采用时按输入理解职责查看，不声称 Prompt 已保证真实互动或成片效果。

### 把剧情事实转成可见设计

下面演示推导方法，不增加题材分类，也不把示例事实带入其他项目。先继承 `剧作方法与类型库.md` 已选类型、题材与呈现路径；仍缺具体设计办法时只查对应条目，不重新选择故事方向。每次从本片已经存在的事实出发，在未锁定的设计空间形成有用途的选择；观众应能看出差别，且该选择能在关键行动中被使用，而不是靠说明文字宣称“独特”。

| 已确认的剧情事实（示例） | 可采用的设计推导 | 怎样在本片起作用 | 不能随之擅自添加 |
|---|---|---|---|
| 悬疑戏里人物要辨认两只相似盒子，其中一只背面已有新刮痕 | 先保持两盒共有的尺寸与机构，再把已定刮痕的位置、方向和尺度设计到能被翻面观察的位置；保留尚未翻面时的相似性 | 观众先能理解认错的可能，翻面后又能辨认依据；不靠通篇深色调制造悬疑 | 新暗格、血迹、密码或原剧本没有的身份秘密 |
| 家庭现实戏里同一张桌子先用于修东西，再用于吃饭 | 桌面与通道要容纳两种已定用途；已确认的工具可有可收起的位置，材料与磨损符合使用者生活条件 | 人物收与不收、让与不让能实际改变彼此空间；美术支持关系行动 | 未设定的贫富标签、额外家庭成员或一套童年创伤 |
| 情感微电影里人物要归还一件修补过的旧外套 | 若补痕尚未锁定，选择与原面料可辨但不抢眼的修补位置、材料和穿用痕迹；取景要让归还时的触碰可读 | 物件的具体历史随当下行动显现；无需另造昂贵信物证明感情 | 新增定情经过、品牌、台词或默认悲伤旧照 |
| 古装权谋戏里决定人物能否进入的是既定文书，而不是武力 | 按已确认时代或架空制度落实载体、收纳、展开方式及既定印记；若准确内容是证据，检查读字与印记的视距 | 身份权限通过递交、展开和核对被看懂；服饰不能遮住需要使用的位置 | 未核实的官制、礼制、历史纹样，或给某一方额外通行权 |
| 喜剧或儿童动画里不同体型角色要认真搬同一件家具 | 在既定角色结构下选择有区别的剪影和接触高度，统一家具尺度与可通过的门口；夸张服务既有误配动作 | 笑点来自可理解的配合偏差或修正，不必给角色统一滑稽表情 | 新肢体、未设定形变能力或用道具故障改写原落点 |
| 科幻/奇幻戏里已定装置或能力只有两种工作状态 | 沿既定规则把两态区别落实为可观察的结构、形态或信号，设计从何处启动及人物怎样接触；漫剧强化关键姿态可读性，真人保留可实现的操作 | 观众能辨认规则在何时生效；视觉变化持续一致，不靠旁白补全部规则 | 新的第三种能力、额外代价、未经确认的符号寓意或万能接口 |

专项领域的设计依据不足时沿 `planning.md` 研究策略补真实缺口；不能为追求新奇编造专业事实。口播解说既有作品时优先采用已授权原片证据；不为填资产类别重画原作人物或伪造原片线索。只有确需新生成的原创画面才按相应类别准备资产。

设计的辨识度落实到本片实际可用的选择：人物剪影与穿戴方式、空间组织、物件结构或材质怎样让已定行动更有表现力；关键差别应在计划观察范围可辨。主次关系由叙事职责决定，不把所有部位都做成高对比装饰。若主要人物、场景与道具各自好看却相互争夺注意，先统一重点，再深化其余层次；沿已确认文字视觉合同执行，不另造风格板。白底资产图只能证明可见设计，正片的光线、纵深与摄影表达仍由分镜落实。

## 状态记录与出图判断

先按剧本记录状态，再判断是否缺少视觉依据，两者分开：

| 变化 | 怎样承接 | 是否补图 |
|---|---|---|
| 持有者、所在位置、朝向或接触关系改变 | 会影响后续理解的交接与位置关系写入适用的剧情时间线，正式分镜再落实动作和连续性；易主不等于物件换了身份 | 外观/结构未变且已有图能说明时复用，不为动作或归属单独生成状态图 |
| 表情、视线、短暂姿势、语气等即时表演改变 | 由已确认剧本和后续分镜逐句逐镜安排；不为每个表情或姿势建立资产 `state_id`，也不逐次写入外观状态时间线 | 沿用身份与当前造型依据，不补情绪全套图，不要求表演首尾相同 |
| 换装、妆发、伤痕、伪装、装具、年龄/生命阶段等可见外观改变 | 记录生效场次、原因和变化范围，先查项目内是否已有该状态 | 当前集需要稳定复现、现有图不能说明时才补；局部变化可用清晰状态主视图或细节，不一律重做三视图 |
| 道具开合、破损、点亮、沾染、内容物或关键可见面出现新结构/内容 | 按 PROP 复现前提记录状态；先检查已批准图是否已清楚包含所需状态 | 确有新的可见信息且要复现时补状态/细节图；单纯翻转到既有背面不算新设计 |
| 时间、天气、灯开关等环境变化 | 在场景状态时间线记录光源、原因和结果，固定空间锚点沿用 | 现有布局加状态描述已足够时不重画；变化产生需稳定复现的新外观且现有依据不足时补图 |

需要 `state_id` 的连续性状态仍按原合同登记。多个状态可绑定同一真实 approved 文件或同图不同分区；在数据卡与本集资产引用中写明所用版本、范围及需要变化的动作关系，复用不伪造生成记录。不同状态名不要求不同图片，不同文件也不能仅因命名就证明状态正确。已有图片不能说明新服装或破损结构时，不能借“复用”跳过必要补图。

资产阶段以当前集场次和关键行动确定需求，不预填尚不存在的镜号/SEG；正式分镜再补映射。如果此后发现确实缺少必要视觉信息，只补受影响资产并按原规则确认，其他已确认内容复用。资产阶段不依赖尚未建立的连续性账本或生成后的 FRM 才能开始；已有 FRM 仅在真实可用且相关时复用。

## 生图工具路由

| 输入条件 | 工具 | 规则 |
|---|---|---|
| 主动扫描后，当前目标没有任何有效视觉参考维度，从项目语言描述创建新图 | `image_gen` | T2I；不传入图片；文字图片、文档截图、剧本图、台词图和 OCR 来源只有在逐张查看后确认只含文字、没有当前目标相关视觉维度时，才不作为图片输入 |
| 当前目标存在需要视觉输入锁定的参考维度 | `image_edit` | I2I；控制外观、结构、构图、姿态、身份、场景、道具、材质、色彩、光影、媒介或风格等维度的用户图、必要检索图、截图、已批准资产、三视图、状态图、FRM、人物或风格参考图都可作为输入图；用户未明确要求“参考”也必须自主判断并传入；按当前生成目标选择足够且必要的相关图片，按实际顺序登记图片 ID、采用维度、剥离维度和编辑范围；命中当前目标的必要参考维度却未真实传入图片、或仅用文字描述参考图，必须停止并修正工具请求，不得改用 `image_gen` |

参考图按“哪些维度能约束当前视觉结果”判断，不按来源判断，也不等用户说“参考”。生成或修订前先扫描已经逐张查看并登记的用户上传/指定/认可图、外部核验图、同资产旧 approved 版、相关 CHR/SCN/PROP、状态图、FRM 和有效用户风格图。用户图优先锁用户指定维度，已生成图锁项目连续性；两者职责不同且都相关时必须同时传入。只传当前目标必要参考，并登记来源、采用维度和剥离维度；“只传必要”只能用于排除与当前目标无关、质量不可用、被用户明确断开或被边界声明剥离的图片，不能用于省略当前目标需要锁定的身份、状态、空间、结构、道具、构图、姿态、媒介、画风、色彩、光影或材质参考。文字资料、剧本图、指令图、文档/表格截图也须逐张查看：只提供文字内容时登记为文字来源；同时提供当前目标需要的布局、形体、色彩或其他视觉维度时，同时登记其视觉用途，不能仅凭来源类型排除。若用户要求断开某参考，记录原文和原因；若用户图与 approved 资产冲突且无法兼容，先确认取舍。若工具请求无法传入已判定必要的参考图，停止生成并返回能力或输入问题，不能降级为纯文生图。

选择参考时依次处理：先列本次要锁的身份、状态、空间、结构与必要画风，再找能真实覆盖各职责的清晰图；同一职责有多个等价来源时选择已确认且适用的版本，不重复叠加。用户图锁其指定维度，approved 图锁项目连续性，职责不同且都必需时同时传入；一个状态图已经覆盖身份与当前服装时，可替代同职责的旧基准图，但不得违反用户明确要求同时采用的来源。已有必要人物或场景参考时必须实际传图，不能只读不传或裁掉必需信息再改用 `image_gen`。图片输入超限时先去掉冗余和无关弱参考；仍无法覆盖必需职责就拆分可分离的编辑任务或报告阻断，不静默降级。

用户认可的任一清晰视觉参考图都可登记为 `style_anchor_reference`，作为后续人物、状态、场景、道具和图片资产的画风锚点。锚点只锁媒介、线条、上色、纸感/颗粒、色阶、材质、光影和设定稿质感，不锁原图无关身份、脸、服装、姿态、剧情状态或场景布局；Prompt 第一句必须写出具体 `style_prompt_terms`，不能只写“参考风格”。例如用户只上传漫画场景图并要求做短剧时，该图至少锁定漫画/非真人媒介，人物首版可以没有人物身份参考，但必须继承同一漫画画风，不得生成真人。真人写实/照片级锚点要求人物、场景和道具都按真实材质、光影、透视和摄影逻辑；2D 漫画/动漫/插画/动态漫/水墨锚点要求人物、场景和道具保持同一非真人媒介。

`project_visual_mode` 由文字视觉合同、用户指令或 approved 图片锁定。即使没有同类别参考，也要继承已有可观察画风词；例如用人物图给场景定媒介、线条、上色、质感、色阶和光影但不继承人物身份，也可以用漫画场景图给人物定漫画媒介、线条、上色、纸感和光影但不继承场景布局。后续人物、场景、道具、视频输入图和视频 Prompt 都沿用同一画风；电影感只体现为构图、光线、节奏和调度，不等于真人化。风格反差只有用户明确要求并登记范围时才允许。若后续参考图质量更差或风格不一致，不能覆盖 `project_visual_mode`，只能作为弱参考或触发用户确认。

该路由覆盖所有类别与首版：没有同类别图、但有本次需要采用的画风锚点时，仍真实传入锚点走 `image_edit`，只继承画风；只有当前目标连画风在内的必要视觉维度均无有效图片来源，才走 `image_gen`。同一素材的新增状态、细节与修订基于 approved 依据编辑；单纯裁取已有视图属于媒体派生，按原委派边界执行，不伪记为生图。图片版式先按信息可读性选择；多视图设定板默认 `16:9`，单视图和细节图可选工具支持且适合主体的画幅。用户指定的资产画幅优先，实际比例只走工具参数，不写进 Prompt；这不改变 `planning.md` 已确认的视频画幅。

执行顺序：

1. 读取已确认项目级故事包、数据卡和 `current_episode` 的详细剧本，只列当前集实际出场的人物、主要场景、剧情功能道具、音色、风格及状态版本；按来源规则完成新增/替换图片的逐张查看并复用未变登记，再为当前集每个 CHR/SCN/PROP 选取可用视觉参考，将可用候选记入 `available_visual_reference_ids`。按上文选择实际必要输入并逐张传入、登记顺序；可用候选不等于全部必传。未选图说明无关、不可用、冲突待确认、用户明确断开，或其必要职责已由哪张适用图充分覆盖，不得把“精简”当作缺失必要依据的理由。未命中的用户图片也保留在 `source_manifest.json` 中。
2. 按稳定 ID、别名、状态名和 `voice_anchor` 查询 `asset_registry.json` 及所有已完成分集的 `asset_usage_ep_N.json`。找到 approved 可用版本时写入当前集 `shared_assets` 或 `reused_episode_assets`，不重新生成；只补当前集实际需要且尚无可用版本的资产，不生成全局风格板。共享资产一旦 `approved` 不得被分集重画。
3. 根据“从剧本确定设计与制作范围”先连通当前场次的人物、空间、物件和声音，按“状态记录与出图判断”区分复用、补局部与新建。需求及生效范围回写既有数据卡，只在未来集出现的变化保留为计划，不提前生成。
4. 先确定本次资产的用途、适用视图和必要参考，再按对应类别章节提交完整 Prompt。满足 PROP 复现前提的物件保留原升级规则；状态 ID 与图片分别判断，指向能真实说明该状态的 approved 文件或分区，不为所有权和动作另造相同图。一次性物件不因手持、特写等动作单独升级为 PROP。
5. 直交、保存、登记并按采用决定收口：每张成功图片先按 `media-delivery.md` 逐项 RichMediaCard 直交，再保存登记；每个条目说明用途、生效场次、实际视图／分区和必要采用边界；场景另列 `3-5` 个一致性锚点。生成结果有问题仍如实展示，不能因交付了就标为 approved。只按现有用户采用确认收口，不安排独立看图／试听验收，不提前进入分镜。

每个图片资产版本必须同时保存 Prompt 文件：共享资产建议使用 `shared/03_资产/提示词/提示词_[资产ID]_[名称]_vNN.md`，分集资产建议使用 `episodes/ep_N/03_资产/提示词/提示词_[资产ID]_[名称]_vNN_ep_N.md`。Prompt 文件保存实际传给模型的完整提交文本，不保存摘要、压缩版、说明版或改写版；若一次调用生成多张候选图，也要能追溯每张 adopted 文件对应的完整 Prompt 原文。

生成图、参考图和下游输入图可使用当前工具支持的常见图片格式，例如 `.png|.jpg|.jpeg|.webp`。打不开、未下载完成、云端占位、扩展名错误或零字节文件不得 approved；发现问题后重新下载、生成或转存并登记新版本。

生成安排与采用清单按“人物 → 场景 → 道具 → 音色”排序；统一风格以文字说明，不生成或展示独立风格板。人物按角色、道具按物件归组安排；只有当前用途需要的基准、多视图、状态、细节或修订版本才生成，返回即展示，不等整组凑齐。采用清单在同一条目引用已展示的相应版本。图片按 `media-delivery.md` 立即逐项直交，音频使用宿主文件工具直接试听；Prompt 文件只在用户明确要求查看、排查或交接时紧邻条目展示。每张图旁用自然语言说明实际状态、适用集／场次和需要采用的内容；不显示内部 ID、工具名、字段、任务号或检查统计。保持图文交叉和同类独立编号；类别顺序用于安排生成，不延迟成功图片的即时交付。归档不重复展示或创建媒体，不用工具预览、裸链接或路径代替交付。

## 分类目录与命名

完整目录和命名只读取 `manifests.md`。本阶段按当前集真实需求和资产使用范围存储：当前集首次需要且预计跨集稳定复用的 CHR/SCN/PROP/VOICE 进入共享资产库；只在当前集首次出现或暂不适合升为共享的分集专属 CHR/SCN/PROP/VOICE、角色/道具状态资产进入对应 `episodes/ep_N/03_资产/`。后续其他集再次需要时通过 `shared_assets` 或 `reused_episode_assets` 引用原 approved 版本。不得因为全剧剧本已经完成，就提前生成未来集才首次出现的共享资产。重生成递增 `_vNN`，不得覆盖已确认版本。

## 资产说明记录

每项资产必须先登记以下信息，再生成资源：

| 字段         | 要求                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 资产 ID      | 使用稳定前缀：角色 `CHRxxx`、场景 `SCNxxx`、道具 `PROPxxx`、音色 `VOICExxx` |
| 类别         | 角色 / 场景 / 音色 / 道具；风格记在文字视觉合同中 |
| 名称         | 唯一、稳定、与剧本和分镜一致的名称                                                                   |
| 介绍         | 一句话说明剧情身份、叙事功能或使用目的                                                               |
| 详细描述     | 完整记录外观、空间、声音、结构、状态、风格和连续性要求                                               |
| 锁定与可变项 | 分开记录不得漂移的身份锚点，以及服装、伤痕、开合、破损等状态变量                                     |
| 使用范围     | 资产阶段先记录适用集数、场次和状态范围；分镜确认后再补镜号与视频片段映射 |
| 来源与下游   | 来源剧本场次，以及用于哪些分镜、视频核对或成片声音轨 |
| 文件与状态   | 媒体就绪后登记真实文件、路径、版本、来源/实际生成模型、审阅日期及 `draft/reviewed/approved/rejected/superseded`；未生成时不得预填通过 |

这些是信息职责，按既有数据卡、`asset_registry.json` 和 `asset_usage_ep_N.json` 分工登记，不为每个类别再维护 `类别_资产说明.md`。分集使用范围和本集状态写入 `asset_usage_ep_N.json`；用户需要的说明紧邻媒体展示，避免重复维护另一份事实来源。

资产登记遵循 `manifests.md` 和 `control-contracts.md`：

- 数据卡定义身份和状态，`asset_registry.json` 登记共享媒体版本。
- 换装、受伤、破损、场景布置或灯光变化先写入数据卡与 `asset_usage_ep_N.json`；是否新建媒体按“状态记录与出图判断”，已有图片足够时登记复用。
- 视频内发生且后续延续的角色/道具状态变化，按 `video.md` 取得清晰 FRM；现有 approved 依据不能说明需延续的新外观时，再基于 FRM 或上游资产补图并确认。资产阶段不要求先有尚未生成的 FRM。
- 同一身份/剧情状态中确被替代的错误或修订旧版标记 `superseded` 并保留；不同有效剧情状态可并存，不因新状态版本号更大就废弃原状态。只有 `approved` 版本可用于下游，分集绑定不能重新批准共享来源已经废弃的媒体。

用户追加或替换图片时：先逐张查看、登记来源、分类并匹配稳定资产 ID；命中现有 CHR/SCN/PROP 时创建新 `_vNN`，不覆盖旧版；再找出依赖旧版本的共享基准图、分集状态图、细节图、修订图和视频输入图，逐项重生或重新绑定并确认。只更新当前单张图片属于遗漏；无依赖项不得连带重做。逐张查看后确实仅提供文字/说明或与当前目标无关的图，也须在 `source_manifest.json` 记录原因；提供当前所需光色、材质或画风的氛围图仍按有效视觉维度处理。

## 场景参考与文字视觉合同

需新生成或复现画面中，每个跨集、反复出现、长时间停留、涉及多人走位/镜头轴线、承担证据或情绪空间功能的主要剧情场景，都必须建立一个 `SCNxxx` 场景布局参考图。它和人物、道具一样是基础资产，不是可省略的氛围图；在该场景生成视频时必须传入对应 approved SCN。仅剪用原片的范围按“目标与输入条件”核验来源，不另造布局。

先用剧本中的关键行动确定场景必须提供的关系：谁能从何处进出，谁能看见或挡住谁，人物与桌面、门口、隐藏处之间的距离怎样影响行动。图中要能辨认这些条件，不能只按“豪华、压抑、温馨”装饰空间。

长期使用、多人调度或空间关系复杂的主要 `SCNxxx` 优先采用完整布局与必要多视角，四宫格沿用下列标准。使用范围明确的简单空间，可从能说明行动区域与主要通道的清晰主视图开始；一个视角看不见关键出入口、遮挡或动线时，补反向、俯视或必要局部，不能因没有正式镜号就判定不需要。需求不清时采用完整布局标准。多视图始终属于同一个场景、同一设计和同一视觉风格，不是不同场景：

- 第 1 格：近景视角，展示最有识别力的固定陈设、材质、墙面/桌面/门窗细节和可被镜头反复核对的场景锚点。
- 第 2 格：远景视角，展示主要行动区域、入口出口、人物可站位区域、通道关系和前中后景层次。
- 第 3 格：平视全景视角，展示观众进入视频时最常用的空间识别角度、地面/墙面/大型家具关系和基础光位。
- 第 4 格：远景俯拍视角，展示完整空间布局、画面外环境结构、门窗朝向、动线、固定家具和场景边界。

有用户上传、指定或已批准的场景参考图时，真实传入所需场景图走 `image_edit`。下例只在选用四宫格时采用；选择主视图/其他补充视角时相应改写版式，保持同等空间信息与参考边界：

```text
全项目统一保持[已确认媒介、线条、上色、纸感/颗粒、色阶、材质、光影、构图和空间氛围]。基于这张场景参考图，生成一张同一场景的四宫格布局参考图。四格分别为近景视角、远景视角、平视全景视角、远景俯拍视角；远景俯拍视角需要展示完整空间布局，补出画面外的环境结构。保持原图场景风格、材质、色调、光影和空间氛围一致，必须保持原图风格、材质、色调、光影一致。只补全空间结构和可见陈设，不改变场景时代、建筑材质、主要家具位置、基础光源方向和整体氛围。
```

场景首版也执行“生图工具路由”：没有场景图但需要采用已有画风锚点时，传锚点走 `image_edit`，只继承其画风；连必要画风在内都无有效图片参考时才用 `image_gen`。继承项目 `project_visual_mode`，真人写实呈现可信实景与材质，非真人保持已确认画法。同场景后续修订和确需补图的状态变化基于 approved SCN 编辑，不重新文生图。

场景资产采用清晰、可读、适合辨认结构的基础光展示，单视图与多视图都按实际行动检查：

- 户型或空间边界、门窗朝向、入口出口和主要通道。
- 固定家具、墙面、地面、台面和大型陈设的位置、比例与材质。
- 固定空间参照和主要人物活动区域，是否支持剧本需要的遮挡、视线与相互接近；正式镜头轴线在分镜阶段确定。
- 基础光源位置、方向、色温；剧情灯光变化另记入数据卡状态时间线。
- 不包含具体剧情动作、临时人物表演、字幕、水印、无关文字或随机新增道具。

每个 `SCNxxx` 只选择 `3-5` 个最有识别力的 `consistency_anchors`。锚点写清对象、外观和固定位置，例如“从室内面向入口时，门右侧的绿色铁皮文件柜”“后墙中央的圆形挂钟”；“老旧、压抑、有年代感”不能作为锚点。固定的是挂钟的位置与外观，指针随剧情时间变化，除非剧本明确停钟；观看角度改变时画面左右可以改变，物件在空间中的关系不能漂移。锚点不是全部物件清单，也不选择频繁移动的临时小物。

多视图逐项对照同一组门窗、家具、光源与锚点关系：桌子不能在反向视图中换墙，补出的通道不能穿过原有固定家具。再顺着关键行动核对通路、距离、遮挡和可用台面是否实际成立；图上未显示且无法判断的关键空间应补清，不能自行宣布一致。

场景基准图只生产剧本实际需要的基础光照。阴天上午、停电应急灯、火灾警示灯等变化从已确认剧情反推，并写入 `project_data_card.json.scenes[].state_timeline`：

- 每个状态绑定生效集、场次、原因和可观察结果。
- 没有进入剧本的白天、黄昏、夜晚版本不预制。
- 临时开灯、停电或环境变化不改写固定空间 `consistency_anchors`，也不另造空间身份。固定结构改造或损毁时更新布局版本；光照等状态是否需要补充媒体，按“状态记录与出图判断”处理，保留同一 SCN 与真实版本来源。
- 把这 `3-5` 个锚点落实到视频 Prompt 和实际参考输入，不安排生成后场景锚点帧核验。

场景布局参考命名为 `场景_SCNxxx_[场景名]_[主视图或实际视图名]_vNN.[ext]`；四宫格仍可用 `_四宫格布局参考_`。若剧情明确改造空间、损毁固定结构或跨时代变化，建立新版本并记录生效范围；临时挪动或开关灯按状态判断，不自动重画。交付时把自然语言介绍与图片放在同一条目，说明剧情功能、使用范围、实际视角、锚点与采用/剥离边界。

## 文字视觉合同与视频参考精简

完整与轻量模式都不默认生成独立风格板。文字合同只锁媒介、必要光色、材质和构图倾向，角色/场景一致性由各自 approved 资产承担。用户提供的有效风格图可按需采用，不产生 STYLE001 必需项。

每个视频输入必须有独立作用；每图一个主 role，附带覆盖维度写入 adopt，同步调整分镜所需主职责，不因同图多维度重复上传。已有清晰图足以锁定一个维度时不重复叠加。多视图、四宫格用于资产设定，输入视频前优先从 approved 图选择适用的清晰单视图；若确需多宫格，明确它是同一主体/空间的参考，禁止输出拼版或复制主体。实际裁剪等媒体变更仍按原委派边界执行，不重画身份。

### 从设定图选取下游可用依据

资产阶段先看图判断当前场次的用途是否有依据；正式镜头和 SEG 输入组合在分镜、视频阶段落实，不提前生产镜头首帧或额外演示图。选取或派生参考时连着本场一次关键行动核对：人物从哪里开始，用哪只手接触什么，物件怎样移动或打开，空间哪里需要留空，结束后哪些外观或关系会延续。图中没有依据的条件标明缺口，不把文字推演当实测结果。

- **人物**：对白近景应能看清身份；全身行动还需体态、服装与接触部位。三视图裁成全身后脸已过小，就查原图清晰头部区是否可派生补充；不能把“画面里有脸”等同于能锁脸，也不默认额外生一张脸。裁剪不能重画身份或改变已确认比例。
- **场景**：选能同时交代当前入口、行动区和关键遮挡的视角；四宫格裁出一个漂亮近景却丢失路径时，保留可说明路径的对应视角，或在正式分镜映射时组合必要依据。不把俯视布局直接当成指定正片机位。
- **道具与状态**：局部图应保留足够的主体边界或连接参照，使人能知道破损、接口、刻字在什么位置；细节无法说明整体时与原主视图合用。同一多状态板选当前所需分区，不将互斥状态一起当成当前状态。
- **合用**：把拟采用的实际图片并排看，比较相对尺度、左右/空间定位、服装与物件状态、关键接触高度及画法；白底、展示光、板式和中性姿势只是资产展示方式，不继承为剧情画面要求。没有实拍或视频结果时，只确认这些可见条件，不声称动作执行成功。
- **输入数量**：一张图已覆盖兼容职责就复用，重复角度、旧造型和无关风格图不叠加。后续按实际工具上限选择真实文件；必要信息无法同时覆盖时按 `video.md` 处理，不能用拼贴多人/多空间、缩到看不清或缺图执行来凑数量。

例如角色要从柜台后拿盒子交给对面的人：全身图负责人物与穿戴，场景图负责柜台高度和两侧通路，盒子图负责可握持尺度与当前开合；三者发生矛盾时修正有问题的设计或视图。资产阶段不因此新增一个“交盒首帧”，也不能直接宣称交接动作已经验证。

## 角色资产

角色不限于真人，也可以是动漫人形、卡通人形、拟人动物、自然动物或其他剧情生物。生成前先依据 `drama_plan.json.type_strategy.format`、视觉风格合同和人物小传登记 `representation_type`：

```text
live_action_human | anime_human | cartoon_humanoid | anthropomorphic_animal | natural_animal | creature
```

不得把动漫、卡通或动物角色强行真人化，也不得把真人角色擅自改成动画形态。除非用户明确设定特殊风格反差，全项目角色使用同一 `project_visual_mode`。首版、状态与修订均执行“生图工具路由”，只含画风的图不能替代身份依据。

先从本集实际行动和出场范围选择版式；不因每个角色有 ID 就重复生成所有视图：

| 本次用途 | 选择与检查 |
|---|---|
| 使用范围明确且有限，一个主要观察角度已足以说明身份与实际可见造型 | 新建时可用清晰身份主视图，已有合格图则复用；取景须覆盖实际需要的身体与服装范围，不能用头像冒充全身依据；不把“尚未想好其他角度”当成简化依据 |
| 主要人物反复出镜、跨集复用、本集需要侧背或全身动作，或服装/装具结构须从多个方向说明 | 优先用下列完整三视图设定板；若已批准素材已覆盖所需角度和造型，登记复用而非重新制板；需求不清时沿完整标准 |
| 局部伤痕、配饰、妆发或服装细节变化 | 基于 approved 图编辑清晰状态主视图或局部细节，说明位置与尺度；细节不足以单独锁身份/整体造型时与原基准一起使用 |
| 整套服装、年龄、伪装或形体大范围改变 | 生成覆盖变化范围的状态主视图或三视图，继续验证同一身份，不能仅用局部贴片代替整体依据 |

三视图设定板选用以下版式；单视图沿用适用的身份、结构、材质与中性状态要求，不套多格排版：

- 纯白中性背景，棚拍均匀柔光，无环境色污染。
- 左侧 `1/3` 为超大高清正面头部特写：头部端正、正对镜头，不偏转、不低头、不抬头、不斜视，头面约占左侧区域 `80%`。
- 右侧 `2/3` 横向排列完整全身正面、严格 `90 度` 侧面、背面三视图；三个身体等大对齐，最高点与最低接地点基线一致，全部肢体、翼、尾、角、耳等完整入画。
- 特写与三视图必须是同一个角色；右侧正面头部与左侧特写在头面结构、颜色纹理和身份标志上完全一致，三个角度的体型、毛发/发型、服装/装具、配饰和识别特征一致。
- 基准角色资产必须使用**中性无表情**：按已确认头面结构与当前外观状态自然放松，不作情绪表演。有且正常可睁开的眼睛自然睁开，有且适合闭合的嘴/喙自然闭合；已确认的特殊结构、器官缺失或固有闭合状态照设定保留，不能为套模板额外补眼、补嘴或修复原有特征。不微笑、不皱眉、不龇牙、不吐舌、不瞪眼，不表现愤怒、悲伤、惊讶、恐惧、轻蔑、挑逗或卖萌等情绪。正面特写、正面全身和侧面保持同一中性状态，观察方向随视图而非全都正面凝视。
- 面部或头部符合已确认角色类型、个体设定、物种和画风。真人遵循可信结构；动漫和卡通遵循已确认设计比例但不得出现非设计性的五官错位；动物遵循物种结构与已确认个体差异，虚构生物遵循既定器官数量与连接关系。不能以“正常”之名覆盖已确认的疤痕、缺失或特殊结构，也不得擅自长出人脸或额外器官。
- 不同角色必须有明显长相区分度。资产 Prompt 和登记必须写 `character_distinction_keys`，至少覆盖脸型/下颌、眼型/眉形、鼻梁/嘴唇、年龄感、发际线/发型轮廓、体态剪影、痣疤配饰或其他身份标志中的多项；除双胞胎、克隆或同一角色状态版外，不能共脸、共轮廓，也不能只靠服装颜色或发色区分。
- 妆容和表面修饰按类型处理：真人默认无妆或自然日常妆；动漫/卡通默认干净基础妆面或原始角色设计；动物默认无人体妆容，只描述毛色、羽色、鳞片、斑纹和必要装饰。特殊妆造、脸谱、战损或物种变形只有在用户或剧情明确要求时建立状态版本。
- 详细描述按下文信息职责组织，覆盖本次实际需要的身份、尺度、形体、妆发、服装可见结构与材质；不为填满字段编造不可见细节。存在 `style_anchor_reference` 时写明采用的具体画风词和剥离边界。
- 三视图是资产设定板，不是多个角色。使用 `image_edit` 或 `media_to_video` 引用三视图时，必须声明：`该图展示同一角色的多个角度，输出中只出现一个该角色，不复制、不并列生成图中的多个角色。`
- 复杂多角色、近景对白或三视图曾引发复制且现有图不足以清楚锁脸时，从 approved 图派生无遮挡头部身份锚点，命名为 `角色_CHRxxx_[角色名]_头部身份锚点_vNN.[ext]`。头部图补脸部识别，主视图/三视图锁本集需要的整体造型；已有清晰身份主视图足够时不重复加图。派生不重画身份，实际裁剪按原媒体委派边界执行。

### 角色资产可见写法

人物资产 Prompt 写可复用的身份和造型，不写剧情高潮表演。用位置、数量、比例、轮廓、材质、纹理、遮挡等可见限定替代空泛形容；同一信息不在多个层级重复。优先保留角色类型、区分点、剪影、发型或物种表面、当前服装装具与剧情必需细节，不靠堆字获得完整度。

脸部区分点要写成可观察差异：脸型、下颌线、眼型、眉形、鼻梁、嘴唇厚薄、耳形、发际线、发型轮廓、年龄感、痣疤或配饰的位置。不要只写“漂亮、英气、高级、少年感强”；改写为眉峰角度、眼裂长度、鼻梁高度、下颌宽窄、嘴角形状、发束走向等可生成特征。不同角色的区分点不能只靠衣服颜色。

体态和肢体按角色类型与取景范围写清：整体造型需要身高或相对尺度、体态比例、肢体结构与自然姿态；动物或其他生物使用体长/肩高、物种关节、爪蹄翼尾等适用结构。三视图完整呈现身体及附属部位；局部身份图不强塞不可见脚部和站姿描述。“高挑、清瘦”等可配合具体轮廓与相对比例，不单靠抽象词锁定设计；剧情关键的可数结构不能写成“若干”。

服装、装具和表面材质写可复现的可见结果：整体层次、领口、衣袖与下摆轮廓、主要材质和颜色；扣具、绑带、口袋、磨损等在影响识别、穿戴或关键动作时细化数量、位置和连接。检查衣物是否支持本集的取藏、奔跑、伸手等既定动作，不为展示“职业”添加无用工具。稳定颜色写具体色名，受光变化写明暗与部位差异。没有剧情确认的文字、logo、品牌或符号不添加；确需短文字时写清载体、位置和准确内容。

中性表情是基准资产要求，不是后续表演限制。状态资产仍保持身份和造型可复用，只修改已确认状态变量，例如换装、伤痕、发型、装具或年龄阶段；表情、视线、动作和与道具互动留给分镜和视频 Prompt。角色状态资产原则上必须 `image_edit` 已批准角色基准图或上一状态图，继续继承同一脸、体态、服装体系和 `project_visual_mode`；不得把状态变化当作新角色重新 `image_gen`。

### 角色表现类型分支

| 类型 | 结构与比例 | 外观重点 | 不适用项 |
|---|---|---|---|
| 真人/写实人物 | 可信人体、头身比、五指和自然站姿 | 真实肤质、五官、发型、自然妆容、服装材质 | 不使用动物器官或卡通夸张比例 |
| 动漫人形 | 遵循已确认画风的头身比与线条设计，正侧背结构可互相推导 | 发束、瞳色、线稿、色块、服装轮廓和角色标志 | 不强制真人毛孔、真人骨相或写实摄影皮肤 |

| 拟人动物 | 先锁物种特征，再锁人形站姿、手/爪功能和服装结构 | 口鼻/喙、耳、角、尾、毛羽鳞纹理及拟人比例 | 不自动替换成人脸，不默认人体妆容 |

### 角色 Prompt 的信息职责

按 `drama_plan.json.language_contract.video_language` 写自然描述。下列七组用于组织信息，不要求机械标题；按选定版式与本次变化范围采用，不为局部编辑复述整套设计。

| 组别 | 按本次用途采用的内容 |
|---|---|
| 1. 类型、风格与用途 | 明确 `representation_type`，继承 `drama_plan.json.style_contract` 的可观察风格机制，并说明该图用于锁定身份与造型；若使用已批准或用户认可的视觉图作为 `style_anchor_reference`，必须从锚点抽取并写出具体画风词，明确不继承锚点中的无关人物、场景、道具、姿态、布局和剧情状态；若该角色为漫画/动漫/插画/水墨风，必须声明全项目画面继续使用同一非真人画风 |
| 2. 版式与身份一致 | 主视图说明覆盖范围；选三视图时用左头部特写、右正侧背的设定板，等大对齐、身体完整且属于同一角色；局部图说明与原身份的对应位置 |
| 3. 体态与肢体 | 按角色类型写年龄/生命阶段、性别表达、身高或相对尺度、体型、头身比或物种比例、肩宽、腰线、四肢比例、自然姿态、重心和肢体结构；人形角色写手指数量和可见手部状态，动物检查爪、蹄、翼、尾及物种关节 |
| 4. 头面结构与中性表情 | 真人写可信个体结构；动漫/卡通和其他生物遵循既定设计；动物写适用的物种结构与个体特征；中性表情不覆盖已确认器官数量、有无与固有状态；用本角色实际具有的结构、颜色纹理、轮廓和年龄感区分身份，不强填不存在的五官 |
| 5. 毛发、妆容与识别特征 | 人形写发型、发际线、发束走向及适用妆容；动物写毛、羽、鳞、斑纹方向；饰品、角、耳、尾、痣、疤痕等身份特征写清位置、数量、大小和是否被遮挡，没有则写“无” |

### 中性表情与正常头面结构合同

每个基准三视图 Prompt 都要落实以下中性语义，按角色实际结构写成具体句子；没有的器官不写，已确认个体特征不矫正，不逐字套用所有物种分支：

```text
表情状态中性，不作情绪表演。按已确认头面结构、器官数量与当前外观状态自然放松，[写本角色实际适用的眼睛开合、口部自然状态和各视图观察方向]，保持已确认的个体特征；不额外添加、修复或改造器官，不用情绪造型代替身份基准。
```

再按角色类型追加且只追加一个结构分支：

```text
真人/写实人物：面部结构自然可信，适用五官无非设定畸变，保留已确认的个体结构、原有标记与真实肤质，无塑料脸、蜡像脸或过度磨皮。
```

```text
动漫/卡通人形：头面结构符合已确认角色设计与画风，正面和侧面的五官位置可互相对应，无非设计性的错位、重复、缺失或左右漂移，不擅自真人化。
```

```text
拟人动物/自然动物/其他生物：头面结构符合已确认物种、生物设定与个体特征，只描述实际存在的器官，数量、位置及连接正确，无非设定的器官补齐、错位、粘连或人脸化。
```

妆容或表面修饰也按类型选择：真人使用无妆或自然日常妆；动漫/卡通保持干净基础妆面或原始设计；动物默认无人体妆容，只描述毛色、羽色、鳞片、斑纹和已确认装饰。



### 角色资产人工查看

写生成要求时明确本片人物辨识、多视图身份、穿戴与覆盖；把活动、取藏、装具和尺度放回关键动作设计。返回后直接展示，由用户确认采用，不新增资产质检。

## 角色身份与状态追踪

- **身份锁定**：脸型/头面、五官、肤色或物种表面、已定痣/旧疤等识别标志、基准身高体型和 `voice_id` 保持；剧情明确的年龄、损伤或变形按已确认时间线变化，不能把新伤与固有标志混写。
- **持续外观状态**：服装、发型、妆容、新伤、沾染、湿润、装具或形体等变化，按已确认剧情在 `project_data_card.json.characters[].state_timeline` 登记生效场次、原因和结果；是否补图另按上文判断。
- **即时表演**：表情、视线、姿态、语气随剧本与分镜变化，只继承适用的身份和持续外观，不逐次建立外观状态条目或资产状态 ID。
- **片段内变化**：换装、受伤、弄湿、变形等持续外观变化必须有已确认的剧情依据，并由分镜交代发生过程或明确省略；没有依据时外观不能自行改变。表情和动作可以自然发展，首尾不要求相同。
- **跨片段变化**：持续外观不同或关键持有关系发生交接时，SEAM 记录可理解的动作、时空跳跃或其他剧情原因；即时表演按接缝关系衔接，不能把情绪自然变化判成换装穿帮。
- **生成读取**：每次视频生成参数确认记录数据卡 revision、出场角色 ID 与当前状态 ID，只补动作、表情和临时接触关系等片段增量。

资产设计继承本集采用的 CHR/SCN/PROP 基准，必要参考实际传入；不额外生成代表候选或做生成后对比，视频返回后直接交付。

## 道具资产

只为满足复现前提并推动剧情的道具生成设定图；单次出现或只在单个镜头内发生状态变化的物件不因“证据、手持、特写、开合、破损、染血、调包”等动作自动升级为 PROP。首版与修订均执行“生图工具路由”，只含画风的图不能替代结构依据。道具优先检查**结构准确、状态准确、材质颜色可信，再完善风格表现**；不能用强光、景深或装饰遮盖结构错误，也不改变已确认媒介。

道具资产清单从已确认剧情亮点、反转、证据链、身份关系和连续性需求反推；不是从场景装饰物穷举。道具必须先满足“多次出现、跨场景出现、跨片段承担连续性、状态会被后续片段复现，或用户明确要求单独生成道具设定图”这一复现前提，才考虑升级为 `PROP` 并生成视觉资产。只出现一次的证据物、手持物、特写物、开合/破损/染血物或调包物，默认写进场景、分镜或视频 Prompt，不单独生成道具图。

满足复现前提后，任一道具再命中以下条件之一，就必须进入数据卡、生成视觉资产并在下游按状态引用：

- 推动剧情反转、改变局势、制造悬念或完成高潮兑现。
- 证明身份、关系、秘密、所有权、时间线或证据归属。
- 被角色持有、传递、争抢、穿戴、打开、损坏、修复、调包或藏匿。
- 会被特写、近景、局部细节卡明确拍到。
- 有开合、破损、染血、发光、内容物、位置、归属、完整性等可观察状态变化，且该状态需要在后续片段中保持或回看。
- 和某个角色强绑定，成为其身份、职业、记忆或动机的标志物。

普通环境装饰和一次性剧情物件只写入场景、分镜或视频 Prompt，不单独出图；删除后不影响剧情理解、镜头连续性或角色行动的物件，不升级为 PROP。若普通物件后来被剧本或分镜赋予复现/连续性职责，必须补入数据卡并回到资产阶段生成或确认对应资产。

每个进入数据卡的核心道具在生成前必须同时确定以下三层：

1. **尺度**：`scale_class` 使用 `handheld|tabletop|furniture_scale|custom`，并用 `scale_reference` 写出厘米尺寸，或它与成人手掌、身体、桌面、门框等稳定参照物的比例。只有“大小适中”“小巧”不能通过。
2. **剧情功能**：`narrative_functions` 逐项绑定真实集、场次和功能，例如制造悬念、证明身份、改变证据归属或完成高潮兑现。没有剧情功能、删除后不影响任何镜头的物件不进入核心 PROP。
3. **状态变体**：`state_timeline` 至少包含初始状态；影响连续性的开合、破损、修复、点亮、沾染、内容物变化或易主记录生效范围、原因、变化字段和可观察结果。状态名不只写“新版”；状态 ID 与补图按“状态记录与出图判断”分别处理。

示例：

```text
尺度：handheld；成人单手可握，约 9 厘米长。
剧情功能：ep_1:E01S01 制造父亲遗物悬念；ep_2:E02S03 通过调包改变证据归属。
STATE001：闭合、完整、内有文件、女主持有。
STATE002：打开、完整、文件可见、女主持有；由当众开箱触发。
STATE003：锁扣损坏、文件丢失、男主取得；由争抢和调包触发。
```

生成前登记 `prop_layout_mode`：

```text
key_multiview | state_sheet | standard_main | detail
```

- **关键道具多视图 `key_multiview`**：本集需要稳定辨认正反结构、开合机构或多面差异，而主视图不能说明时，生成正面、严格 90 度侧面、背面三视图；视角按实际结构设计，不因“关键”二字自动选择多视图。
- **道具多状态图 `state_sheet`**：同一道具确有多种需要补图的外观状态时，优先用一张图分区；标明顺序、状态、触发及场次。多个状态可共用同图，但对应分区须可单独指认；引用沿用下文统一图片分区标记。纯归属变化直接复用原图，不另画一排相同道具。
- **道具主视图 `standard_main`**：一张图足以说明本集所需外观、结构与材质时，选择最有说明力的观察角度，道具居中、完整不裁切；约 `60%` 占比可作参考，以关键细节可读为准。剧情关键道具同样可以选主视图。
- **细节卡 `detail`**：内部结构、刻字、接口、发光部位、破损点、机关或材质细节在主图不可见但承担剧情作用时，另生成局部细节卡；不得把互斥状态或无关细节塞进主图。

画幅按“生图工具路由”的版式规则设置，只走工具参数。道具采用纯白或中性深灰背景、均匀展示光，依据轮廓与材质对比选择底色；不改变项目画法或材质颜色。

### 道具图 Prompt 的 7 组合同

Prompt 按以下七组使用 `drama_plan.json.language_contract.video_language` 的自然描述。七组是信息组织方式，不要求逐项机械堆标签：

| 组别 | 必填内容 |
|---|---|
| 1. 风格、模式与用途 | 继承已确认风格机制；写明 `prop_layout_mode`、道具类型、剧情用途和叙事意义 |
| 2. 版式与一致性 | 三视图写正面/严格 90 度侧面/背面、等大对齐、完整不裁切且三角度结构材质颜色一致；多状态图写分区顺序和每区状态；主视图写最佳观察角度、居中和约 `60%` 占比 |
| 3. 尺寸与整体结构 | 整体尺寸或相对尺度、长宽高比例、边角形态、主要组成部分、连接和开合方式 |
| 4. 部件与空间关系 | 每个关键部件的数量、形状、尺寸、位置、连接关系、朝向及当前状态 |
| 5. 材质、纹理与颜色 | 基础材质、表面处理、光泽度、纹理、主辅色、部位色差，以及与剧情一致的划痕、氧化、污渍或磨损 |
| 6. 使用状态与识别特征 | 打开/关闭、完整/破损、点亮/熄灭、装载/空置、归属及变化节点；刻字、图案、特殊结构等身份锚点写清位置 |
| 7. 棚拍光与画面纯净 | 均匀棚拍光、自然高光与淡阴影、轮廓和材质细节清楚；除已确认的道具原生刻字/图案外，无随机文字、水印、logo 和无关物体 |

### 结构、方向与状态硬规则

- 手机、屏幕、书本、镜子、武器、门、容器、杯把和可穿戴物等方向性道具，必须写清正反面、上下方向、观众可见面、持有/穿戴方式和接触点。
- 可开合道具必须写清部件数量、连接结构与开合机构，例如合页、销轴、卡扣、拉链、螺纹、磁吸或一体成型；禁止只写“有盖子”“可以打开”。
- 尺寸允许使用“约”，但必须给出整体尺度及关键部件比例。剧情中与手、身体、家具或其他道具接触时，再写相对尺寸参照。
- 三视图只展示同一道具的多个角度，不是三个道具。三角度必须保持同一尺寸、结构、材质、颜色、磨损和标志特征。
- 影响连续性的变化记录 `state_id`、生效场次与范围；详细分镜后再补片段映射。新结构或内容需要补图时，绑定对应 approved 主视图、状态图或多状态分区；同一 approved 图已覆盖的状态可以复用。可见面只是既有正反面切换、易主或移位时，另写方向与接触动作，不要求新图；未被任何图说明的新破损或内容不能只靠文字冒充已有视觉依据。
- 标志性文字或图案必须来自已确认剧情。记录准确内容、位置、方向和可见状态；未要求的随机文字、品牌和 logo 一律不得出现。模型无法稳定生成准确文字时，先生成无字结构底图，再用可控局部编辑添加并复验。

### 完整 Prompt 骨架

```text

【版式与一致性】[三视图：纯白或中性深灰背景，横向三等分排列，从左到右依次为正面、严格 90 度侧面、背面；三个角度等大对齐、居中、完整不裁切，保持同一尺寸、结构、材质、颜色、磨损和识别特征。/多状态图：纯白或中性深灰背景，按从左到右或从上到下分区展示同一道具的多个状态，每区只放该道具的一种状态，状态顺序与 state_timeline 一致，状态之间结构差异清楚可见。/主视图：纯白或中性深灰背景，选择最能说明结构的观察角度，道具居中，约占画面 60%，完整不裁切。/细节卡：只展示指定部件及其与主体的连接关系。]

【材质、纹理与颜色】[各部件材质、表面处理、光泽、纹理、主辅色及磨损老化状态]。
```

### 道具状态版本与下游绑定

例如同一个铁盒存在关闭、打开和破损状态：

```text
PROP001_state_sheet_v01
左区 STATE001：关闭、完整、内有文件、女主持有，用于 ep_1:E01S01 开盒前。
中区 STATE002：打开、文件可见、女主持有，用于 ep_1:E01S01 开盒后。
右区 STATE003：锁扣损坏、文件丢失、男主取得，用于 ep_1:E01S03。
```

同一道具各状态只改已确认变量。上例只生成当前集实际需要的状态，资产阶段按场次登记，分镜后再补镜号/SEG。采用多状态图时，视频 Prompt 引用生效 `state_id` 与具体分区，说明结构、方向和状态，不继承板式或棚拍光。`STATE002` 有新的可见内容而基准图未说明时，须传对应 approved 状态图/分区；只有归属等关系变化、现有图已足够时复用原图，另写动作与接触，不能把两种情况混为一谈。

### 道具图人工查看

设计时落实结构、比例、材质、方向与状态，并推演本场关键动作：与手掌/身体/台面的尺度是否相容，开合路径是否被装饰挡住，藏取和传递是否可行，辨认真伪或状态所依赖的差别在预期观察距离是否可读。反光、纹理或很小的刻字不能代替观众必须看清的证据。采用结果写入现有资产要求；不设独立验收，不声称案头推演已验证实际视频动作。

## text_to_audio_plus 专属音色

每个需要新生成人声的主体必须先有可用的已批准音色资产，两种模式均适用。先查项目内已有 approved VOICE；已有合格版本直接复用，没有时使用 `text_to_audio_plus` 准备，按原有音频生成授权和采用规则展示并取得适用采用依据，不把样音生成成功写成已批准。轻量模式把音色版本、真实来源和采用依据保存在已有规划、来源及操作记录，不增设完整模式资产阶段或配套文件。声音主体包括出镜角色、画外角色和无实体叙述者；同一主体跨段、跨集保留稳定名称、`VOICE ID`、同一适用的已批准音色版本和 `voice_anchor`，从首个有人声的片段起，每次新生成人声都必须实际传入对应 VOICE 并走 `media_to_video`，不允许仅用文字音色描述替代。音色样音只用于参考声线，不是完整配音：单条样音按 `5` 秒设计，只写 `1-2` 句短台词，不把长台词、整段剧情或多轮对话塞进音色工具。

已授权原片解说中保留的演员台词与原声属于来源媒体，沿原片、时间码和使用范围引用，不为这些保留声音重新建音色、克隆声线或要求视频模型重说台词。新增解说者或原创新画面确需新生成的声音才适用本节；不把没有真实可访问原片的文字描述当成已观看/已试听来源。此边界不授权替换原演员声音、另录正片配音或新增付费调用。

已有合格 approved VOICE 时直接复用。同一角色的对白、OS、VO默认共用同一声音身份，改变叙事职责、音量或情绪不另建一个声音主体；无实体叙述者则按已确认设定独立处理。

生成前先确定用途：目标包含视频且已有确认的视频模型时，读取实际 schema，核实它能否接收音色音频、将该音频作为对应主体的声线参考，并与本段必需图片及其他输入共同使用；仅能配乐、替换整条音轨或不能绑定主体，不算具备所需音色参考能力。尚未核验时如实记待核验，不凭工具名称或样音生成成功推断支持。缺少必需 VOICE、批准依据或音色参考能力时，暂停受影响的视频调用，说明缺口，按原有规则补齐音色或由用户选择可执行方案；不自动换模型、改为无声或后配，也不使用文字锚点降级。纯音色资产目标不为此强加视频生成前置。原生人声能力和模型变更仍执行 `video.md` 的原有确认边界。真实音色参考有助于保持声线，不承诺正片与样音完全相同，不安排生成后试听。

先依据人物当下关系与戏剧功能选择听感，再区分主体：可比较音区、共鸣、明暗、颗粒、咬字和句尾习惯，不把“反派=低哑、女性=轻软”当固定配方。人物年龄与身份不能只靠朗读自我介绍证明。短剧按具体交锋保证短句清楚、接话有弹性；微电影/短片按关系距离与视角选择声线亲疏，两者都不把快速、缓慢、哭腔等整段表演写死进稳定锚点。

样音优先选择剧本中能自然表现此人发声特征的 `1-2` 句短话；不适合五秒时可用相同身份与语言的试听短句，并标明仅用于选声、不会额外加入正片。样音台词与正片原句相同时，按正片已确认的发声窗口和表演正常生成；不能因为引用音色而额外播放样音或增添台词。保留自然语气与可辨咬字，避免全用尖叫、耳语或宣言掩盖基准声线。五秒不足以证明全部情绪范围，不为勾选“愤怒/哭泣/低语都通过”强制增加样音或伪报试听结果。

### 音色提示词

完整模式根据人物小传、叙述者设定、完整剧本和 `project_data_card.json`，轻量模式根据已采用规划与正文/十五列分镜，为每个确需新建 VOICE 的主体按 `drama_plan.json.language_contract.video_language` 编写音色提示词。使用自然创作语言，提交前替换全部占位符，至少包含：

- 角色身份与声音承担的戏剧功能。
- 性别表达和年龄感，但不得擅自添加用户未设定的敏感身份。
- 音高、音域、共鸣位置、音色明暗、厚薄、颗粒感和气息感。
- 稳定咬字与句尾发声特征，以及样音本次的语速、节奏、停顿和重音；说明这些样音表演安排不锁定正片每句读法，正片按逐句表演变化。
- 用户已指定的语言、方言或口音；用户未指定时保持自然中性，不擅自增加地域口音。
- 日常基准情绪、可覆盖的情绪范围，以及愤怒、哭泣、低语等极端状态下仍需保留的声音锚点。
- 表演要求和禁用表现，如禁止播音腔、机械感、过度夹音、夸张气声或情绪失控。
- 干净录音、近讲距离、稳定响度、无环境噪声、无混响、无背景音乐等质量要求。

推荐结构：

```text
为声音主体“[名称]”设计专属音色。该主体是[出镜角色/画外角色/无实体叙述者、身份、性别表达与年龄感]，在故事中承担[戏剧功能]，使用[语言/已确认口音]。声音整体为[音高、音域、共鸣、明暗、厚薄、颗粒和气息]，各项描述相容；稳定发声为[咬字与句尾习惯]。本次样音采用[语速、节奏、停顿与重音]，正片可按每句剧情改变这些表演安排，不能因此换声线。日常基准情绪为[情绪]，可自然覆盖[情绪范围]，即使在[极端状态]下仍保持[稳定声音锚点]。表演自然、生活化并符合主体设定；禁止[禁用表现]。录音干净、近讲、响度稳定，无环境噪声、无混响、无背景音乐。样音台词为[1-2句短台词]，总长约5秒；只用于选定和参考音色，样音音频不直接加入正片、不替代正片台词。
```

把完整提示词和 `1-2` 句、总长约 `5` 秒的样音台词传给 `text_to_audio_plus` 生成音色，并同时保存：

```text
shared/03_资产/音色/音色_VOICExxx_[声音主体名]_提示词_vNN.md
shared/03_资产/音色/音色_VOICExxx_[声音主体名]_vNN.[ext]
```

生成要求应明确主体与语言、同场声线辨识、自然咬字/气息/句尾及噪声/混响边界；身份声线与本句语速情绪分开。返回样音后保存展示供用户选择采用，不安排自动试听验收，不声称已验证跨段一致性。批准依据必须关联已展示的实际音色版本及用户真实采用答复；已有批准直接复用，轻量可在原有视频生成确认中明确列入已展示的音色版本并一并取得采用依据，不新增独立资产阶段或额外常规确认。仅预告“待生成音色”不能批准未来尚未展示的样音。建立固定引用：

```text
示例前提：林远的 VOICE001 已获批准，并作为本次真实音频输入<音频1>传入。第五层按主体声明一次固定 `voice_anchor` 作为补充描述；每句写明林远、声音类型、按照<音频1>的声线、完整原文和实际表演要求。出镜对白在嘴部可见的发声窗口驱动林远口型，旁白、画外音和内心独白不驱动画面人物口型。正片人声由视频模型原生生成，<音频1>仅参考声线，不额外播放或复述样音台词、不继承样音停顿。实际任务按当前真实输入顺序替换编号，未传音频不得套用本例。
```

同一角色保留同一适用的已批准音色版本和逐字一致的 `voice_anchor`。每个新生成该主体人声的片段，都将对应 VOICE 文件作为真实音色参考传入 `media_to_video`；文字描述、VOICE ID、上次调用记录或前段尾帧均不能替代音频输入，也不因此补传上一段视频或无关音频。多人发声时逐人绑定，不能共用一个未说明归属的参考；无该主体人声的片段不传其 VOICE。完整新生成台词写入视频 Prompt 的 `{spoken_text}`，不要用 5 秒音色样音替代正片台词。已授权原片中保留的声音不送入该新生成链路。只有剧情明确发生年龄、生理或身份伪装变化时才建立音色状态版本，并限定生效范围；对应版本同样须有批准依据并实际传入。

## 图片 Prompt 与参考图引用

按本次实际输入顺序动态编号，图片和主体标记跟随 `language_contract.video_language`；类别、名字和职责用项目语言写在自然描述中，不塞进标记本身。中文 Prompt 使用 `<图片1>`、`<主体1>`，英文 Prompt 使用 `<IMG1>`、`<SUBJ1>`：

```text
中文：<图片1> <图片2> <主体1> <主体2>
英文：<IMG1> <IMG2> <SUBJ1> <SUBJ2>
```

每个标签明确采用内容和不采用内容。多图任务逐张说明身份、保留项和编辑职责，不能仅用“同上、参考原图、其他不变”代替目标与边界。局部修订可以指明保持哪张 approved 图中的身份与未修改部分，不必逐项抄写无变化设计。

所有 `image_edit` 实际 Prompt 使用自然语言或字段化 PE。首句写统一画风；随后按真实顺序定位参考图，例如“参考图1采用脸型、眼距、发型和灰色外套，剥离背景、文字和手机界面；参考图2采用雨衣、湿发与左脸擦伤，剥离原站姿”。继续写完整目标、所需保留项、此次变化、适用构图与展示光、文字及限制。每张真实输入都说明作用，不笼统写“参考这些图”；一张图承担多个兼容维度时合并说明，不重复上传。

按资产类别取舍正文职责：角色写身份、造型、形体和变化部位；场景写空间、通道、陈设、光源及视角对应；道具写结构、尺度、机构与可见状态。基准资产不用剧情高潮表演，空场景不填人物微表情，道具不套手指/呼吸模板；局部修订写清改哪里和保留哪里，未改变的设计不再逐项复述。完整度来自足以执行本次请求的信息，不来自字段或段落数量。

引用道具多状态图时必须指到具体分区，而不是笼统引用整张图。中文使用 `<图片x-第y格>（状态）`，例如 `<图片3-第2格>（打开、文件露出）`；英文使用 `<IMGx-Celly>`。其中 x 是真实输入图片顺序，y 是该图分区顺序；同图不同分区不新增上传顺序。如果同一画面需要表现状态转换，按出现顺序写各分区及采用内容。

图片里需要出现文字时，必须在 Prompt 中说明文字载体、位置、可见程度和内容。短句、标题、牌匾、纸条、手机屏幕等需要精确生成的文字，用中文引号包住；长信件、档案、书页等不逐字展开时，要说明画面上有密集文字、文字大意和可读关键词，不能只写“信纸/文件/书页”导致空白纸或乱码。

下列为可选信息职责，按当前类别与变化范围组合，不要求每次全部出现或达到固定字数；角色/道具选定版式时可查上文对应骨架：

```text
全项目统一保持[统一画风词]。
参考输入：参考图1是……，采用……，不继承……；参考图2是……，采用……，不继承……。
生成目标：基于参考图1、参考图2，生成/修订……。
主体继承：……必须保持与参考图N一致的脸型、五官比例、发型、服装颜色、年龄感和识别标志。
场景继承：……必须保持与参考图N一致的空间结构、固定陈设、光源方向、材质和色彩关系。
变化要求：将……从……改为……，写清本次设计或状态变更的位置、范围及保留边界。
构图与镜头：……景别，镜头位于……，主体位于……，前景/中景/背景关系为……。
姿态或展示关系：……本次需要的中性站姿、结构展开或空间观察关系；无人物表演时不写情绪……。
光影与色彩：……主光、补光、逆光、色温、明暗关系和背景色阶为……。
风格与质感：保持本类资产适用的……画法、色阶、材质和光影关系。
画面文字：无文字；或说明文字载体、位置、可见程度和内容。
负面约束：禁止……。
```

`image_gen` 无图片输入时不写虚假参考说明，也不写“生成类型”；按对应类别把本次目标、设计、展示范围、光色、文字及限制写全。画幅比例只走工具参数；构图可描述“全身身份主视图”“横向布局全景”“关键接口局部”等视觉意图。

## 当前工具链中的资产使用

资产阶段对真实媒体、已确认设计、身份/状态、实际覆盖范围与可见合用条件负责，不能仅以存在且能打开判为合格。每个 SEG 具体传哪些图片，由 `storyboard.md` 规划、`video.md` 按真实工具 schema 执行；实际互动与成片质量不以案头设计或生成成功冒称已验证，生成后直接交付。当前必需的身份、状态、空间、结构与承接职责均须有真实图片输入覆盖；同职责候选按前文选足够且必要者，不因库中存在多个头部、设定板或状态文件而全部传入。下游不得只写资产 ID 或 Prompt 文字引用替代实际传图。

| 依据 | 资产阶段职责 | 下游职责 |
|---|---|---|
| CHR / CHR 状态 | 锁身份、体态、服装、妆发、伤痕、伪装和随身装具 | 当前 SEG 出场角色按 `video.md` 传入 |
| SCN | 锁空间拓扑、固定陈设、通道和基础光位 | 当前 SEG 场景按 `video.md` 传入 |
| PROP / PROP 状态 | 锁结构、尺寸、材质、方向、归属和状态 | 关键、复现或功能性道具按 `video.md` 传入 |
| 已有风格参考（可选） | 只采用用户参考中必要视觉维度，不生成新风格板 | 已由文字或 SCN 表达时不重复传图 |
| VOICE | 固定跨段声线和 `voice_anchor`，复用同一适用的已批准音色版本 | 新生成对应主体人声时必须作为真实音色参考传入 `media_to_video`；缺资源、批准或接口能力时暂停该调用，不用文字兜底 |

## 视频前置关系

完整模式进入分镜所用人物、场景、道具、音色和文字视觉合同须有有效采用依据：新增采用决定取得用户确认，原范围批准复用沿用真实批准来源；不为复用再收一次确认。轻量按目标与实际生成授权承接。这表示所选依据可用于制作，不等于已验证视频生成效果。视频生成与真实输入要求统一读取 `video.md`。

## 资产 JSON 登记

完整模式维护 `shared/03_资产/asset_registry.json` 和每集 `episodes/ep_N/03_资产/asset_usage_ep_N.json`，登记 schema 读取 `manifests.md`；轻量沿上述来源/实际操作记录承载，不建立这些完整模式文件。实际生成的图片、音色与完整提交 Prompt 按本次任务保存；既有数据卡记录设计事实，登记记录媒体版本/来源/使用范围，不能再建一套重复事实源。分类资产说明、风格说明或汇总 Markdown 默认不创建；按登记信息在对应媒体旁给用户说明即可。用户明确需要独立说明文件时从同一登记派生，不另维护设计副本。操作日志和原有交付记录照常保留。

- 共享基准资产只在 `asset_registry.json` 保存一条权威记录。
- 每个 `asset_usage_ep_N.json` 必须在顶层写入 `schema_version`、`episode_id`、`revision`、`project_data_card_revision`、`shared_assets` 和 `episode_assets`。本集使用的全部共享资产版本写入 `shared_assets`，不得写成 `shared_assets_used`；本集新增状态资产写入 `episode_assets`；复用其他分集已 approved 的非共享资产、状态资产、音色、场景或道具时写入 `reused_episode_assets` 并保留来源集数、来源文件和原版本。`shared_assets`、`episode_assets` 和出现时的 `reused_episode_assets` 都必须是数组。
- 资产查找不受当前集限制：后续片段或后续集再次出现同一人物、道具、状态、场景或声音主体时，先按 `project_data_card.json` 中的姓名、稳定 ID、别名、状态名和 `voice_anchor` 去共享库与所有分集 `asset_usage_ep_N.json` 查找 approved 版本。找到可用版本时复用并登记来源；不得因为该资产最初只在第二集出现、没有升为共享资产，就在第四集重新生成导致一致性漂移。
- 单条短片和微电影同样使用 `ep_1`。
- 每个分集专属资产和状态资产文件名必须以 `_ep_N` 结尾，且目录、JSON `episode_id` 和文件后缀一致。

## 资产版本管理

| 场景 | 规则 |
|---|---|
| 新建版本 | 任何已批准资产发生修改都创建 `_vNN` 新文件，不覆盖原文件 |
| 状态变化 | 连续性变化有状态记录；确需新增视觉依据时建媒体版本，已有依据足够则显式复用；资产阶段记场次，正式分镜后补镜号 |
| 差异记录 | 共享版本写入 `asset_registry.json`；当集状态写入 `asset_usage_ep_N.json`，先记录“旧版本 → 新版本、修改内容、原因、影响场次”，下游形成后再补影响镜头/片段 |
| 下游引用 | Prompt 编译、视频核对、原生人声核对及确认后的局部配音修复均记录实际使用的资产 ID 与版本 |
| 旧版处理 | 被替代版本标记 `superseded`，保留文件和记录 |
| 回滚 | 可恢复旧版为当前采用版本，但必须记录回滚原因、影响范围和新的 revision |

版本号只表示修订顺序，状态名表示剧情状态，两者不能混用。例如 `PROP001_v02_打开` 不得仅写成“铁盒新版”。

例如人物前半场日常服 `STATE001/v01`、后半场礼服 `STATE002/v02`，两者都可 approved，并分别用于生效场次；后者版本号更大不使日常服失效。若礼服袖型画错，修正为 `STATE002/v03` 后，把被替代的礼服 v02 标记 superseded，日常服 v01 继续有效。盒子关闭/打开、空间改造前后等采用同样语义。仅易主、移位且同一图片仍足够时，状态绑定沿用真实来源版本，不虚构新生成或复制媒体；共享来源已被废弃时，不能靠分集绑定写 approved 重新启用。

## 资产设计与采用

前述辨识、相对尺度、动作可行性、空间布局、结构、材质和声音要求直接落实到采用设计与 Prompt。返回后保存登记并展示；完整模式继续制作时确认新增采用决定，批准复用和纯资产交付按本文件开头的分支收口。不另跑资产阶段 lint、目视/试听质检或报告。

## 资产生成失败处理

本节只用于真实工具失败或用户主动指出问题后的诊断与修复方向，不主动检查生成结果；重试次数和升级条件统一读取 `troubleshooting.md`。

| 失败类型 | 诊断方法 | 当前处理策略 |
|---|---|---|
| 角色身份或头面漂移 | 对照同一 `CHRxxx` 三视图和头部身份锚点 | 强化固定特征、减少同时变化项、降低编辑范围 |
| 角色服装/装具错误 | 逐层对照款式、颜色、长度、穿戴关系和材质 | 只修改错误部位，其余身份与造型保持 |
| 动漫/动物被错误真人化 | 核对 `representation_type` 和风格合同 | 恢复画风/物种结构，删除不适用的人体与妆容词 |
| 道具结构、部件或状态错误 | 对照 PROP 结构、连接、方向和状态版本 | 局部问题用 `image_edit` 定向修正；系统性错误重做该版本 |
| `text_to_audio_plus` 音色生成失败或试听不合格 | 核对声音主体提示词、工具返回、音频文件和试听记录 | 调整音色提示词并只重生失败 VOICE；持续失败时报告能力限制 |
| 多角色比例或复制问题 | 检查是否把同一三视图误读成多人 | 留在资产阶段拆分身份参考、裁出单角色锚点或定向重生；不得返回尚未开始的分镜阶段 |
| 光影或色彩偏离 | 对照已确认风格机制和中性棚拍要求 | 修正光源、色温、主辅色和材质表现，不添加无依据风格图 |

每次失败和修复都写入操作日志，记录输入版本、问题证据、修改变量、输出版本和复验结论。

## 阶段交接

当前集实际需要的人物、场景、音色、道具、状态完成或完成复用登记且文字视觉合同确认后，进入当前集分镜阶段。后续调用必需尾帧的准备由 `video.md` 管理。资产设计与记录应包含：

- 当前集已确认剧本和项目数据卡列出的实际资产需求均有对应 approved 资源，没有遗漏、无依据新增或为未来集提前生成；分镜阶段再生成分类资产需求清单并补充镜头映射。
- 需新生成或复现画面的每个出场角色有可用 approved 身份与当前造型依据，所选主视图/三视图/必要细节足以覆盖本集实际需要，角色类型、结构、尺度、穿戴和区分点在设计中明确；复用的合格用户素材不要求再生设定板。仅剪用原片的人物按已核验来源及采用范围复用。状态按上文分别记录与补图，未来集状态只留计划。
- 每个计划新生成人声的主体（含无实体叙述者）都有可用的已批准音色版本和固定 `voice_anchor`；由视频 Prompt 原生生成人声，每次调用实际传入对应 VOICE 并走 `media_to_video`。文字锚点仅补充说明，缺少音色输入或接口能力时暂停受影响调用，不登记为文字降级后继续。保留的授权原片声音按真实来源与时间码复用，不另造演员 VOICE。
- 需新生成或复现画面的每个主要场景有 approved `SCNxxx` 布局依据、`3-5` 个锚点及实际需要的基础光/变化说明；视角相互一致，通道、遮挡、距离与台面能支持关键行动，不以四宫格数量代替具体空间依据。仅剪用原片的场景按已核验来源及采用范围复用。文字视觉合同继承项目事实，无独立风格板。
- 当前集已升级为 `PROPxxx` 的道具有清楚尺度、功能、结构、方向与状态依据，能配合人物和空间完成已定关键动作；所需正反差别、开合机构与内容可读。状态记录能解析到足够的 approved 图/分区或明确复用，易主、移位不单独造图。未来集状态只留计划，一次性物件不要求补 PROP。此时继承剧本与数据卡，后续分镜把连续性并入分镜 JSON 的 segments/seams。
- 所有资产均有类别、名称、介绍、详细描述、使用范围、路径和版本。
- 所有进入下游的资产状态均为 `approved`，资产 ID、版本、来源集数/来源场次和计划使用范围可追溯；详细分镜确认后再补实际镜头与片段，旧版本不得覆盖。跨集复用时使用原 approved 文件或等价转存副本，不改变身份、结构、音色或状态锚点。
- 资源按“人物、场景、道具、音色”完成当前环境交付并图文交叉展示，文字视觉合同就近说明；不另造风格媒体/说明文件。每张图片可渲染，音色可试听；Prompt 默认内部追溯，用户要求查看、排查或交接时才提供入口。

实际新增/变化资源保存展示后，完整模式还需继续下游制作时，将资产阶段及当前集状态写为 `awaiting_confirmation`，只确认本次新增采用决定；既有复用项说明沿用版本。若全部沿用同一适用范围内已批准的身份、造型、状态、用途和版本，在 asset_usage 的现有采用项保留批准记录来源与本次绑定，将 assets 记 merged 后进入分镜，不重复询问。缺批准依据、换版本或新增用途仍按新增决定处理。纯资产目标正常交付后结束，状态按控制合同记完成，不伪记用户已认可；不运行独立结构或媒体质量检查。

收到修改意见时只返修受影响资产并再次展示；存在新采用决定时取得明确认可再进入 `storyboard.md`，同范围已批准复用按上条承接。
