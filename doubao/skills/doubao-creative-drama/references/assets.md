# 资产阶段 Ref

本文件是资产生成和目视/试听验收的唯一权威。项目级故事包与 `current_episode` 的详细剧本分别确认后，逐集进入资产阶段；每次只生成并确认当前集实际需要的人物、主要场景、道具、音色、全局风格和必要状态资产。每项媒体必须生成一个、交付一个，非 Mobile 立即上画布并回读一个，完成后才生成下一个。当前集资产确认后才进入当前集分镜；当前集达到目标后，下一集从详细剧本开始。轻量模式未执行资产阶段时，本文件只在需要处理用户已有视觉参考或音色边界时补读。

## 本 Ref 关键要求

- 资产阶段只处理当前集实际需要的 CHR/SCN/PROP/VOICE/STYLE 和必要状态版本；开始生成前先查共享库与所有已完成分集资产，已有 approved 同一身份、场景、道具、音色、风格或完全相同状态时直接复用。只有当前集首次出现、项目内没有可用版本，或当前集发生需要稳定复现的状态变化时才生成；不得为尚未进入制作的后续集提前生成资产。当前集内会在后续片段复现或影响连续性的可见状态，必须在进入相关分镜前生成 approved 状态资产；不生成剧情关键帧或视频。
- 非轻量模式中，长时间出现、多次出现、跨片段承接、影响走位调度或承担剧情识别功能的场景必须生成 `SCNxxx` 场景资产，和人物、道具一起进入资产阶段确认。场景图不是可选氛围图，而是关键帧和视频的空间布局输入；缺失时不得进入依赖该场景的关键帧或视频。
- 人物状态和服装多样时，每个需要在关键帧或视频中稳定复现的角色状态都提前生成一张状态三视图，用来锁当前服装、伤痕、妆发、装具、伪装、年龄/生命阶段和其他仍需保持的可见状态。人物参考优先级固定为：用户上传、指定或认可的人物维度优先，同时参考上一个 approved 对应人物图；用户没有提供人物维度时，参考上一个 approved 对应人物图；首版没有任何可用人物维度时才走首版生成。人物图里的媒介、画风、色彩、光影和质感可同时作为风格维度，但不得因此继承原图无关身份、服装或背景。
- 所有图片资产共享同一套 `project_visual_mode` 和可观察风格词；生图/修图 Prompt 第一句必须先写统一画风，再写主体、参考图、结构和细节，不得在真人写实、漫画/动漫/插画/水彩/照片级等互不兼容模式之间漂移。
- 图片 Prompt 必须按完整 PE 密度书写，不能只写摘要；正文不写“生成类型：T2I/I2I/文生图/图生图”。无参考首版写生成目标、主体、场景、构图镜头、动作情绪、光影色彩、风格质感、画面文字和负面约束；有参考图时再逐张写采用内容、剥离内容、主体/场景继承和变化要求。
- 同一角色的基准图、状态三视图、头部锚点和修订图必须按角色归组展示，不能把不同角色或同一角色不同状态散落展示。每张图旁边用自然语言说明它依次是什么状态、从什么时候生效、用于哪些集/场次；资产阶段不要求面向用户写到具体镜头或 SEG。
- 同一道具存在开合、破损、点亮、沾染、内容物、归属或可见面变化时，优先在一张多状态图上分区展示该道具的多个状态；每个分区必须清楚区分状态顺序、状态名称、结构变化、内容物和使用时机。道具多状态图仍只表现同一个道具，不表现多个无关道具。
- `STYLE001` 全局 moodboard 只生成主色调、色彩关系、线条语言、光影、材质、构图、景深、颗粒和空间氛围等视觉参考信息，不得生成剧情人物、角色脸、具体服装、剧情道具或可误认为剧情物件的主体。
- 有当前目标需要的有效视觉参考维度就用 `image_edit`，没有才用 `image_gen`。人物、场景、道具、构图、姿态、色彩、光影、质感、媒介类型和画风锚点都可能构成视觉参考维度；纯文字指令、剧本/文档/表格截图和 OCR 图在逐张查看后若只提供文字内容，则只作文字来源，若同时提供当前目标相关视觉维度则仍按该维度处理。用户认可图优先，其次是 approved 资产、状态图、KF、FRM 和 moodboard；只传当前目标必要参考，逐张登记采用维度和剥离维度。基于既有角色、状态、场景、道具、风格、KF 或 FRM 继续生成时禁止纯文生图。当前目标命中有效视觉参考维度时，该参考图必须被实际打开查看并作为真实图片输入传给 `image_edit`；只把参考图写进 Prompt 文本、source_manifest 或 available_visual_reference_ids，但工具请求没有传入对应图片，按路由错误阻断。
- 每次生图或修图实际传给模型的完整 Prompt 原文必须保存到对应资产目录的 `提示词/` 下，不能保存简洁版、摘要版、压缩版或说明版，并在 `asset_registry.json` 或 `asset_usage_ep_N.json` 的 `generation.prompt_path` 中登记；Prompt 文件默认内部追溯，只有用户明确要求查看 Prompt、排查或交接时才紧邻对应图片或音频条目展示入口。
- 音色资产使用 `text_to_audio_plus` 生成；样音固定按 5 秒、1-2 句短台词设计，`voice_anchor` 写入数据卡并逐句复用，不检查或修复底层音频格式细节。
- 资产确认前不得进入分镜；下游只能引用 approved 版本，旧版保留不覆盖。

## 目标与输入条件

资产阶段只生产当前集下游实际会消费的基础媒体：人物身份/状态、主要场景、核心道具/状态、角色音色和项目尚未建立时的 `STYLE001` moodboard。SCN 锁空间基准，STYLE 锁色彩、光线、材质与构图语言，FRM 由 `video.md` 记录。非轻量模式里，当前集长时间、多次、跨片段、多人走位、影响轴线或承担剧情识别的场景必须建 `SCNxxx`；一次性、极短、纯抽象或已被用户首帧锁定的轻量场景可不单独生成，但不得冒充 approved SCN。后续集即使已在剧本中规划，也只能保留数据卡中的稳定 ID、状态时间线和需求预测，不得在当前集提前生成对应媒体资产。

任何资产生成、修订、返修或轻量模式复用用户图片前，先逐张打开查看本轮及项目内已登记的用户上传图片，并补全 `source_manifest.json` 的多维拆解。逐张盘点的单位是每个 URL、附件 ID 或输入实例，而不是文件名：多张图即使系统提示给出相同 `local path`、相同 `image.png` 或相同 basename，只要 URL、附件 ID、消息位置或输入顺序不同，都必须分别读取、转存为独立 `SRCxxx`、计算哈希并登记；不得只下载后几张、只看第一张、用同名文件覆盖前一张，或按展示名去重。逐张盘点只判断图片真实内容和可能职责，不等于全部传给生成工具；生成时仍按当前目标只选择足够且必要的相关图和相关维度。不得因为用户图片像文档截图、只含场景、只含风格、只含道具、只含构图、与当前类别不同，或用户没有说“参考”，就跳过查看和登记；同一张图可以同时登记为 `text_source` 与人物、状态、场景、道具、构图、媒介风格、色彩光影或质感参考。

参考图的使用遵循“三段式”：先拆维度，再定权重，最后写边界。拆维度时分别记录身份/状态、空间/道具、构图/姿态、媒介类型、画风、色彩、光影、材质/颗粒/纸感和文字信息；定权重时区分 `lock`、`weak`、`exclude`，只有清晰、稳定、与用户意图一致的维度可锁定；写边界时明确“采用什么、不采用什么、用到哪里”。参考图质量差、主体遮挡、压缩严重、有水印/界面、风格混杂或与 approved 资产冲突时，不得整体照搬：能可靠识别的维度可弱参考，身份、主风格或剧情关键结构冲突时先向用户确认取舍。

资产必须继承已确认剧本、数据卡和视觉风格合同。缺风格候选或视觉机制时才读取 `电影大师风格库.md`；该库只补光线、色彩、构图、材质和节奏机制，不覆盖角色身份、道具结构、状态或镜头职责。

全项目使用同一套渲染语言。剧情可改变时间、天气、磨损、情绪和场景状态，但不得拼贴互不兼容的风格。实际提交给 `image_gen` 或 `image_edit` 的 Prompt 第一写统一画风，例如“全项目统一保持[媒介/线条/上色/纸感/颗粒/色阶/材质/光影/构图/空间氛围]”；之后按完整 PE 写主体、场景、镜头、动作、光影、文字、负面约束。有参考图时逐张写采用/剥离边界；用户明确要求混合风格时，规划阶段先写清主风格、例外元素和可观察边界。若用户参考图之间风格不同，默认只选一个主视觉类型锁定项目，其他图只能按指定维度弱参考。

## 生图工具路由

| 输入条件 | 工具 | 规则 |
|---|---|---|
| 主动扫描后，当前目标没有任何有效视觉参考维度，从项目语言描述创建新图 | `image_gen` | T2I；不传入图片；文字图片、文档截图、剧本图、台词图和 OCR 来源只有在逐张查看后确认只含文字、没有当前目标相关视觉维度时，才不作为图片输入 |
| 当前目标存在需要视觉输入锁定的参考维度 | `image_edit` | I2I；控制外观、结构、构图、姿态、身份、场景、道具、材质、色彩、光影、媒介或风格等维度的用户图、必要检索图、截图、已批准资产、三视图、状态图、KF/FRM、人物或风格参考图都可作为输入图；用户未明确要求“参考”也必须自主判断并传入；按当前生成目标选择足够且必要的相关图片，按实际顺序登记图片 ID、采用维度、剥离维度和编辑范围；命中当前目标的必要参考维度却未真实传入图片、或仅用文字描述参考图，必须停止并修正工具请求，不得改用 `image_gen` |

参考图按“哪些维度能约束当前视觉结果”判断，不按来源判断，也不等用户说“参考”。生成或修订前先扫描已经逐张查看并登记的用户上传/指定/认可图、外部核验图、同资产旧 approved 版、相关 CHR/SCN/PROP/STYLE、状态图、KF、FRM 和 moodboard。用户图优先锁用户指定维度，已生成图锁项目连续性；两者职责不同且都相关时必须同时传入。只传当前目标必要参考，并登记来源、采用维度和剥离维度；“只传必要”只能用于排除与当前目标无关、质量不可用、被用户明确断开或被边界声明剥离的图片，不能用于省略当前目标需要锁定的身份、状态、空间、结构、道具、构图、姿态、媒介、画风、色彩、光影或材质参考。文字资料、剧本图、指令图、文档/表格截图和图中文字不算视觉参考，但仍必须逐张查看后登记为文字来源或无关图。若用户要求断开某参考，记录原文和原因；若用户图与 approved 资产冲突且无法兼容，先确认取舍。若工具请求无法传入已判定必要的参考图，停止生成并返回能力或输入问题，不能降级为纯文生图。

人物图和场景图单独作为强制门：生成或修订人物资产、人物状态、头部锚点、角色关键帧、角色返修图时，只要存在与目标相关的用户上传/指定/认可人物图、approved CHR、approved 角色状态图、头部锚点或同角色旧版，就必须调用 `image_edit` 并真实传入这些人物图；生成或修订场景资产、场景状态、场景关键帧、场景返修图时，只要存在与目标相关的用户上传/指定/认可场景图、approved SCN、approved 场景状态图或同场景旧版，就必须调用 `image_edit` 并真实传入这些场景图。不得只读不传、只登记不传、只在 Prompt 里文字描述“参考某图”，也不得把必须锁身份的人物图或必须锁空间的场景图裁掉后改用 `image_gen`。图片输入超限时先剥离无关弱参考，再拆分人物/场景生成；仍无法带入必须图时停止请求并说明阻断原因。

用户认可的任一清晰视觉参考图都可登记为 `style_anchor_reference`，作为后续人物、状态、场景、道具、关键帧和图片资产的画风锚点。锚点只锁媒介、线条、上色、纸感/颗粒、色阶、材质、光影和设定稿质感，不锁原图无关身份、脸、服装、姿态、剧情状态或场景布局；Prompt 第一句必须写出具体 `style_prompt_terms`，不能只写“参考风格”。例如用户只上传漫画场景图并要求做短剧时，该图至少锁定漫画/非真人媒介，人物首版可以没有人物身份参考，但必须继承同一漫画画风，不得生成真人。真人写实/照片级锚点要求人物、场景和道具都按真实材质、光影、透视和摄影逻辑；2D 漫画/动漫/插画/动态漫/水墨锚点要求人物、场景和道具保持同一非真人媒介。

`project_visual_mode` 由 STYLE001、风格锚点、用户指令或 approved 图片锁定。即使没有同类别参考，也要继承已有可观察画风词；例如用人物图给场景定媒介、线条、上色、质感、色阶和光影但不继承人物身份，也可以用漫画场景图给人物定漫画媒介、线条、上色、纸感和光影但不继承场景布局。后续人物、场景、道具、关键帧、视频输入图和视频 Prompt 都沿用同一画风；电影感只体现为构图、光线、节奏和调度，不等于真人化。风格反差只有用户明确要求并登记范围时才允许。若后续参考图质量更差或风格不一致，不能覆盖 `project_visual_mode`，只能作为弱参考或触发用户确认。

人物、场景、道具、moodboard 和首版基准资产按类别路由：当前类别没有身份、结构、空间或构图参考，但已有风格锚点时，先用锚点锁定 `project_visual_mode` 和 `style_prompt_terms`，再生成该类别首版；只要登记或使用 `style_anchor_reference`，就必须把锚点图作为风格输入用 `image_edit`，Prompt 必须剥离锚点中的无关主体、布局和剧情状态。人物类别一旦有人物图、同角色旧版或 approved CHR/状态图，人物图必须作为 `image_edit` 输入；场景类别一旦有场景图、同场景旧版或 approved SCN/状态图，场景图必须作为 `image_edit` 输入。当前类别有可直接约束外观/结构的参考时用 `image_edit`。基准资产确认后，同一素材的状态版、细节版、关键帧、修订图和视频输入图都传 approved 资产走 `image_edit`；人物状态图通常基于已批准角色基准图或上一状态图。只有角色首版且没有用户图、项目图、同角色旧版或风格锚点时才走无风格锚点的 `image_gen`。人物、场景、道具、风格和状态资产板统一以工具参数 `ratio: "16:9"` 生成；视频成片画幅继承 `planning.md`。

执行顺序：

1. 读取已确认项目级故事包、数据卡和 `current_episode` 的详细剧本，只列当前集实际出场的人物、主要场景、剧情功能道具、音色、风格及状态版本；先逐张打开查看并登记全部用户上传图片，再为当前集每个 CHR/SCN/PROP/STYLE 扫描可用视觉参考，并把命中的图片来源、资产版本、KF/FRM 或 moodboard 记入 `available_visual_reference_ids`。进入 `available_visual_reference_ids` 且被判定用于当前资产目标的图片，后续生成请求必须真实传入并按实际顺序登记；若决定不传，必须在采用/剥离边界中写明该图的所有视觉维度均与当前目标无关、质量不可用、冲突待确认或用户明确断开。未命中的用户图片也必须保留在 `source_manifest.json` 中并说明为何不进入当前资产生成。
2. 按稳定 ID、别名、状态名和 `voice_anchor` 查询 `asset_registry.json` 及所有已完成分集的 `asset_usage_ep_N.json`。找到 approved 可用版本时写入当前集 `shared_assets` 或 `reused_episode_assets`，不重新生成；项目尚无 `STYLE001` 时，在第一个实际需要视觉生成的分集建立并验收一套全局 moodboard。共享资产一旦 `approved` 不得被分集重画。
3. 只建立当前集会出现并需要稳定复现的新增角色、场景、道具、音色和状态版本，并回写数据卡：换装、妆发、伤痕、伪装、装具、年龄/生命阶段、道具开合、破损、点亮、沾染、内容物、可见面、归属和完整性等状态，只要当前集后续片段会看到或承接，就必须先有 approved 状态资产；只在未来集出现的变化保留为计划状态，不提前生成。角色状态按状态分别生成三视图；同一道具的多个当前集所需状态优先合并成一张多状态图。
4. 满足复现前提后，若道具推动剧情、被特写、被持有/传递/开合/损坏/调包/藏匿或承担证据/反转职责，必须先生成 approved 道具资产或状态资产，并为每个会被镜头复现的状态建立独立 `state_id`；多个 `state_id` 可以共用同一张已批准道具多状态图，但图中每个状态分区必须能被清楚指认。一次性物件不因这些动作单独升级为 PROP。
5. 保存、登记、展示并确认资产；每张资产图片生成并通过基础可打开检查后，立即按 `SKILL.md` 的交付前置路由完成当前环境交付并图文交叉展示给用户；非 Mobile 必须由主 Agent 同步写入 Canvas 并 CLI 回读成功，当前图片未交付上画布前不得继续生成下一张。每个场景条目必须在图片旁配文字介绍，说明场景名称、剧情功能、使用集/场次、四宫格分别展示的视角和 `3-5` 个一致性锚点。确认前不进入分镜，下游只可传入真实生成、可打开、已落盘且 approved 的资源。

每个图片资产版本必须同时保存 Prompt 文件：共享资产建议使用 `shared/03_资产/提示词/提示词_[资产ID]_[名称]_vNN.md`，分集资产建议使用 `episodes/ep_N/03_资产/提示词/提示词_[资产ID]_[名称]_vNN_ep_N.md`。Prompt 文件保存实际传给模型的完整提交文本，不保存摘要、压缩版、说明版或改写版；若一次调用生成多张候选图，也要能追溯每张 adopted 文件对应的完整 Prompt 原文。

生成图、参考图和下游输入图可使用当前工具支持的常见图片格式，例如 `.png|.jpg|.jpeg|.webp`；不需要为了通过 Skill 校验统一转成 PNG。打不开、未下载完成、云端占位、扩展名错误或零字节文件不得 approved；发现问题后重新下载、生成或转存并登记新版本。

用户展示按“人物 → 场景 → 道具 → 音色 → 风格”排序；风格必须展示 1 套全局 moodboard。人物按角色归组展示，同一角色的基准图、状态三视图、头部锚点和修订图放在一起；道具按单个道具归组展示，同一道具的多状态图放在该道具条目下。每个用户可见文件都要有入口或预览：图片按 `SKILL.md` 的交付前置路由完成当前环境交付并可渲染直显，非 Mobile 同步写入 Canvas 并回读成功，不得只给 URL 文本、附件链接、纯文件路径、工具自带预览或 HTML `<img>`；音频直接试听；Prompt 文件只在用户明确要求查看 Prompt、排查或交接时紧邻该条目展示。展示必须图文交叉，生成或准备好一个就展示一个；同一类型从 `1` 开始独立编号，例如角色 1-N、场景 1-N、道具 1-N、音色 1-N、风格 1-N。每张图旁边用自然语言说明它依次是什么状态、用于哪些集/场次、需要用户确认什么；不显示内部 ID、工具名、字段、任务号或检查统计；不得使用旧人工通知/展示工具替代。

## 分类目录与命名

完整目录和命名只读取 `manifests.md`。本阶段按当前集真实需求和资产使用范围存储：当前集首次需要且预计跨集稳定复用的 CHR/SCN/PROP/VOICE/STYLE 进入共享资产库；只在当前集首次出现或暂不适合升为共享的分集专属 CHR/SCN/PROP/VOICE、角色/道具状态资产进入对应 `episodes/ep_N/03_资产/`。后续其他集再次需要时通过 `shared_assets` 或 `reused_episode_assets` 引用原 approved 版本。不得因为全剧剧本已经完成，就提前生成未来集才首次出现的共享资产。重生成递增 `_vNN`，不得覆盖已确认版本。

- 换装、受伤、破损、场景布置或灯光变化先写入数据卡，再建立对应分集状态文件和 `asset_usage_ep_N.json`。

- 旧版标记 `superseded` 并保留；只有 `approved` 版本可用于下游。

## 场景参考与全局风格资产

每个跨集、反复出现、长时间停留、涉及多人走位/镜头轴线、承担证据或情绪空间功能的主要剧情场景，都必须建立一个 `SCNxxx` 场景布局参考图。它和人物、道具一样是基础资产，不是可省略的氛围图；关键帧和视频发生在该场景时必须传入对应 approved SCN。

每个 `SCNxxx` 默认生成一张四宫格场景图，四格属于同一个场景、同一设计和同一视觉风格，不是四个不同场景：

- 第 1 格：近景视角，展示最有识别力的固定陈设、材质、墙面/桌面/门窗细节和可被镜头反复核对的场景锚点。
- 第 2 格：远景视角，展示主要行动区域、入口出口、人物可站位区域、通道关系和前中后景层次。
- 第 3 格：平视全景视角，展示观众进入视频时最常用的空间识别角度、地面/墙面/大型家具关系和基础光位。
- 第 4 格：远景俯拍视角，展示完整空间布局、画面外环境结构、门窗朝向、动线、固定家具和场景边界。

若有用户上传、指定或已批准的场景参考图，必须使用 `image_edit` 并把该场景图作为真实图片输入传入工具请求，Prompt 采用以下核心句式并按项目语言扩展：

```text
全项目统一保持[已确认媒介、线条、上色、纸感/颗粒、色阶、材质、光影、构图和空间氛围]。基于这张场景参考图，生成一张同一场景的四宫格布局参考图。四格分别为近景视角、远景视角、平视全景视角、远景俯拍视角；远景俯拍视角需要展示完整空间布局，补出画面外的环境结构。保持原图场景风格、材质、色调、光影和空间氛围一致，必须保持原图风格、材质、色调、光影一致。只补全空间结构和可见陈设，不改变场景时代、建筑材质、主要家具位置、基础光源方向和整体氛围。
```

若没有任何有效场景参考图，才可用 `image_gen` 按剧本和风格合同生成首版四宫格 SCN；但仍必须继承项目 `project_visual_mode`、STYLE001 或风格锚点的媒介、线条、上色、材质、光影和空间氛围。`project_visual_mode` 为真人写实时，场景图必须像可信实景或摄影参考；`project_visual_mode` 为 2D 漫画/动漫/插画/动态漫/水墨时，场景图必须保持同一非真人画法。生成后同场景修订、状态变化、关键帧和视频输入图都必须基于 approved SCN 使用 `image_edit`，不得重新文生图。

场景四宫格采用清晰、可读、近似中性光的空间展示，必须看清：

- 户型或空间边界、门窗朝向、入口出口和主要通道。
- 固定家具、墙面、地面、台面和大型陈设的位置、比例与材质。
- 世界坐标、摄影机可用侧、180 度轴和主要人物活动区域。
- 基础光源位置、方向、色温；剧情灯光变化另记入数据卡状态时间线。
- 不包含具体剧情动作、临时人物表演、字幕、水印、无关文字或随机新增道具。

每个 `SCNxxx` 只选择 `3-5` 个最有识别力的 `consistency_anchors`。锚点必须同时写清对象、外观和固定位置，例如“门口右侧的绿色铁皮文件柜”“后墙中央停在 10:17 的圆形挂钟”；“老旧、压抑、有年代感”属于氛围形容词，不能作为锚点。锚点不是场景全部物件清单，也不得选择会在剧情中频繁移动的临时小物。

场景基准图只生产剧本实际需要的基础光照。阴天上午、停电应急灯、火灾警示灯等变化从已确认剧情反推，并写入 `project_data_card.json.scenes[].state_timeline`：

- 每个状态绑定生效集、场次、原因和可观察结果。
- 没有进入剧本的白天、黄昏、夜晚版本不预制。
- 临时开灯、停电或环境变化不改写 `consistency_anchors`；只有空间固定结构真的被改造或损毁时才创建新 SCN 版本。
- 关键帧、视频 Prompt 和生成后场景锚点帧都逐项核对这 `3-5` 个锚点，而不是笼统判断“看起来像同一个地方”。

场景布局参考命名为 `场景_SCNxxx_[场景名]_四宫格布局参考_vNN.[ext]`。若剧情明确改造空间、损毁固定结构或跨时代变化，建立新版本并记录生效范围；仅临时挪动物件或开关灯时不重画基准图，只更新状态时间线和对应 KF。场景图交付时必须按 `SKILL.md` 的交付前置路由把自然语言介绍和可渲染图片放在同一个场景条目中，介绍至少说明该场景的剧情功能、使用范围、四格视角、可继承内容和不继承内容。

完整模式每个项目生成一张 `STYLE001` 全局风格 moodboard；轻量模式不补造独立风格资产，只继承用户已有参考和已确认文字风格合同。moodboard 锁定主色调、色彩关系、线条语言、光线质感、材质表现、构图倾向、景深和颗粒机制，只画视觉语言参考，但不能抽象成任意项目都能用的通用色卡：它必须关联本项目的具体场景类型、冲突氛围和情绪基调，例如室内权力对峙、雨夜追踪、古宅秘密、病房告别等对应的空间气压和光影关系。画面可包含色卡、冷暖光对置示意、线条粗细与边缘处理、材质样本、空间氛围、构图网格、对称/留白/纵深示意、非叙事性的光影气氛片段；不得生成剧情人物、角色脸、具体服装、剧情道具、可误认为剧情物件的主体、未经授权品牌、字幕、水印或镜头分镜。它不决定角色身份、服装状态、道具结构、场景布局或具体镜头动作，也不把每个镜头细节画死。

风格定位必须从导演或作品感转译成可执行视觉机制。例如用户给出“大卫芬奇式冷冽精密 + 李安古风细腻”时，STYLE001 不画人物、服装或道具拼贴，也不只给孤立色卡，而锁定：与本戏主要场景和冲突氛围相连的冷冽低饱和基底、局部暖光与冷环境光对置、精密对称构图、克制细腻的古风材质、细腻肤色保护、层次化空间留白和安静压迫的纵深。核心机制如“冷暖光对置、精密对称构图”必须进入 moodboard 说明和后续视频风格约束；细节保持在视觉语言层，避免把角色造型、具体服装、道具结构或具体剧情镜头预画出来。

SCN 与 STYLE 都写入 `asset_registry.json` 并经过目视验收。后续每集只引用批准版本，禁止“这集重新画一个相似场景”或临时更换风格板。

## 角色资产

角色不限于真人，也可以是动漫人形、卡通人形、拟人动物、自然动物或其他剧情生物。生成前先依据 `drama_plan.json.type_strategy.format`、视觉风格合同和人物小传登记 `representation_type`：

```text
live_action_human | anime_human | cartoon_humanoid | anthropomorphic_animal | natural_animal | creature
```

不得把动漫、卡通或动物角色强行真人化，也不得把真人角色擅自改成动画形态。除非用户明确设定特殊风格反差，全项目所有角色默认使用同一 `project_visual_mode`，不得一个角色真人、另一个角色 2D 漫画或照片级混搭。主动扫描后没有对应角色的人物身份或状态维度时，才用 `image_gen` 创建首版角色设定图；存在对应角色的人物身份或状态维度，或基于已批准角色生成状态版、细节版、关键帧和修订图时，用 `image_edit` 生成或修订。只含媒介/画风的参考图不能替代人物身份图，但必须作为风格维度继承。画幅只通过工具参数 `ratio: "16:9"` 传入，不得把比例写进 Prompt：

- 纯白中性背景，棚拍均匀柔光，无环境色污染。
- 左侧 `1/3` 为超大高清正面头部特写：头部端正、正对镜头，不偏转、不低头、不抬头、不斜视，头面约占左侧区域 `80%`。
- 右侧 `2/3` 横向排列完整全身正面、严格 `90 度` 侧面、背面三视图；三个身体等大对齐，最高点与最低接地点基线一致，全部肢体、翼、尾、角、耳等完整入画。
- 特写与三视图必须是同一个角色；右侧正面头部与左侧特写在头面结构、颜色纹理和身份标志上完全一致，三个角度的体型、毛发/发型、服装/装具、配饰和识别特征一致。
- 基准角色资产必须使用**中性无表情**：面部或头部相关肌肉自然放松，眼睛自然睁开，嘴、喙或口部自然闭合；不微笑、不皱眉、不龇牙、不吐舌、不瞪眼，不表现愤怒、悲伤、惊讶、恐惧、轻蔑、挑逗或卖萌等情绪。正面特写、正面全身和侧面保持同一中性状态。
- 面部或头部必须符合已确认角色类型、物种和画风的正常结构。真人遵循可信人脸比例；动漫和卡通遵循已确认设计比例但不得出现非设计性的五官错位；动物遵循物种的眼睛、耳朵、口鼻/喙、牙齿和头骨结构，不得擅自长出人脸或额外器官。
- 不同角色必须有明显长相区分度。资产 Prompt 和登记必须写 `character_distinction_keys`，至少覆盖脸型/下颌、眼型/眉形、鼻梁/嘴唇、年龄感、发际线/发型轮廓、体态剪影、痣疤配饰或其他身份标志中的多项；除双胞胎、克隆或同一角色状态版外，不能共脸、共轮廓，也不能只靠服装颜色或发色区分。
- 妆容和表面修饰按类型处理：真人默认无妆或自然日常妆；动漫/卡通默认干净基础妆面或原始角色设计；动物默认无人体妆容，只描述毛色、羽色、鳞片、斑纹和必要装饰。特殊妆造、脸谱、战损或物种变形只有在用户或剧情明确要求时建立状态版本。
- 详细描述按下文 7 组结构组织，覆盖身份、身高或尺度、体态比例、面部、妆发、服装层级、服装可见结构、材质纹理、光影与纯净度，不机械堆叠零散标签。存在 `style_anchor_reference` 时，第一组必须写明采用的具体画风词和剥离边界。
- 三视图是资产设定板，不是多个角色。使用 `image_edit` 或 `media_to_video` 引用三视图时，必须声明：`该图展示同一角色的多个角度，输出中只出现一个该角色，不复制、不并列生成图中的多个角色。`
- 复杂多角色场景、近景对白或三视图曾引发复制角色时，从已批准角色资产中额外裁出一张无遮挡正面头部身份锚点，命名为 `角色_CHRxxx_[角色名]_头部身份锚点_vNN.[ext]`。头部图只锁角色类型、头面结构和身份特征，三视图只锁体态、毛发/发型、服装/装具和背侧特征，二者职责不得混写。

### 角色资产可见写法

人物资产 Prompt 写可复用的身份和造型，不写剧情高潮表演。每句都应包含可见限定，例如位置、数量、比例、轮廓、材质、纹理、光照、遮挡或裁切关系；同一信息不要在多个层级反复写。接近字数上限时优先保留角色类型、脸部区分点、体态剪影、发型或物种表面、服装装具、材质纹理和身份标志。

脸部区分点要写成可观察差异：脸型、下颌线、眼型、眉形、鼻梁、嘴唇厚薄、耳形、发际线、发型轮廓、年龄感、痣疤或配饰的位置。不要只写“漂亮、英气、高级、少年感强”；改写为眉峰角度、眼裂长度、鼻梁高度、下颌宽窄、嘴角形状、发束走向等可生成特征。不同角色的区分点不能只靠衣服颜色。

体态和肢体按角色类型写清：人形角色必须写身高或相对尺度、头身比、肩宽、腰线、四肢比例、手指数量、自然站姿和重心；动物或其他生物写体长/肩高或相对尺度，以及爪、蹄、翼、尾、角、耳、口鼻或喙的位置和数量。身体被遮挡或三视图中必须完整入画的部位要写清；不得用“高挑、清瘦、魁梧、娇小”这类抽象词替代可复现比例，也不得用“若干装饰、一些配件”等概括可数对象。

服装、装具和表面材质写可见结果，并必须能让后续 Prompt 复现同一套造型：内外层顺序、领口形制、肩线位置、衣长、袖长、袖口宽窄、腰封/腰带位置、垂落方向、裙摆/裤脚/鞋履、扣具或绑带数量、布料厚薄、纹理、反光/褶皱/磨损位置都要写清。颜色稳定时写具体色名；颜色受光影响时写明暗、冷暖和部位差异。没有剧情确认的文字、logo、品牌、花纹或符号不要加进人物资产；若身份标志必须含短文字，写清载体、位置和用中文引号包住的内容。

中性表情是基准资产要求，不是后续表演限制。状态资产仍保持身份和造型可复用，只修改已确认状态变量，例如换装、伤痕、发型、装具或年龄阶段；表情、视线、动作和与道具互动留给分镜、关键帧和视频 Prompt。角色状态资产原则上必须 `image_edit` 已批准角色基准图或上一状态图，继续继承同一脸、体态、服装体系和 `project_visual_mode`；不得把状态变化当作新角色重新 `image_gen`。

### 角色表现类型分支

| 类型 | 结构与比例 | 外观重点 | 不适用项 |
|---|---|---|---|
| 真人/写实人物 | 可信人体、头身比、五指和自然站姿 | 真实肤质、五官、发型、自然妆容、服装材质 | 不使用动物器官或卡通夸张比例 |
| 动漫人形 | 遵循已确认画风的头身比与线条设计，正侧背结构可互相推导 | 发束、瞳色、线稿、色块、服装轮廓和角色标志 | 不强制真人毛孔、真人骨相或写实摄影皮肤 |
| 卡通人形 | 保持设计稿的夸张比例、几何轮廓和简化肢体 | 轮廓、色块、材质表现方式和剪影识别度 | 不擅自写实化，不用真人比例修正风格化设计 |
| 拟人动物 | 先锁物种特征，再锁人形站姿、手/爪功能和服装结构 | 口鼻/喙、耳、角、尾、毛羽鳞纹理及拟人比例 | 不自动替换成人脸，不默认人体妆容 |
| 自然动物/其他生物 | 使用物种自然姿态和真实关节数量；四足、翼、尾等完整 | 品种、体型、毛羽鳞甲、斑纹、眼色、耳角尾和独特标记 | 不强制站立、五指、服装、发型或妆容 |

### 角色三视图 Prompt 的 7 组合同

Prompt 按以下顺序使用 `drama_plan.json.language_contract.video_language` 的自然描述。七组是信息组织方式，不要求每组机械写成独立标题，但关键内容不能遗漏。

| 组别 | 必填内容 |
|---|---|
| 1. 类型、风格与用途 | 明确 `representation_type`，继承 `drama_plan.json.style_contract` 的可观察风格机制，并说明该图用于锁定身份与造型；若使用已批准或用户认可的视觉图作为 `style_anchor_reference`，必须从锚点抽取并写出具体画风词，明确不继承锚点中的无关人物、场景、道具、姿态、布局和剧情状态；若该角色为漫画/动漫/插画/水墨风，必须声明全项目画面继续使用同一非真人画风 |
| 2. 版式与身份一致 | 纯白背景；左 `1/3` 正面头部特写，右 `2/3` 为正面、严格 90 度侧面、背面；等大对齐、基线一致、全部身体附属结构完整；四个展示属于同一角色 |
| 3. 体态与肢体 | 按角色类型写年龄/生命阶段、性别表达、身高或相对尺度、体型、头身比或物种比例、肩宽、腰线、四肢比例、自然姿态、重心和肢体结构；人形角色写手指数量和可见手部状态，动物检查爪、蹄、翼、尾及物种关节 |
| 4. 头面结构与中性表情 | 真人写正常人脸；动漫/卡通遵循既定设计；动物写物种正确的眼、耳、口鼻/喙和头骨；所有类型均为中性无表情；写清与其他角色明显不同的脸型、五官比例、眉眼、鼻梁、下颌、嘴唇、耳形或年龄感 |
| 5. 毛发、妆容与识别特征 | 人形写发型、发际线、发束走向及适用妆容；动物写毛、羽、鳞、斑纹方向；饰品、角、耳、尾、痣、疤痕等身份特征写清位置、数量、大小和是否被遮挡，没有则写“无” |
| 6. 服装、装具与材质 | 有服装/装具时写款式、内外层顺序、领口、肩线、衣长、袖长、腰封/腰带、裙摆/裤脚/鞋履、穿戴关系、可数部件、材质纹理和反光/褶皱/磨损；无服装的动物写身体表面材质与纹理，不强制补衣服 |
| 7. 棚拍光与画面纯净 | 均匀柔和棚拍光、淡而一致的阴影、清晰轮廓、无环境色污染；肤质/线稿/色块/毛羽鳞甲与材质符合既定风格；无文字、水印、logo 和无关物体 |

### 中性表情与正常头面结构合同

以下共通句必须进入每个基准三视图 Prompt：

```text
表情状态中性，无任何情绪表演：头面相关肌肉与结构自然放松，双眼自然睁开并直视前方，嘴、喙或口部自然闭合；不微笑、不皱眉、不龇牙、不吐舌、不瞪眼，不表现愤怒、悲伤、惊讶、恐惧、轻蔑、挑逗、卖萌或其他情绪。
```

再按角色类型追加且只追加一个结构分支：

```text
真人/写实人物：面部结构正常自然，五官比例可信，眼球、瞳孔、鼻、嘴唇、牙齿、耳朵和下颌无畸变，保留真实肤质，无塑料脸、蜡像脸或过度磨皮。
```

```text
动漫/卡通人形：头面结构符合已确认角色设计与画风，正面和侧面的五官位置可互相对应，无非设计性的错位、重复、缺失或左右漂移，不擅自真人化。
```

```text
拟人动物/自然动物/其他生物：头面结构符合已确认物种或生物设定，眼睛数量、瞳孔、耳朵、角、口鼻或喙、牙齿及头骨关系正确，无额外器官、错位、粘连或非设定的人脸化。
```

妆容或表面修饰也按类型选择：真人使用无妆或自然日常妆；动漫/卡通保持干净基础妆面或原始设计；动物默认无人体妆容，只描述毛色、羽色、鳞片、斑纹和已确认装饰。

### 角色三视图人工查看

生成后直接查看图片，确认人物身份、结构、服装和版式符合已确认设定。发现问题时修订对应资产，不要求填写固定报告模板。

## 角色身份与状态追踪

- **身份锁定**：脸型/头面、五官、肤色或物种表面、痣/疤痕等身份标志、身高体型和 `voice_id` 全剧稳定。
- **状态可变**：服装、发型、妆容、表情、伤痕和装具可随剧情变化，但必须先在 `project_data_card.json.characters[].state_timeline` 登记生效场次、原因和新状态。
- **片段内变化**：同一 SEG 内只有分镜明确安排换装、剪发、扎发、卸妆或变形镜头时才能发生；否则首尾状态必须一致。
- **跨片段变化**：若两个 SEG 状态不同，SEAM 必须记录时间跳跃、换装动作或其他剧情原因；没有原因即判定穿帮。
- **生成读取**：每个 KF 和视频生成参数确认记录数据卡 revision、出场角色 ID 与当前状态 ID，只补动作、表情和临时接触关系等片段增量。

资产阶段从本集采用的人物、主要场景和核心道具中选择代表资产，与共享 CHR/SCN/PROP/STYLE 基准并排检查。视频生成后的实际画面一致性由 `video.md` 复核；不得要求尚未生成的视频作为资产阶段输入。

## 道具资产

只为满足复现前提并推动剧情的道具生成设定图；单次出现或只在单个镜头内发生状态变化的物件不因“证据、手持、特写、开合、破损、染血、调包”等情节动作自动升级为 PROP。主动扫描后没有对应道具结构/状态维度时才使用 `image_gen` 创建首版道具图；存在对应道具或物件的结构/状态维度，或基于已批准道具生成状态版、细节版、关键帧和修订图时，使用 `image_edit`。只含媒介或画风的图不能替代道具结构参考，但必须继续锁定 `project_visual_mode`。道具图优先级固定为：**结构准确 > 使用状态准确 > 材质与颜色可信 > 风格表现**。不得用强光、景深或装饰遮盖结构错误。

道具资产清单从已确认剧情亮点、反转、证据链、身份关系和连续性需求反推；不是从场景装饰物穷举。道具必须先满足“多次出现、跨场景出现、跨片段承担连续性、状态会被后续片段复现，或用户明确要求单独生成道具设定图”这一复现前提，才考虑升级为 `PROP` 并生成视觉资产。只出现一次的证据物、手持物、特写物、开合/破损/染血物或调包物，默认写进场景、分镜、关键帧或视频 Prompt，不单独生成道具图。

满足复现前提后，任一道具再命中以下条件之一，就必须进入数据卡、生成视觉资产并在下游按状态引用：

- 推动剧情反转、改变局势、制造悬念或完成高潮兑现。
- 证明身份、关系、秘密、所有权、时间线或证据归属。
- 被角色持有、传递、争抢、穿戴、打开、损坏、修复、调包或藏匿。
- 会被特写、近景、局部细节卡或关键帧明确拍到。
- 有开合、破损、染血、发光、内容物、位置、归属、完整性等可观察状态变化，且该状态需要在后续片段中保持或回看。
- 和某个角色强绑定，成为其身份、职业、记忆或动机的标志物。

普通环境装饰和一次性剧情物件只写入场景、分镜、关键帧或视频 Prompt，不单独出图；删除后不影响剧情理解、镜头连续性或角色行动的物件，不升级为 PROP。若普通物件后来被剧本或分镜赋予复现/连续性职责，必须补入数据卡并回到资产阶段生成或确认对应资产。

每个进入数据卡的核心道具在生成前必须同时确定以下三层：

1. **尺度**：`scale_class` 使用 `handheld|tabletop|furniture_scale|custom`，并用 `scale_reference` 写出厘米尺寸，或它与成人手掌、身体、桌面、门框等稳定参照物的比例。只有“大小适中”“小巧”不能通过。
2. **剧情功能**：`narrative_functions` 逐项绑定真实集、场次和功能，例如制造悬念、证明身份、改变证据归属或完成高潮兑现。没有剧情功能、删除后不影响任何镜头的物件不进入核心 PROP。
3. **状态变体**：`state_timeline` 至少包含初始状态；每次开合、破损、修复、点亮、沾染、内容物变化或易主均建立新状态，写清生效范围、原因、变化字段和可观察结果。状态名不能只写“新版”。

示例：

```text
尺度：handheld；成人单手可握，约 9 厘米长。
剧情功能：ep_1:E01S01 制造父亲遗物悬念；ep_2:E02S03 通过调包改变证据归属。
STATE001：闭合、完整、内有文件、女主持有。
STATE002：打开、完整、文件可见、女主持有；由当众开箱触发。
STATE003：锁扣损坏、文件丢失、男主取得；由争抢和调包触发。
```

生成前登记 `prop_layout_mode`：

```text
key_multiview | state_sheet | standard_main | detail
```

- **关键道具 `key_multiview`**：满足复现前提且承担线索、反转、身份、传递、开合、破损或跨片段连续性时，生成正面、严格 90 度侧面、背面三视图；主动扫描当前道具可用视觉参考后选择 `image_gen` 或 `image_edit`，命中参考图时必须使用 `image_edit`，单独传 `ratio: "16:9"`。
- **道具多状态图 `state_sheet`**：同一道具存在开合、破损、点亮、沾染、内容物、归属或可见面变化时，优先生成一张多状态图；横向或网格分区展示同一个道具的各状态，并在画面说明或登记中写清从左到右、从上到下依次是什么状态、由什么剧情触发、用于哪些集/场次。多个状态可以共用同一张 approved 多状态图，但每个状态必须能被单独指认和下游引用；引用某个状态时写成 `<图x-第x个>（状态）`。
- **普通道具 `standard_main`**：只需识别外观和材质时，生成单张最能说明结构的主视图，道具居中、约占画面 `60%`、完整不裁切，单独传 `ratio: "16:9"`。
- **细节卡 `detail`**：内部结构、刻字、接口、发光部位、破损点、机关或材质细节在主图不可见但承担剧情作用时，另生成局部细节卡；不得把互斥状态或无关细节塞进主图。

画幅比例只进入工具参数，不写入 Prompt。关键道具、普通道具、状态图和细节卡全部使用 `16:9` 资产板，不生成 `1:1` 或其他比例版本。道具资产都使用纯白或中性深灰背景、均匀棚拍光；背景颜色根据轮廓和材质对比度选择，不得改变项目风格或材质颜色。

### 道具图 Prompt 的 7 组合同

Prompt 按以下七组使用 `drama_plan.json.language_contract.video_language` 的自然描述。七组是信息组织方式，不要求逐项机械堆标签：

| 组别 | 必填内容 |
|---|---|
| 1. 风格、模式与用途 | 继承已确认风格机制；写明 `prop_layout_mode`、道具类型、剧情用途和叙事意义 |
| 2. 版式与一致性 | 三视图写正面/严格 90 度侧面/背面、等大对齐、完整不裁切且三角度结构材质颜色一致；多状态图写分区顺序和每区状态；主视图写最佳观察角度、居中和约 `60%` 占比 |
| 3. 尺寸与整体结构 | 整体尺寸或相对尺度、长宽高比例、边角形态、主要组成部分、连接和开合方式 |
| 4. 部件与空间关系 | 每个关键部件的数量、形状、尺寸、位置、连接关系、朝向及当前状态 |
| 5. 材质、纹理与颜色 | 基础材质、表面处理、光泽度、纹理、主辅色、部位色差，以及与剧情一致的划痕、氧化、污渍或磨损 |
| 6. 使用状态与识别特征 | 打开/关闭、完整/破损、点亮/熄灭、装载/空置、归属及变化节点；刻字、图案、特殊结构等身份锚点写清位置 |
| 7. 棚拍光与画面纯净 | 均匀棚拍光、自然高光与淡阴影、轮廓和材质细节清楚；除已确认的道具原生刻字/图案外，无随机文字、水印、logo 和无关物体 |

### 结构、方向与状态硬规则

- 手机、屏幕、书本、镜子、武器、门、容器、杯把和可穿戴物等方向性道具，必须写清正反面、上下方向、观众可见面、持有/穿戴方式和接触点。
- 可开合道具必须写清部件数量、连接结构与开合机构，例如合页、销轴、卡扣、拉链、螺纹、磁吸或一体成型；禁止只写“有盖子”“可以打开”。
- 尺寸允许使用“约”，但必须给出整体尺度及关键部件比例。剧情中与手、身体、家具或其他道具接触时，再写相对尺寸参照。
- 三视图只展示同一道具的多个角度，不是三个道具。三角度必须保持同一尺寸、结构、材质、颜色、磨损和标志特征。
- 打开、关闭、破损、修复、沾染、点亮、熄灭、内容物变化、可见面变化或易主会影响连续性时，每种状态建立独立 `state_id`。资产阶段记录生效集数、场次和状态范围；详细分镜确认后可在内部补充视频片段映射。同一道具的互斥状态优先集中在一张多状态图中清楚分区展示，后续片段复现某个状态时，必须传入包含该状态分区的 approved 多状态图，并在 Prompt 中用 `<图x-第x个>（状态）` 点明采用哪一分区；不能只在 Prompt 文字中说明。
- 标志性文字或图案必须来自已确认剧情。记录准确内容、位置、方向和可见状态；未要求的随机文字、品牌和 logo 一律不得出现。模型无法稳定生成准确文字时，先生成无字结构底图，再用可控局部编辑添加并复验。

### 完整 Prompt 骨架

```text
【风格、模式与用途】[已确认的全局风格机制]，[关键道具三视图/普通道具主视图/局部细节卡]；[道具名称、类型、剧情用途和叙事意义]。

【版式与一致性】[三视图：纯白或中性深灰背景，横向三等分排列，从左到右依次为正面、严格 90 度侧面、背面；三个角度等大对齐、居中、完整不裁切，保持同一尺寸、结构、材质、颜色、磨损和识别特征。/多状态图：纯白或中性深灰背景，按从左到右或从上到下分区展示同一道具的多个状态，每区只放该道具的一种状态，状态顺序与 state_timeline 一致，状态之间结构差异清楚可见。/主视图：纯白或中性深灰背景，选择最能说明结构的观察角度，道具居中，约占画面 60%，完整不裁切。/细节卡：只展示指定部件及其与主体的连接关系。]

【尺寸与整体结构】[整体尺寸或相对尺度、长宽高比例、边角形态、主要组成部分、连接和开合方式]。

【部件与空间关系】[逐个写关键部件的数量、形状、位置、朝向、连接关系和当前状态]。

【材质、纹理与颜色】[各部件材质、表面处理、光泽、纹理、主辅色及磨损老化状态]。

【使用状态与识别特征】[当前状态及其可见证据；多状态图要逐区写清 STATE001、STATE002、STATE003 各自的开合、破损、点亮、内容物、归属、可见面和剧情触发]；[剧情确认的刻字、图案、特殊结构或内容物的位置和状态，无则明确写无]。

【棚拍光与画面纯净】均匀棚拍光，阴影淡且方向一致，轮廓边缘清楚；金属、玻璃、塑料等反光材质保留与材质相符的自然高光带，所有纹理与使用痕迹清晰可见。除已确认的道具原生刻字或图案外，无随机文字、水印、logo 或无关物体。
```

工具调用参数单独设置：

```json
{"ratio": "16:9"}
```

关键道具三视图、道具多状态图、普通道具主视图和细节卡全部使用上面的 `16:9`，不再为普通道具切换为 `1:1`。

### 道具状态版本与下游绑定

例如同一个铁盒存在关闭、打开和破损状态：

```text
PROP001_state_sheet_v01
左区 STATE001：关闭、完整、内有文件、女主持有，用于 ep_1:E01S01-SEG001。
中区 STATE002：打开、文件可见、女主持有，用于 ep_1:E01S01-SEG002。
右区 STATE003：锁扣损坏、文件丢失、男主取得，用于 ep_2:E02S03-SEG004。
```

同一道具的各状态保持尺寸、基础结构、材质、颜色和身份标志不变，只修改已确认的状态变量。视频 Prompt 必须引用当前镜号生效的 `state_id`，并明确采用多状态图中的对应分区、结构、方向、材质和状态，不采用设定图背景、排版或棚拍光。分镜、关键帧和视频段不得跳过状态资产：当前镜头或 SEG 需要 `STATE002`，就必须传入包含 `STATE002` 的 approved 多状态图，并用 `<图x-第x个>（STATE002 状态名）` 点明采用具体分区，不能用 `STATE001` 加文字要求模型自行变化。

### 道具图人工查看

生成后直接查看图片，确认结构、比例、材质、方向和状态符合已确认设定。发现问题时修订对应资产，不要求填写固定报告模板。

## text_to_audio_plus 专属音色

每个计划人声主体必须使用当前已有的 `text_to_audio_plus` 生成一个专属音色资产。音色样音只用于锁定**声线**，不是完整配音：单条样音按 `5` 秒设计，只写 `1-2` 句短台词，不把长台词、整段剧情或多轮对话塞进音色工具。声音主体包括出镜角色、画外角色和无实体叙述者；同一主体跨段使用稳定名称、`VOICE ID` 和 `voice_anchor`。视频阶段有人声时始终逐字复用固定 `voice_anchor`；实际视频接口支持音频输入时，再把已批准 VOICE 音频作为 `media_to_video` 输入。

### 音色提示词

先根据人物小传、叙述者设定、完整剧本和 `project_data_card.json`，为每个声音主体按 `drama_plan.json.language_contract.video_language` 编写音色提示词，至少包含：

- 角色身份与声音承担的戏剧功能。
- 性别表达和年龄感，但不得擅自添加用户未设定的敏感身份。
- 音高、音域、共鸣位置、音色明暗、厚薄、颗粒感和气息感。
- 语速、节奏、停连、重音、咬字清晰度和句尾习惯。
- 用户已指定的语言、方言或口音；用户未指定时保持自然中性，不擅自增加地域口音。
- 日常基准情绪、可覆盖的情绪范围，以及愤怒、哭泣、低语等极端状态下仍需保留的声音锚点。
- 表演要求和禁用表现，如禁止播音腔、机械感、过度夹音、夸张气声或情绪失控。
- 干净录音、近讲距离、稳定响度、无环境噪声、无混响、无背景音乐等质量要求。

推荐结构：

```text
为声音主体“[名称]”设计专属音色。该主体是[出镜角色/画外角色/无实体叙述者及身份与年龄感]，在故事中承担[戏剧功能]。声音整体为[音高、音域、共鸣、明暗、厚薄、颗粒和气息]；说话时[语速、节奏、停顿、重音、咬字和句尾习惯]；使用[语言/已确认口音]。日常基准情绪为[情绪]，可自然覆盖[情绪范围]，即使在[极端状态]下仍保持[稳定声音锚点]。表演自然、生活化并符合主体设定；禁止[禁用表现]。录音干净、近讲、响度稳定，无环境噪声、无混响、无背景音乐。
```

把完整提示词和 `1-2` 句、总长约 `5` 秒的样音台词传给 `text_to_audio_plus` 生成音色，并同时保存：

```text
shared/03_资产/音色/音色_VOICExxx_[声音主体名]_提示词_vNN.md
shared/03_资产/音色/音色_VOICExxx_[声音主体名]_vNN.[ext]
```

生成后试听检查角色匹配度、清晰度、语速、情绪范围、噪声和稳定性。通过后建立固定引用：

```text
VOICE001“林远”的 `voice_anchor` 在每段相关台词前逐字复用；出镜对白、旁白、画外音和内心独白均由视频 Prompt 原生生成；实际视频接口支持音频输入时传入该已批准音色文件，不支持时使用同一 `voice_anchor` 作为文字音色锚点。
```

同一角色保留同一已确认音色版本和逐字一致的 `voice_anchor`。全部计划人声由视频模型原生生成；实际视频接口支持音频输入时，把对应已批准 VOICE 文件传入 `media_to_video`，不支持时按真实图片输入选择 `text_to_video` 或 `image_to_video` 并逐字写入同一 `voice_anchor`。完整对白写入视频 Prompt 的 `{spoken_text}`，不要用 5 秒音色样音替代正片台词。只有剧情明确发生年龄、生理或身份伪装变化时才建立音色状态版本，并限定生效范围。

## 图片 Prompt 与参考图引用

按本次实际输入顺序动态编号，图片和主体标记跟随 `language_contract.video_language`；类别、名字和职责用项目语言写在自然描述中，不塞进标记本身。中文 Prompt 使用 `<图片1>`、`<主体1>`，英文 Prompt 使用 `<IMG1>`、`<SUBJ1>`：

```text
中文：<图片1> <图片2> <主体1> <主体2>
英文：<IMG1> <IMG2> <SUBJ1> <SUBJ2>
```

每个标签明确采用内容和不采用内容。多图任务逐张说明身份、保留项和编辑职责，不得使用“同上、参考原图、其他不变”。

所有 `image_edit` 的实际提交 Prompt 必须使用自然语言或字段化 PE。Prompt 第一句先写项目统一画风与可观察风格词；第二句开始按真实传入顺序逐张定位参考图，例如“参考输入：参考图1是用户上传的母亲半身照，采用脸型、眼距、发型轮廓和灰色外套，不继承背景、文字和手机界面；参考图2是已批准 CHR001 雨夜状态图，采用雨衣、湿发和左脸擦伤位置，不继承原始站姿”。随后必须继续写完整生成目标、主体继承、场景继承、变化要求、构图与镜头、动作与情绪、光影与色彩、风格与质感、画面文字和负面约束。多张图中只要包含同一人物、道具、场景、服装、状态或风格线索，就必须逐张说明作用，不能只写最近一张或笼统写“参考这些图”。

引用道具多状态图时必须指到具体分区，而不是笼统引用整张图。写法为 `<图x-第x个>（状态）`，例如 `<图3-第2个>（打开、文件露出）`；如果同一画面需要表现状态转换，按出现顺序分别写出每个分区及采用内容。

图片里需要出现文字时，必须在 Prompt 中说明文字载体、位置、可见程度和内容。短句、标题、牌匾、纸条、手机屏幕等需要精确生成的文字，用中文引号包住；长信件、档案、书页等不逐字展开时，要说明画面上有密集文字、文字大意和可读关键词，不能只写“信纸/文件/书页”导致空白纸或乱码。

建议写法，实际内容必须保持这种信息密度：

```text
全项目统一保持[统一画风词]。
参考输入：参考图1是……，采用……，不继承……；参考图2是……，采用……，不继承……。
生成目标：基于参考图1、参考图2，生成/修订……。
主体继承：……必须保持与参考图N一致的脸型、五官比例、发型、服装颜色、年龄感和识别标志。
场景继承：……必须保持与参考图N一致的空间结构、固定陈设、光源方向、材质和色彩关系。
变化要求：将……从……改为……，动作、姿态、道具接触和情绪变化为……。
构图与镜头：……景别，镜头位于……，主体位于……，前景/中景/背景关系为……。
动作与情绪：……手指、肩颈、眼神、嘴唇、呼吸、身体重心和道具接触具体表现为……。
光影与色彩：……主光、补光、逆光、色温、明暗关系和背景色阶为……。
风格与质感：保持……画风、纸感/颗粒、线条、材质、电影级光影层次和稳定五官。
画面文字：无文字；或说明文字载体、位置、可见程度和内容。
负面约束：禁止……。
```

`image_gen` 首版基准资产没有图片输入时不写虚假的参考图说明，也不写“生成类型”；但仍要用同等详细度写完整 PE：统一画风、生成目标、主体设定、场景设定、构图与镜头、动作与情绪、光影与色彩、风格与质感、画面文字和负面约束。画幅和比例只走工具参数，不写进图片 Prompt；如果需要指导构图，可以写“竖版人物设定图”“横向全景构图”“中近景”等视觉意图。

## 当前工具链中的资产使用

资产阶段只保证 approved 资源真实存在、可打开、可复用；每个 SEG 具体传哪些图片，由 `storyboard.md` 规划、`keyframes.md` 生成 KF、`video.md` 按真实工具 schema 执行。凡人物资产、人物状态、头部锚点、场景资产、场景状态、关键帧、视频输入图或返修图被后续 SEG 命中，都必须继续作为真实图片输入传入视频工具；下游不得只写资产 ID 或 Prompt 文字引用来替代传图。

| 依据 | 资产阶段职责 | 下游职责 |
|---|---|---|
| CHR / CHR 状态 | 锁身份、体态、服装、妆发、伤痕、伪装和随身装具 | 当前 SEG 出场角色按 `video.md` 传入 |
| SCN | 锁空间拓扑、固定陈设、通道和基础光位 | 当前 SEG 场景按 `video.md` 传入 |
| PROP / PROP 状态 | 锁结构、尺寸、材质、方向、归属和状态 | 关键、复现或功能性道具按 `video.md` 传入 |
| STYLE001 | 锁全项目主色调、色彩关系、线条、光线、材质、构图、景深、颗粒和空间氛围；不得生成剧情人物、角色脸、具体服装或剧情道具 | 若未由 KF/SCN 承载，按 `video.md` 传入，只采用视觉语言 |
| VOICE | 固定跨段声线和 `voice_anchor` | 按 `video.md` 读取实际 schema；支持音频输入时传入 `media_to_video`，不支持时使用文字锚点 |

## 关键帧前置关系

资产阶段不生成剧情关键帧。关键帧的数量、职责、Prompt、登记、验收和确认统一读取 `keyframes.md`；本阶段只保证人物、场景、道具、音色和风格资产已批准，可供分镜与关键帧阶段使用。

## 资产 JSON 登记

维护 `shared/03_资产/asset_registry.json` 和每集 `episodes/ep_N/03_资产/asset_usage_ep_N.json`，完整 schema 读取 `manifests.md`。可为人工审阅生成资产摘要 Markdown，但不得把它作为机器权威。

- 共享基准资产只在 `asset_registry.json` 保存一条权威记录。
- 每个 `asset_usage_ep_N.json` 必须在顶层写入 `schema_version`、`episode_id`、`revision`、`project_data_card_revision`、`shared_assets` 和 `episode_assets`。本集使用的全部共享资产版本写入 `shared_assets`，不得写成 `shared_assets_used`；本集新增状态资产写入 `episode_assets`；复用其他分集已 approved 的非共享资产、状态资产、音色、场景或道具时写入 `reused_episode_assets` 并保留来源集数、来源文件和原版本。`shared_assets`、`episode_assets` 和出现时的 `reused_episode_assets` 都必须是数组。
- 资产查找不受当前集限制：后续片段或后续集再次出现同一人物、道具、状态、场景或声音主体时，先按 `project_data_card.json` 中的姓名、稳定 ID、别名、状态名和 `voice_anchor` 去共享库与所有分集 `asset_usage_ep_N.json` 查找 approved 版本。找到可用版本时复用并登记来源；不得因为该资产最初只在第二集出现、没有升为共享资产，就在第四集重新生成导致一致性漂移。
- 单条短片和微电影同样使用 `ep_1`。
- 每个分集专属资产和状态资产文件名必须以 `_ep_N` 结尾，且目录、JSON `episode_id` 和文件后缀一致。

## 资产版本管理

| 场景 | 规则 |
|---|---|
| 新建版本 | 任何已批准资产发生修改都创建 `_vNN` 新文件，不覆盖原文件 |
| 状态变化 | 换装、伤痕、装具、开合、破损、点亮等建立明确状态版本；资产阶段记录生效集数和场次，分镜确认后补镜号 |
| 差异记录 | 共享版本写入 `asset_registry.json`；当集状态写入 `asset_usage_ep_N.json`，先记录“旧版本 → 新版本、修改内容、原因、影响场次”，下游形成后再补影响镜头/片段 |
| 下游引用 | Prompt 编译、视频核对、原生人声核对及确认后的局部配音修复均记录实际使用的资产 ID 与版本 |
| 旧版处理 | 被替代版本标记 `superseded`，保留文件和记录 |
| 回滚 | 可恢复旧版为当前采用版本，但必须记录回滚原因、影响范围和新的 revision |

版本号只表示修订顺序，状态名表示剧情状态，两者不能混用。例如 `PROP001_v02_打开` 不得仅写成“铁盒新版”。

## 资产人工验收

资产质量由实际看图和试听判断。代码只检查文件、编号、版本、引用、媒体类型、图片工具路由证据和 STYLE001 基础登记；当登记了可用视觉参考却使用 `image_gen`，`image_edit` 没有登记实际参考来源，或 STYLE001 缺少场景/冲突氛围关联与视觉语言字段时会阻断。不判断审美、表演或风格质量，也不要求固定质量报告。

## 资产生成失败处理

本节只定义资产问题的诊断与修复方向；重试次数和升级条件统一读取 `troubleshooting.md`。

| 失败类型 | 诊断方法 | 当前处理策略 |
|---|---|---|
| 角色身份或头面漂移 | 对照同一 `CHRxxx` 三视图和头部身份锚点 | 强化固定特征、减少同时变化项、降低编辑范围 |
| 角色服装/装具错误 | 逐层对照款式、颜色、长度、穿戴关系和材质 | 只修改错误部位，其余身份与造型保持 |
| 动漫/动物被错误真人化 | 核对 `representation_type` 和风格合同 | 恢复画风/物种结构，删除不适用的人体与妆容词 |
| 道具结构、部件或状态错误 | 对照 PROP 结构、连接、方向和状态版本 | 局部问题用 `image_edit` 定向修正；系统性错误重做该版本 |
| `text_to_audio_plus` 音色生成失败或试听不合格 | 核对声音主体提示词、工具返回、音频文件和试听记录 | 调整音色提示词并只重生失败 VOICE；持续失败时报告能力限制 |
| 多角色比例或复制问题 | 检查是否把同一三视图误读成多人 | 留在资产阶段拆分身份参考、裁出单角色锚点或定向重生；不得返回尚未开始的分镜阶段 |
| 光影或色彩偏离 | 对照已确认风格机制和中性棚拍要求 | 修正光源、色温、主辅色和材质表现，不添加无依据风格图 |

每次失败和修复都写入操作日志，记录输入版本、问题证据、修改变量、输出版本和复验结论。

## 阶段交接

当前集实际需要的人物、场景、音色、道具、状态和全局风格完成或完成复用登记后，进入当前集分镜阶段。视频生成后的实际 FRM 抽帧由 `video.md` 管理。当前集资产完成后检查：

- 当前集已确认剧本和项目数据卡列出的实际资产需求均有对应 approved 资源，没有遗漏、无依据新增或为未来集提前生成；分镜阶段再生成分类资产需求清单并补充镜头映射。
- 每个当前集出场角色有按生图路由使用 `image_gen` 或 `image_edit` 生成并通过目视验收的三视图设定图：角色类型正确、版式完整、身份一致、中性无表情、身高或尺度、体态比例、头面与肢体符合既定真人/动漫/卡通/动物结构，服装层级、领口、袖口、腰带、裙摆/裤脚/鞋履、材质纹理和可见识别细节清楚可复现，妆容或表面修饰适配类型；只有当前集后续片段会出现或承接的服装、妆发、伤痕、伪装、装具、年龄/生命阶段等状态需要对应 approved 版本。未来集状态只保留在数据卡计划中，等该集成为 `current_episode` 后再生成。
- 每个计划人声主体（含无实体叙述者）都有唯一音色资产和固定 `voice_anchor`；由视频 Prompt 原生生成人声并逐句复用该锚点，实际视频接口支持音频输入时必须传入已批准 VOICE，不支持时登记音频输入降级并只使用同一文字锚点。
- 每个主要场景有唯一已批准 `SCNxxx` 四宫格布局参考、`3-5` 个可逐帧核对的一致性锚点和剧情实际使用的基础光/变化状态；每个项目有唯一已批准 `STYLE001` moodboard，且只包含视觉语言参考，不含剧情人物、角色脸、具体服装、核心道具或剧情道具，已展示给用户确认，并与项目数据卡一致。
- 每个当前集已升级为 `PROPxxx` 的关键/复现道具，其尺度类别与参照、逐场剧情功能、结构、材质、方向和状态版本与剧本及连续性账本一致；当前集后续片段会复现的开合、破损、点亮、沾染、内容物、归属和可见面状态均有对应 approved 版本，关键道具三视图和必要细节卡已通过验收。未来集状态只登记计划，一次性物件不要求补 PROP 资产。
- 所有资产均有类别、名称、介绍、详细描述、使用范围、路径和版本。
- 所有进入下游的资产状态均为 `approved`，资产 ID、版本、来源集数/来源场次和计划使用范围可追溯；详细分镜确认后再补实际镜头与片段，旧版本不得覆盖。跨集复用时使用原 approved 文件或等价转存副本，不改变身份、结构、音色或状态锚点。
- 资源已保存并按“人物、场景、道具、音色、风格”顺序完成当前环境交付并向用户图文交叉展示；每张图片均已可渲染直显。Prompt 文件默认只作内部追溯，只有用户明确要求查看 Prompt、排查或交接时才贴近对应条目展示。

将资产阶段及 `current_episode` 状态写为 `awaiting_confirmation`，运行内部结构检查；存在问题时先修复，图片和音频必须实际看图、试听，不单独输出阶段报告。通过后展示当前集全部采用资产，其中复用项说明沿用已有版本，新增或变化项提供对应媒体；并按 `language_contract.output_language` 使用不固定但语义完整的确认句：请用户确认当前集人物、场景、道具、音色和风格是否需要修改；需要修改则直接指出；确认无误则用明确肯定回复；收到确认后才开始当前集分镜阶段。确认句要礼貌清晰，避免每阶段重复同一句模板。

收到修改意见时只返修受影响资产并再次展示；只有用户明确确认后才进入 `storyboard.md`。
