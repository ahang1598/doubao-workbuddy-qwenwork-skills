# 视频执行分工与多轮消息处理

## 职责、授权与回传

mainagent 负责规划、剧本与分镜、完整 Prompt、工具和参数选择、必要澄清、用户确认、状态记录及结果交付。视频生成、生成式编辑，以及视频任务所需的抽帧、探测、裁剪、拼接、混音、封装和字幕/水印处理，均由 subagent 实际调用相应正式工具；mainagent 禁止直接调用这些视频制作/处理工具，不因单条视频、任务简单、已取得授权或委派失败而代执行。图片与音色资产生成沿用既有分工和授权。subagent 逐项回传，mainagent 逐项交付；取消结果、失败和阻塞也由 mainagent 根据真实回传对用户说明。subagent 不直接向用户发卡、说明失败或发起询问，不自行改变方案、重试生成或再次委派。

生成及生成式编辑必须先按 `interaction-ask-video-clarification-ref.md` 由 mainagent 实际调用 `interaction.ask` 取得本批生成授权；普通聊天同意、选择方向或认可剧本均不能替代。项目执行确认不能替代当批生成确认。普通反馈可自然交流，必要澄清按该 Ref 执行。

生成确认前，mainagent 先按当前成片的实际范围规划完整内容、分镜及分段关系，再完成本批每项任务的工具、参数、全部台词、完整 Prompt 和执行安排。实际输入已具备的任务写定可提交的 Prompt 与请求；依赖前段真实结果的后段，也须提前写好完整 Prompt 模板、镜头内容、接续要求及所需输入职责，只保留真实素材引用和必要编号待绑定，不把“等待尾帧”当成延后创作的理由。模板不能包含伪造的尾帧 ID、路径或已取得素材声明，也不能作为真实请求提交。确认前用户提出修改时，仅更新实际受影响的方案、分镜、Prompt 与依赖，按原展示规则取得当前版本的生成授权，不新增独立 Prompt 确认。

实际 `interaction.ask` 返回用户对当前批次明确选择“按要求生成”后，mainagent 保存真实授权，并必须在处理该确认结果的当前轮次，通过宿主实际提供的创建子代理/派发任务工具委派所有已就绪任务，不能只发送“开始生成”或“已委派”等文字便结束，也不等用户再催促或另行授权。已有负责该任务的 subagent 时，使用宿主真实任务通信工具向它派发本次完整执行包；不为每段强制新建代理。派发前仍遵守最新取消要求及授权有效范围。委派参数只使用实际工具 schema，不猜工具名或字段。

执行包须交给 subagent：集数、SEG、版本、本次授权范围、已确认参数、完整 Prompt、实际工具及全部请求参数、真实素材及接缝说明；编辑任务还须传入 `video.md` 规定的同一最终成片任务、原始输入和已成功编辑次数。subagent 原样执行已定请求，不编写或改写 Prompt；实际视频制作/处理调用只由它发起。委派调用明确返回本次任务已被接受（包括携带执行包创建并接受该任务的 subagent）后，mainagent 才能在现有操作记录中记为已委派，保留真实执行者/任务关联；写执行包、发文字承诺或仅取得生成确认均不算实际委派，不另建证明文件或确认步骤。委派能力不可用、调用失败或是否接受任务未明时，如实说明阻塞，不记为已委派、不改由 mainagent 执行；结果未明时先查询原委派状态，不重复派发或提交生成。subagent 逐项回传真实任务状态、结果资源、实际调用信息或已知失败原因。内部探测、依赖输入准备只回传数据，不单独展示。未知原因不猜测，运行中或查询受阻不冒充失败，不重复提交。

同批最多两项视频生成或编辑任务，输入齐备且独立时可并行；不因编号相邻就假定独立，也不为等待后段输入而推迟已就绪前段的委派。依赖前段真实尾帧等结果的后段先保留待执行计划，mainagent 安排原方案所需的依赖准备；实际抽帧等技术处理仍委派 subagent。真实输入就绪后，mainagent 只将其绑定到确认前写定的 Prompt 模板和请求，调整与真实输入顺序对应的素材引用编号，不新增剧情、台词、镜头或效果，并在处理该就绪结果的当前轮次实际委派后段；subagent 不自行编写后段。仍在同一有效授权范围内且方案不变时，不重复确认。真实结果迫使已确认内容或关键参数实质改变时，按原交互合同重新展示并取得相应授权；不能用绑定输入绕过变更确认。

全片内容及分段关系的规划不等于全片生成授权。首批只派发该次明确列明且已授权的任务；后续批次沿用有效规划，在各批执行前按原规则展示并分别取得授权，不把首次确认扩展为后续所有批次。mainagent 收到每项成功结果即按 `media-delivery.md` 交付，不等同批其他结果或后期；已定后期产物按原交付规则另行交付。取消与明确不再接收结果的例外按下文处理。

## 多轮消息的对象与意图

mainagent 依据用户指向的视频、实际任务状态和本轮完整意图处理；多视频逐条判断。“这版不错，再做一个”同时包含评价和新任务，不能只回应评价。指代能从上下文唯一确定时直接承接，不能确定才按交互 Ref 澄清。

沿用仍有效的要求和素材，明确被替换的旧要求不用于后续版本。生成中的已提交方案仍保留原执行依据，不因本轮反馈改写历史。用户要求与锁定项实质冲突时先澄清；明确替换旧要求时更新待采用方案并按原规则重新确认，不再询问已明确的取舍。

### 取消优先

- 对象明确时只处理指定任务；对象不明且会影响取消范围时由 mainagent 按交互 Ref 澄清，不猜测取消整批或全项目。取消不需要生成授权。
- 尚未派发时停止派发；已派发但尚未提交时，mainagent 用宿主实际通信能力通知对应 subagent 停止提交。已经提交且有真实取消能力时，由 subagent 尝试取消并内部回传真实结果；mainagent 说明取消成功、失败、无能力或结果未明。通知代理、停止代理、停止查询不等于远端任务已经取消。
- 取消成功则停止该任务后续制作与交付。取消未成功或状态未明时，如实说明任务仍可能继续；用户明确表示不再需要结果时，mainagent 不交付该任务后来返回的结果，并将这一要求传给执行者。没有“不再接收”要求且取消未成功时，不自行隐藏已成功结果。
- 不自动重试或继续被取消任务的下一批；停止依赖其未获得结果的后续提交，不影响其他独立且未取消的任务。交付前 mainagent 读取该任务最新取消及接收要求，按已有操作记录保存事实，不新建取消报告。

### 生成中

- 修改该视频或补充相关信息：说明“这条视频正在生成中，暂时无法修改，请稍等生成完成。”保持在途方案，不另起修改生成，也不自动排队执行。已明确的修改保存在已有要求记录中，仅作未授权需求，不作为待执行队列。原请求结束后，用户明确继续调整时，复用记录整理方案并取得原规则要求的生成确认，无需用户重述已记录的修改细节；没有继续调整要求时不自动推进，单纯偏好也不自动进入生成。
- 新视频任务：可以正常规划和必要澄清，按原批次范围与交互合同取得本次授权后派发；不沿用原任务确认，不影响原任务继续和交付。
- 催促：查询并说明真实状态；无查询能力或可靠预计时间时只说明已知情况，不编造进度、不重复提交、不换模型。其他反馈按下节处理。

### 原请求已结束

- 明确修改、追加版本、重做、失败重试或下一批：先明确本次范围，按 `video.md` 判断具体画面编辑、重新生成或原有后期/技术处理。涉及视频生成或生成式编辑时重新展示本批参数并实际调用 `interaction.ask`；查询同一已提交任务、既定依赖输入准备及交付原结果不算新生成。
- 只有字幕、水印或截取、裁剪、既定拼接等处理时，执行原有 `delivery.md` 及相关合同，不因多轮反馈改走生成。不能借处理新增整体调色、风格、转场、运镜、动作、表演节奏或音频内容变化；这些修改按 `video.md` 重新生成。原有已授权成片混音与声音桥不因本节被取消，新增音频创作修改不能冒充既定混音。
- 对结果的评价或情绪不自动转成生成请求；有明确请求时同时处理，不因包含评价而忽略请求。

## 偏好与意见反馈

| 类型 | mainagent 的处理 |
|---|---|
| 正向评价 | 简短回应，有合适延展空间时可提出一个可执行建议，不固定追问，不自动追加生成 |
| 负面评价、情绪或辱骂 | 聚焦具体不满，不编造原因。已明确问题不重复问；确需定位时按交互 Ref 澄清。有多种合理改法时提供可执行方向供选择，用户已指定则直接采用，不固定要求选择 2–3 项；评价本身不触发生成 |
| 具体问题与事实纠错 | 核对相关原要求、采用素材和已有真实记录，不能把用户质疑直接写成已核实事实；必要时只查看用户指出的相关位置，不启动整片质检。信息不足时按交互 Ref 澄清；明确后按实际路径处理，不擅自重生成 |
| 偏好但未要求修改 | 更新对偏好的理解；是否落实到当前视频确实不明且影响下一步时才按交互 Ref 澄清，不视为修改或生成授权 |
| 明确修改 | 范围清楚即整理方案，不重复询问意图；在途任务按上节处理，已结束任务按 video.md 选择路径，再取得适用授权 |
| 催促与状态询问 | 区分生成、后期和交付异常；依据真实状态回复，不编造完成时间，不重复生成 |

本文件不增加常规质检、审片或自动返修；工具与次数以 `video.md`，生成确认以交互 Ref，媒体展示以 `media-delivery.md` 为准。
