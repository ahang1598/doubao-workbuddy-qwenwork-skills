# 视频生成

## 视频生成强规则

1. **视频生成工具调用前必须确认生成参数。** 调用下列任一视频工具前，必须先用一句简短自然的开场白说明准备怎么做，再展示“视频生成参数确认”；参数区最前依次列本批实际使用的模型、时长、比例、条数，之后说明生成内容、适用素材用途和必要分段安排；风格、声音、台词等按实际需要补充，对用户的普通文本展示中，只有按需展示的分镜表使用表格，开场白、参数及其余说明均用 Markdown 段落或列表；简单任务默认不展示分镜表，具体按[展示详略](references/interaction-ask-video-clarification-ref.md#展示详略与表格使用)执行。完整参数展示后，先按[展示预估消耗token](references/interaction-ask-video-clarification-ref.md#展示预估消耗token)调用 `video_token_compute` 计算本批预估消耗，再调用 `interaction.ask`；确认问题必须展示预估 token 消耗、付费／免费额度类型，明确提示“视频生成为高消耗行为”，并询问「是否按以上参数继续生成？」。只有用户明确选择「按要求生成」才可执行。选择「暂不生成」或尚未收到答复时，停止本批生成。同一确认覆盖本批列明的调用；参数或内容发生实质变化时，展示变更后的方案并重新确认。
2. **每个需要交付的成功生成或编辑视频都必须立即交付给用户。** 用户取消或明确不再需要结果时，优先按[多轮消息处理](references/multi-turn-handling.md#取消生成)及[取消与拒收例外](references/media-delivery.md#取消与拒收例外)处理；以下逐项交付规则均适用这一例外。包括每个片段和工具返回的每个候选结果，按[媒体交付合同](references/media-delivery.md)逐项展示，不等待同批其他结果或后期。即使认为效果不佳，也禁止自行审片、反思后反复生成、扣留或筛掉结果。由用户判断效果；用户明确要求修改或重做时，再按第一条确认参数后执行。
3. **执行分工。** mainagent 在确认前完成全部规划并确认全部生成参数，确认后创建 OrganizerAgent 执行和直接交付。创建时 `hint` 必须包含工具与生成参数、RichMediaCard 交付规范、全部交付及禁止反思校验约束，详见[生成与交付策略](#生成与交付策略)。澄清及生成确认继续由 mainagent 按原有 `interaction.ask` 策略执行。
4. **提到豆包，先确认品牌参考。** 凡视觉创作需求提到豆包，生成前必须明确本次要呈现的品牌元素（如 Logo、IP 角色或产品界面），并判断是否已有能确认该元素身份的参考。已有充分参考时，直接将对应原图传入 `image_to_video`或结合实际情况使用`media_to_video`。仅有品牌名称、风格示例或其他元素的图片，均不能作为当前元素的身份依据。参考缺失或不清晰时，按目标元素搜索，优先采用官方品牌资料；涉及与豆包互动或是与豆包合影或角色衍生时，必须搜索并使用字节跳动“豆包官方 IP 角色形象”。合影视频同时传入人物图与角色图。搜索后仍无法确认品牌身份时，请用户补充对应参考后再生成。

## 入口与规则权威

完整读取本文件，并根据用户已知目标一次确定本次所需文件与章节，成组并行读取；入口与已能确定相关的参考可同批读取，需要入口才能确定的补充文件在下一轮并行补齐。先判断用户要新创作、参考创作、素材重组还是局部编辑，再选工具与内容类型。实际输入含视频/音频或明确引用已有视频时，将 [素材工具路由](references/media-cond-video-ref.md)加入同批读取；素材路由只决定工具及硬限制，不取消内容规划。只有时长、比例或“修改”动词不构成已有素材。

新创作任务将生产控制、交互合同、创意底盘、当前类型、分镜合同、资产及 Prompt 合同、媒体交付合同中本次预计会用到的章节一起读取；已明确需要摄影、文字、声音或视觉效果时，将对应章节加入同批。文本或局部编辑任务只读取实际相关部分，不为并行而整包加载。下表定位规则职责，不规定读取先后；已知后续所需规则提前读取，不等执行到某一步才逐文件读取。支持批量读取时合并为一次调用，否则并发读取互不依赖的文件；已读且未变的内容直接复用，仅对新需求或新依赖成组补读。并行读取不改变用户确认、媒体执行顺序或真实输入依赖。

## 默认参数

所有工具路径，包括参考创作和单视频编辑，默认 **seedance 2.0 fast**，工具值为 `seedance_2.0_fast`。用户未明确指定其他模型、也未在前置制作方案选择中明确选定其他模型时，方案的实际模型、生成参数确认、派发包与实际调用参数都必须保持 fast。不得因输入视频/音频、复杂度、成片或片段时长、台词偏长、连续跟拍或一镜到底而主动填写或切换其他模型。用户明确指定或选定其他可用模型时才更新方案并核对真实工具 schema，再按原有规则确认；不能先将其他模型填入参数，再把用户对整套参数的一般生成同意当成换模型授权。

模型方案统一在前置制作方案选择中处理，不在方案、参数确认、限制说明或交付末尾另行推荐其他模型。已有当前有效选择时沿用，不重复推荐或再问一次模型选择；只有用户主动提出换模型，或新要求造成必须重新决定的实质冲突时，才按原有前置选择及必要取舍规则处理。实际参数仍以用户明确指定或选定的模型为准。

| 用户可见名称                                   | 工具值                           | 单次时长                   |
| ---------------------------------------------- | -------------------------------- | -------------------------- |
| seedance 2.0 fast                              | seedance_2.0_fast                | 4-15 秒                    |
| seedance 2.0 mini                              | seedance_2.0_mini                | 4-15 秒                    |
| seedance 2.0（会员模型并消耗更多的额度）       | seedance_2.0                     | 4-15 秒                    |
| seedance 2.5（会员模型并消耗更多的额度）       | seedance_2.5                     | 4-30 秒                    |
| seedance 2.5 flash（会员模型并消耗更多的额度） | 以宿主工具实际支持的模型标识为准 | 以宿主工具实际支持范围为准 |

seedance 2.5 flash 仅在用户明确指定或选定时使用，不作为默认或自动替代模型；展示该模型及相应选择项时必须包含“会员模型并消耗更多的额度”提示。其工具标识和单次时长以宿主实际能力为准，不沿用或推测其他版本的取值。

以上为技能配置，调用前仍以宿主真实能力核对。涉及新生成，命中[交互合同](references/interaction-ask-video-clarification-ref.md#制作方案选择)规定的明确长时长或用户台词明显过长条件时，保留原有前置方案选择，必须先实际询问制作方案及必要取舍，不能以默认模型跳过选择。仅因台词偏长询问时不精确计算朗读用时；两种情况合并询问，不重复设问。保留全文需要分段时默认推荐 fast，另一模型选择仅为条件允许且已核实可执行的 2.5；mini 仅在用户明确指定时使用，不作为默认或替代推荐。前置问询中列出 2.5 是可选方案，不代表已选用；只有用户明确选中才可将该模型写入后续生成参数。选择方案不授权生成，实际生成仍按批次确认。会员说明并入模型字段及相应选择项，不把模型描述为免费；生成确认问题中的预估 token 消耗及付费／免费额度类型按[展示预估消耗token](references/interaction-ask-video-clarification-ref.md#展示预估消耗token)单独展示，不以模型会员说明替代。实际需要生图时默认 `seedream 5.0 flash`；没有生图产物不列生图模型。

用户未指定时长时，默认在 **4-15 秒内动态推荐**：按内容展开、正常语速、完整动作、必要阅读与回应所需时间确定，不固定选 15 秒。General 简单动态默认 4-8 秒，单图自然动起来默认 5 秒；用户明确指定时长时遵循要求与实际工具能力，不因片长增加无关剧情、重复镜头或改变用户锁定内容。长视频默认一条连续成片，先把全片内容按[长视频内容展开](references/creative-core.md#长视频内容展开)写充分，再按所选模型能力拆段，不能用多条独立短片冒充。fast 每段 4-15 秒，2.5 每段 4-30 秒；在内容完整、动作和声句自然结束的前提下优先利用单次容量，边界不合适就提前结束，不硬凑 15 秒或 30 秒。末段不足最低时长时重排相邻段，拼接取用后的总时长符合用户要求，不无故延长成片，也不靠慢动作、拖读、重复画面或空白补时长。具体拆法见[长视频连续性](references/production-control.md#长视频连续性)。

合法比例：`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`。优先级为用户要求 > 平台/展示位 > 类型默认 > 核心参考素材。竖屏社媒默认 9:16，横版官网/会议/TVC 默认 16:9，商品卡可用 1:1 或 3:4；21:9 用于明确超宽屏用途。用户未指定数量时为 1 条，长视频生成段不计为独立成片数量；每批最多两项视频生成/模型编辑任务，分段同样计入批次上限。所有任务采用统一制作流程，按实际需要展开分段接续、必要资产、关联内容及后期安排，具体按生产控制执行。用户要求审某一步只提前交付指定内容，不自动增加其他审阅。

## 类型与读取

同一独立视频保留一个主类型；混合项目逐条选择。仅用户明确要求短剧、微电影、剧情影视、动画短片、动态漫或分集剧本制作时转 `doubao-creative-drama`；带故事感的广告、品牌片仍在本技能内。

| 主类型   | 内容                                                               | 类型参考                                        |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| General  | 概念、风景/空间、旅行记录、MV、视觉实验、时尚、文字动画、简单动态  | [通用创意](references/general-creative-video.md) |
| UGC      | 创作者口播、推荐、测评、使用记录、人物观点、问答采访、探店         | [UGC](references/ugc-talking-video.md)           |
| 产品广告 | 商品、电商、服务/门店/目的地推广、内容预告、功能演示、使用证明     | [产品广告](references/product-ad-video.md)       |
| 品牌 TVC | 品牌主张、态度、人物故事、品牌活动/周年、公益倡导                  | [品牌 TVC](references/brand-tvc-video.md)        |
| 企业商务 | 企业能力、客户案例、招聘、招商/路演、年度/ESG、会议/展会、组织沟通 | [企业商务](references/business-video.md)         |
| 知识讲解 | 原理、方法、操作、教程、数据解读；真人、录屏与动画共用             | [知识讲解](references/explainer-video.md)        |

单图动态不因主体是商品就自动升级为产品广告。将当前类型的适用边界、第一阶段写法及已确定相关的用途/方法章节纳入同批读取，不默认整包加载。主文件定任务，类型文件定取材与表达，共同方法解写作难题，视听和视觉库解实现难题；不在这些层里反复重定主线。

上表是技能内的主策略路由，不把行业里的类型当成互斥标签：TVC 是商业广告成片形式，产品广告也可以采用；UGC 指内容来源，营销中的 UGC 风格广告采用创作者视角，口播只是其表达方式之一。先按用户本次主要任务选择一个策略文件，再明确本片用产品展示、品牌广告、创作者口播、使用记录或其他具体形式。用户要营销时，教学、测评或生活记录是表达方式，不能因采用这些形式就把任务改成不介绍产品价值的普通教程或记录；确实以教会现有用户操作为目标时才按教学取舍。有人声不自动是 UGC，有人物剧情或 30 秒时长也不自动完成了 TVC 创作；来源与营销目的须准确说明。

用途、行业与表现形式分别判断，不增加问卷。例如文旅可以是目的地广告、旅行记录或路线讲解，动画可以用于科普、广告或品牌表达；按本次主要任务选文件，再按需查相关子类型。未列出的用途依观看目标选择最接近的策略，不硬套已有案例。以理解或会做为主的知识/操作讲解统一查知识文件，不因出镜与否改用另一套教学规则；以创作者推荐或营销判断为主的知识型口播仍用 UGC，确需教学时借知识方法；涉及企业事实的责任传播归企业商务，面向公众的议题倡导查品牌文件的相应写法，不凭空补一个品牌。

### 生成与交付策略

mainagent 必须在用户确认前完成全部规划，包括内容、分镜、声音、完整 Prompt、输入素材、工具及所有生成参数。用户确认后，直接创建 OrganizerAgent 执行，不再补写规划或擅自变更已确认内容。

创建 OrganizerAgent 时，`hint` 必须包含以下三项：

1. **工具与生成参数**：明确指定工具、完整 Prompt、真实输入素材及顺序，以及模型、时长、比例、数量等全部适用参数。OrganizerAgent 必须按已确认内容执行，不能自行修改或补充。
2. **RichMediaCard 交付规范**：OrganizerAgent 使用工具返回的真实可用资源，通过 RichMediaCard 直接向用户交付。卡片独立成行，配一句简短产物说明；不得用裸链接或文字总结代替卡片，不得使用虚构或占位资源。
3. **全部交付，禁止反思校验**：每个成功产物，包括片段、候选结果和最终成片，都必须立即逐项交付，不等待其他任务，不筛选、不扣留、不重复交付。禁止反思、审片、质量校验、自动修复或重新生成。异步任务须跟进至取得结果或明确失败、阻塞；失败或结果未明时如实说明，不伪造产物。用户取消或明确拒收的除外。

澄清、制作方案选择和生成确认仍由 mainagent 按[交互合同](references/interaction-ask-video-clarification-ref.md)调用 `interaction.ask`，OrganizerAgent 不向用户提问或请求确认。图片与纯后期执行分工不变；卡片格式、取消、去重和失败恢复见[媒体交付合同](references/media-delivery.md)。
