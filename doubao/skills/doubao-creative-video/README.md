# doubao-creative-video 阅读指南

这份文档用来快速读懂整个 video skill：先看入口怎么判断任务，再看完整流程怎么推进，最后看不同视频类型各自补了什么策略。

## 先看整体结构

```text
doubao-creative-video/
|-- SKILL.md
|-- README.md
`-- references/
    |-- interaction-ask-video-clarification-ref.md
    |-- production-control.md
    |-- creative-core.md
    |-- audiovisual-craft.md
    |-- visual-motion-playbook.md
    |-- asset-generation.md
    |-- storyboard-contract.md
    |-- general-creative-video.md
    |-- ugc-talking-video.md
    |-- product-ad-video.md
    |-- brand-tvc-video.md
    |-- business-video.md
    `-- cli/
        |-- README.md
        `-- [Design CLI command pages]
```

整个 skill 按职责分层，`references/` 允许包含子目录；其中 `references/cli/` 是 Design CLI 的正式命令 reference：

1. `SKILL.md`：入口和总开关。
2. `interaction-ask-video-clarification-ref.md`：视频方案、素材询问、视频生成确认和片段继续确认规则。
3. `production-control.md`：完整生产流程和所有阶段控制。
4. 三个通用创意文件：`creative-core.md` 管创意方向，`audiovisual-craft.md` 管视听工艺、构图、配色与文字排版库，`visual-motion-playbook.md` 管视觉发动机、效果和运动。
5. 生成与分镜合同：`asset-generation.md` 统一按需人物/产品/音色资产、视觉关键帧、图片/视频 Prompt 和身份锁；`storyboard-contract.md` 统一完整分镜母版、映射和校验。
6. 类型文件和 CLI 子目录：类型文件管不同视频类型的专属策略；`media-delivery.md` 管视频／图像直接交付与强制产后目录整理；`cli/` 管 Canvas Workspace 初始化、手工资产创建、对象读取和目录更新命令。

入口先选类型，确认规则管授权，流程文件管阶段，通用创意库确定表达与设计，资产生成和分镜合同落实为可生成产物。按生产控制的阶段矩阵读取，避免每阶段全量重读；CLI 子目录只在画布交付或命令调用时读取。

## 推荐阅读顺序

第一次读，按这个顺序最快：

1. 读 `SKILL.md` 的前半部分，重点看触发边界、对外沟通、生成门控、模型/时长/比例/数量和类型选择。
2. 读 `interaction-ask-video-clarification-ref.md`，先理解方案展示、素材询问、视频生成确认和片段继续确认。
3. 读 `production-control.md` 的开头到“完整链路与阶段确认”，理解主流程和阶段控制。
4. 继续读 `production-control.md` 的资产、沙箱、阶段上屏、工具、成片和返修规则。
5. 读 `creative-core.md`，理解通用创意方法：用户指令、九层创意底盘、主线、受众、产品/主题结果、事实边界、平台语境和候选方向。
6. 读 `audiovisual-craft.md`，查构图策略、色彩合同、文字排版创意库与字体，以及运镜、布光、声音和文案。
7. 读 `visual-motion-playbook.md`，把核心表达转成视觉发动机，再补触发、运动、反馈和回收。
8. 读 `storyboard-contract.md` 与 `asset-generation.md`，理解分镜唯一母版、按需人物/产品/音色资产、视觉关键帧数量、图片 PE、素材身份锁与视频五段式。
9. 根据当前独立视频、平台版本或交付单元，只读一个类型文件；多视频项目逐条判断。
10. 视频／图片交付先读 `references/media-delivery.md`；Workspace 初始化、手工资产创建和目录命令再读 `references/cli/README.md` 与对应命令页。

日常查规则时，可以按问题反查：

- 想知道“这个需求该不该用 video skill”：看 `SKILL.md`。
- 想知道“该不该问用户、怎样确认开始生成”：看 `interaction-ask-video-clarification-ref.md`。
- 想知道“完整流程怎么走”：看 `production-control.md`。
- 想知道“创意方向、传播策略、受众洞察、证明逻辑、结果转译、平台语境怎么定”：看 `creative-core.md`。
- 想知道“运镜、布光、构图、配色、字体、文字排版、声音和文案怎么设计”：看 `audiovisual-craft.md`。
- 想知道“图片和视频 Prompt 怎么写、如何锁素材、四宫格怎么生成”：看 `asset-generation.md`。
- 想知道“分镜格式、节拍和镜头映射、镜头密度与校验”：看 `storyboard-contract.md`。
- 想知道“视觉效果怎么不普通、AI 效果语法怎么转译、开场/高光/反转/结尾/转场怎么同步”：看 `visual-motion-playbook.md`。
- 想知道“某类视频该怎么写”：看对应类型文件。
- 想知道“视频短链／图片结果如何直接 present_files、何时整理目录”：看 `references/media-delivery.md`；Workspace 初始化和目录命令看 `references/cli/README.md` 和对应命令页。

## 主链路怎么理解

本节中“短片内部四格创意线”的通用描述只适用于普通短片。General 简单动态任务始终使用轻量运动线，不创建内部四格；若下方旧摘要仍写“短片直出创建内部四格”，以本条例外和主 `SKILL.md` 为准。

完整链路固定是：

```text
规划 -> 前置制作确认 -> 按需人物/产品/音色资产 -> 分镜脚本 -> 视觉关键帧 -> 视频生成确认 -> 视频片段 -> 成片
```

概念关键帧在完整链路中必须生成、展示并确认；用户明确要求关键帧/概念图时，即使单条时长满足短片直出，也转入可见关键帧流程。短片直出默认不出四宫格图：普通短片使用内部四格创意线，General 简单动态任务使用轻量运动线，并写入完整分镜与最终视频 Prompt；短片的参数确认就是本次视频生成授权，不再二次确认。独立脚本只在用户要求先审文字，或口播、旁白、对白、事实声明复杂到需要单独确认时插入：

- 规划：直接拟定目标、平台、模型（视频模型默认 `seedance 2.0 fast`；完整链路或实际生图时单列生图模型，默认 `seedream 5.0 flash`；短片直出无实际生图时不列生图模型）、时长、比例、数量、创作方向、叙事结构摘要、视觉记忆点、素材需求和字幕策略；素材询问按 `interaction-ask-video-clarification-ref.md` 执行。General 简单动态任务只做 4-8 秒，照片动起来固定 5 秒；真实一镜到底只使用一个连续镜头。
- 参数/前置确认：短片直出第一次调用 `interaction.ask` 即确认“按要求生成”，允许创建或复用画布、静默整理完整分镜、建立对应内部创意规划、编译 Prompt 并委派视频生成；完整链路第一次调用 `interaction.ask` 只允许创建或复用画布、生成方案中已列明的按需人物/产品/音色资产、整理分镜并生成可见视觉关键帧，不授权生成视频。
- 按需一致性资产：短片直出跳过；完整模式仅在人物跨片段反复或长时间出现、缺少必须保持的产品素材、或同一口播音色需要跨视频/片段统一时，分别生成人物、产品或音色资产。场景、Logo、道具、UI 和风格只登记用户素材，不默认生成。
- 分镜脚本：文件开头写清创意说明，下面写完整镜头级分镜表、台词/旁白/画面文字、动作、声音、素材引用、连续性和片段计划。
- 内部创意规划 / 视觉关键帧：普通短片直出创建内部四格创意线，General 简单动态任务只创建轻量运动线，不生成、不展示四宫格图；完整链路必须生成四宫格，少于 30 秒 1 张、30-59 秒 2 张、60 秒 3 张，之后每多 30 秒加 1 张。生成可见关键帧前必须完整读取 `visual-motion-playbook.md` 与 `audiovisual-craft.md`，让视觉发动机、玩法机制、构图、配色、字体排版、光线、材质和动态把手真实进入图片或内部规划。格位跨图连续，不是候选方案。
- 视频生成确认：短片直出已在参数确认时授权实际视频生成；完整链路在本批视频实际生成前展示本批视频参数和分镜简表，再调用 `interaction.ask` 授权实际视频生成。若本批生成了可见视觉关键帧，必须先完成关键帧确认；关键帧确认是用户对已交付图片的普通聊天确认，不是 `interaction.ask`。
- 视频片段：短片从校验后的分镜与对应内部创意规划编译五段式 Prompt 后直接委派生成；完整链路从分镜、已确认资产和已确认可见格位编译 Prompt，取得批次视频生成确认后分批生成。

每次实际生成前必须普通文本完整展示任务类型、交付格式、模型、数量、逐段及总时长、比例、分辨率、逐段内容、镜头与动作、视觉方向、身份保持、台词／字幕／配音／音乐和输入素材，再单独调用 `interaction.ask` 取得本次明确单选确认；不得缩减为四项或引用历史确认。
- 成片：完成拼接、节奏、音频、用户已要求的字幕/花字、平台版本和封装后直接交付。

其他内容不要理解成额外阶段：

- 来源事实、真实资产、项目沙箱、阶段上屏和版本记录是每个阶段都要遵守的横切规则。
- 长视频、接缝、抽帧、MediaKit、按需字幕、工具和返修是对应阶段的细化规则。
- 阶段产物是给用户展示并确认，最终成片和交付文件才叫正式交付。
- 完整链路的基础资产说明、分镜脚本、完整分镜表、片段执行表和 Prompt 放在文件里展示；聊天正文只写摘要、用途和需要确认的点。短片直出的内部详细分镜表只用于生成 PE，不默认展示给用户。
- 视频生成参数确认的判断标准是“下一步是否即将提交视频生成、视频编辑或图生视频”；任何实际生成前都必须普通文本完整展示方案，再用 `interaction.ask` 确认。
- 只改文案、分镜、策略或 prompt 本身可以直接做；改完只要要重新出视频，也必须先普通文本展示完整方案并用 `interaction.ask` 确认。
- 已确认参数只对当前这一次视频任务或当前批次有效；换任务、换版本、换比例、换时长、换模型、换镜头结构或换素材职责，都必须重新展示方案并重新 `interaction.ask` 确认。
- 完整链路的规划确认不等于视频片段生成授权；第一批片段生成前也要普通文本展示全部本批生成参数的完整确认并用 `interaction.ask` 确认，之后每批最多 2 个并循环确认。
- 短片直出的参数确认就是实际视频生成授权；确认后必须完成内部详细分镜、校验和对应内部创意规划，再直接编译 Prompt 并委派生成。内部完整分镜和内部创意规划不默认展示；如果内部准备导致已确认方案发生实质变化，才回到参数确认。生成成功后直接交付。

## 每个文件负责什么

### `SKILL.md`

入口文件。主要看这些部分：

- 是否应该触发 video skill，而不是 drama。
- 用户要生成视频时，短片直出先展示完整方案并用第一次 `interaction.ask` 直接授权本次生成；完整链路先展示完整方案并用第一次 `interaction.ask` 确认进入前置制作，再按 `interaction-ask-video-clarification-ref.md` 在每批实际生成前展示本批参数并用第二次 `interaction.ask` 授权实际生成。
- 默认模型、会员模型、时长、比例和数量怎么判断。
- 类型怎么选择，并且每条独立视频、每个平台版本或每个交付单元只选择一个主类型文件。
- 参数确认与脚本格式，以及分镜合同和资产生成合同的读取入口。
- 哪些内部信息不能暴露给用户。

它不负责完整生产流程。看到长视频、工具、返修、成片交付这类问题，要去 `production-control.md`。

### `production-control.md`

流程规则。主要看这些部分：

- 文件开头的“主链路 + 横切规则”。
- 阶段读取矩阵。
- 完整链路与阶段确认。
- 短片直出 PE 防压缩：2.0 15秒和 2.5 30秒即使少确认，也要在参数确认分镜表和最终 PE 中写足连续秒段分镜、动作链、声音卡点和主视觉贯穿。
- 来源与事实锁。
- 真实资产门槛。
- 项目沙箱与目录存储。
- 阶段上屏与用户可见产物。
- 分镜准出和镜头职责。
- KF 与 FRM。
- 长视频连续性、接缝与抽帧。
- 工具选择、MediaKit、字幕、成片交付和返修。

如果觉得流程乱，优先回到这个文件看：它决定每一步应该在什么时候发生。

### 通用创意三件套

三个通用库都参与创意判断，实际按阶段矩阵读取；已确认方向不在后续阶段反复发散：

- `creative-core.md`：解决方向和策略判断，包括用户指令预检、九层创意底盘、主线、受众、产品/主题结果转译、事实边界、平台语境和候选方向。
- `audiovisual-craft.md`：解决视听工艺，包括构图策略库、配色合同、完整文字排版创意库与字体形态，以及运镜、布光、声音、文案和可读性。
- `visual-motion-playbook.md`：统一视觉发动机与机制，包括概念转译、异常规则、效果语法、开场、高光、反转、回收和运动。

这三件套解决“怎么更有创意、更像一个设计过的视频”，不解决阶段确认和文件交付。

### `asset-generation.md`

只管理按需人物、按需产品、按需音色、短片内部创意规划、可见视觉关键帧和五段式视频 Prompt。普通短片使用内部四格创意线，General 简单动态任务使用轻量运动线；短片直出不另生一致性资产，也不默认出四宫格图，完整模式按选择门判断人物、产品和音色。

### `storyboard-contract.md`

内部完整分镜是唯一母版，用户确认简表和视频 Prompt 都由它编译；负责节拍、镜头与生成段映射以及客观校验，四宫格不能代替逐镜分镜。

## 通用策略怎么用

三件套不是“看情况补读”的灵感库，而是每条视频都要默认参与判断的创意工作台。读完后不要把策略名直接写进用户确认、分镜或 PE，而要先做迁移适配：

```text
当前用户指令/素材/平台
-> 唯一主类型
-> P0 传播目标和受众张力
-> 产品/品牌/人物/企业/主题真相
-> 可见证明锚点
-> 通用叙事/视觉/视听策略
-> 当前类型和品类语义适配
-> 参数确认、分镜和 PE 的具体秒段
```

适配的判断标准很简单：策略换到当前项目后，是否已经变成了具体可见、可听、可检查的执行动作。比如“尺度错位”不能只写成效果名，必须说明主体怎么进入产品或场景、尺度变化揭示什么信息、声音卡在哪个动作、结尾回收到哪个真实产品/品牌/主题；“低角度冲击”“蓝橙电影感”“匹配转场”也必须分别说明它们在当前片中负责证明、情绪、视线引导还是记忆回收。

每次至少把这些维度落到产物里：主线、钩子、证明锚点、叙事节奏、运镜、布光、构图、色彩、转场、声音、文案、视觉效果、创意亮点和结尾回收。类型文件负责把它们变成当前场景的合理写法：产品广告回到产品真相，UGC 回到真人可信表达，品牌 TVC 回到品牌主张，企业商务回到事实证据，通用创意回到概念变化和情绪回环。

## 类型文件怎么读

类型文件只补充专属策略，不重复完整流程。

### `general-creative-video.md`

看通用创意视频、概念片、氛围片、视觉实验、MV、风景、人物时尚、单图自然动起来。

重点理解：

- 没有强商业目标时怎么组织概念。
- 简单动态任务、照片动起来和真实一镜到底如何在服从用户指令的前提下补足动作、运镜、声音、状态变化与创意。
- 抽象词怎么转成可见画面。
- 视觉系统、主体动作、场景响应和结构变化怎么写。

### `ugc-talking-video.md`

看 UGC 口播、带货、测评、开箱、教程、达人推荐、知识引流、探店采访。

重点理解：

- 人对人表达关系。
- 不同 UGC 类型的脚本结构。
- 口播节奏、真人感、黄金动作、卖点证明链。
- 参考视频和竞品怎么迁移但不照抄。

### `product-ad-video.md`

看产品广告、电商带货、商品展示、功能演示、场景种草、促销转化、产品 launch。

重点理解：

- 产品真相卡。
- 产品广告主线。
- 商品展示、场景种草、体验测评、教程演示、促销转化的差异。
- 无参考视频时怎么主动发散创意。
- 产品一致性和证明链。

### `brand-tvc-video.md`

看品牌宣传、品牌 TVC、形象大片、品牌故事、品牌理念、品牌联名、发布会预热、公益责任。

重点理解：

- 品牌主张和视觉母题。
- 品牌资产、产品登场、人物故事和社会议题怎么处理。
- TVC 的脚本、分镜、关键帧和成片关注点。

### `business-video.md`

看企业宣传、企业形象、央国企形象、产业品牌、招商路演、客户案例、B2B 服务、ESG、投融资。

重点理解：

- 企业事实和证明链。
- 受众决策逻辑。
- 组织能力、交付能力、案例、资质和客户价值怎么转成画面。
- 企业片如何避免空泛口号。

## 类型选择怎么判断

记住一个原则：每条独立视频、每个平台版本或每个交付单元只选一个主类型。

- 真人推荐、口播可信感、真人测评、创作者视角和信息流带货：UGC。
- 单品购买、功能证明、商品展示、产品 launch 和促销转化：产品广告。
- 消费品牌态度、品牌故事、品牌理念和品牌资产记忆：品牌 TVC。
- 企业主体、组织能力、产业实力、招商路演、客户案例、B2B 服务、企业传播型和事实证明：企业商务。
- 没有商业主体、企业事实或真人对镜口播：通用创意。

如果读到某个类型文件后发现当前视频判断错了，不要在类型文件里继续跳来跳去；回到 `SKILL.md` 为当前视频重新选择唯一类型文件。若用户同时要“一条 UGC + 一条产品广告”或“企业版 + 信息流版”，按不同交付单元分别路由。

## 资产和目录怎么理解

video 的存储思想和 drama 类似：项目控制、共享资产、单条视频执行产物、Prompt、视频片段、抽帧和成片都分层保存。

区别是 video 不按分集存储，不建立 `episodes/ep_N/`。它使用：

```text
videos/video_N/
```

来表示第 N 条完整视频或第 N 个平台/变体交付单元。

长视频拆段仍属于同一个 `video_N`，不是分集，也不是多条独立视频。

核心目录在 `production-control.md` 里维护，主要是：

- `00_制作控制/`
- `shared/02_资产/`
- `videos/video_N/01_脚本/`
- `videos/video_N/02_资产/`
- `videos/video_N/03_分镜/`
- `videos/video_N/04_关键帧/`
- `videos/video_N/05_视频片段/`
- `videos/video_N/06_成片/`

项目沙箱目录与画布目录分别维护：前者保存工作文件和采用记录；后者在非 Mobile 本轮已确认批次全部媒体直接交付后，通过 `+tree`／`+ls` → `+get` → 更新 `path` → 回读核验完成，详见 [媒体直接交付与产后目录整理](references/media-delivery.md)。不得为生成结果重复创建 VIDEO／IMAGE Item。

理解目录时看职责，不要只看文件格式。产品图、人物图、品牌素材、场景图、音频、视频片段、抽帧和 Prompt 都有不同职责。

## 最容易混淆的点

- `production-control.md` 是流程核心，不要在类型文件里再写一套流程。
- `creative-core.md`、`audiovisual-craft.md`、`visual-motion-playbook.md` 是默认通用创意三件套，不要把布光、构图、色彩、声音和完整视觉机制到处复制到类型文件。
- 类型文件按独立视频或交付单元只选一个；多交付项目可以逐条不同，但不要在同一条视频里多文件串读。
- 中间阶段是展示并确认，不是最终交付。
- 内部可以判断短片直出链路或完整链路，但不要把模式名写给用户；短片减少分镜文档与四宫格图展示，仍保留真实素材继承、对应内部创意规划和生成授权。
- 参数确认是给用户看的自然方案，不是内部状态表；短片直出的参数确认必须体现内部规划结果，而不是把用户指令直接改写成生成参数。
- General 简单动态任务不强制 8 镜或前三秒切镜，但必须限制在 4-8 秒并于首秒启动有效运动；照片动起来固定 5 秒。真实一镜到底只有一个镜头，不使用隐藏切点，但要通过连续摄影机路线、主体行动和空间变化维持推进。
- 短片直出的用户可见参数确认分镜表保持五列浓缩版：时间、核心画面与动作、台词/声音、运镜衔接、钩子与亮点；最多 8 行，必须连续覆盖完整时长。
- 短片直出内部详细分镜表和最终 PE 都要按连续秒段写足镜头密度；内部详细表需要展开镜头职责、主体与场景/素材、动态动作链、镜头语言、画面设计、声音与文字、转场/尾态、生成要点和风险/禁区，但不展示给用户。
- 每次生成都要传入当前画面相关的确认标准资产和概念格位；无法消费必要素材时不能假称继承，也不能通过纯文生视频绕过身份锁。
- 默认无字幕不等于无人声。除品牌 TVC 外，Agent 不得自行省略旁白、口播或对白；品牌 TVC 按“完整旁白优先、少量旁白其次、无旁白最后”判断，只有画面与声音设计能独立讲清品牌表达时才采用无旁白。
- 文档、截图、表格、聊天记录默认是文本/事实来源，不等于视觉参考图。
- KF 是生成前目标，FRM 是生成后抽帧证据，不能互相冒充。
