# 完整分镜合同

## 适用范围

本文件规定短片直出和完整链路共用的唯一完整分镜 Markdown 格式。完整分镜是用户确认简表、镜头级执行和最终视频 Prompt 之间的创作母版，不再建立独立 `video_plan.json` 或另一套镜头事实源。

- 短片直出：mainagent 在执行确认后、编译最终视频 Prompt 前静默创建完整分镜文件并运行客观校验；不向用户展示、不交付、不写入画布。
- 完整链路：在分镜阶段创建同格式文件，客观校验通过后直接交付给用户确认；不写入画布。
- 用户修改分镜：先修改这份完整分镜，再重新校验并重新编译受影响的视频 Prompt；不得只改用户确认简表或 Prompt。

## 文件结构

完整分镜固定按以下顺序组织：

1. 创意说明。
2. 完整分镜表。
3. 按需片段执行与连续性说明。

### 创意说明

开头压缩为 `5` 条，每条 `1-3` 句，不重复上游已经确认的模型、比例、数量和交付流程：

```markdown
# [项目名]完整分镜

## 创意说明

- 核心主线：
- 表达意图与观看路径：
- 视觉记忆点与母题：
- 视听与文字策略：
- 素材使用与风险边界：
```

`视听与文字策略` 写明人声形式和说话关系。非 TVC 默认使用可听人声，只有用户明确要求时才采用无人声；品牌 TVC 按主 `SKILL.md` 的“完整旁白 -> 少量旁白 -> 无旁白”优先级判断。采用无人声时必须说明替代表达层；校验脚本不判断该创作决策是否合法。

`视觉记忆点与母题` 不能只写“高级感”“电影感”“科技感”或风格名，必须写清主创意系统/主玩法、可复述画面、它服务的核心信息，以及后续内部四格创意线或可见四宫格可以继承的创意演化关系。若暂时无法确定四格创意线，也要在这里先锁定至少一个真实触发、一个可见变化和一个结尾回收方向，避免 Prompt 或视觉关键帧阶段临时改主线。

`核心主线` 和 `视觉记忆点与母题` 必须绑定产品、人物、卖点、品牌主张或行动理由。不能写成“雪山行驶、城市漫游、光影变化、情绪递进”这类可替换场景链；必须说明为什么这个场景、创意规则或视觉母题只有当前主体成立。主创意系统至少要在开场、中段和结尾各出现一次，形成建立、升级、回收；允许多个相关创意节点，只要它们属于同一系统并互相承接。若某个创意只服务一个孤立镜头，必须改成转场/辅助效果，不能放进主创意系统。

创意说明还必须承接 `creative-core.md` 的品类套路排雷。不要把排雷过程完整展示给用户，但 `视觉记忆点与母题` 要写出已经避开默认联想后的具体主创意系统：它由哪个当前产品/品牌/人物/素材事实触发，和最常见的同品类套路有何机制差异，为什么不能直接换成任意同品类产品。若只能写成“咬下很脆、光波扩散、雪山疾驰、水光蔓延、数据飞出、花瓣飘散”这类默认感官或装饰效果，必须回到创意阶段重选机制。

`表达意图与观看路径` 必须说明叙事和创意如何合成一条观看路径：观众先看见什么问题/诱因，产品或主体如何触发玩法，玩法怎样带出卖点/亮点，后续镜头怎样继承前一镜留下的形状、声音、文字、材质、动作方向、人物反应或场景状态，最后如何回收到产品/品牌/主题。不能把叙事写成一套、创意写成另一套；若创意去掉后叙事仍完全成立，或创意出现后不影响下一镜头，必须重写。

### 完整分镜表

表头固定，不得增删、改名或交换顺序：

```markdown
## 完整分镜表

| 节拍ID | 镜头ID | 生成段ID | 时间 | 镜头职责 | 新增信息 | 画面层级 | 主体与场景/素材 | 画面动作 | 镜头语言 | 画面设计 | 声音与文字 | 转场/尾态 | 风险/禁区 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| B01 | SH001 | SEG01 | 00:00.0-00:01.2 | 停滑钩子 | 观众第一次知道的具体信息 | A-roll / B-roll / 产品特写 / UI / MG / 混合层 | 主体、场景、道具与素材引用 | 动作起点 -> 过程 -> 反馈 -> 结果 | 景别、视角、机位、一个主运镜 | 构图、光线、色彩、材质 | 旁白：{完整可听文本} (BGM) <拟音> “画面文字” | 切入、切出和可承接尾态 | 事实、身份、产品、文字与生成禁区 |
```

填写规则：

- `节拍ID` 固定使用两位数字 `B01`、`B02`……，按首次出现顺序从 `B01` 连续编号，不得跳号；对应用户确认简表中的叙事节拍。用户确认简表在“时间”单元格中保留对应节拍 ID，例如 `B01｜00:00-00:02`。
- `镜头ID` 固定使用三位数字 `SH001`、`SH002`……，在当前独立视频的 `video_N` 命名空间内按时间从 `SH001` 逐镜连续编号，不得跳号；每条视频都从 `SH001` 重新开始。
- `生成段ID` 固定使用两位数字 `SEG01`、`SEG02`……，按首次出现顺序从 `SEG01` 连续编号，不得跳号；每条视频都从 `SEG01` 重新开始。`SEGxx` 不是集数，也不是 Prompt 内的秒段：它表示同一条完整视频中一次实际提交给视频模型生成的连续视频片段。15 秒以内短片通常只有 `SEG01`；超过单次生成上限或必须分段连续生成时，同一个 `video_N` 才会包含 `SEG01`、`SEG02`……。一个 `SEGxx` 可以覆盖多个连续 `SHxxx`，但一个 `SHxxx` 只能属于一个 `SEGxx`；每个 `SEGxx` 独立编译并提交一份完整五段式 Prompt。项目级关联必须使用 `video_id + 局部 ID` 复合键，例如 `video_2/SEG01`；内部执行包、Prompt 留档元数据和片段清单必须记录生成段覆盖的镜头 ID，例如 `video_2/SEG01（覆盖 SH001-SH002）`。实际发送给媒体模型的 Prompt 正文只写对应连续时间、自然导演语言和真实素材引用，不写内部 ID。
- 一个节拍可以包含多个镜头，一个生成段也可以覆盖多个镜头；镜头只能属于一个节拍和一个生成段。除 General 简单动态任务和用户明确要求的真实一镜到底外，15 秒视频最低 `8` 镜，并按动作需要增加；生成段按动作连续性和模型可执行性划分。完整动作优先在同一镜头或同一生成段内连续完成，不能为了达到下限拆断动作；只有观看任务、证据层级、空间阶段或情绪状态变化时才切镜。General 简单动态任务不套用 `8` 镜下限；用户明确要求真实一镜到底时只允许一个 `SH001`。
- 时间从 `00:00.0` 连续覆盖到总时长，不得有空档、重叠、倒序或零时长。
- 15 秒及以内视频中，单镜超过 `2` 秒时，`画面动作` 必须明确拆出至少三个可分辨动作或状态阶段，并让动作、观看关系和信息状态中的至少两项发生实质变化。单纯慢推、拉远、主体渐大、环绕、旋转、发光、悬浮、人物微动或同画面停留不能支撑长镜；不满足时必须缩短、拆镜或重写调度。General 简单动态任务可以用一个镜头完成，但仍须写清“启动 -> 发展 -> 落定/回环”；真实一镜到底必须保持一个 `SH001`，把人物路线、摄影机路线、空间转换、动作节点和环境反馈写在同一行，不得使用隐藏切点。
- `新增信息` 只写观众在本镜头第一次获得的信息。不得留空，不得与相邻镜头逐字重复；是否真正有价值由 mainagent 做导演判断，不交给脚本判断。新增信息不能只是“看到另一个景别/另一个环境/更漂亮的氛围”，必须推进产品/人物/品牌/卖点/主玩法/情绪判断/行动信息中的至少一项。
- 同一动作、表情、构图、机位或结果不能连续占用多个镜头或以相同状态重复停留。再次出现必须完成升级、反应、对照、答案或回收；否则删除或合并。结尾回到开场构图时，`新增信息` 必须写清主体状态、关系、意义或品牌归属发生了什么变化，不能把“回到开头”本身当作首尾呼应。
- 每个镜头都要标清它和主创意系统/主玩法的关系：建立规则、触发变化、证明产品/品牌、升级视觉母题、制造转场、形成反应或完成回收。与主系统无关的漂亮镜头只能作为短暂过门；连续两个镜头都与主系统无关时，必须删除、合并或改写。
- 每个醒目人物、物品、场景、UI 或 B-roll 都必须能追溯到当前核心、人物关系、证据、情绪、转场或回收职责。若一个插镜会让观众误以为主体、商品、地点或主题改变，必须在前镜建立动机并在后镜兑现关系；做不到就删除，不能以“丰富画面”“生活方式”“氛围细节”保留。
- 每个创意镜头都要经得起同质化审查：它不能只是当前品类的默认声音、光波、粒子、飞溅、花瓣、慢动作或环境奇观。若镜头使用默认感官元素，必须在同一单元格写清它被当前产品/品牌/人物动作如何改造成证明、转场、信息揭示或回收机制；否则降级为声音/质地细节，不能承担主玩法镜头。
- 每个创意镜头都要经得起匹配审查：它必须能追溯到用户指令、素材事实、产品/品牌卖点、目标人群或平台语境，并且在 `转场/尾态` 中留下能被下一镜承接的状态。只写“创意展示、视觉冲击、氛围升级、体现卖点”不合格；必须写清当前创意让观众新增了什么判断，下一镜继承什么。
- `画面动作` 必须写出“触发 -> 过程 -> 反馈 -> 结果”，不能只写机位、景别或“展示某物”。单镜超过 `1.5` 秒时，至少写出主动作的二级变化或反馈；超过 `2` 秒时，必须写成至少三个连续事件组成的小过程。若只能写出一个动词，例如旋开、探入、涂抹、拉远、停住，优先补齐动作起点、运动路径、接触点和结果；只有观看任务确实变化时才拆镜。`转场/尾态` 必须写清当前镜头留下什么可被下一镜头、内部四格创意线、可见四宫格或视频 Prompt 承接的动作、形状、声音、光线、遮挡、材质或构图锚点。
上一条中“超过 `0.8` 秒至少两个变化、超过 `1.2` 秒必须拆小过程”的旧阈值已经废止。当前标准为：超过 `1.5` 秒需要主动作的二级变化或反馈，超过 `2` 秒需要至少三个连续事件；优先补齐完整动作路径，只有观看任务变化时才拆镜。
- `镜头语言` 必须让相邻镜头的观看关系发生变化，至少改变景别、机位高度、拍摄角度、视角来源、主运镜、前后景遮挡、构图轴线或镜头进入/离开方式中的一项。默认不能连续使用同一类“固定机位特写/微距/产品中近景/慢推”超过两镜；若连续使用，必须说明这是为了可读证明、品牌定版或物理连续性，并用动作切、遮挡切、声音桥或形状匹配制造明确切点。镜头多变服务信息和节奏，不是随机换角度；只换景别但没有新信息或新反馈仍不合格。
- 从 `SH002` 开始，每一行都必须与上一镜组成一对可解释的镜间关系。上一镜的 `转场/尾态` 写“留下什么”；本镜的 `主体与场景/素材`、`画面动作` 或 `镜头语言` 必须明确写“如何接住”。至少继承动作、运动方向、主体位置、视线、构图形状、色彩/光线、声音、文字/图形、遮挡或产品状态中的一项。只写“硬切”“切近景”“切换场景”“转产品特写”不合格。
- 每次切镜必须有叙事理由：新动作开始、前一动作产生反馈、视线发现信息、功能进入下一步、人物/场景关系改变、情绪转折或章节结束。若只是为了增加镜头数、换角度、换景别或换一个漂亮画面，应合并、删除或改为镜内运动。镜头数下限不能作为无逻辑切镜的理由。
- 硬切不是默认转场。使用硬切时，必须在 `转场/尾态` 中同时写清“硬切承担的职责”和“前后共享的锚点”，例如“按压落点卡鼓点硬切，手掌位置与产品中心保持一致”；无共享锚点的硬切仅允许作为已完成段落之间的明确章节断点，并用声音桥、黑场标题或稳定落点标识分段。
- 连续动作镜头必须保护匹配剪辑：同一人物/手部身份、服装或袖口、道具、产品朝向、动作方向、握持方式、接触点和轴线不得无解释改变。产品从空到满、开到合、未佩戴到已佩戴、未连接到已连接等状态变化必须有可见触发和过程，或有已经建立的概念化转场规则。
- 人物、地点或功能模块发生切换时，前一镜必须建立切换动机，后一镜必须兑现关系。新增人物要通过同动作、视线、分屏、传递物、共同声音/文字规则或群像汇聚建立角色关系；新增场景要对应功能阶段、任务推进、时间变化或人物移动。不得把随机换模特、换房间、换户外地点当作视觉丰富。
- 景别按观看任务变化：全景/中景建立主体与空间，近景展示操作，特写确认细节，中景/全景回看结果。允许跨级跳切，但必须由动作切点、视线目标、同构图锚点、遮挡或声音重拍驱动。连续三个以上特写必须属于同一可跟随动作链，否则插入空间重建镜头或合并。
- 纯材质、纹理、光斑、参数、结构或环境微距必须能定位到具体主体或场景，并说明它证明、解释或推动什么。既不能由前镜进入、也不能由后镜拉回整体解释的孤立微距是废镜头，不得保留。
- 视觉高光、物体飞出、尺度变化、空间变形、人物惊讶或环境响应必须形成“铺垫/触发 -> 变化 -> 反馈 -> 结果停留”。高光不能突然发生，也不能刚出现就结束；若前镜没有触发、后镜没有反馈，它只是随机特效。
- 文字/图形出现必须与当前镜头中的对应动作、结果或声音同步，并在 `声音与文字` 写清触发点、落位、停留和退场。文字若承担转场，还必须在本镜 `转场/尾态` 和下一镜的承接描述中保持同一字形、位置、方向或运动逻辑；不能把文字只作为突然弹出的卖点标签。
- 镜长必须形成主次，不得整片机械等长。短过场、常规证明、核心结果、情绪停顿和 packshot 应按信息职责分配不同停留；连续同类镜头若没有“操作 -> 反馈”“整体 -> 局部”或“证明 -> 反应”的升级关系，第三镜起删除或合并。
- `声音与文字` 中存在可听语言时，必须先写明形式和主体，再逐句使用 `{}`，例如 `旁白：{完整原文}`、`口播（主播）：{完整原文}`、`人物对白（角色）：{完整原文}`；不得只写“有人声”“人物发声”“配旁白”或“加入解说”。无人声镜头直接写清画面文字、BGM、环境声和拟音，或明确写“无旁白/无台词”。
- `【】` 只用于用户明确要求模型直接生成在画面里的字幕；默认字幕、后期字幕和外挂字幕不写入该符号，也不能用 `【旁白原文】` 代替 `旁白：{旁白原文}`。是否需要旁白/口播/对白、文字是否只是语义占位、台词是否自然，属于 mainagent 的导演判断，不由脚本猜测。
- 单元格中需要竖线时写成 `／`，不得直接写未转义的 `|`。

### 按需片段执行与连续性说明

```markdown
## 片段执行与连续性说明

- SEG01 进入状态：
- SEG01 离开状态：
- SEG01 素材与声音承接：
```

只有长视频、多片段连续生成或复杂接缝需要额外说明时才填写本节。短片或表内 `转场/尾态` 已足够时可以省略。这里不重新创作镜头内容；若与完整分镜表冲突，以完整分镜表为准并先修正文档。

## 客观校验

完整分镜创建或修改后，mainagent 静默执行：

```bash
python3 scripts/validate_storyboard.py <完整分镜.md> \
  --expected-duration <秒数> \
  --min-shots <本条视频已确定的客观镜头下限> \
  [--max-shots <本条视频已确定的客观镜头上限>] \
  [--require-opening-cut] \
  --max-chars-per-second <按主 SKILL.md 选择 4 或 5> \
  --tail-duration <稳定尾帧实际时长；无静态尾帧传 0> \
  --max-tail-duration <普通短片使用 1.0；明确长尾帧时传已确认时长>
```

脚本不判断“这是什么类型的视频”，只接收 mainagent 根据本文件已经确定的客观约束：常规 15 秒视频传 `--min-shots 8 --require-opening-cut`；General 简单动态任务按方案传实际镜头下限，不传 `--require-opening-cut`；照片动起来传 `--expected-duration 5`；真实一镜到底传 `--min-shots 1 --max-shots 1`，不传 `--require-opening-cut`。
