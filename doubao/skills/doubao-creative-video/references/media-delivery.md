# 媒体逐项直交与最终成片

## 适用范围与边界

本文件管理媒体逐项直交、最终成片与真实入口。生成后每个成功结果立即直交，再完成已定后期并交付最终成片；具体边界见[已定后期与交付](production-control.md#成片执行和交付)，不另设审片或自动修复。视频确认、工具路由、每批最多两项视频生成/模型编辑任务与异步委派保持不变。

本合同中的图片交付指生成或编辑的图片资产；CLI 的 HTML、画布及其预览截图继续按原有 CLI 协议执行，不适用本合同的媒体交付格式，不改变其执行策略。

生成与交付的主策略及创建 OrganizerAgent 时的 hint 三项要求统一见[生成与交付策略](../SKILL.md#生成与交付策略)；本文件维护媒体卡片格式、分工、取消、去重和失败恢复细则。阶段顺序与授权边界仍按各自合同执行。

## 交付分工与执行条件

视频由执行对应生成／生成式编辑任务的 OrganizerAgent 直接向用户交付，每个需要展示的片段或成片明确一名负责交付的 OrganizerAgent。mainagent 负责需求、规划、确认、委派、任务跟进、真实素材传递和状态记录，不代发视频卡片，不重复展示或转述 OrganizerAgent 已说明的执行结果；用户主动询问进度时，可根据真实记录简短回复。

图片由 mainagent 使用对应图片能力直接生成和交付，不委派 OrganizerAgent；图片的用户可见交付格式统一按本文件执行。纯后期、技术处理及 CLI 的执行分工也保持不变；后期或技术处理结果由其他执行方取得时，将真实输出内部传给该视频任务负责交付的 OrganizerAgent，由其立即交付，不重新执行处理。原始结果先交付、再完成已定后期并交付成片的时机保持不变。

视频任务已派发后，生成失败、阻塞、结果未明或无法继续，由执行该任务的 OrganizerAgent 根据真实情况直接简短说明，mainagent 仅记录，不重复转述。任务尚未派发、委派不可用或派发失败时，由 mainagent 说明真实阻塞。取消和修改要求的同步仍按多轮规则执行，不改变授权、取消处理或后续任务暂停条件。

mainagent 创建 OrganizerAgent 时，必须在 `hint` 中明确写入工具与全部已确认生成参数、本文件适用的 RichMediaCard 格式，以及全部成功产物立即交付、禁止反思校验和自动修复重生的约束；不能仅提供本文件链接。执行环境须能展示 OrganizerAgent 的用户回复并渲染 RichMediaCard；缺少展示能力时停止受影响交付并如实说明，不代发、不改用链接、不重新生成。

## RichMediaCard 交付规则

本规则适用于面向用户的视频和图片交付。无论由 mainagent、OrganizerAgent 还是其他 agent 执行交付，都必须使用正确的交付格式：一句简短产物说明 + 对应 RichMediaCard；不得因交付 agent、委派方式或回传路径不同而省略或改变该格式。格式规则不改变上文约定的视频交付主体与图片分工。工具成功返回的每个应交付视频或图片结果都必须按下述卡片格式交付；取消或明确拒收的结果按[交付例外](#取消与拒收例外)处理。真实短链只作为卡片的内部资源引用，不作为配文或链接栏展示。创意研究可展示来源网页链接和简短采用理由，但不包括视频或图片资源直链、下载链接，也不得替代生成结果交付。

- 内部回传不等于用户交付；agent 之间可传递真实资源引用，实际面向用户交付时必须遵守本规则。已交付状态须随回传或交接保留，同一结果不重复交付。`refs` 使用本次工具返回且当前卡片可消费的真实资源，不使用示例地址、占位文字或推测地址；卡片结构按宿主实际规范，不编造字段。
- 卡片表达式单独成行，不放入代码块、行内代码、引号或 Markdown 链接，不转义标签；禁止在卡片外输出视频或图片资源的裸 URL、Markdown 链接、下载链接栏或文件路径，也不以文字总结替代视频或图片卡片，不为发卡额外要求 `present_files`。
- 交付正文为一句简短的已完成视频或图片描述和对应 RichMediaCard。卡片紧贴对应说明出现。不要在卡片外输出视频短链、下载链接栏、生成参数清单、参考图数量或“Prompt 按原文传入”等执行说明；时长、比例、模型及已确认参数也不重新汇报。用户明确索取规格或排障信息时才按请求提供，仍不得在卡片外输出视频或图片资源 URL 或下载链接。描述概括主题或核心画面，不复述完整脚本或镜头清单。新生成用“已经为你生成……”；编辑或纯处理用“已经为你完成……”加实际改动，不将处理原片说成重新生成。按用户当前语言表达，不机械复述生成前的开场白。
- 片段配文标明片段序号，拼接成片说明其为完整视频，不把片段说成整片；每个成功结果仍立即逐项展示，再完成已定后期并展示最终成片，同一结果不重复发卡。
- 配文不附带“已核验无误”“音画流畅”“可正常播放”等未经核验的质量结论，不为撰写说明新增审片。默认不展示内部 Prompt、工具名、内部 ID、资源 ID、路径、任务 ID、检查命令、调用参数或日志；用户明确要求查看、排障或交接时按原有规则提供。
- 生成失败、阻塞或结果未明时，按上文交付分工由负责说明的 agent 根据真实结果或回传简短说明已知情况，不猜原因，不声称已生成，不发空卡片或假卡片。已输出标签但未获得展示反馈时，不将其记为展示成功，也不据此重复发卡；明确展示失败时按[交付失败恢复](#交付失败恢复)处理。

禁止反思校验指不对生成内容进行审片、评分或自动返修；查询真实任务状态、确认资源入口可用，以及执行已定续接或后期所需的技术读取不属于质量验收，不能借此寻找缺陷。禁止重新生成指 OrganizerAgent 不得在当前任务中自行重试或重生；用户明确要求修改或重做时，仍由 mainagent 按原有 `interaction.ask` 策略重新确认，再派发新任务。

“全部产物”包括该视频任务的全部成功生成／编辑候选、片段及最终成片；内部 Prompt、日志、临时抽帧和未要求的后期中间文件仍按原有留档规则处理，不因本策略额外展示。

## 取消与拒收例外

取消对象、宿主通信与真实取消结果按[多轮取消规则](multi-turn-handling.md#取消生成)处理。真实取消成功后不再制作或交付该任务；用户明确说“不需要结果／不要发”时，即使不能取消在途任务或后来返回成功，也仅内部保留真实结果与状态，不自动发卡、不恢复后续制作。仅要求停止尚未提交部分、并要求保留或交付已有结果时，按明确范围处理，其他任务照常。

本文件及其他合同的“每个成功结果立即交付”“全部直交后继续”等均只针对仍需交付且未被取消的结果。拒收项记录为“按用户要求不交付”，不标记为 delivered、不补卡、不作为展示失败恢复；不要求为满足交付条件而展示拒收结果，也不把拒收解释为允许继续后续制作。已成功交付的结果不重复发送。技术状态仍按真实回传保存，不把取消请求当作工具已停止。

## 交付失败恢复

某项结果缺少可用入口或展示失败时，保留真实结果与错误，只恢复该项卡片交付操作，不降级为 URL 链接交付；依赖其成功交付的后续步骤暂停，其他无依赖且已授权的任务可继续。不猜测 URL、不假称已交付，不为补交付重新生成或重复创建媒体对象。工具失败不伪造成功产物。视频卡片明确展示失败时，mainagent 通过宿主通信通知原负责交付的 OrganizerAgent，由其使用同一真实结果恢复展示；无法恢复时由其简短说明交付失败。图片由原交付方恢复展示，不改变图片分工。恢复仍按生产控制技术重试上限，不循环重试。

## 完成判据与批次

分别记录生成结果可用、各结果直交、已定后期、最终成片交付状态，不建立视频验收状态。每项应交付的 RichMediaCard 展示成功才将该项记为 `delivery_status=delivered`；片段已交付不等于整片已交付。原始结果直接作为最终成片时，共用同一次交付记录并注明采用关系，不为切换状态重复展示。保留任务 ID、原始短链/图片引用、用途、版本、所属成片/片段/批次与最终采用关系。

以上状态和真实结果可合入生产控制规定的[制作记录](production-control.md#最少留什么何时拆分记录)，不要求分别建立交付清单、状态文件和归档日志；已登记的同一入口或参数直接引用，不重复抄写。

后段依赖前段时，以前段真实任务成功、应交付结果已直交及计划所需接续输入可取得为继续条件，并核对后段未取消、未暂停且仍有有效授权；不增加内容审查、不等待用户审阅反馈。互不依赖的任务可在已确认批次内并行，成功一项就交一项。本批执行结束且全部应交付成功结果直交后，未被取消或暂停的后续任务才按交互合同确认下一批；不先追加“是否继续”，不因展示片段突破每批两项上限。
