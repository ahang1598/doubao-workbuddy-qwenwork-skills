# 全流程生产控制

## Mobile 前置例外（最高优先级）

在能力预检、Workspace 绑定、Brief 存储或任何生成／编辑前，先检查 system 是否明确包含 `Device platfrom:Mobile`。命中则禁止全部 Canvas CLI／Workspace 操作，包括 CLI 探测、画布查询／创建／绑定／复用、Brief 存储、目录整理、写入、更新、回读及画布卡片／ID 交付；已有画布 ID 也不得用于上述画布操作；若对话已有唯一有效 ID，仅按主 `SKILL.md` 的视频工具传参规则作为调用上下文透传，不查询、创建、绑定、复用或写入 Workspace。mainagent 仅通过 `present_files` 直接交付视频，不执行画布分支，不以画布能力缺失阻塞生成。本文件下方全部画布相关要求仅适用于非 Mobile 环境。确认与异步生成规则不变；以主 Skill 的 Mobile 路由为准。


## 文件说明与索引

本文件是跨阶段生产控制索引，只处理完整链路、阶段授权、来源事实、真实资产、项目沙箱、阶段展示、工具、成片交付和平台版本。视频方案、素材询问、视频生成确认和片段继续确认读取 `references/interaction-ask-video-clarification-ref.md`；完整分镜格式与客观校验读取 `references/storyboard-contract.md`；图片／视频工具直接交付与产后目录整理读取 [媒体直接交付与产后目录整理](media-delivery.md)；Design CLI、Canvas Workspace、手工资产登记与目录命令读取 `references/cli/README.md` 与相关命令页。创意规划、分镜、关键帧和视频 prompt 阶段读取对应矩阵与 `SKILL.md` 命中的唯一类型文件；成片、拼接、字幕封装、平台导出和最终交付阶段不重新选择核心表达、主玩法或叙事骨架，默认只按本文件执行。本文件按“主链路 + 横切规则”组织，避免把辅助规则误读成独立阶段：

1. 主链路：规划 -> 按需人物/产品/音色资产 -> 分镜脚本 -> 视觉关键帧 -> 视频片段 -> 成片；短片直出跳过独立资产和可见视觉关键帧图片，改为在分镜与 Prompt 编译之间创建内部创意规划，普通短片使用四格创意线，General 简单动态任务使用轻量运动线。完整链路必须进入可见视觉关键帧阶段并完成确认后，才进入视频片段生成。独立脚本只在用户要求先审文字，或口播、旁白、对白、事实声明复杂到需要单独确认时插入。
2. 每个阶段都应用：阶段确认、阶段上屏与用户可见产物、来源事实、真实资产门槛、项目沙箱、版本记录和上游失效。
3. 分镜、关键帧、长视频、接缝、工具、MediaKit、音轨字幕和成片交付处理是对应阶段的细化规则，不是额外插入的主流程阶段。
4. 默认禁止返修。已生成视频按结果直接交付；用户后续要求改动时，按新版本或新任务重新走确认和生成，不使用“返修”作为默认阶段。

不要在类型策略文件或入口文件里维护第二套全流程规则；类型文件只补充本类型创作策略，入口文件只保留类型选择、默认参数、格式和对外沟通硬门。

## 完整链路与阶段确认

内部模式名、流程模式和阶段合并方式只用于执行选择；参数确认、进度说明和交付说明不得点名这些内部模式，也不得展示阶段编号、内部字段、reference 名称或执行链。

参数确认是后续制作的创作母版。按需人物/产品/音色资产、分镜脚本、可选独立脚本、短片内部创意规划、四宫格视觉关键帧、视频 Prompt、生成批次、成片和新版本都必须继承已确认的主线、叙事节奏、核心信息、素材职责、声音策略、平台目标、模型、比例、时长和数量；允许把已确认方向细化成更具体的镜头、台词、动作、声音和 Prompt，不得在后续阶段悄悄换成另一条创意路线。需要改变母版方向时，先回到参数确认。参数方案按 `references/interaction-ask-video-clarification-ref.md` 直接拟定并完整展示；随后调用 `interaction.ask`。短片直出的该确认即本次实际视频生成授权；完整链路的该确认是前置制作授权，不属于确认 ref 所称的视频生成确认或继续执行确认。本文件只规定阶段时机、问题语义和授权范围，不重复维护工具 schema。

短片直出使用一次封闭式单选，问题只表达“是否按以上参数开始生成？”，选项只允许“按要求生成／暂不生成”。正向选项授权本轮创建或复用画布、静默创建完整分镜、建立内部创意规划、编译最终 Prompt、委派视频生成、透传 Workspace ID 关联画布和视频直接交付；普通短片使用内部四格创意线，General 简单动态任务只使用轻量运动线。不生成独立人物/产品/音色资产，不生成或展示四宫格视觉关键帧图片。内部准备若发现必须改变已确认的模型、时长、比例、数量、素材职责、主线、镜头结构、声音或事实声明，必须停止并回到参数确认，不得借原确认继续生成。完整链路的前置制作授权使用一次封闭式单选，问题只表达“是否按以上方案进入制作？”，选项只允许“确认方案并开始制作／暂不制作”。正向选项说明本轮会创建或复用画布、生成参数方案中已明确列出且命中条件的按需人物/产品/音色资产、整理完整分镜，并生成可见视觉关键帧；不得复用短片直出的“按要求生成”语义，且不得触发视频 subagent。未在参数方案中列明的资产不在授权范围内。

先按模型和时长选择链路。短片直出只适用于 `seedance 2.0 mini/fast/2.0` 单条总时长不超过 15 秒，或 `seedance 2.5` 单条总时长不超过 30 秒的单条短视频。短片直出固定链路为：规划 -> 普通文本完整参数确认（含用户可见简版生成走向/分镜表）-> 调用 `interaction.ask` 确认“按要求生成”并开启或复用画布 -> mainagent 按 `references/storyboard-contract.md` 静默创建并保存完整分镜 Markdown -> 静默运行 `scripts/validate_storyboard.py` -> 按 `references/asset-generation.md` 建立内部创意规划 -> 从校验通过的完整分镜和内部创意规划编译最终 Prompt 与执行包 -> 委派 subagent 生成 -> 视频工具透传 Workspace ID 关联画布并逐项直接交付 -> 非 Mobile 产后目录整理。普通短片的内部创意规划是四格创意线；General 简单动态任务是一条轻量运动线，不得反向扩成四个强创意状态。短片这一次确认同时授权内部准备和实际视频生成，不再展示第二次视频生成参数或再次调用 `interaction.ask`，除非内部准备发现必须改变已确认方案。短片不向用户展示或交付内部完整分镜，也默认不生成、不展示四宫格视觉关键帧图片；视频 Prompt 必须继承对应内部规划的主体状态、动作关系、职责和动态把手，但不得把不存在的内部格位写成 `<图片X-第N格>` 或伪造成真实输入素材。短片只减少中间产物展示，不省略内部创作判断、完整分镜落盘、客观校验、实际视频生成确认和交付处理；用户确认简表、内部完整分镜、内部创意规划和最终视频 Prompt 必须共享 `Bxx -> SHxxx -> SEGxx` 映射。

短片直出和压缩链路最容易出现“有创意但没表达”的问题，因此最终视频 prompt 必须仍按秒段写清每段职责：需要执行黄金三秒切镜规则的视频说明 0-3 秒如何停滑并给价值承诺、中段如何证明或升级、尾段如何回收产品/品牌/主题；General 简单动态任务说明首秒如何启动运动、主体动作如何引发环境或细节响应、最后如何落定或回环；真实一镜到底说明人物与摄影机如何沿连续空间路线推进。任何动效、转场、强风格、数据卡、UI motion、声音桥或文案策略都必须落到具体时间段，写清触发动作、可见变化、声音节点、落点和停留；不能在 prompt 末尾笼统追加“加入动画效果/高级转场/品牌化动效”。

完整链路用于超过上述单条时长、长视频、需要分段连续生成，或用户明确要求逐阶段查看/中间产物的项目。多条独立视频或多平台重生版本按每条视频分别判断时长；单条仍在上述时长内且未要求中间产物时走短片链路。完整链路固定为：规划/完整参数确认并完成执行确认 -> 初始化或复用画布 -> 按条件生成并确认人物/产品/音色资产 -> 创建并客观校验完整分镜 Markdown -> 直接交付分镜文件供用户确认，不写画布 -> 生成视觉关键帧，调用时透传 Workspace ID 关联画布并逐张直接交付、按批次整理目录和确认 -> 每批视频生成前完整但简洁的批次参数确认 -> 委派 subagent 一次最多生成 2 个视频或片段 -> 视频工具透传 Workspace ID 关联画布，生成一个直接交付一个，本批直交后非 Mobile 再整理目录 -> 循环下一批；最后一批展示后按确认 ref 确认是否进入成片拼接；确认进入拼接后，成片阶段直接交付。完整链路必须生成可见视觉关键帧：少于 30 秒生成 1 张四宫格，30-59 秒生成 2 张，60 秒生成 3 张，之后每多 30 秒增加 1 张，统一按 `1 + floor(总时长秒数 / 30)` 计算。每张视觉关键帧都必须同时读取视觉发动机库与视听工艺库，把创意玩法、视觉效果、构图、配色、字体排版、光线、材质和动态把手真实画出来；它不默认等于真实首帧或尾帧，真实片段接缝仍优先使用上一段视频抽取的真实尾帧。

完整链路的画布初始化发生在规划参数按本节完成前置制作确认后、进入按需一致性资产或分镜产物展示前；不得在该确认前创建画布。视频生成确认仍只在每批实际生成前执行，前置制作确认不能替代批次生成确认。

| 主阶段 | 产物职责 | 进入下一阶段前必须确认 |
|---|---|---|
| 规划 | 参数确认、创作方向、叙事结构摘要、视觉记忆点、素材需求、目标/平台/模型/时长/比例/数量/字幕策略 | 规划参数必须普通文本完整展示，并按本节定义调用 `interaction.ask`；短片直出确认后可创建或复用画布并直接进入内部准备和视频生成，完整链路确认后才可创建或复用画布并进入前置制作，且后续视频片段仍需逐批完成实际视频生成确认 |
| 按需一致性资产 | 完整模式仅在人物跨片段反复/长时间出现、缺少必须保持的产品素材、或同一口播音色需跨视频/片段统一时，分别生成人物、产品、音色资产；场景、Logo、道具、UI 和风格只使用用户素材，不默认生成 | 用户确认本次确需生成的人物、产品或音色资产；没有条件命中则跳过 |
| 分镜脚本 | 按 `references/storyboard-contract.md` 创建完整分镜 Markdown，静默通过客观校验后直接交付文件，不写入画布 | 用户确认创意、镜头、动作、声音、文字和素材引用 |
| 视觉关键帧 | 完整链路必须完整读取 `references/visual-motion-playbook.md` 与 `references/audiovisual-craft.md` 后，按 `references/asset-generation.md` 的数量与分镜格位规格生成四宫格，调用时透传 Workspace ID 关联画布并逐张直接交付；非 Mobile 本批直交后再整理目录；每格可独立裁出，登记来源和片段映射。短片直出只创建对应内部创意规划，不进入本可见图片阶段 | 用户逐张确认创意玩法、视觉效果、构图、配色、字体排版、光线、材质、动态把手和片段输入；关键帧确认使用普通聊天，不调用 `interaction.ask`；短片内部创意规划不向用户展示确认 |
| 视频片段 | 分批生成结果、承接关系、转场、尾态和字幕处理；完整链路每批最多 2 个视频或片段，调用时透传 Workspace ID 关联画布并逐项直接交付，非 Mobile 本批直交后再整理目录；短片直出为单条生成结果 | 完整链路每批生成前普通文本完整但简洁展示本批参数列表和本批分镜表；参数列表包含任务类型、交付格式、模型、数量、逐段及总时长、比例、核心故事线或内容、视觉方向、身份保持、输入素材及继承的资产/分镜/可见关键帧或内部四格创意线、台词/字幕/配音/音乐；镜头动作、逐段内容、声音节点和钩子落到分镜表；随后调用 `interaction.ask`。短片直出的同等参数已在规划参数确认中完成，不再二次展示 |
| 成片 | 拼接、音频、按需字幕/花字、平台版本和最终交付 | 用户已确认进入成片拼接后，直接交付成片；不设置默认返修确认 |

独立脚本阶段不是默认主阶段。只有用户明确要求先看脚本，或口播、旁白、对白、法律/功效/客户案例/企业事实声明复杂到必须先锁文字时，才在按需一致性资产前后插入独立脚本确认；否则把叙事结构、台词、旁白、广告语、声音策略和文案策略合并到分镜脚本文件中确认。

完整链路中实际产生的按需人物/产品/音色资产、分镜脚本、视觉关键帧、视频片段和最终成片必须逐阶段展示并等待确认；未命中按需资产门时直接跳过，不用策略说明伪造阶段产物。完整链路的前置制作授权、任何实际视频生成、视频编辑、图生视频、视频片段生成后继续下一批、最后一批后进入成片拼接的确认，都必须使用 `interaction.ask`，且工具可用时必须使用；其他阶段产物确认可以用普通聊天完成。视觉关键帧确认属于阶段产物确认：用户查看已交付四宫格后用普通聊天确认即可，随后进入本批视频生成参数展示和 `interaction.ask` 授权。用户可见话术不得点名 `interaction.ask`、Canvas、`present_files`、画布 CLI 或具体工具命令。

每个实际执行阶段按同一事务推进：

1. 明确本阶段输入、已确认参数、素材职责和受影响范围。
2. 生成或整理用户可查看和确认的正式产物。
3. 做必要的可用性准备，确认产物能被用户查看或播放；不做交付前主观画面返修检查。
4. 按“阶段展示与用户可见产物”规则交付产物；正文只展示用户需要判断的摘要、文件用途和修改入口。完整脚本和完整链路分镜保存为文件后直接交付，不写入画布；短片直出的完整分镜、Prompt、内部检查材料、日志和状态记录默认只内部留档。用户明确要求查看 Prompt、排查或交接时才直接交付对应文件，同时隐藏内部字段、日志、资源 ID、哈希、task id 和检查统计。
5. 等待用户确认阶段产物。对普通文本、脚本、分镜、资产职责和成片确认，`好`、`OK`、`嗯`、`可以` 只有紧跟最新确认内容且没有修改意见时才算阶段确认；对实际视频生成、视频编辑、图生视频、片段生成后继续下一批、最后一批后进入成片拼接，必须改用 `interaction.ask` 的本次确认。
6. 用户提出修改时，不进入默认返修；把修改作为新版本或新任务处理，重新展示受影响方案并按视频生成确认门执行。

视频生成确认门优先于所有阶段便利，并以 `references/interaction-ask-video-clarification-ref.md` 为准。判断标准是“下一步是否即将提交视频生成、视频编辑或图生视频”，不是“用户刚才修改的是文案、分镜、策略还是 prompt”：

- 已确认参数只授权当前这一次视频任务或当前批次；换任务、换版本、换比例、换时长、换模型、换素材职责、换镜头结构、换创作方向或事实声明变化，都必须重新普通文本展示完整方案，并重新调用 `interaction.ask` 后才能生成。
- 短片链路先展示完整参数和用户可见分镜简表，并通过 `interaction.ask` 一次性取得本次视频生成同意；随后静默完成详细分镜、客观校验和对应内部创意规划，直接编译 Prompt 并委派生成。普通短片继承内部格位的创意状态与动态把手；General 简单动态任务继承轻量运动线中的用户锁定项、主动作、因果次级运动、摄影机策略、声音和落点。短片的内部镜头规划仍按适用规则展开，不单独展示完整详细分镜；最终 Prompt 按 `references/asset-generation.md` 的五段式和真实输入合同编译，但不虚构图片输入。内部准备如果导致已确认方案发生实质变化，必须回到参数确认。
- 完整链路的规划参数确认必须调用第一次 `interaction.ask` 完成前置制作确认，确认后才可创建或复用画布并进入资产、分镜和四宫格视觉关键帧制作；它不能替代视频片段生成前的批次视频生成确认。每批视频或片段生成前都必须普通文本完整展示本批参数列表和本批分镜表，并基于已确认资产、分镜和已确认可见格位做简洁复述；参数列表必须覆盖任务类型、交付格式、模型、数量、逐段及总时长、比例、本批核心故事线或内容、视觉方向、身份保持、台词／字幕／配音／音乐、输入素材及继承关系；分镜表必须覆盖逐段内容、镜头与动作、声音节点、衔接和钩子。展示后再按确认 ref 调用第二次 `interaction.ask` 取得本次明确视频生成同意。第一批片段也必须确认。
- 每次实际生成前必须普通文本完整展示本次生成所需参数；不得只展示模型、时长、比例、数量四项，也不得引用历史确认。
- 本批生成完成后，必须先展示本批片段，并立即调用 `interaction.ask` 确认用户是否继续。若还有后续片段，工具问题只确认“继续下一批片段”或“暂不继续”，用户同意后再展示下一批参数澄清/确认并再次用 `interaction.ask` 确认生成。若这是最后一批，必须先把全部已生成片段或片段清单展示给用户，再立即调用 `interaction.ask` 确认“进入成片拼接”或“暂不拼接”；普通聊天不能替代该确认。不得在最后一批片段生成后自主拼接成完整视频。
- 首次生成已经提交后，任何对已生成视频本体的调整、视频编辑、修改重生、新视频、追加变体，或需要重新生成视频的平台版本，都必须重新展示本次调整参数并执行该确认门。只做裁剪、封装、字幕烧录或平台导出且不调用视频生成/编辑能力时，按成片/平台版本确认，不重复视频生成确认。
- 用户要求修改文案、分镜、策略或 prompt 时，可以先修改对应文本产物；但只要下一步要提交视频生成、视频编辑、图生视频，或把修改落实为已生成视频本体的调整，就必须重新展示方案并用 `interaction.ask` 确认，得到确认后才可生成或调整视频。
- 上一个视频还在生成中时，不得未经用户明确要求再提交新视频。用户没有明确要求多个视频时，只回复“上一个视频正在生成中，请耐心等待结果出来后再调整”。用户只是在抱怨、纠正、表达情绪或质疑时，只做礼貌回应并询问修改方向；不要触发生成，也不要进入参数确认。

## 来源与事实锁

将输入按以下状态处理：

| 状态 | 含义 | 使用规则 |
|---|---|---|
| `locked` | 用户明确要求、禁用项、原台词、指定产品或素材职责 | 未经用户确认不得改写或替换 |
| `verified` | 用户材料、可靠来源或实际素材已核实 | 记录来源、日期和适用范围 |
| `pending` | 会影响真实性、合规、成本、权限或交付的未知项 | 不能写成确定事实；优先用可修改假设、概念化表达或技术阻塞说明推进 |
| `assumed` | 为继续规划采用的默认判断 | 在参数确认中说明，允许用户修改 |
| `convention` | 本 skill 的默认惯例，如默认模型、默认无字幕、默认比例推断 | 不等于用户设定，用户可覆盖 |

冲突优先级：系统、安全、合规、授权、真实性和工具硬限制 > 用户本轮最新明确确认 > 产品、人物、企业或品牌身份与已确认素材 > 客户授权和已核实知识 > 台词/旁白 > 平台规范 > 品牌调性 > 场景 > 风格 > 音频。用户要求与第一层硬限制冲突时立即停止受影响步骤，只说明阻塞或提供不改变核心意图的降级方案，取得用户确认前不得执行；不存在硬冲突时，用户最新明确确认高于全部默认策略。

涉及真实品牌、公司、产品、人物、地点、赛事、节日、热点、平台规则、功效声明、客户案例、数据、奖项或资质时，生成或写成确定声明前必须核实可靠来源，或要求用户提供材料。缺失资料不阻止创意规划，但只能作为可修改假设标明；真实外观、事实声明、客户授权和功效承诺未确认前不得进入生成输入或确定文案。

## 真实资产门槛

素材按职责分类，而不是按文件格式简单分类：

- 视觉资产：产品图、人物图、品牌 VI、场景图、道具图、风格图、视觉关键帧和真实视频抽帧。只有这类素材能锁外观、构图、材质、空间、姿态、状态或风格；首帧/尾帧默认来自真实视频抽帧，不默认提前生成。
- 文本来源：文档、截图 OCR、表格、聊天记录、用户指令、脚本图。只能抽取文字、事实和格式偏好，不能作为视觉参考。
- 音频资产：配音、音色、BGM、环境声或节奏参考。必须说明是声音身份、情绪、节奏还是成片音轨。
- 视频资产：参考视频、已有素材、上一段成片或待编辑视频。必须拆解用途：结构、节奏、镜头语言、动作、主体身份、场景或可直接编辑的源视频。

参考视频、动效样片或外部案例不能整体套用。内部先做 motion breakdown：逐段提炼手法、节奏、转场锚点、画面层级、动效性格、声音句式和可迁移关系；再改写到当前主体、真实素材、事实边界和类型策略里。参考片描述的是某一类镜头或动效的感觉，不自动成为全片风格；信息密集、真实 UI、口播可信、企业事实和敏感行业场景必须按当前可读性和真实边界重写。

下游使用前必须满足：文件真实可访问、格式可用、职责明确、用户已上传或已确认采用、必要时已保存到项目素材区或当前宿主可访问位置。未落盘、打不开、未确认、未登记职责或只存在于计划中的资源不得进入 prompt 输入清单。

### 全链路视觉身份锁

所有生成阶段执行 `references/asset-generation.md` 的真实输入与身份锁：用户采用素材或首个确认标准资产是唯一事实源，每次调用重新传入，不以文字替代。需要更换身份或外观时，先确认新版本，再使依赖旧版本的下游失效；跨四宫格和跨片段同时继承主体身份与剧情状态。

所有生成或采用的视觉、音频和视频资产都必须落盘到项目沙箱对应层级。用户上传原件或外部参考应保留原始副本和采用/剥离说明；凡实际提交生图、图片编辑、生视频、图生视频或视频编辑，必须在调用前把实际使用的完整 Prompt 原文静默保存到对应阶段目录，并记录版本和职责。Prompt 默认不展示、不交付、不写入画布；用户明确要求查看、排查或交接时才直接交付对应文件。文本来源和截图 OCR 只能保存为文本或证据材料，不得因其是图片文件就进入视觉参考输入。

参考优先级、采用/剥离边界、图片与视频输入编号和 Prompt 正文要求统一按资产生成合同执行；本文件只登记真实文件、确认状态和上下游依赖。

## 按需一致性资产门

短片直出不生成独立一致性资产，也不默认生成可见视觉关键帧图片；只消费用户已有素材，并用对应内部创意规划约束最终视频 Prompt。用户明确要求单独生成某项资产或关键帧/概念图时例外。完整模式也不是默认全套生资产，只允许以下三类：

资产选择门：

- `CHRxxx` 人物：同一人物会跨多个片段反复或长时间出现，且缺少可用、已确认的人物参考。
- `PRODxxx` 产品：全片必须保持同一产品，但用户没有可用产品素材，需要先生成并确认唯一外观。
- `VOICExxx` 音色：同一口播者、旁白或角色需要跨多个视频或片段保持声音一致，且真实能力可生成或消费该音色。

该选择门优先于全部类型文件；类型文件只能补充素材关注点，不得自行插入资产阶段或扩大生成条件。UGC 类型文件中“没有人物图时生成创作者”等旧建议，仅在完整模式命中 `CHRxxx` 人物资产门，或用户明确要求单独人物资产时生效；短片直出不得据此自动生成人物标准图，无素材概念创作者只在内部四格创意线与视频 Prompt 中作为概念角色建立，且不得冒充真实达人。

场景、Logo、包装、品牌、道具、UI、风格、BGM、环境声和拟音可以登记为用户素材或表达要求，但不建立默认生成阶段，不生成 `SCNxxx`、`BRANDxxx`、`PROPxxx`、`STYLExxx` 等独立资产。已有真实素材直接按职责传入可见视觉关键帧与视频；短片直出没有可见关键帧时，由完整分镜、对应内部创意规划和最终视频 Prompt 建立当前画面；完整链路没有素材时，由视觉关键帧按分镜建立当前画面，不额外先做场景四视图或风格图。

人物设定图、产品标准图、音色样本与全部 Prompt 细节统一读取 `references/asset-generation.md`。确实生成的人物或产品图调用时透传 Workspace ID 关联画布，生成一个就直接交付一个，非 Mobile 本批直交后再整理目录；音色文件生成一个就直接交付一个，不写入画布。没有选择门命中时直接跳过本阶段。后续分镜、视觉关键帧和视频只能引用已确认资产或本轮明确确认采用的用户素材。

## 项目沙箱与目录存储

每个视频项目必须建立可恢复的项目沙箱。沙箱用于隔离用户素材、阶段产物、Prompt 文件、视频片段、抽帧和成片，不把正式交付散落在聊天临时文件、下载缓存或未登记路径里。目录命名可以按宿主和项目习惯调整，但必须具备以下分级职责：

通用 video 的存储架构与 drama 的项目级结构保持同一思想：项目控制、共享资产、单条视频执行产物、Prompt、视频片段、抽帧和成片都分层保存；区别只是 video 不建立 `episodes/ep_N/`，而是用 `videos/video_N/` 表示第 N 条完整视频或第 N 个平台/变体交付单元。长视频拆段仍属于同一个 `video_N`，不是分集，也不是多条独立视频。

| 层级 | 责任 |
|---|---|
| 制作控制 | 参数确认快照、来源清单、版本记录、用户确认记录、操作日志、平台适配记录 |
| 脚本 | 口播、旁白、对白、广告语、脚本修订稿和台词来源 |
| 资产 | 用户素材副本、按需人物资产、按需产品资产、按需音色资产和素材职责说明；场景、Logo、包装、道具、UI、风格和音频参考仅作为用户素材登记 |
| 分镜 | 用户可读分镜、镜头级详细分镜、片段拆分和接缝计划 |
| 关键帧 | 完整链路或用户明确要求时保存四宫格视觉关键帧、格位映射和关键图 Prompt 文件；完整链路按 `1 + floor(总时长秒数 / 30)` 计算。短片直出默认不产生图片关键帧，可在分镜或 Prompt 目录保存对应内部创意规划与映射 |
| 视频片段 | 每段视频、片段 Prompt 文件、上一段尾帧抽帧和必要接缝记录 |
| 成片 | 无字幕版本、用户要求时的字幕版本、平台版本、字幕文件、封面、最终交付清单 |

用户没有要求多条、多版本或多平台版本时，默认只有 `video_1` 或等价的单一交付单元；长视频拆段仍属于同一个完整视频，不建立多个独立视频项目。多条独立视频、A/B 变体或多平台版本需要分别建立清晰的子目录或交付单元，并共享已确认且未失效的素材池。

正式产物必须使用稳定名称和版本后缀，避免 `final`、`new`、`最新版` 这类无法追溯的命名。已确认文件不得覆盖；修改生成新版本，并让实际依赖旧版本的下游失效。临时文件、上传裁剪副本、失败候选和内部检查材料必须与用户可见正式产物分开，不得冒充已验收素材。

下游只能引用项目沙箱内真实可访问、职责明确、已保存、已验收或已确认采用的文件。Prompt 文件是正式内部留档：凡真实生成图片、关键图、视频片段或成片所用的 Prompt，都必须保存完整原文，用于复现和排查；默认不随对应媒体展示给用户。用户明确要求看 Prompt、排查问题或交接给其他系统时，只通过 `present_files` 直接交付对应 Prompt 文件，不执行画布写入或回读。聊天正文默认不粘贴完整 Prompt，用户侧不点名内部交付工具。

内部状态、来源清单、用户确认记录、操作日志和版本记录默认保存在 `00_制作控制/`。这些文件只用于恢复和追溯，不作为用户可见交付；用户询问进度时只说自然制作动作，不展示状态字段、JSON、哈希、日志或内部路径。

### 统一地址、目录和命名

## 阶段展示与用户可见产物

本节说的“展示/可见产物”是阶段确认时给用户查看的产物交付，不等于最终成片交付。最终成片、字幕版、平台版本和封装文件的交付规则在“成片执行和交付”中处理。

所有用户可见产物都使用 `present_files` 提供正式入口。视频／图像生成与编辑工具输出通过 Workspace ID 关联画布，直接交付后再整理真实对象的目录；不重复创建媒体 Item，不把画布回读当成交付前置条件。音频、文档、字幕文件、完整链路分镜和用户明确要求查看的 Prompt 文件只直接交付，不写入画布。纯文字参数确认、脚本摘要、资产职责说明和分镜摘要可以直接在聊天中展示；完整脚本、口播稿、旁白稿和完整链路分镜应保存为文件并直接交付。短片直出的完整分镜与默认 Prompt 文件只静默留档，不展示。

用户可见输出只包括：视频生成参数确认、允许的素材询问、技术阻塞说明、脚本/口播/旁白摘要和文件入口、按需人物/产品/音色资产规划和素材职责、分镜摘要和文件入口、视觉关键帧、片段结果、完整视频、用户上传素材的自然职责说明，例如“这张产品图锁定包装和 logo”“这张图只参考风格，不采用文字和水印”。Prompt 文件入口只在用户明确要求时出现。

默认不展示：内部字段、JSON、哈希、资源 ID、task id、工具名、路由名、命令、prompt 编译过程、批次文件、校验统计、台词字数/每秒字数计算、ASR 明细、字幕检查明细、日志、内部路径、自动检查细节、合规证明、抽帧过程、逐帧画面分析、参数规格复述和“已完成检查/审查/校验”类说明。用户明确要求看 prompt、排查问题或交接给其他系统时，可以提供去内部化后的“可复制的视频提示词”或问题摘要。

阶段展示顺序固定为“简短自然说明 -> 对应媒体或文件入口”。说明只写用户能理解的内容，例如“产品图 1：锁定包装和 logo”“视频片段 2：展示功能演示段”，不要写内部 ID、资源 ID、路径、任务号、检查命令或工具字段。对应文件必须紧贴说明出现；任何类别都是生成或准备好一个就交付一个，不能先堆一串说明、最后再集中发文件。

同一类别从 `1` 开始独立编号，不同类别互不串号。默认生成类别只包括：按需人物图 1-N、按需产品图 1-N、按需音色试听 1-N、视觉关键帧 1-N、视频片段 1-N、成片版本 1-N；用户上传的场景、Logo、道具、UI、风格和音频只作为来源素材展示，不列为生成类别。Prompt 文件只在用户明确要求时单独编号。编号是用户阅读顺序，不替代内部稳定 ID。

凡调用生图、图片编辑、生视频、视频编辑或图生视频工具得到成功图片或视频结果，必须生成一个就由 mainagent 直接交付一个；调用时透传 Workspace ID 关联画布，不重复创建 IMAGE／VIDEO Item，不等多个产物完成后集中交付。音频、文档、字幕和其他用户可见文件也必须准备好一个就直接交付一个，但不写入画布。媒体条目默认只展示资产、片段或成片本体及必要职责说明，不贴 Prompt 文件入口。用户明确要求查看、排查或交接 Prompt 时，只直接交付对应文件，不在聊天正文粘贴完整 Prompt，也不写入画布；用户明确索要可复制 Prompt 时，必须去掉内部字段、资源 ID、任务号、机器日志和不可行动检查细节。

图片将工具返回的原始结果对象单项交给 `present_files`，以可渲染资源展示；视频将工具原始视频短链单项传给 `present_files`；音频优先传入可播放资源本体；文档和用户明确要求查看的 Prompt 文件优先给可打开文件入口。单项 `present_files` 成功即记录媒体已交付；失败时保留真实状态并暂停依赖步骤，不以聊天正文、本地路径或临时 URL 代替。默认非 Mobile 环境的产后目录整理必须另行完成，目录失败不得把已经交付的结果改记为未交付或触发重复生成、交付、创建。生成／编辑工具原始结果不再额外执行 CLI 写入或交付前回读；非直接关联工具产出的本地剪辑／拼接／封装／导出等资产，按其产出协议及手工资产规则处理。

阶段首次确认必须先完整展示该阶段用户可见正式产物，再询问修改意见并停止执行。视频片段阶段可以在当前已确认批次内逐个即时预览，但每批最多 `2` 个；本批完成后必须再次确认下一批，不能用沉默或阶段确认代替批次确认。

## 分镜准出和镜头职责

短片直出和完整链路的完整分镜都必须遵守 `references/storyboard-contract.md`。创建或修改完整分镜后，mainagent 必须静默运行 `scripts/validate_storyboard.py`，并按主 `SKILL.md` 的已确认人声风格传入台词密度上限：快节奏营销、带货或强信息流为 `5`，品牌宣传、剧情化广告、企业宣传、抒情、诗性旁白或舒缓讲解为 `4`。mainagent 先按规则确定本条视频的客观镜头上下限和是否必须在前三秒切镜，再分别通过 `--min-shots`、按需 `--max-shots` 和按需 `--require-opening-cut` 交给脚本；照片动起来直接用 `--expected-duration 5`，真实一镜到底使用 `--min-shots 1 --max-shots 1`。15 秒及以内视频还必须用 `--tail-duration` 传入末镜动作完成后真正稳定定版的时长，没有静态尾帧时传 `0`。脚本只检查固定结构、时间轴、必填项、ID、台词密度和上述客观参数；第一镜超过 `1.2` 秒是否因镜内连续升级而成立，以及因果、相关性、重复语义、动作连续、转场质量、特效合理性和节奏审美，均由 mainagent 按规划、分镜和一次性 Prompt 预检规则判断。

分镜不是画面清单，而是高成本生成前的执行合同。每个镜头必须同时写清：镜头职责、绝对时间、主体、可见动作、景别、机位/角度、主运镜、声音/台词、素材引用、切入/切出动机和尾态。正式详细分镜必须连续覆盖完整视频，不能只给局部示例或方向摘要。除 General 简单动态任务和用户明确要求的真实一镜到底外，15 秒视频最低 `8` 镜，并按动作、证明、反应和节奏需要增加；其他时长按同等信息密度规划。General 简单动态任务允许一个或少量镜头，真实一镜到底必须只有一个镜头；两者都要在镜内写清连续动作与状态阶段。镜头下限用于防止长时间空转，不允许反过来拆断“拿起 -> 送到嘴边 -> 咬下”等完整动作。每镜必须有独立职责，多镜头时还必须有承接锚点和新增信息。

每个镜头至少承担一个明确职责：停滑钩子、产品证明、功能演示、包装/Logo/品牌资产记忆、人物反应、企业能力、客户价值、证据链、情绪转折、过门转场、CTA 收束或尾帧稳定。没有职责的空镜、慢推、氛围镜、抽象光效、随机人物表情或只展示“好看”的镜头必须删除、合并或改成有信息变化的镜头。短片直出的每个片段都禁止缓慢空镜；完整版也必须压低空镜比例，只有空间建立、证据消化、声音桥或情绪转折确实需要时才保留，并写清空镜内的可见变化和承接动作。

分镜完成后必须做一次品类同质化审计。主创意系统/主玩法不得等于当前品类最常见的第一联想；声音、光波、粒子、飞溅、水光、花瓣、烟雾、雪山、光轨、数据卡片等默认元素只能作为局部材料。审计时检查三件事：是否已经避开或转译默认套路；主创意系统是否由当前产品结构、品牌资产、人物动作、使用流程或卖点证据触发；同一系统是否在开场、中段和结尾形成建立、升级、回收，而不是一个孤立特效。多个相关创意节点可以成立，但必须共享同一触发、规则、证明目标或回收路径。任一项不成立，先改创意说明和完整分镜，再进入四格或视频 Prompt。

分镜完成后还必须做“匹配与贯穿审计”。逐一检查主创意系统、相关创意节点、辅助职责、每个高光镜头和文案句：它们分别来自用户哪条指令、哪项素材事实、哪个卖点/亮点、哪个目标人群或哪个平台语境；它们是否与产品/人物/场景处在同一条因果链；它们是否影响后续镜头或被后续镜头回收。若答案只能写成“增加创意感/提升高级感/丰富画面/制造视觉冲击”，说明该创意没有匹配实际任务，必须删除、改成产品证明，或回到创意阶段重选。

分镜完成后必须做逐镜信息增量审计。为每个镜头写一句“观众在这一镜第一次知道了什么”；答案必须是新的问题、产品身份、介入动作、证明、人物反应、场景结果、因果解释、品牌归属或行动信息。若答案与前一镜相同，或只是“换角度看同一主体”“动作继续一点”“环境更有氛围”，该镜头不合格，必须删除、合并或改写。相邻两个镜头不得同时是同一场景、同一主体、同一动作阶段且没有新结果；同一主体连续出现时，至少改变动作目标、空间关系、证据、反应或叙事压力。

分镜和视频 prompt 必须把用户可见粗时间段拆到可执行的镜头与动作事件。15 秒主动节奏视频通常规划 `8-12` 个有价值事件，但事件不等于切镜：手进入、拿起、送向目标、接触、反馈、人物反应、文字同步和结果落定都可在同一连续镜头内完成。只有观看关系、证据层级、空间阶段或情绪状态确实变化时才切镜。单镜超过 `2` 秒必须包含至少三个实质事件，并改变动作、观看关系和信息状态中的至少两项；不能只有主体姿态、慢推、渐大、发光或静态展示。每个事件都写清触发、变化、反馈和落点；语义变化不能冒充画面变化。

生成前必须做镜头关系审计：多镜头视频逐镜列出景别、机位高度、角度、视角来源、主运镜、前景/遮挡和切换动机；相邻镜头如果只是同一主体同一机位继续拍、同一微距继续拍、同一产品特写继续推，且没有新增信息或明确切点，该镜头必须改写。除 General 简单动态任务和用户明确要求的真实一镜到底外，15 秒及以内视频默认形成近景/极近景/俯拍/侧面/主观视角/产品英雄/环境反应等有职责的组合，但不为炫技乱切；每次机位变化都要服务停滑、证明、反应、转场、品牌回收或创意玩法演化。General 简单动态任务审计连续状态变化；真实一镜到底审计唯一镜头中的主体路线、摄影机路线、空间连续、动作节点和环境反馈。

生成前必须检查“动作桥完整度”：跨镜动作要在前镜显示动作发起与运动方向，在后镜从匹配位置、姿态和速度接续并完成接触或反馈。手拿物送向嘴边、手指从嘴边移向脸颊、拿起产品再放回桌面等空间位移，不能省略到让主体瞬移；可用中景连续动作、动作中切、遮挡切或匹配位置完成。若无法生成可靠连续动作，应减少切镜并在同一镜头完成，不得为了镜头多样强行拆开。

短片进入生成前必须通过压缩测试：分别尝试删除每个镜头和把总时长压缩约三分之一；若删除后主线、证明和品牌回收不受影响，该镜头就是填充镜头；若压缩后仍能完整表达，则采用更短时长。只有不同的剧情节点、证明节点、人物反应或场景结果确实需要时间时才保留较长版本。用户指定 15 秒时保留 15 秒总时长，但必须用新增事件填满，不得把一个 5 秒事件放慢三倍。

镜头节奏必须由动作、证明、反应、构图变化、声音、转场或信息递进推动；不能用无信息凝视、泛空镜、重复推拉、无来源光效或音乐煽情填时长。开头镜头尤其不能只平推、慢推、停看产品或长时间贴着一个物体；0-3 秒必须有停滑动作、冲突、结果预告、视觉异常、证明瞬间或声音钩子。品牌片、企业片和产品大片可以保留呼吸段，但呼吸段也必须承担品牌资产显影、空间建立、情绪转折、证据消化或声音桥功能。一个镜头内可以写多个连续可见动作，例如“拿起 -> 旋开 -> 液体倒出 -> 包装正面稳定露出 -> 人物反应”，用动作链提升信息密度，而不是拉长单一凝视。平推、慢推、横移或停留可以使用，但每次都必须绑定信息显影、动作完成、证据读秒、转场遮挡或情绪转折，并控制在必要时长内。

默认节奏处方：除 General 简单动态任务、用户明确要求的真实一镜到底，或用户明确要求舒缓、抒情、冥想、奢华慢片、品牌大片留白外，15 秒及以内视频按主动节奏处理。0-3 秒至少 `3` 个可见信息事件和 `1` 次有意义切镜/观看关系变化，且必须有异常、冲突、主动入场、声音触发或问题与证据并置；第一镜通常不超过 `1.2` 秒。General 简单动态任务不强制切镜，首秒启动可见运动，全片形成“启动 -> 发展 -> 落定/回环”；真实一镜到底不允许任何剪辑，前三秒通过主体目标、运动方向、环境变化或观看悬念建立推进。所有视频都先保证用户指定动作和路线完整，再补镜头、运镜、声音与反馈。存在普通静态尾帧时控制在 `0.6-1.0` 秒；Loop 或持续运动到结束的方案可以没有静态尾帧。只有复杂发布信息、活动日期或必须阅读的合规文字才可延长静态尾帧并写清阅读需求。用户反馈慢、拖、重复或跳切时，不得原 Prompt 重生；必须先删除重复画面、补齐动作桥、压缩无信息停留、移除无关插镜，并重写受影响分镜与 Prompt。

反慢不是增加镜头数量，而是让动作与状态持续推进。单段超过 `1.5` 秒必须包含主动作的二级变化或反馈，例如主体动作引发材质变化、环境响应、文字替换、声音重拍或结果显影；超过 `2` 秒必须形成至少三个连续事件。若只剩“打开/涂抹/拉远/展示/停留”，优先补齐进入路径、接触点和结果，不要先把它拆成多个孤立特写。

上段中“超过 `0.8` 秒不得只有一个动作、超过 `1.2` 秒必须有二级变化”的旧阈值已经废止。当前标准为：超过 `1.5` 秒需要主动作的二级变化或反馈，超过 `2` 秒需要至少三个连续事件；优先补齐进入路径、接触点和结果，不因反慢而拆出孤立特写。

分镜阶段必须提前规定下游输入计划：哪些用户产品图、人物图、Logo、场景图、风格图、视觉关键帧、上一段尾帧、视频或音频会进入当前片段；采用什么、剥离什么；哪些文字必须后期可控而不是交给视频模型随机生成。输入计划只作为内部执行依据，对用户展示时用自然语言说明素材职责，不展示资源 ID 或工具字段。只有人物、产品或音色命中按需一致性资产门时才回到资产阶段补齐；场景、品牌、道具和风格缺少独立素材时，由分镜与视觉关键帧直接建立当前画面，不扩展新的默认资产类型。

## 视觉关键帧与 FRM

- KF 是生成前的可见四宫格视觉关键帧，用于让用户确认完整视频的视觉发动机、玩法机制、构图、配色、字体排版、光线、材质、核心视觉事件、产品证明或品牌记忆点。
- KF 生成前必须完整读取 `references/visual-motion-playbook.md` 与 `references/audiovisual-craft.md`，再继承已确认参数、创意主线、完整分镜和类型策略；设计卡、图片 PE 和验收按 `references/asset-generation.md` 执行。
- KF 数量与四宫格分镜规格只按资产生成合同计算。KF 不自动作为首尾帧，不承担真实接缝事实，也不按镜头数机械堆图。
- `keyframe_manifest_video_N.json` 记录图板与格位职责、所属镜头和生成段、源文件、强锁定/弱参考/排除项、确认版本、裁出文件及本次输入编号映射。整图引用 `<图片X-第N格>`；单格裁出后按真实输入编号引用并保留来源格位。仅明确承担首帧的输入才作为 `0` 秒基准。
- FRM 是生成后从真实视频里抽出的事实帧。首帧和尾帧默认来自真实视频抽帧，不用生成图冒充；分段连续生成时，只抽取上一段视频尾帧作为下一段视频首帧或状态参考。
- 短片链路默认不生成、不展示四宫格视觉关键帧图片。普通短片必须创建文本型内部四格创意线，包含四个格位的创意状态、相邻承接关系、对应 `Bxx/SHxxx/SEGxx`、每格职责和动态把手，并在最终视频 Prompt 中逐段继承。四格是创意顺序，不是固定叙事顺序；可以由 2-4 个强创意节点展开，剩余格位承担递进、回声、转译或收束，不能硬凑无意义的新玩法。General 简单动态任务不创建四格，只记录 `用户锁定项 -> 一个主动作 -> 最多两个因果次级运动 -> 摄影机策略 -> 声音/台词 -> 落定或回环`。用户明确要求看关键帧、概念图或逐阶段确认时，转入可见关键帧流程并按 KF 规则交付确认。

## 长视频连续性

长视频先确认全局方案，再按片段连续生成。每段是全片的一部分，不能重复独立 hook、独立卖点闭环、独立 CTA、logo hold 或最终 slogan。拆段不是把多条独立短片排在一起，而是把同一条视频按生成能力切成连续执行块；每段必须服务全片主线，并通过动作、声音、构图、尾态或状态帧连接相邻片段。

同一 `video_N` 下的 `SEG01 -> SEG02 -> SEG03...` 必须被视为一条连续剧情和同一个时空过程。拆段边界不重置人物、产品、服装、妆发、道具、场景布局、光线方向、时间、动作相位、情绪、声音、视觉母题或已经建立的因果；后一段必须先接住前一段留下的真实状态，再继续推进新的剧情节点。即使每个 `SEGxx` 都分别使用一份完整五段式 Prompt，第 2-5 段也只能重申全片共同合同和当前片段职责，不能借重新写 Prompt 更换演员、产品版本、场景规则、风格或叙事方向。

拆段前先锁定：

- 全片主线、总时长、比例、模型、平台、字幕策略和交付形式。
- 数量默认是 1 个完整视频；只有用户明确要求多条、多版本、多平台版本或 A/B 变体时，才规划多个独立视频。拆段生成不改变数量。
- 每段职责：开场、建立、证明、深化、转折、高潮、过门、收束或 CTA；每段只承担自己的全片位置，不重置世界观和卖点。
- 主体、产品、人物、品牌、场景、光线、声音、视觉母题和关键道具/素材的连续规则。
- 每个接缝的承接方式：动作、遮挡、视线、物件、构图、光线、声音桥、时间省略或概念转场；需要物理连续或同场景延续时，默认用上一段尾帧或状态帧作为下一段首帧输入。

非最终段只做阶段承接或阶段收束，不重复完整结尾。最终段才负责最终品牌/产品/主题记忆点、CTA、logo 或稳定尾帧。

分段连续生成时，上一段生成完成后只需抽取尾帧作为下一段首帧或状态锚点，并说明继承的主体位置、构图、光位、动作方向、动作相位、情绪状态、产品/道具状态和声音余韵。非最终段的视频 prompt 第 4 段必须产出可被下一段承接的尾态；下一段的视频 prompt 第 1 段必须消费上一段尾帧或明确的接缝参考。这里是生成输入承接规则，不设置额外的人工连续性检查阶段。

如果不能真实传入上一段抽帧或状态帧，必须让用户确认降级方案，例如改成明确省略剪辑、改分镜、重做上一段或接受较弱连续性；确认前不得继续伪装连续生成。

非首段视频生成前必须先完成上一段真实尾帧抽帧并登记为 `FRMxxx`，再把该帧作为本段真实输入、首帧或状态参考传入工具；若工具消费该帧，Prompt 第 1 段必须按真实输入编号写明 `<图片N>` 是上一段 `SEGxx` 的真实尾帧/状态帧，锁定主体位置、构图、光位、动作方向、动作相位、产品/道具状态和可继承尾态。禁止只写“承接 SEG01 尾态”“接上一段车头特写”“延续上一段动作”而没有真实 `<图片N>`/`FRMxxx` 输入。不能真实抽帧或不能传入时，必须在批次参数确认中说明采用时间省略、概念转场、重做接缝或接受弱连续性，并取得确认；确认前不得伪装为物理连续生成。

## 接缝与抽帧

FRM 只记录视频真实输出，不美化、不重绘、不冒充关键图。抽帧职责：

- 尾帧：作为下一段视频的首帧或状态参考。
- 必要状态帧：仅在用户明确要求、平台需要封面或后续片段必须引用特定状态时抽取。

每段生成后需要继续下一段时，抽取上一段尾帧并登记为下一段首帧、状态锚点或接缝参考，在派发包中作为真实输入或明确参考传入。只有明确时间省略、概念转场、场景跳切，或工具不能真实传入上一段帧时，才允许不用尾帧承接；不用尾帧时必须在分镜或批次参数确认中说明采用的衔接方式。

接缝文字不能替代事实输入。凡非首段 Prompt 中出现“承接、延续、上一段、尾态、首帧、接续、接上”等连续性表述，必须同时满足：存在上一段真实视频输出、存在从该视频抽出的 `FRMxxx`、本段输入清单包含该帧或已确认的降级衔接方式。缺少任一项时，先补抽帧、改写为明确跳切/概念转场，或暂停确认，不得把普通关键帧、概念四宫格或文字描述冒充真实尾帧。

不做额外的接缝人工核验或主观连续性检查；用户指出具体接缝问题时，按新版本重新确认受影响片段。

## 工具选择和降级边界

工具选择由真实输入和任务目标决定，不因偏好静默换工具、换模态或换模型。工具名称、字段、模型和输入能力以调用时实际 schema 为准；本节只规定选择边界。

每次视频工具调用都必须执行主 `SKILL.md` 的「视频工具必须透传 Workspace ID」规则：mainagent 在派发包中独立传递当前目标的原始 ID 与交付环境，subagent 按实际工具契约将该 ID 显式传入并记录实际值。每个片段、重试、编辑和并行调用分别核对；已有有效 ID 不得省略、传空或用 Prompt 代替。Mobile 仅透传已有 ID，不执行画布操作；没有 ID 不创建。参数不支持、名称不明确或校验失败时停止该调用并向 mainagent 回报，不省略 ID 降级重试。

每次提交视频生成、重生或变体前，都必须根据已确认的素材职责扫描当前片段需要继承的参考资产；凡存在相关且当前工具可真实消费的图片、视频或音频资产，都要作为本次生成输入传入，并在 prompt 第 1 段按真实顺序说明用途。不能因为用户没有再次提醒就遗漏可消费的产品图、人物图、品牌图、场景图、关键帧、上一段尾帧、参考视频、声音、BGM、环境声或拟音参考。不能消费的资产不得登记为真实输入，也不得在 prompt 中写成 `<图片N>/<视频N>/<音频N>`；需要继承但不可消费的视频或音频素材，内部拆成可执行的画面、节奏、声音意图、关键帧、首帧、尾帧或文字约束，不向用户解释工具缺失或降级过程。

派发前做一次 Prompt 硬门检查：最终五段式 Prompt 必须能看见已选择的主创意系统/主玩法如何在开场建立、中段升级、结尾回收；主创意系统已经通过品类套路排雷，不是当前品类默认声音、光波、粒子、飞溅、水光、花瓣、烟雾、雪山、光轨、数据卡片等通用第一联想，或已在同一 Prompt 中写清反套路转译、产品/品牌触发和回收；所有创意补足都服从用户明确指定的主体、动作、场景、时长、风格、镜头方式和叙事意图；主创意系统、相关创意节点、辅助职责、高光镜头和文案都能追溯到用户指令、素材事实、产品/品牌卖点、目标人群或平台语境，并与叙事处于同一因果链；多个创意节点之间有可见继承和递进，而不是无关拼贴；所有跨镜动作都有完整动作桥，多镜头视频的每次切镜都有理由、承接锚点和新增信息，真实一镜到底则没有任何剪辑并保持空间、时间、动作和摄影机路线连续；所有真实素材、可见格位、内部格位、上一段尾帧和音频引用都与实际输入一致；非首段若需要物理连续，必须带真实 `FRMxxx`/`<图片N>` 尾帧输入；每句旁白、口播、对白或画面文字都有对应画面证据；不存在无关插镜、重复镜头、无变化回环、滞后花字、无触发高光或只出现一次且不影响主线的孤立创意。任一项缺失时先改分镜和 Prompt，不得派发给 subagent。

该硬门只执行一次。若发现一项或多项问题，汇总后先回写完整分镜，再集中重编译 Prompt 一次；修订时按“用户锁定内容与事实 -> 核心主线 -> 时长与镜头结构 -> 动作连续 -> 声音文字 -> 视觉细节”的顺序一次解决，尽量保证修订成功，不得逐项循环修补或进行第二轮主观改写。随后只运行一次最终客观校验；除工具无法执行、合规、授权、真实性或必要输入缺失等硬阻塞外，无论内部检查是否仍有未完全解决的问题，都按当前修订版派发生成，不再停止或继续修改。

该检查只针对生成前的分镜和 Prompt。视频生成后不自动执行同类主观审片，不因节奏、画面、特效或连续性观感自动重生；只有用户明确提出修改或重生，才建立新版本并重新确认。

完整链路的最终视频 Prompt 保存后、每批派发前，必须由 mainagent 做一次接缝事实核对。凡同一片段块内出现“承接 SEGxx”“延续 SEGxx”“上一段”“接续”“接上”或类似物理连续表述，必须在同块输入资产说明中点名对应真实 `FRMxxx` 或 `<图片N> 是 SEGxx 的真实尾帧/状态帧`；缺少时不得派发，先补真实抽帧输入，或把该段改写为不伪装物理连续的已确认跳切/概念转场。短片直出不做真实尾帧承接核对，避免把内部四格创意线里的创意承接误判为真实接缝要求。

短片直出默认不先生成独立音频、视频参考资产或四宫格概念图；使用用户已有可消费素材、完整分镜和对应内部创意规划驱动视频。用户提供视频或音频且需要在生成阶段消费时优先多媒体能力；没有用户图片时，不为短片直出强制先生概念图，而是把虚构外观、场景、玩法和禁止项写进内部视觉合同与最终 Prompt，并明确不得冒充真实人物、真实产品或官方品牌外观。mainagent 收到视频工具原始短链后立即单项 `present_files`，成功即完成媒体交付；不再重复创建 VIDEO Item 或执行交付前回读。默认非 Mobile 环境的本轮已确认批次全部直交后再整理目录；交付失败时暂停依赖步骤并保留真实状态。普通音乐、环境声、拟音和旁白意图可直接写入 Prompt，不因此额外生成音频。对用户说明可见产物和结果，不暴露内部工具与字段。

| 环节 | 首选工具/能力 | 关键边界 |
|---|---|---|
| 无参考图生成图片 | `image_gen` 或等价生图能力 | 只有主动扫描后确认当前类别没有有效视觉参考图时使用；文字需求、文档截图、台词图、表格截图和 OCR 图不算视觉参考图 |
| 基于参考图生成或修改图片 | `image_edit` 或等价图片编辑能力 | 只要当前类别存在能锁定外观、结构、姿态、构图、产品、人物、场景、材质、色彩或风格的有效图，就优先使用图片编辑；不得把同一产品/人物/Logo/场景重新文生图导致漂移 |
| 需要多媒体约束的视频片段 | `media_to_video` 或等价多媒体视频能力 | 用于用户上传视频、上一段视频或尾帧承接、需要视频运动/场景/节奏参考、口播/旁白/对白/画外音需要消费音色或音频参考、多张真实参考图共同约束的片段。必须传入当前片段已确认且可消费的产品、人物、品牌、场景、风格、关键帧、上一段视频或尾帧、音色参考、BGM、环境声、拟音等必要输入；输入过多时保留最小充分集 |
| 只需图片驱动的视频片段 | `image_to_video` 或等价图生视频能力 | 用于当前任务只需首帧、产品图、人物图或场景图控制，且没有必须在生成阶段消费的音色、音频或视频参考。短片直出里的纯场景、产品动效、无说话展示可以直接使用，不属于降级；不得登记虚假的视频/音频输入 |
| 无用户视觉素材的新视频 | 短片直出用内部视觉合同与文本生成能力；完整链路先生图，再使用图生视频或多媒体能力 | 短片直出不得虚构 `<图片N>` 输入或把概念外观说成真实还原；完整链路不得绕过视觉关键帧确认或真实输入合同 |
| 修改已有视频 | `video_edit` 或等价视频编辑能力 | 只在用户明确要求编辑已存在视频时使用，并按新版本重新确认；输入必须是真实视频文件，目标必须是局部修改并保留不变项。没有已生成源视频时不能用编辑工具替代生成 |
| 抽帧、裁剪、拼接、探测、ASR、字幕擦除、字幕烧录、封装 | `mediakit` 或宿主正式媒体能力 | 只消费已确认或已验收的正式媒体；禁止用本地脚本或手工命令冒充正式链路 |

工具不可用、能力不匹配或返回结果缺少可展示媒体时，只选择仍能消费必要真实输入、保留已确认声音和画面要求的路径。多媒体能力不可用时可改用满足同一合同的图片驱动能力，不能静默删掉身份素材、确认格位、必要音色或接缝输入。非硬锁定的节奏、氛围与声音意图可以转成描述，但不登记假输入；硬约束无法满足时暂停依赖步骤并说明可见结果的阻塞。部分成功则保留成功项，只补失败项。

多媒体失败时先排查输入上限，只裁剪或精简非必要参考副本。视频参考为非必要风格参考时可移除；承担真实连续性或身份事实时不得静默删除。只支持图片的能力不得写未传入的音频/视频标记或声称音色/视频锁定。可后期合成的已确认音轨按成片策略处理；如改变已确认效果或声音身份，按变更规则确认后再继续。阻塞说明只讲可见结果，不展示内部工具、字段和日志。

用户明确要求看工具细节、Prompt 或交接给其他系统时，可以提供去内部化后的工具选择说明和可复制 Prompt；仍不得暴露资源 ID、任务号、内部日志、机器路径、不可行动检查项或未授权能力字段。

## MediaKit 正式链路

正式媒体处理只走 MediaKit：

- 拼接、裁剪有效区间、探测、抽帧、ASR、字幕擦除、字幕烧录、必要的音频合成或封装。
- 调用前以当前宿主实际能力和 schema 为准；能力不足时停止并说明可见处理方案。
- 异步任务必须保存真实任务结果；只有完成状态后才能消费输出。
- 临时结果需要及时保存为项目产物或当前宿主可访问的正式文件。

不得使用 FFmpeg、ffprobe、本地脚本或手工转码冒充正式链路、正式抽帧、正式探测、正式 ASR、正式字幕烧录或正式拼接。若用户明确要求本地快速预览，可以作为非正式草稿另行说明，不能写成已通过正式交付检查。

每个视频片段交付前只按已确认字幕策略和交付可用性处理，不做主观画面返修：

- 默认无字幕时，只处理逐句字幕、旁白字幕、自动 caption、字幕框、随机字幕文字或旧字幕残留。卖点字、企业口号、品牌主张、标题卡、花字、贴纸、图形标签、尾帧 slogan、CTA、真实 UI 原文和包装可见文字不是字幕，不因默认无字幕而擦除。
- 用户已要求字幕时，片段交付前先确认字幕是否存在且与已确认台词/旁白一致；没有字幕或字幕不完整时，先用 MediaKit 生成/烧录当前片段字幕，再展示该片段。字幕文本来自已确认脚本、台词或旁白；时间轴来自 ASR 或人工对齐，ASR 错字不能覆盖已确认文本。字幕烧录位置与 drama 对齐：`9:16` 使用 `lower_third`、`pos_y=70%`；`16:9` 使用 `bottom_center`；其他比例默认 `bottom_center` 后确认安全区。默认字号 `36px`、字体思源黑体、白色。
- 片段级字幕处理只服务当前片段预览和交付；最终成片仍在音轨锁定后重新执行成片级 ASR、字幕文本、SRT、烧录和检查。

## 旁白、口播、对白、音轨与字幕

非品牌 TVC 默认交付带人声表达的视频，Agent 不得自行改成无人声。默认无字幕只表示不生成逐句字幕或 caption，不表示无旁白、无台词或静音。通用创意、产品广告、企业宣传、UGC/信息流和其他非 TVC 类型都必须包含旁白、口播、对白、画外音、解说或主播念词中的至少一种，并同时安排必要的 BGM、环境声或拟音；只有用户明确要求时才能覆盖为无人声。

品牌 TVC 按“完整旁白优先 -> 少量旁白其次 -> 无旁白最后”判断。品牌主张、事实或因果靠画面无法准确理解时使用完整旁白；画面承担大部分叙事时，只在开场、转折或收束保留 `1-3` 句；只有视觉因果、品牌识别、情绪推进和结尾主张均可由画面动作、文字、音乐、环境声与拟音独立讲清时，Agent 才能主动采用无旁白。不得仅以“更高级”“更电影感”作为无人声理由。

本规则优先于类型文件中任何把无旁白限制为“仅用户明确要求”的旧表述；`references/brand-tvc-video.md` 只提供具体创作方法，不得收紧或改写本节的三级判断顺序。

用户未提供台词时，非 TVC 由 mainagent 根据已确认主线、类型、时长、受众和事实边界起草完整旁白、口播、对白、画外音或解说；品牌 TVC 先完成三级声音密度判断，有旁白或对白时再起草对应数量的完整台词。生成前必须在本次参数列表、分镜表或已确认脚本中逐句展示全部可听文本，并在最终视频 Prompt 的对应秒段中写成 `旁白：{逐字原文}`、`口播（人物）：{逐字原文}`、`人物对白（角色）：{逐字原文}`、`画外音：{逐字原文}` 或 `解说：{逐字原文}`。禁止只写“声音”“有人声”“人物发声”“有旁白”“配解说”“人物介绍产品”“加入品牌口号”“音乐烘托”或任何未提供逐字原文的占位描述。

非 TVC 只有用户明确要求无人声时才允许无台词；品牌 TVC 还允许 Agent 按三级优先级判断采用无旁白。此时参数确认、分镜脚本和视频 Prompt 必须明确写“无旁白/无台词”，并逐段指定由画面文字、产品动作、人物反应、品牌资产、图形信息层、环境声、拟音或尾帧 CTA 承担的核心信息。若无人声结果无法讲清核心表达，必须回退到少量旁白或完整旁白，不能生成后再用说明文字补救。

旁白、口播、对白与解说执行规则：

每次实际生成前必须普通文本完整展示本次参数列表和本次/本批分镜表，再单独调用 `interaction.ask` 取得本次明确单选确认；不得只展示模型、时长、比例、数量四项，也不得引用历史确认。视频批次确认可以简洁复述已确认资产、分镜、可见四宫格格位或内部四格创意线，但必须覆盖本批全部生成参数和这批视频的核心故事线或内容。
- 需要稳定说话声音的视频，只有在当前宿主存在可用的文本转音频、音色克隆或可消费音频参考的视频能力时，才生成或确认独立音色样本，并作为音频资产沿用到后续视频片段。没有这类能力时，静默不生成独立音色，不在参数确认、分镜或交付说明里出现“定制音色”“音色样本”“文字描述的原生声音”等字段或说法。
- 短片直出和完整链路默认不先生成音色或 BGM 文件；按短片对应内部创意规划、完整链路已确认概念图，以及真实素材选择文本生成、图生视频或多媒体能力，并按 `references/asset-generation.md` 的符号合同写清台词、音乐、环境声、音效和画面文字。用户上传视频或音频并要求继承，且当前工具可以消费时，作为真实输入传入。
- 用户提供或指定音频参考时，必须先判断当前工具能否真实消费。能消费时作为音频资产确认其职责：角色声音、旁白声音、BGM、环境声、拟音或节奏参考；不能消费时不登记为真实音频输入，不声称已按音色生成，也不把“定制音色：无”写入用户可见参数。确实会影响用户已确认目标时，只说明可见影响，不展示工具能力细节。
- 视频 Prompt 中的可听语言必须明确形式、声音主体和口型职责，并把逐字原文放入 `{}`；例如 `旁白（画面人物不开口）：{具体原文}`、`人物对白（阿宁，驱动口型）：{具体原文}`。`{}` 不能包音色说明或“说产品卖点”等概述；`【】` 只表示用户明确要求的视频画面内字幕，字幕不能代替旁白、口播或对白。
- 旁白、画外音和内心独白要明确“画面人物不开口”；出镜对白才驱动对应人物口型。
- 每个计划发声的秒段都必须包含真实、完整、可朗读的文本；逐句内容必须与参数确认或脚本一致，不能在 prompt 中缩写、概括、留空或交给 subagent 临场补写。
- 生成后只做可播放性和明显音频缺失判断；不做交付前主观表演或声线返修检查。用户指出具体音频问题时，按新版本重新确认。

台词、人声和画面文字的语言默认与用户当前指令语言一致；只有用户明确要求字幕时，字幕语言才按同一规则处理。用户提供原文台词时默认逐字保留原文，除非用户要求翻译或改写；如输出语言与视频人声语言不同，必须在脚本或成片阶段明确配音处理方式，字幕只在用户已要求时处理。

字幕默认遵守主 `SKILL.md` 的“默认无字幕”。字幕指逐句同步字幕、旁白字幕、自动 caption、双语字幕条、lower-third 说话人条或解释性字幕；卖点字、企业口号、品牌主张、标题卡、尾帧 slogan、CTA、真实 UI 原文和包装可见文字属于设计性上屏文字，不按字幕处理。用户要求字幕时，优先作为后期字幕需求处理：最终音轨锁定后再做 ASR、字幕文本、SRT 或等价字幕对象、烧录和检查。只有用户明确要求“画面内直接生成字幕”，才在视频 prompt 中使用 `【】`。

字幕烧录样式与 drama 对齐：`9:16` 使用 `lower_third`、`pos_y=70%`；`16:9` 使用 `bottom_center`；其他比例默认 `bottom_center`。默认字号 `36px`、字体思源黑体、颜色白色；用户明确要求其他字幕样式时，先确认后再改。设计性上屏文字的位置由分镜和画面构图决定，不套用字幕位置预设。

用户已要求字幕时，最终音轨一旦修改，ASR、SRT、字幕烧录和字幕版处理必须重新执行。不能用字幕修正台词漏说、错说或主体错误；用户指出这类问题时按新版本重新确认受影响片段。

## 成片执行和交付

成片阶段只处理已确认片段的顺序拼接、有效区间、声音、用户已要求的字幕、平台版本和最终交付。不得在成片阶段临时改脚本、替换主体、重生产品、改品牌事实、改变画幅、改变模型、重做镜头设计，或因为主观画面效果判断自行修改。

进入成片前必须具备：

- 已确认的片段顺序、时长和文件。
- 完整链路的所有视频片段已先展示给用户，且最后一批片段之后必须用 `interaction.ask` 单选确认是否进入成片拼接，取得用户明确选择；普通聊天确认不能替代。不得因为最后一个片段已生成就自动拼接完整视频。
- BGM、旁白、音轨和交付版本策略已确认；默认无字幕，若用户已要求字幕，还必须确认字幕策略。
- 没有未处理的素材、事实、授权或平台适配阻断。
- 成片文件可正式展示或交付。

成片交付前默认只做字幕和交付可用性处理：

- 确认可展示或可播放；不向用户复述帧率、编码、音轨、抽帧、命令或检查过程，除非用户明确要求。
- 默认无字幕时，只确认画面中没有未要求的逐句字幕、自动 caption、双语字幕条、lower-third 说话人条、解释性字幕、字幕框或旧字幕残留。
- 用户已要求字幕时，只处理字幕文本、时序、安全区、遮挡和烧录版本，不把卖点字、标题卡、花字、图形标签、真实 UI 原文或包装文字误判为字幕。
- 不主动抽帧评价画面质量、主体美观度、产品生成准确性、构图、光色、风格、节奏、创意效果、表演自然度或镜头是否“好看”。
- 字幕符合用户要求且文件可交付时，直接交付成片；不要因为内部主观效果判断重新生成视频。
- 只有字幕问题、封装/播放/音轨问题或平台版本无法交付时，才做必要技术处理；用户明确指出具体画面问题时，按新版本或新任务重新确认，不走默认返修。
- 不得向用户声称“我已检查画面效果并自动优化/重生”。除可播放、音轨、字幕、封装和平台版本这类交付可用性问题外，画面效果、创意效果、人物好不好看、产品准不准、节奏是否满意等判断交给用户。

技术处理后只确认对应交付项可用。只改字幕就处理字幕链路和成片对应区间；只改封装就处理封装和播放；用户要求重生片段时按新版本重新确认。

成片完成后，向用户展示可用视频并直接交付。默认不展示 MediaKit 任务、抽帧清单、QC 统计、内部路径、资源 ID、命令、日志、参数规格复述或画面质量评价。不固定询问返修；用户主动提出新需求时，按新版本或新任务处理。

## 上游修改与新版本

以下变化会触发受影响下游失效：产品或 SKU、品牌或 VI、人物身份、人物/产品/场景外观、脚本和台词、旁白来源、素材职责、模型、单段时长、总时长、比例、平台、字幕策略、事实声明、客户授权、关键帧职责、片段接缝、音轨策略。

处理原则：

- 只使实际依赖旧版本的下游失效，不推翻未受影响的阶段和素材。
- 已确认产物不原地覆盖；新产物使用清晰版本名或修订标识。
- 阶段状态和版本记录只服务内部恢复；不得把 `confirmed`、`invalidated`、revision、manifest、hash、操作日志或检查报告写进用户可见确认话术。
- 每次明确确认后记录确认原文、阶段、时间和影响范围；缺少当前阶段确认时，不得把该阶段当作已确认继续推进。
- 用户追加或替换有效视觉参考图时，先判断它替代的是人物、产品、品牌、场景、道具、风格、首帧还是关键帧；凡依赖旧参考的分镜、关键帧、片段和成片都需要重做或重新确认。
- 外部调用部分成功时保留成功项，只补失败项；不得因为部分失败重做全部已合格产物。

用户在交付后提出改动时，先定位受影响阶段，再作为新版本或新任务处理；不得用下游裁切、调色、字幕、混音或总结话术掩盖上游错误，也不得因为内部抽帧、主观画面评价或效果偏好自动进入修改。新版本触发来自用户明确反馈、字幕/封装/播放/音轨问题，或无法交付的阻断。

| 症状 | 返回阶段 | 首选处理 |
|---|---|---|
| 目标、受众、平台、比例、模型、总时长或交付数量错 | 规划/参数确认 | 重新确认参数，并让实际依赖旧参数的下游失效 |
| 真实产品、企业、品牌、数据、客户案例、功效或授权不清 | 来源与事实锁/参数确认 | 要求用户补材料、检索核实或改成可修改假设 |
| 台词、旁白、卖点、CTA、主线或信息顺序错 | 脚本 | 修脚本并重新确认，影响分镜和视频片段 |
| 产品图、人物图、Logo、UI、场景、道具、音频或风格职责错 | 基础资产/素材职责 | 重新确认素材职责或补资产，不让分镜和视频临时猜 |
| 镜头职责、节奏、动作、证明链、转场或片段边界错 | 分镜 | 修分镜和片段执行计划，再重做受影响关键帧或片段 |
| 关键图目标或参考继承错 | 关键图 | 新版本中修对应关键图或关键图说明；分镜正确时不回到脚本 |
| 用户明确指出生成片段里产品、人物、Logo、场景、道具、台词、人声或动作执行漂移 | 视频片段 | 作为新版本重新确认受影响片段；输入/Prompt 正确则只重生责任片段 |
| 相邻片段黑帧、跳轴、动作回弹、主体漂移、光位突变或声音断裂 | 接缝/视频片段 | 作为新版本重新确认受影响片段或拼接策略 |
| 字幕、ASR、音轨、封装、平台版本或最终文件错 | 成片 | 只重做字幕/音轨/封装/版本并复查受影响区间 |

同一技术阻塞自动定向重试最多 1 次；再次失败时停止自动重试，向用户说明可见问题和可选择的调整方向。说明只讲用户可理解的产物问题，不展示内部字段、工具栈、日志或机器检查细节。

## 委派边界


**视频回传与交付：subagent 回传工具原始视频短链、任务状态、实际透传的 Workspace ID 与可用的原始结果句柄；mainagent 必须立即把该原始短链作为单项输入调用 `present_files`，成功即完成该项媒体交付。不得为同一结果再执行 `+create`／`+create-batch` 创建 VIDEO Item，不得在直接交付前插入媒体 `+get`、下载、复制或重新上传；不能只在聊天中贴短链或转述提醒。默认非 Mobile 环境在本轮已确认批次全部直交后，按 [媒体直接交付与产后目录整理](media-delivery.md) 定位、读取真实对象，仅更新 `path` 并再次核验；该回读不构成交付前置条件。Mobile 仅通过 `present_files` 交付原始视频短链，禁止全部 Canvas CLI／Workspace 操作，已有有效 ID 只作工具上下文透传。subagent 不调用交付或澄清工具，不执行画布 CLI。**

非 Mobile 的画布操作严格使用 `design-cli design-workspace +<command>`。初始化与卡片交付按 `cli/README.md`：执行确认后复用对话有效 ID，无 ID 直接 `+workspace-create`，新画布卡片只传原始 ID，不另加 title；`+get-workspace` 仅用于显式查询、恢复或排障。视频／图像工具结果通过 Workspace ID 关联画布，直接交付后按 [产后目录整理](media-delivery.md#产后目录整理) 读取真实对象并仅更新 `path`；禁止再为同一结果 `+create`／`+create-batch` 或补写 `source_ids`。手工创建的用户上传／本地处理资产仍按创建协议记录真实来源。主 Skill 的 Mobile 前置例外优先。

subagent 回传最终视频原始短链时，必须同时告知 mainagent：“请将工具原始视频短链单项交给 present_files；成功即完成该项媒体交付，不再创建 VIDEO Item 或在交付前回读。非 Mobile 本轮已确认批次全部直接交付后另行完成目录整理。”回传中区分“生成成功”和“尚待主 Agent 交付”，不得将回传视为用户已收到。mainagent 接收后必须实际调用 `present_files`，不只展示短链或转述提醒。

mainagent 负责所有用户交互和交付；subagent 只执行已获确认的生成／编辑任务。**subagent 禁止调用 `interaction.ask`、`interaction.request_action` 及任何澄清／确认工具，禁止调用 `present_files`，禁止自行执行画布写入。** 本 Skill 中的询问、确认、卡片展示、交付和 CLI 写入／回读均由 mainagent 执行；子任务读取本 Skill 不代表获得这些主 Agent 权限。

派发包必须明确本次方案已经通过确认，携带锁定参数、当前目标的原始 Workspace ID（Mobile 无 ID 时明确记录无 ID）与交付环境、mainagent 完成的最终五段式 prompt、真实素材句柄、允许执行范围、禁止改动项、交付要求及回传要求。不得把“请你优化一下/帮我写 prompt/按这个方向生成”这类半成品 brief 交给 subagent。长视频非首段还必须携带上一段尾帧或已确认的接缝参考；缺少必要承接输入时，subagent 不得自行脑补生成。subagent 只按最终 prompt 和素材句柄执行生成／编辑，不重写 prompt、不补创意、不换模型、不换比例、不调整时长、不自行追加素材、不重复触发生成确认；若输入缺失、方案变化或执行存在歧义，暂停受影响步骤并把问题回报 mainagent，不直接询问用户或调用交互工具。

subagent 生成成功后立即回传原始视频短链、任务 ID、状态、实际透传的 Workspace ID（无 ID 时如实记录）、可用的原始结果句柄与真实 Item ID 及错误信息，不只返回总结或仍在运行的任务 ID；工具没有返回 Item ID 时不得猜测。mainagent 收到成功结果后立即将原始视频短链单项交给 `present_files`，成功即完成该项媒体交付；非 Mobile 在本轮已确认批次全部直交后另行定位、读取真实对象并整理目录。子任务回传不等于用户已经收到，不得重复生成、交付或写入。

视频生成／编辑必须由异步 subagent 执行，即使只有一条简单视频也不豁免。主 Agent 完成确认和画布准备后派发并释放主对话，让用户继续其他任务；subagent 生成成功后回传原始视频短链、任务状态和错误信息，mainagent 收到结果事件后负责以原始视频短链直接交付；非 Mobile 在本轮已确认批次全部直交后另行整理目录，不阻塞等待、不重复生成。异步委派或回传不可用时暂停，不回退主 Agent 直接生成。

委派必须遵守：

- 规划、基础资产、分镜脚本、可选独立脚本和成片不委派。
- 子任务只执行单一阶段和指定范围，不能改上游、换模型、改素材职责、重写 prompt、再次委派或直接向用户交付。
- 主 Agent 必须提供完整交接包：当前阶段必读 reference、已确认参数、上游产物、素材职责、最终五段式 prompt、必要的尾帧承接输入、允许输出范围、禁止行为和交付要求。
- 主 Agent 保留跨段承接、事实一致性、阶段确认和最终交付责任；不设置额外的主观画面检查或默认返修阶段。

## 平台适配 Profile

需要抖音、小红书、TikTok、Instagram Reels、YouTube Shorts、B 站、官网、会议大屏、广告投放平台或其他平台版本时，平台规格和审核规则按当前信息核实，记录日期和来源。不要凭旧记忆断言最新比例、时长、安全区或禁用规则。

平台适配记录至少包含：

```json
{
  "platform": "",
  "verified_at": "YYYY-MM-DD",
  "sources": [],
  "aspect_ratio": "",
  "duration_limit": "",
  "safe_area": "",
  "subtitle_policy": "",
  "cover_spec": "",
  "title_and_tags": "",
  "content_constraints": [],
  "output_version": ""
}
```

同一母版导出不同平台版本时分别确认比例、安全区、用户已要求的字幕/花字位置、封面和交付版本。不得直接拉伸、硬裁产品 logo、人物脸、手部证明动作、用户已要求的字幕或关键品牌资产。
