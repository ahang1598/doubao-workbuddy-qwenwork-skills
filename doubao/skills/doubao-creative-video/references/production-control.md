## 阶段读取矩阵

下表标明规则适用的阶段，不是逐文件串行读取顺序。任务开始时按已知需求，将下列本次会用到的合同、当前类型和方法章节一次成组并行读取，包括已能确定的后续分镜、Prompt、委派和交付规则；不等进入某阶段才单独读取下一个文件。支持批量读取时合并调用，否则并发执行互不依赖的读取；仅对新需求或真实依赖变化补读，并将独立补读合并。已读且未变化的规则不重复整篇加载。每条视频选择一个主类型，跨类型方法按需迁移，不加载所有类型。读取并行不改变实际创作阶段、确认授权、生成批次、后期分工或真实依赖的执行顺序。

| 阶段 | 读取 |
|---|---|
| 第一阶段：创作方案 | 第一阶段写法、当前类型的具体写法、交互合同；先处理命中条件的制作方案选择，再拟定内容及制作参数；查分镜合同的节奏/声音选择 |
| 第二阶段：分镜与声音设计 | 分镜合同与资产及 Prompt 合同；承接完整内容，完成逐镜与声音时间轴、各段完整 Prompt 或依赖模板，全部在视频确认前写好 |
| 第三阶段：生成与交付 | 视频确认前完成必要输入准备和 Prompt 绑定；确认后直接委派，真实依赖就绪再执行对应后段；每个成功结果先按交付合同逐项直交，再完成已定后期并展示最终成片 |
| 长视频/接缝 | 本文件长视频连续性、接缝；输入改变后同步 Prompt |
| 结果/成片/平台版本 | 本文件已定后期与直接交付、媒体交付合同；不审片、不自动修复；实际 CLI 时查 CLI 索引 |

方法库按实际缺口查用；默认单一方案及修改方式按[第一阶段写法](creative-core.md#先找到具体切入点)，不另设候选筛选流程。规划结论进入同一份分镜母版。

## 统一制作流程与阶段确认

参数方案采用[交互合同](interaction-ask-video-clarification-ref.md#先用普通文本展示完整参数)的字段、顺序与按需展示规则，简单任务默认不展示时间表或分镜表，不在本文件另定表格或列数。素材询问与实际生成确认的交互策略见交互合同，具体调用遵循当前工具说明；这里规定阶段时机和授权范围。

以下准备范围按实际任务判断：新创作与参考重创完成全片内容、全部分镜和各段 Prompt；保留原片的局部生成式编辑仅完成指定修改、必要关联及保留项的完整指令和适用母版，沿用仍有效内容，不要求重写或审查全片。仅文本与纯后期仍走原有路径，不因准备前移启动视频生成。所有视频任务使用同一制作流程；新创作和参考重创按[第一阶段的内容创作](creative-core.md#第一阶段创作方案)写好完整内容、台词及关键声画设计，保留型编辑与纯后期只展开本节规定的修改范围。整体风格、关键拍法与逐镜细节的[分工只在第一阶段写法维护](creative-core.md#第一阶段确定到什么程度)。参考研究按需执行，不增加独立报告、素材生成或一轮用户确认。

制作路径或用户台词的必要取舍未定时，先按[交互合同的制作方案选择](interaction-ask-video-clarification-ref.md#制作方案选择)处理。该选择只确定制作方式及必要的台词保留/精简、时长取舍，不授权生成；它不是流程分类。剧情影视任务仍按主入口路由，不因统一流程扩大本 skill 范围。

**统一顺序**（实际需要视频模型生成/编辑时；仅文本与纯后期按本节对应规则处理）：mainagent 完成创作与制作规划 -> 内部完成全片完整分镜、声音脚本及各段完整 Prompt／准确编辑指令（后段真实依赖预写完整模板） -> 完成可预先取得的真实输入准备及绑定，确需新制独立资产时先沿用原有资产授权、制作和采用流程 -> 按交互合同展示开场白、本批完整参数与内容 -> 调用 `video_token_compute` 计算本批预估 token 消耗 -> 实际调用 `interaction.ask`，在确认问题中展示预估消耗、付费／免费额度类型及“视频生成为高消耗行为”提示，取得本批生成确认 -> 直接实际委派已就绪的 OrganizerAgent 任务，按真实依赖取得输入并委派同批后段 -> 成功结果按[交付合同](media-delivery.md)逐项直交并内部回传 -> 完成已定后期 -> 最终成片直交。无需后期且原始视频已作为成片展示时不重复发卡。用户要求先审脚本、分镜或其他某一步时，先交付所需内容并完成审阅，再同步受影响的母版与 Prompt、展示当前方案并确认；未要求时不等待阶段反馈，也不向用户展示全部内部文件。已确认批次内不重复视频确认。

制作工作只按实际需要展开：单次制作直接落实本条内容；多段补分段职责、接续和拼接安排；关联内容确需分别制作或复用时补取用与依赖关系；独立人物/产品/音色资产只按实际缺口及资产门准备。时长、模型、镜头数、素材数、调用次数、多人多场景或创意难度不触发另一套流程，不新增难度评分、流程选择题或默认逐阶段审阅。所有任务保留相同的内容、台词、分镜与声音要求；只减少不需要的制作工作，不简化有效创作细节。按需落实方法见[第三阶段执行顺序](#第三阶段执行顺序)。

- 第二阶段不调用媒体生成工具；用户要求的内容审阅可使用普通聊天，不授权视频生成。只有第三阶段确需生成已列明的独立人物/产品/音色资产时，才在执行前按[交互合同](interaction-ask-video-clarification-ref.md#工具调用边界)取得对应资产制作授权；仅授权列明资产，不授权视频。已有明确有效的对应资产授权则不重复询问；无需生成资产时跳过。
- 视频生产流程不生成分镜效果图、四宫格或关键帧预览，不设置分镜图片确认环节；命中资产门的必要人物/产品图按下述资产流程处理。用户另行明确请求独立图片时，作为独立图片任务处理，不成为视频制作前置条件。用户已提供的参考图/图板仍可按真实职责使用；生成视频的真实抽帧见下文。
- 实际视频生成确认按交互合同执行。参数、数量、素材职责、方向、镜头结构或声音有实质变化时，旧授权失效；导演细节在确认前内部完成，不增加审阅，确认后仅按下述真实依赖与机械纠正规则执行。
- 仅文本任务直接交付文本。独立脚本审阅只在用户明确要求先审文字时插入；实际锁定项冲突按交互合同的必要澄清处理，不成为默认额外阶段。

视频确认前确定所选模型、工具、分段、委派能力及关键输入的可行实现路径，完成可预先取得的输入与完整 Prompt 留档。只有已规划、须由前段真实生成结果取得的依赖可以等待；它的来源、用途、输入顺序、进入状态约束与绑定方式必须写入完整模板和制作记录，不能用空白剧情、空白台词或“生成时再补”替代。其他未解决的关键输入缺口不得提前确认视频。确需新制并采用独立人物/产品/音色资产时，先细排相关分镜，完成已有规则要求的资产制作授权、制作和展示，取得采用意见并绑定、同步母版与 Prompt 后再做视频确认；不把尚未确定的外观或音色当成已确认输入。没有这类缺口时不前置整套资产流程。新制资产的采用可用普通聊天确认，不替代资产制作授权或视频生成确认。

按每条独立成片组织内容，批次只控制执行与授权范围。首次视频确认前完成全片内容、全部分镜与声音脚本、各生成段完整 Prompt 或真实依赖模板，并规划段间关系和批次。每批最多两项视频生成/模型编辑任务，长视频生成段也计入本批两项上限。独立任务可并行；后段依赖前段实际尾帧时必须串行，按既定接续计划取得真实输入后再委派／提交。一次确认只覆盖列明的本批，全片已规划不等于全片已授权；后续批次沿用未变母版和 Prompt，只展示本批当前内容、实际参数及必要变更，按[展示预估消耗token](interaction-ask-video-clarification-ref.md#展示预估消耗token)计算该批预估消耗，再通过 `interaction.ask` 展示消耗信息并确认，不先追加“是否继续”，不为进入下一批重新创作全片。跨批依赖帧已取得时先绑定，未取得时保留上述真实依赖模板；当前批次不得越权提前生成。多个独立视频分别规划；仅实际共享的素材或内容复用，不因同时制作而合并成同一故事。

纯后期仅处理字幕、水印；保留既有内容的截取、裁剪、重排、拼接、探测与封装属于必要技术处理，只写清对象、区间、原文、原声与保留项，多素材重组才展开取用与成片时间轴。不补新故事、全片广告分镜或视频生成确认。整体调色、风格、转场、运镜、动作、表演节奏或音频变化按[素材工具路由](media-cond-video-ref.md#多轮编辑与重新生成)走重新生成；不能用后期新增、替换、重混音频绕过确认。纯技术重排、拼接只衔接既有画面与原声，不新增声音内容或改变声音意图。分镜或类型中的混音设计不授予后期改音频的执行权限；需要的声音内容在生成前写入 Prompt 或绑定真实生成输入，能力不支持则说明限制。

OrganizerAgent 仅执行已确认的生成/编辑。内部分工、日志和资源 ID 默认不进产品话术；用户明确审查规则或排障时如实解释。

### 确认前准备、真实依赖与实质变化

生成确认以从当前完整母版和 Prompt 提炼展示的内容与实际参数为准；正式逐镜设计、切点、表演、声音时间和准确镜数应在确认前完成，用户侧仍按交互合同精简展示，不把内部完整规划变成冗长参数清单。确认后不再安排新一轮导演细化、补写分镜或 Prompt；只进行计划内真实依赖绑定、必要的机械格式／时间换算纠正和实际委派。机械纠正不改变内容、顺序、声音、素材职责或生成规格，不借此补新事件、删内容或重新设计镜头。删除事件或台词、改变证明/揭示顺序、关键拍法、声音路线、模型、分段、锁定规格或其他实质内容时，先更新受影响的母版与 Prompt，展示变更后重新确认，不能以“细化”为由沿用旧授权。

已确认计划要求从前段取得真实状态帧时，可在本批后段执行前补入该真实文件，并将其记录为原定接续用途；不为预定输入到位再确认一次。它不能替代仍需传入的身份/产品参考；后段继续遵循原定身份、物件状态与事件安排，不因取得接续帧就另改故事或采用新的身份设定。后续只按计划取得真实输入；工具失败或必要输入无法取得时，按下文长视频连续性处理，不审查前段质量。

## 第三阶段执行顺序

第三阶段执行已在确认前完成的分镜和 Prompt，不重新选创意方向或留待确认后编写。第三阶段如有必要独立资产准备，仍先按原有授权制作与采用，在视频确认前完成输入绑定和 Prompt 定稿；本批视频确认后直接进入实际委派。每个工具成功结果先按[交付合同](media-delivery.md)逐项直交并内部回传，再完成已定后期并展示最终成片。素材、声音或精确文字没有可行实现路径时，在视频确认前解决受影响部分，不能用一句“保持一致”“后期添加”掩盖缺口。转写细则唯一见[资产合同](asset-generation.md#从分镜转写不另写一条片)。

| 实际需要 | 输入准备与实际执行 |
|---|---|
| 单次或多段模型生成/编辑 | 同一母版已在确认前转为单次或各生成段的完整 Prompt／准确编辑指令并留档；用户指定审阅的内容先交付，其余内部完成。确认后直接委派，不补写规划，不补关键帧或全套资产 |
| 分段、分批与接续 | 确认前排清各段职责、physical/montage 接缝、执行批次和已定拼接；后段完整 Prompt 模板也提前写好。真实依赖到位后仅绑定既定输入与计划内起始状态，立即委派仍有效授权内的对应后段；新批次仍另行确认 |
| 关联场次、角色表演或独立视听内容需要分别制作 | 确认前在同一母版中排清各部分的用途、状态、依赖顺序和有效版本；按实际需要交代跨场次剧情/道具状态、角色表演/对白/视线配合，执行时沿用，不另写一套故事或增加默认审阅 |
| 多条成片、关联版本或内容复用 | 确认前记录共同素材供哪些成片使用，分别确定取用区间、顺序、声画衔接及已定后期；执行时按有效授权使用。普通共享素材直接引用，不强制拆成独立制作任务；用户变更共用内容时只更新实际依赖它的下游 |
| 必要独立资产 | 按资产门准备已授权的人物/产品/音色资产，取得采用意见后用于视频；不因多段或多人出镜默认制作全套资产 |

没有对应需要时跳过该项；以上安排写入现有母版和制作记录，不逐项建卡、增加审批或质量检查。

视频确认前核对工具支持的素材角色并完成可预先取得输入的绑定：身份/风格参考、起始帧、音色参考与成片音轨不是同一用途。若工具把某张输入图作为首帧，不能只在 Prompt 写“仅参考身份”就认为解除了首帧约束；须使用真实支持的参考方式，或在确认前调整受影响的执行安排。计划内后段真实依赖按预定角色到位后绑定，不因绑定重新选路由或改内容；若实际输入无法按已确认用途使用，暂停受影响任务，更新实质变更并重新确认。

Prompt 转写遗漏必须由 mainagent 在生成确认前补齐。确认后发现内容遗漏时，暂停受影响调用并回报 mainagent；mainagent 补齐后按原有实质变更规则处理授权，不由 OrganizerAgent 自行补写。仅不改变已确认内容和参数值的格式编码或等值单位换算可直接执行。故事、素材职责、声音实现或规格发生实质变化时，先更新受影响规划，沿用原有授权失效规则重新确认。生成后不另作质量判断、问题定位或自动修复。

## 来源与事实锁

将输入按以下状态处理：

| 状态 | 含义 | 使用规则 |
|---|---|---|
| `locked` | 用户明确要求、禁用项、原台词、指定产品或素材职责 | 未经用户确认不得改写或替换 |
| `verified` | 用户材料、可靠来源或实际素材已核实 | 记录来源、日期和适用范围 |
| `pending` | 会影响真实性、合规、成本、权限或交付的未知项 | 不能写成确定事实；优先用可修改假设、概念化表达或技术阻塞说明推进 |
| `assumed` | 为继续规划采用的默认判断 | 在参数确认中说明，允许用户修改 |
| `convention` | 本 skill 的默认惯例，如默认模型、默认无字幕、默认比例推断 | 不等于用户设定，用户可覆盖 |

冲突按约束性质处理，不把“声音、风格、场景”排成固定高低：系统、安全、授权、真实性及工具硬限制不可被创意覆盖；用户本轮明确要求与已锁定台词、主体、素材职责同属创作边界；默认策略只补空白。用户明确更改已锁内容时记录新版本；多个锁定项不能同时满足时说明具体冲突和可执行取舍，不由 Agent 静默舍弃某一项。

涉及真实品牌、公司、产品、人物、地点、赛事、节日、热点、平台规则、功效声明、客户案例、数据、奖项或资质时，生成或写成确定声明前必须核实可靠来源，或要求用户提供材料。缺失资料不阻止创意规划，但只能作为可修改假设标明；真实外观、事实声明、客户授权和功效承诺未确认前不得进入生成输入或确定文案。

## 真实资产门槛

素材按职责分类，而不是按文件格式简单分类：

- 视觉资产：已有产品图、人物图、品牌 VI、场景图、道具图、风格图、用户提供的图板，以及第三阶段按需资产与真实视频抽帧。它们按职责锁外观、构图、材质、空间、姿态或风格；新创作的 0 秒状态在分镜中设计，物理续接使用上一段真实状态帧，不能用概念图冒充已生成视频的首/尾帧。
- 文本来源：仅用于读取内容的文档、截图 OCR、表格、聊天记录、用户指令、脚本图。抽取文字、事实和格式偏好，不把指令截图送入画面。明确展示真实 UI、表格布局或操作状态的截图按视觉资产登记，具体采用/剥离见资产合同。
- 音频资产：配音、音色、BGM、环境声或节奏参考。必须说明是声音身份、情绪、节奏还是成片音轨。
- 视频资产：参考视频、已有素材、上一段成片或待编辑视频。必须拆解用途：结构、节奏、镜头语言、动作、主体身份、场景或可直接编辑的源视频。

参考视频、动效样片或外部案例不能整体套用。内部先做 motion breakdown：逐段提炼手法、节奏、转场锚点、画面层级、动效性格、声音句式和可迁移关系；再改写到当前主体、真实素材、事实边界和类型策略里。参考片描述的是某一类镜头或动效的感觉，不自动成为全片风格；信息密集、真实 UI、口播可信、企业事实和敏感行业场景必须按当前可读性和真实边界重写。

下游使用前必须满足：媒体真实可访问、格式可用、职责明确、用户已上传或已确认采用，并已登记到制作记录。原生工具结果可保留实际可消费的句柄/入口，不为满足“落盘”而重复下载、上传或创建媒体；确需本地文件供已定续接抽帧或后期读取时再实际保存。打不开、未确认、未登记职责、只有来源网页或仅存在于计划中的资源不得进入实际调用的媒体参数或标为已就绪输入。首次生成前的后段 Prompt 模板可按既定接续计划保留输入槽位，注明待取得的真实状态帧来源、用途和顺序；它不是现成媒体，须在实际调用前填入计划内取得的真实输入，不另开检查。

### 全链路视觉身份锁

所有生成阶段执行 `references/asset-generation.md` 的真实输入与身份锁：用户采用素材或首个确认标准资产是对应外观的事实源，每次调用重新传入当前需要且工具能消费的素材，不以文字替代已需传入的身份依据。需要更换身份或外观时，先确认新版本，再使依赖旧版本的下游失效；跨调用同时继承主体身份与剧情状态。

生成/采用的媒体保存到项目沙箱对应层级；上传原件保留副本和采用/剥离说明。Prompt 原文留档与展示边界唯一按资产合同的“通用 Prompt 与留档规则”，本文件仅管理目录和版本依赖。文本来源/OCR 保留为证据材料，不因文件格式是图片就成为视觉参考。

参考优先级、采用/剥离边界、图片与视频输入编号和 Prompt 正文要求统一按资产生成合同执行；本文件只登记真实文件、确认状态和上下游依赖。

## 按需一致性资产门

第二阶段只判断缺什么、为何需要以及缺失会影响哪些镜头，写入母版；第三阶段才取得真实输入或执行已授权的资产生成。默认使用已有素材或已定概念；确需独立资产时只插入必要准备，不默认全套生资产，只允许以下三类：

资产选择门：

- `CHRxxx` 人物：同一人物会跨多个片段反复或长时间出现，且缺少可用、已确认的人物参考。
- `PRODxxx` 产品：需要跨调用保持同一产品，且现有可用图片不足以承担外观基准时，才建立必要标准资产；已有足够真实外观依据或用户明确授权概念外观才能制作。单次概念短片可由分镜与 Prompt 锁定外观，不因“产品要一致”就强制补图。缺少真实还原依据时先补素材，不靠生成标准图冒充真实产品。
- `VOICExxx` 音色：同一口播者、旁白或角色需要跨多个相关视频或生成片段保持声音一致时，先复用可用且已采用的样音；没有样音且真实能力支持时，用 `text_to_audio` 为该说话者制作约 5 秒、1-2 句短台词的样音，以正常语速朗读，不为凑时长拖慢或填充。单次生成即可完成、且不需要与其他视频保持声线一致时，直接由视频模型生成正式人声，不额外制作样音。多段同一说话者复用同一份样音，不逐句或逐段重制；样音内容、输入预算和绑定方式按[音色合同](asset-generation.md#音色)。

每个需要该说话者的生成调用都实际传入同一份已采用样音，按音频输入选择 `media_to_video`；不把样音拼成正式配音，也不因是长视频就默认传前段视频。支持音频输入不自动等于支持音色克隆。需要新样音却无法制作，或后续没有可用的声线参考路径时，在母版声音方案中保留统一描述并说明一致性限制，不建立虚构音频资产，也不声称文字描述等同于实际样音参考。

人物/产品/音色资产的生成条件只在这里维护；类型文件补素材关注点，不自行增加制作阶段。无素材概念创作者可在分镜与 Prompt 建立角色，不能冒充真实达人。

场景、Logo、包装、品牌、道具、UI、风格、BGM、环境声和拟音可以登记为用户素材或表达要求，但不建立默认生成阶段，不生成 `SCNxxx`、`BRANDxxx`、`PROPxxx`、`STYLExxx` 等独立资产。已有真实素材按职责直接用于视频；没有素材且已授权概念创作时，由完整分镜与最终 Prompt 建立当前画面，不先做场景四视图、风格图或分镜预览。

人物设定图、产品标准图、音色样本与全部 Prompt 细节统一读取 `references/asset-generation.md`。实际生成的人物或产品图逐项直接交付；音色文件生成一个就直接交付一个，不写入画布。没有选择门命中时直接跳过资产生成。得到实际文件后更新母版的素材状态，视频输入只能引用已确认资产或本轮明确确认采用的用户素材。

## 项目沙箱与目录存储

每个视频项目必须建立可恢复的项目沙箱，保存真实采用的输入、内容母版、实际使用的 Prompt 与结果。按实际产物建立目录，不预建空目录、空清单或占位日志。下列层级说明材料归属，不要求每个任务都建立全套文件；目录命名可以按宿主和项目习惯调整，不把正式交付散落在聊天临时文件、下载缓存或未登记路径里。

通用 video 使用项目控制与单条视频产物的归属结构，用 `videos/video_N/` 表示第 N 条完整视频或第 N 个平台/变体交付单元，不建立 drama 的 `episodes/ep_N/`。长视频拆段仍属于同一个 `video_N`，不是分集，也不是多条独立视频。共享资产、抽帧和后期材料仅在实际发生时建立对应目录。

### 最少留什么，何时拆分记录

简单任务默认只维护一份制作记录，可用 Markdown 或 JSON，择一即可，不要求固定字段模板。记录当前有效要求与参数、必要事实/素材依据及用途、实际确认的原文或可恢复凭据及时间/范围、调用输入与 Prompt/结果的对应关系、当前执行和交付状态。真实任务 ID、Workspace 上下文、版本及已发生的后期或用户明确要求的修改操作随实际结果登记；未发生或不适用的事项不建空记录。生成、后期和交付状态分别记清，不能用一个“完成”相互替代。制作记录可更新当前状态，但须保留已发生的确认、调用和版本变更，不能抹除历史。

创作方案、完整脚本与人声原文、分镜及声音脚本按适用范围完整保留，可合入同一内容母版的不同章节；已有完整内容不再复制成独立口播稿、旁白稿或摘要。实际使用的 Prompt 仍单独保存完整原文；输入文件、原始结果及本次采用的最终入口按真实职责登记。同一素材保存一次并引用，已有生成结果按交付合同保留真实入口，不为留档复制、重传或重复建媒体对象。用户明确要求独立稿件或阶段审阅时，交付对应内容。

| 实际发生的复杂情况 | 需要补充的记录 |
|---|---|
| 多段生成、依赖接续或跨多个批次 | 各段/批次的实际参数、授权范围、结果、依赖、下一步；物理接续补真实状态帧与接缝记录 |
| 多条视频或多版本共享素材 | 素材版本、适用视频与采用/替代关系，避免重复保存同一素材 |
| 多步已定后期、字幕、平台版本或用户要求的修改 | 源取用区间、音轨/文字及时间轴依据、实际处理与结果；修改保留新旧版本，不建立自动返修记录 |
| 多来源事实或频繁修改 | 当前采用的来源、有效版本及受影响下游，保留必要历史依据 |

补充内容优先写在同一制作记录的相应章节；只有分开维护确实更便于恢复时，才拆出对应清单或日志，并从制作记录链接过去。同一当前有效事实只维护一处，其他位置引用，不同时维护同内容的项目规划、项目清单、制作状态和操作日志；历史确认与实际请求保留当时值，不视为重复维护当前参数。记录多少按实际复杂度判断，不机械建全套文件，也不因合并记录省略内容质量、授权或恢复所需材料。

| 层级 | 责任 |
|---|---|
| 制作控制 | 一份制作记录承接参数、来源、确认、状态与版本；复杂任务按上节需要补充 |
| 脚本 | 完整方案、口播、旁白、对白、广告语和台词依据；可合入内容母版，不重复抄稿 |
| 资产 | 已保存用户素材的职责引用、按需人物/产品/音色资产与相应 Prompt；场景、Logo、包装、道具、UI、风格和音频参考仅作为用户素材登记 |
| 分镜 | 用户可读分镜、镜头级详细分镜、片段拆分和接缝计划 |
| 视频片段 | 每段视频、片段 Prompt 文件、上一段尾帧抽帧和必要接缝记录 |
| 成片 | 本次采用的一个最终视频；字幕、封面及其他版本仅按用户明确要求准备。生成片段与原始生成/编辑结果均按交付合同展示并保留，未要求的后期中间文件只留档 |

用户没有要求多条、多版本或多平台版本时，默认只有 `video_1` 或等价的单一交付单元；长视频拆段仍属于同一个完整视频，不建立多个独立视频项目；每个生成片段与后期成片分别展示，不等于制作了多条独立成片。多条独立视频、A/B 变体或多平台版本需要分别建立清晰的子目录或交付单元，并共享已确认且未失效的素材池。

正式产物必须使用稳定名称和版本后缀，避免 `final`、`new`、`最新版` 这类无法追溯的命名。已确认文件不得覆盖；修改生成新版本，并让实际依赖旧版本的下游失效。临时文件、上传裁剪副本、失败候选和内部检查材料必须与用户可见正式产物分开，不得冒充已确认采用的素材。

下游只引用已在项目登记、真实可访问、职责明确且已确认采用或已按计划实际取得的媒体；实际可消费的原生句柄与必要时保存的文件均可，单独的来源网页不能替代媒体输入。Prompt 文件是正式内部留档：凡真实生成资产、视频片段或成片所用的 Prompt，都必须保存完整原文，用于复现和排查；默认不随对应媒体展示给用户。用户明确要求看 Prompt、排查问题或交接给其他系统时，只通过 `present_files` 直接交付对应 Prompt 文件，不执行画布写入或回读。聊天正文默认不粘贴完整 Prompt，用户侧不点名内部交付工具。

制作记录及按需拆出的来源、确认、操作和版本记录保存在 `00_制作控制/`，不因下文列出示例文件名就逐个创建。这些记录只用于恢复和追溯，不作为用户可见交付；用户询问进度时只说自然制作动作，不展示状态字段、JSON、哈希、日志或内部路径。

### 统一地址、目录和命名

所有记录、清单、Prompt 文件和阶段交接都使用项目根目录相对路径。不得把本机绝对路径、聊天临时文件、接口临时 URL 或网页描述当作项目内正式地址；远端生成结果必须先保存或登记到项目沙箱，再进入下游输入清单。每个成功的原始生成/编辑结果及片段先按[交付合同](media-delivery.md)逐项展示并留档，完成已定后期后再展示真实最终结果。未要求的后期中间文件仅内部保留；已展示的同一结果不因留档重发。无需后期时原始结果同时作为最终入口，不重复发卡；不为交付复制、重传原始结果或重复建媒体对象。已定续接抽帧与后期所需的实际读取和保存仍须完成，不为结果验收额外读取媒体。内部清单保留项目相对路径和必要的外部来源记录。

默认目录按 `video_N` 组织；用户没有要求多条视频时仍使用 `videos/video_1/`。下表是产物归属与命名示例，不是必须全部创建的文件清单；脚本与分镜合并时可放在 `03_分镜/` 的内容母版中，不另建重复脚本目录：

| 位置 | 按需保存的职责 | 文件或命名示例，不要求全建 |
|---|---|---|
| `00_制作控制/` | 一份制作记录与真实输入；确需拆分时再建相应清单 | `制作记录.md` 或 `制作记录.json`；实际输入放 `输入素材/`，复杂任务按需拆出来源或批次记录 |
| `shared/02_资产/` | 实际跨视频或版本复用的素材与按需资产 | `来源_SRCxxx_[名称]_vNN.[ext]`、按需人物/产品/音色文件；复用关系可记制作记录，确需独立管理时用 `asset_registry.json` |
| `videos/video_N/01_脚本/` | 确需独立保存的脚本、口播、旁白或修订稿；内容已在母版时不重复建稿 | 按需 `脚本_[项目名]_vNN_video_N.md`、`口播_[项目名]_vNN_video_N.md`、`旁白_[项目名]_vNN_video_N.md` |
| `videos/video_N/02_资产/` | 本条实际生成的资产与 Prompt；已在输入素材或共享区保存的原件直接引用 | 按需 `产品_PRODxxx_[名称]_vNN_video_N.[ext]`、`角色_CHRxxx_[名称]_vNN_video_N.[ext]`、`音色_VOICExxx_[名称]_vNN_video_N.[ext]`、`提示词/`；素材职责可记制作记录 |
| `videos/video_N/03_分镜/` | 内容母版含完整分镜和声音脚本；默认内部保存，只有用户要求先审或仅要文本时交付所需内容 | `分镜_完整分镜表_vNN_video_N.md`，可在同文件前部保存创作方案与完整文案 |
| `videos/video_N/05_视频片段/` | 每次实际使用的视频 Prompt、实际片段及必要状态帧；调用映射可记制作记录 | `提示词_SEGxx_vNN_video_N.md`、实际保存的 `片段_SEGxx_vNN_video_N.[ext]`，物理接续时按需 `抽帧/抽帧_FRMxxx_SEGxx_tail_[time]_vNN_video_N.[ext]` |
| `videos/video_N/06_成片/` | 实际后期产物；无处理的原始视频直接登记为最终入口，不再保存一份重复成片 | 实际需要时保存 `[项目名]_成片_[比例]_无字幕_vNN_video_N.[ext]`，或用户要求的字幕版及所需字幕文件；最终采用关系可记制作记录 |

`video_id` 固定使用 `video_1`、`video_2`……；目录 `video_N` 和文件名最后一个业务后缀 `_video_N` 必须一致。版本号使用两位 `_v01`、`_v02`……并放在 `_video_N` 前面，扩展名永远最后，例如 `产品_PROD001_耳机_佩戴态_v02_video_1.png`、`片段_SEG03_v01_video_1.mp4`。共享资产确实跨全部视频复用时可以不带 `_video_N`，在同一制作记录或确已拆出的素材清单中注明适用视频，不因此另建 `asset_registry.json`。

ID 分为两级命名空间。共享来源与一致性资产使用项目级唯一 ID：`SRCxxx` 用户/外部来源素材、`PRODxxx` 按需产品、`CHRxxx` 按需人物、`VOICExxx` 按需音色锚点；同一资产跨视频复用时沿用同一 ID，不因版本变化重新编号。分镜与生成产物使用视频级局部 ID：每条独立视频内的 可选 `Bxx`、`SHxxx`、`SEGxx`、`FRMxxx` 均分别从 `B01`、`SH001`、`SEG01`、`FRM001` 重新编号，只要求在当前 `video_N` 内唯一；项目级唯一键统一写成 `video_id + 局部 ID`，例如 `video_1/SEG01`、`video_2/SEG01`，manifest、文件依赖和来源映射不得只用裸 `SEG01` 跨视频关联。场景、Logo、品牌、道具、UI、风格和已有音频均作为项目级 `SRCxxx` 来源素材登记，不因职责不同自动生成独立资产。

需要保存的输入素材放入 `00_制作控制/输入素材/`，命名为 `来源_SRCxxx_[原始名称]_vNN.[ext]`；只服务单条视频的来源追加 `_video_N`，例如 `来源_SRC003_用户产品图_v01_video_1.png`。原生媒体按前述规则登记实际句柄和用途，不为归档创建副本。外部来源同时记录原 URL、访问日期、授权或采用范围；来源网页、搜索缩略图与未解析的分享链接不能冒充实际可用媒体。

## 阶段展示与用户可见产物

本节说的“展示/可见产物”是阶段确认时给用户查看的产物交付，不等于最终成片交付。最终成片、字幕版、平台版本和封装文件的交付规则在“成片执行和交付”中处理。

媒体工具原始结果的入口、交付时机与失败恢复统一按[交付合同](media-delivery.md)，这里仅定义阶段展示内容。音频、文档、字幕、需审阅的分镜与按需 Prompt 文件只直接交付文件，不写入画布；纯文字参数、脚本摘要、素材职责和分镜摘要可在聊天展示。完整脚本、口播稿、旁白稿及分镜作为母版留档；用户只要文本或明确要求审阅时，才交付所需文件。分镜默认内部保存，Prompt 默认只留档；最终视频交付不附送这些文件。第一阶段方案的完整内容与文案按[交互合同](interaction-ask-video-clarification-ref.md#先用普通文本展示完整参数)在聊天展示；文件交付不替代这次展示，也不新增脚本审阅阶段。

用户可见输出只包括：第一阶段方案的完整内容与文案、视频生成参数确认、允许的素材询问、技术阻塞说明、其他阶段的脚本/口播/旁白摘要和文件入口、按需人物/产品/音色资产规划和素材职责、按需分镜摘要和文件入口、每个应交付且成功生成或编辑的图片（包括按需人物图、产品图，以及用户明确要求的海报、封面、场景图、风格图或其他普通图片）、每个成功的生成/编辑视频及片段、每条后期完成的最终视频、用户上传素材的自然职责说明，例如“这张产品图锁定包装和 logo”“这张图只参考风格，不采用文字和水印”。Prompt 文件入口只在用户明确要求时出现。

用户明确要求看 prompt、排查问题或交接给其他系统时，可以提供去内部化后的“可复制的视频提示词”或问题摘要。

阶段展示中，视频和图片的交付分工、格式及配文统一按[交付合同](media-delivery.md)执行。音频、文档等其他产物仍按各自原有规则使用“简短自然说明 -> 对应资源或文件入口”。音频、文档等其他产物的说明只写用户能理解的内容，不要写内部 ID、资源 ID、路径、任务号、检查命令或工具字段。对应文件必须紧贴说明出现；本次每个成功生成/编辑视频及片段均即时展示，后期完成后展示最终成片；不重发历史结果，不附送未要求的后期中间文件。

同一类别从 `1` 开始独立编号，不同类别互不串号。可展示类别包括：按需人物图 1-N、按需产品图 1-N、用户明确要求的海报/封面/场景图/风格图或其他普通图片（同一类别从 1 独立编号）、按需音色试听 1-N，以及视频片段 1-N、原始生成/编辑视频和最终成片；每个成功结果均展示，无需后期时原始视频与成片共用一次展示；用户上传的场景、Logo、道具、UI、风格和音频只作为来源素材展示，不列为生成类别。Prompt 文件只在用户明确要求时单独编号。编号是用户阅读顺序，不替代内部稳定 ID。

非媒体工具产出的用户可见文件也准备好一个就交付一个；音频优先用可播放资源，文档用可打开文件入口。Prompt 仅在用户明确要求查看、排障或交接时交付对应文件；索要可复制文本时去掉内部字段、资源 ID、任务号与日志，不将其写入画布。

分镜等内容审阅先完整展示该阶段产物，再等待反馈；实际视频执行只使用交互合同规定的封闭单选。当前批次内每个片段成功即展示，不逐个追加确认或等待审阅；进入下一批仍需该批完整方案及生成授权。

## 真实视频抽帧 FRM

FRM 是真实生成视频的抽帧，不重绘美化、不用概念图冒充。物理续接时取得真实尾帧/状态帧，作为后段真实输入；蒙太奇接缝不强制传上一场景尾帧。

## 长视频连续性

先按[长视频内容展开](creative-core.md#长视频内容展开)完成全片主线、章节、具体内容和声音发展，再按模型单次能力分 SEG。每段负责自己的内容位置，不重新介绍产品、不重启开场、不重复独立 CTA。生成边界不是故事必须换场或停顿的理由；每段必须满足模型最短/最长时长，末段不足时重排相邻段。

分段先以较少调用容纳完整内容，再把边界移到正常语速下的短语结束、动作完成、结果看清或合理换场处；这些位置不能同时满足时回到分镜重排，不拖慢动作和语速填满上限。以下仅演示不同拆法，实际按内容分配：

| 成片总时长 | fast 分段示例（每段 4-15 秒） | 2.5 分段示例（每段 4-30 秒） |
|---|---|---|
| 60 秒 | 4 段：15+15+15+15 秒，拼接为 60 秒 | 2 段：30+30 秒，拼接为 60 秒 |
| 65 秒 | 5 段：15+15+13+14+8 秒，拼接为 65 秒 | 3 段：30+23+12 秒，拼接为 65 秒 |

60 秒用 fast 的 4 段或 2.5 的 2 段时，数学上每段正好到上限；若合适的内容边界不能这样安排，可以增加段数并重新分配，不强迫每个段落占满。更长视频同样逐段满足范围并核对拼接取用后的总时长，不限制为 1 分钟。模型选择、会员提醒和授权仍按主入口及交互合同，不因这里列出示例就自动采用对应模型。

后段只传当前段实际需要的参考图、音频，以及物理接续必需的真实尾帧/状态帧；是否需要尾帧按下述接缝方式判断。不因长视频分段、续接或上一段视频已经可用，就自动把上一段视频传给生成工具，也不累计传入历史片段。只有本段明确需要参考视频中的动作、运镜等内容，或需要编辑该视频时，才按具体用途传入视频。

上述规则只决定是否传入上一段视频，不改变[素材工具路由](media-cond-video-ref.md#再选工具)。工具仍按创作/编辑意图和实际输入选择；不能因为不传上一段视频，就忽略本段已有的音频或其他视频输入。

每个接缝明确两种方式之一：

- **physical 物理接续**：同一动作或同场景的连续时刻，保护身份、服装、位置、方向、握持、产品状态和动作相位。取得并传入上一段真实尾帧/状态帧，第一部分按真实编号说明用途；静帧只能提供可见状态，动作方向、速度、受力与下一步仍须写进第三部分。依赖前段真实结果的后段必须等输入到位后串行执行，不能一边并行生成一边声称已使用前段尾帧；缺少真实输入不能只靠文字伪装连续。
- **montage 叙事接续**：计划内的换场、时间省略、并行线、结果对照或概念转场。可改变时空与光线，但身份、事实、故事状态和因果不能无解释重置；写清因果、声音、图形、反应或章节承接。不强制上一段尾帧为新场景首帧。各段所需的主体、产品及声音参考已经具备，且不依赖前段实际生成结果时，可在既有批次与授权范围内并行；同一项目既有这类段落又有物理接续时，只串行等待真实依赖，不把整片一律并行或一律串行。

执行时仅将计划内取得的真实状态帧及对应起始姿态、位置、相位填入既定用途，不重写后续剧情、不重新审查前段台词、动作或证据。工具报错、真实结果或必要接续帧无法取得时，暂停依赖它的调用并说明执行阻塞；不受影响的已授权任务可继续，不自动重生。仅在已定动作范围内落实真实起始状态时，不新增创作确认。

一条完整视频共用主线、事实、品牌和声音系统，允许有计划的场景与情绪变化。“连续”不等于全片同一时空。原生台词在自然短语边界分段，后期真实连续音轨单独管理，不能重复整句跨段朗读。

不审片，完成已定合成后再展示最终视频。若用户改变 physical/montage 或其他实质方案，按新版本与授权处理；方案本来已安排换场时不额外确认。

## 接缝与抽帧

仅物理接续强制取得上一段真实尾帧/状态帧并登记输入。为实际续接抽帧，不等于把上一段视频作为下一段的生成输入；后段素材选择按上节执行。封面、额外状态帧只在用户要求或已定制作确需时抽取，不默认堆图。生成段首尾状态、声音和镜头映射保存在执行记录，ID 不写进媒体 Prompt 正文。不为结果验收抽帧，不观看或扫描全片后决定是否返修。

## 工具选择和降级边界

带视频/音频按 media-cond-video-ref.md 选择工具，其他按真实输入与宿主工具能力选择。默认模型以主入口 fast 为准，类型参考或工具分支不得另设默认。只使用实际 schema、合法时长与比例，输入句柄必须真实，Workspace 字段不猜造。

模型依据当前有效分镜直接撰写新创作 Prompt；只有用户要求时才提前交付指定内容审阅，不因工作量或调用次数额外加阶段确认。保留型剪辑与局部编辑按 local_edit 保护原片，不擅自套用新广告声音/镜头要求。纯裁切、拼接、字幕或水印按真实处理能力执行，不为凑流程补模型调用或五段式；确需生成的部分才编 SEG 并撰写对应 Prompt。五段式和符号见资产合同。

实际视频生成/生成式编辑所需的完整 Prompt 或准确编辑指令由 mainagent 在视频生成确认前按原有内容规范编写并留档，OrganizerAgent 只执行已确认内容；待前段真实依赖的后段提前写完整模板。确认后直接委派，不要求额外 JSON、哈希或重编译流程，具体内容写法继续按原方法执行。

无法保真、素材不可消费或工具不可执行时说明具体限制，提供不改变核心目标的可执行方案；用户未授权时不擅自更换模型、增加费用、延长时长或改成另一种任务。工具失败保留真实状态，不无限自动重试。

## MediaKit 正式链路

正式媒体处理只走 MediaKit：

- 拼接、裁剪有效区间、探测、抽帧、ASR、字幕擦除、字幕烧录、水印处理或封装；拼接衔接既有原声，不新增、替换或重混音频。
- 调用前以当前宿主实际能力和 schema 为准；能力不足时停止并说明可见处理方案。
- 异步任务必须保存真实任务结果；只有完成状态后才能消费输出。
- 临时结果需要及时保存为项目产物或当前宿主可访问的正式文件。

不得使用 FFmpeg、ffprobe、本地脚本或手工转码冒充正式链路、正式抽帧、正式探测、正式 ASR、正式字幕烧录或正式拼接。若用户明确要求本地快速预览，可以作为非正式草稿另行说明，不能冒充正式后期结果。

原始生成结果先按交付合同逐项展示并保留；按已确认方案完成保留原声的拼接、字幕或水印后，再展示真实最终视频，不检查视频或自动修复。无后期需要时直接采用原始结果，不强制重导出。需要字幕时在已定画面剪辑和音轨完成后做成片级对齐和烧录；片段 SRT 仅在时间与音轨未变且可准确合并时复用，不能沿用已失效时间轴。探测仅用于已定处理的必要参数，ASR 仅用于已要求字幕的时间对齐，抽帧仅用于已定续接/素材取用；不以这些名义重新验收成片。

## 旁白、口播、对白、音轨与字幕

声音路线、逐字原文和发声区间统一使用[分镜合同](storyboard-contract.md#声音方案与声音脚本)，本节只负责实现与后期。

规划时确定实现路径：新创作已选有人声、且单次视频无需跨视频声线一致时，由视频模型原生生成正式人声；跨相关视频或片段保持同一说话者时，按[音色资产门](#按需一致性资产门)准备并传入样音，正式台词仍写在各段 Prompt 中由视频模型生成。样音不是整片台词音轨，不默认把全部正式台词另做一条配音。用户明确需要固定音轨或精确音画同步时，再核对已有音频或真实可用的独立音频与视频生成输入路径，不转为后期换音轨或混音；没有 TTS 不等于没有声音，也不虚构精确保留、同步或克隆能力。生成后不回听排查漏说、错说、错主体或音乐遮挡，也不声称已逐项验收。

跨段音乐需要连续时，优先在真实可用路径中使用一条已采用的连续音轨，并记录全片取用位置及各段对应区间，核实视频生成工具能实际采用；不能通过后期换轨或混音实现。仅传作风格参考不能当作原音精确保留。若只能分段原生生成，在母版安排可听懂的落音、留白与再进入，不承诺同曲无缝续接。精确跟随音乐的剪辑须依据真实音频节点；没有实际音频时先描述音乐发展，不能声称已按拍点剪好。不能承诺通过后期配音解决口型；音频变化须按素材路由重新生成。

新创作默认无逐句字幕；保留型剪辑或局部编辑未要求改字幕时保留原片，不因默认值自动擦除。需要清理的范围是逐句字幕、自动 caption、字幕框及旧字幕残留；品牌主张、标题、花字/贴纸、图形标签、包装/UI 原文、尾帧 slogan 与 CTA 属于画面文字，不随字幕擦除。用户要求字幕时，以已确认文本为原文，ASR/人工对齐只提供时间；不能用 ASR 错字覆盖脚本，也不能用字幕掩盖漏说或错说。音轨锁定后生成 SRT/烧录，音轨变动需重新对齐。

字幕默认思源黑体、36px、白色；9:16 用 lower_third、pos_y=70%，16:9 用 bottom_center，其他比例确认安全区。用户指定样式优先。正式后期按本文件 MediaKit 章节执行，不以本地预览冒充正式输出。

## 成片执行和交付

每个工具成功视频及片段返回后立即按交付合同逐项展示，再完成已定拼接、画面文字、字幕或水印，展示最终成片。不观看审片、不回听、不抽帧验收、不通过 ASR/OCR 排查错误，不新增自动修复或重新生成。分段生成的成片确需已定拼接时，在全部待拼片段实际可用且应交付片段均已逐项直交、没有受影响的取消或暂停后，以 interaction.ask 单选确认进入该次拼接；这项后期授权不等于质量检查。其他已确认的字幕、水印等后期不逐项追加确认，不需要拼接时跳过这项询问。最终展示唯一按[交付合同](media-delivery.md)。

### 取得真实结果，执行已定制作

等待真实任务完成，保留返回的输出入口、实际参数、用途与版本；完成状态和可供下游消费的真实句柄是必要执行信息，不是成片质量验收。无后期时原始视频就是最终成片，沿用已完成的展示记录，不重复发卡；有已定后期时，原始结果先展示，成片使用真实后期输出，不拿处理前入口代替。工具报错、任务未完成或没有输出时保留真实状态并说明具体阻塞，不伪造成功，不自动重生。

确需物理续接时取得原计划的真实状态帧；已要求字幕时可作时间对齐；已定裁切、拼接或封装可读取必要时长、源区间和原音轨参数，不据此修改音频内容。这些操作只为完成已定制作，不扩展为搜索缺陷、试听比较、逐帧分析或反复加工。没有对应制作需要时跳过，不为凑齐步骤额外读媒体。

只在原有制作记录登记实际输入、调用、后期输出与交付状态；不建审片记录、评分或验收状态，不把工具成功写成“内容全部达标”。用户主动指出问题时先按多轮规则区分评价、事实质疑和明确修改要求；仅对明确要求落实的改动进入修改流程，定位方法见[上游修改与新版本](#上游修改与新版本)。

### 各场景的生成前预防要点

| 场景 | 生成前具体落实 |
|---|---|
| 商品广告、产品演示 | 产品可辨，条件、操作、反馈和结果支撑卖点；设计完整证据，不安排剪掉失败过程伪造优势 |
| UGC、口播、采访、知识 | 说话关系与语气自然，前后句逻辑连续；画面对上讲述，步骤、例子及证据可理解，留必要停顿/回应 |
| 品牌 TVC、人物品牌片 | 事件或视听变化推动当前表达，人物行为与品牌/产品有关，结尾回收前文；保留开头看点与中段发展 |
| 企业、SaaS、商务 | 事实、主体和流程有依据；界面、数据和文字留可读时间，台词中的能力有相应材料，不以概念 UI 冒充真实产品 |
| MV、ASMR、风景、简单动态、循环、一镜到底 | 按声音、运动与观看任务设计发展、质感及落点；循环预排末首相位与声音衔接，不强加营销台词、切镜或剧情 |
| 保留原片的局部编辑 | 写清指定修改及保留范围，保护原画面、剪辑、台词与声音，不套新广告的密度与声音默认 |

### 节奏、接缝与声音的预防和已定处理

下表保留具体安排与处理边界，供生成前规划，以及用户明确要求的剪辑/修改使用；不作为生成后自动查错或返修清单。先保护完整事件、台词、关键动作、证明、必要阅读与锁定规格，再安排已知的源取用区间和后期操作。不能事先确定区间的操作不伪造成已定后期。

| 内容或处理目标 | 具体安排与边界 |
|---|---|
| 开头等待、动作后空停、重复区间、结尾拖长 | 分镜从有效内容进入、任务完成就收。已知源素材裁剪只删无新增职责且不切断前提/反馈/台词的区间，并保持已确认规格；固定时长不能靠重复画面、静帧、全片加速或拖慢人声补齐 |
| 操作或阅读不清、关键事件不足、内容平淡 | 在生成前给足动作、例子、证据和阅读时间，不靠快切、裁剪或花字掩盖。已有完整素材可在授权范围内预排重组；没有实际内容不能承诺后期补成剧情 |
| 物理接缝的相位、方向、位置与握持 | 预排切点、后镜入点和实际状态帧职责。已有源素材只有存在可匹配区间且用户已要求时才安排切点调整；尾帧接近不代表动作连续，不用叠化、黑场或缩放代替缺失相位 |
| 叙事换场 | 写清因果、问题与回答、反应或章节关系；按既定授权使用声音桥和源区间，不在生成后临时新增解释台词、替换故事或随机加转场 |
| 音乐、人声、关键动作声的层次与对齐 | 生成前写清让位与落点，通过视频模型原生声音或真实支持的音频输入落实，不在生成后新增、替换或重混声音；只有混合轨时不承诺分轨修复。用户要求音频变化时重新生成并确认 |
| 跨段台词、声线与配乐 | 原生声句在自然短语处划段，统一已采用的声线参考；真实连续音轨按既定区间取用，不能切掉半句、改变原意或自动换新配音/音乐。原生配乐预排落音与再进入，不保证跨次无缝；有意静默与环境变化可保留 |
| 字幕、标题与品牌/UI 文字 | 生成前分清可编辑后期层与画内文字；独立层按已确认原文与时机制作，需精确的文字提前安排真实路径。用户另行要求改画内文字时，仅在实际工具可安全处理且不伤主体的范围内执行，不遮关键证据或叠第二行字冒充纠正 |

音乐在生成前就写出进入、发展、让位、动作落点与收束；自然原声、ASMR 或有意留白按本次目标安排，不为“声音丰富”叠满。拟音对应实际触发，不用合成声音冒充产品真实表现。无完整音轨或精确时间依据时，不宣称已完成卡点、逐字对齐或无缝接续；不为验证这些效果生成后回听。

### 只完成已定后期，不自动返修

已确认的拼接、画面文字、字幕和水印属于正常制作，按实际计划完成；不因为有工具就增加原方案没有的加工。没有后期需要时直接采用原始结果，不额外导出。正常后期完成即进入交付，不再审片或寻找需要修复的问题。

不再保留默认的“一轮自动修复再复查”环节，也不以内部发现、抽查或主观效果为由裁剪、换音轨、改台词、补文字或重做。工具明确失败仅按技术阻塞处理；用户主动要求修改时，作为新版本或新任务执行其明确范围，保留原文件、修改区间和版本关系，不默认重写或重生全片。

不得自动调用视频生成、video_edit、图像重生或配音生成来修复结果，也不默认拉起重生确认。不逐项点评生成质量，不附“本次未自动重生”或未经实际验证的“全部达标”说明。真实调用失败或已定后期无法完成时简述未完成项，不能把片段、损坏入口或错误工具结果冒充已完成成片。

### 后期完成即展示

使用本次真实生成或已定后期返回的最终入口直接展示，不拿旧版或处理前入口替代，不增加播放、音画、接缝或规格验收。默认最终版本无逐句字幕；明确要求字幕时，最终版本须有字幕。原始生成/编辑视频和片段仍先逐项展示，再交后期成片；不额外导出无字幕最终版或附送 SRT、封面或检查报告。标题、品牌、包装/UI 原文及 CTA 不属于逐句字幕，不能一并擦掉。用户锁定的原片保留项优先于默认值。

用户交付格式、配文及结果说明按[交付合同](media-delivery.md)执行。原始生成/编辑结果成功即展示，已定后期完成再展示最终成片；原始结果本身就是成片时不重复发送。无法完成已要求的字幕、合成或其他关键处理时，简短说明真实工具返回的未完成项；不静默用无字幕版、片段或失败结果冒充所需成片，不为凑一个视频伪造成功。平台规范仅在规划确需时检索并记录日期。

## 上游修改与新版本

以下已定内容的实质变化会触发受影响下游失效：产品或 SKU、品牌或 VI、人物身份、人物/产品/场景外观、脚本和台词、旁白来源、素材职责、模型、单段时长、总时长、比例、平台、字幕策略、事实声明、客户授权、参考图职责、片段接缝、音轨策略。内部落实与原定接续输入到位按前述[准备与变更边界](#确认前准备真实依赖与实质变化)，不把所有参数细化都当成方案变更。

处理原则：

- 只使实际依赖旧版本的下游失效，不推翻未受影响的阶段和素材。
- 已确认产物不原地覆盖；新产物使用清晰版本名或修订标识。
- 阶段状态和版本记录只服务内部恢复；不得把 `confirmed`、`invalidated`、revision、manifest、hash、操作日志或检查报告写进用户可见确认话术。
- 每次明确确认后记录确认原文、阶段、时间和影响范围；仅对本流程要求用户确认的步骤检查授权，不给内部工作增设阶段确认。必需确认缺失或失效时，不得将该步骤视为已授权执行。
- 用户追加或替换有效视觉参考图时，先判断它是补充已有职责，还是替代人物、产品、品牌、场景、道具、风格、首帧或某一状态参考。仅补充既定细节且不改变已确认内容时同步引用；发生实质变化时，只更新实际依赖旧参考的分镜与 Prompt，并使受影响授权失效。已经生成的片段或成片不自动重做；确需重新生成时，按用户本次修改范围重新取得生成授权。
- 外部调用部分成功时保留成功项；失败项按下述重试与生成授权边界处理，不自动重跑失败的媒体生成，也不得因为部分失败重做全部已成功产物。

用户在交付后明确提出改动时，按其要求定位受影响阶段，作为新版本或新任务处理。下表保留具体定位方法，仅用于该明确修改请求，不触发默认审片、自动修复或重生，也不得用裁切、字幕或总结话术掩盖上游内容错误。表中的“重做／重生”是受影响范围的定位，不覆盖素材工具合同：主体、人物、物体、场景等具体画面内容变化先核对 edit 全部条件及累计次数；其他需生成的修改再判断重新生成路径。

| 症状 | 返回阶段 | 首选处理 |
|---|---|---|
| 目标、受众、平台、比例、模型、总时长或交付数量错 | 规划/参数确认 | 重新确认参数，并让实际依赖旧参数的下游失效 |
| 真实产品、企业、品牌、数据、客户案例、功效或授权不清 | 来源与事实锁/参数确认 | 要求用户补材料、检索核实或改成可修改假设 |
| 台词、旁白、卖点、CTA、主线或信息顺序错 | 脚本 | 修脚本并重新确认，影响分镜和视频片段 |
| 产品图、人物图、Logo、UI、场景、道具、音频或风格职责错 | 基础资产/素材职责 | 重新确认素材职责或补资产，不让分镜和视频临时猜 |
| 镜头职责、节奏、动作、证明链、转场或片段边界错 | 分镜 | 修分镜和片段执行计划，按本次修改范围重新取得生成授权后，仅重做受影响片段 |
| 用户明确指出生成片段里产品、人物、Logo、场景、道具、台词、人声或动作执行漂移 | 视频片段 | 作为新版本重新确认受影响片段；输入/Prompt 正确则只重生责任片段 |
| 相邻片段黑帧、跳轴、动作回弹、主体漂移、光位突变或声音断裂 | 接缝/视频片段 | 作为新版本重新确认受影响片段或拼接策略 |
| 字幕、ASR、封装、平台版本或最终文件错 | 成片 | 按用户明确范围处理字幕／水印、保留原内容的封装或规格；涉及音频内容变化则按素材路由重新生成并确认，不通过换音轨修复，不自动追加审片 |

同一技术阻塞最多定向重试 1 次，仅限不会重复触发媒体生成或新增生成费用的读取、查询、交付及后期技术操作；这只恢复真实执行，不授权新增内容加工或重生。生成状态不明时先查真实任务，已成功的生成不重跑。再次失败时停止自动重试，简述实际产物或交付问题，不展示内部字段、工具栈、日志或机器检查细节。

## 委派边界

统一执行[生成与交付策略](../SKILL.md#生成与交付策略)：mainagent 在确认前完成全部规划、完整 Prompt、素材准备及所有生成参数，并按原有 `interaction.ask` 策略取得确认；确认后直接创建 OrganizerAgent。创建时 `hint` 必须明确写入指定工具与全部已确认参数、RichMediaCard 交付规范、全部产物立即交付和禁止反思校验三项要求，不能只给文件链接或摘要。完整 Prompt 与真实素材必须可访问；后段真实依赖按已写好的完整模板绑定，不补故事或改变参数。

所有实际视频生成／生成式编辑，包括单条、单镜头、简单动态、分段、新版本及用户明确要求的重新生成，均由 OrganizerAgent 执行并直接交付；mainagent 不代生成、不重复发卡。OrganizerAgent 不调用澄清或确认工具，不向用户提问；需要新决策或参数无法执行时暂停受影响调用并回报 mainagent。委派不可用时停止受影响生成并如实说明。

原有批次、依赖、取消和编辑次数规则不变：每批最多两项生成／模型编辑任务，独立任务可并行，依赖前段真实结果的任务待输入到位再执行；新批次由 mainagent 确认。mainagent 同步原始素材与指令、有效修改、取消／暂停状态和累计 edit 次数。同一最终成片的 edit 串行执行、最多成功一次，在途或结果未明不重复提交。

OrganizerAgent 持续跟进原异步任务，不能仅以“已提交”结束，也不因状态未知或执行方结束而重新提交。每个成功产物立即按[交付合同](media-delivery.md)直接交付，随后同步真实任务状态、结果引用和已交付状态；内部回传不能替代用户交付。失败、阻塞和未知状态如实说明，不反思、审片、质量校验、自动修复或重生。

图片、纯后期、技术处理及 CLI 的执行分工不变。OrganizerAgent 不调用 `present_files` 或 CLI；其他执行方完成的已定视频后期结果，传给负责该任务的 OrganizerAgent 直接交付，不重新处理。用户取消或明确拒收时按[多轮规则](multi-turn-handling.md)及[交付例外](media-delivery.md#取消与拒收例外)处理。

## 平台适配 Profile

需要抖音、小红书、TikTok、Instagram Reels、YouTube Shorts、B 站、官网、会议大屏、广告投放平台或其他平台版本时，平台规格和审核规则按当前信息核实，记录日期和来源。不要凭旧记忆断言最新比例、时长、安全区或禁用规则。

平台适配记录至少包含：

```json
{
  "platform": "",
  "verified_at": "YYYY-MM-DD",
  "sources": [],
  "aspect_ratio": "",
  "duration_limit": "",
  "safe_area": "",
  "subtitle_policy": "",
  "cover_spec": "",
  "title_and_tags": "",
  "content_constraints": [],
  "output_version": ""
}
```

同一母版导出不同平台版本时分别确认比例、安全区、用户已要求的字幕/花字位置、封面和交付版本。不得直接拉伸、硬裁产品 logo、人物脸、手部证明动作、用户已要求的字幕或关键品牌资产。
