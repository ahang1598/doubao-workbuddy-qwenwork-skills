# 视频方案与 interaction.ask 执行确认

**调用主体限制：本文件的素材询问、生成确认及继续执行确认只能由 mainagent 调用 `interaction.ask`。subagent 不得调用任何澄清／确认工具，也不得向用户发问；只执行 mainagent 已确认的任务。需要补充信息或重新确认时，将问题回传 mainagent，由 mainagent 按本文件处理。**

本文件是所有视频场景的方案、素材询问与执行确认的唯一事实源，优先于主 Skill 和业务 ref 中旧的内容澄清、必填问卷或默认值规则。模型能力、素材输入要求、授权与交付规则不变。

## 默认：直接给可执行方案，禁止需求问卷

除下文商业素材询问和必要消歧外，直接依据用户需求、上下文和可用素材拟定一套可执行方案。禁止询问用户未指定的视频内容、动作、镜头、风格、受众、台词、声音、时长、比例或要求从多个创意中选方向；不能因 brief 简短而发起需求问卷。

用户已指定的内容与合法参数优先沿用。需要创意规划的分支，未指定的创意、镜头、台词、音乐、时长和比例由 Agent 合理拟定并随整套方案确认；不得编造事实。原文透传分支优先执行工具路由：展示实际提交的全部用户原文和完整执行参数，镜头、台词、声音或音乐未指定时明确“未指定，不额外补写”，不补分镜、默认旁白或承诺原文没有的内容。所有分支的时长按工具能力拟定一个可执行值，随方案统一确认，不单独提供时长选择题，不静默覆盖用户要求。

旧版“按场景收齐所有信息”“阻塞信息必须逐项追问”“不限题数”“数量/时长不得拟定”等普通澄清规则已废止，不得据此恢复内容提问。

## 商业素材询问例外

同时满足以下两个条件时，必须在出方案前调用 `interaction.ask` 询问素材：
1. 用户要求生成企业宣传片、广告 TVC、卖货／带货／产品销售类视频。
2. 用户未上传任何与当前任务相关的品牌、Logo、产品或企业资料等资产。

先检查当前上传及可恢复的历史上传资产；已有相关上传资产就直接利用，不重复索要，不因某一类别缺失而要求补齐整套资料。普通口播、个人 UGC、创意视频等不因业务 ref 名称而自动触发本例外。只有文字 brief、没有相关上传资产的上述商业任务仍命中例外。

询问仅限“上传相关品牌／Logo／产品／企业素材，或按无素材概念方案生成”，不得借机追问视频内容、规格、卖点问卷或审美偏好。选择上传则等待素材；明确选择无素材概念方案则直接拟定方案，说明不保证真实品牌／产品视觉一致性，不虚构事实。若用户本轮已明确授权无素材概念创作，不重复询问。

## 必要消歧例外

仅在以下情况无法直接执行时允许提问：无法唯一确定操作对象或本次素材职责；必要输入缺失且不能合法替代；用户参数不受支持；用户明确指令互相矛盾且无法判断覆盖关系。工具硬限制、事实、授权等实质阻塞也按此边界处理。用户指令已有明确答案时直接采用，不重复询问。

只问当前阻塞项，能合并的必要问题一次合并，不设整个任务只能询问一次的次数上限；这不允许恢复创意问卷。可直接拟定可执行调整方案时，说明限制并随完整参数统一确认；必须由用户选择对象、补输入或解决矛盾时，只给相关必要选项。询问仍只用 `interaction.ask`。历史“素材最多问一次”条款全部失效。

## 视频生成确认

**所有允许的素材询问和最终执行确认都必须使用 `interaction.ask`，禁止使用其他交互工具或普通聊天问答代替。禁止调用 `interaction.request_action`，它不是别名或替代入口。**

所有实际视频生成、视频编辑和图生视频都需要最终生成确认，包括单段、短时长、单镜头、多镜头、长时长、多段和批量任务。每次实际提交生成前均须完成本节；不能使用历史确认或仅展示四项参数代替。

### 先用普通文本展示完整参数

方案直接展示在普通聊天消息中，不通过工具承载，不把参数只塞进确认问题，也不附开放问句。必须包含：

- 任务类型和交付格式。
- 视频数量、每段时长、总时长、比例和分辨率；规格按真实能力说明。
- 逐段内容、镜头结构、主体动作和镜头运动；原文透传分支仅展示原文已指定内容，其余写“未指定，不额外补写”，不虚构分镜。
- 已锁定的视觉方向与必须保持的角色／产品特征。
- 字幕、配音和音乐范围；实际台词／旁白完整列出，没有时明确说明。原文透传分支不因默认人声策略另补台词或音乐。
- 使用的首尾帧、参考素材或待编辑视频。
- 所选模型、必要工具限制及高消耗提示。

### 随后单独调用一次 interaction.ask

**此类生成确认必须是封闭式单选，禁止开放式问答。**

- 只发一道题，问题只表达“是否按以上参数开始生成”。
- 选项只有 `按要求生成`、`暂不生成`。
- 显式设置 `multi_select: false`。
- 不提供修改方向、其他选项、自由组合、多选或开放式补充题。
- `按要求生成` 的选项说明必须告知用户“视频生成为高消耗生成”。
- 展示完整参数后立即调用工具，不先等用户在聊天中说“好／OK”再补工具。
- 工具自带自由输入能力不代表 Agent 可以设计开放题；不得编造关闭输入的 schema 字段。用户主动提出修改时，更新方案并重新执行本节。

### 确认调用的准确结构

以下为视频生成确认的标准调用范式，必须由 mainagent 在普通文本完整展示参数后，作为 `interaction.ask` 的实际参数提交；不得只在聊天中展示 JSON 代替调用，subagent 禁止调用。

`questions` 必须是数组，禁止 JSON 字符串二次序列化。问题字段使用 `question_id`、`header`、`display_message`、`display_option`；不得用 `question` 或 `options` 替代。每个选项必须含 `option_id`、`label`、`description`，不把 `option_id` 放在问题层。最终确认只发一道题；schema 单次 1–4 题的能力不表示需要发满。

```json
{
  "questions": [
    {
      "question_id": "video_confirm",
      "header": "生成确认",
      "display_message": "是否按以上参数开始生成视频？",
      "display_option": [
        {
          "option_id": "generate",
          "label": "按要求生成",
          "description": "视频生成为高消耗生成，确认后按已展示方案开始后台生成。"
        },
        {
          "option_id": "cancel",
          "label": "暂不生成",
          "description": "暂停执行，不调用视频生成工具。"
        }
      ],
      "multi_select": false
    }
  ]
}
```

### 确认后执行

必须收到用户通过 `interaction.ask` 对当前方案的明确生成同意，才能派发 subagent 开始视频生成／编辑。普通聊天肯定、沉默、模糊答复或历史确认都不替代工具确认。

确认只对展示过的参数有效。数量、时长、规格、镜头结构、方向或素材范围变化后，旧确认失效，必须重新展示完整参数并确认。用户选择“暂不生成”时不执行。subagent 回传工具原始视频短链及实际透传的 Workspace ID，由 mainagent 按 `media-delivery.md` 使用 `<RichMediaCard>{"refs":[...]}</RichMediaCard>` 单项直交，成功即完成媒体交付；非 Mobile 本轮已确认批次全部直交后再按 [媒体直接交付与产后目录整理](media-delivery.md) 整理目录，不创建重复媒体 Item，不做交付前回读。

片段生成后的继续确认也必须使用 `interaction.ask` 单选；继续下一批、进入拼接等选择不替代下一批实际生成前的完整参数展示及生成确认。

## 工具调用边界

`questions` 必须是数组，不得二次序列化为字符串。所有允许的素材询问及执行确认只使用 `interaction.ask`，不得调用 `interaction.request_action` 或其他交互工具，不得用普通聊天收集确认。按实际 schema 调用，不编造字段。

直接出方案不允许编造事实、必需输入、对象 ID 或工具能力；仍须遵守素材与模型硬限制。

## 仅需文本的任务

用户只要脚本、分镜、提示词、镜头表或建议时，直接生成文本方案，不询问视频内容，不调用视频生成工具，也不做视频生成确认。上述商业素材询问仅针对实际视频生成请求；纯文本任务确有操作对象或明确指令矛盾等阻塞时，仍可按必要消歧边界处理。
