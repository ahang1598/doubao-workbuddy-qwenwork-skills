# paper_draft 章节组装

本参考只负责把章节内容组装成 `.workflow/paper_draft.md`。无论段落、单章还是多章，章节结构、表格、公式和图占位都要服务 `make write`，不能另设对话交付状态。

## 一、读取 prepare 结果

开始写作前先看 `.workflow/meta.json`；只有 `needs_citation=yes` 时才读取 `.workflow/source_pool.md`。不要在章节文件里重新发明任务状态。

必须锁定五个字段：章节在全文中的功能、可用材料、Draft/Final、证据来源、交付范围。信息不足时写“待确认/待补”，不补写成事实。

涉及引用时，本文件只消费已核验来源：中文来源来自 `literature-search`，综述合成来自 `literature-review`，证据落句来自 `evidence-driven-writing`。正文中的文献性判断必须挂文内引用标识；只有文末参考文献而正文无引用，视为未完成。

已有文本只做语言润色时应由父入口路由到 `paper-shape`，不进入本参考。进入本写作线的单段任务仍执行prepare、write和三态检查。

## 二、落笔分流

章节不按固定模板套用，先判断本轮要补全文哪一类功能块：

| 功能块 | 落笔前锁定 |
|---|---|
| 摘要 | 只压缩正文已有问题、方法、发现和边界，不提前发明结果 |
| 引言 / 相关工作 / 文献综述 | 先用 evidence map 确定来源能支撑哪些判断，再把引用落到正文句内 |
| 方法 / 模型 / 系统设计 | 从输入、处理、输出、设计理由和可复现步骤展开 |
| 实验结果 | Draft Mode 只能写带 `PLANNING DATA` 标记的规划表与待验分析；Final Mode 必须来自真实数据、图表或日志 |
| 讨论 | 解释成立条件、异常结果和失效边界，避免成果宣传 |
| 结论 | 回收正文已证明内容和适用边界；限制与后续工作按材料需要选用，不新增证据 |

### 2.1 整篇任务的骨架判定

直接生成整篇论文时，先执行 `../../../paper-shape/references/structure.md` 的骨架工作流，按研究承诺、材料状态和主推理路线确定全文结构，而不是默认套六章。下表只作为目标模板和研究设计均未给出时的功能清单，不得覆盖已经推导出的论证路径：

| 任务形态 | 骨架要求 |
|---|---|
| 技术类期刊论文 | 保留题目、摘要、关键词、引言、相关工作、方法、实验与结果、讨论、结论、参考文献；引言以连续问题链推进，少拆空小节。 |
| 毕业/学位论文 | 按学校模板设置摘要、绪论、主体、结论和参考文献；理论、展望、附录与致谢均按模板和材料触发。 |
| 综述/课程论文 | 按课程或题目压缩，重点放在问题界定、主题综述、比较分析、争议或不足、结论。 |

用户要求单文件时，所有章节、表格、图占位和参考文献只进入同一个 Markdown 源稿。整篇任务使用 `.workflow/paper_draft.md`；不要创建或暗示长期分章文件。

## 三、边界锁定

中型章节任务开始前，只锁定会影响正文真实性和交付状态的字段：章节名、Draft/Final、写作范围、可用材料、证据 ID、缺口、禁止进入正文的内容、验收口径。它是对话边界，不是持久产物。

用户已给出清晰大纲时，直接据此继续；不要为了补齐表单反复追问。

## 四、写作流程

1. **定功能**：说明本章解决什么问题，以及它与前后章节的关系。
2. **定证据**：文献、实验、图表相关内容必须指向 evidence map 或明确待补。
3. **定段落**：只安排段落角色、证据和承接关系，不预设固定句式。
4. **写正文**：优先连续段落；文献性判断在句内或句末挂 `[1]`、`（作者, 年份）` 或脚注。
5. **查两遍**：先查规格事故，再查论证质量。
6. **落文件**：凡进入`paper-write-zh`的正文写作，无论整篇、章节还是段落，都写入`.workflow/paper_draft.md`并执行prepare、write和三态检查。只要提纲或语言润色的轻量任务应在父路由转`paper-shape`，不能在本参考内绕过门禁直接交付正文。
7. **控状态**：用户要求加速时可以压缩确认，但不能跳过真实性、Final状态和引用门控。

章节正文不得使用 Markdown 加粗、斜体或 emoji 制造重点；例如 `**预训练与迁移学习**`、`__预训练与迁移学习__`、`_预训练与迁移学习_` 应改为普通小节标题或自然段主题句。

摘要、引言和结论是最容易暴露模板腔的位置。写完整篇或完整章节时，从开始生成正文起就不使用“首先、其次、最后、此外、总之、值得注意的是、需要指出的是、具有重要意义”机械推进；摘要不机械罗列改进模块，引言不把“具有重要意义—近年来显著进展—本文贡献如下”作为固定三段式，结论不重复摘要的效果宣传。若目标模板需要列出贡献，也要让每一项对应具体问题、设计动作、证据位置或适用边界。

## 五、与 make write 对齐的审查

章节写完后先做一次本地审查，再交给 `make write`：

- **结构**：标题层级不超过三层；全文骨架匹配 `discipline_branch`；章节顺序能解释研究问题、证据和结论。
- **证据**：文献、实验、图表和事实判断能回到来源池、实验日志或用户材料；不能把候选文献、搜索摘要或模型记忆写成事实。
- **格式**：正文无 Markdown 装饰、emoji、提示词、AI来源说明；表题、表注、下一节标题分开。
- **状态**：Draft Mode 可保留合格占位；Final Mode 不留待补、待核验、mock、PLANNING DATA。

审查失败先改 `.workflow/paper_draft.md`。无法修复时，状态只能报风险或阻塞，不把章节正文伪装成终稿。

## 六、章节写作规范

### 6.1 反罗列写作

每章必须形成连续论证，而不是把要点平铺为短段落。正文段落应包含因果、转折、承接或限定关系。

完整初稿生成时，章节开头段不要套用固定背景句。优先从本研究对象的具体约束进入，例如数据集、场景、缺陷类型、评价指标或现有方法的局部不足；只有能说明后续方法选择时，才保留行业意义、技术发展或研究热点类背景。

章节结构也要避免八股节奏：引言不写成“宏大意义—传统方法问题—近年来显著进展—本文贡献如下”；方法不机械拆成“整体结构—模块 A—模块 B—模块 C—总结”；实验不逐表朗读数字；讨论不写成“有效性分析—对比优势—应用价值”三段宣传。若这些结构已经出现，至少重构一个章节功能块为具体约束、失败样例、异常结果或边界讨论。

常见段落角色：

- 背景段：场景约束 → 研究矛盾 → 本章承接。
- 文献段：同类研究共同解决的问题 → 代表性证据 → 尚未覆盖的边界；即使改成综合段，也必须保留 `[1-3]`、`（作者, 年份）` 或脚注等文内引用标识。
- 方法段：输入对象 → 处理过程 → 输出形式 → 设计理由。
- 实验段：评价目标 → 对照关系 → 指标含义 → 可接受结论边界。
- 讨论段：结果含义 → 条件解释 → 局限和后续验证。

### 6.2 方法章节

方法章节采用输入到输出 flow：

1. 输入对象：数据形态、样本、特征、约束。
2. 预处理或表示：清洗、编码、划分、标准化。
3. 核心模型/算法：每个模块说明输入、处理、输出、设计理由。
4. 训练或推理流程：公式、算法、参数更新或决策路径。
5. 输出：预测、解释、告警、指标或下游接口。
6. 与实验对应：关键模块应能映射到消融、对照或局限说明。

禁止只写“由三层组成”“包括若干模块”后缺少数据流、公式位置和可复现步骤。

每个方法模块还必须说明“本文决策”：为什么选择该模块、放在网络或流程的哪个位置、针对本文数据或任务的哪类具体问题、对应哪项实验或图表验证。若只能写通用原理，说明它还只是背景介绍，不是本文方法段。

#### 公式输出规范

- 核心模型公式必须使用 LaTeX 数学格式或标准公式编辑器语法，独立成行并建议编号（如式（1））。
- Markdown/纯文本交付中，行间公式统一写为 `$$...$$`，行内变量写为 `$...$`。
- 飞书云文档交付中，优先使用云文档公式块/公式语法；如果只能先输出文本，必须提供可转换 LaTeX 源并说明应转为公式块。
- 禁止在公式中使用 HTML 标签（如 `<sub>`、`<sup>`）或纯文本下标（如 `NQP_{i,t}`、`β_0`）；上下标必须表达为数学格式。
- 幂指数、上下标、分式必须完整写在同一个公式结构内，不得把指数单独拆成一行。
- 公式后的符号说明必须与公式中的系数符号完全一致；例如公式含 `γ_1`、`γ_2` 时，解释中不得写成重复的“γ和γ”。
- 变量定义段落按“被解释变量 / 解释变量 / 机制变量 / 控制变量”等层级分段，每一类单独成段，不与上一段正文粘连。

### 6.3 实验和讨论章节

实验章节不得保留“实验目的、表位、回填模板、讨论提示、请用户替换”等过程性说明。真实结果用数据支撑；Draft Mode 可使用 mock 或 `PLANNING DATA` 形成完整初稿，但表题、表注或状态块必须保留 `PLANNING DATA - replace before submission` 标记，不能写成已验证结论；Final Mode 不允许保留 mock 数据。

讨论章节不要重复摘要或结果表，而要解释：为什么出现该结果、结果在哪些条件下成立、哪些条件下可能失效、还需要哪些补充实验。

#### 表格输出规范

- 出现“一级指标 / 二级指标 / 衡量指标 / 指标属性”等结构化内容时，必须生成标准表格，不得压缩为连续正文。
- 描述性统计必须使用标准表格，每个变量一行，观测值、均值、标准差、最小值、中位数、最大值等统计量分别成列。
- 相关性分析必须输出为矩阵表，变量名作为行列标题；显著性星号紧跟对应系数，不得因换行被拆散。
- 回归结果必须生成标准三线表或结构化表格；每个模型单独一列，变量、系数、括号内统计量、固定效应、样本量和 R² 分行展示。
- 表格结束后另起段落；表题、表注、下一节标题不得与表格内容粘连。
- Draft Mode 不得只写“表 X 待补”。缺真实数据时，生成带表题、列头、单位、TBD/mock 数值和表注的标准表格，并在表注中写明 `PLANNING DATA - replace before submission`。

#### 图占位输出规范

- 缺真实图片时，Draft Mode 使用正式图占位：`图 X-X 待绘制：图题。内容要求：...`。
- 图占位应说明图中需要展示的对象、关键标注、输入输出关系或坐标轴，而不是只写“此处插图”。
- 图占位数量由正文中真实需要可视化的对象决定，不为达到固定数量添加。
- YOLO/CV/缺陷检测论文常用图包括：技术路线图、整体网络结构图、注意力模块结构图、特征融合结构图、数据集样例图、训练曲线/PR 曲线、检测结果对比图和复杂场景示例图。

### 6.4 结论章节

结论只收束正文已经证明的内容：

- 回应研究目的。
- 概括真实贡献。
- 当前证据存在会影响结论理解的限制时，明确说明。
- 前文缺口自然产生具体后续问题时再给出后续工作；没有时省略。

不要在结论中新增文献、实验结果、图表或夸大价值判断。

## 七、交付口径

段落、单章和多章任务统一服从 `paper-write-zh` 的 `PASS`、`BLOCKED`、`DRAFT_ONLY` 三态。正文写入 `.workflow/paper_draft.md`，不再定义另一套状态或对话交付合同。

## 八、错误处理

| 情况 | 处理 |
|---|---|
| 没有大纲 | 先输出章节蓝图或最小大纲，让用户确认后再写正文 |
| 前置章节未完成 | 说明依赖关系；可先写独立小节或待补版，不伪装成终稿 |
| 用户要求跳过确认 | 可加速，但章节完成后仍要给风险说明和下一步 |
| 缺文献 | 不写具体文献结论；先输出检索需求或待核验写法 |
| 文末有参考文献但正文未挂引用 | 视为未完成；补齐正文中的 `[1]`、作者-年份或脚注引用标识后再交付 |
| 缺实验材料 | 不写“全面验证”；写数据需求、占位说明或限定结论 |
| 缺图表 | Draft Mode 生成正式图占位和 `PLANNING DATA` 表格；Final Mode 才正文外列为待补 |

## 九、关键原则

- 一次聚焦一个章节或一个明确小节。
- 每个章节产物都要可复制、可审查、可继续。
- 用户未指定输出介质时，章节正文只是中间 Markdown 源稿产物，最终仍需并入单文件 Markdown 并继续转飞书云文档。
- 用户确认后再进入下一章；用户催促时也不跳过真实性和终稿状态门控。
- 风格遵循 writing-core 规范，证据遵循 evidence-driven-writing 规范。
- 引用、实验、图表和事实不能编造。
