# 抖音生活服务热点查找
为抖音生活服务商家生成一页 HTML 热点查找报告。报告要直接帮商家判断"现在该追哪些热点、怎么拍/怎么写、挂什么商品"，不要把页面筛选项原样丢给商家选择。
## 不适用场景
- 宏观经济/金融/政策热点分析 → 走通用热点分析能力
- 品牌舆情监控、负面口碑追踪 → 走舆情监控类能力
- 通用内容日历/选题日历 → 走通用内容策划能力
- 商家经营数据体检 → 转 `local-life-service-business-report`
## 工具映射
- 浏览器（`open_url_in_browser` / `click` / `type` / `take_screenshot`）：商家后台、数据平台页面只读获取
- `interaction.request_action`：登录/验证码等人机交互
- `CanvasCreateFile`：HTML 报告创建并上屏
- `present_files`：额外附件交付
## 必用能力
- 使用浏览器打开已登录的商家后台（`https://life.douyin.com/p/home`），只读获取商家上下文和热点数据。
- 登录态未接续时，使用 `interaction.request_action` 请用户完成登录，不绕过登录限制。
- **数据平台进入方式（强制）**：必须从商家后台首页点击顶部可见的「生意经」（即数据平台入口）按钮进入。点击后必须检查：当前标签页是否已进入 life-data.cn、是否新增 life-data.cn 标签页或窗口、是否仍在跨域重定向或加载状态；发现新标签页或窗口时必须切换后再继续，不得只根据原标签页没有变化判定跳转失败。禁止直接拼接数据平台 URL（含 groupid）用 `open_url_in_browser` 打开。商家后台与数据平台的 groupid 不是同一个值，直接拼 URL 会导致页面上下文丢失，产生"伪无权限"。
- **多商户选择（强制）**：商家后台存在多个商户且用户目标不明确时，不得默认把列表第一项当作用户目标商户，必须先确认目标商户名称。
- 需要获取维度时读取 [references/data-coverage.md](references/data-coverage.md)。
- 需要生成 HTML 时读取 [references/html-report.md](references/html-report.md)。

## P0：数据平台内部页面导航门禁
本规则优先于后续全部获取流程，违反任意一条即视为执行错误。

**禁止通过以下方式进入数据平台内部页面：**
- 直接在地址栏输入或替换 `life-data.cn` 内部路径；
- 使用浏览器直接导航或修改 `location` 打开内部路由；
- 复用历史对话、收藏、浏览记录或旧标签页中的完整页面 URL；
- 拼接、替换或沿用包含 `groupid` 的完整链接；
- 因页面点击暂未跳转，就直接打开推测出的内部路径；
- 通过商家后台顶部搜索框、经营数据"全部"等非标准路径寻找数据平台内部页面。

**进入数据平台后，所有模块必须通过当前页面上的可见菜单、标签或按钮进入。**

**点击菜单未跳转时，按以下顺序处理：**
1. 等待页面完成加载；
2. 检查并关闭遮挡菜单的引导、弹窗；
3. 再点击同一个可见入口一次；
4. 仍未跳转则停止，并说明"页面导航未成功"；
5. 不得改用地址栏、历史链接或推测 URL。

## P0：商户上下文校验
1. 从商家后台记录当前目标商户名称。
2. 进入数据平台后，必须读取右上角当前商户名称，并与商家后台目标商户名称逐字核对。
3. 如果名称不一致：
   - 立即停止读取经营、流量、热点或搜索词数据；
   - 打开页面商户切换控件；
   - 按商户名称选择后台目标商户；
   - 切换后重新读取右上角商户名称；
   - 复核一致后才可继续。
4. 无法找到目标商户时，停止并如实告知用户。
5. 不得仅根据 URL 中存在 `groupid` 判断商户一致。

## P0："暂无该页面权限"分级处理
**不得仅根据以下现象推断商户没有权限：**
- 页面空白；
- 页面内容较少；
- 页面加载较慢；
- 字段暂未显示；
- 菜单点击未跳转；
- 页面组件尚未初始化。

如果页面明确显示"暂无该页面权限"，先判断当前页面的进入方式。

### 情况一：通过直接 URL、历史链接或不确定路径进入
该情况属于导航上下文异常，**不能判定商户无权限**。必须：
1. 停止读取当前页面；
2. 回到商家后台首页；
3. 重新确认后台目标商户；
4. 从数据平台标准入口进入；
5. 核对数据平台右上角商户名；
6. 通过可见菜单重新进入目标模块一次。

不得刷新或继续使用原来的内部 URL。

### 情况二：通过标准入口和可见导航进入
必须同时确认：
- 后台目标商户名与数据平台右上角商户名一致；
- 本轮没有直接打开或修改内部 URL；
- 页面明确显示"暂无该页面权限"。

以上条件全部满足后：
1. 只刷新当前页面一次；
2. 刷新后重新确认商户名称；
3. 刷新后仍明确显示相同权限提示，才可判断该商户可能未开通权限；
4. 停止该模块取数并如实告知用户。

不得尝试多个入口，不得反复刷新，不得编造数据。

## P0：权限配置建议约束
- 不得根据一次页面异常，直接指导用户修改岗位权限、管理员授权或账号配置。
- 只有在通过标准入口、核对正确商户、使用可见导航进入，并刷新一次后仍明确显示权限提示时，才能建议用户联系管理员确认权限。
- 不得编造具体权限配置路径。只有当前页面可见提示或已验证的官方说明能够作为配置路径依据。

## 异常状态分类（统一使用）
| 状态 | 判定条件 | 对用户表达 |
|---|---|---|
| 页面加载中 | 页面仍有加载状态或内容逐步出现 | 页面仍在加载，稍后重新检查 |
| 导航失败 | 可见菜单点击两次后仍未进入目标模块 | 未能通过页面导航进入目标模块 |
| 商户不一致 | 后台商户名与数据平台商户名不同 | 当前数据平台商户与目标商户不一致，正在纠正 |
| 导航上下文异常 | 页面通过直接 URL、历史链接或不确定路径进入 | 当前页面上下文异常，需要从后台重新进入 |
| 数据缺失 | 页面正常进入，但对应周期没有数据 | 页面可访问，但当前周期暂无相关数据 |
| 权限不足 | 标准入口、商户一致、可见导航、刷新一次后仍明确报权限错误 | 当前商户可能未开通该页面权限 |

## 工作流程
### 第一步：商家上下文获取 + 门店确认
1. 打开商家后台首页，从页面读取商家名称、门店列表、品类、城市、商圈。
2. **多门店处理**：多门店且用户未指定时，**自动选择经营数据最好（成交额最高/动销率最高）的门店作为默认**，在确认卡中展示给商户，商户可改，不单独开一轮追问。
3. 从页面只读获取补充信息：门店品类、城市、商圈、热销商品、客单价、评价关键词、近期曝光/浏览/成交/退款、商品排行。
4. 从当前页面 URL 动态提取 `groupid`、`poiId` 等参数，**不使用任何固定写死的商家标识**。
5. 优先从页面文本提取数据，不截图OCR；页面字段读不到时记录缺失项，不编造。
6. 记录当前目标商户名称，供后续商户上下文校验使用。

### 第二步：一次性确认卡
上下文获取完成后，抛出确认卡，商户一次性回复：
```
【热点洞察确认卡】回复编号修改，无异议回复"全部默认"
1. 分析门店：默认[经营最好的门店名]，可改
2. 热点数量：①Top3 ②Top5 ③Top10
   → 默认：①Top3（优先质量不堆数量）
3. 关注维度：①内容选题 ②商品挂载 ③达人参考 ④全部
   → 默认：④全部
```

### 第三步：数据平台热点洞察获取
1. 从商家后台首页点击顶部可见的「生意经」（即数据平台入口）按钮进入，在商户选择弹窗中选择目标商户后进入数据平台首页。
2. 执行「P0：商户上下文校验」，核对右上角商户名称与商家后台目标商户一致。
3. 通过页面可见导航进入热点洞察页（入口：数据平台首页 → 行业竞争 → 热点洞察，或首页右侧"热门话题→查看更多"）。严格遵守「P0：数据平台内部页面导航门禁」。
4. 若遇到"暂无该页面权限"，按「P0："暂无该页面权限"分级处理」执行。
5. 只读获取页面展示的核心维度。若页面需要登录或字段读不到，按异常状态分类记录，不编造。
6. **获取效率**：优先文本提取，只记录关键字段，不保留完整页面内容。

### 第三步（分支）：用户询问搜索关键词时的专项处理
当用户明确询问以下问题时：
- 大家搜索我的关键词是什么；
- 用户通过什么词搜到我；
- 我的搜索热词有哪些；
- 哪些搜索词带来曝光、点击或成交；

按以下流程处理：
1. 通过可见页面导航进入：数据平台 → 流量 → 搜索分析。禁止直接打开或拼接 `/search/my/overview` 等内部地址。
2. 执行「P0：商户上下文校验」。
3. 记录当前商户名称、数据周期、搜索词及页面可见指标（搜索曝光人数/次数、搜索结果点击人数、搜索成交相关指标）。
4. **区分"商户搜索词"与"行业热点"**：
   - 搜索分析中的搜索词：反映用户如何搜索当前商户或相关需求；
   - 热点洞察中的热点词：反映行业、内容平台或城市热点趋势。
   - 搜索词可以作为热点选题的需求证据，但不得把搜索词榜单直接描述为行业热点榜单。
5. 如果搜索分析页面无法通过可见导航进入，应标记为"导航失败"或"页面加载异常"，不得直接标记为"商户无权限"。

### 第四步：自动选择强相关范围 + 热点提炼
1. 自动选择强相关范围：
   - 品类必须贴合商家主营类目；允许扩展到相邻消费场景，但要说明关系。
   - 城市优先用门店所在城市；可补充同城商圈、本地生活圈层或可迁移的近似城市案例。
   - 内容类型、话题、达人/账号、商品、用户需求、季节节日等维度由模型代商家筛选，不让商家再选。
2. 提炼热点机会：
   - 覆盖页面里的各类维度，不得只看单一榜单。
   - 给出推荐优先级，说明推荐理由、证据指标、适合商品、内容打法和风险。
   - **对可点击打开的热点推荐/抖音图文/视频样例，仅点开Top3强相关的学习可见信息**（提炼开头、标题、画面、卖点、评论反馈或挂载商品逻辑），不逐个点开所有样例。
   - 优先保留可点击来源链接；如果页面只给出标题、话题词或"复制热点去发布"但没有直达 URL，则为每条样例生成可点击的抖音搜索跳转链接，并明确标注为"抖音搜索链接"，不要伪造视频原始分享链接。

### 第五步：输出 HTML
1. 使用 `CanvasCreateFile` 创建单个 `.html` 文件并上屏，文件名使用中文，如 `生活服务热点洞察.html`。
2. **时效性预检**：生成HTML前，以当前系统日期为基准，逐条校验所有推荐热点的有效期；已过期节日/活动/热点直接剔除，不得出现在报告中。
3. 页面首屏直接展示结论、TOP 热点和今天可执行动作，首屏标注"热点已按当前日期时效性筛选"。
4. 报告必须包含"下季度热点前瞻"模块，展示未来3个月的重要节日/大促节点和趋势预测，帮助商家提前布局。
5. 视觉上采用统一的数据平台风格：卡片式布局、清爽配色、数据密度适中，首屏有清晰的视觉层次和重点卡片节奏。
6. 不制作复杂筛选器；最多保留轻量标签、锚点或展开卡片用于阅读。
7. 所有业务判断必须能追溯到获取到的页面数据、商家数据或明确标注的推断；下季度预测必须标注"预测参考"。
8. 报告中必须区分：已获取的真实数据、未获取的字段、页面导航异常、已确认的真实权限不足。
9. 交付前完成渲染验证：DOM结构完整、资源加载成功、首屏/中段正常、移动端可读、控制台无阻塞错误。
10. **参考文件懒加载**：`references/data-coverage.md` 和 `references/html-report.md` 仅在需要时读取，不提前加载。

## 结论标准
- 直接回答商家该追什么热点，不输出泛泛趋势。
- 每个推荐热点都要包含：适配原因、可挂商品、内容角度、素材/图文学习点、预期目标、执行难度。
- 缺少真实数据时，必须把报告降级为"待补获取版"，并列出缺失字段；不要把通用经验伪装成数据平台数据。
- 默认只读。不得执行下载、导出、报名、投放、发布、改价、上下架、保存等动作，除非用户明确要求并完成对应技能的确认门禁。

## AI生成内容说明
通过本 Skill 向商家展示生活服务相关的实际数据或产物时（如经营数据、分析报告、生成的文案或方案），须在该次回复正文末尾另起一行，以普通文本展示以下固定提示，不加粗：
以上内容由 AI 生成，仅供参考，请结合实际情况谨慎甄别。
仅用于需求澄清、信息补充、门店选择、授权确认、进度告知或无结果／失败说明，且未包含实际数据或产物的回复，无需展示。同一条回复交付多项数据或产物时，统一展示一次。提示文案须原样保留并直接可见，不得仅置于折叠区域或工具返回中。

## 时效性校验规则（强制）
### 节日/热点有效期判定
1. **已过期节日禁止推荐**：任何节日、节气、活动类热点，若其核心日期已过，不得作为当前推荐热点出现。
   - 示例：七夕为8月20日，8月21日及以后不得推荐"七夕"相关热点；情人节为2月14日，2月15日及以后不得推荐。
   - 节日前1-3天可推荐"节日预热/最后机会"角度；节日当天可推荐"节日正日"角度；节日过后立即切换到下一个节点。
2. **时效性热点窗口**：
   - 突发热点/话题：从出现起72小时内有效，超过则标注"热度已过"并不再推荐。
   - 平台活动/榜单热点：以活动页面标注的结束时间为准，结束后不再推荐。
   - 季节性热点（如"夏日冰饮""冬季火锅"）：按自然季节判定，跨季后不得推荐。
3. **校验执行方式**：
   - 生成报告前，必须以当前系统日期为基准，逐条校验推荐热点的时效性。
   - 对每个节日/活动类热点，在内部判断中明确其"核心日期"和"推荐截止日期"。
   - 已过期热点直接从推荐列表中剔除，不得出现在"TOP热点"或"今日行动"中。
   - 若页面获取到的热点榜单中包含已过期内容，需主动过滤，不得原样呈现。
4. **临近节日提醒**：若未来14天内有重要节日/节气，可在报告中以"即将到来"标签提前预警，但不得替代当前有效热点的推荐位置。

## 下季度热点预测推荐
在报告中增加"下季度热点前瞻"模块，帮助商家提前布局：
1. **预测范围**：以当前日期所在季度的下一季度为预测周期（如当前为Q3则预测Q4），覆盖未来3个月。
2. **预测维度**：
   - 节日/节气节点：列出下季度所有重要节日、节气、电商平台大促节点（如国庆、双11、冬至、圣诞等），标注日期和适合的内容角度。
   - 季节性消费趋势：结合商家品类，预测下季度的消费场景变化（如餐饮从夏季冰饮转向冬季热饮、服饰换季等）。
   - 平台内容风向：基于当前热点趋势的延续性，预测可能持续或爆发的内容题材。
3. **呈现方式**：
   - 以时间轴或卡片网格形式展示，每个预测节点包含：日期/时段、热点名称、适配品类、建议内容方向、可挂商品类型、提前布局建议（提前多久开始准备）。
   - 标注预测置信度（高/中/低），高置信度为固定节日/平台大促，中低置信度为趋势性预测。
4. **数据来源**：固定节日/节气基于公开日历；平台大促基于历史规律和已公开信息；趋势预测基于当前获取到的热点数据外推，必须标注为"预测参考，非确定性结论"。

## 数据安全与留存
- 只记录报告必需的热点字段和商家上下文，不保留完整页面HTML或原始DOM
- 临时截图和数据文件在报告交付后清理
- 商家groupid、poiId等标识仅用于本次页面定位，不写入报告正文或日志
- 热点数据仅用于本次洞察报告，不用于其他用途
