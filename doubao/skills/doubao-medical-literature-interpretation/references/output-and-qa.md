# 输出、排版与核对

本文件是聊天内回答与飞书完整解读输出结构的唯一权威说明。文章类型 Playbook 只做内部检查；可见目录由文献类型、来源结构和用户任务共同决定。

## 聊天内回答

- 在聊天内直接给出，不创建飞书文档。
- 用户基于文件提出明确问题时，开头先直接回答问题并给出文章依据、确定性和范围边界，再按需要补充文章其他内容；总结请求先给自然总结。
- 未创建文档不等于降低质量或完整度。回答的长度、层次和细节服从论文复杂度、用户问题与当前可读范围；充分保留支撑主要结论所需的关键方法、数据、证据、局限和适用条件。
- 指南更新或重要综述的回答如果讨论了支撑推荐或核心结论的重要研究，原文提供论文题目、DOI、参考链接、试验号或试验注册链接时，同样保留相关可追踪信息。
- 多篇汇总先给跨文献结论，再按需要交代各篇的证据角色、一致与分歧；多篇逐篇解读保留每篇独特贡献；多篇比较围绕真正可比的维度展开。篇幅按相关性、证据价值、复杂度、临床影响和分歧解释价值动态分配，不要求每篇等长。
- 可按内容使用小标题、自然段、列表和加粗。存在真实二维比较、分层推荐、研究特征、关键数字或多组结果时，可使用 Markdown 表格直观呈现；表格不是固定要求，也不受飞书白板或图表最低数量约束。
- 不套完整飞书报告目录，但复杂论文可以主动分节并作较长、完整的解释，不能为了“快速”而只给浅层摘要。
- 来源为短片段时写明“片段解读”；能识别目标文章时尝试定位同一篇全文，但未取得全文前不得声称已通读。
- `quick_answer`、`full_report` 和 `response_mode` 均为内部标识。用户可见回复不得提及模式名称、Skill 内部要求、模板或校验流程，也不解释为何路由到某种模式。
- 结尾只做一次自然引导：是否需要继续基于全文生成图文并茂、结构清晰的完整解读。

## 飞书完整解读的内容构成与自由组织

完整报告先根据文章类型、来源结构、用户问题和阅读节奏设计正文。以下是写作时可调用的语义角色，不是一套必须逐项覆盖的章节模板。除顶部总结和必要图示外，一个角色可以融入另一章、用连续段落自然展开或在当前文章中省略；不预设固定标题、章数、章序、章号或段落标签：

- `总结`：紧接文档标题，使用信息型高亮块。包含总结、解读范围、来源信息和解读边界；单篇可呈现原标题、作者单位、期刊与发表时间，多篇用紧凑方式说明文献数量、类型和覆盖范围，详细书目信息放到更合适的位置。用户提出明确问题时，顶部先用一两句话给出核心答案。
- `核心结论/核心推荐`：研究论文提炼来源支持的关键发现，指南或共识提炼最影响实践的推荐；用加粗导语或高亮块突出重点，随后给必要数据、推荐条件和边界。
- 用户同时提出明确问题时，在顶部总结后优先设置一个能概括真实问题的独立章节，正文直接回答后再展开文章依据和确定性；多个问题按用户顺序或临床重要性归入同一主题或自然拆分。先满足问题，再进入文章背景、结构和全面解读。
- `背景/定位`：研究论文可用“研究背景”；指南或共识优先使用“指南定位与更新要点”；综述、病例或技术文献可根据来源改为主题背景、病例情境或技术定位。只写理解后文所需的来源内信息。
- `全局导读图`：单篇可用文章结构、指南路径、主题脉络或病例进程；多篇可展示各来源围绕核心问题形成的支持、补充、限制、时间演进或比较关系。标题和图型由当前任务决定，不强制使用 `mindmap`。
- `原文解读/多篇文献解读`：设置一个独立 `h1` 主章节统一容纳详细解读，避免把各主题或各篇论文拆成多个并列的解读主章节。单篇服从来源结构；多篇可先综合后分篇，也可按主题、临床问题、研究演进或比较维度穿插证据。主章节内部自由组织 `h2/h3`，并按内容使用段落、列表或表格。图表前先写解释性正文。
- `质量与局限`：研究论文结合真实设计、执行、统计和报告评价；指南或共识评价制定方法、证据到推荐过程、更新机制、利益冲突以及当前来源可见范围。
- `适用与后续`：研究论文可用“适用性与未来研究方向”；指南更适合用“适用人群、实施要点与证据空白”，说明适用条件、资源与可及性、例外、实施障碍和待更新问题。
- `灵感启发`：适合时使用高亮块，围绕不同启发分段展开，直接写由论文内容引出的具体思考或可能方向；也可以融入讨论或结尾。
- `原文重要参考文献`：指南更新或重要综述包含多项关键研究，且集中查看更便于追溯时，可在文末增加本章。只列报告实际重点解读的研究，不搬运整份参考文献表。

问题章节标题提炼用户真正关注的对象、关系或结局，例如“Marker A 与 Marker B 应如何比较”“该结论能否外推至老年人群”。标题保持简洁，正文先直接回答，再展开来源依据。多个问题可共用一个覆盖其主题的概括性主标题，并按内容需要自然分层。

问题章节先直接回答，再自然展开文章依据、确定性和回答边界。可以使用连续段落、列表或简短高亮块，不固定“直接回答、文章依据、回答边界”等段落标签；答案较长时让高亮块只承担摘要作用，证据展开和图表放在正文中。

当指南更新、重要综述或实践更新重点提到影响推荐、核心结论或临床实践的重要实验、临床试验或研究时，在飞书完整报告的对应解读位置必须保留论文题目或规范研究名，并保留原文已有的 DOI、参考文献链接、试验号或试验注册链接中的至少一种。优先使用可点击研究名；原文只有 DOI 时可将其写成 `https://doi.org/<DOI>`。不要求整理全部引用或补齐所有标识符。

文档 `<title>` 不编号。正文中实际使用的标题保持清晰、连续：`h1` 使用“一、”“二、”“三、”等中文序号，`h2` 使用 `1.1`、`1.2`，`h3` 使用 `1.1.1`、`1.1.2`；结构调整后同步顺延，避免同级重复或跳号。模型自行决定正文需要多少层标题。章节可以使用“问题是怎样形成的”“不同分期如何选择治疗”“这项证据有多稳”等内容型标题，不必沿用角色名称或模板措辞。图题、表题、加粗导语和字段标签不是章节。

### 指南 / 共识的组织方式

指南不是按单一假设产生结果的研究论文。解读时优先重建临床决策结构，不套“研究背景—研究结构—结果解读—未来研究”的论文骨架，也不机械照抄出版目录。

指南可以从最影响实践的推荐、用户最关心的分层选择、指南更新变化或诊疗入口切入。随后根据来源实际出现的临床决策关系展开，例如人群与入口、疾病分层、管理目标、推荐行动、推荐强度与证据、替代方案、例外、实施条件、监测和随访；这些只是可选信息维度，不要求逐项成为标题或固定依次出现。

指南若以疾病分期组织，就按分期展开；若以诊疗场景、治疗线次、分子分型或人群组织，就沿其真实决策轴展开。用户明确要求比较不同人群、病理类型或分期时，先把直接答案放在醒目而自然的位置，再在相关路径中补足依据与条件，避免原样重复。

如果材料属于指南更新、局部更新或实践更新，优先建立“更新点—原推荐/既往做法—新推荐—关键依据—受影响人群与实施条件”的阅读关系，但不要求固定做成表格或固定章节。真正推动新增、修改或撤回推荐的研究、试验、证据汇总、安全性或监管依据，应在对应更新点附近得到解释；原文提供的论文题目、年份、DOI、参考链接、试验号或试验注册链接应随研究保留。

### 综述与汇总型文章的组织方式

综述优先保留主题脉络、证据层次、代表性研究、研究演进、争议和空白。作者重点讨论的里程碑研究、临床试验、系统综述或指南节点，应说明其在论证中的作用，而不是只保留作者最后的概括结论。文章提供了清晰时间脉络时，可在相关正文后使用关键研究里程碑图；重要研究的论文题目及原文已有 DOI、PMID、注册号或可点击入口必须在相邻正文保留，也可在文末“原文重要参考文献”集中汇总。

不同综述类型采用不同关注点：叙事综述重视作者框架与选择性引用边界，系统综述/Meta 重视检索、纳入、合并和异质性，范围综述重视证据分布与空白，umbrella review 重视综述重叠和方法质量，实践更新重视新证据是否改变临床决策。它们都不套同一目录。

### 多篇汇总、逐篇解读与比较

先确认用户给定的来源集合和任务重心，再选择正文组织方式。以下是写作策略，不是固定目录：

- 汇总型任务以跨文献综合为主，先解释整组材料共同回答了什么、结论有多稳、哪些差异会影响临床理解；各篇简介只保留支撑综合所需的内容。
- 逐篇解读型任务让每篇都有可识别的研究问题、设计、核心结果、局限和证据角色；可按临床决策链、证据演进或重要性排序，不必机械照附件顺序。
- 对比型任务先用正文建立比较前提，再按真实可比维度组织；适合时使用表格，但表格不能替代对结论差异来源和临床意义的解释。
- 混合类型文献可以按“机制/早期信号—临床验证—真实世界—指南推荐”等证据角色衔接，也可以围绕用户问题把指南、综述和原始研究放在同一主题下讨论。

不同文章的篇幅无需一致。核心或决定性文献、与用户问题高度相关的文献、方法复杂或解释冲突的文献可以明显更长；背景性、重复性、信息有限或只读到摘要的来源简写。不要让数量较多但证据较弱的文献挤压关键研究，也不要因某篇篇幅短就遗漏其独特反例或安全性信号。

## 内容展开原则

- 先重建来源自己的信息结构：研究论文看论证链，指南看临床决策链，综述看主题与证据脉络，病例看时间与推理进程，再决定原文解读主章节内部的二、三级标题。
- 多篇任务先重建每篇结构，再选择能够最好回答用户问题的跨文献结构；可以按主题组织，也可以按文献组织，两者不必同时完整重复。
- 原文结构能够直接帮助理解时优先沿用；指南的出版章节顺序若不利于回答临床问题，可按原文中的人群、分层和推荐关系重组，但不能拆掉推荐条件或把不同情境混在一起。
- 原文解读主章节直接进入实质内容，内部可主动按照真实主题、阶段、证据链或决策点设置二、三级标题，并在相关内容之间合并或继续细分。方法学评价和适用/实施问题可放在其他主章节，也可在相关解读小节中自然承接。避免“本章将按……展开”“下方表格将……”等元话术。
- 重要信息保留优先于表面章节对齐。凡是实验/试验设计、分组与对照、样本流程、关键操作与测量时点、终点定义，或量表/问卷/评分工具的构建、维度、条目、计分方向、阈值、信效度、反应性和临床解释等内容，只要对论文结论、偏倚风险或应用判断有实质影响，就尽量在相关论证或结果附近保留并解释。这些是内容选择提示，不是必备字段、固定章节或逐项清单。
- 每个含图表的原文解读小节，先用一至数段正文讲清该部分内容、关键证据和读图重点，再呈现有具体图题或表题的图表。图表用于承接和归纳正文，图后可按需补充简短解释。
- 原文解读主章节内部可灵活组合二、三级标题、正文段落、`<ul>` 无序列表和 `<ol>` 有序列表；列表适合呈现并列要点、步骤、条件、阶段和递进关系。
- 每份 Full Report 至少保留两个用途不同的飞书白板图。第一张是全局导读图；第二张位于原文解读主章节，必须聚焦文献中的一个重点内容，不能只是换一种布局重复全局框架。指南的全局图可呈现整体临床路径，重点图应下钻一个推荐分支、治疗选择或监测路径。
- 对比表不是固定最低项。论文确有值得并列理解的对象、结果、阶段、条件或研究特征时，在最相关的小节优先使用。先写实质正文，再用一句自然衔接引出，例如“相关 XX 的对比见下表。”标题和比较维度由原文决定，不固定为“总结对比”或 A/B 模板，也不额外介绍表格将如何组织。
- 多篇比较使用表格时，只把定义和尺度足够接近的项目直接并列；终点、时间窗、统计尺度或人群不同则在单元格或相邻正文中明确差异，不用空泛优劣排序代替医学解释。
- 达到两张必需白板后，重要章节存在复杂关系时再插入逻辑图、机制图、流程图、时间线或对比表；图表紧邻对应解读，并配简短、具体的图题或表题。
- 同一信息不得在正文、图和表中完整重复三遍。

## 飞书样式

- 顶部总结适合使用信息型高亮块，灵感启发、独立问题、关键结论、风险或不确定性也可按内容使用相应高亮块。高亮块服务于扫读，不预设数量；长答案和证据展开仍使用普通段落、列表或表格，避免连续、大段或重复高亮。
- 用 `<b>` 突出关键结论、重要结论、结论导语、重要发现、关键数字和段落主旨；避免把整段全部加粗。
- 正文可以在亮点、关键结论、临床提醒、风险、不确定性和启发等位置适度使用高亮块；字体颜色按需少量使用，不设固定语义分类，也不要求用颜色区分信息类型。
- 原文解读主章节内部可主动设置有信息价值的二、三级标题，并灵活使用段落、无序列表和有序列表；真二维比较用表格。

## 飞书 XML

- 用 `assets/feishu-doc-template.xml` 生成本地 `interpretation.xml`。该文件只是轻量脚手架：可见骨架仅预留标题和顶部总结，正文到文末由模型完整自由生成；模板注释用于提醒内容角色，不是必须照抄的目录、标题或段落格式。
- 使用 `<title>`、`<h1>`、`<h2>`、`<h3>`、`<callout>`、`<table>`、`<ul>`、`<ol>`、`<b>`、`<span>`、`<a>` 和 `<whiteboard>` 等 `lark-doc` 支持的结构。
- 行内样式按 `<a> → <b> → <em> → <del> → <u> → <code> → <span> → 文本` 的顺序嵌套。
- XML 标签本身不转义，只转义正文中的 XML 敏感字符；写入前检查标签闭合。
- 禁止 `<sup>`、`</sup>`、`&lt;sup&gt;` 和其他转义上标标签，也不用脚注式角标引用。
- 固定医学单位、指数和上下标使用 Unicode，例如 `10⁹/L`、`m²`、`CO₂`、`¹²³I`；复杂公式才使用 `<latex>`。
- 白板内只放纯 Mermaid，不放 HTML、Markdown 围栏、工具名或内部 ID。

## 写入前预检

对最终 `interpretation.xml` 运行：

```bash
node scripts/validate-report-structure.js interpretation.xml
```

必须通过：

- 仅有一个非空文档标题；
- 无未替换占位符；
- 全文包含两个非空、格式有效且用途不同的白板图；
- 不存在 HTML 上标。

生成时另做写作自检：顶部总结高亮块是否自然交代可得的总结、来源信息、解读范围与边界，字段可合并、改写或使用“期刊 / 发布机构”等贴合来源的名称；文章本身的详细解读是否统一收进一个原文解读主章节；该主章节内部是否按内容自由组织二、三级标题；所有实际使用的标题是否按 `h1` 中文序号和 `h2/h3` 阿拉伯层级编号清晰连续；有明确问题时是否用概括性标题直接回答；每张内容图或表之前是否已有解释性正文；表格是否只在有真实比较价值时于合适位置自然引出；高亮块和加粗是否适度且准确地突出重点；灵感启发是否围绕不同思考分段展开。**元数据字段名称、章节名称、章数、章序、编号、类型骨架和样式选择都属于写作指导，不作为结构脚本的失败条件。**

## 飞书写入

1. 使用已有 `lark-doc` Skill；默认先生成一个完整、已闭合并通过预检的 `interpretation.xml`。
2. 进入 XML 文件目录，用相对 `@interpretation.xml` 创建一个文档；不要使用绝对 `@/…/interpretation.xml`，也不要把整份 XML 通过 shell 字符串替换传入。
3. 默认一次创建完整文档，不建立“写入 → 全文回读 → 再修改”的循环，也不要求绑定最终 revision。创建结果明确成功并返回文档链接后即可交付。
4. 若创建操作本身明确报错，在本地修正 XML 后重新创建；不要先写入不完整骨架，再依赖回读结果补齐正文。

## 事实与质量核对

- 样本量、分母、终点、效应方向、效应量、CI、P 值、随访和不良事件准确；
- 对结论、偏倚或临床使用有实质影响的原文设计信息已被保留：实验/试验设计与关键流程没有被压缩成一句方法名，量表/评分工具也没有只留“信效度良好”这类空泛结论；
- 多篇任务中，每项设计、数据、结论、局限和书目信息归属到正确来源；同一队列、试验的多次发表和指南版本关系已识别，没有被重复计作独立支持；
- 跨文献比较已核对人群、干预/暴露、对照、终点定义、时间窗和统计尺度；不能直接比较的结果保持分开，没有未经方法支持的合并效应、总体排名或统一证据等级；
- 篇幅体现任务价值而非平均分配：关键文献、关键分歧和临床影响得到充分解释，背景性或重复来源得到必要但克制的交代；
- 图表节点与比较项都能在来源中定位；
- 文中使用的重要研究名称、DOI、参考文献链接或试验号与来源一致；
- 指南更新和重要综述中，正文实际讨论的关键研究已保留论文题目或规范研究名；原文提供 DOI、原参考链接、试验号或试验注册链接时，至少一种可追踪信息随研究出现，没有只剩研究简称和结果数据；
- 推荐方向、推荐强度/证据等级和实施条件保持区分；统计学意义没有替代临床重要性，替代终点/机制信号没有被直接写成患者获益，探索性亚组和观察性关联使用与设计相称的措辞；
- 最终 XML 至少有两个白板块：全局导读图和原文解读主章节中的重点内容图；如使用对比表，其位置、字段和内容与所在小节及来源一致；
- 片段没有冒充全文，缺失元数据没有被猜测；
- 文章类型框架没有变成可见的固定目录；
- 内容小节顺序与当前文献的信息结构一致：研究论文保持论证路径，指南保持临床决策路径，其他类型保持其主题、时间或操作主线；
- 不使用“证明”“必然”“适用于所有人”等超出设计的措辞；
- 写入前的最终 XML 不存在 `<sup>` 或转义上标。

## 最终回执

- 聊天内回答：直接交付答案或总结；按文章复杂度使用必要的小标题、段落、列表、加粗或 Markdown 表格，说明来源边界，并自然询问是否需要完整解读。不得显示任何内部模式名。
- 飞书完整解读：用户提出具体问题或要求时，文档外回复先依据文章直接回答其关注的答案，并保留必要的关键依据和边界，再给文档链接和实际来源范围。这一文档外答复可根据问题灵活使用自然段、小标题、列表、加粗或 Markdown 表格；有清晰比较维度时可优先用表格降低理解成本，不要为了形式强行造表。不得只回复文档已完成或用泛化结论代替答案。没有具体问题时，先给简洁核心结果，再给文档链接。不在聊天中复制整篇报告。最后可自然询问是否需要进一步调研相关研究、证据脉络和研究空白；未经用户确认不自动执行，也不解释内部 Skill 路由。
