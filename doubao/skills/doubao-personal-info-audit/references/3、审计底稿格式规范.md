# 审计底稿格式规范

## 一、原则

底稿必须支持从审计意见反向追溯至发现、适用规则、处理情形、法律角色、处理活动、数据分类、不确定性、事实和原始证据。不得以26行模块汇总替代107个审计子项，也不得跳过“证据—事实—不确定性—数据分类—处理活动—法律角色—处理情形—适用规则—审计结论—风险—整改”中的任何环节。

CSV用于增量写入，XLSX用于复核和交付。所有CSV使用UTF-8 with BOM；一张表只保存一种记录类型；每行使用稳定唯一编号。

## 二、工作簿结构

正式工作簿包含16张工作表，顺序固定：

1. 附件与证据目录；
2. 事实与不确定性；
3. 证据矛盾与未决事项；
4. 信息分类；
5. 处理活动与角色；
6. 处理情形与模块适用性；
7. 第三方委托与跨境链路；
8. AI系统与自动化决策；
9. AI高风险专项分析；
10. 法规文献数据库；
11. 法规版本台账；
12. 适用规范矩阵；
13. 主要问题与整改；
14. 审计程序点检；
15. 107项点检；
16. 审计分析链。

模板位于`assets/templates/`。不得删除空模板或通过合并单元格改变表头。

## 四、107项点检最低字段

每个子项必须有独立行，至少填写：

1. 子项编号和模块；
2. 适用性和排除理由；
3. 审计结论；
4. 关联F事实；
5. E证据及精确定位；
6. 直接法源及条、款、项；
7. 辅助标准及章节；
8. 事实与法定要件对应；
9. 相反证据或管理层解释；
10. 风险等级及理由；
11. 待补材料和核验程序；
12. 对应C发现；
13. 对应的U、D、A、RO、SC、NR、RK、RM编号及11环节链条编号；
14. 编制人、复核人和复核日期。

确定性结论没有直接法源或具体证据定位时，校验应失败。

## 五、结论和值域

审计结论只允许：合规、部分合规、不合规、无法判断、不涉及。

事实状态只允许：已确认、材料未提及、线索存在但证据不足、证据冲突、积极证据证明不存在。

法源状态只允许：现行、尚未施行、失效、部分失效、草案、动态核验。

风险等级只允许：重大、重要、一般、轻微、待确认。风险等级不得替代审计结论。

## 六、证据要求

证据目录必须记录：真实文件名、版本、日期、作者或来源、取得方式、页码/条款/单元格/日志定位、文件哈希、完整性、证据等级、保密等级、支持事实和限制。

证据等级建议：

- A：可复现的系统配置、日志、测试或权威第三方记录；
- B：正式合同、审批、签署制度或连续执行记录；
- C：访谈、声明、单次截图或未闭环材料；
- D：未经验证线索、文件名或二手转述。

D级证据不得单独支持确定性结论。

## 七、格式

1. 工作表表头冻结，开启筛选，隐藏网格线。
2. 表头深蓝底白字，仅用于底稿导航；结论同时显示文字，不依赖颜色。
3. 表头10 pt加粗，正文9 pt；中文使用微软雅黑，英文和数字使用Arial或Times New Roman，但同一工作簿保持一致。
4. 所有单元格自动换行并顶端对齐；短编号、日期、状态列居中。
5. 明确设置列宽，不使用等宽列；叙述列宽于编号列。
6. 禁止固定行高造成裁切，禁止合并数据单元格，禁止在一格中用空格模拟表格。
7. URL只放在法规文献数据库或证据目录的专用字段。

## 八、生成和校验

将16个模板复制到项目底稿目录后增量填写，执行：

```text
python scripts/generate_audit_workbook.py <底稿目录>
python scripts/validate_audit_workpaper.py <底稿目录/107项点检.csv>
python scripts/validate_fact_sequence.py <底稿目录>
python scripts/validate_analysis_chain.py <底稿目录/审计分析链.csv>
python scripts/validate_audit_package.py <底稿目录>
```

校验通过后人工复核：

1. 107个子项无缺号、无重复、无空结论；
2. 不涉及项均有积极排除事实；
3. 合规项均有实际履行证据；
4. 不合规项均有直接法源、违反事实和证据链；
5. 无法判断项均有最小补证材料；
6. 每个C发现均按E→F→U→D→A→RO→SC→NR→C→RK→RM完整排列，并引用直接上游；
7. Word报告统计与Excel完全一致；
8. 法规版本台账和文献数据库状态与审计基准日一致。
