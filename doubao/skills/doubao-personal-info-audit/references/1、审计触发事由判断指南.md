# 审计触发事由判断指南

本文档提供"触发事由→审计建议"的完整判断逻辑，用于根据用户输入的触发事由快速定位审计类型并提供针对性建议。

**触发场景**：用户输入触发事由，需要快速获取审计建议

**使用原则**：仅在需要判断审计类型和提供建议时读取

---

## 1. 触发事由分类体系

根据《个人信息保护法》《个人信息保护合规审计管理办法》《网络数据安全管理条例》《未成年人网络保护条例》的规定，审计触发事由分为两大类：

### 1.1 自行定期审计类触发事由（个保法第54条）

| 触发事由 | 审计频率 | 法律依据 |
|---------|---------|---------|
| 处理个人信息超过1000万人 | 每2年至少1次 | 《个人信息保护合规审计管理办法》（国家互联网信息办公室令第18号）第四条 |
| 处理个人信息超过100万、不超过1000万人 | 宜每4年至少1次 | GB/T 46903-2025第4.2.4条b）（推荐性标准） |
| 处理个人信息不超过100万人 | 宜每5年至少1次 | GB/T 46903-2025第4.2.4条c）（推荐性标准） |
| 处理未成年人（未满18周岁）个人信息 | 每年至少1次 | 《未成年人网络保护条例》第三十七条 |

**注意**：
- 《管理办法》第四条仅对"超过1000万人"设定法定审计频次义务，100万以下各档频次来自推荐性国标
- 100万至1000万人及不超过100万人的频次为GB/T 46903-2025推荐性建议（"宜"），结合《个保法》第54条"定期审计"原则作为实施参考
- 未成年人个人信息处理者的审计需将审计情况及时报送所在地设区的市级网信部门

### 1.2 监管强制审计类触发事由（个保法第64条）

| 触发事由 | 审计时机 | 法律依据 |
|---------|---------|---------|
| 发现个人信息处理活动存在严重影响个人权益 | 按监管要求 | 《个人信息保护合规审计管理办法》第5条第（一）项 |
| 发现个人信息处理活动严重缺乏安全措施等较大风险 | 按监管要求 | 《个人信息保护合规审计管理办法》第5条第（一）项 |
| 个人信息处理活动可能侵害众多个人的权益 | 按监管要求 | 《个人信息保护合规审计管理办法》第5条第（二）项 |
| 发生个人信息安全事件，导致100万人以上个人信息泄露、篡改、丢失、毁损 | 按监管要求 | 《个人信息保护合规审计管理办法》第5条第（三）项 |
| 发生个人信息安全事件，导致10万人以上敏感个人信息泄露、篡改、丢失、毁损 | 按监管要求 | 《个人信息保护合规审计管理办法》第5条第（三）项 |

## 3. 触发事由→审计建议映射表

### 3.1 自行定期审计（个保法第54条）建议模板

#### 触发事由：处理个人信息超过1000万人

**审计类型**：法定定期审计

**审计频率**：每2年至少开展1次

**审计机构**：
- 方式一：个人信息处理者内部机构
- 方式二：委托外部专业机构

**审计时限**：无相关要求

**问题整改**：无相关要求

**其他要求**：
- 处理100万人以上个人信息的，应当指定个人信息保护负责人负责个保审计工作
- 提供重要互联网平台服务、用户数量巨大、业务类型复杂的，应当成立主要由外部成员组成的独立机构对个保审计进行监督

**法律依据**：
- 《中华人民共和国个人信息保护法》第五十四条："个人信息处理者应当定期对其处理个人信息遵守法律、行政法规的情况进行合规审计。"
- 《个人信息保护合规审计管理办法》第四条："处理超过1000万人个人信息的个人信息处理者，应当每两年至少开展一次个人信息保护合规审计。"

---

#### 触发事由：处理未成年人（未满18周岁）个人信息

**审计类型**：未成年人个人信息保护专项审计

**审计频率**：每年至少开展1次

**审计机构**：
- 方式一：个人信息处理者内部机构
- 方式二：委托外部专业机构

**审计时限**：无相关要求

**问题整改**：无相关要求

**其他要求**：
- 应当制定专门的未成年人个人信息处理规则
- 处理不满14周岁未成年人个人信息应当取得监护人同意

**法律依据**：
- 《未成年人网络保护条例》第三十七条："个人信息处理者应当自行或者委托专业机构每年对其处理未成年人个人信息遵守法律、行政法规的情况进行合规审计，并将审计情况及时报告网信等部门。"

---

### 3.2 监管强制审计（个保法第64条）建议模板

#### 触发事由：个人信息处理活动存在较大风险

**触发条件**：
- 发现个人信息处理活动存在严重影响个人权益，或
- 严重缺乏安全措施等较大风险，或
- 个人信息处理活动可能侵害众多个人的权益

**审计类型**：监管强制审计

**审计频率**：按照保护部门要求开展

**审计机构**：必须委托外部专业机构

**审计时限**：
- 保护部门限定时间内完成
- 情况复杂的，报保护部门批准后可适当延长

**审计报告要求**：
- 将外部专业机构出具的审计报告报送保护部门
- 外部专业机构主要负责人、合规审计负责人签字
- 加盖外部专业机构公章

**问题整改**：
- 按照保护部门要求对审计中发现的问题进行整改
- 整改完成后15个工作日内向保护部门报送整改情况报告

**其他要求**：无相关要求

**法律依据**：
- 《中华人民共和国个人信息保护法》第六十四条："履行个人信息保护职责的部门在履行职责中，发现个人信息处理活动存在较大风险或者发生个人信息安全事件的，可以按照规定的权限和程序对该个人信息处理者的法定代表人或者主要负责人进行约谈，或者要求个人信息处理者委托专业机构对其个人信息处理活动进行合规审计。个人信息处理者应当按照要求采取措施，进行整改，消除隐患。"
- 《个人信息保护合规审计管理办法》第五条："个人信息处理者有以下情形之一的，国家网信部门和其他履行个人信息保护职责的部门（以下统称为保护部门），可以要求个人信息处理者委托专业机构对个人信息处理活动进行合规审计：（一）发现个人信息处理活动存在严重影响个人权益或者严重缺乏安全措施等较大风险的；（二）个人信息处理活动可能侵害众多个人的权益的；（三）发生个人信息安全事件，导致100万人以上个人信息或者10万人以上敏感个人信息泄露、篡改、丢失、毁损的。"

---

#### 触发事由：发生重大个人信息安全事件

**触发条件**：
- 导致100万人以上个人信息泄露、篡改、丢失、毁损，或
- 导致10万人以上敏感个人信息泄露、篡改、丢失、毁损

**法律性质说明**：发生重大安全事件属于《管理办法》第5条第（三）项规定的"保护部门可以要求审计"的法定情形。在保护部门尚未发出审计要求时，处理者应依据《个保法》第57条履行事件报告义务并采取补救措施，但不自动产生"必须委托外部专业机构审计"的强制义务。如保护部门据此发出审计要求，则适用下述监管强制审计路径。

**审计类型**：监管强制审计（须以保护部门实际发出审计要求为前提）

**审计频率**：按照保护部门要求开展

**审计机构**：必须委托外部专业机构

**审计时限**：
- 保护部门限定时间内完成
- 情况复杂的，报保护部门批准后可适当延长

**问题整改**：
- 按照保护部门要求对审计中发现的问题进行整改
- 整改完成后15个工作日内向保护部门报送整改情况报告

**其他要求**：对同一个人信息安全事件或者风险，不得重复要求个人信息处理者委托专业机构开展个人信息保护合规审计

**法律依据**：
- 《中华人民共和国个人信息保护法》第五十七条："发生或者可能发生个人信息泄露、篡改、丢失的，个人信息处理者应当立即采取补救措施，并通知履行个人信息保护职责的部门和个人。"
- 《中华人民共和国个人信息保护法》第六十四条："履行个人信息保护职责的部门在履行职责中，发现个人信息处理活动存在较大风险或者发生个人信息安全事件的，可以按照规定的权限和程序对该个人信息处理者的法定代表人或者主要负责人进行约谈，或者要求个人信息处理者委托专业机构对其个人信息处理活动进行合规审计。个人信息处理者应当按照要求采取措施，进行整改，消除隐患。"
- 《个人信息保护合规审计管理办法》第五条第（三）项："发生个人信息安全事件，导致100万人以上个人信息或者10万人以上敏感个人信息泄露、篡改、丢失、毁损的。"

## 4. 审计建议输出格式

### 4.1 标准输出格式

当用户输入触发事由后，按以下格式输出审计建议：

```
【审计类型判断】

根据您提供的触发事由，判断审计类型为：
- 审计类型：【自行定期审计/监管强制审计】
- 法律依据：【个保法第54条/个保法第64条】
- 触发情形：【具体触发条件】

【审计要求】

1. 审计频率：【具体要求】
   
   法律依据：【条款原文】

2. 审计机构：【具体要求】
   
   法律依据：【条款原文】

3. 审计时限：【具体要求】
   
   法律依据：【条款原文】（如适用）

4. 审计报告：【具体要求】
   
   法律依据：【条款原文】

5. 问题整改：【具体要求】
   
   法律依据：【条款原文】（如适用）

6. 其他要求：【具体要求】
   
   法律依据：【条款原文】（如适用）

【下一步建议】

根据以上分析，建议您：
1. 【具体建议1】
2. 【具体建议2】

请问您是否需要进一步了解审计流程，或直接开始审计工作？
```

## 5. 特殊情形处理

### 5.1 多项审计义务并存

当用户同时符合多项触发事由时：

```
【多项审计义务提示】

根据您提供的情况，贵单位同时触发多项审计义务：

1. 【触发事由1】→ 【审计类型1】
   - 审计频率：【】
   - 报送要求：【】

2. 【触发事由2】→ 【审计类型2】
   - 审计频率：【】
   - 报送要求：【】

【处理建议】
- 不同类型审计可合并开展，也可分别开展
- 各项报送要求需分别履行
- 如选择合并开展，建议在审计报告中明确区分各审计类型

【法律依据】
【各触发事由对应的法律条款】
```

### 5.2 触发事由不明确

当用户输入的触发事由无法直接匹配时：

```
【触发事由确认】

您描述的情况为：【用户输入】

为准确判断审计类型，请确认以下信息：

1. 贵单位处理的个人信息总量大约是多少？
   - A. 超过1000万人
   - B. 100万-1000万人
   - C. 不满100万人
   - D. 不确定

2. 是否处理不满14周岁未成年人的个人信息？
   - A. 是
   - B. 否
   - C. 不确定

3. 是否发生过个人信息安全事件？
   - A. 是（请说明影响范围）
   - B. 否

4. 是否收到监管部门要求审计的通知？
   - A. 是
   - B. 否

请回复以上问题，我将为您提供准确的审计建议。
```

### 5.3 未规定固定法定周期的审计情形

《个人信息保护法》第五十四条对个人信息处理者设定定期合规审计义务。现行规章未对所有人数档规定固定周期时，按以下方式输出：

```
【定期审计义务与周期建议】

根据您描述的情况：【用户输入】

贵单位仍负有定期开展个人信息保护合规审计的法定义务；但除特别规定外，现行法律、行政法规和部门规章未对该人数档规定统一的固定周期。建议根据风险制定周期，并参考推荐性国家标准。

【周期和提前启动因素】
1. 处理超过100万、不超过1000万人个人信息：可参照GB/T 46903—2025推荐性安排，宜每4年至少开展1次
2. 处理不超过100万人个人信息：可参照该推荐性标准，宜每5年至少开展1次
3. 业务发生重大变更时：建议提前开展审计
4. 发布新的个人信息处理规则时：建议验证合规性
5. 发生个人信息安全事件后：除依法处置和报告外，建议及时开展专项复核；是否必须委托外部审计取决于保护部门是否依《管理办法》第五条提出要求
6. 监管政策发生重大变化时：建议评估政策影响
7. 内部合规管理体系建立或优化时：建议验证有效性

【自主审计的作用】
- 主动识别和防控合规风险
- 提前准备应对监管检查
- 提升企业个人信息保护水平
- 增强用户信任和企业声誉

【法律依据】
《中华人民共和国个人信息保护法》第五十四条："个人信息处理者应当定期对其处理个人信息遵守法律、行政法规的情况进行合规审计。"

请问是否需要我协助制定风险导向审计周期并启动本次审计？
```

## 7. 使用说明

### 7.1 判断流程

1. **接收用户输入**：获取用户描述的触发事由
2. **关键词匹配**：识别触发事由类型
3. **类型确认**：确认属于自行定期审计还是监管强制审计
4. **输出建议**：按标准格式输出审计建议
5. **后续引导**：引导用户进入审计流程

### 7.2 优先级规则

当用户输入涉及多个触发事由时，按以下优先级判断：

1. **最高优先级**：监管强制审计（已收到监管通知）
2. **次高优先级**：未成年人年度审计及报告义务
3. **固定周期优先级**：处理超过1000万人每两年至少一次
4. **一般定期审计**：其他个人信息处理者依《个人信息保护法》第五十四条定期开展，周期按风险确定并可参考推荐性国标
5. **事件专项**：安全事件先履行补救、通知和报告义务；只有保护部门实际提出要求时，才进入监管要求委托专业机构审计路径

### 7.3 注意事项

1. 所有法律条款引用必须准确，标注具体条款号
2. 区分"法定要求"和"建议"，避免误导用户
3. 多项审计义务并存时，必须明确告知
4. 监管强制审计必须强调"必须委托外部专业机构"
