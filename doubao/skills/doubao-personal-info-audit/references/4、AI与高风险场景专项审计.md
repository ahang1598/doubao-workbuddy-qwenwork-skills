# AI与高风险场景专项审计

## 目录

1. 适用范围
2. AI系统清单
3. 风险分流
4. AI事实顺序分析
5. 专项审计域
6. 供应商审查
7. 证据、结论与输出

## 一、适用范围

涉及模型训练、微调、检索增强、提示词、用户输入输出、算法推荐、画像、排序、定价、招聘风控、人脸/声纹、生物识别、生成合成内容、AI代理或AI供应商时，除26模块107项外强制执行本专项。

先判断组织在每个活动中的身份：自研模型提供者、应用提供者、API调用方、部署/运维方、数据提供方、委托方、受托人、共同处理者或独立处理者。产品名称和合同标签不能替代实际控制权分析。

## 二、AI系统清单

每个系统至少记录：系统编号、名称、业务负责人、技术负责人、开发/采购方式、模型/版本、部署位置、业务目的、用户群体、输入、输出、训练/微调/RAG数据、是否含个人信息/敏感信息/未成年人信息、决策影响、人工复核、供应商、下游接收方、跨境路径、日志保存、上线日期、算法备案/安全评估/伦理审查/标识状态和退出计划。

遗漏系统比错误评级更危险。通过采购台账、云账单、API密钥、代码仓库、浏览器插件、员工访谈、数据流和供应商清单交叉发现“影子AI”。

不得只依赖业务部门申报。至少把采购/付款、云资源、域名和网络出口、API密钥、代码依赖、模型网关、浏览器插件、员工报销、数据流、供应商和安全日志相互核对。对每个线索分别记录“已确认系统”“疑似系统待核验”或“积极证据排除”，并引用E/F/U编号。

## 三、风险分流

出现任一情形即进入增强审计：

- 使用敏感个人信息、不满14周岁信息、大规模数据或来源不明训练数据；
- 对就业、信贷、保险、医疗、教育、价格、内容分发或人身安全产生显著影响；
- 具有舆论属性、社会动员能力、深度合成或生成合成内容传播能力；
- 模型可能记忆、推断、输出或泄露个人信息；
- 境外模型/API可访问境内个人信息或供应商保留输入用于训练；
- 缺少人工复核、解释、申诉、关闭个性化或非AI替代方式；
- 发生越权调用、提示注入、数据投毒、模型反演、成员推断或敏感输出。

每个触发条件必须记录对应F/U/D/A/RO/SC和证据定位。不能确认是否触发时，仍进入增强审计的核验阶段，结论标记“证据不足”，不得以未提供材料推定低风险。

## 四、AI事实顺序分析

AI专项不得另起一套与主审计脱节的分析逻辑。对每个系统和用例按以下顺序回写主分析链：

| 顺序 | AI专项分析对象 | 最低记录及分支 |
|---:|---|---|
| 1 | E证据 | 系统申报、架构、代码/API、模型卡、数据集、配置、合同、日志、测试、备案/评估材料的真实名称和定位；区分宣传、约定与实际行为 |
| 2 | F事实 | 分别记录模型训练、微调、RAG入库/检索、提示词输入、在线推理、输出、反馈、人工审核、日志、二次训练、跨境访问和删除；不同模型版本/环境/期间分开 |
| 3 | U不确定性 | 对模型来源、数据授权、供应商训练保留、模型记忆、境外访问、人工复核覆盖率、标识和备案状态提出竞争性假设、最小补证及测试程序 |
| 4 | D数据分类 | 对训练/微调/RAG/评测数据、提示词、输出、反馈、向量、画像、推断数据和日志分别判断个人信息、敏感性、未成年人及匿名化 |
| 5 | A处理活动 | 按业务目的拆分数据准备、训练、部署、推理、决策、内容生成、监控、人工审核、供应商处理、下游传播和退出删除活动 |
| 6 | RO法律角色 | 分别判断模型提供者、应用提供者、API调用方、部署/运维方、数据提供方、委托/受托、共同处理、独立接收方、出境方；以实质决定权为准 |
| 7 | SC处理情形 | 判断自动化决策、显著影响、算法推荐、深度合成、生成式AI、内容标识、拟人化互动、科技伦理、敏感/未成年人、跨境、PIA/AIA等情形 |
| 8 | NR适用规则 | 按服务对象、主体身份、功能、传播能力、行业和基准日匹配具体规则；不得因使用“AI”名称机械套用全部规则 |
| 9 | C审计结论 | 采用五档合规结论，写明系统、模型版本、环境、用例、数据、期间和证据边界 |
| 10 | RK风险 | 分别评价个人权益、偏差歧视、内容/伦理、安全、模型泄露、监管、供应商、跨境、业务连续性和不可逆影响 |
| 11 | RM整改 | 先核验未知事实，再设计数据治理、功能控制、人工监督、标识、备案评估、安全测试、供应商条款、监控和退出措施 |

### （一）模型与数据流拆分

对下列对象分别建事实和活动，不得合并成“使用AI”：数据采集/购买；清洗标注；预训练或第三方基座模型；微调；RAG知识库和向量化；提示词和会话；在线推理；生成输出；内容传播；用户反馈；人工审核；安全日志；再训练；模型/知识库/缓存/日志删除。

记录每一步的数据控制人、物理位置、可访问人员、供应商/分包商、保留期限、是否用于产品改进或训练、跨境路径和退出方式。

### （二）测试与实际行为证据

制度、模型卡和供应商承诺不得替代测试。根据风险至少实施：权限和越权调用测试、提示注入、敏感输出、训练数据记忆/复现、模型反演或成员推断的适当测试、内容标识及元数据检查、人工复核抽样、拒绝/解释/申诉路径、关闭个性化或非AI替代路径、数据删除和供应商“不训练/零保留”配置验证。记录环境、模型版本、提示/样本、步骤、预期、实际结果、截图/日志和可复现性。

### （三）拟人化互动专项

提供持续性拟人化情感互动服务时，核验《人工智能拟人化互动服务管理暂行办法》的适用范围和基准日状态，并检查全生命周期安全、训练与交互数据、敏感交互数据用于训练的单独同意、未成年人模式、身份提示、极端情境处置、依赖沉迷风险、退出机制、评估和算法备案。普通客服、一次性工具或非持续情感互动是否纳入适用范围，应根据实际功能和交互证据判断，不以产品名称决定。

## 五、专项审计域

| 审计域 | 核查问题 | 主要证据 |
|---|---|---|
| 用例合法性 | 目的、合法性基础、必要性、禁止用途、用户预期 | 立项、产品说明、法律评估、用户协议 |
| 数据来源 | 训练/微调/RAG/评测数据是否有合法来源和使用权限 | 数据集清单、授权、许可、采集记录、过滤规则 |
| 个人信息 | 是否履行告知、同意/其他基础、敏感信息、未成年人、权利响应 | 隐私规则、界面、同意日志、DSAR流程 |
| PIA/AIA | 上线前是否评估权益、偏差、安全、可解释性、可逆性和剩余风险 | PIA、AIA、审批、风险接受记录 |
| 自动化决策 | 透明、公平、差别待遇、显著影响、解释、拒绝和人工复核 | 模型卡、特征表、决策规则、申诉记录、偏差测试 |
| 科技伦理 | 是否属于伦理审查范围、是否设委员会、是否复核和持续审查 | 委员会制度、名册、会议、意见、年度报告 |
| 算法/生成式AI | 备案、安全评估、服务协议、投诉、未成年人、内容处置 | 备案回执、评估报告、服务协议、处置日志 |
| 内容标识 | 显式/隐式标识、元数据、传播核验、日志和防篡改 | 产品测试、文件元数据、协议、日志 |
| 安全 | 权限、隔离、加密、日志、红队、提示注入、模型泄露和事件 | 架构、测试、告警、事件记录、修复报告 |
| 人工监督 | 何时必须人工复核、权限、培训、覆盖率和越权处理 | SOP、抽样、复核日志、培训记录 |
| 持续监控 | 漂移、偏差、错误、投诉、版本变更、再评估触发 | 指标、版本记录、监测报告、变更审批 |
| 退出与删除 | 合同终止、模型下线、数据/向量/缓存/日志删除 | 退出计划、删除证明、供应商确认 |
| 拟人化互动 | 持续情感互动、身份提示、敏感交互数据训练、未成年人、极端情境、依赖沉迷和退出 | 产品测试、会话与训练配置、同意日志、模式设置、风险评估、事件记录 |

重点核验《互联网信息服务算法推荐管理规定》《互联网信息服务深度合成管理规定》《生成式人工智能服务管理暂行办法》《人工智能生成合成内容标识办法》《人工智能拟人化互动服务管理暂行办法》《科技伦理审查办法（试行）》、GB 45438—2025以及个人信息和行业规则。按实际主体、服务对象、功能、传播能力和用途判断适用，不机械全量套用。

## 六、供应商审查

AI供应商协议至少审查：

1. 输入、输出、日志、反馈和派生数据的权属与处理角色；
2. 是否默认用于训练、人工审核或产品改进，能否关闭，关闭是否覆盖历史数据；
3. 分包商、模型提供商、云服务商及其地点；
4. 跨境远程访问、数据驻留、政府调取和冲突法处理；
5. 安全措施、事件通知时限、审计权、渗透/红队报告和认证；
6. 数据保留、删除、备份、模型记忆和终止协助；
7. 侵权、个人信息、训练数据来源、偏差和监管处罚责任；
8. 模型/条款/分包商变化通知和重新评估权；
9. 输出准确性、人工复核、禁止用途和用户告知责任；
10. 监管配合、证据保存和争议解决。

供应商“零数据保留”“不训练”等宣传材料仅为线索；以合同、控制台配置、技术文档、日志和测试共同验证。

当供应商同时提供基座模型、云托管、人工审核或安全监控时，分别识别各项活动和角色。合同未披露分包商、数据位置、保留期或训练用途时，建立U记录；不得用单一“受托处理”标签覆盖供应商自主训练、产品改进或跨客户使用。

## 七、证据、结论与输出

形成AI专项附件：AI系统清单、AI高风险专项分析表、数据与模型流图、法律角色矩阵、PIA/AIA/伦理审查状态、备案与标识状态、供应商风险表、测试结果、残余风险和上线/暂停建议。所有专项记录必须引用主分析链编号。

AI结论使用：`允许上线`、`附条件上线`、`暂停上线`、`停止使用/下线`、`证据不足`。该业务决策不得替代107项的合规结论和风险等级。

只有同时满足系统和版本已确认、关键数据流已查明、增强审计触发已判断、适用规则已核验、必要测试已完成、重大不确定性已处置或明确接受、整改条件具有可测试验收标准时，方可输出“允许上线”或“附条件上线”。否则输出“证据不足”或更审慎的业务建议。
