# 法规与资料输出引注规范

## 一、目标

引注必须同时实现：读者可读、法源准确、版本可核、观点明确、证据可追溯、正文不被长网址淹没。

采用“问题法条表展示具体规则 + 正文/分析表精确短引注 + 附件完整著录 + 底稿双向索引”的四层结构。

## 二、编号体系

| 类型 | 编号 | 内容 |
|---|---|---|
| 法律 | L001… | 全国人大及其常委会制定的法律 |
| 行政法规 | AR001… | 国务院制定的行政法规；AR前缀避免与处理活动A编号冲突 |
| 其他直接或配套法源 | R001… | 部门规章、司法解释、地方规则、规范性文件；必须另列具体法律形式 |
| 标准与指南 | S001… | 强制性/推荐性标准、实践指南 |
| 案例与决定 | J001… | 裁判文书、指导性案例、行政处罚决定 |
| 政策动态材料 | P001… | 政策问答、公告、指南、草案和新闻发布 |
| 审计证据 | E001… | 用户材料、系统记录、访谈、测试结果 |
| 原子事实 | F001… | 由一项或多项证据支持的事实 |
| 审计发现 | C001… | 结论、风险、整改和复核闭环 |
| 不确定性 | U001… | 证据缺口、冲突、替代解释和核验程序 |
| 数据分类 | D001… | 个人信息属性、敏感性和匿名化判断 |
| 处理活动 | A001… | 目的、处理动作、系统和数据流 |
| 法律角色 | RO001… | 处理者、共同处理、受托、接收方等 |
| 处理情形 | SC001… | 触发的专项处理场景 |
| 适用规则 | NR001… | 具体法源、规则要件、例外和效力 |
| 风险 | RK001… | 风险等级、影响范围、期间和理由 |
| 整改 | RM001… | 整改目标、措施、责任、期限和验收 |

同一来源全文只分配一个编号。不同版本、不同发布机关文本或效力状态不同的文件分别编号。

## 三、效力与来源规则

### （一）效力顺序

先识别正式法律形式，再判断效力、制定权限、地域、行业、主体、行为期间和具体触发条件。不得将所有文件机械排成一条绝对顺序。通常至少区分：

1. 法律；
2. 行政法规；
3. 地方性法规、自治条例和单行条例、规章等依法制定的规范；
4. 司法解释、规范性文件和行业特别规则；
5. 强制性国家标准；
6. 推荐性国家标准和实践指南；
7. 裁判、执法案例和政策材料；
8. 学术和商业二手资料。

《中华人民共和国立法法》第九十八条至第一百零三条是层级及规则冲突判断的基础：法律效力高于行政法规、地方性法规和规章；行政法规效力高于地方性法规和规章；地方性法规在本行政区域内高于本级和下级地方政府规章；部门规章之间、部门规章与地方政府规章之间不得机械认定高低；同一机关制定的特别规定/一般规定、新规定/旧规定按专门规则处理。以上为规则摘要，非原文，使用时须核验审计基准日官方文本。〔L006，第九十八条至第一百零三条〕

### （二）上下位法及配套规范衔接

每个适用规则`NR###`必须先确定上位法基础义务，再检索同事项的下位法和配套规范：

1. 事实满足细化规范的主体、地域、行业、数据类型、处理动作、规模、技术场景、行为期间及例外条件时，正文同时引用上位法和该细化规范；先写基础义务，再写细化要求，并注明“下位法细化补充”或“配套规范实施补充”。
2. 事实不满足细化规范触发条件时，正文仅引用上位法；在`适用规范矩阵.csv`记录候选细化规范、积极排除事实、证据编号和排除理由。
3. 仅因材料未提及而不能判断时，正文以上位法作为当前基础依据，候选细化规范标为“待确认”，不得形成确定性不合规结论。
4. 没有检索到现行细化规范时，正文仅引用上位法；底稿记录检索范围、日期和复核人，不使用“绝对不存在”的表述。
5. 细化规范疑似越权、抵触或效力状态不明时，不得以其直接形成不合规结论，应回到有效上位法并提交复核。

“下位法”只用于已核实法律形式和层级关系的规范。司法解释、规范性文件、政策问答、标准和实践指南分别按其真实属性标注，不得因内容更具体而统称为下位法。特别法/一般法、新法/旧法关系也不等同于上下位关系。详细步骤见`references/5、上下位规范衔接与引用规则.md`。

### （三）来源优先级

优先使用：国家法律法规数据库、中国人大网、中国政府网/国家行政法规库、中国网信网、最高人民法院/最高人民检察院、国家标准全文公开系统、国务院部委官网。

商业数据库、律所文章、媒体、公众号和搜索摘要只可作为检索线索。未回到官方文本核验，不得作为确定性直接法源。

### （四）版本状态

每个规范必须标记：现行、尚未施行、已失效、部分失效、草案或动态核验。

- 尚未施行规则只进入“后续合规准备”，不得评价施行前行为。
- 草案不得作为确定性义务或不合规结论依据。
- 历史行为适用行为时规范；持续行为按各期间分别评价。
- 推荐性标准不得写成法定强制义务，除非上位法、监管决定或合同明确使其成为具体义务，并说明转化依据。

## 四、正文引用

### （一）强制法条表

每个主要问题必须先设置“参考法条与规范”表，至少包含：

| 法源编号及层级 | 规范名称及条款 | 具体规则内容 | 本案对应要件及效力说明 |
|---|---|---|---|
| L001（法律/强制） | 《中华人民共和国个人信息保护法》第二十九条 | 基于个人同意处理敏感个人信息的，应当取得个人的单独同意。（经官方文本核对的必要原文或准确摘要） | 是否处理敏感个人信息、是否基于同意、是否取得单独同意；基准日现行，直接适用 |
| R0XX（部门规章/强制；下位法细化补充） | 《【细化规范全称】》第【Y】条 | 【经官方文本核对的必要原文，或标明“规则摘要，非原文”】 | 细化L001第【X】条的【事项】；F【】/SC【】满足触发条件；权限、效力及冲突已核验；本案适用 |

“具体规则内容”必须展示本案实际依赖的规范内容，不得只写法规名称、条号、“相关规定”或“详见附件”。逐字引语须核对官方文本并加引号；准确转述须标注“规则摘要，非原文”。标准须说明具体控制要求和强制属性。

### （二）直接法源

首次引用使用完整名称、具体条款、规则内容和编号：

> 《中华人民共和国个人信息保护法》第二十九条要求，基于个人同意处理敏感个人信息的，应当取得个人的单独同意。〔L001，第二十九条〕

后续引用仍须保留具体条款：

> 前述人脸信息处理还应在事前开展个人信息保护影响评估。〔L001，第五十五条第一款第（三）项〕

禁止只写“根据相关法律法规”“依据监管要求”或“根据L001”。编号不能替代规范名称、条款和论证。

同一事项的下位法或配套规范适用时，使用组合短引注：

> 《中华人民共和国个人信息保护法》第【X】条确立【基础义务】；《【细化规范全称】》第【Y】条针对【本案已确认情形】进一步规定【具体要求】。〔L001，第X条；R0XX，第Y条〕

候选细化规范不适用时，不得出现在正文组合引注中；排除过程留在规范矩阵。法条表对实际适用的上位法和细化规范分别成行，不得把两个规范压缩为无法分辨来源的一段摘要。

### （三）标准

首次引用须说明标准属性：

> 推荐性国家标准GB/T 46903—2025《数据安全技术 个人信息保护合规审计要求》第6章提出……〔S001，第6章〕

> 强制性国家标准GB 45438—2025《网络安全技术 人工智能生成合成内容标识方法》第5.2条要求……〔S007，第5.2条〕

“GB/T”不得写成“强制性国家标准”。标准名称前保留完整编号和年代号。

### （四）证据

> 根据《SDK清单（V3.2）》工作表“SDK”第18行，应用在登录场景向某SDK传输设备标识符。〔E012，工作表“SDK”，第18行〕

证据引用必须包含E编号、真实文件名、版本或日期、精确定位和与结论相关的内容。仅写“企业提供材料”“相关截图”无效。

### （五）案例和政策材料

案例须说明可比与不可比事实：

> 某裁判在【相同事实】范围内具有参考意义，但其【主体/期间/行为】与本案不同，不直接决定本案结论。〔J001，案号及裁判日期〕

政策问答和公告只解释操作口径：

> 国家网信部门在相关政策问答中说明……〔P001，发布日期〕

不得用政策解读、新闻稿或个案处罚代替直接法源。

## 五、审计观点的强制结构

每个观点按“法条表—11环节分析链—整改闭环”展开：

1. 法条表：准确到条、款、项或标准章节，并展示具体规则内容、强制属性和适用说明；
2. 11环节分析链：在同一三列纵向表内严格按E—F—U—D—A—RO—SC—NR—C—RK—RM呈现编号、直接上游和分析内容；
3. 整改闭环：明确责任、期限、验收标准和整改证据。

不得把“已确认事实”“审计证据”“相反证据”“待补数据”拆成相距较远的段落或多个独立表格。任务一的事实主表和任务四的11环节表均须让读者在同一表内看到证据支持、证据缺口和结论边界。

禁止用“存在一定风险”“建议进一步加强”“基本合规”等没有主语、对象和要件的表述代替观点。

## 六、附件完整著录

法源数据库至少包含以下字段：

| 字段 | 要求 |
|---|---|
| 编号 | L/AR/R/S/J/P唯一编号；A仅用于处理活动 |
| 层级 | 法律、行政法规、部门规章、司法解释、规范性文件、标准、案例、政策 |
| 完整名称 | 不使用内部简称 |
| 制定或发布机关 | 使用正式机关名称 |
| 文号/标准号/案号 | 有则必填 |
| 公布日期、施行日期、失效日期 | 使用YYYY-MM-DD |
| 基准日状态 | 现行/尚未施行/失效/草案等 |
| 适用范围 | 主体、地域、行业和行为 |
| 引用条款 | 本项目实际使用条款 |
| 具体规则内容 | 必要原文或准确规则摘要；摘要须标记非原文 |
| 官方URL | 直达正文或标准详情页 |
| 核验日期 | 实际最后核验日 |
| 替代或衔接关系 | 上位依据、下位法或配套规范、旧版本、特别/一般及新/旧规则关系；不得混淆 |

正文不堆叠长URL；URL统一放在附件法源数据库。电子版可将正文短引注链接到附件对应行。

## 七、脚注和其他体例

默认使用方括号式短引注`〔L001，第二十九条〕`。如监管模板或用户要求Word脚注：

1. 将短引注转换为Word真实脚注，不使用手工上标；
2. 脚注首次完整著录，后续使用短称加条款；
3. 内部L/AR/R/S/J/P映射仍保留在底稿；
4. 不同时保留重复的正文括号引注和脚注。

如用户明确要求《法学引注手册》、GB/T 7714或其他体例，优先执行指定体例，但不得丢失内部编号和法源版本字段。

## 八、引语规则

- 直接引语必须逐字核对官方文本并标明条款。
- 转述不得加引号，不得使用“原文规定”字样。
- 为审计分析只摘录必要片段，避免大段复制法规、标准或二手文章。
- 不得补写法规没有的主体、条件、期限或责任。
- 对法条存在多种解释时，分别列明文本依据和理由，不伪装成唯一确定答案。

## 九、交付校验

1. 每个确定性问题至少有一个L、AR或R类直接法源。
2. 每个主要事实至少有一个E类证据和精确定位。
3. 每个C类发现能依次反向链接NR、SC、RO、A、D、U、F、E，并继续链接RK和RM。
4. 法规名称、条号、文号、公布日、施行日、状态和官方URL一致。
5. 适用版本覆盖行为期间和审计基准日。
6. 尚未施行、草案、推荐性标准和政策材料已正确降级标记。
7. 正文无裸URL、Markdown链接、工具引用令牌或搜索摘要。
8. 同一来源编号唯一，无断号、重号或同号异源。
9. 观点明确表达结论、理由、反向证据和限制。
10. 引文校验脚本无错误后方可交付。
11. 每项L/AR/R/S正文引用均能定位到含“具体规则内容”的法条表行。
12. 每项主要事实的证据、冲突、尚不能确认事项和待补数据在同一综合表行或同一单项分析表中呈现。
13. `审计分析链.csv`中的每个C编号均按11环节完整排列，且每一环引用直接上游编号。
14. 每个NR记录均已作“适用/不适用/无下位配套/待确认”判断；适用时组合引用上位法与细化规范，不适用时正文仅引用上位法且底稿有积极排除事实。
15. 规范性文件、政策材料、司法解释、标准及特别/一般、新/旧关系未被错误标注为上下位法关系。
