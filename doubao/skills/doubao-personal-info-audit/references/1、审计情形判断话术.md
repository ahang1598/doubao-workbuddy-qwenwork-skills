# 审计情形判断话术

本文档提供审计情形判断的渐进式引导话术，用于判断用户是否触发法定审计义务。

**触发场景**：用户选择"审计情形完整判断"或咨询"是否需要审计"、"审计要求"等问题

**使用原则**：仅在需要判断审计情形时读取

---

## 1. 开场引导与需求确认

### 情况A：用户选择"审计情形完整判断"

**引导话术**：

"好的，我将帮您全面判断是否需要审计、审计类型及报送义务。

根据《个人信息保护法》《个人信息保护合规审计管理办法》《未成年人网络保护条例》《网络数据安全管理条例》的规定，个人信息处理者普遍负有定期审计义务；另需区分是否存在固定法定周期，以及保护部门是否已经要求委托专业机构审计。

让我先问您几个问题：

**问题1：贵单位处理的个人信息总量大约是多少？**

这里说的'处理'包括收集、存储、使用、加工、传输、提供、公开、删除等活动。'总量'通常以注册用户数或活跃用户数作为参考。

- **A. 超过1000万人** → 法定定期审计，每2年至少1次（应）
- **B. 100万至1000万人** → 定期审计义务为法定；国标建议每4年至少1次（宜，不是法定固定周期）
- **C. 不满100万人** → 定期审计义务为法定；国标建议每5年至少1次（宜，不是法定固定周期）
- **D. 不确定**

请告诉我您的选择。"

### 情况B：用户咨询审计要求

**用户可能的表达**：
- "我是否需要做审计？"
- "什么情况下需要做审计？"
- "我们公司有什么审计要求？"

**引导话术**：

"好的，我来帮您判断贵单位的审计要求。

根据《个人信息保护法》《个人信息保护合规审计管理办法》《未成年人网络保护条例》《网络数据安全管理条例》的规定，所有个人信息处理者均应定期审计；以下继续判断固定周期、特别年度义务及监管要求：

**自行定期审计类**：
1. 处理个人信息超过1000万人 → 每2年至少1次（应）
2. 处理个人信息超过100万、不超过1000万人 → 审计义务为法定；宜每4年至少1次是推荐性周期
3. 处理个人信息不超过100万人 → 审计义务为法定；宜每5年至少1次是推荐性周期
4. 处理未成年人（未满18周岁）个人信息 → 每年至少1次

**保护部门可以要求委托专业机构审计的法定条件**（实际外部委托、报告和整改报送义务以保护部门提出要求为前提）：
1. 个人信息处理活动存在严重影响个人权益或严重缺乏安全措施等较大风险
2. 个人信息处理活动可能侵害众多个人的权益
3. 发生安全事件，导致100万人以上个人信息或10万人以上敏感个人信息泄露、篡改、丢失、毁损

让我先问您几个问题：

**问题1：贵单位处理的个人信息总量大约是多少？**

- **A. 超过1000万人** → 法定定期审计，每2年至少1次（应）
- **B. 100万至1000万人** → 定期审计义务为法定；国标建议每4年至少1次（宜）
- **C. 不满100万人** → 定期审计义务为法定；国标建议每5年至少1次（宜）
- **D. 不确定**

请告诉我您的选择，我将继续判断。"

### 情况C：用户上传材料或表达补充需求

**用户可能的表达**：

- 直接上传文件

**引导话术**：

让我先识别一下您上传的材料类型和内容...

**【材料识别结果】**

我识别到您上传了：
- [材料类型1]：[文件名]
- [材料类型2]：[文件名]

**【当前审计进度判断】**

根据材料情况，我判断您的审计进度为：
- [已完成环节]
- [缺失环节]

**请问您接下来的需求是：**
- **A. 继续推进审计流程** → 我将从当前环节继续，完成后续审计工作
- **B. 开始新的审计** → 我将从头开始引导您完成审计流程

请告诉我您的选择。"

### 情况D：用户咨询具体问题

**用户可能的表达**：
- "隐私政策是否合规？"
- "数据出境怎么处理？"
- "未成年人个人信息保护有什么要求？"

### 情况D：用户需求不明确

**用户可能的表达**：
- 简单的"你好"
- "帮我看看"
- 其他模糊表达

**引导话术**：

"您好！我是个人信息保护合规审计助手。请问您需要：

1. **审计情形完整判断** - 帮您全面判断是否需要审计、审计类型及报送义务
2. **直接开展审计工作** - 已确定需要审计，直接进行审前调查、证据收集、报告编制等

请根据您的实际情况选择，或直接告诉我您的触发事由（如：处理超过1000万人信息、发生数据泄露事件、收到监管通知等）。"

## 2. 渐进式信息收集流程

**这意味着：**

【应】**您需要每2年至少开展1次合规审计（《个人信息保护合规审计管理办法》第四条的法定要求）**

【说明】**普通自行定期审计没有当然向监管部门报送报告的一般要求；只有监管要求审计、未成年人年度审计或其他特别规则触发时，才按相应规定报送。**

- **B. 否**
- **C. 不确定**

请告诉我您的选择。"

## 3. 审计情形判断结论输出

"根据您提供的情况，我为您分析如下：

**【审计情形判断结论】**

经综合分析，贵单位属于：**[审计类型名称]**

**一、审计类型**

[自行定期审计：超过1000万人固定周期/自行定期审计：100万至1000万人无固定法定周期/自行定期审计：不满100万人无固定法定周期/未成年人年度专项/监管可要求审计的事件或风险条件（待确认通知）/监管已要求委托专业机构审计/多项义务并存]

**二、审计频次**

[每2年至少1次（法定）/每4年至少1次（国标建议）/每5年至少1次（国标建议）/每年至少1次/按监管要求/多项频次要求]

**三、执行方式**

[可自行开展或委托专业机构/必须委托专业机构]

如选择委托专业机构：需聘请具有资质的律师事务所、会计师事务所或专业审计机构

**四、报送要求**

[普通自行定期审计无一般报送要求/未成年人审计按规定报送/监管要求审计按通知报送/其他特别规则报送/多项报送要求]

**五、法律依据**

上述判断的法律依据：

1. **《中华人民共和国个人信息保护法》第五十四条**
   '个人信息处理者应当定期对其处理个人信息遵守法律、行政法规的情况进行合规审计。'

2. **《中华人民共和国个人信息保护法》第六十四条**
   '履行个人信息保护职责的部门在履行职责中，发现个人信息处理活动存在较大风险或者发生个人信息安全事件的，可以按照规定的权限和程序对该个人信息处理者的法定代表人或者主要负责人进行约谈，或者要求个人信息处理者委托专业机构对其个人信息处理活动进行合规审计。'

3. **《未成年人网络保护条例》第三十七条**
   '处理不满十四周岁未成年人个人信息的个人信息处理者，应当每年至少开展一次未成年人个人信息保护专项合规审计，并将审计情况报送所在地设区的市级网信部门。'

4. **《网络数据安全管理条例》第二十七条**
   '个人信息处理者应当定期对其个人信息处理活动遵守法律、行政法规的情况进行合规审计。'

5. **《个人信息保护合规审计管理办法》第四条**
   '处理超过1000万人个人信息的个人信息处理者，应当每两年至少开展一次个人信息保护合规审计。'

6. **《个人信息保护合规审计管理办法》第五条**
   '个人信息处理者有以下情形之一的，国家网信部门和其他履行个人信息保护职责的部门，可以要求个人信息处理者委托专业机构对个人信息处理活动进行合规审计：（一）发现个人信息处理活动存在严重影响个人权益或者严重缺乏安全措施等较大风险的；（二）个人信息处理活动可能侵害众多个人的权益的；（三）发生个人信息安全事件，导致100万人以上个人信息或者10万人以上敏感个人信息泄露、篡改、丢失、毁损的。'

7. **国家标准GB/T 46903—2025《数据安全技术 个人信息保护合规审计要求》第4.2.4条**
   - a）处理超过1000万人个人信息的个人信息处理者，应每两年至少开展一次个人信息保护合规审计。
   - b）处理超过100万、不超过1000万人个人信息的个人信息处理者，宜每4年至少开展一次个人信息保护合规审计。
   - c）处理不超过100万人个人信息的个人信息处理者，宜每5年至少开展一次个人信息保护合规审计。
   - d）处理未成年人个人信息的个人信息处理者，应每年对其处理未成年人个人信息遵守法律、行政法规的情况进行合规审计（《未成年人网络保护条例》第37条）。

---

**【多项审计义务并存的说明】**

如贵单位同时符合多项审计情形（如：既处理超过1000万人个人信息，又处理未成年人个人信息），则：
1. 各项审计义务**均需履行**
2. 不同类型审计可合并开展，也可分别开展
3. 报送要求按各审计类型分别履行

---

**【未规定固定法定周期情形下的审计安排建议】**

《个人信息保护法》第五十四条对个人信息处理者设定定期合规审计义务。对于现行法律、行政法规和部门规章未规定固定周期的处理者，应结合处理规模、敏感程度、未成年人、出境、AI、人脸识别、安全事件和业务变更制定风险导向周期；GB/T 46903—2025的频率仅作为推荐性实施参考。

**建议自主审计的情形**：

1. **业务发生重大变更时**
   - 建议在业务模式、处理范围发生重大变更后开展审计
   - 如：新增业务线、开展数据出境、引入第三方合作等

2. **发布新的个人信息处理规则时**
   - 建议在隐私政策等处理规则重大修订后开展审计
   - 验证新规则的合规性和实施效果

3. **发生个人信息安全事件后（非重大事件）**
   - 建议在发生个人信息安全事件（即使未达重大标准）后开展审计
