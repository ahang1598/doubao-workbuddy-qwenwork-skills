# 股票技术分析

只依据当前请求及其附件作答。不得声称存在未实际创建的文件、既往交付或会话事实；不得从其他题目或会话带入标的属性、成本、行情或假设。

## 先选模式

- 单标的趋势、背离、量价、形态、关键位或多周期冲突：读取 [references/single-security.md](references/single-security.md)。
- 按行业、市值、突破、量能、指标等条件筛选股票：读取 [references/market-screening.md](references/market-screening.md)。
- 统计信号后的收益、胜率、MFE、MAE 或去重影响：读取 [references/signal-statistics.md](references/signal-statistics.md)。

所有模式先执行 [references/data-contract.md](references/data-contract.md)，交付前执行 [references/output-contract.md](references/output-contract.md)。任务确需联网时读取 [references/search-policy.md](references/search-policy.md)；封闭材料题不得搜索。附件为 CSV/XLSX 且需要大表计算时，若包内附带 `scripts/` 辅助脚本，可运行：

```bash
python scripts/inspect_market_data.py <file> [<file> ...]
python scripts/compute_indicators.py <csv> --date-col <date> --open-col <open> --high-col <high> --low-col <low> --close-col <close> --volume-col <volume> --output indicators.csv
```

以上为可选快捷路径；脚本不存在时改用 pandas/openpyxl 直接探测列结构并计算。脚本或探测结果不识别列时，显式映射，禁止猜列。

## 不可跳过的门禁

1. 写出口径抬头：标的/市场、`as-of`、时区、频率、数据截止点、复权方式及基准日、指标参数，以及哪些字段由数据源预计算。
2. 逐项建立证据台账。题面给出的数据要么进入计算/判断，要么说明为何不适用；不得用“其余条件均满足”代替核验。
3. 事实、计算、解释、假设分层。题内没有的数字不得作为事实；未实际计算的置信区间、成本、盈亏比或显著性结论不得输出。
4. 只使用 `as-of` 当时已知的数据。未收盘 K 线、当前成分股回看历史、窗口未完成和指标预热不足不得作为确认样本。
5. 区间收益必须使用数据源预计算字段或逐期 `pct_chg` 复合；禁止用 OHLC 首尾自行替代题目指定的收益口径。
6. 缺数据就降级：输出“证据不足/无法判断”、缺失字段及复核条件；不得用量比、换手率等代理筹码集中度，不得虚构周线、复权字段或公司行为。
7. 支撑压力必须写明来源、窗口和证据日期；失效条件至少覆盖价格、量能、时间三个可判定维度。
8. 不保证价格或收益，不给买卖、加减仓、数量或资金安排。

## 路由

- 已有持仓的买卖点、加减仓、止盈止损或交易计划：转 `portfolio-trading-decision`，携带已确认的技术状态和关键位，并请求成本、数量、总资产、期限、流动性与风险约束。
- 显著性检验、参数寻优、代码复现、成本滑点后净值或样本外验证：转 `quant-research`，携带信号定义、股票池、样本区间、频率、基准、复权及成本口径。
- 若当前环境不能调用目标 Skill，只展示入口和待补信息；不要重复调用调用链中已访问的 Skill。

## 最终自检

- 回答是否完整交付用户要求的内容，而非只说“已生成/已交付”？
- 遮住全部附件只看正文，关键结论、名单与数值是否仍然完整自含？
- 是否存在任何来自当前请求之外的事实或数字？
- 是否遗漏题面中的成交量、均线、股票池状态、截止日或异常字段？
- 是否把右删失、幸存者偏差、前视偏差、时间聚类或横截面相关混为一谈？
- 是否保留了明确的限制、反证、复核条件和失效条件？

## 证据、交付与边界门禁

以下门禁优先于篇幅、图表数量和语气自信。它们用于处理“回复看起来完整但不可核验”的情况：

1. **材料与时间锁定**：在分析开头固定标的、市场、`as-of`、时区、数据版本和允许来源。封闭附件题或明确禁搜题不得引入附件外行情、新闻、政策、行业数据或当前市场数字；若确需公开事实，必须按 [search-policy.md](references/search-policy.md) 留下来源、发布时间和检索时间。
2. **关键事实可回接**：每个关键数字、筛选结论和信号判断必须能回接到输入字段、证据日期、公式/参数和来源位置。不能用“已计算”“全部通过”或图表代码替代证据。
3. **交付真实性**：题目点名的 CSV/XLSX/HTML/MD/JSON 等文件，只有在当前运行中实际创建、可打开并检查内容后才算交付。仅有文件名、路径、URL、哈希或“已生成/已验收”的文字不算交付；缺失时写明“未交付/无法核验”，并按核心工件缺失处理。
4. **技术失败优先**：空回复、对象或时点错误、完全跳过核心任务、主工件缺失，先标为技术失败或硬门禁，不与可评答案按篇幅或局部亮点抵消。
5. **研究与执行分离**：技术分析可以给条件性观察和失效条件，不能给买卖、仓位、收益目标、实盘策略或“立即执行”指令。

## 回复质检与五方插入

当任务要求把新增回复 F 加入已有 A-D 盲审时：

1. 先核查 F 是否触发技术失败、材料越界、交付缺失或执行越权，再比较专业深度。
2. 将已校准的 A-D 相对顺序作为硬约束；只有规则明确发现 A-D 原顺序仍有错误时才改动既有相对顺序。
3. 把 F 插入最能由证据支持的位置。五方理由必须写出 F 的具体插入依据、第一名优势、末位主要失败点，以及与原四方结论的差异。
4. 同一问题必须对所有回复使用同一标准；不得因 F 的篇幅、图表数量、文件声称或语气自信给予额外权重。
