# 40 · 私聊舆情询问与使用顾虑

> 附加模块，叠加在售前/履约/售后基础场景之上。适用于客户在私聊中引用外部传言、博主曝光、集中反馈、疑似召回、监管信息或品牌争议，询问真假、是否影响自己、还能不能买/用。本模块只生成客服私聊处置，不做公开公关、媒体回应或品牌危机战略。

## 目录

- 先定舆情级别
- 客户回复必须解决三件事
- 内部边界到客户表达的转换
- 首轮回复优先骨架
- 分支处理规则
- 信息收集字段
- 升级摘要
- 可说与不可说
- 必须交付

## 一、先定舆情级别

不要看到“小红书/网上说/有人反馈”就一律按危机处理；也不要把健康、安全、监管、集中反馈当普通咨询。

| 级别 | 判定 | 主策略 | 客户侧重点 |
|---|---|---|---|
| 使用顾虑 | 未使用/无不适，只是担心还能不能买/用 | 安全基线 + 个体差异 + 使用建议 + 售后兜底 | 回答“我手里的商品怎么办” |
| 个案售后 | 已使用并出现不适/问题，但暂无扩散证据 | 停用/停止使用建议 + 取证 + 售后路径 + 升级 | 先保护客户，再核实处理 |
| 疑似集中反馈 | 外部平台多条反馈、同类私聊增加、疑似同批次/同症状 | 记录升级 + 信息收集 + 临时统一口径 | 收集证据，不下结论 |
| 高风险舆情 | 召回、监管、法律、媒体集中报道、群体投诉、健康安全扩大 | 安全承接 + 立即升级 + 已确认口径优先 | 不判真假、不认责、不辟谣 |
| 已有正式口径 | 品牌/平台已有可引用说明 | 转成自然私聊 + 分支处理 | 不照搬声明腔 |

## 二、客户回复必须解决三件事

无论级别如何，私聊回复都要在客户听得懂的语言里解决三件事。下列是内部生成目标，不要逐字写成客服后台话：
1. **真假边界如何处理**：有官方/品牌已确认口径时按口径说；没有口径时，客户侧表达为“我们已经关注到相关反馈，会把您的情况一起登记核实/反馈”，不要直接说“客服不能判断真假”。
2. **手里商品怎么办**：未拆封、已使用无不适、已使用有不适分别给处理建议。
3. **不放心或已受影响怎么走**：给售后兜底、信息收集触发条件和升级路径；把不能承诺的内容自然转成“我先帮您核实/登记/申请/按规则处理”，不要在客户话术里列“当前不能承诺项”。

不要只说“以官方说明为准”。这句话不能替代客户当下处理方案。

## 三、内部边界到客户表达的转换

先在内部守住事实和权限，再把边界翻译成私聊客服语言。客户可见话术不要出现“客服侧、权限、流程、不能判断、不可承诺、未定论、责任认定”等后台词。

| 内部判断 | 客户侧表达方向 |
|---|---|
| 无品牌正式口径 | “我们已经关注到相关反馈，会把您这边的情况一起记录反馈；我先按您现在的使用状态帮您处理。” |
| 不凭外部传言判真假 | “我先不让您凭网上信息自己猜，我这边帮您把情况登记清楚，后续按统一信息同步。” |
| 不能认定产品责任 | “我先帮您把使用情况、订单和材料记录完整，方便售后/相关同事进一步判断处理。” |
| 不能承诺退款赔偿 | “我先帮您看订单和售后规则，能直接处理的我马上给您走，需要申请的我会一起提交。” |
| 不能承诺官方说明时间 | “有进一步统一信息后，我们会按最新口径更新；现在先把您手里的商品处理好。” |
| 需要收集外部链接/截图 | “您方便把看到的链接或截图发我吗？我会一起反馈，方便团队核实具体来源。” |

禁止把这些内部边界直接抛给客户：
- “目前客服侧不能仅凭外部传言判断真假”；
- “暂时不会对真假下结论”；
- “当前不可承诺退款/赔偿/时限”；
- “这个需要走流程/看权限”；
- “不为难您”“您自行处理”“您自己判断”；
- “正常使用/放心吃/放心用”，除非有明确官方口径和适用条件支撑。

## 四、首轮回复优先骨架

### A. 无正式口径 / 健康安全顾虑

适用于“网上说过敏/出问题是真的吗、刚买还能不能用”等场景。首轮顺序：
1. 承接客户担心；
2. 说明已关注/会记录反馈，不直接复述“真假不能判断”；
3. 按客户状态给当下动作：未使用、已使用无不适、已使用有不适；
4. 给售后或登记路径；
5. 只问一个最能分流的问题。

客户侧表达要像一线客服，不像公告或法务说明。可以说“我先帮您按当前情况处理”，不要说“以官方说明为准”后停止。

### B. 行业舆情波及 / 自家事实清楚

适用于“行业被曝光但未点名我家，我方有正规资质/质检/证件”等场景。首轮顺序：
1. 承接客户对安全或质量的谨慎；
2. 正面说出已确认事实，例如原料、资质、报告、未被点名等；
3. 主动提供可公开凭证或查看方式；
4. 对已下单客户给订单/售后处理路径；
5. 问客户想先看凭证还是先处理订单。

不要评价同行、不要看热闹式谴责、不要说“我们和他们完全不是一回事”这种对立表达；用自家证据建立信任。

## 五、分支处理规则

| 客户状态 | 可发送方向 | 信息收集 | 红线 |
|---|---|---|---|
| 未买/准备买 | 说明已确认安全基线或知识缺口；提示适用/不适用条件；不适合则如实提醒 | 只问影响适配的关键条件 | 不为成交淡化风险 |
| 刚买未拆封 | 承接担心；给等待口径/售后政策内选择 | 仅在要退换或品牌要求排查时收订单/批次 | 不默认索要批次制造恐慌 |
| 已使用无不适 | 按真实资料给观察/暂停观察/使用注意；如客户仍不放心，转售后咨询路径 | 仅收集客户担忧点；必要时问肤质/使用情况 | 不承诺绝对安全，不直接说“正常使用” |
| 已使用有不适 | 建议暂停使用并保留材料；按售后流程处理；升级 | 订单、商品、批次、使用时间、症状描述、照片/视频 | 不做医学诊断，不认定产品责任 |
| 要求真假结论 | 区分已确认事实和外部传言；无口径时安全承接并上报 | 外部链接/截图、客户关注点 | 不辟谣、不说黑稿/造谣 |
| 要退款/赔偿 | 转入售后/补偿权限判断 | 订单、诉求、是否使用/不适 | 不越权承诺退款赔偿 |

## 六、信息收集字段

只在触发条件满足时收集，不要普通顾虑阶段一次问完。

**外部事件材料**：
- 来源平台、链接或截图；
- 客户引用的具体说法；
- 发布时间、传播范围或同类反馈数量（如可见）。

**客户个体材料**：
- 是否购买、是否拆封、是否使用；
- 商品名称、型号、批次/订单（仅在售后、排查或品牌要求时）；
- 使用时间、使用方式、是否叠加其他产品；
- 不适表现、出现时间、照片/视频（涉及健康安全时建议保留材料）；
- 客户当前诉求：继续使用、退换、赔偿、等待说明、投诉。

## 七、升级摘要

命中疑似集中反馈或高风险时，必须在文档中给内部升级摘要：

```text
事件来源:
客户问法:
已确认事实:
外部传言/客户主张:
客户当前状态:
潜在风险:
需补充证据:
建议升级对象:
客服临时口径:
当前不可承诺:
```

升级对象只写知识库已有岗位；没有则用 `【客服权限】` 占位。不要默认写具体负责人、时限、召回、暂停销售或官方声明时间。

## 八、可说与不可说

客户侧可说：
- 我们已经关注到相关反馈，会把您这边的情况一起记录反馈；
- 我先按您现在的购买/使用状态给您处理建议；
- 如果还没有使用，可以先不要大面积使用/先按说明做小范围测试/先保留商品，具体按品类和知识库表达；
- 如果使用后确有不适，建议先暂停使用，保留订单与相关照片/视频，我们帮您登记处理；
- 如果您主要想确认凭证，我可以先发【质检报告/检疫证明/备案信息/平台资质】给您查看；
- 如果您已经下单但仍有顾虑，我可以帮您看订单状态和售后处理方式。

不可说：
- 传言是假的、黑稿、造谣；
- 产品绝对安全、绝对不过敏、所有人都适合；
- 我们确认是产品问题/不是产品问题；
- 已经召回/暂停销售/会赔偿/会退款，除非使用者提供明确授权或官方口径；
- 24/48小时一定出说明、第一时间同步所有人，除非有授权时限；
- 主动罗列严重症状制造恐慌；
- 把客服私聊写成公开声明或公关稿。
- 把内部边界直接说给客户，如“客服侧无法判断”“当前不可承诺”“走流程看权限”。

## 九、必须交付

私聊舆情产物必须包含：
- 舆情判断看板；
- 可直接复制发送的完整首轮回复；
- 未买/未拆封/已使用无不适/已使用有不适/要求退款赔偿的分支；
- 信息收集项与触发条件；
- 可答与不可答边界；
- 高风险或疑似集中反馈的升级摘要；
- 上报条件、版本与更新时间。
