# 00 · 需求路由与输入素材处理

> 通用层 reference，几乎每个案例都需读取。负责：先判断使用者要什么产物，再读懂各类输入材料，建立材料间关系，区分事实与主张。本文件规则先于任何业务场景执行。

## 一、需求路由（先判产物，再判业务）

收到请求后**第一步不是判断售前或售后**，而是先判断：**使用者想让模型交付什么产物**。

### 1. 先判产物类型

| 产物类型 | 触发线索 | 下一步 |
|---|---|---|
| 具体案例解决方案 | 处理这条投诉 / 这个客户怎么回 / 分析这张截图 / 退款+赔偿怎么办 / 改现有话术 | 判基础业务场景，读取 `10-presales` / `20-transaction-fulfillment` / `30-aftersales-disputes` 之一 |
| 客服SOP与规则设计 | 设计退换货流程 / 建投诉SOP / 权限矩阵 / 升级规则 / 优化制度 | 读取 `03-risk-permission-escalation`，按 SOP 主题补读场景 reference |
| Bot自动回复配置 | 哪些可Bot答 / 触发条件 / 转人工规则 / 机器人对话流程 / 检查已有Bot | 读取 `50-bot-automation`，涉及权限或动态规则时补读 `03-risk-permission-escalation` / `01-knowledge-and-freshness` |
| 私聊舆情处置 | "网上说你们…是真的吗" / 还能不能用或买 / 品牌说明转客服语 / 同一事件大量咨询 | 读取 `40-public-opinion-inquiry`，同时判断是否叠加售前/履约/售后基础场景 |

“帮我回客户 / 这句怎么回 / 改现有话术”统一归入“具体案例解决方案”。不要只输出一条孤立话术，必须拓展成可交付文档：可发送话术 + 推荐策略 + 核实/操作步骤 + 追问分支 + 风险边界。

若使用者同时要多个产物，先交付最紧急、最贴近当前客户对话的产物；再补充 SOP 或 Bot 沉淀。

### 2. 再判基础业务场景

| 基础业务场景 | 判定标准 | 读取 |
|---|---|---|
| 售前 | 客户未完成购买，主要在问商品、规格、适配、价格、活动、下单顾虑 | `10-presales` |
| 交易履约 | 客户已下单但交付未完成，主要在问发货、物流、改地址、催单、缺货、预售 | `20-transaction-fulfillment` |
| 售后 | 客户已收货，或已明确提出退换修、质量、补偿、差评、投诉等售后诉求 | `30-aftersales-disputes` |
| 不适用 | 纯 SOP、Bot、私聊舆情处置整理，暂不依附某个客户案例 | 按产物 reference 读取 |

### 3. 判定舆情叠加

客户在任一基础场景中引用外部舆情、网络传言、博主曝光、品牌争议、疑似召回、集中投诉时，`舆情叠加` 标为"是"，补读 `40-public-opinion-inquiry`。

舆情模块只处理**私聊客服如何回应和处置**，不是公开公关、媒体采访或品牌危机战略。纯粹要求"把品牌说明改成客服私聊统一回复/处置口径"时，产物类型可直接判为"私聊舆情处置"，基础业务场景可填"不适用"。

### 4. 内部路由卡片

只填写以下 6 项，禁止堆砌重复字段：

```
产物类型：具体案例解决方案 / 客服SOP与规则设计 / Bot自动回复配置 / 私聊舆情处置
基础业务场景：售前 / 交易履约 / 售后 / 不适用
具体问题：
舆情叠加：是 / 否
知识库状态：完整 / 部分缺失 / 完全缺失 / 冲突 / 过期风险
风险等级：低 / 中 / 高
```

**不要新增**：主业务场景、主任务、辅助业务场景、辅助任务、客户诉求、问题来源、发生渠道等重复字段。客户诉求、材料来源等内容放入后续案例分析，不放在路由卡片。

需要生成或改写话术时，另按 `05-context-and-strategy.md` 建立回复骨架策略卡。不要把服务关系状态、主处理目标、回复骨架等字段塞进路由卡。

## 二、可接收的输入类型

客户文字、聊天截图、差评截图、商品图片、商品详情页、订单截图、物流截图、售后记录、已有客服回复、店铺规则、商家知识库、品牌统一口径。

## 三、各类材料的处理规则（可分析 vs 不可确认）

### 1. 文字描述
- **可**：提取客户问题与诉求。
- **不可**：仅凭文字确认商品问题或责任归属。

### 2. 聊天截图
- **可分析**：客户原话、客服原话、沟通顺序、客户情绪变化、明确诉求、哪句话造成矛盾升级、是否答非所问、是否机械重复。
- **不可确认**：截图是否完整、是否被裁剪、订单真实状态、客户陈述是否属实。

### 3. 商品图与详情页
- **可分析**：页面承诺、参数、外观、尺寸、配件、使用说明、描述与客户反馈的差异。
- **不可仅凭图片确认**：材质、成分、实际性能、商品真伪、是否同一批次。

### 4. 订单、物流、售后记录
- 事实价值通常高于单纯客户描述，但仍需检查：是否同一订单、是否最新状态、是否只展示部分节点、平台状态是否更新。

## 四、多材料同时上传的关系建立

**禁止逐张图片孤立描述。** 必须建立关系链：
```
客户说了什么
→ 商品页面承诺什么
→ 订单记录显示什么
→ 客服此前做了什么
→ 哪些一致，哪些冲突
```

最终必须区分四类：
- **已确认事实**（有材料支撑并核对一致）
- **客户主张**（客户陈述但未证实）
- **待核实事项**（需进一步取证）
- **争议项**（材料间冲突或双方说法不一）
