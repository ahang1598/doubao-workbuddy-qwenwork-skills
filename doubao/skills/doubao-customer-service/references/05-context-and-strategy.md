# 05 · 语境与回复策略

> 通用层 reference。当任务需要生成或改写客户可见话术，或需要判断“该回多深、先做什么、怎么收口”时读取。负责在事实、权限和风险判断之后，决定本轮是信息型回复还是补救型回复；`04-talktrack-style.md` 负责落成自然私聊话术。

## 目录

- 默认语境

- 服务补救强度

## 一、默认语境

默认适用于店铺聊天、平台私信、Bot 对话和在线工单：
- 沟通双方：客服 / 客户；
- 关系：陌生客户服务关系，对等，不卑微、不对抗；
- 表达：专业、礼貌、清晰、自然、有承接、有动作、有边界；
- 品牌语气可以叠加，但不能覆盖事实、权限和风险边界。

高风险、监管、健康安全、法律、公开评价场景要更稳；普通售后、催促、投诉、反复沟通不需要默认冷淡，应该有服务承担感。

## 二、先判 9 个决策字段

每次生成话术前只判断会影响回复的字段，不机械展示：

```text
业务场景：售前 / 履约 / 售后 / 舆情叠加
事实状态：已确认 / 客户主张 / 待核实 / 冲突
关系状态：顺畅 / 轻度疑虑 / 明显不满 / 高度对立 / 信任破裂 / 未知
客户诉求：咨询 / 选择 / 催促 / 退换 / 补偿 / 投诉 / 舆情询问 / 其他
服务补救强度：信息型 / 轻补救 / 强补救 / 升级补救
风险等级：低 / 中 / 高
权限状态：已确认 / 可处理 / 需核实 / 需申请 / 需升级 / 权限未知 / 明确不可处理
客户配合成本：低 / 中 / 高
主回复骨架：从第四节选择一个
```

关系状态只来自客户明确表达或上下文强信号。服务补救强度由客户受到的影响、催促次数、是否超承诺、是否售后异常、是否要求补偿/投诉共同决定。

## 三、服务补救强度

先判断客户要的是信息，还是补救。

| 强度 | 适用 | 回复要求 |
|---|---|---|
| 信息型 | 普通咨询、规则解释、低风险选择 | 直接答复，给依据和下一步 |
| 轻补救 | 轻度不满、轻微延迟、普通售后疑问 | 承接影响，给当前动作和处理路径 |
| 强补救 | 反复催促、已超承诺、明显投诉、质量/错漏发/退款争议 | 情绪承接更充分，给负责人感、节点、可选方案、补偿/申请和跟进方式 |
| 升级补救 | 高风险、平台投诉、群体问题、健康安全、跨部门判断 | 稳住情绪，整理事实，给升级对象、等待期间可做事项和客户临时选择 |

客户受到实际影响时，不要只做状态播报。回复要补上：谁在处理、处理到哪一步、接下来什么节点、处理不到怎么办、客户有哪些选择、补偿或申请怎么走、后续如何同步。

## 四、主回复骨架

选择一个主骨架，可附带一个辅助骨架。客户可见话术必须按骨架裁剪，不要把所有模块都塞进一句话。

| 骨架 | 使用场景 | 话术顺序 |
|---|---|---|
| 直接答复 | 信息明确、低风险、客户只是问一个事实 | 结论 → 依据/限制 → 下一步 |
| 条件答复 | 结论取决于型号、SKU、地址、时间、订单状态 | 当前可确认 → 条件分支 → 最少补充项 |
| 澄清确认 | 缺少关键资料，但仍能先给安全方向 | 临时方向 → 一个关键问题 → 补充后怎么处理 |
| 方案推荐 | 多商品、多规格或多处理路径 | 明确首选 → 推荐依据 → 备选条件 |
| 解释说明 | 需要解释规则、原因、价格、流程、进度 | 核心解释 → 对客户的实际影响 → 可做动作 |
| 协商推进 | 议价、补偿、替代方案、客户诉求与权限不一致 | 接住诉求 → 当前可给 → 需申请/核实 → 收口 |
| 补救承接 | 催促、延迟、售后异常、投诉、反复沟通、体验受损 | 情绪承接 → 当前动作 → 节点/边界 → 可选方案 → 补偿/申请 → 跟进方式 |
| 安全承接 | 事实未核实、高风险、健康安全、监管、舆情 | 承接担忧 → 不下结论 → 个体处理建议 → 必要记录/升级 |
| 边界说明 | 明确不能承诺、不能执行、越权要求 | 边界 → 可做动作 → 可选路径 |

## 五、常见客户状态的骨架选择

| 客户状态 | 首选骨架 | 注意点 |
|---|---|---|
| 普通咨询 | 直接答复 / 条件答复 | 少铺垫，直接解决问题 |
| 犹豫顾虑 | 解释说明 / 方案推荐 | 用真实依据降低顾虑，不夸大效果 |
| 模糊不满 | 澄清确认 + 补救承接 | 先给可处理方向，再把问题转成可核实字段 |
| 明确投诉 | 补救承接 | 承接更充分，处理动作靠前 |
| 反复催促/已超承诺 | 补救承接 | 给负责人感、节点、兜底、补偿或申请路径 |
| 强压补偿/退款 | 补救承接 / 协商推进 | 给权限内方案或申请路径 |
| 疑似批量/产品问题 | 安全承接 / 补救承接 | 收集证据，给个体处理和升级路径 |
| 舆情询问 | 安全承接 / 条件答复 | 不把传言当品牌口径，先解决客户手里商品 |
| 高度对立/信任破裂 | 补救承接 / 安全承接 | 承接消耗，整理事实，给升级或复核路径 |

## 六、客户配合成本与渐进追问

优先降低客户配合成本：
- 低：确认型号、规格、订单、提供一张简单截图，可直接请求并说明用途；
- 中：照片/视频、退货打包、等待核实，先给当前可确认内容再请求；
- 高：多次举证、自费寄回、长时间检测、敏感材料，先找低成本替代或升级。

不要把客服内部核实成本转嫁给客户。一次只问当前能推进判断的一个问题；只有客户表达继续办理、换码、退款、排查等明确意向后，再补问下一步所需信息。内部需要的完整字段不要一次性甩给客户。

## 七、输出给 `04` 的内部策略卡

生成客户话术前，内部形成精简策略卡：

```text
主回复骨架:
服务补救强度:
客户关系状态:
本轮目标:
事实状态:
权限状态:
风险等级:
客户配合成本:
必须说清:
可以主动给的动作:
可选方案:
补偿/申请路径:
后续跟进方式:
需要客户补充:
```

该卡不放在正式文档首屏；只把会影响执行的结论写进处理看板或风险边界。
