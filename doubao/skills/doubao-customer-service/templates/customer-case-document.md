# 模板 · 具体客服案例文档

> 用于「具体客服案例解决方案」。正式产物优先生成飞书文档 XML；无法使用飞书时，按同样信息层级生成单文件 HTML。文档必须先给可直接复制发送的首轮回复；若客户处于催促、投诉、售后异常、补偿争议或反复沟通，第一节必须是补救型首轮回复。标题要像给客服主管和一线客服看的工作文档，不使用后台字段、校验痕迹或模型工作流标题。

---

## 使用说明（生成时删除本段）
- 第一眼必须看到能一次复制发送给客户的首轮回复。
- 先判断回复类型：普通咨询用信息型；催促、投诉、售后异常、退款补偿、反复沟通用补救型。
- 补救型首轮回复必须覆盖：情绪承接、当前动作、节点/边界、客户可选方案、补偿/申请路径、后续跟进方式。
- 客户回复不能只有一句、不能只追问；信息不足时也要包含安全处理方向、当前动作、最少补充问题、条件分支和边界。
- 内部先完成策略判断，但文档呈现顺序为：首轮回复 → 处理看板 → 流程图 → 追问接法 → 核实和升级 → 执行步骤。
- 默认 6 个 H2；售后投诉、履约异常、退换货、补偿争议、舆情询问必须保留流程图。
- 即使原始请求只是“这句怎么回客户”，也按本模板拓展成完整客服处置文档，不只输出一句话术。
- 优先使用 `<grid>`、`<table>`、`<whiteboard type="mermaid">`、`<blockquote>`、`<checkbox>`；`<callout>` 默认只用于话术卡，必要时再给 1 个风险红线块。
- 同一事实只完整写一次；后文只引用结论，不重复讲客户投诉背景。
- 信息不足时也要给“当前安全回复 + 待核实项 + 条件分支”，占位符只放在真正缺失处。

---

## 飞书 XML 结构

```xml
<title>【一句话案例标题】</title>

<h2>1. 可直接复制发送的首轮回复</h2>
<callout emoji="💬" background-color="light-green" border-color="green">
  <p>【先判断信息型/补救型。信息型回复给结论、依据、注意事项和下一步。补救型回复必须包含：情绪承接、当前接手动作、明确节点或待核实节点、客户可选方案、补偿/申请路径、后续跟进方式、事实和权限边界。不能只有一句，不能只追问，不能等待客户多轮补充后才给方案。】</p>
</callout>

<h2>2. 处理看板</h2>
<grid>
  <column width-ratio="0.34">
    <p><b>现在怎么做</b></p>
    <ul>
      <li>【第一步行动】</li>
      <li>【推荐处理方向】</li>
      <li>【回复类型：信息型 / 轻补救 / 强补救 / 升级补救】</li>
    </ul>
  </column>
  <column width-ratio="0.33">
    <p><b>先核实什么</b></p>
    <ul>
      <li>【订单/商品/物流/售后关键字段】</li>
      <li>【影响处理结果的缺失信息】</li>
      <li>【客户配合成本：低/中/高 + 是否可降】</li>
    </ul>
  </column>
  <column width-ratio="0.33">
    <p><b>边界与替代说法</b></p>
    <ul>
      <li>【需按权限表达的事项】</li>
      <li>【更合适的替代表达】</li>
      <li>【是否升级：是/否 + 原因】</li>
    </ul>
  </column>
</grid>

<h2>3. 客服处理流程图</h2>
<whiteboard type="mermaid">flowchart TD
  A["客户反馈问题"] --> B["承接情绪"]
  B --> C["核实订单和商品信息"]
  C --> D{"是否符合处理条件"}
  D -->|符合| E["给出处理路径"]
  D -->|不确定| F["补充材料后判断"]
  D -->|不符合| G["说明原因和可选方案"]
  E --> H{"是否超出客服权限"}
  F --> H
  G --> H
  H -->|否| I["客服闭环并记录"]
  H -->|是| J["升级主管或专岗"]
</whiteboard>

<h2>4. 客户追问时怎么接</h2>
<table>
  <thead>
    <tr>
      <th background-color="light-gray">客户追问</th>
      <th background-color="light-gray">客户侧表达</th>
      <th background-color="light-gray">边界</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>【最常见追问 1】</td>
      <td>【按本案事实现场生成，不套示例句】</td>
      <td>【权限或核实边界】</td>
    </tr>
    <tr>
      <td>【最常见追问 2】</td>
      <td>【按本案事实现场生成，不套示例句】</td>
      <td>【权限或核实边界】</td>
    </tr>
    <tr>
      <td>【客户情绪升级】</td>
      <td>【承接 + 记录 + 升级/反馈方式】</td>
      <td>给升级或复核路径，结果按确认信息同步。</td>
    </tr>
  </tbody>
</table>

<h2>5. 核实材料和升级边界</h2>
<grid>
  <column width-ratio="0.5">
    <p><b>待核实材料</b></p>
    <ul>
      <li>【材料 1：为什么影响处理】</li>
      <li>【材料 2：为什么影响处理】</li>
      <li>【材料 3：为什么影响处理】</li>
    </ul>
  </column>
  <column width-ratio="0.5">
    <p><b>需要升级的情况</b></p>
    <ul>
      <li>【升级条件 1】</li>
      <li>【升级条件 2】</li>
      <li>【升级路径：主管/售后/法务/品牌等】</li>
    </ul>
  </column>
</grid>

<blockquote>只在命中高风险时额外使用风险高亮块；普通核实项不要再套 callout。</blockquote>

<h2>6. 客服执行步骤</h2>
<checkbox done="false">按第 1 节发送客户回复，发送前替换所有【】占位符</checkbox>
<checkbox done="false">按第 2 节处理看板完成核实，不把客户主张直接当事实</checkbox>
<checkbox done="false">按第 3 节流程图判断退换/补发/解释/升级路径</checkbox>
<checkbox done="false">客户追问时按第 4 节接，不越权承诺</checkbox>
<checkbox done="false">命中第 5 节任一升级条件时，转主管或对应专岗</checkbox>
```

## 流程图要求

- 飞书正式产物必须优先使用 `<whiteboard type="mermaid">` 插入流程图。
- 流程图应放在话术和处理看板之后，帮助客服快速判断路径。
- 节点文案短，包含关键分叉：符合/不符合、退/换/补偿、需不需要升级。
- 中文节点统一写成 `A["节点文案"]`，判断节点写成 `D{"是否符合条件"}`，避免问号、斜杠、长句导致解析失败。
- 不把大段规则写进节点；规则放在“核实材料和升级边界”。

## HTML 备用

生成 HTML 时保持同样顺序和密度：话术卡、三列处理看板、流程图或流程卡、追问小表、核实/升级双栏、复选清单。高亮块控制在 1-2 个，必须是完整单文件，不要输出纯 Markdown。
