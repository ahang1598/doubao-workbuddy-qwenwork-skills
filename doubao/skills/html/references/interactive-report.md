# 灵动报告设计

把报告当作一次带读者看懂题材的观看过程。你既是编辑，也负责画面与动作的设计：从材料中找到值得展开的问题，让关键证据在读者眼前显现、变化或形成对照。读完后，读者应能记住一个具体发现，以及自己是怎样看懂它的。

本页用于灵动报告。灵动报告先用 hero 首屏动画建立直观的动态感，再按内容安排叙事和探索；用户要求静态、打印或低动效时依其要求设计。已有报告的局部修改沿用现有结构。

## 找到值得观看的问题

沿用 [前端设计](design/frontend-design.md) 的简短规划，先想清读者带着什么问题来，材料中最有解释力的对象或证据是什么，以及观看或操作能让人发现什么。把这个判断与视觉方向一起定下来，无需另写一份策划书。

让材料决定叙事顺序。可以先亮出反直觉的发现，再展开证据；也可以沿时间、地理空间、故事线或演变过程追踪变化，让结论自然出现。动态呈现和交互探索要帮助读者理解核心内容，不把日期、地图或章节标题当作叙事本身。章节的多少、长短与转折都来自论证需要。正文补充画面没有说出的原因、条件与限制，避免把图中标签再抄一遍。

题材应当改变观看方式。看一件作品可能需要接近笔触与构图，理解一项技术可能需要看清内部怎样协作，比较两个方案可能需要亲手改变条件。它们各自值得观看的东西不同，空间组织、节奏和操作也应随之改变；这些例子不是必须采用的分类。

## 从题材里长出画面

先构思最值得观看的关键时刻：主体怎样占据视野，标题、图像与注释怎样形成关系，这些关系怎样随时间、滚动或操作变化。开场就亮出本题最具特征的主体或证据，给读者继续看的理由。构图可以疏朗，也可以密集，可以从局部开始，也可以先交代全局；画面与动作可以营造氛围、带来惊喜或解释内容，选择应能由材料和受众解释。

按所选表达安排素材与图层，并对素材的细节负责。作品要看得见值得讨论的局部，结构图要让人辨认部件和关系，数量比较要有可信的比例与尺度。抽象程度取决于要解释什么；几根线可以准确表达一段关系，却未必能承担一件复杂器物的主视觉。真实形象按主 SKILL 的素材规则处理，结构与机制可以用程序绘制，载体服务于表达；实现时保留决定效果的尺度、取景、前后关系与节奏。

参考作品时，研究它怎样安排注意力、怎样让细节进入论述，以及怎样把一次操作变成发现。把这些判断带回本题，而不是沿用它的配色、固定侧栏或章节外壳。若换掉标题和名词就能把整页用于另一题材，说明设计还没有深入材料。

## 让首屏先动起来

**灵动报告的 hero 首屏要有明显可见的动画，让读者打开页面就感到它在动。** 元素动画、粒子、光影流动或结构变化均可，动画也可以营造题材氛围。教学场景直接以核心讲解对象的动态演示开场，不另加无关片头。默认随页面打开自动开始，给读者足够的观看时间；不要把全部动态藏在 hover、点击或下滚之后。

以一位出色的 motion designer 的身份设计这段开场：想象它是你向客户展示实力、争取下一份工作的 showreel，值得放进作品集。把本题的主体、文字和图形编排成令人记住的 motion graphics；可以按约 15 秒构思一段完整表演，时长随题材和阅读节奏调整。大胆运用尺度、排印、形态和空间关系，安排速度、停顿与视觉重心的变化，让一个鲜明的视觉瞬间成为记忆点。具体动作与组合由题材决定，不套固定分镜，也不把报告写成设计师的自我介绍。

**实现保持可靠，视觉表达要大胆。** CSS / SVG 元素动画或有数量上限的 Canvas 粒子都可以做出完成度高的编排，不要求复杂模拟、连续运镜或贯穿全文的动态叙事。若只做到背景匀速漂浮、标题淡入，却没有构图与节奏的设计，还只完成了“会动”的底线。先把开场的视觉表现做好，再展开全文，避免不同报告只替换标题和配色。

把动画与文字分层，控制密度、亮度和运动范围，让标题与说明始终清晰。循环动画应平滑衔接，粒子与轨迹及时回收，不能越播越密或越来越卡；离屏后暂停。无需等待动画结束才能阅读正文。

需要用运动解释机制或过程时，再设计清楚起点、变化和结果，保留对象身份与比较基准。明确展示“到达”“完成”等结果的动画，应能在预定节奏内到达该状态，不把完成寄托于随机搜索。纯氛围效果无需模拟真实过程，也不应被文案称作真实计算或证明。

实现动效时按需读 [视觉技法](design/visual-techniques.md) 的相应段落。选择适合这次表达的技术，不预设固定场景、章节数或动画组合。

## 让滚动推进主视觉

在适合的关键段落，让主视觉随滚动进度连续变化，把首屏的动态感延续到阅读中。根据题材选择展开、位移、缩放、遮罩或图层切换；向前滚动推进，向后滚动恢复，停下时画面仍可读。先把一段做完整，不要求每章都有，也不限定统一版式。元素进入视野时的一次淡入可以辅助阅读，主要表现放在读者能随滚动控制的变化上。

需要持续参照时，可以让主视觉在这一段短暂固定，正文从旁边经过；段落结束后回到正常文档流。底层优先用少量属性随进度变化，不为视觉丰富度增加复杂模拟。同一元素的同一属性只交给一个动画控制，避免 hero 自动循环与滚动互相抢状态。手机上调整图文位置或简化运动，保持当前画面、正文和操作入口可见；低动效时直接呈现完整的关键状态。

也可以采用**固定 Canvas 背景，内容随滚动变化**：画布留在视口中，前景正文正常滚动，背景中的粒子或普通 2D 场景随当前章节与进度改变形态、位置、颜色或图层。它可以衔接几个相关章节，形成连贯的视觉体验，不必上 WebGL，也不要求所有题材使用。先安排背景和文字的可见关系，让变化有展示空间，同时保持文字对比度；仅作背景的画布不拦截点击和滚动。

这种背景允许停下滚动后继续有粒子流动等局部动画：滚动决定当前场景和过渡进度，时间只推进该场景内部的运动。两者交给同一绘制入口，倒回或跳章时恢复对应场景，不叠加残留图层或重复启动循环。粒子与轨迹数量受控，离开覆盖的章节后退出背景或停止绘制；手机和低动效模式仍能看到与当前内容对应的画面。

## 让探索带来新的理解

交互入口应对应读者想知道的事。查看细节就展示原对象值得观察的部分，查看依据就给出支撑当前判断的材料，改变条件就呈现结果如何变化。弹出的文字若只是重复当前摘要，增加的只是点击成本。

教育教学围绕理解难点选择分步演示、调节条件、对照结果或带即时反馈的练习，让读者观察变化、探索因果或验证理解。反馈说明当前操作或答案与结果的关系，不只给对错标记；交互形式服务教学目标，不要求每页集齐这些控件。

详情可以就地展开、进入局部取景，也可以形成独立视图；按内容和阅读位置决定。保留正在讨论的对象、条件和参照，返回后能从原来的位置继续。入口文字准确说明结果，没有相应内容就不提供入口。

阅读与操作要发生在同一片可见空间里。窄屏可以重新安排图文关系，重点是读者操作时看得到结果，阅读当前段落时找得到对应画面。低动效状态同样提供完整信息，不能停在透明、半展开或无法继续的中间态。

## 把证据与状态做扎实

把容易出错的计算和状态逻辑集中管理，主体、构图、叙事顺序和主要交互仍由本题设计。图形、读数、选中项及依赖当前条件的解释从同一状态派生；滚动、跳转和返回到同一位置时，呈现应一致。

指标数字在首次渲染时直接显示目标值，不从 0 或占位值滚动到目标值，也不等进入视口后再写入；需要动感时让条形、进度或装饰层运动。页面本身在讲一次增长过程时除外。

数量比较共用口径与比例尺，换显示单位不改变实际比例。事实、推算与假设应能区分，关键判断有来源、时点和适用范围。围绕某个截至日形成判断时使用一致的数据快照；需要持续更新时，证据和结论一起更新。材料不足就收窄判断，不补造精确数值或因果关系。具体图表与读图交互按 [图表图谱](chart/atlas.md) 选型。

需要模拟数据时，在 JS 里用代码生成，不在思考中逐个编写数值：先写出决定结论的少数锚点（如谁最高、谁最低、拐点在哪），再用固定种子的随机函数按趋势与波动生成明细，保证每次打开结果一致。用户提供的数据按原样使用。

## 像读者一样复看

先看桌面和手机的 hero：打开后能否一眼看到动画，完整看过开场后能否记住一个属于本题的视觉瞬间，构图与节奏是否有主次和张弛；仅有元素在动不等于表现力足够。再看运行一段时间后是否仍清晰流畅，循环是否衔接、过程是否到达结果，并检查正文阅读和实际提供的交互，核对图文、计算与当前状态是否一致。首屏完成有表现力的动效即可，正文按需要展开。

教学场景还要核对演示与交互是否帮助理解目标概念，变化、因果或练习反馈能否从当前画面和说明中看懂，不以动画数量代替教学效果。

按主 SKILL 使用 `shot.py`，核对 hero 动态时使用 `--motion normal`，通过 `--eval-file` 在不同时间点观察实际状态与画面；按所选效果核对位移、形态或粒子变化。有滚动动画时，再核对关键段落的起点、中段、终点和倒回状态，确认变化发生在当前可见画面，离开该段后能继续正常阅读；用 `--at` 按顺序截取这些位置的视口画面，例如 `--at '#sec-2,#sec-2@50%,#sec-3,#sec-2'`。固定 Canvas 背景还要看跨章、停留和倒回时是否保持正确场景、密度与前景可读性。默认低动效截图可以检查布局，不能证明正常动画播放；另确认低动效下信息完整。没有实际观察到的动态效果如实列为未验证，不把源码里有动画或 lint 无报错当作验收通过。

最后回到题材：首屏是否有鲜明的动态感，整篇是否让读者用适合材料的方式观看、探索和理解？同样的技术可以复用，成品应体现题材差异。保留能建立氛围或帮助理解的画面与动作，删去干扰阅读的装饰和重复内容。
