# 股票筛选分析深度规则

股票筛选不是行业报告、产业链报告或新闻综述。行业、主题、概念、产业链、业绩、估值、风格等都是股票筛选前的范围界定和分析逻辑；最终必须落到候选股票、入选证据、分组判断、风险缺口和后续验证。

## 深度目标

每次正式筛选至少回答四个问题：

1. **这个范围当前是什么状态。** 说明主题、行业、产业链、板块、市场或指标条件的边界、景气、政策、需求、估值、资金、事件或指标分布。
2. **为什么这个范围值得筛。** 说明驱动因素、兑现阶段、关键分歧和对选股的传导路径。
3. **哪些公司进入股票池。** 说明候选来自结构化金融数据、指数/行业/概念成分、用户指定列表、公司披露、券商研报、权威媒体线索或产业链映射。
4. **为什么这些公司更相关。** 对核心候选验证产品、客户、订单、收入、产能、认证、量产、市占率、财务弹性、估值和交易状态中的关键证据。
5. **哪些结论需要降级。** 明确平台标签、媒体线索、券商推断、公司规划、尚未确认订单、收入占比低、数据缺失和反向证据。

对于“优质股”“核心标的”“龙头股”“哪些更受益”等开放式请求，不能只做清单式罗列。正式输出必须形成判断链：范围为什么重要 -> 哪些细分方向更受益 -> 对应公司为什么入选 -> 估值/财务/交易状态是否支持 -> 结论有什么边界。

正式报告必须先按 `references/formal-report-execution-contract.md` 执行研究包，再通过 `references/report-quality-gate.md` 的质量门槛。深度不足时不要用更多公司名单填充篇幅；应回到范围背景、主线证据、重点公司展开、券商研报、交易资金状态、可视化和来源追踪补足。

## 研究动作分层

### 1. 范围和主线

- 先定义筛选范围：市场、证券类型、行业/主题/概念/产业链环节、时间窗口、用户排除条件。
- 正式输出必须先做范围背景概况：当前状态、关键变化、景气或交易温度、主要驱动和约束，并至少使用一种背景可视化或准可视化表达。
- 提炼一条判断主线：例如“政策催化是否能转化为订单和收入”“材料国产替代是否具备客户验证”“高股息是否能被现金流覆盖”。
- 若主题或产业链边界模糊，先写清楚纳入和排除边界，避免把泛相关公司混入核心候选。
- 若用户询问的是完整产业链、制造原料、上游材料、零部件或供应链，不得直接跳到公司列表；必须先比较细分环节的受益强弱和证据门槛。

用户指令中的锚点决定主线。若用户问某概念、行业、产业链、主题或客户供应链，应先围绕该锚点展开范围、传导路径和公司业务证据；财务、估值、资金、交易状态、股息等维度默认作为支撑层和风险体检，不得反过来改写主线或替代业务相关性判断。

范围背景应遵循 `references/scope-context-rules.md`，并自然引出“主线维度筛选 + 辅助多维筛选 + 公司基本面和风险”的后续结构。

正式报告写正文前必须已经形成四个研究包：范围背景包、股票池和业务证据包、财务/估值/交易/资金体检包、券商研报和权威观点包。不能只完成股票池召回和公司简介就进入写作。

### 2. 股票池召回

- 用 `seed_finance_search` 建立初始股票池，优先获取股票代码、市场、行业分类、概念标签、指数/板块、基础行情、估值、市值、财务指标和风险标记。
- 用 `general_search` 扩展或验证股票池线索，包括公告、互动平台回复、官网资料、政府/协会资料、券商研报、权威媒体和业内人士访谈。
- 用户给定固定股票列表时，不主动扩展到未指定股票；若发现重要遗漏，只能作为“可补充观察标的”说明。

### 3. 公司业务证据

核心候选不得只依赖概念标签。尽量为每个核心候选找到至少一种高权重业务证据：

- 公司公告、年报、半年报、季报、投资者关系记录、交易所/互动平台回复；
- 产品、订单、客户、供应关系、产能、认证、量产、收入占比或毛利率披露；
- 权威行业资料或客户/供应商披露能够交叉验证公司角色；
- 券商研报或权威媒体观点，但只能作为观点、测算或线索，不能替代公司事实。

如核心候选缺少公司层面证据，应移入观察名单或标注“仅平台标签/待验证”，并降低结论强度。

候选股和重点公司分析必须进一步遵循 `references/company-analysis-dimensions.md`。相关性真实度只是第一步；还要分析相关业务介绍、后续发展、对业绩牵引性、基本面、估值、资金流、最新价、日涨跌、5 日/20 日/年初至今表现、同行对比和风险。

### 4. 财务、估值和交易状态

正式筛选不能只写业务故事。即使用户未专门提及财务、估值、资金或交易状态，也应对核心候选做基础多维体检；这些维度默认用于支撑比较、解释风险和校验结论，不自动成为主筛选条件。

对候选池至少补齐以下维度中与任务相关的字段：

- 基础维度：市值、行业、上市地、主营业务、主题/产业链角色；
- 交易维度：最新价、最近交易日涨跌幅、5 日涨跌幅、20 日涨跌幅、年初至今涨跌幅、成交额、换手率、相对板块表现；
- 估值维度：PE、PB、PS、EV/EBITDA、股息率等适用指标；
- 财务维度：营收、归母净利润、扣非净利润、毛利率、ROE、经营现金流、研发投入、同比增速；
- 资金维度：主力资金、北向资金、机构持仓、融资余额等工具可得字段，必须标注统计窗口；
- 预测维度：一致预期、券商盈利预测或目标假设，必须标注为预测/观点。

不同市场、币种、交易日、报告期不一致时，必须说明口径。无法对齐时不做强比较。

可按需读取 `references/strategy-factor-library.md` 选择合适的辅助诊断维度。例如概念股筛选可用成长、估值、资金和趋势维度辅助比较；高股息策略才把股息指标升级为主筛选条件；趋势策略才把 5 日/20 日/年初至今涨跌幅和量价指标升级为主筛选条件。

正式输出的核心候选部分中，至少应展示估值、财务质量、交易状态和风险字段中的 3 类；其中交易状态必须在独立“行情与估值对比表”中拆列展示最新价/收盘价、最近交易日涨跌幅、5 日涨跌幅、20 日涨跌幅、年初至今涨跌幅、成交额和换手率，并在重点公司解析中补充相对板块表现、主力/北向/融资/机构持仓等可得字段中的至少 1 类。重点公司解析中必须解释 PE/PB/PS 等估值指标是否适用。亏损或强周期公司不能只写“PE 为负/高估值”，要说明替代口径和结论限制。

如果 `seed_finance_search` 未返回资金流或多窗口行情，按 `references/retrieval-budget-and-stop-rules.md` 和 `references/market-data-completeness-rules.md` 在预算内二次查询；仍缺失时，在候选表或重点公司卡片写明“工具未返回资金流/5 日/20 日/年初至今行情”，并避免用资金或交易热度支撑强结论。

### 5. 券商研报和权威媒体

正式主题、概念、行业、产业链、策略和龙头筛选中，背景分析和最终重点公司必须在预算内尝试检索券商研报或分析师观点；不需要用户专门要求“看研报”。券商研报用于增强分析深度，重点抽取：

- 行业空间、渗透率、国产替代率、景气周期和竞争格局；
- 产业链利润分布、关键环节壁垒、公司覆盖逻辑；
- 公司收入拆分、盈利预测、估值假设、催化剂和风险假设；
- 不同机构之间的分歧，而不是只摘取支持结论的观点。

权威媒体和业内人士采访用于补充事件背景、政策落地、订单节奏、供需变化和市场分歧。媒体内容应标注为报道或观点，不写成公司已披露事实。

### 6. 反向证据

每次筛选必须检查反向证据：

- 公司澄清未涉及相关业务或收入占比很低；
- 产品处于研发、送样、认证、试产或规划阶段，尚未商业化；
- 订单金额、客户名称、收入贡献未披露；
- 业务虽然相关，但利润率、现金流、产能利用率或竞争格局不支持强受益；
- 股价已明显反映预期、估值处于高位或交易拥挤；
- 重大诉讼、退市风险、非标审计、连续亏损、停牌或流动性不足。

反向证据不一定导致剔除，但必须影响分组、结论强度或风险标记。

## 候选分层要求

默认使用可解释分组，不使用黑盒评分。

- **核心候选：** 业务证据强，财务或订单弹性可解释，风险可识别。
- **重要参与者：** 业务相关性明确，但收入占比、利润弹性、市场地位或估值吸引力弱于核心候选。
- **观察名单：** 有布局、规划、合作、平台标签或研报线索，但公司层面证据不足。
- **风险标记：** 业务相关但存在重大风险、数据缺口、交易异常或结论依赖过强假设。
- **排除项：** 与用户条件冲突，或证据不足以支持纳入候选池。

## 重点公司最低展开

对重点公司至少覆盖：

- 公司业务介绍和与本次筛选范围的业务绑定；
- 证据来源和证据等级；
- 相关收入、订单、客户、产能、认证、量产、份额或产品阶段；
- 相关业务后续发展和对整体业绩的牵引性；
- 最近一期关键财务表现及其对筛选逻辑的影响；
- 估值和交易状态是否已经反映预期；
- 资金流、机构关注或股价多窗口表现：最新价、最近交易日/5 日/20 日/年初至今涨跌幅；
- 同行业或同环节可比指标，例如市占率、相关收入、订单、产能、毛利率、ROE、估值和 5 日/20 日/年初至今涨跌幅；
- 券商研报、权威媒体或公司披露中的增量观点；
- 主要反向证据、风险和待验证事项。

正式报告中，核心候选通常选择 4-8 家做重点解析；每家公司不能只写一句“核心优势”，也不能只写“业务结构、核心优势、业绩牵引、风险”四段。若篇幅允许，应按“业务介绍 -> 主线相关性与真实度 -> 后续发展 -> 业绩牵引 -> 基本面 -> 估值与交易状态 -> 资金/最新价/日涨跌/5 日/20 日/年初至今表现 -> 同行对比 -> 券商/媒体观点 -> 风险和验证点”的顺序展开。用户要求简短时，也至少保留业务证据、估值/财务状态、交易/资金状态和主要风险。

重点公司解析中，至少 3 家核心候选应写出同环节或同主题的横向比较结论，例如谁的相关收入更高、谁的认证阶段更靠前、谁的估值更拥挤、谁的资金或股价表现更强、谁的风险更大。不能把每家公司写成互不相干的公司简介。

## 可视化最低要求

复杂主题、行业、产业链、龙头识别和策略筛选默认应包含可视化或准可视化表达，不把所有内容写成段落和普通清单。

至少选择两类，且普通表格不能单独满足可视化要求：

- 范围/产业链图谱：产业链传导图、主题受益路径图、细分环节表；
- 优先级矩阵：按市场空间、国产替代难度、技术壁垒、客户认证、盈利弹性、当前估值和风险比较细分环节；
- 候选全景表：展示股票、代码、环节、证据、财务/估值/交易、研报观点和风险；这是常规结构化表达，不计入复杂图表数量；
- 指标对比图表：市值/PE/PS/PB、营收/净利润/毛利率/ROE、5 日/20 日/年初至今涨跌幅/成交额/换手率、资金流、相关收入/订单/产能/份额；
- 事件时间线：政策、订单、认证、问询、澄清和财报兑现节点。

若数据口径不一致或缺失严重，改用证据表、分组矩阵、事件时间线或文字说明，并写明未生成数值图的原因。正式产业链、主题、行业、龙头和策略报告通常应至少包含一个传导/流程/关系类组件和一个数值对比组件；只有用户明确不要图表或工具无法获得可比数据时才降级。

## 数据完整性门槛

- 候选总表不能大面积出现 `--`、空白或“暂无”。核心候选关键字段缺失时，先在预算内尝试二次检索或换用可比替代指标。
- 若关键字段仍缺失，应在表格中说明缺失原因，并降低该候选的分组等级或把它放入观察名单。
- 不为了凑图表而绘制缺失严重的数据；可改用文字说明、证据表或验证清单。

## 与其他股票研究 Skill 的协作

当平台环境同时存在相关 Skill 时，本 Skill 作为股票筛选的编排层，不复制其他 Skill 的整份报告，只吸收其适合筛选结论的模块：

- 需要行业中长期框架、产业链结构、景气周期、政策和竞争格局时，借用 `doubao-industry-analysis` 的行业研究能力形成筛选前置判断。
- 需要单只股票近期涨跌、资金面、技术面、短期消息和板块联动时，借用 `doubao-daily-stock` 的个股日报能力补充重点候选的交易状态。
- 需要解释单家公司财报、收入利润变化、毛利率、现金流、费用率和业绩预期兑现时，借用 `doubao-earnings-analysis` 的财报因果分析能力补充重点候选的财务质量。

协作后的输出仍必须回到股票筛选问题：候选分组、入选理由、证据强度、风险缺口和后续验证。
