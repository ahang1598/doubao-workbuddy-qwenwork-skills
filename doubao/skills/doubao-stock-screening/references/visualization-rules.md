# 可视化规则

可视化服务于股票筛选结论。图表不是装饰；正式主题、行业、产业链、龙头和策略筛选默认至少使用候选全景表、关系/传导/流程组件、时间线、矩阵或指标对比中的多类表达。复杂数值图可因数据不足而降级，但不能把复杂筛选写成纯文字和普通清单。

候选股整体情况表是正式股票筛选的常规表达，不视为复杂图表，也不能单独满足正式报告的可视化要求。复杂图表只在数据完整、口径一致、能强化结论时生成；若无法生成复杂图表，应使用证据矩阵、环节优先级矩阵、候选分组表、流程/关系图或事件时间线替代。

正式报告中的“数值对比组件”不能只是另一张普通数值表。在 HTML 中按问题选择柱状图、条形图、折线图、散点图、环形图或关系图；制作方式不限。若数据不足或环境无法准确作图，用可复核数据表或矩阵说明，不用字符条、进度条冒充精确图形。

## 何时生成图表

- 用户明确要求图表；
- 正式主题、行业、产业链、龙头和策略筛选需要展示传导路径、环节优先级、候选分层或多指标差异；
- 候选数量和数据完整性适合图表；
- 图表能比文字或表格更清楚回答一个明确问题；
- 指标在标的和时间维度上具有可比性。
- 需要展示产业链、概念传导、公司分布、估值差异、盈利差异、交易状态或事件节奏。

## 何时不生成图表

- 用户明确不要图表；
- 数据不完整或口径不一致；
- 图表会变成主观评分、雷达图或不透明排序。
- 只有单个公司或单个数字，文字更清楚；
- 来源无法追溯或指标来自不同报告期、币种、市场状态且无法对齐。

不生成复杂图表时，仍应保留候选全景表、环节表、证据矩阵或分组表，除非用户明确只要简短回答。

## 先选问题，再选图表

| 要回答的问题 | 优先组件 | 数据门槛 |
|---|---|---|
| 候选池有哪些公司、各自证据强弱如何 | 候选股整体情况表 | 至少有候选来源、角色、核心证据、分组和风险/缺口 |
| 主题或产业链如何传导到股票 | 产业链关系图、价值传导图、环节表 | 能说明上中下游、关键环节、受益路径和代表公司 |
| 这个范围当前处于什么状态 | 背景概况表、市场/景气指标图、事件时间线、估值/资金状态表 | 至少有数据日期、指标口径和来源 |
| 哪些环节或角色候选最多 | 分组柱状图、环形图、环节表 | 分类互斥且合计口径清楚 |
| 谁的市值、估值、成交或涨跌幅更突出 | 单指标柱状图、多股对比柱状图 | 同一交易日或同一截止日，市场和币种已标注 |
| 谁的财务质量或业绩弹性更强 | 多公司财务对比图 | 同一报告期或明确可比的最近报告期 |
| 谁的相关收入、订单、产能或份额更有支撑 | 业务指标对比图、证据表 | 指标口径一致；未披露公司不强行纳入数值图 |
| 事件或催化剂如何演进 | 事件时间线 | 关键事件有日期和来源 |
| 估值和成长是否匹配 | 双指标散点图 | 两个指标均来自可比口径，且候选数量足够 |

## 可用组件

- 表格：常规结构化表达，不属于复杂可视化；
- 候选股整体情况表：展示候选池分组、角色、关键指标、证据强度和风险标记；
- 关系/流程图：用于产业链传导、主题受益路径、筛选漏斗、客户供应链、候选分组流转；可用 HTML、SVG 或清晰图片呈现，不强制 Mermaid；
- 单指标柱状图：市值、PE/PB/PS、营收、归母净利润、毛利率、ROE、成交额、5 日/20 日/年初至今涨跌幅；
- 条形图：多公司横向比较市值、估值、营收、净利润、成交额、资金流、5 日/20 日/年初至今涨跌幅、相关收入或份额；
- 双指标散点图：估值 vs 增速、股息率 vs 派息率、市值 vs 成交额、主题证据强度 vs 估值；
- 股价表现折线图或柱状图：仅在交易状态、相对强弱、回撤或题材生命周期重要时使用；
- 产业链或关系图：用于上中下游、价值传导、客户供应关系、参股合作关系；
- 饼图或环形图：仅用于份额、候选数量分布、收入结构等合计为 100% 的场景；
- 事件时间线：用于政策、订单、披露、异动和历史热门概念核查。
- 多公司财务对比图：营收、净利润、毛利率、现金流、ROE、研发投入等，必须标注报告期。

## 推荐组合

正式股票筛选报告通常选择 3-5 个表达组件。除候选全景表外，至少还应包含一个关系/传导/流程组件和一个数值对比组件；用户明确不要图表或数据不足时才降级说明：

- **主题/概念筛选：** 主题传导图或事件时间线 + 候选全景表 + 市值/估值/涨跌幅/成交额对比 + 重点公司证据表。
- **产业链筛选：** 产业链价值传导图或流程图 + 环节优先级矩阵 + 候选全景表 + 相关收入/订单/产能/份额对比 + 财务/估值/交易对比。
- **行业筛选：** 行业竞争格局表或景气流程图 + 候选全景表 + 盈利质量对比 + 估值/资金/5 日/20 日/年初至今表现对比。
- **策略筛选：** 筛选漏斗或条件命中矩阵 + 候选全景表 + 关键策略指标对比 + 风险排除表。
- **龙头识别：** 龙头类型说明表或关系图 + 候选全景表 + 行情与估值对比表 + 市值/份额/收入/交易热度对比 + 反向证据表。

每份正式报告至少包含一个背景组件，例如行业/主题状态表、景气指标图、事件时间线、产业链价值传导图、市场估值/资金状态表或指标分布表。

## HTML 图像的自然语言说明

每张保留图先在工作材料中写一段视觉说明，再选择当前可用方式制作。正式 HTML 报告的数值图表写入 `report.json` 的 `chart` 组件，由 `scripts/render_structured_report.py` 输出响应式内联 SVG；筛选漏斗、传导路径等写入 `flow` 组件。不要用 Markdown 代码块画字符流程图，也不要先生成 PNG 再嵌入。组件字段见 `references/html-report-schema.md`。视觉说明至少交代：

- 这张图要回答的筛选问题，以及与候选分组的关系；
- 图形类型、横纵轴或节点关系、纳入的公司与指标、日期、单位、币种和来源；
- 读者应看到的对比、传导、分层或时间变化，及需要标出的例外和数据缺口；
- 金融风格的版式要求：白底、深蓝标题、金色少量点缀，涨跌颜色遵守相应市场惯例；标签清楚、留白充足，避免 3D、装饰性渐变与拥挤图例。

例如，多股估值对比可以描述为：“横向条形图展示同一截止日、同一估值口径下各候选股的 PE(TTM)，按候选分组排列；条末直接标出数值，缺失项单独注明；图下注明日期、币种与来源，配色只表示分组，不暗示买卖建议。”这段说明用于制作图像，正式报告应呈现实际图表，不把说明文字或字符条当作图表。精确数值图必须依据已核验数据制作，不让图像生成模型猜测数值或坐标。

### 原生 HTML 图表组件

在 `report.json` 的章节 `blocks` 中放入图表组件。渲染器直接输出浏览器可缩放的 SVG。正文仍需用文字说明结论和数据口径。

```json
{"type":"chart","spec":{"title":"季度营收与毛利率","source":"公司季度报告，2026 Q1–Q3","x":["2026 Q1","2026 Q2","2026 Q3"],"left_unit":"营收：亿元","right_unit":"毛利率：%","series":[{"name":"营业收入","type":"bar","values":[1291,1478,1652]},{"name":"毛利率","type":"line","axis":"right","values":[24.82,23.15,20.69]}],"note":"营收增长，毛利率连续回落。"}}
```

`series` 支持 `bar` 和 `line`，可用 `axis:"right"` 指定右轴；缺失值写 `null`，不要猜数。事件标注可写 `"events":[{"at":"2026-10-20","label":"三季报披露"}]`，其中 `at` 必须与 `x` 中一项完全相同。`title`、`source`、`x`、`series` 必填，系列的 `values` 长度须与 `x` 一致。自定义颜色可用六位十六进制 `color`。数据点过多、标签重叠或图形无法清晰呈现时，改用可复核表格或单独制作的 HTML 图表，而不是栅格截图。

当前内置图表支持柱状与折线。其他图形确有必要时，先扩展原生渲染器并验证输出；不要用字符画、截图或未经核验的数值凑图。

## 图表说明要求

- 每张图都要有图名、指标口径、数据日期或报告期、来源。
- 图表下方必须写 1-2 句解释它对股票筛选结论的作用。
- 不画主观雷达图来表达“综合实力”，除非每个维度都有清晰、可复核的客观数据且不合成总分。
- 不用图表掩盖数据缺失；缺失字段在表格或图注中标出。

## 数据缺失处理

- 若核心候选缺少图表所需字段，先按 `references/data-freshness-and-conflicts.md` 回填。
- 仍缺失时，可改用证据表、环节表或文字解释，不要把缺失公司从图表中悄悄删除后继续做强比较。
- 图中排除公司必须说明原因，例如“未披露相关收入”“报告期不可比”“工具未返回 5 日/20 日/年初至今涨跌幅”。
- 不使用裸 `--` 作为图表数据；表格中也应尽量写明缺失原因。
