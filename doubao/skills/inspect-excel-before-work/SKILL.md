# Inspect Excel Before Work

在正式计算或批量改写前完成结构、字段、版本与业务口径核验；只有不会改变结果的事项才可在合理默认下继续。

## 1. 锁定文件、版本与输出位置

- 列出全部输入文件，记录文件名、格式、大小、修改时间与可打开性；用户重新发送“新版Excel”后重新读取，不沿用上一轮缓存的 sheet、样本量或公式。
- 明确目标文件、目标 sheet 和写入范围。例如证据中的模板回填位置是 `sheet2`；这类位置必须从当前附件或用户指示确认，不能按同名模板猜测。
- 源附件只读；修复、试写或公式实验在副本中进行。若文件由在线文档实时更新，每次处理前重新拉取当前版本。

## 2. 盘点工作簿结构

- 对每个工作簿记录 sheet 名、顺序、显隐状态、有效区域、真实表头行、合并单元格、冻结窗格、命名区域、公式、外部链接和版本标记；表头不得默认在第 1 行。
- 检查公式单元格与常量单元格的分布和覆盖末行。尽调模板应核对 `File Inventory`、`Claim Audit`、`Cross-file Consistency`、`Reproducibility Tests`、`Risk Register`、`90-Day Plan`、`12-Month Investment`、`Decision Scorecard` 这 8 张表是否齐全，而不是只看当前活动 sheet。
- 财务流水逐 sheet 识别“期初”“明细”“官方合计”和排除项；按明细用 `SUM` 重算，官方合计仅用于交叉校验，差异要保留来源和影响范围。

## 3. 抽样确认字段、单位与值域

- 每张数据表读取表头前后数行、首尾样本、空值、重复值和异常值，建立“原字段 → 当前含义 → 单位 → 标准字段”的映射。
- 对容易混淆的字段展示原值请用户确认。证据中用户明确要求“坡度，不是等级”；因此遇到“坡度等级”“平均坡度”“等别”时不得按名称相似自行互换。
- 对样本账做守恒核验。患者案例中三个中心为 `48 + 35 + 8 = 91` 例且输出为 78 个标准字段；数字只用于该附件的核验，换文件时应从当前工作簿重新统计，而非设成通用阈值。

## 4. 冻结会改变数值的计算口径

- 把分母、权重、单位换算、日期字段、事件定义、缺失处理、去重键和区间边界写成可执行规则；旧公式、旧权重和历史列名只作为待确认线索。
- PFS 案例的明确规则是：有 `进展日期` 时，`PFS天数 = 进展日期 - 治疗开始日期` 且 `PFS事件 = 1`；无进展但有 `末次随访日期` 时，`PFS天数 = 末次随访日期 - 治疗开始日期` 且 `PFS事件 = 0`；`PFS(月) = PFS天数 / 30.44`。6 月状态按 `PFS(月) > 6` 记 1，已发生事件且 `PFS(月) <= 6` 记 0，其余保持缺失；不得把 `> 6` 改成 `>= 6`。
- 面积案例的“平均等”按 `Σ(净面积 × 等别) / Σ净面积` 计算，不是对 `等别` 做简单平均；先确认实际列确为 `净面积` 和 `等别`。
- 绩效案例先算 `每天工作量 = 各指标 / 出勤天数`，现行权重为提取图斑 40%、专项图版 10%、基础库图斑 20%、面积 20%、出勤天数 10%，合计必须为 100%。Min-Max 前，缺失检查数据者的“排查”部分记 0，缺失“非自行修改”者的加减得分记 0；“去掉最高与最低分”若未说明是仅排除定标还是删除整条人员记录，必须先确认。

## 5. 核验关联键与跨文件主张

- 对每个候选关联键统计非空数、唯一数、重复数、匹配数和一对多数量，再决定 join。保险案例中非车记录与车险记录共用 `保单号` 的数量为 0，实际需要检查 `车架号`；不得因为列名自然就直接用 `保单号` 关联。
- 跨文件逐项对齐项目名、版本、数量、用途、时间、结论和证据位置。`Claim Audit` 至少 20 项时，每项记录来源文件、sheet/单元格或段落、证据状态、直接或间接证据、可复现性、矛盾、决策影响与待补资料。
- 结论冲突时同时报告两边来源及受影响的 sheet、字段、公式或记录范围；若原始明细与派生合计不一致，以原始明细按已确认口径重算，并报告差额。

## 6. 设置确认闸门

- 将问题分成“证据明确”“证据冲突”“证据缺失”，只阻塞会改变结果数字、记录归属或输出结构的事项。字段歧义、版本冲突、样本异常、模板变化和公式口径冲突都必须确认后再执行。
- 询问时给出具体选项及影响，例如：“6 月状态是否继续按 `PFS(月) > 6`，若改为 `>= 6`，恰好 6.0 月的记录会从 0/缺失改为 1？”不要只问“请确认口径”。
- 对有状态门槛的模板保持原值域。例如尽调风险只用 `P0`、`P1`、`P2`，决策只用“推进”“附条件推进”“暂停”；只要仍有 `P0`，就不能给出无条件付款结论。

## 7. 按确认规则执行并回读

- 把用户确认的字段映射、公式、权重、边界和关联键记录在执行摘要中，再开始正式分析、计算或批量写回；仅替换目标单元格，保留未授权修改的样式、外链和公式。
- 回读生成文件，核对 sheet 位置、表头、样本数、公式覆盖、错误值、外链和关键样例。模板写回 `sheet2` 后还要验证工作簿可重新打开，避免 XML 命名空间或非法 inline string 导致 Office 无法打开。
- 做守恒检查：绩效权重应合计 100%；患者中心数应与总样本数一致；面积分母应等于 `净面积` 合计；预算案例中的累计预算、剩余额度、风险数量和决策提示必须由公式计算，并分别检查首付款不超过 300 万元、90 天预算不超过 60 万元、12 个月预算不超过 800 万元。

## 边界与禁止事项

- 未完成结构和口径核验，不开始正式计算或批量改写；用户要求立即处理也要先完成最小核验。
- 不把旧权重、旧公式、历史列名、PPT 主张、计划或模拟值当作现行事实。
- 不补造缺失 sheet、字段、输入、日期或关联关系；无法从附件确认时标为“未提供”或“无法核实”。例如 `保单号` 匹配数为 0 时不能强行关联，应核验 `车架号` 或询问其他键。
- 不覆盖源附件。跨文件不一致时不得静默选边，必须标注冲突来源和影响范围；仍有 `P0` 时，不得给出无条件付款结论。

## 工具用法

- 使用能以只读方式枚举 sheet、单元格类型、公式与外链的 Excel 工具；计算库读取公式时同时保留公式文本，避免只拿到缓存值。
- 关联前输出候选键的覆盖率、唯一率及一对多统计；日期计算前检查 Excel 日期序列、文本日期和时区/业务日约定。
- 写回后用独立读取路径重新打开产物并抽查至少 3 类记录：普通值、边界值和缺失值。

## 示例

用户说：“新版患者 Excel 已上传，先看表头并计算 6 月 PFS。”先重读当前文件，列出 sheet 与真实表头，抽样核对 `治疗开始日期`、`进展日期`、`末次随访日期`；随后明确使用 `30.44` 天/月和严格 `> 6` 的边界。若字段缺失或恰好 6.0 月的归类与用户要求冲突，先展示受影响记录数并确认，之后才批量计算，最后回读结果核对事件状态与样本总数。
