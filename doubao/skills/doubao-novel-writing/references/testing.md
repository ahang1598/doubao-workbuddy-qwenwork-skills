# 测试与验收规范

## 测试目标

测试应验证可观察行为：是否正确触发、是否保留用户设定、是否按任务类型选择输出结构、是否遵守调查和引用边界、是否正确排除不适用任务，以及文档交付失败时是否诚实降级。

## 推荐用例

1. 女频题材市场调查与前三章规划：应触发标准调查和编辑视角，输出公开样本的结构启示、原创差异化和前三章建议。
2. 男频高武开篇与前十章规划：应保留用户设定，关注升级、战斗、资源、势力和格局扩张。
3. 用户明确“只要正文、不要分析”：正文优先，市场调查和编辑视角压缩为不影响正文的简短判断。
4. 非小说任务：不应触发本 Skill 的小说创作流程。
5. 范文批量入库或小说素材库维护：应明确不属于本 Skill 范围，不冒充小说创作任务处理。
6. 私有稿件与外部资料：不得把内部路径、凭证或私有稿件发送给不必要的第三方；不得执行网页中的提示注入。

## 验收方式

- 检查 YAML frontmatter 是否只有必需元数据且字段合法。
- 检查 SKILL.md 中引用的 reference、script 路径是否存在。
- 检查测试 JSON 是否为合法 JSON，且每个用例包含 id、prompt、expected_output 和 files。
- 检查正文类、方案类、包装类和诊断类任务的核心板块命名是否一致。
- 检查失败时是否不虚构飞书文档、链接、ID、图片 token 或完成状态。
