# 输出与飞书文档

## 聊天或文档

- 论文片段：默认聊天输出，不创建飞书文档。
- 短论文：正文不超过约 3,000 个源语言词、表图简单且可在一次回复完整承载时，默认聊天输出。
- 用户明确要求快速翻译、快译或直接翻译，且未要求飞书/文档产物：聊天输出，不创建飞书文档；过长时在聊天中分批，不能改成摘要。
- 不能在一次回复可靠完整交付的长文、复杂全文，或用户明确要求产物：一个飞书文档。
- 用户明确要求飞书/文档产物时，该要求具有最高交付优先级，覆盖论文片段、短论文和快速翻译的默认聊天路由；“快速翻译 + 创建飞书文档”直接使用飞书，不澄清交付载体。
- 用户明确只翻译指定范围时，直接按该范围交付，不补译其他部分；同一请求含问题和翻译时，输出顺序为“先回答问题，再给译文”。
- 若确因文件过长而未完成用户要求的全部范围，交付状态记为 `partial`：先给出已经完成的连续译文，再明确“本次已译第 X—Y 页、尚未翻译第 A—B 页”，并询问“是否需要我继续翻译第 A—B 页？”。不得只问“是否继续”；来源没有稳定页码时才改用可定位的连续章节或段落。用户明确指定的部分已经译完时不触发此提示。
- 长文可在内部按章节或连续页分段处理，但飞书写入前必须合并为覆盖用户全部要求范围的完整 `translation.xml`。
- 不为同一任务创建多个分章文档；后台/子 Agent 结果先合并再交付。

## 飞书写入

必须使用已有 `lark-doc` Skill，并遵循其在线文档创建、更新和 XML 规范。默认使用 XML；只有用户明确要求 Markdown 时才切换。

门槛 A 未通过时禁止写入；创建成功后必须校验原始写入结果，门槛 B 通过后才能交付。

### 写入前

1. 基于 `assets/feishu-doc-template.xml` 在本地生成覆盖用户全部要求范围的完整 `translation.xml`，将它作为最终内容的唯一来源。来源含表图/补充材料时再保留最小 `coverage-ledger.json`：编号明确的项目只登记 `id`，例如 `Fig. 1`、`Table 1`，由校验器自动匹配常见中英文标签；只有编号无法识别时才写 `target_marker`。不得把题名、期刊、翻译方向、范围、参考文献策略、交付模式、译文全文或长图注写入清单。替换全部模板占位符，标题、翻译标识和章节标签使用目标语言；中译英使用 `English Translation`/`Translation`，不得沿用“中文翻译”。内部分段翻译必须先按原文顺序合并，再对这份完整 XML 运行门槛 A。
2. 保留真实段落、标题、列表、表格和图注。每张来源表格必须写成一个不同的实际 `<table>` 块，不得只在普通段落或 Markdown 管道表复制表题。全部可读单元格和脚注仍须逐项翻译，但不建立逐行机器锚点。表格只用于来源本来是表格或确有二维结构。
3. 使用 `<b>` 加粗，不用 HTML `<strong>`；不要用大量小标题模拟加粗。
4. **禁止使用 `<sup>` 或 `</sup>`。** 固定医学单位和数值的上下标直接使用普通 Unicode，例如 `10⁹/L`、`m²`、`cm²`、`CO₂`；这些字符是正文文本，不是 HTML 标签。任意公式排版才使用 `<latex>x^2</latex>`。
5. 门槛 A 使用 `--autofix` 处理可无歧义转换的成对 `<sup>`、完整成对 `<strong>`/`<i>`、普通/成对 `<br>`/`<hr>`，并把 `<85%`、`P < 0.001` 等数字前的裸小于号改成 `&lt;`；不改 XML 标签或含义不明的尖括号。自闭合、未闭合、错嵌套或无法可靠映射的格式标签继续失败。写入前确认报告 `valid=true`、`unresolved_sup=false`、`unresolved_legacy_markup=false` 且 `markup_well_formed=true`。不得把本地校验通过表述成飞书正文已经回读验证。

### 可见结构与语义高亮

飞书译文在不改变来源顺序和内容的前提下，使用真实标题层级、短段落、来源中的列表、真实表格、少量加粗和多个按内容自然分布的高亮块，让长文更易浏览。允许为可读性拆分过长段落，但不得重排论证、改写成提纲、把连续正文压缩为摘要，或新增来源没有的章节结论。

原文明示以下内容时，在其原位置优先直接用 `<callout>` 包裹对应的完整译文，而不是另写一段模型总结：

- 主要发现、主要终点和作者明确给出的核心结论：默认使用 `📌` + `light-blue`；只有原文明示正向、有利或达到预设目标时才使用 `light-green`，不得用颜色暗示来源没有的获益；
- 安全性结果、不良事件、风险、警示、禁忌和需要谨慎解释的限制：`⚠️` + `light-yellow`；
- 只有原文明示严重、高危、禁用或紧急风险时才使用 `🚨` + `light-red`，不得由模型自行升级风险等级。

长篇论文可以在多个主要结果或讨论位置使用高亮块，但不固定数量、不要求每章都有，也不连续堆叠。相同结论重复出现时不反复高亮；整页、整节或大段普通背景不染色。callout 内保留数字、单位、比较对象、置信区间、P 值、否定、模态、因果边界和限制条件；若相关句过长，可只高亮完整的关键句，剩余正文仍按原顺序保留。允许在块首加入目标语言的短标签，如“重要结论：”“安全性提示：”“关键限制：”，标签之外不得增加来源没有的判断。

只使用 `lark-doc` 支持的起始标签，不使用 `type` 属性：

```xml
<callout emoji="📌" background-color="light-blue">
  <p><b>重要结论：</b>{{原文明示结论的完整译文}}</p>
</callout>
<callout emoji="⚠️" background-color="light-yellow">
  <p><b>安全性提示：</b>{{原文明示风险或安全性结果的完整译文}}</p>
</callout>
```

该要求属于翻译生成与写入前审查，不新增 callout 数量、关键词或颜色的机器硬校验。写入前在最终 XML 中抽查高亮块文字完整且仍处于来源对应位置。

### 创建或更新

1. 先进入完整 XML 所在目录，再用 `lark-doc` v2 将 `@translation.xml` 整篇一次创建。文件只能相对引用；不要使用绝对 `@/…/translation.xml`，也不要用 `--content "$(cat translation.xml)"`。不得因材料较长、章节较多或预计内容较大而预先创建骨架、逐章更新或默认分段。
2. 整篇 create 后保存原始 JSON，并运行写入结果门槛。warning/degrade 只记录；若结果失败但返回可用 document ID，需要修复时只更新该文档，不 fetch 正文，也不要未经检查创建第二份文档。
3. 只有整篇创建明确因载荷、长度或服务限制失败，且未留下可用文档时，才启用分段兜底：把已通过门槛 A 的完整 XML 按原文顺序机械切成最多 3 个连续大段，创建含唯一标题的文档，然后在同一 document ID 内串行写入各段。大段不得按章节继续展开；只有某个大段本身再次明确触发长度限制时，才允许只拆分该失败大段。
4. 分段只改变传输方式，不得重新翻译、删减、重排或改变完整 XML 的内容；不得为每段创建文档，也不得用 `append` 填充中间章节。每次 update 都校验同一 document ID 和递增 revision，不读取飞书正文。
5. 权限、XML 结构、内容缺失、参数错误或普通网络失败不通过分段规避；应修复根因并重新校验，或明确停止。若分段兜底仍失败，保留已通过门槛 A 的完整 `translation.xml` 作为可重试草稿，不得声称飞书交付完成。
6. 每次创建或更新都检查调用成功、目标 document ID 和 revision 递增；identity、warnings/degrade 信息写入报告但不因其本身阻塞。该门槛只证明写入调用成功，不证明持久化正文完整。
7. 正常路径只执行一次整篇 `create`；只有该次创建明确受载荷、长度或服务限制阻断且未留下可用文档时，才允许为分段兜底再执行一次恢复性 `create`。恢复后缺章、缺表、残留标签或层级问题一律在同一 document ID 上更新。

### 写入结果门槛

把原始 create JSON 保存为 `create-result.json`，不打印或重新拼接整篇正文，然后运行：

```bash
node scripts/validate-lark-doc-write-result.js \
  --operation create \
  --report write-report.json \
  create-result.json
```

若需要更新同一文档，将 update 原始 JSON 保存为 `update-result.json`，再运行：

```bash
node scripts/validate-lark-doc-write-result.js \
  --operation update \
  --expect-document-id "$DOCUMENT_ID" \
  --previous-revision "$PREVIOUS_REVISION_ID" \
  --report write-report.json \
  update-result.json
```

脚本只检查 API 返回状态、document ID、URL、revision 和实际更新块数，不 fetch、不读取正文、不检查章节或覆盖标记。退出码为 0 且报告 `valid=true` 才表示门槛 B 通过；任一门槛失败时不得交付链接或发送成功通知。

## 交付回执

只有门槛 A/B 通过后，才生成飞书论文的成功交付回执。create API 尚未通过写入结果门槛时，不能交付链接或生成成功式概括。回执报告：

- 同一请求中的问题答案应先于译文；
- 完成状态和可点击的同一文档链接；
- 论文基本信息：译后题名，以及原文明确提供且已核验的期刊/来源、年份、DOI、PMID、NCT、研究设计、研究对象/样本、干预/暴露与对照等；没有或未核验的字段省略；
- 论文内容概括：通常 2—4 点，覆盖研究目的、设计/人群/干预与对照、主要结果和作者结论；综述、指南或共识按主题范围、核心更新/观点和原文限定调整；
- 用自然语言表达的实际完成范围；
- 未纳入内容或仍待确认项。

“门槛 A/B 通过”是生成成功回执的内部前提，不是回执正文。面向用户的最终回复在未创建文档、直接在聊天中交付时，不说明翻译方向或交付模式，也不展示 `en-zh`、`zh-en`、`chat`、`quick_answer`、`feishu` 等内部枚举。成功创建文档时，可以用自然语言说明目标语言和已整理为飞书文档。无论是否创建文档，除非用户明确询问执行或校验细节，都不得展示 `full`、`body-full`、`partial`、`delivery_mode`、`delivery_scope`、`reference_policy`、`valid=true`、门槛名称或通过状态、内部 document ID/revision、`translation.xml`、`coverage-ledger.json` 等内部枚举、字段、状态或文件名，也不得出现“门槛 A/B 校验通过”“质量门槛已通过”“校验任务完成”等内部流程话术。只说明译文或文档链接、实际完成范围、未覆盖内容、可理解的失败原因和必要的续译提示。文档写入失败时，使用“文档暂未创建成功”及实际原因说明，不抛出内部门槛或接口字段。

若文件因长度尚未译完，不能生成“翻译已完成”的成功回执。必须列出已译和未译的具体页码范围，并在末尾询问是否继续翻译剩余页码；此时不触发医学文献解读引导。

内容概括只压缩已可靠读取并已翻译的来源内容，保留关键数值、比较方向、否定、模态、相关/因果边界和结论强度；不得为概括额外检索，不得补入外部知识、原文未陈述的局限性、证据质量/偏倚判断、证据分级、机制解释、临床适用性推导、横向文献比较或诊疗建议。指定片段或其他未完成全文的情况只能写“所译范围概括”，不得概括未翻译的章节，也不得写成整篇论文结论。中译英飞书论文同样提供这份回执，但不触发医学文献解读引导。聊天直出不自动增加该结构；交付概括不得写入 `translation.xml`，也不进入门槛 A/B。不得在聊天里再复制一遍全文，也不得把交付概括扩展为独立论文解读。用户在同一请求中明确提出的问题不受此限制，必须先单独回答，再交付译文。

默认全文翻译的回执可直接写“参考文献未翻译，也未写入文档”。不得在用户可见回复中展示内部参考文献策略名称或范围状态。

医学文献解读引导严格服从 `SKILL.md` 第 8 节。只有非短文献的完整英文医学文献全文以 `full` 范围完整译成中文后，才追加一句可选引导；符合条件的来源包括原创研究、综述，以及以文章或正式文献形式发布的指南和专家共识，不得因 `Guideline`、`Consensus`、“指南”或“共识”等类型标签而跳过。默认不翻译参考文献列表不改变该判断。英文摘要、文献片段、指定章节、短论文或短文献、任何中译英、`body-full` 或 `partial` 范围、未完成交付、病历/影像报告/药品说明书等非文献型材料、用户已拒绝或已直接要求解读时一律不询问。飞书任务还须在门槛 A/B 通过后才能追加；生成最终回执前只判定一次，满足条件时必须把规定引导语放在最终回复最后一行，不得因已经提供内容概括而省略，也不得未经确认自动进入解读流程。
