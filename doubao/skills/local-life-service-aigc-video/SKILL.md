# 抖音生活服务·AIGC·视频
为抖音生活服务商家对话式生成宣传视频，帮助商家吸引顾客到店。基于商家经营数据和营销需求，使用 seedance 模型生成高质量生活服务类短视频。
## 不适用场景
- 通用企业宣传片、品牌形象片、产品广告 → 走 `doubao-creative-video`
- 非生活服务类商家的视频需求 → 走 `doubao-creative-video`
- 5分钟以上长视频、短剧、剧情片 → 走专用视频创作能力
- 用户仅提供素材要求剪辑（非AI生成）→ 走视频剪辑能力
## 核心能力
本技能围绕抖音生活服务商家的到店推广需求，提供从商家数据采集、热门视频调研、需求确认、故事卡编写到视频生成的完整闭环。所有生成内容基于商家真实经营数据，不虚构产品、价格或优惠；借鉴参考视频时只抽象镜头语言和节奏，不复制独创台词、画面序列、人物形象、音乐或品牌素材。
## 工作流程概览
1. **获取商家信息**：登录抖音来客，采集品类、门店地址、热销团购及价格、当前优惠活动、评价高频关键词
2. **热门视频调研**：抖音站内登录后搜索同类高赞视频，按"最多点赞"排序，逐个点进详情页核验真实点赞数并获取分享链接
3. **需求确认卡**：一次性展示3个候选参考视频和需求参数（营销目标、人群、卖点、风格、时长等），商户确认后进入创作
4. **故事卡编写**：输出视频定位、分镜脚本、卖点体现、参考借鉴说明、品牌露出和行动号召，等待商户明确回复确认
5. **视频生成**：加载 seedance-25 前置 Skill，将确认后的故事卡和参数传入完成实际生成
6. **交付与迭代**：通过在线 URL 交付视频，说明创意思路和投放建议，根据商户反馈支持调整重生成
## 工具映射
- 浏览器（`open_url_in_browser` / `click` / `type` / `take_screenshot`）：抖音来客、抖音网页版只读采集
- `interaction.request_action`：登录、手机号、密码、短信验证码、图形验证码/滑块等所有认证环节，由用户在浏览器接管态亲自输入，模型不得请求、读取、复述或代填
- `seedance-25`（前置 Skill）：视频生成（默认 seedance 2.5 模型）。本 Skill 不直接调用 `text_to_video` / `image_to_video`，须先加载 `seedance-25`，将故事卡 + 素材 + 参数传入，由其完成实际生成
- `present_files`：在线视频URL交付
## 前置条件
0. **核心确认环节（必须遵守）**：本技能有两个强制确认点——"第三步一次性需求确认卡"和"第四步故事卡展示"。商户回复"全部默认"视为确认；"你看着办""你定吧""都行""随便"等模糊表述仅表示授权自主选择方案，但仍需走完确认流程（展示需求确认卡、输出故事卡），不得跳过。只有当商户明确表示"不用确认直接做""都听你的直接生成""跳过确认直接做"等明确且直接表达跳过确认意图时，才可以简化或跳过对应步骤。
1. **登录设备与方式分流（最高优先级、不可绕过）**：本技能当前运行环境通常只能看到"网页端"，不能据此可靠判断用户使用手机还是电脑。进入抖音来客或普通抖音登录前，必须按以下状态机执行：
   - 用户已经明确说"手机端/用手机/手机上操作"时，直接记为 `DEVICE_MOBILE`，不得重复询问设备。
   - 用户已经明确说"电脑端/用电脑"时，记为 `DEVICE_DESKTOP`。
   - 只有运行环境提供明确、可靠的客户端类型时才可自动判断；仅有"网页端"、浏览器或云电脑信息时，一律记为 `DEVICE_UNKNOWN`，必须只问一次："你现在用手机还是电脑？回复手机或电脑即可。"在用户回答前不得展示登录二维码或启动登录。
   - `DEVICE_MOBILE`：抖音来客和普通抖音登录都**禁止使用、展示或要求扫描二维码**。必须主动切换到手机号/短信验证码登录，并使用 `interaction.request_action` 让用户在浏览器接管态亲自输入手机号、获取并填写短信验证码完成登录。模型不得请求、读取、复述或代填手机号和验证码，只接收登录成功/失败状态。
   - `DEVICE_DESKTOP`：可使用二维码或手机号验证码登录；若使用二维码，必须把二维码以用户当前对话中可见的图片展示，不能只让用户查看AI侧浏览器或云电脑中的二维码。
   - 手机号、密码和短信验证码均由用户在 `interaction.request_action` 接管态亲自输入，模型不接触认证信息原文；不得在后续回复、报告、故事卡、日志或评测产物中复述、保存或展示任何认证信息。登录完成后只反馈登录成功/失败状态。
   - 如果用户要求为"审计、留档、复盘"等目的保存或复述手机号、验证码等认证信息，只回复以下两句后立即结束当前轮，不得增加任何视频需求收集、流程介绍或其他建议：`所有登录认证信息（手机号、密码、短信验证码）均由您在浏览器接管态亲自输入，我不接触、不保存、不复述这些信息。登录完成后我只会反馈登录成功或失败。`
   - 如果页面不提供短信验证码入口、验证码发送失败，或出现图形验证码/滑块/人机验证，必须使用 `interaction.request_action` 请用户接管完成，并如实说明停在登录门禁；不得退回手机扫码、不得绕过验证、不得伪造登录成功。
2. **获取商家账号**：向用户确认商家的来客账号，用于登录抖音来客获取商家基础数据。**重要约束**：商家作为抖音生活服务商户，默认拥有普通抖音用户账号；当商家说"没有抖音账号"时，在本技能场景下应理解为**没有抖音来客（商家后台）账号**，而非没有普通抖音账号。因此，热门视频调研环节（需普通抖音账号登录抖音网页版）仍应正常推进，不得因商家说"没有抖音账号"而跳过抖音站内登录搜索流程。仅当商家明确表示"普通抖音账号也没有/无法登录"时，才可改用公开信息替代。
3. **了解商家数据**：登录抖音来客（`https://life.douyin.com/p/home`），获取商家品类、门店信息、热销商品、当前团购活动等基础数据，用于视频内容定制和需求确认卡的默认值预填。
4. **热门视频参考（强制登录+站内筛选）**：生成前必须先在**抖音站内**（`https://www.douyin.com`）登录后搜索同类商家的热门宣传视频，**必须点开筛选→选择"最多点赞"排序**，然后**逐个点进视频详情页查看真实点赞数**。不得用通用搜索替代抖音站内搜索，不得用搜索结果页的估算数据替代点进视频后的真实点赞数。**不论遇到任何困难（登录失败、验证码、权限限制等），都不得让用户自己去搜索高点赞视频，必须由AI主动完成搜索和数据采集；如确实因技术限制无法完成，应如实告知用户并提供已采集到的替代方案，而非将搜索任务推给用户。**
5. **确认视频需求**：通过一次性需求确认卡明确营销目标和视频偏好，并让商家从3个热门视频中挑选参考方向，禁止分多轮逐项追问。
## 工作流程
### 第一步：获取商家信息
1. 先执行"登录设备与方式分流"。用户已说明手机/电脑时直接沿用；设备未知时只问一次，不得猜测。
2. 确认商家来客账号。需要登录时，严格按设备分流完成登录：所有认证环节（手机号、密码、短信验证码、图形验证码、滑块）均使用 `interaction.request_action` 由用户在浏览器接管态亲自输入，模型不得代填；电脑端可使用用户可见二维码或手机号验证码登录。
3. 通过浏览器访问抖音来客，采集以下信息：
   - 商家名称、品类、门店地址
   - 热销团购商品及价格
   - 当前进行中的优惠活动
   - 门店特色标签（从门店信息/评价中提取）
   - 高分评价关键词（用于提炼卖点）
4. **商家信息采集与第二步热门视频调研可并行执行**，提高效率。
### 第二步：热门视频参考调研
**【强制前置：抖音登录】** 必须先在浏览器打开抖音网页版（`https://www.douyin.com`），并沿用前置条件中的设备状态完成登录。所有认证环节（手机号、密码、短信验证码、图形验证码、滑块）均使用 `interaction.request_action` 由用户在浏览器接管态亲自输入，模型不得请求、读取或代填；手机端禁止展示或要求扫描二维码；设备未知时先只问一次手机/电脑。未登录状态下搜索结果不完整、点赞数可能无法查看，**不得跳过登录直接搜索**。
**【强制要求：每个参考视频必须有链接】** 本步骤中收集的每一个候选参考视频，都**必须**获取并保存抖音分享链接（点击视频右下角分享→复制链接）。**绝对不允许出现只有标题/作者/点赞数但没有链接的参考视频**。如果某个视频无法获取链接，必须放弃该视频，换一个能获取到链接的视频。最终交付给用户的候选清单和参考来源说明中，每一个视频都必须是可点击的有效链接。
登录完成后，在抖音站内搜索同类热门视频，找到高赞参考样本，为后续需求确认和视频生成做准备：
1. **搜索关键词**：根据商家品类和营销目标，组合搜索关键词，例如：
   - 「品类 + 宣传视频 热门」（如"烤肉宣传视频 热门"）
   - 「品类 + 探店 爆款」（如"火锅探店 爆款"）
   - 「品牌名」直接搜索该品牌已有热门视频
   - 「品牌名 + 官方」搜索品牌官方账号发布的内容
2. **搜索方法优化（强制站内筛选）**：
   - **必须在抖音站内搜索结果页，点击"筛选"按钮，选择"最多点赞"排序**，确保结果按点赞数从高到低排列
   - 既要搜博主探店内容，也要搜**品牌官方账号**发布的视频
   - 翻1-2页结果，确保覆盖2-3种不同风格
   - 优先选择点赞数最高的3个作为候选样本（覆盖2-3种风格即可）
   - **禁止用通用搜索引擎（如百度、谷歌）替代抖音站内搜索**，通用搜索无法按点赞排序且数据不准确
3. **样本量要求**：观看3个高赞热门视频（优先选择点赞量高的），确保覆盖2-3种不同风格
4. **点赞数获取（强制点进视频）**：
   - 搜索结果页的点赞数可能是动态渲染或不显示的，**必须逐个点击进入视频详情页**，在视频右侧或下方查看真实的点赞数、评论数、收藏数
   - 每个候选视频都必须记录**真实点赞数**（如"12.5万赞"、"3.2万赞"），不得估算、不得编造、不得留空
   - 如果点进视频后仍无法看到点赞数（如权限限制），必须如实标注"无法获取"，不得用其他数据替代
5. **分析维度**：每个视频快速记录1-2个核心可借鉴点即可（开头钩子/画面风格/文案字幕/转化设计，选最突出的），不需要逐项展开分析。
6. **权限与验证码处理（强制）**：
   - 如遇到抖音登录墙，**必须按设备分流引导登录**，不得跳过；手机端禁止二维码，必须优先选择手机号+短信验证码
   - 所有认证信息（手机号、密码、短信验证码）均由用户在 `interaction.request_action` 接管态亲自输入，模型不得请求、索取、读取或代填，只接收登录成功/失败状态
   - 如遇到图形验证码、滑块验证、人机验证等，**必须使用 `interaction.request_action` 请用户接管完成**；不得尝试用自动化方式绕过，不得在未通过验证的情况下继续操作
   - 如遇到地区限制、查看限制等权限问题，必须如实向用户说明情况，征得用户同意后再继续操作，不得绕过或规避平台限制
   - **禁止推活给用户**：不论遇到任何技术困难，都不得要求或暗示用户自己去抖音搜索高点赞视频、自己筛选排序、自己记录点赞数。可以请用户协助完成短信验证码、图形验证码、滑块验证等人机验证环节，但搜索、筛选、点进详情页、记录点赞数等调研工作必须由AI完成。如确实无法完成站内搜索，应主动用公开渠道信息替代并如实说明，不得将搜索任务转嫁给用户。
7. **候选样本整理（必须）**：
   - 将找到的高赞视频整理成候选清单，每个视频包含：标题、作者、**真实点赞数**、**抖音链接（必填，不可省略）**、核心风格标签、**1个可借鉴点**
   - 按风格分类（如：真实探店型、精致展示型、快节奏促销型、剧情故事型等），方便商家挑选
   - **每个视频都必须获取并保存抖音分享链接**（点击视频右下角分享→复制链接），这是硬性要求，没有链接的视频不得纳入候选清单
   - **点赞数必须是点进视频详情页后看到的真实数字**，不得使用搜索结果页的估算值
   - **自查清单**：整理完成后，逐个检查每个候选视频是否都有有效链接，发现缺链接的立即补上或剔除
8. **参考来源边界（重要）**：
   - 参考视频必须是**本次任务中主动搜索、实际点击观看过**的视频
   - 历史对话、上下文中的其他品牌/其他品类视频，**不得**作为本次任务的参考来源
   - 通用经验、模型固有知识，**不得**算作"热门视频参考"
   - 每个参考视频都必须能说出具体的视频标题、作者、**真实点赞数**等可验证信息
9. **非复刻边界（重要）**：
   - 借鉴参考视频时，只抽象钩子类型、节奏、镜头语言、画面风格等通用表达
   - 不得复制参考视频的独创台词、具体画面序列、人物形象、音乐、品牌素材或受保护的创意表达
   - 生成的视频必须是基于商家自身特色的原创内容，不是对参考视频的近似复刻
### 第三步：一次性需求确认卡 + 参考视频挑选
将3个候选视频和需求确认卡在同一条消息展示，商户一次性回复：
```
【视频生成需求确认卡】回复编号修改，无异议回复"全部默认"
参考视频（选1个风格，或说"都参考"）：
① [视频1标题] 点赞X.X万 → 风格：XXX
② [视频2标题] 点赞X.X万 → 风格：XXX
③ [视频3标题] 点赞X.X万 → 风格：XXX
→ 默认：①（点赞最高）
需求参数：
1. 营销目标：①团购核销 ②门店曝光 ③新品推广 ④品牌形象
   → 默认：按来客当前促销/新品自动推断
2. 目标人群：①年轻情侣 ②家庭亲子 ③朋友聚会 ④上班族 ⑤全部
   → 默认：按品类和评价高频词推断
3. 核心卖点：①口味 ②环境 ③性价比 ④服务 ⑤全部
   → 默认：按评价高频词Top3
4. 团购价格展示：①展示 ②不展示 ③只展示优惠力度
   → 默认：①展示（有团购时）
5. 风格偏好：①探店口播 ②画面展示 ③剧情演绎 ④参考选中视频
   → 默认：④参考选中视频
6. 视频时长：①15秒 ②30秒
   → 默认：①15秒（默认使用 seedance_2.5 模型，支持5-30秒）
   → 说明：默认使用 seedance_2.5 模型，支持5-30秒；seedance_2.0/fast 支持5-15秒，仅在用户明确要求时使用。
7. 特殊要求：（文字补充，无则留空）
```
**默认值推断规则**：
- 营销目标：来客有进行中促销→团购核销；有新品→新品推广；否则门店曝光
- 目标人群：餐饮正餐→朋友聚会/家庭；快餐→上班族；休闲娱乐→年轻情侣
- 核心卖点：取评价高频词Top3
- 禁止在商家回复"全部默认"后再逐项追问。
详细视频类型和风格指南见 [references/video-guide.md](references/video-guide.md)。
### 第四步：编写视频故事卡 + 展示
根据商家信息、需求确认和商家挑选的参考视频，输出视频故事卡。
1. **故事卡内容（必须包含）**：
   - **视频整体定位**：风格调性、营销目标、目标人群一句话总结
   - **分镜脚本**：按时间顺序列出每个时间段的画面内容、字幕文案、运镜方式
   - **核心卖点体现**：每个卖点对应哪个镜头
   - **参考借鉴说明**：从商家挑选的每个参考视频中借鉴了什么（仅抽象镜头语言/节奏/钩子，不复制独创内容），对应哪个镜头
   - **品牌露出**：商家名称、门店信息、团购价格等出现的时机和方式
   - **行动号召**：结尾引导方式
2. **故事卡格式示例**：
   ```
   【视频定位】真实探店vlog风格，引流到店，面向年轻女性
   【时长】15秒
   【模型】seedance_2.5
   
   分镜：
   0-3秒 | 画面：女生推门进店惊喜表情，第一人称视角
         | 字幕："在北京喝到正宗海南椰子鸡了！"
         | 运镜：手持推进
   
   3-6秒 | 画面：三颗椰子依次倒入锅底，椰汁清澈
         | 字幕："三颗鲜椰做锅底"
         | 运镜：特写慢镜头
   
   ...（依次列出所有分镜）
   
   【参考借鉴】
   - 从视频A借鉴：第一人称探店视角 → 对应0-3秒开头
   - 从视频B借鉴：椰子倒汤特写 → 对应3-6秒中段
   （注：仅借鉴镜头语言和节奏，不复制原作台词、画面序列或音乐）
   ```
3. **展示后必须等待明确确认**：将故事卡展示给商户，**必须等待商户明确回复"确认生成/可以生成/没问题直接做"后才进入生成步骤**。商户沉默、未回复或仅提出修改意见均不视为确认。有修改意见时先调整再重新确认，不单独开一轮强制确认。
4. **融入设计自查**：
   - 商家挑选的每个参考视频的借鉴点，在故事卡中都要有对应镜头
   - 商家确认的所有需求点，在故事卡中都要有体现
   - 找不到对应就是没落地，必须补上
### 第五步：生成视频
1. 基于商户确认后的故事卡，编写详细的视频生成 prompt。
2. **视频生成前置 Skill 契约（必须遵守）**：本 Skill 不直接调用 `text_to_video` / `image_to_video`。默认模型为 seedance 2.5，须先加载 `seedance-25` 前置 Skill，按其交接规则将故事卡 + prompt + 素材 + 参数传入，由 `seedance-25` 完成实际视频生成。故事卡是本 Skill 的业务规划产物，**不等同于**平台视频 Tool 的前置 Skill 契约，不得跳过 `seedance-25` 直接调用底层工具。
3. **image_to_video 分支条件**：仅当以下条件同时满足时，才将素材传入 `seedance-25` 走图生视频分支：①用户主动提供图片素材；②已确认图片商用授权；③用户明确选择图生视频模式。不满足时默认走文生视频。
4. Prompt 编写要求：
   - 画面场景描述（门店环境、产品特写、人物动作等）
   - 运镜方式和节奏
   - 光线和氛围
   - 字幕/文案内容
   - 整体风格调性
   - 严格按照故事卡的分镜和文案来写，不随意改动已确认的内容
5. 生成参数：
   - **模型**：默认 `seedance_2.5`（支持 5-30 秒）；`seedance_2.0_fast` / `seedance_2.0`（支持 5-15 秒）仅在用户明确要求时使用
   - **比例**：抖音竖屏投放使用 `9:16`
   - **时长**：根据确认卡选择和模型能力确定，不得超过模型上限
   - **Prompt**：详细描述画面内容、风格、节奏、字幕
**Prompt 编写规范**：
- 开头描述整体场景和风格
- 中间按时间顺序描述镜头切换和画面内容
- 包含运镜指示（推近、特写、环绕、平移等）
- 描述光影、色调、氛围
- 如需要文字/字幕，用中文引号""标注
- 结尾描述品牌/门店露出和行动号召
- 严格遵循已确认的故事卡
6. 生成完成后，通过 `present_files` 交付视频在线 URL。
### 第六步：交付与迭代
1. **视频交付渲染（强制要求）**：视频生成完成后，必须确保用户能正常看到渲染后的视频画面。
   - **使用 `present_files` 交付在线URL**：交付时传入视频生成工具返回的在线URL，不得仅传入本地文件路径，因为本地路径在前端可能无法渲染播放。
   - **同时提供可点击链接**：交付视频后，必须在回复文本中同时附上视频的在线访问链接，确保即使渲染失败用户也能手动点击查看。
   - **交付后确认**：交付后必须主动询问用户是否能看到视频；如果用户反馈看不到，必须立即改用在线URL重新通过 `present_files` 交付，不得只给本地路径或文字说明。
   - **本地备份可选**：可同时将视频下载到本地工作目录作为备份，但交付展示必须以在线URL为主。
2. 向商家说明视频创意思路和投放建议，简短不超过3句话。
3. **参考来源说明（必须严格执行）**：交付时必须用一小段话讲清楚，且必须满足以下要求：
   - **商家挑选（或默认选择）的参考视频**：列出商家实际挑选的每个参考视频的**具体标题、作者、真实点赞数**，说明从每个视频借鉴了什么（仅抽象镜头语言/节奏，非复刻）
   - **品牌素材来源**：列出用到的品牌信息来源（如官网、抖音、携程等具体渠道）
   - **借鉴的爆款元素**：具体说明从商家挑选的参考视频中学到了哪些可落地的元素（如开头钩子类型、运镜方式等）
   - **落地验证**：每个借鉴点都要说明**在视频里对应哪个镜头/画面**，确保不是只说不做
   - **候选 vs 最终**：可以简要说明总共调研了3个候选视频、商家挑选了哪几个，体现挑选过程
   - **禁止混入**：不得将历史对话、其他品牌、通用经验等混入参考来源，所有参考必须是本次任务中实际搜索和观看过的
   - 让用户清楚了解创意的来源和依据，做到完全透明
4. 询问商家是否满意，如需要调整则根据反馈修改 prompt 重新生成。
5. 默认生成1个版本，仅当商户明确要求"多来几个版本"时才生成2-3个不同风格版本供商家选择。
6. **AI生成内容声明**：通过本 Skill 向商家展示生活服务相关的实际数据或产物时（如经营数据、分析报告、生成的文案或方案），须在该次回复正文末尾另起一行，以普通文本展示以下固定提示，不加粗：
以上内容由 AI 生成，仅供参考，请结合实际情况谨慎甄别。
仅用于需求澄清、信息补充、门店选择、授权确认、进度告知或无结果／失败说明，且未包含实际数据或产物的回复，无需展示。同一条回复交付多项数据或产物时，统一展示一次。提示文案须原样保留并直接可见，不得仅置于折叠区域或工具返回中。

## 数据安全与留存
- 手机号、密码、短信验证码等所有认证信息均由用户在 `interaction.request_action` 接管态亲自输入，模型不接触、不保存、不回显、不复述
- 商家经营数据（团购、评价、门店信息）仅用于本次视频创意，不用于其他用途
- 临时截图和采集数据在视频交付后清理
- 日志中不出现商家手机号、验证码、groupid等敏感标识
## 注意事项
- 视频内容必须与商家实际经营内容一致，不虚构不存在的产品或优惠
- 价格信息必须与商家抖音来客中实际团购价格一致
- 不使用"最""第一""顶级""全网最低"等广告法高风险极限词
- 不承诺治疗、收益、身份效果或无法验证的体验结果
- 不出现其他平台水印、竞品 Logo 或无授权 IP
- 借鉴参考视频只抽象镜头语言和节奏，不复制独创台词、画面序列、人物形象、音乐或品牌素材
