# 实验刺激物设计

## 触发范围

### 触发

在请求明确涉及以下任一任务时使用本 Skill：
- 设计实验刺激、实验材料、Vignette、情境故事或实验组与控制组材料。
- 将一个或多个自变量转化为可呈现的操纵版本。
- 设计与刺激直接对应的操纵检验题和条件组合表。
- 审查已有刺激中的混淆变量、非预期差异、真实感或需求特征。
- 为视觉、多媒体、回忆或行为唤起刺激提供内容方案、参数约束或脚本。

### 不触发

以下请求不使用本 Skill：
- 量表开发、一般问卷题项、信效度检验；操纵检验题除外。
- 实验平台编程、随机分组实现、数据收集和被试招募。
- 已收集数据的统计分析、假设检验、回归或方差分析。
- 非实验用途的广告、新闻、小说或普通文案写作。
- 单纯的研究选题、理论构建、假设提出或文献综述。

如果请求只有“设计实验”而未说明是否需要刺激材料，先澄清范围，不直接生成刺激。

### 边界

- 混合请求只处理刺激设计部分；将量表、编程、收数和统计部分明确拆出。
- 审查已有材料时只评价刺激设计、内部效度和可执行性，不把审查结果表述为学术价值、因果效应或伦理审批结论。
- 设计本身缺少对照、变量定义矛盾或条件不可识别时，先指出问题并等待修正。
- 游戏、虚拟现实、交互网页或物理道具等超出可直接制作范围时，交付内容脚本、分镜、交互逻辑和实现约束，不声称已生成成品。

## 证据边界

- 将材料相似度、字数和条件覆盖结果表述为设计检查，不把它们等同于操纵成功或因果效应成立。
- 只有真实执行脚本并保留输出时，才写“脚本检查通过”；未执行时写“待执行”。
- 只有 Owner 或指定评审者真实运行测试题库并保存输入、输出与判定时，才写“测试通过”。[测试用例集](references/test-cases.md) 当前是待 Owner 执行的测试设计，不是通过证据。
- 不根据示例、截图或预期结果伪造最终文档、脚本日志、预测试结果、基线比较或完整合规自检。
- 预测试阈值是事先约定的决策标准，不是跨研究通用的伦理或科学保证；结合研究设计、量表质量和领域规范解释。

## 核心设计原则

任何刺激方案同时平衡以下三项：

1. **精准对比度**：刺激只操纵目标自变量，差异足以让被试感知目标构念。
2. **严苛等值性**：非操纵部分保持字数、句式、语气、信息量、版式和视觉参数一致，以减少混淆。
3. **合理真实感**：情境符合目标人群经验，避免荒诞设定和过强需求特征。

采用四条通用法则：
- **最小差异**：先写共用骨架，再替换目标词句；版本字数差异以 5% 为默认设计门槛。
- **场景化呈现**：用行为、对话或事件唤起构念，避免直接给被试贴标签。
- **注意力锚点**：把操纵信息放在易被注意的位置，但不要用夸张格式暴露目的。
- **现实合理性**：人物、任务和媒介贴近被试日常经验。

## 刺激类型

| 类型 | 形式 | 典型用途 | 详细规范 |
|---|---|---|---|
| 情境阅读 | 故事、新闻、对话、Vignette | 态度、领导风格、道德判断、说服 | [刺激类型指南：类型 A](references/stimulus-types.md#type-a) |
| 视觉或多媒体 | 图片、界面、广告、短视频 | 营销、HCI、品牌、界面研究 | [刺激类型指南：类型 B](references/stimulus-types.md#type-b) |
| 回忆或行为唤起 | 写作、回忆、任务 | 权力感、排斥、情绪、自我肯定 | [刺激类型指南：类型 C](references/stimulus-types.md#type-c) |

在概念界定后选择类型，只读取对应章节再构建材料。

## 四步工作流

### Step 1：概念界定

开始写作前确认：
1. 实验类型：单次、多时间点或纵向。
2. 研究主题和目标关系。
3. 被试人群及其情境经验。
4. 每个自变量的名称、水平数和各水平操作定义。
5. 因变量的大致方向和测量时点。

信息缺失时逐项追问；变量定义模糊时先给出可选择的操作定义。输出实验设计摘要并请用户确认，未确认前不进入材料定稿。

### Step 2：原型构建

1. 写出所有条件共用的中立骨架。
2. 按最小差异原则替换操纵部分。
3. 建立覆盖全部组合的条件对照表。
4. 为每个自变量设计至少两道操纵检验题。
5. 对每个成对版本检查字数、句式、信息量和非目标情绪差异。

原型门禁：
- 版本字数差异不超过事先约定阈值；默认 5%。
- 非操纵核心段落保持一致。
- 每个自变量至少两道检验题，其中至少一道直接测量目标感知。
- 条件表覆盖所有组合。
- 情境与目标人群经验相符。

字数和差异检查可使用[字数差异脚本](scripts/check_word_count.py)与[版本对比脚本](scripts/compare_versions.py)，条件枚举可使用[条件组合脚本](scripts/generate_conditions.py)。仅在真实运行后记录日志和退出状态；不能运行时按“失败与降级”处理。

### Step 3：盲审自检

隐去组别标签后逐段比较：
- 除目标变量外，是否还有可感知差异？
- 某组是否更长、更强烈、更正面或包含更多论据？
- 是否暗示研究目的或期望答案？
- 材料格式、媒介参数和呈现时长是否等值？

发现非预期差异就修改。自检完成后建议由 1–2 位不了解组别的同行回答：“这些材料唯一的区别是什么？”将真人复核标为建议或待执行，不能替真人声称通过。

### Step 4：小样本预测试

交付时建议使用与正式样本同质的小样本预测试；20–30 人可作为初步规划参考，不替代功效分析。事先约定操纵检验、效应量、理解度和退出规则。操纵未达到预设标准时，修改材料并重新预测试，不把失败材料直接投入正式实验。

## 操纵检验

默认每个自变量至少配置两道直接对应操纵的题项，并将其放在主要因变量之后以降低目的暴露风险。量尺、反向题、时序和分析标准见[操纵检验指南](references/manipulation-check.md)。多题项并不自动构成有效量表，应结合预测试和测量证据判断。

## 实验伦理与合规

在生成材料前进行风险分级，并把处理结果写入设计说明：
- **知情同意**：说明任务性质、可能不适、退出权利和联系方式；确需隐藏研究目的时，只隐去实现研究所必需的信息。
- **欺骗与事后告知**：只有在研究目的无法用低风险替代方案实现时才考虑欺骗；提供及时 debriefing、撤回数据途径和必要支持，不声称已获伦理审批。
- **脆弱或未成年人群体**：涉及未成年人、认知障碍者、患者、受权力关系影响者或其他脆弱群体时，要求 Owner 依据机构规则补充同意、监护和风险控制。
- **负面情绪与伤害风险**：死亡、排斥、创伤、自伤、歧视、身体意象等材料采用最低必要强度，提供跳过、退出、安抚和支持资源；不能把“真实感”作为提高伤害强度的理由。
- **隐私与敏感数据**：只收集实现操纵所必需的信息，避免在示例材料中放入真实个人身份、健康或联系方式。
- **审批与地域规则**：将机构伦理审查、平台政策和适用法律列为 Owner 的上线前门禁。本 Skill 只能提供检查清单，不能代替 IRB 或其他正式审批。

遇到无法降至合理水平的伤害、胁迫、非法歧视、未获授权的敏感数据使用或诱导危险行为，停止制作相关部分，说明原因并提供低风险替代设计。

## 失败与降级

| 情况 | 处理 |
|---|---|
| 输入不完整 | 输出缺口清单和最少追问，不猜测实验条件 |
| 设计有硬伤 | 标出影响、提出修正方案，等待确认后再写材料 |
| 用户要求破坏等值性 | 说明具体混淆风险；若仍要求保留，显著标记偏离，不声称合规 |
| 脚本不可用或未运行 | 提供人工核对表，把字数、差异和条件覆盖状态标为待验证 |
| 视觉、视频或交互成品无法制作 | 提供内容规范、分镜、参数表和验收标准，不伪造文件或截图 |
| 缺少真实预测试或同行复核 | 输出待执行计划，不填写结果、不宣称通过 |
| 伦理风险无法合理缓解 | 停止相关材料，改给低风险替代方案或建议提交伦理审查 |

## 产物契约

交付一个刺激材料包，明确区分被试材料与研究者材料：

| 产物 | 消费方 | 用途 |
|---|---|---|
| 基线材料 | 被试 | 所有条件共用的启动内容 |
| 条件操纵版本 | 被试 | 对应各自变量水平的刺激 |
| 条件组合对照表 | 研究者、编程人员 | 条件编号、水平组合和呈现顺序的权威依据 |
| 操纵检验题 | 被试 | 验证目标感知是否形成 |
| 设计说明 | 研究者 | 记录定义、操纵逻辑、偏离和风险 |
| 合规性自检表 | 研究者 | 记录已检查、未通过和待执行项 |

默认使用 Markdown。只有用户明确要求 Word 且环境支持时才生成 `.docx`；未生成时不能声称存在最终 Word 文件。按“设计概述 → 被试材料 → 条件表 → 设计说明与自检”的顺序组织。

## 交付前检查

### 范围与构念
- [ ] 实验类型、主题、人群、自变量、水平和因变量方向已明确。
- [ ] 每个版本只操纵目标变量，操纵与操作定义一致。
- [ ] 不用直接标签替代情境化操纵。

### 等值性与真实感
- [ ] 字数阈值、核心段落、句式、语气、信息量和版式已逐项核对。
- [ ] 视觉或视频刺激的尺寸、分辨率、时长、音量等已控制。
- [ ] 情境符合被试经验，不含明显需求特征。

### 条件与测量
- [ ] 条件对照表覆盖全部组合并给出呈现顺序。
- [ ] 每个自变量至少两道操纵检验题。
- [ ] 操纵检验与主要因变量的时序已说明。

### 证据、伦理与风险
- [ ] 脚本是否真实运行及日志位置已如实记录；未运行项标为待执行。
- [ ] 同行盲审、预测试和基线比较的真实状态已标记。
- [ ] 知情同意、欺骗、debriefing、脆弱群体、负面情绪和隐私风险已检查。
- [ ] 未把设计自检表述为伦理审批、操纵成功或因果证据。
