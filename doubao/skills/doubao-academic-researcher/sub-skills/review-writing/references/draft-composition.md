# 综述稿写作细则

成稿的目标不是"分析笔记去掉编号"，而是一篇偏论文文献综述正文节奏、能一口气读下去的连续文本。本文件给段落级、过渡级、收束级的具体写法。

## 写作定位

默认写成中文核心 / 硕博论文文献综述风格，而不是英文论文 Introduction 的直译腔。

形态边界先于文风：最终只允许 3-6 个自然段，2000 字左右（可上下浮动）。不要写拟题、摘要、引言、绪论、方法、结果、讨论、结论、总结，也不要写 `一、二、三` 或 `1. 2. 3.` 小标题。成稿参考稿是**文献综述正文的格式示例**（示范一段合格的文献综述正文长什么样），不是整篇论文的目录，也不是用户论文里那一章"文献综述"的成品。

中文综述正文的基本特征：
- 直白但是严谨，不堆砌术语；必要的专业术语、机制解释和条件边界必须保留。
- 句子可以略长，但主语、对象、条件和判断边界必须清楚。
- 段落内部要有自然承接，不追求每句话都短。
- 允许必要的限定、转折和背景压缩，但不能用空泛套话代替具体信息。
- 文献引用服务于判断，不服务于装饰。
- 段落推进靠问题、路线、条件差异和未解问题，不靠“首先/其次/最后”的模板序号。

## 样本文风提炼

参考中文核心综述样本的可取之处，不是表面格式，而是行文方式：用直白语言解释技术对象，用机制和条件串起句子，用具体模型、任务、指标或应用场景承载判断。正文应当像论文综述，而不是科研汇报或 PPT 讲稿。

### 可取风格

- **对象先行**：段落开头直接说明讨论对象，如“循环神经网络适合处理时序数据”“卷积神经网络提供了视觉数据的分层表示”，不要先写宏大背景。
- **概念解释带机制**：介绍一个方法时，不只说“效果好”，而要说明它靠什么结构、操作或假设起作用。
- **进展叙述有演化链**：介绍一组工作时，按问题推进、结构改进、适用条件或性能变化组织，而不是把论文逐个摆出来。
- **判断落在条件上**：不要写“某方法更优”，而写“在某类任务、数据规模、评价指标或资源条件下表现更稳定 / 更受限制”。
- **语言直白但严谨**：可以用“能”“可以”“需要”“因此”等朴素表达，但必须有明确对象和依据；不要为了显得学术而堆抽象名词。
- **长短句自然变化**：复杂机制可以用长句说明，结论或转折可以用短句收束。不能每句长度相近，也不能每段都像四句模板。
- **术语第一次出现可解释**：中文正文中可保留英文术语或缩写，但首次出现时给出中文名称、英文名或功能说明，后文再直接使用。

### 不可取风格

- 把上游材料改成“第一，第二，第三”的科研汇报。
- 每段只列模型名称和结果，没有说明这些工作之间的关系。
- 用“具有重要意义”“提供理论基础”“具有参考价值”等空泛结尾替代具体未解问题。
- 把“可研究方向”写成作者自己的计划。
- 为了显得流畅，删掉限定条件、数据边界或证据不足提示。

### 推荐段落形态

一个自然的综述段落通常包含三层推进：

```text
对象 / 问题定位 → 既有工作如何处理该问题 → 这些处理方式的条件、差异或剩余限制
```

例如，不能写成：

```text
已有研究分别从理论解释、方法改进和应用验证三个方面讨论了该问题。A 研究提出了一种解释框架，B 研究改进了分析方法，C 研究在真实场景中进行了验证。这些研究推动了该领域的发展。
```

应写成：

```text
围绕该问题，现有研究大体经历了从概念解释到方法检验、再到场景化验证的推进过程。早期文献主要解决“这一现象如何被理解”的问题，为后续研究提供了基本解释框架；随后出现的实证或模型研究进一步把讨论推进到“哪些因素在何种条件下产生作用”，使原本较宽泛的判断被拆解为若干可检验的关系；近期研究则更多关注这些关系在不同样本、不同制度环境或不同应用场景中的稳定性。由此看，该领域的主要分歧已不在于问题是否存在，而在于既有解释能否跨条件成立，以及哪些边界因素会改变原有结论。
```

## 输入边界

成稿阶段只改写上游已有材料，不新增研究内容。写作前内部锁定四类材料：

- `claim_pool`：上游已有核心判断。
- `citation_pool`：上游已有作者-年份引用标识。
- `tension_pool`：上游已有争议、反证、条件差异。
- `gap_pool`：上游已有开放问题、局限、未来研究空白。

正文中任何具体判断、作者年份、方法名、数据集、实验结果、政策事实，都必须能回到这四类材料。不能从模型记忆补背景、补事实、补引用。

## 段落级：从逐篇罗列到主题判断

### 反面写法：逐篇摘要

> Zhang 等提出了方法 A。Li 等提出了方法 B。Wang 等进一步提出了方法 C。

问题：读者只看到三篇论文并排，看不到它们之间的关系，更看不到作者的判断。这是摘要拼贴，不是综述。

### 正面写法：主题判断 + 交叉比较

> 围绕 X 问题，现有研究主要形成 A、B 两条路线。A 类方法依赖 Y 假设，在标准 benchmark 上表现稳定 [1][2]；B 类方法通过 Z 机制放松该假设，在复杂场景中取得更好的泛化 [3][4]。但两类的优势都高度依赖评测设定：前者在受控数据集上占优，后者在跨域或长尾场景中更稳健 [2][4][5]。这说明当前工作的真正分歧不在"是否有效"，而在"何种条件下有效"。

差别在于：正面写法有一个**贯穿全段的判断**，论文是用来支撑这个判断的，而不是被逐个介绍。

**规则**：文献充足、该段承担实质分析时，优先让每段至少有一句同时比较 2 篇以上论文；若该段只承担问题界定或过渡、或该主题只有 1-2 篇关键文献，不强行凑比较。

## 反 AI 痕迹与反拼凑

### 禁止的开头

不要用空泛起手：

- "近年来，X 受到广泛关注。"
- "随着技术的不断发展，X 已成为重要方向。"
- "X 在当今社会中具有重要意义。"

改成有对象、有范围、有问题张力的开头：

> 围绕 X 的研究已经从早期的概念界定转向对 Y 条件下实际效果的检验，但现有证据在样本范围、评价指标和外部有效性上仍存在明显分歧。

### 禁止的连接方式

不要让段落靠机械连接词推进：

- 首先、其次、最后
- 此外、另外、同时、综上
- 值得注意的是、需要指出的是、重要的是

这些词不是绝对不能出现，而是不能成为段落结构的主要支架。优先用语义关系承接：共识与分歧、方法与局限、标准场景与真实场景、理论预期与实证结果。

### 禁止的拼凑形态

以下写法要重写：

- 一段只按论文出现顺序介绍 A、B、C。
- 每句话只引用一篇论文，彼此没有比较。
- 把上游小结、导航段、清单换个说法直接粘进正文。
- 句尾堆多个引用，但正文没有说明这些文献之间的关系。

合格段落必须回答一个问题：这些文献放在一起说明了什么。

## 过渡级：让相邻段落有承接

综述不是一段段孤立堆出来的。相邻段落之间要有显性过渡，常见承接方式：

- **从共识过渡到分歧**：前段讲清共识，后段展开争议
- **从方法过渡到瓶颈**：前段讲路线，后段讲这些路线为什么还不够
- **从标准结果过渡到真实场景**：前段讲 benchmark，后段讲外部有效性

如果相邻两段之间没有一句过渡，往往说明结构还只是并列，没形成主线——回到"锁定叙事主线"重排。

## 每一段应完成的事

一个承担分析的主题段落，通常要完成四件事：

1. **交代位置**：这一段在整篇里回答哪个问题
2. **压缩路线**：这个问题下的工作大体分成哪几类
3. **比较差异**：这些路线在方法、数据、指标、适用条件上如何不同
4. **收束瓶颈**：讲完后，剩下的核心问题是什么，如何引向下一段

做不到这四件事的段落，大概率还是论文清单。

## 常用叙事主线

按上游材料自动选择一条主线，不需要告诉用户：

- **问题链条型**：问题重要性 → 已有路线 → 关键瓶颈 → 未解问题。
- **技术流派型**：路线 A → 路线 B → 路线差异 → 共同局限。
- **证据收束型**：理论机制 → 实证结果 → 真实场景限制。
- **发展演化型**：奠基工作 → 近年进展 → 剩余问题。
- **争议收束型**：已有共识 → 直接争议 → 条件解释 → 仍待验证的问题。

主线可以和调研结果层的主题顺序不同。调研层为“查得清”服务，成稿层为“读得顺”服务。

## 引用怎么放

- 引用服务于判断，不是堆在句尾凑数量。
- 一个判断由多篇独立工作支撑时，把它们放在同一句里体现"收敛"（如 `（张三等，2021；Smith et al.，2020；Lee，2019）`），比逐句各引一篇更有力。
- 正文使用作者-年份引用，与文末参考文献一致；成稿阶段不新增引用（需要新证据就退回上游）。
- 上游没有编号的判断，若必须保留，标 `[证据不足]`；一般情况下优先降低措辞强度或删除。

## 收束怎么写

完整参考稿通常按这个顺序收束：

1. 问题重要性 / 核心矛盾
2. 已有工作沿哪些路线展开
3. 这些路线在何种条件下有效、在何种条件下受限
4. 当前证据指向的主要瓶颈或未解问题

**最后一句停在文献层面的未解问题**，示例：

- "现有研究虽已在标准场景下取得显著进展，但在跨域泛化与评测一致性方面仍缺乏稳定证据。"
- "该方向的关键问题已不再是方法是否有效，而是何种条件下其优势能够稳定成立。"

**不要这样收束**（越界成论文引言的贡献声明）：

- "为解决上述问题，本文提出……"
- "因此，本文将……"
- "our work addresses these limitations by ..."

## 对比表在成稿里用不用

成稿以连续散文为主。对比表属于调研结果层的辅助件，一般不进成稿参考稿。除非用户明确要求保留表格，否则最终正文不要输出表格。

## 自检

1. 删掉所有引用后，剩下的还是一篇有判断、有主线的综述，而不是零散事实？
2. 相邻段落之间有没有过渡句？
3. 把最后一段单独拿出来看，它是在总结文献现状，还是已经偷偷变成论文引言的贡献声明？
4. 有没有残留分点、小结标记、导航段这类调研层脚手架？
5. 有没有新增上游没有的作者、年份、事实、方法、数据或引用编号？
6. 有没有为了显得完整而删掉必要的 `[证据不足]`？
7. 是否通过 `python scripts/check_review_draft.py --input .workflow/review_draft.md --write-report .workflow/review_draft_check.json`？
