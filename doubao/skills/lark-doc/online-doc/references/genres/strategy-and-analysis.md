## 分析报告信息来源：用户附件 > 联网搜索

- **阅读用户附件（重要性与权威性都最高）**：用户上传或提供的一切材料都是本次任务的第一手事实来源，优先级高于联网搜索和先验知识。附件中的关键信息可能藏在图、表或公式里，只读取纯文本会造成遗漏；此前只取得文本或尚未读取附件时，必须重新解析。DOCX 按当前 Skill 的跨载体路由先进入 Office Word 模块，PDF 和其他附件调用对应文件能力；同时读取文字、结构和视觉信息。DOCX 至少覆盖段落、表格、页眉页脚、媒体、图表、嵌入对象和逐页视觉；PDF 提取全文并查看每页，含图表、表格、图片或扫描信息的页面必须查看清晰页面图。附件中的图片和表格插入云文档时必须保留全部信息，不得裁剪，可以等比缩放以适配排版；与其他来源冲突时以用户附件为准。创建飞书文档前，必须完整读取附件中的文字、图片、表格等相关信息。
- **联网搜索**：补齐主题相关的真实数据、事实、案例；不得编造，缺失就标注占位/假设/待补，并标注来源。用户给的是完整文档或逐页大纲、且没说能否扩写时，默认联网搜索扩充素材与案例，除非用户明确要求不扩写。

## 内容密度原则

1. 除非用户明确要求演讲式短稿，否则默认视为报告型云文档——整篇围绕连续阅读、查阅证据和形成判断展开，对标高质量研究报告或咨询分析文档。
2. 每个核心章节都有足够深度：每段、每个章节的核心结论可被迅速抓住，展开阅读能获得完整的证据、解释、边界与下一步，不要用简短的一句结论占据完整的章节。
3. 论证从结论向证据层层展开：标题给出判断后，章节承载若干可独立成立的支撑性判断；每项判断附可核验的数据、案例、引用或明确的推理边界。
4. 正文的一级章节标题优先使用陈述式判断，例如“核心市场份额三年内从 34% 降至 19%——渠道老化与定价失位是主因，非需求萎缩”；但必须根据实际内容决定是否使用并且由材料支持，不能为了结论式标题而夸大推断。如果不适合时，可以退到普通标题。

### 摘要必须先回答决策问题

**首个“执行摘要/报告摘要”必须先给出读者据以行动的核心判断。**

摘要依次说明：

1. **结论**：当前应推进、调整、暂缓，还是补充数据后再判断；
2. **依据**：支撑结论的 3—5 个关键事实或指标；
3. **约束**：最主要的风险、缺口或条件；
4. **行动**：优先动作、决策门槛或待核验事项。

摘要中的结论必须写明适用范围、数据期间和必要限制，并能在正文找到对应证据、计算过程或限制说明。

**禁止**：只罗列收入、成本、增长率等数据，或用“总体良好”“存在一定问题”等空泛表述代替结论。

## 附件、数据与事实边界

**1.用户材料是本次任务的第一手事实来源，优先级高于联网搜索和先验知识。**

用户附件不能只在任务开始时被概括或摘要。开始写作前，必须回到原始附件核对将要采用的细节，避免因早期压缩理解而遗漏限定条件、数据口径、图表信息、例外情况或原文措辞。

- **DOCX 附件**：必须按正文顺序读取段落、表格内容及表格的物理单元格、逻辑列和合并关系；再运行摘要并按提示读取页眉页脚等部件。文本框、内容控件、嵌套表格、图片表格、浮动对象和扫描页必须结合逐页视觉检查，不能仅凭结构化提取认定已读完整。
- **Excel 附件**：按本页“附件必须完整读取后才能分析”执行全工作簿盘点和逐表提取；公式、跨表关系、隐藏表、图片和图表均属于附件内容，不能只读单一工作表或表格预览。
- **PDF 附件**：必须提取文本，并盘点页面视觉对象，渲染或查看每页；含图表、表格、图片或扫描信息的页面必须查看清晰页面图。
- **图片/表格**：插入文档时必须保留原图表的所有信息，不允许裁剪，但可以缩放大小来适配排版布局。

**2.多附件信息处理**：

- **附件角色**：多附件时，先明确每份材料的用途。模板只决定结构和格式；上下文材料用于理解任务背景；素材和事实材料用于支持具体内容；示例只用于学习结构、粒度或表达。
- **按问题整合**：不要按附件顺序分别摘要或写作。应围绕同一对象、时间、事项或结论，将分散在不同附件中的相关信息匹配、补全和整合。
- **冲突处理**：附件信息不一致时，先区分其对象、时间、地区、口径和角色；不能确认时明确保留差异或待确认，不得自行拼接、混算或选择性采用。

**每份附件必须说明角色、读取状态、实际采用内容、排除内容及其影响。在内容规划中说明附件、来源及其用途**

**3.进入核心结论的数据必须记录范围、口径、依据、状态与限制。**

- **依据**：来自何处，是否可复算；
- **状态**：原始事实、计划、假设还是建议；
- **限制**：能否直接比较，是否存在缺失或冲突。

材料未提供、口径冲突或无法核验时，写为“未提供”“待核”或条件性判断；不得补造数字、比例、原因、案例或因果关系。

4.正文不得插入“（来源：文件名、行号……）”等冗长来源说明，避免打断阅读。需标明依据时，正文仅作简短标注；文件名、页码、工作表、行号等定位信息放入脚注、尾注或“资料来源”附录。
图表的数据来源仍按本页图表规则置于图下，不适用本条。

## 数据与图表原则

### 基本原则

1. 数据是论证的核心支撑：围绕主题充分收集和核验真实数据，优先通过可视化图表（HTML5 block承载的交互式可视化图表、表格以及画板（如有需要））呈现；每项数据来源必须注明，绝不杜撰。
2. 图表要素齐全：保留必要的坐标轴、单位、图例、来源、计量口径，使一张图表脱离正文也能独立成立。
3. 在图表中标出数据拐点与关键值并解释含义；每张图表都需要有相应的段落说明其所证明的判断、图表可见的发现、对决策的启示，以及来源与边界，不能只给图表不给任何图表说明段落。
4. 鼓励使用 `table`、`html5-block` 与 `whiteboard` （如有需要）组合表达复杂数据与关系，不要纯文字堆砌数据。
5. 同一篇文档中的数据图表（`html5-block` 及 `whiteboard`，优先使用 `html5-block`）使用同一主色系深浅，不引入第二主色族；多类别图例必须明显可区分，优先保证识别性；不同颜色的图例必须说明差异含义。
6. 可视化选择：

- 如果需要表达三个以上趋势、分布、构成或权衡关系，不要全篇只用 `table`；只有读者任务是逐项查阅精确值、且不存在需要看模式的关系时，才全部使用表格。
- 每一节默认只保留最多一个主可视化；新增图表、表格或画板必须回答不同的读者问题。
- 每个可视化都要支撑一个明确判断；不能说明“它证明什么”的，不生成。
- 同一组数据默认只选一种主表达：查精确值用 `table`，看趋势/分布/权衡用 `html5-block`，看因果/依赖/路径用 `whiteboard`。重复、装饰性或不降低理解成本的可视化一律删除。

1. 关键总量、端点、拐点、异常值、差距或增长率可被标记；不把所有数据点都加标签。
2. 实际与预测、已验证与假设的数据必须采用明确文字和图表标记区分；不能依赖读者自行猜测。
3. 无可靠定量数据时，使用定性证据、待补数据表或结构图；不得生成外观可信但数值虚构的图表。

###### **图表和表格是证据呈现，不是装饰:**

在线文档中的趋势、分布、构成和权衡默认使用单文件 `html5-block`；只有用户明确需要静态图、原始材料本身是图片证据，或 HTML5 无法降低理解成本时，才生成静态 PNG 并通过 `<img path="@./chart.png"/>` 写入飞书文档。制作前明确：

- 它回答什么问题，支撑什么发现；
- 使用哪些数据和口径；
- 放在正文哪个判断之后，读者需要从中看到什么。

###### 制作前先选唯一主证据：**先按关键判断选择证据，再制作图或表**

对同一个分析单元——相同对象、期间、分组维度、核心指标和结论——正文只能选择一种主证据形式：图或表。

- 看趋势、排序、结构、异常或情景变化：选图；
- 精确查数、复核计算或展示图中未呈现字段：选表；
- 完整数据明细、审计复核或计算依据：移入附录。

无法说明图和表分别回答了什么不同问题时，删除其中一种。

###### **每张图或表必须回答一个明确问题**

若不能支持比较、诊断、决策或复核，不新增。报告形成“核心判断—证据—解释或限制—建议动作/待验证问题”的闭环；不得以增加图表或表格数量替代分析。

**禁止**：正文同时放置对象、期间、分组维度、核心指标和结论相同的图和表。

表格多出少量原始字段、比例或计算字段，不能作为保留重复图表的理由。

- **图**：趋势、排序、差距、结构、异常和情景变化；
- **表**：精确查数、计算复核和图中未呈现的字段；
- **附录**：统计指标口径说明、资料来源清单，以及确有复核必要的完整明细或计算依据。

只有读者任务、核心指标或比较维度实质不同且无法由另一种形式替代时，图和表才能同时保留。

### 数据可视化排版

- 可视化对象单独成行，不放入分栏、引用块或其他表格中。飞书 XML 当前没有定义多个 `html5-block` 的并排写法；确需并排比较两个图表时，将它们放入同一个 HTML 文件，并在该 HTML5 Block 内部使用响应式 CSS Grid，否则使用两个独立 Block 纵向排列。
- `table` 用于查阅精确值、逐项比较和选项评估；只保留支撑当前判断的行列，表头清晰，关键单元格只使用全文选定的合法命名色文字或对应 `light-*` 浅色背景。
- `html5-block` 用于快速看出趋势、差异、构成或权衡；自适应文档宽度、不产生横向滚动，常规高度 360–420px。关键数值、标签和结论默认可见，交互仅作辅助。
  - 时间趋势用折线图；类别比较和排名用横向条形图；跨期构成用堆叠条形图；相关或权衡用散点图；阶段转化用漏斗图。
  - 饼图/圆环图用于一个整体内不超过 5 类的互斥构成，需要直接标注类别、数值和占比；雷达图用于同一量尺下、2–3 个对象的多维能力画像。需要精确比较、对象过多或跨期比较时，改用条形图或表格。
- `whiteboard` 用于因果、流程、依赖、决策路径等非数值关系；一张画板只表达一种关系，箭头有方向并止于节点边缘，不穿过文字。
- 表格与图表同时使用时分工明确：图表看模式，表格查明细；不重复呈现同一信息。

## 场景级 Block 规则

| 信息关系                   | 首选表达          | 使用边界                    |
| ---------------------- | ------------- | ----------------------- |
| 指标、选项、情景、字段的精确比较       | `table`       | 可逐项查阅；表前给问题，表后给来源、口径与结论 |
| 趋势、分布、构成、相关性、漏斗、敏感性或取舍 | `html5-block` | 真实数据驱动；图表完整、可读、可追溯      |
| 因果、依赖、决策分支、路线或定位       | `whiteboard`  | 只表达一种主要关系，不替代数值证据       |
| 原始数据、持续维护的计算模型或多人填报    | Sheet/Base    | 以嵌入或链接承接，不用文档截图替代       |
| 原始报告、产品界面、现场证据或外部图表    | `img`         | 仅在图像本身是证据时使用，保留图注与来源    |
| 关键假设、风险或待决事项           | `callout`     | 仅高亮真正需要决策者注意的一项，不连续堆叠   |

## 视觉系统

阅读型分析文档应克制、清晰、可核验，质感由留白、对齐、单一色相色阶与细线建立，而非装饰。将原生 XML 与视觉资产分成两层：

- **原生 XML 层**：标题、正文、列表、表格和 `callout` 只使用 [`lark-doc-xml.md`](../lark-doc-xml.md) 定义的命名色。`text-color`、`border-color` 只使用基础色相；表格背景只使用基础色相、`light-*` 或 `medium-gray`；callout 背景只使用 `gray`、`light-*` 或适用的 `medium-*`。不写十六进制颜色，也不使用未定义的 `black`、`white` 或边框样式。
- **视觉资产层**：HTML5 内部 CSS、SVG 画板和静态图可使用精确十六进制色值。优先使用用户提供的品牌 VI；没有品牌规范时，只选择下表一套资产色板。

| 资产色板 | 主色 | 辅助层级 | 原生 XML 映射 | 适用场景 |
| --- | --- | --- | --- | --- |
| 藏青 | `#1A2B4A` | `#758092` / `#BABFC9` / `#DDE0E4` | `blue` / `light-blue` / `gray` | 战略报告、投资与决策 |
| 墨绿 | `#1C3D2E` | `#778B82` / `#BBC5C0` / `#DDE2E0` | `green` / `light-green` / `gray` | 行业研究、可持续主题 |
| 炭黑 | `#252525` | `#7C7C7C` / `#BFBFBF` / `#DEDEDE` | `gray` / `light-gray` / `medium-gray` | 纯数据驱动、极简中性主题 |

- 精确主色承载 HTML5、SVG 和静态图中的重点对象；同一资产只使用同一主色的有限层级。原生章节编号、短语强调和状态色使用对应命名色，不把十六进制色值写入 XML。
- 风险或异常在原生 XML 中使用 `red` 或 `orange`，在资产内部使用同一语义的低饱和强调色。重点词句可加粗或使用一个合法命名色；不整段染色，不混用多个强调色。
- 信息分区保持一致：结论在章节标题，证据在表格、图表或画板，解读紧邻对象，来源与口径置于对象下方，行动建议集中在收尾。表格来源与口径使用 `<p align="center"><span text-color="gray">来源：…｜期间：…｜单位：…｜口径：…</span></p>`，不与读表结论混写。

### 图表、表格与画板配色系统

先选定整篇主色，再将颜色按下列角色分配；不得按图表或章节任意换色。

| 颜色角色 | 原生 `table` | `html5-block` / SVG `whiteboard` |
| --- | --- | --- |
| 主信息 / 推荐项 | `medium-gray` 或 `light-blue` / `light-green` 表头；关键短语使用对应基础色 | 使用资产主色表示当前期、重点对象、推荐路径或关键结论 |
| 次要比较 | 默认背景，必要时使用 `light-gray` | 使用资产主色浅层级或灰色 |
| 不确定 / 待验证 | `gray` 文字或 `light-gray` 背景 | 灰色虚线、空心标记或浅灰填充 |
| 风险 / 阈值 / 异常 | `red` / `orange` 文字或 `light-red` / `light-orange` 背景 | 使用同语义的低饱和风险色，并直接标注含义 |

**HTML5 图表**

- 默认采用“一个重点色 + 灰色比较项”：重点对象使用深主色，历史期、基准、非重点对象使用灰色或主色 60%。预测使用主色 60% 虚线；阈值使用暖赤或琥珀虚线，并直接标注阈值含义。
- 同一指标确需展示 3–5 个有序系列时，按“深主色 → 主色 60% → 主色 30% → 主色 15%”排列，并在图例/直接标签中保持同一顺序。无序类别不应只靠相近色区分；优先直接标注，类别过多时改用排序条形图或表格。
- 多类别构成图可使用同一主色的 4–5 档清晰色阶；仅当一个类别本身具有风险、异常等明确语义时，才用暖赤或琥珀替换其中一档。禁止彩虹配色、默认 ECharts 配色、渐变填充、3D、投影和大面积高饱和色。
- 坐标轴、网格线、图例文字和非重点标签使用灰色；去除纵向网格线，至多保留极淡横向辅助线。数据标签只显示端点、拐点、异常值和需要决策的值。
- 横向条形图的数据标签必须单行完整显示，不得因柱宽不足而换行、截断或挤压。长条可将标签置于柱内；短条必须将标签移至柱右侧，并使用与背景有足够对比的文字颜色。
- 不按数据百分比硬编码标签位置。生成后按实际渲染宽度比较柱宽与标签文字宽度：柱内空间不足时自动切换为柱外标签；条形仅承担数值编码，不承担强行容纳文字的职责。
- 对 CSS/SVG 自定义条形图，数值标签与色块分离实现；不得将可换行文本直接作为短色块内容。标签容器禁止自动换行，且不得被父容器裁切。
- 生成后必须查看图表实际渲染效果。每个 `markLine`、`markPoint`、箭头、引线、阈值线和文字标记都必须有对应的真实数据、计算口径或明确决策含义，并能在相邻解读中说明；无依据、与指标无关、遮挡数据或位置错误的标记一律删除。

**表格**

- 表头优先使用 `light-gray` 或 `medium-gray`；确有主题语义时可使用 `light-blue` 或 `light-green`。正文保持默认背景，只用合法的 `light-*` 做必要状态或分类提示。不要求 XML 未定义的边框颜色、纵向线、投影或渐变。
- 第一列主体名称加粗；数值列右对齐。关键值可使用全文选定的一个基础命名色或对应 `light-*` 浅底，风险/异常值使用 `red`、`orange`、`light-red` 或 `light-orange`，且不整行染色。
- 对仅包含数字和文字的常规表格，在页面可用宽度内优先减少非必要换行；无法兼顾时，优先保证不横向溢出和可读性，允许长说明自然换行。不得为避免换行将表格扩展到页面外。
- 表格下方的来源与口径使用独立、居中的灰色段落：`<p align="center"><span text-color="gray">来源：…｜期间：…｜单位：…｜口径：…</span></p>`；读表结论另起左对齐段落，不与来源混排。

**画板**

- SVG 画板属于视觉资产层，可使用所选资产色板的精确色值。已验证事实使用默认浅色背景和主色细边；证据分组使用主色浅层级；推荐结论或路径使用主色重点显示；待验证假设使用浅灰填充与灰色虚线边；风险或约束使用同一低饱和风险色。
- 普通连线使用中性灰细线；只有关键依赖、风险传导或推荐路径可使用主色或风险色连线。颜色必须与节点状态一致，不能只靠颜色传达“事实、假设、建议或风险”的区别，节点标题中也要写明状态。

## Presentation Decision

选择本 Profile 时，必须使用 `presentation_mode: "rich"`。`rich` 只在本文件明确允许的表达范围内生效；本文件的视觉系统、组件限制、编号、素材、来源与回读规则为硬约束，优先于通用候选表达，不得因 `rich` 放宽。按本文件的证据、数据可视化、配色与组件规则选择 `table`、`html5-block` 和 `whiteboard`；不为视觉而添加图片、图表或画板。材料只包含定性判断时，不强制生成数值图表。

`visual_plan.reason` 必须包含：`策略与分析｜主色体系｜核心判断；数据来源与口径；表格/图表/画板的分工`。有可用趋势、分布、构成、相关性、漏斗、敏感性或取舍数据时，`visual_plan.blocks` 必须记录至少一个 `html5-block` 的数量和用途；仅有精确比较数据时，使用 `table` 即可，`blocks` 可为 `[]`。需要表达因果、依赖、决策树或路线图时，再记录 `whiteboard` 的数量和用途。`callout` 最多使用一次，只用于开头的核心判断/阅读说明，或结尾的行动建议/待决事项；不连续堆叠，也不用于普通证据说明。

示例：

```json
{
  "presentation_mode": "rich",
  "visual_plan": {
    "reason": "策略与分析｜藏青主色｜比较三种进入策略；以市场规模与单位经济数据支持判断；表格呈现精确假设，HTML5 图表呈现市场增长与回本敏感性，画板补充进入路径依赖。",
    "blocks": [
      {"type": "html5-block", "min_count": 2, "purpose": "展示市场规模趋势与三种策略的回本敏感性"},
      {"type": "whiteboard", "min_count": 1, "purpose": "展示推荐策略的阶段、依赖与复核节点"}
    ]
  }
}
```

## 禁止项

1. 不杜撰数据、来源、样本、对照、基准、客户案例、市场规模、预测或实验结果。
2. 不用一张没有来源、单位、时间范围或口径的图表支撑关键结论。
3. 不用段落罗列替代本可由 `table`、`html5-block` 或 `whiteboard` 清楚表达的关系。
4. 不用 `whiteboard` 绘制密集数据表或伪图表；不把 `html5-block` 做成只有大数字和装饰的空洞仪表盘。
5. 禁止几个不同的图表使用完全不同的色系、无意义网格线或整行高饱和填色。
6. 不把相关性写成因果，不把预测写成事实，不把未验证假设写成结论。
7. 不以图片、装饰、空泛商业套话或复杂术语代替证据、口径与清晰建议。

## 交付前检查

- [ ] 已明确读者要回答的决策问题、判断标准和文档的最终建议或下一步。
- [ ] 每个关键结论均有可追溯证据；事实、推断、假设、预测和建议已清楚区分。
- [ ] 每项外部数据、图表、表格和关键案例均有来源、日期/时间范围、单位、口径和必要边界。
- [ ] 相邻图表/表格是否承担不同阅读任务，是否重复呈现同一数据和结论。如果重复呈现，则需要删除其中一种，仅保留最适合的呈现方式。
- [ ] 有可用定量材料时，已优先采用 `table` 或 `html5-block`；需要同时查值与看模式时，两者分工互补而非重复。
- [ ] 每张表格遵守表前问题、精简行列、清晰表头、数值右对齐、主体名称加粗、有限强调；来源与口径紧贴表格下方、独立居中、灰色显示，读表结论另起段落。
- [ ] 每个 HTML5 图表具有正确选型、真实数据、必要标签/图例/时间范围/单位/来源，且不含默认视觉、伪精确数值或叠印长文字；已实际检查渲染结果：标题、图例、坐标轴、数据标签、来源、标记和连线均完整可见，短条标签未换行、未被裁切，所有标记、阈值线和注释均有明确依据与正确位置。
- [ ] HTML5 图表使用单文件、有效 meta、响应式宽度和适当高度模式，大小不超过 500KB。
- [ ] 每张画板只表达一种主要关系，连线不穿字，且作为数值表格/图表的补充而非替代。
- [ ] 全篇仅使用一套资产主色体系；原生标题、正文、表格和 callout 只使用合法命名色，十六进制色值仅出现在 HTML5、SVG 或静态图片内部。强调色仅用于有语义的关键差异、风险或异常。
- [ ] 创建成功后，使用 `docs +fetch --doc "<document_id 或文档 URL>" --detail full` 回读；核对表格、HTML5 图表和画板均实际存在、可读、与相邻结论对应，来源与口径没有遗漏。发现问题时按 update 流程做最小范围修复并再次回读。
