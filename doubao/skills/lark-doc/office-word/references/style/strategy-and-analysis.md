# 分析报告与决策支持

**工作主线**：1. 确认本指南是否适用并明确分析问题 → 2. 完整读取材料并确认事实边界 → 3. 开展分析并持续关注 P0 风险项 → 4. 形成判断、建议及证据呈现 → 5. 应用一般格式、目录与分页 → 6. 完成交付前逐项检查。

## 适用范围与路由自检

**命中：基于材料形成发现、判断或建议。**

- 适用于经营、销售、成本、项目、产品、市场、行业、竞品、商业机会和战略分析；
- 用户上传表格后仅说“写一份详细分析报告”时，默认命中本题材。

**不命中：只整理材料，不形成判断。**

- 仅转写、提取、排版、摘要或原样整理材料；
- 数据只用于支撑既定的工作总结、请示、发言稿、合同等其他题材。

## 附件、数据与事实边界

1. **用户材料是本次任务的第一手事实来源，优先级高于联网搜索和先验知识。**

用户附件不能只在任务开始时被概括或摘要。开始写作前，必须回到原始附件核对将要采用的细节，避免因早期压缩理解而遗漏限定条件、数据口径、图表信息、例外情况或原文措辞。

- **DOCX 附件**：必须按正文顺序读取段落、表格内容及表格的物理单元格、逻辑列和合并关系；再运行摘要并按提示读取页眉页脚等部件。文本框、内容控件、嵌套表格、图片表格、浮动对象和扫描页必须结合逐页视觉检查，不能仅凭结构化提取认定已读完整。
- **Excel 附件**：按本页“附件必须完整读取后才能分析”执行全工作簿盘点和逐表提取；公式、跨表关系、隐藏表、图片和图表均属于附件内容，不能只读单一工作表或表格预览。
- **PDF 附件**：必须提取文本，并盘点页面视觉对象，渲染或查看每页；含图表、表格、图片或扫描信息的页面必须查看清晰页面图。
- **图片/表格**：插入文档时必须保留原图表的所有信息，不允许裁剪，但可以缩放大小来适配排版布局。


2. **多附件信息处理**：
  - **附件角色**：多附件时，先明确每份材料的用途。模板只决定结构和格式；上下文材料用于理解任务背景；素材和事实材料用于支持具体内容；示例只用于学习结构、粒度或表达。
  - **按问题整合**：不要按附件顺序分别摘要或写作。应围绕同一对象、时间、事项或结论，将分散在不同附件中的相关信息匹配、补全和整合。
  - **冲突处理**：附件信息不一致时，先区分其对象、时间、地区、口径和角色；不能确认时明确保留差异或待确认，不得自行拼接、混算或选择性采用。

**每份附件必须说明角色、读取状态、实际采用内容、排除内容及其影响。在内容规划中说明附件、来源及其用途**

3. **进入核心结论的数据必须记录范围、口径、依据、状态与限制。**

- **依据**：来自何处，是否可复算；
- **状态**：原始事实、计划、假设还是建议；
- **限制**：能否直接比较，是否存在缺失或冲突。

材料未提供、口径冲突或无法核验时，写为“未提供”“待核”或条件性判断；不得补造数字、比例、原因、案例或因果关系。

4. 附件内容使用过程仅需记录在`attachment_purpose.md`中，正文不得插入“（来源：文件名、行号……）”等冗长来源说明，避免打断阅读。需标明依据时，正文仅作简短标注；文件名、页码、工作表、行号等定位信息放入脚注、尾注或“资料来源”附录。
图表的数据来源仍按本页图表规则置于图下，不适用本条。

## P0 分析输入必检验项

内容规划、计算、写作和作图必须遵循以下核验要求；关键结论、指标、图表和建议形成后，必须写入内容规划。

### P0 附件必须完整读取后才能分析

**未完成附件盘点和读取范围确认时，禁止建立数据结论、图表或建议。**

1. **读取用户材料是具体事实的基础**
- 用户上传或提供的一切材料是本次任务的第一手事实来源，优先级高于联网搜索和先验知识。附件中的关键信息常藏在图、表、公式里，仅靠文本提取会丢失；如果之前读取附件时只获得了文本信息或没有读取附件，必须再次解析。
  - **禁止只用摘要替代附件信息细节**：用户附件不能只在任务开始时被概括或摘要。开始写作前，必须回到原始附件核对将要采用的细节，避免因早期压缩理解而遗漏限定条件、数据口径、图表信息、例外情况或原文措辞。
2. **必须完整读取所有内容**：
必须完整阅读完。不得只根据文件名、首个工作表、前若干行、导出预览或单个汇总表开始分析。
DOCX、PDF、图片和表格均须读取其文字与视觉信息；图、表、公式、扫描页、批注和嵌入对象中的相关内容不得因初步提取而遗漏。
  - **表格**：盘点全部工作表名称与状态、使用范围、公式、合并关系、隐藏行列、图表/图片、定义名称和跨表引用；再对每张可能影响任务的工作表按实际单元格、公式及缓存值读取。公式表必须同时理解公式关系和可用计算结果；缓存值缺失、过期或无法复算时，记录为读取缺口，不得把结果写成已核验事实。
  - **DOCX**：按正文顺序完整读取段落、表格、页眉页脚、文本框、内容控件、嵌套表格、图片表格和浮动对象；逐页检查图片、扫描页及其他视觉信息。
  - **PDF**：提取全文并查看每页；图表、表格、图片和扫描内容必须结合清晰页面图完整读取。
  - **PPT/PPTX**：逐页读取标题、正文、备注、表格、图表、图片、形状和动画所承载的信息，并逐页视觉检查版式及非文本内容。
  - **其他文件**：完整读取全部内容及信息性视觉对象；不能可靠读取时，记录读取缺口及其影响。
  - **工作表采用范围**：每个可见、隐藏或非常隐藏工作表都必须在内容规划中明确“采用什么”或“为何排除”。只有与读者问题无关、重复且不改变判断的工作表才可排除；不能把“未读”写成“无关”。
  - **大表、多文件与视觉信息**：大表必须先取得全表字段、数据范围、公式和缺失概况，再按分析问题聚合、筛选或抽取明细；禁止只读取开头区域。多份附件须先比较对象、期间、单位和关联键，确定能否合并。盘点到图表、图片、仪表盘、条件格式或扫描内容时，必须逐项视觉检查；图中信息不能用单元格文本替代。

3. **多附件信息处理**：
  - **附件角色**：**多附件时**，先明确每份材料的用途。模板只决定结构和格式；上下文材料用于理解任务背景；素材和事实材料用于支持具体内容；示例只用于学习结构、粒度或表达。
  - **按问题整合**：不要按附件顺序分别摘要或写作。应围绕同一对象、时间、事项或结论，将分散在不同附件中的相关信息匹配、补全和整合。
  - **冲突处理**：附件信息不一致时，先区分其对象、时间、地区、口径和角色；不能确认时明确保留差异或待确认，不得自行拼接、混算或选择性采用。

4. 完成后，内容规划必须列出已读工作表及采用/排除理由；仅在没有影响判断的未读工作表、未读公式关系、未读视觉信息或未解决数据缺口时，才能视为读取完整。否则说明哪些结论、比较或图表不能成立。

### P0 交付前核验：任一未通过不得交付

- [ ] 摘要先给出核心判断、量化依据、关键限制和行动建议，不得只是概述目录或复述数据；
- [ ] 关键指标已按计算式核验，不得照搬字段名造成指标语义错误；
- [ ] 计划、预算、预测与已发生事实已明确区分；
- [ ] 正文不存在图和表对相同对象、期间、指标和结论的重复表达；
- [ ] 每项建议均对应前文证据、问题或待核验事项；
- [ ] 关键结论、图表和建议均可回溯至附件、计算或明确假设。
- [ ] 每份数据附件的全部工作表、公式关系和信息性视觉对象均已采用或明确排除；不存在会改变判断的未读范围。

### 先建立数据口径层

**关键指标必须可比、可复算、可追溯。**

对每个进入核心结论、图表、表格或计算的关键指标，确认：

- **范围**：对象、期间和比较范围；
- **口径**：单位、统计方式及必要的分子分母；
- **计算**：汇总、筛选或关联方式；
- **依据**：来源位置和可比性。
- **`NaN`空值检查**：如果计算数据的分母存在缺失值，则不适用特定的`NaN`数据，且禁止按照自己的推断补全数据。

关键数字必须可回溯到附件、工作表、原始位置或可复算公式。

**必须**：发现跨期、跨口径、缺失、重复、异常、关联错误或数据冲突时，先说明限制；不得直接得出确定性比较结论。

**禁止**：直接平均日均值、单价、转化率、毛利率等比率；必须按正确分母或总量重新计算。

**禁止**：只按源表字段名理解指标。字段名与计算公式、实际业务含义不一致时，必须按计算式重新命名，并在数据口径说明中指出差异。

### 先确认现象，再解释原因

**先确认“发生了什么”，再判断“为什么”。**

- 先核对数值、趋势、差异、异常、集中度、结构变化或目标偏差；
- **必须**：只有材料、计算或可核验来源支持的原因，才能写为“已证实解释”；
- **证据不足时**：写为“可能原因/需核验”；
- **禁止**：因时间先后、相关性或单个案例直接推出因果关系。

### 事实、计划、推断与行动分开

**必须明确内容的事实状态。**

- **事实/结果**：附件直接记载或可复算得到的内容；
- **计划/测算**：预算、预测、目标和情景测算，写为“计划值”“预计”或“按现有假设测算”；
- **解释**：写为已证实解释或待核假设；
- **行动**：写为“建议/下一步”，并与对应问题、指标或风险绑定。

**禁止**：把附件未记载的经营动作、原因、制度、行业基准和结果，或计划、预测和测算，写成已经发生的事实或成效。

### 摘要必须先回答决策问题

**首个“执行摘要/报告摘要”必须先给出读者据以行动的核心判断。**

摘要依次说明：

1. **结论**：当前应推进、调整、暂缓，还是补充数据后再判断；
2. **依据**：支撑结论的 3—5 个关键事实或指标；
3. **约束**：最主要的风险、缺口或条件；
4. **行动**：优先动作、决策门槛或待核验事项。

摘要中的结论必须写明适用范围、数据期间和必要限制，并能在正文找到对应证据、计算过程或限制说明。

**禁止**：只罗列收入、成本、增长率等数据，或用“总体良好”“存在一定问题”等空泛表述代替结论。

### 以完整论证替代指标罗列

**每个关键段落只推进一个判断。**

按“发现或判断 → 证据与基准 → 解释或限制 → 对读者的含义”推进。每个关键判断至少写清：

- 发生了什么，以及与什么基准相比；
- 影响规模或优先级；
- 已证实解释或待核假设；
- 对决策、资源配置、风险控制或下一步验证的含义。

**禁止**：以多个段落重复同一意思，或按附件顺序逐项复述。

建议、优先级或后续动作必须从前文发现导出；证据不足时提出验证问题或所需数据，不把推测包装成结论。

## 内容分析与决策形成

**先确定读者需要据报告完成什么判断或行动。**

用户未明说读者任务时，根据材料的对象、字段、期间和标题推断最小的分析问题，不凭空设定战略目标。

1. **先核验数据能不能比较**：对每个核心指标确认范围、口径、计算和依据。不同范围、期间、单位或分母的数据不得直接比较、平均或汇总；发现缺失、重复、异常、冲突或无法复算时，先写明限制，不得直接下确定结论。
2. **先写清发生了什么**：从数据中确认趋势、差异、结构、异常、集中度或目标偏差。每个关键判断必须说明数值是什么、与什么比较、差异有多大、影响哪个对象或结果。
3. **再判断为什么发生**：只有附件、计算或可核验来源支持的原因，才能写成确定解释；没有直接证据的原因必须写为“可能原因”或“待核验事项”，不得把相关性、时间先后或经验判断写成因果关系。
4. **最后形成可行动结论**：结论必须说明对读者的影响：是否可推进、应优先处理什么、需达到什么条件，或还缺什么数据。每项建议必须对应前文一个已识别的问题、指标或风险；不得脱离证据单独提出泛化建议。

按读者任务组织正文，可围绕发现、问题、比较、原因、机会、风险、建议或验证安排章节；只保留真正帮助回答问题的部分，不能为了套模板机械补齐“背景、原因、建议”等章节。

## 证据呈现：图表、表格与附录

**图表和表格是证据呈现，不是装饰。**

当前使用 Python 生成静态 PNG 图表后插入 Word。制作前明确：

- 它回答什么问题，支撑什么发现；
- 使用哪些数据和口径；
- 放在正文哪个判断之后，读者需要从中看到什么。

### 制作前先选唯一主证据

**先按关键判断选择证据，再制作图或表。**

对同一个分析单元——相同对象、期间、分组维度、核心指标和结论——正文只能选择一种主证据形式：图或表。

- 看趋势、排序、结构、异常或情景变化：选图；
- 精确查数、复核计算或展示图中未呈现字段：选表；
- 完整数据明细、审计复核或计算依据：移入附录。

无法说明图和表分别回答了什么不同问题时，删除其中一种。

**每张图或表必须回答一个明确问题。**

若不能支持比较、诊断、决策或复核，不新增。报告形成“核心判断—证据—解释或限制—建议动作/待验证问题”的闭环；不得以增加图表或表格数量替代分析。

**禁止**：正文同时放置对象、期间、分组维度、核心指标和结论相同的图和表。

表格多出少量原始字段、比例或计算字段，不能作为保留重复图表的理由。

- **图**：趋势、排序、差距、结构、异常和情景变化；
- **表**：精确查数、计算复核和图中未呈现的字段；
- **附录**：统计指标口径说明、资料来源清单，以及确有复核必要的完整明细或计算依据。

只有读者任务、核心指标或比较维度实质不同且无法由另一种形式替代时，图和表才能同时保留。

### 分析数据表排版

**数据表应与正文版心同宽，并按列统一对齐。**

- 表格总宽度必须等于正文版心宽度，渲染后左右边界与正文对齐；不得因内容多少缩窄为页面中间的小表；
- 表头、表内文字和数字的水平/垂直对齐、字号、缩进及单元格边距，必须按 [writing-taxonomy.md](writing-taxonomy.md) 的“表格样式”执行；同一列保持一致。
- 长段说明不应塞入居中数据列，应改为正文、注释或附录；
- 单元格内段落的首行、左侧和右侧缩进均为 0；除非用户明确要求；
- 表格总宽度按页面可用宽度精确分配列宽，不能依赖内容自动收缩或空格排版。

### 图表排版：位置、图题、分页与图例

**图表首次引用段、图片、图下 Caption 和简短解读必须构成连续阅读单元。**

**禁止**：前页大面积留白、图片单独占页、图题与图片拆页，或图后没有解释就直接进入下一节。

**同一分析问题下，相关图可合并为一张多子图。**

- 同一时间轴下的相关指标：优先上下排列；
- 同一对象维度下的规模与效率指标：可横向并排；
- 子图：必须共享对象、期间或读者问题，颜色含义保持一致，各自仍可独立阅读；
- 图号与图题：整张图使用一个连续图号和总图题，子图以“（a）”“（b）”区分。

**禁止**：为压缩篇幅硬拼无关问题。

**尺寸与分页：优先保证完整阅读单元，而不是填满页面。**

- A4 通用格式：常规单图显示宽度优先为 13—14 cm，高度必须按原图像素比例反算；不得为统一高度拉伸、压扁、裁切或异常放大，且不得超过正文版心（约 16 cm）；
- Python 标准分析图固定导出为 1,680 × 960 px（240 dpi）；不得为放大页面而低分辨率拉伸，也不得无理由输出超大图片；
- 所有图片必须创建为嵌入式（inline）图片，不得使用浮动图片，以免溢出页面或脱离正文；
- 每张插入图必须显式设置有限且大于 0 的宽、高并保持原始比例；只设置单边尺寸、0、变形或因错误单位导致异常物理尺寸，均为交付失败。
- 两个横向子图：整组优先使用 13.5—14.4 cm 宽度；每个绘图区须至少约 6.5 cm 宽、5.5 cm 高，保证坐标、标签和图例可读。达不到时减少子图或拆为独立图，不得把子图压扁；
- 当前页无法容纳：优先缩小至可读尺寸或调整插入位置；仍无法容纳时，将首次引用段与图表整体移至下一页；
- 单独占页：除用户明确要求外不得使用；用户明确要求时，须在内容规划中说明理由和验收条件。

**图题在图下，表题在表上；两者的间距规则不同。**

- **图题**：按首次出现顺序编号；图下使用居中的 `Caption`，格式为“图 1　<图题>”；显式黑色、小于正文、与图片同页，段后固定为正文 1.5 倍行距（360 twip）；
- **图后说明**：每张图必须紧随“数据来源：”说明，并在必要时补充期间和口径；不得省略或用无来源的泛称替代。该段使用正文行距，段后固定为 360 twip，使其与后续正文自然分隔；
- **表题**：按首次出现顺序编号，格式为“表 1　<表题>”；必须固定置于表格上方，并与表格首行同页；不得置于表格下方、跨页或与表格分离。

**图例、标签和刻度必须完整可读。**

- 图例默认置于绘图区外；
- 系列不超过 3 个且名称简短时，优先直接标注线末端、柱组或基准线；
- **务必检查**：图例、数据标签与刻度不得遮挡、碰撞或截断；空间不足时，必须仅保留关键数据标签、调整标签位置或改用图例/表格，不得强行显示全部数据标签。

### 图表自解释与颜色语义

**每个图表单元（图片、图题及紧邻的来源/口径说明）必须脱离正文独立理解。**

交付前仅查看该图表单元时，必须能知道比较对象、期间、单位、统计口径、数据来源、基准线和颜色含义；不能则不得交付。

- 单一数值系列默认使用一种主色；不得为装饰把同一系列随意分成多种颜色；
- 只有颜色代表明确业务判断时，才可使用强调色，例如低于目标、异常或风险项；
- 默认只使用“主色 + 一种强调色”。确需表达高于、接近、低于基准等三档状态时，必须在绘图区外给出简短颜色说明，或直接在对应数据旁标注判断；
- 基准线、目标线和阈值线必须标注数值及含义；支撑正文判断的峰值、拐点、异常值或最大差距必须直接标出关键数值或简短注释；
- 多系列图的图例必须位于绘图区外，且不得遮挡柱、线、标签、坐标轴或数据点；
- 图内不得重复放与图下图题完全相同的标题。以“图 + 图题 + 紧邻口径/来源说明”构成完整图表单元。

### 何时使用图表及如何选择

**有足够数据支撑关键判断时，必须作图；不得全文只堆表格。**

满足以下任一情形时，至少使用一张图表：

- 同一指标有 5 个及以上连续时点，需要判断趋势或拐点；
- 有 3 个及以上可比对象，需要比较、排序或判断差距；
- 有共同分母的 3 个及以上构成项，需要判断份额或结构；
- 起点、终点及中间增减项可严格加总，需要拆解变化来源；
- 样本足够，需要判断关系、异常点或顺序转化。

**例外**：数据不足、用户只需精确查阅，或任务本质是定性材料分析时，不强制作图。

- **时间变化**：优先折线图；
- **类别、对象、方案或地区比较**：优先排序条形图；
- **构成比较**：优先堆叠条形图；仅有 2—5 个类别、份额差异清晰且确有“部分占整体”判断价值时使用饼图或圆环图。类别更多、小份额过多或标签可能碰撞时，改用排序条形图；
- **变化拆解**：只有起点、终点及中间项可严格加总时才用瀑布图；
- **精确字段查阅、多字段对照**：优先表格。

趋势点过少、散点样本过少或数据不足以支持图形时，改用表格或正文；不得为显得专业而强制作图。

每张图表必须有图题、单位、期间、必要口径和以“数据来源：”开头的来源说明；图后紧跟一段解释，说明图中发现、对判断的意义和限制。图表不能成为唯一证据。

### 配色与视觉规则

**图表内不写图号、图题、来源或长段结论。**

生成白底 PNG 图表后，按本页图下注释规则插入 Word。可使用柱形、条形、折线、饼图、圆环、散点、雷达、组合、面积、气泡、瀑布、帕累托和漏斗图。

**使用统一、克制的分析报告配色。**

- 主色与层级：藏青 `#1A2B4A`、中藏青 `#52647D`、浅藏青 `#8D9AAB`、极浅藏青 `#C9D0D9`；同一图默认只使用该色阶与中性灰。
- 同一指标或同一数据序列必须使用同一种颜色，不得按类别任意使用多色；只有颜色明确对应互斥的数据分组或业务状态，并在图例或标签中说明时，才可使用多色。
- 中性色：正文 `#252525`、辅助文字 `#767676`、网格线 `#D8D8D8`、浅底 `#F4F4F4`。
- 单点强调：琥珀 `#C8861A` 或暖赤 `#B84C3A` 二选一，只标记关键差距、风险或异常，不能用于装饰或同时大面积使用。
- 禁止 Word 默认主题配色、彩虹色、渐变、3D、投影、彩色背景、粗黑边框和默认图例框；图表标题、坐标、图例和数据标签使用黑色或深灰，不得使用默认蓝色 Heading 样式。
- 不得只依靠颜色区分系列；结合排序、直接标签、线型、空心/实心填充或数据标签。
- Python 图表导出白底 PNG，分辨率不低于 200 dpi，插入后不超过 A4 正文版心宽度。图表使用统一中文无衬线字体并实际检查中文、数字、负号、单位、刻度和图例无乱码或截断；保留极淡横向网格线，一般不保留纵向网格线。

### 附录只保留复核所需信息

**附录不是按源数据文件名重复堆放明细。**

- 使用自定义指标、计算、分母或口径时，附录优先给出“统计指标与口径说明”，说明指标定义、计算方式、期间、单位和必要限制；
- 使用多份附件、多个工作表或外部资料时，附录列出“资料来源”，说明资料名称、位置、期间及在报告中的用途；
- 只有读者需要逐项复核、审计留档或正文确实引用了完整明细时，才附相关数据表；不得把整份源表或按月份/产品机械拆分的明细表作为默认附录；
- 附录内容必须服务核验正文结论，不得替代正文分析或重复正文主证据。


## 格式规划：一般格式、目录与分页

- **格式优先级**：前述“Word 格式”中的条款结构、签署区、目录、封面、标题颜色和页眉规则，是本文件对一般格式要求的明确覆盖，应优先执行。用户明确要求、有效模板、组织规范或法定文种要求与本文件或一般格式要求冲突时，按[`writing-taxonomy.md`](writing-taxonomy.md) 中的“格式规则优先级”处理。

- 一般格式要求：除上述明确规定的项目外，必须完整读取[`writing-taxonomy.md`](writing-taxonomy.md) 中“## 一般Word排版格式要求”及“## 交付前回读与校验”；除本指南明确覆盖的项目外，按其中规则执行。


## 交付检查：交付前逐项检查

- **样式与目录**：Title、Heading 1–3 是否为真正 Word 样式且显式纯黑；除用户明确要求的模板既有样式外，不得保留默认蓝色标题、默认 Title 标题线或主题色。主正文可见文字超过 5,000 字时，必须生成可刷新的 Word 原生 TOC；目录读取真实 Heading 1–3，不得手工伪造。有封面时，封面、目录和正文分别起页。
- **图表与表格**：是否与内容规划中的判断、数据、位置和图后解释一致；相邻图表/表格是否承担不同阅读任务，是否重复呈现同一数据和结论。逐图检查图例、数据标签、坐标轴、单位、期间、口径、以“数据来源：”开头的来源说明、颜色和基准线含义完整可读；图片宽高是否均为有效正数且保持原始比例、显示尺寸是否在常规单图建议范围内；无图例遮挡、标签碰撞/截断、跨页拆散、变形或与正文数字不一致；横向子图是否未被压扁。逐表检查是否与正文版心同宽、第一列左对齐、其余数据列居中且单元格无额外缩进，表题是否按“表 1　<表题>”连续编号、固定置于表格上方且与表格首行同页；用户明确要求其他图题或表题样式时，是否按其要求执行。
- **摘要与阅读单元**：每项摘要结论是否包含判断、量化依据、关键限制和行动含义，且能回查正文证据、计算或明确假设。逐页检查图表是否紧邻首次引用、图题和图后解读；是否存在单图占页、前页大面积留白、图题/解读拆页、可合并而未合并的相关单图，或图例遮挡绘图区。
- **内容与来源**：每条关键结论是否可回查依据；是否存在影响关键判断的未解决读取缺口；是否把假设、缺口或不可比数据误写成事实；是否遗漏会改变判断的材料、口径、异常或限制。正文是否存在影响阅读的冗长来源括注；详细来源定位是否已移至脚注、尾注或附录。
- **附录**：是否优先提供指标口径说明和按需资料来源；是否只保留支持复核的明细，而非按数据文件名机械重复原始表。
- **执行校验**：基础校验应确保主正文超过 5,000 字时生成目录，每张插入图均有图题、来源说明和合格布局；每张插入图必须紧随 Caption，且图号连续、图题在图下、居中、黑色、小于正文、段后 360 twip；图题后必须紧随以“数据来源：”开头的来源/期间/口径说明段，且段后亦为 360 twip。必须执行结构化回读、基础校验、专项审计和逐页视觉检查；任一未通过不得交付。
- 交付前先检查本指南规定的专项内容与样式要求，再按 [`writing-taxonomy.md`](writing-taxonomy.md) 中“## 交付前回读与校验”完成通用检查。
