# 在线文档写作与体裁选择

## 围绕读者的问题组织材料

动笔前，先想清楚谁会读这篇文档、读完要能做什么。给新同事介绍一套系统，可以沿着一次实际操作解释各部分怎样配合。如果负责人需要在两套系统之间做选择，就按同一组维度比较差异，说明判断依据和适用条件。

组织材料时，为全文选一条能回答核心问题的主线。介绍对象可以从组成写到运行机制，梳理事件可以抓住改变局面的几个节点，涉及多份材料则把回答同一问题的内容放在一起。在作出判断的地方给出依据和适用条件，让读者分得清哪些是已知事实，哪些是解释或推断，哪些仍待核实。材料相互矛盾时，先核对日期、版本、范围和统计口径，再写清分歧所在。

篇幅服从用户要求和阅读用途。把影响理解、判断或行动的细节写足，将方便查找的明细放进列表或表格，删去重复结论以及与核心问题无关的背景。用户指定了模板或写法时优先采用。

## 按成稿用途选择体裁

同样是产品上市，供团队讨论预算与渠道安排的方案可参考营销策划，发给客户的上市通知可参考媒体传播。涉及多个用途时，按主要用途安排全文，只在相应段落借用其他体裁的写法。各指南列举的是常见场景，细分题材也可沿用所属体裁的原则。

| 读者要完成的事 | 常见内容 | 体裁指南 |
| --- | --- | --- |
| 根据证据比较选项、作出判断 | 咨询、经营分析、行业研究、战略、市场机会、消费评测、投资分析 | [分析报告与决策支持](genres/strategy-and-analysis.md) |
| 了解工作进展、确认安排并推进执行 | 工作总结、计划、汇报、会议纪要、项目推进、流程与 SOP | [组织协作与执行文档](genres/organization-collaboration.md) |
| 确认产品需求、技术实现或验收条件 | PRD、技术方案、架构设计、测试记录、故障复盘 | [产品 PRD 与技术协作](genres/product-and-engineering-document.md) |
| 决定营销策略与资源安排 | 品牌、上市、内容种草、活动、增长、渠道与整合营销 | [营销策划方案](genres/marketing-plan.md) |
| 接收消息、理解产品或参与活动 | 公众号、小红书、邮件、品牌与广告文案、产品推荐、现场发言 | [媒体传播与转化表达](genres/media-and-communication.md) |
| 按条件和顺序完成一件事 | 生活教程、旅行、健身、菜谱与个人规划 | [实用指南与规划](genres/practical-guides-and-planning.md) |
| 阅读故事，或据稿表演、拍摄和剪辑 | 小说、故事、人物与世界观设定、剧本、短视频脚本与分镜 | [创意写作与视听脚本](genres/creative-writing.md) |
| 理解一个观点及其论据 | 新闻与热点、公共议题、文化现象、作品评论 | [观点与文化评论](genres/opinion-and-culture.md) |

## 选择文字、表格和图解

用原生标题和段落展开解释，用列表列出并列事项或操作步骤，需要逐项比较、查询或修改明细时用原生表格。若读者需要同时看清多项关系、位置或变化，再选择能显示这些信息的图解。图的数量由内容决定。

| 写作场景 | 图解可以讲清什么 | 正文或表格保留什么 |
| --- | --- | --- |
| 解释概念与分类 | 分类树显示分类依据和包含关系，对比图或关系图显示概念间的区别与交叉 | 准确定义、适用条件、例子和来源 |
| 介绍对象与运行机制 | 结构图或分层图显示各部分如何连接，机制图说明信息怎样传递、各部分怎样共同起作用 | 部件属性、运行条件、具体说明和证据 |
| 梳理事件、人物经历或阶段变化 | 时间轴标出关键节点和转折。有证据支持时再标明因果关系 | 日期、事件细节、出处和必要背景 |
| 说明地点、设施或路线 | 优先沿用真实地图或原图，用布局图或空间示意图标明区域边界、入口、相对位置和路径 | 名称、已知距离与尺寸、使用条件和原始依据 |
| 整合多份材料 | 证据关系图或时间对照图展示哪些材料支持同一说法，哪些因时间、范围或口径差异而得出不同结论 | 原文、出处、版本、逐项比较和仍待核实的分歧 |
| 汇总数量、变化与构成 | 条形图比较高低，折线图显示趋势，堆叠图显示构成，分布图显示数值的集中位置 | 精确数值、比较基准、统计口径、数据来源、计算方法和限制 |

图中的层级、连线、比例和坐标都应有材料依据。只有相对位置时，可以画出入口与各区域的方位并注明“未按比例绘制”。图中就近标出读者要看见的关系或变化，把详细解释留在正文。

排版按创建工作流第 3 步确定。正式版式保留体裁所需的结构，省去高亮块、emoji 和装饰性组件。用户和体裁均未指定版式时，按内容需要组合原生组件、图片或画板。需要定制布局、标注或交互时，按 HTML block 指导制作，沿用全文的配色和组件样式。见[创建工作流](lark-doc-create-workflow.md)和[HTML block 指导](lark-doc-html-block.md)。
