# HTML block 视觉与文字指导

沿用规划中确定的信息任务、图型、数据口径、正文位置和全文视觉方向；不要在制作时重新选择主题或扩充内容。每个 block 是文档中的解释单元，不添加整站导航、封面、页脚或无用按钮。

## HTML色板：先确定，再统一复用

整篇 HTML 沿用已确定的主色系，必要时只加一种反差色，禁止彩虹色。
在草稿中按颜色角色建立一组命名色值，覆盖背景、正文、辅助文字、边线、主色和可选反差色。这组色值对应不同用途，不代表要使用多种鲜艳色相。所有HTML共用这组值，配色计划不写进成稿。

| 颜色角色  | 使用指导                                                               |
| ----- | ------------------------------------------------------------------ |
| 背景与分组 | 背景用白色`#FFFFFF`。分组使用极浅的主色底或浅灰底，搭配细边线，避免大面积深色卡片。                     |
| 正文与说明 | 正文、节点主信息用深灰`#1F2329`，说明和注释用`#646A73`。浅色块上用深色字，不能把关键标签和假设变成难读的淡灰小字。 |
| 边线与网格 | 用`#DEE3E8`或更淡的细线。边线负责分组与定位，不与数据抢眼；普通节点不使用粗深色描边。                    |
| 主色与数据 | 按题材选清亮、不过艳的主色。柱条使用纯色，节点多用浅底；非重点数据可用浅灰并配深色标签，避免厚重灰条加白字。             |
| 唯一反差色 | 与主色在色相上可区分，彩度和面积保持克制。只突出最关键的差异或断点，没有需要就不用。                         |

- **同一色系派生深浅。** 需要浅底、深色文字或连续色阶时，沿用已确定主色的深浅与鲜淡变化，并统一复用，不临时发明新的颜色。
- **图表继承整篇颜色。** 图表沿用全文色板，不自动为每个类别分配一种颜色。普通比较用同一主色或主色加灰色，同一对象跨图颜色一致。
- **颜色变化表达信息。** 连续色阶用于有序数值的高低变化；卡片、柱条和时间条默认使用纯色，不给每根条形添加装饰性渐变。
- **强烈强调集中使用。** 主色和反差色不同时大面积高饱和出现。清爽不等于把整张图调灰、把文字调淡；专业也不等于大面积深色。

## 文字层级与布局

字体选少量但与主题匹配，层级靠字号、字重、行长和语义断行建立，不靠堆字体数量。

HTML与宿主正文协调：图题、节点主信息、说明和注释保持稳定层级；主体与关键关系文字至少16px，辅助文字至少14px。

按文档实际容器组织宽度并自然撑高，不通过缩小文字硬塞内容。留白服务于分组、呼吸和强调，不用于填充版面；避免单侧堆积、大面积空白和反复使用同一种卡片构图。

## HTML block中的文字也是信息设计

图中文字应帮助读者识别对象、看懂关系和作出判断。逐个确定图题、节点、连线、数字标签与注释各自要回答什么；一个文字元素只承担一项清楚的任务，不用抽象口号填满图形。图解说明用平实语言；用户需要的品牌标语、广告文案仍作为方案材料保留，不把两者混成一种语气。

| 文字位置 | 应该写什么 |
| --- | --- |
| 图题 | 点明这张图要看懂的主张、区别或关系，优先写有依据的具体判断；尚无结论时写清问题或比较对象，不只写“机制总览”“核心引擎”“全链路赋能”。 |
| 节点或分组 | 用读者熟悉的具体对象名称，动作节点用“动词＋对象”，判断节点写条件。不能只有“赋能、沉淀、闭环”等抽象词；需要时加一条关键说明，不把全部执行细节塞进去。 |
| 箭头或连接 | 写清传递什么、谁影响谁、什么条件下走这条路。明确单纯先后的连线可以不加字，其他关系不能依靠读者自行猜测。 |
| 数字与数据标签 | 数值与指标名、单位、时间口径相连；比较图直接标关键差值或占比。假设、目标、实际值就近区分，不能只在图下长注释中补充。 |
| 注释 | 只补图中尚未表达的依据、适用条件和限制，放在对应信息附近；不再逐项复述图中所有对象与数字。 |

同一对象、动作和指标在正文、原生表、所有图中保持同名同口径，不为避免重复换近义词。优先主动语态，直接写谁做什么、交出什么；主语已由泳道或分组明确时可省略。短句也必须保留关键条件和关系，不能把完整逻辑压成一串名词。

## 交互控件与动态反馈

- **主图俯瞰，hover／click查看局部细节。** 核心结论、关键阶段和方案差异默认完整可见。主动判断轻量交互能否帮助阅读：悬停或点击查看补充数值、说明或局部小图，指向节点时突出关联路径，点击固定选中或展开次要说明，避免主图信息过载。

- **入口告诉读者怎样操作。** 在图或控件附近简短说明，例如“悬停查看具体数值”“点击节点查看关联内容”。说明必须与实际行为一致，不让读者猜哪里可以操作。

- **控件名称准确说明点下去会发生什么。** 按用户能用简单语言理解的说法命名，例如“展开补充说明”“按渠道筛选”“重新计算预算”，不使用含糊的“提交”。一个动作在整条流程中保持同一个名字，操作反馈沿用同一名称。

- **动效帮助读者看清变化。** 回应用户动作的动效（打开、展开、确认）是受欢迎的，只要它让人看清什么变了。非用户触发的动效要克制，不给每个区块统一添加淡入上滑，也不让每张卡片都悬浮或弹跳。

- **复杂交互按实际需要采用。** 筛选、参数试算、条件演练等操作有明确反馈，关键内容不依赖操作才能看见；局部编辑不能宣称已经保存回云文档。
