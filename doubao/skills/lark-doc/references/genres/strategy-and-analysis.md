# 分析报告与决策支持

**使用方法**：1. 确认适用范围 → 2. 明确核心问题，读取和分析材料并按指南规划组织呈现内容 → 3. 选择合适的可视化元素及排版方式 → 4. 生成并检查后交付

## 适用范围与路由自检

**命中：基于材料形成发现、判断或建议。**
- 适用于经营、销售、成本等数据分析，以及项目、产品、市场、行业、竞品、商业机会和战略分析

**不命中：只整理材料，不形成判断。**
- 仅转写、提取、排版、摘要或原样整理材料；
- 数据只用于支撑既定的工作总结、请示、发言稿、合同等其他题材。


## 第一部分 必须遵循的总原则：核心问题、证据与判断

分析报告和调研报告应围绕核心问题，用可靠证据形成清晰、有用的判断。本部分只规定核心原则，不穷举具体方法。

### 核心逻辑和语言表达（非常重要）
1. **分析逻辑**：从核心问题出发，对相关证据进行分析和验证，在证据支持的范围内形成主要发现或判断。
2. **呈现逻辑（全文最重要需要遵循的原则！！！）**：以主要发现或判断为主线，根据信息对读者判断的重要程度进行取舍和排序，形成与报告目标相匹配的分析结果。整体呈现逻辑可以参考总-分-总逻辑。
  - **摘要**：先呈现“报告摘要/执行摘要”，独立呈现核心发现、结论及其意义。
  - **研究背景、方法、范围等说明**：按需提供分析背景和方法，不得超过正文10%篇幅。
  - **核心分析章节和段落采用结论先行、逐层支撑的金字塔逻辑**：
    - 上层概括下层，下层以分论点和证据支撑上层；同层内容应采用一致的演绎或推理逻辑相互区分、共同完整，并按最有助于读者理解和判断的顺序排列。
    - 建议对“分析性段落”采用：“段首关键结论 → 关键数据 → 原因解释 → 简短启示（可选）”的结构
    - 分析性段落的标题要有结论性提示，不采用“趋势总览”类似的抽象标题。
    - 对超过5000字的长文报告，可在每个分析性一级标题后添加一个简洁精炼的段落，总结该章节的主要发现或判断，整体篇幅不可超过该章节的10%。
  - **报告结尾**：总结分析结果，强调核心发现、建议和限制（如果有）。
3. **呈现逻辑自检**：**完整回读文档，检查是否只需要读`callout`、摘要、标题、每段第一句话、可视化元素，就可以知道全文的核心判断和依据，要有具体的事实判断而不是抽象结论**。
4. **语言风格和写作逻辑禁止项**：
  - 结论重复，信息增量不足：不同章节反复出现同一个结论，没有新的信息增量。
  - 语言风格偶有口语化：全文要保持一致的语言风格，避免使用口语化语言，除非用户明确要求。
  - 分析性段落的段首句禁止使用“更关键的是留存数据。”等没有实质内容的短句。首句应当让读者明确本段要传达的核心信息，并与本段后文形成可验证、可展开的关系。
  - 禁止在缺少相应的证据边界的时候使用“最根本原因”“唯一出路”等强结论语句，如必须使用，则应将绝对判断改为带条件的判断
5. **开头给出结论`callout`**: 
  - 首先要说明文章回答的核心问题，再清晰地分点说明核心发现、结论以及行动建议。
  - 核心发现、结论以及行动建议需要分点用**列表形式**写，每个点内部禁止超过3个小点
  - 不可直接并列排列给出没有内在逻辑的多个点
  - 推荐使用“简短5～8字要点：具体内容”的方式写。整体不得超过300字。

### 核心行动方法
**STEP1：明确核心问题以及预估回答核心问题需要的信息，划定分析范围**
**STEP2: 收集与整理结论依据**
  - **用户提供附件/query信息利用**：是最重要的信息来源之一，需按 [`创建工作流`](../lark-doc-create-workflow.md) 中“收集素材”和“多材料整合”的要求完整执行。
  - **用户提供的链接**：也是最重要的信息来源，需围绕核心问题完整读取内容；可视化的图片、图表等适合利用的信息应尽可能，如有需要可以插入交付报告中。
  - **联网搜索**：如果用户没有明确分析来源，一般默认搜索补充报告资料。优先采用政府、监管机构、官方统计、行业协会、上市公司公告/财报、企业官网和原始研究等权威或第一手来源。
**STEP3: 准确计算数据**
  - 关键数字必须可追溯到原始材料；比较对象必须同口径；缺失、不适用或无法计算的数据必须明示，正文不得出现 `NaN`，不得默认补全或用语言推理替代计算。
**STEP4: 抽出结论主线**
  - 从材料中先提炼最能回答核心问题的 1 条主判断，以及支撑它的 2—4 个关键分判断；正文围绕主线组织，不按材料或指标顺序展开。
**STEP5: 围绕核心判断组织呈现**
  - **核心判断统领全文**：完成分析后，先提炼读者最需要知道的发现或判断，再围绕它组织正文，使各部分共同回答核心问题。按照前文规定的“呈现逻辑”组织内容。
**STEP6: 完整规划摘要内容**
  - **摘要要求**：
    - 摘要必须直接回答核心问题而不是铺垫背景，覆盖核心判断、2—3 个最重要发现、主要建议和关键限制
    - 摘要默认不设二级小标题，不使用项目符号、编号列表或表格，使用 2—4 个自然段完成
    - 摘要必须控制在一页以内，中文摘要建议 500—800 字，最多不超过 900 字
**STEP7:润色标题**
  - 标题要尽可能给出判断，而不是用抽象的标题。例如“用户反馈：挫败感限制进一步使用” 比抽象的 “用户反馈”更好。
**篇幅要求：报告篇幅应由核心问题、证据复杂度和读者决策需要决定，逻辑完整优先于篇幅长度。**
  - **核心原则：**：以用户要求为准、以说明问题为限、根据任务适度增加深度
  - **未指定篇幅时，默认按交付用途控制正文规模**：快速分析/简报 1,500—2,000 字；标准分析报告 2,000—3,500 字；明确要求“深度调研/深度分析”时 3,500—5,000 字。
    - 核心内容灵活使用可视化元素展示，提高可读性
    - 如果使用了复杂元素展示文字逻辑，则可以缩短正文文字的篇幅，提高可读性。（具体使用方法见本指南“第三部分 可视化元素与排版”）
    - 超过 6,000 字必须由材料复杂度、核心问题数量或正式交付场景支撑，并在思考过程中写明原因。
    - 字数口径默认指正文含摘要，不含可视化元素中的文字信息，不含封面、目录、尾注、参考文献和附录。
  - **禁止**：为了写长报告而不考虑逻辑以及可读性堆砌内容。

### **禁止项**
- 禁止每个`seq`小标题底下只有不到200字的一小段话；如果是这种形式，建议采用表格。


### 不同类型报告的分析落点参考
 应优先已用户明确的具体目标为核心分析落点，在用户未明确时，可参考一下思路：
| 报告目的 | 内容重点            | 最终落点        |
| ---- | --------------- | ----------- |
| 描述现状 | 说明当前情况及值得关注的变化  | 帮助读者形成清晰认识  |
| 诊断问题 | 找出主要问题，并分析其形成原因 | 明确问题及改进方向   |
| 探索情况 | 提炼初步发现，并比较可能的解释 | 提出值得继续验证的问题 |
| 评估效果 | 根据既定目标判断实际表现    | 形成有依据的评估结论  |
| 支持决策 | 比较不同选择及其影响      | 给出推荐意见和适用条件 |
| 预测趋势 | 根据现有证据判断未来变化    | 形成有条件的趋势判断  |


## 第二部分 分场景规则 

**说明**：一份报告可以同时使用数据和调研资料。应先判断主要结论依靠哪类证据形成，再选择相应的分析方式。以下内容只说明不同场景需要特别处理的部分，其他要求统一遵循总原则。

### 一、以数据为主要依据的报告

适用于主要通过可计算、可比较的数据形成结论的任务。
- **分析重点**：从数据中寻找最能回答核心问题的变化、差异或联系，并判断这些发现是否足以影响读者的认识或选择。不要停留在逐项报数和描述数字。
- **内容组织**：围绕主要数据发现展开正文，而不是按照数据表、字段或指标的原始顺序介绍。计算过程和完整明细只在帮助理解或复核时展开。
- **可视化重点**：图表用于直接呈现关键的数据关系，表格用于准确查数，完整明细放入附录。只有图形比文字或表格更容易说明问题时才作图，不以图表数量体现分析深度。

### 二、以调研资料为主要依据的报告

适用于主要通过资料检索、案例研究、访谈或其他调研方式形成结论的任务。
- **研究重点**：围绕核心问题确定需要了解什么，并持续补充和核对资料，直到重要判断获得足够支持。无需追求搜集所有相关信息。
- **内容组织**：按照报告需要回答的问题综合不同资料，而不是逐一介绍每个来源。
- **来源说明**：引用外部资料中的重要事实、数据、观点或原文时，应在相关内容首次出现处插入自动编号尾注。
- **公开资料引用说明**：
  - **正文引用**：在正文中使用手动数字编号"[1]"、"[2]"方式标注，必须直接在正文中插入超链接（仅支持跳转，不能将url显示在正文），完整写作后需回读编号顺序检查是否对应
  - **对应尾注标注方式**：对应正文编号，在尾注中标注“作者或机构：《资料标题》（加超链接），发布方，发布日期，页码或章节（如有）”。
- **可视化重点**：
  - 图表呈现：有可靠且可比的数据时，可以使用统计图表
  - 逻辑关系呈现：当内容涉及多个主体、环节或因素，且其层级、分工、流程或作用关系是理解重点时，**强烈建议**使用时间线、结构图、流程图或机制图呈现。图中节点和连线应含义明确、具有事实依据；正文仍需提炼关键关系与结论，不能用图形替代分析。如需使用任何背景色，要与图表背景色保持一致主题色系，建议避免使用深色背景色。
- **内容对标参考**：
  - 综合性商业与管理研究：麦肯锡全球研究院（MGI）、BCG Henderson Institute、PwC Research / Global Surveys、Deloitte Insights、EY、KPMG专题研究、IBM Institute for Business Value等专业机构的报告
  - 宏观、产业与政策研究：世界银行《世界发展报告》、OECD各类Outlook和专题报告、IMF 旗舰报告等
  - 市场、消费者与社会调研：Pew Research Center、Gallup、Ipsos、NielsenIQ、Kantar等专业机构的报告
  - 审计、运营诊断与问题整改：上市公司内部控制审计及风险管理报告、美国政府问责局（GAO）、英国国家审计署（NAO）等专业机构的报告
  - 中文商业与产业报告：除综合性商业与管理研究外，可补充中国信息通信研究院白皮书、中国互联网信息中心（CNNIC）统计报告、艾瑞咨询、易观分析等商业研究报告作为参考


## 第三部分 可视化元素与排版

**使用说明**：本部分规定分析报告与决策支持场景的可视化选择和颜色系统。完成选择后，按 [`创建工作流`](../lark-doc-create-workflow.md) 提交 Presentation Decision 并初始化草稿。

### 一、排版设计系统（必须遵循） 

| 全文位置/场景 | 必须使用的可视化元素 | 内容要求|
| --- | --- | --- |
| 全文开头 | `callout` | 全文仅在开头使用一个`callout`，其他位置禁止使用`callout`。用于一句话说明本文回答的核心问题、核心发现、核心结论和行动建议。 |
| 可视化摘要“一图看懂” | `html5-block` | 摘要必须是全文的摘要，而不是第一章的摘要。摘要前**不需要设置一级标题序号，一级标题直接设置为“一图看懂”，内容全部用图展示无需文字**，摘要内容**必须直接回答核心问题，覆盖核心判断、2—3 个最重要发现、主要建议和关键限制**。禁止只将正文中某一节的核心内容放到摘要。后续内容的一级标题序号从“1.”开始设置自动编号`seq` |
| 每个一级标题下 | `table`、`img`、`html5-block`、`column`等 | 每个一级标题下，必须最少有一个可视化元素 |
| 每个一级标题下，超过3个二级标题时，要有总览元素 | `html5-block` | 一级标题后，第一个二级标签前，使用`html5-block`简洁展示该章节的内容地图及主要发现和结论 |
| 二级标题下并列、对比、罗列的内容 | `table`、`html5-block` | 二级标题下，如果内容是用于对比不同对象、不同口径、不同状态、不同时间等 |
| 报告中市场规模等总览行数据 | `html5-block` | 报告中展示市场规模、用户数量、交易量等总览行数据，必须用`html5-block`展示，禁止只用文字或用`table`展示 |
| 行业调研、公司调研、产品调研等 | `table` + `img` | 在行业、公司对比部分，需要用`table`中插入公司名称和关键有信息量的高质量搜图结果`img`，图片结果一般需要来自公司官网或高质量，然后将对应的特征用文字在`table`对比 |
| 正文结尾、参考来源前，必须以可视化元素结尾 | `html5-block` | 展示结论和行动建议，抓住读者注意力 |
| 连续视觉元素禁止项 | `table`、`html5-block` | 连续使用`table`和`html5-block`，中间最少需要有一个段落的文字过渡 |
| 参考来源 | "[1]"、"[2]"等连续编号 + “作者或机构：《资料标题》，发布方，页码或章节（如有）” （插入`<a href="url">` 超链接） + 获取日期 |  正文结束后需单独添加“参考来源”，按照正文的编号顺序给出所有参考信息，同样用 `<a href="url">` 链接到原始出处，强化专业可信度。|
| 正文文中引用 |"[1]"、"[2]"等连续编号 + `<a href="url">` | 超链接指向原始报告或数据页，禁止直接在正文露出url文字。
| 开头摘要、全文结尾 |`html5-block`| 必须各有一个侧重点不同的block，开头是摘要，结尾是结论和行动建议 |
| 中间每个一级标题内容最少有一个block |`html5-block`| 每个一级标题下，必须最少有一个html5-block，展示该章节的分析内容或核心判断 |

### 二、可视化内容要求及禁止项
- **逻辑理解与可视化呈现**:所有可视化必须在完整把握全文逻辑的基础上，选择合适的表达方式，不可为了可视化而可视化使用。
- **每个block必须回答一个独立问题**：每个图、表等block必须服务一个明确判断；不得为了显得完整而堆图、堆表。**每个block必须回答一个明确且不重复的问题。可视化内容表达的是复杂的文字元素时，正文不重复对可视化元素的详细解释，只用一两句话介绍核心背景或结论。**
- **同一判断只选择一种正文主证据形式**：禁止重复用图和表重复呈现同一信息。
- **可视化block前后必须形成连续阅读单元**：一般图表、图片前后需要有标题、来源说明，如果`table`、`html5-block`、`img`等已经呈现完整信息，则只正文一句话介绍即可，无需重复block内容。
- **确保可视化block能够独立理解**：可视化block应说明比较对象、分析范围、计量方式和数据来源，使读者脱离正文也能理解其基本含义；通过必要的标注或基准，帮助读者直接看到支撑正文判断的关键信息，避免让读者自行寻找重点。
- **每个一级标题下最少要使用一个可视化元素**
- **可视化元素本身可以多次使用，但是禁止出现内容完全一致的可视化元素，例如两个`html5-block`内容完全相同**
- 连续纯正文内容建议不超过500字，中间需要合理使用block减轻阅读压力，帮助快速提炼信息。
- 本体裁禁止使用`whiteboard`元素。

### 三、场景级block选型参考

**说明**：具体执行顺序见 [`创建工作流`](../lark-doc-create-workflow.md)。以下为本类写作体裁的具体信息任务建议：
- 除非用户明确禁止，此类写作鼓励使用block来呈现信息，前提是在逻辑上符合全文逻辑，不为了可视化而可视化使用。每个block必须回答一个明确且不重复的问题。需要在充分理解“适用的信息任务”以及“使用边界”的基础上，选择合适的表达方式，并填入对应的`visual_plan`中 。

### 四、视觉系统与颜色角色

阅读型分析文档应克制、清晰、可核验，质感由留白、对齐、单一色相色阶与细线建立，而非装饰。将原生 XML 与视觉资产分成两层：

- **原生 XML 层**：标题、正文、列表、表格和 `callout` 只使用 [`lark-doc-xml.md`](../lark-doc-xml.md) 定义的命名色。`text-color`、`border-color` 只使用基础色相；表格背景只使用基础色相、`light-*` 或 `medium-gray`；callout 背景只使用 `gray`、`light-*` 或适用的 `medium-*`。不写十六进制颜色，也不使用未定义的 `black`、`white` 或边框样式。

- **视觉资产层**：HTML5 内部 CSS和静态图可使用精确十六进制色值。优先使用用户提供的品牌 VI；没有品牌规范时，只选择下表一套资产色板，**禁止多套资产色混用。**

| 色板 | 主色 | 辅助层级 | 原生 XML 映射 | 适用场景 |
| --- | --- | --- | --- | --- |
| 藏青 | `#1A2B4A` | `#758092` / `#BABFC9` / `#DDE0E4` | `blue` / `light-blue` / `gray` | 战略报告、投资与决策 |
| 墨绿 | `#1C3D2E` | `#778B82` / `#BBC5C0` / `#DDE2E0` | `green` / `light-green` / `gray` | 行业研究、可持续主题 |
| 炭黑 | `#252525` | `#7C7C7C` / `#BFBFBF` / `#DEDEDE` | `gray` / `light-gray` / `medium-gray` | 纯数据驱动、极简中性主题 |


- **主题色下的颜色变化**：先选定整篇主色，再将颜色按下列角色分配；不得按图表或章节任意换色。

| 颜色角色 | 原生 `table` | `html5-block` |
| --- | --- | --- |
| 主信息 / 推荐项 | `medium-gray` 或 `light-blue` / `light-green` 表头；关键短语使用对应基础色 | 使用资产主色表示当前期、重点对象、推荐路径或关键结论 |
| 次要比较 | 默认背景，必要时使用 `light-gray` | 使用资产主色浅层级或灰色 |
| 不确定 / 待验证 | `gray` 文字或 `light-gray` 背景 | 灰色虚线、空心标记或浅灰填充 |
| 风险 / 阈值 / 异常 | `red` / `orange` 文字或 `light-red` / `light-orange` 背景 | 使用同语义的低饱和风险色，并直接标注含义 |


### Presentation Decision

选择本 Profile 时，必须使用 `presentation_mode: "rich"`。`rich` 只在本文件明确允许的表达范围内生效；按证据关系选择 `table`、`html5-block`、`whiteboard` 或 `img`，不设置与内容无关的最低数量。材料只包含定性判断时，不生成数值图表。所有 XML 能力与嵌套边界以 [`lark-doc-xml.md`](../lark-doc-xml.md) 为准。

`visual_plan.reason` 必须包含：`策略与分析｜主色体系｜核心判断；数据来源与口径；表格/图表/html5-block的分工`。`callout` 最多使用一次，只用于开头的核心判断/阅读说明，或结尾的行动建议/待决事项；不连续堆叠，也不用于普通证据说明。

```json
  "reader_task": "比较三种进入策略，确认推荐路径及其证据边界",
  "genre_contract": "strategy-and-analysis",
  "adapter": null,
  "presentation_mode": "rich",
  "visual_plan": {
    "reason": "策略与分析｜藏青主色｜比较三种进入策略；以市场规模与单位经济数据支持判断；表格呈现精确假设，HTML5 图表呈现市场增长与回本敏感性。",
    "blocks": [
      {"type": "html5-block", "min_count": 3, "purpose": "展示市场规模趋势与三种策略的回本敏感性"}
    ]
  }
}
``` 


## 第四部分 交付前检查

- [ ] 已明确读者要回答的决策问题、判断标准和文档的最终建议或下一步。
- [ ] 写完后完整回读文档，检查是否只需要读callout、摘要、标题、每段第一句话、可视化元素，就可以知道全文的核心判断和依据。
- [ ] 每个关键结论均有可追溯证据；事实、推断、假设、预测和建议已清楚区分。
- [ ] 每项外部数据、图表、表格和关键案例均有来源、日期/时间范围、单位、口径和必要边界。
- [ ] 相邻图表/表格是否承担不同阅读任务，是否重复呈现同一数据和结论。如果重复呈现，则需要删除其中一种，仅保留最适合的呈现方式。
- [ ] 有可用定量材料时，已优先采用 `table` 或 `html5-block`；需要同时查值与看模式时，两者分工互补而非重复。
- [ ] 每张表格遵守表前问题、精简行列、清晰表头、数值右对齐、主体名称加粗、有限强调；来源与口径紧贴表格下方、独立居中、灰色显示，读表结论另起段落。
- [ ] 每个 HTML5 图表具有正确选型、真实数据、必要标签/图例/时间范围/单位/来源，且不含默认视觉、伪精确数值或叠印长文字；已实际检查渲染结果：标题、图例、坐标轴、数据标签、来源、标记和连线均完整可见，短条标签未换行、未被裁切，所有标记、阈值线和注释均有明确依据与正确位置。
- [ ] HTML5 图表使用单文件、有效 meta、响应式宽度和适当高度模式，大小不超过 500KB。
- [ ] 全篇仅使用一套资产主色体系；原生标题、正文、表格和 callout 只使用合法命名色，十六进制色值仅出现在 HTML5、SVG 或静态图片内部。强调色仅用于有语义的关键差异、风险或异常。
- [ ] 创建成功后，使用 `docs +fetch --doc "<document_id 或文档 URL>" --detail full` 回读；核对表格、HTML5 图表均实际存在、可读、与相邻结论对应，来源与口径没有遗漏。发现问题时按 update 流程做最小范围修复并再次回读。
