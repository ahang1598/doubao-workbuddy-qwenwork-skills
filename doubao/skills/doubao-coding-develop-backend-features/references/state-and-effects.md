# 状态与副作用

## 持久状态

写清调用方何时可视为提交、提交后可读到什么，以及各失败点允许留下或必须清除的状态。沿用数据所有者现有的事务、约束与冲突方式，不扩大现有保证。通过真实入口验证成功状态，并在可控失败点验证残留与后续读取。

验证边界不得弱于合同边界：跨事务用新事务，重启用新的真实应用实例，跨进程用独立进程；通过生产适配器写入并从同一持久状态读回。同一进程内的新对象、替身或直接调用只能作为补充证据，不能证明更强保证。

若某个副作用必须在主操作失败后保留，或不得改变主操作结果，分别验证主操作失败与副作用自身失败时的可见状态。

## 外部动作、重试和后台工作

写清目标动作、与本地提交或交接的顺序、调用方成功所代表的阶段、已接受的重试与重复语义，以及失败或取消后的状态。

- 沿用现有外部客户端、任务、安全和观测约定；只有合同允许时才重试，超时不能自动证明外部动作未发生。
- 区分后台交接成功与处理完成；不要只因耗时就改变执行模型。
- 用能确定性控制或观察相应边界的验证方式安排合同包含的成功与失败序列，并只检查命中的调用方结果、本地状态、外部记录或后台终态。

## 行为变体

列出现有选择条件、共同约束、本次应变化与必须不变的变体。把改动放在能覆盖目标变体的最局部现有边界；共享改动会触及其他变体时，将其纳入不变量或缩小范围。覆盖所有改变的选择结果，并验证共享改动会触及的未变结果。
