# 缓存合同

只落实已接受方案选中的条目：

- `identity`：哪些输入或主体共享一份内容，如何隔离和规范化；
- `representation`：保存什么，如何识别不可用内容；
- `freshness`：何时可用，由什么时间或事件失效；
- `read`：各读取结果如何向调用方表现；
- `change`：真值变化后何时更新、删除、重算或不动作；
- `failure`：各命中缓存操作失败时的调用方结果与允许残留；
- `coordination`：方案明确要求的共享范围、顺序或调用上界。

不要合并未命中、不可用、内容无效和真值不存在；未明确的负缓存、陈旧读取及过期或并发策略都不是默认能力。

从功能入口找到运行时实际使用的缓存、真值来源和作用域，复用现有身份、转换、时间、错误与观测方式。把变化动作放在合同定义的真值提交位置；只有合同无法被观察时才增加最小测试缝。

对每个选中条目安排能区分错误实现的前置状态，并从功能边界观察返回、真值访问和缓存状态。顺序或协调保证使用可控事件证明；真实 sleep 不能证明新鲜度或并发语义。
