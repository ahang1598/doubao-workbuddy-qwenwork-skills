# 服务端功能开发

完成标准是从实际触发入口得到约定结果，并留下约定的状态或外部副作用。

## 建立可执行合同

1. 改动前记录目标范围的现有状态与 diff；预先存在的修改不得归为本轮成果。若目标行为已存在、基线与任务描述不符或测试数量异常，先确认来源和可信起点，不得据此直接声称完成。
2. 从需求中的公开名称、字段或动作找到真实触发入口，沿调用路径追到业务判断、状态变化、外部动作和调用方结果。
3. 找到语义最接近的已实现路径，确认运行时接入、失败表达和验证方式；权威源存在生成链时修改源而非派生产物。
4. 以本轮明确需求决定目标，未说明的兼容行为沿用当前路径。版本敏感用法以仓库锁定版本、依赖源码或对应官方文档为准。
5. 若明确需求与已发布的安全、兼容或数据契约无法同时满足，不进入默认路径实现：保持现有默认行为，说明冲突及可选的版本化或显式启用方案，先取得用户决定。
6. 写下触发、前置条件、调用方可见结果、失败或相邻路径必须保持的不变量，以及能区分旧行为的最小证明。需求点名多个独立的可观察结果时分别保留证明，不能由一个宽泛 happy path 代替。对最高风险合同写下一个仍可能让宽泛测试通过的错误实现，证明须能区分它。未知项会改变结果或不变量时先确认。

## 识别命中风险

- 本次变化新增、移动或影响信任与权限边界时，复用现有校验和授权，并在首次特权动作前完成；拒绝路径同时证明禁止的副作用未发生。
- 本次变化影响公开输入、输出、错误或持久表示时，检查实际消费者、已有数据和版本兼容；迁移语义未定时先做设计。
- 本次行为经过框架、协议或适配器边界时，从调用方实际入口覆盖边界产生的成功与失败；绕过边界的直接调用不能证明公开行为。

| 本次路径包含 | 读取 |
|---|---|
| 持久写、外部动作、重试、后台任务，或共享改动可能影响多个运行时变体 | [状态与副作用](references/state-and-effects.md) |
| 已接受方案明确采用缓存 | [缓存合同](references/cache-contract.md) |

## 实现并证明

在安全且可行时，修改目标实现前先运行能区分旧行为的最小证明，并确认它因目标行为缺失而失败；不可行时保存可重放的替代证据并说明边界。

1. 把合同映射到现有路径中需要变化的最小完整范围，沿用相邻行为的接入、错误、观测和测试方式。
2. 仅在规则、流程和 I/O 确有独立变化原因时使用仓库已有边界分别承载；不为模式名增加层次，也不复制不同变化轴。
3. 不要仅为测试便利扩大公共 API、构造参数或直接依赖存储内部表示；优先复用已有测试接缝和数据所有者边界，确需扩大时说明调用方影响。
4. 从触发边界设置前置状态，同时断言调用方结果和真实状态或外部记录；mock 调用次数只能补充边界交互，不能单独证明这些结果。
5. 先运行直接覆盖合同的检查，再运行仓库实际提供且受改动影响的格式、静态检查、模块测试、构建或集成调用。

## 验证与交付

按改动范围和风险选择最小但有区分力的验证。优先运行直接覆盖合同的检查，以及仓库已有且受影响的测试、静态检查、构建或集成调用。涉及权限、持久写、外部副作用、并发或恢复路径时，再验证对应的高风险分支；不为无关分支机械补测试。

只报告当前工作区实际执行和观察到的结果。要求的主行为未落地，或直接受影响的验证仍失败时，不得声称完成；无法运行时说明替代证据及未验证范围。

交付时说明调用方能观察到的变化、状态或外部影响、关键改动和实际验证结果；证明弱于明确合同的部分标为未验证，不能按更强保证表述。除非用户要求，不必粘贴完整代码、diff 或逐条罗列所有分支。
