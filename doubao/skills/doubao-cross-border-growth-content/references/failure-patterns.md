# Regression Failure Patterns

Read this when the task resembles a prior correction, budget, mixed-platform, creator-rights, or claim-sensitive case.

## 1. Product Fact Completion

**Bad**

- User says `400 ml, USB-C`; answer adds six blades, two-hour charging, included cable, quick cleaning or frozen-fruit capability.

**Required**

- Use only `400 ml` and `USB-C charging`.
- Put blade count, charging time, included items and cleaning method in `missing`.
- Replace an unsupported demo with a safe specification or scene shot.

## 2. Gross Margin As Break-Even

**Bad**

- User says gross margin is 38%; answer states break-even ACOS is exactly 38%.

**Required**

- Ask whether the 38% is contribution margin after material variable costs.
- If not confirmed, label 38% as a scenario ceiling and list missing costs.

## 3. Conflicting Metrics

**Bad**

- Infer orders from price and revenue, then override a separately reported CVR.

**Required**

- Reconcile clicks, orders, revenue and attribution definitions.
- If the numbers conflict, stop the decision and name the missing field.

## 4. Below-Gate Budget Increase

**Bad**

- State that a channel is below the safety threshold, then increase budget as a “validation” or “small test”.

**Required**

- Any total-budget increase is scaling.
- Maintain, reduce or pause until a mature unit passes a verified profitability gate and safety margin.

## 5. Large Default Learning Budget

**Bad**

- Recommend a large seven-day budget while the account is severely below break-even and no user decision rule supports the amount.

**Required**

- Do not invent the budget.
- Use the user-provided cap/rule, or state the bounded-learning-budget formula and route the amount to ads skill.

## 6. Creative Winner Without Creative Data

**Bad**

- Guess that a fitness, demo or comparison creative has the best CTR/CVR without a creative breakdown.

**Required**

- Label each explanation as a hypothesis.
- Request creative-level spend, impressions, clicks, orders and revenue.
- Design an isolating test without naming a winner.

## 7. TikTok Shop Versus DTC Tracking

**Bad**

- Require a website Pixel and UTM for a TikTok Shop closed-loop sale without confirming the path.

**Required**

- Identify Shop closed-loop, website/DTC, Shop Ads, GMV Max or another path first.
- Require Pixel/UTM only when the chosen path uses them.

## 8. Spark Authorization As One Universal Flow

**Bad**

- State a fixed menu path, code format, duration option or edit permission as universal.

**Required**

- Classify the route and verify official market/account documentation.
- Separate technical authorization from commercial rights, edit rights and music rights.

## 9. Industry Benchmarks As Facts

**Bad**

- Call CTR/CVR “low” using an uncited category average, then make a budget or listing decision from it.

**Required**

- Prefer the merchant’s historical/control data and verified profitability.
- If a benchmark is only contextual, label its source, date, market and non-decision status.

## 10. Output Completeness

**Bad**

- Spend most of the response on diagnostic tables and omit scripts, copy, budgets or the requested action list.

**Required**

- Create `required_deliverables` first.
- Complete every requested item before optional background.
- Compress or split a long answer rather than silently truncating it.
