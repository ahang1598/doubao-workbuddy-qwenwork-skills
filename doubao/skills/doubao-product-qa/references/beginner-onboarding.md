## 目标

让不了解 Playwright、Appium、Xcode、ADB、微信开发者工具或命令行的用户，也能在 Agent 引导下完成测试接入。Agent 负责检测、选择框架、生成配置、运行命令和解释结果；只把必须由人完成的登录、信任、系统权限、设备连接和目标材料选择交给用户。

给出第一条命令前先读取 `platform-compatibility.md` 并检测宿主 OS/Shell。Windows 用户默认只显示 PowerShell 命令；不要让初学者自行把 Bash 命令改写成 PowerShell。Windows/Linux 上的本地 iOS 自动化直接说明平台限制，不引导其安装不存在的 Xcode 工具；立即生成可在 iPhone/iPad 上照着操作的人工方案，远程 Mac 或设备云仅作为可选升级路径。

## 统一引导标准

1. **先检测，后提问**：先读取用户已提供的 URL、目录、安装包和设备状态，再运行 preflight；不要先让用户选择框架或执行一串命令。
2. **不用术语提问**：先说“请提供包含 `project.config.json` 的文件夹”，不要先问“请配置 projectPath”；必须使用术语时立即解释。
3. **一次只推进一个人工步骤**：每步包含目的、用户动作、成功标志和失败时下一步。不要一次发送十条安装命令。
4. **Agent 能做的不要转交用户**：路径搜索、版本检测、依赖检查、配置文件生成、模拟器发现、包信息读取和测试执行由 Agent 完成。
5. **提供推荐默认值**：例如网页先做公开页冒烟，App 先选一个已启动模拟器，小程序初学者优先工程目录模式；只有真实业务约束要求时才让用户选择高级方案。
6. **不假装执行成功，也不在阻塞处结束**：缺少工程、安装包、设备、账号或标准自动化入口时把自动化写成 `阻塞`，同时生成带“【人工操作】”标记的步骤、预期结果和证据要求。
7. **不依赖专有 GUI 能力**：正式路径使用项目文件、标准 CLI 和开源 runner；Computer Use 等只能在用户明确允许后用于探索，不能作为其他 Agent 的必需能力。
8. **每次配置都验证**：用户完成一步后由 Agent 重新检测；不要只凭“我装好了”继续。
9. **截图不替用户做决定**：用户未选择截图策略时，不承诺“每一步截图”，也不采集截图；可以继续非截图检查，并在结构化结果中记录 `screenshotPolicy: unconfirmed` 或 `off`。
10. **结束时给文件路径**：任何实际执行的测试都必须落盘紧凑测试报告和结构化结果，哪怕只有一次点击；没有截图不影响生成报告，回复中给出绝对路径。

建议的单步表达：

```text
现在只需要做 1 件事：用 Finder 选择你的小程序工程文件夹。
成功标志：文件夹里能看到 project.config.json。
把该文件夹拖进对话，或发送它的完整路径；其余检测和配置由我完成。
```

## 先判断用户手里有什么

先将输入归入一种，不让用户理解框架：

| 平台 | 可直接开始的输入 | 只能部分验证的输入 | 自动化阻塞的输入 |
|---|---|---|---|
| 网页 | 公开 URL；或代码目录 + 启动方式 | 需要登录但没有测试账号 | URL 不可达且没有代码/接口 |
| iOS | Xcode 工程、Simulator `.app`、可用真机 + 可安装包 | App Store 名称或 `.ipa` 但没有真机/签名 | Windows/Linux 主机上的 XCUITest；只有名称且无设备云 |
| Android | APK、Android 工程、ADB 在线设备/模拟器 | Play 商店名称但没有可安装目标 | 没有 APK/工程/在线设备 |
| 小程序 | 含 `project.config.json` 的工程；已授权 automator endpoint | 只有体验版/线上名称，可生成清单但不能自动执行 | 没有工程或 endpoint |

用户只说“帮我测试”时，最多先确认：测试目标、会产生的真实副作用、截图策略。其他信息先自动发现。不要在用户没选择截图策略时自行改成“每一步截图”。

## 网页

### 用户只有网址

1. Agent 检查 URL 是否可达，并识别公开页还是登录页。
2. 先检测当前 Agent 是否有可操作浏览器，以及系统或项目是否已有 Playwright 与可用浏览器；已有能力直接复用，不先要求安装。
3. 用户只需一次性冒烟/快速确认时，优先使用能读取 DOM、角色或可访问性语义的浏览器控制能力执行黑盒 UI 旅程，结果记为 `exploratory`；用户需要正式回归、发布验收或 CI 门禁时，使用项目已有测试或 Playwright。
4. 结构化 GUI 执行后使用 HTTP/API、控制台或网络信息交叉验证；只有 HTTP 客户端时只能验证状态码、重定向和静态响应内容，不能把点击、JavaScript 渲染或可见性标为通过。
5. 没有任何可操作浏览器但测试必须点击页面时，说明项目内安装 Playwright/浏览器所需的目录、网络、磁盘和环境影响，再询问是否允许安装；用户拒绝时将自动化标为阻塞或 `partial_validation`，并生成浏览器人工点击方案。
6. 登录页仅在登录是测试目标或必须进入业务页时请求测试账号/用户接管；不要索取生产密码写入文件。
7. 涉及支付、删除、发送消息、上传私人文件或生产写入时，在动作前说明副作用并取得授权。
8. 执行后保存报告，即使范围只有“点击一条新闻进入详情”。

只有 URL 时按能力分级：

| 可用能力 | 能执行什么 | 结论边界 |
|---|---|---|
| Agent 浏览器/Chrome 控制工具 | 打开页面、读取可见内容、点击核心旅程、检查详情页并保留结构化记录 | 适合一次性黑盒探索；不等于已建立可重复回归脚本 |
| 已有 Playwright + 浏览器 | 生成并运行带业务断言的可重复黑盒测试 | 可作为回归基础，但仍只覆盖外部可观察行为 |
| 只有 HTTP 客户端 | 检查 DNS/TLS、状态码、重定向、响应头和静态 HTML 关键字 | 不能验证真实渲染、交互、前端异常和视觉结果 |
| 没有可达网络或可用执行工具 | 输出阻塞证据与人工步骤 | 不得声称页面通过 |

用户最少提供：URL、想验证的流程；若用户不知道流程，Agent 从页面识别一个无破坏性的核心旅程并说明假设。

没有 PRD、原型或验收标准时，测试依据只能是页面可观察行为和通用 Web 质量规则。报告必须把“实际断言”“探索性假设”和“因缺少需求而无法确认的业务预期”分开记录。

### 用户提供代码目录

Agent 先运行 Web 工程识别脚本，自动判断包管理器、启动命令、端口和已有测试。只有依赖缺失时才说明安装目录与影响并请求许可。服务启动后检查 readiness，再生成/运行 Playwright；不要让零基础用户自己找 `package.json` 脚本。

成功标志：目标 URL 可达，至少一条含业务断言的流程执行完成，报告已落盘。

## iOS

### Windows/Linux 宿主

检测到 Windows 或 Linux 后，不再要求用户安装 Xcode、Simulator 或 XCUITest，也不输出 macOS 专用命令。Agent 继续完成测试设计并生成 `10-manual-test-guide.md`：

1. 先确认用户是否有 iPhone/iPad，以及 App 是否已安装或能否通过 TestFlight、App Store、企业分发、MDM、Ad Hoc 安装。
2. 有设备和安装入口时，按真实设备生成逐步人工用例，标明权限弹窗、网络切换、前后台切换、中断恢复、截图/录屏和版本记录要求。
3. 没有设备或安装入口时，同样输出完整用例，但把缺失条件放在“执行前准备”，所有用例保持“未执行”。
4. 告诉用户只需打开 `manual-handoff/02-manual-test-cases.csv`，填写状态、操作人、实际结果、开始/结束时间、证据路径和备注；不要要求其理解 Appium、WDA 或远程 runner。用户交回文件后由 Agent 运行导入器并生成报告。
5. 人工结果回传前发布结论为“无法判断”；回传后也不得称为“自动化通过”。

### 初学者推荐顺序

1. 有 Xcode 工程：优先让 Agent 构建 Simulator 版本并自动识别 scheme/bundle ID。
2. 有 Simulator `.app`：选择一个已启动 Simulator，使用 Appium/XCUITest。
3. 只有 `.ipa` 或 App Store 名称：说明 Simulator 不能直接安装真机包，需要已连接 iPhone、有效签名/开发配置或设备云。

Agent 自动完成：检查 macOS/Xcode、列出 Simulator、读取 App bundle ID、运行 Appium preflight、选择已满足的 runner。

只有系统必须由人处理时才逐步提示：

- 打开 Xcode 完成首次组件安装；
- 在 iPhone 上点击“信任此电脑”；
- 开启 Developer Mode；
- 处理签名账号或系统权限弹窗。

不要要求用户理解 UDID、WDA、XCUITest driver。需要展示时说明：UDID 是设备编号，WDA 是 Appium 在 iPhone/Simulator 上执行点击和读取页面的桥梁。

成功标志：设备为可用状态，应用安装/启动成功，Appium/XCUITest 会话成功，并至少完成一条业务流程；只创建会话不算测试通过。

## Android

### 初学者推荐顺序

1. 有 APK：使用一个已启动 Emulator 或 USB 连接的 Android 手机。
2. 有 Android 工程：Agent 自动识别 Gradle variant，构建测试 APK，再选择 Appium UiAutomator2 或工程内 Espresso。
3. 只有 Play 商店名称：需要带 Play 商店的模拟器/真机或设备云；名称本身不能安装和测试。

Agent 自动完成：查找 `adb`、列出设备、判断 `offline/unauthorized/device`、读取 package/activity、检查 UiAutomator2 driver、安装和启动测试包。

手机未授权时一次只提示：

```text
请解锁 Android 手机并确认“允许 USB 调试”。
成功标志：弹窗消失；确认后告诉我，我会重新检测设备，不需要你运行命令。
```

如果完全没有 Android 环境，优先询问用户是否愿意使用 Android Studio Emulator；获得许可后再安装/创建，不直接让用户配置 SDK 环境变量。

成功标志：`adb` 状态为 `device`，应用安装/启动成功，至少一条业务流程完成并生成报告。

## 微信小程序

### 用户有工程

初学者只需提供包含 `project.config.json` 的文件夹。Agent 自动检查 Node.js、微信开发者工具 CLI、`miniprogram-automator`、页面路由和依赖。

如果用户找不到工程，让其在 Finder/资源管理器中搜索 `project.config.json`，或提供可能的父目录让 Agent 搜索。不要让初学者配置 `wsEndpoint`。

需要开发者工具设置时，一次只引导一个操作：打开微信开发者工具 → 设置/安全设置 → 开启服务端口；不同版本菜单名称不一致时，先让用户提供当前界面文字，不猜坐标。

### 用户只有已上线名称

直接解释：开源 `miniprogram-automator` 控制的是微信开发者工具中的工程或已授权自动化连接，不能仅凭名称稳定控制桌面微信里的发布版。请求以下任一项：

- 工程目录；
- 团队/CI 提供的 `MINIPROGRAM_WS_ENDPOINT`；
- 标准设备云/真机自动化入口。

拿不到时生成可执行人工清单并标记 `阻塞/未执行`，不得使用 Computer Use 冒充自动化通过。

二维码、微信分享卡片和 AppID 可以帮助确认小程序身份，但**不是** `miniprogram-automator` 的自动化入口。收到这些信息后仍需工程目录、已授权 endpoint 或标准设备云；不得因为能定位小程序就宣称可以自动执行主流程。对零基础运营用户，优先问“你能否联系开发人员提供小程序工程压缩包”，再解释压缩包内应包含 `project.config.json`，不要直接抛出 endpoint 术语。

成功标志：可以通过 `launch` 或 `connect` 打开指定路由，元素操作和业务断言成功，result/report 已生成；宿主能力另列真机未验证项。

## 安装与授权

缺少工具时先用普通语言告诉用户：

- 为什么需要；
- 安装到哪里；
- 是否联网；
- 是否修改全局环境；
- 大致占用和可否删除；
- 安装后由 Agent 做什么验证。

推荐话术：

```text
当前缺少项目内的 Appium 依赖。它用于控制测试设备，不会修改你的 App 代码。
我建议安装到本项目目录并使用隔离缓存，需要联网下载；不会全局安装。
你允许后我会自动安装，并重新检查版本、driver 和设备状态。
```

已满足依赖时直接复用，不机械询问“是否安装”。认证、签名、系统信任和隐私权限按动作时确认规则处理，凭证不写进报告或代码。

## 完成标准

零基础接入只有同时满足以下条件才算完成：

1. 用户知道本轮测试目标和会发生的副作用；
2. preflight 明确显示目标、runner 和必需依赖可用；
3. 至少一条带业务结果断言的主流程执行完成，或明确记录不可执行 blocker；
4. 结果区分产品失败、自动化失败和环境阻塞；
5. 报告文件已落盘，并在回复中提供绝对路径；
6. 未验证平台、真机能力和兼容风险已列出。

## 常见失败表达

不要说：

```text
请自行安装 Appium、配置环境变量、启动 WDA 后再试。
```

改为：

```text
当前停在“找不到 iOS 自动化 driver”。应用和模拟器都已经识别，不需要重新配置。
下一步我可以把 driver 安装到本项目的隔离目录；需要联网，不影响全局环境。获得允许后我会执行并重新检测。
```

不要说：

```text
请提供 wsEndpoint。
```

改为：

```text
如果你有小程序源代码，请发送包含 project.config.json 的文件夹路径，这是最简单的方案。
只有团队已经搭建自动化服务时，才需要提供以 ws:// 开头的连接地址。
```
