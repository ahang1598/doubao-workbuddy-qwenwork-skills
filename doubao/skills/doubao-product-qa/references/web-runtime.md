## 上下文优先

先从对话和输入提取：项目路径、启动命令、URL/端口、环境变量、依赖安装状态、登录方式和测试范围。已明确的信息直接复用，不重复询问。

只有出现以下情况才确认：

- 多个启动命令无法判断目标；
- 需要下载依赖、启动数据库或外部服务；
- 缺失环境变量且可能连接生产资源；
- 端口被未知进程占用；
- 启动会写入生产或共享环境；
- 登录需要用户处理验证码、扫码或 OAuth。

## 识别工程

运行：

```bash
python3 scripts/qa_flow.py inspect-web qa-results/<feature>/qa-run.json --project <项目目录>
```

然后读取实际配置，而不是仅依赖探测结果：

- Node：`package.json` scripts、lockfile、Playwright/Cypress/Vitest/Jest 配置；
- Python：`pyproject.toml`、requirements、`manage.py`、Flask/FastAPI 入口；
- Go/Java：`go.mod`、Maven/Gradle wrapper；
- 容器：Compose、Dockerfile、端口与依赖服务；
- 环境：`.env.example/.env.sample` 的键及本地 `.env` 是否存在；
- 文档：README 中与本地启动、测试账号、seed 相关的内容。

区分 Web 页面、纯 API、全栈和静态站点。纯 API 不启动浏览器测试，除非存在 API 文档 UI 或用户明确要求。

## 确认边界

自动推断结果包含候选启动命令和默认端口，但框架默认值不能覆盖项目显式配置。优先级：

1. 用户已给命令/URL；
2. CI、项目脚本或开发文档中的明确命令；
3. package/Makefile/Compose 中的启动入口；
4. 框架默认值。

依赖已安装且命令唯一时直接执行。需要安装依赖或有多个高置信候选时，说明判断与影响后再按当前环境授权规则执行。

## 启动服务

1. 检查目标端口是否已监听，例如 macOS/Linux 使用 `lsof -nP -iTCP:<port> -sTCP:LISTEN`。
2. 若已有服务，先确认其进程、工作目录和 health；符合目标则复用，不重复启动。
3. 使用当前工具提供的长运行会话/后台执行能力启动，不用会丢失 PID 的临时 shell 技巧。
4. 记录：命令、工作目录、PID/会话 ID、开始时间、日志路径、URL 和端口。
5. 将 stdout/stderr 保存到本次测试结果目录；启动失败时先报告原始错误。
6. 不自动修改业务配置来强行启动；需要临时覆盖时记录变量并在结束后恢复。

数据库、队列、对象存储等依赖应使用项目既有开发环境、容器或测试替身。不要把“前端 dev server 已监听”误判为整个系统 ready。

## 等待就绪

按条件轮询而非固定 sleep：

1. TCP 端口开始监听；
2. HTTP health/目标 URL 返回预期状态；
3. 页面不再停留在构建错误、loading/skeleton 或登录重定向循环；
4. 核心 API/数据库依赖可用。

为 readiness 设置总超时并保存最后一次响应和服务日志。HTTP 200 不是唯一成功标准；重定向、401 或业务 health JSON 需按目标解释。

## 登录态

### 选择顺序

1. **复用当前会话**：用户浏览器已有登录态、扩展或企业 SSO 时，使用 Chrome/浏览器控制工具。
2. **测试登录本身**：有头浏览器 + 测试账号；验证码、扫码、MFA、OAuth 由用户完成不可自动化部分。
3. **登录不是目标**：通过测试 API/fixture 获取会话，保存短期 Playwright storage state。
4. **无 GUI**：注入测试 cookie/token 或 API 登录；没有合法入口则阻塞。

### 规则

- storage state 按环境、角色和租户隔离；文件名不含账号隐私。
- 密码、token、cookie 和扫码结果不写入代码、报告、截图或版本库。
- 测试会话使用最小权限和短有效期，结束后撤销或过期。
- 覆盖退出登录、会话过期、权限撤销、跨标签和旧会话行为。
- 登录 fixture 失败时区分凭证、环境、身份服务和产品回归。

## 结束与清理

1. 先保存测试报告、失败证据和服务日志。
2. 清理本轮测试数据、mock、storage state 和临时配置。
3. 只停止由本次任务启动的 PID/会话；复用的已有服务保持运行。
4. 检查进程已退出、端口已释放；强制终止前先尝试正常关闭。
5. 记录未清理的数据、仍运行的依赖和需要人工处理的副作用。
