## 从需求到测试模型

将每条需求写成：

```text
给定 <角色/状态/前置数据>
当 <动作/事件>
则 <可观察结果>
并且 <持久化/通知/下游副作用>
失败时 <错误提示/回滚/可重试行为>
```

无法填满该结构的部分就是需求缺口或可测性问题。页面控件不是测试模型；业务状态与约束才是。

## 通用功能覆盖

对每个功能按相关性选择，不机械全选：

| 维度 | 关键问题 | 示例 |
|---|---|---|
| 主流程 | 用户能否完成核心任务 | 创建订单并得到唯一订单号 |
| 输入 | 类型、长度、格式、字符集、精度 | 空格、emoji、超长文本、小数舍入 |
| 边界 | 最小/最大及边界两侧 | 0、1、上限-1、上限、上限+1 |
| 异常 | 依赖失败或非法操作如何表现 | 超时、断网、4xx/5xx、库存变化 |
| 状态 | 状态迁移是否合法且可恢复 | 草稿→提交→撤回；禁止已结束再编辑 |
| 权限 | 角色、数据归属与越权 | 本人/他人数据，权限撤销后的旧会话 |
| 幂等 | 重复请求是否产生重复副作用 | 连点提交、客户端重试、消息重复投递 |
| 并发 | 冲突时结果是否确定 | 两端编辑、最后一件库存、重复抢券 |
| 一致性 | UI、API、数据库和消息是否一致 | 页面成功但异步任务失败 |
| 生命周期 | 创建、读取、修改、删除、恢复 | 软删后搜索、恢复后的引用关系 |
| 中断恢复 | 刷新、退出、崩溃后是否可继续 | 表单草稿、支付回跳、上传断点 |
| 可观察性 | 失败是否能定位 | 错误码、request ID、审计日志 |

## 测试设计技术

### 等价类与边界值

1. 列出有效类和无效类。
2. 对有序范围测试 `min-1, min, min+1, nominal, max-1, max, max+1` 中有意义的点。
3. 同时检查前端限制与服务端校验；前端不能代替服务端约束。
4. 对文本补充空值、纯空白、组合字符、emoji、换行、HTML/脚本样式文本和规范化差异。

### 决策表

适用于优惠、权限、状态组合等规则。列出条件、动作和结果，合并结果相同且无风险差异的组合。若组合爆炸，优先覆盖：

- 每条规则至少一次为真和为假；
- 冲突规则的优先级；
- 缺省/未知条件；
- 最高业务影响组合。

### 状态迁移

对每个状态验证：合法进入、合法退出、禁止迁移、重复事件、超时事件、撤销/补偿、并发事件。检查 UI 状态与后端状态是否同步。

### Pairwise/代表性组合

用于浏览器、系统版本、账号类型、网络与语言组合。先保证每个单因素重要值出现，再覆盖高风险交互对；资金、权限和一致性场景不能只依赖 pairwise。

### 探索式测试

使用短 charter：

```text
探索 <目标区域>
使用 <数据/角色/中断方式>
发现 <状态、错误恢复、一致性或易用性风险>
时间盒 <分钟>
```

记录路线、观察、证据和未完成方向，避免只写“随机点点”。

## 测试层级与稳定性

测试金字塔用于选择最低成本且足够可信的层级，不是固定的 70/20/10 配额：

| 目标 | 优先层级 |
|---|---|
| 纯函数、边界、金额公式、规则组合 | 单元测试 |
| 数据库、队列、缓存、服务契约 | 集成/组件测试 |
| API 鉴权、状态、幂等与跨服务副作用 | API/契约测试 |
| 用户能否完成跨层关键旅程 | 少量 E2E |
| 浏览器渲染、键盘、视觉、真实设备能力 | UI/设备测试 |

同一业务规则通常由低层大量覆盖、E2E 保留关键代表路径。不要在 Playwright/Cypress 中重复实现全部规则组合，也不要用单元测试替代真实浏览器、权限、支付、推送或设备能力。

自动化稳定性规则：

- 每个测试独立准备和清理数据，不依赖执行顺序；
- 使用条件等待，不使用固定 sleep；
- 定位优先语义角色、label、name，再用稳定 test id；CSS class 最后使用；
- 外部不稳定依赖用 mock/stub/录制回放隔离，真实联调另建用例；
- flaky 必须记录首次失败、复现次数和归因；重试只用于诊断，不把抖动洗成通过；
- 测试标题携带稳定 `TC-*`，执行记录使用独立 `EXE-*`。

## Web 与 H5

- 浏览器：当前稳定版 Chrome 为主；依据用户量选择 Safari/Firefox/Edge 代表版本。
- 视口：桌面、窄屏、常见手机宽度；检查横竖屏和软键盘遮挡。
- 导航：深链、刷新、返回/前进、新标签、过期链接、未登录回跳。
- 表单：原生校验、服务端错误映射、重复提交、自动填充、粘贴、输入法组合。
- 页面状态：初始、加载、骨架、空、部分数据、错误、离线、重试、无权限。
- 持久化：cookie/localStorage/sessionStorage、跨标签、退出登录清理、缓存失效。
- 可访问性冒烟：键盘操作、焦点顺序、可见焦点、名称/角色、错误提示关联、对比与缩放风险。
- 网络：慢网、断网恢复、请求取消、乱序响应、缓存 304、接口超时。

## App

- 平台/版本：按用户分布选 iOS/Android 主版本与最低支持版本。
- 设备：代表性屏幕、刘海/挖孔、低内存、存储不足；平板仅在支持范围内。
- 生命周期：冷启动、热启动、前后台、进程被杀、系统回收、升级安装。
- 权限：首次允许/拒绝、永久拒绝、设置页变更、使用中撤权。
- 中断：来电、锁屏、旋转、网络切换、耳机/蓝牙、系统弹窗。
- 分发：旧版升级、数据迁移、灰度开关、强更/非强更、渠道包差异。
- 推送/深链：前台、后台、未启动、登录态过期、目标内容已删除。

无法接入真机或原生自动化时，生成明确的真机手工矩阵并标为未执行，不把 API/H5 通过替代为 App 通过。

## 小程序

- 基础库与宿主 App 版本；开发版、体验版、正式版配置差异。
- 授权、登录态、手机号/位置/相册等能力的拒绝与重新授权。
- 页面栈、返回、分享进入、扫码/场景值、冷启动和热启动。
- 网络域名白名单、分包加载、缓存、弱网与离线。
- 支付、订阅消息、客服、地图等宿主能力的取消/失败/重复回调。
- 不同机型与系统字体、键盘、安全区。

## API 与数据一致性

每个端点按适用性覆盖：

- 方法、路径、Content-Type、版本和契约 schema；
- 身份认证、token 过期、签名、角色、租户和对象级授权；
- 必填、类型、枚举、长度、格式、未知字段和重复字段；
- 状态码、业务码、错误信息、request ID 与敏感信息；
- 分页首页/末页/空页、排序稳定性、过滤组合、游标失效；
- 幂等键、重复提交、重放、超时后的未知结果；
- 并发写、乐观锁、事务边界和部分成功；
- 速率限制、重试提示、退避、熔断和降级；
- 向前/向后兼容、字段缺省、旧客户端；
- UI 展示、持久化数据、缓存、搜索索引、消息和第三方副作用的一致性。

接口文档未说明的约束不得直接当作正确预期；可作为风险探索，并标注推断来源。

## 非功能风险

除非用户明确要求深测，默认做风险识别与冒烟，不声称完成专业审计：

- **性能**：首屏/关键操作体感、重复请求、N+1 跡象、大数据量退化、资源泄漏风险。
- **安全**：认证/授权、敏感信息暴露、输入处理、CSRF/CORS 配置风险、重放与会话失效；避免破坏性攻击。
- **兼容**：浏览器/系统/设备/版本/语言/时区/字体缩放/网络组合。
- **可靠性**：超时、重试、降级、重复事件、恢复和监控告警。
- **可用性**：反馈、错误可恢复性、防误触、不可逆操作确认。
- **隐私**：最小采集、授权撤回、日志/埋点脱敏、导出与删除链路。

## 回归选择

以变更为中心建立影响圈：

1. 直接变更的需求、页面、端点和配置；
2. 上游入口、鉴权、公共参数和数据准备；
3. 下游持久化、通知、统计、搜索、结算等副作用；
4. 共享组件、SDK、公共接口和跨端复用；
5. 该区域历史高频缺陷；
6. 最小 P0 冒烟集。

输出 `必回归 / 建议回归 / 可延后`，并写明选择依据。不能读取 diff 或依赖图时，把回归范围的不确定性列为风险。

## 停止扩展用例的条件

满足以下条件可停止继续铺量：

- 每条规则、状态迁移和高风险失败模式已有覆盖；
- 新增用例只重复相同缺陷机制，边际价值很低；
- 组合已按风险削减，未覆盖组合有明确理由；
- 所有 P0/P1 风险都有验证或接受决策；
- 余下工作属于环境、账号或需求阻塞，已记录下一动作。
