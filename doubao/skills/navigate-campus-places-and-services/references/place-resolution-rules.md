# 地点解析规则

## PlaceRecord

```json
{
  "mode": "place_resolution",
  "institution": {"name": "", "campus": ""},
  "query_label": "",
  "canonical_name": "",
  "place_type": "building|office|club_office|club_event|event|registration|exam_room|other",
  "building": "",
  "floor_room": "",
  "functions": {"permanent": [], "event_specific": []},
  "event_scope": {"name": "", "date": "", "term_or_batch": "", "session": ""},
  "address_or_landmark": "",
  "map_match": {"provider": "", "label": "", "url": "", "caveat": ""},
  "status": "verified|verified_with_caveat|partial|unresolved",
  "sources": [],
```

## 建筑作用

- 使用学校官方建筑介绍、校园地图、入驻单位页面或当前官方通知确认用途。
- 一个单位在某楼办公，只能证明该单位或当前事项与该楼有关，不能证明整栋楼的全部功能。
- 信息不完整时表述为“已确认的主要用途包括”，不要声称完整覆盖。
- 同名楼宇出现在多个校区时，先消歧校区。

## 社团地址

- `club_office` 表示有官方常驻依据的办公室、长期活动室或固定物资点，不要求 `event_scope`；`club_event` 表示招新摊位或一次性活动场地，必须带活动名称，并至少带日期、批次或场次中的一项。
- 当前活动通知只能支持当次地点，不能自动成为常驻地址。
- 旧招新推文、非认证群聊和地图用户标注不能单独证明当前地址。
- 找不到常驻地址时，给出学校认证社团目录、团委/学生组织咨询入口或当前公开联系渠道，并标记未确认。

## 活动与报名地点

- 保存活动全名、主办方、举办/报名日期、批次、截止时间和地点原文。
- 区分活动举办地点、线下报名点、签到点、领票点和线上报名 URL。
- 活动结束或报名截止后，不把旧地点描述成当前可用。
- 海报与后续变更通知冲突时，优先核对主办方的更新公告并展示变化。
- `event_scope.date` 和考试日期必须是能按公历解析的真实 `YYYY-MM-DD` 日期；非法月份、日期和闰日禁止通过。

## 考试教室与房间代码

- 只读取用户当前凭证中与地点有关的最少字段；不要搜索个人姓名、证件号或准考证号。
- 先确认学校、校区、考试类型、考试日期、场次和完整地点原文。
- 使用本次考场安排、教学楼代码表、官方校园地图或考场示意图建立楼宇映射。
- 不按跨学校经验拆解代码。没有本校证据时，`A3105`、`J2-204` 等只保留原文并标记 `partial` 或
  `unresolved`。
- 地图通常只能确认楼宇；楼层和房间继续以准考证、考试安排或学校编号规则为准。

## 路线与地图降级

- 默认 L0：地址文字、入口/地标和官方校园地图链接。
- 可选 L1：用户明确要求时，通过可用浏览器访问第三方地图；标注来源及校内道路不准确风险。
- 预留 L2：未来地图工具接入。当前不得把不存在的地图 MCP 写成必需依赖。
- 只能定位到楼宇时，不生成楼内步行路线。
