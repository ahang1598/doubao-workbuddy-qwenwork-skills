# 官方来源与搜索协议

## 1. 来源类型

| 类型 | 可支持的事实 | 限制 |
| --- | --- | --- |
| `school_official` | 学校规定、部门职责、常设建筑用途、办事入口、考场安排 | 比较发布日期、校区和适用身份 |
| `transaction_first_party` | 当前社团、活动、报名或考试的时间与地点 | 只在对应活动、日期、批次或场次内有效 |
| `user_current_document` | 用户本次准考证、回执或通知中写明的个人安排 | 只说明材料内信息，不声称已独立鉴真，不外推 |
| `map_spatial` | 地址、坐标、入口、距离和路线 | 不支持部门职责、办理入口/材料/步骤/时间/费用/联系方式、学校政策、建筑用途、活动或考试安排 |

论坛、问答网站、搜索摘要、未认证自媒体和个人经验不得作为正式结论来源。它们最多用于发现别名或候选 URL，
之后仍需可靠来源确认。

## 2. 来源优先级

### 办事流程与常设用途

1. 学校办事大厅、服务门户或事项库。
2. 学校职能部门、学院或校区官方页面。
3. 学校正式通知、办事指南、下载表格或官方问答。
4. 学校认证的官方公众号或正式发布渠道。
5. 与事项直接相关的政府或公共服务官方页面。

### 社团、活动、报名和考试地点

1. 用户提供的当前准考证、报名回执、活动通知或邀请材料。
2. 学校、学院、考试管理部门或主办方的当前原始通知。
3. 学校认证的社团或组织官方账号、报名页面和更新公告。
4. 学校官方校园地图、建筑索引、场馆介绍或考场示意图。
5. 地图服务对建筑位置的空间确认。

用户材料可以确认“材料写了什么”，不能单独证明建筑长期用途；一次活动通知可以确认当次活动地点，不能证明
社团常驻地址。

## 3. 工具选择

不要假设固定工具一定存在。检查运行平台实际可用能力，再按以下顺序选择：

1. **搜索工具**：发现候选 URL。豆包部署若提供 `general_search`，优先用于此步骤。
2. **网页读取工具**：打开公开静态页并提取正文。豆包部署若提供 `web.fetch`，优先用于此步骤。
3. **浏览器能力**：仅处理 JavaScript 渲染、站内交互、复杂页面或可访问的在线地图。豆包部署可使用
   `browser-task`；若工具名不同，选择等价能力。

浏览器不是登录绕过工具。需要用户认证、验证码或内部权限时，停止在公开信息边界，说明限制并提供入口。

## 4. 查询构造

先确认学校全称及官方域名，再使用少量高质量查询：

```text
学校全称 + 事项名称 + 办事指南
学校全称 + 事项名称 + 一网通办/材料/地点/办公时间
学校全称 + 建筑全名 + 用途/部门/楼层
学校全称 + 社团全名 + 办公室/活动室/招新地点
学校全称 + 活动全名 + 日期 + 地点
学校全称 + 考试类型 + 考场安排/教学楼代码/考场示意图
site:已确认学校域名 精确事项或地点原文
```

找到强候选后直接核验原始页面，不循环堆积相似搜索结果。搜索摘要只能帮助选择页面。

## 5. 时效与冲突

记录页面标题、发布主体、发布日期或更新日期、URL 和查询日期。动态地点另记录活动名称、学期、日期、
批次、考试类型和场次。

日期必须能按公历严格解析；形似 `YYYY-MM-DD` 但月份、日期或闰日不成立的值均视为无效。仅地图来源不能
形成 `service_guide` 结论，也不能证明责任部门或办理步骤。

冲突时依次比较：

1. 是否为同一事项或活动；
2. 是否适用于同一身份、校区、批次和场次；
3. 发布主体是否真正负责该事务；
4. 来源是否为更新后的正式规则；
5. 是否只是地图 POI 或旧宣传材料。

无法消解的冲突必须显式展示，不得静默拼接。
