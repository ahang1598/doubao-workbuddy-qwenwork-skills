# 重要营销节点完整活动方案

用于 IP 联名、品牌级节日、新品上市、会员大促、开业周年、连续多日任务或用户明确要求专项策划的场景。参考“葫芦娃 IP 联名社群活动”形成以下固定规范，但不得复用其品牌、IP、奖品、题目、数据或文案。

## 一、交付位置

在月度工作簿中增加`活动方案｜<活动简称>`Sheet，放在`待运营确认活动`之后、`内容配置`之前。一个重要活动一张 Sheet。

活动表保留十列摘要；专项 Sheet 展开执行细节。两处的主题、周期、目标、承载方式、奖励和风险口径必须一致。

## 二、固定方案结构

### 1. 活动概览

写明：

- 背景与营销机会；
- 活动主题及一句话传播主张；
- 总周期、预热期、主活动期、收尾/复盘期；
- 目标人群；
- 品牌目标、社群目标和转化目标；
- 核心机制一句话说明；
- 已确认事实、建议项和待确认项。

### 2. 完整活动节奏

按阶段逐行列出：

`阶段｜日期/时间｜渠道｜内容任务｜活动模块/入口｜用户动作｜结果/下一步｜所需素材`

至少包含：

- 预热与兴趣互动；
- 活动规则公布；
- 主活动每日/每轮任务；
- 答案或结果公布；
- 领券、开奖、兑换或UGC回收；
- 最后提醒；
- 收尾、晒单/社会证明与复盘。

连续多日活动不得只写“Day1–Day7同上”，每一天须有独立任务、内容角度、奖品或进度作用。

### 3. 玩法与规则

完整写明：

- 参与资格、入口和操作步骤；
- 每人/每日/活动期参与次数；
- 正确答案、达成条件或中奖资格；
- 跨群、跨门店、同一用户重复参与的去重口径；
- 活动时间、截止时间、结果公布时间；
- 奖励领取、使用、核销及过期规则；
- 异常、补发、库存不足和作弊处理；
- 隐私、肖像、UGC及实物收货信息规则。

简单投票和轻量调研优先社群答题；收集身份、联系方式、地址、报名字段或截图/文件时使用问卷或活动表单。

### 4. 奖励与备货测算

字段至少包含：

`用户池｜访问率｜参与率｜达成/中奖率｜预计人数｜奖品数量｜安全库存｜数据来源/假设`

要求：

- 优先使用同类历史活动漏斗；
- 说明样本日期、参与池和计算公式；
- 历史机制不同须调整并解释，不可机械套用；
- 无历史数据时给保守/基准/积极三档区间；
- 对外公布数量与内部备用库存分开；
- 未提供用户池、预算或库存时只给测算方法，不虚构数字。

### 5. 题库或任务库

答题、闯关、集卡、连续任务类活动须逐日列出：

`日期/轮次｜剧情/内容角度｜题目/任务｜选项或提交要求｜正确答案/达成条件｜对应产品/利益点｜奖励`

IP活动须让 IP 角色、剧情或能力与品牌产品自然关联，禁止只更换角色名的生硬贴片。

### 6. 推送文案与素材清单

至少提供：

- 预热海报标题及社群/朋友圈配套文案；
- 活动规则发布文案；
- 每日/每轮主推文案；
- 答案、结果或领券指引文案；
- 最后提醒、开奖、晒单引导和收尾文案；
- 主视觉、角色/产品图、规则图、教程图、二维码/链接等素材需求。

首版可用`[文案待品牌确认]`标记语气和产品事实缺口，但不得只留空表头。

### 7. 系统与用户链路

逐条写明：

`触达渠道 → 活动入口 → 用户操作 → 成功/失败反馈 → 奖品页 → 品牌小程序/核销 → 数据回收`

同时列出：

- iCC模块与品牌自有小程序/第三方承载边界；
- 答对、答错、中奖、未中奖、券领取、实物领奖等分支；
- 手机号、姓名、地址、截图/文件上传等信息收集点；
- 链接有效期、活动找不到、跳转失败、库存耗尽等异常测试；
- 上线前必须实测并留截图的关键页面。

### 8. 风险与上线检查

至少检查：

- IP素材、品牌卖点、权益和文案审批；
- 奖品库存、概率、预算和备用量；
- 外部券有效期、适用门店、同人限次与核销；
- 跨群重复参与、资格统计和标签准确性；
- 实物地址、隐私授权、客服及补发；
- 所有链接、二维码、答对/答错、中奖/未中奖和小程序跳转；
- 活动终止、延期或奖品替换预案。

## 三、首版与确认版边界

- 首版也要完整搭出九部分并给出代运营建议，不因资料不足只留标题。
- 产品、IP授权、权益、预算、库存、概率、日期和系统链路缺失时标`[待确认]`，不得虚构。
- 活动未通过时，`内容配置`仍只保留表头。
- 运营确认活动后，再把最终逐日文案、链接、素材、负责人和状态展开到`内容配置`。
