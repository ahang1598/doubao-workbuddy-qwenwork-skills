# iCC 系统玩法落地规则

依据 iCC 图书馆中的《COS系统上线与操作》《COS常用功能讲解》《系统对接场景》整理。系统能力可能迭代；遇到知识库未覆盖的玩法，标记“未验证”，不得推断为原生能力。

## 一、生成活动前检查

1. 确认企业微信、公众号、品牌小程序、微信开放平台和域名的接入状态。
2. 确认活动所需的外部券、奖品库存、领取规则、核销路径和预算。
3. 确认目标人群标签、门店/组织范围和排重规则。
4. 为每项活动给出以下结论之一：
   - `iCC直接支持`：现有模块可直接配置；
   - `iCC条件支持`：模块存在，但依赖公众号、小程序、外部券、H5或接口；
   - `群发承载/人工执行`：iCC仅负责触达，报名、UGC、授权或线下执行由人工/外部工具完成；
   - `未验证`：知识库没有足够证据，必须先向产品或实施确认。

## 二、已验证的 iCC 能力

| 玩法/能力 | 推荐使用场景 | 必要说明 |
|---|---|---|
| 社群答题 | 关键词答题、公布答案、答题后领券 | 奖励需配置外部券及品牌小程序领取链路 |
| 问卷调研 | 投票、兴趣测试、报名、结构化信息收集 | 写清字段、标签回写/人工整理和完成后动作 |
| 抽奖活动 | 有奖互动、会员回馈 | 需配置奖项、数量、规则和活动链接，并验证访问 |
| 盲盒碎片 | 连续多日收集、阶段任务 | 需公众号/H5等接入条件及完整活动规则 |
| 社群签到 | 连续签到、到群习惯培养 | 写清周期、达成条件和奖励 |
| 外部券管理 | 答题、抽奖、签到后的领券 | 需品牌小程序、券库存、有效期和核销规则 |
| 标签与组织定向 | 会员等级、生日、兴趣、门店等精准触达 | 1V1每周1–2次，并尽量避免重复触达同一人群 |

## 三、常见策划映射

- “社群投票/轻量偏好调研/二选一/口味站队/简单选择题”：默认尽可能映射 `社群答题`，直接引导用户在群内回复选项或关键词，以降低参与门槛并形成可见的讨论氛围；不得仅因出现“投票”或“调研”二字就默认使用问卷。
- “正式调研，或需要收集用户身份/联系方式/报名字段、上传截图或文件、标签回写、跨群汇总及后续筛选”：映射 `问卷调研`，并写清字段、上传要求、数据回收及完成后动作。
- 仅群发问题、完全依赖运营人工查看和统计，且未使用社群答题配置时，才标记“群发承载/人工统计”。
- “猜一猜/答题互动”：映射 `社群答题`；需要奖励时补齐外部券或奖品链路。
- “连续打卡”：映射 `社群签到`。
- “抽奖/大转盘”：映射 `抽奖活动`，不得只写奖品方向。
- “集卡/碎片”：映射 `盲盒碎片`，按预热、参与、提醒、开奖/兑换拆分日期。
- “故事征集/UGC/线下见面会”：可用问卷收集报名或群发招募，但素材上传、肖像授权、审核和线下执行默认标记为人工/外部流程。
- “会员日”：标签定向与内容触达可由 iCC 承载；积分、升级礼、储值、预约、POS核销等仅在接口或外部系统已确认时写为“条件支持”。

## 四、表格写法

在 `待运营确认活动` 中使用十个固定字段，不再单设`iCC玩法校验` Sheet：

- `时间周期`：`整体周期｜预热日期｜主推/发生日期｜承接/复盘日期`；
- `关联节点`：`Tn｜品牌节点`；
- `玩法建议`：简述用户参与动作；
- `iCC模块/承载方式`：明确写`iCC活动：问卷调研`、`品牌自有小程序活动`、`群发/人工/第三方承载`或`未验证`；
- `所需资源`：`品牌小程序；外部券×N；会员标签；人工审核……`；
- `风险与规则`：写四档结论及券库存、核销门店、有效期、同人限次、人工边界等。

纯内容活动写：

- `玩法建议`：`[承载方式：社群/朋友圈群发+人工执行] ……`
- `风险与规则`：`群发承载/人工执行｜UGC需取得授权；报名与到场由运营人工管理`

运营日历有活动时，在色块内增加一行活动承载说明，并与活动表保持同名同口径。

## 五、禁止事项

- 不把“可群发”表述成“活动全流程由系统自动完成”。
- 不虚构积分、储值、预约、POS、UGC授权、自动发奖或自动核销能力。
- 不在缺少公众号、小程序、外部券、奖品库存或规则时宣布活动可直接上线。
- 不用模糊表述代替落地路径，如“做个抽奖”“送点小礼物”“七夕活动开始”。
