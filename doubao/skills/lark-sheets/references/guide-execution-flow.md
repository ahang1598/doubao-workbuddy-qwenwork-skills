# 通用执行流程：预检、字段对齐与交付校验

适用于所有场景、**引擎无关**——只给通用流程；具体读写命令与执行细节由各工具参考提供，飞书侧的**编辑准则**与**执行要点**见主文档「飞书表格操作引擎」一章，本文不与之重复展开。

## 1、基本原则

1. **源数据默认必须保留**：除非用户明确要求删除、覆盖或替换原数据，表格编辑 / 整理 / 统计任务都不能破坏源明细。对已有表做“按指定维度统计整理”“分类汇总”“筛选保留若干列”“透视分析”“生成结果表”时，默认保留原 sheet 和原始行列，把结果写到新 sheet、新区域或明确命名的结果表；不要只反馈统计结果、清空明细、覆盖原 sheet，或把原始数据口径改掉。若用户给“已有表 / 模板表 + 新数据”，已有表是 base workbook，默认在原 sheet 末尾追加或新建结果区，不要新建同名空 sheet 后重写。多附件时动手前先显式认定谁是 base、谁是增量源；**追加 / 合并类任务**交付前逐 sheet 断言：产物行数 ≥ base 对应 sheet 原行数，且 base 每张 sheet 的首行与末行原文仍能在产物中原样检索到（用户明确要求删除 / 就地改写的行列不计入）——任一条不成立就是覆盖，不是追加。
2. **输出区域注意保护原表**：用户要求“直接在指定位置修改 / 覆盖原文件”时，才在指定位置就地修改；用户没有指定落点时，优先追加结果而不是覆盖输入，典型做法是新建 `统计结果` / `整理结果` sheet，或在原表右侧 / 下方追加结果区并保留清晰标题。题面点名了 sheet 名 / 单元格坐标 / 列顺序时按该契约排布——被点名承载某一形态结果的区域只放该形态，原始值 / 中间量另置，不要插在指定区域之前把坐标挤偏。
3. **公式优先原则**：凡是需要计算，优先写公式到最终交付的表格对应单元格，保持动态计算能力。把公式写在对话回复或表末说明里、要求用户自行复制到单元格，等同于未交付该列——公式必须真实落在目标单元格内。计算公式对可能为空的输入列先判空返回空（如 `=IF(OR(O2="",R2=""),"",…)`）——空单元格参与算术按 0 计，会产出看似正常的异常数值且不触发错误码，仅 `IFERROR` 拦不住；落完公式后抽查输入为空的行核对输出。
   - Excel 引擎：写 Excel 公式（如 `ws['C2'] = '=A2+B2'`），不要在 Python 中算好数值再写入。
   - 飞书引擎：写飞书公式；Excel 公式到飞书公式的迁移规则见 `lark-sheets-formula-translation`。
   - **例外**（允许直接写静态值）：从外部抓取的数据、永不变化的常量、用公式会产生循环引用。降级写静态值时必须在交付说明中声明（静态值 + 失败原因 + 不随源数据更新）。
   - 🚨 **最高频违规：用 Python 算好结果再硬编码写入单元格。**“先在 Python 里算准（甚至跑了校验脚本）再写进表”不能作为硬编码的理由——结果对≠合规，硬编码出来的是一张没有联动能力的“死表”。Python 可用于推导和验证，但**落进单元格的必须是引用其他单元格的公式**，关键输入要做成可修改的输入格。财务 / 金融场景尤其严格，详见 `ref-financial-modeling-standards`。

## 2、判断数据来源

| 输入信号 | 来源判定 | 走哪套引擎 |
| --- | --- | --- |
| 用户上传 `.xlsx` / `.xls` / `.csv` 文件 | 本地 Excel/CSV | Excel 引擎；默认导入为飞书表格交付 |
| 用户给出飞书 / doubao 的 `/sheets/` 链接或 token | 飞书在线表格 | 飞书引擎 |
| 用户口述 / 粘贴数据，无文件 | 待结构化 | 先结构化，再按产物载体选引擎 |
| 无数据 | 信息不足 | 向用户询问，或先用其它工具获取数据 |

## 3、数据结构和内容的预先检查

拿到数据后，**先检查结构再动手处理**：

1. **运行结构预检**了解数据概况（预检只为了解数据，具体执行仍需读取完整内容）：
   - **Excel 文件**：`python3 scripts/inspect_workbook.py <文件路径>`；若 openpyxl / pandas 等本地库都打不开（文件损坏 / 加密 / 老式 `.xls` / 非标准结构），**不要改用解压 xlsx 直读 XML、手写底层解析等本地绕路**——一律用 `+workbook-import --file <相对路径>` 导入为飞书在线表格，再走飞书引擎读取处理。
   - **CSV 文件**：用 `pd.read_csv(..., nrows=15)` 预览，注意编码（优先尝试 utf-8-sig、gbk、gb18030）。
   - **飞书表格**：优先 `python3 scripts/lark_inspect_workbook.py --url "<表格URL>"` 做只读预检，拿子表清单、布局、预览和 `current_region`；多块表 / 汇总块 / 备注块先用 `scripts/lark_detect_subtables.py` 识别候选 range；批量写入、公式 / 计算、排序 / 筛选、去重 / lookup、透视 / 图表 / 汇总、整表语义或表头不确定时，再用 `scripts/lark_profile_table.py` 对目标区域画像。也可直接调用 `+workbook-info` / `+sheet-info` / `+csv-get` / `+cells-get` 做等价读取，详见 `lark-sheets-read-data`。
2. **评估数据规模**，决定执行策略：小数据（行数 ≤ 1000 且文件 ≤ 5MB）一次性加载处理；大数据分批（分 sheet / 分行批处理 / 流式读取 / 列裁剪）；多 sheet 文件逐个 sheet 单独执行完整的「预检 → 处理 → 输出」流程。
3. **识别合并单元格**：合并单元格的值仅存储在左上角；提取类任务需 `ffill` 填充；写公式 / 做合并时只允许在左上角单元格写值 / 公式。Excel 见 `ref-xlsx-workflow`，飞书见 `lark-sheets-sheet-structure`。
4. **识别必需字段并保留列位**：用户点名输出字段时，先固化表头 schema；源数据缺某字段也要保留该列，值可留空 / 写“未提供”，不要把必需列降级进备注、也不要用其它字段替代。附加字段放在必需字段之后。用户提出的排序 / 命名 / 格式要求对**每一张**同类表一致适用，不因某张表行数少、分组少而豁免。新增的行 / 列 / 汇总行不是裸值：表头格沿用原表头的底色 / 加粗 / 对齐，数据格沿用相邻数据行的对齐与数字格式，写完读回样式确认非默认值。
5. **识别“表头不清晰”并做字段理解**：出现无表头 / 空表头列 / 多行表头 / 前几行是标题说明时：Excel 用 `scripts/preview_excel_rows.py` 对可疑 sheet 预览更多行（如前 30 行），结合数据形态判断真正表头行；对空表头列，观察该列前 20 个非空值的类型与模式，推断临时列名（如 `未命名_金额`）；后续映射与计算优先用“列坐标 / 列字母 + 行号范围”锁定字段来源，避免引用错列。
6. **识别“特殊行 / 特殊单元格”**：出现“合计 / 总计 / 小计 / 汇总 / 累计”等与明细口径不同的行时，做聚合 / 统计 / 建模前从明细中排除这些汇总行，避免重复统计（`inspect_workbook.py` 的 `special_rows` 可辅助定位）。

## 4、字段语义对齐

动手前，确认用户的指标 / 概念与数据中字段如何对应。用户说的“收入”是哪一列？“完成率”怎么算？避免“答非所问”。

- **事实表先于结论**：统计 / 分析 / 诊断类任务先落一张事实表（如学校×学科、分组×指标、分支×KPI），再从事实表派生总结。结论中的每个薄弱点、Top 项、风险域都应能回指事实表行，不要边写 narrative 边自由总结。
- **筛选交付对齐结果形态**：产物是**另一张表**（行、列都裁，如“筛出符合条件的记录并只保留若干列”）时，按规则 1 写入独立结果 sheet 并保留原表，数据要**读全表**再筛（不能只取当前可见行），交付前核对结果 sheet 的列数 / 行数。**纯行级筛选（不裁列，只是“只看 / 仅保留符合条件的行”）不走这条**——按 `lark-sheets-filter` 创建真实筛选器对象，不要新建子表。

## 6、专业格式与视觉规范

专业格式用于降低阅读成本、提高产物质量，不是默认装饰动作，避免过度使用斑马纹 / 交替行颜色等装饰。用户明确的格式要求与既有模板样式优先；只使用能够表达层级、数据类型、状态或对比关系的必要格式。

- **Excel**：`.xlsx` 涉及格式、美化、报表、模板、汇报或打印展示时，读 `ref-excel-visual-standards`。
- **飞书表格**：涉及上述场景时，读 `lark-sheets-visual-standards`。
- **财务数据**：无论产物载体，均叠加读 `ref-financial-modeling-standards`；财务规范优先于通用视觉规范。
- **无需主动美化**：仅计算、补值、临时明细或原始数据导出时，通常只保证必要的数字格式、列宽与基本可读性。
- **最低验收**：无截字、`####`、异常溢出或对象遮挡；数字、日期、百分比和标识符格式正确；图表具有清晰的中文标题、坐标轴与必要图例。**打印 / 下载类任务的完成标准是在线表格和导出 xlsx 都无遮挡**——导出后再检查一次。

## 7、交付

- **改动策略匹配诉求**：默认可在必要范围内修改；若用户要求保留原表（原件不动），则通过新建 sheet / 复制 sheet / 另存等方式实现；用户指定就地修改位置的，按「2、输出区域注意保护原表」就地改。
- **公式在交付表**：计算结果用公式写在最终交付的表格位置，不在临时表 / 中间 sheet 计算后回填数值。
- **载体与通知**：默认交付飞书在线表格链接，只要涉及飞书表格产物，必须调用交付工具交付产物给用户（宿主未提供交付工具时，在回复正文直接给出 URL，不可跳过交付）。交付 HTML 报告时正文必须内联自包含（数据、图表渲染代码、样式都在文件内），不得只放一个指向外部地址的 iframe / 跳转链接——外部地址打不开时等于没交付。
- **结论落进产物**：最终交付聚焦用户需要的结论和建议、过滤中间过程；**分析类结论要写进产物本身**（结果 sheet 的摘要区 / 附注行 / 独立说明块），对话回复只作复述——只写在回复里等于没交付。交付前按主文档「交付建议」逐条核对 query 显式要求：把 query 点名的每一项产出（sheet 名与数量、指标 / 列、图表、说明项）列成清单逐项核到——点名 N 项就核 N 项；缺口在交付说明中逐项声明，不因“主体已完成”就漏核。

> 涉及文本语义抽取 / 归类 / 打标的步骤，方法学见 `guide-semantic-analysis`（本文档管流程与交付，语义处理规范在彼处）。

## 8、信息合理性校验（生成 / 推断信息时必做）

当任务需要“生成信息 / 补全缺失值 / 把口述信息整理成表 / 输出结论建议 / 构造示例数据”，或源数据未能完整读入时，建议做合理性校验：

1. **单位合理**：货币 / 数量 / 百分比 / 温度单位一致；表头写清单位（如 `Revenue (¥)`、`Weight (g)`）。
2. **取值范围**：时间 / 时长 / 数量一般不为负；百分比一般在 `[0,1]` 或 `[0%,100%]`，异常值判断是否格式混淆并统一。
3. **日期时间一致**：结束时间不得早于开始时间；跨天需显式说明或拆分。
4. **月日歧义先定位再转换**：`9/3/24`、`4-Sep-24` 这类月日位置有歧义的日期列，转换前先扫描该列全部值——某个位置出现过 `>12` 的数即可锁定它是「日」；全列都锁定不了时按同文件其它日期列 / 数据来源惯例判定，并在交付说明标注所用规则。逐格按感觉解析必然出现月日颠倒。
5. **领域固定集合列全**：题面出现「五险一金」「四大报表」这类有公认固定构成的领域集合时，先展开集合全部子项（如五险一金 = 养老 / 医疗 / 失业 / 工伤 / 生育 + 公积金共 6 项）再动手，不凭印象省略子项——少一项即为该要求未完成。
6. **来源可追溯**：产物里每个具体数值都要能指出它来自源文件的哪一处；指不出来源的值一律不写，按主文档「附件纪律」留空并声明缺口。
