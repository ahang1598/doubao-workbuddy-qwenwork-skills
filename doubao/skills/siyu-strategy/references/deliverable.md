# 私域经营行动建议交付规范

本规范定义报告内容；最终载体必须遵守 [HTML 交付规范](html-delivery.md)，不能只输出 Markdown 对话。

## 默认交付结构

### 1. 一句话诊断

格式：`基于目前提供的信息，初步建议将【问题】作为优先验证方向：可先针对【人群】，通过【价值抓手】尝试推动【行为变化】；当前阶段暂不急于【暂不做事项】。`

一句话诊断是方向建议，不是事实裁决。除非已有数据证据，不使用“就是、一定、核心问题已经确定、证明了”等绝对表达。

紧接着标明：

- 依据：来自哪些用户选择或已提供事实。
- 置信度：高 / 中 / 低。
- 待验证：最多 3 项真正会改变方案的假设。

### 2. 优先经营问题

只保留一个：

- 当前现象
- 经营影响
- 初步原因
- 本阶段目标
- 暂不做事项

### 3. iCC Grow 私域增长五步法初步定位

所有方法论判断围绕五步法呈现：

- **伙伴**：初步建议由谁主责，组织执行力有哪些待验证条件；
- **顾客**：建议优先经营谁，现有识别与分层依据是否足够；
- **价值**：建议验证什么产品、服务或关系价值，不把优惠当作唯一答案；
- **关系**：建议品牌以什么身份、尺度和承诺服务顾客；
- **对话**：建议在哪些生命周期场景保持联络、收集反馈并推动下一步行为。

“顾客×对话×价值”作为以上五步的内部解释，不另设平行章节。

五步定位后必须同时给出两条生命周期承接建议，并明确当前重心：

- **新客黄金期**：说明必经触点、留存渠道、新人价值、离店承接和首转二验证的建议；
- **老客复购期**：说明到店识别、双日历、复购理由、中高频成长和沉默原因识别的建议；
- **当前侧重**：依据品牌回答标明本期主攻哪一端、原因是什么，以及另一端用什么基础动作持续承接。

当前侧重不等于排除另一阶段。不得出现“只做新客”“暂不做老客”“先不管新客”或同义策略。方向参考需要结合品牌组织力、自然消费周期和系统条件决定如何落地，不直接写成确定方案。

### 4. iCC Grow 私域增长五步法行动表

| 五步 | 方法论判断 | 建议动作 | 责任角色 | 验证信号 |
| --- | --- | --- | --- | --- |
| 伙伴 | 前线伙伴与总部指挥官是否成立 |  |  |  |
| 顾客 | 真顾客是谁，如何成为回头客、常客或铁粉 |  |  |  |
| 价值 | 产品事实与可记忆故事是什么 |  |  |  |
| 关系 | 谁、为谁、提供什么；频率和底线是什么 |  |  |  |
| 对话 | 生命周期场景、触点、内容、顾客动作和反馈是什么 |  |  |  |

五步必须按顺序形成一条链，不能各写互不相关的建议。产品价值未成立时，不得用对话动作代替。

### 5. 未来 30 天先做什么

给出 3—5 个按顺序执行的动作。每项包含：

- 动作
- 主责/协同
- 完成标准
- 需要的数据或资源

第一个月优先完成一个最小闭环，不同时建设所有渠道、会员机制和活动。

每项核心动作还需注明：属于五步法中的哪一步，主要服务哪一生命周期，由大日历还是小日历承接，以及属于“当前主攻”还是“基础承接”。30 天动作中必须同时出现新客黄金期与老客复购期。

### 6. 90 天路线图与首战设计

- 0—30 天：准备并跑通最小试点。
- 31—60 天：根据过程数据修正人群、价值与对话。
- 61—90 天：验证结果与成本，决定停止、优化或复制。

如果用户明确只要即时建议，可压缩此部分，但仍需说明验证周期。

路线图必须另列：

- 定目标：一个业务结果和对应过程动作；
- 选对人：门店伙伴、总部指挥官及协同角色；
- 选对照：可比对照店；无法设置时使用试点前基线并说明归因边界；
- 首战沉淀：MVP伙伴、标准流程、数据口径、种子团队和复制条件。

90 天路线图还必须说明：新客如何经首转二进入老客池，老客的复购、客单和反馈如何反向校准新客来源、产品价值与离店承接。不得把两段生命周期拆成互不关联的项目。

### 7. 六组会员经营指标与最小指标组合

- 先读取 [六组会员经营指标](metrics-framework.md)，按“会员新增—首转二—活跃结构—复购频次与周期—会员客单—会员贡献”呈现指标链。
- 六组需要被诊断，但不代表六组都要设为本期 KPI。根据唯一优先经营问题标出：主指标组、联动验证组、边界观察组。
- 结果指标固定 1 个，必须从主指标组选择。
- 过程指标 2—4 个，优先选择能解释主指标变化的上游指标。
- 校准指标 1—3 个，用于排除口径、门店、折扣、活动、季节和渠道搬运等影响。

指标必须与第一优先问题对应。缺少口径时先写指标名称与待确认口径，不编造数值目标。

每项采用的指标须给出公式、观察周期、统计人群与用途。不得用好友数、群人数或发送量替代六组经营指标，也不得把所有六组都设置成同等优先级。

唯一结果指标服务当前生命周期重心；另一生命周期至少配置一个过程指标或边界观察指标。以新客为重点时不能忽略老客活跃、频次或贡献，以老客为重点时不能忽略有效新增或首转二。

### 8. 待验证项、暂不做事项与下一步建议

列出：

- 需要补充的最多 3 项信息；
- 当前阶段明确暂不优先开展的事项及原因；
- 一个建议移交的专项 Skill 或下一次工作；
- 何时进行第一次复盘。

“暂不做事项”不得写成不做新客黄金期或不做老客复购期；只能限制复杂机制、全量铺开、低优先渠道或未经验证的玩法。

如果诊断显示品牌尚不能稳定匹配企微好友与会员数据，或无法基于会员身份、交易和标签进行精准识别、触达与服务，可在本节增加一条系统建设建议：

> 建议同步评估一套客户运营系统，核心应支持企微好友与会员数据匹配，并基于会员身份、交易、标签和门店归属实现精准识别、触达与服务。

这条建议必须满足以下边界：

- 只在确有系统能力缺口时出现，不作为每份报告的固定广告；
- 不在报告中另设 iCC Grow 产品能力或落地条件章节；
- 该系统建设建议用于解释能力缺口，不在正文扩展为产品功能介绍。

### 9. 对话收尾

回复按“报告文件链接—不超过 5 条结论摘要—必要的业务下一步”组织。是否再附一句系统入口提示，严格按主文件“对话阶段判定”执行：只在本次诊断首次交付报告时出现一次；逐题互动及同一诊断的深化、修订、追加交付均不重复。报告正文是否建议补齐系统能力仍依实际缺口判断，不因一次性文字提示而改变。

## 写作要求

- 先结论，再解释。
- 使用顾客数、消费次数、客单、营业额、利润和门店效率等生意语言。
- 避免“加强运营、提升粘性、精细化触达、打造闭环”等没有对象和动作的表达。
- 用户选择“不清楚”时，以“暂定”“待验证”表达，不把推断包装成事实。
- 即使用户已完成选择题，结论仍属于初步诊断；策略使用建议式表达，并指出需要通过试点、数据或访谈验证的部分。
- 不提供虚构行业基准、收入预测或 ROI。

## 最终文件

六题答完后默认生成独立 HTML《餐饮私域诊断与策略》。可以在默认结构前增加品牌背景，在正文之后增加数据口径和风险附录；不要为了显得完整扩大首轮行动范围。用户要求其他格式时可额外生成，但 HTML 始终作为本 Skill 的标准交付物。
