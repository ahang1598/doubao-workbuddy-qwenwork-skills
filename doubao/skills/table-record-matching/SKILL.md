# Table Record Matching

## 适用范围

用于本地 Excel、CSV 或 dataframe 之间的确定性记录映射、字段回填和核对。不要用于倾向性评分匹配、OCR 题库检索、彩票组合筛选或网络协议容差分析；这些任务虽含“匹配”，但目标和验收口径不同。汽配案例中以`客户型号`/`OE`为主键，`尺寸`只作校验；除非用户明确认可，不把规格、单位、地区或部门单独当唯一主键。

## 流程

### 1. 验表并锁定输入角色

读取所有文件、sheet、真实表头、列名、数据类型、样例和行数，标明主表、映射表、规则表、目标回填列与输出顺序；处理跳行、合并单元格和空列后再匹配。人员案例须先从完整版按`姓名`取得唯一编码，再以该编码匹配`BIP账号`，不能把姓名直接当最终账号键；毛利表中合并单元格留下的客户名空值须先向下继承。

若全量装载不可行或内存不足，按文件或分块流式读取；政务工单案例要求逐文件扫描，而不是一次载入全量工单。

### 2. 冻结键、优先级与统计口径

从任务描述或用户确认中写清：主键/联合键、字段映射、键的数据类型、规则来源、执行优先级、排除集、白名单/黑名单、是否允许补配，以及覆盖率分母。县域面板使用`省份+具体县名`精确键；区域包干使用`城市+区域+街道`，不能仅凭同名`街道`匹配；试剂盒使用`产品名称+检测方法`。

覆盖率定义为`命中量 / eligible总量`；`eligible总量`究竟是匹配前总量还是应用排除规则后的总量，证据未统一规定，必须明确记录。政务工单案例先按`工单编号`排除省厅已命中集，再把剩余记录作为地市匹配与覆盖率统计范围。规则优先级未确认时暂停关键字段回填，但仍可输出候选与待确认项。

### 3. 保留原值并分层清洗

为每个参与匹配的字段保留原值，另建清洗键。第一层只做可逆或无损清洗，如去首尾空格、统一大小写/全半角、规范缺失值，并检查字符串长度和字符编码；XLOOKUP 失败案例须识别并移除零宽空格后重新做精确验证。第二层只使用已确认的标点、空格、旧名或别名规则；县名如`泸水市→泸水县`、`潜山市→潜山县`只能作为已确认旧名规则，不能由相似候选自动回填。

每次补配保留`原始值`、`清洗值`、`匹配类型`、`命中规则`和`命中来源`；不要只覆盖原列。

### 4. 检查重复键并构建匹配关系

在回填前分别统计主表键和映射表键的空值、重复数与一对多关系。映射表同一键对应多个目标值时写入冲突清单，不能用`dict(zip)`、`drop_duplicates(keep="first")`或后值覆盖静默选一条；只有业务规则能证明目标值一致或明确指定保留策略时才去重。

区域包干明细必须先按`城市+区域+街道`去重，再按`街道`计算区域数并筛选区域数`>1`；若直接按设备级行统计，会把区域数膨胀。去重前后行数、唯一键数与冲突键数都要记录。

### 5. 先精确匹配，再有限补配

第一轮仅按冻结的单键或联合键精确匹配，并记录命中键、来源与`匹配类型=精确`。第二轮仅处理第一轮未命中项：可采用已确认旧名/别名、空格标点归一化，或任务明确授权的受控规则。政务工单只允许在`处理部门`字段中对地市部门白名单做包含匹配，并记录完整命中部门；不得扩展到其他文本列。

名称包含、编辑距离或评分匹配不得直接回填关键字段，除非用户确认阈值和冲突策略；工程比价若按名称、特征/规格、单位、位置和单价评分，只输出高/中/低候选及参考行号，不把候选等同于已确认命中。

### 6. 回填并计算质量指标

仅对唯一、无冲突且符合当前优先级的命中回填；保留原始列，并新增回填值、匹配状态、匹配类型、命中来源、命中规则和冲突说明。统计总量、eligible总量、精确命中量、补配命中量、未命中量、重复键量、冲突键量及整体/分组覆盖率；每项都注明分母，且`eligible总量 = 命中量 + 未命中量`。

双表核对须分别计算 A→B 和 B→A 覆盖率，并分别输出两侧反连接结果；不能以单向高覆盖代替双向完整性。试剂盒案例按分组报告覆盖率，并抽查未匹配项与关键货号，而非只看总覆盖率。

### 7. 导出可追溯交付物

至少交付：匹配结果、未匹配清单、重复/冲突清单、覆盖率摘要；若有候选补配，再交付待确认清单。企业层级案例在明细 sheet 中保留命中来源并回填`一级企业`，另在统计 sheet 按`一级企业`汇总；房地产`mapping.xlsx`案例按输入顺序用`备案名称`映射`推广名`，未匹配项目必须单列。

写出后重新读取文件，核对 sheet、行数、列名、输入顺序、公式/值和未匹配清单是否齐全。汇总结果只作交叉校验；与由明细复算的统计不一致时，以明细为准并报告差异。

### 8. 迭代规则并报告变化

把用户确认的旧名、别名、白名单或优先级写成显式规则版本，只重跑受影响阶段，再报告前后`eligible总量`、各匹配类型命中量、未命中量和冲突量的变化。新增县名旧称时仍以`省份+具体县名`验证，防止跨省同名误配；新增部门白名单时仍先按`工单编号`应用省厅排除集。

不得静默覆盖旧逻辑或仅替换最终文件；保留规则版本、变更原因和受影响记录清单。

## 边界与禁止事项

- 未确认规则时，不用泛化模糊匹配直接回填关键字段；有限补配必须可解释并标记规则。
- 不只交付成功匹配表；未匹配、重复和冲突记录是必需产物。
- 不把校验字段冒充唯一主键：例如汽配的`尺寸`仅校验`客户型号`/`OE`命中结果。
- 不静默取重复键第一条或最后一条；一对多先报告冲突。
- 排除集、白名单、旧名规则按已确认优先级执行后再统计覆盖率。
- 不臆造固定分块行数；仅在文件大小或内存使全量载入不可行时分块/流式处理。

## 工具用法

使用 pandas 或等价工具读取 Excel/CSV、检查 schema、执行 merge/anti-join、分组去重与导出；字符串键统一为文本，避免编码前导零在数值转换中丢失。区域包干的计数应基于`城市+区域+街道`去重结果，双向未匹配应用左右 anti-join，政务工单流式处理时跨分块维护已见`工单编号`，避免分块边界产生重复候选。

## 精简示例

用户要求把县名单匹配到面板：先检查表头和键类型，以`省份+具体县名`精确连接；单列未匹配。对`云南省+泸水市`，只有规则源或用户确认`泸水市→泸水县`后才以`匹配类型=已确认旧名`补配，并保留原名、旧名规则和来源。最后输出结果、两侧未匹配、重复/冲突键，以及以明确`eligible总量`为分母的精确与补配覆盖率。
