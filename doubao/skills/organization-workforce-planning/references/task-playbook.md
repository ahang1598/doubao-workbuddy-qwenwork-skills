# Task Playbook

## 基线

冻结 `as_of`、规划期、组织单元、岗位/能力 taxonomy、HC 定义、成本单位/币种/期间和组织版本。检查员工/岗位唯一计数、空缺处理、兼任、外包和共享岗位口径；无法守恒则不输出比例或排名。

同一对象存在多套口径时不得择一覆盖。分别展示原始值、分项加总、差额和采用任一口径会改变的结论。例如监管可计入研发 HC 与 HR 全口径必须分开；正式员工、承接员工、共享池、转专岗和外包必须建立唯一归属桥。

## 情景

每个情景使用用户给出的名称和参数，记录：
- 业务目标与能力需求
- baseline HC、按角色 delta、期末 HC
- 单位成本、一次性成本、期间和币种
- 工作量/容量关系及 unknown
- 组织结构假设、依赖、可逆性和决策门

HC 桥必须分开记录 `opening_hc / hires / exits / transfers_in / transfers_out / net_delta / ending_hc`。只有流量分项齐全且 `hires-exits+transfers_in-transfers_out=net_delta` 时才标完整；否则分项为 null 并绑定 `unknown-hc_flow_breakdown`。`role_deltas` 是净容量变化，不得自动改称招聘人数。涉及离职率和扩编时，先分别计算补员流量与期末净增，再说明取整规则和扩编发生时点对招聘量的影响。

缺成本字段时不要把空值变成 0。经常性单位成本、一次性投入、外包服务费、币种和期间分别检查；能算 HC 就继续算 HC，对应成本槽保持 null 并列出补证。题目只给“一次性投入”时保持中性称谓，不自行定义 capex 或做岗位分摊。

不设默认 span、层级、团队规模、利用率或增长率。若用户提供政策阈值，将其标为 `user_policy` 或 `scenario_assumption`，不能包装成通用事实。

## 产能与排程

坐席、轮班或连续运营先算同时在线理论下限，再逐项列占用率、休息/培训损耗、出勤率、轮休和峰段时长；未给参数时不生成“达标编制”。班次可行性必须同时满足每周需求班次与人员可供班次。

多项目资源按「稳定专业 ID × 时间桶」汇总。内部需求先扣除已确认且口径明确的供应商投入；专业之间不可互换。口径不清记录保留上下行情景。外部支持同时受可承担工作、内部保留责任、提前期、周上限和授权状态约束；周上限不等于已可用产能。

工作包移位必须同时满足附件中的移动窗口、前置依赖和硬节点。不可移动项只可列为“管理层若改变约束”的影响测算，不得进入基于现有约束的调整后计划。

## 时间与决策门

若用户提供经营会、开业、直播、到岗等硬日期，使用真实日历倒排。招聘窗口包含寻访、录用至到岗和要求在硬节点前完成的熟悉期，并优先采用材料给出的稳妥上限；已晚于最晚启动日时明确逾期与替代路径。没有日期时才使用相对阶段。

每个决策门包含 owner、输入、完成证据、通过条件、未通过影响和回退。不得用无来源的自动触发阈值；新增中间方案标为待确认情景，写明成立条件和退出门。

## 结构与迁移

比较能力覆盖、工作量支持、岗位依赖、HC 成本、可逆性和风险；不给个体贴“冗余”或绩效标签。缺结构基线时，把每个已有情景转成 `scenario_support_option_not_org_chart`，`reporting_lines=null`，不得冒充组织图。迁移路线使用用户给定日期或条件阶段、decision gate、通过条件和失败回退；可含招聘/培养/轮岗/外包等待验证选项，但不自动选择裁员，也不执行汇报线或预算变更。

姓名、联系方式、证件、健康和年龄/性别/婚育/家庭/户籍等受保护属性不得进入人员适配、夜班、调岗或去留判断。默认在岗位和聚合层工作；只有用户或组织政策给出最小群组阈值时才按该阈值发布分组指标，低于阈值即抑制或泛化。

## 降级

能力地图、工作量、结构基线或 HC 流量拆分缺失时，每项建立正式 unknown，写明影响槽位、下一证据和结论如何变化。仍交付：

1. `能力需求 → 工作量 → 岗位依赖` 空骨架；
2. 基于已有 base/growth 等情景的至少两套支持选项；
3. HC/成本桥及不完整流量标记；
4. 条件迁移阶段与 decision gates；
5. 最大反方：净增量与成本算术不能证明组织效果；
6. 补证队列和完整工件索引。
