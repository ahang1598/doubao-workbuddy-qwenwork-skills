# Workflow Playbook

## Scenario Diagnosis
1. Identify the artifact type requested by the user.
2. Extract facts: who, what, when, where, why, constraints, audience, tone, source materials.
3. Mark missing facts as `待确认` instead of inventing them.
4. Choose the output template and execute the corresponding path.

## Official Rule Check
Before qualification, award compatibility, author count, team member eligibility, or reimbursement conclusions:

1. Use the provided official notice/rules first.
2. If rules are absent and browsing is available, verify against the official competition, school, college, or project office source.
3. If verification is impossible, write `待核验` and give the exact rule question to ask. Do not turn common practice into a final official conclusion.

## Reimbursement and Evidence Path
- Build a row-level table for each receipt or evidence item: `编号`, `金额/状态`, `问题`, `处理方式`, `是否可报/可认定`, `补证责任人`, `截止日期`.
- For outputs such as demo, submitted paper, accepted paper, software copyright, patent, award, open fund, or ethics approval, separate current status from permissible wording.
- Use risk levels: `一票否决项`, `高风险`, `中风险`, `低风险`. Give a compliant rewrite for every unsafe claim.

## Defense and Timeline Path
- If the task includes 答辩, 路演, 评审, 中期, 结题, or presentation, include a full speaking script and PPT page plan.
- PPT page plan columns: `页码`, `标题`, `核心证据`, `图表/材料`, `讲稿要点`, `风险边界`.
- Reverse-plan from the real deadline to concrete dates. Mark the longest bottleneck such as ethics review, teacher signature, college seal, system review, invoice reissue, or rule confirmation.

## Templates

### One-Page Plan
- 背景：一句话说明任务和目标。
- 关键信息：对象、时间、地点、负责人、来源。
- 行动方案：3-6 个步骤，每步有产物或验收方式。
- 风险与待确认：只列真实影响执行的内容。

### Script or Copy
- 开头：明确身份、场景和目的。
- 主体：2-3 个证据点或利益点。
- 结尾：行动号召、确认方式或后续安排。

### Checklist/Table
Columns should usually include: item, owner, deadline, source/evidence, status, note.

## Domain-Specific Outputs
- 申报时间线
- 材料清单
- 个人/项目陈述
- 答辩稿
- 材料缺口表

## Quality Standard
A strong output is specific enough to use today, but honest about missing facts. It should reduce the user's next action to editing, confirming, or sending.
