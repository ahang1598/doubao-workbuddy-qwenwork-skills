# 交付契约

本组规则约束**如何执行当前 query**，不规定任何市场应得出什么结论，也不提供可复用的默认要素清单。

## 从 query 抽出验收清单

仅当用户点名必填要素、必算项、必填字段或必交文件时触发。

1. 只从当前 query 抽出被点名的名称、字段和计算依赖，形成本次清单。用户列了几项就保留几项。
2. 对清单中每一项给出 `present`、`unknown` 或 `missing`。`unknown` / `missing` 必须写明材料缺什么；不得静默省略。`present` 不得带 `missing` 字段。
3. 不得因为“这类任务通常还要这些栏目”而补用户未点名的模板项。
4. 材料不足以完成某项时，只把该项标为未知或缺失，其余有证据的项继续交付。
5. 普通短答、未列举必填项的问题不触发本清单，也不因此进入文件流程。

零工具时仍在会话内完成抽取与验收，不把清单写成固定章节标题。

## 时间尺度

会影响结论、风险或下一观察的线索必须带尺度：`intraday`、`multi_day`、`multi_week`、`quarter`，或 `unknown`。

- 尺度必须能追溯到当前材料中的窗口，或用户给定的观察窗口。
- 材料没有窗口时写不确定，不得填一个默认天数，也不得把所有事件统一后移一个交易日。
- 修辞性、背景性句子不做尺度审计。
- 没有尺度的线索不得升格为确定信号。

## 会话间隔与是否入价

仅当上次有效收盘与本次 `as-of` 之间存在休市或跨日间隔时触发。

- 先列出间隔内新增信息、首次可见时间、当前状态，以及是否已进入当前价格。
- 首次可见时间必须落在上次收盘之后、本次 `as-of` 之时或之前；截止后信息不得写入间隔表。
- 间隔内没有新增信息时，显式写“无新增”，而不是省略本步。
- 没有同期预期、定位或价格状态证据时，`priced_in` 不得为 `yes`，也不得改称资金提前获知。
- 连续交易日且无新增信息则跳过，不强制出表；跳过时不得提交空 `items`。
- 星期几不能代替交易日历。不得把周一至周五一律当作交易日。

## 指标公式与禁用别称

仅当用户要求验证、核验或按指定口径计算指标时触发。

- 每个被点名的指标写：计算式、单位、至少一个禁用替代口径。
- 禁用名单只从当前 query 与本次材料生成，不维护全局合法指标表。
- 主线判断只能引用题目要求的那个口径。必须把主线正文交给助手，并点名每一个主线指标；正文或扩展短语只要包含禁用别称即失败。
- 附加口径可以出现在表里，但不能作为主线依据。
- 已有禁令保持有效：成交额或成交量不是净流入。
- 助手检查结构完整性和主线正文的禁用子串，不判定经济含义。

## 排序与摘要回读

- 领涨、领跌、最强、最弱及同类排序词必须绑定已验收的 `source_rows`，并申报与行序一致的 `place`。第 1 名只能是已排序表的第一行，不得把任意行标成领涨。
- 无表且无已验收计算时，标明无法排序，而不是用形容词补一个名次。
- 用户要求文件时：先在当前权限下生成真实文件，重新打开得到正文，把正文交给助手计算哈希，再写会话摘要。
- 摘要中的排序和结论必须能在重开正文里回读到；哈希必须由该正文算出。文件改动后旧摘要不得再使用。
- 用户未要求文件时，不因此强制生成附件，也不把内部核对台账交给用户。
