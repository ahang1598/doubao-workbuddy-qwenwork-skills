# 视频方案与 interaction.ask 执行确认

本文件是所有视频场景的方案、素材询问与执行确认的唯一事实源，优先于主 Skill 和业务 ref 中旧的内容澄清、必填问卷或默认值规则。模型能力、素材输入要求、授权与交付规则不变。本 Skill 固定使用 `seedance_2.5`。完整方案展示、素材询问与执行确认均在 seedance-25 完成；确认后才调用 `doubao-creative-video` 组织 prompt 并生成，不要求先展示最终工具 prompt。方案不变时沿用本次真实工具确认，不重复确认；确需变更时返回 seedance-25 重新确认。时长、比例的自动建议仍按主 Skill 的类型表与模型范围执行，不单独追问。

## 默认：直接给完整方案，禁止询问视频内容

除下节唯一素材询问例外外，直接依据用户需求、已有上下文和可用素材拟定一套完整视频生成方案。禁止询问用户视频内容、主体动作、镜头、风格、受众、台词、声音、时长、比例或让用户从多个创意方案中选择。不能因为 brief 简短、没给脚本、没选风格或规格不全而进入需求问卷。

用户已指定的内容与合法参数优先沿用；未指定的创意内容、镜头结构、台词、音乐、时长、比例和产物组织由 Agent 合理拟定，随方案一次展示。按工具能力和主 Skill 的数量限制制定可执行方案，不静默覆盖用户要求。创作补全不等于编造真实品牌卖点、价格、资质、客户案例或人物身份；未核实的事实省略或采用明确的概念化表达。

旧版“按场景收齐所有信息”“阻塞信息必须逐项追问”“不限题数”“数量/时长不得拟定”等普通澄清规则已废止，不得据此恢复内容提问。

## 唯一素材询问例外

只有同时满足以下两个条件，才必须在出方案前调用 `interaction.ask` 询问素材：
1. 用户要求生成企业宣传片、广告 TVC、卖货／带货／产品销售类视频。
2. 用户未上传任何与当前任务相关的品牌、Logo、产品或企业资料等资产。

先检查当前上传及可恢复的历史上传资产；已有相关上传资产就直接利用，不重复索要，不因某一类别缺失而要求补齐整套资料。普通口播、个人 UGC、创意视频等不因业务 ref 名称而自动触发本例外。只有文字 brief、没有相关上传资产的上述商业任务仍命中例外。

询问仅限“上传相关品牌／Logo／产品／企业素材，或按无素材概念方案生成”，不得借机追问视频内容、规格、卖点问卷或审美偏好。选择上传则等待素材；明确选择无素材概念方案则直接拟定方案，说明不保证真实品牌／产品视觉一致性，不虚构事实。若用户本轮已明确授权无素材概念创作，不重复询问。

## 视频生成确认

**强制执行门禁，禁止省略、合并或倒序：普通文本完整展示下列参数 → 单独调用 `interaction.ask` → 收到用户对当前方案的明确同意 → 按主 Skill 工作流执行生成。** “直接出方案”不等于直接生成；用户输入完整、任务简单、时长很短、只有一段或使用后台 subagent，都不能跳过本节。

**执行 Agent 在提交生成任务前逐项检查：**

- 已用普通文本展示任务类型、交付格式、数量、逐段／总时长、比例、分辨率、逐段内容、镜头与动作、视觉方向、身份保持要求、字幕／配音／音乐及输入素材。无对应内容时明确说明；不支持的规格如实标注，不能留给工具猜测。
- 展示参数后，已独立调用 `interaction.ask`，问题仅确认是否按上述参数开始生成；选项严格只有 `按要求生成`、`暂不生成`，`multi_select: false`，不夹带方向修改、其他选项或自由组合，并提示视频生成为高消耗生成。
- 已收到针对本次方案的明确生成同意，而不是把方案展示、工具调用发出、普通聊天回复或历史确认当作授权。

任一项未满足，禁止调用视频工具或交由其他 Agent 开始生成；不得以“先生成再确认”补手续。用户主动修改参数后必须重新执行本节，不恢复内容问卷。

所有实际视频生成、视频编辑和图生视频都需要最终生成确认，包括单段、短时长、单镜头、多镜头、长时长、多段和批量任务。统一顺序为：普通文本展示 → 独立工具确认 → 按主 Skill 工作流执行；本节不增加视频内容询问。

### A. 普通文本展示完整方案，不使用工具展示

先直接发送用户可见的普通文本方案。不得用工具承载方案展示，不得只把方案塞进 `interaction.ask` 的字段，也不得仅写“按上面的要求”。文本只陈述方案，不包含问句或选项。

确认前用普通文本展示：

- 任务类型和交付格式。
- 视频数量、每段时长、总时长、比例和分辨率。分辨率按工具实际能力说明，不承诺不支持的规格。
- 逐段内容、镜头结构、主体动作和镜头运动。
- 已锁定的视觉方向与必须保持的角色／产品特征。
- 字幕、配音和音乐范围。
- 使用的首尾帧、参考素材或待编辑视频。
- 所选模型及工具必要限制。
- 完整台词／旁白、字幕与音乐安排；没有时明确说明。涉及分镜时逐镜头列明声音安排。
- 商业任务的已知品牌／产品信息与素材状态，不填造事实。
- 交付结构、必要限制和生成消耗提示。

### B. 单独调用 interaction.ask，只问是否直接生成

**生成确认必须使用封闭式单选结构，禁止开放式问答。** 不得使用文本输入框、自由填写、开放回答、多选或“其他／自定义”选项；不得用“你觉得怎么样”“有什么修改意见”等开放问题替代是否生成的确认。严格只允许用户单选 `按要求生成` 或 `暂不生成`。

按 `interaction.ask` 的实际 schema 设置单选（`multi_select: false`）；若支持自由输入开关，必须关闭。不得编造 schema 字段。若工具无法提供封闭式单选结构，则报告交互能力阻塞，不退化成开放式问答，不擅自生成。用户在后续对话中主动提出修改，不属于确认问题的选项；收到修改后更新方案，再发起同样的封闭式单选确认。

随后单独调用一次 `interaction.ask`：

- 问题只表达“是否按以上参数开始生成”。
- 选项只有 `按要求生成`、`暂不生成`。
- `multi_select: false`。
- 不提供修改方向、其他选项或自由组合，不夹带内容问题、规格选择或第二套方案。
- `按要求生成`选项必须告知用户“视频生成为高消耗生成”；保留选项名称，在工具支持的选项说明中提示，若无选项说明字段则在确认问题中明确提示，不编造字段。

调用后等待用户回答，不继续生成。

确认只对展示过的参数有效。数量、时长、规格、镜头结构、方向或素材范围变化后，旧确认失效，必须重新展示并确认。

### C. 用户同意后执行

只有取得用户对本次展示方案的明确工具确认后才调用视频生成／编辑工具。普通聊天中的同意、沉默、模糊回答不替代工具确认。用户主动要求修改时直接调整完整方案，重新展示并确认，不转回内容问卷。方案未变化时不重复确认。用户选择暂不生成则停止，不擅自生成替代品。

## 工具边界与硬阻塞

所有允许的素材询问和最终执行确认只能使用 `interaction.ask`。`interaction.request_action` 是不同工具，不是别名；禁止调用，也不得作为替代、回退或重试路径。普通聊天不能替代工具询问或确认。按实际工具 schema 调用，不编造参数。

`interaction.ask` 不可用、失败或没有有效答复时暂停依赖步骤并说明阻塞，不改用其他工具，不自行视为确认。

“直接给方案”不允许伪造缺失的工具必需输入、猜测不可确定的编辑对象或绕过模型限制。先读取已有素材和真实对象；仍不能形成可执行方案时，仅说明技术阻塞及缺失条件，不扩展为创作内容问卷，不调用无效工具。能形成合法替代方案时直接展示该方案并请求一次执行确认，不静默改变用户要求。

## 仅需文本的任务

用户只要脚本、分镜、提示词、镜头表或建议时，直接生成文本方案，不询问视频内容，不调用视频生成工具，也不做视频生成确认。上述商业素材例外仅针对实际视频生成请求。
