## 一、核心术语定义

### 1.1 个人信息

以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，**不包括匿名化处理后的信息**。

### 1.2 敏感个人信息

一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息。

**法定类别**（7类）：

| 类别 | 具体示例 |
|------|---------|
| 生物识别信息 | 人脸、指纹、虹膜、声纹、基因等 |
| 宗教信仰信息 | 宗教信仰、宗教活动等 |
| 特定身份信息 | 残障人士身份、不适宜公开的职业身份等 |
| 医疗健康信息 | 病症、既往病史、医疗就诊记录、检验检查数据等 |
| 金融账户信息 | 银行、证券、基金、保险账户的账号及密码等 |
| 行踪轨迹信息 | 连续精准定位轨迹、车辆行驶轨迹等 |
| 不满14周岁未成年人信息 | 14周岁以下未成年人的所有个人信息 |

### 1.3 同意类型对比

| 同意类型 | 定义 | 关键特征 |
|---------|------|---------|
| **同意** | 个人对其个人信息进行处理自愿、明确作出授权的行为 | 基础要求 |
| **明示同意** | 个人通过书面、口头等方式主动作出声明，或自主作出肯定性动作作出明确授权 | 主动动作（勾选、点击、填写、开启等） |
| **单独同意** | 个人针对其个人信息进行特定处理而专门作出具体、明确授权的行为 | 需与其他处理活动区分，不可捆绑 |
| **书面同意** | 以纸质或数字电文等有形形式表现，由个人签名、签章等形式取得 | 法律法规明确要求的特定场景 |

**明示同意的肯定性动作**：
```
✓ 个人主动勾选
✓ 主动点击"同意""注册""发送""拨打"
✓ 主动填写或提供
✓ 开启API、权限、传感器开关
✓ 纸质或电子书面声明、签字确认
✓ 主动出示证件、刷卡、刷指纹、刷脸
✓ 回复邮件、短信息
✓ 电子签名
✓ 电话录音、视频录像
```

## 二、告知适用情形

### 2.1 收集个人信息

**收集方式**：
| 方式 | 示例 |
|------|------|
| 主动提供 | 填写、勾选、上传 |
| 自动采集 | SDK、API、浏览器、智能终端、传感器、摄像头 |
| 行为记录 | 浏览、交易、客服咨询、使用服务 |
| 间接获取 | 从第三方获取、从非完全公开渠道获取 |
| 关联收集 | 从与个人相关的他人账号收集 |
| 技术生成 | 大数据、AI分析、关联或生成个人信息 |

### 2.2 提供、公开个人信息

```
✓ 向其他个人信息处理者提供
✓ 向境外提供
✓ 在一定范围内或向不特定范围公开
✓ 因合并、分立、解散、被宣告破产等原因转移
```

### 2.3 处理活动发生变更

| 变更类型 | 具体情形 |
|---------|---------|
| 目的/方式变更 | 处理目的、处理方式发生变更 |
| 种类变更 | 处理的个人信息种类发生变更 |
| 接收方变更 | 因合并、分立等原因转移后，接收方变更原先处理目的、方式 |
| 公开范围变更 | 公开的范围发生变更 |
| 期限延长 | 个人信息的保存期限延长 |
| 主体变更 | 个人信息处理者的名称或联系方式发生变更 |
| 行权方式变更 | 个人行使其权利的方式和程序发生变更 |

### 2.4 其他需告知情形

```
✓ 两个及以上个人信息处理者共同决定处理目的和方式
✓ 接入需处理个人信息的其他处理者的产品或服务
✓ 处理的个人信息涉及该个人以外的其他人
✓ 处理已公开的个人信息，对个人权益有重大影响
✓ 停止运营某类业务功能或产品/服务
✓ 个人行使权利，可能对其权益产生影响
✓ 发生或可能发生个人信息泄露、篡改、丢失等安全事件
```

## 三、同意适用情形

### 3.1 需取得同意的情形

涉及上述告知情形的，个人信息处理者处理个人信息前，除有免于取得同意的情形外，需在告知的基础上取得个人同意。

### 3.2 免于取得同意的情形

#### 3.2.1 订立、履行合同所必需

**适用条件**：
- 为订立、履行个人作为一方当事人的合同
- 仅处理必要的个人信息

**典型示例**：
| 场景 | 可处理的必要信息 |
|------|-----------------|
| 提供产品/服务基本功能 | 仅必要的个人信息 |
| 订立劳动合同 | 姓名、联系方式、学历、工作履历 |
| 支付服务 | 向支付系统提供的交易信息 |
| 售后服务 | 购买记录、联系方式 |
| 产品安全运行 | 维护安全、稳定运行所必需 |

**边界**：如处理目的、方式、范围超出合同约定，则不属于该情形。

#### 3.2.2 履行法定职责或者法定义务所必需

**典型示例**：
```
✓ 反洗钱、反恐怖融资、反赌、反诈等监管要求
✓ 网络实名认证要求
✓ 网络运营管理和网络安全保护义务
✓ 差旅住宿、航空、铁路运输等行业实名身份信息
✓ 重要支付系统、证券结算系统等金融基础设施履行法定义务
✓ 国家安全、国防安全相关处理活动
✓ 配合执法或司法机关要求
✓ 犯罪侦查直接相关的调查活动
```

#### 3.2.3 为应对突发公共卫生事件或者紧急情况所必需

**典型示例**：
| 场景 | 说明 |
|------|------|
| 突发重大传染病疫情 | 有关部门、医疗机构收集处理相关信息 |
| 紧急救治 | 患者严重昏迷无法取得同意，不及时救助将威胁生命健康 |
| 自然灾害/事故灾难 | 人身安全遭受现实、紧迫威胁，为实施救助 |
| 正当防卫/紧急避险 | 使自然人生命健康、财产安全免受正在进行的不法侵害或危险 |

#### 3.2.4 为公共利益实施新闻报道、舆论监督等行为

- 在合理的范围内处理个人信息
- 新闻媒体为公共利益报道时事新闻、热点事件
- 新闻媒体为公共利益实施舆论监督

#### 3.2.5 在合理的范围内处理已公开的个人信息

**已公开信息的类型**：
```
✓ 个人自行公开且已知悉或应当知悉可被不特定用户访问
✓ 个人向有关单位提供时明确知悉将被公开
✓ 新闻媒体公开报道的信息
✓ 司法、行政机关依据法定职责公布的信息
```

**合理范围判断**：
- 个人未明确拒绝处理
- 处理未显著违背个人公开目的
- 未对个人权益造成重大影响

## 四、告知的实施

### 4.1 告知方式选择

| 方式 | 适用场景 | 特点 |
|------|---------|------|
| **一般告知** | 首次收集个人信息 | 通过个人信息保护政策，内容全面完整 |
| **增强告知** | 重大影响场景 | 弹窗等方式直接展示，凸显关键内容 |
| **即时提示** | 使用过程中 | 弹窗、浮窗、状态栏、提示条、提示音等 |

**增强告知适用场景**：
```
✓ 停止运营某类业务功能或产品/服务
✓ 涉及合并、分立、解散、被宣告破产等特殊情形
✓ 可能对个人权益产生重大影响的处理活动
✓ 产品/服务基本业务功能开启前
✓ 使用扩展业务功能或新增业务功能时
✓ 开通收集生物识别信息的业务功能
✓ 通过间接方式获取个人信息
✓ 收集不满14周岁未成年人个人信息
✓ 要求个人主动提供敏感个人信息
✓ 采用软件程序或硬件设备自动采集个人信息
```

### 4.2 告知内容要求

#### 4.2.1 收集个人信息时

**一般告知内容（5项必备）**：
```
1. 个人信息处理者的身份和联系方式等基本情况
2. 个人信息的处理目的、处理方式
3. 处理的个人信息种类、保存期限、安全措施等规则
4. 个人的权利及行使方式和程序
5. 处理个人询问、投诉的渠道和机制
```

#### 4.2.2 提供、公开个人信息时

**告知内容（4项必备）**：
```
1. 可能涉及的提供个人信息的场景
2. 接收方的身份（或姓名、联系方式）
3. 提供的具体目的、方式
4. 涉及的个人信息种类
```

#### 4.2.3 跨境传输时

**额外告知内容**：
```
1. 个人向境外接收方行使权利的具体方法
2. 个人信息出境所具备的条件：
   - 通过国家网信部门组织的评估，或
   - 取得专业机构开展的个人信息保护认证，或
   - 与接收方按照国家网信部门制定的标准合同订立了合同
3. 境外接收方的身份、联系方式
4. 处理目的、处理方式
5. 个人信息的种类、保存时间、保存区域（至少具体到国家或地区）
```

### 4.3 告知界面与展示要求

**展示渠道**：
```
✓ 个人可操作的计算机、智能终端等屏幕
✓ 公共场所大屏幕、显示屏
✓ 纸质版用户手册、说明书、设备外包装、外壳、标签
✓ 发布公告、特定范围内张贴
✓ 短信、邮件、电话等方式主动联系
```

**展示要求**：
| 要求 | 说明 |
|------|------|
| 多层次告知 | 一般告知 + 增强告知 + 即时提示 |
| 突出显示 | 敏感信息、重大影响条款、重大变化部分（加粗、增大字号、醒目颜色） |
| 禁止遮挡 | 不得通过弹出窗口遮挡、置于边缘等方式造成个人忽略 |

### 4.4 告知基本原则

| 原则 | 要求 |
|------|------|
| 公开透明 | 公布处理规则，不故意遮挡、隐藏诱导略过 |
| 有效传达 | 通过交互式界面、邮件、电话或短信等方式告知 |
| 适时充分 | 处理活动发生前或同时进行充分告知 |
| 真实明确 | 告知内容与实际情况一致，不使用笼统、宽泛表述 |
| 清晰易懂 | 符合个人语言习惯，使用通用无歧义的语言、数字、图示 |

## 五、同意的实施

### 5.1 明示同意的方式

**交互式界面**：
```
✓ 主动勾选
✓ 主动点击"同意""下一步""继续"
✓ 滑动滑块
✓ 主动发送
✓ 主动填写、上传、输入
✓ 开启可收集个人信息的API、权限、传感器开关
```

**书面形式**：
```
✓ 纸质或电子的书面声明、签字确认
✓ 电子签名
```

**行为动作**：
```
✓ 主动出示证件、刷卡、刷指纹、刷脸
✓ 回复邮件、短信息
✓ 电话录音、视频录像
```

### 5.2 同意实施要点

**合规要求**：
| 要点 | 要求 |
|------|------|
| 同页面展示 | 在展示告知内容的同一页面征求同意 |
| 显著说明 | 说明同意政策不代表所有信息一次性收集 |
| 清晰界面 | 明确各阶段需设置清晰易理解的同意操作界面 |
| 文字准确 | 不得使用含糊其辞、避重就轻、模棱两可的文字 |
| 区分事项 | 将对个人信息处理的同意与其他同意事项区分 |
| 分步获取 | 区分不同处理目的或业务功能，分步骤获取同意 |
| 区分目的 | 区分必需信息与改进服务目的信息，分别取得同意 |

**同意基本原则**：
| 原则 | 要求 |
|------|------|
| 告知一致 | 取得同意的范围不超出所告知的内容 |
| 自主选择 | 支持个人自行操作，**禁止默认勾选** |
| 时机恰当 | 收集行为发生前，同步传达告知内容时取得同意 |
| 避免捆绑 | 不强迫一次性同意多种业务功能或多个处理活动 |

## 六、单独同意的实施

### 6.1 适用情形

**法定必须单独同意的5种情形**：
```
1. 向其他个人信息处理者提供个人信息
2. 公开个人信息
3. 将公共场所图像采集、身份识别信息用于维护公共安全之外的目的
4. 处理敏感个人信息
5. 向境外提供个人信息
```

**其他可能需要单独同意的情形**：
- 实施对个人信用、绩效评定、服务质量、交易价格等产生重大直接影响的自动化决策

### 6.2 实施要点

**核心要求**：
```
✓ 在单独同意前，通过增强告知方式专门充分告知
✓ 选择明示同意方式取得单独同意
✓ 针对具体且独立的目的或业务功能
✓ 不与其他处理活动捆绑或混同
✓ 点击同意政策不构成针对具体处理活动的单独同意
```

### 6.3 各情形具体要求

#### 6.3.1 向其他个人信息处理者提供

**告知内容**：
```
✓ 接收方的身份、联系方式
✓ 处理目的、处理方式
✓ 个人信息的种类
```

**实施规则**：
| 情形 | 处理方式 |
|------|---------|
| 向单一接收方提供 | 取得单独同意后方可提供 |
| 向多个接收方同时提供 | 可在告知内容中逐一列举接收方，由个人一并同意 |

#### 6.3.2 处理敏感个人信息

**额外告知内容**：
```
✓ 处理敏感个人信息的必要性
✓ 对个人权益的影响
```

**未成年人特殊规则**：
- 处理不满14周岁未成年人个人信息 → 应取得监护人的单独同意

#### 6.3.3 向境外提供个人信息

**告知内容（6项必备）**：
```
1. 境外接收方的身份、联系方式
2. 处理目的、处理方式
3. 个人信息的种类
4. 保存时间
5. 保存区域（至少具体到国家或地区）
6. 个人向境外接收方行使相关权利的方式
```

**实施规则**：
- 将涉及出境的业务功能与其他业务功能区分
- 个人拒绝出境功能后，不影响其他业务功能正常使用

## 七、书面同意的实施

### 7.1 适用情形

**法律法规要求书面同意的情形**：
```
✓ 在广告中使用他人名义或者形象
✓ 通过指定网络通道送达某些类型的诉讼文书
✓ 采集人类遗传资源
✓ 征信机构采集个人的收入、存款、有价证券、商业保险、不动产信息和纳税数额信息
✓ 向征信机构查询个人信息
✓ 使用金融信用信息基础数据库查询个人信息
✓ 从事信贷业务功能的机构向金融信用信息基础数据库或者其他主体提供信贷信息
```

### 7.2 实施要点

**形式要求**：
```
✓ 以纸质或数字电文等有形地表现所载内容
✓ 由个人通过主动签名、签章等形式取得
✓ 明示同意需以文字形式明确表达
✓ 可在纸质界面、电子硬件载体、网页交互式界面或对话框上进行手写签名、签章
```

## 八、同意的撤回

### 8.1 撤回机制设计

**设计要求**：
| 要点 | 要求 |
|------|------|
| 明确操作 | 明确个人的何种操作意味着撤回同意 |
| 类似流程 | 采取与取得同意过程类似的方法设置撤回机制 |
| 合理颗粒度 | 可撤回某个业务功能、某类个人信息、单独同意的单独撤回 |
| 政策说明 | 在个人信息保护政策中说明撤回场景和操作方法 |

### 8.2 撤回实施要点

**核心规则**：
```
✓ 撤回范围仅限基于同意进行的处理活动，不包括其他合法性基础的处理
✓ 收到撤回请求后，可通过验证身份确认提出请求者
✓ 撤回后不得再处理相应个人信息
✓ 不影响撤回前基于同意已进行的处理活动的效力
✓ 在承诺时限内（不超过15日）完成确认和删除/匿名化操作
✓ 向个人反馈撤回同意的结果
```

**时限要求**：不超过15日

## 九、典型场景指引

### 9.1 App基本业务功能与扩展业务功能

| 功能类型 | 告知时机 | 用户拒绝后果 |
|---------|---------|-------------|
| 基本业务功能 | 首次进入App或功能开启前 | 可拒绝提供服务 |
| 扩展业务功能 | 使用功能前 | 不影响基本功能使用或服务质量 |

**基本功能实施要点**：
```
1. 首次进入时告知服务类型和功能开启/使用方式
2. 提供基本功能模式设置项
3. 首次使用时以显著方式展示开启路径
```

**扩展功能实施要点**：
```
1. 使用前告知个人信息处理规则
2. 用户拒绝后不影响基本功能
```

### 9.2 App嵌入第三方SDK

**场景一：SDK作为受托处理者**

| 义务主体 | 义务内容 |
|---------|---------|
| SDK提供者 | 向App运营者披露SDK的个人信息处理规则 |
| App运营者 | 向用户告知SDK的处理规则并取得用户同意 |
| SDK | App运营者取得同意后才可处理个人信息 |

**场景二：SDK作为个人信息处理者**

| 义务主体 | 义务内容 |
|---------|---------|
| SDK提供者 | 向App运营者、用户披露SDK的处理规则 |
| 告知界面 | App界面中或跳转至SDK业务功能界面 |
| 同意方式 | 以SDK提供者的名义向用户告知并取得同意 |

### 9.3 处理不满14周岁未成年人个人信息

**场景一：目标人群无限制**

```
→ 主动提示未成年人向监护人转达告知内容
→ 取得监护人的单独同意
```

**场景二：目标人群为不满14周岁未成年人**

```
→ 采取未成年人不易绕过的方式引导向监护人转达
→ 取得监护人的单独同意
```

**场景三：目标人群为已满14周岁未成年人**

```
→ 不设置监护人同意机制
→ 以增强告知方式明确拒绝不满14周岁未成年人使用
```

### 9.4 个性化推送场景

**告知内容**：
```
1. 实现个性化推送需处理的个人信息种类
2. 实现个性化推送的简单原理、算法说明
3. 第三方提供并由第三方直接处理的：第三方身份、所需信息种类及处理方式
4. 用户管理个性化推送功能的方式
5. 用户关闭、退出、拒绝、撤回个性化推送的方法
```

**实施要点**：
| 要点 | 要求 |
|------|------|
| 首次使用前 | 告知个性化推送机制 |
| 服务区分 | 可将个性化推送与非个性化推送服务区分 |
| 功能影响 | 用户关闭个性化推送后不影响其他功能 |

### 9.5 跨境传输场景

**告知内容（6项必备）**：
```
1. 境外接收方的身份、联系方式
2. 处理目的、处理方式
3. 个人信息的种类
4. 保存时间
5. 保存区域（至少具体到国家或地区）
6. 个人向境外接收方行使相关权利的方式
```

**实施要点**：
```
✓ 将涉及出境的业务功能与其他业务功能区分
✓ 取得个人的单独同意
✓ 个人拒绝出境功能后，不影响其他功能正常使用
```

## 十、合规检查清单

### 10.1 告知合规检查

```
□ 是否公布了处理个人信息的种类、目的、方式、安全措施等处理规则
□ 告知内容是否与实际情况一致
□ 是否使用了笼统、宽泛的表述
□ 敏感个人信息、重大影响条款是否明确标识或突出显示
□ 是否在处理活动发生前或同时进行告知
□ 告知文本是否符合个人的语言习惯
□ 是否采用多层次告知方式
□ 是否通过交互式界面、邮件、电话或短信等方式有效传达
```

### 10.2 同意合规检查

```
□ 是否在个人信息收集行为发生前取得同意
□ 是否使用默认勾选的方式取得同意（禁止）
□ 取得同意的范围是否超出所告知的内容
□ 是否采用捆绑方式强迫一次性同意多种业务功能（禁止）
□ 个人拒绝同意时，是否影响与该个人信息无关的业务功能正常使用
□ 是否在同一页面展示告知内容并征求同意
□ 是否区分不同处理目的或业务功能分步骤获取同意
```

### 10.3 单独同意合规检查

```
□ 是否在提供个人信息前取得单独同意
□ 是否在公开个人信息前取得单独同意
□ 是否在处理敏感个人信息前取得单独同意
□ 是否在向境外提供个人信息前取得单独同意
□ 单独同意是否与其他同意事项相区分
□ 是否通过增强告知方式专门告知
□ 是否针对具体且独立的目的或业务功能
```

### 10.4 撤回同意合规检查

```
□ 是否设置了便捷的撤回同意机制
□ 是否在承诺时限内（不超过15日）完成撤回请求确认
□ 是否完成删除或匿名化相关个人信息操作
□ 是否向个人反馈撤回同意的结果
□ 撤回后是否停止处理相应个人信息
□ 撤回机制颗粒度是否合理
```

## 附录：DPA起草快速参考

### 合法性基础判断流程

```
第一步：判断是否免于取得同意
├─ 订立、履行合同所必需？ → 是 → 无需同意
├─ 履行法定职责或法定义务所必需？ → 是 → 无需同意
├─ 应对突发公共卫生事件或紧急情况？ → 是 → 无需同意
├─ 为公共利益实施新闻报道、舆论监督？ → 是 → 无需同意
└─ 在合理范围内处理已公开信息？ → 是 → 无需同意

第二步：判断同意类型
├─ 向其他处理者提供？ → 单独同意
├─ 公开个人信息？ → 单独同意
├─ 处理敏感个人信息？ → 单独同意
├─ 向境外提供？ → 单独同意
├─ 法律要求书面同意？ → 书面同意
└─ 其他情形 → 一般同意
```

### 前端义务分配参考

| 场景 | 提供方义务 | 接收方义务 |
|------|-----------|-----------|
| 对外提供（一般） | 告知 + 取得同意 | 约定范围内使用 |
| 对外提供（敏感信息） | 告知 + 单独同意 + 说明必要性/影响 | 约定范围内使用 |
| 对外提供（跨境） | 告知 + 单独同意 + 出境条件说明 | 配合提供信息 |
| 对外提供（未成年人） | 告知 + 监护人单独同意 | 约定范围内使用 |
