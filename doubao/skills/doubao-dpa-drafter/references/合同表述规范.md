## 当事人描述规范

符合法律行业的严谨表达风格：
- 当事人描述示例：保险公司→"系中国境内依法设立并有效存续的保险公司"
- 公司描述示例：科技公司→"系中国境内依法设立并有效存续的有限责任公司"
- 机构描述示例：银行→"系中国境内依法设立并有效存续的银行业金融机构"

## 鉴于部分结构

鉴于部分用于简述合同背景、双方主体资格和合作前提：

```
鉴于：

1. 甲方是一家【公司性质/业务类型】的公司；

2. 乙方是一家【公司性质/业务类型】的公司；

双方已于【日期】就【合作事项】达成了【合作意向/框架协议】。

因此，双方经友好协商，达成如下协议，以资共同遵守：
```

**填写规范**：
- 公司性质：根据用户提供的信息填写，如"保险"、"科技"、"金融"等
- 日期：用户提供的合作意向达成日期，如未提供则留空
- 合作事项：简述合作内容，如"数据共享"、"数据处理服务"等
- 合作意向：根据实际情况填写，如"合作意向"、"框架协议"、"战略合作"等

**律师口吻**：使用专业、严谨的法律表述，参考上述当事人描述示例。

## 条款编号规范

**层级结构**：

| 层级 | 格式 | 示例 |
|------|------|------|
| 章 | 第X章 | 第二章 数据处理范围 |
| 条 | 第X条 | 第三条 安全保障措施 |
| 款 | X.X | 3.1 乙方应采取以下措施... |
| 项 | （一）（二） | （一）对处理系统实施访问控制... |
| 目 | 1. 2. 3. | 1. 数据加密；2. 日志审计... |

**编号规则**：
- DPA 一般不分章，直接使用"第X条"（短篇幅协议常见）
- 条文较多（超过20条）时可分章
- 同一层级编号须连续，不得跳号
- 引用时使用"本协议第X条第X款"格式

## 签署栏格式

```
（以下无正文）


甲方：【公司全称】              乙方：【公司全称】

法定代表人/授权代表：            法定代表人/授权代表：

签字：______________            签字：______________

日期：    年  月  日             日期：    年  月  日
```

**注意事项**：
- "（以下无正文）"单独占一行，位于正文最后一条之后
- 签署栏应与正文在同一页或另起一页，不得出现仅有签署栏的孤立页
- 如有附件，签署栏在附件列表之前

## 附件与引用规范

**附件标题格式**：
```
附件一：委托处理清单
附件二：安全保护措施
附件三：已批准的子处理者清单
```

**正文引用附件**：使用"详见本协议附件X《附件名称》"格式。

**引用主协议**：使用"主协议"或"《XXX服务协议》"指代，首次出现时在定义条款中明确全称。

**引用法律法规**：首次出现写全称，如"《中华人民共和国个人信息保护法》（以下简称'个保法'）"，后续使用简称。

## 常用过渡语

| 用途 | 表述 |
|------|------|
| 义务引导 | 甲方应当...；乙方有义务... |
| 权利赋予 | 甲方有权...；乙方可以... |
| 例外情形 | 但下列情形除外：...；法律法规另有规定的除外 |
| 兜底条款 | 本协议未尽事宜，双方可另行协商签订补充协议 |
| 效力衔接 | 本协议与主协议不一致的，以本协议为准 |
| 持续义务 | 本条项下义务在本协议终止后仍然有效 |
| 条件前置 | 在...的前提下；经...同意后 |
| 通知送达 | 以书面形式通知对方，通知自送达之日起生效 |
