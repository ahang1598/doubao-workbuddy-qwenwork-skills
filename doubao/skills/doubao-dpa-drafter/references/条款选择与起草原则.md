## 1. 条款选择逻辑

**条款非必选，按需选用**：

| 判断维度 | 条款选择策略 |
|---------|-------------|
| 数据敏感程度 | 敏感数据 → 强化安全、告知同意、留存删除条款；普通数据 → 可简化 |
| 跨境因素 | 有跨境 → 补充跨境条款；无跨境 → 无需写入 |
| 分包情况 | 有分包 → 补充分包控制条款；无分包 → 无需写入 |
| 双方议价能力 | 强势方 → 可提高保护条款；弱势方 → 适当简化以促成签署 |
| 合作期限 | 长期合作 → 完善终止后安排；短期项目 → 可简化 |
| 数据规模 | 大规模 → 强化安全与审计；小规模 → 可适度简化 |

## 2. 各类型协议的重点条款（仅供参考，非必选）

**A. 数据委托处理协议** - 根据实际需要选用：
- 处理指示（核心，通常需要）
- 保密与安全措施（核心，通常需要）
- 分包 / 子处理者（有分包时写入）
- 数据主体请求协助（通常需要）
- 安全事件通知（核心，通常需要）
- 删除返还（核心，通常需要）
- 审计权（根据议价能力决定）
- 跨境支持（有跨境时写入）
- 衍生数据与模型训练限制（有相关风险时写入）

**B. 数据对外提供协议** - 根据实际需要选用：
- 双方独立地位（核心，通常需要）
- 前端合法性基础分配（核心，通常需要）
- 接收方使用边界（核心，通常需要）
- 第三方转传限制（有转传风险时写入）
- 跨境安排（有跨境时写入）
- 数据主体请求协作（通常需要）
- 删除与合法留存平衡（通常需要）
- 责任对等与责任上限（根据议价能力决定）

**C. 数据共同处理协议** - 根据实际需要选用：
- 共同处理范围（核心，通常需要）
- 透明安排与统一窗口（核心，通常需要）
- 同意与合法性基础分工（核心，通常需要）
- 请求响应协作（通常需要）
- 安全基线与事件协作（通常需要）
- 后续独立使用边界（有独立使用时写入）
- 责任分配与内部追偿（通常需要）
- 退出和终止后的数据善后（长期合作时写入）

## 3. 条款精简原则

**以下情况应精简或省略条款**：
- 与当前业务场景无关的条款
- 双方无议价空间、写入也无法执行的条款
- 明显过于理想化、会导致合同难以签署的条款
- 已被主合同或其他条款覆盖的内容
- 法规未强制要求且无实际业务风险的条款

**以下情况应补充条款**：
- 模板未覆盖但实际存在的业务风险
- 行业特有或场景特有的合规要求
- 用户明确关注或反复提及的事项

## 4. 谈判校准方法

对常见商业条款，应设计分级方案而非写入单一极端值：

| 条款类型 | 过严（不推荐） | 推荐方案 | 设计思路 |
|---------|---------------|---------|---------|
| 安全事件通知 | X小时内完整书面通知 | 三级机制：(1)【2】小时内紧急初报（口头/邮件，仅报告当时已知信息，不以原因和影响完全查清为前提）；(2)【24】小时内书面初步报告（含已知影响范围、初步原因、已采取措施）；(3)调查完成后【X】个工作日内提交根因分析和整改报告 | 兼顾时效与信息完整性，符合中国法"立即"要求的操作化标准 |
| 审计权 | 无限制随时现场审计 | 例行审计每年一次 + 重大事件/监管要求下可追加 + 第三方审计报告作为替代证明 | 控制成本，保留升级路径 |
| 子处理者变更 | 必须逐一事先书面同意 | 提前X日书面通知 + 异议期X日 + 逾期无异议视为同意 | 流程可控但不阻塞业务 |
| 责任上限 | 无限责任 | 故意/重大过失不设上限 + 一般违约以年服务费的X倍为限 | 区分主观恶意与过失；例外情形仅限故意、重大过失、未经授权模型训练、擅自跨境、严重保密违约导致泄露 |
| 删除期限 | 立即彻底删除所有备份 | 主数据X日内删除 + 备份在常规清除周期内覆盖 + 法律留存义务除外 | 尊重技术现实 |
| 安全措施 | 写死扫描频率、修复时限、指定认证或加密算法 | 列出控制目标 + 声明"可采用达到同等或更高保护效果的等效措施，现有认证或审计报告可作为履约证明" + 乙方系统未知的实现细节标【待补】 | 在不了解乙方系统时避免写死无法落地的实现细节 |

注：表中"X"均为建议占位符，除非用户已明确数值，否则标注为【待补】或标明"建议值"。

**责任上限例外设计**：仅严重情形不适用普通责任上限——(1)故意违约或重大过失；(2)未经授权进行模型训练；(3)擅自跨境传输；(4)严重保密违约导致数据泄露。不得将"任何违反XX规定的行为"一概排除上限，需区分违约严重程度、是否造成实际损害、主观过错程度；轻微技术性违约（如通知迟延1天但未造成损害）不应自动触发无限责任。

**条款设计方法论**：
- **分级处理机制**：对时间敏感义务设计"初报 + 详报"分级，避免一刀切要求既快又全
- **条件触发升级**：日常义务设合理标准，重大事件/监管要求时自动升级为更严格标准
- **建议值标注**：通知期限、异议期、上限金额等谈判敏感数值，应标明"建议值"或【待补】，不得擅自写入固定数值


## 5. 单独同意操作分工（DPA条款设计参考）

当DPA涉及需要取得个人信息主体单独同意的场景时（对外提供、敏感信息、跨境），条款应明确操作分工：

| 义务类型 | 甲方（个人信息处理者） | 乙方（接收方/受托方） |
|---------|---------------------|---------------------|
| 告知义务 | 负责设计告知内容、选择告知方式、确保告知有效送达 | 提前提供告知所需信息（接收方名称、处理目的、数据种类、联系方式等） |
| 同意获取 | 负责设计同意机制（单独弹窗/独立页面）、确保符合"单独"要求 | 不得在甲方取得同意前开始处理 |
| 同意管理 | 管理同意状态、处理撤回请求 | 配合停止处理、配合删除 |
| 违反后果 | 若因甲方未取得有效同意导致违规，由甲方承担主要责任 | 若乙方明知甲方未取得同意仍开始处理，乙方承担相应责任 |

**注意**：此表为操作分工，不改变法定义务的归属。甲方的法定义务不因乙方配合不力而免除。

## 6. 合同自治边界判断

对每项拟写入DPA的条款，判断其是否受到强制性规定的约束：

| 约束层级 | 举例 | 起草要求 |
|---------|------|---------|
| **可完全约定** | 通知方式（邮件/书面/系统）、联系人指定、审计具体程序（现场/远程/第三方报告替代）、责任上限具体金额、争议解决方式 | 根据双方议价能力和商业需求自由设计 |
| **可约定但不得低于法定底线** | 审计频次（处理超1000万人的不得低于每两年一次——《管理办法》第四条）；安全措施（不得低于法律法规及国家强制性标准，应参照推荐性国标）；保存期限（遵循目的限制原则，不超过必要最短时间，行业法规有具体时限的从其规定） | 可以高于底线，不得低于底线 |
| **不可通过合同排除** | 数据主体法定权利（个保法第44-48条，法律行政法规规定的法定限制除外）；监管检查权；共同处理对数据主体的连带责任（个保法第20条第2款） | 条款中不得出现排除或限缩此类权利/责任的表述 |

**注意**：个保法第21条（委托处理）未明确规定连带责任。委托处理场景下不宜笼统引用"法定连带责任"，但委托人不得通过合同将法定义务完全转嫁给受托人，且委托人对外的责任承担不因内部约定而免除。

## 7. 跨境条款责任分配

根据跨境安排的发起方区分责任归属，不得将全部跨境合规责任不加区分地集中分配给任一方：

| 场景 | 甲方责任 | 乙方责任 |
|-----|---------|---------|
| 甲方主动出境（如选择境外供应商） | 告知、同意、PIA、选择出境路径 | 配合提供信息、签署文件、落实保护措施 |
| 乙方主动出境（如使用自身境外关联方技术支持） | 审查乙方方案合理性、配合PIA中需甲方提供的信息 | 提供境外接收方信息、落实访问控制、签署并履行跨境文件、对关联方行为承担责任、义务传导 |
| 双方共同决定出境 | 各自范围内的告知同意、PIA开展 | 各自范围内的落实义务、信息配合 |

关键规则：
- 谁发起/安排跨境，谁负责组织实施主动义务（尽调、方案设计、接收方管理）
- 甲方法定义务（告知、PIA）不因乙方主动出境而消失，但乙方应负责组织实施具体落实工作
- 乙方使用自身关联方或子处理者进行跨境时，乙方对其关联方/子处理者的行为承担责任

**重要区分**：
- 上表为合同层面的义务分工建议，不是法定责任归属的判断规则
- 法定义务（如告知、PIA、选择合规路径）始终由作为个人信息处理者的一方承担，不因合同约定而转移
- 合同中可以约定"谁发起谁负责组织实施"作为内部分工，但对外（对数据主体、对监管）的法定责任不因此改变
- 条款表述应使用"负责组织实施"而非"承担主要落实责任"，避免与法定责任归属混淆
- **"乙方主动出境"行的前提**是该出境行为已纳入合同约定范围或经甲方书面授权。若乙方未经授权擅自出境，可能被穿透认定为超出委托范围的独立处理行为，乙方须独立承担跨境法定义务，同时甲方承担监督不力的责任
