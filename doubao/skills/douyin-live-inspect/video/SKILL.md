# douyin-live-inspect video

执行脚本前遵循 [父入口的 Skill 目录定位](../SKILL.md#skill-目录定位执行脚本前必读)：以实际加载的父级 `SKILL.md` 所在目录定位 Inspect 根目录，再进入其 `video/` 子目录执行本文及视频叶子文档中的命令。因此 `node ../scripts/report-link.mjs` 相对 `video/` 解析，不从 Inspect 根目录执行。不能根据技能名称或宿主工作区猜测目录；缺文件时按父入口的安装完整性规则处理。Markdown 文档链接始终相对所在文档解析，不改变命令工作目录。

业务脚本自动记录入口和实际版本，不额外执行埋点命令。Lite 入口返回任务标识和目录；实际创建、重试和续办复用原目录，脚本自动读取标识，普通续办不记新选择。

本文件为正式版视频流程。新建视频先遵循 [父入口的版本选择](../SKILL.md#1-新建直播与视频账号入口分流)，不要因来源是附件或网络视频就跳过选择。用户选择 Lite 或正式版不可用时，按 [回退规则](../references/auth-recovery.md#正式版不可用时回退-lite) 转入 [Lite](../lite/SKILL.md) 本地视频入口：沿用可读本机文件或已物化附件；仅有网络链接时提示提供本地文件，不自动下载。已转 Lite 后不执行本文件的上传、正式任务创建与远端交付要求。



仅在项目选择与交付阶段读取对应引用。本产品支持豆包工作中的一个或多个视频附件/HTTP(S) 视频链接；直播返回 [父入口](../SKILL.md)。不提供视频库、Vid、SourceTaskId、项目管理、人工审核或媒资管理入口。

## 来源与场景

- 用户要求“质检这个视频”时，以报告就绪、对应远端控制台报告可读且链接与摘要已交付作为成功终态；只创建任务、本地 HTML 或 Chat 文字不算完整交付。
- 单视频先收集来源，按 [项目与场景选择](../references/product-boundary.md#项目与场景选择) 鉴权、查询和选择视频项目及实际场景，可分轮提供。
- 多视频先列出每个视频名称；允许为本次请求完成内置运行时启用、鉴权和只读项目/场景查询。整批使用同一所选视频项目，再建议“视频 → 项目内真实场景”映射和默认附件顺序，要求用户确认或修改。不能把推断当成确认；最终映射与顺序确认前不上传/物化、不创建任务。
- 用户确认后按计划为每个视频分别创建一次独立的单项 `TaskItems` 任务，可连续创建后统一监听，也可逐项执行。Chat 以 `1/N`、`2/N` 展示视频、场景和状态，并按确认顺序逐项交付报告；不宣称底层存在批量创建接口。
- 某一项失败时保留其他已完成结果和原顺序；确认尚未创建的项因正式版不可用而失败时按回退规则进入 Lite，不重复确认回退。已有任务失败则保留该任务，让用户选择是否继续未执行项。当前项写入结果未知时先只读核对，不重试，也不启动后续项。
- 视频项目、场景的分页、唯一选择、消歧及规则核验统一按 [项目与场景选择](../references/product-boundary.md#项目与场景选择) 执行。
- 所有视频业务命令显式传所选 `project_name`，不使用内置运行时默认项目；任务续办沿用原项目。认证、环境和错误输出遵循产品边界。

## 认证与附件准备

- 复用 inspect-entry 的账号状态与完整项目列表，不重复 auth-status 或项目查询；缺少列表才按 [项目选择](../references/product-boundary.md#项目与场景选择) 查询。业务认证失败按 [认证恢复](../references/auth-recovery.md) 续办。
- 单个视频附件必须先由豆包工作宿主上传并物化为质检服务可访问的远端 HTTP(S) URL。仅存在本地路径、file://、对象 Key 或附件占位字段不能用于创建。
- 上传由宿主完成，不臆造接口，不调用视频库，不用 curl/wget 上传、下载或持久化视频。宿主未物化或无法确认来源可访问时停止正式版创建；若已有本机可读附件，按回退规则转 Lite，否则提示提供本地文件，不自行下载。
- 远端 URL 只在受控内存中经非回显 stdin 传入 独立运行时；不在对话、命令参数、日志或临时文件回显。

## 端到端质检

1. 使用已选择且已核验的视频项目和场景；精确参数以 `node ../scripts/api.mjs --operation 'content/+video-task-create' --schema` 为准。
2. 只使用 `SourceType=4`，组装单项 `[{"Url":"<本次视频地址>"}]`，作为 JSON stdin 的 `task_items` 数组提交；按 [创建任务](references/video-task-create.md) 先 dry-run，参数完整后只创建一次。
3. 保存返回的唯一任务编号，以及 `meta.environment`、`meta.profile`、`meta.account_id`；后续查询、结束和报告请求都显式传回原 `environment`、`profile`、`account_id`。同名 profile 更换账号后不得续办原任务。结果未知或超时不得重放，先只读核对；失败不宣称已完成质检。
4. `+video-task-get` 有界轮询：最多 10 分钟，每 30 秒一次。任务完成后用 `content/+video-report-get` 读取服务端报告并提取结论与必要证据；报告尚未就绪时按 [报告](references/video-report-get.md) 有界等待，不生成本地质检 HTML，不启动本地服务。
5. 报告就绪后输出中文质检结论、任务名称、中文场景、逐条违规内容（类别、时间、证据、结论）。按 [豆包工作交付](../references/doubao-delivery.md) 运行 `node ../scripts/report-link.mjs` 生成并核验本次视频控制台报告链接，在 Chat 交付“打开视频质检报告”链接、结论与证据。项目与任务定位仅保留在本次报告链接中，不展示内部场景 ID、来源地址或原始响应。
6. 核实每项质检报告的就绪状态和结论；尚未就绪、读取失败或远端页面无法打开时如实说明并保留同任务续办信息，不编造结果或声称完整交付。质检交付不依赖 JSON 上传。视频与直播使用同一新版控制台报告页面和样式，按类型展示不同内容；不打开旧任务详情页或直播远端操作台。

## 报告与任务管理

- [报告](references/video-report-get.md) 缺字段写“未返回”；只有明确空违规集合才写“未识别到违规内容”。TASK_RUNNING、TASK_FAILED、REPORT_NOT_READY 分别解释，不把空报告当通过。
- 到达等待上限时返回当前状态和同任务续办信息，不算报告交付成功，不无限轮询。
- 报告形式与失败处理统一遵循 [豆包工作交付](../references/doubao-delivery.md#直播与视频质检远端报告)。
- 查询指定视频任务前先核验可访问性和类型。用户明确要求结束检测时按 [结束任务](references/video-task-end.md) 核对状态、dry-run 并停在本次 exit 10 确认门禁，确认后只执行一次；未知结果不重试。
- 不提交人工审核结论，不开放 WARNING/INTERRUPTION 等操作，不用相邻能力兜底。

### 批量流程埋点

用户确认多个视频的批次计划后、首项创建前，沿用入口返回的批次目录执行 `node ../scripts/inspect-entry.mjs --kind video --mode formal --task-state not_created --batch-dir <原目录> --expected-tasks <确认的视频数>`（1–100）。这会更新同一流程的预期项数，不重建流程；首项创建后不改数量。所有项及交付确认均继承返回的 execution_env，不能给每项另建流程。

该批次中每条正式版业务命令使用进程级环境变量 `INSPECT_TELEMETRY_WORKFLOW=video_batch node ../scripts/api.mjs ...`（报告入口同样设置）。仅本批次命令设置，不全局 export，不用于单视频任务或 dry-run / 确认计划。参数仍通过 stdin 传递；不把视频地址或任务名称写入环境变量。

内部查询按需查 [视频接口索引](references/api-index.md)，精确业务参数通过对应操作的 --schema 核验。
