# 浏览器补充取流方案

## 定位与启用条件

抖音主方案仍是匿名页面解析，正式版受阻且确认未创建任务时才尝试浏览器补充路径。小红书先用宿主浏览器打开实际直播页、提取候选再启动；没有候选时运行时仍支持匿名解析。Lite 已启动任务按 source_refresh 沿原目录补充。创建结果未知时先只读核对任务，不能以补充取流为由重建。

创建脚本支持通过非回显 stdin 接收可选 `browser_source`。抖音仍先匿名解析；小红书正式版校验房间和 CDN 候选后提交服务端，避免匿名接口消耗候选有效期。候选通过后复用原创建流程；不得临时改写脚本或绕过包装脚本直接创建任务。

## 在豆包工作侧边栏打开页面

- 按 [统一宿主浏览器](doubao-delivery.md#统一宿主浏览器) 复用豆包工作内置侧边栏及当前会话，同一直播间优先复用已有标签。不使用系统默认浏览器、独立 Chrome、无痕窗口或另起调试浏览器作为兜底。
登录通过 `scripts/login.mjs` 发起，脚本不自动打开浏览器；授权链接在对话中交付，由用户手动点击。这里的浏览器取流不替代登录流程。
- 打开用户本次提供的直播链接，核对页面对应的直播间。若没有侧边栏打开能力或资源观测能力，说明当前宿主无法完成浏览器补充取流，保留原任务参数，不声称已经启用。
- 只有页面实际出现验证控件时才请用户接管，按 [抖音人工验证](task-create.md#抖音人工验证) 等待；正常播放且没有控件时直接检查媒体资源，不要求用户寻找滑块或反复刷新。

Lite 抖音任务收到 `source_refresh` 时，按下方步骤从同一详情页取流，执行回执的 `resume --task-dir <原目录> --input-file <私有文件>`。原 worker 接收新地址并继续拉流。短链无法核对到同一详情页时由原任务继续匿名重试。

## 获取候选媒体地址

1. 使用宿主正式提供的页面资源清单或网络请求观测能力。支持请求监听时在播放前开始监听；支持资源清单时读取已经加载的资源。工具和字段以宿主当前能力为准，不假设存在固定工具名。
2. 在当前页面实际加载的资源中筛选 FLV 等媒体请求。媒体可能以 `fetch` 或 `xhr` 加载，不能只筛选 `video` 类型；`video.src` 为空或为 `blob:` 时，不能把它当成后端拉流地址。
3. 同时读取当前直播间可见标题、主播名称及浏览器页面标题，分别传入 `room_title`、`account_name`、`page_title`。优先使用直播间自身的标题，不能拿商品标题、推荐直播标题或主播昵称冒充直播间标题。核对直播间及当前播放器，排除广告、推荐直播和预加载视频。出现多个无法确定归属的候选时不任意选择。HTML 中的 `LIVE_SSR_DATA_ID` 可能只有页面配置，不能假设其中一定包含流地址。
4. 保留完整服务端签名参数；只在运行时传递候选地址，不在对话、日志或报告中回显完整签名 URL，不导出 Cookie、Token 或浏览器登录态。不得通过复制认证材料构造新的请求来替代正常页面播放。

## 独立验证与接入要求

- 在获授权的独立运行环境短时读取候选地址，不携带浏览器 Cookie。限制读取时长、大小和跳转次数，校验地址与跳转目标；HTTP 200、文件后缀或浏览器播放成功均不足以证明后端可用。
- 检查实际媒体内容与音视频轨道，记录脱敏结果：HTTP 状态、读取字节数、编码和分辨率。当前匿名解析器仅支持 FLV；发现 HLS 或其他协议不能默认认为创建链路支持。
- 本机独立进程成功，只能说明本机可读。线上使用前仍需确认质检后端出口可访问，且支持对应音视频编码；不要将本机验证描述为线上后端验证。
- 创建脚本会核对本次页面、采集时间、候选地址及有效期，并进行有限的无 Cookie 媒体探测；失败时不进入 dry-run 或创建。探测通过不代表完成解码或线上后端出口验证。不得绕过检查，也不得将任意用户输入的拉流 URL 当作浏览器观测结果。
- 验证或接入能力缺失时保留原上下文，说明当前停在“候选地址已获取”或“独立拉流已验证”阶段，不声称已创建或开始检测。需要会话认证才能读取的地址不自动复制凭证重试。

## 创建脚本接入

匿名取流失败且确认未创建任务后，保留原业务参数，在豆包工作侧边栏取得候选，通过原 `scripts/douyin-task-create.mjs` 的非回显 stdin 增加：

```json
{
  "browser_source": {
    "page_url": "https://live.douyin.com/<本次直播间编号>",
    "captured_at": 1800000000000,
    "room_title": "<当前直播间可见标题>",
    "account_name": "<当前主播名称，可选>",
    "page_title": "<当前浏览器页面标题，可选>",
    "stream_url": "<浏览器实际观测的完整 FLV 地址，仅在运行时传递>"
  }
}
```

- 上例仅展示附加字段，仍需传入原有 `douyin_url`、项目、场景、环境和 `dashboard_mode` 等参数；`captured_at` 必须替换为实际采集时间（Unix 毫秒），有效期为两分钟。
- `page_url` 是观测媒体的页面地址，规范化后必须与 `douyin_url` 一致。短链跳转后无法建立这一对应关系时停止，不猜测房间映射。签名至少剩余 60 秒；当前浏览器路径只接受抖音 CDN 的 FLV。
- 默认任务名称依次取用户明确指定的 `task_name`、`room_title`、去掉站点后缀的 `page_title`；都缺失时才使用时间戳名称。不要主动给 `task_name` 填时间戳或通用名称覆盖直播间标题。观测时应主动补齐标题；空缺时不要猜测。原直播间标题及主播名称同时保存在创建请求的来源信息中。
- `browser_source` 来自宿主观测结果，脚本校验只能检查参数一致性，不能证明观测真实性；Agent 不得伪造采集时间、页面或地址。
- 抖音再次运行仍先尝试匿名解析，匿名恢复则优先使用其结果，不探测浏览器候选。认证、业务参数错误不进入补充取流。
- `INVALID_BROWSER_SOURCE` 表示候选不匹配、无效或过期；`BROWSER_STREAM_UNAVAILABLE` 表示独立媒体探测失败。保留原参数，说明本次未创建任务，不自动循环创建。
- 脚本不会自行打开浏览器；仍由 Agent 使用豆包工作侧边栏完成观测和传参。登录脚本始终不自动打开浏览器。

## 小红书补充取流

本节只负责把直播页面解析为 `browser_source`，不构成独立质检流程。先按主入口确定版本和任务目录；候选交接后，Lite 立即回到 [直播主流程](../lite/SKILL.md#直播主流程)，正式版回到 [正式流程](formal-workflow.md)。不调用参考 Skill 的录制、转写、判定或报告脚本，也不根据浏览器画面直接给出质检结论。

小红书先执行下方 CDP 取流脚本，调试端口不可用时使用宿主浏览器接口；短链须在浏览器中打开并核对最终详情页，单次 HTTP 失败不能判为链接失效。正式版输入 `live_page_url`，Lite 输入 `source`，浏览器由宿主提供，不由脚本启动。打开本次实际详情页，确认播放器归属和播放状态；从实际媒体请求或该页直播信息响应的 `pull_config.streams` 中读取服务端提供的 FLV 候选。优先选择兼容的 H.264 候选，不根据房间号、编码后缀或 CDN 规律拼接地址，不把 `blob:` 当作拉流 URL。

**先确认本房间的直播状态。** CDP 返回 `XHS_NOT_LIVE`、页面观察返回 `status: "not_live"`，或宿主在本次详情页的播放器里清楚看到“直播已结束”“主播已下播”等明确提示时，告知用户该场直播已结束，停止补流。新请求到此结束，不创建实时任务或等待报告。已有 Lite 任务正在补流时，把 CDP 错误回执里的 `browser_source` 原样装入同名字段，写入私有 JSON 文件并执行原任务的 `resume --task-dir <原目录> --input-file <文件>`。使用宿主页面观察时交回当前详情页实际的 `page_url`、`captured_at` 和 `status: "not_live"` 三个字段。按原任务状态完成收尾。忽略页面残留的 FLV；累计点赞、聊天文字、登录提示、播放器黑屏、接口失败或没有 FLV 都不能单独判为停播。

沿用上面的 `browser_source` 字段，将 `page_url` 换为本次小红书详情页，补齐当前 `captured_at`、真实标题及完整 `stream_url`。候选保留完整查询参数，不导出 Cookie、Token 或登录态；仅在私有输入中临时传递，不贴入对话、报告或日志。短链必须由解析器验证跳转到同一详情页，不能仅凭手填 page_url 建立关联。页面需要登录或验证码时交用户在浏览器完成。

候选仅允许小红书 CDN 的 FLV；正式版由火山拉流，Lite 在采集端探测。候选时间窗为两分钟；未知停播状态不当作已结束。宿主没有资源观测能力、短链跳转不可验证时说明具体阻塞，不绕过校验。正式版仍需实际后端产生检测内容才算开始质检。

### CDP 取流代码（优先）

使用已有本机 Chrome/Chromium 的调试端口（默认 `127.0.0.1:9222`），不启动新浏览器或复制登录配置。先从 Inspect 根目录运行：

```bash
# 正式版
python3 scripts/xiaohongshu-cdp-source.py --formal --url "<本次完整直播链接>" --output "<私有目录>/browser-source.json"

# Lite
python3 scripts/xiaohongshu-cdp-source.py --url "<本次完整直播链接>" --output "<私有目录>/browser-source.json"
```

按已选版本执行对应的一条命令。正式版取得本房间候选后直接交接，Lite 在本机探测媒体。Python 3.10+；返回 `CDP_DEPENDENCY_MISSING` 时用同一 Python 安装 `websocket-client==1.9.2` 后重试，无需 requests 或 Node。只有已知宿主提供其他本机调试端口时才传 `--port`，不扫描端口。脚本复用匹配直播标签，否则在同一浏览器中新建标签；通过 CDP 导航、等待页面，收集 Network.requestWillBeSent 中的 FLV，并执行资源和内嵌脚本提取，按当前房间筛选候选，默认总预算45秒；未取得可用候选时，在原预算内最多强制刷新一次并重新监听，不续期。不会录制、转写或判定，也不会输出完整流地址。输出文件独占创建，不覆盖已有候选。

返回成功后，Lite 将文件中的 `browser_source` 合入原 start 输入；补流直接执行原回执的 `resume --task-dir <原目录> --input-file <文件>`。正式版将同一字段合入原创建输入。随后立即回到各版本原质检流程，交接后删除临时文件。浏览器短链导航不替代运行时的短链与房间校验。

`CDP_UNAVAILABLE` 表示调试连接不可用，`CDP_COMMAND_FAILED` 表示浏览器拒绝命令，`CDP_NAVIGATION_FAILED` 表示导航失败，`CDP_TIMEOUT` 表示预算内未取得并验证候选，均不能据此判断停播。`CDP_TIMEOUT` 不表示端口不可用；脚本已包含一次刷新恢复，不重复运行同一脚本或临时编写 CDP/Vue 排查代码，立即沿下方宿主路径取流并在原期限内交接。端口不可用时转下方宿主浏览器路径，不自动启动带调试参数的第二个浏览器。两条路径都不可用时交付具体阻塞。

### 豆包内置浏览器取流（正式版与 Lite 共用）

先读取当前豆包宿主实际提供的浏览器 Skill 和工具说明，按其声明的执行器、参数及返回格式操作。`browser-use`、`browser-use-automation-mac` 仅为可能的名称，不假设固定存在 `plane="bu"`、`aha_browser_use` 或 `bu.js()`。先确认能复用本次直播标签，再分别确认页面 JavaScript 执行和网络资源观测能力；能打开页面或截图不代表能执行提取脚本。会话失效仅按宿主文档恢复。复用宿主原会话，不另起系统 Chrome、调试浏览器或读取认证材料；能力缺失时说明具体缺失的是页面执行还是网络观测，不把它归为直播流不可用。

播放前按宿主能力启用网络观测；页面打开后等待播放器实际加载，未就绪时在当前补流期限内有界等待（原参考脚本默认等待22秒），不把初次空列表当作失败。用宿主声明的网络观测接口（若提供）读取当前页真实请求，在内存中只保留 `.xhscdn.com` 的 FLV URL；该接口会消费缓冲，不要反复空读。不能仅筛选 video 类型，FLV 常由 fetch/xhr 加载。请求记录的结构以当前工具返回为准，不输出完整记录、请求头或响应正文。网络观测不可用或为空时仍执行页面提取，不因某一种观测能力缺失提前退出。读取本包 `scripts/xiaohongshu-browser-observation.js` 的完整文本，作为页面代码传给宿主实际支持的页面 JavaScript 执行接口（参数格式遵循宿主文档）。脚本读取当前页资源和内嵌脚本中的真实地址，处理 `\/`、`\u0026` 转义，只保留本房间的小红书 CDN FLV，返回 `page_url`、`captured_at`、`page_title`、`media_urls`。返回对象时直接保存、返回 JSON 字符串时先解析，不能把对象转成 `[object Object]`；解析失败说明宿主返回格式异常，不用正则从任意工具文本拼造观察结果。结果直接保存到私有观察文件，不回显完整地址。它只提取候选，不代表已开播或媒体探测通过；不得在 Node 中执行页面脚本，也不启动独立 Chrome/CDP。

长连接尚未结束时可能不在 resource timing 中，空列表不是停播证据。此时按宿主文档启用当前标签的网络观测，再刷新本次直播页一次、确认播放后读取请求；不凭空猜测 CDP 参数。网络列表与页面读取之间不可切换房间。仅将本次页面的 URL、实际观测时间、标题和筛选后的 `media_urls` 保存为私有观察文件；从直播信息响应选候选时仅提取 `pull_config.streams` 的真实 URL，按已验证的 EF4 优先排列，不保存完整接口响应。

Lite 直接将本次观测的 `page_url`、`captured_at` 和一个已确认属于本房间的完整 FLV URL（作为 `stream_url`）写入私有 JSON 文件，结构为 `{"browser_source":{...}}`，可附 `page_title`。沿下方 start/resume 路径提交，由原 Python worker 完成房间、时效校验和独立媒体探测；Lite 到此直接提交，不运行下面的正式版 Node 准备脚本。不能确定候选归属时停止交接，不猜测地址。

仅正式版从 Inspect 根目录运行以下准备脚本，筛选观察文件中的候选：

```bash
node scripts/xiaohongshu-browser-source.mjs --output "<私有目录>/browser-source.json" < "<私有目录>/observation.json"
```

脚本按规范化房间筛选实际观测的 `/live/<房间ID>[_后缀].flv`，去重但不改写参数，交由正式质检服务拉流。未知路径不会猜测归属。输出文件独占创建，含标准 `browser_source`；stdout 只给状态，不回显流地址。容器探测不等于实际解码，仍须核验首媒体和字幕。观察文件及输出文件使用后删除；不得纳入报告、日志或发布包。

- Lite 未启动：将输出的 `browser_source` 合入原 start 输入，`source` 保持直播详情页；已启动且仍在窗口内：直接将输出文件交 `resume --task-dir <原目录> --input-file <输出文件>`。首次启动后按 [Lite 交付](../lite/references/delivery.md) 在对话中交付工作台入口，不主动打开；已启动任务补流复用已交付的本地入口，不重复交付或新建工作台标签。入口未交付、交付失败及云电脑快照仍按该交付规则处理。随后持续执行 review-next／review-submit 和 next_action；只有实际媒体和字幕产生才称采集成功，补流不改变原判定合同。
- 正式版：把输出的 `browser_source` 合入原创建输入，保持 `live_page_url` 和原项目参数，沿原创建脚本执行；创建结果未知不重放。
- Lite 单轮补流超时：查询原任务 status。已录到媒体且仍在重连时，按下一轮回执提交新观测的候选；已停止、终止或冻结时沿原任务收尾。用户明确提出新检测时使用新任务目录。
- 用户直接提供 FLV：正式版传 `live_pull_url`，Lite 传 `source`，沿已有直播流程。完整保留查询参数，不伪造为浏览器观测，不要求重新寻找同一地址；直流地址失效时不能凭后缀生成备用流。

## B 站补充取流

B 站先匿名解析，接口受限或全部 CDN 不可读且尚未创建正式任务时使用本节；Lite 按原任务 `source_refresh` 回执补流。复用宿主当前浏览器打开原链接，短链先跳转到实际详情页，确认房间及播放状态。只有页面实际要求验证时才交用户完成。

在该直播标签执行随包 `scripts/bilibili-browser-observation.js`。脚本在浏览器内请求房间及播放信息，核对真实房间归属，返回 `page_url / captured_at / page_title / media_urls`；不读取或导出 Cookie。接口仍受限时，可用宿主网络响应观测取得同房间播放响应里的非 DRM AVC FLV，按同样字段交接。不能仅从资源列表任取 `.flv`，也不能从房间号猜 CDN 路径；没有归属证据就说明无法完成取流。

房间初始化或同一真实房间的播放接口明确返回 `live_status=0` 时，页面观察返回 `status: "not_live"`。新请求提示该房间未开播或已下播。已有 Lite 任务按原补流回执执行 `resume`，私有输入文件的 `browser_source` 只含页面观察中的 `page_url`、`captured_at` 和 `status: "not_live"`。可直接采用 Node 助手 `BILI_NOT_LIVE` 回执中的同名字段。轮播、访问限制、播放失败和弹幕不作为停播依据。

有 Node 时，将完整观测结果经非回显 stdin 交给 `node scripts/bilibili-browser-source.mjs --output <私有目录>/browser-source.json`，脚本逐个独立探测候选并独占创建文件。Lite 不依赖 Node：将一个观测候选整理为 `{"browser_source":{"page_url":"<观测的详情页>","captured_at":<原观测毫秒时间>,"stream_url":"<完整候选>"}}` 私有文件，由原 worker 校验并探测；候选失败后在原补流期限内换下一个，不重启 worker、不刷新采集时间冒充新观测。

正式版将文件的 `browser_source` 合入原创建输入，Lite 初次启动合入原 start 输入，补流执行原 `resume --input-file` 回执。短链仍须运行时验证跳转；候选详情页须与解析后的原页面一致，房间别名不能自行替换。交接后删除临时文件，完整流地址不贴入对话或报告。

候选有效期两分钟，必须无需 Cookie、Referer 即可独立读取 FLV 音视频。浏览器可播放但所有候选均未通过独立探测时，保留正式版并提示提供可访问的流地址。不得修改 hosts、替换 DNS 或跳过地址校验；Lite 单轮期限届满后查原任务 status；已录到媒体且仍在重连时继续跟随补流回执，终止后收尾。宿主无法执行脚本或读取播放响应时明确说明阻塞。当前浏览器脚本的宿主兼容性及正式云端出口仍需现场验证，不能以本地探测替代。
