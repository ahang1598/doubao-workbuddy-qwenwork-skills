# 浏览器补充取流方案

## 定位与启用条件

主方案仍是 `douyin-task-create.mjs` 调用匿名页面解析器。只有匿名取流受阻且确认未创建任务时，才尝试浏览器补充路径；匿名成功时不启动浏览器。创建结果未知时先只读核对任务，不能以补充取流为由重建。

创建脚本现支持通过非回显 stdin 接收可选 `browser_source`。仍先匿名解析，只有来源获取失败才校验并探测浏览器候选。候选通过后复用原创建流程；不得临时改写脚本或绕过包装脚本直接创建任务。

## 在豆包工作侧边栏打开页面

- 按 [统一宿主浏览器](doubao-delivery.md#统一宿主浏览器) 复用豆包工作内置侧边栏及当前会话，同一直播间优先复用已有标签。不使用系统默认浏览器、独立 Chrome、无痕窗口或另起调试浏览器作为兜底。
登录通过 `scripts/login.mjs` 发起，脚本不自动打开浏览器；授权链接在对话中交付，由用户手动点击。这里的浏览器取流不替代登录流程。
- 打开用户本次提供的抖音直播链接，核对页面对应的直播间。若没有侧边栏打开能力或资源观测能力，说明当前宿主无法完成浏览器补充取流，保留原任务参数，不声称已经启用。
- 只有页面实际出现验证控件时才请用户接管，按 [抖音人工验证](task-create.md#抖音人工验证) 等待；正常播放且没有控件时直接检查媒体资源，不要求用户寻找滑块或反复刷新。

## 获取候选媒体地址

1. 使用宿主正式提供的页面资源清单或网络请求观测能力。支持请求监听时在播放前开始监听；支持资源清单时读取已经加载的资源。工具和字段以宿主当前能力为准，不假设存在固定工具名。
2. 在当前页面实际加载的资源中筛选 FLV 等媒体请求。媒体可能以 `fetch` 或 `xhr` 加载，不能只筛选 `video` 类型；`video.src` 为空或为 `blob:` 时，不能把它当成后端拉流地址。
3. 同时读取当前直播间可见标题、主播名称及浏览器页面标题，分别传入 `room_title`、`account_name`、`page_title`。优先使用直播间自身的标题，不能拿商品标题、推荐直播标题或主播昵称冒充直播间标题。核对直播间及当前播放器，排除广告、推荐直播和预加载视频。出现多个无法确定归属的候选时不任意选择。HTML 中的 `LIVE_SSR_DATA_ID` 可能只有页面配置，不能假设其中一定包含流地址。
4. 保留完整服务端签名参数；只在运行时传递候选地址，不在对话、日志或报告中回显完整签名 URL，不导出 Cookie、Token 或浏览器登录态。不得通过复制认证材料构造新的请求来替代正常页面播放。

## 独立验证与接入要求

- 在获授权的独立运行环境短时读取候选地址，不携带浏览器 Cookie。限制读取时长、大小和跳转次数，校验地址与跳转目标；HTTP 200、文件后缀或浏览器播放成功均不足以证明后端可用。
- 检查实际媒体内容与音视频轨道，记录脱敏结果：HTTP 状态、读取字节数、编码和分辨率。当前匿名解析器仅支持 FLV；发现 HLS 或其他协议不能默认认为创建链路支持。
- 本机独立进程成功，只能说明本机可读。线上使用前仍需确认质检后端出口可访问，且支持对应音视频编码；不要将本机验证描述为线上后端验证。
- 包装脚本通过 `runtime/browser-stream.mjs` 绑定本次直播页面与采集时间，检查抖音 CDN 地址及签名有效期，在当前运行环境执行无 Cookie 探测。最多 12 秒、1 MB、3 次跳转，校验 DNS 与跳转目标并检查完整 FLV 音频和视频标签；这不是解码验证，也不是线上后端出口验证。失败时不进入 dry-run 或创建。不得将任意用户输入的拉流 URL 当作浏览器观测结果。
- 验证或接入能力缺失时保留原上下文，说明当前停在“候选地址已获取”或“独立拉流已验证”阶段，不声称已创建或开始检测。需要会话认证才能读取的地址不自动复制凭证重试。

## 创建脚本接入

匿名取流失败且确认未创建任务后，保留原业务参数，在豆包工作侧边栏取得候选，通过原 `scripts/douyin-task-create.mjs` 的非回显 stdin 增加：

```json
{
  "browser_source": {
    "page_url": "https://live.douyin.com/<本次直播间编号>",
    "captured_at": 1800000000000,
    "room_title": "<当前直播间可见标题>",
    "account_name": "<当前主播名称，可选>",
    "page_title": "<当前浏览器页面标题，可选>",
    "stream_url": "<浏览器实际观测的完整 FLV 地址，仅在运行时传递>"
  }
}
```

- 上例仅展示附加字段，仍需传入原有 `douyin_url`、项目、场景、环境和 `dashboard_mode` 等参数；`captured_at` 必须替换为实际采集时间（Unix 毫秒），有效期为两分钟。
- `page_url` 是观测媒体的页面地址，规范化后必须与 `douyin_url` 一致。短链跳转后无法建立这一对应关系时停止，不猜测房间映射。签名至少剩余 60 秒；当前浏览器路径只接受抖音 CDN 的 FLV。
- 默认任务名称依次取用户明确指定的 `task_name`、`room_title`、去掉站点后缀的 `page_title`；都缺失时才使用时间戳名称。不要主动给 `task_name` 填时间戳或通用名称覆盖直播间标题。观测时应主动补齐标题；空缺时不要猜测。原直播间标题及主播名称同时保存在创建请求的来源信息中。
- `browser_source` 来自宿主观测结果，脚本校验只能检查参数一致性，不能证明观测真实性；Agent 不得伪造采集时间、页面或地址。
- 再次运行仍先尝试匿名解析，匿名恢复则优先使用其结果，不探测浏览器候选。认证、业务参数错误不进入补充取流。
- `INVALID_BROWSER_SOURCE` 表示候选不匹配、无效或过期；`BROWSER_STREAM_UNAVAILABLE` 表示独立媒体探测失败。保留原参数，说明本次未创建任务，不自动循环创建。
- 脚本不会自行打开浏览器；仍由 Agent 使用豆包工作侧边栏完成观测和传参。登录脚本始终不自动打开浏览器。

## 已验证范围

对直播间 `554486823301`，曾通过浏览器页面资源清单发现 `fetch` 类型 FLV 请求，并在本机无 Cookie 的独立进程中读取 512 KB 媒体，识别到 AAC 音频与 HEVC 视频（480×852）。此结果是一次本机验证，不代表临时地址长期有效、豆包侧边栏已具备同等资源观测能力，或线上后端已经支持。
