# 浏览器补充取流方案

## 定位与启用条件

主方案仍是 `douyin-task-create.mjs` 调用匿名页面解析器。正式版只有匿名取流受阻且确认未创建任务时才尝试浏览器补充路径；Lite 已启动任务按 source_refresh 沿原目录补充。用户明确要求从已打开页面提取流时可先观测再启动；匿名成功时不额外启动浏览器。创建结果未知时先只读核对任务，不能以补充取流为由重建。

创建脚本支持通过非回显 stdin 接收可选 `browser_source`。仍先匿名解析，只有来源获取失败才校验并探测浏览器候选。候选通过后复用原创建流程；不得临时改写脚本或绕过包装脚本直接创建任务。

## 在豆包工作侧边栏打开页面

- 按 [统一宿主浏览器](doubao-delivery.md#统一宿主浏览器) 复用豆包工作内置侧边栏及当前会话，同一直播间优先复用已有标签。不使用系统默认浏览器、独立 Chrome、无痕窗口或另起调试浏览器作为兜底。
登录通过 `scripts/login.mjs` 发起，脚本不自动打开浏览器；授权链接在对话中交付，由用户手动点击。这里的浏览器取流不替代登录流程。
- 打开用户本次提供的抖音直播链接，核对页面对应的直播间。若没有侧边栏打开能力或资源观测能力，说明当前宿主无法完成浏览器补充取流，保留原任务参数，不声称已经启用。
- 只有页面实际出现验证控件时才请用户接管，按 [抖音人工验证](task-create.md#抖音人工验证) 等待；正常播放且没有控件时直接检查媒体资源，不要求用户寻找滑块或反复刷新。

## 获取候选媒体地址

1. 使用宿主正式提供的页面资源清单或网络请求观测能力。支持请求监听时在播放前开始监听；支持资源清单时读取已经加载的资源。工具和字段以宿主当前能力为准，不假设存在固定工具名。
2. 在当前页面实际加载的资源中筛选 FLV 等媒体请求。媒体可能以 `fetch` 或 `xhr` 加载，不能只筛选 `video` 类型；`video.src` 为空或为 `blob:` 时，不能把它当成后端拉流地址。
3. 同时读取当前直播间可见标题、主播名称及浏览器页面标题，分别传入 `room_title`、`account_name`、`page_title`。优先使用直播间自身的标题，不能拿商品标题、推荐直播标题或主播昵称冒充直播间标题。核对直播间及当前播放器，排除广告、推荐直播和预加载视频。出现多个无法确定归属的候选时不任意选择。HTML 中的 `LIVE_SSR_DATA_ID` 可能只有页面配置，不能假设其中一定包含流地址。
4. 保留完整服务端签名参数；只在运行时传递候选地址，不在对话、日志或报告中回显完整签名 URL，不导出 Cookie、Token 或浏览器登录态。不得通过复制认证材料构造新的请求来替代正常页面播放。

## 独立验证与接入要求

- 在获授权的独立运行环境短时读取候选地址，不携带浏览器 Cookie。限制读取时长、大小和跳转次数，校验地址与跳转目标；HTTP 200、文件后缀或浏览器播放成功均不足以证明后端可用。
- 检查实际媒体内容与音视频轨道，记录脱敏结果：HTTP 状态、读取字节数、编码和分辨率。当前匿名解析器仅支持 FLV；发现 HLS 或其他协议不能默认认为创建链路支持。
- 本机独立进程成功，只能说明本机可读。线上使用前仍需确认质检后端出口可访问，且支持对应音视频编码；不要将本机验证描述为线上后端验证。
- 创建脚本会核对本次页面、采集时间、候选地址及有效期，并进行有限的无 Cookie 媒体探测；失败时不进入 dry-run 或创建。探测通过不代表完成解码或线上后端出口验证。不得绕过检查，也不得将任意用户输入的拉流 URL 当作浏览器观测结果。
- 验证或接入能力缺失时保留原上下文，说明当前停在“候选地址已获取”或“独立拉流已验证”阶段，不声称已创建或开始检测。需要会话认证才能读取的地址不自动复制凭证重试。

## 创建脚本接入

匿名取流失败且确认未创建任务后，保留原业务参数，在豆包工作侧边栏取得候选，通过原 `scripts/douyin-task-create.mjs` 的非回显 stdin 增加：

```json
{
  "browser_source": {
    "page_url": "https://live.douyin.com/<本次直播间编号>",
    "captured_at": 1800000000000,
    "room_title": "<当前直播间可见标题>",
    "account_name": "<当前主播名称，可选>",
    "page_title": "<当前浏览器页面标题，可选>",
    "stream_url": "<浏览器实际观测的完整 FLV 地址，仅在运行时传递>"
  }
}
```

- 上例仅展示附加字段，仍需传入原有 `douyin_url`、项目、场景、环境和 `dashboard_mode` 等参数；`captured_at` 必须替换为实际采集时间（Unix 毫秒），有效期为两分钟。
- `page_url` 是观测媒体的页面地址，规范化后必须与 `douyin_url` 一致。短链跳转后无法建立这一对应关系时停止，不猜测房间映射。签名至少剩余 60 秒；当前浏览器路径只接受抖音 CDN 的 FLV。
- 默认任务名称依次取用户明确指定的 `task_name`、`room_title`、去掉站点后缀的 `page_title`；都缺失时才使用时间戳名称。不要主动给 `task_name` 填时间戳或通用名称覆盖直播间标题。观测时应主动补齐标题；空缺时不要猜测。原直播间标题及主播名称同时保存在创建请求的来源信息中。
- `browser_source` 来自宿主观测结果，脚本校验只能检查参数一致性，不能证明观测真实性；Agent 不得伪造采集时间、页面或地址。
- 再次运行仍先尝试匿名解析，匿名恢复则优先使用其结果，不探测浏览器候选。认证、业务参数错误不进入补充取流。
- `INVALID_BROWSER_SOURCE` 表示候选不匹配、无效或过期；`BROWSER_STREAM_UNAVAILABLE` 表示独立媒体探测失败。保留原参数，说明本次未创建任务，不自动循环创建。
- 脚本不会自行打开浏览器；仍由 Agent 使用豆包工作侧边栏完成观测和传参。登录脚本始终不自动打开浏览器。

## 小红书补充取流

正式版输入 `live_page_url`，浏览器仍由宿主提供，不由脚本启动。打开本次实际详情页，确认播放器归属和播放状态；从实际媒体请求或该页直播信息响应的 `pull_config.streams` 中读取服务端提供的 FLV 候选。优先选择兼容的 H.264 候选，不根据房间号、编码后缀或 CDN 规律拼接地址，不把 `blob:` 当作拉流 URL。

沿用上面的 `browser_source` 字段，将 `page_url` 换为本次小红书详情页，补齐当前 `captured_at`、真实标题及完整 `stream_url`。候选保留完整查询参数，不导出 Cookie、Token 或登录态；仅在私有输入中临时传递，不贴入对话、报告或日志。短链必须由解析器验证跳转到同一详情页，不能仅凭手填 page_url 建立关联。页面需要登录或验证码时交用户在浏览器完成。

候选仅允许小红书 CDN 的 FLV，并须通过无 Cookie、有界音视频探测。候选时间窗为两分钟；未知停播状态不当作已结束。宿主没有资源观测能力、短链跳转不可验证或独立拉流失败时说明具体阻塞，不绕过校验。正式版仍需实际后端产生检测内容才算开始质检。

### 豆包内置浏览器取流（正式版与 Lite 共用）

先读取当前宿主暴露的 **browser-use** 或 **browser-use-automation-mac** Skill，使用它声明的执行器：通用版为 `browser_use(plane="bu")`，Mac 版为 `mac_computer_use_tool(plane="bu")`，在 cell 内 `import aha_browser_use as bu`。只使用当前宿主提供的那个，不先搜索 Chrome DevTools，也不要求安装连接器。先 `bu.list_tabs()` 按本次详情 URL 选择记录，再 `bu.switch_tab(record)` 并观察。会话失效用 `bu.resync()` 重新观察一次。不要把侧边栏页面交给 Chrome DevTools 连接器，也不要用 curl、系统 Chrome 或新调试浏览器替代。没有该执行器时明确说明“宿主浏览器资源观测不可用”，不反复搜索其他浏览器工具。

先用 `bu.network_requests()` 读取当前页真实请求，在内存中只保留 `.xhscdn.com` 的 FLV URL；该接口会消费缓冲，不要反复空读。不能仅筛选 video 类型，FLV 常由 fetch/xhr 加载。请求记录的结构以当前工具返回为准，不输出完整记录、请求头或响应正文。若现有资源未捕获，可用 `bu.js()` 只读已加载资源：

```javascript
JSON.stringify({
  page_url: location.href,
  captured_at: Date.now(),
  page_title: document.title,
  media_urls: performance.getEntriesByType('resource').map(r => r.name).filter(value => {
    try { const u = new URL(value); return u.hostname.endsWith('.xhscdn.com') && u.pathname.endsWith('.flv'); }
    catch { return false; }
  })
})
```

长连接尚未结束时可能不在 resource timing 中，空列表不是停播证据。此时按宿主文档启用当前标签的网络观测，再刷新本次直播页一次、确认播放后读取请求；不凭空猜测 CDP 参数。网络列表与页面读取之间不可切换房间。仅将本次页面的 URL、实际观测时间、标题和筛选后的 `media_urls` 保存为私有观察文件；从直播信息响应选候选时仅提取 `pull_config.streams` 的真实 URL，按已验证的 EF4 优先排列，不保存完整接口响应。

Lite 默认直接将本次观测的 `page_url`、`captured_at` 和一个已确认属于本房间的完整 FLV URL（作为 `stream_url`）写入私有 JSON 文件，结构为 `{"browser_source":{...}}`，可附 `page_title`。沿下方 start/resume 路径提交，由原 Python worker 完成房间、时效校验和独立媒体探测；无需 Node，也无需先运行准备脚本。不能确定候选归属时停止交接，不猜测地址。

已有 Node 的环境可选用准备脚本筛选和预探测：从 Inspect 根目录执行下面的命令，输入文件只含上述四个观察字段，不为 Lite 补流安装 Node：

```bash
node scripts/xiaohongshu-browser-source.mjs --output "<私有目录>/browser-source.json" < "<私有目录>/observation.json"
```

脚本按规范化房间筛选实际观测的 `/live/<房间ID>[_后缀].flv`，去重但不改写参数，逐个作无 Cookie 公网 FLV 音视频探测，总计最多15秒。未知路径不会猜测归属。输出文件独占创建，含标准 `browser_source`；stdout 只给状态，不回显流地址。容器探测不等于实际解码，仍须核验首媒体和字幕。观察文件及输出文件使用后删除；不得纳入报告、日志或发布包。

- Lite 未启动：将输出的 `browser_source` 合入原 start 输入，`source` 保持直播详情页；已启动且仍在窗口内：直接将输出文件交 `resume --task-dir <原目录> --input-file <输出文件>`。之后检查 status，只有实际媒体和字幕产生才称采集成功。
- 正式版：把输出的 `browser_source` 合入原创建输入，保持 `live_page_url` 和原项目参数，沿原创建脚本执行；创建结果未知不重放。
- 已超时、停止或冻结：按原任务收尾，不能继续搜索候选或借 resume 重开采集。用户明确提出新检测时使用新任务目录。
- 用户直接提供 FLV：正式版传 `live_pull_url`，Lite 传 `source`，沿已有直播流程。完整保留查询参数，不伪造为浏览器观测，不要求重新寻找同一地址；直流地址失效时不能凭后缀生成备用流。
