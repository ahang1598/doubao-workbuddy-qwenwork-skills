先遵循 [产品边界](product-boundary.md)；内部参数不可向用户展示；先按 [项目与场景选择](product-boundary.md#项目与场景选择) 完成列表查询和选择。

## 参数

运行 `node scripts/api.mjs --operation 'quality/+task-create' --schema` 读取当前内置运行时的参数、枚举、风险和输入输出合同；不要从 Skill 复制字段表。

`TaskType=2` 由内置运行时自动填充，数组通过 JSON 数组传入。

## When

- 用户给出一个抖音直播页、官方分享短链或 HTTP(S) FLV 流地址、已确定当前账号的直播项目与场景并要求创建质检。

## Avoid when

- 缺少链接或项目/场景选择时只补齐缺项。暂不支持仅提供直播间 ID、房间号或 ActivityId；不要拼接页面链接或调用 ID 来源接口。
- 明确遇到抖音验证码或安全验证时，先按下方“抖音人工验证”处理。项目或场景绑定不一致、场景不可访问时停止正式版创建，按 [回退规则](auth-recovery.md#正式版不可用时回退-lite) 处理确认尚未创建的新请求，不猜测其他正式项目或场景。未取得可用直播流时停止，不用切换版本绕过来源校验。若解析器没有返回确定原因，只说明本次未取得可用直播流且未创建任务，将未开播、直播已结束或直播流暂不可用列为可能原因；不要求用户确认直播状态，不承诺确认后自动创建。用户重新发起时重新解析，取得有效直播流后才可创建。

## Prerequisites

- Agent 先查询所选项目的场景详情并核验一致性；`runtime/product-scope.mjs` 只校验显式项目、场景 ID 与名称，不查询服务端、不使用固定绑定。
- 所有业务调用使用当前环境的 OpenAPI 认证，缺失或失效按 [认证恢复](auth-recovery.md) 处理，不回退其他接口链路。

## Tips

- URL 和创建意图已授权本次匿名解析及质检，无须重复确认来源发送。未请求创建或仅要求预览时不得执行包装脚本。
- 来源必须通过非回显 stdin 传入脚本；页面匿名解析一次，直接 FLV 则跳过页面解析、执行有界音视频可读性探测。FLV 留在包装脚本内存中。dry-run 成功后只创建一次，未知结果不得重放。
- 页面解析的限时、限大小、官方跳转和临时流有效期约束由解析器执行。遇到验证码可在浏览器中请求人工验证；不导出 Cookie 或浏览器登录态供脚本使用。
- 解析器兼容 `expire`、`t` 和 `auth_key` 中的有效期，保留服务端签发的完整流地址；不要手动删改签名参数。解析成功仅代表取得候选流，不能单凭这一结果声称后端已成功拉流。
- 创建时传入 `dashboard_mode=remote`，返回项目、任务编号与场景后按 [豆包工作交付](doubao-delivery.md) 在对话交付脚本返回的同环境完整操作台链接，由用户手动点击，Agent 不主动打开，并保存返回的 `environment`、`profile` 和 `account_id`。打开失败单独说明，保留已创建任务。随后按 [结束监听与自动复盘](task-completion-watch.md) 管理进程、持续等待和接续结果。

## Examples

```text
node scripts/douyin-task-create.mjs
stdin: {"douyin_url":"<用户链接>","project_name":"<所选项目>","scenario_id":<所选场景ID>,"scenario":"<场景名称>","task_name":"<可选名称>","dashboard_mode":"remote","environment":"<本次环境>"}
```

## 直接 FLV 来源

同一创建脚本中将 `douyin_url` 替换为 `live_pull_url:"<用户完整 HTTP(S) FLV 地址>"`，项目、场景、认证、工作台和后续监听参数保持一致。只传一种来源，不同时传 `browser_source`。保留签名参数原文，不要求抖音域名、页面链接或直播间 ID；不得从流地址推断主播或房间名称，未提供任务名时使用默认名称。

脚本校验 HTTP(S)、FLV 路径及公共网络地址，限时限量读取并核验 FLV 音视频。校验失败停止，不创建任务、不转入抖音验证码或浏览器取流流程；提示流不可用并请用户提供有效的新地址。探测成功不等于服务端已开始检测，仍需 dry-run 和实际创建成功。

## 直播链接解析规则

将用户完整原链接交给解析器。在 HTTPS 官方域名 `www.douyin.com`、`live.douyin.com` 下，优先按唯一的纯数字 `live_web_rid` 识别直播间，不依赖页面路径。没有该参数时才按数字直播页路径解析；官方分享短链由服务端跳转解析。重复、非法参数或与直播页路径房间号冲突时拒绝，不忽略错误参数回退路径。`search_id`、`search_result_id` 不作为房间号。解析结果统一进入规范化直播页的取流流程；不根据裸房间号或其他域名的同名参数拼接链接。

## 取流顺序

本节只适用于抖音页面链接，直接 FLV 不执行本节。

匿名 HTTP 解析是主方案，成功时直接使用，不额外启动浏览器。浏览器取得候选后可通过原脚本 stdin 的 `browser_source` 接入，字段与校验见 [创建脚本接入](browser-stream-fallback.md#创建脚本接入)。只有主方案受阻、且未创建任务时，才按 [浏览器补充取流方案](browser-stream-fallback.md) 使用豆包工作侧边栏浏览器检查页面和媒体资源；出现可见验证控件时先执行下方人工验证。浏览器路径是补充方案，不替换主方案，也不绕过原任务的认证、场景核验与创建约束。

## 抖音人工验证

1. 页面、响应或浏览器中明确出现验证码、安全验证或人工验证提示时，进入本流程。页面体积小（例如约 6 KB）、普通超时、403、验证码 SDK 字样或没有流地址不能单独作为验证码的证据；原因不明时可打开原直播链接核对页面，未确认前只说明取流受阻。
2. 按 [统一宿主浏览器](doubao-delivery.md#统一宿主浏览器) 复用当前浏览器，尝试打开本次抖音直播链接或官方响应实际提供的抖音验证页面。优先复用原标签并保留页面跳转，不猜测验证地址，不打开来源不明的验证链接。
3. 页面打开后先检查可见内容。只有实际显示验证码或验证控件时，才请用户接管：**“抖音需要人工验证，请在已打开的页面完成验证，完成后告诉我，我会再尝试获取直播流。”** 验证由用户手动完成，Agent 不代做验证码。浏览器不可用或打开失败时，说明实际阻塞并提供原直播链接，不声称验证页已打开；保留项目、场景等参数供续办。
   浏览器若正常显示直播且没有验证控件，不要求用户寻找滑块，不反复刷新或尝试触发验证码。说明“浏览器可以打开直播，但脚本暂未取得可用流地址”，结束人工验证分支，按 [浏览器补充取流方案](browser-stream-fallback.md) 检查宿主是否具备媒体资源观测能力。浏览器和匿名 HTTP 请求的结果分别判断；不因浏览器正常就宣称脚本可用，也不把它说成用户已完成人工验证。不要临时编写携带 Cookie 的请求来替代解析器。

4. 等待用户完成验证；收到完成通知后，在原标签核对验证页是否已解除，再对原直播链接尝试一次来源解析。浏览器中的验证结果不保证匿名脚本也能取流，不读取、复制或持久化 Cookie、Token 或浏览器登录态。只有解析器返回有效流，且已确认此前未创建任务，才继续原创建流程，无需用户重复提供业务参数。
5. 仍出现验证或取流失败时，说明“人工验证后仍未取得可用直播流，本次未创建任务”，停止匿名自动重试并保留上下文；若浏览器已经正常播放，可按 [浏览器补充取流方案](browser-stream-fallback.md) 检查补充路径。不要反复刷新验证页或承诺一定能恢复。此前创建结果未知时先只读核对任务，不重放创建请求。

页面只有 `LIVE_SSR_DATA_ID`、缺少 `data-config` 时，不能推断未开播，也不能直接认定流数据已迁移到该节点；以实际播放器数据为准。

## 调用配置兼容

- `douyin-task-create.mjs` 的 stdin 可选传入 `profile` 和 `environment`，无需让用户提供这些内部参数。未指定时默认使用线上环境（`environment=online`），不得从当前 profile 或宿主环境推断目标环境，不为获取字段反复重试或要求用户再次确认业务。
- 显式指定时，由脚本查询配置并绑定后续 dry-run 和创建请求。读取 profile 的 `openapi_env`（兼容 `openapiEnv`）；缺少绑定字段时兼容 `meta.environment` 和旧版 `data.environment`。不能把命令默认环境覆盖到已有 profile 绑定上。
- 结构差异由脚本内部处理，不向用户暴露字段名、内部参数、堆栈或“脚本兼容性 bug”。真实环境/账号冲突或无法确认配置时，在创建前停止，提示“当前质检服务配置暂不可用，请检查已选账号的服务配置后继续。本次未创建任务。”，保留原业务参数供续办，不自动切换账号或环境。
