# 正式版用户交付

正式版无论本地或云电脑均用远端控制台；Lite 使用 [自身交付](../lite/references/delivery.md)。任务保存、报告就绪、页面可读、对话交付与清理分别判断。

## 版本选择

入口 interaction 是选项、顺序和完整 fallback_text 的来源。豆包使用当前模式实际可用的结构化单选，其他宿主优先单选；标题与独立选项标签使用纯文本，说明放描述，不把整段文案塞进标题。调用结构化提问组件时，必须将 `interaction.options` 逐项映射到组件的 `display_option`，其中 `id → option_id`、`label → label`、`description → description`；不得把 `options` 原样作为未声明字段传入。问题正文必须直接列明“正式版”和“Lite 本地版”，即使按钮描述未渲染也能独立完成选择。两个版本都支持直播、多视频质检与直播复盘；视频仅质检，不宣称视频复盘。

accepted、排队成功或请求标识不代表卡片已展示，更不代表用户作答。保留本次问题引用，等待真实答案；尚未作答不启动、不重复发卡。组件不可用或展示未确认时在正文交付完整 fallback_text，让用户回复选项；卡片和文字共用一次选择状态，先到的有效回答只消费一次。已经明确选择登录直接续办，不重新询问。

实际执行所选流程时，登录和新建任务脚本自动记录确定版本。只展示卡片、accepted 或等待回答不计入；授权续办保持原任务绑定，Lite 复用原任务目录，不单独发送埋点。切换版本由实际执行路径识别，不重建原任务。

## 交互与进度

只播报真实业务阶段、风险、阻塞及必要操作。不发送“我来处理任务”“先按 Skill 流程”等空泛开场，也不预告生成 UUID、启动脚本、读取文档、Schema、埋点或认证标识；这些步骤直接执行。准备中不称已开始检测；已有任务续办受阻不称服务端检测停止。保留来源、场景、身份及批次进度，不要求重建。

质检报告就绪、复盘尚未生成时先交付质检报告并提示“质检报告已生成。内容复盘还需要一些时间，生成后我会继续为你提供复盘报告。”随后在当前轮继续分析与交付，不用最终回复结束，不承诺具体耗时。已有复盘直接交付。

认证缺失及恢复按 [认证恢复](auth-recovery.md)，已选登录不重复问；授权 URL 生成后立即交付，不等待其他检查，同时明确引导用户授权完成后回到当前对话回复“已授权”或“继续”。授权页面不会自动续接对话；远程模式还需先通过受控输入渠道提交授权结果。

## 统一宿主浏览器

授权链接和监控台链接在正文交给用户手动点击，Agent 不主动打开、不为核验而打开、不通过系统 open/start/xdg-open。scripts/login.mjs 原生不打开浏览器，不追加外部浏览器开关；独立认证有效时不为建立浏览器引用重新登录。

报告及抖音补充验证页按实际工具说明使用宿主内置浏览器，复用同一应用、用户配置、会话和任务标签，不另建无痕或隔离浏览器。授权等待期间保留授权标签。不可用则说明无法自动核验，保留原任务，不切外部浏览器。验证码由用户接管。

续办仅保存宿主提供的非敏感会话/标签引用，不读取或复制 Cookie、Token。独立运行时认证不证明浏览器已登录或页面有权限；OAuth 远程模式也不意味着切换浏览器。链接输出不表示页面已打开，未观察不得声称已打开或可读。

## 直播任务打开远端操作台

1. 创建脚本 scripts/douyin-task-create.mjs 的 stdin 使用 dashboard_mode=remote，固定 environment=online，保留来源校验、dry-run 及只创建一次的约束。
2. 使用创建结果 data.dashboard.dashboard_url；已有任务或地址缺失时，从 Skill 根目录执行 `node scripts/audit-dashboard.mjs --remote --environment <原任务环境> --profile "<原profile>" --account-id "<原账号ID>" --project-name <本次项目> --task-id <本次任务>`，只读核验后取 data.dashboard_url。不得手工拼接，不把视频送入直播路由。
3. 创建成功后立即在回复正文提供 `[打开质检监控台](实际 dashboard_url)`，使用返回原值。每次关于该任务的最终回复或中断说明也必须附本次链接，不能只在工具输出、折叠执行过程出现，不能只写“见上方链接”。地址恢复仍失败则说明原因，不编造链接。请用户沿用授权浏览器会话点击；交付后继续监听，不等待点击、不因此结束执行。
4. 页面登录、权限或部署不可用时保留任务、链接和 Chat 状态，不重建、不启动本地服务。任务身份见 [原账号与任务绑定](auth-recovery.md#原账号与任务绑定)，持续执行见 [结束监听](task-completion-watch.md)。工作台不会唤醒已结束的 Agent。

### 入口配置

URL 由 runtime/remote-dashboard.mjs 维护，线上域名 console.volcengine.com。只允许原任务项目与任务标识出现在本次链接路径，不附凭证或媒体地址、不在正常文字中展开内部 ID。api.mjs 业务参数使用 JSON stdin，不追加 --env 等业务 CLI 参数。

## 直播与视频质检远端报告

不生成、上传或交付本地质检 HTML，不启动本地报告服务，不提供附件、回环地址或端口转发兜底。远端页面不可用也不改用本地报告；仅 Chat 文字不算完整交付。

1. 按对应报告 leaf 核验原身份、类型、任务终态与报告就绪，不根据编号猜类型或跨类型探测。
2. 从 Skill 根目录运行 `node scripts/report-link.mjs`，stdin 为 {"kind":"video","environment":"online","project_name":"原项目","task_id":原编号}；直播 kind=live。从 video/ 执行时用 ../scripts/report-link.mjs。只取 data.report_url；link_generated 不证明报告就绪或归属。
3. 用同一宿主浏览器打开本次链接并核验页面真实可读，登录页、无权限、空白或404不算通过。随后正文交付“打开视频质检报告”或“打开直播质检报告”链接及中文结论、命中时间和必要证据。多视频按确认顺序逐项交付，不复用其他任务链接。
4. 完整交付要求报告就绪、页面可读、链接与摘要已展示。无浏览器能力仍给链接并明确“页面可访问性尚未核验”；失败保留链接、结论与续办上下文，不声称完整交付。

视频与直播共用新版 /report/view/ 页面，不使用旧 /report/ 任务详情页，视频不用 /dashboard/。链接以脚本输出为准，不手工构造。

### 报告链接入口

`scripts/report-link.mjs` 仅生成控制台链接；沿用 kind/environment/project_name/task_id，并按上述流程核验，不读取旧本地文件冒充本次报告、不改写脚本制作 HTML。

### 服务端报告读取约束

直播 quality/+report-get，视频 content/+video-report-get。受控子进程在内存捕获 api.mjs 输出与退出码，检查 ok 及 Result 后只输出任务名称、中文场景、状态、时长、规则结论、命中时间和必要短证据；证据 URL 与凭证片段脱敏。原始 stdout/stderr、完整 ASR/Utterances/TaskResult、媒体地址不进入工具输出、临时文件、tee 或日志，截图完整内容由远端报告展示。

仅任务已结束/完成才查报告；失败停止等待，未知状态说明未确认。成功响应为空、缺 TaskResult，或明确 ReportNotFoundError/REPORT_NOT_READY 才按 leaf 有界等待；认证、权限、网络、解析与结构错误分别处理，不称报告生成中，也不把空响应当无风险。

## 质检报告与复盘交付

直播复盘按 [内容复盘](ecommerce-review.md#默认收尾入口) 使用 finalize；不要手工重串上传。宿主要求技术审批时说明本次数据及原任务既定目的地，不把 Skill 当授权或绕过拒绝。实际拒绝保留产物并说明阻塞。

使用已确认保存的 report_url，核验页面后交付“打开复盘报告”链接和摘要。页面核验失败保留链接及保存状态；缺 ASR 则交付已有质检结果并说明复盘依据不足。

### 收尾与交付状态

未知上传续办只读核验；已保存复用链接，不重新分析或上传。实际交付后才用 finalize --ack-delivered 清理；清理失败只续办清理。未命中限于本次规则与检测范围，不扩大为全面无风险。


### 流程交付回执

正式版直播和视频的质检报告，只有完成上述“报告就绪、页面可读、链接与摘要已展示”后，才从 Skill 根目录执行 `node scripts/workflow-delivery.mjs`（video/ 下使用 `../scripts/workflow-delivery.mjs`）。继承原入口 `execution_env.INSPECT_USAGE_CONTEXT_DIR`，JSON stdin 传入：

```json
{"environment":"online","profile":"原profile","account_id":"原账号ID","project_name":"原项目","task_id":"原任务编号","report_kind":"quality","outcome":"delivered"}
```

这些值必须来自原任务回执，不在正常回复中展示。多视频逐项确认，重复确认不增加流程数。只有内容不足说明时使用 `outcome="insufficient"`；已明确发生报告交付失败时使用 `outcome="failed"`。未核验、未收到宿主确认或结果未知时不发送 delivered/failed；保留续办。该命令不生成报告、不重放任务，失败也不改变已发生的业务交付。

复盘仍使用原 finalize `--ack-delivered`，不额外调用本脚本；它会结合保存的报告质量自动记录有效交付或内容不足。旧收尾状态缺少质量证据不推断成功，不重新上传来补统计。
