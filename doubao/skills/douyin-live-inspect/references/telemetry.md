# 遥测运行约束

遥测由业务入口和运行时自动处理。按正常质检、报告及交付流程执行，不手工调用 `skill-start.mjs`、`version-selected.mjs` 或补报事件，不因遥测缺失重跑业务操作。

- 关闭遥测使用 `BYTEDLIVE_TELEMETRY_DISABLED=1` 或 `true`，后续子进程继承该设置。关闭时不解析遥测身份、不读写设备 ID；业务任务标识仍正常生成。
- 遥测失败不阻断业务。以业务回执判断执行结果，不把发送成功、命令成功或本机捕获事件当作任务完成、报告已交付或线上已入库。
- 不向遥测传入媒体、直播地址、路径、请求正文、用户原话、原始异常、凭证或授权结果；不为补全统计额外查询用户身份。
- 继承入口返回的 `execution_env.INSPECT_USAGE_CONTEXT_DIR`。版本选项作答、登录、创建和续办沿用原请求目录；同一任务的新请求使用 `inspect-entry --mode lite|formal --task-state existing --new-request --task-dir <原目录>`，任务目录保持不变。
- Lite 创建、重试和恢复复用入口返回的任务目录；批量任务复用批次目录，不为修复遥测重建任务或修改本地上下文文件。

版本流程的补充约束见 [正式版](formal-telemetry.md) 和 [Lite](../lite/references/telemetry.md)。

## 一次质检流程

新版入口自动建立一个流程：仅新建质检请求进入分母，查询已有任务、重试和续办不新建流程。后续所有业务与交付脚本均继承入口的 `execution_env.INSPECT_USAGE_CONTEXT_DIR`；不能重新生成目录来补数据。流程从入口开始，等待选择、授权或执行结果不明确时保持“结果未知”。遥测关闭、漏投或旧版本不回填。

直播只有有效质检报告和有效复盘报告均实际交付才算成功；视频仅要求质检报告，多视频要求全部预期项。内容不足说明单列，不算成功；明确失败与未知分别记录。交付是宿主可观察到的链接及摘要展示，不代表用户已阅读。正式版确认方法见 [用户交付](doubao-delivery.md#流程交付回执)。

流程观察由代码自动记录；后续操作沿用入口返回的 `INSPECT_USAGE_CONTEXT_DIR`，不额外手动发送阶段事件。
