# 直播内容复盘核心规则（行业与通用场景，V1）

<!-- SHARED_RECAP_ANALYSIS_START -->

## 目标

仅根据主播 ASR 和 GetReport 质检结论，回答三个问题：主播讲了什么、哪些内容值得保留、哪些内容应当改进。输出结构在全部场景间共用，判断标准随 `fd.ev.quality_report.scenario_name` 调整；其他场景采用通用内容分析，不根据内部 ID 猜行业。

## 数据边界

- 内容事实只来自 `fd.sg[].tx`。
- 合规事实只来自 `fd.ev.quality_report`。
- 不使用评论、商品卡、互动、成交、观众或窗口指标。
- 不输出商品分析、人群分析、五维评分或综合直播分。
- 不把质检“未命中”解释为商品功效、价格、库存或承诺真实。

## 分段

- 按 `fd.sg` 的时间顺序分析，时间单位为毫秒。
- 分段应连续覆盖现有 ASR，不重叠、不倒序。
- 开场可使用 30–60 秒片段；常规片段建议 1–3 分钟；任何片段不得超过 3 分钟。
- 高光和问题片段按完整主题划分，证据跨段时可以合并，最长 3 分钟。
- 不补写 ASR 缺失时间段的内容。

### 语义合并要求

准备脚本的 `fd.sg` 是 ASR 原文读取单元，不是最终分析段。脚本默认目标时长为 2 分钟，达到目标后等待至少 2.5 秒的停顿，在完整 utterance 边界尽量控制为不超过 3 分钟；停顿只是候选边界，不代表主题一定结束。单条超长或互相重叠的 ASR 无法无损切开时保留原文，Agent 需复核。

- 必须通读全部 `fd.sg[].tx` 后再确定输出 `segments`，主动检查相邻单元是否延续同一主题；同一主题被切开时合并，不得直接照搬读取单元。
- 以主题完整和真实转折为准，不强制压缩到固定段数或固定比例。已合理分段、短直播或明确不同的主题无需机械合并；一个读取单元内存在多个主题时可以根据原始时间证据拆分，不编造时间点。
- 分析段以 1–3 分钟为宜，尾段或短主题可以短于 1 分钟；不要为了满足建议时长强行拆分或合并。
- 合并须保持时间顺序、覆盖全部有效 ASR，不丢失证据、不制造重叠，不补写 ASR 空白时段。同一输出段不能同时标记高光（label=2）和问题（label=3）；无法依据真实时间可靠拆分时问题优先。

## 高光判定

只有话术本身形成清晰、可复用的表达时才标记高光。电商场景关注商品价值、适用场景、权益售后及行动引导；金融场景关注概念与信息解释、适用条件、限制与风险揭示、审慎表达和合规行动引导；汽车场景关注车型定位、配置功能、使用场景、价格权益条件、售后用车边界及试驾留资引导。关键说明必须具体且不夸大。

高光评价必须明确是“基于主播话术”的判断，不得借缺失的评论或成交数据证明效果。

高光时刻精选最突出、可复用的话术片段，单场直播最多 2 个；相同优点优先合并，不为凑数标记，证据不足可为零。

## 问题判定

可标记的问题包括：信息含糊、条件遗漏或前后不一致；重复铺陈、节奏拖沓、行动指令不清；电商场景中的价格、库存、赠品、售后口径歧义；金融场景中的适用资格、费用、期限、风险、收益或效果口径不完整；汽车场景中的车型版本、配置参数、价格优惠、金融方案、交付范围、质保保养或用车成本条件不完整；绝对化承诺等质检风险；只介绍不收口。

GetReport 有带时间证据时，可与对应 ASR 片段结合；没有时间证据时，只写入全局质检总结。

一般内容问题精选最值得优先改进的片段，单场直播最多 2 个，同类问题优先合并，证据不足可为零。

已完成质检明确命中的违规/风险必须全部纳入，不占一般内容问题的 2 个名额，不因精选数量或分数低而删除。存在可定位时间证据的命中全部落入问题时刻；没有时间证据的命中全部保留在全局质检总结，不编造定位。未判定、insufficient 或单纯运营建议不得改写为确认违规。

合并仅用于展示，不改变原始命中事件和风险计数。同一主题内相邻、连续的同类违规可合并为一个问题时刻，保留每次命中的证据引用，并在详情列明各次出现时间；仍遵守最长 3 分钟和不跨采集缺口的分段约束。相隔较远的事件分别保留定位，在全局总结中归为同类并注明重复次数，不用一个代表片段替代其余违规。

## 输出契约

输出必须覆盖以下五类信息，不能因为没有评论、商品卡或窗口指标而省略：

1. 一句话结论：概括讲解完整度、主要优势、主要风险和最优先改进方向。
2. 表现亮点：对全场内容进行归纳，精选最多 2 条可复用的优势结论及其价值；不输出时间戳或片段原文。
3. 主要问题：对全场内容进行归纳，精选最多 2 条一般内容问题，另按类型汇总全部已确认违规/风险，不受此数量限制；不输出时间戳或片段原文。
4. 优化建议：至少包含推荐话术结构和针对本场问题的可执行动作。
5. 数据边界声明：明确本版没有评论、流量、停留、商品点击及成交数据，不能判断观众反馈和转化效果，也不生成五维评分。

- 没有足够证据时亮点和问题保留空数组，不为满足建议数量而编造。全场亮点/问题总结与时间片段分别填写；对有明确时间证据的高光和问题，应在对应片段打标并说明依据，不能只写总结遗漏片段标签。

分析结果先输出一个 JSON 对象：

```json
{
  "module_code": "content_analysis",
  "status": "success",
  "conclusion": "一句话结论",
  "summary": "全场内容与质检结论摘要",
  "highlights": [{ "title": "亮点结论", "reason": "全场归纳后的价值说明" }],
  "problems": [{ "title": "问题结论", "reason": "全场归纳后的问题说明", "risk": "可能影响" }],
  "recommended_structure": ["受众问题", "核心信息", "事实或规则依据", "适用条件", "限制与风险", "合规行动引导"],
  "recommendations": ["针对本场的可执行建议"],
  "data_scope_note": "本版没有评论、流量、停留、商品点击及成交数据，因此不能判断观众反馈和转化效果，也没有生成五维评分。",
  "segments": [{
    "segment_id": 1,
    "index": 1,
    "start_time": 0,
    "end_time": 60000,
    "title": "片段标题",
    "content": "基于 ASR 的摘要",
    "labels": [2],
    "tags": ["卖点清晰"],
    "highlight_score": 80,
    "problem_score": 0,
    "momentData": { "reason": "判断依据", "suggestion": "可执行建议" }
  }]
}
```

- `status`：成功为 `success`；无可读 ASR 时不得生成成功结果。
- `conclusion`、`highlights`、`problems`、`recommended_structure`、`recommendations`、`data_scope_note` 均为必填；没有证据的问题或亮点使用空数组，不得编造。
- `labels`：`1` 表示核心对象讲解（电商为商品讲解，金融为产品、服务或知识讲解，汽车为车型、配置、服务或用车知识讲解），`2` 表示内容高光，`3` 表示内容问题；普通片段使用空数组。V1 不使用 AI 扩展标签 `4`。
- `highlights[]` 和 `problems[]` 是面向决策的全场总结，不带 `start_time` / `end_time`，不得只复述某个片段。时间、证据和可执行建议放在对应 `segments[].momentData` 中。
- 同一片段不得同时标记高光 `2` 和问题 `3`。优先依据 ASR 的句级时间拆出各自证据范围；无法可靠拆分时，问题优先，避免同一证据被重复归因。
- `tags` 最多两个非空字符串；分数若存在必须为 0–100 的数值。
- 分数范围为 0–100，只表达话术质量强弱，不代表成交效果。
- `content`、`reason` 和 `suggestion` 应是摘要，不得大段复制 ASR。
- 没有足够证据时保留空数组，不为满足数量而制造高光或问题。
- segments 中高光（label=2）最多 2 个，一般内容问题（label=3）最多 2 个；已确认且有时间证据的违规/风险全部标记为问题，不占一般问题名额。仅一般候选按突出程度和代表性精选，其余保留为普通核心对象讲解（label=1）或空标签；不得因此删除违规标记或证据。合并遵循上述问题判定规则。

## 面向用户的报告

以下是运行时报告视图的展示结构，模型只生成分析 JSON，不手工生成 HTML；显式本地预览由兼容组装入口处理：

- `## 直播复盘`
- 一句话结论
- `表现亮点`
- `主要问题`
- `## 优化建议`
- 推荐话术链路及逐条建议
- 数据边界声明

内部语义分段必须覆盖全部有效 ASR 时间范围，但不单独展示阶段表。“关键发现”只展示无时间戳的全场归纳；“内容分析”展示高光时刻、问题时刻、时间和证据。“全部”标签下不显示“定位复核”；“高光时刻”和“问题时刻”标签下以文字按钮展示“定位复核”，点击时间段或该按钮时应跳转到回放播放器的片段起始位置并开始播放。点击回放时间轴的高光或问题控制条，应切换到对应内容分析标签、展开详情并滚动到对应片段。展开详情时将时刻类型和详情名称合并为单行标题，例如“高光时刻详情：现场验真形成完整闭环”，避免重复标题层级。建议和内容分析标签必须与 JSON 一致。分析 JSON 先与原任务私有上下文组装为完整 v1 报告 JSON（已有分析文件使用 `review_file`），不生成 HTML、不启动本地报告服务；按 [豆包工作交付](../doubao-delivery.md) 上传最终复盘 JSON（用户明确要求仅本地或不上传时遵循该交付规则跳过上传），确认成功后交付真实在线报告链接与结构化摘要，不以本地文件、附件或回环地址替代在线交付。
