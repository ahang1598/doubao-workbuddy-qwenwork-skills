# 认证恢复与原任务续办

直播与视频共用随包的独立 Node.js 认证实现。仅支持线上 OpenAPI，不需要安装或调用企业直播 CLI。认证目录默认是 `~/.douyin-live-inspect`，部署时可通过 `DOUYIN_LIVE_INSPECT_CONFIG_DIR` 指定独立目录；不会读取旧 CLI 缓存或环境变量中的 AK/SK。Agent 只调用脚本，不读取认证目录中的会话、pending 状态、密钥或 Token。

## 新建直播与视频的账号入口

新建请求的探测、版本选项与作答状态只按 [统一账号入口](../SKILL.md#1-新建直播与视频账号入口分流) 执行，本页负责授权与恢复。

## 何时进入

`auth-status.mjs` 只读取并输出脱敏状态，不联网、不刷新。`authenticated` 可继续业务；`expired` 且 `refresh_available: true` 时可继续原业务，由业务运行时在发送请求前刷新 STS。不能把可续期的 STS 过期当成必须重新登录。`login_required`、不可续期的过期会话或实际刷新失败时才进入认证恢复。

仅上传已有完整复盘 JSON 时直接执行上传脚本，它同样在内部读取独立缓存并刷新；返回 `SETUP_PENDING` 后按本页恢复。普通网络错误、项目不可访问、权限不足不能误报为登录过期；`AccessDenyError` 按下方未开通规则处理。

## 原账号与任务绑定

已有任务的执行上下文固定为 `environment:online`、`profile`、`account_id`、`project_name`、`task_id`。任务查询、结束、监听、复盘准备、上传、下载和收尾均显式携带。项目／场景发现及新建入口保留账号选择方式。JSON stdin 使用上述字段；支持 CLI 的入口使用其 Schema 所列参数，不向 `api.mjs` 追加业务 CLI 参数。

实际执行前校验：缺少原身份返回 `ORIGINAL_TASK_CONTEXT_REQUIRED`；所选 profile 已换账号或任务归属冲突返回 `TASK_BINDING_MISMATCH`，停止业务调用。原身份仅从已有创建结果、监听结果、私有复盘上下文或可信续办记录恢复，不从当前 profile 补成原账号。旧记录不足时保留原任务并说明缺项，不迁移、重建或重传。

首次查询用户指定的历史任务时，先按用户选定的账号建立本次查询上下文，带项目、类型及任务编号查询并核验；查询成功后固定沿用这组身份。此入口不是丢失身份的已有任务续办，不得用它覆盖旧任务绑定。同名任务先以名称、时间、状态选择，内部 ID 仅用于执行。

`dry-run` 只校验业务参数，不认证、不联网；预览结果不能当作原身份凭据。仅生成报告链接的脚本不增加认证调用，也不能证明报告就绪或归属。

## 登录失效后的选择

首次缺少登录且尚未选择版本时，使用入口的首次选择文案，不将“未登录”误报为“登录过期”。发现登录态失效时，先说明“火山引擎登录态已失效”，按入口的版本选择规则展示一次：标题“选择后续方式”，独立单选标签“使用 Lite（免登录）”和“继续登录火山引擎”，对应说明“无需火山登录。”和“授权完成后回到当前对话回复‘已授权’，继续正式版质检。”。组件参数、异步等待和重复作答处理统一遵循[交付文档的单选状态流程](doubao-delivery.md#版本选择)。

- 用户已经针对本次认证缺失或失效明确选择登录时，直接执行下方登录能力检查，不再询问。历史正式版偏好不代替本次选择；一次登录尝试失败后按回退规则处理，不再次循环展示选择或登录。
- 选择 Lite 的新建请求按下方规则续接，并遵循 [云电脑推荐交付规则](../lite/references/startup.md#硬约束云电脑环境必须提示本地电脑推荐)，不另行重复提示；其他回退 Lite 的入口同样适用。选择继续登录时保留来源、场景和进度，登录成功后继续原请求。
- 已有正式任务、创建结果未知、仅查询或报告续办时，选项中须说明 Lite 仅供新的检测，无法接续云端任务。选择 Lite 后保留并暂停本次正式版续办，说明新检测需要来源与创建意图，不把版本选择当作重新检测授权。

## 正式版不可用时回退 Lite

以下规则同时适用于直播和视频。首次 inspect-entry 返回 requires_user_input 时先按其 interaction 完成选择，不把尚未作答当失败；下列规则用于已选路径的实际执行失败。正确根目录缺文件、依赖损坏等安装不完整情况先停止，按主入口重新安装完整 Skill；不触发 Lite 回退。仅完整安装中的正式能力受阻，才保留真实失败阶段并按任务状态处理：

- **可回退的新请求**：有创建意图，且确认尚未创建正式任务。登录失败、用户仅取消或拒绝授权、独立登录能力检查失败、缺少可用的受控授权输入渠道、正式版能力检查失败、服务未开通、网络或权限错误、项目/场景/规则缺失或不可用时，说明实际原因及“本次改用免登录的 Lite（本地版）”，直接续接内置 [Lite](../lite/SKILL.md)，不增加回退确认，不循环登录或重试。即使之前选择了正式版也适用；用户明确禁止 Lite 时保留请求并说明阻塞。
- **选择与等待**：仅检测到登录失效时先展示上述选择，不立即回退；用户已选择重新登录但本次尝试失败时才回退。授权进程正常等待、用户尚未点击链接或完成授权不算失败。用户明确停止整个质检请求时停止，不启动 Lite；不要将取消整个任务误解为仅取消授权。
- **已有或未知任务**：已有正式任务、创建写入超时或结果未知、查询历史任务、读取报告及上传复盘时，不自动新建 Lite，也不生成替代报告。未知写入先只读核对，只有确认未创建才能按新请求回退；不能核实时保留原上下文等待续办。批量视频保留成功项、映射和顺序，仅尚未创建项可回退；当前项创建结果未知时先暂停后续项并核对。
- **已有 Lite**：从运行中的 Lite 切换正式版失败时继续原 Lite 任务，不重新 start；按 [切换流程](lite-to-formal.md) 处理。
- **来源与规则**：沿用已提供来源、检测意图、名称、时长需求与视频顺序。直播使用支持的抖音页面或 HTTP(S) FLV 流；视频使用本机可读文件或宿主已物化附件。仅有网络视频链接时提示提供本地文件，不下载、不返回失败的正式链路循环。使用 Lite 自有场景与规则，不套用正式项目/场景 ID 或宣称规则等价；可沿用用户明确指定且 Lite 支持的中文行业。批次沿用已确认顺序，只有场景不适用时补齐 Lite 场景选择，不重复确认未变化的业务输入。
- **启动与边界**：从 Inspect 根目录进入 `lite/`，按 Lite 的来源校验直接启动，返回 setup_pending 后才执行 doctor 诊断；已完成选择或回退后不重新探测火山账号。缺少 Lite 文件或必要依赖时如实说明阻塞，不编造调用路径或声称已启动。Lite 直播默认不限时，用户明确指定时长时按指定时长结束；视频按 Lite 抽检策略处理并披露覆盖范围，不因文件时长拒绝。
- **原因与后续**：只在 `AccessDenyError` 明确指向未开通时使用未开通话术和申请指引；网络、登录或配置问题不归为未开通。保留原正式版上下文，用户要求返回正式版时再验证，已经启动的 Lite 任务不自动迁移。Lite 默认 remote_first，远端处理上传音频须说明；用户要求完全本地或不上传时用 `local_only`。

实际执行所选流程时，登录和新建任务脚本自动记录确定版本。只展示卡片、accepted 或等待回答不计入；授权续办保持原任务绑定，Lite 复用原任务目录，不单独发送埋点。切换版本由实际执行路径识别，不重建原任务。

## 正式质检服务未开通

直播与视频共用本规则。质检业务接口（包括项目列表查询）返回业务错误码 `AccessDenyError` 时，按质检服务未开通处理，不要求同时匹配错误文案。登录成功仅代表认证完成，不代表服务已开通；项目列表为空也不能据此判定未开通。

- 停止本轮正式版后续质检调用和任务创建；批量视频暂停尚未创建的任务，保留已有任务与处理进度。不重复登录、不循环重试、不切换账号或项目，也不引导新建项目来解决未开通问题。
- 优先推荐加入飞书群沟通开通，明确说明“沟通更高效”（通过展示顺序体现推荐关系，对外文案不写“优先”）；其次提供开通工单及能力介绍文档。使用以下完整 Markdown 链接，由用户点击并自行提交，不自动提交工单：

  当前账号尚未开通质检服务，可选择以下任一方式：

  **方式二：提交工单**

  [提交开通工单](https://console.volcengine.com/workorder/create?step=3&SubProductID=P00000078&sessionID=f3eb625d-af6c-11f1-b754-4a64e05716c9&from=doubaoworkcli)，按以下内容填写：

  - **相关产品**：视频服务 / 企业直播
  - **问题分类**：操作指导

- 新建直播与视频按上方回退规则进入 Lite，沿用来源与已核验的未开通结论，记录入口原因为 `formal_service_not_enabled`；仅查询或已有正式任务续办不新建 Lite。Lite 暂不可用时保留上述飞书群优先、工单其次的开通入口，如实说明阻塞。
- 项目列表为空属于配置缺失，按上方回退规则处理，不称为未开通；其他错误按实际原因处理。

- 保留原账号/profile、环境、来源、项目、场景和任务进度。用户说明已开通并要求继续后，使用原上下文重新查询验证，成功后续办；仍返回 `AccessDenyError` 时继续提供飞书群沟通及工单处理指引，不声称已开通或质检已启动。已有任务先核对状态，不重复创建。
- 其他错误码继续按实际认证、权限、配置或网络错误处理，不一概归为未开通。

## 登录能力检查

仅在用户已选择登录、确需重新授权时，从已核验的 Skill 根目录执行 `node scripts/check-login-capability.mjs`。它报告随包的独立登录实现能力，不探测外部 CLI、不发起授权。脚本缺失或 Node.js 无法运行属于安装或运行环境问题，应准确说明并保留业务上下文。

## 主动发起授权

1. 保留原来源、项目、场景、任务、批次顺序、身份和进度。按 [交互与进度](doubao-delivery.md#交互与进度) 说明需要授权，已选择登录时不重复确认。
2. 执行 `node scripts/detect-runtime-mode.mjs`，使用 `data.mode`。**发起远程 OAuth 前**先确认宿主提供不记录、不回显的受控授权结果输入渠道；普通聊天、工具参数记录及非 TTY 本身不证明具备此能力。没有该渠道时不生成授权 URL，新请求按回退规则处理，已有任务保留并暂停。本地浏览器能访问当前 Node.js 的回调时运行 `node scripts/login.mjs --environment online --profile <名称>`；云电脑、未知环境、跨设备或回调不可达时追加 `--remote`。脚本原生只输出 URL，从不打开浏览器，无需也不支持额外的 `--no-open-browser` 开关。
3. 将输出的真实完整 URL 立即作为 Markdown 链接交付，文案用“登录火山引擎并授权”，请用户手动点击，并在链接旁明确提示：“授权完成后，请回到当前对话回复‘已授权’或‘继续’，我会核验登录状态并继续刚才的质检。授权页面不会自动让对话继续。”不得承诺“自动检测回调并继续质检”。远程模式还须说明：“请先通过受控授权输入渠道提交火山页面提供的 code 或浏览器地址栏中的完整回跳 URL，任选一种即可；提交后回到当前对话回复‘已授权’或‘继续’。”输入渠道遵循下方授权结果处理规则，不要求用户必须提供 URL 或自行提取 state。遵循 [统一宿主浏览器](doubao-delivery.md#统一宿主浏览器)，不主动调用浏览器工具、导航标签或执行系统浏览器命令，不以代码块或占位链接代替。
4. 本地模式在 `127.0.0.1` 的随机端口和 `/oauth/callback` 等待回调，校验 state 后使用 PKCE 交换 Token，最长等待 5 分钟。运行中复用该进程，不反复发起登录。
5. 远程模式输出 URL 后立即返回 `status: pending`，这是等待用户授权的正常状态，不是登录成功，也不是失败。内部 pending 状态有效 10 分钟。保留 profile，等待受控授权结果后执行下方续办，不必保持首次命令进程运行，也不要重新生成 URL。

## 授权结果处理

用户可以粘贴火山授权页面提供的 code，也可以粘贴浏览器地址栏中的完整回跳 URL，任选一种即可。火山页面提供的 code 是封装后的授权结果（Base64），运行时自动解码；不要因为用户粘贴的内容不是 URL 就拒绝或要求重新复制 URL，也不要要求用户自行解码或提取 state。

运行时接受完整回调 URL、code/state 查询串，或包含这些内容的 Base64 结果，解析后必须包含与本次登录匹配的 state。火山页面提供的完整 code 与从 URL 中单独截取的 OAuth `code` 参数值不同；后者缺少 state，仍不能用于续办。

只在宿主确实提供不记录、不回显的受控授权输入渠道时提交结果：运行 `node scripts/login.mjs --environment online --remote --profile <原profile> --authorization-response-stdin`，通过受控的非 TTY stdin 传入完整结果并关闭输入（EOF）。首次远程命令正常返回 pending 后就使用这个续办命令；不只用于进程中断恢复。运行时在内存中解码、校验 state 和 PKCE，成功后原子写入独立缓存并删除 pending 状态。

- 授权结果不能写入命令参数、普通聊天、临时文件、仓库、报告或日志，不能通过会记录输入的工具冒充秘密通道。脚本要求非 TTY stdin 只是输入约束，不能保证宿主本身不记录内容。
- 不索取 AK/SK、Cookie、Header、Token 等持久凭证，不自行读取、修改 pending cache。缺少受控输入能力时准确说明限制，按上方回退规则处理。
- 本地回调明确拒绝授权时会结束登录；远程结果过期、state 不符、重复参数或授权失败时不继续业务，不循环提交旧结果，也不自动发起另一轮登录。仅取消授权与停止整个质检请求须区分。

## 恢复业务

授权页面和本地回调只处理认证，不会自动唤醒或续接已结束的对话。用户回到当前对话回复“已授权”或“继续”时，保留原请求与 profile，先核验原登录进程的结果或当前脱敏认证状态，不重复展示版本选择或发起登录。用户的回复仅表示要求续办，不是认证成功的证据；远程模式尚未通过受控输入提交授权结果时，按上方规则引导完成提交，不在普通聊天索取授权结果。

登录命令返回 `status: authenticated` 后，用 `node scripts/auth-status.mjs --profile <原profile> --environment online` 核对脱敏状态和 `account_id`，身份匹配才继续。不同账号不能接续原任务。

只读请求或有明确证据尚未执行的请求最多重试一次。创建、结束、上传等写入超时或结果未知时先只读核对，不自动重放；已有任务编号时续办原任务，批量不重建成功项。后续仍失败时保留上下文、说明已知原因并按回退规则处理，不循环登录或声称业务已完成。

`node scripts/logout.mjs --profile <名称>` 仅清除该 profile 的独立本地会话和待授权状态，不注销其他产品，也不删除已有云端任务。
