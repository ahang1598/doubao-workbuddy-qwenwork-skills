# 认证恢复与原任务续办

直播与视频共用随包的独立 Node.js 认证实现。仅支持线上 OpenAPI，不需要安装或调用企业直播 CLI。认证目录默认是 `~/.douyin-live-inspect`，部署时可通过 `DOUYIN_LIVE_INSPECT_CONFIG_DIR` 指定独立目录；不会读取旧 CLI 缓存或环境变量中的 AK/SK。Agent 只调用脚本，不读取认证目录中的会话、pending 状态、密钥或 Token。

## 新建直播与视频的账号入口

新建请求的探测、版本选项与作答状态只按 [统一账号入口](../SKILL.md#1-新建直播与视频账号入口分流) 执行，本页负责授权与恢复。

## 何时进入

`auth-status.mjs` 只读取并输出脱敏状态，不联网、不刷新。`authenticated` 可继续业务；`expired` 且 `refresh_available: true` 时可继续原业务，由业务运行时在发送请求前刷新 STS。不能把可续期的 STS 过期当成必须重新登录。`login_required`、不可续期的过期会话或实际刷新失败时才进入认证恢复。

仅上传已有完整复盘 JSON 时直接执行上传脚本，它同样在内部读取独立缓存并刷新；返回 `SETUP_PENDING` 后按本页恢复。普通网络错误、项目不可访问、权限不足不能误报为登录过期；`AccessDenyError` 按下方未开通规则处理。

## 原账号与任务绑定

已有任务的执行上下文固定为 `environment:online`、`profile`、`account_id`、`project_name`、`task_id`。任务查询、结束、监听、复盘准备、上传、下载和收尾均显式携带。项目／场景发现及新建入口保留账号选择方式。JSON stdin 使用上述字段；支持 CLI 的入口使用其 Schema 所列参数，不向 `api.mjs` 追加业务 CLI 参数。

实际执行前校验：缺少原身份返回 `ORIGINAL_TASK_CONTEXT_REQUIRED`；所选 profile 已换账号或任务归属冲突返回 `TASK_BINDING_MISMATCH`，停止业务调用。原身份仅从已有创建结果、监听结果、私有复盘上下文或可信续办记录恢复，不从当前 profile 补成原账号。旧记录不足时保留原任务并说明缺项，不迁移、重建或重传。

首次查询用户指定的历史任务时，先按用户选定的账号建立本次查询上下文，带项目、类型及任务编号查询并核验；查询成功后固定沿用这组身份。此入口不是丢失身份的已有任务续办，不得用它覆盖旧任务绑定。同名任务先以名称、时间、状态选择，内部 ID 仅用于执行。

`dry-run` 只校验业务参数，不认证、不联网；预览结果不能当作原身份凭据。仅生成报告链接的脚本不增加认证调用，也不能证明报告就绪或归属。

## 登录失效后的选择

首次缺少登录且尚未选择版本时，使用入口的首次选择文案，不将“未登录”误报为“登录过期”。本次已选择正式版时，认证缺失、不可续期或实际刷新失败均直接执行下方登录能力检查并发起授权，不再询问 Lite 或登录。其余发现登录态失效的请求，先说明“火山引擎登录态已失效”，按入口的版本选择规则展示一次：标题“选择后续方式”，独立单选标签“使用 Lite（免登录）”和“继续登录火山引擎”，对应说明“无需火山登录。”和“授权完成后回到当前对话回复‘已授权’，继续正式版质检。”。组件参数、异步等待和重复作答处理统一遵循[交付文档的单选状态流程](doubao-delivery.md#版本选择)。

- 用户本次已选择正式版或已针对认证缺失或失效明确选择登录时，直接执行下方登录能力检查，不再询问。历史正式版偏好不代替本次选择；一次登录尝试失败后保留正式版等待续办，不再次循环展示选择或登录。
- 选择 Lite 的新建请求进入 Lite 入口，并遵循 [云电脑推荐交付规则](../lite/references/startup.md#硬约束云电脑环境必须提示本地电脑推荐)，不另行重复提示。选择继续登录时保留来源、场景和进度，登录成功后继续原请求。
- 已有正式任务、创建结果未知、仅查询或报告续办时，选项中须说明 Lite 仅供新的检测，无法接续云端任务。选择 Lite 后保留并暂停本次正式版续办，说明新检测需要来源与创建意图，不把版本选择当作重新检测授权。

## 正式版受阻时续办

已选正式版的直播和视频始终保留原版本、来源、账号、项目、场景和任务进度。认证缺失时引导授权；来源、权限、网络或配置受阻时说明实际原因和恢复条件。恢复后从失败步骤继续。

正式版确实无法继续、已确认尚未创建任务，且 Lite 支持当前来源时，可以提示一次：“你可以稍后继续正式版，也可以回复‘改用 Lite’开始免登录质检。”只有用户明确选择 Lite 才启动。未作答、超时或只回复“继续”都保留正式版。用户已要求仅用正式版时省略该提示。

创建结果未知时先只读核对，不重放写入。批量视频保留已完成项和原顺序。由正在运行的 Lite 切换正式版时，按[切换流程](lite-to-formal.md)保留原任务。

## 正式质检服务未开通

直播与视频共用本规则。质检业务接口（包括项目列表查询）返回业务错误码 `AccessDenyError` 时，按质检服务未开通处理，不要求同时匹配错误文案。登录成功仅代表认证完成，不代表服务已开通；项目列表为空也不能据此判定未开通。

- 停止本轮正式版后续质检调用和任务创建；批量视频暂停尚未创建的任务，保留已有任务与处理进度。不重复登录、不循环重试、不切换账号或项目，也不引导新建项目来解决未开通问题。
- 说明“当前账号尚未开通质检服务”。

- 项目列表为空属于配置缺失，引导配置项目，不称为未开通；其他错误按实际原因处理。

- 保留原账号/profile、环境、来源、项目、场景和任务进度。用户说明已开通并要求继续后，使用原上下文重新查询验证，成功后续办；仍返回 `AccessDenyError` 时如实说明服务仍未开通，不声称已开通或质检已启动。已有任务先核对状态，不重复创建。
- 其他错误码继续按实际认证、权限、配置或网络错误处理，不一概归为未开通。

## 登录能力检查

仅在用户本次已选择正式版或登录、确需重新授权时，从已核验的 Skill 根目录执行 `node scripts/check-login-capability.mjs`。它报告随包的独立登录实现能力，不探测外部 CLI、不发起授权。脚本缺失或 Node.js 无法运行属于安装或运行环境问题，应准确说明并保留业务上下文。

## 主动发起授权

入口已返回 `deliver_authorization_link` 时原样交付 `data.message`，不要重组或转义链接；`await_local_authorization` 沿用已交付的同机链接。

1. 保留原来源、项目、场景、任务、批次顺序、身份和进度。按 [交互与进度](doubao-delivery.md#交互与进度) 说明需要授权，已选择登录时不重复确认。
2. 执行 `node scripts/detect-runtime-mode.mjs` 选择授权方式。用户能在与 Node 回调互通的同机浏览器操作时（包括能接管该浏览器的云电脑），运行 `node scripts/login.mjs --environment online --profile "<原profile>"`，提示用户在该浏览器打开链接。跨设备、回调不可达或回调可达性未知时，运行同一命令并追加 `--remote`。环境探测只用于选择回调方式。
3. 首次收到 `data.authorization_url` 时，立即以“登录火山引擎并授权”为文字交付 Markdown 链接，请用户手动打开。本地登录已在等待、回执只有 `pending` 时，沿用先前交付的链接，继续等待原回调。远程模式交付链接时一并说明：授权后复制火山页面显示的完整 code，回到云电脑的授权结果输入框粘贴并提交。提交方式见[授权结果处理](#授权结果处理)。提示用户完成后回到当前对话回复“已授权”或“继续”，再核验登录态并续办。见[统一宿主浏览器](doubao-delivery.md#统一宿主浏览器)。
4. 本地后台进程最多等待回调 5 分钟。收到回调后继续等待令牌交换与会话保存，页面显示“登录成功”才算完成。
5. 远程模式输出 URL 后立即返回 `status: pending`，这是等待用户授权的正常状态，不是登录成功，也不是失败。内部 pending 状态有效 10 分钟。保留 profile，等待受控授权结果后执行下方续办，不必保持首次命令进程运行，也不要重新生成 URL。

## 授权结果处理

在下述受控输入渠道中，可粘贴火山授权页面提供的 code 或浏览器地址栏中的完整回跳 URL。火山页面提供的 code 是封装后的授权结果（Base64），运行时自动解码；不要因为用户粘贴的内容不是 URL 就拒绝或要求重新复制 URL，也不要要求用户自行解码或提取 state。

运行时接受完整回调 URL、code/state 查询串，或包含这些内容的 Base64 结果，解析后必须包含与本次登录匹配的 state。火山页面提供的完整 code 与从 URL 中单独截取的 OAuth `code` 参数值不同；后者缺少 state，仍不能用于续办。

只在宿主确实提供不记录、不回显的受控授权输入渠道时提交结果：运行 `node scripts/login.mjs --environment online --remote --profile <原profile> --authorization-response-stdin`，通过受控的非 TTY stdin 传入完整结果并关闭输入（EOF）。首次远程命令正常返回 pending 后就使用这个续办命令；不只用于进程中断恢复。授权结果由脚本处理，以返回的认证状态确认是否成功。

上述命令由宿主在后台调用。只向用户展示授权链接和粘贴步骤，不交付终端命令或脚本。宿主未提供授权输入框时，说明当前无法接收授权码，保留本次正式版任务。

- 授权结果不能写入命令参数、普通聊天、临时文件、仓库、报告或日志，不能通过会记录输入的工具冒充秘密通道。脚本要求非 TTY stdin 只是输入约束，不能保证宿主本身不记录内容。
- 不索取 AK/SK、Cookie、Header、Token 等持久凭证，不自行读取、修改 pending cache。
- 本地回调明确拒绝授权时会结束登录；远程结果过期、state 不符、重复参数或授权失败时不继续业务，不循环提交旧结果，也不自动发起另一轮登录。仅取消授权与停止整个质检请求须区分。

## 恢复业务

授权页面和本地回调只处理认证，不会自动唤醒或续接已结束的对话。用户回到当前对话回复“已授权”或“继续”时，保留原请求与 profile，执行 `node scripts/auth-status.mjs --profile <原profile> --environment online` 核验当前脱敏认证状态，不重复展示版本选择或发起登录。用户的回复仅表示要求续办，不是认证成功的证据；远程模式尚未通过受控输入提交授权结果时，按上方规则引导完成提交，不在普通聊天索取授权结果。

本地状态查询的 `data.login.status` 为 `pending` 时继续等待原授权，不重启、不回退；为 `failed` 时按 `data.login.error.code` 说明真实原因：`AUTH_INTERRUPTED` 为后台进程中断，`AUTH_TIMEOUT` 为授权超时，`AUTH_CALLBACK_UNAVAILABLE` 为回调监听失败，`AUTH_EXCHANGE_FAILED` 为令牌交换失败，`AUTH_SESSION_INVALID` 为会话校验失败，`AUTH_STORE_FAILED` 为保存失败，`AUTH_START_FAILED` 为后台启动失败。不得把等待状态当成失败，也不得用旧会话掩盖本轮登录失败。宿主若清理后台进程，应说明该宿主的本地授权受阻，保留正式版等待续办，不循环登录。

本地 `data.login.status: authenticated` 或远程登录命令返回 `status: authenticated` 后，用 `node scripts/auth-status.mjs --profile <原profile> --environment online` 核对脱敏状态和 `account_id`，身份匹配才继续。不同账号不能接续原任务。

只读请求或有明确证据尚未执行的请求最多重试一次。创建、结束、上传等写入超时或结果未知时先只读核对，不自动重放；已有任务编号时续办原任务，批量不重建成功项。后续仍失败时保留上下文、说明已知原因并保留正式版等待续办，不循环登录或声称业务已完成。

`node scripts/logout.mjs --profile <名称>` 仅清除该 profile 的独立本地会话和待授权状态，不注销其他产品，也不删除已有云端任务。

## 失败证据与原任务恢复

按业务回执和退出状态处理失败，普通 Forbidden/AccessDenied 不推断为服务未开通。未知写入先核对原结果，不重复提交；沿用原环境、profile、账号、项目和任务编号，不以当前登录替换原身份。

只有明确内存不足证据才判断 `OUT_OF_MEMORY`，不能仅凭 SIGKILL/137 推断。说明失败阶段与已有结果，释放资源后沿原任务恢复，不盲目反复重启。锁冲突先确认原进程，不按锁年龄删除锁或重建任务。

业务权限以实际接口回执为准。不额外查询用户身份、读取其他产品身份或手工解析宿主 Token，不输出或持久化 Token，不编造身份标识。
