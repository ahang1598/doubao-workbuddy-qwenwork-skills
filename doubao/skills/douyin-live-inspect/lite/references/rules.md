# Lite 核心规则

默认使用5条通用规则：违法违规、色情低俗、暴力危险模仿、绝对化用语、虚假功效。实际内容为带货时追加2条电商专项，为投资分析或投顾时追加3条金融专项。通用规则始终保留，行业变化时可追加另一组专项。

一次阅读本批字幕，结合返回的完整 full_prompt、policies 公共原则及 policy 引用判断；历史快照和自定义规则同时遵循其条件、例外与证据要求。关注明确表达的风险；保留仅提及、否定、历史描述、假设、风险提示等主要例外。语义判断由当前 Agent 完成，脚本只序列化结果。

命中项填写简短原因及真实证据；其余规则由 reviewed=true 的短提交补齐。相同证据涉及多条规则时保留对应命中，报告摘要合并重复事件。结论使用“AI 判定”，仅适用于本次已检测内容。

## 追加专项

通过 review-next 返回的 rules_load_contract 提交 task_id、bundle（finance 或 ecommerce）、segment_id、evidence_revision、reason、evidence_ids、images_viewed，执行 `rules-load --next`。直接处理返回的新合同，不重复领取；已加载专项不重复追加。

使用真实字幕或已查看图片作为追加依据。仅出现“价格”“收益”等词不代表金融场景。追加失败按 error.code 和字段修正，已有规则可以继续使用。

## 规则版本

review-next 返回本任务冻结规则；读过相同版本即可缓存，版本变化时读新规则。旧完整 rules 与 no_hit_rule_ids 格式保持兼容。视频和历史协议沿用其原合同；自定义规则保留完整提示。

对外列出实际应用的规则名称，检测方式为“字幕检测”或“字幕与画面抽检”。

## 维护入口

[直播质检规则](../assets/rules/rules.md)是内置质检口径的唯一维护入口：通用5条、电商2条、金融3条、汽车2条。金融原24类条件与例外保留在专项及通用补充中，金融安全补充仅在金融场景启用。编号、优先级、版本和输出结构由运行时维护；自定义规则仍可追加 JSON，不能替换内置规则。

新任务从 Markdown 生成冻结快照；动态追加专项时同步公共原则并更新版本。旧任务沿用已保存快照，不因修改规则文件重写历史结果。规则为业务审核口径，命中不等于法律最终认定。

[复盘规则](../assets/rules/recap-rules.md)独立评价讲解质量，只引用已完成的质检结论，不重新认定违规。
