# Lite 核心规则

默认使用5条通用规则：违法违规、色情低俗、暴力危险模仿、绝对化用语、虚假功效。实际内容为带货时追加2条电商专项，明确涉及证券市场、金融产品分析或金融业务时追加3条金融专项，明确涉及汽车销售、车型配置或用车能力讲解时追加2条汽车专项。通用规则始终保留，行业变化时可追加另一组专项。

一次阅读本批字幕，结合返回的完整 full_prompt、policies 公共原则及 policy 引用判断；历史快照和自定义规则同时遵循其条件、例外与证据要求。品牌、型号只依据明确口播或已查看画面，不凭销量、优惠或行业常识猜测；证据冲突时标注待核对。关注明确表达的风险；保留仅提及、否定、历史描述、假设、风险提示等主要例外。语义判断由当前 Agent 完成，脚本只序列化结果。

## 统一证据门槛

每条规则快照均带 `evidence_gate`。`direct` 允许由口播或已查看画面独立证明的子项直接判断，不表示其余子项无需核实；销量、资质、价格、渠道或事实真伪仍须逐子项满足依据要求。`counterpart` 表示命中还必须同时提供独立的 `counterpart_evidence_ids`，用于证明同一对象的商品详情、政策、配置、资质、规格或实际事实与宣传冲突。主张证据和对照证据不得复用同一 ID。已定位具体风险线索且决定性对照材料缺失时填 `insufficient`，不能因常识、惯例或“未取得证明”判定违规；正常经营表达没有独立风险线索时不命中，不机械要求商家补证。

提交 `hit` 时，`evidence_ids` 写主张或行为本身；`counterpart` 规则及绝对化用语 `claim_specific` 的事实矛盾分支再写 `counterpart_evidence_ids`。已有疑点需要比对时，先确认商品、版本、门店、活动、规格、时间和使用条件是否一致。内容自身即可成立的违规（例如明确私下交易引导、色情低俗、暴力危险）不等待承接侧材料，但仍必须引用实际口播或已查看画面。

命中项填写简短原因及真实证据；仅字幕短提交由 reviewed=true 补齐其余规则，画面抽检按返回模板逐规则填写。每段独立判断，重复出现仍保存本段实际结论，不因前段已记录填 no_hit；程序按规则分组展示并保留各次证据。例外成立则不命中，已有具体疑点且关键语义决定结论时沿用 insufficient，无需新增字段或额外复核步骤。结论使用“AI 判定”，仅适用于本次已检测内容。

## 判定审计轨迹

需要复核某条结论时，执行 `audit-trace --task-dir <原目录> --segment-id <片段ID> --rule-id <规则ID>`。新提交的 `records` 冻结了当时的 Skill 版本、完整规则 Prompt、提交合同、该段全部字幕与图片时间点、模型原始提交、运行时归一化结论及每项门槛校验；可据此用新 Prompt 或新流程重跑对比。每次成功提交还会写入 `review_decision_trace` 操作日志，便于定位对应记录。

轨迹用于核验可见输入和运行时校验，不输出或假称保存模型隐藏推理。若 reason 出现的关键词不在保存的字幕证据中，或图片事件没有对应的实际画面描述，应将该结论视为证据不充分并回退复核，而不是由日志替模型补充理由。旧任务只有 `entries` 时是由现存结果重建，不能保证可完整复放。

人工复核确认原 `hit` 的事实链不足但仍值得保留线索时，使用 `review-disposition --task-dir <原目录> --input-file <JSON>` 保存 `warning`。JSON 绑定 task_id、segment_id、evidence_revision 和 rule_id，并写明复核原因。它不改写模型原结论或证据；报告与工作台将该项显示为“待复核”，不计入确认风险。复核确认仅有证据缺口时，提交 `insufficient`，风险列表不展示该项。两种处置均保留原始审计记录，证据版本变化后自动失效。

## 追加专项

通过 review-next 返回的 rules_load_contract 提交 task_id、bundle（finance、ecommerce 或 automotive）、segment_id、evidence_revision、reason、evidence_ids、images_viewed，执行 `rules-load --next`。直接处理返回的新合同，不重复领取；已加载专项不重复追加。

使用真实字幕或已查看图片作为追加依据；reason 说明实际对象、讨论或业务行为及其与引用证据的关系，不用“经济相关”替代判断。

新动态任务每段还须填写 `content_route`：`type` 为 `general`、上述专项名或 `undetermined`，`reason` 说明实际业务对象，`evidence_ids` 引用本段依据。`general` 须有证据支持不适用专项；无法确定或没有证据时用 `undetermined`，披露“专项路由未完成”，不能宣称专项已通过。专项追加失败保留加载缺口；旧任务按原合同提交。

汽车专项适用于汽车销售以及车型配置、续航、驾驶辅助、价格或质保的实质讲解，不以已经出现违规为前提；仅闲聊提到汽车不触发。汽车销售可同时追加电商专项，实质讲解车贷时再追加金融专项。驾驶辅助的危险能力保证依据实际口播或已查看画面判定；车辆规格、价格及质保的明确矛盾须有同一车型、版本及适用条件的独立对照证据，缺失时保留证据不足。

金融专项用于证券市场、金融产品的分析、投资决策、金融业务或相关营销，包括贷款、保险、信用卡、非法集资等；正常证券分析也可加载，不以已经违规、荐股、收费或成交为前提。对象可由相邻上下文中的简称、代词确认，不要求股票代码。汽车直播实质讲解车贷、分期融资的首付、月供或利率条件时，也应追加金融专项，但证券营销限制不能直接套用于汽车咨询、预约或分期介绍；先确认具体业务及适用子项。不能因主商品是汽车而只加载电商规则，单纯报车价不据此追加。

仅讨论城市 GDP、产业发展、企业经营、就业择城或生活消费，不足以加载金融专项；“投资”“价格”“收益”等词不是触发器。买房话题不自动归金融，明确涉及房贷或金融产品投资回报等业务时再判断。证据不能确认金融对象或业务时继续通用规则，后续出现明确依据再追加。

已加载专项仍须逐片段核对适用性，结合相关上下文确认对象，不把整场固定为金融场景；话题切回金融时继续使用已加载规则。通用规则始终独立检查。追加失败按 error.code 和字段修正，已有规则可以继续使用。

## 规则版本

review-next 返回本任务冻结规则；读过相同版本即可缓存，版本变化时读新规则。旧完整 rules 与 no_hit_rule_ids 格式保持兼容。视频和历史协议沿用其原合同；自定义规则保留完整提示。

对外列出实际应用的规则名称，检测方式为“字幕检测”或“字幕与画面抽检”。

## 维护入口

[直播质检规则](../assets/rules/rules.md)列出内置质检口径：通用5条、电商2条、金融3条、汽车2条。金融各子项的适用条件与例外统一维护在专项及通用补充中，不沿用历史词表直接判定，金融安全补充仅在金融场景启用。编号、优先级、版本和输出结构由运行时维护；自定义规则仍可追加 JSON，不能替换内置规则。

新任务从 Markdown 生成冻结快照；动态追加专项时同步公共原则并更新版本。旧任务沿用已保存快照，不因修改规则文件重写历史结果。规则为业务审核口径，命中不等于法律最终认定。

[复盘规则](../assets/rules/recap-rules.md)独立评价讲解质量，只引用已完成的质检结论，不重新认定违规。
