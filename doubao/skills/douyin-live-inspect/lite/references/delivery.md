实时与停止时限统一遵循 [Lite 主协议](../SKILL.md#实时策略)。

# Lite 交付

启动前：本机默认 local_dashboard，确认豆包云电脑使用 html_snapshot；云电脑即使收到 local_dashboard 参数也交付独立 HTML 附件。显式 chat 保持；历史 local_dashboard 任务在云电脑按快照交付，不改写保存模式或检测数据。全部为静态 HTML 或 Chat，不启动 HTTP 服务。

启动或恢复返回 delivery_required 时，先真实展示 delivery.message，再执行返回的 after_delivery_next_action；notice_id 对应提示实际展示后才 delivery-ack。准备中不宣称已开始检测。视频只交付进度和最终质检报告，不交付直播工作台。

直播启动时，在对话中保留结束方式提示：“如需结束质检，可以直接对我说‘结束质检’。我会停止采集，并基于已检测内容继续生成质检报告和复盘报告；请等待报告交付后再关闭任务，直接关闭可能导致报告未生成。”工作台、HTML 快照和 Chat 模式均需展示，不能仅以页面内提示代替。

## 豆包启动后必须交付控制台 HTML

直播 start 成功后，即使仍在 preparing，也必须先在当前对话中实际返回已就绪的 `monitor.html` 可点击入口，再继续补流或判定。本地模式使用返回的原始文件路径生成 Markdown 链接，例如 `[打开实时质检控制台](<返回的 monitor.html 绝对路径>)`；云电脑使用宿主附件工具展示 HTML 文件卡片。不得只输出纯文本路径、代码块，或仅说“已打开”“请手动打开”。尝试打开侧边栏不能代替聊天中的入口。

确认消息中已展示可点击链接或文件卡片后，才执行对应交付确认；不能把文件存在或工具返回路径当成交付成功。HTML 未就绪、宿主交付失败时明确说明“控制台 HTML 尚未交付”及原因，按下方降级继续原任务，不伪造成功；显式 Chat 模式和视频任务沿原交付规则。

## 静态 HTML 与云电脑附件交付

### 云电脑提示“该文件不存在”时

用户反馈工作台链接打不开且已确认使用云电脑时，先保留原任务，不重新 start，不要求切换电脑才能继续。云电脑路径或 file URI 不代表用户电脑可访问，也不能据此断言任务目录已丢失。

1. 从本次任务上下文取得原 task_dir，先 status 核对任务是否存在；不猜测目录，不读取其他产品缓存。原目录确实不存在时说明无法恢复该任务，请用户提供原任务信息。
2. 原任务存在时执行 `snapshot --task-dir <原目录>`，包括保存模式为 local_dashboard 的历史任务；补导出不改变原任务模式、采集或已保存判定。
3. 将返回的 ready monitor HTML 通过宿主附件能力实际交付，并说明这是生成时的快照，不会实时刷新。不能再次把 snapshot_delivery.path、云电脑绝对路径或 file URI 当成可点击工作台链接。
4. 宿主没有附件能力或附件交付失败时，如实说明尚未交付文件，先在当前对话展示原任务的进度与已有风险，继续原任务判定；保留导出文件用于后续重试。不要宣称已打开工作台或停止质检。

- `local_dashboard`：启动即交付 `monitor.html` 文件链接。必须打开任务目录中的原始 HTML，且保留同目录 data.js；单独上传或复制 monitor.html 到附件沙箱会断开实时数据，不把这种附件承诺为实时工作台。用户首次要求结束时执行原任务普通 stop，停止新增采集，按收尾预算处理剩余内容，再交付双报告结果。
- `html_snapshot`：新云电脑直播仅开始、必要恢复和采集结束时交付快照，不交付周期快照；旧任务仍每满5分钟交付。需要快照时命令返回 `snapshot_events`、`artifacts` 与 `delivery_required`。当前 Agent 先通过宿主附件工具交付 monitor 类型 HTML；运行中的新增风险及时通过 Chat 提示，合并到下一份快照，不为每次命中额外导出 HTML。旧任务的五分钟周期以最近一次成功导出为起点；开始、恢复和采集结束不受周期限制。收到快照后立即通过宿主附件能力交付 snapshot_delivery.path，并在对话给出用户可点击的预览或下载入口；不能只说“已生成”，不能把云电脑绝对路径或 file URI 当作用户可访问链接。附件交付失败或宿主无附件能力时，保留本次路径，在对话交付进度并立即继续判定，不循环等待附件。后续渠道恢复且需要补交时复用该文件；文件不可用才调用 `snapshot --task-dir <原目录>` 补导出，不重新提交判定。旧 HTML 是固定快照，不会自动更新；没有宿主预览能力时交付下载附件。
- `report`、`recap-report` 默认生成 quality、review HTML，样式、脚本、文字和证据图片内嵌，回放共用 `media/` 下的原始 MP4，不默认生成 ZIP。质检报告就绪后立即交付，复盘随后单独交付，不等待两份一起返回。本地直接打开报告链接；移动或下载报告时，须同时交付返回的 media 附件并保留相对目录。云电脑通过宿主附件能力交付文件，在对话给出实际下载入口，不能发送云电脑绝对路径或 file URI；宿主无法保留目录时说明回放限制。仅显式 `--single-file` 内嵌视频，适用于需要单文件交付的小报告。未保存回放时明确说明缺失；导出失败直接交付 Chat 报告正文，不等待附件。
- `artifact_status=failed` 表示文件导出失败，不是质检失败；保留已保存判定。直播启动/运行中在对话交付进度并继续原动作，报告阶段交付完整 Chat 报告正文；视频保留原导出重试流程。没有实际 ready 的产物不能宣称附件已交付。
- 云电脑不自动发布应用、上传公网或启动服务。显式 chat 和已有 chat 任务仍按原对话流程交付。两种 HTML 模式均不改变 Python 3.10+、ASR、MediaKit、逐段判定和视频不复盘的边界。

## Chat

`chat` 仅改变展示方式，不改变检测范围和判定规则；显式 Chat 无需解释为工作台故障。因 HTML 失败降级时简短说明该页面未交付，不把本地路径或端口作为可访问入口。

- 启动或恢复时按上方硬约束完整交付 `delivery.message` 并确认提示交付；云端 Chat 继续当前质检流程，不承诺后台常驻服务。
- 状态有实质变化时简短更新；无变化不重复播报。只展示运行状态、实际风险、必要操作和报告结果。没有有效判定时说明“检测未完成”，不能表示零命中通过。
- 风险更新包含相对时间、规则名称和简短证据依据；采集中说“当前已发现”，不提前给出最终无风险结论。普通片段不逐条输出长摘要。
- `report` 返回 `delivery.type=chat_report` 时，必须在当前对话交付 `report` 中的时长、应用规则、命中及证据，结论只限已检测内容。`report_url` 为空是该模式的正常结果，不称为报告或面板生成失败。
- 若当前宿主不能保证 Agent 持续执行，明确说明本次任务依赖当前会话继续运行；不得承诺离线唤醒、跨设备页面或无人值守后台通知。

## 报告确认与完成条件

- 直播 `report` / `recap-report` 的 `delivery.report_kind` 标识当前质检或复盘报告；文件交付使用 `delivery.path`、`artifact_type` 和 `version`，不能用同一结果里的 monitor 工作台代替，也不能直接读取 data.js 拼聊天摘要后宣称报告已交付。默认交付对应 quality/review HTML 及返回的 media 附件，保留相对目录，不打包 ZIP；沿用现有模板，不用聊天摘要替代已就绪报告页。大结果完整读取 result_file 或沿分页读取，禁止用 `head` 截断 JSON。只有明确 Chat、导出失败或宿主附件能力不可用/交付失败时降级完整 Chat 正文，并说明报告页未交付。
- 当前实时直播质检 ready 后即可执行 `recap-input --begin` 开始复盘计时，不以质检交付回执为前提。可重试的复盘失败只续办，不确认失败交付；终态失败才交付原因并确认。报告链接取对应 quality/review 产物，不通过替换文件名推导。
- 质检 ready 后立即在中间消息交付，直播继续 [复盘](recap.md)，视频不复盘。无媒体的 NO_CAPTURED_CONTENT、全静音 NO_SPEECH 或全程无文字 NO_USABLE_TRANSCRIPT 交付真实终态，不生成空报告；已检测内容直接用于两份报告。
- 直播 review_protocol=lite_review_v2：实际展示 quality 或 recap 后，用 report/recap-report 返回的 delivery_ack_contract 和 evidence_version 写入 JSON，再运行 report-delivery-ack --task-dir <原目录> --input-file <文件>。输入为 {"kind":"quality或recap","evidence_version":"返回原值","outcome":"ready","channel":"file或chat"}。失败结果实际交付后可用 outcome=failed、channel=chat 记录；可重试失败继续按预算重试；仅业务合同允许的终态 blocked 或 terminal_failure 才确认失败结果；输入修复的 recovery_blocked 不属于失败交付条件。终态失败的 workflow_outcome=failed，不能声称成功产出报告。两份实际交付确认前 workflow_complete=false，产物就绪不是交付成功；历史无回执协议的产物状态也不能证明已发消息。
- 视频静态报告：实际交付本次版本后，以 {"version":返回版本,"status":"delivered"} 调用 report-delivery-ack；附件失败使用同版本 status=failed，保留原产物重试交付，不重新判定。缺少宿主附件能力保持 pending/failed。
- 回执 `channel` 必须符合实际交付渠道；附件未发出时不能确认 file。`report_deliveries` 保存实际渠道，Chat 交付不能描述为已交付报告页；历史回执缺少 channel 时不推断为文件交付。
- 当前直播在自然结束、断流重试耗尽或普通停止后，剩余质检队列按120秒无进展窗口有限恢复，总上限本地15分钟、新云电脑3分钟；排空或恢复耗尽后基于已检测内容生成、交付质检报告，并继续复盘。该时限不包含复盘生成与报告交付；批次无进展、积压舍弃按[实时策略](../SKILL.md#实时策略)。报告说明判定与舍弃数量、范围、原因，证据不足和未检测不能当无风险。明确立即舍弃沿用原行为，历史已完成报告不重开。
- 阶段性进度只能用中间消息交付，发出后继续判定；空批次和用户未回复都不能以最终回复结束任务，也不能要求用户再说“继续判定”才能完成原请求。质检报告及时交付，复盘独立生成并交付，分别确认后以 workflow_complete=true 结束。无有效内容时交付真实失败结果；只有宿主真正中断或工具受阻无法继续时说明原任务续办，不承诺后台自动分析或唤醒。

## 生成与交付独立续办

质检 ready 后按 `generation_next_action` 生成或复用复盘，按 `delivery_next_action` 补交未交付结果。导出、附件、页面或回执失败时保留原产物和待交付状态，继续可执行的报告生成；HTML 不可用则交付完整 Chat 正文，不能仅发进度后要求用户说“继续”。局部采集、ASR 或判定失败沿现有收尾预算使用已检测内容并披露缺口；无有效证据仍如实说明失败或内容不足。用户明确取消整个流程时停止自动接续；仅停止采集仍按原停止合同收尾，不重启采集。

### 阻塞恢复与跳过

同一阻塞先沿原任务的已有恢复动作和次数预算自动尝试，不要求用户再次说“继续”。以下降级适用于当前实时直播；视频按 [视频流程](video.md) 及其回执续办。恢复耗尽后，仅跳过非必要环节并继续可生成的报告或失败说明：

- HTML 导出的超时和一次重试由运行时负责，Agent 不叠加重试；收到失败回执后按 `fallback_action` 直接展示已保存的完整报告正文，说明 HTML 未交付，继续另一份报告。复盘正文使用 `recap-report.document`，质检正文使用 `report.report`，不从工作台拼造结论。
- 工作台、附件或页面不可用：跳过该展示渠道，使用已有 Chat 降级；回执按实际渠道确认，不重复采集、判定或生成同版本报告。
- 部分采集、ASR 或判定失败：沿原收尾预算使用已检测有效片段，报告披露遗漏范围和原因；不得将未检测片段标为通过。
- 用户明确取消整个流程立即停止。证据读取、内容校验、必要权限及任务绑定不能跳过；缺少有效依据时交付真实失败或内容不足说明，保留失败原因，不记成功。

## 诊断按需提供

默认只交付质检、复盘报告及其覆盖缺口和原因，不附带内部诊断 HTML，不展示诊断 JSON、调用帧或内部执行平台。`capture_failure` 默认只含面向用户的影响说明；工作台快照也不内嵌详细诊断。

仅当用户明确要求排查或索取诊断时，执行原任务的 `status --include-diagnostics`，按返回的 `diagnostic_delivery` 提供脱敏诊断。附件失败则简述原因并继续原 `next_action`；不为诊断重启采集、扩大权限或阻塞报告。诊断不计作质检或复盘报告交付。

启动/恢复的工作台或运行中的快照不可用时，按返回的 Chat 降级继续，不等待页面修复。此规则适用于 Windows、Mac 和云端；已检测内容仍须交付并披露缺口，零有效内容交付失败说明，不继续空轮询。

任务恢复或报告变化后重新获取、交付当前报告，不沿用恢复前的回执；旧安装的无轮次回执须重新导出。仅使用 Lite 交付命令，不额外执行正式版交付脚本。辅助日志失败不升级为采集失败。

最终 HTML 导出失败后保留原任务，沿原报告命令重新导出；旧文件存在不代表最终内容已更新。实际展示成功后再确认交付。
