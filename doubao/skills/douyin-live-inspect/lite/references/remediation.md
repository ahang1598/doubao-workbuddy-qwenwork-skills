# 整改分级

仅为已确认的问题补充整改依据，不重新判定合规，不评分，不推断成交或互动效果。整改结果在检测结束后的报告展示，规则自身的 priority 不等于整改等级。

每个质检命中事件须复制 `submission_contract.event_template` 并补齐其中的 `remediation`；复盘一般问题的 `remediation` 同样填写：`object`（具体对象与配置/条件）、`issue`（具体问题）、`condition`、`reason`（该条件为何成立或缺少什么）、`action`（有依据的改法）。使用返回合同的模板，不填写等级；等级由程序计算。证据沿用事件或问题的 evidence_ids。同对象、同问题、同改法采用一致表述，以便汇总，不能为合并而省略不同事实。

| 来源 | condition | 依据与结果 |
| --- | --- | --- |
| 合规命中 | dangerous_instruction | 已命中 DY_BASE_001_P0 或 DY_BASE_003_P0，且证据明确是危险行为教学或鼓励模仿 → P0 |
| 合规命中 | driving_substitution | 已命中 AUTO_LOCAL_001，且明确保证驾驶辅助可替代驾驶责任 → P0 |
| 合规命中 | illegal_transaction | 已命中 DY_BASE_001_P0、DY_ECOM_001_P1 或 FIN_CORE_003，且明确引导参与该规则所列非法交易 → P0 |
| 合规命中 | standard | 无上述紧急条件的其他合规命中 → P1 |
| 合规命中 | urgency_unknown | 已确认命中，但缺少判断紧急条件的关键依据；reason 说明缺口 → 待核实，不撤销已有命中 |
| 内容运营 | decision_or_operation | 有明确证据影响购买决策或操作执行，如同配置价格矛盾、关键步骤说错 → P1 |
| 内容运营 | expression | 无新增信息的重复、术语未解释、衔接生硬等表达问题 → P2 |
| 内容运营 | uncertain | 无法确认问题影响，说明待补充依据 → 待核实 |

P0 必须基于完整上下文和当前事件的真实证据。危险词、规则标题、发生次数、风险提示或否定引用不能作为紧急条件。P0 的 action 优先说明人工复核、停止复用相关内容并纠正表达；不要求停止整场直播。

复盘 problems 若仅引用已有合规命中，填写 `compliance_rule_id`，并引用对应命中的 evidence_ids，不另填运营分级；从 remediation_context 获取可引用命中。一般运营问题不填写该字段。相同证据支持不同问题时分别说明，不能仅因时间重合认定是同一问题。

普通聊天、致谢礼物、唱歌无口播不构成整改理由；短片段没讲售后不代表全场没讲。无画面不评价视觉，无成交或评论数据不判断转化和互动效果。整改动作不得补造价格、权益、资质或参数。合规证据不足由程序单列待核实，不生成确认违规或虚构原话。

缺失或无效的分级资料显示“未分级”，须结合原始证据补齐，不以规则 priority 代填；紧急性或证据待确认显示“待核实”，检测尚未结束显示“待分级”。
