# 证据与凭证恢复

本文件仅在 ASR 或凭证异常时读取，命令工作目录为 Lite 根目录。当前直播按下述采集／收尾状态续办；视频按[视频流程](video.md)和原回执恢复，历史任务保留保存的后端、预算与上传权限，不套用新直播默认策略。

### ASR 区间恢复与证据不足

- 采集中且未冻结：按回执恢复受影响区间，继续其他就绪内容。
- 当前直播已停止采集但未冻结：在原收尾预算内继续识别与判定已采集媒体；运行时可按 `processing_only` 恢复 worker，不重开采集。
- `media_frozen=true`：不再恢复媒体或补识别，只按有效合同与 `next_action` 完成剩余判定、报告和交付。
- 缺文字不等于没有质检证据：有效画面仍独立判定；质检是否可交付以 `report_ready` / 阻塞回执为准。复盘无可用文字时交付其阻塞原因，不用画面猜写话术。

新任务默认 remote_first，远端失败、超时或运行时确认存在语音缺口时，本地已就绪模型最多补识别一次，保留成功字幕及原时间轴；静音不补识别。后续远端探测与冷却由运行时管理，认证拒绝须待凭证变化。Agent 不重置次数、不等待模型下载、不自行切换或重试。显式 local_first/local_only 和历史模式沿用任务设置，不新增上传权限。新任务整段模式与旧逐句模式不互迁。检测到语音但无文字须披露语音缺口；已终结证据不承诺自动恢复。

`submission_unknown` 保留提交记录，不重传；已知远端ID沿原协议查询。接管或区间已结束后拒绝迟到云端结果。两端失败只结束该区间语音尝试，记录 `asr_status=failed` 与缺口，画面仍须判定。静音且未检测到语音是正常无语音；没有音轨保留 `no_audio`。前后成功字幕不因中间一句失败被删除。

收到 `ASR_EVIDENCE_MISSING` 时读取最新证据，依赖缺失语音的规则提交 `insufficient`，禁止空字幕直接 `no_hit`。失败区间不阻塞后续就绪单元。旧任务历史 `SEGMENT_SKIPPED` / `ASR_RETRY_EXHAUSTED` 继续按返回结果披露跳过范围。

恢复是否成功以片段业务回执为准，切换后端不代表恢复完成。`ASR_BACKUP_TIMEOUT` 表示备用模型接管超时，`ASR_RUNTIME_UNAVAILABLE` 表示模型不可用；失败时分别披露云端原始原因与本地恢复结果，保留缺口并继续其他就绪片段。

## 凭证与未知提交

- 回执要求 `refresh-credentials` 时，在新一次宿主工具调用中执行，只从当次宿主环境读取并保存私有凭证，不输出值，然后按回执 status 续办原任务。凭证缺失不能用空字幕冒充识别成功。已标记 CLOUD_ASR_AUTH_UNAVAILABLE 且没有远端任务 ID 的失败片段属于未提交，可在凭证更新后重新排队，或在本地备用模型可用时恢复处理；已封存任务不改写已封存报告。上传地址响应缺少 result 本身不证明凭证失效，不据此阻断整场任务；未知提交在本地备用完成前保持待恢复，不重复上传。
- ASR 提交异常先读取 `status` 的 `pipeline.asr`：`cli_failed` 只表示未分类的 CLI 错误，限流、网络错误或超时也不能证明远端未建任务。不得仅凭稍后手动成功断言服务端故障或“同一环境”；后台使用任务目录的凭证快照。`resume` 不重放未知提交，`refresh-credentials` 不会重新排队 `cli_failed` 片段；只按运行时回执执行有界宿主刷新，不自行循环刷新或重试上传；上传地址异常触发核验不等于认证失效。
- 已从可信任务记录核实某个远端 ASR ID 确实对应本片段原音频时，可执行 `asr-reconcile --task-dir <原目录>`，stdin 为 `{"task_id":"本地任务ID","segment_id":20,"remote_task_id":"已核实的远端任务ID","confirmed_same_audio":true}`。仅处理已记录提交失败诊断的未知提交；没有诊断的预提交标记可能仍在执行，不允许关联。该确认字段表达已完成的音频归属核验，不能根据 ID 格式、字幕相似或查询成功推断，不能自行重传音频以获取新 ID。命令只查询已有任务，不上传、不重新提交；completed 后写回原片段并使旧判定失效，继续 review-next 和报告/复盘流程。remote_pending 时保留原状态，稍后可再次核对；query_failed 时按安全诊断处理。远端 ID 未知或归属无法核实则不猜测 ID、不修改数据库；remote_first 或 local_first 的云端处理可由 worker 本地接管。已接管片段返回 local_takeover，不导入远端结果。已封存的本地直播返回 inspection_finished，不能用此命令修改已封存报告。

部分切片因 MediaKit 上传异常（如响应缺少 result）无法处理时，只记录这些切片的错误和未检测范围，不得因此中断或阻塞整体质检。继续处理其他可用切片，并结合已有切片的质检结果产出报告与复盘；有多少内容就检测多少内容，在报告中说明未覆盖范围，不等待所有切片成功。
刷新必须在豆包新启动的工具进程执行；后台旧进程环境不会自动续期，明确鉴权阻断时，重复保存同一凭证不能解除暂停。refresh-credentials 只导入宿主提供的凭证，不签发凭证；冻结或已完成任务不因刷新重开媒体处理。仅停止采集且仍在收尾的任务沿原回执恢复已有媒体，不重新采集。

依赖安装的提示与预算见 [启动](startup.md)。setup_pending 需展示阻塞原因和实际 retryable；显式重试沿用原任务，批次保留当前项，不循环启动。

## 本地备用识别不可用

查看原任务 `status` 返回的 `task` 中的 `local_backup_status`、`local_setup_error` 和 `model_preparation`：

- 缺依赖或依赖版本不符：运行时按[启动说明](startup.md)在后台准备独立环境；失败时展示安全原因，环境修复后沿原任务显式重试，Agent 不另行安装或循环重试。
- 模型下载、校验或准备进程失败：展示具体错误，按现有准备与重试入口沿原任务恢复，不另建任务；原因未知就说明未知。
- 正在准备：直播上传地址失败直接保留缺口，不等待准备；其他场景沿用运行时短暂接管等待，不按失败片段重复安装或下载。

两端都不可用时，明确告知“语音识别暂不可用”，说明受影响范围，继续处理其他就绪内容并保留已完成结果。即使连续多个片段失败，也不询问“结束出报告／继续等待恢复”，不暂停判定循环；无就绪内容时沿回执的 next_action 和 wait_command_argv 等待，由运行时管理后续探测及采集终点。只有用户要求停止或运行时进入收尾时才按原流程收尾；宿主工具确实受阻则保留原任务并说明阻塞。复盘无可用文字时说明阻塞，不用画面猜写话术，也不承诺已终结片段自动补回。
