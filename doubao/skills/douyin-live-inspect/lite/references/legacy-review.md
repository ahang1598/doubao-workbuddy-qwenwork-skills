# 历史任务协议

仅无 lite_review_v2 标记的已有直播按其已保存 inspection_policy 读取本文件；不迁移、不补跑已跳过窗口。新直播读 [当前流程](live-review.md)。

## 历史全量直播 lite_live_full_asr_v1

没有 review_protocol 时保持旧提交合同：review-next --limit 2，有一段立即处理，不为凑批等待。回传 batch_id、generation、task_id、segment_id、evidence_revision，每规则按 modalities 提交 channels 及完整依据；只读返回图片，前30秒 context_subtitles 仅作上下文，不计本批覆盖。缓存规则仅限当前 Agent 已完整读取的同版本规则。

默认串行；宿主真实并发、指定证据读取、结构化返回、观察与取消全部验证后，按 [调度协议](live-dispatch.md) 的历史阈值启用子任务。未验证且最老等待超过120秒可 --limit 4。语音能独立支持的命中不因缺图变为不足，依赖画面且缺失的条件为 insufficient；迟到画面不覆盖既有语音命中。

当前运行时的全量直播普通停止持续排空，明确立即停止才跳过剩余内容；已经封存的历史状态与报告不重开。以原任务 finishing/next_action 为准，复盘沿 recap-input 分页，不读取 sample 窗口。不要套用下节抽检超时策略。

## 历史抽检直播（lite_sample_v1）

仅适用于已保存此策略的旧直播；本地视频读 [视频抽检](video.md)，新直播读 [当前流程](live-review.md)。不改变旧任务策略，不重开已封存报告。

- 按返回的抽检窗口领取、判定和提交，字段见 [抽检合同](video.md#抽检合同)。已有任务继续使用保存的识别模式和采样参数。
- 旧策略优先处理较新的内容，允许运行时跳过积压或在收尾超时后结束。Agent 不自行裁剪音频、清队列或补跑已跳过窗口，始终按返回的 finishing 和 next_action 执行。
- 报告披露抽检范围、跳过、超时和证据不足；跳过不算通过，无命中只能表述“本次抽检范围内未发现规则命中”。
- 先交付质检报告，再用返回的有限 recap_input 完成复盘；不额外读取全场素材补判。大结果必须读完整后再执行原 next_action。宿主中断时保留原任务供恢复，不承诺自动唤醒。

## 历史逐段协议

仅用于既非 lite_review_v2 也非 lite_sample_v1 的历史任务；历史全量任务沿保存的 full_live 合同，禁止套用本节的逐句或抽检参数。

本节逐段示例仅适用于未冻结 lite_review_v2 的任务。新协议任务使用 [当前直播](live-review.md)。

1. 执行 `review-next --task-dir <原目录> --limit 5`。返回 `segments`，一句就绪即可领取，最多5个；省略 limit 仍返回单个 `segment`。按上节检查是否需要追加行业专项；不需要时直接判定。其余返回 segment 为空时读取状态；有未完成采集/媒体处理时每3秒继续一次，当前 Agent 不活跃时保留任务供续办，不承诺自动唤醒。
2. 对每个返回单元分别保存 `task_id`、`segment.id`、`segment.evidence_revision`。首次读取完整冻结 `rules.rules` 并记住 `rules.version`；后续领取/提交追加 `--known-rules-version <已读取版本>`，匹配时返回 `rules.cached=true` 和规则ID列表，直接复用已读规则，不重新打开规则文件。版本不同会返回完整规则，须重新读取；上下文压缩、重启或无法完整记得规则时不传该参数，重新获取完整规则。不要使用后来修改的源规则覆盖已有任务。
3. 读取 `segment.subtitles`，对照 `segment.image_checklist` 整理全部图片（旧输出沿用 frames），清单不代表已经查看。用宿主图片工具实际查看 `task_dir` 下 `segment.frames[].path`。宿主支持多图或并行图片读取时，同一轮批量查看本段全部图片；不串行一张图一轮播报，不减少抽帧覆盖。同一会话已实际看过且证据未变化的图片，可复用观察，无需重复加载。只登记实际看过的图片ID，不能仅凭文件存在声称看过。字幕时间和帧时间均为采集相对毫秒。
4. 提交必须覆盖通用规则及已加载的行业专项，不能只提交金融专项或将通用规则整体标为不适用；每条仍按自身适用条件和证据判断。对每条冻结规则给出一次 `hit/no_hit/not_applicable/insufficient`，原因必须有语境依据；缺ASR、缺帧、未看图或无法确定时使用 insufficient。命中引用本次领取的真实证据ID，不编造时间或原文。模型不得根据关键词直接替代完整规则条件。
5. 通过 stdin 向 `review-submit --task-dir <原目录> --next --limit 5 --known-rules-version <已读取版本>` 提交以下对象（使用 JSON 序列化写入，不手工拼接引号）：

```json
{
  "task_id": "返回的任务ID",
  "segment_id": 1,
  "evidence_revision": 1,
  "images_viewed": ["frame-1-0"],
  "rules": [{
    "rule_id": "本次规则ID",
    "status": "hit",
    "reason": "结合语音与画面给出的判断依据",
    "events": [{"evidence_ids": ["asr-1-0", "frame-1-0"], "description": "实际观察到的画面描述"}]
  }]
}
```

示例只展示单条规则；真实提交须覆盖完整冻结规则。非命中 events 为空数组，命中必须有证据；含图片的命中必须提供观察描述。字幕证据的原文和事件时间由运行时绑定，不由模型填写。视觉路由规则只辅助定位，不计为独立风险。

6. 单 Agent 判定不使用租约、领取凭证或续租。重复 review-next 会返回最早的就绪待判片段，不会跳过当前片段，也没有180秒提交时限。提交携带读取时的 `evidence_revision`，不能猜测或自行递增；返回 `EVIDENCE_CHANGED` 时重新读取并核对更新后的证据。`FRAMES_NOT_REVIEWED` 表示需补看图片或对证据不足作出说明，`RULES_INCOMPLETE` 表示按本任务规则补齐；不将这些错误解释为锁定，不等待租约过期。

严格遵循返回的 finishing 和 next_action：直播普通停止、自然结束或达到指定时长后，继续领取并提交剩余判定，不设整体收尾时限；运行时允许交付后再生成报告和复盘。只有本地视频主动停止使用媒体收尾30秒、随后判定30秒的上限，不等后台模型下载；本地视频自然读完时排空完整文件。返回 inspection_finished 时不重试、不 resume 积压、不重新采集，按 next_action 交付。报告就绪后不得继续质检循环。立即停止或视频收尾到期的未检测范围须披露，不伪造判定或声称全部通过。

单段领取时判完立即提交；批量领取时看全本批图片、逐段判定后一次批量提交，不为凑满5段等待新证据。优先直接处理返回的 `next` 片段，不再单独调用读取命令。只有没有就绪片段才等待3秒，有积压时连续判定。返回 `retry_review_next` 表示本次提交已保存，单独调用 review-next 即可。旧任务遗留的 claimed 状态也可直接读取，无需等待；旧格式提交缺少 evidence_revision 时重新读取一次，使用新格式提交。

异常 ASR 恢复按 [证据与凭证恢复](evidence-recovery.md) 处理；缺语音不能提交 no_hit，不能把未知提交当作未提交而重传。

批量提交格式为 `{"task_id":"当前任务","segments":[单段对象,单段对象]}`，每项仍包含 segment_id、evidence_revision、images_viewed 及完整 rules。逐项校验保存，读取 `results` 及 `saved_count/error_count`；batch_saved 只表示批次已处理，不表示全部成功。按每项 code、message、next_action 修复，仅重试失败项，不回滚成功项；重复提交幂等。图片未看全、缺规则、缺语音和证据变化分别处理，不猜测 INVALID_REVIEW 的原因；未知格式错误按合同修正。单 Agent 顺序分析，不并发启动多个判定 Agent。`context_subtitles` 仅为前30秒最多10句已定稿上下文；不能只引用历史内容重复报风险，每个风险必须包含当前单元证据。临时字幕不作为证据。

### 判定效率

每段一次性结合字幕和已看图片判断全部核心规则，直接生成结构化结果，不逐条展开规则分析或反复输出“读取完毕/正在判定”。未命中或不适用用简短、针对当前证据的原因；命中和证据不足保留必要细节。正常处理主要更新监控台；按宿主要求简短汇报整体进度、实际风险或阻塞，不逐段撰写长摘要。不得以加速为由跳过图片、漏交规则、用关键词匹配代替判断或把证据不足标成无风险。

本地持续读取16kHz单声道 PCM，约100ms传输块；500ms静音后定稿，连续讲话20秒形成续接单元，保留解码上下文。停止/断流/文件结束 flush 尾句。录像分块只用于存档，不等待封片；MediaKit 正常识别仍按约30秒音频批次，结束提交尾段。本地视频按处理能力读取，不模拟实时播放。每500ms缓冲画面，单元保存句内首尾及原抽帧间隔画面；无语音每10秒形成视觉单元，缺图如实标注。运行时 status 区分已采集、已识别、待判定、已判定；语句结束至证据可领取P95目标3秒，Agent判定耗时单独计算，不承诺宿主始终实时跟上。
