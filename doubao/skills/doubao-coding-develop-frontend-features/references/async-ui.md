# 异步界面

## 保持结果归属

- 为每项工作识别其用户意图和界面上下文；意图或上下文变化后，旧结果不得更新当前数据、错误、进度或通知。
- 在每个异步完成入口重新确认提交资格；同一结果涉及的数据和状态使用同一资格，避免旧工作清除新状态。
- 停止底层工作与撤销提交资格分别处理；无法取消不代表仍可提交。

## 管理资源

创建异步资源的一方负责在同步失败、完成、取消、销毁和迟到建立时结束工作并清除自身引用；后续动作不得再操作已结束资源。

## 选择重叠机制

1. 对每个可重叠动作声明拒绝、替换、合并、排队或并行策略，并确定外部副作用资格的归属方。
2. 分开建模意图资格与工作生命周期。入口先同步消费资格，再开始工作；完成、取消与清理只能结束工作并发布仍归属该资格的结果，不能恢复资格。控件禁用只表达状态，不能充当同步准入门闩。
3. 平台把一次用户动作拆成多个入口事件时，先从入口事件对象取得文档化的序列标识、连续激活计数或高层手势边界，并把该证据传入准入判定，不得由无参适配层丢弃。同一序列仅首次入口可消费资格，即使工作已经结束；仅边界后的新序列获得重试资格。
4. 没有可靠序列边界时，改用旧输入无法抵达的新上下文或显式恢复转换；不靠任意时间窗或自造指纹。界面防重不替代外部系统幂等。

## 证明关键顺序

合同涉及复合激活时，用高层用户动作驱动器生成完整序列，禁止用多次单事件 helper 冒充。用可控调度让首次工作在同一序列中仍挂起、成功或失败：副作用次数不得随完成时机改变，恢复后的新序列仍可重试。逐个审计完成、取消与清理分支；不用真实延迟或任意 sleep。缺少任一证据时，停止交付并报告未验证。
