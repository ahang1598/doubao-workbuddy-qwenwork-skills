## 一、安全原则

### 1.1 核心安全原则（零容忍）

**🔴 铁律一：OAuth Token 绝对不能明文出现**
- ❌ 禁止在对话中输入或输出 access_token / refresh_token
- ❌ 禁止通过命令行参数传递 token
- ❌ 禁止通过环境变量传递 token
- ❌ 禁止在代码示例、配置示例中写明文 token
- ✅ **唯一允许方式：由MCP客户端安全管理，自动注入请求**

**🔴 铁律二：授权码（auth_code）绝对不能明文出现**
- ❌ 禁止在任何场景下在对话中出现授权码
- ❌ 禁止通过任何方式传输授权码（聊天、命令行、环境变量）
- ❌ 禁止在任何文档、示例中写明文授权码
- ✅ **唯一允许方式：由MCP客户端在授权流程中自动处理**

**🔴 铁律三：凭证由平台统一安全管理**
- 平台关联模式下，所有 OAuth 凭证由豆包平台统一安全管理，自动注入请求
- 脚本和 Agent 均不接触、不存储、不缓存 Token
- 无需本地配置文件、本地加密存储或手动凭证管理
- 配置文件中所有敏感字段使用占位符示例

### 1.2 风险等级

| 信息类型 | 风险等级 | 处理方式 |
|----------|----------|----------|
| Access Token | 🔴 极高 | 绝不在对话中出现，加密存储 |
| Refresh Token | 🔴 极高 | 绝不在对话中出现，加密存储 |
| 授权码 (auth_code) | 🔴 极高 | 绝不在对话中出现，一次性使用 |
| OAuth Client Secret | 🔴 极高 | 绝不在对话中出现，加密存储 |
| Advertiser ID | 🟡 中等 | 可脱敏展示（如****1234），不完整输出 |
| 广告数据 | 🟡 中等 | 提醒用户保密，不对外分享 |
| 分析结论 | 🟢 低 | 可正常展示，但提醒内部使用 |
| MCP 端点 URL | 🟢 低 | 可公开，是官方公开地址 |

## 二、本地配置文件规范

### 2.1 配置文件位置

**唯一合法路径**: `~/.tiktok_ads_mcp/config.json`

**目录结构**:
```
~/.tiktok_ads_mcp/
├── config.json          # 主配置文件（不含 Token）
├── tokens/              # OAuth Token 存储（加密）
│   └── tiktok_ads.enc   # 加密的 Token 文件
├── cache/               # 数据缓存目录（可选）
│   └── report_cache/
└── logs/                # 日志目录（可选）
    └── mcp_calls.log
```

### 2.2 配置文件格式

```json
{
  "version": "1.0",
  "mcp_endpoint": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-flat",
  "default_account": "main",
  "accounts": {
    "main": {
      "name": "主账户",
      "advertiser_id": "<在此填写你的广告主ID>",
      "currency": "USD",
      "timezone": "Asia/Shanghai"
    }
  },
  "oauth": {
    "client_id": "<OAuth Client ID>",
    "auth_endpoint": "https://business-api.tiktok.com/portal/auth",
    "token_endpoint": "https://business-api.tiktok.com/open_api/v1.3/oauth2/access_token/",
    "redirect_uri": "http://localhost:8888/callback",
    "scopes": ["ads:read"]
  },
  "security": {
    "token_encryption": true,
    "token_expiry_warning_days": 3,
    "enable_request_logging": false,
    "log_sensitive_data": false
  },
  "cache": {
    "enable_cache": true,
    "cache_ttl_hours": 4,
    "cache_dir": "~/.tiktok_ads_mcp/cache"
  }
}
```

**重要说明**：
- 配置文件中使用 `<占位符>` 格式，不要出现真实明文示例
- **Token 不存储在配置文件中**，而是加密存储在 tokens/ 目录下
- 用户需要将占位符替换为自己的真实配置信息
- 任何文档、教程中都不得出现真实的 token 或 secret 示例

### 2.3 Token 存储规范

**存储位置：** `~/.tiktok_ads_mcp/tokens/`

**存储要求：**
- 必须加密存储（使用系统密钥链或 AES 加密）
- 文件权限设置为 600（仅所有者可读写）
- 文件名使用非敏感名称（如 `tiktok_ads.enc`）
- 定期轮换加密密钥

**Token 文件内容（加密前）：**
```json
{
  "access_token": "<加密存储>",
  "refresh_token": "<加密存储>",
  "token_type": "Bearer",
  "expires_at": "<过期时间戳>",
  "scopes": ["ads:read"],
  "advertiser_ids": ["<账户ID列表>"]
}
```

### 2.4 配置字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| version | 是 | 配置文件版本号 |
| mcp_endpoint | 是 | MCP Server 端点地址 |
| default_account | 是 | 默认使用的账户标识 |
| accounts | 是 | 账户配置字典，支持多账户 |
| accounts.{key}.name | 是 | 账户显示名称 |
| accounts.{key}.advertiser_id | 是 | 广告主ID |
| accounts.{key}.currency | 否 | 账户货币 |
| accounts.{key}.timezone | 否 | 账户时区 |
| oauth | 是 | OAuth 配置 |
| oauth.client_id | 是 | OAuth 客户端 ID |
| oauth.auth_endpoint | 是 | 授权端点 |
| oauth.token_endpoint | 是 | Token 端点 |
| oauth.redirect_uri | 是 | 回调地址 |
| oauth.scopes | 是 | 授权范围 |
| security | 否 | 安全相关配置 |
| cache | 否 | 缓存相关配置 |

### 2.5 文件权限设置

**Mac/Linux**:
```bash
mkdir -p ~/.tiktok_ads_mcp/tokens ~/.tiktok_ads_mcp/cache ~/.tiktok_ads_mcp/logs  # 创建目录
chmod 700 ~/.tiktok_ads_mcp                                                         # 设置目录权限（仅所有者可访问）
chmod 700 ~/.tiktok_ads_mcp/tokens
chmod 600 ~/.tiktok_ads_mcp/config.json                                             # 创建配置文件后设置权限（仅所有者可读写）
chmod 600 ~/.tiktok_ads_mcp/tokens/*
```

**权限说明**:
- 目录权限 `700`：只有所有者可以读写执行
- 文件权限 `600`：只有所有者可以读写
- 确保其他用户、进程无法访问配置文件和 Token

## 三、OAuth 授权安全指南

### 3.1 授权流程安全

**安全的授权流程：**
1. MCP 客户端生成授权 URL
2. 用户在**自己的浏览器**中打开授权页面
3. 用户确认授权范围
4. 授权码通过本地回调传递给 MCP 客户端
5. MCP 客户端在后台换取 Token
6. Token 加密存储到本地

**不安全的做法（禁止）：**
- ❌ 在对话中粘贴授权码
- ❌ 通过命令行参数传递授权码
- ❌ 将授权码发送给第三方
- ❌ 使用他人的账户进行授权
- ❌ 在公共设备上保存授权状态

### 3.2 授权范围最佳实践

**最小权限原则：**
- 分析类需求只需 `ads:read` 权限
- 不要授权不需要的写权限
- 不要授权财务权限（除非确实需要）
- 定期审查已授权的权限范围

**权限分级建议：**

| 使用场景 | 推荐权限 | 说明 |
|---------|---------|------|
| 数据分析/报表 | `ads:read` | 只读权限，最安全 |
| 优化建议（不自动执行） | `ads:read` | 只需读取数据 |
| 手动调整预算/出价 | `ads:read` + `ads:write` | 需要写权限，需谨慎 |
| 全自动投放管理 | 全部权限 | 最高风险，需严格控制 |

### 3.3 授权状态管理

**定期检查：**
- 定期检查已授权的应用列表
- 移除不再使用的授权
- 确认授权范围没有被扩大

**重新授权时机：**
- Token 过期且无法刷新时
- 怀疑授权泄露时
- 需要变更授权范围时
- 更换设备时

## 四、凭证安全最佳实践

### 4.1 OAuth Token 管理

1. **加密存储**
   - 使用系统密钥链（Keychain）或加密文件存储
   - 加密密钥使用系统生成的随机密钥
   - 绝不硬编码加密密钥

2. **自动刷新**
   - Access Token 过期前自动刷新
   - 刷新失败时提示用户重新授权
   - 记录刷新失败日志，便于排查

3. **定期轮换**
   - 建议每 30 天重新授权一次
   - 轮换期间新旧 Token 可并行使用一段时间
   - 轮换后确认旧 Token 已失效

4. **过期提醒**
   - Refresh Token 过期前 3 天提醒用户更新
   - 配置文件中可记录过期时间
   - 提前准备重新授权流程

### 4.2 数据安全

1. **缓存数据安全**
   - 缓存的广告数据也属于敏感信息
   - 缓存目录同样设置严格权限
   - 定期清理过期缓存
   - 敏感数据缓存需加密

2. **日志安全**
   - 日志中不记录 Token、授权码等敏感信息
   - 错误日志脱敏处理
   - 定期清理日志文件
   - 日志文件设置严格权限

3. **输出安全**
   - 对话中不展示完整的 advertiser_id
   - 敏感数据（如营收、利润）提醒保密
   - 分析报告标注"内部机密"
   - 不输出 Token 相关的任何信息

### 4.3 操作安全

1. **只读优先**
   - 分析类操作只使用只读权限
   - 不调用修改、创建、删除等写操作工具
   - 如需操作，明确告知用户并确认

2. **写操作确认**
   - 任何写操作必须获得用户明确确认
   - 高风险操作（暂停广告、大幅调整预算）需二次确认
   - 操作前展示操作内容和预期影响
   - 操作后确认结果并通知用户

3. **请求频率控制**
   - 遵守 MCP/API 限流规则
   - 避免短时间大量请求
   - 实现请求队列和退避机制
   - 监控请求频率，防止超限

4. **错误处理**
   - 认证失败时不重试（避免锁定）
   - 权限不足时提示用户检查
   - 限流时自动退避重试
   - 错误信息不包含敏感细节

## 五、常见安全问题

### 5.1 凭证泄露风险

**风险场景**:
- 在对话中不小心粘贴了 token
- 截图中包含配置文件内容
- 分享分析报告时附带原始数据
- 公共设备上保存了授权状态

**防范措施**:
- Skill 自动检测输出中的敏感信息模式
- 发现疑似 token 立即拦截并提示
- 提醒用户分享前检查内容
- **绝对不要**在聊天中发送 token 或授权码
- 公共设备使用后清除授权状态

### 5.2 配置文件丢失

**风险场景**:
- 重装系统忘记备份
- 误删除配置文件
- 更换电脑未迁移
- 加密密钥丢失

**防范措施**:
- 提醒用户备份配置文件（不含 Token）
- Token 可以通过重新授权获取，不需要备份
- 建议使用密码管理器保存配置信息
- 不要把配置文件放在云盘同步
- 记录加密密钥的恢复方法

### 5.3 多账户管理

**风险场景**:
- 多账户凭证混淆
- 误操作其他账户数据
- 权限管理混乱
- 跨账户数据泄露

**防范措施**:
- 配置文件支持多账户，用名称区分
- 每次操作前确认使用的账户
- 不同账户使用不同的授权范围
- 账户间数据严格隔离

### 5.4 MCP 连接安全

**风险场景**:
- 连接到伪造的 MCP Server
- 中间人攻击窃取 Token
- 恶意工具调用
- 未授权的工具访问

**防范措施**:
- 只连接官方的 MCP 端点（验证 URL）
- 使用 HTTPS 加密传输
- 验证服务器证书
- 只调用已知的、可信的工具
- 定期审查工具调用日志

## 六、应急响应

### 6.1 凭证泄露处理

如果怀疑凭证泄露：

1. **立即停用**
   - 到 TikTok 广告后台撤销该应用的授权
   - 或立即修改账户密码
   - 确认所有 Token 已失效

2. **排查影响**
   - 检查 MCP 调用日志
   - 确认是否有异常操作
   - 评估数据泄露范围
   - 检查广告设置是否被篡改

3. **恢复使用**
   - 重新进行 OAuth 授权
   - 获取新的 Token
   - 验证新凭证正常工作
   - 加强安全措施

### 6.2 异常 MCP 调用

如果发现异常 MCP 调用：

1. **暂停使用**
   - 暂时停止调用 MCP 工具
   - 检查调用来源
   - 断开 MCP 连接

2. **排查原因**
   - 检查是否配置错误
   - 检查是否有恶意程序
   - 检查日志中的异常模式
   - 联系 TikTok 技术支持

3. **恢复使用**
   - 确认安全后恢复
   - 加强安全措施
   - 启用更详细的日志
   - 定期安全审计

### 6.3 授权异常

如果发现授权异常：

1. **立即撤销授权**
   - 在 TikTok 广告后台撤销应用授权
   - 清除本地存储的 Token
   - 断开 MCP 连接

2. **排查原因**
   - 检查是否有钓鱼攻击
   - 检查是否误点了恶意链接
   - 检查账户登录记录
   - 确认账户安全

3. **恢复使用**
   - 确认账户安全后重新授权
   - 启用双重验证
   - 定期检查授权状态
   - 设置安全提醒

## 七、安全检查清单

使用本 Skill 前，请确认：

- [ ] 配置文件位于 `~/.tiktok_ads_mcp/config.json`
- [ ] 配置文件权限设置为 600（仅所有者可读写）
- [ ] 配置文件不在公共目录或云盘同步目录
- [ ] Token 加密存储在 tokens/ 目录下
- [ ] Token 文件权限设置为 600（仅所有者可读写）
- [ ] OAuth 只授权了必要的权限范围（最小权限）
- [ ] 了解凭证泄露的应急处理方法
- [ ] 分析数据仅用于内部参考，不对外传播
- [ ] 不会在聊天中发送任何凭证信息
- [ ] 只连接官方的 MCP 端点
- [ ] 写操作前会获得用户明确确认
- [ ] 定期审查已授权的应用和权限
