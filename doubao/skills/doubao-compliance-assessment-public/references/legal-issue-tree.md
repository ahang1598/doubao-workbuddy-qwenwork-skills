# 法律关系与问题依赖

本方法把风险排查结果组织成可论证的法律问题，避免直接按“数据、广告、知识产权”等领域平铺报告。

围绕与本业务最直接、风险最集中的核心法律关系展开分析；次要的、或任何同类互联网业务都需履行的普适性义务，简明带过，不逐一铺开成节。分析深度优先给到真正影响这项业务能否开展的问题，而不是追求把每个沾边领域都写全。

## 三步构建

### 1. 确定关系与法律地位

逐对主体回答：

- 谁与谁发生法律关系？
- 评估对象控制或参与哪些关键行为？
- 可能属于哪一种法定主体或责任角色？
- 哪些事实会改变这一地位判断？

法律地位本身存在争议时，标记 `【需专业人员确认】`。

### 2. 展开具体义务

从每一种可能的法律地位展开其法定义务。问题必须能够拆分构成要件，例如：

- “平台是否属于广告发布者，并已履行法定查验义务？”
- “双方是否构成共同处理个人信息，并满足相应告知和约定义务？”

“广告合规”“数据合规”只是领域，不是可直接论证的法律问题。

### 3. 过滤入选问题

从各维度召回的风险点，在写成独立法律问题前逐一过滤，只有同时满足下列各项的才进入清单。此过滤仅在内部进行，被滤除的风险直接不出现在问题清单与报告中，不在报告里说明某风险被排除、方向相反或关联性不足。

- **相关性**：该风险直接指向评估对象本身及其拟评估的行为，而非由业务中的周边活动、背景信息联想牵连而来。仅与周边活动沾边、不落到评估对象上的，不单独立为问题。
- **成立性与方向**：确认法律关系方向真实成立，即评估对象处于“可能违反某项义务或构成某种责任”的位置。若评估对象实际上是在履行、符合该项义务，或所援引规范约束的是他方而非评估对象，则该点不构成风险，不予立项。
- **区分度（普适义务降级）**：该义务是否针对本业务的具体行为或场景，而非任何同类互联网业务都同样负担的普适性底线义务。反电信网络诈骗、一般内容安全、一般网络与数据安全等对“互联网服务提供者”普遍适用、与本业务无特殊关联的义务，不单独立为法律问题、不单独成节，只在报告中以一句“还需履行反诈、内容安全等通用合规基线义务”概括带过。只有当本业务存在特殊触发场景（如涉及支付资金、主动引流拉新、兼职招募等高发涉诈情形，或业务本身即以内容分发为核心）使该义务落到具体行为上时，才展开为独立问题。

同一行为可能同时落入不同法律部门的评价（如行政监管义务与民事合同效力、行政处罚与合同无效）时，应分别立为独立法律问题，不得以其中一项“已经分析”为由合并或省略；一个维度的合规不代表其他维度的合规。

方向或相关性存疑、但一旦成立则后果重大的，可保留为问题并标注需补充的关键事实，不直接删除。

### 4. 标记依赖关系

| 类型 | 含义 | 处理方式 |
|---|---|---|
| 前提到派生 | 上游定性决定下游义务 | 先检索前提；未确定时作条件分析 |
| 并列 | 同一关系下互不依赖的义务 | 可同时检索 |
| 独立 | 与其他关系无逻辑耦合 | 独立分析 |

## 不确定性传播

前提无法确定时，不得选择有利分支直接下结论。应把每种可能的定性及其对应义务分别写清，并指明缺哪个事实、需谁确认。例如：

> 平台若构成广告发布者，需履行查验义务；若仅为信息服务提供者，则义务较轻。目前缺少平台是否参与广告制作的事实，主体定性需专业人员确认。

## 查漏补缺与查错

问题清单形成后，用 `dimensions.md` 回补真正的高风险遗漏，只补真漏、不为求全而扩列次要或普适性问题：

1. 所有待确认或高风险事项是否都有对应问题；
2. 是否存在固定维度覆盖、且对本业务构成实质风险、但清单遗漏的项（仅回补这类；次要或普适性义务不因“未覆盖”而补列）；
3. 是否存在没有事实或法律意义的重复问题。

同时回头复查清单中是否混入了不成立的问题（这一复查只在内部进行，删除的问题不在报告中说明被删）：

4. 是否存在与评估对象无关、仅由周边活动或背景信息联想牵连进来的问题；
5. 是否存在法律关系方向反了的问题，即评估对象实际上在履行该义务、或所援引规范约束的是他方而非评估对象；
6. 是否把本应分开的不同法律部门评价合并成了一个问题。

## 底稿格式

```text
R1 评估对象与用户
  I1 前提问题：评估对象属于何种法定主体？
    I1a 若属于 X，是否履行 A 义务？
    I1b 若属于 Y，是否履行 B 义务？

依赖：
- I1a、I1b 依赖 I1

检索顺序：
- 第一批：I1
- 第二批：I1a、I1b
```

内部编号只用于底稿；对用户和报告使用自然语言标题。
