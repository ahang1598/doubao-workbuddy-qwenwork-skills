# 组织政策包接口

外部版不预置任何组织的内部知识。用户可为自己的组织提供私有政策包，用于补充风险偏好、审批流程和操作标准。

## 建议目录

```text
organization-policy/
├── manifest.md
├── policies/
├── risk-appetite/
├── procedures/
└── routing/
```

`manifest.md` 至少记录：

- 组织和政策包名称；
- 所有者及维护角色；
- 版本、发布日期和复核日期；
- 适用主体、法域和业务范围；
- 文件清单及状态；
- 数据分类和允许使用范围。

## 内容分类

| 类型 | 可否用于结论 | 使用方式 |
|---|---|---|
| 已批准的强制制度 | 可以影响组织内部处置 | 不替代法律依据 |
| 已批准的风险偏好 | 可以影响是否升级或采取更严格措施 | 不得放宽法律要求 |
| 操作流程和模板 | 用于生成整改步骤 | 核验版本与适用范围 |
| 历史评估 | 仅作事实和检索线索 | 不自动视为现行口径 |
| 未确认反馈 | 不得作为正式政策 | 进入待确认事项 |

## 安全规则

1. 只有用户主动提供或授权连接器时加载。
2. 只读取与当前问题相关的最小范围。
3. 不将内容复制回公共 Skill，不跨组织复用。
4. 报告引用政策时记录标题、版本和适用范围；敏感链接不写入可外发报告。
5. 政策包含个人信息、商业秘密或客户数据时，先最小化和脱敏。
6. 无权限时不主动申请，不推测内容，不把“未读取”解释为“不存在政策”。

## 冲突处理

- 法律要求高于政策：以法律为准，并提示修订政策。
- 政策严于法律：可按政策给出组织内部建议，并明确“严于法律最低要求”。
- 政策存在冲突或版本不明：标记 `【需专业人员确认】`。
- 公开行业实践与政策不同：分别呈现，不用公开文章推翻正式政策。
