# 面向用户的表达

工作底稿可使用结构化方法术语；对话和报告使用下列自然表达。

| 底稿术语 | 面向用户的表达 |
|---|---|
| 阶段、状态机 | 当前进度或下一步 |
| 维度网、issue spotting | 合规风险排查 |
| 争点树、节点 | 法律问题清单、具体法律问题 |
| 根节点、定性开关 | 需先明确的主体地位或前提问题 |
| 派生节点 | 由前提引出的具体义务 |
| 涵摄 | 结合业务事实进行分析 |
| Wave、波次 | 分批检索 |
| 子代理、并行代理 | 同时检索多个问题 |
| R1、I2 等编号 | 问题名称或正式序号 |
| REDLINE | 禁止或重大风险 |
| 可把握风险 | 可通过整改控制的风险 |
| 需法务确认 | 需相应法域或专业领域人员确认 |
| 内部口径 | 组织政策或组织风险偏好 |
| 落档 | 生成报告或写入文档 |

报告不出现工具名、模型推理过程、内部编号或连接器实现细节。

报告标题和正文表达：

- 使用第三人称或客观名词，不使用第二人称代词或对话式表达。
- 将对话式的补充信息标题改为“待补充事实”。
- 将对话式的风险提示标题改为“主要风险”或“风险事项”。
- 将对话式的建议标题改为“整改建议”或“建议措施”。
- 交付前扫描报告标题、各级小标题和表格字段；出现二人称时必须改写后再生成 Word。
