# 合规评估报告模板

## 文体和引用

- 使用客观、严谨、便于非法律人员理解的书面语言。
- 以“评估对象”“运营方”“平台”等第三人称表述。
- 报告标题、一级标题、二级标题和表格字段不得使用第二人称代词或对话式表达。
- 二级标题采用“（编号）主体关系：核心风险”的格式：以中文数字括号编号“（一）（二）（三）……”起头，在同一大节内随小节顺序递增，再点明该节涵盖的法律关系，冒号带出核心风险，例如“（一）平台与广告主：纵向垄断与价格干预风险”“（二）平台与用户：个人信息处理合规风险”。业务背景、待专业人员确认事项等大节内的并列子标题同样用“（一）（二）……”编号，编号在每个大节（一、二、三……）下从“（一）”重新起算。
- 按法律关系和具体问题组织分析，不按领域名称平铺。
- 每个法律问题写成连贯的分析文字，像法律意见书那样把规则、事实与判断融于通顺的段落，前后句自然衔接；不使用“规则 / 分析 / 结论 / 建议”这类标签分段，也不把一段完整推理拆成大量并列圆点。
- 语言是写给法律与合规从业者读的，追求专业、流畅、可读，不是写给模型执行的清单。
- 引用法规只提炼与本案分析相关的规则要点，不整段复制法条原文。
- 公开专业参考和组织政策必须与法律依据分开。

## 说理与详略

分析文字追求律师意见书式的判断与克制，避免把“思考过程”写进纸面：

- **直接切入，不预告步骤**：不写“此处需先厘清 X、再判断 Y”“后者需通过界定相关市场、计算份额等步骤认定”这类路线预告，直接展开实质分析。
- **不树靶子、不自我辩驳**：不先陈述一种没人提出的错误认定再否定它（如“不宜径直认定为……”“不应简单理解为……”）；直接就事实与法律给出判断。
- **给倾向、配翻转**：事实清楚时给出倾向性结论（如“多数情形下应属……”“建议按……档先行推进”），并写明该倾向依赖的关键事实，以及事实翻转时的应对（如“一旦确认……则升级为……”）；不把两种可能并列摆着而不表态。
- **连贯散文，不列清单**：一个问题的规则、事实与判断融进连续段落，不拆成“第一 / 第二 / 第三”或大量并列圆点；条件分析用“若……则……”写在句中。
- **收敛篇幅**：不为凑长度复述法条或背诵抽象标准（如逐条罗列比例原则的三项要求），把抽象规则落到本案事实上，能一句说清的不写三句。
- **限定不可精简（精度禁区）**：上面的收敛与精简只针对件数、铺陈和冗余转述（少写领域、不逐条罗列、不复述抽象标准），不针对规则本身的准确度。凡转述带**期限、起算点、适用主体、合法性基础、比例或前提条件**的法律规则，必须连同这些限定一起转述，不得为让句子变短而删掉限定、或把条件性规则写成绝对化结论；涉及法律定性的标准，用法条采用的标准表述，不用日常模糊量级词替换。此项贯穿全文，含整改建议与汇总表。示例：写“自广告发布行为终了之日起保存不少于三年”，不简写成“保存不少于三年”；写“以同意为合法性基础且构成向独立处理者提供时才需单独同意”，不简写成“需单独同意”；写“取决于对处理目的和方式的决定权”，不写“取决于双方的控制程度”。

## 法条与链接的露出

报告读者为法律与合规从业者，重点在分析而非条文复述：

- **法条原文**：正文只写法规名称、条号和与本案直接相关的规则要点（构成要件、适用条件、法律后果），用简洁转述；确需引用原文时只摘关键句，不整段、不多条罗列。同一法条只在首次出现时点明条号加一句话核心规则，后续分析直接援用该规则、不再复述条文表述。
- **条号密度硬上限**：同一部法规在同一法律问题（同一小节）内，正文点出的具体条号不超过 3 个；确有多条相关时，只列最核心的 2–3 条，其余以“等”概括，不逐条“第X条规定……、第Y条规定……”排列。禁止把某部法规的义务清单或罚则逐条搬进正文；处罚只写幅度定性（如“可处停业整顿、罚款直至吊销许可”），不照抄罚款数额区间与各档情形原文。义务成组出现时合并成一句转述（如“须履行查验、记录、报告等义务”），不拆成并列多条。
- **版本与效力**：引用法规时标注其版本年份与效力状态（如“《广告法》（2021年修正，现行有效）”），至少在该法规首次出现处和文末尾注标明，使版本可辨，避免误用已废止或修正前的旧版本。
- **链接**：正文的“规则—分析—结论—建议”不内嵌 URL；尤其不得在句尾用 `["https://..."]` 这类方括号角标标注检索来源——检索到的出处一律只写进文末尾注，正文靠法规名称、条号和案例名指代即可。每条链接收敛到文末尾注来源，同一法规只出现一次。
- 链接优先使用立法机关、监管机关、官方裁判文书库等稳定官方地址；不粘贴带长查询参数或会话标识的检索工具跳转链接（如数据库分享链）。无稳定官方链接时，只注明来源名称与检索日期，不强行附不可复用的长链接。

## 标题

`<业务简称>合规评估报告 · <评估日期>`

标题生成规则：

- 主标题使用“业务对象 + 合规评估报告 + 日期”。
- 分节标题使用“主体关系 / 法律问题 / 风险事项”的客观表达。
- 禁止使用面向对话的标题，例如“需关注事项”应改为“主要风险”，“建议动作”应改为“整改建议”。

## 评估结论摘要

- 总体判断：可开展 / 满足条件后可开展 / 不建议按当前方案开展 / 信息不足；
- 主要风险：按风险等级排序；
- 核心建议：列最关键的整改动作；
- 评估法域、日期和材料边界。

## 一、业务背景与评估范围

- 业务模式、运营主体和参与方；
- 核心业务、数据、资金和内容流程；
- 上线地区、用户类型和产品形态；
- 已确认事实、待确认事实和分析假设；
- 本次评估包含的事项。

## 二、法律分析

按“评估对象与某参与方的法律关系 → 该关系下的核心风险”组织，二级标题采用“（编号）主体关系：核心风险”的格式，各小节以“（一）（二）（三）……”依次编号。

每个法律问题用连贯的分析文字写成，服务于说清风险而展开简短必要的说理，把适用规则、业务事实、风险定性融进自然衔接的段落，读起来像一段完整的律师说理，而不是填空式的标签清单，也不拆成并列圆点。落笔精准，法律用语不作绝对化或泛化表述（另见“说理与详略”节的“限定不可精简”）。规则要点顺着分析自然带出，不生硬复述法条原文、不为引用而引用；事实前提不确定时，在同一段里用“若……则……；若不……则……”交代清楚。每个问题末尾用一行“依据”列出支撑的法规条款和案例，正文不内嵌长链接。

每节大致顺序：点明该主体关系下的行为 → 适用规则要点 → 结合本案事实的定性与风险等级 →（事实不确定时）条件式翻转，末尾另起一行“依据：”。

## 三、待专业人员确认事项

逐条写明：

- 需要确认的问题；
- 当前无法判断的原因；
- 需要补充的事实或资料；
- 建议的专业领域和责任角色。

## 四、整改建议

每条建议写成一句可执行的话，说清针对哪一项风险、由哪个角色在建议期限内做出什么具体的产品、技术、合同、流程或文案动作、达到什么降险效果与落地状态，避免“加强管理”“做好合规”这类无法执行的空泛表述。建议中援引法律要求（如保存期限、起算点、适用主体）时，同样受“限定不可精简”约束，不得凭印象重述而丢掉起算点或适用条件；拿不准限定原文时回查依据，不靠记忆补全。

## 五、风险与建议汇总

在报告结尾用一张表汇总各项法律问题的风险等级、事实缺口、核心依据、整改措施与责任角色，作为全文收束：

| 序号 | 法律问题 | 风险等级 | 事实缺口 | 核心依据 | 整改措施 | 责任角色 |
|---|---|---|---|---|---|---|

## 免责声明

- 报告基于指定日期、法域和现有材料生成；
- 事实变化或法律更新可能导致结论变化；
- 报告属于辅助研究，不替代具备相应资格的律师正式意见；
- 需专业人员确认的事项在确认前不得作为确定性放行依据。

## 尾注：来源和组织政策

来源不作为正文章节，统一置于文末尾注，不占正文编号：

### 法律依据

- 法规、官方解释、标准和案例去重清单；
- 发布机关、效力状态、URL 和检索日期。

### 公开专业参考

- 作者或机构、标题、URL、检索日期；
- 明确标注“仅供参考”。

### 组织政策

仅在用户提供时列：

- 政策标题、版本和适用范围；
- 与法律最低要求的关系；
- 不在可外发报告中暴露敏感资源地址。

## 直接报告模式提示

若用户选择基于现有材料直接生成，在摘要前增加：

> 本报告基于现有材料形成，法律问题和关键事实未逐项与用户确认。相关假设和信息缺口已在报告中列明，事实变化可能影响结论。

## 涉外/境外法律评估提示

若本次评估涉及中国大陆以外法域的法律检索与分析（涉外/境外法律评估，例如欧盟、美国或其他境外法域），在评估结论摘要之前的题头风险提示处增加下句（与“直接报告模式提示”可并存）：
> 本报告境外信息可能源于公开的非官方资料，准确度与时效性请以官方实时法律更新为准，本报告仅作初步参考。
