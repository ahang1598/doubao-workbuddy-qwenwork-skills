# 知识产权与开源软件

## 触发事实

- 使用名称、商标、图片、字体、音乐、视频、文字、模型、数据或代码；
- 基于第三方作品改编、训练、生成、传播或转授权；
- 使用开源组件、商业组件或第三方 SDK；
- 抓取数据、调用接口、反编译或规避技术措施。

## 关键问题

1. 原始权利人、贡献者和授权链是否明确？
2. 授权是否覆盖地域、期限、媒介、修改、分发、商业使用和转授权？
3. 演绎作品是否同时取得在先作品和改编成果所需授权？
4. 开源许可证的准确版本、例外和组合关系是什么？
5. 组件是否修改、静态或动态链接、网络部署、嵌入设备或对外分发？
6. 抓取、接口和技术措施行为是否涉及著作权、合同或不正当竞争？

## 公开来源方向

- 国家法律法规数据库：著作权、商标、专利和反不正当竞争法律；
- 计算机软件保护相关行政法规；
- 人民法院案例库和最高法院知识产权案例；
- SPDX、OSI、FSF 及许可证发布者的规范文本。

## 开源分析底线

- 不使用“某许可证一律禁止”的静态结论；
- 先识别许可证，再结合修改、链接、部署和分发事实；
- 许可证原文和例外优先于二手分级表；
- 法院案例只支持相似事实下的解释，不能代替许可证文本；
- 许可证冲突、专利条款或复杂组合转开源法律专业人员。

## 输出要求

- 形成“资产—权利人—来源—许可证/授权—使用方式—缺口—措施”清单；
- 商标保护投入根据地域、类别、品牌价值和实际风险提出，不使用预置预算阈值；
- 开源扫描工具只负责识别线索，最终结论需核验源码、依赖和许可证文本。
