# 产品上线合规分诊

仅当用户要求对一个新产品或重大版本进行整体上线前评估时使用。单个法律问题仍走通用流程。

## 产品画像

- 产品形态：App、小程序、网站、客户端、SDK、API、硬件或服务；
- 运营和签约主体；
- 用户类型及年龄范围；
- 收费、订阅和支付方式；
- 上线、服务和数据处理地区；
- 是否有域名、应用分发、设备销售或跨境交付；
- 新产品、改名、新功能、新地区还是新渠道。

## 形态路由

| 形态 | 重点检查 |
|---|---|
| App/客户端 | 用户权益、个人信息、权限、第三方 SDK、应用分发、内容和收费 |
| 小程序 | 宿主平台规则、主体资质、数据共享、内容和交易 |
| 网站 | 域名和备案、Cookie、内容、交易和跨境访问 |
| SDK/API | 数据角色、开发者告知、代码和许可证、跨境技术交付 |
| 硬件 | 产品准入、安全、配套软件、数据、供应链和贸易管制 |
| SaaS/服务 | 资质、合同、数据处理、服务等级、内容和跨境 |

平台或应用商店规则属于合同或分发要求，不得直接写成普遍法律红线。

## 横向检查

1. 主体、资质、域名和分发；
2. 数据、隐私和网络安全；
3. 消费者、收费、退款和未成年人；
4. 内容、广告、AI 和算法；
5. 商标、版权、开源和第三方技术；
6. 竞争、反诈和行业监管；
7. 跨境数据、技术、设备、出口管制和制裁；
8. 清单之外的产品特有风险。

## 分诊结果

每一项标记：

- 不适用，并写明事实理由；
- 可按通用要求整改；
- 需加载对应公开领域包深入分析；
- 需当地律师、隐私、安全、贸易管制或其他专业人员确认。

## 禁止简单化

- 仅在单一地区上线不当然排除跨境和制裁问题；
- 通过商店审核不等于法律合规；
- 完成扫描、体检或问卷不等于已履行全部法律义务；
- 不按预算阈值自动决定知识产权保护程度；
- 不把某个组织的审批流程当作普遍法律要求。
