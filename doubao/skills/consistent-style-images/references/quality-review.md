# 结构化审核记录（可选）

仅在采用 batch.json 的高级模式时填写下列字段。普通任务查看实际图片并按 SKILL.md 的品牌主题、整体设计、细节质感与系列交付四项检查即可，不要求创建审核表。

对最终图片按实际展示尺寸检查。要求脚本确认的是“审核记录齐全且属于当前文件”，不声称自动视觉审核。

## 通用项

| id | 适用内容 | 检查 |
| --- | --- | --- |
| content_accuracy | always | 品牌、主题、产品/活动事实和项目依据一致；无未经确认承诺 |
| message_fit | always | 图片服务本次受众、目标与核心信息；视觉与文案表达相符，标题与主视觉共同突出主信息，存在贴合主题的视觉表达，而非可任意换标题的通用摆件 |
| copy_integrity | text | 逐字、标点、换行核对；无无意重复、伪字、漏字；有意修辞记录依据 |
| readability | text | 在展示尺寸可读，文字不过密、不被裁切、与背景对比足够 |
| visual_integrity | always | 图文有主次与节奏，留白有用途，无松散空洞或机械堆满；字体间距精细，材质光影或图形语言自洽；无生成畸形、遮挡和错误残留 |
| brand_consistency | always | 与用户参考图或描述的本次方向及适用资料一致，系列保持字体、色彩和表现语言；要求多样时构图确有变化，不串用其他品牌规则/资产 |
| asset_fidelity | logo | 官方资产直接使用的要求被满足，版本、比例、颜色、净空正确 |
| cta_integrity | cta | CTA 与任务行动目标一致，组件完整、清晰，整批稳定 |
| delivery | always | 数量、尺寸、格式、文件大小、安全区、命名及约定源文件符合任务 |

`content_flags` 为 text/cta/logo/visual 四个布尔值，依据实际交付内容填写；脚本会核对 flags.text/cta 与 copy 字段是否矛盾。Logo 和视觉是否存在仍需看图确认。省略 CTA 的品牌形象海报可以将 cta_integrity 标为 not_applicable，原因如“本任务明确不含行动按钮”。

每项 `{status, evidence}`：适用项需 passed 才可完成，不适用项需 not_applicable 并说明原因；failed/pending 不能称完成。always 不允许不适用。没有文字的纯视觉任务，文案完整性与可读性可以不适用，但品牌一致性和交付检查仍适用。

品牌检查使用 `brand_review`，按 profile.review_rules 的 applies_to 计算，而非固定禁止人物、固定双色或固定居中。品牌原文需要场景解释时，把解释与原文区分开；具体设计例外留在本次记录，不能自动变成通用规则。

同一内容的准确性可能需要项目依据，视觉问题需要审图；哈希、文件尺寸或“已确认”字段都不能替代这些证据。脚本不会核验 source 字段是否真的来自用户，Agent 必须忠实记录。

## 修改后重审

每张记录 `reviewed_sha256`，整批记录 `profile_fingerprint`。成图变化、品牌配置/本地规则变化或例外变化会让检查失败；应重新检查受影响内容，不能只刷新哈希。完成报告仍区分概念阶段的质量检查与正式交付阶段的品牌检查。
