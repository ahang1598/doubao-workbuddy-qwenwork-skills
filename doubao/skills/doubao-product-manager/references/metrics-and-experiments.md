# 指标、埋点与实验

指标用于支持决定，不用于装饰目标。没有基线、口径或可影响机制时，不写精确提升目标。

时间窗、分流比例、阈值、样本量和实验周期都属于需要依据的数字决策。

## 1. 从决定反推指标

先写产品希望改变的用户状态，再画最小因果链：产品动作如何改变行为，行为如何产生用户价值与业务价值，哪里可能产生副作用。

区分：

- **结果指标：**用户或业务最终状态；
- **领先指标：**更早反映行为变化；
- **诊断指标：**帮助解释变化原因；
- **护栏指标：**防止以质量、安全、公平、成本或长期价值换短期增长。

过程量不能自动当作价值，例如点击、生成次数或消息量上升未必代表问题解决。

护栏必须直接检测用户硬约束是否被破坏，以及受保护对象是否被误覆盖、误路由或阻断核心任务。不能用周期更长、因果更远的留存、满意度或总量指标，替代对实际风险的直接监控。

## 2. 指标定义卡

每个关键指标写清：名称、决策用途、事件或公式、分子分母、目标人群、排除规则、时间窗、数据源、当前基线、刷新频率、负责人和已知偏差。

基线未知时先定义数据需求和口径；观察窗也未知时，不自行补天数。目标若由产品方设定，要说明它是决策参数、设定依据和重新校准条件。

分群天数、观察周期、页面或步骤数量、实验时长、分流比例和样本量也属于数字决策。没有事实、公式或明确决策理由时保持未知，不用“建议至少两周”“先做三屏”等常见写法制造确定性。

### 流程步骤不等于转化漏斗

只列“进入、填写、完成、转化”等步骤，只能说明路径，不能定位真实流失。转化分析至少定义：起点与终点事件、每个可观测阶段、目标人群与排除规则、分子分母、事件去重、当前基线是否已知、数据源，以及看到哪种结果时采取什么动作。

没有现成数据时，明确写为观测方案：需要补哪些事件与属性、如何形成基线、如何分群定位损失、数据满足什么条件后再决定优化点。不得根据页面直觉编造当前掉点、目标提升、观察天数、提醒时点或实验周期。

## 3. 埋点方案

从对象、状态和用户动作推导事件，不从页面按钮清单机械生成。每个事件包含触发时机、主体、对象、前后状态、结果、错误码、关键属性和隐私边界。

检查同一用户重复事件、跨端身份、延迟到达、补发、取消、回滚和版本变更。没有数据基础设施来源时，不断言某字段“已有”。

## 4. 实验只验证关键不确定性

实验卡包含：

1. 决策与待验证假设；
2. 目标人群和随机化单位；
3. 对照与处理差异；
4. 主指标、护栏和分群；
5. 基线、最小可检测效应、显著性、把握度、样本量和观察窗；
6. 污染、学习效应、季节性与新奇效应；
7. 停止、回滚和异常处置；
8. 成功、失败和不确定结果分别采取什么动作。

参数缺失时不自动给行业默认值，也不先写 50/50、至少两周或固定显著性阈值。可用脚本在参数齐全后复算两比例样本量：

```bash
python3 scripts/experiment_math.py --baseline 0.10 --mde 0.01 --alpha 0.05 --power 0.80 --allocation 0.50 --sides two --direction increase
```

输出是统计估算，不是产品目标或上线承诺。

## 5. 不适合 A/B 时

考虑可用性测试、原型测试、概念测试、日志分析、前后对比、分阶段灰度、差分法或人工复核。明确其可回答和不能回答的问题，避免把弱设计写成因果证明。

## 6. 结果判断

先检查实验健康度和数据质量，再看主指标、护栏、效应区间和关键分群。不要只看 p 值或挑选显著结果。结论必须回到原决策：上线、迭代、停止、扩大验证，或因为证据不足保持不变。
