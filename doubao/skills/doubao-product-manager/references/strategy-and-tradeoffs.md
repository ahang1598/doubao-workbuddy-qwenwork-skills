# 产品策略、方案与取舍

用于产品方向、策略选择、方案比较、MVP、资源取舍、Build/Buy/Partner 和高层决策。策略不是愿景口号或功能清单，而是围绕一个结果做出相互约束的选择。

## 1. 锁定决策问题

开头写清：谁在什么时间范围内，必须在什么选项之间做什么决定。若几个问题混在一起，先拆出有依赖顺序的决定。

## 2. 策略链

一条可执行策略应连成：

`目标用户与情境 → 未满足任务 → 价值机制 → 选择的玩法 → 必备能力 → 衡量与反馈`

同时说明：为什么现在、什么约束最重要、因此不做什么。市场、竞品或公司目标只有在改变这条链时才展开。

## 3. 方案比较

保留至少两个可行选项，通常包含“不做/延后/维持现状”。比较维度从当前决定产生，不套固定评分表。常用维度包括：

- 用户结果和业务结果；
- 证据强度与关键假设；
- 时间价值与不行动成本；
- 可逆性、学习速度和失败半径；
- 所需能力、持续运营成本和外部依赖；
- 安全、合规、品牌与信任影响。

对每个选项依次写清：能解决什么、不能解决什么、依据与假设、主要代价，以及在什么条件下更优。需要表格时逐行填全，不保留空表。

不要把不互斥方案强行放成二选一；可改成先后顺序、组合方案或不同人群分层。

## 4. Build / Buy / Partner

比较的不是一次性开发成本，而是获得能力的全周期方式：差异化价值、上市速度、集成约束、数据与合规、供应商锁定、运营维护、退出成本和可替换性。混合方式可作为正式选项。

技术可行性、工期和维护成本由相应角色提供；缺失时列变量和验证动作，不替工程团队承诺。

## 5. MVP 与范围

MVP 是完成一次核心价值闭环并验证最大风险的最小范围，不是把每个模块缩小一点。

维护范围账本：按实际存在的保留、新增、移除或明确禁止项，逐项写清内容、理由、对其他范围的影响和回补条件；没有内容的类别不保留空行。

每个首期项回答：它服务哪个用户任务、验证哪个假设、缺少它闭环是否仍成立。不能回答的先移出。

范围定稿前复查不做项：核心闭环是否完整，关键异常是否有去向，是否存在有真实痛点或竞品证据、实现代价较小且不挤占主线的防御性能力。满足时与主线一起比较；不满足时继续留在不做项并写明回补条件。竞品在做本身不是纳入理由。

## 6. 决策记录

正式决定至少记录：决策问题、采用选项、理由、反对意见、已知假设、约束、机会成本、成功信号、失败或停止条件、复盘节点、改变决定的触发条件。

保留未解决异议，不把沉默或暂时服从写成共识。

## 7. 输出深度

- 快速判断：结论、三条理由、主要反例、下一证据动作。
- 方案评审：选项表、推荐、取舍、不做项、风险与决策请求。
- 策略文档：完整策略链、能力组合、依赖、阶段结果和反馈机制。

策略没有证据时可以形成待验证方向，不能写成确定收益、市场份额或资源承诺。
