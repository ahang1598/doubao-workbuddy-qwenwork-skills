# 上下文与证据

读取材料的目的，是获得足以做决定的信息，而不是制作材料台账或阻止产品判断。

## 1. 读取最小充分材料

覆盖用户提供且会影响当前决定的正文、链接、附件、截图、表格、脑图节点、批注和旧产物。规则藏在图片、表格或附件中时查看真实内容；打不开时说明具体对象及受影响判断，不能用标题、文件名或模型摘要代替。

来源冲突时优先级为：

1. 用户本轮最新明确纠正或决定；
2. 用户较早仍有效的口径；
3. 当前一手事实来源；
4. 历史产物；
5. 模型建议。

无法判断新旧时并列冲突和影响，不拼成一个虚假事实。停止阅读的条件是：新增材料已不会显著改变当前建议、范围或风险判断。

## 2. 让信息承担合适的作用

| 类型 | 判断标准 | 在方案中的用法 |
|---|---|---|
| 事实 | 有当前材料、原始记录或可访问来源 | 描述现状、约束和已知结果 |
| 推断 | 从事实推导，但存在其他解释 | 支持判断，同时说明关键推导 |
| 产品决定 | 为目标和取舍主动选择 | 进入方案，说明理由和调整条件 |
| 待验证假设 | 尚未被行为或数据证实 | 进入验证计划、条件方案或探索方向 |
| 未知 | 缺失后可能改变决定 | 选择暂定方案、保守边界或确认动作 |

事实不是方案的全部。可以在事实基础上提出新流程、能力或规则，只要不把建议写成“当前已经存在”，并说明它解决什么问题、付出什么代价、何时调整。

单一用户意见、销售请求或一条评论是有效线索，但不自动代表普遍需求。现象与结果同时出现只能支持相关性；没有实验、对照或充分排除其他原因时，不把某个功能直接写成指标变化原因。

## 3. 已有产品的处理

先还原与本次改动有关的入口、角色、主流程、对象状态、字段、权限、政策、服务规则、当前数据和已承诺范围。用户未要求改变的部分默认保留。

“默认保留”只表示不主动改变已经确认的现状，不能用来补造现有入口、人工流程、申诉渠道、运营能力或系统机制。没有当前来源时，将其写为待还原的基线，方案使用条件分支，不写“沿用现有能力”。

- 通用安全、权限和数据正确性原则可以作为设计要求，不能反推当前产品已有缺陷；
- 参考材料来自另一行业、国家、角色或服务模式时，只借鉴方法，不继承其业务事实；
- 对高风险或不可逆动作，关键信号未知时保持原状态、原路由或人工处理；
- 对低风险、可逆细节，可以给出暂定设计和调整条件，不需要把所有内容都冻结为“待确认”。

## 4. 对外可核验事实

身份资质、价格权益、保险退款、服务时效、功能范围、效果收益、安全隐私、政策合同和对外承诺等易变化内容，需要当前来源。

缺少来源时，可以提出产品要验证的主张、建议文案方向或参数设定方法，但不能把具体卖点、数字和承诺写成已确认事实。

## 5. 缺失信息时继续交付

- 会影响安全、合规、现状路由或不可逆决定：冻结受影响动作，其他部分继续；
- 不同答案对应不同方案：给出条件方案和推荐选择；
- 低风险且可回退：给出暂定方案，并说明观察信号和调整条件；
- 不影响主判断：采用合理默认值，不把用户留在问题面前。

文档末尾只保留会改变方向、范围或上线条件的少量问题，并说明暂不回复时采用什么决定。

## 6. 来源质量与新鲜度

当前产品状态、价格、政策、排期、负责人、服务承诺和外部能力属于易变化事实，优先回到最新一手来源。二手总结只帮助定位，不能覆盖原文。用户提出的日期属于目标；没有技术、资源和依赖评估时，不能改写为可行排期，即使方案被缩小或改成影子运行。研究证据说明样本、用户分层、时间与方法；竞品、市场和行业结论注明来源时间，无法访问来源时降低结论强度。
