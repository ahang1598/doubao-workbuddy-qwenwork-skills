# 飞书云文档与可视化交付

在用户要求飞书交付，或当前环境已接入飞书且正式方案未指定其他载体时使用本参考。使用前读取当前环境中对应文档能力的最新说明，不猜测命令、属性或接口；用户指定其他载体时，改用该载体的专业能力。

## 1. 选择载体

- 当前环境已接入飞书、用户未指定其他载体，且任务会产生正式产品成果：默认飞书云文档；
- 简单判断、一句话回复或用户明确只要聊天：直接回答；
- 用户指定 PPT、Word、HTML 或 Markdown：服从指定载体并完成真实预览。

方案包含关键交互、流程、状态、角色交接、依赖或阶段关系，且图能明显降低理解成本时，至少提供一种合适的可视化；简单判断、规则说明或短方案不强行画图。在飞书中需要自包含可视化时，默认通过原生 HTML5 Block 承载；只有用户明确要求原生画板，或 HTML5 Block 实际创建、渲染或预览失败并返回明确错误时，才改用画板。

## 2. 先决定图要帮助读者理解什么

图型由核心关系决定：

| 核心关系 | 合适表达 |
|---|---|
| 页面、入口和操作 | 低保真原型 |
| 多步骤和分支 | 流程图 |
| 多角色交接 | 泳道图或服务蓝图 |
| 状态、失败和恢复 | 状态图 |
| 指标与因果 | 指标树或因果图 |
| 资源和前置 | 依赖图 |
| 候选方案取舍 | 取舍矩阵 |
| 阶段结果和门槛 | outcome-driven Roadmap |

一张图只回答一个主要问题。通常先做一张主图；只有多个不同决定都需要视觉表达时才增加互不重复的图。不用甘特图替代产品路线图，不把流程图当成所有方案的默认答案。

状态、路由或权限任务先理清判定顺序和关键边界。主图呈现会改变结果的条件、去向和失败恢复即可；信号来源、字段定义和详细验收留在正文，不为覆盖字段把图塞满长句。

## 3. 制作 HTML5 Block

根据核心关系制作完整、单页、自包含、响应式 HTML，并将其作为文档原生 HTML5 Block 插入对应结论附近。

- 图可以表达已确认事实、证据推断、产品决定和明确标注的探索方向；不能把建议画成当前已有能力；
- 不用模拟数据、示例数字或补造明细填满画面；
- 页面原型展示入口、控件、关键反馈和重要异常，不包装成最终 UI；
- 流程图展示触发、动作、关键分支、结果和恢复；
- Roadmap 展示阶段价值、依赖、进入条件和调整触发器，不凭空增加日期和收益；
- 使用适合阅读的短文案，不把需求表、内部字段或检查词逐字搬进图中。

插入前真实渲染，检查中文、节点、连线、交互和响应式宽度。插入后读取文档返回的真实资源并再次预览；`data-ref`、源码正确或接口成功都不能替代用户可见结果。

## 4. 创建或更新云文档

1. 读取必要材料并形成产品判断；
2. 创建标题、决策摘要和完成当前行动所需的章节；
3. 把主图放在对应判断附近，再补充规则、范围和验收；
4. 修改已有文档时先读最新结构，只改目标区域并检查相邻内容；
5. 写入失败、部分成功或目标不存在时，定位真实原因，不把剩余内容堆到错误位置；
6. 完成后回读标题、正文、表格、链接和原生资源，逐张预览可视化。

最终仍无法创建或预览时，可以交付已完成的本地成品或正文草案，并准确说明未完成环节；不能用聊天文本、源码、截图、空画板或资源 token 冒充已完成的云文档。

## 5. 图文一致性

正文与图保持核心对象、结论、范围、条件、去向和数字一致，但不要求使用完全相同的句子。图不能把候选项画成确定范围，不能把推测现状画成已确认现状，也不能为了“必须有图”补造页面、状态、卖点或数据。

交付前确认默认文档宽度下无溢出、遮挡和不可读文字；每张图回答不同问题；文档修改未破坏原内容。没有完成真实预览时明确标为视觉未验证。
