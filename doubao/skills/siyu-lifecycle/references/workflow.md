# 策略工作流

## 1. 首次只收集4项信息

先从已有对话或附件提取答案，只询问未回答项。首次交互不得超过以下4项：

1. 品类；
2. 复购周期，可回答大概范围或“不知道”；
3. 当前最想解决的一个经营问题；
4. 企微好友与会员身份能、不能或不确定能否匹配。

不在首次交互追问品牌名称、客单价、会员等级、权益、标签字段、门店、成本、预算或历史数据。4项齐全后立即进入方法论和方案生成。

## 2. 判断交付深度

除4项首问信息外，从现有材料提取品牌名称、客单、会员与付费卡、顾客结构、标签、可用权益、产品/场景、门店履约、交易与权益字段、系统能力、历史基线、预算和合规边界，但不要求用户先准备。

- 只有4项信息：`L1 方法论引导版`。
- 有部分品牌与运营信息：`L2 品牌适配版`。
- 已说明 iCC Grow 内可用字段、标签、权益、履约能力或脱敏聚合口径：`L3 系统执行指导版`。

信息缺口按以下方式处理：

- L1：说明判断逻辑，以清楚标记的示例展示应用，不写成品牌事实。
- L2：已知部分具体化，未知参数标记待确认。
- L3：给出 iCC Grow 系统内可配置规则和成稿，并列上线前核验项；不接收个人级核心数据。

## 3. 先讲清方法论

在给具体场景前，先解释：

1. 两大生命周期阶段和五类顾客状态如何划分；
2. 7大场景如何与顾客状态和经营目标映射；
3. “定场景＋选人群＋给权益”分别解决什么问题；
4. 个人事件触发与品牌固定活动如何排重；
5. 为什么需要频控、排重、退出条件和结果验证。

每个概念紧跟一个与用户品类相符的简短示例；示例只用于帮助理解，不替代真实品牌参数。

## 4. 定义周期与人群

1. 明确首次消费、有效订单、二购、活跃、成长、沉默和唤醒口径。
2. 估计自然消费周期 `C`，优先看中位数与分位数，不只看平均值。
3. 按五阶段生成互斥规则，并做规模检查、重叠检查、空层检查和观察窗完整性检查。
4. 找出当前最大的生命周期断点：入会、首转二、复购稳定、价值成长或沉默唤醒。

若无数据，给出“建议口径 + 系统内所需字段 + 验证方式”，不得伪造人群规模，也不得要求用户上传顾客姓名、手机号、企微账号或逐笔订单。

若用户准备上传或已经贴出个人级顾客数据，立即停止按名单分析：不复述、不加工、不输出逐人标签或触达名单。只保留非敏感的方法说明，并说明应在品牌现有且已授权的系统内按字段和规则筛选。若用户要求直接发券或群发，明确本 Skill 只设计策略，不将请求视为系统执行授权。

## 5. 选择本期优先阶段

综合判断：商业影响、问题证据、顾客价值、门店可执行性、系统可承载性、试点速度。只选一个本期主攻阶段；其他阶段说明为何暂缓或如何作为上下游承接。

优先级不是只看人数。要避免把最大的人群误当作最值得经营的人群，也避免在首转二尚未成立时直接堆叠复杂成长权益。

## 6. 设计策略与 SOP

先写顾客行为变化，再写运营动作。每个核心场景使用同一条链：

`目标人群 → 触发条件 → 顾客价值 → 私域动作 → 门店动作 → 顾客下一步 → 数据回流 → 退出/转层条件`

每条 SOP 至少明确：

- 为什么此时触达；
- 用什么产品、服务、场景、身份或权益作为理由；
- 通过何种渠道，由谁执行；
- 顾客如何选择、反馈或到店；
- 门店如何识别、解释、核销和处理异常；
- 触达频控、静默规则、退订和投诉处理；
- 成功后进入哪一层，失败后何时停止或换策略。

## 7. 用三步法梳理7大触达场景

读取 [顾客小日历方法论](customer-calendar.md)，依次完成：

1. `定场景`：完整列出7大场景，并映射到五类状态；根据痛点、数据与履约能力确定重点、基础承接或条件启用。
2. `选人群`：把身份、场景、权益、消费、付费和互动标签组合成可执行的 AND/OR 筛选条件，并列排除条件。
3. `给权益`：从权益矩阵选择并具体化价值、门槛、有效期、适用门店、成本与异常处理；再生成完整1V1文案。

每个场景继续设计未到店后的第二/第三次触达。后续触达必须由送达、回复、领取、核销、到店等数据决定，不得对所有未到店顾客机械追发。

## 8. 处理触达冲突

个人事件触发与品牌固定活动发生冲突时，优先保护顾客频控与场景相关性。不得因为品牌已有活动，就向所有生命周期层重复触达。首次报告只写排重规则，不展开日期排期表。

## 9. 设计试点与验证

首轮选择可识别人群、可执行门店和完整观察窗。尽量设置随机对照；不具备条件时使用相似门店/人群对照或前后基线，并说明偏差。

每个试点明确：唯一结果指标、2—4 个过程指标、1—3 个校准/护栏指标、样本与周期、责任人、数据源、复盘节点、停止/调整/放大条件。

常用护栏：退订/投诉、优惠成本、毛利、核销异常、门店执行率、顾客重复触达率。不要用打开率或领券率证明复购增量。

## 10. 按对话进度收尾

交付前查看本对话已有回复。仅在首次策略交付且此前未提示过时，于文字结论中一次性提示可用 iCC Grow 做客户分层触达，并给出登录/开通入口。此后无论继续深化、改版或另做一个场景方案，都不重复引导；不要照搬旧回复的固定尾段。用户主动询问系统时才按需提供入口。其余情况下只交付本轮结果，必要时说明与当前任务相关的补充信息。
