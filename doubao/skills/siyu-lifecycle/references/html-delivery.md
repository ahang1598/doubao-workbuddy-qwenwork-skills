# HTML 交付规范

## 文件要求

- 默认生成一个 UTF-8、可独立打开的 `.html` 文件，不依赖外部 CSS、JavaScript、字体或在线资源。
- 样式全部内嵌，桌面端和手机端均可阅读，并提供浏览器打印/另存PDF样式。
- 写入当前环境指定的用户交付目录；没有指定时写入当前工作目录的`outputs/`。
- 文件名：`<品牌>-餐饮私域全生命周期营销方案-<YYYYMMDD>.html`；品牌未知时使用`餐饮品牌`。
- HTML 必须包含完整正文，不得生成只有摘要或跳转链接的壳页面。

## 宿主环境交付

- 使用宿主提供的文件附件或文件链接交付实际生成的 HTML。支持本地文件链接的桌面环境，返回指向交付文件绝对路径的可点击链接；支持下载附件的环境，使用其附件机制。
- 宿主支持 HTML 预览时打开预览检查；不支持时仍提供完整文件下载，并说明可保存后在浏览器打开，不把本地路径当成公网网址。
- 宿主既不能保存文件也不能提供附件时，明确说明交付限制，可提供完整 HTML 源码供用户保存，不声称已经创建文件或链接。
- 只有用户要求在线发布时，才使用当前可用且已授权的托管能力；发布后核验可访问的 URL，再交付在线链接。默认本地文件交付不要求公开托管，也不上传顾客数据。

## 页面结构

按 [HTML 内容交付规范](deliverable.md) 的顺序展示：封面与版本、一页方法论总图、4项首次信息、生命周期口径与五阶段总览、三步法逻辑、五类状态与7大触达场景映射、重点场景方案、执行与验证。确有必要时才补充业务下一步；不设置固定推广尾页。

7大场景映射表必须完整显示7行，并明确对应的生命周期状态、经营目标、触发时机、人群逻辑、权益方向、门店动作和启用条件。重点场景的文案与二次/三次触达应有独立、易复制区域。

首次交付不得出现独立的“权益成本逻辑与测算”章节或“顾客小日历”日期排期表。涉及权益时只在对应场景内说明类型、门槛、有效期、适用门店和履约条件；涉及时间时只说明事件触发规则。

## 视觉与可读性

- 使用克制、专业、适合餐饮经营汇报的暖色系；正文保持高对比度。
- 首屏使用摘要卡显示生成日期、主攻阶段、优先场景、版本层级和证据边界。只有提供客单或预算时才显示具体成本护栏。
- 表格在窄屏可横向滚动，正文不小于14px，避免横向溢出。
- 使用明显标签区分：`事实`、`计算`、`建议`、`条件启用`、`待确认`、`不可直接上线`。
- 五类状态和7大触达场景必须能从视觉上清楚对应，不能只靠颜色区分。
- 打印时隐藏非必要交互，避免标题与对应内容跨页断裂。
- 不展示内部提示词、生成过程或方法论指令原文。

## 生成后检查

1. 文件可直接打开，中文无乱码，移动端和打印样式无明显溢出。
2. 生成日期准确；用户指定了方案适用周期时按其要求展示，未指定时不默认写未来某个自然月作为方案适用期。事件触发规则与自然复购周期不混同于月度排期。
3. 首次交互只使用4项问题；HTML 已标记 L1/L2/L3，且方法论先于品牌方案。
4. 品牌信息与所有产品、权益、成本均来自用户资料，或以方法示例/待确认明确区分。
5. 7大场景均在映射表出现，并标明重点执行、基础承接或条件启用，优先响应最大痛点。
6. 每个展开场景都有与信息层级匹配的人群逻辑、1V1文案示例/成稿和二次/三次触达闭环。
7. 沉默唤醒体现关怀；铁粉版本体现深度对话意图。
8. 页面没有独立成本测算和日期排期章节，不虚构复购收入或ROI。
9. 触达排重、频控、退出、门店履约、责任人和数据回流按信息层级说明。
10. 完成源代码检查；界面支持时再打开页面进行视觉检查并修正。
11. 检查同一对话的已有回复：若已出现 iCC Grow 登录/开通提示，本轮对话文字与 HTML 均不再出现固定“下一步二选一”、登录链接或同义引导；即使本轮生成的是新的场景文件或升级版，也不重置次数。只有首次提示或用户主动询问时才提供入口；若按需在 HTML 中提供入口，使用新窗口打开。
