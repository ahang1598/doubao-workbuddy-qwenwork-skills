# 动效设计与编写

输入：已选节点、表达内容、全片风格与分组、候选时段源帧。此时读取 [场景与动作参考](scenario-selection.md#节点与表现)，也可自行设计更合适的表现；构图、样式和动作直接写入 HyperFrames HTML/CSS/GSAP，不再写回计划作文字说明。

## 分组设计

同组使用共用样式常量和生成函数，统一文字层级、配色、底板、描边及质感；单条根据语义采用不同构图与动作。分拍、纠正、对比、步骤推进分别实现，不统一替换为整体淡入。

### 对比与可读性

- 依据实际背景选文字和关键图形颜色；背景复杂或明暗变化时调整颜色、描边、底板或位置。
- 文字完整揭示后留足稳定阅读时间；阅读阶段避免持续位移、缩放或闪烁。
- 对比处理与揭示动作直接落实在代码中；阅读期写入执行字段 `hold`。字号按下方短边比例确定。

### 大小与视觉分量

先按动效类型、信息层级和预期播放场景确定清晰可见的文字与整体尺寸，再选择避开人脸、字幕和关键内容的位置。不得为了塞入空隙把动效缩得过小。

字号下限按原片短边计算，横屏、竖屏和方形均使用同一公式：

`S = min(视频宽度, 视频高度)`；`字号下限 = ceil(S × 用途比例)`，单位为原片像素。

| 文字用途 | 字号下限 |
| --- | --- |
| 辅助说明、次要信息 | S 的 4% |
| 人物名、产品名、普通主文案 | S 的 6% |
| 关键词、卖点、情绪花字、强调数字 | S 的 8% |
| 短标题、强情绪大字 | S 的 11% |

- 这是本 Skill 的默认设计下限，不设统一上限；根据强调程度、字体和播放场景继续放大，不把所有文字贴着下限设计。
- 按文字实际用途选档；同一动效的主字与辅助字分别计算，不将关键信息归为辅助字来缩小。
- 比例约束稳定阅读阶段的有效字号，不是文字总宽度、行高、可见字形高度或容器面积。CSS `font-size` 还须计入自身及祖先的缩放，不通过 `scale`、`zoom` 或压缩字形绕过下限；进退场可短暂缩小。
- 例如 1280×2272 视频的关键词下限为 103px，1280×720 为 58px。

容器随文字、图标和间距适配，长文案换行、重排或拆分。同组保持一致的文字层级；不要仅放大底板或缩小整组来迁就位置。

### 位置与保护区

- 保护人脸及头部轮廓、关键手势、原字幕、关键文字和正在展示的产品细节。普通背景、非关键衣物和材质区域可适当覆盖，不把整个人或整个产品默认设为禁区。
- 人物条优先选择对应人物下方的非关键衣物区域或附近留白，避开所有人物的头脸、关键手势和原字幕。
- 在可读尺寸下选择与内容或人物有关联的位置，不默认顶部中央、角落或底栏；避免贴着头顶，避免把第三方身份标签放得像在标识当前人物。
- 按规划中的按需采样评估完整时段的移动与切镜，不确定时补看相关短片段。跨镜头不能兼容同一布局时，结束、拆分或重新布局；保护区按实际镜头记录，移动对象合并多帧范围。
- 引线端点必须落在对应对象上。不同细节分别标注；目标移动或消失时调整或结束标注。缺少可靠轨迹则缩短至稳定镜头或改用无引线说明，不画装饰性假指向。
- 空间不足依次换位置 → 重排或精简文案（保持可读尺寸）→ 换表现形式 → 在语义允许范围内调整时段；仍不合适则取消并写 `omissionReason`，再核对密度。
- 将倾斜、运动、引线和装饰计入活动范围；外接矩形跨越受保护主体的多组图形拆成独立动效。实现后按 [排版与测量](#排版与测量) 定稿矩形与工程定位。

## 表现分布

实现时按时间顺序统看全片的表达形式和动作。大部分节点重复时，判断不同需求是否被套成同一种表现；仅换文案、颜色、图标或组名不算变化。同类需求可复用，不设种类配额，不另写报告。

## 编写与测量流程

由主 Agent 统一维护风格、计划和工程，按组编写动效，按 [常驻测量](#常驻测量) 启动常驻服务。

- 每组先完成并测通一个代表动效，再展开其余变体；每条达到可测状态即提交，不等全部写完。
- 整个任务复用一个浏览器、一个页面，队列依次测量。提交至结果返回期间不修改对应工程；失败后定点修正并重新提交。
- 根据结果更新计划与工程定位，核对保护区、时间和动效间重叠；仅受影响条目复测。
- 全部编写和复测完成后关闭测量服务，再启动渲染队列。异常退出时同样关闭服务；浏览器意外退出后由服务在下一条任务恢复。

## 实现

根据实际场景自行设计并编写 HTML/CSS/GSAP 动效，遵守上方风格、字号、位置和表现分布要求。

HTML、JSON 和生成脚本统一使用 UTF-8；读取和写入时显式指定编码，修改后核对中文内容。

1. 按 [工程接口](project-contract.md) 准备本地原片并补齐执行字段，`mode` 使用 `custom`，`style.minFontSize` 至少为短边的 4% 向上取整。确定可读字号和候选布局后运行 `node <skill>/scripts/prepare.mjs <task>/plan.json` 生成骨架；已有完整工程时可用 `source` 指向它。
2. 维护共用样式常量，按 `style.groups` 编写组内生成函数，逐条传入文案、时间、布局及组内变体。生成函数可放任务目录，运行所需样式、时间线和资源内嵌或复制到各工程中。
3. 在任务工程 `effects/<id>/index.html` 中完成结构、样式和时间线，移除 `AUTHOR_CUSTOM_EFFECT`。遵循 [HTML 契约](project-contract.md#hyperframes-html-契约)，按真实口播或反应落实揭示时刻；具体设计仅维护在代码中。
4. 字体、配色和质感遵循全片 style；字号、行高、内边距、对齐和位置直接在 CSS 中实现。按 [大小与视觉分量](motion-authoring.md#大小与视觉分量) 的短边比例下限落实组内主字与辅助字字号，再结合源帧选择避让位置，进退场与展开动作在 GSAP 中实现。
   按 [对比与可读性](motion-authoring.md#对比与可读性) 落实文字、关键图形与实际背景的对比处理，并保留稳定阅读阶段。测量只确认几何范围，不代表已验证合成画面效果。
5. 按下节测量实际工程，更新计划的 layoutRect、motionBounds，同步工程定位并重测受影响条目。prepare 默认保留已有代码，修复时定点修改对应工程。
6. 主 Agent 汇总后按 [执行与交付](verification.md) 校验、统一渲染、合成。

可用 `shellHTML(e,c,body,css,timeline)` 生成 HTML 外壳：从 `scripts/common.mjs` 导入 `loadConfig`、`shellHTML`，通过 `loadConfig(planPath).config` 获取 c，从 `c.effects` 取得对应 e。body/css/timeline 分别是内容结构、样式和 GSAP 语句；外壳提供暂停时间线 `tl`、时长秒数 `D` 和本地 GSAP。外壳自动生成下方定位层，body 只写内部内容。

## 坐标与定位

- 原工程按原片尺寸的完整透明画布编写与测量；`#effect-clip` 不按 motionBounds 裁剪，画布边界以外仍不可见。内部定位和内容层默认 `overflow:visible`，仅在明确需要揭示等效果时对局部元素加遮罩。
- `shellHTML` 根据 layoutRect 自动定位 `#effect-stage`，其左上角对应原片中的 x/y。
- body 位于 `#effect-content` 内，使用局部坐标或普通文档流排版，不重复加原片 x/y。进退场位移、缩放和旋转作用于 content 或内部元素，不改 stage 的定位。
- 例如 layoutRect 为 `[40,570,340,90]`，内部元素 `left:20px;top:15px` 的画面位置就是 `(60,585)`。
- layoutRect 的 x/y/width/height 变化后，通过同一生成函数重新生成外壳；内容排版同步适配。motionBounds 变化后同步核对运动设计和保护区，不在原工程中据此裁剪；render 按该范围加余量生成局部副本，见 [执行与交付](verification.md#2-渲染与合成)。导入 source 工程也遵循该结构。

## 排版与测量

先落实组内文字大小和视觉分量，让容器适配内容，完成代码后测量实际范围，再定稿矩形与位置。候选矩形不是固定设计尺寸；仅超出候选矩形且实际内容仍满足画幅、保护区和同期动效约束时，回填矩形并同步定位即可，无须为旧矩形重排内容。空间不足时按 [位置与保护区](motion-authoring.md#位置与保护区) 的顺序处理，不靠裁剪或缩小到难以阅读来通过。

有底板的文字组件，底板尺寸由文字、图标、间距和内边距共同决定。先按实际字体完成内容排版，再确定组件尺寸与位置；超过可用空间时换行或重排。阅读状态下，文字完整位于对应底板内并保留内边距，再测量整个动效的布局范围。

在承载文字的 HTML 底板元素上标记 `data-text-container`，文字放在其内部，用 CSS padding 声明内边距。例如 `<div data-text-container style="display:inline-flex;padding:16px 24px"><span>精致刺绣 + 玩偶挂件</span></div>`。外伸引线和装饰放在底板外的同级元素中，仍计入整个动效范围。

只测稳定阅读状态；全程运动范围由代码确定并写入 motionBounds。测量返回 `suggestedLayoutRect`（原片坐标、向外取整）。仅超出预估 layoutRect 时返回 `needsLayoutSync:true`，不作为测量失败；按建议回填并保留内容的画面坐标，不为旧矩形缩字。若 stage 原点改变，内部坐标须反向补偿；仅同步元数据且画面几何不变时无需复测，影响换行、尺寸或位置时才复测。全程 `motionBounds` 仍须另行核对，回填后执行计划校验。

### 常驻测量

在宿主可持续运行的后台会话中启动一次，看到 `ready:true` 后提交：

```bash
node <skill>/scripts/measure-service.mjs serve <task>/plan.json --browser "<浏览器路径>"
node <skill>/scripts/measure-service.mjs submit <task>/plan.json --effect intro
```

每条命令等待并返回本次结果；浏览器和页面保留供后续测量及复测复用。默认测量 `hold` 中点；尚未确定 hold 时用 `--at-ms <相对起点毫秒>` 指定文字全部揭晓、计数结束的时刻。提交到返回期间保持工程不变。

- 通过后同步计划与工程；不通过则修正并重新提交该条，其他任务仍可继续。
- 结果保存到 `measurements/<id>-<请求ID>.json`；采用前核对工程摘要和布局是否仍有效。
- 全部复测结束后关闭服务；已排队任务会先完成：

```bash
node <skill>/scripts/measure-service.mjs status <task>/plan.json
node <skill>/scripts/measure-service.mjs stop <task>/plan.json
```

服务仅监听本机，连接信息位于 `.measure-service/`。单条执行超时 30 秒后返回失败并重置浏览器；空闲 30 分钟退出。新增动效 ID 或原片画幅改变后重启。遗留目录须在确认 owner.json 中服务和浏览器进程已退出后移除。

宿主无法保持后台进程时使用单次命令，每次独立启动浏览器：

```bash
node <skill>/scripts/measure.mjs <task>/plan.json --effect intro --browser "<浏览器路径>"
```

### 仅试调布局时

`submit --spec <单条JSON文件>` 可覆盖该次参数，不改共享计划。对象含 `id`、`durationMs`、`hold`、`layoutRect`、`motionBounds` 和可选 `project`，格式同 plan.effects；project 始终相对 plan.json。最终采用的值须回填计划。

### 诊断结果

- `readingBounds` 是文字、底板和 SVG 的实际几何并集，不包括透明定位容器；阴影、滤镜和 SVG 标记需另留余量。
- `boundsDiagnostics` 给出相对 layoutRect、motionBounds 的四向越界量及边界来源元素，容差 1px。依据来源修正内容或候选矩形，不为旧矩形盲目缩字。
- `cardDiagnostics` 检查 `data-text-container` 底板：文字矩形进入 padding 仅提示检查视觉间距；越出底板内边界才失败。不要仅为清除提示增大行高。底板和祖先的整体变换会被消除，内部元素变换保留。
- `fonts[].fontSize` 是 CSS 字号，不含 transform 缩放；有效字号须按 [设计下限](#大小与视觉分量) 核对。
- 无可见内容、文字溢出、超出画布或 motionBounds、意外裁剪仍返回 `ok:false`，命令非零退出；仅 layoutRect 不匹配提示同步，正式 bounds-check 仍严格检查。测量通过不代表已检查保护区、同期动效重叠、颜色对比、目标指向或全程运动。

### 图片与 Canvas

图片与 Canvas 在元素上声明 `data-content-bounds="[x,y,width,height]"`，表示元素左上角起算的局部 CSS 像素内容范围；整张不透明图片可填完整尺寸。测量不扫描透明像素。内容或排版变化时同步声明；仅支持普通二维 transform，不使用透视或独立 rotate/scale 属性。
