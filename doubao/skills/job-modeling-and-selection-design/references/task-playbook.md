# 任务剧本：岗位建模甄选

## 状态机

`intake_required` →（齐料）→ 建模/JD/甄选设计 → 质量门 → `ready` | `degraded`  
外发/写入请求 → `confirmation_required`  
相邻域 → `routed`  
合规冲突 → `stopped`

## 模式细节（共享方案包）

### jd_write
1. 对齐业务产出与成功标准  
2. 推导职责与三档任职要求  
3. 若无模型，生成「精简人才标准摘要」并建议后续建模  
4. JD禁出现BEI/维度权重等对候选人不可读黑话  

### competency_model
1. 维度数采用覆盖岗位成功标准所需的最小集合，并记录组织/任务依据；不得复制第三方固定数量  
2. 每维：定义、可观察正负向行为、经组织确认或为本任务显式设计的统一锚点；不得默认固定 1–4、1–5 或字母尺度  
3. 每维回答「为何本岗位必需」  
4. 保证面试可观察、可区分  

### review_driven_model
1. 仅接受**已标准化**面评结构（结果、轮次、职位、评语等已映射）  
2. 原始文件未清洗 → `routed` 到清洗前置  
3. 从评语提炼行为证据驱动维度；样本不足段落标注「样本不足，置信度有限」  
4. 不做假装精确的通过率承诺；不发明统计默认值  
5. 统计类结论若无法复核则降级为定性归纳  

### structured_interview
1. 先锁定模型（活跃标准）  
2. 按用户指定环节增量设计，不擅自做全流程  
3. 每题：统一核心问题、按证据需要设计追问、考察点映射维度、合格/优秀/风险信号  
4. 题目情境通用，不绑定真实候选人隐私  
5. 输出评分表：维度×锚点×证据栏  

### campus_social_selection
- **校招**：潜力与 thrivability、项目/实习证据、价值观情境；可含AI初面/初试/复试/终面/HR面中用户指定子集  
- **社招**：履历深度、职级差异化（若职级未知则单层并`degraded`）、业绩证据与协作影响  
- 两端共享同一方案包骨架，章节开关不同  

## 需求对齐清单

- 业务痛点与90天成功画像  
- 团队缺口：技能/认知/管理跨度  
- 反面：常见失败模式  
- 约束：地点、远程、出差、语言、合规红线  
- 薪酬与HC：用户未给则写「待确认」  

## 结构化面试准备边界

本包使用同岗统一问题、能力映射、行为证据、panel 分工、统一评分锚点和 debrief 模板；不采用外部模板的固定能力数量、问题数量或评分尺度。候选级简历点评、个性化补问、约面和面评写回交给 `interview-execution-and-review`。

## 歧视与合规速查（Hard）

禁止写入筛选标准：民族、种族、性别、性别认同、宗教、年龄（法定例外外）、婚育、残疾（与岗位真正必要资格无关时）、籍贯歧视等。与岗位真正必要的资格（如法定执业资质、安全涉密）须写明法源或业务必要性，否则标「待确认」。

## 与写入/发送

默认交付对话内方案包。若用户要求「发招聘门户/群发面试官」：列出将发送对象与正文摘要 → `confirmation_required` → 未经确认不宣称已发送。

## 降级话术要点

说明缺什么、对哪些章节影响、用户补什么可升至`ready`。
