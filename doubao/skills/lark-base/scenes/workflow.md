# 工作流

## 开工必读

- **接收人绑定承载职责的人员字段。** 用户说负责人、审批人、处理人、区域经理、组长时，接收人引用触发记录或查找结果里对应的人员字段；样例数据里该列的取值不影响配置。只有原话说“发我／通知我／本人”才用当前用户；不写死某个人、配置者、Base 创建人或记录创建人。
- **先列“原话角色 → 人员字段”对照再配置。** 例如处理人对应记录的“处理人员”字段（不是派单人），主管对应员工表的“直属上级”字段。角色在关联表上时，接收人写 `{"value_type":"ref","value":"$.<触发步骤>.<关联字段ID>.<人员字段ID>"}`，或先查找记录再引用其人员字段。表里的查找（lookup）类型字段作接收人能通过校验，但不会送达。表里没有承载该职责的人员字段就先建字段，不用“通知管理员再转告”。
- **职责不同的人分开发。** 员工和主管、申请人和审批人各用一条消息，正文写这个人要做的事；文案对所有人都适用时才合并。
- **汇总通知带出明细。** “通知新增了哪些／有哪些待办”时，正文引用查找结果字段或循环逐条发送，不只发数量和链接。`<field_id>` 取自 `+field-list`：`{"value_type":"ref","value":"$.<find_step>.fields.<field_id>"}`。
- **原话列出的每条流程各建一个 Workflow。** 交付前逐条对照原话，缺一条就补建。
- **业务条件写进触发器或分支。** “结果为不合格时”“金额超过阈值时”“数量低于下限时”要落成条件，不能对所有记录触发。`ChangeRecordTrigger` 的 `condition_list` 不能为空数组；没有条件就换 `AddRecordTrigger` 或补条件。
- **审批、生成单据、更新库存或状态必须有写记录的动作。** 只发通知不算完成；审批要有待审批触发、通知审批人和按结果写回状态。
- **触发类型按原话的时间描述选。** 相对日期字段的提醒（到期前、截止后）用日期提醒；“低于／超过／变为某状态时”用记录变更触发加条件；原话含每天、每周、每月等周期才用定时触发。“上周”是 `lastWeek`（上一个自然周），“最近 7 天”才是 `theLastWeek`。“到了／当天”是 `offset: 0`，“提前 N 天”是 `-N`，“超期”是 `+1` 加未完成条件，不自行提前一天。
- **先 disabled 预检再启用。** 回读条件右值、接收人、动作字段都对了，再 `+workflow-enable`。

原话里的动词决定最少要有哪些节点；只配消息节点都算没做完：

| 原话 | 最少节点 | 反例 |
|---|---|---|
| 通知／提醒某个职责的人 | 接收人引用触发记录或查找结果里该职责的人员字段 | 发给当前用户，正文写“请转告某某” |
| 派给某人处理并限时 | 新增或修改记录，写入负责人字段和截止时间字段；再通知该负责人字段 | 只发消息说“请某某处理” |
| 完成后更新另一张表（库存、设备状态、余额） | 状态类：查找关联记录 → 修改记录。累计量能用关联公式算出时（如期初 + 入库合计 − 出库合计）优先建公式字段；必须用 Workflow 时写成“查到的当前值 + 变动量” | 只发消息；用变动量覆盖原值；公式已算过的累计又让 Workflow 加一遍 |
| 生成某某单 | 新增记录，带上触发记录的关联和关键字段 | 只发消息说“已生成” |
| 超期升级 | 截止日之后的日期提醒（`"offset": 1`）加“未完成”条件，通知上级字段 | 截止当天提醒，或发给自己 |
| 走审批 | 新记录初始状态为待审批 → 通知审批人字段 → 按结果写回审批状态 | 只通知审批人，状态不变 |

关键步骤：触发 → 条件 → 动作 → 写入目标 → 接收人字段 → 目标状态 → 创建（disabled）→ `+workflow-get` 逐项核对 → 启用 → 再读状态。

| 交付前核对 | 读取 | 通过条件 |
|---|---|---|
| 触发与条件 | `+workflow-get` | 触发类型和业务条件与原话一致，条件右值非空、类型对 |
| 接收人 | 同上，对照 `+field-list` 的字段 ID | 职责类接收人引用真实人员字段；分别通知的人各有一条消息 |
| 业务动作 | 同上 | 审批、回写、生成记录等要求都有对应写入动作和目标表 |
| 状态 | `+workflow-get` 的 status | 应启用的已 enabled，要求草稿的保持 disabled |

创建命令只有 `--json`（支持 `@file`）；顶层 `client_token`、`title`、`steps` 缺一即被拒绝。先照 [最小请求体](../references/workflow-commands.md#最小请求体) 写，再按 [步骤图结构](../references/workflow-schema.md) 和示例换节点；条件、接收人、引用的值形态见 [值类型与条件](../references/workflow-values.md)。

## 任务导航

仪表盘按钮先确认绑定目标；绑定 Workflow 时读定义并按按钮绑定协议处理。

### 写入前路由门禁

- 一次性即时通知按主入口路由走消息。未来／定时／事件触发的提醒、预警、到期前后通知、周期汇总、状态联动、自动生成／更新记录（含一次性未来执行）用 Base Workflow；不得用 Base 外 scheduled job、会话临时定时任务、静态字段、即时消息冒充。
- 写前登记、取证：`trigger → conditions → data source → actions → output contract → recipients → target_status`。无法表达则保留原条件、标 `blocked`，不得建删条件的近似流程。
- 只总结、通知或推送时只建消息链；明确要求保存、回写或持续维护时才建其他表。
- `output contract` 登记交付的是数量、名单、明细还是汇总，以及对象集合、必要字段、单条汇总或逐条消息。要求名单时，数量和全表链接不能代替明细；呈现方式不得静默改变。所需聚合或呈现不支持时报告受阻。

## 前置检查

### 命令与授权范围

- 命中未来、定时或事件触发的任务时，Workflow 是必交付项；周期任务也在 Workflow 内完成，不能只建字段模拟流程。
- 仅明确要求自动化／修改既有 Workflow 才创建、更新、启用；未来主动提醒且流程不存在时必须创建。字段、公式、视图、Dashboard、说明不能代替自动化，其需求也不授权新增自动化。
- 只读任务只检查报告，不修复、启停或实测。

### 目标与当前定义

- 确认 Base；可信 Workflow ID 直接 get，缺 ID／归属不明才 list。更新前读全定义、记首次状态，保留未涉节点、参数、连线、引用。
- 只读本次所需表、字段、接收人、外部资源；用 `+base-get`、必要的 `+table-list`、`+field-list`、通讯录／群聊确认 ID、类型，不猜。
- 为每张涉及的表建字段 ID 到名称的映射并校验引用路径，不按顺序、同类型或近义猜字段。
- 新表样例按 [Mock](mock-data.md) 准备；有下游表时必须执行 [样例交接](#下游样例与实际执行交接)。Mock 不授权触发事件；配置、运行状态、实际执行分别验收。

### AI Agent 数据与配置准备

含 `AIAgentAction` 时按 Agent 协议配置：

- Base 数据由上游引用或已挂载查数工具获取；prompt 只写表名不算接入。范围、完整字段名、引用须匹配表结构。
- MCP 工具读写前确认 Base URL、`table_id`、字段，再写入 prompt／上游输入；表名不代替 `table_id`，不得猜 ID。
- 只改 prompt 仍保留模型、输出、工具选择；按工具调用说明更新描述。

### APIHub 资源与参数准备

含 `APIHubAction` 时：

1. 只查本次资源，优先用前置输出；按资源查询协议选 ID 类型。
2. 未指定日历则查当前用户主日历；不得凭同名删日程；移群成员前确认在群内；操作任务前核标题、负责人、状态。
3. 人员优先引用职责字段；仅有姓名先查身份，可新增人员字段存映射，不改姓名字段。无结果／重名走资源异常；多人逐个核，不以部分称全部；只加指定参会对象。
4. 配齐要求的负责人、截止日期、描述、关注人，不因可选／示例省略；动态标题／描述按要求引用，不用固定示例。
5. 先确认 Base 时区；配置时确定的时间按当前日期、时区定时点；随触发变化则用动态日期来源，不固定配置时值。按参数值类型构造。
6. 跨次触发保存创建动作返回的资源标识，后续引用同一对象；不同触发时机分流程。缺资源只阻塞依赖项。

## 流程决策

### 先确定目标运行态

每个目标 Workflow 记录名称、触发时机／方向、条件、动作、接收人／目标、`workflow_id`（新建待返回）、意图、`target_status`、启用前提。仅本次指定／新建对象进入；其他 disabled Workflow 不授权启用。

按整体最终意图而非句中关键词解析；冲突取最后一次无歧义指令：

| 指令 | `target_status` |
|---|---|
| 启用／恢复 | `enabled` |
| 停用／草稿／预览／暂不启用 | `disabled` |
| 保持启停状态（含修改触发时间但保持状态） | `preserve` |

- “检查通过后启用”：目标 `enabled`，授权检查通过即启用。
- “先检查，等我确认后启用”：仍为 `enabled`；确认前只读／准备，不启用或报达成。
- “确认后”主体不明则看上下文；仍不明且影响授权时只澄清此项。

目标状态本身不授权额外创建、修改或实际触发测试。无明确指令时从上到下匹配，命中即停：

| 意图 | `target_status` |
|---|---|
| 只读／检查／审计／解释 | `none` |
| 既有 Workflow [纯定义编辑](#纯定义编辑例外)，未要求启停 | `preserve`；祈使语气不提升为 `enabled` |
| 其余新增／配置自动化或改变执行行为 | `enabled`；未写“启用”也视为要求生效 |

### 触发器与事件范围

先定新增覆盖、监听字段、当前值或前后变化，再选节点，不凭“到达／变为”套用：

| 要求 | 选择与条件 |
|---|---|
| 新增或条件字段修改后满足阈值 | `ChangeRecordTrigger`；须接受新增、修改后仍满足条件的范围 |
| 从非目标状态变为目标，或 A 变 B | `SetRecordTrigger`；表达字段变化、修改前条件、修改后条件 |
| 到期／截止／逾期／截止后仍未处理 | `ReminderTrigger`，绑定业务日期；“仍未处理”加状态条件 |
| 原话含每天／每周／每月等周期 | `TimerTrigger`；只有原话给周期才用 |
| 新增记录 | `AddRecordTrigger` |
| 指定字段被修改 | `SetRecordTrigger` |
| 新增与任意可监听字段修改 | `AddRecordTrigger` + `SetRecordTrigger` 两条 Workflow |

按触发协议配置。只要求修改时不覆盖新增；目标变化不能只查修改后值；前后条件无法表达时报未完成，不扩大成“当前满足”。阈值／时间到达不得用 `TimerTrigger` + `FindRecordAction` 定时扫描替代，说明频率也不算实现。两个字段之间比较（如当前值 < 下限值）时，按 [记录触发条件](../references/workflow-triggers.md#记录触发条件) 建表达同一谓词的派生字段。

“一按／一键／点一下／按钮触发”优先 `button` + `ButtonTrigger` 或结果字段／视图；需沉淀则写回字段、日志表或消息，不用静态说明、普通看板、手动筛选替代。

### 业务动作与结果要求

指定动作须在执行链；逐项取证：`触发事实 → 条件 → 输入与计算 → 实际动作 → 结果承载位置 → 源记录关联`。审核留痕接收真实结果，限时处理含期限、超期路径；不得合并成通知。

- 更新状态／记录、同步结果配写动作；查询、回写、留痕消费真实结果并关联源对象。通知、发起流程、待处理记录不代表完成；取证输出、源关联、目标回读。
- 自动建任务、日程、群组用 `APIHubAction`；直接调 task/calendar/im 会立即操作资源，不能代替节点。状态字段不代替任务，改状态／隐藏不代替删除；对话搜索／写记录不代替 Workflow Agent 工具。
- 区分已通知、待处理、实际完成、结果确认；不得因通知就标已处理。无法表达的阶段保留缺口。
- 同一规则适用多来源表时，先看触发器能否统一覆盖；否则每表建等价路径，或先写统一事件表。各路径保留来源类型、源关联、条件、目标、接收人；未覆盖者标 `blocked`，不删条件。
- 数值写回区分原值、增量、新值；累计重试不得重复入账。文本／AI 结果须被要求的写入／发送动作引用；“已生成”不代替内容。
- 邮件要配置实际收件人、主题和正文。

### 分支选型

- 二元用 `IfElseBranch`；3 路及以上用 `SwitchBranch`，不得多层嵌套 `IfElseBranch`，建议设“其他”兜底分支。
- `IfElseBranch` 连线限制见 [分支协议](../references/workflow-control-flow.md#条件分支ifelsebranch)。两分支执行相同后续动作时用不同 step ID，核动作、引用、次数、副作用。当前不支持汇合到同一公共步骤：先说明限制，用户接受独立节点后才写入。

### 场景速查表

| 业务目标 | 节点 |
|---|---|
| 生成／总结／改写／提取文本，或生成标签且后续动作相同 | `GenerateAiTextAction` |
| 分析 Base 数据 | `AIAnalysisAction` |
| 明确要求 Agent／智能体，或需附件理解、工具调用、结构化输出 | `AIAgentAction` |
| 按文本语义分类且各类执行不同动作 | `AIClassificationBranch` |

多个结果供下游分别引用时，用多个 `GenerateAiTextAction` 或 `AIAgentAction` 结构化输出。

### 接收人、字段与时间条件

登记 `用户指定职责 → 本表或关联表 → 真实人员字段 → 引用路径 → 缺值时的处理`。关联字段只表示记录关系，须沿关系找到人员；相邻字段不能替代。职责／身份不明时标未就绪，不为发送而换人。

依次取首个成立项：唯一解析的点名人／群；否则职责人员字段（按语义可用创建人、修改人等系统人员字段）。本表、关联表均无时才新建；当前用户规则见开工必读。

按 [人员字段引用](../references/workflow-outputs.md#人员字段引用) 绑定。人员字段填值按 Mock 另验；Mock 默认值不得把接收人改成固定本人。

临期、到期、超期、周期截止用真实日期字段、提前量或动态 Formula/Lookup；人工状态不能证明“快到期”。日期边界写进筛选条件，不先查全部再用文案解释；偏移语义见开工必读。

## 执行与启停

连续修改按用户顺序，每步写后验收。

### 读取与解释

仅查列表／状态时报对象、状态；解释／审计时读同一 ID 完整步骤，用字段映射说明节点、条件、引用含义。

### 写入前检查

用真实资源构造完整请求；提交前 dry-run，按非空约束校验条件。

### 创建、更新与启停

仅停用：确认目标／当前状态后 disable 并验收，不重写定义。仅启用：从第 4 步开始。

1. 用完整定义、首次状态、授权范围核目标；逐流程绑定真实 ID。
2. 改触发时间、条件、接收人、动作类型／目标、连线、节点输入、工具配置等执行行为时，若已启用，先 `+workflow-disable`，回读 `disabled` 再 update；无条件流程、最终 `preserve` 也适用。禁止停用且无法安全修改时不写。
3. 保存 `client_token` 等请求标识；更新先登记改变路径、预期值，再按完整替换从原定义构造，留未改内容比较。已吻合时不重复 update。
4. 保存后 `+workflow-get`；新建／临时停用者保持禁用。按定义、专项条件预检；仅启用既有流程也预检，不为预检改定义。实触发／业务结果不属预检。
5. 预检、用户前提满足后 enable/disable；`preserve` 恢复首次状态；不重复取有效证据。
6. 按状态后置条件回读；用户要求才实测。失败转停用恢复。

### 纯定义编辑例外

仅改名称、描述、消息文案，不改执行行为且未要求启停时，跳过临时停用／状态写入，保留首次状态；仍验保存、已有条件、未涉配置。改变执行行为时，即使 `preserve` 也不适用。

### 实际执行测试

仅用户要求时，在已授权资源、收件人、动作内，设置并回读目标状态后触发、留证。目标 `disabled`，或 `preserve` 且原状态禁用时不得自行启用；获准临时运行则测试后恢复、回读。无授权路径时报未完成。

### 下游样例与实际执行交接

新建下游表沿用 Table 数据目标；来源、数量、是否造样例由 Mock 决定，不重定空表、保留来源、补数范围。符合实测条件则造事件、查结果，产出计入原数量；否则仅按原目标补样例，并区分真实证据。就绪后按 Mock 回读验全部样例数量、人员、业务一致性；下游有记录不代替实测。

## 回读验收

分记定义、目标状态、实测结果。按真实 ID 逐流程验收，数量不证明对象正确。报告对象、证据、未完成项、限制及 disabled 不触发；后续结果不代替前段验收。

### 完成条件

读取只报结果；仅启停核目标状态、保留定义，启用还须通过定义预检。创建／修改须全部适用项通过；等待确认不算完成。

### 定义后置条件

逐项核同一目标 ID 的完整 `+workflow-get`：

| 对象 | 内容 |
|---|---|
| 名称与文案 | 名称、描述、消息标题、正文 |
| 输出契约 | 数量／名单／明细／汇总、集合、字段、呈现符合要求；名单正文含对象、字段，不能只验 title/content 或用计数、全表链接 |
| 触发与时间 | 触发器、日期、时刻、周期、星期、间隔、起止时间、提醒偏移 |
| 条件与动作 | 核条件边界；目标表、字段、记录、源关联正确并覆盖业务阶段；`enabled` 只证明状态 |
| 接收人与引用 | 从 `ref` 反查表／字段；动态人员、消息／条件来源正确，群发未扩大；用不同职责数据区分相邻人员字段，样例同人不算证明 |
| 节点与连线 | 用户指定节点在实际执行链，分支和引用正确 |
| 记录触发事件 | 核事件范围、监听字段、前后条件及新增、条件字段修改、其他字段修改覆盖范围 |
| 更新保留项 | 对照更新前定义、允许改变路径；节点 ID、连线、按钮目标、接收人、未涉嵌套配置保持原义，不只比节点数／按钮标题 |

- 逐来源／分支核输入引用、目标赋值：增量不得回写原值，生成内容不得只写完成标记；循环绑定当前对象，不绑固定记录。以已有／授权样例推演新值。
- 名单／明细用至少两条命中、一条排除数据核筛选、引用；另查零结果、超出查找／循环上限，不得静默截断。未运行只报配置、样例推演。
- 独立核接收人：“把名单发我”应发当前用户，不得因样例改发名单对象。
- 错误恢复后重对原动作清单；写入退成消息时，原写入仍未完成。

### 状态后置条件

| `target_status` | 必须证明 |
|---|---|
| `enabled`／`disabled` | 同一 ID、未截断 `status` 的 `+workflow-get` 返回状态等于目标 |
| `preserve` | `status` 等于首次 get 状态 |
| `none` | 不适用状态等式；未创建、更新、启停 |

enable 后再用 `+workflow-list --status enabled` 确认。

### 实际执行后置条件

仅实测时保存触发事件、运行结果、目标记录／外部资源变化。创建、启用、Mock、配置回读不代替实测；未要求则说明未实测，不称成功。数值写回留前值、实际增量、后值并对账，检查无关对象未变；防重累计再测重复事件。生成结果须落入目标字段／消息并关联源记录，不只看成功／回执。

### 条件类型验收

1. 检查服务端完整条件，不只看名称／状态；核对条件类型、值。
2. 每个业务边界均在条件中，含修改前后筛选和监听字段；View 筛选正确不证明 Workflow 正确。
3. 条件可用 `+record-list --filter-json` 表达且有代表数据时，同口径只读筛选；无数据只验保存条件。当前命中不能证明状态变化范围。
4. Mock 支撑的每个 Workflow 均确认条件可命中该批数据；条件命中与真实执行分别留证。

### 定时排期验收

按定时回读协议比较实际触发日与要求，不用示例／无关历史日期代替。回读无法证明则说明限制，不推断生效，不因字段缺失重复提交。

### AI Agent 与 APIHub 专项验收

- AI Agent：定义核模型、输入／数据源、输出、工具、下游消费；实测查下游输出；同一会话多轮验记忆；工具调用须有记录、资源变化，模型自称“已搜索”不算。
- APIHub：定义核组件、参数、引用、连线、日历／人员／群目标；实测核任务／日程／群结果；解析写回并完整分页。

## 异常恢复

恢复限授权范围，沿用主入口通用恢复的现状确认、解析、单次修复预算；等价字段回退不重置预算。

### 配置不符与停用恢复

定义预检（含条件、排期、节点）或状态回读不符时保持禁用。若已启用，先 `+workflow-disable`，以 `+workflow-list --status disabled`、同 ID 的 `+workflow-get` 确认，再修复、重验；期间不得造真实事件。纯定义编辑只免预停用，不免失败处理。

只修不符要求或本次破坏的部分，保留其余配置。预检通过且启用前提满足才恢复目标状态；否则报未完成，不为 `preserve` 留错误的 enabled 流程。

### 条件保存失败与等价回退

原条件一次定向修复、复验仍失败，只再允许一次等价派生字段回退：用可验证文本／布尔字段表达同一谓词，再验条件／定义。不得重复提交同类失败的数值／日期条件或改事件范围、阈值、时间边界、接收人。

先验派生字段创建、计算；无法等价表达、保存或复验仍失败，仅该 Workflow 项标 `blocked` 并禁用。回退一次，不回原条件循环；继续完成不依赖它的交付物。

### 创建幂等与恢复

创建结果未知／重复提交时，按幂等协议核已建对象，再处理未完成请求；状态未知时报未完成。

### 资源与授权异常

- APIHub 身份无结果／重名：报待确认，不用当前用户、创建人、占位 ID；继续独立项，只阻塞依赖项。
- 资源不可访问／日历不匹配：按原身份修授权，不换对象；Workflow 拒绝时报日历上下文／ID 不匹配，不改 ID。
- Agent 飞书 MCP 缺授权：按 MCP 工具包协议修复所选运行身份。

### 能力不支持与常见错误

按 APIHub、AI Agent、控制流协议确认边界、说明缺口；仅用满足原需求的文档节点。替代有差异时先获接受，不自动换相近工具／通知。

命令／节点错误按错误速查修正；APIHub 群引用类型按输出引用协议修正，不据此判能力不支持。调结构回流程决策；修复守预算。
