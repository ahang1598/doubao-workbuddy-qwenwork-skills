# 简单搭建：直接落实已确定的范围

用户明确限定本次组件集合、数量或排除项，且来源、字段和口径已明确时用本页；明确只操作页面树的结构任务也按指定结构执行。只给应用页面树并说“先搭骨架”，仍须补业务内容，见下方 [骨架规则](#页面树明确不等于只交空壳)。已有对象修改走 [1-n](modify.md)；需要业务建模、新表/字段/Form/Workflow、跨页设计或整体重组走 [0-1](create.md)。任务短、数据少不等于范围已限定。

1. 复用真实 App、Page、Base 和字段。已有页面先读当前组件和位置；新建 App 则 `+app-create` 后 `+app-get`，复用默认 Page。
2. 按用户指定的数量、类型、来源、条件和位置创建；不补默认三页、T 型或额外组件。类型已定直接读对应组件文件，参数看该命令 help。
3. 同页串行写入，每次立即 `+app-block-get` 核真实保存配置；图表再用 chart_token 取数。明确几个组件就逐个确认几个，不能用别的同型图充数。
4. 组件就绪后按 [布局](layout.md#组件就绪后落实排版) 写本页布局，完整 structure 核坐标、模式、父级与保留项。已有局部追加只调整授权目标。
5. 对照原话完成 [回读与交付](../../references/base-app/app-checks.md#末次写后)，说明完成内容和未验证项。

## 页面树明确不等于只交空壳

用户已指定完整 PageGroup/Page 树并说“这版先搭骨架”，只限定结构，没有限定页内组件集合。按 [完整搭建](create.md#给定页面骨架时补齐业务内容) 在原树内尽量搭出完整应用：各页须有符合用途的真实数据组件、必要筛选和可达入口，不能每页仅放标题、富文本说明或待建设占位。首页仍按适用的完整搭建规则落实；不为丰富度增加未要求的 Page/PageGroup，不编数据、关系或无关业务流程。

例如“工单处理”组下有“待处理、已完结”，“基础配置”组下有“客户信息、服务组、SLA”，另有独立“总览”首页：最终为 **2 个组、6 个 Page**，其中 5 个组内页、1 个根首页。复用/改名默认 Page 为总览，不另留默认页；不能把客户信息等三个页升成组，也不能把总览塞入任一组。完整 page-tree-list 核类型、父级、顺序及无多余页；逐页 block-get 核有效组件及配置，再按实际打开结果确认首页与核心路径，缺实测证据标未验证。

例如“只要一页、一个列表和三个饼图，不要其它组件”，就做这四个组件；“首页放指标卡、环形图和排行榜”没有限定整个 App 只有一页，需要业务规划时仍走完整搭建。
