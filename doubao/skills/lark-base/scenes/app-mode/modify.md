# 1-n 修改：在既有应用上迭代

先按 AppMode 索引输出三行短计划：目标页/组、组件与配置变化、动作入口与回读项；交付逐项标 `已验证 / 未完成 / 未验证`。只改用户点名内容与必要依赖，保持其它配置。实际新建 App 转 [创建步骤](create.md)；只读问题见 [问答](inspect.md)。协议按 [AppMode 索引](../app-mode.md#协议索引) 命中读取，参数看精确命令 help。

## 第 1 步：定位并读原配置

- 可信 app_token/page_id 直接复用；`/app/` URL 先 `+url-resolve`；只有 Workspace 时 `+workspace-entity-list --type baseapp` 分页收齐；没有全局 app-list，不按标题猜 token。
- `+app-get` 读页面摘要与 ref（key 是已被引用的 base_token）；按名称用 `+app-block-list`，同名时结合 Page/Tab 和坐标找真实 ID。Page name 为空表示无权限，不继续读取/写入该页。
- 用 `+app-block-get` 读目标原配置。涉及布局、容器或结构时再读完整 `+app-structure-get`，确认父级、rect、顺序、邻居和同行关系；改完与原值比较。

## 第 2 步：按原范围修改

### 添加组件先按业务语义查重

先列出用户点名的每项需求，再读取目标 Page/Tab 的组件与候选 `+app-block-get` 配置，逐项决定：

| 当前实际配置 | 操作 |
| --- | --- |
| 目标位置、精确类型、来源实体、字段/聚合、范围与业务用途均满足 | 复用原 widget ID，记为已满足，不再创建 |
| 已有承载同一需求的组件，仅缺本次点名配置 | 在原 ID 上补齐授权属性，保留其余配置；类型不可原位转换时按公开能力说明缺口 |
| 没有匹配项 | 只创建该缺项，再回读实际配置 |
| 用户明确要求另加相同副本或指定多份 | 按明确数量新增，不用复用规则抵扣数量 |

同名/同型/同值不证明等价，别页不抵扣。例：已有专利总数卡/类型饼，要总量/已授权/类型/部门柱图，就复用前两项、补后二项。逐项记ID/回读，结果未知先读状态不重复建。

### 修改边界

- **目标不变**：写/读/链接同一原目标app_token，不另建/复制/另选替代；多资源分source/destination，冲突列ID/原话不盲选。仅明确授权新建才换对象，写错报告并回原目标补做。
- **只改点名属性**：名称、文案或数据修改不顺带重置尺寸、主题、图标、格式或动作。用户只改一个组件，就不扩到全 App，也不补新建默认页数/组件。
- **全局范围**：统一任务状态等要求必读 [范围协议](../../references/base-app/app-scope-contract.md)，覆盖授权内列表/Tabs/详情/视图/图表/指标源及来源视图条件，独立指标资格保留取交集（可0）。
- **完整条件**：data_sources 是有序数组整体替换；保留未被本次要求替换的筛选、AND/OR、来源、指标和排序。clear_fields、空数组与省略不同，不用 null 清空。排序按真实分组值/聚合值明确设置。
- **页与组**：Page不代替PageGroup，先查组复用，新增按 [组→页→回读](create.md#用户点名-pagegroup-时的创建顺序)。明确最终闭合三页先迁移保留内容/修导航和动作再删多页；仅增页不授权删旧，不删底表/字段。
- **源与承载同步**：用户改源 View/表/字段时，同步核 App 承载组件；只改 App 名称不要求改源对象。跨实体资格先核动态关系，不用静态 ID 集合或同名状态替代。
- **类型与 AI**：11 种标准图可 update --type 原位互转，保持原 ID；其它 type 与全部 sub_type 不可改，不删旧建新冒充换型。AI 先读 ai_config，仅改 spec 用 ECharts patch，不重配数据源；存量 VChart/缺 engine 直接 patch，由服务端转换。
- **新增入口和布局**：每个点名录入/处理对象都要有真实入口；只改展示/文案不自动开写。局部布局只调整授权目标，保留其它组件关系。顶部导航用 vertical，侧边用 horizontal，未点名不改。

同页串行写，每次立即 block-get；结果未知先回读再决定补写。组件、字段或日期不够时说明具体缺口，不换主体、口径、条件或新增替代组件求成功。

## 第 3 步：回读结果与保留项

| 本次变化 | 实际读取与核对 |
| --- | --- |
| 换型、配置、字段、筛选、指标、排序 | `+app-block-get` 核精确类型、完整配置与稳定 widget_id/chart_token；图表再用真实 chart_token 和源 Base get-data |
| 改名、文案、图标、样式 | 核实际保存值，保持 ID、原样式和引用；文案变长时核邻居位置 |
| 按钮、录入/详情开关 | 核真实 URL/Page/记录上下文和对应动作；保存成功不等于动作已运行 |
| 位置、尺寸、模式、容器 | 完整 structure 比较写前与写后，核父级、rect、顺序、同行及相对尺寸；无重叠不等于保留正确，整组平移可接受 |
| Page/PageGroup、导航 | 完整分页 page-tree-list 核名称、类型、父子、数量和顺序；闭合集合既不能缺页也不能多页，组另数 |
| 同 App 移动/复制 | 先递归核有无 View；单个 View 按公开配置重建，核新组件、完整公开配置与源未变，底层 View 隔离未实证；含 View 容器不直接复制。其它组件递归核来源/目标的子组件类型、来源、筛选、动作和矩形 |

## 第 4 步：交付

按 [末次验收](../../references/base-app/app-checks.md#末次写后) 核完整原话，最终必须给真实可点击App及必要页面/Form/入口链接，说明已改/保持/未完成/未验证；不猜链接或仅描述，不因副本名不好看改名，不以局部成功称全完成。

## 升级到完整搭建

页面集合整体重组、整体重设计、影响范围无法确认、需要新表/字段/Form/Workflow、全局主题变化、跨页移动复制或递归删除组时，先核影响范围，再按 [创建流程](create.md) 组织工作；已有 App 不因此默认另建 App。仅跨页同步授权筛选不升级。

## 拒绝类请求

| 请求 | 当前边界 |
| --- | --- |
| 复制/克隆 BaseApp 或 Page | 不支持；base-copy 只复制 Base，app-create 只建空 App，不造空壳冒充复制 |
| 从 Workspace 移出资源 | 用 workspace-entity-list 定位并说明不支持移出 |
| 非标准图换型或修改 sub_type | 只能在 UI 处理 |
| unsupported 组件 | 只能从列表识别，不调用 get/get-data/update |
| 跨 App 移动/复制组件 | 不支持；只允许同一 App |
| 直接复制 View 或后代含 View 的容器 | 不支持 block-copy；单个 View 仅按公开可写配置重建，无法表达的项明确缺口，不承诺整树无损重建 |

不以浏览器、OpenAPI、Drive 或其它域同名对象绕过这些能力限制。

## 移动、复制与删除

同页block-move；同App跨页普通无View子树用block-copy --target-page-id，明确搬走且授权删除才删源。单View读 [公开重建](../../references/base-app/component-view.md#复制单个-view按公开配置新建)，一次完整配置建目标、核新组件/配置/源未变；含View容器不copy/承诺递归重建。删前唯一核目标/范围，组级联先读子树再--cascade --yes，留≥1Page；App删除交 [Drive](../../references/base-app/app-commands.md#删除应用)。

## 恢复

读完整错误/查状态仅续失败项，保留父组/源/完整条件/图型/周期/指标/动作/相对布局；ACL记环境/权限阻塞。同因定向修正一次仍失败报缺口并继续独立工作，按 [恢复表](../../references/base-app/app-commands.md#常见恢复)。
