# 布局：先定骨架，再逐页落实

App 使用自己的 [页面布局 API](../../references/base-app/app-page-api.md#页面整体布局)，不套 Dashboard。Agent 确定区域、顺序、尺寸与模板，公开命令交 Builder SDK 执行碰撞处理，不手算避让。

定位：[首页 T 型](#首页-t-型必须落实) · [布局决策](#布局决策) · [补洞约束](#画布会向上补洞不能用空位占行) · [正向示例](#消除留白的正向示例) · [回读](#写后回读)。

## 首页 T 型必须落实

完整新建默认首页执行，用户明确冲突布局/精确组件集合优先。先取得真实首页ID并完成首页，再继续其它页；默认堆叠、空首页或用分析页抵扣均不算完成。

| 区域 | 骨架与内容 |
| --- | --- |
| 顶部 | 根text独占 `x=0,y=0,w=48,h=3`，width=fixed、height=auto；H1、26px粗体与副文案按text协议，业务区在标题下 |
| 左栏 | `x=0,w=32`：真实入口→≥3不同statistics→主list/view（满栏且面积最大）；三项同行11+10+11 |
| 右栏 | 每项 `x=32,w=16`，≥3个progress/countdown/nps及图表；指标、图表各≥1，全部指标在图表前 |
| 控制 | 切片器在全部同源数据前，插控制行同时后移左右数据区；无按钮则上移后续区域 |
| 对齐 | 每行含尾行连续铺满所属栏、同组等高，左右底边对齐；先调主列表，再在原子范围内调右栏高度，不用空行撑高 |

按 [T 型 exact 示例](create.md#t-型首页写法) 一次提交全页，真实根ID各一次，Tabs/组合容器算一个根，内部另配。图表不设高fill。原生1494/520等像素不能写回48栅格。

完整structure核位置、栏界、满宽、顺序、主列表大小、底边及同父重叠；缺项先修复回读。真实字段/目标不足列具体缺口，不编日期、目标值、重复图或空容器，未补齐不得称完整T型已验证。

### T 型自检（交付前必跑）

读实际根坐标；原生像素只比较比例：

```bash
lark-cli base +app-page-get --app-token <app> --page-id <home> --as user \
  --jq '.data.page.widgets[] | {name, parent, x:.layout_config.position.x, y:.layout_config.position.y, w:.layout_config.position.w, h:.layout_config.position.h, size_mode:.layout_config.size_mode}'
```

按parent分组，取含y=0且组件最多的一组为根集，`W=max(x+w)`；左栏取x=0，右栏取x≥0.6W。用户覆盖项按原话，其余默认项须PASS：

| 项 | PASS | 修复 |
| --- | --- | --- |
| 通栏标题 | text的x=0,y=0,w≥0.95W，width=fixed、height=auto | 写48栅格通栏及模式 |
| 左栏 | 有x=0,w≥0.6W根组件，下接主列表；各行含尾行满栏、无跨组串行 | 收回x=0,w=32，按实际数量重分宽，或授权内补真实组件 |
| 右栏 | ≥3根组件x≥0.6W，逐项满栏且顺序正确 | x=32,w=16，不足补真实内容 |
| 底边 | 两栏max(y+h)相等；受原子高度限制时差≤最小根组件高度 | 先调主列表，再调右栏高 |

四项PASS才能继续下一页/交付，FAIL先修复重跑，答复说明不代替修复。

## 写前确定布局骨架

按页面职责确定区域、阅读顺序、主次、列宽与模式；用户位置/同行/左右要求落实到坐标，创建后绑定真实ID。首页按上方T型执行。

## 画布会向上补洞，不能用空位占行

坐标是输入，不锁定最终位置：下方能放入上方空隙的组件会向上压紧，较大y或输入无重叠不保证下一行。此规则适用全部页面，T型分别按32/16栏宽。

- 每行（含尾行、单项）连续铺满所属区域，下一行紧接底边，不留半行/空列/空行，不靠增大y隔组。32列三项11+10+11、两项16+16、单项32；16/48列同理，尾行不沿用前行单项宽。
- 空位可用回答不同真实业务问题的组件补充，或重分现有宽度/行数；明确集合、局部修改不加项。width=fill不能代替真实x/w或阻止重排。
- 不造空文本/容器、重复按钮、虚构指标占位。用户锁定留白/窄宽时保留要求，说明自动压紧限制并核实际效果；局部只调授权目标。

写后独立读最新structure，能访问真实页时刷新核重排：满行、无上挤串行，原分组/上下/左右关系仍成立。失败先修复；仅坐标请求/structure不证明浏览器最终排版。

## 组件就绪后落实排版

用一次 `+app-page-update --layout-config` 绑定根ID位置/尺寸；创建顺序、默认堆叠、只设text auto都不代替整页布局。回读正确后继续下一页。

- 根直接组件各一次，Tabs/组合容器内部另配；局部用exact+keep或modify_layout，保留未点名关系。App顶部/侧边导航不属Page根布局。
- 48栅格整数：x,y≥0，w,h≥1，x+w≤48；原生像素不原样写回。
- 有行列/并排/上下/整行/坐标或切片器作用关系必须显式布局，最终回读核用户位置要求；内容、尺寸、模式改变后检查受影响邻居。
- 增量首写前记根ID、rect、顺序、同行、相对尺寸；未授权关系保持，整组平移可接受。

## 布局决策

- 用户合法尺寸/关系优先；同行取最终有效最大高度，取值顺序：显式→既有rect→原子默认。共同固定高无法展示长内容时不与异类同行。
- 默认顺序：文本/图片→按钮/切片器→指标/进度/倒计时/NPS→图表→list/view/pivot；页面说明先通栏再分列，切片器y小于全部同源组件。
- 根list/view/pivot宽fill；仅单一候选或其余只有按钮/切片器才高fill，有图表/指标/文本/图片/容器则高fixed。图表不高fill。
- 分析/看板/报表页默认≥3不同问题的非指标图，用户排除/真实不足优先，不复制口径。
- 首页按真实目标生成入口，非首页仅明确/流程必需才建；可选按钮组≥3，不足不生成，首页/明确/必需的1～2个全做。
- 首页核心汇总或非首页明确统计才加≥3不同指标；明细/录入页不默认加，非首页不重复无新增用途的首页指标。有列表/图表且字段提供维度才加≥3真实维度切片器，用户指定更少照做。
- 同型成组、同行同高，内部布局/对齐一致；异型遵守各自规则，不异常拉伸。
- 按钮等宽等高；指标每行≤5、多行数量差≤1；切片器每行≤4；图表每行≤3、同高，主次可1/2+1/2、2/3+1/3、1/2+1/4+1/4。全部含尾行按实际数量铺满所属48/32/16列，不能把右栏拉至48。明确集合不补项；锁定尺寸/位置无法消空时说明限制。
- 普通组件用block-update的layout-config.size_mode，如 `{"size_mode":{"width":"fixed","height":"fixed"}}`；默认按 [组件协议](../../references/base-app/app-component-selection.md)，不统一套示例。不用AI外层size-mode；通栏标题fixed宽，fill会参与剩余宽分配。

## 消除留白的正向示例

先按原话、页面职责与真实内容选择：

| 情况 | 处理 |
| --- | --- |
| 已授权补内容、集合开放且有未承载的真实问题 | 补不同指标/入口/分析维度，继承固定范围及切片器，不扩大业务/权限 |
| 内容足够、明确集合、仅授权排版或缺真实口径 | 重分现有宽度/行数/分栏，单项满所属区域 |
| 固定高列表内部空白、真实空结果、组件报错 | 分别核内容高度/业务结果/[取数恢复](../../references/base-app/app-commands.md#常见恢复)，不多建组件掩盖 |

### 有真实待办口径时补一张有用的指标卡

开放的意向线索页已需统计，两张16列卡为“意向线索数”“高预算线索数”，余16列。确认一行一线索、状态有“待跟进”后可补新问题“待跟进线索数”：

```json
{"base_token":"<真实Base>","data_sources":[{"table_name":"品牌合作意向","count_all":true,"filter":{"conjunction":"and","conditions":[{"field_name":"处理状态","operator":"is","value":["待跟进"]}]}}]}
```

示例原范围为全表；已有本人/时间等条件须完整保留并AND待跟进，核schema等价性。三卡16+16+16同高，原高预算阈值不变，0照实。缺依据就两卡24+24；流程已有真实Form时按 [按钮协议](../../references/base-app/component-button.md) 补可点击入口，URL文字不证明动作。图表同理：缺真实状态分布可补，已足够的两图24+24，不复制第三图。

### 明确两个组件或一个入口时扩宽现有内容

只要“今日成交额卡+客服处理量排行”就两项各48列；“进度条+甘特”各占连续整行，不加第三项/T型默认。“新增订阅”单按钮满本按钮行，不造其它入口；分栏只填所属栏。锁定尺寸/位置和局部边界优先。

### 三个图保留两行，尾图独占本行

普通分析页仅A/B/C，A/B在C上方，允许改宽且非新首页/未锁16列。替换真实根ID：

```json
{"exact":[{"name":"A","x":0,"y":0,"w":24,"h":16},{"name":"B","x":24,"y":0,"w":24,"h":16},{"name":"C","x":0,"y":16,"w":48,"h":16}],"on_missing":"strict"}
```

传page-update的layout-config，固定宽高，24+24及尾行48。还有未授权根时改局部更新，不用strict覆盖；不补第四图，C不留16列，不高fill。

### 指标、图表、列表各占自己的连续行

普通页已授权排版，仅指标A/B/C、图D/E、列表F，既有高6/16/20；按页面API提交：

```json
{"rows":[[{"name":"A","w":16,"h":6},{"name":"B","w":16,"h":6},{"name":"C","w":16,"h":6}],[{"name":"D","w":24,"h":16},{"name":"E","w":24,"h":16}],[{"name":"F","w":48,"h":20}]],"source_query":"指标A/B/C同行，图D/E同行，列表F独占下一行；按此顺序铺满每行"}
```

source_query是Agent对授权布局的描述，不冒充原话。同行同高，列表宽fill/高fixed；逐组满行避免上挤，不用大y/空容器隔组。真实间隔仅用公开且已验证能力，关系不能证明则列缺口。

### T型只填所属栏，低数据量不靠空列表撑屏

骨架例：标题y0高3；左32列按钮y3高3、指标y6高6、列表y12高27；右16列进度y3高8、两图各14，底边均39。左三项11+10+11，右逐项16。标题auto变高/内容变化后重核底边和邻居，规划坐标不是渲染结果。

三条记录的明细页不为铺屏额外建图/拉长空列表；单列表按高fill规则，混合页选可读固定高。侧边空洞、内部空白、真实0/空结果分开判断，不造数据。

## 写后回读

完整structure逐页核组件数量/依据、顺序、分组类型/数量、最终x/w/h、满行/等高/对齐、list/view/pivot模式、父级、同父无相交且不越界；增量另比较稳定ID、rect、同行/相对关系。顺序错误、空列、尾行空洞、重复凑数、模式错误逐项修复回读，只修授权对象，不以写响应证明。

主题/图标见 [主题](../../references/base-app/app-theme.md)、[图标](../../references/base-app/app-icons.md)，标题样式见 [text](../../references/base-app/component-text.md)。structure只证明结构，首屏/裁切/像素效果另需真实页证据。
