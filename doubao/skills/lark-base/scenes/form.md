# 表单

## 开工必读

- 区间单选的选项互不重叠、无缺口。每个值只落在一个选项里，如“少于 3、3 至不足 5、5 及以上”，不用在 3 上重叠的“3 以内、3 至 5”。
- 复用表里已有的字段做题目。同名或同义字段存在时用 `use_existing_field` 加 `field_id`，不另建“字段 2”。关联字段不能直接做题目，提交后的关联按 [输入与业务关联](#输入与业务关联) 处理。
- 电话、邮箱保持对应样式。不为加题改成普通文本。
- 必须提供的材料设必填。写进说明不算。
- 截止时间、人数上限、每人提交次数用 `+form-submission-settings-update` 配置，写在标题或说明里不生效。要求提交后通知谁，用 `+form-notifications-update` 开启。
- 移题用 `+form-questions-delete --keep-field`。默认连字段、数据一起删，使引用视图、组件、工作流失效；仅要求删字段时省略 `--keep-field`。
- “其他”放最后。建字段选项时即排好。
- 原话要填写的关联对象补单选题。关联字段不能做题目时，加一道单选题，选项取主档记录名称，提交后按 [输入与业务关联](#输入与业务关联) 建立关联。
- 要他人填写就开分享。`+form-share-get` 回读 `enabled=true` 且有链接才算交付入口。
- 命令写法照抄。建表单、题目、分享、设置的命令都必带 `--table-id`，分享和题目命令再带 `--form-id`。`+form-share-update` 每条只能带一个设置项，写法见 [分享设置示例](../references/form-share.md#分享设置示例)。改题目属性用 `+form-questions-update`，参数见 [题目操作协议](../references/form-questions.md#更新题目form-questions-update)。公式、查找、自动编号字段不能做题目。

## 任务导航

创建完整表单时组合执行底表、题目、配置和入口流程；修改单项只处理该项及受影响的依赖；关联主档、必填与输入范围、运行设置、分享入口、填写提交各按同名章节执行。新底表样例和测试提交按 [新底表样例与真实提交验收](#新底表样例与真实提交验收) 判断。

## 前置检查

### 管理路径

- 按 [Base 定位](base.md#定位已有-base) 取、复用真实 `base_token`、`table_id`、已有 `form_id`；仅表 ID 缺失／归属不明时 `+table-list`。
- 题目前读 `+form-questions-list` 完整配置；复用字段读 `+field-list` 核 ID、类型；移题前存字段、代表值。排序前读 `+view-get-visible-fields`；题目列表核成员／属性，可见列表核顺序。
- 改展示、提交、通知、结果页、抽奖、分享前，先读对应 Get，保留其他配置和版本号；建查询页前先读关联状态。
- 确认底表是本轮新建还是用户既有表，以及是否明确要求空表、数量 0 或指定记录数；这些条件决定样例和测试提交是否适用。

### 填写路径

按 [分享标识协议](../references/form-fill.md#提取分享标识share_token) 从真实链接定位，`+form-detail` 取题。只用当前身份，不取管理权限，不虚构答案。

### 授权与数据保护

- 用户明确要求且目标、范围清楚的写操作直接执行；只读请求不授权写入。对象或删除范围有歧义、会改变用户未要求的访问范围或要求互相冲突时，先澄清具体冲突。
- 移除题目前先按 [底层字段保护](#移除题目与底层字段保护) 明确保留对象；不得为对齐题目删除用户既有字段或记录。
- 分享范围按 [分享范围](#分享范围) 确定；抽奖条款须单独取得用户明确同意。

## 表单决策

外部／多人填报及信息收集默认建表 + 表单。字段即题目，每次有效提交生成一条记录。

### 底表准备与创建前判断

#### 专用收集表与业务表

仅当“本轮要为这张新表建表单”和“这张表只承接表单提交”同时成立时，才适用 [Base 初始 schema 规则](base.md#操作约束) 的例外。本轮不建表单、表同时是台账或业务主表、表单只是既有业务表的附带录入口，都不适用。

| 条件 | 初始字段 |
|---|---|
| 同时成立 | 自动编号（序号，主字段）+ 创建时间（提交时间）；创建人按身份规则；作答字段留给题目创建 |
| 任一不成立 | 按 schema 建要求的业务字段，不交付仅有系统字段的空表 |

两种情况都按 [Table 创建协议](../references/table-commands.md#创建时的初始字段) 显式指定初始字段，避免默认占位；身份规则优先，不固定加提交人。

#### 表单题目来源与底表保护

创建前先读 [初始题目生成规则](../references/form-commands.md#创建语义与初始题目)，按收集项准备底表。既有表保留结构；创建后核／补题，多余题按字段保护移出。

#### 提交时间与填写人身份

提交时间用系统创建时间承接，不建手填日期题。填写人身份只按用户列出的收集项处理；本节只决定新增的字段和题目，不删除已有字段。系统字段承接的项单独验收，不再要求手填题。

| 用户要求 | 处理 |
|---|---|
| 未点名填写人 | 不因留痕加身份题／创建人；匿名不额外收集 |
| 点名记录填写人（如“记录谁提交的”“预约人”“登记人”“收集提交人姓名”），且未要求免登录或匿名 | 用系统创建人，采用登录、记名提交；不建手填身份题 |
| 点名且免登录 | 自填一道题，说明身份自填、不可信；未列身份项则不适用 |
| 匿名且可识别填写人 | 先澄清；不取消匿名，不以访客身份冒充真人 |

身份方案须与分享范围的登录、匿名目标一致；系统字段在不同提交身份下的表现见 [填写人身份协议](../references/form-share.md#登录匿名与系统创建人)。

### 共同约束与收集项核对

- 未要求改名／编号时标题原样，不因排序／美化加序号、必填标记、括号、前后缀。
- 表内已有字段不代表表单已收集。把每个收集项映射到题目或系统字段，标明由填写人输入、系统派生还是管理人员维护；需要作答的每项都要有题。新建表单不把状态、审核结果等管理字段开放给填写人。稳定收集项分字段承载，备注留作自由说明。
- 新底表手填题集合 = 作答项。既有表原题不影响命中则保留；要求移出时保护字段。
- 人数、件数、名次、完整年数等离散量用整数；测量值、比例等连续量按用户要求或业务精度。按 [数字字段协议](../references/field-config.md#number-字段) 显式设精度，不依赖默认值。

| 当前情况 | 动作 |
|---|---|
| 已是可见题 | 复用；属性变化用 `+form-questions-update` |
| 是成员但隐藏 | 恢复可见，不重复创建 |
| 同标题题存在且未要求独立同名题 | 更新已有题，不先建后删；无法定位则澄清 |
| 字段存在但不是成员 | 核真实类型，以已有字段形态加入 |
| 不存在，或明确要独立同名题 | 创建新字段题 |

区间单选在生成和保存后都核对每个分界点及两侧取值；该规则不扩展到多选题或公式分支。用户给定的选项相互冲突时，指出具体边界并澄清，不静默修改。自主设计选项时“其他”放最后，“暂未使用”等状态项放在它前面；用户指定顺序时按用户要求。

### 输入与业务关联

文本／单选主档名只是输入，不是记录 ID 的 Link，不能据此称 Formula / Lookup 生效。题目创建、详情读取和提交值分别核对 [各自能力边界](../references/form-fill.md#普通字段值fields)；不建不支持的 Link 题。

自动接入主档交 [Workflow](workflow.md)，仅本次关联交 [Record](record.md)；普通表单不自动加流程：

1. 用提交记录、稳定业务键定位并核唯一；可能重名不取首条，不虚构键。
2. 结果分 0／1／多条：仅 1 条写关联；0／多条待匹配并说明，不新建或任选首条；赋值按 [关联字段赋值](../references/workflow-values.md#关联字段赋值)。
3. 只回写本次提交记录；重复处理保持同一关联，不重复追加；已有不同关联先核冲突，不盲覆。仅需求包含时配置业务键变更后的重匹配。
4. 回读 Link、适用反向关系、Formula / Lookup；至少核唯一／零／多命中，必要时核重复处理。手工样例不证明自动执行。

题型／环境不能回写时保留可完成的收集，报“自动关联/派生计算未验证或受阻”；不以名称文本、URL、手工关联冒充自动链路。

### 必填、条件显示与输入范围

- 必须材料由必填题承接；无表单先建。条件必填指条件满足时出现且必答，不因“有时不填”设选填。
- 字数／数值／日期范围落实为入口约束；必填、描述、默认值、提醒 Workflow、提交后人工核对均不能代替范围拦截。
- 单侧边界只限该侧。固定日期用绝对日期；“从今天起、未来 N 天、本周内”随运行日滚动，不固化为执行日。
- 选择题区分字段完整选项与本入口可填集合。专用字段只定义允许值；复用共享字段时按 [已有字段题目协议](../references/form-questions.md#形态-b已有字段题目) 判断能否收窄，不删其他用途所需选项。
- 显隐、默认值、描述不等于选项约束；无法表达时报告未完成，不静默更换用户指定的字段。

### 题序目标与依赖

题目集合、题序分别确定和验收。来源有分节、编号／顺序时照用；否则基础信息在前、业务题在后，不为排序加身份题；选填的备注、说明、意见类题放最后；成对的开始与结束按先开始后结束；审批意见、处理结果等管理字段不放进填写表单。顺序须满足 [显隐条件的前序依赖](../references/form-questions.md#显隐条件visible_rule)，冲突先处理再排序。

### 展示与运行目标

| 用户要求 | 配置目标 |
|---|---|
| 一页一题／传统表单 | 填写页分页；其他外观先核展示能力边界 |
| 名额／总量、个人次数、截止／起止时间 | 提交总量、个人次数、有效期；不用字段、名称、描述代替 |
| 提交后／定时通知 | 通知配置及接收人、时间 |
| 结果页／跳转 | 提交后动作；只改标题时保留原描述 |
| 抽奖 | 抽奖配置；先取得条款同意 |

### 分享范围

| 维度 | 判定 |
|---|---|
| 开关 | 要填写链接／扫码时开启；仅创建、读设置、索二维码图片不授权开启 |
| 填写人 | 选仅邀请对象、组织内成员、持链接的任何人；仅组织外不特定对象才用最后一项 |
| 登录 | 单独决定；外部填写不等于免登录 |
| 匿名 | 单独决定；免登录不等于匿名，匿名不等于关闭登录 |

组织内填写／收集个人敏感信息时沿用组织内访问和登录；指定邀请对象时保持更窄范围。与外部／免登录冲突先澄清，不自动放开或改写。只改授权目标必需项，其余保留；登录、匿名须符合身份方案。

## 执行与提交

单项只改目标及依赖；复用对象、有效读取。连续修改按用户顺序逐步验收。同一请求含创建后查／改／删时执行 [阶段验收](build-system.md#连续操作的阶段验收)，创建通过再继续；单独任务也适用。

### 表单读取与维护

- 只读用 `+form-list`／`+form-get`；仅有分享链接则走填写路径。
- 先备底表，再 `+form-create`；存真实 ID，立即 `+form-questions-list`，复用／补／移题，再配题序、运行设置、入口。
- 改标题／描述前读当前值，只改目标；题目文本走题目命令，分页走展示配置。
- 删表单前确认目标、保留对象；写后核表单已删且底表、字段、记录保留。后续删除不替代创建阶段的数据、提交验收。

### 题目管理

先完成收集项和属性决策；涉及提交时间或填写人时同样执行身份规则。

| 操作 | 执行 |
|---|---|
| 创建／复用 | 据前置结果确定建、复用、更新；隐藏成员走可见集合。按 [创建请求与支持类型](../references/form-questions.md#创建请求与支持类型) 执行，存对象 ID 并回读；局部失败走恢复 |
| 更新 | 用有效完整配置，仅改目标；按 [全量覆盖协议](../references/form-questions.md#全量覆盖与回读) 构造 `+form-questions-update`，核目标和保留项；误改标题则恢复 |

#### 移除题目与底层字段保护

| 意图 | 边界 |
|---|---|
| 删／移题 | 仅移出表单，保留字段、数据 |
| 仅隐藏，保留成员关系 | 改可见列表 |
| 明确删字段、整列、已有数据 | 才同时删除字段和数据 |
| “删掉”指代不明 | 先澄清，不取更破坏的解释 |

以保存的字段、代表值为基线，按 [删除题目协议](../references/form-questions.md#删除题目form-questions-delete) 执行并验收。重新显示时区分已移出题、仍是成员的隐藏题。

#### 调整题目顺序

题目集合定稿、创建和移除完成后，`+form-questions-update` 不改题序；按[题序目标](#题序目标与依赖)把全部题目字段排好，用 `+view-set-visible-fields --view-id <form_id> --json '{"visible_fields":[...]}'` 整体提交一次，见 [可见题目与排序协议](../references/form-questions.md#可见题目与排序)。只排序不改成员；隐藏／恢复才改成员。写后 `+view-get-visible-fields` 核成员、顺序、显隐依赖；协议例外据实报告，未回读不标 `verified`。

### 展示与运行配置

按表单配置协议写目标；用有效基线，仅缺失、失效、并发时补读，写后验收。分页后以 `+form-display-settings-get` 核模式；请求取值、版本按展示协议。

#### 填写有效期与抽奖

- 开有效期前确认 Base 时区；未设置时先按目标时区 [设置 Base 时区](base.md#更新-base-时区)，不擅自用其他时区。取值见 [提交设置协议](../references/form-settings.md#提交设置form-submission-settings-get--form-submission-settings-update)。
- 开抽奖前，用户须阅读并明确同意 [《飞书问卷抽奖管理规范》](https://www.feishu.cn/hc/zh-CN/articles/047445276639-%E9%A3%9E%E4%B9%A6%E9%97%AE%E5%8D%B7%E6%8A%BD%E5%A5%96%E7%AE%A1%E7%90%86%E8%A7%84%E8%8C%83)，再按 [抽奖协议](../references/form-settings.md#抽奖配置form-lottery-get--form-lottery-action) 开启；创建授权不代替同意。

### 分享范围与可用填写入口

仅查询时读、报分享设置；修改时复用有效状态，只交差异，最后 `+form-share-get` 验收。

| 入口 | 执行 |
|---|---|
| 链接／扫码／他人／在线提交 | 题目完成后配置并验收分享。交真实链接，不以“前端获取”代替；分报配置已保存、真实提交已实测 |
| 二维码 | 按分享决策核前置，再按 [二维码协议](../references/form-share.md#分享二维码form-share-qrcode-get--form-share-qrcode-download) 取图。未开分享且仅索图、未授权开启时说明前置，由用户决定。仅要链接不下载；要图须展示／附加，不只报路径；失败走恢复 |
| 提交后查询页 | 仅要求查已提交内容时配置；改题／分享／布局不创建。已有复用，没有则按 [首次创建协议](../references/form-share.md#查询页首次创建与关联恢复) 执行并回读；失败恢复且不重复创建。要求修改提交时另配、验权限；查询页不代表可修改 |

### 表单样例准备

- 需样例时按 Mock 数量，先 `+form-questions-list` 核题型、必填，再生成与真实填写同形的数据；建表单不重置来源、数量要求。
- Mock 满足必填、选项、附件、显隐；内部管理字段不作外部填写题。
- 附件题仅有用户文件／fixture 时提交；缺附件不跳过其他 Mock。附件按 [附件协议](../references/form-fill.md#附件上传attachments)，底表仍按 [Mock 回读](mock-data.md#回读验收)。

### 填写与提交

1. 复用有效详情；配置变化后重跑 `+form-detail`。
2. 按 [填写协议](../references/form-fill.md) 备真实答案、附件，核必填、显隐；测试数据先满足新底表条件。
3. 目标、范围清楚且授权后执行 `+form-submit` 并验收；结果未知则恢复。

## 回读验收

配置正确不等于真实提交。创建／分享读 `+form-get`、`+form-questions-list`；题序、分享、设置加专用证据。题目描述读题目列表，表单描述读列表／详情，文字、换行须一致。

### 按操作回读与验收

| 目标 | 证据；通过条件 |
|---|---|
| 表单列／读／改 | `+form-list`／`+form-get`；归属、名称、描述正确，报读取范围 |
| 新底表、表单 | `+field-list`、`+form-get`、题目列表；结构合规，系统承接项单核，其余对应作答项；原话的每个收集项和要登记的关联对象（如食材、客户、房源）都有题 |
| 既有表建表单 | `+form-get`、题目列表、底表；收集项命中，原题按决策留，不为对齐删字段／记录 |
| 建／复用／改题 | 题目列表；对象、题型、描述、必填、选项展示、显隐、范围正确，保留项未变 |
| 场景答案范围 | 题目、字段；有入口加 `+form-detail`；可填项合规，共享用途保留。不能证明约束则报未完成；实提受授权、数据目标约束 |
| 区间单选 | 最终 `staticOptions`；端点、两侧每值恰中一项；非负范围核 0、3、5 及相邻值，不只数三项 |
| 题型／样式／精度 | 题目 + `+field-list`／`+field-get`；三者正确，离散数不回落默认小数精度 |
| 标题保护 | 更新前后配置；同题标题原样，否则恢复 |
| 可见集／题序 | `+view-get-visible-fields` + 显隐；成员、顺序、依赖正确，例外据实报告 |
| 移题保字段 | 题目列表、`+field-list`；有数据加 `+record-list --field-id <field_id>`；题移、字段在、代表值不变，缺一即未完成 |
| 删除表单 | 表单列表、字段、记录；表单不存在，保留对象在，数据量合规 |
| 填写页 | `+form-display-settings-get`；分页正确，留作最新基线 |
| 数量／个人次数／有效期／允许修改 | `+form-submission-settings-get`；启停、次数、时间、时区正确，其他项保留 |
| 提交后／定时通知 | `+form-notifications-get`；启停、接收人、时间、周期正确，其他项保留 |
| 结果页／跳转 | `+form-submit-actions-get`；标题、描述、地址、启停正确，原描述保留 |
| 抽奖 | `+form-lottery-get`；状态、奖品正确，既有奖品保留，条款已同意 |
| 分享／链接 | `+form-share-get`；开关、范围、登录、匿名正确；需入口时开启并返回真实链接 |
| 二维码 | 分享回读 + 返回／下载校验；分享合规，图片已展示／附加，不只报路径 |
| 查询页 | `+form-query-page-get`；要求改提交时加提交设置；关联对象正确，修改权限另成立 |
| 真实填写 | `+form-submit` + 当前身份所得记录／查询；按 [返回语义](../references/form-fill.md#提交返回结构) 确认已被接受。未回读记录则说明范围，不换管理身份或重提 |
| 关联、派生 | 提交记录、主档、Link、Formula / Lookup；自动化加 Workflow 证据。唯一命中正确，0／多未误连，派生生效；分报配置、手工写表、自动执行 |

### 新底表样例与真实提交验收

底表仍适用 [Mock 数量](mock-data.md#数据来源与数量)、[全量验收](mock-data.md#回读验收)；先备样例。适用条件全通过才标创建 `verified`：

- 新底表 + 可填写表单且非空表／数量 0 时，只建 Form、返链接或交空主表不算完成；按指定或默认数量验收，后续要删表单也不例外。
- 空表／数量 0 不写测试记录，保持空并报提交未实测。既有表禁止测试写入；未实测如实报告。
- 仅“新建底表、允许样例／测试写入、非空、目标量 > 0、工具链支持提交”全成立时，创建阶段立即经真实入口执行 `+form-detail → +form-submit`，写入、回读至少 **1 条**并计入总数；其余按需批量写入，补齐指定或默认总量。保留来源时不额外提交虚构记录。
- 提交后 `+record-list` 回读总量、真实提交值，其余样例全核。分享／提交不可用仍回读数量、数据，报“表单提交链路未验证”；写表不代提交，不为测试扩大分享、取消匿名、改登录。

## 异常恢复

与 [通用恢复](../SKILL.md#异常恢复与停止条件) 同时适用。保留已完成对象和证据；解析／局部失败不重放整批。分享失败按目标修复、回读，不放宽范围。

| 情况 | 恢复 |
|---|---|
| 题目创建未知／部分成功 | 读字段、题目，识别已完成项 |
| 提交超时 | 查可得记录／查询状态；仍未知则报告，不自动重提 |
| 标题误变 | 用原题 ID、原标题恢复；全量覆盖时保留其他目标配置并回读。缺原值先核实、不猜，不当优化交付 |
| 二维码失败 | 按 [恢复协议](../references/form-share.md#二维码校验与落盘恢复)；开启仍受原授权，成功后展示／附图 |
| 查询页失败 | 保留对象，按 [未知恢复](../references/form-share.md#查询页部分成功与未知状态恢复)；未知则报事实，由用户决定，不删除重建／重复创建 |
| 展示配置错误 | 按 [重试协议](../references/form-settings.md#展示配置错误与重试)；并发时核原目标，不覆盖他人改动；恢复后验收 |

### 样式拒绝后的恢复

仅协议确认样式拒绝时按 [恢复协议](../references/form-questions.md#样式拒绝后的恢复) 定向恢复一次，仍满足原精度、收集项，不缺项。已有字段先确认授权；电话、邮箱、网址、条码承载语义，未经同意不改普通文本，保留并报平台限制。
降为普通文本须说明失去格式校验，不报完全实现。
