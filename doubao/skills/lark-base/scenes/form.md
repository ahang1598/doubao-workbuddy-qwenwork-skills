# 表单

## 开工必读

- **先定逐题目标，再设计底表字段、创建或改题。** 按 [收集项核对](#共同约束与收集项核对) 确定收集项、提供方和承接位置，分别确定必填／选填（[规则](#必填条件显示与输入范围)：原话点名要填写人提供的字段默认必填）、条件显示及目标题序；创建、修改与报错恢复沿用同一目标。
- **创建后的配置流程（每份表单都做，做完这一份再建别的视图或模块）：** 复用 `+form-create` 返回；全量更新题目前用 `+form-questions-list` 取完整题目基线，全量排序前用 `+view-get-visible-fields` 取完整顺序基线；再补齐题目、设置必填／显隐，并按 [题序目标](#题序目标与依赖) 一次提交全部题目的 [实际题序](#调整题目顺序)，最后完成用户要求的 [提交等设置](#展示与运行配置)和分享。属性与题序的写入次序服从 [显隐依赖](../references/form-questions.md#显隐条件visible_rule)，之后改题须带回要保留的 `visible_rule`。
- 区间单选的选项互不重叠、无缺口。每个值只落在一个选项里，如“少于 3、3 至不足 5、5 及以上”，不用在 3 上重叠的“3 以内、3 至 5”。
- 复用表里已有的字段做题目。同名或同义字段存在时用 `+form-questions-create` 的 `use_existing_field` 加 `field_id`，不另建“字段 2”；`+form-questions-update` 只改已在表单里的题，不能加题。样式被拒按 [样式拒绝恢复](../references/form-questions.md#样式拒绝后的恢复) 定向处理，不静默丢题；复用的已有字段保留原 ID、类型、样式、单位和精度，不自动改成普通字段，也不新建同义字段绕过（改已有字段样式先经用户同意）。关联字段不能直接做题目，提交后的关联按 [输入与业务关联](#输入与业务关联) 处理。
- 电话、手机、邮箱默认用普通文本，金额、进度默认用普通数字；只有用户明确要求专用样式时才进入对应能力。链接、签字仍按对应题型；已有专用字段不自动改型，见[样式拒绝后的恢复](#样式拒绝后的恢复)。
- 公式、查找引用题只读。不设必填、不被显示条件引用、提交时不传值；引用的字段须已存在，同批新建的题要分两次创建。
- 「自动带出」「自动跟过来」的值做成题目。用户说填某几项后其他值“自动带出”“自动跟过来”“填一下就行”，指按所填内容从其他表查出或算出的结果（如按手机号显示历史消费）：用查找引用题按本问卷的填写值匹配其他表取回，还需计算再用公式题，一并放进问卷；不声称表单做不到，也不把这类题移出问卷改为后台计算。这类带出不做成关联字段加公式链式取值（如 `[关联字段].[某列]`）——关联记录要人工挑选或后台维护，不会随填写自动匹配，达不到“自动带出”。
- 必须提供的材料设必填。写进说明不算。要求“每个人”“都得”签署的确认、免责类签名题必须必填；只对部分人群的签署（如“想办某业务的人签个名”）不强制必填。
- 截止时间、人数上限、每人提交次数用 `+form-submission-settings-update` 配置，写在标题或说明里不生效。要求提交后通知谁，用 `+form-notifications-update` 开启。
- 移题用 `+form-questions-delete --keep-field`。默认连字段、数据一起删，使引用视图、组件、工作流失效；仅要求删字段时省略 `--keep-field`。
- “其他”放最后。建字段选项时即排好。
- 原话要填写的关联对象补单选题。关联字段不能做题目时，加一道单选题，选项取主档记录名称，提交后按 [输入与业务关联](#输入与业务关联) 建立关联。
- 要他人填写就开分享。从更新响应取得分享状态和链接；响应未返回链接、结果未知或用户明确要求核验时再 `+form-share-get`。
- 命令写法照抄。建表单、题目、分享、设置的命令都必带 `--table-id`，分享和题目命令再带 `--form-id`。`+form-share-update` 每条只能带一个设置项，写法见 [分享设置示例](../references/form-share.md#分享设置示例)。改题目属性用 `+form-questions-update`，参数见 [题目操作协议](../references/form-questions.md#更新题目form-questions-update)；可用题型与限制以 [创建请求与支持类型](../references/form-questions.md#创建请求与支持类型) 为准。

## 任务导航

创建完整表单时组合执行底表、题目、配置和入口流程；修改单项只处理该项及受影响的依赖；关联主档、必填与输入范围、运行设置、分享入口、填写提交各按同名章节执行。新底表样例和提交按 [新底表样例与真实提交条件](#新底表样例与真实提交条件) 判断。

## 前置检查

### 管理路径

- 按 [Base 定位](base.md#定位已有-base) 取、复用真实 `base_token`、`table_id`、已有 `form_id`；仅表 ID 缺失／归属不明时 `+table-list`。
- 题目前读 `+form-questions-list` 完整配置；复用字段读 `+field-list` 核 ID、类型；移题前存字段、代表值。排序前读 `+view-get-visible-fields`；题目列表核成员／属性，可见列表核顺序。
- 改展示、提交、通知、结果页、抽奖、分享前，先读对应 Get，保留其他配置和版本号；建查询页前先读关联状态。
- 确认底表是本轮新建还是用户既有表，以及是否明确要求空表、数量 0 或指定记录数；这些条件决定样例和测试提交是否适用。

### 填写路径

按 [分享标识协议](../references/form-fill.md#提取分享标识share_token) 从真实链接定位，`+form-detail` 取题。只用当前身份，不取管理权限，不虚构答案。

### 授权与数据保护

- 用户明确要求且目标、范围清楚的写操作直接执行；只读请求不授权写入。对象或删除范围有歧义、会改变用户未要求的访问范围或要求互相冲突时，先澄清具体冲突。
- 移除题目前先按 [底层字段保护](#移除题目与底层字段保护) 明确保留对象；不得为对齐题目删除用户既有字段或记录。
- 分享范围按 [分享范围](#分享范围) 确定；抽奖条款须单独取得用户明确同意。

## 表单决策

外部／多人填报及信息收集默认建表 + 表单。字段即题目，每次有效提交生成一条记录。

### 底表准备与创建前判断

#### 专用收集表与业务表

仅当“本轮要为这张新表建表单”和“这张表只承接表单提交”同时成立时，才适用 [Base 初始 schema 规则](base.md#操作约束) 的例外。本轮不建表单、表同时是台账或业务主表、表单只是既有业务表的附带录入口，都不适用。

| 条件 | 初始字段 |
|---|---|
| 同时成立 | 自动编号（序号，主字段）+ 创建时间（提交时间）；创建人按身份规则；作答字段留给题目创建 |
| 任一不成立 | 按 schema 建要求的业务字段，不交付仅有系统字段的空表 |

两种情况都按 [Table 创建协议](../references/table-commands.md#创建时的初始字段) 显式指定初始字段，避免默认占位；身份规则优先，不固定加提交人。

#### 表单题目来源与底表保护

创建前先读 [初始题目生成规则](../references/form-commands.md#创建语义与初始题目)，按收集项准备底表。既有表保留结构；创建后按目标补题，多余题按字段保护移出。

#### 提交时间与填写人身份

提交时间用系统创建时间承接，不建手填日期题。填写人身份只按用户列出的收集项处理；本节只决定新增的字段和题目，不删除已有字段。系统字段承接的项单独列入完成条件，不再要求手填题。

| 用户要求 | 处理 |
|---|---|
| 未点名填写人 | 不因留痕加身份题／创建人；匿名不额外收集 |
| 点名记录填写人（如“记录谁提交的”“预约人”“登记人”“收集提交人姓名”），且未要求免登录或匿名 | 用 `created_by` 系统创建人，采用登录、记名提交；不建手填身份题 |
| 点名且免登录 | 自填一道题，说明身份自填、不可信；未列身份项则不适用 |
| 匿名且可识别填写人 | 先澄清；不取消匿名，不以访客身份冒充真人 |
| 底表有承载填写人身份的字段 | 区分“系统记录实际提交人”和“填写者提供一个人员值”：登录提交人用系统创建人承接，且系统创建人可使用业务名称；普通人员题只表示填写者选择的人员，不能当作实际提交人。后台写入须有可追溯来源；既有字段不删、不改类型，按实际来源说明 |

身份方案须与分享范围的登录、匿名目标一致；系统字段在不同提交身份下的表现见 [填写人身份协议](../references/form-share.md#登录匿名与系统创建人)。

### 共同约束与收集项核对

- 未要求改名／编号时标题原样，不因排序／美化加序号、必填标记、括号、前后缀。
- 表内已有字段不代表表单已收集。把每个收集项映射到题目或系统字段，标明由填写人输入、系统派生还是管理人员维护；需要作答的每项都要有可见可填题；由系统承接的项（如按[填写人身份](#提交时间与填写人身份)用系统创建人）要有实际配置（如登录记名提交），只凭字段名不算已采集。新建表单不把状态、审核结果等管理字段开放给填写人；用户明确要求收集的其他项不因推断为管理字段而移除。稳定收集项分字段承载，备注留作自由说明。
- 需收集的人员字段也按上述规则核对，隐藏题目前须确认已有可靠取值来源，样例有值不能证明新提交会自动填入。
- 新底表手填题集合 = 作答项。既有表原题不影响命中则保留；要求移出时保护字段。
#### 题型与样式映射

收集项按语义选题型，写法与错误码见 [题目协议](../references/form-questions.md#创建请求与支持类型)：

| 收集项语义 | 题型 | 不能做到时 |
|---|---|---|
| 电话、手机、联系电话 | 普通 `text`；明确要求电话样式时用 `text` + `style.type=phone` | 专用样式被拒时如实报告，不静默改型 |
| 链接、网址、主页 | `text` + `style.type=url` | 附加要求（字数限制、非法链接）做不到时保留超链接题型并说明 |
| 签字、签名确认 | `attachment` + `style.type=signature` | 被拒时如实报告，不退成普通附件 |
| 由其他题或其他表自动算出、查出的值 | `formula` / `lookup` 只读计算题 | 被拒时如实报告，不改成让填写人手填；查找引用的来源表不存在时先向用户确认，不自建来源表或编造数据 |
| 邮箱、条码 | 普通 `text` | 用户明确点名专用样式时才按题目协议处理；不支持则如实报告 |
| 金额、进度 | 普通 `number` | 用户明确点名专用样式时才按题目协议处理；已有专用字段见[样式拒绝后的恢复](#样式拒绝后的恢复) |

不得用 `+field-create` / `+field-update` 绕过表单接口：先建不支持的字段再加入表单，或建题后把底层字段改成不支持的样式，得到的仍是不支持的题型。

- 人数、件数、名次、完整年数等离散量用整数；测量值、比例等连续量按用户要求或业务精度。按 [数字字段协议](../references/field-config.md#number-字段) 显式设精度，不依赖默认值。

| 当前情况 | 动作 |
|---|---|
| 已是可见题 | 复用；属性变化用 `+form-questions-update` |
| 是成员但隐藏 | 恢复可见，不重复创建 |
| 同标题题存在且未要求独立同名题 | 更新已有题，不先建后删；无法定位则澄清 |
| 字段存在但不是成员 | 核真实类型，以已有字段形态加入 |
| 不存在，或明确要独立同名题 | 创建新字段题 |

新建表单可见题目按本入口需作答的收集项确定；系统派生、后台维护且用户没要求在表单里展示的字段从表单隐藏，底表字段与数据保留。原话要求“自动带出”的值按[开工必读](#开工必读)做成查找引用／公式题，保留在问卷中，不隐藏。用户要求展示的参考信息保留；修改已有表单只处理本次目标及受影响项。

区间单选在生成选项时核对每个分界点及两侧取值；该规则不扩展到多选题或公式分支。用户给定的选项相互冲突时，指出具体边界并澄清，不静默修改。自主设计选项时“其他”放最后，“暂未使用”等状态项放在它前面；用户指定顺序时按用户要求。

### 输入与业务关联

文本／单选主档名只是输入，不是记录 ID 的 Link，不能据此称 Formula / Lookup 生效。题目创建、详情读取和提交值分别核对 [各自能力边界](../references/form-fill.md#普通字段值fields)；不建不支持的 Link 题。

自动接入主档交 [Workflow](workflow.md)，仅本次关联交 [Record](record.md)；普通表单不自动加流程：

1. 用提交记录、稳定业务键定位并核唯一；可能重名不取首条，不虚构键。
2. 结果分 0／1／多条：仅 1 条写关联；0／多条待匹配并说明，不新建或任选首条；赋值按 [关联字段赋值](../references/workflow-values.md#关联字段赋值)。
3. 只回写本次提交记录；重复处理保持同一关联，不重复追加；已有不同关联先核冲突，不盲覆。仅需求包含时配置业务键变更后的重匹配。
4. 后续步骤需要关联／派生结果或用户明确要求核验自动链路时，读取 Link、适用反向关系和 Formula / Lookup；按目标核唯一／零／多命中，必要时核重复处理。

题型／环境不能回写时保留可完成的收集，报“自动关联/派生计算未验证或受阻”；不以名称文本、URL、手工关联冒充自动链路。

### 必填、条件显示与输入范围

- 先按当前有效需求确定一次有效提交不可缺少的用户输入，设为必填；原话点名要填写人提供的字段默认算这类输入，原话标明选填的除外；不能因用户没有逐题写“必填”就沿用全部选填的默认值。可省略而不影响业务处理的补充说明、明确选填项保持选填；系统生成或后台处理的结果不要求填写人作答。调整题目结构时保留必填要求的适用范围和条件，不把整体必填扩大为每题必填。必填和是否显示分别确定，配置组合及不能等价替代的情形见 [显隐协议](../references/form-questions.md#显隐条件visible_rule)。
- 要求答完前置题才展示后续题时，前置题排在受控题之前，并按答案配置 `visible_rule`，核对满足与不满足条件的两条路径。若前置条件是外部行为已完成，还须核实当前入口能否取得完成状态；用户勾选声明只证明其自报，不能作为外部行为完成的等价校验。不能实现的部分保留未完成并如实说明。
- 字数／数值／日期范围落实为入口约束；必填、描述、默认值、提醒 Workflow、提交后人工核对均不能代替范围拦截。
- 单侧边界只限该侧。固定日期用绝对日期；“从今天起、未来 N 天、本周内”随运行日滚动，不固化为执行日。
- 选择题区分字段完整选项与本入口可填集合。专用字段只定义允许值；复用共享字段时按 [已有字段题目协议](../references/form-questions.md#形态-b已有字段题目) 判断能否收窄，不删其他用途所需选项。
- 显隐、默认值、描述不等于选项约束；无法表达时报告未完成，不静默更换用户指定的字段。

### 题序目标与依赖

题目集合、题序分别确定并满足各自规则。用户明确指定题序，或要求照来源问卷、模板（含其分节、编号）建表单时照用；“最后”“开头”“放在某题之后”等位置要求是硬约束，与其他顺序冲突时以位置要求为准。用户在对话里列举收集项（含编号清单）只确定收集范围，不自动视为指定题序，按下列语义分组与填写流程确定目标。公式、查找引用题依赖其他题的填写值时，被依赖的题排在前面，先填写、后看到结果。顺序须满足 [显隐条件的前序依赖](../references/form-questions.md#显隐条件visible_rule)；与用户明确要求冲突时先向用户说明，不静默改写要求。

1. **按语义分组**：记录每题的主体／业务环节和语义组，按收集目的分为身份与联系、对象与时间、核心作答、补充说明。同一主体或环节成组，不同主体分开，不按字段类型混排；依附于某个对象的信息紧跟在该对象之后；联系方式不因选填或创建较晚而移至末尾。
2. **按填写流程排序**：身份、对象、时间等前提在核心作答前；同组连续，开始在结束前，因果／显隐前置题在先。仅业务流程或依赖需要时拆组，不无故切走再返回。
3. **补充内容收尾**：备注、说明、意见等自由补充放在相关核心信息后，整表补充放最后，后面不再接主体／对象／业务时间。按业务作用判断，不按必填开关机械排序，核心长文本留在所属组。
4. **先验目标再写入**：逐组核位置；拆组、前提后置、补充后又回到核心信息，须有用户指定或业务／显隐依赖依据，否则先修正再映射字段 ID。只排序现有目标题目，不为排序新增身份题、改标题或必填。

### 展示与运行目标

| 用户要求 | 配置目标 |
|---|---|
| 一页一题／传统表单 | 填写页分页；其他外观先核展示能力边界 |
| 名额／总量、个人次数、截止／起止时间 | 提交总量、个人次数、有效期；不用字段、名称、描述代替 |
| 提交后／定时通知 | 通知配置及接收人、时间 |
| 结果页／跳转 | 提交后动作；只改标题时保留原描述 |
| 抽奖 | 抽奖配置；先取得条款同意 |

### 分享范围

| 维度 | 判定 |
|---|---|
| 开关 | 要填写链接／扫码时开启；仅创建、读设置、索二维码图片不授权开启 |
| 填写人 | 选仅邀请对象、组织内成员、持链接的任何人；仅组织外不特定对象才用最后一项 |
| 登录 | 单独决定；外部填写不等于免登录 |
| 匿名 | 单独决定；免登录不等于匿名，匿名不等于关闭登录 |

组织内填写／收集个人敏感信息时沿用组织内访问和登录；指定邀请对象时保持更窄范围。与外部／免登录冲突先澄清，不自动放开或改写。只改授权目标必需项，其余保留；登录、匿名须符合身份方案。

## 执行与提交

单项只改目标及依赖，复用对象和有效读取；同一请求明确要求创建后查／改／删时按用户顺序执行，异常按恢复处理。

### 表单读取与维护

- 只读用 `+form-list`／`+form-get`；仅有分享链接则走填写路径。
- 先备底表，再 `+form-create`；存真实 ID，执行 [开工必读的配置流程](#开工必读)，隐藏无需填写的系统派生、后台维护字段并保留底表数据；原话要求自动带出的查找引用／公式题保留在问卷中。
- 改标题／描述前读当前值，只改目标；题目文本走题目命令，分页走展示配置。
- 删表单前确认目标、保留对象；写后核表单已删且底表、字段、记录保留。后续删除不替代创建阶段的数据与提交结果检查。

### 题目管理

先完成收集项和属性决策；涉及提交时间或填写人时同样执行身份规则。

| 操作 | 执行 |
|---|---|
| 创建／复用 | 据前置结果确定建、复用、更新；隐藏成员走可见集合。按 [创建请求与支持类型](../references/form-questions.md#创建请求与支持类型) 执行并复用返回对象 ID；局部失败走恢复 |
| 更新 | 用更新前的完整配置，仅改目标；按 [全量覆盖协议](../references/form-questions.md#全量覆盖与更新基线) 构造 `+form-questions-update`；属性更新不改变题序，需另调顺序；显隐依赖先把控制题移到受控题前；误改标题则恢复 |

#### 移除题目与底层字段保护

| 意图 | 边界 |
|---|---|
| 删／移题 | 仅移出表单，保留字段、数据 |
| 仅隐藏，保留成员关系 | 改可见列表 |
| 明确删字段、整列、已有数据 | 才同时删除字段和数据 |
| “删掉”指代不明 | 先澄清，不取更破坏的解释 |

以保存的字段、代表值为基线，按 [删除题目协议](../references/form-questions.md#删除题目form-questions-delete) 执行并检查结果。重新显示时区分已移出题、仍是成员的隐藏题。

#### 调整题目顺序

题目集合定稿、创建和移除完成后，`+form-questions-update` 不改题序；按[题序目标](#题序目标与依赖)把全部题目字段排好，用 `+view-set-visible-fields --view-id <form_id> --json '{"visible_fields":[...]}'` 整体提交一次，见 [可见题目与排序协议](../references/form-questions.md#可见题目与排序)。只排序不改成员；隐藏／恢复才改成员。提交前用 `+view-get-visible-fields` 取得全量覆盖所需的当前成员与顺序基线；已有完整可信基线则复用。响应缺少最终顺序、后续操作依赖实际顺序、结果未知或用户明确要求核验时再读取。

### 展示与运行配置

按表单配置协议写目标；用有效基线，仅缺失、失效、并发时补读。响应缺少最终设置、结果未知或用户明确要求核验时再 Get。

#### 填写有效期与抽奖

- 开有效期前确认 Base 时区；未设置时先按目标时区 [设置 Base 时区](base.md#更新-base-时区)，不擅自用其他时区。取值见 [提交设置协议](../references/form-settings.md#提交设置form-submission-settings-get--form-submission-settings-update)。
- 开抽奖前，用户须阅读并明确同意 [《飞书问卷抽奖管理规范》](https://www.feishu.cn/hc/zh-CN/articles/047445276639-%E9%A3%9E%E4%B9%A6%E9%97%AE%E5%8D%B7%E6%8A%BD%E5%A5%96%E7%AE%A1%E7%90%86%E8%A7%84%E8%8C%83)，再按 [抽奖协议](../references/form-settings.md#抽奖配置form-lottery-get--form-lottery-action) 开启；创建授权不代替同意。

### 分享范围与可用填写入口

仅查询时读、报分享设置；修改时复用有效状态，只交差异。响应未返回所需分享链接、结果未知或用户明确要求核验时再 `+form-share-get`。

| 入口 | 执行 |
|---|---|
| 链接／扫码／他人／在线提交 | 题目完成后配置分享并复用返回的真实链接，不以“前端获取”代替；真实提交仅在实际执行后报告 |
| 二维码 | 按分享决策核前置，再按 [二维码协议](../references/form-share.md#分享二维码form-share-qrcode-get--form-share-qrcode-download) 取图。未开分享且仅索图、未授权开启时说明前置，由用户决定。仅要链接不下载；要图须展示／附加，不只报路径；失败走恢复 |
| 提交后查询页 | 仅要求查已提交内容时配置；改题／分享／布局不创建。已有复用，没有则按 [首次创建协议](../references/form-share.md#查询页首次创建与关联恢复) 执行并保存返回的查询页 ID；结果未知时恢复且不重复创建。要求修改提交时另配、验权限；查询页不代表可修改 |

### 表单样例准备

- 需样例时按 Mock 数量，先 `+form-questions-list` 核题型、必填，再生成与真实填写同形的数据；建表单不重置来源、数量要求。
- Mock 满足必填、选项、附件、显隐；内部管理字段不作外部填写题。
- 附件题仅有用户文件／fixture 时提交；缺附件不跳过其他 Mock。附件按 [附件协议](../references/form-fill.md#附件上传attachments)，底表按 Mock 写入结果或按需核验处理。

### 填写与提交

1. 复用有效详情；仅用户明确要求填写／提交时，配置变化后重跑 `+form-detail`。
2. 按 [填写协议](../references/form-fill.md) 备真实答案、附件，核必填、显隐；公式、查找引用题不传值；签字题只用用户提供的 PNG 签名图片，未提供先索取，不生成或伪造签名。测试数据先满足新底表条件。
3. 目标、范围清楚且授权后执行 `+form-submit`，保存提交返回；结果未知则恢复。

## 结果检查与按需读取

写入结果记录实际表单、题目、顺序、设置、入口及返回 ID。后续步骤缺少必需状态、结果异常／未知、部分成功或用户明确要求核验时，才定向读取目标对象；全量覆盖所需读取在写前完成。

### 按需读取范围

| 触发场景 | 读取范围与判定 |
|---|---|
| 用户明确核验表单、题目或题序 | 分别用 `+form-get`、`+form-questions-list`、`+view-get-visible-fields` 读取点名对象，核对归属、属性、成员与顺序 |
| 用户明确核验展示、提交、通知、结果页、抽奖或分享设置 | 使用对应 Get，只检查点名设置及必须保留项 |
| 移题保字段、删除表单 | 读取题目／表单及必要字段、代表值，确认目标已移除且保留对象未受损 |
| 关联、迁移或派生安全检查 | 读取提交记录、主档、Link 及必要 Formula／Lookup 结果，按授权范围确认映射与保留值 |
| 提交结果未知 | 按[结果不确定时的查询与重试](../references/form-fill.md#结果不确定时的查询与重试)确认是否落库，不直接重提 |

### 新底表样例与真实提交条件

底表沿用 [Mock 数量](mock-data.md#数据来源与数量)和写入结果口径；原话明确空表／数量 0 时不写记录，既有表不写测试数据。真实提交的触发条件是用户明确要求提交或核验提交链路；触发后按[填写与提交](#填写与提交)执行，并把已接受的提交计入既定总量。结果未知按下节恢复，不为测试扩大分享、取消匿名或改登录。

## 异常恢复

与 [通用恢复](../SKILL.md#异常恢复与停止条件) 同时适用。保留已完成对象和证据；解析／局部失败不重放整批。分享失败按目标修复，不放宽范围。

| 情况 | 恢复 |
|---|---|
| 题目创建未知／部分成功 | 读字段、题目，识别已完成项 |
| 提交 `800004014`／超时／网络错误 | 结果不确定，按 [查询与重试](../references/form-fill.md#结果不确定时的查询与重试) 查询底表确认是否落库，不直接重提；参数校验类错误（`800004006`、`800004025`）表示未落库，按报错修正 |
| 标题误变 | 用原题 ID、原标题恢复；全量覆盖时保留其他目标配置。缺原值先核实、不猜，不当优化交付 |
| 二维码失败 | 按 [恢复协议](../references/form-share.md#二维码校验与落盘恢复)；开启仍受原授权，成功后展示／附图 |
| 查询页失败 | 保留对象，按 [未知恢复](../references/form-share.md#查询页部分成功与未知状态恢复)；未知则报事实，由用户决定，不删除重建／重复创建 |
| 展示配置错误 | 按 [重试协议](../references/form-settings.md#展示配置错误与重试)；并发时核原目标，不覆盖他人改动；恢复后检查目标配置 |

### 样式拒绝后的恢复

样式被拒时按 [恢复协议](../references/form-questions.md#样式拒绝后的恢复) 处理：参数／请求错误定向修正并复验；明确的能力拒绝保留缺项并报告未完成。用户明确要求的 Phone、超链接、签字、公式、查找引用题不静默降级；电话、邮箱默认按普通文本收集，金额默认按普通数字收集。已有专用字段未经用户同意不改型，也不新建同义字段绕过；用户同意后交 Field 执行改型，并重验存量值与视图、筛选、公式、Lookup 等依赖。
