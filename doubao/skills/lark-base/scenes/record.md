# 记录

## 开工必读

- 读记录先定格式：数量／抽样用 `--format json --limit 200`（可配 `--jq`），全量用默认 NDJSON（stdout 是 manifest，记录在 `record_file`）；写法见 [常用读取写法](../references/record-read.md#常用读取写法)。
- 单元格值形态（单选数组、人员／关联 `[{"id":...}]`、日期带时分）见 [CellValue](../references/record-cell-values.md)。`not_found` 实测触发：字段名不存在、单选／多选值不是已有选项、人员 ID 不存在、table_id 不存在；一批一条错整批不写（关联 ID 错、数字写成字符串、日期只到天不报错）。
- 写前 `+field-list` 取字段名和选项（也可 `+field-search-options`，值与限制见 [选项值协议](../references/record-cell-values.md#单选与多选select)），选项不够先按用户授权和 [字段更新规则](field.md) 加选项再写。
- 没有 `+record-update`，改记录用 `+record-batch-update`。

## 任务导航

先做 [前置检查](#前置检查)：

| 用户目标 | 流程 |
| --- | --- |
| 定位、筛选、排序、关键词搜索、导出原始记录 | [读取范围](#读取范围与查询边界) → [读取与完整分页](#读取与完整分页) |
| 创建、更新记录 | [写入决策](#写入决策) → [创建与更新](#创建与更新) |
| 删除记录、附件上传/下载/移除、分享链接、单条记录变更历史 | [删除、附件、分享与历史](#删除附件分享与历史) |

执行后按 [回读验收](#回读验收) 核对，失败进 [异常恢复](#异常恢复)；多操作复用有效结构和证据。新 Base、新表其他验收进 [Base](base.md)、[Table](table.md)。

## 前置检查

- 确认目标 Base、表、记录范围，ID 来自可信输入或真实返回；有可信记录 ID 直接读，缺 ID 或目标不唯一再定位。写前明确数据来源、目标字段、预期结果、通过条件；更新前确认记录存在。
- 只读任务不因发现问题自行写入或补数据。删除记录、移除附件前记下目标与保留对象，只动用户明确指定且同类型内唯一确认的资源；业务描述不授权删除。
- 目标无法唯一定位、数量不足或不存在时报告核验范围与缺口，不跨类型替代，不改非目标资源补齐。授权边界见 [主入口执行与协作](../SKILL.md#执行与协作)。
- 按操作查结构，下载、分享、历史不加载字段协议；读取、筛选、排序前用 `+field-list` 确认真实字段、类型、展示字段、业务 key；输出列绑定真实来源字段，不用近义或值看似合理的字段替代。
- 关联记录先确认目标表、业务唯一键、展示字段，跨表读该表真实字段。附件先确认目标记录与文件范围，上传前按 [附件写入限制](../references/record-attachments.md#签字附件限制) 核对字段能力。

## 数据处理决策

### 读取范围与查询边界

- 筛选、排序、结果解释遵守 [共同查询约束](query.md#共同查询约束)。
- 自然语言筛选、Top N、时间限定先读 [任务口径与核对](../references/shared-statistics-rules.md#任务口径与核对) 和 [字段充分性](../references/shared-statistics-rules.md#自然语言条件与字段充分性)，但不因此转入独立 SQL 分析。逐项标 Include / Exclude / Unknown，不把阶段状态当最终状态，不静默丢弃 Unknown。
- 原话中的类别、状态等限定词必须写进 `--filter-json`；表中实际类别多于限定词时筛掉多出的类别。再在云端对完整范围排序后取 N，任意前 N 行不是全局排序结果。返回后逐行核对。

- 看几条、预览、样例只证明已读范围，不推广为全量计数、异常识别或分组结论；读取或导出符合条件的全部原始记录时固定表／视图及筛选范围，完整读取。
- 计数、求和、分组排名等独立分析进 [Analyze-data](analyze-data.md)，由 Query 执行。“金额最大的 10 条订单”是记录排序，“销售额最高的 10 个客户”是分组聚合。
- 普通读取不加载 Context/SQL。聚合、分组走已获准的分析路径或对象计算路径。有限返回只有在云端已做完相应处理时才能支撑结论；本地后处理不能扩大证据范围或绕过选路。
- 查询后要写入或视图化，先取得可复核的目标记录 ID 集合，再进 [创建与更新](#创建与更新) 或 [View 配置](view.md)。逐条回查用真实业务 key；分组结果行不是原始记录，不猜记录 ID。

### 写入决策

- 先定新增还是修改，按 [命令选择](../references/record-write.md#命令选择与公共参数) 构造；创建不按业务键查重更新。每条更新只含要改的字段，不为统一批量结构改其他字段。
- 按 [可写字段边界](../references/record-cell-values.md#只读字段与附件边界) 区分普通存储值、派生结果、附件，走对应路径。
- 复用用户数据与可信记录，既有表不自动补数。本轮新表初始化或补 Mock 必须读 [Mock](mock-data.md)，按其数量、人员、业务一致性规则准备并逐表全量验收。普通事实值（订单金额、Mock 明细）按存储字段写。
- 统计、汇总、派生结果要长期留表并随源数据变化时，必须用 formula / lookup 动态计算，不用 `+data-query` 或程序算静态值写回普通字段；先按 [公式与查找引用](field-formula-lookup.md) 建好字段和依赖再写记录。

## 执行操作

连续修改按用户顺序，每步写后通过当时的 [回读验收](#回读验收) 再进下一步；后续删除、覆盖不能掩盖前一步错误。

### 读取与完整分页

按 [读取协议](../references/record-read.md#调用参数与限制) 选定位方式和命令，按 [输出解析与完整分页](../references/record-read.md#解析返回与完整分页) 取结果；含关联字段接下节。

### 关联记录与多跳回查

按 [关联数据协议](../references/record-read.md#关联记录的数据形态) 取连接键，以候选数最小的事实表为驱动表沿已确认关系读关联表；多跳逐跳建立记录身份与可读字段的映射，输出真实业务信息（连接键不能代替），不凭 ID、自增编号、关联值、字段先验或样本记忆猜测补全。

### 创建与更新

按 [写入协议](../references/record-write.md) 和 [CellValue](../references/record-cell-values.md) 把逐条字段修改组装为请求，遵守批量限制与调用顺序；保存请求、返回、记录身份，按协议区分已写入与未写入，再回读验收。

### 删除、附件、分享与历史

对已确认的目标集合按协议执行，按下表验收：

| 操作 | 协议与要求 | 验收 |
| --- | --- | --- |
| 删除记录 | [删除协议](../references/record-write.md#删除记录record-delete) | 目标确已删除，保留对象仍可读且语义一致；读取失败或无权访问不证明已删除 |
| 上传、移除附件 | [附件协议](../references/record-attachments.md)；“把文件/文档/附件放进表/记录”默认指保留原文件为附件（docx、pdf、图片等），可另写摘要字段，但文本、URL、文件名、摘要不替代原文件 | 回读附件字段，核对实际文件、追加／移除结果、应保留的附件 |
| 下载附件 | 同上 | 本地路径存在、大小合理，文件及范围符合要求才说“已下载” |
| 分享 | [分享协议](../references/record-share.md) | 核对提交的记录集合与真实返回链接；要求可访问时在已授权条件下验证，无访问证据只报链接已生成及未验证项 |
| 历史 | [历史协议](../references/record-history.md#返回字段与事件范围)；也要当前值时另读记录 | 记录身份与事件覆盖符合请求范围；协议限定的事件不能证明当前值或整表审计完整 |

## 回读验收

- 写操作核验服务端保存结果（删除、附件、分享、历史见 [上表](#删除附件分享与历史)），只查本轮修改和受影响对象，不扫无关资源；纯读取用本次查询结果验证，不为验收额外写入或重复查询。
- 读取、搜索、导出：字段映射正确，覆盖选定的 [读取范围](#读取范围与查询边界)，输出可追溯到真实表、字段、条件、连接键。
- 更新：按实际提交的 ID 回读，逐条确认修改生效；ID 来源与返回含义见 [批量更新协议](../references/record-write.md#批量更新record-batch-update)。
- 创建：按返回 ID 回读、核对目标字段。需确认数量或交付时用 `+record-list` 在目标表以本次 ID 集合核对，按已确认条件缩小范围，全量按读取协议分页；不凭创建成功或返回 ID 数宣称达标，不把表总行数当本次创建数。
- 指定视图交付时先确认记录在底表存在，再按视图实际筛选核验可见结果，视图未命中不等于创建失败，不因此重复创建或放宽条件。
- 最终报告实际对象、范围、证据、未完成项、限制；连续任务保留每步验收结果并核对最终保留范围；必需项全通过才声明完成。

## 异常恢复

先按 [通用调用与恢复](../references/shared-cli-invocation.md#通用恢复) 及命令协议区分调用失败、结果未知、解析失败，再按下表：

| 情况 | 恢复 |
| --- | --- |
| 命令成功，解析或后处理失败 | 用本次原始返回修复解析，不重放成功写入；读取或下载失败不拿旧文件当本次结果 |
| 创建、更新或附件变更结果未知 | 先读原目标确认已生效范围；创建没拿到 ID 用本次来源数据和可核实业务键定位；无法确认报告受阻，不再创建或重复追加附件 |
| 写入冲突或部分批次完成 | 保持原目标，核对已完成结果，只处理确认未生效部分，不循环重放整批 |
| 回读值、数量或视图结果不符 | 查记录集合、查询范围、视图筛选、字段来源，只修有证据的失败项，不补造记录、放宽条件、改非目标对象凑数 |
| 字段或类型错误、部分字段未写入 | 见 [字段与记录错误](../references/record-write.md#字段与记录错误)；先确认已生效内容，创建已成功就更新原记录不重建；只读或派生字段转字段流程，做不到留作未完成项，不能删请求字段了事 |

同一原因只定向修复一次并复验，仍失败报告受阻并继续不依赖它的工作；恢复后按原目标和验收范围核验，通用限制见 [主入口恢复协议](../SKILL.md#异常恢复与停止条件)。
