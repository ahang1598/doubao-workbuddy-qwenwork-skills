# 公式与查找引用

本页规定 Formula、Lookup 的选型、依赖与验收。授权、完成态、恢复预算沿用主入口，结构变更、存量保护沿用 Field。

## 开工必读

- **`expression` 写在字段 JSON 顶层。** `--json '[{"name":"状态","type":"formula","expression":"IF(...)"}]'`，不包成 `formula:{...}`。
- **先查重名。** 用 `+field-list`。Formula／Lookup 重名时报 `validation_error: validation_error`；Formula 创建不校验引用字段和函数；Lookup 的 `from` 表或 `select` 字段不存在时报 `not_found`。失败后先查是否已建，不换表达式重试。
- **聚合关联记录前确认括号里是关联字段名。** 双向关联不写 `bidirectional_link_field_name` 时，对端反向字段自动以本表表名命名；`[表名].[字段].SUM()`、`COUNTA([表名])` 算的是整张表，每行结果相同。反向字段与表同名时先改名：`+field-update --field-id <id> --yes --json '{"name":"关联<表名>","type":"link","link_table":"<table_id>","bidirectional":true}'`，再写 `[关联<表名>].[字段].SUM()`。公式引用不存在的字段也能创建成功，只是结果为空；建完抽查两行，每行相同或为空就是引用错了。
- **关联取值写 `[关联字段].[目标字段]`。** 不写 `[表].[字段].FIRST()`（整表第一条），不以 `[表].FILTER(CONTAIN(...))` 拼匹配；多关联按业务用 `SUM`、`MAX` 聚合。
- **空值用 `ISBLANK`／`IFBLANK` 判断。** `BLANK()`、`NULL` 不在支持的函数清单中，不用来构造空值。
- **同行可计算的量建 Formula。** 如差额、剩余，不建普通字段手填。
- **由日期、金额、阈值决定的状态建 Formula。** 是否逾期、是否达标、是否迟到、档位都一样；手填单选不会随数据变化。
- **期限、阈值按明细判断。** “满 N 个月”写 `DATEDIF([开始日期],[判断日期],"M")>=N`；按发生时判断用明细日期，不用 `TODAY()`；“单笔／单次超过 X”逐行判断后汇总，不改成月合计判断。

| 派生量 | 写法 |
| --- | --- |
| 关联记录数 | `COUNTA([关联字段])` |
| 关联字段合计 | `[关联字段].[金额].SUM()` |
| 下次日期 | `[上次日期] + [周期天数]` |
| 差额、剩余 | 两字段相减 |
| 是否超期、及时 | `IF([完成日期] <= [截止日期], "是", "否")` 类判断 |
| 按周汇总 | 先建 `WEEKNUM([日期])` 周次字段，再分组 |

建完用 `+record-list` 抽查有输入的记录；全空或全相同通常是引用错误，如查找条件用关联字段匹配姓名文本。修正后再供视图、图表使用。新字段替代旧字段时，用 `+field-delete` 删除或 `+field-update` 修复旧字段，同一含义不留两个。

## 任务导航

| 任务 | 流程 |
| --- | --- |
| 查看、解释或排查 | 确认目标、现有定义 → 按[回读验收](#回读验收)取证 |
| 新增计算、跨表取值或汇总 | 前置检查 → 计算决策 → 准备依赖并按[字段创建](../references/field-commands.md#base-field-create)创建 → 回读验收 |
| 调整公式、匹配或聚合 | 读原定义、依赖 → 明确差异 → 按[字段更新](../references/field-commands.md#base-field-update)更新 → 验收影响 |
| 用于下游 | 先验收字段再配视图、仪表盘或流程；显示与触发按[交互目标](#交互式一键判断)分流 |

Formula 读[表达式契约](../references/field-formula-expression.md)和[函数契约](../references/field-formula-functions.md)，Lookup 读[查找引用契约](../references/field-lookup-config.md)；
统计、比率、动态时间再读[共享统计规则](../references/shared-statistics-rules.md)。

## 前置检查

### 目标、当前定义与源字段

1. 按 [Field 前置检查](field.md#前置检查)确认目标、授权、依赖；解释／排查不隐式授权新建字段、修改公式或记录。
2. 复用有效真实结构。缺表身份时用 `+table-list` 定位，以 `+table-get` 读当前表、引用表；按数据表契约解析，读取／解析失败不等于不存在。
3. 更新前取完整原定义；按需以 `+field-list`／`+field-get` 核实源字段、匹配键类型、单／多值形态；遵守 Formula 名称约束和 Lookup 约束。
4. 缺关键源字段或口径时，按 Field 口径规则补齐或澄清。
5. 记录已有数据覆盖的分支、时间范围、匹配形态，供验收取证；无需全量读记录。

### 阅读前置

创建或更新前完整阅读本页及导航指定协议；复用仍有效的已读内容。按计算字段阅读确认协议提交参数。

## 计算决策

<a id="执行与验收要求"></a>

### 长期结果与字段选型

长期派生与事实录入遵守 Field 动态计算规则。下表用于新增；更新时保留已确认类型，不擅自转换。

| 目标 | 类型 |
| --- | --- |
| 建立可编辑关系，由用户选择关联记录 | 关联字段 |
| 当前表计算、条件、文本／日期处理、跨表引用或聚合 | 默认 Formula |
| 用户明确要求查找引用 | Lookup；确定来源、匹配和输出 |

不要只为 Lookup 额外建关联列；仅用其协议支持的来源与条件。

### 来源、匹配关系与筛选范围

构造前在验收项写清 `结果所属实体/记录 → 源记录集合 → 全部匹配键与条件 → 输入形态 → 输出类型`。输入区分标量、列表、日期；分别取证计算类型与导出展示，NDJSON 字符串不证明公式内是文本标量。
先定匹配数量、聚合、空值含义，再比较同类型；不得用无条件 `FIRST()` 或 `TEXT()` 掩盖类型问题。

- 有业务关联字段就沿用其取值或聚合；没有时确认两表中业务含义相同的匹配键，不为计算结果改成人工选择关联。
- 用户指定的全部匹配字段都参与计算，并确定日期粒度、固定条件、记录范围；如“汇总已完成订单金额”须同时包含项目匹配和完成状态筛选，不能只保留一个。
- 结果属于某次订单或事件时，同时限定主体、事件，不按客户合并全部历史。各层汇总保留粒度，下游不得扩大范围。
- Formula 的关联访问、单／多值匹配、多字段条件见[关联与跨表引用](../references/field-formula-expression.md#section-5-link-fields-and-cross-table-references)和[匹配键规则](../references/field-formula-expression.md#match-keys-in-patterns-1-3)；Lookup 的匹配方向与条件见[匹配字段对](../references/field-lookup-config.md#how-to-find-the-matching-field-pair)。
- 按共享统计规则确定粒度、分子分母、权重、动态时间和年度口径；下游范围一致。

### 条件、边界与分支优先级

- 将条件写成可核对规则：80% 还原为 `0.8`；“以上／以下／以内”含边界，“小于／大于／以外”不含边界。
- 状态／选项依赖先列真值表：每个状态的条件、预期结果、空状态、未知状态；逐项实现，不用通用算术替代状态规则。
- 保留指定的分支优先级；不得因换函数重排重叠条件。未明确且影响结果时先澄清；仅语义等价时展平嵌套，不强制互斥。
- 明确真实零值、未匹配、不适用、计算错误的呈现；函数与兜底见[条件函数组合](../references/field-formula-functions.md#条件函数组合)，空分支类型见[空分支契约](../references/field-formula-expression.md#typed-blank-branches-in-conditional-formulas)。

累计、封顶、扣减或重置依赖前一事件时，按主体列出事件顺序、有效增量、截断时点、扣减／重置条件和应保留状态，再选实现。逐次截断丢弃的超额不得在后续扣减时计回；全历史收支求和后统一封顶不等于逐事件计算。

流水或周期归属交系统搭建／Field 准备关系，逐次写回交 Workflow。按协议确认能力；重复处理不得重复累计，不把读取行序当业务顺序，不构造未支持的递归公式。无法表达时按能力缺口交付，不用静态结果冒充持续计算。

### 输出与聚合目标

先定输出：全部匹配值、去重列表、单值、总额、平均值、极值、计数、去重计数或排名。分别确认数量与列表、匹配记录数与非空值数，不因返回类型可用就改口径。
单值须要求唯一匹配，或允许多条并按确定规则选择。聚合函数按已读协议选择。

取“最近／最后一次”时先限主体、范围，再按真实事件时间定位并取目标值；不得分别取时间和状态极值、拼全部状态或任取列表首项。
时间并列按已确认顺序处理；无唯一依据时保留歧义。分别处理无匹配、事件时间缺失、最新目标值为空，不擅自改取更早非空值。

### 交互式“一键判断”

先区分持续展示与点击动作。持续展示用判断 Formula 配合筛选视图或仪表盘；按原始字段的空值、布尔、枚举筛选，不对自造文案做包含匹配；确需按文案筛选时枚举全部目标状态。
点击写回按 Field 派生能力和按钮协议准备按钮；自动化进入 Workflow，完成绑定、执行验收。

## 执行与提交

1. 按 Field 依赖准备先建表、源字段、关系，再配计算字段；新表数据沿用 Mock。
2. 逐字段把结果实体、源集合、全部匹配条件、输出落实到表达式或 Lookup；批量创建也逐项对应。引用须在当前映射定位；缺源字段交回 Field，不猜近义名称。
3. 新增用 `+field-create`；调整用 `+field-update`，按 Field 更新流程保留字段身份。结果未知或部分成功时进入[异常恢复](#异常恢复)。
4. 每次写后执行[回读验收](#回读验收)，通过适用检查后才供下游引用。

## 回读验收

### 共同证据与完成条件

创建／更新后，必须以 `+field-get` 核对定义、以有界 `+record-list` 核对结果并按协议处理返回差异。只读解释按证据区分定义解读、结果核验。

| 证据 | 通过条件 |
| --- | --- |
| 保存定义 | 字段正确；来源、全部匹配条件、分支优先级、范围、输出与确认内容一致；逐个确认匹配字段名是用户指定业务键，而非同类型相邻字段 |
| 计算结果 | 以条件字段、必要源值和结果对账；已有代表数据覆盖的每个分支及适用专项检查符合预期 |
| 存量、下游 | 按 Field 验收核对影响；视图、仪表盘、流程保持同一口径 |

从保存定义逐项查预期键、日期粒度、状态限制。Base/Table 字段数组中每个计算字段都查引用语法、定义，不只验收后补字段。按实体记录协议处理完整分页；manifest 不提供计算值证据。

Mock 数据须逐项核对正常、边界、异常取值和业务一致性。缺代表记录的分支只核定义并标为未验证；不得编造记录、改既有表凑验收或重写公式。
最终答复和下游引用须区分已验证、证据缺口、实际失败，不把未取证称为已验证。

### 年度计算回读

按年度规则核验日期依据、动态范围、下游一致性；实际结果覆盖范围内外已有代表记录，缺口按共同条件处理。

### 条件公式的空分支

匹配行返回预期数值，不适用行为空，真实零值仍为零，分支结果类型符合目标；失败进入[异常恢复](#异常恢复)。只聚合符合条件记录时，仪表盘仍设对应筛选；筛选不能替代逐行区分真实零值与不适用空值。

依赖事件顺序时核对连续状态变化。截断／重置须覆盖“先超额封顶 → 扣减或重置 → 新增量”，确认丢弃超额不结转、其他主体和无关状态不变、重复处理不重复累计。仍遵守共同条件，不向空模板写测试流水。

### 跨表匹配与关联聚合

- **逐行关联计数：**按真实关联数对账；数量不同则计数不同，无关联为零；其他聚合按输出验收。
- **多值匹配：**多关联或多选匹配键须以多值代表记录验收，不从单关联结果推断。
- **匹配结果：**覆盖匹配、不匹配、多条匹配；同主体多事件时检查串算。最近值核对所选记录身份、事件时间、目标值，并按已定选择／唯一性要求验收。
- **跨表日期：**覆盖提前、同日、延迟、空日期、多匹配日期；同日按已定粒度验收。整列全 `0` 或全空不能凭保存成功通过。

用已有记录或授权样例验收：多键匹配覆盖完全匹配和仅一键不同的反例；主体汇总用金额不同的两个主体查串算，整表 `SUM` 不得冒充主体累计；状态重叠边界确认零值分支不提前命中阈值分支。无代表记录按未验证处理。

## 异常恢复

只有保存定义不符需求，或已有代表数据结果错误，才定向修正。验证缺口按[共同条件](#共同证据与完成条件)处理；恢复预算及未知状态的读取、停止要求沿用[主入口](../SKILL.md#异常恢复与停止条件)，切换协议不重新计数。

| 故障 | 恢复 |
| --- | --- |
| 读取失败，创建／更新结果未知、部分成功、类型不一致或 no-op | 按 [Field 恢复](field.md#异常恢复)及命令协议确认现状，再继续 |
| Formula 语法、引用、类型错误 | 按[表达式错误](../references/field-formula-expression.md#section-12-anti-pattern-collection)定位；空分支异常用[定向诊断](../references/field-formula-expression.md#空分支异常的定向修正) |
| Lookup 配置错误 | 按[查找引用错误](../references/field-lookup-config.md#section-8-anti-pattern-collection)处理 |
| 协议不能表达已确认条件 | 说明具体条件和能力缺口，将对应要求标为未完成 |

修复须保持[计算决策](#计算决策)确认的范围、匹配键、分支优先级、输出；验收未通过的结果不得交给下游。仍失败时报告未完成项，保留有效结果和缺失证据。
