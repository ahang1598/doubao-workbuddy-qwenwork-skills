# 视图

## 开工必读

- 视图组合包含表单时先交 [Form](form.md#开工必读)，完成题目属性与题序，不以普通视图数量代替。
- 类型与配置分别登记：用户指定时间轴／甘特时用 `gantt`，指定日历／月历时用 `calendar`；未指定时按浏览用途选择，仅修改配置时保留原类型。创建后记录返回的视图 ID；修改前需要保留现状时读取已有类型和配置。

- 把原话、背景句和视图名里的每个限定词各列一条：时间范围、状态集合、分组、排序、显示字段。每条都要配置。
  时间词修饰被筛记录时配时间筛选（如“这个月的工资里没发的”）；只修饰事件经过时不配（如“上次巡检出过问题，把所有没处理的找出来”）。
  只有日期字段时，用它建“是否本月”辅助公式再筛选；当前命中为空也保留条件和辅助字段。
- 自定名称含“本月／本周”就配对应时间筛选，否则删去该词；日历按月显示不等于本月筛选。
- 新建的看板、日历、甘特视图只是空壳。创建后用 +view-set-group 设分组、+view-set-timebar 设起止字段；平台默认配置不证明目标已完成。
- 日历、甘特按“一条记录代表什么”和用户浏览目的选择 timebar `title`：该字段的实际值须能在概览中标识记录。其余要求直接查看的信息用 +view-set-visible-fields 配置。
- 分组字段须符合视图名称和目标。指定字段不可分组时保留原业务语义并报告缺口；仅自行补充且未指定分组的看板可以选择等价字段，并同步调整名称。
- 状态集合按字面正向列值：“还没开始”只取未开始；“未完成／待处理”包含全部未结束选项（未开始、进行中、已暂停等），不得用 `!=` 只排一个终态。
- 本周、本月须动态。相对日期仅有 `Today`／`Yesterday`／`Tomorrow`；其他范围先建返回“是／否”的辅助公式再筛。本月范例：

```bash
lark-cli base +field-create --base-token '<base_token>' --table-id '<table_id>' --i-have-read-guide \
  --json '{"name":"是否本月","type":"formula","expression":"IF(AND(YEAR([业务日期])=YEAR(TODAY()),MONTH([业务日期])=MONTH(TODAY())),\"是\",\"否\")"}'
lark-cli base +view-set-filter --base-token '<base_token>' --table-id '<table_id>' --view-id '<view_id>' \
  --json '{"logic":"and","conditions":[["是否本月","==","是"],["状态","intersects",["未开始","进行中"]]]}'
```

公式字段写 `==` 加单个值；`intersects` 加数组只用于单选、多选，用在公式字段上报 `invalid_request`。

提交的 filter 必须同时包含时间和状态条件。

- “新增了哪些／昨天新增”筛创建时间；业务日期是事件时间，不等于新增时间。
- “只显示这些字段”用 +view-set-visible-fields 设为相等、保序的集合。

关键步骤：列出限定词清单 → 创建或定位视图 → 逐项 `+view-set-*` → 完成目标配置。日历、甘特配置 timebar 和 visible fields；单日事件允许起止相等。后续缺少必需 ID／配置、更新需读取现状、部分成功／结果未知、删除安全检查或用户明确要求核验时，定向读取配置或记录。

## 前置检查

### 目标、现状与能力

- 确认 Base、表、视图身份；可信 ID 直接复用，缺 ID、目标不唯一或现有配置影响决策时再定位／读取。修改／删除前记目标、保留项、受影响依赖。
- 决策／解释前取得真实字段定义、必要记录；核对能力后选字段／派生字段。可筛选不等于可分组／作时间轴。
- 类型合规仍须语义正确：起止属同一事件；不得因“创建时间”是日期就代替业务开始时间。

### 数据与计算依赖

- 使用真实记录。命令新建表按 [Mock](mock-data.md) 准备并满足数据目标；复制表按 [Table 副本保护](table.md) 保持范围，不因检查补样例；既有表不得为命中造数或放宽条件。
- 缺指标／动态判断字段时，在授权内按 [Formula / Lookup](field-formula-lookup.md) 建等价计算；复用创建返回后配置。查询／重命名不授权改辅助字段。

## 视图决策

只改已有视图该项及其影响，不重设计整组。

### 选择视图用途与类型

同表视图共享数据、各存配置。类型值见[创建协议](../references/view-commands.md#创建名称的传参约束)。表格用于逐行查看、分组、排序；看板（`kanban`）按状态或类别分列；画册展示带图卡片；日历按业务日期安排；甘特用于排期、工期或时间轴。

保留用户指定类型：时间轴／甘特／拖动排期用 `gantt`，日历／月历用 `calendar`；只有日期事件不等于工期，只有起止字段也不自动创建甘特。设计只选有用切面；单项修改不增视图。收集表单转 [Form](form.md)。

只有一个业务日期时，单日事件可按[时间轴协议](../references/view-display.md#日历与甘特的时间轴)用同一日期绑定起止；真实区间缺结束日期时保留缺项并说明，不借其他日期补造区间。

### 将用户要求和名称映射到目标配置

按开工清单映射并逐项配置；时间、主体、状态范围均转筛选。“未归还”等状态覆盖全部目标状态或原始事实；“今年”等同样须动态；“优先／最早／最新”先转成可验证的业务谓词，再配字段、优先级和方向。阈值类要求先形成相对阈值的标记或差额；“有差异／不为零”筛差异不等于零，`isNotEmpty` 不排除零。指定卡片或排期须内容符合要求，相关 Dashboard 组件也保持同一范围。

日历、甘特的 timebar `title` 是每条时间项的标题字段名；按记录粒度、用户目的和实际值选择。配置须覆盖计划中的限定词和目标字段；被拒时核对真实字段和协议。

各项分别配置，筛选按原逻辑组合。完整清单须集合相等、保序。计算、关联、权限辅助字段可留底表，但不自动显示；未要求改列就保留现有配置。

分组、聚合不得互代（如类别分组与各类别金额合计）。按[汇总边界](../references/view-display.md#分组与汇总边界)执行；指定位置不支持就标未完成，不得用 Dashboard 替代。

### 名称与修改范围

- 自定名称须准确；配置不符时在授权内修正，不得改名取消要求。
- 指定名称保留原意；已有名称不授权改其他配置或底表。仅重命名时普通文案只改名；新名增加业务含义时，要求配置则同改，否则说明差异、澄清。不得修复／宣称完成范围外项。

### 筛选与业务分组

- 筛选、状态、统计、Dashboard 共用口径，按[完整候选集](../references/shared-statistics-rules.md)定保留、排除、未知。优先筛原始事实；只能筛公式文案时须覆盖全集。
- 源字段映射类别时，分组字段须输出类别，不得用源值逐项分组或沿用不符名称。
- “每个 A 下面按 B 分”是两级分组：grid／gantt 视图的 `group_config` 依次放 A、B 两个字段；kanban 只放 1 个分组字段，二级用 grid 或按 A 建筛选视图再按 B 分组。
- 视图按创建先后排列；原话列了顺序就按顺序创建，不把默认视图改名充当中间某个视图。
- 按要求限范围；仅明确要求才清空全部筛选。确定目标后按协议请求；合并、提交见 Reference。

### 持久视图的相对时间

遇[相对时间](../references/shared-statistics-rules.md#时间范围与动态配置)，区分动态范围和固定历史区间；相关对象用同一业务日期、范围。按[日期协议](../references/shared-filter-tuple.md#datetime--created_at--updated_at)表达；需要辅助字段时先完成计算依赖。无法等价则受阻；不得省略时间、改固定日期、加未授权自动化。

本轮创建的“本周视图”须持续滚动；只靠名称或当前记录恰在本周都不算。未要求、未创建该名称时不强制新增。

## 执行与提交

创建后还有查询、修改、删除时，复用创建响应中的视图 ID 继续；删除前仍按安全流程确认唯一目标和保留项。

### 读取视图

按需读身份、保存配置、记录并分别说明范围；按本页规则解释。读取见[按需读取](../references/view-display.md#按需读取)。

### 创建与配置

1. 完成决策、依赖，定目标、通过条件。
2. 新建按生命周期创建并记返回对象；修改复用目标。非表格按开工规则显式配置，按类型、目标补展示项。
3. 保存筛选、分组、排序、展示，保留未涉及项。不得以临时查询代替、绕 raw API、交付替代物或只在答复描述。
4. 逐项提交配置；连续修改按用户顺序执行。

### 重命名

按名称范围重命名；同时改配置则执行创建与配置流程。

### 删除视图

按生命周期删除唯一目标。不得删底表、字段、记录（含 Mock）、其他视图。目标不存在／不唯一则报告，不得替代。

## 按需核验与交付

### 按操作完成

- 读取：对象符合请求，结论不超范围。创建／改配置／重命名：目标对象、类型和配置覆盖本轮要求，未涉及项保持原状。
- 删除：执行前确认唯一目标和保留项，执行后确认目标移除、受影响对象仍可读；按[生命周期协议](../references/view-commands.md#结果未知时的读取)区分缺失、读取失败。

### 名称、配置与记录一致性

读取已有视图、排障或用户明确要求核验时，数据表按 View 协议、Dashboard 组件按其[协议](../references/dashboard-view.md#返回结构与配置读取)定向取证：

- 名称符合目标，差异按名称范围处理。
- 保存配置兑现集合、分组、顺序、展示，不只看非空；动态范围核对条件、依赖表达式；完整清单按字段身份核对集合、顺序。
- 只有要求核验实际可见结果时才按保存范围、顺序读取记录；分别查命中、排除项，适用时做候选子类对账。

按 [Record 解析](../references/record-read.md#解析返回与完整分页) 消费记录：先读保存条件，再按视图取数；临时 `--filter-json` 正确不证明保存配置正确。

- **空配置**：要求存在但保存值为空才算未实现；要求清空则已空即通过。
- **组合筛选**：用记录／授权样例核对命中、时间不符、状态不符；待办类查全部已结束状态，不得只排一种成功状态。Unknown 不得归入待办／终态。
- **样本不足／空结果**：区分无命中、全命中、底表无记录，说明缺失证据。配置正确且范围为空可交付；要求实测却无证据则受阻。底表范围按创建／复制规则处理。
- **时间轴**：有记录则抽样确认结束不早于开始；无样本说明未实测。样例符合不替代保存配置证据。

### 对照目标交付

汇报视图和本轮配置；实际读取过记录时再汇报记录范围、空结果或未实测。失败、部分成功、结果未知和受阻项单列。

## 异常恢复

| 问题 | 恢复与边界 |
|---|---|
| 展示配置被拒 | 按[展示协议](../references/view-display.md#配置校验与恢复)核对能力、真实字段和请求；调整后只让受影响证据失效：类型、分组字段或业务语义变化时重核名称，配置变化重读对应配置，记录范围或顺序受影响时重读记录。用户指定项未经确认不得替换；仍失败则报告未完成项 |
| 筛选请求失败 | 按[筛选协议](../references/view-filter.md#类型约束与易错点)修正；业务集合不变 |
| 相对时间无法直接表达 | 回到动态范围决策，判断等价方案 |
| 配置已存但记录范围不符 | 回到筛选、时间决策，核对底表事实、计算依赖；只修已定位项 |
| 创建、更新、删除结果未知 | 按[生命周期恢复](../references/view-commands.md#结果未知时的读取)确认状态，再做未完成操作 |

所有路径共用[恢复预算](../SKILL.md#异常恢复与停止条件)，换路径不重置。仍失败时报告缺失的证据，继续做不依赖该项的工作。
