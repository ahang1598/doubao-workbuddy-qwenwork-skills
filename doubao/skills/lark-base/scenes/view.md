# 视图

## 开工必读

- 把原话、背景句和视图名里的每个限定词各列一条：时间范围、状态集合、分组、排序、显示字段。每条都要配置并回读。
  时间词修饰被筛记录时配时间筛选（如“这个月的工资里没发的”）；只修饰事件经过时不配（如“上次巡检出过问题，把所有没处理的找出来”）。
  只有日期字段时，用它建“是否本月”辅助公式再筛选；当前命中为空也保留条件和辅助字段。
- 自定名称含“本月／本周”就配对应时间筛选，否则删去该词；日历按月显示不等于本月筛选。
- 新建的看板、日历、甘特视图只是空壳。创建后用 +view-set-group 设分组、+view-set-timebar 设起止字段；平台自动填的分组（常是第一个单选字段）不算配置。
- 日历、甘特设完 timebar 后，用 +view-set-visible-fields 加入原话关心的对象和数值字段（如负责人、金额），不能只显示记录标题。
- 分组字段要和视图名一致：“状态看板”按状态分组。看板分组字段必须是可分组类型（如单选；公式不可）；原话点名的字段不可分组时，按同一含义建单选字段承载。
  名称写 `<分组字段>看板`；+view-set-group 后用 +view-get-group 回读，确认字段名与名称一致。改用其他字段时同步 +view-rename，不保留名不副实的名称。
- 状态集合按字面正向列值：“还没开始”只取未开始；“未完成／待处理”包含全部未结束选项（未开始、进行中、已暂停等），不得用 `!=` 只排一个终态。
- 本周、本月须动态。相对日期仅有 `Today`／`Yesterday`／`Tomorrow`；其他范围先建返回“是／否”的辅助公式再筛。本月范例：

```bash
lark-cli base +field-create --base-token '<base_token>' --table-id '<table_id>' --i-have-read-guide \
  --json '{"name":"是否本月","type":"formula","expression":"IF(AND(YEAR([业务日期])=YEAR(TODAY()),MONTH([业务日期])=MONTH(TODAY())),\"是\",\"否\")"}'
lark-cli base +view-set-filter --base-token '<base_token>' --table-id '<table_id>' --view-id '<view_id>' \
  --json '{"logic":"and","conditions":[["是否本月","==","是"],["状态","intersects",["未开始","进行中"]]]}'
```

公式字段写 `==` 加单个值；`intersects` 加数组只用于单选、多选，用在公式字段上报 `invalid_request`。

+view-get-filter 必须同时返回时间和状态条件。

- “新增了哪些／昨天新增”筛创建时间；业务日期是事件时间，不等于新增时间。
- “只显示这些字段”用 +view-set-visible-fields 设为相等、保序的集合并回读。

关键步骤：列出限定词清单 → 创建或定位视图 → 逐项 +view-set-* → 逐项 +view-get-* 回读，在返回里逐个找到清单上的限定词，缺一个就补 → +record-list --view-id 检查命中和排除的记录。日历、甘特读回 +view-get-timebar 后抽一条记录确认开始早于结束；起止配反会让所有记录变成负区间。

| 交付项 | 读取 | 通过条件 |
|---|---|---|
| 筛选 | +view-get-filter | 时间、状态齐全；动态范围非固定日期 |
| 分组、排序 | +view-get-group／+view-get-sort | 字段符合原话和名称，方向正确 |
| 时间轴 | +view-get-timebar | 绑定正确的业务起止字段；抽一条记录确认开始不晚于结束 |
| 显示字段 | +view-get-visible-fields | 集合、顺序符合要求；日历、甘特含状态、负责人等原话关心的字段，不只显示标题 |
| 记录 | +record-list --view-id | 应出现的在，应排除的不在 |

多视图任务逐个记录目标和证据。只读任务不写入。只有要求长期打开、共享或复用时才建持久视图；查询不授权写入，也不能代替已要求的视图。

写前先做前置检查，写后做回读验收。新 Base 或多模块读[系统搭建](build-system.md)；新表做视图枚举；样例、计算、分享走对应流程。
筛选、状态、统计、时间范围先读[任务口径](../references/shared-statistics-rules.md#任务口径与核对)，不得只按名称判断。

## 前置检查

### 目标、现状与能力

- 确认 Base、表、视图身份；可信 ID 直读，否则定位。修改／删除前记目标、保留项、受影响依赖。
- 决策／解释前取得真实字段定义、必要记录；核对能力后选字段／派生字段。可筛选不等于可分组／作时间轴。
- 类型合规仍须语义正确：起止属同一事件；不得因“创建时间”是日期就代替业务开始时间。

### 数据与计算依赖

- 使用真实记录。命令新建表按 [Mock](mock-data.md) 准备、验收；复制表按 [Table 副本保护](table.md) 保持范围，不因检查补样例；既有表不得为命中造数或放宽条件。
- 缺指标／动态判断字段时，在授权内按 [Formula / Lookup](field-formula-lookup.md) 建等价计算；创建、回读后配置。查询／重命名不授权改辅助字段。

## 视图决策

只改已有视图该项及其影响，不重设计整组。

### 选择视图用途与类型

同表视图共享数据、各存配置。类型值见[创建协议](../references/view-commands.md#创建名称的传参约束)。表格用于逐行查看、分组、排序；看板（`kanban`）按状态或类别分列；画册展示带图卡片；日历按业务日期安排；甘特用于排期或工期。

保留指定类型，如分组表格不得改看板。设计只选有用切面；单项修改不增视图。收集表单转 [Form](form.md)。

### 将用户要求和名称映射到目标配置

按开工清单映射、逐项回读；时间、主体、状态范围均转筛选。“未归还”等状态覆盖全部目标状态或原始事实；“今年”等同样须动态；“优先／最早／最新”须配正确的排序字段、优先级和方向；指定卡片或排期须内容符合要求。相关 Dashboard 组件也核对范围。

各项分别配置，筛选按原逻辑组合。完整清单须集合相等、保序。计算、关联、权限辅助字段可留底表，但不自动显示；未要求改列就保留现有配置。

分组、聚合不得互代（如类别分组与各类别金额合计）。按[汇总边界](../references/view-display.md#分组与汇总边界)执行；指定位置不支持就标未完成，不得用 Dashboard 替代。

### 名称与修改范围

- 自定名称须准确；配置不符时在授权内修正，不得改名取消要求。
- 指定名称保留原意；已有名称不授权改其他配置或底表。仅重命名时普通文案只改名；新名增加业务含义时，要求配置则同改，否则说明差异、澄清。不得修复／宣称完成范围外项。

### 筛选与业务分组

- 筛选、状态、统计、Dashboard 共用口径，按[完整候选集](../references/shared-statistics-rules.md)定保留、排除、未知。优先筛原始事实；只能筛公式文案时须覆盖全集。
- 源字段映射类别时，分组字段须输出类别，不得用源值逐项分组或沿用不符名称。
- 按要求限范围；仅明确要求才清空全部筛选。确定目标后按协议请求；合并、提交见 Reference。

### 持久视图的相对时间

遇[相对时间](../references/shared-statistics-rules.md#时间范围与动态配置)，区分动态范围和固定历史区间；相关对象用同一业务日期、范围。按[日期协议](../references/shared-filter-tuple.md#datetime--created_at--updated_at)表达；需要辅助字段时先完成计算依赖。无法等价则受阻；不得省略时间、改固定日期、加未授权自动化。

本轮创建的“本周视图”须持续滚动；只靠名称或当前记录恰在本周都不算。未要求、未创建该名称时不强制新增。

## 执行与提交

创建后还有查询、修改、删除时，执行[阶段验收](build-system.md#连续操作的阶段验收)：创建通过再继续并核对最终数据；单项也适用。

### 读取视图

按需读身份、保存配置、记录并分别说明范围；按本页规则解释。取证见[配置与记录读取](../references/view-display.md#配置回读与记录读取)。

### 创建与配置

1. 完成决策、依赖，定目标、通过条件。
2. 新建按生命周期创建并记返回对象；修改复用目标。非表格按开工规则显式配置，按类型、目标补展示项。
3. 保存筛选、分组、排序、展示，保留未涉及项。不得以临时查询代替、绕 raw API、交付替代物或只在答复描述。
4. 每步回读；连续修改按用户顺序验收，后续覆盖／删除不得掩错。复用有效证据，不重复成功写入。

### 重命名

按名称范围重命名；同时改配置则执行创建与配置流程。

### 删除视图

按生命周期删除唯一目标。不得删底表、字段、记录（含 Mock）、其他视图。目标不存在／不唯一则报告，不得替代。

## 回读验收

### 按操作验收

- 读取：对象符合请求，结论不超范围。创建／改配置／复用：表、视图身份、类型正确，一致性通过，未涉及项不变。
- 仅重命名：同一视图名称合规、原配置保持，含义沿用名称决策。删除：目标移除，受影响对象可读、语义一致；按[生命周期协议](../references/view-commands.md#结果未知时的读取)区分缺失、读取失败。

### 名称、配置与记录一致性

核验三层证据；数据表按 View 协议、Dashboard 组件按其[协议](../references/dashboard-view.md#返回结构与配置回读)取证：

- 名称符合目标，差异按名称范围处理。
- 保存配置兑现集合、分组、顺序、展示，不只看非空；动态范围核对条件、依赖表达式；完整清单按字段身份核对集合、顺序。
- 记录按保存范围、顺序核对；临时查询不算持久证据；分别查命中、排除项；适用时做候选子类对账。

Mock 支撑的视图逐个回读应出现记录；配置存在不等于可用。

按 [Record 解析](../references/record-read.md#解析返回与完整分页) 消费记录：先读保存条件，再按视图取数；临时 `--filter-json` 正确不证明保存配置正确。

- **空配置**：要求存在但保存值为空才算未实现；要求清空则已空即通过。
- **组合筛选**：用记录／授权样例核对命中、时间不符、状态不符；待办类查全部已结束状态，不得只排一种成功状态。Unknown 不得归入待办／终态。
- **样本不足／空结果**：区分无命中、全命中、底表无记录，说明缺失证据。配置正确且范围为空可交付；要求实测却无证据则受阻。底表按创建／复制范围验收。
- **时间轴**：有记录则抽样确认结束不早于开始；无样本说明未实测。样例符合不替代保存配置证据。

### 新表视图枚举与逐项检查

1. **范围**：本轮新建表（含复制表）写完后逐表枚举全部视图；单独建表或未要求筛选、分组也执行。原样复制按副本保护核对，不改造。
2. **对象**：本轮创建、修改、重命名或明确交付并保留的视图；已删除者用删除证据。枚举不授权改未涉及的默认视图。
3. **验收**：按 View 范围取配置、记录并验收。复用有效最终证据；后续写入使其失效则重读。

### 对照目标验收与交付

汇报视图、保存配置、记录证据及空结果、未实测、受阻项。仅必需项全为 `verified` 才声明完成；命令／名称正确不代表生效。

## 异常恢复

| 问题 | 恢复与边界 |
|---|---|
| 展示配置被拒 | 按[展示协议](../references/view-display.md#配置校验与恢复)核对能力、请求；需改类型／字段范围就重做决策，不用近似字段 |
| 筛选请求失败 | 按[筛选协议](../references/view-filter.md#类型约束与易错点)修正；业务集合不变 |
| 相对时间无法直接表达 | 回到动态范围决策，判断等价方案 |
| 配置已存但记录范围不符 | 回到筛选、时间决策，核对底表事实、计算依赖；只修已定位项 |
| 创建、更新、删除结果未知 | 按[生命周期恢复](../references/view-commands.md#结果未知时的读取)确认状态，再做未完成操作 |

所有路径共用[恢复预算](../SKILL.md#异常恢复与停止条件)，换路径不重置。仍失败时报告缺失的证据，继续做不依赖该项的工作。
