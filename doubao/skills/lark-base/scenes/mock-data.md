# 示例与测试数据

## 开工必读

- **逐表写 5～10 条。** 覆盖本轮每张新业务表：主档、表单底表、收集表、事件表、Workflow 下游表；以后才产数的表也先写 5 条以上。下游受上游状态限制时调整上游分布；空表、指定数量、保留来源从用户要求。
- **逐字段填值。** 群组、附件、超链接、地理位置、条码、签字、公式、查找、系统字段除外。阶段字段（实际完成时间、审核人、审核意见）把状态设为该阶段后再填；“待处理”视图可暂无命中。
- **逐列逐条填人员。** 非必填、多人、后补列也适用。在写记录的同一条 `+record-batch-create` 里给值；后加的人员或关联列加完立刻回填已有记录；交付前逐表数空值。未指定人员时用当前用户（`lark-cli contact +get-user --jq '.data.user.open_id'`），同行多个人员列可都填当前用户。
- **统一操作时刻。** 已完成、已发生的时间不得晚于该时刻；计划、预约可在未来。状态与日期一致，已逾期的截止日必须在过去。
- **单选、多选只写已有选项。** 先用 `+field-list` 读取；缺少状态／类别时先用 `+field-update` 增加，否则整批报 `not_found`。
- **先定源值再推结果。** 从同行字段推出数量×单价、合格与否、是否通过、等级；身份证号第 7–14 位对应出生日期，第 17 位奇数为男、偶数为女；姓名文本与人员字段同指一人；不手写公式、查找引用。
- **同行及关联一致。** `当前库存 ≥ 安全库存` 不得写“库存不足”，`截止日 > 今天` 不得写“已逾期”；备注写“迟到”的考勤结果不是“正常”，已到货数量不超过订购数量；完成不晚于今天，结束不早于开始。待处理记录填措施、负责人；改变关联主档状态时同步主档。
- **删除验证记录。** 交付前删除名称含“测试”“占位”的记录。
- **全量回读。** 用 `+record-list` 回读每表，按下表核对，答复逐表写记录数。

| 交付前核对 | 通过条件 |
|---|---|
| 条数 | 每张本轮新建表（含表单底表、下游表）不少于 5 条，或符合用户指定 |
| 人员字段 | 每个可写人员列每条都有值 |
| 时间 | 已发生事件不晚于本轮操作时刻 |
| 状态与内容 | 状态和对应的日期、措施、关联记录状态一致 |
| 测试记录 | 没有残留测试或占位记录 |

## 任务导航

仅处理本轮新业务表或明确授权的测试数据。既有表新增视图、字段、公式、表单、权限不触发补数据；既有记录的未知事实保持待核实，不得补造。

| 任务 | 流程与交接 |
|---|---|
| 新业务表 | 按 [Table 新表清单](table.md#数据与展示目标)逐表登记，再执行本页全部流程 |
| 已授权 Mock／测试数据 | 限授权范围执行；普通写入交 Record，不补造既有事实 |
| 写后新增字段，或改变状态、条件、人员／关联来源 | 重判[字段义务](#字段完整性与数据保护)，补应填、保留应空，再做[人员与业务核验](#人员与业务核验)；不得加记录改变指定数量 |
| 表单底表 | 执行[表单场景交接](#表单场景交接)；Form 检查题目并完成适用的真实提交，本页核验全部样例 |
| Workflow 下游表 | 执行[下游样例与实际执行交接](workflow.md#下游样例与实际执行交接)；本页核验数量和业务一致性 |

## 前置检查

- 按 [Table 数据目标](table.md#数据与展示目标)取得完整新表清单和真实对象；确认用户数据、指定数量、空表或数量 0 要求。
- 用 `+field-list` 枚举字段、选项、可写 `user` 字段，确认主档、关联、人员依赖；按 [Record 字段协议](../references/record-cell-values.md#只读字段与附件边界)核对边界，不写只读派生字段。
- 固定操作时刻（日期、时间、Base 时区），据此推导相对日期和状态；同日但晚于当前时刻也属未来。
- 表单数据先读 [Form 样例准备](form.md#表单样例准备)；Workflow 下游表先定[样例与实际执行路径](workflow.md#下游样例与实际执行交接)。

## 数据决策

### 数据来源与数量

按用户原话和表来源逐表登记目标；用户明确的范围、条数、比例、保真要求优先：

| 目标 | 条件 | 写入与通过条件 |
|---|---|---|
| 空模板 | “空模板／空表／不填示例／数量 0”或仅复制结构 | 每表最终 `record_count=0`；不得插入后删除以验证公式、表单、工作流。缺少运行证据则记录；仅获授权后在测试副本验证 |
| 指定数量 | 给出条数及比例／状态分布 | 严格等于指定数并验各组换算数；真实提交、流程实测计入总量，只补差额；不为默认下限或分支覆盖增行 |
| 保留来源 | 要求原样复制、导入或写入真实明细，且未授权虚构 | 按来源和范围对账；不为凑 5 条混入 Mock，不补造未知值 |
| 默认样例 | 本轮新表，无上述限制和真实明细 | 每表不少于 5 条，一般 5～10 条，并通过全量核验 |

空模板范围覆盖相关新表（含后建收集表、下游表）；跨 Scene 不重置。冲突时先澄清；改变时更新目标、证据，不自行恢复默认。

默认目标覆盖所有适用新表，不得只写主表、脚本所列、最初计划表；“正式表保持干净”不构成空表要求。下游 Mock 不得冒充 Workflow 运行。

### 字段完整性与数据保护

逐行按状态、表单条件判定应填、应空；除表列情形外每字段均填值：

| 义务 | 生成与验收 |
|---|---|
| 必需源事实、当前状态必填 | 填业务一致的值；业务主体、已分派负责人不因未处理而豁免 |
| 阶段字段 | 到达该阶段后再填实际时间、实际处理人等；状态不得与值矛盾 |
| 系统派生 | 不写；回读结果及空值是否符合源事实 |
| 条件未命中的表单题目 | 按真实路径省略；隐藏不要求清空历史答案，不改既有数据 |
| 一般可选字段 | 除群组、附件、超链接、地理位置、条码、签字外仍填合理样例；“非必填”不构成整列留空理由 |

不得仅凭字段名判断整列或只统计非空。撤销职责不触发补值；未知既有事实不得补造。条件要求附件时准备真实有效附件；上传受阻则留缺口，不造值、不降为选填。

不得使用真实身份证号、手机号、邮箱等敏感个人信息；演示用明显虚构的值。

### 人员字段填值

- 逐条核验可写 `user` 字段；应填真实 ID，单／多人、必填／非必填均不豁免。区分业务主体、计划负责人、实际执行人：按分派填计划负责人；实际审批／验收人仅在事件发生后填。
  语义不明先核实；未指定可整列填当前用户。
- 用户给出人员时沿用；否则按[当前用户身份与人员值协议](../references/record-cell-values.md#当前用户身份与人员值)查询一次本人并复用。
  姓名、人员字段、主档同指一实体；同一 ID 不配多个虚构姓名。查询失败走[人员与业务数据恢复](#人员与业务数据恢复)，不得空值交付。全部填本人不证明多角色隔离已实测。
- 后增可写人员字段时重查全部 Mock，补应填、保留应空并回读。默认填值仅限本页样例，不补既有事实；Workflow 接收人执行[职责接收人规则](workflow.md#接收人字段与时间条件)。

### 业务不变量与分支覆盖

先列约束再生成，至少检查：

- **实体**：稳定实体的主档属性一致；变化时用生效日期、历史表或备注表达，不让随机 Mock 暗含冲突。
- **时间**：开始≤结束，先行≤后续；到期日来自明确起算日和周期，不用录入／创建时间等相近字段替代；口径不明则新增明确字段或询问用户。
- **状态与时间（双向）**：核对当前、计划、实际日期。完成须有实际完成时间；计划日期已过而未完成时标逾期、延期或写明例外；逾期／过期／超时的日期不得在未来。日期派生的状态，逐条拿记录日期与固定当前日期比较后反推，不先挑状态再配日期。
- **金额与数量**：已付≤应付，未付额与付款状态一致，数量、单价、小计、总额守恒；取消／作废不得冒充履约。“已满／已完成”等数量断言须有达到阈值的关联记录，不能是 0 或远低于阈值。
- **关联**：流水引用的实体须存在于主档；同一实体跨记录复用同一主档，不以重复文本制造隐式关联；关联对端与本行描述同指一事。
- **手填与派生**：状态、等级、标记须与公式、查找、汇总一致；区间先定下限再定上限。备注／摘要中的结算、完成、附件留存须来自源事实；不得删描述代替必需材料。
- **资源**：同一人员、资源的占用不得冲突；按回读的全部取值逐个检查。
- **分支**：覆盖 Formula、View、Dashboard、Workflow、表单必填校验所需的正常、边界、异常分支，不为覆盖制造矛盾。

## 生成与写入

1. 复用既定目标、日期、字段、身份。空模板、保留来源不生成 Mock；指定数量／比例先分组，后续不得改变总量或分布。
2. 先生成稳定主档，再生成引用它的流水；同一实体属性只在主档定义一次。
3. 先生成源字段，再推导状态、金额、日期；不得独立随机互相约束的字段。
4. 逐表落实目标；普通写入执行 [Record 创建与更新](record.md#创建与更新)，值格式执行 [CellValue 协议](../references/record-cell-values.md)；表单、Workflow 走各自交接。
5. 写后执行[回读验收](#回读验收)，记录数量、人员、业务证据；失败进入[异常恢复](#异常恢复)。

### 表单场景交接

表单底表 Mock 生成前，按 [Form 样例准备](form.md#表单样例准备)核对题目、类型、必填、选项、附件、显示条件，按真实路径准备。
完整执行 [Form 新底表样例与真实提交验收](form.md#新底表样例与真实提交验收)中的真实提交、计数和不可用处理，再回本页验全部样例；普通写入不得替代。

## 回读验收

### 数量与字段核验

逐表用 `+record-list` 完整分页回读全部 Mock 和依赖字段，逐字段核对，不抽查。
按 [Record 输出解析](../references/record-read.md#解析返回与完整分页)读取记录文件或 JSON 行矩阵；manifest、`head`、stdout 行数均不能证明验收。

按 [Table 实际创建集合](table.md#逐表数据证据)对账，再核对每表目标、实测数、分布、字段完整性。默认不足只补差额；空模板有记录、指定数量超量、保留来源混入 Mock 均失败，不得套用“至少 5 条”。

### 人员与业务核验

逐条逐列回读人员：补应填缺失，修正应空有值；核对全部适用不变量和资源取值。
每个条件字段记录“适用记录数、应填缺失的 record_id、必须为空却有值的 record_id、例外依据”。不得用整列多数非空代替单元格验收；未导出列／未读完页是证据缺失，不是真实空值。

表、字段、状态改变会使原核验失效；重查全部受影响样例、关联对象和结果，不只查新增／修改记录。复验限本轮数据及受影响依赖，不改无关记录；修正后的范围不得窄于首次。

### 专项结果与阶段交接

数据支撑下列对象时逐个验收实际结果：

| 对象 | 结果验收 |
|---|---|
| Formula / Lookup | [计算结果与样例分支](field-formula-lookup.md#共同证据与完成条件) |
| View | [实际筛选记录](view.md#名称配置与记录一致性) |
| Dashboard | [图表数据与统计口径](dashboard.md#交付健康门禁写任务必做) |
| Workflow | [条件命中检查](workflow.md#条件类型验收)；运行证据按[下游样例与实际执行交接](workflow.md#下游样例与实际执行交接)区分 |
| Form | [真实提交及底表记录](form.md#新底表样例与真实提交验收) |

创建后继续查询、修改或删除表单／视图时，执行[连续操作阶段验收](build-system.md#连续操作的阶段验收)：创建通过后继续，全部结束后核对最终保留数据。

### 逐表报告

答复逐表列数据来源、目标和 `record_count` 实测值：默认样例注明是否≥5，空模板核对 0，指定数量按要求核对，保留来源按范围对账。同时报告人员与业务一致性、专项证据和未完成项；样例写入不算表单提交或 Workflow 实测成功。

## 异常恢复

### 人员与业务数据恢复

- 身份查询失败时按实际错误恢复，不得空值交付；人员漏填或后增人员列时补齐全部适用 Mock 并回读，保留业务应空值。
- 发现矛盾时补源记录或修正手填值后回读；不得改公式迁就数据或只改展示状态掩盖上游错误。按[人员与业务核验](#人员与业务核验)原范围复验。

### 写入与专项恢复

命令失败、部分写入或结果未知时，按 [Record 恢复](record.md#异常恢复)及命令协议确认实际状态。
表单提交不可用执行 [Form 专项处理](form.md#新底表样例与真实提交验收)；Workflow 回填不可行执行[下游样例交接](workflow.md#下游样例与实际执行交接)。修复后重做适用验收。
