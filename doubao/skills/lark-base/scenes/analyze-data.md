# Base 数据分析

<a id="适用范围与对象关系"></a>

本页定口径、核验结论、回答和交接产物。取数、计算、查询核验、回退、截断、精度复算归 [Query](query.md)，本页不另设重试；持久对象由对应 Scene 创建验收。

## 开工必读

- **类别词先对照全部枚举。** 类别词（某几类内容、某类售后、某种状态）先用 `+field-list` 或 SQL 读出字段全部取值，定好纳入、排除再写 SQL，答复说明排除了哪些。比率类结论同时给绝对量。
- **先定统计边界。** 只问两类时第三类不算，“已完成”不含已取消；边界写进 SQL 的 WHERE。修饰对象的词（看过的、买过的、在职的、已交付的）也是边界：读状态类字段全部取值，对得上就写进 WHERE 并在答复说明，对不上就说明没筛。
- **Top N、合计、平均用 SQL 在完整数据上算。** 排名用 `ORDER BY 指标 DESC LIMIT N+1`（最少、后 N 用 `ASC`），答复照抄前 N 行；第 N+1 行与第 N 行指标相同时写明并列条数，按表内原顺序取。不先查长列表再自己挑。
- **状态按原值描述。** “已取消”不写成“被拒绝”，“待处理”不写成“未完成”；合并时写明合并了哪些原值。
- **数字照抄本轮查询结果。** 合计、占比、区间、名单不心算、不估算；自定义分档用 SQL `CASE WHEN` 打档后 `GROUP BY` 档位出个数、合计、平均，答复和写回都取这条结果。
- **复合结论逐条件判定。** “满意度最低且售后最多”先分别找两个极值，同一对象才这样说，否则分开说。
- **答复前对数。** 名称、数量、排名顺序逐个对照查询结果。写“最高、最低、唯一、全表第一”前用同一指标 `ORDER BY` 首行核对；“哪个 X 最多／更多”按绝对量下结论；比率作补充时写明分子、分母。
- **结果要落进 Base 时写回用户给的源 Base**（汇总表或视图），不新建 Base。

## 任务导航与交付选择

| 用户目标 | 处理路径 |
|---|---|
| 查某条记录、筛原始记录、金额最大的 10 条订单 | Record，不走本页 |
| 读取或解释已有图表 | Dashboard，按组件实际配置、结果和模板解释 |
| 计数、求和、平均、分组、聚合 TopN、占比、趋势、对比、多表（含简单单表） | 本页定口径，Query 走 Context → SQL |
| 分析并画图、建看板 | 先分析，再交 Dashboard 建图并回读；明确要图即是交付要求，不需“长期”二字 |
| 只在会话回答、画临时图或不改 Base | 不建持久对象；做不到时说明限制 |
| 持续查看、保存结果或动态计算 | 按下文产物交接选对象 |
| 同时搭系统、分析、出图 | Build-system 登记全部子目标，本页只承接独立分析 |

只问趋势、占比、对比不等于要建图，纯分析默认只读。对象搭建中的辅助计算由原对象 Scene 调 Query 并验收，不经本页。写查询前读[共享统计规则](../references/shared-statistics-rules.md#任务口径与核对)“任务口径与核对”，把总体、条件、分组、指标、时间落到查询表达式；读过分类不代表计算已用其筛选条件。

## 业务问题与分析口径

1. 列出必答问题与对象；有明确依据就复用，不把简单问题扩成全面探索。
2. 业务概念绑定到真实表和源字段，不凭简称猜；区分应收/实收、预算/实际、业务日期/创建日期。字段名相近、样例值合理不证明语义等价。
3. 记录指标、粒度、实体键、时间与筛选范围、分母、权重、空值、舍入，并标明每项来自用户要求、可信业务定义还是显式假设，规则见共享统计规则。
4. 问总耗时、总成本等总量，且同一对象有同单位、互补可加、不重复的多个环节时，取各环节之和并说明构成；只问某环节取单项；并行或替代口径不相加。
5. 各指标分别固定总体与粒度；会改变结论的歧义先澄清。可信业务定义可纠正模型推断，与用户明确的公式或范围冲突时，确认前不覆盖。
6. 主查询、补查、复算、回答用同一口径（来源字段、日期、范围、粒度、分母、权重）；覆盖不足、异常值、结果意外不静默改口径。默认用全量符合条件数据；敏感性对照按共享规则“口径保持与对照”单列。
7. 排除主体、判定短缺的阈值必须来自用户要求或可信业务定义，自提假设只作分列对照。数量少的主体仍在候选集，不排除、不标缺数据；覆盖缺失与业务低值分开说。
8. 只用实际记录；除用户明确要求或业务定义规定估算外，不插补、外推、年化、构造数据。要预测时先答事实，只预测指定目标，分列模型、假设、不确定性；风险排序不等于未来概率；先按组预测再求和与先汇总再预测不互相冒称。
9. 供需、闲置、短缺结论须对应同范围的实际需求与可用资源；单一库存量或申请排名不证明缺口。字段不足只答已证实部分。

## 查询编排与停止条件

把问题、口径、交付需求、工具限制交给 [Query](query.md#前置检查与结构准备)，结构不足先取结构；Query 返回结果和来源、覆盖、计算、限制证据。

- 优先一条主查询，同范围、兼容粒度的指标、派生计算、核验合并或复用；不硬限调用次数，也不为省调用强拼难核验、低效 SQL。
- 只在必答项缺证据、有具体矛盾或新的可检验疑点时补查，先明确验证什么；不重复拉 Context、不扫无关数据。
- 结果完整覆盖所需范围与粒度时，Query 可用程序确定性算差额、比例、排序并留输入与公式；不借此导出原始记录，也恢复不了聚合值丢失的精度。
- 主结果与必要核验完成即停，不固定追加 DSL、完整复算、解释性统计。覆盖率、最大日期、空值注明表与过滤范围；局部缺口不推出全表缺失、停业、需求下降或数据生成方式。

## 结论核验

Query 完成查询核验后，本页核对每个交付数字与断言有可复核证据、未扩范围、未换口径；接口成功不等于分析正确。

| 核验项 | 要求 |
|---|---|
| 来源与角色 | 答案列追溯到查询表达式和源字段；别名、列位置、数值合理不算证据；预算与实际、当前与基期、分子与分母角色一致 |
| 数字有依据 | 解读数字也来自已核验结果或确定性计算。分类数量、名单、合计取自同一筛选结果并保留完整条件；不用 `A AND B` 的数量描述 `A`。必答项缺证据就补查或报限制；非必答项省略，不改用定性措辞保留未证明结论 |
| 粒度 | 一个分组对应一个实体；总额守恒、JOIN 行数不变不证明分组和 TopN 正确，合并同名实体会改变排名。复用 Query 实体键核验，不重扫 |
| 断言 | 比较、排序、趋势写明同口径的对象、范围、指标、两侧值，用确定性计算判定，不从另一指标、局部样本或展示值推断。复合结论各条件按完整对比或可信阈值判定，同一对象同时满足才成立，否则分开说明。排名、并列、舍入按共享规则“数值展示与精确计算”；用户明确要求时才按舍入值比较 |
| 汇总语义 | 检查指标可加性、分母、权重 |
| 状态计数 | 总数、已完成、未完成各自绑定结果，仅状态互斥且覆盖总体时可相减；Unknown 不自动归未完成 |
| 表达 | 表格、图表、正文复用已验证断言，区分事实、推断、预测、未知原因。榜单取按目标指标排序后的结果，逐项核对名称、数值、顺序，不凭目测另列排名。展示值相同不证明原值相等；精度不足不强判并列或阈值 |

## 产物交接与一致性

搭建或修改 Base 时，用户要的分组、排序、排名、汇总或最终查看方式就是交付物：

| 展示目标 | 交给 | 回读证据 |
|---|---|---|
| 原始记录持续筛选、分组、排序 | View | 保存的范围、分组、排序与实际记录 |
| 聚合分组值、排名或图形 | Dashboard；明确要汇总表时交 Table / Record | 保存配置与实际计算结果或结果记录 |
| 表内长期动态计算 | Formula / Lookup | 保存定义及代表记录的计算结果 |

- 汇总表含随源数据变化的值时按 [Field 动态计算规则](field.md#字段类型选择含公式关联)，不把一次性算值写进普通字段。
- 交接数据源、范围、粒度、指标，接收对象 Scene 的回读证据。SQL 不代替对象状态验收，Markdown 表格不代替要求的持久对象。
- 按共享规则“查询、产物与回答一致性”逐项对齐。不通过时交对应 Scene 定向修复并复验；仍不一致就把该项标为未完成。

## 回答与未完成项

- 逐项回答必答问题，直接给分组明细、总数、占比或关键结论，不只贴链接。未要求不加分类汇总；要求再分类时先定规则再算。
- 输出可读业务值；内部 ID、关联键只用于定位，明确索取才给。缺可读字段交 Query 按原工具限制补取，不猜、不绕过 SQL-only。
- 说明必要的范围、口径、单位、舍入、限制；用了失败回退或精度复算如实说明，不冒称 SQL 成功。
- 有效空集报无数据；失败、缺失、截断、覆盖不明不当 0、不下全局结论；列出未答问题、受阻原因、缺失证据，只交付已验证部分。
- 有持久对象时同报位置、验收结果、未完成项；分析完成不等于搭建完成。后续记录定位交 Query 关系回查，写入仍按原授权。
- 回答顺序：口径 → 结果明细 → 有证据的解读 → 限制与产物位置；简单问题一句话，不为填模板追加查询。必答占比缺完整分母证据时补证据或标未完成，不用部分结果凑成 100%。
