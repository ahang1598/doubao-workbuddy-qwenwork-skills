# Base 与资源管理

业务建模和跨模块编排交 [系统搭建](build-system.md)；各模块的操作和验收在各自 Scene。

| 从零新建 Base | [创建与复制决策](#创建与复制决策) → [创建与复制的顺序](#创建与复制的顺序) |
| 复制 Base 或一张表 | 先按 [复制对象与范围](#复制对象与范围) 判断层级；表进入 [Table](table.md) |

## 前置检查

- 操作已有对象时，先按定位流程取得可信 Base 和对象 ID；本任务已取得且仍有效的返回直接复用。新建 Base 不需要目标 Base；复制前先确认源对象。
- 写入前登记用户目标、预期结果和需保留的对象。复制时核对源内容和复制范围；目录维护时核对目标位置、需保留的子资源和依赖。处理额外子资源须核对授权，不扩大删除范围。
- 已授权且目标清楚的操作直接执行；目标不唯一或要求冲突时再澄清。查询模板、定位、读取只产生读取结果，不授权创建、改造或删除。

## 创建与复制决策

### 复制对象与范围

- 复制层级以用户的宾语为准：“数据表、表、某张表”进入 Table；“整个 Base、多维表格文件”，或明确要独立流转、隔离时，复制独立 Base。“给我一个副本”不改变层级，不用新 Base 冒充表副本。
- 独立流转包括发给别人参考、单独分享、隔离沙箱和交接；实际分享仍按主入口授权执行。
- 默认保留结构和内容；用户明确只要结构时才排除内容。
- 用户没明确要求改造时，不合并交付物，不修改复制件。原样复制、导入和仅结构复制按源内容和约定范围交付；后续改造单独登记，先验收副本再继续。

### 新建来源与初始表

| 目标 | 创建前决策 |
|---|---|
| 定义业务表/字段或从零搭建 | 一次指定初始表名/全部业务字段；先定记录粒度、业务主字段；见 [Table](table.md#记录粒度与初始结构)、[Field](field.md) |
| 初始表承接本轮表单 | 按 [Form](form.md#专用收集表与业务表)定初始字段/题目职责，不得套业务表或平台占位结构 |
| 明确空白/平台默认 | 可用默认初始结构；输入、主字段限制见[创建协议](../references/base-commands.md#创建-base-与初始表) |
| 公开模板 | 按下述模板流程选可复制 Base 模板，再按范围复制 |

字段名只写业务含义，去掉原文章节/条目序号前缀（如“一、”“1.”）；分节用表单题序、字段描述或视图。

### 新 Base 的交付计划

产生新 Base 前，进入 [系统搭建](build-system.md) 确定关系、模块和依赖顺序，按 [交付类别规则](#模块验收项) 登记类别目标和保真例外。系统搭建已确认的清单直接复用，只补缺项。更新时区或普通读取不进入系统搭建。

类别不足时按 [入口选型](build-system.md#新建-base别只交一堆表) 补方案。首次写入前，在清单里列出“类别 → 业务用途 → 所属表或模块 → 验收方式”，写明还缺哪一类；不能只写“丰富视图”或留作最终建议。补类别不授权擅自启用自动化、配置权限或对外分享。

## 执行与管理

每步完成后按回读验收核对；多步操作的顺序沿用主入口。

### 定位已有 Base

缺可信坐标时按线索选路；参数、输入限制、ID 映射见[解析协议](../references/base-resolve.md)。

| 线索 | 路径 |
|---|---|
| URL/分享链接 | `+url-resolve`；按返回对象继续。Base/多维表格分享链接不得交文档工具打开 |
| 标题/关键词/不确定名称 | `+title-resolve`；长标题取最有区分度的短关键词，多候选先消歧 |
| 最近访问、owner、创建人、时间、类型 | `drive +search`；取得 URL/token 后按形态解析或读取 Base |
| 文档 `<bitable>`/`<base_refer>` | 按[嵌入标签映射](../references/base-resolve.md#文档嵌入标签)取 Base、表、视图坐标 |

仍无法定位且用户不是要新建时，请用户明确目标 Base，不用创建对象代替定位。定位出错按 [定位与权限恢复](#定位与权限恢复) 处理。

### 读取 Base

本体用 `+base-get`（[协议](../references/base-commands.md#读取-base)）；结构进 [Table](table.md)，记录进 [Record](record.md)，独立分析进 [Analyze-data](analyze-data.md) 组织 Query 的 Context/SQL。仅需表/记录时不查资源目录。

### 创建与复制的顺序

1. 按方案调用 `+base-create`；复制 Base/公开模板用 `+base-copy`（[复制协议](../references/base-commands.md#复制-base)）；表复制进 [Table](table.md#复制数据表)。
2. 保存真实返回，按 [按操作核对证据](#按操作核对证据) 确认新对象和初始结构；异常进入 [创建结果未知与重复对象](#创建结果未知与重复对象)。
3. 接续初始表进入 Table，按 [数据目标](table.md#数据与展示目标) 处理用户数据、Mock 或复制内容；需要计算和关系时进入 [Field](field.md)、[Formula／Lookup](field-formula-lookup.md)；专用收集表进入 Form。
4. 按 [模块编排](build-system.md#模块编排与阶段验收) 完成已选模块，再汇总类别验收证据。

### 导入文件并返回 Base

1. 确认源文件（Excel、CSV、`.base`）、导入目标和保真要求；会产生新 Base 时先完成交付计划，已有计划直接复用。导入交给 Drive 的 `+import`，按 [Drive 导入协议](../../lark-drive/references/lark-drive-import.md) 选择 Base 类型与目标；不用手工建表、写记录代替导入。
2. 导入未完成或结果未知时，按同一导入任务续查状态，遵守恢复预算；确认失败前不重新导入。确认完成并取得可信坐标后，再读结构和记录。
3. 核对对象、字段类型和数据。用户没要求原样保留类型、且字段类型与语义不匹配时，交 [Field 更新流程](field.md#更新字段) 评估转换与数据保护；只有确认安全时才修正，并回读结构和受影响数据；否则保留现状并报告缺口。
4. 把导入和字段验收证据交回原主责。产生新 Base 时继续完成已登记的模块和类别验收；原样导入按保真例外交付，不重建或补写已导入的内容。

### 公开模板检索与创建

没有已有对象锚点时，“有没有适合项目管理的模板”进入公开模板查询；“帮我建一个 CRM 多维表格”“找个 OKR 模板照着做”可检索模板后接续创建。用户提供 Base／Wiki 链接、Base token，或说“我之前的／我的模板／最近访问的”时，先按 [定位已有 Base](#定位已有-base) 处理。

1. 检索/分页按[模板协议](../references/base-templates.md)：仅大类方向先 `+template-categories` 后 `+template-list`；有业务词用 `+template-search`。分类不贴切、无合适结果或跨类目时用关键词补查；不必全调。
2. 按名称、介绍、场景选择；依协议区分可复制/仅预览应用模板。仅查询则交候选/理由；不可复制须说明。
3. 创建意图/目标明确时按创建决策及顺序执行；命名参数、缺省行为沿用模板协议。

### 更新 Base 时区

对已定位 Base 执行 `+base-update`（[协议](../references/base-commands.md#更新-base-时区)）。目标明确时不为比较当前值增加写前读取；不得以创建/复制代替。

### 查询与管理资源目录

- 直接管理资源用 `+base-block-list`；按类型转 Table、Dashboard、Workflow 或文档工具读内容。目录 ID/内容 ID 见[协议](../references/base-resources.md#资源-id-与返回)。
- 创建/移动/重命名/删除按确认目标调用对应目录命令；创建后需配内容则进模块。业务表 schema 先按 Table 创建路径准备，再处理目录位置。

## 回读验收

对照用户目标、本次写入和受影响对象完成下表，复用仍有效的读取证据；完成态见 [主入口](../SKILL.md#执行验收与交付)。名称正确、写命令成功或对象出现在列表中，都不能代替业务验收。

### 按操作核对证据

| 操作 | 通过条件 |
|---|---|
| 定位/读取 | 解析、所需 `+base-get`/模块结果对应目标；多候选不猜；报告可信标识/实际引用 |
| 查模板 | 真实查询所得；理由符合介绍；说明复制限制 |
| 新建 | `+base-get` 验对象，`+table-list`、逐表 `+field-list` 对照方案；业务表须有 Table/Field 字段、关系及适用记录/Mock/Form 结果；空白/默认按约定，默认占位表不算业务表 |
| 复制 Base | 回读表、字段、范围内记录/模块并与源/范围对账；副本独立、源保留、保真未被补写/改造破坏。表副本按 [Table 验收](table.md#按操作回读与验收) |
| 导入 | 任务确认完成；以 Base/Table/Field/Record 对账目标、结构、范围内数据、源、保真；字段类型符合语义/原样要求；修正须有 Field 结构/数据证据，任务完成响应不能代替内容验收 |
| 更新时区 | 按[响应协议](../references/base-commands.md#响应)取证；独立读取等于目标才通过。仅有写响应则报“已接受更新、缺独立回读证据”，不标回读通过 |
| 读/建目录资源 | `+base-block-list` 的对象、类型、名称、位置达标；需内容者另取模块证据 |
| 移动/改名 | 回读原对象，确认位置、所需相对顺序/新名称；移动文件夹后所需子资源仍在其下 |
| 删除 | 完整读取目标位置，确认对象移除、保留资源仍在；读取失败不算成功；底层影响按模块核对 |

产生 Base 后报告真实标识/可用链接；访问状况以实际读取为准；可选授权信息按[身份与返回](../references/base-commands.md#身份与返回)处理。

<a id="模块验收项"></a>

### 新 Base 的交付类别

本轮通过新建、复制或导入产生新 Base 时，把类别覆盖加入验收清单。普通新建及没有保真限制的新 Base 至少覆盖 **3 类**页面级模块或视图，用户已点明表名和字段也适用；原样复制、导入的例外见下文。原话含“只要／只需要这些／不要其他／不要新增入口”等排除性表述时按限定交付，不扩建；只列出要做的操作（如“建表并按 X 排序、改名”）不算限定，仍补齐 3 类。记录数为 0 的空模板约束另按 Mock 判断，不被丰富度覆盖。

| 交付物 | 计类 |
|---|---|
| 数据表 | 任意张合计 1 类 |
| 非表格视图 | 按实际 `type`：`kanban`、`gallery`、`calendar`、`gantt` 各 1 类 |
| 仪表盘、表单、工作流、高级权限 | 各 1 类；表单视图并入表单 |
| `grid` 视图 | 筛选、排序、分组、字段显隐、改名均不加类 |
| 空壳/未通过对应模块验收 | 不计 |

逐表 `+view-list` 验类型；取 `+dashboard-block-list`/`+form-list`/`+workflow-list`/`+role-list` 及对应 Scene 配置/结果证据。

- 原清单保存真实 ID、所属 Base/表、实际类型、用途、验收状态。只计最终存在且通过者：`{table, kanban, dashboard}`=3，`{table, permission}`=2；3 表、3 `grid`、3 Dashboard 组件均非 3 类。
- 完成/删除模块即更新集合；`pending`、写后未验、已删、空壳不计。独立 HTML 报告、会话图表、后续建议不计；表单视图/对应表单共算一类。
- 用户要求的产物已达 3 类即可，无需额外补建。没有范围限制或保真例外且不足时，回到交付计划补有业务用途的缺失类别并复验；不反复增加同类对象，不扩大权限、分享或通知来补数。
- 原样复制/导入且源不足 3 类：保持副本，报告实际类别及保真冲突；仅要副本则按复制目标交付，不称完整搭建通过。
- 最终列实际模块/视图及各视图 `type`，汇总去重集合/数量并接收模块验收摘要；列明缺类、未完成模块、证据限制。

## 异常恢复

参数错误按对应 Reference；次数/停止条件见[通用恢复](../SKILL.md#异常恢复与停止条件)。恢复后回原验收项，不得缩减目标。

### 创建结果未知与重复对象

Base 命令失败按[未知结果](../references/base-commands.md#部分成功与未知结果)取证；目录写入按[目录恢复](../references/base-resources.md#读取范围与状态恢复)核对。有可信 ID 直接读；否则结合写前候选、创建时间、目标结构、返回识别，不凭同名认领。

| 状态 | 恢复 |
|---|---|
| 对象/本次配置完成 | 复用验收，不重复写 |
| Base/目录已建，仅初始结构/后续模块未完 | 原对象只补缺步，不重建完成项 |
| 确认创建未生效 | 在恢复预算内重试原目标 |
| 读取失败、仍未知/不唯一 | 保留证据并报未验证；必要时请用户明确；不改名重建/操作同名候选 |
| 误建重复 Base | 保留已完成配置和数据的对象；确认多余对象无须保留的数据、配置、依赖后按主入口授权清理；无法确认先询问 |

### 定位与权限恢复

- Token/Wiki 报错：按 [ID/参数错误协议](../references/base-resolve.md#返回-id-与错误)核输入。
- 其他工具读取 Base 链接报无权限、需授权或无法读取时，先回到本页 `+url-resolve` 和模块读取路径；只有 lark-base 读取本身也不可用时，才进入授权处理。
- 目录读取缺少 `base:block:read` 时，先判断是否真的需要目录：普通结构和记录直接进入 Table／Record，独立分析进入 Analyze-data；只有必须读取或管理目录资源且无替代路径时，才处理该权限。Context／SQL 自身的权限拒绝仍须处理授权。
- 明确无权访问 Base 时，按实际错误和平台授权入口处理，沿用当前用户身份，不盲目重试，不换身份绕过。
