# 数据表

## 开工必读
- 建表用 `+table-create --name "<表名>" --fields '[...]'`；只有 `--name`，`--table-name` 属于 `+base-create`。
- `--fields` 每项只能含 `name`、`type` 及该类型的 `style`／`options`／`link_table`。先按 [Field](field.md#字段决策) 选型，再套 [字段 JSON 模板](../references/table-commands.md#字段-json-模板)；不得写 `property`、`formatter`、`default_value`、`date`。
- 建表后按 [Formula / Lookup](field-formula-lookup.md) 用 `+field-create` 添加公式、查找字段。
- 用 `--jq '.data.table.id'` 取返回；解析失败先用 `+table-list` 确认是否已建，不得重复创建。

## 任务导航
命令参数和返回结构见 [数据表生命周期命令](../references/table-commands.md)；各路径先做前置检查。

| 目标 | 路径/依赖 |
|---|---|
| 列出、查看 | 读取数据表；不加载建表、Mock、表单规则 |
| 创建业务表 | 决策→创建；字段进入 [Field](field.md)，初始数据进入 [Mock](mock-data.md) |
| 重命名、删除 | 对应小节；删除时保留非目标对象 |
| 复制表 | 复制范围→复制数据表；复制文件进 Base |

新 Base 或多模块搭建按系统搭建组织依赖；只有新 Base 才按 Base 交付类别覆盖。

## 前置检查
- 按 [Base 定位](base.md#定位已有-base) 确认真实 `base_token`，已有表使用可信 `table_id`；缺 ID 或目标不唯一时用 `+table-list` / `+table-get` 定位。
- 写前记录目标名、预期状态和保留对象。复制前读取源表及所需结构和记录；删除前核对同类型唯一目标及受影响的关联、视图等依赖；只读本次相关对象。
- 已授权且目标、范围清楚时直接执行；只读请求不授权写入。只在目标有歧义或要求冲突时澄清；确认参数按调用协议处理。

## 建表与复制决策
### 记录粒度与初始结构
先确定一条记录代表什么、业务主字段是什么、需要哪些关联；再为每个初始字段登记 `字段名 → 业务语义 → type → style／单位／多值 → 来源`，按 [Field 字段决策](field.md#字段决策)确定定义，`--fields` 批量创建不跳过。初始字段输入和主字段约束见 [创建字段协议](../references/table-commands.md#创建时的初始字段)。新表用于表单时，创建前按 [Form 的专用收集表判断](form.md#专用收集表与业务表) 确定它是业务表还是专用收集表，并划分字段和题目的创建职责。

提交初始字段前，按[主字段类型约束](../references/field-config.md#主字段类型)核对候选的类型、样式，将符合业务语义与支持范围的字段放在首项；公式主字段按创建协议分步配置。

用户明确指定行维度、列维度或交叉单元格结构时，按指定结构建表；规范化主档或明细表作为补充，核心交付仍须满足指定结构。完整系统搭建同时执行 [Build-system 结构与派生保真](build-system.md#结构与派生保真)。

### 复制范围与副本保护
按 [Base 的复制粒度规则](base.md#操作约束) 确认对象。复制数据表默认保留结构和记录；只有用户明确只要结构才排除记录。除非用户明确要求改造副本，不得合并交付物或修改复制件。

### 数据与展示目标
逐张登记本轮新建业务表：初始表、追加表、收集表、Workflow 下游表，不得因主表完成而漏表。每获新 `table_id` 就更新同一清单：`table_id、用途、数据来源、目标数量与分布或例外依据、实际数量、业务约束、未完成项`。
写前确定 [数据目标](mock-data.md#数据来源与数量)；Form、Workflow 后建的表继承适用范围，不得丢失空模板或指定数量要求，不另建脱离原交付项的账本。

| 表的来源与目标 | 数据要求 |
|---|---|
| 本轮新建的业务表（含 Base 初始表、已有 Base 内新表） | 保留用户的空表、来源、指定数量要求；其余**每表不少于 5 条（一般 5~10 条）**。建表时登记，源字段、关联、表单题目就绪后写入，按实际成功项累计数量 |
| 原样复制且含记录 | 以源表、复制范围为准；不得为达到新表样例数补写副本 |
| 只复制结构 | 副本保持 0 记录，不自动补样例；用户另有填充或改造要求时照办 |
| 仅读取、重命名、维护既有表 | 不自动补样例 |

搭建或修改 Base 的同一请求要求按字段筛选、分组、排序、排名、汇总或“最后这样看”时，该展示结构就是交付物，必须创建并配置持久 View、Dashboard 或汇总表。分析查询和答复里的表格只用于计算；仅纯查询且未要求改造 Base 可只返回分析结果。

## 执行与维护
连续操作按用户顺序执行；后续缺少必需 ID 时定向读取，复制异步未终态、部分成功／结果未知、删除安全检查或用户明确要求核验时按对应流程处理。

### 读取数据表
用 `+table-list` 列出或定位，需详情用 `+table-get`；按返回解析判定读取是否完整。记录内容进 Record，独立统计分析进 Analyze-data，取数、计算交 Query。

### 创建数据表
1. 按初始结构执行 `+table-create`；新 Base 初始表承接 Base 创建流程的结果，不得另建替代表；取得真实 `table_id` 和字段结构后处理依赖。
2. 先准备表和源字段，再按 Field、Formula / Lookup 补关联和计算依赖；专用收集表业务字段按 Form 题目路径准备。
3. 按数据与展示目标准备记录和所需视图、表单或看板；普通写入进 Record，用户明确要求的真实提交进 [Form](form.md#新底表样例与真实提交条件)。

### 重命名数据表
对已定位原表执行 `+table-update`；不得以新建、复制、替换表实现重命名。

### 复制数据表
按范围执行 `+table-copy`，参数映射和等待方式见 [复制协议](../references/table-commands.md#复制数据表)；等待复制完成并取得副本 ID 后，再按要求改造。

### 删除数据表
仅对已定位且获授权目标执行 `+table-delete`。目标不存在、数量不足、无法唯一定位时报告缺口；不得删除字段、记录、视图或整个 Base 替代删表。

## 完成与交付
各操作的完成条件如下；异步、结果未知和删除按对应协议处理。

### 按操作完成
| 操作 | 通过条件 |
|---|---|
| 列出、读取 | 表与目标 Base、范围一致；按读取完整性协议读全后才能声明全量或目标不存在 |
| 创建 | 取得真实 `table_id` 和初始字段，供后续数据、计算、视图使用 |
| 重命名 | 目标表名称按要求更新，继续沿用原 `table_id` |
| 复制结构及记录 | 等待复制完成，取得任务返回的副本 ID 和范围 |
| 只复制结构 | 等待复制完成，取得任务返回的副本 ID；不自动补样例 |
| 删除 | 完整表列表无目标 ID，或有该 ID 明确不存在的证据；权限拒绝、网络错误不能证明成功；受影响的保留对象仍可读且语义达标 |

复制整个 Base 文件由 Base 交付。

<a id="逐表数据证据"></a>

### 逐表数据结果
用实际创建结果维护本轮业务表清单；已有 Base 不把他人新增表作为本轮 Mock 目标。漏登的表先补回清单和数据目标。
对照数据目标，按 Record 的实际成功项逐表累计 `record_count`、完成情况和例外依据；部分成功或结果未知时按 Record 恢复。复制表沿用复制范围。

### 新表视图
只把用户要求或系统计划登记的视图交 [View](view.md)；不因新建或复制表而枚举全部视图，复制件仍遵守副本保护。

## 异常恢复
- 命令失败或结果未知时，按 [创建与维护恢复](../references/table-commands.md#创建与维护恢复) 或同文件的复制状态与恢复核对已生效步骤；结果确定前不得推进依赖操作。
- 表已建但字段、数据、展示未达标时，只修失败项并复验；不得重建整表或删除应保留数据。缺少可信证据时报告受阻。
- 修复次数和停止条件按主入口；仍失败则报告该项受阻，继续不依赖它的工作。
