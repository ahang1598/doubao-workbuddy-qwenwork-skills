# 数据表

## 开工必读
- 建表用 `+table-create --name "<表名>" --fields '[...]'`；只有 `--name`，`--table-name` 属于 `+base-create`。
- `--fields` 每项只能含 `name`、`type` 及该类型的 `style`／`options`／`link_table`。写第一张表前读 [字段 JSON 模板](../references/table-commands.md#字段-json-模板)，照抄后只换名称、选项；不得写 `property`、`formatter`、`default_value`、`date`。电话、邮箱、网址写 `{"type":"text","style":{"type":"phone"}}`；顶层写 `"type":"phone"`／`"email"`／`"url"` 不报错，但会存成普通文本。
- 建表后按 [Formula / Lookup](field-formula-lookup.md) 用 `+field-create` 添加公式、查找字段。
- 用 `--jq '.data.table.id'` 取返回；解析失败先用 `+table-list` 确认是否已建，不得重复创建。

## 任务导航
命令参数和返回结构见 [数据表生命周期命令](../references/table-commands.md)；各路径先做前置检查。

| 目标 | 路径/依赖 |
|---|---|
| 列出、查看 | 读取数据表；不加载建表、Mock、表单规则 |
| 创建业务表 | 决策→创建；字段进入 [Field](field.md)，初始数据进入 [Mock](mock-data.md) |
| 重命名、删除 | 对应小节；删除时保留非目标对象 |
| 复制表 | 复制范围→复制数据表；复制文件进 Base |

新 Base 或多模块搭建按系统搭建组织依赖；只有新 Base 才按 Base 验收类别覆盖。

## 前置检查
- 按 [Base 定位](base.md#定位已有-base) 确认真实 `base_token`，已有表使用可信 `table_id`；缺 ID 或目标不唯一时用 `+table-list` / `+table-get` 定位。
- 写前记录目标名、预期状态和保留对象。复制前读取源表及所需结构和记录；删除前核对同类型唯一目标及受影响的关联、视图等依赖；只读本次相关对象。
- 已授权且目标、范围清楚时直接执行；只读请求不授权写入。只在目标有歧义或要求冲突时澄清；确认参数按调用协议处理。

## 建表与复制决策
### 记录粒度与初始结构
先确定一条记录代表什么、业务主字段是什么、需要哪些关联。字段类型和语义由 Field 决定，初始字段输入和主字段约束见 [创建字段协议](../references/table-commands.md#创建时的初始字段)。新表用于表单时，创建前按 [Form 的专用收集表判断](form.md#专用收集表与业务表) 确定它是业务表还是专用收集表，并划分字段和题目的创建职责。

### 复制范围与副本保护
按 [Base 的复制粒度规则](base.md#操作约束) 确认对象。复制数据表默认保留结构和记录；只有用户明确只要结构才排除记录。除非用户明确要求改造副本，不得合并交付物或修改复制件。

### 数据与展示目标
逐张登记本轮新建业务表：初始表、追加表、收集表、Workflow 下游表，不得因主表完成而漏表。每获新 `table_id` 就更新同一清单：`table_id、用途、数据来源、目标数量与分布或例外依据、实际数量、业务约束、未完成项`。
写前确定 [数据目标](mock-data.md#数据来源与数量)；Form、Workflow 后建的表继承适用范围，不得丢失空模板或指定数量要求，不另建脱离原验收项的账本。

| 表的来源与目标 | 数据要求 |
|---|---|
| 本轮新建的业务表（含 Base 初始表、已有 Base 内新表） | 保留用户的空表、来源、指定数量要求；其余**每表不少于 5 条（一般 5~10 条）**。建表时登记，源字段、关联、表单题目就绪后写入并回读，交付前达标 |
| 原样复制且含记录 | 以源表、复制范围为准；不得为达到新表样例数补写副本 |
| 只复制结构 | 副本保持 0 记录，不自动补样例；用户另有填充或改造要求时照办 |
| 仅读取、重命名、维护既有表 | 不自动补样例 |

搭建或修改 Base 的同一请求要求按字段筛选、分组、排序、排名、汇总或“最后这样看”时，该展示结构就是交付物，必须创建并回读持久 View、Dashboard 或汇总表。分析查询和答复里的表格只用于计算和验证；仅纯查询且未要求改造 Base 可只返回分析结果。

## 执行与维护
每项操作后回读。连续操作按用户顺序逐项验收，后续修改或删除不得掩盖前一步错误；还须执行 [阶段验收](build-system.md#连续操作的阶段验收) 并回读最终保留表。有效证据直接复用。

### 读取数据表
用 `+table-list` 列出或定位，需详情用 `+table-get`；按返回解析判定读取是否完整。记录内容进 Record，独立统计分析进 Analyze-data，取数、计算交 Query。

### 创建数据表
1. 按初始结构执行 `+table-create`；新 Base 初始表承接 Base 创建流程的结果，不得另建替代表；取得真实表和字段结构后再处理依赖。
2. 先准备表和源字段，再按 Field、Formula / Lookup 补关联和计算依赖；专用收集表业务字段按 Form 题目路径准备。
3. 按数据与展示目标准备记录和所需视图、表单或看板；普通写入进 Record，表单样例的真实提交进 [Form](form.md#新底表样例与真实提交验收)。

### 重命名数据表
对已定位原表执行 `+table-update`；不得以新建、复制、替换表实现重命名。

### 复制数据表
按范围执行 `+table-copy`，参数映射和等待方式见 [复制协议](../references/table-commands.md#复制数据表)；先验收副本，再按要求改造。

### 删除数据表
仅对已定位且获授权目标执行 `+table-delete`。目标不存在、数量不足、无法唯一定位时报告缺口；不得删除字段、记录、视图或整个 Base 替代删表。

## 回读验收
对照原话和受影响依赖完成下表和新表检查；写成功不等于业务验收。

### 按操作回读与验收
| 操作 | 通过条件 |
|---|---|
| 列出、读取 | 表与目标 Base、范围一致；按读取完整性协议读全后才能声明全量或目标不存在 |
| 创建 | 回读目标 Base 的表和字段，核对真实 `table_id`、名称、主字段、字段结构、关联，再验收适用的数据、计算、视图 |
| 重命名 | 按原 `table_id` 回读；ID、所属 Base 不变，名称达标 |
| 复制结构及记录 | 复制完成；在原 `base_token` 下回读源表与副本，确认 ID 不同；按范围对账字段、记录数、内容；源表未被本次操作改变 |
| 只复制结构 | 回读源表与副本；同 Base 下 ID 不同、结构达标、副本记录数为 0、源表符合保留要求 |
| 删除 | 完整表列表无目标 ID，或有该 ID 明确不存在的证据；权限拒绝、网络错误不能证明成功；受影响的保留对象仍可读且语义达标 |

复制整个 Base 文件由 Base 验收。

### 逐表数据证据
用最终 `+table-list` 和创建回执对账完整清单，不得只查写过记录的表。新 Base 核对全部业务表；已有 Base 只核对本轮确认创建的表和受影响依赖，不把他人新增表作为本轮 Mock 目标。漏登的表先补回清单和数据目标再验收。
对照数据目标逐表记录 `record_count` 实测值、通过情况、例外依据；复制表同时保留源表与副本的数量证据。计数按 Record 分页协议；新业务表的数量门槛、Mock 全量质量检查和逐表报告格式按 [Mock 验收](mock-data.md#回读验收)。

### 新表视图验收
每张本轮新表（创建或复制）均执行 [View 新表视图枚举与逐项检查](view.md#新表视图枚举与逐项检查)，复制件仍遵守副本保护。

## 异常恢复
- 命令失败或结果未知时，按 [创建与维护恢复](../references/table-commands.md#创建与维护恢复) 或同文件的复制状态与恢复核对已生效步骤；结果确定前不得推进依赖操作。
- 表已建但字段、数据、展示未达标时，只修失败项并复验；不得重建整表或删除应保留数据。缺少可信证据时报告受阻。
- 修复次数和停止条件按主入口；仍失败则报告该项受阻，继续不依赖它的工作。
