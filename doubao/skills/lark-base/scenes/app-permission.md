# BaseApp 权限

用于 App 的角色、页面 / 按钮、表 / 记录 / 字段权限及成员、分享、申请。页面与组件搭建见 [AppMode](app-mode.md)。BaseApp 使用 `app_token`、`+app-role-*`；普通 Base 使用 `base_token`、`+role-*`，顶层配置不可混用。

## 任务导航

- 仅查看：读对象边界，调用 list / get，按 [返回结构](../references/lark-base-app-role-config.md#角色命令的返回结构)解析，不补建角色。
- 配置角色：读对象边界、角色流程；按新建 / 更新分流，写后验收。JSON 与接口恢复见 [CLI 权限协议](../references/lark-base-app-role-config.md)。
- 仅改成员、分享或申请：读对象边界后直接按 [成员、分享授权和申请](../references/lark-base-app-role-config.md#成员分享授权和申请)操作，不加载角色生成规则。模板先读 [模板边界](../references/lark-base-app-role-config.md#模板-app-的权限边界)；申请须有用户明确意图。

## 开工必读：操作对象边界

- 用户给出的 App 链接 / `app_token` 是唯一目标。禁止用 `drive +search`、`+workspace-entity-list` 或名称、结构相似度寻找其他 App / Base；同账号的同名副本也不得读取角色作参考或写入。全程写入、回读、最终链接必须绑定该目标，关联 Base 仅从其 `+app-get.ref` 获取。
- 新建和更新均按以下步骤取页面、表与字段全集，不能从角色 Get（含系统角色）推断全集，它只返回显式配置：
  1. `+app-get --app-token <app_token>`：`pages[].name` 为页面全集；`ref` 为 `base_token -> table_name[]`，一个 App 可关联多个 Base，value 是可配置的**表名**，不是 ID。
  2. 每个 Base 用 `+base-get --base-token <base_token>` 取名称，作为 `base_data_rule_map` 外层 key。
  3. 用 `+table-list --base-token <base_token>` 取该 Base 完整表列表，将每个引用表名与 `tables[].name` **精确且唯一匹配**。保留 `base_token + table_id + name`，内层 key 用表名，`+field-list` 用对应 ID；跨 Base 同名表不串用 ID。缺失或多匹配时停止受影响配置，不能跳过后继续集合授权、既有表保护或默认档变更。未被 `ref` 引用的表不可写，否则整请求报 `table_not_exist`（800004993）。详见 [ref 表名解析](../references/base-app/app-commands.md#ref-表名解析)。
- `app_token` 不能当 `base_token`：误传给 `+base-get` 会返回 App（URL 含 `/app/`），传给 `+table-list` 会得到 `tables: []`，不代表目标无表。
- 目标删除（`note has been deleted`，1002）、无权限或 not found 时停止，不换对象；回复目标 token、原始错误及“未做任何修改”，请用户确认链接或恢复。
- 若已写错对象，如实报告对象与改动，不在其他 App 继续“修正”；回到原目标补做。临时 / 误建 App 不能作为交付物，交付另一 App 须先获明确授权。

## 角色流程

0. 扫描完整 query：明确要求配置的角色、或有独立页面 / 数据 / 按钮 / 功能约束的具名人群，分别配置为独立角色；约束可在页面描述或禁止句中，不限「权限」段落。仅使用人群、工作流审批 / 通知对象且无独立 App 权限约束时，不补建。不得合并角色约束或用 Editor / Reader 代替业务角色。
1. `+app-role-list --app-token <app_token>` 定位新建 / 更新，以 `role_id`、`role_type` 为准，不能仅凭显示名判类型。更新或删除前用 `+app-role-get` 读完整源配置；只创建 `custom_role`，系统角色不可删除，Reader 不得获得编辑、增删或按钮操作能力。除非原话明确点名并要求调整，系统角色 / 默认角色 / 普通用户的所有权限及成员冻结。
2. **先抽权限要求，再生成 JSON**：扫描全文，先在现有任务清单按「角色 × 页面 / 表」记录原句、对象、动作、行范围、字段、可新增、可删除及依据；不只看「权限」段，也不把展示 / 流程背景带入。每项依据标为原话、平台默认、写前源档或已确认能力降级。对象结构只用于定位和验证映射，不创造授权。先完成两轴取证、表档和增删判定，再处理行 / 列；JSON 只从该清单和对象回读生成，不重新从搭建全文补权限。需要新授权或条件时先补清单，不能从 JSON 反推需求；不另建平行清单。更新只改触及项。
3. 按 [角色 JSON](../references/lark-base-app-role-config.md#角色-json-与字段取值)调用 create / update；角色 CRUD 不改成员。写后按「验收与交付」回读。

## 新建角色

### 授权证据与两轴判定

**页面与表独立取证：未提页面，全部已有页默认可阅读；提了页面范围，只按页面原话，不从表权限反推。页面可见不产生底表授权。**

按角色流程中的权限清单逐项取证：保留原话精确片段、实际对象 ID 和映射回读来源；页面零表述记默认基线，页面用 Page ID，表用 `base_token + table_id`。JSON、写入成功和模型答复均不是授权证据；可沿用本会话明确确认的设置。

**开放数据前逐项取证**：`base_data_rule_map` 每个非 `no_perm` 表条目及其动作必须回指表 / 记录授权原句、字段最低承载，或更新未触及的源权限。集合 / 业务对象展开须证明原句确实涵盖该表数据与动作；同域、同名、关联字段、页面取数或岗位职责本身都不新增授权。行范围只能限制已授权表，不能以「只开本人记录」补出表权。

**提交入口先分承载**：独立表单的打开 / 提交、页面上的表单按钮不要求给 App 角色开放底表；「只能提交表单、不能看后台」不能翻成该表 `edit + add`，也不用虚假空筛选模拟后台无权。明确要求在 App 列表 / 数据表新增记录时才配置相应数据新增能力；若另有查看自己记录要求，按该原句独立配置阅读范围。纯权限任务不以表无权限断言表单不可提交。

- 集合授权（「全部页面」「所有表只读」「其他表只读」）只展开该句指向的目标 App 全集。业务名称可不等于完整表名，但须用结构 / 字段证明承载关系；有精确匹配优先使用，同名须核对 Base，不扩至旧 Base、上下游或同业务域对象。
- 对象与范围分开：「自己负责客户的订单」授权订单，客户只限定订单范围，不开放客户表。
- 页面取数 / 组件引用、关联 / 查找字段、工作流、建表清单、岗位职责和页面规划均不产生跨轴授权。字段原句属于表轴，只推导字段所在表的最低承载，不开放关联表。

| 每个角色对该轴的原话 | 新建规则 |
|---|---|
| 明确页面、表、记录或字段授权，含集合 | 只展开该轴获授权对象，按动作 / 范围配置，其余既有对象最终 `no_perm` |
| 授权并限范围：「可编辑订单，但只能改本人」 | 先确认订单授权，再限制行；不能把本人筛选复制到其他表并据此补权 |
| 全集无权限 | 无授权项，仅保留原话明确放行的例外 |
| 页面零表述，或只提未来新增页默认 | 全部已有页逐个显式 `read_only + all_visible`；未来默认另配 |
| 表零表述，或只提未来新增表默认 | 既有表不开放，不因页面可见或取数补权；未来默认另配 |
| 纯负向：「某页不可见」「某表不许改」 | 点名页 `no_perm`、表 `read_only`；禁改是最低只读依据，不产生编辑权，其余未授权对象不开放 |

页面是否零表述须**逐角色判断**：搭建背景不是该角色的页面权限，其他角色的页面限制不收束本角色。两个集合确定后才生成 `page_rule_map`、`base_data_rule_map` 与行列规则；角色身份不扩大或缩小明确范围。映射不唯一或授权缺失时保留缺口，不用业务常识补齐。

| 需求与结构 | 结果 |
|---|---|
| 客服只要求编辑本人订单；已有订单、售后、统计三页，未提页面权限 | 三页均可读、按钮全可见；仅订单表按本人编辑，其余表无权 |
| 客服仅看售后页、仅编辑本人订单；售后页引用退换货表 | 售后页可读、订单按本人编辑；退换货表无权，处理客服字段 / 分派流程不构成授权 |
| 主播只看直播排期页、自己的业绩页，销售明细表只读 | 仅点名页可读、销售明细表只读；不补开直播排期表 / 月度业绩表 |
| 区域主管只看任务概览、风险洞察，禁止复制，无表权限原句 | 两页可读、复制关闭；不为图表取数开放任务 / 风险 / 里程碑表 |

**页面取数冲突单独处理**：授权页引用未授权表时，不补权、不删除原限制。完整搭建可在原需求内改用已授权数据；纯权限任务保留页面 / 组件，说明缺少授权的数据能力。额外表须先获明确授权；管理员取数成功不证明业务角色有权，缺口未解不能宣称完整可用。

### 表档与动作

按**角色 × 表**的动作定 `perm`；「全量 / 完整」只定覆盖范围，「本人 / 派给自己」只定归属，不把阅读升级为编辑。

| 数据动作 | 表档与范围 |
|---|---|
| 只有查看 / 浏览 / 查询 / 完整查看（含派给自己的记录） | `read_only`、`record_operations: []`，范围用 `read_member_scope` / `read_filter_rule_group` |
| 明确新增 / 录入 / 添加 / 删除 / 编辑 / 修改 / 处理 / 更新记录，或管理 / 维护表数据 | `edit`，范围用 `edit_member_scope` / `edit_filter_rule_group`，增删按下表 |
| 可看全部、只能改本人 | `edit`、本人编辑范围、`other_record_all_read: true` |

同角色同表的**后置具体动作优先**：「专利表只让看、能新增但不能删」为 `edit + ["add"]`，不附加提交后不可修改。只有另行明确「已有记录不可修改 / 提交后只读」才用字段 `create` 等限制；覆盖不扩至其他对象或取消禁删。

角色名、表名中的「管理」不算动作；职责与明确只读限定并存时按只读。「看全量项目、不能删除数据表」仍只读，删表是结构能力，不等于禁删记录。字段只读或部分记录只读不降低已有编辑表档。

#### 新建表规则的记录增删

先定表档，再**独立逐表判定可新增、可删除**；修改记录随 `edit`，不写入数组。在现有任务清单分别记「允许（默认 / 原话）」或「禁止（原句）」。新建可编辑表先取 `["add","delete"]`，只按下表去掉项目；不能因「只处理本人记录」、只编辑指定字段或角色身份主动写 `[]`。更新未触及增删时保留源值，不按新建默认重置。

| 条件 | 记录操作 |
|---|---|
| `read_only` / `no_perm` | 只读 `[]`；无权不带记录子规则 |
| `edit`，无下述限制 | `["add","delete"]` |
| 明确禁新增 / 删除，或「仅改已有记录」排除新增 | 去掉对应项，均禁止为 `[]` |
| 只 / 仅限定动作清单且含新增 / 录入 / 添加 / 删除 | 仅保留清单项，如「只能看和新增」为 `["add"]`，「只看和删除」为 `["delete"]` |
| 只限档位、字段、本人范围：「只能编辑表 / A 字段 / 自己记录」 | 不关闭增删，仍用默认 |

非排他表述「能看能新增 / 可以录入 / 本人记录可处理」不禁止删除。角色级禁删记录未指定表时逐张可访问表判断；单表禁令不扩散，删表禁令不转成记录开关。**「别人不能改 / 删」只限范围外记录**：范围外只读 / 无权限即不能删除，不因此关闭整表删除或新增；本人范围与字段白名单均不是增删禁令。

### 记录范围

**生成行规则只读取已抽出的权限要求**：先按主体和用途剔除页面 / 列表「只显示、只取、筛选」等展示条件；同表、相邻段落或先后出现不产生继承，背景条件不进入能力降级或创建人兜底。只有原话限定角色 / 成员可查看或操作哪些记录，或明确把页面筛选指定为该角色记录范围，才记入权限清单并生成 scope / filter。生成时逐项回查该原句，不能再用搭建段落补条件。新建已授权表未提行范围时为所有记录；更新未触及时保留源范围。

| 原话 | 行权限处理 |
|---|---|
| 专利页只显示有效专利；助理能新增、不能删 | `edit + record_operations: ["add"]`，不加有效期 / 状态筛选 |
| 助理只能查看有效专利，失效专利不可见 | `read_only`，按角色原话配置可读范围 |

**再核实范围能否实现**：原话限定本人 / 本团队 / 指定条件内记录时，先核实字段类型与身份映射。能用合法 `edit_member_scope` / `edit_filter_rule_group` 表达的编辑范围必须随 `edit` 一并提交，不能先开放后补筛选。人员字段或结果为人员的公式 / 查找引用字段须有业务归属证据，不能仅凭名字把派单人等当作实际处理人。

**已确认不可实现的条件允许降级**：字段类型不支持，或必须跨表 / 按成员组织属性动态映射而现有结构无法表达时，允许忽略该条件，或用创建人保守兜底；保留原话授权的表档及其余可实现限制，不因该能力缺口强制降为只读 / 无权限。说明忽略了哪个条件或采用了什么近似，不声称原范围已精确实现。此例外只适用于本轮新要求的不可实现条件，不能删除源配置已有的筛选或其他禁止项。尚未查清映射、名称歧义、参数拼错或临时接口失败不等于能力不支持，确认前不先开放无范围编辑。

`other_record_all_read` 仍须以有效编辑范围为前提。例如「本人派单可处理、别人只读」但已确认分派映射无法表达：可保留 `edit` 并忽略该条件，此时不写 `other_record_all_read`；或配置创建人编辑范围加 `other_record_all_read: true`，明确这是创建人兜底。能表达原范围时必须按原范围配置；明确授权全表编辑时可省略编辑范围。

查看范围用读规则、编辑范围用编辑规则；全量阅读省略读范围。JSON 见 [记录协议](../references/lark-base-app-role-config.md#记录范围行权限)。

- 「与自己 / 本人相关」未点字段：用 `*_member_scope` 勾选创建人及该表全部人员类字段，不用筛选拼接替代；「自己负责 / 派给自己」只选对应人员字段，也可用等价的当前访问者 `contains`。
- 编辑范围外默认隐藏，`other_record_all_read: false`；明确「看全部、改本人 / 其余记录只读」才为 `true`。维护 / 处理 / 负责不意味着其余可读，「只能看和改自己的」同时限看、改。
- 「看不到别人 / 别的团队的某字段」限别人记录的可读范围，不能用整列隐藏或只读代替；多表逐表判断。
- 筛选锚点普通字段至少 `read`，允许新增时至少 `create`，不主动升 `edit`；类型例外见 [筛选字段约束](../references/permission-role-config.md#筛选字段的-field_perms-权限约束)。

### 字段范围

按**承载表 / 点名字段 / 其余字段**三层定目标。字段指令本身授权最低必要承载，不因未独立授权表而跳过；整表禁令优先。隐藏主字段不可实现时说明边界，不用整表隐藏代替。字段名单必须以字段 / 列为对象，不能把本人记录限制当字段白名单；新建仅有字段只读 / 隐藏要求时，表最低 `read_only`、增删 `[]`；「其余字段正常」不是全表编辑授权，不从 Editor / 模板继承编辑。更新保留未触及源档。

| 句式 | 表档 | 点名字段 | 其余字段 |
|---|---|---|---|
| 表 / 记录编辑 +「A 不可见、B 只读」 | `edit` | A `no_perm`，B `read` | 普通可写字段 `edit` |
| 仅「看不到 A」 | `read_only` | A `no_perm` | `read` |
| 仅「A 不许改」 | `read_only` | A `read` | `read` |
| 仅「A、B 可编辑 / 只能编辑 A、B」 | `edit` | A、B `edit` | 默认 `read`，不得 `edit` |
| 仅「能看 / 只能看 A、B」 | `read_only` | A、B `read` | `no_perm`，不因缺少「只」而全表开放 |
| 明确其余字段只读 / 不可见 | 按原话 | 按原话 | 按原话 |

优先级：明确其余档位 > 独立表 / 记录编辑基准 > 字段名单推导。混合正向字段按**最低正向档降一档**定其余，如 A 编辑、B 只读 → 其余无权；独立隐藏字段不参与计算。主字段恒只读，类型上限见 [字段协议](../references/lark-base-app-role-config.md#字段范围列权限)。承载升档只限本表，不扩大关联表、记录范围、增删、页面或复制。

字段模式按 [协议合法组合](../references/lark-base-app-role-config.md#字段范围列权限)选择：无自定义要求、字段随表且无扩展限制才用 `all_edit` / `all_read`；要求开启 / 保留自定义、字段不随表或有差异 / 扩展限制时用 `specify`。**表可编辑、全部字段只读必须为 `edit + specify`，完整字段逐个 `read`**，不能用 `edit + all_read`、整表降档或字段升档绕过；若同时明确禁止自定义，说明冲突并停止该项，不试写。仅「全部字段可见」不等于只读，不据此降字段档或开启自定义。

生成 `specify` 前取字段全集，逐个列出应可见 / 可写字段，仅省略应无权的普通字段。编辑白名单的其余普通字段未明档位时，**生成默认 `read`，但现有合法 `read` / `no_perm` 均可**，不补开已隐藏字段；明确可读不能隐藏，明确不可见不能开放。

切换到 `specify` 要保留仍可见附件的下载能力及源选项能力；省略扩展列表会改变能力。只关闭明确禁止下载的附件，不借字段隐藏收窄其他附件。

### 未触及维度与默认档

- **复制**：新建未提时显式 `base_rule_map.copy: true`；仅明确禁止复制应用内容 / 批量复制记录时为 `false`。只读、隐藏敏感字段、外部身份不自动禁复制；角色级禁导出按能力边界说明，不替换为禁复制。更新未触及保留源值。
- **按钮**：可读页默认 `all_visible`；仅显式带「数据 / 内容 / 记录」中心词（如「能看数据就够了」）才收为 `none_visible`；「看看 / 可阅读」不收束按钮。
- **默认档必填**：未提未来默认时，`default_page_rule: {"perm":"no_perm","button_perm":"deny"}`、`default_table_rule: {"perm":"no_perm","record_operations":[]}`；明确未来要求则按原话。
- 默认档实际覆盖**所有未显式配置的既有及未来对象**，Get 不展开。先按两轴配置既有对象，未来默认会额外开放的既有对象逐个显式 `no_perm`；表轴无授权且默认表无权时 `base_data_rule_map: {}`。例如只要求「新增页无权、新增表可读」：已有页全量显式可读，已有表全量显式无权，未来才走默认。

## 修改既有角色

以 Get 源配置为未触及项的保留依据，按原话 delta 更新；页面、按钮、表、字段、行范围、增删和复制均不主动扩缩，不套新建默认。不能删除显式规则恢复跟随默认，不试空对象 / `null`，说明此限制。

- 撤权显式写目标表 `no_perm`；省略表项、删除本地表项或空 `base_data_rule_map` 均不撤权。提交的页 / 表条目**整条覆盖**，完整保留仍适用的子规则和扩展列表，见 [更新协议](../references/lark-base-app-role-config.md#更新请求与覆盖语义)。
- 字段追加（「再允许看 B / 把 A 隐藏」）保留其余源档；完整重设（「改成只能看 A、B」）将其余普通字段收为无权。例外：原表无权、本轮要求隐藏 A，最低升只读、A 无权、其余普通字段可读；已有编辑 / 只读不因局部隐藏降档。
- 切换到 `specify` 时按目标状态列全仍可见 / 可写字段，不能仅发目标字段；源为 `specify` 且未要求退出时保持，即使全部同档。字段正向授权使表升档时，不能让其余源无权 / 只读字段随表升级。保留源记录规则、增删及扩展能力；只读表不能带编辑范围。
- **只改未来默认**：先由 App 全集、显式规则和源默认算出每个既有对象的有效权限，为缺少显式规则的对象补等价源规则，再改默认；不重写已有显式项，除非用户同时要求改它。无法完整还原源规则则停止该项并说明缺口。

## 验收与交付

每次写后回读，成功回执不能代替验收。按 [返回结构](../references/lark-base-app-role-config.md#角色命令的返回结构)和 [序列化约定](../references/lark-base-app-role-config.md#回读与报错)解析本目标 App：角色配置 list / get，删除 list，成员变更 member-list。

| 检查 | 必须确认 |
|---|---|
| 角色齐全与目标一致 | 对照完整 query 的角色逐个 list 定位、get，缺失补建后再验；解析未完成不能据空输出补建。最终链接、写入与回读的 `app_token` 一致，其他 App / Base 的回读不算 |
| 授权双向对账 | 写前证据每项落实；再由页面 / `ref` 表全集反查每个有效非 `no_perm` 对象的角色、ID、动作、范围依据。零页面表述回指默认基线，字段承载回指字段原句，更新未触及回指源配置；逐个核每个开放表及动作的依据，不接受用行范围、页面取数或表单提交解释额外表权 |
| 记录增删独立验收 | 对照清单逐表核 add / delete：新建 edit 无排除项必须两者允许；每个关闭项须有独立动作依据，本人 / 字段限制不算；未触及的更新沿用源值。写入前核 record_operations，写后核实际两项开关，不只验表 edit 或行条件 |
| 动作与记录 | 每条新增 / 变更行条件须回指角色权限原句，页面展示原句不算；能力兜底还须有原权限要求与不支持证据。仅阅读为 `read_only`、增删 `[]` / `null`；可实现范围必须回读对应读 / 编辑 scope 或 filter，筛选 `is_invalid=false`、勾选项符合原话。已确认不可实现时按上述例外核对忽略条件或创建人兜底及缺口说明，不把近似当作原范围生效。本轮非能力例外的范围遗漏 / 误授编辑须纠正回读；看全量改本人在范围可实现时须有本人编辑范围及其余可读 |
| 字段三层 | 表可访问、点名及其余字段符合上文，`specify` 未列普通字段无权；自定义须保留，编辑表全字段只读须 `edit + specify` 且全集 `read`。按类型上限、扩展能力和明确可见性验，不用生成默认覆盖已合法结果 |
| 既有与未来 | 从显式项 + 默认档计算真实权限。新建零页面表述须已有页全量显式可读、按钮全可见；有页面范围不从表补开；集合不漏项。默认额外开放的既有对象显式无权，未来默认保留；更新未触及项保留源档。逐项核按钮、复制、增删，不因身份 / 只读 / 本人范围另加限制 |
| 精确对象与系统角色 | 权限落在精确同名对象；只有精确对象不存在才考虑近义对象并说明。未点名系统角色时抽查其与源一致，误改按源恢复，不用其承载业务角色 |

本轮误补开的对象、新建缺表授权或超明确页面范围的对象，显式收为 `no_perm` 后回读；零页面表述的默认可读及更新未触及源权限不得误收。取数缺口按上文单列，不靠扩权消除。确认角色齐全、目标生效、源权限保留后交付；受阻项列角色 / 对象、原始错误、未实现要求与影响，不以局部成功宣称完成。
