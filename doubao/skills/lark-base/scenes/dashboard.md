# 仪表盘（Dashboard）

## 适用范围与对象关系

Dashboard 是容器，Block 是图表、指标卡、视图、文本等组件；视图组件还引用表视图。

## 开工必读

- **看板风格要落到容器主题。** 按 [主题映射与推荐风格](../references/dashboard-commands.md#仪表盘主题映射与推荐风格) 选择 `--theme-style` 并独立 Get 验证；笼统要求“清爽”推荐 `SimpleBlue`，不能只改组合图颜色。只要求局部配色时不改全局主题。
- **多表来源不能静默缩成单表。** 同一图表点名多张表时，先读 [多表需求与聚合失败的恢复边界](../references/dashboard-chart-config.md#多表需求与聚合失败的恢复边界)；字段聚合失败不代表可以换源、把金额改计数或新建辅助表代替原要求。
- **进度完成率精度不等于数值百分比格式。** 按 [百分比格式与进度百分比](../references/dashboard-progress.md#百分比格式与进度百分比不是同一项) 区分 `percentPrecision`、`precision` 和 `formatName`，逐项回读，不能以回执里出现某个关键词代替单位正确。
- **每个组件先写下范围、粒度、指标、排序四项再创建。** 名称不能替代配置。
- **把原话、标题中的范围写进本组件筛选。** 渠道、本月、某状态、某部门都算；按“各／每 X”统计时配置分组。其他组件或视图上的筛选不作用于本组件。
  组件筛选（动态时间示例）写 `"filter":{"conjunction":"and","conditions":[{"field_name":"<日期字段>","operator":"is","value":["CurrentMonth"]}]}`，不是视图的 `logic` + 元组；操作符只有[筛选条件](../references/dashboard-filter-conditions.md#操作符)所列，没有 `intersects`、`isAnyOf`、`containsAny`。不建 yyyy-MM 文本字段，回读 filter 为具体年月即写死。
- **“各 X 的 A、B”每个指标都按 X 拆分。** 趋势按“时间 + X”分组，平均、合计也按 X 分组；不用全局指标卡代替。
- **判断类主题词先建派生字段。** “周转慢”“滞销”“超期”等先在源表用明细算出判定公式，再按它筛选或聚合，不用库存量、金额等相近指标代替。例如周转慢：`最近出库日期 = [关联出库记录].[出库日期].MAX()`，`是否周转慢 = IF(TODAY()-[最近出库日期]>30,1,0)`。
- **已有 Base 里的业务状态词先找现成定义。** “待处理”“异常”等先 `+view-list`，有同名视图就沿用它的筛选组合；判定涉及多个字段时组合使用，不只取一个状态字段。
- **指标逐个对应到字段和聚合。** 数量、次数、单量用计数，金额、时长用求和；“率”建 0／1 公式取平均，“剩余／还能”建“上限 − 已用”公式，“趋势”按年月分组；不用总量、计划值等相近字段顶替。原话要求放进看板的筛选和分组写进组件本身，另建视图不算。见 [口径](#指标口径与展示单位)。
- **优先用承载明细记录的表做数据源。** 关联表属性先在当前表建公式投影并抽查；跨表点号路径不能作字段。见 [字段核对](#数据源与字段核对)。
- **排名先按实体聚合，再按指标值排序，最后取 Top N。** 不按原始行或维度名排序。
- **不主动创建文本组件。** 说明、标题、提示和分析文字都写在会话回复中；用户明确要求把文字放进看板时才创建。同时要求图表和分析，不等于要求把分析写进看板。
- **新建看板先定组件构成。** 默认按「核心指标 → 分类对比 → 趋势或分布」配齐组件，用户只点名一个分组图表时补一张同源的总量指标卡，见 [默认组件构成](#默认组件构成)。
- **建第一个组件前读 [视觉规范](../references/dashboard-visual-standards.md)，按组件清单选骨架、给每个组件定好 `--position`；全部建完用 `+dashboard-layout` 统一提交。** 见 [统一布局流程](#统一布局流程)。
- **画布是 48 列，不是 24 列。** 同一行各组件 `w` 相加等于 48，左右分栏两侧高度相加相等；行没排满时 `+dashboard-layout` 会把行末组件拉宽，指标卡变宽条、饼图被压扁。结构、尺寸和骨架按 [视觉规范](../references/dashboard-visual-standards.md) 的组件清单决策树、组件尺寸表和常用骨架定，不凭经验套坐标；未读视觉规范不写 `--position`。为凑页面类别补建或顺带建的看板同样先读视觉规范，不因是补充产物省略。

执行顺序：

1. 读取现有组件，检查同名或重复组件。
2. 为每个组件写一行口径：数据源表、筛选条件、分组字段、指标字段和聚合、排序。
   - 排名、“从高到低／最多的排前面”在分组上设 `"sort":{"type":"value","order":"desc"}`。
   - 收入和支出、有效和作废这类方向或状态，按该字段分系列或加筛选，不混在一个求和里。
   - 剩余量、差额、比率、合格率先在源表建公式字段再引用。“各 Y 的 X 率”建明细 0／1 公式，取平均并按 Y 分组；“A 和 B 的比值”先建公式。
   - “量”用计数或数量字段，不用金额；“分布”先建分段公式再分组。
   - 同一数据源、指标、分组、筛选的组件只建一个；重试后删掉重复的。
3. 准备公式字段或投影，抽查有值。
4. 按口径串行创建组件，`--position` 按已读的视觉规范定。每建一个就用 `+dashboard-block-get` 读回，对照第 2 步核对筛选、分组、聚合、排序都在，不对就当场修。创建命令直接用 `--jq` 取 ID，不接 `2>&1 | python3`：

   ```bash
   lark-cli base +dashboard-block-create --base-token '<base_token>' --dashboard-id '<dashboard_id>' \
     --name '<组件名>' --type column --data-config '{"table_name":"订单表","count_all":true,"group_by":[{"field_name":"渠道","mode":"integrated"}]}' \
     --position '{"x":<x>,"y":<y>,"w":<w>,"h":<h>}' --jq '.data.block.block_id'
   ```

   指标卡用 `--type statistics`（没有 `metric`，写 `metric` 报 `API error: [1]`）。`data_config` 只写 [结构表](../references/dashboard-chart-config.md#普通图表-data_config-结构) 里的键：指标用 `series:[{"field_name":"金额","rollup":"SUM"}]` 或 `count_all`，维度用 `group_by`；没有 `metrics`、`dimensions`、`aggregation` 这类写法（`aggregation` 是 `+data-query` 的键）。
   成功时输出即 `block_id`，`Tip:` 提示在 stderr。解析脚本报错（`JSONDecodeError` 等）不代表创建失败；先 `+dashboard-block-list` 确认该组件是否已存在，再决定是否重建。
5. 全部组件写完后必须调用 `+dashboard-layout --layout '[全部组件坐标]'` 收尾，哪怕只有一个组件。它只有 `--layout` 参数，没有 `--json`，也不包 `blocks` 层。先用 `+dashboard-block-list` 读 `data.items[].position`，把全部组件写进去，命令见 [布局调用示例](../references/dashboard-layout.md#调用示例)。
   `data_config` 的计数、求和、分组、筛选写法见 [常用形态示例](../references/dashboard-chart-config.md#常用形态示例)。
   搭建任务以配置核对为准，不用 `+dashboard-block-get-data` 读数来判断配置对错：表里数据少或为空时，读数说明不了口径。只在用户要读取、解释图表结果时调用；报 `API error [1]` 时同一组件只重读一次，仍报错就停止重读并在答复说明。不串 `sleep`。
6. 按下表验收。多轮任务里用户要求删除的仪表盘或组件，删除后回读确认已不存在。

| 交付前核对（读取命令） | 通过条件 |
|---|---|
| 配置（`+dashboard-block-get`） | 需求里的数据源、分组、聚合、筛选、排序都已保存；点名的每个指标都有对应字段 |
| 结果（仅读取、解释图表结果的任务，`+dashboard-block-get-data`） | 口径正确；源表有匹配数据却为空时修配置，不当作业务为零 |
| 时间范围（组件筛选及依赖公式） | 动态范围写在配置里，名称里有“本月”不算 |
| 布局（`+dashboard-layout` 返回的最终坐标） | 无空洞、无重叠、不越界（`x+w≤48`），尺寸没被成倍放大，并排的组件没变成整宽堆叠；核心指标在首屏，按「核心指标 → 分类对比 → 趋势与明细」排列；符合 [视觉规范自检](../references/dashboard-visual-standards.md#布局自检流程)；不符合就修正坐标重提一次 |

## 任务导航

读任务走「读取与解读」；写任务按写前决策、创建与维护（或布局、专属配置）、验证与交付的顺序。涉及新表、样例、计算或分享时同样触发对应模块；跨模块搭建由 [系统搭建](build-system.md) 编排。含指标、分组、比率、业务筛选或时间范围时，先执行 [任务口径与核对](../references/shared-statistics-rules.md#任务口径与核对)。

容器命令见 [容器协议](../references/dashboard-commands.md)，进度图见 [进度图协议](../references/dashboard-progress.md)；同一图表点名多张表时见 [多数据源协议](../references/dashboard-multi-source.md)，组件标题、背景、图例、数据标签、字体和子形态见 [自定义样式](../references/dashboard-style.md)。

<a id="默认组件构成"></a>

## 默认组件构成

新建看板（包括系统搭建时默认配置的看板）先定组件构成，再规划布局。用户点名了具体组件时以用户的为准，再按下面补齐：

- **核心指标**：至少一张总量指标卡（记录数、金额合计等最核心的单值），放在首屏。
- **分类对比**：用户点名的分组 / 对比图表；系统搭建默认配置的看板补一张分类占比或对比图。
- **趋势或分布**：有日期字段时加一张趋势图；有状态字段时可加状态分布。
- **只点名一个分组图表时**：补一张同数据源、同指标、不分组的总量指标卡，与图表组成「指标卡 + 图表」；用户明确表示只要这一个图表时不补。
- 补的组件只用当前表已有字段和用户关注的指标，不加与需求无关的组件；后文「不为填满画布增加组件」限制的是这类无关组件，不限制本节的默认构成。

<a id="重排仪表盘布局"></a>

## 统一布局流程

新建或追加组件、调整位置或大小、重排、美化都触发，用户没提“布局”也一样。只删除组件且未要求整理、或只改名称、指标、筛选时不触发，不因历史空洞重排。
本轮写完后收尾一次；已带位置、只有一个组件或没有命令提示也要执行。之后有布局变化或定向修复时才重新收尾。

闭环：`metric/source/range/grain → component config → actual result → unified layout → final coordinates`。创建成功、名称正确、结果有数都不能替代最终坐标回读。指标、范围、粒度或剩余量、比例、及时率等语义无法证明时，保留原要求并标 `blocked`，不用相近指标凑交付。

验收范围按操作确定，尺寸与例外以 [视觉规范](../references/dashboard-visual-standards.md#适用范围与入口) 为准：

| 操作 | 验收 |
|---|---|
| 新建整盘或整盘重排且未指定排法 | 无洞、无重叠、不越界、末行铺满、整体底齐，并满足类型尺寸；不能只验证坐标合法 |
| 追加组件 | 保留既有布局和授权范围；底部表格用追加例外，不整盘重排 |
| 定点调整或用户指定布局 | 优先满足指定位置与保留范围；检查局部尺寸、重叠和边界 |

1. 完整枚举现有组件与坐标；本轮刚建的空容器可跳过。
2. 规划任何坐标之前先读 [视觉规范](../references/dashboard-visual-standards.md)，**未读视觉规范不要规划坐标**；再完整读 [布局协议](../references/dashboard-layout.md)，它只讲 `--layout`／`--position` 的格式与命令行为，不能代替视觉规范。视觉规范必读适用范围、坐标体系、位置关系、涉及类型的尺寸和自检流程；新建或整盘重排还读“布局选型”到组件尺寸之前的全部条款和硬约束，用分栏时再读分栏算法。
3. 在允许范围内规划坐标并自检，范围外组件保留；新组件按规划位置串行创建。用户只说美化、撑满或铺满时自行规划。新增指标卡放进顶部指标行，不放在图表下方；盘底是表格时把新组件插到表格原 `y` 并下移表格，不追加到表格下面；其余追加到底部时按现有最大 `y+h` 逐行累加，不用任意大 `y` 值避让；计算示例及近似坐标处理见 [底部追加规则](../references/dashboard-visual-standards.md#追加到底部按实际底边累加)。
4. 用 `+dashboard-layout` 收尾；它每次都调用服务端兜底整理。不再执行 `+dashboard-arrange`，也不逐个改坐标代替。返回的 `data.tidied_block_ids` 里有组件被拉宽（如指标卡 `w>24`、非表格组件 `w=48`），说明提交的那一行没铺满 `[0,48)`：把同行组件加宽到铺满后重提一次。
5. 按 [布局收尾与验收](#布局收尾与验收) 核对返回的最终坐标；复用有效返回，不再次提交。

布局只授权改坐标，不授权改非目标组件的数据、名称或删除它们。类型约束已证明无解时按规范停止；不为填满画布增加与需求无关的组件，[默认组件构成](#默认组件构成) 里的指标卡和图表不在此限。

## 读取与解读

### 读取现状与计算结果

缺可信 ID 才 list；本次可信 ID 复用。完整清单按 [分页协议](../references/dashboard-block-commands.md#组件列表与分页) 读全。已有图表读/解读走本页；独立分析走 [Analyze-data](analyze-data.md#适用范围与对象关系)。

#### 读取图表结果与完整仪表盘

直接读聚合结果，不先导出全量底表；需确认身份/类型/配置先读详情，查异常先列组件再读可疑项。
“全部图表/完整仪表盘”先枚举全部：图表/指标卡读结果，视图读配置/记录，文本读正文，其他读专属配置；文本也属完整内容，失败项单列。多组件在一个 shell 调用内串行读，按 [批量读取示例](../references/dashboard-block-commands.md#多个组件串行读取) 组织；先确认类型支持该命令，不为减少调用裁剪内容。

### 图表结果解读与交付

按 [解析规则](../references/dashboard-chart-result.md#如何正确解读返回值) 还原含义：

- 交代指标/分组/范围及主值/关键分类；组合分组说明维度；词云说明词项统计含义，不当原文列表。指标卡交付主值、周期变化、趋势；窗口不明就读配置，不猜同比/环比。
- [解释模板](../references/dashboard-chart-explanation.md)：读数/简述用基础版；分析/总结/异常/Top N/趋势用增强版，提炼差异、峰谷、结论，不逐条复述。建图又要求分析时，回复必须给解读，不能只给链接。
- 只读解读也遵守 [指标可加性](../references/shared-statistics-rules.md#指标与统计总体)：新增合计/占比/差额/排名先核范围、粒度再确定性计算；Top N 不含总体分母/全局最低值，均值/比率/去重数不能跨组相加。
- 缺证据只述已证实范围；必答补算交 [Query](query.md) 对象路径后回本页解读，不自动转独立 SQL/导出原始记录。

## 写前决策

### 操作约束

先读 [使用边界](../SKILL.md#适用范围与能力边界)。明确要求图表/看板/Base 可视化就创建 Dashboard，无需“长期”字样，外部图片/文本不能替代。
只问占比/趋势/对比属 [独立分析](analyze-data.md)，不建图；只要会话输出/不改 Base 时不创建；读已有图也不新建。
系统搭建需求模糊/要求完整系统时，按 [模块选择](build-system.md#系统能力与丰富度) 配关键结论仪表盘；普通问答不触发。

### 指标、数据源与时间口径

创建/修改前定粒度、数据源、指标、时间范围；占比/率再定分母和 `denominator_group`，然后构造 `data_config`；这些不是 CLI 参数。
涉及指标、范围、状态、自然语言筛选、相对时间、统计口径时先读 [共享规则](../references/shared-statistics-rules.md)，构造条件再读 [筛选协议](../references/dashboard-filter-conditions.md)。

#### 数据源与字段核对

按 [字段查找](../references/field-commands.md#字段查找与完整性) 核字段/类型，按 [字段边界](../references/dashboard-chart-config.md#字段所属表边界) 查维度、指标、筛选字段。关联属性：

1. 字段所在表能作 `table_name` 且保持粒度→直接用。
2. 否则按 [Formula / Lookup](field-formula-lookup.md) 在当前表投影；默认 Formula，仅明确要求才用 Lookup。确认本地字段，以一次记录查询验证有源值样例行，再用于 Dashboard。
3. 无法安全投影/结果为空→不猜点号路径，不宣告完成。

选项筛选先确认完整候选值域，再按 [操作符协议](../references/dashboard-chart-config.md#筛选字段与操作符) 核选项来源、公式返回类型、条件格式。

#### 指标口径与展示单位

| 需求 | 口径 |
|---|---|
| 固定总体类别占比 | 类别 `SUM`/计数作分子；图表须按总体算占比，金额柱图只改百分比格式不算 |
| 每月/每部门类别占比 | `denominator_group` 为同年月/部门，分子按类别分；跨月总饼图不能替代。不支持归一化就按共享规则计算并持久展示；不猜百分比堆叠参数，不把 `number_format` 当除法 |
| 计算率（完成率、合格率等） | 按统计单位算分子、分母；仅分子不算率。同记录有二者时建比值公式；更粗粒度重汇总二者，不平均行比率 |
| 0/1 平均 | 仅当每条明细是等权分母单位且覆盖总体；未满足条件的分母写 0，不留空/筛掉；维度率保留分组 |
| 去重、多次参与、权重不同 | 按目标粒度分别算分子分母再相除，遵守分组、范围、去重、零分母规则；辅助表/字段须持续计算，不用一次查询值 |
| 格式 | 不假设继承源样式；区分比例小数和已乘 100 的百分数。普通数值/记录数不用百分比，金额用实际币种；单值率用指标卡，率/占比显示百分比、保留一位小数，见 [number_format](../references/dashboard-chart-config.md#statistics-指标卡数值格式-number_format可选) |

#### 时间范围与分组粒度

范围决定记录，分组决定粒度，不互代。首次 Create/Update 前逐项定 `range`、`grain`；时间词不从相邻项继承；现有组件名/配置不能覆盖本次语义。

| 语义 | 决策 |
|---|---|
| 本周 | 动态本周；仅保留另行要求的分组 |
| 按年月、逐月、各月、月度趋势、跨月比较 | 按稳定年月键分组；不用本月筛选代替，不按原始日期分日桶 |
| 本月、当月、当前月 KPI | 动态本月；单值指标卡不加月份分组 |
| 按月份和另一维度 | 同时按年月键和该维度分组，顺序匹配主轴/系列 |
| 本年度 | 保留年度范围；筛选类型不匹配也不能删除 |
| 裸“每月”或“月度” | 要趋势、各月、跨月或时间轴时按年月分组；要本期单值或当月汇总时限定本月；仍不明先澄清。用户要求立即执行或禁止追问时，没带“本月／当月／当前月”的“月度对比／趋势”按完整年月分组，不借相邻交付物的本月范围 |

月份分组/年度范围无法保存时，按 [时间辅助字段](../references/dashboard-chart-config.md#时间粒度与范围辅助字段) 和 Formula 建字段、验代表记录；年度字段还须验范围内有值、外部为空。
不得删年度约束换成功或靠名称声称粒度正确。

### 组件类型选择

`group_by` 非空或要求“按/各/每某维度”时，单指标也用分类轴图表并保留 `group_by`，不用 `statistics`；仅空分组、单值结果用指标卡。

- 类别比较用柱状图或条形图；趋势用折线图或面积图；占比分布用饼图、环形图或词云；多指标对比用组合图。
- 两变量关系用散点图；流程转化用漏斗图；多维度评分用雷达图；行列交叉汇总多个指标用透视表；无维度单值用指标卡。
- 单维度 Top N 用 [排行榜](../references/dashboard-chart-config.md#ranking-排行榜专属契约)；评分分布用 [NPS 图](../references/dashboard-chart-config.md#nps-评分图专属契约)；宽表多指标横比见 [宽表多指标对比](#宽表多指标对比)。
- 按单字段离散值筛整盘用 [切片器](../references/dashboard-slicer.md)；距指定日期的时间用 [倒计时](../references/dashboard-countdown.md)；用户明确要求的看板文字用 [文本组件](../references/dashboard-block-commands.md#text-类型特殊结构)。

源表行序即业务顺序时首次创建即配 [排序](../references/dashboard-chart-config.md#sort-排序)；类型配置从 [类型入口](../references/dashboard-chart-config.md#支持的组件类型type-枚举) 进入。

#### helper 汇总表的更新方式

仅源表无法直接聚合时建 helper：

- 长期：按 [派生规则](field-formula-lookup.md#执行与验收要求) 用 Formula/Lookup 动态算；固定维度/阶段可写普通字段。验关联/计算/代表结果后接图；一次 `+data-query`/脚本值不算持续更新。
- 明确快照：可写确定性聚合值，但标时点/口径/不自动刷新；无快照要求不得降级。
- 汇总/校验值由 `+data-query` 或可复核程序产生，不心算。无法动态实现就报受阻，不加未授权 Workflow。

#### 宽表多指标对比

比较多个数值字段平均值/评分项时，实体主键不进 `group_by`。多个 `series` 不能以字段名作横轴时，按 helper 建 `指标项`、`平均值` 等列，每字段一条记录，动态计算或明确快照后画柱状图。
配置见 [宽表协议](../references/dashboard-chart-config.md#宽表多指标横向对比多个数值字段本身就是要比较的对象)。

#### 漏斗图的当前与累计数量

- 当前数量（“各环节当前数量/当前阶段分布”）：按状态/阶段直接分组计数。
- 累计数量（“流程转化/从 A 到 B 各环节转化”）是当前及后续阶段的后缀和，仅在单向、无跳阶/回退、记录不删除时成立，否则用状态历史。
  已有累计字段/阶段汇总表直接用；否则确认前提，以 helper 按阶段顺序准备、验收再画。见 [漏斗模板](../references/dashboard-chart-config.md#漏斗图流程转化)。

### 已有 Dashboard 的冲突检查

新增、替换、纠错前读全组件，找同名/同义指标，或同源但 `range`、`grain`、`measure` 不一致项。
唯一确认目标旧组件才原位更新；换类型走删建。新建时不静默复用含冲突组件的旧盘，另建一个；修改旧盘时未经授权不删其他项，无法安全处理则报阻塞，不以并存新项宣称整盘正确。查询、看板、回答须一致。

## 创建与维护

### 公共写入流程

复用可信 ID，旧盘增改先查冲突；按 [组件写入协议](../references/dashboard-block-commands.md#创建更新与删除) 和本类型配置规则准备完整配置，更新只改用户要求的部分；完成写前决策及依赖验收，改名/删除不读无关字段；串行写入并保存 ID；完成布局/验收，交回最终 ID、类型、坐标。
仅改数据语义就保留布局；写入使证据失效就重验；连续修改遵守 [逐阶段验收](../SKILL.md#执行与协作)，最终状态不能代替中间证据。

### 创建仪表盘

先定类型、数量、依赖、布局；建容器后串行建组件。指标卡/分布图优先组件聚合；仅 Top N、字段值探索、复杂筛选校验、helper 汇总先查询。
简单卡/分布图/趋势图按模板直建；仅调试 JSON、复杂自造配置、参数校验错误时 dry-run，不逐个预演。首组件前规划，写后验收。

### 追加组件

检查既有指标/内容，定范围并串行创建；不越权，验收新项和受影响依赖。

### 修改或删除组件

读现状，只备所需更新；换源重核字段。按 [更新限制](../references/dashboard-block-commands.md#创建更新与删除) 判断原位更新；换类型须获授权后删建，内部模式切换不算换类型。
容器改名/删除走 [容器协议](../references/dashboard-commands.md)。删除前确认唯一目标/保留项，删除后核目标不存在/保留项无误；按布局条件决定是否整理空位。

## 专属功能配置

未涉及不配置。通用顺序：读协议，定位并读现状，只改要求的部分并保留其余，再提交、回读、验收。

### 配置与读取视图组件

明细/列表/甘特图/画册用 [视图协议](../references/dashboard-view.md)。创建前核数据源/字段/目标；读取先确认组件/真实视图引用，复用可信详情，读配置/记录，不猜源，全量须分页。
修改前读受影响配置；换源/展示类型时重核配置/保留项。组件命令无法设置时间轴/封面时须报受阻，不静默忽略。

### 配置全局筛选

整盘预设用 [全局筛选](../references/dashboard-global-filter.md)，单图固定条件写组件，交互选值用切片器，点击数据点用联动。确认入口/权限/现状；局改保留其他项；读不全旧配置先恢复；写后验状态/效果。

### 配置图表联动

点击源图筛目标图用 [联动协议](../references/dashboard-linkage.md)；固定筛选不能替代，按钮另走流程。

1. 确认环境有联动能力；定位源和目标，逐个核类型、数据源支持范围。
2. 确定最终关系，保留未要求移除的目标；新图先建并取真实 ID。
3. 提交并回读关系；源或目标换表须重查。不能确认同时换表和联动时，分步执行并回读。
4. 分别验证配置和点击效果。

### 查询、绑定或解绑按钮工作流

定位盘/按钮，按 [绑定协议](../references/dashboard-button-binding.md) 查真实关系；不确定先排错，不猜。完整定义须用返回标识进 [Workflow](workflow.md)；查绑定与读定义是两项操作，列表流程未必适合按钮。
按协议绑定/更换/解绑；新建则按 [按钮触发器](../references/dashboard-button-binding.md#仪表盘按钮的触发器) 定义后编排，涉及记录须定目标表/记录。分别验组件、关系、要求的运行状态；仅查询/解绑不附带启停。

### 统计权限与访问控制选择

| 目标 | 路径；不能互代 |
|---|---|
| Base 高级权限开关；角色看板阅读权限 | [Permission](permission.md) |
| 查询/设置跟随访问者统计 | 按 [统计协议](../references/dashboard-permission-statistics.md) 查入口/权限/现状；查询交结果，设置后回读。前置不足时仅获总开关修改授权才进 Permission，不自动开启 |
| 分享设置/链接 | 按 [分享协议](../references/dashboard-share.md) 读改回读。给他人查看须开启并交有效链接；地址栏 Base/看板地址不算，不只说“可自行分享”；受限标 `blocked` |

## 验证与交付

### 验收范围与完成条件

组件增改复用或依赖字段变更须过门禁：新盘查全部数据组件；旧盘查本次及目标指标相关项；同一指标范围/粒度/数值矛盾即失败。
只自动改新组件或唯一对应交付物的旧组件；其他同义/冲突项只读报告，未经授权不改删，限目标盘。新建的派生字段须被组件实际引用；布局、交互另验。

### 交付健康门禁（写任务必做）

1. **定位**：复用可信 ID；定位和冲突检查须完整枚举。
2. **配置**：按上方交付前核对表回读；引用不存在、API 报错、关键项缺失均判失败。
3. **内容**：Mock 图逐个读结果，有数且口径正确；配置不能代替结果，样例仍做 [Mock 回读](mock-data.md#回读验收)。空数据仅在有界源表查询证明本应为空时通过；有匹配数据却空/矛盾须修。
4. **依赖**：新增/修改 Formula/Lookup 时，以有界记录查询抽查有输入样例行并执行模块验收。
5. **布局/失败**：触发则验布局，未收尾先完成，有效证据复用；按 [恢复预算](../SKILL.md#异常恢复与停止条件) 修复/复验/停止；全部通过才称可用。

时间范围按 [动态时间](../references/shared-statistics-rules.md#时间范围与动态配置) 核配置/依赖公式，样例恰好符合不算证据；格式/选项/视图走下列验收。
文本须回读正文；交互筛选器核绑定字段/展示/选择模式，过滤条件或单次统计正确不能替代控件验收；其他项按专属协议验保存状态/效果，不套普通图表协议。

### 指标格式与筛选结果验收

- 单位：以回读配置/原始值核口径；数值正确或名称带单位不等于格式正确。
- 分组占比：核分子、分母分组、结果。两月 A/B 为 30/70、90/10 时，各月应为 30%/70%、90%/10%，全时段 60%/40% 不通过；用实际数据或已授权样例验证，不为测试改数据。
- 计算率逐组核分子/分母/原始比值，分母含未满足条件的有效主体；重复主体/不等权时验算法粒度。排名核实体/聚合值/顺序；标题、百分号、原始行序不算证据。
- 选项回读条件，逐项核字段/操作符/选项，再验命中/排除；空结果走门禁，视图/全局筛选走专属路径。

### 布局收尾与验收

按 [返回协议](../references/dashboard-layout.md#返回结构) 取最终坐标，按用户要求和视觉规范自检清单验收。CLI 不检查空洞和重叠，服务端整理也不能替代结构检查（同排两张半宽图高 6 和 12，不重叠但短图下有洞）。只读位置不重复调用，规划坐标不算结果。
按组件 ID 与交付清单对账，逐项查类型尺寸、位置关系、空洞、重叠、边界；缺坐标标“布局未验证”。整理移动要求不动的组件即失败；说明变化，不反复撤销。不符则在预算内重规划/复验；无解停止，不交违规坐标。

### 视图组件验收

按 [一致性](view.md#名称配置与记录一致性)，将原话、视图名、组件名限定词并集逐项对配置；按 [回读协议](../references/dashboard-view.md#返回结构与配置回读) 取证，不凭名称/记录恰好符合。要求页面展示、分组折叠、交互时另验页面，不用记录查询代替。

### 全局筛选验收

回读目标/保存状态，清空须有证据。要求图表随筛选变化时再读结果验命中/排除；写成功不能替代。

### 联动交互验收

回读证明保存。要求点击效果时在页面选源图数据点，确认目标变化、无关项不变，再取消并确认恢复；结果查询不能证明点击。无法页面验则写“配置已回读、交互尚未验证”。

### 按钮绑定与启停验收

回读确认按钮、工作流；解绑须确认关系解除。要求运行/停用时按 [Workflow](workflow.md) 核对处理。组件存在、绑定正确、运行状态分别取证。
