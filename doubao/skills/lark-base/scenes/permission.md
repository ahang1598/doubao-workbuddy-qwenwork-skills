# 权限

## 开工必读

只配原话中的角色、表、能力：

| 原话 | table_rule_map 配置 |
|---|---|
| 某角色“查看／只能看”A 表 | A 表 perm: read_only |
| 某角色“可编辑／维护”A 表 | A 表 perm: edit，保留新增记录、删除记录和视图编辑；原话明确禁止才收窄。原话未提到的表不写入该角色 |
| 某字段“不能改／只读”，其余可编辑 | 表级 edit 保留新增、删除和视图编辑；只在 field_rule 把该字段设为只读 |
| “只有 X 能改”A 表 | X 对 A 表 edit；其他自定义角色对 A 表至多 read_only |
| “各看各的／只看自己负责的” | read_only+记录范围（人员字段=当前访问者），不升 edit |
| “只能看／管本部门的、关联到自己的” | 按 [记录权限与行级条件](#35-记录权限与行级条件) 在该表 record_rule 加记录范围，不开放全表。条件字段用该表的人员字段；表里没有时先建人员字段或查找关联表的人员字段，对它用 contains（不填值即当前访问者） |
| 某角色“管理／可以管理”A 表 | A 表 perm: manage |
| “敏感 X 按角色控制可见” | 未指定可见者时按职责定并说明；至少落一种角色差异：按敏感标记设记录范围，或敏感字段在 field_perm_mode: specify 下对无权角色设 no_perm |
| 权限精确到列 | 配 field_rule；未点列则选敏感列（证件号、电话、金额），对非主责角色设只读或 no_perm，答复写明限制了哪些列 |
| 某角色需填写 A 表表单 | 不因此给 A 表 edit 或 add |
| 某角色“只能填／只能录入”A 表（直接在表里录入） | A 表 edit，record_operations 只留 add（不给删除），业务字段设 create（只能在新增时填，不能改已有记录），写法见 [3.6.1](#361-新增记录--部分字段可持续编辑) |
| 原话列出 N 类人员 | 每类各建一个自定义角色；不合并、不增造，缺一即未完成 |
| “所有人／大家都能看”A 表 | 每个自定义角色对 A 至少 read_only；Editor／Reader 保持默认并说明 |

提交后逐角色 +role-get 回读两个方向：出现原话没有的表或高于原话的能力时，删除或降级；edit 表的 record_operations 为空或 allow_edit: false 而原话没有禁止时，改回默认。

顺序：+base-get 查 is_advanced → 必要时 +advperm-enable → +role-create → 逐角色 +role-get → +role-update。

- 只有用户点名要把具体人员加入某角色时才用 +role-member-add。搭建系统或只要求建角色、分权限时只建角色，不加人。不把当前用户加进自定义角色：当前用户是 Base Owner，平台拒绝改 Owner 权限，返回 MsgCannotSpread。任何成员返回 MsgCannotSpread 都不重试、不换写法反复加，在答复里说明未加入的人员。
- 角色命令只有 --json，没有 --name；返回的 data.data 是字符串化 JSON。
- 角色 JSON 里的表名、看板名、字段名都用 list 命令返回的真实名字（表不用 table_id）；每张表给完整四件套；perm 只用协议枚举；角色名不能与已有角色重复，否则报 API error [1]。
- 完整序列见 [从零建角色](../references/permission-role-commands.md#从零建角色的命令序列)，记录和字段 JSON 见 [角色配置协议](../references/permission-role-config.md)。

## 任务导航

查状态、读角色、开关高级权限、增改删角色（删除跳过权限决策）、管理自定义角色成员：先做前置检查，再进下文对应小节并回读验收。系统角色协作者、普通 Base 协作者和文档链接访问用 lark-drive；角色对仪表盘的访问写 dashboard_rule_map；仪表盘按访问者权限统计转 [Dashboard](dashboard.md)。组合任务分别完成命中的操作；只查状态或管理成员时，不加载角色配置规则。

## 前置检查

### 目标、状态与依赖

- 按 [Base 定位](base.md#定位已有-base) 取可信 base_token 及真实角色／成员／表／字段／视图／仪表盘／类型／选项。更新前 +role-get 完整配置，保留未涉及项／原值。
- Base 快照只含本次可信读取及前序已验收对象。规划新建的对象先创建、回读；依赖被本轮改动后更新快照，不把计划名当事实。
首次调用任一角色命令（+role-list、+role-get、+role-create、+role-update、+role-delete）前，按顺序执行：

1. 同一请求新建了业务 Base 或数据表时，先写样例记录并回读：按用户指定数量写；未指定且未要求空模板时写 5–10 条，用 +record-list 验证数量和关键字段。之后才进入 +advperm-enable 和角色配置。
2. 执行 lark-cli base +base-get --base-token <base_token>，读 data.base.is_advanced。
3. is_advanced=false 时：只读请求只报告该状态；获得高级权限配置授权后才 +advperm-enable。查看设置或成员的请求不算开启授权；写入请求未获开启授权时，停止并说明必须先开启高级权限。
4. 仅 is_advanced=true 或 +advperm-enable 成功后调用角色命令；后续复用该状态。

不得用不受支持的 +advperm-get 探测。高级权限关闭时 +role-list 也可能返回空列表，不能据此推断状态。

### 授权范围与身份边界

- 仅明确要求高级权限／角色配置，或同句有可解析主体+能力+资源时启动；普通协作者／文档分享、Workflow“只要……就……”、普通字段／表单／视图中的“只／仅／所有”不触发。
- 数据敏感或要求按职责限制可见／改／删时才启用配角色；先确认目标、影响和 [角色处理](#角色处理)。全角色读取不授权改未点名系统角色；既有路径破坏隔离则 blocked，不越权收窄。
- 权限配置／成员分配／分享授权独立；未点名人员／用户 ID 不分配成员。高级角色配置／自定义角色成员要求已启用且调用者为 Base 管理员；系统角色协作者走 Drive，不要求两者。
- 所选网关和后端须提供对应路由；多次调用保持主机、环境、应用和身份一致。用读取命令查状态和诊断问题；--dry-run 只预览请求，不能证明部署、权限或写入完成。
- +role-create／+role-delete 仅适用自定义角色；Editor／Reader 等系统角色可在支持范围调整，不可删。
- 更新按 [角色更新合并协议](../references/permission-role-commands.md#读取与更新角色) 提交；嵌套规则必填条件见 [TableRule 契约](../references/permission-role-config.md#数据表权限-tablerule)。
- +advperm-disable 使现有自定义角色失效；--yes 前确认 Base／意图。+role-member-remove --yes 撤销该角色带来的访问；先确认角色／成员。
- 访问申请使用申请人身份；不先调管理员角色读取，不换管理员代提。

## 权限决策

确定权限意图后转成 AdvPermBaseRoleConfig，不得用默认值覆盖目标。

### 权限账本、角色与默认值

创建／修改前逐句填写；无约束写“不适用”：

| 允许主体 | 排除主体 | 资源 | 能力 | 目标状态 | 保留状态 |
|---|---|---|---|---|---|

- 资源：Base、表、字段、记录范围、视图、Dashboard。能力至少拆成阅读、编辑已有值、仅新增时填写、新增／删除记录、复制、下载、视图／表结构管理；“可编辑”不代替其他能力。
- “只让／仅让／只有／仅限 + 角色、人群或可回指人称 + 权限动作”先记角色轴排他和排除主体；字段、记录条件只定范围。角色、表、字段、记录轴同时命中时全部处理。
- 有排他语义时，写后枚举系统角色和全部自定义角色；只读取或只创建被允许角色不能证明隔离成立。
- “本人／本部门／关联到自己”须有真实关系、受支持字段，不等于本人创建；无法表达则报缺口，不用非等价条件缩／扩范围。

### 角色处理

| 类型 | 规则 |
|---|---|
| Owner、Admin、Editor、Reader | 保持平台默认，不改、不收窄、不声称已限制；只有原话点名平台角色才按字面处理，并按 [上限](../references/permission-role-config.md#角色类型-roletype) 校验 |
| 平台生成“普通用户” | +advperm-enable 生成的 custom_role 默认全表可编辑、可复制下载；必须 +role-delete，再按题面从 no_perm 逐个 +role-create。平台未生成时，不自建“普通用户”或兜底角色 |
| 业务角色 | 按题面角色词建；职责／范围不同不合并；排他约束其他自定义角色；收尾 +role-list：无“普通用户”，题面角色齐全 |

偏序：可管理 > 可编辑 > 仅新增时可编辑（仅字段）> 仅可阅读 > 无权限；“严于／低于／收窄”均按此序。

**基线**：新建还是更新，按目标角色本身是否已存在判断，不按是否执行了 +advperm-enable。

- 新建角色从 no_perm 起，只开放明确要求的权限及其平台默认附带能力，不因猜测或常见做法扩展。no_perm 起点不意味着授予 edit 后还要逐项关闭新增、删除和视图管理。
- 更新角色只改本轮约束命中的能力，未涉及项保持现状，不用新建默认值覆盖旧配置。
- 最小权限只约束可访问的表、字段和记录范围；已授权“可以改 A 表”时，编辑权限整体授予，不拆碎其内部操作。
- 某角色对一张表只有读方向动作（看、各看各的、只能看自己的、不能改但可以看）时，该表为 read_only，用 record_rule 收窄；不按业务职责推测升为 edit。
- 字段必须映射真实 +field-list；无法唯一映射时只处理已确认项并澄清，不放宽为 all_edit。角色权限配置本身就是交付物；是否分配成员按授权范围单独判断。

#### 表级 edit 默认能力

表级 edit 在平台上自带记录新增、记录删除和视图管理。用户只交代谁能改、没对这些操作提要求时，保留平台默认，不要逐项关闭；字段范围或行条件不取消这些默认能力。“新增记录 + 部分字段可持续编辑”按 [§3.6.1](#361-新增记录--部分字段可持续编辑) 处理，不套本表默认值。

| 能力 | 默认 | 关闭条件 |
|---|---|---|
| record_operations.add | 包含 | 明确禁新增，或“只能修改” |
| record_operations.delete | 包含 | 明确禁删除，或“只能新增／只能修改” |
| view_rule.allow_edit | true | 明确禁新增／修改／删除视图 |

用户提出以下任一要求，视为对权限粒度有要求：限定记录范围或字段的可见／可编辑范围；“只能新增”“只能修改”“仅可录入”；直接禁止记录操作或视图操作；“防舞弊”“精细化管控权限”等风控要求。此时只在被点名的维度收窄：字段要求只写 field_rule，行要求只写记录范围，其余默认能力不变。

以下表述只约束编辑对象或字段范围，不关闭默认能力：

- 先总括“不能修改数据／只读”，后文又对某表给出编辑例外：例外表按 edit 默认能力处理。
- “只能编辑满足条件的记录”：约束编辑哪些记录，不是删除禁令。
- “某字段只读／不可见”：约束字段范围。

#### 默认关闭项

1. 新建角色：默认携带 base_rule_map，按下表取值。
2. 更新角色且未涉及 Base 级权限：省略 base_rule_map，不写 false 撤销已有复制或下载权限。
3. 更新并明确修改 Base 级权限：先 +role-get 回读，只改用户要求的项。原有 true 保留不算新授权；用户未要求时不把 false 改为 true；明确禁止的项改为 false，其余保持。

| 能力 | 默认 | 开启条件 |
|---|---|---|
| 未提表访问 | no_perm | 明确提表 |
| 仪表盘 | 不配置 | 明确提仪表盘 |
| base_rule_map.copy | false | 明确允许复制 |
| base_rule_map.download | false | 明确允许下载／打印／副本 |

### 实体映射与范围（§1–§2）

1. 无完全同名时选语义最近者；近义／换名／长短形／同义梯度可替换（“优先级=紧急”，选项仅高／中／低→高）；无关名不按顺序兜底。
2. 去后缀“表／明细表／记录表／情况表／登记表／统计表／汇总表／明细／清单／列表／信息表／数据表／台账”后，A 与 B 或 B 去后缀形相同即同一实体；字段／视图／仪表盘同理，字段还可去“字段／信息／内容”；多命中跳过。
3. 规划项先创建、回读入快照；未完成按依赖处理。仅快照和“本轮将新建”都无近似项时跳过，不写授权／字段／视图／行条件，不虚构。请求用映射后真实表／字段／视图／仪表盘／选项名，不简化、翻译、缩写、修饰，保留空格。
4. 仅“显式点名+属于当前角色+有授权／修改语义”的明确表／仪表盘或唯一指代（当前表／这张表）入选；不按常识、职责、相似名、他角色历史扩展。当前角色未提的兄弟／关联／既有表、字段、视图、仪表盘不出现；不补全／对齐／默认开放，语义路径不明则不写。
5. SingleLink／DuplexLink 不连带授权关联表；检查承载不等于授权；只收窄获授权且命中保护约束的对象。

#### 字面清单、主题词、范围词

- “管理／维护／处理／负责+A、B、C”等字面清单=§1 映射结果；枚举具体表名（含“等”）仍守清单，不按主题／上下游／关联／互补名／他角色扩展；先映射再收束。
- 仅“管理／维护／处理／负责／对所有+主题词 X”时扫描全部表：含 X 或经后缀／近义映射锚定 X 者全纳入；X 在中尾、复合名、分析／统计／汇总／派生表也纳入；只展开表轴，字段／视图／行条件仍收束。
- 未列字段的范围词（基本信息／反馈内容／评分／状态／明细／备注／说明／薪酬／福利／收入／绩效／考核／资金／财务／金额等）：绑表只查该表，否则查该角色按清单／主题获访问的所有表；逐表只匹配该词，无命中跳过。只纳入同语义层级、直接承载描述的原始采集字段；公式／查找引用／汇总等计算／统计／聚合派生字段归其余；SingleLink／DuplexLink 是原始可录入字段。
- “这张表／这表／该表／此表／它／这”指同角色段落此前最近字面表名，不扩散到他表、范围词、关联表、主题词。表／字段轴先精确匹配，命中即停；否则从概括词抽关键词，对全部表名＋字段名逐个做 包含(token) 子串／正则；命中必纳入，但仍守轴收束／派生排除。

#### 全集与视图

| 原话 | 范围 |
|---|---|
| 所有／全部／每一张数据表 | 快照全部表逐张写，不按业务过滤；仪表盘不动 |
| 所有／全部／全量数据 | 全部表+全部仪表盘；查看／阅读→只读／可见 |
| 所有内容／信息 | 有看板／仪表盘语境→所有数据；否则→所有数据表 |
| 所有／全部+主题 X+数据／内容 | X 同根表+名称 包含(X) 的全部仪表盘；按阅读授权 |
| 其他／其余表保持／设为只读／可查看 | 本轮未处理表逐张 read_only；不得漏／写无权限 |

无表轴全集词时，不得写“所有表／全部数据表／每张表／逐表／所有已授权表／已有权限表／已访问表”或枚举未点名既有表。仅“所有／全部视图”时只绑最近点名表；“只能看默认视图”先映射真实视图，写仅该视图可见、其余隐藏，不得写所有视图可见；视图管理另判。

### 权限维度与默认策略（§3）

只生成原话命中的维度。本次 JSON 没写某角色，不代表该角色在服务端没有权限。原话有“只有／仅限”、互相不可见、保密、隐私或安全等排他要求时，写后按 [全角色验收](#角色配置与全角色安全验收) 回读系统默认角色和相关自定义角色；获授权修改的角色仍有敏感数据的访问、编辑、增删、复制或下载路径时显式收窄；未点名的系统默认角色保持不变；既有权限使隔离无法成立时标 blocked 并报告访问路径。

| 方向 | 触发词／规则 |
|---|---|
| 正向 | 能／可以／可／具有／拥有／允许／保留／仍可／仍然／继续／保持／维持／沿用／不变；只影响点名实体，保持=维持现状，“保留 X”≠“只保留 X” |
| 否定 | 不能／不可／不允许／禁止／看不到及“X 不可见／不可阅读”等谓语；只影响点名实体 |
| 排他 | 只能／仅可／仅能／只允许／只保留／仅保留／仅显示；其余项按新建／更新分支 |
| 覆盖／反向 | 改为／设为按字面等级；撤销／去掉／解除／取消／放开按 §5 反向规则 |

表／字段先精确匹配：命中表走表级，命中字段走字段级；都不精确时优先表；仅表全不命中而字段精确／后缀命中时走字段。

#### 3.1–3.4 角色、基础操作、表与字段

- 无显式角色名时取角色主体；不得用权限用途／任务动作合成“对象+管理员／审核员”。允许／禁止复制内容、创建副本、导出下载、打印时只列字面操作，保留否定。

| 表目标 | 等级 |
|---|---|
| 看、查看、各看各的、阅读、浏览、访问、查阅、查询内容／记录 | 仅可阅读 |
| 编辑、修改、维护内容／记录 | 可编辑 |
| 明确管理表／字段结构、表配置、权限配置、整表结构 | 可管理 |

- “访问／进入／接触／能看到”默认只读；视图／选项管理、记录增删、基础操作、仪表盘不能单独定可管理。查看／阅读／浏览／访问／查阅／录入／填写／登记／打分／评分／编辑／修改／上报／提交／更新等动作直接定级。
- 职责动词单独作用于表内容：“管理 X”→可管理；“维护／处理／负责 X”→可编辑；同句有具体动作则按动作。阅读表／字段结构、视图／权限配置等元数据→可管理；管理带行条件的记录→可编辑+条件。同表全是阅读→只读；“不能删／改／编辑／更新／新增数据”只强化只读，不反推编辑／另写禁止。

字段语义写入承载表块：

| 原话 | 目标 |
|---|---|
| X、Y 可编辑，其余只读 | X、Y edit；其余 read |
| 所有字段只读 | all_read |
| 仅 X 不可见，其余可编辑 | X no_perm；其余 edit |
| 仅 X、Y 可见，其余可编辑 | X、Y read；其余 edit |
| X 编辑、Y 只读、其余不可见 | X edit；Y read；其余 no_perm |
| 仅编辑／阅读 X，无表级和其余语义 | 只写 X edit／read |
| 所有字段可新增／仅新增时填 | 所有字段 create |
| X 可新增，其余只读 | X create；其余 read |

“可新增／新增时写／仅新建时填／写后不可改”=create，非 edit。纯字段排他且无表级时不推断其余；同句有表级走 §4.2。

#### 3.5 记录权限与行级条件

- 新增／删除按 edit 默认；只给编辑范围时阅读范围与之相同，不扩大。结构见 [RecordRule](../references/permission-role-config.md#可读范围字段) 和 [同步表限制](../references/permission-role-config.md#记录操作与同步表限制)。
- 先核对 [可筛选类型和条件](../references/permission-role-config.md#可筛选字段与条件范围)。优先原文同名且类型可用字段；无／不支持才按 §1 换成可验证、严格等价的受支持字段；不能任换人员／创建人、用近似名或跳过行条件配宽表级；无法等价则报隔离未完成。
- “自己／本人／我”先定关系；“属于自己”≠“由自己创建”：自己创建→创建人；自己提交／录入→实际承载该身份的字段，缺失也不换创建人；指派／负责→被指派人／负责人；本部门／关联→组织／关联关系。点名人员字段按实际关系，不把发起人当负责人；裸“自己的记录”复用已确认归属，否则澄清，不猜。
- 当前成员绑定见 [匹配协议](../references/permission-role-config.md#字段类型与筛选算子的强约束关系)。Link 不可直接过滤；替换前核验结果类型、保存后条件有效、数据关系；无等价表达则未完成。验证“他人创建但归属本人”可见、“本人创建但归属他人”不可见；无代表记录／身份则保留静态边界；表级不能代替本人范围。
- 字段 = 选项A 的选项须来自该字段 optionList，按 §1 映射，不跨字段借值。

##### 3.5.5 数值边界与百分比还原

| 原文 | 条件 |
|---|---|
| 以下／不到／低于／不足／之前／以前 | 小于 N |
| 不超过／不大于／不多于／最多 | 小于等于 N |
| 以上／超过／高于／之后／以后 | 大于 N |
| 不少于／至少／不低于／达到 N 及以上 | 大于等于 N |

“以下／以上”均为开区间，不含 N。百分比按 [协议](../references/permission-role-config.md#百分比字段) 还原存储单位；边界仍按原文。

多条件：且／并且／同时／还要→且；或／或者／或是／任一／任何之一→或。混用时按“或”拆完整并列记录组，组内同对象条件用“且”；含至少 2 条件的组加括号；单条件组、纯且串、纯或串可不加。

#### 3.6 视图权限与表内操作

- 仅明示才写：禁新增／删除记录，禁管理／新增／修改／删除视图，禁管理选项 X，禁下载附件 Y。视图限制须有“视图”宾语；选项／视图管理、记录增删不等于表级管理；各项只写承载表。
- “禁下载附件 X”只限下载；“禁新增／编辑／修改附件（内容／字段）”按字段编辑禁止，不写禁新增／编辑附件。
- 单／多选字段的加／新增／增删／管理／维护／编辑选项，或只许新增／只能加／仅可维护选项，唯一写法是 允许管理选项 {字段名}；不拆成增改删，不跨表，不抬高表级。只有明示才配置；空列表与省略的含义见 [协议](../references/permission-role-config.md#选项与附件权限字段)。
- 提具体视图：all_visible=false，清单只含明示可见视图，其余隐藏；未提：all_visible=true。edit 按默认管理视图，read_only 不可管理。按 [ViewRule](../references/permission-role-config.md#视图权限-viewrule) 填完整结构，校验名称／非空。

##### 3.6.1 新增记录 + 部分字段可持续编辑

明确授权新增（含新角色填写／录入／提交）且只点部分字段创建后可继续编辑时：

1. record_operations 加 add；未明确授权删除不加 delete。
2. field_perm_mode=specify，禁用 all_edit。
3. 点名可修改字段=edit；其余可录入业务字段=create。
4. 按字段类型／同步表限制排除物理不可写的系统／派生字段。
5. 先映射真实 +field-list；不唯一则澄清，只处理已确认项，不放宽整表或 all_edit。

这是 §4.2 特例：add 要求新建时填完整业务字段，故未点名可写字段=create 而非 read；仅适用明确新增，不影响普通“仅编辑 A、B”；请求仍须满足 TableRule。

#### 3.7 仪表盘

点名仪表盘先映射再按只读／可见／隐藏／不可见写块；全集按 §2。

### 新建角色分支（§4）

表仍只按 §2 入选，不连带关联、兄弟或既有表。

4.2 字段正向授权（降一档）：具体字段带“仅／只／仅能／只能／仅可／只可”，或字段等级低于表级时，先定目标等级 L：阅读为 read，编辑／管理／维护／配置字段为 edit。表级=L，目标字段=L，其余字段降一档（edit→read，read→no_perm）；同等级也写三层。无排他词但有动作动词 + 具体字段／范围词时同样写三层，如 X、Y 可编辑、Z 不可修改→表 edit，X、Y edit，Z 和其余 read。范围词无任何字段命中时只写表级。

4.3 正向后紧邻“其他／其余／别的／剩下的+范围词／类指+不能看／不可见／看不到／不能编辑”，且指同表其余字段时，合并进既有“其余字段”，不触发黑名单／扩散他表；若指另一表／新点名独立字段则走 4.4。

4.4 黑名单：其他具体字段禁止仅收窄目标，不反推／改变表级、其余字段；无正向授权仍 no_perm，不为表达禁止扩权。

| 禁止 | 目标字段 |
|---|---|
| 阅读／可见 | no_perm |
| 编辑／修改／更新／管理／维护字段 | 最高 read；原 no_perm 保持 |

仍写表级／目标／其余三层；有正向授权不得以整表只读／无权限代局部禁止。未绑单表的范围词 deny：承载表=该角色按清单／主题获访问的全部表；逐表只展开原始字段并写三层，表级／其余（含派生）沿用正向等级；无命中仅留表级；不得整表禁用／漏表。

4.5 部分记录：未明确“其余记录可看”时，条件外隐藏。

| 需求 | 模板 |
|---|---|
| 部分可编辑，其余明确可看 | 可编辑, 仅可编辑{条件}的记录, 其余记录仅可查看 |
| 部分可编辑，其余隐藏 | 可编辑, 仅可编辑{条件}的记录 |
| 部分编辑、部分查看、其余隐藏 | 可编辑, 仅可编辑{A}的记录, 可查看{B}的记录 |
| 部分查看、其余隐藏 | 仅可阅读, 仅可查看{条件}的记录 |
| 全部编辑／查看 | 可编辑／仅可阅读，不写记录子句 |

仅本角色、本表出现“其他／其余／别的／剩下的记录+只能查看／只能看／仅可查看／仅可阅读／保持可见／还能看”，或“可见全表／全表可见／全部记录可见／能看到全部记录／能看所有记录”时开放其余可读。短语只绑最近一组角色+表+条件、用一次、不跨角色表；否则隐藏。只读范围即使带编辑否定也用部分查看，不抬编辑。

### 更新角色分支（§5）

只改明示／规则连带项，其他保持；不套 §4。完整单表更新：省略未涉及模块／表；目标表带完整 TableRule 并保留未涉及值。

#### 输出骨架与三层裁定

- 字段／记录／视图／记录增删／视图或选项管理／附件下载均写承载表块；仅原文明示“其他／其余／所有表”才枚举他表；仅有已满足的冗余禁止时不生成表块。
- 先判纯阅读（见下文“表级正向、查看与反向”）。其余需要写入的非冗余子权限变更（含字段隐藏等负向限制），若当前表级为可管理，表块必须以“表权限改为可编辑”开头。
- 每个“角色 + 表”分别读快照生成表块；“所有角色／两个岗位都”等对称措辞不代表当前权限相同，不套同一模板。
- 字段子句依次定①目标、②其余、③表级。X 快照低于表级则取快照，否则 X 当前=表级。仪表盘／基础操作无承载表，按 §3.7／§3.1–3.4。

语序：字段作主题“X 只能看不能改”=负向不能编辑 X，其余不排他隐藏；字段作宾语“只能查看 X”=排他，X=read、其余=no_perm。两类句式的表级都先按纯阅读用 read_only；只有同一角色、同一对象仍有明确有效的编辑要求时，才用编辑承载。第二类句式无论末尾是否带“不能编辑／不能改”，都按纯阅读。

① 目标：正向／排他看→read；编辑→edit；负向不能看→no_perm；不能编辑→最高 read（原 no_perm/read 保持）；改为／设为→字面等级。先判纯阅读；正向且当前≥目标则不写／不进②③；保留不等于排他。

② 其余字段：

1. 非冗余正向／覆盖／未满足负向：仅改 X，其余逐字段保留；源表 no_perm 时即使表升 edit 也不开其余。
2. 已满足负向：X／其余／表级保持；他授权另算，不从禁止扩权。
3. 排他：其余<X，已更低者保持；只能看 X→其余 no_perm；只能编辑 X→其余最高 read。
4. 阅读+编辑白名单：名单外交集=no_perm。
5. 白名单+独立黑名单：前者按①，后者只降点名字段，名单外按 1／2；启用字段自定义须显式写其余字段档位。

③ 表级：先判纯阅读；纯禁止／视图操作不因无编辑要求降 read；冗余禁止保持；非冗余子权限承载下限=①②最高级，manage 封顶 edit。

| 当前表级 | 目标 |
|---|---|
| 可管理 | 降可编辑以配子权限，不再更低 |
| 可编辑 | 保持；仅“只能查看 X”且有整表不能编辑信号时降只读 |
| 只读／无权限 | 升至承载下限 |

当前≠目标才写表权限改为{目标}；升档且其余保持时显式写实际等级；降档时未点字段随表级降。

#### 表级正向、查看与反向

整表且无字段／记录子集：编辑／维护→可编辑；明确管表结构且无子权限→可管理；查看／阅读／访问→只读（源 edit/manage 也降）；表级明确“保持不变／不修改／沿用原配置／保留原权限／其他不动”→保持；改／降为只读／可阅读→只读。

- 查看整表且无编辑动作→只读，可叠字段／视图／记录阅读限制；查看记录／字段且无编辑要求也只读；“在 X 表中”只定位。查看整表且同句编辑字段／选项→不压只读：源 edit/manage 保留，源无权限／只读升 edit，字段走三层。
- 表 edit 只给编辑记录条件时，阅读范围=编辑条件，不补“其余记录可看”；仅本角色本表明示才补，且只绑最近一组、用一次、不跨角色表。
- 反向按字面写入表块并查表级跃迁：撤销字段 X 不可见→X 改可编辑（或原文目标）；解除禁下载附件 Y→允许下载；去掉行条件→移除行条件。

### 冲突、排他、敏感与隔离（§6）

1. 表／字段／记录／视图／选项／基础操作／仪表盘分维度写，禁止不跨维度。
2. 正向访问+子维度收束：先写新建 仅可阅读／可编辑 或更新 表权限改为…；不写“保持原表级”／省略表级；旧高权限仅作冲突判断。
3. 字段≤表级：表只读／无权限则降字段／删子句；确需字段编辑且表有编辑／管理目标则升表至字段最高（manage 封顶 edit）。升表仅承载字段，不开记录增删／视图／选项；不确定则收窄。
4. 排他仅收窄目标资源／能力：“只让 X 新增”仅移除他角色 add，不删字段编辑；“只有 X 看全部数据”给 X 全表+仪表盘，并收窄其他自定义角色同范围。

敏感／保密／隐私表／字段／Dashboard 或“仅 X 可见”且列允许角色时，以其为白名单；其他自定义角色的敏感表 no_perm、复制／下载关闭；Editor／Reader 不收窄。敏感字段及关联／查找／公式带到他表的承载字段均须 field_perm_mode=specify、字段 no_perm。

按密级／是否敏感标记隔离：白名单保留；每个非白名单自定义角色在同表设 record_rule、other_record_all_read=false、按标记过滤的 read_filter_rule_group 并回读；不得仅改一个角色／白名单或将记录过滤写成字段权限。

人员行隔离覆盖所有可能访问表的默认／自定义角色；各角色用同一有效隔离或表 no_perm；获授权管理角色可全量。沿主体／字段核对关联／反向关联／Formula／Lookup 投影／Workflow 下游，在账本记源／承载／实际内容；主表条件不证明他表，存在关联也不证明泄露；回读字段／配置。

分别落实读取行／编辑行／字段；可填表单不授底表全量 edit；保留管理角色／未涉及配置和 edit 默认。承载路径超范围／能力不足则报缺口，不扩权／删关系／改数据。

view_rule.visibility.all_visible 只证视图可见；记录隔离须查 record_rule。当前成员条件仅在字段类型正确、回读 is_invalid=false、无其他全表可读路径时有效。

## 执行与提交

#### 查询状态与角色

按前置检查第 2–4 步查状态，再读角色完整配置；只读请求不授权开启。

#### 开启或关闭高级权限

按 [高级权限命令](../references/permission-commands.md)；开启前回读样例，开启后处理默认角色／验收；关闭前确认 Base／意图／影响，不替代前阶段验收。

#### 创建、更新或删除角色

按角色是否已存在选基线，填账本、定目标后提交；更新保留未涉及项。删除前读角色类型、目标和影响。

#### 自定义角色成员

按 [成员协议](../references/permission-role-members.md#适用范围与阅读依赖) 查身份、类型和权限；+role-list 取角色 ID，确认 role_type=custom_role；系统角色走下一节，不建自定义替代。

- 同应用／环境从通讯录／群聊搜 open ID 候选并确认；不存在／歧义先澄清；仅获授权才换用户／部门／群聊。
- 按 [写入结果](../references/permission-role-members.md#成员写入结果) 查失败成员 result_code、列现有成员；修因后仅重试未解决者，其他成员可能已生效；写后 +role-member-list。
- 移除不撤销全部 Drive/CCM 访问；他角色／分享仍可授权，须以受影响身份核验。数量、组合 ID 和去重见 [参数](../references/permission-role-members.md#参数与命令示例)，分页见 [返回](../references/permission-role-members.md#返回与分页)。

#### 系统角色协作者

按 [协议](../references/permission-role-members.md#系统角色协作者) 核对角色、Drive 路径／范围、成员类型、Wiki 范围、默认值；处理分享身份时直接用 Drive，不先读管理员角色。

- 先读授权并保留无关访问；未明确降级不得将 full_access 改 edit／view；移除前确认、移除后回读。
- 按 ID／类型／权限／Wiki 范围核对 data.items；移除成功不证明原授权存在。
- Drive 列表≠Web 系统角色精确成员清单；自定义角色匹配／继承／群组／分享开关均影响关系。不得以空 +role-member-list 报系统角色无人，或以 Drive 写成功报 Base 访问生效。
- 精确 Web 关系／实际访问须用受影响身份核验，否则说明未验；改分享授权／自定义角色成员须有独立意图。

#### 系统角色分享授权

只查用 +advperm-share-get；获授权后读→改→回读，成功回读才确认；临时测试后恢复原值。见 [协议](../references/permission-role-share.md)。

#### 提交访问申请

以申请人用户身份提交，不先管理员读取／代提；按 [结果](../references/permission-access-request.md#提交结果) 判状态；管理员处理后权限才变；超时先查申请／通知再重试。

### 配置生成与提交

只改获授权目标，但提交必要完整结构。按 [角色 JSON 输入](../references/permission-role-commands.md#角色-json-输入) 构造 AdvPermBaseRoleConfig。

#### field_perms 构造 SOP

| 步骤 | 动作 |
|---|---|
| 1 定目标 | 用真实全量字段：新建按默认值／§4；更新按逐字段现状／本轮约束。保留新建其余降档、更新未涉及项、排他／否定结果；不靠模糊“继承”，不因表 edit 把全字段重设 edit |
| 2 枚举 | 每个真实字段映射 no_perm／read／create／edit；§3.6.1 未点持续编辑的可写业务字段=create |
| 3 物理限制 | 按 [限制](../references/permission-role-config.md#字段类型与同步表限制)；不可写字段的可见目标降 read，不可见仍 no_perm |
| 4 筛选字段 | 表 edit 且字段目标 edit 时保持，除非明确降级；作为筛选不强制 read 或 edit |
| 5 筛选依赖 | 按 [最低权限](../references/permission-role-config.md#筛选字段的-field_perms-权限约束) 校验；与明确不可见冲突则保留未完成，不静默扩权 |

field_perm_mode：整体“所有／全字段”且不管选项→all_edit／all_read；字段有差异或要求选项增删改→specify；仅系统字段物理降级不触发 specify。“仅／只能／部分”沿用已定范围，不重推；再按 [字段协议](../references/permission-role-config.md#字段权限-fieldrule) 校验枚举／附加操作。

#### 提交前检查与更新协议

1. 核对输入、必填结构、枚举、技术限制；请求逐项对应目标／保留范围。
2. 更新复用有效完整配置，只改目标表 TableRule，按完整单表协议提交；完整结构不授权重置未涉及字段／记录／视图。
3. 保存真实 ID／结果；写后立即回读；不确定则恢复。

## 回读验收

### 按操作回读与验收

| 操作 | 证据／通过条件 |
|---|---|
| 状态／角色读取 | +base-get／角色结果准确；关闭时不以空列表判状态 |
| 高级权限开关 | +base-get 符合目标；开启后默认角色处理和权限验收完成 |
| 角色增改删 | +role-list + 逐角色 +role-get；目标、禁止、保留项均正确 |
| 自定义角色成员 | 成员读取和部分成功信息；身份、角色、最终关系正确，失败不算成功 |
| 系统角色协作者 | Drive 回读 ID、类型、权限、Wiki 范围；不当作 Web 精确清单 |
| 系统角色分享 | +advperm-share-get 符合目标；临时值已恢复 |
| 访问申请 | 有提交／通知证据；管理员处理前不声称已获权限 |

实际 Base 访问须用受影响身份证明，无法取得时说明。证据不足标 blocked，不以“角色已创建”或“管理员默认有权限”代替目标状态。最终答复列出：启用高级权限后的初始角色列表、本轮新建角色的 ID 与用途、系统角色是否被改动。

### 角色配置与全角色安全验收

先 +base-get。授权准确且读／写范围分别成立，“看”只授阅读；未授权自定义角色不得访问／增删／复制／下载敏感数据。启用后无“普通用户”、题面角色齐全；新角色无关表 no_perm；完全未提表权限则保持默认。

每个编号／多轮权限步骤写后立即：

1. +role-list 枚举全部系统／自定义角色；逐个 +role-get 完整配置。
2. 逐账本核对 perm、record_operations、field_perm_mode、相关 field_perms、record_rule、copy、download；行／字段限制分开核对；空 record_rule／全继承不证隔离。
3. 用已有结构／记录各核一个允许／排除范围；沿关联／反向关联／投影／下游承载查有效性／绕过；无代表记录保留静态边界，不造业务数据。
4. 任一即未完成：允许主体缺目标能力；排除主体仍有禁能；新角色仅许部分字段修改但回读 all_edit；只获“看”但 perm != read_only。
5. 只修获授权且违规的角色／能力，再完整 +role-list／逐角色 +role-get；角色总数须等于按 role_id 去重的成功回读数。全过再进下一步；后续扩权／删角色／+advperm-disable 不替代前验收。

未点名系统角色保持默认；其路径破坏隔离则 blocked。本会话前序明确且未撤回的授权仍有效。配置核对≠身份实测；仅有授权／身份时实测，否则说明边界。

## 异常恢复

保持目标／授权范围，不为消错放宽；错误码／参数／部分成功信封见对应 Reference。

| 状态 | 恢复 |
|---|---|
| 参数／JSON／枚举失败 | 按 [角色命令](../references/permission-role-commands.md)、[配置协议](../references/permission-role-config.md) 或操作 Reference 定向修正 |
| HTTP 404、非 JSON、环境／身份不匹配 | 核对路由／主机／环境／应用／身份／错误；不据此判状态／写成功 |
| 超时／结果未知 | 先读状态；复用完成项，不重放整批；访问申请先查申请／通知 |
| 成员部分成功 | 查成功／失败者，仅处理未完成项并回读 |
| 写成功但验收不符 | 只修获授权失败项并复验；系统角色路径不可收窄则 blocked |
| 能力／权限限制 | 报未完成项／缺失证据；不扩范围／换身份绕过 |

解析失败只修解析，不重放成功写入。同因仅定向修复／复验一次；仍失败则 blocked，继续不依赖项。保留完成对象／证据，报告失败调用／未验证内容，遵循 [恢复预算](../SKILL.md#异常恢复与停止条件)。
