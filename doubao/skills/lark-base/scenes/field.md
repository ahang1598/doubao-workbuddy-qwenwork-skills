# 字段管理

授权、完成态、恢复预算沿用[主入口](../SKILL.md)；操作细节见 Reference。

## 开工必读

- `+field-create` 仅有 `--json`，无 `--name/--type/--from/--select`；单字段也传数组 `[{...}]`。只建 1 个字段时返回 `data.field`，2 个及以上返回 `data.fields[]`，统一取 ID：`--jq '(.data.fields // [.data.field])[].id'`；`data.created` 是布尔。字段 JSON 与建表相同，见[示例](../references/field-commands.md#调用示例)。
- 公式／查找字段先读 [Formula / Lookup](field-formula-lookup.md)，再带 `--i-have-read-guide`；公式写在字段对象顶层的 `expression` 键（不包成 `formula:{…}`／`property:{…}`，否则报 `Request validation failed with 2 issues`），formula 不收 `style`，lookup 必带 `where`；不等用 `!=`，`<>` 报 compile failed。
- 公式报 `validation_error: validation_error` = 字段重名；引用不存在的字段、未知函数在创建时不报错。建前 `+field-list` 查重；失败后先查是否已建，不换表达式反复试。
- `+field-update` 用 `--field-id` 并带 `--yes`；改 formula／lookup 时同样带 `--i-have-read-guide`。

## 任务导航

先做适用的前置检查，写后做回读验收。

- 查字段：[查找与完整性](../references/field-commands.md#字段查找与完整性)；解释配置时加读对应类型协议。
- 新增字段：[创建命令](../references/field-commands.md#创建字段field-create)、[字段 JSON](../references/field-config.md)；修改或转换类型：[更新命令](../references/field-commands.md#更新字段field-update)。
- 选项：[选项协议](../references/field-options.md)；插件：[字段插件](../references/field-extension.md)；通讯录信息列：[补全协议](../references/field-contact-enrichment.md)；删除：[字段命令](../references/field-commands.md#调用与边界)及子命令帮助。
- 按钮字段和工作流绑定读[按钮协议](../references/field-button-binding.md)；流程定义、启停和执行进入 [Workflow](workflow.md)。
- 写记录、上传附件、迁移单元格用 Record。新建 Base / Table 时同时完成 Base、Table、Mock 验收；只处理字段时不扩大成整库搭建。

## 前置检查

### 目标与授权

- 确认 Base／Table／字段；可信 ID 直接读，否则查找定位；未读全不得判不存在。
- 目标、操作明确就在授权内执行并带确认参数，写操作不重复确认；歧义、未授权损失／依赖改动先澄清。
- 删除前记目标、保留字段、影响依赖；只删明确且唯一确认字段，禁删其他字段替代。

### 当前配置与存量数据

- 更新前取字段、详情、完整选项；可复用有效可信结果；识别主列、签字、关联、动态选项、系统／计算、通讯录派生列、插件。
- 判断损失／迁移，按记录协议取原值、范围、异常值、多值分布、须保留生成结果；抽样不证明整列空／无损；是否读选项值由选项决策定。
- 只查受影响视图／筛选／分组／排序／公式／Lookup／关联／写入引用并记保留语义；读取不全就留缺口，禁做可能丢数据的转换／迁移。

### 源字段与依赖准备

计算／关联／派生前确认源、目标结构；跨表必读对侧，名称、ID 以返回为准。先建普通源字段、跨表关系，再配计算／插件／按钮／通讯录补全。已有表不造事实验收；新表样例用 Mock。

## 字段决策

适用于新 Base、单独建表、已有表新增字段。

<a id="建模表结构与字段类型"></a>

### 字段类型选择（含公式、关联）

类型标识与 JSON 见[字段类型速查](../references/field-config.md#字段类型速查)。

| 数据语义 | 选型 |
|---|---|
| 状态、类别、优先级、等级 | 单选或多选，不用自由文本 |
| 数值区间分档 | 单选；边界值只能落一个选项，如 `0-2`、`3-5`、`6 及以上` |
| 金额、价格、预算 | 货币数字 `{"type":"number","style":{"type":"currency","precision":2,"currency_code":"CNY"}}`，按业务定币种／精度 |
| 完成度、占比 | 进度数字 |
| 评分、星级、满意度 | 评分数字；保留要求的评分语义 |
| 日期、时间 | 日期时间 |
| 电话、手机、邮箱、网址、条码 | 文本加专用样式，如 `{"type":"text","style":{"type":"phone"}}`，`style.type` 取 `phone`／`email`／`url`／`barcode`；不用普通文本，顶层写 `"type":"phone"` 会存成普通文本 |
| 负责人、参与人 | 人员；按业务选单／多人 |
| 是非、是否完成 | 复选框 |
| 文件、图片、扫描件、文档 | 附件；上传须传原件，禁用文本摘要替代 |
| 记录编号、单号 | 自动编号 |
| 创建、修改的时间与人 | 系统时间／人员 |
| 地理位置 | 地理位置字段 |

- 本表内计算用 `formula`：小计（数量×单价）、总分、平均分、是否逾期、是否达标、距到期天数、文本与日期处理。用户说“自动算”“不用手动加”“一眼看出达标与否”时用公式字段。
- 基于已有数据做统计、汇总或派生时用 `formula` / `lookup` 动态计算，不先静态算好再写回普通字段；只有事实录入值才用普通字段。
- 逐项写明来源：时长取起止事实和明确的业务日历，人数取实际关系，主档当前属性取关联投影。历史快照或独立含义的日期可单独存，不因值相似判为冗余。工作日、半天口径不明先澄清。审批结果、处理完成由真实业务产生，不用公式猜测或发通知代替。
- 录入时就确定的对应关系用关联字段登记，如订单指向客户。指向 Base 中已有实体表（客户、供应商、人员档案等）时也建关联并写对端记录 ID，不另建同名文本手填。来源数据的单号、批次号、合同号保留原值作独立字段，不改成自动编号或塞进备注；主表与流水表拆分见 [1:N 建模](build-system.md#新建-base-前的-1n-建模)。
- 展示对方信息时从关联字段派生，不手填。关联字段名避开表名。
- 两表由不同来源各自登记、按字段值对应时，用公式比对用户指定的全部业务键（如付款方、日期、金额）；缺这些字段就在建模时补齐，按天匹配时统一日期口径。对侧没有用户指定的日期字段就先新建，不用签订日期、创建时间等相邻日期顶替。结果带回对应信息或匹配状态，不改成手选关联。写法见[多字段匹配](../references/field-formula-expression.md#多字段匹配与取值)。

### 默认值、精度与配色

- 只在用户要求时设默认值，新表、已有表都一样；新表样例按 Mock 逐条填。
- 新增状态字段不授权断言历史状态；回填须有本次授权和真实事实，不统一填“未开始”去凑字段或视图条件。
- 普通数字显式定精度：人数、件数、名次、完整年数等离散量 0 位；测量值、比例等连续量按要求／业务需要。
- 未要求配色就保留默认样式。

### 业务口径与源字段

关键口径不用未确认的相邻字段，缺源字段就新增或澄清；过期／临期须有“到期日期”或明确起算日；到期日由起算日和周期得出，不借录入日期。随时间变的状态用公式。

### 派生能力选型

- 同行数据的总结／分类／翻译／提取可用 prompt 表达就用字段插件；输出类型须符合能力；先建输出列。
- 部门／直属上级／工号等通讯录属性：用符合来源限制的人员／创建人字段建补全；禁用普通字段／手填模拟。
- 需 Workflow AI 节点就按 Workflow 选型；字段生成不授权额外创建／启用工作流。

### 字段类型变更规则

按“接口能力→存量影响→授权与路径”判断；同样覆盖样式、选项、多值、编号规则变化。

| 环节 | 规则 |
|---|---|
| 接口 | 按转换限制核对；接口禁项无数据风险例外。能力不明先查；不支持就说明限制、选支持路径 |
| 存量／语义 | 保值保义就执行已授权转换；会空／截断／重算／丢义，仅损失已明确接受才继续，否则说明并确认；已接受不重问。系统／计算字段还查审计、逻辑、下游引用 |
| 原地例外 | 无保值保证就用客户端操作／新字段迁移。接口支持且满足其一才原地转：整列已验空；新空表初始化；用户接受具体损失（含整列变空）。主列也须空／获损失授权，禁因无法删除而覆盖 |
| 不满足 | 禁原地转；新字段迁移须查可迁移性、授权，禁把须保留计算／联动降为静态复制 |

### 选项变更决策

先按选项协议区分静态、动态来源，再判存量值是否失效。

| 变更 | 执行 |
|---|---|
| 仅新增、调顺序／配色，旧名与含义不变 | 保留配置并普通更新；不扫描／重写记录 |
| 改名、删除、合并，完整检查确认旧值未使用 | 直接更新已授权配置；不做空迁移 |
| 已使用选项改名、删除、合并／变义 | 明确旧→新映射并迁移；未映射旧值不得丢弃 |
| 动态／静态来源切换或修改动态来源 | 按 Reference 接口限制判断，不套静态选项迁移 |

## 执行与迁移

每步写后回读再继续；后续覆盖／删除不得掩盖前错；部分成功／异常进入异常恢复。

### 读取字段

读任务所需列表、完整定义／选项，解释实际类型、样式、来源、限制；只读任务仅报告范围、缺口，不修正建模、迁移、生成插件。

### 创建字段

按协议提交定义；同表多字段优先批量；依赖须先就绪时分步；通讯录派生列走补全流程。

### 更新字段

按协议提交定义，保留未要求改的配置；只读、关系维护、特殊字段用支持操作。现状等于目标时不重写，直接验收。

### 新建字段并迁移

1. 确认源可读、目标可写、映射明确；留存源定义、范围内记录 ID／原值。签字／系统派生关系不得用普通单元格重建；只迁移授权的记录、依赖、旧列范围。
2. 建目标并验结构，再按 Record 写授权值；无法映射就保留、报告，不以空覆盖。
3. 核对目标值、源值；通过后才调授权依赖；中断按迁移未完成续做。
4. 按既定策略处理旧列；仅获删除授权且目标值、依赖验收通过后删除。

### 修改已有选项

仅选项变更决策判定需迁移时执行：

1. 取完整旧选项、范围内记录 ID／原值，保留映射、不变项；补齐计算依赖。
2. 用 `+field-update` 加新选项，暂留仍被引用的旧选项。
3. 用 `+record-batch-update` 按映射迁移；单／多选形状按选项协议；保留未涉及记录值、多选其他选择。
4. 选项迁移验收通过后才删旧选项／调最终顺序并验定义；中断进入迁移未完成。

### 配置或触发字段插件

1. 定位输出字段，按插件读取协议查现状；需新增就先创建、验收。
2. 按目标安装、更新／清空配置；遵守写入格式、自动更新协议。不支持目标运行方式就说明限制，不承诺额外模式。
3. 仅明确要求立即生成／刷新时触发；默认精确到指定记录，整列刷新须明确授权。按范围协议核对记录／视图，分别验收配置、生成。

### 创建通讯录补全列

1. 按来源限制核对源字段、已有关系，复用符合目标的关系。
2. 用专用命令建派生列；多个补全项可一次提交；核对关系、实际值。
3. 保留系统生成列名称、定义，不为美化调用普通字段更新；用户要求改名前确认支持操作能保留关系，技术限制下不能保留就说明。

### 删除字段

按目标与授权执行 `+field-delete`；被拒就按限制处理，不删其他列／改类型绕过；验收结构、保留对象。

## 回读验收

复用最后一次相关写入后的有效读取；完成态遵守主入口协议。

### 字段保存定义验收

- 按创建／更新返回选详情读取，核对目标、保留配置；要求属性无证据就补读。简单创建不固定加 get；结构列表仍按下表验收。
- 电话、手机、邮箱、网址同时核对类型、样式；数字核对精度、货币、进度／评分配置。

### 结构验收矩阵

| 范围 | 证据与通过条件 |
|---|---|
| 仅操作已有表字段 | 目标表 `+field-list` 核对新增、保留、删除，详情按需 get；有可信表 ID 不枚举无关表 |
| 新建／调整 Base / Table | `+table-list` 核对目标表；`+field-list` 核对相关字段、关联；继续 Base / Table Scene 验收 |
| 修改关联／影响对侧表 | 核对关联目标、对侧字段、实际关系；按关联建模验两侧 |

判定删除／不存在时按完整读取要求核实，并确认受影响保留对象可读、语义一致。

### 存量值与依赖验收

- 转换后读完整定义、代表性单元格，核对保留值、已接受损失、目标语义；覆盖已识别异常值；抽样不得宣称整列无损。
- 收缩多值、改编号规则／样式时核对真实数据、影响；替代字段迁移须覆盖授权记录，验证映射、源值保留。
- 涉及视图、看板、筛选、分组、排序、Lookup、公式、写入引用时核对结果；类型正确不等于下游可用。
- Formula / Lookup 按计算字段协议验代表性分支；无真实数据的分支注明未验证，不改已有表凑验收。

### 选项迁移验收

删旧选项前确认映射、未涉及值、迁移范围正确，且待删旧值全表计数为 0。部分迁移时保留其他记录仍用的旧选项；局部视图／子集为 0 不证明整列可删。

### 专项结果验收

| 能力 | 必需证据与通过条件 |
|---|---|
| 字段插件配置 | `+field-extension-get` 核对；清空结合写入、读回；按返回语义判断证据 |
| 生成／刷新单元格 | 按异步返回记提交状态；`+record-list` 查目标记录；注明抽样范围，不称全范围完成 |
| 通讯录补全 | 最后一次结构写后用 `+contact-field-enrichment-list` 核对来源、补全项、生成列、关系健康；再用 `+record-list` 核对源人员、派生值；错误按补全协议解释 |
| 按钮工作流 | 用绑定读取命令核对目标工作流；定义、启停、用户要求的真实执行结果分别按 Workflow 验收 |

通讯录关系不存在／报错时不得称联动完成，不手填掩盖。关系正常但派生值为空时分别报配置已验证、取值未验证；仅查到源人员真实通讯录信息后解释空值，不凭空值断言未设置组织信息。

### 完成条件

结构、值、关系、下游结果全通过才声明完成并交付对象、验证范围；否则按主入口协议列未完成项、缺失证据，包括生成未完成、读取不全、缺代表性样本。

## 异常恢复

重试预算、结果未知时的读取、停止条件沿用通用恢复。

| 故障 | 恢复 |
|---|---|
| 批量创建部分成功 | 按部分成功协议续做，再验新字段、业务要求 |
| 更新结果异常 | 按更新异常协议核实现状；类型不匹配／no-op 不能替代定义、存量依赖核验 |
| 签字字段异常 | 创建被拒／更新误降级时按签字协议停止不安全路径；恢复方案单独验证后再继续 |
| 通讯录补全异常 | 按返回与限制协议定位来源字段／权限；关系不存在时核实最近结构变更，不立即重建；修复后重验；仍受阻就报告联动未完成 |
| 字段插件权限不足 | 按 Base 权限或高级权限角色确认用户权限 |
| 插件生成未完成 | 保留任务 ID、范围、已读结果，不因空值重触发；按工具支持的等待／后台机制续验；无完成证据就报告已提交、未完成范围 |
| 评分范围过大 | 按评分协议核对平台限制；被拒后说明普通数字或进度字段等替代，不静默替换评分语义 |

### 迁移未完成

先读现状，对照记录 ID、原值、映射，只续做失败／未迁移记录，不重建字段／覆盖成功结果。映射冲突、读取不全／验收未过时保留源列、仍用旧选项，停止清理并报告余量。
