# 仪表盘组件布局 Reference

## 适用范围与布局前置

写 `--layout` 前先读完 [视觉规范](dashboard-visual-standards.md)，按它选骨架、取 `w/h`、自检硬约束。

## 精确布局：48 列坐标

坐标一律按 48 列写，不做换算。`x`、`y` 是左上角坐标（`>=0`），`w` 是宽度（`1<=w<=48` 且 `x+w<=48`），`h` 是高度（`>=1`）。

CLI 写入和读回都按 48 列：list、get 读到的和 create、update 回包里的 `position` 与提交坐标同一套栅格。服务端未返回像素坐标时，CLI 按取整坐标折算并在 stderr 提示精度有损。

## 坐标输入与校验

### 全盘坐标 --layout

- `--layout` 只接受数组 `[{"block_id","x","y","w","h"}]`，四个坐标键齐全且为整数；支持 `@file` 和 `-`（stdin）。本地逐项校验范围，不满足就报错并一格不写。
- `--layout` 必须覆盖盘上全部组件。漏组件、写了盘上没有的 `block_id`、同一 `block_id` 出现两次，都会报错列出 ID，一格不写。
- 空洞和重叠不在本地校验，提交前自己检查。

### 组件坐标 --position

`--position` 的 `x`、`y`、`w`、`h` 必须齐全且都是数字，显式 `null` 会被拒绝。`position` 整体提交、不逐字段合并，只传 `{"x":6}` 会被本地拒绝。不传时 create 由服务端自动放置，update 保持当前布局。

## 写入与整理行为

`+dashboard-layout` 依次执行：校验坐标范围 → 读现状 → 校验覆盖全部组件 → 一次批量写入坐标有变化的组件（都没变就不写）→ 调用服务端兜底整理 → 输出整盘最终坐标。

stderr 出现“服务端没有返回 standard_position”时，只表示读回坐标由 12 列取整值换算，每个坐标可能差 2 格以内；写入仍按 48 列生效。已有看板追加或调整时，新组件尺寸按 [组件尺寸](dashboard-visual-standards.md#组件尺寸) 取值，不按读回的 `w/h` 成倍推算。

兜底整理每次都执行，会填补盘上所有空洞（包括原本就有的），处理重叠和越界；它可能挪动或拉宽你没改的组件，但不决定盘面结构，也不居中或对齐。

## 返回结构

`+dashboard-layout` 的 stdout 在 `data` 下，如 `--jq '.data.layout'`：

| 字段 | 含义 |
|---|---|
| `written_block_ids` | 实际写入的组件（坐标与现状不同） |
| `tidied_block_ids` | 被兜底整理挪动的组件，可能包括没改的；stderr 逐个说明从哪移到哪 |
| `layout` | 整理后整盘最终坐标（48 列），是验收对象 |
| `grid_cols` | 坐标口径，恒为 48 |

以下属于写入异常：任一组件 `x+w>48`；尺寸或 `y` 成倍放大；两组件坐标相同；原本并排变成整宽堆叠；新建看板有空洞。修正坐标重提一次仍异常时标 `blocked`。

create 成功、带 `--position` 的 update 成功后，stderr 会提示用 `+dashboard-layout` 提交全部坐标。

## 部分成功的含义

兜底整理失败时命令报错，但批量写入已生效，stderr 写明已写入的组件；按 [布局失败恢复](#布局失败恢复) 处理。

## 调用示例

```bash
lark-cli base +dashboard-layout --base-token xxx --dashboard-id blk_xxx \
  --layout '[{"block_id":"<block_a>","x":<x>,"y":<y>,"w":<w>,"h":<h>},{"block_id":"<block_b>","x":<x>,"y":<y>,"w":<w>,"h":<h>}]'
```

## 布局失败恢复

- 漏交组件时，按报错把缺少组件的真实原坐标补进完整数组。多交、重复 ID、坐标越界等本地校验失败时一格未写，修正后再提交。
- 批量写入成功、整理失败时，用同一份 `--layout` 重新调用，已一致的组件不会重复写入；不要重建组件，也不要当作零写入。
