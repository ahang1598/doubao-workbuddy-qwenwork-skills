## 适用范围与入口

本文是仪表盘组件 `x/y/w/h` 的唯一规划依据；用户指定的坐标、行列数、尺寸比例、顺序优先于通用取值。

| 场景 | 执行口径 |
|---|---|
| 新建且用户未提布局 | 执行分栏要求、全部整盘硬约束和自检；整盘重排/美化但未给排法时同样处理 |
| 用户指定位置、顺序、同一行等 | 按要求排；未指定部分按本文，不强制分栏 |
| 已有看板追加 | 保持原坐标；新组件放空位或末尾；只为铺满其所在行而调整同行组件，不强制分栏 |
| 定点移动、缩放或放入空位 | 只改目标组件；兜底整理可能上移下方组件补位，以 `+dashboard-layout` 输出为准 |

最底部为 `view`/`pivotTable` 时，把新增组件插在其上方。先并入上方末行，按列基线收窄同行组件并铺满；容不下时占用表格原 `y` 成行、下移表格，该行仅此组件时允许 `w=48`。

任何场景均禁止重叠、越界（`x+w≤48`）。用 `+dashboard-layout` 提交；禁止逐个 `+dashboard-block-update --position` 或加 `--no-validate`。

## 坐标体系

画布为 48 列固定宽度、无限高度 Grid；组件为矩形 `(x,y,w,h)`。

| 量 | 含义 | 取值 |
|---|---|---|
| `x` | 左上角起始列 | `[0,48)` |
| `y` | 左上角起始行 | 从 0 起，无上限 |
| `w` | 列数 | `w>0`，`x+w≤48` |
| `h` | 行数 | `h>0` |

### 追加到底部：按实际底边累加

为避免与现有组件重叠而追加到底部时，用 `+dashboard-block-list` 读完全部分页，在同一套 CLI 48 列坐标中计算 `bottom = max(y + h)`，空仪表盘取 `bottom = 0`。新行从 `y = bottom` 开始；`y` 不是像素，不要额外乘以 4，也不要混用原生 `api GET` 的 `position` 与 CLI 快捷命令的 `position`。

- 默认紧接现有底边，不加人为安全留白；用户明确要求间距时才加对应的栅格间距。
- 依次追加多行时，每行从上一行底边累加；一行有多个组件时，下一行从该行最大的 `y+h` 开始。不能只看列表最后一项，也不能把所有组件高度相加。
- 例如现有最大底边为 `58`、新组件高 `16`，则新组件 `y=58`，下一行 `y=74`。不要用 `120`、`240` 等与实际底边无关的大坐标兜底避让。
- 宽高按组件类型、用户要求及周围组件尺度选择，不因追加到底部就强制 `w=48` 或放大高度。底部表格的插入例外仍按上文：在表格原 `y` 插入，并按新增行高度下移表格，不制造空白。
- 缺少精确坐标且 CLI 提示近似换算时，不靠不断增大 `y` 掩盖误差；按现有流程提交 `+dashboard-layout`，检查返回的最终坐标是否重叠、越界或产生不必要的大空白。无法确认时说明布局验证受限，不把“坐标写入成功”当作布局合理。

## 位置关系

| 关系 | 判定 |
|---|---|
| 同行 | 两组件的 y 区间相交 |
| 同列 | 两组件的 x 区间相交 |
| 相邻 | 水平或垂直边缘紧贴，中间无空隙 |

## 布局选型

| 模式 | 结构 |
|---|---|
| 行列式 | 先分行再分列；行内横排、行间纵叠 |
| 分栏式 | 先按主题/功能切矩形区块，区内再用分栏或行列式细分 |

优先分栏式复合结构，再用行列式；两者允许嵌套。

### 分栏适用条件

分栏区块：左右分别纵排，水平分界线错开且底部齐平；一侧主趋势图、排行榜、表格或 2×N 指标卡块跨过另一侧至少 2 个矮组件。

等高 2×N 网格、左右每层均对齐的同高堆叠仍是行列式。

仅新建场景执行：组件 ≥5（不计 `text`、`slicer`）时至少设一个分栏区块，禁止整盘仅行列式；组件 <5 时按决策表成行。

无图表、仅指标卡或指标卡加表格时不强制分栏：指标卡排一行或 2×N，表格整行置底。指定排法、追加、定点修改不适用。

命中复合条件即用纵向分栏或 2×2/2×N 指标卡组，禁止一图一行。排坐标前先按组件构成定结构；复合结构同样满足全部[硬约束](#硬约束)。

### 按组件清单选结构

先统计指标卡（`statistics`/`progress`/`nps`/`countdown`）、图表（柱/条/线/饼环/组合/雷达/漏斗/排行等）、表格（`view`/`pivotTable`）、控件（`slicer`/`text`）：

| 条件 | 动作 |
|---|---|
| 指标卡 ≥4 | 排一行或 2×N（如 2×2、2×3）；全部集中在顶部同一行或侧栏同一栏，不拆散。指标卡为主（图表 ≤2）用骨架 A：左栏指标卡 2×N 成块，右栏图表与左栏齐平；无图表时指标卡排一行或 2×N 铺满 |
| 指标卡且图表 ≥2 | 优先纵向分栏：左栏 2×N 指标卡、右栏等高主图；或“顶部指标行+骨架 B+底部表格” |
| 图表 ≥3 | 至少有一处用最核心的趋势图或排行榜作高主图（如 `w=32`）、旁边纵叠 2 个矮图（如 `w=16`）的分栏区块，剩余图表两两并排；任一图不占 `w=48`，禁止全排等高 2×N。不受组件总数限制，组件 <5 时同样适用 |
| 图表恰好 2 | 各取 `w≈24` 并排；禁止单图独占满宽，表格/透视表除外 |
| 1 个图表 + 1~2 张指标卡 | 排成分栏：指标卡在左栏（`w=12~16`）纵向叠放，图表在右栏（`w=32~36`），图表高度与左栏指标卡块齐平；不让图表和指标卡各占半宽，也不把指标卡拉成整行 |
| `view`/`pivotTable` | 独立整行置底，允许 `w=48`；上方指标卡与图表按骨架 A/B 分栏，表格不参与上方区块 `H` 结算 |
| `slicer` | 置顶或置左，`h=3`；多个切片器放同一行 |
| `text` | 仅用户要求时加入，`h=3`；按下表定位，禁止把多个文本集中堆顶 |
| 未命中或多而杂（图表 ≥6 或多类型混杂） | 按主题或类型切 2~3 区，区内套骨架和对齐算法，禁止退回 1×N |

| 文本用途 | 位置 |
|---|---|
| 整盘标题 | 第一行 `y=0`、切片器上方；单独 `w=48`，或与切片器同排铺满 |
| 分区副标题 | 紧贴所属区块上方且同宽；满宽区块取 `w=48`；区块组件均放在它下方，直至下一副标题 |
| 说明/解读 | 放相关区块上方；无法判断归属时置顶并排在整盘标题后 |

### 避免单组件过度拉伸

- 除[单组件例外](#硬约束)外，单个非表格图表不要独占 `w=48`；优先取 `w≤32` 并与其他组件并排。
- 保持宽高比：饼/环/雷达约 0.6~3.5，柱/条约 0.5~4，折线/面积/组合约 1~5。组件少且不满足单组件例外时用分栏或并排填满。

## 硬约束

任何场景均执行禁止重叠、边界限制。新建场景 100% 执行其余约束；追加、定点修改禁止为此挪动非目标组件。

| 约束 | 判定/修复 |
|---|---|
| 禁止空洞 | 完全覆盖 `[0,48)×[0,Y_max)`，`Y_max=max(y+h)`，无空白单元格 |
| 禁止重叠 | 组件矩形不得相交 |
| 边界限制 | `x+w≤48`；纵向无限 |
| 水平铺满 | 任意 y 截面的 x 投影为 `[0,48)` |
| 末行铺满 | 最后一行也填满 `[0,48)`；除单组件例外外，仅表格/透视表可独占满宽。整盘不止一个组件而末行仅剩非表格组件时，将它与上一行并排或并入上方分栏，禁止拉到 48 |
| 垂直紧凑 | 任意列 x∈[0,47] 上的组件从 y=0 紧密堆叠，无垂直间距 |
| 底部齐平 | 所有列底边对齐 `Y_max`，无锯齿底 |
| 面积校验 | `∑(w_i*h_i)=48*Y_max`；不等时调整尺寸 |

**单组件例外**：新建看板默认不要只放一个组件。用户只点名了一个分组图表时，按 [Dashboard Scene 的默认组件构成](../scenes/dashboard.md#默认组件构成) 补一张同源的总量指标卡，按“1 个图表 + 1~2 张指标卡”分栏排布。只有用户明确表示只要这一个组件时，才允许整盘只有一个非表格组件（非 `view`／`pivotTable`），此时可取 `x=0,w=48`，从 `y=0` 开始，仍须满足类型高度、合理宽高比、无重叠、边界检查与 `+dashboard-layout` 收尾。按全部实际组件计数，含 `text`/`slicer`。

仍执行类型高度、合理宽高比、无重叠、边界检查和 `+dashboard-layout` 收尾；禁止为凑布局新增组件。组件 ≥2、追加、定点修改、既有看板整盘重排、用户指定布局均不适用。

**类型约束无解时停止**：单个 `funnel`/`ranking` 的 `w≤h`、`h:12-24` 与 `w=48` 冲突。确认无解后，按[通用完成与停止协议](../SKILL.md#异常恢复与停止条件)把该布局验收项标记 `blocked`，说明冲突并停止自动布局。

禁止提交违规坐标、循环调整、放宽高度或比例、新增组件或宣称通过；继续执行不依赖该项的任务。

尺寸规则：

- 按类型推荐区间取值；未指定时 w∈[12,36]、h∈[12,24]；单组件例外仅宽度可取 48。
- 并排的同类组件高度一致，分栏区块的主高图除外；同类组件相邻放置成区块。
- 指标卡 h≥5，优先 `h=6`；与图表同行时增高对齐。文本、切片器 `h=3`；其他图表 h≥12。

## 分栏对齐算法与常用骨架

骨架只规定组件落在哪栏、哪行；坐标由对齐算法按实际组件数结算，不硬套。

### 分栏对齐算法

1. 为并列区块设共用总高 `H`，各栏均结算到 `H`。
2. 一栏纵叠 `k` 个组件时，先令每个 `h=floor(H/k)`，再把余数 `H-floor(H/k)*k` 全补给最后一个组件，使总高等于 `H`。
3. 令各栏同高；栏宽拼满 `[0,48)`，如 16+32 或 24+24。
4. 参考推荐高度取 `H`：指标卡分组区约 16，含图表分析区约 28~36；令每个结算高度落入其类型推荐区间。
5. 顶部指标行、底部表格行独立取 h，不参与 `H`。

统一全盘列基线：如 2 栏 `[0,24)[24,48)`、3 栏 `[0,16)[16,32)[32,48)`、4 等分 `12/12/12/12`。相邻行切分点落在同一基线，不在这一行切 x=16、下一行切 x=20。顶部指标行、底部表格等整行组件可跨基线满宽。

### 常用骨架

| 骨架 | 适用 | 结构 |
|---|---|---|
| A：左指标/右分析 | 指标卡为主+2~3 图表 | 左 `[0,16)` 放 2×N 指标卡并允许再叠 1 图；右 `[16,48)` 纵叠图表；两栏同 `H` |
| B：顶部指标+中部分栏+底部表格 | 指标卡+多图表+表格 | 首行指标铺满；中部一侧高主图（如 `[0,32)`），另一侧纵叠 2 矮图（如 `[32,48)`），同 `H`；末行表格 `w=48`；禁止中部两栏每层等高 |
| C：少组件防拉伸 | <5 个组件、仅 1~3 图表、无表格 | 2 图各 `w≈24` 并排；3 图用高主图+旁叠 2 矮图，而非单图 `w=48`；1 图配 1~2 张指标卡时指标卡在左栏纵叠、图表在右栏与之齐平；含 ≥3 张指标卡时先放顶部一行或 2×N 指标卡，再接图表 |

## 美观度优化

满足硬约束后执行：

| 维度 | 动作 |
|---|---|
| 视觉流与层级 | 按 F/Z 型、倒金字塔组织：核心 KPI 指标卡放左上或顶部中央（y 最小），其次关键趋势图，最后明细；用大小和位置体现重要性 |
| 分组与控件 | 相关组件相邻成模块；切片器等控件置顶或置左，排列一致；留白只能通过调整组件尺寸实现 |
| 密度与平衡 | 减少单行组件数或增大单组件尺寸以降低密度；左右视觉重量均衡 |
| 对齐/比例 | 复用水平、垂直对齐线；避免极端瘦长或扁平；统一同模块尺寸和间距 |

## 布局自检流程

按以下顺序执行，禁止跳步。

### 第一步：整体布局设计

1. 确定分栏优先、行列为辅的模式；按主题和重要性划分功能区块。
2. 规划 F/Z 视觉流；把核心 KPI、关键趋势图放左上或顶部中央，形成倒金字塔层级。
3. 初定各区 `x/y/w/h`；把同类、同主题组件归入同一区块。

### 第二步：几何调整

1. 按[组件尺寸](#组件尺寸)分配尺寸和精确坐标。
2. 按密度、平衡、对齐、比例微调：对齐边缘、同类等高、左右平衡。此步允许尚未满足硬约束。

### 第三步：自检与调整

提交前逐项核对，失败先修正。追加/定点修改只查：无重叠、不越界、落实用户要求、新组件所在行铺满、表格仍置底；其余仅查新建场景。

| 项 | 判定与修复 |
|---|---|
| 末行铺满（最高优先） | 检查末行 x 投影为 `[0,48)`；有空白时与上一行并排或并入分栏。仅单组件例外（用户明确只要一个组件）允许非表格满宽 |
| 列基线 | 检查各行复用同一切分基线且纵向贯通；否则归拢边界 |
| 分栏区块 | 新建、组件 ≥5 且有图表时，检查存在一侧跨过另一侧 ≥2 个组件的错层区块；只有等高行/2×N 时按 A/B 重排 |
| 指标卡 | 检查全部集中在顶部同一行或侧栏同一栏；否则归拢 |
| 文本 | 检查整盘标题位于第一行，副标题紧贴所属区块上方且同宽；否则移回 |
| 拉伸 | 除单组件例外外，检查无非表格图表 `w=48`、无极端比例；按过度拉伸规则修复。整盘只有一个组件而用户并未明确只要这一个时，回到 [Dashboard Scene 的默认组件构成](../scenes/dashboard.md#默认组件构成) 补齐组件后重新排布 |
| 少组件分栏 | 新建看板、图表 ≥3 个，或 1 个图表配 1~2 张指标卡时，检查已按[组件清单决策树](#按组件清单选结构)和骨架 C 排成分栏；指标卡被拉到 `w>16` 与图表各占半宽时按骨架 C 重排 |
| 阅读顺序 | 检查核心指标卡在首屏（顶部或左上），其后是分类对比，最后是趋势与明细；核心指标在底部时调整到顶部或左栏 |
| 其余硬约束 | 检查无空洞、无重叠、水平铺满、垂直紧凑、底部齐平及 `∑(w_i*h_i)=48*Y_max` |

违规时在不破坏整体结构的前提下微调 `x/y/w/h`，先调宽/高，再调位置。在[通用恢复预算](../SKILL.md#异常恢复与停止条件)内完成校验与修正，全部通过后确定最终坐标。已证明无解（单个 funnel/ranking 类型约束冲突）时标记 `blocked` 并停止，不重复调整，不提交违规坐标。
