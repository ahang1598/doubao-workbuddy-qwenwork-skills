# Dashboard 视觉规范

> 用 Read 一次读完本文（传 `limit: 600`，本文不到 200 行）。配方、尺寸硬表、阅读顺序和自检都是硬约束，只读开头会漏。

## 适用范围与入口

本文是规划仪表盘组件坐标的唯一依据，按专业 BI 仪表盘的排版规范为每个组件确定 `x/y/w/h`。

目录：适用范围与入口；常见组合排版配方；坐标体系；布局选型；组件尺寸；阅读顺序；硬约束；分栏对齐算法与常用骨架；结构对照示例；布局自检流程。

**用户指令优先**：用户明确给出的坐标、行列数、尺寸、顺序具有最高权重；说明与尺寸硬表或默认阅读顺序的偏离，未指定部分仍按本文规划。禁止重叠和越界是任何场景都不能放宽的安全约束。

**适用范围**：[组件尺寸](#组件尺寸)和[阅读顺序](#阅读顺序)是默认规范；追加、定点修改时至少对本次新建或改动且用户未明确指定冲突尺寸／顺序的组件满足。[分栏适用条件](#分栏适用条件)、[硬约束](#硬约束)的整盘约束和自检里的整盘项只用于**新建看板且用户没提布局要求**的场景；整盘重排或美化而没给排法时按新建处理。其他场景：

- **用户指定了位置、顺序、同一行等**：以用户要求为准，不强制分栏。
- **在已有看板上追加**：现有组件保持原坐标，只为让新组件所在行铺满而调整同行组件。
  - 图形类、饼环、表格类：盘面最底下是表格或透视表时，插在表格上方（并入表格上方最后一行，或占用表格原 `y` 单独成行、表格整体下移），不接在表格下面。
  - 点值类（指标卡、进度、倒计时）：并入位于所有图表之上的那组指标卡（同一行或紧接其下新起一行，下方组件整体下移），不放到图表或表格下面。
  - 已有文本组件不移动、不拉宽、不改写；新组件不插到同一栏已有文本的上方。
- **改造已有看板**（改名、改配置后重排坐标）：这次写了新坐标的组件按「点值类 → 图表 → 明细表」排。
- **定点修改**：只改目标组件坐标，最终坐标以 `+dashboard-layout` 输出为准。
- **任何场景**都不重叠、不越界（`x+w ≤ 48`），布局改动都用 `+dashboard-layout` 提交，不逐个 `+dashboard-block-update --position` 或加 `--no-validate` 绕开。

**为什么每行必须拼满 48**：`+dashboard-layout` 每次提交都会调服务端兜底整理，把所有空位补满、把相邻组件拉宽，且不检查类型尺寸上限。规划时留的空位一定留不住（指标卡 12+12 右侧留空会被拉到 24~36 宽，图表 w=24 右侧留空会被拉到 48）。所以新建看板按下面的配方选列切分，让每一行在类型尺寸内正好拼满。

## 常见组合排版配方

坐标为 `(x,y,w,h)`；“指标卡”含进度、倒计时，“图表”未注明时指图形类。组件数不同时按同样列切分重算高度，每行仍拼满 48。

| 组件组合 | 列切分 | 坐标 |
|---|---|---|
| 1 指标卡 + 1 图表 / 饼环 | 补一张同源指标卡，按下面「2 指标卡」一行排 | — |
| 2 指标卡 + 1 图表 | 左 16（卡叠放 7+7）+ 右 32 | 卡 (0,0,16,7)(0,7,16,7)；图 (16,0,32,14) |
| 3 指标卡 + 1 图表 | 左 16（卡叠放 7×3）+ 右 32 | 卡 (0,0,16,7)(0,7,16,7)(0,14,16,7)；图 (16,0,32,21) |
| 2 指标卡 + 1 饼环 | 左 24（卡叠放 9+9）+ 右 24 | 卡 (0,0,24,9)(0,9,24,9)；饼环 (24,0,24,18) |
| 1 指标卡 + 2 图表 | 左 16（卡 + 矮图）+ 右 32 高图 | 卡 (0,0,16,8)；矮图 (0,8,16,14)；高图 (16,0,32,22) |
| 2 指标卡 + 2 图表 | 左 16（卡 6+6 + 矮图）+ 右 32 高图 | 卡 (0,0,16,6)(0,6,16,6)；矮图 (0,12,16,12)；高图 (16,0,32,24) |
| 只有指标卡 | 2 张 24×2；3 张 16×3；4 张 12×4；5 张 16×3 + 24×2 两行；6 张 8×6 或 16×3 两行 | 4 张 (0,0,12,8)(12,0,12,8)(24,0,12,8)(36,0,12,8) |
| 3~4 指标卡 + 2 图表 | 左 12 卡叠放 + 右 36 两图叠放，同高 24 | 卡各 h=8（4 张各 h=6）；图 (12,0,36,12)(12,12,36,12)；含饼环时两栏都改 24 |
| N 指标卡 + 3 图表 | 首行卡等分 48；主图 32 + 右栏两矮图 16 | 主图 (0,8,32,24)；矮图 (32,8,16,12)(32,20,16,12) |
| N 指标卡 + 多图表 + 表格 | 同上，末行表格 48 | 表格 (0,32,48,16)；多 2 张图时中部下方加一行 24+24；多 1 张时与表格同排 32+16 |
| 只有 2 / 3 / 4 图表 | 2 张时补一张同源指标卡按「1 指标卡 + 2 图表」排；主图 32 + 矮图 16×2；左 32（14+14）+ 右 16（12+16） | 4 张 (0,0,32,14)(0,14,32,14)(32,0,16,12)(32,12,16,16) |
| 含漏斗 | 主图 36 + 右栏 12（饼环、漏斗叠放） | 主图 (0,y,36,24)；饼环 (36,y,12,12)；漏斗 (36,y+12,12,12) |

新建看板有图表时，少组件也优先排成分栏：一侧一个高组件跨过另一侧纵向叠放的 2 个及以上组件，两栏底部齐平；1×N 单行、2×2 网格只在拼不出分栏时用。指标卡竖叠成 16 宽窄栏，图表高取 14~24，不把组件压成矮条或单行各占一半。饼环卡片接近方形（w:h 约 1~1.5，如 16×14、24×18）。分栏边界（组件左边缘 x）取 4 的倍数，常用 16/32、24/24、12/36；36 宽的位置只放图形类。组合不在表里时套最接近的列切分，再用[分栏对齐算法](#分栏对齐算法与常用骨架)结算高度。

## 坐标体系

画布 **48 列固定宽度、无限高度**。`x ∈ [0,48)`、`y ≥ 0`、`w > 0` 且 `x+w ≤ 48`、`h > 0`。1 列约 31px、1 行约 26px，同样格数一列比一行宽约 1.2 倍；本文宽高关系都已写成栅格数，直接比较 `w`、`h`。

**位置关系**：两个组件列区间 `[x, x+w)` 至少共用 1 列即为**同一栏**（只是边缘相接不算）；满宽组件与每个组件同栏。把全盘所有 `y` 与 `y+h` 去重排序，相邻两值之间的横条为一条**水平带**。

### 追加到底部：按实际底边累加

用 `+dashboard-block-list` 读完全部分页，在 CLI 48 列坐标中取 `bottom = max(y+h)`（空看板为 0），新行从 `y = bottom` 开始；不把 `y` 当像素、不乘 4，不混用原生 `api GET` 的 `position`。多行追加时每次从上一行最大 `y+h` 累加，不留安全间距，不用 `120`、`240` 这类与底边无关的大坐标避让。宽高按类型选，不因追加到底部就强制 `w=48`。CLI 提示坐标近似换算时，以 `+dashboard-layout` 返回的最终坐标核对重叠、越界和大空白。

## 布局选型

- **行列式**：先分行、行内分列，适合简单规整的看板。
- **分栏式**：先按主题把画布切成矩形区块，区块内再细分，能体现层级、避免组件少时被拉宽。优先用分栏式。

### 分栏适用条件

**分栏**指存在一个区块，左右两侧各自纵向排列、水平分界线**错开**、底部齐平；典型是一侧一个高的主组件跨过另一侧纵向叠放的 2 个及以上矮组件。各行等高的 2×N 网格、左右各叠同高组件都不算分栏。

新建看板有图表且组件 ≥ 3 个（不计 `text`、`slicer`）时，至少有一个分栏区块；≥ 5 个时必须有。没有图表时指标卡排一行或 2×N，表格整行置底。

### 按组件清单选结构

先按类别计数：**点值类**（`statistics` / `progress` / `countdown`）、**图形类**（柱 / 条 / 线 / 面积 / 组合 / 散点 / 雷达 / 漏斗 / 词云 / NPS）、**饼环类**（`pie` / `ring`）、**表格类**（`view` / `pivotTable` / `ranking`）、控件（`slicer` / `text`）。“图表”指图形类和饼环类。

1. 指标卡集中在一处（顶部同一行，或侧栏同一栏），≥ 4 张可排一行或 2×N。
2. 指标卡 + ≥ 2 图表：左栏指标卡 2×N、右栏图形类主图齐平；或顶部指标行 + 中部分栏 + 底部表格（骨架 B）。
3. 图表 ≥ 3：至少一处「1 个高的主图 + 旁边叠 2 个矮图」，主图为图形类或排行榜；不全部排成等高 2×N。
4. 少组件按配方分栏：指标卡在左栏纵向叠放，图表在右栏，只调高或叠加指标卡来齐平；不让单个非表格组件独占满宽。
5. 表格、透视表在图表下方，一般独占末行，也可与排行榜或图表并排。排行榜尺寸按表格类，位置与图表同级。
6. 切片器置顶，h=3，多个排同一行。
7. 文本（仅用户要求时才建）h=3，只能是 `y=0,w=48` 的整盘标题，或紧贴所属区块正上方、与区块同宽的子标题；说明文字写在回复里。
8. 组件多而杂时先切成「概览指标 / 分析图表 / 明细表格」等区块，区块内再套骨架。

## 组件尺寸

**尺寸硬表**：除[单组件例外](#硬约束)明确覆盖的宽度外，每个组件的 `w`、`h` 和宽高关系都必须满足（`⌊⌋` 向下取整）。

| 类别 | `--type` | 宽 w | 高 h | 宽高关系 |
|---|---|---|---|---|
| 点值类 | `statistics` | 8~24 | 6~12 | `h ≤ ⌊1.7w⌋`；不满宽 |
| 点值类 | `progress`、`countdown` | 8~24 | 8~16 | 同上；不作主图 |
| 饼环类 | `pie`、`ring` | 12~24（最多 36） | 12~18 | `w ≤ 2.5h`；最佳 `w:h` 约 1~1.5 |
| 图形类 | `column`、`line`、`area`、`combo`、`scatter` | 12~36 | 12~24 | `w ≤ 4h`，`h ≤ 3.5w` |
| 图形类 | `bar` | 12~36 | 16~24 | 同上 |
| 图形类 | `radar`、`wordCloud`、`nps` | 12~24 | 12~24 | 同上 |
| 图形类 | `funnel` | 8~18 | 12~24 | `w ≤ h` |
| 表格类 | `view`、`pivotTable` | 24~48 | 12~24 | 至少完整显示 2 行数据 |
| 表格类 | `ranking` | 12 或 16 | 12~24 | `w ≤ h`，至少完整显示 2 行 |
| 控件 | `slicer` | 12~48 | 3 | |
| 文本 | `text` | 48 或与所属区块同宽 | 3 | |

`--type` 区分大小写。表外类型按图形类处理。不为铺满把组件拉到超出上表；齐平时只调高或叠加指标卡、调整栏宽。

**渲染可读性**：饼环类目不超过 6 个（多出的合并为“其他”）；柱状图类目超过 8 个或类目名长时改 `bar` 或放宽到 w ≥ 24；表格把短字段放在前几列。

## 阅读顺序

```text
总标题 → 切片器 → 子标题 → 点值类 → 分析类（图形类、饼环类、排行榜） → 明细类（表格 / 透视表）
```

**按栏判断**：只比较同一栏的组件。同一栏里 A 的类别排在 B 前面时，必须 `A.y < B.y + B.h`；同类之间不限，不同栏之间不比较；满宽组件与每一栏都比较。所以顶部指标卡行在所有图表之上，满宽表格在所有图表之下；侧栏指标卡块只要求在本栏图表之上；子标题在本栏最上方且下面紧跟所属内容。

## 硬约束

在任何场景都满足：**禁止重叠**、**不越界**；用户未明确指定冲突尺寸／顺序的部分还要满足[尺寸硬表](#组件尺寸)和[阅读顺序](#阅读顺序)。新建场景再满足以下整盘约束：

- **每一行拼满 48**：从 `(0,0)` 起排，每条水平带（含最后一行）组件首尾相接，`x` 从 0 到 48，w 之和正好 48；分栏区块按栏分别拼满。拼不满就换配方或列切分，不留空、不靠拉宽凑满。
- **无空洞、垂直紧凑、底部齐平**：每列从 `y=0` 紧密堆叠，各栏底边对齐到 `Y_max = max(y+h)`。
- **面积校验**：`∑(w·h) = 48 × Y_max`，对不上就是有空洞或重叠。

**单组件例外**：新建看板默认不只放一个组件；用户只点名一个分组图表时，按 [默认组件构成](../scenes/dashboard.md#默认组件构成) 补同源总量指标卡（凑成两张），用「2 指标卡 + 1 图表」配方。用户明确只要一个组件时：图形类、表格可 `(0,0,48,h)`，此处 `w=48` 覆盖尺寸硬表的宽度上限，高度和宽高关系仍按表内要求；其他类型放左上角保持类型尺寸，并在回复中说明。

**无解时停止**：用户指定与尺寸硬表冲突时按用户执行并说明冲突；自己规划确实无解时按 [通用停止协议](../SKILL.md#异常恢复与停止条件) 将布局项标 `blocked`，不提交违规坐标、不循环调整。

## 分栏对齐算法与常用骨架

**对齐算法**：并列各栏共用总高 `H`；某栏叠 `k` 个组件时每个 `h = ⌊H/k⌋`，余数补到最后一个；各栏结算到同一 `H` 即底部齐平。结算出的每个 `h` 都要落在尺寸硬表内，越界就改 `H`、栏宽或该栏组件数。顶部指标行、底部表格行独立取高，不参与 `H`。

**列基线**：全盘复用一套列边界（如 24/24、16/16/16、12×4），相邻行切分点对齐到同一基线。

- **骨架 A（左指标 / 右分析）**：左栏 16 放指标卡 2×N（每张 w=8），下方可再叠一个 w=16 的图；右栏 32 放图形类图表纵向叠放。
- **骨架 B（顶部指标 + 中部分栏 + 底部表格）**：首行指标卡拼满 48；中部一侧高主图（图形类 32 或排行榜 16）、另一侧叠 2 个矮图；末行表格 48，或表格与排行榜并排。
- **骨架 C（少组件）**：按配方让一侧高图跨过另一侧叠放的指标卡或矮图；3 图表用主图 32 + 矮图 16×2。

## 结构对照示例

示例坐标以组件 id 为键，`type`、`name` 仅供对照；提交 `+dashboard-layout --layout` 时每项只需 `block_id` 与 `x/y/w/h`（见 [全盘坐标协议](dashboard-layout.md#全盘坐标---layout)）。

反例：「4 指标卡 1×4 + 条形图、饼图各 24 + 满宽表格」几何合法，但组件 ≥ 5 却没有分栏区块，新建看板不能用。

正例（左指标 2×2 + 饼图 / 右主图，表格置底）：

```json
{
  "s1": {"x": 0, "y": 0, "w": 8, "h": 6, "type": "statistics"},
  "s2": {"x": 8, "y": 0, "w": 8, "h": 6, "type": "statistics"},
  "s3": {"x": 0, "y": 6, "w": 8, "h": 6, "type": "statistics"},

  "c1": {"x": 16, "y": 0, "w": 32, "h": 24, "type": "bar"},
  "t1": {"x": 0, "y": 24, "w": 48, "h": 16, "type": "view"}

```

  "k2": {"x": 12, "y": 0, "w": 12, "h": 8, "type": "statistics"},

  "trend": {"x": 0, "y": 8, "w": 32, "h": 24, "type": "line"},

## 布局自检流程

### 第一步：整体布局设计

按组件清单选结构（分栏优先），按阅读顺序逐栏定上下次序，同主题组件归到同一区块；核心指标在首屏，左右视觉重量均衡，同类组件高度一致。

### 第二步：几何调整

在尺寸硬表内为每个组件分配坐标，复用列基线，任何调整都不越出尺寸硬表。

### 第三步：提交前自检

追加或定点修改时只核对：无重叠、不越界、新组件和改动组件的尺寸与阅读顺序、新组件所在行铺满、表格仍在最底；其余为新建场景整盘项。

- **尺寸硬表**：逐个组件核对 `w`、`h` 和宽高关系。
- **阅读顺序**：逐栏核对每一对组件，满宽组件与每一栏核对。
- **每行拼满 48**：逐行列出 `x`、`w`，首个 `x=0`、首尾相接、末个 `x+w=48`（含最后一行）；再核对面积校验。
- **结构**：组件 ≥ 5 且有图表时有分栏区块；指标卡集中一处；无单个非表格组件满宽（单组件例外除外）；文本只作标题或子标题。
- **渲染可读性**：饼环类目数、长类目柱状图。

### 第四步：提交后自检
