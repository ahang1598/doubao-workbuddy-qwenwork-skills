# Base 查询页面生成

本文件仅用于**以查询条件、查询 / 重置、真实结果、分页和只读详情为核心**的页面，描述查询页的交互与布局搭建规则。只读看板、输入表单、静态页或原生 Dashboard 不加载本专项；通用开发流程见 [页面开发入口](../scenes/webpage.md)，取数 DSL / 字段编码 / 分页等数据契约以 [数据规则](webpage-data.md) 为准。

## 何时使用

- 用户明确要求创建查询页／检索页，核心用途是查询并展示真实 Base 记录。
- 用户要求修改已有查询页的查询条件、结果字段、空状态、结果卡片或只读详情交互。
- 混合需求仅在查询为主流程时加载；普通页面取数、展示或附带筛选不加载。

新建或修改均按 [页面开发入口](../scenes/webpage.md) 的目标发现与源码状态分支准备工程：空页 `init`，已有源码 `pull`。

**不使用**：纯看板 / KPI / 图表、静态推广页、自然语言问数、输入型表单、通用增删改查，以及任意页面复刻。不要声称导入了原生查询页的配置、访问策略或视觉——页面生成拿不到这些配置。

## 开工资料

编码前确认或提取：

1. 页面标题与可选描述。
2. 真实 `tableId`、字段 ID、字段类型及选项元数据（来自已核实资料或 Base 表 / 字段查询命令）。
3. 查询字段、结果字段、单一 `and` / `or`、默认排序、必填条件行为、详情字段。
4. 任何截图、参考链接、布局偏好或明确的新增记录要求。

缺元数据先用 `+field-list` / `+field-get` 补齐。用户未指定查询字段时，选两个有可用控件的已核实字段；查询条件最多六个。明确需求超出上限或含不支持的控件时说明缺口，不静默删减。截图仅作布局参考，不带入示例客户、数字或选项。

## 查询状态与请求边界

查询只在显式用户动作后发起：

- **初始态不请求记录**，不显示假预览；编辑查询控件不请求记录。
- 点击「查询」先校验必填 / 格式，再提交本次条件、发起一次查询并关闭已选详情；相同条件再次点击仍发起新请求。
- 点击「重置」清空控件、结果、已选详情、错误与页码，回到无查询初始态。
- 查询中保留控件与取值但禁止重复提交；不伪造取消按钮（Host 无 abort 契约）。
- `useBaseData` 保持顶层调用：Hook 若无 `enabled` / `skip`，在首次有效查询后再挂载结果组件；相同条件重复提交用 Hook 的 `refetch`。

## 数据与分页

DSL 结构、过滤值编码、value / originValue、日期 token、返回 key 的完整契约见 [数据规则](webpage-data.md)，本文件只强调查询页相关要点：

- 用稳定的 `columns` DSL（`useMemo`）获取真实结果，遵守扁平单 conjunction。空条件省略；所有搜索、排序、筛选都在 Host DSL，不在当前页处理。
- 下拉选项来自真实元数据：Select 过滤用 option ID，展示用选项名称；关联条件用真实 recId；附件只用空 / 非空过滤；Formula/Lookup 按真实结果类型选控件，不凭语义发明操作符。
- 需要人员选择时，用 [数据规则](webpage-data.md) 中 `common/api` 的 `searchUsers` 做真实搜索 picker，用 `userId` 作过滤值与 key；不要把人名当 ID。
- 通过 `pageIndex` / `pageSize` 重新请求对应页，用 `total` / `hasMore` 决定页按钮；不对当前页 `slice` 造分页。新查询 / 重置回第一页并关闭详情，保证所有结果可到达。只有明确的 Top N / 单条查询可省略分页。
- 结果用 `.value` 展示，数值逻辑才读 `.originValue`；`total` 未知不显示为 0。数据为空显示未命中，错误按 Host 实际暴露的类型提示，不臆断权限或网络原因。

## 默认界面与交互

用户没有更强的布局或交互要求时，使用「查询主页 + 查询结果 + 只读详情」三段式。

### 查询主页

- 全屏页面布局，居中一个醒目的主查询面板，标题与简短说明在控件上方。
- 查询控件宽屏两列、窄屏单列，每个控件有紧凑标签与清晰的当前值。
- 控件下方放全宽主「查询」按钮；「重置」可达但交互优先级更低。

### 查询结果

- 保留页面头部与本次条件，把查询栏收为顶部紧凑工具区；宽屏控件一行、窄屏换行。
- 主内容区展示真实总数（可用时）、结果卡片 / 列表与分页。每张卡片一个清晰主标题，其余已核实字段分区紧凑排布；不要复制参考图的示例客户、日期、人名或状态值。
- 提供清晰的「返回查询」入口，返回时保留上次输入以便调整再提交，不冒充重置。
- 提交查询时居中面板可向上收拢、结果区在下方进入；动效克制并尊重 `reduced-motion`。

### 只读记录详情

- 点击结果卡片按 `rec_id` 选中并打开只读详情：桌面端右侧全高、可独立滚动的 Drawer（约占宽屏一半，保留左侧列表上下文），移动端底部或全屏 Sheet。
- 选中卡片给明确选中态；点另一张卡片更新详情内容与选中态，不回到查询主页。
- 详情字段按既定顺序纵向展示：真实 select / status 渲染为只读内容，数组按真实类型展示，长文本换行，空值用短横线；全部取自所选 `useBaseData` 记录。
- 关闭详情恢复焦点到所选卡片，保留当前查询、页码与滚动位置；支持键盘关闭与焦点收敛。
- 始终不添加修改已有记录、删除记录或批量写入的控件与交互。
- 用户明确要求时，可另加符合 [新增记录规则](webpage-record-create.md) 的单条新增入口；记录详情保持只读。

## 交付前审查

- [ ] 任务确实是 Base 支撑的查询 / 检索页。
- [ ] 每个 `tableId` / `fieldId` / option ID / recId / 用户 ID 均已核实。
- [ ] 默认查询字段有效、不超过六个，未支持控件已省略。
- [ ] 初始无请求、编辑不请求、点击「查询」提交一次、相同条件刷新、重置归零。
- [ ] DSL 稳定、扁平、含全部筛选 / 排序，无任何客户端数据语义。
- [ ] 完整列表每一页都可经真实 Host 分页 / 加载更多到达。
- [ ] 初始、加载、成功、空、错误、只读详情六态齐备。
- [ ] 查询主页与结果页为不同响应式视图，结果页可返回查询主页并保留上次条件。
- [ ] 点击结果卡片打开匹配的只读详情 Drawer / Sheet；选中、关闭、焦点恢复、字段顺序、滚动上下文正确。
- [ ] 无修改已有记录、删除记录或批量写入交互；单条新增仅在用户明确要求时提供。
- [ ] 值的 `.value` / `.originValue` / 附件 / `rec_id` 使用正确。
- [ ] 桌面与移动端布局、标签、焦点、禁用态均已核对。
