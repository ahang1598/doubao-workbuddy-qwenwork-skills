# App 搭建规则与视觉质量

本页统一维护默认页数、角色丰富度、首页 T 型的适用条件与覆盖顺序；组件尺寸见对应组件文件。

## 适用与优先级

1. 用户明确数量/闭合页或组件集合/布局优先；首页/看板/总览、区域描述、小应用、数据少、时间不足不减页。
2. 完整新建默认三页、有效用途、首页T型；实际树/完整structure核结果，限制未解列缺口，不减页/放宽。
3. 已有迭代保持范围，结构写后对完整App核重叠；资源壳/单页例外来自用户任务。
4. 原子尺寸写前落实，用户/首页模板/组排版覆盖记依据。

明确集合的 [简单搭建](../../scenes/app-mode/simple.md) 不套默认页数/丰富度/T型，仍验数量/布局/上限/真实内容/保留项；不用于开放搭建降要求。

## Page 与 PageGroup

| 用户要求 | 规划与检查 |
| --- | --- |
| 明确数量或闭合 Page 集合 | 严格按指定集合/数量，含复用默认页；不额外补页 |
| 明确 Page 下限 | 至少 max(3, 用户下限) 页；“至少两页”不等于只建两页 |
| 未限定页面数量 | 至少 3 页，按真实职责建至少三页，不复制页面凑数 |
| 明确单页/一页/两页 | 严格按数量。仅描述页面类型或区域不构成例外 |
| 已有 App 局部修改 | 按实际变动规划，保留项另行回读；不机械套新建页数 |
| 明确 PageGroup 数量 | 单独从完整页面树数真实 page_group，不拿 Page 代替 |

PageGroup不计Page、最多两层，无空组；默认组≥2有效页。有效Page≥7必按职责分组，<7且未要求不强加。强制指定组真实创建、首页保留父组，单子页也保留，不为凑数补无关页。

判例（只看原话，不看篇幅）：

| 原话 | 判定 | 做法 |
| --- | --- | --- |
| “页面放个排行榜，再配个饼图”“帮我搭个小应用”“只有一个首页” | 不是页数限定 | 仍建至少 3 个 Page |
| “只要一页”“做成两个页面”“就这三个页面” | 明确页数 | 严格按数量，不补页 |
| “分成 A、B 两个页面组” | 限定组数，不限定页数 | 建 2 个 PageGroup，再按至少 3 页安排 Page |
| “拆成 A、B 两个页面” | 明确 2 个 Page | 建 2 个 `type=page`，不建组 |
| “总览、待办、档案三个页面组” | 3 个组 | 建 3 个 PageGroup，页面放进组内，首页也放指定组 |

计数方法：用 `+app-page-tree-list` 回读，只数 `type=="page"` 的节点；`type=="page_group"` 单独计数。`pages` 不含 `groups`，空页不计入有效页。

## 页面角色与丰富度

角色只绑定真实 Page ID。home 最多一个，未指定时取导航深度优先第一个有效 Page；data_overview 只在用户明确或规划选择时声明，普通列表页不自动升级；home 与 data_overview 都是顶层页时后者紧接前者。

| 角色 | 默认搭建要求 | 计数口径 |
| --- | --- | --- |
| home | ≥5 个有效根组件、全树 ≥2 种类型、≥1 List | 容器计一个根组件，空容器不充数 |
| data_overview | ≥5 个有效组件、≥2 种类型、≥3 张非指标图 | 非指标图不含 statistics/progress/countdown/nps/list/view/pivot |

App/Page/组名非空且有业务语义，自拟≤8字、不用默认文案，用户名保留；新对象显式选公开语义图标，首位且名含首页的Page用home。

首页默认标题+一句说明，其它页不显示/重复生成页面标题；原生显隐无公开更新参数，不能删文本/隐藏组件名冒充，不能配/验则缺口。局部保留未点名标题，首页主列表有详情路径。

### 首页主列表字段计数

默认首页同一主列表≥5语义相关、初始可见字段，按真实ID去重；不跨列表/右侧或点击详情/折叠/隐藏字段凑数，筛选/分组/按钮/名称/文本不计。combined可见子字段各1，绑定业务字段的卡标题1，重复不再计。

未指定用可外露≥5字段的普通列表；card可1标题+4正文（正文≤6），detail左侧1+≤2不能借右侧凑5。指定类型/字段/更少数量优先，记覆盖及实际数，不换型/塞扫描区/加无关字段；真实不足列缺口，不擅改底表/造字段/判通过。

独立block-get与schema映射字段身份/去重数/区域，初始可见另需页面证据则补取，缺证据未验证；局部未要求不补默认。

## 首页 T 型

新建/现有Base转App的实际home执行；仅明确冲突布局/精确组件集合/严格排版覆盖，字段不足/工期/warning列缺口不跳过，局部按需求。写法见 [exact示例](../../scenes/app-mode/create.md#t-型首页写法)。

- 完整坐标/模式/满行骨架必按 [布局执行表](../../scenes/app-mode/layout.md#首页-t-型必须落实)：通栏标题、左32入口/≥3statistics/主list或view、右16≥3指标及图表，不重叠。
- 入口目标≥3至少建3，1～2全做，0跳过；页面/已有相关Form合计。右栏仅progress/countdown/nps和图表（含ranking/pivot/AI），指标/图各≥1，全部指标在图前。真实不足不编日期/阈值、重复分析或空组件。

必按 [补洞约束](../../scenes/app-mode/layout.md#画布会向上补洞不能用空位占行) 和 [T型自检](../../scenes/app-mode/layout.md#t-型自检交付前必跑) 核单位、每行满所属栏/无串行、两栏max(y+h)，先调主列表再原子范围调右栏。补内容须真实/授权，不扩业务/造目标/复制；完整structure未核顶部、32/16、成组满宽、底边不得称完成。

## 检查与执行入口

| 维度 | 执行位置 |
| --- | --- |
| 页面职责、数量与用户覆盖 | 本页定义，[create](../../scenes/app-mode/create.md) 规划与执行 |
| 阅读顺序、同行、成组与尺寸模式 | [layout](../../scenes/app-mode/layout.md) |
| 来源、口径、字段、标题、交互与样式 | [逐组件索引](app-component-selection.md) 中命中的组件文件 |
| 主题、背景、颜色、图标 | [主题](app-theme.md)、[图标](app-icons.md) |

只修证据明确的对象，视觉调整不改指标口径、筛选范围、业务对象、权限与动作。无公开方法或无法回读时保留缺口；没有具体规则的主观审美建议不阻塞交付。
