# App 指标口径与比率配置

创建/修改点名指标、比率、余额、去重或跨层统计时必读本页；协议仍以 [公共数据](app-data-common.md) 及对应组件为准。用户明确口径优先，样例不替代真实资格。

## 比率类指标：先定口径，再落实指定组件

组件/口径分验；点名回款完成率进度条按 [progress](component-progress.md#点名进度条时保留组件与口径)，保留progress+bar及真实分子/分母，不改statistics。下方卡配方仅明确指标卡/未指定单值形态。

通用比率为**分母对象+分子条件**：先定分母表和一行的对象。“A占B”先找B表/粒度，符合等权一行一对象才生成A的0/1；退款/续费/售罄/动销是示例，不是封闭清单。

0→1先补点名指标字段/源再排其它组件，不因改表/已建表/复杂换count、健康分或卡/进度条。新建补最小依赖，既有仅授权内补，否则原指标缺口。

**0/1均值前提**：一行一唯一分母对象且等权，核成功判定/完整资格/周期；重复跟进回对象/机会粒度，金额/异权不套。分母不只成功项、不因其它列表缩小。

按以下顺序选择配置路径：

1. **同表可直接判断（首选）**：分母表已有状态字段，建 Formula 0/1 标记，statistics 取 `AVERAGE`。
2. **分子在另一张表**：先用 Lookup 把分子条件关联到分母表（只作筛选条件，不改变计量实体），再建 0/1 标记，最后取 `AVERAGE`。
3. **分母本身需要聚合**：建“指标汇总”表，分子、分母各存一列，再用 Formula `分子/分母` 计算比率，statistics 读该列的 `AVERAGE` 或 `MAX`。

### 示例：跨表比率（退款率）

假定订单表一行一单，退款状态在订单表。先读 [公式流程](../../scenes/field-formula-lookup.md)，再用真实表/字段替换占位符：

```bash
# 1. 分母表建 0/1 标记
lark-cli base +field-create --base-token <base_token> --table-id <订单表id> --i-have-read-guide \
  --json '[{"name":"是否退款","type":"formula","expression":"IF([退款状态]=\"已退款\",1,0)"}]' --as user
# 2. 指标卡取 AVERAGE，保留完整分母
lark-cli base +app-block-create --app-token <app_token> --page-id <page_id> --name '退款率' --type statistics \
  --data-config '{"base_token":"<base_token>","data_sources":[{"table_name":"订单","series":[{"field_name":"是否退款","rollup":"AVERAGE"}]}]}' \
  --display-config '{"format_percent":{"precision":1}}' --as user
# 3. 独立回读
lark-cli base +app-block-get --app-token <app_token> --page-id <page_id> --block-id <block_id> --as user
```

回读校验，三条都需满足：

- `series` 只有「是否退款」`AVERAGE`，没有 COUNTA，没有 group_by。
- `filter` 不得出现分子条件（如“已退款”）；分母范围要完整。
- 取数用实际返回的 `chart_token`，不传 `widget_id`；用可区分的数据核对，2 个退款 / 5 个订单 = 0.4，显示 40%，不是 2 或 5 加百分号。

仅授权新表Mock/测试造区分样例，不向既有表造数；无结果待验证。field-get未露类型unknown，Record字符串非底层类型，继续公开配置/边界验证；空分母按真实结果/约定，不假称0%。

一人多缴费行等先去重/回对象表再标记，不明细直接AVERAGE；字段/关系/能力不足原指标blocked，补最小依赖不换count。

## 从业务词到配置

先确认每个指标统计的对象、资格、字段、聚合、时间和分子分母，再配置对应组件；修改时保留未要求变化的口径。显示名称不能证明字段、计算或筛选正确。

| 口径类型 | 必须核对 | 不能替代为 |
| --- | --- | --- |
| 比率／转化 | 对象粒度、资格条件、分子、完整分母、周期与零分母处理 | 分子数量或给数量加百分号 |
| 金额／工时度量 | 真实数值来源、单位、业务资格与SUM等适用聚合；多指标每项单独series | 待办条数、记录数或只保留容易取到的一个度量 |
| 去重活跃 | 活跃行为、业务日期、去重对象与时间粒度 | 原始事件数或累计对象数 |
| 余额／净额 | 真实余额字段，或期初、增减项、适用状态与持续计算来源 | 单边流入／流出量求和 |
| 跨层级状态统计 | 目标实体粒度、目标状态及上下层关联 | 子级行数、子级状态或子级数量 |
| 时间趋势 | 按业务日期聚合事件数据，或读取各时点的历史观测值；核对粒度与时间顺序 | 用分类对比或当前快照代替时间变化 |

协议不能完成去重、持续比率或跨表计算时，交最小数据依赖并回读；不发送未公开的聚合、公式或日期语法。

## App 比率验收

固定粒度/资格/分子分母/聚合/日期范围/维度/图型/单位格式。总体合计比用已验证持续机制重算，不逐行AVERAGE/算一次手填；能力缺失保留原组件、交最小依赖。

配置/独立结果分验：10/100+9/10总体19/110≈17.27%，等权均值50%；单行/同分母无法区分，无区分数据仅报配置，不称实测。数量/百分比格式不计算。

## 把口径落成回读项

逐指标block-get核实体/表→字段聚合或count_all→资格→日期窗口→单位格式，再取数对账；statistics/名称/有数据不证明口径，本月须度量+完整月份，不按错结果改口径。

0合法保留证据，疑数据查同范围记录/参数，不换本月为未来30天或动态源为手填汇总；恢复核实体/源/资格/周期/图型/保留项不变。
