# App 范围覆盖与当前访问者

固定范围/“我的”必读；时间另读 [时间配方](app-time-recipes.md)，指标资格另读 [指标口径](app-metric-recipes.md)。只写授权范围，逐类使用公开schema。

### 范围覆盖与时间窗口

1. **定谓词和授权**：记录对象、页面/组件范围、真实表字段、操作符/值，状态、时间、访问者分列。“有效期”仅在字段/数据证明等价时复用状态，否则核起止/失效日期及边界，不凭名称猜。仅建底表不等于App展示；局部只枚举指定范围，全局对象限制跨页核消费者，同表不同用途按授权判断。
2. **枚举消费者**：按实际结构/完整配置匹配源，不只按名：

| 入口 | 消费位置 |
| --- | --- |
| 列表/视图 | 原有、新增、不同名列表；Tabs各子项、详情抽屉、日历/看板/甘特等引用视图 |
| 图表/指标 | 每个受约束data_sources槽位；progress当前/目标源分别判断 |
| 来源视图 | 实际引用和有效筛选；已满足的记录回读证据，无需重写 |

“统一/只显示X”覆盖全部授权消费者，历史名称/其它页签不构成排除依据，不用新同名组件缩小集合。先区分旧条件职责：展示范围按授权替换，独立资格/指标/分子条件保留并与新范围AND；已完成数与进行中范围交集可0，不改名换指标。明确例外/局部边界优先。

3. **合完整条件**：保留未授权替换的条件、AND/OR、来源视图范围、排序。标准图主源view_name与filter互斥，选择能等价表达完整范围的路径；普通图、statistics、list/view嵌套能力不同，不照搬。可用公开多值条件/真实视图时核等价性，否则标缺口，不删冲突条件。
4. **逐源写后独立回读**：block-get读保存的完整条件，引用视图另核引用/有效筛选；空对象、无法解析、请求回显均未验证。最终结构复核旧/新组件和全部源槽位，各项有结果才称完成。

例：任务只看进行中/已停滞，旧所有任务、Tabs按项目、甘特、统计源各列一项；真实状态集合与旧“负责人A OR B”整体AND。已完成数仍保留已完成资格，交集可0；只改新图不算全局完成。

滚动窗口不换自然周期（最近30天≠本月）。固定业务日期/时区/周期与双边界，动态窗口不固化成搭建日时间戳、不只设下界纳入未来；历史区间才绝对双边界，不支持则缺口。可取数组件用同口径对账，已有/授权样例区分命中、排除、边界、未来，无区分数据仅记配置证据。

### 同一范围跨组件的正向示例

“本周截止且未完成”约束任务列表、待完成卡、人员图、优先级图。确认截止日期为日期、是否已完成为checkbox：

```json
{"filter":{"conjunction":"and","conditions":[{"field_name":"截止日期","operator":"is","value":"CurrentWeek"},{"field_name":"是否已完成","operator":"is","value":false}]}}
```

列表放顶层filter，图/卡放完整data_sources受约束源内，保留原聚合/分组/资格。等价动态“是否本周截止”字段先核定义再复用。四ID均须回读两个谓词，正确卡/分组不抵扣图；其它任务消费者继续覆盖，风险表不自动继承。

本周未完成命中，已完成/周外排除；缺样例仅配置验证。额外资格按交集对账，不要求不同口径数值相等。

### 跨实体的动态资格筛选

先分计量实体与资格：任务按关联项目状态筛仍计任务，不换项目count或任务状态。优先核已有动态Formula/Lookup及实际结果；真实关联可按 [公式/Lookup](../../scenes/field-formula-lookup.md) 派生资格，公开能力未核实不判后端缺能力。

缺字段先核最小依赖/授权；无权限或授权标blocked，不改权限/手填。按 [Lookup合同](../field-lookup-config.md)：from/select属条件来源表，field_ref属当前计量表，核主字段/同名冲突/真实关系与状态选项，不把“进行中”写成实际“推进中”。

例：任务“所属项目”关联项目主字段“项目名称”，状态选项“推进中”，需求明确“至少一个关联项目推进中”：

```json
{"name":"符合条件的关联项目数","type":"lookup","from":"项目表","select":"项目名称","aggregate":"counta","where":{"logic":"and","conditions":[["项目名称","intersects",{"type":"field_ref","field":"所属项目"}],["状态","==",{"type":"constant","value":["推进中"]}]]}}
```

读计算字段协议后用 `+field-create --base-token <base_token> --table-id <任务表id> --i-have-read-guide --json '<上述 JSON>'`。where元组、状态选项数组、动态field_ref，不用当次关联ID集合。counta数非空项目名，核非空/匹配/数值再筛>0：

```json
{"base_token":"<base_token>","data_sources":[{"table_name":"任务表","count_all":true,"filter":{"conjunction":"and","conditions":[{"field_name":"符合条件的关联项目数","operator":"isGreater","value":0}]}}]}
```

count_all仍计任务，Lookup仅资格；更新保留完整有序源/条件/聚合分组，列表filter放顶层。多关联>0为any，all及空关联按业务确认，不沿用本例猜。

field-get核定义、record-list核计算、block-get核动态筛选；用项目符合/任务不符及反例区分实体。仅授权样例中验证状态、新任务、关联变化持续影响入选；dry-run、字段创建或单次静态数不证明动态重算，配置/运行证据分报。

### 当前访问者筛选

用户原话或自拟“我的”页都须真实人员字段/已验证动态归属，覆盖页内相关列表/视图/指标。客户名称/公司文本不套人员selector；角色页面可见、标题、可选切片器不代替固定范围，不留给用户手动选。缺归属/能力标缺口，局部只核授权消费者。

“我的待办/承办案件”按打开App的访问者：回读目标为user人员字段，filter.conditions[].value精确为 `{"$slot":"current_user"}`，无额外字段、不是数组；不查询搭建者填固定ID，不套人员default_value数组。

确认任务负责人为人员字段后，标准列表最小配置：

```json
{"base_token":"<base_token>","table_name":"任务表","filter":{"conjunction":"and","conditions":[{"field_name":"任务负责人","operator":"contains","value":{"$slot":"current_user"}}]}}
```

真实App/Page/名称用 `+app-block-create --type list --sub-type standard --data-config '<上述 JSON>'`；已有列表先block-get，保留状态等完整AND/OR再block-update，不用最小例覆盖全范围。图表放对应data_sources内。

独立block-get须保存相同动态selector而非固定ID，请求回显不算证据；有可区分人员记录/两名访问者再验结果随人变化，否则仅配置验证。筛选不是记录权限，不替代/修改角色可读可编辑。Node拒绝、丢配置、返回固定ID则blocked，保留错误/回读，不换内部payload、删筛选或固定执行者求成功。

### 每个相关组件都要回读

每个消费者/源槽位分别按真实ID核完整条件，主列表不能替代旧历史列表、今日卡、详情、其它页/日历；同表同义也逐ID核。先核主体表/关系：项目≠任务状态，有效期≠已授权；源缺关联条件先核公开动态关联/Lookup/视图，不用静态ID、同名状态、换源计数或手填冒充。
