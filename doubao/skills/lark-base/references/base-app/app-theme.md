# App 全局主题

无 Base 新建、现有 Base 转 App 都必须选择并显式设置唯一主题。已有 App 只在明确主题、配色、明暗、整体风格要求或全局视觉重设计时改主题；局部页面、组件或布局修改保持原主题。

## 决策顺序

1. 明确主题、配色、明暗及用户排除项优先于业务推荐；冲突时暴露冲突。公开主题无法覆盖用户配色时，在公开背景色等能力内尽量对齐并说明边界，不静默改用业务推荐主题。
2. 排除相应主题、明暗或配色后，以可区分的风格优先于业务推荐。
3. “好看、高级、现代、简约、专业”不能单独决定主题，继续识别核心用途。
4. 按下表的业务语义选择，不要求逐字命中；无法判断用途，或明确朴素中性、黑白灰时才用 default。

| 值 / 名称 | 核心用途 | 风格与选择边界 |
| --- | --- | --- |
| default / 默认 | 用途不明的记录工具或明确中性 | 黑白灰、弱装饰；有表格不是选择默认的依据 |
| cloudBlue / 云蓝 | 集团经营、跨部门审批、预算财务、供应链统筹、销售组织管控 | 正式商务、蓝白；须有组织标准化管控，普通客户跟进不因“企业”选云蓝 |
| fresh / 清新 | 项目任务、客户跟进、订单售后、门店、报名预约、社区，以及农业健康环保服务 | 清爽、轻盈、绿色；日常管理首选，重服务关系转柔光，重分析转未来 |
| softLight / 柔光 | 咨询、设计、客户方案、读书文化、家居酒店、美业生活服务 | 温暖、雅致、低饱和暖色；效率/状态推进选清新，关系/内容品味选柔光 |
| future / 未来 | 增长转化、渠道效果、游戏内容传播、AI实验、创新数字展示 | 前沿、赛博、深紫；附带少量图表不足以触发，日常排期仍优先清新 |
| technology / 科技 | 设备生产、机器人物联网、能源、IT运维、网络、工程质量监测 | 工业、灰蓝、克制控制台；故障告警参数为核心，制造企业采购/客户管理不自动选科技 |

泛化“科技感”或“深色”优先 future；明确工业灰蓝控制台选 technology。主题之间没有覆盖配额。温暖的投放分析选 softLight，制造企业客户跟进选 fresh。

## 写入与回读

使用 [App 更新命令](app-commands.md)，`+app-update --theme-style <canonical值>`。主题与背景独立：只改主题保留背景，仅用户点名背景色时按命令公开字段设置；主题名称的颜色不自动转成自定义背景。当前没有 App 背景图设置能力。

theme-style只使用上表六个公开值，不编造表外主题。用户指定背景色可用`--background-color`；指定整体色系则逐项判断公开主题及相关组件样式能覆盖的范围，部分满足须明确余下缺口，不以背景色变化宣称全部主题配色完成。按数据条件突出风险属于条件样式，不能用全局背景或静态文案样式代替；无公开能力时报告受阻。

写后独立 `+app-get` 核对最终主题及被要求的背景。主题变化时同步核对页面标题副文案：future/technology 用 `#FFFFFFB3`，其余灰色，具体实施见 [text](component-text.md)。不能拿命令成功或规划值代替保存结果。
