# 多维表格（Base）

按交付目标选主责 Scene，由它组织依赖、执行和验收。**第一条 `lark-cli base` 命令前读 [CLI 调用契约](references/shared-cli-invocation.md)及其[命令写法速查](references/shared-cli-invocation.md#命令写法速查)**，参数名、JSON 顶层键、返回键以它为准，不凭记忆拼。SKILL 管边界与分流，Scene 管业务决策与验收，Reference 管命令、协议与恢复。

## 适用范围与能力边界

- 用 `lark-cli base +...` shortcut，不用旧聚合式 `+table / +field / +record / +view / +history / +workspace`，不依赖 `lark-cli schema`。`lark-cli api` 只用于尚无类型化命令的仪表盘权限统计开关、全局筛选、按钮绑定，按 [Dashboard 入口](scenes/dashboard.md#任务导航)的专属协议并满足功能开关和资源条件，不作通用回退。
- 只执行经典 Base，不执行 BaseApp／AppMode（不同资源，不混用标识；命令帮助里的应用、页面、应用组件入口也不用）；Scene 与 Reference 不能放宽此边界。
- 只用当前用户身份 `--as user`。凭证、scope 或资源权限不足按实际错误和平台现有授权入口处理，不调未提供的认证命令，不换身份或接口绕过拒绝；Context／SQL 明确拒绝时停止受影响分析。

## 核心概念与对象关系

```text
Base（base_token）
  资源目录 Base Block（资源 ID，可由 Folder 组织）
    Table（table_id，同一业务粒度）：Field（field_id）｜Record（record_id）｜CellValue（结构随字段类型）｜View（view_id，多视图共享底层记录）｜Form（form_id，有效提交创建底表记录）
    Dashboard（dashboard_id，图表、指标卡、视图、文本、交互组件的页面）→ Dashboard Block（block_id，配置与计算结果分别读取）
    Workflow（workflow_id，触发器、动作、分支等节点及连接）｜Docx（目录与正文分别标识，正文走文档工具）
  高级权限 → Role（role_id，成员对表、字段、记录的访问范围）
```

对象关系只用于判断归属、引用与受影响范围，不扩大授权。

- Link 建记录关系，Formula 按表达式计算，Lookup 按条件从源表取值或聚合（无须先建 Link）；可写边界、计算结果与附件按各自协议。
- Bitable 是 Base 的历史名称，调用路径相同；不凭历史返回字段名判断资源类型，兼容字段见 [Base 返回协议](references/base-commands.md#身份与返回)。

## Base 定位与读取

续接任务没给链接时沿用本会话已交付的 Base，不按标题搜索或新建；新建任务用创建返回的坐标。可信坐标和读取结果复用，只补缺的 ID；缺坐标走 [Base 定位流程](scenes/base.md#定位已有-base)按输入选路并消歧；名称和 ID 只取可信返回，不猜，不以新建替代定位。

按目标读取：Base 本体走 [Base 读取](scenes/base.md#读取-base)，结构走 Table，原始明细走 Record，独立分析走 Analyze-data。先确认所需真实结构，跨表覆盖依赖表；只需表或记录时不探测资源目录。Excel／CSV／`.base` 导入走 [导入交接](scenes/base.md#导入文件并返回-base)，Drive 导入后回 Base 验收。

操作涉及或可能涉及全表或完整筛选范围时，先确认该范围的行数；超过 1000 行，禁止将全量原始记录读取到本地处理，应使用后端统计或完整条件筛选，具体执行 [共同查询约束](scenes/query.md#共同查询约束)。

## 模块职责与入口

- [Base](scenes/base.md)：定位、创建复制、导入交接、模板、时区、资源目录、类别验收
- [Table](scenes/table.md)：建表、读取、复制、维护，逐表数据目标与条数证据，视图验收交接
- [Field](scenes/field.md)／Link：字段选型、选项、关联、派生，变更时保护存量数据
- [Record](scenes/record.md)：明细读写、筛选排序、附件、分享、历史、完整性证据
- [View](scenes/view.md)：视图生命周期、配置与实际结果
- [Form](scenes/form.md)：收集方案、题目、设置、分享、提交，回查底表
- [Dashboard](scenes/dashboard.md)：组件配置、数据、布局、交互
- [Workflow](scenes/workflow.md)：定义、接收人、启停、执行证据，区分定义验证与运行验证
- [Permission](scenes/permission.md)：高级权限、角色、成员；普通文件协作者交 Drive
- [Formula／Lookup](scenes/field-formula-lookup.md)：计算依赖、表达式或匹配条件、实际值
- [Query](scenes/query.md)：Context／SQL、完整性、精度、受控回退；独立分析交付归 Analyze-data
- [Mock](scenes/mock-data.md)：样例数量、人员与业务一致、全量回读；提交与运行验证回 Form／Workflow
- [Analyze-data](scenes/analyze-data.md)：口径、查询编排、结论，查询／产物／答复一致
- [Build-system](scenes/build-system.md)：业务建模、模块选型、依赖编排、组合验收

Query、Mock、计算字段也可承接独立目标；用到依赖能力不改交付主责。

## 任务选择

<a id="写入前路由"></a>

### 写入前路由

第一次写入前按原话命中下表，不因任务简单、命令已知、已读 Reference 或字段已明确而跳过；多目标分别记录产物与主责，共用一份验收清单。`--fields` 数组、表单生成字段、批量脚本也按内容路由，不免除子对象决策与验收；筛选、统计路由也用于只读任务，不改主责、查询选路或写入授权。做不到标 `blocked`，不用近似产物或会话说明替代。

| 触发信号 | 强制路由与完成条件 | 禁止替代 |
|---|---|---|
| 新建、复制、导入 Base，或明确搭建业务系统 | 先读 [Build-system](scenes/build-system.md)，第一条写命令前登记模块、依赖和[类别目标](scenes/base.md#新-base-的交付类别)（例外见该节）：普通新建**至少 3 类页面级产物**（数据表、非表格视图、仪表盘、表单、工作流等各算一类；grid 视图不论怎么筛选分组都算数据表类；`table + permission` 只算 2 类）；原话有“每周／按周”时建 `WEEKNUM([日期])` 周次字段并让视图或图表按它分组，只做“本周”筛选不算完成 | 只建一堆表、只交付表+权限或表+工作流都不算系统完成；只列出要做的操作（如“建表并排序、改名”）不构成“只要这些对象”的限定 |
| 本轮创建任意业务表（含 Base 初始表及已有 Base 内新建的登记、收集、事件、下游表） | 逐表交 [Table](scenes/table.md#数据与展示目标) 和 [Mock](scenes/mock-data.md#数据来源与数量)，**写第一条记录前读 Mock [开工必读](scenes/mock-data.md#开工必读)**（人员空缺、时间晚于当前、状态与日期矛盾等规则在此）。除原话明确要空表／空模板、指定数量或只保留来源数据外，**每表不少于 5 条（一般 5~10 条）**；下游表受上游状态限制时调整上游样例分布使每表达标 | 不能只给主表写样例或用创建成功代替 Mock；自行推断“以后由用户/表单/流程填写”“正式表保持干净”“让大家自己报名／填写”都不是空表例外；验算公式的 2~4 条不算达标 |
| 本轮创建业务表后的条数验收 | 写后完整分页回读条数（NDJSON 累计 `records_count`，JSON 累计 `len(data.data)`）记入账本 `record_count`，答复逐表列出；非例外且不足 5 条先补写再回读，不得声明完成。数据目标随表传给 Form、Workflow 等依赖模块；维护既有表不自动补数据 | 不能用创建成功代替回读条数 |
| 创建或修改自动计算、关联取值、累计、匹配、计数等持续派生字段 | 交 [Field](scenes/field.md) → [Formula / Lookup](scenes/field-formula-lookup.md)，核对来源、结果粒度、保存定义和实际值；业务执行产生的结果交 Workflow | 不能用脚本算一次后填入普通字段冒充持续派生 |
| 只要一个统计答案：计数、排名、Top N、占比、对比、趋势 | 先读 [Analyze-data](scenes/analyze-data.md#开工必读)，用 SQL 在完整数据上算，答复数字照抄查询结果；原话点名的类别能对上字段选项时，第一条取数命令（SQL 或 `+record-list`）就只取这些选项 | 不能凭部分记录估算或心算；不能省略筛选边界 |
| 自然语言筛选、Top N、分组、比率、占比或动态时间 | 当前主责先读 [统计口径与条件](references/shared-statistics-rules.md#任务口径与核对)，把口径对应到实际查询或保存配置及结果 | 不能仅靠名称、文案或另一对象的正确配置证明范围正确 |
| 新建或追加 Dashboard 组件 | 交 [Dashboard](scenes/dashboard.md)，第一条 `+dashboard-block-create` 前读其[开工必读](scenes/dashboard.md#开工必读)（指标口径在此）；原话里的筛选、分组、排序写进图表组件本身，另建筛选视图只算补充，“出单／单量”用计数；**规划任何组件坐标前读 [视觉规范](references/dashboard-visual-standards.md)**（画布 48 列、组件清单决策树、尺寸表、骨架只在此），按它定好每个组件坐标；为凑页面类别补建或顺带建的看板同样适用，不因是补充产物跳过；回读指标口径、实际结果和统一布局 | 不能以组件创建成功或名称正确代替布局、结果验收 |
| 报名、登记、收集、问卷或表单链接 | 交 [Form](scenes/form.md)，核对题目、必填、分享及适用真实提交；题目定稿后按[题序目标](scenes/form.md#题序目标与依赖)用 `+view-set-visible-fields` 整体提交一次题序 | 不能以底表字段代替表单题目 |
| 未来触发的提醒、定时、事件触发的通知、自动汇总、状态联动或自动写入 | 交 [Workflow](scenes/workflow.md)；第一条 `+workflow-create` 前读其[开工必读](scenes/workflow.md#开工必读)定动作、写入目标和接收人，再按协议写请求体 | 禁止 Base 外 scheduled job（包括平台的定时任务工具，如 `create_cron_job`）；禁止只建字段、视图或发一条即时消息代替未来执行 |
| 角色、字段/记录范围、敏感数据或排他访问 | 交 [Permission](scenes/permission.md)，第一条 `+role-create` 前读其[开工必读](scenes/permission.md#开工必读)（原话到 table_rule_map 的对照表在此）；生成“允许主体 × 排除主体 × 资源 × 能力”账本并逐角色回读；只为题面出现的角色建角色，只对题面点名的表授权，能力不超过原话（“查看”即 `read_only`，未点名的表不写入角色）；“所有数据表”“其他表保持只读”等集合表述按 Permission 正文展开 | 创建角色、配置单个角色或添加成员不代替隔离验收；不自建题面没有的「普通用户」等兜底角色，不借它给未点名的表开放编辑 |
| 只要求当前一次性总结、即时通知或会话内分析 | 即时通知走消息路径，不因“提醒/通知”字样建 Workflow；分析交 Analyze-data；明确要求保存/沉淀才建持久结果 | 不得擅自新增 Workflow、总结表、Helper 表或下游表；一次性但未来执行的任务仍交 Workflow |

“看板”按 Dashboard 处理；原话说“看板视图”或要求按字段分列展示记录卡片时才建 `kanban` 视图。

#### 执行前的通用约束

| 约束 | 内容 |
|---|---|
| 取输出 | 取值用 `--jq`；成功 JSON 在 stdout，`Tip:` 和失败 JSON 在 stderr；不用 `2>&1 \| python3 -c 'json.load(...)'` |
| `--jq` 写法 | `+record-list` 配 `--jq` 必须带 `--format json`，此时 `--limit` 为 1～200；jq 对象键写 `{"日期":.[0]}`（加双引号）或英文键，`{日期:.[0]}` 这类裸中文键会被拒；按字段名取列用 `(.data.fields\|index("字段名")) as $i \| .data.data[] \| .[$i]`。`--jq` 报 `cannot iterate over: null` 时：只读命令去掉 `--jq` 重跑一次看真实错误；创建、更新类命令不重跑写入，先用对应的 list 命令查是否已写入，再按返回键速查改取值路径 |
| 写入结果不明 | 解析失败（含 python `JSONDecodeError`／`KeyError`）或超时时写命令多半已成功：先用对应 list／get 回查再决定是否补写，不重发同一批写入 |
| 高风险写入 | `+field-update`、`+field-delete`、`+record-delete`、`+form-questions-delete`、`+dashboard-delete`、`+dashboard-block-delete`、`+role-update`、`+role-member-remove` 带 `--yes`；`+field-update` 用 `--field-id` 定位 |
| 计算字段 | `+field-create`／`+field-update` 的 `formula`／`lookup` 读完 [Formula / Lookup](scenes/field-formula-lookup.md) 后带 `--i-have-read-guide` |
| 不存在的命令 | 没有 `+record-update`（改记录用 `+record-batch-update`）、`+permission-*`、`+form-question-list`、`+advperm-get` |
| 复制表 | “复制一张表／表副本”在同一 Base 内 `+table-copy`，不复制整个 Base |

<a id="单模块功能"></a>

### 对象操作与模块搭建

单项操作与完整模块搭建走同一 Scene 流程，按目标取舍：改表单必填与搭报名表都归 Form，仪表盘补计算字段后仍由 Dashboard 验收。从 CLI 帮助或兼容入口直达 Reference 也须完成该 Scene 的前置、授权和业务验收。已有 Base 内补建依赖表或字段不重启系统规划，仍履行新表要求。

<a id="场景搭建"></a>

### 系统搭建

新 Base、业务系统或多模块组合由 [Build-system](scenes/build-system.md) 首写前统筹，再交各 Scene 执行并收证据；已有清单沿用。用户要求的查看方式是交付物，落为 View、Dashboard 或汇总对象，不以会话查询结果代替。

### 数据分析

独立分析（从单表计数到多表聚合）由 [Analyze-data](scenes/analyze-data.md) 主责，组织 [Query](scenes/query.md) 走 Context → 固定口径 → SQL → 核验；纯分析只读，不触发系统搭建。硬规则：

1. 总量取全部同单位分量之和（总耗时＝各分项耗时相加）。
2. 类别和范围词先读出字段全部取值，写明纳入与排除。
3. “最高／最多／占比”结论用同一次查询结果核对，“多”按绝对量排序；小结、建议里的合计、占比、缺口、约数也取自本轮查询，写“最／唯一／同时”前用 `ORDER BY` 前两行核对。

“金额最大的 10 条订单”是记录排序，“销售额最高的 10 个客户”是聚合分析。搭建中的辅助计算与回读走对象 Scene，SQL 不代替对象状态验收；分析要持久产物时由 Analyze-data 交接产物模块并核对结论一致。

## 执行、验收与交付

### 执行与协作

只读主责 Scene 和路由命中的 Scene（先读开工必读），其他 Scene 不读；Reference 按 Scene 指引按需读，不按目录通读；已读仍适用的不重读。分段读按任务导航取必需章节，提示有后文就补读；读到目录不算读到操作、恢复、验收条款。

写任务首写前把显式要求和适用默认项拆成原子验收项（内部记录），对象、时间、状态、维度等限定各定预期、回读方式与通过条件，简单任务只列必要项；更新先确认替换／合并／增量语义，保护原配置。

- **位置与口径分别验收**：交付物落在用户指定的对象与层级，数值对不代替位置对，不擅换对象。
- **保持业务要求**：条件无命中时如实交付空结果，不放宽条件或造记录凑数；给已有表新增的字段不给存量记录批量填值或设默认值；缺指标时按计算字段流程从真实来源构造并验证，不用近似字段；样例只按已触发的数据规则准备。
- **状态条件正向列出，按字面取值**：“还没开始”只取未开始；先读状态字段全部选项，“未完成／待处理／进行中”写成包含全部未结束选项的条件，不用 `!=` 或只排除一个终态；结束状态通常不止一个。
- **相对时间进筛选并保持动态**：“本周、本月、今年、近 N 天”写进视图、组件或工作流条件，不写死换算日期，名称写“本月”不算；修饰被筛记录的时间词（如“这个月的工资里没发的”，含句首背景时间词）在视图里要有时间条件；结果为空时保留条件，答复说明并另列条件外记录参考。
- **相对日期写法**：仪表盘组件筛选日期直接用 `["CurrentMonth"]` 等关键字；视图只有 `Today`／`Yesterday`／`Tomorrow`，其他范围先建返回文本的辅助公式再筛（本月：`IF(AND(YEAR([日期])=YEAR(TODAY()),MONTH([日期])=MONTH(TODAY())),"是","否")`），写法见 [筛选元组](references/shared-filter-tuple.md)。
- **视图配置写进视图**：新建看板、日历、甘特视图是空壳，创建后用 `+view-set-group`／`+view-set-timebar` 设分组和起止字段。
- **仪表盘从明细表统计**：普通图表优先以明细表为数据源；组件标题里的范围（渠道、本月、某状态）也写进该组件筛选；拆维度配分组，“各 X 的 A、B”每个指标都按 X 分组（平均值也不用全局指标卡）；点名指标在 `data_config` 都有字段和聚合；比率、合格率、及时率先建公式字段；排名按聚合指标排序。
- **自动化先预检再启用**：新建 Workflow 先 disabled，回读条件右值、接收人和动作；接收人绑定承载职责的人员字段（用户说“通知我”才用当前用户），通过后 `+workflow-enable` 并回读状态。
- **写样例数据前先读 [Mock](scenes/mock-data.md#开工必读)**：人员字段空缺、时间晚于当前、状态与日期矛盾、表内少于 5 条都是数据缺陷，这些规则只写在 Mock。
- **派生状态用公式**：由日期、金额、阈值等字段决定的状态（逾期、达标、迟到、金额档位）及可算的金额、余额、人数建公式字段，不建也不留同义手填列。
- **已有实体用关联**：新表字段指向 Base 中已有实体表时建 Link 写对端记录 ID（从源表搬数据直接用源 `record_id`，不转文本）；单号、批次号等业务编号另留独立字段。
- **保护授权与非目标对象**：删除、移除、停用前唯一确认同类型目标和保留项，过 CLI 确认门禁；业务描述不授权删记录。目标不唯一、不存在或不足时报告缺口，不跨类型替代或改非目标资源凑数。验收不扩大写入、启用、触发或外发授权。

跨 Scene 交接带上目标与主责、阶段、待补依赖、授权范围、保留项，复用真实 ID、口径、逐表计划和有效证据，不另建文档；依赖模块只补缺项，交回实际对象、证据与缺口由原主责续验；不重复创建、造数，不重置授权与恢复预算。

### 验收与交付

写任务逐项维护 `pending → written → verified`：写成功只到 `written`，服务端回读满足通过条件才 `verified`；写响应、名称、写前状态、已读协议都不算写后证据。只读任务查读取范围、完整性与结论依据。

- 只核验本轮目标、复用对象、受影响依赖和保留项（须仍可读且语义符合），不扫无关资源。
- 回读证据有效就复用；数据、结构、配置、口径／时间基准、身份／访问或来源一变，相关证据（含已 `verified`）失效并复验。
- 多步骤按用户顺序做，每步写后先过该时点验收（先建后查改删时，创建阶段的结构、数据、提交检查先通过），后续覆盖、关闭、删除不掩盖前阶段未完成。表单／视图连续任务（含单模块）执行 [阶段验收](scenes/build-system.md#连续操作的阶段验收)；收尾按逐表数据目标回读最终状态，明确空表或仅结构副本按例外验收。
- **逐对象回读**：每建完视图、组件、工作流或角色立即按下表读回；原话每个限定词（渠道、状态、本月、降序、剩余量、起止字段、接收人职责）都在返回里找到，找不到当场修。例：“华东区各门店本月销售额从高到低”→ 区域=华东、本月、门店分组、销售额求和、降序。

  | 本轮涉及 | 回读 | 通过条件 |
  | --- | --- | --- |
  | 新建 Base | 逐表 `+view-list`，及已建的仪表盘、表单、工作流、角色列表 | 达到类别目标；答复列出实际模块和每个视图的 `type` |
  | 表结构 | `+field-list` | 同一事实不同时存在公式字段和手填列；库存、人数、到期状态等可算的量是公式或查找 |
  | 视图 | `+view-get-filter`／`-group`／`-sort`／`-timebar`，再 `+record-list --view-id` | 原话和视图名里的时间、状态、分组、排序都在回读配置中 |
  | 仪表盘 | `+dashboard-block-get` 核对配置，布局读 `+dashboard-layout` 返回；只在要读取或解释图表结果时用 `+dashboard-block-get-data` | 点名指标的字段、聚合、筛选、排序都在；布局合规范 |
  | 工作流 | `+workflow-get` 及运行状态 | 触发、条件右值、接收人、写入字段与要求一致；应启用的已 enabled |
  | 角色权限 | `+role-list`，逐个 `+role-get` | 点名角色齐全；每个角色的表、字段、记录权限与要求一致 |

  不一致只修该项再回读一次，仍不一致如实写为未完成。

**答复前核对（四步，缺一步不写答复）**

1. 按[写入前路由](#写入前路由)和原话列出本题应交付的对象：每张表、每个视图、仪表盘及其组件、表单、每条工作流、每个角色。
2. 逐个对照本轮实际执行成功的创建命令：没有对应命令的对象现在就建，不写“已预留”“需手动启用”“后续可配置”；不以任务复杂、缺真实人员或耗时为由简化、推迟或改用当前用户，做不到时写出具体报错。
3. 每个对象按上表回读一次，限定词逐个找到。
4. 主责汇总实际对象、必要入口、验证范围，只写回读到的配置（照抄）和逐表实测条数，不写没执行的内容；必需项全通过才声明全部完成，`pending`／`written`／受阻项分别写明未完成、未验证、失败或 `blocked`、缺失证据及影响，不以局部成功代替整体。

## 异常恢复与停止条件

- 命令确认、响应解析、参数错误按 [调用与恢复协议](references/shared-cli-invocation.md)处理；对象与业务异常进所属 Scene，恢复后回原任务。
- 写入结果未知或部分成功：按「写入结果不明」回查，只续做未成功项；异步操作按协议生效条件核验。
- **同一原因只做一次定向修正并复验**；仍失败报告具体未完成项，继续不依赖它的工作。切换 Scene、Reference 或工具不重置预算；恢复沿用原验收清单，不删业务条件换成功。
- 恢复后对照原要求：自动更新退为通知、专用输入退为普通文本等降级，原能力仍未完成，不移出清单或标 `verified`。
- 必需文件缺失、版本解析失败、能力不支持或前置不成立时停止受影响操作并说明缺口；路径以当前 Skill 根目录为准，不猜本机路径或复杂请求，不用反复写入探测缺失契约。
- 等待只用工具明确支持的等待／后台机制，不拼 `sleep`，被拒不改用脚本绕过。最终答复用最新实测状态。
