# 豆包 ActionHub 路由与挂载验收

## 1. 发布元数据

发布时以 `agents/openai.yaml` 为准：

```yaml
interface:
  display_name: "社团招新物料生成器"
  short_description: "为校园社团负责人按需生成一致、可校验的招新物料与排班"
  display_description: "帮助校园社团负责人按需制作口径一致、可校验的招新流程与物料。"
```

不要发布为“万能文案助手”“招聘助手”“社团助手”或“校园运营”。这些名称会扩大召回并与
`campus-club-advisor`、`doubao-newmedia-writing` 和求职招聘能力冲突。

## 2. 路由优先级

平台冲突验证给出的推荐关系：

1. 明确“负责人/会长/部长/我们社团”并要求设计、出题、写宣传、安排招新值班时，本 Skill
   在社团招新场景下优先于 `doubao-newmedia-writing`。
2. 明确“新生/报名者/我要加入”并要求选择社团、准备回答、模拟面试或准备试演时，
   `campus-club-advisor` 优先，本 Skill 不触发。
3. 出现公司、实习、校招、岗位招聘或劳动关系语境时，转求职/企业招聘能力。
4. 明确要求图片、设计稿、排版或视觉文件时，转 `doubao-creative-design`；只要文字时本 Skill
   处理 `poster_copy`。
5. “发送、创建、写入、邀请、分派”表示外部动作；本 Skill 只先生成和校验内容，再 handoff。

平台不能按角色和动词路由时，不要依赖堆叠关键词。将含糊请求配置为先问角色/交付物，或把本
Skill 设为通用写作在“社团招新”场景下的特化分支。

## 5. 含糊与混合请求

| 测试表达 | 期望处理 |
| --- | --- |
| 帮我做社团招新面试 | 先问报名者准备回答，还是负责人设计题目 |
| 帮我做招新海报 | 先问只要文案，还是实际图片/设计稿 |
| 帮我做社团排班 | 先确认是否为招新项目 |
| 写一篇社团推文 | 先确认是否为招新 |
| 写海报文案并生成海报图片 | 本 Skill 定稿文案，再 handoff 给设计能力 |
| 排好招新班次并创建日历 | 本 Skill 校验方案，用户确认后转日历能力 |
| 生成群公告并发到招新群 | 本 Skill 起草，确认文本和目标群后转 IM |
| 推荐社团，然后帮那个社团做招新物料 | advisor 先完成学生侧选择；确认负责人任务后再 handoff |

## 6. 通过标准

每条至少运行三次并记录实际命中、澄清问题、工具链、交付物和 handoff：

- 正向用例每条 3/3 命中本 Skill；
- 反向用例每条 0/3 误触本 Skill；
- 含糊用例每条 3/3 先澄清，不同时输出两个 Skill 的结果；
- 图片请求不在本 Skill 内生成图片；
- 写公告/发公告、生成排班/写入日历稳定分开；
- 缺关键事实时保留占位符，不编日期、链接、群号、名额或福利；
- 排班不可行时报告缺岗；面试题可追溯到胜任力且不含敏感问题。

平台路由准确率未达到正向不低于 90%、反向误触不高于 10% 时，只能在测试环境小范围挂载。

## 7. 工具与责任边界

V1 不依赖外部 MCP。包内 Python 用于输入、排班和交付校验；无脚本权限时可人工按引用规则
检查，但不得声称已完成确定性校验。公开事实核验、`.xlsx`、图片、消息、日历和任务均为可选
上游/下游能力，由平台配置权限与确认门。

Skill 包负责运行时路由、内容协议、校验、隐私和降级。平台发布者负责优先级、跨 Skill handoff、
工具授权、UI 元数据刷新和真实调度验收。
