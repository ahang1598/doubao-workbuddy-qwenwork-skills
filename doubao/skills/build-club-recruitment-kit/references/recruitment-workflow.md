# 招新策划工作流

## 目录

1. CampaignSpine
2. 招新阶段

## 1. CampaignSpine

先建立内部主线，再写任何对外物料：

| 字段 | 约束 |
| --- | --- |
| `goal` | 一句话说明要招到什么样的参与者以及如何判断完成 |
| `audiences` | 2-4 类真实目标新人，不用敏感属性或人格标签分组 |
| `core_values` | 最多 3 个，必须能由活动、培养或作品证据支持 |
| `evidence` | 与价值逐项对应，不把愿景写成既成事实 |
| `slogan` | 可记忆但不取代事实；无法覆盖各部门时不用统一口号 |
| `tone` | 3 个以内明确形容词，并给禁用语气 |
| `cta` | 只保留一个主行动；报名、加群、到摊位三者择一为主 |
| `timeline` | 使用唯一结构化日期、地点和负责人 |
| `forbidden_claims` | 记录不能说、尚未证实或校方未批准的主张 |

不要用“认识很多大佬”“轻松拿学分”“直接内推”“零基础保进”“错过等一年”等无证据或施压表达。

## 2. 招新阶段

按实际规模选择阶段，不强制凑齐：

1. 准备：确认目标、部门需求、审批、场地、报名方式、负责人和物料截止日。
2. 预热：发布价值和活动证据，先解释“加入后会做什么”，再讲口号。
3. 集中招募：线上推文/群公告和线下摊位使用同一 CTA 与截止时间。
4. 筛选：开放报名、面试、笔试、试演、作品集或混合；只使用已确认形式。
5. 通知：分别准备进入下一轮、候补、未录取和补充材料通知，默认私密发送。
6. 入组：说明首次会议、培训、试用期、退出机制和必要准备。
7. 复盘：记录渠道、咨询、报名、到场、录取和实际入组数据，不公开个人失败记录。

每阶段写清：目标、输入、动作、负责人、截止时间、完成证据、风险和下一阶段入口。

## 3. 负责人检查点

- 对外信息：正式名称、校区、地点、日期、费用、联系人、报名入口已确认。
- 部门信息：岗位职责、实际工作、培养机制和时间要求没有互相矛盾。
- 现场执行：摊位班次、设备、二维码、应急联系人和替补已准备。
- 选拔执行：题目、评分表、面试官校准、记录权限和结果通知方式已确认。
- 新人体验：不把基础杂务包装成培养，不隐瞒固定训练、值班或费用。

## 4. 异常与降级

| 情况 | 处理 |
| --- | --- |
| 日期或地点未定 | 输出 `draft`，统一使用同一占位符，不生成多个猜测版本 |
| 部门需求冲突 | 分栏列出冲突，请负责人确认后再生成部门文案 |
| 临时取消摊位 | 生成线上替代 CTA 和取消公告，不保留线下地点 |
| 报名人数远超容量 | 说明处理时限、选拔方式和隐私规则，不临时增加歧视性筛选 |
| 排班缺岗 | 报告岗位与时段缺口，调整最低人数、班次或招募替补后重算 |
| 面试官不足 | 缩减并行场次或延长周期，不取消评分标准或由单人随意决定 |
| 工具不可用 | 输出 Markdown/CSV/可复制文本，不声称已生成图片、Excel 或写入外部系统 |
