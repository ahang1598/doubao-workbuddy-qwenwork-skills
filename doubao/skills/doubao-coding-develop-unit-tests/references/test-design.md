# 测试设计

写、补或修测试时读取。目标是用少量反例保护调用者可观察的契约。

## 行为依据

按权威性选择预期：

1. 用户要求和验收条件。
2. 公开协议、API、需求和仓库规则。
3. 可信既有测试、类型/schema 和直接调用方。
4. 当前实现；仅有此依据时标记为“推断行为”。

冲突会改变断言时请求确认。实现独有的 panic、nil 处理、内存别名、拷贝方式和私有缓存结构作为风险报告，除非上层契约确实依赖。

## 最小行为表

从适用行中选择：

| 风险 | 期望 | 典型错误实现 |
|---|---|---|
| 主要路径 | 完整结果和必要副作用 | 默认值、漏字段、漏调用 |
| 边界/无效输入 | 临界点两侧、错误、状态保持 | `<`/`<=`、空与缺失混同 |
| 依赖失败 | 错误传播、回滚或停止 | 吞错、泄漏污染结果、继续调用 |
| 状态轨迹 | 中间状态和最终不变量 | 陈旧状态、部分更新 |
| 重试/时序 | 正确次数、停止点和顺序 | 多一次、少一次、成功后继续 |
| 转换/聚合 | 字段、顺序、精度和总量 | 映射错位、局部量当总量 |
| 幂等/并发 | 重复或换序后的不变量 | 重复副作用、竞争、超卖 |
| 历史缺陷 | 最小稳定复现 | 只验证补丁结构 |

对每个公开入口，列出失败点之后仍可观察的状态变更、写入和调用，并给出期望。资金、权限、租户、资源生命周期和并发先写不变量，再选择能破坏它的输入。

## 选择反例

写入前必须实际列出编号表 `测试 | 输入轨迹 | 唯一错误实现`，再按表写代码。每增加一行，错误实现必须与已有行不同；否则不得新增测试，只能把新输入或断言并入已有行。不同名称、输入、验收条目或 trace 长度不构成不同反例。

边界只取决策点两侧的最少代表；同一分区的多个值放进一个参数化/循环测试。同一轨迹上的结果、次数、顺序、停止点和最终状态合并断言，不按验收条目逐项拆测试。

重试类通常只需四条不同轨迹：零次、首次成功、失败后成功、全部失败；尝试编号、调用次数、成功停止和最终错误是这些轨迹内的断言，不能据此再拆测试。只有能命名新的错误实现时才增加轨迹。

优先使用：

- 翻转条件或遗漏分支。
- 出错时泄漏非零、部分或污染结果。
- 跳过状态更新、清理或必要副作用。
- 重复、提前停止或多执行一次。
- 使用陈旧缓存、游标、索引或累计值。

断言完整结果、错误、状态和必要交互。“未报错”“非空”或 truthy 只有在它们构成完整契约时才足够。错误身份属于契约时比较同一对象；值相等、类型相同或消息相同不能代替身份。

状态型目标至少包含一条 `初始 → 操作 → 中间状态 → 操作 → 不变量` 轨迹。重试目标覆盖成功停止和耗尽停止，并使用可控结果序列。

## 模式

- **补测试：** 原实现 GREEN；探针反例 RED。
- **TDD：** 新行为缺失产生有效 RED，再实现 GREEN。
- **缺陷回归：** 最小输入先复现错误，修复后同一测试 GREEN。
- **修复测试：** 先确认契约，再修 fixture、替身、状态或环境根因。

## 完成

- 用户点名行为均已映射。
- 回读最终测试并重做 `测试 → 唯一错误实现` 映射；删除任一测试后若同一错误实现仍被其他测试击穿，合并或删除该测试。
- 断言通过公开结果成立，并能经受保持行为的重构。
