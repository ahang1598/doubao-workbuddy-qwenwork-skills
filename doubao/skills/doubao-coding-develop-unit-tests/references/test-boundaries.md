# 测试边界

涉及外部依赖、时间、随机、全局状态、资源、异步、并发或不稳定测试时读取本文件。

## 选择替换点

按 `真实依赖 → Fake → Stub → Spy/Mock` 选择最轻方案：

- 保留快速、确定、内存内且无外部副作用的领域计算。
- 在网络、数据库、文件、进程、SDK、时钟、随机源和不可逆操作的最低可注入点替换。
- 交互次数、参数或顺序属于契约时，才记录并断言它们。

## 替身契约

实现替身前对齐：

| 项目 | 必须保持 |
|---|---|
| 查找与调用 | 真实注入点，以及同步、异步、流或回调形态 |
| 输入 | 本场景需要观察的参数、上下文和值 |
| 输出 | 成功、空、部分结果、错误和超时的真实类型 |
| 数据与状态 | 被测路径读取的字段，以及写入、事务或缓存变化 |
| 轨迹 | 契约要求的次数、顺序和失败后的下游行为 |

管线失败使用同一份 `trace` 记录已发生阶段，并让失败依赖同时返回可识别的非零或部分结果。断言错误语义、结果是否泄漏、状态是否保持，以及 trace 在失败点停止。这样一个调用即可击穿“忽略错误继续执行”和“返回脏结果”两类错误实现。

## 确定性设施

- 时间：fake clock、可注入时钟或框架定时器；固定时区和边界时刻。
- 随机：固定 seed 或生成器；把失败 seed 固化为回归输入。
- 环境：每个测试设置并恢复自己的环境变量、locale、flag 和注册表。
- 文件与资源：隔离临时目录；teardown 释放文件、连接、线程、任务、timer 和订阅。
- 异步与并发：事件、屏障、channel、continuation 或条件变量；等待“已进入”再断言，释放后等待任务退出。

## 不稳定测试

保存原始命令、环境、seed、失败信息及单测/套件差异。有限重复只用于测量失败率；依次检查时间、随机、顺序、共享状态、固定端口/路径、未等待任务和资源泄漏。把根因变成可控条件后，用原命令稳定复验。

**完成：** 替身保持真实契约；失败轨迹和脏结果可观察；时间、状态和资源生命周期可控；相同输入独立运行得到相同结果。
