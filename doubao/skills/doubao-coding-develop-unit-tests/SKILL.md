# 单元测试

用 **契约 → 反例 → 证据** 驱动测试。先完成一个 **探针测试（tracer test）**：它保护最高风险契约，并能对一个明确错误实现变红；取得这份证据后再扩展。

## 边界

- 以用户要求、项目规则和现有工具链为准；沿用邻近测试的框架、位置、命名、fixture、替身和断言风格。
- 默认只写测试和既有测试辅助文件；用户授权 TDD 或生产修复后才改生产代码。依赖、lockfile、测试配置和 CI 变更需要单独授权。
- 通过公开入口和调用者可观察结果取证。覆盖率只用于发现遗漏。

## 1. 建立契约

1. 判断模式：补测试、TDD、缺陷回归、修复测试或仅运行。
2. 读取仓库规则、目标代码、公开需求或接口、直接调用方、构建配置和一至两个邻近测试。
3. 为每个目标记录：`符号 | 行为依据 | 可观察结果 | 失败后的状态/副作用 | 写入范围 | 聚焦命令`。

测试入口、发现规则或模块边界不明确时，读取 [工具与发现](references/tooling.md)。

写、补或修测试时，写入前必须读取并执行目标语言适配器：

| 语言 | 适配器 | 语言 | 适配器 |
|---|---|---|---|
| Go | [Go](references/languages/go.md) | JavaScript / TypeScript | [JS/TS](references/languages/javascript-typescript.md) |
| Python | [Python](references/languages/python.md) | C / C++ | [C/C++](references/languages/c-cpp.md) |
| Java | [Java](references/languages/java.md) | Kotlin | [Kotlin](references/languages/kotlin.md) |
| Rust | [Rust](references/languages/rust.md) | Swift | [Swift](references/languages/swift.md) |

其他语言沿用仓库证据和本流程；仅运行既有测试时跳过适配器。

**完成：** 目标语言适配器已读取；每个目标都有权威依据、可观察结果、写入边界和可执行命令；歧义会改变断言时，只询问该项。

## 2. 设计反例

仅运行既有测试时进入步骤 4。其他模式读取 [测试设计](references/test-design.md)。写代码前实际列出编号表：`测试 | 输入轨迹 | 唯一错误实现`；没有不同错误实现就不得新增测试。同一轨迹上的结果、次数、顺序、停止点和状态合并断言。

需要替身，或涉及外部依赖、时间、随机、全局状态、资源、异步或并发时，读取 [测试边界](references/test-boundaries.md)。选择最高风险行作为探针测试。

探针针对依赖失败时，让失败替身在同一次调用返回 `可识别污染结果 + error` 并写入 trace；断言错误、结果不泄漏且 trace 停在失败点。

**完成：** 用户点名行为均已映射；表中错误实现互不重复；同一等价类的输入已合并为一个参数化/循环测试；失败点后的状态和副作用都有预期。

## 3. 证明探针

1. 先写必要 fixture 和一个探针测试，运行项目原生命令并确认它被发现。
2. 补测试时取得 **GREEN**；本地源码可复制且命令可运行时，在仓库外临时副本引入探针反例并取得 **RED**。无法实跑变异时，回读并指出会变红的具体断言和未验证原因。
3. TDD 或缺陷回归先取得有效 **RED**，再在授权范围内实现 **GREEN**；编译、fixture 和环境错误不算 RED。
4. 探针证据成立后，才按表扩展。写完回读最终测试：逐个写出其唯一错误实现；若删除某测试后，同一错误实现仍会被其他测试击穿，就合并输入或删除该测试。

**完成：** 探针被发现；GREEN/RED 原因属于目标行为；每个新增测试对应一个不同反例。

## 4. 收集证据

1. 运行聚焦测试，再运行所属文件、包或模块的相关回归；核对测试名称或执行数量。
2. 失败归类为 `behavior_failure`、`test_failure`、`environment_block`、`not_discovered` 或 `flaky`。从第一条因果诊断修正，最多三轮。
3. 运行版本控制状态命令核对文件范围；缓存、报告和临时产物留在仓库外。非授权路径仍存在时，清理后复查，不能报告通过。

**完成：** 每个目标都有原生命令、退出状态、发现证据和结论；请求范围与必要回归全部通过时才报告 `通过`。

交付顺序：`状态 | 修改文件 | 已验证行为 | 命令与结果 | 剩余缺口`。状态使用 `通过`、`部分完成`、`失败`、`已编写未运行` 或 `无法执行`。
