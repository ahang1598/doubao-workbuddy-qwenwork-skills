# 角色体验与 UI 设计

## 从角色推导互动

先写一张简短的“角色体验卡”：

- 角色是什么、叫什么；
- 3–6 个不可丢失的身份特征；
- 2–4 个性格词；
- 用户与它最自然的接触方式；
- 它喜欢的食物、玩具或奖励；
- 不适合它的动作和文案。

首版互动需要同时满足：用户一眼能理解、角色做得自然、能形成可见动作、能给出一句角色化反馈。避免只有数据变化而没有动作，也避免生成漂亮动作却没有入口。

示例仅用于推理，不是固定菜单：

| 角色 | 合理互动 | 避免机械套用 |
|---|---|---|
| 猫 | 摸头、喂小鱼干、逗猫棒、睡觉 | 给所有动物都喂小鱼干 |
| 狗 | 挠下巴、喂骨头、扔球、握手 | 复制“踩奶、舔毛” |
| 兔子 | 摸耳朵、喂胡萝卜、蹦跳、钻纸箱 | 强行做犬类接球 |
| 机械/物品 | 充能、擦拭、校准、展示状态 | 使用动物器官和食物文案 |

互动 ID 使用语义化小写连字符，例如 `pet-head`、`feed-bone`、`play-ball`。每个互动在 `experience.interactions` 中绑定独立 `emoji`、`stateId`、持续时间、好感变化和 2–6 条短反馈。菜单统一渲染为“emoji + 文案”，不要把 emoji 混进 `label` 后再丢失。

## 动态层级

动画由三层组成：

1. **素材帧**：眨眼、进食、玩耍、触摸反馈等关键动作必须有真实姿势变化。
2. **程序微动**：待机呼吸使用 1%–3% 的纵向伸缩和更小的横向反向补偿，底部锚点不漂移。
3. **交互回弹**：点击、落地或成功反馈可做一次 180–420ms 的压缩—超调—复位。

程序形变只增强生命感。禁止用整张图大幅旋转、平移或拉伸冒充走路、挥手、摇尾巴等局部动作。

## 圆润可爱但不幼稚的 UI

根据角色毛色、材质和性格生成一套色板，写入 `experience.theme`。默认规则：

- 背景使用低饱和暖色或角色主色的浅色阶；
- 主按钮使用高对比强调色；
- 面板、提醒窗设置 `frame: false`，内容容器 18–28px 圆角；
- Electron 宿主、`html` 和 `body` 全透明且 `overflow: hidden`；确需滚动时只让设计过的内部容器滚动，并隐藏系统滚动条；
- `button/input/select` 重置系统外观，选择框使用自定义箭头和角色色板，避免 Windows 默认灰框；
- 使用 8px 间距体系、清楚标题层级和最多两级阴影；
- 输入框、快捷时间和按钮都有明显悬停/按下反馈；
- 文案使用角色名字和真实互动，不出现通用的 `DESKTOP PET` 占位感；
- 关系数值配进度条，数据卡不超过 3–4 张；
- 表情符号只能作为小图标辅助，不能替代布局、图标和层级。

桌宠窗口默认基线为 220px、默认档位 0.8，处理后主体最大边约占透明画布 72%–80%，使首屏可见主体通常落在 130–170px。提供 0.65/0.8/1/1.2 四档，不使用“最小档仍接近 200px”的尺寸梯度。

托盘图标使用确认的核心形象生成 32×32 透明 PNG，裁成清晰头像或轮廓，不直接缩整张带大量留白的 512px 图。Windows 运行时必须检查图像非空；右键菜单的提醒、小屋、文件口袋、隐藏和退出也应有语义匹配的 emoji。

面板默认包含角色头部、名字/关系等级、好感度进度、三张状态卡、提醒/设置标签和底部操作。提醒窗默认提供 1/5/10/30/60 分钟快捷选项、自定义时间和一句示例占位文案。

## UI 验收问题

- 去掉文字后，主次按钮是否仍能辨认？
- 角色颜色是否真正进入面板，而非只有一条强调线？
- 是否存在系统标题栏、默认灰背景或未经设计的原生表单观感？
- 360–540px 窗口下是否无裁切、无横向滚动、无系统滚动条和矩形宿主底色？
- 默认档位与最小档的可见主体是否分别落在合理范围，而不是只缩了透明窗口？
- 托盘图标是否真实可见、与角色有关，托盘和右键菜单是否都有克制的 emoji？
- 提醒内容很长、列表为空、权限关闭时是否仍然美观？
- 互动后动作、气泡和数据是否同步变化？
