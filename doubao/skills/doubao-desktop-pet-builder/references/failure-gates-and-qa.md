# 失败门禁与验收

命中任一阻断项时，不得宣称完成。

## 快速目录

- 资产与功能覆盖
- 视觉阻断

## 资产与功能覆盖

- 状态没有 `triggers`，或触发器没有代码/菜单/系统事件入口；
- 启用功能没有对应视觉与反馈，或关闭功能仍生成专属素材；
- 互动入口存在但只改数字，不播放动作或角色反馈；
- 新生成首版待机少于 4 帧，眨眼/点击/提醒/贴边或任一首版互动少于 5 帧，或把 3 帧当成默认交付；
- 重复同一图片文件、复制像素相同图片或整图形变冒充多帧；
- `walk-left/right`、`typing`、文件拖入等素材在功能关闭时仍被当成完成项；
- 联系表只展示状态图，没有“入口/触发器、帧序号、持续时间”。
- `src/assets/pet` 中存在未被 `pet-spec.json` 引用的 PNG，或 spec 引用的文件无法被 Webpack 递归导入；
- 语义分割后仍保留不透明矩形、地面、底座、投影和宽扁底色块；
- 执行者用 padding、改写背景配置、放宽阈值或关闭 QA 迁就生成结果；

`qa:assets` 区分两类结果：高置信度问题（`GROUND_RESIDUE`、`SOLID_BLOCK`、触边、无透明、尺寸错误）为阻塞失败，必须重生成；中置信度的 `GROUND_RESIDUE_REVIEW` 只是需人工复核的非阻塞警告，对照联系图确认是角色本体即可放行，不得为消除它而放宽 `targetOccupancy` 或关闭检查。`process:assets` 输出已被限制在 `targetOccupancy` 之内，正常不会再触发 `OCCUPANCY_TOO_LARGE`；若仍触发，说明单帧构图确实过大，应重生成该帧而非调高阈值。

`qa:experience` 必须非零拦截不可达状态、缺入口互动、条件功能错配和动态不足。

## 视觉阻断

- 动作与 `core-ip` 的身份、配色、比例或配饰明显漂移；
- 伪透明、白底当透明、全局近白阈值误删主体；
- 深色联系图上出现明显白色光晕，或 `SOLID_BLOCK` 检出高填充率不透明矩形；
- 主体触边、色边、缺帧、同状态锚点或角色尺寸明显跳动；
- `idle`/`blink` 主体高度漂移超过 2.5% 或中心漂移超过 1.5%，其他同状态动作等效尺度漂移超过 8%；
- 未许可镜像、空闲状态朝向反复翻转；
- UI 使用系统标题栏、宿主底色框、系统滚动条、默认灰背景或未经设计的原生表单观感；
- 默认可见主体明显大于约 170px，或最小档仍接近 200px；
- 托盘图标为空、与角色无关或缩成无法辨认的小点，右键/托盘菜单没有语义化 emoji；
- 角色名、物种、食物、玩具或文案与实际角色不匹配；
- 360–540px 窗口出现裁切、横向滚动、长文案溢出或按钮遮挡。

## 动态与交互阻断

- 待机完全静止，没有素材微动或轻微呼吸；
- 呼吸导致脚底漂移，或缩放幅度过大像果冻；
- 点击没有压缩/回弹、动作或气泡中的任何两种反馈；
- 右键菜单仍只有“面板/退出”等工具项，没有 2–4 个角色互动；
- 提醒、互动、拖拽、贴边后状态没有恢复到合理基态；
- 多套定时器覆盖，没有统一抢占、恢复和销毁规则。
- 循环互动没有明确持续时间或结束后不回到 `idle`，低优先级状态能够打断高优先级状态，冷却期可以重复触发。
- 拖拽直接触发浏览器图片拖影，或移动后的 pointer/click 仍误触点击动画。

## 工程与安全阻断

- renderer 开启 Node、直接访问文件系统或接收完整 IPC；
- 严格 CSP 与 Webpack `eval-*` devtool 同时存在，或通过加入 `unsafe-eval` 掩盖开发配置错误；
- `npm run dev` 执行 package/make、生成 `out`/`release`，或普通开发命令长期开放远程调试端口；
- IPC 未同时校验 sender 和 payload；
- 面板/提醒挤进桌宠透明小窗；
- 拖拽在多屏/DPI 下跳变；
- 全局键盘监听记录键值或权限失败导致主程序崩溃；
- 硬编码盘符、依赖 `File.path`、吞掉未捕获异常；
- 报错窗口出现但仍宣称“持续运行”。
- 第二实例创建重复托盘/写入者，退出没有等待原子持久化，或损坏设置、统计、提醒导致启动失败且没有 `.corrupt` 备份。
- 代码、配置或包名出现 UTF-8/GBK 乱码，但校验仍放行。

## 启动与话术阻断

- 把 Webpack 编译完成、开发服务器地址、Electron 进程存在或 `Launched Electron app` 当作可见桌宠证据；
- 图片 `src` 为空、`naturalWidth` 为 0、渲染器未回报状态或窗口不可见时仍说“启动成功”；
- 日志写入、初始化或 renderer 报错后说“不影响主功能”，却没有自动证据；
- 把开发预览说成最终版，未提醒尚未试玩、未打包或未生成可执行程序；
- 用“Sharp 比我写的靠谱”“先安装 Pillow”等工具自评和临时换库话术代替稳定流程。
- 只有 `DEV_PREVIEW_READY`，没有截图证据或用户确认，却声称用户已经看到桌宠。

## 构建阻断

- 通过反复 `TaskOutput`、按 1–3 分钟猜测、停止并重启来等待构建；
- 构建进程仍活跃时删除 `.webpack`、`out` 或切换打包方式；
- 没有完整日志、退出码、状态文件和唯一 PID；
- Squirrel 失败后未经用户同意改交 ZIP，或用系统压缩并伪造清单；
- 把 package 目录中的 EXE 描述为可单文件分发；
- 构建成功但没有核对本轮时间、大小、SHA-256 和实际启动。

## 自动检查顺序

保存命令、时间、退出码和证据路径：

1. `validate_pet_spec.py` / `npm run check`：v5 schema、语义分割配置、独立母版、互动、条件功能、UTF-8、运行时素材路径和 Webpack 递归导入。
2. 单元测试：状态抢占、计时器、拖拽、持久化、互动统计、触发器覆盖和权限降级。
3. `qa:assets`：尺寸、alpha、实心矩形、触边、背景/投影残留、同状态帧锚点与严格尺度漂移；同时查看浅色和深色联系图。
4. `qa:experience`：所有状态可达、所有互动有入口、动态帧基线满足。
5. `qa:ui`：透明宿主、无系统滚动条、原生控件重置、默认尺寸档位、非空托盘 PNG 和菜单 emoji。
6. 开发预览握手：必须输出 `DEV_PREVIEW_READY`，报告三个 renderer bootstrap、IPC、图片 `naturalWidth`、素材数、当前状态和桌宠可见性；仅有三个 BrowserWindow 不算通过。
7. Playwright Electron：三个独立窗口、无页面错误、首帧真实显示、无页面级溢出/系统滚动条、菜单互动、动作变化、气泡、提醒、面板头像/数据和关键截图。测试必须读取当前 spec，禁止硬编码回归夹具的角色名、状态 ID 或互动 ID。
8. 稳定性：常规候选至少连续 5 分钟循环互动、拖拽和设置切换；发布候选运行 60 分钟，不得出现 renderer 崩溃、日志堵塞、IPC 堆积或持续内存增长。
9. 用户试玩确认：至少实际完成一次互动和提醒，并明确知道这不是最终包。
10. 目标平台构建、manifest、安装/解压启动。

首轮生成先运行 `generate_asset_plan.py`，再用 `idle` 做一组试产。每个状态生成后运行 `npm run inspect:assets -- --state <状态>`，按错误码只返工失败组；完整 `npm run check` 仍必须覆盖全部状态，状态级检查不能作为最终通过证据。

## 真人清单

Windows 与 Mac 分别执行：启动/退出、托盘、左右键、角色互动、动作和气泡、好感变化、拖拽、多屏/DPI、置顶、贴边、提醒、面板、条件功能、重启恢复、最终产物运行。

两端各至少一次 60 分钟稳定性测试：无未处理异常、窗口丢失、监听器泄漏、持续增长的计时器或内存明显单向增长。无法完成的端标记“待确认”。GUI 工具只辅助取证，不替代自动握手、renderer ready、素材加载、窗口可见性和真人体验。

## 豆包前向测试

1. 纯文字创建：从任意角色描述创建 `core-ip`，完成试产、逐状态素材、试玩和交付；QQ 企鹅仅作为背景残留与身份一致性的回归样例，不是能力边界。
2. 上传单图创建：保留用户角色身份，完成互动设计、母版、功能联系表、试玩反馈和最终交付。
3. 完整素材创建：复用合格帧，只补缺失或失败状态。
4. 专家修复：导入已有桌宠，优先局部修复，不推倒重做。
5. 打包：Windows 与 Mac 在真实目标系统运行受控构建。

展开豆包思考记录，检查是否先生成无用途素材、每张图使用不同背景色、把状态文件当功能、全部单帧、跳过试玩、把进程存在当启动成功、忽略初始化错误、反复等待重启、临时安装单个库、临时改配置或手工伪造交付。观察结果与预先期望分开记录。
