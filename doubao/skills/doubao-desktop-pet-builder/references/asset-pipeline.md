# 资产流水线

## 先建功能清单，再生成素材

`core-ip` 是角色身份的唯一视觉真值。先锁定轮廓、主色、五官、比例、标志配饰、材质和禁改项，再为 `pet-spec.json` 中已启用的触发器生成素材。

每个状态必须同时具备：

- `triggers`：谁会触发；
- `frames`：实际播放帧；
- 入口或系统事件：右键互动、点击、提醒、贴边、文件拖入等；
- 自动或人工验收步骤。

没有触发器的状态不要生成。条件功能关闭时，不生成其专属状态：全局打字关闭则不生成 `typing`；自动行走关闭则不生成左右行走；文件口袋关闭则不生成拖入成功/失败素材。

## 唯一母版规则

- 单图输入：用 `image_edit` 标准化上传图为 `core-ip`。
- 文字输入：只在创建 `core-ip` 时使用一次 `image_gen`。
- 所有动作：继续引用确认的 `core-ip`，提示词写明只改变动作/表情，不改变身份特征。
- 完整动作包：优先确定性修复，只有缺失或不合格的功能帧才补图。
- 照片参照：默认生成轻度卡通化桌宠贴纸，保留脸型、花纹、配色、身体比例和标志配饰，不追求照片级材质与环境光；只有用户明确要求写实才生成真实照片风动作帧。`subjectKind: photo` 只控制抠图模型，不控制生成画风。

默认先用 `image_gen`/`image_edit` 请求“独立角色素材，真实透明背景，无地面、无投影”。真实 alpha 直接保留；Alpha 校验失败时，macOS 14+ 只使用 Apple Vision，Windows 只创建一次模板受控的临时 `rembg` 环境：插画选择 `isnet-anime`，照片选择 `birefnet-general`。平台后端失败立即停止，不切换后端、不重复安装。成功结果按源图哈希缓存，源文件未变时不重复分割。

`assetPipeline.subjectKind` 必须按输入设置为 `illustration` 或 `photo`，不确定时才用 `auto`。`generationBackground` 为 schema v5 兼容字段，不得在语义后端失败后通过修改它切换回颜色抠图，也不得把生成出来的背景颜色回写成配置真值。

模型输出必须满足：角色悬空呈现为独立贴纸/PNG 素材；无环境光、地面、底座、投影、接触阴影、色块和装饰边框。不得依据模型口述认定透明，也不得因为脚本能抠掉大部分就忽略联系表中的残留底色。

## 动作提示词骨架

先运行 `python scripts/generate_asset_plan.py <pet-spec.json> --output <asset-plan.json>`。它将状态、触发入口、帧序号、动作阶段和禁止元素固化。每个状态作为同一动作序列一次生成，不能把帧提示词拆成互不相关的独立任务：

> 保持核心角色的脸型、五官、毛色/材质、身体比例和标志配饰完全一致。参照照片且用户未明确要求写实时，采用轻度卡通化桌宠贴纸风，优先身份特征，不生成真实照片风动作帧；用户明确要求写实时才保留照片级材质。卡通原图沿用既有画风与风格化程度，不因背景要求改变角色画风。为【触发入口】制作【动作名称】的第 N/M 帧：描述当前关键姿势及与前后帧的变化。完整身体居中，角色身体基准高度、头部中心、镜头、画幅和脚底基线与本状态第 1 帧一致，四周都有充足安全留白。输出独立透明 PNG 素材；若无法真实透明，仅背景使用与角色明显区分的单一纯色（只改背景，不改角色）。禁止人手、额外角色、未确认道具、文字、水印、装饰边框、场景、渐变、光晕、地面、底座、投影和接触阴影。只改变完成该动作所需的局部姿态和表情。

先列关键姿势：准备 → 接触/发力 → 反馈 → 回位。不要把多帧理解成重复生成几张近似静态图。

先只生成一组 `idle` 试产帧并立即检查。试产失败时先修正母版引用、背景策略或构图提示，不继续批量生成。试产通过后逐状态生成；不得因为单组失败重新生成已经合格的其他状态。

## 帧数基线

| 用途 | 默认帧数 | 说明 |
|---|---:|---|
| `idle` | 4–6 | 配合轻微呼吸，包含耳、尾或表情的细微变化 |
| `blink` | 5 | 睁眼 → 半闭 → 闭眼 → 半开 → 睁眼 |
| 点击/开心 | 5 | 准备 → 压缩 → 反馈 → 回弹 → 回位 |
| 首版角色互动 | 5–6 | 必须出现准备、接触、主动作、反馈、回位 |
| `notify` / `peek` | 5 | 出现、强调与回位清楚 |
| 文件拖入反馈 | 5 | 仅功能开启时生成 |
| 行走/跑动 | 6–8 | 仅自动移动开启时生成，不能用静态图平移代替 |
| 睡眠 | 4–6 | 呼吸、耳尾或气泡变化 |

新生成首版不再以 3 帧作为合格默认。交互帧间隔通常为 80–140ms，眨眼为 55–90ms；需要停顿时在状态机中延长关键帧或重复节奏，不把每帧拖到 200ms 以上制造卡顿。

## 确定性处理

1. 优先接受真实 alpha；不透明输入严格按平台执行一次语义分割。成功后先检查 Alpha 边缘是否触边，再计算前景边界，不重复执行背景颜色簇检测。后端不可用时立即停止。
2. Alpha 边缘必须恢复前景颜色，不能只把白色背景像素的 alpha 调低，否则在深色桌面上仍会出现白色光晕。
3. `SOLID_BLOCK` 表示结果仍是高填充率矩形；必须更换正确分割后端或重出。`SUBJECT_TOUCHES_BORDER` 表示源图已裁断，padding 无法恢复缺失内容。
4. 检查真实 alpha、透明像素比例、矩形填充率和非主体连通块，并同时生成浅色与深色联系图。
5. 同一状态先完成全部抠图，再使用同一个缩放系数归一化到 512×512；禁止每帧各自“尽量放满画布”。保持底部中心锚点，主体最大边默认占画布 72%–80%。
6. `idle`/`blink` 以主体高度和脚底锚点锁定尺度：高度漂移不得超过 2.5%，中心漂移不得超过 1.5%；宽度可随耳、尾和肢体姿态变化。其他动作按等效面积判断尺度漂移。
7. 生成资产报告、素材链接报告、体验覆盖报告、联系表和对齐图。联系表按状态分组，标注触发入口、帧序号、尺寸和锚点漂移。
8. 从处理后的 `core-ip` 生成 32×32 透明托盘 PNG，检查非空、主体占比和边缘清晰度。

使用 `npm run inspect:assets -- --state <状态>` 做状态级处理和 QA。报告中的 `SOLID_BLOCK`、`SUBJECT_TOUCHES_BORDER`、`GROUND_RESIDUE`、`SCALE_DRIFT`、`ANCHOR_DRIFT`、`DUPLICATE_FRAME` 等错误码都包含对应修复方向。不得使用 padding、修改阈值或跳过 QA 的方式消除错误。

禁止旋转整张身体伪造局部动作，也禁止用同一张图片重复命名来伪造多帧。

## 扩展动作词表

按真实互动增补：`pet`、`eat`、`play`、`sleep`、`stretch`、`lick`、`tail-wag`、`fetch`、`hop`、`charge`、`wave` 等。词表只是灵感，不强制数量。

## 橘猫回归夹具

`assets/regression-fixture/synthetic-pet` 是依赖无关、可重复生成的 40 张合成素材（独立母版加 39 个运行帧），只用于离线脚本、状态机和资产 QA。生成用户工程时禁止复制；仅 `scaffold_project.py --use-regression-fixture` 可显式启用并标记测试工程。
