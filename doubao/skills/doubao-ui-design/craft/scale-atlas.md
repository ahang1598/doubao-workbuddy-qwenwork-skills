# 参考库的数值分布：你现在这个数，掉在获奖稿之外了吗

> **未读完这一份之前，不要定字阶和圆角。** 读它约 1.5 秒。
>
> 这一份**不是模板，是区间**。它不告诉你该长什么样，只告诉你
> 「所有获奖稿都在这个范围里，你现在这个数在不在」。
> 参考库里 H1/正文 从 2.4 到 9.8 都拿了奖——**区间里怎么长，是你的事。**

数据来自 12 份 web 获奖稿的实测（2026-07）。
存的是分布与关系，**不存品牌名、不存原文、不存品牌专属色值**——
可复用的是「这一类气质该用多饱和的色」，不是「某家用的那个色」。
原始数据：[`reference/scale-atlas.json`](../reference/scale-atlas.json)

### 圆角：50 对 3

这是我们和获奖稿差得最远的一项，而且它是"看起来都像同一个 App"的直接成因。

**参考库 12 份里有 4 份是纯直角（0px），中位数只有 3px。**
我们的 gold 和两次试跑，圆角中位数全部是 **50px**——也就是所有东西都是胶囊。

大圆角是"默认好看"的安全牌：它让任何东西都不难看，也让任何东西都不特别。
真正在做选择的稿，圆角是**有角色分工的**：

- 版面与图片 `0`，可点的东西 `999px` —— 只有可点的才是圆的，圆角自己成了可点性的提示
- 全站直角，靠字号和留白拉层次（参考库里 1/3 是这一路）
- 统一一个中等圆角（12–20px），但**只用在一类元素上**

**一律 50px 不是这三种里的任何一种，它是没做选择。**

### 字阶断崖：什么时候适用

| 载体 | 下沿 | 为什么 |
|---|---|---|
| 官网 / Landing | **2.8** | 参考库就是这一类，直接适用 |
| 年度报告 / 活动 H5 | **2.8** | 巨数字 + 一句短文案，一屏一件事 |
| **App / 小程序界面稿** | **不设** | 真实 App 的标题就是 24–32px。把网站的尺子架上去，会把一份正确的 App 稿判成缺陷 |

包内 `gold/h5-cycle` 实测 1.9——**它是对的**，因为它是 App 界面。
`gold/h5-qq2026` 实测 4.1——它是年度报告，落在区间里。
两份 gold 各自证明了这条分界线。

### 底色与强调色

- **暗场 7 / 亮场 5** —— 两边都有获奖稿。底色是**选择**，不是默认。
  唯一不成立的是「浅底 + 首屏没有影像」，那不是克制，那是白卡片阵列。
- **强调色饱和度中位 0.80，12 份里 10 份 ≥0.6** ——
  酸黄、荧光绿、电光蓝、纯白都出现过。低饱和的莫兰迪色做强调色，在获奖样本里是少数。
  这不是说你必须用高饱和；是说**你选低饱和时，那得是个决定**。

## 怎么用这份东西，才不会把它用成模板

**用错的样子**：把中位数当目标，H1 一律 72、圆角一律 3、正文一律 16。
那就是把 12 份不同的获奖稿平均成了一张脸——比现在还糟。

**用对的样子**：先按 `style.json` 的签名决定这一稿的性格，
**再拿区间检查你的决定是不是掉在所有获奖稿之外**。

```
签名 typeVoice=display-art、energy 高   → 字阶往 p90 走（6–10 倍），圆角往 0 走
签名 typeVoice=rounded-friendly        → 圆角可以大，但字阶别塌到 2 以下
签名 ground=paper、tone 克制            → 字阶取中位偏下，靠留白和字重拉层次
```

区间是**下限与上限**，签名决定你落在区间的哪一段。
两个不同 query 应该落在区间的不同位置——这正是它们不该长得一样的地方。

> 一句话：**门守下限，签名定方向，区间告诉你有没有跑出场外。**
> 三者都不替你做设计。
