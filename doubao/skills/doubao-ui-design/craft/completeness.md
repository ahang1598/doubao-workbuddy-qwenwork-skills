# 完成度合同

`aesthetic-baseline.md` 管**好不好看**，本文件管**做没做完**。两者都过才算交付。

防止两种失败：「路由对了但页面很素」与「清单凑满但仍然廉价」。

## 〇、四类 artifact_class 的首轮最低交付

先判定 `artifact_class` 再开工。**标题与勾选清单必须与真实完整度一致**——
完整度不够可以降级命名，不可以降级偷偷交付。

| 用户信号 | artifact_class | 首轮最低交付 | 文档标题允许 |
|---|---|---|---|
| 含「落地页 / 官网 / 网站 / Web Dashboard / 营销长页 / landing」 | `landing-page` | 完整 Doc；完整响应式网站含导航、声明、query 驱动的中段、证据、转化与 Footer；mediaIntent 要求时含真实视频；宿主 Web 卡片 | 「官网 / Web UI 设计方案」 |
| 含「App / 移动端 / 小程序 / H5 / 多屏界面」 | `app-screens` | state 中每个约定方案均按 `task-shape-contract.md` 完成关键流程与主要状态；默认 1 案；交付完整 Doc | 「App / 移动端 UI 设计方案」 |
| 明确只要 Hero / 方向 / 气质预览 | `direction-preview` | 色板 + 字体 + 组件 + 1 个 Hero | **必须**称「视觉方向预览」，禁止称落地页/完整方案 |
| 未说范围的一句话 | `proposal-starter` | 默认 1 个独立详细 HTML（≥3 设计段）与静态证据；有参考图写其深度 DNA，无参考图才含竞品+设计库；均含方向裁决与取舍 | 「UI 设计方案」；**不可**自称已完成未指定的长流程 |

硬规则：

1. 说了「落地页」却只做出 Hero → 补齐段落，或降为 `direction-preview` 并改标题；
   **禁止**交付名不副实的「落地页 UI 设计方案」。
2. 本文件的完整度表对 `landing-page` / `app-screens` **强制生效**；前者是 `web-dual`，
   后者是 `doc-only`，不得互相降级或替代。
3. `proposal-starter` 仍须在一份 Doc 中一次完成 state 约定数量的详细 HTML；默认只做一套但至少覆盖 Hero、
   核心内容/状态、收束。用户明确多案时每套同一完整度；`direction-preview` 仅限明确只要 Hero/气质预览，
   不得成为默认 Doc 的省成本路径。

## 总则

- 交付物必须是**可感知的产品级界面**，不是线框，也不是五段说明书式模板。
- 品类需要的表现力（沉浸、玻璃、设备框、光晕、微交互）**该用就用**。
  护栏只打无依据的滥俗默认值，不打有依据的表现力。
- **视觉预算优先于效果计数**：一屏一个焦点；signature motion 与装饰机制数量由 query 决定。
  禁止为凑"至少 N 种氛围/动效"而堆砌。
- **风格由当前 query 决定**：设计基因必须能追溯到目标、受众、品牌材料、内容结构或参考意图；
  禁止用固定模板、行业皮肤、随机数或 query hash 选择视觉风格。
- 先定构图原型、逐屏视觉母版与主资产，再谈工艺零件；母版完成前不得写 HTML。
- 交互产品至少实现 2 个任务流状态变化（如分类切换、加购/数量、规格选择、购物车联动），并提供
  `prefers-reduced-motion`；只有漂浮、蒸汽等装饰 keyframes = 未完成。

## 成品文案与 Hero 模式

设计说明和成品文案必须是两套字段：

- `purpose / entry / result / successSignal` 只解释“为什么这样设计”；
- `contentPlan[].copy.eyebrow/headline/body/cta` 才能进入最终 HTML；
- “用鲜明主张定义”“不看说明也能理解”“获得进入下一段”“查看证据”等内部语句出现在网页即 FAIL。

`layoutRecipe.heroMode` 由 query 语义编译，不是风格池随机选项：

| 模式 | 触发依据 | 首屏工艺下限 |
|---|---|---|
| `cinematic-full-bleed` | 真实对象/人物为主角、heroic 影像、高能量或时间性 | 媒体覆盖首屏；内容、遮罩/纹理、状态信息形成独立层；有持续运动与 reduced-motion |
| `typographic-editorial` | 字体/观点为主角，编辑或低能量叙事 | 稳定阅读轴、尺度跳变、作品/证据图版，不强制暗场 |
| `data-command` | 数据与决策为主角 | 指标关系、异常与行动同屏；不用电影式大图 |
| `product-pedestal` | 对象为主角但语气理性/静态 | 产品尺度与材质证据优先，允许受控留白 |
| `task-interface` / `editorial-split` | 功能任务或常规内容叙事 | 主任务或图文关系优先，禁止退化为固定卡片长卷 |

不同模式共享质量下限，不共享外观。参考案例只提供“媒体成为场景、章节有节奏、文案内容化、
状态信息成为证据”等机制；蓝黑底、扫描线、HUD 不得进入非 cinematic 查询。

## 一、信息架构完整度（所有 query 适用）

长页 / 落地页缺任一环即不完整：

| 环节 | 职责 | 不可省 |
|---|---|---|
| 导航 | 定位与主 CTA | ✔ |
| Hero | 建立世界 + 唯一焦点 + 主 CTA | ✔ |
| 价值 / 功能 | 解释在做什么 | ✔ |
| **证据** | 真实界面 / 作品 / 数据 / 案例 —— 不是 icon + 短语卡 | ✔ |
| 转化 | 二次 CTA，与 Hero 的措辞不同 | ✔ |
| 页脚 | 导航冗余 + 合规 | ✔ |

**章节之间必须有构图变化**（基线 §8 换气）。六个环节用同一种版式 = 未完成。

## 二、状态完整度（所有交互界面适用）

缺任一项即不完整：

- `hover` / `press`
- `focus-visible`（键盘可达）
- `disabled`
- `loading`（骨架屏或 spinner）
- **空态**（有列表 / 结果区就必须有）
- 错误态（有表单就必须有）

## 三、响应式完整度

- 桌面 + 移动两套**都要出**；移动端**重构图**，不是竖排桌面块
- 移动端导航形态明确（抽屉 / 底部 tab / 折叠）
- 移动端仍保留主角，不是把主视觉删掉了事

## 四、按主角类型的表现力下限

主角类型来自 designIntent；案例家族的必须项不得覆盖本节。

### 影像驱动（真实摄影 / 空间 / 环境为主角）

- 主影像必须是**证据**而非配图：能证明能力、场景或结果
- 图片比例不得全部相同：一主多辅 / 不等高错落 / 跨栏大图，三选一
- 文字进负空间，不靠在图上压半透明黑条了事
- 无合格主影像时降低 imageDependency 或报告关键资产阻塞，不切换预设 family

### 角色 / 3D 驱动（吉祥物 / 软 3D / 符号为主角）

- 角色 kit ≥3 个姿态或视角，**光色锁定同一套**
- 角色必须跨章复现，不能只出现一次
- 必须是真实 HTML 文本 + 独立资产图层，**不得整页截图冒充网页**
- 主资产短边 ≥1024，透明底优先

### 产品 / 界面驱动（真实 UI、数据、功能为主角）

- ≥1 处真实界面 mockup 或真 DOM 复刻
- ≥1 处局部放大 + 引线，用于解释关键交互
- 密度与留白交替；等宽卡片阵列全页最多连续一次
- 数据用 display 字号 + mono 数字，不用正文字号平铺

### 字体驱动（无强影像可用时的合法路径）

必须**事先在 `art-direction.json` 声明** `"typeLed": true`，否则视为"缺主视觉"。声明后：

- 影像下限打折，但仍需 ≥1 个视觉锚点（纹理、几何母题、大色域）
- 巨字必须参与构图（被遮挡 / 出血 / 咬合），不是居中大标题
- 字体角色必须形成清晰层级；同一家族可通过字重/字号/宽度完成，不强制两家字体

## 五点五、资产预算（`check_assets.py` 对账）

资产数量由 `assetPlan` 的独立内容职责决定，不按 artifact_class 固定凑数：

- imageDependency=heroic：至少一个高质量主资产；
- 每个 required assetRole 有独立文件，不用同一图冒充不同职责；
- App 的每个关键屏有对应整屏资产；
- Web 的 poster/video 一一绑定；静态方向不生成空视频槽；
- 进入 Doc 的封面和真实站点截图另有明确职责。

检查真实 alpha、可解码、足够分辨率和一图一职责；“图越多越好”不是指标。

## 六、禁止的「假完成」

- 只有导航 + 三列卡片 + 页脚的交差模板
- 有证据可用却用 icon + 短语卡代替
- 读完对标品牌文档后，输出比不读更素的页面
- 用「避免 AI 味」当借口删掉全部氛围与动效
- 声称完成但缺移动端、缺空态、缺 focus-visible
- 主视觉是占位灰块、emoji 或 CSS 圆球
- **Tab bar / 主导航用通用描边图标**（Feather/Lucide 默认造型）—— 见基线 §7b
- **同一张图冒充多个 SKU / 多个角色姿态**；商品图背景与光向不统一
- **方案文档只有原生标题 + 正文 + 默认灰表**，零章节横幅、零证据板

## 七、时间分配

- 参考拆解 + 艺术方向 + 素材 ≤30%
- Hero 合同与实现 + 截图返修 ≥70%

不要把回合耗在反复勾选清单上而挤掉实现深度。**清单是下限，不是目标。**
