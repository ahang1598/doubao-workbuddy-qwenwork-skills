# 构图与动效：为什么那些稿好看

> **未读完这一份之前，不要决定首屏长什么样。** 读它约 2 秒。
>
> 上一份（`scale-atlas.md`）给的是**数值区间**。这一份给的是**关系**——
> 数值对了但关系不对，仍然是一稿"技术上没问题、就是不好看"。
>
> 证据来自 2026-07 实看：motionsites 的 17 个动效案例逐个定格比对、
> superopc 的 12 个案例视觉与 Brand Data、网易哒哒的 H5 列表、
> 数英的 H5 项目榜、dribbble 的 web design 热榜（后者主要贡献了一条告警，见第五节）。
> **存的是机制，不是可抄的版式**——每条都说清"为什么"，不给成品代码。

## 一 · Web 构图：四条能指认的关系

### C1　主体是一个「物」，不是一个卡片布局

实看的每一个获奖稿，画面中心都有一个**具体的、有体积感的东西**：
一个玻璃生态球、一团爆裂的火花、一条横贯画面的岩层、一只手、一台产品。

我们的产出是什么样：**图片放进容器里，文字在旁边**。
这两者的差别不是"图更大一点"，是**画面有没有一个主角**。

| 这样 | 不这样 |
|---|---|
| 一个物占据视觉中心，页面为它让位 | 三张等大的卡片，每张里一张图 |
| 物有体积、有光、有影，像被拍下来的 | 图是平的，贴在一个圆角矩形里 |
| 文字围着物排 | 文字和图各占一半，互不相干 |

**落到我们的能力上**：生图只能出矩形，但**矩形里可以是一个物**。
prompt 写"一个 X 悬浮在纯色场中，柔和顶光，浅景深"，
比写"X 的产品图"能拿到的画面强一个量级。

### C2　字与物互锁

获奖稿里标题和主体从不各站一边。实看到的三种互锁：

| 形式 | 实例 | 怎么做 |
|---|---|---|
| **字在物后** | 巨号衬线标题被玻璃球压住一截 | 物 `z-index` 高于字，物用透明底 PNG 或满版图 + 字在其下层 |
| **字被视口裁切** | 巨字只露出下半截，上半截被切在视口外 | 字放大到超出容器，`overflow:hidden` 裁掉 |
| **字压在物上** | 斜体衬线压在岩层上 | 字在上层 + 一层可控暗场保对比度 |

三种都要求**字大到能和物抗衡**——这就是 `scale-atlas.md` 里字阶断崖那个数的意义。
字如果只有正文的两倍大，怎么摆都是"图上、字下、各不相干"。

### C3　品类不决定视觉

这一条直接回答「不要所有人做出来长得一样」。

实看到的：
- 一个 **SaaS**（部署数字员工）用的是**满版薰衣草花田摄影 + 居中衬线大字**
- 另一个 **SaaS**（数据叙事）用的是**蓝天 + 一条横贯的岩石地层 + 斜体衬线**
- 一个**硬件**站用的是**淡蓝天空场 + 酸黄强调色**
- 一个 **Web3** 站用的是**纯黑 + 176px 巨字**

**没有一个用了"SaaS 该有的样子"。**
如果你的稿一眼能看出品类，多半是照着品类的平均值做的——那正是所有人长得一样的成因。

**做法**：视觉从 `style.json` 的签名长出来，不从品类长出来。
品类只决定**内容**（要讲什么），不决定**气质**（怎么讲）。

### C4　一个高饱和强调色，只出现在一个地方

参考库强调色饱和度中位 **0.80**（酸黄、荧光绿、电光蓝）。
但它们在页面上的用法是**克制到极点的**：整屏灰绿岩层，只有右下角一个荧光绿按钮。

饱和度高 + 面积小 = 强调；饱和度高 + 到处都是 = 廉价。
`anti-patterns.md` 里那条「同一块面积里只允许一个强调色」说的就是这件事。

## 二 · 动效：入场揭示 ≠ 滚动驱动

这是我们和获奖稿差得最远的一层，而且有实测证据。

把 motionsites 的一个案例定格在两个时间点：

| | 开头 | 72% 处 |
|---|---|---|
| 底色 | 浅灰 | **深色** |
| 主体 | 一团火花 | **一个网状球体** |
| 标题 | "SCALING FASTER USING AI" | **整段换成另一句** |
| 版面 | 单屏 | **底部多出一栏** |

**这不是入场动画，是滚动驱动的场景推进**：滚动位置 = 场景进度，
底色、主体、文案在滚动过程中被连续地换掉。

我们现在的骨架只有：

```css
.rv{opacity:0;transform:translateY(24px)}   /* 播一次，完了 */
.rv.in{opacity:1;transform:none}
```

**入场揭示解决的是"元素怎么出现"，滚动驱动解决的是"页面怎么讲一件事"。**
只有前者的页面，滚起来是一串各自淡入的块；有后者的页面，滚起来是一个连续的场景。

### 三档动效，按签名选

| `motionVoice` | 做什么 | 成本 |
|---|---|---|
| `still` / `slow-push` | 入场揭示 + 图的缓慢缩放。够用，不丢分 | 低 |
| `parallax` | 前后景不同速度位移；主体比背景慢 | 低 |
| **`scene-advance`** | **滚动驱动的场景推进**：一段 `position:sticky` 的舞台，内部状态跟着滚动进度连续变 | 中 |

`scene-advance` 的最小骨架（`skeletons/web.html` 里已经备好，见 `.scene` / `.scene-stage`）：
一段高 `300vh` 的容器，里面一个 `position:sticky; top:0; height:100vh` 的舞台；
监听滚动算出 `0→1` 的进度，把进度写进 CSS 变量，让底色、主体、文字各自绑上去。

**三条硬约束不变**：加性（关掉动效不能白屏）、绑真实内容（不新建装饰层）、
`prefers-reduced-motion` 全降级。

## 三 · 移动端 H5：两条路，我们只做了一条

实看网易哒哒近几年的 H5，标题几乎全是这个句式：

> 测测你的花卉人格，生成花园吧　｜　制作你的童年成分表　｜　预见你的 2025
> 点击查看你出生那天的月亮　｜　来生成你的人生满意度报告

**它们不是年度报告，是互动生成器。**

| | 路 A · 单向叙事 | 路 B · 互动生成器 |
|---|---|---|
| 主角 | 数据本身 | **"关于你的那个结果"** |
| 屏序 | 封面 → 数据屏 ×N → 分享页 | 钩子 → 选择/输入 ×2–4 → **专属结果卡** → 分享 |
| 用户动作 | 只能滑 | 点、选、填，然后**看到属于自己的东西** |
| 分享动力 | 数据够惊人 | **结果卡是"我的"** |
| 代表 | 年度报告、盘点、品牌叙事 | 测试、生成器、人格卡、节日互动 |

`gold/h5-qq2026` 是路 A 的样本。**包里没有路 B 的样本**，
而 query 里出现「测测 / 生成 / 制作你的 / 你是哪种 / 专属」这些词时，
用户要的多半是路 B——这时候做成单向滑动的年度报告，形态就错了。

**路 B 的最小结构**（不是模板，是骨骼）：

```
屏 1  钩子      一句问题 + 一个"开始"，满版美术
屏 2  选择      3–5 个选项，选完立刻有反馈（不要"下一步"按钮）
屏 3  选择      同上，换构图
屏 4  生成中    把等待做成内容（gold/h5-qq2026 的开机动画就是这一手）
屏 5  结果卡    称号 + 一段专属描述 + 一张能保存的卡
屏 6  分享      保存长图 / 分享给好友 + 社交证明 + 站内引导
```

路 B 的结果卡是**整个 H5 的产品**——前面五屏都是为了它。
它必须能**保存成一张图**，因为那才是被发出去的东西。

## 四 · 「借一个世界」：中国获奖 H5 最强的那个母题

实看数英的 H5 项目榜，头部作品几乎都有同一个手法——
**不是先定配色，是先借一个现实世界里已经存在的媒介或场景形态，
再把内容装进去。**

| 作品 | 借的世界 |
|---|---|
| 某会员年度报告 | **一个电视新闻台**——台标、演播室、主播剪影，数据变成"今日播报" |
| 某物流年度报告 | **非遗版画**——民俗神像的构图与手写标题，快递员变成"神仙" |
| 某出行年度报告 | **3D 等距微缩场景**——一年的行程变成一座可俯视的小城 |
| 某双人格测试 | **左右对分的两极**——上班人格 / 下班人格各占半屏，两套色 |
| 包内 `gold/h5-qq2026` | **一台 2003 年的旧机器**——开机、读盘、频道，数据是它播出来的 |

**为什么这一手这么有效**：

1. **它一次性决定了所有视觉决定。** 借了"电视台"，色板、字体、图标、
   转场、文案口吻全部有了出处，不用一项项去"选好看的"。
2. **它天然反同质化。** 借的世界不同，产出就不可能像——
   而配色和字体是可以撞的。
3. **它给了动效一个理由。** 开机、换台、翻页、盖章——
   动效不再是"加点动画"，是那个世界本来就有的动作。

**怎么找这个世界**：从内容里找，不从视觉里找。
问一句「这件事在现实里最像什么」——
年度数据像**一份报纸/一台电视/一本档案**；
测试像**一次体检/一张签文/一份说明书**；
路线规划像**一张地图/一本行程手册**。

**反面**：如果你的 H5 只能被描述成「深色 + 渐变 + 大数字」，
那就是没有借到世界，只是选了个配色。那正是"每年都像同一张"的成因。

### 这一条对 doc 画布同样成立

窄栏画布不是网站，但"先借一个世界"这一手照样管用——
包里三份 gold 正好是三个借法：

| | 借的世界 | 落到版面上 |
|---|---|---|
| PULSE | **一本时装杂志** | 白纸、压缩重体、单墨线分节、直角 |
| QQ 2026 | **一份翻出来的旧卷宗** | 微黄档案纸、宋体、双线分隔、零圆角 |
| 骑不骑 | **一本随身手册** | 沙色、圆润体、无分隔线、大圆角、柔和阴影 |

三份的七节结构一字不差，**没有一个视觉角色相同**（实测两两最多 5/13）。
这就是 `skeleton.py doc` 为什么不给人格默认值：
借哪个世界是这一稿最先要做的决定，不该由骨架替你做。

**反面**：如果你的画布只能被描述成"白底 + 一条主色 + 等宽小标签"，
那是骨架的样子，不是这一稿的样子。

## 五 · 一条告警：作品集图不是网站

用户给的参考里有 dribbble。实看之后必须说清楚一件事：
**dribbble 的 web design 热榜和前面那些站不是同一种东西。**

热榜上占多数的是**作品集展示图**：
界面截图铺在浅紫/浅蓝渐变底上、显示器与手机 mockup 悬浮、多屏拼贴成一张长图。
它们作为**一张图**很好看，但那份好看来自 mockup、渐变底和拼贴，
**不来自版面本身**——真做成网站打开，那些东西一个都不在。

**照着 dribbble 学，最可能的产出是"一张好看的作品集图"，不是一个好看的网站。**

dribbble 上值得学的是那些**能当网站看**的：
巨号品牌名压在人像上、字被显示器实物挡住一半（还是 C2 的字物互锁）、
产品被放进**真实场地**里拍（手机躺在网球场上俯拍，UI 长在场景里）——
后面这一条是 C1 的一个好变体：**物不一定要悬浮在纯色场里，放进真实场景往往更强。**

判断方法很简单：**把 mockup、渐变底、拼贴全部拿掉，剩下的还成立吗？**
不成立的，就不是可学的版面。

## 怎么用这份东西

先按 `style.json` 的签名定气质，再回到这里挑关系：

```
imageWorld=photo + layoutLogic=full-bleed-stack  → C1 一个物 + C2 字被裁切
motionVoice=scene-advance                        → 用滚动驱动，不要只做入场
query 含 测测 / 生成你的 / 专属                    → H5 走路 B（互动生成器）
任何 H5                                          → 先回答「这件事在现实里最像什么」
```

**这份文件里没有一行可以直接抄的代码，这是故意的。**
给了成品代码，所有人的产出就又长得一样了——
而那正是这个包这十几轮一直在治的病。
