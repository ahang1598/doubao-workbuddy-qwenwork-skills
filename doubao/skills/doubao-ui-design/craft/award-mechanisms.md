# 得奖级的机制

> **未读完这一份之前，不要开始定风格。**
> 它是这个包里唯一**正向**定义「什么叫好」的文件；其余工艺讲的多是「别做什么」。
> 读它约 1.5 秒 —— 在这里省下的时间买不到任何东西，只买到一稿平庸。

> 这一份是**正向定义**：什么叫得奖级，而不是"底线没问题"。
> 判据来自 dribbble Web Design 热榜、superopc 电商精选、motionsites、
> digitaling / h5anli / 网易哒哒 的实看，每条都能在具体案例上指出来。
>
> 包里其它文件大多在说"别做什么"。这一份说的是**做什么**——
> 因为"不丑"和"好"之间隔着的是机制，不是更小心。

---

## Web：六条可指认的机制

| # | 机制 | 案例 | 反例 |
|---|---|---|---|
| **M1** | **一个主角占画面 ≥50%**，其余全部退让 | Derek®（巨名 + 人像）、Framer（一个发光体 + 一句话） | 三张等大卡片并排 |
| **M2** | **底色是承诺**：暗场或高饱和色场，不是白底 | CINETIK（近黑 + 橙）、VELARO（满版橙） | 米白底 + 浅灰卡 |
| **M3** | **字与图互锁**：图压字、字绕图、字被裁切 | VELARO 的标题里嵌着视频/照片小方块 | 图上、字下、各不相干 |
| **M4** | **卡片尺寸不等**，有主次 | Voedo（大产品图 + 三张不同大小的浮动数据卡） | 等分 2×2 网格 |
| **M5** | **一个饱和强调色 + 面积配额** | CINETIK 全站只有一个橙 | 强调色同时出现在标题、卡底、按钮、图标上 |
| **M6** | **真实影像或真实渲染** | 全部样本 | emoji、CSS 圆球、图标字体 |

## H5：中国获奖案例的共同点

样本：京东「神马送好运」年度报告、MTTV、2024 年度报告、小美说 IP。

| # | 机制 |
|---|---|
| **N1** | **满版美术驱动**：插画 / 3D 场景 / 摄影铺满整屏，UI 控件极少 |
| **N2** | **标题是美术字**，不是系统字号加粗 |
| **N3** | **一个 IP 形象或一个主体贯穿全程** |
| **N4** | **几乎不用系统卡片**——信息直接长在画面里 |
| **N5** | 巨数字 + 一句短文案，一屏一件事 |
| **N6** | 底部固定操作条 + 结束页分享闭环 |

对照一份典型的低分关键屏：白卡片阵列 + emoji + 系统字号，
**六条一条都没占**。这不是"再精致一点"能补的差距，是机制层的差距。

## 这些机制里，哪些能被量出来

只有四条通过了标定，其余的**故意没做成门**。这不是偷懒，是有代价的教训：

### 做成了判据的四条（`check.py --aesthetic`，全部 REPORT）

| 判据 | 对应机制 | gold-web | gold-h5 | 低分参照样本 |
|---|---|---:|---:|---:|
| `asset-count` ≥8 | M6 / N1 | 17 | 14 | **2** |
| `aes-emoji-per-asset` ≤1.0 | M6 | 0.47 | 0.07 | **5.0** |
| `aes-flat-ground`（浅底 **且** 首屏影像 <15%） | M2 | 通过 | 通过 | **命中** |
| `aes-no-real-imagery`（影像 <15% **且** CSS 画面 <5 处） | M6 / N1 | 通过 | 通过 | **命中** |

它们全部是**比值或组合**，没有一条是单一指标。

### 没做成判据的三条，以及为什么

这三条都拿参照案例验过，都会把好稿判成缺陷：

| 试过的判据 | gold-web | gold-h5 | 低分参照样本 | 为什么废掉 |
|---|---:|---:|---:|---|
| 主角占比 ≥0.35（M1） | 1.00 | **0.17** | 0.10 | 判死 gold-h5——它的美术是 CSS 画的。换成"最大视觉簇"之后 低分参照样本 反涨到 0.95，两个方向都不成立 |
| 强调色面积 3–12%（M5） | **0.6%** | **22.5%** | 5.3% | 完全反了：gold 两个都在区间外，低分参照样本 反而在区间内 |
| 卡片等分度（M4） | 0.82 | 0.25 | **1.08** | 不区分好坏；而 gold doc 的关键屏网格等分度是 0——等分是它的正当版式 |

**教训：单一指标不区分好坏，比值和组合才区分。**

所以 M1、M4、M5 留在这份文档里当**做设计时的正向清单**，
不留在 `check.py` 里当门。想把它们变成门，先拿出新的定义和新的标定数据——
一条会判死好稿的门，会把产出往平庸的方向推，而不是往得奖级推。

---

## 为什么这些判据全是 REPORT，一条 BLOCK 都不是

因为它们是"平庸 vs 优秀"的判据，不是"能不能读"的判据。
设成 BLOCK 就会判死正当的克制型设计——获奖站 lunge 的首屏只有十几段文字，
按任何"画面占比"的硬门都活不下来。

但它们**必须被打印出来**，并且必须在你改稿之前被读到：
门守下限，抬不高上限；这份清单是你抬上限时唯一的对照物。
