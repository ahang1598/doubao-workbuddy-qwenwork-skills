# 页面语法：可拆机制库

> 本文件**只提供可拆解的机制和验收判据**，不提供风格家族、固定页序、默认配色、
> 固定图数或"高级感标配"。要用哪一条、怎么变形、用不用，由本稿的内容与证据决定。
>
> 它是移植自 `doubao-visual-creative` 的那套方法（那边的 PPT 效果被验证过），
> 核心差别只有一条：**那边没有一个脚本生成画面，每一页的构图都是模型现场推的。**
> 这个包里 Python 负责几何真值与宿主协议，构图归你。

## 0. 先决定职责，再决定形状

每一段按顺序回答四个问题，**顺序不能换**：

1. `job`：这一段让读者**理解 / 相信 / 比较 / 感受 / 决定**什么？
2. `proof`：为了做到这件事，必须让读者**看见**什么（哪张图、哪个数、哪段关系）？
3. `geometry`：这些证据的**原始形状**是什么（几条、横的竖的、多长、是否必须完整展示）？
4. `move`：用哪个机制把 2 和 3 兑现。

**先用矩形和文字块验证主次，再决定颜色、装饰和家具。**
装饰救不回错误的证据几何——这是所有"过完了所有门却依然不高级"的共同死因。

## 1. 段职责表

| job | 首要目标 | 常见机制 | **不应强制** |
|---|---|---|---|
| `opening` | 一眼说清是什么、为谁、凭什么 | 满版影像 + 一句话 + 一个动作 | 不强制满版；留白开场也可以是对的 |
| `thesis` | 让一句判断被记住 | 巨字、留白、单焦点 | 不强制配图；不强制居中 |
| `narrative` | 讲清因果或过程 | 图文序列、时间轴、编号轨 | 不强制卡片阵列 |
| `evidence` | 证明主张 | 一张强证据，或多图互证 | 不为凑数放无关图 |
| `comparison` | 支持选择 | 同尺度并置、差异标注 | 不强制平均分栏；分栏而无结论等于没比 |
| `system` | 说明能力/结构关系 | 关系图、分区、层级 | 不强制三卡；不强制图标 |
| `data` | 得出决策 | 大结论 + 可读图表 + 口径来源 | 不让装饰图抢占图表 |
| `spec` | 保证可复现 | 密排表格、线性分区 | **永不做开篇**（见 §4） |
| `application` | 说明怎么用 | 场景图、真实界面、状态 | 不强制每屏一图 |
| `closing` | 收束到一个动作 | 一个 CTA、一句承诺 | 不只有"谢谢"；不重复前文 |

`job` 是机器决策层。**读者看到的标题必须是人话**，不能直接印 `evidence` / `application`。

## 2. 可拆构图机制

下表是**候选动作**，不是清单。按职责与证据几何选择、变形，或者不用。

| 机制 | 适合证明 | 关键参数 | 常见失败 |
|---|---|---|---|
| 满版影像 | 氛围、对象、场景体验 | 主体完整度、文字落点的可读性、暗部预留 | 图只是壁纸，文字无处可读 |
| 巨字命题 | 需要被记住的一句判断 | 断行位置、级差、留白 | 空洞口号冒充内容 |
| 非对称分屏 | 一条判断 + 一项强证据 | 证据侧主导、比例、阅读顺序 | 连续复用退化成默认左图右文 |
| 多图互证 | 整体 / 细节 / 材料共同证明 | 主图与辅图的职责分工、共享对齐轴 | 等大九宫格、语义重复 |
| 接触表 | 一眼看完全景（多屏、多参考） | 列数由**内容**算，不写死 | 固定三列，第 4 个孤儿掉行 |
| 比较舞台 | 支持选择 | 同尺度、差异维度、给出推荐 | 平均分栏无结论 |
| 数据判断 | 数据 → 行动 | 结论先行、单位口径、来源 | 图表装饰化、伪数据 |
| 过程序列 | 时间、流程、旅程 | 节点数、动作连续、完成信号 | 节点过密、复述界面名 |
| 色域块 | 章节换气、给纯文字段一个面 | 面积、色相来源、与相邻段的反差 | 每段都铺，等于没铺 |
| 材料关系 | 色与材如何落地 | 来源、比例、真实对照 | 只有情绪拼贴，没有因果 |

## 3. 层是工具箱，不是配额

- **L0 表面**：底色、材料、色域；来源必须可解释。
- **L1 图形**：分割、母题、线、标注；没有职责就省略。
- **L2 证据**：影像、界面、图表、产品；多图必须有主次。
- **L3 文字**：标题、判断、说明、来源；断行服从语义。
- **L4 家具**：导航、页码、章节标识；只保留真的需要持续出现的。

极简命题段可以只有 L0+L3；数据段可以没有摄影图。
**禁止为了"看起来设计过"添加英文微标签、幽灵字、细线、印章或多余层数。**

## 4. 两条硬约束（其余都是判断）

1. **规范永不做开篇。** 读者先看作品，再看它凭什么长这样。
   约束落在 `job == "spec"` 上，不落在章节名上——所以新增任何规范类章节都自动受管。
2. **每一段的证据必须真的存在。** 声明了机制而源码里找不到实现，等于没做
   （`signature-hook-evidence` 门查的就是这个）。

## 5. 重复与变化

重复用于建立系统，变化用于响应内容。

**可以重复**：对齐轴、章节标记、分隔机制、字号层级、同类信息的骨架。
**必须变化**：职责改变时；从概念进入证据时；从总体进入细节时；从高密度进入换气时。

判据很简单：**连着三段同一种密度，就是节奏坏了。**
（文档画布这一条已由 `doc_ia._breathe` 自动兜底，但它只保证不连排，
选择在哪里换气仍然是设计决定。）

## 6. 外部样本实测出来的几条共性

以下是 2026-07 在真实浏览器里量过的顶级样本（`references/reference-fingerprints/index.json`
里那四个站点，以及 superopc / motionsites 精选）的共同点。它们是**瞄准点，不是门**：

- **首屏几乎都是满版影像或满版暗场 + 一句话 + 一个动作。**不是卡片网格。
- **字号断崖**：一个巨字（64–122px），其余全部很小（13–18px），中间层几乎不存在。
  实测字阶比 2.25–4.5。
- **底色只有 1–3 个面。**不是"配色方案有 5 个颜色"，是**画面上真的出现几块面**。
- **画面来自数量，不是放大**：ClassDojo 实测 41 张图、中位高 260px、零满版。
- **产品截图本身就是主角之一**，不是插画的陪衬。
- 移动端样本（Dribbble 热门）里，**关键屏是成组出现的**——2–4 屏叠放/倾斜在一块
  有色背板上，而不是一张孤立的平铺截图。屏内是真实照片与真实数据密度，不是灰块。

## 7. 自检：这一段成立吗

写完一段，回答三句话。答不上来就是这一段还没设计完：

1. 这一段让读者**做到了什么**（不是"展示了什么"）？
2. 如果把这一段删掉，读者会**少知道哪件事**？
3. 它和上一段的**反差**在哪里（密度 / 尺度 / 明暗 / 证据类型）？
