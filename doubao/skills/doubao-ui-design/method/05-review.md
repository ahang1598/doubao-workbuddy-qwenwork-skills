# 5 · 看自己

> **这一步是整个包最重要的一环：看自己做出来的东西。**
>
> 一条"静态门通过即放行、不看渲染结果"的链路，等于从头到尾没见过产物。
> 截图必须有下游消费者，否则它等于没截。

## 为什么非看不可：一组真实数据

在两份参照产物上统计，7 处修改的来源分布：

| 缺陷 | 数值门能测吗 | 怎么发现的 |
|---|---|---|
| 会员区两种橙打架 | 不能 | 看图 |
| 装饰气泡在小屏上变成噪音 | 不能 | 看图 |
| 日历底纹像二维码 | 不能 | 看图 |
| 十屏共用一个骨架 | 不能 | 看图 |
| 文案写"12 件"但网格只有 8 件 | 部分能 | 看图 |
| `--dust` 对比度 2.92:1 | **只有门能测** | 断言 |
| 单位渲染成 4.16px | **只有门能测** | 断言 |

**构成错占一半，而且它就是"丑"的主要来源。**
反过来，最后两条肉眼几乎发现不了（"有点淡"、"少了个字"）。

> 看图和跑断言是两种正交能力，缺一不可。

## 怎么看

**一条命令**：

```bash
python3 scripts/ui.py review
```

它按合同取产物和取景尺寸，整页截一张、移动端再逐屏截一遍拼成联络表、
跑真值门、把 `observed-*.json` 连量值写好。doc 画布由 `ui.py doc` 的第二段
自己截自己跑门，你不用记。

要单独截某一份（调试、或者临时想看别的东西）时才用底下这几条：

```bash
python3 scripts/ui.py review --url doc/canvas-a.html   # 换一个目标，仍然走全套
python3 scripts/shoot.py strips site/index.html shots/ # 长页切段逐段看
python3 scripts/shoot.py sheet   shots/qq shots/sheet.png 5
```

**直接传本地路径。** `shoot.py` 自己挑一个空闲端口托管、截完自动关——
不用手工 `python3 -m http.server`，也不用试端口。
手工起服务器加等待，光这一件事就要烧掉十几次往返。

**把图读进上下文。** 缩略图不算——放大到能看清字。

**要给文档配"这一块长什么样"的证据图时，用元素级截图，不要按像素裁长图**：

```python
im = pg.locator(".band").first.screenshot   # 所见即所得
```

按坐标裁很容易把两个区块裁进一张，于是图和说明对不上——
已知失败条件：说明只讲了大片轨，图里其实是"数值区 + 大片轨"的混合。

`shoot.py` 已经替你处理了三个坑：
- 冻结入场动画并把揭示类元素置为终态（否则拍到半透明中间态）
- 把 `loading=lazy` 改成 eager 并等所有图解码完
  （不这么做长图里的图是空的，然后你会跑去"修"一个根本没坏的页面）
- **超时只降级、不崩溃，失败也先出图**。
  用 `networkidle` 等页面安静是不行的：有大图解码、外链字体、持续动画
  或 `setInterval` 的页面**永远等不到**——它崩了两次，
  于是五个关键屏只截了一个，用户看到的按钮错位没人发现。
  一张有问题的图也比没有图强。

## 看的时候问自己什么

按这个顺序过一遍，每一条都对着图看，不要凭印象：

1. **第一眼落在哪？** 如果落在导航或一堆等大的卡片上，主角就是缺失的。
2. **有没有两块颜色在打架？** 尤其是两个相邻的高饱和色块。
3. **有没有元素变成了噪音？** 装饰性随机元素在小屏上几乎必然变噪音——
   能读的内容永远优于抽象氛围。
4. **相邻的段是不是长得一样？** 连着三段同密度就该换气。
5. **文案里的数字和版面对得上吗？**（"12 件"配 8 个格子）
6. **有没有重复用同一张图？**
7. **底部/边缘有没有被切掉的东西？**

## 写回执

`ui.py review` 第一次跑完就把 `observed-<产物>.json` 写好了：
`selector` 和 `measure` 是脚本量出来的，**别动**；你补的是判断那几栏
（`where` 在页面上哪儿、`what` 具体是什么缺陷、`fix` 怎么改）。
播种出来的条目可以删（不成立的），也应该加（只有看图才发现的那些）。

形状写错不会再把你挡在门外：最外层写成对象会被自动包成数组，
`css` / `problem` / `suggestion` 这类别名会被自动改名，
`measure` 里的 `n` / `color` / `font-size` 也一样。
**这个脚本最容易卡在"JSON 形状不对"上，反复重跑却一条收据都留不下。**

每条必须带一个**可验证量值**：

```json
[
 {"where":"会员区左右分界","selector":".join-media",
  "what":"左侧 #FF3B14 与右图背景橙相邻，两块橙打架",
  "measure":{"hex":"#FF3B14"},
  "fix":"换成高调黑白人像并锁 grayscale"},
 {"where":"屏 3 底部","selector":".chatlog",
  "what":"漂浮气泡重叠成一堆碎片，读不出内容",
  "measure":{"count":3},
  "fix":"砍掉随机漂浮，换成 3 条能读的聊天记录"}
]
```

```bash
python3 scripts/ui.py review        # 同一条命令：它会逐条去页面上量
```

它会把 `selector` 去页面上找、把 `measure` 里的 hex/fontSize/width/count/contrast
逐个量一遍。**对不上就是编的，会被当场戳穿。**

支持的 measure 键：`hex` `fontSize` `width` `height` `count` `contrast`。

> 这道门不判断你的审美，只判断你**是不是真的看了**。
> 关键词表匹配式的审美门是无效的：失败提示里若写着能过门的范例——
> 复述报错就能通过"唯一的质量决策点"。那种门只会教人怎么过门。

## 看两轮 —— 第一轮是硬要求，第二轮是披露

看 → 改 → 再看。第二轮通常还能再找出 1–2 条。

第二轮的条目要带 `"resolved": true`：

```json
{"where":"会员区左右分界","selector":".join-media","resolved":true,
 "what":"两块橙已换成高调黑白，不再打架",
 "measure":{"hex":"#1A1A1A"},
 "fix":"已改：锁 grayscale"}
```

它的 `measure` 会按**改完之后的新数值**去页面上量一遍——
所以"改了"这件事也是量出来的，不是声明出来的。

**只看一轮也发得出去**，但"第一轮说要改的地方改没改"会被写进交付前的披露清单，
`ship` 发完印一遍、`deliver.py` 再印一遍。

这里**不设 BLOCK**（不因"少于 2 轮"拒发）。理由不是这条判据错了，
是它连同其余几条一起，把一次 22 分钟的会话堵成了**零产物**——
而"看了两轮但只交出 0 张卡"对用户没有任何意义。
第二轮的意义仍然成立：复核第一轮说要改的地方改了没有，不是再挑三个新毛病。

**自检：如果一次任务里「看自己产物」少于 2 次，这一稿多半是丑的。**
一次 48 步的会话里看图 0 次，是最典型的失败形态。
