# 4 · 做（飞书文档窄栏画布）

> 文档这一侧拼的是**排版**：多大的地方放什么、分几栏、谁大谁小、先看到哪个。
> 像一份印出来的专题 / PPT，不是一块大屏。
> 做错的样子是：用宽版网页的尺度排窄栏——页面级间距当格子内 gap、三列网格、12 种字号。

两块画布、封面、`proposal.xml` 骨架，外加关键屏出图，都由一条命令建好：

```bash
python3 scripts/ui.py doc --persona "paper=…,ink=…,…"
```

`--persona` 是 11 个视觉角色，**没有默认值**（理由见下面「人格」那一节）。
写完内容之后再跑一次同一条命令：出封面图、给画布截图、跑 doc 门。

---

## 封面怎么进文档

封面写进 `proposal.xml`，就在 `<title>` 后的第一个块，但 `href` 必须是公网 URL：

```xml
<p><img width="3200" height="1800" caption="" name="cover.jpg" href="https://aka.doubaocdn.com/s/…"/></p>
```

飞书的 `<img href>` 只吃公网 URL，本地路径会被**静默丢弃且不报错**——发布仍然报成功，封面没了。
`ui.py doc` 出图后会提示你用 FileBatchUpload 把 `shots/cover.jpg` 换成 URL；
`publish.py --cover-url` 会把这一行写进临时 proposal，随 `+create` / `+update` 一起发布。

没有公网 URL 时才走 `+media-insert` 回退路径。那条路要模糊匹配锚点，
匹配不上会静默追加到文末，所以不是主路径。

> 这条链断过三轮，两次都是同一条命令的参数写错：用了不存在的 `--index`，
> 又发现 `--file` 传的是绝对路径而 lark-cli 只收 `./文件名`。
> 三轮实测 cover.html 建了 3/3、文档里有封面 **0/3**。
> **验过 flag 不等于验过参数的取值形态。**

> 为什么要写这么细：这条链上有四个位置会同时出错——
> `skeleton.py` 的"下一步"教了一个飞书根本没有的做法（base64 内嵌进图片块）；
> `preflight` 的 FIX 让你发布后手跑 media-insert，还把 `.html` 当 `--file` 传；
> `publish.py` 的创建路径压根没有插封面这一步；
> 闭包查的是「`doc/cover.html` 这个**文件**在不在」。
> 典型失败：cover.html 建出来了，而文档里没有封面。
> **门量了文件，用户看的是文档。判据的对象错了，比没有判据更危险。**

## 图怎么进画布：先选图位，再出图

飞书单块 512KB，图要 base64 内嵌（外链和相对路径都是裂图）。
**不要自己搓压缩命令。** 三条真实 trace 各搓了一套，做法一模一样：
撞上 512KB 就 `sips -Z` 再降一档尺寸，600 → 500 → 400。
而 `-Z` 压的是长边——一张竖着的手机截图 `-Z 400` 之后宽度只剩 185px，
放进 795px 的通栏里是 4 倍放大 —— **文档里图片糊，就是这么来的。**

```bash
# 关键屏那一批 ui.py doc 已经替你跑了；下面这几条是给其余图位用的
python3 scripts/pack_img.py shots/full.png --slot plate
python3 scripts/pack_img.py shots/s0*.png  --slot screens3
python3 scripts/pack_img.py shots/home.png --slot device
```

**`--for-doc-screens` 是给「关键界面」那一节用的**：一条命令把 `shots/` 里的
关键屏批量出成 `.device` 尺寸，**并直接打印一段可粘进画布的 `<figure>`**，
图已经是 data URI。预算从飞书块上限倒推按张数平摊，超了会告诉你少放几屏。

> 为什么要做成一条命令：截图和"放进 doc"之间隔着出图、压缩、转 base64、写标签
> 四步。典型失败是关键屏都截了，**进 doc 的是 0 张**——
> 一份把 `.screens` 和 `.device-showcase` 建好了却全空着，
> 另一份在 512KB 压力下把截图丢了、留下了素材照片。
> **隔四步的事情不会自己发生。**

它按图位算出目标宽度（优先渲染宽 × 2，但不低于 1× 渲染宽），
JPEG 质量不低于 q72；高宽比 >2.5 的长图自动切段，必要时用 `--bands`
只取代表性版面带。出 `<名字>.b64.txt` 直接 sed 进画布。

| 图位 | 渲染宽 | 需要源图 | 用在哪 |
|---|---:|---:|---|
| `plate` 通栏 | 795 | 1590 | 宽屏长图、横构图版面证据 |
| `duo` 两栏 | 496 | 992 | 左右对照 |
| `screens3` 三列 | 320 | 640 | 4 台以上关键屏联络表 |
| `device` 单机 | 227 | 454 | **一台手机放进一个场里** |

**一条实测的craft**：通栏满版照片在飞书文档里**装不下 2× 分辨率**——
`gold/doc-canvas/pulse-canvas-b` 三张通栏图做到 1.38× 时画布已经 430KB。
所以要真正清晰，办法不是"把图做大"，是**把图放小**：
用 `duo` / `screens` / `device`，同一张源图的倍率立刻就够了。

## 怎么把一台手机放进文档

要求是：

> 在文档里面，如果要放一个移动端的页面，尽量美观一点，
> 而且图片有点模糊，需要高清一点。

并给了三张参考图。实测那三张，机制完全一致：

| 参考 | 机身占容器宽 | 场 | 机身 |
|---|---:|---|---|
| 三机错落（酒店 App） | **25.5%** | 浅灰渐变场 | 深色圆角机身 + 投影，中间那台抬高 |
| 单机 + 装饰物（同程旅行） | ≈17% | 浅绿场 + 行李箱 / 相机 / 云 / 植物 | 有 |
| 单机嵌场景（水下） | ≈15–19% | 满版水下美术 | 有，带辉光 |

共同点：**手机被缩到容器宽度的 15%–26%**，两侧各留 30%+ 的场，
场是**有内容的**（渐变／装饰物／满版美术），机身有圆角边框与投影
——它看起来是「一台手机」，不是「一张竖图」。

骨架里有两个组件：

```html
<div class="device" style="--stage:linear-gradient(160deg,var(--soft),var(--bg))">
  <figure><img src="…"></figure>
</div>
<p class="device-cap"><b>这一屏解决什么</b>他在这里想干什么，所以我们放了什么。</p>

<div class="device-row">…2–3 台，中间那台自动抬高…</div>
```

场（`--stage`）三选一，按 `style.json` 的 `ground` 定，别都用灰渐变：
渐变 / 纯色 / 满版图。

**竖图塞进 `.plate` 会被 `device-scale` 报出来。**
那不是"图不够大"，是**图位选错了**：铺满通栏就得压像素，压像素就是糊。
**"模糊"和"不成比例"是同一件事的两面——把手机缩到 22%，
它需要的像素只有铺满通栏时的 1/14，糊的问题自己就没了。**

## 先把文档类型搞对：这是给客户看的汇报

这一节针对的是参照案例里也没做好的那一格。要求是：

> 你把你当做乙方，你的 doc 是要给客户看的，让客户可以看清你的设计是什么，
> 吸引客户采纳，就像汇报文档一样。现在的 doc 写的很技术，
> **明确拒绝的做法、验收与边界、两种末屏状态、数据诚实性原则**这些都不是汇报应该有的。

这不是换措辞的问题，是**文档类型搞错了**——
把「内部方法的严谨」当成了「汇报的内容」。两者不是一回事：

- 内部严谨（拒绝清单、门、断言、边界）是**我们怎么保证不做砸**，是乙方的家务事；
- 汇报是**让客户看懂并想采纳**。客户不关心你不做什么，
  只关心你要做什么、凭什么、对他有什么用。

### 必须移出正文的内容

| 移出项 | 移到哪 |
|---|---|
| 明确拒绝的做法 / 反模式清单 | 留在包里（动作 3 的拒绝清单**保留**，只是不进文档） |
| 验收与边界 / 已知边界 | 收据文件；文档末尾最多化成一句正向的「下一步」 |
| 两种末屏状态 / 空态错误态枚举 | 交互规格文档（客户要才另出） |
| 数据诚实性原则 | 删 |
| 断言 / 门结果 / 对账 | `run.json` 的收据里 |
| px / hex / 选择器 / em 继承 | 四宫格里**视觉化呈现**；实现细节不进文档 |

### 七节

| # | 节 | 客户在这一节想知道 | 一句话判据 |
|---|---|---|---|
| 1 | **我们怎么理解这件事** | 你听懂我了吗 | 用客户自己的话复述目标与人群，不加术语 |
| 2 | **我们看到的机会** | 为什么是现在、为什么这么做 | 一条洞察 + 支撑它的观察，**不是竞品罗列** |
| 3 | **设计主张** | 一句话，你要给我什么 | 能被客户复述给他老板听的一句话（≤40 字，加粗） |
| 4 | **视觉语言** | 它会长什么样、什么气质 | **感受先行**：色彩讲情绪、字体讲性格、影像讲世界 |
| 5 | **关键界面** | 用户会怎么用 | 按用户动线走一遍，每屏一句"他在这里想干什么" |
| 6 | **为什么这对你有效** | 回到我的业务 | 接回商业目标（转化、留存、品牌资产） |
| 7 | **下一步** | 接下来怎么推进 | 正向的推进项，不是「我们还没做完」清单 |

第 2 节的写法要变：以前是「我们看了谁，取走了什么」的竞品对照表——
那是设计师的工作笔记。汇报版是**一条洞察**，竞品作为佐证出现在洞察**后面**。

### 改写对照

| 别这么写 | 这么写 |
|---|---|
| 首屏媒体占比实测 100%，最大字号 168px | 首屏把整块画面让给一张照片，标题压在人身上——**先给态度，再给货**。这一屏不介绍产品，只回答"这是谁的品牌" |
| 骨色 #EFECE3 + 信号橙红 #FF3B14 + 近黑，三色封顶 | 那种白是**中产的安静**。你的用户要的是有声音的那种。所以底子留给照片，信号橙红只在"该往下走"的地方出现一次——它不是装饰，是路标 |
| 商品网格 4 列，缝隙 4px | 8 张同一场拍摄的照片，缝只留一线——它们要连成**一张接触印相**，而不是散成 8 张卡片 |
| **明确不做的事**：不做三卡片 feature 区、不做玻璃拟态… | （**整节删除**。这是我们的方法，不是给客户看的） |
| **验收与边界**：摄影为占位素材、结算未接支付… | （降为末尾一句）「下一步：替换品牌自有大片、接入支付」 |
| 两种末屏状态：出发就绪 / 条件不足 | 「最后一屏会告诉他能不能出发——**能，就一句话让他走；不能，就告诉他差什么**」 |

数值不是不能出现，是**不能在正文里被读出来**。
它们的正确位置是第 4 节那个带 `data-spec` 的四宫格——**用看的，不用读的**。
带了 `data-spec`，口吻判据会自动跳过它。

自查：

```bash
python3 scripts/ui.py ship        # 它第一段就是汇报口吻，全部 REPORT 不阻断
```

> 一句话判据：把文档发给客户方的市场负责人（不写代码、不做设计），
> 他能读完、复述出你的主张、并且想约你聊下一步——就对了。
> 他停在某个 hex 上问"这是什么"、或者读到「已知边界」开始担心——就写错了。

## 四条物理约束（都是真事故换来的）

1. **必须是完整 HTML 文档**。片段会被飞书当片段渲染。
2. **注释和样式里不得出现结构标签字面量**。
   曾经一句 CSS 注释里的 b-o-d-y 字面量，让消费方从那里截出 143KB CSS 当正文印了出来。
3. **单块 ≤ 512KB**，图一律 base64 内嵌。外链和本地路径在飞书里都是裂图。
4. **不要写断点**。飞书块宽在 560–1145px 之间浮动（侧栏展开 698，最典型 820）。
   一律 `min` + `auto-fit` + `clamp`。

## 版面语言：参照物在包里，不在链接里

**通则：任何"参照物"都必须能在离线的包里打开。**
外部链接可以作为出处标注，不能作为唯一参照——这个 skill 给无数人用，
绝大多数人点不开某个内网文档。

要看排版怎么写，直接读源码：

| 看什么 | 读哪个文件 |
|---|---|
| 章节头、四宫格、左标签右正文、对照表怎么写 | `gold/doc-canvas/pulse-canvas-a.html` |
| 关键屏网格、通栏版面证据怎么写 | `gold/doc-canvas/qq-canvas-b.html` |
| 两块怎么拆、XML 怎么包 | `gold/doc-canvas/*-proposal.xml` |
| 整篇怎么生成 | `gold/doc-canvas/build_docs.py` |

**大量留白，字号克制，没有卡片阴影。**

但读源码是学**机制**，不是抄版式：

> gold 是**机制的证据**，不是可以照抄的版式。
> 允许学：为什么用 2px 墨线做章节分隔、为什么商品缝隙压到 4px、为什么砍掉装饰气泡。
> 禁止抄：四宫格的具体排法、章节编号的具体样式、关键屏网格的具体结构。
> **如果你的产物和 gold 在版式上一眼能认出是同一套模板，就是抄了。**

典型失败：把参照案例的结构学去了、工艺没学去，
关键屏区退化成 5 行完全相同的「左手机 + 右三段清单」，图标全用 emoji。
门会查这个（`doc-layout-repeat`：相邻 3 节结构指纹不得全同）。

## 两块拆分

一篇 doc 拆两个 `html5-block`：01–04 一块、05–07 一块。
理由：单块有 512KB 上限，而且章节可以单独更新。

`proposal.xml` 用飞书原生块包住画布：

```xml
<title>…</title>
<callout emoji="📌" background-color="light-orange" border-color="orange">
  <p><b>一句话主张</b>｜…</p></callout>
<h1>我们看到的机会</h1>
<p>…</p>
<html5-block path="@canvas-a.html"></html5-block>
```

标签清单见 [../delivery/lark-doc-xml.md](../delivery/lark-doc-xml.md)。

## 版面工艺：所有门都是绿的，用户一眼说"乱"

手工把三份 doc 从"乱"改到"好多了"的那一轮，13 个错里有 9 个是
**技术上全对、看起来就是不对**。能量出来的那几条已经做成门了
（孤儿行、贴边、左右不对称、转义残留、声明没生效、示例字折行）——
**能被量出来的就不写进方法论，写进门**，方法论里每多一条，被整体跳过的概率就高一分。

剩下这四条只能靠判断，所以留在这里，每条都给正反例。

### 一 · 图文相符：用元素级截图，不按像素裁

**已知失败条件**：文档里两张配图的说明和图对不上——左图实际是"数值区 + 大片轨"的混合，
说明却只讲了大片。根因是按像素坐标裁长图，很容易把两个区块裁进一张。

```python
im = pg.locator(".band").first.screenshot   # 所见即所得
```

裁长图只在"确实要展示一整段滚动"时用。**说明写的是哪一块，就截哪一块。**

### 二 · 等动画落定，再把终值钉死

**已知失败条件**：证据图里数值是 `216/3/80/26`，而页面真值是 `248/4/92/30`——
截图截在数字滚动动画的中间态。这种错在文档里最伤：
客户看到的数字和产品里的对不上。

```python
el.scroll_into_view_if_needed; pg.wait_for_timeout(2200)
pg.evaluate("=>document.querySelectorAll('[data-count]')"
            ".forEach(e=>e.textContent=e.dataset.count)")
```

`shoot.py` 已经替你做了这件事；**如果你自己写截图代码，别忘了做。**

### 三 · 人格是整套换，不是只换强调色

**被门抓到的是我自己**：给三份 gold 加了"色板 Jaccard ≤0.34"这条自检，
它当场判死 PULSE 和 QQ——两份实测 **0.67**。
因为那两份只换了 accent，中性色、字体栈、圆角、分隔方式全部共用。
"不要所有人都长得一样"这条要求，参照案例自己也曾经是反例。

**人格 = 纸色 + 墨色 + 灰阶 + 分隔线 + 字体栈 + 圆角 + 分隔件，整套换。**
改完实测 `0.00 / 0.06 / 0.00`。

包里三份 gold 现在各证明一件事，可以直接并排看：

| | 纸与墨 | 字 | 分隔 | 封面版式 |
|---|---|---|---|---|
| PULSE | 白纸 / 近黑 / 信号橙红 | 无衬线压缩重体 | 单墨线，直角 | 满版压字 |
| QQ 2026 | 微黄档案纸 / 深靛 | **衬线宋体** | **双线**，零圆角 | 界面陈列 |
| 骑不骑 | 沙色 / 暖褐 / 橄榄绿 | 圆润体 | 柔和阴影，大圆角 | 左字右物 |

**三份的七节结构一字不差，视觉人格没有一处相同。**
判据很简单：把三份并排放，能不能一眼看出是三个不同的项目。

### 四 · 素材层：生图只当满版背景

生图**只能出矩形、没有透明底**。矩形图当浮动元素贴上去必然带一圈白边。
所以每一屏都是满版照片 + 可控暗场 + 文字压在最上层——
`gold/h5-cycle` 六屏零白边就是这么做的。

**暗场不是可选件。** 压在照片上的文字，对比度门会跳过（背景不可信）——
**跳过不等于安全，是没人管了。** 那层暗场是你自己对可读性的担保。

圆形头像用 `border-radius`，异形用 `clip-path`，图标用 SVG。别指望生图。

## doc 也走看图闭环

doc 不是"排完就完"。它和成品页走**同一条链**：

```bash
python3 scripts/ui.py doc                              # 截 698 宽 + 跑 doc 门
python3 scripts/ui.py review --url doc/canvas-a.html   # 想给画布也走一遍看图回执
```

**把截出来的图读进上下文，真的看。**

两个宽度都要看。只看一个的话，`auto-fit` 在另一个宽度上塌成一列你不会知道。
`--profile doc` 会自己在 698 和 820 各跑一遍，并附带四条排版正向判据（REPORT）：
