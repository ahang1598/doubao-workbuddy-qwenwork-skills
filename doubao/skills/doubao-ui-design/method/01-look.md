# 1 · 看

> 先看到好东西，才做得出好东西。这句话不是鸡汤，是这个包里唯一能抬高上限的输入。

## 看什么

**三类，缺一类就会做出"技术都对但就是不高级"的东西。**

| 类别 | 至少几个 | 看什么 |
|---|---|---|
| 同品类竞品 | 3 | 信息架构、他们把什么放第一屏、商品/数据怎么组织 |
| 质量参照（不必同品类） | 2 | 版面尺度、字号对比、留白、影像占比、滚动时发生什么 |
| 用户给的参考图/视频 | 全部 | 逐张拆；视频必须抽帧 |

## 怎么看

**真的打开它。** 只读别人的文字描述等于没看。

```bash
# 参考视频抽帧 + 拼联络表，一次看完
ffmpeg -i ref.mp4 -vf "fps=1,scale=300:-1,tile=4x4" -frames:v 1 contact.png
```
（宿主没有 ffmpeg 时：`pip install imageio-ffmpeg`，二进制在
 `imageio_ffmpeg.get_ffmpeg_exe`。实测可用。）

网页参考用浏览器打开，**滚动它**，看：
- 首屏是什么占主导：一张照片？一句巨字？一个产品？
- 滚动时有没有连续状态（不是只有入场播一次）
- 有几种颜色、几种字号、几种圆角

## 质量锚点是数值，不是感觉

`reference/fingerprints/index.json` 是 4 个获奖站在 1280×720 视口里跑同源 JS 量出来的：

| 指标 | 实测区间 | 怎么用 |
|---|---|---|
| 首屏底色数 | 1–3 | >4 种就该问为什么 |
| 字阶比 | 2.25–4.5 | **2.25 也能得奖**（lunge 的主角是产品照不是字）→ 不能当硬门 |
| 最大展示字号 | 36–72px | **绝对下限不成立**；正确判据是「巨字 ≥48px **或** 首屏媒体 ≥40%」二者其一 |
| 首屏文本块 | 4–15 段 | **4 段也能得奖** → 不得拿"内容丰富度"当否决项 |
| 首屏媒体占比 | 40–100% | 40% 是下沿 |
| 运行中动画数 | 0–17 | **0 也可以是对的**（fuse 是纯静态且极好） |
