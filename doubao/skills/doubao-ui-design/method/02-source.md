# 2 · 采

> 没有采集通路的包做不出"找一张真照片"这件事。
> 而「00 后运动品牌官网」那一轮 12 张生成图上传拿到了地址却没写进页面，
> 症状是：网页里一张真实照片都没有。
>
> **先把素材落地，再排版式。** 顺序反了就会出现"版式等着图，图最后没来"。

## 三条路

### ① image_gen / image_edit —— 生图

适用：品牌主视觉、产品英雄图、插画、场景、App 关键屏（画面上中文少的那种）。

**必读 [reference/image-direction.md](../reference/image-direction.md)**，尤其两条：

- **失败一：内容描述式 prompt**——没有镜头、光线方向、色彩世界、构图留白，
  模型只能回吐图库均值。识别特征：只有题材+风格形容词、只有质量词、
  全篇没有焦段/光线方向/色温/材质反应词、长度 <80 字。
- **失败二：统一后缀退化成同一张照片**——后缀统一了，但每条只换了主体名词，
  没换场域、机位、距离与被摄关系，整组就是同一张照片拍十几遍。
  **统一后缀负责"看起来是一个世界"，变量矩阵负责"每张都是新的一眼"。**

门 A 八项自检，缺任一项不发送。**prompt 原样送，不要改写成中文段落。**

#### 生图的两条硬约束（用户实测，绕不过去）

这两条不是设计选择，是**能力边界**。素材策略必须绕着它们设计。

**一 · 只能出矩形，没有透明底，也不能出异形。**

| 别这么用 | 会发生什么 | 改成 |
|---|---|---|
| 生"抠好的产品/人物/图标"当浮动元素 | 白底矩形贴在页面上，四周一圈白边 | 生**整屏背景**，主体在画面里，文字压上去 |
| 生一堆小图当图标 | 每个都是带底色的小方块 | 图标用 SVG / 字体图标 / CSS 画 |
| 生圆形头像、异形卡片 | 方图套圆框露角，或裁掉主体 | CSS `border-radius` / `clip-path` 裁，或干脆用方图 |

所以**生图在这套方案里只有一个正确角色：满版背景图。**
这与骨架里的 `.art` / `.scrim` / `.content` 三层完全吻合——
那三层本来就是为"矩形背景图 + 文字压在上面"设计的。

合同里 `how: image_gen` 的素材，`slot` 只能是 `full-bleed`，
写成 `inline` 会被 `plan.py --validate` 拦下。

**二 · 画不了精确中文。**

所以分工是：**生图负责背景与氛围，HTML 负责所有要读的字。**
关键屏一律用 HTML 渲染真界面再截图——字是真的、能选中、CJK 不糊。
（不要设"中文超过多少字才用 HTML"这类阈值，它是多余的：
既然统一走 HTML，就没有这个判断了。判断本身就是失败点。）

### ② text_to_video / image_to_video —— 生视频

只在这三种情况下用：query 明确要视频/动态影像/持续运动、参考含真实时间帧、
内容职责确实依赖时间媒体。

"酷炫、沉浸、电影感"**可以由排版、材质、空间、交互和 CSS 动效实现**，
不能单独作为强制视频证据。

要做就 5–8 秒，必须有 poster 降级，`prefers-reduced-motion` 显示 poster。
能力不确定时先探测，不要假设。

### ③ fetch_photos.py —— 检索真实照片

适用：真人上身、真实场景、材质。生图画真人容易出手指与面部瑕疵，真照片更稳更便宜。

```bash
python3 scripts/fetch_photos.py ids                       # 打印在浏览器里抠 id 的方法
python3 scripts/fetch_photos.py get --ids ids.txt --out research/pool --sheet
python3 scripts/fetch_photos.py pick --map picks.json --out site/assets
```

实测：Unsplash 有机器人验证、Pexels 搜索页 curl 403，
但 `images.pexels.com` 这个 CDN 不挡 curl。所以先浏览器抠 id，再 curl 批量下。

## 选片规则（这不是审美建议，是可执行的取舍）

1. **本稿只允许 2 种摄影类型**，写进 `art-direction.photoTypes`。
   例：`影棚白底全身`（商品）＋ `现场强色光`（大片）。中间态一律不用。
   混着放的结果是整站像图库拼盘——这是"技术上都对但就是廉价"的头号来源。
2. **同一类型内要同一场拍摄**。商品网格 8 张底色深浅不一，网格就散了。
   宁可少 2 件商品，也不要混两场光。
3. **同一块面积里只允许一个强调色**。
   实测教训：会员区放了张琥珀橙背景的照片，和信号橙红并排——两块橙打架，
   `hue-rotate` 和叠色都救不回来，最后换成高调黑白。
4. **避开可见的竞品 Logo**。评审会一直盯着别家的勾。
5. 候选要够多。**80–120 张里选 15–17 张**；候选太少必然选不出统一的一组。

## 完成标准

素材在盘上、`photoTypes` 已写死、每张有明确角色（hero / product-01 / lookbook-02…）。
角色决定尺寸：hero 1800、通栏 1400–1600、商品 1000、缩略 640。
