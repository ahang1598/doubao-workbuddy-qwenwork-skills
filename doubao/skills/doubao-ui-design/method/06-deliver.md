# 6 · 发

## 先跑门

**门不用你手工调。** `ui.py review` 按合同选 profile 跑成品页那一侧，
`ui.py doc` 跑画布那一侧，`ui.py ship` 补跑漏掉的那几份 + 汇报口吻。
下面这张 profile 表是给你**读懂报错**用的，不是给你选参数用的——
"合同的形态是产品界面，但门是按 web 跑的"这类错误判定，
正确修法就是**根本不给选错的机会**。

要单跑（调试某一份、或者想在改稿中途看一眼）：

```bash
python3 scripts/check.py --url <产物> --profile web|h5|app-screen|doc --aesthetic
```

`✗ BLOCK` 是"预算内要重出一次"，不是"不能交付"。
`· REPORT` 不拦你，但它是「离得奖级还差什么」的清单——改稿前读一遍。

**四个 profile，别选错**：

| profile | 什么稿 | 特别查什么 |
|---|---|---|
| `web` | 宽屏官网 1440×900 | 首屏画面占比、元素重叠 |
| `h5` | 多屏 H5 390×844 | 分屏高度、正文不被操作条压住、每屏有主角 |
| `app-screen` | App / 小程序**单屏独立文件** | 固定底栏与正文重叠面积 = 0、安全区 |
| `doc` | 飞书窄栏画布 | 698 和 820 两个宽度都跑 + 四条排版判据 |

`app-screen` 存在的理由：有些产物的关键屏是 `screens/screenN.html`
这种单屏独立文件，类名是 `.phone-frame` / `.app-screen`，
`h5` profile 写死的 `.screen,[data-screen]` **一个都不匹配**——
四道门于是静默跳过，而 `every` 对空数组返回 `true`，**空真空通过**。
现在任何门在目标集合为空时一律 FAIL。

**BLOCK 之前先问一句：这条门 FAIL 掉 `gold/` 里的产物吗？**
会 —— 那多半是门的判据不对，先怀疑门。
但也有例外：doc 画布的强调色小字实测 2.3:1，那种情况是稿子确实错了。

### 再写一层任务级断言

通用门测不出"这一稿承诺了什么"。抄 `gold/*/assertions.py` 的写法，
按本次的具体承诺写 8–16 条：

```python
ck("小计 = ¥1,158（459+699）", pg.inner_text("#sub") == "¥1,158")
ck("选中 M 带进购物车", "尺码 M" in pg.inner_text("#items"))
ck("单位标签字号 >= 14px", min(us) >= 14)
```

最后那条抓到过一个真 bug：`.unit` 写 `font-size:.26em`，
但它是巨数字的**兄弟节点**不是子节点，em 按父级 16px 算 → 实际渲染 4.16px，
六处单位全隐形。**50 条通用门一条都没报。**

## 发布飞书文档

```bash
python3 scripts/ui.py ship
```

它按这个顺序做：**汇报口吻 → 补跑没跑过的门 → 阻断线 → preflight →
创建（或重发同一篇）→ 插封面 → 字节级回读对账 → 出交付参数**。

### 一条阻断线 + 一份披露清单

| | 判据 | 后果 |
|---|---|---|
| **阻断** | 没有 `proposal.xml` / 一块画布都没有 / proposal 还是没填的占位稿 | 不发。**盘上没有可发的东西** |
| **阻断** | preflight：画布不是完整 HTML / 超 512KB / 图不是 data URI / 注释里有结构标签字面量 | 不发。发出去也是坏的 |
| 披露 | 封面没出图、某份产物没有截图收据、看图不满两轮、门还有未处理的 BLOCK、素材不够、合同被手改 | **照发**，然后一次报完，并写进收据由 `deliver.py` 再印一遍 |

这里**不设"任何一条不过就一张卡都不发"的硬闭包**。
那样做的后果是可预期的：一次 22 分钟的会话，第 18.4 分钟第一次尝试发布被拒，
第二次又被拒，**产物 0 个** —— 而带着瑕疵的 2 张卡远比 0 张有用。

> **用户拿到 0 个产物，和拿到一个"少了封面的 doc"，差距是天壤之别。**
> 唯一还该阻断的判据形态是**可证伪的产物存在性**；
> "产物够不够好"由强制披露承担——披露由收据状态自动决定，不需要你加参数。

收据全部由包内脚本产出，带 sha256，编不出来。不要手写收据进 `run.json`。

### 为什么必须对账

一条只写 JSON 却打印成功的命令会骗人：比如 `register-site` 打印
「PASS 官网卡片已登记：https://…」—— 而它什么都没登记，只是把地址写进了一个 JSON。
执行者读到 PASS 就以为第二张卡完成了。

> **脚本自己打印的 PASS 不是证据。**
> 唯一不能自我欺骗的证据是把发出去的东西读回来比字节。

对账输出长这样：

```
  一致  qq-canvas-b.html   本地 315176B  回读 315176B
```

## 交付：不要手抄任何机器产出的值

`ui.py ship` 的最后一段就是它。调完 NotifyHuman 之后把返回原文贴回来对账：

```bash
python3 scripts/deliver.py --run run.json --confirm "<返回原文>"
```

「文档打不开」的全部原因就在这里：

```
publish.py 打印    …/docx/Z8eXdXZydoq62BxhjMQcopOhnPh   （27 字符）
模型抄进 NotifyHuman …/docx/Z8eXdXZydoq6BxhjMQcopOhnPh   （26 字符）
                                    ↑ 少了一个 2
```

**文档本身完好，字节级对账全绿，卡片指向一个不存在的文档。**

> 这条是通则性的：再严的产物校验也拦不住"交付时抄错"。
> 只要中间隔了一次转写，就有失真概率。
> **质量机制的完备性，不取决于最严的那一环，取决于没有被机器接管的那一环。**
> 下次可能是 app_id、图片 URL、block_id——同样处理。

## 两张卡，顺序不可换

| # | 卡 | 谁生成 | 怎么交 |
|---|---|---|---|
| ① | 设计方案 Doc | 本包 publish | `NotifyHuman(attachments=[飞书 URL])`　**必须最先** |
| ② | 可运行网页 / H5 | `app_builder_agent` | 它自己上屏出卡，不再 NotifyHuman，不把地址写进正文 |

**HTML 文件永远不是卡片**——宿主明文禁止用 NotifyHuman 交付 HTML/JS。
上传 `site.html` 拿到的地址只会变成正文里一行纯文本。

**顺序为什么不能换**：先调 `app_builder_agent` 会让模型把宿主那条规则
推广成"整轮不再 NotifyHuman"，Doc 卡直接丢失。实测三条 trace 全部栽在这里。
完整依据见 [../delivery/host-contract.md](../delivery/host-contract.md)。

## 演示态怎么说

产物里凡是"演示态"的，都要如实交代——
**但不是在文档里写一节「已知边界」**。那是给我们自己看的，
写给客户会让他拿着一份看起来没做完的方案去开会。

汇报文档里它们的正确形态是**第 7 节「下一步」的正向推进项**：

| 别这么写（像认错） | 这么写（像推进） |
|---|---|
| 已知边界：摄影为免费授权占位素材 | 下一步：换上你们自有的大片。版式已按这种光线排好，换图不用改版 |
| 已知边界：结算为前端演示，未接支付 | 下一步：接入支付与真实商品接口。网格与筛选不需要重排 |
| 已知边界：数据为示意样本 | 下一步：接上真实数据，同步几处具体数字 |
| 已知边界：二维码为装饰点阵 | 下一步：换成可扫的真码，指向站内报告入口 |

同一件事，一个让人担心，一个让人想约下一次会。
**如实交代不等于自我贬低。**
