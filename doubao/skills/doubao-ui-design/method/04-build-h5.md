# 4 · 做（移动端）

> 这里最容易犯的错是**把桌面官网压窄**当成 H5：`--maxw:1180px`、
> 分屏高度从 330 到 895 不等、最大字号 30px、没有分屏、没有翻页、没有安全区。
> 那不是 H5，那是一个被压窄的 landing page。

# 先确认形态：你交的是三种里的哪一种

**这一步比下面所有工艺都重要。形态判错了，做得再好也是错的东西。**

`plan.py` 已经替你判过一次并打印在合同里（`deliverables.product.shape`）。
判错了就改：`python3 scripts/ui.py start --force --shape <形态> --query "<当前请求原文>"`。

| 形态 | 什么时候 | 交的是 | 骨架 |
|---|---|---|---|
| **产品界面** | App / 小程序 / 界面改版 / 首页 / 列表 / 详情 / 下单 / 后台 | **能用的产品界面原型** | 见下面第一节 |
| **单向叙事** | 年度报告 / 盘点 / 品牌活动页 / 营销专题 | 分屏叙事 H5 | `skeleton.py h5` |
| **互动生成器** | 测测你的… / 生成你的… / 专属… | 钩子 → 选择 → 结果卡 → 分享 | `skeleton.py h5` |

## 这里最容易判错的一件事：形态

query 是「咖啡点单小程序首页改版，增加社区感，加入邻居晒单动态流」。
交出去的网页卡是一份 **5 屏宣讲 deck**：

```
1 封面屏：标题 + 副标题
2 会员体系屏：会员卡片展示
3 社区晒单屏：邻居晒单动态流
4 完整首页屏：改版后全貌      ← 屏中央贴了一张 400px 宽的首页缩略图
5 结束屏：设计总结
```

点开网页卡的人想用的是**改版后的咖啡点单首页**，
拿到的是**一份关于它的幻灯片**，第 4 屏还只是一张缩略图。

**这不是执行者跑偏，是合同写错了。** 如果合同 note 写的是
「封面 + 内容屏 + 结束页」——那是年报 H5 的定义，被套在了所有 App 和小程序上。
`method/04-build-h5.md` 全文也只教年报式分屏。
**模型忠实执行了一个错的合同。这一类 bug 不在执行层。**

# 一 · 产品界面原型

> 你这一稿的对手不是获奖 H5，是**用户手机里那个真的 App**。
> 参照 `gold/app-home/`（带完整源码）。

骨架 `ui.py start` 已经按形态拷好了（产品界面 → `app/index.html`）。

**这是一份独立的骨架，不是 `h5.html` 的变体。** 它里面没有分屏引擎、没有页码、
没有分段进度条、没有「上一页 / 继续 / 分享」三键条 —— 产品不需要那些。
有的是：取景框 · 状态栏 · 顶部栏 · 一条连续的内容流 · 底部 tab · toast · 骨架屏。

> 用户在这一条上说得很直接：**「不能抄 QQ 的，有些 app 没有 QQ 年终报告顶部和
> 底部的这些按钮。每个产品不一样，不能完全一模一样抄。」**
> 所以骨架分了两份 —— 不给"套错形状"留机会。
> **连底部 tab 都是可以删的**：工具类 App 常常只有一个悬浮主操作，删了不违反任何门。

## 三条正向口径（`prototype-not-deck` 会逐条量，BLOCK）

**1 · 首屏 = 产品首页本身。**
第一眼看到的就是用户每天会看到的那一屏：导航、搜索、内容流、主 CTA。
不是封面页、不是标题页、不是"我们的设计主张"。
门量的是：首屏 >=3 个可操作元素。

**2 · 至少 2 个真实的界面状态切换，点了真的变。**
切 tab / 点进详情 / 展开卡片 / 切筛选 / 下拉刷新 / 加入购物车。
门是**真的去点**：它逐个点可点元素，比较点击前后的可见几何与文字指纹，
数有几个真的改变了界面。**这一条编不出来。**

最省力的两个状态（做完就够过门，但别只做这两个）：
- 底部 tab 切换：`首页 / 发现 / 我的` 三个内容区，`hidden` 切换
- 卡片展开：点一张卡展开详情，再点收起

**3 · 首屏标题里 0 处元叙述词。**
「设计方案 / 改版后 / 全貌 / 关键屏 / 视觉语言 / 设计主张 / 封面页 / 结束页 /
设计说明」——这些属于 doc，不属于原型。
产品界面里出现「方案」两个字未必是错（「套餐方案」就没问题），
所以门只查**首屏可见的标题**。

## 五个版式原语：一条单列竖流装不下所有产品

实看 269 份参考稿里的移动端案例，反复出现的就是下面这五种，**混用是常态**
（一个首页往往同时有 rail 和 grid2）。骨架里都写好了，用不到就整段删掉。

| 原语 | 什么时候 | 参考库里的样子 |
|---|---|---|
| `.rail` | 横滑轨道 | 分类 chip 行、推荐位、「查看全部」那一行 |
| `.grid2` | 双列瀑布 | 商品、菜谱、房源、图集 |
| `.rows` | 密集列表 | 排行榜、流水、消息——**一屏十几行几乎无图是正当的** |
| `.hero` + `.sheet` + `.cta` | 顶部大图 + 上浮面板 | 详情页；这种页**没有 tab**，底部是一条通栏 CTA |
| `.canvas` + `.panel` | 全屏画布 + bottom sheet | 地图 / 相机 / 播放器；**主操作可以在屏幕中间** |

后两种要连带删掉 `.tabbar`。

**三份结构样本在 `tests/archetypes/`**（详情页 / 地图页 / 排行榜页），
带完整源码，三份都是 `21/21 全绿`。它们同时是门的负向标定基准：
门判死其中任何一份，就是门错了。

> 这三份是被用户点出来的：「你的移动端框架还是不够通用」。
> 它们共触发 **6 处错误判定**，全部是门的问题——
> 排行榜每行 14 字导致 `reading-gutter` 目标集合为空、
> 叫车页只有点击一条通路被判"多通路不足"、
> 纯浏览页被要求必须有 toast、
> 12 个小头像被 3% 面积门槛筛掉、
> 地图页的上浮面板被当成常驻底栏、
> 产品界面被要求 8 个满版素材。
> **六条已逐条改掉，并写成回归。**

## 产品界面的刻度和年报不一样

| | 年报 / 活动 H5 | 产品界面 |
|---|---|---|
| 字阶断崖 H1÷正文 | 2.8–6.9 | **1.9 左右**（真实 App 的标题就是 24–32px） |
| 每屏 | 一屏一件事 | 一屏放得下十几条信息，这是对的 |
| 巨数字 | 56–116px | 只有数据卡片里才有，且 32–44px |
| 画面 | 满版影像压文字 | 内容即画面：真实的商品图 / 头像 / 场景图 |

**不要把产品界面做成"每屏一个巨数字"的年报。** 那是形态错。

## 素材

产品界面里的图是**内容**，不是背景：商品图、头像、封面、场景。
所以它们通常是小图多张，不是满版一张。
`assetPlan` 里的 `full-bleed` 只对首屏 banner 成立，其余按内容尺寸走。

## 交互

`craft/interaction-contract.md` 的九条，产品界面那一列。
最容易漏的三条：按钮四态（默认/加载/完成/禁用）、骨架屏、副作用 toast。

# 二 · 单向叙事 H5（年报 / 盘点 / 活动专题）

骨架 `ui.py start` 已经按形态拷好了（单向叙事 / 互动生成器 → `h5/index.html`）。

## H5 的定义（门会逐条查）

- **一屏 = 100dvh**，`scroll-snap-type:y mandatory` + `scroll-snap-stop:always`
- **一屏一件事**，一个数据点
- **巨数字**：数据屏最大字号 56–116px
- **强入场**：进屏才播，不是一进页面全播完
- **底部常驻操作条**：上一页 / 继续 / 分享
- **安全区**：`env(safe-area-inset-*)`，正文不被 76px 操作条压住
- **桌面观看套手机取景框**，评审在电脑上看

## 十屏不要共用一个骨架

这是年度报告类产物最容易犯的错。`gold/h5-qq2026` 的十屏构图：

| 屏 | 构图 |
|---|---|
| 1 封面 | CRT 电视机 + 星点 + 开机动画（把等待做成内容） |
| 2 天数 | **满版日历底纹压巨数字** |
| 3 消息 | 巨数字 + 能读的聊天记录堆栈 |
| 4 深夜 | **Win98 窗口装柱状图** |
| 5 挚友 | **居中人像** |
| 6 群聊 | 方阵 |
| 7 空间 | 三数并置 + 窗口列表 |
| 8 关键词 | 词云 |
| 9 形象 | RPG 属性面板 |
| 10 分享 | 卡片 + 二维码 + 双 CTA |

## 换色不换人格

十屏可以十个色相，但**底纹、扫描线、质感层共用一套**。
`gold/h5-qq2026` 的做法：每屏 `data-t` 给一组 `--bg1/--bg2/--key`，
而 `.screen::before` 的径向渐变和 `::after` 的扫描线是全局同一条。

## 风格类需求要落到能指认的元素上

"复古风"如果只做成一层噪点滤镜，等于没换。拆成 4 个具体元素：

| 元素 | 实现 | 为什么是它 |
|---|---|---|
| 像素企鹅 | 16×18 字符点阵 → JS 渲染成 SVG rect，`shape-rendering:crispEdges` | 点阵化后放大不糊、改色零成本，比插画便宜一个数量级 |
| Win98 窗口 | 外凸边框 + 蓝色渐变标题栏 + `_ □ ×` | 一眼可辨 |
| CRT 扫描线 | 每 3px 一条暗线 + 四角压暗 + multiply | 全屏统一底 |
| QQ 等级图标 | 月亮/星星 `clip-path` | 只有老用户懂的暗号 |

**画面全用 SVG/CSS 画也完全成立**——`gold/h5-qq2026` 一张 `<img>` 都没有。
门查的是"首屏有没有画面"（含 CSS/SVG 画的），不是"有没有 img 标签"。

## 素材层：满版底图 + 可控暗场 + 文字压上面

生图**只能出矩形、没有透明底**，所以它在移动端唯一正确的角色是满版背景。
骨架里已经备好三层：

```html
<section class="screen" data-t="3" style="--art:url(assets/scene-03.jpg)">
  <div class="art"></div>        <!-- 满版素材 -->
  <div class="scrim"></div>      <!-- 可控暗场 -->
  <div class="content">…</div>   <!-- 文字压在上面 -->
</section>
```

**`.scrim` 是必需件，不是装饰。** 没有它，压在图上的文字对比度不可控——
而对比度门会**跳过**"背景不可信"的文字（压在图上就算不可信），
等于这块文字没人管。跳过不等于安全，你得自己保证读得出来。
暗场强度调 `--scrim`，先调到能读，再调到好看。

异形和图标一律不要用生图：
圆头像用 `border-radius`，异形用 `clip-path`，图标用 SVG。
方图套圆框会露角，矩形图当浮动元素会带一圈白边。

## 结束页要真的能分享

- 一张把前面所有数据压缩起来的卡片
- 两个动作：保存长图（发朋友圈）/ 分享给好友（发 IM）
- 社交证明（"已有 12 位好友看过"）
- 站内引导（"打开 XX 搜索…"）

## 常见返工（gold 里真实发生过）

| 症状 | 修法 |
|---|---|
| 装饰气泡在小屏上变成一堆重叠碎片 | **砍掉随机装饰，换成能读的内容**。抽象氛围永远输给可读内容 |
| 底纹像二维码 | 格子改细（14 列 → 28 列）+ 三档热力，而不是二值高对比 |
| Win98 窗口深色内容区像渲染错误 | 窗框保持浅色（98 就是浅的），深色内容单独套一层"窗口里的屏幕" |
| 单位「天/条/%」几乎看不见 | `.unit` 是巨数字的**兄弟节点**，`em` 按父级 16px 算 → 4.16px。**一律用绝对值** |
| 装饰字形被最小字号门拦 | 加 `data-decor="理由"` 显式豁免。豁免要写理由，不写就是在关门 |

# 三种形态共用的：取景框也要跟着设计方向走

评审是在电脑上看的，所以移动端产物都套了一个手机取景框。
**取景框不是中性的**——它是评审看到的第一层画面，
把它写死成「黑机身 + 一块纯黑台面」，所有稿就都长一个样。

要求是：

> **移动端 h5 页面应该支持多种颜色，不能全部都是黑色的手机，
> 其次背景也可以参考上图基于设计方向有模糊背景效果。这样看起来更加美观。**

看他给的参考图，机制是一致的：
**浅机身 / 深机身按稿子的底色选，台面是一大片模糊的氛围，不是一块平的纯色。**
水下那张的台面就是水下，森林那张的台面就是森林——**台面是产品世界的延伸**。

两份骨架的 `:root` 里已经备好八个变量和四组预设：

```css
--frame     机身        --stage-1 台面近处    --halo-1  模糊光斑一（通常是强调色）
--frame-2   机身外圈    --stage-2 台面远处    --halo-2  模糊光斑二（第二色）
--halo-a    光斑强度（亮场 .22 左右，暗场可到 .40）
--stage-art 想让台面就是产品世界本身：url(assets/hero.jpg)，它会被放大并模糊
```

| ground | `--frame` / `--frame-2` | `--stage-1` / `--stage-2` |
|---|---|---|
| 暗场 | `#14161C` / `#2A2E38` | `#131A2C` / `#07080E` |
| 亮场 | `#FFFFFF` / `#E4E7EE` | `#EEF2F8` / `#D9DFEA` |
| 纸感 | `#F7F2E7` / `#DED5C2` | `#F3ECDD` / `#DFD3BC` |
| 高饱和 | `#FFFFFF` / `#F0D7CB` | `#FFE2CE` / `#F6B18A` |

**预设是起点不是终点。** 光斑两色一定要换成你这一稿自己的颜色——
`gold/app-home` 用的是站台灯的琥珀和 4 号线的绿，
所以那块台面一眼就知道是这个产品的台面，不是一块通用的深蓝。

有满版主素材的稿，直接 `--stage-art:url(assets/hero.jpg)` 最省力也最好看：
台面是同一张图放大模糊，产品像是从那个世界里被拿出来的。

# 三种形态共用的：交互合同

`craft/interaction-contract.md` 九条，每条都给了两种落法。
其中五条 `check.py` 会量，**但只查"有没有"，不指定"长什么样"**——
一组带选中态的同级元素算位置表达，一个 `N / M` 页码也算；
贴底固定条里有可点元素算拇指区，最大可点元素在下半屏也算。

**骨架里已经写好的，别删**（各拿各的那一份）：

| | `skeletons/app.html`（产品界面） | `skeletons/h5.html`（叙事 H5） |
|---|---|---|
| 位置表达 | 底部 tab 选中态 | 页码 + 分段进度条 |
| 主操作 | 底部 tab / 悬浮主按钮 | 三键底栏，「继续」最宽 |
| 状态响应 | 展开↔收起、按钮多态 | 末屏「继续」→「再看一遍」 |
| 翻页/导航 | 点击 + 滚动懒加载 | 按钮 / 键盘 / 点空白 / 滑动 |
| 副作用 | `toast` | `toast` |
| 等待 | 骨架屏 `.skel` | 开场壳 `.intro` |

典型失败：这些骨架里有的东西，产物里**一处都没出现**——
拷了骨架，然后把它整个换掉了。
而另一个方向的错同样致命：**把年报那一列照抄到产品上**。
两份骨架就是为了让这两种错都不容易犯。
