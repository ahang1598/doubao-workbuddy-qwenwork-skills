| 评分维度             | 分值 | 满分标准                                                     | 扣分判断                                                     |
| :------------------- | :--- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **需求命中**         | 15   | 一眼能够看到各项监控数据，主要内容是数据、图表、列表。监控的核心是数据服务api的调用情况，数据及文案都反应api调用的运行情况。 | 制作成了非监控数据页面，而是普通的列表页面或者api创建、查看页面，看不出数据主体是api调用情况，而做成了数据量、或者数据表等其他内容。 |
| **信息与任务闭环**   | 15   | 只做一个页面，包含数据服务调用数据总览、调用量的趋势、各api本身角度调用频次对比分析，api调用异常情况、具体告警情况等。数据内容具体清晰、告警预警突出详尽，主次分明，阅读顺序自然 | 不能拆分成多个页面；不能做与api调用无关的数据；没有调用统计、异常情况、告警数据。 |
| **构图与视觉表达**   | 20   | 分析数据展示清晰，各板块数据使用多种图表表达；各数据板块分割清晰，有联系的板块在空间上放一起；层级、节奏、排版、色彩和材质统一，重要内容有明确注意力顺序。 | 数据展示少；主次不清、数据单纯罗列没有图表，数据名称与数字混淆不清，颜色风格不统一；板块混乱，如异常与告警在空间上远离；板块重点不突出，看完不知道是表达什么数据内容。 |
| **界面细节与响应式** | 20   | 导航、按钮、文字和关键状态可读可点；界面尺寸按照规定尺寸来设计，无溢出、截断和大面积死空；无图文混合不清晰。 | 界面尺寸与要求不符；按钮太小；正文不可读；出现横向滚动、遮挡、截断或布局塌陷；文字与图表或图片含混在一起。 |
| **内容与素材可信度** | 15   | 所有数据、文案都是与api调用相关的运行数据；图表选择恰当，能表达当前数据对比情况；重点内容和告警要有详细列表；数据基本逻辑正确不虚假夸张，文案与需求一致。 | 内容与api调用无关，图表类型选择与板块数据表达目的不符，数据无逻辑过分虚假，文案与需求内容无联系。 |
| **交付完整与可落地** | 15   | 有完整的数据服务web端设计图，可供开发；文件可打开；功能点完善，需求中的功能点和点击状态都有设计；设计稿与最终页面一致。 | 只交截图或半成品；文件打不开；功能点或点击状态等关键资源缺失；设计说明与最终页面不一致。 |
