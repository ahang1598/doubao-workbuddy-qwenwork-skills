# gold —— 八份真的做出来、并被打过分的产物

> **gold 是机制的证据，不是可以照抄的版式。**
> 允许学：为什么章节用一条墨线分隔、为什么商品缝隙只留一线、为什么砍掉装饰气泡。
> 禁止抄：四宫格的具体排法、章节编号的具体样式、关键屏网格的具体结构。
> **如果你的产物和 gold 在版式上一眼能认出是同一套模板，就是抄了。**
>
> 用途有三个，缺一不可：
> ① **参照系**——先看到好东西才做得出好东西；
> ② **判据的参照样本**——任何 BLOCK 门判死它们，就是那条判据不对；
> ③ **回归的阳性对照**。

### 后四份解决的是**载体缺口**

包里长期只有"移动端 + 官网"两族样本，而真实需求里还有 B 端后台、数据大屏、
设计展板、活动长图。没有样本的后果不是"做得差一点"，是**门无从标定**——
一条从来没在真产物上执行过的门，阈值是拍的。

这四份还原自真实项目的**设计终稿**，其中两份带当初打分用的评分细则
（`console-api/rubric.md`、`screen-hotan/rubric.md`，六个维度各有满分标准与扣分判断）。

补进来之后立刻抓到三处门自己的毛病，都改了门不改稿：

| 抓到什么 | 改了什么 |
|---|---|
| `text-invisible` 的选择器里**没有 `div`** —— 白字压白底报 PASS | 加上 div 等元素，但**只量自己有文本节点的**，否则包装层会造一片假阳性 |
| `asset-count` 的下限 8 标定自影像驱动的稿，拿去要求监控页和展板 | 下限**按载体分**，每个数写清依据（不是拿实测值回填） |
| 资产面积的分母是**整张画布** —— 长图越长，同一张图越不算数 | 分母改成**一屏**（`vw × min(vh,1000)`）|

**`longimg-summit/` 有一处已知短板并且刻意没修**：它的礼品与人像是手绘 SVG，
而原稿是 12 张实拍，所以 `asset-count` 在它身上会报一条 REPORT。
那条 REPORT 是对的 —— 把阈值调低去迁就一份还原稿，等于把尺子拧弯来量自己。

### `app-home/` 解决的是一个形态缺口

典型失败：把「咖啡点单小程序首页改版」做成 5 屏宣讲 deck，第 4 屏叫
「完整首页 · 改版后全貌」，屏中央贴着一张 400px 宽的缩略图。
点开网页卡的人想用的是产品，拿到的是一份关于它的幻灯片 —— 严重缺陷。

根因之一是**这一形态在包里没有任何样本**——三份 gold 全是官网或叙事 H5，
而 `method/04-build-h5.md` 全文只教年报式分屏。
`app-home/` 补的就是这一格，同时是 `prototype-not-deck` 这道 BLOCK 门的标定基准。

它要证明三件事：

1. **首屏就是产品本身** —— 一打开就知道下一班车几分钟后到，不是封面页
2. **点了真的会变** —— 方向切换 / 换乘展开 / 底部 tab，三个真实状态；
   `assertions.py` 逐个点下去比较点击前后的可见几何与文字指纹
3. **不照抄年报的机箱** —— 没有页码、没有分段进度条、没有「上一页 / 继续 / 分享」
   三键条。位置表达是 tab 的选中态和段控件的选中态，**那才是产品的形式**。
   规则：不要照抄年报 H5 的顶栏与底栏按钮 ——
   每个产品的导航不一样，形式要按这一稿的产品长。

它的机箱在 `skeletons/app.html`，和叙事 H5 的 `skeletons/h5.html` 是**两份**，
就是为了让人没有机会把年报的形状套到产品上。

### 四份 gold 各自证明一件事

| | 素材策略 | 文档人格 | 封面版式 |
|---|---|---|---|
| **PULSE** | 实拍摄影，两种且只有两种 | 骨色 / 近黑 / 信号橙红，压缩重体，直角，墨线分隔 | `cinematic-field` 满版压字 |
| **QQ 2026** | 零照片，全 SVG/CSS 手绘美术 | 深场 / QQ 蓝 / 像素黄，编辑体 | `interface-archive` 界面陈列 |
| **骑不骑** | **生图/照片只当满版背景**，文字压上面 | 沙色 / 棕灰 / 橄榄绿，圆润体，大圆角，卡片 + 柔和阴影 | `editorial-object` 左字右物 |
| **班次** | 零照片，**内容即画面**（线路色带 / 拥挤度热力 / 站点轴 / 出站路径） | 深夜靛 / 站台灯琥珀 / 线路色，10px 圆角 | —（产品原型不出封面） |

**三份的七节结构完全一样，视觉人格完全不一样。**
这就是这组 gold 要说的话：**结构可以共享，人格不能共享。**

一个周末骑行的产品如果套上 PULSE 那身硬边编辑体，气质就错了——
它讲的是"轻松出门转一圈"，不是"跑给自己看"。
**同理，你手上这一稿的主题，多半和这三个都不一样，所以也不该长得像它们中的任何一个。**

每个产物目录里的 `assertions.py` 是**任务级断言**，不是通用门。抄它的写法。

## 20 条决策清单：这些产物为什么长这样

### 素材（1–5）

1. **先定素材再定版式。** 17 张照片先落地，版式围绕照片排。
   反过来做的那一轮，结果是"版式等着图，图最后没来"。
2. **只允许 2 种摄影类型**：影棚白底全身（商品）＋ 现场强色光（大片）。
   中间态一律不用。混着放 = 图库拼盘。
3. **商品网格 8 张来自同一场拍摄**（Pexels 6516xxx 系列），底色一致，
   缝隙压到 4px，8 张连成一张接触印相。
4. **会员区那张照片换过一次**：原图是琥珀橙背景，和信号橙红并排打架。
   试过 `hue-rotate`、试过 multiply 叠色、试过放大裁掉背景，都救不回来。
   最后换成高调黑白并锁 `grayscale(1)`。**同一块面积只允许一个橙。**
5. **QQ H5 一张照片都没用。** 复古像素风用 SVG 点阵企鹅 + CSS 画的 CRT 电视，
   放大不糊、改色零成本。**画面不等于 `<img>`。**

### 版面（6–11）

6. **首屏一个主角一个主行动。** 中文巨字 168px 压在满版摄影上，
   一个实心 CTA + 一个幽灵 CTA，导航是第二眼的事。
7. **八段没有两段结构相同**：满版摄影 → 跑马灯 → 商品网格 → 深场主张 →
   横向大片轨 → 左图右规格 → 满版社群 → 强调色整块。
8. **H5 十屏十个构图**：满版底纹压巨数字 / 居中人像 / 窗口容器 /
   并置三数 / 词云 / 卡片…… 十屏一个模子是往期报告最常见的错。
9. **十屏十色但共用一层质感**：每屏换 `--bg1/--bg2/--key`，
   但径向渐变和 CRT 扫描线是全局同一条。**换色不换人格。**
10. **文档画布不写断点**，全靠 `min()` + `auto-fit`。
    飞书块宽 560–1145 浮动，写死断点必崩。
11. **文档第一眼是作品不是规范。** 设计语言节必须出示成品数值，不能只摆色板。

### 交互与动效（12–14）

12. **"支持直接购买"做成了 5 步可点链路**，不是一句文案。
    11 条断言盯着它：小计、免运费门槛、尺码带入、增删、下单清空。
13. **动效加性、绑真实内容、可降级。** 入场只播一次；
    滚动驱动的连续状态才是"大屏很酷"和"像 PPT"的分界。
14. **H5 的开机动画把等待做成内容**：扫描线扫过 + 日志逐行打印 + 拨号进度条。
    这 2 秒建立"这是一台旧机器"的前提，后面九屏才成立。

### 看图改出来的（15–17）—— 任何数值门都测不出

15. **装饰气泡砍掉了。** 屏 3 原本有一层随机漂浮的聊天气泡，
    截图一看是左下角一堆重叠碎片。调过高度和不透明度，还是像垃圾。
    换成 3 条**能读的**聊天记录（"在吗 / 算了没事 / 刚刚那条当我没说"）。
    → **装饰性随机元素在小屏上几乎必然变噪音；能读的内容永远优于抽象氛围。**
16. **日历底纹重做。** 14 列大格子高对比 → 像二维码。
    改成 28 列 + 三档热力（未在线 8% / 在线 50% / 连续 61 天 100% + 辉光）。
17. **Win98 窗口的内容区改回浅色。** 第一版做成深色，配米色窗框像渲染错误；
    屏 7 的访客列表深棕底深色字几乎读不出。
    修法：窗框保持浅色（98 就是浅的），需要深色的内容单独套一层"窗口里的屏幕"。

### 断言抓出来的（18–19）—— 肉眼几乎发现不了

18. **单位「天/条/%」渲染成 4.16px。** `.unit` 写了 `font-size:.26em`，
    但它是巨数字的**兄弟节点**不是子节点，em 按父级 16px 算。
    六处单位全隐形，截图上只是"少了个字"。
    → 一律用绝对值。这条已写进 `check.py` 的 `unit-too-small`。
19. **弱信息色对比度 2.92:1。** `--dust:#8E8A7E` 在骨色 `#EFECE3` 上不够。
    改成 `#6E6A60`（≈4.5:1）。肉眼只觉得"有点淡"。

### 门本身错了的（20）

20. **两条门是改门不是改稿：**
    - 对比度门把压在满版照片上的白字导航判成 1.18:1 →
      **透明定位层背后不可从父链推断，必须跳过**；
      后来又发现半透明底色（`rgba(...,.14)`）被当成不透明算，
      **必须做 alpha 合成**。
    - "每个数据屏必须有 ≥48px 巨数字"会判死词云屏和称号屏 →
      改成"必须有视觉主角：≥30px 巨字 **或** ≥20% 屏面积的画面/卡片"。

### 人格随主题变（25–27）

25. **结构共享，人格不共享。** 三份 gold 的七节顺序一字不差，
    但底色、字、圆角、分隔方式、封面版式没有一处相同。
    评判标准很简单：**把三份并排放，能不能一眼看出是三个不同的项目。**
26. **骑行案的照片只当满版背景。** 生图只能出矩形、没有透明底——
    矩形图当浮动元素贴上去必然带一圈白边。所以每屏都是
    满版照片 + 可控暗场 + 文字压在最上层，六屏零白边。
    要圆形头像或异形贴纸，用 CSS 裁或 SVG 画，别指望生图。
27. **暗场不是可选件。** 压在照片上的文字，对比度门会跳过（背景不可信）——
    跳过不等于安全，是没人管了。那层暗场是你自己对可读性的担保。

### doc 是给客户看的（21–24）

21. **doc 的读者是甲方，不是 QA。** 第一版把方案写成了工程记录：
    「首屏媒体占比实测 100%」「16 项断言全通过」「.unit 用绝对值避免 em 继承」。
    这些证明我们没做砸，但客户要的是**你要做什么、凭什么、对他有什么用**。
22. **移出正文的四类东西**：拒绝清单（是我们的方法）、验收与边界（是收据）、
    状态枚举（是交互规格）、px/hex/选择器（数值该被**看到**，不该被**读到**）。
    它们没有消失，只是各归各位。
23. **换成乙方汇报七节**：我们怎么理解这件事 → 我们看到的机会 →
    设计主张 → 视觉语言 → 他会怎么走完这一趟 → 为什么这对你有效 → 下一步。
    第 3 节必须是**一句能被客户复述给他老板听的话**。
24. **每篇有封面**，版式由内容定：App/多屏用界面陈列（`interface-archive`），
    横图大片用满版压字（`cinematic-field`），竖图产品用左字右物（`editorial-object`）。
    封面上那行小字（`DESIGN PROPOSAL / 01`）成本极低，但它是"这是一份正经方案"的信号。

## 已知边界（这些产物本身也不是终稿）

- 摄影是 Pexels 免费授权占位素材，正式上线要换品牌自有大片
- PULSE 的结算是前端演示，未接支付；商品是 8 条静态样本
- QQ H5 的数据是示意样本；"保存长图"是提示态；二维码是装饰点阵

**把这类话写进交付文档的「已知边界」，不要让评审拿演示稿当终稿去开会。**
