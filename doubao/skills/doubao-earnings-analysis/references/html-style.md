# HTML 视觉与版式规范

本文件与 `assets/` 下的 HTML 只用于视觉呈现，不规定报告内容。章节、顺序和必备信息仍按原有报告或聚焦工作流执行；预览中的章节、指标、图表、数字和文字均为占位示意，不能作为内容要求。生成时复制 `assets/report-starter.html` 的视觉外壳，按原工作流写正文；`assets/report-layout-preview.html` 只供查看组件写法。

## 目标效果

- 采用机构研报版式：首屏清楚展示报告身份和核心判断，标题下方用细规则线建立层级，关键数字集中成横向摘要，正文由分析逻辑组织。
- 使用白底、海军蓝与钢蓝：页面背景 `#ffffff`、正文文字 `#102a3e`、强调色 `#1b628d`、浅色证据底 `#eef5f8`。开篇判断用浅底和蓝色竖线突出，表格与图表用细边框和表头底色分层。蓝色只表示信息层级，不表示利好；涨跌的好坏由文字和上下文解释。
- 页面宽度约 1080px；长文本列限制在约 40 个汉字的阅读宽度。标题和正文都使用清晰的无衬线字体，关键数值使用对齐的数字字形。桌面版保持紧凑但可扫读的间距，窄屏时指标单列、表格可横向滚动。
- 标题、导语、数字、来源各有可辨的层级。数值强调靠字号、字重和位置，不能只靠颜色；浅色文字与背景要保持足够对比度。

## 按信息作用使用组件

starter 的 CSS 提供 `.thesis-panel`（核心判断）、`.metric-card`（关键数字）、`.data-panel`（结构化对比）、`.chart-panel`（趋势或比较图）、`.insight-note`（解释或证据局限）和 `.watch-list`（后续验证）。组件标记可在 `assets/report-layout-preview.html` 查看。按信息作用选用，使用的组件要真正包含有效内容；没有合适内容时不创建。不要为凑卡片重复数字，也不要把完整论证压成标签。

报告模式和聚焦模式都依据各自原有的内容要求决定章节。需要突出主判断时可用 `.thesis-panel`；需要并列展示数字时可用指标卡；有证据表格时可用 `.data-panel`。这些都是呈现选择，不新增内容要求，也不固定章节数和顺序。

## 鼓励用图表解释数据

写 HTML 时检查已核验的事实：如果有多期趋势、业务结构、同口径横向对比，且图比文字或表格更容易看出关键关系，优先画一张图。折线图适合趋势，条形图适合对比，堆叠图适合结构；图表的种类和数量由数据决定，不为装饰而画，也不为了画图补造数据。

图表优先使用内联 SVG，放在 `.chart-panel` 中，保证独立 HTML 离线可见。图上写清指标、数值、单位和时间或比较对象；图注说明口径、关键局限，并在可见文字中按原有规则绑定事实来源。不要把 `{fact:...}` 写在 SVG 属性、注释或不可见内容里。颜色之外还要有文字标签；窄屏时图形应缩放或滚动，不能裁掉关键数据。图表之后保留正文解释，让读者知道图形与主判断的关系。

## 交付前视觉检查

打开最终 HTML，同时看约 1440px 桌面宽度和约 390px 手机宽度：首屏是否能读出公司、报告期、核心判断；关键数字是否有单位和来源；表格与图表是否易读且窄屏不溢出；正文是否仍是连贯的因果分析；所有示例占位符与空组件是否已删除；来源链接和风险提示是否完整。页面必须在断网状态下正常显示，不依赖外部字体、图标或脚本。

视觉规范不能改变事实口径、删去来源或风险提示，也不能把推断包装成确定事实。正文内容要求以对应分析模式工作流为准。
