# 妙搭渲染规范

## 使用方式

在妙搭中一次性导入 `assets/miaoda-template/index.html` 作为固定前端。先运行：

```bash
python3 scripts/render_report.py report_data.json validated_report.json --collection collection_result.json --data-only
```

在页面初始化前把输出对象绑定到 `window.REPORT_DATA`。渲染器只负责展示，不再推理经营结论。首次搭建后冻结视觉与组件结构，每次报告只替换数据对象。

## 固定页面结构

1. 经营总览：分析范围、周期、双节趋势、本店判断与有数据的关键指标。
2. 双节经营调整：一次展示全部 5—8 条建议，支持详情弹窗，不提供节日筛选。
3. 双节消费趋势：仅展示有内容的消费趋势、热点、同行、投流、商品模块。
4. 双节执行安排：节前、中秋、切换期、国庆。
5. 后续任务：只提供可复制的文字任务说明。

## 视觉与商家表达

- 暖白背景、松绿主色、月金中秋点缀、少量朱红国庆点缀。
- 保留圆月、桂花、国庆飘带等节日元素，不使用普通后台仪表盘皮肤。
- 页面不显示工具栏、样例标识、内部版本、数据平台、采集路径、来源编号、P0/P1 进度和来源弹窗。
- 正常数据直接显示，不附加“已取得”。
- 无数据的指标卡、洞察 Tab、表格和图表直接不渲染；页面只保留一句合并的“暂无数据”提示。
- 建议卡和详情不出现改价、调价、涨降价、折扣加深或具体价格建议。
- 桌面、平板和手机自适应；手机端卡片为单列。

## 组件绑定

| JSON | 妙搭组件 |
|---|---|
| `report`、`store` | 页头、分析范围与报告周期 |
| `overview` | 双节总览与本店经营判断 |
| `metrics` | 已有数据的经营指标卡 |
| `actions` | 全部建议卡和详情弹窗 |
| `insights` | 仅有内容的洞察 Tab |
| `missing` | 一句合并的暂无数据提示 |
| `timeline` | 四阶段执行时间线 |
| `next_tasks` | 可复制的后续任务说明 |

账号未校验通过时只显示停止提示，不渲染经营内容。妙搭不可用时，使用同一数据契约和 `scripts/render_report.py` 生成单文件 HTML。

## 交付检查

检查桌面和 390px 窄屏的页头、指标、全部动作、动作详情和可用洞察切换。同时确认空模块已隐藏、暂无数据提示已合并、页面没有来源说明和改价建议。
