# 已有能力复用

## 复用范围

参考用户提供的「技能包（0908）」中的六个技能。它们提供通用流程和细分方法；本技能主任务仍是选定单店或多店的中秋国庆经营方案。

| 原技能 | 可复用内容 | 本技能中的边界 |
|---|---|---|
| `local-life-service-hot-find` | 品类／城市匹配、热点与搜索区分、商机内容、相关样例提炼、来源记录 | 不自动选经营最好的店，不新增热点确认卡，不固定附带下季度前瞻，不把所有热点设为同一有效期 |
| `local-life-service-peer-comparison` | 同行商品、流量或内容观察，指数／区间语义，差距到动作的表达 | 不强迫整份报告改自然周；同行保留页面实际周期和层级，不把品牌数据变成店级，不限制主报告只能给 3 条建议 |
| `local-life-service-product-edit` | 商品定位与详情、字段原值及五态能力识别、商品 ID 和单位核验 | 仅用只读诊断部分；不进入写入、草稿、保存或提审流程。实际改品只提供后续任务说明 |
| `local-life-service-aigc-video` | 真实素材要求、卖点到镜头、选题与故事卡文字结构 | 当前 skill 可形成文字内容任务，不启动生成、渲染或发布，不让用户再选视频方案作为报告前置条件 |
| `local-life-service-merchant-onboarding` | 可借鉴身份核验与操作后回读的原则 | 不调用入驻流程。分析门店选择不能借用认领、绑定、资质提交或审核步骤 |

这些参考文件只提供分析方法，不参与登录、账号校验或数据采集。V6 的浏览器取数由本 Skill 使用 DOM 完成；不跨 Skill 请求经营数据，不硬编码浏览器 SDK、Canvas 工具或模型名称。

## 调用方式

优先在一个主流程里复用浏览器上下文和已取得的数据。若环境支持细分技能调用，传入任务边界，让其返回数据或文字分析，不分别生成完整报告。

```text
任务：为选定门店的中秋国庆经营方案提供【具体子任务】。
已确认上下文：本 Skill 通过 DOM 得到的账号一致结果、本次分析范围、各店城市地址与品类、节日年份、本店观察窗口。
现有资料：相关来源记录、目标商品和已知缺口。
只做：需要的取数／诊断／比较／选题提炼。
返回：实际对象层级、数据窗口、来源、事实、推断、缺失状态、建议候选。
本次不做：重复选店问卷、独立成稿、后台业务变更、视频生成或发布。
```

如果原技能的整体流程不能限制在这些细分能力内，不直接启动其完整流程；读取相关方法后，由主技能使用当前工具完成对应步骤。不能在报告中宣称“已调用某能力”但实际没有调用。

接收结果时回查本次分析对象、周期、层级与口径。不通过两端门店数量比较重新判断账号一致性。同行品牌级、城市行业级、目标店级结果分开；原技能产生的通用方向不能自动升级为本店事实。

## 后续任务说明

只有本店方案确实需要继续操作时展示对应任务卡，不固定为每家店都展示两个按钮。按钮负责查看或复制文字，不能伪装为自动执行。

### 商品编辑

携带目标店、真实商品名称及可核验标识、当前字段与规则、建议表达、建议原因、适用节日、尚未确认的条件。任务不包含改价或折扣调整。提示用户在豆包办公使用 `local-life-service-product-edit` 继续，由该技能完成实际页面能力验证和执行。

新建商品不是既有改品技能的能力。建议“新增四人餐／家庭房组合”时，若没有可用的商品创建技能，给人工配置清单或引导商家后台处理，不把任务交给只支持改品的技能。

### 宣传视频

携带目标店、节日、客群、选题、开头、镜头或脚本、真实商品及权益、门店素材要求、实际参考来源。引导使用 `local-life-service-aigc-video` 继续制作，不在本技能里实际生成视频。

正文中的“拟调整商品名”“拟上线活动”与当前已生效状态分开。任何下游任务在执行前需核验实际对象与当前状态，不能直接依据旧报告或视觉样例修改线上业务。

## 工具降级

优先使用豆包办公当前真实可用的浏览器 DOM、文件创建、HTML 预览和附件能力。不得把 DOM 取数降级为 `mcp-http` 或页面内部接口。原技能写到的 `interaction.request_action`、`CanvasCreateFile`、`present_files` 等只是可能实现；工具不存在时改用环境已提供的等价能力，不输出不存在的按钮、伪造任务链接或调用结果。

已有登录、门店、日期和约束在主流程中共享。只有当前状态变化或新信息影响具体动作时才补问，不让商家因为组合使用多个技能而重复回答同一件事。
