# 医学证据持续监控

每期创建一份新的、面向医生阅读的飞书进展报告。用户可见的定时运行说明必须简洁自然，只写与更新频率匹配的相对窗口：每周一次对应“近 1 周”，每两周一次对应“近 2 周”，每月一次对应“近 1 个月”；不得写具体日历日期。说明同时明确关注主题、完整使用本 Skill 的“定时推送新内容”模式、避免重复历史内容、不附上一期报告链接与不再邀请订阅。上一期报告和原定时任务只用于非用户可见地恢复配置、延续关注问题和更新内部报告引用；不把上一期报告作为任务附件、用户可见 Prompt 或定时推送链接，不另建跨期去重流程，不向用户展示检索流水、内部台账或原始状态字段。

## 执行原则

- **多路发现、统一择优**：论文发现先并行使用 `general_search` 与 `scholar_search`。检索开始前只查看当前会话已加载、可用的 Skill 与 MCP 工具：若 `pubmed-medical-literature` 存在且其 PubMed MCP 可调用，后续 PubMed 通道优先按该 Skill 说明使用 MCP；否则沿用参数化 PubMed URL。随后无论首批数量是否已足，都继续补充 Europe PMC 与 Crossref。用户明确关注最新临床试验、试验注册、招募、状态变化或结果发布时，同批增加 ClinicalTrials.gov 专线；单个入口失败即跳过，不循环重试。正式发表研究仍不充足时才追加预印本检索。预印本不是每期必跑项。
- **来源偏好是软偏好**：关注主题和重点话题决定查询与排序；来源范围偏好用于加权、补充和展示，不是白名单、硬准入或“必须逐个覆盖”的清单。不要因为某个偏好来源没有结果而中止报告。
- **明确问题贯穿全链路**：用户原话已包含希望通过持续文献关注回答的明确问题时，提取并保留 `focus_question` 与相关 `question_context`，用它们辅助检索、筛选、报告回答和后续订阅。不要把问题压缩成宽泛主题，也不要额外要求用户重填已给出的背景；具体患者的诊疗决策仍转 `doubao-clinical-decision-support` 技能。
- **论文宁缺勿滥**：预警/疑似掠夺性、期刊身份或同行评议机制不透明、明显低质量的论文不进入报告。开放获取（OA）本身不是低质量证据，不得仅因 OA 排除正规高质量期刊；结合期刊质量信号、研究设计和来源透明度判断。用户明确只要“关键/重大/重磅研究”时进一步提高门槛：低质量、边缘相关或仅有题录的论文一律不补位；若严格窗口及必要扩展窗口内仍无合格更新，直接说明“当前核心期刊未检索到符合条件的有效更新”。
- **按需获取原文**：检索结果和摘要足以支持候选时，直接据此筛选；只对少量日期冲突、链接异常、来源身份不清或关键数字缺少支持的最终候选选择性回源。
- **单文件运行态**：各路检索结果先保留在当前上下文中，完成检索、去重和筛选后写入一次 `report-data.json`，随后只允许期刊分区脚本原地富化一次。不要生成第二份报告 JSON、`evidence-ledger.json`、`batch-*.json`、逐批快照或嵌套转义的 JSON 字符串；使用原生 JSON 写入 UTF-8 文件并保留可读中文。
- **来源支持内容**：报告条目保留可点击来源和支持正文的证据片段，呈现实际取得的研究或官方内容。文档生成后直接交付实际链接。
- **尽量不派生子 Agent**：由当前主 Agent使用批量并行工具调用完成检索、筛选、写作和交付。只有用户明确要求，或单 Agent 遇到真实工具硬限制时才例外。
- **聊天就地引用**：聊天正文、首期报告交付摘要、多轮追问和定时推送摘要中，积极在关键进展或判断所在句段使用引用角标。`general_search` 和 `seed_medical_search` 实际返回的内容均可使用 `<RichMediaReference>["真实来源URL"]</RichMediaReference>`；URL 取工具真实返回的 `url/link`，与来源题名成对保留，所引内容须支持相邻主张。组件放在所支持句段的标点之后，尤其是句号之后；同处多个来源使用纯 URL JSON 数组。其他来源可在相关句段用可点击的完整题名或可读研究简称引用。已用角标或就地链接引用的来源，不在聊天文末重复列“参考来源”。飞书文档 XML 继续使用可读文字超链接，不写入聊天富引用组件；文档原有来源和参考文献要求保留。
- **聊天表达自然**：最终聊天摘要和订阅邀请可适度使用 1–3 个与进展、报告或提醒相关的 emoji，帮助扫读；不要每段堆 emoji，也不要用 emoji 替代医学事实、证据边界或风险表述。

## 1. 判断当前动作

- **首次只表达持续关注**：完成一次检索并创建首期报告，不创建定时任务；原话有明确关注问题时，同时保留问题及背景，报告后自然邀请订阅。
- **明确要求创建订阅**：从原话预填关注主题领域、重点标注话题、更新频率、来源范围偏好；原话有明确关注问题时，将原问题和与判断有关的人群、场景、技术路线、干预/对照或争议背景一并加入订阅，不另设必答问题。更新频率缺失时，根据领域更新速度和完整首期检索结果生成默认建议；无法可靠判断医学进展快慢时优先建议每两周一次，不把未知当作更新慢。用户明确频率始终优先。用户提到临床试验、试验注册、招募、NCT、试验状态或结果发布时，在重点话题或来源偏好中保留该意图，后续每期启用 ClinicalTrials.gov 专线。邀请用户进一步明确重点关注的子领域、技术路线、人群或进展类型；确认后只创建一个任务。
- **定时运行/立即更新**：读取原任务；定时运行按已确认频率检索近 1 周、近 2 周或近 1 个月的新内容，不单独维护跨期去重清单，仅在筛选和写作时避免把明显的历史旧内容重复推送。用户明确要求“立即更新”时作为一次性运行处理，默认不提前首次定时推送，也不改变长期调度锚点。完成后创建并交付新报告，再更新原任务。
- **修改/暂停/恢复/删除**：操作原任务，不新建第二个任务。
- **只有一次性“查某领域最新进展”**：完成一次进展检索和报告，不创建定时任务；普通文献调研、综述或课题调研才转「医学文献检索」。

用户回复“确认创建”前不得调用定时任务工具。不要让用户选择重要性阈值、无更新策略或其他内部参数。

## 2. 检索与筛选

检索时读取 `references/baseline-and-multisource-search.md`。

在执行任何检索前，只检查一次当前会话明确暴露的 Skill、MCP 与可用工具清单，不用 Bash、`find`、`rg` 或其他方式扫描用户本地/隐藏 Skill 目录：

- 若 `pubmed-medical-literature` 已加载且对应 PubMed MCP 工具可调用，记住本轮 PubMed MCP 可用；General/Scholar 首批完成后，PubMed 通道优先按该 Skill 说明使用 MCP，并沿用本次日期窗口与概念簇。MCP 成功时不要再重复拼接 PubMed URL；
- 若该 Skill/MCP 不存在或未激活，直接记住本轮使用 PubMed URL fallback，不中断检索、不要求用户先安装，也不反复探测；若 MCP 已明确可用但单次调用失败，可回退一次 PubMed URL 后继续，不能循环重试，也不能把临时错误表述为用户未激活连接器；
- 这项优先级只替换 PubMed 通道，不取代 General、Scholar、Europe PMC、Crossref 或按需启用的 ClinicalTrials.gov。

### 第一阶段：General + Scholar 并行发现

1. 建立主题的中英文名称、缩写、常用同义词与重点概念簇，确定明确的 `start_date`、`end_date`。如存在 `focus_question`，再拆出问题中的人群/对象、干预或暴露、比较、结局、场景与关键争议词，用于查询扩展和相关性排序，但不要把所有概念硬塞进同一条窄查询。
2. 并行调用 `general_search` 与 `scholar_search` 搜最近发表的论文：
   - General 同时做宽主题和重点概念查询，按需用 `site:pubmed.ncbi.nlm.nih.gov`、期刊/出版商域名等限定站点，并加入窗口对应的英文月份与年份；
   - Scholar 每次传 `publish_start_date` 与 `publish_end_date`，先宽主题，再拆重点概念；
   - 不把所有概念塞进一条过窄的布尔式查询，零结果时换同义词或减少一个概念扩展一次。
3. 同时用 General 搜最新医学资讯、共识/指南、监管和专业动态：中文使用 `YYYY年M月`，英文使用 `Month YYYY`；跨月分别查自然月。按主题追加一个中外建议信源名做定向发现，但信源表不是白名单。
4. General 命中论文报道、机构新闻稿或会议报道时，把它作为发现线索：提取论文原题、DOI、PMID、作者、期刊或试验简称，用 General/Scholar 或结构化入口反查对应论文页。找到后，研究条目的 `source_url` 指向论文、PubMed/Europe PMC、DOI 或正式预印本页面；报道页可另存为 `discovery_source_url`，不能替代论文链接。

### 第二阶段：PubMed MCP 优先与结构化入口常规补充

General/Scholar 首批完成后，无论结果数量是否已足，都尽量并行运行以下论文入口：

- PubMed：本轮 MCP 可用时优先调用 `pubmed-medical-literature` 的 PubMed MCP；本轮未检测到可调用 MCP 时，拼接 PubMed `[dp]` 参数化 URL；
- Europe PMC `SRC:MED + FIRST_PDATE` 参数化 URL；
- Crossref `from-online-pub-date/until-online-pub-date`，请求 `container-title` 和 `abstract`；
- 必要时对已选中的多个 PMID 做一次 Europe PMC `resultType=core` 批量摘要补充。

用户明确关注最新临床试验、试验注册、招募、状态变化或结果发布时，同批增加 ClinicalTrials.gov API 专线，分别查询窗口内首次发布的干预性试验、首次发布的试验结果和近期更新的试验记录。优先呈现 `ResultsFirstPostDate` 和 `StudyFirstPostDate` 对应的真实增量；`LastUpdatePostDate` 只说明注册记录发生变化，除非现有记录或跨期对比能支持具体变化，否则不得写成“公布新结果”或推断疗效。

结构化入口是补充召回，不是硬性完成门：单个入口不可用、返回 0 条或解析失败时直接跳过，不因故障重试拖慢报告。只有某个关键概念仍明显缺口时，才在可用入口缩短概念簇扩展一次。PubMed、PubMed Central/PMC、Europe PMC、Crossref 是收录或检索平台，不是期刊；ClinicalTrials.gov 是试验注册平台，也不是期刊。论文 `journal_name` 优先从批量结构化元数据提取真实刊名：Europe PMC `journalInfo.journal.title`/`journalTitle`、PubMed ESummary `fulljournalname`/`source`、Crossref `container-title`。PMC 命中项只要这些字段可得，用户可见元信息必须显示真实期刊，不得笼统写“来源：PubMed Central”。

把 General、Scholar 与结构化结果合并去重，按主题相关性、研究设计质量、来源可信度、证据成熟度和时效性统一排序。使用自适应纳入阈值：窗口内只有少量可核验研究时，有多少**达到质量底线**的相关结果就呈现多少；若没有合格论文，宁可少写或不写。已有约 5–6 篇较强候选足以支撑本期时，提高门槛，只保留更相关、设计更强、来源更可信的研究，剔除边缘相关、低信息量、仅有题录、预警/疑似掠夺性或明显低质量期刊的候选。优先系统综述/Meta 分析、指南相关研究、随机对照试验、大型前瞻性队列和高质量专科研究；不为了凑数保留垃圾文献。用户要求关键/重大研究时，先判断研究设计、样本与结果完整度、领域影响和来源权威性，再把本地期刊分区作为辅助信号；不能把“命中分区”直接等同于重大研究，也不能因没有分区自动排除设计可靠的新刊或专业期刊论文。

对候选论文的真实 `journal_name` 使用 Skill 包内 `scripts/match-journal-rank.js` 做本地批量匹配。脚本会从自身所在 Skill 包及邻近层级自动发现内置 `journal-rank-index.json`；直接调用包内脚本，不要把脚本或索引复制到报告工作目录，不要创建 `assets` 目录、推导 `__dirname`、检查符号链接或搬运文件。只有运行环境已经明确提供另一份索引时，才可选传 `--index <path>` 覆盖。期刊分区只是可选富化，不能阻塞报告：脚本返回 `journal_rank_index_unavailable` 时直接继续并省略 `journal_rank_2025`，不排查路径、不重跑、不猜分区。索引口径为 **2025 年中科院分区/北大核心**；只接受脚本返回的高置信匹配。若检索结果或可信期刊信息源另有明确的影响因子或 JCR 分区，可选写入 `journal_impact_factor` 或 `journal_quartile`，并同时记录指标年份与口径/来源；影响因子不得用 CiteScore、SJR 等替代。没有可靠数据就省略对应字段。

若本次不是定时任务触发，且用户明确限定“一周/近 7 天”，先完整执行严格窗口检索；如仍不足以形成有参考价值的权威进展报告，主动向前扩展近期窗口。通常先补近 30 天，更新较慢的领域仍明显稀疏时可再补近 90 天；这是补充背景，不把旧内容冒充一周内新增。只要主动扩展，就在 `report-data.json` 记录 `requested_date_range`、`included_date_range`、`window_expanded=true` 与 `window_note`，并在报告开头、总览画板和聊天摘要明确显示原始窗口及实际纳入时间跨度，区分“原始窗口新增”与“扩大窗口补充”；原始窗口为近 7 天时可分别标为“近 7 天新增”和“扩大窗口补充”。`action=scheduled_run` 时不得用扩大窗口替代真实增量。

### 第三阶段：按需补预印本

只有正式发表研究仍不充足时，才检索 medRxiv、bioRxiv、Research Square、Preprints.org，按领域补 SSRN、arXiv、OSF 或 Europe PMC `SRC:PPR`。这里的“不充足”是指主问题或用户重点仍有明显缺口。已发表研究充足时跳过本阶段；用户明确排除预印本时不搜索。纳入时醒目标注“未经同行评议”，旧预印本新版本与后续正式发表合并为同一事件链。

检索、筛选和去重全部完成后，再把最终入选内容一次写入 `report-data.json`；不要为每批工具结果创建本地文件。只要至少一条主要检索路径可用即可完成报告；搜索成功但没有合格增量时可如实写“本期未检出可核验的新研究或进展”。

### 日期、身份与证据边界

日期判断、资讯身份和来源规则以 `references/baseline-and-multisource-search.md` 为准，不在多个文件重复维护。保留三条底线：

- 不把旧论文、旧指南或旧监管动作冒充成本期新进展；
- 不根据题名或主题补造对象、设计、数字、结论或临床建议；
- 只有具备可点击来源和可支持正文的片段、摘要或官方内容时才写成用户可见条目。

## 3. 每期飞书报告

成文时读取 `references/output-and-qa.md`，使用 `assets/feishu-monitor-template.xml`。

报告依次包含：

1. **顶部总结内容**：报告开头直接显示日期范围和浅色总结 callout，不添加独立的“进展总结”标题。callout 内用无序列表覆盖正文中大多数值得提及的进展；如主动扩大时间范围，callout 上方先显示原始检索窗口和实际纳入跨度；
2. **你关注的问题进展**：仅当用户给出明确 `focus_question` 时放在顶部总结 callout 之后、“本期进展总览”之前。章节 H1 固定写成“你关注的问题进展：{section_title}”，其中 `section_title` 只是简洁的关注主题后缀；不使用 callout 或其他高亮块。章节内忠实呈现关注问题与必要背景，回答正文紧接背景直接开始，不添加固定的“基于本期证据的阶段性回答”小标题。正文可按内容自由使用短段、要点或按需小标题，不强制无序列表，但避免堆成大段文字。将证据日期、关键结果与 `display_id` 就近写在同一句或相邻句中，例如“6 月 26 日，VICTORION-Mono China 研究显示……（研究-01）”；可适度加粗关键结论、重要数字或证据边界以提高扫读效率，不整段加粗。不在段末集中堆叠编号，不再另列“对应时间”，也不重复成“【研究-01】研究-01（发表日期……）”。证据边界另起一段；证据不足时明确写暂不能得出结论；
3. **本期进展总览画板**：用 `scripts/render_overview_whiteboard.py` 生成 SVG，只呈现具体核心观察与三类彩色分类卡；画板应脱离正文也能读懂，逐条原题、期刊/来源和链接留在正文，避免头部重复堆叠；
4. **最新医学资讯**；
5. **共识、指南与监管进展**；
6. **研究进展**，按本期主题自然拆分；
7. **临床试验进展**，仅在用户关注试验注册、招募、状态或结果发布且本期有合格增量时出现；
8. **灵感启发**，每条用独立浅色 callout，只写由本期证据触发的研究或方法学问题；
9. **订阅设置**：仅首期或非定时触发时放在最后；`action=scheduled_run` 时省略整个章节。

空章节可省略。除主动扩大时间范围时必须展示原始窗口与实际纳入跨度外，不展示检索过程、覆盖情况、基线、当前结论、task_id、checkpoint、证据台账或运行日志。用户只要关键/重大研究而没有合格论文时，研究进展章保留一句“当前核心期刊未检索到符合条件的有效更新”，不要用低质量论文填满空章。不要给每条内容机械套“发生了什么/为什么值得关注/证据边界”；根据材料自由使用段落、列表、小表、callout 或补充图表。

所有用户可见内容只从最终 `report-data.json` 生成；各路检索结束后写入一次，再由期刊匹配脚本原地富化一次，不生成第二份报告数据：

- 顶层写入 `requested_date_range` 与 `included_date_range`；主动扩大时再写 `window_expanded=true` 和简短 `window_note`，禁止让“近一周/本周”等文案覆盖半年或其他更长时间的论文；
- 用户有明确关注问题时，顶层另写逐字或忠实转述的 `focus_question`、只保留与问题判断有关的 `question_context`，以及 `focus_question_answer={section_title,points,evidence_boundary}`。`section_title` 只写固定标题“你关注的问题进展：”后的简洁关注主题，不包含该固定前缀，不照抄过长问句，也不附加“近期进展”或“阶段性判断”等套话；`points` 为对象数组，每项写 `text`、`supporting_display_ids` 与 `evidence_dates=[{display_id,date,date_type}]`，一项只承载一个阶段性判断。`evidence_dates` 必须与该点支持条目一一对应，使用来源可核对的发表、发布、监管动作或试验首次发布/更新日期；不得填检索日期、网页访问日期或报告生成日期，也不得把随访时长当作发表时间。生成用户可见回答时，将每个日期与它支持的研究/机构、关键内容及简洁编号自然融入同一叙述单元，不把 `evidence_dates` 机械渲染为独立的对应表。回答必须由入选条目支持，不能把搜索前的假设写成结论；
- `key_observations` 可直接写成 3–4 条字符串；如希望保留证据映射，也可写成 `{"text":"…","supporting_display_ids":["研究-01"]}`。两种形式均可直接渲染，不要为此读取脚本源码；
- 建议每个 `report_item` 写入时直接带上 `category`：医学资讯用 `news`，共识/指南/监管用 `guideline`，论文/预印本/临床研究和注册试验增量用 `research`；漏填时渲染器会尝试从编号或类型推断；
- `display_id` 全报告唯一；`short_label` 是易读中文概括，`original_title` 逐字保留来源原题；
- 存在 `focus_question` 时，每个入选 `report_item` 增加 `question_thread={relation,relevant_evidence,bounded_inference}`：分别说明它为何与问题有关、来源中哪部分信息直接相关，以及据此最多能推导到哪一步。间接证据必须标为间接，不能把相关性、机制或二次报道升级为因果、疗效或临床建议；与问题没有可解释关系的材料不应为凑数纳入；
- 正文逐条列举资讯、共识/指南/监管和研究时，尽量在标题前沿用画板中的同一 `display_id`，让读者可以从画板定位正文；用于图文相互定位；
- 每个资讯、研究/预印本、共识/指南和监管条目的**标题本身**都用对应 `source_url` 创建可点击超链接，不能只在段末另放来源；
- 期刊名只显示结构化结果真实返回的 `journal_name`。PubMed Central/PMC 命中的论文先通过一次批量 PubMed ESummary、Europe PMC `resultType=core` 或 Crossref 元数据补全真实刊名；真实刊名仍不可得时显示“收录平台：PubMed Central”，不得写“期刊：PubMed Central”。PubMed、Europe PMC、Crossref、ClinicalTrials.gov 都不是期刊，PMID/DOI/NCT 有则显示、无则省略；`journal_rank_2025` 非空时追加“期刊级别：中科院 X 区/北大核心（2025）”，未命中时整段省略；
- ClinicalTrials.gov 条目使用 `display_id=试验-XX`、`category=research`，写明 `trial_id`、`trial_delta_type=new_registration|results_first_posted|record_update`、对应 `delta_date`、试验状态与可得分期；标题链接 `https://clinicaltrials.gov/study/{NCTId}`。注册信息或结果发布不是期刊论文，不填写 `journal_name` 或期刊分区。
- 问题回应、总结、画板和灵感不得比正文证据更具体或更确定；正文中的 `question_thread` 必须区分来源直接事实与模型推导。

写 JSON 时正文引号优先使用中文全角引号 `“”`。渲染器会保守兼容正文中误写的未转义 ASCII 双引号，以及字符串形式的 `key_observations`；不要因这两类轻微格式问题中断流程、检查行号或读取源码。

`report-data.json` 写完后直接运行下列固定命令，不需要先查看脚本帮助或源码。期刊脚本只原地补充高置信 `journal_rank_2025`，不生成另一份证据文件：

```bash
node scripts/match-journal-rank.js \
  --report-json report-data.json \
  --in-place

python3 scripts/render_overview_whiteboard.py \
  --input report-data.json \
  --output overview.svg
```

上面的相对路径是从 Skill 包根目录运行时的简写；若运行环境暴露的是 Skill 文件实际路径，直接调用该包内脚本即可，不复制文件来重建目录结构。期刊脚本会自动发现内置索引；`--index` 只是可选覆盖参数。若脚本返回 `journal_rank_index_unavailable`，直接跳过期刊分区并继续生成画板和报告，不创建目录、检查软链接或读取源码。`report-data.json` 本身仍须是合法 JSON，因为期刊富化和画板共用它；如语法错误，只修复这一个交付真源，不另建转义副本。

渲染器可在遗漏 `category` 时根据 `display_id` 或类型字段做一次安全推断，但这只是容错；生成数据时仍应一次性补齐类别。

生成完整 `monitor-report.xml`，并固定在“本期进展总览”标题下写入 `<whiteboard type="svg" path="@overview.svg"></whiteboard>`。把 `monitor-report.xml` 与 `overview.svg` 放在同一工作目录，让飞书文档创建能力直接读取两个相对文件。不要上传 SVG、不要构造公网 URL、不要改用 `<img>`，也不要为选择插入方式重新阅读 XML 说明。连接器激活提示属于飞书文档生成后的聊天后处理，不能进入 `report-data.json` 或 `monitor-report.xml`；飞书报告正文在“确认创建”段后封口，不在其后追加聊天提示。

飞书写入路径已经由本 Skill 的 XML 模板固定：在 `monitor-report.xml` 所在目录以相对 `@monitor-report.xml` 一次创建完整文档。当前上下文已经有飞书创建能力及其参数说明时，直接执行，不要再搜索、Grep 或通读 `lark-doc` 的顶层 Skill、XML 语法、样式、创建工作流、更新、媒体等通用资料。本地模板与本节是本任务的写入依据；只有首次创建明确返回参数或 XML 语法错误时，才读取与该错误直接相关的 create/XML 小段参考，不读取无关模块。

正常路径只执行一次完整 create。只有该次调用明确因载荷或长度限制失败且没有留下可用文档时，才把同一份已完成 XML 机械拆成最多 3 个连续 section，在一个 document ID 中创建并顺序追加。文档生成后交付实际 URL，可通过 `present_files` 提供文档入口。

首期聊天给出本期摘要和 `[查看完整飞书进展报告]({本次实际 URL})` 后，再自然邀请订阅，并在回复末尾区域完整展示订阅邀请与配置。若本次由定时任务触发，只发送订阅周期对应窗口内的进展摘要和新报告链接，不再次邀请订阅，不展示“确认创建”或订阅配置表：

> 🔔 我可以定期帮你跟踪「{关注主题领域}」的最新研究、指南监管与医学资讯，并推送新的进展报告。需要订阅推送吗？我已经根据该领域特点和本次检索结果生成以下默认配置；如无调整，回复 **确认创建** 即可。你也可以进一步告诉我最想重点关注的子领域、技术路线、人群或进展类型。

随后直接展示 Markdown 配置表，至少包含“关注主题领域、重点标注话题、更新频率、来源范围偏好”四项。若用户已给出明确关注问题，再展示一行“持续关注的问题与背景”，直接从原话预填，不把它变成第五个必答问题。该配置表和“确认创建”提示既要出现在飞书文档，也要完整出现在聊天 response 的末尾区域；不能只给文档链接或说“配置详见文档”。飞书报告在该配置表的“确认创建”段后封口；以下连接器提示不属于报告。

飞书文档生成后，再独立组装最终聊天。只有本轮开始时没有可调用的 PubMed MCP、实际走了 PubMed URL fallback 时，才在聊天配置表之后追加下面这一行，作为整条聊天回复的最后一行；MCP 可用或只是单次临时调用失败时不显示。该提示不写入飞书报告、用户可见定时任务说明、订阅配置或内部状态，也不算再次邀请订阅：

> 如需提高 PubMed 检索质量，可以在「连接器」中激活添加「PubMed/医学文献 MCP」。

来源范围偏好可由用户调整，但始终作为搜索与排序偏好，不作为硬准入。

更新频率未指定时，结合领域特点和完整首期结果给出一个默认值：

- 更新快、首期有多条重要研究/监管/会议进展：建议**每周一次**；
- 更新中等、重要变化通常隔周出现，或现有信息不足以可靠判断医学进展快慢：建议**每两周一次**；
- 更新较慢、首期有效增量较少：建议**每月一次**。

首期检索不完整、可用样本太少或领域特点与检索结果的快慢信号矛盾时，都属于无法可靠判断；未知不等于更新慢，不得仅因无法判断就默认月更。用户明确选择的频率始终优先。

若首期必须主动扩大用户指定的近 7 天窗口后才获得有效、有价值的文献，默认频率随实际更新速度放宽：补到近 30 天才形成有效报告时优先建议**每两周一次**；补到近 90 天或仍然较稀疏时优先建议**每月一次**。不要在这种情况下仅因用户最初问了“一周”就默认每周推送；这是推荐值，用户明确选择的频率仍优先。

这是默认建议而不是硬规则；用户可直接调整。未指定具体推送日/时间时，在建议频率后写“推送时间待确认”，不得擅自填写“每周一”。

## 4. 创建和维护订阅

用户确认后读取 `references/monitor-contract.md` 与 `references/scheduled-run-protocol.md`：

1. 复用已交付的首期报告作为非用户可见的上一期报告引用，仅用于延续关注问题和更新内部状态；不要把该链接附在定时任务、用户可见 Prompt 或后续推送中；
2. 创建唯一任务。用户可见的定时运行说明用两个编号写清：“请完整使用 `$doubao-medical-literature-monitoring` 的‘定时推送新内容’模式。1. 时间与主题：按{更新频率}跟踪「{关注主题}」的新进展。2. 推送要求：只推送{相对时间范围}内新出现或有实质变化的内容，避免重复历史内容。完成后直接发送本期摘要和新报告链接，不要附上上一期报告链接，不要再次邀请订阅，也不要展示订阅配置。”创建前必须把频率、主题和相对范围替换为用户确认的真实值，不保留占位符，也不写具体日历日期。频率映射固定为：每周一次→近 1 周，每两周一次→近 2 周，每月一次→近 1 个月；
3. 首期报告已经即时交付，创建任务后不得立即再推送。以用户确认且任务成功创建的时间为生效锚点：每周一次至少等待满 1 周，每两周一次至少等待满 2 周，每月一次至少等待满 1 个日历月。用户指定星期、日期或时刻时，首次触发取满一个完整周期后的第一个匹配点；未确认具体推送日或时间时保持“推送时间待确认”，不得猜测；
4. 将 `action=scheduled_run`、任务 ID、上一期报告引用、最新成功时间、订阅设置、调度锚点、具体首次/下次运行时间、可选关注问题与背景保存在调度工具或任务对象的非用户可见结构化状态中；上一期报告引用不得成为任务附件或用户可见链接，也不得把这些原始字段名、具体运行日期或键值串拼入用户可见说明；
5. 后续普通运行不滚动改写用户可见说明；仅当关注主题、更新频率或关注问题改变时更新相应文字。修改频率后以修改生效时间为新锚点，按新周期重算下一次定时触发。

定时运行按已确认频率检索近 1 周、近 2 周或近 1 个月的新内容，再按相同“General + Scholar → PubMed MCP 优先/URL fallback + Europe PMC/Crossref 常规补充 → 用户关注临床试验时增加 ClinicalTrials.gov → 正式研究不足时补预印本”顺序执行。每次检索前只检查一次当前会话已加载的 Skill/MCP 能力，不扫描用户目录。运行时再把相对周期换算为检索接口和报告所需的真实起止日期；每月按日历月计算，不等同于近 4 周或固定 30 天。用户可见任务说明始终只写相对范围。不另建跨期去重清单或专门流程；只在筛选和写作时避免重复明显的历史旧内容。存在 `focus_question` 时，每期继续围绕同一问题和背景检索，在顶部无独立标题的总结 callout 后，用“你关注的问题进展：{section_title}”独立章节更新阶段性回答，并说明本期新增证据是否改变、加强或削弱既有判断；回答紧接问题背景直接开始，不添加固定的“基于本期证据的阶段性回答”小标题。正文可自由使用短段、要点或按需小标题，适度加粗关键结论、重要数字或证据边界，并将日期、证据内容和条目编号就近融入叙述。每个入选条目继续呈现与问题的关系和有限推导。每期创建新报告，不追加旧报告；新报告创建并交付后更新 `last_success_at`。定时触发只发送本期摘要和新报告链接，不附上一期报告链接；飞书报告与外部聊天均不再次邀请订阅、不展示“确认创建”或订阅配置表。只有本轮实际走了 PubMed URL fallback 时，才在飞书文档生成后向聊天末尾追加上述连接器提示；绝不把它写进飞书报告。报告用于医学证据跟踪，不替代临床决策或监管原文。
