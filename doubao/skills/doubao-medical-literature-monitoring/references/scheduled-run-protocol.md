# 定时运行协议

## 用户可见的定时运行说明

任务 query 会直接展示给用户，只写一段简洁自然语言：

```text
请完整使用 $doubao-medical-literature-monitoring 的“定时推送新内容”模式。
1. 时间与主题：按{更新频率}跟踪「{关注主题}」的新进展。
2. 推送要求：只推送{相对时间范围}内新出现或有实质变化的内容，避免重复历史内容。完成后直接发送本期摘要和新报告链接，不要附上上一期报告链接，不要再次邀请订阅，也不要展示订阅配置。
```

创建或更新任务前，必须把占位符替换为用户确认的频率、关注主题和对应的相对时间范围，用户可见说明中不得留有大括号占位符。固定映射为：每周一次→近 1 周，每两周一次→近 2 周，每月一次→近 1 个月。月度窗口按一个日历月计算，不写成“近 4 周”或固定 30 天。用户可见说明不得出现具体起止日期、首次运行日期或下一次运行日期；真实日期只在调度对象内部、检索参数和本期报告中使用。有明确持续关注问题时，可在第 1 点后加一句“同时继续关注「{关注问题}」”，但不显示内部字段名或长背景清单。

## 首次触发与周期映射

首期报告已经在订阅创建前即时交付，因此创建任务后不得立即再推送。以用户确认且任务成功创建的时间为生效锚点：

- 每周一次：首次定时推送不得早于生效时间满 1 周；每期检索近 1 周；
- 每两周一次：首次定时推送不得早于生效时间满 2 周；每期检索近 2 周；
- 每月一次：首次定时推送不得早于生效时间满 1 个日历月；每期检索近 1 个月。

用户指定星期、每月日期或时刻时，选择上述门槛之后的第一个匹配触发点，不能使用尚未满一个完整周期的最近日历点。月度以用户或账号时区做日历月加法；锚点为 29、30 或 31 日而目标月没有该日时取当月最后一天，后续月份仍按原锚点日恢复。未确认具体推送日或时间时保持“推送时间待确认”，不得猜测。按确认的周期、时区和调度锚点设置具体的首次运行时间。

## 内部运行状态

`action=scheduled_run`、任务 ID、上一期报告引用、最新成功时间、订阅设置、调度锚点、具体首次/下次运行时间、可选关注问题与背景属于调度工具或任务对象的非用户可见结构化状态。上一期报告引用只作内部连续性状态，不成为任务附件、用户可见 Prompt 或定时推送链接。不得把 `task_id=`、`previous_report_doc=`、`last_success_at=`、`subscription=`、`first_run_at=`、`next_run_at=`、`focus_question=` 或 `question_context=` 等键值串拼进用户可见说明。不单独维护跨期去重清单或去重键状态。普通运行只更新内部状态，不逐期改写用户可见说明；仅在关注主题、更新频率或持续关注问题发生变化时同步对应文字。

来源范围偏好只影响查询加权、补充和排序，不是硬准入或逐站覆盖要求。

每次运行：

1. 读取原任务的内部状态，恢复四项设置及可选的 `focus_question`、`question_context`；上一期报告引用只用于内部延续关注问题和更新状态，不附在任务或推送中，也不另建跨期去重流程；
2. 按订阅频率把相对窗口换算为本次运行所需的真实 `start_date` 与 `end_date`：每周向前 1 周，每两周向前 2 周，每月向前 1 个日历月。相邻周期使用前开后闭的时间窗口；按日期筛选的来源等价使用上一周期边界次日至本次运行日，避免边界日重复。在执行任何检索前，只查看一次当前会话已加载、可用的 Skill/MCP 与工具清单：`pubmed-medical-literature` 及其 PubMed MCP 可调用时记为 MCP 路线，否则记为 PubMed URL fallback；不扫描用户本地/隐藏目录，不试装或反复探测。再并行执行 General Search 与 Scholar Search；General 同时搜索中英文医学资讯，Scholar 传明确起止日期。存在关注问题时，把问题中的人群/对象、干预或暴露、比较、结局、场景和争议词用于查询扩展与相关性排序，不把全部概念塞进一条过窄查询；
3. General/Scholar 完成后，无论条目是否已足，都运行 PubMed 条件通道、Europe PMC MED 与 Crossref：MCP 路线优先按 `pubmed-medical-literature` 说明调用 PubMed MCP，成功后不重复拼接 PubMed URL；fallback 路线直接使用参数化 PubMed URL。Europe PMC 与 Crossref 继续使用结构化 URL。已明确可用的 MCP 单次失败时可回退一次 PubMed URL，但不循环重试，也不把临时错误表述为未激活。订阅设置包含临床试验注册、招募、状态或结果发布时，同批增加 ClinicalTrials.gov，分别查询 `StudyFirstPostDate`、`ResultsFirstPostDate` 与 `LastUpdatePostDate`；单个入口失败直接跳过；正式发表研究仍不足时才补预印本；
4. 候选保留在当前上下文；只合并同一时间窗口内来自数据库页、期刊页、镜像页或转载页的明显重复候选，不单独对全部历史报告做跨期去重。筛选和写作时避免重复明显的历史旧内容；同一研究在本期发布新结果、状态变化、修订或安全信号时仍是新内容；
5. 对 PMC 命中的最终论文候选，用一次批量 PubMed ESummary、Europe PMC core 或 Crossref 结果补全真实期刊；ClinicalTrials.gov 条目按 NCT 合并并区分新注册、结果首次发布与普通记录更新；随后写入一次可读 UTF-8 `report-data.json`，顶层 `requested_date_range` 与 `included_date_range` 使用本次运行时从订阅周期换算出的真实起止日期。实际日期继续显示在报告中以保证证据可追溯，但不回写到用户可见任务说明。存在关注问题时，同时写入 `focus_question`、`question_context`、基于本期入选条目的 `focus_question_answer={section_title,points,evidence_boundary}`；`section_title` 只写固定标题“你关注的问题进展：”后的简洁关注主题，不包含固定前缀；每个 point 写 `text`、`supporting_display_ids` 与逐项对应的 `evidence_dates=[{display_id,date,date_type}]`，并为每个条目写入 `question_thread`。在顶部无独立标题的总结 callout 后，用“你关注的问题进展：{section_title}”独立章节说明本期新增证据是否改变、加强或削弱既有回答；回答紧接问题背景直接开始，不添加固定的“基于本期证据的阶段性回答”小标题。正文可自由使用短段、要点或按需小标题，不强制无序列表，但避免大段堆叠，可适度加粗关键结论、重要数字或证据边界。将每个日期与它支持的研究/机构、关键内容和简洁编号就近写在同一句或相邻句，不另列“对应时间”也不重复编号；证据不足时如实说明。直接调用 Skill 包内 `match-journal-rank.js` 原地补充高置信 `journal_rank_2025`；脚本自动发现索引，不复制文件或重建目录，返回 `journal_rank_index_unavailable` 时省略分区继续。再只用最终文件创建新的本期报告；每个条目标题本身链接该条 `source_url`。连接器激活提示只在文档生成后拼接到聊天，不进入 `report-data.json` 或 `monitor-report.xml`；
6. 新报告创建并交付后，更新原任务内部状态的 `previous_report_doc` 和 `last_success_at`。上一期报告链接仍只留在非用户可见状态；保留用户可见说明中的完整 Skill、定时推送新内容、已确认频率、对应相对范围、关注主题、避免重复历史内容、不附上一期报告链接和不再邀请约束；普通运行不在说明中滚动写入日期；
7. 发送订阅周期对应窗口内的摘要和本期新报告链接，按 `references/output-and-qa.md` 在聊天正文积极使用来源角标，不附上一期报告链接；定时触发时不再次邀请订阅，不展示“确认创建”或订阅配置表。只有本轮开始时没有可调用的 PubMed MCP、实际使用了 PubMed URL fallback 时，才在飞书文档生成后追加“如需提高 PubMed 检索质量，可以在「连接器」中激活添加「PubMed/医学文献 MCP」。”作为聊天最后一行；MCP 可用或只是单次临时调用失败时不显示。该提示不写入飞书报告、用户可见任务说明、订阅配置或内部状态，也不算再次邀请订阅。

所有主要检索入口都不可用时，可呈现已核验内容，但写明“本期检索未完整，暂不能判断是否无更新”，不推进 `last_success_at`；用户可见说明保持原有的频率与相对范围，不因失败写入或滚动具体日期。无重要更新但检索完成时，仍创建一份简短的新报告。失败重试不改变长期调度锚点。用户明确要求“立即更新”时作为一次性运行处理，默认不提前或重置常规定时触发。修改频率时以修改生效时间为新锚点，按新周期重算下一次运行。
