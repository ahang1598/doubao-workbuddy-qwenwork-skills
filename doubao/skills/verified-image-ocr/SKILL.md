# Verified Image OCR

把图片视为待核验的数据源，而不是可凭印象转写的版面。先读附件、逐图建账、按可见结构提取，再通过结构与数值校验门；只有校验后的数据才能进入去重、计算、图表或台账更新。

## 1. 盘点并读取输入

1. 枚举本轮全部附件，建立来源清单；每项记录 `图片编号`、`文件名`、`页码`、`顺序`、`主题/版块` 和读取状态。用户给了本地路径时先读取本地附件；只有本地读取失败、同名路径疑似覆盖多图或附件确实不可用时，才改用用户已提供的对应链接。
2. 每一张新图都必须实际读取后才能产出内容；不得沿用上一张图的识别结果。用户说上传了 4 图而清单实际有 5 图时，先明确第 5 图是否纳入，不能静默遗漏或并入。
3. 大批图片按编号分批读取并保留全量清单，不用一次载入全部高分辨率图片。低清、倾斜或密集表格先裁剪目标区域、放大或去斜，再 OCR。

**具体约定：** 若两个附件暴露为同一个本地路径，不能把同一路径读取两次当作两张图已处理；在清单标记“路径冲突”，再按各自附件链接读取，并分别保留 `图片编号`。赛事材料还需从图中保留 `赛事编号` 与 `时间`，以免初盘和尾盘错配。

## 2. 按图提取可见结构

1. 严格按 `图片编号` 逐图提取。普通版面保留版块、段落、原顺序和换行；表格先确定可见表头、网格、合并单元格、行列顺序、单位和跨页续接关系，再逐格填值。
2. 只记录图上可见内容。空单元格写为显式空值 `null` 或空串并另记 `空白类型=原图空白`；被裁切、遮挡或模糊的格写 `待确认`，不得用相邻行、同系列商品或上下文补齐。
3. 保持值与标签绑定。例如完税证明逐项提取 `税种`、`所属期`、`金额`；检验表保留 `受试者编号`、`姓名缩写`、`年龄`、`性别`、`T0（单位%）`、`T1.5h（单位%）`、`T2.5h（单位%）`、`T3.5h（单位%）`，不能因版面错位把年龄与性别互换。

**具体约定：** 跨页表中只把上页末行与下页首行拼接到同一记录，当两页的可见表头/列数相容且续接关系可由图片确认；截断字段保留可见原文并标 `待确认`，不得推断缺失后缀。词表按图中的 `单元` 边界归组，不能只按上传顺序猜单元。

## 3. 做结构与覆盖校验

1. 为每图记录 `可见行数`、`提取行数`、`可见列数`、`提取列数`、`空行数`、`空单元格数`、`截断项数` 和 `待确认项数`；逐图核对后再合并。
2. 检查表头完整性、每行列数、空行、空格、错位、重复图片、重复记录、首尾截断和跨页重叠。空白必须留在原行原列，不能删除后让后续数据上移。
3. 多图合并时检查来源覆盖：清单中的每个 `图片编号` 必须有提取结果或明确失败原因；输出中的每行必须能回指 `图片编号/页码/行号`。

**具体约定（可量化）：** 必须满足 `提取行数 + 未识别行数 = 可见行数`；纯号码批次若需求规定每组 25 个号码，则每组必须恰有 25 个、范围为 `01–35` 且组内无重复。最终要求 50 项时，交付前必须核对序号 `1–50`、首项、末项与分组边界，不能以“看起来完整”代替计数。

## 4. 做数值、合计与去重校验

1. 数值字段二次回看原图，重点检查 `0/8`、`1/7`、小数点、百分号、负号、日期和单位。逐列核对时间或年度表头，防止数值整体错列。
2. 重算可验证的小计、合计、占比、条目数和净增量；用户给出的已知值用于交叉校验，但冲突时回到原图定位具体单元格，不静默覆盖。
3. 去重前先定义业务键和标准化规则。漏洞对比先规范化 IP 与 CVE/漏洞名、展开成“一 IP 一漏洞”，再按 `(IP, CVE)` 求交集；不能仅凭相似描述目视判重。
4. OCR 明细是核验基准；已有汇总结果只能做交叉校验。若二者不一致，回读图片明细并报告差异位置。

**具体约定（可量化）：** 更新抽奖或台账时必须展示 `原始条数`、`重复条数`、`净增条数`，且满足 `净增条数 = 原始条数 - 重复条数`；设备清单同时校验 `条目数` 与逐行 `数量` 之和形成的 `总台数`，二者不得混报。赔率材料需分别保留 `初赔` 与 `即时赔`，并先核对机构数量和重复机构，再进入凯利计算。

## 5. 隔离并确认不确定项

1. 对模糊、遮挡、涂改、截断、列边界不清或 OCR 多解的内容，记录 `图片编号`、`页码/区域`、`行列位置`、`可见原文`、`候选识别`、`不确定原因` 和 `影响`。
2. 先局部裁剪、放大或二次 OCR；仍不能唯一确定时标为 `待确认`，请求更清晰图片或让用户确认候选。不得把 `TBD`、`待确认` 或原图空白替换成猜测值。
3. 若疑点影响合计、去重、图表、更新台账、工程量、合规或结论，暂停受影响的下游步骤；不影响的已确认部分可以先交付，并明确范围。

**具体约定：** 涂改的温度—时间表必须先确认涂改单元格再绘图；固定套餐截图必须先列出识别出的 `套餐`、`泵数` 与 `年用量` 疑点，经确认后才能反推用量；工程或发奖核对分别保留 `尺寸/材料`，以及 `区服`、`角色ID`、`日期`、`档位`、`发奖串` 的逐字段差异，不能用整体“基本一致”放行。

## 6. 交付、更新与回读

1. 交付结构化结果时保留来源列，推荐至少包含 `图片编号`、`页码/区域`、原业务字段、`识别状态` 和 `备注`。随后附校验摘要：覆盖图片数、行列计数、空白/截断/待确认数量、合计或去重等式及未决疑点。
2. 只有通过结构校验和关键数值校验的数据才能用于计算、图表、统计、去重或决策。下游产物生成后，抽查关键结果回指到结构化中间表和原图。
3. 若任务要求写入 Excel、飞书表格或台账，实际写入后必须回读目标范围，核对新增行数、关键字段与来源映射，再声明“已更新”；仅生成文本或口头声称不算完成。

**具体约定：** 图片发奖核对按用户指定的逆序关系对齐文本后，逐条比较 `区服/角色ID/日期/档位/发奖串` 并输出“一致/差异”清单；漏洞去重结果必须逐项带两个月份各自的 `图片编号`。任何交付都要区分 `已验证`、`待确认`、`无法识别` 三种状态。

## 禁止事项与停止条件

- 不读取新附件就输出识别结果；不把 OCR 候选或历史结果伪装成已读图事实。
- 不臆造表头、字段值、空白内容、图片缺失部分或跨页续接文本。
- 不删除空行、空单元格、重复项或错位迹象来制造整齐表格。
- 不在关键 `待确认` 项未解决时继续会改变数字或结论的计算、图表、更新与合规判断。
- 不宣称“全量复核”，除非清单中的每个 `图片编号` 都逐图完成；抽样复核必须明确写“抽样”及样本范围。

## 精简示例

用户要求比较两个月的漏洞截图并找重复项：先为每图分配 `图片编号`，提取 IP 与 CVE/漏洞名并保留空白；把一行多漏洞展开为“一 IP 一漏洞”，规范化后按 `(IP, CVE)` 求交集；核对两月原始条数、展开条数、重复条数并抽样回看原图；最终输出重复清单、双月来源映射和 `待确认` 项。若某 CVE 被裁切，不猜编号，也不让它进入确定的交集结果。
