# 抖音生活服务商家对比分析报告
为抖音生活服务商家生成行业对比经营报告。目标是把对比数据整理成"结果 - 拆解 - 归因 - 动作"的结构化分析，明确差距、机会和优先行动。
## 不适用场景
- 需要全量经营体检 → 转 `local-life-service-business-report`
- 用户上传 Excel/CSV 等附件做离线数据分析 → 转通用数据分析能力
- 仅需热点选题/内容建议 → 转 `local-life-service-hot-find`
## 交付形式
支持两种交付形式。
| 形式 | 适用场景 | 特点 |
|---|---|---|
| 飞书文档版 | 需要详细文字解读、可打印存档、多人协作批注 | 7 大模块完整文字报告，区分事实/推断/建议 |
| 精美网页版 | 需要直观可视化、交互体验好、对外展示演示 | 自然周维度，生意经风格 UI，图表丰富 |
默认优先按用户要求的形式输出；未明确时，沿用模板化的文档口径组织内容。
## 使用原则
- 先结论，后证据。
- 严格区分事实、推断、建议。
- 行业数据按指数化、区间化或加权结果理解，不把它写成真实经营数值。
- 建议必须绑定验收指标，避免空泛表述。
- 聚焦 2 到 3 个最关键的差距，不堆满全部指标。
## 工具映射
- 浏览器（`open_url_in_browser` / `click` / `type` / `take_screenshot`）：生意经页面只读采集
- `interaction.request_action`：登录/验证码/商家切换等人机交互
- `lark-doc`：飞书文档版交付
- `CanvasCreateFile`：精美网页版 HTML 上屏
- `present_files`：额外附件交付
## 工作流程
### 第一步：确认账号与对比需求
1. 询问商家来客账号，若用户已提供则跳过。
2. **对比周期固定为自然周（本周一至昨日）**，不提供其他周期选项，无需询问商户。报告和网页版均只展示自然周数据。
3. 确认对比商家选择方式：
   - 相似商家：与本商家经营品类、规模较接近的商家
   - 标杆商家：平台推荐的表现较好的参考商家
   - 关注商家：商家已关注的行业商家
   - 指定商家：用户指定的具体品牌/店名
4. 确认是否有特定关注维度：流量、商品或全部。
5. 确认交付形式：飞书文档版或精美网页版。
6. 提醒用户：行业数据经过指数化/区间化处理，不代表真实数值，仅供相对对比参考。
### 第二步：浏览器登录与数据采集
从生意经平台采集行业对比数据，优先以页面真实可见内容为准，不编造。
- PC 端入口：`https://www.life-data.cn/industry/rank`
- 入口路径：生意经 -> 行业竞争 -> 行业对比
- URL 中的 `groupid` 参数根据商家账号动态获取，登录后从页面 URL 或账号切换器中提取
**登录态校验**：打开页面后先确认当前登录商家身份与目标一致；若未登录或登录态未接续，使用 `interaction.request_action` 请用户完成登录后再继续。
采集维度：
- 自然周（本周一至昨日，固定唯一周期）
采集内容：
- 核心指数对比：成交指数、核销指数、流量指数、转化指数，以及趋势曲线数据
- 流量分析：流量来源对比、流量体裁对比，分别按成交和曝光记录
- 商品分析：在售商品数、商品曝光人数、访问-成交转化率、热销商品 Top5
- 人群分析：人群总资产、各层级人群数量；若行业数据不展示，仅采集本商家
- 额度与授权：今日剩余对比次数、本周剩余对比次数、授权状态
- 排名信息：本商家及对比商家的品类排名、门店数、品牌名称
### 第三步：经营解读与分析
按"结果 - 拆解 - 归因 - 动作"展开。
1. 整体定位：四大核心指数综合表现、最核心优势、最核心差距、整体经营水位一句话结论。
2. 维度拆解：流量、商品、人群分别解读，先写事实，再写推断。
3. 差距归因：把优势、差距、机会按优先级排序，差距最多保留 3 到 5 个。
4. 行动建议：聚焦 3 个最优先动作，每条写清问题、动作、效果、验收指标、周期。
### 第四步：生成报告
#### 飞书文档版
- 严格按 `references/report-template.md` 的结构输出。
- 结构保持 7 大模块：核心结论、经营结果解读、流量结构解读、商品表现解读、人群资产解读、差距与机会、行动计划。
- 文案要区分事实、推断、建议。
- 使用 `lark-doc` 创建并交付飞书文档。
#### 精美网页版
- 采用统一生意经风格，视觉规范遵循 `references/design-system.md`，页面结构按 `references/web-ui-spec.md` 实现。
- 顶部吸顶导航包含 7 个模块锚点，移动端变为可横向滚动标签栏。
- 数据维度固定为自然周，**不提供时间切换组件**。
- 页面结构紧凑，数据密度接近生意经平台，各模块用主题色区分。
- **必须移动端适配**：<768px 单列堆叠、KPI 2列、表格横向滚动、字体间距自适应。
- **单文件自包含**：所有CSS内联，无外部字体/JS依赖，可直接转发他人打开。
- 使用 `CanvasCreateFile` 创建 HTML 并上屏，交付前完成渲染验证（DOM结构、资源加载、首屏/中段、移动端、控制台无阻塞错误）。
## 采集与分析规则
- 对比周期固定为自然周，不支持自然日或自然月。仅采集自然周维度数据，不采集多周期。
- PC 端最多同时对比 2 个商家。
- 任何页面未展示的指标都标注"暂未获取"。
- 人群数据若对比商家不展示，只分析本商家，不强行对比。
- 行动建议最多 3 条，最多不超过 5 条。
- 每条建议都要写清：针对问题、具体动作、预期效果、验收指标、建议周期。
- 行业数据是指数化/区间化结果，不要写成真实绝对值。
- 连锁商家按总账户聚合维度理解，非单店数据。
- 换绑或新增门店后，历史对比记录不保留。
## 结果写法
### 1. 核心结论
- 开头先给整体经营定位，再给优势、差距和优先动作。
- 只保留 2 到 3 个最关键发现。
### 2. 经营结果解读
- 看成交、核销、流量、转化四大核心指数。
- 结合趋势判断差距是在扩大还是缩小。
### 3. 流量结构解读
- 从流量来源和流量体裁两个角度判断问题。
- 重点判断是流量规模问题还是结构问题。
### 4. 商品表现解读
- 按供给 -> 曝光 -> 转化判断短板。
- 热销商品对比重点看商品结构、价格带和套餐设计。
### 5. 人群资产解读
- 行业人群数据若不展示，只写本商家的人群层级结构。
- 不强行对比无法获取的行业人群数据。
### 6. 差距与机会
- 优势项不超过 3 项。
- 差距项按 P0 / P1 / P2 排序。
- 机会点按投入产出比优先排序。
### 7. 行动计划
- 每条行动都必须可执行、可验证。
- 避免"加强直播""多发视频"这类空话。
## 数据安全与留存
- 只记录报告必需的对比指标字段，不保留完整页面HTML或原始DOM
- 临时截图和数据文件在报告交付后清理
- 行业数据仅用于本次对比分析，不用于其他用途
- 日志中不出现商家groupid、门店ID等敏感业务标识
## 特殊约束
- 行业数据经过加权、指数化或区间化处理，不代表真实经营数值。
- 对比周期固定为自然周，不支持其他周期。
- 日额度每日 0 点重置，周额度每周一 0 点重置。
- 授权关闭后无法继续使用行业对比功能，且恢复存在限制。
- 网页版商品图片优先使用真实图片；无法获取时再使用按品类生成的占位图。
- 抖音生活服务表述应使用"直播/短视频运营能力"，不要写成电商话术。
## 交付选择
- 用户要求"飞书文档""文字版""可存档"时，按模板生成文档版。
- 用户要求"网页版""可视化""展示效果"时，按网页版结构生成。
- 默认优先采用用户明确要求的形式；未指定时按模板里的默认口径处理。
- 通过本 Skill 向商家展示生活服务相关的实际数据或产物时（如经营数据、分析报告、生成的文案或方案），须在该次回复正文末尾另起一行，以普通文本展示以下固定提示，不加粗：以上内容由 AI 生成，仅供参考，请结合实际情况谨慎甄别。仅用于需求澄清、信息补充、门店选择、授权确认、进度告知或无结果／失败说明，且未包含实际数据或产物的回复，无需展示。同一条回复交付多项数据或产物时，统一展示一次。提示文案须原样保留并直接可见，不得仅置于折叠区域或工具返回中。
