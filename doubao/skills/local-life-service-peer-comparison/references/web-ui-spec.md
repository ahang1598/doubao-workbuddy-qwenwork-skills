## 一、整体风格
- 统一遵循 [design-system.md](design-system.md) 视觉规范。
- 主色调：生意经蓝色系 `#165DFF`
- 背景色：浅灰蓝 `#F5F7FA`
- 卡片：白色背景 `#FFFFFF`，圆角 `12px`，轻阴影 `0 2px 12px rgba(0,0,0,0.06)`
- 字体：系统字体优先（`'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', -apple-system, BlinkMacSystemFont, 'Helvetica Neue', sans-serif`），不依赖外部CDN
- 商家配色：
  - 本商家蓝 `#165DFF`
  - 对比商家 1 青绿 `#0FC6C2`
  - 对比商家 2 紫 `#722ED1`
- 各模块可用主题色区分：经营结果蓝、流量紫、商品青、人群橙、差距红、行动绿
- 单文件HTML，内联CSS，可直接转发他人在浏览器中打开

## 二、页面结构
- 顶部吸顶导航栏：7 个模块锚点
- 周期显示：顶部右侧展示当前自然周区间（本周一 ~ 昨日），**不可切换**
- 正文：7 大模块纵向排列，滚动时导航高亮对应模块

## 三、模块设计
### 1. 封面/头部信息区
- 商家名称、门店数、排名
- 对比商家列表，每家一个卡片，含品牌名、门店数、排名
- 自然周周期显示
- 额度信息提示

### 2. 核心指标对比模块
- 左右布局，各占 50% 宽度
- 左侧：菱形四维雷达图，流量上、成交左、核销下、转化右
- 右侧：趋势折线图，顶部下拉切换成交指数 / 核销指数 / 流量指数 / 转化指数
- 图例：本商家、对比商家 1、对比商家 2
- 雷达图空心样式，只保留线条和数据点

### 3. 流量对比模块
- 子 Tab：按成交 / 按曝光
- 左右布局：左侧流量来源，右侧流量体裁
- 横向堆叠条形图，每行一个商家
- 商家名称在左侧，条形图在右侧
- 百分比数字直接标在色块上
- hover 显示 tooltip

### 4. 商品对比模块
- 上半部分：核心指标对比表格，三列为本商家 / 较对比商家 1 / 较对比商家 2
- 指标包含：全部商品数、商品曝光人数、访问-成交转化率
- 胜/平/败标签使用绿色/灰色/红色圆角标签
- 下半部分：热销商品成交金额
- 三列布局，每列一个商家
- 每行包含：
  - 排名角标，1/2/3/4/5，方形圆角数字徽章
  - 商品图片，44px 正方形，带圆角
  - 商品名称，12px 字号，单行省略
  - 价格，右对齐，主色突出
  - 原价，划线灰字
  - 胜/败标签
- 行高 36px，紧凑布局

### 5. 人群对比模块
- 横向条形图展示各层级人群占比
- 四层级数字卡片：L1 潜在 / L2 新客 / L3 活跃 / L4 沉默
- 同行人群数据可能不展示，仅展示本商家数据
- 底部小字说明数据更新时间

### 6. 差距与机会模块
- 三列卡片矩阵布局
- 优势项：绿色主题，列 2 到 3 个核心优势
- 差距项：红橙主题，按 P0 / P1 / P2 列出
- 机会点：蓝色主题，列 2 到 3 个优化方向
- 每个卡片包含标题、简要说明、相关数据

### 7. 行动计划建议模块
- 三大行动卡片，P0 / P1 / P2 优先级标签
- 每个卡片包含：
  - 优先级标签
  - 行动标题
  - 问题描述
  - 具体动作
  - 预期效果
  - 验收指标

## 四、交互规范
- 导航锚点点击后滚动到对应模块，滚动时自动高亮当前模块。
- 所有图表支持 hover 显示详细数据（桌面端）；移动端通过点击或直接展示关键数据。
- **响应式布局**：
  - 桌面端（≥768px）：多列布局、左右分栏、表格完整展示。
  - 平板/手机端（<768px）：单列堆叠，KPI卡片2列，表格外层 `overflow-x: auto` 允许横向滑动，导航栏变为可横向滚动的标签栏。
  - 字体、间距按 design-system.md 响应式规范自适应缩小。
- 图表通过 key 触发重新渲染，过渡平滑。
- 不依赖 JavaScript 渲染核心内容；如有 tab 切换等交互，优先用 CSS `:target` 或 `<details>` 实现。

## 五、移动端适配要求
1. **导航栏**：顶部吸顶导航在移动端变为可横向滚动的标签栏，不换行，每个标签最小宽度适配文字。
2. **核心指标对比**：雷达图和趋势图在移动端上下堆叠（不再左右分栏），图表高度适当缩小但保持可读。
3. **流量对比**：左右分栏改为上下堆叠，条形图标签宽度缩小。
4. **商品对比**：三列布局改为单列或可横向滑动的卡片，商品图片和文字保持清晰。
5. **人群对比**：横向条形图保持，四层级数字卡片在移动端改为2列网格。
6. **差距与机会**：三列卡片矩阵改为单列堆叠。
7. **行动计划**：保持单列，行动卡片内边距缩小。
8. **表格**：所有数据表格外层包裹 `overflow-x: auto`，设置 `min-width` 确保内容不被压缩。
9. **字体**：页面标题降到 20px，模块标题 16px，核心数据 20-24px，正文保持 14px。
10. **可分享性**：单文件自包含，所有CSS内联，无外部字体/JS依赖，可直接转发他人打开。

## 六、数据层设计
- 统一数据结构：`reportData`
- 仅包含自然周单周期数据，不存储多周期
- 所有子组件共享同一份自然周数据
- 数据格式与飞书文档版保持一致，确保两种交付形式数据同源

## 七、注意事项
- 视觉规范统一遵循 [design-system.md](design-system.md)，颜色/字体/间距/组件不得擅自偏离。
- 同行数据必须来源于真实页面可见数据，不用比例缩放估算。
- 商品图片优先真实图片；无法获取时按品类生成精致占位图。
- 数据密度要接近生意经平台，避免做得太松散。
- 抖音生活服务应写"直播/短视频运营能力"，不要写成"内容电商"。
- 排名角标使用方形圆角数字徽章（遵循 design-system.md 排名徽章规范）。
- 胜败标签使用绿色/红色圆角标签。
- 固定自然周维度，不提供时间切换入口。
- 必须移动端适配：<768px 单列堆叠、表格横向滚动、导航横向滚动标签栏。
- 单文件自包含，可直接转发他人打开。
