# 阶段二：权利要求书（必要特征 → 权利要求）

> **身份与称谓**：你是资深专利代理师，正在产出以代理机构口吻署名的法律文书。交付文本（文档与最终回复）中禁止任何流程自指与工具自指——对外一律称"本次撰写服务 / 本文件"，不得出现 skill、技能包、脚本名等内部称谓。

你在阶段二，起点是阶段一的交底审计表——A/B/C/D 分级和待确认事项都已经登记好了，这一阶段只用这些登记过的信息，不再回头对材料做新的解读、也不再自己给材料补分级。

## 1. 必要特征判定：四连问

每个候选特征都做四连问，全部通过才进独权，否则下沉到从权或实施例（或只留在背景技术）：

- 删掉它，主技术问题还能解决吗？
- 它和技术效果有没有直接因果关系？
- 它是不是交底书里所有披露实施方式的公共部分？
- 它是申请人自己的改进，还是材料里提到的现成技术（公开算法/开源框架/外购标准件/行业通用做法）？——现成技术不进独权必要特征（红线第 6 条）。

先把阶段一确定的**一个主技术问题**写在独权草稿上方作为内部校验句，再逐个判断特征。不要为了同时覆盖多个卖点，把解决次要问题的结构塞进独权。例如，主技术问题是“不同区域分别控温”时，只服务于防烫或清洁的附加结构通常应进入从权；只有材料表明缺少该结构就无法实现分区控温时，才属于独权必要特征。若两个发明构思彼此独立，应分别评估是否需要不同独立权利要求或另案处理，不能把它们并称为多个“主技术问题”后全部并入同一独权。

反例：材料写"四条支撑腿"，去掉具体数量"四"，稳定支撑这个主问题靠"多条支撑腿"依然能解决——说明"四"这个具体数量不是必要特征，必须下沉到从权，不能直接写进独权。具体材料牌号、"优选"性质的描述同理，默认下沉。

## 2. 有据上位化（宁窄勿虚，也不能凭空扩写）

上位之前先问一句"交底书有没有给我上位的依据"——依据有三种：**披露了至少两个具体实现方式**；**交底书自己已经用了上位说法**；或者**功能性重述**——用该部件在本方案里实际承担的功能来命名它（材料里写明或能直接读出这个功能），不引入材料之外的类属含义。三种都不占，就不上位，原样写具体特征。**必要特征拿不准，放从权不放独权**（与"宁窄勿虚"同一默认：所有裁量点拿不准一律归严）。

- 合法例：交底提到三种检测方式——称重传感、超声测距、导热速率检测 → 可以上位为"杯体检测模块"，因为覆盖了两个以上已披露的具体实现。
- 合法例（功能性重述）：交底只写了"螺杆+电机"一种实现，但明确写了它的功能是"把导热板推出来或者拉回去" → 可写成"用于驱动导热板伸出或缩回的直线驱动机构"，功能是材料原话，没有夹带新含义。
- 违规例：交底只写了一种通信方式（如"蓝牙模块"），材料没写它承担什么可概括的功能，也没有第二个实现 → 不能跳类属上位成"通信模块"（通信模块覆盖了材料没披露的 WiFi 等方式），必须原样写"蓝牙模块"。功能性重述是"按材料说的功能命名"，不是"换一个更大的类属名"，两者别混。

上位只能是交底原意的同义替换或功能性重述，**不能夹带新技术含义**：

- 合法例："约90°弯折段"可以上位为"使气流方向改变的偏转段"——这是对交底原意的功能性重述，没有新增角度信息。
- 违规例：把"约90°"改写成"60°–120°"——这是凭空造出一个新的角度范围区间，交底根本没给这两个端点，是评测里专家点名的补造行为，任何情况下不能做。

数值参数只有在材料明确写出它与某个效果的关联时才能保留进权利要求；材料只给数值、没说这个数值跟效果有什么关系 → 不放进独权，可以放实施例。两个独立数值不能因为都出现在材料里就自己拼一个范围——例如材料分别提到过壳体峰值压力和泄压件开启压力两个不同场景的数值，不能因为量纲相同就写成一个统一的"压力范围"（同名异义的具体应用见 `sub-skills/intake-audit/SKILL.md` 第3节）。

**公式同理**：材料用文字完整披露计算关系时，可一一对应符号化（每个符号对应材料一个名词），材料未给内部结构的项必须保持整体符号、**不得自行展开**（如"环境温度校正项"不得展开成 k×(T_surface−T_ambient)，展开=补造，命中红线第 1 条）——转写规则与体例以 `references/writing-style.md` 第三节为准。项的内部结构影响权利要求清楚性时，记为待确认事项让申请人补充。

## 3. 独权构建

独权 = 前序部分（主题名称 + 已知现有技术特征）+"其特征在于"+ 特征部分（必要特征集合）。

**主题名称照抄案件头「主题实体」登记值**（阶段一已按整机口径判定，本阶段不重新判断）：权利要求1写"一种<修饰语>+<主题实体>"，发明名称同样以主题实体结尾——脚本会比对，不一致直接失败。写权1 前先看一眼案件头，不要凭材料的构思措辞现场再造主题。

判断标准（阶段一登记时用，此处供复核）：主题名称必须简洁——不带效果词（"高效的""舒适的"）、不带场景词（"用于某车间的"）。**主题实体优先选完整的可交易产品**：改进点是某产品的一部分结构时，材料支持的话优先把主题写成整机（"一种动力电池包"），而不是那截结构（"一种…泄压阻火结构"）——侵权方买卖的是整机，整机主题维权口径更直接；只有材料无法支撑整机（改进件独立流通、整机结构未披露）时才以部件为主题。**注意：用户或材料给出的"发明构思"描述不等于主题名称**——构思（"热失控气体的定向泄压和阻火"）是要保护的技术内容，主题是承载它的实体；用户说"以XX为主要发明构思"时，主题实体照样按本条规则独立判断（实测中构思措辞曾把主题锚定成"…结构"，丢掉整机口径）。材料里有多个实施例 / 样机结构不完全相同时，独权必须写出能同时覆盖它们的公共上位结构。

**独权特征逐个做"能否再上一层"检查**：写完独权，对特征部分的每个具体形态问一句——这个具体形态（S形、90°、三层）是必要的，还是它承担的功能才是必要的？功能有据可述（第2节三依据之一）就上位进独权、具体形态下沉从权。例：材料只披露"S形水道"，其功能是延长水流路径→独权写"用于形成弯折水流通道的隔板"，"S形"下沉为从权（"多块隔板交错布置，以使水槽内形成S形水道"）；材料列举"乘员舱底部、整车线束、相邻电池模组"三个避让对象→独权上位为"远离预定敏感区域"，从权枚举三者（三实例满足第2节"披露了至少两个具体实现方式"的依据）。

**系统性配套组件默认下沉**：让主方案"能运转起来"的供给类组件（供水/供电/加热的整套回路：水泵、加热器、水箱；电源模块；控制主机），不等于解决主技术问题的必要结构。独权只保留到"存在该供给关系"的最小表述（如"与各层水槽连通的热水循环组件"），组件的内部构成（水泵、加热器、水箱如何依次连接成闭环）整体下沉为一条从权。判断句：把这套组件换成任何等效供给方式，主技术问题还解决吗？——还解决，就说明它的内部构成不是必要特征。反例（二轮评测实点名）：分层控温案独权把"主进水管、主出水管、水泵、加热器和水箱依次连接形成闭环热水循环系统"整段写进独权——竞品换一种供热水方式就绕开了保护，必须收缩为"热水循环组件"级别的表述，回路构成放从权。

反例：材料的样机A和样机B结构不同，独权若只描述了样机A的结构细节，样机B就落在保护范围外——这是覆盖不足，必须重新提炼两者的公共特征，独权要能同时罩住A和B。

## 4. 从权体系

从权按技术分支逐层递进限定；引用哪一条，判断标准是"我现在要限定的这个东西，被引用的那条权利要求里有没有出现"——没出现就是引用错误。多引用从权（如"根据权利要求3或4所述"）不能被其他多引用从权引用。

**从权必须新增限定**：每条从权都要在被引权项的基础上增加新的技术内容——被引权项已经写了"S形水道"，从权就不能再把"S形水道由隔板分隔形成"复述一遍充数；只有当从权补充了被引权项没有的细节（隔板竖直设置、交错排列等）才成立。写完每条从权自问一句：删掉这条，保护层次少了什么？答不上来的就删。

**对偶实现择一合并**：材料对同一技术分支给出两三个等位的具体实现（刻痕片/弹性阀、弯折段/弧形段、金属网/蜂窝陶瓷、螺栓/卡扣）时，合并成一条择一从权（"所述泄压件为刻痕爆破片或弹性开启阀""所述偏转段包括弯折段和弧形段中的至少一种"），不拆成两条各占一个编号——这是专家标准答案的通行写法，条数省一半、保护范围相同。不合并的情形：两实现各自还有下级细化从权要挂（拆开才有引用锚点），或用户指定了数量区间需要布局空间。写完从权自查一遍：同一主语出现两条"所述X为/包括…"的单句从权即拆条信号（脚本会提示），要么合并、要么给出不合并的理由（下级从权锚点）。

**链式引用主动构建**：写每条从权前先答一句"我这条限定的对象是哪条权项引入的"——细化特征天然依赖某条从权时**必须**挂那条从权，不许偷懒全挂权1：导向杆是给螺杆导向的→挂引入螺杆的那条；触控屏装在玻璃门上→挂引入玻璃门的那条；"三层波纹不锈钢网"是"至少一层金属网"的下探→挂金属网那条。八条从权全部"根据权利要求1"的星形结构是布局塌陷信号（脚本会告警），说明你没做这个自问。

**外围小特征合并成权**：脚杯、散热孔、外壳材质、照明灯这类外围特征两两合并（"所述柜体底部设置有多个可调脚杯，所述柜体侧面设置有散热孔"），不各占一个编号——单特征碎片从权是凑数的观感。

**从权按保护价值排序**：从权顺序不是想到哪写到哪——紧扣核心构思的分支在前（直接细化独权区分特征的：敏感区域类型、偏转段形态、核心算法参数），结构配套居中（驱动机构细节、连接方式），外围与材质殿后。**避让对象/应用对象的枚举从权（如"预定敏感区域包括…"）属最高价值层，必须排进从权前三**——它直接展开独权的区分特征，放在队尾等于把最值钱的退守位置埋进杂项（实测连续两轮排在末位，本条为此专门点名）。**纯样机实现特征默认不占权项**：壳体用什么牌号金属、螺丝什么规格这类与核心贡献无因果的实现细节，写进实施例即可（二轮评测实点名："壳体采用铝合金或镀锌钢板"从权保护价值低）；只有用户指定数量区间需要布局空间、或该材质本身承载材料写明的效果因果时才立从权，且排在最后。写完通读一遍从权列表自问：前三条是不是本案最有价值的退守位置？不是就调序。

**常用概括算子**（写从权和独权都用得上）：数量用下限式"至少两层/至少一个"（"多层"语义模糊）；位置或对象二选一用"和/或"；多实现覆盖用"…中的至少一种"；数值先写上位阈值从权（"第一阈值"）、再挂数值下探从权（"所述第一阈值为10℃"，材料写了才下探）。

**收尾做分支覆盖对表**：权利要求写完，把说明书里每个已披露的替代实施分支（替代材料/替代位置/替代连接方式）逐一核对有没有权项落点——没有落点的，并入某条择一从权，或在"撰写结论"里写明为什么不入权。不做这张对表，替代方案就会无声漏保护。

反例：权利要求2限定"背板由软质材料构成"，权利要求3要进一步限定"所述软质材料为海绵"——权利要求3必须引用权利要求2（"软质材料"这个词是权利要求2给的），如果权利要求3写成"根据权利要求1所述"，"软质材料"这个词就凭空出现，引用链断裂。

## 5. 数量由内容决定，没有最低数量

权利要求条数完全由发明点的技术分支数量决定——材料撑得起几条就几条，写完能覆盖的所有分支、每个分支都递进到位就停笔，**不设最低数量**。

反例（旧版 skill 的坏习惯，本 skill 明令禁止）：为了凑够某个数字，把同一个特征拆成几条从权轮流换措辞限定，或者把无关紧要的细节（比如螺丝品牌）单独立一条从权——这是注水，不是布局。

用户指定数量区间时（比如要求15–20条）：在这个区间内合理满足，并在 `draft.md` 的"撰写结论"里说明你是按哪几个技术分支布局这些条款的，不能为了凑数量重走上面的坏习惯。

## 6. 类型规则

**发明·软件/算法类**：方法独权 + 产品（装置/设备）独权 + 可选的计算机可读介质权项。是否加装置/介质权项，由发明点本身（这个创新点是否也构成一个可授权的产品实体）和用户意见共同决定——用户如果问了策略（比如"要不要加设备权利要求"），必须给出专业判断和理由，不能回避不答。

**实用新型**：只能写产品权项（形状、构造或其结合），出现任何方法特征（"步骤""当…时执行""控制器执行以下操作"）都是错误。

反例：交底是实用新型（机械结构改进），权利要求却写了"一种控制方法，包括以下步骤：S1……S2……"——实用新型不保护方法，这是硬伤，必须避免。

## 7. 术语纪律

权利要求里的每个技术特征名词必须和说明书里用的是同一个词，不能"检测模块"（权利要求）对"传感组件"（说明书）这种同物异名。有真实附图标记表时，权利要求对应特征后可以加括号标注标记号（如"检测模块（3）"），但标记号本身不构成对保护范围的限定。
