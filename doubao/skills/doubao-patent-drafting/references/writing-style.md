# 撰写语言规范

本文件是 `claims` 和 `specification` 两个阶段撰写正文时的查阅表：落笔前查"措辞分寸表"，落笔后对一遍"套话黑名单"。三张表都不是背景知识，是可以直接照着执行的检查清单。

## 一、套话黑名单（按类别判定，同义改写视同命中）

**判定以类别为准，不以字面为准**：每一条是一个套话类别，例句只是已知样本、不是穷尽清单——凡表达同一意思的任何措辞都属于该类，换几个词重写一遍照样命中。脚本 C7 的精确短语和句式正则只是兜底安全网（拦已知逃逸样本），你写作时按各条的"判定问句"自查。命中任何一条，按"替换出口"改写成贴合本案技术内容的表述，不能靠删掉几个字敷衍过去。

**反向护栏（防过矫）**："其特征在于""根据权利要求N所述"等法定固定句式必须逐字保留，它们不是套话，是格式要求。

1. **模板过渡句类**。判定：这句话换到任何别的专利里是不是照样通顺？例："有鉴于此，提出本申请"及其变体。替换出口：背景技术结尾直接指出现有技术缺什么，发明内容开头直接说本方案给什么——内容衔接，不用桥句。
2. **示例性实施例模板前言类**（旧版 skill 的产物）。判定：这一段是不是在解释"实施例是什么"而不是"本案实施例做了什么"？例："这里将详细地对示例性实施例进行说明，其示例表示在附图中……"。替换出口：删除整段，直接进入第一个实施例的技术内容。
3. **术语免责整段类**。判定：是不是用一整段解释"术语不限定本申请"？例："在本申请使用的术语是仅仅出于描述特定实施例的目的……"整段（旧版 skill 产物，命中即改）。**校准（以专家标准答案为准）**：一句式行规免责句（"应当理解，以下实施方式仅用于说明本申请，并不用于限定保护范围"）是行业惯例，**允许保留**（脚本 C7 只 WARN 提示）；被禁的是整段展开的术语免责。
4. **空转承接句类**。判定：删掉这句，上下文是否毫无损失？例："为了更好地理解上述技术方案，下面将结合具体的实施方式……"。替换出口：删除，直接进入实施方式正文。
5. **固定开头复读类**。判定：同一引导句式是否第 3 次出现？例："在具体实施过程中"逐段开头（全文最多 2 次，脚本同阈值告警）。替换出口：换成呼应该段具体内容的句式。
6. **空洞效果罗列类**。判定：效果词后面有没有挂具体技术特征？例："综上所述，本申请具有以下有益效果：效率高、成本低、易维护"。不是句式本身违规，是"句式+空洞列举"组合违规。替换出口："因为……（具体特征），所以……（具体效果）"因果句，逐条挂特征。
7. **收尾段默认不写（二轮专家评测校准：保护范围由权利要求书确定，说明书只负责充分公开）**。"均应落入保护范围"式收尾被专家评为套话——写完发明点该展开的内容就收笔，默认不写任何收尾段。若申请人模板确实要求保留，只允许实质性范围说明——点名本案核心特征的变体声明，如"各结构的具体尺寸、层数均可调整，只要其采用（多层独立腔室+水浴循环+导热板推出结构），均应落入本申请的保护范围"（句中必须出现本案具体特征名）；收尾行规免责句"以上所述仅为……较佳实施例……"及"凡在……精神和原则之内……"等同替换段**禁止**（脚本 C7 FAIL 阻断；开场式的"以下实施方式仅用于说明……"一句仍属行业惯例 WARN 级）；旧版整段免责模板"上面结合附图对本申请的实施例进行了描述，但是本申请并不局限于……"任何情况下禁止（精确命中 FAIL）。
8. **空洞开篇铺垫类**。判定：开篇句里有没有具体的现有技术或技术问题？例："随着……技术的不断发展/日益广泛应用"。替换出口：背景技术第一句就写具体的现有技术方案及其缺陷。

**压缩原则（管住词表外的未知变体）**：正文里每句话要么承载技术信息、要么划定保护边界，两者皆无即删——判定不了某句是不是套话时，用这条原则裁决。

## 二、措辞分寸表：事实分级 → 动词选择

事实分级的定义见 `sub-skills/intake-audit/SKILL.md` 第2节，这里只管分级之后该怎么落笔：

| 事实级别 | 可以用 | 不能用 | 例句 |
|---|---|---|---|
| A 实测事实（材料有测试数据） | 经测试、实测数据显示、使…从X降至Y、达到、实现 | 彻底、完全、100%、杜绝、永久、从根本上解决（除非材料原文、测试数据与测试范围共同支持） | "经测试，在材料记载的工况下，火焰长度由15cm降至2cm" |
| B 披露方案（材料写了方案，未附测试） | 能够、有利于、可以、有助于、便于；材料披露的数值带"设计目标为/预期可达"定位词照写 | 已实现、经验证、显著提升、明显优于、优于传统方案、从根本上解决；以实测或断言口吻写数值 | "设计目标为±1℃，该结构有利于降低装配难度" |
| C 预期设想（材料自认未验证） | 预计、设计预期、作为替代实施方式、理论上、尚待验证 | 能够、已实现、经测试、彻底 | "作为替代实施方式，某材料预计具备更优吸热性能，其效果尚待验证" |
| D 缺失待确认 | 不写入正文，用"（具体数值待申请人确认，见待确认事项N）"占位 | 任何编造的具体数值 | — |

判断标准只有一条：**这句话里的动词，会不会让读者以为这件事已经被证明了？** 会，就要看这条事实是不是真的到了A级；不是，就换成对应级别的词。

如果审阅说明中仍有“测试状态待确认”“仅为设计目标”“尚未验证”等事项，说明书摘要、发明内容、有益效果和撰写结论中不得出现“明显优于”“优于传统方案”“从根本上解决”“有效解决”等已经形成比较结论的措辞。不能一边提示申请人数据未确认，一边在正文中给出确定结论。

**技术机理同理（二轮评测实点名）**：材料只说了"怎么做"、没解释"为什么有效"时，机理解释（削弱冲击动能、延长流动路径、增加散热时间这类原理性说明）不得以确定语气自行补写——工程上再合理也是推断，交底未记载就不是事实。要么不写机理、只写结构与材料记载的现象，要么用"可以认为 / 推测其原因在于"引出；机理有交底原文或实测数据支撑时才能平铺直叙。

**拿不准归严（所有裁量点的统一默认，不解释、不留"视情况"）**：事实级别拿不准，按低一级用词；某句是不是套话拿不准，按套话改写；措辞与术语二选一拿不准，选交底书原词。

## 三、公式与符号

**文字计算关系的符号化转写（以专家标准答案为准的校准规则）**：材料用文字完整披露了计算关系（每一项都有名字）时，**可以一一对应地符号化**——每个符号对应材料的一个名词、不多不少，如"估算温度=表面温度+功率×热阻−环境温度校正项"可转写为 `T_liquid = T_surface + P × R − ΔT_correction`，并按下方体例先列符号表。**唯一禁区是展开材料未给出内部结构的项**："环境温度校正项"材料没说怎么算，就保持 ΔT_correction 整体符号，**不得**自行展开成 k×(T_surface−T_ambient)——展开=补造公式结构，命中红线第 1 条。判定问句：这个符号背后的结构，材料写了吗？写了才能拆，没写就整体保留。

以下体例在写出任何符号公式时执行：

1. **符号表先行**：正文出现第一个公式之前，先列符号表——每个符号给出含义、下标含义（如 i=任务、j=节点）、量纲或取值范围；公式和实施例里用到的每个符号都必须在表中出现。
2. **维度写下标不写上标**：类型/维度标签（cpu、mem、peak 等）写成下标 `b_{i,cpu}`；禁止 `b_i^{cpu}`（会被读成幂次）。上标只用于幂次、转置、序号。
3. **禁止同一字母多义**：任务侧用了 b，节点侧就换 g/h，不许一个字母在不同对象上表示不同物理量。
4. **全文体例统一**：行内/块级公式分隔符全文各选一种不混用；公式编号（式(1)）与正文引用格式全文一致；块级公式尽量单行。
5. **跨节逐字同形**：符号表、正文公式、参数表、实施例四处的同一符号必须逐字一致——改任何一处就同步核对其余三处。
6. **不等式方向与文字互推**：公式里的 ≤/≥/正负号必须与文字含义一致（"有余量"对应哪个方向要能对上）；边界情形（分母为零、空集合、达到上下界）至少不与主公式矛盾。
7. **符号不得先用后定义**：公式或运算表达式中出现的每个变量，都要在符号表中有同形定义；`T_liquid`、`Tliquid`、`T_liquid ` 视为不同写法，不能混用。控制目标 `Tset` 等在后文新增的变量也必须补入符号表。

## 四、高频错误对照表（落笔后快速扫一遍）

| 场景 | ❌ 错误写法 | ✅ 正确写法 |
|---|---|---|
| 权项句号 | 一条权项里出现两个句号，或以逗号结尾 | 每条恰好一个中文句号，且在末尾 |
| 权项间排版 | 权项之间空一行 | 紧密相邻不留空行 |
| 从权引用 | 权3 限定"所述软质材料"却引用权1（软质材料是权2 引入的） | 引用引入该词的那条（权2） |
| 从权内容 | 复述被引权项已有的特征充数 | 每条从权新增限定 |
| 上位化 | "约90°"扩成"60°–120°"（材料没有的范围） | 保留"约90°"，或功能性重述"使气流方向改变的偏转段" |
| 类属跳跃 | 材料只有蓝牙 → 写"通信模块" | 原样写"蓝牙模块"（无第二实现且无功能概括依据时） |
| 效果措辞（B级） | "经测试，该结构能将压力降低50%"（材料没测过）；或干脆删掉50%虚化成"降低压力" | "该结构能够降低压力，设计目标为降低50%（尚待验证）"——换定位词，数值保留 |
| 效果措辞（C级） | 用确定语气写未验证方案的效果 | "作为替代实施方式…属于设计预期，尚待验证" |
| 公式转写 | 把"环境温度校正项"展开为 k×(T_s−T_a)（材料没给内部结构） | 一一符号化：T_liquid = T_surface + P×R − ΔT_correction（校正项保持整体符号） |
| 缺参数 | 顺手填一个常见值 | "（具体数值待申请人确认，见待确认事项N）" |
| 附图 | 无正式图却写"如图1所示" | 规划图名清单 + 声明"附图待申请人提供" |
| 对外称谓 | "本skill职责范围不包含检索"（实测原句） | "现有技术检索不在本次撰写服务范围内" |
| 摘要措辞 | 正文"能够提高"，摘要压缩成"显著提升" | 摘要动词与发明内容逐字同级（抄录压缩，不升格） |
| 对外确认事项 | `[P0] 数据待确认`、`A级事实` | `本次定稿前需要确认：请补充测试条件和原始数据` |

## 五、AI 腔治理要点（脚本拦不住，靠写作时自己控制）

- 不用"首先……其次……最后……"这类机械排比去组织本来没有顺序关系的并列内容，读起来像列提纲不像专业文书。
- "进一步地"是合法的递进引导词，但发明内容技术方案段连用超过 5 次就该换写法（"在一种实施方式中""作为可选结构""所述X还可以……"轮换），密度过高读起来像逐条翻译权利要求。
- 每个实施方式的效果论述要换角度呼应发明内容，不能逐段复读同一开头句式——不只是"在具体实施过程中"这一句，任何固定句式反复出现三次以上都要警惕。
- 效果不脱离特征单独罗列——"效率高、成本低、易维护"这种不挂技术特征的形容词堆砌，即使不在黑名单词句里，也是模板腔的典型表现，一律改写成"因为……（具体特征），所以……（具体效果）"的因果句式。
- 不为了显得完整而写填充式收尾段——写完发明点该展开的都展开了就收笔，没有内容支撑的总结段不写。
- 不自创未定义的术语；确需使用交底书没有的表述时，只能是同义替换或功能性重述，不能夹带新技术含义（见 `sub-skills/claims/SKILL.md` 第2节"有据上位化"）。
