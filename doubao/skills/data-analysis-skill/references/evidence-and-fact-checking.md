# 事实与证据检查清单

## 论文与材料

- 核对标题、作者、期刊、年份、卷期页码和 DOI 或稳定链接。
- 分别记录全文、代码、数据、说明文档和软件环境是否可获得。
- 记录访问日期和来源；搜索摘要只能用于发现候选，不单独支撑最终事实。
- 无法确认的数据规模、变量定义、模型设定或开放状态标记 `NOT_VERIFIED`。

## 运行证据

一次可审计运行至少保存：

1. 用例 ID 与输入说明。
2. 输入文件相对路径、大小和 SHA-256；敏感数据只保存经批准的摘要或脱敏校验信息。
3. 操作系统、软件版本、依赖锁定信息。
4. 完整执行命令与工作目录。
5. stdout、stderr、退出码和时间戳。
6. 输出文件相对路径、大小与校验值。
7. 预期、实际、容差、判定人和判定理由。

## 状态使用

| 状态 | 可陈述内容 | 不可陈述内容 |
|---|---|---|
| `SOURCE_VERIFIED` | 来源与书目信息已核验 | 代码可运行、结果一致 |
| `FILE_INSPECTED` | 文件存在且已读取 | 语法正确、运行成功 |
| `STATIC_CHECK_ONLY` | 结构或关键命令已检查 | 已在目标软件实跑 |
| `EXECUTED` | 命令已运行并有原始日志 | 与论文一致 |
| `RESULT_COMPARED` | 已按容差比较结果 | 超出已比较范围的结论 |
| `NOT_VERIFIED` | 当前证据不足 | 确定性判断 |

## 截图边界

截图可证明某个画面曾被展示，但通常不能证明输入来源、完整命令、退出码、运行环境和产物可复现。截图必须关联用例 ID 和原始运行记录；只有截图时，状态不得高于 `FILE_INSPECTED`，除非有其他独立证据支持。

## 独立证据与基线

Owner 证据存放在发布包外，避免把测试数据和运行痕迹上传为 Skill 内容。每个核心能力至少准备一个真实或合成用例，并使用同一输入进行 no-skill/原流程基线对比。统一记录：

- 完成时间与人工干预次数；
- 一次通过率和返工次数；
- 论文匹配准确性；
- 代码可运行性；
- 表图完整性与数值正确性；
- 失败原因和 badcase。

汇总只能由逐项原始记录复算，不用“全部通过”替代明细。
