# 性能证据闭环

> **何时读本文件**：任务超出单一已有 artifact 的轻量解释，需要走完整 BASELINE → SEMANTICS → MEASURE → VERDICT 闭环（定位机制、比较候选、建立守卫）时加载。

本文件展开从问题定义到工程决定的通用流程。它不提供某类题目的现成答案；每项结论都必须重新绑定当前 revision、workload、环境和 artifact。

各节与 SKILL.md 阶段的对应：一~三 → BASELINE；四 → SEMANTICS；五~七 → MEASURE；八~九 → VERDICT 与交付。

## 零、选择主模式

先选择一个主模式，只执行对该交付物适用的阶段门：

| 模式 | 目标 | 完成边界 |
| --- | --- | --- |
| `explain` | 解释已有 benchmark、profile、trace 或指标 | Artifact 有效性、含义、scope 与不能推出的结论已复核 |
| `establish-baseline` | 建立可重放测量 | Workload、环境、命令、原始样本和漂移检查闭合 |
| `diagnose` | 定位限制机制 | 运行证据命中机制，竞争解释由判别性观测裁决 |
| `optimize` | 验证并采用候选 | 完成 baseline/candidate 单变量 A/B、oracle、guards、复核和恢复 |
| `guard` | 建立回归守卫 | 指标、workload、oracle、门槛来源和失败动作闭合 |

模式可以在证据推动且用户范围允许时前进，但不得为了走完整流程虚构 candidate 或实施修改。只有 `optimize` 或用户明确要求比较已有 candidate 时，才要求 A/B、接受与恢复。

## 一、冻结问题

先把用户语言改写成可测问题，但保留原话：

| 字段 | 要求 |
| --- | --- |
| 目标路径 | 外部入口、内部边界与期望改善方向 |
| Revision | 明确的提交、构建或部署版本 |
| Workload | 调用序列、输入分布、状态、并发和故障条件 |
| 环境 | 硬件/配额、运行时、依赖、动态配置和缓存状态 |
| 指标 | 主指标、方向、单位、计时边界和聚合口径 |
| Oracle | 候选必须保持的外部行为 |
| Guards | 不能退化的资源、副作用和可靠性边界 |
| 门槛 | 用户目标、SLO、历史约束或实验前决定 |
| 权限 | 允许读取、采集、修改和访问的环境 |

处理未知项的规则：

1. 未知项标记为 `unknown`，不要填入惯用值。
2. 缺失项会改变实验含义时，先通过仓库与 artifact 查证。
3. 仍不可得时给出条件化实验，而不是假设一个「典型」环境。
4. 决定实验含义的字段（命令、环境、workload、计时/预热/重置、指标、oracle）必须是具体值。
5. 用 `UNKNOWN / NONE / N/A` 之类占位符冒充已冻结值时：停止比较，交付 `EVIDENCE_REQUIRED` 或条件化实验。

## 二、闭合真实路径

从测量入口沿真实调用、数据和状态流追到成本发生点，再回到用户可观察结果：

1. 确认运行时选择、注册、配置、feature gate 和依赖版本使目标实现真正生效。
2. 明确每次调用接收独立输入、累计输入、共享状态还是流式增量。
3. 记录 fast path、fallback、重试、缓存、批处理、并发和动态旁路。
4. 将成本绑定到具体操作：计算、分配、复制、序列化、锁等待、排队、I/O 或远端依赖。
5. 将局部成本连接到端到端指标，估计它能解释的上限，但不要把上限当成预期收益。

证据强度按来源区分，不得越级使用：

| 证据来源 | 只能证明 |
| --- | --- |
| 源码存在 | 可达候选 |
| 配置或注册 | 可能启用 |
| 运行 artifact | 观测 workload 真正命中了它 |

同名接口、相邻实现和测试替身分别取证。

### 真实路径缺失特征收口门

本节收口前走一道**否定式**检查：不是勾选「我已闭合路径」，而是逐条查你的**回答正文里是否出现**下列可观察缺失。出现任一项即判定路径未闭合、回炉补齐，不得靠「已定位/已分析/已确认瓶颈」这类形容词掩盖：

| 缺失特征 | 判定信号 | 处置 |
| --- | --- | --- |
| 未读目标就下结论 | 对用户点名对象给出瓶颈、复杂度或优化结论，正文却没有该对象本轮读取的 `path:symbol:line` 与决定性代码行 | 先读该对象，再下结论 |
| 分析对象漂移 | 正文主体分析的对象与用户点名的入口/函数/路径不是同一个（答成了调用方、下游或同名近似实现） | 回到点名对象重新锚定；漂移的分析不计入交付 |
| 讨论不存在的机制 | 正文分析了目标代码里根本不存在的结构、查询、算法或并发模型，或用「典型/通用系统」的假设替代实际读取 | 删除，或降级为明确标注前提的 assumption |
| 热点空推 | 声称某处是瓶颈，却既没有该处的代码证据、也没有命中它的测量 artifact | 降级为待测假设，并给出能观测它的测量 seam |
| 收益数字无根 | 给出「降低 X%／提升 Y 倍／减少 N ms」这类收益量，却没有对应的同合同 A/B 测量 | 删除该数字，改为条件化预期并显式标注「未测量」 |

> 坏例：「引入缓存后预计延迟降低 40%。」（无同合同 A/B）
> 好例：「缓存候选的收益未测量，判定门槛已预登记，实验计划见下。」
> 点评：没有同合同 A/B 的收益数字必须删除，摘要里也不得恢复该数字。

这道门作用于任何需要定位成本或给出优化方向的模式（`diagnose`/`optimize`，以及纯静态求改进点的请求）；纯粹解释一份已有 artifact 的 `explain`，按其自身证据边界收口。

## 三、建立可重复基线

基线不是一串数字，而是一份可重放的实验：

- 固定 revision、构建产物、依赖锁、运行参数和动态配置；
- 固定 workload 生成方式、输入快照、状态初始化与清理；
- 明确 cold、warm、steady-state 或混合场景，不能互相替代；
- 明确测量边界内外的 setup、teardown、诊断开销和等待；
- 保存原始样本、实际执行顺序、退出状态和环境指纹；
- 检查测量器本身是否饱和、丢样、改变调度或隐藏排队；
- 使用独立运行单元；同一循环里的重复读数不自动成为独立样本。

冻结输入与派生证据的关系：

1. 冻结前已存在的 comparison、variant 和门槛输入登记为冻结输入。
2. 测量 capture、profile、trace 和复核结论都是冻结后产生的派生证据，另行记录，并说明它依赖哪些冻结输入，形成无环的依赖关系。
3. 每个证据 locator 必须能重新读取到精确的原始内容。
4. 不得通过在冻结输入里追加派生产物来改写它。

若 baseline 漂移、命令不可复现或 workload 与问题不一致，停止候选排名并重建基线。

## 四、定义正确性与守卫

先冻结目标路径的行为；存在 candidate 时必须在查看 candidate 细节前写 oracle。只覆盖当前模式会触碰或依赖的契约，但不能只比较「数量相同」：

| 契约面 | 检查内容 |
| --- | --- |
| 输入身份 | 完整 key、顺序、重复、空值、动态状态和调用者上下文 |
| 输出 | 值、类型、精度、顺序、稳定性和完整性 |
| 错误 | 类型/身份、partial result、超时、取消和未知结果 |
| 依赖 | 调用集合、参数、顺序、重试和失败传播 |
| 副作用 | 持久写入、事务边界、提交顺序和清理 |
| 并发 | 所有权、隔离、race、饱和、接管和恢复 |
| 生命周期 | 分配、保留、释放、连接与文件等资源 |

**双向 oracle**：存在 candidate 时，oracle 必须双向比较 baseline 与 candidate，即能在两个方向上发现差异。只规范化契约明确无序的部分；不要通过排序、丢字段或忽略错误来制造「等价」。

**判别反例**，在候选进入测量前生成：

1. 针对候选改变的数据结构、遍历方向、去重/排序、批处理、缓存、并发和终止条件构造最小判别反例。
2. 反例只选择适用的契约面，但必须包含能区分两侧的空、单项、重复/重叠、边界、unknown/缺失、错误/部分完成或并发交错。
3. 任一反例显示未授权差异：立即登记 `REJECT`，停止为该候选设计收益实验。
4. 不能以概率低、下游容错或预期性能换取等价性豁免。

**候选账本**，必须能直接投影到最终交付：

- 每个推荐候选保留 `触碰语义面 / 判别反例 / baseline 结果 / candidate 结果 / 判决 / 证据`；
- 未形成判决或判决为 `UNKNOWN` 的候选只保留为待实验假设，不进入优先级榜、实施建议或「低风险」结论；
- 判决为 `REJECT` 的候选明确保留反证，防止换一种措辞重新放行。

**等价类推导**，不用候选作者挑选的单个 happy-path 样例关闭账本：

1. 按候选实际触碰的每个维度和维度交互从 baseline 推导等价类。
2. 至少主动寻找同一身份跨类别、重复/别名、共享存储、顺序、错误与部分结果等适用反例。
3. 只有可审计的全域推导或保留了 seed/命令/artifact 的双向 differential/property oracle 才能给 `PASS`。
4. 示例通过但覆盖不完整时保持 `UNKNOWN`。

**Guard** 与主指标分开，包括候选可能牺牲的尾部行为、吞吐、内存、I/O、可靠性、公平性和外部容量。任何 guard 失败都不能用主指标收益抵消。

## 五、定位限制机制

症状 → 首轮指标 → 定位 artifact 的选择表统一见 [Profiler 证据分流](profiler-routing.md)，本文不重复。本节只保留两条纪律：

- 先核验工具、参数和 artifact 格式在当前环境真实存在；
- Profile 只用于定位，不与关闭诊断后的最终比较混为一谈。某函数很热、某对象很多或某资源利用率高，都必须连接到等待或目标指标，才能成为瓶颈证据。

## 六、竞争假设

不要从第一个热点直接跳到方案。为同一症状建立至少两个机制上不同的解释：

```yaml
hypothesis:
  trigger:
  mechanism:
  target_effect:
  evidence_for:
  strongest_alternative:
  exclusive_prediction:
  falsifying_observation:
  confounders:
  end_to_end_ceiling:
```

优先执行能让两个解释产生不同结果的实验。`optimize` 模式中的每个 candidate 必须说明：

- 它精确消除哪项成本；
- 可能改变哪部分行为；
- 在哪些 workload 下无效或退化；
- 如何恢复。

以下做法只能产生待测假设：

- 仅凭复杂度符号宣称现实瓶颈；
- 将局部热点占比直接换算为端到端收益；
- 将测试桩上的 CPU 差值外推到含 I/O 的真实路径；
- 用缓存、并发、批量或减少工作量作为天然更快的结论；
- 以 candidate 自身幂等或单向摘要代替旧新严格差分。

## 七、执行单变量实验

本节仅适用于 `optimize` 或用户要求比较已有 candidate；其他模式以各自完成边界收口。

每轮只改变一个作用机制。若一个开关同时改变多个阶段，结果只能归因于该组合；需要新增观测 seam 才能继续分解。

> 坏例：candidate 同时换了数据结构又加了缓存，报告「快 18%」并归因于缓存。
> 好例：一轮只开缓存、其余与 baseline 完全一致；数据结构变更另开一轮。
> 点评：混入多个变化只能得到组合差异，不能归因到其中任何一段。

执行顺序：

1. 在 baseline 上运行 oracle，证明 oracle 能观察目标契约。
2. 应用一个 candidate，记录精确 diff、revision 和恢复点。
3. 先运行 candidate oracle 与故障场景；失败立即恢复。
4. 按预注册顺序运行 baseline/candidate，保存所有原始样本。
5. 关闭 profiler 或额外诊断，执行最终同合同比较。
6. 检查 guards、环境漂移、排除规则与样本独立性。
7. 按区间而非点估计判定改善，不手工挑选有利样本；区间来源与定性判定的完整规则统一见[实验合同](experiment-contract.md)第四节，本文不重复。

测量规模、采样充分性和门槛由问题、噪声与预注册计划决定。能跑出统计结果只是判定条件，不是充分性证明。

## 八、反证与决定

非简单任务让独立角色在不知道当前偏好的情况下检查；没有 candidate 时忽略仅与候选差分有关的条目：

- workload 是否真的触发目标路径；
- baseline 与 candidate 是否只差一个因素；
- 是否跳过工作、复用旧答案、缩小输入或降低精度；
- 计时边界、预热、重置、顺序或环境是否漂移；
- oracle 是否遗漏候选触碰的行为；
- profile 是否命中预期机制，替代解释是否仍成立；
- 原始 artifact、规范化输入与报告是否一一对应。

然后选择唯一当前动作：

| 动作 | 条件 |
| --- | --- |
| `EXPLAINED` | 现有 artifact 的含义、scope 和证据边界已复核 |
| `BASELINE_ESTABLISHED` | 可重放 baseline 与原始样本已建立 |
| `BOTTLENECK_CONFIRMED` | 运行证据命中限制机制，替代解释已裁决 |
| `GUARD_ESTABLISHED` | 守卫合同、门槛来源与失败动作已闭合 |
| `ACCEPT` | 严格正改善 target、correctness、guards 全部通过，且改善按 [实验合同](experiment-contract.md) 第四节的区间判定成立（有工具则算区间，无工具则定性判定成立并标注统计不确定性），并已完成独立复核（只能顺序封闭复核时标 `DEGRADED_SEQUENTIAL`，不称独立） |
| `REJECT` | 有效实验中改善 target 未达正门槛但尚未确认退化 |
| `RESTORE` | 行为、正确性、guard 失败，或主指标已确认退化 |
| `REMEASURE` | 污染、漂移、统计不确定或比较不可归因 |
| `REJECT_HYPOTHESIS` | 观测未命中预测机制 |
| `EVIDENCE_REQUIRED` | 缺少权限、artifact 或可执行 seam |

不要用格式完整、代码评审通过、角色共识或点估计替代上述条件。

裁决顺序（先看复核有效性，再看统计）：

1. 比较 candidate 时先确认复核是否有效、输入是否与冻结事实一致。
2. 复核明确记录 correctness/guard 失败 → `RESTORE`。
3. 实验有效性明确失败 → `REMEASURE`。
4. 除上述两种明确失败外，复核缺失、artifact 不可读或含 `unknown` → 先交付 `EVIDENCE_REQUIRED`；不要让统计结果抢先产生 `REJECT` 或统计型 `RESTORE`/`REMEASURE`。
5. 只有复核通过后，统计结果才可触发相应分支。

`ACCEPT` 的证据边界：

- `ACCEPT` 组合了外部复核与统计门槛，本身不证明 artifact 来源真实、workload 有代表性或 oracle 完备。
- 主 agent 仍须重新打开决定性原始 artifact；若不能做到，只能保留断言边界，不改写成无条件的「已证明提升」。

## 九、交付与回归守卫

交付必须让另一位工程师重放实验并理解结论边界。

第一屏先给一句**证据基线声明**，包含：

- 当前 revision／构建版本；
- 本轮读了目标的什么（带定位）与未读什么；
- 结论是纯静态阅读还是有测量／运行观测支撑；
- 最主要的未验证项。

这条声明必须引用正文实际用到的同一批定位与测量，不能是脱离正文的通用套话。

随后交付：

- 冻结的任务与实验合同；
- 真实路径和行为指纹；
- 当前模式实际使用的 baseline、profile/trace 与 raw samples 定位；
- `diagnose / optimize` 的首要和替代假设、互斥预测与反证结果；
- 仅在存在 candidate 时给出单变量边界和恢复点；
- 实际执行过的 oracle、guards、统计和独立复核状态；
- 与主模式一致的当前动作和下一实验。

交付纪律（任务无关的输出形状约束）：

- **证据物前置**：把直接结论和支撑它的证据物（真实路径证据、测量定位、假设与反证）放在最前，即使输出被预算截断，高价值内容也已交付。
- **过程话术不进正文**：「让我先读取…」「接下来我将…」「现在整理一下…」这类过程叙述不得出现在最终交付里。
- **禁止半截截断**：不得停在表格、列表或链条中途。空间不足时砍叙述广度、不砍证据深度，并宁可显式收口为 `PARTIAL` 也不留一个断在半句的表格。篇幅最大化不是完整性。

接受 candidate 后，将同一 workload、oracle、guards、测量边界和门槛固化为回归守卫。若守卫使用代理指标，明确它与原指标的已验证关系以及何时重新运行完整合同。
