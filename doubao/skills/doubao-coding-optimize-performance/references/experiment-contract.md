# 实验合同与比较器语义

> **何时读本文件**：进入 MEASURE 阶段、需要冻结实验语义或对 baseline/candidate 做最终判定（含区间判定规则）时加载。

本文件只保留设计和比较测量时的可迁移原则；具体 JSON schema 与机检细节不在此列。核心是：测量能否成立由采样前冻结的语义决定，不由事后拼凑数字决定。

## 一、先冻结语义，再收集数字

采样前先固定实验的全部含义，之后不得改动：

| 冻结项 | 内容 |
| --- | --- |
| 任务边界 | 原始任务、scope、权限和硬性环境限制 |
| Revision | baseline 与 candidate 各自对应的不可变 revision |
| 实验条件 | workload、输入分布、调用序列、状态重置、环境和计时边界 |
| Oracle | 必须保持的不变量与双向 correctness oracle（能在 baseline、candidate 两个方向发现差异） |
| 判定口径 | target、guard、方向、单位，以及门槛和门槛来源 |

冻结内容变化时重建基线，不能把变更后的设定与旧样本拼接。

## 二、单一比较轴

1. 一次比较只声明一个作用机制（comparison axis）。
2. 除这一个轴以外，命令、环境、workload、采样方式、状态重置、计时边界、预热等全部 held-constant，两侧必须一致。
3. baseline 与 candidate 只应有这一个差异；混入多个变化只能得到组合差异，不能归因到其中一段。

## 三、门槛登记在采样之前

1. 改善 target 的门槛必须在采样前登记，且严格大于零，防止事后按结果挑一个刚好通过的门槛。
2. 只有实验前显式登记为非退化（zero-boundary）时才允许零门槛，且只能得出「未见退化」的结论，不能称为提升。
3. 每个 metric 用自己独立的门槛来源，不共用。

## 四、按区间判定，而不是按点估计

判定改善看分布与不确定性，而不是点估计、平均值更好或单次最佳值：

- 统计量取 baseline 与 candidate 中位数之差；
- 改善 target 的区间下界必须越过严格正门槛；
- guard 的上界必须不越过允许退化的负边界；
- 样本数、耗时、tokens、上下文长度和 agent 数量都不作为质量裁剪理由。

得到区间的手段由当前环境实际可用的工具决定，本 skill 不自带比较器：

| 环境条件 | 判定手段 | 允许的结论 |
| --- | --- | --- |
| 已有可复现的统计比较工具（如 bootstrap 置信区间脚本、`benchstat`） | 用它计算区间，记录工具、参数与随机种子来源，使判定可复现 | 区间判定成立可支撑 `ACCEPT` |
| 无此类工具 | 基于保留的原始样本做透明的定性判定：报告每组中位数、离散范围（最小/最大或分位数）、样本量和运行顺序；只有改善方向在样本上一致、幅度明显大于观测噪声时才可判为改善 | 显式标注「未做区间估计，结论存在统计不确定性」，产出 `REMEASURE` 或降强度结论，而不是 `ACCEPT` |

无论哪种手段：不得口算或编造置信区间，不得把定性观察改写成精确的统计置信度数字；合法输入因客观机器资源无法完成时如实报告工具/资源限制，不删样本冒充同一实验。

> 坏例：「candidate 平均快 7%，我估计 95% 置信区间为 [5%, 9%]，判 ACCEPT。」（无工具，区间是编的）
> 好例：「无区间工具；两组各 10 个样本方向一致，中位数差 7%，噪声范围 ±2%；标注统计不确定性，判定降强度。」
> 点评：没有可复现工具时，区间数字必须消失，不确定性必须显式出现。

## 五、真实性边界

结构上能通过（可解析、字段完整、统计达标）都不证明 workload 真实、artifact 可信、环境可比或行为等价。成功结论仍要由主 agent 重新打开决定性原始 artifact，解释适用 revision、环境、workload、未验证边界和恢复路径；不得把统计结果改写成超出证据的真实世界结论。
