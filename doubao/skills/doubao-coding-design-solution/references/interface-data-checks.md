# 接口与数据调查

只读取命中的分支。以下规则用于裁决责任、契约、数据和迁移，不定义 artifact 的 profile、章节或表结构。

## 信任边界

已核验的否定权限、数据驻留和禁止流向是端到端硬门，覆盖主流程、失败、重试、排障、观测、缓存、备份、恢复、清理与派生数据。未知只附着于落实方式、owner 或证据；同等或更高权威来源改变约束后，才重新比较跨界路线。

对每条相关数据流记录：原始与派生数据类别、允许主体和操作、跨界前转换，以及重试/日志/备份是否保持同一约束。候选要求被禁止主体先接触受限数据时直接淘汰；随后加密、脱敏或删除不修复已经发生的越界。

## 同步接口

- 入口、调用方、所有者、认证/授权、运行时注册和生成边界；
- 字段、默认值、大小限制、成功结果和可区分错误；
- 超时、取消、并发、幂等、限流、重试预算和部分失败；
- 旧客户端、灰度实例、多版本共存与兼容验证责任；
- 真正约束行为的 schema、IDL、类型、运行时校验或契约测试；
- 可关联且不泄密的日志、指标和 trace。

类型声明和框架惯例只形成候选契约；真实消费者、注册和调用路径负责确认。

## 事件、队列与后台任务

- producer、consumer、schema owner 与系统记录源；
- 交付、去重、顺序、回放和 schema 演进语义；
- 退避、死信、毒消息、积压上限和人工恢复；
- 数据库与消息系统之间的提交点、对账和补偿；
- 租户隔离、权限、敏感字段、保留与删除。

## 数据所有权

- 每个实体的系统记录源、写入者、读取者和派生副本；
- 唯一性、引用、状态机、守恒、时间与租户不变量；
- 逻辑模型、物理 schema、缓存、索引和分析副本的区别；
- 隔离级别、一致性窗口、冲突解决、重复请求和部分失败；
- 基数、增长、热点、索引成本、保留期与恢复目标的来源。

抽象 ID 不推导存储宽度、编码或索引布局；这些物理建议以已验证表示和数据库能力为前提。

## 迁移与回填

1. 固定兼容部署顺序和旧新版本共存窗口。
2. 为每阶段标出读路径、写路径和系统记录源。
3. 为回填定义分片、速率、检查点、幂等、重试和线上负载保护。
4. 用数量、校验和、业务不变量或抽样对账验证数据。
5. 写出停止条件、可逆边界、恢复与前向修复。
6. 清理旧路径前证明无消费者，并满足约定观察窗口。

**完成判据：** 每个命中分支都有所有者、精确契约或不变量、失败语义、兼容边界、验证证据和恢复动作；缺项直接回到方案主流程作为阻塞或条件分支。
