# Evidence-locked design

默认只读调查。不要创建或修改仓库文件。最终回答本身必须完整承载用户要求；不得用本地文件、链接、附件或“详见文档”代替方案正文。

## 五条签发规则

1. **先锚定决定性事实。** 推荐中的当前行为、责任、接口、状态和依赖必须回链到本轮实际读取的当前 revision 源码、配置、测试或权威契约。用 `path:symbol:line` 紧凑引用即可，不输出仪式化事实表。点名但未读的边界、由命名/框架惯例推断的行为，以及冲突来源，明确写成 `unknown`，不能进入无条件推荐。

2. **跨边界性质必须能被反例击穿。** 当方案涉及状态、外部副作用、消息、发布切换、身份、迁移或恢复时，先确定适用的 `observer / identity+scope / writer / reader / commit or ACK / effect order`。为每个准备采用的强性质给一个最小反例，至少检查：
   - 动作成功但调用方不知道结果；
   - 崩溃后重试、重复或并发；
   - 旧新版本共存，或回滚后仍有新状态和在途工作。
   逐个说明检测、重试 owner、恢复动作和恢复后的可观察 oracle。单点 CAS、rename、Lua、锁、TTL、重试或 feature flag 只能证明局部语义，不能自动证明端到端原子、兼容、不丢不重或最终收敛。

3. **只在真实决策存在时比较候选。** 跨责任、外部契约、持久状态、迁移或恢复通常至少比较两个机制不同的完整候选；若约束只允许一条安全路线，给出最强真实替代及其决定性拒绝证据。对候选使用同一组适用约束，但不要强制展示 gate 表。候选必须说清 owner、机制、最大代价、失效条件和恢复成本。

4. **未知不能签发。** adopted 结论只能包含已有证据和闭合合同支持的范围。决定性依赖、消费者行为、失败窗口或恢复 oracle 仍未知时，交付条件化的 `PARTIAL`，并给最小判别动作；不得用更多章节、伪代码、未来测试或自称复核把未知写成已通过。无来源的阈值、次数、容量、工期、收益或外部能力保持待校准参数，并说明如何测量。

5. **答案即制品。** 最终只展开本题适用内容：裁决与范围、证据基线、候选取舍、采用合同、当前模块/符号的实施切片，以及命中的兼容、迁移、恢复、测试、灰度和开放决定。测试必须说明它能推翻哪种错误机制；回滚必须处理状态和在途工作，而不只是回退代码。签发前删除不能回链到当前证据、合同或 oracle 的强断言，并确认没有把计划测试写成当前证明。再做一次**删链检查**：移除所有链接、附件和未展示的“完整设计”后，正文仍须让独立评审判断用户明示的每个核心机制，以及支撑 adopted 强性质的决定性机制——当前依据、采用契约/边界、实现落点、失败恢复和可证伪验证（仅适用项）。关键机制只存在于未交付 artifact 时，结果只能是 `PARTIAL`，不得称“已完成”或 `ADOPTED`。

准备采用 `atomic / rollback / backward compatible / reproducible` 等强性质时，按需读取 [强性质证明卡](references/strong-property-proofs.md)；接口、数据、事件或迁移命中时读取 [接口与数据调查](references/interface-data-checks.md)。只加载命中的参考，不复制卡片或模板充数。
