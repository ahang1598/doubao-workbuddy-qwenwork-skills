# SQL 诊断与最小修复

## 概述
从执行环境和第一处错误出发，先做最小复现，再核对业务粒度和字段含义。Skill 不携带任何特定业务的内部表名或生产口径。

## 使用场景
### 应使用
- SQL 编译/执行错误。
- 字段不存在、聚合粒度错误、日期方言或性能问题。
- SQL 与 PRD/模型文档口径不一致。

### 不应使用
- 无 SQL/DDL/日志的从零数据建模。
- 直接执行生产 DELETE/UPDATE/迁移。
- 纯表格分析。

## 核心流程
### 1. 锁定环境
确认数据库方言、版本、执行入口、权限和第一处错误。

### 2. 分离可执行内容
剔除日志、OCR 误识别、自然语言和完成时间等非 SQL 文本。

### 3. 最小复现
收敛到最小语句，并用元数据查询确认表、字段、类型和函数。

### 4. 核对业务粒度
确认主键、时间、单位、过滤、去重、分组和 join 基数；未知含义不猜。

### 5. 最小修复与验证
限制替换范围，先运行只读/小样本检查；无法执行时给编译与样本验证 SQL 并明确未通过。

## 工具与协作
- 代码文件使用 Read/Grep/Edit/Bash；数据库执行需用户合法环境和权限。
- 内部表名、字段和值只来自本次用户材料，不写入 Skill 或日志。

## 安全边界
- 只陈述已读取、已执行或有来源支持的结果；未验证项必须明确标注。
- 涉及删除、覆盖、发布、系统设置、生产数据或不可逆操作时，先展示目标、影响、回滚方式并取得明确确认。
- 不得记录或输出密钥、Cookie、访问令牌、身份证号、银行卡号等敏感信息；示例使用脱敏占位符。
- 生产写操作必须备份、展示精确语句和影响范围并取得确认；默认只提供只读验证。
- 不得将生产表名、状态码、用户 ID 或业务快照固化为示例。

## 输出与验收
- 环境和第一错误
- 根因
- 最小补丁
- 验证 SQL/结果
- 回滚与未验证项

## 冒烟用例
### Should trigger
- Spark SQL 报函数不存在，日志和表结构在附件里
- 这段 SQL 汇总数不对，帮我核对 join 粒度

### Should not trigger

- 直接在生产库执行这批 DELETE

### 边界输入
- 只有截图且字段名无法辨认，需要先 OCR/DDL
