# 视频理解：场景内敏感词判定

ASR 只能给出「说了什么」和词级时间戳。是否屏蔽要看**这个词出现在什么画面/情境里**。本任务**只做场景内敏感词判定**——硬字幕框由 [字幕处理.md](字幕处理.md) 的 `video-ocr --mode Detailed` + OCR×ASR 交叉确认主导,不归本任务。

本任务用来做场景内敏感词判定,给 Step 4「词 × 场景」裁定提供场景结论。**另外,它也是 Step 8 文案校准的重要消歧证据**:用于补充人物称呼、品牌/产品名、游戏/UI 术语、镜头主题和同音字语境。
**本节所有真实的 `mediakit-cli` 业务调用都固定前缀 `DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction`。** 不要省略,不要改值,也不要写成 `--DOUBAO_MEDIAKIT_RUNTIME` 业务 flag。

由 Agent 直接执行 CLI。提交后 `query-task --poll-complete`，见 `SKILL.md`。

## 何时调用

**Gate 0 `probe-video-metadata` 确认有音轨之后**发起（无音轨则整个 skill 终止,本任务和 asr 一样**不发**,不空跑付费云任务）。有音轨后与 `separate-voice` **并行**,输入用**原始视频 URL**,不要等 vocals。默认必发,不再判"要不要发"。

## 命令

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video video-understand-router \
  --video-urls "<用户视频本地路径或 URL>" \
  --level Balanced \
  --scene editing \
  --manual-option '{"need_audio":true}' \
  --prompt '这是视频内容审核。请做场景内敏感词判定（不是黑名单扫描）：结合画面、人物行为、对白和硬字幕，找出可能被当成敏感的词语或短句；逐条输出词语原文、所处场景、在该场景是否需要屏蔽（涉黄/涉毒/真实暴力/色情/脏话/反恐）、判定理由和时间范围（秒）。同一词语在不同场景结论可以不同；游戏或竞技口播中的玩法用语以及新闻、普法、医疗科普中的客观提及通常不屏蔽；明确脏话辱骂、色情挑逗、真实伤害、教唆犯罪必须屏蔽；表面中性的词若画面已是涉黄或真实暴力仍判敏感。不要输出字幕擦除框。'
```

Windows PowerShell 必须把对象 JSON 放在 `--%` 后，并直接内联：

```powershell
$env:DOUBAO_MEDIAKIT_RUNTIME="scene-video-redaction"
mediakit-cli video video-understand-router --video-urls "C:\path\video.mp4" --level Balanced --scene editing --prompt "这是视频内容审核。请做场景内敏感词判定（不是黑名单扫描）：结合画面、人物行为、对白和硬字幕，找出可能被当成敏感的词语或短句；逐条输出词语原文、所处场景、在该场景是否需要屏蔽（涉黄/涉毒/真实暴力/色情/脏话/反恐）、判定理由和时间范围（秒）。同一词语在不同场景结论可以不同；游戏或竞技口播中的玩法用语以及新闻、普法、医疗科普中的客观提及通常不屏蔽；明确脏话辱骂、色情挑逗、真实伤害、教唆犯罪必须屏蔽；表面中性的词若画面已是涉黄或真实暴力仍判敏感。不要输出字幕擦除框。" --% --manual-option "{\"need_audio\":true}"
```

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli shared query-task --task-id "<task_id>" --poll-complete
```

- **flag 名固定是 `--video-urls`，不是 `--video-url`**。虽然一次只传 1 个值，CLI 仍然要求用复数 flag；传错会直接报 `unknown flag: --video-url`。
- `--prompt` 是**必填**，直接使用上面命令中的完整内容；不要省略、传空字符串或把 `<prompt>` 占位符原样提交。下节是语义等价的分行版，便于审阅。
- `--video-urls` **单次只传 1 个视频**。本 skill 只关注 **HTTP/HTTPS URL、本地文件路径** 两种输入；不要逗号拼多个值，也不要重复传该 flag。
- `--level Balanced`：内容审核用均衡档。
- `--scene editing`：需要带时间的分镜/场景，便于和 ASR 对齐。
- `--manual-option` 必须开启 `need_audio`。POSIX / bash 用单引号整体包裹；Windows PowerShell 必须按上例放在 `--%` 后内联，禁止 `$json` 变量。
- 不要传 `prefer_endpoints` / `prefer_models` / `queue_id` / callback 类字段，除非用户明确给了值。

## Prompt 要求

**只做场景内敏感词判定。** 硬字幕框由 [字幕处理.md](字幕处理.md) 的 `video-ocr --mode Detailed` + OCR×ASR 交叉确认主导,**不要**让 video-understand 出擦除框。

```
这是视频内容审核。请完成：场景内敏感词判定（不是黑名单扫描）。

结合画面、人物行为、对白和硬字幕，找出可能被当成敏感的词语或短句。
对每一条输出：词语原文、所处场景、在该场景是否需要屏蔽（涉黄/涉毒/真实暴力/色情/脏话/反恐）、判定理由、时间范围（秒）。
原则：
- 同一词语在不同场景结论可以不同。
- 游戏、竞技口播里的「杀、死、炸、爆」等玩法用语，通常不按真实暴力屏蔽。
- 新闻、普法、医疗科普里客观提及「毒品、色情、暴力」，通常不屏蔽。
- 明确脏话辱骂、色情挑逗、真实伤害、教唆犯罪，即使是「梗」也要屏蔽。
- 表面中性的词，若画面已是涉黄/真实暴力，仍判敏感。
```

若 ASR 已先返回，可以把转写摘要附在 prompt 末尾，请模型逐条裁定这些候选词在当前镜头里要不要屏蔽。

## 如何与 ASR / OCR / 文案校准合并

两边都齐后先写 `sensitivity_candidates.json` 并进入 Gate 1；用户下一条消息确认后才写终稿 `sensitivity.json`。输入有硬字幕时，Step 8 必须再生成 `subtitles.json`：

- ASR 提供词级时间戳；视频理解提供「该词在该场景是否敏感」。
- 字面像敏感、场景判定为不敏感：候选表说明理由；用户确认保留后不打哔，重建字幕时保持原词。
- 场景判定为敏感：先进入候选表；用户确认屏蔽后才用 ASR 时间戳写入 `sensitivity.json`，并在重建字幕时把对应字符换成 `*`。
- ASR 有、视频理解没点名：按同一套场景原则再裁一次，不要只因字面命中就屏蔽。
- 视频理解指出画面敏感但 ASR 没有对应语音：在回复里说明；没有语音区间就不要凭空打哔。
- 明确脏话 / 色情 / 真实暴力：屏蔽优先。其余歧义词以场景判定为准。

当进入 Step 8 文案校准时，再把 video-understand 结果额外用于：

- 提取当前镜头的术语表（人物、品牌、App/游戏名、技能名、地点名）
- 给 OCR / ASR 冲突句子提供语境锚点
- 压低纯同音替换的权重，避免把专业术语改成“读音像但语义不通”的词
- 在 OCR 缺字、ASR 错字时，辅助 Agent 选出最符合镜头主题的终稿文本

擦除不等本任务,硬字幕框走 [字幕处理.md](字幕处理.md) 的 OCR 路线,本任务不出框。
