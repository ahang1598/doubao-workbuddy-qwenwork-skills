# 前置探测

执行本节前,先读 [安装.md](安装.md) 与 [`../SKILL.md` 的“使用前请阅读”](../SKILL.md#使用前请阅读)。**本节要求直接执行,不是允许先跑错再修**:先按文档确认命令、参数、轮询方式,再下命令;不要把报错当成探路手段。
**本节所有真实的 `mediakit-cli` 业务调用都固定前缀 `DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction`。** 不要省略,不要改值,也不要写成 `--DOUBAO_MEDIAKIT_RUNTIME` 业务 flag。

必须在音频线、擦除线、视频理解之前先跑完本节。有两个硬分叉：

1. **音轨探测**：无音轨直接终止。
2. **硬字幕抽帧**：无硬字幕跳过擦除；有硬字幕先 `video-ocr --mode Detailed` 定位并归纳框，Gate 1 用户确认后再一次 `erase-video-subtitle-pro` 擦完。

## 1. probe-video-metadata

**先锁定用户输入再跑本步。** `--video-url` 的值必须是用户本条任务里真实给出的视频路径 / URL，原样存为 `INPUT` 并全程复用；不要猜文件名、补目录、改扩展名或拿占位符顶替。含空格或中文的路径整体加引号。用户没给可用输入时，先向用户要，不要用假设值跑 probe。

**输入是 HTTP/HTTPS URL 时，先探活确认地址有效，再发起 probe / 抽帧 / `separate-voice` / `video-understand-router` 等并行云任务。** 这一步是**文档定义的预检**（不是先盲跑业务命令看报错），因为 Step 1/2 会同时打出多个付费云任务，URL 失效/过期会一次性全废。用 1 字节 ranged GET 看状态码与 `content-type`：

```bash
curl -sS -L -r 0-0 --max-time 15 \
  -o /dev/null \
  -w '%{http_code} %{content_type}\n' \
  "$INPUT"
```

Windows 用系统自带 `curl.exe`，参数相同。判定：

- 状态码 2xx（含 200 / 206）且 `content-type` 是 `video/*` 或通用二进制（`application/octet-stream`）→ 视为有效，继续。
- 状态码非 2xx（403/404/410 常见于链接过期或签名失效）、`content-type` 是 `text/html` / `application/json`（多为报错页）、或连接超时/失败 → **判定无效，停下来把状态码/类型告诉用户并索要有效地址，不要继续 probe 或任何云任务**。
- 服务端不支持 Range 而返回 200（非 206）也可接受，不要因此判失败。

输入是本地路径时跳过 curl，改为确认文件存在且可读即可。

**mediakit 工具的 `--video-url` 支持两种输入:HTTP/HTTPS URL、本地文件路径(别的不用关注)。** 原视频是 URL 就全程原样传给各 mediakit 工具,不用先下载。仅 ffmpeg amix、本地 FunASR、Agent 看图/交付才需要落盘,见 [SKILL.md](../SKILL.md#mediakit-cli-调用约定)。

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video probe-video-metadata \
  --video-url <原始视频 URL 或本地路径>
```

`query-task --poll-complete` 后读 `result.audio_stream_meta`：

- `null` 或 `codec` 为空 → **终止整个 skill**，告知用户"视频无音轨，本 skill 不做任何处理"。不要继续 `separate-voice`、`asr-subtitles`、`video-understand`、`erase-video-subtitle-pro`。
- 非空 → 记下 `duration` / `sample_rate` / `channels`，供后续 amix `duration=first` 校验用。

顺便读 `result.video_stream_meta.width` / `height` / `fps`，抽帧字幕框计算需要归一化。

## 2. 画布尺寸 + orientation

从 `probe-video-metadata` 的 `result.video_stream_meta` 拿 `width` / `height` / `fps` 判定横竖片：

- `width/height > 1.2` → 横屏；
- `width/height < 0.8` → 竖屏；
- 其间 → 方屏。

orientation 只用于 `add-subtitle-to-video` 的位置预设选择（见 [新字幕字号 / 位置](#新字幕字号--位置仅用于-add-subtitle-to-video)）。**不需要 cropdetect / content_box** —— 擦除框由 OCR 归纳（见 [字幕处理.md](字幕处理.md)）、新字幕位置只按横竖片二选一。

## 3. 雪碧图抽帧（mediakit extract-frames --enable-sprite，判定有无硬字幕）

**统一走 mediakit `extract-frames --enable-sprite=true`**，一次任务把 25 张帧合成为**一张雪碧图**（5×5 网格），交给 Agent 一次读完判定。**禁止用本地 ffmpeg -ss 抽帧**——所有音视频处理保持在 mediakit 里,鉴权和产物 URL 才一致。

**为什么走雪碧图而不是抽 1 张或 3 张独立帧**：
- 分段字幕、说话人换镜、转场空镜都可能让少量帧刚好落在字幕间隙 → 假阴性致命。
- 25 张独立帧 Agent 要下载 25 次、逐张判定；**雪碧图是一张图**，Agent 一次视觉判定就能把全片时间轴扫一遍，token / 延迟大幅下降。
- mediakit 服务端合成雪碧图与抽多张独立帧耗时一致（同一次异步任务），成本几乎为零。

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video extract-frames \
  --video-url <原始视频> \
  --snapshot-type TimeInterval \
  --time-interval <duration/25> \
  --snapshot-limit 1 \
  --enable-sprite=true \
  --sprite-rows 5 \
  --sprite-cols 5 \
  --scale-long 480
```

- `time_interval = duration/25` 保证 25 张均匀铺满全片。
- `snapshot_limit=1` + `sprite_rows=5` / `sprite_cols=5` → 一张雪碧图内嵌 25 个小图（`snapshot_limit * sprite_rows * sprite_cols`）。
- `scale_long=480` 控制单张小图长边，整张雪碧图 ≤ 2400px 单边，Agent 一次视觉读完不吃力。
- `query-task --poll-complete` 后从 `result.snapshots[0].image_url` 下载唯一一张雪碧图。

### 判定标准（Agent 视觉一次判完，宁松勿严）

Agent 看这张雪碧图,**任一格子命中即判"有硬字幕"**——需要**同时**满足：

1. 是**文本行**（连续 ≥2 字组成一行，不是孤立词或图标）；
2. 位置在**下三分之一**（横屏）或**中下部**（竖屏）；
3. 通常有**描边 / 阴影 / 半透明底条**（作者压制字幕的典型特征）；
4. 内容看起来像**对白 / 旁白**，不是场景标注。

**判"非字幕"**（排除项，避免假阳性触发无谓 erase）：

- 抖音 / 快手 icon、平台水印、UP 主 ID / 头像标签；
- 主播胸前/腰间赞助商 logo；
- 画面场景内本身的招牌、路牌、聊天截图 UI 上的字；
- 封面大字标题（画面顶部超大字号横排）。

### 分叉

- **雪碧图任一格子有字幕** → 判"有硬字幕"并设置 `MUST_REBUILD_SUBTITLES=true`：先发起 `video-ocr --mode Detailed`，与 `asr-subtitles` 交叉确认并归纳擦除框；**Gate 1 用户确认前不提交 erase**。确认后一次擦除，最终必须重压去敏字幕。
- **雪碧图所有格子都无字幕** → 判"无硬字幕"：跳过 `video-ocr` 与 `erase-video-subtitle-pro`；在 Gate 1 候选确认回复中一并询问是否需要压制去敏字幕。
  - **Step 4 兜底复检**：如果 `asr-subtitles` 或 FunASR 有敏感词命中而雪碧图判"无字幕"，Agent 回看雪碧图对应命中词 `start_time` 的格子（雪碧图第 `⌈start_time / (duration/25)⌉` 张）二次判定。仍判"有" → 追发 `video-ocr` 并归纳框，设置 `MUST_REBUILD_SUBTITLES=true`；Gate 1 确认后再一次提交 `erase-video-subtitle-pro`。（不用再发第二次抽帧。）

### 字幕擦除方法论（Detailed OCR 定位 → 归纳一个框 → 一次擦完）

**"裸发 Subtitle 模式让服务端自定位"** 在竖屏内容装横屏画布、字幕带位置漂移的视频上会误伤（抖音水印在 y=0.877-0.981 与真字幕同处下半屏，被 Subtitle 模式一起扫了）。**标准做法:先 OCR 定位、给框,一次擦完**（对任何"自动定位会误伤"的视频通用）：

**Step A：先跑 `video-ocr --mode Detailed`**（1-2 分钟，比盲发擦除省 5+ 分钟返工）

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video video-ocr \
  --video-url <原始视频> \
  --mode Detailed
```

`Detailed` 模式返回每条文本带 `text_label`（`Subtitle` / `Others`）与 `text_location`（像素坐标）。直接暴露误伤源——把 `Others` 类（水印、台标）从擦除框排除。

**Step B：把 `Subtitle` 条目归纳成擦除框（通常一个）**

字幕位置一般固定,取所有 `Subtitle` 条目的**最小外包框**(x/y min-max,上下各留 0.012 余量)当**一个框**。只有位置明显分几簇(y 差距大到一个框会圈进大片无字幕区)才合并成**多个框**(≤20),放进**同一次**调用的 `--erase-ratio-location` 数组。**不切时段、不发多任务。**

**Step C：一次提交擦完**

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video erase-video-subtitle-pro \
  --video-url <原始视频> \
  --mode Subtitle \
  --model-version v5 \
  --erase-ratio-location '[{"top_left_x":0.05,"top_left_y":0.56,"bottom_right_x":0.95,"bottom_right_y":0.69}]'
```

Windows PowerShell：

```powershell
$env:DOUBAO_MEDIAKIT_RUNTIME="scene-video-redaction"
mediakit-cli video erase-video-subtitle-pro --video-url "C:\path\video.mp4" --mode Subtitle --model-version v5 --% --erase-ratio-location "[{\"top_left_x\":0.05,\"top_left_y\":0.56,\"bottom_right_x\":0.95,\"bottom_right_y\":0.69}]"
```

`--erase-ratio-location` 单次支持 20 框;Subtitle 模式只擦"框内 ∩ 下半屏 ∩ OCR 判定是字幕",框大点也不误擦,所以**不必按时段切**。**不传 `--time-segment-filter`**(不需要保留片头片尾)。仅当验收发现残留才调整框重提一次。详见 [字幕处理.md](字幕处理.md)。

### 误判成本分析

- **假阴性**（有字幕漏判）**代价致命**：成片留原字幕 → 用户手动重跑整个流程。判定门槛应**宁松勿严**。
- **假阳性**（无字幕误判成有）**代价廉价**：多花 1-2 分钟 Detailed OCR 就能确认没字幕（`Subtitle` 条目为空）后放弃 erase，画面不会坏。

## 4. 擦除默认一次完成（不抽验收帧）

`erase-video-subtitle-pro` 返回 `result.video_url` 后**默认视为擦除完成**，直接把该 URL 传给后续 `mux-audio-video` / `add-subtitle-to-video`。**不再抽 3-5 张验收帧、不做人工确认**——擦除框已由前面的 `video-ocr --mode Detailed` × ASR 交叉确认归纳过，Subtitle 模式只擦"框内∩下半屏∩OCR判定是字幕"，误伤概率低。

只有在**最终成片阶段**肉眼发现明显残留（如竖屏内容装横屏画布、字幕落到画布上半屏没被框住）时，才调整/追加框重提一次擦除，属于例外而非默认关卡。

`video-ocr` 直接吃原视频异步跑，不依赖抽帧。

### 新字幕字号 / 位置（仅用于 add-subtitle-to-video）

`add-subtitle-to-video` **只接受预设位置 `--subtitle-pos-preset` + 像素字号 `--subtitle-font-size`，没有自定义 x/y 坐标**。可选预设仅 4 个：`top_center` / `center` / `lower_third` / `bottom_center`。

**调用前必须先读 `byted-mediakit-editing/reference/add-subtitle-to-video.md`。** 特别是 `subtitle_pos_preset`、`subtitle_font_size` 的默认值、最大渲染高度和最大渲染宽度，都以那份 reference 为准；**禁止继续写死 `45`**。

**字号**：不再固定写 `45`。按下面规则处理：

1. 用户明确指定字号：可以透传，但仍要校验是否满足 reference 里的两条约束：
   - `subtitle_font_size_px <= 视频原始高度 × 当前预设的 height%`
   - `最长单行字数 × subtitle_font_size_px <= 视频原始宽度 × 当前预设的 width%`
2. 用户未指定字号：
   - 先根据 orientation 选位置预设；
   - 再用 probe 拿到的 `width/height` 和 `subtitles.json` 的**最长单行字数**计算可容纳字号；
   - 若工具默认值 `50` 已满足约束，则**优先省略 `--subtitle-font-size`**，直接走工具默认值；
   - 只有默认 `50` 会超出约束时，才显式传 `--subtitle-font-size <subtitle_font_size_px>`，其中：

```text
max_height_px = floor(video_height * preset_height_ratio)
max_width_px = floor(video_width * preset_width_ratio)
longest_line_chars = subtitles.json 中最长单行的字符数（按手动换行拆分后取最大值）
subtitle_font_size_px = min(max_height_px, floor(max_width_px / max(1, longest_line_chars)))
```

其中 `preset_width_ratio` 固定按 reference 的 80%；`preset_height_ratio` 按预设取值：`top_center=10%`、`center=15%`、`lower_third=10%`、`bottom_center=10%`。算出的字号 `< 1` 视为字幕内容过长，应先改写分句/断句，不要硬塞超长单行。

**位置**：只按横竖片二选一，**不再从帧里读原字幕位置**（那套规则把横屏视频压到画布顶部，视觉上很离谱）：

| orientation                   | 预设            |
| ----------------------------- | --------------- |
| 横屏（`w/h > 1.2`）           | `bottom_center` |
| 竖屏（`w/h < 0.8`）           | `lower_third`   |
| 方屏                          | `lower_third`   |

- 有黑边（letterbox / pillarbox）也照此选：预设本身水平居中，字幕会落在画布下方 / 下三分之一，视觉上和主流平台字幕位置一致，不会跑到画面顶部。
- 用户明确要求"覆盖原字幕位置"再手动覆写预设，默认不做。

**禁止**：不要试图自定义 x/y 坐标；CLI 不接受，传了会被忽略或报错。

## 5. 分叉总览

| probe 音轨 | 抽帧硬字幕 | 用户选择新字幕 | 走向                               |
| ---------- | ---------- | -------------- | ---------------------------------- |
| 无         | -          | -              | 终止                               |
| 有         | 有         | 强制           | 全流程：Gate 1 后擦除 + 音频去敏 + 压新字幕 |
| 有         | 无         | 需要           | 跳过擦除；音频去敏 + 压新字幕      |
| 有         | 无         | 不需要         | 跳过擦除；仅音频去敏后合流输出     |
