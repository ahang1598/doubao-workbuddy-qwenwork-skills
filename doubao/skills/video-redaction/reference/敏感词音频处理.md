# 敏感词音频处理(base + sine beep 分步混音)

## 核心方案

正式路径固定拆成三个独立 ffmpeg 步骤:

1. `vocals` 在敏感区间静音,与 `bgm` 混成等长 `base.wav`
2. 生成全程 1000Hz `sine`,在所有非敏感区间静音并补 `+18dB`,得到等长 `beep.wav`
3. `base.wav + beep.wav` 混成最终 `output.m4a`

分步产物是有意保留的隔离点,便于出问题时分别排查底轨、beep 门控和最终混音,但**不是强制验收或用户试听关卡**。不要再把
所有窗口拼成多路 `atrim + adelay + amix`,也不要再使用 `output_1min.mp3`、
`dd6a0e.mp3`、`-stream_loop -1` 或 `volume=if(...)` 作为正式路径。

音频处理统一使用本地 `ffmpeg` CLI,不引入 `ffmpeg-python`、`pydub`、`av` 或新的
Python 脚本。

**执行前硬门**：必须已收到用户在候选表之后的下一条消息明确确认 Gate 1。setup 会把 ffmpeg 绝对路径写入 `.ffmpeg`；当前会话必须读取该路径，不依赖宿主 PATH 是否已刷新：

```bash
FUNASR_HOME="$HOME/.local/share/funasr_env"
IFS= read -r FFMPEG_BIN < "$FUNASR_HOME/.ffmpeg"
```

Windows PowerShell 使用 `$FUNASR_HOME = Join-Path $env:LOCALAPPDATA "funasr_env"` 和 `$FFMPEG_BIN = Get-Content "$FUNASR_HOME\.ffmpeg" -TotalCount 1`，调用时写 `& $FFMPEG_BIN ...`。下方模板的行尾 `\` 仅用于 mac/Linux；PowerShell 改用反引号续行或合并成单行，`-filter_complex` 的双引号参数保持不变。

## 前置变量

- `WORK`: 本次任务输出目录
- `BASE`: 输入文件基础名
- `DUR`: 视频总时长,单位秒
- `SR`: 原音轨采样率;取不到时使用 `44100`
- `SENSITIVE_EXPR`: 所有敏感窗口表达式
- `NON_SENSITIVE_EXPR`: 敏感窗口在 `[0, DUR]` 内的补集表达式

假设合并后的敏感窗口按时间排序为:

```text
[s0,e0], [s1,e1], ... [sn,en]
```

则:

```text
SENSITIVE_EXPR =
between(t,s0,e0)+between(t,s1,e1)+...+between(t,sn,en)

NON_SENSITIVE_EXPR =
between(t,0,s0)+between(t,e0,s1)+...+between(t,en,DUR)
```

必须先按时间排序并合并重叠窗口。首段从 `0` 开始或末段到 `DUR` 结束时,省略对应
零长度区间。两类表达式都使用运行时外扩后的 `[s_beep,e_beep]`,不要误用 Gate 1
展示的原始时间。

## 时间窗外扩

FunASR 词级时间戳:

```text
pre_pad  = min(0.18, max(0.08, dur * 0.25))
post_pad = min(0.12, max(0.04, dur * 0.12))
```

句级均分插值:

```text
pre_pad  = min(0.35, max(0.15, dur * 0.35))
post_pad = min(0.25, max(0.10, dur * 0.22))
```

实际窗口:

```text
s_beep = max(0, s - pre_pad)
e_beep = min(DUR, e + post_pad)
```

相邻间距小于 `80ms` 的窗口合并。句级插值中,若一句里敏感字占比过半或连续出现,
直接按整句窗口打哔。运行时外扩结果不回写 Gate 1 已确认的 `sensitivity.json`。

## Step 1:生成 base.wav

默认使用 `vocals + bgm`。只对人声轨的敏感区间静音,背景轨全程保留:

```bash
"$FFMPEG_BIN" -y \
  -i "${WORK}/${BASE}_vocals.mp3" \
  -i "${WORK}/${BASE}_bgm.mp3" \
  -filter_complex \
  "[0:a]volume=0:enable='${SENSITIVE_EXPR}'[voc];\
[voc][1:a]amix=inputs=2:duration=first:normalize=0[base]" \
  -map "[base]" \
  -t "$DUR" \
  -fs 209715200 \
  -c:a pcm_s16le \
  "${WORK}/${BASE}_base.wav"
```

### original_audio 底轨回退路径

若 `bgm.mp3` 丢失关键环境声、游戏音效或转场声,使用原始音轨做底轨:

```bash
"$FFMPEG_BIN" -y \
  -i "${WORK}/${BASE}_original_audio.m4a" \
  -filter_complex \
  "[0:a]volume=0:enable='${SENSITIVE_EXPR}'[base]" \
  -map "[base]" \
  -t "$DUR" \
  -fs 209715200 \
  -c:a pcm_s16le \
  "${WORK}/${BASE}_base.wav"
```

输入本来是本地视频时可直接把视频作为第 0 路输入。输入是 URL 时,仅在需要回退时
下载或提取原始音轨,不要预先无脑落盘。

## Step 2:生成 beep.wav

`sine` 默认峰值约为 `-18dB`,所以必须显式补 `+18dB`。门控规则是:

- 非敏感区间: `volume=0`
- 敏感区间: 保留 sine
- 禁止使用 `volume=if(...)`

```bash
"$FFMPEG_BIN" -y \
  -f lavfi \
  -i "sine=frequency=1000:sample_rate=${SR}:duration=${DUR}" \
  -filter_complex \
  "[0:a]volume=0:enable='${NON_SENSITIVE_EXPR}',\
volume=18dB,\
pan=stereo|c0=c0|c1=c0[beep]" \
  -map "[beep]" \
  -t "$DUR" \
  -fs 209715200 \
  -c:a pcm_s16le \
  "${WORK}/${BASE}_beep.wav"
```

这里必须用 `NON_SENSITIVE_EXPR`。如果误用 `SENSITIVE_EXPR`,会把应该发声的敏感窗口
静音。

## Step 3:最终混音

```bash
"$FFMPEG_BIN" -y \
  -i "${WORK}/${BASE}_base.wav" \
  -i "${WORK}/${BASE}_beep.wav" \
  -filter_complex \
  "[0:a][1:a]amix=inputs=2:duration=first:normalize=0,\
alimiter=limit=0.97:level=disabled[out]" \
  -map "[out]" \
  -t "$DUR" \
  -fs 209715200 \
  -c:a aac -b:a 192k \
  "${WORK}/${BASE}_output.m4a"
```

`alimiter` 只限制叠加后的削波,不自动拉升全片音量。禁止删除以下两道硬护栏:

- `amix=duration=first`
- 输出侧 `-t "$DUR"` 和 `-fs 209715200`

## 生成后直接合流(不自检、不试听确认)

`beep.wav` 和最终 `output.m4a` 生成后**直接进入视频合流**：不跑 `volumedetect` 自检，也不生成 `preview.mp3` 交给用户人工试听确认。按上面三步把命令一次跑完即可，产物落盘后直接供 [合并.md](合并.md) 的 `mux-audio-video` 使用。

分步产物（`base.wav` / `beep.wav`）仍然保留，但只作为出问题时的排查隔离点，不是强制验收或用户确认关卡。

## 已知错误

1. **忘记 `+18dB`**: `sine` 默认输出过轻,混入背景后像没有 beep。
2. **门控方向反了**: beep 轨必须在非敏感区间静音,不能在敏感区间静音。
3. **使用 `volume=if(...)`**:当前链路已验证容易生成近静音轨,禁止恢复。
4. **恢复 `adelay` 多路拼装**:会重新引入 fade 时基、输入索引和多路 amix 排查问题。
5. **`enable` 引号错误**:固定使用外双内单:

   ```bash
   -filter_complex "...enable='between(t,1,2)+between(t,3,4)'..."
   ```

6. **一步混十几路**:即使命令成功也难以确认哪一路丢失。正式方案必须分别生成
   `base.wav`、`beep.wav`,再二次混音。

## 特殊情况

- `sensitivity.json` 为空:不重混音频,直接保留原视频音轨。
- `bgm.mp3` 为空或音效明显丢失:切换到 `original_audio` 底轨。
- 中间 WAV 或最终音频逼近 `200MB`:视为触发容量护栏,删除产物并检查时长和参数。
