# 文案校准（Agent 语义融合，生成 subtitles.json）

**触发条件**：输入有硬字幕时强制执行；输入无硬字幕时仅在用户明确需要新字幕时执行。本文直接生成 `add-subtitle-to-video --subtitles` 所需的 `subtitles.json`。**敏感词候选（Step 4）不走这里**，候选仍直接吃 OCR / asr-subtitles / FunASR 原始证据。
**本文涉及的真实 `mediakit-cli` 业务调用都固定前缀 `DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction`。** 不要省略,不要改值,也不要写成 `--DOUBAO_MEDIAKIT_RUNTIME` 业务 flag。

字幕文本错字会让新字幕看起来是"AI 转写"（如 "2026年" 被 ASR 写成"二零二六年"、"iPhone" 写成"爱疯"），也会让画面所见与字幕不符。**只要要压新字幕，就必须走 Agent 语义融合裁决**，不允许直接把 asr-subtitles 原文丢给 `add-subtitle-to-video`。

## 证据来源与启用条件

| 来源         | 命令                                         | 提供什么                                          | 优先级        | 启用条件                                    |
| ------------ | -------------------------------------------- | ------------------------------------------------- | ------------- | ------------------------------------------- |
| 硬字幕 OCR   | `mediakit-cli video video-ocr`               | 画面上烧录的字幕文本（作者已校对）                | 1（最高）     | 雪碧图判定有硬字幕才发；无硬字幕跳过        |
| 句级 ASR     | `mediakit-cli video asr-subtitles`           | 句级 `subtitle_text` + 起止时间                   | 2             | 有音轨即必跑（主线，**输入是分离后的 vocals.mp3**） |
| 词级 ASR     | `scripts/asr_funasr.py`                      | 词级 `start` / `end`，用于打哔精确定位            | 3（仅时间戳） | **优先启用**（默认尝试；装不上按 [环境准备.md](环境准备.md) 让用户在“修环境 / 接受句级插值降级”中二选一） |
| 视频理解语义 | `mediakit-cli video video-understand-router` | 场景语义 + 镜头上下文 + 术语线索，用于纠正专有名词/同音字/场景术语与镜头语境 | 4             | **probe 确认有音轨后与 separate-voice 并行发起，默认必发**（只依赖原视频 URL；无音轨不发） |

优先级只对**文本内容**生效。**时间戳**优先用 FunASR 词级；若 FunASR 不可用且用户明确接受降级，则退回 `asr-subtitles` 句级窗口内均分插值（误差可达 ±150ms），asr-subtitles 始终提供句级窗口作参考。

## 前置：必须先做人声分离

`asr-subtitles` 和 FunASR 都跑在 `separate-voice` 输出的 `vocals.mp3` 上，**不能对原视频/原音轨直接跑 asr-subtitles**——BGM、笑声、掌声、观众声会污染 ASR，导致漏识别脏话或识别成同音字。详见 [音频处理.md](音频处理.md)。

## 提交时机（与 SKILL.md 工作流步骤对齐）

- **Step 1**：`probe-video-metadata` + 雪碧图抽帧（5×5，25 格）+ FunASR 安装（t=0 独立命令进程）（并行）。
- **Step 2**：probe 有音轨 → 并行发起 `separate-voice` + `video-understand-router`；同时判横竖片、选字幕位置预设。
- **Step 3**：雪碧图判定结果——
  - **有硬字幕** → 设置 `MUST_REBUILD_SUBTITLES=true`，执行 `video-ocr --mode Detailed` 并归纳框；Gate 1 前不提交 erase。
  - **无硬字幕** → `video-ocr` 跳过，在 Gate 1 回复中询问用户是否要压新字幕。
- **音频线**（独立并行）：`separate-voice` 产 `vocals.mp3` → 并行 `asr-subtitles`（对 vocals）+ FunASR（对 vocals）。
- **Step 4 敏感词候选**：直接吃各路原始文本（OCR / asr-subtitles / FunASR），**不走文案校准**。
- **Step 5-7**：Gate 1 跨回合确认 → erase（一次擦完即完成）与 base/sine beep 并行 → mux-audio-video（beep/混音生成后直接合流，不自检、不试听确认）。
- **Step 8 文案校准**（本文档主流程）：有硬字幕时强制执行，Agent 语义融合裁决产 `subtitles.json`。
- **Step 9**：`add-subtitle-to-video` 消费 `subtitles.json`。有硬字幕时只有其终态结果可交付。
- **video-understand-router** 在 probe 确认有音轨后与 separate-voice 并行发起（默认必发），Step 4 场景裁定、Step 8 融合场景消歧都直接取其结论。**Step 8 不只拿它判断“敏不敏感”，还要拿它补镜头上下文、人物称呼、游戏/UI/品牌术语和同音字消歧线索。**

## video-ocr 命令

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video video-ocr --video-url <原始视频>
```

`query-task --poll-complete` 后读 `result` 内的 OCR 文本条目（含 `text` 与出现时间段）。Agent 从条目位置和内容判定是否是字幕（长句、时间连续、位置稳定），忽略台标、弹幕、logo、UP 主水印等。

## 校准逻辑（Agent 语义融合裁决）

**核心理念**：OCR、asr-subtitles、FunASR、video-understand 都是**证据**，不是**权威**。任何一路都可能有错（OCR 误识别 / 断句错、ASR 数字读汉字 / 同音字、FunASR 词级漂移）。**由 Agent 逐句用语义连贯性 + 常识判断产出终稿**，不做机械的"整段替换"或"硬优先级取一路"。

对每条 `asr-subtitles` 句子（时间窗 `[s, e]`）执行以下裁决：

### 1. 收集证据

- **OCR 候选**：所有与 `[s, e]` **时间戳有任何重叠**的 OCR 条目（不设 80% 覆盖率之类的机械阈值）。可能是 0、1、或多条 OCR 落在同一 ASR 窗内（也可能一条 OCR 横跨多个 ASR 窗）。
- **ASR 文本**：本条 `asr-subtitles` 的 `subtitle_text`。
- **FunASR 词级**（如启用）：`[s, e]` 内的词级 words。
- **视频理解线索**（如启用 video-understand）：当前镜头场景（游戏 / 医疗 / 新闻等）、人物/物体名称、品牌/产品名、界面术语、动作上下文、镜头主题摘要。

在逐句裁决前，先从 video-understand 结果里抽一份**镜头术语表**，至少包含：

- 人物/角色称呼
- 品牌名、产品名、App/游戏名
- UI 文案、玩法术语、技能名、关卡名
- 时间/地点/机构名等专有名词

这份术语表不是直接输出字幕，而是作为 OCR/ASR/FunASR 冲突时的**消歧证据**。

### 2. Agent 语义裁决产出 `text`

Agent **不做整段替换**，而是逐句用下列规则理解 + 融合：

- **画面所见为准**（OCR 是作者校对过的字幕原文）：OCR 与 ASR 冲突时**默认信 OCR**，除非 OCR 明显错误。
- **数字/英文/专有名词一律跟 OCR**：如画面写 "2026"，即便 ASR 说"二零二六"，也写 "2026"；画面写 "iPhone"，ASR 说"爱疯"，写 "iPhone"。
- **视频理解可提升专有名词判定置信度**：若 OCR 与 ASR 都不稳定，但 video-understand 明确给出镜头主题/术语（如游戏技能名、品牌名、人物名），可据此把同音词收敛成更合理的文本。
- **允许 Agent 主动纠 OCR 错误**：
  - 一条 OCR 明显包含**下一句字幕的串入内容**（如 "咋的啦2026年就播两回多了"，"多了" 若在本句时间窗末尾且下一 OCR 条起点很近，判为串入 → 删掉）→ 截取本句实际对应的部分。
  - OCR 断句错误（把两句连在一起）→ 按 ASR 时间戳切分。
  - OCR 明显别字/繁简混淆 → 结合语境改。
- **允许 Agent 用 ASR 补 OCR 缺失**：OCR 没识别到的整句，用 ASR 兜底。
- **允许 Agent 用 ASR 补 OCR 错识**：OCR 把"河南"识成"河雨"，ASR 是"河南"，按常识选"河南"。
- **场景消歧**（有 video-understand 时）：游戏视频里的"艹"当"操作"用不算敏感，医疗视频里的"死了"不当脏话。
- **镜头术语优先于机械同音替换**：若 ASR 听成同音字，但 video-understand 已表明当前镜头在讲某款游戏、某个角色、某个品牌或某项技能，优先把文本收敛到该术语体系，避免生成“语音上像、语义上不通”的字幕。

**禁止**：不要因为"OCR 时间窗与 ASR 时间窗对不齐 ≥ X%"就整段回退到 ASR（这是之前"二零二六年就播两回"走 ASR 的错误模式）。时间戳只是参考，**语义连贯性优先**。

### 3. 时间戳选择（与 text 选择解耦）

- `[s, e]` **句级窗口**：用本条 asr-subtitles 的 `start_time` / `end_time`。
- **词级时间戳**（打哔硬依赖）：
  - 有 FunASR → 从 `words[]` 中取 `[s, e]` 内的字，按字符顺序对齐 `text` 里的每个字；字数不一致时多字丢弃、少字线性插值。
  - 无 FunASR → 按 `text` 字数均分：`word.start = s + i / N * (e - s)`。

**关键**：`text` 可以来自 OCR / ASR / 融合；时间戳默认以 ASR 句级 + FunASR 词级为准，若 FunASR 不可用且用户接受降级，则回退到 ASR 句级窗口内的均分插值。画面上字幕的时间戳有时会晚于口播 200-500ms，用 OCR 时间戳做打哔会漏。

### 4. 写入 `subtitles.json`

```json
[
  {
    "subtitle_text": "2026年就播两回",
    "start_time": 17.08,
    "end_time": 18.44
  }
]
```

每项只能使用 `subtitle_text`、`start_time`、`end_time` 三个字段。写出前按 Gate 1 已确认的敏感词做等字数 `*` 替换；未确认候选不得替换。数组为空、时间倒置或缺字段都不能提交字幕压制。

## 边界情况

- OCR / video-understand 未启用 → 按上表优先级顺延使用 asr-subtitles 主线。
- `asr-subtitles` 终态为空或字段异常 → 在 Gate 1 和 erase 前停止，报告 ASR 异常；不得只靠 FunASR/OCR 静默完成成片。
- FunASR 失败但 `asr-subtitles` 正常 → 让用户选择修环境或接受句级插值降级；用户未选择前停止。
