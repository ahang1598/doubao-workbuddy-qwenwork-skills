# 字幕处理

前置：[前置探测.md](前置探测.md) 已确认画面有硬字幕。
**本节所有真实的 `mediakit-cli` 业务调用都固定前缀 `DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction`。** 不要省略,不要改值,也不要写成 `--DOUBAO_MEDIAKIT_RUNTIME` 业务 flag。

擦除按 [erase-video-subtitle-pro](byted-mediakit-video/reference/erase-video-subtitle-pro.md) 调用。去敏字幕由 AI 写成 `subtitles.json`，对接 [add-subtitle-to-video](byted-mediakit-editing/reference/add-subtitle-to-video.md) 的 `--subtitles`。不要生成 ASS，也不要传 `--subtitle-url`。

**检测到硬字幕即设置 `MUST_REBUILD_SUBTITLES=true`。** 这条分支固定是“识别原字幕 → Gate 1 用户确认敏感词 → 擦除 → 合流 → 重压去敏字幕”，不再询问用户是否需要新字幕。擦除后或合流后的无字幕视频只能作为中间产物，禁止交付。

## 擦除（OCR 定位一个框，一次擦完，走 mediakit）

字幕擦除**只用 mediakit 的 `erase-video-subtitle-pro`**，不要用 ffmpeg 或其它方式擦画面文字。`video-ocr` 与 `erase-video-subtitle-pro` 的 `--video-url` 支持 **HTTP/HTTPS URL、本地文件路径**两种——原视频是链接就原样传,不用先下载到本地。

**核心:一次调用擦完，不分时段、不发多个任务。** Gate 1 前只执行 `video-ocr --mode Detailed` 并归纳擦除框；收到用户下一条消息明确确认敏感词后，才一次提交 `erase-video-subtitle-pro`。

**为什么带框而不是裸发**:裸发 `--mode Subtitle` 不带框时,服务端 OCR 自动定位可能误擦抖音水印/台标/UP 主标签(实测反复出问题)。给了框就限定搜索范围,规避误擦。

**为什么一次就够**(官方文档实证,见 [erase-video-subtitle-pro.md](byted-mediakit-video/reference/erase-video-subtitle-pro.md)):

- `--erase-ratio-location` 一次支持**最多 20 个框**,y 漂移分散也放一次调用里,不用切多个任务。
- Subtitle 模式**只擦"框内 ∩ 下半屏 ∩ OCR 判定是字幕"的文本**——框大一点覆盖到没字幕的位置也不会误擦,所以不必按时段精细切。
- `--time-segment-filter` 的用途是"只擦正片、保留片头/片尾字幕",**本任务不需要保留,就不传它**。

### Step A：Detailed OCR 拿字幕/水印分类（1-2 分钟）

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video video-ocr \
  --video-url <原始视频> \
  --mode Detailed
```

- `--mode Detailed` 每条文本带 `text_label`（`Subtitle` / `Others`）+ `text_location`（像素坐标）。
- 只保留 `text_label == "Subtitle"` 的条目算框；`Others` 类（抖音水印、台标、UP 主标签）**必须排除**,不进框。
- 抖音水印典型位置 y ≈ 0.877-0.981；擦除框下界应留 ≥ 0.19 安全间隔,别把水印圈进去。

### Step B：OCR × ASR 交叉确认，再归纳成擦除框（通常 1 个，最多 20 个）

**不能单纯信 OCR**：`--mode Detailed` 会**多识别**——把弹幕、UI 文字、场景招牌、甚至画面里一闪而过的非对白文字也标成 `Subtitle`。若直接拿这些去算框,框会被撑大、误擦正常画面。**必须结合 ASR 确认**:

1. 拿 `asr-subtitles`(跑在 `vocals.mp3` 上,见 [音频处理.md](音频处理.md))的句级文本 + `start_time/end_time`。
2. 对每条 OCR `Subtitle` 条目,看**同一时间点附近 ASR 是否有对应人声文本**(文字大致对得上、时间窗重叠)。
   - **OCR 有 + ASR 有** → 真字幕,进框。
   - **OCR 有 + ASR 无**(该时刻没人说话) → 大概率是 OCR 多识别的非字幕文字,**不进框**。
3. 用**确认后的**字幕条目算**最小外包框**(x/y 的 min-max,上下各留 0.012 余量)当**一个框**。

只有当确认后的字幕位置**明显分成几簇**(如上半屏对白 + 下半屏解说,y 差距大到一个框会圈进大片无字幕区)时,才按簇合并成**多个框**(≤20),放进同一个 `--erase-ratio-location` 数组。**不要一簇一任务,更不要按时间切段。**

> 交叉确认让擦除框只圈"真·对白字幕",既防 OCR 多识别撑大框误擦,也和音频打哔用的是同一套 ASR 证据,时间轴一致。

### Step C：一次提交擦完

仅在 Gate 1 已收到用户明确确认后执行：

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video erase-video-subtitle-pro \
  --video-url <原始视频> \
  --mode Subtitle \
  --model-version v5 \
  --erase-ratio-location '[{"top_left_x":0.05,"top_left_y":0.56,"bottom_right_x":0.95,"bottom_right_y":0.69}]'
```

Windows PowerShell：

```powershell
$env:DOUBAO_MEDIAKIT_RUNTIME="scene-video-redaction"
mediakit-cli video erase-video-subtitle-pro --video-url "C:\path\video.mp4" --mode Subtitle --model-version v5 --% --erase-ratio-location "[{\"top_left_x\":0.05,\"top_left_y\":0.56,\"bottom_right_x\":0.95,\"bottom_right_y\":0.69}]"
```

- `--erase-ratio-location`:**一个框**就是数组里一个对象;位置分散时追加更多对象(≤20),仍是这**一次**调用。POSIX / bash 用单引号整体包裹；Windows PowerShell 必须把该 flag 放在 `--%` 后并转义内部双引号，禁止 `$json` 变量。
- `--mode Subtitle`(默认):框内 ∩ 下半屏,OCR 认定是字幕才擦。
- `--model-version v5`:阴影字幕、误擦、闪烁都优于默认 v4。
- **不传 `--time-segment-filter`**(不需要保留片头片尾)。
- **不发多个任务**:`query-task --poll-complete` 拿这一个任务的 `result.video_url`。
- 不要用非 pro 的 `erase-video-subtitle`。

### 残留才补框(例外,不是默认)

首轮一次擦完后**默认视为完成**，不抽验收帧、不做人工确认。**仅当**最终成片阶段肉眼发现残留(如竖屏内容装横屏画布、字幕落到画布上半屏没被框住),才调整/追加框**重提一次**。默认永远是"一次调用"。

参数吃不准先 `erase-video-subtitle-pro --help` 或 `--schema`;`video-ocr --schema` 看 Detailed 模式返回结构。

## 擦除产物直接进合流（不抽验收帧）

`erase-video-subtitle-pro` 返回 `result.video_url` 后直接传给 [合并.md](合并.md) 的 `mux-audio-video`。擦除框已由 `video-ocr --mode Detailed` × ASR 交叉确认归纳，Subtitle 模式只擦"框内∩下半屏∩OCR判定是字幕"，不再单独抽帧验收。

## 新字幕压制（合流之后）

见 [合并.md](合并.md)。字幕压制**只用 mediakit 的 `add-subtitle-to-video`**，`--subtitles` 传 `subtitles.json`。**调用前必须先读 `byted-mediakit-editing/reference/add-subtitle-to-video.md`**，尤其确认 `subtitle_pos_preset` / `subtitle_font_size` 的约束；`add-subtitle-to-video` **只有预设位置 `--subtitle-pos-preset`（bottom_center/top_center/center/lower_third）+ 像素字号 `--subtitle-font-size`，没有自定义 x/y 坐标参数**——不要臆造 `--subtitle-pos-x/y`。

输入有硬字幕时本步骤是 **Gate 2 必做项**。只有任务终态成功返回的新 `result.video_url` 才能称为成片；失败时报告失败并保留中间产物用于重试，不能改成交付无字幕版本，也不能在交付后再问用户要不要压字幕。

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli editing add-subtitle-to-video \
  --video-url <擦除并合流后的视频> \
  --subtitles '<subtitles.json 数组>' \
  --subtitle-font-color "#FFFFFFFF" \
  --subtitle-font-size <subtitle_font_size_px> \
  --subtitle-pos-preset <横屏 bottom_center | 竖屏 lower_third>
```

Windows PowerShell 必须把所有普通参数放在 `--%` 前，把 `--subtitles` 及内联 JSON 放在其后：

```powershell
$env:DOUBAO_MEDIAKIT_RUNTIME="scene-video-redaction"
mediakit-cli editing add-subtitle-to-video --video-url "C:\path\muxed.mp4" --subtitle-font-color "#FFFFFFFF" --subtitle-font-size <subtitle_font_size_px> --subtitle-pos-preset bottom_center --% --subtitles "[{\"start_time\":0,\"end_time\":3,\"subtitle_text\":\"大家好\"}]"
```

- Windows 禁止 `--subtitles $json`、`--subtitles "$json"`、`Get-Content` 或 `@file.json`；必须把实际完整字幕数组直接内联到命令中。
- **位置**：只按横竖片二选一——横屏 `bottom_center`、竖屏 / 方屏 `lower_third`。不要从帧里读原字幕位置或算 content_box，那样容易把字幕压到画面顶部（详见 [前置探测.md](前置探测.md#新字幕字号--位置仅用于-add-subtitle-to-video)）。
- **字号**：不再固定 `45`。先按 `byted-mediakit-editing/reference/add-subtitle-to-video.md` 校验默认值 `50` 是否满足当前预设的 height/width 约束；满足就优先省略 `--subtitle-font-size`，不满足才显式传入按 [前置探测.md](前置探测.md#新字幕字号--位置仅用于-add-subtitle-to-video) 计算出的 `subtitle_font_size_px`。
- 不要试图自定义 x/y 坐标；CLI 不接受。

参数吃不准跑 `mediakit-cli editing add-subtitle-to-video --help` 或 `--schema` 确认。

只有前置探测判定“无硬字幕”且用户明确不要新字幕时，才跳过 `add-subtitle-to-video`。
