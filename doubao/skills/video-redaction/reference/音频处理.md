# 音频处理

执行本节前,先读 [环境准备.md](环境准备.md)、[敏感词音频处理.md](敏感词音频处理.md) 与 [`../SKILL.md` 的“使用前请阅读”](../SKILL.md#使用前请阅读)。**不做前置环境探测** 仅表示不额外插预检流程;不表示可以先把命令跑错一遍再回来看文档。
**本节所有真实的 `mediakit-cli` 业务调用都固定前缀 `DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction`。** 不要省略,不要改值,也不要写成 `--DOUBAO_MEDIAKIT_RUNTIME` 业务 flag。

音频线先 **必跑** `separate-voice`（人声/背景音分离），再对分离出的**人声轨**跑 `asr-subtitles` 与 FunASR。`asr-subtitles` 是主线；FunASR **默认尝试启用**，若装不上则按 [环境准备.md](环境准备.md) 让用户在“修环境 / 接受句级插值降级”中二选一。**不允许对原视频/原音轨直接跑 asr-subtitles**——BGM、笑声、掌声、观众声会污染 ASR，导致漏识别脏话或识别成同音字，后续打哔和字幕都会错。

Cloud 查询协议见 `SKILL.md`：提交拿到 `task_id` 后执行 `query-task --poll-complete`。CLI 约 9 分钟自动退出，未完成则用同一 `task_id` 再查。

## 第一步：separate-voice（必跑，先做）

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli audio separate-voice \
  --video-url <本地视频路径或 URL> \
  --output-format mp3
```

纯音频把 `--video-url` 换成 `--audio-url`(两者都支持 HTTP/HTTPS URL、本地文件路径,原视频是链接就不用先下)。读到 `task_id` 后 `query-task --poll-complete`；终态字段 `result.voice_audio_url` / `result.background_audio_url`。**这里要下载**为 `<basename>_vocals.mp3` / `<basename>_bgm.mp3`——因为下游是 **ffmpeg 本地混音** 和**本地 FunASR 脚本**,它们读本地文件更稳(不像 mediakit 那样传 URL 就行)。

`vocals.mp3` 供下一步 `asr-subtitles` 和 FunASR 共用；`bgm.mp3` 默认供 [敏感词音频处理.md](敏感词音频处理.md) 的本地 `ffmpeg` 混音步骤使用。**但 `bgm.mp3` 可能因源片质量、声道布局和用户环境差异丢失部分环境音/音效**；若听感明显受损,允许按 [敏感词音频处理.md](敏感词音频处理.md#original_audio-底轨回退路径) 回退到 `original_audio` 底轨路线。

### `original_audio` 回退准备(只在需要时执行)

如果输入本来就是**本地视频路径**,直接把原视频文件当作 `original_audio` 源即可,不需要额外导出音轨。

如果输入是 **HTTP/HTTPS URL**,且抽查分离出的 `bgm.mp3` 发现丢了关键环境声/音效,再一次性落本地原始底轨:

```bash
FUNASR_HOME="$HOME/.local/share/funasr_env"
IFS= read -r FFMPEG_BIN < "$FUNASR_HOME/.ffmpeg"
"$FFMPEG_BIN" -y \
  -i "<原视频 URL>" \
  -vn \
  -t "$DUR" \
  -fs 209715200 \
  -c:a aac -b:a 192k \
  "<输出目录>/<basename>_original_audio.m4a"
```

这个文件只给 [敏感词音频处理.md](敏感词音频处理.md#original_audio-底轨回退路径) 的底轨回退方案使用。**不要预先无脑导出**;只有在抽查 `vocals + bgm` 分离结果确认“关键音效 / 环境声丢失或断层”时才补这一步。

## 第二步：asr-subtitles + FunASR（对人声轨并行）

拿到人声轨之后，两路并行。注意两路对输入的要求不同:

- **asr-subtitles 是 mediakit 工具**,`--audio-url` 直接传上一步的 `result.voice_audio_url`(HTTP URL)即可,**不用等本地下载**。
- **FunASR 是本地脚本**,读本地 `vocals.mp3` 路径,依赖上面那步的下载。

### asr-subtitles（句级 + 主文本）

```bash
DOUBAO_MEDIAKIT_RUNTIME=scene-video-redaction mediakit-cli video asr-subtitles \
  --audio-url <voice_audio_url 或本地 vocals.mp3> \
  --language cmn-Hans-CN
```

`query-task --poll-complete` 后使用 `result.subtitles[]`：`subtitle_text`、`start_time`、`end_time`（秒）。语种只用文档枚举（中文 `cmn-Hans-CN`，英文 `eng-US`），不确定就省略让算法探测。需要打哔粒度评估时加 `--enable-confidence=true`。

**结果校验是硬门**：终态必须存在非空 `result.subtitles[]`，且至少一项有非空 `subtitle_text` 和合法的 `start_time < end_time`。空数组、缺字段、全空文本都视为 ASR 失败；不得继续生成候选或用 video-understand 猜对白。若任务尚未终态，继续查询同一 `task_id`；若终态为空，停止并告知用户。

### FunASR(词级时间戳,默认尝试启用)

**前置**:FunASR 安装在**会话一启动就已通过当前平台的独立 `setup.sh` 或 `setup.ps1` 命令发起(只此一次)**,见 [环境准备.md](环境准备.md)。这里检查 guard 文件 `.ready`，就绪后从同目录的 `.python` 读取解释器路径；没就绪就等会话开头那个 setup 命令进程跑完——**不要在这里再调用 setup**。若最终装不上,按阶梯(系统 → venv → 告知用户)处理,由用户在“修环境 / 接受句级插值降级(不准)”中二选一;**不要静默降级**。**禁止**裸 `python scripts/asr_funasr.py`(会回落到没装依赖的系统解释器)。

macOS / Linux:

```bash
FUNASR_HOME="$HOME/.local/share/funasr_env"
IFS= read -r FUNASR_PY < "$FUNASR_HOME/.python"
"$FUNASR_PY" scripts/asr_funasr.py <basename>_vocals.mp3 \
  -o <输出目录>/transcription.funasr.json \
  --language Chinese
```

Windows PowerShell:

```powershell
$FUNASR_HOME = Join-Path $env:LOCALAPPDATA "funasr_env"
$FUNASR_PY = Get-Content "$FUNASR_HOME\.python" -TotalCount 1
& $FUNASR_PY scripts/asr_funasr.py <basename>_vocals.mp3 `
  -o <输出目录>\transcription.funasr.json `
  --language Chinese
```

常用参数:`--device auto|cpu|cuda:0`、`--language Chinese|English`。VAD 用 `fsmn-vad`。ModelScope 已缓存 `paraformer-zh` 则直接加载(缓存位置见 [环境准备.md 模型缓存](环境准备.md#模型缓存))。

Windows 的 `$FUNASR_PY` 指向 `%LOCALAPPDATA%\funasr_env\Scripts\python.exe` 或已满足依赖的系统 Python，不依赖 Bash。

FunASR 输出同样必须校验：`segments[]` 非空，且敏感词定位所需片段必须有非空 `words[]`。不满足即视为 FunASR 失败，必须让用户选择修环境或接受句级插值降级，不能静默继续。

FunASR `words[]` 与 asr-subtitles 句级窗口先作为 Step 4 的原始证据参与敏感词候选；需要字幕时，再按 [文案校准.md](文案校准.md) 融合生成 `subtitles.json`。

## base.wav 用到的 BGM

默认混音（[敏感词音频处理.md](敏感词音频处理.md)）先把敏感区间静音后的 `vocals` 与 `bgm` 合成 `base.wav`,再单独生成 sine `beep.wav`,最后二次混音。`separate-voice` 已产出 `bgm.mp3`,先走默认路线；若**抽查 `bgm.mp3` 分离结果**出现“关键音效 / 枪声按钮音环境声明显消失 / 转场声断层”,就**直接切到** `original_audio` 打孔生成 `base.wav` 的保守路线。仍必须先分离,不能省 `separate-voice` 这一步,因为 ASR 和候选敏感词时间戳都依赖 `vocals.mp3`。
