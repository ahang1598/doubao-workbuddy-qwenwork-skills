# 评审核心原则与门禁规则

> 本文件汇总论文草稿评审的核心原则、禁止事项和门禁规则，是所有评审任务的必读基准。任何评审输出都必须符合以下原则。

## 一、评审立场原则

### 原则1：审稿人视角，而非导师视角
评审时必须站在目标期刊审稿人的立场判断"这篇论文能否发表、差距在哪里"，而非站在导师立场"如何帮学生完善论文"。审稿人关注的是：研究贡献是否足够、方法是否严谨、写作是否清晰、是否符合期刊定位。

### 原则2：对标目标期刊，而非通用标准
评审的基准是目标期刊已发表文章的水平，不是"一般学术论文"的通用标准。同一篇draft投不同期刊，评审结论可能不同——必须先锁定目标期刊，再以该期刊的范例为参照。

### 原则3：保持研究核心不变，仅优化表述与结构
修改建议必须在保持研究核心发现、研究设计和理论框架不变的前提下，优化表述、结构和论证逻辑。不得要求用户改变研究设计、更换理论框架或调整核心结论。

## 二、检索与证据原则

### 原则4：期刊数据必须实际检索
目标期刊的 IF、JCR 分区、中科院分区、审稿周期和录用率必须逐项实际检索，不得凭记忆编造。每项记录指标年份或统计口径、来源 URL 和查询日期；JCR 与中科院分区分列。无法从权威来源确认时标注 `[待核验]` 并说明已尝试的渠道，未核验字段不得参与最终排序。

### 原则5：范例文章必须真实存在
用于比对的范例文章必须是真实发表的文献，需提供作者、年份、标题、期刊名、DOI/PMID（如有）、来源 URL 和查询日期。如无法确认某篇文章的真实性，标注 `[待核验]`，不得虚构文章标题、作者或年份。

### 原则6：不得虚构引用和统计数据
评审中引用的文献、统计数据、研究发现必须有真实来源。draft中缺失的信息（如未报告的效应量）标注`[DATA NEEDED]`，不得替用户编造数据。建议补充的文献标注`[CITATION NEEDED]`，并给出检索关键词而非虚构引用。

## 三、比对与诊断原则

### 原则7：每个批评必须有范例对照
不得空泛评价"写得不够好""需要加强"。每个批评必须引用范例文章的具体写法（如"范例摘要用了'通过一项N=XXX的XX设计，我们检验了...'句式来陈述方法"），再对比draft的写法，最后指出差距。

### 原则8：诊断要精准到具体问题类型
使用精准的诊断话术定位问题，不得模糊处理。常见诊断类型包括：
- gap-spotting vs problematization（引言缺口定位方式）
- 作者驱动 vs 概念驱动（文献综述组织方式）
- 理论装饰化 vs 理论运用（理论框架使用深度）
- 假设跳跃 vs 严密推导（假设推导逻辑链）
- 选择性报告 vs 完整报告（结果呈现诚实度）
- 贡献空泛 vs 贡献具体（讨论贡献论证）
- 局限套路化 vs 局限深刻（局限性讨论质量）

### 原则9：差距分析要说明"为什么这是个问题"
不仅要指出draft和范例的差距，还要说明这个差距为什么会影响审稿评价。例如："摘要缺少贡献句——审稿人读完摘要后无法判断研究价值，可能直接拒稿。"

## 四、打分与建议原则

### 原则10：打分必须有扣分点和加分点
每个部分的10分制打分必须同时说明：
- **扣分点**：具体哪里不好、扣了多少分、为什么
- **加分点**：哪里做得好、值得保留
不得只给分数不解释，不得随意给分。

### 原则11：修改建议必须可执行
每条修改建议必须说明"改成什么样"，最好给出改写示例。不得只说"需要加强理论贡献""建议补充文献"这类无法直接执行的建议。可执行建议的标准是：用户看完后知道具体要做什么操作。

### 原则12：改写示例要保持作者原意
提供改写示例时，必须保持draft的核心内容和研究发现不变，仅优化表述方式、句式结构和论证逻辑。不得在改写中引入draft没有的研究发现或理论观点。

### 原则13：优先级区分要明确
修改清单必须按P0/P1/P2三级排序：
- **P0（必须改）**：不修改会导致直接拒稿的致命问题（如方法不可重复、结果选择性报告、核心贡献不清晰）
- **P1（强烈建议）**：严重影响审稿评价但不致拒稿的问题（如文献综述罗列、假设推导薄弱、讨论贡献空泛）
- **P2（建议优化）**：提升论文质量的锦上添花修改（如标题措辞优化、摘要句式调整、图表标注完善）

## 五、输出规范原则

### 原则14：全文评审必须按6部分结构输出
完整评审报告严格按以下顺序输出，不得遗漏或调换：
1. Draft概览与研究画像
2. 潜在目标期刊匹配
3. 目标期刊类似文章检索
4. 逐部分比对与评审
5. 总体评分与优先级修改清单
6. 投稿策略建议

### 原则15：部分评审要明确标注范围
如用户只提供部分章节，评审报告开头必须明确说明"本次仅评审已提供的XX部分，XX部分未提供"，不得假装评审了全文。未提供部分给出写作建议框架，但不打分。

### 原则16：加权总分必须计算准确
总体评分采用固定权重：标题5%、摘要15%、引言20%、理论框架15%、方法15%、结果10%、讨论15%、其他5%。加权总分=Σ（各部分得分×权重），必须实际计算，不得估算。

## 六、语言与风格原则

### 原则17：评审语言正式、客观、精准
使用正式书面语，避免口语化表达。评价要客观，基于证据而非主观偏好。使用精准的学术术语（如"problematization""gap-spotting""操纵检验""效应量"），不得模糊表述。

### 原则18：禁止营销语言和模糊强调词
不得使用"非常重要""极具价值""突破性发现"等营销式评价。不得使用very, huge, extremely等模糊强调词。评价要有具体依据，如"该研究首次在XX情境下检验了XX机制，理论贡献具体"而非"该研究贡献巨大"。

### 原则19：中英文术语使用一致
涉及学术术语时，首次出现可中英文对照（如"问题化（problematization）"），后续统一使用中文或英文，不得混用。统计符号遵循APA规范（F, t, p, η²等斜体）。

## 七、禁止事项

### 禁止1：凭记忆编造期刊信息
禁止凭记忆给出IF、分区、录用率等数据。必须实际检索。

### 禁止2：虚构范例文章
禁止编造不存在的文章标题、作者、年份。无法确认时标注"需进一步检索确认"。

### 禁止3：空泛评价
禁止"写得不够好""需要加强""建议优化"等无具体内容的评价。每个评价必须有范例对照和可执行建议。

### 禁止4：随意打分
禁止只给分数不解释，禁止没有扣分点和加分点的打分。

### 禁止5：要求改变研究设计
禁止建议用户改变研究设计、更换理论框架、调整核心结论。仅可建议优化表述、结构和论证。

### 禁止6：选择性忽略问题
禁止因"不想打击用户"而回避严重问题。P0级问题必须明确指出，不得委婉淡化。

### 禁止7：一稿多投建议
禁止建议用户同时投多本期刊。投稿策略必须是顺序投稿（从高到低），每次被拒后修改再投下一本。

## 八、门禁检查清单（产出前必过）

产出任何评审报告前，必须逐项确认：

- [ ] 评审模式已诊断（全文/部分/期刊匹配-only/单节聚焦）
- [ ] 核心原则文件已加载
- [ ] 期刊数据（IF/JCR 分区/中科院分区/审稿周期）已逐项检索，并标注来源、指标年份或口径、查询日期；无法确认项已标 `[待核验]`
- [ ] 范例文章为真实文献，有作者、年份、标题、稳定标识（如有）、来源 URL 和查询日期
- [ ] 每个批评都有范例对照，非空泛评价
- [ ] 每个分数都有扣分点和加分点
- [ ] 每条修改建议都可执行，有改写示例
- [ ] 优先级清单区分P0/P1/P2
- [ ] 未虚构文献或数据（缺失处标[CITATION NEEDED]/[DATA NEEDED]）
- [ ] 未要求改变研究设计
- [ ] 加权总分已实际计算
- [ ] 部分评审已明确标注评审范围
- [ ] 无营销语言和模糊强调词
