# PDF 转飞书文档

> ⚠️ **先读完再动手**：未读到末行 `===== 全文完 =====` 标记，即视为未读完；必须调整 `offset` 继续读取，直至出现该标记。

模型可以直接读取 PDF 页面并生成飞书 XML。本文档只说明一件事：**如何正确处理公式、表格、图片这几类容易出错的元素，以及飞书 XML 的几个常见陷阱。**

其余内容（正文段落、标题、列表、粗体、斜体、代码块、书签）按照 `lark-doc/references/lark-doc-xml.md` 中的通用规则编写即可。

### 命中信号

用户提供 PDF，且交付目标是**飞书云文档**（Docx 或 Wiki）时，使用本流程。命中关键词包括 `飞书文档`、`飞书云文档`、`lark doc`，以及包含 `feishu.cn/docx/...` 或 `larkoffice.com/docx/...` 的 URL。若目标是 `.docx` 格式的 Word 文件，则使用 [pdf-to-word.md](pdf-to-word.md)，不使用本流程。

### 按阶段必读

- `lark-doc/SKILL.md`
- `lark-doc/references/lark-doc-xml.md`（飞书 XML 语法）
- `lark-doc/references/lark-doc-update.md`（分批 `append`、`str_replace`、`block_replace` 等）
- `lark-doc/references/lark-doc-media-insert.md`（图片上传）

用户未提供目标文档时，先使用 `docs +create` 创建一篇空文档；不得将 PDF 内容直接追加到用户已有的正文中。

### 一、公式 → `<latex>`

公式必须使用飞书原生 `<latex>...</latex>`；禁止以纯文本近似（如 `x^2 + 1`）、Unicode 上下标（如 `x²`）或截图代替，也不得创建空 `<latex>`。

**识别**：先检查源页面。数学字体名（`CM*`、`MSAM`、`STIX`、`Cambria Math`、`Symbol`）、密集数学符号（`∑ ∫ ∏ √ ± ≤ ≥ ≠ → ∈ ∀ ∃`、希腊字母、上下标嵌套、根号）、分数线特征（水平细线夹在两行小字之间），以及整行居中且右侧带 `(数字)` 或 `(章节.序号)`的文本行。

**转录规则**：

- 同时参考源页面高清渲染图、文本层和字体信息；三者冲突时以可见渲染结果为最终依据，不直接采信可能错误解码的公式字符。
- 上下标、共轭 `\bar`、转置 `^{\top}`、极限 `\lim_{n\to\infty}`、大定界符 `\left(\right)`、分段函数 `\begin{cases}...\end{cases}`、对齐推导 `\begin{aligned}...\end{aligned}`，以及矩阵 `\begin{bmatrix}` 或 `\begin{pmatrix}` 均按源文转录。
- **希腊字母与形近字逐条核对**：`v/ν`、`o/O/0`、`l/1/I`、`ε/ϵ`、`φ/ϕ`。局部无法辨认时，在对应位置使用 `\text{[unclear]}`，并在交付说明中记录 `unclear_source` 的页码、位置和上下文；整条公式无法可靠辨认时，不创建空 `<latex>` 或猜测内容，改用相邻普通段落明确标注“源公式无法可靠转录”，并将其列入未完成项。
- **函数名直立**：`\sin \cos \log \exp \lim \min \max` 使用内置命令（自动直立）；单字母变量默认使用斜体。
- **多字符变量名**使用 `\mathrm{Var}` 或 `\text{if}`，不要写成 `Var`（否则会被当作 `V·a·r`）。
- **疑似原文笔误**（量纲不匹配、明显手误）应**忠实保留**，并在交付说明中单独列为 `source_anomaly`；不要擅自改成正确形式。

**写入 XML**：

- **行内公式** → 与正文写在同一段中：`<p>由 <latex>a=2</latex> 可得...</p>`。
- **独立公式** → 单独成段并居中：`<p align="center"><latex>a^2 = 4</latex></p>`。
- **带编号的独立公式** → 使用 2 列 `<grid>` 承载：左列用居中 `<p>` 放置 `<latex>`，右列用右对齐 `<p>` 放置编号。通过每个 `<column>` 的 `width-ratio` 调整左右占比，默认设为 `0.8 / 0.2`，并可按源版式调整，两列之和必须为 `1`。编号体例（阿拉伯数字、`(3.14)`、`(A.3)` 等）与源文一致；编号本身不要写入 LaTeX，以保留普通文本搜索能力。

**LaTeX 中的 XML 转义**：LaTeX 源码中的 `<`、`>`、`&` **必须写成 XML 实体** `&lt;`、`&gt;`、`&amp;`；花括号 `{}` 无需转义。

```xml
<!-- 错 -->
<latex>a<b</latex>
<latex>P(A&B)</latex>

<!-- 对 -->
<latex>a&lt;b</latex>
<latex>P(A\land B)</latex>
<latex>\begin{aligned}a&amp;=b+c\\&amp;=d\end{aligned}</latex>
```

逻辑“与”优先使用 `\land`；`aligned`、矩阵等 LaTeX 语法中的对齐符 `&` 仍须保留，但在 XML 中写成 `&amp;`。

**LaTeX 元素内禁止嵌套任何 XML 标签**——强调或颜色样式应写在 `<latex>` 外部，或使用 LaTeX 内置命令（如 `\boldsymbol`、`\color{red}`）。

**自检**（交付前逐条检查）：`\begin{X}` 与 `\end{X}` 成对，且 `X` 一致；`\left` 与 `\right` 成对（需要单侧定界符时使用 `\left.` 或 `\right.`）；`\frac{}{}`、`\sqrt{}`、`^{}`、`_{}` 的花括号完整；命令拼写正确（例如 `\sum` 不是 `\Sum`，`\infty` 不是 `\infinity`）。

### 二、表格 → `<table>`

表格必须使用飞书原生 `<table>`；禁止转为段落文本、用制表符拼接的 `<pre>` 或代码块、项目符号列表或整表截图。

**结构要求**：

- 源表存在语义表头时，在 `<thead>` 中使用 `<th>`；没有表头时不要凭空创建。数据行放在 `<tbody>` 中并使用 `<td>`。
- 合并单元格使用 `colspan` 或 `rowspan`，且**只在起始单元格中出现**；被合并的单元格不要重复写入。
- 使用 `<colgroup><col width="..."/></colgroup>` 显式指定列宽，`width` 数值按照源表格的列宽比例反推，不附加未在 `lark-doc-xml.md` 中声明的单位。禁止**无依据**均分；源表本身等宽时可以等分。
- 单元格内如果包含公式，必须仍用 `<latex>`。
- 底纹使用 `background-color` 命名色：基础 7 色、`light-{色相}` 或 `medium-gray`；表格单元格不得使用其他 `medium-*` 值。源文使用飞书不支持的十六进制颜色时，降级为最接近的命名色，并在交付说明中列出“源色 → 落地色”。无法通过飞书 XML 表达的边框颜色也应列入保真妥协。

**跨页表格**：语义连续且服务端可接受时使用一张 `<table>`，并删除续页中重复出现的表头。若单表写入失败或体量过大，则按连续行拆表，每张表重复语义表头并注明“续表”；不得删除数据行。

**超宽表**：不要为了缩窄版面合并不同语义的列。确实无法在文档宽度内清晰呈现时，按列组拆成多张 `<table>`，每张重复主键或标识列，并在正文中明确说明“该表按列分段呈现”。服务端返回容量或结构错误时停止当前批次，根据错误缩小表格或拆分行；当前 `lark-doc-xml.md` 未声明固定列数或单元格数上限，不得编造具体上限。**禁止**降级为 `<pre>` 或代码块。

**目视可见但未被识别的表格**：PDF 中的表格有时没有边框，仅依靠空白对齐。先使用 PyMuPDF `page.find_tables()`，必要时用 pdfplumber 的表格策略复核；仍未识别时，再结合文本 x 起点、行基线、列间空白和语义一致性补建 `<table>`。仅凭 x 坐标聚类不足以判定表格。

### 三、图片 → `<img>`（必须真实上传）

本地图片必须在对应批次 XML 的原位置使用 `<img path="@./relative/path"/>` 上传；公开 HTTPS 图片可使用 `href`，仅复制文档中已有图片时使用 `src` token。禁止用占位文字代替图片、以 `src` 引用本地文件，以及使用 `file://` 或 `data-src`。

**硬性要求**：正文与图片必须同步处理。当前页图片未全部检查或仍有 `recrop` 时，不得完成该页 XML；写入后未逐图预览时，不得继续下一批或交付。

#### 1. 使用脚本批量定位并裁剪

使用`python scripts/locate_pdf_figures.py <source.pdf> --output <out-dir>`，将PDF中的图片裁剪下来。
每轮输出只包含裁剪图，命名为 `page-<四位页码>-image-<两位序号>.png`，例如 `page-0030-image-01.png`。

**注意**
1. 同页裁剪图序号不代表其在原 PDF 中的位置或图号顺序。写入 XML 前，必须实际读取每张裁剪图并逐一对照原页，确认对应图号、裁剪完整性和插入位置。
2. 原 PDF 中一张图片可能包含多个子图（如图 2.1-a、2.1-b），也可能被裁成多张；必须确认各裁剪图的归属和组合关系，避免子图错位或顺序错乱。

#### 2. 随正文逐步检查

生成正文 XML 时，图片检查必须逐页、逐张完成。每完成一页文本，立即按以下顺序处理，全部通过后才能完成该页 XML：

1. 使用`scripts/pdf2png.py <source.pdf> --output <out-dir>`一次渲染全部页面，每两页会被渲染成一张图片。读取 PDF 原页的高清渲染图，确认对应页目视可见的图片及其位置。
2. 找到当前批次的全部裁剪图，然后将**每一个裁剪 PNG 作为图片实际读取**；只执行 `ls`、查看文件名、读取图片尺寸，或根据正文、图注和原页猜测裁剪内容，均不算完成检查。
3. **将每张裁剪图与 PDF 原页逐一对照**，检查四边是否完整、是否包含全部子图，以及是否混入图注、页眉页脚或相邻正文。不得遗漏原PDF中的任意一个有效图片，否则整个转换任务将毫无意义。
4. 为每张裁剪图立即给出且仅给出一种结论，并写入过程记录文件：
   - `use`：裁剪完整且内容确为应保留的图片，记录对应图号或内容摘要，并按原位置写入本页 XML。
   - `skip`：属于误检、装饰碎片、重复项，或已被另一张更完整的裁剪图覆盖；记录不写入的理由。
   - `native`：内容实际为公式或语义表格；分别按 `<latex>` 或 `<table>` 处理，不写入图片。
   - `recrop`：存在缺边、留白不当、子图缺失、文字不可辨或混入其他内容；暂停该页 XML，按“问题页重裁”处理。
5. 对照原页复核：原页中的每张有效图片都必须对应一个 `use` 结果；当前 run 的每张裁剪图也必须具有上述结论，不得遗留“可能是”“稍后检查”或未分类项。

**硬性门槛**：过程记录文件中必须能找到当前页每张裁剪图的实际图片读取记录。不得先写 `<img>` 路径再补查，也不得以读取整页渲染图代替读取裁剪图。任一裁剪图尚未读取、结论为 `recrop`，或原页有效图片尚无对应裁剪图时，禁止生成或写入该页 XML。重裁产生新的 run 后，必须按新文件和新编号重新逐张检查。

#### 3. 问题页重裁

命中 `recrop` 结果时需要重裁其所在页。每轮必须使用新的 `--run-id`。根据问题类型分别使用以下参数：

- **候选图被拆成多张**：使用 `--adaptive-merge-gap-pt` 增大候选组的二次合并距离。该参数作用于所选页面的候选分组，可能改变图片数量和编号；应从接近默认合并距离的较小值开始调整，并重新检查该页全部裁剪图。例如：

```
python scripts/locate_pdf_figures.py <source.pdf> \
  --output <out-dir> \
  --pages "30" \
  --run-id <new-run-id> \
  --adaptive-merge-gap-pt 12
```

- **候选分组正确但裁剪边界不准**：使用 `--adjust` 只调整指定图片的最终裁剪框，四个数值依次对应左、上、右、下；正数向外扩，负数向内收。图片 ID 必须采用当前候选分组下的编号。例如：

```
python scripts/locate_pdf_figures.py <source.pdf> \
  --output <out-dir> \
  --pages "30" \
  --run-id <new-run-id> \
  --adjust PAGE-0030-IMAGE-01,8,0,0,0
```

重裁后重新检查该页对应图片，若无问题，继续写入 XML。

### 四、飞书 XML 的几个陷阱

**不要在待上传 XML 中使用注释**：XML 注释不是 `lark-doc-xml.md` 声明的文档结构，页码、批次和审计备注应保存在本次任务的过程记录文件中。若草稿已含注释，使用支持 XML fragment 的解析方式（先包裹临时根节点）删除注释，再序列化根节点的全部子节点；不要直接对包含多个顶层 block 的 DocxXML 调用 `etree.fromstring(xml_bytes)`，也不要用正则表达式处理 XML。

**多栏页面按语义选择 `<grid>`**：双语并排、逐项对照或阅读关系依赖横向位置时使用 `<grid>`，各栏 `width-ratio` 之和为 `1`，并按源页面比例设置。普通学术或报纸双栏若只是连续阅读流，可以按“左栏从上到下，再右栏从上到下”转成单栏；同页存在跨栏标题、表格或图片时，应拆成“满宽 block + grid + 满宽 block”，不要把整页机械包进一个 grid。

### 五、写入与回读

**分批 `append`**（长文档必需）：

- 每批最多包含 2 页源 PDF 对应的 XML，且不得超过 200 KB，以先达到的限制为准。
- 严格按 PDF 页码升序 `docs +update --command append`。
- **每批写入后使用 `fetch` 回读**（`docs +fetch --detail full`），确认最后 `K` 个 `block` 与本批 XML 的等价内容匹配，包括文本顺序、`<latex>` 源码、`<img>` 的数量和顺序、`<table>` 行列数，以及 `colspan`、`rowspan` 序列。
- 每批完成写入和回读后，将页码范围、写入结果、`revision_id`、核对结果和异常写入过程记录文件，再开始下一批。
- 如果出现内容缺失或不匹配、`warning` 或 `partial`，应**立即停止，不要重试 `append`**（否则会导致重复写入）；先使用 `fetch` 判断远端写入到哪一批，再使用 `str_replace`、`block_replace` 或 `block_delete` 修正，确认无误后继续。

**跨页段落合并**：只有在版面位置、缩进、字体、行距和语义均支持连续，且前页末尾没有明确段落终止信号时才合并。英文可辅助检查下一页是否以小写字母或续词开头；中文及 OCR 文本不能套用该条件。标题、列表项、图注、公式之间不得仅因物理位置相邻而合并。应使用 XML 解析器移动子节点，禁止采用字符串截断拼接。

**终版全文回读**：交付前再次执行 `docs +fetch --detail full --as user`，并对照本地稿逐项检查：

1. 按统一口径统计正文段落，比较每段首尾 16 字；标题、列表项、表格单元格和图片 caption 单独计数，不混入正文段落分母。
2. 解析 XML 实体后，逐条比较 `<latex>` 文本与本地转录稿字符相等；不要直接比较 `&lt;` 与 `<` 等不同序列化形式。
3. `<img>` 数量与顺序一致；所有图片均已完成本地四边检查，并逐张调用 `+media-preview`，确认上传结果完整、无额外正文且可以正常访问。
4. 语义 `<table>` 的数量、行列数与 `colspan`、`rowspan` 序列一致；公式编号使用的 `<grid>` 均为左公式、右编号的两栏结构，且不计入表格数量。
5. 需要保持横向关系的多栏内容仍使用 `<grid>`；转换为单栏的连续阅读流顺序正确。

**回读通过不等于视觉检查通过**：分式括号大小、上下限位置、图片裁剪边界和宽表滚动效果只能在受控浏览器或导出预览中检查；至少应目视核对 `max(1, ceil(总页数 × 5%))` 页、所有公式密集页、所有语义 `<table>` 和所有页面裁剪图片。

### 六、交付说明

必须包含：

1. **文档链接与当前 `revision_id`**（便于用户回滚）。
2. **计数**：正文段落 X/X、公式 X/X、语义表格 X/X、图片实例 X/X，以及因公式编号或版式使用的 `<grid>` 数量。
3. **LaTeX 自检结果**：通过条数、修正条数，以及未解决的 `unclear_source` 和 `source_anomaly` 清单（附页码与位置）。
4. **视觉检查范围**：列出抽样对照的页码，以及已逐张检查的裁剪图片；不要笼统写成“全部通过”。
5. **保真妥协**：源色 → 落地色映射、栏宽近似值、跨页或超宽表拆分说明、转为单栏的页面、无法完全排除的裁剪残留文本，以及无法映射的 PDF 内部锚点。
6. **未能验证的限制**：受控浏览器不可用、OCR 未接入、部分图片上传失败等。

**飞书不保留 PDF 的物理分页**——这是产品特性，应在交付说明中明确指出，避免用户误认为这是保真失败。
