# 数据来源与证据政策

## 工具顺序

先按强制读取完整性协议完整读取 `references/source-tool-priority.md`：

1. 对每个数据项目先调用用户明确指定的工具、网站、文件和字段。
2. 用户未指定该项目来源时，检查是否存在 `seed_finance_search`；存在时优先查询财务数据与市场数据。
3. 用公司公告、监管申报和交易所文件核验影响估值、债务及现金流的关键字段。
4. 指定来源或 `seed_finance_search` 缺失、失败或覆盖不足时，记录实际尝试与降级原因，再检索权威原始来源。
5. 仅在原始来源缺失时使用可靠数据供应商、评级资料或主流财经媒体。
6. 搜索摘要、自媒体、论坛和无来源转载不得作为关键数值的唯一依据。

## 每个数据点的证据字段

记录：

- 字段名称与标准化字段名；
- 报告值和调整值；
- 币种与单位；
- 财务期间或价格日期；
- 公布日期；
- 来源标题、机构、链接、页码或表名；
- 数据分类：公开事实、口径调整、模型假设、模型推导；
- 置信度：高、中、低；
- 与其他来源的差异及处理。

## 截止日纪律

只使用估值基准日当时已经公开的信息进行历史复盘。实时分析使用最新可得信息，但写明查询日期。不得用后来披露的信息悄悄修正历史判断。

价格、股份数和财务报表必须日期匹配。若价格日在最新财报之后，明确净债务和股份数所依据的财报日期。

## 交叉核验

至少对以下项目执行原始文件核验：

- 完全稀释股份数；
- 现金、受限现金和总债务；
- 租赁负债、优先股、少数股东；
- EBITDA调整项；
- 资本开支和营运资本；
- 债务期限、利率和担保；
- 管理层指引。

一致预期可以用于预测情景，但必须标成第三方前瞻估计，不能写成公司指引。

## 数据冲突

按“口径适配度、日期匹配度、来源权威性、披露细度”排序选择。保留冲突值，解释为何采用其中一个。无法解决且影响回报时，使用区间并降低置信度。
