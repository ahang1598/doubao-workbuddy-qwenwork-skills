# 数据工具与来源优先级

## 目的

把“先调用哪个工具”与“冲突时采信哪个证据”分开。`seed_finance_search` 是默认检索入口和缺口补充工具，不得覆盖用户明确指定的工具、网站、文件或数据口径。

## 按数据项目确定调用顺序

对股价、财务报表、股本、公司行动、汇率、利率、Beta、一致预期和行业数据分别建立来源路由，不用一个全局默认工具覆盖全部字段：

1. 先调用用户对该数据项目明确指定的工具、网站、文件、代码、字段和历史时点口径。
2. 若用户给出多级来源顺序，严格按其顺序逐级尝试。
3. 用户没有指定该项目来源时，优先检查并调用可用的 `seed_finance_search`，再按工作流使用监管文件、交易所公告、公司正式披露、官方市场数据或其他权威工具。
4. `seed_finance_search` 可用于定位文件、批量建立初始数据集、补充未指定字段和交叉检查；关键报告值、股本和公司行动仍按工作流要求回查原始证据。

“用户指定来源优先”只适用于其指定的数据项目。例如用户指定 Yahoo Finance 的历史 Close，只约束价格字段；不因此用 Yahoo 替代交易所财报。

## 指定来源失败与降级

指定来源不可访问、权限不足、缺少历史快照、字段不存在或口径不适用时：

1. 保存来源名称、请求字段、目标日期、实际尝试时间和失败原因。
2. 在来源台账标记 `Source unavailable` 或 `Coverage insufficient`。
3. 说明拟采用的备用来源、替代字段和数据等级变化。
4. 再调用 `seed_finance_search` 或工作流允许的其他来源。
5. 将替代值明确标记为备用来源值，不得伪装成指定来源数据。

若指定来源仍可继续尝试，不得仅因其他工具更方便而提前降级。不得用当前值、复权价或后来发布的数据替代指定历史时点值。

## 证据冲突

工具调用顺序不改变证据权威性。发生冲突时，保留全部原始值、日期、单位和口径，并按以下原则选择最终模型值：

1. 先遵守用户明确规定的冲突处理和来源层级。
2. 财务报表、股本及公司行动通常以日期匹配的监管申报、交易所文件和公司正式披露为准。
3. 股价、汇率、利率或其他市场字段按用户指定的发布机构、字段和时点为准；用户未指定时按工作流的权威来源层级处理。
4. `seed_finance_search` 的结果按其可识别的上游来源定级，工具名称本身不构成更高证据等级。
5. 无法解释的重大冲突保留两种口径并量化影响，不取平均值。

## 阻断质量门

出现以下任一情况时，来源路由状态为 `FAIL` 或 `INCOMPLETE`，不得把相关模型或估值描述为完成：

- 用户指定来源尚未实际尝试；
- 使用备用来源却没有 `Source unavailable`、`Coverage insufficient` 或替代理由记录；
- 静默用 `seed_finance_search` 或第三方数据替换用户指定来源；
- 来源台账声称使用了实际未调用的工具；
- 关键历史字段使用了指定截止日之后才公开的信息；
- 冲突未保留原始记录或没有最终选择依据。

在 `execution-plan.json` 和最终来源台账中保存每类数据的 `requested_source`、`actual_source`、`attempt_status`、`fallback_reason` 和 `source_id`。没有用户指定来源时，将 `requested_source` 记为 `default routing`，不得虚构用户要求。
