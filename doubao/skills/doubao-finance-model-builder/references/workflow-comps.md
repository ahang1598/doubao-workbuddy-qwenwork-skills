# 中文可比公司分析

## 目标

以时点一致、证券口径一致、来源可追溯和计算可复核为原则完成公开市场可比估值。先识别经济实质与经营阶段，再选择同行和主锚。把报告事实、第三方估计、计算推导与分析判断分开呈现，不为得到目标价格反向选择同行、期间或调整。

## 默认用户体验

- 只把目标公司和历史估值基准日视为可能阻塞的信息；其余缺失项优先采用合理默认值并披露。
- 用户要求“当前估值”时，使用最近一个已完成交易日；默认报告币种为目标证券主要交易或财务报告币种，默认观察期为未来 12 个月。
- 正式任务默认只交付一个用户可见、通过审计的公式工作簿；`decision-brief`直接写入工作簿结论页。只有用户明确要求时才额外输出完整研究报告、飞书文档或审计包。
- 在开始数据检索前，用一句话说明估值基准日、主分析问题和预计采用的主锚；不让用户为内部字段逐项回答问题。

## 中文语境硬规则

- 除公司法定英文名称、证券代码、数据源名称和必要英文缩写外，面向用户的标题、表头、结论、脚注、警告和单位一律使用简体中文。
- 金融指标首次出现时采用“中文全称（英文缩写，简明口径）”，后续可使用“中文简称（缩写）”。不得只写 `P/E`、`P/S`、`EV/Revenue`、`FCF Yield` 或 `ROE`。
- 将 `Core/Secondary/Excluded` 分别写为“核心可比公司/辅助可比公司/排除公司”；将 `Pass/Limited/Fail` 分别写为“通过/受限/不通过”。英文值仅可保留在审计 JSON 中。
- 将 `bridge` 写为“调节表”或“桥接表”，将 `Median/P25/P75` 写为“中位数/第25百分位数/第75百分位数”。金额单位优先写“人民币百万元”“港元百万元”或“美元百万元”，不得在中文正文单独显示 `CNY millions`。
- 首次出现 `NA` 和 `NM` 时说明：`NA` 表示数据缺失，`NM` 表示指标无经济意义。所有报告在结尾附“指标释义与口径”小节。
- 区分两种 `EV`：一般行业中的 `EV` 指企业价值（Enterprise Value）；保险 `P/EV` 中的 `EV` 指内含价值（Embedded Value），必须在表头和释义中明确消歧。
- 优先使用公司的官方中文名称；没有官方中文名称时保留法定英文名称并附证券代码，不自行翻译专有名称。

## 按需读取规则

执行完整估值时必须完整读取：

1. `references/comps-finance-search-and-data.md`：数据工具、时点、来源、数据等级和降级规则。
2. `references/comps-industry-and-stage-routing.md`：行业、经营阶段与主辅锚路由。
3. `references/comps-peer-selection.md`：角色化同行、四维评分与数据质量门。
4. `references/comps-normalization-and-valuation.md`：股本、现金、FX、股息、EV、NTM和估值计算。
5. `references/comps-output-modes.md`：按用户场景选择输出结构和视觉规范。

仅在相关时读取行业模块：

- 商业化或临床阶段创新药、生物科技：读取 `references/comps-industry-biotech.md`。
- 银行、保险、证券、地产、软件平台、制造或周期公司：读取 `references/comps-industry-and-stage-routing.md` 中对应部分；只有用户需要完整报告时再读取 `references/comps-report-schema.md`。

## 工作流

正式可比公司任务先建立并验证 `execution-plan.json`。计划至少冻结估值日、财年口径、币种、核心/次级/排除同行角色、同行理由、目标公司与同行的股价/股本/企业价值桥日期、主要倍数、溢折价分析和交付模式。不得先看倍数结果再改变同行角色而不保留理由。

### 1. 锁定任务和数据能力

确认证券身份、交易所、股本类别、ADR 比率、估值基准日和信息截止日。分别记录价格日、股本日、资产负债表日及公开日、估计快照日、FX 日期和查询日。禁止使用基准日之后才公开的信息回填历史估值。

对目标公司和每个进入倍数统计的同行，分别执行 `references/equity-evidence-acquisition.md`：先保存官方基准股本、官方检索结果和公司行动正文，再建立股数桥并运行 `validate_equity_evidence.py`。不得因批量数据库已有股数而跳过本地官方证据。股数日必须等于估值日，价格使用不复权近端收盘价；逐家公司用股价×估值日股数与同日独立市值反向勾稽。

在报告中标记数据等级：

- `A`：同一专业供应商的历史时点一致预期，覆盖与口径完整。
- `B`：多家基准日前卖方预测或可靠结构化数据，已完成口径核对。
- `C`：单一卖方预测、FY1/FY2 日历化或部分公开替代数据。
- `D`：缺少可比前瞻数据，只能做方向性或 LTM 分析。

先按强制读取完整性协议完整读取 `references/source-tool-priority.md`。对股价、股本、财务、企业价值桥和一致预期分别优先调用用户指定来源；用户未指定的项目再优先使用 `seed_finance_search`。指定来源或默认工具不可用时，记录实际尝试与降级原因，再按能力组合历史行情、监管文件、公司披露和公开数据工具。披露请求来源、实际数据工具、替代关系及置信度下降，不静默换源，不声称接入不存在的专业数据源。

### 2. 路由行业、阶段和估值锚

判断经济模式、经营阶段、利润质量、资本密集度、收入质量及资本结构。形成“主锚、辅助锚、弃用指标、理由”表。

成长且预期变化快的公司优先 NTM；金融机构使用股权价值口径；亏损或分母无经济意义时标记 `NM`。不得把目标公司的 NTM 与同行 LTM 混入同一统计。

市销率（P/S）只在收入可比且资本结构差异不显著时作为主锚或辅助锚。若同行间净现金、净负债、优先索取权或非经营投资差异较大，优先使用企业价值/营业收入倍数（EV/Revenue）。使用 P/S 时必须同时比较收入增长、毛利率、经常性收入占比和现金转化，不得只按收入倍数机械定价。

### 3. 建立目标经营画像和角色化同行池

先描述目标公司的产品、客户、收入结构、地区、规模、增长、利润率、现金转化、资本需求和主要风险，再建立宽口径候选池。

按 `references/comps-peer-selection.md` 评分并赋予角色：

- 商业核心（内部值 `Commercial Core`）：收入形成和商业化模式最接近。
- 阶段核心（内部值 `Stage Core`）：增长、盈利和融资阶段最接近。
- 成熟边界（内部值 `Mature Boundary`）：成熟盈利或现金转化边界。
- 管线/模式边界（内部值 `Pipeline/Model Boundary`）：平台、管线、授权或其他局部经济边界。
- 排除公司（内部值 `Excluded`）：结构性不可比、数据失败或重复证券。

只有满足核心可比公司硬门槛且数据质量为“通过”的公司进入主统计。评分用于审计，不覆盖结构性不相容；只展示一位小数，避免伪精确。

每个非目标公司必须保存纳入候选池理由、最终分类理由、经营差异、可使用指标和不可使用指标。仅有分数而没有文字分析时，状态为 `INCOMPLETE`。

### 4. 建立数据台账和标准化调节表

对目标公司、核心可比公司和辅助可比公司记录股价、完全稀释股本、企业价值调节表、最近十二个月/未来十二个月财务指标、自由现金流、行业关键绩效指标、日期、币种、来源和数据标签：

- `[R]`：监管、公司披露或原始市场数据。
- `[A]`：分析调整。
- `[E]`：第三方预测或一致预期。
- `[D]`：计算、日历化、插值或 FX 转换。

同时保留报告口径和调整口径。现金必须从现金等价物、定期存款、短期投资、受限现金、经营所需现金到可扣现金逐项桥接；不得把现金等价物当作全部流动资金，也不得默认扣除全部账面现金。FX 必须记录币种对、汇率、日期和来源。

### 5. 通过质量门并计算

准备标准化 JSON，运行：

```bash
python3 scripts/comps/calculate_comps.py normalized-comps.json --output calculated-comps.json
```

必须处理或披露脚本的日期、FX、现金桥、样本、分母和数据等级警告。保留未舍入中间值。

对主锚计算核心可比公司样本数、第25百分位数、中位数和第75百分位数。核心可比公司少于三家时，不把四分位数描述为稳健市场基准；报告渲染仅展示观察区间和低置信度提示。

### 6. 判断合理溢折价

比较增长、利润率、现金转化、收入质量、竞争地位、资产负债表和执行风险。先判断方向，再判断幅度；把调整连接到可观察证据。禁止无模型支持的“平台 +40%、增长 +25%”式数值拆分。

必须形成目标公司与核心同行的逐项对比表，并保存溢折价方向、理由、来源ID和反证条件。不得由脚本统计值直接跳到目标价。

### 7. 推导价值和市场隐含预期

完成主锚到企业价值、股权价值和完全稀释每股价值的调节表。并列展示标准企业价值与分析调整企业价值，说明现金、投资、租赁、少数股东和稀释处理。

至少执行：

1. 当前交易倍数与核心可比公司分布位置。
2. 在核心可比公司中位数或建议倍数下反推市场隐含收入、息税折旧摊销前利润、净利润、自由现金流、每股净资产或行业关键绩效指标，并与未来十二个月预期比较。市销率路径从股权市值反推收入，企业价值/营业收入路径从企业价值反推收入，两者不得混用。
3. 倍数 × 基本面二维敏感性。
4. 悲观、基准、乐观情景；分别说明基本面、倍数、净债务和股本变化。

只有具备经营模型时才把隐含财务指标继续翻译为增长或利润率。没有 rNPV 或独立管线模型时，不得把“市值减商业化价值”的残差称为管线价值；只能称为未解释估值溢价或市场隐含期权价值。

### 8. 定义三项失效证据

每项写明观察指标、方向、来源、阈值或时间点，以及触发后需要重做的环节。必须是未来可观察证据，不得用“样本较少”或“方法有局限”替代失效触发器。

### 9. 渲染和交付

正式任务必须生成公式工作簿，并将其作为唯一默认用户交付物。工作簿至少包含封面、结论摘要、目标公司、同行筛选、原始数据与计算、历史数据与口径、标准化调整、假设与方法、市值与企业价值桥、交易倍数、核心样本、同行统计、隐含估值、市场隐含预期、情景与敏感性、结论依据、数据质量与失效条件、模型检查和数据来源。目标公司与同行关键字段逐项披露来源、报告期、币种、口径和调整；目标倍数及溢折价关联假设编号。先建立公式语义合约与冻结布局，至少覆盖分证券市值、企业价值桥、核心样本统计、目标倍数、隐含企业价值/股权价值/每股价值、情景和敏感性；保存后运行语义审计及`scripts/common/audit_formula_workbook.py --recalculate required`。没有`formula-semantic-audit.json=PASS`和`artifact-audit.json=PASS`时不得输出推荐倍数或隐含价值结论。

不得由语言模型自行拼装可比公司工作簿。完成`calculate_comps.py`确定性计算后，必须从同一标准化输入运行固定生成器和专属审计器：

```bash
python3 scripts/comps/build_comps_workbook.py normalized-comps.json comps-model.xlsx --contract comps-workbook-contract.json
python3 scripts/comps/audit_comps_workbook.py comps-model.xlsx comps-workbook-contract.json artifact-audit.json
```

生成器固定物化分证券市值、企业价值桥、全部适用交易倍数、Core样本链接、样本数/P25/中位数/P75、目标公司隐含价值、二维敏感性和模型检查。专属审计器读取生成时冻结且绑定工作簿SHA-256的完整公式单元格清单；任一必需单元格变成静态值、公式失去输入或计算链引用、工作表缺失或哈希变化均为`FAIL`。不得缩小、重写或用模型自报的`formula_ranges`替代该固定清单。

`assets/comps/`提供一套可直接复测的参考资产：

- `example-input.json`：包含目标公司、核心样本和边界样本的标准化示例输入；
- `comps-model-template.xlsx`：由固定生成器从示例输入生成的公式工作簿；
- `workbook-contract-example.json`：与示例工作簿SHA-256及完整公式清单绑定的审计契约。

参考资产只用于理解结构、回归测试和失败注入，不得将示例公司、同行池、估值倍数或计算值用于正式任务。正式任务必须基于估值基准日证据生成新的标准化输入、工作簿和审计契约，并重新运行专属审计器；不得复制示例工作簿后仅替换展示数值。

工作簿通过审计后，默认将`decision-brief`内容放入工作簿结论页并停止生成用户可见产物。只有用户明确要求独立辅助报告时，才运行数值渲染器生成一致的表格骨架：

```bash
python3 scripts/comps/render_comps_report.py calculated-comps.json --output report.md --mode decision-brief
```

由分析者补充同行理由、溢折价判断、关键事实和就近引用。数字表不得手工改写为与脚本不一致的值。辅助报告定稿后必须重新运行渲染器并执行直接产物审计，且不得覆盖工作簿审计文件：

```bash
python3 scripts/common/audit_report_artifact.py report.md calculated-comps.json --workflow comps --output report-artifact-audit.json
```

按`references/delivery-package-contract.md`保存主要公式工作簿、标准化输入、计算结果、运行记录和文件清单；独立报告仅在用户明确要求时加入。所有正式任务增加关键倍数、企业价值桥和隐含每股价值的单元格追溯。

计算输出的 `model_status_code` 必须为 `PASS` 才能将报告描述为完成。存在同行角色/理由缺失、核心样本不足、来源覆盖不足或分析摘要占位符时，只能输出 `INCOMPLETE` 底稿，不得直接给出推荐倍数或目标价。

辅助展示模式：

- `decision-brief`：默认写入Excel结论页；包含结论卡、核心同行、EV桥、估值、隐含预期、敏感性和三项触发器。
- `full-report`：用户明确要求时，额外输出在决策摘要后补充完整经营画像、数据口径、同行审计和来源的报告。
- `audit-pack`：用户明确要求时，在Excel之外附完整报告、标准化输入、计算输出、来源台账和脚本警告。

飞书文档、Markdown或其他文档格式只能作为用户明确要求的辅助产物，不得替代、延后或绕过已通过审计的Excel主要交付物。

## 交付前检查

完成原子验证后按`references/model-and-artifact-controls.md`运行统一质量门，工作流参数为`comps`。G3必须纳入同行角色过滤、同行统计复算、租赁统一、原币到报告币种桥、分证券市值、目标倍数及隐含价值；G5的`release-decision.json`未允许结论时，不得显示推荐倍数、估值区间或上涨下跌空间。

- 信息公开日、估计快照日和 FX 日期均不晚于基准日。
- 行业、经营阶段、主锚、辅助锚和弃用指标有明确理由。
- 核心可比公司、边界公司和排除公司均有角色、评分、数据质量和理由。
- 现金、股本、股息和企业价值调节表可复算且无重复计入。
- 目标公司及所有核心/辅助同行的公司行动检索覆盖至估值日；不复权股价、估值日股数和独立市值在容差内一致。
- LTM/NTM 期间一致；`[R]/[A]/[E]/[D]/NA/NM` 使用一致。
- 当前倍数、核心可比公司统计、隐含价值、反向预期、情景与报告正文一致。
- 使用市销率时已解释资本结构为何足够可比，并同时展示收入增长、毛利率、收入质量及企业价值/营业收入倍数交叉检查；不适用时已明确弃用理由。
- 数据等级、关键缺口、调整强度和总体置信度已披露。
- 面向用户的静态文本均为简体中文；每个金融指标首次出现时已有中文全称、英文缩写和口径解释，报告末尾已有指标释义。
- 工作簿为主要交付物并先给决策结论；额外报告正文表格结构清晰，但不得代替或脱离已交付且通过审计的Excel。

## 分析边界

不得把本流程扩展为完整公司研究、DCF、先例交易、并购套利、信用分析或自动交易。用户明确要求时，可将其他估值方法作为独立交叉检查，不与交易可比主结论机械平均。

修改可比公司计算或工作簿规则后，至少运行：

    python3 scripts/comps/test_comps_quality.py
    python3 scripts/comps/test_comps_workbook.py
