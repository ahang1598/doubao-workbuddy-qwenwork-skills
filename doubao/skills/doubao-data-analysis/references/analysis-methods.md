# 专项分析与定向判定方法

先按用户问题选择方法，不要让方法反过来扩张任务。共同原则：先复现事实，再找原因；只有具备完整分段和可复算公式时才量化贡献。

## 零、定向筛选、规则判定与字段问答

适用于“找出哪些记录、是否重复、是否超标、某字段交叉条件是否存在”等 L1 任务。

1. 写出严格条件：对象、业务键、字段、方向、阈值、时间范围和规则来源。
2. 检查结论所需证据是否存在。没有同名字段不自动等于无法判断：数据字典明确的等价字段或逻辑上唯一闭合的事件链可以替代，但要说明推导路径；相似字段、关键词或相邻记录只能形成线索，不能替代目标证据。
   - 复合筛选缺少必要谓词字段时，严格命中数不可计算，不报告 0；零命中要求所有必要字段存在且覆盖完整。
3. 严格结果和延伸结果分开：
   - 严格结果：同时满足用户原条件，进入主计数。
   - 延伸结果：相关但不等价，只作补充，不进入主计数。
4. 重复或阈值任务可在内部识别候选组，再按用户规则计算最终结论；候选组不是默认交付项。
5. 输出优先包含判定口径、最终结果/计数和关键证据；确有缺失或相关延伸时再增加无法判断项、延伸项，不为凑固定结构输出空章节。

## 一、指标异动归因

### 流程

1. **复现指标**：用原始数据算出被质疑的那个数字，和用户/看板说的对上。对不上先解决口径问题。
2. **定义对比并判定时间语义**：先把记录分为点事件、互不重叠期间、重叠期间、累计快照或未知。存在开始/结束字段时，必须让 `scripts/time_window_audit.py` 直接读取全部相关 CSV/XLSX 源表的时间列，再由 `scripts/decision_guard.py` 重新打开源表复核；模型手抄或改写的日期列表不作为证据，不能只审计单日行、方便归因的 sheet 或记录子集。共同起点配不同终点、滚动窗口、累计截至日，或与单日记录混杂的区间不能当成独立单日，也不能按开始日/结束日相加或拼成动作前后。只有脚本判为点事件或互不重叠期间时，才能直接构造环比、前后对比和日均变化；其他类型只报告各区间覆盖范围与静态结构。
3. **对齐动作与断点**：若存在已知动作、规则、配置、版本或口径变化，先枚举时间字段的唯一值、覆盖范围、区间重叠关系和各期样本量，选择最细且样本充分、周期完整的决策粒度，再建立“动作时间 → 合理响应时滞 → 指标拐点”的时序链。动作必须来自用户陈述、变更日志或明确配置记录；对象名称、分组标签、文件时间或创建时间不能单独证明参数已改变。发生在结果之后、方向不符或时滞不合理的候选不得列为原因；时间吻合只提高候选优先级，不单独证明因果，有对照或反事实证据时再升级。时间信息不足或窗口重叠时说明缺口并继续静态分析，不追逐稀疏噪声。
4. **选诊断模式**（四选一）：
   - **趋势变化**：焦点窗口 vs 基线窗口，逐分段算贡献
   - **尖刺/事故**：定位 onset/峰值/恢复时间点，看影响面是广谱还是集中
   - **头部贡献者**：定义"最大"，排名对比两期，找大幅变动者/新进者/退出者
   - **口径对账**：两个数字对不上——对齐定义、过滤、粒度、分子分母，逐项量化差异来源
5. **有条件地分解贡献**：
   - 加法指标（DAU、GMV、消息量）：分段 i 的贡献率 = (本期_i − 基期_i) / (本期总 − 基期总)。全部分段贡献率加总应 ≈ 100%，对不上说明分段不完备。
   - 率指标（转化率、人均时长）：先拆分子分母各自的变化；仅当分段完备、分母一致且可回算到总变化时再做 **mix-shift 分解**：
     - 总率变化 = Σ[占比变化_i × 基期率_i]（结构效应） + Σ[本期占比_i × 率变化_i]（组内效应）
     - 结构效应大 = "用户构成变了"；组内效应大 = "同类用户行为真的变了"。业务含义完全不同，必须分开说。
6. **排查测量性解释**：埋点/发版/回填/去重逻辑变更的时间点是否与拐点吻合。
7. **下结论**：只有贡献已计算且分段覆盖完整时才称“主因”；否则输出“候选原因 + 证据 + 还需验证的数据”。不要为满足格式编造贡献占比。

### 输出格式

> 结论一句话 → 驱动因子表（因子 | 变化 | 贡献占比 | 证据 | 结论层级）→ 排除项（查过但不成立的假设）→ 残差与不确定性 → 建议。

## 二、漏斗分析

1. **定口径**（漏斗结论 80% 的分歧来自口径）：
   - 用户、订单、线索、会话、设备还是事件级？分析单位由业务对象和决策问题决定，不能确定时声明假设或并列口径。
   - 转化窗口：进入漏斗后多久内完成算转化（当日？7 天？）
   - 是否要求严格顺序（跳步算不算）
2. **算两组率**：逐步转化率（第 i+1 步 / 第 i 步）和累计转化率（第 i 步 / 第 1 步）。
3. **找瓶颈**：绝对流失人数最大的步 ≠ 转化率最低的步，两个都要报；优化优先级 = 流失量 × 可改善空间。
4. **分维度对比**：按渠道/平台/新老用户拆漏斗，找"哪类用户在哪一步流失显著高于均值"。对比要报绝对差和相对差。
5. **时间趋势**：瓶颈步骤的转化率按周画趋势。长期稳定差异提示结构性因素，近期突变提示事件性因素；产品、渠道、流量结构、口径与季节性均需证据验证，不据曲线形态直接定因。

## 三、留存 / Cohort 分析

1. **定义三要素**：
   - Cohort 分组依据：通常是首次行为日期（按日/周/月分组）
   - 留存行为：什么算"回来了"（任意活跃？核心行为？）
   - 留存口径：**严格日留存**（第 N 天当天回来）还是**滚动留存**（第 N 天及以后回来过）。按用户或规则定义选择；未定义时声明假设或并列口径，不静默默认。
2. **算留存三角矩阵**：行 = cohort（首次日期），列 = 第 N 天/周，值 = 该 cohort 第 N 期仍活跃的用户数 / cohort 总数。右下角天然缺数据（还没到期），**别把未到期当流失**。
3. **读矩阵的三个方向**：
   - 横着读：单个 cohort 的衰减曲线（次留 → 7 留 → 30 留，找平台期——曲线走平说明沉淀下核心用户）
   - 竖着读：同一个 N，不同 cohort 对比（新版本/新渠道来的用户留存是否更好 = 产品改进的真实验证）
   - 对角线读：同一自然日的表现（某天所有 cohort 集体掉 = 当天出事了，不是 cohort 质量问题）
4. **规模加权**：小 cohort（几十人）的留存率波动大，对比时报 cohort 规模，别拿 30 人的 cohort 和 3 万人的比。

## 四、A/B 实验判读

1. **先识别设计**：
   - 独立分流：每个实验单位只进入一个组。
   - 成对设计：同一实验单位同时有两种条件下的结果。
   - 重复测量或聚类设计：观测之间存在相关性，不能把每行视为独立样本。
   无法完全确认时，说明采用的设计假设及其对结论的影响。
2. **做匹配的有效性检查**：
   - 只有已知预期随机分流比例时才做 SRM；成对设计不适用 SRM。
   - 根据任务检查周期完整性、重复分配、分组污染、数据缺失和事件时序，不要求无关检查项。
3. **选择匹配的方法**：
   - 独立两组率指标可用两比例检验；独立两组均值可用 Welch 方法，重尾数据补充稳健性分析。
   - 成对二元结果使用 McNemar；区间估计可按配对单位 Bootstrap。连续型配对结果使用配对方法。
   - 重复测量或聚类设计使用能处理相关性的模型或稳健标准误。
4. **完整报告效果**：同时报告绝对差、相对差、区间估计、p 值和样本量，并说明主指标、护栏指标与多重比较。显著性不等于业务价值，不显著也不等于无效果；MDE 只在假设充分且方法与设计一致时使用。
5. **谨慎解释分段结果**：样本量较小或未预设的分段结果主要用于生成后续假设。

### 成对二元最低合同

1. 先声明配对键、实验单位和有效标签集合，并报告潜在配对数、有效配对数、两侧缺失/非法数、重复键数和剔除原因；总体及用户要求的分层均生成四格计数。
2. 机械检查标签枚举、缺失、重复配对、同一输出异标签及可验证的“标准答案—输出—标签”矛盾。不一致对驱动 McNemar：数量可控时逐条复核，过大时采用预先声明的分层随机样本，报告复核数、确认错标数和未决数；不能复核时不得声称标签质量通过。
3. 每个主比较实际运行 `ab_paired_binary`，报告两侧成功率、绝对/相对差、四格表、精确双侧 McNemar p 值、配对 Bootstrap 区间、重复次数和随机种子。
4. 同一决策包含多个模式、指标或版本时，先定义检验族；没有预注册层级时，默认把全部主推断比较作为一个族，运行 `p_adjust method=holm`。正文同时报告原始和校正后 p 值，决策使用校正后结果。
5. 总体显著、方向一致或单个名义 p 值都不能自动称为“稳定/可复现”。上线还须满足业务阈值、护栏和标签敏感性；否则只给条件式、可回滚的验证方案。

## 决策转译（L2/L3 或用户明确要求建议时）

拿到数字后过一遍决策棱镜，挑相关的回答，转成业务语言：
- **规模**：这个问题/机会大到值得投入吗？（占大盘的 %）
- **动量**：在变好还是变坏？加速还是减速？
- **集中度**：集中在少数分段（可定点解决）还是广谱（系统性问题）？
- **可行动性**：团队有对应的抓手吗？
- 最后落到：**建议做什么、如何验证、还需要什么数据提高置信度**。L1 默认在结果、证据与会改变结论的限制处结束，不强制追加行动计划。
- 区分预期收益和情景测算。预期收益需要可追溯基数、已验证的响应或明确可比证据、改善幅度依据和公式；多个行动相加时还要证明不重叠或完成去重。只有假设时可给明确标注的敏感性测算，但不得称为预计收益，也不能进入事实结论或用于证明方案有效。
- 若决策针对明确规格或属性，先报告目标相关子集的构造口径、覆盖数和未知量，再基于该子集做竞品与策略分析；不得先用全集得出策略，再用目标属性作文字限定。先分别写出“决策目标资格”和“候选排名筛选”：前者只能来自决策对象原句，后者可以来自价格、销量、分数等筛选章节，两者都命中后才可推荐。目标子集单独生成明细或汇总，至少报告覆盖数、价格分布、需求代理分布和未知量；所有面向目标的区间选择、分层定价和推荐，在合同 `decisions` 中标记 `basis_scope=target_subset` 并引用该子集证据。不能直接把全市场固定分箱的商品数或均值当成目标对象策略。入门/品质层级要同时满足顺序、目标子集需求证据和可比对象：品质价位高于入门价位，但若更高档需求代理显著更弱且没有功能、利润或品牌证据，只能作为待验证高端情景，不能直接主推。把避开、停止、排除视为负向动作，把入门、品质、主推、进入视为正向动作；交付前比较两类动作的数值区间，存在重叠就重写为互斥方案。只有额外资格条件能把重叠部分划成不同对象时才可保留，并须明确写出该条件；“差异化竞争”本身不是资格条件。每个推荐对象必须保留稳定源键以及命中目标规格/属性的原始字段或标题证据，并在交付合同的 `recommendations` 中登记。`target_scope` 同时登记 `decision_target_quote`、源文件、稳定键、完整展示字段和可执行谓词（正则、枚举或数值区间），每个谓词的 `source_quote` 必须是决策目标原句中的约束片段；门禁回到原始记录逐项验证。`target_scope.decision_output` 必须指向直接回答决策问题的最终区域；工作簿若恰有一个名称明确含“建议/决策/行动/策略”或对应英文的 sheet，就必须指向该 sheet。最终建议区域展示同一批推荐对象的完整源名称或稳定源键；脚本自动从源记录取展示名，不使用合同中另填的宽泛搜索词，并扫描最终建议区的正负动作区间冲突。不能把验证位置改成全局 TopN 候选池。手填“符合”不能代替验证。不满足目标或无法证明的对象不得进入推荐名单。
- 样本充分性按结论类型判断。确定性查询和规则命中不因记录少而拒答；趋势、稳定性、因果和激进行动则结合样本量、分母、波动与风险。小基数报告绝对数，限定为描述性发现，并优先采用可逆测试。
- 用户要求多个分析维度时，每项都要得到回答；证据不足的维度可以合并列出当前无法判断的事项及所缺证据，不必复制相同说明。
