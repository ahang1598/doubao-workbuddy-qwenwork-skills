# 数据质量与规则判定门禁

分析前按任务风险选择必要检查。目的不是把数据修到完美，而是**知道数据哪里不可信，让结论避开雷区**。内部记录发现；最终只披露会改变本题口径、结论或可复核性的问题。

## 第零步：确认实际读取范围

- 列出全部相关附件、sheet、有效行列范围和表头；图片/PDF记录实际读取页或提取字段；识别说明区、明细区、汇总行与错位表头。
- 用逐附件回执机械核对覆盖：`相关附件总数 = 成功读取数 + 明确失败数`。当一个附件缺少用户要求的时间范围时，继续检查其他附件后才能下“数据缺失”结论。
- 读取全部相关数据，不等于对每列都做 EDA。L1 先建立附件、sheet/页和字段索引，只加载命中区域及验证上下文，未命中再逐级扩大。
- 汇总行不得与其明细重复参与同一次聚合；有明细时把汇总值留作回验，无明细时可直接使用并标明无法下钻。
- 若出现“不良数 > 批量”等常识冲突，先检查列错位、合并单元格和单位。不能可靠对齐时把字段标为存疑，不强行命名。
- 日期、人员或分类纵向合并时，按工作簿 merge range 将左上角锚点值只传播到该合并范围，并保留原始行号；不要用无边界 `ffill` 或 DataFrame 索引重建日期。
- 同一工作簿存在“原始记录/明细”“签批/汇总”“导出/中间表”等多个近似 sheet 时，先按稳定键、记录数、粒度、版本、时间范围、公式和关键字段判断血缘与权威性。能确定唯一权威源时在该源执行主判定，其他派生或历史视图仅按任务需要对账；派生源冲突不反向抹去权威源命中，分层报告“权威源结果、跨源一致确认、冲突待核实”。无法唯一确定，或需要据一个 sheet 证明另一个的全量完整性时，才分别规范化各候选事实源、独立运行同一规则，并比较完整业务键集合的仅左、仅右和字段差异数。
- 解析器因筛选器、样式或其他工作簿元数据报错时，可定向读取目标 sheet、兼容转换或解析底层 XML/单元格；但成功读取一张 sheet 不代表同工作簿其他相关 sheet 已核验。

## 第一步：确认粒度（最重要）

- 这张表一行代表什么？（一个用户？一次事件？一个用户×一天？一个订单？）
- 用候选主键检查多行，只把它们标为**候选重复组**。多行可能是合法拆分、多个事件或状态流水，不自动等于重复数据或业务违规。
- 粒度没确认之前，任何聚合数字都不可信。

## 第二步：区分“候选重复”和“最终违规”

必须先识别规则约束的对象，再选择判定方式：

| 规则类型 | 候选组 | 最终判定 | 禁止 |
|---|---|---|---|
| 记录唯一性：每个业务键只能一条 | 同一业务键记录数 > 1 | `COUNT(*) > 1` 判违规 | 不得改用总量阈值 |
| 总量阈值：每个业务键指标不得超过 T | 同一业务键一条或多条 | 先 `SUM(指标)`，仅 `SUM > T` 判违规 | 不得因记录数 > 1 判违规 |
| 生命周期/状态异常 | 同一实体的多条事件 | 按时间与显式状态字段闭合事件链 | 不得把相邻行、拆分行推断为取消/重建 |

**总量阈值原则**：规则约束业务键的指标总量时，按规则指定的业务键聚合后再比较阈值。拆分成多行但聚合值未越界，仍判合规；只有规则明确约束记录唯一性时，才按记录数判违规。边界值按规则中的 `>`、`≥`、`<`、`≤` 原样执行。

**歧义消解步骤**：

1. 从约束短语中提取被限制的名词和单位。
2. 结合数据字典、业务键、记录粒度和指标单位判断；可加列或多行拆分只是证据之一。
3. 规则指向总量时使用聚合阈值，指向记录、订单、事件、行数或唯一键时使用记录唯一性。
4. 两者都会实质改变结论且仍无法区分时，不预设主次；并列两种结果、成立条件和待确认规则。
5. 非平凡、多文件、高风险或需批量复算时，将业务键与度量规范化后运行 `scripts/evidence_audit.py rule-check`，并回查源记录；简单小表可用等价可复算方法。

默认主结果只报告按用户规则判定的最终违规组及证据。候选多行组用于内部核验；仅当用户询问候选数、候选与违规的差异会改变结论，或需要解释数据粒度时才单列。候选数不得进入执行摘要或替代最终违规数。

## 第三步：字段充分性门禁

对用户每个问题确认结论所需证据。优先使用直接字段；只有数据字典定义的等价字段或能够唯一闭合的事件链可以替代，并须说明推导路径。仅有相似字段、文本关键词或局部事件时，不得写成确定事实，应输出“无法判断”或“待验证线索”：

- 缺少显式状态字段时，除非完整事件链能够唯一推出状态，否则不得断言具体状态或状态流转。
- 只有用户规则、附件说明或显式状态字段定义了资格/否决条件时，才构造资格集合；数值非空不能替代所要求的资格证明。未定义资格门槛时，默认用户指定范围内的全部记录为计算全集，不自行增加门槛。
- 缺少目标属性字段时，不得用相似属性、名称文本或行为结果替代该属性。
- 复合条件采用三值逻辑：可证真、可证伪、未知。缺少必要谓词字段时，分别统计确定命中、确定不命中和未知，给出严格总数的可支持区间；若用户要求唯一精确数，则回答当前不可精确计算。基于标签、相邻事件、领域惯例或代理字段得到的结果只能另列“代理/假设口径”，写明映射条件，不得在摘要、合计、受影响量或建议中重新称为严格条件命中。只有数据字典定义的等价字段或唯一闭合事件链才能解除未知。
- 缺少单位成本或库存金额，不得把库存数量换算成库存估值。
- 缺少退款原因、投放成本、客户或门店字段，不得据结果倒推具体原因或责任。

## 第四步：核心检查（按数据形态选做）

| 类别 | 检查项 |
|---|---|
| 完整性 | 各列缺失率；按天/按分段的缺失率趋势（整体 3% 缺失可能是某一天 100% 缺失）；哨兵值（0/-1/'unknown'）冒充缺失 |
| 唯一性 | 全行重复、主键重复、业务键多行的候选数；是否违规必须另按规则判定 |
| 有效性 | 类型符合预期；时间戳在合理范围（有没有未来时间/1970）；枚举值有没有意外新值；数值范围（负的收入/超过 100% 的率） |
| 一致性 | 跨字段规则（结束时间 ≥ 开始时间）；单位/币种统一；同一事实的冗余字段是否一致 |
| 时效性 | 数据最新到哪天；最近分区是否完整（末尾几天数据量骤降=未到齐，趋势图要截掉） |
| 体量形态 | 按天行数趋势有无断崖/尖刺；关键维度占比结构有无突变；新出现/消失的类别 |

## 埋点/事件数据专项

- 事件 ID 重复上报（客户端重试）；同一用户瞬间多条相同事件。
- 版本发布日前后事件构成突变 → 埋点变更，不是用户行为变化。
- 事件覆盖缺口：某平台/版本/渠道整段缺失。

## 稳定键与字段血缘门禁

- 分析前建立规范字段映射：`field_id → 来源附件/sheet/列 → 类型 → 单位 → 期间 → 粒度 → 聚合规则 → 空值规则`。
- 为每张事实表定义稳定业务键并验证唯一性或明确合法基数；连接前声明预期基数，连接后核对仅左、仅右、多对多放大和字段冲突。
- 禁止用显示名称、排名或行号代替稳定键；同一事实跨 sheet 或附件出现时先指定权威来源，不能确定时保留冲突状态。
- 总量即使勾稽，同一业务键发生字段互换、错位、单位或期间变化仍属于高严重度；影响决策数字或行动时属于 Critical。
- 对进入产物的字段建立血缘台账，至少含 `business_key、field_id、source_locator、source_value、calc_value、unit、period、scenario_id`，再与产物回读值和摘要值对账。

## 实验数据专项

- 先识别独立分流、成对、重复测量或聚类等设计；检查项应与随机化单位和观测相关性匹配。
- **SRM 仅适用于存在预期随机分流比例的设计**：比较实际分流比与设计比，出现明显偏离时先排查分流与数据链路。成对设计不做 SRM。
- 重复分配：同一用户进了多个组。
- 曝光无分配 / 分配无曝光；事件时间早于分配时间。

## 严重度分级（写进报告）

- **Critical**：影响核心结论可信度（主键大量重复、适用时 SRM 明显异常、关键字段整段缺失）→ 结论必须降级或不下
- **High**：会实质性带偏结论（某分段缺失率突增、口径中途变更）→ 结论带显著 caveat
- **Medium**：局部问题，标注即可
- **Low**：外观问题，不影响分析

## 经典分析陷阱（下结论前对照一遍）

0. **合计行当明细**：把"合计/小计/Total"行混进明细一起 SUM，总量翻倍或虚高。这是最隐蔽的翻倍源——比率会照样正确（分子分母同倍），只有总量错，极难一眼看出。聚合后必对分项和 vs 自带合计。
0b. **只读了半张表**：只读表头/前几行/某一个 sheet 就下结论，漏掉下方的真实明细或其他 sheet 的关键数据。分析前先 `列出所有 sheet + 每个 sheet 的行数`，确认数据边界。
0c. **小计/净额公式失真**：明细有值但小计漏项，或流入、流出均非零而净额被填0。不得照抄汇总行；重算 `小计=Σ分项`、`净额=流入-流出`、`期末=期初+净变动`，报告原值、重算值与差异。
0d. **合并单元格日期错位**：读取库把合并区域后续行变为空，随后错误前填或用行号推断日期，导致相邻日串位。规则命中记录交付前必须回查原始 sheet、单元格坐标和 merge range；两种解析路径不一致时先解决坐标差异，不得选择更顺眼的结果。
0e. **把派生表当唯一事实源**：未确认权威性或要证明跨 sheet 全量一致时，只验证一侧已发现的候选会漏掉另一侧独有记录，不能证明一一对应。
1. **Join 放大**：多对多 join 悄悄把行数翻倍，SUM 全错。join 后核对行数。
2. **幸存者偏差**：只统计今天还存在的实体（在职员工/未删号用户）回看历史。
3. **不完整周期对比**：本月（过了 10 天）vs 上月（完整 30 天）。
4. **分母漂移**：两个时期的"合格人群"定义不同，率不可比。
5. **平均的平均**：把各组均值不加权再平均。
6. **时区错位**：数据 UTC、业务方说的是本地时间，日切分差 8 小时。
7. **选择偏差**：用结果本身定义分组（"活跃用户留存高"——活跃的定义就包含留存）。
8. **辛普森悖论**：总体趋势和每个分段趋势方向相反。凡是混合人群的对比，必须至少按一个关键维度拆开验证方向一致。
