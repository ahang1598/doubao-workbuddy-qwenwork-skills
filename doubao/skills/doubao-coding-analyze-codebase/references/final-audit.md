# 最终审计

出稿前用这份清单尝试推翻草稿，而不是检查格式是否齐全。审计输入是冻结的任务边界、证据图和拟交付结论。

## 1. 覆盖

- 直接结论前是否显示 `named stage | literal locator | observed branch/callee | claim scope | status` 紧凑证据矩阵，且用户点名的每个阶段、符号、路径、入口、行为和限定条件都有独立行与明确裁决；
- 是否用相邻名称、旧实现、示例或同类入口替代了点名对象；
- 点名对象是否先绑定 `repo@revision + path + literal symbol/key` 身份卡，主链每个关键关系是否仍回指该对象；若答案改为另一个实现，是否明确标为对照而非静默换题；
- 行为/流程回答是否闭合到用户真正关心的结果，而非停在中间 helper——指认链账本终点的符号与行号，及它产生的返回、状态提交或副作用；说不出具体终点即视为停在 helper；
- 存在性结论是否带查询、路径范围、名称变体、排除项和快照；
- 结构/边界或归属结论是否由边界图或关系主张闭合，而非被强制改写成虚构流程；
- 多仓任务是否列全相关仓库，每条跨仓关系的两端是否分别绑定所属仓库的版本；
- 纳入与排除范围是否与任务边界一致；
- 服务、模块、发布单元、运行单元或状态所有者等边界标签，是否由匹配维度的构建、发布、装配或运行证据裁决，而非由目录名、初始化代码或文档措辞代替；
- 当前未提交改动是否只作为快照差异处理，而没有被写成用户意图、正确设计、生产热点或任务默认焦点；
- 是否声称“完整/全面/完整心智模型”却未附“未检查/未覆盖范围”清单——缺清单即删除该完整性用词或降级；
- 正文是否出现“让我读取／现在整理／接下来我会”等过程话术，或停在表格、列表、链账本中途的半截截断——出现即判审计失败，回炉补齐。

缺失必答项时回到证据图，不用“代表性路径”静默覆盖。

## 2. 激活五类混淆

为每项关键实现重新核对 `定义 → 装配 → 选择 → 运行时激活`，确认正文没有把：

- 定义存在写成已接入；
- 注册存在写成本次选中；
- 静态可达写成线上运行；
- 测试或示例装配写成目标环境；
- issue、fixture、mock、示例或注释中描述的行为写成当前实现、生产事实或外部契约；
- 某个条件下的观测外推到所有条件。

缺少来源、目标绑定或可复核内容的运行观测，只能保持 `inferred`，用静态范围措辞表达。

## 3. 关系与反证

- 行为/流程任务：调用、数据、状态和副作用是否分别闭合；凡声称 RPC、持久化、提交、重试、版本变化、外部副作用或下游责任，是否已读实际 callee/当前实现到可观察边界，并把存在的 pass-through、conditional、no-op、error 分支分别写入证据矩阵；是否仍从接口名、调用点或返回成功误推实际效果；
- 存在性任务：搜索无结果是否被越过声明边界外推为全局不存在；
- 结构/归属任务：定义、导出/装配、依赖、消费者和状态所有者关系是否足以回答问题；
- 提前返回、错误、部分完成和旁路是否会改变核心解释；
- 最强同名实现、动态分派或替代路径是否已检查；
- 一致性、幂等、唯一性、可靠性等保证是否仅由局部机制推导；
- 外部边界内无法证明的语义是否保留为未知。
- “没有看到/没有显式设置”是否只限定在已记录的搜索范围，而没有被外推为系统不存在、依赖默认值、永久状态或自动恢复；
- 出现“所有、始终、绝不、保证、原子、自动恢复、失败不改变状态”等措辞时，是否逐项覆盖所有实际实现、条件路由、批次/循环、提前返回和外部边界；任一格未知即缩小主张或标为未知。

发现竞争解释时，优先给能区分它们的最小核实动作，不要用更强措辞掩盖冲突。任何虚构路径、符号、行号、命令结果或运行观察都使审计失败。把某个真实文件/符号说成使用了它实际没有的机制（锁、反射、缓存、分派或注册方式等）同样使审计失败——定位真实不等于机制描述真实，措辞前回到该定位核对。空断言同样使审计失败：出现"已检查旁路/已闭合/已排除"这类结论却给不出对应的断点、搜索范围或判别动作时，等同于未闭合，回到对应图边补齐，而不是保留这句声称。

## 4. 诚实分层与交付

- 定位是否来自本轮实际读取，文件、symbol 和行号是否存在；
- 最终答案中每个精确 path、symbol、flag、配置键、数字、枚举和固定顺序是否有逐字声明或完整检索边界；找不到的精确标识是否已删除或降级；
- 事实、推断、未知是否分层清楚，标注 confirmed/inferred/unknown/conflicted；
- 第一屏是否先给点名阶段证据矩阵、紧接直接答案，并限定快照与证据类型；
- 是否只保留会改变理解的未知、冲突和下一验证动作，规模与问题相称。

任一决定性主张未通过审计时，降级为推断或未知，或回到对应图边补证据；不得宣布完成后再用附注补救。决定性证据被用户明确硬 deadline、需要新权限或平台/环境硬限制阻断时，第一屏标记 `PARTIAL` 或 `BLOCKED`，列出未闭合主张、影响和最小解阻动作，不得冒充闭合。
