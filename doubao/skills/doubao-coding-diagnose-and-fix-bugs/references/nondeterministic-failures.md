# 非确定性故障

## 建立可反驳的顺序假设

1. 写下必须始终成立的外部结果，并识别实际共享状态或资源的参与者。
2. 列出会改变前提、开始副作用、完成或使结果可见的相关事件。
3. 说明正确结果要求的顺序，以及违反哪条关系会预测原始症状；没有共享范围或症状预测的候选先排除。

## 控制最小边界

比较正常与异常执行，在首次结果分叉附近控制或可靠记录能区分候选原因的最少事件。可以使用可控依赖、故障注入、隔离组件或带顺序信息的观测；验证方式不得改变当前假设依赖的语义。

测试替身只需保留当前假设依赖的完成时机、错误、共享范围或可见性。若替身与真实契约冲突，先用实现、协议或独立观测证明差异，再修正验证。

补丁应恢复被破坏的顺序、所有权或提交资格。无法控制关键事件时，组合有稳定身份和顺序信息的 trace 与状态快照，并明确仍不能排除的解释。
