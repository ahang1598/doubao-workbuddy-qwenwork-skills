# fallback · Refine Handbook

通用兜底场景的 refine 手册。当内容页需要 refine 时,**判断这页缺什么(缺内容 / 缺表达 / 缺视觉),补什么**。三种动作平权,不排序。

## 一、气质定位

**母题特征**:
- 眉标偏纤细短线(2-3px × 24-48px · 顶部或左侧 · letterSpacing 3-5 极宽)
- 常用符号:◆ 菱形 / ● 圆点 / · 中点 / 上下双 1px 线夹标题
- 编号偏克制方块(20×20 主色底白字 · 罗马数字或阿拉伯 · 编号后空开一小段字)
- 装饰图腾**极简克制**:hairline 分割线 / signature 竖装饰条 / 少量圆角 round-rect / 散布小圆点群
- 信息密度高但**没有明显 style 偏向**:低饱和绿 / 冷灰 / 强表态黑 / 糖果暖色 / 米黄老派各种气质并存,但每页只挑一种签名贯穿
- **图片策略**:通用兜底 —— 各种图片工具都可用,但**都克制用**。图片是为信息服务,不是装饰。优先 SVG 数据可视化,次之 IconPark 图标,再次真实照片 / 生图。一页最多 1-2 个图片元素

## 二、什么样的页需要 refine

**必 refine**:
- `refine_triggers.should_refine=true`(命中任一信号)

**主观 refine**(截图检查):
- 缺内容:整页就一句话 + 几段简介 · 信息量撑不起一页
- 缺表达:3 段纯文字堆砌 / 数字散在正文 / 长段落无层级
- 缺视觉:一角挤另一角空 / 缺 hero 视觉锚 / 装饰母题全缺
- 以上 3 点有任意可以进一步优化的地方

## 三、Refine 三类动作(平权 · 缺什么补什么)

三类动作**没有先后**,一页可能同时缺内容 + 缺视觉,那就 enrich + decorate 一起做;也可能只缺表达,那就只 reframe。

### 3.1 · Enrich · 补内容(缺 payload 时用)

**fallback 是通用兜底 · 强调信息密度 · 各类工具平衡用**。

**A · 用户已给附件/原稿**(`is_manuscript_apply=true`):
- Read 原稿相关章节 · 挖这页可加的**次要信息层**:
  - hero 之外的**具体案例 / 事实 / 时间节点**(整体结论之外的分项、佐证片段)
  - **相关引文 / 权威说法**(原稿引用列表里跟本页主题相关的 1-2 条)
  - **对照 / 前后 / 分项拆解**(有对比结构就拆两栏,有分类结构就做卡阵)
  - **数据细节**(具体数字 · 时间戳 · 单位 · 出处)
- 按信息密度分层塞进页(hero + 支撑数据 + 引文脚注)

**B · 用户只给主题**(`is_manuscript_apply=false`):
- **搜索方向 · 通用权威优先**:
  - 主题相关的通用权威数据(不限行业)
  - 高被引 / 高影响力资料(Wikipedia · 官方文档 · 权威机构)
  - 具体案例 / 事实 / 时间节点
- **搜索关键词模式**:主题 + 通用限定词
  - "\<主题\> facts and figures" / "\<主题\> definition and examples"
  - "\<主题\> 2024 statistics" / "\<主题\> overview"
- **搜完必须标 Source**:关键数据挂来源 · 引文挂来源 · 图片挂来源

**图片策略**:
- **原生 chart / SVG chart 中度用**:数据可视化优先 · 有数据先做图
- **image_search 中度用**:主题相关真实图 · 单张为主
- **image_edit 少度用**:统一多张图的色调 / 边框风格
- **生图** 用于抽象概念示意 · 但克制(一页 ≤ 1 张生图)
- **IconPark 图标** 用于列表 / 分类 · 每页至多 3-4 个

**enrich 后的产物**:一份"内容清单"(hero + 支撑数据 + 引文 + 脚注 + 至多 1-2 个图片元素)· 直接塞进本页

### 3.2 · Reframe · 换表达形式(有内容但表达弱时用)

把已有内容**换更强视觉表达**。fallback 常用替换:

- **3 段纯文字 → 信息卡阵**(前提:内容平权 · 每卡自成一体 · 信息密度高)
- **3 段纯文字 → 图文卡片**(前提:每项有类别属性 · 左 icon / 右 label + description)
- **长段落 → 分点 bullet + 首句加粗**(前提:段内有 3-5 个平行观点)
- **散布正文的数字 → hero KPI 数字带**(前提:数字是本页 payload)
- **数据 → 双列长表 zebra**(前提:多行数据 · 奇偶行 hairline 交替)
- **对照句子 → 前后对比 / 左 vs 右 / 上 vs 下**(前提:两方视角对峙)
- **列举 → 编号阶梯**(前提:有先后 / 步骤 · 1./2./3./4. 大编号 · 编号后空开一小段字)
- **概念 → 定义框**(前提:多概念需消歧 · 术语 + 定义 + 例子 三层)
- **例证 → 引文块 + 作者归属**(前提:名家 / 权威说法)
- **结论 → 大字号 statement**(前提:是本页 payload · 单句突出 · 上下 hairline 夹)
- **时序描述 → 横向时间线 / 竖向阶段带**(前提:有明确时间节点)

**reframe 时的 fallback 风原则**:
- 卡阵克制(3-4 卡最多 · 卡内 3 层:label / value / 脚注)
- 编号阶梯用一种编号风格贯穿(大编号 · 编号后空开一小段字 · 一页一致)
- accent 色仅用于"结论词 / 关键数字"高亮 · 一页至多 1-2 处
- zebra 表格 hairline 交替(1px 极浅主色 · 无竖线)

### 3.3 · Decorate · 加视觉锚点(缺视觉时用)

**装饰母题库**(签名装饰一页只挑一种贯穿 · 不混用):
1. 32×2 纤细短线眉标(低调感 · 用于低调眉标 · 顶部 y=88-94)
2. 中点 · 分隔符(低调感 · 用于列表项之间 / 眉标副标之间)
3. 24×3 直角短线眉标(清晰冷感 · 用于清晰眉标 · letterSpacing 3 极宽)
4. 48×3 长短线眉标(强表态感 · 用于强观点页)
5. ◆ 菱形眉标(强表态感 · rotate 45 的 rect · 6-10px)
6. ● 圆点眉标(暖糖感 · 8-12px 主色实心圆)
7. 12×12 主色圆点装饰群(暖糖感 · 6-8 颗散布 · 页面角落)
8. round-rect 圆角块(暖糖感 · borderRadius 4-8 · 用于卡片 / 编号底)
9. 上下双 1px 线夹眉标(老派档案感 · letterSpacing 5)
10. 编号方块(20×20 主色底白字 · 罗马数字或阿拉伯 · 卡内左上或主标左侧)
11. hairline 分割线(1px 极浅主色 · 分节 / 分列 / 段间)
12. signature 竖装饰条(2-3px × 60-100px 主色 · 卡内侧或整页左侧)

**视觉锚点升级库**(把已有元素做大做强):
- hero KPI 提到 60pt+ · 加圆环底(220×220 主色 1-2px 边框)或方块底
- 主标副标重叠矩形(半透明主色色块 · 做视觉分区)
- 关键结论 accent span 高亮(一页至多 1-2 处)
- hero 引言块(24-32pt · 上下 hairline 夹 · 左右各留 100px 白)

**布局重构库**(修视觉塌陷 · 每次 refine 最多挑 1 个):
- 左右对称分栏(60% 主 + 40% 支撑 · 中间 hairline)
- 上 hero + 下 3 卡
- 中央聚焦 + 四周对称留白(结论页 / 关键发现页)
- 全宽多列(3-4 列 · 均匀信息密度 · 平权信息展示)

## 四、使用规则

**判断这页缺什么的信号(每类独立触发 · 不排序)**:
- `total_text_chars < 60` 或截图看整页几句话就完 → 3.1 enrich 补内容
- 文字够但堆砌成段落 / 数字散在正文 → 3.2 reframe 换表达
- `visual_elements ≤ 12` 或截图看装饰全缺、视觉重心塌陷 → 3.3 decorate 加视觉锚
- **一页可能同时缺 2 类 / 3 类**,那就多类一起做

**气质一致性**(每次 refine 后过):
- 加的元素克制吗?(fallback 是通用兜底 · 加什么都要克制 · 不追求冲击力)
- 一页只挑 1 种签名装饰吗?(◆ 或 ● 或 · 或双线夹 · 不混用)
- letterSpacing 用一种风格贯穿吗?(2 或 3 或 5 · 一页一致)
- 一页图片元素 ≤ 2 个吗?
- 强调色克制吗?(一页至多 1-2 处 accent 色高亮)

**不要做的事**:
- 不要动 brand_assets(背景 / 页眉 / 页脚 / 装饰线 · 一律保留 · 只加不删)
- 不要混不同签名装饰(◆ + ● + 中点混着用是灾难 · 一页一种)
- 不要追求 pitch 冲击力 / 学术档案感 / 品牌情绪(fallback 是中性的 · 有明确气质需求应换 style)
- 不要滥用装饰(fallback 已经不知道用户要什么了 · 再堆装饰会更乱)
- 不要编造数据:enrich 走搜索时必须真实来源 · 带 Source 脚注
- 不要跳过 enrich 只做 decorate 装饰凑数(内容不足时补装饰只会让页更难读)
