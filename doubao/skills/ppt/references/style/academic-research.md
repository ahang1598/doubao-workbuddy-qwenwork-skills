# 学术研究

**视觉参考**：可参考顶尖高校学术模板、成熟 Beamer 主题、权威科研期刊图版和高水平学术会议演示的共通特征，但不要机械模仿具体模板；应提炼其背后的视觉原则，理性、克制、清晰、可信，强调严谨的信息层级、充足留白、稳定网格、低饱和配色和高质量图表整合能力


## 目标

### 叙事：第一分钟就抓住价值；进度始终可见
遵循「研究背景、证据缺口、研究问题、实验假设、核心证据、结论、贡献」的叙事逻辑——让评委/导师在第一分钟内就把握到价值所在。

通过合理的章节规划、在关键位置增加过渡页、把导航栏内建进正文骨架等方法，让评委/导师随时了解演示文稿的进度。

### 视觉：简约而不廉价
学术场景下的演示文稿往往朴素，但朴素不等于简陋，更不等于廉价。使用恰当、精致的颜色——在精神气质上意料之中，在具体选择上意料之外——搭配精心的排版，营造高级感。
1. **保持极简风格**：装饰元素与装饰图片只允许用于封面页、章节过渡页、结尾页、页面背景图等区域；严禁用装饰图片来填充正文区域。图标也不是填补留白的万能药——只有当添加图标能带来明确收益时才使用。
2. **高级感来自精细的细节设计**：统一的页面骨架、标注数据来源与参考文献的脚注标记、图与表的图注、恰当的页码、精心设计的字号层级与字体……
3. **反常规高端配色**：
  - 当用户精确提到某个学校/机构/组织名称/会议名称/期刊名称时，必须下载官方 logo，用 logo 的主色作为主色，并在合理位置插入 logo。若无法获取 logo，则不要使用 logo 的主色，以免出现偏差。
  - 拒绝本场景中最常见的配色：不能使用医院蓝、医疗绿、环保绿、海洋蓝等颜色
  - 除非用户明确要求，否则不要使用粗糙、简陋的黑、白或浅蓝背景；向更精致的背景靠拢，例如钛灰 #E7E8E5、档案纸 #F1E9DA 或象牙纸 #F7F3E8。
4. **大字号下的高密度**
  - 学术演示文稿应在恰当字号下保持高密度，同时保留一些呼吸空间。不同于行业研究与金融的小字号与单倍行距，学术研究的正文应使用更大的字号（10 以上）与合适的行距（1.3 左右），除非交付物是学术海报之类的阅读型产物。同时，它应具备行业研究与金融那样的「饱满感」：区域之间留出一些呼吸空间，但每个区域内部要填满。
  - 严禁出现规划了 100px 的区域最终只放下 70px 内容的情况。
5. **严谨精细的排版**：禁止卡片布局，需要使用视觉密度合适的排版，用线段、留白以及字体/字号差异展示信息差异。长段文字之后应该空一行，再写下一段，不要大段的堆砌。
6. **一定的示意图与图表密度**：学术研究应该保持一定数量的学术示意图和丰富的图表来进行展示，学术示意图需要重点展示研究主体的细节和逻辑关系

### 从研究领域出发；考虑视觉焦点
不同研究领域的学术演示文稿各有侧重：思考该领域真正重要的是什么，并决定每一页应聚焦于什么。
- 基础研究与理论推导：公式、定义、命题与证明步骤是焦点；严谨、完整的推理过程占据大面积区域。
- 计算机科学与工程：系统图、代码、运行轨迹、消融实验与性能曲线构成页面骨架。
- 实验研究：研究图、图像与表格是焦点。属于同一研究结论的公式、图表、表格与图像应尽可能紧凑。
- 实证分析：本质上也是实验研究，但社会科学的工作应比理工科的工作更具叙事性。
- 人文/建筑/艺术：档案、手稿、图像细节、时间线索与文本证据……除了学术严谨性之外，还应有品牌级别的精致——必须读一遍 `brand-storytelling.md`。
- 使用形状、线条与箭头作为标注，来强调或解释图表与图像的内容，但是注意禁止任何文字穿线现象，线条应该止于节点边缘
- 使用图片必须是能够辅助当页信息表达，优先使用附件内的真实图片，准确传达信息

## 禁止项

1. **默认禁止使用卡片**：除非用户明确要求，否则严禁使用圆角矩形或矩形卡片来构建层级或对齐：线段、留白以及字体/字号差异是更好的解决方案。
2. **禁止均分构图**：除非没有其他可用布局，否则不要默认采用三等分、四等分或 2×2 矩阵——包括「三栏 + 标题 + 结论」这类三段式套路。
3. **禁止平庸、常见或典型 AI 味的配色**：严禁任何蓝白搭配、蓝紫渐变、青紫霓虹、彩虹光晕、玻璃拟态卡片或发光边框——除非用户明确要求。
4. **禁止过小的字号**：除非用户要求，或交付物是阅读型产物（海报等），否则正文不得使用小字号。
5. **区域内禁止留白不足**：严禁出现任何内容无法填满其规划区域的情况。文本框填满还不够——从截图中看到的实际文本内容必须填满区域。填不满是最严重的一种粗糙，会让人感觉排版完全没有用心。
6. **禁止用默认图表设置**：严禁使用软件默认的坐标轴、网格线、图例框、彩虹配色、粗黑表格边框、3D 柱形、渐变填充、投影——必须全部重做；同一份演示文稿中所有图表使用同一色系深浅，不引入第二色族，但在饼图等多类别图表中，各图例颜色需明显可区分，优先保证识别性，避免颜色过近；
7. **禁止不合理截图**：附件素材内图表必须原汁原味使用，不得进行图片切割，应该让排版适应图片而不是图片适应排版。
8. **禁止不规范用图**：学术论文内的图片除了用于信息展示或者机构院 logo 之外不得重复使用，用图需要严谨，且避免信息被裁切。

## 数据获取先于画图

**学术 deck 的核心是证据,一张图承担一个结论。** 在挑 slug 之前,先尝试拿到真实数据:

- **用户附件**: 最重要的数据源。附件里的 CSV / xlsx / 实验表 / 公开 benchmark 数据 优先使用。
- **检索限时**：检索与精读合计控制在约 8 分钟；网页抓取被拒（robots、超时）或 PDF 下载失败就改用搜索摘要里的数值，不要绕道渲染 PDF 页面、截图读数。
- **学术搜索工具（scholar_search）**: 你有用专门进行学术数据搜索的工具，你可以通过学术搜索到大量相关的论文 pdf 数据的摘要，从而用来构造 ppt 中需要的图表与示意图，但不需要过度使用，防止上下文过大而无法进行精读，一般最多只使用1-3轮搜索即可。
- **论文精读（web fetch）**：你可以更多的使用 web fetch 工具调用论文的 url 来得到搜索到的论文的完整内容，工具会为你返回具体的论文中的文本、图表、图片等，从而使得你可以使用这部分内容来构造 ppt：
  1. 当你获取到了论文中的关键图片时，你可以直接使用论文中的原图（用 curl 下载后再上传）来制作 ppt，而无需再次二次重画
  2. 当你需要表达多篇/一篇论文中的核心观点，并且获取到的图片不能完整表达这一点时，你可以使用手画 svg 的方式来展示核心的机制图
  3. 你可以使用一篇或多篇论文中获取到的数据来共同制作图表，从而大幅提高你的 ppt 的可信度；精读时优先记下置信区间/SD、多个时间点或剂量、对照组与处理组的成对数值，这些是专业图的原料；规划大纲时给每个正文章节写下要找的量（疗效找 HR/率 + CI 与 n，毒理找各物种 EC50，性能找曲线上的点），标题核心章节必须有数据图
  4. **这是构造 ppt 的图表的完整数据和图片的真实来源，即使搜索工具得到了一部分数据，这一步也不可跳过！**，精读同样控制在1-3轮即可
- **示意/模拟数据**：真实数据无法获得或暂未提供时，可以使用合理的模拟数据，但是需要在图注(`note=` 参数)明确写"示意性结构,数据为模拟"或者是在图的下方写明白数据来源于模拟数据。

## 常用学术数据图

本场景默认使用 SVG 图表库。每页数据图先写下要回答的研究问题，再参考 `chart_help()` 总览（完整阅读，不截断）里“按研究问题选图”的学科表选入口——疗效与风险比较、两状态差距、时间变化、剂量效应、性能曲线、谱学与相区、能垒等都有对应专业图，文献已报告的汇总值就能画；该表只是举例，表中没列的学科、问题或图种（见总览末尾全部入口）只要更贴切，同样鼓励使用；类别柱状只用于确实没有更贴切问题的少量类别概览。不为增加图形复杂度补造分布、区间或统计结果。

SVG 数据图在 `chart_help()` 短总览核对条件后，调 `chart_help('<slug>')` 看参数；用 `chart_slide(slug, x=, y=, width=, height=, **kwargs)` 放进页面（文字原生可编辑、同色色块可整体换色）。关系库支持的结构走 `relation_help('<slug>')` + `make_relation_atomized(..., strict_no_embed=True)`；自定义示意图用 drawing 库画后 `to_slide`。学术页的数据图必须来自图表库，不用原生 `<chart>`、shape/drawing 拼的条形图或手画坐标曲线、PNG 图片代替。**一份学术 deck 至少要有 2 页由图表库生成的数据图，其中至少 2 页使用 grouped_bar 以外的专业图种（按数据分布从 chart_help() 选出）**：文献中报告过的数值（容量保持率、电压平台、HR、ORR、丰度、生存率、回归系数、温度序列等）用该学科的专业图呈现并标注来源；缺少原始数据时可用已报告的汇总值作图，或标注“示意数据”。**每张图至少 3 个数据点/行**——只有 1–2 个数字时写成大号数字放进正文，不要为凑图做一两行的哑铃图或柱图。时间序列（温度、海冰、发病率、价格）优先 `scatter` 曲线 / `line_band`，标量场与纬度–时间用 `contour` / `time_latitude`，效应与系数（可为负）用 `coef_plot` / `forest`等等。

**统计标识画进图里，不留在正文**：来源报告了的 CI/范围、n、事件数、P 值作为行字段传给图表——`forest` 行的 `n`/`events`/`p`、汇总行 `is_overall` 菱形、`favours=("A 更优","B 更优")`；`dumbbell` 行的 `before_lo/hi`、`after_lo/hi`、`p`、`n`、`delta_ci`；`coef_plot` 行的 `lo/hi`、`n`、`p`、历史对照或目标值 `benchmark`；柱图/曲线的 `reference_lines` 画基线、目标值或 =1 线。文献给的是范围就传 lo/hi，不取中值；≥3 个“估计值 + CI”进 forest/coef_plot，不写成大号数字。`chart_slide` 自动把配对、窄幅、数值型类别的柱图换成专业图时，按警告补字段，不要改回柱图。文献里是曲线（等温线、生存、剂量–效应、循环）就用图表库重绘，不截原图。

**每页都要有主视觉**：正文页里纯文字页（只有文字栏/列表）不超过 2 页，其余页必须有示意图、数据图、表格或图片之一，并占据页面主要面积（≥40%）。规划大纲时就为每页写下主视觉（图表 slug、示意图要画的对象或图片来源）。

**按子风格选图**：图表推荐写在下文各子风格的「图表」条目里，先按研究问题选入口，再 `chart_help('<slug>')` 看参数与示例；不要使用其他原生图表或 shape 拼接的图表。不同研究条件的汇总值不默认合并计算均值或误差。

## 学术示意图（schematic）手写规范

**数量**：一份学术 deck 手画示意图控制在 **1–3 张**（至少 1 张），只画最核心的内容（核心机制、核心结构、核心算法/方法流程；综述类也要有自然史/因果链、研究设计或检索流程之一），不用文字加 → 代替；其余页用论文中的图、图表库数据图、表格或文字版式承载，不要每页都手画，防止运行的时间过长。

**示意图** 用 drawing 库绘制，对象精细度与连线规则见 `references/xml/svg-writing-guide.md` 第三、四节（教科书级辨识度、部件优先、端点传节点对象），这里不重复；下面只写**学术示意图特有**的构图与收尾流程。

**先定构图，再画对象**：期刊机制图的可读性首先来自版面结构，其次才是部件细节。动笔前先从下表选一种范式写进大纲（如“第 5 页 主视觉 = 对照：未治疗 vs 抗 PD-1”），一张图只讲一个机制结论。

| 范式 | 什么时候用 | 骨架 | 可运行模板 |
|---|---|---|---|
| 对照 | 治疗前后、野生型 vs 突变、正常 vs 疾病 | 左右两面板画同一结构，只改变一个条件；面板间一条细竖线；差异处用强调色 | `scripts/svg_lib/drawing_examples/compare_panels.py` |
| 全景 + 局部放大 | 机制发生在大结构的某一处（界面、突触、细胞器、器件某层） | 左侧整体交代位置，放大框坐标取自部件端口；右侧放大**框内那一处**结构讲机制，虚线连接两框 | `scripts/svg_lib/drawing_examples/overview_zoom.py` |
| 通路流向 | 信号转导、物质/能量转化、跨膜转运、方法流程 | 上游→下游单一主方向（左→右或上→下）；分支和反馈接到明确对象上；输出写成结论框 | `scripts/svg_lib/drawing_examples/membrane_transport.py`（两层膜 + `transporter` 泵/通道/反向转运体 + 离子流向：离子转运、上皮转运、线粒体内膜同一骨架；细菌包膜用 `cell_envelope`） |
| 分区面板 A/B/C | 一个结论需要 2–3 个互补角度（结构 + 过程 + 结果） | 每块左上角粗体字母 + 一句小标题，面板间用留白或细线分隔，不用卡片框 | `compare_panels.py` 的面板骨架 |

构图通用约定：面板标号 `A`/`B` 粗体与小标题同行；图例（线型含义）用 `legend_row` 放在左下角；全图同一配色、同一线宽；面板内的结构用同一部件、同一尺寸，读者才能一眼对比出差异。模板路径相对 skill 根目录，先 Read 选中的那个模板，复制到工作目录改成该示意图页的 `build_pNN.py`（首行 `sys.path` 改成 skill 根目录绝对路径），替换部件与文字即可；模板只生成示意图片段，页面的标题、正文、来源仍在 `page_xml` 里手写。

**第一轮就画到位，审查有提示再预览精修（仅限手画示意图）**：
1. 第一轮直接把研究主体画成有形态的对象：优先用部件，库里没有的用 `svg_at` 写内嵌 SVG 节点（多个形状、分区着色、结构细节），不要先用 `box_at` 方框占位、准备以后再改；方框只给步骤名、结论框和配角标签。
2. 画完先 `d.check()` 改掉报出的问题；再看 `d.review()`（`to_slide` 也会自动打印「细节审查」）：它会点名连线最多、面积最大的主体里只画成方框/单个图形/纯文字的节点，以及手画的膜、字符箭头。
3. **review 为空**：主体已有细节，直接 `publish_slide` 写入，不用预览。
4. **review 有提示**：先判断点名的节点是不是实体——是实体就按提示换成部件或 `svg_at` 外形（`node.replace_svg` 原位替换，连线跟着走），只是概念/步骤标签就保留；然后 `d.preview("pNN.png")` 看一次，对照四点（主体一眼认得出、关系读得通、对照/放大对得上、无大块空白或拥挤）精修一轮后写入，不做第二次预览。
4. 数据图（`chart_slide`）、关系树、纯原生页不做预览，仍按 Step 7 只看 lint 响应。

## 视觉参考


### 自然科学与工程实验研究

**路由条件**：理工科实验研究（生命科学、物理、化学、材料科学、工程系统）；结果驱动、数据图表密集；会议海报或研究成果展示。

**核心特点**：实验室海报的秩序与张力——严格网格、巨大结论、大面积纯色色块与出血研究图像，比例强烈，安静但不保守。

**配色**：优先从研究领域或机构标识中提取一至两个主色；无机构标识时**必须从本文顶部「推荐 palette」表选一个 slug,下面是从命名 palette 衍生的 slide 层色号,与 chart 库 `palette=` 保持同色,不要自造 HEX 组合**。色块使用大面积纯色,拒绝多彩。

**参考配色**：
- `science_cell_eng`：主题色 深李紫 #5B1061；辅助色 品紫 #9B2D6F 和 玫瑰粉 #F06A99；背景色 近白 #FAFAFC；标题文字色 靛紫 #2A1A4A；正文字色 中灰 #5B5A55。chart 调用传 `palette="science_cell_eng"`。
