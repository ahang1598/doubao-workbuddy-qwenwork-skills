# 商务汇报（business-deck）

**路由条件**　商业分析与汇报是商务类默认档。面向具体受众，围绕业务问题说明进展与结果、解释经营变化、分享研究发现、论证方案或提出建议时，使用本指南。适用于工作与述职汇报、经营复盘、项目评审、董事会汇报，也适用于行业与市场研究、公司与竞品分析、商业提案。

**边界**　按整份材料的主要沟通目的归类。以业务事实、研究证据或方案论证为主，归本档；以品牌形象、产品亮相或活动传播为主，归品牌叙事或发布宣讲；学术课题、政策研究和科学技术研究按各自体裁处理。

**对标参考**　经营与管理汇报参考企业季度经营回顾、董事会材料和咨询公司高管汇报，让读者迅速读出结果、差距及其含义。商业研究与分析型汇报 deck——每页一个可验证的判断，围绕相关证据组织分析，读者可独立读完并追溯每个数字。

**气质**　专业、克制，重点清楚。现场讲述让听众迅速找到主张和关键证据。连续页面保持稳定的阅读顺序，强调色指出值得关注的对象或变化。信息密度、字体和构图随使用场合、品牌规范与内容关系确定。

## 先保证清楚可读

- **正文字号最小为 14 pt**：正文、bullet、表格、图表标签最小 **14pt**，只有仅供追溯的来源和脚注可小一层级到 10–12pt；除用户另有要求，字号采用偶数 pt 档位。
- **字号体现信息层级**：可通过字号与字重建立页面大标题、小标题和正文层级，标题字体相对大小必须与信息层级一致；同一级小标题或正文使用相同字号，一个页面正文通常不设置2种以上字号；模块内的小标题字号不小于正文字号。
- **字体分工明确**：展示字体与正文字体分工明确（同一无衬线家族的不同字重，或无衬线体标题 + 另一家族的正文）；编号、标签、脚注的样式保持一致；字体与配色互相参照，一并设计。

- **字号参考**：页标题 28–32 pt，分区标题 20–24 pt，局部小标题 18 pt，正文 14–18 pt。以上是无指定模板时的起始档位；按实际层级和展示尺寸选用，仍执行正文最小 14 pt。

## 一、组织内容与页面

### 1. 明确业务问题与受众

- **明确受众要解决的业务问题。** 从需求和材料中确认谁在汇报、谁会听或读，以及对方需要弄清什么。把“做一份经营分析”这样的主题落成一个能回答的问题。结合受众已经知道的背景、关心的结果和材料的使用方式，确定本次汇报的重点。
- **按业务实际拆解问题，用证据形成判断。** 复杂问题沿着业务实际如何运作，拆成几个可以验证的子问题：每个子问题要弄清什么，哪些事实能回答它，它的答案会怎样影响对整体问题的判断？优先分析最可能改变结论的部分。
- **围绕核心判断组织论证。** 用一句话回答本次汇报的核心问题，再选择共同支撑这个回答的理由、证据和必要条件。每一部分都应让读者更容易理解结论为何成立、适用于什么范围。
- **措辞专业、贴合身份**：采用受众熟悉的业务语言，准确表达具体事实、判断和行动。

### 2. 使用附件和证据形成判断

- **落实交付要求**：把附件明确要求的PPT内容落实到页面。 编排内容时，按照用户要求回答的问题、呈现的图示和说明的方法安排具体页面。

- **数字保真与计算**：用户给的数字和事实原样呈现；判断依赖比较基准时，将基准值与结果一并展示；附件 / 来源里没有的数（客单价倍数、毛利率、回收期、目标值）不写，确需示意就标"示例 / 待确认"；差值、占比、倍数和"升至 / 降至 / 增长 x%"的方向与数值用程序从本稿的上下两期原数算，同一目标值全篇取同一变量，不心算。

### 3. 将论证组织成页面

- **把论证主线编排成页面，排出关键页。** 从受众已知的背景出发，判断哪些发现、解释或建议需要单独讲清。页与页的顺序取决于读者接下来需要理解什么。
- **为每页确定标题和依据。** 标题点明本页要传达的结论，正文给出直接支撑。连续几页围绕同一问题时，每页应推进一层理解；连读标题，应能看出整份材料怎样回答核心问题。
- **按理解需要决定分合。** 需要逐项对照的信息尽量放在同页，按共同维度对齐。一页解释能讲清的，就放在对应证据旁；两个主题相互独立、重要追问需要另一组证据，或必要内容在实际观看尺寸下难以读清时，再拆页展开。
- **目录与章节导航**：需要帮助读者定位章节时，用目录、页眉章节标签或章节页。目录可用单列或双列，章节标题、编号或图标按实际导航需要选择；一般不添加目录项释义、英文译名和导航小字。

### 4. 按用途取舍信息密度

- **按读者任务取舍主次。** 向管理层汇报情况，优先讲结果、业务影响和需要讨论的事项。
- **按使用方式决定一页放多少。** 现场讲述应让听众在讲到这一页时能看清主要发现及其依据，需要放在一起比较的证据保留在同页。同页内容必须有内容联系，共同支撑标题结论。
- **正文聚焦业务内容。** 用标题、图表和正文直接呈现事实与判断。一般不加副标题、装饰性英文、页面写作说明及重复内容；除必要的页面最下方的脚注外，一般不添加其他小字号的、灰色字体的说明。
- **研究与投资分析型汇报**：兼顾独立阅读和讲解。信息密度来自相关证据与分析的集中呈现，不靠增加辅助说明、无关指标、重复结论或缩小字号。

## 二、把内容关系变成图表与结构图

### 1. 找出本页需要看懂的关系

- **按关系选图**：先问“要表达什么关系”（演进 / 流转 / 层级 / 对比 / 构成 / 趋势 / 分布），再选图表或结构图，具体形式见下表。
- **图形辅助理解**：结合汇报内容使用配图或图形组合，把对象、关系、过程和推理依据呈现清楚，图文对应，避免仅作装饰。

### 2. 数据关系：选择图表

| 读者需要看懂什么 | 推荐图型 | 使用条件与画法 |
|---|---|---|
| 哪些对象更大，排名如何？ | 条形图 / 柱状图 | 比较同一口径的指标，柱或条从零起画。排名按数值排序，有业务顺序的类别沿用原顺序。 |
| 各期规模分别是多少？走势在哪里发生变化？ | 柱状图 / 折线图 | 看各期规模用柱状图，看连续变化、转折或多条走势用折线图。时间按先后排列。折线图需要判断绝对水平时保留有意义的零点，重点是看波动时可收窄纵轴并清楚标出刻度。目标或行业基准按实际数值画参考线，纵轴范围另行决定。 |
| 一个整体如何构成？总量或结构怎样变化？ | 堆积柱状图 / 100% 堆积图 / 环形图 / 堆积面积图 | 分项互不重叠、可加总。比较总量及其构成时用普通堆积图，比较不同对象或时期的构成比例时用 100% 堆积图。单个整体、类别较少时可用环形图。需要精确比较某一分项时，用共用零线的条形图。连续时间上的构成变化可用堆积面积图，面积图从零基线开始。 |
| 总量为什么从起点变到终点？ | 瀑布图 | 各项增减使用同一单位，起点加上各项变化应等于终点。柱的位置表示变化前后的累计水平，分别标明正负贡献。 |
| 各对象在两个指标上处于什么位置？还要同时看规模吗？ | 散点图 / 气泡图 | 每个点代表一个对象，横纵位置分别对应两个指标的实际数值。只看两项指标时用等大点。第三项非负数值也影响判断时，用气泡**面积**表示。 |
| 同一批对象在两个时期或状态之间，各自变了多少？ | 哑铃图 | 每个对象占一行，两端点表示同一指标的两次读数，用同一数轴呈现方向和差距。只看期末排名时用条形图，需要观察中间转折时用折线图。 |
| 同一批对象经过哪些阶段，流失主要发生在哪一步？ | 转化漏斗图 | 阶段有先后关系，后一阶段的对象来自前一阶段。用各阶段数量表示宽度，标注关键环节的流失量或转化率，计算基准保持一致。 |
| 数量从哪里流向哪里，各条路径占多少？ | 桑基图 | 每条连线都有同单位的流量，线宽与流量成比例，分流和汇合处的数值能对应。只有角色、合作或交接关系时，用关系图。 |
| 两个维度交叉后，哪些组合偏高、偏低或异常？ | 矩阵热力图 | 行、列分别表示两个维度，每格用同一色标表示可比数值，注明色标含义。需要精确核对的格子保留数值。 |
| 贡献集中在哪些对象，累计到哪一项达到某比例？ | 帕累托图 | 柱按贡献量降序，累计线按同一组数据计算，标明累计百分比。仅需排名时用条形图。 |
| 需要逐项核对多个数值或文字？ | 对照表 | 将对象与共同的比较维度分别放在行、列上，对应内容对齐呈现；同一指标使用一致的单位和口径。 |

- **双轴**：确需在一张图中对读两条不同单位的序列时才考虑双轴，分别标明两轴单位和刻度；两轴刻度相同就合成一轴。不同基期的指数先换算成同一基期，或拆为两张图。
- **轴与标签**：保留读数所需的坐标、刻度与关键标签，弱化多余网格线。标签不压线、不互叠；放不下时调整图幅、方向或使用无歧义的简称。

### 3. 文字关系：选择结构图

**常见文字内容结构图**

| 读者需要看懂什么 | 可选的页内元素 | 选用与画法 |
|---|---|---|
| 有哪些同级要点？哪些属于同一组？ | 分组列表、并列栏 | 同级项沿共同方向排列，重复项提取出共同的维度，具体特征在对应位置展开。各项用同级粗体短标题，所属内容紧跟其后；无先后关系不用箭头。 |
| 多个对象分别在相同的几个方面表现如何？ | 对照表、行列对齐的文字版式、成对示意图 | 逐个介绍对象时，每行放一个对象，每列回答一个共同问题，列名只写一次。若重点是逐项比较，可将维度放在行上，让各对象并列。文字可通过对齐和间距组成行列，是否画边框按可读性决定。|
| 各部分归属哪一层？核心问题可以拆成哪些子问题？ | 层级树 | 单层归类可用组名和缩进。需要看清多层归属或问题拆解时，将父项连到直属子项。每个父节点和它的子节点群作为一个整体，根节点居中，子节点横向排列，逐层展开；同层对齐，需要节点边界时用矩形，归属连线不自动加箭头。 |
| 事情按什么顺序推进？什么条件会改变路径？ | 编号步骤、条件流程图 | 线性步骤按执行顺序编号；需要追踪路径时，用矩形表示业务处理节点、菱形表示判断路由，箭头连接相邻步骤，条件分支标明“是 / 否”“通过 / 拒绝”等触发条件。 |
| 哪一步由谁接手？ | 跨职能流程图（泳道图） | 按角色、部门或系统划分泳道，将步骤放在负责方的泳道内。水平泳道为横向条带，流程从左到右推进；垂直泳道为纵向列，流程从上到下推进。跨泳道同一阶段严格对齐，按实际先后连接，发生交接时再跨泳道。 |
| 不同条件组合分别采用什么处理方式？ | 决策表 | 每行写一条规则，前几列列出条件，末列写对应动作或结果。简单条件可直接用一句话说明。 |
| 哪些任务相互依赖？何时发生或持续多久？ | 任务依赖图、里程碑时间线、甘特图 | 看依赖时，由前置任务连向依赖它的任务。看日期时，用圆点将事件落在时间轴上，事件名称贴近对应圆点；需比较工期或并行区间时，用横条的起止位置表示起止时间。 |
| 谁向谁提供、支付或移交什么？ | 角色关系图 | 用矩形或“图标＋名称”表示参与方，箭头指向接收方，线上标明交付物或动作。仅需介绍参与方时，按角色分组列出即可。 |
| 一个问题有哪些待调查的原因？ | 原因树、鱼骨图 | 逐层追问用原因树；按类别梳理可能原因用鱼骨图，鱼头写问题，主分支写类别，细分支写原因假设。 |
| 举措通过什么变化产生结果？结果是否反过来影响起点？ | 机制链、反馈回路图 | 用矩形节点按作用路径连接举措、中间变化和结果，区分预期与实绩。后续结果确实会反馈到前面环节时，再画回程箭头。 |
| 各阶段分别做什么，需要同时核对哪些工作？ | 阶段矩阵 | 阶段做列、工作类别做行，或反向排列；共同标题只写一次，动作或交付物放在对应格。日期和工期影响判断时再用时间轴或甘特图。 |

- **组合使用**：这些图形是页内表达元素，可与数据图、表格或图片组合。
- **准确表达关系**：形状大小、连接方向、尺度与分组反映真实关系。节点内容来自材料，不能为补齐层数、分支数或对称布局添加事实。
- **节点与连线**：按图形语义选择矩形、菱形、圆点或图标＋文字。普通节点用白底或浅底、深色文字，需要边界时加细描边。连线用低干扰的灰色，关键路径可用强调色，线端落在节点边界并避开文字；箭头表示有方向的关系，关系类型需进一步区分时在线上标注。

### 4. 在图中突出支持判断的证据

- **图表服务于内容理解与判断**：依据任务和数据决定图表类型、数量与组合。图表呈现关系与证据，文字只写图表未直接呈现的解读或判断。
- **突出关键数据**：比较差距时就近标出差额或基准；观察转折时标出关键时点；解释阶段影响时，可用浅色区间覆盖对应范围。标注与对象使用一致的名称和颜色。
- **标注准确对应数据**：使用图表本身的数据标签或参考线，避开图形与文字；当前实现无法可靠定位时，调整图表或生成方式。

## 三、把图文组织成规整的页面

### 1. 确定整页阅读方向与空间

- **主要内容沿一个方向展开**：先确定读者理解本页需要依次看什么，再将主要内容组从左到右或从上到下排列。需要相互比较的内容组成一个完整对照区，支撑共同判断的背景和总结分别安排在整组之前或之后。横向并列时各组完整地并排呈现，纵向展开时各组依次向下排列；一般不将同级内容排成一侧完整大区、另一侧上下两个独立区域。
- **按内容主次分配空间**：平等比较可用等宽布局，主次不同的对象按信息作用分配空间。主要证据在实际展示尺寸下清楚可读；放不下时精简重复内容、扩大主材料区域或拆页。
- **保持清楚的对齐边界**：同组内容靠近，组间留白；并列区域的标题起点、外边界和间距保持一致。区域内部按内容长度安排高度。
- **信息定位固定**：结论 / 标题在固定的标题位；同类页面的阅读起点保持一致，正文分区随内容关系调整。来源和脚注统一放在页脚。

### 2. 将同一主题的内容放在一起

- **整组呈现**：同一主题的标题、图表、数据和文字集中在一个区域，组内内容紧随所属标题。不同主题分别占据独立区域。
- **同级同构**：同一组并列条目使用同一套标题、正文和标记格式，对齐标题起点和需逐项对读的内容；保持同级字号一致。
- **共同维度共用标题**：多个对象反复回答同一组问题时，提取共用行标题或列标题，对应内容在同一行或同一列对齐。可用加粗维度标签或浅色表头帮助定位。
- **位置和跨度对应范围**：只解释一项的文字留在该项内部；引领或总结多项的标题与结论放在这些项共同的上方或下方，跨组独立成行。已有共同结论可用粗体或浅底结论带，左右边界与所概括的整组对齐。
- **多图组成完整图区**：需要连续阅读或相互比较的图表集中排在同一行或同一列。每张图的标题和解读归入对应图区；综合多张图的解读位于整个图区共同上方或下方。

### 3. 选择标题与区域的呈现方式

- **按区域选择形式**：根据内容关系和全稿风格，从下表选择分区形式。同级区域沿用同一种标题和分区样式，底色或边框覆盖完整内容组；一般不在同一区域叠加标题带、整组浅底和外框。
- **标题体现归属**：小标题放在所属区域上方或内部顶部，与正文左边缘对齐；标题到内容的间距小于组间距。组内确有下一层内容时，局部小标题紧邻对应材料，字号或字重低一级，字号执行前文规定。

| 分区形式 | 标题怎么放 | 区域怎么画 | 适用情况 |
|---|---|---|---|
| 留白分区 | 左对齐粗体短标题；对象或动作有明确图标时，可配图标＋短标题 | 沿用页面底色，通过统一对齐和组间留白划分区域 | 内容简洁，归属清楚 |
| 标题带分区 | 标题放在浅色标题带内，同级标题带顶部对齐 | 用横向矩形承载标题，宽度与所属内容区一致；正文区沿用页面底色 | 需要快速辨认几个并列主题 |
| 整组浅底分区 | 标题放在区域内部上方，与正文左边缘对齐 | 用浅灰或主题浅色矩形承托标题及全部内容，使用直角或统一的小圆角，四周保持一致内边距 | 每组包含图表、数字和文字，需要强化整体归属 |
| 细边框分区 | 标题放在框内上方，与正文左边缘对齐 | 用透明填充、浅灰细描边矩形围住整组，四周保持一致内边距 | 页面底色保持统一，同时需要明确区域边界 |

- **分区语言保持一致**：同页样式和跨度相同的底色、边框或分隔线表达同一层级的边界。细分隔线用于独立信息组之间或辅助表格逐行对读；一般不在同一标题所属内容中反复划线。

### 4. 标记组内要点

- **按内容关系选择标记**：有严格先后顺序的步骤用序号；并列发现、举措或理由用短标题或项目符号（•）。图标有助于辨认对象或动作时，可放在文字标签旁，含义对应、风格一致；章节编号用于导航。
- **保持文字对齐**：换行后的文字与该条首行文字对齐。普通说明段、图注和表格内容按各自结构排版，一般不添加列表标记。


### 2. 颜色语义与重点表达

- **图表色系**：所有图表沿用全稿色板，同一对象或类别跨图保持颜色含义一致。单系列默认用同一基础色，结论指向特定时点或类别时，可用全稿统一的强调色突出对应数据。多系列从色板选取可辨的颜色，并配合文字标签。
- **类别与状态**：类别色和状态色在全稿中保持一致；数值高低用带色标的连续深浅表达，普通并列要点沿用同级样式。
- **重点表达**：用字重、强调色突出关键对象、数字或短标签，关联标注沿用相同颜色；重点行可用低对比度整行浅底。
- **形状风格**：照片和面板沿用统一的圆角规格；节点和区域使用平面形状，文字保持清楚的对比。

### 3. 图片、品牌与封面

- **封面定调，按需给出全貌**：封面贴合品牌，根据主题、受众和情绪选择构图，配图按需使用。

- **品牌档案**（有品牌时，提炼颜色之外的辨识度）：从官网、发布会、官方海报 / 视频封面、产品包装、公众号等官方物料提取（看到几处算几处），按可用素材记录——标志性图形（logo 衍生形状 / IP / 辅助纹样）、字体气质、主色 + 辅色 + 中性色（不只一种品牌色）、真实画面（门店 / 产品 / 包装 / IP 高清图）、图标风格（线性 / 面性、圆角 / 直角）、品牌语言（slogan、产品命名、常用说法）；看不出来写"未见，按本文默认"。
- **全稿应用**：写进 design brief 并全篇执行：封面、章节页用同一个品牌母题（纹样 / logo 圆标 / IP），亮点与案例页用真实产品或门店图，图标按档案风格，标题措辞用品牌语言；品牌元素按内容需要使用，不为凑数量挤占分析空间。
- **真实素材**：真实门店 / 产品图通过 image_search 获取；素材不足时，可使用 logo 衍生纹样或线性图标。生图 prompt 写明"无文字、无任何品牌 logo / 商标（含第三方与竞品，如服装鞋帽上的标志）"，每张生成后立即看一眼，有字或标志当场重生成。

**用户给的 pptx 是最高优先级视觉指导**。用户要求"参考"其风格或用它作模板时，先提取可迁移的设计特征，再按以下步骤处理：

1. **先看渲染效果**：打开样本截图看真实视觉，结合 XML 核对文字。
2. **提炼精简的参考要点**，分三类记录可迁移的部分：
  - **版式手法**：网格骨架、配色规则、步骤式导航、证据分区等结构性设计。
  - **风格基调**：克制、亲和、严谨，或活动现场感、公务通传感。
  - **图形语法**：并列模块、时间轴路径、嵌套层级、取景框等表达手法。
3. **保留模板特征**：主要字体、背景图（尺寸与 ppt 一致的视为背景）、模板自带品牌标识、真实人物 / 照片、原始文案、专属色值、装饰纹样——这些要保留，但可以在其基础上灵活设计。
4. **判断内容属于模板中的哪一类页面再用**，按匹配的页面采用相应设计。
5. 没有能直接复用的页面时，按本文件的设计系统自行搭建。

## 五、生成方式与参考

### 1. 原生图表、表格与可编辑图形

- **数据图型优先查找原生 `<chart>`。** 原生图表能准确表达所需关系时，直接使用原生图表。先 `python3 <ppt skill 目录>/scripts/slides_chart_tool.py get <类型>` 获取当前支持的片段，再按本稿数据与配色调整。逐项核对数值或文字时使用原生表格。
- **组件与可编辑图形**：原生图表不能准确表达所需关系或重点标注时，查找包内 `chart_slide`、exhibit 等适用组件；结构图先查 `relation_help()`。常规折线需要突出关键时点、差额或阈值时，也可以用合适的 exhibit 组件。没有匹配组件时，按主 Skill 的绘图与 atomize 流程生成可编辑图形。用图形作数据图时，位置、长度、面积和颜色都应按数据映射，不凭目测画比例。
- **组件服从整稿设计**：沿用已确定的标题位置、字号、底色、配色、来源行和页码，仅正文构图随页型变化，不直接套用组件默认页面外观。`brand_palette('#品牌色')` 与配色脚本同一套色值，可传 `palette=`。组件若会截断内容、缩小必要文字或把关键解释转入备注，应调整组件或页面分区。

### 2. 页型组合参考

以下组合按本页判断与证据关系选择。图形按第二部分选用，图文分区、标题与解读位置统一按第三部分安排。

| 页型 | 内容组织 |
|---|---|
| 图 + 结论 | 用主图与重点标注支持标题结论；多项发现或另一组文字证据共同支持判断时，按第三部分集中组织对应内容。|
| 诊断 / 多因素归因 N 项 | 按因素分组，分别写出判断和依据。有可比的贡献量时可按影响大小排序；因素之间有因果或先后关系时，按关系展开。待验证的原因标明为假设。 |
| 举措详情 | 围绕举措说明预期结果、动作、负责人和时点。需要横向对照的举措沿用相同顺序，涉及流程变化时可用前后对照 |
| 亮点 / KPI 行 | 需要同时扫读几项关键指标时，可将指标并列，数值紧邻名称、单位和期间。判断依赖目标或上期表现时，把比较基准放在对应指标旁。 同页图表已清楚呈现的读数，不再单独复制成 KPI 行。|
| 核心优势 | 每项用短标题点明优势，紧邻能支持它的事实、案例或比较结果。几项优势并列时对齐呈现；主张优于其他方案时，写清比较对象和依据。 |
| 前后流程对照 + 驱动落点 | 将前后流程并列或上下排列，对齐可对应的环节。突出新增、取消或改变的步骤，把变化原因或实际影响放在相应步骤旁。 |
| 前后对照 / 案例 | 按相同指标对齐前后状态，比较期间明确、单位和口径一致。重点是变化幅度时，就近标出差额；比较流程或体验时，让相应环节处于对应位置。 |
| 竞争定位 | 按读者关心的共同维度对齐各方的事实和差异。需要看两个指标的联合位置时，标明坐标含义，并按实际数值落点；只有定性分档时，用有定义的类别或对照表。 |
| 资源诉求 / 规划 | 先写需要什么资源、用于什么事项，再按判断需要列出数量、时点、预期作用或所需决议。多项用途可按共同字段对齐，金额只在涉及预算时列出。 |
| 壁垒 / 飞轮 | 讲壁垒时，将能力或资源与它为何难以复制的依据放在一起。讲飞轮时，沿因果关系排列各环节；只有后续结果会反过来增强前一环节时，才画闭环箭头。 |

### 3. 按需读取脚本与组件说明

数据图型支持、XML 属性与发布命令以包内当前工具说明为准，不把错误码或默认组件样式当成设计依据。

- **原生片段改法**：图例用于区分多个系列；单系列图省略 `<chartLegend>`，图名写在图外小标题里就删 `<chartTitle>`（没有 `position="none"`，`fontSize` 不能写 0）；数据标签柱用 `outside`、线用 `auto`，按读图需要保留首尾或关键点，不压线不互叠。
- **百分比系列**：`format="0%"`（含 `0.0%`、`0'%'`）会把数值 ×100：比率存小数配它（0.68 → 68%，NRR 1.12 → 112%）；按百分数录入的值（不良率 1.74、毛利率 21.5）配字面写法 `format="0.00\%"` / `format="0.0\%"`，否则显示成 174%。
- **编辑轮**：沿用主 Skill 当前编辑与发布流程。只改用户点名的内容，原页其余文本块和标题原样保留；空间不够先调整分区和位置，不低于字号底线。新增内容沿用全稿已有版式和颜色语义。

### 4. 分场景参考

以下场景中的问题与论证方式都是示例。按第一部分，从本次汇报中受众真正关心的业务问题出发，结合业务实际取用。

| 场景 | 读者关心的问题 | 如何论证 |
|---|---|---|
| 运营 / 财务 / 董事会汇报 | 常见议题：本次是通报经营情况、讨论问题，还是审议方案？通报重在结果及其影响，讨论重在尚待厘清的问题，审议重在需要决定的事项和取舍。 | 常见议题拆解示例：判断经营表现，用与本次议题相关的基准说明结果好在哪里、差距有多大，以及为什么值得管理层关注。提出建议时，围绕影响取舍的条件比较可行方案，说明什么情况下建议会改变。 |
| 业务经营回顾（零售 / 制造 / 消费 / 供应链） | 常见议题：本期哪项经营结果值得解释，变化集中在哪里？按业务实际选取拆解维度，例如零售可按品类或渠道分析，制造与供应链可按产线、库存或交付环节分析。 | 常见议题拆解示例：解释经营变化时，用同口径数据说明哪些业务单元贡献了变化、各自影响多大。把变化归因于具体原因，需要有能支持该解释的业务事实。提出改善措施时，说明它针对哪个已发现的问题，以及用什么结果判断是否有效。 |
| 互联网 / 科技 / 增长月报 | 常见议题：本期要解释用户行为、判断一次改动的效果，还是同步项目进展？先明确读者关心的结果，再选指标和分析方法。 | 常见议题拆解示例：选择能反映本次问题的结果指标，说明变化发生在哪些用户或环节、幅度是否具有业务意义。主张某项改动有效时，说明比较依据能否区分改动的作用与同期其他变化。汇报项目进展时，用已交付成果支撑进度判断，有实际使用或效果证据时再说明业务影响。 |
| 人力、行政与专项工作汇报 | 常见议题：事项执行到哪一步、工作取得了什么效果，或某个组织问题影响了谁？报告进度时可看覆盖范围和节点；评价效果时，应给出与工作目标对应的结果。政策解读、干部培训和党建汇报按政务党建场景处理。 | 常见议题拆解示例：判断执行进度，对照工作要求说明已完成的事项和仍受阻的环节。评价成效，用与目标对应的结果说明受影响的人群或流程发生了什么变化。提出处理建议时，说明建议针对的事实、影响范围和落实条件。 |

## 六、禁止项

| 类别   | 禁止内容                                                                        |
| ---- | --------------------------------------------------------------------------- |
| 布局   | 避免把每个数字或每条要点都单独装进卡片；把主次不同的内容机械均分；将共同总结放进某一项的同级版位 |
| 字体   | 除用户明确指定外，最终显示正文小于14pt；以“注释”为名缩小必要条件、图内标签或比较依据 |
| 圆角   | 同类容器无依据地混用不同圆角规格                                                        |
