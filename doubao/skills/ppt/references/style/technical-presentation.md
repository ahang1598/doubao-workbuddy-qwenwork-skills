# 技术与工程

**路由条件**：系统架构 （RFC、ADR、容量规划、技术债评审）；AI 技术或者数据平台提案（LLM、RAG、Agent、特征工程、ML 平台、向量检索）；生产故障复盘（Postmortem、SRE 事故报告、影响面分析、防复发审议）；对外技术演讲（QCon、KubeCon、DevRel、开源发布会、技术白皮书）。

## 叙事原则

- **标题直接给结论**：读者扫一眼就知道这页在说什么。举例：写「引入 Envoy 后 P99 从 320ms 降到 85ms」，别写「性能优化情况」。
- **顺着"决策链"讲**：目标与约束 → 现状与瓶颈 → 机制 / 架构 → 关键证据 → 取舍 → 上线与回滚 → 风险与下一步。不埋伏笔，不搞"最后揭晓"。
- **文字答"为什么"，图形答"怎么走"**：动机、取舍、依据交给文字；调用关系、数据流向交给图形，各司其职别互相翻译，图形要技术级的专业。
- **数据严谨可追溯**：环境、版本、样本量、负载条件一并附上；至少给到 P50 / P95 / P99 或置信区间，只贴一个均值等于什么都没说。
- **已知与推测严格分家**：现状、目标态、假设、已验证结论各占各的位置；数据没到位就写"待补齐 / 假设值"，绝不用估算糊上去，需要的时候用字体大小或者颜色区别的区分。
- 术语与缩写第一次出现就解释清楚，之后全篇一个叫法。

## 用户附件模板参考

**用户给的 pptx 是最高优先级视觉指导**。用户要求"参考"其风格或用它作模板时，不是逐页复用，先按以下步骤处理再套用本文件的设计原则：

1. **先看渲染效果，别止步于抠文字**：打开样本截图看真实视觉；只跑 xml 提出一堆文字不算看懂模板。
2. **提炼一份精简的参考要点，不逐页照搬**，分三类记录可迁移的部分：
  - **版式手法**：网格骨架、配色规则、步骤式导航、证据分区等结构性设计。
  - **风格基调**：克制、亲和、严谨，或活动现场感、公务通传感。
  - **图形语法**：并列模块、时间轴路径、嵌套层级、取景框等表达手法。
3. **不能改的东西**：主要字体、背景图（尺寸与 ppt 一致的视为背景）、模板自带品牌标识、真实人物 / 照片、原始文案、专属色值、装饰纹样——这些要保留，但可以在其基础上灵活设计。
4. **判断内容属于模板中的哪一类页面再用**，不把局部经验放大成整套通用规则。
5. 没有能直接复用的页面时，回落到下面的设计系统自行搭建。

## 视觉规则

**工程克制**：装饰只允许出现在封面、章节页、结尾页；正文页把视觉分量让给架构图、代码、数据、截图。

**字体**：中文黑体承担标题与正文；代码、路径、字段一律等宽字体（JetBrains Mono / Sarasa Mono / IBM Plex Mono）；一份材料不超过两个正文字体家族。

**网格**：先锁定标题基线、图例位置、颜色语义、来源版本号的固定坐标——这套"看不见的骨架"决定材料的可信度。

**图形语法**：箭头端点、拐角、虚线节奏、圆角半径、线型编码全篇一致；同一张结构图只表达一种主要关系。

**目录**：主题色编号 + 章节标题 22pt + 一行 12pt 浅灰说明，三者左对齐；章节间加 0.5pt 细横线；超过五章可左右对称。

**排版**：靠文字、极细浅灰线段、留白、字号差异（用大数字凸显关键值）组织信息，非必要不用卡片堆叠。

## 分场景参考

### 系统架构

**气质**：白皮书式严谨——中性哑光底、精确直角结构图、连贯的文档轴；不追视觉冲击，追求"从头翻到尾都很稳"。

**字号**：封面标题 48–64pt，页面标题 28–36pt，正文 15–18pt，代码 11–13pt，图注与来源 9–11pt。

**布局**：十二列网格；顶部固定短标题 + 章节名 + 页码；架构图落在稳定坐标系上，多页复用同一坐标，让读者一眼看到"哪里变了"。

**图形规则**：系统区域用嵌套或并列直角块；调用与数据流用带方向的箭头链；数据流 / 控制流 / 异常路径用线型 + 颜色做冗余编码；一份材料所有架构图共用一套图例；复杂架构先给概览再放大，不要每页重画整体图；性能数据必须挂测试环境、版本、样本量。

**页面语法**：封面（方案标题 + 一句话结论 + 版本号 + 作者 / 团队 / 日期）→ TL;DR（3–5 条结论并挂上证据页码）→ 现状页（一图 + 瓶颈列表）→ 目标架构页（一图 + 用色差或线宽突出差异）→ 迁移页（阶段 / 依赖 / 关卡 / 回滚点按真实时序）。

**视觉母题**：细金属线 · 章节编号徽章 · 稳定图例条 · 关键路径粗线 · 编号锚点。

**场景禁止**：3D 架构图、透视立方体、球体、齿轮堆叠；借用 AWS / Azure / GCP 品牌色伪装通用架构；"系统架构概览""整体设计"这种空洞标题。

### AI / 数据平台提案

**气质**：冷静、数据驱动——强调数据链路可信度与模型效果证据；配色偏冷但不冰冷，避开"AI 未来感"套路。

**字号**：封面标题 48–64pt，页面标题 28–36pt，正文 15–18pt，指标大数字 60–96pt，代码 11–13pt。可用朱红 #C9302C 标记当前评估的组件、模型或评估集。

**布局**：可用较高密度的仪表盘布局，仍以固定网格切分；顶部固定评估集与版本号；数据流水线图占主视觉位。

**图形规则**：数据流水线必须分层——离线批式 / 近线流式 / 在线服务的边界要一眼可辨；模型效果对比必须给出评测集名称、样本量、baseline、置信区间；LLM 效果按任务维度分开呈现（推理 / 指令遵循 / 代码 / 安全），不允许用综合分掩盖差异；延迟-质量-成本三方权衡用散点图或帕累托前沿，每个方案在图上标出位置。

**页面语法**：封面（场景一句话 + 关键效果指标 + 版本 / 日期）→ 用户任务页（任务定义 + 输入 / 输出示例 + 成功判据）→ 流水线页（完整链路一图，标注延迟预算和降级路径）→ 机制页（检索 / 排序 / 对齐等核心技术，每模块单独一页）→ 评估证据页（多任务效果对比 + 消融实验 + 与 baseline 的差异）。

**视觉母题**：分层流水线条 · 指标数字 + 迷你分布图 · 帕累托前沿曲线 · 评估集徽章 · 消融矩阵。

**场景禁止**：紫粉渐变、赛博霓虹、"AI 感"发光边框；大脑图案、神经网络插画、拟人机器人；没有 baseline 或置信区间的效果对比；"智能""自适应""端到端优化"这类无实质内容的填充语。

### 生产故障复盘

**气质**：法庭档案式冷静——事实驱动、时间线为骨、不推诿；配色偏暗或偏纸，克制用色，避免情绪化渲染。朱红 #C9302C 用于事件节点与超阈指标警戒色，正文页警戒色面积 ≤ 5%。

**字号**：封面标题 44–56pt，页面标题 28–34pt，正文 15–17pt，时间戳与日志 11–13pt（等宽保证纵向对齐）。

**布局**：主时间轴贯穿关键页；顶部固定事故编号、影响时段、严重等级；影响曲线（QPS / 成功率 / 延迟）与事件标注必须垂直对齐。

**图形规则**：时间线横向刻度对齐真实时间；关键事件（触发 / 告警 / 介入 / 恢复）在同一时间轴上标注；根因分析用故障树或因果链，从表象追到直接原因再追到系统性因素；影响必须量化（用户数 / 请求数 / 收入损失 / SLA 违约时长），不允许"少量用户"这种模糊描述；修复动作按已完成 / 进行中 / 待启动分层，每一项挂验证方式与责任人。

**页面语法**：封面（事故编号 + 影响时段时间戳 + 严重等级 + 一句话影响描述）→ 影响概述页（全部量化）→ 时间线页（主时间轴 + 事件节点 + 指标曲线垂直对齐）→ 直接原因页（故障链 + 触发条件 + 首次可发现时点）→ 系统性因素页（从组织 / 流程 / 工具 / 监控 / 文化维度拆解）→ 行动项页（每条挂责任人、时点、验证判据）。

**视觉母题**：主时间轴刻度 · 事件节点圆点 · 严重等级标签 · 影响曲线 · 因果链箭头 · 状态色点。

**场景禁止**："未来一定加强""后续持续关注"这种没有验证判据的动作；只讲直接原因不追系统性因素；把根因归到个人而非流程 / 工具 / 文化的缺口；用装饰性红绿状态灯替代具体数字；写"我们快速响应""团队通力协作"这种自我表扬。

### 对外技术演讲 / 开发者布道

**气质**：允许更强的视觉张力和情绪节奏，可用暗场发布；但依然专业克制——不炫技、不上营销词、不硬拉悬念。

**字号**：封面标题 72–120pt，钩子数字 96–160pt，页面标题 32–44pt，正文 18–22pt（现场投影偏大保证后排可读），代码 14–18pt。

**布局**：允许出血视觉与非对称大主图；每页只承载一个概念；章节页可极简（一句话 + 一个数字）制造节奏停顿。

**图形规则**：概念图重于精确架构图——听众要看的是"这件事的形状"，不是"每个组件的接口签名"；代码片段只保留支撑论点的最小行数，并预先高亮关键行；数据钩子必须真实可复核，绝不虚构性能或用户数字；演示要截取关键帧作为静态代表。

**页面语法**：封面（主题一句话 + 演讲者 / 机构 + 场次）→ 钩子页（一个有冲击力的数字、对比图或 before/after）→ 问题页（具体的用户痛点或工程约束）→ 机制页（分层展开 3–5 步）→ 边界页（诚实说明局限）→ 采纳路径页（链接 / 代码仓 / 试用入口）。

**视觉母题**：巨大数字钩子 · 单色章节停顿页 · before/after 对照 · 关键代码高亮行 · 出血主图。

**场景禁止**：一页超过 7 行文字不拆；结尾页只写「Thank you」不给采纳路径；"下一代""革命性""重新定义""颠覆"这类营销套话；不可复核的性能夸张（"快 100 倍"没有环境说明）；硬拉悬念的"揭晓页"。
