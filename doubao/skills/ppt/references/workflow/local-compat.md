# 新建本地工作空间
当前你处在用户的本地电脑空间里进行操作，所以请你新建一个文件夹，每一个 PPT 的创建/更新所需要的材料都可以在这个文件夹中进行处理

# 背景说明	
`lark-cli slides`是一套兼容云端slides、本地PPT操作的统一指令，其操作本地文件的逻辑如下，获取用户的真实幻灯片文件将其解码为底层产物放入工作目录，其解码后的路径被 `token` 唯一标识，前端（`canvas`）通过实时渲染底层产物，让用户实时感受到对此产物的任何变更，一切变更均发生于工作目录中的底层产物，仅当用户要求保存时才会打包成同类型文件覆盖用户提供的真实本地路径。	
 	
每次用户通过`canvas`发起对话时可能会注入`<system-reminder>`告知如下与操作文件相关的信息:	
- `**path**`: 用户目前打开的本地文件的真实地址	
- `**type**`: 文件类型，幻灯片（PPT/slides）文件被标识为 `lark_slides`	
- `**token**`: 底层产物的唯一标识	
- `**file_status**`: `canvas` 状态，包括 "open | close"，仅当状态处于 "open" 时 `lark-cli` 指令才能正常执行	
- `**selection**`: 具体选区，用户当前在`canvas`中选中的位置	
 	
`<system-reminder>`中文件相关信息实际代表用户对文件发生的操作，需要注意：	
- 用户可能多次操作激活或者关闭`canvas`，所以`file_status`会发生变化，同样选区也可能发生变化，应该以最后一次告知的状态为准	
- 用户可能同时操作多个文件，所以传递的可能是一个文件的状态，也可能是多个文件的状态	
- 文件状态只有在发生变化时才会被传递，当没有传递时，应该以最后一次告知的状态为准	
 	
所以：	
- **不能**以是否存在 `token` 或者 文件类型被标识为 `lark_slides` 来判断是否是在线文件，若用户明确提供了 "url" 才可明确判断为是在线文件，若用户明确提供了本地文件路径则应判断为本地文件。  	
- 当操作本地文件时：	
  - `file_status`为 "close" 时不得使用 `lark-cli` 操作本地指令，此时一定会执行失败，必须先新建一个本地文件的副本方便回滚，再使用 Python 对副本进行处理	
  - 用户发起最新对话时无之前传递的文件信息，此时意味着该文件状态与之前保持一致，如此前 A 文件的`file_status`为"open"，当前传递的是 B 文件的状态，此时意味着 A 文件的`file_status`依旧为"open"	
  - 如果存在"<system-reminder>"且`file_status`状态被标识为 "open" 时，操作/获取PPT内容时优先使用 `lark-cli` 指令，不得因为历史对话出现过`lark-cli`执行失败就不再使用，若指令执行失败可使用代码能力兜底。	
  - 用户要求进行文件级操作（如复制、移动、重命名等）时本 skill 指令不再适合，建议使用 `bash`(linux/mac)、`PowerShell`(windows) 类指令进行操作，注意此时应该操作的是用户的真实文件，不得操作底层产物	
  - 最终呈现本地文件给用户时，**禁止**擅自拼接`token`当成在线链接提供给用户	
  - 若`lark-cli`长期出现超时问题，应当考虑当前`canvas`可能被关闭，不要继续使用`lark-cli`指令	
- 注意区分多文件，当给出的`token`不一致时代表这是不同的文件	
- 当用户提供的是在线文件url时，完全以`lark-cli`进行操作	
- 背景说明仅是帮助理解运行逻辑，在用户未明确要求的情况下，**禁止**输出任何与"工作目录" "底层产物"相关的内容，也**禁止**向用户解释底层原理

# 编辑 Slide/PPTX
使用 slides-editing.md 中的逻辑对 PPTX/Slides 进行编辑时，需要新增以下三个逻辑：
- 当存在 `<system-reminder>` 且最后一次的 `file_status` 状态为 "open" 时：确认需要本地编辑，直接使用提供的 `token` 进行读取或编辑，**禁止**将本地文件上传至在线文档
- 当存在 `<system-reminder>` 且最后一次的 `file_status` 状态为 "close" 时：不得使用 `lark-cli` 操作本地指令，此时一定会执行失败，必须先新建一个本地文件的副本方便回滚，再使用 Python 对副本进行处理
- 当从未存在 `<system-reminder>` 或所有的 `<system-reminder>` 中完全没有 `file_status` 时：此时保持 [`slides-editing.md`](references/workflow/slides-editing.md) 中原有的逻辑进行编辑即可
