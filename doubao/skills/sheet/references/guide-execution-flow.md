# 通用执行流程：读取、字段对齐与交付

适用于两套引擎，覆盖通用流程与源文件保护；具体 CLI 操作由各工具参考提供，飞书侧的**编辑准则**见主文档「飞书表格引擎」一章。

## 0、多项显式产出先对应到目标位置

用户明确列出多项产出时，用要求的范围、维度与指标直接驱动结果区的生成，子表 / 区域、字段顺序和所需对象随同绑定；摘要或子集不代替完整结果，缺输入时保留要求的结果位置并说明缺口，不靠裁减范围或补造凑齐。普通单项编辑不增加清单。复杂公式保留字段/阈值/单位/范围，见 `references/lark-sheets-formula-translation.md`。

## 1、基本原则

1. **源数据默认必须保留**：除非用户明确要求删除、覆盖或替换原数据，表格编辑 / 整理 / 统计任务都不能破坏源明细。用户要求表格结果，对已有表做“按指定维度统计整理”“分类汇总”“筛选保留若干列”“透视分析”“生成结果表”时，默认保留原 sheet 和原始行列，把结果写到新 sheet、新区域或明确命名的结果表；不要只反馈统计结果、清空明细、覆盖原 sheet，或把原始数据口径改掉。若用户给“已有表 / 模板表 + 新数据”，已有表是 base workbook，默认在原 sheet 末尾追加或新建结果区，不要新建同名空 sheet 后重写。多附件时动手前先显式认定谁是 base、谁是增量源；追加 / 合并保留 base 的全部原始记录及重复次数；仅用户明确要求删除 / 就地改写时处理对应行列。
2. **输出区域注意保护原表**：用户要求“直接在指定位置修改 / 覆盖原文件”时，才在指定位置就地修改；用户没有指定落点时，优先追加结果而不是覆盖输入，典型做法是新建 `统计结果` / `整理结果` sheet，或在原表右侧 / 下方追加结果区并保留清晰标题。用户点名了 sheet 名 / 单元格坐标 / 列顺序时按该契约排布——被点名承载某一形态结果的区域只放该形态，原始值 / 中间量另置，不要插在指定区域之前把坐标挤偏。**例外**， 当运行环境为本地电脑且使用**Excel 引擎**编辑文件时，结果的落点仍按上面几条排布，只是整份存回原文件——动手前先复制一份备份，它只做回滚快照。
3. **公式优先原则**：需要交付表格时，可推导的计算结果优先写公式到对应单元格，保持动态计算能力。把公式写在对话回复或表末说明里、要求用户自行复制到单元格，等同于未交付该列——公式必须真实落在目标单元格内。缺失值按运算口径处理：单价×数量、比率等缺少必需输入时返回空或说明；按已有分项求和时用 `=SUM(B2:E2)`，不擅加“分项齐全才算”的条件。源空格保持空，不因求和忽略空格就回填 0；全空结果与平均值分母按用户及源规则确定，`IFERROR` 不能代替这些分支。
   - Excel 引擎：写 Excel 公式（如 `ws['C2'] = '=A2+B2'`），不要在 Python 中算好数值再写入。
   - 飞书表格引擎：写飞书公式；Excel 公式到飞书公式的迁移规则见 `references/lark-sheets-formula-translation.md`。
   - **例外**（允许直接写静态值）：直接来自输入或外部来源的原始值、固定常量，或用户明确要求固定结果。原地调整需保留联动时，先在允许位置保存原值，再以公式引用原值和调整项；同一次操作重试复用基准，避免重复累计。无法在允许范围保留输入时说明限制；公式降级为静态结果时说明原因及不再联动的影响。
   - **需要联动的结果用公式表达**：Python 可用于推导，但需随输入变化的单元格应写引用源格的公式，关键输入做成可修改的输入格。财务 / 金融场景详见 `references/ref-financial-modeling-standards.md`。

## 2、判断数据来源

| 输入信号 | 来源判定 | 走哪套引擎 |
| --- | --- | --- |
| 用户上传 `.xlsx` / `.xls` / `.csv` 文件 | 本地 Excel/CSV | 用 Excel 引擎读取与处理；默认在线交付时，导入后用 CLI 完成所需原生图表 / 透视 / 条件格式，不能到“导入成功”即结束 |
| 用户给出飞书 / doubao 的 `/sheets/`、`/spreadsheets/`、指向电子表格的 `/wiki/` 链接或 token | 飞书表格 | 飞书表格引擎 |
| 用户口述 / 粘贴数据，无文件 | 待结构化 | 先结构化，再按产物载体选引擎 |
| 无数据 | 信息不足 | 向用户询问，或先用其它工具获取数据 |

## 3、按当前操作一次读取所需结构和内容

拿到数据后，按主文档识别运行环境、选择执行引擎。下面是按缺失信息选用的读取方式，不是逐项执行清单：把本次操作缺少的字段、范围及必要对象信息合并读取，已有信息直接复用；后续只补实际缺项。模板补内容直接保留未修改属性，不为保留样式另行枚举整表样式。

1. **按操作选择内存策略**：名称 / 尺寸探查和普通值 / 公式文本读取默认只读；逐行转换、筛选、计数或求和边读边处理，只保留当前批次与必要结果。确需一次持有所选数据时，先确认范围及驻留数据能容纳于可用内存；规模未知先迭代，不先全量加载来判断大小。排序、去重、关联或高基数分组的状态仍可能随数据量增长，超出可用内存时用可用的磁盘暂存或数据库处理；分批读取后累计所有批次 / 建全量 DataFrame 不会降低最终内存。文件大小和行列数仅用于估算，不作为加载安全的硬阈值；XLSX 压缩大小不代表单元格对象、字符串与样式的驻留内存。只读取任务相关数据，只修改授权子表与属性；列裁剪不得漏掉参与计算、匹配或要求保留的字段，复用已确认的数据；同一遍扫描合并所需统计与异常归类，结构探查只输出必要摘要，需模型逐条语义处理的文本按完整记录分批读取。
2. **按输入格式读取所需内容**；流式读取仍须覆盖任务需要的完整范围，样本只用于结构探查：
   - **Excel 文件**：本地电脑的 Canvas 模式下 `file_status` 为 "open" 时，用 `lark-cli sheets` 直读，失败按 `references/ref-local-compat.md` 恢复，不走未保存内容的文件导入兜底；其余情况用支持源格式的 Python 库读取（openpyxl 读 `.xlsx`，xlrd 可读 `.xls`）。`.xlsx` 的名称 / 尺寸探查、普通值或公式文本读取用 `openpyxl.load_workbook(path, read_only=True, data_only=False)`；需要公式缓存值才设 `data_only=True`，无缓存不代表源格为空，该参数不控制内存模式。不需要外部链接对象时可加 `keep_links=False`。同一子表保持一次 `iter_rows(...)` 迭代，传任务所需的行列范围并在消费端分批；逐格读取或每批重新指定 `min_row` 会从头扫描。用完在 `finally` 中 `close()`；只读模式仍有共享字符串与样式开销，且不提供合并区、批注、超链接及富文本 / 特殊公式的完整信息，不能据此判定源文件没有这些内容；需要这些信息或整簿编辑时按第 7 项加载。内存不足时不原样重试或改成普通模式。文件无法读取时，不改用解压 xlsx 直读 XML、手写底层解析；已知含 `x14:dataValidation` 扩展或读取警告该扩展将被移除时，不用 openpyxl 保存。用户明确要求仅本地处理、不得上传或拒绝在线表格时，仅用能保留所需内容的可用本地工具；没有可行工具则说明限制，不上传。允许在线处理时，云电脑可用 `lark-cli sheets +workbook-import --file ./source.xlsx` 转飞书引擎；本地电脑须先取得用户对在线处理的同意，已有明确同意时直接继续。
   - **CSV 文件**：用 `pd.read_csv(...)` 按任务范围读取；编码或表头不明时可先限量读取样本，注意编码（优先尝试 utf-8-sig、gbk、gb18030）。
   - **飞书表格**：结构不明时可用 `python3 scripts/lark_inspect_workbook.py --url "<表格URL>"` 取得子表清单、布局、预览和 `current_region`；有多块表、汇总块或备注块且范围不明时，用 `scripts/lark_detect_subtables.py` 识别候选 range；字段、类型或键关系不明时，用 `scripts/lark_profile_table.py` 对相关区域画像。也可直接调用 `+workbook-info` / `+sheet-info` / `+csv-get` / `+cells-get` 做等价读取，已有信息足够时直接处理，详见 `references/lark-sheets-read-data.md`。
3. **识别合并单元格**：合并单元格的值仅存储在左上角；提取时仅在已确认的合并区内传播该值，不对全表空值 `ffill`，不跨来源借填。已有合并区只写或引用左上角，不向 openpyxl 的非锚点 `MergedCell` 赋值；仅补内容 / 样式不拆合并，新增结果列不扩并原区，空白合并标题行不写逐行公式。新合并不得覆盖其余格需保留的内容；迁移区块同步映射合并范围及锚点公式依赖，跨行合计不能被逐行通用公式替换。飞书结构操作见 `references/lark-sheets-sheet-structure.md`。
4. **识别必需字段并保留列位**：用户点名输出字段时，先固化表头 schema；源数据缺某字段也要保留该列，值可留空 / 写“未提供”，不要把必需列降级进备注、也不要用其它字段替代。填写已有模板或汇入已有汇总表时，复用其字段和列序；行标签与待填格分别定位，不为来源说明扩列或改写标签，也不把表外信息写进空列。多源合并按用户指定 schema；未指定时取所有来源的有效字段并集，不只沿用列最多的一份。按各源完整表头建立字段映射后再裁列，保留源列坐标并区分同名异义列，不以第一份表的宽度截掉其它来源的尾部字段；必需字段无法映射时列明缺口。新建结果表允许的附加字段放在必需字段之后；用户限定“仅这些列 / 仅明细行”时不增列、不加合计行，来源与说明另置于允许区域。用户提出的排序 / 命名 / 格式要求对**每一张**同类表一致适用，不因某张表行数少、分组少而豁免。新增区域继承对应模板样式；已有区域仅补内容时保留原样式。
5. **识别“表头不清晰”并做字段理解**：出现无表头 / 空表头列 / 多行表头 / 前几行是标题说明时：Excel 用 `python3 scripts/excel_preview_rows.py` 对可疑 sheet 预览更多行（如前 30 行），结合数据形态判断真正表头行。多级表头结合各层标题与合并范围确定列含义，例如“预算/金额”与“实际/金额”不能只按底层同名子标题匹配；已有表头信息足够时直接复用。对空表头列，观察该列前 20 个非空值的类型与模式，推断临时列名（如 `未命名_金额`）；后续映射与计算优先用“列坐标 / 列字母 + 行号范围”锁定字段来源，避免引用错列。
6. **按原始纳入条件提取业务行**：先按用户指定的原始字段建立纳入掩码，后续派生字段、回填与分析缺值不改该掩码或源值；不同分析的完整样本子集分别处理，不用 `dropna()` 所有列收窄原始纳入范围。结合行结构排除标题、空白合并行、合计 / 小计等非明细，避免重复统计；不能只凭名称关键词或非数量字段为空删除有效数量。分页或续表沿全部有效分录取数，重复表头与结转行不重复计入，追加位置按实际末条分录及模板续页规则确定，不把首屏行号当整表边界。标题、备注、批注中的规则对应到适用记录、期间和来源，条件直接驱动取数与公式，不只复制说明。说明与缓存冲突时明确例外优先，依据不足则保留并说明冲突，不自动选缓存。
7. **完整对象读取与编辑保留源文件能力**：读取完整对象或整簿编辑 `.xlsx` 时，评估整个工作簿的加载与保存开销，并给其他常驻进程留余量；只编辑几格或限制后续 sheet / 行列不会减少全簿加载内存。已知规模与可用内存不足以支持完整加载时，先选能保留所需内容的可用工具或足够资源，不原样重试；不以固定文件大小阈值拒绝正常编辑。已确定编辑路径时直接加载并复用，不额外做一次只读预检。在本技能目录用随包加载器 `from scripts.excel_load_workbook import load_workbook as load_editable_workbook; wb = load_editable_workbook('./source.xlsx')` 打开原工作簿或其完整副本，需要编辑时在同一对象上修改、保存，保留公式、富文本及字面 `x005F_`；若因不支持的 OOXML 特殊转义拒绝加载，保留源文件并说明未完成部分，不以 `rich_text=False` 或裸加载降级。原生只读 / 普通读取均可能改写共享字符串中的字面 `x005F_`，已知涉及该文本时用上述保真路径。`read_only=True` 的实例不能用于编辑保存；`data_only=True` 只用于读缓存，保存该实例会丢公式。仅改本地xlsx布局内单元格的值 / 普通公式且布局不变时，优先用下方 `excel_apply_edits.py` 生成保真副本，保留待填格原填色；脚本拒绝不支持的元素时按其说明选择兼容路径，不绕过保护；该脚本也会全簿加载，不是降低内存的替代路径。pandas 可用于分析，不用 `df.to_excel` 重建需要保留结构的源文件。保留目标范围的 Excel 数据验证规则（如下拉选项、数值上下限），写入内容遵循这些规则；用户要求修改规则时才定点更新。公式还可能是数组公式或敏感性分析 Data Table 对象，不能只检查以 `=` 开头的字符串；只改格式时保留对象类型、覆盖区域与输入引用，输出数值相同不能证明计算关系保留。插删或移动行列不会由 openpyxl 自动维护公式、Table 和图表依赖，需同步维护引用与对象范围。

只需工作表名称和尺寸时，不启动整簿编辑加载：

```python
from pathlib import Path
from openpyxl import load_workbook

path = Path('./source.xlsx')
print('File bytes:', path.stat().st_size)  # 加载前检查文件大小
wb = load_workbook(path, read_only=True, data_only=False, keep_links=False)
try:
    for ws in wb.worksheets:
        print(ws.title, ws.max_row, ws.max_column)
finally:
    wb.close()
```

只读模式的 `max_row` / `max_column` 来自文件声明，不能当作实际非空数据量；声明偏小会静默漏数据。完整取数的末行 / 末列未独立确认，或尺寸声明缺失、可疑、与已知范围不符时，先 `ws.reset_dimensions()`，再流式读取所需范围；不把旧 `max_row` / `max_column` 作为迭代上限。范围已独立确认时可直接显式传行列边界；仅名称 / 尺寸探查不额外扫描全表，预览保留所需窗口。扫描中自行统计行列，迭代后不会自动回填尺寸；不切回普通模式只为取得尺寸。

## 4、字段语义对齐

动手前，确定指标对应的字段、聚合算子与单位：单件量按需求乘件数，整行合计不重复乘；比率的分子分母对应同一总体，求和、平均与加权平均不互换。来源与目标单位不同，先换算再落格，不以备注代替换算；未明确的口径标明假设及影响，不以异常行推断整段无效。

- **标识符保持文本原值**：编号、证件号、订单号、商户 ID 等标识符，用 pandas 读入时要保持原文。读取时需注意：不指定类型时被推断成数值，可能丢精度和前导零；默认缺失值识别会把值为 `NA`、`NULL` 等字样的 ID 读成 `NaN`；关闭缺失值识别（`keep_default_na=False`）对整表生效，其他列的空单元格会变成 `''`，需计算的列要另行转回数值。合并、关联等后续处理也可能把 ID 重新转成数值，写回保持源表文本语义。写回按 `references/ref-excel-visual-standards.md` 以字符串写入并设文本格式。
- **身份匹配按约定的键执行**：明确相等、包含或归一化后相等；比较键另存，原文不变，仅归并任务允许忽略的差异，规格 / 版本等身份字段冲突时保留为不同对象。未授权时不去空格、删版本后缀或用价格相近代替同一商品。同名多条先核对其他身份字段，不取第一条或最后一条覆盖冲突；一对多且无唯一依据时保留冲突状态：文本目标允许列候选时列全，金额 / 日期等单值目标不取首条或就近值，按任务约定保留原格或留空并说明。来源侧可用 `lark_profile_table.py --key-cols` 连同返回字段检查重复键与冲突，完整命令和显示值限制见 `references/lark-sheets-read-data.md`。单格含多个值时先确认是集合、按位配对还是普通文本，按实际关系拆分，既不把集合当整串单值比较，也不将多列任意笛卡尔组合。未命中按用户规则留空或标注。
- **按业务粒度处理数据**：按用户要求确定业务粒度，明确标识字段与业务实体的对应，不以方便分组的列替代业务键。按一对一 / 一对多关系及连接类型处理关联，区分记录数、唯一对象数和数量合计。重排跨行记录或分组区块时，先绑定实体键、从属行与组内序位，再整体移动；不同类别分别应用排序依据，不用单个关键词跨类别定序。重排、合并或填模板时保留源文件 / 子表 / 行列到目标格的映射，清洗与计算在独立数据视图中进行，需保留的源区仍保存原值。翻译等多文件文本转换按文件、子表与目标语言处理全部指定正文；没有预设语言列不代表无需处理，原样复制或局部词典不能代替正文转换。
- **事实核验先于结论**：统计 / 分析 / 诊断类任务先按用户要求的粒度和范围核验必要事实，再派生结论、图表与排名；需要结构化结果或体现数据关系时可形成事实表。要求完整统计时核齐指定分组和指标，不用筛选子集代替全量；缺失与真实 0 分开，不擅自补造不存在的维度组合；已确定分母 / 容量且事件计数为零时写 0，不把无事件当成没有该记录。
- **计算精度与显示精度分开**：中间计算保留完整精度；仅要求固定小数位显示时设置补零数字格式，后续计算继续引用未舍入值。明确要求逐笔或逐期舍入时才在指定层使用 ROUND，累计值与尾期差额按该口径处理。统计检验记录单 / 双侧、连续性校正、零频平滑及样本筛选规则，不用库默认值或事后换口径凑预期；很小的 p 值用科学计数法或明确上界，不能显示为精确 0。
- **派生变量按定义构造**：变量变换的顺序、参照样本与参数来自任务或方法定义；例如先中心化再相乘与乘积再中心化不等价，不互相替代。同一口径复用派生列，不同口径分别命名；定义不明时澄清或显式说明假设，不按目标数值切换算法。
- **时间计算先固定时间轴**：完整时间戳保留日期；仅有时刻时，按明确的跨日规则确定日期归属。跨序列对齐先定基准日历、区间端点与补值范围，先在完整基准日历生成下一期 / 下一交易日，再关联和筛选条件日；允许补值的尾部缺失不用于截短区间。缺失、无效输入和合法零值分别处理；时差方向按业务定义，不用 `MOD`、绝对值或截断掩盖日期与方向错误。
- **多阶段分析保留样本链**：拟合、聚类、匹配、回测等跨阶段处理时，保留主键、纳入 / 排除标记、关键派生量及参数，区分全样本与匹配样本，各结果区使用用户要求的样本。按原始缺失 / 条件筛行时，先按指定字段确定保留行，再做允许的补值与派生，不对未参与筛选的列扩大删行。算法需要完整案例时另取分析子集并记录排除原因，不把模型变量的 `dropna` 结果覆盖主数据集。保留逐主键分组标签与处理 / 对照配对清单，跨轮聚类按成员或质心对齐，不赋予任意簇编号固定业务含义。算法优先用成熟实现；产物须能追溯中间数据与方法，不只给系数和“已验证”结论。
- **筛选交付对齐结果形态**：产物是**另一张表**（行、列都裁，如“筛出符合条件的记录并只保留若干列”）时，按规则 1 写入独立结果 sheet 并保留原表，数据要**读全表**再筛（不能只取当前可见行）。**纯行级筛选（不裁列，只是“只看 / 仅保留符合条件的行”）不走这条**——按 `references/lark-sheets-filter.md` 创建真实筛选器对象，不要新建子表。

### 在现有处理循环中复用字段映射与匹配

随包模块 `scripts/sheet_data.py` 不打开或重建工作簿，可直接接已有行迭代器；单来源新建结果区也可用 `MappedTable.write_to` 同时写表头与记录。多源表头不同时，先按完整表头与源列位置消除同名歧义，再用 `MappedTable` 生成字段并集。每个结果区共用一个起始列和字段列映射，表头、数据、公式引用与格式都从该映射取列位；留白列不能只偏移表头。示例的 `result_ws` 与 `target_cell` 是现有处理链中已定位的结果区，不另建工作簿；在线路径把同序行提交给原 CLI 写入操作。

```python
from scripts.sheet_data import MappedTable, UniqueLookup

table = MappedTable([
    {"fields": ["编号", "数量"], "rows": iter([["001", 2]])},
    {"fields": ["编号", "数量", "说明"], "rows": iter([["002", 0, "待处理"]])},
])
table.write_to(result_ws, header_row=2, start_column=2)

lookup = UniqueLookup([{"编号": "001", "版本": "A", "数量": 2}], ["编号", "版本"])
match = lookup.find({"编号": "001", "版本": "A"})
if match.status == "unique":
    target_cell.value = match.value("数量")
```

`MappedTable` 单次消费各源迭代器，不保留全量行；`fields` 与每行等长，`rename` 对齐名称，默认保留字段并集，`output_fields` 定列序，明确裁列才用源的 `omit`。缺字段补 `None`，不改合法0或空文本。`write_to` 用同一列序写表头，数据自动从下一行起，`start_column` 默认1；只用于已授权的结果区，追加已有明细时直接遍历 `table`，按已定位的追加起点写入，不重复表头、不用另一段固定行号裁切源迭代器。字符串按文本写入，公式显式用 `{"formula":"=B3*C3"}`。已有等价映射直接复用，不另读数据。`UniqueLookup` 用完整身份键建索引；空键不匹配、多候选不自动合并，仅 `unique` 提供单值，其他状态按约定保留目标或说明，不取 `candidates[0]`。大参考表沿用数据库等可容纳路径。

**要求保留全部匹配时，按完整候选元组投影**，不按列各自去重；唯一匹配任务仍用上面的 `value`，不因有候选就猜配。`project(fields, distinct=True)` 仅按所选字段整个元组去重，保留首次顺序、类型及原文；默认不去重，行号参与匹配或写回时一起投影。多列文本拼接使用同一元组前缀，某列放不下时全部列同时停止，完整剩余元组返回 `overflow`：

```python
match = lookup.find(target_record)
fields = ["名称", "类型", "来源"]
packed = match.text_columns(fields, distinct=True)
for cell, value in zip(target_cells, packed["columns"]):
    cell.value = value
    cell.data_type = "s"
for candidate in packed["overflow"]:
    overflow_rows.append({"源行": target_row, **candidate})
```

`target_cells` 与 `fields` 必须一一对应；默认分隔符为换行，文本含换行时原样保留，不把拼接串再解析为候选记录。只接受文本 / `None`（显示为空串），数值日期需先按任务明确格式化。默认按32767个UTF-16单元限制输出，不裁原文；`overflow_rows` 要在用户允许的明细区域完整写出并与源行关联，必要时给目标格可定位提示。用户不允许增加承载区域时说明容量限制，不丢弃溢出或擅自插行；`inline_rows=0` 时整组都在溢出记录中。批量选行着色直接使用 `project` 返回的行号，金额累加/扣减仍按用户规则另算，不因有多候选就取首条或重复扣款。

### 派生结果在原簿追加，分析子集单独取数

已确认需要保留原簿并新增结果页时，复用第3节的保真加载对象，再调用 `create_sheet`，不从空 `Workbook()` 重建输入页。结果名称已存在时按用户授权另名或更新指定区域，不自动删掉同名页。复杂或不支持的对象仍按原加载边界选择引擎；下例不增加库的保真能力：

```python
from scripts.excel_load_workbook import load_workbook
from scripts.sheet_data import MappedTable

workbook = load_workbook(source_path)
try:
    if result_name in workbook.sheetnames:
        raise ValueError("结果页已存在，请按用户授权选择名称或更新范围")
    result_sheet = workbook.create_sheet(result_name)
    MappedTable([{"fields": result_fields, "rows": result_rows}]).write_to(result_sheet, header_row=1)
    workbook.save(output_path)
finally:
    workbook.close()
```

例子适用于单行字段表，复杂结果布局按需求写入同一原簿；`result_rows` 的公式用 `{"formula":"=B2*C2"}` 表示，普通字符串保持文本。`source_path`、`output_path` 按所选环境保存规则绑定，另存时输出不覆盖原件。指定筛选后的交付数据集先固定，各指标只取自己的有效子集，例如：

```python
dataset = source.loc[source[required_field].notna()].sort_values(order_field, kind="stable").copy()
model_sample = dataset.loc[:, model_fields].dropna().copy()
metric_sample = dataset.loc[dataset[metric_field].notna(), [group_field, metric_field]].copy()
```

只有用户指定非缺失筛选、排序和完整案例分析时才使用对应表达式；0与False不作为缺失。交付 `dataset`，模型和指标分别消费自己的子集；多指标各自排除缺失时不能共享“所有指标均非空”的筛选，分组统计和图表沿用用户指定的同一粒度。不得为保留对照组、凑样本数或修复统计报错回写主数据集。

### 5.1、从零新建普通明细表时分开数据与构建代码

本技能随包提供 `scripts/excel_build_workbook.py`，是减少重复代码生成的可选路径：已选 Excel 引擎、从零新建字段表格与基础样式时按收益选择。小表、已有 CSV / DataFrame 处理链直接写出；大表按资源采用流式方式，不为使用本脚本额外序列化。脚本使用普通工作簿内存模型，不是大数据导出优化工具；不用于编辑 / 另存已有表或模板。用户指定的样式、合并布局、富文本、图表等超出脚本能力时，使用能满足需求的现有路径，并复用已有数据。

先确定字段、分类口径、来源映射与用户要求的记录数，再按子表或记录组写成多个完整的 UTF-8 JSONL 文件。字段顺序稳定且能声明列类型时，可选紧凑记录以减少重复字段名；字段常变、类型混合或已有具名对象时沿用具名格式，不为切换格式重写。确实相同的批次、平台、日期等可放入公共默认值。长文本表可从每块约 20 条记录起步，按正文体量调整，不逐格拆调用，也不为多建文件而增加分块。

例如 `part-1.jsonl` 与 `part-2.jsonl` 分别包含：

```json
["001","标题含\"引号\"",12.5]
```

```json
["002","第一行\n第二行",0]
```

另写 `book.json`：`data_keys` 绑定输入数组，`columns` 决定输出字段和列序，文件路径相对配置所在目录；不在业务代码中手写位置下标。

```json
{"sheets":[{"name":"明细","data_keys":["id","note","amount"],"defaults":{"batch":"A"},"columns":[{"key":"id","type":"text","title":"编号","width":12,"align":"center"},{"key":"note","type":"text","title":"说明","width":40},{"key":"amount","type":"number","title":"金额","number_format":"0.00"},{"key":"batch","type":"text","title":"批次"}],"data_files":["part-1.jsonl","part-2.jsonl"],"expected_rows":2}]}
```

```bash
python3 scripts/excel_build_workbook.py --spec ./book.json --output ./report.xlsx
```

- 配置 `data_keys` 后，每行必须是等长数组，所有输出列须声明 `type`（`text` / `number` / `boolean` / `date` / `formula`）；缺值用 null 占位，不省略中间项。类型不符报错，不自动转换；同类型字段错位和业务语义仍需调用方保证。未配置时沿用具名对象，如 `{"id":"001","note":"说明","amount":12.5}`，可选声明列类型。`defaults` 只补缺省字段，显式 null / 0 / false / 空字符串均保留；绑定后须覆盖全部输出列；未映射输入字段报错。仅任务明确裁列时用子表的 `omit_keys` 列出不输出的字段，回执 `output_keys` / `omitted_keys` 列出映射结果，不为消除报错把遗漏字段全部加入裁列清单。
- 单元格保留 JSON 文本、数字、boolean、null；以 `=` 开头的文本不自动变公式，公式显式写 `{"formula":"=C2*2"}`，真日期写 `{"date":"2026-01-01"}`。不能经数值序列化与浮点表示精确保留的整数，以及当前编辑加载器不支持的 `_xHHHH_` 形态文本，在构建时定位报错；按业务语义选择文本或其它可保真路径，不自动舍入或删改原文。公式只写入不计算，需要计算值时再按下文取值流程处理。外部文本放在数据文件中，不拼成 Python 字符串；程序生成 JSON 用标准库处理引号与换行。
- `expected_rows` 可声明用户要求或上游已确定的结果条数，不校验来源真实性或语义。确认筛选结果为空或只需表头时显式设为 `0`，允许 `data_files: []` 或空数据文件；未确认空结果时，空块仍报错，不能用 `0` 掩盖未生成的数据。JSON、字段、行宽或数量错误只修当前文件，已有输出不被覆盖。多个视图复用事实文件；概览计数从实际记录或回执 `sheets[].rows` 派生，不重复生成全量数据。
- 构建器一次设置表头居中与底边框、文本左对齐、数值右对齐、日期 / boolean 居中；公式按结果类型显示。可用列的 `align`（`left` / `center` / `right`）/ `width` / `number_format` 和子表的 `row_height` / `freeze_header` 配置；默认列宽 18、行高 30pt，不逐格估高、不设打印版式、不渲染。成功后不为确认这些默认样式另起回读和补刷；用户要求或已有具体异常时仅处理相关范围。
- 子表 `header_row` 默认1；前面留标题空间时直接设置该行号，数据从下一行开始，筛选和冻结自动跟随，不另改数据行偏移。
- 默认拒绝覆盖；仅重建本次生成的工作簿时加 `--overwrite`，不得用于用户原件或模板。完整工作簿先写临时文件，再原子发布并清理临时名称；默认不覆盖并发创建的同名文件。环境不支持安全发布时报告错误，不改为直接写最终路径。若导入路径被拒绝，按 `references/lark-sheets-workbook.md` 的实际错误恢复，不预先复制所有文件。

**截断后先修复当前块**：输出或工具参数已截断时，保留此前完整数据块与构建代码，只重写不完整的块并减小下一批体量。当前块是否完整不明时，仅查看该文件的大小、末尾或报错位置；空正文和“创建成功”回执不能证明所需内容已生成，不为此新增全表复验。

## 6、专业格式与视觉规范

专业格式用于降低阅读成本、提高产物质量，不是默认装饰动作，避免过度使用斑马纹 / 交替行颜色等装饰。用户明确的格式要求与既有模板样式优先；只使用能够表达层级、数据类型、状态或对比关系的必要格式。

- **Excel**：`.xlsx` 需要新建或修改格式、布局，或制作报表 / 打印展示时，读 `references/ref-excel-visual-standards.md`；仅在模板补内容且保留原格式时不触发。
- **飞书表格**：涉及上述场景时，读 `references/lark-sheets-visual-standards.md`。
- **财务数据**：无论产物载体，均叠加读 `references/ref-financial-modeling-standards.md`；财务规范优先于通用视觉规范。
- **仅补内容时保留既有格式**：已有模板补值仅写内容，保留原空格的底色、边框、数字格式；不复制邻格样式覆盖待填格，新增区域继承样式，用户要求调整格式时按指定范围修改。必要的排版调整仅限本次内容显示不全的目标区域，不统一重刷旧数据区。

## 7、交付

- **改动策略匹配诉求**：默认可在必要范围内修改；若用户要求保留原表（原件不动），则通过新建 sheet / 复制 sheet / 另存等方式实现；用户指定就地修改位置的，按「2、输出区域注意保护原表」就地改。
- **公式在交付表**：计算结果用公式写在最终交付的表格位置，不在临时表 / 中间 sheet 计算后回填数值。
- **载体与通知**：交付载体按主文档「一、通用流程」的「交付契约」判定，包括导入不支持元素时的完整 Excel / 双交分支，交付本地文件时**禁止**擅自把 `token` 拼成在线链接。只要涉及表格产物，必须调用宿主的产物交付工具交出去，并确认这次调用返回成功、回执列出了交付的条目；只把 URL 写进回复正文不算交付。当前宿主的交付工具是 `present_files`；工具交付时，调用前后的回复文本均不输出产物 URL（含裸链接与 Markdown 超链接），用产物名称指代。宿主未提供该能力或调用明确报工具不存在时，在正文给出最终 URL / 路径。交付 HTML 报告时正文必须内联自包含（数据、图表渲染代码、样式都在文件内），不得只放一个指向外部地址的 iframe / 跳转链接——外部地址打不开时等于没交付。
- **分析结论按需回写表格**：当需要与原始数据联动或体现数据之间的关系时，可将分析结论回写到表格中（如结果工作表的摘要区或独立说明块）。用户仅需文字结论时，可直接在回复中交付，完成必要读取与核验，不为交付额外制表。仅请求分析、解释或建议不等于要求修改表格，不据此直接改表或另存修正版。用户要求制作、修改或交付表格，或本轮已写入表格时，仍须完成表格交付。用户点名“表后 / 指定章节 / 指定子表”时按原位置放置；最终交付聚焦结论和建议、过滤中间过程，缺口逐项声明。

### 本地 Excel 内容编辑与取值

**已有布局的精确关联回填直接用同一编辑器**：以 `--lookup` 替代 `--changes`，声明实际数据区（不含表头）、目标列到来源列的键与结果映射。多附件时 `reference.file` 指定来源，省略则来源与目标在同一原簿；键保留类型与原文，不自动 trim 或猜别名。下例只补空格、保留原样式，明确例外来自用户或原资料，不由脚本推断：

```bash
cat > lookup.json <<'JSON'
{"reference":{"sheet":"来源","range":"A2:C50"},"target":{"sheet":"待填","range":"A2:C40"},"keys":{"A":"A"},"columns":{"B":"B","C":"C"},"mode":"unique","only_empty":true,"overrides":[{"key":["编号甲"],"values":{"B":0,"C":"按来源明确例外"}}]}
JSON
python3 scripts/excel_apply_edits.py --source ./before.xlsx --output ./output.xlsx --lookup ./lookup.json --scope '待填!B2:C40'
```

`mode=unique` 只接受唯一候选，歧义不取首条；`mode=all` 保留完整元组并按同一顺序换行对应，仅文本与空值适用。明确按整组结果去重时设 `distinct=true`，默认保留重复。需要覆盖已填目标时显式 `only_empty=false`；无匹配保留原格，`overrides` 按 `keys` 顺序提供完整键，明确例外优先于来源列值。多候选目标部分已填、超出单格容量或源格是公式/错误/富文本时拒绝本次写出，保留源文件；应按用户许可另处理完整候选与承载区，不改样式或裁剪来绕过。只有文本值/普通标量关联且结果不需动态联动时用此模式；公式关联、清洗/聚合、结构/样式修改沿对应路径。`status=unchanged` 表示没有可写项、没有新文件或上传；需要另存副本时直接复制原件。在线交付可同次追加后述发布参数。

**原件内容补丁保留布局与样式**：已选Excel引擎、仅修改原xlsx布局内单元格（含未定义的稀疏空格）的值 / 普通公式、且布局与样式不变时，按交付形态选择下方命令。`value`保留JSON类型，`formula`才写公式；源文件只读，output须为新文件。

```bash
cat > changes.json <<'JSON'
[{"sheet":"明细","cell":"A2","value":"00123"},{"sheet":"明细","cell":"D2","formula":"=B2*C2"}]
JSON
```

**本次补齐后直接在线交付**（允许上传，已无其他本地加工）：编辑、所需取值与导入在一次调用完成；不需要计算值时省略 `--read-range`。

```bash
python3 scripts/excel_apply_edits.py --source ./before.xlsx --output ./output.xlsx \
  --changes ./changes.json --scope '明细!A2' --scope '明细!D2' \
  --publish-state ./publish.json --name "交付标题" --read-range '明细!D2'
```

**仅本地交付、禁止上传，或还要继续本地加工**：只保存，不上传。

```bash
python3 scripts/excel_apply_edits.py --source ./before.xlsx --output ./output.xlsx \
  --changes ./changes.json --scope '明细!A2' --scope '明细!D2'
```

在线分支的 `saved` 返回保存回执，`delivery.calculation.ranges` 返回所需值，`delivery.import` 保留导入回执及兼容性信息；按该回执完成剩余在线操作并交付。标题随导入设置。退出3表示本次编辑未生成新文件；退出4表示文件已保存但后续阶段未完成，保留 `saved.output` 与状态文件，按 `delivery` 恢复，不重做编辑；已有导入任务用 `excel_publish.py` 的同一状态文件恢复。

原文片段提取可把 `value` 换成 `"extract":{"cell":"C2","start":0,"end":4}`：从同一子表、同行源格按0起的Unicode字符位置截取（不含end），保留原标点与空白；非法区间不写出，目标仍受 `--scope` 和原样式保护。多片段、跨行与语义改写沿用对应路径。在线写入可在现有循环中用 `from scripts.sheet_data import extract_span`、`value = extract_span(source_text, start, end)` 后按原CLI路径提交，不为此导出或重导。

脚本局部替换目标内容，传统批注及其VML原样保留；支持原布局内稀疏空格，继承无冲突的行/列默认样式，不扩大行列范围。清除全簿公式旧缓存并标记打开或导入时计算，避免依赖格沿用旧结果；`formula_cache` 描述文件缓存状态，`calculated_values=not_requested` 表示本地保存未请求取值，不代表还欠一轮验算。默认样式冲突、控件VML、不支持的格/结构或兼容性警告仍拒绝写入。不适用于在线编辑、样式 / 结构调整及特殊公式对象，不忽略拒绝理由。需存回原件时保留改前备份后按环境保存规则替换。

后续操作需要公式计算值、用户要求核验计算结果或需定位已知计算异常时，用独立副本重算；下一步所需区域合并为一次调用的 `--read-range`，直接消费返回值。写入公式或缓存为空本身不触发额外验算：

**本地处理已完成，需取值后在线交付**：合并取值与导入，不再单独重算后另调导入：

```bash
python3 scripts/excel_publish.py ./output.xlsx --state ./publish.json --read-range '汇总!B2:D6'
```

原文件导入，重算副本只供 `calculation.ranges` 取值；`import` 保留 CLI 完整回执，按 `references/lark-sheets-workbook.md` 处理 `data.extra` 与剩余操作，再交付。`--state` 保存本次请求及进度，重复同一命令只返回已有导入回执；超时 / 输出缺失时恢复原任务，不换状态文件重导。输入变化会停止并返回已有回执，后续修改在已导入在线对象上完成；尚未导入的取值错误按 `calculation` 修复。脚本退出3时按 `status` / `action` 恢复当前阶段，不当作整条链路均未执行。

**仅本地交付，或尚需计算值继续本地加工**：只重算取值，不导入：

```bash
python3 scripts/excel_recalculate.py ./output.xlsx --read-range '汇总!B2:D6'
```

`--read-range` 可重复，最多16个有界区域、合计1000格；`ranges[].values` 保留数字 / 文本 / 布尔 / 空值类型，日期时间为ISO文本，公式错误按原值返回并列于该区域的 `error_cells`。未指定时不额外读表。退出5且 `status=recalculated, read_status=failed` 表示重算成功但范围读取失败，保留并读取回执 `output`，不因此重算；范围名取实际子表名，不猜默认sheet。

重算默认安全复用：首次调用、输入变化或回执不可复用时会自动重算，无需加 `--fresh`。省略 `--output` 时在源旁 `.sheet-calculated/` 管理副本，重算自动选新路径、不覆盖旧文件。后续取值使用回执 `output`，无需换名重试。转换仍显式开启复用：

```bash
python3 scripts/excel_lo_convert.py ./output.xlsx csv --outdir ./preview --reuse
```

仅在明确需要绕过已有复用结果（如排查旧回执）时使用 `--fresh`；它不是“第一次算”或“输入改过”的标记，`--output` 仍可省略：

```bash
python3 scripts/excel_recalculate.py ./output.xlsx --fresh
```

仅自包含 `.xlsx` 的输入、参数、引擎运行库 / 注册配置、区域 / 时区设置与已有输出内容匹配回执时复用，返回 `cached=true, cache_reason=hit, attempts=0`；否则 `cached=false` 与具体原因说明未启用、内容变化、布局不支持、加载配置受限或扫描失败。易变 / 未知函数、外部依赖、特殊公式对象或指纹不可靠时不复用，输出路径可用时正常执行。重算显式 `--output` 或 CSV/XLSX 转换开启 `--reuse` 时，已有输出不匹配回执则拒绝覆盖；重算可省略 `--output` 改用管理副本，转换改用新 `--outdir`。重算的 `--reuse` 与 `--fresh` 互斥；PDF/PNG 始终重新渲染。删除隐藏回执不能绕过已有输出保护。

依赖计算值的 Python 处理直接消费成功回执；跨工具步骤需复用时保存这份回执，后续读它而不是重新调用重算，不用 `| tail` 隐藏退出状态：

```python
import json
import subprocess
import sys
from pathlib import Path

delivery_path = './output.xlsx'
receipt = json.loads(subprocess.run(
    [sys.executable, 'scripts/excel_recalculate.py', delivery_path,
     '--read-range', '明细!D2'],
    check=True, capture_output=True, text=True).stdout)
Path('calculated.json').write_text(json.dumps(receipt, ensure_ascii=False), encoding='utf-8')
calculated_value = receipt['ranges'][0]['values'][0][0]
```

`receipt.output` 的角色是 `values_only`，可能改变格式；交付始终使用 `delivery_path`，不把取值副本覆盖、移动为交付源，不在取值副本上继续编辑。后续写入仍操作原工作簿或用上面的保真内容编辑；无可用引擎时说明结果尚不可用。

**后续步骤沿用同一回执**：源内容未变时，先复用 `ranges` 中已有值；确需其他范围时，从保存的回执取得准确的 `output` 并一次只读加载，保留 `.sheet-calculated` 及隐藏回执供本任务后续使用。源确实变化后再重算并绑定新回执；不靠目录排序猜输出，交付只选择交付文件，不以清空工作目录作为交付步骤。

## 8、生成 / 推断信息的处理规则

当任务需要“生成信息 / 补全缺失值 / 把口述信息整理成表 / 输出结论建议 / 构造示例数据”，或源数据未能完整读入时，按以下规则组织信息：

1. **单位合理**：货币 / 数量 / 百分比 / 温度单位一致；表头写清单位（如 `Revenue (¥)`、`Weight (g)`）。
2. **日期时间一致**：结束时间不得早于开始时间；跨天需显式说明或拆分。部分东亚内置日期格式可能被读成普通数值，先结合字段语义确认日期列；确认为 Excel 日期序列后，用 `from openpyxl.utils.datetime import from_excel`、`from_excel(value, wb.epoch)` 按源工作簿纪元转换，不凭数值大小猜日期。
3. **月日歧义先定位再转换**：`9/3/24`、`4-Sep-24` 这类月日位置有歧义的日期列，转换前先扫描该列全部值——某个位置出现过 `>12` 的数即可锁定它是「日」；全列都锁定不了时按同文件其它日期列 / 数据来源惯例判定，并在交付说明标注所用规则。逐格按感觉解析必然出现月日颠倒。
4. **领域固定集合列全**：用户提到「五险一金」「四大报表」这类有公认固定构成的领域集合时，先展开集合全部子项（如五险一金 = 养老 / 医疗 / 失业 / 工伤 / 生育 + 公积金共 6 项）再动手，不凭印象省略子项——少一项即为该要求未完成。
5. **来源可追溯**：产物里每个具体数值都要能指出它来自源文件的哪一处；指不出来源的数值一律不写，按主文档「附件读取」留空并声明缺口。
