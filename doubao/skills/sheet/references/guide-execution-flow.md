# 通用执行流程：预检、字段对齐与交付校验

适用于两套引擎，覆盖通用流程与源文件保护；具体 CLI 操作由各工具参考提供，飞书侧的**编辑准则**见主文档「飞书表格引擎」一章。

## 0、多项显式产出先对应到目标位置

用户明确列出多项产出时，先对应到子表 / 区域、字段顺序、所需对象及说明位置，再逐项落实；普通单项编辑不增加清单。复杂公式保留字段/阈值/单位/范围/哨兵，见 `references/lark-sheets-formula-translation.md`。

## 1、基本原则

1. **源数据默认必须保留**：除非用户明确要求删除、覆盖或替换原数据，表格编辑 / 整理 / 统计任务都不能破坏源明细。对已有表做“按指定维度统计整理”“分类汇总”“筛选保留若干列”“透视分析”“生成结果表”时，默认保留原 sheet 和原始行列，把结果写到新 sheet、新区域或明确命名的结果表；不要只反馈统计结果、清空明细、覆盖原 sheet，或把原始数据口径改掉。若用户给“已有表 / 模板表 + 新数据”，已有表是 base workbook，默认在原 sheet 末尾追加或新建结果区，不要新建同名空 sheet 后重写。多附件时动手前先显式认定谁是 base、谁是增量源；**追加 / 合并类任务**交付前逐 sheet 断言：产物行数 ≥ base 对应 sheet 原行数，且 base 每张 sheet 的首行与末行原文仍能在产物中原样检索到（用户明确要求删除 / 就地改写的行列不计入）——任一条不成立就是覆盖，不是追加。
2. **输出区域注意保护原表**：用户要求“直接在指定位置修改 / 覆盖原文件”时，才在指定位置就地修改；用户没有指定落点时，优先追加结果而不是覆盖输入，典型做法是新建 `统计结果` / `整理结果` sheet，或在原表右侧 / 下方追加结果区并保留清晰标题。用户点名了 sheet 名 / 单元格坐标 / 列顺序时按该契约排布——被点名承载某一形态结果的区域只放该形态，原始值 / 中间量另置，不要插在指定区域之前把坐标挤偏。**例外**， 当运行环境为本地电脑且使用**Excel 引擎**编辑文件时，结果的落点仍按上面几条排布，只是整份存回原文件——动手前先复制一份备份，它只做回滚快照。
3. **公式优先原则**：凡是需要计算，优先写公式到最终交付的表格对应单元格，保持动态计算能力。把公式写在对话回复或表末说明里、要求用户自行复制到单元格，等同于未交付该列——公式必须真实落在目标单元格内。计算公式对可能为空的输入列先判空返回空（如 `=IF(OR(O2="",R2=""),"",…)`）——空单元格参与算术按 0 计，会产出看似正常的异常数值且不触发错误码，仅 `IFERROR` 拦不住；落完公式后抽查输入为空的行核对输出；无需 AI 真值的 AI 区域按主文档首检交付，不追加结果回读。
   - Excel 引擎：写 Excel 公式（如 `ws['C2'] = '=A2+B2'`），不要在 Python 中算好数值再写入。
   - 飞书表格引擎：写飞书公式；Excel 公式到飞书公式的迁移规则见 `references/lark-sheets-formula-translation.md`。
   - **例外**（允许直接写静态值）：直接来自输入或外部来源的原始值、固定常量，或用户明确要求固定结果。已命中 AI 分流的原位编辑，先在独立计算区求值，验收后回写原格。原地调整需保留联动时，先在允许位置保存原值，再以公式引用原值和调整项；同一次操作重试复用基准，避免重复累计。无法在允许范围保留输入时说明限制；公式降级为静态结果时说明原因及不再联动的影响。
   - **用 Python 算好数值再写进单元格，交付的是改输入不重算的死表。** Python 可用于推导和验证，但**落进单元格的必须是引用其他单元格的公式**，关键输入要做成可修改的输入格。财务 / 金融场景尤其严格，详见 `references/ref-financial-modeling-standards.md`。

## 2、判断数据来源

| 输入信号 | 来源判定 | 走哪套引擎 |
| --- | --- | --- |
| 用户上传 `.xlsx` / `.xls` / `.csv` 文件 | 本地 Excel/CSV | 按主文档「用户边界优先」「按结果区域分流」命中 AI 公式时用飞书表格引擎；否则用 Excel 引擎读取与处理；默认在线交付时，导入后用 CLI 完成所需原生图表 / 透视 / 条件格式，不能到“导入成功”即结束 |
| 用户给出飞书 / doubao 的 `/sheets/`、`/spreadsheets/`、指向电子表格的 `/wiki/` 链接或 token | 飞书表格 | 飞书表格引擎 |
| 用户口述 / 粘贴数据，无文件 | 待结构化 | 先结构化，再按产物载体选引擎 |
| 无数据 | 信息不足 | 向用户询问，或先用其它工具获取数据 |

## 3、数据结构和内容的预先检查

拿到数据后，按主文档识别运行环境、按操作产物类型选执行引擎，**再检查结构才动手处理**：

1. **运行结构预检**了解数据概况（预检只为了解数据，具体执行仍需读取完整内容）：
   - **Excel 文件**：本地电脑的 Canvas 模式下 `file_status` 为 "open" 时，用 `lark-cli sheets` 直读；其余情况用支持源格式的 Python 库读取（openpyxl 读 `.xlsx`，xlrd 可读 `.xls`）。文件无法读取时，**不要改用解压 xlsx 直读 XML、手写底层解析等本地绕路**——云电脑用 `lark-cli sheets +workbook-import --file ./source.xlsx`（替换为实际文件相对路径）转飞书引擎，本地电脑先提醒用户再走此兜底。已知源文件含 `x14:dataValidation` 扩展，或读取时警告该验证扩展将被移除时，不用 openpyxl 保存，按上述环境规则转飞书引擎处理。
   - **CSV 文件**：用 `pd.read_csv(..., nrows=15)` 预览，注意编码（优先尝试 utf-8-sig、gbk、gb18030）。
   - **飞书表格**：优先 `python3 scripts/lark_inspect_workbook.py --url "<表格URL>"` 做只读预检，拿子表清单、布局、预览和 `current_region`；多块表 / 汇总块 / 备注块先用 `scripts/lark_detect_subtables.py` 识别候选 range；批量写入、公式 / 计算、排序 / 筛选、去重 / lookup、透视 / 图表 / 汇总、整表语义或表头不确定时，再用 `scripts/lark_profile_table.py` 对目标区域画像。也可直接调用 `+workbook-info` / `+sheet-info` / `+csv-get` / `+cells-get` 做等价读取，详见 `references/lark-sheets-read-data.md`。
2. **评估数据规模**，决定执行策略：小数据（行数 ≤ 1000 且文件 ≤ 5MB）一次性加载处理；大数据分批（分 sheet / 分行批处理 / 流式读取 / 列裁剪）；多 sheet 文件逐个 sheet 单独执行完整的「预检 → 处理 → 输出」流程。
3. **识别合并单元格**：合并单元格的值仅存储在左上角；提取时仅在已确认的合并区内传播该值，不对全表空值 `ffill`，不跨来源借填。已有合并区只写或引用左上角，不向 openpyxl 的非锚点 `MergedCell` 赋值；新合并前确认其余格没有需保留的内容，迁移区块时同步映射合并范围。飞书结构操作见 `references/lark-sheets-sheet-structure.md`。
4. **识别必需字段并保留列位**：用户点名输出字段时，先固化表头 schema；源数据缺某字段也要保留该列，值可留空 / 写“未提供”，不要把必需列降级进备注、也不要用其它字段替代。填写已有模板或汇入已有汇总表时，复用其字段和列序；行标签与待填格分别定位，不为来源说明扩列或改写标签。多源合并按输出要求核对各源字段映射，必需字段无法映射时列明缺口。新建结果表允许的附加字段放在必需字段之后；用户限定“仅这些列 / 仅明细行”时不增列、不加合计行，来源与说明另置于允许区域。用户提出的排序 / 命名 / 格式要求对**每一张**同类表一致适用，不因某张表行数少、分组少而豁免。新增区域继承对应模板样式；已有区域仅补内容时保留原样式。
5. **识别“表头不清晰”并做字段理解**：出现无表头 / 空表头列 / 多行表头 / 前几行是标题说明时：Excel 用 `python3 scripts/excel_preview_rows.py` 对可疑 sheet 预览更多行（如前 30 行），结合数据形态判断真正表头行；对空表头列，观察该列前 20 个非空值的类型与模式，推断临时列名（如 `未命名_金额`）；后续映射与计算优先用“列坐标 / 列字母 + 行号范围”锁定字段来源，避免引用错列。
6. **识别“特殊行 / 特殊单元格”**：结合行结构确认合计 / 小计等汇总行，聚合前排除，避免重复统计；不能只凭名称关键词删除记录。提取数据区时同时保留标题、备注、批注中的规则与例外，并指向受影响记录；说明与公式缓存冲突时，按用户要求核验来源，不直接照抄缓存。
7. **Excel 编辑保留源文件能力**：用 `load_workbook(..., data_only=False)` 打开原工作簿修改；`data_only=True` 只用于读缓存，保存该实例会丢公式。仅改本地xlsx布局内单元格的值 / 普通公式且布局不变时，可用下方 `excel_apply_edits.py` 生成保真副本。pandas 可用于分析，不用 `df.to_excel` 重建需要保留结构的源文件。写入前读取目标范围的数据验证并核验值，不为写入成功而移除规则；用户要求修改验证时才定点更新。公式还可能是数组公式或敏感性分析 Data Table 对象，不能只检查以 `=` 开头的字符串；只改格式时保留对象类型、覆盖区域与输入引用，输出数值相同不能证明计算关系保留。插删或移动行列不会由 openpyxl 自动维护公式、Table 和图表依赖，必须另核引用与对象范围。

## 4、字段语义对齐与结果核对

动手前，确认用户的指标 / 概念与数据中字段如何对应。用户说的“收入”是哪一列？“完成率”怎么算？避免“答非所问”。

- **标识符保持文本原值**：编号、证件号、订单号、商户 ID 等标识符，用 pandas 读入时要保持原文。读取时需注意：不指定类型时被推断成数值，可能丢精度和前导零；默认缺失值识别会把值为 `NA`、`NULL` 等字样的 ID 读成 `NaN`；关闭缺失值识别（`keep_default_na=False`）对整表生效，其他列的空单元格会变成 `''`，需计算的列要另行转回数值。合并、关联等后续处理也可能把 ID 重新转成数值，写回前抽查，与源表保持一致。写回按 `references/ref-excel-visual-standards.md` 以字符串写入并设文本格式。
- **身份匹配按约定的键执行**：明确相等、包含或归一化后相等；未授权时不去空格、删版本后缀或用价格相近代替同一商品。同名多条先核对其他身份字段，不取第一条或最后一条覆盖冲突；一对多保留整组候选的字段对应。来源侧可用 `lark_profile_table.py --key-cols` 连同返回字段检查重复键与冲突，完整命令和显示值限制见 `references/lark-sheets-read-data.md`。单格含多个值时先确认是集合、按位配对还是普通文本，按实际关系拆分，既不把集合当整串单值比较，也不将多列任意笛卡尔组合。未命中按用户规则留空或标注。
- **重塑数据后核对形状**：先按用户要求确定业务粒度，核清标识字段与业务实体的对应关系，不以方便分组的列替代业务键。合并 / 关联 / 透视 / 分组汇总 / 宽长转换后，核对键集合、行数与各键观测数，总额一致不能证明分组正确。区分记录数、唯一对象数和数量合计；关联按一对一 / 一对多及连接类型核验，区分预期展开、筛选与意外丢失或重复。
- **源到目标逐格核**：把源表的值搬进新版式（重排、映射、填模板）时，按「区块 + 标签 + 期间」定位比对源与产物，抽查覆盖每个区块的首末项。只核总计对不对，会漏掉单格错位。
- **事实表先于结论**：统计 / 分析 / 诊断类任务先按用户要求的粒度和范围形成事实表，再从中派生结论、图表与排名。要求完整统计时核齐指定分组和指标，不用筛选子集代替全量；缺失与真实 0 分开，不擅自补造不存在的维度组合。
- **计算精度与显示精度分开**：仅要求固定小数位显示时设置补零数字格式，后续计算继续引用未舍入值；按期结算等明确要求逐期舍入时才在指定层使用 ROUND，并核对尾期差额。统计检验记录单 / 双侧、连续性校正、零频平滑及样本筛选规则，不用库默认值或事后换口径凑预期；很小的 p 值用科学计数法或明确上界，不能显示为精确 0。
- **时间计算先固定时间轴**：完整时间戳保留日期；仅有时刻时，按明确的跨日规则确定日期归属。缺失、无效输入和合法零值分别处理；时差方向按业务定义，不用 `MOD`、绝对值或截断掩盖日期与方向错误。
- **多阶段分析保留样本链**：拟合、聚类、匹配、回测等跨阶段处理时，保留主键、纳入 / 排除标记、关键派生量及参数，区分全样本与匹配样本。算法优先用成熟实现；自行实现时先用可手算的小样本或另一独立实现核对，尤其是分母、样本集合和时点，不能只验证代码与自己生成的预期一致。产物须能追溯中间数据与方法，不只给系数和“已验证”结论。
- **筛选交付对齐结果形态**：产物是**另一张表**（行、列都裁，如“筛出符合条件的记录并只保留若干列”）时，按规则 1 写入独立结果 sheet 并保留原表，数据要**读全表**再筛（不能只取当前可见行），交付前核对结果 sheet 的列数 / 行数。**纯行级筛选（不裁列，只是“只看 / 仅保留符合条件的行”）不走这条**——按 `references/lark-sheets-filter.md` 创建真实筛选器对象，不要新建子表。

按主文档「动手前必读的 References」读取对应 reference，按其工作流程执行任务。

## 6、专业格式与视觉规范

专业格式用于降低阅读成本、提高产物质量，不是默认装饰动作，避免过度使用斑马纹 / 交替行颜色等装饰。用户明确的格式要求与既有模板样式优先；只使用能够表达层级、数据类型、状态或对比关系的必要格式。

- **Excel**：`.xlsx` 涉及格式、美化、报表、模板、汇报或打印展示时，读 `references/ref-excel-visual-standards.md`。
- **飞书表格**：涉及上述场景时，读 `references/lark-sheets-visual-standards.md`。
- **财务数据**：无论产物载体，均叠加读 `references/ref-financial-modeling-standards.md`；财务规范优先于通用视觉规范。
- **仅补内容时保留既有格式**：已有模板补值保留原空格的底色、边框、数字格式；新增区域继承样式，用户要求调整格式时按指定范围修改。必要的排版调整仅限本次内容显示不全的目标区域，不统一重刷旧数据区。
- **最低验收**：无截字、`####`、异常溢出或对象遮挡；数字、日期、百分比和标识符格式正确；图表具有清晰的中文标题、坐标轴与必要图例。**打印 / 下载类任务的完成标准是每份交付产物都无遮挡**——交在线表与导出 xlsx 时两者都检查；因不支持元素只交完整 Excel 时检查该文件。

## 7、交付校验

- **改动策略匹配诉求**：默认可在必要范围内修改；若用户要求保留原表（原件不动），则通过新建 sheet / 复制 sheet / 另存等方式实现；用户指定就地修改位置的，按「2、输出区域注意保护原表」就地改。
- **公式在交付表**：计算结果用公式写在最终交付的表格位置，不在临时表 / 中间 sheet 计算后回填数值；已命中 AI 分流的原位编辑，先在独立计算区求值，验收后回写原格。
- **载体与通知**：交付载体按主文档「一、通用流程」的「交付契约」判定，包括导入不支持元素时的完整 Excel / 双交分支，交付本地文件时**禁止**擅自把 `token` 拼成在线链接。只要涉及表格产物，必须调用宿主的产物交付工具交出去，并确认这次调用返回成功、回执列出了交付的条目；只把 URL 写进回复正文不算交付。当前宿主的交付工具是 `present_files`；工具交付时，调用前后的回复文本均不输出产物 URL（含裸链接与 Markdown 超链接），用产物名称指代。宿主未提供该能力或调用明确报工具不存在时，在正文给出最终 URL / 路径。交付 HTML 报告时正文必须内联自包含（数据、图表渲染代码、样式都在文件内），不得只放一个指向外部地址的 iframe / 跳转链接——外部地址打不开时等于没交付。
- **结论落进产物**：最终交付聚焦用户需要的结论和建议、过滤中间过程；**分析类结论要写进产物本身**（结果 sheet 的摘要区 / 附注行 / 独立说明块），用户点名“表后 / 指定章节 / 指定子表”时按原位置放置，对话回复只作复述——只写在回复里等于没交付。交付前按主文档编辑准则「产物可核对」逐条核对用户需求中显式要求的事项：把用户点名的每一项产出（sheet 名与数量、指标 / 列、图表、说明项）列成清单逐项核到——点名 N 项就核 N 项；缺口在交付说明中逐项声明，不因”主体已完成”就漏核。

> 文本语义任务的执行方式与质量边界以主文档「用户边界优先」「按结果区域分流」和「语义结果质量」为准。

### 本地 Excel 校验与重算（执行时适用）

本节仅用于本地 `.xlsx`，按主入口和所选模式决定是否执行，不因读取本节增加门禁。CSV使用 `excel_csv_verify.py`；在线表用 `references/lark-sheets-formula-verify.md`。

**声明产物要求再检查对应事实**：需要核验公式覆盖、对象数量或精确格式字符串时，可直接给检查器传参；参数来自用户要求或已确认的设计，不从当前产物反推。下例仅演示参数组合，按任务删改：

```bash
python3 scripts/excel_artifact_verify.py ./output.xlsx \
  --require-formulas "明细" "F2:F101" \
  --require-pivots "月度汇总" 1 --require-charts "概览" 2 \
  --require-format "明细" "F2:F101" "0.0000"
```

参数可重复；公式覆盖包含有效数组 / 数据表公式的结果区，声明范围排除不适用行，输出值仍需重算核对。两个检查器均扫描特殊公式的结果格；直接存储的 `LINEST` / `LOGEST` 五行统计数组仅豁免已确定的 `#N/A` 占位格，截距列按输入方向和自变量数量定位，无法确定输入维度或输出截断未包含该列时不豁免；其余错误照常报告，不据此批量清除错误值。格式检查比较原文，不判断不同格式是否语义等效。退出0仅表示静态扫描及声明项通过，3按定位修缺，2修正输入；均不代替重算或业务核验。

**原件内容补丁保留布局与样式**：已选Excel引擎、仅修改原xlsx布局内单元格（含未定义的稀疏空格）的值 / 普通公式、且布局与样式不变时，可用下方脚本。`value`保留JSON类型，`formula`才写公式；源文件只读，output须为新文件。

```bash
cat > changes.json <<'JSON'
[{"sheet":"明细","cell":"A2","value":"00123"},{"sheet":"明细","cell":"D2","formula":"=B2*C2"}]
JSON
python3 scripts/excel_apply_edits.py --source ./before.xlsx --output ./output.xlsx \
  --changes ./changes.json --scope '明细!A2' --scope '明细!D2'
```

脚本局部替换目标内容并核对其余内容与格式，传统批注及其VML原样保留；支持原布局内稀疏空格，继承无冲突的行/列默认样式，不扩大行列范围。清除全簿公式旧缓存并标记需重算，避免依赖格沿用旧结果。默认样式冲突、控件VML、不支持的格/结构或兼容性警告仍拒绝写入。不适用于在线编辑、样式 / 结构调整及特殊公式对象，不忽略拒绝理由。成功不代表已重算，后续按所选模式核验；需存回原件时保留改前备份后按环境保存规则替换。

最终文件保存后，按目标调用随技能分发的脚本；参数可组合，超时秒数不传时默认 30：

```bash
# 从零新建
python3 scripts/excel_formula_verify.py ./output.xlsx 60
# 编辑已有文件：动手前保留基准、确定允许改动范围
python3 scripts/excel_formula_verify.py ./output.xlsx 60 --baseline ./before.xlsx --scope '明细!G:I'
# 检查点示例见下方；其余参数查 --help
python3 scripts/excel_formula_verify.py ./output.xlsx 60 --checkpoints @./checkpoints.json
```

| 退出码 | 含义与处置 |
| --- | --- |
| `0` | 重算与确定性检查通过，按实际覆盖范围报告结果 |
| `3` | 公式错误、缺前缀 / 区域形状错误、基准保护失败、检查点不符或文件读不到等确定性错误；按 stderr 的格址和原因修复后重跑 |
| `4` | 重算未完成、新函数本机引擎不认（`engine_unsupported` / `engine_affected` 非空）、静态值嫌疑、检查点未判或基准比较不完整；按 stderr 处理并说明未完成项或静态值原因，不原样反复重跑 |

`status='success'` 且 `formula_execution_verified=true` 只证明公式重算完成且未发现错误，仍须结合退出码判断基准、检查点与 `engine_*`——引擎不认的格不计入错误总数，这两项成立时也可能退出 `4`；`formula_execution_verified=false` 时，`total_errors=0` 不代表通过。找不到 LibreOffice 时脚本自动跳过重算，继续执行静态诊断、基准对比与可判定检查点；无确定性错误时退出 `4` 属正常降级，可说明计算结果未验证后交付。本地电脑的现有引擎替代与交付边界见 `references/ref-local-compat.md`。用户明确要求的验证未完成时须说明，不用同源复算、公式字符串检查或计数冒充执行验证。

**基准与范围**：`--baseline` 必须是改前文件，`--scope` 写前固定；范围外的改写 / 新增、原公式丢失和原 sheet 丢失会被报告，新增子表也须授权。不传 scope 只列改动事实；只传 scope 而无基准、或 `baseline.truncated_sheets` 非空均表示未完整比较，退出 `4`。基准比较覆盖值与公式（含数组公式和 Data Table 的类型、区域及输入引用），样式、验证和其它对象结构仍须另核；scope 授权的是值 / 公式变化，仅改格式不能据此放行同区计算变化，也不能靠扩大 scope 消除差异。多份 `--baseline` 按坐标合并，同格值冲突时返回 `conflicted_baseline` 并阻断，先确定应使用的源文件。

基准对比也保留文本原字符和单元格类型，不把空白文本当作空单元格、不用数值舍入吞掉末位变化；数值相等的整数 / 小数存储表示视为相同。原公式按文本比较，字符串中的大小写、空格和引用交集均不被归一化；即使等价重写，也会作为公式变化列出。

scope 支持 `明细!G:I`、`明细!A2:C10` 或整表名，可逗号分隔或重复参数。名称含逗号 / 感叹号时单引号包住，内部单引号写成 `''`，如 `--scope "'Sales,2026'!A1:C20"`。坐标必须在 Excel 边界内，整列 / 整行须正序；拼写错误和越界退出 `3`。

**检查点**：`--checkpoints` 接受 `@文件` 或内联 JSON。以下内容保存为 `checkpoints.json`，替换为本任务的真实范围与独立预期：

```json
[
  {"cell": "汇总!B12", "label": "由源明细独立求和", "expect": 1234.56, "tolerance": 0.01},
  {"range": "明细!G2:G200", "all_formula": true},
  {"range": "明细!A1:F1", "label": "要求的表头齐全", "non_empty": true},
  {"cell": "说明!A2", "label": "指定位置的说明", "non_empty": true},
  {"sheets": ["明细", "汇总", "说明"]}
]
```

示例按任务取舍，只声明明确要求的字段、结果和说明位置；不为套检查点新增无关内容。期望值从用户要求和原始输入独立推导，不抄产物值或复用生成函数。每条只选 `cell` / `range` / `sheets` 之一；坐标带子表名，`expect` 仅对单格，多个值拆条。单元格 / 区域须含 `expect`（可为 0、false、空串），或至少一个为 true 的 `non_empty` / `formula` / `all_formula`；`formula` 允许空格，`all_formula` 要求每格都有公式；`non_empty` 要求目标格均有可读非空值，合法空行 / 合并从属格应排除，未取得可信计算值时记为未验证，已重算为空则不满足非空要求，不能以公式存在代替结果已产出。`sheets` 为非空数组，`tolerance` 为非负有限数且不能用布尔值。

`expect` 的 JSON 类型决定比较方式：文本按原字符精确比较，保留前导零、空格与完整长编号；布尔值不等同于 0 / 1 或文本。数值预期才解析百分比 / 货币显示值并应用容差。显式 `tolerance` 是绝对容差，`0` 表示精确比较，不被默认相对容差放宽；未声明时，仅已重算公式格默认使用 `1e-9` 相对容差，静态格精确比较，报告列出实际采用的容差。例如 `{"cell":"明细!A2","expect":"00123"}` 检查文本编号，`{"cell":"汇总!B2","expect":0.4,"tolerance":0.0001}` 检查比例；不要为编号写数值预期。日期格写 `YYYY-MM-DD`，时间与时长格写 `HH:MM:SS`，按日期 / 时间比较。

公式格（含数组公式溢出区）按本次重算结果判，非公式格读产物本身。重算未完成、新函数引擎不认，或副本落在临时目录致跨文件引用 `#REF!` 时，值类条目记 skipped，按每条原因处置。`checkpoints.status='pass'` 才是全部通过；`failed` 退出 `3`，含未判项的 `inconclusive` 退出 `4`，不能用“没有失败项”代替通过。

**重算取值使用副本**：LibreOffice 可用时，脚本以无头模式在临时副本与独立 profile 中重算，默认不改原产物。不可用时按上述降级分支处理，不继续索取重算副本。核对公式结果直接用 `--checkpoints`；要拿具体计算值另作他用时才另存副本：

```bash
python3 scripts/excel_formula_verify.py ./output.xlsx 60 --recalc-output ./.recalced.xlsx
```

返回 JSON 的 `recalc_output` 非空后，才用 `load_workbook(path, data_only=True)` 读该副本；为空则不读取旧文件。取计算值只读这份副本，不为取值再跑门禁，也不靠检查点的 `actual` 探值。同时要核对检查点和取值时，`--checkpoints` 与 `--recalc-output` 写进同一次调用，一次重算两者都拿到。

原表保护仍比较原产物和改前基准。重算副本经 LibreOffice 保存，样式可能改变，只用于读值，不作为交付物。仅允许重写原文件时才加 `--in-place`；它不能与 `--recalc-output` 同用，副本路径也不能指向原文件。启动失败已自动换 profile 重试一次；`lo_start_failed` / `timeout` / `macro_setup_failed` 按 stderr 处理，不原样重跑、不加长超时等待、不自行 `pkill -f soffice`。

**其余诊断按覆盖范围解读**：`error_summary` 给出错误格址；`static_risks` 提示缺前缀时按提示补 `_xlfn.` / `_xlfn._xlws.` 或采用兼容函数，区域形状错误则核对 `SUMIFS` / `COUNTIFS` / `SUMPRODUCT` 等参与区域。`hardcode` 是静态值嫌疑，能公式化且成本可控时改写，历史 / 外部数据可按精确 sheet 名声明 `--static-source-sheets '历史快照,外部数据'` 降级，但不得豁免应联动计算的区域。`invariants.categories.*.samples` 为不变量抽查，`static_risks.coverage.formula_share` 为公式占比；画像和基准均有扫描上限，未命中或高占比不能证明业务口径正确。

## 8、信息合理性校验（生成 / 推断信息时必做）

当任务需要“生成信息 / 补全缺失值 / 把口述信息整理成表 / 输出结论建议 / 构造示例数据”，或源数据未能完整读入时，建议做合理性校验：

1. **单位合理**：货币 / 数量 / 百分比 / 温度单位一致；表头写清单位（如 `Revenue (¥)`、`Weight (g)`）。
2. **取值范围**：时间 / 时长 / 数量一般不为负；百分比一般在 `[0,1]` 或 `[0%,100%]`，异常值判断是否格式混淆并统一。
3. **日期时间一致**：结束时间不得早于开始时间；跨天需显式说明或拆分。部分东亚内置日期格式可能被读成普通数值，先结合字段语义确认日期列；确认为 Excel 日期序列后，用 `from openpyxl.utils.datetime import from_excel`、`from_excel(value, wb.epoch)` 按源工作簿纪元转换，不凭数值大小猜日期。
4. **月日歧义先定位再转换**：`9/3/24`、`4-Sep-24` 这类月日位置有歧义的日期列，转换前先扫描该列全部值——某个位置出现过 `>12` 的数即可锁定它是「日」；全列都锁定不了时按同文件其它日期列 / 数据来源惯例判定，并在交付说明标注所用规则。逐格按感觉解析必然出现月日颠倒。
5. **领域固定集合列全**：用户提到「五险一金」「四大报表」这类有公认固定构成的领域集合时，先展开集合全部子项（如五险一金 = 养老 / 医疗 / 失业 / 工伤 / 生育 + 公积金共 6 项）再动手，不凭印象省略子项——少一项即为该要求未完成。
6. **来源可追溯**：产物里每个具体数值都要能指出它来自源文件的哪一处；指不出来源的数值一律不写，按主文档「附件读取」留空并声明缺口。
