# 本地电脑与 Canvas 模式

用于运行环境判定为**本地电脑**、或两条判定都判不出的会话（SystemPrompt 的 `Computer OS` 为 `Windows` / `Mac`，或 `<system-reminder>` 中出现 `Runtime: local_pc`）。云电脑不受本文件约束。Windows 上还需另读 `references/ref-windows-compat.md`：那份管命令怎么写，本份管文件在哪、产物交什么。

## Canvas 模式的底层机制

用户可以在宿主客户端通过一个 canvas 打开 `.xlsx` / `.xls` / `.csv` 等表格文件或在线飞书表格，实现人机协作。此时系统会通过 `<system-reminder>` 注入下列与打开文件相关的信息，即使用户关闭了 canvas，该信息也会保留，但 `file_status` 会更新。没有被打开过的本地文件或飞书表格不带这些字段。

Canvas 模式打开一个本地文件时，文件会被解码为底层产物放入工作目录，其解码后的路径被 `token` 唯一标识，宿主客户端（`canvas`）通过实时渲染底层产物，让用户实时感受到你对此产物的任何变更。一切变更均发生于工作目录中的底层产物，不改变用户本地文件，仅当用户要求保存时才会打包成同类型文件覆盖用户提供的真实本地路径。

## 注入字段

| 字段 | 含义 | 读取注意 |
| --- | --- | --- |
| `path` | Canvas 模式打开的文件路径，仅当打开的是本地文件时才存在 | — |
| `type` | 文件类型，excel/csv 均被标识为 `sheet` | — |
| `token` | 底层产物的唯一标识，供 lark-cli 指令引用（用 `--spreadsheet-token <token>` 传入，不是 `--url`） | 用户可能同时操作多个文件，传递的可能是一个文件的状态、也可能是多个；**`token` 不一致代表这是不同的文件**。它标识的是本地文件的底层产物，不是在线表格的 token |
| `file_status` | `canvas` 状态，包括 "open/close" | 仅当处于 "open" 时 `lark-cli` 指令才能正常执行。用户可能多次打开或关闭`canvas`，**以最后一次的状态为准**；只在发生变化时才传递，未传递即与之前保持一致（此前 A 文件为 "open"、当前传来 B 文件的状态，则 A 依旧为 "open"） |
| `selection` | 表格选区，用户当前在`canvas`中选中的位置 | 同 `file_status`，以最后一次告知为准 |
| `url` | Canvas 模式打开的在线表格的 URL, 仅当打开的文件是在线表格时才存在 | 此时操作的是在线表格，应使用 `lark-cli sheets` 指令操作。|

## 选引擎与失败判定

按 `<system-reminder>` 是否注入过这些字段，分三态覆盖主文档第 1 节的选引擎结论：

| 状态 | 编辑本地表格时怎么走 |
| --- | --- |
| 注入过且最后一次 `file_status` 为 "open" | 用该 `token` 走飞书表格引擎读写（`--spreadsheet-token`，不是 `--url`），可回滚、编辑状态实时可见；不要把本地文件上传成在线表格 |
| 注入过且最后一次 `file_status` 为 "close" | `lark-cli` 一定会执行失败，`token` 指向的底层产物这条路也随之断掉。先复制一份备份，再用 Python 改 `path` 指向的用户真实文件；改动已落盘，交付时不要再提醒用户自行保存 |
| 从未注入过（非 Canvas 场景，不带 `token`） | 按主文档第 1 节走 Excel 引擎，同样先复制一份备份——Python 改动不可回滚，备份只做回滚快照，编辑落在原文件上 |

- `lark-cli` 长期出现超时问题，应当考虑当前 `canvas` 可能被关闭，不要继续使用 `lark-cli` 指令。
- 历史对话里 `lark-cli` 失败过，不构成停用它的理由：只要最后一次 `file_status` 是 "open" 就继续用，失败再用 Python 兜底。

## 交付与对外表述

- Canvas 打开期间编辑的是工作目录里的底层产物，只能由用户自行保存：不要将修改写回用户真实本地文件，也**禁止**通过 `lark-cli` 把底层产物导出成文件。默认交付用户提供的原文件路径，并提醒用户自行保存。
- 交付形态按主文档「一、通用流程」的「产物载体」判定——本地电脑的编辑场景默认交本地文件路径，新建场景交飞书表格；用户明确要在线表格 / 飞书链接时按那里的例外走，导入后交在线表。交本地文件时不得把 `token` 拼成在线链接当产物给出。
- 用户要求进行文件级操作（如复制、移动、重命名等）时本 skill 指令不再适合，建议使用 `bash`(linux/mac)、`PowerShell`(windows) 类指令进行操作，注意此时应该操作的是用户的真实文件，不得操作底层产物。
- 用户未明确要求的情况下，**禁止**输出任何与"工作目录"、"底层产物"相关的内容，也**禁止**向用户解释底层原理。
