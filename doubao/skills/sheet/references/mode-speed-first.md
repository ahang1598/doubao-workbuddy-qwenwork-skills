# 速度优先模式：按入口选择校验强度

**无论从哪个入口进入，用户明确要求的复核、校验、审计或验收都必须执行。** 本模式只精简技能自动附加的检查。

**入口以本轮 `<system-reminder>` 的 `<current-state>` 为准**，不要根据当前正在读取的文件判断：

- **直接指定**：入口指向 `references/mode-speed-first.md`。只做用户要求的校验，不额外做产物自检，也不先读 `SKILL.md` 重新判断任务复杂度。
- **SKILL 自动分流**：仅在本轮满足 `SKILL.md` 的速度条件且未命中标准任务时适用。**自动分流时，既有产物编辑走标准**：在现有工作簿、模板或上一轮产物上继续写入、整理或修复，包括同一工作簿新增结果 sheet、另存编辑副本；不因只改少量单元格、规则明确或公式已给定而降级。仅把原表作为只读数据源、另建独立产物不属于编辑原表。误读本文件不构成模式切换；已选标准或命中任一标准任务时，回到标准路径补读所需 reference，第三节停做清单不适用。其余自动分流任务交付前按第三节完成一轮基础校验。

无法确定入口来源时按 `SKILL.md` 的自动分流规则判断，先排除既有产物编辑及其他标准任务，其余保留基础校验。本轮沿用已确定的入口，下一轮重新判断；读过的文档不重复读取。

**公式与完整产出仍须保留**：可推导结果（含关联汇总）写引用源数据的公式，题面点名的中间结果也要落进产物；停用门禁不改变这些要求。

**尽量合并工具调用**：复用数据、批量读写。**本模式不使用任务清单与计划类工具**（包括 `task_create` / `task_update` / `task_list` / `task_get` / `submit_plan`），转入标准模式后不受此限。必要读取、校验、修复和交付不得省略；未验证不得声称通过。

## 一、按运行环境和数据位置选择引擎

**先判断环境，读取适用的兼容说明**：

根据 `<system-reminder>`（下称SR） 注入内容判断运行环境，多轮会话时上下文可能存在多个 SR，只看最后一个包含 `Main project directory` 字段的 SR，更早的 SR 注入的字段不作为依据：存在 `Computer OS` 字段时，值为 `Windows` / `Mac` 判为**本地电脑**，值为其他判为云电脑；没有该字段时用`Main project directory` 字段，Linux 路径`/home/user/Doubao/…`判为云电脑；值为其他，如 Mac 路径`/Users/…`、Windows 路径 `C:\…` 判为**本地电脑**。本地电脑或环境不明时，执行命令前先读 `references/ref-local-compat.md`；运行环境为 Windows 时还要读 `references/ref-windows-compat.md`。环境不明时按云电脑规则交付，不因此切换到标准模式。

- **选择引擎**：从零新建或处理本地 `.xlsx` / `.xls` / `.csv`，使用 Python + openpyxl；原位编辑在线表，使用 `lark-cli sheets`。本地电脑编辑本地文件时，还要看 Canvas 状态：最新 `file_status=open` 时，通过 `--spreadsheet-token <token>` 用 CLI 编辑；状态为 `close` 或从未打开时，先备份，再用 Python 编辑真实文件，已注入路径时使用 `path`。Canvas 的具体规则见 `references/ref-local-compat.md`。
- **本地处理一次完成**：选定Excel引擎后，仅改xlsx布局内单元格的值 / 普通公式且布局与样式不变时，可用本技能的 `python3 scripts/excel_apply_edits.py --source ./before.xlsx --output ./output.xlsx --changes ./changes.json --scope '明细!B2'` 保留原格式（变更清单语法查该脚本 `--help`）；它是写入实现，不启动第三节停用的额外门禁。其它本地任务把读取、计算、写值、公式、样式、列宽和保存合并在一个 Python 进程中，不拆成多轮试探。
- **在线处理批量写入**：复用已确认的子表名 / id 和数据。信息不足时，用 `+workbook-info` 定位，并读取必要的值、公式或样式，不猜表名、字段含义和写入位置。数据用 `+table-put` 按类型写入，公式用 `+cells-set`；需要新设或修改样式时，样式、合并、行高列宽和冻结用一份规格调用 `+styles-put`，只修改用户要求的属性，仅补内容不刷原格式。
- **在线产物的原生对象在导入后用 CLI 完成**：图表 `+chart-create-basic`、透视 `+pivot-create`、筛选 `+filter-create`、条件格式 `+cond-format-create`、迷你图 `+sparkline-create`、浮动图片 `+float-image-create`。已有汇总数据或导入成功不能代替创建对象；本地 Python 生成的这些对象导入后可能退化成静态数据或图片，必须保留的不支持元素按下文交付完整 Excel。
- **参数不确定时查 `--help` 或 `--print-schema`**，不要猜 schema。
- **不直接执行 `soffice` / `libreoffice` / `unoconv`**：转 PDF / PNG / CSV / xlsx 用 `python3 scripts/excel_lo_convert.py <文件> <格式> --outdir <目录>`（`--sheet` 选子表）；仅用户要求转换格式或预览时使用，基础校验不做渲染预览。

## 二、按运行环境和编辑对象交付

- **云电脑任务，以及本地电脑上的新建任务**：默认交飞书表格。本地产物完成后，运行 `lark-cli sheets +workbook-import --file <文件>`，无下述兼容性问题时只交返回的链接，不重复附带 xlsx。导入重试一次仍失败时，才改交本地文件并说明原因。“做个 Excel / 输出 .xlsx / 可下载的文件”不代表拒绝在线表格。
- **本地电脑上的编辑任务**：修改在线表就交在线链接，修改本地文件就交原文件路径，无需导入。不要把 Canvas 的 `token` 拼成在线链接。Canvas 打开时，不写回真实文件、不导出，交付时提醒用户自行保存；Python 就地编辑的结果已保存，无需再提醒用户保存。

**交付形式按用户的明确要求调整**：明确拒绝在线表格（“不要飞书表格”“不要在线链接”“给我 .csv 就行”）时交本地文件；编辑本地文件时，用户明确要在线表格 / 飞书链接，就导入后交在线表；明确说“两个都要”时两者都交；处理不支持元素时，也可按下文交完整 Excel 或双交。Canvas 打开时，先由用户保存，再导入已保存的真实文件；不得导出底层产物，也不得导入尚未保存修改的旧文件。

**导入后必须检查 `data.extra`**：有不支持元素提示时，即使 `ok=true` 也不能忽略。已确认导入或导出使用户要求保留的格式 / 功能发生变化时，同样按此分支处理，不以 `data.extra` 是否列出为条件。所有元素按同一原则判断：有能满足需求且改动合理的方案时尽量替代，不强制替换。选择替代时修改 Excel 副本再导入，检查新回执后用最终新链接交付；无法满足需求或不适合替代时，可交付包含本轮全部成果与原元素的完整 Excel，也可双交并说明在线版差异。不得删除必需内容或从有损在线版导出文件冒充完整 Excel；读取导入回执并处理已知有损提示不属于第三节停做的默认校验。

**每轮修改后都要交付**：使用宿主提供的产物交付工具（当前为 `present_files`），按工具说明传入 URL 或文件路径。以本轮调用成功、回执列出交付条目为准；只在回复中写 URL / 路径不算交付。**工具交付时不重复贴产物 URL**：产物 URL 只填工具参数，调用前后的回复文本（包括进度说明和最终回复）均不输出裸 URL 或 Markdown 超链接；用产物名称说明结果与必要提醒。用户说“返回链接”也通过产物卡片满足。宿主未提供该能力或调用明确报工具不存在时，在正文给出最终 URL / 路径。

分析、对比、排查等任务的结论，也要写进结果子表的摘要区或说明区，再交付产物。用户指定了文件名就沿用：工作簿标题去掉扩展名，附件名保留扩展名，`/` 换成 `-`。

## 三、只执行当前入口要求的校验

下表规定技能自动附加的检查，并替代其他文档中的默认门禁要求。表中的“停做”不适用于用户明确要求的校验。

默认不为校验导出改前快照。用户要求改前对比时，必须保留真实基准；编辑本地文件前的回滚备份也要保留。

| 校验动作 | 直接指定 | SKILL 自动分流 |
| --- | --- | --- |
| 完整自检 `lark_sheet_selfcheck.py` 及其自查清单 | 停做 | 停做 |
| Excel / CSV 门禁 `excel_formula_verify.py`、`excel_csv_verify.py`、`excel_artifact_verify.py` | 停做 | 停做 |
| 写后回读值、公式和样式 | 停做 | 只核对本轮改动 |
| `+formula-verify`（含 `--exit-on-error` / `--ai-only`）、整表重算与逐格比对 | 停做 | 停做，改用下文的公式样本核对 |
| 图表验收 `lark_chart_quality_check.py`、缩略图视觉质检 | 停做 | 停做，只核对本轮对象 |
| 交付前逐项验收清单 | 停做 | 只核对本轮目标结构与关键结果 |

**自动分流时，在所有写入和导入完成后、交付前做一轮基础校验**：

1. **检查最终交付的产物**：在线表和 Canvas 直接通过 CLI 回读；Canvas 使用原 `token`，不导出。本地文件保存后，用 openpyxl / csv 重新打开检查，不只检查保存前的内存数据。本地文件导入在线交付时，只检查导入后的在线表，不重复检查中间文件。
2. **用一组样本覆盖本轮改动**：核对子表、区域、表头和记录数。少量单元格直接读全；批量写入优先选首、中、末及关键汇总格，覆盖受影响子表和不同处理规则，并复用这些样本检查值、类型、公式引用和样式。关联任务关注匹配、未匹配和重复键（若存在）；合并 / 汇总核记录数或总计；结构调整核记录对应关系与边界。期望值根据用户要求或源数据得出。CLI 使用 `+cells-get`，计算区域带 `--include formula`，涉及样式时合并为 `--include formula,style`；表级属性用 `+sheet-info`，相关读取尽量合并。
3. **复用样本核对公式与结果**：本轮有推导结果时，先用第 2 条样本确认各类计算均为引用源数据或公式辅助区的公式，覆盖明细与汇总，不能用静态数值代替；原生透视等对象按第 4 条核对。再复用每类一条有计算值的样本，检查公式错误并独立复算，不重新抽样或回读。没有计算缓存、或结果尚未算出时，说明“公式文本已核，计算结果未验证”。基础校验不启动 LibreOffice（不跑重算门禁、不直接调 `soffice` 取值或渲染），也不轮询计算结果；不能把空缓存当作零值或验证通过。
4. **核对本轮创建或修改的对象**：按受影响子表合并读取对象列表，检查数量、类型、数据源范围和关键配置。最终操作已返回完整对象快照时直接复用，不只看 `ok`。图表核类别、系列和标题；透视核分组、聚合方式，并用源数据抽核一项汇总；条件格式核规则、范围和样本命中效果。不遍历历史对象，不启动整套质检。异步对象按对应 reference 的就绪条件处理，不把加载中当作失败或通过。

基础校验中，计算结果暂不可用时可以说明未验证后交付。若用户明确要求验证该结果，就必须实际核验；无法完成时，要说明这项要求尚未完成。其他校验缺失或差异按下一节处理。直接指定入口不自动执行上述基础校验，只做用户要求的校验。

## 四、处理执行错误，保留正确性约束

必要的数据读取、子表定位、工具错误处理、写入与交付回执确认，以及 high-risk 命令的授权和 `--yes` 确认，都要照常执行。省略额外校验不代表可以忽略执行失败。

- **自动分流**：遇到执行错误或校验差异，先局部修复一次，只复核受影响部分。仍失败、无法完成必要回读，或任务超出 `SKILL.md` 的适用条件时，转标准模式。
- **直接指定**：执行错误修复一次后仍失败，就说明未完成部分，不额外启动标准模式的校验。用户要求的校验不能因此省略，也不能在未完成时声称完成。

转入标准模式后，读取相关流程与 reference，恢复对应校验，本轮不再切回速度优先。复用已取得的数据和成功结果，不重复创建产物或写入。需要改前基准时，只使用真实的原始文件 / 快照；没有基准就说明无法对比，不能把修改后的表当作改前快照。

**以下正确性要求始终有效**：

- **保留原表**：用户未要求删除或覆盖时，不删原子表、不丢原始行列，结果写入指定目标或空白新区域。先锁定目标 sheet、坐标与允许改动的属性，编辑已有工作簿时在源工作簿上改；补值不重刷原格式，美化不清理原文本或改写公式。非连续目标按坐标提交，不把保留格填成空串 / null；新区域或用户要求复制格式时才继承模板。
- **正确处理结构与关联**：排序移动完整记录，删除记录用行列操作，不用读值后重写来模拟。跨表取数和条件清空先明确相等 / 包含、允许的归一化及重复键处置，不擅自 trim、删版本后缀或取第一条覆盖冲突；计数区分明细行数与唯一对象数。
- **计算结果写公式**：能由源数据推导的值，用引用源单元格的公式表达，不写成静态数值；空值、无效输入与明确例外先分支处理。飞书公式不 spill，整列计算用 `ARRAYFORMULA` 包住整个表达式，或在内容与样式都可被模板覆盖时用首行公式 + `--copy-to-range`；已有逐格样式需保持时用不带样式字段的 `+cells-set --writes`。
- **按语义设置类型**：金额、百分比、计数、参与运算的真日期写数值；编号、前导零、身份证、电话、单据号读写都用文本，pandas 读取时注意 `NA`、`NULL` 等字样的 ID 会被默认缺失值识别读成 `NaN`，`keep_default_na=False` 则会让其他列的空单元格变成 `''`，需在写回前进行抽查， 与源表保持一致。
- **完成用户要求的全部内容**：数量、字段、子表名和文件名都按用户要求落实到产物中；点名的辅助列先写表头与公式，再做标色，指定表内的说明不能只留在回复。

## 五、保留环境兼容必读，其余文档按需查

按第一节读取适用的 `references/ref-local-compat.md` / `references/ref-windows-compat.md`。其他 reference 不强制预读：

- **命令参数**：用 `lark-cli sheets +<命令> --help` 查看 flag。
- **基础样式**：只用于新建区域或用户要求美化的范围。标题行加粗，表头底色配白字，数值右对齐并带千分位，列宽按内容设置；其他区域保持原样。
- **Excel 引擎**：常规 openpyxl 用法直接使用，报错后再查。

处置 `data.extra` 的不支持提示、需要查替代方案时，可读 `references/lark-sheets-workbook.md` 的替代示例及相关 reference。`--help` / `--print-schema` 仍无法解决参数或操作语义疑问时，再读对应 reference，不必先试错。本模式适用时，查阅业务 reference 不增加第三节之外的默认校验；按入口纠正误入或按第四节升级后，执行标准流程。文档仍须读到末行“全文完”标记。
