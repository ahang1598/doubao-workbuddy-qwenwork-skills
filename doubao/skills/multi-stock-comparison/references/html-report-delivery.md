# 多股票比较的HTML 报告交付规范

本文件只规定多股票比较的交付路由、信息结构和组件选择。HTML 生成命令以本包 `scripts/render_html_report.py` 为准。

需要任何图表或图解时，同时读取 `advanced-html-visuals.md`，逐图选择富表格、HTML 图表组件、SVG/Mermaid SVG 图示 或段落；不要先决定“做几张图”再寻找内容填充。

## 1. 先设置 delivery_mode

在检索、分析、起草或图表生成前，先选择 `TEXT` 或 `HTML_REPORT`，写入交付清单并运行 `scripts/delivery_gate.py --phase plan`。只有单一事实、同口径指标或单一决策问题能用一至三段短文无损回答，且不需要表格、结构化比较、多章节导航、图示或高级组件时，使用 `TEXT`；否则使用 `HTML_REPORT`。研究中条件失效时升级为 `HTML_REPORT`。

三家以上比较、两家公司多维比较、财报/估值比较、股价行为、组合适配、配对交易、完整报告、可复核引用和可分享交付物默认使用 `HTML_REPORT`。报告骨架、金融快照和视觉计划仍按本技能原有质量标准执行。

## 2. HTML 生成前的校验

完成事实校验和内容准入后，用 Markdown 起草读者版正文。交互图表文件以独立一行 `{{embed:相对路径.html}}` 嵌入；SVG/PNG 图示用 Markdown 图片语法嵌入。运行 `scripts/render_html_report.py` 生成自包含的单文件 HTML。生成后确认 HTML 文件完整，并核对正文、表格、引用和图表嵌入。浏览器预览可按需进行，不作为交付条件。

## 3. 专业研究文档的信息顺序

默认按读者决策顺序组织，不套固定的“公司简介—行业—财务”模板。核心财务金融快照是股票比较的默认底座；其他部分按相关性保留：

1. **标题与比较元信息**：全部证券名称/代码、市场、信息截止日、比较期间、币种、会计、业务层级和价格口径；
2. **选择结论**：先回答本质差异、什么情景下谁更优，以及不能排名的边界；
3. **核心财务金融快照**：一张紧凑横向表，默认覆盖市场数据、估值和至少两个经营财务类别；不相关时必须有质量清单记录；
4. **胜负驱动**：通常 3–5 条，按改变选择的重要性排序，并指出分别偏向哪家公司；
5. **增量横向矩阵**：只放核心快照未覆盖、但当前问题需要的 KPI、情景或事件数据；不可比项显式标注；
6. **差异机制**：只展开用户问题需要的大盘/板块/外围、供应链与新闻监管、市场位置、商业模式、经营财务、成长、预期、估值或价格行为；
7. **最强反例与翻转条件**：说明什么证据会改变相对排序；
8. **验证点/催化剂**：写清公司、指标、阈值、时间窗和数据来源；
9. **数据来源与方法**：读者可复核即可，证据账本和冗长细节放附录；
10. **免责声明**：完整研究最后保留规定文本。

核心结论必须出现在正文最前部。默认 `standard` 最多 8 个分析章节，但上限不是配额；证据链较少时主动缩短。若使用高亮块，全文通常只把这一处作为唯一重强调；若核心判断不确定，明确写出会限制结论的数据缺口或条件，不用颜色制造虚假的确定感。

## 4. 组件选择矩阵

由信息关系选择组件，不按“每篇都要有”的配额选择。

每个组件还必须通过内容准入测试：若删除后不影响判断或理解，若内容已由其他表格/段落表达，或证据质量不足，就删除该组件。高级样式不是内容质量的替代品。

| 研究内容 | 首选表达 | 适用边界 |
|---|---|---|
| 选择结论、重大不可比提醒、关键数据缺口 | 高亮块 | 仅强提醒；通常 0–1 个，避免每节一个 |
| 公司 A vs B、胜出理由 vs 翻转条件、做多端 vs 对冲端 | 对比分栏 | 仅限两侧信息量接近的短对照；多家公司或多指标改用表格 |
| 默认核心财务金融快照 | 紧凑富表格 | 5–12 个行业适用指标；全部公司同列，日期、期间、币种、单位和口径完整 |
| 横向矩阵、KPI、财务、估值、情景、事件窗口 | 富表格 | 真正行列数据；公司为列或行为一致规则，统一期间、币种、单位和口径 |
| 大盘/板块/外围市场与公司表现 | 富表格或 `timeseries` HTML | 统一时区、交易窗口、币种和基准；只保留有传导关系的市场 |
| 差异因果链、供应链位置、盈利传导、配对交易逻辑 | SVG 图示 | 图示明显比段落更清楚；精确数字回表格，图旁保留比较结论 |
| 公司/供应链/监管新闻 | 时间线表或 `timeline` SVG SVG 图示 | 两项以上且时序/阶段关系重要；区分发生、发布、生效与可交易时间 |
| 同业定位、候选优先级、风险或组合暴露 | `quadrant` SVG SVG 图示 | 两个维度、刻度和分割阈值必须可解释；不代替原始数据表 |
| 完整 OHLC、成交量、事件标记和价格路径 | K 线 HTML 图表组件| 股价分析的默认主视觉；必须有同口径 OHLC，跨公司统一窗口、频率与复权定义 |
| 相对收益、预期修正、A/H 历史路径 | `timeseries` HTML 图表组件| 路径比端点重要；基期、对齐方法和缺失交易日必须说明 |
| 估值敏感性、板块强弱或暴露矩阵 | `heatmap` HTML 图表组件| 网格足够密且同口径；保留精确数值、色阶中心和不可行区域 |
| 利润率、现金流、量价或指引桥接 | `waterfall` SVG SVG 图示 | 桥接项可复算、起终点一致；不要与相同信息的表图重复 |
| A/H 折溢价、历史区间与事件 | 同步表 + `timeseries` HTML | 同步价格/汇率/股份权利；执行障碍必须与价差同屏呈现 |
| 公式与关键假设 | 公式或简洁段落 | 展示可复算的关键公式，不把整篇写成方法论文 |
| 叙述、机制、判断与解释 | 连贯段落 | 默认表达；不要机械拆成 bullet 或卡片 |
| 来源、公告、监管文件 | 可点击引用/来源列表 | 来源紧随事实，并保留发布日期和截止日 |

### 高亮块

适合放“结论 + 关键条件 + 最大风险”的短摘要，不要把完整正文塞入。颜色保持语义一致：信息用中性/蓝色，风险用红色，待确认用黄色；不要用绿色或红色暗示无条件买卖建议。

### 对比分栏

适合以下短对照：

- 公司 A 的优势 vs 公司 B 的优势；
- 当前胜出理由 vs 会翻转排序的条件；
- 配对交易做多端逻辑 vs 做空/对冲端逻辑。

若每侧超过少量要点、需要跨行比较或含多期数值，改用表格。分栏不能替代三情景估值表。

### 表格

一张表只回答一个问题。表头写明期间，标题或注释写明币种、单位、是否复权、FY/CY/TTM、法定/调整后。重要变化优先展示绝对值与同比/环比，避免只用颜色表达涨跌。典型表格包括：

- 默认核心财务金融快照：市场数据、估值及至少两个经营财务类别；
- 用户问题需要、但核心快照尚未覆盖的增量 KPI；
- 市场位置、经营、财务质量、增长和估值比较；
- 各公司 Bull/Base/Bear 情景、关键假设、估值结果与相对排序；
- 催化剂/风险的公司归属、时间、影响路径与验证指标；
- 同窗口股价事件反应、相对表现和缺失交易日说明。
- 大盘、板块、外围市场及公司相对收益的传导证据；
- A/H 同步价格、汇率、折溢价、成本假设、执行门禁与历史位置。

### Whiteboard

优先用于结构关系，而不是精确数字表。多股票比较中的高价值场景包括：

- 同一行业变量如何通过不同商业模式传导到各公司的量价、利润率、现金流、预期与估值；
- 各公司在供应链、价值链、客户、产品和利润池中的不同位置；
- 相对投资论点的证据树、排序翻转条件和证伪路径；
- 配对交易的共同因子、差异因子和风险传播链；
- 国际或监管事件如何沿地区、供应链节点和公司暴露传导；
- 同业、候选或风险项目在两个清晰维度上的象限定位；点大小只能承载已说明口径的第三变量。

图中只放理解结构所需的信息，精确数字回到正文表格。以 Markdown 图片语法引用 SVG，生成完整 HTML 后确认图片已嵌入；空白图示不算完成。

格式选择遵从本包 `scripts/render_html_report.py` 的责任边界：象限、瀑布、金融事件时间线、供应链/传导/风险网络等自定义金融图优先 SVG；天然属于思维导图、时序、类图、饼图或甘特图时才考虑 Mermaid。SVG 使用完整 `viewBox` 与 `<text>`，不得引用外部资源；不要用一张巨大画板同时承载多个独立问题。

### HTML 图表组件

股价分析默认使用带悬停明细和事件标记的 K 线；其他 HTML 图表组件仅当时间路径、密集矩阵、悬停明细或多序列联动确有实质价值时使用，例如 `timeseries` 相对表现/预期/AH 历史路径或 `heatmap` 估值敏感性/板块矩阵。遵守本包 `scripts/render_html_report.py` 对单文件、尺寸、资源和运行时的限制，并满足：

- HTML 图表组件前后各有一段文本，说明它回答的问题和读者应看到的结论；
- 关键结论不能只存在于交互组件内；
- 不内联大体积数据或图片，不把同一张表再做一遍 HTML；
- K 线只使用完整、严格升序、同一复权口径的 OHLC；只有收盘价时改用折线图；跨公司比较必须统一窗口、频率、复权与时区说明；
- 归一化相对收益必须写明共同基期、基准值、汇率和非共同交易日处理，不能把起点选择当作稳健结论；
- A/H 图必须同时显示价差定义、价格/汇率时间戳和执行限制，不能把历史均值线包装成必然回归；
- 除股价分析默认 K 线外，若静态表格足够，优先表格。
- 禁止把多个低相关图塞进单个 HTML Dashboard 规避图表预算；一个 HTML 图表组件只承担一个主要信息任务。

## 5. 按任务组合，而非固定模板

- **比较一页纸/会前准备**：选择结论 + 紧凑核心财务金融快照 + 估值/风险短段；除涉及股价分析时默认使用 K 线外，通常不需要 HTML 图表组件。
- **全面股票对比**：选择结论 + 核心财务金融快照 + 胜负驱动 + 必要机制章节 + 情景/风险；按领域扫描加入真正影响结论的大盘/板块、供应链、新闻监管、外围和 A/H 信息。默认最多三个视觉家族，不以载体增加图表配额。
- **财报比较**：选择结论 + 核心财务金融快照 + 各公司实际值/预期值/差异表 + 指引和盈利变化机制；仅在多期趋势复杂时加图。
- **投资二选一**：高亮选择结论 + 核心财务金融快照 + A/B 短分栏 + 翻转条件；不能排名时明确分情景结论。
- **估值比较**：相对估值与反向 DCF 表为主；二维可复算敏感性用 `heatmap` HTML，透明双维定位用 `quadrant` SVG，二者不因“完整”自动同时出现。
- **股价与事件比较**：默认使用同窗口 K 线 HTML + 相对表现/事件反应表；只有质量清单记录了允许的不适用原因时省略 K 线。
- **大盘/板块/外围复盘**：市场状态短表 + `外围变量 → 板块/供应链 → 公司` 传导结论；跨市场曲线只在交易时区、币种和基期可对齐时使用。
- **供应链/国际/监管事件**：存在多节点分叉时用供应链 SVG，存在两项以上关键阶段时用 `timeline` SVG，否则使用段落/表格；新闻摘要不能替代传导分析。
- **同业定位**：统一口径比较表是主证据；只有双轴确实回答决策问题时，再加多象限 SVG。
- **组合适配/配对交易**：共同因子、差异因子、相关性、流动性和压力测试表 + 暴露/风险传播图；缺少组合输入时明确限制。
- **A/H 或 H 股相对价值**：同步价差表 + 历史折溢价 HTML 图 + 执行条件/成本/风险表；未验证可转换、借券和交收时，标题与结论均不得使用“可执行套利”。

## 6. 生成与校验

1. 按 `core-financial-snapshot.md` 建立同口径快照，按 `writing-quality.md` 建立质量清单并通过 `editorial_gate.py --phase plan`；适用时运行 `audit_ledger.py`。
2. 只保留准入章节，完成读者版 Markdown；图表与 `visual_plan` 一一对应；依据自然语言视觉说明制作并嵌入正文，不指定必须使用的出图脚本。
3. 运行 `python3 scripts/render_html_report.py <读者版正文.md> --output <报告.html>`，确认最终 HTML 文件完整，核对核心结论、快照表、引用、图表嵌入和免责声明。
4. 删除不改变判断的句子、普通背景、新闻流水账和重复图表；修改后重新生成并核对文件。
5. 逐图完成最终验证，运行 `editorial_gate.py --phase final`。通过后在交付清单记录 `editorial_gate_passed=true`；有图表时核对与 `visual_plan` 一致，再运行 `delivery_gate.py --phase final`。
6. 两个门禁通过后，聊天中返回一至三句核心结论和 HTML 文件链接。

## 7. 最终交付门禁（必须执行）

最终回复前运行 `scripts/editorial_gate.py --phase final <quality-manifest.json>`，再运行 `scripts/delivery_gate.py --phase final <delivery-manifest.json>`。`HTML_REPORT` 必须记录 `html_created=true`、`html_path=<实际存在的完整 .html 文件>`、`file_verified=true`；`file_verified=true` 表示生成文件实际存在且包含完整 HTML 结构，无需浏览器检查。带图表时 `visual_family_ids` 与 `visual_plan` 一致，并逐图确认来源、单位、嵌入位置、结论和无重复。

若 HTML 生成或图表嵌入失败，保持未完成，修复后重新生成并核对文件。报告应保留原有内容准入、核心快照、风险、来源和免责声明标准。
