## 共同原则

先写清图形要回答的决策问题，再选择图形。图表不扩大研究范围，也不替代事实校验。

- 每张图只回答一个主要问题，并在图前用一句话说明“为什么看这张图”；
- 图后用一至三句写出观察结果、反证和限制，关键结论不能只存在于图内；
- 标明证券、期间、信息截止日、币种、单位、复权/会计口径和来源；
- 颜色承载稳定语义，不作为唯一编码；涨跌配色应与市场惯例一致并显示图例；
- 图形精度不得高于数据精度。作者打分、标准化值和模型输出必须明示方法；
- 表格更清楚时用表格，段落更清楚时用段落。不要为了“高级”重复同一信息。
- 图形必须进入质量清单的 `visual_plan`，说明决策相关性、新信息、读者结论和为什么优于文字/表格；无法通过 `writing-quality.md` 内容准入测试时不生成。

使用生成器前运行：

```bash
python3 "$MULTI_STOCK_COMPARISON_SKILL_DIR/scripts/lark_visuals.py" --self-test
```

## 先选信息关系再选格式

逐图执行以下判断，不按“报告里应该有几类图”的模板装配：

1. **精确查值、字段对齐或少量离散情景**：使用飞书富表格。读者主要任务是查数和逐行比较时，不要升级为图。
2. **时间路径、密集矩阵、悬停明细或多序列联动**：优先 HTML block。交互能减少正文或标签拥挤时才有价值。
3. **因果、桥接、位置、阶段、网络或分叉关系**：优先 SVG whiteboard；思维导图、时序、类图、饼图、甘特图等天然适合 Mermaid 时才用 Mermaid。
4. **一段话能清楚说明的简单线性关系**：使用段落，不画图。

| 决策问题 | 默认表达 | 不应使用的情况 |
|---|---|---|
| 完整 OHLC、量价与事件路径 | `kline` HTML | OHLC 不完整；详见 K 线例外 |
| 公司—板块—大盘、外围市场、预期或 A/H 历史路径 | `timeseries` HTML | 只有一个时点、日期无法对齐或端点表已足够 |
| 估值敏感性、板块强弱、风险暴露矩阵 | `heatmap` HTML | 网格稀疏、口径混杂或颜色只是装饰 |
| 两个透明维度下的同业/风险定位 | `quadrant` SVG | 轴由神秘综合分数构成或边界无法解释 |
| 量价结构、利润率、现金流、指引修正桥 | `waterfall` SVG | 桥接项不可复算或起终点不一致 |
| 公司、监管、供应链与国际事件阶段 | `timeline` SVG | 只有一项事件，或字段表更便于核对 |
| 供应链位置、外围传导、风险传播、证据树 | 自定义 SVG whiteboard | 关系简单、连接无证据或精确数字被塞进图内 |
| 少量可比指标、事件字段、情景数值 | 富表格 | 不要为了样式改造成 HTML/SVG |

HTML block 必须是完整单文件、宽度自适应、无外部脚本/字体/图片依赖，并包含用途明确的 `meta description`。SVG 必须完整自包含、含 `viewBox`，使用 `<text>` 保留文字，避免画板不支持的 `pattern`、`clipPath`、`mask` 和非阴影复杂 `filter`。实际标签、文件引用、画板责任边界和渲染流程以写入时线上最新版 `lark-doc` 为准。

## 图表预算与逐图准入

图表预算按“视觉家族”计算：同窗口的多家公司 K 线算一个家族；一张图的桌面/移动版本不重复计数。默认上限为：

| 文档档位 | 默认视觉家族上限 |
|---|---:|
| `one_pager` | 1 |
| `standard` | 3 |
| `deep_dive` | 5 |

上限不是配额。没有高质量图表时可以为 0；超过上限必须在质量清单提供不可压缩的 `visual_budget_reason`，不能用“内容丰富”或“更美观”解释。

每个候选图都写入 `visual_plan`：

- `include=true` 时必须填写唯一 `id`、`chart_type`、`format`、`information_job`、`decision_relevance`、`reader_takeaway`、`why_visual_beats_text_or_table`、`evidence_ids` 和 `redundancy_group`；
- 同一 `redundancy_group` 只能保留一个视觉家族。例如 K 线已经回答价格路径时，相同窗口的装饰性折线图必须排除；
- `include=false` 时记录 `exclusion_reason`，让“想过但删掉”可审计；
- 最终阶段逐图设置 `rendering_verified`、`source_and_units_verified`、`text_summary_present` 为 `true`；
- 图前一句说明读图目的，图后一至三句只写最重要观察、反例和限制，不复述全部数据。

## K 线 HTML block

### 何时使用

只要选择 `capability-price-behavior.md`，K 线就是默认价格主视觉。它用于让读者直接核对价格路径、波动聚集、跳空、影线、量价和事件窗口，而不是依赖区间端点概括。下列场景尤其重要：

- 比较公司在同类事件前后的跳空、盘中振幅、长上下影或波动聚集；
- 量价形态差异会改变相对价格行为判断；
- 财报、公告或监管事件前后的交易路径需要逐家公司复核；
- 用户明确要求 K 线或交易路径比较。

未选择股价分析能力的报告，仍只在 K 线会增加决策信息时使用。K 线不是技术分析结论，不能凭形态直接推导未来涨跌。

### 可审计的不适用条件

`price_analysis=true` 时，只有下列实质性条件可把 `kline_plan.status` 设为 `not_applicable`：

| `reason_code` | 适用事实 |
|---|---|
| `missing_complete_ohlc` | 只有收盘价或 OHLC 字段不完整，且无法从可靠来源补齐 |
| `no_continuous_trading_series` | 标的停牌、未上市、退市或工具性质导致没有连续可比较交易序列 |
| `universe_too_large_for_readable_kline` | 全部标的逐只展示会失去可读性；应优先保留焦点子集 K 线，并说明选取依据 |
| `incompatible_windows_or_frequency` | 经过合理对齐仍无法形成可比窗口或频率，例如上市时间错位严重 |
| `user_explicitly_declined` | 用户明确不要 K 线或不要飞书高级组件 |
| `single_price_point_only` | 问题只核对单一时点价格/估值输入，不分析价格路径、涨跌或事件反应 |
| `other_material_reason` | 其他会使 K 线失真、误导或无法可靠生成的重大理由，必须具体说明 |

篇幅、制作成本、已有收益表/折线图、追求版面简洁或作者主观认为“不重要”均不是有效例外。若只有部分标的不适用，应为可用且决策相关的标的生成 K 线，并在 `coverage` 中说明范围，不能把局部缺失扩大成全部省略。

### 数据门禁

每根 K 线必须具备同一证券、交易时区和复权口径下的 `date/open/high/low/close`。检查高价不低于开盘、收盘和低价，低价不高于三者；交易日严格升序且不重复。成交量、事件标记可选。

必须写明：

- 每家公司的起止交易日、市场和证券代码；
- 币种以及不复权/前复权/后复权/总回报口径；
- 日线、周线或其他频率；
- 数据来源与查询截止日。

只有收盘价时不得用相邻收盘价猜测开高低；改用折线图。

### 生成与装配

按 `script-usage.md` 为决策相关公司分别准备 `kline.json` 并运行 `lark_visuals.py kline`。生成器每只证券产出一个单文件 HTML，包含：

- 响应式 K 线与成交量；
- 悬停显示交易日、OHLC、成交量和事件；
- 区间涨跌、最高、最低和最新收盘摘要；
- A/港股常用红涨绿跌与全球常用绿涨红跌两套显式图例。

在文档中按以下顺序装配：

1. 图前结论句：说明观察窗口和读图目的；
2. HTML block：按线上最新版 `lark-doc` 扩展块流程写入生成的 `.html`；
3. 图后解释：指出公司间路径差异、共同市场因素、事件一致性与不能确认的归因；
4. 同窗口事件表：提供各公司及基准的可复算数值，不让读者只能目测图形。

多标的装配规则：

- 2–4 只决策相关标的逐只展示，统一窗口、频率、时区、复权、图形尺寸和颜色语义，并作为一个成组视觉连续放置；
- 超过 4 只时，用统一基期相对收益图或表覆盖全样本，再为焦点标的或决策相关代表性子集展示 K 线；说明子集选择，不用多个异质窗口制造视觉排名；
- 不强制所有证券共用同一价格纵轴，因为绝对价位差异可能压平波动；应保持尺寸与口径一致，并用区间收益、振幅或基准相对表现补足可比性；
- 同组 K 线已经回答价格路径后，不再添加内容重复的装饰性价格图。

## 多象限 SVG

### 何时使用

象限图适合展示对象在两个决策维度上的位置关系，例如：

- 同业：估值吸引力 × 盈利确定性；
- 候选：基本面改善 × 预期差；
- 风险：影响程度 × 发生可见性；
- 组合：持仓权重 × 流动性压力；
- 业务：市场吸引力 × 竞争位置。

不适合用象限图展示强时间序列、超过两个核心维度的综合结论，或把多个不可比指标压成一个神秘分数。

### 轴与编码门禁

- 明确定义横轴、纵轴、方向、单位、范围和分割阈值；
- 轴可以是原始指标、透明标准化值或有方法说明的评分；
- 分割阈值来自业务门槛、样本中位数、历史分位数或明确假设，不能只为让点分散；
- 点大小只承载一个已说明的第三变量，如市值、持仓权重或收入；
- 颜色只区分行业、业务组或风险类型，不同时承担好坏含义；
- 距离接近时不要声称显著排名差异，象限边界附近的点应视为敏感项。

### 生成与装配

按 `script-usage.md` 准备 `quadrant.json` 并运行 `lark_visuals.py quadrant`。生成器产出自包含、可导入画板的 SVG，包含四象限底色、双轴、分割线、气泡大小和分组图例。

SVG 不使用 `clipPath`、`mask`、`pattern`、外部图片、远程字体或脚本。按线上最新版 `lark-doc`/`lark-whiteboard` 责任边界执行 SVG 插入与渲染检查；本技能中的示意不能覆盖线上流程。

文档中同时保留原始数据表或方法附注。象限图负责“位置关系”，表格负责“精确数值”。图后指出右上/左上等区域的投资含义、边界点和最强反例，但不自动把右上象限等同于买入。

## 其他 HTML 与 SVG 视觉

以下为补充路由；可由 `lark_visuals.py` 直接生成的类型优先使用脚本，以减少临时图表代码和渲染差异。

| 问题 | 合适形式/命令 | 关键门禁 |
|---|---|---|
| WACC × 永续增长、价格 × 盈利等二维敏感性 | `heatmap` HTML | 展示基准格、单位、色阶中心和不可行区域 |
| 收入到利润、利润到现金流、旧指引到新指引 | `waterfall` SVG | 桥接项可复算且起终点一致 |
| 多家公司归一化相对收益 | `timeseries` HTML | 统一共同基期、汇率、基准值和非共同交易日处理 |
| 大盘—板块—公司相对表现 | `timeseries` HTML | 指数定义、交易时区和本地/统一币种回报必须明确 |
| 概念/行业板块强弱与估值 | `heatmap` HTML | 概念归属可验证，颜色不能替代数值和图例 |
| 股价与盈利预期/估值倍数联动 | 双轴 HTML 图 | 各公司期间必须对齐，两轴不能暗示虚假因果 |
| 同一行业变量到各公司盈利与估值的差异传导 | SVG whiteboard | 分叉机制明确，精确数字回到表格 |
| 企业供应链位置与风险节点 | SVG whiteboard | 标明上下游、地区、替代周期和缓释措施，不补造关系 |
| 公司新闻、国际事件和监管里程碑 | `timeline` SVG | 区分发生、首次发布、生效/执法和可交易时间 |
| 美股/日韩到目标公司的事件传导 | `timeline`/自定义 SVG | 先处理时差和共同因子，不把相关性当因果 |
| A/H 折溢价历史与催化剂 | `timeseries` HTML | 同一公式、同步汇率/复权；图旁展示执行障碍和成本 |
| 组合暴露和风险传播 | SVG 网络/路径图 | 边表示的关系必须定义，不把相关性写成因果 |

同一章节通常保留一个主视觉家族。确需多个时，必须拥有不同 `redundancy_group` 并分别回答不同问题；不把 K 线、折线、热力图和象限图堆在一起制造“仪表盘感”。

## 文档装配与校验

写入前按 `lark-doc-delivery.md` 的线上校验门禁重新读取最新版 `lark-doc`。写入后完成以下检查：

1. **数据**：证券、指数/概念定义、日期与时区、频率、复权、币种、单位、来源和截止日完整；A/H 图同时核对股份经济权利和汇率时间戳；
2. **语义**：标题和轴能独立解释，颜色、大小、分组有图例；
3. **渲染**：HTML 无外部依赖、无横向溢出，悬停和响应式尺寸正常；SVG 在画板中无裁切、乱码或严重标签碰撞；
4. **一致性**：图中数字与正文、横向表、证据账本一致；涨跌色与图例一致；
5. **可访问性**：不依赖颜色区分唯一信息，图前后文本足以让无法交互的读者理解结论；
6. **克制**：删除不改变判断的装饰、重复指标和无解释的图形；图前后文字不重复图中全部信息，只解释最重要观察和边界；
7. **强制飞书交付**：只要生成过本文件涉及的 HTML、SVG、whiteboard 或其他非 Markdown 视觉，`delivery_mode` 必须是 `LARK_DOC`，并将其实际写入飞书文档后拉取复核；聊天只摘要核心结论并给飞书文档链接。不得直接发送图表文件、预览图、源码、本地路径或下载链接。写入受阻时按 `lark-doc-delivery.md` 的最终交付门禁处理，不得降级为直接输出。
8. **K 线闭环**：`price_analysis=true` 时，检查 `kline_plan` 为 `included` 或有允许原因的 `not_applicable`；若已包含，逐个确认实际渲染、覆盖范围以及窗口/频率/复权一致性。
9. **逐图闭环**：将最终保留图与 `visual_plan` 一一核对；没有登记、超过预算无理由、与其他图重复、渲染未验证或缺少文字结论的图均不得交付。
