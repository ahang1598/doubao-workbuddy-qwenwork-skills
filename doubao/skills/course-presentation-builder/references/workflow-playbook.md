# Workflow Playbook

## Scenario Diagnosis
1. Identify the artifact type requested by the user.
2. Extract facts: who, what, when, where, why, constraints, audience, tone, source materials.
3. Mark missing facts as `待确认` instead of inventing them.
4. Choose the output template and execute the corresponding path.

## Draft Diagnosis Path
Use this when the user provides a draft, notes, or a rough outline.

1. Diagnose the draft before rewriting: mark `流水账`, `概念混用`, `证据强度混淆`, `相关当因果`, `结论先行但证据不足`, and `页面超载`.
2. Convert the diagnosis into a repair plan: what to merge, split, delete, visualize, or move to appendix.
3. In the final page plan, state which slide fixes each diagnosed issue.

## Actual PPT Path
The comparison report showed that a text-only package is often less useful than a usable deck.

1. If the user asks for "PPT", "幻灯片", "可直接展示", or a course deliverable, ask only if ambiguous; otherwise plan for an actual PPT or a slide-generation handoff after the text package.
2. Keep a complete slide table with `页码`, `模块`, `标题`, `时长`, `页面要点`, `图表/版式建议`, `硬性要求落点`, `讲稿要点`.
3. If a slide tool is available in the environment, use it after the structure is stable. If not, provide a table that can be imported into a slide builder without rethinking the content.
4. Do not let the fixed output contract suppress depth. For literature comparison, use as many dimensions as the task requires; 12-16 dimensions is acceptable when the grading criteria demand it.

## Templates

### One-Page Plan
- 背景：一句话说明任务和目标。
- 关键信息：对象、时间、地点、负责人、来源。
- 行动方案：3-6 个步骤，每步有产物或验收方式。
- 风险与待确认：只列真实影响执行的内容。

### Script or Copy
- 开头：明确身份、场景和目的。
- 主体：2-3 个证据点或利益点。
- 结尾：行动号召、确认方式或后续安排。

### Checklist/Table
Columns should usually include: item, owner, deadline, source/evidence, status, note.

## Domain-Specific Outputs
- PPT 结构
- 逐页标题与正文
- 演讲稿
- 答辩问题
- 素材缺口清单

## Quality Standard
A strong output is specific enough to use today, but honest about missing facts. It should reduce the user's next action to editing, confirming, or sending.
