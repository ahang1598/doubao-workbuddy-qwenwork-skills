# 任务路由：意图识别 + 市场识别

## 一、意图识别（单条深度解读 vs 批量监控摘要）

先判断用户想要哪种交付，判断依据主要看用户给的"锚点"是什么：

| 用户给的锚点 | 判定为 | 示例 |
|---|---|---|
| 具体的一条或几条公告（给了标题/事项/公告编号/链接，或明确的一次性事件） | 单条深度解读 | "解读一下宁德时代这份关联交易公告""帮我看看这份 8-K 讲了什么" |
| 公司 + 时间段，没有指向具体某条公告 | 批量监控摘要 | "帮我看看腾讯最近一周有哪些重要公告""这家公司这个月发了哪些公告" |
| 公司 + 某个大类但不确定具体是哪条（如"最近有没有增持"） | 先按批量模式检索该大类，找到后再视信息量决定是否升级为单条深度解读 | "台积电最近有没有回购动作" |
| 用户没说清楚，且公司/时间都模糊 | 先反问确认公司、市场、时间窗口、关注类型，不要猜测着做 | — |

两种模式不是互斥的：批量监控摘要中如果某一条公告信息量特别大（如重大并购、控制权变化），可以在摘要合集里对这一条做加长处理，形成"重点摘要 + 深度小节"的混合结构，但要在交付时明确告知用户做了这个升级。

## 二、市场识别

### 2.1 判断依据

- 用户直接给了交易所代码后缀（`.SH`/`.SZ`/`.BJ` → A股；`.HK` → 港股；无后缀但给了 ticker 且能查到在 NYSE/NASDAQ 挂牌 → 美股），直接采信。
- 只给了公司中文名/英文名，没给代码：先用 `general_search` 或 `seed_finance_search` 确认该公司的主要上市地。
- **同名/同一集团多地上市（A+H、ADR）**：不要默认只处理一个市场。先确认用户关注的是哪个上市主体（有的公告只在其中一个市场披露，如 A+H 公司的股东大会公告两地都发，但某些两地存在时间差或内容差异的情形要在解读里指出）。用户没指定时，优先按用户提到的具体市场线索判断；仍无法判断则反问。
- 港股/美股上市的中国内地公司，要留意"注册地在境外、主要业务在境内"的红筹/VIE 架构对信息披露路径的影响（如是否同时受两地监管）。

### 2.2 市场 → 分类体系的对应

确认市场后，跳到 `markets-taxonomy.md` 里对应市场的分类表，定位公告属于哪个大类；跨市场共性维度对照也在该文件里，用于快速把"陌生市场的公告类型"映射到你熟悉的概念上。

## 三、锁定标的与基准时间

- 用系统时间确定"当前"基准，批量监控模式要明确交付里覆盖的时间窗口起止日期，不要含糊说"最近"。
- 公司名称可能与同名公司混淆（不同市场、不同行业），锁定时要核对股票代码、交易所、主营业务，避免张冠李戴。
- 用户给的是集团层面的名字但实际有多个上市主体（如控股公司+子公司分拆上市）时，先确认具体指向哪个主体。
