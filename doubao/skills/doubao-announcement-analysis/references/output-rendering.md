# 呈现渲染：正文、表格、图表与对话摘要

## 一、交付形态

完整内容在结构化 report.json 中写一次，由固定模板直接生成自包含 HTML。对话框只返回固定风险提示、2–5 条重要结论和 HTML 报告链接，不粘贴完整报告。report.json 的字段见 report-schema.md，执行顺序见 delivery-pipeline.md。

## 二、表格和图表

成行成列的精确数字优先用表格。趋势、占比或事件与价格的时间对应关系需要图表时，在 report.json 的 chart block 写入已核验数据，交由 HTML 模板绘制响应式 SVG。少于三个数据点或数据不足时不用图表。不要先制作大 PNG 后再贴进正文，也不要让图像生成模型猜测精确数值。

每张图表要回答一个明确问题，包含中文图题、市场、坐标轴单位、图例、来源与口径。混合单位拆成多张图，不用双轴图掩盖量纲差异。图题和来源作为 HTML 图注与图表一起排版。图表宽度由报告版心决定，不由画布像素决定。

## 三、股价与事件

先按 linked-signals.md 的量化标准检查股价是否明显异动。没有明显异动，在 price_reaction 章节用简短段落说明，status 设为 normal。有明显异动，status 设为 abnormal，并提供带事件标记的价格图；每个事件必须有日期位置、所属市场、事实引用。事件发生、公告披露、市场可交易的时间不能混写。A 股事件叠加在 H 股价格上时要解释跨市场关系，不能仅凭同日反弹推断因果。

## 四、版式和复核

固定模板负责 HTML、图注、表格、来源清单、免责声明和移动端样式。交付前打开 HTML，核对：

- 图表数值、事件位置和市场口径。
- 表格列宽、长链接、图表在桌面与移动端没有全页横向溢出。
- 图题、坐标、图例、来源和风险提示清晰可见。
- 对话摘要只保留重要结论，没有完整正文。

需要其它交付格式时，从同一份 report.json 生成，避免维护两份不同内容。
