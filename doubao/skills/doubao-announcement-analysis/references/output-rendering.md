# 呈现渲染：表格、图表与交付方式

只写文字不够，成行成列的数据要用表格，趋势/对比类数据要配图表；同时要给一份视觉呈现有质量的成品，不是把脚本原始输出直接甩给用户。**呈现（做出好看的图表/报告）和交付（这份成果怎么出现在用户面前）是两件事**，第零节先讲交付，避免"生成了但用户看不到/看不好"的情况。

## 零、部署场景与默认交付规则

本 Skill 部署在豆包等客户端环境里，**终端用户是通过客户端直接调用技能，不是和 agent 共享同一套文件系统**——这意味着"生成一个本地文件、给用户一个 `file://` 链接"这条路径在这个部署场景下没有意义（用户点了也打不开，那是服务端沙箱里的文件，不是用户本机文件）。据此，默认交付规则是：

- **不管用户是否指定输出格式，最终回复都是固定的三段式**：固定风险提示语 → display markdown 正文（含表格 + 直接嵌入的图表图片）→ 飞书文档链接。display markdown 怎么生成、飞书文档怎么创建，完整流程见 `references/delivery-pipeline.md`，本文档只讲"表格/图表本身怎么做"（第一到第三节）和"正文里的呈现规则/飞书文档创建细节"（第四到第六节）。
- **图片**：按系统规则直接用 Markdown 图片语法嵌入正文，不作为独立文件附件交付。
- **视频类产物**：本 Skill 不生成视频，不适用。
- **本地文件（如独立的 HTML 报告）**：**不是默认路径**，因为多数部署场景下用户拿不到、打不开。只有用户明确说清楚"我需要一个可以在我自己电脑上直接打开的 HTML 文件"且确认所在环境支持本地文件交付时，才按第六节的方式走这条路径；否则一律用飞书文档替代"完整版报告"的角色。
- 如果用户明确指定了别的格式要求（如"只要文字，不用生成飞书文档""帮我发一份纯 Markdown 就行"），按用户的具体要求处理，但固定风险提示语这一段永远保留，不因为用户要求"只要文字"就省略。

## 一、什么时候用表格、什么时候用图表

- **表格**：字段明确、逐项对比的数据——如历史几期业绩数字、多条股权变动记录明细、三市场分类对照。默认优先用表格呈现结构化数据，不要写成段落堆数字。
- **图表**：趋势变化、占比结构、时间线事件——这三类信息文字/表格不容易让人一眼看出形态，配图更有效：
  - **趋势变化**（如近几期营收/净利润走势、股价走势）→ 折线图。
  - **对比/占比**（如几家可比公司的某指标对比、交易金额占市值的比例）→ 柱状图。
  - **事件时间线**（如同一公司近期多条联动公告的发生顺序）→ 只是罗列几个事件先后顺序时，优先用表格（对少量事件反而比图更清楚）；但如果需要把**股价走势和多类型事件叠加**在一起看（`linked-signals.md` 第四节触发的"关联动态时间线"），必须用图（`event_timeline` 类型，见第三节），纯表格没法表现价格和事件的时间对应关系。
- **不要为了"美观"硬凑图表**：数据点少于 3 个、或数据本身没有明显趋势/对比意义时，不需要画图，用一句话或一个小表格说清楚即可。

## 二、图表必须自解释

每张图表都要包含：标题（说明具体指标，不能只写"趋势图"）、坐标轴标签（含单位）、图例（多于一条series时）、来源与口径说明（一行小字，如"来源：公司定期报告，2024Q3–2025Q3"）。缺失以上任一项的图表不能交付。

## 三、生成流程：用脚本而不是手绘

图表不由 agent 直接"手画"或用 ASCII 拼凑，统一走 `scripts/render_charts.py` 生成真实图片，理由：

- 保证坐标轴、图例、数值标注的准确性和一致的视觉风格，不依赖手工排版。
- 生成的是标准 PNG 文件，可以直接嵌入 Markdown 正文，也可以作为图片资源插入飞书文档，不受渲染环境差异影响。

调用方式：把图表数据整理成 JSON（见脚本内文档的字段说明），执行：

```bash
python3 scripts/render_charts.py --input chart-spec.json --output-dir charts
```

脚本会在 `charts/` 目录下生成对应 PNG 文件，并打印一份 `id → 文件路径` 的清单，供后续引用——正文里嵌入图片、或后续插入飞书文档时都用这份清单里的路径。

支持三种图表类型：`line`（趋势）、`bar`（对比/占比）、`event_timeline`（价格 + 多类型事件叠加，专门给 `linked-signals.md` 第四节触发的"关联动态时间线"用）。`event_timeline` 需要提供 `price_series`（日期+价格序列）和 `events`（每个事件的日期、说明文字、分类标签，如"本公告"/"联动公告"/"互动平台回复"），脚本会自动按分类分色，在价格曲线上标出每个事件对应的时间点并加图例——分类标签用什么名字，图例就显示什么名字，不需要在脚本里预先注册。

## 四、正文呈现：源稿里怎么放图表

写源稿（`delivery-pipeline.md` 第四节的源稿）时，正文永远要包含：

1. 结构化数据用表格。
2. 有趋势/对比/事件叠加意义的数据配图表，图表**直接**用 Markdown 图片语法嵌入源稿（`![标题](charts/xxx.png)`），不是只在描述里提一句"已生成图表"——`finalize_report.py` 不处理图表，图片引用会原样保留在 display markdown 里，所以源稿里图片放对位置，最终就是对的。
3. 触发了 `linked-signals.md` 第四节判定的关联动态时间线（`event_timeline` 图表）时，这张图同样直接嵌入源稿。

飞书文档的内容就是 display markdown 全文（含相同的表格、图表引用），不是"正文之外的另一份不同内容"，两者呈现内容应保持一致。

## 五、飞书文档创建（display markdown 生成之后的下一步）

display markdown 生成后（走完 `delivery-pipeline.md` 第五节的 `finalize_report.py`），创建飞书文档：

- **优先用当前运行环境内置的飞书文档/云文档创建能力**：如果运行环境本身提供"把一段 Markdown/富文本内容转成在线文档"的原生工具（多数豆包类客户端场景下存在这种能力），直接用这个原生工具，把 display markdown 全文传入即可，不需要额外的登录态管理。
- **没有原生能力时，退化用 `lark-cli`**：`lark-cli` 首次使用前需要 `lark-cli auth login`（用户授权登录，登录态持久化），操作权限与当前登录用户一致。具体的文档创建/内容写入操作优先直接调用已封装好的 `lark-doc` 技能来完成，不在本 Skill 内重新实现一套 `lark-cli` 调用逻辑；图表按 `lark-doc` 技能里图片资源的处理方式插入（上传图片，不是贴文件路径文本）。生成后必须在最终回复中，以当前运行环境支持且用户可访问的方式提供在线 URL。这条路径依赖当前运行环境已经安装并登录 `lark-cli`，如果两者都不满足，就只能如实告知飞书文档创建失败，见下一条。
- **失败处理**：不管走哪条路径，如果登录态失效/权限不足/其它原因导致飞书文档创建失败，不要让整个任务失败——固定风险提示语和 display markdown 正文依然要完整交付，如实告知"飞书文档生成失败，原因是 XX"，不要静默跳过。

完整的三段式回复契约（固定风险提示语 → display markdown 正文 → 飞书文档链接）见 `delivery-pipeline.md` 第六节；不得在回复中展示中间文件列表或生成过程，见同文档第六节"不得输出的内容"。

## 六、非默认路径：本地 HTML 报告 / Word 导出（仅用户明确要求且环境支持时）

**HTML 报告**：只有用户明确说清楚需要一份可以在自己本机直接打开的独立 HTML 文件，且确认所在运行环境支持把文件交付到用户本机，才走这条路径：先按第三节生成图表 PNG，再把 display markdown 的内容整理成结构化 JSON（见脚本内文档的字段说明），执行：

```bash
python3 scripts/render_html_report.py --input report-spec.json --output report.html --charts-dir charts
```

脚本会把图表文件读取并转成 base64 内嵌进 HTML，输出一份无外部依赖的单文件报告。

**Word/DOCX 导出**：只有用户明确提出才生成，在 display markdown 之上多跑一步 `scripts/make_docx.py`，用法见 `delivery-pipeline.md` 第七节。

以上两条路径都**不是默认交付方式**，默认场景请走第五节的飞书文档。

## 七、正文 Markdown 里的表格/图表写法

- 表格：标准 Markdown 表格语法，列宽由内容自动决定，不需要额外处理。
- 图表：`![图表标题](图片路径)`，图片下方紧跟一行小字说明来源和口径（Markdown 本身不支持图注，用紧随的斜体文字模拟）。

## 八、依赖说明

`scripts/render_charts.py` 依赖 `matplotlib`；`scripts/make_docx.py`（可选）依赖 `python-docx`（均见 `scripts/requirements.txt`，执行前如未安装需先 `pip install -r scripts/requirements.txt`）。`scripts/normalize_report.py`、`scripts/check_facts.py`、`scripts/lint_report.py`、`scripts/make_display_markdown.py`、`scripts/finalize_report.py` 只用 Python 标准库，无额外依赖。`scripts/render_html_report.py` 只用 Python 标准库，无额外依赖，但按第六节属于非默认路径。生成飞书文档在没有平台原生能力时依赖 `lark-cli`（见第五节）。
