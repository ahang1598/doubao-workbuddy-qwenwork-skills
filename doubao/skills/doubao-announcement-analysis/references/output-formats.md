# 交付形式：两种模式

## 一、单条深度解读

面向一条或几条具体公告，结构化但不是填空模板——按下面的要素完整覆盖，具体详略按公告类型的 playbook 调整。**第 4、5 项（历史对比 + 关联信号）是必做项，不是选做的加分内容**，缺了这两项就是"只看了孤立一条公告"的浅层解读。

1. **公告基本信息**：公司、市场、公告类型、发布时间、公告编号/表单类型。
2. **客观内容摘要**：用自己的话概括公告讲了什么，关键数字和条款要准确（金额、比例、日期），不要照抄公告原文段落。
3. **重要性判断**：依据该市场的官方分类/披露规则判断这条公告的量级（如是否触及港股比率测试阈值、是否是美股 8-K 的强制披露事项），说明判断依据，不要只给"重要/不重要"的结论没有依据。
4. **历史同类公告对比**：这条公告放进该公司过去几次同类公告的时间序列里看，是延续趋势、拐点，还是节奏突变？用表格列出近几期的关键数字对比（见 `output-rendering.md`），不要只用文字定性描述。
5. **关联信号排查**：按 `linked-signals.md` 的联动规则表，检查是否存在应同步关注的关联类型公告（如业绩向好是否伴随股权变动），以及资讯/研报/投资者评论区/投资者互动平台里是否有值得正面回应的具体疑点。没有发现联动信号也要写明"未发现同期联动动作"。
6. **股价阶段表现（条件展开）**：先按 `linked-signals.md` 第四节的判断标准检查股价是否明显偏离常态。没有明显异动，这一项一句话说明"股价反应平淡，未见明显异动"即可，不用展开；如果判定为明显异动，要整理一张叠加本公告、联动公告、互动平台回复、股价走势的关联动态时间线图，说明这次异动更可能是被哪个具体信息驱动的。
7. **多视角分析**：至少覆盖对基本面/估值的影响、可能的动机解读（含管理层/大股东视角）、潜在反方或风险点。不要只写正面解读，也要指出这条公告本身没有回答、需要继续跟踪的问题；涉及研报的定量测算要显名归因。
8. **呈现**：结构化数据（历史对比、可比公司、股权变动明细等）用表格；有明显趋势或对比意义的数据配图表（用 `scripts/render_charts.py` 生成，规则见 `output-rendering.md`）。
9. **来源**：按 `data-grading-and-citation.md` 第六节的格式附文末"数据来源"清单（按出现顺序编号），紧接着按第七节附免责声明，这两项是单条深度解读的固定收尾，不能省略；不要再附「未获取清单」。

篇幅按信息量走，公告本身信息量小（如常规回购）不要硬凑长度；信息量大（如重大并购）可以分点展开，但要保持叙述性，不要变成纯清单堆砌。写作语气按 `writing-style.md` 收敛。

## 二、批量监控摘要

面向某公司/某组公司在某时间段内的公告合集，时效和覆盖面优先，深度让位于速度和广度：

1. **顶部信息**：覆盖的公司范围、时间窗口起止日期、市场。
2. **按大类分组**：参照 `markets-taxonomy.md` 的大类分组呈现（如"业绩类""股权变动类""重大合同/并购类"……）。默认用表格呈现（列：日期、公司、公告类型、关键数字、来源），逐条罗列文字摘要仅在字段不规整时使用；每条摘要/每行一到两句话说清楚"谁、做了什么、关键数字"，不展开深度分析。
3. **重点标注**：如果某一条摘要触发了 `linked-signals.md` 里的联动信号（如同期出现关联类型公告），或触及 Tier 1/2 类型且影响显著，可以在该条摘要后追加一段简短的"重要性提示"（写明联动到了什么），但不要把整条摘要写成深度解读——如果用户后续想深入，再单独走单条深度解读模式。
4. **遗漏提示**：如果检索窗口内有理由怀疑存在未覆盖到的公告（如某类公告通常发布频率高但这次没搜到），要提示用户，不要假装覆盖完整。
5. **来源**：每条摘要末尾简注来源（媒体/公告原文链接/数据库），不需要逐句编号；结尾附一句简版免责声明（见 `data-grading-and-citation.md` 第七节）。

## 三、混合场景

批量监控中遇到信息量特别大的单条公告，可以先在摘要合集里给出加长的"重点摘要"，并明确告知用户"这条建议做单条深度解读，是否需要展开"，由用户决定是否升级为完整的单条深度解读交付。
