# 检索取证协议

## 一、两条工具通道，分工明确

- **只用授权可用的通道**：对外取数只通过 `general_search`、`seed_finance_search` 两条工具通道，以及用户主动提供的文件/链接；不得自行调用其它未授权的数据接口或数据源。下面第二节列的"六类检索目标"都要通过这两条通道去覆盖，不是新增通道。
- **`general_search`**：找公告原文、资讯/新闻、研报动态、投资者评论区、投资者互动平台回复等一切公开网页内容——交易所/监管机构官网的公告页面、公司投资者关系页面、巨潮资讯网、HKEXnews、SEC EDGAR 页面、财经媒体、券商研报发布信息、同花顺/东方财富等平台的公告页评论区、上证e互动/深证互动易等公司互动问答平台。**检索时优先命中 `data-grading-and-citation.md` 第一节列出的具体信源清单**（金融监管机构类、公司渠道类、媒体与三方机构类），不要什么结果都往正文里搬——信源杂是解读可信度不稳定的常见原因。
- **`seed_finance_search`**：金融数据库口径的结构化数据——历史财务、行情、估值、一致预期、可比公司数据，用于给深度解读提供"这条公告的数字放在什么基准线上"的对比背景（如"这次增持金额相对公司市值占比多大""这次业绩预告增速在同业里处于什么位置"），也用于第三节第 6 步的股价阶段表现检查。

## 二、六类检索目标（缺一不可）

只找到公告原文是不够的。除批量监控摘要的快速模式外（见 `output-formats.md`），单条深度解读**默认要覆盖以下六类检索目标**，覆盖不到的要在正文里明确说明缺口，不能默认跳过：

1. **公告原文**：交易所/监管机构官网、公司 IR 页面、巨潮资讯网/HKEXnews/EDGAR 的原始公告页面。
2. **历史同类公告 + 关联公告**（纵向 + 横向联动检索）：按 `linked-signals.md` 的规则，检索该公司过往同类型公告的历史节奏，以及和这条公告存在联动逻辑的其它类型公告。**这一步是必做步骤**，不是"有余力再做"的加分项。
3. **资讯/新闻流**：财经媒体对这条公告或相关事项的报道，用于交叉验证、补充背景（如交易对手方背景、行业事件时间线）。
4. **券商研报动态**：检索是否已有券商就该事项发布研究报告或点评——如果有，可以引用其中的定量测算（如对 EPS 的影响测算）和分析框架作为解读的参考视角，但研报的结论和目标价不能直接当作本次解读的结论（见 `data-grading-and-citation.md` 关于二级来源的措辞限定）。
5. **投资者评论区**：同花顺、东方财富等平台该公告对应页面下的投资者/用户评论。评论本身不能作为事实来源引用，但往往能提示"市场实际在纠结/质疑哪个具体问题"——用来定位解读的切入点（如评论普遍质疑"这次增持是不是为了配合减持套现"，就要在解读里正面回应这个具体疑点，而不是泛泛而谈）。使用方式见 `data-grading-and-citation.md`。
6. **公司投资者互动平台回复**：上证e互动、深证互动易等官方问答平台上，公司对投资者提问的公开回复。这类回复是公司自己的表态（不是第三方转载或猜测），有时会影响股价，但不是正式公告渠道，措辞可能不如公告严谨——检索时要留意该公司近期是否在互动平台上就相关事项有过回复，可信度定位和引用方式见 `data-grading-and-citation.md`。

## 三、取证顺序

1. **先定位公告原文**：用 `general_search` 找到公告的原始发布页面，确认公告的发布主体、发布时间、公告编号/表单类型。批量监控模式下要覆盖时间窗口内的公告列表页，不要只搜到被媒体转载的那几条。
2. **提取公告关键要素**：从原文里提取关键数字、条款、时间节点，原样记录（金额+单位+口径），不要在检索阶段就转述或简化。
3. **跑联动检索**：按 `linked-signals.md` 检索历史同类公告和关联类型公告。
4. **补充背景数据**：用 `seed_finance_search` 取该公司的基准数据（市值、股本、历史同类事件、可比公司数据）。
5. **补充资讯/研报/评论区/互动平台回复**：按第二节第 3、4、5、6 类目标补充检索，用于交叉验证和定位解读切入点。
6. **股价阶段表现检查**：用 `seed_finance_search` 拉该股公告发布前后的价格/成交量数据，按 `linked-signals.md` 里的判断规则确认是否出现明显偏离常态的波动。**这一步是必做的判断动作**（哪怕结论是"没有明显异动"），但只有判断结果为"是"时，才需要进一步整理关联动态时间线——不要不做判断就默认展开，也不要因为嫌麻烦而跳过判断本身。
7. **交叉验证重大判断**：涉及"是否重大""是否触及某条红线（如退市指标、比率测试）"的判断，尽量找到两个以上独立来源互相印证，或直接对照官方规则条文（如港股比率测试的具体计算方式、A 股退市新规的具体指标）。

## 四、批量监控模式的覆盖要求

- 明确时间窗口起止日期，检索时按窗口边界取数，不要遗漏窗口首尾的公告。
- 覆盖面优先按 `markets-taxonomy.md` 里的大类过一遍，而不是只挑"看起来有新闻价值"的公告——容易漏掉的类型：股权披露类（DI 通知/13D-13G/Form 4）、停牌复牌类，这些通常不会被媒体单独转载，但对投资判断价值很高。
- 如果同一事项在两地同时披露（如 A+H 公司），要在摘要里说明是否存在两地披露时间差或内容差异。

## 五、数据缺口处理

两条通道都拿不到的数据，如实标注"数据缺口"，不得凭印象、常识或模型推断补齐；缺数据本身也是一个结论，尤其是"应该披露但没有搜到"的情况要在正文相关判断处用「数据不足」「待核实」点明（可能是搜索没覆盖到，也可能确实存在披露滞后）。**不要**再在文末单独汇总成给用户看的「未获取清单」——整体免责声明已覆盖信息缺漏；读者只需要在相关判断处看到边界即可。
