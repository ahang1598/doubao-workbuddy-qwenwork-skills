# 数据分级与引用规则

## 一、信源分类清单与可信度分级

检索取证时优先落在下面清单里的具体信源上，不要什么结果都往里搜——信源杂、可信度参差不齐，是解读质量不稳定的一个主要原因。信源按来源性质分三大类，分级对照如下：

### 1.1 金融监管机构类（一级，最高可信度）

交易所/监管机构自己的官方发布渠道：

- 上交所（www.sse.com.cn）、深交所（www.szse.cn）、北交所（www.bse.cn）官网信息披露栏目
- 香港交易所披露易 HKEXnews
- 美国 SEC EDGAR
- 中国证监会及地方证监局官网（监管处分、警示函等文件的原始出处）

### 1.2 公司渠道类（一级，官方但要分辨正式程度）

- **公司公告原文、定期报告（年报/半年报/季报/业绩预告快报）**：最核心的一级来源，公告关键数字必须能追溯到这里。
- **巨潮资讯网（cninfo）**：中国上市公司信息披露官方指定网站，是公告原文的官方托管渠道，等同于交易所披露平台，视为一级。
- **公司官网/投资者关系（IR）页面**：一级，但更新节奏可能滞后于公告本身。
- **公司官方认证社交媒体账号**（认证微博/微信公众号等）：视为公司官方表态，比照一级，但措辞随意程度、更新及时性都不如正式公告，引用时要显名标注"来自公司官方账号"，不要笼统写成"公司公告"。
- **投资者互动平台回复**（上证e互动、深证互动易等）：单独说明见第四节，比照一级但有特殊使用限制。

### 1.3 媒体与三方机构类（二级，须显名归因）

- **高资质财经媒体**：央视财经、财联社、券商中国、《财经》、中国证券报、第一财经等；国外可用纽约时报、华盛顿邮报等主流财经/综合媒体。
- **数据/资讯平台（东方财富、同花顺等）**：平台上转载呈现的公告原文/行情数据，可视为等同一级的数据库口径；但平台自身撰写的文章、"财富号"一类的个人/机构观点栏目，属于二级，需要显名归因，不能当作平台本身的权威结论。
- **券商研报**：可引用其中的定量测算和分析框架作为参考视角，但结论、目标价不能直接当作本次解读的结论。
- 行业协会数据。

二级来源用于交叉验证、补充背景、刻画市场解读/共识，不能替代一级来源作为公告关键事实的唯一出处，引用时必须显名归因（"据XX媒体报道""据XX研报"）。

### 1.4 三级来源（仅作线索，不可引用为事实）

- 未指明具体出处的转载、自媒体/论坛/社交媒体讨论、无法核实出处的数字。
- 同花顺、东方财富等平台公告页下的**投资者/用户评论**（区别于 1.3 提到的平台自身数据/文章，评论是用户生成内容，见第三节）。

这份清单不是封闭列表，检索中遇到清单外但明显权威或明显不可信的来源，按"是不是原始发布方"“需不需要显名归因”"只能不能作线索"三条标准类推处理即可，不用逐一列举穷尽。

## 二、公告关键事实的来源红线

- 公告本身的关键数字（金额、比例、日期、条款）必须来自 `general_search` 取到的公告原文，或 `seed_finance_search` 的数据库记录；不得用二级来源的转述数字替代。
- 涉及"是否触及监管红线"的判断（退市指标、比率测试阈值等），要能引用到具体规则条文或官方说明，不能仅凭公告标题或媒体报道的定性描述下结论。
- 背景性的行业/市场信息（如"这类交易近期是否常见""同业可比公司近期是否有类似动作"）可以适度使用二级来源，但要显名归因（"据XX媒体报道""据XX研报"）。

## 三、投资者评论区的特殊定位

同花顺、东方财富等平台公告页下的投资者/用户评论，不属于上面三级可信度里的任何一级"事实来源"——评论本身可能是主观猜测、情绪化表达甚至误导信息，**任何情况下都不能把评论内容当作事实引用**（如"有投资者称XX"这种写法本身就是在给未经核实的说法背书，要避免）。

评论区的正确用法是**"挖掘视角的线索来源"**：

- 扫描评论区，找出高频出现的具体疑问或质疑角度（如"这次增持是不是为了配合后续减持""募资用途是否真的投向了公告说的项目"）。
- 把这些具体疑问当作解读时要主动回应的问题，去公告原文、历史记录、数据库里找依据正面回应或证伪，而不是照抄评论区的猜测。
- 如果一个疑问确实找不到依据回应，就在解读里如实说"市场对此有疑问，目前公开信息不足以证实或证伪"，不要回避，也不要替评论区的猜测下结论。
- 评论区可以反映的是"市场关注度/情绪倾向"这类氛围性信息（如某条公告下评论量明显异常），这类观察可以描述为"该公告引发了明显的投资者讨论"，但不能量化成精确结论（不能说"X%的投资者认为……"，除非平台本身有公开的投票统计功能且已核实）。

## 四、投资者互动平台回复的特殊定位

上证e互动、深证互动易等官方互动平台上，公司对投资者提问的回复，和投资者评论区不是一回事——**这是公司自己发出的表态，不是第三方转载或猜测**，可信度上比照一级来源（视为公司官方口径），但使用时要注意两点：

- **不是正式公告渠道**：措辞通常比公告更随意、更简短，有时会出现和正式公告口径不完全一致、甚至前后矛盾的情况。引用时要显名标注来源是"互动平台回复"而不是笼统写成"公司公告"，让读者能分清信息的正式程度。
- **与正式公告冲突时，以正式公告为准**：如果互动平台回复的内容和正式公告、定期报告有出入，解读里要如实指出这个不一致，不能选择性只引用对解读结论有利的那一边。
- 互动平台回复本身有时会直接影响股价（如公司在互动平台上确认或否认某个传闻），这种情况下要把回复的具体时间和内容作为"关联动态时间线"的一个节点（见 `linked-signals.md` 第四节），而不是只当作背景信息一笔带过。

## 五、正文内引用方式

单条深度解读模式下，**正文里不手写引用编号**。写源稿时，关键数字/判断后面跟一个 `{fact:claim_id}` 绑定标记（如 `公司拟通过集中竞价方式回购不超过 2 亿元股份。{fact:buyback_amount}`），`claim_id` 对应事实表（`facts.json`）里这条事实的 `claim_id`。同一句话由多条事实支撑时用逗号分隔：`{fact:a,b}`。

展示给用户看的 `[1]` `[2]` 编号，由 `scripts/finalize_report.py` 按正文里第一次出现的顺序自动生成——**同一个来源（相同的来源名称+链接）不管被多少个不同 `claim_id` 引用、被引用多少次，只占一份编号**，不需要（也不允许）手写。事实表结构、`{fact:claim_id}` 语法细节、脚本用法见 `references/facts-template.md`、`references/delivery-pipeline.md`。

批量摘要模式篇幅短、引用密度低，不强制走事实表机制，直接在每条摘要末尾用括号简注来源即可（如"（来源：巨潮资讯网，2026-07-17）"）。

表格走表下"资料来源"行，写法不受上面规则约束（表格里的来源说明本身就是可读文字，不是需要编号追溯的角标）。

## 六、文末溯源清单格式（单条深度解读必做）

单条深度解读结尾必须有一份"数据来源"区块，源稿里先写好下面这个骨架（标题、标记行、风险提示都是模型手写的固定文字），把编号列表留空：

```
## 数据来源

文中引用对应以下来源：

### 风险提示与免责声明：
（见第七节固定文字）
```

`scripts/finalize_report.py` 会定位到"## 数据来源"标题和"文中引用对应以下来源："这一行，把按第五节规则生成的编号列表插入进去，`[1]` `[2]` 顺序对应正文里第一次出现的顺序。**这份清单不按信源类别分组**——不管是公司公告、互动平台回复、券商研报还是媒体报道，统一按出现顺序编号排成一份列表；信源的可信度差异不通过"分组标题"体现，而是通过正文里的措辞（"公司披露""据券商研报估算""媒体报道称"等，见 `writing-style.md` 第八节和 `facts-template.md` 的 `usage_type` 对照表）体现，这样读者读到某条引用时就已经知道它的性质，不需要跳到文末再对照分组。

**不要在文末单独写「未获取清单」**——数据缺口已由文末免责声明覆盖（信息缺漏、时效性不足等）；需要提示读者的缺口，只在正文相关判断处用「数据不足」「待核实」一带而过即可，不必再汇总成给用户看的清单。`make_display_markdown.py` 若发现源稿里仍残留「未获取清单」区块，会在生成 display markdown 时自动剥掉。

批量监控摘要模式不强制走事实表机制，按第五节的简注方式即可；但如果用户明确要求"给一份完整的来源清单"，可以手工按上面骨架的样式组织（批量模式本身不经过 `finalize_report.py`）。

## 七、结尾免责声明

风险提示与免责声明的具体文字是模型在源稿里直接写好的固定长文本（三段，内容固定，不逐字改写），紧跟在"数据来源"区块之后，作为 `### 风险提示与免责声明：` 小标题下的内容：

```
- 以上内容为 AI 自动生成或 AI 辅助生成，仅用于信息整理、投研辅助、教育交流或一般性分析参考，不构成对任何金融产品、交易策略或投资行为的推荐、邀约、承诺或保证，也不构成投资、法律、税务、会计等专业意见。
- 以上内容可能基于公开信息、历史数据或用户提供材料进行总结、归纳、推演与情景分析，但相关内容可能存在时效性不足、信息缺漏、事实误差、模型偏差或生成性错误。历史数据、历史业绩、回测结果及情景假设均不代表未来表现。
- 用户应基于自身风险承受能力、投资目标、财务状况及适用法律法规独立作出判断，必要时咨询持牌专业机构或顾问。任何因依赖本分析输出而作出的决策及其后果，由用户自行承担。
```

`scripts/finalize_report.py` 不会生成或修改这段文字，只会原样保留——写源稿时必须已经包含它，不能等脚本"自动补全"。批量监控摘要模式需要附简版声明，至少保留"不构成投资建议"和"用户自行判断"两个核心意思，可以合并成一句话，不必逐条照搬长版措辞。

除这份长版免责声明外，**最终回复给用户的最前面，还必须固定输出一句更简短的风险提示语**（这是回复层面的契约，不是 display markdown 内部的内容，两者都要保留，不能相互替代）：

```
回答基于AI 生成，仅用于信息参考与研究辅助，不构成任何投资建议。股市有风险，请结合自身风险承受能力决策。
```

具体的回复组装顺序（固定风险提示语 → display markdown 正文 → 飞书文档）见 `references/delivery-pipeline.md` 第六节。

## 八、缺口披露

拿不到一级来源支撑的关键判断，如实标"数据不足"或"待核实"，不要用二级/三级来源的措辞包装成确定事实。缺口只在正文相关处点到为止，**不要**再单独汇总成文末「未获取清单」；整体免责声明已覆盖信息缺漏风险。
