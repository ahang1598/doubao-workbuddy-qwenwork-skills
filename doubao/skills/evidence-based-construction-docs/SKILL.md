# 工程建设文档证据化编审

## 概述
本 Skill 负责证据化编审，不承担结构计算、施工安全审批或注册工程师责任。所有参数、日期、项目主体和规范引用必须能追溯到项目资料或当前有效权威来源。

## 使用场景
### 应使用
- 依据招标文件、图纸、清单和日志编制或审校工程文档。
- 从多份附件提取工程事实并核对缺项、编号和冲突。
- 对现有方案做事实一致性和规范引用检查。

### 不应使用
- 从零设计结构、脚手架或危大工程技术参数。
- 在缺少项目资料时生成可直接施工的方案。
- 纯 Word/Excel 排版。

## 核心流程
### 1. 建立项目证据台账
登记来源文件、版本、页码、日期、主体、参数和适用阶段。

### 2. 锁定文档类型和责任边界
区分材料整理、合规检查、草案编制与专业审查；高风险专业结论只列待复核。

### 3. 生成或修订
严格从证据台账取值；缺失参数保留占位和补资清单，不用常识补齐。

### 4. 核验规范
优先使用项目合同/招标文件指定规范；需要外部规范时核验现行版本、地域和适用范围。

### 5. 交付复核
检查章节、编号、单位、数量、日期、引用和待复核标记；文件生成转 lark-doc/sheet。

## 工具与协作
- 文件读写使用 lark-doc/sheet；字符和空编号可用随包纯 Python 脚本。
- 涉及专业安全、结构和施工参数时必须提示注册专业人员复核。

## 安全边界
- 只陈述已读取、已执行或有来源支持的结果；未验证项必须明确标注。
- 涉及删除、覆盖、发布、系统设置、生产数据或不可逆操作时，先展示目标、影响、回滚方式并取得明确确认。
- 不得记录或输出密钥、Cookie、访问令牌、身份证号、银行卡号等敏感信息；示例使用脱敏占位符。
- 不得把示例规范编号、通用经验值或旧项目参数直接作为当前工程依据。
- 不得声称草案已完成法定审查、施工审批或安全论证。

## 输出与验收
- 证据台账
- 文档草案或问题表
- 规范/参数来源
- 待补材料与专业复核项

## 冒烟用例
### Should trigger
- 依据招标文件审校施工组织设计并列缺项
- 从监理日志生成可追溯的巡视问题表

### Should not trigger
- 帮我计算脚手架承载力并直接用于施工
- 只调整 Word 标题字体

### 边界输入
- 项目指定规范与外部现行规范不一致
