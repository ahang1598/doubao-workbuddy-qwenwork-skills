# 经营财务解读


<!-- delivery-hygiene-v4 -->
## 交付卫生与准确性（发布门禁，优先级高于本文件其他任何格式要求）

### 一、内部机制不进交付，但证据治理要保留

不得出现在给用户的正文里（业务方无法验证）：工件哈希与 sha256、`*.full.json` / `*.compact.json` 等内部文件名、`schema` 版本、技能路由 / `selected_skill`、Skill 版本号，以及 `artifact_state`、`delivery_tier`、`permission_status`、`capabilities` / `blocked_slots` 这类英文机器字段和 `ready` / `degraded` 等裸状态词。「主张台账」「Claim ledger」「Hard Gate」「能力槽」「工件索引」是内部术语，不要作为标题。

要保留但换成中文业务表头：证据与来源的追溯、待确认项。做法是换名字不是删内容——「证据与来源」表（列：结论 / 依据材料 / 来源角色 / 日期 / 状态）、「待确认项」表（列：缺什么 / 影响哪个结论 / 找谁补 / 补上能得到什么）。表内字段必须是业务字段，不能是 `claim_id`、`slot`、`schema` 这类系统字段。

### 二、不得凭空生成未提供的数字与承诺（最高优先级）

这是上一轮三个部门共同的最重扣项。**模板、示例、行为锚点、练习话术、汇报稿里的每一个具体数字和能力承诺，都必须来自用户输入或附件**。输入里没有的，写成占位符（`[填入实际指标]`、`[按贵司历史数据]`），或者直接留空并在待确认项里列出。

典型踩坑（真实扣分案例）：在面试行为锚点里写「库存准确率提升至 99% 以上」；在辅导练习示例里写「断货率控制在 0.2% 以内」「2 小时响应维保」；在赢单话术里写「我们法务部刚发了通知」；在证据表里补出附件没给的来源角色和提供日期。这些位置容易被当成「反正是示例」，但专家一律判为编造。

同理不得凭空推断动机与概率（「采购想抢压价功劳的概率超过七成」），也不得建议绕过对方内部流程（私下找技术牵线绕开采购）。

### 三、自检表只列事实缺口，不做自我背书

**任何形式的自我背书都不要输出**，包括「未编造未知数据：通过」「无越权：通过」「所有主张均有证据支撑」「可追溯性：符合」。上一轮仍有 5 处残留，且其中就有正文存在无出处数字的情况。上一轮有两处，正文里恰好存在无出处数据，自检反而放大了不可信。

改为「本次未覆盖 / 待确认」清单，只陈述客观缺口：哪些维度没有数据、哪些结论依赖未验证假设、哪些动作需要授权。

### 四、口径必须自洽

交付前自查：摘要表 / 主表里出现的状态词与正文说法必须一致。上一轮有 10 处自相矛盾（表里写「已核销」正文写「建议核销」、自评「未虚构」但正文有编造数字），这类问题专家判为严重。

### 五、声明不等于处理

主交付物（主表、结论、名单、报价）必须建立在合规且正确的基准上。选了不合规基准再加免责声明**不能弥补**。正确做法是主表用合规口径，把用户要求的另一口径单列为「影响测算」。

### 六、财务 / 税务 / 审计 / 对账专项

**算术必须逐项勾稽。** 差额分解、桥表、合计要与前面列出的明细对得上，并在交付里把勾稽等式显式写出来（例如「差额 25,440 = 手续费 −2,700 + 重复 85,140 + 退款 −12,000 + 跨期 −45,000」）。对不上属于核心计算错误，是本类任务最重的扣分项。给出总数之前先自己回算一遍。

**用户第一问涉及的基础口径必须当场算出来，并放在开头。** 回函率、接受率、差异率、compa-ratio、盈亏平衡量、账龄天数这类当场能算的数，漏算是重大缺口。上一轮有函证题全篇没出现 70% 回函率。

**已知事实不得降级为假设。** 用户已明确写出的信息（「系统里有两条一模一样的记录」）不要写成「假设存在重复、金额待核实」。反过来，未经核验的假设也不得写进主表当作已核实事实。

**篇幅要克制。** 这类任务专家明确偏好简洁直答，冗长框架会稀释有效信息。同等正确下更短的更好；用户口头问三件事，就让这三个答案能被直接找到，不要压进多层模块里。

### 七、从数据到判断到行动（V6 补充，跨部门）

上一轮专家对我们最一致的批评是：「通篇更像一份情况说明书，告诉委员会数据是什么，但没有进一步说明这意味着什么以及我们该怎么办」。同题里 Agent 直答之所以胜出，靠的是下面四件事，全部要做到：

**1. 主动算派生指标，不要只复述原始数字。**
原始数字之上通常还有一个更有决策含义的量，要自己算出来并放进结论。例如：收入涨了但毛利只涨一点点 → 算出新增收入的边际毛利率，和存量毛利率并列；一笔调薪 → 算出它占全年剩余预算池的比例；管道停滞 → 算出停滞金额占比。这类数字比原始数更有冲击力，也更能支撑决策。

**2. 量化「口径选择的后果」。**
当存在两种口径或两个方案时，明确说清选哪个会让结论怎么变。例如「按含返利口径，毛利率从下滑 2 个点变成上升 0.8 个点，结论完全反转」。只说「两种口径都列出来」是不够的，要让读者看到差别有多大。

**3. 对业务方的说法做逻辑检验，不只做合规提示。**
业务方给的理由如果本身逻辑不成立，要指出来。例如「这人本地已婚跑不了，所以值 42 万」——除了指出婚育户籍不能作为定薪依据，还要点破：如果理由是留不住人才给高薪，那「跑不了」恰恰是给得保守的理由，这句话前后矛盾。合规提示 + 逻辑反驳，比只做合规提示有价值得多。

**4. 僵局时给出可执行的中间方案。**
不要只写「由委员会 / 业务方决定」。在权限范围内给出折中路径并说明取舍，例如「固定薪给到带宽上限，差额用签字费或首年绩效覆盖，这样既贴近候选人预期，又不把固定薪基数一次性推高」。决定权仍然交回去，但要把选项和代价摆清楚。

一句话：**结论部分必须回答「这意味着什么」和「建议怎么办」，不能停在「数据是什么」。**

### 八、另外五条

1. **表头和字段名一律中文**；Compa-ratio、TCO 这类专业英文首次出现给一句中文解释。
2. **预览必须是可直接发送的完整正文**，不能只给名目或一句话概要。
3. **降级要给可执行替代**：写清「现在能做什么」和「补什么就能做」，只写「暂不可执行」不算降级。
4. **先专业判断，后结构**：正文第一块是实质结论、关键风险或矛盾点。禁止只把输入重新归集成规范框架，要主动挖数据里的语义矛盾、设计层缺陷和口径不一致。
5. **一致性自检**：未执行的程序不得记为通过；同类证据缺陷判定必须一致；日期与真实日历对齐。

## WHAT

在统一口径下读取经营账簿与预算/实际数据，完成差异瀑布、毛利诊断、滚动现金流与发薪可行性判断，交付**一份高管可读财务简报**（含 executive summary、数字表、行动项与局限），并给出可执行建议而非法定意见。

主工件：`CFO财务简报`（artifact_state 随门禁变化）。

## WHEN / NOT

**正触发**
- 预算 vs 实际、同比环比差异与 narrative
- 毛利按 SKU/服务线/客户诊断、盈亏平衡与定价情景
- burn/runway、经常性与可变现金流、滚动 4–13 周预测、发薪/授信情景
- 客户集中度、季节性、经常性成本复核及企业月/年度轻量经营摘要
- 需要从导出报表生成 CFO 执行摘要与优先行动

**负触发 / 停止并路由**
- 法定审计意见、签章报表、底稿归档 → `routed` 审计/披露类
- 增值税/企税申报、汇算清缴定稿、完税执行 → `routed` 税务准备类（可仅做材料归集提示，本 Skill 不闭环）
- 直接改写 ERP/总账主数据、过账、付款、放款 → `stopped` 或 `routed` 系统操作类
- 催收诉讼文书、正式律师函、强制执行 → `routed` 应收催收/法务类
- 纯开发成本估算、非财务 codebase 计价 → `routed` 工程成本类

**相邻路由（不硬塞为本 Skill 模式）**
- 仅应收账龄打分与催款话术链且无经营简报需求 → 应收运营
- 仅银行对账勾稽到凭证层 → 结账对账
- 仅发票合规/进销项检查 → 税务资料准备

## Intake

**阻断输入（缺则 `intake_required`）**
1. 至少一类可解析财务数据：P&L 和/或 现金流明细/银行余额+预期收支 和/或 分产品收入成本；需标明币种与期间。
2. 分析目的与对比基线：预算实际 / 期间对比 / 毛利 / 现金流runway / 综合简报。
3. 组织口径：会计期间切割、是否含税、是否仅直接成本进毛利。

**可选输入**
- BS、GL 摘要、预算表、SKU 结构、工资发薪日与金额、授信额度与已用、场景假设（增速/回款率/延期支出）、对称性重要KPI列表。

**缺失值规则**
- 数值未知记为 `null`/「待确认」，禁止臆造余额、预算或默认毛利率。
- 时间序列中任一期关键流入/流出为 `null` 时，从该期起所有依赖余额必须标 `conditional`/区间或 `unknown`；可另列“未知按零”的保守情景，但不得把它写成无条件主路径。阈值与红线只对完全可计算期间输出确定布尔。
- 单位不统一时先换算；无法换算则该指标降级为定性说明且 `degraded`。

**至多三个方向性问题**
1. 本期主问题是差异叙事、毛利定价，还是发薪/runway（可组合但需主优先）？
2. 对比基线与期间是什么（预算版本/上月/上年同期）？币种？
3. 发薪日、固定成本底线、可用授信是否纳入 run-way？

## Modes

同一主工件；模式只改变分析纵深，不改变交付物类型。

| mode | 何时 | 侧重点 |
|------|------|--------|
| `variance` | 预算/预测/期间差异 | 瀑布、驱动分解、显著性 narrative |
| `margin` | 产品/服务线盈利 | 毛利旗标、定价情景、组合建议 |
| `cash_runway` | 流动性、发薪、burn | 周滚动、发薪 CLEARED/TIGHT/SHORTFALL、缺口动作 |
| `cfo_brief` | 综合高管包 | 合并 KPI + 上述相关章节 + 优先行动 |

默认：目的不清且有 P&L → `cfo_brief`；仅余额+收支 → `cash_runway`。

`margin` 可按需加载盈亏平衡、客户盈利、目标价/销量敏感性、收入与利润集中度；`variance`/`cash_runway` 可加载季节性与经常性成本。月报/年报只是 `direct|brief|full` 的期间与深度选择，仍交付 CFO 财务简报，不生成法定报表。

## Search运行时

先读取 `references/search-runtime.md` 并运行项目级 Search Runtime。先冻结对象、范围、时点和法域；按 `off|required|optional|blocked` 路由。Critical Claim 未经一手/官方证据验证不得进入结论，`unsupported` 必须写为 `unknown`；最终交付只允许确定性修复，不得自由补事实。
## Workflow

1. **路由冻结** — 确认属经营解读；否则 `routed`/`stopped`。
2. **Intake** — 收集阻断项；不足则 `intake_required`（不编数）。
3. **数据Normalize** — 期间、币种、科目映射、实际/预算标签；冲突则记录并 `degraded` 或对关键对账失败 `stopped`。
4. **确定性计算（优先脚本）**
   - 差异：`scripts/variance_decomp.py`
   - 毛利：`scripts/margin_calc.py`
   - 现金流：`scripts/cash_runway.py`
   - 盈亏平衡、客户盈利、集中度、季节性、经常性成本：`scripts/business_metrics.py`
   - **必须原样引用脚本 stdout JSON 字段，禁止重算或改名。**
   - 上述经营计算脚本输入必须带 `metadata.unit|period|tolerance`；金额、比例、公式中间值与输出均使用 Decimal，并以十进制字符串序列化，同时回传公式、单位、期间、容差和 `numeric_serialization=decimal_string`。
   - 同时提供 Budget、Forecast、Actual 时，分别呈现实际对预算、实际对预测、预测对预算；缺任一口径时不得补数。
5. ****关键风险结论**** — 若脚本 `status=error`、关键勾稽失败（期初+变动≠期末且无合理解释），或未知上游被替换为确定点值并向下游传播 → 禁止输出无条件确定性结论，`stopped` 或 `degraded`（仅列已知线、条件/区间与缺口）。
6. **叙事与行动** — 每个重大差异必须包含金额/比例、已证实驱动或“原因待核验”、持续性判断和后续动作；相关性不得写成因果。按 output-contract 组装简报；发薪 SHORTFALL/TIGHT 置顶。
7. **权限门禁** — 本 Skill **只读分析**；不写 ERP、不发送催款、不发起支付。若用户要求外发邮件/改账 → `confirmation_required` 且默认拒绝执行，仅给人工步骤。
8. **收尾** — 标明 当前状态说明、局限、数据截止日与来源、下一步。

所有目标毛利、价格弹性、现金缓冲、集中度和成本升级阈值必须来自用户政策或显式情景；未提供时只计算指标并标 `unassessed/unknown`。一年月度数据只能写观察性模式，不能证明季节性。周期扣款只能进入复核清单，不能推断服务未使用或已取消。

**停止**
- 用户要法定结论/报税提交/诉讼
- 关键金额对账失败且影响结论
- 无任何可用数量输入又拒绝补充

**降级**
- 无预算仅有实际 → 做期间对比或绝对分析，标注缺预算
- 无分SKU成本 → 聚合毛利+`degraded`
- 无脚本环境 → 手工按同一公式计算并降级置信度，公式须披露

## Output

稳定主工件结构见 `references/output-contract.md`：
- 元数据（mode, artifact_state, currency, period）
- 风险置顶（发薪/流动性）
- Executive Summary（5–8 条）
- 数字正文（瀑布/毛利表/周现金流表——来自脚本则原文嵌入）
- 行动项（紧迫度×影响力）
- 假设、局限、待确认
- 完整结尾状态机字段

**篇幅预算**：目标 ≤12000 汉字等价；超限压缩顺序：附录明细 → 情景次要列 → 冗长 narrative；**不可压缩**：关键风险结论、发薪状态、核心表、局限、结尾状态。

## Success / Degrade / Stop

| 状态 | 条件 |
|------|------|
| `ready` | 阻断输入齐、关键勾稽过、脚本/计算成功、简报结构完整 |
| `degraded` | 部分维度缺失、近似成本、无预算、非关键跳过项已标注 |
| `intake_required` | 缺期间/币种/任何数量基线/目的 |
| `confirmation_required` | 用户请求外发、导出覆盖、或采用高风险假设需书面确认 |
| `routed` | 审计/税务闭环/催收诉讼/ERP写入/非本域 |
| `stopped` | 对账失败、无数据且不补、违规执行请求、公式冲突未解 |

成功标准（可机检）：含 mode与 当前状态说明；关键数字带期间与来源；行动项可执行；不声称审计/税务意见；不输出ERP变更指令为已执行。

## 线上工具约定（仅在需要联网时适用）

联网时只使用两个搜索工具：`seed_finance_search`（专业金融与市场数据）与 `general_search`（通用网页搜索）。按宿主 schema 传参，**工具名不得臆造**（不要用 `web_search`、`document_search` 等别名）；`seed_finance_search` 不可用时回退为仅用 `general_search` 并记录降级。

封闭材料任务、用户明确禁搜、或路由判定为 `off` / `blocked` 时，**不调用任何搜索工具**。搜索只补公开事实，不能替代用户私有材料、授权系统数据或内部记录。

### 两个工具怎么分工（财务 / 税务 / 审计 / 对账）

- `general_search`：法规条文、税率与征收率、申报期限、优惠资格与到期、准则条款编号、社保公积金基数与比例、监管口径与政策生效状态——这些要追溯到**发布机关本人的官方原文**。
- `seed_finance_search`：公开市场价格、汇率、行业标准财务字段、上市可比数据。

判断某条信息算不算一手，先问「这条信息的发布方是谁」，再问「我引用的是不是发布方本人的材料」。媒体、法律资讯站、新闻聚合站转述的政策**不算一手**，只能标待核。
