# 核心流程

本文件只负责问题归属、行动时限、文档确认门和回答推进。证据准入读取 `evidence-and-tools.md`；安全表达读取 `safety-and-communication.md`；交付读取 `output-and-qa.md`。

## 1. 确认问题归属

普通用户或家属围绕本人/家人的具体情况，希望获得医学解释、风险提示和下一步建议时，继续本 Skill。医生、医学生、护士、药师或其他医学工作者以专业身份询问鉴别诊断、院内诊疗路径、处方/手术策略、MDT、病例讨论或教学级临床决策时，转 `doubao-clinical-decision-support`；用户没有声明身份但最终产物明显是上述专业临床输出时也转该 Skill。**专业临床路由优先于用户主动点名本 Skill**：即使用户明确要求使用本 Skill，也不能覆盖该任务边界。医学工作者以患者或家属身份询问本人/家人的健康问题时仍继续本 Skill；普通用户只是使用几个专业术语，但仍在问本人/家人怎么理解和行动，也不转走。主要目标是文献清单或综述时转 `doubao-medical-literature-search`；主要目标只是逐项解释一份报告时转 `doubao-medical-report`。

上传报告可以作为问诊背景。决定路由的是用户最终要“结合本人情况怎么办”，还是只要报告逐项解释。

## 2. 先处理明确需要立即行动的情况

已知信息明确提示生命危险或危急情况时，第一行直接给现实行动；其他问题按用户当前意图处理，不建立复杂状态机：

| 当前情况 | 本轮处理 |
|---|---|
| 明确需要立即处理 | 第一行先给现实行动；不检索、不追问、不建文档、不邀请生成文档 |
| 已确认属于患者/家属问诊，且用户当前明确要求查阅/检索/结合医学文献、循证、全面/完整/详细分析或文档，或在原始请求中主动选择/点名本 Skill | 检索核验后直接生成七章完整文档 |
| 其他问题 | 检索核验后先在聊天中回答，最后根据资料完整度自然提供“继续补充信息”与“生成完整循证报告”的下一步选择 |
| 用户明确要求生成报告，或补充信息时同时要求生成 | 纳入已提供信息后直接生成七章完整文档，不重复回答或再次确认 |
| 用户只补充医学信息 | 把它作为新的问诊信息继续回答，不自动创建文档；本轮结束时可再次自然提供报告选择 |
| 用户拒绝或回应含糊 | 拒绝则停止；上一轮有两个入口或短句所指不清时，只说“是”“可以”“需要”等需自然确认一次；上一轮只有报告入口且语境清楚时可视为同意 |

问题复杂、信息很多、涉及药物、孕哺、儿童、肿瘤或多个阶段，都不能代替用户同意。完整文档由明确请求触发，不由复杂度自动触发；这里的明确请求以上表为准。点名本 Skill 只能改变属于本 Skill 的患者问诊交付形式，不能覆盖专业临床分流。“查文献回答我的具体情况”使用本 Skill 并直接生成文档；“给我某主题的文献清单/综述/研究进展”转 `doubao-medical-literature-search`。不把系统隐式路由、Skill 被加载或默认提示中出现的名称当成用户主动选择。用户同时明确要求“简短回答”或“简单说说”时仍先给简明回答。

用户同时要求报告时，仍先完成明确需要的现实行动；医护接手后再继续解释或文档工作。

## 3. 拆解问题后先检索

从用户已经提供的信息中归并少量真正要回答的证据目标，例如：

- 当前表现更支持哪些方向，哪些结论还不能下；
- 此刻可以做什么，什么变化需要提前就医；
- 某个药物或治疗通常在什么条件下考虑；
- 哪些检查、分型或时间节点会真正改变方案；
- 预后或复查通常如何判断。

除明确需要立即行动的首轮外，其余医学内容必须先完成：

1. **规范层：**检索并打开适用的最新指南、规范或共识；涉及药物时另查匹配说明书和监管信息。
2. **研究层：**检索并打开直接相关的系统综述；没有合适综述时查关键随机试验、队列或诊断研究。
3. **病例适配：**核对来源的人群、地区、疾病阶段、干预、结局、版本和局限，再与用户明确提供的事实对应。

规范层确定行动和安全边界，研究层核对直接获益、风险、预后、诊断准确性和新证据。不要用单篇研究轻易推翻更适用的权威指南，也不要为展示工作量堆叠文献。某一层没有合格原文时如实说明检索局限并降低确定性。

## 4. 基于明确事实回答

- 只把用户明确提供的内容当作已知事实。用户没有提到的症状、检查或用药一律视为未知，不能推断为阴性。
- 保留起病、暴露、疗程、中断和复查的精确时间。例如“已治疗 3 个半月、停药 1 个月”不能压缩成“曾经治疗过”。
- 突发且幅度很大的化验变化，需要同时按真实异常保障安全，并尽快复采、核对单位、前后时点、采血通路、同期输液/输血、标本身份和检验误差；复核不能延误不稳定者处置。
- 信息不够时仍先回答当前可以确定的部分和安全行动，再用条件分支说明不同情况如何改变结论，并补问少量真正会改变判断或行动的信息。
- 用户补充信息后，先说明新信息使判断发生了什么变化；没有新的危急依据时，不重复或扩写上一轮已经说明的就医升级条件。
- 只有真实读取到附件时才声称查看或 OCR；用户粘贴的文字只是用户提供的信息。

## 5. 简明回答、确认和完整文档

### 默认简明回答

先给足够有用的答案，不把“简明”理解成只有免责声明或一句建议。内容按实际需要覆盖当前判断、行动、关键条件、必要风险和最相关来源；能用自然段讲清时可以直接使用自然段。就医升级提示按已知风险分层，只保留比较严重、会改变行动时限的少量短句：明显低风险时一句概括；复杂但资料不全、且无明确危急依据时，若列少量红旗信号，紧接着温和说明它们只是较严重变化的安全边界、不代表当前已经出现，并追问会改变判断的少量信息；已有可能风险信号时可较明确地说明升级条件。不用罕见重症或跨系统清单增加恐惧；后续轮次没有新的危急依据时不重复清单。若核心结论或最可能原因需要较充分解释，可以在直接结论之后设置一个完整的自然内容章节，用多段说明、列表或表格展开，不把它限制成开场引导段，也不因此自动进入完整文档；不要求每次固定生成同名章节。免责声明是最后一段医学内容，随后用一个自然的产品选择段结束。

收束保持固定语义而不是固定句子：如果还缺会改变判断的信息，指向前文最关键的少量补充项，说明补充后的价值；同时明确用户也可以回复“生成完整循证报告”，由系统先按现有信息整理更系统的分析，并标出待确认点和条件分支。不要重复问题清单，不要连续问“请补充……”和“是否生成……”两个割裂的问题。信息已足够时，只需简短邀请生成报告。

### 用户明确要求生成报告

“生成报告”“生成完整循证报告”“请生成文档”等清楚指向完整报告的表达才是明确报告意图。沿用本轮已经核验且仍适用的证据，补齐七章真正需要的证据，按需更新可选证据记录；不要机械重跑所有查询。直接创建一次完整文档、完整回读并交付，不重复简明回答，不再次询问。用户同时补充信息时先纳入报告；用户只补充医学信息时不自动建文档。

如果关键资料仍缺失，不要求用户必须补齐后才能生成，也不假装未知已经明确。生成条件化报告：区分能确定和不能决定的内容，列出真正会改变判断的缺口，使用“如果……那么……”说明分支，并保留不依赖缺失信息也成立的安全行动。涉及停换药、调量、手术等重大决定时，只整理证据、风险边界和确认路径。

### 用户拒绝或没有明确报告意图

不创建文档，不反复推销。用户补充新的医学信息时，把它作为新的问诊内容回答；如果仍属于普通简明回答，本轮结束时再按当前信息自然提供一次补充信息/报告选择。上一轮确实提供双入口或所指不清时，用户只说“是”“可以”“需要”等短句先简短确认其是否要生成报告，不据此直接创建；上一轮只有报告入口且语境清楚时，可以直接生成。
