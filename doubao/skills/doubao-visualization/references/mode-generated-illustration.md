# 生成式知识配图

## 读取门

编写 image plan、Prompt 或调用图片工具前，**必须完整读取**：

1. `mode-generated-illustration.md`
2. `generated-prompt-rules.md`
3. `generated-style-guide.md`
4. `generated-tool-contracts.md`
5. `shared-quality.md`

没有读完不得开始写 Prompt。需要完整多图规划示例时再读取 `examples/generated-worked-example.md`；example 不能替代规范文件。这些文件保留原知识配图 Skill 的标题、可见文字、视觉母题、风格、尺寸、工具路由和重试细则，模型版本相关条款以当前工具 schema 为准。

## 适用范围

用于图文结合讲解概念、机制、流程、角色关系、知识对比、历史脉络、教程章节和作品解读。可以直接根据可靠文字生成，也可以把用户原图作为外形、结构、材质或风格参考进行解释性重绘。

不用于精确数据图表、原图证据、真实 UI 操作路径、精确地图、严格测量或必须完全正确的几何关系。

## 用户原图策略

### 保持原图

若结论依赖真实位置、数量、文字、边界或证据，停止二次生成，改用原图叠加或原图交互。

### 作为生成参考

只有在用户明确要求或意图清楚地允许重绘、改风格、剖面化、简化或再创作时使用。Prompt 中说明应保留的外形、结构、材质和视角；不得声称生成结果是原图或精确复刻。

若工具支持参考图输入，按实际 schema 传递；若不支持，不伪造参数，可从原图提炼可观察特征后生成，并明确可能存在差异。

## 图文规划

先形成正文，再选择一图流或 2-4 张多图：

```text
article_sections:
- 每段只讲一个结论或子问题

image_plan:
- title
- subtopic
- content_scope
- visible_text_list
- visual_motif
- layout_role
- aspect_ratio_reason
- width
- height
- source_image_role: none | reference
```

每张图只使用对应段落信息；多图保持色板、标题、线条和材质统一，但子主题、视觉母题和构图角色不同。

## Prompt 原则

- Prompt 中只能出现用户信息、已确认事实、核验事实和从参考图直接观察到的特征。
- 主标题使用陈述式短标题；副标题补充一个新角度，不复述主标题。
- 单图通常 3-5 个信息模块，多图单页 2-4 个；短句尽量不超过 24 个汉字。
- 所有需要生成的文字使用中文引号 `“”` 标注；禁止额外文字、伪文字和水印。
- 先选择能承载解释的主视觉：机器、剖面、轨道、阶梯、循环系统、关系网、舞台、沙盘或时代长卷。
- 主视觉建议占 45%-70%，图形信息多于文字信息，有清晰阅读路径和主题化背景。
- 禁止“标题 + 若干等大卡片”、企业 PPT、表格截图、密集小字、低幼 Q 版和无关装饰。

## 尺寸

按信息关系选择，不统一套竖图：

- 中心机制、关系网络 → 2048×2048。
- 横向对比、三方格局 → 2048×1536。
- 时间线、长流程 → 2048×1152。
- 教程、纵向层级 → 1536×2048。
- 明确手机全屏长图 → 1152×2048。

聊天正文优先横图或方图，避免无理由竖图显示过小。

## 工具与版本

- 使用当前可用的官方图片生成工具，不调用本地私有脚本或猜测 HTTP API。
- 先读取实际工具 schema，再使用其支持的参考图、宽高、批量请求和模型版本参数。
- 若平台已经确认必须使用某个模型版本，应显式传入；若 schema 不支持或版本不可用，不强行提交未知字段，改用当前受支持模型或说明限制。
- 多图可批量提交，但每张图使用独立宽高和 Prompt；部分失败只重试失败项。

## 生成后检查

- 主视觉是否明显，是否退化成普通 PPT 卡片。
- 文字是否清晰、简短、无乱码、额外文字或裁切。
- 构图是否符合流程、时间、关系或对比结构。
- 参考图的必要特征是否保留，是否产生误导性变化。
- 多图是否统一但不重复。
- 若无法实际读取生成结果，不声称已完成视觉检查；明确限制，并以工具返回状态和更保守的 Prompt 为准。

输出中说明生成图是解释性图解；图片紧跟对应正文，不集中堆在结尾。
