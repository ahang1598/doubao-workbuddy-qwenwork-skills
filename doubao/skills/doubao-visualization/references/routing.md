## 一、判断可视化收益

以下任一条件成立即可进入规划：

- 用户明确要求可视化、图表、图解、信息图、标注、流程图、关系图、时间线、动画或交互。
- 内容包含趋势、占比、排行、分布、相关性或多指标比较。
- 答案依赖图片中的对象、位置、区域、数量、路径、匹配或差异。
- 参数变化、算法步骤、状态迁移、物理过程或几何约束需要观察过程。
- 流程、机制、架构、层级、人物关系、因果链、历史脉络或状态机用图能显著降低理解成本。

普通改写、翻译、简短定义、闲聊、安全拒答、纯文字已足够清楚，或用户明确不要图时，不强行可视化。

海报、头像、壁纸、写实图片和艺术插画创作不由本 Skill 承接。

## 二、确定任务目标

允许一个主目标和一个辅助目标：

- `data_analysis`：准确呈现数值、统计关系和可复核趋势。
- `knowledge_explanation`：解释流程、机制、结构、架构、关系、时间线和叙事。
- `visual_evidence`：指出用户原图中支持结论的真实证据。
- `dynamic_exploration`：通过操作或播放观察状态、因果或参数变化。

主目标决定主要输出，辅助目标只能增加互补模块。

## 三、确定素材策略

- `structured_data`：用户数据或合法核验数据。
- `user_image`：用户提供的原图。
- `text_context`：用户文字、附件内容或当前可靠答案。
- `verified_sources`：合法搜索或资料工具核验的事实。
- `none`：不依赖外部素材，自绘抽象结构。

### 用户原图策略

按顺序判断：

1. 结论是否依赖原图真实位置、数量、文字、边界或细节？是 → `preserve`。
2. 用户是否要求“在原图上”圈、标、连、点或演示？是 → `preserve`。
3. 用户是否明确要求简化成结构示意，且不要求写实或精确复刻？是 → `observe_for_schematic`。
4. 用户只上传图片但任务与图片没有必要联系？不要强行使用。
5. 意图不清且自绘可能损害事实时，默认 `preserve` 或简短确认。

`observe_for_schematic` 只允许提取可直接观察的结构特征并自绘 HTML/SVG，必须标明“示意”，不能替代原图证据。

## 四、选择呈现方式

### `echarts`

用于趋势、排行、占比、分布、相关性、层级、流向、漏斗和 K 线等精确图表。用户明确要求 ECharts/option 时直接选择。

### `static_image_overlay`

保持用户原图不变，在其上叠加点、框、线、箭头、路径、匹配和标签。只在标注有信息增量时使用。

### `html_svg`

用于确定性知识图解和动态演示：

- 流程、workflow、pipeline → 步骤流、泳道或阶段门。
- 机制、因果、反馈 → 因果链、回路或输入—处理—输出。
- 架构、分层、数据流 → 分层架构、组件连接或数据流。
- 人物、组织、角色关系 → 分组关系网、层级树或关系矩阵。
- 历史脉络、事件演进 → 时间线、阶段带或转折点。
- 生命周期、状态机 → 状态节点和迁移箭头。
- 比较、选型、差异 → 对比矩阵、双栏结构或坐标定位。
- 算法、证明、参数变化 → 分步画布、状态演示、滑块或曲线联动。

`html_svg_behavior` 默认选择 `static`。只有点击、拖动、播放、切换或参数变化能揭示新的状态、因果或过程时，才选择 `interactive`。

### `text_only`

可视化收益不足、事实或结构不足以可靠绘制，或用户明确只要文字时选择。

## 五、组合决策

默认选择一个 presentation。只有满足以下全部条件才增加第二个：

1. 单一模块遗漏独立核心目标；
2. 两个模块表达的信息不同；
3. 第二模块的理解收益明显大于额外复杂度；
4. 每个模块的事实和素材条件都满足。

推荐组合：

| 需求 | 组合 |
| --- | --- |
| 点击设备照片查看工作原理 | `preserve + html_svg(interactive)` |
| 将设备照片简化为结构示意 | `observe_for_schematic + html_svg(static)` |
| 在原图指出部件并展示参数趋势 | `static_image_overlay + echarts` |
| 基于截图逐步讲解状态变化 | `preserve + html_svg(interactive)` |
| 算法动画并比较每步耗时 | `html_svg(interactive) + echarts` |
| 历史文章展示事件演进 | `html_svg(static)` |

组合顺序通常为：文字结论 → 原图证据或原图交互 → 精确数据 → 辅助结构图解。

## 六、常见冲突

- **精确数据 vs 自绘图解**：标准统计图优先 ECharts；HTML/SVG 只承担数据图无法表达的结构。
- **原图证据 vs 示意图**：结论依赖原图时保持原图；示意图只能辅助理解。
- **ECharts option vs HTML ECharts**：普通数据图只输出原生 option；只有自定义交互需要 DOM 或多视图联动时才放入 renderer。
- **静态 vs 交互**：静态图已能讲清时，静态默认且优先；交互必须具有解释价值或明显增加理解。
- **知识结构 vs 纯文字**：节点、边、顺序、层级或状态可准确枚举时优先 HTML/SVG；无法可靠确定时用文字。
- **地图需求**：所有模式均禁止地图渲染，改为非地图表达。

## 七、降级顺序

1. 复杂交互 HTML/SVG → 静态 HTML/SVG。
2. 外部库方案 → 纯 HTML/SVG/Canvas。
3. HTML/SVG 无法可靠表达 → 结构化文字。

不因可视化失败而调用图片创作能力。
