# 多模式组合

## 什么时候组合

只有单一模块无法完整回答两个独立核心目标时组合。默认不超过两个可视化模块；确需更多时按章节拆分，不做一张“万能大图”。

## 模块职责

- 原图叠加：证明“图中哪里支持结论”。
- 原图交互：解释“点击、切换或逐步变化时发生什么”。
- ECharts：表达“准确数据如何变化或比较”。
- 生成配图：解释“机制、结构、背景和知识关系如何理解”。

不要让两个模块承担同一职责。

## 推荐组合

### 原图 + 交互

把原图作为 HTML 底图，交互层负责点击区域、分步高亮和说明面板。不要先输出一份静态标注，再重复输出相同交互标注；一个交互模块即可。

### 原图 + ECharts

先用原图指出部件或采集位置，再用 ECharts 展示对应参数。部件名称、颜色和单位保持一致。

### 交互 + ECharts

当参数调整需要同步改变精确曲线时，可在一个 HTML renderer 内联动；若只需静态对比，则分为交互示意和原生 ECharts 两个模块，降低复杂度。

### 原图参考 + 生成配图

输入原图仅作为参考。输出说明“基于原图特征的解释性重绘”；不要同时把生成图作为原图证据。

### ECharts + 生成配图

ECharts 显示准确数据，生成配图解释背后机制。数据图在前，知识图在后；不要让生成图重复显示精确数字。

## 顺序与文字

1. 先给核心结论。
2. 原图证据或原图交互优先，因为它连接用户提供素材。
3. 精确数据图表随后，解释量化关系。
4. 生成式配图最后或紧跟相关知识段落，用于理解而非证明。
5. 每个模块前只解释它回答的问题，模块后给一个 takeaway。

## 冲突处理

- 两个模块结论不一致：停止交付，重新核对事实和数据。
- 原图和生成图外观差异大：以原图为准并标注生成图为示意，必要时重试或取消生成图。
- 页面过长：保留主模块，辅助内容改成文字或拆章节。
- 工具能力不足：优先保留确定性、可验证的模块。
