# 多模式组合

## 什么时候组合

只有单一模块无法完整回答两个独立核心目标时组合。默认不超过两个可视化模块；确需更多时按章节拆分，不做一张“万能大图”。

## 模块职责

- 原图叠加：证明“图中哪里支持结论”。
- 原图 HTML/SVG 交互：解释“点击、切换或逐步变化时发生什么”。
- ECharts：表达“准确数据如何变化或比较”。
- 静态 HTML/SVG：解释“流程、机制、架构、关系、时间线或状态如何组织”。

不要让两个模块承担同一职责。

## 推荐组合

### 原图 + HTML/SVG 交互

把原图作为 HTML 底图，交互层负责点击区域、分步高亮和说明面板。不要先输出静态标注，再重复输出相同交互标注；一个交互模块即可。

### 原图 + ECharts

先用原图指出部件或采集位置，再用 ECharts 展示对应参数。部件名称、颜色和单位保持一致。

### HTML/SVG 交互 + ECharts

当参数调整需要同步改变精确曲线时，可在一个 renderer 内联动；若只需静态对比，则分为结构示意和原生 ECharts 两个模块。

### 静态 HTML/SVG + ECharts

ECharts 显示准确数据，静态 HTML/SVG 解释背后的确定性机制。数据图在前，机制图在后；不要在机制图中重复精确数字。

### 原图 + 静态 HTML/SVG

原图承担事实证据，静态 HTML/SVG 只抽象原图外的流程、连接或原理。若示意结构来自原图观察，必须标注“示意”，并以原图为准。

## 顺序与文字

1. 先给核心结论。
2. 原图证据或原图交互优先。
3. 精确数据图表随后。
4. 静态 HTML/SVG 紧跟对应知识段落。
5. 每个模块前只解释它回答的问题，模块后给一个 takeaway。

## 冲突处理

- 两个模块结论不一致：停止交付，重新核对事实和数据。
- 原图与结构示意不一致：以原图为准，修正或取消示意。
- 页面过长：保留主模块，辅助内容改成文字或拆章节。
- 交互不稳定：降级为静态 HTML/SVG。
- 工具能力不足：优先保留确定性、可验证的模块。
