## §A HTML 硬约束（渲染环境强制，违反则不渲染）

- 用 ` ```html type="renderer" ` 代码块包裹；**禁** `<!DOCTYPE>`/`<head>`/`<body>`/`<TEXT>`。
- 回复里**第一个** renderer 块外层：`<html style="margin:0;padding:0;">` + 一个 `<div style="background:transparent;">`；同一回复后续块直接 `<div …>` 起手（不重复 `<html>`）。
- 所有 CSS **内联** `style="…"`；`<style>` 标签只允许写伪元素（如 `::-webkit-slider-thumb`）。单条 style ≤ 250 字符。
- **全局禁**：`box-shadow`、`height:100vh`/`min-height:100vh`、固定 `height`、外部 CSS 链接，以及**任何视口单位 `vh`/`vw`/`vmin`/`vmax` 和 `min()`/`max()`/`clamp()`**（端上无真实视口，`vh` 会时而被忽略、时而≈0 把图缩成极小）。图像舞台高度默认交给图片本身 `height:auto`；**所有 `<img>` 统一按"在 `max-width` 与 `max-height` 约束框内严格等比缩放、并尽量放大到可显示最大尺寸"的规则渲染**：使用 `width:auto;height:auto;max-width:100%;max-height:720px`（**固定 px，不用 vh**），要求图片始终保持原始宽高比、不得拉伸或压缩变形；在满足 `width<=100%` 且 `height<=max-height=720px` 的前提下，渲染结果需尽可能大，并使宽或高至少有一边触达对应上限。舞台用 `display:inline-block;max-width:100%` 收缩包住图，`#svp` 用 `text-align:center` 居中；这是纯静态 CSS，不用 JS 判方向。
- 顶层 `width:100%`（按约 784px 宿主设计），外层 `background:transparent; border:none;`。
- 公式用 Unicode（π ω Σ √ ≈ ²），禁 LaTeX。
- **JS 稳定性（Shadow DOM）**：`(function(){ try{ … }catch(e){console.error(e);} })();` 包裹；取 DOM 后判空 `if(!el)return;`；**禁 `DOMContentLoaded`**（不触发，直接执行）；自包含、不访问外部变量；**不引外部库/CDN**（标注用内联 SVG + 绝对定位即可）。
- `<img>` 用真实 https URL（保留完整 TOS 参数），样式统一为 `width:auto;max-width:100%;height:auto;max-height:720px;display:block;border-radius:6px;`；不要再使用会强制竖图铺满宽度的 `width:100%` 版本。

## §B 坐标转换 + 两层舞台（这里最容易画出畸变，务必照做）

process 的坐标是 0-999 相对值。把它们变成画面位置，**有且仅有这一处**换算，用"占舞台百分比"而非像素（天然抗缩放、无需图像宽高）。舞台固定两层：

```
<div style="position:relative;width:100%;">            ← 舞台
  <img … style="width:100%;height:auto;display:block;">
  <svg class="lines" viewBox="0 0 999 999" preserveAspectRatio="none"
       style="position:absolute;inset:0;width:100%;height:100%;pointer-events:none;overflow:visible;"></svg>   ← 只画线/路径/框
  <div class="layer" style="position:absolute;inset:0;pointer-events:none;"></div>   ← 画所有圆点/胶囊/文字/符号
</div>
```

**【硬性分工 —— 违反就会畸变】**
那张 `viewBox="0 0 999 999" preserveAspectRatio="none"` 的 SVG 是把一个**正方形坐标系强行拉成图片的真实长宽比**：直线 / 折线 / 路径 / 矩形的**顶点**仍落在正确位置（所以它们能用），但任何**本该是圆/正比例的东西会被拉成椭圆、文字会被拉伸变形**。因此：

- ✅ **SVG 层 `.lines` 只允许**：`<line>` / `<polyline>` / `<path>` / `<rect>`（连线、路径、生长轨迹、bbox 框）。所有描边必须 `vector-effect="non-scaling-stroke"`。
- ❌ **SVG 层里绝对禁止** `<circle>` / `<ellipse>` / `<text>` / `<image>` / 任何圆点、序号、字幕、✕✓ 符号——它们一进这个被拉伸的 viewBox 就变形（圆变椭圆、字变扁/长）。
- ✅ **所有圆点、序号、label 胶囊、✕✓ 等符号一律放 `.layer`（HTML `<div>`）**，用百分比定位：`left=(x/999*100)+'%'`、`top=(y/999*100)+'%'` + `transform:translate(-50%,-50%)`。div 不受 SVG 拉伸影响，圆永远是正圆、字永远不变形。

换算口径：
- div 标记：`left=(x/999*100)+'%'`，`top=(y/999*100)+'%'`。
- SVG 线/框：直接把 0-999 当坐标写进属性（viewBox 自动换算），**不做 JS 数学、不碰像素、不碰图像宽高**。
- **process 必须作为数据内嵌 + JS 解析驱动**：把整份 process 放进 `<script type="application/json" id="...">{…process…}</script>`，JS 里 `JSON.parse(el.textContent)`，**遍历 steps/coords 动态生成标记**。**禁止把坐标（无论 0-999、百分比还是像素）手敲进各个元素**——所有位置只能由代码从 process 算出来。

## §C 各类别视觉标准（freehand：自己实现成这个样子）

**通用 · 标记长什么样（关键，别画丑）**：

- **一切圆点 / 序号 / 文字 / 符号都是 `.layer` 里的 HTML `<div>`**（见 §B），不进 SVG，保证不变形。
- **点标记 = 小圆点 + 旁置胶囊**：圆点直径约 **14-18px**、实心语义色、**2px 白描边**即可；**点内不写数字、不做大色块**——绝不画成又大又实心、中间塞编号的"大圆饼"（≥24px 实心圆中央写号，既丑又遮挡原图，这是反面教材）。序号 / label 放在圆点**旁边**的小胶囊里（圆角、半透明底、12px）。
- **半透明、让原图透出**：标记常态（idle）透明度约 **0.55**，不要做成纯不透明大色块盖住原图——原图可见性优先，标记彼此重叠时也能透出下面的内容；只有 hover 聚焦的那一项才升到 1.0（见 §E 交互）。
- 每条证据的 `label`（process 给的非空字幕）要显示：稀疏时用点旁胶囊；拥挤时点旁只留小序号、详细 label 进图例（见 §E）。

按 process 每个 step 的 `type` 决定画法：

- **count_pop（计数/枚举）**：每个物体一个**小圆点**（见上）；序号 / label 放点旁小胶囊或进图例，**不要把序号塞进放大的实心圆里**。顶部或角落给一个总数徽标"共 N 个"。
- **match_pair（配对/归属）**：每个 match_pair step 就是**一对**（2 个 coord）——画**一条连线**（SVG，`non-scaling-stroke`，可虚线）连两端 + 两端落点 + 小胶囊标注归属。多对会是多个 match_pair step：**每对一种颜色**、不同对换色。
- **path_grow（迷宫/连线/轨迹/遍历/边界）**：一条 polyline 按序穿过全部点（静态画出整条）；起点/终点各一个 div 标记区分；**线不重描、不回跳、不抄近路**。**线色必须和迷宫墙/背景明显区分**（深底/同色系底上给线垫一条更宽的白色底线，保证在任何墙色上都看得清，别撞色糊在一起）。
- **node_walk（A→B 方向指引/单跳）**：SVG 画一条 A→B 有向线且**必带真箭头头**——`<defs><marker id="ah" markerWidth="9" markerHeight="9" refX="7" refY="3" orient="auto"><path d="M0,0 L7,3 L0,6 Z" fill="语义色"/></marker></defs>`，线加 `marker-end="url(#ah)"` + `non-scaling-stroke`；深底给线垫一条更宽白线或 `filter:drop-shadow(0 0 1px #fff)`。A 端小圆点锚起点、B 端箭头贴住目标；线短促、指向明确。**禁**用字符箭头（▶ →）或无箭头头的裸线充当箭头。
- **bbox_zoom（ROI 读数/聚焦）**：矩形描边 + 极淡填充（≤8% 透明度），紧贴关键细节；可选把 ROI 以外区域加一层半透明遮罩做"聚焦"；标签胶囊贴边、不挡内容。
- **default（轻强调）**：1-2 个锚点圆点 + 胶囊即可。

> 选错类别比画得糙更糟：照 process 的 `type` 来；并列同类物=count_pop，连续轨迹=path_grow，两两映射=match_pair，A→B 方向/指路=node_walk，框区域=bbox_zoom。

## §D 配色（低饱和语义色，点睛而非铺场）

- **颜色由你自己按语义选**（process 不含颜色字段）。推荐调色板（低饱和，与原图不抢）：强调/主体 靛灰蓝 `#4F46E5`；成功/正确 `#355E4B`、描边 `#5B9279`；警告/注意 `#7C5A33`、描边 `#C99A4E`；错误/排除 `#7A3F3F`、描边 `#C06A6A`；中性 `#4B5563`。同类对象同色，对比项用不同语义色。
- **禁止 raw 高饱和原色**：不要用 `#4CAF50`/`#2196F3`/`#f44336`/`#FF9800`/`red`/`lime`/`blue` 这类刺眼原色，一律用上面的低饱和语义色。
- **必须与背景对比、不撞色（关键）**：下笔前先判断标记要压上去的那块图像底色 / 前景色。**线 / 路径的颜色绝不能和它穿过的物体同色系**——迷宫墙是绿/深色就别用绿线，浅底用深色描边、深底用亮描边 + 白外发光（如 `filter:drop-shadow(0 0 1px #fff)` 或给线加一条更宽的白色底线垫在下面）保证任何底上都看得清。
- 胶囊底：`rgba(17,24,39,0.62)` + 白字 `#fff` + 语义色 1px 描边；填充块透明度 ≤8%。**胶囊 / 图例底必须包住文字**：`white-space:nowrap` 须配 `max-width` + `overflow:hidden;text-overflow:ellipsis`，或允许换行——字不许溢出色块外。
- **每张图最多 2 个色相**（语义对比可破例但克制）；accent 主色 ≤1 处大用；饱和度整体克制，别盖过原图。
- 图例文字 12-13px；图上 caption 11-12px；总数/结论徽标可加粗。

## §E 单图布局 + 防拥挤 + 交互

**默认单图合并**：单图任务把所有证据画进同一张舞台图。拥挤时（点多/标签长）这样化解，而非拆成多图：

- 标记**编号化**（图上只留小编号圆点），把 `label` 移到图**右侧或下方的图例列**（`<ol>`，每行：色点 + 编号 + label），用编号一一对应。
- 标签可能互相压住时，用细引导线（leader）把胶囊拉到留白处；或降低非聚焦标记透明度。
- 标记 ≥2 个时**必须**给图例（避免图上字幕堆叠）。
- 版心稳、留白足；分隔用留白或 `1px solid #E5E7EB` 细线，不用阴影。

**多图任务（process 里带 `images`/`img`）**：**每张图各一座独立舞台**（各自 `<img>`+SVG+`.layer`），按 `images` 顺序纵向排列，坐标 0-999 相对**各自那张图**；**禁止重复铺同一张图 / 输出空白舞台**——附件几张就几座舞台，绝不多也不少。跨图对应（同一物体 / 对比 / 配对）用 `match_pair`：两端 coord `img` 不同，画连线（若跨舞台连线难画，则两端用同色胶囊 + hover 联动高亮替代）。对应关系不明确时，只标主图、其余图不硬凑。

**交互（桌面 hover + 移动端 click/tap + idle 半透明）**：

- **idle 半透明**：所有标记常态 opacity ≈ **0.55**（让原图透出，标记彼此重叠时也能看清下面内容）。**禁止**做成"纯不透明 → 一直全亮"的死标记。
- **联动必须全覆盖**：桌面端悬停某标记 / 胶囊 / 图例行，或移动端点击/轻触对应项 → 该项升到 1.0 并轻微放大，**其余降到 ~0.16**；移开、再次点击或点击空白复原到 idle。
  - **每一个标记都要绑**：计数点、配对点、单只点、排除/聚焦框……一个都不能漏（最关键的结论点尤其不能是死的）。
  - **图例行也要绑、且双向**：图例操作高亮对应标记，标记操作也高亮对应图例行。
  - 实现：标记 / 胶囊 / 图例 `pointer-events:auto`；同时绑定 `mouseenter/mouseleave` 与 `click`，按"同一证据 = 同一组"统一改透明度，**别依赖 CSS `:hover` 跨元素**。（Gold 示例中的 `bindHover`/`setActive` 仅展示桌面基础实现；实际交付需在其上补 click/tap。）
- 标记加载即以 idle 半透明呈现；核心结论必须已在正文和静态初始状态中表达，不依赖交互才能理解。
- 交互失败时至少保留前置文字答案和原图。由于标记由 JS 根据 process 动态生成，不得宣称脚本解析失败后标记仍一定存在；需要更强降级时，应预渲染静态标记而不是只依赖运行时生成。

## §F 发送前自检（逐条过，全过才发）

1. **零泄漏单趟 + 可视化在末尾**：回复第一字符是讲解实质内容，先把讲解与答案写完、**可视化放在回复最末尾**（让用户先读到结论）；正文收尾**可用一句自然的衔接**引出末图（面向内容，如"我把…都标在图上了，对照看更清楚"），但无"我来帮你…并把过程可视化展示出来 / 做可视化标记 / 让我先看图规划 / 下面是可视化 / 见下图"这类**机制式预告或点名**；无工具/文件/process/JSON/坐标/skill 痕迹，无"创建/校验/渲染/验证通过"旁白。
2. **HTML 约束**：` ```html type="renderer" ` 包裹；无 DOCTYPE/head/body；CSS 内联；无 box-shadow / `height:100vh` / 固定 `height` / **视口单位 vh·vw 与 min()·max()·clamp()**（竖高图舞台可用固定 `max-height:720px` + `width:auto` 限高，见 §A）；首块 `<html>`+透明 `<div>`；JS 为 IIFE+try/catch+判空、无 DOMContentLoaded、无外部库。
3. **图片**：真实 https URL（含完整 TOS 参数），非本地/base64/裸 URI。
4. **process 内嵌 + 真画出标记 + 无硬编码**：整份 process 以 `<script type="application/json">` 内嵌、**合法非空 JSON**、JS `JSON.parse` 后遍历生成标记，**图上确有标记画出**（只铺原图 / 空 svpdata / 解析失败 = 失败）；位置全由 0-999 经 §B 百分比/viewBox 算出，**没有任何手敲坐标**；SVG 描边带 `non-scaling-stroke`。
5. **无畸变（关键）**：`preserveAspectRatio="none"` 的 SVG 里**只有** line/polyline/path/rect；**没有任何** `<circle>`/`<ellipse>`/`<text>`；所有圆点 / 序号 / 字幕 / 符号都是 `.layer` 的 HTML div（圆是正圆、字不拉伸）。
6. **类别正确 + 标记不丑**：按 process 每步 `type` 画，各按 §C 标准；点标记是**小圆点 + 旁置胶囊**，无"大圆饼塞数字"。
7. **配色 + 对比**：≤2 色相、低饱和、无 raw 高饱和原色；线/路径与所穿过物体**不撞色**、任意底色上都看得清；标记不盖过原图。
8. **交互全覆盖**：标记 idle 半透明（≈0.55）不是死全亮；hover 与 click/tap 联动**绑到每一个标记（含单只 / 排除点）+ 每一行图例**、且图↔图例双向（该组升 1.0、其余降 ~0.16）；JS 失败时仍有前置文字答案和原图，不虚假承诺动态标记仍在。
9. **图上忠实**：每个标记真的压在它 `label` 所述、**图中真实存在**的物体上（找不到就不标，绝不凭空标空白 / 不存在的物体）；每条结论都有图上对应标记；近似/不确定在文字里诚实说明。
10. **不拥挤 + 图数正确**：≥2 标记 → 有图例；密集时已编号化 + leader 线；版心干净；单图任务一张讲清；多图任务每张各一座舞台、按序排列、**不重复铺图 / 不留空白舞台**（舞台数 = 附件数）。
