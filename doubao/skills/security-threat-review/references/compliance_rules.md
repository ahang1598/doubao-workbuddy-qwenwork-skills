# 安全设计合规规则

## 规则包：secure_design（安全设计基线）

本规则包包含 12 条通用安全设计基线规则，适用于绝大多数互联网服务和企业应用的设计评审。每条规则包含：规则编号、规则内容、验证方法、严重级别。

### SD-01：外部入口服务端认证

- **规则**：每个外部入口点都在服务端对调用方进行认证
- **验证方法**：列出所有公网/外部入口点，确认每个都在服务端（而非客户端）强制执行认证
- **严重级别**：high
- **常见缺口**：内部 API 误暴露到公网无认证、API Key 在客户端校验、JWT 仅前端校验

### SD-02：对象级/租户级授权

- **规则**：授权按对象/租户粒度执行，而非仅按角色（无 IDOR）
- **验证方法**：对每个资源访问操作，确认存在对象级/租户级授权检查
- **严重级别**：high
- **常见缺口**：仅检查用户是否登录，未检查用户是否有权访问该具体资源；多租户系统未隔离租户数据

### SD-03：密钥通过 Vault/KMS 管理

- **规则**：密钥通过密钥管理服务（Vault/KMS）管理，绝不写入代码、配置或镜像
- **验证方法**：确认凭证/密钥从密钥管理服务注入，而非硬编码或打包到制品中
- **严重级别**：critical
- **常见缺口**：API Key 写在配置文件中、数据库密码硬编码在代码里、密钥提交到 Git 仓库

### SD-04：传输层 TLS

- **规则**：传输中的数据使用 TLS 且启用证书校验
- **验证方法**：确认所有服务间和客户端流量使用 TLS；确认证书校验未被禁用
- **严重级别**：high
- **常见缺口**：服务间调用使用 HTTP、TLS 证书校验被跳过（InsecureSkipVerify）、使用自签名证书无校验

### SD-05：敏感数据静态加密

- **规则**：静态敏感数据使用托管密钥加密
- **验证方法**：确认存储敏感数据的数据库/对象存储/磁盘启用了静态加密
- **严重级别**：medium
- **常见缺口**：用户密码明文存储、PII 数据未加密、加密密钥与数据同库存储

### SD-06：输入校验与边界

- **规则**：输入经过校验和边界限制（大小、类型、长度、字符集）
- **验证方法**：对每个输入面，确认存在服务端校验 + 大小/超时限制
- **严重级别**：medium
- **常见缺口**：无请求体大小限制、文件上传无类型/大小校验、字符串长度无限制、数值无范围校验

### SD-07：安全操作审计日志

- **规则**：安全相关操作写入不可篡改的审计日志
- **验证方法**：确认认证、权限变更、数据导出、配置变更等操作记录了用户+时间戳+操作详情
- **严重级别**：medium
- **常见缺口**：管理操作无日志、审计日志可被管理员删除、日志缺少操作人标识

### SD-08：公网端点限流

- **规则**：公网端点强制执行限流/节流/背压
- **验证方法**：确认公网或多租户路径存在速率限制和资源上限
- **严重级别**：medium
- **常见缺口**：登录接口无防暴力破解限流、API 无 QPS 限制、大查询无超时/取消机制

### SD-09：错误信息不泄露内部细节

- **规则**：错误响应不泄露内部信息（堆栈跟踪、主机名、版本、密钥）
- **验证方法**：确认客户端收到的错误响应是通用的；详细信息仅在服务端日志中
- **严重级别**：low
- **常见缺口**：生产环境开启 debug 模式、异常堆栈直接返回给客户端、错误信息包含 SQL 语句

### SD-10：依赖锁定与漏洞扫描

- **规则**：依赖和基础镜像锁定版本，并扫描已知 CVE
- **验证方法**：确认使用锁定版本（lock 文件），构建流水线包含漏洞扫描步骤
- **严重级别**：medium
- **常见缺口**：使用 latest 标签、依赖版本浮动、无 SCA 扫描、基础镜像长期未更新

### SD-11：管理面网络隔离与强认证

- **规则**：特权/管理路径网络隔离，并要求步进式认证
- **验证方法**：确认管理/控制平面在网络策略之后，并使用强认证（MFA/SSO）
- **严重级别**：high
- **常见缺口**：管理后台可从公网访问、运维接口无认证、跳板机无 MFA、内网管理面无访问控制

### SD-12：LLM/Agent 组件有成本和循环上限

- **规则**：LLM/Agent 组件有成本、循环和工具使用上限（无无限自主）
- **验证方法**：如果存在 LLM/Agent 组件，确认有 Token/迭代/工具调用次数上限和输出校验
- **严重级别**：high
- **常见缺口**：Agent 最大迭代次数未设置、工具调用无次数限制、用户输入可触发无限循环、输出未做结构化校验

## 规则判定标准

| 状态 | 含义 |
|------|------|
| pass | 设计文档明确描述了满足该规则的控制措施 |
| partial | 部分满足，存在明显缺口或控制措施不完整 |
| fail | 未满足，或设计与规则要求矛盾 |
| na | 该规则不适用于此系统（需在 gap 中说明原因） |

## 判定原则

1. **不假设控制存在**：如果文档未明确描述某个安全控制，不应假设它存在；应标记为 fail 或 partial，并在 gap 中说明"文档未提及"
2. **区分设计与实现**：合规检查基于设计文档，不评估实际代码实现。设计中描述了控制即视为 pass，即使实现可能有缺陷
3. **证据引用**：每条判定应引用文档中的相关内容作为依据
4. **可操作建议**：fail/partial 项必须给出具体的整改建议，不能只说"需要加强安全"
5. **全覆盖**：22 条规则（12 + 10）必须逐条给出结论。文档中完全找不到相关内容的规则，判定为 na（gap 填写"文档未提及相关内容"），不得遗漏

## 规则包：owasp_top10（OWASP Top 10 设计审查）

本规则包基于 OWASP Top 10（最新版），从设计评审角度重新表述为检查项。每条规则包含：规则编号、规则内容、验证方法、严重级别。

### A01：访问控制失效

- **规则**：Broken Access Control — 授权在服务端按对象粒度执行
- **验证方法**：检查每个受保护资源的访问控制；deny-by-default；不信任客户端的授权判断
- **严重级别**：high
- **常见缺口**：客户端控制授权、缺少对象级检查、管理路径无访问控制

### A02：加密失败

- **规则**：Cryptographic Failures — 敏感数据在传输和存储时受到保护
- **验证方法**：确认 TLS 启用证书校验、静态加密、强密钥管理、无弱/弃用密码套件
- **严重级别**：high
- **常见缺口**：明文传输、TLS 证书校验被跳过、弱加密算法、密钥管理不当

### A03：注入

- **规则**：Injection — 不可信输入与命令/查询分离（SQL、命令、Prompt）
- **验证方法**：确认使用参数化查询、无 shell 拼接、LLM 调用有 Prompt 注入隔离
- **严重级别**：high
- **常见缺口**：SQL 拼接、命令注入、LLM Prompt 注入无隔离

### A04：不安全设计

- **规则**：Insecure Design — 设计中考虑了滥用场景和信任边界
- **验证方法**：确认设计建模了信任边界、限流和滥用场景（不仅仅是正常路径）
- **严重级别**：medium
- **常见缺口**：仅设计正常路径、未考虑滥用场景、无信任边界建模

### A05：安全配置错误

- **规则**：Security Misconfiguration — 安全默认值，无调试/管理面暴露
- **验证方法**：确认加固默认值、禁用调试端点、最小权限配置、无默认凭证
- **严重级别**：medium
- **常见缺口**：默认凭证未改、调试端点暴露、权限过宽、默认配置不安全

### A06：脆弱和过时的组件

- **规则**：Vulnerable & Outdated Components — 依赖追踪、锁定版本、扫描 CVE
- **验证方法**：确认有依赖清单 + 自动化 CVE 扫描 + 补丁流程
- **严重级别**：medium
- **常见缺口**：无依赖清单、版本未锁定、无漏洞扫描、基础镜像长期不更新

### A07：身份认证失败

- **规则**：Identification & Authentication Failures — 强认证、会话管理
- **验证方法**：确认敏感访问有 MFA、安全会话 Token、轮换、锁定、无凭证暴露
- **严重级别**：high
- **常见缺口**：无 MFA、会话 Token 不安全、无锁定机制、凭证暴露

### A08：软件和数据完整性失败

- **规则**：Software & Data Integrity Failures — CI/CD 和更新有完整性保护
- **验证方法**：确认签名制品、受保护流水线、依赖完整性验证（如 lockfile、SBOM）
- **严重级别**：medium
- **常见缺口**：制品未签名、流水线可篡改、无依赖完整性验证

### A09：安全日志和监控失败

- **规则**：Security Logging & Monitoring Failures — 安全事件可审计、可告警
- **验证方法**：确认认证/访问/失败有日志、集中化、防篡改、有告警
- **严重级别**：medium
- **常见缺口**：无安全日志、日志分散、日志可篡改、无告警

### A10：服务端请求伪造（SSRF）

- **规则**：Server-Side Request Forgery — 出站请求经验证和白名单过滤
- **验证方法**：确认获取用户提供 URL 的组件验证了 host/scheme 白名单；阻断内部元数据 IP
- **严重级别**：high
- **常见缺口**：用户可控 URL 无校验、可访问内部元数据服务（169.254.169.254）、无出站白名单
