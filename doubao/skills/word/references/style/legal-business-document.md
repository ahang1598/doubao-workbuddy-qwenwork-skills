# 专业法律文书与商务协议写作指南

## 一、适用范围与核心要求

适用于法律意见、诉辩申请、函件、合同协议及其审查修改。

**写作哲学：以真实事实和适用法律为基础，帮助用户维护合法权益、安排交易，并作出有依据的决定。** 法律文书应说明主张为何成立、结论受什么条件限制。商务协议应让交易能够完成，并妥善安排关键风险。好的文书能抓住决定成败的问题，给出符合用户立场的处理，让使用者知道下一步怎样行动。

**质量标准：专业判断有依据，正文足以支持使用，Word 排版符合要求。** Agent 须用这一标准指导规划、写作和终稿检查。将判断落实为论证和条款。

材料读取与文件处理沿用 [SKILL.md](../../SKILL.md) 和 [writing-taxonomy.md](writing-taxonomy.md)。规划仍记入原 `outline.md` 或 `edit_plan`。

## Roadmap: Agent 执行路径

1. **确定文种与事实**：明确法律关系和立场，完整利用范围内事实。
2. **核验依据并完成正文**：查明适用规则，形成主张或条款，按体例成文。
3. **完成 Word 排版**：组织版面，落实格式要求。
4. **检查与交付**：验证实际用途，检查内容与格式，再交付。

新建按四步执行。审查修改用同一方法定位问题，再给出必要修改。局部任务只处理授权范围内的目标及关联项。新材料改变判断时，返回相应步骤。

## 步骤1：确定文种与事实

### 1.1 确定起草条件

**文种与关系：** 先确定要写哪类文书，再明确所处理的法律关系。例如借款合同，要分清谁向谁借款，以及双方的主体类型。

**起草立场：** 明确代表谁、希望实现什么结果。据此确定重点保护的利益和必须核实的问题。

**交付要求：** 明确起草或修改的范围，落实用户的模板与提交要求。篇幅预算包括签署区及交付附件。

### 1.2 完整使用事实，守住使用范围

**完整利用：** 读完全部用户材料，逐项记录事实的原文位置与使用范围。在原规划中安排正文落点，范围内事实都须按原有事实状态写入。

**事实边界：** 当事人陈述按陈述使用，证据按其证明范围使用。用户未提供的信息不可编造，如需使用时必须留下展位；引用法律条例等，必须搜索校验后再交付

方案核对： 在正文定稿前，核对以下三件事：
- 数字算得出： 将具体数字代入公式。例如，所有报价都为100元时，继续计算每一步，确认最终仍能得到结果。
- 条款对得上： 读到“前述责任上限”时，回查前文是否确实规定了最高赔偿额。
- 条件保得住： 对照用户原要求核金额和权益比例。条件无法同时满足时，指出具体冲突，并将调整方案列为待确认。

### 1.3 起草前识别易错点

| 容易出错表现 | 禁止项 |
|---|---|
| **事实漏用**：已给的事实或限制条件未进入文书。 | 禁止遗漏范围内事实，或删去改变含义的限定条件。 |
| **改变条件**：每人出资100万元被改成99万元。 | 禁止擅改已定条件，或补造事实与合意。 |
| **错用法源**：条号错配 | 禁止凭记忆填写条号，或用未核规则支持结论。 |
| **机制失效**：最低赔偿被称为责任上限 | 禁止只列出条款或公式，不验证是否合法合规 |
| **正文缺项**：容易漏掉落款（身份、机构、日期等比必备的要素） | 禁止删去必要身份与签署信息。 |
| **多轮遗漏**：补充证据后，原有有效争点消失。 | 禁止在同案增补中丢弃有效事实与论证。 |

## 步骤2：核验依据并完成正文

### 2.1 核验依据

**法条核验：** 所有拟引用的法律规范，写入前都须搜索并打开官方正式原文。核名称、条号及原文，查修订、施行和废止状态。再匹配本案主体、地区与时间，确定适用版本。

**数据核验：** 补充的外部事实与数值参数，均须查证原始来源。利率等动态参数匹配适用时点。由用户数据推算的结果须复算，明确金额口径与计算对象。用户未提供的用户侧事实信息禁止编造，必须留下占位。

**条款核验：** 按法律关系查明强制要求与限制，检验拟议安排是否合法、能否获得法律支持。例如借款先区分借贷类型，再核利率与费用限制；金额是否受限也按主体和业务判断。具体数值经核验与复算后写入。

按问题选择下列中国内地入口。其他法域或地方事项查对应官方来源，仲裁查对应机构规则。
**核验记录：** 在原底稿逐项记录事实、数值或判断的来源位置与链接。法律规范另记版本和条款，动态来源记查询日。未完成核验的部分标为待核，说明受影响内容。

| 要查什么 | 优先入口 |
|---|---|
| 法律及历史版本 | [国家法律法规数据库](https://flk.npc.gov.cn/) |
| 行政法规、规章 | [国家行政法规库](https://xzfg.moj.gov.cn/)；[国家规章库](https://www.gov.cn/zhengce/xxgk/gjgzk/index.htm) |
| 司法规则与类案 | [最高法](https://www.court.gov.cn/)；[最高检](https://www.spp.gov.cn/)；[人民法院案例库](https://rmfyalk.court.gov.cn/) |
| 文种示范与业务方法 | [最高法诉状示范文本](https://www.court.gov.cn/fabu/xiangqing/468671.html)；[合同示范文本库](https://htsfwb.samr.gov.cn/)；[全国律协](https://www.acla.org.cn/) |
| 动态参数与主体登记 | [中国人民银行](https://www.pbc.gov.cn/)；[LPR](https://www.chinamoney.org.cn/chinese/bklpr/)；[企业信用信息公示系统](https://www.gsxt.gov.cn/) |


### 2.2 形成处理方案

按文书目的选择以下两类方法。同一任务涉及两者时分别处理，专业信息随问题补查。

**法律主张：** 围绕请求或问题，逐项检验成立条件。将事实证据对应到适用规则，回应关键反证。依适用证明标准判断证据能否支持结论。诉辩先核受理条件与期限。证据程序争议先定位环节，再判断瑕疵后果。

**交易安排：** 先走通正常履行，再处理最影响交易目的的异常。写清各方在什么条件下做什么，明确期限和确认凭证，衔接补救与结算。依据适用法律和已定条件，结合控制能力与事件成因安排责任。重要取舍须符合用户立场，并说明理由与代价，但都需要在合法合规范围内。

形成方案后，检验条件能否同时成立。用户要求与适用规则冲突时，说明影响并提出可行调整。评分或分配规则用正常与边界输入试算。

### 2.3 组织正文

**结构：** 按该类文书的正式结构顺序组织内容，落实适用的法定事项。在其允许范围内遵循用户要求及模板。按下表补齐相应文种的体例要素，再展开正文。

| 文种 | 通用体例要素及关键区别 |
|---|---|
| 法律意见 | 受托问题 → 结论与条件 → 事实证据 → 法律分析 → 出具主体与日期；写明实际审阅范围。 |
| 诉辩与程序申请 | 当事人与案件 → 请求或意见 → 事实理由与证据 → 致送、签署及附件。答辩回应对方请求，上诉针对原裁判；申请按所求措施核资格及法定条件。 |
| 函件与授权 | 出具身份与收件人 → 权利基础及要求，或授权事项 → 期限及生效安排 → 联系与署名。解除核通知到达；授权区分一般与特别权限。 |
| 合同协议 | 主体与交易目的 → 具体权利义务 → 履行及异常处理 → 通知与争议解决 → 生效、签署及附件。补充协议明确新旧条款关系，和解协议明确付款与权利终止的时点。 |
| 审查意见 | 原条款位置 → 问题与依据 → 实际影响 → 修改建议或替换文本 → 待确认事项。 |

**表达：** 法律意见和诉辩写出结论及论证。合同写成明确的权利义务，计算方法与法律限制进入对应条款。正文满足使用需要，压缩时先删重复说明。

**引用：** 写法源全称及具体条款，直接引语核原文。来源链接附在名称或论证句上。检索过程留在底稿。

## 步骤3：完成 Word 排版

### 3.1 按文种组织版面

**排版目标：** 让读者看清请求或约定，方便核对、签署和提交。先按下表确定版面，再执行3.2的格式。

| 文种 | 具体排法 |
|---|---|
| 传统文字式起诉状、答辩状等 | 主标题居中，当事人逐方分段左对齐。按文种使用“诉讼请求”或“答辩意见”等分区名，单独成行；请求或意见逐项编号，事实理由连续成段。末尾按体例安排致送、附件清单、签名和日期。 |
| 要素式起诉状、答辩状 | 使用匹配的官方示范文本时，保留栏目、勾选项和填写说明。正文栏沿用模板字号与续页方式，填写后检查文字是否完整显示。 |
| 合同、补充协议、和解协议 | 以连续编号条款为主，多项价款或交付清单可用表格。签署区紧接正文；单独成页时写明对应合同名称。附件名称和编号与正文引用一致。 |
| 律师函、催告函、授权书 | 函件的收件人、授权书的双方身份置于正文前。具体要求或授权内容集中呈现，期限突出显示。出具人、签署和日期在末尾完整保留。 |
| 法律意见、审查意见 | 按问题分节，结论与理由相邻。短条款审查可用“原条款—问题—替换文本”对照表；长篇论证用段落展开。 |

### 3.2 设置格式

**格式依据：** 先落实适用的提交要求和用户指定模板。可编辑模板按原流程复制使用，局部编辑保留范围外的内容和格式。**无具体要求的项目必须执行下表**。这是本 skill 的默认排版；覆盖 taxonomy 同项，表外对象沿用通用格式。

**统一设置：** 使用真实 Word 样式。全文黑色，中文显式设置 `eastAsia`，西文 `ascii/hAnsi` 为 Times New Roman。下表的表格设置用于清单与对照表；要素式诉状按模板，签署表按签署区要求。

| 模块 | 设置 |
|---|---|
| 页面 | A4，四边2.5 cm；默认无封面、页眉、边框线及水印。 |
| 正文 | 宋体12 pt，两端对齐，1.5倍行距，首行2字符，段前后0。允许段落分页，启用孤行控制。 |
| 主标题 | `Title` 黑体18 pt，居中加粗，段前0后12 pt。单倍行距，零缩进，无标题线，全文一次。 |
| 分级标题 | `Heading 1` 黑体14 pt，段前10后6 pt。`Heading 2` 宋体12 pt，段前6后3 pt。均加粗顶格，单倍行距，零缩进，无标题线，与下文同页。 |
| 条款编号 | 有序项使用自动编号，绑定层级。无模板时，合同“第一条→（一）→1.”；其他文书按需使用“一、→（一）→1.”。诉状分区名可不编号，分项请求用“1.、2.……”。编号项悬挂对齐，首行缩进0。正文仅条名、关键定义及重大利害条款加粗。 |
| 条名 | 独立成段时用对应 Heading。与条文同行时用正文格式，条名加粗。 |
| 表内文字 | 宋体10.5 pt，单倍行距，段距与缩进0。所有单元格垂直居中。金额水平右对齐，描述左对齐，序号居中。 |
| 表格外观 | 外框1 pt，内线0.5 pt。表头浅灰 `F2F2F2`、加粗居中，数据白底。单元格左右边距0.19 cm。 |
| 表格分页 | 总宽≤版心，列宽按内容分配，行高随内容增长。行设 `cantSplit`，长表行间续页，表头设 `tblHeader`。表题置上，10.5 pt，居中，段后4 pt，与首行同页。 |
| 致送与落款 | 身份及致送信息顶格左对齐，出具主体与日期分别右对齐。均12 pt，1.5倍行距，零首行缩进，与前文关联分页。 |
| 协议签署区 | 列各方名称、有权代表、签字/签章位及日期，留足签署空间。沿用落款字号、行距和缩进。同一方同页，空间允许时整个签署区同页。无框签署表无底色和表头。 |
| 附件 | 按“附件1、附件2……”编号并对应正文。各自新页，标题居中，页码延续。附件表题可用“表1-1”。必要附件实际随文提供。 |
| 页码 | 单页不设。多页页脚居中“第 PAGE 页 共 Y 页”，宋体9 pt。正文及附件从1连续计数，封面目录不显示且不计入。Y 无前置页用 NUMPAGES，有前置页用正文及附件页数计算域。 |
| 目录与脚注 | 默认无目录。用户或模板要求时，用基于 Heading 1–2 的原生 TOC，宋体12 pt，单倍行距，另起页。脚注用原生功能，9 pt。 |

## 步骤4：检查与交付

### 4.1 验证成品

**实际用途：** 从最终 DOCX 回读。读者能否据此判断主张、履行约定或完成提交？回到步骤1的关键问题，检查正文是否已给出相应处理。

**事实使用：** 逐项对照用户材料与规划，确认范围内事实均已落实。核正文是否保留原意、限定条件和证明范围，并与上一版比较遗漏。

**专业准确：** 核法条、外部事实和参数的查证记录，复算数字，推演履行与关键异常。实质错误回步骤2处理；纯排版核原内容保真。

**文件质量：** 执行主流程全部适用检查，逐项记录终稿证据。用 `read.py` 核实际生效格式，按 [audit.md](../workflows/audit.md) 完整审计。模板及编辑任务同时比对源稿。刷新目录与页码后，核最终审计结果并查看 LibreOffice 全页渲染。每次修改后重跑完整审计，复验受影响项目。

### 4.2 交付 Word

全部适用必检项通过后，交付可编辑 Word，简述已核内容与格式。确有事实或签署待填项时，标明草案及待补内容。检查未完成时继续补验；客观无法验证则说明阻塞，保留为待核文件。
