# 分析报告与决策支持

**工作主线**：1. 确认适用范围 → 2. 明确核心问题与分析范围 → 3. 读取材料并核验证据、口径和计算 → 4. 在证据边界内形成判断与建议 → 5. 按照呈现逻辑规划组织内容 → 6. 选择合适的可视化及排版格式呈现方式 → 7. 完成交付检查。

## 适用范围与路由自检

**命中：基于材料形成发现、判断或建议。**
- 适用于经营、销售、成本等数据分析，以及项目、产品、市场、行业、竞品、商业机会和战略分析

**不命中：只整理材料，不形成判断。**
- 仅转写、提取、排版、摘要或原样整理材料；
- 数据只用于支撑既定的工作总结、请示、发言稿、合同等其他题材。


## 第一部分 必须遵循的总原则：核心问题、证据与判断

分析报告和调研报告应围绕核心问题，用可靠证据形成清晰、有用的判断。本部分只规定核心原则，不穷举具体方法。

### 核心逻辑和语言表达（非常重要）
- **分析逻辑**：从核心问题出发，对相关证据进行分析和验证，在证据支持的范围内形成主要发现或判断。
- **呈现逻辑（全文最重要需要遵循的原则！！！）**：以主要发现或判断为主线，根据信息对读者判断的重要程度进行取舍和排序，形成与报告目标相匹配的分析结果。整体呈现逻辑可以参考总-分-总逻辑。
  - **摘要**：先呈现“报告摘要/执行摘要”，独立呈现核心发现、结论及其行动建议，每个部分一般不超过三点。
  - **研究背景、方法、范围等说明**：按需提供分析背景和方法，不得超过正文10%篇幅。
  - **核心分析章节和段落采用结论先行、逐层支撑的金字塔逻辑**：
    - 上层概括下层，下层以分论点和证据支撑上层；同层内容应采用一致的演绎或推理逻辑相互区分、共同完整，并按最有助于读者理解和判断的顺序排列。
    - 建议对“分析性段落”采用：“段首关键结论 → 关键数据 → 原因解释 → 简短启示（可选）”的结构
    - 分析性段落的标题要有结论性提示，不采用“趋势总览”类似的抽象标题。
    - 对超过5000字的长文报告，可在每个分析性一级标题后添加一个简洁精炼的段落，总结该章节的主要发现或判断，整体篇幅不可超过该章节的10%。
  - **报告结尾**：总结分析结果，强调核心发现、建议和限制（如果有）。
- **呈现逻辑自检**：**目标是让读者只需要读每个标题以及每一段的第一句话就可以把握全文内容，要有具体的事实判断而不是抽象结论**。
- **语言风格和写作逻辑禁止项**：
  - 结论重复，信息增量不足：不同章节反复出现同一个结论，没有新的信息增量。
  - 语言风格偶有口语化：全文要保持一致的语言风格，避免使用口语化语言，除非用户明确要求。
  - 分析性段落的段首句禁止使用“更关键的是留存数据。”等没有实质内容的短句。首句应当让读者明确本段要传达的核心信息，并与本段后文形成可验证、可展开的关系。
  - 禁止在缺少相应的证据边界的时候使用“最根本原因”“唯一出路”等强结论语句，如必须使用，则应将绝对判断改为带条件的判断

### 核心行动方法
**STEP1：明确核心问题以及预估回答核心问题需要的信息，划定分析范围**
**STEP2: 收集与整理结论依据**
  - **用户提供附件/query信息利用**：是最重要的信息来源之一，需按照[`writing-taxonomy.md`](writing-taxonomy.md)中有关附件的要求完整执行。并在`attachment_purpose.md` 说明每份附件的角色。
  - **用户提供的链接**：也是最重要的信息来源，需围绕核心问题完整读取内容；可视化的图片、图表等适合利用的信息应尽可能，如有需要可以插入交付报告中。
  - **联网搜索**：如果用户没有明确分析来源，一般默认搜索补充报告资料。优先采用政府、监管机构、官方统计、行业协会、上市公司公告/财报、企业官网和原始研究等权威或第一手来源。
**STEP3: 准确计算数据**
  - 关键数字必须可追溯到原始材料；比较对象必须同口径；缺失、不适用或无法计算的数据必须明示，正文不得出现 `NaN`，不得默认补全或用语言推理替代计算。
**STEP4: 抽出结论主线**
  - 从材料中先提炼最能回答核心问题的 1 条主判断，以及支撑它的 2—4 个关键分判断；正文围绕主线组织，不按材料或指标顺序展开。
**STEP5: 围绕核心判断组织呈现**
  - **核心判断统领全文**：完成分析后，先提炼读者最需要知道的发现或判断，再围绕它组织正文，使各部分共同回答核心问题。按照前文规定的“呈现逻辑”组织内容。
**STEP6: 完整规划摘要内容**
  - **摘要要求**：
    - 摘要必须直接回答核心问题，覆盖核心判断、2—3 个最重要发现、主要建议和关键限制
    - 摘要默认不设二级小标题，不使用项目符号、编号列表或表格，使用 2—4 个自然段完成
    - 摘要必须控制在一页以内，中文摘要建议 500—800 字，最多不超过 900 字
**篇幅要求：报告篇幅应由核心问题、证据复杂度和读者决策需要决定，逻辑完整优先于篇幅长度。**
  - **核心原则**：以用户要求为准、以说明问题为限、根据任务适度增加深度
  - **未指定篇幅时，默认按交付用途控制正文规模**：快速分析/简报 1,500—2,000 字；标准分析报告 3,000—5,000 字；明确要求“深度调研/深度分析”时 6,000—9,000 字。
    - 超过 10,000 字必须由材料复杂度、核心问题数量或正式交付场景支撑，并在 `outline.md` 写明原因。
    - 字数口径默认指正文含摘要，不含封面、目录、脚注、参考文献和附录。
  - **禁止**：为了写长报告而不考虑逻辑以及可读性堆砌内容。

### 不同类型报告的分析落点参考
 应优先以用户明确的具体目标为核心分析落点，在用户未明确时，可参考以下思路：
| 报告目的 | 内容重点            | 最终落点        |
| ---- | --------------- | ----------- |
| 描述现状 | 说明当前情况及值得关注的变化  | 帮助读者形成清晰认识  |
| 诊断问题 | 找出主要问题，并分析其形成原因 | 明确问题及改进方向   |
| 探索情况 | 提炼初步发现，并比较可能的解释 | 提出值得继续验证的问题 |
| 评估效果 | 根据既定目标判断实际表现    | 形成有依据的评估结论  |
| 支持决策 | 比较不同选择及其影响      | 给出推荐意见和适用条件 |
| 预测趋势 | 根据现有证据判断未来变化    | 形成有条件的趋势判断  |

### 语言表达：避免英语式句法

- 中文分析报告默认使用“事实/对象 → 结果/变化 → 判断/限制”的句序；不要频繁使用英语式“连接词/状语从句 → 分析动作 → 抽象判断”的句序，例如“然而，当我们审视……时，……”。
- 少用抽象名词作动作主体，如“证据表明、数据提供、研究揭示”；优先改为具体事实作主语，如“样本结果显示……”“该实验覆盖……，因此……”。
- 英文习惯“结论先行、层层限定”，中文更讲究语气与证据同步落地。强判断必须带依据和边界；无明确标准时，不写“最权威、最根本、唯一出路”，改写为“在……范围内更有参考价值/更可能是主要原因”。

## 第二部分 分场景规则 

**说明**：一份报告可以同时使用数据和调研资料。应先判断主要结论依靠哪类证据形成，再选择相应的分析方式。以下内容只说明不同场景需要特别处理的部分，其他要求统一遵循总原则。

### 一、以数据为主要依据的报告

适用于主要通过可计算、可比较的数据形成结论的任务。
- **分析重点**：从数据中寻找最能回答核心问题的变化、差异或联系，并判断这些发现是否足以影响读者的认识或选择。不要停留在逐项报数和描述数字。
- **内容组织**：围绕主要数据发现展开正文，而不是按照数据表、字段或指标的原始顺序介绍。计算过程和完整明细只在帮助理解或复核时展开。
- **可视化重点**：图表用于直接呈现关键的数据关系，表格用于准确查数，完整明细放入附录。只有图形比文字或表格更容易说明问题时才作图，不以图表数量体现分析深度。

### 二、以调研资料为主要依据的报告

适用于主要通过资料检索、案例研究、访谈或其他调研方式形成结论的任务。
- **研究重点**：围绕核心问题确定需要了解什么，并持续补充和核对资料，直到重要判断获得足够支持。无需追求搜集所有相关信息。
- **内容组织**：按照报告需要回答的问题综合不同资料，而不是逐一介绍每个来源。
- **来源说明**：引用外部资料中的重要事实、数据、观点或原文时，应在相关内容首次出现处插入自动编号脚注。
- **公开资料引用说明**：脚注统一采用“作者或机构：《资料标题》，发布方，发布日期，页码或章节（如有），URL（访问日期：YYYY年M月D日）”的格式，确保读者能够找到并核对原文。
  - 公开资料：作者或机构：《资料标题》，发布方，发布日期，页码或章节（如有），URL（访问日期：YYYY年M月D日）。
  - 同一来源再次引用时，可简写为：作者或机构：《资料标题》（简称），页码或章节。
  - 图表和表格不应只依赖正文脚注说明来源。应在图表下方直接标注：数据来源：作者或机构，《资料标题》，年份；根据原始数据整理。
- **可视化重点**：
  - 图表呈现：有可靠且可比的数据时，可以使用统计图表
  - 逻辑关系呈现：当内容涉及多个主体、环节或因素，且其层级、分工、流程或作用关系是理解重点时，**强烈建议**使用时间线、结构图、流程图或机制图呈现。图中节点和连线应含义明确、具有事实依据；正文仍需提炼关键关系与结论，不能用图形替代分析。如需使用任何背景色，要与图表背景色保持一致主题色系，建议避免使用深色背景色。
- **对标参考**：
  - 综合性商业与管理研究：麦肯锡全球研究院（MGI）、BCG Henderson Institute、PwC Research / Global Surveys、Deloitte Insights、EY、KPMG专题研究、IBM Institute for Business Value等专业机构的报告
  - 宏观、产业与政策研究：世界银行《世界发展报告》、OECD各类Outlook和专题报告、IMF 旗舰报告等
  - 市场、消费者与社会调研：Pew Research Center、Gallup、Ipsos、NielsenIQ、Kantar等专业机构的报告
  - 审计、运营诊断与问题整改：上市公司内部控制审计及风险管理报告、美国政府问责局（GAO）、英国国家审计署（NAO）等专业机构的报告
  - 中文商业与产业报告：除综合性商业与管理研究外，可补充中国信息通信研究院白皮书、中国互联网信息中心（CNNIC）统计报告、艾瑞咨询、易观分析等商业研究报告作为参考

## 第三部分 证据呈现：图表、表格与附录

### 一、呈现原则
- **每个图表必须回答一个独立问题**：每个图、表或附录项必须服务一个明确判断；不得为了显得完整而堆图、堆表。**每张图或表必须回答一个明确且不重复的问题。**
- **同一判断只选择一种正文主证据形式**：看趋势/差异/结构用图，查精确值/多字段对照用表，复核明细/计算口径放附录。禁止重复用图和表重复呈现同一信息。
- **图表前后必须形成连续阅读单元**：正文首次引用 → 图/表 → 标题/来源/口径 → 简短解读。
- **确保图表能够独立理解**：图表应说明比较对象、分析范围、计量方式和数据来源，使读者脱离正文也能理解其基本含义；通过必要的标注或基准，帮助读者直接看到支撑正文判断的关键信息，避免让读者自行寻找重点。
- 每张图表必须有图题、单位、期间、必要口径和以“数据来源：”开头的来源说明；图后紧跟一段解释，说明图中发现、对判断的意义和限制。

### 二、图表选型

1. **有足够数据支撑关键判断时，必须作图；不得全文只堆表格。**

| 信息关系 | 默认形式 | 触发条件 |
|---|---|---|
| 时间变化 | 折线图 | 同一指标有 5 个及以上连续时点 |
| 对象比较/排序 | 条形图 | 3 个及以上可比对象 |
| 构成关系 | 堆叠条形图；少量类别可用饼图/圆环图 | 有共同分母，且需要判断份额或结构 |
| 变化拆解 | 瀑布图 | 起点、终点和中间项可严格加总 |
| 精确查数/多字段对照 | 表格 | 读者需要查阅具体数值 |
| 复核明细/口径说明 | 附录 | 正文不需要逐项展开 |

2. **同一分析问题下，相关图可合并为一张多子图。**
  - 同一时间轴下的相关指标：优先上下排列；
  - 同一对象维度下的规模与效率指标：可横向并排；
  - 子图：必须共享对象、期间或读者问题，颜色含义保持一致，各自仍可独立阅读；
  - 图号与图题：整张图使用一个连续图号和总图题，子图以“（a）”“（b）”区分。

3. **数据不足、用户只需精确查阅或任务以定性材料为主时，不强制作图。**


### 三、图表元素与排版

1. **空间布局**：
- **禁止**：前页大面积留白、图片单独占页、图题与图片拆页，或图后没有解释就直接进入下一节。

2. **图表标题与说明**：
**图题在图下，表题在表上；两者的间距规则不同。**
  - **图题**：按首次出现顺序编号；图下使用居中的 `Caption`，格式为“图 1　<图题>”；显式黑色、小于正文、与图片同页，段后固定为正文 1.5 倍行距（360 twip）；
  - **图后说明**：每张图必须紧随“数据来源：”说明，并在必要时补充期间和口径；不得省略或用无来源的泛称替代。该段使用正文行距，段后固定为 360 twip，使其与后续正文自然分隔；
  - **表题**：按首次出现顺序编号，格式为“表 1　<表题>”；必须固定置于表格上方，并与表格首行同页；不得置于表格下方、跨页或与表格分离。

3. **图表图例、标签与刻度**：
**图例、标签和刻度必须完整可读。**
  - 图例默认置于绘图区外；
  - 系列不超过 3 个且名称简短时，优先直接标注线末端、柱组或基准线；
  - **务必检查**：图例、数据标签与刻度不得遮挡、碰撞或截断；空间不足时，必须仅保留关键数据标签、调整标签位置或改用图例/表格，不得强行显示全部数据标签。

4. **图表尺寸与分页**：
  - A4 通用格式：常规单图显示宽度优先为 13—14 cm，高度必须按原图像素比例反算；不得为统一高度拉伸、压扁、裁切或异常放大，且不得超过正文版心（约 16 cm）；如果为圆环图、饼状图、雷达图等，宽度可以适当缩小至 8—10 cm，以防整图过大。
  - Python 图表导出白底 PNG，标准固定导出为 1,680 × 960 px（240 dpi）；不得为放大页面而低分辨率拉伸，也不得无理由输出超大图片；
  - 所有图片必须创建为嵌入式（inline）图片，不得使用浮动图片，以免溢出页面或脱离正文；
  - 两个横向子图：整组优先使用 13.5—14.4 cm 宽度；每个绘图区须至少约 6.5 cm 宽、5.5 cm 高，保证坐标、标签和图例可读。达不到时减少子图或拆为独立图，不得把子图压扁；
  - 当前页无法容纳：优先缩小至可读尺寸或调整插入位置；仍无法容纳时，将首次引用段与图表整体移至下一页；
  - 单独占页：除用户明确要求外不得使用。
  - 图表使用统一中文无衬线字体并实际检查中文、数字、负号、单位、刻度和图例无乱码或截断；保留极淡横向网格线，一般不保留纵向网格线。

### 四、表格排版
**数据表应与正文版心同宽，并按列统一对齐。**
  - 表格总宽度必须等于正文版心宽度，渲染后左右边界与正文对齐；不得因内容多少缩窄为页面中间的小表；
  - 表头、表内文字和数字的水平/垂直对齐、字号、缩进及单元格边距，必须按 [writing-taxonomy.md](writing-taxonomy.md) 的“表格样式”执行；同一列保持一致。
  - 单元格内段落的首行、左侧和右侧缩进均为 0；除非用户明确要求；
  - 表格总宽度按页面可用宽度精确分配列宽，不能依赖内容自动收缩或空格排版。

### 五、整体配色与视觉规则
1. **必须项与禁止项**

  **必须**：
  - 单一数值系列默认使用一种主色；同一系列一般禁止使用不同的颜色，如使用了不同颜色务必说明必要性。
  - 只有颜色代表明确业务判断时，才可使用强调色，例如低于目标、异常或风险项；
  - 默认只使用“主色 + 一种强调色”。确需表达高于、接近、低于基准等三档状态时，必须在绘图区外给出简短颜色说明，或直接在对应数据旁标注判断；
  - 基准线、目标线和阈值线必须标注数值及含义；支撑正文判断的峰值、拐点、异常值或最大差距必须直接标出关键数值或简短注释；
  **禁止项**：
  - 不得为装饰把同一系列随意分成多种颜色，如果使用多种颜色务必有明确的图例说明
  - 多系列图的图例必须位于绘图区外，且不得遮挡柱、线、标签、坐标轴或数据点；
  - 图内不得重复放与图下图题完全相同的标题。以“图 + 图题 + 紧邻口径/来源说明”构成完整图表单元。

2. **使用统一、克制的分析报告配色**

- 主色与层级：藏青 `#1A2B4A`、中藏青 `#52647D`、浅藏青 `#8D9AAB`、极浅藏青 `#C9D0D9`；同一图默认只使用该色阶与中性灰。
- 中性色：正文 `#252525`、辅助文字 `#767676`、网格线 `#D8D8D8`、浅底 `#F4F4F4`。
- 单点强调：琥珀 `#C8861A` 或暖赤 `#B84C3A` 二选一，只标记关键差距、风险或异常，不能用于装饰或同时大面积使用。
- 禁止 Word 默认主题配色、彩虹色、渐变、3D、投影、彩色背景、粗黑边框和默认图例框；图表标题、坐标、图例和数据标签使用黑色或深灰，不得使用默认蓝色 Heading 样式。
- 不得只依靠颜色区分系列；结合排序、直接标签、线型、空心/实心填充或数据标签。

## 第五部分 交付检查：交付前逐项检查

### 交付前核验清单
**必须重读文档的完整内容、检查xml结构和渲染视觉检查，任一关键项未通过，不得交付。**
- [ ] **内容结构**：报告是否围绕核心决策问题组织；摘要是否先给出核心判断、量化依据、关键限制和行动建议；正文是否删除或下沉了不支撑判断的背景、复述、明细和泛化建议。
- [ ] **呈现逻辑与篇幅**：是否按照前文的呈现逻辑参考展开，禁止内容多但逻辑散乱，避免陷入读者难以抓住重点的情况。重读每个标题以及每一段的第一句话，检查是否可以把握全文内容，要有具体的事实判断。
- [ ] **证据、来源与计算**：关键结论、图表和建议是否可回溯至附件、计算结果或明确假设；关键指标是否按公式核验；是否存在未解决读取缺口、口径冲突、异常或限制；是否把假设、计划、预测、测算或不可比数据误写成事实。
- [ ] **图表与表格**：图表和表格是否支撑正文判断，并与内容规划中的数据、口径、位置和图后解释一致；正文是否避免用图和表重复表达同一对象、期间、指标和结论；图表单元是否可独立读懂比较对象、期间、单位、统计口径、数据来源、基准线和颜色含义。
- [ ] **排版与样式**：是否按照用户要求格式或者一般格式指南中指定的图表、正文、目录等格式要求严格执行，尤其是表标题是否跟表格保持同一页、图表是否过大导致前后出现大片空白
- [ ] **附录与复核信息**：附录是否优先提供指标口径说明、资料来源、必要明细和读取限制；是否只保留支持复核正文结论的信息，而非按数据文件名机械重复原始表。
- [ ] **执行校验**：是否完成结构化回读、基础校验、专项审计和逐页视觉检查；目录、图题、来源说明、图表布局和通用 Word 格式是否按本指南及 [`writing-taxonomy.md`](writing-taxonomy.md) 要求通过。
