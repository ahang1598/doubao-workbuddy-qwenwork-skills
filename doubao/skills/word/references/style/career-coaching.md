# 简历写作指南

## 写简历的哲学

- **内容上：用一页与目标岗位相关的证据，让读者看清“你能做什么、为什么值得面试”。** 岗位需要什么，就优先呈现什么；用本人行动和成果证明硬、软素质，按相关性取舍经历。真实信息与启发性示例必须分清。
- **排版上：让用人单位和 HR 形成清晰、专业的第一印象，并快速抓住重点。** 遵循清晰的层级、统一的字体与对齐、适当的留白和克制的配色，通过位置、字号和加粗突出重要信息。

## 写作主线

| 情况 | 执行过程 | 必须执行的步骤 | 内容与模板处理 |
|---|---|---|---|
| 用户需要从零创建简历，或提供已有简历要求优化内容／匹配目标 | 整理用户信息 → 读取或搜索目标岗位 JD／学术申请要求、提取能力要求 → 匹配经历并按建议结构改写 → 缺数据用 XX、补写示例逐点标红 → 选择并填写模板、处理排版易错点 → 核对禁止项及内容、样式和页数 | 步骤1 → 步骤2 → 步骤3 → 步骤4 → 步骤5 | 用户提供模板时使用用户模板，未提供时使用内置模板；补写示例的每一点末尾加红色“【仅作示例】”。 |
| 用户提供自己的简历附件，仅要求“美化简历排版” | 完整读取原简历 → 选择模板 → 将原内容填入对应栏目、处理排版易错点 → 核对禁止项及内容有无遗漏、样式和页数 | 步骤1 → 步骤4 → 步骤5；跳过步骤2、3 | 完整保留已有内容，不大幅改写、不补写示例，不搜索 JD 做内容匹配。原简历作为内容来源；用户另有指定模板时使用该模板，未指定时必须从内置模板列表选择适合其简历类型和内容结构的一份，读取并复制模板，将原内容填入对应栏目，继承字体、层级和布局。 |

## 步骤1：用好用户提供的信息

- 先用好用户提供的叙述、旧简历和附件，把同一经历中的信息合起来。已有事实准确保留，分清本人职责，突出本人贡献。
- 用户提供的照片能明确确认是本人时，可替换到简历；否则照片位置留空。
- 除非用户没有提供完整信息，否则需要交付完整简历，不能通篇留下占位符。

## 步骤2：提高内容匹配度并按建议结构改写

### 2.1 提高内容匹配度

- **工作简历搜索精确岗位说明 JD（job description）。** 按目标公司、岗位方向、行业、级别及地点搜索，优先读取企业招聘官网的当前职位原文；用户提供的目标 JD 优先。未指定公司时比较数份同方向、同级别 JD，不混用同名但职责不同的岗位；目标不明先确认，搜索不到则说明，不编造要求。学术简历匹配目标项目、导师或科研岗位的申请要求，用户提供的要求优先。
- **提取关键词并匹配证据。** 区分必需条件与加分项，提取专业技能、经验及协作要求，对应到用户的具体经历。尽可能使用准确对应的岗位用语，不堆关键词，不把 JD 或申请要求直接写成用户能力。
- **硬、软素质都要呈现。** 所需素质不同阶段不同，侧重点以目标 JD 或申请要求为准：

| 职业阶段      | 硬素质重点               | 软素质重点             |
| --------- | ------------------- | ----------------- |
| 校招 / 初入职场 | 相关教育、课程、实习、项目及基础技能  | 学习应用、主动解决问题、团队协作  |
| 有经验的专业人员  | 独立交付、专业深度、复杂问题与业务成果 | 跨团队沟通、推动落地、判断与取舍  |
| 管理岗位候选人   | 相关领域经验、团队或业务结果、资源配置 | 目标拆解、协调决策、培养与带领团队 |
| 转岗 / 转行   | 可迁移技能、目标岗位相关项目及成果   | 适应变化、快速学习与协作      |

### 2.2 内容结构：按用途调整

- **整体精简到一页纸，用户要求或用户提供的模版要求时可以拓展至2页** 。优先保留与目标相关的经历，压缩重复和次要内容，不靠缩小字体硬塞。
- 以下六部分主要适用于工作简历，不要求凑齐。校招有相关实习时重点写实习；社招以工作经历为主，教育及校园经历可精简。技术岗突出问题、方案、实现与验证；非技术岗按业务或专业任务展开。
- 学术简历以教育、研究经历、代表成果和方法技能为主，写研究问题、方法、本人贡献和产出，不套商业指标；学位状态、论文作者顺序和发表状态按用户材料准确表达。

#### 2.2.1 个人信息：姓名、电话、邮箱即可，可适当加求职城市、求职方向及相关的真实作品链接，可以列出3个个人关键词，可以体现AI Native的能力。

#### 2.2.2 教育背景：（必须项）学校 + 专业 + 时间，准确注明学位或培养项目。可加有优势且相关的课程、奖项，如计算机课程、创业大赛一等奖、国家奖学金；不重复列奖项。

#### 2.2.3 工作 / 实习经历：相关经历是工作简历的重点。身份行写 **公司 + 业务 + 岗位 + 时间**，可加城市，尤其是经历所在地与投递岗位所在地一致时。

- **O：一句话说明工作内容、目标及拆解。** 如“负责 XX 业务的 XX 工作，通过提升 A 和 B 来提升总体目标 X”。
- **KR：按现象 → 问题 → 行动 → 结果展开。** 如“针对 XX 人群的 XX 现象，发现 XX 问题，优化 XX 环节、增加 XX 板块，最终使 XX 指标提升 XX%”。
- 重点项目展开，其余可压缩为关键动作与结果，不必每条写得同样细；O / KR 是组织方式，不强制印出标签。上述句式用于缺少事实的补写时，每一点末尾均按步骤3要求加红色“【仅作示例】”。

#### 2.2.4 创业经历：说明项目、本人角色和时间，重点写市场调研中发现什么人群的需求未被满足、采取什么动作、最终取得什么效果。按与目标岗位的相关性决定是否作为加分经历，不只写创始人头衔。

#### 2.2.5 项目 / 竞赛经历：没有实习或创业经历时，可用课题组项目、竞赛、课程作业；已有工作经历时，补充不同的能力证据。写清项目与角色、问题、本人行动和结果，优先呈现可量化成果；缺数据用 XX，补写内容逐点标为示例。

#### 2.2.6 技能荣誉：补充相关等级证书、奖项和技能，如 SQL、Python、Java、Xmind、Axure，按实际用途归类，不默认用户全部掌握。与教育或项目相关的奖项放回对应经历，同一成果只写一次。

## 步骤3：信息不足时怎么写

- **数据占位**：用户未提供的数据可用 `XX` 占位，如 `XX%`；已提供的信息不要重新留空。
- **启发式写作**：为启发用户补充，可以按上述结构写完整的项目或工作经历示例，包括目标、问题、行动和结果；示例应贴合已知岗位或方向。
- **凡含补写情节、假设成果或待补数据的示例，每一点末尾都必须追加红色“【仅作示例】”；正文仍保留模板颜色。** 不能只在章节末尾或交付说明中统一提醒；只有 `XX` 也不能代替标注。

## 步骤4：使用模板，关注排版易错点

**用户提供模板时必须使用用户模板；未提供时，必须从文末列表选用内置模板。** 先读取模板，再复制填写，继承实际样式，不新建空白文档仿制。模板无法使用时说明具体问题，不静默改成无模板生成。

### 4.1 使用模版时的注意点
**应避免的易错点**：注意所有内容要素对应的字体、颜色、字号、强调，以及整体页面的页数和留白情况。
- **内置模板中的示例个人信息与经历，使用时必须替换为用户提供的信息；保留的示例按步骤3逐点标注。** 用户的姓名、邮箱、联系方式等信息，用户未提供时必须留下占位，不可以直接删除空。
- 使用模版前先列出checklist：（1）根据实际模板，列出“内容角色—所在位置—对应格式”表，至少覆盖姓名、联系方式、栏目标题、公司／岗位／时间、经历描述（经历加粗部分、经历不加粗部分）。格式记录字体、字号、颜色、加粗及必要的段落设置。（2）同一段内存在不同格式时，分别记录对应的文字范围，例如标签、冒号、普通描述或局部强调；不把首个 run 的格式当成整段格式，也不强制所有经历采用“标签＋正文”。
- **禁止通篇字体加粗**：一个字段可能跨多个 run，一个段落也可能有多个字段。不能把全部新内容塞进首个 run。直接赋值 paragraph.text 会清除原有 run 层级的加粗、斜体等格式。因此需要按内容要素对应的格式替换文字，不能直接整段覆盖。如果生成简历后检查发现**全篇字体均加粗**，一定要返回修改。
- **模块栏目服从用户内容**。 模板中的栏目不是必填项，没有对应经历时可删除或调整栏目，保留模板的视觉样式。不得为了填满“项目经历”栏，将工作职责、成果从所属公司中拆出或重复呈现；仅美化排版时，保留原有经历分类及归属关系
- **空白页面比例检查**：在填写用户提供的信息后，必须进行渲染检查，一是检查页数是否超过一般要求或用户要求（一页）；二是检查页数在一页之内时，检查页面中空白底部是否还能插入超过4行正文文字以上的内容，如是，则需要进行以下的排版调整。**不能默认一次调整**就会满足页面空白比例要求，必须重新渲染并严格检查；如果仍不满足要求应进一步补充内容或调整行距和页边距。

**调整排版策略**：
  - 如果页面空白较多，在保留模板风格的前提下，需要：（1）优先考虑补充经历描述，使内容更加充实；（2）如果信息已经充分，可以通过调整行距，再调整页边距的方式使页面更充实。一般行距每次增加1磅或0.1倍，页边距每次上下左右同时增加0.15厘米。每次调整后检查页面，留白协调后停止，不强求填满页面。

### 4.2 可选内置模板

先按**语言和用途（求职／学术）**筛选，再按内容量选择排版密度，按栏目需求选择具体模板，最后考虑配色偏好。需要独立展示项目或研究经历时，优先选择已有对应栏目的模板，不要仅凭模板中的示例岗位限定用途。

- **标准版**：兼顾信息容量与可读性。**用户信息较模糊，未明确内容量或排版偏好时，优先选择标准版。**
- **紧凑版**：适合经历较多、需要保留更多内容或展开技术与研究细节的用户。
- **舒展版**：适合经历较少或精选代表经历、偏好较大字号和宽松阅读的用户。

没有语言和用途匹配的标准版时，先保证语言、用途与栏目匹配，再按标准密度调整。栏目可根据用户真实经历增删，不必完整保留模板中的所有模块。

## 步骤5：禁止项与交付前检查

### 5.1 内容真实性与经历归属

- [ ] 用户未提供的姓名、邮箱、联系方式等必要信息必须保留占位，不得直接删除；已提供的信息应完整填写，不得重新留空。
- [ ] **用户没给经历，却直接写成真实经历且没有上述警示，按 0 分简历处理。** 示例须经用户确认、替换为真实信息后才能去掉标注。
- [ ] 检查是否为适配模板而改变经历分类，或将同一经历重复放入多个栏目。

### 5.2 字体、强调与颜色

- [ ] 对照填写模版前的checklist，检查各类内容是否放在正确位置，并继承对应格式。
- [ ] 逐条检查经历描述：普通正文有没有误用标签格式，局部加粗是否丢失或扩展到整段。
- [ ] 禁止**通篇、整段经历文字加粗**的情况出现，生成后务必检查。
- [ ] 继承模板实际样式；示例标注单独设为红色，不改变正文颜色。
- [ ] 禁止在简历中使用emoji，任何地方都不可以使用，除非是用户模版本身就有的。

### 5.3 段落结构、页数与留白

- [ ] 检查增删经历后是否留下多余空行、空项目符号、空表格行或孤立标题；不因段落没有文字就直接删除，先确认其是否承担图片、分页或间距作用。
- [ ] 渲染全部页面，检查换行、对齐、间距、分页和遮挡。
- [ ] 默认一页，用户要求或用户提供的模板要求时可拓展至2页；仅美化时不得为压页数删改原内容，无法兼顾时说明具体冲突。
- [ ] 渲染检查当只有一页的时候，如果还有10%以上的空白空间，需要通过内容增加或行距和页边距调整的策略，使页面更加充实。

### 5.4 修复与交付状态

- [ ] 发现异常，修复后重新检查对应位置。
- [ ] 交付前核对用户信息、逐点示例标注、模板样式及实际页数；含 XX 或示例时，交付为待补稿。
