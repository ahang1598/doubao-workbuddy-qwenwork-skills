# Canvas 自动目录：CLI 工作流

本页执行 [`canvas-doc.md`](../workflows/canvas-doc.md#目录任务与提交收尾) 定义的独立目录阶段，处理用户要求的目录更新，或正文修改影响既有目录时所需的关联更新。

- **执行时机**：`open_local` 在正文完成后执行；`open_ooxml` 在提交并确认同步后执行。
- **命令**：优先使用 `table_of_contents_update`，必要时 Fetch `pdf` 获取并核对页码；PDF 不执行目录写入。
- **文件状态**：打开态不调用 `catalogue.py` / `+word-post-process`；文件分支按 `docx-editing.md` 处理。
- **参数来源**：完整参数及各 action 的能力边界统一见[领域命令](../cli/canvas-doc-update-domain.md#自动目录-table_of_contents_update)。

**规划时先读，正文完成后执行**：一次规划目录位置、来源、配置和必要分页边界；先完成影响标题与分页的正文/布局修改，再提交所需目录 action，最后核对操作后的实际版面与页码。`insert` 或 `configure` 后不默认再追加 `update`，仅在下文验收确认需要且共享恢复预算允许时修正。

## 写前检查

1. 规划正文修改时，判断是否影响目录来源、条目或页码；无影响且用户未要求目录操作时不刷新，受影响的必要更新纳入计划。需要目录操作时，在正文/分页写入前确认当前 CLI 暴露所需 command 与 option，且支持目标形态及 action；不支持或必要身份不可读取时记录目录受阻，只继续可独立完成的正文目标，不先执行仅为目录服务的分页变化。不得改用 OOXML、普通块替换或手工页码缓存绕过目录命令。
2. 未要求新增目录时不自行新增。为每个目标目录记录 `insert/update/configure/remove`、位置、用户要求或关联维护依据和保留项；新增/刷新/配置还须确定来源、配置及条目验收依据，按“原稿＋本次预期修改”验收。已有目录仅改用户要求的配置，不用默认值覆盖现值；`remove` 只要求唯一身份、删除边界及范围外保留证据，不要求来源可刷新。`update` 通常完整重建；只有生成因无标题源阻塞时，运行时才自动改为更新现有 PAGEREF 页码。两种结果都须按回读事实验收，不能预设一定保留或重建条目。
3. 先完成一批会影响标题、编号或分页的正文与布局修改，再处理目录，不逐段刷新。正文走 OOXML 时，先完成 audit、提交并确认同步；按 action 核对导入后的必要前置状态：新增检查插入位置与来源，刷新/配置检查既有目录结构、来源标题、层级、配置及相关书签，删除检查目标身份、边界及范围外保留项。发现非预期丢失或缺少必要验证证据时停止对应目录写入，不用重建掩盖导入损失。
4. 使用前置修改后最新 Fetch 的目录身份、配置和必要分页证据；主流程的屏障回读已覆盖所需范围且仍有效时直接复用，否则补读缺失范围。旧基线仅用于比对，不复用正文/布局修改或 OOXML 提交前的 ID、修订号或页码。多个目录须唯一定位；新增按 parent 的完整 children 顺序定位，刷新/配置/删除锁定已有目录，避免重复创建。顶层 `--revision-id` 按 [revision 规则](../cli/canvas-doc-update.md#revision-规则) 绑定本次 checkpoint；已有有效 checkpoint 但响应未给具体 revision 时使用契约允许的 `-1`，不为寻找未返回的数字原样重读。

**读取能力边界**：content-control 的 Fetch 只承诺 `target_id,parent_id`，不承诺目录 metadata、完整 children 或具体 XML。必需的配置/来源可复用仍有效的可靠基线；不能从 PDF 推断隐藏配置或用提交前快照证明导入后结构。新增所需 parent/完整 children、field-only 所需 PAGEREF 身份，或其他必需证据未由当前公开读取提供时，停止对应 action，说明具体缺口，不猜 ID、默认配置或插入索引。

## 分页边界

- 默认保留原有分页与分节，不因刷新目录强制目录或后续正文另起一页。用户要求或本次生效的版式要求需要换页时，复用已有边界；目录可自然跨多页，不压缩为单页。
- **文首新增目录页**：用户要求目录与后续正文分开，首个正文块为可保真回写的段落或标题，且不需改变分节、页眉或页码规则时，优先在该块最新完整 XML 上仅设置 `page-break-before="true"`，保留原标签、ID、文字、样式及全部非目标子节点；已有有效分页边界则复用。属性写法按 [`canvas-doc-text.md` 的段落属性](canvas-doc-text.md#段落)，写入仍遵循公共 XML 约束。不要为换页把 `<h1>` 改成 `<p>`、复制新标题再删除旧标题，或额外叠加空段与分页符。回读确认属性与正文保留后，在最新 parent children 中的正文前插入目录。段前分页本身不证明已预留物理空白页，目录与正文是否分开在插入目录后验收。
- 需要独立分页符、块内分页或分节/布局修改时，才按 [`canvas-doc-update-layout.md`](../cli/canvas-doc-update-layout.md#插入分页符) 的对应流程执行，并在结构写入后重新 Fetch；按具体页首/页尾定位仍须通过页面边界证据门禁。目录 option 不承载分页内容；删除目录时不删除共享或归属不明的分页边界。

## 执行

按用户目标选择 `insert`、`update`、`configure` 或 `remove`，通过 `docs +local-update` 提交对应 option。配置字段及完整性要求只查领域命令文档；不构造 TOC/PAGEREF 域、书签、占位条目或内部请求。

多个目录串行操作，每次使用更新后的身份并完成结构回读；全部目录操作结束后，再统一核对受影响目录和来源标题的最终页码。后一个目录改变分页时，前一个目录的旧分页验收失效，需重新核对。

退出码、成功信封、warnings、冲突、未知终态和重试预算沿用 [Canvas 恢复流程](../workflows/canvas-doc-recovery.md#失败处理)。写前能力不支持时保留原目录；写入后的恢复预算耗尽时停止新写入，按最新证据保留并披露已应用、未验证或未知状态，不能声称原目录未变，也不自动回滚。恢复结果仅回到独立目录阶段，不重进正文路由或触发 OOXML 兜底。未知写入只读恢复，不重复新增或刷新。

## PDF 补查与失败出口

分别记录目录写入终态、条目/结构验收和页码/版面验收，沿用主流程状态，不新增 CLI 字段。失败先按 recovery 确认原请求与实际写入范围；不能仅凭空片段、缺少页码或 PDF 导出失败就断定“目录未写入”或“渲染器页码计算失败”。

| 目录结果 | 下一步 |
|---|---|
| 命令成功，已有有效页面证据足以验收 | 直接核对，不重复导出 PDF |
| 命令成功，但条目、页码或实际版面无法从回读确定 | Fetch `pdf`，查看目录页及受影响来源标题所在页，补充下节验收证据 |
| 返回 warning / `partial_success` | 按 recovery 验证；通过后继续目录验收，不为消除警告重发 |
| 已确认只有页码不符 | 按下文“按验收结果收尾”的条件使用共享修正额度并重验 |
| 明确失败，且 recovery 判定可修正或重试 | 按共享预算取得最新身份与前置证据后恢复目录操作；PDF 不代替恢复 |
| 命令不支持、必要身份不可读取，或 recovery 判定不可继续 | 停止目录写入；若用户目标涉及页码且 PDF 可用，可只读获取实际标题页码并报告待更新项，不能因此标记目录已更新 |
| 写入终态未知 | 按 recovery 只读确认原请求；PDF 只能补页面证据，不能单独证明写任务已结束，也不能据此重发 |
| PDF 导出失败或明确不支持 | 按 [宿主 PDF 失败出口](../workflows/canvas-doc-recovery.md#4-宿主-pdf-失败) 分类处理；仍缺必要页面证据时保留页码/版面未验证，不重发目录命令或用 `update` 试探 |
| 读取恢复预算耗尽，或配置/保留项仍无法验证 | 保留已确认的写入结论，记录具体未验证项并结束 |

PDF 使用 Fetch 返回的实际路径，页码按页面显示编号核对。它既不修改 TOC 域，也不提供合法写入身份；不把 PDF 当作 `catalogue.py` 的等价替代，不手工填页码缓存或自动生成静态目录。

失败后的页码诊断仅在有助于用户目标时执行，说明所查标题及其当前显示页码、目录中已确认的差异和未验证范围；写入终态未知时同时保留这一结论。公开目录命令没有接收外部页码映射的参数，不把 PDF 提取结果作为写入 option，也不假定存在备用页码计算或写回命令。

## 回读验收

- 新增、刷新或配置后，按写前基线和计划回读目录，核对位置、标题来源及集合、条目顺序、层级、自动编号、配置和必须保留的格式；不能只以当前正文与新目录互相一致证明无损。同名标题按级别、顺序和位置区分；是否属于来源由真实配置和结构决定，不凭可见文字或标题外观推断。
- content-control 目录身份从 Fetch 的 `data.command_result.table_of_contents` 读取；主 XML 未出现目录条目或目录页的 `page` 返回空片段，不代表目录未插入。身份与可写锚点用 Fetch，条目、外观及页码在 XML 无法呈现时用宿主页面/PDF；不为取得目录 XML 重复 Fetch，也不因此重新 `insert`。配置或保留项仍缺必要证据时标为未验证。
- 回读目录前后相邻块，用更新后的 page/PDF 证据核对计划内分页要求、原有章节边界及是否出现非预期空白页。仅看到 `<page-break/>` 或目录命令成功不能证明分页通过。
- **页码逐项对照**：包含页码时，在原 `edit_plan` 的验收记录中，为受影响的来源标题记录 `条目及来源标题定位 | 目录显示页码 | 标题所在页的显示编号 | 宿主页面证据 | 一致/不一致/未验证`。两侧证据均须来自目录操作后的有效 Canvas 页面；按真实引用目标、级别、顺序和位置匹配，不能把目录页上出现的标题文字当作正文标题。
  - 对照的是文档显示编号，包括罗马数字、分节重启等规则；PDF 物理页序只用于定位证据。无法确认显示编号或标题页归属时记为未验证，不从整段 XML 中“标题后的第一个数字”推断页码，书签 ID 或 OOXML 缓存不能替代页面证据。
  - 例如已确认单节、从 1 连续编号时，目录写“基本情况……1”，正文标题实际在显示编号 2 的页面，应判为不一致；`entry_count` 正确、outline 齐全、目录有页码或外观整齐都不能证明对应关系正确。
  - 目录自身占位也会影响分页，不能使用插入前快照或把所有页码简单加一；验证范围仍覆盖受影响的来源标题，不能只看目录页。后续正文/布局变化使相关页面证据失效，须按新影响范围重新验收。
- **按验收结果收尾**：条目、保留项、分页与页码均符合计划即结束；缺少页面证据时补必要的只读验证，不用 `update` 试探。已确认目录页码与实际标题位置不符时，先核对来源、配置及分页边界；这些均符合计划、该目标仍有共享合并修正额度，且完整重建或无标题源时的 PAGEREF 页码更新满足保留要求时，使用最新 Fetch 身份执行一次 `update`，再按同一标准验收。其他偏差按恢复流程定位并修正，不能用刷新目录掩盖。此修正与此前参数/XML 错误及实际偏离共用同一预算，不新增一次“目录重试”额度。预算耗尽、修正后仍不一致或无法满足保留要求时停止并披露待核项，不反复更新、不手工补页码缓存。
- 删除后确认目标目录已消失、相邻正文与其他目录仍保留，并核对专用分页清理没有改变其他章节边界；其他操作同样核对非目标目录的身份、内容和配置。命令成功不等于验收通过。
- 位置、缩进、字重、引导符等视觉要求使用宿主页面/PDF 验证；仅有 XML/文本不能声称视觉通过。空目录只有在当前标题来源确实无匹配项且符合用户目标时才算有效结果。

最终说明实际完成的操作及未验证项。CLI 不支持用户要求时明确指出具体限制，保留原目录；已完成的正文等修改按主流程披露，不将目录待完成项记为全部完成。
