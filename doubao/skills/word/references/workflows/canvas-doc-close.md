# Canvas 关闭文件流程

客户端明确报告文件关闭后，由 [Canvas 流程](canvas-doc.md) 进入本页。接下来操作原文件，无需调用 `+local-*` 或 `+ooxml-*`。

文件仍打开时，即使 Canvas 连接不可用，也不能走本流程。

> 使用前须完整读取本页；未见末行「全文完」时，继续读取至该标记。

## 读取

用 `scripts/read.py` 从客户端提供的 `<path>` 读取所需内容。只读任务读到所需内容后就可以回复。

## 编辑前备份

要修改文件时，确认 `<path>` 仍是同一份可读写文件，记录大小、修改时间和哈希。

在同目录创建时间戳备份并核对哈希。失败即停止。

## 编辑

从只读备份 `SOURCE_DOCX` 取要改的内容，在唯一目标 `TARGET_DOCX`（原 `<path>`）上增量修改。

需要 DOCX 写法时，从 [DOCX 编辑方法](docx-editing.md)读取本次涉及的定位、结构保留和专项操作。

目标、计划和交付沿用本页及 Canvas 流程，不另建固定清单或计划表。

若本轮已在 Canvas 应用改动，必须先确认磁盘版本已包含这些改动，否则停止文件写入。

## 保存

每次保存前比对磁盘文件的大小、修改时间和哈希，须与最近一次读取或自己成功保存后的值一致。保存成功后记录新值。

- 首次写入前发现外部变化，可以重新备份和定位一次。
- 再次变化，或写入后发现外部变化，立即停止。
- 任务要求排他写入时，说明本流程无法保证并停止。

## 交付

保存成功后按 [Canvas 交付规则](canvas-doc.md#交付)直接交付，说明原路径和备份路径。

客户端要求交付文件时，交付原路径的文件。

不得把此前 CLI XML、OOXML 候选或历史上下文覆盖到 `<path>`，也不得把 token 拼成 URL。
