## 图片转 Word

从一张或多张图片新建 Word 时，按本流程执行。需要写入已有 DOCX 时，按顶层 `SKILL.md` 中`场景路由`选择对应编辑流程，图片读取和转录参照本文。
默认生成可编辑正文、Word 表格和原生公式，保留原图内容、层级、阅读顺序和主要版式。先明确用户要求保留、删除和改变的范围，变化只作用于指定内容或属性，不套用通用文书样式。仅提取文字时可简化视觉形式，但保留信息层级与对应关系；要求纠错、重排或仅插入原图时按要求处理。图片只作配图或风格参考时，走原有新建或编辑流程。
未要求删减时，页眉、页脚、原页码、水印和署名均保留其角色，不混入正文或按新分页改写原页码。删除项按内容作用识别，位置仅作辅助；在文字、文本框和配图等承载位置一致处理，不连带删除非目标内容。

### 本场景的校验规则

图转word场景不要遵循 `SKILL.md` 中禁止最终校验、回读修改及使用校验或渲染工具的要求；生成后按本文“检查成稿”完整检查，修复问题并复查后再交付。在检验过程中不要怕浪费时间。

### 执行步骤

- **读清原图**：按用户指定顺序逐张完整读取；未指定时按附件顺序。先确定原件区域，区分工具栏、选区边框和纸外背景；校正拍摄旋转，再判断原件的横竖排、栏目及阅读顺序。复杂页面先明确各区域包含什么、标签属于谁、对象与何处相连、哪些位置需要留空，作为还原与核对的依据。密集、手写或低清区域放大后逐区读取，相邻区域留重叠核对接缝，不跳过图旁、图下文字；无需另交大纲或核查表。
- **逐区还原**：逐行核准文字、数字、标点，按原段落和条目组织内容，再执行用户要求的翻译、注音或纠错，派生内容与原文保持对应。用户未要求时不改原字、重复编号、占位符，不新增标题、解答或解释。看不清或截断处保留可辨片段，仅在缺口处标明不确定；语句通顺、常见写法或领域常识不能作为补字、补数的依据。
  按内容作用选择表达方式：文字用原生文字；依赖图形表达的信息保留图内文字、标记、方向及与正文的对应，不用描述或普通表格替代连接关系。未要求图形原生编辑时可使用完整清晰的原图局部，嵌入后核对比例与四边；要求原生编辑的对象使用形状、文本和连接线，逐项核对形状、连接端点、尺寸与标签归属。背景装饰可单独保留为图像层，避免与转录文字重复叠印。颜色、圈线、着重标记等保留原作用范围；小图、功能入口和留白若承担阅读、判断或填写作用，都应有对应表达，不能因非文字或面积小而省略。
- **表格与公式**：表格用 Word 表格。先把可见边界映射为一致的底层网格，按原跨行、跨列关系保留表头、分组、共享说明和空白填写区；逐格核对字段、数值及其所属行列，共享信息覆盖的对象不能改变。按原比例、内容长度和填写用途分配列宽，在可用宽度内整体调整，避免短标签挤占正文或填写空间；保留边框、底色和对齐，不擅增删空白行格或添加占位符。
  公式含行内变量均用原生 OMML，按原位置与正文混排；逐符号核对整式各项、公式内文字、式号，以及分数、运算符、括号和上下标的作用范围，不因表达等价而改写。整式不拆成公式与普通文本拼接，衔接处不重复抄入同一字符，不用截图或斜线文本替代分式。
- **安排版式**：保留原件方向、分栏、图文相对位置与空间比例，不把窄格内横排折行当成竖排，真实竖排中的数字和字母保持原朝向。对象按所在栏或单元格的可用宽度排放，不超出容器。以能独立理解或使用的最小关联单元安排分页，例如标题与首段、图表与题注；可在一页自然容纳的单元保持完整，更长内容在不破坏归属关系的位置拆分，跨页只重复真实表头。出现新增分页或稀疏尾页时，先回查段落边界、页面可用区域、列宽和对象尺寸，以及实际生效的文字间距、单元格内边距，修正后再安排分页；保留实际填写空间，避免孤行，不靠缩小文字或删留白强压页数。不强求一图一页，原有并排、重复区域照原关系安排；跨图衔接只合并已确认重叠的片段，不自动去重原有内容。
- **检查成稿**：使用 `<Word skill 目录>/scripts/render.py render TARGET_DOCX --output-dir TASK_TMP_DIR` 指令获取 `PDF` 和 `PNG` 渲染结果（`TASK_TMP_DIR` 为本任务临时输出目录），退出码 `0` 表示渲染成功，`1` 表示未成功（注意渲染图中公式结构可能不会正确显示，不要去尝试解决这个问题）。成功后必须逐张查看返回的全部页面图片，以原图为依据双向核对：从原图逐区检查文字、对象、标记、空白及其归属均有对应；从成稿反查每项内容与样式变化均有来源或用户要求的依据。逐行回核正文，逐符号回核公式，重点复查关键值与低置信片段，不只比关键词或对象数量。
  逐页综览检查方向、区域缺失与分页，局部放大检查小字、细标记、长内容末端、公式及对象四边；同时检查关联内容是否仍可独立理解、填写区域是否实际可用。修正后重新保存和审计，内容改动回核对应原区，布局改动复看受影响页，分页变化连查后续页；中间版本预览不能代替终稿检查。结构合法、页面可见与含义正确分别核实；渲染异常结合文档结构判断，不把原生公式改成普通文本消除异常。不同引擎显示不一致时，结合原图和文档结构定位，不把替代预览等同于目标编辑器结果；未实测的兼容性不作保证。
- **交付文件**：交齐用户要求的文件，说明实际核实的页数、可编辑范围和待核内容。多种格式分别核对，区分文字、形状、轮廓与图片的编辑范围；未提供的模板或未实测的应用兼容性不作保证。正文只保留所需内容与必要的局部缺口标记，转录说明和过程记录放交付回复。

### 注意事项

以下按实际内容和用户要求选用。

- **生成依据**：在已有转录变量或数据结构中，一并保存原区的文字片段、局部格式、对象引用、留白用途及归属，再由其生成文档；不能只存纯文本后凭记忆补图或重建关系。空白区域也参与网格和版式构建。调版复用这份已核准内容，只修改受影响属性；确需改字先回查局部字形，更新同一份转录，不另抄一遍。记录只供生成与回核，无需另交付。
- **表格宽高**：先由来源边界建立含空白区域的网格，再写内容和合并。`python-docx` 的 `cell.width` 只写单元格宽度，不会同步底层网格；在合并前逐列设置 `table.columns[i].width = widths[i]`（数组元素用 `Length` 值），再由同一数组派生 `tblW`、`tblGrid` 与 `tcW`，写 XML 时统一用整数 twip，`tblW`、`tcW` 的类型设为 `dxa`。按每行实际 `w:tc` 的网格位置及 `gridSpan` 写入，跨列宽度为覆盖列宽之和，不通过 `row.cells` 的合并别名反复覆盖同一格。保持比例时设置 `table.autofit = False`；更新已有单值属性，不重复追加。保存后读回验证总宽等于网格列宽之和、每格宽度等于其覆盖宽度，并核对合并首行和续行；不一致先修正再调字号或分页。含换行文字使用自动或最小行高，避免固定高度裁字。
- **表格边界与表头**：逻辑网格与可见边框分别设置，合并后清理不应显示的默认或继承线条，斜线端点和标签以所在格定位。多层表头将完整、连续的真实表头行设为重复，包括纵向合并的起始行和续格行；正文分组行不因此变成表头。发生跨页时查看续页的完整层级、标签归属及首条记录，不能只检查首行的重复属性。
- **段落与间距**：结合编号、缩进及上下文识别真实段落，自然折行不另建段；有语义或版式作用的分行保留。按原比例分别分配内容、填写区和区域间隔，避免各生成函数默认累加段前、段后距和撑版空段。异常分页先查容器宽度，再查直接格式、样式及继承默认中的有效间距；`space_before/space_after = None` 表示继承，不是零，确需清除模板间距时显式设零，空段本身的行高也要计入。空白行格和作答线按来源的数量、分隔及可用宽高建立，不因无文字而删除，也不额外扩张。填写线用制表位引导线或边框，并查看实际长度。换渲染器后出现差异时先查字体替代和布局约束，不凭页数直接压缩内容。
- **关联内容与空间**：先确定能在一页自然容纳的短组所包含的实际节点，涵盖提示、图像和作答线，不只连接题干或标题。在段落的 `paragraph_format` 中，组内设 `keep_together = True`（`keepLines`），除末段外设 `keep_with_next = True`（`keepNext`），末段显式设 `False`；标题连接到实际首内容，跨空段、表格时沿实际节点继续，不能仅遍历不含单元格正文的 `document.paragraphs`。短表格行用 `cantSplit`；它只防行内拆分，跨行短组还需串接非末行各实际单元格的段落，在组末结束。长组在子项或记录等可理解边界续页并保留共享归属，不把整篇锁定。并排长内容用可独立折行的容器；放大对象时同步调整容器与标记。保存后查看分页两侧，不能用属性存在代替关联有效。
- **图形与功能对象**：需保留图形且未要求其原生编辑时，复杂图优先采用完整清晰的原图局部，正文仍用原生文字。每个来源对象先绑定实际图片或原生对象及其放置位置，插入齐全后再微调排版，名称或解释不能代替对象。裁图坐标换算回原图像素；先查看裁出的局部，四边包含完整图形及相关标注，再检查嵌入后的比例与边界。原生重建共用校正、裁剪、缩放的坐标变换，图形、标签和连接端点一起定位，文字朝向另设；同一区域对象使用一致的定位参照，避免独立锚点随段落漂移。小型功能对象也逐项绑定和核对，不只清点大图或媒体文件数。
- **局部修正**：`paragraph.text`、`cell.text` 重赋值会重建子内容；已含局部格式、公式或图形时，调版应修改对应对象属性，不能用整段纯文本回填。公共样式先设置，再按来源文字片段应用局部字色、字重、底色及标记，不用加粗代替底色，不把字或首行的样式扩大到整段或整格。着重号也区分位置：`w:em` 的 `dot` 为字上点，`underDot` 为字下点；按来源选择并查看实际位置。保存后回核原编号、关键值、对象归属、局部样式及填写空间；过程说明留在交付回复。
- **图形颜色值**：直接写 DrawingML 时，`a:srgbClr` 的 `val` 使用不带 `#` 的六位十六进制值，例如 `000000`。结构合法后仍需查看实际线条、文字和裁切情况。

直接编写 Word 原生公式（OMML）时，注意以下结构。“子节点”指放在某个节点内部的内容项，“属性”指写在节点自身标签上的设置。

- **公式字符格式**：`m:r` 表示一段公式字符；`m:rPr` 管数学格式，`w:rPr` 管字体、颜色等文字格式。两者同为 `m:r` 的直接子节点，不相互嵌套。
- **求和、积分及上下限**：`m:nary` 表示求和、积分等运算，属性容器是 `m:naryPr`，不可写成 `m:nPr`。其中 `m:chr` 的 `m:val` 指定原图的 `∑` 或 `∫`，避免运算符变成默认符号。`m:sub`、`m:sup`、`m:e` 分别存放下限、上限和参与运算的内容，均保留；没有上下限时将对应节点留空，并在 `m:naryPr` 中把对应的 `m:subHide`、`m:supHide` 设为 `m:val="1"`，用于隐藏空位置。
- **极限条件的位置**：`m:limLow` 用于在主体下方放置条件。例如在 `lim` 下方标注 `h→0` 时，将 `lim` 放在 `m:e`、`h→0` 放在 `m:lim`；两者都是 `m:limLow` 的直接子节点。
- **括号和绝对值**：`m:dPr` 保存左右符号的设置。左符号写在 `m:begChr` 子节点，右符号写在 `m:endChr` 子节点，符号本身用各自的 `m:val` 指定；例如绝对值两端都设为 `|`。不要把 `m:begChr`、`m:endChr` 写成 `m:dPr` 的属性。
- **局部颜色**：颜色只作用于原图着色的字符，不扩大到整项或整式。原图是红圈内的黑字时，应保留红圈和黑字，不能用红字代替。
