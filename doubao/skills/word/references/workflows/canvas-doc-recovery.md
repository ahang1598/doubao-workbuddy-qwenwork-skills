# Canvas 遇到问题怎么办

## 停止条件

权限被拒绝、用户取消或 `token` 无效时，停止对这份 Canvas 的操作，告诉用户原因。

## 读取失败

读不到内容时，按错误信息选择缩小范围、等客户端加载，或用 `+ooxml-fetch` 取回 DOCX 来读，不把这些方法依次跑一遍。

只有明确知道整个 Canvas 连接不可用，且允许读取原文件、已保存内容也足以回答时，才读取磁盘文件。

告诉用户这份文件可能缺少 Canvas 上尚未保存的改动。

## 写入回执

### 结果不明

写入没给出明确结果时，先跟进原请求。

- 后台还在处理或结果仍不明时，暂停对同一份文档的写入。
- 请求未结束时，读到旧内容也不能证明它没有写入。

### 部分成功

回执为 `partial_success` 表示写入已执行，但有内容或格式可能降级。根据回执判断哪些目标还没完成，只处理能明确定位的剩余问题。

## 写入失败与提交超时

明确知道原请求已结束且没有写入时，按失败原因处理。

- 版本冲突就用当前内容和版本继续。
- 命令不支持时，查用法或换一个能完成同一改动的工具。

整份 DOCX 提交超时或结果丢失时，继续跟进原请求，别再提交一次。

## 恢复范围与结束

恢复只处理本次错误，复用已有材料和已完成的改动。

- 修正一次后仍是同一错误，且没有新线索时，说明未完成部分，停止重复尝试。
- 查询暂时超时不代表写入失败；原请求仍在执行或结果不明时，说明状态尚未确认，暂停后续写入。

恢复成功后按 [Canvas 交付规则](canvas-doc.md#交付)结束，不补一轮全量检查。

## 客户端暂时无法编辑

客户端暂时无法提供 Canvas 编辑时，告诉用户原因。用户保存并关闭后，原文件可写且上一笔写入已结束，就可以按[关闭后的原文件](canvas-doc-close.md)处理。
