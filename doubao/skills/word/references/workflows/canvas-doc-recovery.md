# Canvas 失败恢复与标准化结果

**进入条件**：Canvas 读取、更新、提交或回读失败，写入终态未知，或更新返回 warning / `partial_success`。输入包括原始调用证据、当前 `edit_plan`、路由记录和写入状态。

按调用阶段返回结果：

- **Local 只读**：恢复成功后将新读取结果交回原阶段，继续能力判断或只读回答。
- **Local 更新**：返回本页定义的一个标准结果。
- **OOXML Fetch**：更新 `ooxml_fetch` 的 ready/unavailable 状态，保留失败分类、路径与原始信封。

正文 Local 和 OOXML 获取结果交回 [`canvas-doc.md`](canvas-doc.md#第四层cli-调用与失败判定)；OOXML Update 的已受理、明确未派发、`unknown_write` 或 `local_blocked` 交回 `canvas-doc-ooxml.md` 的提交步骤；目录结果交回独立目录阶段。本页不重选引擎。

标准结果名、原始错误码和恢复动作只写入内部记录。需要告知用户时，按 [`canvas-doc.md`](canvas-doc.md#用户可见表达) 转换为内容、格式、版面、保存状态或所需用户动作，不直接复述路由和工具名词。

> 使用前须完整读取本页；未见末行「全文完」时，调整 offset 继续读取至该标记。

## 失败处理

固定顺序是：**确认写入终态 → 验证 warning 或实际偏离 → 必要时使用剩余修正预算 → 返回标准结果**。本页的读取、补提交和修正请求同时计入入口记录的 CLI 实际调用数；不得先换引擎再确认终态，也不得通过改名、换 scope 或换命令重置任一预算。

### 1. 先确认终态

- 后台任务仍运行：只跟踪同一 task，不重发。
- 写请求已派发或派发状态不明：按操作类型只读回读；正文用稳定相邻锚点，表格读整表，layout 读 `layout + full`，分页读 `page`，图表读 `chart_data`，目录/水印用领域验收范围。
- 将写入终态与验收结论分开记录。完整成功回执须满足命令的终态字段；普通 Local Update 的 `partial_success` 表示已应用但含诊断，不表示回滚或尚未写入。回执不足时，须确认原任务已终止，再以最新完整回读确认实际写入范围和结果；旧快照、部分目标、无响应、非法 JSON、缺字段和脚本解析异常都不能自行消除未知。
- 已确认写入终态但缺少格式、结构或必要视觉证据时，记录验收缺口；不能因此改称 `unknown_write`，也不能记为已验收。
- 终态仍未知立即返回 `unknown_write`。在未知消除前禁止新增写入、OOXML 提交和文件分支。

### 2. warning 先验证，实际偏离才修正

本节的标准结果用于 Local 更新；OOXML Update 仍按其专项同步门禁处理。Local 更新出现任意 warning 或 `partial_success` 时暂停后续写入，按[公共 warning 契约](../cli/canvas-doc-update.md#warnings-的格式)逐条分类，并复用或补齐覆盖已提交目标及保留项的完整回读。`COMPAT_STYLE_LOST` 不能只回读文字后结束，也不能仅凭警告自动重写或切换 OOXML。

- 对照写前基线与计划变化，核销目标内容、结构及非目标格式；视觉检查仍按[编辑流程](canvas-doc-editing.md#第-4-步--回读验收)触发。可在批次结束统一做的视觉检查仍保留为待办；后续编辑依赖的检查须先通过。
- 当前屏障要求的证据齐全且无非预期差异时，返回 `local_succeeded`，保留原始 warning / `partial_success` 和验收依据。无需把 warning 消除，也不为取得干净回执重复提交。
- 只有确认非预期差异或参数/XML 错误时，才使用下表每目标共享的 1 次合并修正。以最新状态定位，在写前基线和计划约束下恢复非目标项并完成目标；不能把已降级结果当成新的保真基准。
- 修正后仍须回读。同一 warning 再次出现不等于同类实际偏离复现；证据通过即可结束，真实偏离复现才判 `local_unstable`。
- 在适用读取预算内仍无法核销当前屏障必需的保留项时，已知写入终态返回 `local_blocked` 并记录缺失证据；终态本身仍未知才返回 `unknown_write`。停止后续写入，不猜测通过、不为消除警告试写。

只读验证计入 CLI 总调用数和适用读取预算，不消耗合并修正的写入次数；已有完整且有效的验收证据直接复用。

### 3. 使用固定恢复预算

同一目标、同一读取阶段从首次可恢复失败起共用一个 20 秒墙钟截止时间（包含请求执行和等待）；加载态、超时和 5xx 交替出现也不重置。超时/5xx 的补请求至多 2 次，同时受该截止时间约束；单次只读调用由进程执行器设置不超过剩余预算的超时，截止后不再派发新请求。`--timeout-ms` 仅用于契约支持的 PDF scope，不给其他命令添加该参数。写前读取与写后验收分别记账；OOXML 提交后的必要同步校验使用其专项 60 秒预算，不再叠加本页读取窗口。

| 失败类型 | 允许动作 | 预算耗尽后的结果 |
|---|---|---|
| 加载态的只读请求，或明确未派发的请求 | 按 `0.5s / 1s / 2s / 4s` 起退避，之后每 4 秒；同一目标总墙钟不超过 20 秒 | 按实际证据分类 |
| 写前 Local Fetch 临时超时/5xx | 最多补请求 2 次；full 超时可缩小范围但共享预算 | `local_unstable` |
| 写后回读临时超时/5xx | 最多补请求 2 次，在同一 20 秒读取预算内确认完整目标和保留项 | 写入终态仍未知为 `unknown_write`；终态已知但验收证据不足为 `local_blocked` |
| OOXML Fetch 临时错误 | 最多补请求 2 次；返回路径暂不可读时只等待同一路径 | 记录 OOXML 不可用，交回入口 |
| Local Update 超时/5xx | 先回读；仅在明确未落盘且定位稳定时补提交 1 次。样式 commit 例外：确认原请求已结束、原 plan token 仍有效且 document/command/intent/guards 完全一致时，可原样重放 1 次取得幂等结果；不得改 payload 或并发重发 | 仍明确未落盘为 `local_unstable`；终态未知为 `unknown_write`；已确认应用则按第 2 节验收分类 |
| OOXML Update 超时/5xx | 跟踪同一 task，必要时只读确认以消除未知；不重发整份提交 | 取得完整成功回执并核对 warnings 后，按 OOXML 的既定同步门禁继续；明确未派发为 `local_blocked`；否则 `unknown_write` |
| 参数/XML 错误或已确认的非预期回读偏离 | 每个目标共享 1 次合并修正；修正必须基于公开契约、写前保留约束和最新状态 | 调用错误为 `local_blocked`；同类实际偏离复现为 `local_unstable` |
| ID 失效或内容冲突且明确未写入 | 最新完整 Fetch 后补提交 1 次 | `local_blocked` |
| 定位不唯一 | 重新 Fetch 消歧 1 次 | `local_blocked` |

恢复不得删减或弱化 `edit_plan`。`ATTR_CAPABILITY_LIMITED` 影响用户目标或 baseline 保真时返回 `local_unsupported_runtime`；只有结构化证据明确不支持时才使用该结果。`partial_success` 本身不决定分类。权限/确认拒绝、样式 token/fingerprint 冲突及其他明确停止状态返回 `local_blocked`。

已验收目标不回滚、不重发；恢复只处理当前失败和剩余目标。任何相同失败在预算耗尽后必须结束分类，不循环修正。

### 4. 宿主 PDF 失败

保留导出的原始错误，按上节实际失败类型判断能否重试，共享当前阶段剩余读取预算；不能把任意渲染错误都当作临时超时。已有有效宿主页面证据足以覆盖验收时直接复用，否则在明确不支持、不可恢复或预算耗尽后，把缺失的页码/版面检查保留为未验证，停止依赖这些证据的后续写入，按原流程披露已完成项和缺口。

PDF 失败不使已确认的写入失效，也不表示全部 Canvas CLI 不可用；不因此重发目录命令、重选正文路由或提交旧 OOXML 候选。即使任务另有离线诊断需求，LibreOffice 等本地渲染也不能清除当前 Canvas 的待验收项；不把其页码写入 TOC/PAGEREF 缓存。后续进入合法修正周期时，仍须保留这些待验收项，以修正后的宿主证据核销。

## 全部 Canvas CLI 不可用的判定

`all_canvas_cli_unavailable` 表示 Canvas 命令通道整体不可用，不表示某个命令或能力失败；仅在没有未知写入时判定：

1. 保存首次失败的 returncode/stdout/stderr 和结构化错误。
2. 只做一次环境修复：重新解析现有 `lark-cli`，核对 `+local-fetch --help` 与 `+ooxml-fetch --help`，修正工作目录、API 版本、公开参数或误选命令；不安装、不更新、不写文档。
3. 修复后按上述读取预算依次测试最小 `+local-fetch` 和只读 `+ooxml-fetch`；同一环境下已有的成功/失败证据直接复用，环境确实变化时只重验受影响入口，不重置已用恢复预算。OOXML 获取成功时保留路径供后续使用；任一成功都不能输出“全部不可用”。
4. 只有 CLI 无法启动导致两个入口都不能执行，或两个入口均稳定返回同类环境、桥接、客户端级错误，才输出 `all_canvas_cli_unavailable`。

普通超时/5xx、单个未知命令、非法参数/XML、无效 token/path、权限拒绝、定位冲突、单项能力不足、Local 写后回读失败，或只测试一个入口，都不满足此结果。

## 标准化运行结果

| 结果 | 必须具备的证据 | 含义 |
|---|---|---|
| `local_succeeded` | 只读阶段：取得退出码 0、完整 JSON、`ok=true` 及该 scope 必需内容，读取 warning 不影响当前目标；更新阶段：写入终态已确认，warning 已分类，当前屏障回读核销目标与保留项，可保留已验证的 `partial_success` | 只读成功交回原阶段；更新成功表示当前 Local 目标已验收，计划内后续检查仍须完成 |
| `local_retryable` | 明确未写入、只读失败，或终态已知且已确认可安全修正的实际偏离；仍有固定预算 | 留在 Local 恢复 |
| `local_unsupported_runtime` | 结构化错误明确不支持，或能力限制破坏目标/baseline | Local 能力不足 |
| `local_unstable` | 写前 Fetch 耗尽；补提交后仍明确未落盘；或同类实际偏离复现 | Local 运行不稳定 |
| `unknown_write` | 仍运行，或派发/响应不明且回读仍无法确认写入终态 | 阻断所有新写入 |
| `explicit_close` | 宿主字段或 CLI 结构化结果明确关闭 | 文件已关闭 |
| `all_canvas_cli_unavailable` | 符合上一节的双入口整体不可用证据 | Canvas 通道整体不可用 |
| `local_blocked` | 权限/确认拒绝、无法消歧、调用错误预算耗尽、冲突无法解决，或写入终态已知但当前屏障必要验收证据不足 | 当前目标必须停止 |

输出一个结果后立即返回对应调用阶段，不在本页调用 `+ooxml-update`、进入文件编辑、选择候选路径或改变目录策略。
