# Canvas 打开态 CLI 编辑流程

- **读取条件**：仅在以下情况读取：[`canvas-doc.md`](canvas-doc.md) 要求完成最少必要读取与 CLI 能力/预算判断、前两层优先 OOXML 但探测不可用后评估 Local，或已选中 `open_local`。
- **职责**：按操作类型给出一次 Local 能力与调用预算结论；在 `open_local` 中完成计划、写入和验收。
- **边界**：不重新选择首选策略、OOXML、文件分支或最终交付。用户可见表述遵循 [`canvas-doc.md`](canvas-doc.md#用户可见表达)，不播报路由名、命令或状态值。

> 使用前须完整读取本页；未见末行「全文完」时，调整 offset 继续读取至该标记。

## 输入、输出与执行顺序

**输入**：`file_status=open`、无未知写入、本轮目标与路由记录。**输出**只能是：

- 写前：`local_supported` / `local_unsupported` / `local_unverifiable`；`local_supported` 同时返回 `local_budget_ok` / `local_budget_high` 及计算依据；
- 执行后：成功证据，或 [`canvas-doc-recovery.md`](canvas-doc-recovery.md) 的一个标准结果。

顺序固定为：**最新目标 → 最少必要读取 → 按操作类型完成一次能力门禁 → 调用预算 → edit_plan 与写入分组 → 屏障回读 → 必要视觉验收**。同一份最新 Fetch 同时用于门禁、预算和写前 baseline；能力与预算门禁通过后不重复评估。执行失败或更新出现 warning / `partial_success` 时交给 recovery，随后回到入口消费结果。

> **CLI XML 编辑原则**：① 正文编辑从首次内容读取就选择 `--detail full`，scope 仅覆盖必要范围；layout 的 `with-ids` 也包含完整样式；② 在返回 XML 上修改，`block_replace` 保留 ID 不等于继承省略的行内格式；③ 新增内容按用户要求或写前确定的同类基准显式携带格式；④ 用“写前基线＋计划变化＋验收屏障后的完整回读”验收，不能只比较提交 XML 与回读，或凭 `warnings=[]` 判定保真。

按命中的命令契约和 XML 专项确认命令、读取身份、合法写入、baseline 保真、写后验收五项。五项均成立才返回 `local_supported`。修改点数、篇幅和预计调用次数不改变能力事实；在能力成立后按入口的[调用预算门禁](canvas-doc.md#第三层最少必要读取cli-能力与调用预算)独立决定是否实际选择 `open_local`。

### 第 1 步 · 理解任务并读取定位

- 判断用户的任务是一个指令明确的简单编辑任务，还是一个包含写作质量要求的任务。
- 对于包含写作要求的任务，读取 [`../style/writing-taxonomy.md`](../style/writing-taxonomy.md)，结合用户要求和已经完整读取的附件选择一个体裁，并完整读取对应指南。写作指南只能补充用户和原稿未规定的内容与表达规则，不能覆盖用户要求、可靠材料、原稿固定结构或计划外内容。规则优先级为：用户明确要求与可靠材料 > 原稿中必须保留的内容和结构 > 类型指南 > taxonomy 通用规则。当前稿件仍是版式 baseline，不套用 `assets/templates`。
- 如用户有附件，按 [`SKILL.md` 的附件前置处理](../../SKILL.md#附件前置处理) 完整读取与任务相关的内容和结构，明确每份附件的角色并维护 `attachment_purpose.md`；只有摘要或局部摘录时，必须按源定位回读原件。
- 判断任务是否为强附件和信息遵循类型；公文、论文、法律、科研等严谨场景以附件原文为事实边界，不得自行补写。
- 按 [读取流程](canvas-doc.md#读取流程)选择最小且足以规划与验收的 scope/detail；样式、布局、图表数据等查询直接使用对应 scope，不预先读取无关正文。取得目标及必要相邻内容的最新状态和 block ID；不使用跨轮或前序写入前的旧内容、XML 或 block ID；同轮有效响应按入口中的读取复用规则使用。

**写前身份与快照门禁**：按命令选择对应条件，缺失时先补读取或修正寻址，不试写：

| 操作 | 写前要求 |
|---|---|
| 修改/删除已有 block、表格 | 目标 ID 来自最新 Fetch，在 owner/story 内唯一命中，根标签与 [寻址表](../cli/canvas-doc-update.md#可寻址标签与可用命令) 一致。Field、Note reference 和 story owner 不能作 block target；story 内合法 block ID 可更新，但不能作正文 range/section 锚点 |
| `block_replace` 或依赖 carrier/owner graph 的操作 | 完整快照含必需属性、defaults、非目标子节点及 detached graph；正文摘要、裁剪结果或 `BLOCK_REF_INCOMPLETE` 不能作底稿，layout 的 with-ids 例外同上 |
| 插入、`append` | 确认真实插入锚点或文末位置、容器/节归属及同类格式；按页首/页尾定位时还必须满足 [`页面边界证据门禁`](canvas-doc.md#读取流程)；新对象按语法省略或分配身份，不要求 Fetch 已存在的新对象 ID |
| `str_replace` | 确认目标文本和共同格式，遵守全搜索范围唯一性；不传 block ID，固定 block 的修改优先按下表选择 |
| 样式、图表数据、目录、水印 | 使用专项定义的身份、版本/fingerprint、作用域及新建条件；不套用普通 block 根标签规则，预创建成功不等于已挂载 |

前序写入、协同变化、revision 冲突或目标移动/删除后重新读取受影响范围，确认身份、锚点和相邻关系。所有既有身份直接来自响应，不手写、推测或跨 story 复用。

**读取警告处理**：先判断警告是否影响本次操作所需的身份、快照完整性或保真。已确认不影响的记录后继续；能通过调整 scope/detail 或补齐 owner graph 解决的，针对性重读并重新检查；仍影响目标或无法确认时，产出 `local_unverifiable` 交回 [能力门禁](canvas-doc.md#第三层最少必要读取cli-能力与调用预算)。警告本身不表示快照过期，不原样反复 Fetch 来消除同一警告。

写入前按 [`canvas-doc-update.md` 的读取导航](../cli/canvas-doc-update.md#按需读取)完整读取公共契约、当前命令章节和所涉 XML 规则；纯文本替换不要求 XML 规范。同轮已完整读取且仍可见的章节不重复加载。

### 第 2 步 · 规划修改

在上下文记录每个独立目标的定位、期望变化、必须保留项及验收条件，作为轻量 `edit_plan`，并标明所属写入组及其验收屏障；执行后在同一记录补充实际证据和验收结果，无需另建计划或验收清单。先复用入口已有的规模与请求下界：写请求或总请求已超过适用阈值，或无法形成有限上限时，立即返回 `local_budget_high`，不为精确目标总数、完整 ID 清单或逐项合法性继续 Fetch/解析。只有下界未超限时，才选择最小操作、完成安全合并，并证明 `estimated_write_calls`、`estimated_validation_calls`、其他后续读取、固定 2 次恢复预留和 `estimated_total_calls` 的有限上限，交回入口判定 `local_budget_ok/high`。第一笔正文写入前必须已有预算结论；重试和修正按同一目标记账，改名、换命令、重定位或拆分批次不重置预算。先完成会改变标题、正文、布局或对象位置的前置编辑，再读取受其影响的目录、页码、布局和 fingerprints，避免使用失效基线；所有写入仍串行执行。

润色、纠错或“加粗修改处”默认保留原段落、空段、段内换行及非目标格式；不要把分行、短段或空段仅凭文本观感认定为错误并合并、删除。只有用户要求调整结构，或完成目标确需改变边界且依据明确时，才将该变化纳入计划。加粗只作用于需要标记的文字，按[局部文字与格式修改](../xml/canvas-doc-text.md#局部文字与格式修改)保留其余样式。

#### 列表重组与保留项

增删、拆分、合并或重新分组有序条款时，在同一 `edit_plan` 中记录受影响列表的分组边界、编号层级、起始／接续关系，以及保留项在新结构中的位置；验收范围包含这些保留项和衔接处，不只包含改过文字的块。

- **保留内容不等于冻结旧编号结构**：前序项被删除或移入新列表后，原本自动接续的保留项可能成为旧列表首项。逐项确定它应接续哪个分组、是否有意另起编号，或在用户允许重组且它仅为引导语时改为无编号段落。业务文字、引用关系和用户明确要求保留的编号仍须保留；不能一律去号或统一从 1 开始。
- **列表归属不能靠外观推定**：相邻的 `<ol>` 即使 `list-style-type`、`marker-template` 相同，也不能当作同一个连续列表；`seq="auto"` 不证明会接上前面的另一列表。新分组各自从 1 开始可以是正确设计，应按计划的分组边界核对，而不是查找全文是否出现多个 1。
- **后续补字也要重验同级项**：列表项经 `block_replace` 再次修改后，前次编号验收失效。回读其所属列表、原同级保留项及必要相邻列表，确认没有非计划分裂或重启；合法载荷及单项替换风险见 [Update 列表约束](../cli/canvas-doc-update.md#可寻址标签与可用命令)。

#### 局部格式修改与保留约束

本节同时适用于 Local 与 OOXML。用户要求局部格式调整或明确要求“保留／不变”时，在既有 `edit_plan` 中记录目标范围、允许修改的属性、必须保留的属性及写前值、排除区域和对应检查；不另建一套计划。相同规则可按目标组记录，但验证覆盖组内全部目标。

- **格式要求按属性解释**：“统一字体／字号”只授权对应属性变化，不包含清除颜色、高亮、加粗、斜体、下划线等；“加粗、下划线等强调保留”不是只保留列举的两项。未获授权修改的属性保持原样，用户明确要求去色、清除强调时才将其列为目标变化，不能以“统一风格”或默认排版规范扩大范围。
- **保留原格式结构**：在完整基线上仅修改允许的属性，不先清空格式再重建；拆分文字片段时复制完整格式后再定向修改。属性缺席可能表示继承，不等于无颜色、未加粗或默认值。
- **字符样式盲区**：`full` XML 不导出 character style 引用及其继承格式，写前后 XML 相等不能单独证明这部分保留。涉及这些保留项时补足样式来源或必要页面证据；公开读取仍无法验证时，写前返回 `local_unverifiable`，写后按 recovery 报告验收缺口，不把缺席属性补成默认值。
- **约束共享影响**：改共享样式或编号定义前，检查直接引用及继承链是否涉及排除区域；局部任务优先局部覆盖。确需复制定义并重新绑定目标时，必须保持非目标属性及原有编号连续性；无法证明影响被限制时不修改共享定义，按能力／恢复流程处理。
- **把保留项变成比较条件**：纯格式任务按稳定段落／对象定位及对应文字区间比较内容、强调属性和顺序，不以 run/span 数量相等代替。覆盖全部目标及共享定义实际影响的范围外对象；有编号时另核对显示号码、层级和连续关系。直接格式与继承来源一起检查，只有能证明有效格式等价时才接受表示差异。
- **差异处理与记录**：验收记录位置、属性、写前值、写后值和授权依据；未经授权的差异须定向恢复后重验，不能事后补进计划。必要证据不足时记为未验证，不能靠抽样、通用审计零错误或提交成功宣称“全部保留”。视觉检查仍按第 4 步触发，不因本节无条件扩大到全篇渲染。

### 选择最小操作

复用前面已读取的 [Update 公共契约](../cli/canvas-doc-update.md#按需读取)，按命中命令和对象补齐所需章节。workflow 只保留选型顺序，命令参数、标签和属性边界以专项契约为准：

| 顺序 | 场景 | 选择 |
|---|---|---|
| 1 | 搜索范围内唯一的单处纯文本替换，且新文字只需共同格式 | `str_replace` |
| 2 | 同一 carrier 内多处文字/格式变化，或需保留各 span | 基于最新 `full` XML 合并为一次 `block_replace` |
| 3 | 已有 block、表格、layout、story 或领域对象 | 使用最小可寻址命令；精确命令可用时不扩大到父级或整表 |
| 4 | 相邻新增内容 | 复用真实锚点和相邻同类格式，合并为一次 `block_insert_after` / `append` |
| 5 | 样式、图表数据、目录、水印 | 使用专项领域命令；XML content 与领域 option 不混用 |

所有选型沿用第 1 步的写前身份、快照及读取警告门禁，不重复进行能力探测。

`block_replace` 只修改计划内内容，其余 XML 和属性保持不变。含 Field、Note、Drawing、书签、分离 story、共享页眉页脚等复杂对象时，即使只改普通文字也须加载专项并核对 owner graph。图片/表格尺寸需要版心时才补读 `layout + full`；纯文字或保留尺寸的格式修改不额外读取 layout。

保存稳定相邻锚点用于写后重新定位；不为减少请求扩大替换范围。

### 批量修改与验收屏障

需要多次 CLI 更新时，只有入口已选择 `open_local` 才能执行。优先使用单个 Python 脚本串行处理，但脚本每次只发出一个请求并完整解析结果，不能预先排队或在后台继续发送后续写入。脚本按参数数组调用 CLI，显式指定工作目录和 UTF-8 编码，不依赖 Bash、`eval` 或拼接命令字符串。并行写入同一文档始终禁止。

规划时把目标划为三类，优先使用靠前且安全的类型：

| 类型 | 适用条件 | 写入与回读 |
|---|---|---|
| 合并写 | 同一 carrier 的多处文字/格式修改，或同一锚点后的相邻新增内容；可形成一个合法最终载荷 | 一次 update，一次完整回读 |
| 延迟回读组 | 多个目标来自同一份仍有效的完整快照；目标互不重叠、无前后依赖，只做不改变 block 顺序、数量、身份、坐标、story/owner graph 或分页结构的确定性修改；每次写入都能以安全寻址或当前 revision/checkpoint 发现目标漂移 | update 串行执行；全部干净受理后，在一个验收屏障统一读取覆盖全部目标的最小范围 |
| 逐项屏障 | 插入、删除、移动、append、表格结构、图片/图表、Field/Note/Drawing、layout、页眉页脚、样式、目录、水印，或任何会影响后续 ID、锚点、坐标、revision、分页及作用域的操作 | 每次 update 后立即完整回读，通过后才执行下一项 |

延迟回读组优先只包含互不重叠的 `str_replace`：唯一 pattern 既是寻址条件，也能在目标已变化时阻止盲目覆盖。独立文本或直接格式 `block_replace` 只有在当前 CLI 能为每次后续写入使用已推进的 revision/checkpoint 时才可加入；不得对同组后续请求复用首次 Fetch 的旧显式 revision。回执不返回可继续使用的新 revision、当前 checkpoint 语义无法确认，或命令缺少等价漂移保护时，将该 `block_replace` 放入逐项屏障。只要无法证明目标彼此独立，就使用逐项屏障；不得为了减少请求扩大替换范围。

**中断条件**：任一 update 的进程退出码非零、`ok != true`、出现 warning、`partial_success`、冲突、响应缺字段、终态未知、非预期新 ID，或检测到协同变化时，立即停止脚本和该组后续写入。按 recovery 先确认所有已提交目标的终态，再决定继续、拆成逐项屏障或停止；不能带着未知状态执行批次末回读。原本以 `local_budget_ok` 进入的任务，执行中若目标扩张或恢复消耗使“已用请求＋最低剩余请求”超过入口预算，在下一次写入前停止，确认现有终态并把 `local_budget_high` 交回入口；不得等循环结束后才上报。带 `budget_override=fallback` 进入的受控兜底已经复用过同一预算和 OOXML 探测结果，不因原有高预算再次选路，只继续记账并在首个非干净结果时进入 recovery。

**执行要求**：

1. `edit_plan` 为每项目标记录定位、期望变化、保留项、写前基线、写入组、验收条件及对应的预计请求数；执行时同步记录累计实际请求数。
2. 每组只做一次能够覆盖全部目标的最新完整读取；范围过大时拆成多个组，不用全文 Fetch 换取更少调用。`block_replace` 使用 `full` XML；新增内容同时读取相邻同类元素。目标已满足则记为 `skipped`；基线漂移且不能自动合并时停止。
3. 按组类型串行提交。每次都按 [公共返回值契约](../cli/canvas-doc-update.md#返回值与验证) 保留 returncode/stdout/stderr，并区分明确未写入、已受理及终态未知；非法 JSON 或缺字段不能推断未写入。
4. 到达验收屏障后，使用能够覆盖本组全部目标和必要相邻内容的最小 scope 做一次完整回读，逐项目标核对内容、位置、结构、格式及保留项；一个目标失败不能把整组记为通过。该回读可作为紧接着下一组的写前基线，但中间出现写入、协同变化或作用域不足时必须重读。
5. 保存组级 Fetch、每项 Update 和屏障回读证据，只向模型返回每项目标的 `success/skipped/failed`、当前 ID 和异常定位。视觉验收仍按下文在相关组及目录完成后统一执行。

- **结果类型**：批处理返回 `clean_success`、`stopped_warning`、`stopped_failure` 或 `unknown_write`，不能只返回布尔值。
- **成功条件**：Local Update 的 `clean_success` 要求退出码为 0、JSON 完整、`ok == true`、`data.result == "success"` 且 `data.warnings` 为空；领域命令另须满足自身终态字段。
- **继续条件**：主循环仅在 `clean_success` 时直接进入下一项。不能仅凭 `ok` 累计成功，也不能打印 warnings 后继续。
- **证据保存**：脚本先分别保存完整 stdout/stderr 和 returncode，再解析 JSON。写命令后不得接 `head`、`grep`、末尾 `echo` 或其他会替换退出码、截断信封的管道。

`stopped_warning` 必须退出提交循环并进入 recovery 验证；只有 recovery 返回 `local_succeeded`、本组此前已提交目标均已核销，且剩余预算与定位仍有效时，才从下一未完成目标恢复。保留当前回执的 warning / `partial_success`，另记目标已验收，不改写为 `clean_success`，不重发已完成更新。使用回读确认的当前 ID、基线及漂移保护；独立性不再成立时拆成逐项屏障。

批量执行不能以规划阶段的 ID、命令成功或笼统的最终全文 Fetch 代替逐项目标核销。缺参、缺文件、未知命令或缺少验收证据均为失败；`skipped` 只表示写前已证明满足目标。组中断后先按恢复流程确认当前写入终态；已落盘但未验收的目标在同一屏障中回读，不直接重发。状态明确且恢复条件允许时才继续未完成目标。

### 第 3 步 · 执行更新

按专项组装 XML/content 或领域 option，二者不混用。使用 `docs +local-update` 提交更新，按 [公共返回值契约](../cli/canvas-doc-update.md#返回值与验证) 分支解析退出码、完整信封与命令所需字段；原始错误必须保留，不能用成功字段的索引异常覆盖。成功后逐条检查 warnings；出现任意 warning / `partial_success` 时暂停后续写入，按 [`恢复流程`](canvas-doc-recovery.md#失败处理) 先验证再分类。验证通过即可继续，只有确认实际偏离或调用错误才使用修正预算。样式 dry-run 只记录 diff/impact，携带 plan token 且返回 `applied=true,new_revision_id` 的成功提交才表示运行时样式已更新；响应不暴露内部持久化阶段，最终文件交付仍须保存重开验证。图表数据预创建成功只表示待挂载，不得记为编辑目标完成。

### 第 4 步 · 回读验收

- 当前前端 Update 回执的 `data.document.new_blocks` 始终为空。普通新增块必须使用写前保存且未受影响的前后 block ID、所属顶层容器或章节锚点重新 fetch，不能从 Update 回执推导新 ID。
- `block_replace` 写回原 `id` 时，可按 [目标读取规则](../cli/canvas-doc-fetch.md#编辑前后如何读取目标) 用该 ID 定向回读并核实身份；不能据此取消所属验收屏障。除上节满足并发保护条件的延迟回读组外，通过本次屏障后才能继续下一次写入。未保留 ID、删除或定向回读找不到时，用新 ID、所属顶层容器或写前相邻锚点重新定位；布局仍读 `layout`。仅无可用锚点时扩大到 outline 或必要范围，不默认重拉全文。
- 重新定位后，以**写前完整基线和计划变化**为验收依据：先确认提交 XML 只包含计划内变化，再用写后完整 XML 核对目标生效、非目标内容/结构/格式仍与写前一致；提交 XML 与回读一致不能单独证明保真，正文 `simple/with-ids` 不能用于格式验收。领域 option 对照专项的业务字段和结果验证。比较仅允许服务端生成的 block ID、属性顺序与等价转义差异、明确请求的 clear/remove 所对应的属性缺席、宿主按协议计算的 Field result，以及规范明确允许或与本次 [`REPAIR_*` warning](../cli/canvas-doc-update.md#warnings-的格式) 对应的归一化；其他差异均视为验证失败。后续操作只使用回读确认的当前 block ID，不要求 ID 必须改变。
- 写作型或补充型编辑还要逐条核对 `edit_plan` 的内容依据：每个新增数字、日期、专名、成效、评价、因果结论和能力范围都必须能回指用户指令或附件源定位。来源只支持部分含义时不得外推为更强结论；“估算”“可能”“建议核实”的措辞不能把无来源事实变成可交付内容。发现无来源强断言时先删除或改成不增加事实的保守表达，再继续验收。
- **列表验收保留结构证据**：命中[列表重组与保留项](#列表重组与保留项)时，用写后完整 XML 逐组核对容器边界、层级、项顺序、`seq` 和 `marker-*`，在同一 `edit_plan` 中记录预期与实际编号关系，包含末尾保留项。为语义检查提取纯文本可以另做，但 `re.sub(r'<[^>]+>', '', xml)`、`itertext()` 或正文摘要会丢失编号结构，不能据此判定编号通过。结构不足以确定实际显示时查看受影响页面；发现非计划重启、跳号或分裂，按共享修正预算修复并重验，未核清不得宣告该项完成。
- 同一次完整回读可同时核验内容、位置、结构、格式，并作为紧接着同一范围下一组的写前基线；组内只有符合上节条件的延迟回读目标可共享写前基线。其他中间写入、协同变化或缺少必要对象时重新读取。在同一 edit_plan 核销内容、位置、格式和指令要求；写作型编辑结合该响应与来源证据核验文种、事实边界和表达要求，不为语义验收重复请求。纯格式任务核对内容未变，未要求全文审核时不额外评审全文事实与文风。
- **视觉验收**：用户明确要求视觉检查、XML 无法确认实际版面，或存在大范围正文改写、大段增删、章节重写、表格/图文布局调整、全局排版变化时，默认使用宿主 Fetch `pdf` 导出并逐页查看渲染结果，检查分页、标题落单、表格断页、遮挡和溢出。插入表格或修改表格内容、结构、格式时，必须完成上述视觉验收。未命中上述条件的少量改字、局部加粗且无版面疑点时，完整 XML 验收即可；不单凭文档大小或更新次数触发渲染。
  - 范围覆盖受影响页及相邻页，分页变化向后传播时继续扩大；整篇重写、全局字体/行距/页边距调整，或无法可靠界定影响范围时覆盖全篇。
  - 每项仍先完成 XML 验收，相关批次结束后统一视觉校验；后续编辑依赖中间分页结果时提前检查。视觉问题修正后重验受影响页，不必每改一段就导出。PDF 导出成功、分页元素或 `page` 返回的完整块均不能代替实际视觉检查，PDF 也不能替代结构与格式验收。
- **格式专项校验**：按[局部格式修改与保留约束](#局部格式修改与保留约束)核销允许变化与保留项，逐项核对全部非目标属性；段落重点检查 `align`、缩进、`line-height`、`spacing-before/after` 与 auto 值，文本检查字体槽、`font-size`、`text-color`、底纹和文字效果；有编号时同时检查 `marker-*`。旧读取属性即使不在白名单也保留，不能用本表列举项替代完整比较。新增内容对照写前确定的相邻同类基准；用户明确要求的格式变化按计划验收，不能要求所有属性一概不变。

| 操作类别 | 必须补充的验收证据 |
|---|---|
| Field、题注、Note | 完整 carrier/owner graph；身份、定义、只读缓存及 reference-owner-body 一致。定义未变的缓存保真；定义变化的宿主新结果核对目标和依赖，不能写缓存“修复” |
| Drawing、TextBox、共享页眉页脚 | 完整 owner graph、非目标属性及全部受影响 placements；不得跨 story 复用 ID。保存重开保真属于专项验证，未实际完成只能披露未验证，不能自动关闭用户文件 |
| 表格与布局 | 最新完整表格/layout、坐标、几何、共享关系和非目标格式；跨页表头、分栏或分页要求再读实际 page。表格视觉验收核对数据与表头、行列的对应关系；排版优先遵循用户要求和原稿风格，未规定项参考适用文种规范及 [表格样式](../style/writing-taxonomy.md#表格样式)、[连续显示](../style/writing-taxonomy.md#连续显示)，不据此重设非目标格式 |
| 图表 | 创建后从宿主范围重新 Fetch chart ID，不依赖 `new_blocks`；数据更新用 `chart_data` 回读完整数据和版本，同时核对占位位置、尺寸 |
| TOC、水印 | 领域结果与作用范围，再读相关 layout/正文/page；目录核对标题集合、层级、编号、条目和实际显示页码，不能把命令成功当分页正确 |
| 样式管理 | dry-run 核对 diff/impact、fingerprints 与 plan token；提交后重新读取 runtime 样式。需持久化时等待宿主保存，再以保存重开回读证明 DOCX 已生效 |
| 视觉或导出要求 | 使用 Fetch `pdf` 的实际输出路径核对导出页范围、页数与页面内容；需全页验收时覆盖全部页面。PDF/图片视觉不能替代可编辑结构和动态域证据 |

验证方式必须覆盖用户目标；仅见 XML 属性不能声称已渲染，只有 page 文本不能证明浮动位置或视觉效果。必要视觉/保存验证缺失按 `SKILL.md` 报告失败或待核，不标为通过。
