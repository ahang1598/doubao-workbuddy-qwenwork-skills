# Seed Finance Search 双通道路由

## 线上工具约定（必须按此工具名调用）

宿主 Agent 只暴露以下两个搜索工具，Skill 必须按**确切工具名**自主选用，不得写成 `document_search`、`structured_data`、`general_or_document_search` 等别名：

| 工具 | 用途 | 适用场景 |
|------|------|---------|
| `seed_finance_search` | 专业金融数据库搜索 | 财务数据、财报原文、券商研报、一致预期、公司公告、公开行情/估值、公开融资与机构观点 |
| `general_search` | 通用网页搜索 | 监管/公司原文、新闻事件、行业与经营事实、政府规则、交易对手与客户证据、独立交叉验证 |

两者可组合使用。`seed_finance_search` 不可用、报错或无覆盖时，回退仅用 `general_search`，不降低一手证据要求。库内命中不等于一手披露，关键数字仍应尽量回到监管/公司/政府原文。

## 本 Skill 路由顺序

默认顺序：`general_search` → `seed_finance_search`。
事件原文、法规状态、辖区与生效日先用 `general_search`；市场价格、曲线、成交、一致预期、财务暴露、机构观点与 priced-in 基线再用 `seed_finance_search`。


## 边界

事件原文、事件状态、法规效力、司法辖区和生效日优先使用 `general_search`，并以发布机关、法规原文、交易所或公司公告核验。

`seed_finance_search` 用于：

- 事件前后的市场价格、收益率曲线、成交和资金数据；
- 一致预期与预期修订；
- 公司财务暴露和公开分部线索；
- 机构观点及事件前 `priced-in` 基线。

金融数据库命中不自动等于一手来源。它可以承担市场数据或一致预期的数据库来源角色，但不得替代事件原文、法规状态或公司原始披露。

## 双通道工作流

1. `general_search` 先核验事件身份、版本、状态、辖区、生效日和适用范围。
2. 通过事件门禁后，使用 `seed_finance_search` 获取市场、预期、财务暴露与机构观点。
3. 对公司财务数字和事件决定性事实回到公司披露、交易所/监管文件或发布机关原文核验。
4. 分开记录 `reported`、`estimate` 和派生计算，核对文档日期、报告期与事件时间窗。
5. 建立 claim 级证据台账，保留支持、反对、冲突和缺口，不静默择一。

该流程采用财报专项分析常用的“官方结果/公司披露 + 一致预期/市场数据”双通道，以及市场热点分析的阶段读取、证据台账和来源核验门禁。这里描述的是取数模式，不是可调用的相邻 Skill。

缺少受支持的事件前市场基线时，`can_assess_priced_in=false`。这只降级 priced-in 判断；事件核验、传导机制、财务暴露和监控项仍按证据继续。

## 工具调用与回退

- 工具 schema 未知时，先读取宿主暴露的实际 schema，再按该 schema 调用；不得发明工具名、字段或参数。
- `seed_finance_search` 不可用、无权限、报错或无有效结果时，回退仅用 `general_search` 流程。
- `closed_fixture`、Search=`off` 或用户禁止联网时，不调用任一搜索工具。
- 回退后仍须优先核验官方事件原文；不得以媒体摘要或金融库条目替代。

## 查询与证据台账

每次结果至少记录：

- `tool`
- `query`
- `asof`
- `source`
- `period`
- `unit`
- `currency`
- `reported-vs-estimate`

字段缺失时写 `unknown`，不得猜测补齐。还需记录 claim、来源层级、支持/反对/冲突/缺口状态、是否为事件前基线及下一核验入口。
