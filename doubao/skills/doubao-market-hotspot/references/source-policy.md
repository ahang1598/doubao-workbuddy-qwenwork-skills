# 事件研究的来源、时间坐标与取证纪律

## 双模时间坐标判定

开展检索与阅读材料前，先识别问题属于哪种时间约束，避免两类典型失误：

1. **历史截点或给定材料模式**：当问题指定截止时刻（`as-of`）或限定仅用给定材料时，逐件核对资料的**实际公布日与具体时刻**，不把统计覆盖期或事后复盘文章回顾的日期误判为截点前已知信息。核对相关市场的交易时段与时区，截点时刻尚未收盘的市场不得引用当日收盘值。
2. **开放时点模式**：当问题未设历史截点、直接询问某事件或数据的影响时，先核查事件发生日至当前的后续演进（如草案是否已正式落地、最新数据或财报是否已改写提问隐含的旧前提）。若外部环境已跨入下一阶段或前提已反转，先基于最新事实对齐现状，再判断往后的增量变化。

## 原件全载体取证与归属保真

- **正文、附注与图表同级提取**：阅读公告、研报或政策原件时，正文、附注及文内图表中的数据应同级提取，避免遗漏正文之外的关键条款或定量事实。
- **区分发布日、截至日与多口径**：分别记录报告发布日与底层数据的截至日；多份材料因时点或统计范围不同给出不同数值时，分别保留各自机构、截至日与统计口径，不强行合并。
- **署名与限定条件保真**：核对政策文号、发布机构及研报出处，保留原件中的限定条件与不确定性表述，不在后文归纳中升级为“官方目标”或“既成事实”。
- **跨辖区与不可核验法规**：用户跨辖区提问时分别列出各地规则，不做未经验证的合并结论；专业法规无法核验时列为待咨询事项。
- **查不到与搜到**：数据库查不到不等于事实不存在，新闻搜到也不等于已核实；工具不可用时说明缺口，不用同名主体或相邻事件替代。社区帖、文库转载站与自媒体不作关键数字来源。
- **独立信源甄别**：多篇二手媒体转引同一消息只算单一信源，不构成交叉证实；单一来源支撑的关键数字需标明单源属性。不同语言版本或摘录与原文冲突时，以一手原件为准并点明差异。

## 检索分工与规划工具

只围绕当前会改变判断的事实缺口发起检索，证据足以支撑结论即停止，不追求固定搜索轮数：

- **发布机关与法规原文**：政策状态、适用范围、豁免条款、关联修订文号与生效日，优先查询主管机关公报或官网原文。
- **上市公司与行业研究**：企业公告、定期报告、交易文件及机构深度分析，优先查询交易所公告与正式披露文件。
- **结构化行情与财务基准**：事件前后价格序列、收益率曲线、成交额、一致预期与标准财务科目，使用宿主可用的结构化金融数据工具；数据库字段不替代法规原文对法律效力的界定。

多源复杂任务需要梳理检索模式与信源优先级时，可按需运行 `scripts/search_router.py`（仅依赖 Python 标准库，输入上限为 1 MB UTF-8 JSON，成功退出码 `0`，输入格式或字段非法退出码 `2`）。以下示例从 Skill 根目录运行，输入文件见 [路由示例](schemas/router-input.json)：

```bash
# 示例1：从请求文件推断封闭材料/历史截点模式与信源优先级
python3 scripts/search_router.py references/schemas/router-input.json --pretty

# 示例2：通过内联 JSON 规划开放时点监管事件的检索模式与信源顺序
python3 scripts/search_router.py '{"skill":"doubao-market-hotspot","prompt":"分析近期行业准入征求意见稿对龙头企业的影响"}' --pretty

# 示例3：从标准输入读取已冻结主体的检索信号并输出到指定路径
cat references/schemas/router-input.json | python3 scripts/search_router.py - --output /tmp/search-plan.json --pretty
```
