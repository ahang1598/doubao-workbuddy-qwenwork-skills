# 线上 Agent 执行契约

## 运行档案

对router、evidence validator、event guard、calculator、finalizer分别记录`availability`、`task_execution`、实际调用、退出码和artifact。`--help`/导入不算执行。全部必要门禁在本任务成功才是`full_runtime`，部分为`hybrid_runtime`，未执行为`agent_only`。

无附件direct/brief默认`online_direct_fast_path`，不创建工件、不修脚本Schema。没有发布机关一手文件时，事件保持未确认，必须从用户正文删除相邻规则税率、配额、数量、概率、财务敏感度、股价方向和priced-in结论。

## 工具、阶段与预算

仅调用`general_search`和`seed_finance_search`：

1. General先冻结事件原文、版本、状态、辖区、生效日和适用对象。
2. 上一阶段通过后，Seed获取市场价格、曲线、成交、consensus、公司财务暴露与事件前priced-in基线。

required最多4次、optional最多3次，均为硬上限；保留一次失败Claim修复。一次查询只解决事件身份或一个市场/暴露字段。

4次总预算包含成功、empty、error和fallback；Seed空结果不产生额外General额度。二手研究给出的出口降幅、成本和利润区间只能标`provisional estimate`，并披露输入/公式；缺计算闭环时保留变量，不进入主情景或证伪阈值。

事件身份/状态未通过时停止定量、概率、收益和交易姿态，但保留定性传导与确认清单。缺事件前市场基线只令`can_assess_priced_in=false`，不阻断其他分析。

## Seed信任边界

市场价格、曲线、成交、标准财务暴露和明确标记的consensus字段，若具备provider、对象、field、period/as_of、unit/currency、reported/estimate且无冲突，可标`supported + authoritative_financial_database`。

Seed不是事件原文来源，不能承担法规效力、提案是否通过、辖区、生效日或适用范围。Seed新闻/研报摘要按底层来源判断。

## Claim状态

使用`supported|provisional|conflict|empty|unsupported|blocked`。工具成功不等于证据满足；目标字段为空为empty。多家普通二手重复不会升级supported。

只有发布机关、法规原文、监管/交易所/公司正式公告可支持关键事件身份和状态。提案、草案、传闻、批准和生效不得混用。事件关键Claim全为provisional时不得进入量化情景。

## 口径、推断与计算

比较市场反应前统一对象、时间窗口、时区、币种、单位、基线和reported/estimate。事件后价格不能倒作事件前基线。

最终每个外部数字必须在Claim ledger。派生敏感度、情景和影响区间需calculation id、输入Claim、公式、时间窗和假设来源。阈值和概率必须来自规则、历史、用户设定或透明计算，不得补造。

相关性不等于事件因果；同时期宏观、行业和公司事件作为替代解释。公司暴露、产业传导和市场定价分开。

## 原始轨迹与自检

优先宿主/API原生事件流；模型节选、`note`、`response_source`不是raw，不可用写`raw_trace_unavailable`。

交付前检查：脚本/guard真执行、硬预算、事件原文与状态、Seed边界、transport/evidence、supported/provisional、pre-event baseline、时区/窗口、Claim与计算闭环、阈值来源、轨迹真实性。失败项必须删除或局部降级。

## 输出硬模板执行细则

SKILL 顶部的输出硬模板是本契约在 `agent_only` 与 `hybrid_runtime` 下的替代门禁。逐条自检：

1. **身份核验**：写结论前必须有一次真实检索用于确认主体身份或规则身份；问题短不构成豁免。没有检索时该段结论标 `[待核·模型记忆]` 并降级。
2. **逐条标记**：交付前逐段扫描精确数字，检查是否紧跟 `[一手·…]`、`[库·…]` 或 `[待核·…]`。缺标记时不删数字，先补标记；补不出就标 `[待核·模型记忆]`。整段来源声明不计入。
3. **分档表**：关键输入未知而结论依赖它时，把结论改写为以该未知量为自变量的分档表；不填默认值，也不整题拒答。
4. **假设卡**：无一手来源的量级只能进假设卡，卡头写假设来源与本对象的差异点；摘要段和结论段不复述卡内数字。
5. **可审计摘要**：正文第一节不超过5行，含结论、最强证据及来源等级、最大未知项、证据强度、推翻信号。

自检失败时动作顺序固定：补检索 → 补标记 → 改分档表 → 进假设卡 → 才允许降为 unknown。不得跳过前四步直接删掉整段分析。可交付性以"数字是否可审计"衡量，不以"数字是否被删除"衡量。

## Cycle10 摘要纪律细则

摘要位置在最前，写作顺序在最后。先完成正文与全部来源标记，再补写摘要。

摘要里的数字一律来自摘抄，不来自现写：

1. 第2行"最强证据"从正文中已带 `[一手·…]` 或 `[库·…]` 的句子里原样复制一句，含标记；
2. 其余行引用数字时，同样只能摘抄已标 `[一手·…]`、`[库·…]`、`[用户·…]` 的句子；
3. `[推算·…]` 需正文已写出算式且输入合格，方可连算式一起摘抄；
4. `[待核·…]` 不进摘要；正文有、摘要无是正确结果；
5. 正文无合格句子时，第2行写"当前无一手或库级证据支撑，结论为条件式"，摘要内不出现数字。

自检判据：摘要里每个数字都能在正文中定位到带相同标记的原句；定位不到即为现写，必须删除或替换。

## Cycle11 补充判据

1. 标签词表为六类：`一手`、`库`、`用户`、`推算`、`待核`、`阈值`。判定门槛、观察窗口和证伪触发值标 `[阈值·分析设定]`，必须写明是设定值而非观测值并说明设定理由。
2. 摘要每一行只能来自一次摘抄；复制完即结束该行，不得在同一行后面拼接其他来源或无标记推论。
3. 兜底行是前置判断的结果：写摘要第2行前先检索正文有无 `[一手·…]` 或 `[库·…]` 句子，检索为空直接写兜底行，不得降格用 `[待核·…]` 顶替。
