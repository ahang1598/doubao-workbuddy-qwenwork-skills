# 节点条件型事件、情景构建与观察证伪

## 日期与条件驱动型事件

针对并购重组、监管审批、再融资、司法诉讼、贸易救济、股份解禁或指数调整等具有明确程序节点的事件：

- **拆清程序阶段与前置条件**：区分已完成的程序与尚未满足的生效前置条件（如审批、注册、交割条件或最终文本发布），说明各阶段的法律效力差异。
- **关键焦点**：
  - **并购与资本运作**：核实交易对价、资金来源、审批层级、锁定期、业绩承诺、交割期限及交易终止时的影响。
  - **监管审查与诉讼**：核实管辖范围、裁决时间窗、救济、豁免或过渡安排及可上诉空间。
  - **指数与资金流事件**：核实规则、生效时点、被动资金规模、预计调仓金额相对日均成交额的比例。

## 条件情景构建（Base / Upside / Downside）

仅在事件结果存在明显分岔且需要并列权衡时构建多情景，不为凑齐栏目强设三情景：

- **情景要素清晰互斥**：每条路径写明成立前提、关键时间窗、所需的外部确认，以及路径受阻后的次生影响。
- **量化与概率边界**：缺少可靠基准时，用条件区间或待核变量表达，不虚构概率、时间或损益金额。确有依据赋予概率时，各情景概率之和为 `100%`；各情景期限不同时，不强行加总为单一期间收益率。

## 可观测跟踪信号与证伪条件

选择跟踪指标遵循三条标准：

1. **公开可得且频率匹配**：选用跟踪期内可从公开渠道获取且披露频率与观察窗口匹配的指标，避免使用外部不可观测的内部数据。
2. **门槛与前文口径一致**：设定价格、利差或业务变化门槛时，与前文测算使用同一币种、计量单位与统计口径；涉及跨币种时先换算再比较。
3. **证伪条件指向具体反向证据**：写明观察到哪项具体数据或官方动作即可推翻当前判断，不把情景实现后的常态重复写成证伪条件。
