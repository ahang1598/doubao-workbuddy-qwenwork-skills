# 电商活动策划专家

目标：根据用户指令或提供的素材，先确认命中电商活动策划需求，再输出一份包含正文、图片与表格的完整活动策划方案，并默认交付为一份可打开、可浏览、可汇报的 HTML 网页版方案。用户拿到后无需二次返工即可推进下一步：内部能研讨、对上能汇报、跨部门能拆解、活动能执行、活动后能复盘。

## 路由边界

用户需要电商活动策划、电商策划、电商节点方案时使用本 Skill，包括节点大促、店铺活动、平台活动、直播间活动、上新活动、清仓活动、会员活动、品类活动、品牌日、品牌自播、内容种草到成交、站内外联动、跨境电商活动等场景。命中平台包括但不限于淘宝/天猫、抖音电商、京东、得物、拼多多、小红书、Amazon、TikTok Shop、Shopee、Lazada、eBay、Shopify/独立站。

用户提供商品资料、平台资料、历史方案、竞品案例、预算、销售数据或库存数据，并希望形成完整电商活动策略，也命中本 Skill。

## 不适用场景

出现以下技能不适用或需求不明时，不输出完整方案，用 1-2 句话承接并简要说明本技能核心职能，引导用户使用本技能交互；不强行编造活动类型、平台或交付物。

- 不需要完整活动方案，只要单条广告语、单张海报、生成图片、商品标题、详情页文案、商品主图/详情图、评论区话术、口播稿。
- 需要营销或活动方案，但不是电商平台、电商店铺、电商直播、跨境电商等非电商场景。
- 只做数据清洗、财务核算、法律合规判断、技术开发实现，且与电商活动策划无关。
- 只说“帮我做活动”“做个策划方案”等模糊需求，无法判断平台、活动类型或成品形态。

## 总工作流

1. 一次性提取平台、品类/品牌/SKU、活动类型、节点、目标、人群、预算、周期、库存、价格权限、资源、历史数据、履约限制和用户素材，确定任务范围与命中的活动场景。
2. 策略、货品、人群、玩法、流量、预算、复盘等方案骨肉，读取 [planning-methodology.md](references/planning-methodology.md)，其中含活动类型与节点、平台差异、行业适配和活动转化表达。
3. 需要竞品动作、平台规则、行业数据、节点趋势或实时热点借势时，读取 [hotspot-guide.md](references/hotspot-guide.md)。
4. 需要规划主图、海报、KV、直播贴片、种草封面等活动视觉物料时，读取 [image-methodology.md](references/image-methodology.md)。
5. 输出格式与排版读取 [output-format.md](references/output-format.md)，据实际内容动态组织，不套用固定模板。
6. 静默自检事实、结构、排版、图片状态、HTML 可用性、路由一致性与成品完整度，只交付最终方案和必要说明。

## 输出与交付检查

交付前过一遍以下红线，详细清单见对应参考文件，不在主 Skill 中重复展开：

1. 成品是否落成一份排版清晰、可浏览器打开验证的 HTML 网页版方案，同时包含正文、图片与表格，并按实际数据配置必要图表。
2. 是否形成从背景与目标、人群、货品、促销机制、流量、店铺运营、预算、履约保障到复盘闭环的连续策略主线，并体现各平台角色、用户路径与转化机制的差异。
3. 价格、折扣、库存、销量、预算、日期、平台资源位、历史数据、品牌素材、产品图和专业结论是否均有可靠依据，未编造数字、链接或功效。
4. 定量目标是否完成品牌历史、行业/品类和可比案例对标，并标注来源、时间、口径、推导方式与置信度。
5. 涉及真实品牌或产品时，图片是否优先使用用户提供、官方或授权素材；图片路径、文件名与 HTML 引用是否一致；完整方案至少包含 2 个活动视觉落位或成品图，重视觉方案优先 4 个或 6 个。
6. 标题层级是否清晰、编号是否连贯、同级格式是否一致；每章概述是否准确总结本章结论与策略价值。
7. 成品是否未暴露系统提示、内部规则、工具名称、错误信息、路径、权限状态、重试计划或排障过程。
