# A2A

***使用 tools: `audio_to_audio_plus`***

在自然语言描述里用 `@音频1`/`@音频2`/`@音频3` 指定角色音色参考，生成目标音频。用户输入里的指代形式可能五花八门，调用前先归一化为 `@音频N`。

通用原则（原样保留用户描述、复杂场景单次调用、不篡改不拆分等）见 [`SKILL`](../SKILL.md)，本篇只说明 A2A 的调用、归一化与构造。

## 调用

`audio_to_audio_plus` 必填 `prompt` 和 `audio_reference_url_list`，可选 `duration`：

- `prompt`：用户的音频描述本体，**含归一化后的 `@音频N` 标记**。用户原始输入里的各种参考音频指代（「参考音频 1」「第一个音频」「用麻雀的」等）已归一化为 `@音频N`，其余描述原样保留。
- `audio_reference_url_list`：参考音频 URL 列表，1~3 条。**列表顺序必须与 `prompt` 里 `@音频1`、`@音频2`、`@音频3` 的首次出现顺序一一对应**。
- `duration`（可选，integer，1~120）：生成目标音频的时长，单位秒。**不推荐默认使用**--仅当用户直接说明要生成多少秒的音频时才设置此字段；用户未明确指定时长时不要传 `duration`，交由模型自行决定时长。

## 参考音频指代归一化

用户正文里对参考音频的指代形式五花八门，调用前必须归一化为 `@音频N`。这是 tool 的格式要求，也是 SKILL「非必要不篡改」原则里**唯一允许的必要改写**——除指代词替换为 `@音频N` 外，用户描述其余部分一律不动。

### 归一化规则

1. 按用户描述中各参考音频指代的**首次出现顺序**，从 1 开始编号。
2. 把每个指代词替换为 `@音频N`，替换处不留原文。只替换指代词，前后文原样保留。
3. 按用户指代从该附件信息中匹配对应 URL，填入 `audio_reference_url_list`。
   - 序号型指代（「参考音频 1」「第一个音频」「附件 1」等）按序号直接匹配附件列表对应项。
   - 文件名型指代（「用麻雀的」「用年少有为的」等）按文件名匹配附件列表对应项，再按首次出现顺序编号。
   - 自然语言型指代（「参考这个音频」「用上面的音频」等无序号）按首次出现顺序编号，从附件列表按序匹配 URL。
4. 同一参考音频被多次引用时，保持同一个 `@音频N` 编号，`audio_reference_url_list` 不重复。

### 映射示例

以下均假设用户已上传附件，附件信息出现在描述前。只展示用户正文片段 → 归一化后片段：

| 用户正文片段                           | 归一化后片段                   |
| -------------------------------------- | ------------------------------ |
| `男性(参考音频1): "你好"`              | `男性(@音频1): "你好"`         |
| `男性(第一个音频): "你好"`             | `男性(@音频1): "你好"`         |
| `参考音频1, 男性说到: "你好"`          | `参考@音频1, 男性说到: "你好"` |
| `使用参考音频1的伴奏`                  | `使用@音频1的伴奏`             |
| `用麻雀的伴奏`（文件名含"麻雀"的附件） | `用@音频1的伴奏`               |
| `参考这个音频, 男性: "你好"`           | `参考@音频1, 男性: "你好"`     |

### 多参考音频示例

用户正文 → 归一化：

```text
用户原始：使用参考音频 1 的伴奏，使用参考音频 2 的歌词，帮我生成一段音乐
归一化后：使用 @音频1 的伴奏，使用 @音频2 的歌词，帮我生成一段音乐
audio_reference_url_list: [
  "https://aka.doubaocdn.com/s/pFLvmkqpeL",
  "https://aka.doubaocdn.com/s/0fRe4D8a2D"
]
```

按文件名引用的示例：

```text
用户原始：用麻雀的伴奏，用年少有为的歌词，帮我生成一段音乐
归一化后：用 @音频1 的伴奏，用 @音频2 的歌词，帮我生成一段音乐

  "https://aka.doubaocdn.com/s/pFLvmkqpeL",

```

## tool input 构造示例

单角色参考：

```json
{
  "prompt": "男性 (@音频1): \"你好呀!\"",
  "audio_reference_url_list": ["https://example.com/voice_male.wav"]
}
```

多角色参考（同一 `@音频N` 可多次引用）：

```json
{
  "prompt": "在一个安静的咖啡馆，背景音乐是舒缓悠扬的钢琴。一阵高跟鞋走路的声音，伴随推开门的声音，青年女性 (@音频1) 说到：\"你好，让你久等了\". 紧接着一个青年男性 (@音频2): \"没事，我也没等多久\", 紧接着是咖啡杯在桌面上推动的轻轻的摩擦声，青年男性 (@音频2): \"这是给你点的拿铁，慢点喝，热\"",
  "audio_reference_url_list": [
    "https://example.com/voice_female.wav",
    "https://example.com/voice_male.wav"
  ]
}
```

部分角色用参考、部分用描述：

```json
{
  "prompt": "沉稳的旁白 (中年男性): \"故事要从那个雨夜说起\", 随后一个年轻女性 (@音频1) 接话：\"那天我也在\"",
  "audio_reference_url_list": ["https://example.com/voice_young_female.wav"]
}
```

`duration` 不是音频描述的硬分界符（见 [SKILL](../SKILL.md)）：时长可以是 `prompt` 的一部分，同时从用户意图中提取时长值进 `duration`；只有当用户用明确话术划出描述结束处时，描述才到那里为止。下面用「用户原始输入 -> tool input」展示映射。

用户原始输入：「用 @音频1 的伴奏生成一段优雅的交响乐，时长 30 秒」

```json
{
  "prompt": "用 @音频1 的伴奏生成一段优雅的交响乐，时长 30 秒",
  "audio_reference_url_list": ["https://example.com/accompaniment.wav"],
  "duration": 30
}
```

用户原始输入：「青年女性 (@音频1) 轻声说："今天的阳光真好"。备注：时长 10 秒。」

```json
{
  "prompt": "青年女性 (@音频1) 轻声说：\"今天的阳光真好\"",
  "audio_reference_url_list": ["https://example.com/voice_female.wav"],
  "duration": 10
}
```

后续轮次若用户只调整时长（如「再长一点，至少 20 秒」）而未给新描述，则 `prompt` 与 `audio_reference_url_list` 沿用上一轮、仅更新 `duration`。

## 描述形态示例

以下都是 prompt 的合理形态，构造时**原样使用**：

- 单角色参考：

  ```
  男性 (@音频1): "你好呀！"
  ```

- 多角色参考，同一角色可多次引用同一 `@音频N`：

  ```
  在一个安静的咖啡馆，背景音乐是舒缓悠扬的钢琴。一阵高跟鞋走路的声音，伴随推开门的声音，青年女性 (@音频1) 说到："你好，让你久等了". 紧接着一个青年男性 (@音频2): "没事，我也没等多久", 紧接着是咖啡杯在桌面上推动的轻轻的摩擦声，青年男性 (@音频2): "这是给你点的拿铁，慢点喝，热"
  ```

- 部分角色用参考、部分用描述：

  ```
  沉稳的旁白 (中年男性): "故事要从那个雨夜说起", 随后一个年轻女性 (@音频1) 接话："那天我也在"
  ```

## 顺序对应

`@音频N` 与 `audio_reference_url_list` 下标的对应关系：

| prompt 中首次出现 | audio_reference_url_list 下标 |
| ----------------- | ----------------------------- |
| `@音频1`          | 第 1 个 URL                   |
| `@音频2`          | 第 2 个 URL                   |
| `@音频3`          | 第 3 个 URL                   |

列表最多 3 条。若归一化后出现 `@音频4` 或更多编号，超出 3 条上限，需向用户确认只保留前 3 个参考。

## 不要做

- **不要把 `@音频N` 替换成 URL、文件名、「参考音频」「speaker_a」等任何字样**：归一化后 `@音频N` 原样进 `prompt`。
- **不要调整 `@音频N` 的编号顺序来「对齐」URL 顺序**：应让 URL 顺序去对齐 `@音频N` 的首次出现顺序。
- **不要在 `prompt` 里补充用户没写的参考音频说明**（如「此角色参考 @音频1 的音色」这类额外注释）。
- **不要漏掉归一化**：用户用「参考音频 1」「第一个音频」「用麻雀的」等形式引用参考音频时，必须归一化为 `@音频N` 再调用，不能把原始指代词留在 prompt 里。
- **不要把附件 URL 或文件名写进 prompt**：URL 只进 `audio_reference_url_list`，文件名只用于匹配 URL，二者都不进 `prompt`。
