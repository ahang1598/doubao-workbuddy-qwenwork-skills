# 语义身份方法

本文件用于 provider、factory、adapter、wrapper、delegate、registry/session lookup、type guard、alias、key、ID 或 handle 发生变化时。它是主文档结构审计的展开方法；必须先覆盖 diff 中全部改变的调用，再深入任一字段或候选，不以“对象非空”“测试通过”或“调用最终停止”代替身份比较。

## 1. 来源集合

固定一个消费点，比较：

```text
base 可达来源集合 → head 可达来源集合 → head 新增来源的最弱合法行为 → 消费所需能力
```

来源包括 producer、实现、注册项、路由、分支、返回状态、序列化形态和测试替身。消费语句没有修改，不代表来源集合没有扩大。新增来源能通过最小公开入口到达旧消费点，而消费依赖接口未保证的另一能力时，登记候选。

“完整样例能工作”“相邻实现能工作”“包装类型相同”和“配置通常一起开启”都不能证明所有合法新增来源满足契约。只接受接口、选择条件、支配性检查、拒绝或回退作为保护。

## 2. 动态接收者

对每个改变的接口调用写出，普通直接调用也不能因“看起来明显”省略：

```text
调用表达式 → receiver 的取得位置 → 注册/选择/优先级 → 具体实现 → 下一跳
```

- 从构造函数、provider factory、service registration、session/container lookup 或锁定依赖实现确认 receiver，不从变量名和接口类型猜测。
- 当前类持有同接口 delegate 时，明确比较 lookup 路径与 delegate 路径：返回集合、过滤、缓存层、失效、副作用、错误和资源所有权是否相同。
- lookup 回到当前 wrapper/cache/provider 本身时，继续走一跳，判断是受控重入、重复包装、绕过底层还是错误递归。调用最终返回只证明终止，不证明语义等价。
- 在 receiver 冲突关闭前，不转而用 N+1、重复缓存或对象分配等次要性能候选替代它。

不得用对同一文件中另一个调用的深入分析代替本调用的身份确认。尤其当一个方法同时包含 delegate 调用和 session/container lookup 时，两种写法本身就是必须解释的差异；逐个解析它们，不从最终集合看似合理反推 receiver 正确。

若显式 delegate 或接口职责已经证明该分支应取得底层源数据，而 lookup 确定重新进入包装层，receiver 冲突本身就是具体证据；再追一个直接调用说明消费者影响即可成案。

## 3. 返回角色

对 factory、getter、adapter 和 type guard 写出：

```text
调用方需要的语义角色/能力 → 权威契约或选择条件 → 实际构造/返回对象 → 消费方式
```

- 方法名只能提供线索；接口、选择条件、常量用途和当前消费者证明所需角色。
- 确认实际对象的具体类型、provider、配置和安全属性。相同父类、兼容返回类型和非空 fallback 不证明角色正确。
- 先比较对象身份与能力，再讨论创建、缓存或复用成本。不能把“返回了错误角色”改写成“创建对象略多”。
- 如果所需角色和具体返回对象已经确定不同，这就是静态契约矛盾。运行环境缺失不妨碍报告；按能够证明的消费者影响下界定级。

## 4. 资源身份

对记录、缓存项、文件、订阅、任务、凭据、别名和外部句柄写出：

```text
create/lookup 标识 → read/update 标识 → invalidate/cleanup 标识
```

逐段比较规范化、前缀、作用域、租户、版本、显示名/内部 ID 和包装前后对象。测试 cleanup 同样需要指向实际创建资源。只要两端具体标识确定不同，不需要运行完整环境才能证明清理错误。

## 5. 结果与所有权

对 builder、encoder、转换器、append/update、异步调用和资源操作写出：

```text
产生结果/副作用 → 保存或返回位置 → 最终消费者 → 错误/关闭所有者
```

检查结果是否被丢弃、覆盖、重新构造，异步工作是否被拥有者等待，错误是否能到达有效处理者，资源是否在所有成功和失败出口关闭。diff 新增的确定死结果可以作为 P3 候选，但只报告精确死语句和无用工作，不虚构功能影响；普通可读性、已有死代码和没有规模证据的泛化性能结论应关闭。存在确定的错误结果、重复 I/O、未等待副作用或资源泄漏时继续证明。

## 关闭标准

- `protected`：具体身份满足契约，或差异在消费前被支配性检查、拒绝或回退可靠补偿。
- `candidate`：当前入口产生身份差异，且直接消费者需要另一角色或同一资源。
- `gap`：producer、注册选择或具体类型确实无法从目标仓库、锁定依赖或最小探针确认。

没有崩溃、没有无限递归、测试未失败、对象非空和相邻模式相同都不是身份等价证据。
