# 范围与覆盖

本文件仅在完整 diff 过长、大型新增文件无法一次可靠覆盖或内容受阻时读取。

## 固定比较范围

- 记录平台 base、实际 diff base、head 和目标快照。MR/PR 优先使用平台精确 patch；否则使用目标分支与 head 的 merge-base，不把已经前进的平台 base 直接双点比较成 PR diff。
- 用户明确给出 revision 范围时按其语义执行。本地模式包含已暂存、未暂存和属于本任务的未跟踪文件。
- 第一批一次取得文件列表、统计和完整 diff。revision 变化、diff 截断或无法唯一确定时停止扩展，按实际可读范围输出 `partial` 或 `unable`。

## 分批建图

1. 按模块、依赖方向或完整行为链分批，使定义、实现选择和主要消费点尽量位于同一批。
2. 大型新增文件按 method、函数或顶层声明拆分；不能把“已打开文件”当作内部声明均已审查。
3. 每批按 diff 顺序记录：

```text
文件 | 语义变化单元 | mechanical/normal/high | reviewed/skipped/blocked | 候选或结论
```

4. `high` 用于跨实现、信任、进程、存储、异步或版本边界，或改变权限、持久状态、原子性、生命周期和外部副作用的变化。
5. 一批结束后检查与其他批共享的接口、来源集合、数据表示、状态、配置、错误和资源所有权；跨批关系单独保留，直到两侧都已读取。

`mechanical` 只用于能由源文件、生成规则或一致替换证明没有语义变化的内容。二进制、权威生成物和权限受阻内容可 `skipped/blocked`，但其源配置、交付契约和对消费者的影响仍需检查。lockfile、迁移、CI、权限和部署配置不能因“不像业务代码”自动跳过。

完成条件：每个 changed file、hunk 及大型文件内的 changed declaration 都归入一个变化单元；每个单元有状态；跨批关系已关闭；跳过或受阻项有原因及结论影响。
