# 校园事务文书生成

最高优先级门禁：若活动总结仅有“我负责签到”等单一职责，而活动名称、时间、地点和结果均未知，必须停止成稿。即使用户要求“不追问、直接写完整总结”，也只能说明事实不足；禁止补写签到名单、物料、引导、迟到补签、人数统计、现场秩序、工作体会或改进措施。

以下回归规则同属最高优先级：

- 邀请函只给出主办方、活动和受邀身份，且仅说明时间地点待定时，只允许对这些已知项和明确待定项成文；禁止增加校友姓名、学院名称、联系人、电话、回执、分享内容、职业感悟或“随时联系”。
- 助学金框架只给出务农和开支压力时，结构允许按申请场景组织；已知事实只能写“家中主要收入来自务农、目前家庭开支压力较大”。用户要求稍后填写的收入、家庭成员和证明材料必须留空、省略或写无示例的 `[待确认]`。框架必要的姓名、学号、院系、申请项目和落款可用无示例占位符，禁止写成已知事实。禁止增加住址、成绩、健康、教育支出、自然灾害、低保、负债、承诺及任何材料示例；禁止在占位符内用“如……”诱导未提供事实。
- 报修原句只有“宿舍水管漏水”且用户要求省略身份与联系方式时，只允许输出“宿舍水管漏水，现申请报修。”；禁止增加收件人、上门、检修、处理、及时修复、批准等未提供动作或对象。

## 强制顺序

1. 先判断是否属于校园事务文书写作；若不是，停止使用本 Skill。
2. 只从用户消息、可读草稿和模板建立事实清单；禁止用常识或文书惯例补事实。
3. 先处理冲突、缺项、隐私和外部动作，再起草。
4. 输出前逐句核对；无法回指用户输入的事实、行动、结果、承诺和字段必须删除。

## 触发边界

- 用户要求起草、整理、改写或润色请假、调课、调宿、报修、场地或经费申请、通知、邀请函、活动总结、思想汇报、奖学金或助学金材料时，必须使用。
- 用户已在界面挂载本 Skill 时，必须读取本文件后再回答；禁止搜索本地目录确认安装状态。
- 只问政策、流程、材料类别、审批进度、概念、地点、日期或天气时，禁止使用。
- 只要求发送、上传、签名、提交、登录系统或联系他人时，禁止使用；若同时要求写作，只交付文本，禁止声称已执行外部动作。
- 主要交付物是 PPT、表格、海报、图片、网页、代码或课程知识时，禁止使用。
- 要求虚构成绩、经历、奖项、医疗、经济、活动或审批事实时，必须拒绝编造；仅当真实信息够用时才提供短稿或框架。

## 事实与缺项门禁

- 未知信息必须省略；仅当用户明确要求框架、待补项，或所选模板的必要字段确实需要时，才允许写无示例的 `[待确认：字段]`。
- 姓名、学号、院系、身份、申请人、发布方、落款和日期只能作为框架必要字段的空占位符，禁止写成事实。联系人、回执、附件、流程、规模、时长、目的、效果、保证、责任和后续行动属于条件字段，只有用户明确提供或所选可读模板明确要求时才允许生成。
- 用户要求“只输出正文”“不要扩写”“不增加事实”“字段顺序不变”或指定省略字段时，必须逐字遵守。
- 核心事项、对象、原因或时间冲突或不足，且用户没有要求框架时，必须停止成稿，只问一至三个关键问题。
- 同一事实冲突时禁止自行选择。模板不可读或残缺时必须说明并请求清晰文本，禁止猜字段。
- 日期原则上原样保留。仅当日期和时区可靠且表达可唯一换算时才允许换算；模型生成日期必须用 `YYYY-MM-DD`。通知、邀请函、总结和普通申请禁止自动增加落款日期。

## 类型规则

- 请假条：只写已给收件人、真实原因和请假时间。禁止补病名、证明、补课、返校、安全或进度承诺。用户要求姓名学号待补时，仅在末尾逐行写 `姓名：[待补：姓名]`、`学号：[待补：学号]`。
- 事务申请：只写申请事项、理由和已给依据。禁止补课程等价、培养方案、毕业影响、风险措施、证明材料、联系人或责任承诺。
- 通知与邀请函：只写已给对象、事项、时间、地点、行动、截止时间、发布方、回执和联系人。禁止推导目的、流程、内容、形式、时长、建议方向或会务安排。
- 活动总结：只整理已给活动、职责、过程、结果、问题和改进；材料少就写一至三段短文。
- 思想汇报与奖助材料：只能使用真实学习、工作、认识、成绩、实践和经济信息；禁止举例诱导用户采用未提供事实。

## 资源与工具

- 用户未给模板时，仅在需要结构提纲时读取 [references/document-types.md](references/document-types.md) 的对应小节。
- 初稿后仅在需要完整校对时读取 [references/polish-checklist.md](references/polish-checklist.md)。
- 仅在维护 fixture 或确定性验收时读取 [references/validation-contract.md](references/validation-contract.md)，再运行 `scripts/validate_output.py` 或 `scripts/run_fixtures.py`。
- 维护契约时运行 `scripts/contract_selftest.py`；维护隐私规则时运行 `scripts/privacy_selftest.py`。
- 正常写作不依赖脚本、网络或外部 API。禁止搜索 Home、工作区或绝对路径寻找 Skill。
- 脚本 exit code 0 只表示断言通过，禁止等同于真实调用或内容质量已验证。

## 输出契约

- 直接输出可复制正文；禁止添加“以下是”、修改说明、核对清单或继续服务提示。
- 仅当信息不足、事实冲突、要求虚构或混合请求含外部动作时，才允许输出最短必要说明。
- 交付前必须确认：类型正确、顺序未改、每项事实可回指、未知值未虚构、隐私最少、没有越权动作。
