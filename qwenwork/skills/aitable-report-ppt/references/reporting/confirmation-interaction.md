# 用户确认交互协议

## 目的

让内容边界、内容蓝图、主题选择、下钻降级和发布授权真正进入“等待用户决定”的状态。结构化卡片由宿主产品渲染；Skill 只负责在正确时机调用宿主提供的提问工具并给出合格参数，不自行绘制确认界面。

## 工具选择顺序

1. 若宿主提供原生结构化提问工具，必须使用。例如 `AskUserQuestion`、`request_user_input` 或语义等价工具。
2. 不要为了获得卡片而切换产品模式、调用浏览器脚本或自建 HTML 表单。
3. 若当前宿主没有结构化提问工具，使用一条简短文本消息列出编号选项，并明确“收到选择前不会继续生成正式版”。
4. 若用户已在当前对话明确给出该决定，直接记录决定，不重复提问。

调用原生提问工具后立即停止当前阶段。不得并行启动生成、写入、发布或其他依赖该答案的工作；等待宿主返回用户选择后再继续。

## 当轮答案优先铁律

**当轮结构化确认的答案优先于一切历史记忆、用户画像和既有偏好。**历史偏好只能用来设计选项和推荐位；一旦用户在确认卡上做出选择：

- 未被选中的选项（包括标了"推荐"的）即视为**本次明确拒绝**，不得事后以"按你之前的偏好""既有习惯"等理由复活；
- 不得把用户的单选答案重新解释为"只回答了其中一个维度"，再用记忆补答其余维度——答案覆盖该题的全部语义；
- 交付范围、输出形态等执行参数必须完全由当轮确认记录（`content-approval.json`、`design-selection.json`）表达，确认文件中不得出现确认卡上没有的扩展声明。

## 卡片设计约束

- 一次集中询问 1–3 个真正会改变结果的问题；不要把可从数据或上下文推断的事项交给用户。
- 每题使用不超过 12 个汉字的题头、一个完整问题和 2–3 个互斥选项。
- 把推荐项放第一位，并在标签或说明中标明“推荐”。每个选项用一句话说明影响。
- 默认单选。只有多个选择可以同时成立且会分别进入结果时才用多选。
- 保留宿主提供的“其他/自填”和“跳过”能力；但跳过不等于批准。关键门禁被跳过时只能输出草稿或停留在当前阶段。
- 不在同一题混合两个决策，例如不要把“受众与视觉风格”合成一个问题。
- 不询问抽象审美形容词代替真实预览；主题确认必须发生在三套真实预览生成之后。

## 五类确认关口

### 1. 输入边界确认

仅在受众、用途、交付形态或保密边界无法推断且会改变结果时询问。最多三题，例如：

- `汇报场景`：向上汇报（推荐）/ 团队复盘 / 跨部门或外部分享
- `交付形态`：演示稿（推荐）/ 连续长页 / 两者都要
- `数据边界`：仅当前表（推荐）/ 当前 Base 全部表 / 补充指定资料

### 2. 内容蓝图确认

先按 `content-blueprint.md` 的格式展示第一层（一句话核心观点 + 页面序列编号和标题 + 预计页数），再发起一题。确认时不展示逐页数据明细——用户确认的是故事线，不是数字。

如果宿主支持可视化组件（如 `show_widget`），用编号卡片或流程图展示页面序列，让用户一眼看出整体结构。纯文本宿主用编号列表。

- 题头：`内容确认`
- 问题：`这条故事线和页面安排是否可以进入视觉设计？`
- 选项：
  1. `确认并继续（推荐）`：冻结当前蓝图，进入三套主题预览
  2. `调整故事线或页面`：用户说明需要增删、改序或改重点的部分
  3. `展开看每页详情`：展示第二层逐页内容明细后重新确认

只有第 1 项或用户语义明确等价的批准，才可生成 `content-approval.json`。第 2、3 项处理完成后必须重新确认。

### 3. 主题选择

三套真实预览都已打开并可查看后，再发起一题：

- 题头：`主题选择`
- 问题：`三套真实预览中，正式报告采用哪一套？`
- **选项只能是主题名称**（用户可见名，不要内部 slug），并说明最适用的汇报场景。⛔ 禁止在本题混入交付范围类选项（如“三套都做完整版”）——“选哪套”和“交付几套”是两个决策，混在一题会让单选答案留下歧义空间。

如果历史偏好或用户主动提出多套交付的可能，**单独追加一题**（题头：`交付范围`；选项：`只交付选中主题（推荐）` / `三套都交付完整版`）。只有用户在该题明确选择多套，才允许 `selection_mode: all_versions`；否则一律单套交付。

如果宿主自动提供“其他/自填”，用户可填写“混合 A 与 B”“再换三套”或“三个完整版都做”。只有明确选定后才写入 `design-selection.json`；该文件只允许契约字段，不得自造扩展交付字段（校验器会拒绝）。

### 4. 下钻降级确认

没有真实记录 ID 或原始明细链接，且用户仍希望继续时发起一题：

- 题头：`下钻方式`
- 问题：`当前只能提供本地明细，无法跳转钉钉原始记录，是否接受？`
- 选项：`接受本地明细草稿` / `补齐权限或数据后继续（推荐）` / `取消下钻`

只有用户明确接受降级时，才把 `no_original_record_links` 写入批准记录。

### 5. 外部动作授权

上传、发布、公开分享、写回 AI 表格或修改权限前单独确认，不与内容或主题选择合并。推荐项应是风险更低、可逆的动作。

## 跨宿主行为

| 宿主能力 | Skill 行为 | 用户看到的结果 |
|---|---|---|
| 有原生结构化提问工具 | 传入题头、问题、选项、说明和单选/多选标记，然后停止 | 宿主原生卡片、步骤条或按钮，并等待回复 |
| 只有普通对话 | 输出同样结构的编号选项，然后停止 | 文本选择题 |
| 用户已明确决定 | 不再询问，记录 `approval_source: user_explicit` | 直接进入下一阶段 |

Skill 不能保证不同 Agent 产品呈现完全相同的视觉样式；它能保证优先触发该产品提供的原生确认组件，并保持相同的决策语义和门禁。
