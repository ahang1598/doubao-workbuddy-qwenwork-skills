# 核心框架与内容确认规范

## 目的

AI 表格只有原始数据，不能直接等同于一份已经写好的演示稿。正式设计之前，先把"要讲什么"从"怎么呈现"中分离出来：程序负责验证数据事实，用户集中确认故事主线和页面序列。用户不需要逐页逐句审批，也不承担重新验算数字的责任。

## 适用范围

- AI 表格、CSV、JSON、XLSX 等原始数据生成正式演示稿或管理报告时，默认需要本阶段。
- 已有完整 PPT、经用户确认的逐页文稿或明确要求仅做视觉转换时，可记录 `content_source: user_approved_existing_content` 并跳过重新编写，但仍要保存确认记录。
- 用户明确要求"先出草稿，不用确认"时允许生成带明显草稿状态的内容或页面；不得把它当作正式交付。

## 两层内容蓝图

创建 `content-blueprint.json`，包含完整的两层数据。确认环节只展示第一层；第二层按需查阅。

### 第一层：故事线总览（默认展示，用户确认的唯一对象）

用户确认的是"讲什么、怎么讲"，不是数字对不对。确认时只展示以下内容：

1. **一句话核心观点**：整份报告要传达的核心信息。
2. **页面序列**：只有编号和标题，标注叙事节奏——开场、关键发现、过渡、收尾。
3. **预计页数和交付形态**（演示稿 / 连续长页 / 两者都有）。

**确认时不展示：**每页的管理问题、图表类型、关键数字、数据来源、下钻入口、数据口径、验证方式、空值处理。这些信息保存在蓝图 JSON 中，由程序自动验证，用户只在主动要求时看到。

### 第二层：逐页内容明细（按需查阅，不默认展示）

完整数据保存在 `content-blueprint.json` 的每个 page 对象中，至少包含：

- 页码、标题和本页回答的管理问题；
- 核心信息与准备展示的文字要点；
- 图表类型、图表标题、指标引用和关键数字摘要；
- 数据来源、筛选条件、口径或证据引用；
- 下钻入口及其能力等级；
- 可选的演讲备注。

用户说"展开看看""看具体内容""每页讲什么"时再呈现第二层。第二层供用户参考和调整，但确认范围仍然是第一层的故事线。

## 确认输出格式

### 可视化宿主（推荐）

如果宿主支持可视化组件（如 `show_widget`、`AskUserQuestion` 的富文本），用以下格式展示第一层：

- 顶部：一句话核心观点，加粗或高亮。
- 中部：页面序列用编号卡片或水平流程图呈现，每张卡片只含编号和标题，用颜色或标签区分叙事节奏（开场 / 关键发现 / 收尾）。
- 底部：预计页数和交付形态。

卡片不展示图表类型、数据来源或任何第二层信息。

### 纯文本宿主（降级）

```
核心观点：[一句话]

页面序列：
  1. [标题]  ← 开场
  2. [标题]
  3. [标题]  ← 关键发现
  ...
  N. [标题]  ← 收尾

预计 N 页 · 交付形态：演示稿
```

## 内容确认门禁

呈现第一层后，按 `confirmation-interaction.md` 使用宿主原生结构化提问工具发起"内容确认"，并立即停止等待。普通回复文字不自动构成批准；只有用户明确选择"确认并继续"或表达语义等价的批准，才创建确认文件。

确认后保存 `content-approval.json`：

```json
{
  "status": "approved",
  "approved_at": "2026-08-18T16:00:00+08:00",
  "approval_source": "user_explicit",
  "blueprint_path": "content-blueprint.json",
  "blueprint_sha256": "...",
  "approved_scope": ["story_line", "page_sequence", "delivery_format"],
  "approved_degradations": [],
  "requested_changes": []
}
```

规则：

- `blueprint_sha256` 必须对应用户实际看到的版本；确认后修改蓝图会使确认自动失效。
- `approved_scope` 是整体范围，不建立逐页审批状态。
- 数字、排序、分组成员和图表总数由程序独立验证；用户确认的是业务叙事和页面序列。
- 若数据读取降级导致无法打开钉钉原始记录，必须在蓝图中写明，并在 `approved_degradations` 记录 `no_original_record_links`。
- 没有有效内容确认时，只能生成标为 `draft` 的预览或内容稿，不能生成正式报告。

## 推荐状态机

```text
DATA_READY
→ CONTENT_DRAFTED
→ CONTENT_APPROVED
→ STYLE_PREVIEWS_READY
→ STYLE_APPROVED
→ FINAL_GENERATED
→ VERIFIED
```

任何后续阶段使用的内容或主题发生变化，都要回到对应确认阶段，而不是沿用旧确认文件。
