# 证据、指标与结论规范

## 为什么先做证据台账

可视化页面会放大结论的可信感。如果指标或解释本身没有依据，视觉越专业，误导风险越高。因此先确定“这句话凭什么出现”，再决定放在哪张图里。

## 四类内容

| 类型 | 定义 | 默认能否进入正式报告 |
|---|---|---|
| `data_fact` | 记录直接支持的计数、求和、均值、分布 | 可以 |
| `rule_calculation` | 用户提供公式、阈值、权重或分档规则得到的结果 | 可以，必须显示口径 |
| `human_conclusion` | 人工报告、负责人确认或正式文件中的判断 | 可以，必须保留来源 |
| `ai_inference` | AI 对原因、趋势意义、人才标签等的解释 | 默认不可以，需证据和确认 |

## 指标定义最小字段

每个指标至少写明：

```json
{
  "id": "metric_total_people",
  "label": "参评人数",
  "kind": "data_fact",
  "source_id": "people",
  "fields": ["employee_id"],
  "aggregation": "count_distinct",
  "filters": [],
  "null_policy": "exclude_null",
  "formula": "COUNT_DISTINCT(employee_id)",
  "expected_value": 104,
  "tolerance": 0,
  "verification": "recompute_from_snapshot"
}
```

## 计算规则

- 计数、求和、分组人数默认精确一致。
- 百分比必须写清分子、分母和是否排除空值；展示舍入与计算精度分离。
- 均值必须说明按记录、按人、按批次还是按月份平均。
- 同比要求相同自然周期；环比要求相邻周期。
- 排名必须说明排序键、并列规则和 N 大于类别数时的处理。
- 交叉表必须保留业务要求的零值格子。
- 跨表指标必须写复合键或稳定键，记录未匹配数量。
- 缺失目标、缺失评分或未解决记录不得被均值、相邻月份或模型估计静默补齐。

## 结论定义

每条文字结论使用：

```json
{
  "id": "finding_writing_lowest",
  "text": "文字能力是本次评价得分最低的维度",
  "kind": "data_fact",
  "evidence": ["chart_dimension_scores", "metric_writing_score"],
  "scope": "本次104名参评人员",
  "caveat": "仅表示本次评价结果，不代表长期绩效",
  "human_approved": false
}
```

如果结论包含“导致、说明、反映、潜力、应该晋升、能力不足的原因”等解释性语义，默认归为 `ai_inference`，除非人工文件已明确提出并提供上下文。

## 禁止推断清单

项目可以配置自己的禁用项。通用默认包括：

- 从职位名称推断组织职级或上下级关系；
- 从一次考试直接推断长期能力；
- 从相关性推断因果；
- 从缺失值推断零值；
- 根据相邻月份、全体均值或常识补造目标；
- 将模型生成的人才标签当作正式分档；
- 把模拟数据、反推数据或脱敏示例当作业务事实。

## 验证设计

在报告规格阶段为每项内容指定一种验证：

1. `recompute_from_snapshot`：脚本从数据快照重算。
2. `compare_with_business_rule`：与正式规则或公式逐项比对。
3. `trace_to_source_record`：点击可定位原始记录。
4. `trace_to_human_document`：定位人工报告段落或正式文件。
5. `manual_review`：无法机器判定的文字、视觉或实际页面效果由人工检查。

正式报告中不能出现 `verification` 为空的指标或结论。
