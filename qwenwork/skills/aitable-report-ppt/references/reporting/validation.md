# 可视化报告验收规范

## 验收顺序

先验证数据，再验证交互，最后验证视觉和交付。页面运行正常不代表数字正确，数字正确也不代表隐私安全。

正式生成前先执行内容与主题门禁：

```bash
python3 scripts/validate_content_blueprint.py content-blueprint.json --approval content-approval.json
python3 scripts/validate_generation_gate.py \
  --spec report-spec.json \
  --blueprint content-blueprint.json \
  --content-approval content-approval.json \
  --design-selection design-selection.json \
  --manifest snapshot/manifest.json
```

任一门禁失败时只能保留草稿或预览，不能交付正式版本。

## 0. 主题预览

主题预览只回答“用户更希望采用哪种视觉语言”，不承担正式报告验收：

- 三套预览分别是可直接打开的单页、固定 1920×1080 HTML；
- 可使用不同 DOM、版式、字体、图形语言、背景和动效，不要求共用视觉组件；
- 使用同一份已确认的核心内容和少量真实聚合数字，避免比较对象不一致；
- 不读取或嵌入行级明细，不生成下钻、记录列表、iframe、明细按钮或“点击查看”提示；
- 不出现看似可操作但实际无功能的按钮、筛选器或弹窗；
- 预览验收只检查页面可打开、比例正确、无溢出和三套视觉确有区分。

执行：

```bash
node scripts/validate_visual_report.js <preview.html> --preview
```

用户选定主题后，再读取完整主题规范并设计正式报告的信息架构、图表和下钻。

## 1. 数据与口径

**API 优先验收（runtime 报告的标准路径）**：

```bash
python3 scripts/build_verification_oracle.py --snapshot-dir snapshot/ --spec report-spec.json --output verification-oracle.json
node scripts/validate_visual_report.js report.html report-spec.json --oracle verification-oracle.json
```

- oracle 由页面外的 Python 实现从冻结快照独立计算（第二把尺子，与页面内 runtime 不共享代码，共同语义见 `semantics.md`）；
- 验收先逐项核对页面 `fingerprints` 与 oracle 的快照哈希、规格哈希、语义与合同版本，**任何一项不一致即 `FINGERPRINT_MISMATCH` 硬失败**——数据或口径变了必须重建 oracle，不允许拿旧尺子量新页面；
- 指纹一致后，比较 oracle 期望值与页面 `verificationSnapshot()` 观察值：指标（按容差）、图表 categories/values、下钻成员数量与成员摘要；
- 页面接口只报告观察值；判定只发生在验收脚本。未内嵌 runtime 的存量报告自动回退为下述 DOM 检查。

**人工与项目级核对**：

- 从冻结快照独立重算全部关键指标；
- 计数、求和、排名成员精确一致；
- 百分比按规格容差核对；
- 核对空值、零值、未分类和重复主键；
- 跨表指标核对匹配率与未匹配记录；
- 图表分组之和与总数一致，除非规格明确允许重叠；
- 页面不得出现规格中不存在的标签、数字或结论。

## 2. 证据抽查

至少随机抽查五项：

1. 页面显示值；
2. `report-spec.json` 中的指标或结论；
3. 数据快照字段或人工文档段落；
4. 计算公式和筛选；
5. 原始记录链接。

任何一项无法闭环都不能标为通过。

## 3. 下钻

每类交互至少测一个代表案例，同时每个 `mode != aggregate_only` 的下钻触发点都要有浏览器自动化或人工验收记录。**drills 用例支持 `slide` 字段（0 起的页索引）**：验证器先翻到该页再点击触发点，因此触发点应放在其真实归属的页面上，禁止为了"验证器只点活动页"而把所有触发点堆到末页抽查条——图表下钻必须在图表本身可点（trigger `type: chart` + 可选 `category`），页外 chip 只能作为补充验收辅助：

- KPI 卡 → 全部记录；
- 柱/饼图类别 → 对应记录；
- 排名或表格行 → 单条详情；
- 单条详情 → 钉钉原始记录；
- 搜索后的结果数量；
- 零记录和无权限状态。

自动断言图表数量、筛选后快照数量和弹窗行数相等。

- 不要求所有主题共用同一视觉模板，但必须共享同一成员筛选、层级、返回、关闭和降级语义；根节点位于固定演示舞台之外；
- `full` 模式真实 ID 与链接覆盖率必须均为 100%；
- `local_only` 必须有用户批准的 `no_original_record_links` 降级记录；
- 禁止模拟 `recordId`、伪造钉钉页面或把 Base 首页当作行级链接；
- 阅读和演示同时启用时必须使用同一记录集合；视觉容器可以分别适配。
- 单条详情顶部只保留返回、记录标题和关闭；正常嵌入时不显示重复来源按钮、记录数量说明或额外工具条。
- iframe 跨域内容无法自动读取时，验收状态必须记为 `manual_required`，不能自动写成通过；人工只需确认是否打开了对应原始记录、返回和关闭是否正常。

## 4. 连续阅读模式（仅在用户明确要求时）

- 所有章节可访问；
- 目录状态与当前章节一致；
- 章节切换后图表正确 resize；
- 无隐藏演示层拦截阅读模式点击；
- 页面不重复标题或导航标签；
- 长文本、表格和图例不被裁切。

未启用连续阅读模式时跳过本节，不把 `reading-first` 内容密度误判为阅读模式。

## 5. 演示模式

- 固定 1920×1080 舞台，按比例整体缩放；
- 桌面和手机均保持 16:9，不重排内部内容；
- 每页只有一个活动 slide；
- 无溢出与遮挡；正文可读性按第 5.1 节的实显字号硬门槛判定，不再用"舒适阅读尺寸"这类无数字的措辞；
- 方向键、空格、滚轮、触屏和退出有效；
- 减少动态效果设置有效；
- 演示图表可以使用统一下钻组件；如果同时启用连续阅读，两者数据和下钻成员必须一致。

## 5.1 可读性与密度硬门禁

由 `validate_visual_report.js` 自动判定，失败即不通过。

**为什么需要这一节**：此前验收只检查溢出。这是单向记分——"装不下"是硬失败，"没装满"零代价。在这套规则下，把字号和图表调小是通过验收最省力的路径，于是生成出既不饱满、也读不清的报告。这些门槛把"太小"和"太空"变成和溢出同等的失败。

### 验收视口

桌面验收固定 **1280×720**（`frontend-slides-engine.md` 第 81 行的规定尺寸）。所有字号门槛都是**在该视口下的实显值**：

```
实显字号 = 1920 画布上书写的字号 × 舞台缩放比
```

1280 窗口的缩放比是 0.667，即画布上 12px 只有 8px 实显。**门禁看实显值，不看 CSS 声明值。** 改视口就等于改了"可读"的定义。

字号门槛只在桌面执行。手机上固定舞台按设计就会缩小，在那里套用同一套门槛会让所有合规演示稿失败。

### 字号下限（实显 px）

| 文字角色 | 实显下限 | 1920 画布对应值 |
|---|---:|---:|
| 正文、结论、注释段落 | 16 | 24 |
| 表格正文 | 14 | 21 |
| 坐标轴刻度、图例、数据标签 | 14 | 21 |
| 页脚、页码等非关键 chrome | 12 | 18 |

这是**下限不是目标**。正文建议实显 17–19px，16px 只负责阻止退化。

**角色如何判定**：`<table>` 内为表格，`<footer>` 内为 chrome，**其余一律按正文判定**。类名不作为依据——本模板包里 kicker 有 `.ck`、`.kicker`、`.overline` 三种写法，且其字距区间（0.14–0.34em）与 KPI 标签完全重叠，无论按名称还是按排版属性都无法区分"设计上就该小"和"为了塞下而缩小"。

刻意小的文字必须用 `data-text-role="chrome"` 显式声明，与下钻门禁的 `drilldown_required:false` + `drilldown_opt_out_reason` 是同一种约定：**豁免要申报，不能靠猜**。

### 图表内文字

图表文字画在 canvas 里，DOM 查不到，因此从 ECharts `getOption()` 读取坐标轴与标签字号。runtime 默认按 1920 画布 21px 供给，主题可用 `--chart-axis-font-size` 等 CSS 变量调整。**不设置就会得到 runtime 默认值**；若绕过 runtime 自行 `setOption` 且未配字号，会掉进 ECharts 的 12px 默认值，实显仅 8px，必然失败。

### 密度门槛（仅 `reading-first`）

页面角色由规格的 `sections[].slide_role` 声明，**不从 CSS 类名猜测**。`cover`、`section`、`chapter`、`statement`、`closing` 为稀疏角色，豁免密度门槛但仍受字号门槛约束。

| 指标 | 门槛 | 说明 |
|---|---|---|
| 单页内容覆盖率 | ≥ 25% | 任一非稀疏页 |
| 非稀疏页平均覆盖率 | ≥ 35% | |
| 最大连续空白带 | ≤ 画布高度 35% | 约 378px |
| 主图高度（两栏） | ≥ 360px | 1920 画布尺寸 |
| 主图高度（单栏/全宽） | ≥ 420px | 1920 画布尺寸 |
| 稀疏页占比 | ≤ 25% | 防止把每页都标成 `statement` 逃避门禁 |

覆盖率按 48×27 网格统计有内容的格子。计入可见文本、图表、表格、图片和数据卡；排除 `data-visual-role="decorative"`、`chrome` 和 `<footer>`。

未声明 `slide_role` 时只把第 1 页当稀疏页，并给出警告——这会让金句页、章节页被按分析页判定，应当补齐声明而不是调低门槛。

### 主图高度为什么单列一条

覆盖率能被一张巨大的空白卡片骗过：卡片本身占满网格，里面却是空的。主图最小高度直接约束**图表实体**，是拦住"面板撑满、图表却只有 250px"这种退化的那一条。

## 6. 打印与 PDF

- 演示稿 PDF 默认逐张捕获固定 16:9 幻灯片，每页一张，不重新排版为 A4 阅读报告；
- 交互按钮、弹窗遮罩和演示控制不得进入 PDF；
- 图表以动画结束后的可读静态状态出现；
- 只有用户明确要求 A4 阅读报告时，才检查 A4 分页、页眉页脚和连续阅读打印样式。

## 7. 手机端

- 连续阅读模式启用时，字体、点击目标和章节导航可用；
- 弹窗在窄屏可滚动；
- 演示舞台在屏幕中完整显示；
- 页面不能产生不可控横向滚动。

## 8. 隐私与发布

- 扫描禁用字段和值；
- 外发版不含真实行级 URL；
- 页面源码不含被标记为“不可离表”的字段；
- 标明快照时间、版本和保密等级；
- 发布前检查链接权限；
- 不把登录页、403 或 iframe 失败误判成数据不存在。

## 浏览器验证脚本

执行：

```bash
node scripts/validate_visual_report.js <report.html> [report-spec.json] [--oracle verification-oracle.json]
node scripts/validate_visual_report.js <preview.html> --preview
```

脚本负责结构、运行错误、固定舞台、桌面/手机溢出、基础图表初始化和规格中声明的下钻动作；提供 `--oracle` 时额外执行指纹核对与期望值/观察值独立比对（见第 1 节）。预览模式会额外禁止下钻、iframe 和伪交互。隐私以及跨域 iframe 内部页面仍需根据 `report-spec.json` 增加项目断言或人工确认。

## 验收输出

生成 `verification.json` 或 `verification.md`，包括：

- 数据：通过项、失败项、证据；
- 交互：测试动作与结果；
- 视觉：视口与截图；
- 打印：页数和异常；
- 隐私：扫描结果；
- 未自动验证、需要人工确认的事项。

没有通过的项目不得写“已全部完成”。
