# 话题趋势报告

根据用户指定的**主题**和**时间范围**，自动检索权威动态，生成按类别聚类的钉钉在线文档动态报告。每条新闻包含标题简介、详情描述和索引链接，确保时间精准、来源权威、内容去重。

---

## 禁止事项

- 禁止以对话文本替代钉钉在线文档作为最终交付物
- 禁止纳入发布时间无法确认的资讯（无法核实时间的条目直接剔除）
- 禁止将不同来源的同一事件重复计入报告
- 禁止使用非权威来源（个人博客、论坛帖子、未标注日期的页面）作为主条目
- 禁止编造新闻标题、链接或发布时间

---

## 强制要求

- 本技能触发即代表用户期望生成钉钉在线文档，无需询问
- 草稿文件路径必须动态化：`/home/workspace/draft_topic-trend_{主题}_{YYYYMMDD_HHMMSS}.md`
- 每条资讯必须包含：标题、简介、详情描述、原文链接、发布时间
- 时间核验：所有资讯必须通过时间核验，超出时间窗口的条目剔除
- 最终报告必须包含附录：信息来源统计 + 时间核验结果

## Phase 1 — 参数解析

**目标**：明确主题范围和时间边界，确定分类框架。

### 主题解析

从用户输入中提取：
- **核心关键词**：主题的中英文表达（如「AI大模型」「LLM」「Large Language Model」）
- **扩展关键词**：相关子话题（如「AI大模型」→「GPT」「Claude」「Gemini」「国产大模型」）
- **排除词**：明确不在范围内的子话题

### 时间范围转换

| 用户输入 | 转换结果 |
|---------|---------|
| 「最近一周」 | 当前日期 - 7天 至 当前日期 |
| 「本月」 | 当月1日 至 当前日期 |
| 「2024年Q3」 | 2024-07-01 至 2024-09-30 |
| 「最近3天」 | 当前日期 - 3天 至 当前日期 |

> ⚠️ 若时间范围模糊，向用户确认具体日期后再继续。

### 分类框架确认

根据主题自动推断分类框架，示例：
- **AI大模型**：模型发布 / 技术突破 / 产品更新 / 政策监管 / 资本动向 / 安全风险
- **新能源汽车**：新品发布 / 销量数据 / 技术进展 / 政策补贴 / 竞争动态
- **互联网行业**：产品动态 / 财报数据 / 人事变动 / 政策合规 / 出海进展

## Phase 2 — 多源检索

> 每轮搜索后立即将整理结果写入草稿文件，避免数据丢失。

### 搜索策略

**第一轮：权威来源优先**
```
WebSearch("{主题} 最新动态 site:reuters.com OR site:bloomberg.com OR site:36kr.com {时间词}")
WebSearch("{主题} {当前年} 官方公告 新闻")
```

**第二轮：多关键词覆盖**
```
WebSearch("{核心关键词1} 进展 {时间词}")
WebSearch("{核心关键词2} 发布 更新 {时间词}")
WebSearch("{主题} {子话题1} 最新")
WebSearch("{主题} {子话题2} 动态")
```

**第三轮：英文来源补充**
```
WebSearch("{英文关键词} latest news {时间词}")
WebSearch("{英文关键词} announcement update {当前年}")
```

**第四轮：深度阅读**

对搜索结果中标题高度相关、来源权威的条目，使用 `WebFetch` 获取全文：
```
WebFetch("{重要页面URL}")
# 提取：精确发布时间、完整标题、核心内容摘要（100字以内）
```

### 权威来源优先级

| 优先级 | 来源类型 | 示例 |
|--------|---------|------|
| P0 | 官方发布（官网、官方公众号、官方博客） | openai.com/blog, 官方微信公众号 |
| P1 | 主流财经/科技媒体 | 36氪、虎嗅、路透社、彭博社、TechCrunch |
| P2 | 行业分析机构 | IDC、Gartner、中国信通院 |
| P3 | 综合新闻媒体 | 新浪、腾讯新闻、The Verge |
| P4 | 社区/论坛（仅作参考，不作主条目） | 知乎、Reddit |

```markdown
### 批次 2（第二轮搜索）
...

### 深度阅读结果

|------|------|---------|-------------|-----|

```

## Phase 3 — 时间核验与去重

> 时间核验是本技能的核心质量保障，不得跳过。

### 时间核验流程

```
for 每条候选资讯:
    if 发布时间 == 无法确认:
        → 剔除，计入"时间无法核实"计数
    elif 发布时间 NOT IN [时间窗口起始, 时间窗口结束]:
        → 剔除，计入"超出时间范围"计数
    else:
        → 保留，记录精确发布时间
```

### 去重规则

- **同一事件判断标准**：主语（发布方/事件主体）+ 核心动作相同
- **去重处理**：保留信息最完整、来源最权威的条目作为主条目；其他来源作为「参考来源」附在主条目下
- **保留原则**：若不同来源对同一事件有不同侧重，保留最权威来源，差异部分在详情中说明

### 核验统计写入草稿

```markdown
## 时间核验统计

- 候选资讯总数：N 条
- 时间核验通过：M 条
- 剔除原因：
  - 时间无法确认：X 条
  - 超出时间范围：Y 条
  - 重复/合并：Z 条
- 最终纳入报告：M-Z 条
```

## Phase 4 — 分类聚合

> 将通过核验的资讯按分类框架归类，每类内部按时间倒序排列。

### 聚合格式

每条资讯的标准格式：

```markdown
#### {序号}. {标题}
- **简介（intro）**：一句话概括事件核心（30字以内）
- **详情（description）**：事件背景、关键数据、影响分析（100-200字）
- **来源**：[{来源名称}]({原文链接}) | {精确发布时间}
```

### 核心要点提炼

基于全部资讯，提炼 3-5 条本期最重要的趋势信号：

```markdown
## 核心要点

> 💡 本期 {时间范围} 最值得关注的 {N} 个信号：

1. **{信号标题}**：{一句话说明}（详见{分类}·第{N}条）
2. **{信号标题}**：{一句话说明}
...
```

## 易混淆场景

| 场景 | 本技能行为 | 注意 |
|------|----------|------|
| 主题过于宽泛（如「互联网」） | 建议缩小范围或指定子领域 | 不要直接检索，先与用户对齐 |
| 某时间段无内容 | 如实告知，建议扩大时间范围 | 不得编造或用旧内容填充 |
| 信息源受限（境外媒体无法访问） | 说明限制，使用替代源，附录中注明 | 不得假装成功获取 |
| 内容过多（>50条） | 按重要性筛选，保留 Top N，权威源优先 | 说明筛选标准 |
| 同一事件多来源冲突 | 保留权威来源为主条目，差异在详情中说明 | 不得自行判断哪个来源「更准确」 |

---

## 错误处理

| 错误情况 | 处理方式 |
|---------|---------|
| 时间范围模糊 | 向用户确认具体日期，转换为精确时间窗口 |
| WebSearch 无相关结果 | 尝试扩大关键词范围或时间窗口 |
| WebFetch 获取失败 | 标注「原文无法访问」，基于搜索摘要处理 |
| dws doc create 失败 | 将完整 Markdown 输出到对话，提示用户手动创建 |
