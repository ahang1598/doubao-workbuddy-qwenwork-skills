# 完整工作流步骤与命令示例

## Module A — 确认消息来源

**目标**: 确定用户要从哪个群聊或单聊中提取任务。

### A1 确认目标会话

如果用户已明确指定群聊名称或单聊对象，直接进入 A2。

如果用户未指定具体会话，**第一步必须立即执行搜索命令和获取当前用户信息**（不要先用文字追问）：

```bash
dws chat search --query " " --format json
dws contact user get-self --format json
```

第一条命令返回用户最近的会话列表，第二条命令返回当前用户的 `userId`（后续排序和创建待办都需要）。

拿到搜索结果后，**直接进入 A3 对会话列表进行智能排序（默认搜索最近 3 天内的会话消息），排序完成后展示给用户选择，不需要询问用户确认时间范围**。

**重要**：禁止在未执行搜索命令的情况下仅用文字询问用户"你想从哪个群聊提取？"。必须先执行搜索、拿到真实的会话列表后再展示给用户。

### A2 搜索会话获取 ID

**群聊场景**:
```bash
dws chat search --query "<群名关键词>" --format json
```
从返回结果中提取 `openconversation_id`。

如果搜索结果有多个匹配，进入 A3 进行智能排序后再让用户选择。

**单聊场景**:
```bash
dws contact user search --query "<用户名>" --format json
```
从返回结果中提取目标用户的 `userId`。

### A3 会话智能排序

当搜索结果返回多个会话时，对**所有**会话拉取最近消息进行相关度分析和排序，确保打分准确、不遗漏高相关度会话。只展示与用户相关的会话（总分 ≥ 5 分），过滤掉无关会话。

**步骤**：

1. 确保已获取当前用户 `userId` 和 `name`（A1 中已执行 `dws contact user get-self`）

2. 对搜索结果中的**每个**会话，拉取最近 3 天的全部消息：

**群聊**：
```bash
dws chat message list --group <openconversation_id> --time "2026-03-21 00:00:00" --format json
```

**单聊**：
```bash
dws chat message list-direct --user <userId> --time "2026-03-21 00:00:00" --format json
```

注意：排序阶段使用当前时间减去 **3 天**的绝对时间（格式为 `yyyy-MM-dd HH:mm:ss`）。**不要加 `--limit` 限制**，必须拉取完整 3 天的消息才能准确打分。当返回结果 `hasMore=true` 时，必须用最后一条消息的 `createTime` 作为下次 `--time` 继续翻页拉取，直到 `hasMore=false`，确保 3 天内的消息全部覆盖。

3. 对每个会话的消息进行以下维度的统计和打分：

**群聊打分规则**：

| 维度 | 统计方式 | 得分规则 |
|------|---------|---------|
| @我的消息数 | 按 [task-recognition-rules.md](./task-recognition-rules.md) 中的匹配策略统计 @当前用户 的消息条数 | 每条 +10 分 |
| 我的活跃度 | 统计当前用户（按 userId 匹配消息发送者）发送的消息条数 | 每条 +3 分 |
| 关注人消息 | 如果用户提到了特定人名，统计该人发送的消息条数 | 每条 +5 分 |
| 最近消息时间 | 最新一条消息距当前时间的小时数 | 24h 内 +5 分，24-48h +2 分，48h 以上 +0 分 |

**单聊打分规则**（单聊没有 @我 的概念，侧重活跃度和关注人）：

| 维度 | 统计方式 | 得分规则 |
|------|---------|---------|
| 我的活跃度 | 统计当前用户发送的消息条数 | 每条 +5 分（单聊权重更高） |
| 对方活跃度 | 统计对方发送的消息条数 | 每条 +3 分 |
| 关注人匹配 | 如果对方是用户提到的关注人 | 匹配 +20 分 |
| 最近消息时间 | 最新一条消息距当前时间的小时数 | 24h 内 +5 分，24-48h +2 分，48h 以上 +0 分 |

4. **过滤低相关度会话**：总分 < 10 分的会话不展示在推荐列表中。10 分意味着至少满足以下条件之一：有 1 条 @我消息（+10）、我发了 3+ 条消息且 24h 内有新消息（9+5=14）、有关注人消息 2+ 条（10+）。如果过滤后没有任何会话剩余，则展示所有会话并提示用户"未发现高相关度会话，以下是最近的会话列表"。

5. 对过滤后的会话按总分从高到低排序，分数相同时群聊优先于单聊。

6. 排序后向用户展示推荐列表（**只展示总分 ≥ 10 分的会话**）：

```
请问要从哪个会话中提取任务？以下是与你相关度较高的会话：

群聊：
1. 🔴 项目冲刺群 [3条@我, 活跃]
2. 🟡 技术讨论群 [1条@我]

单聊：
3. 🟡 与张三的单聊 [活跃]

标签说明：🔴 高相关(≥20分)  🟡 中相关(≥10分)  无标签=有一定相关(≥5分)
你也可以直接告诉我群名关键词或单聊对象的名字。
```

如果过滤后无会话剩余：
```
最近 3 天内未发现与你高相关度的会话。以下是你最近的会话列表，请选择：
1. 项目冲刺群
2. 技术讨论群
3. 与张三的单聊

你也可以直接告诉我群名关键词或单聊对象的名字。
```

**标签规则**：
- 🔴：总分 ≥ 30 分（高相关，如有 3 条 @我消息，或 @我+活跃）
- 🟡：总分 ≥ 20 分（中高相关，如有 2 条 @我消息，或 1 条 @我+活跃）
- 无标签：总分 ≥ 10 分的其余会话（有一定相关度）
- **不展示**：总分 < 10 分的会话（过滤掉，相关度不足）

用户选择后进入 A2 获取对应 ID（如果 A1 搜索结果中已包含 ID 则直接使用）。

### A4 获取当前用户信息

如果 A1 中未执行过 `dws contact user get-self`（例如用户直接指定了群名跳过了 A1），则在此步骤获取：

```bash
dws contact user get-self --format json
```
提取当前用户的 `userId`，用于：
- 会话排序中统计 @我 和活跃度
- 过滤 @我 的消息
- 作为待办的 executors 参数

## Module B — 获取并分析消息

**目标**: 拉取目标会话的消息并识别任务类内容。

### B1 拉取消息

拉取消息前，如果用户未在对话中明确指定时间范围，应主动询问用户：

```
默认拉取最近 3 天的消息进行任务识别，你也可以指定其他时间范围（如"最近一周"、"3月15日到今天"）。请问使用默认的 3 天吗？
```

用户确认或指定时间后，计算出绝对时间执行拉取。

**群聊消息**:
```bash
dws chat message list --group <openconversation_id> --time "2026-03-21 00:00:00" --format json
```

**单聊消息**:
```bash
dws chat message list-direct --user <userId> --time "2026-03-21 00:00:00" --format json
```

**`--time` 格式要求**：必须使用 `yyyy-MM-dd HH:mm:ss` 格式的绝对时间（如 `"2026-03-21 00:00:00"`），不支持相对时间（如 `"7d"`、`"30d"`）。

**⚠️ 强制翻页要求**：`dws chat message list` 单次调用不会返回所有消息，返回结果中包含 `hasMore` 字段。**必须检查 `hasMore` 字段，当 `hasMore=true` 时，必须立即使用返回结果中最后一条消息的 `createTime` 作为下次调用的 `--time` 参数，继续拉取后续消息，循环直到 `hasMore=false` 为止**。禁止在 `hasMore=true` 时就停止拉取直接进入任务识别，否则会遗漏大量消息导致任务识别不完整。

翻页示例：
```bash
# 第 1 次拉取
dws chat message list --group <id> --time "2026-03-21 00:00:00" --format json
# 返回结果: hasMore=true, 最后一条消息 createTime="2026-03-22 08:30:15"

# 第 2 次拉取（用上次最后一条的 createTime 作为 --time）
dws chat message list --group <id> --time "2026-03-22 08:30:15" --format json
# 返回结果: hasMore=true, 最后一条消息 createTime="2026-03-23 14:20:00"

# 第 3 次拉取
dws chat message list --group <id> --time "2026-03-23 14:20:00" --format json
# 返回结果: hasMore=false → 拉取完成，合并所有消息后进入 B2 识别
```

时间范围选择策略：
- 用户未指定时间：默认拉取最近 3 天的消息（消息转待办场景具有时效性，3 天内的消息最具待办价值），需用当前时间减去 3 天计算出绝对时间作为 `--time` 参数值（例如当前是 2026-03-24，则传 `"2026-03-21 00:00:00"`）
- 用户指定了时间范围：按用户要求计算出绝对时间设置 `--time`（如用户说"最近一周"则减 7 天，说"3月15日起"则直接使用 `"2026-03-15 00:00:00"`）
- 如果 3 天内未识别到任务，可主动建议用户扩大时间范围重试

### B2 识别任务类内容

从消息中识别任务的信号词和模式，详见 [task-recognition-rules.md](./task-recognition-rules.md)。

核心识别逻辑：
1. 扫描每条消息，寻找任务信号（动词+对象、截止时间、@某人做某事）
2. 对于"@我的消息"场景，先过滤包含 @当前用户 的消息
3. 排除明显的非任务内容（问候、表情、闲聊）
4. 为每个识别出的任务提取：标题、优先级（默认 20-普通）、截止时间（如有）

### B3 展示识别结果

向用户展示识别出的任务列表，格式：

```
从 [群名/单聊对象] 中识别出以下任务：

1. 📋 [任务标题] — 优先级: [普通/较高/紧急] — 截止: [日期/未指定]
   📎 来源: [发送者名称] 于 [yyyy-MM-dd HH:mm:ss] 发送
   💬 原文: "[原始消息内容摘要]"
2. 📋 ...

请确认是否创建这些待办？可以告诉我需要修改或删除的项。
```

**展示要求**：每条识别出的任务必须附带**发送者名称**和**精确到秒的发送时间**，方便用户在钉钉中按时间和发送者快速定位到原始消息。

## Module C — 创建待办

**目标**: 将用户确认的任务创建为钉钉待办。

### C1 用户确认

等待用户确认识别结果。用户可以：
- 确认全部创建
- 删除某些项
- 修改标题/优先级/截止时间
- 指定其他执行者

### C2 批量创建待办

对每个确认的任务执行：

```bash
dws todo task create --title "<任务标题>" --executors <userId> --priority <优先级> --format json
```

如果有截止时间：
```bash
dws todo task create --title "<任务标题>" --executors <userId> --priority <优先级> --due "<ISO-8601时间>" --format json
```

优先级映射：
- 10 = 低
- 20 = 普通（默认）
- 30 = 较高
- 40 = 紧急

### C3 汇报结果

创建完成后，向用户汇报：

```
✅ 已成功创建 N 条待办：
1. [任务标题] — 优先级: [等级]
2. ...

你可以在钉钉待办中查看和管理这些任务。
```
