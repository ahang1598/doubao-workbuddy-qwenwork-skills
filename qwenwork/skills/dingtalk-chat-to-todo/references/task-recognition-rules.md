# 任务识别规则与信号词

## 任务信号词

以下模式表明消息中包含任务类内容：

### 强信号（高置信度）

| 模式 | 示例 |
|------|------|
| 动词 + 对象 + 截止时间 | "周五前把报告交了" |
| @某人 + 动词 + 对象 | "@张三 帮忙审核一下代码" |
| "需要/要/必须" + 动作 | "需要更新一下文档" |
| "记得/别忘了" + 动作 | "记得提交周报" |
| "TODO/待办/任务" 关键词 | "这个作为 TODO 记一下" |
| "负责/跟进/处理" + 对象 | "这个 bug 你来跟进" |

### 中信号（需结合上下文判断）

| 模式 | 示例 |
|------|------|
| 疑问句 + 动作暗示 | "这个功能谁来做？" |
| 时间词 + 动作 | "明天开会讨论方案" |
| "可以/能不能" + 动作 | "能不能帮忙测一下" |

### 非任务信号（应排除）

| 模式 | 示例 |
|------|------|
| 纯问候/表情 | "早上好"、"👍"、"哈哈" |
| 纯信息分享 | "分享一篇文章给大家" |
| 纯讨论/观点 | "我觉得这个方案不错" |
| 已完成的事项 | "报告已经提交了" |

## 优先级推断规则

| 消息特征 | 推断优先级 |
|----------|----------|
| 包含"紧急/urgent/ASAP/马上" | 40（紧急） |
| 包含"尽快/抓紧/优先" | 30（较高） |
| 包含明确截止时间 | 20（普通） |
| 无特殊标记 | 20（普通） |

## 截止时间提取规则

| 消息中的时间表达 | 转换为 ISO-8601 |
|----------------|----------------|
| "今天" | 当天 18:00 |
| "明天" | 次日 18:00 |
| "周五/本周五" | 本周五 18:00 |
| "下周一" | 下周一 18:00 |
| "X月X日" | 对应日期 18:00 |
| 无时间信息 | 不设置截止时间 |

## @我 消息过滤

当用户要求"把@我的信息记下来"时：
1. 获取当前用户的 userId 和名称
2. 在消息列表中过滤包含 @当前用户 的消息
3. 对过滤后的消息执行任务识别
4. 注意：@所有人 的消息也应包含在内

### 钉钉 @ 消息格式说明

`dws chat message list` 返回的消息中，@ 某人的内容可能以多种格式出现，识别时需要同时匹配以下模式：

| 格式 | 示例 | 说明 |
|------|------|------|
| `@用户名称` | `@张三 帮忙审核代码` | 最常见的格式，消息文本中直接包含 @+用户显示名 |
| `@所有人` | `@所有人 请注意` | @ 全体成员，应视为 @我 |
| `@All` | `@All 请查收` | 英文版 @ 全体成员 |

**匹配策略**（按优先级）：
1. 检查消息文本中是否包含 `@` + 当前用户的显示名称（从 `dws contact user get-self` 返回的 `name` 字段获取）
2. 检查消息文本中是否包含 `@所有人` 或 `@All`
3. 如果消息返回的 JSON 中有 `atUserIds` 或类似的结构化字段，优先使用该字段匹配当前用户的 `userId`（比文本匹配更准确）
4. 如果以上都无法匹配，检查消息文本中是否包含 `@` + 当前用户的 `userId`

**注意事项**：
- 文本匹配时应注意 `@张三` 不应误匹配 `@张三丰`，建议匹配 `@用户名` 后跟空格、标点或字符串结尾
- 优先使用结构化字段（如 `atUserIds`）而非纯文本匹配，因为文本中的 @ 可能被富文本格式包裹
