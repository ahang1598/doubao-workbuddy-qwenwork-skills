# A股上市公司深度研究编排

对A股上市公司进行完整的研究工作流：先识别公司分析模式，再选择和编排分析模块，最终合并为统一的有据可查研究框架。

## 不可违反的规则

- 严格区分 `事实`、`解读` 和 `待验证问题`，三层证据不得混淆
- 每个关键事实和数据都必须附带可访问的来源链接
- 优先使用官方披露、监管机构和政府公开平台，优先于媒体和评论
- 所有中间输出和最终输出默认使用简体中文，除非用户明确要求其他语言
- 不得在证据不充分时编造模式匹配结论，不确定性应标注在 `待验证问题` 中
- 不得生成无来源支撑的目标价或投资结论
- 合并各模块输出时保持证据分层，不得将事实和解读合并为单层叙述

## 触发条件

在以下场景中使用本技能：

- 用户要求对某家A股上市公司进行深度研究或分析
- 用户提出"分析这只股票"、"帮我研究XX公司"等模糊请求，需要转化为结构化工作流
- 用户需要评估某家公司的业务转型、财务健康度、行业竞争力、风险或估值
- 用户需要将多个维度的分析合并为一份统一的研究框架
- 用户提到"个股研究"、"深度报告"、"投研框架"等关键词

## 所需输入

| 输入项 | 说明 |
| --- | --- |
| 公司名称与股票代码 | 必须提供，用于定位所有披露和分析 |
| 研究目标或核心问题 | 必须提供，决定分析侧重方向 |
| 数据截止日期 | 可选，用户关注特定时间节点时提供 |
| 行业、商业模式或疑点提示 | 可选，有助于加速模式识别 |

## 工作流程

1. **模式识别**：使用本技能中的"分析模式选择器"识别公司的主要和次要分析模式
2. **模块路由**：使用本技能中的"路由矩阵"决定哪些分析模块为必选、可选或可跳过
3. **行业叠加判断**：使用本技能中的"行业叠加层升级规则"判断是否需要加载行业特定分析维度
4. **执行分析**：按正确顺序运行所选分析模块（通常为：战略转型 -> 业务拆解 -> 财务健康 -> 行业竞争 -> 风险预警 -> 估值策略）
5. **输出合并**：每个模块输出 `事实`、`解读`、`待验证问题` 三层结构，最终按"研究输出模板"合并
6. **质量检查**：确认所有事实都有来源引用，三层证据未混淆，冲突观点已保留双方

# 一、分析模式选择器

在加载行业特定叠加层之前，先使用此选择器确定公司的通用分析模式。

以下六大分析模式覆盖A股研究中的常见情形。仅在公司明确匹配某模式时才加载对应的行业叠加层。

## 常见分析模式

| 分析模式 | 适用条件 | 关键特征 |
| --- | --- | --- |
| **商业模式转型** | 原有业务萎缩，新增长引擎正在建设中 | 遗留业务仍贡献资产、应收、诉讼、担保或减值；资本配置、组织架构、客户结构、收入结构同时变化 |
| **项目/订单驱动型业务** | 收入依赖合同签约、在手订单、里程碑交付和客户验收 | 重大合同公告是股价主要驱动力；收入确认依赖完工进度或验收；客户集中度和回款条款比销售量更重要 |
| **重资产爬坡** | 固定资产、在建工程、产能利用率、资本开支和融资主导投资逻辑 | 固定资产和负债快速上升；产能建设先于完全变现；利用率/入驻率/负荷率比短期会计利润更重要 |
| **周期/价格驱动型业务** | 大宗商品价格、利用率、价差、库存周期和供给增量主导盈利 | 收入和利润随商品或现货价格波动；毛利率变动更多来自价差而非量增；产能投放、停产和库存周期比产品发布更重要 |
| **消费渠道与品牌** | 品牌力、同店趋势、渠道、分销、复购和终端动销决定业绩 | 收入依赖零售终端动销、门店客流或经销商库存；品牌定位和定价权比项目中标更重要；市场份额通过渠道扩张、品类组合或促销力度变化 |
| **受监管医药/医疗** | 医保报销、集中采购、审批、产品注册和医疗政策变化显著影响估值 | 产品获批、招标结果、医保准入或定价政策可能引发股价重估；集采、医院准入或药械政策比宏观增长更重要 |
| **出口制造与供应链** | 海外需求、客户集中度、关税、汇率、产能利用率和库存周期主导股价 | 大部分收入来自出口或海外客户；OEM/ODM集中度和订单可见性重要；关税、汇率和贸易政策可快速重塑盈利 |
| **政策敏感型行业** | 监管、补贴、配额、报销或牌照对业绩有显著影响 | 使用行业核查清单，并匹配上述最接近的叠加模式 |

## 重要规则

- 先从通用模式出发，再考虑行业叠加层
- 行业叠加层不是默认路由假设，仅在公司已匹配更广泛的模式后才加载
- 如果公司同时匹配三种或以上模式且权重接近，运行全部六大分析模块

# 二、路由矩阵

根据分析模式决定哪些分析模块必选、可选或可跳过。

## 模式到模块的路由

| 分析模式 | 必选模块 | 常见可选模块 | 说明 |
| --- | --- | --- | --- |
| 商业模式转型 | 战略与业务转型、财务健康度 | 风险预警与催化剂、估值与投资策略、行业竞争与护城河 | 适用于新旧业务重叠期 |
| 项目/订单驱动型业务 | 业务拆解与订单质量、财务健康度 | 风险预警与催化剂、估值与投资策略、行业竞争与护城河 | 收入质量和现金转化最重要 |
| 重资产爬坡 | 财务健康度、风险预警与催化剂 | 战略与业务转型、估值与投资策略、行业竞争与护城河 | 聚焦资本开支、爬坡、融资、利用率 |
| 周期/价格驱动型业务 | 行业竞争与护城河、估值与投资策略、风险预警与催化剂 | 财务健康度 | 需将周期与护城河分开 |
| 消费渠道与品牌 | 行业竞争与护城河、业务拆解与订单质量、风险预警与催化剂 | 财务健康度、估值与投资策略 | 渠道和终端动销质量最重要 |
| 受监管医药/医疗 | 行业竞争与护城河、风险预警与催化剂、估值与投资策略 | 战略与业务转型、财务健康度 | 政策和审批节奏驱动风险 |
| 出口制造与供应链 | 业务拆解与订单质量、行业竞争与护城河、财务健康度 | 风险预警与催化剂、估值与投资策略 | 客户集中度、汇率和库存最重要 |

## 默认规则

- 公司明确匹配一到两种模式时，按上表路由
- 公司匹配三种或以上模式且权重接近时，运行全部六大分析模块
- 商业模式不明确时，先运行"战略与业务转型"、"财务健康度"和"行业竞争与护城河"三个模块，再扩展

## 执行顺序

默认按以下顺序执行分析模块：

1. 战略与业务转型
2. 业务拆解与订单质量
3. 财务健康度
4. 行业竞争与护城河
5. 风险预警与催化剂
6. 估值与投资策略

仅在模式逻辑明确表明某模块非必要时才跳过。

# 三、行业叠加层升级规则

仅在通用分析模式已明确后再使用行业叠加层。

## 升级原则

- 从通用模式出发
- 仅当行业特定变量会实质性改变至少两个分析模块的证据收集或判断标准时，才添加行业叠加层

## 合理的升级理由

- 受监管的审批或报销制度决定收入确认时点
- 渠道库存和同店表现决定报告的增长是否真实
- 大宗商品定价、价差或行业库存主导盈利
- 出口敞口、关税、汇率和客户集中度实质性重塑盈利能力
- 资产爬坡、利用率和融资结构主导投资逻辑

## 典型叠加层选择

| 情形 | 叠加层 |
| --- | --- |
| 新业务替代旧业务 | 商业模式转型叠加层 |
| 收入依赖合同或在手订单 | 项目/订单驱动业务叠加层 |
| 资本开支、在建工程和利用率主导 | 重资产爬坡叠加层 |
| 价差和周期主导 | 周期/价格驱动叠加层 |
| 品牌和渠道主导 | 消费渠道与品牌叠加层 |
| 政策和审批主导 | 受监管医药/政策叠加层 |
| 出口客户和汇率主导 | 出口制造与供应链叠加层 |

## 输出要求

明确说明每个叠加层的加载原因及其影响的分析模块。

# 四、六大核心分析模块

## 模块一：战略与业务转型

### 目标

分析A股公司如何从旧业务模式转向当前模式，评估转型真实进度。

### 适用场景

- 评估公司从遗留业务向新增长引擎的转型
- 检验管理层的转型叙述是否有披露支撑
- 识别旧资产、旧客户或旧负债的持续拖累

### 分析步骤

1. 调取招股说明书、最新年报、最新中报和近期重大公告
2. 构建业务模式变化、资本配置、融资行为和项目里程碑的时间线
3. 识别旧业务、新业务和重叠期
4. 衡量收入、毛利、资产和现金流是否已跟随叙述迁移
5. 使用转型记分卡评估：能力、客户结构、收入质量、轻资产进度、现金转化
6. 输出战略层面的结论和待验证要点

### 必问问题（转型类公司）

- 新业务是在改变收入结构、毛利结构和现金流结构，还是只改变了故事？
- 遗留业务的拖累是否在足够快地缩小？
- 管理层是用股权、债务还是内生现金来资助转型？
- 哪个里程碑能证明新业务真正商业化，而不仅仅是公告？

### 所需输出

- `事实`：业务历史、分部变化、资本配置、资产变化、管理层声明
- `解读`：转型完成度、内部矛盾、可能的瓶颈
- `待验证问题`：仍需验证的内容及应查询的来源
- `转型雷达`：能力、客户结构、收入质量、轻资产进度、现金转化

### 边界

- 不深入项目管线执行细节
- 不计算偿债能力记分卡
- 不生成目标价或买卖建议

---

## 模块二：业务拆解与订单质量

### 目标

拆解公司的增长引擎，检验订单质量——区分已签约、在手订单、已交付收入和已回款现金。

### 适用场景

- 分析合同驱动或项目驱动的增长
- 检验新业务是高质量还是仅仅高营收标题
- 审视客户集中度、订单取消、延迟执行和区域结构

### 分析步骤

1. 收集所有重大订单公告和近期报告
2. 构建包含产品、项目、客户、区域、合同金额、期限、交付阶段和收入确认方法的表格
3. 比较订单增长与收入增长、毛利率、应收账款、合同资产和回款
4. 审视项目变更、取消和合同修订的信号价值
5. 区分哪些增长是经常性的、哪些是一次性的、哪些可能无法转化

### 必问问题（订单驱动类公司）

- 哪些订单只是框架协议、哪些已签约、哪些实际可执行？
- 哪些已交付收入已转化为实际回款？
- 合同资产、应收账款或库存的增长是否快于可信的执行进度？
- 哪个外部来源可以验证项目、客户或合同范围？

### 所需输出

- `事实`：分部结构、客户结构、项目清单、订单管线、收入确认方法
- `解读`：订单质量、集中度风险、执行风险、交付可见性
- `待验证问题`：未知的定价、里程碑时间表、付款条款或客户依赖
- `管线表`：订单金额、阶段、预期转化率、来源

### 边界

- 不做完整的偿债能力诊断
- 不构建最终的行业护城河结论
- 不出具买卖建议

---

## 模块三：财务健康度

### 目标

诊断公司的会计利润是否有真实现金流和稳健资产负债表支撑。

### 适用场景

- 收入增长但利润或现金流疲软
- 营运资本扩张快于销售
- 债务、融资成本、担保或资本开支可能威胁资产负债表

### 分析步骤

1. 调取最新年报、中报和季报
2. 构建三表视图：利润表、现金流量表、资产负债表
3. 重点关注：现金转化、应收账款、合同资产、库存、资本开支、债务、融资成本和减值
4. 将当前压力点与管理层解释进行比对
5. 对流动性、杠杆和盈利质量打分

### 所需输出

- `事实`：关键科目、比率集合、债务明细、减值、营运资本趋势
- `解读`：主要结构性问题、风险传导路径、可能的断裂点
- `待验证问题`：隐性担保、回款节奏、再融资时间表、表外项目
- `健康记分卡`：盈利质量、现金转化、流动性、杠杆、资产质量

### 边界

- 不复述完整的行业结构
- 不选择估值方法
- 不做投资组合配置判断

---

## 模块四：行业竞争与护城河

### 目标

将公司置于其真实的行业结构中，检验其是否拥有可防御的经济学特征。

### 适用场景

- 评估行业吸引力和竞争格局
- 将公司与上市同行和替代商业模式进行比较
- 检验政策、资本、资质、数据、渠道或转换成本是否构成护城河

### 分析步骤

1. 定义价值链及公司在其中的确切位置
2. 从官方来源调取行业政策和需求数据
3. 选择有来源支撑的可比公司集合，比较产能、客户、毛利率和商业模式
4. 应用护城河网格和五力分析框架
5. 突出公司在哪些环节获取价值，在哪些环节仍然脆弱

### 所需输出

- `事实`：行业规模、政策顺风/逆风、可比公司定位、价值链角色
- `解读`：护城河强度、结构性优势、可能的压力点
- `待验证问题`：缺失的同行指标、不确定的供给增量、不清晰的监管
- `价值链图谱`：每个环节标注强、中、弱的价值获取能力

### 边界

- 不深入公司订单管线的细节
- 不构建风险仪表盘
- 不生成目标价或交易计划

---

## 模块五：风险预警与催化剂

### 目标

将静态研究转化为实时监测框架，覆盖订单、融资、治理、政策、运营和市场情绪。

### 适用场景

- 在深度研究报告后建立监测清单
- 跟踪投资逻辑是在改善还是恶化
- 建立月度或事件驱动的更新流程

### 分析步骤

1. 调取最新公告，识别自上次报告以来的变化
2. 按类别映射风险：执行、财务、治理、政策、客户、技术、诉讼
3. 按类别映射催化剂：订单、政策、融资、资产处置、利用率、利润率改善
4. 为每个项目附加阈值、预期证据来源和审视频率
5. 构建月度仪表盘和催化剂日历

### 所需输出

- `事实`：已确认风险、已确认催化剂、最近更新状态
- `解读`：哪些因素对投资逻辑最重要及原因
- `待验证问题`：哪些缺失数据点可能改变信号
- `仪表盘`：指标、阈值、最新值、来源、下次检查日期

### 边界

- 不复述完整的战略回顾
- 不重新计算所有财务比率（除非监测所需）
- 不生成目标价或仓位建议

---

## 模块六：估值与投资策略

### 目标

在事实基础完成后，构建基于情景的估值框架和投资计划。

### 适用场景

- 完整的公司研究已存在，需要估值框架
- 公司处于转型期，简单的PE估值不够用
- 报告需要看空、中性、看多三种情景及明确假设

### 分析步骤

1. 整合前五个模块的输出
2. 选择合适方法：可比公司倍数、分部估值（SOTP）、EV/EBITDA、PB、DCF 或资产基础法
3. 定义情景表，包含收入、利润率、资本开支、利用率和资产负债表假设
4. 将每个假设链接到支撑来源，或标注为分析估算
5. 生成价值区间、投资逻辑检查点和失效触发条件

### 所需输出

- `事实`：估值相关事实、可比公司集合、资产基础、融资约束
- `解读`：哪种方法最合适及原因
- `待验证问题`：缺失的入驻率、利润率、资本开支或处置假设
- `情景表`：看空、中性、看多，附带链接假设
- `投资计划`：建仓条件、止损条件、投资逻辑确认里程碑

### 边界

- 不从头重建原始公司事实库
- 不展示无支撑的精确数字（如没有区间的精确公允价值）
- 不忽视风险和资产负债表约束

# 六、研究输出模板

合并各分析模块输出时，使用以下统一结构。所有输出默认使用简体中文。

## 最终输出章节顺序

### 1. 公司概览与路由决策

- 公司名称、股票代码、数据截止日期、选定的分析模式
- 已运行的核心分析模块及其选择理由
- 已加载的行业叠加层及其选择理由

### 2. 核心结论

- 一段式结论摘要
- 主要看多点
- 主要看空点
- 结论置信度

### 3. 事实

- 仅包含有来源支撑的事实
- 每条关键声明都附带引用
- 在有用时标注来源模块，例如 `事实 | 财务健康度`
- 保留原始单位、期间和会计口径
- 在已知时标注数据是否经审计、审阅或未经审计

### 4. 解读

- 解释事实可能意味着什么
- 不将推断转化为事实
- 引用回所支撑的事实和来源
- 明确写出假设

### 5. 反证

- 哪些信息会削弱或推翻当前判断
- 哪些指标或事件会改变观点

### 6. 待验证问题

- 仍需进一步核实的未知点
- 下一步应去核查的具体来源
- 保持问题的明确性，不隐藏不确定性

### 7. 监测指标

- 从"风险预警与催化剂"模块提取最高信号强度的指标
- 附加阈值和来源路径
- 需要月度或季度跟踪的指标
- 关键触发事件与阈值

### 8. 情景与估值钩子

- 悲观 / 中性 / 乐观情景
- 关键假设与敏感性因素
- 有来源支撑的可比对象
- 仅在证据不完整时不强制给出精确目标价

### 9. 来源附录

- 完整引用清单
- 主要来源集合
- 重要次要来源集合
- 不可访问、冲突或不完整的证据说明
- 数据限制与证据缺口

## 合并规则

- 不得将事实和解读合并为一句话而模糊证据边界
- 如果两个模块的结论冲突，保留双方观点并解释差异
- 所有来源链接必须可直接点击

# 八、引用标准

每个输出都必须分离 `事实`、`解读` 和 `待验证问题`。

## 最小引用单位

- 每个关键句子必须附带至少一个可访问的来源链接
- 关键表格的每一行必须附带主要来源
- 每个数据图表必须在图表下方列出来源集合

## 引用格式

使用以下内联格式：

```
[来源: 机构或公司, 文档名, 日期, 链接, 页码/章节/公告编号]
```

示例：

```
2025H1 IDC业务收入占比达到100%。[来源: 城地香江, 2025年半年度报告, 2025-08-XX, https://www.cninfo.com.cn/, 第X节]
```

## 证据层级

- **第一层级**：法定申报、监管发布、交易所披露
- **第二层级**：部委数据、公共采购公告、公开统计、官方协会材料
- **第三层级**：公司网站、媒体、券商研报、访谈、会议纪要

## 判断规则

- 核心投资结论必须由至少一个第一层级或第二层级来源支撑
- 第三层级来源可丰富背景，但不可作为关键结论的唯一支撑
- 如果不同来源存在冲突，双方观点并列展示并明确说明冲突

## 写作规则

- 未验证但合理的推理标注为 `解读`，不标注为 `事实`
- 缺失的证据标注为 `待验证问题`，并指明下一步应核查的来源
- 引用数据时保留原始单位、期间和会计口径
- 在已知时标注数据是否经审计、审阅或未经审计

## 链接规则

- 尽可能使用直接可访问的URL
- 如果披露平台使用可搜索的着陆页而非稳定的文档URL，同时引用门户和足够的元数据以便重新查找文档
- 不得在没有底层公开URL的情况下引用截图

- 不得直接替代六大核心分析模块内部的深度分析工作
- 不得在证据薄弱时编造模式匹配结论，不确定性标注在 `待验证问题` 中
- 不得生成无来源支撑的目标价或投资结论
- 合并模块输出时保持证据分层，不将事实和解读合并为单层叙述
- 不得忽视风险和资产负债表约束
