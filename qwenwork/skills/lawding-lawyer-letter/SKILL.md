# 律师函撰写技能

## 核心定位

以20年资深民事律师的执业水准，提供战略性、专业化的律师函撰写服务。不仅生成文书，更提供发函策略、风险评估、后续行动建议。

## 六大函件类型

- **催告函**：催促履行合同义务、催收款项、催告采取特定行动
- **警告函**：警告停止侵权、严重违约警示，施加心理压力
- **询问函**：了解事实、核实信息、调查告知
- **法律意见函**：就委托人对特定事项向对方提供书面法律意见
- **声明函**：明确事实、表明立场、声明权利归属
- **告知函**：告知法律事实、权利义务、程序性通知

## 工作流程

### 阶段一：需求分析与策略评估

1. **明确用户目的**：催告协商 / 证据固定 / 诉讼准备 / 程序性通知
2. **评估发函时机**：当前处于什么阶段（首次沟通、多次催告无果、诉讼准备）
3. **确定函件类型与措辞强度**（见下方"措辞强度参考"）
4. 复杂策略场景参考 [references/strategy.md](references/strategy.md)

### 阶段二：信息收集与完整性核查

**必填信息（起草前必须向用户确认无误）：**
- 委托人信息（姓名/全称、联系方式、地址）
- 收件人信息（姓名/全称、地址）
- 律师信息（律所名称、律师姓名）
- 基础法律关系（合同/侵权/不当得利等）
- 关键事实与时间线
- 诉求内容（履行、赔偿、停止行为等）
- **关键数字确认**：涉及的金额、利息计算基准、日期期限等必须逐项与用户核实

**可选信息：**
- 函件编号偏好
- 附件清单
- 送达方式偏好

**缺失信息占位符约定（重要，防止以假乱真）：**
- 若用户未提供某项必填信息，**禁止杜撰具体主体名称、地址、账号、电话等**（虚构的真实感极易导致误用）。
- 统一使用醒目占位符 `【待补充：XXX】` 标注，例如 `【待补充：委托人开户行及账号】`、`【待补充：律所全称】`。
- 生成文档末尾追加一节「⚠️ 待补充信息清单」，逐条列出所有占位符，提醒用户补齐后方可正式使用。
- 仅在用户明确说明「用示例/mock 数据演示」时，才允许填入示例值，并在文首标注「本文为示例稿，主体信息均为虚构」。

### 阶段三：法律分析与风险评估

1. **证据充分性评估**：现有证据能否支撑主张；是否需要补强
2. **法律关系定性**：参考 [references/scenarios.md](references/scenarios.md) 确定适用场景和法条
3. **诉讼时效检查**：是否临近届满；是否存在除斥期间
4. **风险提示**：发函可能的不利影响和应对策略

**法律引用原则**：始终引用现行有效法律。优先引用《中华人民共和国民法典》及其配套司法解释，禁止引用已废止的《合同法》《担保法》《婚姻法》等旧法。如需引用旧法条文，必须标注"已被《民法典》第X条替代"。

**旧法自检（强制）**：引用任一法条前，先对照 [references/legal-mapping.md](references/legal-mapping.md) 的「旧法→民法典映射表」交叉核对；凡命中旧法名称（合同法/物权法/担保法/婚姻法/继承法/收养法/民法通则/侵权责任法等）一律替换为对应民法典条文，禁止直接引用。金额涉及利率上限（LPR 四倍）、违约金与利息合并封顶等，也在该表中核对现行口径。

### 阶段四：撰写律师函

结构要素参考 [references/templates.md](references/templates.md)，法律术语规范参考 [references/legal-terms.md](references/legal-terms.md)。

**三段论结构（法律分析部分）：**
- 大前提：概括法律规范（行为模式 + 法律后果）
- 小前提：代入案件事实（"本案中……"）
- 结论：得出法律观点（"因此……"）

**写作禁忌（所有类型通用）：**
- 禁用模糊表述："可能""或许""大概"
- 禁用弱化语气："我们认为""初步判断"
- 禁止"逾期未答复视为默认"（无法律依据）
- 禁止捏造事实、夸大事实
- 禁止人身攻击性语言

### 阶段五：质量检查

1. **内容**：事实准确、法律引用无误、诉求明确具体、时间期限合理
2. **格式**：编号规范、落款完整、联系方式无误
3. **策略**：措辞强度符合策略定位，无过激表述

### 阶段六：输出与后续指导

1. **生成 Word 文档（按下列降级链依次尝试，优先产出本地 `.docx`）：**

   **① 首选：`docx` skill** —— 若环境已安装 `docx` skill，调用它生成专业排版 Word 文档。

   **② 兜底（推荐，`docx` skill 未安装时）：本机 `python-docx` 直接生成本地 `.docx`。** 本技能内置 [scripts/gen_letter_docx.py](scripts/gen_letter_docx.py)，读取一份 JSON 数据即可产出格式规范的律师函 Word（含标题、发函号、三段论正文、落款、附件、待补充清单）。这是与 description「输出 Word 文档」承诺最一致的路径，务必优先于钉钉在线文档：
   ```bash
   python3 scripts/gen_letter_docx.py <数据.json> <输出.docx>
   # 若报缺库：python3 -m pip install python-docx
   ```
   JSON 字段说明见脚本头部注释；未提供的字段按「阶段二占位符约定」填 `【待补充：XXX】`。

   **③ 最后降级：`dws doc create` 生成钉钉在线文档**（仅当本机无 python-docx 且无法安装时）。注意这会产出在线文档链接而非本地 Word 文件，须向用户说明格式差异。先将 Markdown 落盘再用 `--content-file` 读取（`dws doc create` 用 `--name` 而非 `--title`，无 `--content`/`--markdown` 参数）：
   ```bash
   dws doc create --name "[对方当事人]_律师函" \
     --content-file ./律师函_[对方当事人].md \
     --content-format markdown --fix-jsonml -y
   ```

   **字体 fallback（跨平台必读）：** 模板推荐的「方正小标宋简体」「小标宋体」等仅 Windows 常见，macOS/Linux 会静默回退导致排版走样。生成时正文统一用「宋体」、标题用「黑体」这类跨平台通用字体作为 fallback；`gen_letter_docx.py` 已内置该回退，无需额外处理。

   **金额规范：** 所有金额须「阿拉伯数字 + 中文大写」并列（如「人民币 250,000 元（大写：贰拾伍万元整）」）。中文大写不得手工臆写，调用 [scripts/amount_cn.py](scripts/amount_cn.py) 的 `to_cn_upper(amount)` 转换（支持元/角/分），`gen_letter_docx.py` 已自动调用。
2. **送达方式建议**：
   - EMS 快递：最常用，便于举证，建议保存底单
   - 公证送达：重大案件，提供绝对证据效力
   - 直接送达：面交，要求签收，留存签收记录
   - 电子送达：辅助方式，建议同时使用其他方式
3. **证据保存提醒**：快递底单、签收凭证、送达回证
4. **后续行动建议**：对方履行 / 部分履行 / 拒绝履行 / 完全无应答 各情况下的应对方案
5. **时间节点管理**：履行期限届满日、诉讼时效关注点、计划起诉日（如需要）

## 措辞强度参考

| 强度 | 适用场景 | 关键词特征 |
|---|---|---|
| **温和协商型** | 首次发函、长期合作方、误会型纠纷 | "希望""建议""期待协商" |
| **中立告知型** | 程序性通知、需核实事实 | "特此告知""请予说明" |
| **警示施压型** | 多次催告无果、明显违约 | "严正要求""务必""将追究" |
| **强硬最后通牒** | 证据充分、决定起诉、对方恶意拖延 | "立即""必须""将立即起诉并申请财产保全" |

## 特殊场景处理

详见 [references/scenarios.md](references/scenarios.md)，涵盖：
- **合同纠纷类**：合同履行催告、合同解除通知、付款催收、变更补签
- **债权债务类**：欠款追讨、担保追偿、债权转让通知
- **侵权纠纷类**：一般侵权、知识产权侵权（商标/著作权/专利/不正当竞争）
- **劳动争议类**：解除劳动关系、竞业限制、自赔追讨
- **房地产类**：租赁纠纷、房屋买卖、物业纠纷
- **股权行使类**：股权转让通知、请求分红、行使知情权
- **其他**：消费维权、保险理赔、交通事故赔偿、工程款催收

## 特殊主体处理

- **政府机关**：措辞严谨，依法行政，引用行政法规
- **金融机构**：关注监管合规，引用金融法规
- **外国主体**：考虑送达方式（海牙公约），必要时附语言版本
- **个人独资/合伙**：明确责任主体，穿透个人责任
