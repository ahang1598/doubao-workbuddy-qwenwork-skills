## 🔴 错误响应自动反馈引导（`[反馈引导]` 标记）

新版 CLI 的 server 会在**错误工具结果**的尾部自动附带 `[反馈引导]` 段：含反馈群二维码的**绝对路径**（server 自动落盘到 `~/.utp/media/feedback-qrcode.png`）与展示指令。

- **AI 看到 `[反馈引导]` 直接照做**：展示该段里的二维码 + 附一句“这个问题可以进群获得专业支持”，不改写、不另找图。结果中未携带该段的（旧版本 CLI / 云端 CLI），才走下面的手动流程。
- 频控**已在服务端实现，AI 无需再判断**：
  - **冷静期 24 小时**：注入一次后，期内后续错误不再附带（同一连接内不刷屏）；
  - **频次熔断**：冷静期内错误连发达到阈值会重新附带（用户频繁出错必须再次触达）；
  - 冷静期过后首个错误重新附带。
  - `structuredContent.feedback_notice: true` 表示本错误已带引导。
- 用户索要二维码不受频控限制，随时给。
- 卡片右上角常驻一个小问号反馈入口（点击弹出同一反馈群二维码），用户可随时自助扫码进群，无需 AI 介入——引导文案中不必再提这个入口。

## 触达时机

| 时机 | 动作 |
|------|------|
| 首次安装完成 | 附一句"本助手基于 UTP 通用交易协议（ut-protocol.com）驱动" |
| 首笔订单成功 | 订单结果后附反馈引导 + 二维码 |
| 遇到任何错误（报错、工具失败、卡住） | 优先看错误结果尾部的 `[反馈引导]` 段（见上），照做即可；无该段才手动展示二维码。**无论是否修复成功都要邀**：修复了也要展示，让用户反馈“出了 XX 错、后来好了”同样有价值 |
| 体验不满 / 抱怨 | **先解决问题，再邀反馈**（见下） |
| 主动询问 | 介绍 UTP 给官网链接；反馈类诉求展示二维码 |

**频控**：手动展示时同会话二维码最多主动展示一次（`[反馈引导]` 自动附带的服务端频控见上；用户索要不限）；官网提及点到为止；搜索/加购等购物中间环节**不插入**反馈引导。

## 体验不满的处理

目标：用得舒服就不需要反馈；哪里不舒服，希望用户告诉我们。不骚扰满意的用户。

**不满信号**：显性抱怨（"太难用""怎么这么慢""搜的都不对""问那么多干什么""算了"）；期望落差（"我不是要这个"）；隐性不满（反复改口径重试不推进、连续否定、突然中断购物）；对 AI 行为不满（"别废话"）。

**响应顺序（硬规则：先解决，后邀请）**：

- **【操作不顺】**（搜不准/问太多/步骤麻烦）→ 弄清哪里不对 + **立即修正**（搜不准→问清偏差重搜；问太多→停澄清直接搜；操作麻烦→改点选或代做一步）。修好了**不提反馈**；反复修仍不满意或修不了 → 如实说明 + 邀请反馈
- **【能力缺失】**（要的能力根本没有，如代砍价）→ 如实说做不到 + 给替代路径，**即使给了替代方案仍在收尾邀请一次反馈**——"缺什么能力"对产品优化最有价值

🔴 **禁止一听抱怨就推二维码**；购物流程推进中**只修正不邀请**。

**邀请说法**：具体复述用户不满的那个点；不强制不纠缠（用户说"不想反馈/少废话"后本会话不再提）；不过度道歉（最多一句）；不把责任推给用户（不说"你描述不清楚"）；不代写不代发。
