# 来源选择与结果评估

## 判断提取结果是否可用

结合 `Keyword coverage`、`Missing keywords`、`Extracted: <shown>/<total> chars` 和质量标志评估抓取结果。关键词采用不区分大小写的字面匹配。设置日期或数字关键词时，优先使用年份或 ISO 日期等稳定片段。

| 信号 | 必需操作 |
| --- | --- |
| `dynamic_js` | 使用可用的浏览器获取渲染后的内容，或改用其他官方页面 |
| `short_content` 或 `low_keyword_coverage` | 调整 `--keywords`，或选择相关性更高的来源 |
| `sparse_extract` | 使用 `--format markdown` 或 `--full` 重新抓取表格或矩阵 |
| `truncated` | 在认定某事实不存在前，使用更具体的关键词或 `--full` |
| `error_page` | 不得将该页面作为信息依据 |
| `no_keyword_matches` | 当前提取（通常是回退密度窗口）未命中任何关键词；更换 `--keywords` 或改选相关性更高的来源 |
| `partial_keyword_coverage` | 部分关键词未命中；用 `Missing keywords` 判断该页是否仍能支持结论，否则补充来源 |

仅在确需提取完整内容时使用 `--full`（重复抓取同一 URL 的限额计入方式见 `SKILL.md`）。

## 选择可靠来源

按以下顺序选择来源：

1. 官方文档、公告、代码仓库、监管申报材料或论文。
2. 独立、权威且提供原创内容的来源。
3. 可信的二手来源。
4. 新闻聚合器、转载文章和搜索摘要，仅用于发现来源或回退。

对于规格、价格、可用性、发布计划、法律、医疗或金融等重要主张，至少使用一个第一方来源。不得将转载副本视为独立证据。除非用户请求与网站主页本身有关，否则未指定路径的根主页只能用于识别相关域名。

## 提取失败时的处理顺序

命令已对传输故障、HTTP 408/425/429/5xx 响应及同类临时服务错误自动重试两次。不得立即重复执行相同命令。

无法抓取页面时：

1. 在五页预算内选择另一个官方页面。
2. 两个不同页面均抓取失败后，仅当相关搜索摘要足以支持该主张时，才可将其作为信息依据。
3. 使用搜索摘要时，说明原页面不可用。
4. 说明尚未核实的事实；缺少可靠信息时不得推断。

不得引用空白、不可读、与主题无关、明显被截断或标记为 `error_page` 的内容。优先使用稳定的原始 URL，不使用重定向链接或包含签名、时效参数的 URL。必须注明供应商自身声明的出处；信息具有时效性时注明有效日期；链接建议紧邻其支持的陈述。

## 搜索与提取参数

下列参数用于控制搜索与提取行为，通常使用默认值即可；仅在确有必要时覆盖。

| 参数 | 适用子命令 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--max-results` | `search` | `10`（范围 1–50） | 每次搜索返回的结果数 |
| `--context-lines` | `fetch`、`fetch-many` | `4` | 每个关键词命中上下文的行数 |
| `--max-chars` | `fetch`、`fetch-many` | `12000` | 单次提取的字符上限；超过后触发 `truncated` 标志 |
| `--workers` | `fetch-many` | `3`（上限 4） | 并发抓取的工作线程数 |
