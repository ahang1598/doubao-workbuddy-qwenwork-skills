# 安全与质量门禁

## 1. 数据安全

- 欢迎语情形判定仅读写单个布尔标记（平台记忆可用时）；身份、关系、财产债务、意愿、附件、工作数据和生成文件不得进入长期 Agent 记忆。
- 记忆不可用、不可读、无效或含义不明时使用中立文案，不以当前对话或材料猜测调用历史。
- 收集前说明目的、必要性、保存位置和删除方式。
- 隐私分层：律师通道必须先完成与《千问办公隐私政策》一致的隐私确认卡；其他模式在采集方式选择话术中告知用途，首次作答视为同意并自动记录 `consent`；无 `consent` 记录不得进入检索与生成。欢迎语不包含隐私条款。
- 对证件、金融账户、健康、未成年人和家庭争议信息实行更严格访问控制。
- 身份数据与案件业务数据分离；对模型优先使用别名和掩码。
- 默认禁止将案件输入用于模型训练或通用样本。
- 文件名、调试日志、错误堆栈和分析指标不得包含完整敏感信息。
- 分享前执行脱敏和权限检查；分享后保留撤回路径。

## 2. 内容安全

- 识别是否为本人表达或授权协作；可疑时转人工。
- 不推动用户作出不可逆决定；展示不确定性和专业审核状态。
- 不使用带有污名或歧视性的家庭关系标签。
- 用户表达紧迫的人身安全、自伤或他伤风险时，暂停遗产规划流程并转入适当的安全支持，不继续强化死亡安排。
- 不根据用户情绪、年龄、性别、婚姻状态或家庭形式降低服务质量。

## 3. 质量门禁

### 数据门禁

- JSON 可解析；
- 所有 ID 唯一；
- 所有外键引用存在；
- 关键实体有来源和确认状态；
- 未知值显式记录；
- 不存在静默覆盖。
- 已在卡片前完成材料和指令覆盖度评估；
- 总问题数等于本次编译的必答卡片数（可重复实例展开后更新），进度与已确认响应数一致；
- 基本信息与行为能力/表达情况来自两张独立卡片；
- 进入检索前全部必答卡的响应已写入 work-data.json；
- 成果选择卡与 `requested_deliverables` 一致。

### 内容门禁

- 欢迎语随首条回复逐字开场（文案取自 SKILL.md），同轮发出采集方式选择卡；无记忆读写、无额外轮次；
- 人物名称和角色前后一致；
- 财产、债务和意愿映射一致；
- 用户陈述、系统检查和专业判断分层；
- 所有未决问题进入待办；
- 没有把推断写成事实；
- 规则包状态和审核状态醒目标注。
- 用户类型与语言档位匹配，普通用户表达通俗但信息不缩水；
- 必答卡组一次编译、以选项/填空卡片分组发出，导航由卡组确定性决定，模型不临时改题；因材料充分跳过的问题有来源且进入最终汇总确认；
- 快速模式的枚举解析结果在汇总核对确认前保持 `system_inference`，未升级为确认事实；框架稿预览显著标注“待律师人工复核的 AI 草案”；全程仅一次汇总核对，已确认字段不重复发卡；签署要件以单张告知卡确认；律师通道的文本输入例外已向用户披露；
- 行为能力卡只记录陈述和观察，未把 AI 判断写成法律结论；
- 法律原文和案例原文已打开，链接、检索时间、效力/类型和关联完整；
- 待判断事项在执行指引中具体、简明列明，不以通用免责声明代替，不另生成 AI 待判断文件。
- 所有文件均含精确 AI 文件声明；输出元数据固定 `preparation_only=true`、`signature_ready=false`；任何 PASS、零 error 或无阻断结果均不转述为可以签署。

### 文档门禁

- 案件 ID、版本和生成时间正确；
- 名称、数字、日期和编号一致；
- 表格无截断；
- 附件引用存在；
- 页眉中的草案或审核状态正确；
- 输出文件可打开；
- 不包含内部提示词、工具日志或模型推理文本。
- 遗嘱 DOCX 的源范本哈希、固定标题顺序和分节数量正确；
- 页眉、页脚、页码字段、封面和签署区保留；
- 已渲染并逐页检查，没有异常空白、截断、重叠或页码错误。
- AI 遗嘱草案、执行指引及用户勾选的全部可选成果均按门禁实际生成；经核验的普法内容直接进入交付对话，不生成独立文件；
- 财产清单覆盖全部已知财产和债务/义务；
- 关系人示意图覆盖全部已知人物、继承/受益角色、全部已知财产和拟继承/受益映射。
- 未生成案件概览、案件快照、专业交接单、归档或生命周期文件。

## 4. 评测集

建立专家审核的黄金案例，覆盖标准、资料缺失、关系复杂、资产复杂、前后矛盾、重复实体、错误引用、文件损坏、超长对话和高风险人工升级等场景。

每个案例定义：

- 应询问和不应询问的问题；
- 标准结构化事实；
- 预期缺口和冲突；
- 预期分流级别；
- 允许生成的成果；
- 必须人工处理的事项；
- 不应出现的内容。

## 5. 发布指标

重点监控：

- 信息缺口召回率；
- 无效追问率；
- 结构化字段纠正率；
- 专业人员新增问题数；
- 专业人员平均审查时间；
- 文档字段不一致次数；
- 用户确认后错误改写次数；
- 规则包和模板升级回归通过率；
- 采集卡组数量与单组题量（合组效率）、因漏采或误判导致的重发率；
- 卡片回答写入 work-data.json 的完整率（card_responses 与 required_card_ids 对账）；
- 已选成果完整交付率；
- 敏感信息越权访问和泄露次数；
- 人工升级准确率。

不要把“生成了多少份文档”作为唯一成功指标。
