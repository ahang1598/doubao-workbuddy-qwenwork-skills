# 法律规则包接口

## 当前实现

`assets/rules/cn-will-core-v0.2.0.json` 是当前开发版规则目录，`scripts/evaluate_rules.py` 是确定性执行器。每条规则声明规则 ID、处理器、输入路径和法源引用；法律判断不得只藏在 Prompt 中。

规则包固定包含：

- `rule_pack_id`、版本、法域、状态和法源核验时间；
- 官方法源 URL、文号、生效日期和条文；
- 每条规则的输入路径、执行处理器和法源引用；
- 批准角色、批准人和批准时间。

执行报告固定包含规则 ID、`PASS/WARN/REVIEW_REQUIRED/BLOCKED`、结果代码、用户可读说明、法源引用和相关对象 ID，不保存模型隐藏推理。

## 状态门禁

- `development`：可以运行、测试和生成带显著 AI 声明、状态为 `draft_pending_review` 的草案；不能宣称规则已经完成专业批准，不能给出签署结论。
- `approved`：一名继承领域律师确认规则，另一名律师独立复核，工程测试和黄金案例全部通过后才可设置。

任何法源修改均需更新版本、`authority_checked_at`、规则测试和批准记录。不能只改自然语言说明而保留旧版本号。

## 发布要求

1. 对每条规则建立正向、反向、缺失输入、边界和冲突测试；
2. 用标准、资料缺失、能力疑点、见证人不合格、多份遗嘱、必要份额和协议冲突案例回归；
3. 律师逐条核对法源和结果级别；
4. 独立复核人不参考首位审核人的结论先行判断；
5. 记录差异、修订和最终批准；
6. 发布后监控人工改判率和漏报率。
