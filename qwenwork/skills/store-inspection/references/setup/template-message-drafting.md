# template-message-drafting — Agent 起草派发/提醒消息文案

> 本文件是 Agent 起草并写入 `dispatch_message` + `message_title` 的**行为处方**，
> 仅在收到下文「触发信号」时加载。模板的 CRUD 命令请回到 [03-template.md](./03-template.md)。

---

## 触发信号

**起草触发**：

- 创建模板时未显式指定 `--dispatch-message`（Agent 应主动起草并用 `template update` 补写入）
- "帮我设计一份派发 / 提醒消息文案 / 帮 TPL_xxx 写个文案"
- "我不知道怎么写消息，你帮我起个稿"
- "重新生成 TPL_xxx 的消息模板"

**用户直接提供模板触发**（判断是永久修改还是一次性使用）：

- "用以下格式发送 / 用这个模板发送 / 请使用如下模板派发"
- "巡检标题为：xxx，内容包含 xxx"
- "通知消息用这个：[用户给出的文案内容]"
- 用户在对话中给出了明确的消息内容/格式/结构描述

> [!CAUTION]
> **当用户明确提供了消息模板内容时，Agent 必须区分两种场景**：
>
> **场景 A · 永久修改模板**（用户意图是"以后都用这个格式"）：
> 1. 将用户提供的内容**增强为 Markdown 格式**（加粗、emoji、链接语法等）
> 2. 将合适的动态信息替换为**占位符**（如门店名 → `{门店名称}`、链接 → `[👉 立即填写]({表单链接})`）
> 3. **立即调用 `template update --dispatch-message-file`** 写入模板表
>
> **场景 B · 一次性使用**（用户意图是"这次用这个格式发"但不改模板）：
> 1. 同样增强为 Markdown + 替换占位符
> 2. 写入临时文件，**通过 `dispatch notify --message-override-file` 传入**
> 3. **不写入模板表的 `dispatch_message` 字段**
>
> **判断依据**：
> - 用户说"以后都用这个" / "把模板改成" / "更新消息格式" → 场景 A（永久）
> - 用户说"这次用这个发" / "临时用这个格式" / 仅在派发上下文中提及格式 → 场景 B（一次性）
> - 不确定时 → 默认场景 B（一次性），避免意外修改模板

**修改触发（二次更新）**：

- 用户**明确指出修改点**：如"把电话改成 13800001111"、"加上逾期天数提醒"、"标题改严肃些"、"去掉所有 emoji"、"加一句必须当天 18 点前完成"

## 总原则

> [!IMPORTANT]
> **默认一稿即写入，不主动追问"是否调整"。**
>
> Agent 收集到必要信息（业务场景、占位符）后，**直接起草**一版 `message_title` + `dispatch_message`，
> 在对话里展示给用户**同时立即调用** `template update` 写入。**不再询问"是否需要调整"**。
>
> **二次更新只发生在以下情况**：用户在后续对话中**主动**说出具体修改点（如"加上 xxx"、
> "把 yyy 改成 zzz"、"去掉 emoji"等带有明确修改意图的指令）。此时 Agent 才在已写入版本基础上
> 改动并重新写入，**仍然不询问、不询问"是否调整"**——既然用户已经提了修改点，那就是确认修改。
>
> 本处方覆盖 `dispatch_message` + `message_title` 两个字段；提醒消息无需单独维护
> （messenger 自动复用，详见 `../shared/placeholders.md#提醒消息自动复用派发模板`）。

## 步骤 1 · 必要时收集业务场景（能从上下文推断就跳过）

如果用户的请求里**已经包含足够信息**（如"帮 TPL_xxx 食安督查模板写个严肃点的提醒"），
直接进入步骤 2 起草，**不要再追问**。

只有在**完全没有线索**（如用户只说"帮我写个提醒"）时，才一次性问清以下 2 个最关键要素
（其他细节由 Agent 凭模板名称推断即可，不要逐项追问）：

| 要素 | 取值示例 | 用途 |
| :--- | :--- | :--- |
| **业务场景** | 日常巡检 / 食安督查 / 陈列检查 / 收银盘点 / ... | 决定文案语气基调 |
| **期望语气** | 温和 / 中性 / 严肃 / 紧急（默认中性偏提醒） | 决定开头副词与 emoji |

支持的占位符：见 `../shared/placeholders.md#占位符表中英文等价可混用`，**不要在这里重复占位符表**。

---

## 步骤 2 · 起草 + 立即写入（一次性完成）

Agent 起草后**立刻**调用 `template update` 写入，**不要询问**。
对话里同时给出"草稿 + 渲染预览 + 已写入提示"，让用户一眼看到结果即可。

> [!IMPORTANT]
> **巡店场景必含检查项目**：当模板用于巡店/巡检场景时，Agent **必须**在起草的
> `dispatch_message` 中包含**检查项目**（从模板的 `custom_fields` 中获取所有字段名）。
> 检查项目是店长了解本次巡检需要做什么的关键信息，缺失会导致店长不清楚具体任务内容。
>
> **获取检查项名称**：先通过 `template list` 或 `template get --template-id TPL_xxx`
> 查看模板的 `custom_fields`，提取每个字段的 `name` 属性，列入消息正文。
>
> **示例**：模板 `custom_fields` 为 `[{"name":"门头形象"},{"name":"店内陈列"},{"name":"卫生状况"}]`，
> 则消息中应包含 `- **检查项目**：门头形象、店内陈列、卫生状况`。
>
> 默认模板（`message_defaults.py`）是**通用派发模板**，不含检查项目行。
> 因此在巡店场景下，Agent **应主动起草自定义 `dispatch_message` 并写入模板表**，
> 而不是依赖默认模板。

**输出格式样板**：

````markdown
已为 TPL_xxx 起草并写入派发/提醒消息模板：

### message_title（已写入，派发/提醒共用，提醒第 N 次 N≥2 自动加 `【第N次提醒】` 前缀）
```
⏰ {门店名称} 巡检任务
```

### dispatch_message（已写入，派发/提醒共用同一份正文）
```markdown
### ⏰ 巡检任务

**{店长姓名}** 你好，**{门店名称}** 今天的巡检任务待处理：

- **任务**：{任务名称}
- **任务表**：{任务表名}
- **检查项目**：门头形象、店内陈列、卫生状况
- **截止时间**：{截止时间}

[👉 立即填写]({表单链接})
```

### 渲染预览
（省略，参考 `../shared/placeholders.md#渲染样例用户视角`）

✅ 已写入。如需调整，**直接说出具体修改点**（如"加上电话 13800001111"、"语气改严肃"），
我会在当前版本上改并重新写入。
````

**写入命令**（推荐用 `--dispatch-message-file` 避免 shell 转义长 Markdown）：

```bash
# 1. 把 dispatch_message 正文写入临时文件（跨平台写法，<TEMP> 按系统替换）
printf '%s\n' '### ⏰ 巡检任务' '' '**{店长姓名}** 你好，**{门店名称}** 今天的巡检任务待处理：' '' '- **任务**：{任务名称}' '- **任务表**：{任务表名}' '- **截止时间**：{截止时间}' '' '[👉 立即填写]({表单链接})' > <TEMP>/dispatch_TPL_xxx.md

# 2. 调用 template update（dispatch_message 用 -file 参数，message_title 短可直传）
cd <SKILL_DIR> && uv run python scripts/cli.py template update \
  --template-id TPL_xxx \
  --message-title "⏰ {门店名称} 巡检任务" \
  --dispatch-message-file <TEMP>/dispatch_TPL_xxx.md
```

## 步骤 3 · 写入后反悔 / 回滚

- 用户对已写入的版本不满意 → 等用户**主动说出修改点** → 走步骤 2
  `template update` 是**覆盖式**的，不需要先"撤销"
- 用户希望恢复"系统默认派发 / 提醒文案"（不再自定义）→ 当前 CLI 没有 `--clear-dispatch-message` 参数
  如确有需要，告知用户："本能力暂未提供，可在 `store-inspection-skills-group` 仓库提需求扩展 CLI"
  **严禁** Agent 自行写脚本或直接走 `dws aitable record update` 绕过 CLI
  （违反 `../shared/hard-constraints.md#H2`）

---

## 输出风格规范（所有 Agent 起草都要遵守）

- **务必**给出 `message_title` + `dispatch_message` 两段，并标注"已写入"
- **务必**附带渲染预览（用具体门店 / 店长名字举例），让用户直观感受效果
- **不要**追问"是否需要调整"
- **不要**在文案里编造模板没有的占位符（用了模板里没定义的占位符会原样保留 `{xxx}` 显示给店长）
- 默认控制在 5～10 行 Markdown 内，避免冗长
