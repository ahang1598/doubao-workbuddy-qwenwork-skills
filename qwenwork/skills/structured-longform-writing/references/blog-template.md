# Blog Template

用于博客、技术博客、观点文章、经验总结、教程、指南、公众号文章等长文写作。

## 适用场景

- 用户希望解释一个复杂概念。
- 用户希望输出技术、产品、业务或方法论观点。
- 用户希望把经验沉淀成可读文章。
- 用户希望让读者获得启发、理解或行动建议。

## 不适用场景

- 只需要一段摘要。
- 只需要标题。
- 只需要说明书式操作步骤。
- 纯文学创作。

## 默认结构

```text
1. 标题
2. 开篇 hook：用问题、场景、反差或常见误区引入
3. 核心观点：本文要证明或说明什么
4. 背景：为什么这个问题重要
5. 主体展开：2-4 个分论点，每个分论点包含解释、例子、影响
6. 方法或建议：读者可以如何应用
7. 总结：回到核心观点，给出清晰收束
```

## 可选结构

### 问题驱动型

```text
1. 一个真实问题
2. 为什么常规做法失效
3. 关键原因分析
4. 更好的做法
5. 实践建议
```

### 经验复盘型

```text
1. 背景和目标
2. 初始做法
3. 遇到的问题
4. 调整过程
5. 最终经验
6. 可复用原则
```

### 技术解释型

```text
1. 读者困惑
2. 概念定义
3. 工作机制
4. 示例
5. 常见误区
6. 工程建议
```

## 写作策略

1. 先提炼中心观点，再写正文。
2. 不要以百科式定义开头，优先从读者会遇到的问题切入。
3. 每个分论点都要回答“这对读者有什么用”。
4. 尽量加入具体场景、例子、类比或经验判断。
5. 技术博客可使用代码、流程图或架构图，但必须服务解释。
6. 观点文章要有明确立场，不要两边都说但不下判断。
7. 结尾要收束观点，不要喊口号。

## 常见失败模式

- 开头空泛，像百科定义。
- 全文只有概念堆叠，没有具体场景。
- 标题层级整齐但内容重复。
- 每节都在说“提升效率、改善体验”，没有机制。
- 没有中心观点，读完不知道作者想表达什么。
- 结尾用口号代替总结。

## 输出前检查清单

- 是否有明确中心观点。
- 开篇是否能吸引目标读者。
- 每个分论点是否有解释和例子。
- 是否避免了空泛价值词堆叠。
- 是否像一篇文章，而不是说明书或报告。
- 是否有可迁移的经验或建议。

## 简短示例大纲

主题：《为什么 Agent 长文写作不能只靠一次性 Prompt》

```text
1. 开篇：一次性 Prompt 为什么看起来省事，实际容易失败
2. 核心观点：长文质量来自流程，而不是单轮表达能力
3. 失败原因一：需求不完整，模型只能猜
4. 失败原因二：缺少大纲，结构容易漂移
5. 失败原因三：缺少证据和审稿，内容容易空泛
6. Skill 的价值：把写作拆成 brief、大纲、正文、review
7. 工程建议：为 Agent 建立写作质量门
8. 总结：让 Agent 写好长文，要产品化写作经验
```
