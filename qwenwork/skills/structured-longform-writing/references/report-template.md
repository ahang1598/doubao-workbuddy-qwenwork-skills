# Report Template

用于分析报告、调研报告、竞品分析、现状分析、问题分析、研究总结等文档。

## 适用场景

- 用户需要基于材料形成判断。
- 用户需要解释一个问题的现状、原因、影响和建议。
- 用户需要比较多个对象或方案。
- 用户需要给产品、技术或管理团队提供决策依据。

## 不适用场景

- 纯观点文章。
- 纯执行计划。
- 没有分析目标的资料堆叠。
- 需要严格学术引用但没有提供来源且无法检索的场景。

## 默认结构

```text
1. 摘要：核心结论和建议
2. 背景：为什么要做这份报告
3. 问题定义：要分析的问题是什么，边界是什么
4. 分析框架：从哪些维度分析
5. 事实与材料：用户提供或可验证的信息
6. 关键发现：从事实中得到的发现
7. 原因分析：为什么会出现这些现象
8. 结论：最重要的判断
9. 建议：下一步行动
10. 风险与待补充信息：哪些信息不足，后续如何补齐
```

## 可选结构

### 竞品分析报告

```text
1. 分析目的
2. 对比对象
3. 对比维度
4. 横向对比表
5. 关键差异
6. 对本产品的启发
7. 建议动作
```

### 问题诊断报告

```text
1. 问题现象
2. 影响范围
3. 根因假设
4. 证据检查
5. 主要原因
6. 修复建议
7. 后续验证方式
```

### 调研总结报告

```text
1. 调研背景
2. 调研范围
3. 主要材料
4. 发现一
5. 发现二
6. 发现三
7. 综合判断
8. 建议
```

## 写作策略

1. 报告必须有判断，不只是资料整理。
2. 开头应给核心结论，方便管理层快速阅读。
3. 明确区分事实、判断和推测。
4. 对比型内容优先用表格，但表格之后必须写关键发现。
5. 当没有数据时，不得编造比例、增长率、排名或用户规模。
6. 建议要能对应前文发现，不能凭空出现。
7. 风险和待补充信息要单独说明。

## 常见失败模式

- 只有背景和现状，没有结论。
- 罗列信息很多，但没有分析框架。
- 对比表很长，但没有关键发现。
- 把推测写成事实。
- 建议过于泛泛，例如“加强建设”“持续优化”。
- 没有说明信息不足的地方。

## 输出前检查清单

- 是否有摘要和核心结论。
- 是否定义了分析问题和边界。
- 是否有清晰分析框架。
- 是否区分事实、判断、推测。
- 是否有关键发现。
- 是否有可执行建议。
- 是否避免编造数据和引用。
- 是否列出待补充信息。

## 简短示例大纲

主题：《QoderWork长文写作能力现状与改进方向》

```text
1. 摘要：当前问题和建议方向
2. 背景：用户反馈长文效果不好
3. 问题定义：博客、报告、方案的生成质量不稳定
4. 原因分析框架：需求理解、结构规划、证据处理、审稿机制
5. 关键发现：一次性生成无法稳定满足长文质量要求
6. 竞品经验：Skill 化、流程化、模板和质量门
7. 改进方案：建设结构化长文创作 Skill
8. 风险：业务背景不足、模板泛化、评测样例不足
9. 建议：先 MVP，后扩展文档类型和评测集
```
