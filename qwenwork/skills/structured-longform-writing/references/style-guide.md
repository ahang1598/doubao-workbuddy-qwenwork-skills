# Style Guide

此文件定义结构化长文创作的默认表达风格和受众适配规则。

## 默认中文风格

默认使用专业、清晰、具体、结构化的中文表达。

优先：

- 结论清楚。
- 句子不过度堆叠。
- 标题能表达判断或功能。
- 段落有信息密度。
- 价值表述有对象、机制和结果。

避免：

- 大量口号。
- 过度正式的公文腔。
- 过度对称的标题结构。
- 每段都用“因此、所以、总之”。
- 没有内容的连接词。

## 受众语气差异

### 管理层

写法：结论前置、关注取舍、风险、资源和下一步。

适合结构：摘要、关键判断、建议动作、风险、决策点。

避免：过多实现细节和底层术语。

### 技术人员

写法：准确、具体、可实现。关注约束、架构、模块、调用链路、异常处理、可维护性。

适合结构：目标、约束、设计原则、架构、模块、流程、风险、验证。

避免：只讲价值，不讲机制。

### 产品经理

写法：围绕用户问题、场景、需求边界、优先级、指标和迭代。

适合结构：用户问题、目标、功能范围、用户流程、指标、版本规划。

避免：技术细节过多或方案边界不清。

### 客户

写法：清楚解释价值、成本、交付方式和风险控制。

适合结构：客户问题、解决方案、实施路径、预期效果、保障措施。

避免：内部黑话和未解释的缩写。

### 公众读者

写法：自然、有例子、有解释，不假设读者熟悉内部背景。

适合结构：问题引入、概念解释、案例、建议、总结。

避免：堆砌概念和组织内部术语。

## 标题层级规则

1. 一级标题用于主要结构，不要超过 8 个，除非用户要求非常详尽。
2. 二级标题用于展开关键点，不要机械追求每节数量一致。
3. 标题应尽量表达内容功能或判断，例如“问题不在模型不会写，而在写作流程缺失”。
4. 不要使用过多“背景介绍、现状分析、问题分析、方案设计”的模板标题，除非文档类型需要。

## 段落长度规则

1. 中文长文每段通常控制在 80-180 字，复杂说明可更长。
2. 每段只承担一个主要意思。
3. 如果一个段落包含三个以上并列点，考虑改成列表。
4. 如果连续列表过多，补充解释性段落，避免像提纲。

## 表格、列表和图示

### 使用表格

适合：对比竞品、对比方案、列验收标准、列风险和应对。

不适合：表达复杂推理过程或重要结论。表格后应补充关键判断。

### 使用列表

适合：步骤、检查项、模块、风险、建议动作。

不适合：整篇文章全部用列表堆叠。

### 使用 Mermaid 图

适合：流程、架构、依赖关系、Agent loop。

不适合：只是为了显得复杂。图示必须能减少理解成本。

## 何时简洁，何时展开

应简洁：

- 用户要求快速结论。
- 面向管理层摘要。
- 已知背景充分。
- 内容是清单、步骤或验收标准。

应展开：

- 需要解释复杂概念。
- 需要论证观点。
- 用户材料不完整但可以合理推断。
- 面向外部读者或跨团队读者。

## 默认表达偏好

用“为什么、做什么、怎么做、如何验收”组织方案类文档。

用“事实、发现、判断、建议”组织报告类文档。

用“问题、观点、论证、例子、收束”组织博客类文档。
