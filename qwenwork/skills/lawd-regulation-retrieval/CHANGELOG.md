# CHANGELOG

## v1.3.0 - 2026-08-11

依据 QwenWork 真机测试轮（设计合同法规+GB标准检索场景，普通/高级模型两次执行）整改 4 项：

1. **多主题拆分规则**（Step 2 + references/query-rewrite-prompt.md）：多争议焦点时每个主题单独输出一组标准 JSON，禁止合并为自定义格式；query-rewrite-prompt.md 补多主题示例（示例 5）
2. **时效性主动覆盖**（时效性策略新增第 3 条）：工具时效性入参自带默认值（如默认"现行有效"）时，必须主动传空字符串覆盖取得完整时效性光谱；覆盖失败才按例外声明处理；入参语义映射表交叉引用同步更新
3. **技术标准检索策略**（常见错误表新增行）：GB/IEC/ISO 标准号不走法规结构化检索——语义检索查发布公告 + 检索强制性标准约束条款 + 声明全文需另行获取
4. **检索路由速查表**（Step 3）：多主题/语义模糊/技术标准/废止版本/精确取条五类需求的推荐路径

## v1.2.0 - 2026-08-10

**P0 修复（交付环节此前跑不通）**
- 法条引用格式统一为 `《法规全称》第X条`（书名号 + 条号紧连，支持简称括注、带款项、并列列举），与交付门禁脚本 `scripts/verify_laws.py` 的提取口径对齐；此前法规清单格式为 `### [序号]. [法规名称] [条款编号]`，被脚本提取到 0 条引用而必然触发拦截，合规报告 100% 无法交付。约束原则、法规清单模板、洞察总结提示词、示例 tips 全量统一
- 补齐全流程落盘约定：归一化 JSON 落 `outputs/law-search-<时间戳>.json`，Markdown 交付物落 `outputs/regulation-report-<时间戳>.md`（同时间戳配对）；确立交付顺序「归一化 JSON 落盘 → 生成 md 交付物 → 运行门禁 → 通过后展示/按需转 docx」，门禁此前因无文件可传而必然被跳过
- 落盘退化路径：运行时不允许写中间文件时，改为对话内贴出归一化 JSON 并逐条人工核对引用，且必须显式声明未运行脚本，禁止无声跳过门禁
- 门禁调用统一带 `--require-citations`（本技能交付物按定义即法条清单，零引用必须拦截），仅"本次只命中整部法规、无任何条号"时可去掉并在报告中说明；已按新模板构造样例实测：新格式交付物门禁退出码 0，旧 `[法规名称] [条款编号]` 格式在开启该开关后被拦截

**P1 修复**
- 删除 dws CLI 时代的行为契约残留：「关键词必须英文逗号分隔，中文逗号导致 0 结果」「Query 控制 8-15 字」不再作为铁律，改为按 `qwenwork_mcp_tool_get` 返回的 schema 判定检索类型（语义检索类支持自然语言长句；关键词检索类按其分词规则传短语组合）；references/query-rewrite-prompt.md 同步改写
- 统一空结果重试字数口径（此前 Step 3 写「8 字以内」、异常处理写「8-10 字」），统一为「精简为 2-3 个核心术语、不超过 10 字」，并新增第三步「切换下一家连接器」
- 入参映射表按入参形态分列「扁平入参型 / 嵌套对象型」，覆盖结构化对象（法规名称/条款编号/主题关键词子字段）如何填写，以及该类工具缺失条数、效力级别、发布机关、日期范围、分页入参时的处理（本地筛选/本地截取/多路检索 + 声明能力受限）
- 时效性策略统一为「默认不过滤、全部返回并强制逐条标注」，消除此前「默认按现行有效过滤」与「标注但不过滤」的自相矛盾；工具入参自带不可关闭默认值时保持默认并在「检索说明」声明覆盖范围受限
- references/response-schema.md 新增「时效性枚举映射」表：各家真实枚举（废止或失效/部分废止或失效/已被修改/尚未施行/失效/部分失效/尚未生效/待核实）→ 六值归一化枚举，并新增 `timelinessRaw` 保留原始值

**P2 修复**
- 探测关键词补中文与能力词：`法律法规 / statute / regulation / 北大法宝 / 元典 / 法智`
- `qwenwork_mcp_tool_get` 由「不确定时查看」改为**调用前必须验证 schema**，仅传 schema 支持的参数
- 相似度排序改为条件性：连接器返回相似度时降序，未返回时保持数据源默认相关度顺序并在报告中说明，清单「相似度」字段写「未提供（按数据源默认相关度排序）」
- 删除「加载更多按钮」等无 UI 载体的遗留话术，改为分页/提高条数/换词分批检索/多路检索合并去重
- 参考文件表补入 `scripts/verify_laws.py`；新增「异常处理 → 门禁拦截」分支（不可溯源/未提取到引用/检索说明缺要素的各自处置）

## v1.1.0 - 2026-08-10

- 检索主路径改造：去除原 dws CLI 法规检索命令依赖，改为「法规检索」连接器能力语义写法（三段式探测：qwenwork_mcp_tool_list 探测 → 语义匹配 → qwenwork_mcp_tool_call 调用）
- 参数映射表由原 CLI 参数改为连接器入参语义（查询文本/时效性/效力级别/发布机关/日期范围/返回条数），运行时按工具 schema 适配
- 新增 A 档降级策略：探测不到法规检索连接器时停止执行并提示启用连接器，禁止 WebSearch/记忆编造法条
- 执行门禁与「检索说明」块要求保留（query/keywords/返回条数/执行时间）
- **新增 `scripts/verify_laws.py` 交付前强制门禁**：从交付物提取被引法条并与落盘检索 JSON 逐条比对（防大模型编造法条），同时校验「检索说明」块四要素；退出码非 0 禁止交付
- references/response-schema.md 重构为连接器无关的归一化统一契约，供下游校验脚本消费
