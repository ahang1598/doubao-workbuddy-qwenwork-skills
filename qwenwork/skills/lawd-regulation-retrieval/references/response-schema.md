# 法规检索返回数据结构（统一契约）

不同法规检索连接器的原始返回结构各异。生成洞察总结、落盘检索结果之前，**必须先将检索返回归一化为本文件的统一结构**；下游交付物与校验脚本（如引用法条核对脚本）均以本结构为准。连接器的原始返回可整体保留在 `_raw` 字段备查。

**落盘约定**：归一化结果写入 `outputs/law-search-<时间戳>.json`（时间戳格式 `YYYYMMDD-HHmm`），与 Markdown 交付物 `outputs/regulation-report-<时间戳>.md` 共用同一时间戳，交付前由 `scripts/verify_laws.py` 逐条核验引用溯源。运行时不允许写文件时按 SKILL.md Step 4 的退化路径处理（对话内贴出 JSON 并逐条人工核对，显式声明未跑脚本）。

## 顶层结构

```json
{
  "source": "实际使用的法规检索连接器/工具（如实填写探测到的名字）",
  "query": "本次检索 query",
  "keywords": ["关键词1", "关键词2"],
  "size": 10,
  "searchedAt": "执行时间，如 2026-08-10 14:30",
  "success": true,
  "data": {
    "currentPage": 1,
    "pageSize": 10,
    "totalCount": 200,
    "lawResult": [...]
  },
  "_raw": { }
}
```

顶层说明：

| 字段 | 说明 |
|------|------|
| source / query / keywords / size / searchedAt | 与交付物开头「检索说明」块一一对应，便于核对数据来源 |
| data.totalCount | 归一化后的命中总数；无该信息的连接器填实际返回条数 |
| data.lawResult | 法规/法条结果数组，按相关度（相似度）降序 |

## lawResult 数组元素结构

| 字段 | 类型 | 说明 |
|------|------|------|
| lawDomain | object | 法规详细信息 |
| similarity | string | 相似度/相关度分数；连接器未提供时填 "未提供"，保持连接器返回的相关度排序，并在交付物中说明"本次数据源未返回相似度分数，按数据源默认相关度排序" |

### lawDomain 详细字段

| 字段 | 类型 | 必备 | 说明 | 示例 |
|------|------|------|------|------|
| lawId | string | 建议 | 法规/法条唯一标识，供需要时再调「详情/精确取条」能力 | "b2274825c8c3bc2343ca73680243ddc8" |
| lawName | string | **必备** | 法规名称 | "中华人民共和国民法典" |
| lawOrder | string | **必备** | 条款编号（中文数字格式） | "第二百六十三条" |
| lawTitle | string | 建议 | 条款标题（法规名+条号组合亦可） | "最高人民法院关于常见犯罪的量刑指导意见第二百六十三条" |
| lawSourceContent | string | **必备** | 条款原文内容 | "第二百六十三条 [抢劫罪]以暴力..." |
| issuingOrgan | string | 建议 | 发布/制定机关（取机关名称文本） | "最高人民法院" |
| potencyLevel | string | 建议 | 效力级别（取级别名称文本） | "司法解释" |
| releaseYearMonthDate | string | 可选 | 发布日期 | "2014年01月03日" |
| implementYearMonthDate | string | 可选 | 施行日期 | "2014年01月03日" |
| timeliness | string | **必备** | 时效性，归一化为六值枚举之一（见下方「时效性枚举映射」）：`现行有效` / `已废止或失效` / `部分废止或失效` / `已被修改` / `尚未生效` / `待核实`；原始值一并保留在 `timelinessRaw` | "现行有效" |
| timelinessRaw | string | 建议 | 连接器返回的时效性原始文本，便于溯源与人工复核 | "废止或失效" |
| thematicClassify | string | 可选 | 主题分类 | - |

## 连接器返回 → 统一字段映射

按匹配到的工具实际返回做语义映射（字段名以该工具返回为准）：

| 返回字段语义 | 映射到统一字段 |
|---|---|
| 法规名称/标题 | lawDomain.lawName |
| 条号/条款编号（第X条） | lawDomain.lawOrder |
| 条文原文/法条内容 | lawDomain.lawSourceContent |
| 时效性/效力状态 | lawDomain.timeliness |
| 效力级别/效力位阶 | lawDomain.potencyLevel |
| 发布机关/制定机关 | lawDomain.issuingOrgan |
| 发布日期 / 施行（实施）日期 | lawDomain.releaseYearMonthDate / lawDomain.implementYearMonthDate |
| 相似度/相关度得分 | similarity |
| 法规/法条唯一 ID | lawDomain.lawId |

归一化注意：
1. 连接器返回的嵌套对象（如效力级别、发布机关以对象形式返回）取其名称文本填入对应字段。
2. 仅返回法规列表片段而无条文原文的连接器：展示与引用前，应使用其「详情」或「精确取条（法规名+条号）」能力补齐 lawSourceContent；补齐失败的条目不得引用条文原文。
3. 条号统一为中文数字格式（如"第四十八条"）；连接器返回阿拉伯数字条号（如"第48条"）时转换后写入。

## 时效性枚举映射（真实返回值 → 归一化值）

各家连接器的时效性/效力状态枚举文本不一致，归一化时按语义映射到六值枚举，并把原始文本保留到 `timelinessRaw`：

| 连接器返回的原始值（各家实际枚举合集） | 归一化 `timeliness` | 展示与使用规则 |
|---|---|---|
| `现行有效` | `现行有效` | 可作为现行义务依据 |
| `废止或失效`、`失效`、`已废止`、`已失效` | `已废止或失效` | 必须标注"已废止/失效"，不得作为现行义务依据；仅用于说明历史适用或新旧对比 |
| `部分废止或失效`、`部分失效` | `部分废止或失效` | 必须标注，并提示所引具体条款是否在废止范围内需另行核实 |
| `已被修改` | `已被修改` | 主体仍有效但已修订，必须提示"应以最新修订版条文为准"，引用前建议用「精确取条」复核当前文本 |
| `尚未施行`、`尚未生效` | `尚未生效` | 必须标注生效日期，说明当前尚不可直接适用 |
| `待核实` | `待核实` | **不得作为唯一依据**，须再调「详情/精确取条」或换一家连接器复核后才可引用 |
| 字段缺失/空值 | `未提供` | 标注"数据源未提供时效性"，并提示用户自行核实 |

处置规则：
1. **默认不按时效性过滤**：全部返回并逐条标注（与 SKILL.md「时效性策略」一致）。
2. 工具的时效性入参自带默认值且不可关闭时（如默认只检现行有效），保持默认值并在交付物「检索说明」中声明覆盖范围受限。
3. 用户明确要求某一状态时，把归一化值反向映射回该工具的枚举文本再传入；该工具无对应枚举时改为检索后按 `timeliness` 本地筛选并说明。

## 交付物引用格式（与门禁脚本口径一致）

由归一化结果生成的交付物中，法条引用必须写作 `《法规全称》第X条`（书名号 + 条号紧连，可带款项、可并列列举、可在书名号后括注简称）。`scripts/verify_laws.py` 按该格式提取引用并回溯本文件定义的 `lawName` + `lawOrder`；格式不符会被判为"未提取到任何引用"而拦截交付。门禁读取字段与比对口径详见下方「交付门禁对本结构的硬性要求」。

## 常用展示字段建议

向用户展示时，建议优先使用以下字段：

1. **法规基本信息**：lawName, lawOrder, lawTitle
2. **内容展示**：lawSourceContent
3. **效力信息**：timeliness, potencyLevel
4. **时间信息**：releaseYearMonthDate, implementYearMonthDate
5. **来源信息**：issuingOrgan

## 交付门禁对本结构的硬性要求

交付前必跑的 `scripts/verify_laws.py` 以本结构为唯一判据，逐条核对交付物中的 `《法律名》第X条`：

| 门禁行为 | 说明 |
|---|---|
| 只读法规名专用字段 | `lawName`（兼容 `law_name` / `法规名称` / `法律名称`）；**不读** `name` / `title` 等通用键，避免把无关对象误认为法条记录 |
| 只读条号专用字段 | `lawOrder`（兼容 `law_order` / `articleNumber` / `articleNo` / `条号` / `条款编号`）；**绝不**从 `lawSourceContent`、`lawTitle` 或 JSON 原文里找条号 |
| 法规名比对口径 | 允许有无「中华人民共和国」前缀（`《民法典》` ↔ `《中华人民共和国民法典》`）；不做模糊/部分匹配，`民法典` 不会匹配 `民法典合同编通则司法解释` |
| 条号比对口径 | 中文数字与阿拉伯数字互通（`第五百七十七条` ↔ `第577条`）；`第X条之一` 独立成条，不与 `第X条` 混同；引用中的「第X款/第X项」不参与比对 |
| 契约不合规即阻断 | 若 JSON 中识别不出任何含法规名专用字段的记录，门禁直接报错「检索结果未按归一化契约落盘」并拦截，**不会**降级为宽松/原文匹配放行 |

因此归一化时必须落实：

1. `lawName` 写**完整法规名称**（如「中华人民共和国民法典」），不要写成 `name` / `title`；
2. 引用了具体条文，就必须有对应记录的 `lawOrder`；只取到整部法律（无 `lawOrder`）时，交付物只能谈法律整体，不得写「第X条」；
3. 条文正文里的交叉引用条号（如第五百七十七条正文提到的「第五百九十条」）**不构成**已检索条文，需引用时必须另行检索取条。
