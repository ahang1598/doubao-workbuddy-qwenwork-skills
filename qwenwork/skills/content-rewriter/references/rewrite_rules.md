# 改写 / 扩写 / 缩写 操作规则

## 改写

**目标**：保留原文的全部核心信息和立场，用不同的表达方式重新呈现。

### 执行规则

1. **语义守恒**：每一个核心观点、事实、数据必须出现在改写版本中，不得增减。
2. **结构可调**：可以调整段落顺序、合并或拆分句子，但不得改变论证逻辑的走向。
3. **表达替换层级**（由浅到深，根据用户需求选择）：
   - 词汇替换：同义词、近义词替换，句式保持不变
   - 句式重构：主被动互换、长短句调整、并列/递进关系重组
   - 段落重组：调整信息呈现顺序，但保持段落间逻辑关系
4. **禁止引入**：不得加入原文没有的背景信息、观点或例子。
5. **长度控制**：改写后篇幅应与原文相近（±20%以内），除非用户另有要求。

### 常见改写策略

| 原文特征 | 改写策略 |
|---------|---------|
| 被动语态偏多 | 转为主动语态，主语前置 |
| 长句堆叠 | 拆分为短句，用连接词明确关系 |
| 短句碎片化 | 合并为长句，用从句或并列结构整合 |
| 定义式开头 | 改为场景式或问题式开头 |
| 总结式结尾 | 改为判断式或开放式结尾 |

## 扩写

**目标**：在保留原文全部信息的基础上，增加内容密度，使表达更完整、更有说服力。

### 执行规则

1. **原文优先**：原文的每一句话都必须在扩写版本中有所体现，不得删减。
2. **扩展方向**（默认按以下优先级选择，用户可指定）：
   - **补充背景**：为原文的核心概念或场景提供更多上下文
   - **增加细节**：用具体描述替换抽象表述（数字、案例、过程步骤）
   - **强化论据**：为判断句补充支撑依据或对比参照
   - **补充示例**：用具体例子说明抽象原则
   - **展开推论**：把原文点到即止的结论往下推一步
3. **扩展内容必须与原文逻辑一致**：不得引入与原文立场矛盾的内容。
4. **不得无效扩写**：重复原文意思、堆砌同义词、加入套话都不算扩写。

### 扩写量级参考

| 用户指令 | 扩写目标 |
|---------|---------|
| 未指定 | 原文的 1.5-2 倍 |
| "稍微展开" | 原文的 1.2-1.5 倍 |
| "详细展开" | 原文的 2-3 倍 |
| 指定字数 | 以指定字数为准 |

### 扩写质量标准

- 每个扩展段落必须服务于原文的某个核心观点
- 新增内容应有具体锚点（时间、数字、案例名称），避免空泛
- 扩写后的结构应比原文更清晰，而不是更混乱

## 缩写

**目标**：在保留原文核心信息的前提下，减少篇幅，提升信息密度。

### 执行规则

1. **核心信息守恒**：原文的主要论点、关键数据、核心结论必须保留。
2. **删除优先级**（先删低价值内容）：
   - 重复表达：同一意思说了两遍的，保留更精准的那一遍
   - 过渡语句：纯起到"承上启下"作用、不含实质信息的句子
   - 修饰堆叠：多个形容词/副词修饰同一对象时，保留最关键的一个
   - 背景铺垫：读者已知的常识性背景，可大幅压缩或删除
   - 举例说明：如果原则已经清晰，可删除部分例子（保留最典型的一个）
3. **不得删除**：
   - 用户明确标注"必须保留"的内容
   - 唯一支撑某个核心论点的数据或事实
   - 文章的立场和结论
4. **结构保持**：缩写后应保持原文的段落逻辑，不得打乱论证顺序。

### 缩写量级参考

| 用户指令 | 缩写目标 |
|---------|---------|
| 未指定 | 原文的 50-60% |
| "稍微精简" | 原文的 70-80% |
| "大幅压缩" | 原文的 30-40% |
| 指定字数 | 以指定字数为准 |

### 缩写质量标准

- 缩写后的文本应能独立成文，不依赖原文才能理解
- 每个保留的段落都应有明确的存在理由
- 不得因为追求字数而删除关键判断句
