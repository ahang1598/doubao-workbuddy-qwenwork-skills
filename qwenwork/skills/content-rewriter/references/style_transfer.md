# 风格语气迁移规则

## 核心原则

风格迁移只改表达层，不改内容层。

- **保持不变**：原文的核心信息、数据、立场、结论
- **允许改变**：句式结构、词汇选择、段落节奏、语气强度、修辞方式

---

## 常用风格库

### 正式程度维度

| 风格标签 | 特征 | 典型场景 |
|---------|------|---------|
| **正式/商务** | 完整句式、被动语态适度使用、避免口语词、段落结构严整 | 报告、方案、对外沟通 |
| **中性/专业** | 清晰直接、主动语态为主、技术词汇准确、不过度修饰 | 技术文档、产品说明 |
| **轻松/口语** | 短句多、第一人称、口语词（"其实""说白了""你懂的"）、句末可用语气词 | 公众号、社交媒体 |
| **亲切/对话** | 直接称呼读者（"你""我们"）、提问句多、像和朋友说话 | 用户沟通、品牌文案 |

### 情感色彩维度

| 风格标签 | 特征 | 典型场景 |
|---------|------|---------|
| **客观/中立** | 无情感词、陈述事实、避免主观判断 | 新闻、报告 |
| **积极/鼓励** | 正面词汇、强调可能性和机会、句式倾向肯定 | 激励文案、产品推广 |
| **批判/犀利** | 直接指出问题、不回避矛盾、判断句强硬 | 评论、分析文章 |
| **温和/委婉** | 软化表达（"可能""也许""建议"）、避免绝对化表述 | 反馈、建议、外交沟通 |

### 行业/场景风格

| 风格标签 | 特征 |
|---------|------|
| **学术** | 文献引用式表达、定义严谨、逻辑推导显式、被动语态多 |
| **法律** | 条款式结构、精确限定语（"在……情况下""不得……"）、无歧义 |
| **营销/文案** | 利益点前置、动词有力（"解锁""突破""重新定义"）、情感共鸣 |
| **技术/工程** | 步骤清晰、术语准确、数字具体、结论可验证 |
| **新闻** | 倒金字塔结构、5W1H、无立场、引用来源 |

## 执行步骤

### 第一步：识别目标风格

用户可能用以下方式表达目标风格：
- 直接命名："改成商务风""改成口语化"
- 场景描述："改成适合发朋友圈的""改成适合写进报告的"
- 对标对象："改成像XX公众号的风格""改得像新闻稿一样"
- 语气描述："改得更强硬一点""改得更委婉一点"

如果目标风格不明确，询问：**"你希望改成哪种风格或语气？"**（给出上面的风格标签供选择）

### 第二步：分析原文风格

记录原文当前的风格特征（内部分析，不展示）：
- 正式程度（正式 / 中性 / 口语）
- 情感色彩（客观 / 积极 / 批判 / 温和）
- 句式特征（长句 / 短句 / 混合）
- 人称使用（第一 / 第二 / 第三人称）

### 第三步：确定迁移操作清单

根据原文风格 → 目标风格的差距，列出需要做的具体改动：

| 迁移方向 | 典型操作 |
|---------|---------|
| 正式 → 口语 | 拆长句、加第一人称、替换书面词为口语词、加语气词 |
| 口语 → 正式 | 合并短句、去语气词、替换口语词为书面词、补完整句式 |
| 中性 → 积极 | 替换中性动词为积极动词、句末加肯定判断、突出收益 |
| 积极 → 客观 | 去情感词、改判断句为陈述句、数据支撑替代形容词 |
| 柔和 → 犀利 | 去软化词、判断句直接给结论、不回避矛盾 |
| 犀利 → 委婉 | 加限定语、判断句改为建议句、避免绝对化表述 |

### 第四步：执行迁移

逐段处理，保持以下不变：
- 段落逻辑顺序
- 核心论点和数据
- 专有名词（人名、产品名、术语）

---

## 组合风格处理

用户可能要求组合风格（如"专业但不失亲切""正式但口语化"）。

处理原则：
1. 识别主风格（权重更高的那个）
2. 识别修饰风格（作为调节方向）
3. 主风格定结构和词汇，修饰风格调节语气强度

示例："专业但亲切" = 专业（主）+ 亲切（修饰）
→ 保留技术准确性和完整句式，但增加第二人称、缩短部分句子、减少被动语态

---

## 风格迁移的边界

以下情况需要提前告知用户：

- **原文信息密度过低**：风格迁移后可能显得更空洞，建议先扩写再迁移
- **原文含大量专业术语**：迁移为口语风格时，部分术语无法替换，会保留原词
- **目标风格与原文立场冲突**：如原文是批判性的，改成"积极鼓励"风格会改变立场，这超出风格迁移的边界，需用户确认
