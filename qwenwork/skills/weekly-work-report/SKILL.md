# 工作周报

基于钉钉生态，从当周**日程、任务、听记、云文档**四大数据源自动提取工作内容，多维分析后生成结构化的钉钉在线文档周报。

---

## 禁止事项

- 禁止以对话文本替代钉钉在线文档作为最终交付物
- 禁止编造任何工作内容、会议记录或任务信息
- 禁止在有钉钉原生工具可用时使用外部搜索替代内部数据
- 禁止将 `knowledge` 补充的信息覆盖 MCP 工具返回的事实数据
- 禁止在未获取任何数据的情况下直接生成周报

---

## 强制要求

- 本技能触发即代表用户期望生成钉钉在线文档，无需询问
- 草稿文件路径必须动态化：`/home/workspace/draft_weekly-report_{week_start_date}_{HHMMSS}.md`
- 统计区间标注必须正确：`{week_start_date}（周一）~ {week_end_date}（周日）`
- 所有工作内容必须来自草稿文件，不得在生成阶段凭空添加
- 每类数据必须有「洞察」小节，不得只罗列原始数据
- MCP 工具调用失败时，使用 `knowledge` 兜底，并在周报末尾注明「该来源暂无数据」

---

## 能力清单

| 工具 | 用途 | 说明 |
|------|------|------|
| `dws calendar event list` | 获取当周日程/会议事件 | 提取会议名称、参与人、时间 |
| `dws todo` | 获取任务列表及完成状态 | 已完成/进行中/逾期任务 |
| `dws minutes get/list` | 获取会议听记摘要 | 关键决策、Action Items |
| `dws doc search` | 搜索当周创建/更新的文档 | 关键词含当周日期 |
| `dws doc read` | 读取关键文档详情 | 提取核心内容摘要 |
| `knowledge` | 内部知识库兜底 | 补充 MCP 工具遗漏的工作信息 |
| `dws doc create` | 生成钉钉在线文档 | 直接输出周报，无需 Writer Agent |

---

## 工作流

```
用户输入（可选：指定周次或日期范围）
    |
    v
  Phase 1 — 时间范围确认
  → 解析目标周的起止日期（周一 ~ 周日）
  → 转换为时间戳（UTC+8）
    |
    v
  Phase 2 — 数据采集（5个并行子任务）
  ┌─────────────────────────────────────────────────────┐
  │ A1: dws calendar → 日程/会议列表                      │
  │ A2: dws todo → 任务列表（已完成/进行中）               │
  │ A3: dws minutes → 听记摘要                           │
  │ A4: dws doc search → 当周文档                        │
  │ A5: knowledge → 兜底补充                             │
  └─────────────────────────────────────────────────────┘
  每步完成后追加写入 draft_weekly-report_{week_start_date}_{时间戳}.md
    |
    v
  Phase 3 — 汇总分析
  → 去重合并多来源重叠信息
  → 按周报结构归类
  → 每类提炼洞察
    |
    v
  Phase 4 — 生成周报
  → 读取 draft.md 全部素材
  → dws doc create 生成钉钉在线文档
    |
    v
  钉钉在线文档工作周报（含链接）
```

---

## Phase 1 — 时间范围确认

**目标**：确定目标周的精确起止时间。

**解析规则**：
- 「本周」/ 无指定 → 当前自然周（周一 00:00:00 至周日 23:59:59）
- 「上周」→ 上一自然周
- 「YYYY-MM-DD 那周」→ 包含该日期的自然周
- 「第 N 周」→ 当年第 N 周

**时间戳转换**（UTC+8）：
```
week_start_date = 目标周周一日期（YYYY-MM-DD）
week_end_date = 目标周周日日期（YYYY-MM-DD）
start_ts = week_start_date 00:00:00 → Unix 时间戳（毫秒）
end_ts = week_end_date 23:59:59 → Unix 时间戳（毫秒）
```

**初始化草稿文件**：
```
file_path = /home/workspace/draft_weekly-report_{week_start_date}_{HHMMSS}.md
写入：# 周报草稿 · {week_start_date} ~ {week_end_date}
     生成时间：{YYYY-MM-DD HH:MM:SS}
```

---

## Phase 2 — 数据采集

> **执行策略**：5个子任务可并行执行，但每个子任务完成后立即追加写入草稿文件。任何子任务失败，使用 `knowledge` 兜底，并记录失败原因。

### A1. 日程获取

**工具**：`dws calendar event list`

**调用方式**：
```
dws calendar event list \
  --start "{week_start_date} 00:00:00" \
  --end "{week_end_date} 23:59:59"
```

**提取字段**：会议名称、开始时间、时长、参与人、会议链接

**写入草稿**：
```markdown
## A1. 日程数据

| 日期 | 时间 | 会议名称 | 时长 | 关键参与人 |
|------|------|---------|------|-----------|
| {date} | {time} | {title} | {duration} | @XX, @XX |
| ... | ... | ... | ... | ... |

### 日程洞察
- 本周共 {N} 场会议，合计约 {X} 小时
- 高频会议类型：{类型}
- 主要协作对象：@XX, @XX
```

---

### A2. 任务获取

**工具**：`dws todo`

**调用方式**：
```
# 获取当周任务
dws todo --start "{week_start_date}" --end "{week_end_date}"
```

**提取字段**：任务标题、状态（已完成/进行中/逾期）、优先级、截止时间

**写入草稿**：
```markdown
## A2. 任务数据

### 已完成
| 任务名称 | 完成时间 | 优先级 |
|---------|---------|--------|
| {task} | {date} | P{N} |

### 进行中
| 任务名称 | 截止时间 | 进度 |
|---------|---------|------|
| {task} | {date} | {%} |

### 逾期
| 任务名称 | 原截止时间 | 说明 |
|---------|-----------|------|
| {task} | {date} | {reason} |

### 任务洞察
- 本周完成 {N} 个任务，完成率 {%}
- 进行中 {N} 个任务，逾期 {N} 个
```

---

### A3. 听记获取

**工具**：`dws minutes list all` + `dws minutes get summary`

**调用方式**：
```
# 列出当周听记
dws minutes list all \
  --start "{week_start_date}" \
  --end "{week_end_date}"

# 获取每条听记摘要
dws minutes get summary --id "{minutes_id}"
```

**提取内容**：会议主题、日期、关键决策、Action Items、参与人

**写入草稿**：
```markdown
## A3. 听记数据

### 听记列表

#### {会议名称}（{日期}）
- **关键决策**：
  1. ...
  2. ...
- **Action Items**：
  - [ ] {任务} — Owner: @XX — Due: {date}
  - [ ] {任务} — Owner: @XX — Due: {date}
- **参与人**：@XX, @XX

### 听记洞察
- 本周 {N} 场会议有听记，覆盖会议率 {%}
- 产生 Action Items {N} 条，已关闭 {N} 条
```

---

### A4. 文档获取

**工具**：`dws doc search`

**调用方式**：
```
# 搜索当周创建的文档
dws doc search --keyword "" --start-time "{start_ts}" --end-time "{end_ts}"

# 对关键文档深度读取
dws doc read --node "{nodeToken}" \
  --prompt "提取文档核心内容，100字以内"
```

**写入草稿**：
```markdown
## A4. 文档数据

### 当周文档产出
| 文档标题 | 类型 | 创建时间 | 链接 |
|---------|------|---------|------|
| {title} | {type} | {date} | [查看]({url}) |

### 关键文档摘要
#### {文档标题}
- 创建时间：{date}
- 核心内容：{100字摘要}
- 文档链接：[查看]({url})

### 文档洞察
- 本周产出 {N} 篇文档
- 主要类型：{type}
- 高频主题：{topic}
```

---

### A5. knowledge 兜底

**工具**：`knowledge`

**调用时机**：A1-A4 完成后执行，补充可能遗漏的工作信息。

**查询策略**：
```
knowledge(query: "{当前用户}本周（{week_start_date}至{week_end_date}）的主要工作内容")
knowledge(query: "{当前用户}本周的关键产出和进展")
knowledge(query: "{当前用户}本周的会议和协作情况")
```

**使用规则**：
- 以 A1-A4 的 MCP 数据为准，knowledge 仅作补充
- 若 knowledge 与 MCP 数据冲突，以 MCP 数据为准
- 补充信息写入草稿时标注「来源：knowledge」

---

## Phase 3 — 汇总分析

> 将 Phase 2 的多来源数据去重合并，按周报结构归类，每类提炼洞察。

### 去重规则

- 同一会议在日历（A1）和听记（A3）中均有记录 → 合并，以听记为主，日历信息补充时间/参与人
- 同一任务在任务列表（A2）和文档（A4）中均有提及 → 合并，以任务列表为主，文档链接作为附件
- knowledge 与 MCP 数据重叠 → 保留 MCP 数据，knowledge 补充新增信息

### 周报结构归类

将所有数据归入以下周报章节：

```
📌 核心产出（本周最重要的 3-5 项成果）
📊 数据概览（任务/文档/会议统计数字）
📅 日程回顾（重要会议及决策）
✅ 任务进展（已完成/进行中/逾期）
🎙️ 会议纪要摘要（重要听记 Action Items）
📄 文档产出（本周创建/更新的文档）
⚠️ 风险与阻塞（需关注的问题）
📋 下周计划（基于进行中任务和 Action Items 推断）
📎 附录（数据来源说明）
```

## Phase 4 — 生成周报

主 Agent 完成 Phase 2-3 后，直接调用 `dws doc create`：

```
dws doc create \
  --name "工作周报 · {week_start_date} ~ {week_end_date}" \
  --markdown "{按周报模板填入的完整内容}"
```

**周报模板**：


## 易混淆场景

| 场景 | 本技能行为 | 注意 |
|------|----------|------|
| 用户要求「日报」 | 本技能不处理日报 | 说明「本技能仅支持周报」 |
| 数据源全部返回空 | 说明无数据，不生成空白周报 | 引导用户确认时间范围 |
| 任务数量过多（>50项） | 按优先级筛选 Top 20，其余归入「其他」 | 说明筛选标准 |
| 用户补充了额外信息 | 将用户提供的信息写入草稿，与 MCP 数据合并 | 用户信息优先级高于 knowledge |

---

## 错误处理

| 错误情况 | 处理方式 |
|---------|---------|
| `dws calendar` 调用失败 | 标注「日历数据暂无」，knowledge 兜底 |
| `dws todo` 调用失败 | 标注「任务数据暂无」，knowledge 兜底 |
| `dws minutes` 调用失败 | 标注「听记数据暂无」，knowledge 兜底 |
| `dws doc search` 无结果 | 标注「本周无文档产出记录」 |
| 所有数据源均失败 | 停止执行，提示用户手动提供工作内容 |
| `dws doc create` 失败 | 将完整 Markdown 输出到对话，提示用户手动创建 |
