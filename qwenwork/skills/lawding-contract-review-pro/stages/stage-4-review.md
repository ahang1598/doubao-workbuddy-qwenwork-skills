# 阶段四：执行四层审查

> **你接收到的上游数据：** 阶段三产物 JSON（含 contract_type, type_scenario, checklist, review_scope, fallback_flag, loaded_references）。阶段二产物 JSON（可选；含 overall_risk_level 和 counterparty_risks 数组，若 overall_risk_level 非 null 则影响本阶段审查策略）。
> **你需要产出的下游数据：** 阶段四产物 JSON（格式见 SKILL.md）。

> **⚠️ 相对方主体风险对审查策略的影响：**
> 如果阶段二产物中 `overall_risk_level` 为**"中风险"或"高风险"**，在步骤 2-5 的审查中必须对以下条款**提升审查优先级**，即使原风险模板中未将其列为重点：
>
> - **付款/收款条款**：付款节奏、预付比例、付款条件是否充分保护我方
> - **担保/保证金条款**：是否要求对方提供履约担保、保证金或第三方担保
> - **违约责任条款**：违约金是否足以覆盖实际损失，是否有加速到期条款
> - **解除/终止条款**：我方是否有充分的单方解除权，解除后的清算安排
> - **争议解决条款**：是否有利于我方快速采取法律行动（如财产保全）
>
> 若上述条款在合同中**缺失**，应标记为"重要"级别缺失（即使通常仅为"一般"级别）。
> 若上述条款已存在但**保护力度不足**，风险等级应至少提升一级。

## 步骤 1：占位符识别（预处理）

在开始审查前，先识别合同中的待填空白。以下内容视为"有意预留"，**不计入风险**，仅在最终产物的 `placeholders` 列表中统一记录：

| 占位符类型 | 示例 |
|-----------|------|
| 下划线占位 | `___`、`______` |
| 方括号占位 | `[日期]`、`[金额]`、`[ ]` |
| 括号标注 | `（待填）`、`（另行确定）` |
| 数字占位 | `XX`、`×× 元`、`XX天` |

**操作：** 扫描合同全文，将所有占位符记入 `placeholders` 列表，格式如下：

```json
{"location": "第X条", "content": "XX天", "suggestion": "填写具体天数，建议不少于30日"}
```

## 步骤 2：基础层审查

### 第一步：完整性核查（逐项勾选）

对照阶段二的 `checklist`，**逐项**执行以下判断表：

| 判断条件 | 结论 | 操作 |
|---------|------|------|
| 合同中有专门条款约定该事项，且包含具体权利义务内容 | ✅ 已检 | 进入第二步逐条分析 |
| 仅在前言/背景/定义中提及该事项，但无实质权利义务约定 | ❌ 缺失 | 记入 `missing_clauses` |
| 合同中完全没有涉及该事项 | ❌ 缺失 | 记入 `missing_clauses` |

**完整性核查输出格式：**

```json
{"check_item": "标的", "status": "已检/缺失", "clause_location": "第X条（如已检）"}
```

> 如完整性核查发现缺失争议解决/管辖条款，且阶段二未加载 `jurisdiction-review-rules.md`，此时加载。

### 第二步：逐条分析（查表式审查）

对合同中已存在的条款，**从已加载的风险模板中查找对应风险点**，按判定条件匹配：

**审查操作流程：**

1. 读取条款内容
2. 在风险模板中找到该条款类型对应的判定表
3. 逐条检查判定条件是否命中
4. 命中则记录风险，未命中则该条款无风险

**风险等级映射表：**

| 风险模板等级 | findings.level 值 | 处理方式 |
|-------------|-------------------|---------|
| 致命风险 | 致命 | 必须修改，否则不建议签署 |
| 重要风险 | 重要 | 建议修改 |
| 一般风险 | 一般 | 视情况修改 |
| 轻微瑕疵 | 轻微 | 可选修改 |

**category 判定表：**

| category | 判定条件 | 后续呈现方式 |
|----------|---------|-------------|
| `tc` | 能给出具体的替换文本（原文有明确错误或不规范表述） | 修订标记 + 批注 |
| `comment_only` | 仅风险提示，无法给出确定替换（如商业风险、法律风险提示） | 仅批注 |
| `tc_insert` | 缺失的关键条款（来自 missing_clauses） | 插入新段落 + 批注 |

## 步骤 3：商业层审查

参照已加载的 `review-methodology.md` 中"商业层审核"检查项，按以下表格逐项检查：

| 检查项 | 判定条件 | 风险等级 |
|-------|---------|---------|
| 权利义务分配 | 我方义务明显多于权利，或对方权利明显多于义务 | 重要风险 |

| 标的交付 | 交付条件不明确，或交付风险全部由我方承担 | 重要风险 |

## 步骤 4：法律层审查

参照 `review-methodology.md` 中"法律层审核"检查项，按以下表格逐项检查：

| 检查项 | 判定条件 | 风险等级 |
|-------|---------|---------|
| 法律法规符合性 | 条款内容违反法律强制性规定（如约定排除法定责任） | 致命风险 |
| 公序良俗 | 条款内容违背公序良俗（如约定违法用途） | 致命风险 |
| 效力风险 | 条款可能导致合同无效或部分无效（如格式条款未提示说明） | 致命风险 |
| 违约责任-完整性 | 仅约定我方违约责任，对方违约责任缺失 | 重要风险 |
| 违约责任-对等性 | 我方违约责任明显重于对方 | 重要风险 |
| 担保安排 | 担保方式不符合法律规定（如公司对外担保未经决议） | 重要风险 |
| 争议解决 | 管辖约定无效或不明（如同时约定仲裁和诉讼） | 重要风险 |

发现记入 `findings` 列表，`layer` 字段标记为 `"法律层"`。

## 步骤 6：首尾与附件审查

如阶段三已加载 `references/general-structure-rules.md`，对照该文件执行通用结构审查。

**审查范围：**
- 合同名称与交易实质是否一致
- 首部主体信息、主体简称、授权代表权限是否清晰
- 前言/鉴于条款是否与正文交易结构冲突
- 签署栏主体、签署日期、签订地点是否存在可判断风险
- 正文引用附件与实际附件是否对应
- 附件效力、附件优先顺序、正文与附件冲突是否明确

**输出控制：**
- 影响主体识别、授权、核心附件或交易结构的，记入 `findings`，`layer` 字段标记为 `"基础层"` 或 `"法律层"`。
- 签署习惯、骑缝章、面签录像、手写日期等内控建议，除非合同文本中存在明确缺失或冲突，不单独作为 finding。
- 附件缺失导致核心条款无法确定的，记入 `missing_clauses` 或 `findings`，风险等级至少为 `"重要"`。

## 步骤 7：微观文本质量审查

如阶段三已加载 `references/general-micro-review.md`，对照该文件执行文本质量审查。

**审查范围：**
- 错别字、漏字、重复字
- 语句不通、句意不明、指代不明
- 金额大小写不一致、分项合计不一致
- 日期、期限、起算点前后冲突
- 条款编号引用错误或不存在
- 主体名称/简称混用
- 权利义务前后矛盾
- 正文与附件冲突
- 生效、终止、解除条款之间冲突

**输出控制：**
- 标准审核：错别字、标点、格式类轻微问题以原文批注为主；审核意见书只汇总数量或典型例子，不进入重大风险汇总。
- 标准审核：金额、日期、主体、附件、权利义务冲突等影响履行或解释的问题，应记入 `findings`。
- 深度审核：可展开轻微瑕疵、格式统一和表达精修。
- 快速审核：仅在用户明确要求或该问题影响签署决策时输出。

## 步骤 9：关键字提取操作规程（强制执行）

> **⚠️ 关键字准确性直接决定原文批注版的成败。**
> 以下字段的值将被脚本用于在原文中做**字符串匹配**。如果内容与原文有任何偏差（哪怕一个标点不同），批注和修订标记都将无法插入。

**必须从合同原文中逐字复制的字段：**
- `findings[].keyword`：定位关键字（10-20字连续片段）
- `findings[].old_text`（仅 `tc` 类）：需要替换的原文片段（10-30字）
- `missing_clauses[].anchor_keyword`：插入位置的锚点关键字

### 强制操作步骤（每条 finding 必须执行）

**步骤 9.1：定位**
在合同原文中找到对应条款位置

**步骤 9.2：复制条款编号（如有）**
- 有条款编号 → 复制"第X条"或"X.X"作为 keyword 的一部分
- 无条款编号 → 复制段落开头 5-10 字

**步骤 9.3：复制关键字**
- 复制连续 10-20 字的原文片段
- 优先选择：条款编号 + 前几个字（如 `"9.1由乙方原因"`）
- **禁止跨段落**：keyword 和 old_text 不能包含换行符 `\n`

**步骤 9.4：验证**
将复制的关键字与原文逐字比对，确保无任何差异

### 禁止事项

| 禁止行为 | 错误示例 | 正确做法 |
|---------|---------|---------|
| 凭记忆复述 | 把"逾期付款的"写成"逾期付款" | 逐字复制原文，包括"的"、"了"等虚词 |
| 概括改写 | 把"每日按未付金额的0.5%"写成"日0.5%" | 保持原文表述，不做任何修改 |
| 跨段落复制 | old_text 包含多个段落的内容 | 每条 old_text 只包含单个段落 |
| 使用模糊定位 | keyword 为"付款条款"等泛指 | 使用条款编号 + 具体文字

### 正确示例

```
原文："逾期付款的，每日按未付金额的0.5%支付违约金"

✅ 正确 keyword："逾期付款的，每日按"
✅ 正确 old_text："每日按未付金额的0.5%支付违约金"

❌ 错误 keyword："逾期付款条款"（不是原文）
❌ 错误 old_text："日0.5%支付违约金"（丢失"每日按未付金额的"）
```

## 步骤 10：审查质量自检

进入阶段四之前，逐项确认以下检查表：

| 检查项 | 确认方式 |
|-------|---------|
| 检查表（checklist）每项都已判定为"存在"或"缺失"？ | 查看完整性核查输出 |
| 所有 findings 都已映射到四个风险等级之一？ | 检查 level 字段 |
| 所有 findings 都已标记 category（tc / comment_only / tc_insert）？ | 检查 category 字段 |
| 所有修改建议的措辞是否符合已加载的法律语言规范？ | 对照语言规范检查 |
| 所有 findings 的 keyword、old_text 是否从合同原文中逐字复制？ | 执行步骤 9.4 验证 |
| 用户的特殊关注点（如有）已专项回应？ | 检查 special_concern_responses |
| 占位符已单独归集到 placeholders，未混入 findings？ | 检查两个列表无交叉 |
| 若相对方为中/高风险，履约保障类条款已做重点审查？ | 检查相关条款 findings |
| 若加载了通用首尾审查，合同名称、主体、签署栏、附件一致性已检查？ | 检查 findings/missing_clauses |
| 若加载了通用微观审查，金额日期冲突、条款引用、主体简称、文字质量已检查？ | 检查 findings/comment_only |

**如有不通过项，返回补充后再进入阶段五。**

## 步骤 11：整理阶段四产物

按 SKILL.md 中定义的阶段四产物 JSON 格式整理所有数据。

**关键字段硬性约束：**

| 字段 | 来源 | 说明 |
|------|------|------|
| `findings[].keyword` | 从原文逐字复制 | 10-20字连续片段 |
