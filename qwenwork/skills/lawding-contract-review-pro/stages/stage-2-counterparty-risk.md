# 阶段二：相对方主体风险查询 (Counterparty Risk Check)

> **你接收到的上游数据：** 阶段一产物 JSON（含 contract_file, user_position, skip_counterparty_check 等）。
> **你需要产出的下游数据：** 阶段二产物 JSON（格式见下方）。

相对方的主体状态会影响审查重点和签署建议，在加载方法论前先完成查询。

> **⚠️ 本阶段仅在对话中向用户展示风险速览，不生成文件。查询结果将在阶段五纳入审核意见书和解读报告。**

**跳过判断（优先级从高到低）：**
1. 阶段一产物中 `skip_counterparty_check` 为 `true`（用户主动选择跳过）→ 直接跳过，`skip_reason: "用户选择跳过"`
2. 步骤 1 无法提取有效企业名称 → 跳过

---

## 步骤1：提取相对方名称

从阶段一的合同摘要中，识别"非我方"的签约主体名称。

以下情况直接跳过本阶段，继续阶段三：
- 无法提取名称（合同中无明确主体信息）
- 名称明显虚拟（如仅写"甲方"、"XX公司"、`___` 占位符、"某某有限公司"等）
- 名称为自然人（非企业主体）

原则：宁可跳过，不胡编乱造。

## 步骤2：调用天眼查 MCP

尝试调用 `mcp__tianyancha__search_companies`（用相对方名称作为关键词）：

- **工具不存在**：询问用户是否现在配置（引导访问 https://mcp.tianyancha.com/ 获取 API Key，参照 `lawding-company-info` skill 安装流程写入 `~/.claude/.mcp.json`）；不配置则跳过，继续阶段三
- **调用失败**（key 过期/网络问题）：降级用 WebSearch 搜索企业名称；有结果则生成简版风险速览并标注"来源：公开网络检索，信息可能不完整"；无结果则提示"已跳过主体风险查询"，继续阶段三
- **调用成功**：进入步骤3

## 步骤3：查询主体信息

**并行调用**以下天眼查接口：
1. `mcp__tianyancha__get_company_info(company_id)` — 工商信息（经营状态、注册资本、实缴资本、成立日期、经营范围）
2. `mcp__tianyancha__get_company_risks(company_id, risk_type="自身风险")` — 自身风险（诉讼、处罚、失信等）

**搜索结果校验：**
- 搜索无结果 → 跳过，在意见书中提示："合同载明的相对方主体名称未查询到对应企业信息，建议核实主体名称准确性"
- 搜索返回多条结果 → 展示列表让用户确认目标企业

## 步骤4：生成主体风险速览

在对话中展示简洁的风险速览，聚焦两个维度：

**维度一：主体资质风险**
- 经营状态是否正常（存续/在营 vs 吊销/注销/清算）
- 成立时间（过短可能履约能力不足）
- 注册资本 vs 实缴资本（与合同金额对比）
- 经营范围是否覆盖合同标的

**维度二：履约能力风险**
- 失信被执行人记录
- 严重违法记录
- 经营异常名录
- 破产/强制清算信息
- 被诉记录（频次和类型）
- 行政处罚记录

**对话中展示格式：**

```
⚠️ 相对方主体风险速览

企业名称：XX有限公司
经营状态：存续 ✅
成立时间：2015-03-20（运营11年）
注册资本：500万 / 实缴：500万
经营范围匹配：✅ 覆盖合同标的

风险提示：
- 失信被执行人：无 ✅
- 经营异常：无 ✅
- 自身风险：2条 ⚠️（1条开庭公告、1条裁判文书）
- 行政处罚：无 ✅

综合评估：低风险
建议：相对方经营状态正常，无重大履约风险信号。
```

> 风险速览仅供参考，不替代专业尽调。详细信息将纳入审核意见书。

## 步骤 5：风险等级判定

对每个主体分别判定综合风险等级：

| 风险等级 | 判定标准 |
|---------|---------|
| 低风险 | 经营状态正常，无失信/经营异常/严重违法记录，自身风险 ≤ 2 条且均为非重大事项 |
| 中风险 | 经营状态正常，但存在以下之一：经营异常记录、自身风险 3-10 条、注册资本与合同金额严重不匹配 |
| 高风险 | 存在以下任一：失信被执行人、吊销/注销/清算状态、严重违法记录、破产/强制清算、自身风险 > 10 条 |

> **定性补充规则（覆盖上述定量标准）：**
> 以下情形无论自身风险数量多少，均应**直接判定为高风险**：
> - 涉诉案件中存在单笔标的额**超过本合同金额 50%** 的诉讼（被告方）
> - 存在与本合同**同类业务**相关的败诉记录（如审查的是工程合同，相对方有工程质量纠纷败诉）
> - 成立时间不足 1 年且注册资本为认缴（实缴为 0 或极低）
>
> 以下情形应将风险等级**至少提升一级**（低→中，中→高）：
> - 近 12 个月内新增诉讼数量显著增加（同比增长 > 100%）
> - 实缴资本不足注册资本 10%，且合同金额超过实缴资本

**多主体综合风险等级：** 取所有主体中**最高**的风险等级作为本次查询的综合风险等级，用于影响阶段四审查策略。

> 高风险判定将影响阶段四的审查策略（履约保障类条款提升审查优先级）和阶段五审核意见书的"总体签署建议"——即使合同条款无重大风险，若任一相对方主体为高风险，签署建议应至少调整为"修改后签署"并强调主体风险。

## 步骤 6：整理阶段二产物

`counterparty_risks` 为数组，每个成功查询的主体对应一个元素：

```json
{
  "query_date": "2026-03-25",
  "overall_risk_level": "所有主体中最高的风险等级",
  "counterparty_risks": [
    {
      "company_name": "XX有限公司",
      "contract_role": "乙方（施工方）",
      "data_source": "tianyancha / web_search",
      "skip_reason": null,
      "business_status": "存续",
      "established_date": "2015-03-20",
      "registered_capital": "500万",
      "paid_capital": "500万",
      "scope_match": true,
      "risk_level": "低风险 / 中风险 / 高风险",
      "risk_summary": "一段话综合评估",
      "risk_details": {
        "dishonest": 0,
        "abnormal_operation": 0,
        "own_risks": 2,
        "administrative_penalty": 0,
        "bankruptcy": false
      },
      "recommendation": "一句话建议"
    }
  ],
  "skipped_parties": [
    {
      "name": "张三",
      "contract_role": "担保方",
      "skip_reason": "自然人主体"
    }
  ]
}
```

若整体跳过本阶段：

```json
{
  "query_date": null,
  "overall_risk_level": null,
  "counterparty_risks": [],
  "skipped_parties": [],
  "skip_reason": "用户选择跳过 / 所有相对方名称均为占位符或自然人"
}
```
