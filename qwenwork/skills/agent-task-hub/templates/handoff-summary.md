# 交接摘要模板（六块外壳 + 交接元信息 + 固定子块）

摘要唯一目标：让接收方**无需回到本地、无需原始对话**就能独立续接。写之前自问一遍：接手人是一台陌生电脑 + 一个陌生 agent，只拿到这段文字和台账附件，能不能直接开工？

**开发任务硬性必填三项：仓库/分支/commit、交付物清单、验证结果。** 缺一即视为摘要不合格。生成后连同通知文案一起过 `scripts/check-handoff-ready.py`（开发任务加 `--dev`），PASS 后再写进「交接摘要」和「通知文案」字段。

产出物引用规则：交付物清单一律引用台账「产出物/工作文件」字段的附件（文件名/大小/OSS 链接或 fileToken），不要只写本地路径。本地绝对路径只在「交接元信息」里作"仅本机有效"的补充，接收方非本机时应显式忽略。

## 固定结构

六块是外壳，头部「交接元信息」和尾部「接手方式」是固定附加段：

```
【交接元信息】   （六块之外，先写）
【目标】
【当前状态】     （已确认 / 推断 / 未知）
【已完成/已产出】（含交付物清单 + 验证）
【下一步】       （含先读材料）
【关键决策/约束】
【风险/阻塞】
【接手方式】     （粘贴即用的接手 prompt，六块之外收尾）
```

## 模板正文

```
【交接元信息】
任务ID：<裸 ID，不带 agent 前缀>
Agent类型：<qwenwork / codex / qoder / claudecode / qoderwork / 其他>
状态：进行中
交接置信度：<高 / 中 / 低> —— 一句话理由
（开发任务必填以下四项）
仓库：<git remote URL，接手方可 clone>
分支：<branch>
基线 commit：<sha>
未提交改动：<无 / 有：改了什么、接手前是否需处理>
本地路径：<absolute path> —— 仅本机有效，非本机接手请忽略

【目标】
<一句话：这条任务要达成什么>

【当前状态】
已确认：<由代码、命令、产物或显式决策支撑的事实>
推断：<合理推断，接手方接手后需复核>
未知：<不明确、不应被默认的空白>

【已完成/已产出】
已完成：<做了哪些>
交付物清单（以台账「产出物/工作文件」附件为准，逐项列名不写本地路径）：
- <文件名>（<大小>）—— <它是什么、给接手方解决什么问题>
验证：
- <命令或证据> → <pass / fail / not-run>（<它证明了什么>）

【下一步】
最小下一步：<精确到下一个动作>
先读材料：
- <spec / 入口文件 / 分支说明> —— <为什么先读它>

【关键决策/约束】
- 决策：<取舍> 依据：<文件 / 命令 / 用户表态>
- 约束：<边界 / 非目标 / 隐私红线 / 仓库规范>

【风险/阻塞】
- <卡在哪、未验证项、可能踩的坑>

【接手方式】
新开会话，对 agent 说：
<完整接手 prompt：让它先读这段摘要和先读材料，再明确做什么、怎么验证>
```

## 通知文案（通知卡片正文，richText markdown）

写入「通知文案」字段，值格式 `{"markdown":"..."}`。这是自动化通知的正文，控制在卡片可读长度，不要塞进完整六块摘要。

通知文案与交接摘要一起由 `scripts/check-handoff-ready.py` 交检并渲染（内部用 `render-notice.py` 作为唯一渲染源，禁止自由组装），PASS 后把打印的 cell 值原样嵌入「通知文案」字段：

```bash
python3 scripts/check-handoff-ready.py handoff --title "【交接】<父任务标题>" --summary "<一句话摘要>" --handoff-summary-file <交接摘要文件> [--dev]
python3 scripts/check-handoff-ready.py claim   --title "【交接】<父任务标题>" --summary "<一句话摘要>" --handoff-summary-file <交接摘要文件>
```

输出为三块结构，样式已实机验证：`**任务**` / `**交接说明**`（claim 为 `**待认领**`）/
`**接手方式**`（claim 为 `**认领方式**`，prompt 用引用块独立成段）。
`--title` 必须与交接子记录「任务标题」一致，接手/认领 prompt 靠它定位记录。
