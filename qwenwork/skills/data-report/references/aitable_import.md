# Step 2.5 · 备份导入 AI 表格 详细规则

目的: 把清洗后的数据持久化到钉钉 AI 表格 (新建 Base 为主), 作为报告的可追溯数据底表。定位是 **备份**, 不是第二计算源; 任何失败不阻塞 HTML 交付。

## 时机与前置

- 在 Step 2 spot check **通过之后**执行 — 只有过了对账门, 导入的数据才可信
- 与写 HTML 的先后无强约束 (两者互不依赖), 建议: 导入动作在写 HTML 前发起, 不必等导入完成再写 HTML

## CSV 导出规范

```python
# df = 按 suggested_read_code 读出并清洗后的最终 DataFrame
# 日期转 ISO 字符串, 避免导入端解析歧义
for c in df.select_dtypes(include=['datetime64', 'datetimetz']).columns:
    df[c] = df[c].dt.strftime('%Y-%m-%d %H:%M:%S')
df.to_csv(csv_path, index=False, encoding='utf-8-sig')
```

- `index=False`: 索引列不是数据, 不进 Base
- `utf-8-sig`: 带 BOM, 防导入端中文列名乱码
- 空值: 保持空串/NaN 原样, 不要填 0 或 "无" (改变语义)
- 多 sheet: 每个 sheet 一张表, 各自导出; 表名 = sheet 名

## 字段类型映射

| pandas dtype | AI 表格字段类型 |
|---|---|
| int / float (无 NaN) | 数值 |
| float (含 NaN) | 数值 (空值留空) |
| datetime (已转 ISO 串) | 日期 |
| bool | 单选/布尔 (按目标能力) |
| object (低基数字符串) | 单选 — 基数 ≤ 50 时 |
| object (其余) | 文本 |

- 列名有重复/含换行: 导出前先重命名 (复用 INSPECT data_traps 的修复), 否则建字段阶段即失败
- 精度: 金额列不做四舍五入, 原样导出

## 目标选择

- **默认**: 新建 Base, 命名 `{报告主题}-数据底表`; 表 = 清洗后数据
- **仅当用户明确指定** 现有 Base 名称或 alidocs URL 时导入现有 Base: 在其中**新建表**接收数据, 不改写/覆盖任何已有表
- 用户指定的 Base 找不到/无权限: 原样透出错误, **不要**回退到自建 Base (用户指定了目的地, 换地方 = 违背意图)

## 大数据分批

- 行数 > 5 万: 按目标端单次写入上限分批导入, 记录累计成功条数
- 部分批次失败: 透出失败批次与错误, 注明已成功的条数区间, 不整单重导

## 失败透出格式 (交付消息附注)

```
[数据备份] 导入失败, 不影响报告交付
- 命令/工具: <调用对象>
- 参数: <脱敏后的关键参数>
- 错误: <错误码 / 异常信息 原文>
- 建议: <一句可执行的下一步, 如"检查网络后重试"或"稍后手动导入清洗文件 <csv 路径>">
```

## 结果告知 (必须, 成功/失败均不阻塞流程)

导入无论成功还是失败, 交付消息**必须**有一段告知用户备份结果 — 用户始终知道数据在哪里、能不能回溯。三种情形:

**成功** — 三要素:
1. **明确告知**: 一句话说明"清洗后数据已导入为 AI 表格底表"
2. **可点击链接**: AI 表格 Base 链接 `https://alidocs.dingtalk.com/i/nodes/{baseId}` (从 create_base / 导入工具返回结果中获取; 面向用户时展示名称+链接, 不暴露技术 ID 字段名)
3. **规模说明**: 一行注明导入规模与对账结果, 如 `32 条记录, 导入后服务端聚合对账与报告总额零偏差`

示例:
```
数据备份：清洗后数据已导入 AI 表格「渠道市场营销预算-数据底表」(32 条记录),
导入后服务端聚合对账与报告总额零偏差。 → https://alidocs.dingtalk.com/i/nodes/xxxx
```

**失败** — 按下方「失败透出格式」输出完整错误, 并注明本地清洗文件路径 (用户可手动导入) 与"不影响报告交付"。

**跳过** (环境无 AI 表格能力) — 注明跳过原因与本地 CSV 路径。

HTML 报告页眉/页脚也应注明数据备份位置 (成功: Base 名称; 失败/跳过: 本地文件路径), 与交付消息一致。

## 禁止事项

- 禁止从 Base 回读数据参与 KPI 计算 (数字单源 = `kpis` dict)
- 禁止静默重试、降级导出格式、或吞掉错误只说"导入失败"
- 禁止导入原始文件 (data_traps 未处理, 备份了脏数据等于没备份)
