# 社媒内容生成

根据用户指定的目标平台，生成适配的社交媒体内容。内容生成后先展示摘要供用户确认，确认通过后写入钉钉云文档。

## 禁止事项

- 禁止通过 curl、HTTP API 等非 `dws` 方式操作钉钉产品
- 禁止凭空构造 docUrl、nodeId 等标识符，所有 ID 必须从实际命令返回值中获取
- 禁止 `dws` 命令不加 `--format json`
- 禁止在未确认目标平台时直接输出内容——必须先跟用户确认平台
- 禁止把同一版文案不做改写直接发给所有平台——每个平台必须独立适配
- 禁止把长文机械截断后当作多平台改写结果
- 禁止承诺曝光量、涨粉数或转化率等结果
- 禁止编造品牌事实、数据、客户案例或用户评价
- 禁止未经用户确认就写入文档——必须先展示内容摘要获得确认
- 禁止 markdown 内容以 `#` 一级标题开头——`dws doc create --name` 已设置文档标题
- 禁止一次性传入超长 markdown 内容——必须分块写入，每块 ≤ 1500 字符
- 禁止在写入文档的 markdown 中使用 ASCII Art 架构图——钉钉文档等宽字体不保证对齐，改用表格或列表

## 强制要求

- 每条 `dws` 命令均须携带 `--format json` 参数
- 生成内容前必须确认目标平台；用户未指定时主动追问
- 平台、目标、受众三项至少确认两项才可开始生成
- 内容生成后必须先展示摘要（首段 + 结构概要），用户确认后再写入文档
- 用户确认写入时，使用 `dws doc create` 创建文档或 `dws doc update --mode append` 追加
- 内容过长时必须分块写入，每块 ≤ 1500 字符
- 每条内容必须包含明确的 CTA（行动号召）或下一步动作
- 首句必须有钩子（hook），禁止平淡开头
- 不得编造事实、案例、评价或数据——素材不足时标注"需补充"
- 多平台改写时必须先生成母稿，再按各平台规则独立适配

## 总体工作流

```
用户: "帮我写一条小红书笔记，推广我们的新产品"
      |
      v
Module A: 需求确认（两轮交互）
  → 第 1 轮: 确认目标平台（用户已指定则跳过）
  → 第 2 轮: 补充确认内容目标、受众、品牌语气、素材来源
  → 📖 读取 references/platform-playbooks.md 中目标平台章节，获取规范和规则
  → doc search 检索已有品牌/产品资料（可选）→ doc read 读取
  → WebSearch 搜索行业热点和平台趋势（可选）
      |
      v
Module B: 内容生成
  → 📖 读取 references/hook-formulas.md 中对应平台的钩子策略，选择合适公式
  → 生成母稿（1 个核心观点 + 1 个支撑证据 + 1 个 CTA）
  → 按 platform-playbooks.md 中的内容结构模板和字数限制适配改写
  → 多平台时：母稿 → 逐平台独立改写
      |
      v
  ⏸ 检查点: 展示内容摘要
  → 展示每个平台版本的首段 + 结构概要 + 字数统计
  → 用户选择: 确认写入 / 修改调整 / 放弃
      |
      v
Module C: 文档写入（用户确认后执行）
  → doc create 创建文档（文档名: "社媒内容-{平台}-{主题}-{日期}"）
  → doc update --mode append 分块写入完整内容
  → 返回文档链接
```

## 平台确认策略

用户提到内容创作但未指定平台时，必须先确认：

| 场景 | AI 应该怎么做 |
|------|-------------|
| 用户明确说了平台名 | 直接按该平台规则生成，无需追问 |
| 用户说"帮我写个社媒内容" | 追问: "请问要发布到哪个平台？比如小红书、微信公众号、微博、抖音、LinkedIn 等" |
| 用户说"一稿多发" / "多平台分发" | 追问: "请问需要适配哪几个平台？" |
| 用户说"发个朋友圈" | 确认为微信朋友圈，按朋友圈规则生成 |
| 用户提供了素材但没说平台 | 根据素材类型建议最适合的平台，说明原因，等用户确认 |

## 内容确认与写入策略

内容生成后不直接写入文档，必须经过用户确认：

```
AI: 内容已生成，以下是摘要预览：

📌 小红书版本（共 856 字）
首段: "3 个月从 0 到 10w 粉，我只做对了这一件事……"
结构: 钩子开头 → 3 个干货点 → 产品植入 → 互动引导
Hashtag: #职场效率 #AI工具 #打工人必备

是否需要将完整内容写入钉钉文档？
```

| 用户回复 | AI 动作 |
|---------|--------|
| "可以" / "写入" / "保存" | `doc create` → `doc update append` 写入完整内容 → 返回文档链接 |
| "改一下XX部分" / "语气再强一点" | 按反馈修改 → 重新展示摘要 → 再次确认 |
| "不用了" / "我先复制走" | 展示完整内容供用户复制，不写入文档 |
| "再出一版不同角度的" | 生成变体版本 → 展示摘要 → 等待确认 |

## 平台适配规则

### 国内平台

| 平台 | 字数限制 | 内容特点 | 关键规则 |
|------|---------|---------|---------|
| 小红书 | 标题 ≤ 20 字，正文 ≤ 1000 字 | 种草/干货/教程，人设感强 | 标题必须有数字或情绪词；必须带 emoji 分段；末尾引导互动（收藏/关注）；hashtag 3-8 个 |
| 微信公众号 | 正文建议 1500-2500 字 | 深度内容/观点输出 | 开头 3 行决定打开率；小标题分段；末尾引导关注+转发；长文本技能不处理（>3000 字路由到长文技能） |
| 微博 | ≤ 2000 字（建议 ≤ 300 字） | 短平快/热点借势/话题互动 | 首句即观点；带话题标签 #XX#；@相关账号；配图建议 |
| 抖音（脚本） | 15-60 秒脚本 | 前 3 秒必须有冲突/结果/收益 | 口播脚本格式：画面描述 + 口播文字 + 字幕；前 3 秒定生死 |
| 视频号 | 脚本 1-3 分钟 | 知识分享/品牌故事 | 比抖音节奏稍慢，可更深入；重点在价值传递 |
| 朋友圈 | ≤ 6 行可见（约 120 字） | 人设/日常/软植入 | 前 6 行必须完整表达核心意思；避免硬广；口语化 |

### 国际平台

| 平台 | 字数限制 | 内容特点 | 关键规则 |
|------|---------|---------|---------|
| LinkedIn | 建议 1300 字符以内 | 职场观点/行业洞察/专业人设 | 观点开头 + 3 段主体 + CTA；正文内不放链接（影响分发）；链接放评论区 |
| X (Twitter) | ≤ 280 字符 | 短句/强观点/互动 | 首句即钩子；线程（thread）适合深度内容；hashtag 1-2 个 |
| Instagram | 标题 ≤ 2200 字符 | 视觉优先/生活方式/品牌美学 | 配图是核心；文案辅助说明；hashtag 5-15 个；Stories 和 Reels 需单独适配 |
| Facebook | 建议 ≤ 500 字符 | 社区互动/品牌故事 | 提问式开头提升互动；鼓励评论和分享 |
| TikTok | 15-60 秒脚本 | 同抖音，英文语境 | 同抖音规则，语言和文化背景适配 |

## 使用示例

### 示例 1: 指定平台生成

**用户说**: "帮我写一条小红书笔记，推广我们的 AI 效率工具，目标用户是职场人"
**执行步骤**:
1. 平台已确认（小红书），补充确认: 品牌语气、核心卖点、有无素材
2. `dws doc search --keyword "AI 效率工具" --format json` 检索产品资料（可选）
3. 生成小红书笔记（标题 ≤ 20 字 + 正文 ≤ 1000 字 + emoji 分段 + hashtag）
4. ⏸ 展示摘要: 标题、首段、结构概要、字数、hashtag
5. 用户确认 → `dws doc create --name "社媒内容-小红书-AI效率工具-20260325" --format json`
6. `dws doc update --node {docUrl} --mode append --format json` 分块写入
7. 返回文档链接
**期望输出**: 文档链接，包含完整小红书笔记

### 示例 2: 多平台分发

**用户说**: "这篇产品文章帮我改成小红书和微博的版本"
**执行步骤**:
1. 平台已确认（小红书 + 微博），读取素材文章
2. 生成母稿 → 小红书版（种草风格 + emoji + hashtag）→ 微博版（短平快 + 话题标签）
3. ⏸ 分别展示两个版本摘要
4. 用户确认 → 创建文档写入两个版本
**期望输出**: 文档链接，包含两个平台的适配版本

### 示例 3: 最简触发

**用户说**: "帮我发个动态"
**执行步骤**:
1. 追问: "请问要发布到哪个平台？比如小红书、微博、朋友圈、LinkedIn 等"
2. 用户回复后，继续确认内容主题和目标
3. 生成 → 展示摘要 → 确认 → 写入
**期望输出**: 确认平台和主题后生成内容

## 输入与输出

- **必选输入**: 目标平台（未提供时追问）
- **建议输入**: 内容目标（曝光/互动/转化）、目标受众、品牌语气、素材来源、CTA
- **可选输入**: 发布时间建议、竞品参考、已有内容（优化场景）
- **输出**: 内容摘要预览 → 用户确认 → 钉钉云文档（含完整内容）

## 错误处理

| 错误 | 原因 | AI 应该怎么做 |
|------|------|--------------|
| 用户未指定平台 | 触发词不含平台信息 | 追问目标平台，列出常见选项 |
| 平台+目标+受众均未提供 | 信息严重不足 | 至少确认平台和目标两项才开始生成 |
| 素材不足以支撑内容 | 无事实依据 | 只做表达优化，标注"需补充"的部分，不编造案例和数据 |
| 用户要求承诺效果 | "保证涨粉1万" | 说明无法承诺具体效果，可提供最佳实践建议 |
| `doc create` 失败 | 权限或认证过期 | 提示用户 `dws auth login` 重新认证 |
| `doc update` 报 inputArgs.invalid | `--node` 用了裸 nodeId 或内容过长 | 改用完整 URL；内容分块 ≤ 1500 字符后重试 |
| 多平台版本雷同 | 未做独立适配 | 必须回到母稿，按各平台规则重写结构和节奏 |
| 用户说"只看看不用存" | 不想写入文档 | 展示完整内容供复制，不执行 doc create |
