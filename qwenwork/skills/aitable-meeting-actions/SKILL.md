# 会议纪要转行动项追踪表

从指定钉钉 AI 听记（会议纪要）中提取行动项，经行动项适合度判断后，写入 AI 表格的「行动项追踪表」进行持续跟踪；可选为每条行动项的责任人创建钉钉待办。

## 禁止事项

- 禁止通过 curl、HTTP API 等非 dws 方式操作钉钉产品
- 禁止凭空构造 taskUuid、baseId、tableId、fieldId、recordId、userId、corpId 等标识符，所有 ID 必须从实际命令返回值中获取
- 禁止 dws 命令不加 `--format json`
- 禁止在用户未指定会议时自行猜测——必须列出候选听记让用户选择，或要求用户提供会议名称/时间线索
- 禁止把 `minutes get todos` 的原始结果不加处理直接写入表格——必须结合摘要上下文补全任务语义（明确"做什么、交付什么"）
- 禁止将即时性事务（"会上现场对齐一下"）、已完成事项、纯信息知会写入行动项表
- 禁止用 fieldName 作为 record cells 的 key——cells 的 key 必须是 `table get` 返回的 fieldId
- 禁止向人员（user）字段写入姓名字符串——必须写入 `[{"userId":"...","corpId":"..."}]` 结构，userId 从 contact 命令返回值获取
- 禁止在责任人搜索出多个同名结果时擅自选择一个——必须请用户确认
- 禁止向日期字段写入"周五前"、"明天"等相对时间——必须换算为 `YYYY-MM-DD` 绝对日期，且换算基准是**会议日期而非今天**（"下周三"按会议那周算，详见「日期换算规则」）
- 禁止将"尽快 / ASAP / 越快越好"折算为任何具体日期——硬编日期等于造假数据，必须留空并计入回执「待确认清单」
- 禁止臆造人员——通讯录匹配不到的姓名严禁猜测 userId 或张冠李戴，必须降级写入备注列，并在回执「未匹配人员清单」中列出
- 禁止未经用户确认就执行任何写入动作（建 Base、建表、写记录、建待办）
- 禁止在用户未明确目标表时跳过「目标表选择」询问直接落表——即使 `base search` 探测命中了疑似既有跟踪表，也只能作为推荐选项列入第一级选择，必须等用户选定后才可继续；「写入确认」不能替代「目标表选择」
- 禁止单次 `record create` 超过 100 条记录
- 禁止在 todos + summary 信息已足够时仍拉取全量转写原文（transcription 可能非常长，会撑爆上下文）
- 禁止使用 `contact user get --ids me/self` 获取本人信息（会返回空数据的假成功），必须用 `contact user get-self`
- 禁止 `minutes list all` 不显式传 `--limit`——该参数**默认仅 10 条**，一周会议超过 10 场时候选会被静默截断，与"覆盖我参与的所有会议"直接冲突
- 禁止对听记状态非「转写完成」的会议提取行动项——此时 todos/summary 可能为空，会被误判成"本场没有行动项"
- 禁止 `table get` 在已从 `base get` 拿到 tableId 后仍不传 `--table-ids`（默认返回 Base 下全部表的字段与视图目录，造成上下文突增）
- 禁止查重用的 `record query` 不传 `--field-ids`（全字段全记录拉回，表越大开销越高；查重只需行动项与备注两列）
- 禁止在用户处于多组织时不确认目标组织就写入（会把行动项写进错误企业的表）

## 强制要求

- 每条 dws 命令均须携带 `--format json` 参数
- 流程起点必须先执行 `contact user get-self` 获取当前用户 userId、姓名和 corpId（corpId 用于后续 user 字段写入）
- 会议定位：用户已给出会议纪要内容或明确指定了会议 → 优先直接使用；未给出 → 列历史会议供选，默认时间窗为**最近一周**（用户指定了时间段则按用户指定的来），候选列表必须含**序号/主题/时间/人数**，支持多选合并处理（如回复 "1,3" 则两场会议的行动项合并入同一张表）
- 候选必须双源合并，覆盖"我参与的所有会议"：① `minutes list all`（有听记，可提取）② `calendar event list --start/--end`（我参与的日程会议）；按时间重叠+标题相似去重，仅在日程源出现的会议标注「无听记，暂不可提取」，并引导开启听记或请发起人共享；无日程且无听记的临时视频会议任何接口均不可见，需如实告知边界
- 两源都必须显式传 `--limit`（`minutes list all` 默认 10，取 30 起；`calendar event list` 取 100）：返回带游标时用 `--cursor` 翻页直到覆盖完整时间窗；若确因上限截断，必须在候选列表中如实标注"仅显示前 N 场，可扩大范围或直接给出会议名"
- 候选列表的人数信息用 `minutes get batch --ids <uuid1,uuid2,...>` 一次批量补齐（返回参与人列表、时长、**听记状态**）。
**batch 仅限听记创建者调用**：共享而来、非本人发起的听记会报 `user is not minutes creator`，但这类听记的单条 `get info/todos/summary/transcription` 全部可用（已实测）——batch 无权限只影响候选阶段的人数/听记状态补齐，**不影响后续提取**，严禁引申为"非本人发起的会议不可处理"或向用户暗示非本人受限；人数降级：日程源会议用 `calendar event list` 返回的参会人数补位，仍拿不到则该列显示"—"；"禁止逐个轮询"仅指候选阶段为补人数而逐个 `get info`，B 阶段提取本来就逐会议单条 get，不受此限
- 听记状态非「转写完成」的会议须在候选中标注「转写中，暂不可提取」，与"无听记"同等处理：不得进入 Module B 提取，避免把空内容误判为"本场无行动项"
- 时间参数必须使用 ISO-8601 绝对时间（如 `2026-08-17T00:00:00+08:00`），不得使用相对时间；时区以本人所在时区为准，无法判定时按 `+08:00`，跨时区参会人的截止时间统一按会议所在时区解释并在回执注明
- 多组织（多企业）用户：先用 `dws profile list` 列出已登录身份，确认目标组织后对全链路命令统一附加 `--profile <corpId:userId>`；单组织用户无需该参数
- 行动项提取遵循三级信息源策略：① `minutes get todos`（系统已提取的待办）为主料 → ② `minutes get summary`（AI 摘要）补全上下文语义 → ③ 仅当前两者信息明显不足（todos 为空且摘要无行动项线索）时才拉 `minutes get transcription`
- 每条行动项必须产出六字段：**行动项、负责人、截止日期、状态**（标准四件套）+ **协作人、关联议题**；行动项须为动宾结构（如"整理 Q2 数据报告"，不得是"你来跟进一下"这类残句）；缺失字段按「六字段提取与缺失推断规则」处理
- 推断标注规则：text 类字段的推断值加后缀「（推断）」；日期/人员/单选字段存不了后缀，改为在回执中集中列出推断项与依据
- 责任人/协作人解析：先在听记参与人信息中匹配；匹配不到再用 `contact user search --query "<姓名>"`；唯一命中才可写入，多个命中必须请用户选择；仍匹配不到 → 不写 user cell，姓名降级写入备注列（如"负责人待认领：王五"）
- 追踪表定位采用两级选择（见「目标表选择交互」）：第一级询问新建/添加到已有表格（`base search` 探测到疑似既有行动项表时将其作为推荐项直接列入）；选"已有表格"后用 `base list` 列最近访问的表格供选，不在列表中的表名由末位「其他（请填写）」项承接（输入后走 `base search` 检索）；用户在指令中已明确指定表/链接则跳过询问直接用
- 复用既有表前必须校验字段结构：先 `base get` 取 Base 下的表目录（轻量，只返回 summary）定位 tableId，再 `table get --table-ids <tableId>` 取该表的 fieldId/type，缺失字段用 `field create` 补齐；新建时按本 SKILL 的标准 schema 建表
- 新建追踪表后必须补建两个视图（让表开箱即用，同时反向验证字段类型正确）：① 「状态看板」`view create --view-type Kanban` 按状态字段分组 ② 「我负责的未完成」`view create --view-type Grid` 筛选负责人为本人且状态非已完成/已取消；复用既有表时不擅自加视图，可询问用户是否补建
- 写入前必须向用户展示完整预览（建议入表 / 不建议入表两区，含判断理由）并获得确认
- 首次向某张既有表写入时，可先用 `--dry-run` 预演 `record create` 校验 cells 结构（不实际写入），确认无误后再正式执行
- 写入完成后必须输出结构化回执：表格访问链接（`https://alidocs.dingtalk.com/i/nodes/{baseId}`）+ 写入统计 + 推断项清单（字段/值/依据）+ 待确认清单（"尽快"类无截止项）+ 未匹配人员清单
- 创建钉钉待办是可选增值步骤，必须在入表确认之外单独征得用户同意；只对**有负责人且状态为未开始/进行中**的行动项建待办，状态为已完成/已取消的一律跳过并在回执说明
- 本 SKILL 不含仪表盘/图表能力：禁止调用 `aitable dashboard *` 与 `aitable chart *`；用户要求做图表统计/仪表盘时，告知本技能只负责行动项入表与待办，建图请走 AI 表格仪表盘能力或在表格内手动创建
- **「看板」指两个不同的东西，不得混为一谈**：① **看板视图（Kanban view）**——表内视图，用 `view create --view-type Kanban` 创建，**属于本技能能力范围**；② **仪表盘/图表（dashboard / chart）**——独立可视化面板，**属于禁区**。用户说"建个看板"时先辨意图：想按状态分列、拖卡片 → 建 Kanban 视图；想看完成率/趋势等统计图 → 属于仪表盘，如实告知不支持
- 所有向用户提问必须使用客户端的「选择卡片」能力（结构化提问/问题选项控件，用户直接在卡片上点选完成），见「交互形态规则」；严禁在正文中用 markdown 文字列表模拟选项让用户打字回复；自由输入一律收敛为卡片末位「其他（请填写）」选项
- 全程只对当前会议的行动项做增量写入，不得修改、删除表中已有的其他记录

## 涉及工具

| 工具 | 用途 |
|---|---|
| `dws contact user get-self` | 获取当前用户 userId、姓名、corpId |
| `dws contact user search` | 按姓名搜索责任人，获取 userId |
| `dws minutes list all` | 按关键字/时间范围检索听记，获取 taskUuid（必须显式传 `--limit`，默认仅 10 条）|
| `dws minutes get batch` | 批量补齐候选会议的参与人数、时长、听记状态（禁止逐个 `get info` 轮询）|
| `dws calendar event list` | 拉取我参与的日程会议（双源候选的第二源，无听记者仅列不提） |
| `dws minutes get info` | 获取听记基础信息（标题、会议时间） |
| `dws minutes get todos` | 获取听记中系统提取的待办事项 |
| `dws minutes get summary` | 获取听记 AI 摘要（Markdown） |
| `dws minutes get transcription` | 获取转写原文（兜底信息源） |
| `dws aitable base search` | 按名称搜索既有 Base：探测疑似跟踪表 + 用户手输表名时检索 |
| `dws aitable base list` | 列最近访问的 Base（第二级"已有表格"候选；注意仅含最近访问，非全部）|
| `dws aitable base get` | 取 Base 下的表目录 summary（不含字段详情），获取 tableId 的轻量入口 |
| `dws aitable base create` | 新建 Base |
| `dws aitable table create` | 在 Base 中新建行动项追踪表（附带初始字段） |
| `dws aitable table get` | 获取表的 fieldId/fieldName/type 映射（写记录前必查；已知 tableId 时传 `--table-ids` 控制返回体）|
| `dws aitable field create` | 复用旧表时补齐缺失字段（含本版新增的「来源标识」列）|
| `dws aitable view create` | 新建表后补建「状态看板」(Kanban) 与「我负责的未完成」(Grid) 视图 |
| `dws aitable view get` | 读回既有视图的真实 config 作为模板，避免凭空构造 filter/group 结构 |
| `dws aitable record create` | 批量写入行动项记录 |
| `dws aitable record update` | 回写遗留行动项的状态（只传 recordId + 需改字段，其余保持原值）|
| `dws aitable record query` | 按「来源标识」查重 + 拉回逾期未完成的遗留项（必须传 `--field-ids` 限列）|
| `dws todo task create` | （可选）为责任人创建钉钉待办 |
| `dws profile list` | 多组织用户确认目标组织，取 `--profile` 所需的 `corpId:userId` |

## 总体工作流

```
用户: "把昨天项目周会的行动项沉淀到表格里跟踪"
      |
      v
Module A: 准备与会议定位
  → contact user get-self 获取本人信息
  → 用户已给出会议内容/明确会议 → 直接使用
  → 否则双源列候选（默认最近一周，可指定时间段）：
     minutes list all（有听记） ∪ calendar event list（我参与的日程）→ 去重合并
     + minutes get batch 批量补人数（batch 仅限创建者；非本人发起时人数降级：日程补位/显示"—"，提取不受影响）
     → 展示 序号/主题/时间/人数，无听记者标注「无听记」 → 支持多选合并
  → 得到一个或多个 taskUuid（仅有听记的会议可进入后续流程）
      |
      v
Module B: 行动项原料提取
  → minutes get info（会议标题/日期） + get todos（主料） + get summary（上下文）
  → 信息不足时才 get transcription 兜底
      |
      v
Module C: 六字段结构化 + 适合度判断
  → 结合摘要补全语义 → 产出六字段（行动项/负责人/截止日期/状态 + 协作人/关联议题）
  → 缺失字段按推断规则补全并标注（推断）
  → 适合度判断 → 分类为"建议入表"/"不建议入表"
  → 责任人/协作人解析（参与人匹配 → contact user search → 匹配不到降级进备注）
  → 截止时间以会议日期为基准换算；"尽快"类不折算
      |
      v
Module D: 定位/创建追踪表（两级选择，询问不可跳过）
  → 用户已指定表/链接 → 直接定位校验，不询问（唯一例外）
  → 否则必须先抛第一级选项：添加到《疑似跟踪表》(base search 命中时，仅作推荐不自动选) / 新建表格 / 添加到其他已有表格
  → 选"其他已有表格" → base list 列最近访问 + 支持输入表名 base search → 选中 Base → base get 定位 tableId
  → 复用：table get --table-ids 校验字段 → 缺则 field create 补齐（含「来源标识」列）
  → 新建：base create + table create（标准 8 列 schema）+ view create 补建看板与筛选视图
      |
      v
Module E: 复盘遗留项 + 确认与写入
  → record query 按「来源标识」 contain 本次 taskUuid 查重（只取行动项+来源标识两列）
  → record query 拉回逾期未完成的旧行动项 → 预览新增「📋 上次遗留」区
  → 展示预览（三区 + 理由 + 推断标注） → 用户确认 → record create 写新增
  → 用户勾选了遗留项状态 → record update 回写
  → 输出回执（表格链接 + 推断项清单 + 待确认清单 + 未匹配人员清单 + 遗留项更新统计）
      |
      v
Module F: （可选）创建待办
  → 用户单独确认（选择卡片）后，按责任人逐条 todo task create
```

## 行动项适合度判断规则

对每条候选行动项，必须结合摘要上下文理解完整语境后再判断，不得孤立看 todos 中的单条文本。

### 上下文补全要求

系统提取的待办常常是残句，必须结合摘要还原完整任务：

| 场景 | todos 原文 | 摘要上下文 | 正确入表标题 |
|---|---|---|---|
| 任务对象在讨论中 | "张三跟进一下" | 摘要提到"供应商报价未回复" | 跟进供应商报价回复 |
| 截止时间在结论区 | "李四整理数据" | 摘要结论"周五评审前备齐材料" | 整理评审数据（截止：本周五对应日期） |
| 多轮讨论后认领 | "行，我来吧（王五）" | 前文是竞品分析分工讨论 | 完成竞品分析 |
| 表态非任务 | "收到，没问题" | 仅是对结论的附议 | 不入表 |

### 建议入表（高匹配度）

| 信号类型 | 典型表达 | 说明 |
|---|---|---|
| 交付类 | 整理一份、输出方案、提交报告、准备材料 | 有明确交付物，适合表格跟踪 |
| 跟进类 | 跟进、推进、确认、落实、对接 | 需要持续跟进，有状态流转价值 |
| 时间类 | 周五前、下周评审前、月底、X 号之前 | 有截止时间，适合截止日期字段 |
| 分配类 | 你来负责、交给你、A 和 B 一起 | 责任人明确 |
| 决议类 | 会议决定由 X 完成 Y | 会议正式决议产生的任务 |

### 不建议入表（低匹配度）

| 信号类型 | 典型表达 | 说明 |
|---|---|---|
| 即时性事务 | 会上现场看一下、散会后聊两句 | 会议期间/紧随其后即完成，无跟踪价值 |
| 信息知会 | 大家知悉、同步给大家、FYI | 无行动要求 |
| 已完成事项 | 已经做完了、上周已提交 | 会上汇报的既成事实 |
| 模糊表态 | 后面再看、有空研究下 | 无责任人、无交付物、无时间，跟踪无意义 |
| 长期例行 | 每天记得打卡、注意安全 | 例行提醒，不属于本次会议产出 |

用户可以对"不建议"条目手动选择"仍然入表"。

## 六字段提取与缺失推断规则

每条"建议入表"的行动项必须产出以下六字段（标准四件套 + 协作人 + 关联议题），缺失时按对应规则处理：

| 字段 | 说明 | 缺失时的推断规则 |
|---|---|---|
| 行动项 | 动宾结构任务描述 | 残句必须结合摘要补全；补全部分属推断 → 值后缀「（推断）」；无法补全则原文入表并在回执标注 |
| 负责人 | 单人 | 无明确负责人时按会上认领者 > 被点名者 > 议题主讲人推断（依据进回执）；均无 → 留空 + 回执待确认清单 |
| 截止日期 | 绝对日期 | 相对时间以会议日期为基准换算（见下节）；"尽快/ASAP"不折算留空进待确认；完全无时间线索 → 留空 |
| 状态 | 未开始/进行中/已完成/已取消 | 默认"未开始"；会上明确"已经在做" → "进行中"（单选存不了后缀，推断依据进回执） |
| 协作人 | 多人 | 会上明确提到配合者才填；**不推断**，缺失即留空 |
| 关联议题 | 行动项所属的会议议题 | 从摘要议程结构定位；定位不到 → 用会议主题兜底，值后缀「（推断）」 |

推断标注总规则：text 字段用值后缀「（推断）」；日期、人员、单选字段无法携带后缀，一律改为在回执中集中列出推断项与依据。

## 日期换算规则（单列，同类技能最常见错误）

- **换算基准 = 会议日期（`minutes get info` 返回的开始时间），不是今天**。"下周三"按会议那周的下周三算；即使执行时已过了该日期，仍按会议基准换算，并在回执标注「已过期」提醒
- 可换算：明天/后天/本周X/下周X/月底/X 号前/评审前（评审日期会上明确时） → 换为 `YYYY-MM-DD`
- 不可换算：尽快/ASAP/越快越好/有空/回头 → 截止日期留空，进回执「待确认清单」，由用户定期限
- 只有日期无具体时刻 → date 字段仅存 `YYYY-MM-DD`

## 目标表选择交互（Module D）

用户未在指令中明确目标表时，写入前**必须先抛出第一级选择，等用户选定后才能继续**；探测命中疑似跟踪表 ≠ 自动选中，命中只改变推荐项，不免除询问。唯一可跳过询问的情况：用户已在指令中给出表名/链接，或同一会话内用户已说过"后面都写这张表"。

第一级（单选）：先用 `base search --query "行动项"` 探测疑似既有跟踪表，命中时作为推荐项直接列入：

```
行动项写到哪张表？
1. 添加到《项目行动项跟踪》（推荐）
   检测到的既有行动项表，将追加写入
2. 新建表格
   按标准六字段 schema 新建《产品项目周会·行动项》
3. 添加到其他已有表格
   列出你最近访问的 AI 表格供选择
4. 其他（请填写）
   直接输入目标表格名称，或对行动项提出调整要求
```

（探测未命中时不出现选项 1，"新建表格"作为推荐项）

第二级（选了"其他已有表格"时，单选）：

- `base list` 列最近访问的 Base（每页最多 10 个）作为选择卡片的选项，末位固定加「其他（请填写）」项，说明为"输入不在列表中的表格名称"（base list 仅返回最近访问，不是全部，列表没有不代表表不存在）；禁止用末尾文字提示替代「其他」项
- 用户在「其他」中输入表名 → `base search --query "<表名>"` 检索；仍搜不到 → 请用户确认名称或直接提供表格链接（从链接解析 baseId）
- 选中 Base 后 `table get`：Base 下仅一张数据表 → 直接用；多张 → 再出一张选择卡片让用户选表

选定既有表后走字段校验/补齐/类型降级告知的既有逻辑。本技能不做跨会话记忆；同一会话内用户明确说"后面都写这张表"时，本会话后续直接沿用不再询问。

## 落表：表名规则与字段类型映射

表名规则（新建时）：

- Base 默认名「会议行动项跟踪」，已有同名 Base 优先复用
- 单会议 → 表名「<会议主题>·行动项」；多会议合并 → 「会议行动项汇总-YYYYMMDD」（执行当天日期）
- 表名≤100 字符且不含 `/ \ ? * [ ] :`，主题超长时截断；重名由服务端自动续号，以返回的实际表名为准

字段类型映射表（六字段 + 系统保留列 2 列，共 8 列）：

| 提取字段 | type | config | 写入格式与要点 |
|---|---|---|---|
| 行动项 | text | — | 动宾结构；推断补全部分带「（推断）」后缀 |
| 负责人 | user | `{"multiple":false}` | `[{"userId":"...","corpId":"..."}]`；未匹配 → 不写 cell，姓名降级进备注 |
| 协作人 | user | `{"multiple":true}` | 同上，可多人 |
| 截止日期 | date | `{"formatter":"YYYY-MM-DD"}` | 绝对日期；存不了后缀，推断依据进回执 |
| 状态 | singleSelect | options: 未开始/进行中/已完成/已取消 | 选项名字面量；新写入默认"未开始" |
| 关联议题 | text | — | 会议主题兜底时带「（推断）」后缀 |
| 备注 | text | — | 系统保留列：固定以「来源会议：《主题》(日期)」开头；追加未匹配人员（"负责人待认领：王五"）与其他降级信息 |
| 来源标识 | text | — | 系统保留列（本版新增）：格式 `<taskUuid>#<todoId>`；由摘要提取、无对应 todoId 时写 `<taskUuid>#summary`。查重的唯一依据，不得留空、不得人工改写；建表后可在视图中隐藏此列 |

本版变更说明：新增「来源标识」列（第 8 列）仅适用于**本版及之后新建的表**；复用本版之前建的旧表时不做任何数据迁移，走既有的"缺字段就 `field create` 补齐"逻辑自然补上这一列；若因权限等原因补不上，降级为旧查重口径（标题 + 备注含会议名）并告知用户查重可靠性下降。

硬约束：**人员/日期/单选三类字段的类型必须严格正确**，否则表内按人筛选、到期提醒、按状态分组看板全部失效。复用既有表时若这三类字段是 text 类型，必须向用户明确提示降级后果后才可降级写入。

### 新建表后补建视图

`view create` 支持 Grid / Kanban / Gantt / Calendar / Gallery；新建追踪表后固定补建两个：

| 视图名 | viewType | 作用 |
|---|---|---|
| 状态看板 | `Kanban` | 按「状态」字段分组成列，可拖动卡片改状态 |
| 我负责的未完成 | `Grid` | 只看负责人为本人、状态非已完成/已取消的条目，按截止日期升序 |

**幂等（防重复建视图）**：创建前先 `view get` 读回本表视图全量目录；同名视图已存在 → 跳过创建、复用既有 viewId；创建完成后再读回一次目录确认无同名视图。重跑技能、超时重试等场景绝不允许无条件再建出一个「状态看板」。

视图 config 的 filter/sort/group 结构**不得凭空构造**：先对同 Base 任一既有视图执行 `view get` 读回真实 config 作为样板，再按本表 fieldId 改写。构造失败时降级为只建「状态看板」（仅需 group 一项），并告知用户筛选视图需在表格里手动配置。

「我负责的未完成」筛选三条件（负责人=本人、状态≠已完成、状态≠已取消）必须遵守以下纪律：
- 负责人取值只能来自 A1 的 `get-self`；`get-self` 返回空或异常时，禁止从其他数据（待办 executors、会议参与人等）借 userId 猜测"本人"——降级为不建该视图并告知用户
- 条件值格式（已实测）：负责人用 `any_of` + `[{"userId":"<userId>","corpId":"<corpId>"}]` 对象数组（服务端归一化为 uid 存储；直接写 userId 字符串不命中）；状态用 `ne` + 选项名（服务端归一化为选项 ID，读回看到 ID 属正常）；多条件 AND 组合用合法 token 已实测正确求值。
**严禁写 `is`/`isnot`**：参考文档将其列为错误拼写别名，view config 写入路径不做归一化，会原样存储致 UI 筛选面板裸显示 IS/ISNOT；view create/update --config 的 filter 外层须数组包裹，传对象报 syntax error
- 写入后必须自检：`view get filter` 读回确认条件已落且操作符为合法 token（读回看到 uid/选项 ID 属正常归一化；若读回仍是 is/isnot 字面量说明写错 token，立即用 `view update --config` 重写为 any_of/ne 格式）；禁止用 `record query` 核对人员条件（实测对人员字段比较报 INTERNAL_ERROR 或 0 条，不可用作自检手段）
- 平台边界（如实告知）：CLI 筛选不支持"当前用户/包含我"动态值，该视图只能钉死为本次执行者；同事打开同一视图看到的是执行者的未完成项，需自行在筛选面板把负责人改成自己。回执中必须一句话说明此边界

补建视图同时是字段类型的反向验证：若「状态」不是 singleSelect，Kanban 无法按其分组——此时应回头确认字段类型，而不是放弃建视图。

### 查重口径（以「来源标识」为准）

1. 写入前用 `record query` 按「来源标识」`contain <本次taskUuid>` **一次**拉回该会议已入表的记录，`--field-ids` 只取「来源标识 + 行动项」两列
2. 标识为 `<taskUuid>#<todoId>` 的：与待写入项**精确比对该标识**，命中即重复 → 跳过并在回执标注「已存在」
3. 标识为 `<taskUuid>#summary` 的（摘要提取项无稳定 todoId）：退化为"同一 taskUuid 内行动项标题相同"比对；因 taskUuid 全局唯一，仍优于旧口径（不会被同名会议误伤）

为何改用来源标识：行动项标题经过 AI 推断补全，同一场会两次运行可能产出"整理 Q2 报告"与"整理 Q2 数据报告"两种字面，靠标题比对会漏判成新条目而重复写入。

### 上次遗留项复盘

目标表已有历史记录时，写入前必须多做一步复盘（周会真实场景的第一件事是"上次那几件做完了没"，不做复盘表会迅速退化成一堆永远「未开始」的死数据）：

- 用 `record query` 拉回**截止日期早于今天**的记录（date 字段用 `before` 算子），`--field-ids` 只取行动项/负责人/截止日期/状态/来源标识五列
- 在本地过滤出状态仍为「未开始/进行中」且来源标识**不属于本次会议**的条目，作为遗留项
- 遗留项在预览中单独成区（「📋 上次遗留」），用选择卡片（多选）让用户勾选已完成的，确认后用 `record update` 回写状态（只传 recordId + 状态字段）
- 遗留项更新与新增写入是**两个独立确认**：用户可以只写新增、不动遗留项；不得把两者捆绑成一个确认
- 能力边界（如实告知）：截止日期留空的未完成项不会被 `before` 命中，不在复盘范围内；首次向空表写入时跳过复盘

复用既有表时：以 `table get --table-ids <tableId>` 返回的实际字段为准做"名称+类型"匹配；缺失字段（含「来源标识」）用 `field create` 补齐后再写入。

## 交互形态规则（很重要）

所有需要用户做选择的环节，**必须使用客户端的选择卡片（结构化提问/问题选项）能力向用户提问，让用户直接在卡片上点选完成操作**：

- **严禁在回复正文里用 markdown 编号列表模拟选项**——那会退化成要用户打字回复的纯文本；只有当前环境确实不存在结构化提问能力时，才降级为文本编号列表
- 卡片内容结构：一句明确的问题 + 选项（每项一行标题 + 一行简短说明）+ 末位固定一项「其他（请填写）」作为自定义输入入口（若客户端控件自带"其他"项则无需重复添加）
- 禁止在选项之外用文字段落引导用户打字回复（如"也可直接回复表格名称/其他要求"）——所有自由输入统一收敛到「其他（请填写）」选项里
- 有推荐项时在选项标题后标注「（推荐）」，并把推荐项放在前面
- 单选/多选必须在问题中说明（多选如"可多选"）
- 禁止用开放式问句（"你想怎么处理？"）替代可枚举的选择；禁止一次抛出多个问题混在一段文字里；分析结果、预览、回执等展示性内容仍用正文输出，只有"需要用户做决定"的那一步用选择卡片
- **选项数量上限 10 项**（含末位「其他」）：候选超出时按「会议候选列表规则」的排序取前 9 项，并在「其他（请填写）」的说明中注明"共 N 场，可扩大范围或直接给出会议名"；禁止一次抛出十几个选项把卡片撑爆

适用环节与选项模板（均以选择卡片形式呈现）：

| 环节 | 形态 | 选项模板 |
|---|---|---|
| 会议候选选择 | 多选 | 每场会议一个选项（主题/时间/人数/是否有听记）+ 末位「其他（请填写）」：扩大时间范围或直接给会议名 |
| 目标表选择（第一级） | 单选 | 1. 添加到《疑似既有跟踪表》（推荐，探测命中时才出现） 2. 新建表格 3. 添加到其他已有表格 4. 其他（请填写） |
| 已有表选择（第二级） | 单选 | 每个最近访问的表格一个选项（表名）+ 末位「其他（请填写）」：输入不在列表中的表格名称 |
| 写入确认 | 单选 | 1. 确认写入（推荐） 2. 调整后再写（说明要改哪条） 3. 取消 |
| 遗留项状态更新 | 多选 | 每条逾期未完成项一个选项（行动项 + 负责人 + 逾期天数），勾选者标为已完成 + 末位「都未完成，不用改」；与写入确认分开抛 |
| 责任人多命中 | 单选 | 每个候选人一个选项（姓名 + 部门）+ 都不是/留空 |
| 建待办确认 | 单选 | 1. 创建待办（列出将给谁建几条） 2. 不创建，仅表格跟踪 |

## 会议候选列表规则

用户未给出会议内容时，列历史会议供选，必须覆盖"我参与的所有会议"（双源合并）：

- 默认时间窗：最近一周（`--start` = 执行日减 7 天的 0 点，`--end` = 当前时刻，均为 ISO-8601 绝对时间）；用户指定了时间段则按用户的来
- 两源均须显式传 `--limit`（`minutes list all` 默认仅 10，取 30 起；calendar 取 100），结果带游标时用 `--cursor` 翻页至覆盖完整时间窗；仍被上限截断时如实标注"仅显示前 N 场"，禁止静默丢弃
- 源 1：`minutes list all`（有听记、可提取）；源 2：`calendar event list --start/--end`（我参与的日程会议）；两源按时间重叠 + 标题相似去重，听记源优先
- 用户带了会议名线索 → minutes 源追加 `--query` 缩小范围，calendar 源拉回后按标题本地过滤
- 候选列表四要素：序号/主题/时间/人数；人数优先由 `minutes get batch --ids` 批量补齐；
batch 仅限创建者，非本人发起的听记报无权限时用日程参会人数补位，仍无则显示"—"，不阻断——且须明确：非本人发起不影响提取（单条 get 全可用），回执不得暗示非本人受限；可提取性按 `get batch` 返回的听记状态标注（有听记 / 转写中 / 无听记）；batch 无权限拿不到状态的非本人听记不标「转写中」，按「有听记」进入提取，内容空再走空内容兜底并注明"转写可能未完成"：

```
找到最近一周你参与的 14 场会议，请选择要提取行动项的会议（可多选）：
1. 产品项目周会
   08-16 14:00 (62 分钟) · 8 人 · 有听记
2. 架构评审会
   08-15 10:00 (45 分钟) · 5 人 · 有听记
3. 双周技术评审
   08-17 16:00 (38 分钟) · 12 人 · ⚠️ 转写中，暂不可提取
4. 飞鸿殿发起的视频会议
   08-17 15:07 · — 人 · ⚠️ 无听记，暂不可提取
...
10. 其他（请填写）
   共 14 场，可扩大时间范围（如最近一个月）或直接给出会议名
```

候选列表必须按「交互形态规则」以选择卡片（多选）形式提问，严禁在正文里写成文字列表或段落叙述。

- 无听记的会议必须列出但标注「无听记，暂不可提取」；用户选中时如实告知：需先在会议中开启 AI 听记，或请发起人共享听记，之后才能提取
- 听记状态非「转写完成」的会议同样列出并标注「转写中，暂不可提取」（刚结束的会议常处于此态）；用户选中时告知稍后重试，严禁硬拉 todos/summary 后拿空结果当作"本场无行动项"
- 能力边界（如实告知，不得掩盖）：无日程且无听记的临时视频会议，开放平台无查询接口，无法列出
- 排序：标题与用户描述的字面匹配度 > 时间接近度 > 时间倒序兜底；可提取者（有听记且转写完成）排在转写中/无听记者之前
- 支持多选合并：选中的多场会议各自走 B→C，行动项合并预览、一次确认、写入同一张表（备注列区分来源会议），回执按会议分组
- 一周内双源均无结果 → 提示用户扩大时间范围（如最近一个月）或提供会议名
- 禁止在多候选时不询问直接选第一条

## 使用示例

### 示例 1: 指定会议，新建追踪表

用户说: "把昨天产品周会的行动项沉淀到表格里跟踪"

执行步骤:
1. `dws contact user get-self --format json` 获取本人 userId/corpId
2. `dws minutes list all --query "产品周会" --start "<昨天0点ISO>" --end "<昨天24点ISO>" --format json` 定位听记，取 taskUuid
3. `dws minutes get info/todos/summary --id <taskUuid> --format json` 三连拉取原料
4. 结构化 + 适合度判断 + 责任人解析（参与人匹配，缺失者 `contact user search`）
5. `dws aitable base search --query "行动项" --format json` 无可复用表 → 征得同意后 `base create` + `table create`（标准 8 列 schema）
6. `dws aitable table get --base-id <baseId> --table-ids <tableId> --format json` 取 fieldId 映射
7. `dws aitable view create` 补建「状态看板」(Kanban) 与「我负责的未完成」(Grid)
8. 展示预览（新建表无遗留项，故仅两区）→ 用户确认 → `record create` 写入（含「来源标识」列）→ 输出回执

### 示例 2: 复用既有表 + 顺带建待办

用户说: "把今天站会的任务加到《项目行动项跟踪》，并给每个人建待办"

执行步骤:
1. get-self → minutes 定位今天站会 → 提取与判断（同上 1-4）
2. `dws aitable base search --query "项目行动项跟踪" --format json` 命中 → `base get` 定位 tableId → `table get --table-ids` 校验字段 → 缺"协作人"与"来源标识" → `field create` 补齐
3. `record query` 按「来源标识」 contain 本次 taskUuid 查重（`--field-ids` 只取两列），过滤已入表条目
4. `record query` 拉回截止日期 `before` 今天的记录 → 本地筛出未完成且非本次会议的 → 预览「📋 上次遗留」区
5. 预览确认 → `record create` 写新增；用户勾选遗留项 → `record update` 回写状态（两次独立确认）
6. 单独确认建待办 → 仅对状态为未开始/进行中且有负责人的条目，逐条 `dws todo task create --title "<行动项>" --executors <userId> --due "<截止ISO>" --priority 20 --format json`

### 示例 3: 用户未指定会议（默认一周候选 + 多选合并）

用户说: "帮我把会议行动项管起来"

执行步骤:
1. `dws minutes list all --start "<执行日减7天ISO>" --end "<当前时刻ISO>" --limit 30 --format json` 拉最近一周听记（**必须传 --limit，默认仅 10 会截断**）
2. `dws minutes get batch --ids <uuid1,uuid2,...> --format json` 批量补齐参与人数与听记状态
3. 展示候选卡片（多选，最多 10 项）：按序号/主题/时间/人数 + 可提取标注（有听记/转写中/无听记）
4. 用户选 "1,3" → 两场会议各自走 B→C，合并预览后一次确认，写入同一张「会议行动项汇总-YYYYMMDD」表，每条的「来源标识」分别带各自的 taskUuid，回执按会议分组

## 错误处理

| 错误 | 原因 | AI 应该怎么做 |
|---|---|---|
| 听记检索无结果 | 默认一周窗口内无会议或关键词过窄 | 先扩大时间范围（如最近一个月）或去掉 query 重试；仍无结果则请用户确认会议名称，或确认该会议是否开启了闪记/听记 |
| 候选列表被 `--limit` 截断 | 时间窗内会议数超过 limit 且未翻页 | 用 `--cursor` 翻页补全；确实超量时卡片取前 9 项并如实标注"共 N 场"，禁止静默丢弃 |
| 听记状态为转写中 | 会议刚结束，AI 转写未完成 | 标注「转写中，暂不可提取」并告知稍后重试；禁止把空 todos/summary 当作"本场无行动项" |
| `get batch` 报无权限 | batch 仅限听记创建者调用，非本人发起的共享听记必报 `user is not minutes creator` | 人数降级：日程参会人数补位，仍无则显示"—"；但**提取不受影响**——共享听记单条 `get info/todos/summary/transcription` 全部可用（已实测），选定后正常走 B 阶段；禁止阻断流程、逐个轮询补人数，或暗示"非本人发起的会议不行" |
| 用户选了"无听记"会议 | 该会议未开听记或未共享 | 如实告知无内容源可提取，引导开启 AI 听记或请发起人共享；不得用日程标题臆造行动项 |
| `get todos` 返回空 | 系统未从会议中识别出待办 | 正常回退：以 summary 为主料由 AI 自行提取行动项，并在预览中注明"由摘要提取" |
| summary 也无行动项线索 | 会议偏讨论/宣讲性质 | 征得用户同意后拉 transcription 兜底；仍无则如实告知"本场会议未发现可跟踪的行动项" |
| 责任人多个同名 | `contact user search` 多命中 | 展示候选（姓名+部门）请用户选择，选定前该条负责人留空 |
| 责任人搜索无结果 | 外部参会人或昵称 | 不臆造：user cell 不写，姓名降级写入备注列（"负责人待认领：XX"），回执「未匹配人员清单」列出 |
| 截止时间为"尽快/ASAP" | 无法折算为绝对日期 | 不硬编日期：截止日期留空，回执「待确认清单」列出请用户定期限 |
| 推断截止早于今天 | 会议基准换算结果已过期 | 仍按会议基准写入，回执标注「已过期」提醒用户确认是否顺延 |
| `record create` 部分失败 | 单条 cells 格式错误（常见：user 字段缺 corpId、日期传了相对时间） | 检查失败条目的 cells 格式并修正重试；向用户报告成功/失败明细，不得静默吞掉失败 |
| 复用表字段类型冲突 | 既有"负责人"列是 text 类型 | 人员/日期/单选三类字段类型不对会废掉筛选/提醒/看板，必须向用户明确提示降级后果，同意后才降级为字符串写入 |
| 重复入表 | 同一会议跑过两次 | 依赖 E 阶段查重：按「来源标识」`<taskUuid>#<todoId>` 精确比对命中则跳过，回执标注"已存在"；摘要提取项（`#summary`）退化为同一 taskUuid 内比标题 |
| 用户手输表名搜不到 | 名称不准或无权限 | 请用户确认名称或直接提供表格链接（可从链接解析 baseId）；禁止拿相似名的表当作命中直接写入 |
| `base search` 命中多个同名 Base | 组织内存在重名表格 | 以选择卡片列出候选（Base 名 + 区分信息）请用户确认，禁止默认取第一个 |
| `base create` 权限错误 | 无创建权限或目录受限 | 提示用户改为提供一个已有 Base 的链接/名称来承接 |
| `record create` 报无写权限 | 对该表仅有只读/评论权限 | 如实告知无写入权限，引导申请编辑权限或改选其他表；禁止反复重试 |
| `view create` 建视图失败 | config 的 filter/sort/group 结构不合法 | 先 `view get` 读回既有视图 config 作模板改写；仍失败则只建 Kanban 并告知筛选视图需手动配置（不得因此阻断主流程）|
| 重跑/重试建出重复「状态看板」 | 无条件执行 `view create`，未做幂等检查 | 建前 `view get` 读目录、同名跳过并复用 viewId；建后读回确认无同名视图 |
| `get-self` 返回空 | 拿不到本人 userId | 禁止从其他数据借 userId 猜"本人"：跳过「我负责的未完成」视图并告知用户，不得因此阻断主流程 |
| `record update` 部分失败 | recordId 已被删除或状态选项名不存在 | 逐条报告失败原因；选项名必须取自 `table get` 返回的实际 options，不得自造 |
| 待办创建失败 | executors userId 无效 | 核对 userId 是否来自 get-self/user search 的真实返回；逐条报告失败原因 |
