# Changelog

## v1.2.0 (2026-08-11)

依据 QwenWork 真机测试轮（合同证据清单场景，普通/高级模型两次执行）整改 3 项：

1. **阶段一分类与完整性检查改为必须输出**：进入阶段二前必须输出①材料分类结果（证据类型+证明目的分组）②证据链完整性提示（已有+建议补充清单）；即使只提供单一合同也必须提示补充付款凭证/交付签收单/往来函件/验收报告等；提示不阻塞流程
2. **六项自查改为逐条必输出 + 门禁前置**：生成清单后须逐项输出六项自查结果（✅/❌），未输出不得运行门禁脚本；明确自查（管内容质量）与门禁（管格式合规）分工，不得互相替代
3. **docx 页数提取指引**：页码计算方法新增第 0 步——须同时统计 lastRenderedPageBreak 与 w:br type="page" 两种分页符，先打印总页数做校验基准，禁止用目录页码粗估，清单页码总跨度不得超过文档实际页数

## v1.1.0 (2026-08-11)

- 新增交付门禁脚本 `scripts/validate_evidence_list.py`（支持 md/txt/docx，docx 用 zipfile 直接解析表格文字，无额外依赖）。拦截判据：①必备五列缺失（序号/证据名称/页码/原-复印件/证明对象）；②证明对象为空/占位/过短；③页码重排违规（未自第 1 页起、断档、重叠、倒序）；④序号不连续；⑤原/复印件未标注；⑥落款缺项或提交日期仍为模板占位；⑦表格空壳（仅表头或全占位行）；⑧可选 `--evidence-count` 防漏项。退出码 0=通过 / 1=拦截（逐条明细）/ 2=输入错误
- 修正 docx 口径矛盾：阶段五改为三档降级——首选预置脚本 `scripts/generate_evidence_docx.py`（唯一许可生成路径）、次选 `docx` skill、兜底 Markdown；命令示例与脚本真实签名对齐（`--title` / 可重复 `--evidence` / `--submitter` / `--submit-date` / `--output` / `--json-input`），删除原「docx skill 首选 + dws doc create 降级」写法
- 门禁挂点：阶段三清单生成后（对 Markdown 自检）+ 阶段六交付前（对最终 .docx 复核），未通过禁止交付
