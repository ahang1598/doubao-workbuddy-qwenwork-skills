# 管理 SKU、上传衣服 & 切换数据源

## 上传衣服流程

### 步骤 A：收集图片

使用 `ask_human` 提示用户上传衣服照片：
```
ask_human: 👗 请上传您想要添加到试衣间的衣服照片。
📌 照片要求：
- 必须是衣服照片（平铺拍摄或挂起拍摄均可）
- ❌ 不接受非衣服类物品的照片
（支持图片 URL 或本地文件路径）
```

### 步骤 B：图片审核（严格校验）

收到图片后 **必须严格审核**，依次检查：
1. **违规内容检查**：色情、暴力、政治敏感 → 拒绝，提示"该图片包含不适当内容，请上传合规的衣服照片"
2. **是否为衣服**：非衣服（鞋子、包包、食物、风景等）→ 拒绝，提示"请上传衣服照片，当前图片不是衣服"

> ⚠️ 审核必须在任何后续操作之前完成。不合格则持续提示重新上传，直到收到合格图片。

审核通过后，使用 `dt_media_upload` 将图片上传到钉钉，得到下载链接（`https://down.dingtalk.com/media/xxx.png`）。

### 步骤 C：分析衣服特征

观察图片，提取以下结构化特征：

| 字段 | 说明 | 示例 |
|------|------|------|
| `name` | 衣服名称，简洁描述款式 | "经典白衬衫"、"宽松牛仔外套" |
| `desc` | 详细描述（面料、剪裁、工艺） | "优质棉质面料，透气修身显气质" |
| `category` | 品类：上衣/下装/外套/连衣裙/裤子/裙子/内搭/配件 | "上衣" |
| `color` | 主色调，尽量精确 | "白色"、"藏蓝色"、"卡其色" |
| `style` | 整体风格 | "通勤简约"、"休闲街头"、"法式优雅" |
| `features` | 核心特征标签（3-6个） | ["透气棉质", "修身剪裁", "百搭经典"] |
| `occasion` | 适合场合（可多选）：职场/日常/约会/运动/聚会/旅行/正式场合 | ["职场", "日常"] |
| `season` | 适合季节（可多选）：春季/夏季/秋季/冬季 | ["春季", "夏季"] |
| `sellingPoints` | 一句话核心卖点 | "高级垂感面料，显瘦修身，百搭不挑人" |

> ⚠️ `features` 是穿搭推荐的核心依据，需从面料质感、版型特点、视觉风格、功能性等多维度提炼，至少 3 个标签。`occasion` 和 `season` 至少各选 1 个。

### 步骤 D：收集卖点

```
ask_human: 👗 衣服分析完成！请问这件衣服有什么特别的卖点想要突出吗？比如面料、工艺、设计亮点等。
（直接输入卖点，或回复"没有"由我来帮您生成）
```

- 用户提供了卖点 → 使用用户提供的内容作为 `sellingPoints`
- 用户回复"没有" → 根据图片分析自动生成一句简洁有吸引力的卖点描述

### 步骤 E：上传到店铺

```bash
python scripts/cli.py try-on upload \
  --name "衣服名称" \
  --image-url "图片URL" \
  --desc "衣服描述" \
  --category "品类" \
  --color "颜色" \
  --style "风格" \
  --features "特征1" "特征2" "特征3" \
  --occasion "场合1" "场合2" \
  --season "季节1" "季节2" \
  --selling-points "衣服卖点描述"
```

### 步骤 F：输出结果

上传成功后，简洁展示：
1. ✅ 衣服已成功添加到店铺试衣间
2. 📱 提醒所有衣服共享同一组店铺二维码（无需重新生成）
3. 💡 穿搭建议（基于 occasion 和 season 给出一句话搭配提示）
4. 📤 提示可继续上传更多衣服

## 切换 SKU 数据源

### 切换到多维表模式

用户需提供多维表链接（格式如 `https://alidocs.dingtalk.com/i/nodes/xxx?...`），系统自动提取 dentryUuid 并完成配置。

```bash
python scripts/cli.py try-on sku-source --aitable-url "https://alidocs.dingtalk.com/i/nodes/QPGYqjpJYRyab0nxsZpNLEeO8akx1Z5N?iframeQuery=entrance%3Ddata%26sheetId%3DhERWDMS%26viewId%3DqvGDAH2"
```

### 切换回系统数据库模式

```bash
python scripts/cli.py try-on sku-source --source mongodb
```

### 数据源说明

- **多维表模式**：SKU 数据从多维表读取，店主可在多维表中直接管理商品数据。
- **系统数据库模式**（默认）：SKU 数据从系统数据库读取，通过本技能上传功能管理。
- 两种模式数据互相独立，切换不会影响另一种模式下的数据。
