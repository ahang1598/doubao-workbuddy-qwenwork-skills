# 当事人信息格式规范

> 仅在 SKILL.md Step 5（当事人信息标准化）阶段读取。本文档规定各类当事人的法定列明要素、格式规范及「企业工商信息查询」连接器自动补全规则。所有规则以《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》第 209 条为基准，并结合各地立案实践制定。

---

## 一、自然人当事人

### 1.1 法定列明要素（全部必填，缺项须向用户补全）

| 要素 | 规范表述 | 注意事项 |
|------|----------|----------|
| **姓名** | 依居民身份证或户籍证明确定 | 有别名、曾用名或化名的，在姓名后用**圆括号**注明，**不加引号**，如「张三（张小三）」 |
| **性别** | 明确标注「男」或「女」 | 不得省略，不得用「先生」「女士」代替 |
| **出生日期** | 规范表述为「××××年×月×日出生」 | **严禁**简写为「年龄」或「××岁」 |
| **民族** | 依身份证或户籍信息填写 | 不带「族」字（脚本自动添加），如填「汉」而非「汉族」 |
| **住所** | 精确到具体**门牌号**，格式为「住××（具体地址）」 | 若实际居住地址与身份证住址不一致，需**同时注明**「现住××（现地址）」 |
| **联系方式** | 可写明手机号码、邮箱等，便于法院联系 | 至少提供一种联系方式 |
| **公民身份号码** | 18 位居民身份证号码 | 推荐填写，立案时法院通常要求 |

### 1.2 国籍特殊情形

| 情形 | 列明方式 |
|------|----------|
| **中国大陆居民** | 无需单独注明国籍，默认中国国籍 |
| **外国人** | 写明国籍（如「美国国籍」），并写明相应国家**护照号码** |
| **无国籍人** | 注明「无国籍」，写明相关身份证明文件号码 |
| **香港特别行政区居民** | 注明「香港特别行政区居民」，写明**回乡证/香港永久性居民身份证号码** |
| **澳门特别行政区居民** | 注明「澳门特别行政区居民」，写明**澳门居民身份证号码** |
| **台湾地区居民** | 注明「台湾地区居民」，写明**台湾居民来往大陆通行证号码** |

### 1.3 生成效果示例

**标准自然人（大陆居民）：**
> 原告：张三（张小三），男，汉族，1985年3月12日出生，公民身份号码：110101198503120011，住北京市朝阳区建国路88号3号楼501室，现住北京市海淀区中关村大街99号1单元302室，联系电话：13800138000，电子邮箱：zhangsan@example.com。

**外国人：**
> 被告：John Smith，美国国籍，护照号码：G12345678，住北京市朝阳区建国路88号，联系电话：13900139000。

**港澳台居民：**
> 原告：李明，香港特别行政区居民，香港永久性居民身份证号码：A123456（7），住香港特别行政区九龙旺角弥敦道500号，联系电话：13800138000。

### 1.4 JSON 字段对应

```json
{
  "type": "natural_person",
  "name": "张三",
  "alias": "张小三",
  "gender": "男",
  "ethnicity": "汉",
  "birth_date": "1985年3月12日",
  "id_number": "110101198503120011",
  "address": "北京市朝阳区建国路88号3号楼501室",
  "current_address": "北京市海淀区中关村大街99号1单元302室",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "nationality": "",
  "passport_no": "",
  "cert_no": ""
}
```

> `nationality` 字段：大陆居民留空；外国人填「美国」等；港澳台居民填「香港特别行政区居民」「澳门特别行政区居民」「台湾地区居民」。
> `cert_no` 字段：港澳台居民的证件号码（回乡证/澳门身份证/台湾通行证号码）。
> `alias` 字段：别名/曾用名/化名，有则填写，脚本自动添加圆括号。

## 二、法人当事人

法人包括：有限责任公司、股份有限公司、国有企业、机关法人、事业单位法人、社会团体法人等。

### 2.1 法定列明要素

| 要素 | 规范表述 | 注意事项 |
|------|----------|----------|
| **名称** | 使用营业执照/登记证书上的**全称** | 不得使用简称或商号 |
| **住所** | 注册地址，精确到**街道/门牌号** | 不接受仅到区/县级的地址 |
| **统一社会信用代码** | 18 位，格式如「91110108MA001ABC23」 | 必填，「企业工商信息查询」能力自动补全 |
| **联系方式** | 可写明法定代表人或单位的联系方式 | 推荐填写，便于法院送达 |
| **法定代表人** | **另起一行**写明姓名、职务 | 格式：「法定代表人：张××，董事长」 |

### 2.2 生成效果示例

```
被告：测试科技有限公司，住所地：北京市海淀区大关街道中关村大街1号，统一社会信用代码：91110108MA001ABC23，联系电话：010-88886666。
法定代表人：李四，董事长。
```

### 2.3 JSON 字段对应

```json
{
  "type": "legal_person",
  "name": "测试科技有限公司",
  "address": "北京市海淀区大关街道中关村大街1号",
  "uscc": "91110108MA001ABC23",
  "legal_rep_name": "李四",
  "legal_rep_title": "法定代表人",
  "rep_position": "董事长",
  "phone": "010-88886666"
}
```

## 三、合伙组织当事人

合伙组织分为**个人合伙**和**合伙企业**两种，列明方式不同。

### 3.1 个人合伙

以**全体合伙人**为当事人，每位合伙人的写法同自然人（见§一）。

有字号的：在最后一位合伙人信息后，另起一行注明字号和经营场所：

```
原告一：张三，男，汉族，1980年1月1日出生，住……
原告二：李四，男，汉族，1982年5月5日出生，住……
（经营字号：北京华强电器行，经营场所：北京市朝阳区XX路XX号）
```

### 3.2 合伙企业

以**合伙企业名称**为当事人，写明名称、住所、统一社会信用代码、联系方式，**另起一行**写明执行事务合伙人的姓名或名称：

- 执行事务合伙人为**自然人**：`执行事务合伙人：张三`
- 执行事务合伙人为**非自然人**（公司等）：须同时写明委派代表，格式：`执行事务合伙人：XXXX有限公司（委派代表：张三）`

**生成效果示例：**
```
被告：北京华强投资合伙企业（有限合伙），住所地：北京市朝阳区XX街道XX路XX号，统一社会信用代码：91110105XXXXXXXXXX，联系电话：010-66668888。
执行事务合伙人：华强管理有限公司（委派代表：王五）。
```

### 3.3 JSON 字段对应

**合伙企业：**
```json
{
  "type": "partnership_enterprise",
  "name": "北京华强投资合伙企业（有限合伙）",
  "address": "北京市朝阳区XX街道XX路XX号",
  "uscc": "91110105XXXXXXXXXX",
  "phone": "010-66668888",
  "gp_name": "华强管理有限公司",
  "gp_delegate": "王五"
}
```

**个人合伙（有字号）：**
```json
{
  "type": "partnership_individual",
  "partners": [
    {"name": "张三", "gender": "男", "ethnicity": "汉", "birth_date": "1980年1月1日", "address": "..."},
    {"name": "李四", "gender": "男", "ethnicity": "汉", "birth_date": "1982年5月5日", "address": "..."}
  ],
  "trade_name": "北京华强电器行",
  "business_address": "北京市朝阳区XX路XX号"
}
```

## 四、个体工商户当事人

### 4.1 有字号的个体工商户

以**营业执照上登记的字号**为当事人，写明字号和住所（经营场所），**另起一行**注明经营者的姓名、性别、出生日期、民族、住所：

```
被告：朝阳区华强电器商行（个体工商户），经营场所：北京市朝阳区XX街道XX路88号。
经营者：王五，男，汉族，1975年6月10日出生，住北京市朝阳区XX路XX号XX室。
```

### 4.2 无字号的个体工商户

以**营业执照上登记的经营者**为当事人，写法同自然人（见§一），在姓名后括注「（个体工商户）」：

```
被告：王五（个体工商户），男，汉族，1975年6月10日出生，住北京市朝阳区XX路XX号XX室，联系电话：13900139000。
```

### 4.3 登记经营者与实际经营者不一致

需将**登记经营者与实际经营者**均列为共同诉讼人（共同被告或共同原告）：

```
被告一：朝阳区华强电器商行（个体工商户），经营场所：……
经营者（登记）：王五，……
被告二：赵六（实际经营者），男，……
```

### 4.4 JSON 字段对应

**有字号：**
```json
{
  "type": "individual_business",
  "has_trade_name": true,
  "name": "朝阳区华强电器商行",
  "address": "北京市朝阳区XX街道XX路88号",
  "operator_name": "王五",
  "operator_gender": "男",
  "operator_ethnicity": "汉",
  "operator_birth_date": "1975年6月10日",
  "operator_address": "北京市朝阳区XX路XX号XX室",
  "phone": "13900139000"
}
```

**无字号：**
```json
{
  "type": "individual_business",
  "has_trade_name": false,
  "name": "王五",
  "gender": "男",
  "ethnicity": "汉",
  "birth_date": "1975年6月10日",
  "address": "北京市朝阳区XX路XX号XX室",
  "phone": "13900139000"
}
```

## 五、非法人组织当事人

非法人组织包括：未取得法人资格的分支机构、村民委员会、居民委员会、业主委员会、基金会（未登记为法人的）等。

### 5.1 法定列明要素

| 要素 | 规范表述 | 注意事项 |
|------|----------|----------|
| **名称** | 使用**登记注册文件上的全称** | 不得使用简称 |
| **住所** | 以**主要办事机构所在地**为准，格式同法人 | 精确到街道/门牌号 |
| **统一社会信用代码** | 同法人 | 有则填写 |
| **代表人** | **另起一行**写明姓名、职务 | 使用「**代表人**」称谓，**严禁**用「负责人」或「诉讼代表人」 |
| **联系方式** | 可写明代表人或单位的联系方式 | — |

### 5.2 生成效果示例

```
被告：北京市朝阳区劲松街道劲松社区居民委员会，住所地：北京市朝阳区劲松街道劲松南路1号，联系电话：010-67778888。
代表人：陈七，主任。
```

### 5.3 JSON 字段对应

```json
{
  "type": "unincorporated",
  "name": "北京市朝阳区劲松街道劲松社区居民委员会",
  "address": "北京市朝阳区劲松街道劲松南路1号",
  "uscc": "",
  "rep_name": "陈七",
  "rep_title": "代表人",
  "rep_position": "主任",
  "phone": "010-67778888"
}
```

## 六、未成年人当事人

未成年人作为原告时，由**法定代理人**代为参加诉讼。法定代理人通常为父母（共同监护时可只列一方但需说明）。

```json
{
  "type": "minor",
  "name": "张小明",
  "gender": "男",
  "birth_date": "2015年6月1日",
  "id_number": "...",
  "address": "...",
  "guardian": {
    "name": "张大明",
    "relation": "之父",
    "id_number": "...",
    "address": "...",
    "phone": "..."
  }
}
```

**生成效果：**
> 原告：张小明，男，2015年6月1日出生（未成年人），公民身份号码：…，住…。
> 法定代理人：张大明，系原告之父，公民身份号码：…，住…，联系电话：…。

## 七、多原告 / 多被告 / 第三人排列顺序

1. **原告**：主要权利人在前；共同共有时按身份顺序（夫妻、父母子女、合伙人）
2. **被告**：主要责任人在前，担保人/连带责任人在后；多个加害人按责任比例由重到轻
3. **第三人**：有独立请求权第三人列前，无独立请求权第三人列后

JSON 中通过 `plaintiffs` / `defendants` / `third_parties` 数组顺序控制。

## 八、信息缺失时的处理

如用户未提供以下要素，**应一次性向用户请求补全**（不要反复打扰）：

| 主体类型 | 必须补全 | 工商信息查询能力可自动补全 |
|---------|---------|----------------|
| 自然人 | 姓名、住所、联系电话 | — |
| 法人 | 名称 | USCC、法定代表人、注册地址（含街道） |
| 合伙企业 | 名称 | USCC、执行事务合伙人、注册地址 |
| 非法人组织 | 名称、住所、代表人姓名 | USCC |
| 个体工商户 | 字号/经营者姓名、经营场所 | 经营者信息（如有工商登记） |
| 未成年人 | 姓名 + 法定代理人全部要素 | — |
| 涉外 | 姓名、国籍、护照/证件号、在华地址 | — |

> **重要**：身份证号、USCC 等敏感信息，直接采用用户提供的内容，**不要由模型自行编造**。如用户暂未提供，在 JSON 中省略该字段，并在交付时提醒用户补齐后方可立案。

## 九、「企业工商信息查询」能力全面调取规范

### 9.1 触发条件

当案件中存在**企业主体**（法人、合伙企业、非法人组织、个体工商户）当事人，**必须通过「企业工商信息查询」能力全面调取并填入**，无需等待用户手动提供。不得只取部分字段就收手，须把下列全部可用字段取齐（**取齐可能需要多次调用，不等于一次调用**）。

**能力语义**（两段能力，缺一不可）：

1. 「企业主体定位 / 模糊搜索」能力——输入企业名称（可能是简称、品牌名、部分名称），返回候选企业清单（企业全称及该连接器内部的主体标识）。用于确认唯一企业全称；
2. 「工商登记信息查询」能力——以已确认的企业全称（或主体标识）为入参，返回 USCC、法定代表人、注册地址（须含街道级）、经营状态等登记字段。

不写死任何具体工具名或供应商，运行时按 §9.2 的「探测三段式 + 取数两步」流程动态选用。

> ⚠ **不得跳过第 1 段能力直接调第 2 段**：多数工商类连接器的登记信息接口要求精确企业全称或先行获得的主体标识，直接传简称/未定位的名称通常返回空数据或错误命中，反而把本可核验的案件推入 §9.4 降级区。

### 9.2 调用规范（探测三段式 + 取数两步，严格按序执行）

**第一步：探测可用连接器**

```
qwenwork_mcp_tool_list(keyword="企业 / 工商 / 企业信息 / 工商登记 / 企查查 / 天眼查 / 元典 / 启信宝 / registration / company / enterprise / qcc / tianyancha / qibook / yuandian")
```

关键词覆盖能力中文名、能力英文名与同类供应商的中英文名，建议逐词探测以免遗漏。

**第二步：语义匹配 + schema 验证（不写死工具名）**

同一连接器下须分别匹配出**两类**能力：

- 「企业主体定位 / 模糊搜索」能力：工具名或 description 含「企业搜索」「模糊搜索」「主体定位」「企业名称检索」「company search」「fuzzy search」等语义，入参为关键词，返回**候选企业清单**；
- 「工商登记信息查询」能力：工具名或 description 含「企业登记」「工商信息」「工商登记信息」「企业基本信息查询」「company registration」「basic profile」等语义，入参为企业全称或主体标识，返回登记字段。

匹配后用 `qwenwork_mcp_tool_get` 确认两类工具的 schema：定位类须返回企业全称（及可用于下游的主体标识），登记类须返回 USCC、法定代表人、注册地址；schema 不符则切下一家候选。

**第三步：先定位唯一主体（不可跳过）**

用 `qwenwork_mcp_tool_call` 调用「企业主体定位 / 模糊搜索」能力，入参为用户提供的企业名称/简称，取回候选清单：

- **唯一精确命中** → 锁定该企业全称（及主体标识），进入第四步；
- **返回多个候选** → **必须把候选清单完整展示给用户，等待用户明确选定后再继续；严禁自行选择排名第一或"看起来最像"的候选**；
- **零命中** → 提示用户核对企业名称拼写（营业执照全称）后重试；仍零命中的按 §9.4 处理。

> 起诉状当事人块中的企业名称，必须使用本步骤确认的**营业执照全称**，不得使用简称、品牌名或股票简称。

**第四步：取工商登记字段并填入**

以第三步锁定的企业全称（或主体标识）为入参，调用「工商登记信息查询」能力，取回以下字段并逐一填入 JSON；多家连接器可用时按匹配度（语义贴合度与字段完整度）选用，首选出错或返回字段不全时切下一家：

| 字段 | 填入 JSON 位置 |
|------|--------------|
| 企业全称 | `name` |
| 统一社会信用代码 | `uscc` |
| 注册地址（含街道/门牌） | `address` |
| 法定代表人/执行事务合伙人 | `legal_rep_name` / `gp_name` |
| 法定代表人职务 | `rep_position` |
| 企业联系电话 | `phone` |
| 经营状态 | 仅用于风险预警，不填入起诉状 |

**字段缺口续探（重要）**：部分连接器的「基础画像/基本信息」类能力**不返回 USCC**（USCC 可能只出现在定位类能力的候选清单中，或需要该连接器下另一个专项能力才能取到）。因此：

- 若登记类能力返回结果中缺少 USCC，**先回看第三步候选清单是否已带 USCC**；
- 仍缺失时，**继续在同一连接器下探测可提供 USCC 的其他能力**（如"企业能力清单/可用维度查询 + 通用维度调用"两段式、或"企业详情/扁平详情"类能力），按第二步的语义匹配 + schema 验证流程选用；
- 同一连接器全部能力都取不到 USCC 时，再切下一家连接器；所有连接器均无法提供时按 §9.4 处理。

> ⚠ **严格禁止**：不得调用未经探测/匹配成功的工具，**禁止编造或猜测工具名称**，禁止凭模型记忆编造企业登记信息。

**第五步：核验与标注（标注只进交付说明，不进文书正文）**

- 连接器返回的注册地址即为起诉状中「住所地」的填写依据；
- 若返回的地址不含街道层级，**JSON 的 `address` 字段仍填连接器返回的原文（不得追加任何括注）**，同时在**交付说明/质量自检报告**中列明「住所地缺街道层级，立案前须补全」，并提醒用户核实；
- 企业经营状态如为「注销」「吊销」「撤销」，须向用户提示主体资格风险，并确认是否继续。

> ❗ **正文洁净原则（强制）**：`uscc` / `address` / `legal_rep_name` 等字段的值会被 `scripts/generate_complaint.py` **原样拼进起诉状当事人段落**。因此这些字段内**只允许**填真实值或中性占位「（待补充）」；**严禁**写入「（用户自报，待核验）」「（待补全街道）」「（未核验）」等任何核验状态标注——所有核验状态标注一律写在**交付说明/质量自检报告**里。

### 9.3 住所地完整性要求（起诉状立案规范）

| 层级 | 示例 | 必填 |
|------|------|------|
| 省/直辖市 | 浙江省 / 北京市 | ✅ |
| 市（地级市） | 杭州市 | ✅ |
| 区/县 | 拱墅区 | ✅ |
| **街道/镇** | **大关街道** | ✅（**不可省略**） |
| 具体地址 | 祥园路88号 | 推荐 |

> ❌ 错误示例：「浙江省杭州市拱墅区×××路×号」——缺少街道，不符合起诉状规范
> ✅ 正确示例：「浙江省杭州市拱墅区大关街道祥园路88号」

### 9.4 降级（A 档·连接器不可用时禁止编造）——**全技能唯一真源**

> 本节是本技能企业主体信息降级处理的**单一真源**。`SKILL.md` Step 5.5 与 `references/templates/contracts/contract-general.md` §八自检项均引用本节，不另行复述出口清单；如需调整降级话术，只改本节。

**触发情形（三种，处理口径相同）**：

1. 探测不到任何可用的企业工商信息查询连接器；
2. 探测到但调用失败（连接失败、鉴权失败、工具报错、零命中）；
3. 调用成功但**关键字段不全**（USCC / 法定代表人 / 注册地址含街道 任一缺失，且已按 §9.2 第四步「字段缺口续探」逐家尝试仍取不到）。

当事人信息须提交法院，准确性即价值。上述任一情形下，**严禁编造任何企业信息**，必须按以下三个出口处理：

**出口 1（首选）：提示用户启用连接器后重试**

> 未检测到可用的企业工商信息查询连接器（或连接器调用失败）。请前往千问办公『设置 → 连接器』启用工商类连接器（企业/工商信息查询类）后重试。

**出口 2：由用户手动提供缺失字段**

用户手动提供 USCC、法定代表人姓名、注册地址（含街道）、联系电话等字段时，**照原样填入 JSON，不得在字段值内追加任何括注**；同时必须在**交付说明与质量自检报告**中单列一条：

> ⚠ 企业主体工商核验状态：**用户自报，未经连接器核验**（字段：USCC / 法定代表人 / 住所地 …）。**立案前须由律师核对营业执照原件或国家企业信用信息公示系统（gsxt.gov.cn）**，核对无误后方可提交法院。

**出口 3：用户亦未提供的字段，正文用中性占位**

在起诉状当事人块中以「（待补充）」占位（该占位为立案窗口可接受的中性写法），并在交付说明中列明待补字段清单，不得编造任何信息。

**❗ 标注位置铁律（防正文污染）**

`uscc` / `address` / `legal_rep_name` 等字段值会被 `scripts/generate_complaint.py` 原样拼进起诉状当事人段落，因此：

| 位置 | 允许写什么 | 禁止写什么 |
|------|-----------|-----------|
| JSON 字段值 / 起诉状正文 | 真实值；或中性占位「（待补充）」 | 「（用户自报，待核验）」「（待补全街道）」「（未核验）」等任何核验状态标注 |
| 交付说明 / 质量自检报告 | 全部核验状态标注、待补字段清单、立案前核对提示 | — |

> 反面示例（**禁止**，立案窗口不接受）：`统一社会信用代码：91330105MA2xxxxxxx（用户自报，待核验）`、`住所地：浙江省杭州市拱墅区祥园路88号（待补全街道）`
> 正确做法：正文写 `统一社会信用代码：（待补充）` 或用户自报的真实值本身，核验状态另在交付说明中提示。
