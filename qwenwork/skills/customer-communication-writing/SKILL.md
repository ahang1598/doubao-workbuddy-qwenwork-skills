# 客户沟通话术写作

## 总原则

先给用户能直接复制发送的话术，再给必要说明。用户要的是客户沟通短文时，不要先输出方法论、销售策略或长篇分析。

用户提供的角色、客户阶段、渠道、顾虑、事实、数据、产品信息和限制条件是写作边界。不得编造客户案例、合作关系、价格权益、处理时限、补偿承诺、政策依据或已完成动作。缺少关键事实但仍可起草时，用 `[待补充：客户名称]`、`[待补充：产品差异点]` 这类占位符承接。

本技能风格应像一名懂业务的同事：自然、克制、短句清楚、能推进下一步。不使用夸张营销词，不用空泛口号，不把客户沟通写成品牌宣传稿。

## 执行流程

1. 判断任务类型：新写、改写、润色、压缩、扩写、按渠道生成、多版本生成、异议回应、售后安抚、FAQ 整合、内部协作话术或模板化话术。
2. 提取硬约束：说话人角色、接收对象、关系阶段、沟通渠道、核心目标、客户顾虑、事实依据、语气、语言、长度、版本数量、禁止承诺事项和下一步动作。
3. 选择参考材料：
   - 销售开发、拜访建联、老客回访、群发、跟进催办、内部协作和短句改写：读取 `references/scenario-playbook.md`。
   - 续费挽回、报价异议、竞品对比、老板汇报、售后安抚、自动回复、FAQ、差评复盘和升级处理：读取 `references/objection-support-playbook.md`。
   - 电话、微信私聊、客户群、邮件、英文即时回复、语音提示、FAQ 或模板字段输出：读取 `references/channel-format.md`。
   - 交付前终检、评估集回归或用户强调“不要小作文”“直接写”：读取 `references/quality-checklist.md`。
4. 先搭话术骨架，再写具体句子：
   - 销售和拜访：信任入口 -> 业务问题 -> 价值差异 -> 低压力 CTA。
   - 异议和挽回：承认顾虑 -> 换到总成本或风险视角 -> 给证据或可验证动作 -> 约下一步。
   - 售后和客服：共情 -> 当前状态 -> 正在做的动作 -> 可执行节点 -> 不越界承诺。
   - 催办和群消息：共同目标 -> 事实或截止点 -> 需要对方做什么 -> 未完成影响 -> 支持入口。
   - 润色和短句改写：保留原意 -> 压缩冗余 -> 补足关键事实 -> 控制为用户要求的长度。
5. 严格按用户要求输出版本数量、标题、语言和格式。用户要求“三个版本”就给三个；用户要求“只输出一段”就只给一段。
6. 终稿前检查是否真实可发：读起来是否像真人业务沟通、是否处理了客户顾虑、是否有下一步动作、是否没有虚假承诺。

## 默认判断

用户未指定渠道时，默认按微信私聊或通用短消息输出；如果内容明显是外呼、拜访、群通知、邮件或客服自动回复，则按该渠道处理。

用户未指定长度时，默认短而完整：微信私聊 80 到 180 字，电话开场白 20 到 45 秒，群消息 80 到 160 字，客服自动回复每条 1 到 2 句。

用户未给产品细节时，不要硬造卖点。使用可替换表达，例如“结合你们现在的履约效率、客户留存和成本控制目标”，或用占位符标记需要补充的差异点。

用户情绪明显不满或强调“不要空泛”“不要小作文”“直接写”时，减少铺垫和解释，直接给话术正文。

## 交付要求

起草类任务：先输出可复制话术。需要多个渠道或多个语气时，用清晰小标题区分。

改写类任务：只改用户给定话术，不擅自改掉关键事实、产品名、责任方、动作和时间点。除非用户要求说明，否则不要额外解释太多修改思路。

异议回应类任务：先承认对方顾虑，再回应价值差异。不得攻击竞品，不得把“贵”简单解释成“质量更好”，要落到总成本、风险、迁移成本、服务稳定性、数据资产或可验证结果。

售后安抚类任务：先接住情绪，再给处理动作。不得承诺一定退款、一定赔付、一定成功、一定时限，除非用户明确提供了可承诺依据。

电话脚本类任务：写出第一句、第二句、客户追问时的接法、客户没时间时的收尾。句子要能念出来，不写成书面稿。

群消息和内部协作类任务：礼貌但有推动力，写清截止时间、提交内容、未完成影响和联系人。避免甩锅、指责和情绪化表达。

英文话术：保持自然、真诚、清楚，不强行邮件格式；用户说不要邮件格式时，不输出 subject、dear、best regards。
