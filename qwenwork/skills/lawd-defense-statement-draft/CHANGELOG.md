## v1.1.0 (2026-08-10)

指令自相矛盾修复 + 交付门禁落到流程内：

- **消除硬编码技能名互斥（P1）**：区分两种场景——**输入侧识别**（识别上游传入的结构化产物）保留 Skill 名称以便精确匹配；**输出侧向用户推荐**只写能力描述、不写 Skill 名称。落点：输出 B 模板"后续建议"、下游推荐表、`Skill 串联`章节新增输入/输出两侧对照表、系统提示语规则 21 改写为同一口径（与规则 19 不再冲突）
- **A/B/C 编号与必选性统一（P1）**：`references/output-spec.md` 由「A=要素式必出 / B=传统式 / C=辅助提示」改为与 `SKILL.md` Phase 3 一致的「**A=传统式（必出）、B=答辩辅助提示（必出）、C=要素式（仅律师明确要求时出）**」，章节顺序同步重排；`examples/sales-contract/expected-output.md` 标号同步
- **交付形态改为「先 Markdown 过门禁、再转 Word」（P1）**：正式交付形态仍为 Word（.docx），但流程上先生成 Markdown 稿用于门禁校验，通过后转 docx；Markdown 中间稿不作为最终交付物。落点：Phase 3 交付形态说明、系统提示语规则 3a、`output-spec.md` 交付形态段
- **门禁指令进流程（P1）**：新增 **Phase 4.2 交付门禁**——对 Markdown 稿运行 `scripts/validate_answer.py --file <md> --claims N`，**退出码非 0 禁止交付**，通过后才转 docx；系统提示语规则 3b 改为与 Phase 4.2 呼应（此前门禁只写在系统提示语里，按流程走的 agent 看不到，可被静默绕过）
- **`--claims` 取值来源（P1）**：Phase 2 步骤 2.1 的产出增加「原告诉请条数 N」，供门禁参数取值
- **展示名对齐（P2）**：引用上游技能的中文名改为被引技能实际 `name_zh`——lawd-civlit-dispute-focus =「律师争议焦点分析」、lawd-evidence-chain-builder =「举证要点整理」、lawd-argument-chain-constructor =「论证逻辑梳理」、lawd-analysis-report =「案情法律分析报告」；串联表统一为「中文名（英文名）」风格
- **文档索引修正（P2）**：`examples/` 说明改为「买卖合同纠纷完整示例；其他案由目录为预留位，暂无示例内容」（原称"各案由示例"与实际空目录不符，目录保留）；补入 `scripts/validate_answer.py` 索引行
