# 宜搭总入口

本技能只负责分流。先保留用户的完整原始需求，再判断应该读取哪份 reference；读取后继续完成原始需求。

## 分流规则

### 创建或修改宜搭资源

当用户要创建、搭建、补齐或修改宜搭资源时，读取 [references/app-builder.md](references/app-builder.md)。

典型场景：

- 创建或搭建客户管理、项目管理、活动报名、工单、审批、台账、运营工作台等应用或系统。
- 新增或调整表单、字段、审批流程、业务规则、报表、权限、连接器、集成自动化或自定义页面。
- 开发、优化或发布宜搭自定义页面、工作台、看板、数据大屏。
- 基于已有宜搭应用、页面、表单链接或资源 ID 继续修改完善。

这个分支不检查宜搭连接器状态。

### 查询、分析或办理已有业务

当用户要查询或分析已有宜搭业务事实，或办理已经发布成业务 Action 的操作时，读取 [references/app-ask.md](references/app-ask.md)。

典型场景：

- 查询应用、表单、字段、schema、记录列表、表单数据、子表数据或流程任务。
- 统计指标、趋势、分布、排行、占比、异常、流程效率或审批耗时。
- 查询通讯录、应用管理员、表单权限、业务关系或血缘链路。
- 明确要求使用 `initialize_yida_app` 初始化单个宜搭应用图谱。
- 查找可办理的业务 Action，预览提案，并在用户明确确认后执行已发布 Action。

这个分支不执行 OpenYida CLI 安装、登录、创建、修改或发布流程。

### 混合诉求

仅当同一个原始请求要求在本轮同时完成以下两类结果时，才读取两份 reference：

- **问办结果**：查询或分析租户内已有业务事实，或办理已经发布的业务 Action。
- **搭建结果**：通过 OpenYida 创建、修改或发布宜搭资源定义或配置，例如应用、表单、字段、流程配置、页面、报表、权限、连接器、集成自动化。

按最终操作对象判定，不按是否发生写入判定：

- 创建、更新、删除业务记录，提交或审批流程，发送通知等，如果通过已经发布的业务 Action 办理，仍属于问办，不属于搭建。
- 调用已发布 Action 是问办；新增、修改或发布 Action 的定义与配置才属于搭建。
- 为完成搭建而定位应用、表单、字段、schema 或资源 ID，是搭建链路的正常准备步骤，不因此变成混合诉求。
- 查询后调用已发布 Action 仍是纯问办；只有请求中还包含宜搭资源定义或配置的建改，才是混合诉求。

混合诉求通常先读取 [references/app-ask.md](references/app-ask.md)，取得搭建所需的事实或完成问办子任务，再读取 [references/app-builder.md](references/app-builder.md) 完成资源建改。若两项没有依赖关系或用户指定了顺序，按实际依赖和用户顺序执行。

不要把宜搭问办结果当作 OpenYida 写权限；搭建操作仍需独立校验登录态、目标组织、目标资源和权限。

混合诉求示例：

- 统计近三个月各部门报销量和审批时长，再在费用应用里新增经营看板。
- 查询客户阶段分布和当前字段，再据此调整客户表字段及跟进流程。
- 确认合同与回款的关系和实例血缘，再新增合同回款健康页。
- 查询当前人员对表单的提交、查看权限，再重新配置该表单的权限组。
- 查出逾期跟进记录并调用已发布的催办 Action，同时新增以后自动催办的规则；查询和催办走问办，新增规则走搭建。

## 边界

- 没有宜搭数据或资源操作的通用知识、纯文档、纯表格、纯 PPT、纯 IM 任务，不读取这两份 reference。
- 用户明确指定其他数据源或平台时，按用户指定来源处理，不默认转到宜搭。
- 分流不确定时，优先走只读查询确认事实；任何宜搭写操作前都要简短确认目标。

## 完成标准

- 创建或修改分支：原始建改需求完成，或 OpenYida Skills 明确要求等待用户操作。
- 查询或办理分支：宜搭问办返回结果、要求补充输入，或停在明确授权/确认点。
- 混合分支：必要事实查询完成，并且用户要求的创建或修改工作也已处理。
