# 选区（遮罩）局部编辑

本文件只处理两件事：**选区如何构建并验证正确**，以及 **prompt 如何保留用户意图**。

- 本文件按当前 `open-image-2` 的遮罩接口编写（`mask_image`）。其他模型若在当前工具 Schema 中提供遮罩能力，先核对字段及极性，不直接套用本模板。
- 用户提供的所有选区或遮罩都要检查，不能只看第一张。
- 多个选区默认合并后只生成一次。只有用户明确要求分步，或明确描述了不同选区之间的先后依赖时，才拆成多次。

## 1. 遮罩的构建与验收

构建这一步只决定“哪里改”，不得改写“改什么”。完成后得到：处理后的底图、遮罩，以及每个选区对应的可见对象或位置（下称 `region_map`）。

### 1.1 提交给本包 Open Image 2 工具的最终遮罩

- PNG，带透明通道（RGBA）。
- 与 `images[0]` 的宽高完全一致，并且处于同一显示方向。
- 透明度 0（`alpha=0`）表示要修改的区域，不透明（`alpha=255`）表示保留。
- 底图带有 EXIF 旋转时，先提交一份已摆正的底图，再让遮罩与它同向。
- 遮罩与底图的显示宽高比不一致时，不得静默拉伸；先重新构建，或向用户确认。

### 1.2 归一化遮罩的极性

默认的用户遮罩是“白色区域编辑、黑色区域保留”。其他情况先归一化，再二值化：

| 用户遮罩的含义 | 处理 |
| --- | --- |
| 灰度，白色＝编辑 | 直接二值化，白色变为透明 |
| 灰度，黑色＝编辑 | 二值化后反转 |
| 用红／绿／蓝等颜色涂出编辑区 | 取对应颜色通道，再二值化 |
| 调色板模式（P-mode） | 先转成 RGB，再按颜色取通道 |
| RGBA，原图透明区＝编辑 | 取 alpha 通道，二值化后反转 |

颜色含义不明确时，按用户的说法判断（通常是白色或涂的颜色）；仍不明确就先问。无论输入是哪种，都必须经过二值化、写入透明通道和下面的验收。

单张遮罩示例（Python Pillow，白色＝编辑）：

```python
from PIL import Image, ImageOps
base = ImageOps.exif_transpose(Image.open(base_path))
source_mask = ImageOps.exif_transpose(Image.open(user_mask_path))
ratio_delta = abs((source_mask.width / source_mask.height) / (base.width / base.height) - 1)
if ratio_delta > 0.01:
    raise ValueError("Mask and base aspect ratios differ; check alignment before resizing")
gray = source_mask.convert("L").resize(base.size, Image.NEAREST)
mask = Image.new("RGBA", base.size, (0, 0, 0, 255))
mask.putalpha(gray.point(lambda value: 0 if value > 127 else 255))
mask.save(mask_path)
```

若底图经过 EXIF 转正，还需将示例中的 `base` 另存为新底图，并用新路径作为 `images[0]`；不要只转正遮罩计算用的图，却继续提交方向未归一的原底图。

### 1.3 多个选区

- 先为每个选区建立 `region_map`：选区 → 用户的原始诉求 → 最小可见对象或位置。确认对应关系可靠后，再合并遮罩。无法可靠区分时先问用户。
- 合并方式：每张遮罩先各自摆正方向，核对与底图的显示宽高比及对应位置；只有对齐可靠时才用最近邻缩放到底图尺寸并二值化，再取并集，写成一张遮罩。比例或位置对不上时先重建或确认，不直接拉伸合并。
- 不要用“透明块的数量等于选区数量”做校验：选区可能相交或相邻，一个选区也可能包含多个不连通的区域。

### 1.4 提交前的验收闸门

1. 取出最终遮罩的透明通道单独查看：透明区就是重绘区，其位置和面积必须与用户的选区相当。用户画的是小块时，重绘区不得覆盖画面的大部分。
2. 把重绘区以半透明红色叠到底图上查看：标记必须完整覆盖用户的目标，没有明显的漏盖、偏移或误盖。
3. 多个选区时，检查并集的覆盖范围，以及每个区域与诉求的对应关系，不按连通块数量判断。

任一项不通过，都不得提交。

### 1.5 自行定位目标并构建遮罩

用户没给遮罩、但要求只改一个能可靠定位的小区域时，才可以自己构建：

- 用媒体理解获取目标的 0–1 归一化坐标，再按图片的真实宽高换算成像素，并略微外扩。不要让视觉模型直接给像素坐标，也不要凭像素启发式猜位置。
- 在与底图相同的画布上画出“目标区域透明、其余不透明”的遮罩，同样必须经过 1.4 的验收。
- 无法可靠定位时，请用户提供选区，或改为不带遮罩的普通编辑。

### 1.6 结果交付

- 当前遮罩接口仍属于生成式编辑：遮罩外的像素可能有轻微变化，输出尺寸也可能与 `images[0]` 不同。生成结果按原样交付，并报告它的实际尺寸。
- 默认不要在本地把结果贴回原图。重新生成的图可能无法与原图精确对齐，贴回容易留下接缝。
- 用户要求遮罩外完全不变时，在交付中说明：生成式编辑可能让遮罩外的区域有轻微变化。

## 2. prompt 的约束与规范

唯一公式：

```text
final_prompt = 必要的功能／结构脚手架 + intent_text
```

`intent_text` 是用户当前仍然有效的意图：后来的修正覆盖之前的说法，其他仍有效的约束按原意合并。无论是用户直接请求，还是其他技能调用，每个语义片段都必须来自用户原话，或用户明确回答中新增、修正且仍然有效的意图。调用技能的内部审计、图片观察只能用于构建遮罩、`region_map` 和验收，不会自动成为 prompt 的内容。

### 2.1 意图不得改写

优先保留用户的措辞和用户自己提出的保留要求。不翻译、不正向化、不润色、不套内容模板，也不添加、删除或替换任何事实性语义。

只允许以下处理：

1. 用“图片 1”“图片 1 的选区 1”等资源引用建立底图、参考图和选区的绑定，然后从最终文本中删除这些原始标记。
2. 合并多轮中仍有效的用户原话；有冲突时以后来的修正为准。
3. 多图输入时，增加底图和参考图的角色说明。
4. 把模型看不到的“选区 1／选区 2”，替换成 `region_map` 中最小必要的可见对象或位置名称。

除此之外，不得自行增加材质、纹理、工艺、颜色、光泽、风格、情绪、对象类别、删除范围、保留范围或其他画面语义；也不得把用户指定的参考图自动扩写成一组推测的属性。必须把参考内容写成文字才能完成任务时，先向用户确认这段描述。用户意图不足以判断要做什么，或无法可靠建立 `region_map` 时，先提问，不靠想象补足。

### 2.2 允许的结构脚手架

单张图时不需要额外模板：

```text
{intent_text}
```

多张图时只增加角色说明，不增加画面内容。按用户原始的资源绑定，写明每张参考图的职责：

```text
以第 1 张图为唯一编辑底图；第 2 张及后续图片仅用于用户指定的{reference_roles}参考，不作为底图；{intent_text}
```

多个选区时，只把“选区 1／选区 2”这样的编号替换为 `region_map` 中的对象或位置，其余原话不动；无法可靠区分时向用户确认。

不得在模板之外追加“自然衔接”“保持原纹理”“不含任何文字”等尾巴，除非它们就是用户原话、用户明确确认的内容，或能逐项追溯到用户当前有效的意图。

### 2.3 提交前检查

- `final_prompt` 中每一段内容语义，都必须来自用户原话、用户明确确认的内容，或能逐项追溯到用户当前有效的意图；新增的部分只能是上面白名单中的结构说明。
- 不得仅为丰富 prompt 而分析图片。遮罩对齐验收和建立 `region_map` 所需的最小视觉检查不受此限，但观察结果不得变成 prompt 的新属性。
- 提交前，在方案说明中逐字展示将要提交的 `final_prompt`，让用户能看到实际提交的内容。
