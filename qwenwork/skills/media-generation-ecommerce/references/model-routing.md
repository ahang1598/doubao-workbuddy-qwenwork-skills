# 模型选择

本表是随包发布时的推荐与参数参考。提交前以当前可见工具及其 Schema 为能力边界；字段、模型或取值未列在本表时先核对当前工具，不能仅凭本表断言不可用。

## 原则

1. **已锁定的模型**：用户点名了模型，或其他技能的任务单写明了 `model` → 锁定该模型，只校验下文的硬约束。不满足时说明哪一项不支持并给出可用方案，不静默换模型。
2. **未锁定时**：先按硬约束过滤，再把场景顺序作为正常可用情况下的初始偏好。能确认实际模型时，用一句话告诉用户其公开名；用户要求时再列出当前可用模型及差异。
3. **显式传 `model`**：当前工具 Schema 和说明允许指定模型、且所选值可用时才传。字段未暴露时，先从工具说明或 Profile 配置确认实际锁定的模型；用户或任务单点名的模型无法确认匹配时先说明，不凭本表假定默认模型。
4. 用户明确要求速度、稳定性或成本，或首选模型当前不可用时，在满足硬约束的模型中调整选择，并说明影响。
5. 对用户只说公开模型名：Open Image 2、Banana Image 2、Seedance 2.0、Happy Horse 1.0、MiniMax Music 2.5。

## 图片

### 可用取值

| 项目 | `open-image-2` | `banana-image-2` |
| --- | --- | --- |
| 模式 | `generate`、`edit` | `generate`、`edit` |
| 尺寸 | `size`：`auto`、原有预设，或符合下述规则的自定义 `宽x高` | `aspect_ratio`：`1:1`、`2:3`、`3:2`、`3:4`、`4:3`、`4:5`、`5:4`、`5:8`、`9:16`、`16:9`、`9:21`、`21:9`、`1:2`、`2:1`；`resolution`：`1K`、`2K`、`4K` |
| 张数 | `output_count` 1–4 | 每次 1 张，多张分多次提交 |
| 输出格式 | `output_format`：`png`、`jpeg`、`webp` | — |
| 质量档 | `quality`：`generate`、`edit` 均支持 `low`、`medium`、`high`、`auto` | — |
| 选区编辑 | `mask_image` | 不支持 |
| 联网检索 | — | `web_search` |
| 参考图 | `edit` 时 1–14 张 | `edit` 时 1–14 张 |

`open-image-2` 的生成与编辑均可用自定义 `size`：以小写 `x` 分隔的正整数宽高都须为 16 的倍数、单边不超过 3840、宽高比在 1:3–3:1 之间，总像素在 655360–8294400 之间，边界均包含。`1200x1600` 可直接输出 3:4；原有预设和 `auto` 仍可用。用户指定合法尺寸时原样提交，不因预设列表未列出而改选模型。

- 两列的专属字段不得混用。`quality` 仅用于 Open Image 2；按下文的质量档规则和当前 Schema、Profile 传递。
- 规格超出上述自定义尺寸规则或其他模型表列范围时，先核对当前工具 Schema；确认不支持后，按调用技能的规则处理，或请用户选择可用规格。不要把合法的 3:4 等自定义尺寸误判为不支持。
- 保持原图比例、4K、跟随底图尺寸只是参数要求，不是选 open-image-2 的理由。先按下面的顺序选模型，再在该模型的取值里构造参数。
- banana-image-2 的 `aspect_ratio`、`resolution` 不传 `"auto"`；open-image-2 的 `size` 可以用 `auto`。

### 场景初始偏好（先看用户锁定、硬约束与当前可用性）

1. **点名**：GPT Image 2、gpt-image-2、gpt-image2、Open Image 2 → `open-image-2`；Banana Image 2、nano-banana-2、Gemini 3.1 Flash Image → `banana-image-2`。点名其他模型时先查当前工具 Schema，确认不能使用后再说明限制并推荐替代方案。
2. **选区／遮罩局部编辑**（用户给了选区或遮罩，或要求只改框选区域）→ 当前工具仍提供遮罩时，优先考虑 `open-image-2` 的 `edit` + `mask_image`，见 `mask-edit.md`。
3. **文字渲染**（判定见 `image-rules.md` 第 1 节）→ 优先尝试 `open-image-2`；默认显式传 `quality: "medium"`，覆盖规则见下文。去文字、去水印、去字幕属于删除已有文字，不算。Banana Image 2 也能生成画内文字；比例等硬约束更适合它时用它，写法见 `image-rules.md` 第 1 节。
4. **泛创意**（用户明确要自由发挥、开放式创作、扩氛围、主动补内容，或任务更重画面丰富度而非可控还原）→ `open-image-2` 的 `generate`；仍默认显式传 `quality: "medium"`，不因创意场景自动升级为 `high`。
5. **服装平铺白底主图，要求强保真**：目标图是衣物本体，要保留面料、印花、颜色、Logo、款式细节；另一张参考图只提供平铺姿态、褶皱或光影；输出白底平铺图 → `banana-image-2`。
6. **换脸／换头 + 局部清理**（迁移参考图的五官、发型，同时去掉道具，保持身体、服装、姿势、背景不变）→ `banana-image-2`；人物融合效果可能不稳定，交付时如实说明。
7. **AI 扩图**（在原图外侧自然补充背景或被截断的边缘）→ `banana-image-2`：原图作为 `images[0]`，编辑到目标比例，prompt 写清“只在原图外侧新增内容，原图中的人物、商品、文字、Logo、姿势、构图不改写”。只要纯色补边或留白时，用本地图像处理，不提交生成任务。
8. **其他常规生成与编辑**（包括高质量写实、产品图、人像、快速预览）→ `banana-image-2`。

`open-image-2` 的 `generate`、`edit` 都支持四档 `quality`；当前 Schema 和 Profile 暴露该字段时，两种模式均默认显式传 `quality: "medium"`，不省略该参数。只有用户点名 `high`，或明确表达同等的最高质量意图（如“最高质量”“最高画质”“用最好的质量档”“画质拉满”“highest quality”）时才传 `quality: "high"`。按上下文理解用户意图，不做精确关键词匹配，以上例子并非穷举；任务单也可以转述这一用户意图。泛创意、笼统的“高质量”“高清”“更精致”描述或任务单自行推荐 `high` 均不足以触发升级，仍使用 `medium`。用户或任务单明确指定 `low`、`medium`、`auto` 时原样传递。

### 模型特点（向用户解释差异时使用）

| 模型 | 擅长 | 限制 |
| --- | --- | --- |
| Banana Image 2 | 常用于材质还原、场景氛围和多种比例；也能生成画内文字 | 文字效果需要逐张检查；当前接口没有遮罩参数 |
| Open Image 2 | 当前可优先尝试画内文字、卖点图、封面合成和遮罩编辑 | 自定义尺寸须满足 16 倍数、比例与像素范围约束 |

## 视频

### 可用取值

| 项目 | `seedance-2.0` | `happy-horse-1.0` |
| --- | --- | --- |
| 模式 | `text_to_video`、`image_to_video`、`first_last_frame_to_video`、`reference_images_to_video` | `text_to_video`、`image_to_video` |
| 时长 | 4–15 秒 | 4–15 秒 |
| 清晰度 | `480p`、`720p`、`1080p`、`4k` | `720p`、`1080p` |
| 比例 | `1:1`、`4:3`、`3:4`、`16:9`、`9:16`、`21:9`、`adaptive` | 不支持 |
| 音轨 | `generate_audio` | 不支持 |
| 参考素材 | 参考图 1–9 张；不接受参考视频、参考音频 | 不支持 |

完整约束见 `video-constraints.md`。

### 选择

- 点名：Seedance 2.0、SeeDance 2.0、sd2.0、seedance → `seedance-2.0`；Happy Horse 1.0 → `happy-horse-1.0`。「豆包」等宽泛名称不能唯一确定模型，先确认具体型号。点名其他模型时先查当前工具 Schema，确认不能使用后再推荐可用模型。
- 推荐顺序：`seedance-2.0` → `happy-horse-1.0`，作为未锁定模型时的初始偏好；再按硬约束、当前可用性及用户对速度、稳定性、成本的要求调整。用户询问时列出当前可用的选项。

### 特殊需求

| 需求 | 处理 |
| --- | --- |
| 可复现 | 传 `seed` |
| 4 秒以下 | 当前工具最短为 4 秒时，说明限制并提供 4 秒方案；用户接受后再调整 |
| 16–30 秒 | 先核对当前可用模型的单段时长上限；能单次生成时按用户时长提交。超出上限时可按镜头分段（每段不超过当前上限）；需要单个成片且本地可合成时再拼接并检查衔接，无法合成时说明限制，不把分段当作单片交付 |
| 4K | 当前 Schema 暴露小写 `4k` 且实际模型为标准 `seedance-2.0` 时提交；Profile 锁定不支持的模型时说明冲突，不自行降到 1080p |
| 参考音频（含只有音频） | 当前 Schema 无参考音频字段时，把节奏、氛围写进 prompt；所选模型支持 `generate_audio` 时可生成原生音轨。要指定配乐且用户接受合成时，可另提交音乐任务并用本地 `ffmpeg` 合成 |
| 参考视频、原地编辑、保留原片画面或原声 | 先核对当前 Schema：有参考视频字段时按其语义生成新片段；没有时用媒体理解解析源视频的动作、运镜、节奏和分镜，再抽关键帧作为参考图或首帧。两种路径都不能承诺保留原片像素或原声音轨；要求原地编辑时需另有对应能力 |
| 视频替换：换模特、换商品 | 同上，把替换目标作为参考图重新生成；先按 `video-rules.md` 第 6 节说明风险 |
| 视频延长、串联 | 优先首帧连续性时，抽上一段末帧作为 `image_to_video` 的首帧；优先跨段身份一致性时，按 `video-rules.md` 第 7 节使用共享身份参考图，并将末帧作为附加参考图。两者都需严格满足时，先说明当前单次生成的取舍；拼接不保证无缝 |

### 模型特点

| 模型 | 特点 |
| --- | --- |
| Seedance 2.0 | 当前常用于光影、复杂动作和多元素视频；本表记录其支持四种模式、参考图、seed，默认带音轨；效果仍需看生成结果 |
| Happy Horse 1.0 | 支持文生、图生两种模式；没有画幅和音轨参数 |

## 音乐

本表当前列出的音乐模型为 `minimax-music-2.5`，用于歌曲、配乐、背景音乐，不用于文字转语音；其他模型是否可用以当前工具 Schema 为准。纯音乐或无歌词请求关闭自动歌词，见 SKILL.md。
