# 视频任务规则

模型选择见 `model-routing.md`，数值约束见 `video-constraints.md`，prompt 写法见 `video-prompts.md`。

## 1. 先出方案还是直接生成

被其他技能调用时，执行调用技能的计划，不重复出计划。本技能直接承接用户请求时：

- **直接生成**：单条文生、单图生视频、首尾帧、参考图生视频或简单编辑，素材角色和目标动作明确；多个素材只是共同参考生成一条连贯视频；用户已指定模型、时长、比例、清晰度等参数；用户说“直接生成”“重试”“按上次再来”“微调”，且上下文路径清楚。
- **先整理方案，必要时确认**：用户只给商业目标、脚本方向或传播效果，镜头节奏、素材职责、动作或声音还有影响结果的未决选择时，先整理视频目标、素材角色、执行路径、关键参数和自检点。脚本、分镜、时间轴、参考素材或多阶段操作已经明确时，按已确认内容执行；只有素材职责或执行路径仍有关键歧义时再一次性确认。
- **“给个方案”类首轮诉求停在文本方案**：用户说“给个方案”“给个思路”“先给分镜”“先给脚本”“不要直接生成”“先别生成”等时，即使同一句里也说了要做视频，也只输出文本分镜方案（主体、动作、场景、节奏、视听建议、建议参数）和卖点拆解，末尾用一句话询问是否按此生成。只有同一轮里明确写了“直接生成”“现在生成”“按这个方案出”“直接出片”等，才跳过方案直接生成。
- **只看模型选择**：用户只想了解可用模型时，按 `model-routing.md` 列出可用模型和差异，不提交任务。

## 2. 默认值

用户没有给参数时，从下面的默认偏好起步，核对当前工具支持后传入，并在提交前说明实际选择，不逐条追问：

- **时长**：5 秒；有明确的动作或镜头时 5–8 秒。本包所述工具没有自动时长；若当前 Schema 已变化，以实际取值为准。
- **清晰度**：720p。
- **比例**：
  - 用户明示的具体比例优先；当前工具支持时按原值传，不支持时说明取舍；
  - 有源视频或参考视频、且已探测到画幅时，以源视频比例为目标，核对当前工具是否支持；
  - 用户要求“跟随原图比例”时，先把主参考素材的比例映射到当前可用的具体值；无法可靠映射且工具支持时，可用 `adaptive`；
  - 以上都没有时，按场景推断：短视频 9:16、横版 16:9、商品方图 1:1。
- **音轨**：`seedance-2.0` 默认生成音轨（`generate_audio: true`），用户要求静音时传 `false`；不需要询问用户是否要声音。旁白、字幕等只在用户主动提出时处理。`happy-horse-1.0` 没有音轨控制。
- **seed**：只在用户要求可复现时传整数。
- **prompt 语言**：中文请求默认用中文描述；用户或调用技能明确指定其他语言时遵照其要求。品牌名、型号、商标，以及指定的英文文字或口播保持原样；不要仅为迎合模型而擅自翻译已确认内容。

## 3. 四条硬护栏

### A. 参考生成还是图生视频，按意图选，不按图片张数选

- 要「用图片生成新内容」（新场景、模特上身、运镜、锚定商品保持一致）→ 在当前模型支持时优先考虑 `reference_images_to_video`，即使只有 1 张图；不要仅凭图片张数选择模式。`image_to_video` 以首帧构图为主要约束，也可能生成一定的新动作和运镜，选路以用户最需要保留的内容为准。
- 只让一张已经成型的图动一动（模特和场景已经在画面里，只加动作和运镜）→ `image_to_video`。
- 需要跨镜头保持人物或商品一致时，优先把当前有效的身份锚定图放在 `reference_images`。若用户更重视指定首帧或明确排除某张图，按最新意图和当前模式能力处理；多张参考图在 prompt 里逐张点名「图 1、图 2……」，不复制同一张图凑数。
- **身份与姿态分开看**：身份图用于锚定人物五官、发型、体型、肤色，或商品造型、颜色、材质、Logo 等，不等同于姿态图。用户未排除、模式支持且未超过输入上限时，姿态或视角不同的清晰身份图仍可优先保留；在 prompt 中写明「仅参考其形象，不借用其姿态」。若用户更重视指定首帧，或最新要求排除该图，按其意图处理。
- **身份优先不等于同主体图片全收**：通常先选身份信息最清晰的一张，需要互补角度时再选少量附加图。其余姿态图仍按本镜头用途、用户要求与当前上限筛选。

### B. 比例的写法

- `seedance-2.0`：用户明示的具体比例最优先；当前工具支持时原样使用，不支持时先说明。用户要求保持原比例、且已探测到源素材的标准画幅时，传可用的具体比例；无法可靠映射到支持的比例时，可传 `adaptive`。不要传空字符串，也不要把 `adaptive` 作为普通选项展示给用户。
- `happy-horse-1.0`：本包所述工具没有比例参数。比例是硬要求且模型未锁定时，可考虑支持该比例的模型（如 `seedance-2.0`）；用户明确点名 Happy Horse 时，先说明当前工具无法控制比例，让用户选择接受这一限制或换模型。

### C. 有视频、音频素材时的限制

- 本包所述视频工具不接受参考视频和参考音频，也没有原地编辑能力。当前 Schema 仍无这些字段时，按第 4 节转成可用输入：视频先理解、再抽关键帧作为参考图或首帧；音频的节奏和氛围写进 prompt。
- 这样得到的是一段重新生成的新视频，无法保证原片画面或原声音轨保留；提交前先向用户说明。

### D. 参考素材按镜头意图筛选，不全量塞入

> **身份锚定优先**：筛选附加的姿态、场景、动作、服装和道具参考图时，优先保留当前镜头需要的身份锚定图。用户最新要求排除或替换某图、模型不支持该模式，或参考图数量超过当前上限时，先按最新意图处理并说明取舍，不能强行全传。

- **上传不等于全用**：`reference_images` 放几张，依据本镜头真正需要的视觉信息、用户指定的素材和当前输入上限决定，不按上传数量机械全传。同一主体的多张姿态图可能含有重复身份信息，不必每张都当作独立元素。
- **身份锚定图少而精，不是“只能 1 张”**：优先挑 1–3 张光线、朝向相近的正脸或侧脸。1 张最清晰的正面图通常足够；光线或朝向差异大、单张信息不全时，可以再加 1–2 张互补。
- **先列职责清单，再逐图匹配**：
  1. 先列出本镜头需要锁定的独立视觉职责（身份、服装、场景、Logo、动作、风格、多角度展示），共 N 项；
  2. `reference_images` 的张数以真正需要的视觉职责和当前输入上限为准；一张图可以承担多项职责；
  3. 对每张候选图问三个问题：它是否是当前有效的身份锚定图？是否承担本镜头必需的职责？是否与镜头意图明显冲突？身份图优先保留；附加图按下一条筛选。超过上限时先缩减冗余图，仍无法满足就请用户拆分镜头或指定优先级。
- **冲突图按角色处理**：非用户指定、又不承担身份或关键阶段职责的附加图，与镜头目标明显对立时可不提交。例如纯背影图与全程正面镜头、纯街景图与纯色棚拍、静态坐姿图与全程走动且无对应起始帧。用户明确要求使用时，先说明潜在干扰，再结合其决定和输入上限处理。
- **复合动作的部分匹配**：本镜头是动作链（如「坐 → 起身 → 走 → 触摸光斑」）时，分辨起始姿态、关键转折动作和全程不会出现的姿态。匹配某个关键阶段的图可留作该阶段参考；与所有阶段都不匹配、且无其他必要职责的图通常不提交。
- **参考图按用途选**：按本镜头意图给每张参考图分配角色。把所有上传图都塞进去，可能使身份、姿态、视角信号互相干扰，增加姿态污染和身份漂移的风险。
- **筛选只决定素材取舍**：这一阶段只决定 `reference_images` 放哪几张；第 4 节的输入检查若需要处理图片，应另按其规则和用户要求进行，不因筛选而擅自缩放、裁剪或抠图。
- **按目标选路径**：筛选后即使只剩 1 张身份锚定图，若目标仍是用它生成新镜头、且当前模型支持，继续用 `reference_images_to_video`；若需要把某张图作为准确首帧，则考虑 `image_to_video`，并说明两种约束的取舍。
- **用户显式意图优先**：用户明确要求使用、排除或替换某些图片时，以其最新要求为准。图片数量超过当前上限时说明限制，协商拆分或取舍；意图模糊、难以判断是否冲突时，优先核实关键图的角色，不凭筛选规则覆盖用户要求。
- **说明关键取舍**：自动筛掉冗余或无关图时，可简要说明本次采用的关键素材。若准备不使用用户明确指定的图片，须在提交前说明模式、上限或画面冲突造成的取舍，不能留到用户追问时才解释。

## 4. 输入素材预处理

- **图片输入检查（`seedance-2.0`，提交前完成）**：按本包所述工具约束，首帧、尾帧、参考图每边需在 300–6000 px 之间，宽高比需在 0.4–2.5。服务端可能拒收不合规图片，且错误信息可能不具体；先核对当前 Schema 及素材，不对同一不合规输入盲目重试。
  - 宽高未知时，先读取实际宽高（macOS 用 `sips -g pixelWidth -g pixelHeight <文件>`，或用 Python Pillow）；上游已给出可靠宽高的可以直接使用。
  - 仅边长不合规、等比缩放能满足要求时，用 Pillow 等比缩放（LANCZOS），另存到当前工作目录，后续任务改用新文件。宽高比超出要求时，等比缩放无法修复；先说明裁剪、补边或更换素材的取舍，不静默改变构图。
  - 放大倍数达到 1.5 倍以上时，交付时说明“该素材分辨率较低，已等比放大至最低尺寸要求，细节可能偏软”；能向用户要到高清原图时先要。
- **视频、音频素材**：当前 Schema 没有对应参考字段时，按下面的方式转成可用输入；若当前工具新增参考字段，先核对模式、输入限制及「新片段」语义，再决定是否直接传入。
  - 没有参考视频字段时，用媒体理解解析本地或 HTTPS 视频中的动作、运镜、节奏和分镜，写进 prompt；需要画面锚点时，用 `ffmpeg` 抽取关键帧作为参考图或首帧（抽出的图同样要过上面的图片输入检查）。
  - 用户说「只要前 N 秒」「截取 X 到 Y」时，只使用该范围内的内容；若当前工具新增参考视频字段，也要先取得符合该范围和输入限制的片段。
  - 没有参考音频字段时，把节奏、氛围写进 prompt；所选模型支持 `generate_audio` 时可生成原生音轨。用户指定独立配乐、且接受后期合成时，可另提交音乐任务，再用本地 `ffmpeg` 合成；需核对原声保留或替换、时长及音量，不声称口播或字幕已精确同步。

## 5. 续接已确认的方案时锁定终版

前文已给出文本方案、脚本、分镜或大纲，用户后续说“生成”“按上面生成”“就按这个方案”“直接出片”时，必须以最近一次包含用户修改的终版方案作为 prompt 的内容来源：

- 不得重新创作、重排剧情、泛化摘要，或删除已确认的镜头、时间轴、台词、字幕、旁白、OS、文字上屏、禁用项。用户只改了某一处时，其余已确认要素默认保留。
- 需要压缩时只做机械整理，保留镜头顺序、关键时间轴、角色动作、台词、字幕、旁白、文字上屏和用户的显式约束。不要求逐字照搬，但必须保持原方案的剧情骨架和视听要素类型。
- 禁止把已确认的分镜改写成新的剧情钩子、冲突事件、角色关系、卖点顺序或转化收尾。为了适配模型、商品锚点、参考图数量或安全表达，只能在终版分镜主体之外追加商品锚点、生成约束、音频描述等执行补充。
- 终版方案的表格中有“台词”“动作／台词”“台词／字幕”“旁白／字幕”等列，或单格里同时写了字幕、旁白、OS、角色台词时，prompt 中要逐镜头保留对应的语义，不得压成纯画面描述。
- 提交前自检：prompt 应覆盖终版方案的时间段、核心镜头顺序、主要角色动作、字幕／台词／旁白类要素和用户禁用项。发现剧情被改写成另一条故事、台词或字幕类要素整类缺失、禁用项丢失时，先按终版方案重组 prompt 再提交。

## 6. 高风险需求，先说明边界

- **口播、旁白、配音 + 多素材成片**：用户同时要求按文案口播（或旁白、配音、字幕与口播对齐），又提供多段视频素材或要求多分镜叙事时，单次生成不能保证按文案逐字配音或字幕与口播精确对齐；当前工具也不提供精细剪辑与最终合成输入。生成前用会话语言说明。用户把逐字口播、字幕对齐或后期合成作为硬性要求时，不把单次生成当作达标路径；先拆成具备相应能力的后期任务，当前没有能力时说明限制。否则可按直接连贯视频继续。成片实际没有口播时，交付时如实说明「当前为无口播版本」。
- **视频里换包装、换 Logo、换商标文字、换商品本体**：当前工具没有原地编辑路径时，按第 4 节重新生成。生成前说明风险：原片画面无法保证保留，包装文字或 Logo 字符可能崩坏，商品本体或周边画面可能漂移。按用户已明确的路径执行；路径不明时，可提供「先做单帧替换再延展成短视频」「重新生成含目标商品的新视频」等选项。执行后目标元素没换成，或包装文字崩坏时，如实说明，不把未达标的结果当作正常交付。

## 7. 多段视频保持身份一致

生成多段、且涉及同一人物或商品时，各段若使用互不关联的输入，更容易出现身份漂移。根据用户优先保留的内容选择：

- 优先跨段身份一致性：各段尽量共享同一组当前有效的身份锚定图（`reference_images_to_video`），动作、场景参考图按镜头意图筛选；需要衔接时，可把上一段末帧作为附加参考图并说明用途。
- 优先从上一段画面连续起步：抽取上一段末帧作为 `image_to_video` 的首帧，并在 prompt 中说明后续动作；仍需检查实际衔接效果。当前首帧模式不能同时传身份参考组时，需说明一致性与衔接效果的取舍。
- 图生视频可能丢失小物件；该物件属于用户已确认的关键内容时，在 prompt 中说明希望它持续可见，并在生成结果中检查。

## 8. 失败处理

- **瞬时错误**（限流、服务端错误、超时）：原样重试最多 1 次。第二次仍失败时不要盲目重试，按下面的清单排查。
- **没有错误详情的失败**（只有失败状态）可能与时长、数量、尺寸或服务暂态有关；先排查已知参数问题，再决定是否重试：
  1. 提交参数里是否误放了工具不提供的字段（参考视频、参考音频、自动时长等）；
  2. 素材是否过大（见第 4 节和 `video-constraints.md`）；
  3. 模型能力是否选错（本表记录 `happy-horse-1.0` 只支持文生和图生，没有比例和音轨控制；以当前 Schema 为准）；
  4. 模式是否错配：想用参考图生成新镜头时优先考虑 `reference_images_to_video`（单张也可以）；要以成型图片为首帧时考虑 `image_to_video`；
  5. 比例写法是否错误（见护栏 B）；
  6. 参考图数量是否越界（最多 9 张），清晰度和比例是否在支持范围内；
  7. 图片是否通过了第 4 节的输入检查。
- **多张参考图 + 1080p 偶发失败**：确认是可重试错误后可原样重试 1 次。仍失败时，可提出 720p 或精简非必需参考图等方案；用户或任务单锁定了 1080p 或参考图时，按调用技能的后备规则处理，没有授权就先说明取舍，不自行降规格或去掉关键素材。
- 把持续报错当作瞬时错误连续重试三四次，是典型的反模式。

## 9. 能力边界

本技能只做通用的单条视频生成和生成式改写。混剪脚本、爆款裂变、视频脚本拆解、独立的语音合成或配音文件、精确的字幕／配音／BGM 混音、最终剪辑合成，不当作单步视频生成直接承接：先拆成当前可执行的直接连贯视频或视频片段任务，或明确告知能力边界。成套电商素材（多平台、多 SKU、多步骤）由对应的电商业务技能先出计划；没有对应技能时，按第 1 节整理方案，必要时确认。

## 10. 对外表述

面向用户的文字（执行前说明、过程说明、待办文案、最终回复）使用其会话语言和业务化表达。用户未要求技术细节时，避免内部代号、接口路径、技术形态名，以及 `task_id`、`seed` 等调试字段；需要换方式时，直接说明对画面和规格的影响。中文会话可写「版本一（5 秒，含音频）」；公开模型名（Seedance 2.0、Happy Horse 1.0）可在说明所用模型时提及。
