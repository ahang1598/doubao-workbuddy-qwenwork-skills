# 群聊内容摘要

基于钉钉群聊的**智能摘要与洞察**生成能力。从指定群聊/时间范围的消息中提取关键信息，识别决策、行动项、风险，生成**钉钉在线文档结构化摘要**。

---

## 环境前置：连接器与技能依赖

本技能依赖以下资源，使用前需确保已就绪：
- **DingTalk 连接器**（dws）：未开启时钉钉群聊消息拉取、文档创建等功能不可用。
- **dws 技能**：本技能调用 `dws chat`、`dws contact`、`dws doc` 等命令，需先激活 dws 技能。

> **草稿文件路径说明**：本技能中的 `{工作区目录}` 指当前 QoderWork 会话的工作区目录（如 `~/.qwenworkcn/workspace/<session_id>/`），agent 可通过 Bash 执行 `echo $TMPDIR` 获取可用临时路径，或使用自身工作区目录。

---

## 禁止事项

- 禁止以对话文本替代钉钉在线文档作为最终交付物
- 禁止绕过钉钉工具直接构造 API 请求
- 禁止编造消息内容或捏造发言人
- 禁止将闲聊/表情/无实质内容纳入摘要
- 禁止行动项缺少负责人（无法确认时标注"待分配"）
- 禁止摘要过于笼统（关键结论必须引用具体时间、人名、数据）

## 强制要求

- 本技能触发即代表用户期望生成**钉钉在线文档**，主 Agent 无需询问确认
- 消息拉取必须循环调用直至获取完整时间范围内的所有消息（处理分页）
- 数据收集完成后，直接调用 `dws doc create --name --content-file --content-format markdown --format json` 创建钉钉在线文档
- 每个数据步骤完成后立即写入草稿：`{工作区目录}/draft_group-chat-summary_{YYYYMMDD_HHMMSS}.md`
- 消息量大时，采用全量拉取后 Agent 本地语义过滤

## 能力清单

| 工具 | 用途 | 说明 |
|------|------|------|
| `dws chat search --query --format json` | 搜索/定位目标群聊 | 仅返回会话名，不含消息内容 |
| `dws chat message list --group --time --limit --format json` | 拉取群聊消息 | 循环调用处理分页，直至获取完整范围 |
| `dws chat message list-topic-replies --group --topic-id --format json` | 拉取话题回复 | 获取话题讨论的完整上下文 |
| `dws contact user get --ids --format json` | 查询用户信息（姓名、部门） | 将 user_id 映射为真实姓名 |
| `dws doc search --query --format json` | 获取群内分享的云文档内容 | 补充消息中引用的文档 |
| `dws doc read --node --format json` | 读取具体文档内容 | 深度提取文档信息 |
| `dws doc create --name --content-file --content-format markdown --format json` | 创建钉钉在线文档 | 最终交付 |
| `Write` | 写入草稿文件（追加内容时先 Read 再 Write，或用 Bash `>>` 追加） | 每步完成后执行 |

```

  → dws doc create --name "{群名} 消息摘要 · {时间范围}" --content-file "{草稿文件路径}" --content-format markdown --format json
    |
    v
```

## 触发方式

- "帮我总结一下 XX 群的消息"
- "把这个群最近一周的内容整理一下"
- "群聊摘要" / "群消息总结"
- "帮我看看 XX 群里有什么重要决定"

## 输入

**必选：**
- 群名称或群 ID（支持模糊匹配）
- 时间范围（如"最近 3 天"、"2025-04-10 至 2025-04-16"）

**可选：**
- 摘要重点（决策/行动项/风险/全部，默认全部）
- 关注话题（指定关键词，如"项目A"、"发布计划"）
- 输出详略（简报/标准/详细，默认标准）

## Phase 1 — 信息确认

收到请求后，若缺少必选输入，向用户确认群名称和时间范围。

初始化草稿文件：
```
Write 工具创建草稿文件：{工作区目录}/draft_group-chat-summary_{YYYYMMDD_HHMMSS}.md
（后续追加内容时先 Read 再 Write，或用 Bash `>>` 追加）
```

## Phase 2 — 消息获取

### A1. 定位目标群聊

```
dws chat search --query "{群名称关键词}" --format json
→ 返回群 ID 和群名，确认目标群聊
```

若返回多个结果，向用户确认是哪个群。

### A2. 全量拉取消息

```
dws chat message list \
  --group {group_id} \
  --time "{开始时间}~{结束时间}" \
  --limit 100 \
  --format json
→ 循环调用直至获取完整时间范围内的所有消息
```

**分页处理：** 每次调用后检查是否还有更多消息，若有则继续拉取，直至所有消息获取完毕。

**关键词语义过滤：**
若用户指定了关注话题，在获取全量消息后，Agent 在本地进行关键词匹配和语义相似度过滤，筛选相关消息。

### A3. 拉取话题回复

对消息中识别到的重要话题，拉取完整回复链：
```
dws chat message list-topic-replies \
  --group {group_id} \
  --topic-id {topic_id} \
  --format json
```

### A4. 查询发言人信息

收集消息中出现的所有 user_id，批量查询真实姓名：
```
dws contact user get --ids "{user_id1},{user_id2},..." --format json
→ 建立 user_id → 姓名/部门 映射表
```

### A5. 获取引用文档

消息中出现钉钉文档链接时，读取文档内容：
```
dws doc read --node {doc_id} --format json
→ 提取文档标题、核心内容、关键数据
```

## Phase 3 — 内容分析

### B1. 去噪与预处理

过滤以下内容（不纳入摘要）：
- 纯表情/贴纸消息
- 系统通知（入群/退群/改群名等）
- 闲聊内容（问候语、无实质信息的短回复）
- 重复转发的相同内容

### B2. 话题分段

采用双重分段策略：
1. **时间间隔**：消息间隔 > 30 分钟视为话题切换
2. **语义相似度**：相邻消息语义相差较大时切分新话题

每个话题段：
- 提取话题标题（2-5 字概括）
- 统计参与人数和消息量
- 按热度（消息量 × 参与人数）排序

### B3. 决策识别

识别以下信号词触发的消息：
- "决定"、"确认"、"拍板"、"同意"、"OK就这样"、"定了"、"批准"

```markdown
## 决策事项

| 时间 | 决策内容 | 决策人 | 相关背景 |
|------|---------|--------|---------|
| {日期 时间} | {决策描述} | {姓名} | {上下文} |
```

### B4. 行动项提取

识别以下信号词触发的消息：
- "需要"、"负责"、"跟进"、"截止"、"deadline"、"你来"、"麻烦"、"帮忙"

```markdown
## 行动项

| 行动项 | 负责人 | 截止时间 | 状态 |
|--------|-------|---------|------|
| {描述} | {姓名}（无法确认时标注"待分配"） | {日期/时间} | 待跟进 |
```

### B5. 风险识别

识别以下信号词触发的消息：
- "风险"、"延期"、"问题"、"阻塞"、"待确认"、"不确定"、"可能来不及"

```markdown
## 风险与待跟进

| 风险/问题 | 提出人 | 时间 | 当前状态 | 影响 |
|---------|-------|------|---------|------|
```

### B6. 核心议题热度排序

按热度（消息量 × 参与人数）对话题排序，输出：

```markdown
## 核心议题（按热度排序）

### 议题 1：{话题标题}（{N} 条消息，{M} 人参与）
**核心讨论**：{2-3 句话概括}
**结论**：{如有结论}
**引用原文**："{关键发言}"—— {发言人}，{时间}

### 议题 2：...
```

## Phase 4 — 文档生成

```
dws doc create \
  --name "{群名} 消息摘要 · {时间范围}" \
  --content-file "{工作区目录}/draft_group-chat-summary_{时间戳}.md" \
  --content-format markdown \
  --format json
```

**文档结构（必须遵循）：**

```markdown
# {群名} 消息摘要 · {时间范围}

> 消息总量：{N} 条 | 参与人数：{M} 人 | 生成时间：{日期}

## 摘要速览（3-5 条要点）

## 一、核心议题（按热度排序）
（每个议题：核心讨论 + 结论 + 关键引用）

## 二、决策事项（表格）

## 三、行动项（表格，含负责人+截止时间）

## 四、风险与待跟进（Callout 高亮高风险项）

## 五、重要链接
（群内分享的文档/链接汇总）

## 六、待跟进清单
（综合行动项 + 风险的完整 TODO 列表）
```

## 易混淆场景

| 场景 | 判断依据 | 处理方式 |
|------|---------|---------|
| 群名模糊匹配到多个群 | dws chat search 返回多个结果 | 向用户确认是哪个群 |
| 时间范围内消息量极大（>1000条） | 拉取时间较长 | 告知用户正在处理，建议缩小时间范围 |
| 消息中有大量图片/文件 | 非文本消息 | 仅记录"分享了图片/文件：{文件名}"，不解析内容 |
| 用户要求"每天自动总结" | 定期任务 | 说明本技能为单次触发，建议配合定时任务使用 |

## 扩展场景

### 主题追踪模式
- 用户指定关键词/话题
- 全量拉取后本地过滤相关消息
- 输出：话题时间线 + 各阶段结论
- 适用：跟踪某技术方案从提出到落地的全过程

### 多群聚合
- 多个相关群的讨论汇总
- 识别跨群关联话题
- 全局行动项汇总表
- 适用：项目涉及多个子群，需要统一视图

## 错误处理

| 错误 | 原因 | 修复方法 |
|------|------|---------|
| 遗漏关键决策 | 识别信号词覆盖不全 | 扩大决策识别信号词，加入"拍板"、"OK就这样" |
| 行动项无 Owner | 消息中未明确分配 | 标注"待分配"，列入待跟进清单 |
| 噪音过多 | 闲聊/表情未过滤 | 加强去噪规则，降权非实质内容 |
| 时间范围错误 | 时区未统一 | 明确标注 UTC+8，解析用户意图时确认时区 |
| 摘要过于笼统 | 缺少具体信息 | 引用原始表述，补充具体时间、人名、数据 |
| 消息拉取不全 | 分页未处理 | 循环调用 dws chat message list 直至所有页获取完毕 |
