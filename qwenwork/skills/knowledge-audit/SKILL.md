# 知识库审计

对钉钉知识库进行系统性诊断，支持两种审计模式，输出审计报告与知识地图索引。定位为"诊断 + 规划"，不承诺自动移动文件。

## 禁止事项

- 禁止通过 curl、HTTP API 等非 `dws` 方式操作钉钉产品
- 禁止凭空构造 nodeId、UUID 等标识符，所有 ID 必须从实际命令返回值中获取
- 禁止 `dws` 命令不加 `--format json`
- 禁止在未读取文档证据前直接给出分类结论
- 禁止把"建议迁移"写成"已完成移动"——本技能不执行文档移动
- 禁止未经用户确认执行写入操作；`doc update --mode overwrite` 会清空原内容，风险极高，除非用户明确要求否则只用 append
- 禁止遇到子文件夹就跳过——必须递归扫描子文件夹内的文档

## 强制要求

- 每条 `dws` 命令均须携带 `--format json` 参数
- 范围确认和审计模式选择不可跳过
- 所有分类结论必须有已读取的文档证据支撑
- Module A 完成后必须向用户展示诊断摘要，确认后再进入 Module B
- Module B 目录方案确认后，才能进入 Module C 索引生成
- 扫描文件夹时必须递归处理子文件夹（`type=folder` 的节点继续 `doc list --folder`）

## 能力清单

| 动作 | 安全等级 | 说明 |
|------|---------|------|
| 范围与模式确认 | 只读 | 确认目标范围 + 审计模式（轻量/深度） |
| 文档扫描与诊断 | 只读 | doc list/search + doc info + doc read，递归扫描子文件夹 |
| 目录方案设计 | 只读 | 根据分类结果设计目录结构（不实际创建） |
| 目录创建 | 写入 | 用户确认方案后创建分类文件夹（需用户确认） |
| 知识地图生成 | 写入 | 创建索引文档并写入审计结果（需用户确认） |

## 环境前置：连接器依赖

本技能依赖以下连接器和技能，使用前需确保已就绪：

- **DingTalk (DWS)** 连接器（`qwenwork.settings.connector.builtin.dws`）：提供钉钉文档读写能力。未连接时所有 `dws doc` 命令将失败。
- **dws** 技能：提供 `dws` CLI 命令的使用指引。

前置检查步骤（在检查点 0 之前执行）：

1. `qw_query qwenwork.settings.connector.builtin.dws` 确认 `enabled: true` 且 `authenticated: true`。
2. 若未连接，用 `qw_action connect` 引导用户完成钉钉 OAuth 登录，或提示用户在「设置 → 连接器」中手动开启。
3. 确认 `dws` 技能已安装（`qw_query qwenwork.settings.skills`）。
4. 前置检查失败时，停止执行并告知用户需先启用 DWS 连接器。

## 总体工作流

```
用户: "帮我审计一下知识库"
      |
      v
  ⏸ 检查点 0: 范围与模式确认（三选一 + 两选一）
  范围: ① 个人文档空间（默认）② 指定知识库/文件夹（需提供链接）③ 关键词搜索
  模式: ① 轻量级审计（快速，基于标题+元数据）② 深度审计（精确，逐篇读取+摘要）
      |
      v
  Module A: 文档扫描与诊断 → ⏸ 检查点 1（用户确认诊断摘要）
      |
      v
  Module B: 目录规划 → ⏸ 检查点 2（用户确认目录方案）
      |
      v
  Module C: 落地索引文档 → 返回文档链接
```

### 检查点 0 — 范围与模式确认（不可跳过）

**审计范围**（向用户提供三个选项）:

| 选项 | 说明 | 对应操作 |
|------|------|---------|
| ① 个人文档空间（默认） | 审计我的个人知识库 | `dws doc list --format json` 从根目录开始递归 |
| ② 指定知识库或文件夹 | 需提供知识库首页链接或文件夹链接 | `dws doc list --folder "{URL}" --format json` 从该目录递归 |
| ③ 关键词搜索 | 搜索特定标题的文档 | `dws doc search --keyword "{关键词}" --format json` |

**审计模式**（向用户提供两个选项）:

| 模式 | 速度 | 精确度 | 适用场景 | 核心差异 |
|------|------|--------|---------|---------|
| 轻量级审计 | 快 | 中等 | 快速摸底、文档数多 | 仅用标题+元数据分类和去重 |
| 深度审计 | 慢 | 高 | 精确诊断、文档数适中 | 逐篇 doc read + AI 摘要，基于内容分类和去重 |

### Module A — 文档扫描与诊断

**目标**: 扫描目标范围内所有文档（含子文件夹），产出健康度评分和分类结果。

1. **A1 文档扫描**: 按检查点 0 确定的范围获取文档列表。遇到 `type=folder` 的节点，递归 `doc list --folder` 继续扫描子文件夹，详见 [references/command-recipes.md](./references/command-recipes.md) 递归策略
2. **A2 元数据采集**: 对每篇文档 `dws doc info --node "{docUrl}" --format json`，提取 title/type/creator/updatedAt
3. **A3 内容采集（仅深度模式）**: 对每篇文档 `dws doc read --node "{docUrl}" --format json`，生成 ≤ 100 字摘要，存入分析上下文
4. **A4 健康度评估**: 按 [references/health-model.md](./references/health-model.md) 评分模型打分（A/B/C/D 四档）
5. **A5 分类诊断**: 轻量模式按标题+类型分类；深度模式按摘要内容分类。分类动态生成，不硬编码
6. **A6 问题识别**: 轻量模式按标题重合度 > 80% 标记疑似重复；深度模式按摘要相似度标记内容重复

**⏸ 检查点 1**: 展示诊断摘要（文档总数、健康度分布、分类数量、主要问题），用户确认后继续。

### Module B — 目录规划

**目标**: 根据分类结果设计目标目录结构和迁移清单。

1. **B1 目录设计**: 根据 A5 分类结果设计目录树，每个目录附定义和归入规则
2. **B2 迁移清单**: 列出待迁移文档（原位置 → 建议目标 → 原因）
3. **B3 处理清单**: 列出待处理文档（过期/重复/标题不规范 → 建议操作 → 优先级）

**⏸ 检查点 2**: 展示完整目录方案和清单，用户确认（可调整目录名称/合并拆分分类）后继续。

### Module C — 落地索引文档

**目标**: 创建目录结构和知识地图索引文档。

1. **C1 创建目录**: `dws doc folder create --name "{分类名}" --workspace "{ID}" --format json`，提取 docUrl
2. **C2 创建索引**: `dws doc create --name "{知识库}审计报告与知识地图 {YYYY-MM}" --format json`，提取 docUrl
3. **C3 写入内容**: `dws doc update --node "{docUrl}" --content "{内容}" --content-format markdown --mode append --format json`，按 [references/index-template.md](./references/index-template.md) 结构分块写入（每块 ≤ 1500 字符）
4. **C4 返回链接**: 返回索引文档链接 + 审计核心数据摘要

**关键陷阱**:
1. markdown 内容禁止以 `#` 一级标题开头——`doc create --name` 已设置文档标题
2. markdown 参数中的换行必须使用真实换行符（U+000A），不能使用字面量 `\n`
3. 索引文档中避免 ASCII Art 架构图——钉钉文档等宽字体不保证对齐，用表格或列表替代

## 使用示例

### 示例 1: 深度审计
**用户说**: "帮我深度审计一下某项目知识库"
**执行步骤**:
1. 检查点 0: 范围（某项目知识库链接），模式（深度审计）

**期望输出**: 含内容摘要的精确审计报告

### 示例 2: 轻量扫描个人空间
**用户说**: "快速看看我的文档情况"
**执行步骤**:
1. 检查点 0: 范围（个人文档空间），模式（轻量级）
2. Module A: 递归扫描 → 标题+元数据分类
3. ⏸ 展示诊断摘要
**期望输出**: 快速概览 + 健康度分布

**期望输出**: 确认后生成审计报告

## 错误处理

| 错误 | 原因 | AI 应该怎么做 |
|------|------|--------------|
| `doc search` 结果为空 | 关键词过窄 | 换更宽泛的关键词重试；仍无结果建议 doc list |
| `doc info` 字段缺失 | 权限不足 | 基于已有字段评估，标注"元数据不完整" |
| `doc read` 无权限（403） | 文档访问限制 | 深度模式降级为标题分类，标注"无法读取正文" |
| 递归深度超过 5 层 | 文件夹嵌套过深 | 停止该分支递归，标注"深层文件夹未扫描" |
| 文档总数超过 200 篇 | 大规模知识库 | 轻量模式分批；深度模式建议缩小范围或改用轻量 |
| `doc folder create` 失败 | 重名冲突 | 换名重试；仍失败则跳过，仅输出方案 |
