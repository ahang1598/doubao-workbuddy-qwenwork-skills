# 公文写作

## 总原则

用户提供的事实、附件、模板和单位口径是写作依据，不是可自由发挥的素材。不得编造日期、姓名、数字、政策、批复、部门、法规依据、工作成效或承诺事项。关键信息缺失时，先简短询问；若不影响继续起草，使用 `[待补充：批准机关]` 这类占位符明示。

## 执行流程

1. 判断任务类型：新拟、改写、润色、压缩、扩写、按模板套写、格式审校、质量审读或生成附件。
2. 判断文稿类别和行文方向：
   - 法定党政机关公文：读取 `references/document-types.md`。
   - 按用户模板写作：读取 `references/template-adaptation.md`。
   - 格式、层级、语体、标点、日期或 GB/T 9704-2012 基础规范检查：读取 `references/format-and-style.md`。
   - `.docx`、Word 附件或可分发文档输出：读取 `references/docx-production.md`。
   - 终稿把关、风险扫描：读取 `references/quality-checklist.md`。
3. 提取硬约束：主送机关、发文机关、写作目的、政策依据、事实材料、时间范围、语气、密级、篇幅、交付格式和截止时间。
4. 按文种组织结构，保持机关文稿的庄重、准确和可执行；责任主体、完成时限、报送路径能明确就明确。
5. 终稿前对照来源事实、模板栏位、文种要求和缺失信息做自检。
6. 按用户要求交付。默认输出 Markdown 正文；用户要求 `.docx`、修订痕迹、批注或其他附件时，再调用相应文档工具处理。

## 模板优先模式

只要用户提供模板、范文、历史文稿、提纲、表格、复制文本、`.docx`、`.pdf`、图片，或提出“按这个模板”“照这个格式”“参考附件”，就进入模板优先模式。

优先级：

1. 用户本次明确指令。
2. 用户模板中的结构、标题、固定表述、表格、编号和版式。
3. 用户提供的事实和素材。
4. 对应文种的一般规范。
5. 机关文稿语体和 GB/T 基础格式要求。

套写模板时：

- 固定标题、必填栏目、表格列、审批栏、落款日期区和编号方式原则上保留。
- 模板中的旧单位、旧项目、旧日期、旧金额、旧联系人必须替换或删除，不能混入新稿。
- 能体现单位风格的详略程度、句式节奏和常用提法应尽量延续。
- 无法填写的字段显式标为 `[待补充：字段名]`，不得猜测。
- 模板与用户硬性要求冲突时，以用户要求为准；必要时在正文后简要说明调整点。

## 写作口径

机关文稿应准确、凝练、庄重、可执行，前后口径一致。

- 部署类文稿先交代目的和依据，再写措施、责任和时限。
- 上行文先写情况、依据和必要性，再提出请示事项或工作建议。
- 评议、通报、整改类文稿先写事实和依据，再写处理意见、整改要求或下一步安排。
- 责任表述要有明确主体；已知责任单位、完成时限、交付物时，不写成泛泛要求。
- 中文正文使用中文全角标点，数字、日期、名称与用户材料保持一致。
- 优先使用 `制定`、`印发`、`组织`、`落实`、`报送`、`整改`、`验收`、`归档`、`督办` 等可执行动词。
- 避免夸张、文学化、宣传化和缺乏事实支撑的判断。

## 交付要求

起草类任务先给完整文稿；如有缺失事实或影响发文的假设，再附简短的 `需确认事项`。

审校类任务先列问题，按严重程度排序，指出所在段落或原句，并给出替代表述。

模板类任务要说明模板栏目是否已全部填充，并列出仍需确认的占位项。

涉及 `.docx` 或附件交付时，不得直接套用通用 Markdown/Word 默认主题样式；应优先从 `assets/templates/template-catalog.json` 选择内置模板，并按 `references/docx-production.md` 建立公文样式、检查正文、页眉页脚、表格、编号、落款日期区和版面效果；能渲染核验时应先核验再交付。
