# 竞品分析

针对目标产品及其竞品，从产品定位、功能体验、定价策略、市场表现、用户口碑、技术架构等多维度进行**对齐口径、深度对比**的全面分析，输出结构化的竞品分析报告。

---

## 禁止事项

- 禁止以对话文本替代钉钉在线文档作为最终交付物
- 禁止编造数据、链接或来源；所有结论必须有公开信息或内部数据支撑
- 禁止对不同竞品使用不同评估标准（口径必须统一）
- 禁止主观臆断，不做无依据判断
- 禁止竞品数据缺少获取日期（产品功能和定价可能随时变化）
- 禁止直接构造 API 请求绕过钉钉工具

## 强制要求

- 本技能触发即代表用户期望生成**钉钉在线文档**，主 Agent 无需询问确认
- 每个竞品必须在相同维度下收集信息，不可遗漏任何竞品
- 数据收集完成后，直接调用 `dws doc create --name --markdown` 创建钉钉在线文档
- 每个数据步骤完成后立即写入草稿：`/home/workspace/draft_competitive-analysis_{YYYYMMDD_HHMMSS}.md`
- 竞品对比优先使用表格呈现，确保横向可比

## 触发方式

- "竞品分析" / "对比 A 和 B" / "竞对研究"
- "帮我分析一下 XX 的竞品"
- "XX 和 YY 有什么区别？各自优劣势？"
- "做一份 XX 产品的竞品调研"

## 输入

**必选：** 目标产品名称 + 竞品列表（至少 1 个竞品，建议 2-5 个）

**可选：**
- 对比维度（功能/价格/技术/体验/市场，默认全维度）
- 产品版本范围（如"仅对比企业版"）
- 时间范围（默认：当前最新版本及近 1 年数据）
- 关注重点（如"重点关注 AI 能力对比"）
- 目标受众（如"给产品经理看"、"给管理层决策用"）

---

## Phase 1 — 范围确认

**确定竞品范围：**
- 直接竞品：同品类、同目标用户的产品
- 间接竞品：满足相同需求但形态不同的产品
- 潜在竞品：可能进入该领域的跨界玩家

**默认 6 大对比维度：**

| 维度 | 说明 | 关键指标 |
|------|------|---------|
| 产品定位 | 目标用户、核心价值主张、品牌调性 | slogan、官网首屏文案、目标客群 |
| 功能与体验 | 核心功能清单、差异化功能、交互体验 | 功能覆盖率、独有功能数、用户体验评分 |
| 定价与商业模式 | 价格体系、免费/付费策略、变现方式 | 客单价、免费版功能范围、付费转化路径 |
| 渠道与获客 | 分发渠道、获客方式、生态合作 | 渠道覆盖数、合作伙伴、应用市场排名 |
| 用户与市场 | 用户规模、市场份额、用户画像 | DAU/MAU、市占率、NPS 评分 |
| 技术与架构 | 技术栈、API 开放程度、数据安全 | 技术选型、API 数量、安全认证 |

初始化草稿文件：
```
write_file(path: "/home/workspace/draft_competitive-analysis_{YYYYMMDD_HHMMSS}.md", mode: "write")
```

## Phase 2 — 信息收集

### A2. 产品功能与体验（逐竞品执行）

**WebSearch 查询（对每个竞品执行）：**
```
"{产品} 功能 特性 更新日志 2025"
"{产品} 核心功能 功能列表 产品介绍"
"{产品A} vs {产品B} 对比 评测"
"{产品} 用户体验 交互设计 UI 评价"
```

**WebFetch 获取产品官网详情（对每个竞品执行）：**
```
WebFetch(url: "https://{竞品官网}/product")
→ Agent 提取：核心功能列表、产品定位描述、最新更新功能、目标用户群体
```

**功能粒度统一原则：**
- 统一到"功能模块"级别（如"实时协作"、"模板库"、"API 接口"）
- 状态统一标注：已支持 / 部分支持 / 不支持 / 即将上线

**写入草稿：**
```markdown
## 产品功能与体验

### {竞品名称}
**产品定位**：{一句话描述}

**核心功能**：
- {功能模块1}：{描述}
- {功能模块2}：{描述}

**最近重要更新**：
- {年份 Q}：{功能更新}

**用户体验评价**：
- 优势：{描述}
- 劣势：{描述}

> 来源：{来源}，{获取日期}
```

### A3. 市场与定价（逐竞品执行）

**WebSearch 查询：**
```
"{产品} 定价 套餐 pricing 2025"
"{产品} 免费版 付费版 企业版 价格对比"
"{产品} 用户量 市场份额 DAU MAU"
"{行业} 市场份额 排名 TOP10"
```

**WebFetch 获取定价页面：**
```
WebFetch(url: "https://{竞品官网}/pricing")
→ Agent 提取：所有定价套餐的价格、功能范围、限制条件、企业版定制方案
```

```markdown
| 团队版（人/月） | | | | |

| 产品 | 全球用户 | 付费用户 | 估值/市值 | 增速（估） |
```

## 意图映射

| 用户说 | 实际意图 | 处理方式 |
|--------|---------|---------|
| "帮我做竞品分析" | 完整竞品报告 | 触发全流程 |
| "帮我对比一下 A 和 B 的定价" | 仅定价对比 | 仅执行 A3，输出定价对比表 |
| "帮我看看 XX 最近有什么新功能" | 竞品动态跟踪 | 仅执行 A2，聚焦功能更新 |
| "我们和竞品相比有哪些优劣势" | 战略对比 | 执行全流程，重点输出 B4 差异化机会点 |

## 易混淆场景

| 场景 | 判断依据 | 处理方式 |
|------|---------|---------|
| 竞品超过 5 个 | 用户列出很多竞品 | 与用户确认优先级，选 3-5 个深度分析，其余简要提及 |
| 目标产品本身信息不全 | 用户未提供 | 先通过 knowledge 和 dws doc 获取内部产品信息 |
| 竞品功能信息过时 | 距上次更新超 3 个月 | 在报告中标注数据获取日期，建议定期更新 |
| 用户要求"客观分析" | 担心偏向自家产品 | 明确说明使用统一评估标准，结论有数据支撑 |

---

## 错误处理

| 错误 | 原因 | 修复方法 |
|------|------|---------|
| 竞品信息不完整 | 部分竞品信息较少 | 标注"信息有限"，说明来源局限性 |
| 定价信息缺失 | 竞品未公开定价 | 标注"定价需询价"，收集用户反馈中的价格信息 |
| 功能对比口径不统一 | 不同竞品功能粒度不同 | 强制统一到模块级别，细节差异在备注中说明 |
| 内部资料与外部信息冲突 | 内部情报与公开信息不符 | 以内部情报为准，外部信息作参考，标注差异 |
| dws doc create 失败 | 内容过长 | 分章节创建，或精简示例数据 |
