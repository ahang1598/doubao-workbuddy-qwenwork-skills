# 法律文书模板扫描

## 重要提示

模板规范的价值在于确定性：同一个模板，不同人使用、不同时间使用，产出的文书在格式和结构上应当一致。本 skill 的目标是将一份"只有人看得懂"的模板文件，转化为一份 agent 也能准确遵循的结构化规格说明书。提取过程必须做到：不遗漏关键格式要素、不臆测模板中没有的规则、不确定的地方明确标出让用户确认。

## 适用场景

当你需要"先理解用户的模板，再按模板出活"时使用：
- 用户上传律所内部的文书模板，要求后续生成的文书"长得一样"
- 用户对 agent 输出的格式不满意，拿出自己的模板说"照这个来"
- 需要将模板的格式规范传递给其他文书生成 skill 作为输入约束
- 用户想确认 agent 是否真正理解了自己模板的要求

## 不适用场景（NOT for）

| 用户意图 | 处理 |
|---|---|
| 根据案情直接生成起诉状/答辩状/代理词等文书 | 交对应文书生成技能；本技能只提取模板规格，不生成文书内容 |
| 扫描目录、批量枚举多份模板文件 | 本技能只解析用户提供的单份模板文件，不做目录枚举 |
| 成品文书的纯格式转换（docx→pdf 等） | 属格式转换，非模板规格提取 |
| 审查文书内容的法律实质（条款风险、案情分析等） | 交对应审查/分析技能；本技能只提格式与结构，不审内容实质 |
| 解析完模板后要求直接产出最终文书 | 先交付规格说明书并经用户确认，再由文书生成技能承接 |

## 输入参数

开始解析前，确认以下信息：
1. **模板文件**：用户上传的模板（支持 .docx / .pdf / 图片 / 纯文本描述）
2. **文书类型**（可选）：如果用户明确告知文书类型（如"这是起诉状模板"），直接采纳；否则由 agent 自行判断
3. **特殊要求**（可选）：用户是否有模板文件中看不出来的额外要求（如"我们所里正文统一用仿宋，不管模板里写的是什么"）
4. **使用场景**（可选）：这份模板主要用于什么场景（法院提交 / 客户汇报 / 内部存档），影响格式严格程度的判断

**默认值规则（强制）**：用户未提供可选项时**不阻塞流程、不反复追问**——文书类型由 agent 自行判断，特殊要求与使用场景标注"未指定"。四项参数的实际取值（含"自动判断"/"未指定"）必须在规格说明书开头以一行记录：`输入参数：模板文件=XX | 文书类型=XX | 特殊要求=XX | 使用场景=XX`，供用户事后校正。

## 异常处理

解析过程中遇到下列情况，按对应方式收口，**不得臆测模板内容、不得静默跳过**：

| 异常场景 | 处理 |
|---|---|
| 文件无法读取 / 损坏 / 加密 | 停止解析，向用户说明原因，请其重新提供可读文件或文本内容；不得编造模板内容 |
| 空模板 / 无可识别内容 | 告知用户模板为空，请其确认是否提供了正确文件 |
| 图片模板识别失败或置信度低 | 说明识别困难，请用户改提供 Word/PDF 版本，或口头描述关键格式要素 |
| 权限不足无法读取文件 | 停下并说明，请用户确认文件可访问；不得绕过权限继续 |
| 模板缺少某格式要素（如无页码、无页边距信息） | 在规格说明书记"模板未定义"，并列入待确认清单，不得臆造默认值 |
| 模板自相矛盾（同层级标题字号不一等） | 按 Step 5.2 一致性自检标出，给统一方案建议，交用户确认 |

## 五步解析流程

### Step 1：模板识别与分类

**目标**：确定模板的基础属性，为后续解析建立上下文。

**操作清单：**

| 步骤 | 提取项 | 说明 |
|---|---|---|
| 1.1 | 文件格式 | 原始文件类型：docx / pdf / 图片 / 纯文本 |
| 1.2 | 目标输出格式 | 用户期望的最终输出格式（通常与原始格式一致） |
| 1.3 | 文书类型 | 判断属于哪类法律文书（起诉状 / 合同 / 法律意见书等） |
| 1.4 | 纸张大小 | A4 / Letter / 其他 |
| 1.5 | 页面方向 | 纵向 / 横向 |
| 1.6 | 页边距 | 上、下、左、右四边的具体数值 |
| 1.7 | 页眉页脚 | 是否有页眉/页脚，内容是什么 |
| 1.8 | 页码 | 页码格式（阿拉伯数字 / 中文）、位置（底部居中 / 右下等） |

### Step 3：内容结构解析

**目标**：提取模板的完整大纲骨架，标注每个章节的内容定位。

**操作要求：**

对模板中的每个章节/段落，按以下格式输出：

| 序号 | 章节名称 | 层级 | 性质 | 主题定位 | 写作要求 | 预估篇幅 |
|---|---|---|---|---|---|---|
| [编号] | [章节标题] | [一级/二级/三级] | [必填/可选] | [这部分要写什么] | [有什么特殊写作规范] | [约 X 字 / X 段] |

**关键区分：**

在每个章节内，进一步标注哪些内容是"固定文本"，哪些是"可变内容"：

- **固定文本**：模板中不随案情变化的文字，如标题"民事起诉状"、落款格式词"此致"、章节标题"诉讼请求"等。生成时必须原样保留。
- **可变内容**：需要根据案情填写的部分，如当事人信息、诉讼请求具体内容、事实经过等。生成时根据上下文填写。

**固定文本与可变内容标注格式：**
```
[章节名称]
├── 固定文本："[原文]"
├── 可变内容：[需要填写什么]
│   ├── 填写说明：[具体指导]
│   └── 格式约束：[如编号格式、字数建议等]
└── 可变内容：[需要填写什么]
    └── 填写说明：[具体指导]
```

**长文档降级策略（强制）**：文档超过 50 个章节时，**主章节（一级/二级标题）必须全覆盖树状标注**；同构子条款（如通用条款 49 条逐条结构相同）可合并标注——给出代表性展开 + 一句"第X条至第Y条结构相同，可变内容为[...]"的合并说明。**合并范围与理由必须在 Step 5 完整性自检中显式注明**，不得静默省略。

### Step 4：模板规格说明书生成

**目标**：整合 Step 1-3 的提取结果，输出一份结构化的规格说明书。

**前置硬指令（强制）**：输出前**必须先 Read `references/output-template.md` 与 `references/example.md`**，确认输出结构后再动笔；**未实际执行 Read 禁止输出**（在任务清单中标记 completed 不能替代实际读取）。输出结构、章节命名、表格列项、树状标注格式一律以 output-template.md 为准，不得自创章节名或用 emoji 标题替代。

**操作要求：**

- 按 `references/output-template.md` 中定义的结构输出
- 兼顾两种使用场景：
  - **用户审阅场景**：每个模块有中文标题和简要解读，格式友好，便于律师/法务快速确认"这和我的模板一致吗"
  - **agent 引用场景**：关键参数使用统一的结构化表格/列表，后续 skill 可直接提取使用

### Step 5：自检与确认清单

**目标**：确保提取结果的完整性和准确性，标出需要用户确认的不确定项。

#### 5.1 完整性自检

逐项检查是否遗漏：

| 检查项 | 是否完成 |
|---|---|
| 文件类型和页面设置是否完整 | □ |
| 所有标题层级的样式是否都已提取 | □ |
| 正文样式是否完整（字体、字号、行距、缩进） | □ |
| 编号体系的所有层级是否都已覆盖 | □ |
| 落款、日期等特殊格式是否已记录 | □ |
| 大纲中所有章节是否都已列出 | □ |
| 每个章节的固定文本/可变内容是否都已标注 | □ |

#### 5.2 一致性自检

检查模板自身是否存在不一致之处：

- 同一层级的标题是否使用了不同的字体或字号？
- 正文部分是否存在行距不统一的情况？
- 编号体系是否存在中途切换格式的问题？
- 如发现不一致，在确认清单中标出并建议统一方案

#### 5.3 待确认清单

将所有不确定项汇总为待确认清单：

```
【待确认项 1】[描述不确定的内容]
  模板现状：[模板中实际是什么样的]
  建议处理：[推荐的统一方案]
  
【待确认项 2】[描述不确定的内容]
  模板现状：[模板中实际是什么样的]
  建议处理：[推荐的统一方案]
```
