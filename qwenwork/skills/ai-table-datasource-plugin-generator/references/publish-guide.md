# 插件发布指南

> **使用说明**：在帮助用户发布插件前，请先确认他们的使用场景：
> - **企业内插件**：仅供本企业内部使用，无需平台审核，流程简单
> - **三方企业插件**：面向多家企业客户开放，需入驻钉钉服务商并通过平台审核
>
> 确认类型后，再按对应章节指导用户完成发布。发布前请参考 `docs/publish-guide.md` 完成检查清单和部署准备。


数据源插件支持两种发布模式：**企业内插件**和**三方企业插件**。

## 类型对比

| 对比维度 | 企业内插件 | 三方企业插件 |
|---------|-----------|------------|
| 目标用户 | 单一企业内部 | 多家企业客户 |
| 审核要求 | 企业内部自审 | 钉钉平台严格审核 |
| 收费模式 | 自建自用，无需付费 | 可商业化收费 |
| 发布难度 | 简单，步骤少 | 复杂，需入驻服务商 |

---

## 一、企业内插件发布

适合：为本企业内部员工提供数据同步能力，无需对外开放。

### 发布步骤

1. **进入钉钉开发者平台**：[open-dev.dingtalk.com](https://open-dev.dingtalk.com)

2. **创建企业内部应用**
   - 选择「企业内部应用」→「创建应用」

3. **添加酷应用**
   - 进入创建的应用 → 点击「酷应用」→「添加」
   - 选择「创建酷应用」→ 在弹窗中选择「扩展到AI表格」
   - 填写基本信息：
     - 前端页面地址（部署后的前端 URL）
     - 服务端接口地址（部署后的后端 URL）

4. **发布酷应用**
   - 进入「应用发布」→「版本管理与发布」→「创建新版本」
   - 选择版本号和可见范围 → 保存发布

5. **验证**
   - 在 AI 表格「数据连接中心」→「企业专用」中找到发布的插件
   - 点击插件，验证前端配置页面和数据同步是否正常

> 发布后可在「版本管理与发布」中调整「应用可见范围」控制插件可见人员。

---

## 二、三方企业插件发布

适合：作为 ISV 向多家企业提供数据源插件服务。

### 前置条件

- 企业管理员账号（需在 OA 管理后台配置管理员权限）
- 已完成钉钉服务商入驻

### 发布步骤

#### 步骤 1：入驻钉钉服务商

只有入驻钉钉的服务商企业才可以注册三方应用。

- 入驻申请页面：[partner.dingtalk.com](https://partner.dingtalk.com/#/)
- 注意：入驻申请需由**企业管理员**提交

#### 步骤 2：注册三方应用并开通免费规格

1. 在钉钉开放平台创建三方企业应用
2. 联系相关负责人开通发布免费规格商品的权限（需提供 AppID）
3. 申请免费应用（0元路费，需提供 AppID）
4. 申请不在开放平台展示入口（避免用户误入）
5. 去掉开通通知（避免用户启用插件时通知企业管理员）

#### 步骤 3：发布酷应用（扩展到AI表格）

- 在三方应用中创建酷应用，选择「扩展到AI表格」
- 填写前端页面地址和服务端接口地址
- 提交发布

#### 步骤 4：开通成员授权

参考文档：[钉钉应用市场成员授权文档](https://open.dingtalk.com/document/isvapp/document-on-authorization-of-application-market-members)

#### 步骤 5：功能验证与审批发布

完成后联系钉钉平台负责人完成数据源插件的功能测试和审批发布。

## 开放平台配置项说明

无论是企业内插件还是三方插件，创建或编辑「扩展到 AI 表格」的酷应用时，都需要填写以下配置项。

| 字段 | 必填 | 说明 |
|------|------|------|
| 插件类型 | ✅ | 选择「数据源同步」 |
| 插件分类 | 否 | 在插件市场展示的分类，未选则展示在「其它」分类 |
| 用户界面地址 | ✅ | 前端页面的公网 URL，即用户配置数据源时唤起的页面 |
| 配置界面宽度 / 高度 | 否 | 用户使用插件时弹出的配置面板大小，默认宽度 520 |
| 服务端地址 | ✅ | 后端服务的公网地址，如 `https://your-plugin.example.com` |
| 数据表结构同步接口 | ✅ | 返回表字段结构的接口路径，如 `/api/sheet_meta` |
| 行记录同步接口 | ✅ | 分页拉取行记录的接口路径，如 `/api/records` |
| 账号校验接口 | 否 | 三方账号代管场景可选配置。填写后，平台会在创建关联账号时以及创建同步数据表前调用此接口验证账号凭证，校验不通过则中断流程（详见后端开发指南） |
| `secretKey` | 否 | 签名验证密钥，用于验证请求来源。设置后同步请求会携带 `Ding-Docs-Signature` Header，后端需同步配置进行校验（生产环境强烈建议开启） |
| `encryptionKey` | 否 | 加密密钥，用于启用三方账号代管能力中的 `getCredentialToken` 加密功能。设置后，`getCredentialToken` 返回的 token 将由钉钉一方用此密钥加密，插件服务端用同一密钥解密得到明文凭证（详见后端开发指南） |
| 问题反馈入口 | 否 | 用户提交需求或问题反馈的渠道链接 |

> **`secretKey` 与 `encryptionKey` 的区别**：
> - `secretKey`：用于**验证请求来源**（HMAC-SHA256 签名），防止价冒调用。详见后端开发指南的「签名验证」章节。
> - `encryptionKey`：用于加密三方账号凭证 token，仅在使用 `getCredentialToken` 能力时才需要配置。
