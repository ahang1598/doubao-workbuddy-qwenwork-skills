# 三种模式完整工作流

> HTML 简历模板参照 [templates/resume-template.html](../templates/resume-template.html)，包含完整的简约现代风格 CSS 和打印样式。

## 流程A：创作简历

### 步骤1：【最多一轮问答】确认目标岗位 + 收集用户信息

这是信息收集的**唯一一次**机会，必须在这一轮中完成所有提问：

- 若用户未提供目标岗位，**必须停下来**询问：「请问您想应聘什么岗位？」
- 同时一次性引导用户补充以下信息：

1. **基本信息** — 姓名、联系方式（电话、邮箱）、求职意向
2. **教育背景** — 学校、专业、学位、时间、GPA（较高时列出）、相关课程/荣誉
3. **工作/实习经历** — 公司、职位、时间、主要职责和成就（使用STAR法则）
4. **项目经验** — 项目名称、角色、时间、描述、技术栈、个人贡献
5. **技能清单** — 专业技能、工具/框架、语言能力、证书
6. **其他加分项**（可选） — 开源贡献、技术博客、竞赛获奖、志愿者经历

**【硬性规则】** 用户回复后**立即开始构建 Markdown 简历**，未提供的信息用 `[待补充]` 占位符标注，用户可在 Markdown 中自行填写。**禁止二次追问**，否则会引起用户反感。

### 步骤2：构建简历结构

标准简历结构（参照 output-templates.md）：

```
[姓名]
[联系方式] | [邮箱] | [LinkedIn/GitHub]

## 求职意向
[目标岗位]

## 教育背景
[学校] | [专业] | [学位] | [时间]

## 工作经历
[公司] | [职位] | [时间]
- 成就1（动词开头 + 量化）
- 成就2
- 成就3

## 项目经验
[项目] | [角色] | [时间]
- 技术栈 / 个人贡献 / 成果

## 技能
- 专业技能 / 工具框架 / 语言 / 证书
```

### 步骤3：生成 Markdown 简历并暂停

将组织好的内容生成为 Markdown 格式简历，写入当前工作目录（或 outputs 目录）文件，再通过 `present_files` 呈现给用户。

**【必须暂停】** 保存后告知用户：

> 「请确认并修改生成的 Markdown 简历，修改完成后我来帮你美化简历。」

此时**不要**自动生成 HTML，等待用户回复确认。

用户可能的操作：

- 直接回复「好了」「确认」「美化吧」 → 进入步骤4
- 提出修改意见 → 修改 Markdown 后重新保存，再次暂停等待确认
- 补充新内容 → 更新 Markdown 后重新保存，再次暂停等待确认

### 步骤4：生成 HTML 简历（用户确认后）

用户确认 Markdown 内容无误后，将 Markdown 转换为 HTML 简历（参照 templates/resume-template.html）：

- 使用简约现代风格，蓝白配色（`--primary: #2563eb`）
- 章节用 `<div class="section">` 包裹，标题用 `<div class="section-title">`
- 工作经历/项目经验用 `<div class="entry">` 包裹
- 技术栈用 `<span class="tag">` 标签样式展示
- 技能清单用 `<div class="skills-grid">` 双列布局
- **必须**包含 `@media print` 样式，设置 `print-color-adjust: exact` 保证导出 PDF 背景色不丢失

将 HTML 文件写入当前工作目录（或 outputs 目录），通过 `present_files` 呈现给用户。

- **必须**提示用户：在浏览器中打开该 HTML 文件，按 `Ctrl+P`（Mac: `Cmd+P`）即可导出 PDF。

### 步骤5：排版调整（可选）

用户可对 HTML 简历进行排版微调：

- 用户说"收紧" → 缩小 `.resume` 的 padding 和行间距（line-height）
- 用户说"放宽" → 加大 `.resume` 的 padding
- 用户说"紧凑" → 缩小字号（font-size）和间距（margin-bottom）
- 每次调整后重新将 HTML 写入工作目录文件、通过 `present_files` 呈现给用户预览效果

## 流程B：优化简历

### 步骤1：获取简历内容

- 用户直接粘贴文本：直接分析
- 用户上传文件：调用 `Read` 读取 PDF/图片简历（QoderWork 多模态 Read 支持 PDF 文档和图片识别）

### 步骤2：四维度评估

| 维度       | 检查要点                                |
| ---------- | --------------------------------------- |
| 结构清晰度 | 章节划分、信息层次、重点突出            |
| 内容质量   | 成就量化、动词有力、无冗余              |
| 针对性     | 岗位匹配、关键词充足（ATS）、核心竞争力 |
| 语言表达   | 语法/拼写、简洁专业、避免主观形容词     |

### 步骤3：按优先级列出改进建议

- **高优先级**：结构性问题、关键信息缺失、严重表达问题
- **中优先级**：成就可以更量化、动词不够有力、部分冗余
- **低优先级**：格式微调、措辞优化、细节完善

### 步骤5：输出 Markdown 版本并暂停

1. **修改对比版** — 使用 ~~删除线~~ 标注删除内容，**加粗** 标注新增内容
2. **最终优化版** — 干净的专业版本

将最终优化版 Markdown 写入当前工作目录（或 outputs 目录）文件，再通过 `present_files` 呈现给用户。

**【必须暂停】** 保存后告知用户：

> 「请确认并修改生成的 Markdown 简历，修改完成后我来帮你美化简历。」

此时**不要**自动生成 HTML，等待用户回复确认。

### 步骤6：生成 HTML 简历（用户确认后）

用户确认 Markdown 内容无误后，将最终优化版转换为 HTML 简历（参照 templates/resume-template.html）：

- 同流程A的步骤5：简约现代风格、蓝白配色、print-color-adjust: exact
- 将 HTML 文件写入工作目录并通过 `present_files` 呈现
- 提示用户：在浏览器中打开该 HTML 文件，`Ctrl+P` / `Cmd+P` 导出 PDF

### 步骤7：个性化建议

- 哪些技能应该前置
- 哪些经历应该详细展开
- 是否需要补充某些内容

## 流程C：面试准备

### 步骤1：解析简历关键点

从简历中提取：

- 核心技术栈和技能
- 重要项目经验
- 关键工作成就
- 教育背景亮点
- 可能的薄弱环节或空白期

### 步骤2：生成知识点清单

针对简历中每个技术点，列出面试官可能深入询问的知识点，按优先级排序：

- **必会 ⭐⭐⭐** — 该技术的基础核心概念
- **进阶 ⭐⭐** — 常见面试考点
- **深入 ⭐** — 高级主题或源码级别理解

### 步骤3：生成模拟面试题

为每个重点领域生成3类问题：

1. **基础概念题** — 考察对技术的理解深度
2. **实践应用题** — 考察实际项目经验
3. **情景分析题** — 考察问题解决能力

每道题附带：考察点、参考回答要点、常见误区

### 步骤4：生成行为面试题

基于工作经历生成行为面试题（STAR法则），每题附带：

- 考察维度（沟通能力、领导力、问题解决等）
- 回答框架（如何用STAR法则组织答案）
- 优秀回答示例

### 步骤5：输出完整面试准备文档

包括：

1. 技术知识点复习清单（按优先级）
2. 模拟面试题及答案要点
3. 行为面试题准备指南
4. 常见问题（自我介绍、优缺点、职业规划等）
5. 反问面试官的问题建议

### 步骤6：交互模拟面试（可选）

- 逐一提出问题
- 等待用户回答
- 给出反馈和改进建议
- 继续下一题
