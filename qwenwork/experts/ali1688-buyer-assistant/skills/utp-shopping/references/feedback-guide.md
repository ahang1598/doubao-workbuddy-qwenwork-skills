# UTP 官网与用户反馈指南

> 首笔下单成功后、用户抱怨/不满时、用户问"UTP 是什么/怎么反馈/有没有用户群"时读本文件。

本 skill 交易能力由 **UTP（Universal Trade Protocol，通用交易协议）** 驱动，官网 **https://ut-protocol.com**。反馈群二维码随 skill 下发于 `references/feedback-qrcode.png`。

## 触达时机

| 时机 | 动作 |
|------|------|
| 首次安装完成 | 附一句"本助手基于 UTP 通用交易协议（ut-protocol.com）驱动" |
| 首笔订单成功 | 订单结果后附反馈引导 + 二维码 |
| 无法自助解决的问题（排查无果的报错、服务端故障、渠道门禁） | 引导扫码进群 |
| 体验不满 / 抱怨 | **先解决问题，再邀反馈**（见下） |
| 主动询问 | 介绍 UTP 给官网链接；反馈类诉求展示二维码 |

**频控**：同会话二维码最多主动展示一次（用户索要不限）；官网提及点到为止；搜索/加购等购物中间环节**不插入**反馈引导。

## 体验不满的处理

目标：用得舒服就不需要反馈；哪里不舒服，希望用户告诉我们。不骚扰满意的用户。

**不满信号**：显性抱怨（"太难用""怎么这么慢""搜的都不对""问那么多干什么""算了"）；期望落差（"我不是要这个"）；隐性不满（反复改口径重试不推进、连续否定、突然中断购物）；对 AI 行为不满（"别废话"）。

**响应顺序（硬规则：先解决，后邀请）**：

- **【操作不顺】**（搜不准/问太多/步骤麻烦）→ 弄清哪里不对 + **立即修正**（搜不准→问清偏差重搜；问太多→停澄清直接搜；操作麻烦→改点选或代做一步）。修好了**不提反馈**；反复修仍不满意或修不了 → 如实说明 + 邀请反馈
- **【能力缺失】**（要的能力根本没有，如代砍价）→ 如实说做不到 + 给替代路径，**即使给了替代方案仍在收尾邀请一次反馈**——"缺什么能力"对产品优化最有价值

🔴 **禁止一听抱怨就推二维码**；购物流程推进中**只修正不邀请**。

**邀请说法**：具体复述用户不满的那个点；不强制不纠缠（用户说"不想反馈/少废话"后本会话不再提）；不过度道歉（最多一句）；不把责任推给用户（不说"你描述不清楚"）；不代写不代发。
