# 用户偏好指南

> 需要读/写用户偏好画像时读本文件。**读取每会话至多一次**（与澄清前的画像查询合并），结果全程复用；查不到就立即继续主流程，不重试。

## 存储优先级（三级降级）

偏好必须沉淀在用户自己的 Host 记忆体系里（而非 skill 私有文件），用户可见可管、其他会话/技能也能受益。

| 优先级 | 方式 | 用法 |
|--------|------|------|
| 1 | **千问 Work 内置记忆** | 读 `qwenwork_memory_search`（关键词：`采购偏好, 常购品类, 预算范围, 材质偏好, 发货地`）；需精读时 `qwenwork_memory_get`；写 `qwenwork_memory_write` 且**一律 `target=user`**（用户画像区），新发现 `add`、修正 `replace`、用户要求忘掉 `remove`。**不要**写 `memory`/`daily` 目标 |
| 2 | 其他 Host 的记忆工具 | 同上语义：澄清前搜索、确认后写入，按该 Host 参数规范组织 |
| 3 | 文件降级 `~/.utp/preferences.json` | 仅当记忆工具都不可用。结构：`{"profile": "自然语言画像", "updated_at": "ISO8601"}` |

## 写入内容规范

自然语言画像式描述，像真人导购对熟客的印象（如「采购偏好：裙装类喜雪纺面料，单件预算常在100～200元；习惯要电子发票；偏好江浙沪发货」），不写结构化表单。

**可写**：稳定偏好——材质倾向、常用预算带、发货地偏好、要发票的习惯、批量采购身份、品类倾向、决策风格、采购规模。
**不写**：一次性信息（本次买几条、临时收货地）。

写入前必须经用户确认（如"下次默认按雪纺+这个预算带帮你找？"），拒绝或修改按用户意愿处理。

## 用户身份信息

- 千问 Work 提供 `qw_query` 查账号/个人资料，可取收货城市等基础信息
- **收货地址不走记忆也不走对话采集**——结账需要地址时由地址卡片让用户自己选/填（隐私规范），agent 只记录"发货地偏好"这类非隐私地域倾向

## 首次采集与持续学习

- 首次：不做问卷式逐项询问，用一两个开放问题（"平时主要采购哪类商品？有没有预算范围或偏好的供应商？"）；用户想直接购物就跳过
- 持续：像逐渐熟悉老客户的导购那样积累理解，不限固定维度。执行时机仅两处：澄清后确认写回、结账后偏好学习步骤

## 偏好应用（辅助不限定）

结果展示时可标注"符合你的常购品类"；多规格时提示"你通常选 XX"；价格明显偏离画像预算时温和提醒；用户犹豫时结合画像建议；澄清时已知偏好变提问为前置确认（确认后才可合成进搜索词）。
