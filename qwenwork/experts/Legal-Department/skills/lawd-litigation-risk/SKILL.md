# 诉讼风险与清偿评估

## 一、能力总述

**一句话**：面向律师立案与保全决策，对目标企业做「诉讼风险」与「债务清偿能力」两类穿透评估——前者输出胜诉概率推演与执行风险评级，后者输出追偿评级、清偿率区间与可保全标的清单。

本单元对外是**一个技能入口**，内部按用户意图分流为两个模式：

| 模式 | 名称 | 解决的问题 | 核心产出 |
|------|------|-----------|---------|
| **模式A** | 诉讼风险评估 | 这个案子能不能打、打赢后能不能执行到 | 9 章诉讼风险报告 + 执行风险评级（极低/低/中/高/极高）+ 立案建议 |
| **模式B** | 债务清偿能力评估 | 对方还得起吗、保全什么、能收回多少 | 9 章清偿能力报告 + 追偿评级（S/A/B/C/D）+ 清偿率区间 + 保全标的清单 + T+N 行动时间线 |

两个模式共用同一套「企业工商信息查询」数据源（见 §四）与同一个交付门禁脚本（见 §五）。

## 二、触发与分流

### 2.1 意图 → 模式 路由表

| 用户意图（典型表述） | 命中关键词 | 路由 |
|---|---|---|
| 评估起诉某企业的风险、要不要立案 | 诉讼风险、立案评估、诉前评估、可行性 | **模式A** |
| 这案子胜诉概率多大、赢面如何 | 胜诉概率、赢面、胜诉率 | **模式A** |
| 对方是被告/原告的历史涉诉情况、司法状态 | 涉诉分析、司法状态、对手方分析、涉诉历史 | **模式A** |
| 判决拿到手能不能执行到、执行风险如何 | 执行风险、执行难度、判后执行 | **模式A** |
| 被起诉了要怎么应诉、应诉策略 | 应诉策略、答辩方向（仅风险面） | **模式A** |
| 对方还款能力如何、还得起吗 | 偿债能力、还款能力、债务清偿 | **模式B** |
| 要不要做诉前保全、保全什么标的 | 财产保全、诉前保全、保全标的、可执行资产 | **模式B** |
| 这笔债能收回多少、追偿值不值得做 | 追偿、清偿率、回收率、追偿评级 | **模式B** |
| 对方有哪些财产可以查封冻结 | 强制执行、查封、冻结、可执行资产 | **模式B** |

### 2.2 分流判定规则

1. **关键词命中优先**：命中模式A 关键词集 → 模式A；命中模式B 关键词集 → 模式B。
2. **两侧都命中 / 意图不明**：不要猜。用一句话反问确认，例如："您是要评估**能不能打赢、判后执行风险**（诉讼风险评估），还是要评估**对方还得起多少、保全什么**（清偿能力评估）？两者也可以连做。"
3. **提供了债权金额** 且提到追债/保全 → 直接进模式B（模式B 必须有债权金额，见 §B0）。
4. **A→B 连做**：模式A 输出中执行风险评级为「中 / 高 / 极高」时，**主动建议**接续模式B（执行风险高意味着必须靠保全兜住），用户同意后复用模式A 已取得的工商与司法数据，不重复调用。
5. **B→A 连做**：模式B 中发现对手方涉诉密集、诉讼应对成熟时，可建议接续模式A 补齐胜诉概率与应诉视角。

> 原两个技能互指的 NOT for 条目（诉讼风险评估 ↔ 债务清偿/保全评估）已**内化为本单元模式路由**，不再做跨技能跳转。

### 2.3 不适用场景（仍需跳转其他技能）

- **综合企业尽调** → `律师企业尽调报告`
- **签约前快速核验** → `合同相对方主体核验`
- **合同条款审查** → `律师合同预审`

## 三、模式工作流

> 两个模式的第一步都是「实体锚定」，第二步起都依赖 §四 的企业工商信息查询能力。**任何模式在开跑数据采集前，必须先完成 §四 的探测与匹配**；探测不到工商连接器时按 §四 A 档降级处理，不得硬跑。

### 模式A ｜ 诉讼风险评估

立案前的对手方诉讼风险全景评估。三层穿透扫描（企业当前司法 × 企业历史轨迹 × 核心人员涉诉），输出执行风险评级与立案建议。完整工作流细则（§A0 实体锚定 → §A2-§A4 三层扫描 → §A5 补充检索 → §A6 九章报告）已整体外移至 references。

> ⛔ 执行模式A 前，必须先完整读取 [references/mode-a-litigation-risk.md](references/mode-a-litigation-risk.md)，严格按其流程执行。

---

### 模式B ｜ 债务清偿能力评估

诉前财产保全决策的核心评估工具。对被告方执行"财务底盘 + 可执行资产 + 债务压力 + 历史偿债模式 + 实控人兜底"五维度穿透，输出追偿评级、清偿率区间与保全标的清单。完整工作流细则（§B0 锚定与参数确认 → §B2-§B6 五维穿透 → §B7 补充检索 → §B8 综合评级与输出）已整体外移至 references。

> ⛔ 执行模式B 前，必须先完整读取 [references/mode-b-recovery-assessment.md](references/mode-b-recovery-assessment.md)，严格按其流程执行。

## 四、数据源：企业工商信息查询能力

本单元两个模式**都依赖「企业工商信息查询」能力**。本节写"要什么能力 + 怎么找到它 + 找不到怎么办"，**不指定任何供应商**——运行时动态发现，多家可用时按匹配度选择。

### 4.1 所需能力语义清单

| # | 能力语义 | 一句话描述 | 用于 |
|---|---|---|---|
| ① | **企业主体定位** | 输入企业名/简称/品牌名/USCC，返回候选主体清单（含企业全称、USCC、登记状态） | §A0 / §B0 实体锚定 |
| ② | **工商登记信息** | 返回法定代表人、注册资本与实缴、成立日期、登记状态、注册地址、经营范围 | 模式A 章三 / §B2 |
| ③ | **股权结构与关联穿透** | 返回股东名册、实际控制人/受益所有人、对外投资、分支机构 | §B2 / §B3 / §B6 |
| ④ | **司法涉诉记录** | 返回裁判文书/涉诉清单与统计（案号、案由、当事人身份、裁判日期、涉案金额），含开庭公告、法院公告；支持历史区间更好 | §A2 / §A3 / §B4 |
| ⑤ | **强制执行与信用惩戒** | 返回被执行人、失信被执行人、限制高消费、终本案件（当前 + 历史），含案件数与执行标的金额 | §A2 / §A3 / §B4 / §B5 |
| ⑥ | **经营异常与合规负面** | 返回经营异常、严重违法、行政处罚、欠税公告、破产重整、注销备案 | §A2 补充 / §B2 / §B4 |
| ⑦ | **财务数据** | 返回资产负债与利润数据或财务比率（总资产/总负债、流动资产/流动负债、货币资金、应收账款、有息负债），**用于偿债能力判断** | §B2（模式B 第一判据） |
| ⑧ | **资产与权利负担** | 返回动产抵押、股权质押/出质、土地抵押、股权冻结、知产出质、对外担保（当前 + 历史） | §B3 / §B4 |
| ⑨ | **人员维度查询** | 输入人员姓名（+企业标识），返回该人员的涉诉/被执行/失信/限高/限出境/控制企业/个人投资 | §A4 / §B6 |

**能力分档**：①②④⑤ 为**必需**（缺任一即视为工商数据未取得）；③⑥⑧⑨ 为**重要**（缺失时对应维度标注"未核验"并下调置信度）；⑦ 为**模式B 关键**（缺失时按 §B2 无财务数据口径处理并将综合评级下调 1 级）。

### 4.2 探测

调用 `qwenwork_mcp_tool_list`，keyword 逐个尝试以下关键词（覆盖供应商名、能力英文名、能力中文名三类）：

```
企业 / 工商 / 企业信息 / 涉诉 / 失信 / 被执行 / 终本 / 股东 / 实控人 / 财务 /
company / enterprise / registration / judicial / execution / shareholder / financial / credit /
qcc / tianyancha / qibook / yuandian
```

探测结果按「能力语义清单」逐项登记命中情况，形成本次运行的能力覆盖表（哪些能力有、哪些没有）。**该能力覆盖摘要表必须附在报告「数据来源」章节**（能力语义 + 命中/未命中），使探测过程可审计。

### 4.3 匹配（按语义判定，不写死工具名）

1. 在返回工具中，按**工具名或 description** 是否命中 4.1 各项的语义关键词判定候选（关键词见 §A2/§A3/§A4/§B2-§B6 各表「语义关键词」列）。
2. **命中后必须用 `qwenwork_mcp_tool_get` 验证**：
   - 入参 schema 支持的主体标识形式（企业名 / USCC / 企业 ID / 人员姓名），并据此适配调用入参名与类型；
   - 返回 schema 是否包含本单元所需字段（见 4.1 与各 Step 表的「必需返回字段」）。
   - **返回 schema 不含所需字段的，视为该能力未命中，切换下一家候选**；不得因为工具名"看起来对"就直接调用。
3. 同一能力有多家候选时，按**匹配度**选择：①必需返回字段齐备度 → ②能力覆盖条目数（一家能覆盖更多能力优先，减少跨源口径冲突）→ ③是否支持历史区间与分页。
4. 多源数据冲突时，以工商登记类能力（②）的主体信息为锚，逐项标注来源代码后在报告「互证方法」中说明取舍。

### 4.4 调用

- 用 `qwenwork_mcp_tool_call` 执行；同一层级的多个维度**并行调用**。
- 首选候选调用失败（报错/超时/鉴权失败/空结构）时，**切换下一家**候选并在报告中记录切换事实。
- 每次调用只传该工具 schema 支持的参数；分页能力存在时须翻页取全，避免只取首页造成计数偏低。

### 4.5 降级（A 档：准确性即价值，禁止硬跑）

本单元结论直接用于**立案与财产保全决策**，属 **A 档**（拒绝降级）。

**探测不到任何企业工商信息连接器（或必需能力 ①②④⑤ 缺失）时：**

1. **停止执行，禁止输出完整评估结论**（不得输出执行风险评级、立案建议、追偿评级、清偿率测算、保全标的清单等结论章节）。
2. 告知用户：
   > 本单元需要「企业工商信息查询」能力（企业主体定位、工商登记、司法涉诉、强制执行与信用惩戒等）。当前未探测到可用连接器，请前往 **千问办公 设置 → 连接器**，搜索并安装**企业信息类连接器**后重试。
3. 若用户**坚持要初步判断**：只能基于**用户自报信息**输出，且必须：
   - 报告头部声明 `**工商数据获取状态：** 未取得`；
   - 报告顶部加醒目提示"本文基于用户自报信息，未经工商数据核验，不得作为立案/保全决策依据"；
   - **全文每一项事实与判断均标注「未核验」**；
   - 只出"待核验事项清单 + 初步方向"，**不出**结论章节与任何评级/概率/清偿率数字。

**禁止事项（硬红线）**

- 禁止用网页检索（WebSearch）或模型记忆顶替工商连接器数据后不加标注；
- 禁止在无工商数据的情况下照常输出评级、胜诉概率、清偿率；
- 禁止把"连接器缺失"当异常抛出——它是必然场景，须按上述话术处理；
- 禁止在本 SKILL 与报告正文中写死任何连接器/供应商/server_id 名称（报告「数据来源」列填运行时实际匹配到的展示名除外）。

## 五、门禁脚本

**脚本**：`scripts/validate_risk_report.py`（独立可运行，`--help` 查看用法）

```bash
python3 scripts/validate_risk_report.py <报告文件.md> [--mode auto|litigation|recovery] [--registry-data auto|available|missing]
```

**校验三件事**

| # | 校验项 | 拦截条件 |
|---|---|---|
| 1 | **概率/清偿率数字合理性** | 胜诉概率 / 清偿率 / 回收率 / 追偿率若出现，必须是区间或带明确依据；出现无依据的单一精确数值即拦截（防模型心算拍脑袋） |
| 2 | **工商数据缺失硬门禁** | 报告须含 `**工商数据获取状态：** 已取得/未取得` 声明行；声明「未取得」时出现完整评估结论章节（执行风险评级/立案建议/追偿评级/清偿率测算/保全标的清单等）即拦截，且必须含「未核验」标注与安装连接器提示 |
| 3 | **必备章节齐备** | 按模式校验 9 章是否齐备，缺章即拦截 |

**交付前必须运行本脚本，未通过禁止交付。** 脚本以非零退出码阻断交付；拦截清单逐条列出问题，修复后重跑至通过为止。**禁止**以"脚本报错/环境问题"为由跳过门禁。

## 六、交付物

**交付路径**：所有最终交付物（.docx / .md）一律写入当前工作区的 `outputs/`（复数）目录；`outputs/` 是 UI 唯一扫描的交付目录，写成单数 `output/` 用户看不到成果。报告须落盘并核对文件存在后才可向用户报告路径。

| 模式 | 产出物 | 格式 | 必备构件 |
|------|--------|------|---------|
| **模式A** | 诉讼风险评估报告 | 默认 `md`；用户要正式文书时 `docx` | 9 章齐备（模板见 [output-report.md](references/output-report.md)）；执行摘要 Decision Pack；五维司法清查表；年度趋势表；关键案件表（≤6 件）；执行风险评级（全文唯一且一致）；胜诉概率以区间或带依据表述；置信度分布；`工商数据获取状态` 声明行；每条判断附来源代码 |
| **模式B** | 债务清偿能力评估报告 | 默认 `md`；用户要正式文书时 `docx` | 9 章齐备（模板见 [recovery-output-report.md](references/recovery-output-report.md)）；追偿评级 S/A/B/C/D + 五维度得分；预期回收率**区间** + 三档测算表；可执行资产清单（每项具体标的/登记状态/净值/执行难度/建议保全金额）；建议保全金额与担保金提示；T+N 行动时间线；`工商数据获取状态` 声明行 |
| **A+B 连做** | 两份报告 + 一页联合结论 | 同上 | 联合结论须同时给出执行风险评级与追偿评级，并说明"能不能打 × 收不收得回"的组合建议；两份报告分别过门禁 |
| **降级场景** | 待核验事项清单 + 初步方向 | `md` | 顶部降级提示 + 全文「未核验」标注 + 连接器安装指引；**不含**任何评级/概率/清偿率 |

**交付流程（强制顺序）**

1. 完成模式工作流 → 生成报告草稿（含 `工商数据获取状态` 声明行）
2. 运行 `python3 scripts/validate_risk_report.py <报告> --mode <litigation|recovery>`
3. 有拦截项 → 修复 → 重跑，直至通过
4. 通过后交付，并在交付说明中附门禁通过结论

## 边界与免责

本单元基于企业工商信息连接器返回的公开数据 + 补充检索生成评估结论。

- **模式A**：胜诉概率推演基于历史数据统计经验，个案实际结果受法官裁量、诉讼时机、证据充分性等多重因素影响。
- **模式B**：可执行资产估值基于公开登记信息与行业经验估算，并非司法评估价；真正的保全顺位、查封金额、拍卖价格以法院实际处置为准。财务数据能力对非上市且未披露财报的企业可能返回空数据，此时通过事件信号间接推断，置信度相应降低。刺破公司面纱涉及复杂法律论证，本单元仅提供数据线索与路径初判。

本单元输出属**决策支持材料**，不构成对诉讼结果或追偿结果的承诺，具体情形请由承办律师判断。

## 可选套件上下文（不影响独立使用）

1. 工作目录根存在 `套件运行规则.md` 时必须先读取并执行；不存在时以本技能硬规则为准，不影响独立使用。
2. 工作目录根存在 `办案画像.md` 时，只读取与当前任务有关的诉讼立场、风险偏好和文书风格；不存在时按本技能默认运行，不追问、不报错。
3. 仅当用户明确切换到某案或提供唯一案件路径时，读取 `cases/{案件简称}/案件画像.md`；不得猜测案件，不得跨案带入。
4. 画像只影响表达与偏好，不得覆盖事实、法律依据、必备结构、验证结果或本技能硬规则。
5. 已明确绑定唯一案件且案件管家可用时，成果完成后提交标准案件事件；无案件不建档、不回写，回写失败不得阻塞成果交付。
