# 材料接收与评估清单

用于建立证据索引、识别材料局限并准备生成脚本所需的结构化数据。

## 一、最小可处理材料

开始实质质证至少需要：

1. 代理方身份；
2. 对方证据编号、名称和可阅读的具体内容；
3. 对方主张的证明目的，或足以从材料中可靠识别该目的的内容。

起诉状、答辩状、己方证据、庭审通知和完整卷宗均能提升质量，但不是每次处理的机械前置条件。缺少增强材料时，记录局限并限定结论范围。

## 二、证据索引字段

| 字段 | 要求 |
|---|---|
| `id` | 沿用对方证据编号；没有编号时使用稳定临时编号并说明 |
| `name` | 按材料原名记录，不润色为不存在的正式名称 |
| `submitter` | 原告、被告、第三人或其他实际提交主体 |
| `purpose` | 对方明确写明的证明目的；无法确认时写“待核验” |
| `locator` | 页码、条款、段落、文件名或时间戳；禁止编造页码 |
| `evidence_type` | 书证、物证、视听资料、电子数据、证人证言、鉴定意见等 |
| `form_status` | 原件、复制件、截图、打印件、原始载体等已知状态 |
| `known_context` | 形成、签署、取得、保管、提交等已由用户说明的事实 |
| `missing_information` | 影响判断的具体缺项 |

## 三、接收核对

- [ ] 清单项数与实际收到的材料项数一致；
- [ ] 编号唯一，分组不影响单项编号；
- [ ] 每项证据可以定位到原材料；
- [ ] 没有把附件中的附件误当成独立证据，或反之；
- [ ] 对复印件、截图、节选和转录件如实记录材料形态；
- [ ] 对方证明目的与己方理解分开记录；
- [ ] 用户口述事实与文书可见事实分开记录；
- [ ] 争议焦点不明确时，避免过度推断关联性和证明力。

## 四、四维评估卡

每项证据复制一份评估卡：

```text
证据编号：
证据名称：
对方证明目的：

真实性：无异议 / 有异议 / 待核验 / 不适用
理由与材料定位：

合法性：无异议 / 有异议 / 待核验 / 不适用
理由与材料定位：

关联性：无异议 / 有异议 / 待核验 / 不适用
理由与材料定位：

证明力：无异议 / 有异议 / 待核验 / 不适用
理由与材料定位：

认可部分：
单项结论：
程序性申请：
反证建议：
```

## 五、状态使用检查

### 无异议

- 当前材料没有显示可支持异议的具体事实；
- 只对相应维度表态；
- “真实性无异议”不得写成“认可对方证明目的”。

### 有异议

- 指明材料中的事实基础和定位；
- 说明该问题如何影响相应维度或证明目的；
- 避免只写“形式不合法”“关联性不足”等空话。

### 待核验

- 指明缺少什么，例如原件、完整聊天记录、原始载体或签收主体信息；
- 指明如何核验；
- 说明核验结果可能怎样影响结论；
- 不得把“未看到”写成“客观不存在”。

### 不适用

- 仅在该维度确实无法适用于具体问题时使用；
- 写明不适用原因，不得用来回避分析。

## 六、暂停和继续的判断

仅在以下情况暂停并向用户提问：

- 无法识别正在质证哪一项证据；
- 缺失内容会使实体结论发生明显分叉；
- 用户要求正式文书，但提交人、提交方或证据范围无法确定；
- 用户要求引用具体法律依据，但无法核验法规版本。

以下情况无需暂停：

- 仅缺少建议性增强材料；
- 某一维度可以明确标为“待核验”；
- 非关键格式信息可以如实写“未提供”；
- 用户已明确要求直接生成，且现有材料足以限定范围完成。

## 七、交付前一致性清单

- [ ] 每个索引编号都进入 `evidence_items`；
- [ ] 每项四个维度齐全；
- [ ] 单项结论与四维理由不冲突；
- [ ] 总结论未夸大单项结论；
- [ ] 程序申请与具体证据关联；
- [ ] 反证建议没有虚构现有证据或获取线索；
- [ ] 所有事实和引文可回到用户材料或已核验官方来源；
- [ ] DOCX 生成输入不含占位符。
