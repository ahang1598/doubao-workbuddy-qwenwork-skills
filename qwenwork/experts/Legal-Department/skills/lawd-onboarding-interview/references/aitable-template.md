# 案件台账模板规格（aitable-template）

> 本文件是台账 **20 项最小字段集** 的唯一规格来源，同时服务两种载体：
> - **在线表格**：产品方预建的模板 Base 按本规格配字段、视图、格式；
> - **本地文件**：`scripts/init_local_ledger.py` 生成的 `cases/案件台账.xlsx` 表头与本规格逐字段一致。
>
> 字段与案件管家 `SKILL.md` 第 1 节「台账最小字段集（20 项）」一一对应，改字段须两处同步。

## 二、模板分发（在线表格用）

**通道：钉钉 AI 表格模板市场 + `base create --template-id`。** 新建台账统一走此通道，不动态逐字段创建，也不用 base copy。

| 项 | 值 |
|---|---|
| 模板 templateId | `1824` |
| 上架源 | 「案件台账模板」Base（baseId: P0MALyR8knpgo9GycYAnAaOXJ3bzYmDO，主表「案件台账」），按第一节规格配齐字段与视图后提交上架 |
| 主表名 | 案件台账 |
| 必备视图 | 全部案件 / 待办（按第 12 项分四档）/ 临期看板（按第 13–15 项） |
| 字段与格式 | 严格按第一节配置；单选字段预置选项与配色 |

建表命令：

```bash
dws aitable base create --name "案件台账" --template-id <templateId>
```

规则与依据：

1. **归属**：新建 Base 直接归执行命令的律师本人。AI 表格有归属人概念，不能把任何现成表的 baseId 直接给律师（只有查看权限、无法管理）。
2. **结构整体携带**：字段、视图、仪表盘、说明文档由模板带过去，无需逐字段创建，也不指定目标文件夹（默认落在律师自己的空间）。
3. **标识回写**：创建成功后取新 baseId，再查主表 tableId，写入 `办案画像.md` 第三节「台账标识」：`baseId: xxx · 主表 tableId: xxx · 表格名: 案件台账`。
4. **失败处理**：创建失败 → 向律师说明原因，可改选本地文件；不静默降级、不拿其他现成表的 baseId 顶替。
5. **搜索索引不依赖**：`template search` 可能搜不到该模板（实测 templateId=441 搜索 0 命中但直接指定可用），技能内写死 templateId 即可，不受影响。

**为什么不用其他通道（2026-08-12 实测结论）**：

- **base copy（已废弃）**：要求对源 Base 有阅读权限；跨组织场景下外部身份一律拿不到他组织 Base 的阅读权限（两个组织复现，`ORG_DOC_TOKEN_MISMATCH`），链接分享也不传导到 API 层。中心化"公开知识库 + base copy"路线不可行。
- **field create × 20 动态创建（不用）**：只能建字段，视图、格式带不过去，且 20+ 步调用失败面大。
- **模板市场通道（实测通过）**：平台级消费模板，律师身份无需对模板源有任何权限，天然绕开跨组织墙；字段/视图/仪表盘/文档全量携带。

## 三、本地 Excel（本地文件用）

| 项 | 值 |
|---|---|
| 文件路径 | `cases/案件台账.xlsx` |
| Sheet 名 | `案件台账` |
| 表头 | 第一节 20 个字段名，顺序一致，首行冻结、加粗 |
| 读写工具 | openpyxl（案件管家 `scripts/ledger_excel.py`），不用文本方式读写 |
| 备份 | 每次写入前备份上一版为 `cases/案件台账.backup.xlsx` |
| 占用保护 | 文件被打开占用导致写入失败时报错提示律师关闭后重试，**不静默跳过** |

创建初始文件：

```bash
python3 scripts/init_local_ledger.py --path cases/案件台账.xlsx
```

退出码：`0` 创建成功；`1` 文件已存在（保留原文件，沿用即可）；`2` 目录不可写等 IO 错误。
