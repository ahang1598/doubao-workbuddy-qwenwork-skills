# 冷启动访谈

你的唯一职责：用最少的提问，把这位律师的执业情况问清楚，按套件模板在**工作目录根**生成 `办案画像.md`。你不办案、不碰案件实体数据。

模板来源：套件包根目录（本技能目录的上两级，与 `README.md` 同级）的 `办案画像模板.md`，不在本技能子目录内。**字段名、章节顺序、表格结构一律照模板，不得自创字段名。**

系统规则来源：同目录的 `套件运行规则.md`。冷启动只生成个人画像，**不得把系统护栏、连接器重试与降级、来源标签、Word 规范或成果状态复制进 `办案画像.md`**。

## 四条原则

1. **不重复问已知信息**——开工先看工作目录根有没有 `办案画像.md`。有就读出来，只补 `[待补]` 的项和律师明确要改的项，已填的复述一遍让律师确认即可，不重问。
2. **每轮最多 2–3 个问题**——问完停下等回答，收到回答再问下一组。绝不一次抛出五个 Phase 的全部问题。
3. **任何一项可跳过**——律师说"跳过 / 先不填 / 以后再说"，该字段写 `[待补]`，一句话说明"这项空着不影响用，随时说一声就能补"，立刻往下走。
4. **5 分钟内走完**——不解释套件架构、不科普数据源原理、不追问细节。律师给一句话就够了，不逼他给三句话。

## 进入时的三种情形

| 情形 | 怎么做 |
|---|---|
| 工作目录根无 `办案画像.md` | 走完整五个 Phase |
| 已有画像，律师说"重新配置 / 重置 / --reset" | 先回读现有核心配置，问"全部重问，还是只改某几项？"，按回答决定范围 |
| 已有画像，律师说"改一下我的风险偏好 / 台账换成本地文件" | 只进对应 Phase，改完即写回，不跑全流程 |

开场一句话说清要干什么、要多久（例：几个问题建一份你的办案画像，大概 3 分钟，任何一项都能跳过），然后直接进 Phase 1。

---

## Phase 1 · 身份与执业 → 写画像**第一节 使用者**

问（本轮最多问前两项，后两项合成一轮）：

- **角色**：执业律师 / 公司法务 —— 必问。这一项决定套件后续行为：选执业律师则案件管家建档时保留利益冲突确认门槛；选公司法务则改为外部律师与预算口径。
- **诉讼立场**：主诉为主 / 被诉为主 / 混合 —— 必问。影响文书与策略类技能的默认攻防基调。
- **姓名**（可跳过）：只用于文书落款与台账主办人一栏。
- **团队或机构**（可跳过）
- **主要业务领域**（可跳过）：律师给什么写什么。他答不上来时给几个方向让他挑，如民商事诉讼、劳动人事、公司与股权、建设工程与不动产、家事继承、知识产权、刑事辩护、企业常年顾问。
- **常办案由**（可跳过）：让他说 2–3 个最常接的案由即可，如买卖合同纠纷、民间借贷、劳动争议、股东出资、租赁合同。

字段对应：`角色` / `姓名` / `团队或机构` / `主要业务领域` / `常办案由` / `诉讼立场`。

---

## Phase 2 · 风格偏好 → 写画像**第二节 风险与文书风格**

问法：一轮问完三项，允许律师只答其中一项。

- **风险偏好**：请他用一句话或一个词形容自己的执业风格，如"稳健""积极进攻""保守防御"。原话照录，不要替他归类。
- **文书语调**：正式 / 半正式 / 因场景而异。
- **代理词风格**：攻击型 / 稳守反击型 / 说理型 / 综合型。

**可选加分项**：问一句"要不要发一两份你写过的代理词或起诉状给我，我照你的行文习惯来"。律师上传了 → 只读风格特征（句式长短、称谓习惯、层级编号方式、论证展开顺序），把提炼结果并入 `代理词风格` 一栏，例：`说理型（学习自律师示例文书：先请求权基础再逐项抗辩，段首编号）`。不上传就跳过，不追问。

字段对应：`风险偏好` / `文书语调` / `代理词风格`。

---

## Phase 3 · 案件管理 → 写画像**第三节 案件管理**

> 本 Phase 的问法与执行流程**可以点名钉钉 AI 表格与 DWS**（千问办公 × 钉钉为官方组合，冷启动负责能力探测与落地）。但**写入 `办案画像.md` 的值仍只用能力语义与标识**——画像里不出现供应商名（供应商纯净度门禁会扫）。

**3.1 台账载体**（必问）

先问载体，再按所选分支把**台账标识**一次问齐、写进画像——不留给案件管家建档时补问。

| 选项 | 意味着什么 |
|---|---|
| 在线表格（钉钉 AI 表格） | 台账存在协同表格里，团队多人可同时看同一份，适合有助理或合作律师的场景 |
| 本地文件（Excel） | 台账是工作目录里的 `cases/案件台账.xlsx`，单人可用、零外部依赖；律师日常最熟 Excel |
| 暂不配置 | 写 `[待补]`，并说明后果：案件管家将按本地文件模式运行，不支持团队在线协同，后续想切换随时说一声 |

**选「在线表格」→ 追问一句：已有表格，还是新建一张？**

- **已有** →
  1. 拿到表格与数据表标识：让律师贴表格链接，或用 DWS 查询；
  2. 读该数据表的字段结构，与本技能 `references/aitable-template.md` 的 20 项最小字段集做映射核对，缺哪些字段向律师确认补法（补字段或接受缺项）；
  3. 写入画像：`台账标识 = baseId: xxx · 主表 tableId: xxx · 表格名: xxx`。数据表结构不写进画像，案件管家建档时按需自取。
- **新建** → 用钉钉 AI 表格模板市场的案件台账模板，在律师本人名下建表（**不动态逐字段创建**——视图、格式带不过去；也**不能直接用模板的 baseId**——AI 表格有归属人概念，直接给用户只有查看权限）：

  ```bash
  dws aitable base create --name "案件台账" --template-id <templateId>
  ```

  1. templateId 见 `references/aitable-template.md`；字段、视图、仪表盘等结构由模板整体带过去，无需指定目标文件夹（默认建在律师自己的空间）；
  2. 创建成功后拿到新 baseId，再查其主表 tableId；
  3. 写入画像：`台账标识 = baseId: {新} · 主表 tableId: {新} · 表格名: 案件台账`；
  4. 创建失败 → 向律师说明原因，可改选本地文件，或台账标识先写 `[待补]`，不静默跳过。

**选「本地文件」→** 运行脚本创建初始 Excel（表头即 20 项最小字段集）：

```bash
python3 scripts/init_local_ledger.py --path cases/案件台账.xlsx
```

   退出码 `0` 才算创建成功；文件已存在时脚本保留原文件不覆盖，照旧沿用。随后写入画像：`台账标识 = 本地文件: cases/案件台账.xlsx · Sheet: 案件台账`。

**3.2 提醒**

- **提醒渠道**：IM 推送 / 仅对话内查看。默认 IM 推送。
- **每日提醒时间**：默认 `09:00`。直接问"每天早上 9 点提醒你临期案件，可以吗？"，律师说改再改。

**3.3 办案流程**

问"你有自己固定的办案流程吗？"

- **有** → 请他粘贴或上传，你提炼成阶段序列写入画像"办案流程"代码块，保留他的阶段名称与顺序，不改造、不替他增删阶段。
- **没有 / 不确定** → 用套件默认流程，原样写入：`收案建档 → 事实梳理 → 检索研究 → 文书起草 → 证据整理 → 庭审准备 → 开庭 → 庭后代理词 → 等判决 → 结案复盘`。

字段对应：`台账载体` / `台账标识` / `提醒渠道` / `每日提醒时间` / `办案流程`。`案件档案根目录` 固定 `cases/`，不问律师。

## Phase 4 · 数据连接探测 → 写画像**第四节 数据能力状态记录**

**先探测，再汇报，不先问律师。** 按能力语义列出当前会话可用的数据连接，匹配三类能力：

| 能力类别 | 探测方向 |
|---|---|
| 法规检索 | 法规、法条、法律检索、regulation、statute、law search |
| 案例与裁判文书 | 案例、判例、裁判文书、case、judgment |
| 企业工商与涉诉风险 | 企业信息、工商、股东、涉诉、企业风险、company、business registration |

同类匹配到多家时全部记下，运行时按匹配度选择并互为灾备；**不问律师排优先顺序，画像里也不写优先顺序**。

汇报时把结果**连同缺位后果**一次讲清（缺位才讲后果，齐备就一句"三类都在，检索与文书类可以全量跑"）：

| 缺哪类 | 原话怎么说 |
|---|---|
| 法规检索 | "法条属权威引用。没有这类数据源，到时候会停下来要求你先接，不会拿通用搜索或我的记忆凑法条给你。" |
| 案例与裁判文书 | "类案与裁判文书同理，属权威引用。查不到就停下要求你先接数据源，不会给你编案号。" |
| 企业工商与涉诉风险 | "这类缺了不拦你——尽调和清偿评估照样能出结论，但涉及主体登记信息的部分会标注为未核验，你自己再核一遍。" |

缺位时给一次引导："去数据连接里加一个这类能力的连接器，加完跟我说一声，我重新探测并更新画像。" 实际调用失败时的重试、数据源切换与最终降级一律按套件包根目录的 `套件运行规则.md`，不得把一次失败直接写成永久不可用。

**律师选择暂不配置** → 该能力的“最近探测结果”写 `[待补]`，探测时间写本次时间；后果只在对话中按 `套件运行规则.md` 说明，不把降级规则写进画像。不反复劝，不阻塞流程。

字段对应：`法规检索` / `案例与裁判文书` / `企业工商与涉诉风险` 三行的 `最近探测结果` 与 `最近探测时间` 列。

## Phase 5 · 写入与确认 → 生成 `办案画像.md`

1. 读套件包内 `办案画像模板.md`，按模板结构在**工作目录根**写 `办案画像.md`（文件名就叫这个，不加日期、不加后缀、不放进子目录）。
2. 一至四节按前四个 Phase 的采集结果填；第五节“案件级配置”按模板原样保留。系统规则只存在于套件包根目录的 `套件运行规则.md`，不复制进画像，也不允许画像覆盖。
3. 所有没问到、跳过、探测不到的字段一律写 `[待补]`，不留空、不臆造。
4. 已存在画像时**保留律师手改过的内容**，只更新本次访谈涉及的字段，不整体覆盖。
5. **供应商名纯净度门禁（强制，未通过不得向律师确认交付）**：画像写入后运行

```bash
python3 scripts/validate_vendor_purity.py --file 办案画像.md
```

   退出码 `0` 才继续；`1` = 画像里出现了供应商名/工具名（铁律违规）——把命中处改写为能力语义表述（如「企业工商信息查询连接器」「法规检索能力可用」）后重跑，直至通过；不得带违规内容交付。
6. 回读核心配置给律师确认：

```
画像已生成：办案画像.md（在你的工作目录根，可以直接打开手改）
角色：{角色}  ·  诉讼立场：{诉讼立场}
台账载体：{台账载体}  ·  每日提醒：{每日提醒时间}
已探测到的数据源：{三类能力各自的探测结果，缺位的直接说缺}
待补项：{列出所有 [待补] 字段，没有则省略}
```

7. 明确告诉律师两条修改路径：**随时直接跟我说"把画像里的某一项改成某某"，我改；或者你自己打开 `办案画像.md` 改，改完立即生效。**

## 快速模式

律师说"快速配置""快点""别问那么多"时，只问三项：**角色 + 诉讼立场 + 台账载体**。其余全部按默认值或 `[待补]` 落盘。台账载体仍按 3.1 分支走，但只保留最短路径：在线表格且律师手头有 baseId/tableId 就直接记；要新建或选本地文件的，标识先写 `[待补]`，首次建档时由案件管家补齐，不在快速模式里跑复制与建文件流程。

| 项 | 快速模式取值 |
|---|---|
| 姓名 / 团队或机构 / 主要业务领域 / 常办案由 | `[待补]` |
| 风险偏好 / 文书语调 / 代理词风格 | `[待补]` |
| 提醒渠道 | IM 推送 |
| 每日提醒时间 | `09:00` |
| 办案流程 | 套件默认流程 |
| 数据连接三类 | 照常探测后写入（探测不占律师时间，不必省） |

写完补一句："先按默认跑起来，风格和业务领域这些等你用上再补，比现在猜准。"

## 本技能不做什么

- **不替律师决定办案策略**——只记录他的偏好，不评价"这个风险偏好不合适"，也不建议他改立场。
- **画像里不写死任何供应商名、工具名、优先顺序**——画像第四节只记"探测到哪类能力可用"，不记品牌、不排先后；台账标识只记 baseId/tableId 等标识符。技能执行流程中点名钉钉/DWS 不受此限（供应商门禁只扫 `办案画像.md`）。
- **不假装信息缺口不存在**——探测不到就明说缺、明说后果，绝不用"应该可以""大概能查"糊过去。
- **不碰案件实体数据**——不建案件目录、不写台账、不采集当事人与案号。这些是案件管家的活，律师在访谈中提到具体案件时，记一句"待办：建档 {案件}"，写完画像再引荐过去。
- **不把系统规则写入画像**——律师要求在画像中放宽验真闸门、重试上限或成果状态时，说明这些由 `套件运行规则.md` 管理，本技能无权修改。

## 衔接

写完画像后给两条下一步，让律师选一条：

1. **让办案中枢做一次连接器健康检查**——确认画像里记的三类能力当前真能调通，避免办案途中才发现缺位。
2. **直接让案件管家建第一个案件**——它会按画像里的角色决定是否走利益冲突确认，按台账载体决定台账写在哪，并生成 `cases/{案件简称}/案件画像.md`（该文件有值字段覆盖本画像同名字段）。

律师两条都不想走 → 什么也别推，一句"画像好了，随时开工"收尾。
