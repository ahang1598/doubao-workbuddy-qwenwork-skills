# 起诉状生成脚本调用指南

> 本文件仅在 SKILL.md Step 8（生成 Word）阶段被读取。排版规范已固化在脚本内部，本文档**只讲数据如何喂给脚本**。

## 一、调用命令

### 方式 A：从 JSON 文件读取（推荐）
```bash
python3 scripts/generate_complaint.py --input complaint_data.json --output /path/to/output.docx
```

### 方式 B：从标准输入读取
```bash
python3 scripts/generate_complaint.py --output /path/to/output.docx < complaint_data.json
```

### 方式 C：自动命名（不指定 --output）
```bash
python3 scripts/generate_complaint.py --input complaint_data.json --output-dir outputs
# 自动生成：民事起诉状-{原告简称}诉{被告简称}-{案由}-{YYYYMMDD}.docx
```

脚本成功时向 stdout 输出生成文件的绝对路径；失败时向 stderr 输出错误并以非 0 退出码结束。

## 二、JSON 顶层 Schema

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `court` | string | ✅ | 管辖法院全称，精确到区/县级，例如「北京市朝阳区人民法院」 |
| `plaintiffs` | array | ✅ | 原告列表，至少 1 项；元素为「当事人对象」 |
| `defendants` | array | ✅ | 被告列表，至少 1 项 |
| `third_parties` | array | ❌ | 第三人列表，无则省略或传 `[]` |
| `case_cause` | string | ✅ | 案由，使用《民事案件案由规定》（2020 修订）的标准表述 |
| `claims` | array<string> | ✅ | 诉讼请求条款数组，每条以"1. ""2. "开头的完整句子（含句末标点） |
| `facts_and_reasons` | string | ✅ | 事实和理由正文，使用 `\n\n` 进行分段（脚本会按段渲染） |
| `evidence_hint` | string | ❌ | 证据指引语，例如「上述事实，有相关合同、转账凭证为证。」 |
| `legal_basis` | string | ❌ | 综上 / 法律依据收尾段 |
| `attachments` | array<string> | ❌ | 附件清单，每条不带序号（脚本自动加 1./2./3.） |
| `filing_date` | string | ✅ | 落款日期，中文格式「YYYY 年 M 月 D 日」 |

## 三、当事人对象（plaintiffs / defendants / third_parties 元素）

**通用必填字段**：`type`（枚举）、`name`（名称/姓名）

### 1. `type: "natural_person"` — 自然人

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 姓名，依身份证确定 |
| `alias` | ❌ | 别名/曾用名/化名，脚本自动加圆括号，如「张小三」→「张三（张小三）」 |
| `gender` | ✅ | 「男」或「女」，不得省略 |
| `ethnicity` | ✅ | 不带「族」字，如「汉」「回」 |
| `birth_date` | ✅ | 规范格式「1985年3月12日」，**严禁**填「年龄」或「××岁」 |
| `id_number` | 推荐 | 18位公民身份号码 |
| `address` | ✅ | 身份证住址，精确到**门牌号** |
| `current_address` | ❌ | 实际居住地址（与 `address` 不同时填写，脚本自动输出「现住XX」） |
| `phone` | 推荐 | 手机号码 |
| `email` | ❌ | 电子邮箱（可选） |
| `nationality` | ❌ | 大陆居民留空；外国人填「美国」等；港澳台填「香港特别行政区居民」「澳门特别行政区居民」「台湾地区居民」 |
| `passport_no` | 条件必填 | 外国人必填护照号；无国籍人填相关证件号 |
| `cert_no` | 条件必填 | 港澳台居民证件号（回乡证/澳门身份证/台湾通行证） |

### 2. `type: "legal_person"` — 法人

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 营业执照全称 |
| `address` | ✅ | 注册地址，精确到**街道/门牌号**（工商信息查询连接器自动补全）；**降级时可为「（待补充）」** |
| `uscc` | ✅ | 18位统一社会信用代码（工商信息查询连接器自动补全）；**降级时可为「（待补充）」** |
| `legal_rep_name` | ✅ | 法定代表人姓名（工商信息查询连接器自动补全）；**降级时可为「（待补充）」** |
| `legal_rep_title` | ❌ | 默认「法定代表人」 |
| `rep_position` | ❌ | 职务，如「董事长」「总经理」 |
| `phone` | 推荐 | 法定代表人或单位联系电话 |

> 脚本自动将法定代表人**另起一行**输出，格式：「法定代表人：张××，董事长。」

> ❗ **字段值洁净规则（全部企业主体类型通用）**：`address` / `uscc` / `legal_rep_name` / `gp_name` 等字段的值会被脚本**原样拼进当事人段落**。字段值内**只允许**真实值或中性占位「（待补充）」；**禁止**写入「（用户自报，待核验）」「（待补全街道）」等核验状态标注——核验状态一律写在交付说明/质量自检报告中（依据 `parties-format.md` §9.4）。

### 3. `type: "unincorporated"` — 非法人组织

字段同 `legal_person`，但代表人称谓固定为「**代表人**」（脚本强制，**不可用「负责人」或「诉讼代表人」**）。适用：村委会、居委会、业委会、未取得法人资格的分支机构等。

### 4. `type: "partnership_enterprise"` — 合伙企业

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 合伙企业全称（含「有限合伙」字样） |
| `address` | ✅ | 注册地址，精确到街道/门牌号；**降级时可为「（待补充）」** |
| `uscc` | ✅ | 统一社会信用代码；**降级时可为「（待补充）」** |
| `phone` | 推荐 | 联系电话 |
| `gp_name` | ✅ | 执行事务合伙人名称（自然人姓名或公司全称） |
| `gp_delegate` | 条件必填 | 执行事务合伙人为公司时，填委派代表姓名 |

> 脚本自动另起一行输出：「执行事务合伙人：XXXX有限公司（委派代表：张三）。」

### 5. `type: "individual_business"` — 个体工商户

| 字段 | 必填 | 说明 |
|------|------|------|
| `has_trade_name` | ✅ | `true`=有字号，`false`=无字号 |
| `name` | ✅ | 有字号时填字号；无字号时填经营者姓名 |
| `address` | ✅ | 经营场所地址 |
| `phone` | 推荐 | 联系电话 |
| `operator_name` | 有字号时✅ | 经营者姓名（另起一行输出） |
| `operator_gender` | 推荐 | 经营者性别 |
| `operator_ethnicity` | 推荐 | 经营者民族 |
| `operator_birth_date` | 推荐 | 经营者出生日期 |
| `operator_address` | 推荐 | 经营者住所 |
| `id_number` | 推荐 | 经营者身份证号 |

### 6. `type: "minor"` — 未成年人

自然人字段 + 额外必填 `guardian` 对象：
```json
"guardian": {
  "name": "张大明",
  "relation": "之父",
  "id_number": "...",
  "address": "...",
  "phone": "..."
}
```

### 7. `type: "partnership_individual"` — 个人合伙

| 字段 | 必填 | 说明 |
|------|------|------|
| `partners` | ✅ | 自然人对象数组，每位合伙人同 `natural_person` 字段 |
| `trade_name` | ❌ | 字号（有字号时填写） |
| `business_address` | ❌ | 经营场所地址 |

## 四、claims 字段写作规范

每条 claim 是**完整一句**，自带序号和句末标点：

```json
"claims": [
  "1. 判令被告立即向原告支付货款人民币 500,000 元；",
  "2. 判令被告支付逾期付款利息（以 500,000 元为基数，自 2025 年 3 月 1 日起按全国银行间同业拆借中心公布的同期贷款市场报价利率（LPR）计算至实际清偿之日止）；",
  "3. 本案诉讼费、保全费由被告承担。"
]
```

具体撰写原则参见 `references/claims-drafting.md`。

## 五、facts_and_reasons 字段写作规范

- 使用 `\n\n`（双换行）分段，每段一个完整意思
- 不要在内部加 `1. 2. 3.` 编号（影响段落缩进）
- 关键事实用「（详见在案证据）」「有相关凭证为证」等引用，无需另列证据清单
- 写作方法论详见 `references/facts-reasoning.md`

## 六、最小可用 JSON 模板

```json
{
  "court": "XX市XX区人民法院",
  "plaintiffs": [
    {"type": "natural_person", "name": "原告姓名"}
  ],
  "defendants": [
    {"type": "natural_person", "name": "被告姓名"}
  ],
  "case_cause": "买卖合同纠纷",
  "claims": ["1. ……；", "2. ……。"],
  "facts_and_reasons": "第一段事实……\n\n第二段事实……\n\n法律分析……",
  "filing_date": "2026年5月5日"
}
```

但**强烈建议**填齐当事人六要素 / 法人四要素 + 法定代表人，否则起诉状不符合立案要求。

## 七、错误码与排查

| 退出码 | 含义 | 排查 |
|--------|------|------|
| 1 | JSON 解析失败或文件不存在 | 检查 JSON 语法、路径 |
| 2 | python-docx 未安装 | `pip install python-docx` |
| 3 | 必填字段缺失 / 列表为空 | 按 stderr 提示补齐 |
| 4 | docx 生成异常 | 检查特殊字符、字段类型是否为字符串 |

## 八、字体与字号（脚本固化，调用方无需关心）

脚本已固化下列排版规范，不接受外部参数覆盖：

| 元素 | 字体（含 fallback） | 字号 | 其他 |
|------|--------------------|------|------|
| 标题「民事起诉状」 | 微软雅黑 → 黑体 → SimHei → 宋体 | 三号（16pt） | 居中、加粗、单倍行距 |
| 段落标题（诉讼请求 / 事实和理由 / 附件） | 仿宋_GB2312 → 仿宋 → 宋体 | 四号（14pt） | 加粗、段首空两格、单倍行距 |
| 正文 | 仿宋_GB2312 → 仿宋 → 宋体 | 四号（14pt） | 首行缩进 2 字符、单倍行距、两端对齐 |
| 当事人块 | 同正文 | 四号 | 顶格 |
| 此致 / 法院 | 同正文 | 四号 | **此致段首空两格（首行缩进2字符）、法院名顶格（无缩进）** |
| 落款（原告 + 日期） | 同正文 | 四号 | 右对齐；自然人→「原告（签字）：姓名」；法人→「原告（盖章）：名称」+下一行「法定代表人（签字）：___」；非法人组织→「原告（盖章）：名称」+下一行「执行事务合伙人（签字）：___」；个体工商户→「原告（签字）：经营者姓名」 |

如本机字体环境异常导致 Word 显示为默认字体，请在 Word 内手动选中 → 应用相应字体即可（不影响段落结构与对齐）。

## 九、要素式脚本 `scripts/generate_element_complaint.py`

针对最高人民法院《关于印发部分案件民事起诉状、答辩状示范文本（试行）的通知》要素式示范文本，与传统脚本并存的独立生成器。**严格保留模板原有的字体、字号、表格、复选框样式**，仅按调用方指令进行内容填充，不做任何排版改写。

### 9.1 调用规则

```bash
python3 scripts/generate_element_complaint.py --input element_data.json --output /path/out.docx
python3 scripts/generate_element_complaint.py --input element_data.json --output-dir /tmp
# 调试：强制走通用要素式（即便案由有模板）
python3 scripts/generate_element_complaint.py --input element_data.json --output /tmp/out.docx --force-general
```

脚本自动按 `case_cause` 查找 `references/templates/element-based/要素式起诉状-{案由}.docx`：
- **命中模板** → 打开模板，按 `template_fill` 指令做文本/复选框替换，保留所有格式；
- **未命中** → 走通用要素式路径，文档开头自动加警示语「⚠ 本案由不在《通知》要素式示范文本覆盖范围……」。

### 9.2 顶层 JSON Schema

| 字段 | 必填 | 说明 |
|------|------|------|
| `court` | ✅ | 管辖法院全称 |
| `case_cause` | ✅ | 案由（用于模板路由 + 文件命名） |
| `plaintiffs` / `defendants` | ✅ | 同传统脚本「当事人对象」 |
| `third_parties` | ❌ | 同传统脚本 |
| `filing_date` | ✅ | 中文日期 |
| `elements` | ❌（通用路径必填） | 通用要素式骨架数据，详见 9.3 |
| `template_fill` | ❌（模板路径推荐） | 模板填充指令，详见 9.4 |
| `evidence_hint` | ❌ | 证据指引语（通用路径用） |
| `attachments` | ❌ | 附件清单 |

### 9.3 `elements`（通用路径数据）

```json
"elements": {
  "claim_elements": {
    "本金": "500000 元",
    "利息": "按 LPR 计算自 2025-01-01 至清偿之日止",
    "提前还款或解除合同": "解除合同"
  },
  "claim_total": "500000",
  "claim_basis": "合同约定（第 5 条违约责任）+ 法律规定（《民法典》第 670 条）",
  "fact_elements": {
    "合同签订情况": "2024 年 1 月 5 日……",
    "借款金额": "人民币 500000 元",
    "借款利率": "年化 6%"
  },
  "jurisdiction_clause": "合同第 12 条约定 XX 区人民法院管辖",
  "arbitration_clause": "无",
  "preservation": "拟申请财产保全",
  "service_address": "北京市朝阳区……",
  "electronic_service": "13800138000 / xxx@xx.com"

```

要素清单参见 `references/element-based-format.md` 第六节。

### 9.4 `template_fill`（模板填充指令）

仅在脚本路由到模板路径时生效。所有指令都是「针对模板原文本的查找替换」——模型负责理解模板结构（通过 `references/element-based-format.md` 描述）后构造精确指令。

```json
"template_fill": {
  "replacements": [
    {"find": "____①____", "replace": "张三", "once": false},
    {"find": "借款金额：______", "replace": "借款金额：人民币 500,000 元"},
    {"find": "（合同编号：______）", "replace": "（合同编号：JK-2024-001）"}
  ],
  "checkboxes": [
    {"anchor": "是否约定管辖", "select": "是"},
    {"anchor": "是否申请财产保全", "select": "否"}
  ],
  "appendices": [
    "本案另附补充说明：原告同意分期偿还。",
    "联系人：张三 13800138000"
  ]
}
```

字段说明：
- `replacements[].find` — 模板中要查找的原文字符串。**不存在则在 stderr 输出未匹配提示，不中断生成**；
- `replacements[].replace` — 替换文本；
- `replacements[].once` — 默认 `false`，即替换文档中该 `find` 的所有出现；`true` 时只替换第一处；
- `checkboxes[].anchor` — 复选框前后的锚定文本（如「是否约定管辖」）；
- `checkboxes[].select` — `"是"` 或 `"否"`，脚本会把对应的 `☐`/`□` 改为 `☑`；
- `appendices` — 文档末尾追加段落，每项一段。

### 9.5 错误码（要素式脚本专属）

| 退出码 | 含义 |
|--------|------|
| 1 | JSON 解析失败或文件不存在 |
| 2 | python-docx 未安装 |
| 3 | 必填字段缺失 |
| 4 | docx 生成异常 |
| 5 | 案由属《通知》11 类白名单，但模板文件缺失 |

### 9.6 命名规则

```
要素式民事起诉状-{原告简称}诉{被告简称}-{案由}-{YYYYMMDD}.docx
```

### 9.7 排版策略（与传统脚本的关键差异）

- **不固化字体字号**：模板路径下保留模板原排版；通用路径下使用 python-docx 默认样式；
- **不做段落缩进调整**：所有格式均来自模板；
- **不替换或破坏表格 / 复选框结构**：仅替换 run 中的文本字符。

## 十、结构化字段映射模式（新增，消除随机性）

> **设计目标**：模型无需猜测 `find` 字符串，只需按字段规范提供语义字段值，脚本自动完成模板内的精确填充。

### 10.1 使用方式

在 `template_fill` 中使用 `fields` 代替（或补充）`replacements`：

```json
"template_fill": {
  "fields": {
    "截止日期_年": "2026",
    "截止日期_月": "05",
    "截止日期_日": "18",
    "尚欠本金": "500,000.00元",
    "欠付利息": "12,500.00元",
    "利息计算方式": "按合同约定年利率6%计算",
    "是否支付至清偿日": "是",
    "贷款合同签订日期": "2024年1月5日",
    "贷款金额": "500,000.00元",
    "贷款期限": "2年",
    "贷款用途": "流动资金",
    "担保方式": "保证",
    "担保人": "李四",
    "逾期起始日": "2026年1月5日",
    "管辖约定": "合同约定朝阳区人民法院",
    "保全申请": "是",
    "送达地址": "北京市朝阳区建国路88号",
    "电子送达方式": "短信"
  },
  "checkboxes": [
    {"anchor": "是否请求支付至实际清偿之日止", "select": "是"},
    {"anchor": "是否接受电子送达", "select": "是"}
  ]
}
```

脚本内部维护「字段名 → 模板 find 字符串」映射表，自动将 `fields` 中的键值对转换为 `replacements` 数组后再执行替换。

### 10.2 各案由字段规范快查表

**金融借款合同纠纷** → `fields` 键名：
`截止日期_年` / `截止日期_月` / `截止日期_日` / `尚欠本金` / `欠利息` / `欠复利` / `欠罚息` / `利息计算方式` / `是否支付至清偿日` / `贷款合同签订日期` / `贷款金额` / `贷款期限` / `贷款用途` / `担保方式` / `担保人` / `逾期起始日` / `管辖约定` / `保全申请` / `送达地址` / `电子送达方式`

**民间借贷纠纷** → `fields` 键名：
`借款金额` / `借款日期` / `约定还款日` / `尚欠本金` / `利率约定` / `截止日期` / `欠付利息` / `利息计算方式` / `是否支付至清偿日` / `担保方式` / `担保人` / `借款用途` / `出借方式` / `管辖约定` / `保全申请`

**买卖合同纠纷** → `fields` 键名：

### 10.3 字段缺失处理规则

| 情形 | 脚本行为 |
|------|---------|
| `fields` 中某键无对应映射 | stderr 输出警告，跳过该字段，继续生成 |
| `fields` 中某键值为空字符串 | 以「（未提供）」填充，并在 stderr 输出提示 |
| `fields` 与 `replacements` 同时存在 | 先处理 `fields` 转换结果，再处理 `replacements`，后者可覆盖前者 |
