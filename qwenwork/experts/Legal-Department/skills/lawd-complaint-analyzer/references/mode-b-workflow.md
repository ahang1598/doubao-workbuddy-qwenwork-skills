## 模式B ｜ 争议焦点分析

> 原「律师争议焦点分析」全部工作流，内容未删减。以资深民商事诉讼律师的专业视角，专注案件争议焦点的精准识别与深度分析。

### B.1 执行顺序（模式B 独立调用，不得跳步）

模式B 独立调用时，**必须按以下顺序执行**。上一步未完成，禁止进入下一步。

| 步骤 | 名称 | 完成标志 |
|------|------|----------|
| **Step 0** | **版本确认（report_profile）** | 已从用户指令识别版本，或已向用户询问且得到回复/触发默认规则 |
| Step 1 | 材料收集与审阅 | 案卷材料齐备并开始深度审阅 |
| Step 2–4 | 焦点分析（Phase 1–4） | 按 `report_profile` 完成对应分析深度 |
| **Step 5** | **大纲确认** | 用户确认焦点体系图/清单（或触发默认继续） |

| Step 7 | 生成 Word | 调用 docx skill |

**Step 0 与 Step 5 是两个不同的检查点，不可合并、不可跳过 Step 0。**

> ⚠️ Step 0 仅适用于路由到**模式B** 的场景。模式A 不需要 `report_profile`；模式A + 模式B 连做时，在进入模式B 前完成 Step 0 版本锁定。

#### Step 0 强制首行动作（模式B 独立调用，不可跳过）

模式B 独立调用时，**首条回复的第一段**必须显式锁定版本，然后才能读材料或写分析。格式固定如下（按实际值替换 `{profile}` 与 `{说明}`）：

```
【版本锁定】report_profile={profile}
{说明}
```

| report_profile | 首条必写 `{说明}` |
|----------------|-------------------|
| `full` | 将按完整版 8 章生成，含攻防推演与类案法条引用 |
| `simplified` | 将按简易版 3 章叙述体生成，跳过 Phase 4 辩论推演，正文不展开类案/法条引用块 |
| `both` | 将分别生成完整版与简易版两份 Word |

**禁止**在未输出上述「版本锁定」声明前：读取案卷、列出争议焦点、展示体系图、调用检索技能、生成 Word/Markdown 报告。

#### Step 0：版本确认（report_profile）— 门禁规则

**触发时机**：模式B 独立调用时，**在读材料写分析结论之前**（Step 1 之前）必须完成。

**识别规则**（命中即确定，不再询问）：

| 用户表述 | report_profile |
|---------|----------------|
| 「完整版」「专业版」「深度分析」「攻防策略」「专项分析报告」 | `full` |
| 「简易版」「简要版」「精简」「快速梳理」「争点摘要」 | `simplified` |
| 「两个版本都要」「完整版和简易版」 | `both` |

**未明确时 — 首条回复必须询问版本**（可与材料清单并列，但不得写焦点分析结论）：

> 请确认报告版本：**1）完整版**（8 章，含攻防推演、类案法条引用）或 **2）简易版**（3 章叙述体争点梳理）？未指定时将默认按 **完整版** 执行。

**默认规则**（避免事后补救式询问）：

- 用户 **30 秒内未回复** → 锁定 `report_profile=full`，继续 Step 1，在报告开头标注「未指定版本，已按完整版生成」
- **禁止**在 Step 5 或 Step 6 才首次询问版本
- **禁止**使用「我的失误 / 现在补救 / 遗漏了确认环节」等话术回溯询问；若已误进入后续步骤，按已锁定的 `report_profile` 继续，勿重新打断用户

**自动化 / 评测约定**（prompt 含「凡需确认的按是处理」「勿等待用户输入」等）：

- 含「简易版」→ `simplified`
- 含「完整版和简易版」→ `both`
- 否则 → `full`，**不询问版本**，直接进入 Step 1

**上游透传**：被 `庭前准备整合助手（律师庭前准备）` 调用时，使用上游指定的 `report_profile`（默认 `full`），不询问。

#### 两版正确定义（禁止混淆）

### B.2 案件信息收集

> **前置条件**：模式B 独立调用时，须先完成 **Step 0 版本确认**，再进入本节。

在开始争议焦点分析前，必须收集完整的案卷材料。如用户未提供完整信息，应通过提问引导用户提供必要信息。

**必需材料**

1. **起诉状/仲裁申请书**：包含诉讼请求、事实与理由
2. **答辩状**：被告的答辩意见和抗辩理由
3. **证据材料**：双方提交的所有证据及证据清单
4. **代理词**：如有，提供双方代理意见
5. **相关法律文书**：如管辖权异议申请书、保全申请等

如用户无法提供完整材料，则通过针对性提问收集必要信息：争议金额、合同签订及履行情况、主要争议事实、对方主要抗辩理由、已有证据情况、案件特殊性说明。

> 材料**仅有起诉状**时，只要用户目标是归纳争点，即可启动模式B，并在报告中标明材料局限（如"截至分析时未取得答辩状，被告立场系基于现有材料推断"）。

**材料深度分析原则**

**强制要求：对用户提供的所有材料和信息，必须进行深度分析、充分捕捉、完整保留细节。**

- **逐页逐段审阅**：不得跳过或忽略任何材料内容，包括附件、备注、落款、日期等细节
- **关键数字复核**：所有金额、日期、期限、面积、数量等数字必须精确提取和交叉验证
- **矛盾点捕捉**：主动识别不同材料之间、同一材料前后、当事人陈述与证据之间的矛盾和不一致
- **隐含信息挖掘**：从材料字里行间挖掘隐含的事实信息（如合同条款的默示含义、通信记录的言外之意）
- **细节保留**：即使看似次要的细节（如证据的形成时间、签字人身份、证据载体形式），也必须保留并在分析中体现
- **信息溯源**：每一个提取的事实都必须标注其信息来源（证据编号+页码、当事人陈述、诉讼文书等）

### B.3 约束原则

#### 1. 证据锚定

所有事实引用必须标注证据编号及对应页码。禁止出现无证据支撑的事实陈述 — 无证据支撑的事实主张在法庭上不会被法官（仲裁案件为仲裁员）采信，反而暴露我方准备不足。

**简易版例外**：允许 inline 标注（如「见证据三」），不必单独建证据评估表，但关键事实仍须可追溯。

#### 2. 客观中立与全面披露

事实梳理必须忠实于用户提供的资料，不得主观臆断。必须全面披露对双方有利和不利的因素，对我方不利的事实必须如实呈现。

#### 2.5 禁止编造争议焦点

所有争议焦点必须基于用户提供的证据材料和法律规定推演得出，禁止凭空编造争议焦点。如用户提供的材料不足以支撑某个争议焦点的深度分析，必须在报告中标注"材料不足，分析受限"，并建议用户补充相关材料。

#### 3. 风险敏锐

必须主动识别并指出：相对方陈述之间的矛盾、陈述与证据的矛盾、证据之间的矛盾、法律观点的冲突。

**完整版**：独立成章（第四部分「矛盾点识别与风险提示」）。**简易版**：可在焦点叙述中 inline 点出，不必独立成章。

#### 4. 专业规范

使用规范的法言法语。所有引用的法律法规必须标注相应的年份版本号（如《公司法》（2023年修订）、《民法典》（2020年））。引用案例时必须提供：案件名称、案号、审理法院/仲裁机构、裁判人员、裁判日期、裁判要旨摘录。

**简易版**：正文不展开类案/法条完整引用块；内部分析仍应遵循专业规范。

#### 5. 检索规范

**完整版（report_profile = full 或 both 的 full 部分）** — 必须明确调用指定 skill 获取案例和法规信息：

- 类案检索：调用 `类案检索（律师类案检索与报告）` skill
- 法规检索：调用 `法规检索（律师法规检索）` skill

**简易版（report_profile = simplified）** — 检索 skill **可选**（用于内部分析校验）；**即使已调用检索，也不得**在报告正文中写入「专业检索指引」章节或类案/法条完整引用块。检索结论仅可转化为 inline 一句法律依据，不得展开案号、裁判要旨摘录块。

严禁编造案例或法条 — 虚构的法律依据会导致律师在法庭上被对方或法官（仲裁案件为仲裁员）质疑，严重损害当事人利益和律师执业信誉。

#### 5.5 检索结果不足时的处理

若 `类案检索（律师类案检索与报告）` 和 `法规检索（律师法规检索）` 均返回空结果或结果明显不足：

- 在报告中明确注明："类案检索和法规检索结果不足，以下分析仅基于用户提供的案件材料，分析深度受限"
- 不强行生成基于检索结果的结论，但仍可基于用户提供的材料进行基础争议焦点分析
- 建议用户调整检索关键词后重试，或提供更多案件信息以改善检索效果

#### 6. 被整合调用模式

当由 `庭前准备整合助手（律师庭前准备）` 整合调用（作为「争议焦点分析」子模块）时：

- **跳过检索**：若上游已提供检索结果，直接使用，不再调用 `类案检索（律师类案检索与报告）` 和 `法规检索（律师法规检索）`
- **跳过 Word 输出**：仅输出结构化分析内容，不调用 docx skill 生成独立 Word 文档
- **跳过信息收集**：使用上游已收集的案件材料，不再重复向用户询问
- **report_profile**：默认 `full`；上游指定简易版时使用 `simplified`

模式B 独立调用时，上述步骤照常执行。

被整合调用时，输出长度控制（**≠ 简易版**）：

- **full**：核心焦点（★★★★★）完整展开，重要焦点（★★★★☆）简要展开，其余焦点仅列要点
- **simplified**（上游指定）：全部识别出的焦点均叙述展开（150–400 字/焦点），仍跳过 Word

#### 6.1 简易版额外约束

- 叙述性 prose，禁止大段表格、禁止「焦点体系图」树状结构
- 每个焦点 150–400 字，全文建议 1500–3000 字
- 仍须证据锚定（inline 即可）
- 禁止编造焦点；材料不足时 inline 标注
- 文风参考：[examples/dispute-focus-simplified-sample.md](examples/dispute-focus-simplified-sample.md)

**正文禁止出现的章节/标题**（出现任一项即视为误用完整版模板，须重写）：

- 争议焦点体系图
- 各争议焦点深度分析（独立成章）
- 矛盾点识别与风险提示（独立成章）
- 焦点攻防路线图
- 法庭辩论推演与应对
- 专业检索指引
- 风险提示与应对预案
- 结语（完整版第九部分）

**正文禁止出现的符号/格式**：

- `★`、`☆` 及「决定性/重要/一般/次要焦点」星级标注
- 「立论→反驳→回应→最终陈述」等多轮辩论模拟结构
- 类案/法条完整引用块（案号 + 裁判要旨摘录段落）

#### 7. 输出质量自检

**完整版（full）** 生成报告前自检：

- 所有事实是否标注了证据索引来源
- 所有引用的法律法规是否经过检索验证且现行有效
- 每个争议焦点是否都完成了双方立场对比和攻防策略建议
- 核心焦点是否都完成了法庭辩论推演
- 法庭辩论话术是否具体到可直接使用
- 矛盾点是否全部识别并标注利用策略

**简易版（simplified）** 生成报告前自检（**任一项不通过则不得调用 docx**）：

- 结构是否为三章（基本情况 / 核心焦点 / 简要结论）
- 争议焦点是否不少于 2 个，且按法律逻辑与重要性排序
- 每个焦点是否覆盖双方主张（叙述性 prose，150–400 字/焦点，非列表式攻防）
- 关键事实是否有 inline 证据来源
- 简要结论是否有一句话点明胜负要点（「本案关键在于：……」）
- 全文是否未包含 §6.1 禁止章节、辩论推演、类案法条完整引用块、★/☆ 符号
- 文件名是否为 `《XX案-争议焦点分析报告（简易版）》.docx`（**不得**含「专项分析报告」）

### B.4 争议焦点分析工作流程

> Phase 1–3 为共享分析管道，与 report_profile 无关。

#### 第一阶段：争议焦点识别

**1.0 案由匹配法（前置步骤）**

首先识别案由类型，调用对应的典型争议焦点知识库：

**操作步骤**：

1. 根据诉讼请求和案件事实确定案由
2. 查阅知识库：`references/typical-disputes-by-case-type.md`
3. 找到该案由对应的章节，获取典型争议焦点清单
4. 对照典型焦点清单与本案具体情况，标注本案涉及的典型焦点（✓）、不涉及的典型焦点（✗）、本案特有的非典型焦点

**1.1 请求权基础分析法（核心方法）**

识别请求权基础，检查构成要件，发现要件争议点：

**操作步骤**：

1. 确定原告主张的请求权基础
2. 查阅知识库：`references/legal-elements-checklist.md`
3. 找到该请求权对应的构成要件清单
4. 逐项核对本案是否满足各项要件事实：已满足的要件（✓）、未满足或有争议的要件（✗）→ **这就是争议焦点**
5. 查看该请求权的举证责任分配和常见抗辩事由

详细示例参见 [dispute-focus-methodology-examples.md](dispute-focus-methodology-examples.md)。

> **要件清单唯一性规则（防两套要件打架）**：`references/legal-elements-checklist.md`（16 类请求权，含举证责任分配与争议要件详解）与 `references/case-dimensions-<案由>.md`（11 种案由，含常见抗辩与风险权重）存在部分重叠。
> - 模式B 单独执行 → 以 `legal-elements-checklist.md` 为要件权威源。
> - 模式A 单独执行 → 以 `case-dimensions-<案由>.md` 为要件权威源。
> - 模式A + 模式B 连做 → **以模式A 已确立的 `case-dimensions` 要件编号为唯一主干**，`legal-elements-checklist.md` 仅用于补充举证责任分配与争议要件详解；**禁止**在同一交付中并列两套要件编号（否则门禁脚本的「要件↔争点映射」校验会失败）。

**1.2 证据审查法**

从证据材料中发现争议点和薄弱环节：

**操作步骤**：

1. 查阅知识库：`references/evidence-checklist-by-focus.md`
2. 根据已识别的争议焦点，查找对应的证据清单
3. 逐项核对本案证据：核心证据是否齐备？证明力如何？证据是否存在瑕疵或矛盾？
4. 识别证据缺口

> 连做场景下，可直接复用模式A Sub-phase 3B 的三性评估与证据链缺口图，不重复评估。

**1.3 诉请拆解法**

将原告诉讼请求逐项拆解，识别每个请求对应的法律要件：

- 请求权基础是什么？
- 需要证明哪些要件事实？
- 每个要件是否存在争议？

**1.4 抗辩对应法**

将被告抗辩与原告主张逐一对照：

- 哪些抗辩是对事实的否认？
- 哪些抗辩是法律上的反驳？
- 哪些抗辩提出了新的事实？

**1.5 证据冲突法**

从证据材料中发现争议点：

- 双方证据是否存在矛盾？
- 同一方证据是否存在不一致？
- 证据与陈述是否吻合？

**1.6 法律适用分歧法**

识别法律理解上的差异：

- 对合同条款理解的分歧
- 对法律条文适用的分歧
- 对举证责任分配的分歧

#### 第二阶段：争议焦点列举

**按照法律逻辑层级排序**：

**第一层：前置性/程序性焦点（优先审查）**
诉讼时效、管辖权争议、主体资格、证据资格等问题。

**第二层：权利基础焦点**
合同效力、物权归属、侵权构成要件、股东资格等问题。

**第三层：履行/违约焦点**
合同义务是否履行、标的物是否交付、质量是否合格、价款是否支付等。

**第四层：责任范围焦点**
违约责任如何承担、损失如何计算、违约金是否过高等。

**第五层：抗辩事由焦点**
是否存在免责事由、过错相抵、同时履行抗辩权等。

> **编号纪律（门禁校验项）**：焦点一律用「争议焦点一/二/三……」连续编号，从一开始，不得断号、不得重复、不得跳号；焦点合并或删除后必须重新连续编号。

#### 第三阶段：争议焦点优先级排序

按照对案件结果的影响程度标注优先级。**★ 符号仅允许出现在内部分析笔记中，禁止写入 Step 5 大纲、Markdown 草稿、Word 正文。**

内部分析标注（**不得原样复制到报告**）：

- **决定性焦点 ★★★★★**：直接决定胜败，必须全力攻防（如合同效力、诉讼时效届满）
- **重要焦点 ★★★★☆**：影响责任范围或金额，需重点准备（如违约金是否过高、损失金额计算）
- **一般焦点 ★★★☆☆**：对结果有一定影响，适度关注
- **次要焦点 ★★☆☆☆**：对结果影响较小，简要准备

综合评估标准：法律逻辑位阶、对案件结果的决定性程度、证据充分性、法官（仲裁案件为仲裁员）关注度。

**写入报告前**：若 `report_profile = simplified`，删除全部 ★/☆ 符号，仅保留按上述优先级排序后的焦点顺序；焦点标题用「争议焦点一：{名称}」，不加星级前缀。

#### 第三点五阶段：要件 ↔ 争点映射表（门禁前置产物）

在进入 Phase 4 / 输出渲染前，必须产出**要件 ↔ 争点映射表**，确保 Phase 1.1 拆出的每一个法律要件都有争点归属，无悬空要件：

```markdown
## 要件—争点映射表

| 法律要件 | 是否有争议 | 对应争议焦点 |
|---|---|---|
| 要件1 合同有效成立 | 无争议 | 争议焦点一 |
| 要件2 出卖人已交付标的物 | 有争议 | 争议焦点二 |
| 要件3 标的物符合约定 | 有争议 | 争议焦点二、争议焦点三 |
```

规则：

- 每个要件行的「对应争议焦点」不得为空、不得写"无"/"—"/"未归属"；无争议的要件也须写明由哪个焦点覆盖（或归入「无争议要件」焦点行并说明）
- 引用的焦点编号必须真实存在于第二阶段的焦点清单中
- 该表在**完整版**中并入第二章（争议焦点体系图）之后；在**简易版**中作为内部分析产物用于门禁校验，正文不展示表格（避免违反 §6.1 禁表格约束）
- 本表是门禁脚本 `validate_analysis_report.py` 的校验对象，缺失即拦截

#### 第四阶段：法庭辩论推演与应对

**仅 `report_profile = full`（或 `both` 的完整版部分）执行本阶段。**

`report_profile = simplified` 时**跳过本阶段**，直接进入输出渲染。

围绕每个核心争议焦点（★★★★★ 和 ★★★★☆），按 [辩论推演框架](dispute-focus-debate-simulation-framework.md) 进行多轮辩论推演（立论→对方反驳预判→我方回应→最终陈述），并预判法官（仲裁案件为仲裁员）庭审关注点和突发情况应对。

### B.5 异常处理

**材料无法解析**

若用户提供的材料无法解析或格式错误：

- 向用户说明："提供的材料无法解析，请检查文件格式或提供清晰的文本内容"
- 引导用户提供可用的材料格式

**信息极度不完整**

若用户提供的信息不足以完成基本的争议焦点分析：

- 向用户说明："当前信息不足以完成争议焦点分析，请补充以下材料：[缺失材料列表]"
- 明确告知缺少哪些关键材料（如起诉状、答辩状、证据材料等）
- 等待用户补充材料后再继续

**检索服务不可用**

若 `类案检索（律师类案检索与报告）` 或 `法规检索（律师法规检索）` 调用失败：

- 向用户说明："检索服务暂时不可用，请稍后重试"
- 记录错误信息，建议用户联系技术支持
- 可基于用户提供的材料进行基础争议焦点分析，但在报告中明确标注"检索服务不可用，分析深度受限"
- **不得**因检索失败而罗列未经核验的法条或虚构案例（见 §四）

**用户不回复确认**

在以下确认步骤中，若用户在合理时间内（建议等待 30 秒）不回复：

- **Step 0 版本确认** → 锁定 `report_profile=full`，继续 Step 1；报告开头标注「未指定版本，已按完整版生成」
- 材料收集确认 → 假设用户确认当前材料，继续执行
- **Step 5 大纲确认**（争议焦点大纲 / 简易版焦点清单） → 自动使用当前大纲，继续生成 Word
- 在报告中标注："用户未确认，使用默认选项"

**禁止**因 Step 0 未执行而在 Step 5/6 回溯询问版本。

**信息矛盾**

若用户提供的材料之间存在明显矛盾：

- 向用户指出矛盾点，请用户确认或澄清
- 等待用户回复后再继续
- 若用户不回复，在报告中如实标注双方信息，不自行判断

**docx + 钉钉双重失败**

若 `docx` skill 和 `dws doc create` CLI 均失败：

- 向用户说明："文档生成失败，请检查网络连接或联系技术支持"
- 提供争议焦点分析内容的纯文本版本作为临时方案
- 记录错误日志，便于问题排查

### B.6 输出流程

#### Step 5：大纲确认（模式B 独立调用时必须执行）

> 前提：`report_profile` 已在 **Step 0** 锁定。本步**只确认焦点清单/体系图**，不再询问完整版还是简易版。

**完整版（full）** — 在调用 `docx` skill 之前，展示争议焦点体系图和报告大纲（含优先级 ★），等待用户确认。话术示例：

> "以下是本案争议焦点分析大纲（完整版），请确认后我将生成 Word 文档：\n[争议焦点体系图和大纲]"

**简易版（simplified）** — 展示焦点清单（无体系图、无 ★），等待用户确认。话术示例：

> "以下是本案争议焦点清单（简易版），请确认后我将生成 Word 文档：\n[焦点一、焦点二、……]"

**双版本（both）** — 可一次展示两版大纲，或先完整版后简易版依次确认。

#### 禁止行为（反模式）

| 反模式 | 正确做法 |
|--------|----------|
| 跳过 Step 0，直接读材料写分析 | 首条回复输出「【版本锁定】report_profile=…」后再读材料 |
| 用户说「简易版」仍走完整版 8/9 章 | 锁定 `simplified`，只读 `dispute-focus-output-format-template-simplified.md`，跳过 Phase 4 |
| 分析完成后才问「完整版还是简易版」 | 版本在 Step 0 锁定，Step 5 只确认大纲 |
| 把简易版理解为「只写高优先级焦点」 | 简易版 = 3 章叙述体，**全部焦点**均展开 |
| 把 Phase 3 内部分析（含 ★）直接粘贴进报告 | ★ 仅内部分析；simplified 输出前必须删除 |
| 调用检索 skill 后在简易版写「专业检索指引」 | simplified 正文不展开检索结果，最多 inline 一句法条名 |
| 简易版用「专项分析报告」文件名 | 必须用 `…分析报告（简易版）》.docx` |
| 「我的失误，现在补救请您选择版本」 | 按已锁定版本继续；若 Step 0 未执行则默认 `full` 并标注 |
| Step 0 与 Step 5 合并为一次确认 | 分两次：先版本，后大纲 |
| 用模式A 的《起诉状风险分析报告》模板渲染争议焦点报告 | 两模式模板互不通用，按 Step 0 锁定的模板渲染 |

#### Step 6：渲染前硬校验（模式B 独立调用，调用 docx 之前）

按已锁定的 `report_profile` 执行对应校验；**不通过则修正内容后重检，禁止带错交付**。

**`simplified` 必过项**：

1. 一级章节仅 3 个：案件基本情况 / 本案核心争议焦点 / 简要结论
2. 全文检索无 `★`、`☆`
3. 全文无「法庭辩论推演」「专业检索指引」「焦点攻防路线图」「争议焦点体系图」等 §6.1 禁止标题
4. 每个焦点为 prose 段落，非「被告抗辩：… / 我方应对：…」分栏列表
5. 文件名含「（简易版）」且不含「专项分析报告」

**`full` 必过项**：

1. 含 Phase 4 辩论推演章节
2. 已调用检索 skill 且类案/法条写入「专业检索指引」
3. 文件名含「专项分析报告」

**`both` 必过项**：上述两份文件分别通过各自校验后，再分别调用 docx。

**两版共同必过项**：`scripts/validate_analysis_report.py --mode b` 通过（争点编号连续无重复、要件↔争点映射完整、法条引用格式合规），见 §五。

本模式生成的争议焦点分析报告，必须以 **Word 文档(.docx 格式)** 输出（被整合调用时除外）。

#### 报告结构概览

**完整版（full）** — 详见 [dispute-focus-output-format-template.md](dispute-focus-output-format-template.md)：

1. 案件基本信息
2. 争议焦点体系图（其后接「要件—争点映射表」）
3. 各争议焦点深度分析
4. 矛盾点识别与风险提示
5. 焦点攻防路线图
6. 法庭辩论推演与应对
7. 专业检索指引
8. 风险提示与应对预案

**简易版（simplified）** — 详见 [dispute-focus-output-format-template-simplified.md](dispute-focus-output-format-template-simplified.md)：

1. 案件基本情况
2. 本案核心争议焦点
3. 简要结论

#### Word 文档格式规范

**必须调用 docx skill 生成 Word 文档**，格式规范详见 [docx-format-standard.md](docx-format-standard.md)。
