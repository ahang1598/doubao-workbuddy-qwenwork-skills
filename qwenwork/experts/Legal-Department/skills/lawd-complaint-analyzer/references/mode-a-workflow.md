## 模式A ｜ 起诉状风险分析

> 原「起诉状深度解析」全部工作流，内容未删减。

### A.0 重要提示与核心原则

起诉状是律师了解对方攻击路径的第一手材料。本模式不止做结构化提取，而是从被告视角出发，对每项诉请进行风险评估、对证据进行脆弱性分析、并生成可操作的防御行动清单。

核心原则：

1. **解析分析，不生成文书** — 本模式输出分析报告，不生成答辩状或其他法律文书
2. **被告视角** — 所有分析从被告防御角度出发
3. **反幻觉** — 不编造法条、案号、证据评估；起诉状未提及的信息标注"起诉状未载明"
4. **概率判断** — 风险评估是基于起诉状文本的主观概率判断，不是案件结果预测
5. **逐项覆盖** — 原告每项诉请必须逐一分析，不遗漏

### A.1 适用场景

当律师收到民事起诉状，需要快速分析时使用：

- 被告方律师收到起诉状 → 快速拆解诉请、评估风险、制定防御方向
- 作为 `答辩状一键起草`（答辩状起草）的前置步骤（先解析、再答辩）
- 接收上游 `案情法律分析报告` 的结果作为增强输入
- 作为本技能**模式B** 的前置步骤（先评估诉请风险，再归纳争点，见 §2.2）

### A.3 处理流程

#### Phase A1：文书识别与信息提取

**目标**：从起诉状中提取全部结构化数据。

| 步骤 | 动作 | 降级处理 |
|------|------|----------|
| 1.1 | 检测输入类型（文本/图片/文件），如需则进行 OCR 识别 | OCR 质量差时请求用户提供文本版 |
| 1.2 | 验证文书类型确为民事起诉状（非判决书、裁定书、上诉状等） | 非起诉状则提示并引导至对应技能 |
| 1.3 | 提取基础信息：原告、被告、第三人、案号、案由、管辖法院、诉讼代理人 | 缺失字段标注"起诉状未载明" |
| 1.4 | 逐项提取诉讼请求，每项记录：编号、请求类型（给付/确认/形成）、具体内容、金额/数量、引用的法律依据 | — |
| 1.5 | 提取事实与理由部分，构建关键事件时间线 | — |
| 1.6 | 提取证据清单（如起诉状附有证据目录），记录：编号、名称、类型、证明目的 | 无证据清单标注"证据清单未附" |

#### Phase A2：案由路由与维度加载

**目标**：确定案由类型，加载对应的分析框架。

| 步骤 | 动作 | 降级处理 |
|------|------|----------|
| 2.1 | 从案由字段或案情描述中识别案由（关键词 + 语义匹配） | 无法识别时列出 11 种案由供律师选择 |
| 2.2 | 加载对应的 `references/case-dimensions-<type>.md`，获取：(a) 原告需证明的法律要件清单 (b) 该案由常见抗辩策略 (c) 关键法条索引 (d) 风险权重调整参数 | — |
| 2.3 | 案由不在 11 种之内时，使用通用民事分析框架，在输出中标注"本案由暂无专用分析维度，以下分析基于通用民事框架，置信度降低"；可查阅 [legal-elements-checklist.md](legal-elements-checklist.md)（16 类请求权要件清单）补充要件 | — |

#### Phase A3：风险评估与证据分析

**目标**：对每项诉请评估风险等级，对证据进行脆弱性分析。

**Sub-phase 3A：逐项诉请风险评估**

对每项诉讼请求，按 [风险评分方法论](risk-scoring.md) 执行：

| 步骤 | 动作 | 输出 |
|------|------|------|
| 3A.1 | 识别原告需证明的法律要件（从案由维度文件加载） | 要件清单 |
| 3A.2 | 评估事实主张对各要件的覆盖程度 | 要件覆盖图 |
| 3A.3 | 评估法律依据强度（法条是否直接适用、有无争议） | 法律依据评分 |
| 3A.4 | 评估证据支撑预估（基于证据清单或合理推断） | 证据评分 |
| 3A.5 | 评估金额/标的合理性（计算依据是否充分） | 金额评分 |
| 3A.6 | 参考司法实践倾向（同类案件裁判趋势） | 实践评分 |
| 3A.7 | 计算五维度加权综合分值 → 映射风险等级 | 🔴高危/🟠中高/🟡中等/🔵中低/🟢低危 |
| 3A.8 | 识别该诉请的推荐抗辩方向（从案由维度文件匹配） | 抗辩策略 |

**风险等级映射**（加权总分 5.0-25.0）：

- 20.0-25.0 → 🔴高危：诉请很可能被支持，需重点防御
- 15.0-19.9 → 🟠中高：有较大支持可能，被告需有力抗辩
- 10.0-14.9 → 🟡中等：胜败取决于举证和庭审表现
- 6.0-9.9 → 🔵中低：诉请有明显薄弱环节
- 5.0-5.9 → 🟢低危：诉请缺乏充分支撑

每项评分须附**置信度**（高/中/低），取决于信息完整性：

- 高：起诉状完整、有证据清单、法律依据明确
- 中：起诉状完整但无证据清单，或案由罕见
- 低：起诉状信息残缺或法律适用存在重大争议

**Sub-phase 3B：证据脆弱性分析**

仅当起诉状附有证据清单时执行，否则标注"证据清单未附，以下分析基于起诉状事实主张推断"。

按 [证据脆弱性分析框架](evidence-vulnerability.md) 执行：

| 步骤 | 动作 | 输出 |
|------|------|------|
| 3B.1 | 对每项证据评估三性（真实性/合法性/关联性）→ 强/中/弱 | 三性评估表 |
| 3B.2 | 四关筛查（形式→合法性→关联性→真实性），标记未过关的证据 | 攻击点清单 |
| 3B.3 | 证据链完整性评估：哪些法律要件有直接证据？哪些仅有间接证据？哪些完全无证据支撑？ | 证据链缺口图 |
| 3B.4 | 按证据类型（书证/电子数据/证人证言/鉴定意见/当事人陈述）适用差异化评估规则 | — |
| 3B.5 | 对每个薄弱点生成具体质证策略 | 质证建议 |

> 需要按争点维度核对证据是否齐备时，可查阅 [evidence-checklist-by-focus.md](evidence-checklist-by-focus.md)（分焦点证据清单 + 司法实践认定规则）。

#### Phase A4：防御策略生成

**目标**：将风险评估和证据分析综合为可操作的防御行动方案。

| 步骤 | 动作 | 输出 |
|------|------|------|
| 4.1 | 识别程序性抗辩机会：管辖异议、诉讼时效、主体适格、前置程序（如劳动仲裁） | 程序抗辩选项 |
| 4.2 | 为每项诉请匹配实体抗辩策略（从案由维度文件的常见抗辩中匹配），按强度排序 | 实体抗辩矩阵 |
| 4.3 | 生成被告需收集的证据清单，按优先级（P0/P1/P2）排序 | 证据收集清单 |
| 4.4 | 计算关键时限：答辩期（15日/涉外30日）、管辖异议期、举证期限 | 时限表 |
| 4.5 | 评估反诉可能性和价值 | 反诉建议 |
| 4.6 | 整合为按 [防御行动清单模板](defense-checklist-template.md) 格式的行动方案 | 防御行动清单 |

#### Phase A5：输出渲染与合规自检

**目标**：按模板格式输出分析报告，执行质量检查。

| 步骤 | 动作 |
|------|------|
| 5.1 | 按 [律师版输出模板](output-template.md) 渲染完整分析报告（完整示例见 [example.md](example.md)） |
| 5.2 | 执行质量检查清单（见 A.5）：**必须逐项显式输出 8 项检查结果（每项 ✅/❌ 及说明），未输出不得进入 5.3 门禁** |
| 5.3 | **运行门禁脚本 `scripts/validate_analysis_report.py --mode a`（见 §五），未通过禁止交付** |
| 5.4 | 根据分析结果生成下游串联建议 |
| 5.5 | 附加法律合规声明 |

### A.4 反幻觉保障措施

| 编号 | 规则 | 处理方式 |
|------|------|----------|
| AH-1 | 引用溯源 | 分析中引用的每个事实须标注 `[起诉状第X段]`，可追溯。**扫描件/图片 PDF 无段落编号时**：先将起诉状内容按逻辑段落划分并编号（第1段=当事人信息，第2段=诉讼请求，第3段起=事实与理由各节），再按此编号引用，不得用物理页码替代 |
| AH-2 | 缺失标注 | 起诉状未包含的信息标注"起诉状未载明"或"待补充"，不推断填充 |
| AH-3 | 法条引用 | 法条须精确到条款项（《法律名称》第X条第X款）；不确定时标注"相关法律规定（待律师核实）" |
| AH-4 | 风险分值 | 不得无依据地给出极端评分（5分满分或1分）；极端评分须附具体理由 |
| AH-5 | 证据置信度 | 无证据清单时，证据相关分析须标注"基于起诉状文本推断，置信度降低" |
| AH-6 | 禁止预测 | 不使用"被告必败""原告必赢"等表述；用条件句："如原告能充分举证……则该项诉请被支持的可能性较高" |
| AH-7 | 司法实践 | 参考司法实践倾向时不编造案例；如无检索结果支撑，标注"基于一般裁判经验" |

### A.5 质量标准

**交付前必须逐项显式输出以下 8 项检查结果（✅ 通过 / ❌ 不通过及修正说明），仅口头声明"全部通过"视为未执行。**

| 检查项 | 要求 | 不通过处理 |
|--------|------|----------|
| 诉请完整性 | 原告全部诉请逐项分析，无遗漏 | 补充遗漏项 |
| 风险评估覆盖 | 每项诉请有五维度评分和综合风险等级 | 补充缺失评分 |
| 证据分析覆盖 | 每项证据有三性评估（当有证据清单时） | 补充缺失评估 |
| 法条准确性 | 引用法条编号和内容正确，不编造；格式为《法律名称》第X条 | 标注"待律师核实" |
| 防御清单可操作性 | 每项行动有具体内容+时限建议 | 补充具体信息 |
| 引用溯源 | 事实引用有起诉状段落标记 | 补充引用标记 |
| 合规声明 | 输出包含法律合规声明 | 添加声明 |
| 门禁 | `validate_analysis_report.py --mode a` 通过 | 修正后重跑，未通过禁止交付 |

### A.6 上下游串联

**上游（输入增强）**

| 上游 | 提供什么 | 模式A 如何使用 |
|-------|---------|---------------------------|
| `案情法律分析报告` | 类案检索结果、深度法律分析 | 增强 Phase A3 Sub-phase 3A 的"司法实践倾向"评估维度 |

**识别规则**：当用户输入中包含 `案情法律分析报告` 的结构化输出格式（如类案分析表格、法律适用分析），自动识别并复用其分析结果。

**下游推荐（输出引导）**

在分析报告的"后续建议"中，根据分析结果推荐后续可用功能：

| 场景 | 推荐 |
|------|------|
| 整体风险≥中高 | "建议尽快起草答辩状文书，将本次分析中的逐项抗辩方向转化为正式法律文书" |
| 证据缺口≥2项 | "建议对被告方证据进行系统化梳理，建立完整的证据-主张对应关系" |
| 存在复杂多点抗辩 | "建议对核心抗辩观点逐一构建完整论证链条（法条-事实-结论）" |
| 多项高风险诉请 | "建议对各项诉请风险进行优先级排序，合理分配防御资源" |
| 需要庭审层面的争点体系与攻防路线 | "建议继续进行争议焦点分析（本技能**模式B**），把风险敞口转化为争点体系与攻防路线" |
| 需要深入案件研究 | "建议生成完整法律分析报告，结合类案检索深入研判" |

**注意**：推荐外部技能时使用功能描述而非硬编码技能名，避免用户未安装时产生困惑；推荐本技能模式B 时可直接说明"继续做争议焦点分析"。

**下游数据衔接**

| 下游 | 模式A 提供的数据 | 衔接方式 |
|---|---|---|
| 本技能**模式B** | 诉请清单 + 要件清单及覆盖状况 + 证据脆弱性结论 + 程序抗辩机会 | 见 §2.2；模式B 跳过 Phase 1.1/1.2 的重复拆解 |
| `答辩状一键起草` | 诉请清单 + 逐项态度 + 抗辩方向 + 证据缺口 | 该技能检测到 `=== 起诉状深度解析报告 ===` 格式时，跳过其争点分析阶段，直接使用本报告结果 |
| `综合证据策略 模式C` | 原告证据清单 + 脆弱性分析 + 被告需准备证据 | 提供证据-要件映射基础 |
| `论证逻辑梳理` | 逐项抗辩方向 + 法律依据 + 可争议事实 | 提供论证目标结论和法律基础 |
| `风险评级排序` | 逐项风险分值 + 概率/影响评估 + 时限 | 直接对接风险排序输入格式 |

### A.7 模式A 系统提示语

```
你是一个面向中国执业律师的民事起诉状深度解析助手，支持 11 种高频民事案由。
你的任务是从被告视角出发，对起诉状进行结构化提取、逐项风险评估、证据脆弱性分析和防御策略生成。

你必须始终遵守以下规则：

【分析规则】
1. 对原告每项诉讼请求逐一分析，不遗漏任何一项
2. 每项诉请按五维度评分：法律依据强度、事实主张完整性、证据支撑预估、金额合理性、司法实践倾向
3. 每项评分附置信度（高/中/低），不做无依据的极端评分
4. 证据分析按三性（真实性/合法性/关联性）和四关筛查（形式→合法性→关联性→真实性）执行
5. 防御策略区分程序性抗辩和实体抗辩，按强度排序

【内容规则】
6. 不编造法条、不伪造证据评估、不对无依据事实作确定性判断
7. 法条引用精确到条款项，格式为：《法律名称》第X条第X款
8. 起诉状未包含的信息标注"起诉状未载明"或"待补充"，不推断填充
9. 分析中引用的每个事实须标注起诉状段落来源
10. 禁止预测案件结果，使用条件表述

【输出规则】
11. 按律师版输出模板（references/output-template.md）格式输出
12. 输出以"=== 起诉状深度解析报告 ==="开头，便于下游自动识别
13. 必须包含：基本信息、风险总表、逐项分析、事实分析、证据分析（如有）、防御清单、后续建议
14. 输出末尾附法律合规声明
15. 交付前必须运行 scripts/validate_analysis_report.py --mode a，未通过不得交付

【交互规则】
16. 当用户未提供起诉状全文时，请求用户提供
17. 当无法识别案由时，列出 11 种案由供选择
18. 如识别到用户输入中包含上游技能的结构化输出，自动复用，不重复分析

【串联规则】
19. 在"后续建议"中根据分析结果推荐后续可用功能
20. 推荐外部技能时使用功能描述，不硬编码技能名；如用户还需争点与攻防，提示可继续走本技能模式B
```
