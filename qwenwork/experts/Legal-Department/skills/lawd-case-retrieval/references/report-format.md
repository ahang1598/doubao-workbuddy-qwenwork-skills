# 类案检索报告格式规范

## 使用范围

本文件定义 `律师类案检索与报告` **模式C（正式类案检索报告）**的五部分结构和写作边界，原属 `lawd-case-retrieval-report`（旧名「类案检索报告」）。数据字段与缺失值规则见 `report-case-input-contract.md`，生成前后的检查见 `report-validation-rules.md`。

## 标题页

- 标题：`类案检索报告` 或用户指定的正式标题。
- 可选副标题：案件或专项名称。
- 制作主体、制作日期等信息仅按输入数据填写；缺失时写“未提供”。

## 一、检索说明

按实际输入列明：

- 制作主体；
- 制作日期；
- 数据来源或检索平台；
- 检索方法；
- 检索查询；
- 用户明确指定的时间、地域或其他约束。

用户未指定时间或地域时，写“未设定特定时间限制”或“未设定特定地域限制”，不得添加默认范围。

## 二、检索目标

- 用编号列出本次需要回答的法律问题。
- 多个问题按用户任务顺序排列。
- 不把检索关键词直接冒充法律问题。
- 输入未提供目标时，写“未提供明确检索目标”，不要自行虚构案件争点。

## 三、检索结果

- 结论仅限当前纳入案例能够支持的内容。
- 首句使用“基于本次纳入的 N 个案例”限定样本范围。
- 结论与案例裁判内容存在分歧时，分别呈现，不强行归纳单一趋势。
- 没有充分数据时写明“现有样本不足以形成稳定结论”。
- 不使用“司法实践一致认为”“全国法院普遍”等超出样本的表述。

## 四、检索内容

每个案例独立成节，顺序与输入 JSON 一致。

### 案例标题

格式：`序号. 案件名称【案号：案号】`。

案号缺失时写“案号：检索结果未提供”。

### 基本信息

使用两列表格列示：

- 审理法院；
- 裁判日期；
- 审判人员；
- 数据来源；
- 原始记录定位。

来源缺失时统一写“检索结果未提供”，不得推断法院全称、日期或审判人员。

### 基本案情

- 基于来源数据压缩与争点无关的事实。
- 保持主体、行为、时间和法律关系不变。
- 材料不足时写“检索结果未提供”。

### 裁判要旨

- 概括裁判结论及其适用条件。
- 不新增原裁判没有的前提或例外。
- 只有检索摘要时明确标注“根据检索摘要”。

### 裁判观点

- 优先使用来源中“本院认为”的原文摘录。
- 原文摘录不得由模型改写后仍标称“原文”。
- 无原文时写“该案例未提供‘本院认为’原文”。

### 法律依据

- 只列来源数据明确提供的法律依据。
- 不自动补充法条，不把报告撰写者的法律分析混入案例原始依据。

## 五、附件

### 有案例全文

- 按正文案例顺序附录全文。
- 每篇全文前标明案件名称和案号。
- 可做版式高亮，但不得改变正文内容。

### 无案例全文

- 列出案件名称、案号、来源链接和原始记录定位。
- 明确注明“本次检索数据未包含案例全文”。
- 不把基本案情、摘要或裁判观点称为案例全文。

## 排版要求

- A4 纵向，正文使用中文常用字体。
- 一级标题清晰分节，案例标题单独成段。
- 正文行距、段前段后保持一致。
- 表格不得超出页面宽度。
- 案例正文之间分页，避免标题悬挂在页尾。
- 页眉可使用报告标题，页脚使用页码。

## 交付边界

- 正式交付必须是通过校验的 `.docx`。
- Markdown 仅作为大纲预览或失败诊断。
- 钉钉在线文档可作为协作副本，但不能替代 Word 文件。
