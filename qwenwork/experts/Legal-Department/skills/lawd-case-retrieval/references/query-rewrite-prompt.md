# 类案检索 Query 改写

## 目标

将用户表达转换为案例检索连接器「案例语义检索」入参可用的自然语言检索句，同时保留用户明确指定的时间、地域、法院、案例级别和争议方向。

## 选择处理模式

不要按字数机械判断，按实际改写工作量选择：

| 模式 | 适用条件 | 处理 |
|---|---|---|
| `direct` | 输入已经是明确的主体名称、案号、案由、罪名或法律问题 | 删除“查一下”等纯指令词，其余尽量原样保留 |
| `cleanup` | 法律问题明确，但存在口语、重复或无关表达 | 清理噪声并统一常见法律术语 |
| `full` | 长案情中包含多项事实，需要识别法律关系和核心争点 | 提炼案件类型、关键事实、争议焦点和裁判方向 |

输入短不等于无需改写，输入长也不等于必须改变用户的法律定性。

## 改写规则

1. 使用自然语言短语，推荐 50 个汉字以内，硬上限 128 个字符。
2. 优先保留案由、罪名、主体名称、关键行为、争议焦点和裁判方向。
3. 民事问题优先使用规范案由或法律关系；刑事问题优先使用罪名和量刑情节。
4. 不在一个 Query 中堆叠相互无关的多个法律问题；必要时拆成多次检索。
5. 不输出用户没有提出的事实、罪名、地域、法院或时间限制。
6. 用户明确要求地域或法院时放在 Query 前部；明确要求时间时放在末尾。
7. 案情发生地、合同签订地、当事人所在地或事件年份，不当然构成检索过滤条件。
8. 具体数字只有在会影响裁判尺度或相似性时保留，例如涉案金额、期限、伤残等级。
9. 不生成关键词数组；检索文本为单条自然语言检索句，结构化约束按连接器入参语义单独映射。

## 明确约束识别

只有以下表达才记录为筛选约束：

- 时间：“近五年案例”“2020 年以后判决”“仅看 2023 年至 2025 年”；
- 地域：“只看浙江案例”“杭州地区判决”“限上海法院”；
- 法院：“最高人民法院案例”“上海金融法院判决”；
- 数量：“给我 5 个”“检索 20 条”；
- 级别：“只要指导性案例”“参考案例”；
- 分类：“按原告胜败分类”“分一审和二审展示”。

“最近发生在杭州的纠纷”“2022 年签订合同”属于案情事实，除非用户同时表达检索范围要求，否则不得转成过滤条件。

## 法院观点字段

用户提及下列表达时，将 `need_court_think` 设为 `true`：

- 法院认定、本院认为、裁判理由；
- 法院观点、法官认为、裁判思路；
- 认定标准、说理逻辑、为什么这样判。

其他情形设为 `false`，以便处理脚本裁剪 `courtThink` 节省 Token。

## 输出格式

只输出以下 JSON，不添加解释性前后文：

```json
{
  "scene": "类案检索",
  "rewrite_mode": "direct | cleanup | full",
  "original_intent": "用户目标的一句话概括",
  "query": "最终自然语言检索句",
  "requested_count": null,
  "need_court_think": false,
  "explicit_constraints": {
    "caseType": null,
    "referLevel": null,
    "trialCourt": null,
    "timeRange": null,
    "region": null,
    "classification": null
  }
}
```

- `requested_count`：用户明确指定时填正整数，否则必须为 `null`。
- 未明确指定的约束必须为 `null`，不得填默认值。
- `query` 不包含说明文字或“建议筛选”等策略性内容。

## 示例

### 已可直接检索

用户：“查杭州洋驼网络科技有限公司的案件”

```json
{
  "scene": "类案检索",
  "rewrite_mode": "direct",
  "original_intent": "查询该公司相关案件",
  "query": "杭州洋驼网络科技有限公司",
  "requested_count": null,
  "need_court_think": false,
  "explicit_constraints": {
    "caseType": null,
    "referLevel": null,
    "trialCourt": null,
    "timeRange": null,
    "region": null,
    "classification": null
  }
}
```

公司名称中的“杭州”是主体名称的一部分，不额外设置地域过滤。

### 需要完整提炼

用户：“房东在租期未满时强制把公司物品搬走，造成损失，想找五个承租人获赔的类似案例。”

```json
{
  "scene": "类案检索",
  "rewrite_mode": "full",
  "original_intent": "寻找承租人获赔类案",
  "query": "房屋租赁合同 租期内强制清场 财产损失赔偿 承租人获赔",
  "requested_count": 5,
  "need_court_think": false,
  "explicit_constraints": {
    "caseType": "民事案件",
    "referLevel": null,
    "trialCourt": null,
    "timeRange": null,
    "region": null,
    "classification": null
  }
}
```

### 明确时间与法院观点

用户：“找近三年浙江法院关于竞业限制补偿金认定标准的案例，主要看法院为什么这样判。”

最终 Query 可写为：`浙江法院 竞业限制补偿金 认定标准 2023-2026`。年份应根据执行时的真实当前年份换算，不照抄示例年份。

## 自检

- Query 是否可直接用于语义检索？
- 是否只加入了用户明确要求的时间、地域和法院限制？
- 是否保留了决定案件相似性的事实？
- 是否错误地把案情地点或年份转成筛选条件？
- 是否超过 128 字符？
- 是否误生成了关键词数组，而不是单条自然语言 Query？
