# 案例检索连接器调用指南

本文件是该 Skill 中「案例/裁判文书检索」能力调用方式的唯一来源。主文件和其他引用文件不得复制维护另一套调用方式。**禁止在本文件和 SKILL.md 中写死任何供应商的具体工具名或首选顺序**：运行时按能力语义动态探测、按匹配度选择。

## 能力需求

本技能需要「案例/裁判文书检索」能力：输入自然语言案情描述或结构化过滤条件，返回真实案例列表（案号、法院、裁判日期、案由、裁判要旨/摘要等）；部分连接器另提供权威案例（指导性/公报/典型案例）检索与单案例详情查询。

## 三段式探测

### 1. 探测

调用平台连接器工具列表能力 `qwenwork_mcp_tool_list`，依次用以下关键词检索并汇总候选（同一会话内可缓存探测结果，避免重复探测）：

`案例 / 判例 / case / ptal / qwal / pkulaw / fabao / yuandian / 裁判文书`

### 2. 匹配（按工具语义，不写死名字）

在返回工具中，按工具名或 description 是否包含以下语义关键词判定：

- 「案例语义检索」：描述含案例、裁判文书、case 的自然语言/案情语义检索；
- 「案例条件/列表检索」：描述含按案由、法院、地域、裁判日期、文书种类等条件检索案例；
- 「权威案例检索」（增强，可选）：描述含指导性案例、公报案例、典型案例或参考案例检索；
- 「案例详情」（增强，可选）：描述含按案号或记录标识查询单案例详情。

**Schema 验证（必做）**：候选工具确定后，用 `qwenwork_mcp_tool_get` 查看其参数与返回 schema，确认入参语义和返回字段能对上本文件约定；schema 明显不符的，切换下一候选家，不得强行套用。

### 3. 调用

用 `qwenwork_mcp_tool_call` 执行检索。多家可用时按与本技能能力需求的匹配度选择（语义检索、条件检索、权威案例、详情四项覆盖越全越优先）；首选出错切下一家。

## Query 改写 → 连接器入参语义映射

以下内容按语义传入连接器；**具体参数名、取值格式（日期格式、枚举值等）以连接器运行时 schema 为准**，调用前用 schema 查询能力确认：

| Query 改写输出 / 用户约束 | 入参语义 | 说明 |
|---|---|---|
| `query` | 检索文本（必需） | 自然语言案情描述，传入「案例语义检索」能力 |
| 案由（用户明确指定时） | 案由过滤 | 使用完整案由名称；Query 已含且用户未单独强调时不必重复传 |
| `explicit_constraints.caseType` | 案件类别过滤 | 如民事案件、刑事案件、行政案件 |
| `explicit_constraints.trialCourt` | 审理法院过滤 | 使用法院正式全称 |
| `explicit_constraints.region` | 地域过滤 | 使用省级行政区全称 |
| `explicit_constraints.timeRange` | 裁判/结案日期范围 | 起止日期 |
| 文书类型（用户明确要求时） | 文书种类过滤 | 判决书、裁定书、调解书、决定书 |
| `explicit_constraints.referLevel` | 权威案例来源过滤 | 指导性案例、公报案例、典型案例等；仅用户明确要求时传入 |
| `requested_count` | 返回条数 | 各家连接器返回条数上限不同，以运行时 schema 为准，不得虚报 |

- 用户未明确给出的约束一律不传入。
- 连接器不支持某项用户明确约束对应的过滤参数时，把该约束并入检索文本，并在结果返回后逐条核验，同时在检索说明中注明；不得本地猜测式过滤，也不得静默丢弃约束。

## 结果归一化与保存

连接器原始返回 schema 因供应商而异。每一检索轮次（页）的原始返回，必须先按 [data-structure.md](data-structure.md) 的「归一化分页 JSON」结构归一化，再写入本次任务临时目录，交 `scripts/process_case_results.py` 校验：

- 按连接器实际返回字段逐一映射；连接器未返回的字段在 `caseDomain` 中保持为空，不得虚构、补全；
- 案号、法院名称、日期等逐字照录，不清理、不纠错、不格式化；
- 错误响应、空结果也要如实保存并交脚本校验，不得绕过校验直接摘取案例；
- 命令行输出需要管道保存时用 `scripts/save_stdout.py`；连接器调用的返回 JSON 由执行者直接写入分页文件。

### 连接器返回处理（程序化写入，禁止手动转写）

**硬要求：归一化必须程序化完成，禁止手动转写 content / sourceContent 等长文本字段**——手动转写曾导致内容截断、中文引号引发 JSON 解析失败、反复重试（逐字照录原则的底线）。正确做法：把 `qwenwork_mcp_tool_call` 返回的 Python 对象（dict）在内存中完成字段映射后，直接 `json.dump` 写入分页文件，由 Python 处理全部编码：

```python
import json

# raw = qwenwork_mcp_tool_call 的返回（dict，勿手工誊写其中任何字段）
page = {"Body": {"success": True, "data": {
    "caseResult": [
        {"caseDomain": map_fields(item),   # 按 data-structure.md 映射表逐字段赋值，值直接取 raw 中的原对象
         "similarity": item.get("score")}
        for item in raw_cases
    ],
    "currentPage": 1, "query": query, "totalCount": total,
}}}
with open(f"{tmp_dir}/page_1.json", "w", encoding="utf-8") as f:
    json.dump(page, f, ensure_ascii=False, indent=2)
```

- 返回值含中文引号（""''）或其他特殊字符时**不做任何替换**——`json.dump` 会正确转义；解析失败几乎都是"先把返回当文本读再 json.loads"造成的，直接从 dict 出发即可避免；
- 确需从文本解析时，先检查引号/转义再重试，禁止以"截断内容"方式绕过解析错误；
- 写入后运行 `scripts/process_case_results.py` 校验，字段缺失按脚本提示补映射，不得改脚本判据。

## 临时目录

每次检索创建独立目录，例如：

```text
./tmp/lawd-case-retrieval-<时间戳>-<随机标识>/
```

目录内建议使用：

```text
page_1.json
page_2.json
cases_full.json
cases_delivery.json
stats.json
```

不得使用跨会话固定文件，避免并发覆盖。

## 分页（批次）规则

1. 始终先请求第 1 页；单页请求条数以 10 条为上限，连接器返回条数参数的上限或默认值更低时，以其运行时 schema 为准。
2. 用户未明确指定数量：不请求下一页，首页返回多少条就处理多少条。
3. 用户明确指定 N：保持 Query 和过滤条件不变，按连接器支持的分页或偏移语义依次请求下一批。
4. 每获取一页，运行处理脚本统计去重后的 `deliveryCount`。
5. `deliveryCount >= N`、服务端已无更多数据或到第 5 页时停止。
6. 不通过更改 Query、放宽地域或扩大时间范围来静默凑数。

每次新增分页后运行：

```bash
python3 "<本技能目录>/scripts/process_case_results.py" \
  --input "<临时目录>/page_1.json" \
  --input "<临时目录>/page_2.json" \
  --full-output "<临时目录>/cases_full.json" \
  --trimmed-output "<临时目录>/cases_delivery.json" \
  --stats-output "<临时目录>/stats.json" \
  --requested-count <N>
```

未指定数量时省略 `--requested-count`。需要保留法院观点时增加 `--include-court-think`。

## 处理脚本输出

- `cases_full.json`：全部分页合并并去重后的完整案例，供详情回读和报告交接。
- `cases_delivery.json`：按用户数量形成的交付集，并裁剪文书正文等重字段，供模型分析。
- `stats.json`：页数、原始数、去重数、交付数、缺口和案号缺失统计。

脚本退出码非 0 时视为数据校验失败，禁止继续生成案例分析。

## 单条详情

用户要求查看第 X 条时，从 `cases_full.json` 的 `cases[X-1]` 读取完整对象。交付集保持检索返回顺序，处理脚本不按相似度重新排序。

需要回读某案例更多字段时，若探测到的连接器提供「案例详情」能力，可按该案例的案号或记录标识查询；回读结果以连接器返回为准，不得改写、补全或超出返回字段。不得为猜测其他案例而反复调用检索。

## 服务异常

- 调用失败（鉴权、网络、额度等）：用相同参数重试一次；仍失败切换探测到的下一家可用连接器。
- 返回结构无法对上 schema：重新用 schema 查询能力确认后重试一次；仍失败则向用户说明检索数据响应异常，停止生成案例事实。
- 全部连接器不可用：按 SKILL.md 执行门禁作 A 档降级处理——停止执行并提示用户安装，不罗列案例，不虚构案号。
- 空结果：可清理一次非必要术语后重试，但不得改变用户明确的时间、地域、法院和案例级别约束。

## 已知缺口：裁判文书逐字全文

> 合并后指向说明：裁判文书逐字全文由本技能**模式B（按案号取裁判文书全文）**承担。浏览器能力的探测关键词、schema 验证、A 档降级与实验性提示以 `SKILL.md` 的「模式B 浏览器能力段」为**唯一来源**；本节以下文字保留原有口径，与该段冲突时以该段为准。

现有法律案例检索连接器均**无裁判文书逐字全文抓取能力**：语义检索、列表检索和案例详情返回的是整理后的案例内容、命中片段或裁判要旨，**不等同于原始裁判文书逐字全文**。

用户要求裁判文书完整全文时：

1. 先读取 `cases_full.json` 中的 `sourceContent`；该字段缺失、仅为摘要或属整理后内容时，视为全文未取得。
2. 全文未取得且用户仍需要时，探测千问办公内置浏览器连接器（探测关键词：`browser / 浏览器 / web / browse`），匹配「网页浏览/网页内容读取」能力后，以案号为线索访问公开的裁判文书披露页面并读取正文：
   - 浏览器读取的内容必须原样保存到本次任务临时目录，并记录来源页面地址；不得由模型改写、拼接或补全；
   - 浏览器能力未探测到、页面访问失败、被访问限制或内容不完整时，降级为「仅提供检索摘要+出处」，并明确注明"未取得逐字全文"。
3. 不得把摘要或整理后内容扩写、补全成全文。
