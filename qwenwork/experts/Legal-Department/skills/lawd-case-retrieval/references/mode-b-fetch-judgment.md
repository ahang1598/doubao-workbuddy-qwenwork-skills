# 模式B：按案号取裁判文书全文（完整工作流）

> 本文件为 SKILL.md「三、模式工作流」3.2 模式B 的完整工作流细则（自 SKILL.md 外移），执行模式B 时必须完整读取并严格遵循。

### 3.2 模式B：按案号取裁判文书全文

已知案号时，用「浏览器页面操作」能力登录并访问中国裁判文书网，按案号检索、取回文书详情与逐字全文，落盘 Markdown 与 PDF。

> ⚠️ **实验性能力提示（必须向用户显性交代）**：模式B 依赖浏览器登录与页面抓取，**当前为实验性能力，尚未在千问办公完成实测**，站点改版、登录风控、人机验证、懒加载都可能导致抓取失败。抓取失败时**必须明确告知用户失败原因**，并建议改用**模式A 取裁判要旨/裁判观点**作为替代；**禁止让失败静默**，禁止用摘要冒充全文收尾。首次进入模式B 时，在第一条回复中用一句话提示用户："裁判文书网抓取属实验性能力，如遇登录风控或页面变动可能失败，届时我会明确告知并改用类案检索的裁判要旨。"

#### 模式B 定位与硬前提

| 情形 | 处理 |
|------|------|
| 已知 **caseNo** → 要文书详情、Markdown、PDF、URL | **走模式B** |
| 仅关键词、案由、当事人等模糊条件 | **不走模式B** → 回落 **模式A**（见 SKILL.md 2.2） |

#### 模式B 前置条件

1. 从用户或上下文得到原始案号，按 `references/detail-query-case-no-examples.md` 产出与文书网标准形态一致的 **caseNo**（细则与校验见该文件「裁判文书网标准形态」「步骤 1.4」）。缺关键段则请用户补全，禁止猜测补全。
2. 「浏览器页面操作」能力可用（导航、点击、输入、截图、读取页面内容；用于打开站点、轮询登录态、抓取正文，可选导出 PDF）——按 SKILL.md 第 4.2 节探测与验证，不可用则按 A 档停止。
3. **Python 3.x** 可运行 `scripts/convert_to_md.py` 与 `scripts/normalize_case_no_for_search.py`（标准库即可）。执行时 **cwd** 须为**本技能包根目录**（使 `scripts/` 相对路径可用），或改用脚本绝对路径。
4. 默认输出目录 `{当前工作区}/outputs/`：写入前须可创建、可写；不可写或空间不足则**停机**说明原因，**禁止**擅自改路径并声称已按规范交付（除非用户明确同意其他目录）。

#### 模式B 硬约束（优先级最高）

- **正文真实性**：无法从页面合法取得**完整文书正文**时，**禁止**编造、推测、补全或「合理还原」语句；只可复述页面上已展示的可核实字段，并标明未展示部分未获取。
- **交付路径**：`convert_to_md.py` 非零退出、异常或无 `FILE_PATH:` 时**禁止**伪造路径；记录错误摘要，走步骤 B10 降级或停机。
- **禁止静默覆盖**：未经用户明确同意，不得覆盖 `output` 下已存在的同名 `{案号}_案例详情.md` / `.pdf`（同意含：用户确认覆盖，或明确要求 `--on-collision overwrite`）。
- **PDF 契约落点（`output`）**：浏览器能力的 PDF 导出动作**常把文件写在运行时目录**（如 `artifacts/`、`snapshot/browser-pdf-*.pdf` 等），**不等于**已按本技能交付。**禁止**在最终回复中仅报告上述路径并声称已保存到 `output`。**必须**在步骤 B9 内将 PDF **复制或移动**到**当前工作区** `{工作区}/outputs/`，且文件名符合 `references/detail-query-file-naming.md`（经 sanitize 的 `{案号}_案例详情.pdf`），并确认该文件在 `outputs/` 中**实际存在**后，方可在步骤 B10 中给出**该 `output` 下路径**；若无法写入 `output`，按失败处理并说明，**禁止**伪造或混用临时目录路径交差。
- **禁止绕行全文**：不得以 `WebSearch`、网页摘要、外站转载或模式A 的检索列表/摘要替代**登录后可访问的完整正文流程**。出现登录/注册拦截时，唯一合法路径是请用户在浏览器中完成登录后继续本流程，或满 5 分钟超时后终止（见步骤 B3）；**在累计未满 5 分钟前须保持本会话与任务为进行中**（轮询 + 提示），**禁止**因对话空窗、用户暂未聊天回复或习惯性收尾而提前结束；**禁止**改写为「改从其他渠道获取」。
- **搜索框零空白（强制）**：写入裁判文书网**搜索框**的字符串**不得**含任何空白类字符（含全角空格、不换行空格等）；**禁止**将带空格的采集串（如 `（2025）辽 10 执复 24 号`）未处理直接粘贴进搜索框。去空白后的串须与步骤 B1 定稿 **caseNo** 一致；若去空白后与步骤 B1 不一致，回到步骤 B1 以该串为输入重新走 1.1 全流程后再定稿 **caseNo**。
- **敏感信息与版权**：当事人敏感信息按合规处理；尊重站点声明与法律，不得篡改已获取原文含义。

#### 模式B 工作流程

按步骤执行，任一步出现登录拦截时，适用步骤 B3 的「登录与绕行」。

##### 步骤 B0：探测浏览器能力

按 SKILL.md 第 4.2 节完成「浏览器页面操作」能力的探测、匹配与 schema 验证。**能力不可用时不进入 B1**，直接按 A 档停止并提示用户启用浏览器连接器。

##### 步骤 B1：案号

以 `references/detail-query-case-no-examples.md` 为唯一权威：标准化、禁止猜测、对用户说明、**标准形态校验（1.4）**。本步产出唯一 **caseNo**（示例：`（2026）最高法刑申3号`）。步骤 B4 与步骤 B5 **只认**本步定稿的 caseNo；不得用半角括号版、带空格中间态或未走 1.1 的原始串参与检索或比对。

##### 步骤 B2：打开站点

用浏览器能力的**导航**动作打开：`https://wenshu.court.gov.cn/`

##### 步骤 B3：登录检测与等待

**登录与绕行（步骤 B3 及全程适用）**

凡跳转或提示**登录/注册**、或无法进入**完整文书正文**且原因明确为需登录：

- 告知：查看该案文书须先登录中国裁判文书网；**必须**提示：**「请查看千问办公打开的浏览器窗口并手动完成登录」**。
- **会话保持（未满 5 分钟）**：自判定需登录起至累计等待满 **5 分钟**止，任务视为**仍在执行步骤 B3**，**禁止**因「聊天侧暂无新消息」、用户未在对话框里打字或模型对话轮次限制而**主动结束会话**、宣告失败、交付部分结果、总结收尾或切换外站替代方案；应**持续**轮询并在对话中按下列「周期性提示」提醒用户，直至登录成功或满 5 分钟。
- **轮询**：约每 **10～20 秒**用浏览器能力的「读取页面内容」或「截图」动作**检查一次**是否已登录；轮询期间**不得**并行外站检索或交付非完整正文流程的产物。
- **周期性提示**：约每 **30～60 秒**（或每 **2～3 次**轮询）在对话中**简短复提示**一次（例：请在浏览器窗口完成登录，登录成功后将继续查询该案），避免用户误以为会话已结束；**不得**用冗长重复刷屏。
- **超时（满 5 分钟）**：仅当自进入本登录等待起**累计满 5 分钟**仍未登录 → **方可**结束本会话，提示用户重新发起，并按实验性能力提示建议改用模式A 取裁判要旨；**不得**用列表片段、历史步骤或外站内容收尾。**未满 5 分钟前不得**套用本项提前终止。
- 步骤 B4～B10 中**再次**被拦登录：同样处理，不得绕行。

若无需登录或已登录 → 进入步骤 B4。

##### 步骤 B4：搜索

**步骤 B4.0（键入前闸门，不得跳过）**

1. 取得拟写入搜索框的原始串（含用户输入、列表复制、OCR、上一步机读结果等）。
2. **必须**先删除串内**全部**空白（与 `references/detail-query-case-no-examples.md` 步骤 1.1 第 7 条同义）。**推荐**运行 `scripts/normalize_case_no_for_search.py`，将 stdout **整段**复制进搜索框；命令行、`stdin` 用法与退出约定见 `references/detail-query-script-usage.md` 第 1 节（须在技能包根目录或等价路径下执行，见前置条件第 3 条）。
3. 将第 2 步得到的串与步骤 B1 的 **caseNo** 做逐字符比对：**须完全一致**。不一致则不得提交搜索；回到步骤 B1 用去空白后的串重新标准化并更新 **caseNo**，再重复 B4.0～B4.1。

**步骤 B4.1（提交）**

用浏览器能力的**输入**动作写入搜索框，字符串须与步骤 B1 的 **caseNo** **完全一致**：**任意两相邻字符之间不得有空格或其他空白**（禁止在 `（` 与年份、`）` 与法院代字、代字与数字之间人为加空格；不得用「可读分段」键入）。宜整段写入经 B4.0 核对后的 **caseNo** 再用**点击**动作提交搜索，避免手打漏删空格。文书网标准形态（全角年份括号等）见 `references/detail-query-case-no-examples.md`。禁止跳过步骤 B1、禁止为「好打」改成半角括号或在串内插入任何空白；**禁止**跳过 B4.0 直接把带空格的采集串写入搜索框。

##### 步骤 B5：列表核对（强制，不得默认点第一条）

1. **取数与匹配**：用「读取页面内容」动作抓取列表页每条结果的**案号**文本；按 `references/detail-query-case-no-examples.md` 步骤 **1.1 全流程（含删空白、年份段全角括号）**规范化后，与 **caseNo** 做**字符串完全相等**判断。**禁止**在比对阶段改动年份、法院代字、类型代字、顺序号；禁止跳过列表、仅凭标题点进详情。
2. **命中条数与分支**：
   - **恰好一条**与 `caseNo` 完全一致 → **直接进入步骤 B6**（点开该条）。
   - **零条**完全一致且列表**仅一条**结果 → **不得**自动点开；向用户列出该案**案号、案例名称**（及页面若有的裁判/发布日期），说明与目标不一致，请用户确认是否仍查看本条。
   - **零条**完全一致且列表**多条**结果 → 向用户展示编号清单：**序号**、**案号**、**案例名称**（页面另有可靠字段如日期可附在同一行），请用户回复序号或案号后再点击对应条；**确认前不得**进入步骤 B6～B10。
   - **两条及以上**列表项在规范化后与 `caseNo` 均完全一致（异常重复）→ 同样用**序号、案号、案例名称**列出全部命中行，请用户指定一条后再点，**不得**擅自择一。
   - **无结果** → 见异常处理「无结果」，不捏造案号。
3. **用户改选后**：落盘文件名与文书案号以**用户最终确认的列表案号**为准；若与最初输入不一致，最终回复中客观说明「用户已改选为 xxx」，**禁止**单方面称原始输入为笔误。

##### 步骤 B6：详情页

用**点击**动作点开选定条目；等待正文加载完成（禁止用空白冒充已加载）。长文书须重复「向下滚动 → 等待 2～3 秒 → 读取页面内容」直到内容不再增长、正文落款段已出现。提取完整文书结构信息；若页面提供合法下载，可优先下载原文。

##### 步骤 B7：Markdown

结构化整理后调用 `scripts/convert_to_md.py` 写入 `output`（命令见 `references/detail-query-script-usage.md`）。

##### 步骤 B8：URL

记录当前详情页完整 URL（示例形态：`https://wenshu.court.gov.cn/website/wenshu/.../index.html?docId=...`），作为结果一部分。

##### 步骤 B9：PDF

1. 用浏览器能力的 **PDF 导出/打印为 PDF** 动作对**当前详情页**导出。先确认正文已渲染；长文滚动确保懒加载完成；导出**整页**而非仅视口。失败时至少「滚到底 → 等待 2～3 秒 → 再导出」一次；仍失败则记录错误，步骤 B10 降级，**禁止**伪造 PDF 路径。等待与滚动要点见 `references/detail-query-script-usage.md` 第 3～4 节。匹配到的浏览器能力**不提供** PDF 导出动作时，跳过本步并在 B10 中明确"本次未生成 PDF"。
2. **复制/移动到 `output`（必做，不得跳过）**：导出返回的路径若在 `artifacts/`、`snapshot/` 或其他**非** `{工作区}/outputs/` 的位置，或仅有浏览器侧临时名（如 `browser-pdf-*.pdf`），须使用运行环境允许的方式（`cp`/`mv`、文件读写 API 等）将内容写入 **`{工作区}/outputs/{sanitize(案号)}_案例详情.pdf`**，与 `references/detail-query-file-naming.md` 一致。完成后**再核对**：`outputs/` 目录中**确实存在**该文件；**未出现**在 `outputs/` 中则**不得**在步骤 B10 中声称 PDF 已按契约保存。
3. 细节、同名策略见 `references/detail-query-file-naming.md` 与 `references/detail-query-script-usage.md`「落盘」段。

##### 步骤 B10：回复用户

**优先**：Markdown 路径、PDF 路径（若成功）、详情 URL。

**降级**：仅当文件或 PDF 确实失败时，才可内联展示文书正文作为备选；**禁止**内联全文与「文件已生成」同时成立。

**失败必须显性告知**：抓取全流程失败（浏览器能力不可用、登录超时、无结果、正文不可展示、限流风控等）时，明确说明失败环节与原因，并给出建议："可改用**模式A 类案检索**取该案或同类案件的裁判要旨与裁判观点（非逐字全文）。"不得用摘要、外站转载或模型记忆冒充文书全文收尾。

#### 模式B 异常处理

| 情况 | 处理 |
|------|------|
| 浏览器能力探测不到 / schema 不具备导航与内容读取 | 按 SKILL.md 第 4.2 节 **A 档**停止执行并提示用户启用浏览器连接器；**禁止** WebSearch 搜摘要冒充全文、禁止凭模型记忆编造判决内容 |
| 需登录 | 按「登录与绕行」轮询并周期性提示；**未满 5 分钟不得**因会话习惯或空窗结束；满 5 分钟仍未登录再终止。用户明确不登录 → 结束，不交付拼凑内容，不引导外站全文替代 |
| 无结果 | 告知未找到；说明**实际用于检索的 caseNo**（可与原始输入并列）；提示核实案号、未公开或未收录可能；可建议改用模式A |
| 有结果但无完全一致 | 已在步骤 B5 列候选；用户未确认前不进详情；用户放弃或未选 → 结束 |
| 非登录导致的权限/付费/不可展示正文 | 说明原因；可列页面上已展示字段，**禁止**编造正文；不启动外站全文检索替代 |
| 网络/加载/工具超时 | 有限重试（刷新、等待、重新读取页面）；仍失败则停机说明并建议改用模式A，禁止臆测填充文书 |
| 限流/人机验证 | 暂停高频自动化；由用户人工处理或稍后重试；禁止暴力绕过 |
| 会话中途失效 | 同登录流程轮询；禁止用缓存片段冒充最新正文 |
| 脚本失败、目录不可写、磁盘满 | 记录要点；**禁止**伪造 `FILE_PATH:` 或 PDF 路径；权限/路径变更须用户明确同意 |
