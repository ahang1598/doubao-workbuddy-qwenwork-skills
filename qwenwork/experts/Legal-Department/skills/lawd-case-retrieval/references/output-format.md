# 类案检索输出格式

> **格式使用场景**：对话交付可用表格（易扫读），Markdown 文件交付按本文件的编号+缩进列表格式；两种载体的字段内容要求一致。**核心法规关注清单**统一用"《法条名》第X条：本次样本中用于处理…"格式，不得只列法条名称。

## 默认对话输出

用户未指定分类时按以下顺序连续展示，不自动生成文件。

```markdown
## 检索说明

- 检索 Query：...
- 用户明确约束：无 / ...
- 检索范围：共 X 页，原始 X 条，去重后 X 条，本次展示 X 条

## AI 洞察

> 以下结论仅基于本次检索并交付的 X 个案例样本。

- 裁判观点：...
- 主要争议焦点：...
- 样本中的差异：...

## 核心法规关注清单

- 《...》第 ... 条：本次样本中用于处理 ...

## 类案列表

1. **案件名称**
   - 案号：原始案号 / 无
   - 法院：原始法院名称 / 未提供
   - 日期：原始日期 / 未提供
   - 关联说明：基于实际返回字段说明与用户问题的关联
```

没有实际出现的法条时写“当前交付样本未提供可核验的明确法条”，不要凭专业常识补齐。

## 数量规则

- 用户未指定数量：展示首页返回并去重后的全部案例。
- 用户指定 N：展示处理脚本形成的 N 条交付集；实际不足时展示现有全部，并明确缺口。
- 不因认为某些案例“更典型”而再次筛选交付集。
- 服务端重复记录不重复展示，检索说明中列出去重数量。

## 案号与缺失字段

- `caseNo` 为非空字符串：逐字复制。
- `caseNo` 为空、`null` 或缺失：固定写 `案号：无`。
- 法院、日期等其他字段缺失：写“未提供”或省略该字段。
- 不拼接法院全称，不格式化案号，不从标题或正文反推字段。

## 分类输出

仅当用户明确指定分类时，将“类案列表”替换为对应分组：

```markdown
## 类案列表

### 原告胜诉
...

### 原告败诉
...

### 无法根据返回字段判断
...
```

分类必须有字段依据。分类后的总数必须等于 `deliveryCount`，不得隐藏无法判断的案例。

## 详情输出

用户指定某条案例时，从完整集合输出存在的字段：

```markdown
## 案件名称

| 字段 | 内容 |
|---|---|
| 案号 | 原始案号 / 无 |
| 案由 | ... |
| 审理法院 | ... |
| 日期 | ... |
| 审级 | ... |
| 参考级别 | ... |

### 争议焦点
...

### 法院查明
...

### 法院认为
...

### 裁判结果
...

### 法律依据
...
```

空字段可省略；不得用 AI 关联说明替代文书字段。

## Markdown 文件

仅在用户明确要求 `.md` 时生成。文件正文沿用默认对话结构，文件名可用 `类案检索结果_YYYYMMDD_HHMMSS.md`，保存到用户指定目录；未指定目录时使用当前工作区内安全、明确的位置。

交付时同时说明文件路径和样本数量。Markdown 文件不是 Word 文件。

## Word/DOCX 请求

1. 先检查当前环境是否具备正式报告或 DOCX 生成能力，不使用固定 Skill 名称或 UUID。
2. 能力可用时传递：用户原始问题、Query、明确约束、完整集合、交付集和统计数据。
3. 只有验证真实 `.docx` 文件存在且内容包含交付集后，才能说“Word 报告已生成”。
4. 能力不可用时提供经核验的报告素材，并明确说明“当前环境没有完成 DOCX 生成，本次未交付 Word 文件”。
5. 用户接受 Markdown 兜底后方可生成 `.md`；不得自行把 Markdown 当作 DOCX。

## 表述禁区

- 不把样本比例写成普遍胜诉率。
- 不说“全国法院普遍认为”，除非数据范围和样本足以直接支持。
- 不把数据库相似度写成案件胜算。
- 不对缺失字段使用推断值。
- 不在没有生成文件时声称“报告已生成”。
