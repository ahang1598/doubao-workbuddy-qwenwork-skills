# 案件事件规格

业务 Skill 完成案件相关成果后，用本格式交给案件管家。它只适用于用户已经明确绑定的唯一案件；无案件、案件不明确或用户拒绝关联时，不生成事件、不创建台账。

## 最小字段

```json
{
  "案件编号": "A001",
  "案件简称": "甲诉乙买卖合同案",
  "事件类型": "文书起草",
  "产出名称": "民事起诉状",
  "产出路径": "outputs/甲诉乙买卖合同案_民事起诉状_2026-08-13.docx",
  "来源Skill": "起诉状生成",
  "成果状态": "待核验稿",
  "完成日期": "2026-08-13",
  "摘要": "已生成起诉状，主体地址仍待核验",
  "下一步动作": "核验被告注册地址后运行交付门禁"
}
```

## 约束

- 必填：案件编号、案件简称、事件类型、产出名称、来源 Skill、成果状态、完成日期、摘要。
- 成果状态只允许：`草稿`、`待核验稿`、`门禁通过稿`、`律师确认稿`。
- `律师确认稿` 只能来自用户对当前版本的明确确认，业务 Skill 不得自行填写。
- 产出路径可空；填写时必须是实际存在或已由外部系统返回成功标识的成果。
- 回写失败不得阻塞主成果，也不得声称“已经同步”。

## 写入结果

案件管家应当：

1. 向 `cases/{案件简称}/办案历程.md` 追加事件，不覆盖历史。
2. 本地台账按案件编号刷新“当前进展、下一步动作、最后更新”；在线台账用同一字段语义写入。
3. 不因一条成果事件擅自改变案件阶段、风险等级、期限或结案状态。
