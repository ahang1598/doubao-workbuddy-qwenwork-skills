# 案件管家

> 管住律师手上所有案子的**记录、期限与状态**：收案 → 在办 → 结案 → 归档。
>
> **设计哲学**：最小干预、自动沉淀——台账随办案交互更新，律师不必刻意"维护台账"。
>
> **本技能最危险的部分是期限**。算错一天就可能导致失权。期限子模式设三道安全线（第 4 节）：日期运算交脚本、节假日缺失时安全停止、法条验真状态透明。个人使用不需要另一个人复核签字。

---

## 0 · 前置三步

1. **读公共层** `办案画像.md`：角色（执业律师 / 公司法务）、台账载体与标识、提醒渠道与时间、办案流程、案件档案根目录。文件不存在 → 提示可先跑冷启动访谈，但不阻塞，用默认值继续并标注"未配置画像"。
2. **确定台账载体**（冷启动访谈已做过能力探测与用户确认，本技能信任画像配置，不重复探测）：
   - **画像已配置则直接使用**：`办案画像.md` 第三节「台账载体」有值 → 按配置执行，不重新探测能力是否可用。
     - 在线表格 + 有台账标识 → 直接用标识中的表格与数据表标识，找到能操作该表格的工具后写入；**写入失败再降级**。
     - 在线表格 + 无台账标识（`[待补]`）→ 探测可用工具，找到后要么使用已有表格要么新建，将标识回写画像第三节「台账标识」。
     - 本地文件 → 读写 `cases/案件台账.xlsx`（读写方式见第 7 节脚本）。
   - **画像未配置或值为 `[待补]` 时才探测**：按能力语义探测「在线表格 / 结构化数据表」类能力。探测范围须覆盖 **MCP 连接器与 available skills 两类通道**，不只查单一通道。探测顺序、供应商、优先级一律不在本文件写死；同类多家按匹配度选择，先确认返回结构符合预期再正式写入。
   - **探测失败或写入失败 → 降级本地模式**：台账写 `cases/案件台账.xlsx`，每次输出显式标注 `[本地模式]` 并说明降级原因。
3. **分发子模式**：`建档 | 跟进 | 期限 | 全景 | 结案 | 归档`。判断不了 → 只问 1 个澄清问题。
   有激活案件时读 `cases/{案件简称}/案件画像.md`，案件级字段覆盖全局。

## 2 · 案件档案结构

```
cases/
├── 案件台账.xlsx                  本地模式下的台账（经 scripts/ledger_excel.py 读写）
└── {案件简称}/
    ├── 案件画像.md                 案件级配置与关键字段（模板见 references/matter-template.md）
    └── 办案历程.md                 审计流水，只追加不覆盖
```

正式交付物（案卷目录清单、组合看板报告等）落 `outputs/`；命名 `{案件简称}_{文书类型}_{日期}.md`。

## 3 · 六个子模式

### 3.1 建档

**入口参数**：案件名称、案由、当事人、我方地位、标的额、审理机关、案号（可为"未立案"）、主办人、收案日。缺项标 `[待核验:事实]`，不静默补空。

**步骤**

1. 采集基础信息；确定 `案件简称`（当事人简称 + 案由，作为目录名）。
2. **⛔ 利益冲突确认门槛**：`办案画像.md` 角色 = 执业律师时**必过**——须律师明确答复冲突检索已完成、无冲突，并记录确认人与确认日期。未确认则停在此步，不写台账、不建目录。角色 = 公司法务时跳过本步并在画像里注明"法务模式跳过"。
3. 写台账（按前置三步 Step 2 的载体：在线表格直接用台账标识，本地用 `scripts/ledger_excel.py`），补齐 20 项中可得字段。
4. 复制 `references/matter-template.md` 生成 `cases/{案件简称}/案件画像.md`；**务必填第四节「建档时结果预判」**——结案子模式要拿它做敞口校准，此时不填，结案就没得对比。
5. 生成 `cases/{案件简称}/办案历程.md`，首条为建档事件。

**产出**：台账 1 行 + `案件画像.md` + `办案历程.md`。

**衔接**：① 已有法院文书 → 建议立即进入 3.3 期限子模式算首批期限；② 建议跑「起诉状分析与攻防策略」定请求权基础与攻防方向；③ 需要问客户什么 → 「咨询信息采集清单」。**只建议，不自动调用。**

### 3.2 跟进

**入口参数**：案件定位（案件编号 / 案件名称 / 案号 / 案件简称）+ 本次事件描述 + 来源（律师口述 / 法院文书 / 某技能产出）。

**步骤**

1. 定位案件；命中多个则列出让律师选，**不猜**。
2. 向 `办案历程.md` **末尾追加**一条 `YYYY-MM-DD ｜ 事件类型 ｜ 事项 ｜ 来源`。**绝不覆盖、绝不删行、绝不改历史行**。
3. 刷新台账与 `案件画像.md`：当前阶段、风险等级、当前进展、下一步动作、最后更新。
4. 重要变化提示联动（只提示，等律师点头）：

| 变化 | 提示联动 |
|---|---|
| 和解或调解达成 | 结案子模式；核对履行期限 |
| 二审改判 / 发回重审 | 重新定阶段与风险；模拟裁判类技能 |
| 追加或变更当事人 | 主体核验；重算答辩期与举证期限 |
| 保全即将届满 | 期限子模式复核续封/续冻时间 |
| 风险升档 | 组合看板复看；相关分析类技能 |
| 收到任何法院文书 | 期限子模式提取送达日重算 |

**产出**：办案历程 +1 行；台账字段刷新。
**衔接**：明确绑定唯一案件时，中枢或直接调用的业务 Skill 都通过下方标准案件事件入口回写。没有明确案件、临时起草或案件不唯一时，不建档、不回写。

#### 标准案件事件入口

业务 Skill 已明确绑定唯一案件时，按 [references/case-event-spec.md](references/case-event-spec.md) 提交事件；无案件、案件不明确或用户拒绝关联时不生成事件、不建档。收到事件后：

1. 本地模式调用 `scripts/write_case_event.py --json '<事件JSON>'`，追加办案历程并按案件编号刷新台账；
2. 在线模式调用 `scripts/write_case_event.py --json '<事件JSON>' --online-ledger` 追加办案历程，再按脚本返回的同一事件字段写在线台账；
3. 回写失败不阻塞主成果，但须提示一次“案件记录未同步”，不得静默宣称成功；
4. 成果事件不自动改变阶段、风险、期限或结案状态。

### 3.3 期限

**入口参数**：起算日（送达日 / 生效日 / 履行期最后一日 / 保全裁定执行日）+ 期间类型 + 适用情形（判决/裁定/涉外/动产…）；`举证期限` 另需法院指定天数。

**步骤**

1. **模型只做提取**：从法院文书可读文本里读出**送达日期与文书类型**，逐项回读给律师确认。PDF/扫描件先用「材料文字化」外部前置能力处理；该能力不可用时，请用户提供可读文本。文书没写清 → 标 `[待核验:事实]` 并向律师索取，不推断。
2. **算术全部交脚本**（禁止模型心算任何日期）：
   ```bash
   python3 scripts/compute_deadline.py --start-date 2026-07-15 --type 上诉期 --scene 判决 --doc-type 民事判决书
   python3 scripts/compute_deadline.py --list-types      # 看规则表有哪些期间
   ```
3. 按脚本退出码分流：

| 退出码 | 含义 | 怎么回复律师 |
|---|---|---|
| 0 | 出届满日 | 给届满日 + 完整推算过程 + 紧迫度 + 失权警示 |
| 2 | 入参/资源问题 | 原样转述脚本报错，索取缺失信息（如法院指定天数） |
| 4 | 节假日表缺位 | **只给**"原始末日 + 该日可能为节假日，顺延需人工核对"，**不给顺延后日期** |

4. 读取规则表「验真状态」：`[待验真]` 不阻断个人辅助计算，但结果必须标为「辅助草算-法条依据待验真」；已标「时效风险 / 语义不一致 / 未命中」的规则不继续使用。
5. 回写台账第 12–15 项与 `案件画像.md` 第五节；把推算过程和验真状态追加进 `办案历程.md`。
6. 待办四档呈现：🔴 已过期 / 🟠 今日届满 / 🟡 7 天内 / 🟢 30 天内。跨案件聚合时按紧迫度排序。

**产出**：期限计算单（届满日 / 原始末日 + 推算过程 + 失权警示）+ 台账回写 + 四档待办。

**提醒克制**：按 `办案画像.md` 的提醒渠道，默认对话内展示或 IM 推送。**不擅自创建日程、不建群、不发外部通知**；律师明确要求才做。

**不做**：不做自动申报、不代提交任何材料、不替律师决定是否上诉或是否申请执行。

### 3.4 全景

**入口参数**：无参数 = 组合全景；给案件定位 = 单案简报。

**单案简报**：当前阶段 / 风险等级 / 下一个届满日 / 近期变化（办案历程最近 N 条）/ 未完成事项 / 可选下一步。

**组合看板**

| 板块 | 内容 |
|---|---|
| 风险分布 | 重大 / 高 / 中 / 低 各几件 |
| 阶段分布 | 收案 / 一审 / 二审 / 再审 / 执行 / 已结案 各几件 |
| 临期看板 | 四档（已过期 / 今日 / 7 天内 / 30 天内），列案件与期限类型 |
| 长期未更新 | 最后更新距今 > 30 天且未结案的案件 |
| 近期结案 | 结案件数与结果分类构成 |

**异常巡检**（逐条给出案件与事实依据）

1. 高风险且有过期/临期期限
2. 保全将届满而未见续封/续冻记录
3. 上诉期或申请执行期临近而未见决策记录
4. 已结案但未归档
5. 长期未更新（在办案件）
6. 律师模式：利益冲突确认缺失；法务模式：外部律师或预算状态待定

⚠️ **只呈现事实与异常，不做决定**。禁止出现"建议撤诉""应当上诉""放弃执行"这类替律师决策的表述；可以写"上诉期 3 天后届满，未见上诉决策记录"。

### 3.5 结案

**入口参数**：案件定位 + 结案日 + 审理结果 + 结果分类（胜诉/部分胜诉/败诉/调解/撤诉/和解/其他）+ 最终标的 + 是否上诉或执行。

**步骤**

1. 捕获上述信息，缺项标 `[待核验:事实]`。
2. **与建档时预判对比**：取 `案件画像.md` 第四节「建档时结果预判」，逐项写出实际 vs 预判的差异与方向（优于/劣于/一致），差异原因留给复盘，不在此处下判断。
3. 台账阶段标「已结案」，填第 18 项；`案件画像.md` 第九节回填。**记录保留，不删不移**。
4. 若判决未生效或存在后续程序，同时算上诉期 / 申请执行期（回 3.3）。

**产出**：结案登记 + 预判对比小结。
**衔接**：建议进入 3.6 归档；建议跑办案小结类技能做复盘。

### 3.6 归档

**入口参数**：案件定位 + 已有材料清单（或指向材料目录）。

**步骤**

1. 按标准装订顺序生成案卷目录清单：

   | 序号 | 卷内材料 |
   |---|---|
   | 1 | 卷内目录 |
   | 2 | 委托代理合同、授权委托书 |
   | 3 | 当事人主体资料（身份证明、营业执照、法定代表人身份证明） |
   | 4 | 起诉状 / 答辩状 / 反诉状 / 上诉状及送达凭证 |
   | 5 | 证据材料及证据清单（按提交批次） |
   | 6 | 法院通知类文书（受理通知、举证通知、传票、鉴定文书） |
   | 7 | 庭审材料（庭审提纲、笔录复印件、质证意见、代理词） |
   | 8 | 裁判文书（判决书/裁定书/调解书）及送达回证 |
   | 9 | 执行材料（执行申请、执行裁定、结案文书） |
   | 10 | 结案报告、费用结算凭证 |
   | 11 | 归档说明与移交记录 |

2. 完整性核对：逐项标 ✅ 已归入 / ❌ 缺失 / ⚠️ 仅有复印件。**缺失项必须显式列出，不得静默略过。**
3. 双模式收尾：
   - **执业律师模式**：出移交确认要点——移交人/接收人/日期、卷册数与页数、原件与复印件区分、**工作底稿（内部分析、策略备忘、模型产出草稿）须抽出留所内，不随案卷移交**、保密与去向说明。
   - **公司法务模式**：出公司归档清单——档案编号、保管期限、责任人、电子件存放位置、涉密等级。
4. `案件画像.md` 第九节回填归档状态与缺失项；台账阶段改「已归档」。

**产出**：`outputs/{案件简称}_案卷目录清单_{日期}.md` + 缺失项清单 + 移交确认要点或归档清单。

## 4 · 期限的三道安全线

| # | 门 | 落在哪 | 过不去时的行为 |
|---|---|---|---|
| 1 | **日期运算交脚本，不让模型心算** | `scripts/compute_deadline.py`：起算日不计入、月年按对应日（无对应日取月末）、末日遇休假顺延，全部由脚本算并打印推算过程 | 模型不得自行给任何届满日；只允许提取送达日与文书类型 |
| 2 | **节假日表过期保护** | `assets/holidays-{年}.json`；脚本 `HolidayCalendar.classify()` | 目标年份表缺失、无数据或未覆盖该日期 → 退出码 4，只给原始末日 + "该日可能为节假日，顺延需人工核对"，**拒绝输出顺延后日期** |
| 3 | **法条验真状态透明** | `references/deadline-rules.md` 第二节 + 表内「验真状态」列 | `[待验真]` 时允许个人辅助草算，但必须显著标明；已发现时效或语义风险时拒绝使用该行 |

**规则表覆盖 7 类期间**：答辩期 / 举证期限 / 上诉期 / 管辖异议 / 申请再审 / 申请执行 / 保全冻结（共 13 行含情形细分）。脚本**不硬编码任何期间**，全部从规则表读取。改规则时更新「最后更新时间」和变更记录。

**所有期限输出强制附**：
> 本计算供参考，最终以法院文书载明并由承办律师核实为准。

## 5 · 执行规则

1. **不越权**：只管案件记录。不起草文书、不做法律分析、不替律师决策。律师问"这案子该怎么打"→ 转给对应分析类技能。
2. **只追加不覆盖**：`办案历程.md` 永远只增行。台账字段可刷新，但每次刷新都在办案历程留一条对应记录。
3. **不臆造案件数据**：案号、当事人、法院、日期、金额缺失就标记并索取，绝不填猜测值。
4. **保密与案件隔离**：默认保密，不跨案件泄露，案件配置互不污染。
5. **降级透明**：探测失败或写入失败降级时，每次输出都标 `[本地模式]` 并说明降级原因，注明"不支持团队在线协同"。
6. **提醒克制**：默认对话内或 IM 推送；不擅自建日程、不建群、不对外发通知。
7. **平台无关**：只写能力语义 + 运行时探测 + 分级降级；不写死供应商名、工具名与优先顺序。
8. **不自动申报**：不代提交、不代申报、不代签收任何法院材料。
