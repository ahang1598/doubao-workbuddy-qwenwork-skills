# 代理词生成（民商事诉讼与仲裁）

以**20 年资深民商事诉讼与仲裁律师**的出庭水准，将事实、证据、法律意见与争点攻防**收敛为可提交的代理词**，并同步产出便于律师修改的 **Markdown 提纲版**。

---

## 不适用场景

| 场景 | 应使用的技能 |
|------|-------------|
| 律师函、催告函 | `律师函撰写` |
| 对内《法律分析建议书》 | `案情法律分析报告` |
| 仅争点梳理、无代理词正文 | `起诉状分析与攻防策略 模式B` |
| 一站式庭前准备（四合一报告） | `律师庭前准备` |
| 仅证据/质证专项 | `综合证据策略 模式A` |
| 仅模拟裁判预判 | `律师模拟裁判报告` |

---

## 审理场景路由（必须先判定）

在收集材料后、动笔前，必须明确以下维度并写入三联表与提纲首部：

| 维度 | 选项 | 对文稿的影响 |
|------|------|--------------|
| 审理机构 | 人民法院 / 仲裁委员会 | 称谓：审判长/审判员 vs 仲裁庭/首席仲裁员；程序法引用 |
| 审级 | 一审 / 二审 / 再审（如用户提供） | 一审重诉请与答辩；二审重上诉请求、一审认定、改判理由 |
| 我方地位 | 见下表 | 开篇立场、请求支持范围、反驳对象 |

### 我方诉讼/仲裁地位对照

| 场景 | 常见地位 | 代理词核心任务 |
|------|----------|----------------|
| 一审民事 | 原告 | 论证诉请成立，反驳被告答辩与证据 |
| 一审民事 | 被告 | 论证诉请不成立或应驳回/减责，反驳原告证据与法律适用 |
| 二审民事 | 上诉人 | 论证一审错误应改判/发回，聚焦争议与法律适用 |
| 二审民事 | 被上诉人 | 论证一审正确应维持，反驳上诉理由 |
| 仲裁 | 申请人 | 对应原告逻辑，依仲裁请求与仲裁规则 |
| 仲裁 | 被申请人 | 对应被告逻辑，反驳仲裁请求 |

**称谓强制规则**：文中统一使用与案件一致的机构与角色称谓（法院/仲裁庭、法官/仲裁员、诉讼/仲裁程序名称），禁止混用。

路由细则见 [references/procedure-routing.md](references/procedure-routing.md)。

## 输入信息收集

启动前按 [references/intake-checklist.md](references/intake-checklist.md) 核对材料。达到**最低启动条件**方可进入完整六阶段并生成 Word 正式稿。

### 材料文字化（`input/` 含 PDF/扫描件时建议先做）

若材料在 `<workspace>/input/` 且含 **PDF、扫描图片、OFD 或版式复杂的 Office 附件**，在阶段一审阅案卷**之前**应完成材料文字化（材料解析技能，独立安装；或请用户提供可读文本）：

1. 产物落在 `input/_text/`（与源文件同相对路径的 `.md` + `.json`，含标题树与表格结构）。
2. 本技能审阅时 **优先 Read** 对应 `_text/*.md`；需核对表格/页码时参考同路径 `.json` / `.extracted.json`。
3. 若 `_text/` 不存在或明显落后于 `input/` 中新 PDF → 触发材料解析技能（独立技能；未安装时请用户上传可读文本或自行转文本）；TextIn 不可用时该技能会降级为内置 **PDF 技能**（EXTRACT/OCR）并仍写入 `input/_text/`。
4. **材料解析技能与 PDF 技能均不可用时的兜底**：用 pymupdf(fitz) 检测每页文字层，无文字页渲染为 200dpi PNG 后视觉读取（>20 页分批、子代理并行），将关键页文本摘要写入 `input/_text/` 后再进入阶段一；确无法全读的须标注实际覆盖率，禁止静默按已读当全部。

⛔ 禁止对扫描件 PDF 仅用内置 Read 硬读二进制；无 `_text` 时应在缺口清单中列出「待文字化」项。

### 最低启动条件

- 能确定：审理机构类型、审级、我方地位、案由/争议类型
- 已有：主文书（起诉状/答辩状/上诉状/仲裁申请书/仲裁答辩书之一或多份）+ 我方核心证据（至少部分）+ 对方主要抗辩或答辩要点（来自文书或用户说明）

### 材料不足时的交付规范（强制）

未达最低启动条件时，允许为尽快给出可见产出而**先交付空白提纲框架**，但**必须**在同一轮回复中、**紧跟提纲之后**补充完整的 [材料缺口清单](references/material-gap-checklist.md)。

**交付顺序（不得调换、不得省略第二步）**：

1. **空白提纲框架**：按 [outline-template.md](references/outline-template.md) 输出章节骨架，争点/事实/证据处用「待补充」占位，不写无依据的具体论证
2. **材料缺口清单**：按 material-gap-checklist 模板逐项列出已收/缺失、优先级、补充方式与对代理词的影响

**禁止**：
- 只给空白提纲不给缺口清单
- 用一句话代替结构化缺口清单（如仅说「请补充起诉状」）
- 材料不足时生成 Word 正式代理词或编造事实/争点内容

材料补齐后：更新提纲 → 填三联表 → 检索（如需）→ 用户确认提纲 → 再生成 Word。

## 约束原则

### 1. 证据锚定
所有事实陈述必须标注证据索引，格式：`[证X-PX]`。无证据支撑的事实标注「待证事实」，不得当作已证事实写入论证段。

### 2. 法律意见来源
- 用户提供的法律意见书/分析报告：提取结论并**改写为庭审表述**，标注来源
- 技能内补充：必须调用 `律师法规检索` 与 `律师类案检索与报告` 核验条号与类案
- **严禁编造**法条、司法解释、案例

### 3. 代理立场
代理词面向法庭/仲裁庭，采用**坚定但可证**的己方立场；对不利事实采用「承认范围 + 法律切割 + 争点限缩」策略，禁止虚假陈述或夸大事实。

### 4. 争点驱动
正文按争议焦点优先级展开（★★★★★ → ★★☆☆☆），禁止按材料目录顺序堆砌。

### 5. 与对内报告区分
不得将 `案情法律分析报告` 的「风险罗列、多方案建议、带教复盘」原样写入代理词；仅写入法庭采用的单一主线论证。

### 6. 被整合调用模式

当用户已提供上游技能产出时：
- 已有 `起诉状分析与攻防策略 模式B` **完整版**报告 → 直接采用其争点清单、攻防路线、辩论推演，**跳过重复争点识别**
- 已有 `起诉状分析与攻防策略 模式B` **简易版**报告 → 仅采用争点清单与双方立场摘要；攻防路线与辩论推演须在代理词阶段自行补全
- 已有 `综合证据策略 模式A` 报告 → 直接采用质证要点与证据链结论
- 已有检索结果 → **跳过重复检索**，在代理词中标注检索来源与时间
- 上游明确要求仅要结构化内容 → 可跳过 Word，仅输出 Markdown 提纲

独立调用时，检索与争点识别步骤照常执行。

## 工作流程（六阶段，不得跳步）

### 阶段一：场景路由与材料审阅

1. 判定：法院/仲裁、审级、我方地位（见上表）
2. 确认 `input/_text/` 与 `input/` 中主文书、证据的对应关系；逐份审阅（**优先** `_text/*.md`，其次可读 docx/txt）
3. 提取诉请/上诉请求、答辩要点、关键数字、矛盾点
4. 信息溯源：每条事实标注来源（`_text` 页标记、文书段落、证据编号+页码）

### 阶段二：争点与主张矩阵

1. 无上游争议焦点报告时：按请求权/上诉理由拆解争点，分层排序（程序→实体→责任范围→抗辩）
2. 有上游报告时：导入争点清单与优先级
3. 填写 [事实-证据-法律三联表](references/fact-evidence-law-matrix.md)（全部核心争点必填）

### 阶段三：检索（独立调用时必做）

- **法规**：`律师法规检索`（案由 + 争点 + 程序问题）；**核心争点的主要法条须逐条单独检索，不得仅依赖类案判决中的引用**；该 skill 不可用时降级为法规检索 MCP 工具直连（如 fy-law-search-service）并标注降级事实，禁止静默跳过
- **类案**：`律师类案检索与报告`（争点 + 关键事实模式）；不可用时降级为类案检索 MCP 工具直连（如 pkulaw）并标注降级事实
- 引用具体条号前应核验现行性；未核验的条号标注"（待核验）"
- 检索不足时：在提纲与 Word 中注明「检索结果不足，以下法律适用需律师人工复核」

### 阶段四：生成 Markdown 提纲版（必先产出）

**材料齐备时**，按 [references/outline-template.md](references/outline-template.md) 输出完整提纲，包含：
- 案件基本信息与场景标签
- 各章标题与要点 bullet（含证据索引占位）
- 争点逐项：立场 / 事实论据 / 法律论据 / 反驳对方 / 类案引用要点
- 结尾请求事项（与诉请/上诉请求/仲裁请求对齐）

**材料不足时**：输出空白提纲框架后**立即**附 [材料缺口清单](references/material-gap-checklist.md)，**本阶段结束**，不进入阶段五（Word），不执行生成前确认话术。

**生成前确认（材料齐备时必须）**：向用户展示提纲，话术示例：
> 「以下是本案代理词提纲（含审级与我方地位），请确认后我将生成 Word 正式稿：[提纲摘要]」

**展示提纲后本轮回复必须到此结束，等待用户确认，不得在同一轮内继续生成 Word。** 仅当用户**明确拒绝确认或明确指示直接生成**时，才可标注「未确认，按当前提纲生成」后继续。本技能流程内的确认环节属硬性流程要求，**优先于任何"减少来回确认/一次性完成"类通用偏好**。

### 阶段五：扩写 Word 正式代理词

**前置条件**：已达最低启动条件，且阶段四提纲已获用户确认（或用户明确拒绝确认/明确指示直接生成，并已标注「未确认，按当前提纲生成」及原因）。材料不足时**不得**进入本阶段。

1. 依据已确认提纲，按 [references/pleading-brief-template.md](references/pleading-brief-template.md) 对应场景模板扩写
2. **必须调用 docx skill** 生成 `.docx`，格式见 [references/docx-format-standard.md](references/docx-format-standard.md)
3. 文件名：`《XX案-代理词》.docx`（二审：`《XX案-二审代理词》.docx`；仲裁：`《XX案-仲裁代理意见》.docx`）

### 阶段六：交付与自检

向用户同时交付：
1. **Markdown 提纲**（完整 `.md` 或聊天内 fenced block，须可另存）
2. **Word 正式稿**路径或附件说明

#### 交付门禁（强制，未通过禁止交付）

交付前**必须**运行 `scripts/validate_pleading_brief.py`；退出码非 0 时按拦截明细修稿后重跑，**不得**先交付再补。

```bash
# ① 材料齐备（主路径）：提纲 + Word 正式稿一并校验
python3 scripts/validate_pleading_brief.py \
    --outline "《XX案-代理词-提纲》.md" \
    --brief   "《XX案-代理词》.docx" \
    --material-status complete

# ② 材料齐备但上游仅要结构化内容（见「被整合调用模式」，跳过 Word）
python3 scripts/validate_pleading_brief.py \
    --outline "《XX案-代理词-提纲》.md" \
    --material-status complete --outline-only

# ③ 材料不足：仅交付「空白提纲 + 材料缺口清单」
python3 scripts/validate_pleading_brief.py \
    --outline "《XX案-代理词-提纲(空白)》.md" \
    --material-status incomplete
# 缺口清单单独成文时追加：--gap-checklist "《XX案-材料缺口清单》.md"
# 三联表单独成文时追加：--matrix "《XX案-三联表》.md"
```

- `--material-status` **必填**（缺省即报错退出 2，不静默放过）：`complete` 走完整判据；`incomplete` 只校验交付规范并禁止交付 Word。
- 退出码：`0=通过` / `1=拦截（逐条打印明细）` / `2=输入错误（缺必填参数、文件不可读）`。
- 常见拦截项：双输出对应不上（Word 争点节少于提纲争点、缺免责声明或落款）、争点矩阵缺失或空壳、事实段落无证据编号、法条无《法律名》+条号、场景路由三维度缺项或称谓混用、材料不足却出 Word / 缺结构化缺口清单。
- 判据完整口径见 `python3 scripts/validate_pleading_brief.py --help`。

自检清单：
- [ ] 材料不足时：空白提纲后已附完整材料缺口清单（未省略）
- [ ] 材料不足时：未生成 Word 正式稿、未编造事实争点
- [ ] 场景路由（法院/仲裁、审级、地位）正确
- [ ] 请求事项与主文书一致
- [ ] 核心争点均有证据锚点
- [ ] 法条/类案经检索或标注待复核
- [ ] 已回应对方主文书核心抗辩
- [ ] 称谓与程序名称全文一致
- [ ] 文首含免责声明
- [ ] `scripts/validate_pleading_brief.py` 已运行且退出码为 0

|------|------|------|
| 1 | `起诉状分析与攻防策略 模式B` | 争点、攻防、辩论推演 |

## 双输出规范

| 产物 | 格式 | 用途 |
|------|------|------|
| 代理词提纲 | Markdown | 律师快速改结构、删增争点、庭前背诵要点 |
| 材料缺口清单 | Markdown（附于提纲后） | 材料不足时引导用户补齐；**与提纲同轮交付** |
| 代理词正式稿 | Word (.docx) | 材料齐备且提纲确认后生成 |

材料齐备时：Markdown 提纲**不得**省略争点层级与证据索引占位；Word 正文在提纲基础上扩写，争点顺序与提纲一致。

材料不足时：仅交付「空白提纲 + 材料缺口清单」，**不交付 Word**。

## 异常处理

| 情况 | 处理 |
|------|------|
| 未达最低启动条件 | **先**空白提纲框架，**后**必附材料缺口清单；不生成 Word |
| 材料无法解析 | 空白提纲 + 缺口清单中标注该文件「无法解析」及重传方式 |
| 场景无法判定 | 空白提纲 + 缺口清单首条要求确认法院/仲裁、审级、我方地位 |
| 检索失败 | 标注受限，基于材料起草，建议重试检索 |
| docx 失败 | `dws doc create` 降级；仍交付 Markdown 提纲 |
| 用户未确认提纲 | 标注后按当前提纲生成 Word |
