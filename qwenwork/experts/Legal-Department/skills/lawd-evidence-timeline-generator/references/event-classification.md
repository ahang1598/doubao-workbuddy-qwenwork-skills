# 事件分类指南

## 概述

本文档提供证据事件分类的标准方法和指导原则，帮助律师系统化地整理和分组时间线事件。

## 分类原则

### 1. 按案件发展阶段分类

最常见的分类方式，按照案件的自然发展阶段进行分组。

#### 适用场景
- 合同纠纷案件
- 建设工程案件
- 合作协议纠纷
- 买卖合同纠纷

#### 分类标准

| 阶段 | 包含事件 | 示例 |
|------|----------|------|
| **前期准备阶段** | 意向书、备忘录、尽职调查、股东会决议 | 2019年2月25日股东会决议 |
| **合同签署阶段** | 正式合同签署、补充协议、担保设定 | 2019年3月合作协议签署 |
| **履约阶段** | 付款、交付、验收、阶段性成果 | 2019年4月1日支付保证金3000万 |
| **违约阶段** | 未履行、延迟履行、质量不合格 | 2019年8月15日未取得预售许可证 |
| **催告与协商阶段** | 法务函、律师函、协商会议、催告 | 2019年8月16日法务函发出 |
| **诉讼准备阶段** | 律师委托、律师费、保险费、保全申请 | 2019年10月8日支付律师费10万 |

### 2. 按证据类型分类

根据证据的法律分类进行分组。

#### 适用场景
- 证据类型多样化的复杂案件
- 需要突出某类证据的案件

#### 分类标准

| 证据类型 | 包含事件 | 示例 |
|----------|----------|------|
| **书证** | 合同、协议、函件、凭证 | 合作协议、电子回单、法务函 |
| **物证** | 实物证据 | 产品质量不合格的产品样本 |
| **视听资料** | 录音、录像 | 协商会议录音 |
| **电子数据** | 微信聊天记录、邮件、系统日志 | 微信催款记录 |
| **证人证言** | 证人陈述 | 员工证言 |
| **鉴定意见** | 鉴定报告 | 工程质量鉴定报告 |

### 3. 按证明目的分类

根据证据要证明的案件事实进行分组。

#### 适用场景
- 争议焦点明确的案件
- 需要围绕争议点组织证据的案件

#### 分类标准

| 证明目的 | 包含事件 | 示例 |
|----------|----------|------|
| **证明合同关系成立** | 合同签署、补充协议 | 2019年3月合作协议签署 |
| **证明付款事实** | 银行转账、收据、发票 | 2019年4月1日支付保证金 |
| **证明违约事实** | 未履行、延迟履行 | 2019年8月15日未取得预售许可证 |
| **证明损失金额** | 损失计算、费用凭证 | 2019年10月8日律师费10万 |
| **证明催告行为** | 法务函、律师函、催告记录 | 2019年8月16日法务函发出 |

### 4. 按当事人分类

根据行为的主体进行分组。

#### 适用场景
- 多方当事人案件
- 需要区分各方行为的案件

#### 分类标准

| 当事人 | 包含事件 | 示例 |
|--------|----------|------|
| **甲方行为** | 甲方的履约、违约行为 | 甲方未按时支付款项 |
| **乙方行为** | 乙方的履约、违约行为 | 乙方未按时交付货物 |
| **丙方行为** | 丙方的履约、违约行为 | 丙方提供担保 |
| **共同行为** | 多方共同参与的行为 | 三方签署补充协议 |

## 分类方法选择

### 推荐策略

**优先使用"按案件发展阶段分类"**，原因：
1. 最符合律师的思维习惯
2. 最便于理解案件全貌
3. 最有利于发现证据链缺失
4. 最便于向客户或法庭展示

**特殊情况下使用其他分类**：
- 案件争议焦点非常明确 → 按证明目的分类
- 证据类型是案件关键 → 按证据类型分类
- 多方当事人责任不清 → 按当事人分类

### 混合分类

对于复杂案件，可以采用"主分类 + 子分类"的混合方式：

```
阶段一：前期准备阶段
  ├─ 按证据类型：书证
  │   ├─ 股东会决议
  │   └─ 尽职调查报告
  └─ 按证据类型：电子数据
      └─ 往来邮件

阶段二：合同签署阶段
  ├─ 按当事人：甲方行为
  │   └─ 提供合同文本
  └─ 按当事人：乙方行为
      └─ 签署合同
```

## 事件归类规则

### 1. 单一归属原则

每个事件只归入一个分组，避免重复。

**错误示例**：
```
前期准备阶段：
  - 2019年2月25日股东会决议

合同签署阶段：
  - 2019年2月25日股东会决议  ← 重复！
```

**正确示例**：
```
前期准备阶段：
  - 2019年2月25日股东会决议（为合同签署做准备）
```

### 2. 时间优先原则

当事件可能归入多个分组时，以事件发生的时间阶段为准。

**示例**：
- "2019年3月签署合作协议" → 合同签署阶段（即使也是履约的开始）
- "2019年4月支付保证金" → 履约阶段（即使合同3月已签署）

### 3. 主要目的原则

当事件具有多重目的时，以主要目的为准。

**示例**：
- "支付律师费" → 诉讼准备阶段（主要目的是诉讼准备，而非一般付款）
- "发送法务函" → 催告与协商阶段（主要目的是催告，而非一般通信）

## 时间线输出边界

本文件仅用于识别事件类型、确定时间线分组和规范事件描述。生成 Markdown 时间线时，不得根据事件分类结果额外输出“关键争议点”“证据清单”“法律分析意见”或“诉讼策略”章节。

如事件本身涉及争议、违约、时效等重要信息，只能体现在对应时间线事件的“核心摘要”或“备注”中，保持文档主线为按时间排序的事实脉络。

## 事件描述规范

### 1. 描述格式

```
{时间} + {主体} + {行为} + {关键信息}
```

**示例**：
- ✅ "2019年4月1日，乙方支付保证金3000万"
- ✅ "2019年8月16日，甲方向乙方发出法务函"
- ❌ "付款"（过于简单）
- ❌ "乙方在2019年4月1日的时候向甲方支付了保证金，金额是3000万元整"（过于冗长）

### 2. 描述长度

- 事件描述控制在 30-50 字以内
- 关键金额单独标注
- 复杂事件可分多行描述（使用 `<br>` 换行）

### 3. 主体明确

- 明确行为主体（甲方、乙方、丙方等）
- 多方共同行为标注"共同"
- 示例："甲乙丙三方共同签署补充协议"

### 4. 关键信息突出

- 金额使用加粗：**3000万**
- 截止日期使用加粗：**8月15日前**
- 违约行为使用加粗：**未取得**

## 特殊事件处理

### 1. 持续性事件

跨越多个时间段的事件：

**处理方式**：
- 在开始时间和结束时间分别记录
- 或使用时间段标注

**示例**：
```
2019年3月-2019年9月：合作期限（协议约定）
```

### 2. 条件性事件

附带条件的事件：

**处理方式**：
- 在事件描述中明确条件
- 在备注中标注条件是否成就

**示例**：
```
| 时间 | 事件 | 备注 |
|------|------|------|
| 2019-08-15 | 取得预售许可证（合同约定） | 条件未成就，实际未取得 |
```

### 3. 相对时间事件

使用相对时间描述的事件：

**处理方式**：
- 尽可能转换为绝对时间
- 无法转换的保留相对时间，并标注基准事件

**示例**：
```
| 时间 | 事件 | 备注 |
|------|------|------|
| 2019-03-28 | 签署后3日内支付保证金 | 基准：3月25日签署 |
| 2019-04-01 | 实际支付保证金3000万 | 符合"签署后3日内"约定 |
```

### 4. 时间冲突事件

不同证据对同一事件时间描述不一致：

**处理方式**：
- 同时列出多个时间
- 标注"时间存在矛盾"
- 向用户请求澄清

**示例**：
```
| 时间 | 事件 | 备注 |
|------|------|------|
| 2019-03-25 | 合作协议签署 | 证据1：P1-10 |
| 2019-03-26 | 合作协议签署 | 证据2：P15（时间存在矛盾，请用户确认） |
```

## 注意事项

1. **保持一致性**：同类事件使用相同的分类标准
2. **避免过度细分**：分组不宜过多，一般 4-8 个分组为宜
3. **逻辑清晰**：分组名称简洁明了，便于理解
4. **灵活调整**：根据案件特点调整分类，不必拘泥于标准分类
5. **用户确认**：生成时间线后，向用户确认分组是否合理
6. **可追溯性**：每个事件都能追溯到具体的证据材料
