# 企业主体信息全能查询

本技能依赖「**企业工商信息查询**」能力（企业主体定位、工商登记、股权与关联、司法涉诉与强制执行、经营异常与处罚等），**运行时探测**当前会话已启用的企业信息类连接器并按语义匹配选用，**不绑定任何数据供应商**；同时使用 **WebSearch** 作为补充数据源（裁判文书、基金备案、行业资质、新闻舆情等），补充结果须标注来源且不得顶替连接器数据。输出为「公开信息尽调预检报告」，含 13 个章节、法律分析框架和待线下核实事项清单。

> **A 档准确性要求**：本技能结论用于律师立案与合作决策，属 A 档（准确性即价值）。探测不到任何企业工商信息连接器时，**禁止编造数据、禁止照常输出完整尽调报告**，按 §1.6 降级处理。

## 不适用场景

- **类案检索** → `律师类案检索与报告`

- **合同审查** → `律师合同预审`
- **自然人信息查询**（本技能仅支持企业主体）

## 第一步：数据源能力探测（路由层）

本技能依赖「企业工商信息查询」能力。本节只写「**要什么能力 + 怎么找到它 + 找不到怎么办**」，**不指定任何供应商、不写死任何工具名**——运行时动态发现，多家可用时按匹配度选择。

> **硬红线**：本技能**不读写任何 MCP / 连接器配置文件**、**不向用户索取或代存任何访问凭据**。连接器一律由用户在「千问办公 设置 → 连接器」中自行启用。

### 1.1 所需能力语义清单

| # | 能力语义 | 一句话描述 | 用于 |
|---|---|---|---|
| ① | **企业主体定位** | 输入企业名/简称/品牌名/USCC，返回候选主体清单（企业全称、USCC、登记状态） | §3.1 入口锚定 |
| ② | **工商登记信息** | 返回法定代表人、注册资本与实缴、成立日期、核准日期、登记状态、注册地址、经营范围、曾用名、营业期限 | 报告章二 |
| ③ | **股权结构与关联穿透** | 返回股东名册、实际控制人/受益所有人、对外投资、控制企业、分支机构 | 章四 / 章五 |
| ④ | **历史与变更记录** | 返回历次工商变更（法代/股东/资本/范围/地址）的前后值与日期 | 章三 |
| ⑤ | **司法涉诉与强制执行** | 返回裁判文书/涉诉清单、立案开庭、被执行、失信、限高、终本、拍卖冻结出质、破产清算（含案号、案由、当事人身份、标的额、日期） | 章九 · 司法风险 |
| ⑥ | **经营异常与合规负面** | 返回行政处罚、经营异常、严重违法、抵押、欠税、信用评价 | 章九 · 经营风险 |
| ⑦ | **主要人员与任职** | 返回主要人员名录、职务、交叉任职、人员风险（失信/限消/被执行） | 章六 |
| ⑧ | **知识产权** | 返回专利、商标、软著等及其状态与发明人 | 章七 |
| ⑨ | **资质许可与招投标** | 返回行政许可、行业资质、中标与招标记录 | 章八 / 章十 |
| ⑩ | **风险汇总计数** | 返回风险概览统计（失信/被执行/限高/经营异常计数） | §3.0 快速核验 |

**能力分档**：

- **必需**：① ② ⑤ ⑥ —— 缺任一即视为「**工商数据未取得**」，走 §1.6 A 档降级
- **重要**：③ ④ ⑦ ⑧ ⑨ —— 缺失时对应章节标注 `该维度数据获取失败（未探测到对应能力）`，主流程继续
- **快速模式必需**：① ② ⑩ —— ⑩ 缺失时可用 ⑤ ⑥ 的原始条目自行计数

能力语义与探测关键词的完整对照见 [dimension-tool-map.md](references/dimension-tool-map.md)；三类能力划分与启用说明见 [connector-setup.md](references/connector-setup.md)。

### 1.2 探测（第一段）

调用 `qwenwork_mcp_tool_list`，keyword 逐个尝试以下关键词（覆盖能力中文名、能力英文名、同类供应商名三类；**供应商名仅作匹配关键词，不作为调用目标，不得写入报告**）：

```
企业 / 工商 / 登记 / 企业信息 / 企业信用 / 股东 / 股权 / 实控人 / 涉诉 / 诉讼 /
被执行 / 失信 / 限高 / 行政处罚 / 经营异常 / 变更 / 人员 / 高管 / 知识产权 / 资质 / 招投标 /
风险概览 / 风险汇总 / 风险总览 / 聚合 /
company / enterprise / registration / credit / shareholder / equity / judicial / litigation /
execution / penalty / abnormal / personnel / patent / trademark / qualification / bid /
risk overview / risk summary / aggregation
```

探测结果按 §1.1 能力语义清单逐项登记命中情况，形成本次运行的**能力覆盖表**（见 §1.5）。**只登记「哪些能力有、哪些没有」，不记录、不持久化任何供应商名。**

### 1.3 匹配（第二段，按语义判定，不写死工具名）

1. 在返回工具中，按**工具名或 description** 是否命中 §1.1 各项语义关键词（详表见 [dimension-tool-map.md](references/dimension-tool-map.md)「探测关键词」列）判定候选。
2. **命中后必须用 `qwenwork_mcp_tool_get` 验证**：
   - 入参 schema 支持的主体标识形式（企业名 / USCC / 企业 ID / 人员姓名），据此适配调用入参名与类型；
   - 返回 schema 是否包含该能力所需字段（见 dimension-tool-map 各维度「必需返回字段」）。
   - **返回 schema 不含所需字段的，视为该能力未命中，切换下一家候选**；不得因为工具名"看起来对"就直接调用。
3. 同一能力有多家候选时，按**匹配度**选择：① 必需返回字段齐备度 → ② 能力覆盖条目数（一家能覆盖更多能力优先，减少跨源口径冲突）→ ③ 是否支持历史区间与分页。
4. 多源数据冲突时，以工商登记类能力（②）的主体信息为锚，在报告「数据来源与局限」中说明取舍。

### 1.4 调用（第三段）

- 用 `qwenwork_mcp_tool_call` 执行；同一层级的多个维度**并行调用**。
- 首选候选调用失败（报错/超时/鉴权失败/空结构）时，**切换下一家**候选并在报告中记录切换事实。
- 每次调用只传该工具 schema 支持的参数；有分页能力时须翻页取全，避免只取首页造成计数偏低。

### 1.5 能力覆盖表与处理

| 本次运行覆盖情况 | 处理 |
|---|---|
| 必需能力 ①②⑤⑥ 全部命中 | 正常执行，按 §2 选择输出模式；缺失的「重要」能力在报告中逐项标注 |
| 必需能力齐备，部分重要能力（③④⑦⑧⑨）缺失 | 主流程继续；对应章节首行标 `该维度数据获取失败（未探测到对应能力）`，并在「数据来源与局限」写明 |
| 快速模式下 ⑩ 缺失但 ①②⑤⑥ 齐备 | 用 ⑤⑥ 原始条目自行计数，速查卡照常输出 |
| 必需能力任一缺失 / 零命中 | 走 §1.6 **A 档降级**，禁止输出完整尽调报告 |

**用户偏好**：用户可口头指定偏好后端（如"优先用司法数据更全的那家"），agent 据此调整 §1.3 的匹配优先级；**技能不硬编码任何供应商名，也不把偏好写入 memory**。

### 1.6 降级（A 档：准确性即价值，禁止硬跑）

**未探测到任何企业工商信息连接器（或必需能力 ①②⑤⑥ 缺失）时：**

1. **停止执行，禁止输出完整 13 章尽调报告**（不得输出分维度/综合风险评级、法律评价与建议等结论章节）。
2. 告知用户：

> 本技能需要「企业工商信息查询」能力（企业主体定位、工商登记、股权结构、司法涉诉与强制执行、经营异常与处罚等）。当前未探测到可用连接器，请前往 **千问办公 设置 → 连接器**，搜索并安装**企业信息类连接器**（关键词：企业信息 / 工商 / 企业信用）后重试。

3. 若用户**坚持要先看点公开情况**：使用 `WebSearch` 基于企业全称检索基本工商/风险信息，**仅**输出「公开信息摘要」，**不**输出完整尽调报告、**不**套用 [report-template.md](references/report-template.md)，且必须：
   - 头部强制标注：
     > ⚠️ 本摘要基于公开网络检索整理，**未经工商数据核验**，可能滞后或不完整，不能替代正式尽调，不得作为立案或合作决策依据。如需正式报告，请前往「千问办公 设置 → 连接器」安装企业信息类连接器。
   - **全文每一项事实与判断均标注「未核验」**；
   - 只出「已知公开信息 + 待核实事项清单」，**不出**任何风险评级、结论性判断与概率数字；
   - **禁止**空输出空手结束。

#### 声明纯化（强制）

⚠️ 公开信息摘要模式下，**严禁**在任何位置（摘要正文、免责声明、数据来源标注）出现任何**数据供应商品牌名、连接器名或具体工具名/server 名**。全部来源必须写为「公开网络检索（WebSearch）」，免责条款照实写"基于公开网络检索结果，可能滞后或不完整"。

#### 禁止事项（硬红线）

- 禁止在无工商连接器数据时照常输出完整尽调报告或任何风险评级（§6.2 门禁脚本会拦截）；
- 禁止用 WebSearch 或模型记忆顶替连接器数据后不加「未核验」标注；
- 禁止编造工商登记、股东、涉诉、被执行等任何数据；
- 禁止把"连接器缺失"当异常抛出——它是必然场景，须按上述话术处理；
- 禁止在本 SKILL、references 与报告正文中写死任何供应商 / 连接器 / server / 工具名；
- 禁止技能自行创建或修改连接器配置文件、禁止索取或代存访问凭据。

### 快速核验模式识别

以下关键词/句式触发快速模式（不区分大小写）：

- `查一下`、`帮我查`、`看看`（后接企业名，无其他维度指定）
- `怎么样`、`靠谱吗`、`靠不靠谱`、`正常吗`、`有没有问题`、`能合作吗`
- 用户仅给出企业名称，无额外需求说明

**不触发快速模式**（即使含上述词汇）：
- 用户明确要求"尽调报告"/"完整报告"/"出一份报告" → 综合报告
- 用户指定具体维度"查股东"/"查风险" → 专项输出
- 用户追问"详细查一下" → 综合报告

### 模式未明确时引导

> 请问您需要快速看一下这家公司的基本情况（一页速查卡），还是要一份完整尽调报告？

## 第三步：数据收集（执行层）

### 3.0 快速模式（仅限快速核验）

**快速模式仅查 3 个维度**，不触发 TodoWrite 执行计划门：

1. **工商基础**：调用入口搜索 → 获取工商登记信息（企业名、USCC、法代、登记状态、成立日期、注册资本/实缴）
2. **风险概览**：调用风险概览工具（description 含 risk_overview / 风险概览 / 风险汇总 / 聚合统计 / aggregation summary，**或**返回 schema 含失信/被执行/经营异常计数的聚合统计工具）获取风险汇总
3. **经营状态**：从工商信息中提取登记状态 + 从风险概览中提取失信/被执行/限高/经营异常计数

完成后直接跳至 **第六步 §6.4 快速模式输出**，不执行第四步和第五步。

---

### 3.1 搜索企业

按 [dimension-tool-map.md §入口](references/dimension-tool-map.md#入口搜索企业) 调用入口工具，取得企业标识；多候选时让用户确认。

### 3.2 按维度并行收集

**必读** [references/dimension-tool-map.md](references/dimension-tool-map.md)：含 6 个核心维度、5 个按需维度，以及每个维度的「能力语义 → 探测关键词 → 必需返回字段」对照。

#### 执行前计划（强制，综合报告/专项模式）

**必须先用 TodoWrite 把本次任务的全部核心维度列为待办**（综合尽调：8 核心维度 + 按需维度 + WebSearch 补充 + 交叉分析 + 待核实事项生成；专项：所选维度）。每完成一个维度 → 立即 mark complete；接口失败的维度同样 mark complete 并在内部状态记录"失败"。

#### 并行调用

- 综合尽调：**必须**覆盖 dimension-tool-map 中全部「核心维度」
- 各维度并行调用；单维失败不阻断其他维度

### 3.3 历史与变更数据降级

「历史与变更记录」能力（§1.1 ④）未探测到时（部分连接器的历史类能力需额外开通）：

1. 先退回「工商登记信息」能力附带的基本变更数据；
2. 仍无数据 → 跳过历史维度，报告章三首行标注 `该维度数据获取失败（未探测到历史与变更记录能力）`；
3. **不阻断**其他维度与主流程。

### 3.4 通用规则

- 调用失败 → 该维度标 `该维度数据获取失败`
- 接口成功但字段为空 → 填 `数据缺失`，不得省略整段
- 数据明显异常（注册资本为 0 等）→ 标注「数据可能存在异常，建议核实」

## 第四步：WebSearch 深度补充（执行层）

**必读** [references/websearch-sources.md](references/websearch-sources.md)：含各指定网站的搜索策略、触发条件与频次上限。

### 4.1 触发条件

WebSearch 补充**仅在综合报告模式**下执行。根据第三步连接器收集结果，按条件触发：

| 触发条件 | 动作 |
|---------|------|
| 综合报告（必做） | 新闻舆情搜索 + 信用中国查询 |
| 连接器数据发现诉讼/被执行 | 裁判文书网搜索重点案件（最多3件） |
| 股东含基金/合伙企业 | 基金业协会查备案状态 |
| 经营范围含特定行业关键词 | 对应行业监管网站查资质 |
| 核心人员疑似高校/科研机构 | 机构官网验证任职信息 |
| 连接器某维度数据缺失 | WebSearch 尝试获取替代信息 |

### 4.2 执行规则

- 单次报告 WebSearch 调用**不超过 10 次**
- 优先级排序：必做 > 高风险触发 > 中优先 > 低优先（详见 websearch-sources.md）
- 搜索失败不阻断报告生成，标注"未查询到相关公开信息"
- 所有 WebSearch 结果须在报告对应章节标注来源：`来源：{网站名称}（{域名}），检索时间：{YYYY-MM-DD}`

### 4.3 专项输出模式

专项输出（单维度查询）**不触发** WebSearch 补充，仅使用连接器数据。

## 第五步：分析处理（分析层）

**必读** [references/analysis-framework.md](references/analysis-framework.md)：含风险严重性判断标准、交叉模式定义、待核实事项触发规则。

### 5.1 风险严重性分析

对第三步+第四步收集的数据，按 analysis-framework.md 中的标准进行法律分析：

- 诉讼严重性：标的额/注册资本比、诉讼频率/公司年龄比、案由集中度
- 行政处罚严重性：重复性、近期性、类型
- 经营异常严重性：原因类型、当前是否在列、反复次数

每项风险必须输出「法律分析」和「建议」（填入报告模板对应位置）。

### 5.2 跨维度风险交叉分析

逐一检查 analysis-framework.md 中定义的 5 个模式：

1. 内部不稳定（频繁变更 + 人员流动 + 公司年轻）
2. 知识产权权属争议（发明人跨公司任职）
3. 财务困境信号（多诉讼 + 被执行 + 经营异常）
4. 系统性合规缺陷（处罚 + 异常 + 资质缺失）
5. 空壳公司嫌疑（高认缴低实缴 + 新设 + 无IP + 少人员）

匹配到的模式填入报告「风险交叉分析」表。

### 5.3 经营范围-资质匹配检查

按 analysis-framework.md §四 的匹配表，对照经营范围与已查到的资质/许可证，识别缺口。

### 5.4 生成"待线下核实事项清单"

按 analysis-framework.md §三 的触发规则，根据报告中发现的风险点自动填充「待线下核实事项清单」。

### 5.5 分维度评级 + 综合评级

按 analysis-framework.md §五 的规则，对各维度评级并汇总综合风险评级。

## 第六步：格式化输出（执行层）

### 6.1 模板与数据来源

- 专项 → [output-single-dimension.md](references/output-single-dimension.md)
- 综合 → [report-template.md](references/report-template.md)

**头部数据来源**（按实际使用填写）：

- 主要数据来源：`企业工商信息查询连接器（运行时探测所得）` —— 报告内按实际命中的**能力语义**标注（如「工商登记信息」「司法涉诉与强制执行」），**禁止**写任何供应商 / 连接器 / 工具名
- 补充数据来源：`公开网络检索（WebSearch）— 具体来源见各章节标注`
- 必填声明行：`**工商数据获取状态：** 已取得 / 未取得`（门禁脚本据此判定是否允许输出完整报告）
- 未取得时按 §1.6 只出「公开信息摘要」，使用其 ⚠️ 声明（**不得**套用综合报告模板、不得写为正式连接器来源）

### 6.2 输出完成标准（交付前自检）

#### 自审循环（强制门禁）

检查 TodoWrite 列表，若任何核心维度仍为 `pending` / `in_progress` → **禁止**生成报告，必须回到第三步补跑或显式标记 `该维度数据获取失败` 后才能继续。综合报告还须确认：WebSearch 补充已完成、交叉分析已执行、待线下核实事项已生成。

#### 综合尽调报告

| 检查项 | 要求 |
|--------|------|
| 必填章节 | 执行摘要、企业基本信息、工商变更历史、股权结构、关联企业图谱、主要人员、知识产权、行业资质、风险评估（含司法/经营/周边/交叉分析）、法律评价与建议、待线下核实事项清单、免责条款 |
| 建议章节 | 联系信息、招投标（无数据时章节保留，表内填 `数据缺失`） |
| 缺失字段 | 统一写 `数据缺失`，禁止留空或删节 |
| 维度级失败 | 对应章节首行写 `该维度数据获取失败` + 简要原因 |
| 数据来源 | 报告头部 + 「数据来源与局限」表均须填实质内容 |
| 禁止交付 | 工商数据未取得（未探测到必需能力）却输出完整尽调报告；无任何正文的空报告；报告内出现任何供应商 / 连接器 / 工具名 |

#### 脚本门禁（强制，未通过禁止交付）

综合尽调报告**交付前必须运行** `scripts/validate_dd_report.py`；退出码 `0` 才允许交付（DOCX 生成前先对 Markdown 过门禁）：

```bash
# 主路径：对 Markdown 稿过门禁（工商数据获取状态从报告声明行自动读取）
python3 scripts/validate_dd_report.py outputs/某某公司_企业尽调报告.md

# 显式声明本次运行的工商数据状态（与报告声明行交叉校验）
python3 scripts/validate_dd_report.py outputs/某某公司_企业尽调报告.md --registry-data available
python3 scripts/validate_dd_report.py outputs/某某公司_企业尽调报告.md --registry-data missing

# 复核路径：对最终 Word 成稿复核（需 python-docx）
python3 scripts/validate_dd_report.py outputs/某某公司_企业尽调报告.docx

# 查看完整用法与判据
python3 scripts/validate_dd_report.py --help
```

**退出码**：`0` = 通过，可交付；`1` = 拦截（按打印的拦截清单逐条修复后重跑）；`2` = 输入错误（文件不存在/格式不支持/为空）。

脚本硬拦截：① 模板文件（report-template.md 或其副本）当报告；② 降级/摘要态（⚠️ 公开信息摘要声明，或声明「工商数据获取状态：未取得」）却输出完整 13 章报告或风险评级结论；③ 13 个必填章节缺失；④ 全篇空壳（无任何章节含实质信息）或必需维度（企业基本信息/股权结构/主要人员/知识产权/行业资质/风险评估）整体无实质内容仍出综合评级；⑤ 报告内出现供应商名（匹配前归一化，防「天 眼 查」「**企查查**」等写法绕过）；⑥ 缺失字段留空而未写 `数据缺失`；⑦ 形态不一致：完整 13 章却声明 WebSearch-only 数据来源。带 ⚠️ 公开信息摘要强制声明的文件按摘要规则校验（免责声明 + 实质内容 + 无评级结论），合规即放行。

**禁止**：以"脚本报错"为由跳过门禁、手工改脚本判据放行、或先交付再补跑。

#### 专项输出

- 必须包含所选维度模板中的**全部字段块**；无数据字段写 `数据缺失`
- 头部须有 §4.1 数据来源一行

#### DOCX 与 Markdown 降级（三档）

| 优先级 | 路径 | 触发条件 | 命令 / 操作 |
|--------|------|---------|-------------|
| 1（首选） | **scripts/generate_docx.py** | python3 + python-docx 可用 | `python3 scripts/generate_docx.py --workspace output --file <md路径> --filename "[企业名称]_企业尽调报告.docx"` |
| 2（次选） | `docx` skill | 脚本执行失败且 `docx` skill 已注册 | 调用 `docx` skill |
| 3（兜底） | Markdown 文件 | 以上均不可用 | 写入 `outputs/[企业名称]_企业尽调报告.md`，告知用户可手动导入 Word |

**强制**：严禁 agent 自行编写 Python 代码生成 docx；必须使用预置脚本 `scripts/generate_docx.py`。脚本已内置统一排版（宋体 12pt 正文 / 黑体标题 / 1.5 倍行距 / A4 标准页边距 / 表格统一样式），无需额外指定格式参数。

**综合报告交互**：数据收集完成后，**先以 Markdown 表格预览**，并引导：生成 DOCX / 修改报告 / 补充维度。

### 6.3 文档格式规范

#### DOCX（由脚本保证）

脚本 `scripts/generate_docx.py` 已内置以下规范，无需 agent 额外干预：

- 正文：宋体 12pt（中文）+ Times New Roman 12pt（英文/数字）
- 标题：黑体，一级 22pt 居中、二级 16pt、三级 14pt、四级 12pt，全部加粗
- 行距：1.5 倍
- 页面：A4，上下 2.54cm / 左右 3.17cm
- 表格：Table Grid 样式，统一边框，表头加粗
- 禁止同层级字号/加粗混用

#### Markdown 兜底

章节顺序与命名须严格对齐 [report-template.md](references/report-template.md)，不得自行增删/重排章节。

### 6.4 快速模式输出

快速核验模式**跳过**第四步（WebSearch）和第五步（分析），直接输出速查卡。

- 输出格式：Markdown（不走 DOCX）
- 模板：[references/output-quick-card.md](references/output-quick-card.md)
- 不触发 TodoWrite 执行前计划门
- 不执行交叉分析、不生成待核实事项
- 末尾固定引导："如需完整尽调报告或专项查询，请告诉我。"

| 场景 | 处理 |
|------|------|
