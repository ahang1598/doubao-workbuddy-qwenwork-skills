# 维度 → 能力语义 → 探测关键词

执行第三步「数据收集」时**必须先阅读本文件**。本文件**不写死任何供应商或工具名**：每个维度只给出「应查能力（业务含义）」+「能力语义」+「探测关键词」，由 agent 在运行时按 `SKILL.md` §1 的三段式（探测 → 匹配 → 调用）动态选定工具。

## 通用规则

1. **先搜后查**：先用「企业主体定位」能力拿到唯一主体标识，再按维度并行调用（维度间无依赖，尽量并行）
2. **匹配顺序**：工具名或 description 命中下表「探测关键词」→ 用 `qwenwork_mcp_tool_get` 验证返回 schema 覆盖「应查能力」所需字段 → 字段不覆盖则视为该能力未命中，切换下一家候选
3. **禁止跨源口径混乱**：同一维度优先由同一连接器提供；确需跨源拼接时，以工商登记类数据的主体信息为锚，并在报告「数据来源与局限」中说明取舍
4. **失败处理**：单维度失败 → 输出中该段标 `该维度数据获取失败`，继续其他维度
5. **字段缺失**：接口成功但字段为空 → 填 `数据缺失`，**不得**省略表格行或整段
6. **能力未探测到**：该维度对应能力在本次运行的「能力覆盖表」中未命中 → 章节标 `该维度数据获取失败（未探测到对应能力）`，不得用模型记忆或未标注的网络检索结果顶替

## 入口：搜索企业

| 项目 | 内容 |
|------|------|
| 应查能力 | 输入企业名 / 简称 / 品牌名 / 统一社会信用代码，返回候选主体清单（企业全称、USCC、登记状态） |
| 能力语义 | **企业主体定位**（必需） |
| 探测关键词 | 搜索、模糊搜索、企业搜索、企业查询、关键词、search、query、fuzzy、company search |
| 提取标识 | 连接器返回的主体标识（企业 ID / USCC / 企业全称，按其 schema 实际字段取用） |
| schema 验证 | 返回中须含企业全称 + 可用于后续维度调用的主体标识；否则换下一家候选 |

多条候选时展示列表让用户确认目标企业；确认后的主体标识贯穿后续所有维度调用。

## WebSearch 补充层（第四步）

连接器数据收集完成后，按条件触发 WebSearch 深度补充。详见 [websearch-sources.md](websearch-sources.md)。

> **定位约束**：WebSearch 是**补充**层，不得顶替工商连接器数据。凡由 WebSearch 得到的事实，报告中须标注来源网站与检索时间，且不得作为风险评级的唯一依据。

| 用途 | 搜索目标 | 触发条件 |
|------|---------|---------|
| 新闻舆情 | 企业相关负面新闻 | 综合报告必做 |
| 信用记录 | 信用中国公示信息 | 综合报告必做 |
| 裁判文书 | 重点案件判决详情 | 发现诉讼记录时 |
| 基金备案 | 私募基金备案状态 | 股东为基金/合伙企业时 |
| 行业资质 | 行业监管网站验证 | 经营范围含特定行业时 |
| 人员背景 | 高校/科研机构验证 | 人员疑似高校/科研人员时 |
| 专利详情 | 法律状态补充 | 核心发明专利需确认时 |
