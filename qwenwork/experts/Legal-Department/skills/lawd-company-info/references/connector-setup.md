# 企业工商信息查询能力：连接器启用说明

本技能**不绑定任何数据供应商**，只声明所需的**能力语义**；运行时由 agent 探测当前会话已启用的连接器，按语义匹配自动选用。本文说明：需要哪三类能力、如何在千问办公里启用、未启用时会发生什么。

> **本技能不做的事**：不读写任何 MCP 配置文件、不向用户索取或代存任何凭据、不代替用户开通第三方账号。连接器一律由用户在平台侧启用。

---

## 一、需要哪三类能力

| 能力类 | 语义 | 覆盖的报告章节 | 档位 |
|--------|------|----------------|------|
| **A. 主体与工商登记类** | 输入企业名/简称/统一社会信用代码，返回候选主体清单；返回工商登记信息（法定代表人、注册资本与实缴、成立日期、登记状态、注册地址、经营范围、曾用名）、历次工商变更记录、股东名册与实际控制人、对外投资与分支机构 | 章二 企业基本信息 / 章三 工商变更历史 / 章四 股权结构 / 章五 关联企业图谱 / 章六 主要人员 | **必需** |
| **B. 司法与经营风险类** | 返回裁判文书与涉诉清单、立案与开庭、被执行、失信被执行、限制高消费、终本、拍卖冻结出质、破产清算；返回行政处罚、经营异常、严重违法、抵押与信用评价；返回风险汇总计数 | 章九 风险评估（司法风险 / 经营风险 / 周边风险） | **必需** |
| **C. 经营扩展类** | 返回专利/商标/软著等知识产权，行政许可与行业资质，招投标与中标记录，融资与舆情，财务与上市数据 | 章七 知识产权 / 章八 行业资质 / 章十 招投标记录 | **重要（缺失可降级标注）** |

**判定口径**：A 类或 B 类任一未探测到 → 视为「工商数据未取得」，按 `SKILL.md` §1.6 走 A 档降级，**不得输出完整 13 章尽调报告**。C 类缺失 → 对应章节标注 `该维度数据获取失败（未探测到对应能力）`，主流程继续。

---

## 二、如何启用

1. 打开 **千问办公 → 设置 → 连接器**；
2. 搜索**企业信息类连接器**（关键词可用：企业信息、工商、企业信用、企业查询、company、enterprise、credit）；
3. 平台上架的企业工商数据类连接器通常不止一家，**任选一家或多家启用即可**——本技能按能力语义匹配，不要求特定某家；
   - 若只启用一家而其覆盖能力有限（例如只有 A 类没有 B 类），报告中风险章节会被标注为未取得，建议再启用一家补齐；
4. 启用后返回会话，直接重试查询即可，**无需重启客户端**；agent 会重新探测工具列表。

**多家同时启用时**：agent 按匹配度自动择优（必需返回字段齐备度 → 能力覆盖条目数 → 是否支持历史区间与分页），首选调用失败时自动切换下一家，并在报告「数据来源与局限」中记录切换事实。用户可口头表达偏好（如"优先用覆盖司法数据更全的那家"），agent 据此调整匹配优先级，但技能本身不记录、不硬编码任何供应商名。

---

## 三、未启用时会发生什么

| 情形 | 结果 |
|------|------|
| 一个企业信息类连接器都没有 | **停止出具正式尽调报告**。提示用户前往「千问办公 设置 → 连接器」安装企业信息类连接器后重试 |
| 用户坚持要先看点东西 | 仅输出「公开信息摘要」：基于 WebSearch 的公开检索结果，头部强制 ⚠️ 声明、全文标注「未核验」、**不出**任何风险评级与结论章节、不套用 13 章报告模板 |
| 部分能力缺失（如只缺 C 类） | 主流程继续，缺失维度章节标注 `该维度数据获取失败`，并在「数据来源与局限」写明缺失原因 |

**声明纯化（强制）**：无论正式报告还是公开信息摘要，正文、来源标注、免责条款中**一律不得出现任何数据供应商品牌名或具体工具名/server 名**。来源统一写为「企业工商信息查询连接器（运行时探测）」或「公开网络检索（WebSearch）」。交付前由 `scripts/validate_dd_report.py` 硬门禁校验，出现供应商名即拦截。

## 四、能力自检速查

探测完成后，用下表自检本次运行的能力覆盖情况（对应 `SKILL.md` §1.5 能力覆盖表）：

- [ ] 能拿到候选主体清单并锚定唯一主体（A 类入口）
- [ ] 能拿到工商登记核心字段（A 类）
- [ ] 能拿到涉诉 / 被执行 / 失信 / 经营异常 / 行政处罚（B 类）
- [ ] 能拿到股东与实际控制人（A 类）
- [ ] 能拿到知识产权 / 资质许可 / 招投标（C 类，缺失可降级）

前三项任一为否 → 走 A 档降级，禁止出完整报告。
