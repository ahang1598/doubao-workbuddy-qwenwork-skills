# 数据连接器探测与字段映射指南

## 概述

本 Skill 通过两类**能力**获取权威数据，不绑定任何具体连接器或工具名：

- **法规检索能力**：检索法律法规条文（法智 flfg 系列、北大法宝 pkulaw、元典 yuandian 等均提供该能力）
- **案例检索能力**：检索司法案例（北大法宝 pkulaw、元典 yuandian 等提供该能力；注意并非所有法规检索供应商都有案例检索能力）

运行时按下方「三段式探测」流程决定实际调用哪家连接器。MCP 工具由 Agent 运行时直接调用，无需通过 Bash CLI。

## 一、三段式探测流程

### 1.1 探测

调用 `qwenwork_mcp_tool_list`，keyword 逐个尝试以下关键词（覆盖能力中英文表述与供应商标识，不预设优先顺序，运行时按匹配度选）：

- **法规检索能力**：`法规 / 法条 / 法律法规 / fatiao / law / article / statute / regulation / flfg / pkulaw / fabao / 北大法宝 / yuandian / 元典 / 法智`
- **案例检索能力**：`案例 / 司法案例 / 案号 / 裁判文书 / case / judgment / pkulaw / fabao / 北大法宝 / yuandian / 元典`

### 1.2 匹配（按工具语义判定，不写死任何工具名）

- 在返回工具中，匹配工具名或 description 含「法规检索」「法条检索」「statute/law search」「article」等语义的工具（法规检索能力），或含「案例检索」「案件查询」「case search」「案例详情」等语义的工具（案例检索能力）；
- **必须**对候选工具调用 `qwenwork_mcp_tool_get` 取回参数 schema 并验证后，才能发起调用；不得凭工具名或本文示例猜测入参名与类型；
- 依据 schema 适配入参，**只传该工具 schema 支持的参数**，schema 未定义的参数一律不传。

### 1.3 调用

用 `qwenwork_mcp_tool_call` 执行；多家连接器可用时按探测命中顺序依次尝试，首选调用失败（报错/超时/鉴权失败）时切换下一家。

### 1.4 探测不到时的降级（strict）

- **停止执行**，并告知用户："本技能需要「法规检索」/「案例检索」能力，请前往千问办公 设置 → 连接器，搜索并启用相应连接器后重试。"
- 不硬跑：**禁止**用 WebSearch 或模型记忆编造法条原文、案例信息替代权威检索。

## 二、法规检索连接器

### 2.1 入参构造策略

常见入参语义（实际参数名与结构以 `qwenwork_mcp_tool_get` 返回的 schema 为准）：

| 入参语义 | 说明 |
|---------|------|
| 检索文本（必传） | 法规名 + 条号关键词，或结构化对象的子字段（法规名/条号/内容关键词） |
| 条数 / 分页 | 工具支持时传入；不支持时取全部返回本地处理 |
| 排序 | 工具支持时按相关度排序；不支持时保持返回顺序 |
| 时效性过滤 | 默认不传（见 2.5 status 默认值覆盖） |

**Query 构造规则**（扁平检索文本型工具）：

| 输入 | query 构造 | 示例 |
|------|-----------|------|
| 法规全称 + 条号 | 法规简称 + 条号 + 核心关键词 | "民法典 第五百七十七条 违约责任" |
| 仅法规简称 + 条号 | 法规简称 + 条号 | "劳动合同法 第四十七条" |
| 法规名 + 条款项 | 法规简称 + 条号 + 款项 | "民法典 第五百六十三条 第一款" |

**query 长度控制**：15-30 字。过短匹配不精确，过长引入噪音（语义检索类工具例外，可传自然语言长句，以 schema 说明为准）。

### 2.2 常见字段映射（法规检索连接器）

不同连接器返回字段名不同，先用 `qwenwork_mcp_tool_get` 与首次调用返回确认实际字段，再映射到本 Skill 的校对语义字段。下表以法智 flfg 系列工具（`flfg_parallel_search_tool` 多路并发 / `flfg_iterative_search_tool` 单条迭代，入参为 `title`/`item`/`content`/`status`）为常见示例：

| 校对语义字段 | 常见对应字段 | 差异与适配规则 |
|-------------|-------------|---------------|
| 法规名称 | `lawName` / `title` | 语义一致 |
| 条款编号 | `lawOrder` / `item` | 语义一致 |
| 条文原文 | `lawSourceContent` / `content` | 语义一致，**核心校对字段** |
| 时效性 | `timeliness` / `status` | 语义一致（现行有效/已被修改等），枚举文本各家不同，照录原文 |
| 匹配度 | `similarity`（0-1 百分比）/ `score`（无固定上限的匹配分，实测常见 40-250+） | **score 不可直接换算为百分比**。报告中如实展示原始值，并标注"本工具返回 score 匹配分，非 similarity 百分比"（见 2.6） |
| 施行日期 | `implementYearMonthDate` / 实际服务可能不返回 | 连接器未返回的字段一律标注"⚠️ 数据源未返回，请人工核实"，**严禁用模型知识填充**（违反反幻觉规则 AH-1） |
| 效力级别 | `potencyLevel` / 可能不返回 | 同上，未返回即标注，可选展示 |
| 发布日期 | `releaseYearMonthDate` / 可能不返回 | 同上，辅助判断（可选展示） |

### 2.3 结果匹配策略

连接器可能返回多条结果，需从中选择最匹配的一条：

1. **精确匹配**：法规名称字段包含目标法规名 AND 条款编号字段与目标条号一致 → 直接采用
2. **近似匹配**：法规名匹配但条号略有差异（如中文数字 vs 阿拉伯数字）→ 采用 + 标注
3. **最高匹配度**：无精确匹配时，取匹配度（similarity/score）最高的结果 → 采用 + 标注"匹配置信度"
4. **无匹配**：所有结果的 similarity < 0.3（或 score 明显偏低）或法规名完全不匹配 → 判定为 🔍 未找到

### 2.4 重试策略

每条法条引用最多检索 2 次：

| 次数 | Query 策略 | 触发条件 |
|------|-----------|---------|
| 第 1 次 | 法规名 + 条号（如"民法典 第五百七十七条"） | 默认 |
| 第 2 次 | 法规名 + 核心关键词（如"民法典 违约责任 继续履行"） | 第 1 次无结果或匹配度偏低 |

### 2.5 status 时效性参数默认值覆盖

- 连接器的时效性入参（如 `status`）可能自带默认值（如默认"现行有效"）。需要完整时效性光谱（含已废止/已修改版本）时，**主动传空字符串 `status=""` 覆盖默认值**；确不可关闭时在报告中声明"本次数据源默认仅返回现行有效法规"。

### 2.6 score 置信度标注规则（对应 AH-6）

- score 明显低于同组最高分（如不足最高分的 50%）时，标注"⚠️ 匹配置信度较低（score: X），建议人工复核"
- 报告基本信息表的"匹配度"栏写 `score X（匹配分，非相似度百分比）`，避免用户误解

## 三、案例检索连接器

### 3.1 Query 构造策略

**案例校验的核心是案号精确匹配**，因此 query 策略与法条不同：

| 次数 | Query 策略 | 示例 |
|------|-----------|------|
| 第 1 次 | 直接使用完整案号 | "(2023)京01民终5678号" |
| 第 2 次 | 案号核心部分 + 案由关键词 | "京01民终5678 买卖合同" |

### 3.2 常见字段映射（案例检索连接器）

案例检索连接器（如北大法宝 `search_case`、元典案例工具 `yuandian_rh_case_details` 等）返回结构各家不一，**以实际探测到的工具返回为准**：先用 `qwenwork_mcp_tool_get` 与首次调用返回确认实际字段，再按语义映射到下列校对语义字段。

| 校对语义字段 | 校对用途 | 报告中的位置 | 适配规则 |
|-------------|---------|-------------|---------|
| 案号（`caseNo` 语义） | 案号精确匹配 | 基本信息 - 权威案号 | 比对时忽略全角/半角括号与空白差异 |
| 案由（`caseCause` 语义） | 核对案件类型 | 基本信息 - 案由 | 照录原文 |
| 审理法院（`trialCourt` 语义） | 核对法院 | 基本信息 - 审理法院 | 可能为对象（含 name 子字段）或字符串，均取法院名称 |
| 裁判日期（`trialDate` 语义） | 核对裁判时间 | 基本信息 - 裁判日期 | 日期格式各家不一（YYYY-MM-DD / YYYY年MM月DD日），照录原文 |
| 裁判结果（`verdict` 语义） | 核心比对字段 | 文本对比 - 权威裁判要旨 | 未返回时标注"数据源未返回"，严禁模型知识填充 |
| 裁判理由（`judgReason` 语义） | 补充比对 | 文本对比 - 权威裁判要旨（补充） | 同上 |
| 争议焦点 / 法律依据 | 辅助校对 | 可选展示 | 未返回即省略 |
| 参考级别（`referLevel` 语义） | 辅助判断 | 基本信息 - 参考级别 | 未返回即标注"未提供" |
| 匹配度（`similarity` / `score` 语义） | 置信度判断 | 基本信息 - 匹配度 | score 类匹配分按 2.6 规则标注 |

### 3.3 结果匹配策略

1. **案号精确匹配**：案号与目标案号一致（忽略全角/半角括号差异）→ 直接采用
2. **案号近似匹配**：案号核心部分一致（年份 + 法院代字 + 序号相同）→ 采用 + 标注
3. **无匹配**：无任何案号相似的结果 → 判定为 🔍 未找到

## 四、检索组合策略与张冠李戴交叉验证

| 场景 | 策略 |
|------|------|
| 条号准确、内容已知 | 法规名 + 条号 + 内容关键词组合检索 |
| 不确定条号准确性 | 先仅用条号检索（取该条号真实内容）或仅用关键词检索（找近似条文），**避免条号+关键词组合互相干扰导致零结果** |
| 重试命中了不同条号（疑似张冠李戴） | 见 SKILL.md 重试策略中的"张冠李戴交叉验证"：允许追加 1 次目标条号真实内容检索用于交叉比对，该次不计入常规重试上限 |

## 五、错误处理

### 5.1 连接器服务级错误

| 错误类型 | 处理方式 |
|---------|---------|
| 连接超时 | 重试 1 次；仍失败则切换下一家已探测到的连接器；全部失败标注"未能验证（连接超时）" |
| 认证失败 | 切换下一家连接器；全部失败标注"未能验证（认证失败，请检查连接器配置）" |
| 服务端错误（5xx） | 重试 1 次；仍失败则切换下一家；全部失败标注"未能验证（服务异常）" |
| 响应格式异常 | 标注"未能验证（响应异常）" |

### 5.2 业务级异常

| 异常情况 | 处理方式 |
|---------|---------|
| 返回结果为空 | 进入重试策略；重试后仍为空则判定 🔍 未找到 |
| 匹配度极低（similarity < 0.3 或 score 明显偏低） | 视同无匹配，判定 🔍 未找到 |
| 匹配度偏低（similarity 0.3-0.6 或 score 明显低于同组最高分） | 采用该结果但标注"匹配置信度较低，建议人工复核" |
| 返回多条高相似度结果 | 取法规名/案号最匹配的一条；有歧义时展示候选列表供用户选择 |

## 六、性能建议

- 条数入参建议设小（法条校对不需要大量结果，精确匹配即可，如 5 条；案号检索通常第一条就是精确匹配，如 3 条）；工具无条数入参时取全部返回本地截取
- 避免在 query 中包含过长的法条原文（query 建议 15-30 字）
