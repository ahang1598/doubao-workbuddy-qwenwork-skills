# 律师庭前准备

> 本技能为「律师办案助手」套件单元 7，由「庭前准备整合助手」与「律师庭审发问策略」合并而成：对外一个入口，内部按用户意图分流到模式A / 模式B。
> 本单元同时是套件内唯一的**编排器**：模式A 需要跨技能调度其他单元的特定模式，接线关系见 §3.1.1，务必按表指定模式，不得指向已被合并的旧技能目录。

---

## 一、能力总述

本技能融合 **20 年资深民商事诉讼律师**与 **20 年资深员额法官**的双重视角，覆盖开庭前的两类需求：

- **模式A 完整庭前准备报告**：一站式庭前准备。先做客户沟通与材料收集、诉讼文书质量审查，再**集中做一次法律检索**，然后编排「证据分析 + 争议焦点分析 + 庭审发问策略 + 模拟裁判」四项子工作，叠加对方代理人全景模拟与客户辅导，去重整合为一份可交付的《庭前准备报告》（.docx）。
- **模式B 庭审发问策略**：单独交付发问能力。既精通律师向对方发问的攻击技巧，又深谙法官（仲裁案件为仲裁员）发问的审查逻辑，产出向对方发问设计、法官发问预判与应答准备、禁止发问清单，交付《庭审发问策略报告》（.docx）。

| 模式 | 名称 | 解决什么问题 | 前身 |
|---|---|---|---|
| 模式A | **完整庭前准备报告** | 开庭前所有准备工作一次做完，四项子分析统一编排、去重整合 | `律师庭前准备`（编排器主体） |
| 模式B | **庭审发问策略** | 只要发问提纲/交叉询问/应答准备 | `lawd-civlit-courtroom-questioning`（旧中文名「庭审发问策略」，已吸收） |

共同底线：**不编造法条、不虚构案例**；所有事实引用标注证据索引可溯源；未取得检索结果时不得罗列法条或案号（见 §四）。本报告用于开庭，属"准确性即价值"的 A 档场景。

## 二、触发与分流

### 2.1 用户意图 → 模式 路由表

| 用户意图 / 典型指令 | 关键词 | 路由 |
|---|---|---|
| "下周开庭帮我准备"、"帮我做庭前准备"、"全面准备一下这个案子" | 庭审准备 / 庭前准备 / 开庭准备 / 准备开庭 / 马上开庭 / 全面准备 | **模式A** |
| "出一份庭前准备报告"、"庭前分析"、"庭审材料准备" | 庭审准备报告 / 庭前分析 / 开庭前准备 / 庭审材料准备 / 诉讼准备 | **模式A** |
| "给我一份庭前清单"、"庭前 Checklist" | 庭前清单 / 庭前 Checklist / 一站式庭前 | **模式A** |
| "怎么问对方"、"帮我设计庭审发问"、"出个发问提纲" | 庭审发问 / 发问策略 / 发问提纲 / 发问设计 / 怎么问对方 / 庭审怎么问 | **模式B** |
| "交叉询问怎么做"、"庭审问答准备"、"质询要点" | 交叉询问 / 询问策略 / 问话设计 / 庭审问答 / 质询 | **模式B** |
| "法官会问什么我怎么答"、"帮我准备应答" | 应答准备 / 发问准备 / 法官发问预判 | **模式B** |

**分流判定纪律**：

1. 用户要的是**开庭前的全套准备** → 模式A；用户要的**只有问答环节** → 模式B。
2. **模式A 内部已自动产出发问章节**（编排第 3 项，见 §3.1.1）。因此：
   - 用户已经走过模式A、事后又说"再给我一份发问提纲"→ **不重跑模式B 全流程**，直接把模式A 已生成的发问子产物扩写为独立《庭审发问策略报告》，复用同一份检索结果与案件材料，避免重复劳动；
   - 用户一开始只说"怎么问对方"→ 直接走模式B，不启动模式A 的四项编排。
3. 意图含糊（如"帮我看看这个案子开庭的事"）→ **先问一句**："您是要（1）完整庭前准备（证据 + 争点 + 发问 + 裁判预判，出一份庭前准备报告），还是（2）只要庭审发问策略？" 用户不回复时按材料判断：材料齐备（起诉状 + 答辩状 + 双方证据）→ 模式A；仅有零散材料且明确提到"问"→ 模式B。
4. **禁止**在同一次交付里混用两套报告模板（模式A 的《庭前准备报告》 vs 模式B 的《庭审发问策略报告》）。两者都要时分别成文。

## 三、模式工作流

### 3.0 两模式共用：信息收集与材料审查

#### 3.0.1 执行状态管理

| 阶段 | 状态 | 进入条件 | 完成标志 |
|------|------|----------|----------|
| 意图判定 | `ROUTING` | 技能触发 | 模式已确定（模式A / 模式B） |
| 信息收集 | `COLLECTING` | 模式确定 | 核心材料齐备 |
| 文书审查 | `REVIEWING` | 信息收集完成（模式A） | 诉讼文书审查完毕 |
| 集中检索 | `SEARCHING` | 文书审查完成 | 检索全部完成（一次性） |
| 子能力编排 | `ANALYZING` | 检索完成（模式A） | 四项子产物全部落盘 |
| 对方模拟 | `SIMULATING` | 子能力完成（模式A） | 对方策略模拟完成 |
| 门禁校验 | `VALIDATING` | 分析完成 | `check_sub_outputs.py` 退出码为 0 |
| 报告生成 | `GENERATING` | 门禁通过且用户确认大纲 | Word 文档生成成功 |

#### 3.0.2 客户沟通信息（模式A 强制，模式B 按需）

**必须识别和确认的信息**：

- **核心经济利益**：当事人诉讼的真实经济目标是什么？（可能不等于诉讼请求）
- **案外商业目的**：是否存在诉讼之外的商业考量？（如施压谈判、阻止对方行为、维护商誉等）
- **诉讼成本承受力**：评估当事人可提供的诉讼成本（鉴定费、调查费、律师费等）
- **社会资源支持**：当事人可调动的资源情况
- **调解意愿**：是否愿意调解？可接受的调解方案？心理底线？调解策略偏好？
- **预期管理**：客观告知案件难度和可能结果范围，管理当事人合理预期

**信息收集是庭前准备的首要任务，必须在任何分析之前完成。** — 信息收集不充分时进行分析，会导致遗漏关键争议点，后续修正成本极高。

**弹性执行（材料齐全场景）**：用户已提供完整诉讼文书与证据材料时，客户沟通可简化为**确认 3 个关键假设**——①核心经济目标 ②调解意愿 ③诉讼成本承受力，须显式向用户提出并等待回应；用户未回应的，在报告开头标注"客户沟通未完成，以下分析基于材料推断，策略偏好相关结论请人工复核"，不得静默跳过。

#### 3.0.3 案件材料收集

**诉讼文书材料**：起诉状/仲裁申请书/上诉状（了解诉讼请求和事实理由）、答辩状（了解对方抗辩主张）、反诉状（如有）、代理词（如有）

**证据材料**：己方证据清单及证据材料、对方证据清单及证据材料、法院调取的证据（如有）

**案件基本信息**：案由、审理法院/仲裁机构、审级、案号、开庭时间（如已确定）、我方诉讼地位（原告/被告/第三人；仲裁中为申请人/被申请人）

**程序节点信息**：管辖异议期截止日（如未过期限）、答辩期截止日、举证期限截止日、各项程序性申请的时限要求、其他重要程序节点（如开庭日期等）

**模式B 的信息分层**（单独调用模式B 时按此收集）：

- **必要信息**：案由、诉讼地位（原告/被告/第三人）、审理阶段（一审/二审/再审）、核心争议焦点、现有证据清单
- **重要信息**：案件基本事实（交易背景、履行过程、纠纷起因）、对方当事人/证人信息、法官信息（如已知）（仲裁案件为仲裁员信息）
- **补充信息**：既往庭审情况（二审/再审）、对方可能策略

如信息不足，主动询问用户补充；如用户提供了起诉状/仲裁申请书、答辩状、证据材料等文件，优先读取分析。

#### 3.0.4 材料深度分析原则

**强制要求：对用户提供的所有材料和信息，必须进行深度分析、充分捕捉、完整保留细节。**

- **逐页逐段审阅**：不得跳过或忽略任何材料内容，包括附件、备注、落款、日期等细节
- **关键数字复核**：所有金额、日期、期限、面积、数量等数字必须精确提取和交叉验证，逐项执行：①诉称/主张金额 vs 凭证逐笔加总 ②退费、已还款是否已从诉请金额中扣减 ③同一金额跨证据一致性 ④差异必须标注并给出可能原因，禁止静默取其一
- **矛盾点捕捉**：主动识别不同材料之间、同一材料前后、当事人陈述与证据之间的矛盾和不一致
- **隐含信息挖掘**：从材料字里行间挖掘隐含的事实信息（如合同条款的默示含义、通信记录的言外之意）
- **细节保留**：即使看似次要的细节（如证据的形成时间、签字人身份、证据载体形式），也必须保留并在分析中体现
- **信息溯源**：每一个提取的事实都必须标注其信息来源（证据编号+页码、当事人陈述、诉讼文书等）

**扫描件 PDF 处理流程（强制）**：用 pymupdf(fitz) 检测每页文字层 → 无文字页渲染 200dpi PNG 视觉读取 → >20 页分批（每批 ≤20 页）子代理并行 → 全部读完才能进入分析；确无法全读的须标注实际覆盖率与受限原因，禁止静默按已读当全部。

材料不齐全时，向用户发出补充材料提示，说明缺失材料对分析质量的影响。**对于现有证据无法完整反映的关键事实或者之前忽略或存在断层的事实细节，及时询问当事人。**

## 四、数据源

### 4.1 检索依赖：通过兄弟技能获得，本技能不直接调用外部数据连接器

本技能的法律检索能力**全部通过调用兄弟技能获得**，不在本 SKILL 内直接探测或调用法律数据连接器（连接器探测、多家优先级与降级由被调技能自身按《SKILL 连接器写法指南》三铁律负责）：

| 需要的能力 | 调用对象 | 何时调用 |
|---|---|---|
| 类案裁判规则（同类案件裁判尺度、证据认定口径） | `律师类案检索与报告` skill | 模式A 第三步集中检索；模式B 独立调用时的分析前置 |
| 法条与司法解释（实体法要件、证据与程序规则） | `律师法规检索` skill | 同上 |

**文档生成**：`docx` skill 为首选；不可用时降级 `dws doc create`（钉钉文档）。这不是法律检索命令，不受连接器改造影响。

### 4.2 集中检索一次 + 全局复用（编排器的核心约定，必须遵守）

**为什么必须集中**：四项子工作各自都具备调用类案检索与法规检索的能力。若不加管控，同一案件会被重复检索四遍——既慢、又重复计费、且各子产物可能引用互相矛盾的检索结果。因此**模式A 由本单元集中做一次检索，结果打包复用**。

#### 检索方案（模式A 第三步执行）

**基本检索**（所有案件必须执行，共 4 次）：

**类案检索**（调用 `律师类案检索与报告`）：

1. **证据与争议焦点角度**：query 包含案由 + 核心事实争议 + 关键证据类型 + 证据认定规则
2. **裁判预判与发问角度**：query 包含案由 + 核心事实争议 + 法律适用争议 + 裁判要旨 + 同类案件裁判结果

**法规检索**（调用 `律师法规检索`）：

1. **实体法**：query 包含案由相关实体法条 + 构成要件 + 法律效果
2. **证据与程序法**：query 包含举证责任分配 + 证据规则 + 证明标准

**追加检索**（根据案件情况判断是否需要）：

- 涉及多个法律关系的，每个法律关系单独检索
- 争议焦点涉及法律适用分歧的，针对分歧问题追加检索
- 基本检索结果不充分的，调整关键词追加检索
- 每次追加检索前评估必要性，避免无效检索

#### 统一检索结果包与"跳过重复检索"的显式传入（硬约束）

集中检索完成后，将结果整理为**统一检索结果包**（类案：案号 / 法院 / 裁判要旨 / 证据采信要点；法规：法律名称 + 年份版本 + 条款号 + 条文内容），随每次子能力调用**显式传入**，并在指令中明确要求跳过重复检索：

| 子能力 | 目标技能与模式 | 该技能的复用机制（已核实保留） | 编排时必须写明 |
|---|---|---|---|
| 争议焦点分析 | `起诉状分析与攻防策略` 模式B | 「被整合调用模式」：上游已提供检索结果则不再调用检索技能 | "由 `律师庭前准备` 整合调用，检索结果如下，禁止重复调用 `律师类案检索与报告` / `律师法规检索`" |
| 证据分析 | `综合证据策略` 模式A | 同上（其模式A 约束原则第 8 项「被整合调用模式」） | 同上 |
| 庭审发问策略 | **本技能内部模式B** | §3.2 B.6 第 9 项：复用上游统一检索结果包 | 内部执行，直接引用同一结果包，不新发检索 |
| 模拟裁判 | `律师模拟裁判报告` | 其「被整合调用模式」：跳过检索 | 同第一行 |

**纪律**：

1. 模式A 全流程**检索总次数 = 基本 4 次 + 必要的追加次数**，四项子工作**不得**各自新发检索。
2. 若某项子工作反馈"检索结果不覆盖其分析需要"，由**本单元**发起追加检索并把结果补入结果包后再回传，仍不允许子能力自行检索。
3. 模式B 独立调用时，由模式B 自行完成一次检索（无上游结果包），检索方案取上表"发问角度"一路即可。

### 4.3 检索失败与结果不足的分级降级（A 档，不得降级编造）

《庭前准备报告》直接用于开庭，属"准确性即价值"的 **A 档**场景。因此：

| 情形 | 处理 |
|---|---|
| 检索返回**空结果 / 结果明显不足** | 在统一检索结果包中标注"检索结果不足"并随调用传下去；各子能力仍可基于案件材料做基础分析，但相关章节必须标注**"未取得检索支撑，分析深度受限"**；建议用户调整关键词重试或在报告完成后单独运行检索模块补充 |
| 检索技能**调用失败 / 服务不可用** | 告知用户"检索服务暂时不可用"；报告顶部加显著提示"本报告部分内容未经检索验证"，并逐处标注受影响结论为**"未取得检索支撑"**；不中断编排 |
| 部分成功（如类案有、法规无） | 按维度分别标注，不把已取得的一路结果冒充另一路 |

**门禁语义（硬约束，两模式均适用）**：

1. **未取得检索结果时，不得罗列法条** — 正文不得出现未经检索核验的法条清单或条文引用块；确需提及法律依据时只能写"相关法律规定（未取得检索支撑，待律师核实）"。
2. **未取得检索结果时，不得虚构案例** — 严禁编造案件名称、案号、法院、裁判人员、裁判日期或裁判要旨；相关章节写明"未取得类案检索支撑"。
3. **不得用 WebSearch 或模型内置知识冒充检索结果** — 只允许标注降级，不允许无标注兜底。
4. **不得静默编造** — 任何因检索缺失而降低确定性的结论，必须在该结论处就地标注，不允许只在文末一句话免责了事。
5. 违反上述任一条等同交付事故。

## 五、门禁脚本

### 5.1 交付前必须运行

**生成《庭前准备报告》前必须运行本脚本，未通过禁止交付。** 脚本对四项子产物做齐全性与非空性硬校验，缺一即以非零退出码阻断；必须先补齐或重跑缺失的子工作，通过后才能进入 Word 生成与交付环节。

```bash
# 完整报告模式：要求 4 份子产物齐全且非空
python3 scripts/check_sub_outputs.py --mode full --dir <子产物目录>

# 单项模式：只校验对应 1 份
python3 scripts/check_sub_outputs.py --mode single --skill questioning --dir <子产物目录>

# 查看帮助与可用子产物名
python3 scripts/check_sub_outputs.py --help
```

脚本路径：[scripts/check_sub_outputs.py](scripts/check_sub_outputs.py)

### 5.2 四份子产物与识别口径

脚本以**内容级识别**为主、**文件名**为辅归属子产物（文件名仅辅助定位，不单独构成通过依据）。为保证识别稳定，编排时**必须**按下表命名中间文件（推荐统一落在 `outputs/sub/` 目录）：

| # | 子产物 | 产出来源 | 推荐文件名 | 脚本 `--skill` 名 |
|---|---|---|---|---|
| 1 | 证据分析 | `综合证据策略` 模式A | `sub-evidence-analysis.md` | `evidence-analysis`（别名 `evidence`） |
| 2 | 争议焦点分析 | `起诉状分析与攻防策略` 模式B | `sub-dispute-focus.md` | `dispute-focus` |
| 3 | 庭审发问策略 | 本技能内部模式B | `sub-questioning.md` | `questioning` |
| 4 | 模拟裁判报告 | `律师模拟裁判报告` | `sub-judge-simulation.md` | `judge-simulation` |

脚本同时兼容中文关键词（证据 / 争议焦点 / 发问 / 模拟裁判），并兼容旧技能英文名（`lawd-civlit-evidence`、`lawd-civlit-dispute-focus`、`lawd-civlit-courtroom-questioning` 等）作为历史别名，便于识别历史产物。

### 5.3 处理规则

- 退出码 0：打印通过清单，可进入大纲确认与 Word 生成。
- 退出码 1：打印拦截清单（标明缺失或为空的子产物），**禁止生成最终报告**；补齐后重跑至通过。
- 退出码 2：输入错误（`--dir` 与 `--files` 未二选一、目录不存在、`single` 模式未给 `--skill` 等）。
- **识别口径提醒（避免假通过）**：脚本按**内容级识别**判定子产物，须同时满足四点——①文件类型为 `.md`/`.txt`/`.docx`（`.pdf`/`.png` 等律师原始输入材料不认）；②标题行含产物标记（如「证据专项分析报告」「模拟裁判报告」）；③实质内容 ≥ `--min-chars`（默认 300）字符；④必备小节达标。模板/知识库类文件自动排除，`--dir` 即使误指向 `references/` 也不会把 `questioning-knowledge-base.md` 误判为子产物。准确性最高仍推荐 `--files` 显式列出四份产物：

```bash
python3 scripts/check_sub_outputs.py --mode full --files \
  outputs/sub/sub-evidence-analysis.md outputs/sub/sub-dispute-focus.md \
  outputs/sub/sub-questioning.md outputs/sub/sub-judge-simulation.md
```

- 脚本只做"齐全 + 非空"的机械门禁，不做法律实质判断；通过不代表内容正确，仍须完成 §3.1.11 第 12 项输出质量自检。

```

```

## 七、异常处理

### 材料无法解析

- 告知用户材料无法解析及可能原因，建议重新上传或转换格式
- 建议用户提供文件截图或文字描述
- 不得编造或猜测文件内容

### 信息极度不完整（模式B 常见）

若用户提供的信息严重不足（如仅说"帮我设计发问"但无任何案件信息）：

1. 主动询问用户补充关键信息：案由、诉讼地位、核心争议焦点、现有证据等
2. 明确告知用户需要哪些信息才能设计发问策略
3. 不得基于不充分的信息强行生成发问策略

### 子能力调用失败

- **单项失败**：按 §3.1.5 错误隔离处理，标记"分析未完成，请单独运行该模块补充"，继续后续子工作；最终报告注明未完成部分
- **全部失败**：告知用户子能力服务暂时不可用，建议分别单独运行 `综合证据策略`（模式A）、`起诉状分析与攻防策略`（模式B）、本技能模式B、`律师模拟裁判报告`

### 子能力被路由到错误模式

若返回内容形态与预期不符（如要争议焦点却收到《起诉状风险分析报告》、要综合证据分析却收到逐份质证意见）：

1. 判定为**模式指定失败**，不得将错误产物当作子产物落盘
2. 按 §3.1.1 重新发起调用，指令中显式重申模式名
3. 连续两次仍错，标记该项"分析未完成"并在报告中注明

### 检索服务不可用

按 §4.3 A 档降级处理：标注"未取得检索支撑"，不静默编造法条与案例。

### 门禁脚本拦截

若 `check_sub_outputs.py` 返回非零退出码：

- 按拦截清单逐项补齐或重跑对应子工作，重新运行至通过
- 不得跳过门禁直接生成报告

### 用户不回复确认

- 除任务消息已写明「一律按是 / 勿等待用户输入」的情形（此时直接继续），未经确认不得调用 docx skill 生成 Word 文档
- 可主动询问用户是否需要调整或修改大纲

### docx 和钉钉文档双重失败

若 `docx` skill 和 `dws doc create` CLI 均失败：

- 将报告内容以 Markdown 格式直接在对话中输出，并显式写入 `outputs/*.md`
- 告知用户文档生成失败，已以文本形式输出，不得因生成失败而终止任务

## 九、合并与接线说明（供维护参考）

本技能为「律师办案助手」套件单元 7「律师庭前准备」，由以下两个技能合并：

- `lawd-civlit-preparation`（编排器主体，目录名保持不变；`name` 中文化后为「律师庭前准备」）→ 模式A
- `lawd-civlit-courtroom-questioning`（旧中文名「庭审发问策略」，已吸收，目录暂予保留，不再作为独立入口对外触发）→ 模式B

**编排接线变更记录**（原四个外部子技能 → 现在的位置）：

| 原子技能 | 现在在哪 | 本单元的调用方式 |
|---|---|---|
| `lawd-civlit-evidence`（律师证据分析） | 已并入 `综合证据策略`（单元 10），成为其**模式A「综合证据分析」** | 外部调用 `综合证据策略`，显式指定模式A |
| `lawd-civlit-dispute-focus`（律师争议焦点分析） | 已并入 `起诉状分析与攻防策略`（单元 9），成为其**模式B「争议焦点分析」** | 外部调用 `起诉状分析与攻防策略`，显式指定模式B 并透传 `report_profile` |
| `lawd-civlit-courtroom-questioning`（庭审发问策略） | 已并入**本单元**，成为**模式B** | 内部执行 §3.2，不再跨技能调用 |

`lawd-civlit-evidence` 与 `lawd-civlit-dispute-focus` 的旧目录虽暂时保留，但**已不是有效调用目标**（随时可能移入归档目录）；本 SKILL.md 内所有编排调用一律指向新位置，旧名仅在 §2.2 与本节作为历史别名说明保留。
