# 综合证据策略

## 一、能力总述

本 Skill 以资深民商事诉讼律师的专业视角，提供民商事诉讼**证据工作的一站式能力**：从举证责任分配、己方证据三性与证明力审查、原件准备、证据链完整性评估、缺口识别与补强、举证策略推演，到对对方证据的逐份深度质证，以及把零散证据系统化对应到每一项法律主张、编制可提交的证据目录。

本单元由原三个技能合并而成，对外只有一个入口，内部按用户意图分流为三种模式：

| 模式 | 名称 | 解决什么问题 | 前身技能 |
|------|------|--------------|----------|
| 模式A | **综合证据分析** | 整体审查己方及对方全部证据，出综合证据专项分析报告 | `lawd-civil-evidence`（旧名"律师证据分析"） |
| 模式B | **质证意见** | 针对对方证据逐份出可直接上庭的质证意见 | `lawd-civil-evidence-enhanced`（本技能主体原侧重） |
| 模式C | **证据链构建与举证要点映射** | 把证据挂靠到每个法律主张，建立五层证明链条、识别缺口、编制证据目录 | `lawd-evidence-chain-builder`（旧名"举证要点整理"） |

> **模式C 的准确称谓**：`综合证据策略` 模式C「证据链构建与举证要点映射」。库内其他技能（如答辩状、庭前准备）需要「证据链构建」能力时，应指向本技能并注明走模式C，不再指向已被吸收的旧技能 `lawd-evidence-chain-builder`（举证要点整理）。

## 二、触发与分流

### 2.1 意图 → 模式路由表

三种模式的关键词高度重叠（"证据分析""质证""证据链"在原技能中都能触发多个），因此**不按关键词硬切，按用户意图判定**。判定顺序：先看用户要的**产出物形态**，再看**处理对象**，最后看**范围**。

| 用户意图（原话典型形态） | 判定要点 | 路由 |
|---|---|---|
| "帮我整体审查一下这批证据" / "证据梳理" / "庭前证据准备" | 处理对象 = 己方 + 对方全部证据；范围 = 全流程 | **模式A** |
| "分析下我方证据的三性" / "这几份证据的真实性合法性关联性怎么样" | 要素 = 三性/证据能力审查 | **模式A** |
| "举证策略怎么定" / "先举哪份证据" / "举证责任在谁" / "证明力够不够" | 要素 = 策略/举证责任/证明力评价 | **模式A** |
| "帮我写质证意见" / "对方这份证据怎么质证" / "对对方证据发表意见" | 产出物 = 质证意见文本；处理对象 = 对方证据 | **模式B** |
| "逐份质证" / "质证话术" / "开庭时怎么反驳这份证据" | 产出物 = 可当庭宣读的质证发言 | **模式B** |
| "这些证据能不能支撑我的主张" / "证据和主张对不对得上" | 关系 = 证据 ↔ 主张映射 | **模式C** |
| "帮我搭证据链" / "哪些主张还缺证据" / "证据缺口在哪" | 关系 = 链条完整性 + 缺口 | **模式C** |
| "编个证据目录" / "举证要点整理" / "证据清单怎么列" | 产出物 = 证据目录/举证要点表 | **模式C** |
| "帮我看下证据"（未说明目的） | 意图不明 | **默认模式A**，见 2.2 |

### 2.2 模糊情形处理（默认路由）

用户只给证据材料、未说明目的（如"帮我看下证据""这些材料你看看"）时：

1. **默认进入模式A**（覆盖面最全，含模式B 的质证章节与模式C 的证据链章节的简版）；
2. **在回复开头一句话告知用户可切换**，话术模板：

> 我按「综合证据分析」（模式A）来处理，会覆盖举证责任、三性审查、证据链缺口、举证策略和对方证据质证。如果你只需要**逐份质证意见**可以说"只写质证意见"（模式B），如果只需要**证据对应主张、查缺口、出证据目录**可以说"搭证据链/出举证要点"（模式C）。

3. 用户中途改变目的时，直接切换模式，已完成的分析结果复用，不重复索要材料、不重复检索。

### 2.3 边界（NOT for，指向本单元之外的技能，原样保留）

- 仅需**法律法规条文检索** → 使用 `律师法规检索`
- 仅需**类案/判例检索** → 使用 `律师类案检索与报告`
- 需要**庭审发问提纲、交叉询问设计** → 使用 `律师庭前准备`
- 需要**争议焦点归纳、要件攻防推演** → 使用 `起诉状分析与攻防策略`

> 原 `lawd-civil-evidence`（律师证据分析）description 中"若用户仅需简单证据目录或逐份正式质证意见，且当前环境已有更专门的能力，应优先使用专门能力"这一条，**已落地为本单元内部路由**：简单证据目录 → 模式C；逐份正式质证意见 → 模式B。不再外跳其他技能。

### 2.4 模式组合

- 模式A 完成后可直接续接模式B（把 A 的"对方证据质证意见"章节扩写为独立质证意见文书）；
- 模式C 完成后可直接续接模式A（把 C 的主张-证据映射作为 A 的证据链章节输入）；
- 组合执行时**检索只做一次**，结果在模式间复用。

## 三、模式工作流

### 3.0 三模式共用：输入信息收集

启动分析前必须确认材料是否齐备。材料不齐全时，向用户列出缺失项并引导补充。

#### 必需材料

- **基础诉讼文书**：起诉状/仲裁申请书/上诉状（必需）、答辩状（必需）、反诉状（如有）、代理词（如有）
- **证据材料**：己方证据清单及材料（必需）、对方证据清单及材料（必需）、法院调取证据（如有）
- **程序性文书**：举证通知书（必需）、开庭传票（必需）、庭前会议通知书（如有）、证据交换笔录（如有）

#### 最低启动条件

- **模式A**：起诉状/仲裁申请书（或能说明案件基本事实的材料）+ 己方证据清单及材料（至少部分）+ 举证期限信息。低于此条件，明确告知用户无法分析并说明原因。
- **模式B**：对方证据清单及材料（必需，可为部分）+ 案件基本事实。无对方证据材料时无法执行。
- **模式C**：主张清单（用户希望证明的法律主张）+ 证据清单（编号、名称、来源、形成时间）。无主张清单时先引导用户从起诉状/答辩状中提炼。

材料基本齐备但有缺失时，可进行基础分析，但须在报告中注明局限性。完整材料清单与齐备性核对表参见 [references/material-collection-guide.md](references/material-collection-guide.md)。

#### 渐进式引导

当用户首次使用本技能时，按以下顺序引导用户提供信息，避免一次性要求过多材料：

1. **第一轮**：请用户提供案件基本信息（案由、诉讼地位）和己方证据清单
2. **第二轮**：根据案件类型，针对性地请求补充材料（如对方证据、举证通知书等）
3. **第三轮**：确认是否有特殊证据类型需要关注（电子数据、鉴定意见、证人证言等）

#### 材料深度分析原则

**强制要求：对用户提供的所有材料和信息，必须进行深度分析、充分捕捉、完整保留细节。**

- **逐页逐段审阅**：不得跳过或忽略任何材料内容，包括附件、备注、落款、日期等细节
- **关键数字复核**：所有金额、日期、期限、面积、数量等数字必须精确提取和交叉验证，逐项执行以下清单：
  - ① 诉称/主张金额 vs 凭证逐笔加总（如起诉状称"共支付90,600元"，须与电子凭证逐笔相加核对）
  - ② 退费、已还款、已付部分是否已从诉请金额中扣减
  - ③ 同一金额在不同证据（凭证/收据/聊天记录）中是否一致
  - ④ 发现差异必须标注差异额并给出可能原因，禁止静默取其一
- **矛盾点捕捉**：主动识别不同材料之间、同一材料前后、当事人陈述与证据之间的矛盾和不一致
- **隐含信息挖掘**：从材料字里行间挖掘隐含的事实信息（如合同条款的默示含义、通信记录的言外之意）；收据/凭证上的客户名、收款方与当事人不一致时，必须查明其与当事人的关系并分析影响
- **细节保留**：即使看似次要的细节（如证据的形成时间、签字人身份、证据载体形式），也必须保留并在分析中体现
- **信息溯源**：每一个提取的事实都必须标注其信息来源（证据编号+页码、当事人陈述、诉讼文书等）

**扫描件 PDF 处理流程（强制）**：

1. 用 pymupdf(fitz) 打开 PDF，检测每页是否有可提取文字
2. 无文字的页面 → 渲染为 200dpi PNG 图片 → 通过 Read 工具视觉读取
3. 页数超过 20 页的 PDF → 分批渲染（每批 ≤20 页）→ 用子代理并行读取
4. **所有页面读取完毕后才能进入分析阶段**；确因客观限制无法全读的，必须在报告中标注实际覆盖率（已读页/总页数）并说明受限原因，**禁止静默按已读部分当作全部材料**

#### 执行状态管理

本技能的执行分为以下明确阶段，每个阶段完成后进入下一阶段：

| 阶段 | 状态 | 进入条件 | 完成标志 |
|------|------|----------|----------|
| 意图判定 | `ROUTING` | 技能触发 | 模式已确定（含默认模式A 并告知用户） |
| 信息收集 | `COLLECTING` | 模式确定 | 满足该模式最低启动条件 |
| 检索前置 | `SEARCHING` | 信息收集完成 | 类案检索和法规检索均完成 |
| 证据分析 | `ANALYZING` | 检索完成 | 该模式全部分析步骤完毕 |
| 门禁校验 | `VALIDATING` | 分析完成 | `validate_evidence_report.py` 退出码为 0 |
| 报告生成 | `GENERATING` | 门禁通过且用户确认大纲 | Word 文档生成成功 |

### 3.1 模式A ｜ 综合证据分析（骨架模式，内容最厚）

> 承自旧技能 `lawd-civil-evidence`（律师证据分析）。整体审查己方及对方证据，分析真实性、合法性、关联性和证明力，梳理举证责任、证据链缺口、补强方案、举证顺序和庭审证据应对。核心交付物为**综合证据专项分析报告**。

> ⛔ 执行模式A 前，必须先完整读取 [references/mode-a-evidence-analysis.md](references/mode-a-evidence-analysis.md)，严格按其流程执行。

---

### 3.2 模式B ｜ 质证意见

> 承自本技能主体（`lawd-civil-evidence-enhanced`）原侧重的逐份质证。产出**可直接在法庭上使用**的质证意见，处理对象是对方证据。

#### 执行步骤

1. **确认质证范围**：对方证据共几份、逐一确认编号与名称；确认是否有原件核对、是否已完成证据交换。
2. **完成强制检索前置**（见第四节）：类案检索 query 聚焦"证据采信规则 + 本案证据类型"；法规检索聚焦证据规定与特殊证据规则。
3. **逐份质证分析**，每份证据必须完整覆盖：
   - **真实性分析**：是否原件、形成过程、签章与落款、篡改与伪造可能、与其他证据的时间/内容矛盾
   - **合法性分析**：取证主体、取证手段、取证程序、是否侵害他人合法权益、是否属于非法证据排除范围
   - **关联性分析**：与待证事实的关联程度（直接证明/间接证明/无关联）、审查结论（认可/不认可/关联性弱）
   - **证明目的反驳**：对方主张该证据证明什么、实际能证明什么、不能证明什么、为什么达不到对方主张的证明效果
   - **法律依据**：每个质证观点引用具体法条或司法解释条款
   - **完整质证话术**：按"第一，关于真实性…第二，关于合法性…第三，关于关联性…"结构写成可当庭宣读的发言稿
   - **追问设计**：针对薄弱环节设计法庭调查阶段可向对方发问的具体问题
   - **法官视角补充**：预判法官（仲裁案件为仲裁员）对该证据的关注点和可能询问方向，准备应答
   - **质证策略选择**：完全否认 / 部分认可 / 认可但削弱证明力 / 认可但限定范围
4. **证据体系层面**：证据体系弱点识别、质证重点排序（哪几份必须重点打）、庭审质证节奏建议。
5. **反证引用**：如有己方证据可反驳对方证据，必须明确引用证据编号与页码。

#### 质量红线

- 严禁笼统表述（"对真实性有异议""不予认可"），必须指出具体质疑点（如：该证据为复印件而非原件、签字日期与合同约定不符、电子数据未经公证保全等）。
- 每份证据的质证意见必须逐一满足 [references/cross-examination-depth-guide.md](references/cross-examination-depth-guide.md) 的深度、丰富度、细致程度三方面要求。
- 未取得法规检索结果时，不得凭记忆罗列法条编号。

---

### 3.3 模式C ｜ 证据链构建与举证要点映射

> 承自旧技能 `lawd-evidence-chain-builder`（举证要点整理）。将零散证据与法律主张建立结构化对应关系。核心思路：法律主张不能凭空存在，必须拆解为法律要件，再对应到具体事实，最后由证据支撑。整个链条中任一环节缺失，该主张即无法成立。

> ⛔ 执行模式C 前，必须先完整读取 [references/mode-c-evidence-chain.md](references/mode-c-evidence-chain.md)，严格按其流程执行。

## 四、数据源

### 4.1 检索依赖：通过兄弟技能获得，本技能不直接调用外部数据连接器

本技能的法律检索能力**全部通过调用兄弟技能获得**，不在本 SKILL 内直接探测或调用法律数据连接器（连接器探测与降级由被调技能自身按三铁律负责）：

| 需要的能力 | 调用对象 | 何时调用 |
|---|---|---|
| 类案裁判规则（证据采信口径） | `律师类案检索与报告` skill | 三模式的分析前置，必做 |
| 法条与司法解释（证据规则依据） | `律师法规检索` skill | 三模式的分析前置，必做 |

### 4.2 强制检索前置程序

确认材料齐备后，必须按顺序完成以下检索，再进入证据分析：

**第一步：类案检索**

调用 `律师类案检索与报告` skill，检索 query 应包含：案由 + 核心争议焦点 + 关键证据类型（如"电子数据证据认定""举证责任分配""书证真实性认定"）。从检索结果中提炼类案证据裁判规则，作为本案证据分析的参考依据。

**第二步：法规检索**

调用 `律师法规检索` skill，检索 query 应包含：
- 《民事诉讼法》证据相关规定
- 《最高人民法院关于民事诉讼证据的若干规定》
- 本案涉及的特殊证据规则（如电子数据、鉴定意见、证人证言等）

确保所有证据能力判断有明确法律依据，避免引用过时法条。

**检索结果整合**

在证据分析报告中须包含两个专章：
- 【类案裁判规则摘要】：案号、裁判规则、证据采信要点、对本案的指导意义
- 【本案证据分析法律依据】：相关法条及内容

模板中这两个章节已标注"必须调用 律师类案检索与报告 / 律师法规检索 后填写"，见 [references/output-format-template.md](references/output-format-template.md)。

**未经上述检索程序，不得进行后续证据分析** — 未经检索的证据能力判断缺乏法律依据支撑，可能引用过时法条或编造规则，对律师造成误导。

### 4.3 检索不可得时的门禁语义（不得降级编造）

检索工具调用失败或未返回结果时：

- **不得罗列法条**：禁止凭模型记忆写出具体法条编号、条文内容或司法解释条号。只能写"该项判断需要核验《民事诉讼法》证据章相关规定（未取得检索结果，待核验）"。
- **不得虚构类案裁判规则**：禁止编造案号、法院名称、裁判要旨。【类案裁判规则摘要】章节留空并标注"检索服务不可用，未取得类案"。
- **必须显著标注**：报告顶部加提示"本报告部分内容未经检索验证"，并逐处标注受影响的结论。
- **正式质证意见（模式B）与举证责任结论（模式A 第一阶段）属权威引用场景**：法规检索完全不可得时，**停止输出正式质证意见文书**，改为输出"待核验版分析要点"并告知用户需在检索恢复后重出，不得直接交付。

## 五、门禁脚本

### 5.1 交付前必须运行

**交付前必须运行本脚本，未通过禁止交付。** 脚本对报告做结构完整性硬校验，拦截时以非零退出码阻断，必须先修复报告再重跑，通过后才能进入 Word 生成与交付环节。

```bash
python3 scripts/validate_evidence_report.py <报告文件.md 或 .txt> --mode A|B|C
python3 scripts/validate_evidence_report.py --help
```

脚本路径：[scripts/validate_evidence_report.py](scripts/validate_evidence_report.py)

### 5.2 校验项

| # | 校验项 | 适用模式 | 拦截条件 |
|---|---|---|---|
| 1 | **证据三性表格结构完整** | A、B | 存在证据能力审查表/质证三性分析，但某份证据的真实性、合法性、关联性任一栏缺失或为空 |
| 2 | **证据链缺口标注完整** | A、C | 缺口章节缺失；或存在已识别缺口但未给出补强/补救建议 |
| 3 | **证据编号连续无重复** | A、B、C | 证据编号重复，或序列出现断号 |
| 4 | **无悬空主张** | C | 主张清单中的主张未出现在主张-证据映射中，或映射中无任何支撑证据且未标注为缺口 |

### 5.3 处理规则

- 退出码 0：打印通过清单，可进入交付。
- 退出码 1：打印拦截清单（每条含问题定位），**禁止交付**；修复后重跑至通过。
- 脚本不做法律实质判断，只做结构门禁；结构通过不代表内容正确，仍须完成 [references/mode-a-evidence-analysis.md](references/mode-a-evidence-analysis.md) 中约束原则第 9 项「输出质量自检」。

## 六、交付物

### 6.1 生成前确认（必须执行）

在调用 `docx` skill 生成 Word 文档之前，必须先向用户展示报告大纲，等待用户确认后再生成文档：
- 模式A 大纲须含：己方证据审查要点、对方证据质证要点、证据链缺口
- 模式B 大纲须含：待质证证据清单与每份的质证策略结论
- 模式C 大纲须含：主张清单与映射完成度、缺口清单

用户未回复确认前，**不得直接生成文档**。

**交付路径**：所有最终交付物（.docx / .md）一律写入当前工作区的 `outputs/`（复数）目录，如 `outputs/《XX案-证据专项分析报告》.docx`；`outputs/` 是 UI 唯一扫描的交付目录，写成单数 `output/` 用户看不到成果。未确认文件已落盘并存在前，不得声称"报告已生成"。

### 6.2 各模式产出物

| 模式 | 交付物 | 文件名 | 内容模板 |
|---|---|---|---|
| 模式A | 综合证据专项分析报告（.docx） | `《XX案-证据专项分析报告》.docx` | [references/output-format-template.md](references/output-format-template.md) |
| 模式B | 质证意见（.docx） | `《XX案-质证意见》.docx` | [references/output-format-template.md](references/output-format-template.md) 第九章"对方证据质证意见"结构扩写为独立文书；深度要求见 [references/cross-examination-depth-guide.md](references/cross-examination-depth-guide.md) |
| 模式C | 证据链组织报告 / 举证要点表 + 证据目录（.docx） | `《XX案-证据链组织报告》.docx` | [references/chain-builder-output-template.md](references/chain-builder-output-template.md) |

**模式A 报告结构**（十三章 + 两个专章）：

1. 案件基本信息
2. 证明责任分配专项分析
3. 己方证据审查
4. 证据链完整性深度分析
5. 证据缺漏与补强方案
6. 证人证言专项模块
7. 鉴定意见专项审查
8. 举证策略推演
9. 对方证据深度质证意见
10. 证据保全与调查令申请
11. 庭前会议证据整理
12. 庭审证据应对预案
13. 行动清单与时间表

此外须包含：【类案裁判规则摘要】和【本案证据分析法律依据】。

**模式C 报告结构**：一、案件基本信息；二、主张-证据映射总表（五层映射）；三、证据缺口清单（含风险等级、补救建议、论证节点预检结果）；四、证明力总评；五、证据目录（格式化，可直接提交）/ 优先补证建议。

### 6.3 Word 文档格式规范

三种模式的交付物**一律以 Word 文档（.docx）输出**，**必须调用 `docx` skill 生成**，格式规范（字体、字号、标题层级、表格格式）详见 [references/docx-format-standard.md](references/docx-format-standard.md)。

**降级处理（docx 不可用时）：** 改为调用 `dws doc create` CLI 生成钉钉文档：

```bash
dws doc create --title "《XX案-证据专项分析报告》" --content "[Markdown 内容]"
```

### 6.4 交付顺序（硬约束）

```
分析完成 → 运行 validate_evidence_report.py（未过则修复重跑）
        → 向用户展示大纲并等待确认
        → 调用 docx skill 生成 .docx
        → 交付
```

## 七、异常处理

以下异常情况必须按对应方案处理：

### 材料无法解析
若用户提供的材料无法正常解析：
- 告知用户材料无法解析及可能原因
- 建议重新上传或转换格式

### 检索服务不可用
若检索工具调用失败：
- 告知用户检索服务暂时不可用
- 可基于用户材料进行基础分析，但须注明"未经检索验证"
- 严格适用 4.3 的门禁语义：不得罗列法条、不得虚构类案裁判规则；模式B 正式质证意见与模式A 举证责任结论不得在无法规依据情况下交付

### 用户不回复确认请求
若向用户发出确认请求后用户未回复：
- 不得在未经确认的情况下直接生成文档

### 门禁脚本拦截
若 `validate_evidence_report.py` 返回非零退出码：
- 按拦截清单逐项修复报告内容，重新运行至通过
- 不得跳过门禁直接生成文档

### docx 和钉钉文档双重失败
若 docx skill 和 dws doc create CLI 均失败：
- 将分析内容以 Markdown 格式直接在对话中输出
- 告知用户文档生成失败，已以文本形式输出

## 九、合并说明（供维护参考）

本技能为「律师办案助手」套件单元 10「综合证据策略」，由以下三个技能合并：

- `lawd-civil-evidence-enhanced`（主体，目录名保持英文 lawd-civil-evidence-enhanced，`name` 为中文 综合证据策略）→ 模式B 的来源
- `lawd-civil-evidence`（律师证据分析，工作流骨架来源）→ 模式A
- `lawd-evidence-chain-builder`（举证要点整理）→ 模式C

被吸收的两个目录暂予保留，不再作为独立入口对外触发。库内其他技能引用「证据链构建」能力时，应指向**本技能模式C「证据链构建与举证要点映射」**。

## 可选套件上下文（不影响独立使用）

1. 工作目录根存在 `套件运行规则.md` 时必须先读取并执行；不存在时以本技能硬规则为准，不影响独立使用。
2. 工作目录根存在 `办案画像.md` 时，只读取与当前任务有关的诉讼立场、风险偏好和文书风格；不存在时按本技能默认运行，不追问、不报错。
3. 仅当用户明确切换到某案或提供唯一案件路径时，读取 `cases/{案件简称}/案件画像.md`；不得猜测案件，不得跨案带入。
4. 画像只影响表达与偏好，不得覆盖事实、法律依据、必备结构、验证结果或本技能硬规则。
5. 已明确绑定唯一案件且案件管家可用时，成果完成后提交标准案件事件；无案件不建档、不回写，回写失败不得阻塞成果交付。
