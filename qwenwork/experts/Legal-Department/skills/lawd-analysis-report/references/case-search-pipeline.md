# 案例检索连接器管道

本文档定义使用「案例检索」连接器能力进行类案检索的完整管道流程。
本环节按 SKILL 连接器写法三铁律执行：只写能力语义、三段式探测、分级降级，**不写死任何供应商/工具名**。

---

## Step 0：能力探测与匹配

本管道需要**「案例检索」**能力：输入案情/争议焦点，返回类案清单（案号、审理法院、案由、裁判日期、争议焦点、裁判要旨、法律依据）。

1. **探测**：调用 `qwenwork_mcp_tool_list`，keyword 逐个尝试：
   `案例 / 判例 / 类案 / case / 元典 / 法宝 / pkulaw / yuandian / ptal / qwal`
2. **匹配**：在返回工具中，按工具名或 description 含「案例检索」「类案」「判例」「case search」等语义判定候选；不确定时用 `qwenwork_mcp_tool_get` 查看 schema，确认支持案情/关键词入参且返回含案号、审理法院、裁判日期、裁判要旨等字段。
3. 多家可用时按探测命中顺序依次尝试，首选调用失败切下一家。

## Step 1：Query 改写

使用 [case-query-rewrite-prompt.md](case-query-rewrite-prompt.md) 将争议焦点转化为检索语句：
- **query**：控制在 30 字以内，使用空格分词，使用法律专业术语
- **keywords**：提取 3-5 个关键词，若工具要求逗号分隔的关键词字符串则**必须使用英文逗号分隔**

示例：
```json
{
  "query": "租赁合同 强制清场 赔偿",
  "keywords": "房屋租赁,提前解除,强制清场,违约赔偿"
}
```

## Step 2：执行检索

用 `qwenwork_mcp_tool_call` 调用匹配到的「案例检索」工具，实际入参名以该工具 schema 为准，将 Query 改写输出适配到其支持的参数（案情文本 / 关键词 / 分页 / 每页条数）。示意（入参语义级）：

```text
qwenwork_mcp_tool_call(
  tool: <匹配到的「案例检索」工具>,
  args: {
    <检索文本>: "<改写后的检索语句>",
    <关键词>: "<关键词1>,<关键词2>,<关键词3>",   // 若为逗号分隔字符串，用英文逗号
    <分页>: 1,
    <每页条数>: 20
  }
)
```

将连接器返回结果保存为 JSON（如 `/tmp/lawding_analysis_cases.json`）以备后续裁剪与门禁核对。

## Step 3：检查结果数量

统计返回的案例条数：
- 若结果为空：缩短 query 至 8 字以内、减少 keywords 至 2-3 个后重试，最多重试 2 次
- 若结果不足 5 条：翻页继续检索并合并结果（工具支持分页时，最多取 3 页）

## Step 4：裁剪重字段，提取精简数据

不同连接器返回结构各异，先归一化为 [case-data-structure.md](case-data-structure.md) 描述的统一契约，再删除体量较大的重字段（如本院查明、文书正文、审理经过、前审情况等）以节省 token，得到精简数据用于报告撰写。

## Step 5：提取裁判要旨

从检索结果中提取以下信息用于报告撰写（完整字段说明见 [case-data-structure.md](case-data-structure.md)）：
- 案号、审理法院、判决日期
- 争议焦点（`disputeFocus`）
- 裁判结果（`verdict`）
- 法律依据（`legalBasis`）

## 降级策略（A 档：权威引用拒绝硬降级）

探测不到任何「案例检索」连接器、或全部连接器调用失败时：
- **跳过类案检索环节**，在报告中注明"暂未检索到高度匹配的公开判例，以下分析基于法理推导"；
- **严禁编造案号**，**严禁**用 WebSearch 或模型记忆虚构案例充当"已检索类案"；
- 可提示用户前往千问办公 设置 → 连接器 安装案例检索类连接器后重试。
