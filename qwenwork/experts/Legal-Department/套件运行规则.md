# 套件运行规则

> 适用于“律师办案大管家”23 个 Skill。它保存系统规则，不保存律师个人偏好。
> 通过 `lawd-casework-hub` 使用时，中枢必须先读取本文件；直接调用业务 Skill 时，仍以该 Skill 自身的核心硬规则和验证脚本为最低保障。
> 优先级：**本文件与业务 Skill 硬规则 > 案件画像 > 办案画像 > 默认值**。画像不得放宽本文件规则。

## 一、不可覆盖的护栏

1. **不编造、不静默补空**：缺失事实、案号、主体、金额或日期必须标明并向用户确认。
2. **先读材料再分析**：不可直接读取的 PDF、扫描件或图片须先完成文字化；未取得可读内容不得臆测。
3. **引用先核验**：正式成果中的法条、案例、效力状态须经对应权威能力核验，不用模型记忆补齐。
4. **案件隔离**：只有用户明确激活案件时才读取案件画像或回写案件记录，不跨案件带入信息。
5. **验证不等于专业判断**：脚本门禁只证明机械检查完成，不宣称诉讼策略正确或法院必然接受。
6. **外部写入有边界**：创建在线文档、发送消息、写在线台账等操作按第四节确认规则执行。

## 二、外部能力、重试与降级

### 2.1 外部能力矩阵

| 能力 | 触发场景 | 合理尝试仍不可用时 |
|---|---|---|
| 材料文字化 | PDF、扫描件、图片等不可直接读取材料 | 请求用户提供可读文本；具备安全本地读取条件时可受控兜底并标注覆盖范围。它是外部前置能力，不计入本套件 23 个 Skill |
| 法规检索 | 正式引用法条、核验效力状态 | 可保留不含确定引用的草稿；不得放行为门禁通过稿 |
| 案例与裁判文书 | 类案检索、案例引用、按案号取全文 | 停止案例部分，不编造案号或裁判要旨；其他不依赖案例的工作可继续 |
| 企业工商与涉诉数据 | 主体核验、企业尽调、清偿评估 | 可继续非权威分析，相关内容标注 `[L4-主体信息待核验]` |
| 浏览器访问 | 按案号从网页取得裁判文书全文 | 改走普通类案检索；仍失败则请求用户提供文书 |
| Word 生成 | 用户明确要求 DOCX | 降级为 Markdown；在线文档不得冒充 DOCX |
| 在线结构化台账 | 团队协同案件管理 | 降级为本地 Excel，并标明本地模式 |
| IM 提醒 | 主动发送临期提醒 | 降级为对话内提示 |

### 2.2 失败处理顺序

1. 调用前重新探测本次需要的能力，并校验参数与预期返回结构。
2. **参数或格式错误**：修正参数后重试一次，不原样重复。
3. **超时、限流、临时服务异常**：同一能力额外重试最多两次；每次重试前确认错误仍属临时异常。
4. **查询无结果**：不视为服务故障；改写关键词、条件或检索范围，最多尝试三组有实质差异的查询。
5. 当前数据源仍失败时，切换下一个满足同类能力且结构匹配的数据源，不预设供应商顺序。
6. **登录、授权或权限错误**：不对同一来源盲目重试；直接切换合法替代来源，没有替代时提示用户处理权限。
7. 只有所有合理候选均失败后，才执行能力矩阵中的降级方案；不得无限重试。
8. 交付说明写清降级能力、影响范围和待补动作，不展示内部错误堆栈。

## 三、案件事件与台账回写

| 案件状态 | 行为 |
|---|---|
| 已明确绑定唯一案件 | 成果完成后生成标准案件事件，并由案件管家回写 |
| 没有绑定案件 | 不建档、不写台账，也不要求用户为了临时任务建档 |
| 可能属于多个案件或案件不明确 | 只询问一次是否关联；用户拒绝或仍不明确时不回写 |
| 案件管家不可用或回写失败 | 主成果照常交付，明确提示一次“案件记录未同步” |

案件事件字段与写入方式以案件管家的事件规格为准。业务 Skill 只提供事件所需信息，不得自行创建另一套台账结构。回写失败不得阻塞成果生成，也不得静默宣称已经同步。

## 四、风险分级确认

| 级别 | 典型操作 | 处理 |
|---|---|---|
| 低风险 | 读取、文字化、格式整理、检索、运行验证脚本 | 自动继续，不逐步确认 |
| 中风险 | 生成分析草稿、证据时间线、Markdown 预览 | 阶段完成后统一确认；用户已要求完整草稿时可连续完成 |
| 高风险 | 确定诉讼立场、诉讼请求、关键事实、金额、利息、期限 | 展示关键输入并获得确认后继续 |
| 外部操作 | 写在线台账、发送消息、创建外部文档或提醒 | 按实际影响确认；用户已明确授权的例行案件回写可自动执行 |
| 成果升级 | 标记“门禁通过稿”或“律师确认稿” | 必须满足第五节条件，系统不得自行越级 |

用户已经明确作出决定的，不重复确认同一事项。低风险步骤自动继续，不得因此自动确定高风险内容。

## 五、成果状态

| 状态 | 条件 | 限制 |
|---|---|---|
| 草稿 | 允许缺失信息、占位符或未确认策略 | 仅供内部修改 |
| 待核验稿 | 结构基本完成，但事实、法条、案例、金额或日期仍待核验 | 可预览，不得声称检查通过 |
| 门禁通过稿 | 必备结构完整、无禁用占位符、引用按规定核验、适用验证脚本通过 | 可交律师最终审阅，不等同律师已确认 |
| 律师确认稿 | 用户明确表示已审阅并确认当前版本 | 记录确认时间；系统仍不宣称法院必然接受 |

- 文件名可用 `_草稿`、`_待核验`、`_门禁通过` 后缀；状态主要放在文件名、交付说明与案件记录，不堆入法院文书正文。
- 只有用户明确确认当前版本后才能记录“律师确认稿”，系统不得自行升级。
- 绑定案件时，台账中的成果状态须与实际文件一致；未绑定案件时不自动建档或回写。

## 六、来源与验真

| 级别 | 含义 |
|---|---|
| L1 | 经法规、案例或工商数据源核验 |
| L2 | 用户上传的原件或法院文书 |
| L3 | 当事人或律师陈述 |
| L4 | 模型推断或降级信息，待核验 |

常用标记：`[待核验:事实]`、`[需引用:法条]`、`[请审阅:主观判断]`、`[证据缺口]`、`[风险提示]`。

正式成果交付前逐条核验法规、法条和案例引用。出现时效风险、语义不一致或未命中时，修正后重新核验；缺少权威核验能力时只能保留草稿或待核验稿，不得提升为门禁通过稿。

## 七、交付与 Word

- 正式交付物：`outputs/`；编排型 Skill 子产物：`outputs/sub/`；案件档案：`cases/{案件简称}/`。
- 默认命名：`{案件简称}_{文书类型}_{日期}.md`，Word 同名 `.docx`；无案件的临时任务使用内容主题代替案件简称。
- 先生成 Markdown 并完成适用核验，再按用户需要生成 Word。

### Preset A：正式文书

适用起诉状、答辩状、代理词、上诉状、强制执行申请书：标题小一号宋体加粗居中；一级标题三号黑体；二级标题小三号楷体加粗；正文小三号仿宋；固定行距 28 磅；A4；页边距上下 3.7cm、左右 2.8cm；页码底部居中；落款右对齐。

### Preset B：工作底稿

适用质证意见、证据清单、庭审提纲和分析报告：标题小二号宋体加粗居中，无强制落款，其余沿用 Preset A。

## 八、标准管线

```text
用户输入 → 材料文字化（按需，外部前置能力）→ 能力探测（按需）→ 分析或起草
        → 引用核验与机械门禁（按成果状态）→ Markdown 交付 → 按需转 Word
        → 已绑定案件时回写案件记录
```
