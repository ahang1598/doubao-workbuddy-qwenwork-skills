# 立项报告

## 适用场景

用户需要一份**可以拿给老板、合伙人或投资人看的正式材料**，把选址评估数据整合为完整的投资决策报告。

**典型问题**：
- "生成立项报告"、"输出可行性报告"
- "帮我写一份开店计划书"、"制作开店投资决策报告"

---

## 前置依赖

### 数据依赖（强制）

**必须先完成「点位评估」或「多点位对比」，取得五维评估数据后才能执行本技能。**

前置检查清单：
1. ✅ 已调用 `evaluate:report:analysis` 获取五维评估数据
2. ✅ 已知 POI 基本信息（名称、地址）
3. ✅ 已明确业态类型

如尚未完成评估，**必须先执行「点位评估」**，不得基于假设数据生成报告。

### 能力与鉴权依赖

本技能的主要数据来自「点位评估」/「多点位对比」的执行结果，不需要重复查询。**但当报告所需模块缺失时（如 `potentialGuest`、`competition`），本技能需自行调用网关补齐，因此必须具备完整鉴权能力。**

- **自包含**：完整鉴权规范、OAuth 登录脚本、错误码与降级路径见**本技能目录内**的 `./references/gateway-auth.md`，不依赖套件内其他技能
- **能力待接入**：选址数据源尚未以千问办公标准 Connector（MCP Server）形态上架，当前为技能内直连。详见套件根目录 `CONNECTORS.md`

#### 鉴权要点（需补充查询时必做）

**请求地址**（POST）：`${YT_GATEWAY_BASE_URL:-https://yt-gateway.amap.com}/proxy/yt-xd-lite/openapi/v1/gateway`

**认证 Header**：

| Header | 值来源 | 说明 |
|--------|--------|------|
| `X-Session-Token` | YTOSS 文件中 `sessions.wukong.session_token` | 必传 |
| `X-Skill-Id` | `amap-store-location-assistant` | 必传。**套件内四个技能统一使用该值**，不要改成本技能目录名，否则鉴权与配额校验失败 |

**禁止传** `X-Access-Key` / `X-Tenant-Id` / `X-User-Id`（由网关侧反查注入，技能层不持有）。

**执行顺序**：

1. **先读 YTOSS 文件**，按优先级：macOS/Linux `~/.config/yt/oss.json` → Windows `%APPDATA%\yt\oss.json` → 降级（沙箱）`./.yt/oss.json`
2. **校验** `sessions.wukong.session_token` 存在且以 `gwst_` 开头
   - ✅ 有效 → 直接发起补充查询
   - ❌ 不存在 / 无效 → 执行 `./references/gateway-auth.md` 中的 **OAuth 登录脚本**，落盘后再查询
3. **禁止**跳过文件读取直接登录（已有有效 token 时重复登录会浪费用户操作）
4. **禁止**向用户索要 token 等鉴权信息；唯一需要用户参与的是在浏览器中完成登录
5. curl 必须带 `-k` 跳过 TLS 证书校验

**鉴权与调用异常处置**：

| code | 处置 |
|------|------|
| `19002` / `1001` | 删 YTOSS 中 wukong 条目 → 重走 OAuth，**仅重试 1 次** |
| `19003`（账号冻结） | 提示联系管理员，**不重登** |
| `2001`（配额不足） | 提示充值；已有数据的章节正常输出，缺数据章节标注无法测算 |
| `1004`（限流） | 退避重试 |
| `5001` / `5002`（上游异常） | 透传错误，session 仍有效 |

若补充查询最终失败，按 `./references/gateway-auth.md` 的「数据不可用时的降级原则」处理：对应章节标注数据缺失，**不得编造五维分数、潜客数量或同业门店数**。

## 执行步骤

```
1. 前置检查：确认已具备五维评估数据；缺失则先执行「点位评估」
    ↓
2. 从已获取的评估数据中提取关键字段（按下方数据映射规则）
    ↓
3. 基于 potentialGuest 模块计算预期营收区间
    ↓
4. 结合行业通用参数填充投资预算与成本结构
    ↓
5. 生成盈亏测算（月度收支模型 + 分阶段预测 + 三情景）
    ↓
6. 提取 SWOT 要素（优势来自高分维度，劣势来自低分维度）
    ↓
7. 整合为完整立项报告（Markdown格式）
    ↓
8. 询问是否需要生成 PPT 版本
```

### 数据映射规则

| 报告字段 | 数据来源 |
|----------|----------|
| 综合评分 | `baseInfo.score` |
| 星级 | `baseInfo.starLevel` |
| 超越百分比 | `baseInfo.abovePercent` |
| 五维雷达 | `baseInfo.radar[]` |
| 特征标签 | `baseInfo.tags[]` |
| 同业门店数 | `competition.value.peer.num.value` |
| 品牌占比 | `competition.value.peer.brand.value` |
| 平均客单价 | `competition.value.peer.customer_pay.value` |
| 同业门店列表 | `competition.value.peer.occupation_list.value` |
| 搜索群体数 | `potentialGuest` 中搜索UV |
| 导航群体数 | `potentialGuest` 中导航UV |
| 潜客总数 | `potentialGuest` 中去重总UV |
| 交通配套 | `trafficConvenience.value` |
| 商业配套 | `business.value` |

### 用户确认门（生成前必做）

投资预算、成本结构、目标客单价等属于**经营假设**，直接影响报告结论。生成报告前必须向用户确认或明确标注：

| 项目 | 处理方式 |
|------|---------|
| 月租金、初期投资 | 优先问用户实际数字；用户给不出时用行业参考值，并在报告中标注"行业参考值，待实际替换" |
| 客单价、毛利率 | 按 `./references/financial-params.md` 行业默认值，标注为假设 |
| 城市级别（影响预算） | 从 POI 所在城市推断，向用户确认 |

**报告生成完毕后，如用户要求导出为文件或对外发送，需再次确认输出路径与用途。**

## 评分口径

报告中引用的综合评分、星级、超越百分比均为不同口径，**星级与分数禁止互相推断**，综合总分也不是各维度分数的加和或平均。写报告时若遇到分数与星级不一致，解释为「评价口径不同」，属正常现象。完整说明见 `./references/scoring-model.md`。

## 常见错误与恢复

| 情况 | 处置 |
|------|------|
| 无前置评估数据 | **不得生成报告**。先执行「点位评估」，或明确告知用户需要先完成评估 |
| `potentialGuest` 缺失 | 补充查询该模块；确实取不到时，市场规模与盈亏测算章节标注"缺少潜客数据，无法测算"，**不编造数字** |
| 用户拒绝提供成本信息 | 用行业参考值并在报告中显著标注"行业参考值，待实际数据替换" |
| 报告数据与评估时点相隔较久 | 提示"报告数据基于评估时点，建议 3 个月内使用"，必要时重新评估 |

## 约束

- **数据依赖**：必须基于真实接口返回数据，不得虚构或推断指标
- **区分实测与假设**：五维评分为实测数据，投资预算与盈亏测算为行业假设推算，必须在报告中明确区分
- **行业差异**：客单价、毛利率、成本结构参数需按实际行业调整
- **地域差异**：投资预算和租金水平需参考城市级别（一线/二三线）
- **时效性**：报告数据基于评估时点，建议 3 个月内使用
- **免责**：营收测算基于行业通用假设，实际经营结果受多种因素影响，仅供参考
