# 选址顾问

面向**门店开店选址**的专家能力包。基于高德问店五维选址模型，把"不知道开在哪"到"确定选址并出立项报告"的完整链路拆成四个可独立触发的技能。

---

## 适用角色

- **连锁品牌拓展/开发岗**：负责为品牌批量筛点、评点、出决策材料
- **区域加盟商 / 个体创业者**：手上有 1–3 个候选铺位，需要判断该不该签
- **投资决策方**：需要一份有数据支撑的立项报告作为投资依据

典型画像："连锁茶饮品牌 3–20 人拓展团队的拓展经理，每周要跑 5–10 个候选铺位，每月要给决策会提交 2–5 份选址立项材料。"

---

## 五维选址模型

| 维度 | 说明 |
|------|------|
| **客群聚集** | 评估区域内消费群体规模与活跃度，判断客流基础是否充足 |
| **潜客匹配** | 评估区域客群与目标业态的适配程度，判断"来的人是不是你的目标客户" |
| **同行竞争** | 评估同业供给密度与竞争压力，判断市场是否饱和 |
| **交通便利** | 评估到达便捷性与通行条件，判断客户是否容易到达 |
| **商业成熟** | 评估区域商业氛围、业态丰富度及消费承接能力，判断经营环境是否成熟 |

## 包含的技能

| 技能 | 何时用 | 输入 | 输出 |
|------|--------|------|------|
| **商圈推荐** | 还没有候选点位，只知道城市/行政区 | 行政区 + 业态 | 带评分排名与特征标签的商圈清单，可下钻五维详情 |
| **点位评估** | 有一个明确点位，想做体检 | 点位 + 业态 + 范围 | 综合评分、星级、超越同行百分比、五维解读与建议 |
| **多点位对比** | 有 2 个以上候选铺位要取舍 | 多点位 + 业态 | 同口径五维对比表、营收对比、回本测算、SWOT、首选建议 |
| **立项报告** | 需要给老板/投资人看的正式材料 | 已完成的评估数据 | 八章立项报告（概述/评估/市场/规划/预算/盈亏/风险/结论） |

### 典型工作流

```
商圈推荐 ──► 点位评估 ──┬──► 立项报告
（圈范围）   （单点体检） │
                        │
            多点位对比 ──┘
            （横向取舍）
```

四个技能均可**独立触发**，不必按顺序走完。唯一的硬依赖：「立项报告」需要先有「点位评估」或「多点位对比」产出的评估数据。

---

## 需要连接哪些系统

本套件依赖**高德问店选址网关**获取选址评估数据，采用 OAuth 认证。首次使用时会自动拉起浏览器完成登录，登录凭据以 session token 形式保存在本地配置文件，不需要用户手动填写任何密钥。

⚠️ 当前该数据源**尚未以千问办公标准 Connector（MCP Server）形态上架**，是由技能内直连网关实现的。这一形态差异及后续接入计划见 [CONNECTORS.md](./CONNECTORS.md)。

---

## 未连接时如何降级

| 情况 | 表现 |
|------|------|
| 未完成 OAuth 授权 | 明确告知"未完成授权，无法获取选址数据"，可选择改为仅做定性建议（会声明无数据支撑） |
| 网关不可达 | 告知"选址数据服务暂时不可用"，说明已完成到哪一步，建议稍后重试 |
| POI 检索不到 | 反问更精确的店名/商场名/详细地址，不会自行猜一个相近的点位 |
| 某维度数据未返回 | 只解读已返回的维度，缺失维度标注"该维度数据本次未返回" |
| 配额不足 | 提示充值；同参数查询按 MD5 幂等，不重复扣费 |

**核心原则**：任何情况下都不会用常识编造五维分数或潜客数量。数据取不到就说取不到。

---

## 数据口径须知

- **分数与星级是两套不同的评价体系**：分数衡量"与行业优质点位模型的接近程度"，星级衡量"该指标数量在城市内的相对排名"。两者不一致属正常现象，不可互相推断。
- **综合总分不是各维度分数的加和或平均**，而是基于行业优质点位模型综合计算。
- **营收与回本测算**中，潜客数量为接口实测数据，转化率/客单价/成本为行业假设值——输出时会明确区分。
- 评估数据仅供参考，建议用宏观数据把握方向，结合实地考察和物业条件综合判断。

### 关于 references 的双份存在（重要）

四个技能**各自独立触发**，不能依赖 `../../` 向上跨目录读取共享文档——白皮书只规定 `skills/<目录>/SKILL.md` 会被扫描，根目录的共享 `references/` 不在技能的可靠可达范围内。因此：

- **每个技能目录内自带一份 `references/` 副本**，技能内引用统一用 `./references/xxx.md`，保证任一技能被单独触发时都能独立完成鉴权与执行
- **根目录 `references/` 是维护源文件**（单一编辑入口），改完后执行同步脚本，再重新打包：

```bash
bash scripts/sync-references.sh
```

- 每个 `SKILL.md` 的 Step 0 内还**内联了鉴权要点**（请求地址、认证 Header、token 读取顺序、错误码处置），即使不读任何附件也知道必须先鉴权；`references/gateway-auth.md` 只承载完整 OAuth 登录脚本与详细降级规则

> ⚠️ 修改鉴权规范时，务必改根目录 `references/gateway-auth.md` 后跑同步脚本，不要只改某一个技能目录内的副本，否则四份会漂移。
