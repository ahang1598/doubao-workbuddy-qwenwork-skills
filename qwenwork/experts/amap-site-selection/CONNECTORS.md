## 二、与标准 Connector 规范的差距（须在评审中确认）

本套件**未提供 `.mcp.json`**。原因如下，供千问办公侧评审判断：

| 白皮书对 Connector 的要求 | 当前实现 | 差距 |
|------------------------|---------|------|
| 传输方式为 HTTP（Streamable HTTP）的 MCP Server | 普通 HTTP openapi 网关，`{"action","params"}` 私有协议，非 MCP Tool schema | ❌ 未实现 MCP 封装 |
| 已上架并分配 `server_key` | 无 `server_key` | ❌ 未上架 |
| OAuth 授权码 + PKCE，回调地址加白 `wukong-cn://mcp-oauth` 等三个地址 | 自建 OAuth，回调为本地一次性 `http://127.0.0.1:<随机端口>/cb` | ❌ 未走客户端标准 OAuth 流程 |

**为什么不先写一个 `.mcp.json` 占位**：白皮书明确指出「这里声明的连接器必须是已经上架的连接器的 Server Key。键名写错不会报错，但用户安装套件后会看到一个连不上的数据连接项」。为避免给用户呈现一个永久连不上的数据连接项，本期不声明 `.mcp.json`。

**待接入计划**（需与千问办公侧确认优先级）：

1. 将 `yt-xd-lite` openapi 封装为标准 MCP Server，把上表 6 个 action 暴露为独立 Tool 并补全 name/description/参数 schema
2. 授权服务器完成客户端标识与三个 `redirect_uri` 加白（`wukong-cn://mcp-oauth`、`https://nango.wukong.cn/oauth/callback`、`https://nango-cn-main-3uvzij.mulerun.cn/oauth/callback`），支持授权码 + PKCE（S256）与 `refresh_token`
3. 以 `maps_location` 或 `industry_data` 分类提交连接器上架，取得 `server_key`
4. 套件补 `.mcp.json` 并在提交表单勾选「引用连接器」，技能内 Step 0 改为 `qw_query` 连接器就绪性检查

**首期降级处理**：在连接器上架前，四个技能沿用现有网关直连 + 自建 OAuth 路径运行，功能完整可用。按白皮书原则一「保留场景，标注能力待接入」，不因形态未对齐而删减任何场景。

## 三、降级方案（无连接器/数据不可用时）

技能层的完整降级规则见 [`references/gateway-auth.md`](./references/gateway-auth.md) 的「数据不可用时的降级原则」。摘要：

| 情况 | 降级动作 |
|------|---------|
| 网关不可达 / 502 持续 | 明确告知"选址数据服务暂时不可用"，说明已完成到哪一步，建议稍后重试；**不得用常识编造五维分数** |
| 登录超时 / 用户放弃授权 | 说明"未完成授权，无法获取选址数据"，询问是否改为仅做定性建议（并声明无数据支撑） |
| POI 检索不到 | 反问更精确的店名/商场名/详细地址，不自行猜相近 POI |
| 某个 module 无返回 | 只解读已返回模块，缺失维度标注"该维度数据本次未返回"，不推断补全 |
| 配额不足（`2001`） | 提示充值，说明同参数 MD5 幂等不重复扣费 |
| session 失效（`19002`/`1001`） | 自动重走 OAuth，**仅重试 1 次**，第二次失败则中止报错 |
| 账号被冻结（`19003`） | 提示联系管理员，**不重登** |

**降级红线**：任何降级路径下都不得虚构五维分数、潜客数量、同业门店数等接口数据。缺数据就说缺数据。

## 四、风险动作确认门

本套件的四个技能**均为只读查询与分析类能力**，不涉及写入、发送、提交、下单、改价、发布、退款、审批、对外通知等对外部系统产生副作用的动作。因此不存在外部系统写操作确认门。

需要确认门的环节如下：

| 环节 | 所在技能 | 确认门设计 |
|------|---------|-----------|
| OAuth 授权 | 全部（Step 0） | 由用户在浏览器中主动完成登录，技能不代持凭据、不向用户索要 token |
| 配额消耗 | 全部 | 每次评估查询会消耗配额；配额不足时提示充值而非静默失败 |
| 经营假设参数确认 | 立项报告 | 投资预算、租金、客单价直接影响结论，生成前须向用户确认实际数字；用户给不出时用行业参考值并在报告中显著标注"待实际数据替换" |
| 报告导出/对外发送 | 立项报告 | 如用户要求导出为文件或对外发送，须再次确认输出路径与用途 |
| 点位歧义确认 | 点位评估、多点位对比 | POI 检索有多个相似结果时，列出候选让用户确认，不自行选定 |

## 五、本地凭据与数据安全

| 项目 | 说明 |
|------|------|
| 本地存储内容 | 仅存 `session_token`（`gwst_` 前缀）与 `created_at` |
| 明确禁止存储 | `access_token` / `refresh_token` / `mobile` / `expires_in`（仅网关侧持有） |
| 存储路径 | macOS/Linux `~/.config/yt/oss.json`；Windows `%APPDATA%\yt\oss.json`；沙箱降级到工作目录 `.yt/oss.json` |
| 文件权限 | `chmod 600`（在支持的环境下） |
| 同步目录限制 | 禁止存放在 iCloud / OneDrive / Dropbox 等同步目录 |
| 租户边界 | 技能层不持有 `X-Access-Key` / `X-Tenant-Id` / `X-User-Id`，由网关侧按 session token 反查注入 |
| 错误信息 | 不回显密钥或完整请求体 |
