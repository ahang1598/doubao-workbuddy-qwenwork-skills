# 自学习分析引导

> 本文件在工作流 2 Phase 2（自学习分析）时读取。
> 作用：引导 AI 对项目产物进行开放式深度分析，提取有价值的可复用知识。
> ⚠️ 核心理念：不局限于固定维度，基于实际执行过程和产物去深度挖掘。

---

## 分析逻辑：三层递进

```
第一层：What（发生了什么）
  → 客观提取本次项目中的事实、选择、产出

第二层：Why（为什么有效/无效）
  → 分析背后的原因、规律、因果关系

第三层：So What（对未来的指导）
  → 生成可在下次直接复用的建议和知识
```

每条知识都应该能回答：**"下次什么场景能用？怎么用？"**

---

## 分析方法

### 步骤 1：逐文件阅读

按以下顺序阅读项目目录下的所有产物：
1. `metadata.json` — 获取结构化信息
2. `step_01_brief.md` — 理解产品卖点分析
3. `step_02_creative.md` — 理解创意方案
4. `step_03_script.md` — 理解脚本草稿
5. `final_script.md` — 查看最终交付脚本

### 步骤 2：捕捉信号

在阅读过程中，关注以下信号（但不局限于此）：

| 信号类型 | 什么时候出现 | 提取什么 |
|---------|------------|---------|
| 做了选择 | 在多个方案中选了一个 | 选择依据 → 决策规律 |
| 效果好 | 某个做法产出了好结果 | 为什么好 → 可复用模式 |
| 被否定/打回 | 方案被用户否定或合规打回 | 为什么失败 → 避坑经验 |
| 获得启发 | 从参考资料中获得了灵感 | 什么参考有效 → 参考推荐 |
| 用户偏好 | 用户的反馈、选择、态度 | 偏好模式 → 用户画像 |
| 创新做法 | 以前没有的新角度、新方法 | 新知识 → 方法论迭代 |
| 意外发现 | 过程中的意外收获 | 新规律 → 沉淀为知识 |

### 步骤 3：追问复用性

对每条提取的知识，必须追问：
- 下次什么情况下可以复用？
- 复用时需要什么前提条件？
- 这条知识属于哪个类别？（用于决定写入位置）

## 参考分析维度

以下维度仅为引导思考方向，**不是必须逐一回答的清单**。任何有价值的认知都应提取。

### 内容维度

- **脚本结构与骨架**
  - 最终脚本属于什么类型？
  - 结构骨架是什么？（如：痛点引入 → 产品出场 → 功能演示 → 效果对比 → CTA）
  - 各段时长占比？节奏如何？

- **Hook/钩子策略**
  - 用了什么类型的 Hook？
  - Hook 的具体文案是什么？
  - 设计意图是什么？为什么选这种？

- **卖点策略**
  - 原声卖点有几个？最终选了哪几个？
  - 卖点的表达方式？（直述 / 类比 / 场景化 / 数据化 / 对比竞品）
  - 用户在卖点选择环节的偏好

- **创作技巧**
  - 叙事手法、情绪节奏、视觉设计
  - 有没有特别巧妙的创作方式

### 行业/平台维度

- **行业/品类认知**
  - 目标受众特征（年龄、痛点、消费场景）
  - 高频关键词
  - 竞品内容特点
  - 用户关心什么

- **平台适配**
  - 针对目标平台做了哪些适配？
  - 平台的内容规则或限制
  - 平台的流量逻辑对内容的影响

### 过程维度

- **决策规律**
  - Brief → 脚本类型的选择依据
  - 爆款视频分析中的共性发现
  - 卖点排序的决策逻辑

- **方法论迭代**
  - Brief 分析方法有没有新的有效做法？
  - 视频分析方法有没有新角度？
  - 卖点提炼方式有没有优化？
  - 脚本生成策略有没有新发现？

- **合规经验**
  - 本次合规检测命中了什么规则？
  - 如何修改规避的？经验是否可复用？

### 关联维度

- **品类-结构关联**：什么品类适合什么脚本结构？
- **卖点-表达关联**：什么类型卖点用什么方式呈现效果好？
- **Hook-平台关联**：什么平台上什么 Hook 更有效？
- **行业-风格关联**：什么行业适合什么调性？

### 反面维度

- **失败方案**：被否定的原因、下次如何避免
- **用户负反馈**：不满意什么、期望是什么
- **合规踩坑**：什么表述容易触发、如何修改

---

## 分析原则

1. **开放式挖掘**：维度列表仅为引导，任何有价值的认知都应提取，不被列表限制
2. **重质量不重数量**：一条高质量的可复用规律 > 十条流水账式记录
3. **面向复用**：每条知识必须回答"下次什么场景能用？怎么用？"
4. **对比历史**：如果资产库中已有相关知识，对比本次案例是验证、推翻还是补充
5. **标注置信度**：
   - 基于 1 个案例 → 标为"初步发现"
   - 基于 3+ 个案例 → 标为"规律"
   - 被数据验证 → 标为"已验证"

## 写入位置映射

分析完成后，按知识类别写入对应位置：

| 知识类别 | 写入位置 |
|---------|---------|
| 脚本结构 | `patterns/script-structures/{类型名}.md` |
| Hook/钩子 | `patterns/hooks/{Hook类型}.md` |
| 卖点策略 | `patterns/selling-points/{卖点类型}.md` |
| 创作技巧 | `patterns/creative-techniques/{技巧名}.md` |
| 行业/品类知识 | `industry/{行业}/` 下各子文件 |
| 平台规律 | `patterns/platform-rules/{平台}.md` |
| 方法论迭代 | `patterns/methodologies/{对应文件}.md` |
| 品类-结构关联 | `industry/{行业}/what_works.md` |
| 失败经验 | 对应主题文件的"踩坑记录"段 |
| 合规经验 | `references/compliance_rules.md` 或对应文件 |
