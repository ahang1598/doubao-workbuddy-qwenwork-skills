# 选题报告输出模板（Step 3 强约束）

本文件是 SKILL.md Step 3 的**结构契约**。**报告结构、表头字段、信源标签格式、保存路径全部以本文件为准**，禁止自由发挥。

---

## 报告整体结构（5 个固定区块，缺一不可）

```
# {{topic}} 内容雷达报告 - {{YYYY-MM-DD}}

## 0. 本轮说明
（描述本轮采集了哪些平台、跳过了哪些平台及原因，以及环境/能力降级说明）

## 1. 选题总览
（固定 4 列总览表）

## 2. 选题详情
（每个选题 6 个子区块）

## 3. 数据来源汇总
（按平台列出本轮采集的原始数据条数）

## 4. 已知限制与建议
（对未采集平台的诚实标注 + 用户后续行动建议）
```

---

## 区块 0：本轮说明（强制必填）

```markdown
## 0. 本轮说明

- **采集引擎**：mcp-autocli MCP（v0.1.7+）
- **采集时长**：{{X 分钟}}
- **本轮采集平台**：{{HackerNews ✓, Lobsters ✓, 小红书 ✓, ...}}
- **本轮跳过平台**：{{Twitter ✗（原因：登录态失效，本轮跳过）, ...}}
- **环境说明**：{{如：因仅国内网络，本轮跳过所有海外平台}} / {{如：follow_list.weibo 暂不支持，本轮已跳过}}
```

> ⚠️ **诚实标注硬约束**：跳过的平台**必须列出来**，禁止假装"全部成功"。这是用户判断报告完整度的关键依据。
>
> ⚠️ **采集引擎字段**：必须写 `mcp-autocli MCP（v0.1.7+）`。

---

## 区块 1：选题总览（固定 4 列）

```markdown
## 1. 选题总览（共 {{N}} 个候选，按推荐分降序）

| 序号 | 推荐选题 | 推荐理由（≤30 字）| 推荐分数 |
|------|----------|------------------|----------|
| 1 | {{选题标题}} | {{一句话理由}} | {{0-100}} |
```

> ⚠️ 选题数量**必须 5-8 个**。
> - 少于 5 个 → 说明数据不足，应在区块 0 标注"本轮数据不足"；不要硬凑
> - 多于 8 个 → 必须按分数砍到 8 个，不要堆砌

---

## 区块 2：选题详情（每个选题 6 个子区块，缺一不可）

```markdown
### 选题 {{序号}}：{{选题标题}}

#### 📊 信息速览
- **推荐分数**：{{0-100}}（信息差 {{X}}/30 + 受众匹配 {{X}}/30 + 可操作性 {{X}}/20 + 时效性 {{X}}/20）
- **舆情判断**：{{正向热议 / 负向吐槽 / 中性讨论 / 争议拉扯}}
- **事件时效**：{{当日 / 近 3 日 / 近 7 日 / 持续话题}}
- **适合的内容角度**：{{对比测评 / 实操教程 / 深度解读 / 趋势盘点 / 避坑指南}}

#### 💡 推荐理由
（150-300 字，回答"为什么是现在做这个选题"）

#### 🔥 需求证据（来自需求侧平台）
- [{{条目标题}}]({{完整 URL}}) 🟢 {{平台中文名}} | 互动 {{数字}}
- [{{条目标题}}]({{完整 URL}}) 🟡 {{平台中文名}} | 互动 {{数字}}

#### 📚 参考材料（来自供给侧）
- [{{条目标题}}]({{完整 URL}}) 🟢 {{平台中文名}}
- [{{条目标题}}]({{完整 URL}}) 🟢 {{平台中文名}}

#### 🏷 信源标签综合
{{🟢 一手 X 条 / 🟡 二手 X 条}}

#### 🎬 建议怎么做
（结合用户 `role` 和 `style` 给 2-3 个具体切入方式，每条 1-2 行）
```

> ⚠️ **每个选题必须满足**：
> - 需求证据 ≥ 2 条
> - 参考材料 ≥ 2 条
> - 所有链接必须是 `[标题](完整 URL)` 格式，禁止裸 URL
> - 所有条目必须带信源标签（🟢/🟡）
> - 不满足以上任一条 → 该选题**禁止入选**，从总览表移除

## 区块 4：已知限制与建议

```markdown
## 4. 已知限制与建议

### 本轮限制
- {{如：Twitter 登录态失效 → Twitter / X 数据缺席}}
- {{如：因仅国内网络，本轮跳过所有海外平台}}
- {{如：follow_list.weibo / follow_list.youtube 暂不支持，配置已跳过}}

### 提升报告质量的建议
- {{如：在悟空对话框说"重新登录 twitter"，技能会调 launch_login 打开 Edge 登录页，登录后重新触发本技能即可拿到 Twitter 数据}}
- {{如：在 my-radar.yaml 中调高 platforms.weight 可优先处理某些平台}}
- {{如：在 my-radar.yaml 中补充 keywords_cn / keywords 关键词，可显著提升相关度}}
```

> 重新登录走 `launch_login` MCP 流程话术。

## 信源标签详细规范

| 标签 | 含义 | 适用场景 |
|------|------|----------|
| 🟢 一手 | `mcp-autocli.search` 直接命中的条目 | HN / Lobsters / Dev.to / SO / Arxiv / HF / Wikipedia / 小红书 / B站 / 抖音 / 微博 / Twitter / YouTube / Instagram |
| 🟡 二手 | `web_search` 兜底 / RSS 订阅源 | 某平台 search 失败后用 web_search 补的引用、`rss_feeds` 抓到的条目 |

> ⚠️ **未带标签的条目禁止落盘** —— 这是报告落盘前的最后一道质检。

---

## 报告保存（Step 3 末尾的强制动作）

报告生成完毕后，将报告内容直接写入 `output/radar_{{topic}}_{{日期}}.md`，向用户告知最终路径。

> 注：报告保存为只读输出动作，**不需要 Y/N 确认**。同名文件直接覆盖（同日多次运行视为最新结果）。
