# 场景执行指南

本文件是 SKILL.md 中场景一/二/三的详细执行步骤。每个场景按线性指令链编写，Agent 从头到尾逐步执行，不需要在多个文件之间跳转。场景四的执行细节已在 `calibration-protocol.md` 中完整定义，此处不重复。

---

## 场景一：首次学习风格（≥3 篇原创）

**前置条件**：`material_scanner.py` 输出 `scene = "场景一：首次学习"`，`original_files` 列出 ≥3 个文件。

### Step 0：干扰项检查（可选）

在开始分析前，检查 `material_scanner.py` 输出的 `unrecognized_files` 字段。
*   **如果存在压缩包类文件**（`.zip`, `.rar`, `.7z` 等），且标记为 `source: "upstream"`：
    *   **引导话术**：“检测到你的原创素材库中有未解压的素材包（如 xxx.zip）。为了更准确地学习你的风格，建议先解压这些文件，然后重新运行本技能。”
    *   **决策点**：询问用户是否继续分析现有文本素材，还是等待解压后重试。
*   **如果不存在或用户选择继续**：直接进入 Step 1。

### Step 1：选取样本

从 `original_files` 列表中选取 3-10 篇作为分析样本。

**选取规则**：
1. **话题覆盖优先**：如果文件名或首段内容涉及不同话题，优先选取覆盖话题最广的组合
2. **数量上限**：最多选 10 篇。超过 10 篇时，按文件修改时间取最近的 10 篇
3. **数量下限**：至少 3 篇。如果恰好 3 篇，全部选取
4. **格式处理**：对非纯文本文件（.docx / .pdf / 图片），先按 `references/content-sources.md` 的对应方式提取纯文本，保存为临时 `.txt` 文件供后续脚本使用

**执行动作**：
```
对每个选中的样本文件：
  ├─ .txt / .md → 直接读取
  ├─ .docx / .pdf → parse_file(file_path, query="提取文档正文内容")
  ├─ .png / .jpg / .jpeg / .webp → understand_media(media_path, question="请提取图片中的所有文字内容，保持原始排版格式")
  └─ 将提取的纯文本保存为临时文件：<工作区>/tmp/style_sample_<序号>.txt
```

### Step 2：单篇分析（逐篇执行）

对每篇样本依次执行定量统计 + 定性分析，产出单篇风格卡片。

**2a. 定量统计**：
```bash
.venv/bin/python scripts/quantitative_analysis.py --input <临时文件路径>
```
读取输出 JSON，记录 `avg_sentence_length`、`sentence_length_std`、`type_token_ratio`、`avg_paragraph_length`、`paragraph_count`。

**2b. 定性分析**（LLM 执行）：

对每篇内容使用以下 prompt：
```
请分析以下原创内容的写作风格特征，从 5 个维度逐一输出：

1. **语气调性**：这篇内容的整体语气是什么？（正式/口语/犀利/温暖/戏谑/教学/...）
   给出 1-2 个原文例句作为证据。

2. **视角和人称**：作者用什么人称？是否直接对话读者？
   统计"我""你""我们"的使用频率。

3. **修辞手法**：作者最常用的表达技巧是什么？（类比/反问/列表/故事/数据引用/对比/...）
   每种手法给出 1 个原文例句。

4. **标志性表达**：有没有反复出现的口头禅、固定句式、特殊标点用法？
   逐一列出，附原文位置。

5. **开头/结尾习惯**：文章是怎么开头的？怎么结尾的？有没有固定模式？

---
原文内容：
{content}
```

**2c. 合并为风格卡片**（内部中间产物，不展示给用户）：
```json
{
  "source": "《文章标题》",
  "quantitative": { /* 脚本输出 */ },
  "tone": "口语化、直接",
  "perspective": "第二人称'你'为主",
  "rhetoric": ["类比", "反问"],
  "signature_expressions": ["说白了就是…", "选错了等于白…"],
  "opening_pattern": "直接抛结论",
  "closing_pattern": "行动建议收尾"
}
```

将所有风格卡片合并为 JSON 数组。**注意**：如果上游 `quantitative_analysis.py` 输出的是包含 `files` 键的对象格式，聚合脚本会自动识别并提取。保存为 `<工作区>/tmp/style_cards.json`。

### Step 3：跨篇提炼

```bash
.venv/bin/python scripts/cross_sample_aggregator.py --input <工作区>/tmp/style_cards.json
```

读取脚本输出 JSON。**兼容性说明**：该脚本已内置格式适配器，能同时处理标准的 JSON 数组和上游技能直出的 `{ "files": [...] }` 对象结构。如果 `contradictions` 不为空，LLM 需判断：
- 检查矛盾特征是否与话题/场景相关（如教程类偏正式、测评类偏口语）
- 若场景相关 → 标注"视场景切换"
- 若无规律 → 取多数方向，少数标注为偶发

### Step 4：反面提取

检查 `material_scanner.py` 输出的 `reference_count`：

**有参考素材（reference_count > 0）**：
1. 从 `素材库/参考素材/` 读取参考素材（提取方式同 Step 1）
2. 对参考素材做同样的定性分析（仅关注措辞和表达模式）
3. 交叉对比：参考素材中出现 ≥3 次但用户原创中 0 次的词汇/句式 → 禁用清单
4. 每条标注来源证据，如：`← 参考素材中出现 8 次，用户原创 0 次`

**无参考素材（reference_count = 0）**：
1. 从用户原创内容中反向推断：用户是否刻意回避某些常见表达？
2. 与同领域"通用写法"对比，用户明显缺失的表达模式
3. 标注 `[基于原创推断]`，置信度较低


### Step 5：生成说明书草稿

**5a. 生成元信息头**：
```bash
.venv/bin/python scripts/spec_metadata.py init --sample-count <样本数> --changelog "基于N篇原创内容首次生成"
```
将输出的 JSON 转为 YAML front-matter 放在说明书头部。

**5b. 按模板填充 6 个模块**（→ 格式规范见 `references/style-spec-template.md`）：

| 模块 | 数据来源 | 填充方式 |
|------|----------|----------|
| 整体调性 | Step 2 定性分析汇总 | LLM 用一个比喻概括，2-3 句话 |
| 语气与视角 | Step 3 脚本输出 `tone_distribution` | 从稳定项中提取，附原文证据 |
| 句式与节奏 | Step 3 脚本输出 `quantitative_summary` | 定量数据 + LLM 定性描述 |
| 标志性表达 | Step 3 脚本输出 `signature_expressions.stable` | 直接提取，附原文出处和频率 |
| 禁用清单 | Step 4 反面提取结果 | 逐条列出，附来源证据 |
| 验证样本 | 原创内容 | LLM 选取 2-3 段最具代表性段落（50-150 字/段，覆盖不同话题） |

**5c. 质量检查**：
```bash
.venv/bin/python scripts/spec_validator.py --input <说明书文件路径>
```
如果检查不通过（某模块为空或验证样本不足），补充对应内容后重新检查。

LLM 额外自检：
- 每个模块都有原文证据支撑，不是凭空概括
- 整体调性的比喻/描述是否精准传神

### Step 6：展示风格对比

这是用户最直观感受风格差异的环节，**必须在展示说明书之前执行**。

**6a. 选择对比话题**（按优先级依次判断）：

1. **标志性表达最密集的话题**：回看 Step 1 的风格卡片，找 `signature_expressions` 数量最多的那篇，用它的话题。理由：标志性表达越密集，说明用户在这个话题上"个人味"最浓，对比效果最明显。
2. **如果多篇并列**（标志性表达数量相同）：选 `sentence_length_std`（句长标准差）最大的那篇话题。标准差大 = 长短句交替明显 = 节奏感强 = 风格辨识度高。
3. **如果仍然并列**：选文件列表中最后一个（最近创建/修改的），与用户当前关注点最近。

**6b. 写「通用版」**：
- 刻意使用用户禁用清单里的词
- 用标准书面语、正式语气
- 句式工整，不带个人特色

**6c. 写「用户风格版」**：
- 严格按生成的说明书来写
- 使用用户的标志性表达
- 模仿用户的句式节奏

**6d. 展示话术**：
```
我看了你「我的创作」里的 {N} 篇内容，发现你的写作有一些很明显的特点。
我帮你整理成一份《风格说明书》，以后帮你写内容的时候就按这个风格来。
先给你看个对比——同一个选题，我用两种风格各写一段：

**通用版**：
{通用版内容}

**你的风格版**：
{风格版内容}

看出区别了吗？你的风格特点是：{1-2 句话概括核心特征}。
我生成了一份完整的《风格说明书》，你看看哪里需要调整？
```

### Step 7：用户确认与保存

**7a. 展示说明书**：
- 逐模块展示，重点关注：整体调性描述、标志性表达、禁用清单
- 每个模块后可附一句"这个准确吗？"

**7b. 收集反馈**：
- 用户可能说"语气应该更直接一些""这个词我其实会用"等
- 按反馈逐条修改说明书对应字段

**7c. 保存**：
- 将最终版说明书保存到悟空记忆
- 完成后话术：`好的，《风格说明书》已保存。以后帮你写内容时会按这个风格来，你随时可以让我更新。`

## 场景二：原创内容不够（1-2 篇）

**前置条件**：`material_scanner.py` 输出 `scene = "场景二：内容不够"`，`original_files` 列出 1-2 个文件。

### Step 1：简化版风格提取

与场景一的区别在于：样本少，部分步骤需要降级处理。

**1a. 内容提取**：与场景一 Step 1 相同，将文件提取为纯文本。

**1b. 单篇分析**：与场景一 Step 2 完全相同——每篇都做定量统计 + 定性分析，产出风格卡片。

**1c. 跨篇提炼（降级处理）**：
- 如果只有 **1 篇**：跳过 `cross_sample_aggregator.py`，直接使用单篇风格卡片作为初步结论。所有特征标注 `[待验证-仅1篇样本]`。
- 如果有 **2 篇**：正常调用 `cross_sample_aggregator.py`，但脚本输出的 `confidence` 会自动标为 `low`。两篇都出现的特征标为"初步确认"，仅一篇出现的标为 `[待验证]`。

**1d. 反面提取（可选）**：
- 有参考素材 → 正常执行（同场景一 Step 4）
- 无参考素材 → 跳过此步，禁用清单留空，标注"待补充更多样本后生成"

### Step 2：生成低置信度说明书

**2a. 生成元信息头**：
```bash
.venv/bin/python scripts/spec_metadata.py init --sample-count <1或2> --changelog "基于N篇原创内容生成初步风格画像"
```
输出的 `confidence` 会自动为 `low`。

**2b. 按模板填充**：与场景一 Step 5b 相同，但需在不确定的特征后标注 `[待验证]`。

**标注规则**：
- 仅在 1 篇中出现的特征 → `[待验证-仅1篇样本]`
- 2 篇中出现但方向不一致 → `[待验证-样本矛盾]`
- 无参考素材导致禁用清单为空 → 整个模块标注 `[待补充]`

**2c. 质量检查**：同场景一 Step 5c，但允许禁用清单为空（标注了 `[待补充]` 即可）。

### Step 3：展示初步画像

**不做完整的风格对比**（样本太少，对比不够有说服力），改为直接展示初步画像。

**展示话术**：
```
你目前「我的创作」里只有 {N} 篇内容，我能看出一些倾向，但还不够准确。

我先生成一份初步的风格画像，标注了哪些判断是确定的、哪些还需要更多样本验证：

{逐模块展示，[待验证] 标记用醒目格式}

你后续多写几篇，我会自动检测并更新。你也可以：
1. 把你在小红书/公众号上发过的内容链接发给我
2. 现在随便写一段你擅长的话题——不用长，三五百字就行
```

### Step 4：保存并设置自动更新

- 保存低置信度说明书到悟空记忆
- **自动更新机制**：后续每次触发本技能时，`material_scanner.py` 会重新扫描 `素材库/我的创作/`。若检测到新增内容（文件数 > 说明书的 `sample_count`），主动提议更新：

```
你的「我的创作」里多了 {新增数} 篇新内容，要不要我重新分析，更新你的《风格说明书》？
```

用户同意后，按场景一的完整流程重新执行（此时样本数已 ≥3）。

## 场景三：没有原创内容 / 用户主动提供素材

`material_scanner.py` 输出 `scene` 为 `"场景三：引导提供素材"` 或 `"场景三：用户主动提供素材"` 时进入。

### 分支 A：用户已主动提供了内容（文本/文件/链接）

当 `scene = "场景三：用户主动提供素材"` 时执行。

**Step A1：识别来源类型**：
```bash
.venv/bin/python scripts/content_classifier.py --input "<用户提供的URL或文件路径>"
```
读取输出的 `source_type` 和 `extraction_command`。

**Step A2：提取内容**：
按 `extraction_command` 的指引提取纯文本。如果是小红书链接，按 `references/content-sources.md` 的 xhs-content-reader 调用流程执行。

**Step A3：保存到素材库**：
将提取的内容保存到 `素材库/我的创作/` 路径下（文件名保留原标题或用时间戳命名）。

**Step A4：判断走场景一还是场景二**：
统计 `素材库/我的创作/` 中的总文件数（包括本次新增的）：
- 总数 ≥3 → 按**场景一**的 Step 1 开始执行
- 总数 1-2 → 按**场景二**的 Step 1 开始执行

**Step A5：检查无法识别的文件**：
如果 `material_scanner.py` 返回的 `unrecognized_files` 不为空，Agent 需主动提示用户：
```
我扫描了你的文件夹，发现以下文件暂时无法直接读取：
{列出文件名及类型，如：xxx.zip (压缩包), yyy.exe (程序)}

建议你：
- 如果是压缩包，请先解压后再让我扫描。
- 如果是其他格式，请确认是否为文档或图片。
```

**衔接话术**（提取成功后）：
```
好的，我已经提取了 {来源描述} 的内容。加上之前的，你现在「我的创作」里共有 {总数} 篇内容。
{总数≥3: "够了，我来帮你分析风格。"}
{总数<3: "还需要更多内容才能准确分析，我先基于现有的做个初步画像。"}
```

### 分支 B：没有任何内容

当 `scene = "场景三：引导提供素材"` 且用户没有在当前对话中提供内容时执行。

**Step B1：引导话术**：
```
要学你的风格，我需要看到你自己写的东西——收藏的同行内容不算，那不是你的表达。

你可以通过以下方式提供素材：
1. **发送链接或文件**：把你在小红书/公众号上发过的内容链接发给我，或者直接上传 Word/PDF/图片文件。
2. **手动输入文本**：现在随便写一段你擅长的话题——不用长，三五百字就行，就按你平时的习惯写。
3. **指定本地路径**：如果你本地已经有整理好的素材库（例如之前通过其他方式归档的 Markdown 或文本文件），可以直接告诉我文件夹的路径。**请确保该文件夹内包含 .md, .txt, .pdf 等可读文本文件，压缩包请先解压。**
```

**Step B2：等待用户响应**：
- 用户提供了链接/文件/文本 → 转入**分支 A** 的 Step A1
- 用户表示没有内容 → 回复：

```
没关系，你可以先用我帮你写几篇内容，写完之后修改成你满意的版本，
然后告诉我「学习我的风格」，我就能从你修改后的版本中提取你的风格了。
```

## 场景间衔接速查

| 当前状态 | 下一步 |
|----------|--------|
| 场景三分支 A 提取成功，总数 ≥3 | → 场景一 Step 1 |
| 场景三分支 A 提取成功，总数 1-2 | → 场景二 Step 1 |
| 场景二保存后，用户后续新增内容 ≥3 | → 场景一 Step 1（完整重新分析） |
| 场景一/二完成后，用户对初稿做了修改 | → 场景四（见 `calibration-protocol.md`） |
