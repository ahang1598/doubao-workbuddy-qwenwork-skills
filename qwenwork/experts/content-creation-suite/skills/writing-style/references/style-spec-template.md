# 风格说明书模板

本文件定义《风格说明书》的完整格式。生成或更新说明书时，严格按此模板填充。

---

## 元信息头

每份说明书必须包含以下 YAML front-matter，用于版本管理和增量更新：

```yaml
---
version: 1                    # 版本号，每次更新 +1
sample_count: 5               # 分析的原创样本数量
confidence: high               # high(≥5篇) / medium(3-4篇) / low(1-2篇)
created_at: "2026-04-14"      # 首次生成日期
updated_at: "2026-04-14"      # 最近更新日期
changelog:
  - "v1: 基于5篇原创内容首次生成"
  - "v2: 根据用户反馈调整语气描述，新增禁用词3个"
---
```

**confidence 判定规则**：
- `high`：≥5 篇样本，覆盖 ≥2 个不同话题
- `medium`：3-4 篇样本，或话题单一
- `low`：1-2 篇样本，多数特征标注 `[待验证]`

## 说明书正文（6 个模块）

### 模块一：整体调性

一段话概括这个人写东西的感觉——用一个比喻或一句话让 LLM 快速理解。

**示例**：
> 像一个懂行的朋友在饭桌上跟你聊天——不端架子，但说的都是干货。偶尔毒舌，但出发点是帮你避坑。

**写法要求**：
- 必须用比喻或场景描述，不能用抽象标签堆砌
- 控制在 2-3 句话以内
- 这段话会作为 LLM 的第一印象锚点，所以要精准传神

### 模块二：语气与视角

用结构化列表描述，每项附带从原文中提取的证据：

```markdown
## 语气与视角
- **主要语气**：口语化、直接 ← 出自多篇，如"说白了就是…"
- **人称习惯**：直接"你"对话读者 ← 《玻尿酸选购指南》中 12 次使用"你"
- **情绪节奏**：先抛结论再展开 ← 5 篇中有 4 篇首段即给出核心观点
- **态度倾向**：帮读者避坑的立场 ← "选错了等于白涂""踩过的坑告诉你"
```

### 模块三：句式与节奏

定量数据 + 定性描述结合：

```markdown
## 句式与节奏
- **平均句子长度**：约 18 字（标准差 8.2，说明长短交替明显）
- **节奏特征**：短句为主，偶尔用长句做解释；喜欢用破折号插入补充说明
- **段落习惯**：每段 2-4 句，一个观点一个段落，不堆砌
- **标点特征**：大量使用破折号（——）和省略号（……），几乎不用分号
```

**数据来源**：`scripts/quantitative_analysis.py` 的输出结果。

### 深度分析指标解读指南（V2.0）

为了让《风格说明书》更具洞察力，Agent 在填充上述模块时，应参考以下维度对数据进行“语义化翻译”：

| 维度 | 核心指标 | 解读逻辑（如何转化为人话） |
| :--- | :--- | :--- |
| **认知与逻辑密度** | `information_entropy` (信息熵) | > 7.0 为高密度干货型（适合硬核读者）；< 6.5 为情绪叙事型（适合大众共鸣）。 |
| | `logic_connectors` (逻辑词) | “因为、所以、本质上”多 → 严谨推导型；“然后、其实”多 → 随性聊天型。 |
| **情感曲线与共鸣点** | `empathy_triggers` (共情词) | 识别出“说实话、避坑、太难受了”等词，标记为“高共鸣触发器”，建议在标题中强化。 |
| | `sentiment_score` (情感极性) | 持续正向 → 鼓励型博主；波动剧烈 → 剧情/吐槽型博主。 |
| **平台适配性诊断** | `xhs_fit_score` (小红书适配) | 分数低但用户想发小红书时，建议增加 Emoji 密度并缩短单句长度。 |
| | `zhihu_bilibili_fit_score` | 分数高说明内容具有深度或专业感，适合长图文或中长视频脚本。 |
| **修辞与记忆锚点** | `potential_golden_quotes` | 提取出的金句应直接放入“验证样本”或作为“标志性表达”的补充。 |
| | `repeated_keywords` | 反复出现的词汇构成了用户的“口头禅系统”，是风格辨识度的核心。 |

**应用示例**：
> “你的内容**信息熵高达 7.2**，说明单位字数内的干货极多。虽然这让你的**知乎适配度很高**，但在小红书上可能会让读者觉得‘有点累’。建议在排版上多用空行和 Emoji 来调节阅读节奏。”

### 模块四：标志性表达

从用户原文中提取反复出现的标志性表达，**必须附原文出处**：

```markdown
## 标志性表达
- "说白了就是……" ← 出自《玻尿酸选购指南》《防晒霜测评》（3/5 篇出现）
- "选错了等于白……" ← 出自《防晒霜测评》《面膜避坑》
- "你品，你细品" ← 出自《成分表解读》
- 喜欢用「」而非""做引号 ← 全部 5 篇均使用
```

**提取规则**：
- 在 ≥2 篇中出现的表达才纳入
- 仅出现 1 次的标记为 `[偶发]`，不放入正式清单
- 记录出现频率（如 3/5 篇）

### 模块五：禁用清单

从"用户原创 vs 参考素材"的对比中提取——参考素材中常见但用户从不用的表达：

```markdown
## 禁用清单
- 不用"赋能""抓手""底层逻辑"等商业黑话 ← 参考素材中出现 8 次，用户原创 0 次
- 不用"众所周知""不言而喻"等空洞过渡 ← 参考素材中出现 5 次，用户原创 0 次
- 不用被动句式（如"被广泛应用于"）← 用户全部使用主动句
- 不以问句结尾 ← 用户 5 篇文章无一以问句收尾
```

**重要性**：禁用清单是防止 AI "跑偏"的关键约束。AI 最常犯的错就是加入用户从不用的措辞。

**无参考素材时**：仅从用户原创内容中提取"明显回避的常见表达模式"，标注 `[基于原创推断]`。

### 模块六：验证样本

选取 2-3 段用户原文作为 few-shot 参考，供下游 LLM 生成时对照：

```markdown
## 验证样本

> "玻尿酸这东西说白了就是帮你的皮肤'抓水'的——大分子的锁住表面水分，小分子的渗透到里面去。选错了等于白涂。"
> ——《玻尿酸选购指南》

> "防晒霜不是越贵越好。我自己用了二十多款，最后常回购的就三款——一款日常通勤的，一款户外暴晒的，一款敏感肌专用的。"
> ——《防晒霜年度测评》

> [更多样本...]
```

**选取原则**：
- 优先选最能体现用户风格特征的段落
- 覆盖不同话题，避免全选同一篇
- 每段 50-150 字为宜，太短不够代表性，太长浪费 token

## 增量更新规则

当需要更新已有说明书时，遵循以下策略：

### 加权合并

```
新特征权重 = 新样本数 / (总样本数 × 1.5)
老特征权重 = 1 - 新特征权重
```

- 老特征有惯性，避免加一篇新文章就导致风格大变
- 矛盾特征（如某些文章正式、某些口语）标注"视场景切换"

### 更新触发条件

- 新增 ≥1 篇原创样本
- 累积 ≥5 次用户对 AI 初稿的修改
- 用户主动要求更新

### 更新后必做

1. `version` +1
2. `updated_at` 更新为当前日期
3. `sample_count` 更新为累计样本数
4. `confidence` 重新评估
5. `changelog` 追加本次更新摘要
