# 风格提取流程（五步详解）

本文件是 SKILL.md 中"风格提取流程"的完整执行指引。当进入场景一/二/三需要从原创内容中提取风格时，按此流程逐步执行。

---

## Step 1：单篇分析（每篇内容独立执行一次）

对每篇原创内容同时进行**定量统计**和**定性分析**，产出单篇风格卡片。

### 1.1 定量统计

执行脚本：
```bash
.venv/bin/python scripts/quantitative_analysis.py --input <文本文件路径>
```

输出 JSON 包含：
- `avg_sentence_length`：平均句子长度（字数）
- `sentence_length_std`：句子长度标准差（反映节奏感——标准差大=长短交替明显）
- `type_token_ratio`：词汇丰富度（0-1，越高越丰富）
- `avg_paragraph_length`：平均段落长度（句数）
- `paragraph_count`：段落总数

**注意**：如果输入是文件/链接，先用内容提取能力（见 `content-sources.md`）转为纯文本，再保存为临时文件传给脚本。

### 1.2 定性分析（LLM）

对每篇内容，使用以下 prompt 结构进行分析：

```
请分析以下原创内容的写作风格特征，从 5 个维度逐一输出：

1. **语气调性**：这篇内容的整体语气是什么？（正式/口语/犀利/温暖/戏谑/教学/...）
   给出 1-2 个原文例句作为证据。

2. **视角和人称**：作者用什么人称？是否直接对话读者？
   统计"我""你""我们"的使用频率。

3. **修辞手法**：作者最常用的表达技巧是什么？（类比/反问/列表/故事/数据引用/对比/...）
   每种手法给出 1 个原文例句。

4. **标志性表达**：有没有反复出现的口头禅、固定句式、特殊标点用法？
   逐一列出，附原文位置。
   **格式约束**：每个表达取最短的核心形式——
   - 同一口头禅有不同后缀时，只保留公共前缀（如"说白了就是…""说白了这个…"统一记为"说白了"）
   - 同一句式有不同宾语时，用省略号代替变化部分（如"选错了等于白涂""选错了等于白搭"统一记为"选错了等于…"）
   - 目的是确保跨篇聚合时同一特征不被重复计数

5. **开头/结尾习惯**：文章是怎么开头的？怎么结尾的？有没有固定模式？

---
原文内容：
{content}
```

### 1.3 产出：单篇风格卡片

将定量和定性结果合并为一张风格卡片（内部中间产物，不展示给用户）：

```json
{
  "source": "《玻尿酸选购指南》",
  "quantitative": { /* 脚本输出 */ },
  "tone": "口语化、直接",
  "perspective": "第二人称'你'为主",
  "rhetoric": ["类比", "反问"],
  "signature_expressions": ["说白了", "选错了等于…"],
  "opening_pattern": "直接抛结论",
  "closing_pattern": "行动建议收尾"
}
```

> **注意**：`signature_expressions` 取最短核心形式，省略号表示后续有不同变体。这样跨篇聚合时同一特征才能被正确合并计数。

---

## Step 2：跨篇提炼（多篇取交集）

**执行方式**：将所有单篇风格卡片合并为 JSON 数组，调用 `scripts/cross_sample_aggregator.py` 自动完成频率统计和定量汇总，LLM 只需解读矛盾项。

```bash
# 将所有风格卡片保存为 cards.json，然后执行：
.venv/bin/python scripts/cross_sample_aggregator.py --input cards.json
```

脚本输出 JSON 包含：
- `rhetoric.stable` / `rhetoric.occasional`：修辞手法按出现率分类
- `signature_expressions.stable` / `.occasional`：标志性表达分类
- `tone_distribution`：语气分布统计
- `quantitative_summary`：各定量指标的 mean/std/min/max
- `contradictions`：矛盾特征列表（需 LLM 判断是场景切换还是偶发）
- `confidence`：基于样本数的置信度

### LLM 仅需处理的部分

脚本输出中 `contradictions` 不为空时，LLM 需判断：
- 检查是否与话题/场景相关（如教程类偏正式、测评类偏口语）
- 若场景相关 → 标注"视场景切换"
- 若无规律 → 取多数方向，少数标注为偶发

---

## Step 3：反面提取（从参考素材中对比）

**目的**：找出"参考素材中有但用户自己从不用"的表达模式，生成禁用清单。

**参考素材来源**：`素材库/参考素材/` 目录——上游「素材管家」技能将用户收藏的同行内容保存在此路径。本步骤仅读取此目录做对比分析，**绝不从参考素材中学习风格**。

### 有参考素材时（`素材库/参考素材/` 路径存在且有内容）

1. 从 `素材库/参考素材/` 读取用户收藏的参考素材
2. 对参考素材做同样的定性分析（仅关注措辞和表达模式）
3. 交叉对比：
   - 参考素材中出现 ≥3 次但用户原创中 0 次的词汇/句式 → 禁用清单
   - 参考素材中常见的结构（如"首先…其次…最后…"）但用户从不用 → 禁用清单
4. 禁用清单每条标注来源证据，如：`← 参考素材中出现 8 次，用户原创 0 次`

### 无参考素材时（路径不存在或为空）

从用户原创内容中反向推断：
- 用户是否刻意回避某些常见表达？（如从不用被动句、从不用问句结尾）
- 与同领域"通用写法"对比，用户明显缺失的表达模式
- 标注 `[基于原创推断]`，置信度较低

---

## Step 4：生成风格说明书草稿

按 `references/style-spec-template.md` 的模板，将 Step 1-3 的结果填充为完整说明书。

### 填充顺序

1. **元信息头**：调用 `scripts/spec_metadata.py init` 自动生成：
   ```bash
   .venv/bin/python scripts/spec_metadata.py init --sample-count 5 --changelog "基于5篇原创内容首次生成"
   ```
   将输出的 JSON 转为 YAML front-matter 放在说明书头部。
2. **整体调性**：用一个比喻概括，这是最关键的一段，要反复打磨（LLM 完成）
3. **语气与视角**：从 Step 2 脚本输出的 `tone_distribution` 稳定项中提取
4. **句式与节奏**：用 Step 2 脚本输出的 `quantitative_summary` 数据 + LLM 定性描述
5. **标志性表达**：从 Step 2 脚本输出的 `signature_expressions.stable` 中提取，附原文出处
6. **禁用清单**：从 Step 3 的结果中提取
7. **验证样本**：从原创内容中选取 2-3 段最具代表性的段落（LLM 选取）

### 质量检查

生成后调用 `scripts/spec_validator.py` 自动检查完整度：
```bash
.venv/bin/python scripts/spec_validator.py --input <说明书文件路径>
```

脚本自动验证：
- [x] 元信息头完整（version/sample_count/confidence/日期）
- [x] 6 个模块全部非空
- [x] 禁用清单至少 3 条
- [x] 验证样本至少 2 段
- [x] confidence 与 sample_count 匹配

LLM 额外自检（脚本无法覆盖的语义质量）：
- [ ] 每个模块都有原文证据支撑，不是凭空概括
- [ ] 整体调性的比喻/描述是否精准传神

---

## Step 5：用户确认与保存

### 展示策略

1. **先展示风格对比**（这是用户最直观感受风格差异的方式）：
   - 选一个用户擅长的话题
   - 用「通用版」写一段（刻意用用户禁用清单里的词，用标准书面语）
   - 用「用户风格版」写一段（严格按说明书来）
   - 让用户自己感受差异

2. **再展示说明书**：
   - 逐模块展示，每个模块后问"这个准确吗？"
   - 重点关注：整体调性描述、标志性表达、禁用清单

3. **收集反馈**：
   - 用户可能说"语气应该更直接""这个词我其实会用"
   - 逐条修改后更新说明书

### 保存

确认完毕后，将最终版说明书保存到悟空记忆（MEMORY.md 或专用记忆文件）。

如果是更新已有说明书，调用 `scripts/spec_metadata.py update` 处理版本递增：
```bash
.venv/bin/python scripts/spec_metadata.py update \
  --current '<当前元信息JSON>' \
  --new-samples 2 \
  --changelog "根据用户反馈调整语气描述，新增禁用词3个"
```
