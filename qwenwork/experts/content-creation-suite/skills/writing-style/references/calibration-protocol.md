# 持续校准协议

本文件定义场景四「持续校准」的完整执行细节，包括 diff 记录格式、修改模式分析、说明书字段映射表和话术模板。

---

## 一、Diff 记录格式

每次用户对 AI 初稿做修改后，记录一条校准信号，格式如下：

```json
{
  "type": "style_calibration",
  "timestamp": "2026-04-14T17:00:00+08:00",
  "source_doc": "关于玻尿酸的科普文",
  "diffs": [
    {
      "category": "word_replace",
      "original": "因此，我们建议",
      "revised": "所以，",
      "context": "...大分子的锁住表面水分。因此，我们建议选择小分子..."
    },
    {
      "category": "sentence_split",
      "original": "玻尿酸是一种广泛应用于护肤品中的保湿成分，具有优异的锁水能力，能够有效改善肌肤干燥问题。",
      "revised": "玻尿酸就是帮皮肤锁水的。大分子锁表面，小分子渗透进去。",
      "context": "（首段）"
    },
    {
      "category": "tone_shift",
      "original": "建议消费者根据自身肤质选择合适的产品。",
      "revised": "选错了等于白涂，先搞清楚自己是干皮还是油皮。",
      "context": "（结尾段）"
    }
  ]
}
```

### Diff 分类体系（category 字段）

| category | 含义 | 示例 |
|----------|------|------|
| `word_replace` | 替换用词 | "因此"→"所以"、"赋能"→删除 |
| `word_delete` | 删除用词 | 删掉"众所周知"、删掉"不言而喻" |
| `word_add` | 新增用词 | 加入"说白了"、加入口语化比喻 |
| `sentence_split` | 长句拆短 | 一句拆为两句或三句 |
| `sentence_merge` | 短句合并 | 两个短句合成一句 |
| `sentence_rewrite` | 整句重写 | 书面语改口语、换修辞手法 |
| `tone_shift` | 语气调整 | 正式→口语、温和→犀利 |
| `structure_change` | 结构调整 | 调换段落顺序、增删小标题 |
| `punctuation_change` | 标点调整 | 句号改破折号、逗号改省略号 |

## 二、修改模式→说明书字段映射表

累积 ≥5 次 diff 后，分析修改模式，按以下映射表更新说明书对应字段。此外，若检测到“单次重大重写”，应立即触发即时校准逻辑。

### 2.1 累积校准映射表（≥5 次）

| 修改模式 | 判定条件 | 更新说明书字段 | 更新方式 |
|----------|----------|----------------|----------|
| 用户总是把长句拆短 | `sentence_split` 出现 ≥3 次 | **模块三：句式与节奏** | 降低 `avg_sentence_length` 目标值，增加"偏好短句"描述 |
| 用户总是删掉某个词 | 同一词在 `word_delete` 中出现 ≥2 次 | **模块五：禁用清单** | 将该词加入禁用清单，标注来源为"用户校准" |
| 用户总是替换某类词 | `word_replace` 中存在规律性替换（如书面→口语） | **模块二：语气与视角** | 调整语气描述，如"比之前更口语化" |
| 用户总是加入口语化比喻 | `word_add` 中 ≥2 次新增比喻/类比 | **模块二：语气与视角** + **模块四：标志性表达** | 更新修辞手法描述，新增标志性表达 |
| 用户总是改写整句 | `sentence_rewrite` 出现 ≥3 次且方向一致 | **模块一：整体调性** | 重新评估整体调性描述 |
| 用户总是调整标点 | `punctuation_change` 出现 ≥3 次 | **模块三：句式与节奏** | 更新标点特征描述 |
| 用户总是调换段落结构 | `structure_change` 出现 ≥2 次 | **模块三：句式与节奏** | 更新段落习惯描述 |

### 2.2 即时校准触发逻辑（单次重大重写）

当单次修改满足以下任一条件时，视为“风格突变信号”，应跳过累积阈值，立即提议更新说明书：
1. **大面积重写**：`sentence_rewrite` 或 `structure_change` 的字数占比超过全文的 30%。
2. **核心词汇反转**：用户在短时间内（同一次对话）连续删除并替换了多个核心关键词（如将“赋能”改为“帮忙”，将“闭环”改为“收尾”）。
3. **语气极端偏移**：从极度正式转为极度口语（或反之），且涉及全篇的语气调整。

**处理流程**：
- LLM 识别到上述信号后，立即输出：“⚠️ 我注意到这次修改幅度非常大，似乎你希望彻底改变这篇文章的表达基调。是否立即根据这次修改更新《风格说明书》？”
- 若用户确认，则直接基于本次 diff 执行增量更新，并在元信息中标记 `trigger: major_rewrite`。

**分析 prompt**（LLM 对 diff 记录做模式识别）：

```
以下是用户最近 N 次对 AI 初稿的修改记录。请分析这些修改中的规律性模式：

1. 用户倾向于做哪类修改？（参照 category 分类统计频次）
2. 每类高频修改的具体方向是什么？（如：总是把书面语改口语、总是拆长句）
3. 有没有反复出现的具体操作？（如：总是删"因此"、总是加"说白了"）
4. 这些修改反映了用户风格的什么变化趋势？

请输出结构化的修改模式清单，每条包含：模式描述、出现次数、对应的说明书更新建议。

---
修改记录：
{diff_records}
```

## 三、即时反馈话术模板

每次检测到用户修改，立即给出简短反馈。话术需**具体**——引用用户的实际修改内容，而非泛泛而谈。

### 模板

```
📝 我注意到你做了这些修改：
- {修改1的具体描述}
- {修改2的具体描述}
这些修改我记下了，下次会注意。
```

### 示例

**用词替换**：
> 📝 我注意到你把"因此"改成了"所以"，把"消费者"改成了"你"。这些修改我记下了，下次会注意用更口语化的连接词。

**长句拆短**：
> 📝 我注意到你把那个 45 字的长句拆成了两个短句，节奏感好多了。下次我会控制句子长度，多用短句。

**语气调整**：
> 📝 我注意到你把结尾从"建议根据肤质选择"改成了"选错了等于白涂"——更直接、更有你的风格。记下了。

**整段重写**：
> 📝 你重写了开头段，从平铺直叙改成了先抛结论。这个开头模式我记下了。

### 话术原则

1. **必须引用用户的实际修改**，不能说"你做了一些调整"这种空话
2. **点明修改方向**（更口语/更短/更直接），让用户知道 AI 理解了意图
3. **控制在 2-3 句话以内**，不要长篇大论
4. **语气轻松**，不要像在做学术分析

## 四、累积校准话术模板

累积 ≥5 次修改后，触发模式分析，向用户提议更新说明书。

### 模板

```
📊 你最近 {N} 次修改中，我发现了一些规律：
- {模式1}
- {模式2}
- {模式3（如有）}

这些变化说明你的风格{变化趋势概述}。要不要我更新一下《风格说明书》？

更新内容预览：
- {说明书字段1}：{原值} → {新值}
- {说明书字段2}：{原值} → {新值}
```

### 示例

> 📊 你最近 7 次修改中，我发现了一些规律：
> - 5 次把长句拆成了短句（平均从 38 字降到 18 字）
> - 3 次删掉了"因此""然而"等书面连接词
> - 2 次加入了生活化的比喻
>
> 这些变化说明你的风格比原来更口语化了，句子更短更直接。要不要我更新一下《风格说明书》？
>
> 更新内容预览：
> - **句式与节奏**：平均句子长度从 25 字 → 18 字
> - **禁用清单**：新增"因此""然而"
> - **语气与视角**：从"口语化"调整为"强口语化、极简直接"

### 话术原则

1. **先展示数据**（N 次修改中有 M 次做了某事），让用户看到客观依据
2. **给出变化趋势的一句话概括**，帮用户理解整体方向
3. **必须展示更新预览**，让用户知道具体改什么，而不是盲目同意
4. **用户确认后才执行更新**，不自动修改说明书

## 五、校准记录的存储与读取

### 存储

每条 diff 记录存入悟空记忆，标记 `type=style_calibration`：
- 下游技能（如「用我的风格写初稿」）在用户修改初稿后负责写入
- 本技能在触发时负责读取和分析

### 读取

本技能在场景四触发时：
1. `memory_search(query="style_calibration")` 读取所有未处理的 diff 记录
2. 统计未处理记录数量
3. 若 ≥5 条 → 执行模式分析 → 提议更新
4. 若 <5 条 → 仅做即时反馈，不提议更新
5. 分析完成后，标记已处理的记录为 `processed=true`
