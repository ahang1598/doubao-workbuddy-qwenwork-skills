# PAS 写作框架

## 全称

**P**roblem → **A**gitate → **S**olution
问题 → 激化 → 解决方案

## 适用场景

- 深度教程、how-to 文章
- 种草笔记、痛点营销
- 问题解决类内容
- 个人观点/认知颠覆

## 默认适配文章类型

| 文章类型 | 适配理由 |
|---------|---------|
| 深度教程 | 教程天然是"问题→放大痛点→解决方案"结构 |
| 个人观点 | 观点型 = 提出问题→放大争议→给出见解 |

## 三段结构

### P - Problem（提出问题）| 占全文 20-25%

**目标**：用"你是不是也…"句式直击痛点，让读者对号入座。

**常用技巧**：
- **场景代入**："你是不是也遇到过这种情况——花了 3 小时写的报告，领导一句话全推翻？"
- **数据开场**："调查显示，78% 的 [人群] 都面临 [问题]"
- **反向提问**："你有没有想过，为什么你 [做了X] 却 [没有Y]？"
- **共鸣列举**：列出 3-5 个读者常见的具体困扰

**要求**：
- 问题必须具体、可感知，不要抽象
- 让读者在前 5 行内产生"说的就是我"的感觉
- 描述具体场景（时间、地点、动作），而非泛泛而谈

### A - Agitate（放大痛点）| 占全文 20-25%

**目标**：让读者从"知道这个问题"升级到"必须解决这个问题"。

**常用技巧**：
- **展示后果**："如果继续这样下去，3 个月后你会发现…"
- **时间成本**："按现在的方式，你每周在这上面浪费 [N] 小时"
- **机会成本**："当你还在纠结的时候，别人已经…"
- **情感共鸣**："那种反复尝试却毫无进展的挫败感，我太懂了"
- **反面案例**："我见过太多人因为忽视这个问题，最终…"

**要求**：
- 情绪放大，但不过度恐吓
- 从理性（数据/成本）和感性（情感/场景）两个维度放大
- 不要在这里给解决方案——先让"伤口"充分暴露

### S - Solution（给出解决方案）| 占全文 50-60%

**目标**：给出具体可执行的解决方案，让读者拿到就能用。

**常用技巧**：
- **步骤化拆解**：把复杂方案拆成 3-7 个可执行步骤
- **数据佐证**："用这个方法，我把 [X] 从 [A] 提升到了 [B]"
- **案例展示**：展示真实用户/作者使用方案后的效果
- **避坑指南**：每个步骤附上常见错误和注意事项
- **工具推荐**：推荐具体工具/资源，降低执行门槛

**要求**：
- 方案要具体可执行（做什么、怎么做、做多久）
- 每个步骤都有信息增量，不凑字数
- Solution 是全文篇幅最大的部分（50-60%）
- 结尾给出"快速回顾清单"（1-2-3 式总结）

## 段落骨架模板

```
[Problem - 提出问题]
[痛点场景描述：你是不是也…]
[数据/现象佐证]

[Agitate - 放大痛点]
[不解决的后果]
[时间/机会成本]
[情感共鸣]

[Solution - 解决方案]
[方案概述：一句话总结]

  [步骤 1：小标题]
  [操作说明 + 案例 + 避坑]
  
  [步骤 2：小标题]
  [操作说明 + 案例 + 避坑]
  
  [步骤 3：小标题]
  [操作说明 + 案例 + 避坑]

[快速回顾清单]
[CTA]
```

## 注意事项

- PAS 是最通用的框架，几乎适合所有问题解决类内容
- Problem 和 Agitate 合计不超过 40%——核心在 Solution
- Agitate 不是"恐吓"，是"让读者意识到问题的严重性"
- Solution 中的每个步骤都应该是可复现的，不要给模糊建议
