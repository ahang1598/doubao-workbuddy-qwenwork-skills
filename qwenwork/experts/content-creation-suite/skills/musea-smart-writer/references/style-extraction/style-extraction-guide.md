# 风格提取指南

## 概述

本文档定义了从参考文章中提取写作风格的标准流程和 10 个维度。提取结果将存储在 `profiles/default.yaml` 中，作为后续写作的"软约束"。

## 风格提取的触发时机

| 触发场景 | 提取方式 | 提取强度 |
|---------|---------|---------|
| 用户主动提供参考文章 | 完整 10 维度提取 | 全量 |
| 用户确认可用的生成文章（Step 7） | 轻量提取（仅差异维度） | 增量 |
| 用户修改后确认的文章 | 对比修改差异推断偏好 | 精准 |
| 用户主动反馈（"emoji太多"） | 直接转化为规则 | 精准 |

## 10 个提取维度

### 维度 1：开头策略

**提取目标**：作者偏好什么样的文章开头方式

**分析要点**：
- 开头类型：痛点式 / 反转式 / 数据冲击式 / 悬念式 / 结论先行式 / 场景切入式
- 钩子长度：1 行 / 2-3 行 / 整段
- 是否使用提问
- 是否直接给出结论

**输出格式示例**：
```
opening_strategy: "偏好反转式开头，先给结论再讲方法。钩子通常2-3行，喜欢用数据开场。"
```

### 维度 2：行文结构

**提取目标**：文章的整体组织方式

**分析要点**：
- 结构类型：并列式 / 递进式 / 时间线 / 问题-方案 / 总-分-总
- 小标题风格：是否使用、什么形式（疑问句/陈述句/动词短语）
- 段落间的逻辑连接方式
- 是否有明确的起承转合

**输出格式示例**：
```
structure: "递进式结构，从现象到本质到方法。小标题用动词短语，段间有明确过渡。"
```

### 维度 3：段落节奏

**提取目标**：段落的长度、密度和视觉节奏

**分析要点**：
- 平均段落长度（行数）
- 是否有单句成段
- 分隔符使用（---、···、emoji 行）
- 列表/表格使用频率
- 长段和短段的交替模式

**输出格式示例**：
```
paragraph_rhythm: "段落3-5行为主，金句和关键结论单独成段加粗。偶尔用···分隔章节。"
```

### 维度 4：语气与人称

**提取目标**：作者的语气基调和人称使用

**分析要点**：
- 主要人称：你 / 我 / 我们 / 第三人称
- 正式度：学术 / 专业 / 中等 / 口语 / 极口语
- 情绪强度：克制 / 适中 / 热烈 / 激昂
- 与读者的关系定位：老师-学生 / 朋友-朋友 / 专家-外行

**输出格式示例**：
```
tone_and_person: "第二人称'你'为主，口语化程度中等，像一个有经验的朋友在聊天。情绪适中，不太热烈也不太冷淡。"
```

### 维度 5：句法特征

**提取目标**：句子层面的写作偏好

**分析要点**：
- 句子平均长度（短句为主 / 长短交替 / 长句为主）
- 特殊句式频率：反问句 / 祈使句 / 感叹句 / 排比句
- 标点偏好：感叹号频率、省略号使用、破折号使用
- 是否使用括号补充说明

**输出格式示例**：
```
syntax: "短句为主，长短交替。高频使用反问句和祈使句。偶尔用括号补充说明，感叹号使用频率中等。"
```

### 维度 6：词汇与口头禅

**提取目标**：作者的标志性用词

**分析要点**：
- 高频词汇（出现 3 次以上的非通用词）
- 标志性口头禅（"说真的"、"你猜怎么着"、"划重点"）
- 过渡词偏好（"但是"、"不过"、"换句话说"）
- 是否使用网络用语（yyds、绝了、真香）
- 行业术语使用密度

**输出格式示例**：
```
vocabulary: "常用'说真的'、'你猜怎么着'、'划重点'。过渡词偏好'但是'和'换句话说'。适度使用网络用语。"
```

### 维度 7：修辞手法

**提取目标**：作者偏好的修辞策略

**分析要点**：
- 类比频率和类型（生活类比 / 技术类比 / 历史类比）
- 对比使用（前后对比、优劣对比）
- 故事片段嵌入频率
- 数据引用密度
- 幽默/自嘲使用

**输出格式示例**：
```
rhetoric: "大量使用生活类比解释技术概念，每个核心观点配一个类比。偶尔自嘲增加亲和力。数据引用频率中等。"
```

### 维度 8：信息密度

**提取目标**：文章中可执行/可操作信息的密度

**分析要点**：
- 可执行块（步骤、清单、工具推荐）出现频率
- 表格/对比图使用频率
- "干货"与"故事/情感"的比例
- 每段是否都有信息增量
- 是否有"快速总结/回顾"段落

**输出格式示例**：
```
information_density: "每300字至少一个可执行块。干货:故事 = 7:3。结尾必有快速回顾清单。"
```

### 维度 9：标题风格

**提取目标**：标题的构造偏好

**分析要点**：
- 句式类型：数字型 / 疑问型 / 陈述型 / 反转型 / How-to 型
- 情绪词强度：无 / 低 / 中 / 高（"震惊"、"必看"、"绝了"）
- 标题长度偏好
- 是否使用 emoji
- 是否使用竖线/冒号分隔

**输出格式示例**：
```
title_style: "数字型标题为主（'N个方法'），中等情绪强度，不使用emoji，18-25字。"
```

### 维度 10：结尾动作

**提取目标**：文章结尾的收束方式

**分析要点**：
- 结尾类型：金句总结 / 行动号召 / 互动引导 / 悬念预告 / 情感升华
- CTA 风格：直接型 / 温和型 / 互动型
- CTA 数量：单一 / 多个
- 是否有"下期预告"
- 最后一句话的语气

**输出格式示例**：
```
ending_action: "金句总结+单一CTA。CTA偏温和型（'觉得有用就点个赞吧'），不使用强制性语气。"
```

## 风格档案格式

提取结果存储为 YAML 格式：

```yaml
# profiles/default.yaml
name: "默认风格"
created_at: "2026-06-05"
updated_at: "2026-06-05"
version: 1

source_articles:
  - title: "[参考文章标题]"
    source: "user_provided"
    learned_at: "2026-06-05"

style_rules:
  opening_strategy: "[提取结果]"
  structure: "[提取结果]"

  title_style: "[提取结果]"

```

## 风格合并策略

当已有风格档案需要与新提取的风格合并时：

### 优先级规则

```
user_adjustments（用户显式反馈）
  > agent_generated_modified（用户修改后确认的文章）
  > agent_generated_confirmed（用户确认可用的文章）
  > user_provided（用户主动提供的参考）
  > 旧规则
```

### 冲突处理

当新旧规则对同一维度有不同描述时：

1. **无冲突**：新规则补充旧规则 → 合并
2. **轻微差异**：以新规则为准 → 替换
3. **明显冲突**：向用户确认，提供 2-3 个选项

### 轻量提取（用于已确认文章）

仅提取与现有 `style_rules` 有明显差异的维度，不重做完整分析：

```
<thinking>
对比当前风格档案 vs 本次生成文章：
- opening_strategy：一致 → 跳过
- paragraph_rhythm：本次段落更短 → 微调
- tone_and_person：一致 → 跳过
- vocabulary：本次新增高频词"其实" → 更新
...
仅更新有差异的 2-3 个维度。
</thinking>
```

## 关键约束

- 风格规则是"软约束"——可以被文章类型模板和平台规范覆盖
- 硬性约束（字数限制、平台格式要求等）**永远不可被风格覆盖**
- 渐进式收敛：version 1-3 时风格波动正常，version 5+ 应趋于稳定
