# 归档四约定 · 详细展开

> 本文件是 SKILL.md 的附件。
> 运行时 AI 执行"工作流 4 · 外部材料归档"前必读。
> SKILL.md 里是每条约定的一句话简版，本文件是完整展开（反模式表 + 示例 + 自检清单）。

---

## 概览

归档外部材料（URL、文章、PDF）时，必须同时遵守 4 条约定：

| 约定 | 一句话 | 对应的管家承诺 |
|---|---|---|
| A · 按主题归档 | 一份材料讲谁，归到谁那里，不按格式分 | 宁可不建，不建垃圾 |
| B · 反向链接一步到位 | 归档时同步更新所有被提及实体的 `## 被提到` 段 | 双向连通 |
| C · Citation 三轨 | 三种引用格式按场景选 + 未标即推断 | 每句事实可追溯 / 猜测和事实分开 |
| D · 老档案宽容 | 新规则只对新页生效，旧页机会性补齐 | 迁移零风险 |

---

## 约定 A · 按主题归档

### 一句话
一份材料**讲谁**，就归到**谁**那里。不按格式分（PDF / 视频 / 推文），不按来源分（36Kr / 知乎 / Twitter）。

### 反模式表

| ❌ 常见错误 | ✅ 正确做法 | 原因 |
|---|---|---|
| 关于 Alice 的 PDF → 按格式归档到"PDF 文件" | → `2-AI知识库/专题/Alice.md` | 主题是人，不是 PDF |
| 关于某公司的视频 → "视频摘要"目录 | → `2-AI知识库/专题/{公司名}.md` | 主题是公司，不是视频 |
| 36Kr 的行业分析 → "36Kr 文章"目录 | → 按分析的**行业主题**（专题页 entity_kind=method 或普通专题页） | 主题是行业，来源只是 36Kr |
| 提出新框架的文章 → 按作者归档 | → `2-AI知识库/专题/{框架名}.md`（entity_kind=method · 同时作者按专题 3 规则处理） | 主题是框架，作者是次要 |

### 决策流程

```
这份材料主要讲什么？
     ↓
 ┌── 一个人（作者观点、传记、访谈）→ 专题/{人名}.md（按专题 3 规则）
 ├── 一个组织/项目（产品、公司分析）→ 专题/{组织名}.md（按专题 3 规则）
 ├── 一个可复用的方法/框架/抽象 → 专题/{名称}.md（entity_kind=method · ≥2 份素材提及才建）
 ├── 跨多源的综合分析 → 洞察/{主题}.md
 └── 纯素材本身（无主题抽象）→ 只建素材摘要，不抽象
```

### 自检问题
- 这份材料讲的"主要对象"是什么？人？组织？概念？
- 我选的归档位置是**对象决定**的，还是被"格式/来源"带偏了？

## 约定 B · 反向链接一步到位

### 一句话
归档时，**同步**更新所有被提及实体页的 `## 被提到` 段。不允许"只写正向、反向等整理"。

### 为什么"一步到位"而不是"批量回算"

早期设计曾考虑"整理时批量重建反向链接"以降低归档成本。但计算后发现：
- 一次归档提到的实体通常 **5-20 个**
- 每个实体页追加 1 行反向链接 = 1 次 Edit 调用
- 悟空的 Edit 是毫秒级
- 5-20 次 Edit 在用户可接受的等待时间内

**"等整理时再算"的代价**（放弃的方案）：
- 刚投喂完、立刻想看 Karpathy 的反向链接 → 还没算出来 → 体感割裂
- 用户不知道"什么时候数据是新的"
- 需要额外"审计 / 重建"工作流

**"一步到位"的代价**（采用的方案）：
- 一次归档多 5-20 次 Edit → 可接受
- 原子性：任何一步失败 = 回执明告 = 易修复
- 所见即所得：投完立即双向连通

### 具体操作步骤

在"工作流 4 · Phase 4 · 反向链接传播"里：

```
对摘要里每个 [[]] 双链的目标页：
  1. 读取目标页
  2. 找到 ## 被提到 段
     - 已存在 → 追加一行
     - 不存在 → 在文末创建该段 + 追加一行
  3. 追加的格式：
     - **YYYY-MM-DD** | [[新摘要页]] — 一句话上下文（20 字以内）
```

### 示例

**目标页**：`2-AI知识库/专题/Karpathy.md`

追加前（文末）：
```
## Timeline
- **2026-04-17** | 发表 LLM Wiki Gist
```

追加后：
```
## Timeline
- **2026-04-17** | 发表 LLM Wiki Gist

## 被提到
- **2026-04-22** | [[素材摘要/karpathy-llm-wiki-gist]] — 提出 raw/wiki/schema 三层架构
```

### 自检问题
- 这次归档里，摘要提到了几个实体？
- 我为**每一个**实体页都追加反向链接了吗？
- 回执里"触达的实体"列表和实际更新的页数对得上吗？

## 约定 C · Citation 三轨

### 一句话
每个事实都必须带来源锚点，按场景选三种格式之一。**未带锚点的句子 = AI 推断**，必须显式标注 `（AI 推断）`。

### 三轨对照表

| 场景 | 格式 | 示例 |
|---|---|---|
| 有素材页 | `[[素材页名]]` | Karpathy 主张 raw/wiki/schema 三层架构 [[素材摘要/karpathy-llm-wiki-gist]] |
| 外部引用（无素材页） | `（来源：{出处}, {URL}, {日期}）` | 深度学习在 2012 年 ImageNet 大赛突破（来源：维基百科, https://..., 2026-04） |
| 用户口述 | `（来源：用户口述 YYYY-MM-DD）` | 张三是我今天见的新客户（来源：用户口述 2026-04-22） |

**优先级**：主路径 > 外部引用 > 用户口述。能建素材页的**优先建素材页**再用 [[]] 引用；只有外部信息不值得建素材页（如维基百科一句事实）才用裸引用。

### "未标即推断" 铁律

管家写摘要/洞察时，常会做**综合判断**——比如"这三篇都在讨论认知飞轮，共同点是..."。这种综合：
- 不是某一份素材里的原话
- 不能归因到任何一个 `[[]]` 目标
- 但有价值，不能删

**正确处理**：在综合判断的**句末**显式标注 `（AI 推断）`。

**反模式**：把 AI 推断**伪装成事实**混进引用流，三个月后用户无法区分"这是原文说的"还是"这是管家综合的"。

### 示例

❌ **错误**：
```
Karpathy 的核心观点是"AI 必须闭环"——这是当前最重要的设计原则 [[素材 A]]。
```
问题：后半句"这是当前最重要的设计原则"是管家的推断，不是素材 A 的原话。把它包进 [[素材 A]] 的引用里 = 伪装。

✅ **正确**：
```
Karpathy 的核心观点是"AI 必须闭环" [[素材 A]]。这是当前最重要的设计原则（AI 推断）。
```

### 自检问题
- 这段事实属于哪一轨？
- 如果是综合判断，我标了 `（AI 推断）` 吗？
- 用户读完能一眼区分"原文说的"和"管家总结的"吗？

## 约定 D · 老档案宽容

### 一句话
新规则只对**新建/新修改的页**强制生效。旧页不主动回溯。触碰旧页（更新/被引用/被用户问到）时顺手补齐。

### 为什么宽容

知识管家的规则会持续演化（专题规则、citation 格式、反向链接机制都可能变）。如果每次规则变更都强制全库回溯：
- 一次小变更 = 几十到几百个页面重写
- 用户看不到"规则变化的好处"，只看到"大量旧页被动"
- 长期打击用户对产品的信任

### 遇到旧页时的处理流程

当你在某次工作流里**第一次碰到一个旧页**（它被新摘要引用、或被用户问到、或你要更新它）：

1. 打开旧页看它
2. 检查它是否符合当前规则：
   - 有 `## 被提到` 段吗？
   - frontmatter 有 `source_type` 字段吗？
   - 事实都带 citation 吗？
3. **不符合**：
   - 补齐到当前规则（加段、补 frontmatter、补 citation）
   - 在页末追加一条 `## 修订记录`：`- **YYYY-MM-DD** | 补齐到 v3.1 规则`
4. 继续做你原来的事

### 整理工作流的"机会性迁移"

整理工作流的"反向链接审计"会扫全库，**报告**哪些旧页不符合规则——但**不自动修**。用户可以选择"批量修"或"继续宽容"。

### 自检问题
- 我是在"触碰到旧页顺手补"还是在"批量重写旧页"？（前者对，后者错）
- 我补齐时有没有加 `## 修订记录` 小节？

## 专题创建 3 规则（贯穿 4 约定）

归档过程中遇到"人/组织/项目/话题"时，统一按下面 3 条规则处理（**不分作者/人物/机构**）：

```
规则 1：单次出现
  不建专题页
  只在摘要 frontmatter 的 author / 相关字段记名字
  摘要正文里用纯文本提及，不用 [[]] 双链

规则 2：第 2 次出现
  管家**直接建**专题页（不问用户）
  回执中告知："已建 [[X]]，不需要的话说一声我删"
  同时**回扫第 1 次的摘要**，把纯文本 "X" 替换为 [[X]]

规则 3：用户显式说"帮我记下这个 X"
  立即建，无论出现次数
```

**为什么第 2 次直接建而不先问**：减少交互，节奏快；用户嫌多时说一声删即可。

## 打包自检清单

在结束任何"工作流 4 · 外部材料归档"之前，过一遍：

- [ ] 约定 A：归档位置是"主题决定"的吗？
- [ ] 约定 B：摘要里每个 [[]] 目标页都追加了反向链接吗？
- [ ] 约定 C：每个事实都带三轨引用之一，综合判断都标了 `（AI 推断）` 吗？
- [ ] 约定 D：触碰的旧页我顺手补齐了吗？
- [ ] 专题 3 规则：新提到的实体按"出现 1 次不建、出现 2 次直接建、用户说记就建"处理了吗？
- [ ] 完成回执：给用户的回执包含**原文路径 / 摘要路径 / 触达实体 / 新建专题**吗？
